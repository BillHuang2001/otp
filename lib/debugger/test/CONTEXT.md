# debugger — Common Test Suites

## Intent
Common Test suites for the `debugger` application: they exercise the interpretation engine (`int`, `dbg_ieval`, `dbg_icmd`) and the Debugger GUI, by interpreting test code and checking that interpreted execution behaves like compiled execution.
The bulk of the directory covers *headless* interpreter behaviour (no display required); GUI behaviour is only covered by manual tests.

## API Surface
- `Makefile` — lists every suite/helper in `MODULES`; `TARGET_FILES` are installed as `$(RELEASE_PATH)/debugger_test` (see `RELSYSDIR`); `release_tests_spec` installs the compiled modules, `debugger.spec`, `debugger.cover` and untars every `*_SUITE_data/` directory.
- `MODULES` includes two non-suite helper modules: `test_lib` and `cleanup`.
- `ERL_COMPILE_FLAGS += +nowarn_missing_spec_documented`, and `+deterministic` is filtered out (test suites rely on non-deterministic code paths).
- An `Emakefile` is generated by `$(ERL_TOP)/make/make_emakefile -o. $(MODULES)` plus a second pass over the glob `'*_SUITE_make'` (no such modules currently exist); `make tests` (and `make test`) then runs `erl -make`.
- `debugger.spec` — `{suites,"../debugger_test",all}.` i.e. the installed test release is run with all suites.
- `debugger.cover` — `{incl_app,debugger,details}.`: coverage is collected for the whole `debugger` app.

## Test Strategy
- `make test` in `lib/debugger/` (via `make/app_targets.mk` → `make/test_target_script.sh`) builds the test release and runs `ct_run` with `debugger.spec`; suites can also be run directly with `ct_run`/`ct:run_test` against `lib/debugger/test`.
- All suites use the `ts_install_cth` CT hook (`{ct_hooks,[ts_install_cth]}`) and a `{timetrap,...}`; they are therefore designed to run against an *installed* release (`RELSYSDIR`), not only in-tree.
- Three families of suites (see Routing Table): interpreter-API suites, language-feature suites, and the GUI/app-level suites.
- **Language-feature suites** interpret *themselves*: `test_lib:interpret(?MODULE)` (which uses `i:ii/1`) is called in `init_per_suite`/`init_per_testcase`, so every testcase body executes through `dbg_ieval` rather than natively — that is what makes them interpreter tests.
- Several of these suites are copies of the corresponding `erts`/`compiler` suites (`bs_construct_SUITE`, `map_SUITE`, `lc_SUITE`, `mc_SUITE`, `zlc_SUITE` from Per Gustafsson's suite, …), with cases that make no sense under the interpreter removed; they intentionally duplicate coverage with the compiler/emulator suites.
- **Test data**: `*_SUITE_data/` directories are CT `data_dir`s; suites load modules from them with `int:i(DataDir/Mod)` or `compile:file` into `priv_dir`.
  - `int_SUITE_data/` is compiled by `int_SUITE:init_per_suite/1` via `make:all()` in the data dir, driven by its `Emakefile` (`+debug_info` required for interpretation).
  - `bug_SUITE_data/`, `int_break_SUITE_data/`, `int_eval_SUITE_data/` carry a legacy `Makefile.src` (configured to `Makefile` by the top-level build; `+debug_info`), an older test_server data-dir convention.
  - `native_record_SUITE_data/ext_records.erl` is compiled at test time into `priv_dir` and interpreted; `dbg_ui_SUITE_data/manual_data/src/` is only used by the manual GUI tests.
- Every `*_data` module that is *interpreted* (rather than merely compiled) must be built with `debug_info`, otherwise `int:i/1` returns `error`.

## Known Issues
- `dbg_ui_SUITE:dbg_ui/1` returns `{skipped,"No display"}` when `DISPLAY` is unset and `{skipped,"Gunilla: Workaround"}` even when it is set — the actual GUI check is commented out, so no automated GUI coverage exists.
- The `manual_tests` group of `dbg_ui_SUITE` (start/interpret/break/step/save/attach/dist cases) is human-driven: each case calls `check/2`, which consults `dbg_ui_SUITE_data/manual_results.erl` (an untracked file the tester creates by hand) and is skipped unless the case is marked `pass`/`fail`.
- Consequently the only suites with automated, headless coverage are the interpreter and app-level ones; the GUI is effectively untested in CI.
- `debugger_test.erl` is not referenced by any suite — it is a helper for the legacy FrameMaker test document `debugger_testdoc.fm5` (not installed into the test release) and is only kept because it is listed in `MODULES`.
- Manual case descriptions still reference the obsolete path `/clearcase/otp/tools/debugger/test/...` (the app was formerly part of `tools`).

## Routing Table
| Path | Description |
| --- | --- |
| `int_SUITE.erl`, `int_SUITE_data/` | Interpreter API: `int:i/1`, `int:n/1`, `int:interpreted/0`, `int:interpretable/1`; `list_suite` group evaluates the interpreted `lists1`/`my_lists`/`ordsets1`/`guards`/`test`/`test1` data modules |
| `int_break_SUITE.erl`, `int_break_SUITE_data/` | Breakpoints: `i:ib/2,3`, `i:ia*`, `int:auto_attach`, `int:no_break`, `int:clear` against interpreted `ordsets1` |
| `int_eval_SUITE.erl`, `int_eval_SUITE_data/` | Deeper evaluator semantics (BIFs outside `erlang`, spawn/apply, catch/throw, stacktraces, maps, calls in binaries) via the interpreted `my_int_eval_module`/`stacktrace` |
| `andor_SUITE.erl`, `bs_*_SUITE.erl` (bincomp, construct, match_bin, match_int, match_misc, match_tail, size_expr, utf), `erl_eval_SUITE.erl`, `exception_SUITE.erl`, `fun_SUITE.erl`, `guard_SUITE.erl`, `lc_SUITE.erl`, `line_number_SUITE.erl`, `map_SUITE.erl`, `maybe_SUITE.erl`, `mc_SUITE.erl`, `native_record_SUITE.erl` (+`_data`), `overridden_bif_SUITE.erl`, `record_SUITE.erl`, `trycatch_SUITE.erl`, `zlc_SUITE.erl` | Language-feature interpreter coverage: each interprets its own suite module via `test_lib:interpret/1` and checks interpreted == compiled behaviour for that construct |
| `bug_SUITE.erl`, `bug_SUITE_data/` | Regression tests for specific tickets (`otp2163`, `otp4845`), comparing compiled vs interpreted results |
| `dbg_ui_SUITE.erl`, `dbg_ui_SUITE_data/` | Debugger GUI suite: currently always-skipped `dbg_ui` case plus the human-driven `manual_tests` group; data in `manual_data/src/` (`test.erl`, `lists1.erl`, `ordsets1.erl`) |
| `debugger_SUITE.erl` | App-level tests: `app_test`, `appup_test`, `erts_debug`, `no_abstract_code`, `encrypted_debug_info` (needs `crypto`) |
| `test_lib.erl` | Shared helper: `interpret/1` (interpret a module if not already interpreted), `binary/1` for the overridden-BIF test — not a suite despite being in `MODULES` |
| `cleanup.erl` | Helper module exposing `cleanup/1` (uninterprets all modules, kills `interpret`/`int_db` processes); compiled into the test set but not part of `debugger.spec` |
| `debugger_test.erl` | Legacy manual-test helper for `debugger_testdoc.fm5` (`installation_ok/0`, `list/0`, `fac/1`, `c_break/1`) — unused by the suites |
| `debugger_testdoc.fm5` | Legacy FrameMaker document describing the manual debugger test procedures; not installed and not processed by the build |
| `debugger.spec`, `debugger.cover` | CT suite spec (`{suites,"../debugger_test",all}`) and coverage spec (`{incl_app,debugger,details}`) |
| `Makefile` | Build/install driver for the test set (`MODULES`, `RELSYSDIR`, `make_emakefile`) |
