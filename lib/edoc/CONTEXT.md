# edoc — EDoc, the Erlang Documentation Engine

## Intent
The `edoc` OTP application: a tool that reads Erlang source files, extracts legacy `%%` edoc comment blocks (with `@`-tags), builds an internal XML data model, and renders it through a pluggable *doclet* + *layout* pair — HTML by default, or EEP-48 doc chunks / EEP-59 Markdown.
Product version `EDOC_VSN = 1.5` (`vsn.mk`); it is one of the `ALL_ERLANG_APPLICATIONS` in `lib/Makefile`.
Follows the standard OTP application layout (`src/`, `include/`, `ebin/`, `test/`, `doc/`, `priv/`, `Makefile`, `vsn.mk`).

## API Surface
- `edoc/` → the only user-facing API: `files/1,2`, `application/1,2,3`, `toc/1,2,3`, `run/2`, `file/1,2`, `read/1,2`, `layout/1,2`, `get_doc/1,2,3`, `read_comments/1,2`, `read_source/1,2` (some `@deprecated`).
- `edoc_doclet/` → the fixpoint behaviour for renderers: any module exporting `run/2` taking a `command()` and a `context()` is a doclet.
- `edoc_doclet_chunks/` + `edoc_layout_chunks/` → produce EEP-48 `#docs_v1{}` doc chunks.
- `edoc_doclet_markdown/` + `edoc_html_to_markdown/` → convert existing edoc docs to EEP-59 Markdown (`-moduledoc`/`-doc` attributes).
- `edoc_layout/` → the default HTML layout (`module/2`, `overview/2`).
- `edoc_run/` → `erl -run edoc_run ...` interface used from Makefiles; terminates the emulator with a success/failure status.
- `bin/edoc/` → an `escript` front-end delegating to `edoc_cli:main/1` (installed to `lib/edoc-<vsn>/bin`).

## Constraints
- **Input is legacy `%%` edoc comments** parsed via `edoc:read_comments/2` → `erl_comment_scan`; the modern `-doc`/`-moduledoc` attributes and EEP-48 chunks are an *output* format produced by the chunks/markdown doclets, not parsed as input.
- Depends on `syntax_tools` (AST, pretty-printing, comment scanning) and `xmerl` (XML model); compile flags are strict (`-Werror`, see `src/Makefile`).
- Never edit generated files: `src/edoc_parser.erl` (from `edoc_parser.yrl`) and everything under `ebin/`.
- The doclet/layout contracts are public API (documented in `include/edoc_doclet.hrl`); changing them affects third-party doclets/layouts.

## Dependencies
- From `src/edoc.app.src`: applications `compiler, kernel, stdlib, syntax_tools`; runtime deps include `xmerl-1.3.7`, `syntax_tools-2.0`, `stdlib-4.0`, `kernel-7.0`, `inets-5.10`, `erts-11.0`.
- `kernel/include/eep48.hrl` and `shell_docs` are used by the EEP-48 chunk path.

## Notes for Agents
- `edoc_parser.erl` appears only after a build (generated by Yecc); treat `edoc_parser.yrl` as the source of truth.
- `ebin/` is build output; `bin/` and `priv/` hold installed runtime files, not build artifacts.
- The app version lives in `vsn.mk` (`EDOC_VSN`); `Makefile` derives `VSN = $(EDOC_VSN)` and includes `make/app_targets.mk`.
- `lib/edoc/Makefile` contains two leftovers from the pre-ExDoc era: `RELSYSDIR = $(RELEASE_PATH)/lib/xmerl-$(VSN)` (copy-paste from xmerl; the effective doc install dir comes from `make/doc.mk`'s `$(RELEASE_PATH)/lib/$(APPLICATION)-$(VSN)` fallback) and an obsolete `edocs`/`EXTRA_FILES`/`HTML_FILES` HTML path.

## Test Strategy
- Common Test suites in `test/` run with `make test` in this directory; called from the app-level `test/Makefile`.
- Tests are file-system based (generate docs into `priv_dir` and assert on output) plus `.app`/`.appup` metadata checks and EEP-48 chunk validation through `shell_docs`.
- Requires a built `edoc` and `syntax_tools` on the code path; see `test/CONTEXT.md` for details and known gaps.

## Routing Table
- `src/` → all Erlang sources (20 modules + `edoc_parser.yrl` + `edoc.app.src`/`edoc.appup.src`) — the public API, doclets, layouts, extraction/data-model, parsing and support modules
- `test/` → Common Test suites (`edoc_SUITE`, `eep48_SUITE`) and their data
- `doc/` → documentation sources (guides, `references/edoc_cmd.md`, `docs.exs`) and the ExDoc/chunks build
- `include/` → public Erlang header `edoc_doclet.hrl` (doclet records `#doclet_context`/`#doclet_gen`/`#doclet_toc`, `?NO_APP` macro)
- `priv/` → runtime assets: `stylesheet.css`, `erlang.png`, `edoc.dtd`, and the `edoc_generate` shell helper (installed to `lib/edoc-<vsn>/priv`)
- `bin/` → the `edoc` escript front-end and its install `Makefile`
- `ebin/` → build output (only `.gitignore` tracked) — ignore
- `Makefile`, `vsn.mk` → build driver and version (`EDOC_VSN`)
