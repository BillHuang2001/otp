# xmerl — Test Suites (Common Test)

## Intent
Common Test (`test_server`) suite directory for the `xmerl` application: functional suites for the DOM scanner, SAX parser and XSD validator, plus the vendored W3C/IBM/OASIS/Sun/Japanese XML-conformance and MS/NIST/Sun XSD-conformance corpora.
The suites are built in place and installed (`RELSYSDIR = $(RELEASE_PATH)/xmerl_test`), and run either from the app dir or against the installed release.

## API Surface
Suites (`SUITE_FILES` in `Makefile`):
- `xmerl_SUITE.erl` — core functional suite: `doctests` (runs `ct_doctest:module/2` over `xmerl`, `xmerl_xpath`, `xmerl_xs`), XPath groups (`xpath_text1`, `xpath_main`, `xpath_abbreviated_syntax`, `xpath_functions`, `xpath_namespaces`), `cpd_tests`, `misc`, `eventp_tests` (`xmerl_eventp`), `ticket_tests`, and nested `{xmerl_app_test, all}` / `{xmerl_appup_test, all}` / `format_test` groups.
- `xmerl_std_SUITE.erl` — W3C XML 1.0 conformance via `xmerl_scan` (~1788 cases), one test per conformance file; groups `sun_test_cases`, `ibm_test_cases`, `xmltest_test_cases`, `japanese_test_cases`, `oasis_test_cases`.
- `xmerl_sax_SUITE.erl` — SAX parser (`xmerl_sax_parser`) functional/ticket tests: groups `basic` and `bugs` (continuations, entities, event-fun errors, fragmented directive).
- `xmerl_sax_std_SUITE.erl` — same W3C XML 1.0 conformance corpus as `xmerl_std_SUITE` but driven through `xmerl_sax_parser:file/2` (~30k lines, one test case per file).
- `xmerl_sax_stream_SUITE.erl` — `xmerl_sax_parser:stream/2` over a real TCP socket (continuation_fun/continuation_state), cases `one_document`, `two_documents`, `one_document_and_junk`, `end_of_stream`.
- `xmerl_xsd_SUITE.erl` — XSD functional suite: `type_tests` (primitive + derived datatypes), `facets`, `misc_block_tests`, `validation_tests` (schema/primer examples), `ticket_tests`.
- `xmerl_xsd_MS2002-01-16_SUITE.erl` / `xmerl_xsd_NIST2002-01-16_SUITE.erl` / `xmerl_xsd_Sun2002-01-16_SUITE.erl` — XSD conformance suites (MS/NIST/Sun corpora), one test case per schema/group, results compared against a reference log.
Helpers:
- `xmerl_test_lib.erl` — `cmp_element/2`/`cmp_elements/2`/`cmp_attributes/2` DOM-tree comparison and `get_data_dir/1` (redirects a `xmerl_sax_std_SUITE_data` path back to `xmerl_std_SUITE_data`, since the two suites share one corpus).
- `xmerl_xsd_lib.erl` — XSD test drivers: `unpack/2`, `rmdir/2`, `schema_test/4,5`, `instance_test/5`, `compare_test_results/3`, reference-log lookup (`xsd_reference_log/1`), error-log create/close.
- `xmerl_app_test.erl` — app-file checks (`fields`, `modules`, `exportall`, `app_depend`) on the installed `xmerl.app`.
- `xmerl_appup_test.erl` — `test_server:appup_test(xmerl)` on `xmerl.appup`.
Non-source artifacts: `xmerl.spec` (legacy suite spec `{suites,"../xmerl_test",all}.`), `xmerl.cover` (coverage spec `{incl_app,xmerl,details}`), `xmlconf.xml` + `xmlconformance.xsl`/`xmlconformance.msxsl` + `testcases.dtd` (W3C conformance-suite index, result XSLTs and DTD), `ReadMe` (provenance/copyright of the corpora).

## Test Strategy
- Run all suites from the app dir with `make test` in `lib/xmerl` (or `otp_build` / the release `xmerl_test` dir); `test/Makefile` is self-contained CT plumbing (`opt`, `tests`, `release_tests_spec`).
- Run a single suite/case with `ct_run -dir lib/xmerl/test -suite <suite> [-case <case>]` after `make opt` in `lib/xmerl/test`; the release target copies `MODULES`, `SUITE_FILES`, `xmerl.spec`/`xmerl.cover` and all `*_SUITE_data` dirs into `$(RELEASE_PATH)/xmerl_test`.
- Corpora are unpacked at suite start into each suite's `data_dir` (via `erl_tar:extract/2`), and the unpacked trees are removed in `end_per_suite` unless built with `XMERL_PRESERV` (`-Ddont_rm_test_dirs`).
- XSD conformance suites compare per-testcase results against `<suite>_data/<name>_failed_cases.log`; a result that fails when the reference log says it should pass is a hard failure (`[] = NewFail`), while already-known failures are tolerated.
- Adding a suite: add the `.erl` to `SUITE_FILES` (and the module to `MODULES` if it is a helper); a `*_SUITE_data/` dir is only installed into the release if it is added to the `tar cfh -` block in `release_tests_spec`.

## Constraints
- `xmerl_test.erl` is generated — copied by the Makefile rule from `../doc/examples/xmerl_test.erl` and deleted by `make clean`; never edit the copy, edit the doc example.
- `xmerl_xsd_{MS,NIST,Sun}2002-01-16_SUITE.erl` are generated by the (now-absent) `generate_xsd_suite` module — verify against a corpus change rather than editing by hand.
- Never edit the vendored conformance archives (`xmlts20130923.tar.gz`, `*.tgz`, `msxsdtest.tar.gz`, `nisttest.tar.gz`, `suntest.tar.gz`); they are upstream test data and their `w3c-copyright-*.html` files must stay.
- `ERL_COMPILE_FLAGS` force `+nowarn_missing_spec_documented` and strip `+deterministic` (the generated corpora suites are not deterministic-reproducible).
- Corpus suites are huge (`xmerl_sax_std_SUITE.erl` ~30k lines, `xmerl_xsd_MS…` ~24k, `xmerl_xsd_NIST…` ~16k, `xmerl_std_SUITE.erl` ~10k); edit sparingly and prefer the shared helpers.

## Known Issues
- The conformance data dirs ship two byte-identical archives pairs: `xmerl_std_SUITE_data` and `xmerl_sax_std_SUITE_data` have identical `ibm.tgz`/`japanese.tgz`/`oasis.tgz`/`sun.tgz`/`xmltest.tgz`/`xmlts20130923.tar.gz`; only `xmerl_std_SUITE_data` is fully installed (the SAX suite reuses it via `xmerl_test_lib:get_data_dir/1`).
- `xmerl_sax_stream_SUITE` binds hardcoded TCP port 11111 on localhost — it can fail on a busy port.
- `xmlconf.xml`, `ReadMe` and `xmerl.spec`/`xmerl.cover` sit in `test/` (the spec/cover files are installed; `xmlconf.xml`/`ReadMe` are not listed in `XML_FILES` and stay source-only).
- The XSD conformance `*_failed_cases.log` files encode the current accepted-failure baseline; a real fix to `xmerl_xsd` will be reported as "new succeeding cases" until the log is refreshed.

## Dependencies
- Requires `common_test` (`ct.hrl`, `ct_doctest`) and the built `xmerl` app on the code path (tests include `xmerl/include/xmerl.hrl` and `xmerl_xsd.hrl`).
- `xmerl_xsd_*_SUITE` and `xmerl_std_SUITE`/`xmerl_sax_std_SUITE` need their `*_SUITE_data/` tarballs present (they are consumed read-only and extracted into `data_dir` at runtime).

## Routing Table
- `xmerl_SUITE_data/` → DOM-scanner/XPath/eventp test data: `cpd.tar.gz`, `misc.tar.gz`, `eventp/` (XML+DTD+stubs), `xpath/` (`*.xml` + `xpath_lib.erl`/`xpath_text.erl`/`xpath_abbrev.erl` compiled at runtime)
- `xmerl_std_SUITE_data/` → W3C XML 1.0 conformance corpus archives (shared, canonical copy)
- `xmerl_sax_std_SUITE_data/` → duplicate of the W3C corpus dir (SAX suite resolves to `xmerl_std_SUITE_data`)
- `xmerl_sax_SUITE_data/` → SAX entity/streaming fixtures
- `xmerl_sax_stream_SUITE_data/` → documents for the TCP-streaming suite
- `xmerl_xsd_SUITE_data/` → XSD functional fixtures (`po*.xsd/xml`, `ipo*`, `*.xsd`, `gpx/`, `netsim/`)
- `xmerl_xsd_MS2002-01-16_SUITE_data/` → `msxsdtest.tar.gz` + `msx_failed_cases.log`
- `xmerl_xsd_NIST2002-01-16_SUITE_data/` → `nisttest.tar.gz` + `nist_failed_cases.log`
- `xmerl_xsd_Sun2002-01-16_SUITE_data/` → `suntest.tar.gz` + `sun_failed_cases.log`
