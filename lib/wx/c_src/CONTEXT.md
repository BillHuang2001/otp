# wx native glue (`lib/wx/c_src`)

## Intent
Hand-written C/C++ that implements the Erlang `wx` application's native side.
Exposes wxWidgets (plus OpenGL/GLU) as a NIF driven by an Erlang command queue, so all GUI work happens on one dedicated native thread.
`gen/` holds the machine-generated half (see `gen/CONTEXT.md`).

## API Surface
Outputs two shared libraries into `../priv/$(SYS_TYPE)/` (on Windows also `WebView2Loader.dll` and `.pdb` files):
- `wxe_driver$(SO_EXT)` — the wxWidgets driver NIF; registers Erlang module `wxe_util` (`ERL_NIF_INIT(wxe_util, ...)`).
- `erl_gl$(SO_EXT)` — the OpenGL/GLU NIF; loaded lazily as module `gl` by `gl:init_nif/0` only when GL is first used.

NIF entry points (`wxe_nif.c`/`wxe_nif.h`): `queue_cmd/1..15`, `init_opengl/2`, `make_env/0`, `delete_env/1`, `debug_driver/1`, `get_consts_impl/0`.
`wxe_nif.h` also holds the `WXE_*` op-code and state macros (`WXE_SHUTDOWN`, `WXE_CB_*`, `WXE_DESTROY_OBJECT`, `WXE_REGISTER_OBJECT`, `OPENGL_START`) and the `wxe_me_ref` handle type.

Hand-written units:
- `wxe_nif.c` — NIF table, atom cache (`WXE_ATOM_*`), `wxeMemEnvRt` resource type, term→C converters (`wxe_get_size_t/float/double`, `get_ptr`).
- `wxe_main.cpp` — GUI-thread lifecycle: `start_native_gui`/`stop_native_gui`, `wxe_main_loop` running `wxEntry`; on Darwin it steals the main thread via `erl_drv_steal_main_thread`.
- `wxe_impl.cpp`/`.h` — `WxeApp` (a `wxApp`), command dispatch, the pointer↔ref object map (`ptr2ref`, `newPtr`/`getRef`/`clearPtr`/`getRefData`), delayed-delete bookkeeping, `wxe_fns_t` dispatch-table type.
- `wxe_helpers.cpp`/`.h` — `wxeCommand`, `wxeFifo` command queue, `wxeMetaCommand` wx event, `wxeErlTerm`/`wxETreeItemData` (term holders attached to wx client data).
- `wxe_callback_impl.cpp`/`.h` — Erlang callbacks: `wxeEvtListener` (forwards wx events to an Erlang pid), `handle_event_callback`, `wxEListCtrlCompare` (wxListCtrl sort callback).
- `wxe_return.cpp`/`.h` — `wxeReturn`: typed `make(...)` overloads (refs, atoms, strings, point/size/rect, colour, arrays, html link) plus `send`/`send_callback`.
- `wxe_gl.cpp`/`.h` — GL dispatch inside the driver: `gl_dispatch`, `setActiveGL`/`deleteActiveGL(Context)`, `wxe_initOpenGL`, and the `glc` canvas↔context map (`wxe_glc`).
- `egl_impl.c`/`.h` — GL entry-point loading (`egl_load_functions` over `gl_fns[]`) via dlsym, tessellation helpers, GL-side argument converters; compiled into `erl_gl`.
- `wxe_events.h` — event-table types (`wxe_evInfo`, `wxeEtype`) and `sendevent`.
- `wxe_memory.h` — `wxeMemEnv` (per-Erlang-process ref→ptr table), `wxeRefData` (object class/owner/deletion metadata), `wxe_badarg` exception, `ptrMap`.
- `wxe_ps_init.c` — pre-`wxEntry` platform init: Darwin sets process name/icon from `WX_APP_TITLE`/`WX_APP_ICON`; Windows prepends `WX_PRIV_DIR` to `PATH` so wx DLLs load; no-op elsewhere. Compiled with the Objective-C compiler on Darwin.
- `wxe_win32.rc` — Windows resource script (icon/version info), compiled to `$(SYS_TYPE)/wxe_win32.res`.
- `Makefile.in` — autoconf template producing `c_src/Makefile`; defines the object sets, both link rules and `release_spec`.

## Constraints
- Never hand-edit anything under `gen/`; it is generated by `../api_gen/` (see `gen/CONTEXT.md`).
- Build depends on `../configure` substitutions (`@WX_CFLAGS@`, `@WX_LIBS@`, `@GL_LIBS@`, `@CC@`, `@CXX@`, `@OBJC_CC@`, `@SO_EXT@`, `@WXERL_SYS_TYPE@`, …); the generated `c_src/Makefile` is a configure output (listed in `../prebuild.skip`) and is not committed.
- All object files and libraries live under `$(SYS_TYPE)/` / `../priv/$(SYS_TYPE)/`, where `SYS_TYPE = @WXERL_SYS_TYPE@` is the target platform (`win32` on Windows, the host triple otherwise); these are build artifacts.
- `TYPE=opt` (default) or `TYPE=debug` selects the opt/debug wx and C flags; on Darwin with a debug wxWidgets the `@FORCED_DEBUG_BUILD@` macro forces `TYPE=debug`.
- Generated `gen/*.cpp` are compiled with `CXX_O_NO_OPT` (optimization off), unlike the hand-written units.
- `HAVE_OPENGL` is hard-coded `true`, so `erl_gl` is always built.

## Dependencies
- A system wxWidgets build with GL/GL-canvas support (and optionally webview) discoverable through `wx-config`; `../configure.ac` checks the compiler, the wx version, whether the wx webview is available, whether wx static libs are used, and whether a wx program links.
- OpenGL + GLU headers and libs (`-framework OpenGL` on Darwin, `-lglu32 -lOpengl32` on Windows, `-lGL -lGLU` elsewhere), plus glib in the wx cflags.
- A C++ compiler for the `.cpp`/`.c` units and an Objective-C/Cocoa compiler for `wxe_ps_init.c` on Darwin.
- `erl_nif.h` and the OTP build's `$(DED_INCLUDES)` (`make/$(TARGET)/otp_ded.mk`).

## Design Decisions
- Split into two libraries: `wxe_driver` links wxWidgets only, while `erl_gl` (loaded lazily as module `gl`) owns GL/GLU; the driver learns GL function pointers through `wxe_util:init_opengl/2` rather than linking GL itself.
- One dedicated wxWidgets GUI thread runs the whole wx main loop; Erlang processes enqueue `wxeCommand`s into a `wxeFifo` via `queue_cmd/N` and get results back asynchronously (`wxeReturn` sends `_wxe_result_`/`_wxe_error_` messages), so the emulator never blocks on GUI work.
- Raw wx pointers never cross into Erlang: each object is tracked in a per-process `wxeMemEnv` ref table and referenced as `{wx_ref, Ref, Type, Class}`; `wxeRefData` records its class, owning pid and whether the wx or the Erlang side deletes it.
- The NIF surface stays tiny and stable (`queue_cmd/N`); the huge wxWidgets API is reached through the op-number-indexed generated wrappers, so adding classes normally only touches the generator.

## Notes for Agents
- To trace an Erlang `wx` call: Erlang API → `queue_cmd/N` in `wxe_nif.c` → `push_nif`/`WxeApp::dispatch` in `wxe_impl.cpp` → entry in `gen/wxe_func_table.cpp` → body in `gen/wxe_wrapper_*.cpp` → reply via `wxeReturn`.
- `wxe_impl.cpp` intentionally does `#define private public` around `<wx/dcbuffer.h>` (a `wxBufferedDC` crash workaround) and installs a non-fatal X error handler for benign asynchronous GLX `BadMatch` errors on `SwapBuffers` during GL teardown (GLX/X11 backend only; wx 3.2+ EGL/Wayland builds take no Xlib path).
- `wxeRefData::type` codes in `wxe_memory.h` (0=wxWindow subclasses, 1=wxObject subclasses, 2=wxDialog subclasses, 3=allocated-but-not-returned, 4=non-overloadable wxGraphicsObjects, 8=always delete directly (wxDC), >10=no virtual dtor / stack-allocated) drive the delete-vs-defer decision; changing them changes object lifetime.
- Verbose native logging to stderr is gated on `wxe_debug` (set from Erlang via `wx_util:debug/0`).
- `wxe_gl.cpp` is the only place that touches the GL canvas/context map; GL calls themselves go through the `erl_gl` NIF, not here.

## Routing Table
- `gen/` → machine-generated wxWidgets/OpenGL NIF wrappers and tables (`wxe_wrapper_*.cpp`, `wxe_func_table.cpp`, `wxe_events.cpp`, `wxe_init.cpp`, `gl_nif.cpp`, `glu_nif.cpp`, …) — produced by `../api_gen/`, never hand-edit.
- Sibling (read-only, escalate writes to parent): `../api_gen/` → the Erlang code generator and its `*.conf`/doxygen specs that emit `gen/`; `../src/` → the Erlang `wx` API (incl. `src/gen/gl.erl` which loads `erl_gl`).
