# dialyzer — Common Test suite directory

## Intent
Common Test suites for the `dialyzer` application: they exercise the public `dialyzer`/`typer` APIs, the PLT build/update machinery, the type subsystem (`erl_types`), and Dialyzer's warning output against curated input files with expected results.
Two kinds of suites live here: hand-written suites (checked in as `*_SUITE.erl`) and auto-generated suites produced at release time from `*_SUITE_data/` directories.

## API Surface
- `dialyzer_common.erl` — shared helper/generator. Exports `check_plt/1` (build-or-validate the shared test PLT in the CT run dir), `check/4` (run one test case), `create_all_suites/0` (regenerate every `*_SUITE.erl` from its `*_SUITE_data` dir), `new_tests/2` (list src test cases not yet declared), `plt_file/1`. Compiled by `Makefile` at release time and run via `erl -noshell -run dialyzer_common create_all_suites`.
- `file_utils.erl` — `list_dir/3`, `file_type/1`, `diff/2` (LCS-based file diff used to compare actual vs expected warnings; skips SPDX header lines).
- `dialyzer_test_constants.hrl` — defines `?plt_timeout` = `{hours, 2}`.
- `dialyzer.spec` — `{suites, "../dialyzer_test", all}`; drives `ct_run` against the installed test dir.
- `dialyzer.cover` — cover config (`{incl_app,dialyzer,details}`).
- `Makefile` — installs `AUXILIARY_FILES` plus `*_SUITE_data`/`property_test` into `RELSYSDIR = $(RELEASE_PATH)/dialyzer_test`, compiles the helpers, then generates the suites (`release_tests_spec`).
- `README` — the (authoritative) convention for adding test cases and new suites.

## Test Strategy
- Run from the app dir with `make test` in `lib/dialyzer` (the tests need an installed release: `release_tests_spec` populates `$(RELEASE_PATH)/dialyzer_test`, then `ct_run` runs `dialyzer.spec`).
- A single suite/case can be run with `ct_run`, e.g. `$ERL_TOP/bin/ct_run -suite ../dialyzer_test/dialyzer_SUITE -case app_test`.
- The hand-written suites build the shared test PLT themselves in `init_per_suite/1` via `dialyzer_common:check_plt(priv_dir)`, and `{skip, "Plt creation/check failed."}` if it fails.
- The PLT is cached as `dialyzer_plt` in the CT run (priv) dir; if present it is re-validated with a `plt_check` analysis, otherwise it is (re)built by extending the system default PLT with `erts`, `kernel`, `stdlib`, falling back to a from-scratch `plt_build` (with `no_unknown`).
- A `plt_lock` marker file in the run dir prevents concurrent PLT builds, so Dialyzer suites must NOT run in parallel (see `dialyzer_common`).
- PLT build/check can take up to `?plt_timeout` (2 hours); generated suites set `init_per_suite/0` timetrap to it.
- Most test cases call `dialyzer:run/1` with `[{files, Files}, {from, src_code}, {init_plt, Plt}, {check_plt, false}]` + suite options, format warnings via `dialyzer:format_warning/2`, sort, write them to the priv dir, and diff against the expected file in `results/`.

## Auto-generated suites (do NOT hand-edit `*_SUITE.erl` for these)
- A `*_SUITE_data/` dir containing a `src/` subdir is turned into `<name>_SUITE.erl` by `dialyzer_common:create_all_suites/0` at release time (the generated `.erl` is NOT checked in; only the `_data` dir is).
- Each generated suite has one test case per `.erl` file (or per subdirectory of `.erl` files) in `_data/src/`, plus a `<name>_SUITE_consistency` case that fails with `{missing_tests, New}` if a src test case is not declared.
- `_data/dialyzer_options` supplies `{dialyzer_options, List}` (Dialyzer options; e.g. `{warnings, [no_unknown]}`) and optional `{time_limit, Minutes}` (default 1 minute) per test case.
- Expected warnings go in `_data/results/<testcase>`; a missing/empty expected file means "no warnings".
- The generated header says "Use './remake' script to refresh it" — no such script exists in this tree; regenerate via `create_all_suites` (release) instead.
- `_SUITE_data` dirs WITHOUT a `src/` subdir (`cplt_SUITE_data`, `iplt_SUITE_data`, `incremental_SUITE_data`, `dialyzer_cl_SUITE_data`) are plain data for hand-written suites and are not used to generate suites; `dialyzer_cl` (and `plt`) are also explicitly excluded in `dialyzer_common`.

## Suites
- `abstract_SUITE.erl` — hand-written; abstract-code edge cases (generated/autogenerated annotations, `test/5` on abstract forms).
- `cplt_SUITE.erl` — hand-written; classic-PLT operations (build/update/remove/merge, `plt_check`, module-dependency tracking) using `cplt_SUITE_data/type_deps.erl`.
- `dialyzer_SUITE.erl` — hand-written; app-level smoke (`app_test`, `appup_test`), cplt/iplt info, mixing classic & incremental mode, `file_list`, `line_coverage`; uses `ts_install_cth`.
- `dialyzer_cl_SUITE.erl` — hand-written; the `dialyzer_cl` API on BEAM, callsite info in warnings, bad `-pa` dir; data in `dialyzer_cl_SUITE_data/` (`data_dir`); builds its own base PLT.
- `dialyzer_utils_SUITE.erl` — hand-written; unit tests for `dialyzer_utils` (`p_map` semantics/ordering).
- `erl_types_SUITE.erl` — hand-written; `erl_types` consistency/`to_string`, map representations, and a `property_tests` group (absorption/associativity/commutativity/idempotence/identity/limit) run via `ct_property_test` against `property_test/erl_types_prop.erl` (PropEr only; skipped if `proper_erlang_abstract_code` is unavailable).
- `iplt_SUITE.erl` — hand-written; incremental-PLT build/update, iplt info & module deps; data in `iplt_SUITE_data/`; suite timetrap is `?plt_timeout`.
- `incremental_SUITE.erl` — hand-written; incremental mode reporting, stored warnings, legal-warnings/select-warnings, app/env/xdg config; data in `incremental_SUITE_data/`.
- `typer_SUITE.erl` — hand-written; `typer` smoke tests, incremental PLT, contract violations; uses `ts_install_cth`.
- Generated from data (each `*_SUITE_data` has `src/` + `results/`): `behaviour`, `callgraph`, `default_ignore_overlapping_contract`, `extra_return`, `indent`, `indent2`, `line`, `map`, `missing_return`, `nowarn_function`, `opaque`, `options1`, `options2`, `options3`, `overlapping_contract`, `overspecs`, `r9c`, `small` (large corpus of warning cases), `specdiffs`, `underspecs`, `unmatched_returns`, `user`.

## Constraints
- Never hand-edit the auto-generated `*_SUITE.erl` (e.g. `small_SUITE.erl`, `options*_SUITE.erl`) — they are produced from the matching `_data` dir; change the `_data` inputs/results/options instead.
- Add/adjust expectations only through `_SUITE_data/src` (inputs) and `_SUITE_data/results` (expected), plus `dialyzer_options` for options/time limit.
- Dialyzer suites share one PLT keyed by the CT run dir and use a lock file, so they must be run sequentially, not in parallel.

## Notes for Agents
- The generated suites are absent from the source tree; only `dialyzer_common:create_all_suites/0` (release) creates them, so grepping for `small_SUITE.erl` etc. finds nothing in a plain checkout.
- `dialyzer_common:check/4` returns `same` or `{differ, TestCase, Diff}`; `diff` output is XML-escaped and comment/blank differences are ignored.
- `plt_timeout` (2 hours) also bounds PLT creation; a leftover `plt_lock` without a PLT makes `check_plt/1` fail with an explanatory message.
- `options1_SUITE_data/` carries a stale `my_include/CVS/` dir (VCS leftovers) — harmless.

## Dependencies
- Common Test (`common_test`) and `stdlib`/`kernel`; the property group needs PropEr and `proper_erlang_abstract_code`.
- Tests run against a released Erlang/OTP (test dir installed as `$(RELEASE_PATH)/dialyzer_test`).
