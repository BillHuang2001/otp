# Common Test (`lib/common_test/`)

## Intent
The **common_test** OTP application (`COMMON_TEST_VSN = 1.31.2`, see `vsn.mk`) — the automated test framework used to test every other OTP application and by external users.
It provides the `ct` Erlang API, the `ct_run` command-line tool, the suite behaviours (`ct_suite` / suite callbacks, `ct_hooks`/`ct_hook`), test-spec handling, distributed test execution (`ct_master`) and HTML/XML log generation.
The historical Test Server (`test_server*` modules in `src/`, plus the legacy `test_server/` harness dir) is bundled inside this application.

## API Surface
- `src/common_test.app.src` — app resource: version `%VSN%`, ~45 modules, registered processes `ct_logs`, `ct_util_server`, `ct_config_server`, `ct_make_ref`, `ct_master`, `ct_master_logs`, `test_server_ctrl`, `test_server`, `test_server_break_process`.
  Hard dependencies are only `kernel` and `stdlib`; `runtime_dependencies` (compiler, crypto, debugger, ftp, inets, observer, runtime_tools, sasl, snmp, ssh, syntax_tools, tools, xmerl) are *optional* runtime apps that must be used lazily.
- `src/common_test.appup.src` — release-upgrade instructions template.
- `include/` — the **public** headers `ct.hrl` (peer-node macros, importance/verbosity levels, legacy `?config`/`?line` shims), `ct_event.hrl` (`#event{}` for event handlers) and `ct_property_test.hrl` (property-test macros for EQC/PropEr/Triq).
- `src/` — implementations; entrances are `ct`, `ct_run` (driven by the `bin/ct_run` C launcher from `erts/etc/common/ct_run.c`), the execution driver `test_server_ctrl`, the suite semantics in `ct_framework`, logging in `ct_logs`/`erl2html2`, specs in `ct_testspec`, hooks in `ct_hooks`, and connectivity helpers `ct_telnet`/`ct_ssh`/`ct_ftp`/`ct_snmp`/`ct_netconfc`/`ct_gen_conn`.
- `proper_ext/` — `ct_proper_ext`/`ct_quickcheck_ext`, shipped in `lib/common_test-<VSN>/proper_ext` and used by `ct_property_test`.
- `priv/` — `ct_default.css`, jQuery/tablesorter JS and `tile1.jpg` used by the HTML logs; `priv/Makefile.in` is configured by `configure.ac`.
- `test_server/` — the legacy Test Server *harness* (`ts`, `ts_run`, `ts_install`, `ts_install_cth`, …): the build/install frontend used by `make test` and cross-compile CI; **not** the runtime Test Server.
- `Makefile` — `SUB_DIRECTORIES = doc src priv proper_ext`; includes `../make/app_targets.mk`, declares `VSN = $(COMMON_TEST_VSN)`, `DIA_PLT_APPS = compiler tools crypto runtime_tools syntax_tools ftp inets debugger sasl snmp ssh reltool observer xmerl`, and `TEST_NEEDS_RELEASE=true`.
- Builds in place: `../ebin/common_test.app` + beams; `TEST_NEEDS_RELEASE=true` means `make test` runs the suites against an installed release (`$(RELEASE_PATH)/common_test_test`).
- `configure` / `configure.ac` — own autoconf step (generated by `./otp_build update_configure`, never edited by hand); it only configures `priv/$host/Makefile` for the OS-specific priv setup and runs as part of the top-level `./configure`.
- `prebuild.skip` — empty marker file (nothing to skip when prebuilding this app during bootstrap).

## Constraints
- This app must remain able to test **all** other OTP applications: never add a hard dependency beyond `kernel`/`stdlib`; use the optional apps (crypto, ssh, snmp, netconf, telnet, observer, debugger, xmerl, tools…) only lazily at run time.
- All sources compile with `-Werror` (`+warn_obsolete_bool_op +nowarn_deprecated_catch`) — keep the tree warning-free.
- Internal headers (`src/ct_util.hrl`, `src/test_server_internal.hrl`, `src/ct_netconfc.hrl`) are *not* public; only `include/` is installed and may be relied on by suites.
- `doc/notes.md` is the app's release notes file and must be updated for user-visible changes; module documentation is written in the `-doc`/`-moduledoc` attributes of `src/*.erl`, not in `doc/`.
- `ebin/`, `doc/html/`, `man*/` and `priv/$host/` are build outputs — never edit or commit.

## Dependencies
- Erlang/OTP build toolchain from the repo root (`ERL_TOP`, `make/target.mk`, `make/otp.mk`, `make/app_targets.mk`, `make/doc.mk`).
- GNU autoconf ≥ 2.71 for the bundled `configure.ac` files; `test_server/` additionally needs `config.guess`/`config.sub`/`install-sh` and a C compiler/make at test time.
- Optional run-time integrations: OpenSSL-backed `crypto`, `ssh`, `snmp`, `inets`/`ftp`, `xmerl`, `tools` (cover/xref), `observer`/`debugger`, and the Quviq QuickCheck / PropEr / Triq tools for property testing.

## Design Decisions
- **`common_test` vs `test_server` split**: the historical Test Server provides the framework-agnostic execution core (`test_server`, `test_server_ctrl`, `test_server_io/gl/node/sup`) while `common_test` supplies the suite semantics, hooks, logging and CLI; the suite-behaviour dispatch goes through `test_server_sup:framework_call/2,3,4` to the module named by the `TEST_SERVER_FRAMEWORK` environment variable (CT sets it to `ct_framework`).
- The old `test_server/` directory was kept as a separate, self-contained harness with its own autoconf because `make test`, `ts:install()` and cross-compilation CI still depend on its workflow (`variables` file, data-dir `Makefile.src` substitution) — it is legacy but live code.
- Property-testing support was kept out of the app (in `proper_ext/`) so no property-testing tool becomes a dependency of CT.

## Test Strategy
- CT tests CT: `test/` holds ~53 suites that start nested CT runs (on `ct_test_support:start_slave/3` nodes) against dummy suites in sibling `*_SUITE_data/` dirs, then assert on the event stream, logs and results.
- `TEST_NEEDS_RELEASE=true` → run from `lib/common_test` with `make test` (or repo-root `make test`) against an installed release; the suites are installed as `$(RELEASE_PATH)/common_test_test` with `test/common_test.spec` (all) or `test/common_test_gh.spec` (GitHub CI, skips `ct_release_test_SUITE`).
- Coverage config `test/common_test.cover` (`{incl_app,common_test,details}`); several suites self-skip when a capability is missing (SSH/SNMP/netconf, QuickCheck, Windows, cross-compilation).

## Notes for Agents
- The legacy `test_server/` harness is easy to confuse with the runtime Test Server in `src/` — read `test_server/CONTEXT.md` before touching it.
- `bin/ct_run` is not built from this directory; it comes from `erts/etc/common/ct_run.c` and runs `erl -s ct_run script_start`.
- There is no OTP `supervisor` inside CT: `ct_util_server`, `ct_config_server` and `ct_logs` are hand-rolled `register/2` + `spawn_link` receive loops, not `gen_server`s (see `src/CONTEXT.md`).
- `ct_make_ref` is still listed in `common_test.app.src`'s `registered` list although no module registers it (stale entry) — do not read it as an existing process.
- `ct_slave` is deprecated in favour of `peer`; `ct_ftp` is deprecated as well.
