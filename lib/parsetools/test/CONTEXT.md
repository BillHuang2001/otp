# parsetools — Test Suite

## Intent
Common Test suite directory for the `parsetools` application: it verifies the `yecc` LALR(1) parser generator and the `leex` lexer generator end-to-end, plus the app/appup file consistency.
All tests live in `*_SUITE.erl` files in this directory; there is no `*_SUITE_data/` fixture directory.

## API Surface
- `yecc_SUITE.erl` (~2.3k lines) — `all/0` = `[app_test, {group,checks}, {group,examples}, {group,bugs}, {group,improvements}]`.
  - groups: `checks` = `[file, syntax, compile, rules, expect, conflicts, deterministic]`; `examples` = `[empty, prec, yeccpre, lalr, old_yecc, other_examples]`; `bugs` = `[otp_5369, otp_6362, otp_7945, otp_8483, otp_8486, otp_17535]`; `improvements` = `[otp_7292, otp_7969, otp_8919, otp_10302, otp_11269, otp_11286, otp_14285, otp_17023]`.
- `leex_SUITE.erl` (~1.4k lines) — `all/0` = `[{group,checks}, {group,examples}, {group,tickets}, {group,bugs}]`.
  - groups: `checks` = `[file, compile, syntax, deterministic]`; `examples` = `[pt, man, ex, ex2, not_yet, unicode, column_support]`; `tickets` = `[otp_10302, otp_11286, otp_13916, otp_14285, otp_17023, compiler_warnings]`; `bugs` = `[line_wrap]`.
- `app_SUITE.erl` — `all/0` = `[app, appup]`; `test_server:app_test(parsetools)` and `test_server:appup_test(parsetools)` (`app_test` in `yecc_SUITE` duplicates the former).
- `parsetools.spec` — `{suites,"../parsetools_test",all}.` (run all suites from the installed `parsetools_test` dir).
- `parsetools.cover` — `{incl_app,parsetools,details}` (coverage of the app itself).
- `Makefile` — `MODULES = app_SUITE leex_SUITE yecc_SUITE`, `EBIN = .` (objects compiled in place); `erl -make` on an `Emakefile` generated by `$(ERL_TOP)/make/make_emakefile`; `release_tests_spec` installs the suites + spec + cover + Emakefile into `$(RELEASE_PATH)/parsetools_test`.

## Test Strategy
Both big suites are self-contained: each test case embeds its grammar/scanner fixture as a binary literal, so nothing is read from `data_dir`.
Table-driven helpers drive nearly every case:
- `run(Config, Tests)` iterates a list of `{Name, Fixture, PreInclude, [Opts], Expected}` tuples and `ct:fail`s with expected-vs-got on mismatch.
- `run_test/3,4` writes the fixture to `priv_dir` as `yecc_test.yrl` / `leex_test.xrl`, runs `yecc:file/2` / `leex:file/2` with `[return,{report,false}]` (+ `{includefile,Pre}` when not `default`), then `compile:file` of the generated `.erl` (`[return, warn_unused_vars, {outdir,PrivDir}]`), `code:purge` + `code:load_abs` the module and calls its `t/0`, which asserts on `parse/1` / `string/1` results; the returned value is compared to the case's expected value (usually `ok`).
- `yecc_SUITE`'s `run_test` also snapshots the port/process list (`pps/0`) around `yecc:file` and fails if yecc leaked ports or processes.
- `leex_SUITE`'s `run_test` passes `[verbose, dfa_graph, {error_location, column}]` to `leex:file` purely for code coverage.
- Error paths assert the exact `{error,[{File,[{Loc,Module,Message}]}],Warnings}` / `{ok,Outfile,Warnings}` shapes from `yecc:file`/`leex:file`, the `format_error/1` text of the returned module, and whether the output file was written (`filelib:is_regular`), across the `return`, `report`, `return_warnings`, `return_errors`, `warnings_as_errors` option combinations.
- The `deterministic` cases compile with `yecc:compile/3` / `leex:compile/3` and the `#options{specific=[deterministic]}` record, then `epp:parse_file` the output and assert (via `search_for_file_attr/2`) that the include's `-file` attribute is the bare basename in deterministic mode and the full path otherwise.
- `syntax`/`rules`/`expect`/`conflicts`/`prec` assert exact error locations (`{Line,Col}` by default, `{Line}` with `{error_location,line}`), warning lists (`unused_terminal`, `unused_nonterminal`, `duplicate_declaration`, `bad_declaration`, `illegal_empty`, `undefined_pseudo_variable`, `{conflicts,S,R}`, …) and conflict counts.
- Coverage areas: bad files/options (`badarg` exits), syntax/declaration validation, `Expect`/`States`, precedence (`Left`/`Right`/`Unary`/`Nonassoc`), `'$empty'` rules (incl. left-corner regressions), LALR-vs-SLR grammars, the legacy `yecc:yecc/2,3,4` API, `parse_and_scan` with fun/MFA scanners and error/throw/exit propagation, `return_error/2`, `'$0'`/`'$n'` pseudo variables, `reserved` symbols, `file_attributes` option, caller-supplied include via `includefile` (`my_yeccpre/0`, `yeccpre_v1_2/0` inline fixtures), encoding (`%% coding:` latin-1/utf-8), Unicode filenames, `{error_location,column}`/`TokenCol`/`tab_size`, and warning-free compilation of generated code (`compiler_warnings`, `otp_17535`).
- leex-specific: `pt` (push-back/skip_token), `man`/`ex` (manual/example scanners), `ex2` (full embedded Erlang tokenizer exercising the incremental `tokens/3` / `token/3` continuation API vs `string/1`), `line_wrap` (locations across lines, `token/2`/`tokens/2` more/done continuation), `not_yet` (`^`/`$` regex errors).
- `otp_11286` in both suites spawns a peer node with `?CT_PEER(["+fnu"])` (from `ct.hrl` → `test_server:start_peer/2`) and does file/yecc/leex/compile work via `rpc:call` in a directory whose name contains a >255 Unicode codepoint.
- `otp_17023` in both suites sets/un-sets `ERL_COMPILER_OPTIONS` to check that explicit options and the env var interact as documented, restoring the previous value.
- leex's `file` case uses `unwritable/1`/`writable/1` (chmod via `file:write_file_info`) to check write errors on the `.erl`/`.dot` outputs.

## How the suites locate modules and templates
- Header records/helpers come from `-include_lib("stdlib/include/erl_compile.hrl")` (`#options{}` for `yecc:compile/3`/`leex:compile/3`), `stdlib/include/assert.hrl`, `common_test/include/ct.hrl`, and (leex) `kernel/include/file.hrl` for `#file_info{}`.
- The app under test is used as the *installed* `yecc`/`leex` module; `default_yeccpre/0` resolves the template with `filename:join([code:lib_dir(parsetools),"include","yeccpre.hrl"])`, so tests exercise the installed `parsetools` (its `include/` dir), not `../include`.
- Generated-code checks reach into stdlib/compiler: `compile:file/2`, `epp:parse_file/2`, `erl_scan:string/2,3`, `erl_parse:parse/1`, `erl_parse:parse_and_scan/1`, `erl_anno:new/1`.
- `-ifdef(debug)` fallback in both big suites defines `?config/2`, `?datadir` and `?privdir` as plain strings (`*_SUITE_data` / `*_SUITE_priv`) so a suite can be compiled with `erlc -Ddebug` and its case functions called directly without Common Test; under CT the macros expand to `data_dir`/`priv_dir`.
- All fixtures/artifacts are written to `priv_dir`, with generated modules named `yecc_test` / `leex_test` (fixed names, purged and reloaded each run).

## Constraints
- `suite() -> [{ct_hooks,[ts_install_cth]}]` in all three suites: the OTP test-system hook is required (peer nodes, installdir handling); a bare `ct_run` without it will not work.
- Keep `MODULES` in `Makefile` in sync when adding a suite.
- `ERL_COMPILE_FLAGS` adds `+nowarn_missing_spec_documented` and filters out `+deterministic`; the filter is deliberate — the `deterministic` cases compare full-path vs basename `-file` attributes and break if the suites themselves are compiled with `+deterministic` semantics.
- Do not add a `*_SUITE_data/` dir expecting it to be shipped: the tar line for it in `release_tests_spec` is commented out.

## Known Issues
- `yecc_SUITE:syntax`, `otp_7292` assert generated-code line numbers as `N + SzYeccPre` where `SzYeccPre` is the line count of `include/yeccpre.hrl`; any edit to that template must keep these offsets in mind (the `pps/0`-style process-snapshot and line-offset checks are intentionally brittle).
- leex's `unwritable/1` chmod-based checks assume a non-root user; running the suite as root makes the write succeed and the expected `{file_error,_}` assertions fail.
- `ex2` embeds a hand-maintained Erlang tokenizer (`erlang_scan.xrl`) whose `reserved_word/1` list is not the real `erl_scan` one; it is a fixture, not a spec.

## Notes for Agents
- Build the suites in place from this dir with `make` (needs `ERL_TOP` and the OTP test makefiles); run a single case with `ct_run -suite yecc_SUITE -case conflicts` (or `-group checks`); the full suites take minutes.
- `?datadir` is defined in both big suites but never used — don't go looking for fixture files.
- The tests need a full OTP: `compiler`, `stdlib` (`compile`, `epp`, `erl_scan`, `erl_parse`) and Common Test with peer-node support (`otp_11286`).
- `Test Strategy` above lists how each case names itself; ticket-numbered cases (`otp_NNNNN`) keep the historical ticket name for the behaviour they pin — the same ticket may appear in both suites.
