# parsetools — Code Templates for Generated Modules

## Intent
Holds the two source templates that the `parsetools` generators splice into the modules they emit — not ordinary compiled/`-include`d headers used by normal Erlang code.
- `yeccpre.hrl` (Apache-2.0, ~189 lines) is textually inserted by `yecc` into the generated parser, *after* the generator has already emitted the `-module`/`-export`/`-file` prologue (sentinel comment at line 24: "The parser generator will insert appropriate declarations before this line.").
- `leexinc.hrl` (BSD-2-Clause, 376 lines; originally Robert Virding's leex) is a template copied line-by-line by `leex`, with marked lines replaced by generated code.
Both are installed verbatim to `$(RELEASE_PATH)/lib/parsetools-$(VSN)/include` (see `../src/Makefile`, `HRL_FILES`, line 45/103).

## API Surface

### `yeccpre.hrl` — runtime support body of a generated parser
Defines (into the generated module's namespace, so `?MODULE` = the grammar's module):
- `parse/1`, `parse_and_scan/1`, `format_error/1` — the three functions the generator exports; they build the initial `yeccpars0/5` call.
- `yeccpars0/5` — try/catch trampoline; converts an internal `error` (via `yecc_error_type/2`) into `{yecc_bug, ?CODE_VERSION, Desc}` and rethrows, and returns `throw:{error,{Location,?MODULE,Message}}` from `return_error/2` as `{error,...}`.
- `yecc_end/1`, `yecctoken_end_location/1`, `yecctoken_location/1`, `yecctoken_to_string/1`, `yecctoken2string/1`, `yecctoken2string1/1` — location/text helpers built on `erl_scan:text/1`, `erl_scan:location/1`, `erl_anno:end_location/1`.
- `yeccerror/1` — builds `{error,{Location,?MODULE,["syntax error before: ",Text]}}`.
- `return_error/2` — user-visible helper; throws `{error,{Location,?MODULE,Message}}`.
- `yeccpars1/5` and `yeccpars1/7` — the multiplexer called from generated code (see the `yeccpars1/7` warning below).
- `-type yecc_ret() :: {'error', _} | {'ok', _}.`
- `-define(CODE_VERSION, "1.4").` — the generated-code schema version; must stay in sync with `../src/yecc.erl` (`-define(CODE_VERSION, "1.4")`, line 2594) since both embed it in the `yecc_bug` error.
Not defined here: `yeccpars2/7`, `yeccgoto_*`, `yeccpars2_*` — those are generated by `yecc`.
Optional doc injection: if the caller defines `YECC_PARSE_DOC` / `YECC_PARSE_AND_SCAN_DOC` / `YECC_FORMAT_ERROR_DOC`, the matching `-doc ?MACRO.` (lines 28–48) attaches a doc attribute to `parse/1`, `parse_and_scan/1`, `format_error/1`.

### `leexinc.hrl` — template with `##` substitution directives
`leex` copies the file line by line; any line whose first 5 chars match a directive is replaced, all other lines are emitted verbatim (`../src/leex.erl`, `out_file/8`, lines 1860–1880 — matching uses `string:slice(Line,0,5)`, so only the first five characters are significant).
Directive lines (line no. → generated output):
- `##module` (41) → `-module(Name).` (`out_module/2`).
- `##code` (47) → the user's Erlang code extracted from the `.xrl`.
- `##str` (58) → the `string/1,2` wrappers plus the `do_string/5` body (`out_string/2`); `error_location` option picks `Line` or `{Line,Col}` result shape.
- `##tkn` (110) → the `token/2,3` wrappers plus `do_token/4` (`out_token/2`).
- `##tks` (187) → the `tokens/2,3` wrappers plus `do_tokens/4` (`out_tokens/2`).
- `##tab_size` (358) → `tab_size/0` (`out_tab_size/2`).
- `##dfa` (370) → the `yystate/0,1` transition functions (`out_dfa/8`).
- `##actions` (376) → the `yyaction/5` functions (`out_actions/4`).
Functions present in the template body (all resolved against the generated module): `format_error/1`, `do_string/5`, `string_cont/5`, `do_token/4`, `token/10`, `token_cont/4`, `do_tokens/4`, `tokens/11`, `tokens_cont/5`, `skip_tokens/4`, `skip_tokens/11`, `skip_cont/5`, `yyrev/1,2`, `yypre/2`, `yysuf/2`, `adjust_line/4`, `adjust_col/3`, `tab_forward/1`.

### Version/override contract
- `yecc` uses `lib/parsetools/include/yeccpre.hrl` unless the user passes `{includefile, File}` to `yecc:file/2`; a custom prelude must define `yeccpars1/7` (comment at lines 112–117), because `yecc` detects the "1.4" prelude by parsing the file for a `yeccpars1/7` function (`includefile_version/1` / `parse_file/1`, `../src/yecc.erl` lines 3167–3189) and otherwise assumes the old, incompatible "1.1" prelude that defined `yeccpars1/5`.
- `leex` uses `lib/parsetools/include/leexinc.hrl` unless the `includefile` option points elsewhere (`../src/leex.erl`, line 261/488).

## Constraints
- `yeccpre.hrl` contains **no `-module`/`-export`/`-include`** attributes — the generator emits those before splicing it in; do not add module attributes here.
- `leexinc.hrl` cannot be compiled directly: its eight `##...` directive lines and its use of `##` at column 0 are not valid Erlang; never add either file to any compile/`MODULES` list.
- Both files use `?MODULE` to refer to the *generated* module — never hard-code a module name.
- Where both templates reference generated names (`yeccpars2/7`, `yystate/1`, `yyaction/5`, `yystate()/0`, `tab_size()/0`) the shape must match what the corresponding generator emits; changing an emitted-code signature requires coordinated edits in `../src/yecc.erl` / `../src/leex.erl`, the template, and (yecc) `CODE_VERSION`.
- License: generated scanners are the property of the scanner's author, not covered by leex's BSD-2-Clause (note at `leexinc.hrl` lines 35–39).

## Known Issues / Notes for Agents
- `-compile({nowarn_unused_function, F/A})` is used for helpers reachable only from some grammars (`return_error/2`, `yeccerror/1`, `yecctoken_to_string/1`, `yecctoken2string/1`, `yecctoken2string1/1`); do not "clean these up" — they are flagged for valid reasons and used by generated code that does not appear in this file.
- The `leexinc.hrl` continuation protocol is opaque tagged tuples returned inside `{more,Continuation}`: `{token,State,Line,Col,Tcs,Tlen,TokenLine,TokenCol,AccAction,AccLen}` for `token/2,3`, and `{tokens,...}` / `{skip_tokens,...}` with an extra accumulator for `tokens/2,3`; re-entry appends the new chars with `Tcs ++ Chars`.
- `yecc_error_type/2` only handles `function_clause` on a `yeccgoto_*` function, reporting `{Symbol,State,missing_in_goto_table}`; other internal errors fall through to a plain rethrow.
- `adjust_col/3` counts columns by UTF-8 byte width (1–4) and expands tabs via `tab_size()`; `skip_cont/5` and `skip_tokens/4` reuse a stashed error to skip the rest of the token stream.
- `-dialyzer({nowarn_function, ...})` guards the continuation functions (`string_cont/5`, `token_cont/4`, `tokens_cont/5`, `skip_cont/5`).

## Dependencies
- Runtime (of generated code): stdlib `erl_scan` (`text/1`, `location/1`), `erl_anno`, `io_lib`, `lists`; `leex` uses `lists:reverse/1,2`, `lists:sublist/2`, `lists:nthtail/2`.
