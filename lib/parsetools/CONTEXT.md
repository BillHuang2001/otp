# parsetools — Parser and Lexer Generators

## Intent
The OTP `parsetools` application ships the two Erlang code generators: `yecc`, a `yacc`-like LALR(1) parser generator that turns a BNF grammar (`.yrl`) into an Erlang parser module, and `leex`, a `lex`/`flex`-like generator that turns regular-expression rules (`.xrl`) into an Erlang scanner module.
Both are developer tools that run at build time and emit ordinary Erlang modules which are then compiled with `erlc`.
App version is `PARSETOOLS_VSN` in `vsn.mk` (currently `2.8`).

## API Surface
- `yecc:file/1,2` — generate a parser from a `.yrl` grammar; `yecc:format_error/1`; `yecc:compile/3` (the `erl_compile` hook that makes `erlc file.yrl` work); legacy `yecc:yecc/2,3,4` kept for R10B compatibility.
  - `yecc` options: `{includefile, F}` (replace the default `include/yeccpre.hrl` prologue), `{parserfile, F}`, `{error_location, column|line}` (default `column`), `report_errors`/`report_warnings`/`report`, `return_errors`/`return_warnings`/`return`, `warnings_as_errors`, `verbose`, `deterministic`; `ERL_COMPILER_OPTIONS` supplies defaults that are appended to the given options.
- `leex:file/1,2` — generate a scanner from a `.xrl` file; `leex:format_error/1`; `leex:compile/3` (the `erlc` hook).
  - `leex` options: `{includefile, F}` (default `include/leexinc.hrl`), `{scannerfile, F}`, `dfa_graph` (emit a `.dot` graph), `{error_location, line|column}` (default `line`), `{tab_size, N}` (default `8`), `report_*`/`return_*`/`verbose`/`warnings_as_errors`/`deterministic`.
- Generated-module contract:
  - yecc emits a parser exporting `parse/1`, `parse_and_scan/1`, `format_error/1` (the runtime body comes verbatim from `include/yeccpre.hrl`).
  - leex emits a scanner exporting `string/1,2`, `token/2,3`, `tokens/2,3`, `format_error/1` (body from `include/leexinc.hrl`).
- `src/yeccgramm.yrl` is the metagrammar of `.yrl` files and `src/yeccparser.erl` is yecc's own parser generated from it; `src/yeccscan.erl` is yecc's tokenizer.
- App metadata: `src/parsetools.app.src` (`applications [kernel, stdlib]`, `runtime_dependencies ["stdlib-3.4","kernel-3.0","erts-6.0"]`, env `file_util_search_methods`) and `src/parsetools.appup.src` (`{restart_application,parsetools}` for all versions); `%VSN%` is substituted by `sed` in `src/Makefile`.
- Build/config files: `Makefile` (`SUB_DIRECTORIES = src doc`), `vsn.mk`, `AUTHORS`; `ebin/` holds build output only (just a `.gitignore` is tracked).

## Constraints
- Never hand-edit `src/yeccparser.erl`: regenerate it from `src/yeccgramm.yrl` (`make regenerate` in `src/`, i.e. `erlc +deterministic -o yeccparser.erl yeccgramm.yrl`); it is listed in `DEP_SKIP_FILES`.
- The emitted-code version string must stay in sync: `-define(CODE_VERSION, "1.4")` exists both in `src/yecc.erl` and in `include/yeccpre.hrl`, and a mismatch surfaces at runtime as a `{yecc_bug, Version, Desc}` error from a generated parser.
- `src/Makefile` compiles with `-Werror` (plus `+warn_obsolete_bool_op`, `+nowarn_deprecated_catch`, `-I$(ERL_TOP)/lib/stdlib/include`); warnings in the sources break the build.
- The public user documentation is the `-moduledoc` inside `src/yecc.erl` and `src/leex.erl` — there are no `doc/src/*.md` sources, so user-visible behaviour changes must update those moduledocs.
- Both include templates are installed to `$(RELEASE_PATH)/lib/parsetools-$(VSN)/include`, so parsers/scanners generated elsewhere (other OTP apps and user code) depend on this app's installed headers.
- Keep the license split in mind: `src/leex.erl` and `include/leexinc.hrl` are BSD-2-Clause (by Robert Virding) while the yecc files are Apache-2.0; a scanner generated by leex belongs to its author.
- Adding/removing a module means touching `MODULES` in `src/Makefile` and the `modules` list in `src/parsetools.app.src` together.

## Notes for Agents
- Build order: `parsetools` is in `lib/Makefile`'s `ERLANG_APPLICATIONS` (second tier, after `stdlib sasl kernel compiler`) and is the *only* application built under `TINY_BUILD`; it is not part of `ALL_ERLANG_APPLICATIONS`.
- In-tree drivers: `../../make/otp.mk` builds `$(ESRC)/%.yrl` and `$(ESRC)/%.xrl` by invoking `$(ERLC)`, which routes through `erl_compile:compiler/1` (`".yrl" -> {yecc, compile}`, `".xrl" -> {leex, compile}`) → `yecc:compile/3` / `leex:compile/3`; `c:y/1,2` in stdlib calls `yecc:file/1,2` directly.
- In-tree `.yrl` consumers: stdlib `erl_parse.yrl` (built first, during bootstrap), compiler `core_parse.yrl`, edoc, megaco, snmp, tools/xref, xmerl, diameter and parsetools itself; no `.xrl` file ships in OTP (the `leex` targets are exercised only by the suites and external users).
- `git log -p -- lib/parsetools/` is the change history; `doc/notes.md` is the user-facing release-notes document for the app.

## Dependencies
- Runtime/build: only `kernel` and `stdlib` (see `src/parsetools.app.src`); the sources use `erl_scan`, `erl_anno`, `erl_parse`, `epp`, `io`, `io_lib`, `file`, `filename`, `ets`, `lists`, `ordsets`, `orddict`, `sofs`, `string`, `re`, `unicode`, `proplists`, `code`, `os`.
- `erl_compile.hrl` from `lib/stdlib/include` (the `#options{}` record matched by both `compile/3` functions).
- Build-time: GNU make, `erlc`, `sed` for `%VSN%`; `../../make/target.mk`, `../make/$(TARGET)/otp.mk`, `app_targets.mk`, `otp_release_targets.mk`, `dep.mk` and `doc.mk` from the shared build system.

## Test Strategy
- Common Test suites live in `test/` (`yecc_SUITE`, `leex_SUITE`, `app_SUITE`, `parsetools.spec`, `parsetools.cover`) and verify the generators end-to-end: fixture grammar/scanner → `yecc:file`/`leex:file` → `compile:file` → load → assert on tokens/parse results; see `test/CONTEXT.md` for groups, helpers and known brittle assertions.
- `make test` from here (or from `test/`) builds the suites in place (`EBIN = .`) and runs them; `TEST_NEEDS_RELEASE` is not set, but the suites need a full OTP.
- Generated parsers of other applications are the de-facto integration tests of the emitted code (stdlib `erl_parse`, compiler `core_parse`, edoc, megaco, snmp, xmerl, tools/xref).

## Routing Table
- `src/` → generator sources: `yecc.erl`, `leex.erl`, `yeccscan.erl`, the metagrammar `yeccgramm.yrl` + generated `yeccparser.erl`, app/appup `.src`, `Makefile`
- `include/` → the generated-code templates installed with the app: `yeccpre.hrl` (parser runtime/entry points) and `leexinc.hrl` (scanner runtime with `##`-placeholders)
- `test/` → Common Test suites for yecc/leex/app; end-to-end generated-code verification (plain `test/`, not part of `SUB_DIRECTORIES`)
- `doc/` → `docs.exs` (ExDoc local config; `extras: []`) and `notes.md` (the app's release notes rendered into the docs); `Makefile` includes the shared `../../make/doc.mk`, which generates HTML/man from the modules' `-moduledoc` and copies `notes.md` via `../../make/ex_doc.exs`
- `../../make/otp.mk`, `../../lib/stdlib/src/erl_compile.erl` → build-side dispatch to `yecc:compile/3`/`leex:compile/3` (read-only, other nodes)
