# syntax_tools — Documentation

## Intent
Documentation source and doc-build glue for the `syntax_tools` application (app version 4.1.1 from `../vsn.mk`).
Uses the modern, ExDoc/Elixir-based OTP doc pipeline (`$(ERL_TOP)/make/doc.mk`), not the legacy `doc/src/` + `overview.edoc` layout.

## API Surface
- `Makefile` — includes `$(ERL_TOP)/make/target.mk`, `make/$(TARGET)/otp.mk`, `../vsn.mk` (`VSN=$(SYNTAX_TOOLS_VSN)`), sets `APPLICATION=syntax_tools`, `EPUB=false`, then includes `$(ERL_TOP)/make/doc.mk` (which supplies the `html`, `man`, `docs`, `clean`, `release_docs_spec` targets).
  - Extra rule: `assets/demo.erl: ../examples/demo.erl` (plain `cp`) and `$(HTMLDIR)/index.html: assets/demo.erl`, so the generated demo copy exists before the docs are built.
- `docs.exs` — local ExDoc config; only sets `extras: ["guides/chapter.md"]`, with a comment that the order of entries determines the docs listing. Merged into the global `make/ex_doc.exs` config (local keys other than `extras`/`groups_for_extras`/`groups_for_docs` override the global ones).
- `guides/chapter.md` — the single user guide, "Erlang Syntax and Metaprogramming tools" (overview of ASTs/`erl_syntax`, `erl_prettypr`/`prettypr`, `merl`, and a pointer to the demo module). Licensed Apache-2.0 OR LGPL-2.1-or-later (contains third-party, Richard Carlsson, copyright).
- `notes.md` — "Syntax_Tools Release Notes", ~24 KB, one `## Syntax_Tools <VSN>` section per release (current 4.1.1 at the top, 62 sections in total, down to 1.x). This is the app's change log. `skip_undefined_reference_warnings_on: ["notes.md"]` in the global config means unresolved references there don't fail the build.
- `demo.erl` — tracked symlink to `../examples/demo.erl`, a leftover from the legacy edoc build so that a bare `demo.erl` link resolved. Not referenced by the current Makefile, `docs.exs`, or `guides/chapter.md` (the guide links `assets/demo.erl` instead); it is effectively vestigial but committed.
- `assets/.gitignore` — contains `*`: everything in `assets/` is generated (currently the copied `demo.erl`).
- No `doc/src/`, `references/`, `internal_doc/`, `html/`, or nested `Makefile` exist — the tracked content is exactly the six files listed above.

### Where reference documentation comes from
- There is **no per-module `.md` source** here. Reference docs are generated by ExDoc from `-moduledoc`/`-doc` attributes inline in `../src/*.erl`.
- Hiding/filtering: `make/doc.mk` computes `ERL_FILES_WITH_DOC` with `grep -L "moduledoc false."`; `../src/merl_tests.erl` has `-moduledoc false.` and is excluded, leaving nine documented modules (`epp_dodger`, `erl_comment_scan`, `erl_prettypr`, `erl_recomment`, `erl_syntax`, `erl_syntax_lib`, `merl`, `merl_transform`, `prettypr`).
- Those same `.erl` basenames become `MAN3_DEPS` (via `ERL_FILENAMES_ONLY`), so `man` is part of `DEFAULT_DOC_TARGETS` alongside `html`.
- The global `make/ex_doc.exs` also auto-adds extras: top-level `*.md` (= `notes.md`) plus `{guides,references,internal_docs}/*.md`, and auto-detects `../ebin/*.beam` as `HTML_DEPS` and `docs.exs`/`make/ex_doc.exs` as prerequisites.
- Cross-app links (`m:module`, `deps`) resolve against sibling apps' `doc/html` directories produced by `make/ex_doc.exs`; `groups_for_extras` maps `guides/` → "User's Guides" and `references/` → "References".

## Constraints
- Never edit generated output: `doc/html/`, `doc/assets/*` (other than `.gitignore`) and the `man/` pages are build products. `doc/assets/` in particular is copied verbatim into the HTML output (`assets: %{cwd/assets => "assets"}` in the global ExDoc config).
- New prose documentation belongs in `guides/*.md` (user guides) and must be registered in `docs.exs` `extras` if it is a new file outside the auto-globbed dirs, or in `../src/*.erl` `-moduledoc`/`-doc` for API reference. Do **not** add `doc/src/` or `references/` here.
- Release notes go in `notes.md`: add a new `## Syntax_Tools <VSN>` section at the top when the app's version in `../vsn.mk` changes.
- Keep guide content free of unresolvable references — warnings are errors (`EX_DOC_WARNINGS_AS_ERRORS=default` in `make/doc.mk`).

## Notes for Agents
- `notes.md` (not git history alone) is the app's user-facing change log; the version heading must match `SYNTAX_TOOLS_VSN` in `../vsn.mk`.
- ExDoc `extras` order is significant: the global config prepends local `docs.exs` extras to the auto-globbed `*.md` + `guides`/`references`/`internal_docs` list (deduplicated), so local entries appear first in the docs sidebar.
- `EPUB=false` in the Makefile disables EPUB output via `make/get_ex_doc_formats_no_epub.sh`.
- Doc builds require the app's `../ebin/*.beam` and an ExDoc/Elixir toolchain; `make docs` in this directory is the entry point.

## Dependencies
- Elixir + ExDoc, detected/downloaded via `$(ERL_TOP)/make/check_ex_doc` and invoked through `$(ERL_TOP)/make/ex_doc_wrapper` with the merged config `make/ex_doc.exs`; `EX_DOC_VERSION` must be set by that wrapper.
- GNU make and the OTP build `make/target.mk`/`make/$(TARGET)/otp.mk` variables (`ERL_TOP`, `TARGET`); man pages additionally need the app to be compiled first.

## Test Strategy
- No tests live here; doc correctness is verified by building: `make docs` (or `make html` / `make man`) in `lib/syntax_tools/doc` must succeed with warnings-as-errors, which also validates guide and `-moduledoc` cross-references.
