# syntax_tools — Erlang Syntax and Metaprogramming Tools

## Intent
OTP application providing utilities for Erlang abstract syntax trees (ASTs): the `erl_syntax` ADT, tolerant parsing, pretty-printing, comment re-attachment, and Merl metaprogramming.
App version `SYNTAX_TOOLS_VSN = 4.1.1` (`vsn.mk`); pure-Erlang, library-only application — no processes, no application callback module, no `priv/` runtime assets (`priv/` holds only `.gitignore`).
Built from `lib/Makefile` as one of the `ALL_ERLANG_APPLICATIONS` (only with `BUILD_ALL`, i.e. `make` in `lib/`), after `stdlib sasl kernel compiler`.

## API Surface
- Nine public modules in `src/`: `erl_syntax` (the AST ADT, largest file), `erl_syntax_lib` (traversal/analysis utilities), `erl_prettypr` (`format/1,2`, `best/1,2`), `prettypr` (generic Hughes pretty-printing documents, AST-independent), `epp_dodger` (parse without macro expansion; strict `parse*` vs tolerant `quick_parse*`), `erl_comment_scan` (`file/1`, `string/1` → comment records), `erl_recomment` (`recomment_forms/2`), `merl` (`quote/1,2`, `qquote/2,3`, templates, `match_spec_run/2`, `compile_and_load/1,2`) and `merl_transform` (parse transform).
- `include/merl.hrl` — the only installed public header: `?Q(Text)` / `?Q(Text, Env)` macros; including it enables the `merl_transform` parse transform unless `MERL_NO_TRANSFORM` is defined first.
- `src/syntax_tools.app.src` / `src/syntax_tools.appup.src` — templates; the `.app`/`.appup` in `ebin/` are generated with `%VSN%` substituted.
- `doc/notes.md` — the app's user-facing release notes (change log per version).

## Constraints
- `{applications, [stdlib]}`; `{runtime_dependencies, ["compiler-9.0","erts-16.0","kernel-10.3","stdlib-8.0"]}`.
- The syntax-tree representation is deliberately undocumented and subject to change; the only public guarantees are that no tree is a bare atom, `[X|Y]` or `[]`, and that `erl_parse` trees are valid input while `erl_syntax` trees need `revert/1` to become `erl_parse` trees.
- Edit `src/*.app.src`/`*.appup.src`, never the generated `ebin/syntax_tools.app`/`.appup`.
- `src/Makefile` compiles with `-Werror +warn_deprecated_catch +warn_obsolete_bool_op +warn_unused_import` — new warnings break the build.
- `merl_transform.erl` must stay compilable with the transform disabled; it is bootstrapped through a `-DMERL_NO_TRANSFORM` compile of `./merl_transform.beam` followed by a recompile applying the transform to itself.
- No autoconf `configure` here (unlike `crypto`, `wx`, `odbc`, …) — nothing platform-specific to configure.

## Notes for Agents
- Downstream consumers of this app's API in-tree: `edoc` (uses `erl_syntax`/`erl_prettypr`/`erl_comment_scan` heavily and lists `syntax_tools` in its `.app.src`), `stdlib`/`common_test` runtime dependency lists, `dialyzer`/`edoc`/`xmerl` Dialyzer PLT app lists, and `erts` test suites that `-include_lib` `merl.hrl`; changing an exported API affects those.
- `doc/` holds no per-module reference sources — reference docs are generated by ExDoc from the inline `-moduledoc`/`-doc` attributes in `src/*.erl`, so API documentation edits belong in the sources.
- `priv/` and `ebin/` contain no tracked content besides `.gitignore` (build/output areas).

## Dependencies
- Runtime libs used: `erl_parse`/`erl_scan` (`stdlib`) for parsing and `revert` compatibility, `epp` for the examples, `eunit` only for the `merl` test modules.
- Build/test tooling: `make` + the shared `make/` infrastructure (`otp_subdir.mk`, `app_targets.mk`, `dep.mk`); docs additionally need the Elixir/ExDoc toolchain via `make/doc.mk`.
- No OS packages or external libraries.

## Test Strategy
- Common Test suites live in `test/` (`syntax_tools_SUITE` with 22 cases, `merl_SUITE` with 4) plus the `syntax_tools_SUITE_data/` fixtures; run with `make test` from this directory.
- Suites exercise `erl_syntax` wrap/`revert` round-trips against real OTP sources, `epp_dodger` strict and quick parsing, comment scan/recomment, pretty-print re-parse round-trips, and Merl quoting/compile-and-load.
- EUnit tests for `merl`/`merl_transform` live in `src/merl_tests.erl` (not in the app `modules` list, not built by make) and in `examples/merl/` (standalone Makefile with `eunit:test/2`).

## Routing Table
- `src/` → all application modules, `syntax_tools.app.src`/`.appup.src`, the merl_transform bootstrap build rules and the AST representation contract
- `include/` → `merl.hrl`, the `?Q` macros and the parse-transform activation side effect
- `test/` → Common Test suites, ct specs/cover config, fixtures under `syntax_tools_SUITE_data/`
- `doc/` → ExDoc doc build (`docs.exs`, `Makefile`), user guide `guides/chapter.md`, release notes `notes.md`
- `examples/` → runnable tutorial programs (`demo.erl` and its input files); `examples/merl/` → Merl interpreter/compiler tutorial with its own Makefile and EUnit tests
- `ebin/`, `priv/` → build output / empty placeholders (only `.gitignore` tracked)
