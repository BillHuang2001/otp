# HTTP Client (`httpc`)

## Intent
Implementation of the `httpc` HTTP/1.1 client service of the `inets` application (no caching support).
Owns the user-facing HTTP client API, the per-profile connection/session management and the cookie store.
The wire-level HTTP/1.1 primitives (chunked encoding, header/URI parsing, request/response encoding, transport) are NOT here — they live in the shared sibling `../http_lib/`.
The directory is flat: no subdirectories.

## API Surface
`httpc` is the only public module; everything else is `-moduledoc false.` internals.

Public API (`httpc`):
- Requests: `request/1` (Url), `request/2` (Url, Profile), `request/4` (Method, Request, HttpOptions, Options), `request/5` (+ Profile); there is deliberately NO `request/3`.
- Request control: `cancel_request/1,2`, `stream_next/1` (drives the next streamed message for `{self, once}` receivers).
- Options: `set_option/2,3`, `set_options/1,2`, `get_option/1,2`, `get_options/1,2` — each available in 4 scopes: `default|profile|session|request`.
- Cookies: `store_cookies/2,3`, `cookie_header/1,2,3`, `which_cookies/0,1`, `reset_cookies/0,1`.
- Debug/introspection: `which_sessions/0,1`, `info/0,1`, `ssl_verify_host_options/1`.
- Profile helpers: `default_profile/0` (`default`), `profile_name/1,2` (atom→registered name, pid→pid), `profile_name/1` on `default` returns `httpc_manager`.
- `inets_service` behaviour callbacks: `start_standalone/1`, `start_service/1`, `stop_service/1`, `services/0`, `service_info/1` (dispatched from `../inets_app/inets.erl`).

Internal modules:
- `httpc_internal.hrl` — private, shared header: records `#http_options{}` (per-request settings), `#options{}` (per-profile settings incl. proxy, pipeline/keep-alive, max_sessions, cookies mode, ipfamily, unix_socket, max_connections_open), `#request{}`, `#session{}`, `#http_cookie{}`, plus logging macros `?hcri/?hcrv/?hcrd/?hcrt` and the connection/pipeline/keep-alive/redirect default constants. It is the data contract between all modules in this directory and is also copied under `../../test/` for the suites.
- `httpc_handler` — `gen_server` (via `proc_lib` + `gen_server:enter_loop`) per connection/session: owns the socket, the `pipeline`/`keep_alive` queues, request timers, retry/redirect bookkeeping, streaming receiver and proxy/CONNECT handling (`TLS_UPGRADE_TOKEN`).
- `httpc_manager` — `gen_server` per profile: holds ets tables for handlers, cookies, sessions and requests; dispatches requests to handlers, pools sessions per `{Host,Port}`, and implements retry/redirect/`request_done`/`cancel_request`/options/cookie bookkeeping.
- `httpc_sup` — top supervisor (`one_for_one`), children `httpc_profile_sup` and `httpc_handler_sup`.
- `httpc_profile_sup` — dynamic supervisor with one `httpc_manager` child per profile (`start_child/1`, `restart_child/1`, `stop_child/1`); child id is `httpc_manager` for the default profile, `{httpc, Profile}` otherwise.
- `httpc_handler_sup` — dynamic `simple_one_for_one` style supervisor used to start handler processes when the client runs standalone (no profile supervisor in the path).
- `httpc_request` — outgoing request encoding/classification: `send/3`, `is_idempotent/1`, `is_client_closing/1`.
- `httpc_response` — incoming response decoding/classification: `parse/1`, `result/2`, `send/2`, `error/2`, `is_server_closing/1`, `stream_start/3`, and the incremental `parse_version/1`, `parse_status_code/1`, `parse_reason_phrase/1`, `parse_headers/1`, `whole_body/1,2` callbacks.
- `httpc_cookie` — RFC 2109/6265 cookie store: `open_db/3`, `close_db/1`, `reset_db/1`, `insert/2`, `header/4`, `cookies/3`, `which_cookies/1`, `image_of/2`, `print/2` (last two for debug).
- `Makefile` — per-directory build: lists `MODULES` and `HRL_FILES`, compiles into the shared `../../ebin`, and generates the `deps/http_client.d` dependency file.
- `deps/http_client.d` — generated by `erlc -M` from the Makefile; a build artifact, never edit by hand (`deps/` is git-ignored via `../.gitignore`).

## Architecture / Process Tree
- `httpc_sup` → `httpc_profile_sup` → one `httpc_manager` per profile → starts/coordinates `httpc_handler` processes (one per connection/session).
- `httpc_sup` → `httpc_handler_sup` → `httpc_handler` processes when the client is started standalone (`httpc:start_standalone/1`).
- Profile naming: default-profile manager is globally registered as `httpc_manager`; other profiles as `{httpc, Profile}`; `httpc:profile_name/*` maps between the user-facing profile atom/pid and the registered name.
- Session pooling: `httpc_manager` keeps an ets `session_db` keyed by `{Host,Port}`; a session is `pipeline` or `keep_alive` (`pipeline_timeout = 0` disables pipelining and makes the client wait for each response).
- `httpc_handler` uses `proc_lib:start_link` + `enter_loop` on purpose so a slow/hanging `gen_tcp:connect` in `init/1` cannot block the `httpc_manager`.

## Design Decisions
- Client and server share the wire-level HTTP layer in `../http_lib/` (`http_chunk`, `http_util`, `http_request`, `http_response`, `http_transport`, `http_uri`, `http_internal.hrl`), so this directory only holds client-specific policy: profiles, connection/session management, cookies and the `httpc` API.
- Two-level supervision (profile supervisor for managers + a separate handler supervisor) lets profiles be added/removed at runtime via `inets:start(httpc, Config)` / `inets:stop(httpc, Profile)` without disturbing existing handlers.
- All HTTP client settings are split into two record scopes: `#http_options{}` (per request, user supplied) and `#options{}` (per profile, set with `set_options`), matched by the 4 option scopes of the public API.
- Cookie persistence is optional: with a profile `data_dir` cookies are stored in a disk database, otherwise (`only_session_cookies`) all cookies are treated as session cookies.

## Constraints
- Every module in `MODULES` compiles into the single shared `../../ebin` (no per-directory ebin); new modules must also be added to the `http_client` group in `../inets_app/inets.app.src` `{modules, [...]}`.
- All modules include the private `httpc_internal.hrl`; new records/settings that cross module boundaries belong there, not in individual modules.
- Compile flags come from `../inets_app/inets.mk` (`-Dinets_trace_io` when `INETS_TRACE=io`, `-Dinets_debug` when `INETS_DEBUG=true`) plus include paths `../../include`, `../inets_app`, `../http_lib`.
- `httpc_internal.hrl` is shipped in the release (`release_spec` installs `HRL_FILES`) but is private API — do not document or depend on it outside `inets`.

## Known Issues
- `httpc` normalizes input URIs before processing, so `%` in a URL must already be percent-encoded as `%25` — documented as a warning in `httpc`'s moduledoc.
- No HTTP caching is supported.
- "TLS upgrade" per RFC 2817 is not supported; only proxy `CONNECT` tunnelling followed by a TLS upgrade of the connection.
- `httpc` uses `list_to_atom` for profile names/headers and therefore carries `{nowarn_possibly_unsafe_function, ...}` (atoms are created from user input).

## Dependencies
- `../http_lib/` for chunk/header/URI/transport helpers and `http_internal.hrl`; `../inets_app/inets_internal.hrl` for the logging `?report_*` macros used by `httpc_internal.hrl`.
- `public_key`/`ssl` at runtime for `https` and `ssl_verify_host_options`.
- The `ssl` application must be started by the user before any `https` request.

## Test Strategy
- Tested from `../../test/` (installed as `inets_test`), not from this directory: `httpc_SUITE.erl`, `httpc_cookie_SUITE.erl`, `httpc_proxy_SUITE.erl` (with `httpc_SUITE_data/` and `httpc_proxy_SUITE_data/`).
- The suites use their own copy of `httpc_internal.hrl` and the shared `http_test_lib.erl` / `inets_test_lib.erl` helpers, and start local test servers (`httpd_1_0.erl`, `httpd_1_1.erl`, `httpd_test_lib.erl`).
- `which_cookies/1`, `which_sessions/1`, `info/1`, `httpc_cookie:print/2` exist mainly to support these suites and manual debugging.
