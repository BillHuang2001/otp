# Inets — Documentation

## Intent
Documentation sources for the `inets` application (OTP `INETS_VSN`, see `../vsn.mk`).
Holds the user guides, the ExDoc configuration, the release notes and a reference archive of upstream RFC texts.
The per-module API reference is **not** stored here: it is generated from the `-moduledoc`/`-doc` attributes on the Erlang sources in `../src/{inets_app,http_lib,http_client,http_server}`.
`../Makefile` lists this directory in `SUB_DIRECTORIES` (`src examples doc`), so it is built as part of the app.

## API Surface
- `Makefile` — includes `$(ERL_TOP)/make/target.mk`, `$(ERL_TOP)/make/$(TARGET)/otp.mk`, `../vsn.mk` (`VSN=$(INETS_VSN)`, `APPLICATION=inets`) and finally `$(ERL_TOP)/make/doc.mk`. No inets-specific targets.
- `docs.exs` — app-local ExDoc config (merged with `$(ERL_TOP)/make/ex_doc.exs`). Sets the ordered `extras` list and `groups_for_modules`.
- `guides/*.md` — the user guides (see Routing Table).
- `notes.md` — Inets release notes; one `## Inets <vsn>` section per release, newest first (currently `## Inets 9.8` down to `## Inets 5.1`).
- `src/` — contains only the legacy binary `marting_tankar.sdw`.
- `archive/` — checked-in upstream reference material (RFCs and NCSA HTTPd notes), not part of the built docs.

## How the docs are built
- `make docs` / `make release_docs_spec` delegate entirely to `$(ERL_TOP)/make/doc.mk`; `release_docs_spec` installs HTML into `$(RELEASE_PATH)/lib/inets-$(VSN)/doc/html` and man pages into `$(RELEASE_PATH)/man/man3`.
- HTML is produced by `make/ex_doc_wrapper` with `ERL_FLAGS="-pz $(ERL_TOP)/erts/ebin"`, using `make/ex_doc.exs` as `-c` config and this `docs.exs` as the local config; output goes to `doc/html/index.html`.
- `make/ex_doc.exs` **merges** extras: `docs.exs :extras` is concatenated with `Path.wildcard("*.md")` and `Path.wildcard("{guides,references,internal_docs}/*.md")`. Hence `notes.md` (a top-level `*.md`) is picked up automatically as an extra even though it is not listed in `docs.exs`; `skip_undefined_reference_warnings_on: ["notes.md"]` suppresses link warnings for it.
- Man pages (`man3`) are generated by `make/markdown_to_man.escript` from the `../src/**/*.erl` files that have a moduledoc (the `man3/%.3: %.erl` rule in `doc.mk`).
- docs.exs `groups_for_modules` = "Service API" `[:inets]`, "HTTP client modules" `[:httpc]`, "HTTP server modules" `[~r/httpd/, ~r/mod_/]`, "Deprecated functionality" `[:http_uri]` — the HTTP server group is a regex, so every new `httpd*`/`mod_*` module is grouped automatically.

## Guides (subject)
- `guides/introduction.md` — Purpose of Inets (container for Internet clients/servers; HTTP client & server are HTTP 1.1 / RFC 2616 compliant) and prerequisites.
- `guides/inets_services.md` — the "service" concept, `inets:start()`, configuring services at startup/maintenance via `[{inets,[{services,List}]}]`, supervision tree and the `standalone` option.
- `guides/http_client.md` — `httpc`: default/extra profiles, config via `{httpc, PropertyList}`, getting-started examples (proxy, GET/POST/HEAD).
- `guides/http_server.md` — `httpd`: configuration, getting started, dynamic web pages (SSI/ESI), logging, the Erlang Web Server API, the inets web server modules (`mod_*`), serving files from the command line.
- `guides/hardening.md` — security hardening guidance for `httpc` and `httpd`, a full hardened example, general recommendations, and a "Changes from OTP 28" upgrade-differences section (largest guide; adds OTP-specific defaults that can bite on older releases).

## Archive (`archive/`) — reference-only, not built or installed
Checked-in copies of the upstream specs the HTTP implementation refers to (kept for offline reference; nothing in `doc.mk` or `docs.exs` reads this directory):
- `rfc1123.txt` — RFC 1123 (Requirements for Internet Hosts; date/time formats).
- `rfc1945.html` — RFC 1945 (HTTP/1.0), HTML rendering.
- `rfc2068.txt` — RFC 2068 (HTTP/1.1, obsolete).
- `rfc2145.txt` — RFC 2145 (HTTP version numbers).
- `rfc2616.txt` / `rfc2616.pdf` — RFC 2616 (HTTP/1.1) — the spec cited by the guides/sources.
- `rfc3986.txt` — RFC 3986 (URI generic syntax).
- `includes.txt` — NCSA HTTPd notes on Server Side Includes (SSI), the reference for `httpd_esi`/SSI behavior.
- `pieces_of_code.txt` — commented-out Erlang snippets (a `script_name` helper and `mod_*` fragments) kept as historical coding notes.
- `rfc1123.txt.license` — SPDX companion file for `rfc1123.txt` (`SPDX-License-Identifier: NOASSERTION`, `SPDX-FileCopyrightText: NOASSERTION`).

## Constraints
- Generated output (`doc/html/`, `man*`) is a build artifact — never edited by hand.
- The archive is third-party text: it must keep its SPDX companion `.license` file (files that cannot carry an inline header get a sibling `<file>.license`).
- Guide files must keep the `%CopyrightBegin% … %CopyrightEnd%` SPDX header block.
- Guide ordering in the rendered docs is driven by the `extras` list in `docs.exs`; adding/renaming a guide requires updating `docs.exs`.

## Design Decisions
- Only the guide order and module grouping are app-local (`docs.exs`); everything else (theme, deps, grouping of `guides/`/`references/`, search, EPUB handling) lives in the shared `$(ERL_TOP)/make/ex_doc.exs`, so inets docs stay visually consistent with the rest of OTP.
- Guides use ExDoc autolinks (e.g. `` `m:httpc` ``) to cross-reference module docs, so guide text and generated module docs stay linked.
- The RFC/SSI archive is kept in-tree (rather than linked out) so the documented protocol behavior can be checked against its source spec offline.

## Dependencies
- `$(ERL_TOP)/make/doc.mk`, `$(ERL_TOP)/make/ex_doc.exs`, `$(ERL_TOP)/make/ex_doc_wrapper`, `$(ERL_TOP)/make/check_ex_doc` (`check_ex_doc` prompts to download ExDoc; `EX_DOC_VERSION` env var is required by `ex_doc.exs`), and `make/get_ex_doc_formats_no_epub.sh` (used when `EPUB=false`).
- ExDoc (Elixir tool, downloaded on demand) — the actual documentation generator.
- `make/markdown_to_man.escript` for the man pages.
- The HTML build depends on compiled beams: `HTML_DEPS` includes `../ebin/*.beam` and ExDoc reads moduledocs from `../ebin`, so `make` (compile) in `../` must run before `make docs`.

## Notes for Agents
- `notes.md` is auto-included only because `ex_doc.exs` wildcards `*.md` in this directory; do not add it to `docs.exs :extras` (that would duplicate it).
- `src/marting_tankar.sdw` is a ~20 KB binary (a legacy FrameMaker/Word-style artifact). It is **not** referenced by any Makefile, `docs.exs` or `doc.mk` rule and produces no output — treat it as dead weight; do not build tooling around it.
- `doc.mk`'s `man3` rule matches `src/*.md`; this directory has none, so all inets man3 pages come from `../src/**/*.erl` only.
- Editing the guides only affects prose; the API reference text lives in the `../src` modules' moduledocs.
