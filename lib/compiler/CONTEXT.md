# Erlang Compiler (`lib/compiler`)

## Intent
The `compiler` OTP application: the Erlang-to-BEAM compiler, exposed as the `compile` module and driven by `erlc`.
Not to be confused with `erts/` (the runtime that *executes* BEAM files) — this app only produces BEAM object code.
It is one of the first-built applications (`ERTS_APPLICATIONS = stdlib sasl kernel compiler` in `../Makefile`) because everything else is compiled by it.
Current version floor `COMPILER_VSN = 10.0.6` (see `vsn.mk`); release-wide mapping is `otp_versions.table` at the repo root.

## API Surface
- `src/compile.erl` — the only public entry point other apps/tools call: `file/1,2`, `noenv_file/2`, `string/1,2`, `forms/1,2`, `output_generated/1`, `options/0` (`--help`), `env_compiler_options/0`; the erlc-facing `compile/3`/`compile_asm/3`/`compile_core/3`/`compile_abstr/3`.
- `src/cerl.erl` (+ `cerl_trees`, `cerl_clauses`) — the documented Core Erlang AST API (used by `lfe` and other external tooling); `core_lib` is the undocumented Core AST helper library also relied on externally.
- `src/compiler.app.src` — application resource template (`vsn` from `%VSN%`); declares `{applications,[kernel,stdlib]}` and `{runtime_dependencies, ["stdlib-...","kernel-8.4","erts-13.0","crypto-5.1"]}`.
- Input forms accepted: Erlang source (`.erl`), abstract code (`.abstr`/forms), Core Erlang (`.core`), BEAM assembly (`.S`); see `passes_1/1` in `compile.erl`.
- Consumed indirectly by `dialyzer`, `syntax_tools`, `eunit`, `debugger`, `xmerl` (parse transforms) and the build system's `erlc`.

## Constraints
- Must build very early with only `kernel` + `stdlib` at compile time — never add a compile-time dependency on a higher-level app.
- Source must stay `-Werror` clean and fully spec'd (`ERL_COMPILE_FLAGS` include `-Werror +inline +warn_missing_spec`); the test suites are additionally self-linted with `+clint +ssalint`.
- The pass *order* is semantic and is encoded as data in `compile.erl` — changing the pipeline means editing the pass-list builders there, not reordering modules.
- Never hand-edit generated files: `src/beam_opcodes.erl`/`.hrl` (from `genop.tab` via `erts/emulator/utils/beam_makeops`), `src/core_parse.erl` (yecc from `core_parse.yrl`), `ebin/*`, and generated `compiler.app`/`compiler.appup`.
- The public `compile` and `cerl` APIs are widely used — treat them as stable.

## Design Decisions
- Four intermediate representations, one module family per stage: Erlang abstract code → Core Erlang → BEAM SSA → BEAM assembly → BEAM binary.
- The compilation pipeline is *data*: `passes/2` selects a list of pass commands built by `standard_passes/0`, `abstr_passes/1`, `core_passes/1`, `kernel_passes/0`, `asm_passes/0`, `binary_passes/0`; `select_passes/2` expands `{iff,_}`, `{unless,_}`, `{delay,_}`, `{listing,_}`, `done` into a flat list.
- Each pass is a module exporting `module/2` (old-behavior-style `beam_*`/`sys_core_*`), and pass state is the private `#compile{}` record.
- Type information lives in the SSA layer (`beam_types` lattice + `beam_ssa_type`/`beam_call_types`), replacing the old Core-only type passes; features are version-gated via `+r29`/-feature flags (`expand_opt/2`).

## Stage 2 opt-in passes (loop opts / fusion / FBIP)
The Rust-rewrite "Stage 2" compiler workstream (root `ERTS_RUST_REWRITE_DEEPDIVE.md` §E/§H) adds three **opt-in, default-OFF** SSA passes here, each with its own CT suite, plus an opt-in per-pass budget/watchdog/effort/eligibility-gate framework.
All three are wired *inside* `src/beam_ssa_opt.erl` (NOT in `compile.erl`'s pass lists): loop opts and fusion are appended to `repeated_passes/1`, FBIP is registered as a *named module pass* in `epilogue_module_passes/1`; `options/0` advertises their flags in `--help` via synthetic entries (`compile.erl:3272-3300`).
Every pass and sub-pass is gated on an option that `expand_opt/2` passes through unchanged when absent, so the default compilation path stays byte-for-byte identical (measured: 0 `Code`-chunk differences over the 96-module `lib/stdlib/src` corpus; `[binary]`, `[binary,no_ssa_opt_fus]` and `[binary,fusion_opt,no_ssa_opt_fus]` give the identical `Code` chunk for all 771 `lib/*/src/*.erl`).
The framework is `src/beam_ssa_opt_budget.erl` (`ssa_opt_budget` / `ssa_opt_fn_budget` / `ssa_opt_watchdog` / `ssa_opt_gates`; see Known Issues).

- `src/beam_ssa_loop_opt.erl` (441-line driver; flag `loop_opt`) — the loop-optimization pass, run in `repeated_passes/1` (`beam_ssa_opt.erl:366-375`), i.e. AFTER the SSA type analysis, so the `beam_ssa_type`/`beam_bounds` annotations are available.
  Its machinery is split into `beam_ssa_loop_cfg.erl` (CFG / dominators / natural-loop recognition / preheader insertion), `beam_ssa_loop_reduce.erl` (strength reduction + integrality/non-negativity proofs) and `beam_ssa_loop_arith.erl` (arithmetic LICM).
  It performs: natural-loop recognition (back edge H->P iff H dominates P) + **LICM** of pure non-raising tag-test BIFs (`?SAFE_BIFS`) and constructors (`?SAFE_OPS` = `put_list`/`put_tuple`) into the loop preheader (`?MAX_HOIST`=64); **whole-function strength reduction** performed in place (same block/destination; never moved or duplicated): `X*2^n`→`X bsl n` only for an X proven to be an integer *and* to have a FINITE bounded range (|X| < 2^128) with n =< 64, `X*2`→`X+X` unconditionally (exact for every number, incl. floats/subnormals), `X div 2^n`→`X bsr n` and `X rem 2^n`→`X band (2^n-1)` for a provably non-negative integer X; and **induction-variable canonicalisation** (a loop-carried `{Init,Step}` recurrence proves integrality/non-negativity and licences canonicalising `C+V`/`C*V` to `V+C`/`V*C`; the recurrence itself is not rewritten). The bounded-range proof is what keeps the shift rewrite exception-preserving: `erts_bsl` raises `system_limit` for an absurd shift count, so an unbounded bignum operand must not be rewritten.
  Kill via `no_ssa_opt_loop_opt` (auto-derived) or `no_ssa_opt`.
  Eligibility gate (`beam_ssa_opt:gate/1` → `beam_ssa_loop_opt:eligible/1`, consulted whenever the budget machinery is armed) is `has_back_edge OR has_reduce_candidate` — a cheap NECESSARY precondition that must stay a SUPERSET of the pass's real effect, because the whole-function strength reducer fires with no loop.
- `loop_arith_licm` (separate pass `ssa_opt_loop_arith_licm` in `repeated_passes/1`, implemented in `beam_ssa_loop_arith.erl`) — **arithmetic LICM**: hoists non-raising arithmetic into the loop preheader only when every operand is loop-invariant and its integrality (and, for `div`/`rem`, the second operand) is proven AT THE PREHEADER (a loop-dependent annotation is rejected). `?ARITH_BIFS` is `+`/`-`/`*`/`div`/`rem`/`band`/`bor`/`bxor` — `bsl`/`bsr` are deliberately NOT hoistable (their `system_limit` raise is not proven away). `loop_opt` alone never enables it. Kill via `no_ssa_opt_loop_arith_licm` or `no_ssa_opt`.
- Measured effect: the loop passes DO fire on real code — 24 of 96 `lib/stdlib/src/*.erl` change under `+loop_opt +loop_arith_licm` (22 under `+loop_opt` alone; `supervisor.erl` and `timer.erl` additionally need the arithmetic LICM, where `T - ?MAX_RECEIVE_AFTER` is hoisted out of the `sleep/1` receive loop), with 0 compiler crashes over the sweep.
- Negative results (documented in the `beam_ssa_loop_opt.erl` moduledoc): **loop unrolling** (`loop_unroll`) and **loop-index narrowing** (`loop_index_narrowing`) are deliberately NOT implemented and have NO flags. The only CFG cycles reaching this pass are the `receive` loops built by `beam_ssa_recv` (a tail-recursive function is still a tail `call`; `beam_ssa:is_loop_header/1` recognises a header only by `peek_message`/nonzero `wait_timeout`): a receive loop has no compile-time trip count and duplicating its body is not semantics-preserving. BEAM has a single arbitrary-precision integer type with no narrow/wrapping instruction, so there is nothing to narrow an index into (the one cheaper form, `rem 2^n`→`band`, is already the strength reducer's `rem` rule).
- `src/beam_ssa_fus.erl` (1064 lines) — **map-lookup and constant-chain fusion** (flag `fusion_opt`), appended to `repeated_passes/1` only when the flag is present, so it can never run otherwise; kill via `no_ssa_opt_fus` (auto-derived) or `no_ssa_opt`.
  Four transforms, each fired only when its precondition is proven: **Fusion 1** collapses a redundant `has_map_field(Map,Key)` test + `get_map_element(Map,Key)` extraction on the success edge into one lookup; **Fusion 2** generalises it to a chain of `has_map_field(Map,Ki)` tests whose keys are exactly those re-extracted by a following `get_map_element`+`succeeded` chain; **Fusion 4** folds a multiplication by an integer constant whose result is immediately multiplied by a second integer constant into a single multiplication by the product; **Fusion 5** turns a `has_map_field(Map,Key)` test plus a guard call to `maps:get/2` into a single `get_map_element` that fails to the test's OWN false label, so no raise is added or removed (every guard-safe map-get spelling compiles to the same `{bif,map_get}` instruction; `is_map/1`/`is_map_key/2` supply the needed proofs, whereas `maps:is_key/2` is rejected by `erl_lint` as an illegal guard expression).
  The multi-pair BEAM instruction is still produced by `beam_block:opt_maps/2` (no new SSA op/opcode); tuple-element (`get_tuple_element`) chain fusion stays deliberately unimplemented (no fused instruction exists), as do `X*C1 div C2` (truncation), `map_get` chains and `bsl`/`bsr` chain folding.
  Verified by differential testing: 996 generated probe modules / ~156k compared calls under `[binary]` vs `[binary,fusion_opt]` plus the `no_ssa_opt_fus`/`no_ssa_opt` controls — 0 behavioural mismatches (compared on values *and* exception class+reason), and injecting a deliberate unsoundness into each of the four transforms is caught by the harness.
  Reach (host rig): `fusion_opt` changes 11 of 771 `lib/*/src/*.erl` (19 of the 771 cannot be compiled by the host at all) and 2 of the 96-module `lib/stdlib/src` corpus.
- `src/beam_ssa_fbip.erl` — **FBIP**: rewrites a *copying* `update_record` to the `inplace` hint when the source is provably fresh (a heap *tuple*: `put_tuple`/`put_tuple2`, a `call` to a local fresh-returning function, an already-`inplace` `update_record`, or an all-fresh `phi`), uniquely owned (single use, not a function argument) and positioned so the update runs at most once per allocation. Only tuple-producing sources are accepted — the allocating-binary sources (`bs_create_bin`, `bs_init_writable`) are deliberately rejected, because an `update_record` of a binary is not a valid instruction: the code generator's `is_tagged_tuple` guard is inserted long after this pass, and `i_update_record_in_place` untags the source unconditionally, so licensing an in-place write there would corrupt the heap instead of raising `badrecord`. STILL no in-place reuse for lists/maps — map in-place is infeasible compiler-only (no map-update instruction carries a `copy`/`reuse`/`inplace` hint and the emulator always allocates a fresh map). Enabled by `fbip_opt`: `beam_ssa_opt:epilogue_module_passes/1` registers it as the named module pass `{ssa_opt_fbip,Fun}` (so `passes/3` derives the real kill switch `no_ssa_opt_fbip`), and it is bounded/observed through `beam_ssa_opt_budget:run/5`.

## Dependencies
- Compile-time: `kernel`, `stdlib` only.
- Runtime only: `crypto` (encrypting/decrypting the `debug_info` chunk via `beam_lib:get_crypto_key/1` + `crypto:crypto_one_time/6`) — hence `DIA_PLT_APPS=crypto` in `Makefile`. `beam_lib` is used only on the `{debug_info_key,…}`/`encrypt_debug_info` and `strip_types` paths, never by default.
- `syntax_tools` is NOT a dependency of `compiler`: no `src/` module references it; only test suites do (`-include_lib("syntax_tools/include/merl.hrl")` in `bif_SUITE`/`bs_match_SUITE`/`guard_SUITE`) — `syntax_tools` is a *consumer* of `compile`/`cerl`.
- Build tool: Perl (for `beam_makeops`), `sed`; yecc is bootstrapped from `bootstrap/`.
- `make test` here force-enables the `maybe_expr` feature via `ERL_ARGS` (see `Makefile`) — required by `maybe_SUITE` and others.

### Runtime facilities the default `compile:file/2` path relies on
(Relevant when porting the compiler onto a new/from-scratch BEAM runtime.)
- OS/FS: `file:*` (open/consult/write_file/rename/delete/get_cwd) plus `epp` reading includes; `os:getenv("ERL_COMPILER_OPTIONS")` in `env_default_opts/0` (`src/compile.erl:1215`; skipped by `noenv_file/2`).
- Processes/messaging: every `compile:file/2` runs the compilation in a `spawn_monitor`ed child and receives its untimed `'DOWN'` (`src/compile.erl:1246-1252`; bypassed by `no_spawn_compiler_process`). `epp` is itself a process; on the default `{file,…}` path the handshake runs in the worker inside `epp:parse_file/2` (`lib/stdlib/src/epp.erl:386` spawn; `:686-687` untimed `{features,…}` receive; `:406-408` `epp:close/1` monitored `'DOWN'` receive), and epp's token reads block on `io:scan_erl_form/4`'s monitored receive (`lib/stdlib/src/io.erl:1671`). The `Epp ! {get_features,self()}` at `src/compile.erl:2175` is the `compile:string/2` (`do_parse_string/2`) path, not `file/2`.
- `apply/3` (BIF) on the normal path: literal-argument constant folding of safe BIFs/calls (`src/sys_core_fold.erl:932`, `src/beam_ssa.erl:609`, `src/beam_ssa_type.erl:1979`, `src/beam_ssa_bc_size.erl:502`, `src/beam_ssa_bool.erl:1422`, `src/beam_ssa_dead.erl:590`).
- Hashing/serialization: `erlang:md5/1` for the module `vsn`/`FunT` checksum (`src/beam_asm.erl:400`); `term_to_binary` for the `Dbgi`/`Docs`/`Meta` chunks and the literal table (`src/compile.erl:2292,2810,2870`, `src/beam_asm.erl:308-309`, `src/beam_dict.erl:346`).
- Optional / NOT default-path: `crypto:*` only via `encrypt_debug_info`/`debug_info_key`; `zlib:compress` only with `compressed_literals`; `beam_lib:*` only for debug-info crypto and `strip_types`; `ets:*` only in `cerl_inline` (reached via `inline`/`{core_transform,inline}`); `code:*` only for parse-transform loading and `to_dis`; `erts_debug:flat_size` + `erlang:system_info(wordsize)` only with `time`.
- Not used anywhere in `src/`: `persistent_term`, `erl_prim_loader`, `open_port`, `unique_integer`.
- Reporting goes to the group leader only (`io:put_chars`/`io:fwrite`), never `logger`/`error_logger` (grep-clean); with `compile:file(File, [])` and `ERL_COMPILER_OPTIONS` unset nothing is printed at all — see `src/CONTEXT.md` §"Default-path runtime model".

### Artifact determinism (for the Rust-rewrite differential harness)
- The `.beam` output embeds the source location: the `CInf` chunk carries `{source,Path}` and the OTP-28+ `Line` chunk embeds the source name (stripped relative to the compiler's cwd). So the same source compiled under a different path or cwd yields byte-differing `.beam` files, while all semantic chunks (`AtU8`,`Code`,`StrT`,`ImpT`,`ExpT`,`Meta`,`LocT`,`Attr`,`Type`,`Dbgi`) stay identical; same path + same cwd yields byte-identical files.
- `deterministic` (`erlc +deterministic` / `{deterministic,true}`) strips both (`CInf` → `[{version,…}]`, `Line` loses the name) and gives byte-identical output across paths — the recommended normalization for `cmp`-ing two compiler artifacts.
- Alternatively compare semantic chunks, e.g. `beam_lib:chunks(File, ["AtU8","Code","StrT","ImpT","ExpT","Meta","LocT","Attr","Type","Dbgi"])`; requesting a chunk the file lacks (`LitT`/`Docs`/`Abst`) makes `beam_lib:chunks/2` return `{error,{missing_chunk,…}}`. Verified with host OTP 29.1.1.

## Known Issues
- A node with `time`/`eprof`/`tprof` options exposes internal pass timing via the process dictionary (`compile__pass_times`) — debugging aid only.
- Besides the per-pass hard caps (`?MAX_REPETITIONS`=16 in `beam_ssa_opt`/`beam_ssa_alias`, `?SS_DEPTH_LIMIT`=30 in `beam_ssa_ss`, `beam_ssa_dead`'s 64-var cap) there is an **opt-in wall-clock bound** for the SSA optimization phases: `ssa_opt_budget` / `{ssa_opt_budget,Millis}` (cumulative budget for `beam_ssa_opt`, default 5000 ms), `ssa_opt_watchdog` / `{ssa_opt_watchdog,Millis}` (upper bound on a single sub-pass, default 1000 ms), `ssa_opt_gates` (enable the eligibility gates and statistics without a bound) and `ssa_opt_fn_budget` / `{ssa_opt_fn_budget,Millis}` (override the size-derived per-function allowance for every function; `0` exhausts each function immediately, activating per-function skipping). All are OFF by default and, when off, the pass funs are not wrapped at all, so the default output is byte-for-byte unchanged. The eligibility gates are consulted whenever the machinery is armed by *any* of those options (`ssa_opt_gates` merely arms it with gates and statistics but no bound). A module-level pass run (a state that is not `{#opt_st{},_}`, e.g. `ssa_opt_fbip`) is attributed to no function, so it contributes no `effort`/`size` entry, and `passes/3` derives the `no_ssa_opt_<name>` kill switch from the pass's registered name. Implementing module: `src/beam_ssa_opt_budget.erl`.
- `time`/`eprof`/`tprof` only measure; the budget/watchdog is what bounds. An exhausted budget stops the fixpoint and skips the still-skippable sub-passes (always a monotone suffix — the deadline never un-expires). A watchdog timeout does NOT skip the pass: the sub-pass runs in a monitored child process and a timeout aborts the compilation with reason `{ssa_opt_watchdog_timeout,Pass}` (the `timed_out` counter is still bumped), because a timeout races the pass and would otherwise skip an arbitrary, non-deterministic subset of passes, which was measured to leave the SSA inconsistent.
- Passes that are never skipped by either bound: `ssa_opt_split_blocks`, `ssa_opt_linearize`, `ssa_opt_blockify` (SSA representation and block granularity), `ssa_opt_type_finish` (publishes the type annotations the code generator and `beam_validator` rely on), `ssa_opt_live` (the only pass that drops or strength-reduces instructions whose result has become dead — a bare `get_map_element` or an unannotated `bs_start_match` reaching codegen crashes it) and `ssa_opt_bs_ensure` (annotates the binary-match blocks; `beam_ssa_pre_codegen:bs_restores_is/5` asserts the annotation is present).
- `beam_ssa_opt_equiv_SUITE`'s benchmark case reports a verdict qualified by the run's own measured spread (observed verdict: "inconclusive"): it warms up and takes the median of 11 interleaved repetitions, prints the ON/OFF ratio with its spread, and hard-asserts only the loose `ON =< OFF*2` bound. On a shared/loaded host the per-kernel spread is 10-30%, so the opt-in passes are performance-neutral on these kernels (fusion only removes a redundant `has_map_fields` probe: `maplookup/2` shrinks 20→16 instructions and never adds work) — do not quote the printed ratio as a speedup.

## Notes for Agents
- To add or change an optimization: find the owning pass module and its position in the relevant `*_passes/0` builder in `compile.erl`; toggleable passes are wrapped in `{unless,no_<x>_opt,…}` and their flag handled in `expand_opt/2`.
- The opt-in Stage 2 SSA passes are the exception: they are wired *inside* `beam_ssa_opt.erl`'s phase builders (`repeated_passes/1` for the loop opts and fusion, `epilogue_module_passes/1` for FBIP) and are appended only when their flag is a member of `Opts`; their `no_ssa_opt_<name>` kill switch is auto-derived by `passes_1/2` from the registered pass name — which is why FBIP is registered there as a *named module pass* `{ssa_opt_fbip,Fun}` instead of being invoked ad hoc from another module — and a plain helper like `loop_arith_licm` is registered under `ssa_opt_loop_arith_licm` so the derived switch is `no_ssa_opt_loop_arith_licm`.
- Core Erlang optimizations belong in the `core_passes/1` list; SSA optimizations in the `{delay,[...]}` block of `kernel_passes/0`; low-level BEAM peephole opts in `asm_passes/0`.
- `src/erl_bifs.erl` is the static BIF property table consumed by the Core and SSA optimizers.
- `priv/` is empty (only `.gitignore`); `scripts/` holds the host-side test rig `host_env.sh` + `host_env_xform.py` (makes `src/` runnable under the host's released OTP — see Test Strategy), a manual smoke test and `otp30_env.sh` (a dev helper to build/test the compiler in an otherwise unbuilt OTP-30 tree), and is NOT in `SUB_DIRECTORIES` (not installed).
- Adding a new compiler pass typically requires wiring it into `compile.erl`, `compiler.app.src`'s `modules` list, and the corresponding test suite; a new `src/*.erl` module must also be added to `src/Makefile`'s `MODULES`.
- Files that legitimately exceed the ~1000-line soft target: `src/beam_ssa_fus.erl` (1064) is one pass whose four transforms share the block-scan/rewrite scaffolding and whose preconditions must stay next to the rewrites they license (splitting it would separate them); `test/beam_ssa_loop_opt_SUITE` (1459), `test/beam_ssa_fus_SUITE` (1104) and `test/beam_ssa_opt_equiv_SUITE` (1017) carry large probe-generator fixtures — do not split these for size alone.

## Test Strategy
- Common Test suites live in `test/` (no `TEST_NEEDS_RELEASE`): `make test` there builds an `Emakefile` and runs CT against the in-tree compiler.
- Central strategy is optimization-correctness: base feature suites are cloned by the Makefile into suffixed suites (`_no_opt`, `_no_ssa_opt`, `_no_copt`, `_inline`, `_cover`, `_dialyzer`, `_r29`, …) that re-run the same code under different optimizer option sets.
- Pass-specific suites (`beam_ssa_SUITE`, `beam_types_SUITE`, `beam_jump_SUITE`, `core_fold_SUITE`, `beam_validator_SUITE`, …), plus `random_code_SUITE` and `property_test/` (PropEr/EQC) for randomized compilation.
- The opt-in Stage 2 passes have dedicated suites (`beam_ssa_loop_opt_SUITE`, `beam_ssa_fus_SUITE`, `beam_ssa_fbip_SUITE`, `ssa_opt_budget_SUITE`, `beam_ssa_opt_equiv_SUITE`, all in `test/Makefile` `MODULES`); each compiles its own probe modules and needs a `compiler` built with the matching pass module. Each pass must both *fire* and stay behaviourally equivalent ON vs OFF, and the suites assert both (hint/`beam_disasm` inspection, plus executing every probe function in both builds and comparing `{ok,Value}`/`{Class,Reason}`). Last host run: 77 testcases, 0 failures (loop_opt 22, fus 15, fbip 12, budget 20, equiv 8).
- `ssa_opt_budget_SUITE` covers the budget/effort/watchdog/eligibility-gate framework and the `{ssa_opt_fn_budget,Ms}` option; `beam_ssa_opt_equiv_SUITE` cross-checks behavioural equivalence of the opt-in passes ON vs OFF and benchmarks them (its verdict is de-noised and inconclusive — see Known Issues).
- `make test`/`ct_run` cannot drive these suites when the environment's OTP is older than this tree (OTP-30 beams fail to load on a released host OTP with "Use of opcode 193", and `ts_install_cth` is not installed). Use the committed host-side runners instead: `scripts/host_env.sh build` (flattens a scratch copy of `src/*.{erl,hrl}` via `host_env_xform.py` and compiles it with the host `erlc`; prints `RIG_EBIN=<dir>`), then `test/run_stage2_suites.sh` (the five Stage-2 suites; exit 0 = green) and `test/measure_stage2_compile.sh` (deterministic "modules whose `Code` chunk changed" counts per option set plus wall-clock ratios). See `test/CONTEXT.md` and `scripts/CONTEXT.md`.
- The opt-in passes fire on real code: over the 96-module `lib/stdlib/src` corpus `loop_opt+loop_arith_licm` changes 24 modules, `fusion_opt` 2, `fbip_opt` 3 and all of them together 27 (deterministic counts); the wall-clock cost of enabling all of them is ~+11-15% — the host is shared/heavily loaded, so only that ratio is meaningful, never absolute times.
- `beam_validator` rejects malformed assembly; `beam_ssa_check` consumes `%%` directives in test data to assert SSA annotations.
- `scripts/smoke` is a manual, release-time end-to-end check (builds Elixir + Mix projects) — not part of CI/CT.

## Routing Table
- `src/` → all compiler sources: `compile` API + pass pipeline, Core Erlang (`v3_core`/`cerl*`/`sys_core_*`), BEAM SSA (`beam_core_to_ssa`/`beam_ssa*`/`beam_types`), codegen & assembly (`beam_ssa_codegen`/`beam_asm`/`beam_a`/`beam_block`/`beam_jump`/`beam_validator`/`beam_disasm`), generated `beam_opcodes`/`core_parse`; also the opt-in Stage 2 passes — `beam_ssa_loop_opt` (flag `loop_opt`; machinery in `beam_ssa_loop_cfg`/`beam_ssa_loop_reduce`/`beam_ssa_loop_arith`, incl. the `loop_arith_licm` arithmetic-LICM sub-pass), `beam_ssa_fus` (flag `fusion_opt`; Fusions 1/2/4/5), `beam_ssa_fbip` (flag `fbip_opt`; registered in `epilogue_module_passes/1` as the named module pass `ssa_opt_fbip`) — and the opt-in per-pass budget/effort/watchdog/eligibility-gate framework `beam_ssa_opt_budget` (`ssa_opt_budget`/`ssa_opt_fn_budget`/`ssa_opt_watchdog`/`ssa_opt_gates`, see `src/CONTEXT.md` for the wiring, reach and soundness limits)
- `test/` → Common Test suites (feature suites, cloned option-set suites, pass suites incl. the Stage-2 `beam_ssa_loop_opt_SUITE`/`beam_ssa_fus_SUITE`/`beam_ssa_fbip_SUITE`/`ssa_opt_budget_SUITE`/`beam_ssa_opt_equiv_SUITE`, property tests, fixture data dirs) plus the host runners `run_stage2_suites.sh` + `stage2_suite_driver.erl` and the compile-throughput harness `measure_stage2_compile.sh` + `stage2_bench.erl`
- `doc/` → ExDoc build config (`docs.exs`), `Makefile` (via `make/doc.mk`), and `notes.md` (app release notes)
- `internal_doc/` → contributor-facing internals docs: `beam_ssa.md` (SSA invariants), `ssa_checks.md` (SSA checkers), `cerl-notes.md`
- `scripts/` → the host-side test rig `host_env.sh` + `host_env_xform.py` (builds `src/` for a released host OTP), the manual end-to-end smoke test (`smoke` escript + `smoke-mix.exs` + `smoke-build/` scratch dir) and `otp30_env.sh` (dev build/test helper for a full OTP-30 build, needs autoconf/m4); not installed, not in CI
- `priv/` → empty runtime-data dir (only `.gitignore`), reserved by convention
- `vsn.mk` / `Makefile` → `COMPILER_VSN`, `SUB_DIRECTORIES = src doc`, and the `test` override that enables `maybe_expr`
- `../make/` → shared OTP build makefiles (`app_targets.mk`, `otp_subdir.mk`, `doc.mk`) invoked from here (sibling — read-only, escalate writes to parent)
- `../stdlib/` → provides `erl_lint`, `erl_parse`, `erl_compile.hrl` used by `src/` (sibling — read-only from this node)
- `../../erts/emulator/utils/beam_makeops` → generates `src/beam_opcodes.*` from `genop.tab` (external to this app)
