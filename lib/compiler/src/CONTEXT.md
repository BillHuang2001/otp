# Erlang Compiler — Sources (`lib/compiler/src`)

## Intent
Implementation of the `compiler` OTP application: translates Erlang source (`.erl`) or an intermediate form (`.abstr`, `.core`, `.S`) into BEAM object code.
Flat directory of ~68 modules with **no subdirectories** — one module per compiler pass/family, all installed under `compiler`.
Public API lives entirely in `compile.erl`; every other module is an internal pass or helper (`-moduledoc false` except `cerl`, `cerl_clauses`, `cerl_trees`, `compile`).

## API Surface — `compile.erl` (the module other apps/tools call)
- Entry points: `file/1,2`, `noenv_file/2` (skip `ERL_COMPILER_OPTIONS`), `string/1,2`, `forms/1,2`, `output_generated/1`.
- Legacy `erl_compile`/`erlc` interface: `compile/3`, `compile_asm/3`, `compile_core/3`, `compile_abstr/3` (take the `#options{}` record from `stdlib/include/erl_compile.hrl`).
- Introspection/utility: `options/0` (prints `--help`), `env_compiler_options/0`, `run_sub_passes/2`.
- Exported types: `option/0`, `forms/0` (abstract forms or `cerl:c_module()`), `comp_ret/0`.
- `cerl`/`cerl_clauses`/`cerl_trees` are the documented Core Erlang AST API (the only compiler modules with real `-moduledoc`, grouped as "Internal Modules" in `../doc/docs.exs`; used by `lfe`, `dialyzer`-adjacent tools, etc.); `cerl_inline` and `core_lib` are `-moduledoc false` but also used externally.

## The compilation pipeline (intermediate representations)
Source → Erlang **abstract code** (AST) → **Core Erlang** → **BEAM SSA** → BEAM **assembly** → **BEAM binary**, driven by `compile.erl`.
- Abstract level: `compile.erl` pass funs `parse_module` (epp), `transform_module` (parse transforms), `lint_module` (`erl_lint`), `beam_docs`, `remove_doc_attributes`, `compile_directives`, `expand_records`, `legalize_vars`, `core` (→ `v3_core`).
  - `sys_pre_attributes` reorders/normalizes source attributes; `sys_messages` formats errors/warnings; `sys_coverage` instruments code for line coverage (`line_coverage`); `beam_doc` builds the EEP-48 `Docs` chunk.
- Core Erlang: `v3_core` (AST→Core); `cerl`, `cerl_trees`, `cerl_clauses`, `core_lib` (AST API); `core_scan` + `core_parse.yrl`(→ generated `core_parse.erl`) parse Core text; `core_pp` pretty-prints it; `core_lint` validates; `rec_env` is the record environment (`cerl_inline`).
  - Optimizers: `sys_core_prepare`, `sys_core_fold` (+ `sys_core_fold_lists` for lists inlining), `cerl_inline` + `sys_core_inline` (inliner, `core_inline_module`), `sys_core_alias`, `sys_core_bsm`.
- BEAM SSA: `beam_core_to_ssa` (Core→SSA); `beam_ssa` + `beam_ssa.hrl` (format/utilities), `beam_ssa_lint` (internal consistency checks), `beam_ssa_pp` (pretty-printer), `beam_ssa_check` (`check_ssa` assertions in test suites).
  - SSA passes run from `kernel_passes/0`, in order: `beam_ssa_bool` → `beam_ssa_share` → `beam_ssa_recv` → `beam_ssa_bsm` → `beam_ssa_opt` → `beam_ssa_throw`.
  - `beam_ssa_dead`, `beam_ssa_bc_size`, `beam_ssa_alias`, `beam_ssa_destructive_update` run as sub-passes *inside* `beam_ssa_opt` (as does `beam_ssa_share:block/2`).
  - Type system: `beam_types` + `beam_types.hrl` (type lattice), `beam_ssa_type` (SSA type analysis run inside `beam_ssa_opt` via `opt_start/opt_continue/opt_finish`), `beam_call_types` (call return-type inference), `beam_bounds` (tight integer bounds, "Hacker's Delight").
  - `beam_ssa_pre_codegen` (prepare SSA for codegen: register allocation, frame size, native records), then `beam_ssa_codegen` (SSA→assembly).
- BEAM assembly/codegen: `beam_a` (normalize), `beam_block`, `beam_jump`, `beam_clean`, `beam_trim` (stack trimming), `beam_flatten`, `beam_z` (inverse of `beam_a` renames), `beam_utils`, `beam_validator` (strong/weak stack/register validation), `beam_asm` (final assembler, emits the BEAM binary), `beam_dict` (literal/atom table), `beam_listing`, `beam_disasm` (+ `beam_disasm.hrl`).

## The pass pipeline is data
- `passes/2` → `passes_1/1` picks the initial pass list by input type (`from_abstr`, `from_core`, `from_asm`, else `parse_module` + `standard_passes/0`); `fix_first_pass/1` adapts it for `forms` input.
- Pass-list builders define each stage: `standard_passes/0` (abstract + `abstr_passes/1`), `abstr_passes/1`, `core_passes/1`, `kernel_passes/0` (Core→SSA→codegen), `asm_passes/0` (assembly opts), `binary_passes/0`.
- `select_passes/2` expands commands into a flat `[{Name,Fun}]` list; `select_cond/5` + `select_list_passes/1` resolve conditions. Command forms: `{pass,Mod}` (calls `Mod:module/2`), `?pass(Name)`/`{Name,Fun}`, `{Name,Test,Fun}`, `{listing,Ext}`, `{src_listing,Ext}`, `done`/`{done,Ext}`, `{iff,Flag,Cmd}`, `{unless,Flag,Cmd}`, `{delay,[Cmds]}`.
- Pass state is the private (unnamed) `-record #compile{}` in `compile.erl` (filename, module, abstract_code, options, mod_options, errors, warnings, extra_chunks).
- New optimizations are inserted by editing the relevant builder list (`core_passes`/`kernel_passes`/`asm_passes`); toggleable passes are wrapped in `{unless,no_<x>_opt,…}` (see the `no_*` / listing flag options in `expand_opt/2` and `options/0`). These `compile.erl`-level `no_*` toggles are **hand-written** — there is NO `no_<pass>` auto-generator in `compile.erl` (no `passes_2/3`, `opt_passes`, or `return_not_used_pass` exist anywhere in the repo; `passes_1/1` at `compile.erl:1680` only picks the input-type pass list).
- The SSA sub-pass `no_*` toggles ARE **auto-generated**: `beam_ssa_opt.erl:457-467` (`passes/3`, called by both `passes_1/2` and `passes_1_module/2`) builds `{no_<name>,<name>}` from each `{Name,Fun}` pass, feeds them to `proplists:normalize(Opts,[{negations,…}])`, and for a disabled pass substitutes `{no_<name>,fun(S)->S end}` — the pass stays in the pipeline (and is still timed) but does nothing.
- `options/0` (`compile.erl:3277`) prints `--help` by `help/1` walking `standard_passes/0`: each `{unless,no_X,{pass,Y}}` becomes "no_X - Skip the Y pass" (`help/1` at `compile.erl:3296-3309`), so the documented `no_*` flags are derived from the pass-list data. `options/0` additionally feeds `help/1` synthetic entries for flags consumed inside `beam_ssa_opt` (in pass lists that `help/1` does not walk, hence invisible to `standard_passes/0`): four `{iff,Flag,{Name,Fun}}` entries for the opt-in SSA optimization flags `loop_opt`, `loop_arith_licm`, `fusion_opt` and `fbip_opt` (`compile.erl:3282-3285`, rendered "<Flag> - Run <Name>") and four `{iff,Flag,{desc,Text}}` entries for the SSA budget/watchdog/gate options `ssa_opt_budget`, `ssa_opt_watchdog`, `ssa_opt_gates` and `ssa_opt_fn_budget` (`:3288-3295`, rendered "<Flag> - <Text>"; the latter four are also registered in `expand_opt/2` at `compile.erl:1318-1340`).
- `run_sub_passes/2` runs phase-level sub-passes with optional timing; the `time` option collects per-pass and per-sub-pass times (`?PASS_TIMES` / `?SUB_PASS_TIMES`).

## Core Erlang stage (`core_passes/1`, `compile.erl:1925-1952`)
Runs under `unless,no_copt` inside a `{delay,…}`, in order: `core_old_inliner` → `sys_core_fold` → `core_inline_module` → `core_fold_after_inlining` → `sys_core_alias` → `core_transforms`; then `kernel_passes/0` (`compile.erl:1954`) runs `sys_core_bsm` before `core_to_ssa`.
- `sys_core_prepare` (receive lowering) runs only for `non_verified_core` input (`compile.erl:1927-1932`), i.e. Core generated from Erlang, not verbatim `.core`.
- TWO Core inliners coexist:
  - legacy `sys_core_inline` via `core_old_inliner` (gate `test_old_inliner`, `compile.erl:2746` — any `{inline,_}` option); node-count weight threshold (`-record(inline,{exports,thresh,inline})`); effectively a no-op without explicit inline options.
  - default modern `cerl_inline:core_transform/2` via `core_inline_module` (gate `test_core_inliner`, `compile.erl:2753` — any `inline` option unless `no_inline`); Waddell/Dybvig algorithm, effort/size/unroll counters `default_effort()`=150, `default_size()`=24, `default_unroll()`=1 (`cerl_inline.erl:118-120`).
- `sys_core_fold` optimizes each function to a fixed point (`find_fixpoint/3`, max 20 iterations, `sys_core_fold.erl:133-150`): constant folding, call/case/guard/boolean/comprehension simplification, list-function inlining (`sys_core_fold_lists`).
- `core_lib` is small (180 lines), exports only `make_values/1` and `is_var_used/2` — not a general Core AST library.

## BEAM SSA optimizer structure (`beam_ssa_opt.erl`)
`module/2` (`beam_ssa_opt.erl:111`) runs six phases: `prologue_passes` → `module_passes` → `repeated_passes` (to fixpoint, `?MAX_REPETITIONS`=16) → `early_epilogue_passes` → `epilogue_module_passes` → `late_epilogue_passes` (the six builders span lines ~319-444).
- Each phase runs every sub-pass on all functions before the next phase; a sub-pass is an in-file `ssa_opt_*` function or a delegate to a module: `ssa_opt_bc_size`→`beam_ssa_bc_size:opt/1`, `ssa_opt_alias`→`beam_ssa_alias:opt/2`, `ssa_opt_destructive_update`→`beam_ssa_destructive_update:opt/2`, `ssa_opt_type_start/continue/finish`→`beam_ssa_type:opt_*`.
- Function order is chosen by call order and alternated each fixpoint iteration; only changed functions (SSA or type info) are re-run (`changed/5`, `changed_types/5`).
- Watchdogs / budgets: `fixpoint/6` gives up after `?MAX_REPETITIONS`=16 iterations returning the current state (`beam_ssa_opt.erl:106`, `:145-173`); `beam_ssa_alias` has its own per-function cap (`?MAX_REPETITIONS`=16, `beam_ssa_alias.erl:33,392`) and on `throw:too_deep` discards the whole module's result (`:133-139`); the sharing-state depth limit is `?SS_DEPTH_LIMIT`=30 (`beam_ssa_ss.erl:67,486` → `throw(too_deep)` at `:496`); `beam_ssa_dead` caps its forward search at 64 unset vars (`beam_ssa_dead.erl:208-214`); `cerl_inline` uses effort/size/unroll counters that `throw({counter_exceeded,…})` (`cerl_inline.erl:2819-2838`, caught at `:1811`/`:1846`).
- The `time` option (`compile.erl:1318-1319`) records per-pass and per-sub-pass timings: `internal_comp/5` selects `fold_comp_times/4` (`:1433-1451`), `runner/1`→`run_tc/3` (`:1521-1534`) writes `{Name,Elapsed,Mem,SubTimes}` into the `?PASS_TIMES` process-dictionary list, `run_sub_passes/2` (`:1189-1204`) times each sub-pass into `?SUB_PASS_TIMES`, and `print_pass_times/2` (`:1536-1568`) formats them. Related profiling options: `call_time`/`call_memory` (tprof) and `eprof` (`runner/1` at `:1498-1519`, `run_eprof/4`/`run_tprof/5` at `:1570-1591`).

## Type system (SSA)
- `beam_types` + `beam_types.hrl`: lattice of normal-form records (`#t_atom/#t_bitstring/#t_bs_context/#t_bs_matchable/#t_cons/#t_float/#t_fun/#t_integer/#t_list/#t_map/#t_number/#t_record/#t_tuple`) plus one `#t_union{}` (six non-overlapping slots); ops `meet/1,2`, `join/1,2`, `subtract/2`, `glb/2`, `lub/2`, `normalize/1`, `limit_depth/1`; union simplification is only `shrink_union/1` + `normalize/1` (no digraph).
- `beam_ssa_type`: `opt_start/2` (module-wide signature/success-typing pass), `opt_continue/4`, `opt_finish/3` (joins per-call-site param types and publishes the `parameter_info` annotation). Cross-function types flow through `#func_info{arg_types,succ_types}` (`beam_ssa_opt.erl:51-78`).
- `beam_call_types`: `types/3` (return type + arg types for builtins/known funcs), `will_succeed/3`, `arith_type/2`.
- `beam_bounds`: integer range lattice — `bounds/2,3`, `relop/3`, `infer_relop_types/3`, `is_masking_redundant/2`; ranges cap at `?NUM_BITS`=128.
- External type format: `beam_types:encode_ext/1` / `decode_ext/1` / `convert_ext/2` emit a compact `Type` chunk (version `?BEAM_TYPES_VERSION` in `beam_types.hrl`) consumed by the erts JIT; encoded in `beam_dict`/`beam_asm`, decoded by `beam_disasm`.

## Loop, fusion, specialization & plug-in point
- **Loop optimizations are opt-in only**: `beam_ssa_loop_opt.erl` is a 441-line driver owning two passes, both registered in `beam_ssa_opt:repeated_passes/1` (`beam_ssa_opt.erl:366-384`) — i.e. AFTER the SSA type analysis, so `beam_types`/`beam_bounds` annotations are available. `loop_opt` (pass `ssa_opt_loop_opt`, entry `opt/1`) does loop recognition, LICM of non-raising tag tests/constructors into a preheader, whole-function in-place strength reduction and induction-variable canonicalisation. The separate `loop_arith_licm` (pass `ssa_opt_loop_arith_licm`, entry `opt_arith/1` → `beam_ssa_loop_arith:arith_licm/4`) hoists non-raising arithmetic (`?ARITH_BIFS`) into the loop preheader only when every operand is loop-invariant and its integrality is proven AT THE PREHEADER; `loop_opt` alone never enables it.
  The machinery is split into three siblings: `beam_ssa_loop_cfg.erl` (CFG vocabulary — successors/predecessors, dominators, natural-loop recognition, the loop iteration region, preheader insertion, RPO ordering, the cheap back-edge gate), `beam_ssa_loop_reduce.erl` (whole-function strength reduction, induction-variable canonicalisation, integrality/non-negativity proofs) and `beam_ssa_loop_arith.erl` (the arithmetic LICM).
  `beam_ssa:is_loop_header/1` (`beam_ssa.erl:397`) is receive-only (`peek_message`/`wait_timeout`).
- **Deliberately NOT implemented (no flags)**: loop unrolling (`loop_unroll`) and loop-index narrowing (`loop_index_narrowing`) — see the `beam_ssa_loop_opt.erl` moduledoc. The only CFG cycles reaching the pass are the `receive` loops built by `beam_ssa_recv` (a tail-recursive function is still a tail `call`), which have no compile-time trip count and cannot have their body duplicated without reordering the mailbox; and BEAM has one arbitrary-precision integer type with no narrow/wrapping instruction, so there is nothing to narrow an index into (the one cheaper form, `rem 2^n`→`band (2^n-1)`, is already the reducer's `rem` rule).
- Loop-shaped infrastructure: the loop pass's CFG machinery (`beam_ssa_loop_cfg`) builds its own recognition, dominators and RPO ordering; the shared `beam_ssa` helpers `rpo/1,2`, `linearize/1`, `dominators/2`, `dominators_from_predecessors/2`, `common_dominators/3`, `predecessors/1`, `successors/1` remain available.
- Existing fusion — the opt-in `beam_ssa_fus.erl` (flag `fusion_opt`) fuses a `has_map_field` test + `get_map_element` extraction across a block edge (Fusion 1) and a matching multi-key `has_map_field` test chain (Fusion 2); the remaining fusions are block-local peepholes in `beam_ssa_opt.erl` and none of those fuses mixed ops or crosses blocks:
  - `merge_updates_bs` (~`:525`): merge consecutive `update_record` on the same record; folds `put_tuple`+`update_record`.
  - `update_tuple_opt` (~`:1081`): merge a chain of `setelement/3` into one `update_tuple` pseudo-instruction (undone by `ssa_opt_deoptimize_update_tuple` ~`:3953`, re-expanded in `beam_ssa_pre_codegen:expand_update_tuple`).
  - CSE `combine_put_maps` (~`:1392`): merge a `put_map` whose source is a preceding assoc `put_map`.
  - `record_opt` (~`:990`): fuse `is_tuple`+`tuple_size`+`get_tuple_element(0)` → `is_tagged_tuple`.
  - `ssa_opt_element` (~`:917`): reorder `element/2` calls (highest index first; no fusion).
- Destructive/in-place reuse chaining is module-level: `beam_ssa_destructive_update.erl` (+ `beam_ssa_alias.erl` for uniqueness) marks `update_record` with the `inplace` hint and rewrites growing `bs_create_bin` chains to `bs_init_writable` + `private_append` (the instruction is `bs_init_writable/0`, NOT `bs_writable_binary` — the latter name appears only in comments/docs).
- Specialization points: `ssa_opt_is_between` (~`:625`) rewrites `is_integer/3` range tests to `is_integer/1` + two `=<`; `ssa_opt_ne` (~`:2762`) rewrites `=/=`→`=:=` / `/=`→`==` and swaps branch targets; `ssa_opt_sw` (~`:2713`) turns a single-value/boolean `#b_switch{}` into `#b_br{}`/`is_boolean`. Type-driven opcode selection lives in `beam_ssa_type`/`beam_call_types` and codegen (`beam_ssa_codegen`: `is_tagged_tuple` constraints, `has_map_field`→`has_map_fields`, `get_map_element`→`get_map_elements`). `beam_ssa_bc_size` computes exact writable-binary sizes.
- **Plug-in point for a new SSA pass**: add a `?PASS(name)`-wrapped `name/1 :: #opt_st{} -> #opt_st{}` fun to `prologue_passes/1`, `repeated_passes/0` (the fixpoint loop), `early_epilogue_passes/1`, or `late_epilogue_passes/1` in `beam_ssa_opt.erl` (pass lists are data; `passes_1/2` auto-generates the `no_<name>` toggle). Module-level passes take `{StMap, FuncDb}` and are wired in `module_passes/1` / `epilogue_module_passes/1`. Sub-pass contract is `compile:run_sub_passes/2` (runs `Fun(St) -> St`, ~`compile.erl:1187`). A wholly new IR would sit between `core_to_ssa` (`compile.erl:1962`) and `beam_ssa_pre_codegen` (`:1992`).

## List operations — lowering & optimization
- Higher-order `lists` inlining is **opt-in only** (`inline_list_funcs`; gate `sys_core_fold.erl:116,827`, documented `compile.erl:125-146`): `sys_core_fold_lists:call/4` (`:37-396`) rewrites `lists:all/2 any/2 foreach/2 map/2 flatmap/2 filter/2 foldl/3 foldr/3 mapfoldl/3 mapfoldr/3` into a Core `#c_letrec{}` reproducing the library loop with the SAME evaluation order (`:32`) and the same error terms (`match_fail`/`function_clause`, `:400-409`). It does **NOT** eliminate output cons cells (`map` still builds `#c_cons` at `:138`; foldl/foldr still do one fun call per element `:233-263`).
- `++`/`lists:append/2` are only constant-folded (`sys_core_fold:eval_append/3` `:987-1004`); `'++'` is pure (`erl_bifs.erl:60`), `[] ++ L → L` at SSA (`beam_ssa_type.erl:1855`). No pass fuses *chains* of list functions (`map∘filter∘fold`) or Elixir `Enum.*` — every intermediate list is materialized; `beam_call_types.erl:942-1062` only infers per-call return/arg types.
- List comprehensions are lowered in `v3_core`: each generator → a recursive `letrec` (`lc_tq1` `:1937`, `zip_tq` `:1990`), filters woven in as guards/`bad_filter` cases of the same loop (`filter_tq` `:2279`, `:2300`) — generator+filter fuse into one loop but output cons cells are still built. `sys_core_fold:opt_lc/1` (`:2225`, called `:308`) specializes a singleton-list generator. `beam_ssa_bsm` is **bit-syntax only**, not lists.
- Cons lowering: build = `put_list` (`beam_core_to_ssa.erl:355`); match `[H|T]` = `is_nonempty_list`+`get_hd`+`get_tl` (`:2936-2943`); `hd`/`tl` bifs → `get_hd`/`get_tl` when cons-typed (`beam_ssa_type.erl:1302-1315`).
- In-place reuse covers bitstrings + tuples/records only (`beam_ssa_destructive_update.erl:53-90`); `beam_ssa_alias.erl` marks `put_list` unique (`:573`) but there is no destructive list path — the tracker explicitly refuses the tail field of a cons (`beam_ssa_destructive_update.erl:627-636`).

## Destructive update & alias analysis (in-place reuse)
Two epilogue module passes do all destructive-update work, in this order (`beam_ssa_opt.erl:348-357`): `ssa_opt_alias` → `beam_ssa_alias:opt/2`, then `ssa_opt_destructive_update` → `beam_ssa_destructive_update:opt/2`. `beam_ssa_opt` phase order is prologue → module → repeated(fixpoint) → early_epilogue → epilogue_module → late_epilogue (`beam_ssa_opt.erl:124-129`); `ssa_opt_no_reuse` runs in early_epilogue (`:362`), i.e. BEFORE the alias/destructive passes.

### `beam_ssa_destructive_update.erl` — exactly two transforms
- **In-place `update_record`**: a `update_record` with `anno=#{source_dies:=true}` whose `Src` is `unique` gets its hint rewritten `reuse`→`inplace` (`fai_i/5` `:204-218`, `is_unique/2` `:304-305`, `set_inplace/1` `:892-894`).
- **`private_append` for growing binaries**: `bs_create_bin` with `append` flag + `first_fragment_dies:=true` + unique first fragment (`is_unique/2`, `is_appendable/2` `:307-314`) is rewritten to `private_append`; a literal `<<>>` seed becomes `bs_init_writable` (`fai_i/5` `:176-203`, `patch_is/5` `:860-874`, `patch_literal_term/3` `:1034-1059`).
- Both consult annotations written by `beam_ssa_alias`: the `unique` ordset, plus the booleans `source_dies` (update_record) and `first_fragment_dies` (bs_create_bin).
- Three phases: scan (`find_applicable_instructions/2` `:154`), initial-value search (`find_initial_values/3` `:240`, dataflow tracker `fiv_*`), patch (`patch_instructions/5` `:272`). Depth/`too_deep` bail-out via `?ELEMENT_DEPTH_LIMIT` (`:116`).
- Literal list handling exists (`fiv_track_put_list/8` `:627`, `patch_literal_list/3` `:1072`) but ONLY for the HEAD field of a cons — the tail is deliberately never tracked because "the type analyser always assumes that a cons is part of a list" (`:379-386`, `:632-636`). There is NO destructive update of cons cells.

### `beam_ssa_alias.erl` + `beam_ssa_ss.erl` — uniqueness/escape analysis
- Lattice: `sharing_status() :: unique | aliased | no_info` (`beam_ssa_ss.erl:86`). The state (`sharing_state()`) is a **graph** of variables/values whose edges are labelled `{extract,Element}` / `embed` / `{embed,Element}` where `Element` is `hd | tl | non_neg_int` (`beam_ssa_ss.erl:87,103-122`); per-node label is the status. Whole-pass state is `#aas{}` (`beam_ssa_alias.erl:61-79`).
- Seeding at function boundaries (`aa/5` `beam_ssa_alias.erl:330-348`): **exported functions' args = `aliased`; non-exported = `no_info`** (comment says "unique" but the code sets `no_info`); refined per call site by `aa_add_call_info/4` (`:1357`) via `beam_ssa_ss:merge_in_args/3` (`:730`). `initialize_in_args/1` (`beam_ssa_ss.erl:671-673`) is a trivial identity.
- Return seeding: `aa_terminator/3` for `#b_ret{}` (`:680-694`) computes a per-return-type status; consumed at the call site by `aa_get_status_by_type/2` (`:951-966`).
- Calls: local known+analysed → `set_call_result/4` (`:1303-1334`, `beam_ssa_ss.erl:579`); local not-yet-analysed → Dst `no_info` (`:1340`); remote/fun/unknown → Dst AND surviving args `aliased` (`:1348-1353`); `erlang:exit/1` → dead end (`:1342`). Funs: `aa_make_fun/5` (`:1445-1468`) aliases env + forces callee args `aliased` and schedules a revisit.
- Merge/meet: `beam_ssa_ss:merge/2` (`:345-445`, aliased dominates) for branching, `forward_status/2` (`:318-337`) for post-order status propagation; `meet_in_args/1` (`:675-703`) for call-arg statuses.
- Annotation producers: `aa_update_annotation_for_var/3` writes the `unique` / `aliased` ordsets (`:906-931`); `aa_update_annotation1/3` writes `first_fragment_dies` / `source_dies` (`:868-901`). These four are the ONLY alias outputs other passes read (grep: only `beam_ssa_destructive_update.erl:191,206,305` consume them).
- Synthetic-IR trick: `expand_record_update/1` + `restore_update_record/1` (`:1538-1647`) temporarily insert synthetic `get_tuple_element` ops so the alias pass can see fields read by `update_record`, then strip them.
- `beam_ssa_ss` has depth limits (`?ARGS_DEPTH_LIMIT=4`, `?SS_DEPTH_LIMIT=30`, `:66-67`) and throws `too_deep` (caught in `beam_ssa_alias.erl:133-139`).

### Where lists/maps are excluded from reuse (`beam_ssa_opt.erl`)
- `inhibits_reuse/2` (`:3898-3937`): any `put_list` (`:3934`) or `put_tuple` (`:3935`) result is unconditionally marked non-reusable; `put_map` (`:3902-3903`) is marked non-reusable when any of its update values is already non-reusable. Any `update_record` whose update values intersect that set is downgraded `reuse`→`copy` (`ssa_opt_no_reuse_is/3` `:3878-3886`, `cannot_reuse/2` `:3939-3942`).
- Map values also get whole-term (not per-key) alias treatment: `put_map` → `aa_construct_term/5` (`beam_ssa_alias.erl:578,1125`), `get_map_element` → `aa_map_extraction/4` → `aa_derive_from/3` with a plain `embed` edge (`:1408-1411`). Cons cells DO get per-field edges via `aa_construct_pair/5` (`:1181-1187`) → `aa_build_tuple_or_pair/6` (`:1153-1179`) → `beam_ssa_ss:embed_in/3` (`:159`), and `get_hd`/`get_tl` → `aa_pair_extraction/5` (`:1382`) → `beam_ssa_ss:extract/4` (`:213`).
- `beam_ssa_share.erl` is NOT relevant to value reuse — it shares equivalent basic-block terminators (`module/2`, `block/2`), nothing about cons cells/maps.

### `beam_ssa_bc_size.erl` — relevance
Module pass `ssa_opt_bc_size` (`beam_ssa_opt.erl:317-321`). Computes the exact size of a writable binary built by `bs_init_writable` + `bs_create_bin private_append` (binary comprehensions) so the initial allocation is right-sized (`opt_blks/7` `:77-112`, `opt_writable/7` `:114`, `calc_size_instr/2` handles `private_append` at `:323`). It only feeds the writable-binary/`private_append` path (via `beam_ssa_destructive_update`); unrelated to tuple/cons destructive update. Runs before the `private_append` rewrite (in `module_passes`, i.e. before `epilogue_module_passes`).

### Gap for extending in-place reuse to LISTS / MAPS (FBIP)
- No destructive-update IR exists for these: `genop.tab` has only `update_record/5` (`:683`) and `update_record_id/7` (`:801`) with `copy`/`reuse` hints (doc lists only those two hints, `:672-682`; the compiler also emits `inplace` — a doc gap). `put_list` codegen is a plain 2-field `{put_list,Hd,Tl,Dst}` (`beam_ssa_codegen.erl:2453`); no `update_cons`/chunked-append op.
- Would require: (1) a new IR/codegen instruction + alias-aware construction pattern recognized by a `find_applicable_instructions`-style scan (the writable-binary + `private_append` path in `beam_ssa_destructive_update.erl` is the closest existing template); (2) relaxing `inhibits_reuse/2` put_list/put_map (`beam_ssa_opt.erl:3902,3934`); (3) per-key map embed/extract edges (maps currently coarse: `beam_ssa_alias.erl:578,1408`); (4) a type-system notion of a uniquely-owned partial chunk with spare capacity (today a cons is only modelled as part of a list — `beam_ssa_destructive_update.erl:379-386`); (5) alias/codegen/heap-need wiring for the new op (`beam_ssa_alias.erl:495-672`, `beam_ssa_codegen.erl:423,439`).

## `genop.tab` — external generic instruction table (format)
- Input to `erts/emulator/utils/beam_makeops -compiler` → `$(EGEN)/beam_opcodes.erl` (numbered opcode table, `format_number/0`) + `.hrl`; the **same** file feeds the emulator build, so opcode numbers must stay backward compatible. `Makefile:178` drives it; `OPCODES-GENERATED` is the git-ignored marker.
- One declaration per line: `N: name/arity` (external generic instruction) or `N: -name/arity` (obsoleted — `-` prefix: compiler must not emit it, loader refuses it). `N` is the opcode, 1-based, unique, never reused; new instructions must be **appended** with higher numbers (arity = operand count).
- Opcodes currently **1..193** (193 declared): 134 live, 59 obsolete (`-`-prefixed). Only `name/arity` is declared here — operand **types are NOT in this file**; they live in the emulator's `ops.tab` (types `x/y/l/i/a/n/q/f/p/u/…`).
- `genop.tab` lists ONLY the opcodes the compiler may emit. Loader-only super-instructions (`move_call{,_only,_last}`, `move_jump`, `move_return`, `move_deallocate_return`, `deallocate_return{0..4}`, `test_heap_1_put_list`, `move_window{2..5}`, `move_shift`, `move_trim`, `swap2`, `i_*`, `call_light_bif*`, `i_jump_on_val*`, `select_literals`, `split_values`, `new_small_map_lit`, `sorted_put_map_*`, `update_map_{assoc,exact}`, `wait_timeout_unlocked*`, `int_func_{start,end}`) are deliberately absent — they are created by the emulator's loader/combining rules in `erts/emulator/beam/emu/ops.tab` (`=>`), never written into a `.beam`.
- `bif` and `gc_bif` are NOT opcodes here: `beam_ssa_codegen` emits them as pseudo-instructions (`{bif,Name,Fail,Args,Dst}`, `{gc_bif,Name,Fail,Live,Args,Dst}`) and `beam_asm` expands them to `bif0/bif1/bif2/bif3` (`beam_asm.erl:667-680`), `gc_bif1/2/3` (`:681-688`), or a dedicated op for float/misc BIFs (`fadd/fsub/fmul/fdiv/fnegate/get_record_field` via `bif_type/2` `:645-653`, `raise` `:670`) and drops `{'%',_}` (`:655`). The final Code chunk is also reshaped by the assembly passes before `beam_asm`: `beam_a` normalizes (`put_map_assoc`→`put_map`, `select_val`→`select`, `send`→`call_ext 2 send`) and `beam_z` restores the external forms and fuses `get_hd`+`get_tl`→`get_list` (`beam_z.erl:87-103`) and `{test,is_eq_exact,[S,nil]}`→`is_nil` (`:113-114`); `beam_trim` emits `trim` (`beam_trim.erl:217`); `beam_asm` emits `on_load` (`:125`) and `int_code_end` (`:137`).
- `BEAM_FORMAT_NUMBER=0` (line 22) — instruction-set format version stored in the BEAM code header; only bump if an existing op changes number/arity/semantics.
- `#` lines are comments; `## @spec …`/`## @doc …` lines are documentation **not consumed by `beam_makeops`**. No `%if`/`%hot`/C-code directives here (those are emulator `.tab` features).
- Existing opcodes' number/arity/semantics must not change (see `erts/emulator/internal_doc/beam_makeops.md`).

## Notes for Agents
- Everything is a module, not a directory: to change a stage, edit the owning module and (if it is a toggleable pass) the corresponding list in `compile.erl`.
- Low-level BEAM assembly passes run in this fixed order (`compile.erl` `asm_passes/0`): `beam_a` → `beam_block` → `beam_jump` → `beam_clean` → `beam_trim` → `beam_flatten` (under `unless no_postopt`), then `beam_z`; they operate on the flat instruction stream and (apart from `beam_a`/`beam_z`) use the `{block,[{set,Dst,Src,Op}]}` intermediate representation created by `beam_block`. `beam_a`/`beam_z` are a rename/undo-rename pair.
- `beam_utils` is minimal: only `replace_labels/4` and `split_even/1`. BIF classification helpers (`is_pure/3`, `is_safe/3`, `is_exit_bif/3`) live in `erl_bifs`, NOT in `beam_utils`; low-level register-inspecting passes must handle `#tr{}` type-tagged regs (`beam_asm.hrl`).
- `erl_bifs` is a static table of Erlang BIF properties consumed by Core and SSA optimizers (`sys_core_fold`, `beam_ssa_type`, `beam_call_types`, `beam_ssa_opt`, …).
- `beam_ssa_loop_opt` is an OPT-IN SSA pass (compiler option `loop_opt`), registered in `repeated_passes/1` in `beam_ssa_opt.erl` (after the SSA type analysis, so the `beam_types`/`beam_bounds` annotations are available); kill switches are `no_ssa_opt_loop_opt` / `no_ssa_opt` (both auto-derived by `passes_1/2`). It recognises natural loops (edge H->P is a back edge iff H dominates P) and hoists loop-invariant instructions into the loop preheader; hoisting is limited to two hand-written whitelists, because `beam_ssa:no_side_effect/1` is only a "may be omitted if the result is unused" predicate, NOT a cannot-raise predicate: `?SAFE_OPS` (the constructors `put_list`/`put_tuple`, which have block-independent `cg_instr` rules) and `?SAFE_BIFS` (the `{Name,Arity}` tag tests `is_atom/1 is_binary/1 is_bitstring/1 is_boolean/1 is_float/1 is_function/1 is_integer/1 is_list/1 is_map/1 is_number/1 is_pid/1 is_port/1 is_reference/1 is_tuple/1`, pure `ubif` tag comparisons that codegen emits as a standalone `{bif,Name,{f,0},…}`). The arity is part of the key so that the raising `is_function/2` and `is_record/2,3` are never hoisted, and the fused `is_tagged_tuple`/`is_nonempty_list` tests stay excluded (no standalone `cg_instr/3` rule — hoisting them fails code generation). It also *strength-reduces arithmetic in place* (same block/destination): `X*2^n`→`X bsl n` when X is provably an integer, `X*2`→`X+X` otherwise (exact for every number), while `X div 2^n`→`X bsr n` and `X rem 2^n`→`X band (2^n-1)` need X provably a non-negative integer; a non-power-of-two literal factor/divisor, `X div 0` and any operand whose integrality/non-negativity cannot be proved are left untouched. Its third transform is *induction-variable canonicalisation*: a loop-carried phi whose inside edges are all `V+C`/`C+V`/`V-C`/`V` (same literal C) is described by an `{Init,Step}` pair from which the pass proves integrality (and non-negativity for a non-negative Init and Step) and propagates it through integer-valued ops; the recurrence itself is not rewritten, only the operand order of a commutative `C+V`/`C*V` is canonicalised to `V+C`/`V*C`.
- Loop recognition still only finds the message-matching loops built by `beam_ssa_recv` (no other Erlang construct produces a CFG cycle; plain tail recursion is not an SSA loop), but because the pass now runs after the SSA type analysis the whole-function strength reducer fires on ordinary integer arithmetic, and the arithmetic LICM's preheader check accepts a type annotation the loop does not narrow (the droppable `{succeeded,_}`-marker case that used to block it). Reach (over all 98 `lib/stdlib/src/*.erl`): `+loop_opt +loop_arith_licm` changes 23 modules (e.g. `timer.erl`, where `T - ?MAX_RECEIVE_AFTER` is hoisted out of the `sleep/1` receive loop), with 0 compiler crashes.
- LICM needs the loop header to have exactly one predecessor outside the loop (a preheader; a fresh one is inserted on that edge when the predecessor has other successors). A whole-function loop (header = entry block, e.g. most tail-recursive loops) has no outside predecessor and is left untouched. The pass runs AFTER the SSA type analysis, so `#t_integer{elements=...}`/`beam_bounds` annotations are available; they are path-dependent, so the arithmetic LICM trusts one only for an operand the loop does not narrow (`narrowed_vars/3`), and a structural integrality/non-negativity fact (valid because its defining blocks dominate the preheader) is the fallback.

- **Opt-in FBIP pass (`fbip_opt`)** — `beam_ssa_fbip.erl` (module pass `opt/2`) extends in-place reuse to `update_record` sites whose source is provably freshly allocated, uniquely owned and used exactly once, including the result of a local "smart-constructor" call (a case `beam_ssa_alias` treats conservatively: call returns seed `no_info`). A source is accepted only if it is a `#b_var{}`, is not a function argument, has exactly one use, and is defined by `put_tuple`/`put_tuple2`, a `call` to a local "fresh-returning" function (least fixpoint over functions whose every real `#b_ret{}` is fresh; the never-returning `?EXCEPTION_BLOCK` return is ignored), an already-`inplace` `update_record`, or an all-fresh `phi` — the two allocating binary instructions (`bs_init_writable`/an allocating `bs_create_bin`) are deliberately NOT freshness sources, because an `update_record` of a binary is never a valid instruction; and only when the definition block dominates the update block and no cycle through the update block avoids it, so the update runs at most once per allocation (same block, or a unique predecessor of the update block, are special cases). Sound because such a source has reference count 1, making `inplace` indistinguishable from a copy; only for such a source is the hint (`copy` or `reuse`) rewritten to `inplace`, never for any other source. Measured on a record-rebuild loop, `inplace` halves the number of GC'd words and is ~10% faster than `copy`. Enabled by the `fbip_opt` compile option (a raw pass-through option; `options/0` advertises it in `--help` via a synthetic `{iff,fbip_opt,…}` entry): `beam_ssa_opt:epilogue_module_passes/1` then appends the named module pass `{ssa_opt_fbip, fun({StMap,FuncDb}) -> beam_ssa_opt_budget:run(ssa_opt_fbip, beam_ssa_fbip:opt/2, beam_ssa_fbip:eligible/1, true, …) end}` after `ssa_opt_alias`/`ssa_opt_destructive_update`, which is what makes `passes/3` auto-derive its kill switch `no_ssa_opt_fbip` (like its siblings; the global `no_ssa_opt` disables it too). Module pass funs are not wrapped by `wrap_fun/3`, so the pass bounds itself with `beam_ssa_opt_budget:run/5`.
- **Infeasible compiler-only (out of scope)**: in-place reuse of LISTS and MAPS cannot be done by the compiler alone. It requires new BEAM instructions/opcodes (an in-place cons update / chunked append and a per-key map update) added to `erts/emulator/.../genop.tab` + `ops.tab`; the stock erts-17.1 emulator (opcode max 191) could not load or run them, and a cons's tail field is deliberately left untracked. The compiler may only emit existing instructions/annotations.

## Per-SSA-pass time budget, watchdog and eligibility gates (`beam_ssa_opt_budget.erl`)
`beam_ssa_opt_budget.erl` (~700 lines) is the framework that bounds how much time the SSA optimization phases of `beam_ssa_opt` may spend and lets a pass declare a cheap precondition the driver checks before running it.
It is the single decision point at three levels: the whole compilation (a cumulative budget), a single sub-pass (a watchdog) and a single *function* (an effort level plus a wall-clock allowance).
The state term and the pass fun are taken and returned unchanged (it never rewrites the function database), but it does inspect the function size inside `#opt_st{}` (record imported from `beam_ssa_opt`, `beam_ssa.hrl` included) to derive the per-function effort and allowance.
- Compile options (all opt-in and OFF by default; registered in `compile.erl` `expand_opt/2` (`:1318-1340`) and advertised by `options/0`/`help/1` (`:3288-3295`)):
  - `{ssa_opt_budget,Millis}` / `ssa_opt_budget` (default 5000) — cumulative budget for the SSA phases. Once exhausted, `fixpoint/6` returns the current state instead of iterating (equivalent to `?MAX_REPETITIONS`=0) and the still-skippable sub-passes stop running; because the deadline never un-expires, the skipped set is always a monotone suffix of the pass list, which is the only subset shape that is sound.
  - `{ssa_opt_watchdog,Millis}` / `ssa_opt_watchdog` (default 1000) — upper bound on a SINGLE sub-pass, which runs in a monitored child process (started with a copy of the parent's process dictionary, so a pass that reads pdict state sees what it would have seen). On timeout the child is killed and the compilation is aborted with `{ssa_opt_watchdog_timeout,Pass}`; it does NOT silently skip the pass, because a timeout races the pass and the skipped set would be an arbitrary, non-deterministic subset (measured to leave the SSA inconsistent).
  - `ssa_opt_gates` — enable the gates and the statistics without setting any bound.
  - `{ssa_opt_fn_budget,Millis}` / `ssa_opt_fn_budget` — replace the size-derived per-function allowance with `Millis` for every function (`0` ⇒ every function's allowance is immediately exhausted, so all its skippable sub-passes are skipped). Per-function skipping is active only when a global budget or this option is given; with `ssa_opt_gates` alone the output is unchanged. Registered in `compile.erl` `expand_opt/2` (`:1334-1340`) and advertised by `options/0` (`:3294`); covered by the CT case `fn_budget_option_registered/1` in `test/ssa_opt_budget_SUITE.erl`.
- Per-function effort model: `classify/2` (pure) maps a function's *instruction count* to `full` (`≤500`), `reduced` (`≤5000`) or `minimal`; the allowance is `max(50, 500 - Instructions div 20)` ms, i.e. it *shrinks* with size and is floored, so a huge function cannot blow up compile time. Per-function skipping only ever removes a monotone *suffix* of that function's skippable passes, which is sound because functions are optimized independently of each other.
- Public API: `init/1` (called first thing in `beam_ssa_opt:module/2`, before the phase pass lists are built, because wrapping happens while they are built; clears the state when no option is given), `enabled/0`, `over_budget/0` (global), `wrap_fun/4` (returns the original fun unchanged when disabled), `run/5` (also called directly by the `ssa_opt_fbip` entry of `beam_ssa_opt:epilogue_module_passes/1`, i.e. for the opt-in FBIP pass), `get_stats/0`, and the per-function query surface for passes: `effort/0` (`undefined | full | reduced | minimal | none`), `function_size/0`, `function_budget/0`, `function_over_budget/0`, `remaining/0`, plus the pure `classify/2`.
- Per-compilation state lives in the process dictionary of the process running `beam_ssa_opt:module/2` (readable only in that process — use the `no_spawn_compiler_process` compile option to observe it). `get_stats/0` returns `#{ran,gated,over_budget,function_over_budget,timed_out,effort => #{full => N,reduced => N,minimal => N},passes => #{Name => #{ran,gated,over_budget,function_over_budget,timed_out}}}` or `undefined` when the machinery is off. The `effort` counters classify real functions only: a module-level run registers no function.
- Never skipped by the driver (`beam_ssa_opt:skippable/1`): `ssa_opt_split_blocks`, `ssa_opt_linearize`, `ssa_opt_blockify` (they change the SSA representation or its block granularity), `ssa_opt_type_finish` (it publishes the type annotations the code generator and `beam_validator` depend on; skipping it makes codegen emit code the validator rejects — e.g. an unchecked `get_tuple_element` on a value of type `any`), `ssa_opt_live` (the only pass that removes instructions whose result has become dead and strength-reduces their test-only counterparts — `live_opt_is/3`; other passes, among them `ssa_opt_type_finish`, which folds a `{succeeded,guard}` marker away, regularly leave a dead `get_map_element`/`bs_start_match` behind, and codegen has no clause for a bare one) and `ssa_opt_bs_ensure` (it annotates the skip-all binary matches `beam_ssa_bsm` produces; `beam_ssa_pre_codegen:bs_restores_is/5` asserts the annotation is present).
- Eligibility gates (`beam_ssa_opt:gate/1`, `beam_ssa_opt.erl:478-485`) are cheap NECESSARY preconditions of the opt-in passes; when false the pass is skipped and counted as `gated`: `beam_ssa_loop_opt:eligible/1` (`beam_ssa_loop_opt.erl:283-304`) = `beam_ssa_loop_cfg:has_back_edge/1` **orelse** `has_reduce_candidate/1` (a whole-function `*`/`div`/`rem`, or a literal-first `+`/`*`) — a SUPERSET of the pass's real effect, because the whole-function strength reducer fires with no loop, so a back edge is not a necessary precondition; used by BOTH `ssa_opt_loop_opt` and `ssa_opt_loop_arith_licm`. Also `beam_ssa_fus:eligible/1` (a block's last instruction is a `has_map_field` whose dst is the block's branch variable and whose success edge starts with a `get_map_element` for the same map and key) and `beam_ssa_fbip:eligible/1` (some function still has a non-`inplace` `update_record` after the regular destructive-update transform). A false gate means the pass could not have changed anything.
- Module-level phases are not wrapped by `wrap_fun/3`: `ssa_opt_bc_size`/`ssa_opt_type_start`/`ssa_opt_alias`/`ssa_opt_destructive_update` run in the compiling process and have their own internal convergence caps, and the opt-in FBIP pass (`ssa_opt_fbip`, a module-level pass) bounds itself with `run/5`. A module-level run is recognised as such (its state is not `{#opt_st{},_}`): it registers no function in the per-function model, so it can never add a phantom entry to the `effort` counters, and only its gate, the cumulative budget and the watchdog apply to it — the per-function allowance is never consulted for it.

## Known Issues
- `beam_ssa_opt_equiv_SUITE`'s benchmark verdict is UNRELIABLE: its per-kernel min-of-5 in-process timing has a ±25-35% single-sample spread (the ON/OFF ratio for a fixed kernel flips sign across runs while the code is byte-identical), so a printed "maplookup ~18-20% slower" is measurement noise — the opt-in passes are performance-neutral on these kernels (the fusion pass only removes a redundant `has_map_fields` probe: `maplookup/2` shrinks 20→16 instructions and never adds work). The suite only hard-asserts a loose `ON =< OFF*2` bound.
