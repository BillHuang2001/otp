# Erlang/OTP System Documentation (`system/doc`)

## Intent
Authored Markdown source for the Erlang/OTP **User's Guides and system-level reference** — the Erlang language, OTP system/design principles, efficiency, interoperability, installation, getting-started, embedded systems, SBOM, VEX statements, and deprecation bookkeeping.
Built with **ex_doc** into `system/doc/html/`; the sibling `system/doc/top/` app additionally builds the top-level index at `$(ERL_TOP)/doc/index.html`.
This is a **docs-only tree**: there is no OTP application here, no `src/`, no `ebin/`, and nothing is compiled from this directory.

## API Surface (build inputs)
- `Makefile` — declares the pseudo-application (`APPLICATION=Erlang System Documentation`, `APP_DIR=../../lib/erl_interface`, `INDEX_DIR=../../../doc`, `RELSYS_HTMLDIR=$(RELEASE_PATH)/doc/system`), derives the guide list from `guides`, then includes `$(ERL_TOP)/make/doc.mk`.
- `docs.exs` — the ex_doc config *for this directory only*: `extras:` (the publication list), `main: "readme"`, `api_reference: false`, `skip_code_autolink_to`, and `groups_for_extras` computed at build time from `guides`.
- `guides` — extensionless text file, one `dirname:Human Readable Title` per line; the single source of truth for the sidebar group list of this tree (12 lines).
- `guides.license` — REUSE sidecar giving `guides` its Apache-2.0 header (the file is extensionless, so no in-file header is possible).
- `README.md` — guide landing page ("Erlang/OTP System Documentation"); also the ex_doc `main` page.

## Build Pipeline
Invoked by the top-level `Makefile.in` `docs`/`release_docs` targets in the order `lib` → `erts` → `system/doc` → `system/doc/top` (docs need the built EEP-48 `.beam` chunks, and `top` needs the generated `general_info` pages).
1. `make/docs.mk`-driven `docs` target → `check_ex_doc` (interactive ex_doc download prompt) → `html` → `$(HTMLDIR)/index.html`.
2. The `html` rule runs
   `ERL_FLAGS="-pz $(ERL_TOP)/erts/ebin" make/ex_doc_wrapper $(EX_DOC_FORMATS) --homepage-url ../../../doc/index.html "Erlang System Documentation" $(DOC_VSN) ../../lib/erl_interface/ebin -o html -c $(ERL_TOP)/make/ex_doc.exs`.
   ex_doc version is pinned in `make/ex_doc_vsn`; `make/get_ex_doc_formats_no_epub.sh` yields `-f html -f markdown` for ex_doc >= 0.40, else `-f html`.
3. `make/ex_doc.exs` is the **global** config: it evaluates this dir's `docs.exs`, derives the "app" id from the parent directory name (`system` here — note it is *not* set in `docs.exs`), special-cases `rootdir = ../../` for `:system`, and defines `assets: %{cwd/assets => "assets"}`, the logo, mermaid support (`before_closing_body_tag`), and the `system` / `erts` / `general_info` link prefixes.
   It also merges `Path.wildcard("*.md")` and `Path.wildcard("{guides,references,internal_docs}/*.md")` into `extras` — **guide subdirectories are *not* globbed**, which is why every guide page must be listed explicitly in `docs.exs`.
4. Pre-ex_doc generation steps in `Makefile`:
   - `assets.copy` flattens every guide's `assets/*.{gif,png,svg}` plus `$(ERL_TOP)/lib/runtime_tools/src/versions.erl` into `system/doc/assets/`.
   - `installation_guide/{INSTALL,INSTALL-CROSS,INSTALL-WIN32}.md` and `installation_guide/OTP-PATCH-APPLY.md` are `sed`-copied from `../../HOWTO/`, substituting `%EX_DOC_VSN%`, `%OTP-VSN%`, `%OTP-REL%`.
   - `general_info/{deprecations,scheduled_for_removal,removed}.md` are generated by `escript $(ERL_TOP)/lib/stdlib/scripts/update_deprecations make_markdown <type> $(ERL_TOP) $@`.
   All of these are extra prerequisites of `$(HTMLDIR)/index.html`.
5. Release install: `release_html_spec` copies `html/` to `$(RELEASE_PATH)/doc/system` and runs `make/fixup_doc_links.sh` to rewrite `system/doc/html` → `doc/system` and `../../../doc` → `..`.

## Constraints
- **Registration is mandatory**: every published page must be listed explicitly in `system/doc/docs.exs` `extras:`. An unlisted guide page is silently omitted from the build.
- **`guides` is overloaded** — it drives (a) the `groups_for_extras` regexes in `docs.exs`, (b) the `GUIDES` variable → `ASSETS_SRC` and `HTML_DEPS` in `Makefile`, and (c) the `SYSTEM` variable → per-guide stub pages and redirects in `top/`. Adding a new guide directory therefore requires a `guides` line *plus* `docs.exs` entries.
- Order of entries in `docs.exs` `extras:` is the sidebar order within a group; there is no in-file next/previous navigation.
- **Basenames must be unique across all of `system/doc`**: cross-app autolinks address pages as `e:system:<basename>.md` (e.g. `e:system:misc.md`, `e:system:release_handling.md`), so page identity in the `system` namespace is the basename.
- Every authored source file starts with an HTML-comment `%CopyrightBegin% … %CopyrightEnd%` Apache-2.0 header (checked by `scripts/license-header.es`). Files that cannot carry a comment header (extensionless files, binary assets) get a `<file>.license` REUSE sidecar.
- **Assets**: reference them in Markdown as the *flat* path `assets/<basename>`; the copy is flat, so a basename collision between guides silently overwrites. Only `.gif`/`.png`/`.svg` are copied — `.fig`/`.odg` are editable diagram sources and are never published or referenced.
- Anchors are **not validated**: `page.md#anchor` and `e:app:page.md#anchor` links are never checked, so renaming a heading silently breaks external (including other-app) links. `assets/<file>` references *are* validated and are fatal when `EX_DOC_WARNINGS_AS_ERRORS=true` (the default).
- `APP_DIR=../../lib/erl_interface` is a placeholder standing in for "no app" — because of it, no man pages are produced for this tree and the local `.erl` files in `efficiency_guide/` and `tutorial/` are never compiled by the docs build.

## Generated vs Authored
Generated (git-ignored or never committed — never hand-edit):
- `assets/*.png|*.gif|*.svg` and `assets/versions.erl` (from `assets.copy`), plus the `assets.copy` stamp.
- `installation_guide/{INSTALL,INSTALL-CROSS,INSTALL-WIN32,OTP-PATCH-APPLY}.md` (from `../../HOWTO/`).
- `general_info/{deprecations,scheduled_for_removal,removed}.md`.
- `html/` (this tree's output) and everything under `top/` that is generated (`man_index.md`, `README.md`, the stub directories, the top-level `doc/`).
Authored: everything else, including the `HOWTO/*.md` sources that feed `installation_guide/` (owned by the repository root).

## Known Issues
- The `guides` line `secure_coding:Secure Coding Guidelines` currently produces **no sidebar group**: the page lives at `design_principles/secure_coding.md`, which the earlier `design_principles` regex already matches (`groups_for_extras` is first-match-wins in ex_doc). There is no `secure_coding/` directory, so the entry contributes nothing but a nonexistent directory name to `GUIDES`/`SYSTEM`.
- `system/doc/assets/versions.erl` is a build-time copy of `lib/runtime_tools/src/versions.erl` but is **not** git-ignored (`assets/.gitignore` only covers `*.png|*.gif|*.svg`); it simply shows up untracked after `make docs`.
- `system/doc/README.md` links to `vex/vulnerabilities.md`, which does not exist — the guide is at `vulnerabilities/vulnerabilities.md`. Because README uses plain relative `.md` links instead of `e:system:` autolinks, this is never validated by the build and fails silently.
- `README.md` also lags the guide list: it omits `sbom`, `secure_coding`, and all `general_info` pages.
- Although this tree contains no compilable app, `make docs` here still requires a preceding full `lib`+`erts` build (the deprecation pages scan `lib/*/ebin`, and autolinks resolve against EEP-48 chunks).
- `general_info/` has **no entry in `guides`** and is not part of this ex_doc app: its four pages are `extras` of `system/doc/top/docs.exs`, rendered into the top-level `doc/general_info/` and addressed as `e:general_info:*`. They are only up to date because `make docs` builds `system/doc` before `system/doc/top`.

## Notes for Agents
- Files may be listed in `docs.exs` `extras:` with an `[source: <path>]` tag when the tracked source lives elsewhere (used for the `HOWTO/` copies); use that form rather than duplicating content.
- Adding a guide: create the directory, add a `dirname:Title` line to `guides`, add every page to `docs.exs` `extras:`, and re-check `top/` (its `SYSTEM` variable and stub generation pick the line up automatically).
- `CONTEXT.md` files in the guide subdirectories are *not* published (subdirectories are not globbed). A `CONTEXT.md` at this directory's top level **is** auto-published, because `make/ex_doc.exs` merges `Path.wildcard("*.md")` into `extras`.
- Mermaid blocks render client-side from a CDN (`before_closing_body_tag` in `make/ex_doc.exs`), so diagrams are invisible in non-JS/offline HTML.
- `make clean`/`clean_docs` here removes only `$(EXTRA_FILES)` (currently unset); generated `html/`, `assets/`, `installation_guide/*.md` and `general_info/*.md` are not cleaned.

## Test Strategy
- The doc build itself is the test: `EX_DOC_WARNINGS_AS_ERRORS` defaults to `true`, so undefined-autolink and missing-asset references fail the build.
- `scripts/otp_check_html_links.exs` (run from `scripts/otp_build_check`) validates links in the built HTML; note it only sees built output, so anchors and plain relative `.md` links inside Markdown remain unchecked.
- Two Markdown sources in this tree are exercised as *doctests* from OTP test suites: `reference_manual/ref_man_native_records.md` (via `lib/stdlib/test/records_SUITE.erl`, plumbed by `DOCTEST_NATIVE_RECORDS_MARKDOWN` in `lib/stdlib/test/Makefile`). Check `reference_manual/CONTEXT.md` for detail.
- Guide sources outside a running build cannot be rendered independently; verifying content changes requires a full `make docs` (or at least a built `lib` + `erts`).

## Routing Table
Guide content (each directory has its own CONTEXT.md):
- `reference_manual/` → Erlang language reference (syntax, types, processes, errors, distribution, ports, code loading; one page is doctested by `lib/stdlib/test`)
- `design_principles/` → how to build OTP applications: behaviours, supervision, releases, appup; contains `secure_coding.md`
  - `design_principles/assets/` → `.fig`/`.odg` diagram sources + exported `.gif`/`.svg`
- `system_principles/` → how to build and operate OTP systems: boot scripts, error logging, target systems, upgrading, version scheme
- `efficiency_guide/` → performance guidance; the only guide shipping runnable Erlang helper modules and a legacy benchmark framework
- `tutorial/` → interoperability tutorial (ports, port drivers, Erl_Interface, C nodes, NIFs) with companion `.c`/`.erl` listings
- `general_info/` → deprecation/removal data and fragments; generates the `deprecations`/`scheduled_for_removal`/`removed` pages (rendered by `top/`, not by this app)
- `top/` → separate ex_doc app that builds the top-level `doc/index.html` index, app/guide redirect stubs, and `man_index.md`

Content areas without a dedicated CONTEXT.md (small, single-purpose; document here if they grow):
- `getting_started/` → gentle Erlang introduction (`getting_started.md`, `seq_prog.md`, `conc_prog.md`, `robustness.md`, `records_macros.md`, `howto_debug.md`)
- `programming_examples/` → record/fun/comprehension/bit-syntax examples plus example `.erl` sources
- `installation_guide/` → landing page only; the `INSTALL*.md` / `OTP-PATCH-APPLY.md` pages are generated from `../../HOWTO/`
- `embedded/` → single page, `embedded.md`, on running Erlang on embedded systems
- `sbom/` → single page, `sbom.md`, software bill of materials
- `vulnerabilities/` → single page, `vulnerabilities.md`, VEX statements
- `assets/` → build-target directory: flattened copies of all guide assets plus the tracked ex_doc logo `erlang-logo.png` (only that file is committed)
