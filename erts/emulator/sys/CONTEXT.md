# erts/emulator/sys/ — OS integration layer of the BEAM emulator

## Intent
Everything in the emulator that directly depends on the host operating system: the I/O polling framework, memory mapping/mapped segments, OS environment (`osenv`), monotonic/system time, float↔string conversion, dynamic driver/NIF loading (`ddll`), signal stacks, the process entry point, and (on Unix) the `erl_child_setup` fork helper.
The directory exists so that OS differences are confined to a small number of clearly separated files instead of `#ifdef`s spread over the VM.
Structure: `common/` (portable, compiled for every OS), `unix/`, `win32/` — the latter two selected by `ERLANG_OSTYPE` set by `erts/configure.ac` (only these two values exist).
The per-OS part is also where the built-in `spawn`/`fd`/`forker` drivers live (`sys/unix/sys_drivers.c`, `sys/win32/sys.c`), not in `../drivers/`.
Siblings: `../beam/` (VM core, owns `sys.h` and the port/NIF-side consumers), `../drivers/`, `../nifs/`, `../internal_doc/`.

## API Surface
This directory implements two contracts: (a) types/macros the whole emulator depends on at compile time, and (b) functions the VM core calls.

### Headers that define the OS contract
- `common/erl_check_io.h` — the cross-platform check I/O API (`erts_check_io*`, `ErtsIoTask`, `ErtsDrvSelectDataState`, `ErtsNifSelectDataState`); includes `erl_sys_driver.h` + `erl_port_task.h` when compiled with `ERL_CHECK_IO_INTERNAL__`.
- `common/erl_poll.h` + `common/erl_poll_api.h` — the raw pollset API (`erts_poll_init|create_pollset|control|wait|interrupt|max_fds|info|get_selected_events`), the `ERTS_POLL_EV_*`/`ERTS_POLL_OP_*` event model and the `ErtsPollSet`/`ErtsPollResFd` types. Selects epoll / kqueue / /dev/poll at build time, with `poll()`/`select()` as fallback.
- `unix/driver_int.h` and `win32/driver_int.h` — define `SysIOVec`; installed into `$RELEASE_PATH/usr/include` as `driver_int.h` (part of `RELEASE_INCLUDES`), so their contents are an **external ABI** for statically linked drivers. The two versions differ (unix: `struct iovec` or a 2-field fallback; win32: a WSABUF-compatible `{unsigned long iov_len; char *iov_base;}`).
- `unix/erl_unix_sys.h` / `win32/erl_win_sys.h` — the per-OS half of `sys.h` (included by `../beam/sys.h` based on `__WIN32__`). Define `ERTS_SYS_FD_TYPE`/`ERTS_SYS_FD_INVALID`, `ERTS_SYS_CONTINOUS_FD_NUMBERS` (unix only), `MAXPATHLEN`, `ErtsMonotonicTime`/`ErtsSystemTime`/`ErtsSysHrTime`/`ErtsSysPerfCounter`, the `OS_*_TIME_USING_*` configure knobs, the FP/`isfinite` mapping, `ERTS_SYS_TRY_CATCH`, and the `SIGFUNC` signal API. These files are meant to be the only OS-conditional headers.
- `win32/erl_win_dyn_driver.h` — win32 only, installed; `TWinDynDriverCallbacks` function-pointer table plus `WDD_TYPEDEF`/`WDD_ASSIGN_...` macros, included from `../beam/erl_driver.h` when `STATIC_ERLANG_DRIVER` is not defined, so a Windows dynamic driver DLL can rebind the whole driver API to the emulator's copy.
- `common/erl_mmap.h` / `common/erl_mseg.h` — memory mapper and mapped-segment allocator interfaces (`erts_mmap*`, `erts_munmap`, `erts_mremap`, `erts_mem_guard`, `erts_mem_discard`, `erts_mseg_alloc*`/`dealloc*`/`realloc*`/`init`/`late_init`/`info*`, `ERTS_MMAPFLG_*`, super-alignment macros, `erts_dflt_mmapper`/`erts_literal_mmapper`).
- `common/erl_osenv.h` — instance-based replacement for `getenv`/`putenv` (`erts_osenv_t`), used for both the global environment and per-port environments.
- `common/erl_os_monotonic_time_extender.h`, `common/erl_util_queue.h` (the `erts_circleq_*` intrusive queue used by the check I/O and port code).
- `unix/sys_uds.h` (`sys_uds_read|write|readv|writev`, Unix-domain-socket fd passing), `unix/erl_child_setup.h` (`ErtsSysForkerProto` — the wire protocol between the VM's `forker` driver and `erl_child_setup`).

### Functions the VM core calls (declared in `../beam/sys.h`, implemented here)
- **Startup/shutdown**: `erts_sys_pre_init`, `erl_sys_init`, `erl_sys_late_init` (unix: `sys_drivers.c`, starts the forker), `erl_sys_args` (consumes emulator command-line switches), `erts_sys_scheduler_init`, `erts_sys_main_thread`, `erts_sys_prepare_crash_dump`, `sys_tty_reset`, `erts_sys_sigsegv_handler`/`ERTS_SYS_TRY_CATCH`.
- **Signals/break handling**: `sys_signal`, `sys_sigblock`, `sys_sigrelease`, `sys_init_suspend_handler`, `init_break_handler`, `erts_set_signal`, `erts_set_ignore_break`, `erts_replace_intr`, `erts_do_break_handling`, `sys_thr_suspend`/`sys_thr_resume` (unix); win32 keeps the break handling in `win32/sys_interrupt.c` behind a console ctrl-handler.
- **OS queries**: `sys_max_files`, `sys_init_io`, `sys_preloaded`/`sys_preload_begin`/`sys_preload_end`, `os_flavor`, `os_version`, `sys_get_pid`, `sys_get_hostname`, `erts_sys_is_area_readable`, `erts_sys_misc_mem_sz`. The page size is published as the globals `sys_page_size`/`sys_large_page_size`, initialized in `erts_sys_pre_init`.
- **Time**: `sys_init_time`, `erts_late_sys_init_time`, `erts_os_system_time`, `erts_os_monotonic_time`, `erts_os_times`, `erts_sys_hrtime`, `erts_sys_perf_counter`(+`_unit`), the exported `erts_sys_time_data__` read-only cache-line-aligned struct.
- **Float**: `erts_sys_init_float`, `sys_chars_to_double`, `sys_double_to_chars`, `sys_double_to_chars_ext`, `sys_double_to_chars_fast`, `sys_double_to_chars_short`.
- **Environment**: `erts_sys_env_init`, `erts_sys_explicit_8bit_getenv`/`putenv`, `erts_sys_explicit_host_getenv`, `erts_sys_rlock_global_osenv`/`runlock`/`rwlock`/`rwunlock`.
- **Dynamic loading (`ddll`)**: `erl_sys_ddll_init`, `erts_sys_ddll_open`/`_noext`/`close2`/`sym2`/`vsym2`/`load_driver_init`/`load_nif_init`/`call_init`/`call_nif_init`/`error`/`free_error` — `unix/erl_unix_sys_ddll.c` (`dlopen`), `win32/erl_win32_sys_ddll.c` (`LoadLibrary` + `TWinDynDriverCallbacks`).
- **Common misc**: `erts_init_sys_common_misc`, filename-encoding getters/setters (`erts_get_native_filename_encoding`, `erts_get/set_user_requested_filename_encoding`, `erts_get/set_printable_characters`).
- **I/O waiting**: `erts_init_check_io`, `erts_check_io`, `erts_check_io_interrupt`, `erts_create_pollset_thread`, `erts_check_io_max_files`, `erts_check_io_size`, `erts_check_io_info`, `erts_check_io_debug`, `erts_io_notify_port_task_executed`, `erts_io_handle_nif_select`, `erts_io_clear_nif_select_handles`, the tunables `erts_no_pollsets`/`erts_no_poll_threads`.
  `common/erl_check_io.c` also **implements the public driver API `driver_select()`** (declared in `../beam/erl_driver.h`) — it is the gateway between linked-in drivers/NIFs and the pollsets.
- **Built-in drivers implemented here** (not under `../drivers/`): unix `spawn`, `fd` and `forker` (`unix/sys_drivers.c`, `erl_drv_entry` definitions `spawn_driver_entry`/`fd_driver_entry`/`forker_driver_entry`); win32 `spawn` and `fd` (`win32/sys.c`). These three are hard-wired: `../beam/io.c` declares them `extern` and binds them to its `erts_driver_t spawn_driver`/`fd_driver`/`forker_driver` globals rather than relying on the generated `driver_tab[]`.
- win32-only extra: `sys_primitive_init(HMODULE beam)` (DLL init, exported through `erl.def`). `sys_get_key(int fd)` exists on both platforms and is exported on win32.

## Constraints
- `common/` must compile and work on both Unix and Windows; put OS differences in `unix/`/`win32/` unless there is genuinely no other option (the accepted exceptions are `erl_mmap.c`'s mmap-vs-`VirtualAlloc` pair, `erl_sys_common_misc.c`'s filename-encoding selection (`__WIN32__`/`__DARWIN__`/`__ANDROID__`), `erl_osenv.c`, and `erl_check_io.c`'s `MUST_DEFER` macro).
- Never let a `main()` symbol reach the emulator object list — `unix/erl_child_setup.c` defines `main()` and is only linked into the standalone helper binary.
- `driver_int.h` and `erl_win_dyn_driver.h` are installed public headers: changing them changes the ABI for third-party statically linked drivers and Windows dynamic drivers.
- Anything added to `common/` or `sys/$(ERLANG_OSTYPE)/` is picked up automatically by `ALL_SYS_SRC=$(wildcard sys/$(ERLANG_OSTYPE)/*.c) $(wildcard sys/common/*.c)` in `../Makefile.in`, but new non-trivial files usually also need to be added to that Makefile's `OS_OBJS` (or `CS_OBJ`) explicitly — the wildcard only drives dependency generation and the `compdb` target.
- One object name per source basename: `sys/common/X.c` and `sys/$(ERLANG_OSTYPE)/X.c` both map to `$(OBJDIR)/X.o`. The per-OS pattern rule is defined first in `Makefile.in`, so the per-OS file wins (this is how `sys/win32/erl_poll.c` shadows `sys/common/erl_poll.c` on Windows).
- `erts/emulator/Makefile.in` comment above `FLAVOR_MARKER`: when adding a new `TYPE` (build flavor) you must also update `ERL_BUILD_TYPE_MARKER` in `unix/sys_drivers.c`, or the VM will look for a wrongly named `erl_child_setup` binary.

## Design Decisions
- **`common/` + per-OS directory instead of pervasive `#ifdef`s.** `sys.h` (`../beam/sys.h`) is the single switch: it includes `erl_win_sys.h` or `erl_unix_sys.h`, both of which state in their header comment that they should be the only place with OS-conditional compilation.
- **Two-layer I/O waiting.** `erl_poll` is the raw, platform-specific event-wait mechanism (epoll/kqueue//dev/poll/poll/select on Unix; `WaitForMultipleObjects` + a grow-only thread pool on Windows). `erl_check_io` is the portable layer that owns pollsets, fd→state hashing, port-task/NIF dispatch and the driver visible `driver_select`. See `../internal_doc/CheckIO.md` for the authoritative description.
- **Two pollset update models, and one-shot event delivery.** `common/erl_poll.c` has a *concurrent-update* mode (epoll/kqueue) that modifies the kernel set in place with no wakeup and no pollset mutex, and a *non-concurrent* mode (poll/select//dev/poll) that buffers modifications in an update-request queue and has to wake the waiter. Delivery is one-shot in both: epoll uses `EPOLLONESHOT`/`EPOLL_CTL_MOD`, kqueue uses `EV_ONESHOT`/`EV_DISPATCH`, and the non-kernel path emulates it by zeroing `fds_status[fd].events`; the fd must be re-armed via `erts_poll_control(OP_MOD)`. `ps->oneshot` is 0 only for the scheduler pollset (`id == -1`), which is persistent-read. Only epoll/kqueue can be shared between poll threads (`ERTS_POLL_USE_CONCURRENT_UPDATE`) and only they support the fallback/scheduler-pollset optimisations (`ERTS_POLL_USE_FALLBACK`/`ERTS_POLL_USE_SCHEDULER_POLLING`).
- **The fd→state map is striped, not a single lock.** `erl_check_io.c` keeps `ErtsDrvEventState` per fd behind `ERTS_CHECK_IO_DRV_EV_STATE_LOCK_CNT` (128) hash-striped mutexes (`fd_hash`/`fd_mtx`). On Unix (`ERTS_SYS_CONTINOUS_FD_NUMBERS`) the state array is indexed by fd and grown on demand under a grow lock; on Windows (HANDLE keys) it is a `SafeHash` table (`DRV_EV_STATE_HTAB_SIZE` 1024, depth ≤ 16).
- **Kernel polling with a user-polling fallback.** When `ERTS_ENABLE_KERNEL_POLL` is on, the configure variable `ERTS_BUILD_FALLBACK_POLL` causes `common/erl_poll.c` to be compiled **twice**: once with `-DERTS_KERNEL_POLL_VERSION` (the kernel implementation) and once via a copied `$(TTF_DIR)/erl_poll.flbk.c` with `-DERTS_NO_KERNEL_POLL_VERSION` (the `poll()`/`select()` fallback). `erl_poll_api.h` is included twice with `ERTS_POLL_EXPORT(FUNC)` mapping to `FUNC` and to `FUNC_flbk`, so every poll function exists in both variants. The fallback pollset exists for FDs the kernel mechanism cannot monitor (e.g. a regular file or terminal stdin under epoll).
- **Scheduler pollset.** FDs that are never deselected can be moved to a pollset checked by the ordinary schedulers instead of the dedicated poll threads, avoiding the ONESHOT re-insert cost for very active FDs (guarded by `erts_port_task_outstanding_io_tasks`); enabled with `+IOs true`, only compiled when the poll implementation supports it (`ERTS_POLL_USE_SCHEDULER_POLLING`).
- **`erl_child_setup` is a separate executable, not VM code.** Forking from inside the VM would temporarily duplicate the VM's entire address space per parallel `open_port/2` (and `vfork` would block the VM on `execve`, e.g. on an unavailable NFS mount). Instead the VM starts `erl_child_setup` once at boot, sends it the fds over a Unix domain socket (`sys_uds.c`, `ErtsSysForkerProto`) and the commands over the pipe, and the helper does the `fork`+`execv` and forwards `SIGCHLD`/exit status back over the UDS. The VM side is the `forker` driver in `unix/sys_drivers.c`. Objects `erl_child_setup.o`, `sys_uds.o` and `../beam/hash.o` are shared with the VM (the same `.o` files are linked into both artifacts), but `erl_child_setup.c` itself is linked only into the helper.
- **Instance-based `osenv`.** `erts_osenv.c` provides a lockable, copyable environment object so the VM can keep a global environment plus per-port overrides, which `getenv(3)` cannot express. The legacy 8-bit `driver_getenv`/`driver_putenv` semantics are preserved via `erts_sys_explicit_8bit_*`, and `erts_sys_explicit_host_getenv` deliberately bypasses `osenv` and asks the host.
- **Shortest-float printing.** `sys_double_to_chars_short` is implemented in C++ (`common/erl_float_short.cpp`) using `std::to_chars` plus string post-processing to match Erlang's shortest-round-trip format (`12345.0`, no `+`, no exponent zero padding), unless `--enable-builtin-ryu` selects the vendored ryu-based implementation under `../ryu/`. `sys_double_to_chars_fast`/`_ext` live in `common/erl_sys_common_misc.c`; the OS-dependent `sys_chars_to_double`/`erts_sys_init_float` stay in `unix/sys_float.c`/`win32/sys_float.c`.
- **Alternate signal stacks on Unix.** With `BEAMASM` + `NATIVE_ERLANG_STACK` the JIT uses the C stack pointer for Erlang stacks, which may be too small for a signal handler; `unix/sys_signal_stack.c` installs a `sigaltstack` per scheduler thread (`sys_thread_init_signal_stack`) and patches `SA_ONSTACK` onto already-registered handlers (`sys_init_signal_stack`, called from `main` before any thread starts). It no longer overrides the libc's `sigaction`.
- **Monotonic time extension.** `erl_os_monotonic_time_extender.c` runs a background thread that counts the 32-bit wraparound of a raw OS clock so a 32-bit monotonic counter can be extended to 64 bits (`ERTS_EXTEND_OS_MONOTONIC_TIME`), with two alternating halves to stay race-free.
- **`erts_mseg`/`erts_mmap` split.** `erl_mmap.c` owns the OS view (mmap/`VirtualAlloc`, super-aligned carriers, memory reservation, `madvise`-based `erts_mem_discard`); `erl_mseg.c` builds the mapped-segment cache allocator on top of it, falling back to plain `malloc` when no genuine mmap exists (`HAVE_ERTS_MSEG`/`HAVE_ERTS_MMAP`).
- **Windows builds the emulator as a DLL.** `win32/erl.def` exports exactly `erl_start`, `sys_get_key` and `sys_primitive_init`; the process entry point is `../../etc/win32/win_erlexec.c`, which loads `beam.dll` and calls those three symbols. `win32/erl_main.c`'s `main()` is legacy (it is still compiled into the DLL through `INIT_OBJS`).

## Known Issues / Gotchas
- `win32/erl.def` must stay in sync with what `../../etc/win32/win_erlexec.c` resolves via `GetProcAddress` — a missing export breaks every Windows start-up with a bare "Unable to load emulator DLL"-style failure.
- `sys/unix/driver_int.h` and `sys/win32/driver_int.h` are **different** headers with the same installed name; consulting the wrong one gives a wrong `SysIOVec` layout. The win32 one also force-defines `__WIN32__`.
- On win32 both `sys/win32/erl_poll.c` and `sys/common/erl_poll.c` appear in `SYS_SRC` (the Makefile no longer filters the common one out), yet only one produces `$(OBJDIR)/erl_poll.o`. The per-OS rule is listed first, so the win32 file wins — do not "fix" this by deleting the comment or reordering the rules.
- `common/erl_check_io.c` and the pollsets depend on `../beam/erl_port_task.c`, thread progress and `ErtsAllocType` allocation types; it is compiled in a special mode (see `ERL_CHECK_IO_INTERNAL__` / `ERTS_ALLOC_C__` guards in `erl_check_io.h`) that changes what the header pulls in.
- `ERTS_SYS_CONTINOUS_FD_NUMBERS` (unix, fds are small consecutive ints) makes the check I/O layer index an array by fd and grow it on demand; on Windows a "fd" is a `HANDLE`, so `/dev/poll`-style fd-indexed code paths do not apply (`NO_FSTAT_ON_SYS_FD_TYPE`).
- `erl_mmap.c`, `erl_mseg.c` and `erl_mmap.h` are empty-ish no-ops on configurations without `HAVE_ERTS_MMAP`/`HAVE_ERTS_MSEG`; a "missing" function there is usually a compile-time switch, not a bug.
- `../beam/sys.h` declares `erts_sys_get_page_size()`/`erts_sys_get_large_page_size()` but nothing in the tree defines them; the page size is actually read from the `sys_page_size`/`sys_large_page_size` globals. Treat those two declarations as stale.
- `unix/sys.c`'s `erts_sys_pre_init` opens `/dev/null` up to fd 3 and keeps one spare fd for crash-dump creation — subtle but load-bearing for the old shell/fd-driver code paths.
- The `TYPE` marker (`opt`/`debug`/`valgrind`/...) is duplicated in the Makefile (`TYPEMARKER`) and in `unix/sys_drivers.c` (`ERL_BUILD_TYPE_MARKER`); the two must agree or the VM cannot find `erl_child_setup<TYPEMARKER>`.

## Notes for Agents
- Read `../internal_doc/CheckIO.md` before changing anything in `common/erl_check_io.c` or `common/erl_poll.c`; it is the authoritative design document for this subsystem. Also `../internal_doc/PortSignals.md`, `SuperCarrier.md` and `CarrierMigration.md` for the `mseg`/`mmap`/carrier side.
- Almost every file here includes `"sys.h"`, which lives in `../beam/sys.h` (found via `-Ibeam`) — this directory does not own it. `COMMON_INCLUDES` in `../Makefile.in` adds `-Ibeam -Isys/$(ERLANG_OSTYPE) -Isys/common -I$(TARGET)`.
- These files need a configured tree (`erts/$(TARGET)/config.h`) to compile; the `config.h` feature macros (`HAVE_*`, `ERTS_ENABLE_KERNEL_POLL`, `ERTS_BUILD_FALLBACK_POLL`, `HAVE_ERTS_MMAP`, `ERTS_MACH_CLOCKS`, ...) select most implementations.
- `unix/erl_child_setup.c` includes `../beam/erl_term.h` and `../beam/hash.h`, so it is coupled to VM headers despite being a "small helper".
- `common/erl_poll.c` compiles to **two** objects when `ERTS_BUILD_FALLBACK_POLL=yes`; when editing it, remember the `_flbk` copy and that `ERTS_POLL_EXPORT` renames everything.
- The check I/O tunables are emulator command-line flags parsed in `parse_args` (`common/erl_check_io.c`): `+IOt` (poll threads), `+IOp` (pollsets), `+IOPt`/`+IOPp` (same, as percentages of the scheduler count), `+IOs` (scheduler pollset), and `+K` (kernel poll, argument parsed and discarded here).
- win32 `sys.c` (3.3 kloc) is much bigger than its unix sibling because it also carries the spawn/fd drivers, async-I/O (`OVERLAPPED`) machinery and console handling; the equivalent unix logic is in `sys_drivers.c` + `sys.c` + custom helpers.
- **Async-I/O inventory of this layer:** no `io_uring`/`liburing`, no IOCP (`CreateIoCompletionPort`/`GetQueuedCompletionStatus`), no `eventfd`, no `signalfd` anywhere under `sys/`. Whatever exists is level-triggered readiness polling: `epoll` (+ Linux `timerfd` for sub-ms timeouts, `ERTS_POLL_USE_TIMERFD`), `kevent`, `/dev/poll`, `poll`/`ppoll`/`select`, and Windows `WaitForMultipleObjects` over per-fd auto-reset events. The OS-native async model that *does* exist is (a) the spawn/fd drivers' `OVERLAPPED` reads/writes in `win32/sys.c` (thread-simulated in parts) and (b) the esock IOCP socket backend — both feed results back through the normal pollset/`driver_select`/`enif_select` path (esock on Windows instead posts `enif_send` completion messages); neither bypasses check I/O at the C level except esock-win32.

## Dependencies
- POSIX: `poll()`/`select()`, optionally `epoll` (Linux, incl. `timerfd` when available), `kqueue` (macOS/BSD), `/dev/poll` (Solaris); `mmap`/`mremap`/`madvise`; `dlopen`/`dlsym` for `ddll`; `sigaltstack`/`sigaction`; Unix domain sockets with `SCM_RIGHTS` for `sys_uds`; `clock_gettime` (MONOTONIC/MONOTONIC_RAW/REALTIME), `mach_absolute_time`/`gethrtime`/`times()` depending on `OS_*_TIME_USING_*`.
- Windows: `WaitForMultipleObjects` (64-handle limit drives the poll thread pool), `VirtualAlloc`/`VirtualFree`, `LoadLibrary`/`GetProcAddress`, console ctrl handlers; the esock/socket check-I/O path uses completion ports but lives elsewhere (`../nifs/`).
- Linux-specific tuning: Transparent Huge Pages handling in `unix/sys.c`, `sysconf(_SC_MINSIGSTKSZ)` for the signal stack size.
- C++ compiler for `common/erl_float_short.cpp`; `--enable-builtin-ryu` switches to `../ryu/` (`ERTS_USE_BUILTIN_RYU`) and removes that object.
- `sys/unix/erl_child_setup.c` is linked against `../lib/internal/$(TARGET)/liberts_internal` (`erl_printf`, alloc, thread helpers) — see `CS_LIBS` in `../Makefile.in`.

## Test Strategy
- No test suites live in this directory; the code is exercised through `../test/` (owned by another node):
  - Poll/select behaviour and `driver_select`: `../test/driver_SUITE.erl`, `../test/async_ports_SUITE.erl`, `../test/z_SUITE.erl`, `../test/scheduler_SUITE.erl`, `../test/nif_SUITE.erl` (they reference `+IOt`/`+IOp`/`check_io`), plus `../test/iovec_SUITE.erl` for `SysIOVec`.
  - Distribution/networking over the check I/O layer: `../test/distribution_SUITE.erl`, `../test/port_SUITE.erl`, `../test/port_bif_SUITE.erl`, `../test/trace_port_SUITE.erl`.
  - `erl_child_setup` (port spawning, exit status, tty restore): `../test/port_SUITE.erl`, `../test/port_bif_SUITE.erl`; `run_erl`/`to_erl`/`erlexec` launcher suites are at the `erts` level (`../../test/`).
  - Dynamic driver/NIF loading (`ddll`): `../test/driver_SUITE.erl`, `../test/nif_SUITE.erl`.
- Run with `make emulator_test ARGS="..."` (or `make test ARGS="..."` from `../`); `TEST_NEEDS_RELEASE` is NOT set at the `erts/emulator` level (only `erts/Makefile` sets it), so no full release is required. Use `TYPE=debug`, `TYPE=valgrind` (suppressions in `../valgrind/`) or `TYPE=asan` (suppressions in `../asan/`) to actually exercise the C paths.
- Coverage gaps: OS-specific branches (kqueue, `/dev/poll`, Windows poll thread pool, `VirtualAlloc` mapper) are only exercised on the respective platform; the fallback pollset and scheduler pollset are only actively used on Linux/macOS builds where kernel polling is enabled.

## Routing Table
- `common/` → portable core: check I/O + `driver_select` (`erl_check_io.c/.h`), the pollset implementations (`erl_poll.c`, `erl_poll.h`, `erl_poll_api.h`), memory mapper and mapped segments (`erl_mmap.*`, `erl_mseg.*`), OS environment (`erl_osenv.*`), monotonic-time extender, shortest-float printing, misc portable sys helpers and the `erts_circleq_*` queue header
- `unix/` → POSIX implementation: entry point (`erl_main.c`), main OS abstraction and signal/break handling (`sys.c`, `erl_unix_sys.h`), built-in `spawn`/`fd`/`forker` drivers (`sys_drivers.c`), environment (`sys_env.c`), time (`sys_time.c`), float (`sys_float.c`), signal stacks (`sys_signal_stack.c`), UDS fd passing (`sys_uds.c/.h`), the `erl_child_setup` fork helper (`erl_child_setup.c/.h`), `dlopen`-based `ddll`, and the installed `driver_int.h`
- `win32/` → Windows implementation: `WaitForMultipleObjects`-based pollset (`erl_poll.c`), OS abstraction + spawn/fd drivers + async I/O (`sys.c`), time (`sys_time.c`), environment (`sys_env.c`), float (`sys_float.c`), break handling (`sys_interrupt.c`), errno mapping (`dosmap.c`), `LoadLibrary`-based `ddll`, DLL export list (`erl.def`), the installed `erl_win_dyn_driver.h`, and the Windows `driver_int.h`
- `../beam/` → VM core; owns `sys.h` (the header that pulls in `unix/erl_unix_sys.h` or `win32/erl_win_sys.h`), the port-task/thread-progress machinery the check I/O layer builds on, and the `driver_select` declaration (sibling — read-only, escalate writes to `..`)
- `../drivers/` → linked-in drivers (`inet_drv`, `ram_file_drv`, cross-OS `common/`+`unix/`+`win32/` split) that call into `driver_select` here (sibling — read-only)
- `../nifs/` → NIFs, including the Windows completion-port socket implementation (sibling — read-only)
- `../test/` → the Common Test suites that exercise poll/select, ports, `erl_child_setup` and `ddll` (sibling — read-only)
- `../internal_doc/` → design documents (`CheckIO.md`, `PortSignals.md`, `SuperCarrier.md`) (sibling — read-only)
- `../../test/` → `erts`-level install/launcher/upgrade suites (`erlexec_SUITE`, `run_erl_SUITE`, `install_SUITE`) that cover the launcher side of this layer
- `../../etc/unix/` → launcher programs (`run_erl`, `to_erl`, `heart`) that interact with `erl_child_setup` and the terminal handling in `unix/sys.c`
