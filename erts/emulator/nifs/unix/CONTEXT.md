# erts/emulator/nifs/unix/ — Unix backends for the emulator's static NIFs

## Intent
POSIX implementations behind the cross-platform NIF modules in `../common/`: the `essio_*` *synchronous* socket backend used by the `prim_socket`/`prim_net` NIFs, and the `efile_*` file backend used by `prim_file`.
Both are compiled directly into their NIF module (`OS_OBJS` in `../Makefile.in`), never into a separate shared object, and are wired in at `on_load` from `../common/prim_socket_nif.c` / `../common/prim_file_nif.c`.
Layout is the emulator-wide convention: `unix/` holds only the OS-specific code; all argument validation, option conversion and term encoding live in `common/`.

## Constraints
- Everything in this directory is Unix-only; it is compiled only when `ERLANG_OSTYPE != win32` and (for the socket file) under `#ifdef ESOCK_ENABLE` — with esock disabled the socket file compiles to an empty object and `../common/prim_socket_nif.c` installs a `notsup` stub.
- These files are *backends*, not NIF modules: no `ERL_NIF_INIT`, no `ErlNifFunc` table, no resource type of their own (the socket file uses the `ESockDescriptor` resource opened in `common`; the file backend uses the `efile` resource opened in `../common/prim_file_nif.c`).
- The public NIF API used is `../beam/erl_nif.h` (`enif_*`). `unix_prim_file.c` additionally uses `erts_atomic32_*` and `sys.h`; `unix_socket_syncio.c` uses `sys.h`, the `ESock*` types from `../common/socket_int.h` and the `sock_*` syscall macros (200–255).

## Design Decisions (verified against the code — do NOT assume thread pools)
- **The Unix socket backend is synchronous *and single-threaded from the NIF's point of view*: there is NO I/O thread pool, no `pthread`/`ErlNifMutex`/`ErlNifCond`, and no `enif_thread_create` anywhere in `unix_socket_syncio.c`** (`grep -nE "pthread|_thread|mutex|cond_|TID"` finds only comments). The `TCREATE`/`TJOIN` thread macros in `../common/socket_int.h` (910–915) are used *only* by the Windows `win_socket_asyncio.c` IOCP backend, and `git log -S TCREATE/enif_thread_create -- unix_socket_syncio.c` shows they were never present here.
- **`essio_init` ignores its `numThreads` argument** (`unix_socket_syncio.c:1105-1116`, `VOID(numThreads)`), and `essio_finish` (1329-1332) is a no-op with the comment "For 'standard' (unix) synchronous I/O, in our case this is just a dummy function".
- The thread-count value *is* computed one level up in `on_load()` of `../common/prim_socket_nif.c` (**18714**): `ioNumThreadsDef = (sysInfo.scheduler_threads > 0) ? 2*sysInfo.scheduler_threads : 2;` at **18938-18940** (after `enif_system_info(&sysInfo, sizeof(ErlNifSysInfo))` at 18928), overridable via the `io_num_threads` key of the load-info map (18942-18944, doc comment at 18930-18933 mentions a wanted `--esock-num-io-threads` option), then passed via `ESOCK_IO_INIT(ioNumThreads)` (19090) to `io_backend.init`. On Unix that value is dropped on the floor by `essio_init`; it is consumed only by the Windows `esaio_init` (which allocates `ctrl.threads = MALLOC(numThreads * sizeof(ESAIOThread))`).
- **Blocking is avoided by non-blocking sockets + `enif_select`, not by offloading to threads.** The sockets are non-blocking (`#define WANT_NONBLOCKING` at 60-62). The blocking syscalls are macros over the plain POSIX calls in the calling NIF thread: `sock_recv`→`recv` (238), `sock_send`→`send` (246), `sock_accept`→`accept` (200/203), `sock_connect`→`connect` (213), `sock_recvmsg`/`sock_sendmsg`/`sock_recvmmsg`/`sock_sendmmsg` (241-249), `sock_shutdown` (255). On `EAGAIN`/`EWOULDBLOCK`/`EINPROGRESS`/`EINTR` the operation returns a `select`/`select_read`/`select_write` term *and* the backend registers the fd with the VM's pollset itself (see below), so the calling scheduler never blocks.
- **Completion is signalled through the VM pollset (`enif_select*`) and Erlang messages** — the classic `{'$socket', Socket, select, selectRef}` protocol. The backend calls the wrappers in `../common/prim_socket_nif.c`: `esock_select_read` (17636 → `enif_select_read` 17645), `esock_select_write` (17660 → `enif_select_write` 17669), `esock_select_stop` (17684 → `enif_select(..., ERL_NIF_SELECT_STOP, ...)` 17688), `esock_select_cancel` (17693 → `enif_select(..., ERL_NIF_SELECT_CANCEL|mode, ...)` 17698). Call sites in the backend: connect `EINPROGRESS` (2138-2156), accept retry (2775), send flush/select (7159), sendfile select (9412), recv select (10285), close stop (4611). Async notifications use `enif_send` via `esock_send_close_msg` (17314) and `esock_send_abort_msg` (17368) (`enif_send` at 17433).
- **Which thread runs the syscall:** the `prim_socket` NIFs `nif_send`/`nif_recv`/`nif_accept`/`nif_connect`... are registered with flag `0` (normal scheduler) in the `esock_funcs[]` table (`../common/prim_socket_nif.c:18625-18677`), so the non-blocking syscall runs inline on whatever scheduler called the NIF. Only `nif_sendfile`, `nif_ioctl`, `nif_finalize_close` are `ERL_NIF_DIRTY_JOB_IO_BOUND`, and `nif_sendmmsg`/`nif_recvmmsg` reschedule to a dirty I/O scheduler when the batch exceeds `ESOCK_MMSG_DIRTY_THRESHOLD` (64). `essio_fin_close` (4772) deliberately runs on a dirty scheduler so the final `close(2)` may block on `linger` (comment 4826-4831, `SET_BLOCKING` at 4832).
- **Concurrency inside the descriptor is a "two-level locking architecture"** (documented at `unix_socket_syncio.c:6785-6806`): per-descriptor `writeMtx`/`readMtx` (ErlNifMutex, acquired by the *NIF entry points* in `../common/prim_socket_nif.c`, e.g. 18378-18379, created at 16922/16948) serialise C-level descriptor state, while the Erlang-process-level ordering is done with request queues (`currentWriterP`/`currentReaderP`/`currentAcceptorP` + `writersQ`/`readersQ`/`acceptorsQ`). Non-current callers are pushed onto the queue via `esock_writer_push`/`esock_reader_push`/`esock_acceptor_push` and get the `select` atom (`send_check_writer` 6809, `recv_check_entry` 9869, `essio_accept_accepting_other` 2746); `esock_activate_next_{reader,writer,acceptor}` (generated in `../common/prim_socket_nif.c:17718-17799`) pops the queue and re-selects.
- **Cancellation / close race safety** uses `ErlNifMonitor`s on every waiting process: connector (2147), current reader/writer/acceptor (`MONP`/`DEMONP`), closer (4565) and owner/controller (`ctrlMon`). `essio_down` (9658) dispatches an owner/closer/connector/reader/acceptor/writer exit and `essio_down_*` (10532-10710) clean up or abort the affected operation. `essio_close` (4544) sets `ESOCK_STATE_CLOSING` and calls `do_stop` (4601): `esock_select_stop` may either complete synchronously (`ERL_NIF_SELECT_STOP_CALLED`) or schedule `essio_stop` (9574); `essio_stop` then either sends a close message to a waiting closer (→ `nif_finalize_close` → `essio_fin_close`) or does an unclean non-blocking close itself. `essio_fin_close` (4772) demonitors closer+owner, `SET_BLOCKING`s the socket and does the real blocking `esock_close_socket`. `essio_dtor` (9510) asserts a selected socket was properly closed and otherwise closes it non-blocking.

## Known Issues / Gotchas
- The claim in `../CONTEXT.md` that the Unix backend uses "a pool of `2*schedulers` I/O threads doing synchronous socket calls" is **stale/incorrect for `unix_socket_syncio.c`**: the `2*sysInfo.scheduler_threads` number is only *computed* generically in `on_load` (see above) and is consumed solely by the win32 `esaio_init`; the Unix backend runs the calls inline and never creates threads.
- `essio_init`'s `numThreads` parameter exists only to match the shared `ESockIOInit` signature (`../common/socket_io.h:38`); do not "restore" a thread pool based on it.
- There is no `essio_io_data`/worker/queue struct — the only shared state is the file-static `ctrl` (SCTP + debug flags) and per-descriptor state in `ESockDescriptor`.
- `essio_command` mutates `ctrl.sockDbg`/`ctrl.dbg` without locking (self-noted at 1419/1427).
- SCTP blocks are compiled only when the platform has `netinet/sctp.h`; Solaris needs the `_XPG4_2`/`__EXTENSIONS__` workaround at 42-47. SCTP functions come from `LIBSCTP` at runtime (`HAVE_STATIC_SCTP` chooses direct calls vs `esock_dlopen`/`dlsym`, 1206-1304).
- `unix_prim_file.c` is **fully synchronous too** (no threads, no `enif_select`): it just wraps the POSIX syscalls and loops on `EINTR`. Its callers in `../common/prim_file_nif.c` are all `ERL_NIF_DIRTY_JOB_IO_BOUND`, so the blocking is absorbed by dirty schedulers — `efile_close` even asserts `enif_thread_type() == ERL_NIF_THR_DIRTY_IO_SCHEDULER` (250). Its race safety is the atomic `efile_data_t.state` machine (`IDLE/BUSY/CLOSE_PENDING/CLOSED`, `../common/prim_file_nif.h:73-121`) plus an `ErlNifMonitor` owner-death callback (`owner_death_callback`, `../common/prim_file_nif.c:377`).
- `unix_prim_file.c` uses platform fallbacks that matter on macOS/no-`preadv`: `FALLBACK_RW_LENGTH` (2³¹−1) for >2 GB read/write (48, 324-325, 374-375) and lseek-based emulation of pread/pwrite (399-409, 436-443, 458-465, 492-499).

## Notes for Agents
- To understand the socket data flow read, in order: `../common/prim_socket_nif.c:on_load` (18714, backend wiring 18949-19083) → the `esock_funcs[]` NIF table (18625) → `ESOCK_<OP>` macros (2972-3207) → the `essio_*` backend here.
- `SSDBG`/`SGDBG` per-descriptor debug macros gate the extensive `"UNIX-ESSIO"` tracing; enable via the socket `debug` option / `essio_command`.
- Do not look in these files for the select/queue logic: the queue helpers (`esock_*_push`, `esock_activate_next_*`, `esock_send_*_msg`, `esock_requestor_*`) and the `enif_select*` wrappers live in `../common/`.
