# erts/emulator/beam/ — BEAM emulator core (VM implementation)

## Intent
The flat, single-directory core of the BEAM virtual machine: ~107 `.c` files and ~97 `.h` files that implement data types, BIFs, GC, scheduling, allocators, ETS, distribution, code loading, tracing, NIF/driver support, timers and ports.
Everything here is compiled and linked into the emulator executable (`$ERL_TOP/bin/$(TARGET)/beam.smp`) and into the archive `libbeam.a`.
Flavor/architecture-specific code lives in the child dirs `jit/` and `emu/` (see Routing Table); this directory holds the flavor-independent parts plus the codegen *inputs* shared by both.

## API Surface
### Public C headers (installed to `$RELEASE_PATH/usr/include` and `erts-$(VSN)/include`)
- `erl_driver.h` — driver developer API (threads, locks, memory, binary, async, port I/O).
- `erl_nif.h`, `erl_nif_api_funcs.h` — NIF API (version history in the header maps API version → OTP release).
- `erl_drv_nif.h` — types/decls shared between `erl_driver.h` and `erl_nif.h`.
- `driver_int.h` is per-OS and lives in `../sys/<ostype>/`, not here.
- `erl_internal_test.h` — internal only, installed to `erts-$(VSN)/include/internal`.
These four headers (plus per-OS `driver_int.h`) are the ONLY stable ABI exposed from this directory; everything else is private to the emulator.

### Generated-code INPUTS kept here (hand-maintained, not generated)
- `atom.names`, `bif.tab`, `erl_dirty_bif.tab` → generated into `$(TTF_DIR)` by `../utils/make_tables`: `erl_bif_table.c|h`, `erl_bif_list.h`, `erl_atom_table.c|h`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c` (further consumed by `../utils/beam_makeops`).
- `erl_alloc.types` → `$(TTF_DIR)/erl_alloc_types.h` via `../utils/make_alloc_types` (defines `ErtsAlcType_t` values and type→strategy mapping).
- `predicates.tab`, `generators.tab` → concatenated with the flavor tables (`../beam/jit/$(JIT_ARCH)/{predicates,generators}.tab` for `FLAVOR=jit`, `../beam/emu/{predicates,generators}.tab` for `FLAVOR=emu`) and fed to `../utils/beam_makeops`, producing `$(TTF_DIR)/beam_opcodes.c|h`, `beam_hot.h`, `beam_warm.h`, `beam_cold.h` (the instruction table + dispatch code shared by interpreter and JIT).
- `erlang_dtrace.d` → `$(TARGET)/erlang_dtrace.h` when DTrace is enabled.
`$(TTF_DIR)` = `erts/emulator/$(TARGET)/$(TYPE)/$(FLAVOR)`.

### Sources rewritten by the yielding-C compiler (YCF)
`erl_map.c` → `$(TTF_DIR)/erl_map.ycf.h`, `utils.c` → `utils.ycf.h`, `erl_db.c` → `erl_db_insert_list.ycf.h`.
Each `.c` `#include`s its own generated `.ycf.h` near the bottom; the generator binary is `../lib_src/yielding_c_fun`.

### What it contributes to the build
`../Makefile.in` globs `BEAM_SRC=$(wildcard beam/*.c)` (dependency/compdb scanning) and lists the objects explicitly in `COMMON_OBJS` (loader/JIT-shared: `beam_common`, `beam_bif_load`, `beam_bp`, `beam_catches`, `beam_debug`, `beam_load`, `beam_opcodes`, `beam_ranges`, `beam_transform_helpers`, `code_ix`), `RUN_OBJS` (everything else here), `LTTNG_OBJS` (`erlang_lttng.c`), plus `OS_OBJS`/`NIF_OBJS`/`DRV_OBJS` from other dirs.
Outputs: `$ERL_TOP/bin/$(TARGET)/beam.<flavor>` and the archive `EMULATOR_LIB` (`libbeam.a`, `libbeam.lib` on Windows) installed to `erts-$(VSN)/lib`.
There are currently **no `.cpp` files directly in `beam/`** (the `BEAM_CPP_SRC` glob is for `jit/`).

## Constraints
- **Never edit the generated outputs**; edit the inputs listed above and regenerate. Generated files are `erl_bif_table.c|h`, `erl_bif_list.h`, `erl_atom_table.c|h`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c`, `erl_alloc_types.h`, `beam_opcodes.c|h`, `beam_hot.h`, `beam_warm.h`, `beam_cold.h`, `erl_map.ycf.h`, `utils.ycf.h`, `erl_db_insert_list.ycf.h`, `erlang_dtrace.h` — none of these exist in this directory.
- **`#include "global.h"` is the convention** for essentially every translation unit here (it pulls in `sys.h`, allocators, term/process/port headers); the remaining files are deliberately low-level (`hash.c`, `safe_hash.c`, `packet_parser.c`, `erl_md5.c`, `erl_printf_term.c`, `erl_iolist.c`, `beam_file.c`, `beam_transform_helpers.c`, `erl_thr_queue.c`, `erl_lock_*.c`, `erl_zlib.c`, `erl_flxctr.c`, `erlang_lttng.c`, `erl_errno_str.c`, `erl_internal_test.c`, `erl_bif_atomics.c`, `erl_bif_counters.c`, `erl_bif_unique.c`, `erl_crash_dump.c`, `erl_sched_spec_pre_alloc.c`, `erl_dyn_lock_check.c`).
- No internal library boundary: this is one flat compilation set. Do not introduce public headers here beyond the four installed ones; treat all other headers as emulator-private.
- Code must compile in every `TYPE` flavor (`opt`, `debug`, `lcnt`, `valgrind`, `asan`, `gprof`, `frmptr`, `icount`, `gcov`) and under both `FLAVOR=jit` and `FLAVOR=emu`. Keep flavor/arch-specific code out of this directory (put it in `jit/` or `emu/`).
- Concurrency is lock-free in hot paths: changes touching deferred work must respect thread progress (`erl_thr_progress`) — see `../internal_doc/ThreadProgress.md`.

## Design Decisions
- **Tagged `Eterm` representation** (`erl_term.h`): 2-bit primary tags (`HEADER`/`LIST`/`BOXED`/`IMMED1`); `IMMED1` splits into pid/port/immed2/small-int, `IMMED2` into atom/catch/nil; boxed headers carry a 4-bit sub-tag (arityval, fun, big, float, ref, bin_ref, external pid/port/ref, heap_bits, map, record, sub_bits). Boxed data reference-counted where shared (`Binary`, node containers, funs). `ET_DEBUG` (on by default in `DEBUG` builds) swaps the type-access macros for runtime-checked variants.
- **Internal vs external node containers** (`erl_node_container_utils.h`): internal pids/ports are immediates, internal refs are boxed; external ones are heap-allocated with a pointer to a ref-counted node-table element (`erl_node_tables.c`), GC'd by ref count like refc binaries.
- **PTab** (`erl_ptab.h/.c`) unifies pids and ports in one id-allocating table with links/monitors — see `../internal_doc/PTables.md`.
- **Allocator "type" model**: all internal allocation goes through `erts_alloc(ErtsAlcType_t, ...)`; types are declared in `erl_alloc.types` and mapped to one of the carrier-based strategies. `erl_alloc_util.c` implements the shared carrier machinery (single-block carriers, multi-block carriers, super carriers, carrier migration, delayed deallocation) — see `../internal_doc/{CarrierMigration,SuperCarrier,DelayedDealloc}.md`.
- **Cooperative yielding in C**: long-running BIFs are written to trap; `erts/lib_src/yielding_c_fun` rewrites marked functions in `erl_map.c`, `utils.c`, `erl_db.c` into resumable state machines (`*.ycf.h`), which is how `maps:*`, `lists:sort/*`, and the ETS insert loops avoid blocking a scheduler. Truly blocking work goes to dirty schedulers (`erl_dirty_bif.tab`).
- **Multi-generation code loading** (`code_ix.c`, `erl_code_staged.h`): three logical copies of code (active/staging/previous) selected by an index so running processes need no locks; `erl_code_staged.h` is an X-macro template included multiple times with different `ERTS_CODE_STAGED_*` macros to synthesize the staged tables for exports/funs/records. See `../internal_doc/CodeLoading.md`.
- **Public headers are the ABI**: driver/NIF code only ever sees `erl_driver.h`/`erl_nif.h`; the emulator's internal structs are hidden behind `*_TYPES_ONLY__`/`*_TYPE_ONLY` include guards used all over these headers to let low-level files pull in just the type definitions.

## GC Root Set & Erlang Stack Scanning (quick reference)
- `setup_rootset()` (`erl_gc.c:2615`) builds the roots as vectors `Roots {Eterm* v; Uint sz}` (`erl_gc.c:107`, default 32-slot `Rootset` `:114`).
- Root vector 0 is the ENTIRE Erlang stack: `roots[0].v = p->stop; roots[0].sz = STACK_START(p) - p->stop` (`erl_gc.c:2630-2631`; `STACK_TOP(p)==p->stop`, `STACK_START(p)==p->hend`, `erl_process.h:1018-1019`). The stack is scanned word-by-word, not frame-by-frame: a word is followed only if `primary_tag()` is BOXED/LIST and the target lies in the young gen / mature area (`do_minor` `erl_gc.c:1677-1717`; `full_sweep_heaps` `erl_gc.c:1995-2033`). Non-term words (JIT return addresses, trace frames) are skipped by the tag test.
- The GC never needs frame boundaries, CP→metadata lookup or per-frame liveness: every value live across a call is in a y slot on the stack (or the caller's frame), so the linear scan finds it.
- Other root vectors (`erl_gc.c:2634-2705`): process dictionary, explicit `objv`/`nobj` (x registers), `seq_trace_token`, `dt_utag`, `group_leader`, `parent`, `fvalue`, `ftrace`, receive-marker block, and saved native-function (trapped NIF/BIF) arguments via `erts_setup_nfunc_rootset()` (`erl_nfunc_sched.h:103`).
- `copy_erlang_stack()` (`erl_gc.c:1581`) only copies the stack to the top of the new heap and relocates pointers: plain `sys_memcpy` for `ERTS_FRAME_LAYOUT_RA` (`:1602-1603`), word-by-word with CP fixup + `FRAME_POINTER(p)` update for `ERTS_FRAME_LAYOUT_FP_RA` (`:1605-1633`).
- Frame layouts (`erl_vm.h:64-80`): default (no `ERLANG_FRAME_POINTERS`) is `ERTS_FRAME_LAYOUT_RA` = return-address-only frames, `CP_SIZE == 1`; `ERTS_FRAME_LAYOUT_FP_RA` = {frame pointer, return address}, `CP_SIZE == 2`, only with `+JPperf true` (see `../internal_doc/BeamAsm.md:161-176`). A "CP" is an untagged word-aligned raw code pointer: `make_cp(x) == (Eterm)(x)`, `is_CP(x) == ((x) & _CPMASK) == 0`, `_CPMASK == 0x3` (`erl_term.h:177,1373-1383`).
- CP → code metadata is NOT done by the GC. `gather_stacktrace()` (`beam_common.c:784`) walks `p->stop`..`STACK_START(p)` testing `is_CP()`, decodes each frame with `erts_inspect_frame()` (`beam_common.h:300-318`) and resolves return addresses via `erts_lookup_function_info()` (`beam_ranges.c:245`) → `FunctionInfo{mfa, loc, fname_ptr}`; consumed by `erts_build_stacktrace()` (`erl_bif_info.c:2409`), `process_info(backtrace)`, crash dumps and `erl_debugger.c`.
- **`live` x registers are not stored in any per-frame metadata.** `BeamCodeLineTab` is only `fname_ptr + loc_size + loc_tab + func_tab` (`beam_code.h:143-151`) and the `.beam` "Line" chunk carries only {name, line} (`beam_file.c:506-536`). `Live` is a per-instruction compile-time operand emitted into the instruction word (`u`/`t` = "number of live registers", `../internal_doc/beam_makeops.md:677-682, 785-787`): emu `$GC_TEST(Ns,Nh,Live)` → `erts_garbage_collect_nobump(c_p, need, reg, $Live, FCALLS)` (`emu/macros.tab:85-97`); JIT `emit_gc_test()` → `mov_imm(ARG4, Live.get())` + `ga->get_garbage_collect()` (`jit/x86/instr_common.cpp:153-175`, `jit/x86/beam_asm_global.cpp:102-134`). DEBUG builds fill dead x registers beyond `Live` with `ERTS_HOLE_MARKER` to catch bad counts (`jit/x86/instr_common.cpp:160-165`).
- `erts_garbage_collect(p, need, objv, nobj)` (`erl_gc.c:983`) / `erts_garbage_collect_nobump(p, need, objv, nobj, fcalls)` (`:966`): `objv` = pointer to x register 0, `nobj` = number of live x registers; they become one root vector (`erl_gc.c:2639-2643`).
- `ErtsSchedulerRegisters` (`erl_process.h:626-685`) holds `aux_regs`, `x_reg_array` (`Eterm[ERTS_X_REGS_ALLOCATED]`, `:659`; `ERTS_X_REGS_ALLOCATED = MAX_REG+3 = 1027`, `erl_vm.h:49,58`) and `f_reg_array`; `ErtsSchedulerData::registers` points at it (`erl_process.h:688`). It is NOT part of the process stack/heap block: with `BEAMASM` a normal scheduler allocates it on its own runtime (C) stack in `process_main` (`jit/x86/process_main.cpp:64-78`); only non-BEAMASM/dirty schedulers heap-allocate it (`erl_process.c:5971-5991`). The emu's `reg` is `esdp->registers->x_reg_array.d` (`emu/beam_emu.c:398`); the JIT keeps `rbx` centred on `x_reg_array` (`jit/x86/beam_asm.hpp:109-111`).
- When a process is scheduled out the live x registers are copied to `Process::arg_reg` (count `Process::arity`, `erl_process.h:1073-1079`) by `copy_out_registers()` and back by `copy_in_registers()` (`beam_common.c:306,336`). With `NATIVE_ERLANG_STACK` (x86 JIT) the Erlang stack pointer is `rsp` (`jit/x86/beam_asm.hpp:113-116`) and the Erlang stack is the top of the process heap block: `emit_leave_runtime<Update::eStack>` loads it from `Process::stop`, `emit_enter_runtime` stores it back (`jit/x86/beam_asm.hpp:751-752,832-833`); C code runs on the separate runtime stack (`../internal_doc/BeamAsm.md:178-199`).
- **No generational write barrier, card marking or remembered set.** A minor GC (`do_minor`, `erl_gc.c:1638`) traces only the rootset and the young to-space; correctness rests on the immutability-implied "no old-heap→young-heap pointer" invariant (`../internal_doc/GarbageCollection.md:108`). The only per-process remembered list is `Process::wrt_bins` (writable refc binaries; swept in `sweep_off_heap`, `erl_gc.c:2047-2049`), which tracks binary lifetimes, not heap generations.

## Cheney Copy Core — Forwarding Markers & Per-Subtag Sizes (quick reference)
The copier is a classic Cheney two-pointer scan. `move_boxed`/`move_cons`/`follow_moved` live in `erl_gc.h:39-122` (not `erl_gc.c`); the scan loops that drive them are `do_minor` (`erl_gc.c:1638`), `full_sweep_heaps` (`:1963`) and the shared `sweep()` (`:2280`, dispatched by `sweep_new_heap`/`sweep_heaps`/`sweep_literal_area`).
- **Forwarding markers are in-place.** Boxed marker = the object's header word is overwritten with the tagged new pointer: `IS_MOVED_BOXED(x) == !is_header(x)` (`erl_gc.h:36`). Cons marker = `ptr[0]` set to `THE_NON_VALUE` and `ptr[1]` to the new pointer: `IS_MOVED_CONS(x) == is_non_value(x)` (`erl_gc.h:37`); `THE_NON_VALUE` is `0` normally, `_make_header(0,_TAG_HEADER_FLOAT)` under `ET_DEBUG` (`erl_term.h:374-378`).
- `move_cons(ptr,car,hpp,orig)` (`erl_gc.h:42-55`): `htop[0]=ptr[0]; htop[1]=ptr[1]; *orig=make_list(htop); ptr[0]=THE_NON_VALUE; ptr[1]=gval; *hpp+=2`.
- `move_boxed(ptr,hdr,hpp,orig)` (`erl_gc.h:61-94`): `nelts=header_arity(hdr)` **plus** `flatmap_get_size(ptr)+1` (flatmap) or `hashmap_bitcount(MAP_HEADER_VAL(hdr))` (HAMT) **plus** `fun_num_free(ptr)` (fun); then `*orig=make_boxed(htop); *htop++=hdr; *ptr++=gval;` copies `nelts` more words. `orig`/`hpp` are the caller's slot/top pointers, so the marker is written into the from-space word and the caller's reference is fixed simultaneously.
- **`follow_moved(term, xptr_tag)`** (`erl_gc.h:104-122`) resolves a marker: BOXED → `term = (*ptr) | xptr_tag`; LIST → `term = ptr[1] | xptr_tag`. **`xptr_tag` is the literal bit `TAG_LITERAL_PTR` (0x4)** (or 0): when a term was stored as a literal pointer, its forwarded target on the new heap lacks that bit, so the bit must be re-OR'd to keep it flagged as a literal (only caller: `copy.c:2109`, `erts_move_multi_frags`, with `literal_tag = literals ? TAG_LITERAL_PTR : 0`, `copy.c:2057-2062`). The GC's own loops call `move_boxed`/`move_cons` directly and pass `xptr_tag == 0` via `follow_moved(t, 0)` (`erl_gc.c:2646,2661,2669`).
- **Per-subtag traversal size** (words copied by `move_boxed`, header included): ARITYVAL/RECORD `arity+1`; FLOAT `2` (64-bit, `FLOAT_SIZE_OBJECT = DOUBLE_DATA_WORDS+1`, `erl_term.h:526`); POS/NEG_BIG `digits+1`; REF internal ordinary/magic `ERTS_REF_THING_SIZE+1 = 3` on 64-bit (3 words total, `erl_term.h:990`); FUN `ERL_FUN_SIZE + fun_num_free` (= 2 + env); MAP flatmap `flatmap_get_size+3`, HAMT head `2+bitcount(MAP_HEADER_VAL)`, HAMT node `1+bitcount`; BIN_REF `3`; HEAP_BITS `heap_bits_size(bits)` (`=1+(size word)+data words`, `erl_bits.h:160-164`); SUB_BITS `ERL_SUB_BITS_SIZE = 5`; EXTERNAL_PID/PORT/REF `EXTERNAL_THING_HEAD_SIZE + data words` (`=4` for pid/port on 64-bit; `erl_term.h:1161-1188`).
- **Leaf vs. recursed (the scan loop, not `move_boxed`, decides).** `move_boxed` copies raw words with no recursion. The `sweep()` loop re-examines the to-space word-by-word and moves any word pointing into from-space: transparent headers (ARITYVAL, RECORD) are consumed with a single `n_hp++` so their elements are scanned individually (`header_is_transparent`, `erl_term.h:170-172`); a FUN header advances `thing_arityval+1 == 2` (header+entry) so `env[]` is scanned as terms; a MAP header advances `MAP_HEADER_ARITY+1` (header+size) so keys/values/items are scanned; every other thing advances `thing_arityval+1`, skipping its scalar interior (FLOAT, BIG digits, REF numbers, BIN_REF val/next, HEAP_BITS bytes, EXTERNAL data). SUB_BITS is special-cased (`erl_gc.c:2332-2346`): it resolves `sb->orig` (BinRef or on-heap `ErlHeapBits`) and calls `erl_sub_bits_update_moved` before being skipped.
- **`size_object_x` (`copy.c:88-263`)** is the standalone size calculator mirroring `move_boxed`'s arithmetic (used by message/ETS copy, not the GC); `copy_struct_x` (`copy.c:647`) is the iterative to-heap copier. Neither is used by `erl_gc.c`.

## Two-Generation Model & Tenuring (quick reference)
- `p->high_water` (`HIGH_WATER(p)`, `erl_process.h:1021`) splits the young heap `[HEAP_START, HEAP_END)`: `[heap, high_water)` is **mature** (survived the previous minor GC) and `[high_water, htop)` is fresh **young**. A minor GC sets `HIGH_WATER(p) = n_htop` (`erl_gc.c:1810`), i.e. all copied nodes become mature.
- `minor_collection` (`erl_gc.c:1397`) computes `mature = p->abandoned_heap ? p->abandoned_heap : p->heap` and `mature_size = high_water - mature` (`:1402,1427`) and allocates the old heap on first need (`erts_next_heap_size(size_before,1)`, `:1463-1479`). `do_minor(p, live_hf_end, mature, mature_size, new_sz, objv, nobj)` moves **mature objects to the old heap** (`move_boxed(...,&old_htop,...)`, `:1694`), **young objects to the new young heap** (`&n_htop`, `:1696`), and leaves **old-heap objects untouched** (they fail both area tests). `ErtsInYoungGen(t,ptr,oh,ohsz) := !erts_is_literal(t,ptr) & !ErtsInArea(ptr,oh,ohsz)` (`erl_gc.h:97-99`).
- A **major/`fullsweep`** (`major_collection`, `erl_gc.c:1854` → `full_sweep_heaps`, `:1962`) allocates one new heap sized `stack + young_usage + old_heap_usage + S_RESERVED`, copies **all** non-literal live data (young + mature + old) into it via the same scan, derefs the MSO list with `fullsweep=1`, and frees the old heap (`:2051-2056`); it then clears `GEN_GCS(p)=0` and `F_NEED_FULLSWEEP`.
- **When a major runs**: `garbage_collect` chooses minor iff `GEN_GCS(p) < MAX_GEN_GCS(p) && !(FLAGS(p)&F_NEED_FULLSWEEP)` (`erl_gc.c:831`), else major. `minor_collection` returns `-1` (forcing major + setting `F_NEED_FULLSWEEP`) when there is no old heap, the old heap lacks room (`mature_size > OLD_HEND-OLD_HTOP`), or the binary old-vheap is exhausted (`:1486-1576`). `F_NEED_FULLSWEEP` is also set by `erlang:garbage_collect(major)`, `process_info`-requested major GC, hibernate, and GC signals (`erl_gc.c:1164`, `bif.c:4085`, `erl_bif_info.c:5301`, `erl_process.c:10842,11198`).
- **Heap-size policy** (`erts_init_gc`, `erl_gc.c:240-303`; `erts_next_heap_size`, `:310-338`): a static `heap_sizes[]` table — stage 1 `12, 38` then Fibonacci+1 (`heap_sizes[i]=heap_sizes[i-1]+heap_sizes[i-2]+1`, `:265-271`), stage 2 +20% growth (`:283-290`), capped at `2^53/sizeof(Eterm)` words (`MAX_HEAP_SIZES` 154 on 64-bit). `erts_next_heap_size(size, offset)` binary-searches `offset==0` for the smallest size `>= size`, `offset==1` for the next strictly larger; `next_heap_size` clamps to `p->min_heap_size`. Defaults: `H_DEFAULT_SIZE 233`, `H_MAX_SIZE 0` (off), `S_RESERVED = CP_SIZE + S_REDZONE` (`erl_vm.h:60-62,101-111`). Growth/shrink between GCs: `adjust_after_fullsweep` grow if `HEAP_SIZE < need_after`, set `F_HEAP_GROW` if `3*HEAP_SIZE < 4*need_after`, shrink if `4*need_after < HEAP_SIZE && HEAP_SIZE > H_MIN_SIZE` (`erl_gc.c:2061-2098`). There is **no `HEAP_NEED` macro**; the reserve is `S_RESERVED`/`HEAP_LIMIT(p) = MAX(htop, stop - S_REDZONE)` (`erl_process.h:997`).

## Term Encoding (Eterm) Reference
Authoritative source: `erl_term.h`. Word = `Eterm`/`Uint`; `ERTS_SIZEOF_TERM` 8 (`ARCH_64`) / 4 (`ARCH_32`) (`sys.h:403-461`). All bit positions below are within one word.
- **Primary tag** bits 0-1 (`_TAG_PRIMARY_MASK 0x3`, `erl_term.h:70-77`): HEADER 0x0, LIST 0x1, BOXED 0x2, IMMED1 0x3.
- **Pointer tag bits**: `_TAG_PTR_MASK__` 0x7 (64-bit) / 0x3 (32-bit); optional `TAG_LITERAL_PTR 0x4` flags literals in the literal area (`erl_term.h:55-67`). `boxed_val`/`list_val` mask these off (`erl_term.h:211-238`).
- **IMMED1** bits 0-3 (`_TAG_IMMED1_MASK 0xF`): PID 0x3, PORT 0x7, IMMED2 0xB, SMALL 0xF. **IMMED2** bits 0-5 (`_TAG_IMMED2_MASK 0x3F`): ATOM 0xB, CATCH 0x1B, NIL 0x3B (`erl_term.h:79-90`).
- **Small int**: `value<<4 | 0xF`; `SMALL_BITS` 60/28; `MAX_SMALL` 2^59-1 on 64-bit (`erl_term.h:262-290`). **Atom**: `index<<6 | 0xB`; `MAX_ATOM_INDEX` = 2^(wordbits-6)-1. **CATCH**: `val<<6 | 0x1B`; **NIL** literal 0x3B (`erl_term.h:293-305`).
- **Boxed header word**: ptag 0 (bits 0-1), 4-bit subtag bits 2-5 (`_HEADER_SUBTAG_MASK 0x3C`), arity/words bits 6+ (`_HEADER_ARITY_OFFS 6`) (`erl_term.h:151-153`). Subtags (`erl_term.h:127-168`): 0x00 ARITYVAL (tuple), 0x08 POS_BIG, 0x0C NEG_BIG, 0x10 REF, 0x14 FUN, 0x18 FLOAT, 0x1C RECORD, 0x20 HEAP_BITS, 0x24 SUB_BITS, 0x28 BIN_REF, 0x2C MAP, 0x30 EXTERNAL_PID, 0x34 EXTERNAL_PORT, 0x38 EXTERNAL_REF. `make_arityval(sz)=sz<<6`, `arityval(x)=x>>6`, `MAX_ARITYVAL` 2^24-1.
- **Fun header** overloads arity bits (`FUN_SUBTAG | arity<<8 | num_free<<16 | external<<24`, `erl_term.h:396-422`); **Map header** overloads as `val:16|arity:8|mtype:2|ptag` (`erl_map.h:151-195`).
- **Lists**: `TAG_PRIMARY_LIST` tags the 2-word heap cell directly (no header word); cell = `[CAR, CDR]` (`erl_term.h:218-244`).
- **Internal pid/port/ref**: pid/port are IMMED1 (pid data `serial<<28 | number`; port number = low `_PORT_DATA_SIZE` bits) (`erl_term.h:617-710`). Internal ref is boxed, 3 words on 64-bit: header + three 32-bit numbers sharing words with a 32-bit `0xffffffff` marker; magic refs are the same size, distinguished by marker != 0xffffffff (`erl_term.h:711-1095`).
- **External pid/port/ref**: boxed `ExternalThing` = `[header, node*, off-heap next*, data...]`; `node*` points at a ref-counted node-table element (`erl_term.h:1097-1288`, `erl_node_container_utils.h`).
- **ET_DEBUG** (auto-on under `DEBUG`, `erl_term.h:38-53`) swaps accessors for runtime-checked `checked_*` variants (`erl_term.c:165-220`) and makes `THE_NON_VALUE` = `_make_header(0,_TAG_HEADER_FLOAT)` instead of `0`. No extra debug size/magic word is added to headers.
- All constants above are emulator-private but exported read-only to the debugger via `erl_etp.c`; only `erl_driver.h`/`erl_nif.h`/`erl_nif_api_funcs.h`/`erl_drv_nif.h` (+ per-OS `driver_int.h`) are stable ABI.

## List (cons) Representation — Access Sites & Hybrid Precedent (quick reference)
- **Cons cell** = a *headerless* 2-word heap slot: `CAR(x)=x[0]`, `CDR(x)=x[1]`, `CONS(hp,car,cdr)`, `make_list(p)=p+TAG_PRIMARY_LIST`, `list_val(p)=p-TAG_PRIMARY_LIST` (masking `_TAG_PRIMARY_MASK`/`TAG_LITERAL_PTR`) (`erl_term.h:219-244`); `NIL` is the distinct immediate `_TAG_IMMED2_NIL` (`erl_term.h:90,293`), `TAG_PRIMARY_LIST=0x1` (`:73`). A list term is a single tagged `Eterm` word (must stay so for NIF/ETF/msg ABI).
- **Deconstruct/construct sites** (all raw CAR/CDR, no abstraction layer): interpreter handlers `get_list`/`put_list`/`update_list`/`is_list`/`is_nil`/`is_nonempty_list*` (`emu/instrs.tab`, `emu/ops.tab` — see `emu/CONTEXT.md`); JIT emit methods + `getCARRef`/`getCDRRef`/`emit_test_cons` (`jit/{x86,arm}/instr_common.cpp`, `jit/{x86,arm}/beam_asm.hpp` — see `jit/CONTEXT.md`); **NIF ABI** `enif_get_list_cell`/`enif_make_list_cell`/`enif_make_list`/`enif_is_list`/`enif_get_list_length`/`enif_make_reverse_list` (`erl_nif.c:1283-1290,1971-1991,2183-2285` — raw CAR/CDR + CONS); BIFs `erts_list_length` (`utils.c:345`), `ebif_plusplus_2`→`append` (`erl_bif_lists.c:345`, `:111-250`), `lists_member_2` (`:1108`), `lists_reverse_2` (`:1246`), `erl_bif_binary.c`, `erl_iolist.c`.
- **GC / copy / equality**: `copy.c` `size_object_x` sums 2 words/cons (`:103-114`), `copy_struct`/`copy_list` (`:692-742`), `size_shared` (`:319`); `eq()` LIST case walks CAR/CDR (`utils.c:1137-1163`); GC stack scan is primary-tag-based (`erl_gc.c` `do_minor`/`full_sweep_heaps`, `setup_rootset`).
- **Observable / wire**: ETF encodes lists as `LIST_EXT` cons chains terminated by `NIL_EXT` (`external.c:4581,6263` + encoder `:3335,3709`); `erts_debug:same/2` is raw-word `==` (`beam_debug.c:64-68`), `erts_debug:flat_size/1`→`size_object` / `size`→`size_shared` (`beam_debug.c:70-98`). These (plus `process_info(_,memory)`) expose the physical cons word count.
- **Hybrid precedent — small map**: `flatmap_t` = sorted keys *tuple* + parallel values array (`erl_map.h:57-91`); switch to HAMT at `MAP_SMALL_MAP_LIMIT` (32 release / 3 DEBUG, `erl_map.h:93-97`). Growing path `erts_maps_put` (`erl_map.c:2105-2175`) and `erts_maps_update` (`:2036`) reshape flatmap→HAMT; HAMT→flatmap collapse when size ≤ limit (`:555`); HAMT leaf nodes hold each k/v pair as a `CONS` cell (`:527,736`). Both shapes live behind `is_flatmap`/`is_hashmap` (`erl_term.h:1305-1314`).
- **Hybrid precedent — binaries**: on-heap `ErlHeapBits` when ≤ `ERL_ONHEAP_BINARY_LIMIT` (64 B) else off-heap ref-counted `BinRef`; sub-bitstrings/match contexts share `ErlSubBits` (`erl_bits.h:130-172`).

## Allocator Subsystem (quick reference)
Allocation goes through `erts_alloc(ErtsAlcType_t, ...)` (`erl_alloc.h`).
- **Type model**: `erl_alloc.types` (hand-maintained) declares `allocator` (SYSTEM, TEMPORARY, SHORT_LIVED, STANDARD, LONG_LIVED, EHEAP, ETS, FIXED_SIZE, LITERAL, BINARY, DRIVER, TEST), `class` (6: PROCESSES/ATOM/CODE/ETS/BINARIES/SYSTEM) and ~200 `type`s. `../utils/make_alloc_types` turns it into `$(TTF_DIR)/erl_alloc_types.h` defining `ErtsAlcType_t` values `ERTS_ALC_T_<TYPE>` plus `ERTS_ALC_T2A(type)` (→allocator number) / `ERTS_ALC_T2N(type)`. Dispatch is `erts_allctrs[ERTS_ALC_T2A(type)].{alloc,realloc,free}` (`erl_alloc.h:253-288`, `erl_alloc.c:102`).
- **Allocator → strategy defaults** (`erl_alloc.c`): sl GOODFIT, std BESTFIT, ll BESTFIT+ao, literal BESTFIT+ao, temp AFIT, eheap GOODFIT, binary BESTFIT, ets BESTFIT, driver BESTFIT, fix BESTFIT+ao, test FIRSTFIT (`:226-469`). Default ACUL 60 / eheap 45 / ll 85 (`erl_alloc.c:76-86`).
- **Carriers**: `Carrier_t` (`erl_alloc_util.h:505`: chdr+next+prev+atomic allctr+cpool) and `Block_t` (`:373`: one `bhdr` word packing size + THIS_FREE/PREV_FREE/LAST + carrier offset). SBC = 1 block (`sbc_threshold` default 512 KB, `erl_alloc_util.h:123`); MBC = many blocks, size grows over `mbc_growth_stages` (default 10) from `smbcs` (1 MB) to `lmbcs` (10 MB) (`:128-133`, `get_next_mbc_size` `erl_alloc_util.c:1187`). `Allctr_t` is the per-instance struct (`:640`).
- **Free-block search**: goodfit = 256 size buckets + `max_blk_search` depth (default 3, `erl_goodfit_alloc.c:344`); bestfit/aobf = `RBTree_t` (`erl_bestfit_alloc.c:815`/`:657`); aoff family = two-level rbt (carriers, each with an rbt of free blocks sorted by address/size/age, `erl_ao_firstfit_alloc.c:862`/`:894`); afit = size-ordered linked `free_list` (`erl_afit_alloc.c:122`).
- **Per-process heaps use the EHEAP allocator**: `p->heap` is `ERTS_HEAP_ALLOC(ERTS_ALC_T_HEAP, ...)` (`erl_process.c:12593`), old heap `ERTS_ALC_T_OLD_HEAP` (`erl_gc.c:1226`); overflow goes to `ErlHeapFragment` (`ERTS_ALC_T_HEAP_FRAG`, `erl_message.h:198/490`, `erts_heap_alloc` `utils.c:134`). `ERTS_HEAP_ALLOC` is just `erts_alloc` (`erl_process.h:88`).
- **Memory-efficiency features**: carrier migration + lock-free carrier pool (`cpool_fetch` `erl_alloc_util.c:3558`); delayed dealloc lock-free queue (`erl_alloc_util.h:592`, `handle_delayed_dealloc` `erl_alloc_util.c:2073`); super carrier in `../sys/common/erl_mmap.c` (docs `../internal_doc/{CarrierMigration,SuperCarrier,DelayedDealloc}.md`). Cache-line concerns: `ErtsAllctrDDQueue_t` aligned to `ERTS_ALC_CACHE_LINE_ALIGN_SIZE` (`erl_alloc_util.h:596-600`), cpool array cache-line aligned (`erl_alloc_util.c:3209`); `ERTS_CACHE_LINE_SIZE` = configure `--with-assumed-cache-line-size` default 64 (`erl_alloc.h:240`).

## Message Passing & Process-Memory Model (quick reference)
Every process owns a heap; a send copies the payload term graph into the receiver's heap/queue. Core files: `erl_message.c` (message struct, fragment, queue), `copy.c` (the copy engine), `erl_proc_sig_queue.c` (signal queues + receive-side handling), `bif.c` (`do_send`).
- **Local send path**: `erlang:send/2,3` and `!` (`ebif_bang_2` `bif.c:2359`) → `erl_send` → `do_send` (`bif.c:2458`). For an internal pid it reaches the `send_message:` label (`bif.c:2676`) and calls `erts_send_message(p, rp, &rp_locks, msg)` (`bif.c:2681`).
- **`erts_send_message`** (`erl_message.c:698`) sizes with `size_object_litopt` (`:771`/`:839`), reserves destination space via `erts_try_alloc_message_on_heap` (`:621`) then `copy_struct_litopt` (`:797`/`:860`) → `copy_struct_x` (`copy.c:647`) deep-copies the WHOLE graph. A local (same-node) send of a non-immediate term therefore still copies the entire term graph; only immediates (`IS_CONST`/`TAG_PRIMARY_IMMED1`, `copy.c:677,707`) and literal-tagged subtrees are not copied.
- **A local `reference()` is BOXED, not immediate** (`ERTS_REF_THING_SIZE` = 3 words on 64-bit, `erl_term.h:873-877,990`), so the common gen-server envelopes (`{'$gen_call',{Pid,Ref},Req}` and `{Ref,Reply}`) are never immediate-only — the request-id `Ref` is deep-copied on every call and every reply. A small non-immediate message is thus copied in TWO full passes: `size_object_litopt` (`erl_message.c:839`) sizes it, then `copy_struct_litopt` → `copy_struct_x` (`copy.c:647`) copies it. There is no word-threshold size fast path.
- **The on-/off-heap message-queue choice is STATIC, not size-based**: the default `SPO_ON_HEAP_MSGQ` (`erl_process.c:132`) is only changed at spawn, via `+hmqd`, or by `process_flag(message_queue_data, on_heap|off_heap)` — no size/length heuristic exists. An on-heap queue is added to the GC rootset on every GC (`erl_gc.c:2709-2777`) whereas an off-heap queue is excluded from it; the thread-progress synchronised switch is `erts_change_message_queue_management` (`erl_message.c:1021`).
- **Self-send fast path**: if `receiver == sender` and the queue is on-heap, nothing is copied (`msize=0`, `erl_message.c:824-833`).
- **Where the copy lands**: with the default on-heap message queue the term is copied directly onto the receiver's heap (`HEAP_TOP(pp)`, `erl_message.c:653-659`); otherwise into a `new_message_buffer()` `ErlHeapFragment` (`erl_message.c:69`, `:681`).
- **Enqueue**: `erts_queue_proc_message` (`erl_message.c:532`) → `queue_messages` (`:371`) → `LINK_MESSAGE` (`erl_message.h:475`) onto `sig_qs.first`. Outer buffered queues (`ErtsSignalInQueueBufferArray`, `erl_message.h:407-446`) cut sender lock contention when off-heap msgq is active.
- **Signal model (OTP 21+)**: messages are just one signal kind; exits/monitors/links share the same queues. `ErtsSignalPrivQueues` (`erl_message.h:337`) = inner "message queue" + middle/outer in-transit queues. Tag classifiers: `ERTS_SIG_IS_INTERNAL_MSG` (heap term), `ERTS_SIG_IS_EXTERNAL_MSG` (`THE_NON_VALUE`, still-ETF-encoded), `ERTS_SIG_IS_NON_MSG` (`erl_message.h:263-282`). Handled in `erts_proc_sig_handle_incoming` (`erl_process.c:10952`, main loop `:10345`).
- **Receive**: the term is NOT copied at receive. Off-heap msgq adopts the fragment: `save_heap_frag_eterm` (`erl_proc_sig_queue.c:3923`) → `erts_link_mbuf_to_proc` (`erl_message.c:563`); on-heap msgq already lives on the receiver heap. Live received terms are moved to the new heap only at the next GC.
- **Off-heap message queue** knob: `+hmqd` / `process_flag(message_queue_data, on_heap|off_heap)` (`erl_init.c:1577`; default `SPO_ON_HEAP_MSGQ` `erl_process.c:132`). RN `ERTS_PSFLG_OFF_HEAP_MSGQ` (`erl_process.h:1322`), switch machinery `erts_change_message_queue_management` (`erl_message.c:1021`). Off-heap keeps messages out of the process heap so GC need not scan the queue. There is **no `+MBas`**; the message/fragment allocator is the `HEAP_FRAG`→`EHEAP` type (`erl_alloc.types:127`). `+sbwt`/`+A` are scheduler/async-thread knobs unrelated to copy cost.
- **Remote send** (`remote_send` `bif.c:2381` → `erts_dsig_send_msg` `dist.c:1592`): the term is ETF-encoded (copied) via `erts_encode_ext*` (`external.c:356,763,798`) and decoded on the receiver into a heap fragment (`erts_decode_dist_ext` `external.c:1273`) → `erts_queue_dist_message` (`erl_message.c:273`). No sharing across nodes.
- **What crosses process boundaries without copying**: immediates; refc/off-heap large binaries — only the `ErlSubBits`+`BinRef` descriptors are copied and `Binary.intern.refc` bumped (`copy.c:812-848`, `erl_binary.h:63`); on-heap binaries ≤ `ERL_ONHEAP_BINARY_LIMIT` 64 B are copied (`erl_bits.h:167`); writable binaries stay shared until observed (`BIN_FLAG_WRITABLE` `erl_binary.h:47`, `erts_pin_writable_binary` `erl_bits.c:2051`); module literals/constants are preserved, not copied (`copy.c:720,744,767`); `persistent_term` lives in a global literal area (`erl_bif_persistent.c:754,761`); external pid/port/ref share the ref-counted node-table element (`copy.c:890`); magic refs share the `Binary` by refc (`copy.c:934-938`). Funs ARE copied including their env (`copy.c:866-880`) but the code they point into is module code.
- **Copy is charged as reductions** proportional to size: `ERTS_MSG_COPY_WORDS_PER_REDUCTION` (`erl_message.h:35`, DEBUG 4 / 64) applied at `erl_message.c:881`.

## ETS Storage & Copy Semantics (quick reference)
- **Off-heap, table-owned memory.** A stored object is a `DbTerm` (`erl_db_util.h:68`): `{first_oh (off-heap list head), size (words), tpl[] (word array, top tuple first)}`. Allocated with `erts_db_alloc(ERTS_ALC_T_DB_TERM, tab, n)` → `erts_alloc` (type `DB_TERM`, allocator `ETS`=BESTFIT; `erl_alloc.types:195`), never from a process heap. Nested refc binaries/refs/funs are held in the `first_oh` off-heap list, not byte-copied. Table structs ref-counted (`DbTableCommon.refc`, `erl_db_util.h:317`); a global clist holds all tables (`ErtsEtsTables`, `erl_db.h:49`).
- **Table layouts:** hash (`DbTableHash`, bucket chains of `HashDbTerm{next,hvalue,pseudo_deleted,DbTerm}`, `erl_db_hash.h:41,70`) for set/bag/duplicate_bag; AVL `DbTableTree{root}` of `TreeDbTerm{left,right,balance,DbTerm}` for ordered_set (`erl_db_tree.h:28,40`); CA tree `DbTableCATree` (base/route nodes over `TreeDbTerm`) for ordered_set + `write_concurrency` (`erl_db_catree.h:38,81`).
- **Locks:** one `erts_rwmtx_t rwlock` + `fixlock` per table (`erl_db_util.h:322`). Default = table-wide rwlock; hash + `write_concurrency` = per-slot `DbTableHashFineLockSlot` locks (default 64, auto-adapts; `erl_db_hash.h:57`, `erl_db_hash.c:177`); catree = per-base-node lock. `read_concurrency` = `ERTS_RWMTX_TYPE_FREQUENT_READ` lock variant only (`erl_db_hash.c:354`).
- **Put is always a full deep copy.** `db_put`→`new_dbterm`/`replace_dbterm`→`db_store_term`/`db_store_term_comp`: computes per-element `size_object` then `copy_ets_element`→`copy_struct` (`erl_db_util.c:3556,3517`). `replace_dbterm` reuses the same allocation iff the new size matches, but still re-copies all elements. `ets:insert(T,List)`/`insert_new` use the yieldable bulk path `ets_insert_2_list` (`erl_db.c:2022`): inserts from the process heap under the table lock, or copies the list to standalone dbterms *before* locking. `ets:update_element` fast-paths immed / same-size self-contained boxed elements in place (`sys_memcpy`), otherwise rewrites the WHOLE tuple via `db_finalize_resize` (`erl_db_util.c:3275,3663`). `ets:select_replace` builds a fresh dbterm from the match result (`erl_db_hash.c:2819`).
- **Reads all copy into the caller's heap; none aliases table memory.** `lookup` = deep copy of each whole object (`db_copy_object_from_ets`, `erl_db_util.h:425`; `build_term_list` `erl_db_hash.c:3591`; `db_get_tree_common` `erl_db_tree.c:1019`). `lookup_element` copies ONLY the requested element (bag: list of that element; `db_copy_element_from_ets`, `erl_db_util.c:3763`). match/select run PAM and copy result/bound terms in with `copy_shallow`/`copy_struct` under `ERTS_PAM_COPY_RESULT` (`erl_db_util.c:2638`). `first`/`next`/`last`/`prev` copy only the KEY (`db_copy_key*`); `*_lookup` variants copy key+object. `ets:tab2list/1` = `ets:match_object(T,'_')` (stdlib `ets.erl:2788`).
- **Large binaries are shared, not copied** on both put and read: the `BIN_REF_SUBTAG` cases just `erts_refc_inc` the underlying `Binary` (`copy.c:1652,1986`); a writable binary is pinned/frozen on copy (`copy.c:834`). This is the main existing copy-avoidance.
- **`{compressed}`**: non-key tuple elements stored in OTP external-term format (key uncompressed); decoded back into the caller's heap on read (`erl_db_util.c:3436,3726`). Saves table memory; still a per-read copy.
- **Memory accounting is per-table, not per-process.** Each table has an `ErtsFlxCtr counters` (nitems + total bytes, updated on every `erts_db_alloc/free`; `erl_db.h:161`); `ets:info(T,memory)` returns `DB_GET_APPROX_MEM_CONSUMED` in words (`erl_db.c:5475`). `process_info(P,memory)` does NOT include ETS memory.

## Shared / Off-Heap Reference-Counted Objects (quick reference)
Only three kinds of object are shared read-only across process heaps: **refc binaries**, **literal areas** and **persistent_term**. Each is reached through a small heap-resident *handle* while the payload lives outside every process heap.
### Refc (large) binaries
- Payload = `Binary` (`erl_binary.h:63`) = `{intern{flags,apparent_size,refc}, orig_size, orig_bytes[]}`; the count is `intern.refc` (`erts_refc_t` = `erts_atomic_t`, `sys.h:964`), initialized to 1 (`erl_binary.h:278,312`).
- On-heap handle = `ErlSubBits` (`erl_bits.h:60`, subtag `SUB_BITS_SUBTAG`) whose `orig` points at a `BinRef` (`erl_bits.h:135` = `{thing_word=HEADER_BIN_REF, Binary *val, next}`); `next` threads the process's off-heap (MSO) list. A `BinRef` is never a user term — a bitstring must wrap it in an `ErlSubBits` (`ERL_REFC_BITS_SIZE` = `ErlSubBits`+`BinRef` words, `erl_bits.h:147`).
- Threshold: `size <= ERL_ONHEAP_BITS_LIMIT` (512 bits = 64 B, `erl_bits.h:167`) → copied inline as `ErlHeapBits` (`erl_bits.h:150`, subtag `HEAP_BITS`); larger → refc (`erts_build_sub_bitstring` `erl_bits.c:2643`).
- Crossing a process boundary: `copy_struct`/`copy_shared_perform` copy only the `ErlSubBits`+`BinRef` words and bump the shared refc (`copy.c:836,1666`); the bytes are untouched. Distribution encodes the handle but *does* put the payload in the iov (`external.c:3851-3934`); `BINARY_INTERNAL_REF` is the local-only encoding.
- Free: `erts_bin_release` → `erts_refc_dectest(...,0)` → `erts_bin_free` (`erl_binary.h:399`).
- GC: the MSO list (`MSO(p)` = `p->off_heap`, `erl_process.h:1030`; `struct erl_off_heap_header` `erl_message.h:73`) is walked by `sweep_off_heap` (`erl_gc.c:2996`) — moved handles are re-pointed, dead ones deref the binary. Writable binaries live on `p->wrt_bins` (`erl_process.h:1151`), shrunk/pinned in the same sweep (`erl_gc.c:3146`; `erts_pin_writable_binary` `erl_bits.c:2051`).
- The append optimization mutates the payload in place while refc==1 (`BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER`, `erl_binary.h:47`); any observation/sharing clears it.
### Literal areas
- `ErtsLiteralArea` (`global.h:948`) = `{ErlOffHeap *off_heap; Eterm *end; Eterm start[]}`, a bump-allocated read-only term block. Module constants are registered by the loader via `erts_set_literal_tag` (`erl_term.c:36`), which ORs `TAG_LITERAL_PTR` 0x4 into every boxed/list word and into `ErlSubBits.orig`.
- Detected either by pointer range or by that tag: `erts_is_literal` (`global.h:1574`) / `erts_is_in_literal_range` (`erl_alloc_util.c:949`) / `is_literal_ptr` (`erl_term.h:257`). `TAG_LITERAL_PTR` is only compiled in when NOT `ERTS_HAVE_OS_PHYSICAL_MEMORY_RESERVATION`, or under DEBUG (`erl_term.h:55-61`).
- Copy paths treat literal subterms as shared and never copy them (`copy.c:105,720,1164,...`); `erts_debug:same/2` is raw word `==` (`beam_debug.c:64`).
- Retirement: when a module is purged the area is queued (`erts_queue_release_literals` `global.h:954`); `sweep_literal_area` (`erl_gc.c:2379`) then copies surviving literal subterms onto each referencing process's own heap. VM-internal constants use a parallel mechanism, `erl_global_literals.c` (`ERTS_GLOBAL_LIT_*`, `GLOBAL_LIT_*`).
### persistent_term
- Global atomic hash table `HashTable` (`erl_bif_persistent.c:58`) of `{Key,Term}` tuples; both key and value are frozen into a fresh literal area on `put` via the sharing-preserving copier (`copy_shared_calculate`/`copy_shared_perform`, `erl_bif_persistent.c:749-761`).
- `persistent_term:get/1` does NOT copy — `persistent_term_get` returns the stored term straight from the literal area (`erl_bif_persistent.c:359-372`).
- Update is expensive: new literal area + thread-progress barrier to publish (`erts_schedule_thr_prgr_later_op`, `erl_bif_persistent.c:777`), and the retired area is copied onto every still-referencing process at that process's next GC (`copy_literals`/`in_literal_purge_area` in `copy.c:1118-1524`).
### What makes an object shareable here (exact conditions)
(a) its payload holds NO tagged `Eterm` pointer into any process heap (raw bytes/offsets only) — otherwise a peer GC move/deref dangles it; (b) it stays immutable for as long as it is shared (BEAM has no write barrier / card marking / remembered set — see `../internal_doc/GarbageCollection.md`); (c) it is either reference-counted (refc binary) or permanently frozen (literal / persistent_term). Only those three object kinds satisfy all three today.

## `.beam` File/Chunk & Operand-Tag Encoding (quick reference)
`beam_file.c` is the authoritative `.beam` reader (`beamfile_read` :1586, `iff_init` :2040, `read_beam_chunks` :1536, `beamcodereader_read_next` :2286); the writer is `../../lib/compiler/src/beam_asm.erl` (`encode/2` :854, `chunk/2` :283, `build_form/2` :275). No in-tree doc describes the format.
- Container: `"FOR1"` + u32 form-length (includes the 4-byte form type) + `"BEAM"` + chunk dir. ALL ints are **big-endian** (`beamreader_read_i8/i16/i32` :101-145). Each chunk = 4-char id + u32 size + payload + pad-to-4 (:1561-1570). Known ids (:1588-1605): `AtU8 Code StrT ImpT ExpT FunT LitT Attr CInf Line LocT(BEAMASM only) Atom(obsolete) Type Meta DbgB Recs`. Mandatory: `Code`,`AtU8`,`ImpT`,`ExpT` (:1645-1681).
- `AtU8`: i32 count; if negative (`count=-count`) atom lengths are `u`-tagged varints (OTP 28+), else u8 (OTP 27). Names are **UTF-8** (:291). File atom index 0 = NIL, real atoms 1..N, module = 1 (:255-299); atoms sorted by term order.
- `Code`: u32 head_size(=16) + u32 format_number (`BEAM_FORMAT_NUMBER`=0, `../../lib/compiler/src/genop.tab:22`), u32 max_opcode, u32 label_count, u32 function_count, then instruction stream (:1511-1534). End-of-code = the `int_code_end/0` instruction, not size exhaustion.
- `ImpT`/`ExpT` (:302-386): i32 count then count×{module,fn,arity}/{fn,arity,label} (u32 each). `FunT` (:394-441): i32 count then count×6×u32 {fn,arity,label,index,num_free,old_uniq}. `Line` (:443-602): version 0 then flags/instr_count/item_count/name_count u32, item stream of `a`(file idx)/`i`(line) varints, then name_count×(i16 len+UTF-8). No column field.
- `LitT` (:1471-1509): i32 uncompressed_size; **0 ⇒ uncompressed** (OTP 28+), else zlib-deflate payload of that decompressed size. Payload = i32 count then count×(i32 ext_size + external-term-format bytes). `StrT`/`Attr`/`CInf` are raw bytes.
- Operand tags — only **8** values occur in the file (`tag = len & 7`): u0 i1 a2 x3 y4 f5 h6(unused) z7; loader-internal n8 p9 r10 v11 l12 q13 o14, `BEAM_NUM_TAGS`=15. `TAG_<letter>` is generated from `compiler_types="uiaxyfhz"`+`loader_types="nprvlqo"` (`../utils/beam_makeops:135-137,1034-1052`); regen `perl ../utils/beam_makeops -wordsize <32|64> -outdir $(TTF_DIR) -jit yes|no -emulator <tables>` (`../Makefile.in:655-661`).
- Tagged varint (`beamreader_read_tagged` :167-240 / `encode/2`): `len&8=0` ⇒ 1 byte, value `len>>4`; `len&8=1,len&0x10=0` ⇒ 2nd byte, value `((len>>5)<<8)|b`; else long ⇒ `count=((len>>5)+2)` (or, if `len>>5==7`, a `u` sub-varint `+9`) payload bytes, big-endian; `i` sign-extends to small/bignum/literal (:2132-2232).
- `z` extended sub-tag = following `u` value (:2339-2447): 0=obsolete float, 1=args list(count + sub-operands), 2=float reg, 3=alloc list, 4=static literal index, 5=**typed register** (sub-operand `x`/`y` then `u` type-table index; packed `reg | (type<<10)`, `REG_MASK`=1023).
- Type entries (`beam_types.c:44-105`): u16 BE `type_union|metadata_flags`, then 8-byte BE `min`/`max` + 1-byte `unit-1` per BEAM_TYPE_HAS_* bits (`beam_types.h:42-91`, version 4; v3 = OTP 27/28 meta-bit shift :654-687).
- BIF operand in `bifN`/`gc_bifN`: a plain untagged `u` = **index into the `ImpT` chunk** (`internal_doc/beam_makeops.md:954-990`; `beam_asm.erl:774-776`), NOT the `bif.tab` number; resolved to a BIF pointer after the loader's `u$is_bif` check.
- `s`(source) `b`(BIF ptr) `d`(dest reg) `t`/`I`/`W`(untagged int) `c`(const) `r`(x0) `e` `F` `L` `P` `Q` `j` are *specific-instruction operand types* in `ops.tab` (`internal_doc/beam_makeops.md:720-817`), not file tags; there is no `tr` tag — the typed register is `z,5`.

## External Term Format (`external.c`) — special tags (quick reference)
Codec entry points declared in `external.h`: `erts_encode_ext(Eterm,byte**)` / `erts_encode_ext_size[_2]` (:197-201) and `erts_decode_ext(ErtsHeapFactory*,const byte**,Uint32)` / `erts_decode_ext_size(const byte*,Uint)` (:229-232). Public tag macros live in `external.h` under `#ifdef ERTS_WANT_EXTERNAL_TAGS` (:29-90). Term encode → `enc_term_int` (:3253); term decode → `dec_term` (:4308); the size/validation pass → `decoded_size` (:6040). `binary_to_term` = `binary2term_prepare` (:1744; requires `VERSION_MAGIC` 131 at byte 0, optional `COMPRESSED` 'P') + `decoded_size` + `dec_term` (:1842-1869). Every payload begins with `VERSION_MAGIC`; term-only tags never carry it.
- **`LOCAL_EXT` (`'y'`=121, `external.h:62`) is the `term_to_binary/2 [local]` wrapper — NOT a local fun/export tag.** Set by `parse_t2b_opts` (`am_local`, :1499) → `DFLAG_LOCAL_EXT` (`0x10<<32`, `dist.h:68`). Wire: `VERSION_MAGIC, LOCAL_EXT, uint32-BE node-hash(4 bytes), <normal ETF term>`. Encode: `enc_term_int` emits the tag + 4 reserved bytes at the very start (:3305-3317) and patches the hash at the end (:4046-4105); sized +5 (`:5589-5600`). For *internal* pid/port/ref the node atom is replaced by the single byte `NIL_EXT` (0x6A) and creation is forced 0 (:2978, :3651, :3686); external pids are unaffected. Decode: `dec_term` `case LOCAL_EXT` (:5250) consumes 4 hash bytes, materializes no term, and sets `ERTS_DIST_EXT_INTERNAL_NC`, which makes `dec_sysname` (:3109) map the `NIL_EXT` node to `INTERNAL_LOCAL_SYSNAME`=NIL so `dec_is_this_node` (:3123) resolves local identifiers to `erts_this_node` even across node-name/creation change. The hash is verified **only** in `decoded_size` (:6437-6516; mismatch ⇒ error) using Bob-Jenkins `erts_block_hash` seeded with `local_node_hash` (`erl_term_hashing.c:428,505`; `external.c:136`). Encoder emits it once, top-level; `[local]` is incompatible with `[deterministic]` (:1543). Introduced OTP 26.
- **`RECORD_EXT` (`'C'`=67, `external.h:63`) — native record term, introduced OTP 29 (doc `erts/doc/guides/erl_ext_dist.md:778`).** Wire: `tag(1)`, `#Fields` (uint32 BE), `Flags` (1 byte: 0=not-exported, 1=exported; other bits MUST be 0), `Module`(atom), `Name`(atom), then `#Fields` field-name atoms, then `#Fields` values. Atoms use `enc_atom`/`dec_atom` so the distribution atom cache applies. Requires the native-record term layer: `ErtsRecordInstance` / `ErtsRecordDefinition` / `RECORD_INST_SIZE` / `RECORD_DEF_SIZE` / `MAKE_RECORD_HEADER` all in `erl_record.h:31-95` (`keys[]` sorted by atom index, `field_order` tuple maps back; definition is a tuple-tagged object). Encode `case RECORD_DEF` (:4006-4036), decode `case RECORD_EXT` (:5257-5381: validates Flags∈{0,1} :5286, duplicate field keys ⇒ error :5345), size `:6447` + `:5917`. The codec does NOT gate it on `DFLAG_NATIVE_RECORDS` (that flag only appears in the handshake). Not deprecated.
- **`DIST_HEADER` (`'D'`=68, `external.h:65`) is a distribution-transport wrapper only — never produced or consumed by the term codec.** There is no `DIST_HEADER` case in `enc_term_int`/`dec_term`/`decoded_size` (`default:` ⇒ error), so a bare `binary_to_term(<<131,68,...>>)` is REJECTED (`badarg`). Constructed by the dist-header encoder `erts_encode_ext_dist_header_setup` (:389; degenerate fallback :7078) and rewritten by `erts_encode_ext_dist_header_finalize` (:483); wire `VERSION_MAGIC, DIST_HEADER, dist_hdr_flags(1), NumAtomCacheRefs(1), [flag bytes], [cache entries]` (fragmented: `DIST_FRAG_HEADER` 'E' + seq_id/frag_id u64×2 before the flags; `DIST_FRAG_CONT` 'F' = `VERSION_MAGIC, 'F', from u64, frag u64`). Parsed/stripped before term decode by `erts_prepare_dist_ext` (:901), called from `erts_net_message` (`dist.c:2017,2073`); it sets `ERTS_DIST_EXT_DFLAG_HDR` and builds the atom translation table. `PASS_THROUGH` 'p' (:56) is the no-header control byte.

- **Binaries (refc layout)**: on-heap `ErlHeapBits` ≤ `ERL_ONHEAP_BINARY_LIMIT`=64 B / `ERL_ONHEAP_BITS_LIMIT`=512 bits (`erl_bits.h:150-176`); larger ⇒ heap `ErlSubBits` (5 words: `thing_word, base_flags, start, end, orig`; `erl_bits.h:60-82`) whose `orig` is a tagged `BinRef` (3 words: `thing_word, Binary *val, off_heap_header *next`; `erl_bits.h:135-139`); combined `ERL_REFC_BITS_SIZE = ERL_BIN_REF_SIZE+ERL_SUB_BITS_SIZE = 8` (`erl_bits.h:147`). `HEADER_BIN_REF=_make_header(2,0x28)=0xA8`, `HEADER_SUB_BITS=_make_header(4,0x24)=0x124`. Off-heap decision = `erts_build_sub_bitstring` (`erl_bits.c:2643`) / `erts_extracted_bitstring_size` (`erl_bits.h:584-593`). Payload struct is `Binary` (`erl_binary.h:63-81`), NOT the older `ProcBin` name. Note the current C no longer uses the name `ProcBin` anywhere.
- Binary/bitstring types were renamed: the off-heap ref-counted reference is `BinRef` (`erl_bits.h:135`) wrapping a `Binary` payload (`erl_binary.h:63`); sub-bitstrings AND match contexts are the single `ErlSubBits` struct (`erl_bits.h:58`). The older names `ProcBin`, `ErlSubBin`, `ErlBinMatchState` and the `ERL_MATCH_*`/`ERL_SUB_BIN` sub-tags no longer exist — do not search for them. On-heap small binaries use `ErlHeapBits` (`ERL_ONHEAP_BINARY_LIMIT` 64 bytes / `ERL_ONHEAP_BITS_LIMIT` 512 bits, `erl_bits.h:166`).
- Legacy GC names from older OTP versions / third-party writeups are gone: no `halloc`/`halloc_extra`, `GENERATION_LIMIT`, `HEAP_HWM`, `save_young_heaps`, nor compile-time `ERTS_MAX_HEAP_SIZE`. Default `fullsweep_after` is `(Uint16)-1` = 65535 (`erl_init.c:843`).
- `BinRef`/`ExternalThing`/`ErlFunThing`/off-heap headers share identical `thing_word`/`next` offsets — asserted in `erts_init_gc` (`erl_gc.c:246-250`); adding a new off-heap term type requires updating those assertions and the MSO sweep switch in `sweep_off_heap` (`erl_gc.c:2989`).
- **There are TWO copiers and the default does NOT preserve sharing.** The flat copier `copy_struct_x` (`copy.c:647`, macros `copy_struct`/`copy_struct_litopt`) used by all send/spawn/ETS/message paths copies a subterm once per occurrence (a term appearing twice is copied twice); it shares only immediates, literals (and the empty-tuple global literal), refc binaries via `BinRef` refc, magic refs, and external pid/port/ref node entries. The sharing-preserving copier `copy_shared_calculate` (`copy.c:1111`) + `copy_shared_perform_x` (`copy.c:1382`, macro `copy_shared_perform`) keys sharing on the from-space term address (an `SHTABLE` + in-place marker mangling during the calculate pass), and is compiled in only under `SHCOPY` = `--enable-sharing-preserving` (`make/configure.ac:300`, OFF by default); when on, `SHCOPY_SEND`/`SHCOPY_SPAWN` (`global.h:1054-1057`) redirect `erts_send_message` (`erl_message.c:767,791`) and process spawn (`erl_process.c:12543`) to it. `erts_debug:copy_shared/2` (`beam_debug.c:169`) and `persistent_term` freezing (`erl_bif_persistent.c:749`) call the sharing copier unconditionally.
- **There is no `erts_move_msg` function.** Moving message fragments onto a process's main heap: `erts_move_multi_frags`+`move_one_frag` (`copy.c:2049,2113`, GC-style move markers for multi-fragment internal messages) and `erts_copy_one_frag` (`erl_gc.c:2513`, plain offset copy for a single fragment), both invoked from `move_msg_to_heap`/`erts_proc_sig_move_msgs_to_heap` (`erl_proc_sig_queue.c:8851`).
- `driver_select()` and `enif_select()`/`enif_select_x()` are NOT implemented here: the fd/pollset registration and the ready-event → `ERTS_PORT_TASK_INPUT`/`ERTS_PORT_TASK_OUTPUT` scheduling live in `../sys/common/erl_check_io.c` (see `../internal_doc/CheckIO.md`). This node owns the port-task queues (`erl_port_task.c`), the driver callback invocation (`ready_input`/`ready_output` in `erl_port_task_execute`), and the driver-API functions (mostly in `io.c`, but `driver_async` is in `erl_async.c`).

## Notes for Agents
- Authoritative design docs, read before changing internals: `../internal_doc/GarbageCollection.md`, `DelayedDealloc.md`, `CarrierMigration.md`, `SuperCarrier.md`, `PTables.md`, `ThreadProgress.md`, `PortSignals.md`, `ProcessManagementOptimizations.md`, `CheckIO.md`, `Tracing.md`, `CodeLoading.md`, `CountingInstructions.md`, `AutomaticYieldingOfCCode.md`, `beam_makeops.md` (also `BeamAsm.md` for the JIT in `jit/`).
- Adding/removing a BIF means editing `bif.tab` (and `erl_dirty_bif.tab` for dirty BIFs), not the generated tables.
- Most files are large on purpose (e.g. `dist.c`, `erl_alloc_util.c`, `bif.c`, `erl_process.c`); navigate by section comments rather than expecting small modules.
- Building only this directory requires a configured tree and the generated headers; without `erts/$(TARGET)/config.h` and `$(TTF_DIR)` most files cannot even be parsed.

## Test Strategy
- No tests in this directory. VM tests are the 104 tracked `../test/*_SUITE.erl` suites (plus the build-generated `*_no_opt_SUITE`/`*_stripped_types_SUITE` variants) run via `make emulator_test` from `ERL_TOP` or `make test` from `../`: `beam_SUITE`, `bif_SUITE`, `gc_SUITE`, `alloc_SUITE`, `dirty_bif_SUITE`, `dirty_nif_SUITE`, `nif_SUITE`, `big_SUITE`, `binary_SUITE`, `bs_*_SUITE`, `map_SUITE`, `process_SUITE`, `signal_SUITE`, `register_SUITE`, `node_container_SUITE`, `ref_SUITE`, `native_record_SUITE`, `distribution_SUITE`, `port_SUITE`, `driver_SUITE`, `trace_SUITE`/`tracer_SUITE`/`emulator_trace.spec`, `lcnt_SUITE`, `jit_SUITE`, `system_info_SUITE`, `dump_SUITE`.
- ETS behavior is tested at the stdlib level (`../../../../lib/stdlib/test/ets_SUITE.erl`), not from `../test/`.
- C-level bugs are usually reproduced under `TYPE=debug`, `asan`, `valgrind` or `lcnt` flavors; suppression/helper files live in `../asan/` and `../valgrind/`, lock-count tests use `lcnt`.

## Routing Table
- `jit/` → JSV/JIT (BeamAsm): `beam/jit/` C++ + per-arch subdirs (`x86/`, `arm/`) with their own `ops.tab`/`predicates.tab`/`generators.tab`; child of this node, owns all `.cpp` in the emulator.
- `emu/` → interpreter (`beam/emu/`): hand-written dispatch loop `beam_emu.c` (there is no `beam_emu.h`), `emu_load.c` + `load.h` (emu flavor loader), `ops.tab` and the `*_instrs.tab` instruction bodies; only `beam_hot.h`/`beam_warm.h`/`beam_cold.h`/`beam_opcodes.*` are generated (into `$(TTF_DIR)`).
- `../test/` → BEAM VM test suites (`*_SUITE.erl`, spec files); sibling subtree — read-only, escalate writes to `../` (erts/emulator).
- `../utils/` → code generators invoked by `../Makefile.in` (`beam_makeops`, `make_tables`, `make_alloc_types`, `make_preload`, `make_driver_tab`, `beam_strip`, ...). Read-only from here.
- `../internal_doc/` → design documents for the VM internals (GC, carriers, PTab, thread progress, port signals, code loading, tracing, beam_makeops).
- `../nifs/`, `../drivers/`, `../sys/`, `../zlib/` → platform/3PP and port/NIF implementations that call back into functions exported from this directory (`erl_drv_nif`, `erts_atomic`, `erts_mmap`).
