# erts/emulator/beam/ — BEAM emulator core (VM implementation)

## Intent
The flat, single-directory core of the BEAM virtual machine: ~107 `.c` files and ~97 `.h` files that implement data types, BIFs, GC, scheduling, allocators, ETS, distribution, code loading, tracing, NIF/driver support, timers and ports.
Everything here is compiled and linked into the emulator executable (`$ERL_TOP/bin/$(TARGET)/beam.smp`) and into the archive `libbeam.a`.
Flavor/architecture-specific code lives in the child dirs `jit/` and `emu/` (see Routing Table); this directory holds the flavor-independent parts plus the codegen *inputs* shared by both.

## API Surface
### Public C headers (installed to `$RELEASE_PATH/usr/include` and `erts-$(VSN)/include`)
- `erl_driver.h` — driver developer API (threads, locks, memory, binary, async, port I/O).
- `erl_nif.h`, `erl_nif_api_funcs.h` — NIF API (version history in the header maps API version → OTP release).
- `erl_drv_nif.h` — types/decls shared between `erl_driver.h` and `erl_nif.h`.
- `driver_int.h` is per-OS and lives in `../sys/<ostype>/`, not here.
- `erl_internal_test.h` — internal only, installed to `erts-$(VSN)/include/internal`.
These four headers (plus per-OS `driver_int.h`) are the ONLY stable ABI exposed from this directory; everything else is private to the emulator.

### Generated-code INPUTS kept here (hand-maintained, not generated)
- `atom.names`, `bif.tab`, `erl_dirty_bif.tab` → generated into `$(TTF_DIR)` by `../utils/make_tables`: `erl_bif_table.c|h`, `erl_bif_list.h`, `erl_atom_table.c|h`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c` (further consumed by `../utils/beam_makeops`).
- `erl_alloc.types` → `$(TTF_DIR)/erl_alloc_types.h` via `../utils/make_alloc_types` (defines `ErtsAlcType_t` values and type→strategy mapping).
- `predicates.tab`, `generators.tab` → concatenated with the flavor tables (`../beam/jit/$(JIT_ARCH)/{predicates,generators}.tab` for `FLAVOR=jit`, `../beam/emu/{predicates,generators}.tab` for `FLAVOR=emu`) and fed to `../utils/beam_makeops`, producing `$(TTF_DIR)/beam_opcodes.c|h`, `beam_hot.h`, `beam_warm.h`, `beam_cold.h` (the instruction table + dispatch code shared by interpreter and JIT).
- `erlang_dtrace.d` → `$(TARGET)/erlang_dtrace.h` when DTrace is enabled.
`$(TTF_DIR)` = `erts/emulator/$(TARGET)/$(TYPE)/$(FLAVOR)`.

### Sources rewritten by the yielding-C compiler (YCF)
`erl_map.c` → `$(TTF_DIR)/erl_map.ycf.h`, `utils.c` → `utils.ycf.h`, `erl_db.c` → `erl_db_insert_list.ycf.h`.
Each `.c` `#include`s its own generated `.ycf.h` near the bottom; the generator binary is `../lib_src/yielding_c_fun`.

### What it contributes to the build
`../Makefile.in` globs `BEAM_SRC=$(wildcard beam/*.c)` (dependency/compdb scanning) and lists the objects explicitly in `COMMON_OBJS` (loader/JIT-shared: `beam_common`, `beam_bif_load`, `beam_bp`, `beam_catches`, `beam_debug`, `beam_load`, `beam_opcodes`, `beam_ranges`, `beam_transform_helpers`, `code_ix`), `RUN_OBJS` (everything else here), `LTTNG_OBJS` (`erlang_lttng.c`), plus `OS_OBJS`/`NIF_OBJS`/`DRV_OBJS` from other dirs.
Outputs: `$ERL_TOP/bin/$(TARGET)/beam.<flavor>` and the archive `EMULATOR_LIB` (`libbeam.a`, `libbeam.lib` on Windows) installed to `erts-$(VSN)/lib`.
There are currently **no `.cpp` files directly in `beam/`** (the `BEAM_CPP_SRC` glob is for `jit/`).

- **Processes / scheduling**: `erl_process.c`/`erl_process.h` (the largest single unit: process struct, scheduling, signals, priority), `erl_nfunc_sched.c` (native-function trap wrappers), `erl_sched_spec_pre_alloc.c` (scheduler-specific pre-allocated pools), `erl_proc_sig_queue.c`, `erl_monitor_link.c`, `erl_process_dict.c`, `erl_process_dump.c`, `erl_process_lock.c`, `erl_message.c`.

- **ETS / term storage**: `erl_db.c` (API + ycf trap loop), `erl_db_hash.c`, `erl_db_tree.c`, `erl_db_catree.c`, `erl_db_util.c`, plus headers `erl_db.h`, `erl_db_hash.h`, `erl_db_tree.h`, `erl_db_tree_util.h`, `erl_db_util.h`, `erl_db_catree.h`.
- **Binaries / bits / iolists**: `binary.c` + `erl_binary.h` (ref-counted `Binary`/`ErlDrvBinary`, magic refs, writability), `erl_bits.c|.h` (bit syntax), `erl_iolist.c|.h` (iolist→binary), `erl_bif_binary.c` (binary BIFs).
- **Atoms**: `atom.c`/`atom.h` (+ `atom.names`).
- **Code loading & loader**: `beam_load.c`, `beam_file.c` (`.beam` file reader/validator), `beam_common.c`, `beam_bif_load.c` (`erlang:load_module` etc.), `code_ix.c|.h` (2/3-generation code index scheme), `beam_ranges.c` (faulting/line tables), `beam_transform_helpers.c`, `beam_types.c` (type/beam_types representation), `beam_bp.c|.h` (breakpoints/instrumentation), `beam_catches.c` (catch/exception table), `beam_code.h`, `module.c`, `export.c`, `index.c`, `erl_fun.c` (funs), `erl_record.c` (native records), `erl_code_staged.h` (X-macro template included with `ERTS_CODE_STAGED_*` macros defined to instantiate the per-code-index "staged" tables/blobs; used by `export.c`, `erl_fun.c`, `erl_record.c`).
- **Distribution / node tables**: `dist.c`/`dist.h` (external term distribution protocol, DFLAGs), `erl_node_tables.c` (ref-counted node table), `erl_node_container_utils.h` (pid/port/ref ↔ node-table element macros), `erl_etp.c` (constants exported for the debugger), `erl_async.c`, `external.c` (external term format), `packet_parser.c` (packet framing).
- **Tracing / debugging / instrumentation**: `erl_trace.c|.h` (tracers), `erl_bif_trace.c` (`erlang:trace*`), `erl_debug.c` (DEBUG-only print/verbose categories, `DEBUG_BAD_BYTE`), `erl_debugger.c` (`erts_debug` support), `break.c`, `erl_msacc.c` (microstate accounting), `erl_flxctr.c` (decentralized/flexible counters), `erlang_lttng.c`.
- **NIF/driver C-side support — the frozen C-ABI ground truth**: `erl_nif.c` (NIF loader/dispatch, `ErlNifEnv`; ~178 distinct `enif_*` definitions backing the 180-entry `erl_nif_api_funcs.h` API list, plus the internal `erts_nif_*` machinery: `erl_nif_init`, `erts_nif_get_funcs`, `erts_nif_call_function`, `erts_nif_get_module`, `erts_nif_taints`, `erts_nif_demonitored`, `erts_nif_sched_init`, `erts_nif_execute_on_halt`/`erts_nif_notify_halt`/`erts_nif_wait_calls`), `erl_drv_thread.c` (~37 `erl_drv_*` mutex/cond/rwlock/TSD/thread implementations), `erl_dyn_lock_check.c`, `erl_internal_test.c`.
  - The `erts_nif_*` internals are NOT NIF-only: called from `erl_init.c` (`erl_nif_init`, `erl_drv_thr_init`, halt/wait), `erl_process.c` (`erts_nif_sched_init`, `erts_nif_notify_halt`), `erl_trace.c` (user-tracer bridges), `erl_alloc_util.c`, `erl_bif_info.c`, `erl_proc_sig_queue.c` (resource demonitor) — so `erl_nif.c`/`erl_drv_thread.c` cannot be deleted without touching core scheduler/trace/signal code.
- **Threading / locking / sync**: `erl_thr_progress.c` (global "all threads passed here" barrier), `erl_thr_queue.c` (many-to-one lock-free queue), `erl_lock_check.c`, `erl_lock_count.c`, `erl_lock_flags.c`.
- **Timers / time**: `time.c` (timer wheel), `erl_time_sup.c` (Erlang time services), `erl_hl_timer.c` (high-level/BIF timers), `erl_time.h`.
- **Ports / I/O**: `erl_port.h`, `erl_port_task.c|.h` (port task queues/scheduling), `erl_io_queue.c|.h` (IO queues for file/socket ports), `erl_bif_port.c`, `erl_zlib.c|.h` (zlib 3PP wrapper).
- **`io.c` — the Port subsystem AND the `driver_*` C ABI (frozen driver ABI ground truth)**: ~63 `driver_*` definitions (`driver_output*`, `driver_alloc/free/realloc`, `driver_enq*/deq/peekq*`, `driver_monitor_process`, `driver_failure*`, `driver_dl_open/sym/close/error`, `erl_drv_output_term`/`erl_drv_send_term`, `erl_drv_init_ack`, `erl_drv_set_os_pid`) but it is ALSO the whole port layer: `ErtsPTab erts_port`, `erts_init_io`, `erts_port_output`, `erts_port_exit`, `erts_port_link`, `erts_port_monitor`, `erts_open_driver`. These core port functions are called from `bif.c`, `erl_bif_port.c`, `erl_process.c`, `dist.c`, `erl_init.c` and `sys/{unix,win32}/sys.c` — deleting `io.c` breaks `send`/`!` to ports, port links/monitors, distribution and heart, not just driver callers.
- **`erl_async.c`** implements the async-thread pool (`erts_init_async`, `erts_check_async_ready`, `erts_get_async_ready_queue`, `erts_exit_flush_async`) used by `erl_init.c`/`erl_process.c`, plus the `driver_async`/`driver_async_port_key` driver-API entry points.
- **Crash dumps / misc**: `erl_crash_dump.c` (writes `erl_crash.dump`), `erl_unicode.c|.h` + `erl_unicode_normalize.h`, `erl_md5.c`, `erl_printf_term.c` (term→string), `erl_errno_str.c`, `erl_cpu_topology.c` (CPU/cache topology detection for schedulers), `hash.c`, `safe_hash.c` (thread-safe hash table), `register.c`, `erl_init.c` (VM bootstrap/`main` support), `erl_main.c` is in `../sys/`, not here.
- **Wrapper headers**: `dtrace-wrapper.h`, `lttng-wrapper.h` (no-op macros when the trace backend is disabled).

## Constraints
- **Never edit the generated outputs**; edit the inputs listed above and regenerate. Generated files are `erl_bif_table.c|h`, `erl_bif_list.h`, `erl_atom_table.c|h`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c`, `erl_alloc_types.h`, `beam_opcodes.c|h`, `beam_hot.h`, `beam_warm.h`, `beam_cold.h`, `erl_map.ycf.h`, `utils.ycf.h`, `erl_db_insert_list.ycf.h`, `erlang_dtrace.h` — none of these exist in this directory.
- **`#include "global.h"` is the convention** for essentially every translation unit here (it pulls in `sys.h`, allocators, term/process/port headers); the remaining files are deliberately low-level (`hash.c`, `safe_hash.c`, `packet_parser.c`, `erl_md5.c`, `erl_printf_term.c`, `erl_iolist.c`, `beam_file.c`, `beam_transform_helpers.c`, `erl_thr_queue.c`, `erl_lock_*.c`, `erl_zlib.c`, `erl_flxctr.c`, `erlang_lttng.c`, `erl_errno_str.c`, `erl_internal_test.c`, `erl_bif_atomics.c`, `erl_bif_counters.c`, `erl_bif_unique.c`, `erl_crash_dump.c`, `erl_sched_spec_pre_alloc.c`, `erl_dyn_lock_check.c`).
- No internal library boundary: this is one flat compilation set. Do not introduce public headers here beyond the four installed ones; treat all other headers as emulator-private.
- Code must compile in every `TYPE` flavor (`opt`, `debug`, `lcnt`, `valgrind`, `asan`, `gprof`, `frmptr`, `icount`, `gcov`) and under both `FLAVOR=jit` and `FLAVOR=emu`. Keep flavor/arch-specific code out of this directory (put it in `jit/` or `emu/`).
- Concurrency is lock-free in hot paths: changes touching deferred work must respect thread progress (`erl_thr_progress`) — see `../internal_doc/ThreadProgress.md`.

## Design Decisions
- **Tagged `Eterm` representation** (`erl_term.h`): 2-bit primary tags (`HEADER`/`LIST`/`BOXED`/`IMMED1`); `IMMED1` splits into pid/port/immed2/small-int, `IMMED2` into atom/catch/nil; boxed headers carry a 4-bit sub-tag (arityval, fun, big, float, ref, bin_ref, external pid/port/ref, heap_bits, map, record, sub_bits). Boxed data reference-counted where shared (`Binary`, node containers, funs). `ET_DEBUG` (on by default in `DEBUG` builds) swaps the type-access macros for runtime-checked variants.
- **Internal vs external node containers** (`erl_node_container_utils.h`): internal pids/ports are immediates, internal refs are boxed; external ones are heap-allocated with a pointer to a ref-counted node-table element (`erl_node_tables.c`), GC'd by ref count like refc binaries.
- **PTab** (`erl_ptab.h/.c`) unifies pids and ports in one id-allocating table with links/monitors — see `../internal_doc/PTables.md`.
- **Allocator "type" model**: all internal allocation goes through `erts_alloc(ErtsAlcType_t, ...)`; types are declared in `erl_alloc.types` and mapped to one of the carrier-based strategies. `erl_alloc_util.c` implements the shared carrier machinery (single-block carriers, multi-block carriers, super carriers, carrier migration, delayed deallocation) — see `../internal_doc/{CarrierMigration,SuperCarrier,DelayedDealloc}.md`.
- **Cooperative yielding in C**: long-running BIFs are written to trap; `erts/lib_src/yielding_c_fun` rewrites marked functions in `erl_map.c`, `utils.c`, `erl_db.c` into resumable state machines (`*.ycf.h`), which is how `maps:*`, `lists:sort/*`, and the ETS insert loops avoid blocking a scheduler. Truly blocking work goes to dirty schedulers (`erl_dirty_bif.tab`).
- **Multi-generation code loading** (`code_ix.c`, `erl_code_staged.h`): three logical copies of code (active/staging/previous) selected by an index so running processes need no locks; `erl_code_staged.h` is an X-macro template included multiple times with different `ERTS_CODE_STAGED_*` macros to synthesize the staged tables for exports/funs/records. See `../internal_doc/CodeLoading.md`.
- **Public headers are the ABI**: driver/NIF code only ever sees `erl_driver.h`/`erl_nif.h`; the emulator's internal structs are hidden behind `*_TYPES_ONLY__`/`*_TYPE_ONLY` include guards used all over these headers to let low-level files pull in just the type definitions.

## Deep internals reference (moved out to stay within the read limit)
The full reference for the C implementations of GC root-set/stack scanning, the Cheney copier
(forwarding markers and per-subtag sizes), the two-generation tenuring/heap-size model and the
`Eterm` term encoding lives in the **`beam-c-internals-reference` skill** (`.agents/skills/`), which
also holds the map/flatmap/HAMT header packing and the refc-binary layout.
Read it before changing or porting `erl_gc.c`, `copy.c`, `erl_term.h/.c`, `erl_map.h` or `erl_bits.h`.
Summary kept here: GC forwards in place (boxed marker = header overwritten with the tagged new
pointer, cons marker = `THE_NON_VALUE` in word 0), a minor GC moves mature objects to the old heap and
young objects to the new young heap, a major/fullsweep copies everything but literals into one new
heap, there is no write barrier / card marking / remembered set, and `Eterm` is a tagged word
(2-bit primary tag; `IMMED1` → pid/port/immed2/small, `IMMED2` → atom/catch/nil; boxed headers carry a
4-bit sub-tag plus arity).

## Subsystem internals reference (moved out to stay within the read limit)
The full reference for the C implementations of the cons-list representation, the allocator subsystem, the message-passing/process-memory copy model, ETS storage & copy semantics, the shared off-heap reference-counted objects, the `.beam` file/chunk & operand-tag encoding and the external term format's special tags lives in the **`beam-subsystems-reference` skill** (`.agents/skills/`); the GC/term-encoding half lives in the `beam-c-internals-reference` skill.
Read them before changing or porting `erl_map.c`, `erl_db*.c`, `erl_message.c`/`copy.c`, `erl_alloc*.c`, `external.c`, `beam_file.c` or `erl_bits.h`, or writing their Rust counterparts.
Summary kept here:
- **Message copy**: a local send deep-copies the whole term graph into the receiver's heap (`erts_send_message`); only immediates, literal subterms and refc/off-heap binary handles are shared; remote sends are ETF-encoded and decoded on the receiver. No size fast path.
- **ETS copy**: `put` is always a deep copy into table-owned off-heap memory and every read (`lookup`/`match`/`select`/…) deep-copies into the caller's heap; large off-heap binaries are shared by refc, not copied.
- **Only three object kinds are shared off-heap**: refc binaries, literal areas and `persistent_term` — the exact condition is "payload holds NO tagged `Eterm` pointer into any process heap + immutable while shared + ref-counted or permanently frozen".
- **Message-queue on/off-heap is a STATIC per-process flag** (spawn / `+hmqd` / `process_flag(message_queue_data, on_heap|off_heap)`) — no size or length heuristic.

## Legacy C removal plan (parity-gated)
This directory is the legacy C/C++ BEAM core. It is still (a) the OTP build's **DEFAULT runtime** (`FLAVOR=jit`) and (b) the `FLAVOR=emu` bootstrap fallback while `erts_rust/` becomes the runtime. NOTE: the differential/benchmark **oracle** is the system `erl`/`erlc` on `$PATH`, not a built in-tree emulator.
The mandate is to delete it **module by module as Rust parity is proven** — never on a "looks unused" judgement alone.
Current tracked size (excl. vendored 3PP): this directory 107 `.c` + 97 `.h` = ~264.8k lines; `../` (emulator) ~439.1k; the whole `../../` (erts) ~512.5k.
### Mechanical dead-source check (reproducible)
- `check_dead_sources.py` scans `--root <dir>` (default `erts`; also accepts `erts/emulator`, `erts/lib_src`, `.` for the whole repo) over every tracked `<root>/**/*.{c,h,cpp,hpp,cc}`, in two tiers.
- **STRICT (the deletion gate):** a compilation unit is seeded LIVE when **(a)** a real object-list entry names it (`<stem>.o`/`.obj`), including make-variable-synthesised lists — `$(VAR:...%.o)`, `$(VAR:.c=.o)`, `$(patsubst %.c,$(OBJDIR)/%.o,$(VAR))`, `$(addprefix D,$(notdir $(VAR:.c=.o)))`, and the source-naming reverse form `$(VAR:%=dir/%.c)` (`RYU_SRC`/`ZLIB_SRC`) — or a `$(wildcard ...)` pattern covers it; **(b)** it is a `*_SUITE_data/**` fixture named by its owning `<x>_SUITE.erl`; or **(c)** a build/script/codegen source names its basename verbatim (a makefile, `*.sh`/`*.erl`/`*.escript`, the extension-less codegen tools in `../utils/`, `xcomp/*.conf`, a CI yaml) or, in a makefile-role source, its whole-word stem. Liveness then propagates to a fixpoint through `#include`-by-basename and externally-visible-symbol use, restricted to candidate files; text inside a never-compiled `#if` region does not count. A mention that comes only from a doc (`*.md`/`*.rst`/`*.txt`) or an already-dead file does NOT make a file live. Everything not live after closure is `STRICT DEAD`; the ACTIONABLE set is strict-dead minus exemptions and the exit status is 1 iff it is non-empty.
- **LOOSE (advisory only):** the single-pass A/B/C classes — **(A)** a build/config source names the file's whole-word stem/basename or a `$(wildcard)`/`$(VAR)` pattern covers it (the same build-role classes as STRICT (c): makefiles, `xcomp/*.conf`, CI yaml, the extension-less `../utils/` codegen tools); **(B)** another translation unit `#include`s its basename; **(C)** an *externally visible* symbol it defines is used elsewhere. A verbatim basename match (`foo.c` naming `foo.c`) is decisive regardless of source kind, so a `*.sh`/`*.erl`/`*.escript` test corpus/script and each owning `<x>_SUITE.erl` that names a `*_SUITE_data` fixture both count. Matching is whole-word; `static`/`inline`/file-local macros are excluded from (C) so same-named statics (e.g. `read_fill`) do not fabricate references. Reported for context, never decisive.
- Exemptions (applied to BOTH tiers): vendored 3PP `asmjit/pcre/ryu/zlib/zstd`; CT fixtures (`**/test/*_SUITE_data/**`, plus all of `erts/emulator/test/` and `erts/test/`); `erts/example/` (doc samples, not built); the sanitizer/valgrind fixtures; and the installed public headers.
- Windows resource scripts (`*.rc`/`*.rc.in`, e.g. `erts/etc/win32/beam.rc`) are include-bearing build sources: their verbatim basename mentions seed class A, and their `#include` directives feed the by-basename include edge — so a header included only by a `.rc` file (`erts/etc/win32/resource.h` via `#include "resource.h"`) still gets a real liveness edge. They are reference sources only, never candidates/objects.
- Run `python3 erts/emulator/beam/check_dead_sources.py --root erts --write-report` — writes the whole-`erts/`-tree report to `dead_source_report.txt`. Runtime ~5 s. `--explain GLOB` prints the evidence plus both verdicts per file. The report also carries an **advisory** section listing never-compiled `#if` regions — a guard macro with no `#define`/`-D`/`AC_DEFINE`/`config.h.in` entry anywhere (a doc or Rust-comment mention is not a definition) — which never affect the STRICT/ACTIONABLE verdict or the exit status.
- **This is a reference proof, not a build proof.** A full legacy `erts` compile is deliberately out of scope (expensive); the bar is that no Makefile, `#include` or symbol reference reaches the file. Any *module*-level deletion must additionally be preceded by a full `erts` build.
### What a C file needs before it can go
1. Its Rust owner is the proven implementation, not a partial fallback.
2. A **live** differential-gate run (`erts_rust/tools/differential`, oracle = system `erl`/`erlc` via `$ERTS_ORACLE`/`$ERLC`) with **0 mismatches**.
3. **No `unsupported` case on the contract the file covers.** "unsupported" is self-declared by the Rust runtime, so "0 mismatch" can partly mean "never ran"; only a case-count check proves coverage.
4. A **value oracle** (compare results), not merely a breadth/loader sweep that shows the file parses.
5. No object-list entry and no `#include` anywhere in the repo.

### Removal order (first → last)
Only the PARTIAL groups are removal candidates; a NOT READY group waits until its `### Blockers` line clears. The order follows how close each group's Rust owner is to being *proven*, and every removal is gated by the full 5-point `### What a C file needs before it can go` checklist **plus a green full `erts` build** (the C emulator must still link after the file leaves its object-list/`#include` graph).
1. **term primitives** (`beam_term`, `beam_codec`) — best candidate: the bottom of the dependency stack and the only group with a value-oracle differential run over its *own* contract (terms/binary/map/bitstring). **Gate:** a live `erts_rust/tools/differential` run with **0 mismatches and 0 `unsupported`** on that contract at a case-count ≥ today's (points 2–4) with `beam_term`/`beam_codec` the sole owner (point 1); then remove `erl_term.c`, `erl_term_hashing.c`, `atom.c`, `erl_bits.c`, `binary.c`, `erl_iolist.c`, `hash.c`, `safe_hash.c`, `erl_md5.c`, `erl_unicode*.c` from `../Makefile.in` and every `#include` (point 5), and re-link a full `erts`.
2. **BIFs** (`beam_bifs`) — same value-oracle coverage (arithmetic/lists/maps/binary) but every BIF routes through the term layer, so it follows (1). **Gate:** 0 mismatch / 0 `unsupported` on the arithmetic+lists+map+binary BIF contract with a case-count check (not just the 640-key registry), then remove `bif.c`, `erl_bif_*.c`, `erl_arith.c`, `erl_math.c`, `big.c` and the `bif.tab`/`erl_dirty_bif.tab` entries; full `erts` build green.
3. **distribution + ETF** (`beam_codec`, `beam_dist`) — ETF/term-codec is value-oracle (byte-exact) but the protocol side is codec-level only (no live two-node loopback) and inbound delivery is default-OFF. **Gate:** add a live two-node handshake/loopback value oracle and clear every inbound signal family out of `Unsupported`, then remove `dist.c`, `external.c`, `packet_parser.c`, `erl_node_tables.c`, `erl_async.c`.
4. **IO / ports / drivers** (`beam_io`) — oracle-grade differential evidence today but concurrency is uncovered and the verdict is still PARTIAL with no case-count gate. **Gate:** a value-oracle port/driver run over the ready-event path, then remove `io.c`, `erl_port_task.c`, `erl_io_queue.c`, `erl_zlib.c`.
5. **NOT READY groups** — each behind its `### Blockers` line and the same 5-point list, in dependency order: **code loader** (needs a value oracle instead of the current breadth/loader sweep) → **GC + copy** → **process / scheduler** (both need the proven collector) → **ETS** (needs the `ordered_set` CA-tree) → **NIF / driver ABI** (needs end-to-end execution through the runtime) → **tracing** (needs full event coverage) → **execution engine** (`beam_engine`, then `../jit/`, `../emu/`) last, once the `erts_rust` path is the runtime.

### Blockers before any module can be deleted
- No proven collector: no differential value-oracle run for GC, and the mature/GenImmix generation is not reachable at runtime — blocks GC *and* process/scheduler removal.
- No scheduler pre-emption / thread-progress / signal-queue behaviour proven under real concurrency.
- Inbound distribution is partial and gated default-OFF — only local `Send`/`RegSend` delivery works, the other inbound signal families are `Unsupported`, and there is no `erl_node_tables.c` equivalent.
- No ETS `ordered_set` CA-tree (`erl_db_catree.c`) equivalent — `erts_rust`'s `ordered_set` is a K-ary B+-tree.
- Rust tracing is partial (`send`/`'receive'`/`call`/`return_*` only; no `spawn`/`exit`/`register`/in-out and no settable system tracer), and the NIF/driver ABI is not proven end-to-end through the runtime.
- The JIT/tiering path (`../jit/`) is off the `erts_rust` execution path.
- **CI gate scope**: `.github/workflows/erts_rust.yml` (path-triggered only on `erts_rust/**` + its own file) DOES build/test the Rust workspace and run `erts_rust/tools/differential/gate.sh`. ## Known Issues / Gotchas
- `packet_parser.c`/`packet_parser.h` is the shared packet/header decoder for BOTH the `erlang:decode_packet/3` BIF (`erl_bif_port.c`) and the legacy inet port driver (`../drivers/common/inet_drv.c`, which `#include "packet_parser.h"`): external symbols are `packet_get_length()` (c:248), `packet_parse_http()` (c:662), `packet_parse_ssl()` (c:864) and `packet_parser_init()` (c:235); `packet_parse()`/`packet_get_body()` are header-only `ERTS_GLB_INLINE` wrappers. `packet_parser_init()` is called once from `erl_init.c`; the inet driver never calls it.
- `utils.c` `#include`s `packet_parser.h` (line 39) but uses nothing from it — a vestigial include.
- `ErtsCodeMemento` no longer exists anywhere in `erts/`; function/line metadata is `BeamCodeHeader.functions[]` (sorted `ErtsCodeInfo*`, `beam_code.h:137`), where `ErtsCodeInfo = {u/gen_bp, ErtsCodeMFA mfa}` (`code_ix.h:106-125`), resolved via `beam_ranges.c`. Search for `ErtsCodeInfo`/`FunctionInfo`, not for the old name.
- `../internal_doc/GarbageCollection.md` is OTP-18/19-era: its source links point at OTP-18 tags and its root-set description/line numbers are stale — use `setup_rootset()` (`erl_gc.c:2615`) as the authority.
- Files here that look like they should be generated but are hand-maintained: `atom.names`, `bif.tab`, `erl_dirty_bif.tab`, `predicates.tab`, `generators.tab`, `erl_alloc.types`, `erlang_dtrace.d`.
- Conversely, `erl_atom_table.*`, `erl_bif_table.*`, `erl_bif_list.h`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c`, `erl_alloc_types.h`, `beam_opcodes.*`, `beam_hot|warm|cold.h`, `*.ycf.h` are generated into `$(TTF_DIR)` — do not look for them here and do not add them.
- The ycf outputs come from `erl_db.c` (NOT `erl_db_util.c`): `$(TTF_DIR)/erl_db_insert_list.ycf.h` is generated from `beam/erl_db.c`.
- `erlang.erl` (the BIF module stub) lives in `../preloaded/src/`; the actual implementations are `bif.c`/`erl_bif_*.c` + `bif.tab` here.
- `beam_debug.c` is the byte-code disassembler, not the `-D` debug print facility (that is `erl_debug.c`).
- Symbol names in `erl_etp.c`, `erl_debugger.c` and `erl_assert`-adjacent debug helpers are relied upon by debugger scripts and `erts_debug`; keep them stable.
- Same-looking names exist in child dirs (`beam/emu/*.tab`, `beam/jit/*/ops.tab`) — the `beam/predicates.tab` and `beam/generators.tab` here are the shared ones.
- Compound terms: a map is a `flatmap_t` (sorted key-tuple + values) or a HAMT `hashmap_head_t`, switching at `MAP_SMALL_MAP_LIMIT` (32 release / 3 `DEBUG`, `erl_map.h:93`); HAMT fanout is 4 bits / 16-way with a 16-bit bitmap per node, flatmap lookup is a LINEAR scan (`erts_maps_get` `erl_map.c:186`). Tuples are `[make_arityval(N), e1..eN]`.
- **Map/flatmap/HAMT word layout** (`erl_map.h:181-216`; details in the `beam-c-internals-reference` skill): `MAKE_MAP_HEADER(Type,Arity,Val) = _make_header((((Val<<8)|Arity)<<2|Type), _TAG_HEADER_MAP)`, `_make_header(sz,tag)=sz<<6|tag`; `MAP_HEADER_{TYPE,ARITY,VAL}` extract bits 6/8/16; types `FLATMAP_HEAD=0`, `HAMT_NODE_BITMAP=1`, `HAMT_HEAD_ARRAY=2`, `HAMT_HEAD_BITMAP=3`; `MAP_HEADER_FLATMAP=0x12C`, `MAP_HEADER_HAMT_HEAD_ARRAY=MAKE_MAP_HEADER(2,1,0xffff)`, collision node = plain `make_arityval(Arity)`; derived subtag words `HEAD_FLATMAP 0x2C`/`NODE_BITMAP 0x6C`/`HEAD_ARRAY 0xAC`/`HEAD_BITMAP 0xEC`.
- **Map/HAMT node word sizes** (`erl_map.h:199-211`): `HAMT_NODE_ARRAY_SZ=17`, `HAMT_HEAD_ARRAY_SZ=18`, `HAMT_NODE_BITMAP_SZ(n)=1+n` (no size word), `HAMT_HEAD_BITMAP_SZ(n)=2+n`, `HAMT_COLLISION_NODE_SZ(n)=1+n`; `hashmap_head_t = {thing_word; size; items[]}` and a node's item count is `hashmap_bitcount(MAP_HEADER_VAL(hdr))` (head-array: fixed 16), each item a heap `CONS` leaf or a boxed child (`erl_map.c:3500-3535`). Binaries: on-heap `ErlHeapBits` <= 64 B else `ErlSubBits`(5 words)+`BinRef`(3 words) -> `Binary` payload (`erl_bits.h:60-176`, `erl_binary.h:63-81`, `HEADER_BIN_REF=0xA8`, `HEADER_SUB_BITS=0x124`); the names `ProcBin`, `ErlSubBin`, `ErlBinMatchState`, `ERL_MATCH_*`, `ERL_SUB_BIN` no longer exist.
- Legacy GC names from older OTP versions / third-party writeups are gone: no `halloc`/`halloc_extra`, `GENERATION_LIMIT`, `HEAP_HWM`, `save_young_heaps`, nor compile-time `ERTS_MAX_HEAP_SIZE`. Current equivalents: `HAlloc`/`HAllocX` (`erl_vm.h:148/156`), `GEN_GCS`/`MAX_GEN_GCS` (`erl_process.h`), `p->high_water`, per-process `max_heap_size` (`MAX_HEAP_SIZE_GET/SET`), runtime `H_MAX_SIZE`/`H_MIN_SIZE` (`erl_vm.h:253`). Default `fullsweep_after` is `(Uint16)-1` = 65535 (`erl_init.c:843`).
- `BinRef`/`ExternalThing`/`ErlFunThing`/off-heap headers share identical `thing_word`/`next` offsets — asserted in `erts_init_gc` (`erl_gc.c:246-250`); adding a new off-heap term type requires updating those assertions and the MSO sweep switch in `sweep_off_heap` (`erl_gc.c:2989`).
- **There are TWO copiers and the default does NOT preserve sharing.** The flat copier `copy_struct_x` (`copy.c:647`, macros `copy_struct`/`copy_struct_litopt`) used by all send/spawn/ETS/message paths copies a subterm once per occurrence (a term appearing twice is copied twice); it shares only immediates, literals (and the empty-tuple global literal), refc binaries via `BinRef` refc, magic refs, and external pid/port/ref node entries. The sharing-preserving copier `copy_shared_calculate` (`copy.c:1111`) + `copy_shared_perform_x` (`copy.c:1382`, macro `copy_shared_perform`) keys sharing on the from-space term address (an `SHTABLE` + in-place marker mangling during the calculate pass), and is compiled in only under `SHCOPY` = `--enable-sharing-preserving` (`make/configure.ac:300`, OFF by default); when on, `SHCOPY_SEND`/`SHCOPY_SPAWN` (`global.h:1054-1057`) redirect `erts_send_message` (`erl_message.c:767,791`) and process spawn (`erl_process.c:12543`) to it. `erts_debug:copy_shared/2` (`beam_debug.c:169`) and `persistent_term` freezing (`erl_bif_persistent.c:749`) call the sharing copier unconditionally.
- **There is no `erts_move_msg` function.** Moving message fragments onto a process's main heap: `erts_move_multi_frags`+`move_one_frag` (`copy.c:2049,2113`, GC-style move markers for multi-fragment internal messages) and `erts_copy_one_frag` (`erl_gc.c:2513`, plain offset copy for a single fragment), both invoked from `move_msg_to_heap`/`erts_proc_sig_move_msgs_to_heap` (`erl_proc_sig_queue.c:8851`).
- `driver_select()` and `enif_select()`/`enif_select_x()` are NOT implemented here: the fd/pollset registration and the ready-event → `ERTS_PORT_TASK_INPUT`/`ERTS_PORT_TASK_OUTPUT` scheduling live in `../sys/common/erl_check_io.c` (see `../internal_doc/CheckIO.md`). This node owns the port-task queues (`erl_port_task.c`), the driver callback invocation (`ready_input`/`ready_output` in `erl_port_task_execute`), and the driver-API functions (mostly in `io.c`, but `driver_async` is in `erl_async.c`).
