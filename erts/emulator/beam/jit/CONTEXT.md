# erts/emulator/beam/jit/ — BeamAsm, the Erlang JIT

## Intent
BeamAsm: load-time conversion of BEAM instructions into native machine code, replacing the interpreter's `process_main` dispatch loop.
The loader still parses/optimizes each module as for the interpreter, but instead of writing `BeamInstr` code it calls in here, which emits x86-64 or AArch64 via the vendored asmjit library.
Only compiled when `FLAVOR=jit` (the default when `configure` reports `JIT_ENABLED=yes`, i.e. 64-bit x86/aarch64 with a C++17 compiler); otherwise `FLAVOR=emu` builds the interpreter and this directory is not compiled at all.
This directory is the source for BOTH backends plus the arch-independent glue; `../emu/` is the parallel interpreter implementation.

## API Surface
The rest of the emulator interacts with BeamAsm through two contracts:

- **C interface (`beam_asm.h`, guarded by `#if defined(BEAMASM)`)** — the only entry points called from `../beam_load.c` (via the JIT loader backend `asm_load.c` here) and the generic emulator code:
  `beamasm_init`, `beamasm_new_assembler`, `beamasm_emit`, `beamasm_emit_coverage`, `beamasm_codegen`, `beamasm_register_metadata`/`beamasm_unregister_metadata`, `beamasm_delete_assembler`, `beamasm_get_code`/`_lambda`/`_rodata`/`_header`/`_base`/`_offset`/`_on_load`, `beamasm_embed_rodata`/`_bss`, `beamasm_patch_catches`/`_import`/`_literal`/`_lambda`/`_strings`, `beamasm_emit_call_nif`, `beamasm_seal_module`/`beamasm_unseal_module`, `beamasm_flush_icache`, `beamasm_purge_module`, `beamasm_is_line_breakpoint_trampoline`.
  `beam_asm.h` also defines the inlined breakpoint-trampoline helpers (`erts_asm_bp_get_flags`/`_enable`/`_disable`/`_set_flag`/`_unset_flag`) and the per-arch prologue constants `BEAM_ASM_FUNC_PROLOGUE_SIZE` / `BEAM_ASM_NFUNC_SIZE`; all are arch-conditional (`__aarch64__`).
- **Process-main entry point `process_main(ErtsSchedulerData *)`** (defined in `beam_jit_main.cpp`) — the JIT-flavor replacement for the interpreter's scheduler loop.
- **Runtime helpers called from generated code (`beam_jit_common.hpp`, implemented in `beam_jit_common.cpp`)** — ordinary C functions the emitted native code `call`s: `beam_jit_call_bif`, `beam_jit_call_nif`, `beam_jit_load_nif`, `beam_jit_get_map_elements`, `beam_jit_bs_init_bits`/`_get_integer`/`_bit_size`/`_put_binary_all`/`_construct_fail_info`, `beam_jit_decode_dist`, `beam_jit_remove_message`, `beam_jit_int128_to_big`, `beam_jit_take_receive_lock`/`wait_locked`/`wait_unlocked`/`wait_timeout`/`timeout`, `beam_jit_return_to_trace`, `beam_jit_build_argument_list`, `beam_jit_handle_unloaded_fun`, `beam_jit_is_list_of_immediates`, `beam_jit_is_shallow_boxed`. These are the seam where the JIT touches the generic runtime.
- **Opcode-table contract with `../../utils/beam_makeops`** — invoked with `-jit yes`, it reads `$(JIT_ARCH)/ops.tab|predicates.tab|generators.tab` (plus the shared `../ops.tab|predicates.tab|generators.tab`) and emits:
  - `$(TTF_DIR)/beamasm_emit.h` — a `switch (specific_op)` that calls `emit_<opname>(args[i], ...)`; included by `$(JIT_ARCH)/beam_asm_module.cpp`.
  - `$(TTF_DIR)/beamasm_protos.h` — `void emit_<opname>(const ArgXRegister&, ...)` prototypes; included by `$(JIT_ARCH)/beam_asm.hpp`.
  - `beam_opcodes.{c,h}` with the `opc[]` table used by `BeamModuleAssembler::emit`.
  An instruction therefore only works if `ops.tab` names it AND a matching `emit_<name>` method exists (name is derived from the op, not chosen freely).
- **Generated global-fragment header** — `$(TTF_DIR)/beam_asm_global.hpp` is produced by `perl $(JIT_ARCH)/beam_asm_global.hpp.pl`; it declares the `BeamGlobalAssembler::GlobalLabels` enum, the `labelNames`/`emitPtrs` maps and the `get_*()` accessors, and is included by `$(JIT_ARCH)/beam_asm.hpp`.
- **`load.h`** — `LoaderState_` (the JIT/loader shared state struct, incl. the opaque `void *ba` assembler handle) and `Label`/`LineInstr`.

## Constraints
- Arch-specific code MUST live in `x86/` or `arm/`; the top-level `.cpp`/`.hpp` are arch-independent and compiled for both flavors. Only the configured `$(JIT_ARCH)` backend is compiled (sources taken from `beam/jit/$(JIT_ARCH)/*.cpp`); `-Ibeam/jit -Ibeam/jit/$(JIT_ARCH)` is added to includes for `FLAVOR=jit`.
- Both backends must stay functionally in sync: they have the SAME set of `instr_*.cpp` files and parallel `ops.tab`/`predicates.tab`/`generators.tab`, and any new instruction must be implemented for x86 and arm.
- This is the ONLY clang-formatted part of the emulator; `clang-format` runs over exactly `beam/jit/*.hpp *.c *.h *.cpp` and `beam/jit/*/*.cpp */*.hpp`, configured by the checked-in `.clang-format` (LLVM-based, 4-space indent, 80 columns, 8-space continuation).
- New instructions are added in the `.tab` files + a new `emit_<name>` method; do NOT hand-write dispatch tables.
- Do not create a third backend directory ad hoc; a new architecture needs asmjit support and passing `JIT_ARCH`/`JIT_ENABLED` detection in `../Makefile.in`/configure.
- Requires a C++17 compiler; the emulator uses asmjit's Assembler API only (a small subset).

## Design Decisions
- **C++ + asmjit rather than LLVM or hand-written codegen**: asmjit offers ~1:1 C++→asm mapping and abstracts x86/AArch64 encoding, letting one instruction be one `emit_*` method that calls `a.mov(...)`, `a.jmp(...)`, etc. asmjit is a static lib built from the vendored copy (see Dependencies). Choosing asmjit over LLVM (used by the earlier abandoned tracing-JIT prototypes) is deliberate: this is load-time, mostly one-instruction-at-a-time translation, so LLVM's compile latency is not repaid by its optimizations, whereas a lightweight assembler keeps load time low; a hand-rolled backend was rejected because the common library alternatives were either inflexible or GPL-licensed.
- **Shared `BeamGlobalAssembler` fragments** are the main code-size lever: common sequences (GC, dispatch/return, error raising, export trampoline, breakpoint trampolines, NIF calls) are emitted ONCE per VM and jumped to from every module, keeping loaded-code size ~10% above the interpreter. `beam_jit_main.cpp` owns the single `bga`/`bma`/`jit_allocator` instances and also builds a tiny "erts_beamasm" module for the special instruction targets (`beam_run_process`, `beam_exit`, `beam_export_trampoline`, ...).
- **Static register allocation**: x/y/x-float state lives in the `ErtsSchedulerRegisters` struct pointed at by a fixed callee-saved register (x86: `rbx`), with `rbp`/`r12`–`r15` holding stack/ptr/reductions/heap/etc.; caller-saved regs are scratch. See `../../internal_doc/BeamAsm.md`.
- **`beam_jit_register_cache.hpp`** — a small, templated `RegisterCache<Size, Mem, Reg>` that avoids reloading BEAM x/y registers already resident in machine registers within a straight-line sequence; instantiated per-arch (x86: 20 entries, temporaries list, `registers`/`E` bases; arm: 16 entries, `scheduler_registers`/`E` bases). `preserve_cache`/`load_cached`/`store_cache`/`mov_preserve_cache` in `$(JIT_ARCH)/beam_asm.hpp` are the guarded accessors.
- **`beam_jit_types.hpp`** — a type-safe `BeamTypeId` (`enum class`) wrapper over `beam_types.h` BFs, with `static_assert`s that reject overlapping/ambiguous type-mask usage (`always_one_of`, `exact_type`, `masked_types`). These drive per-instruction specialization from the loader's type info.
- **Bit syntax is arch-independent and shared**: `beam_jit_bs.hpp/.cpp` implement the segment analysis/optimization (`BscSegment` for construction, `BsmSegment` for matching, `beam_jit_bsc_init/_combine_segments`, `beam_jit_bsm_init`, `beam_jit_opt_bsm_segments`) that each backend's `instr_bs.cpp` consumes and turns into native sequences.
- **W^X-safe code memory**: `JitAllocator` allocates dual-mapped (executable + writable alias) memory by default; `beamasm_seal_module`/`unseal_module` switch protection and `+JMsingle` / valgrind / Apple-aarch64 force single-mapped RWX. `beamasm_flush_icache` handles per-OS/per-arch I-cache invalidation (manual on aarch64 GNU/Linux, `sys_icache_invalidate` on Apple, `FlushInstructionCache` on Windows).
- **Breakpoints / NIF loading via a per-function trampoline**: instead of rewriting an instruction as the interpreter does, each function starts with a short-jump/NOP that can be rerouted (by patching one byte/word) to a shared fragment; see `beam_asm.h`.

## GC & Root Set (JIT ↔ collector contract)
- **Memory register model preserved.** The JIT keeps BEAM's `x`/`y` registers in memory: `x` in `ErtsSchedulerRegisters.x_reg_array`, `y` on the Erlang stack. `registers` (x86 `rbx`) points at `x_reg_array`; `load_x_reg_array()` copies that pointer into the `reg` argument of `erts_garbage_collect_nobump` (`x86/beam_asm.hpp:109-111,293-296`; `x86/beam_asm_global.cpp:127-133`). The collector's root set for the running process is therefore `x_reg_array[0..Live)` plus the whole Erlang stack (`E`/`Process.stop` .. `Process.hend`). There are NO per-frame GC descriptors: GC scans the stack as a flat word vector (`y` slots + CPs), and the `Live` x-register count is a compile-time instruction operand, not metadata.
- **No hidden CPU-register roots on x86**: `RegisterCache` (`beam_jit_register_cache.hpp`) is a straight-line write-through reload cache keyed on code offset; every BEAM-register write goes to memory first (`store_cache`) and the cache is invalidated at each label/code-offset boundary (`consolidate`/`validAt`), so no term lives only in a CPU register across a GC.
- **arm keeps `x` registers 0-5 in CPU registers** (`x25,x26,x27,x28,x15,x16`, `num_register_backed_xregs`, `arm/beam_asm.hpp:100-139`). They MUST be flushed to `x_reg_array` before entering the runtime (GC / any C call): `emit_enter_runtime<...eXRegs>` does this (`arm/beam_asm.hpp:461-537`) and the GC fragment always calls it with `eXRegs`; within instructions `flush_var(s)` writes them out (`arm/beam_asm.hpp:1716+`). Missing a flush is a hidden-root bug.
- **GC entry fragment** (`GlobalLabels::garbage_collect`, via `get_garbage_collect()`): `BeamGlobalAssembler::emit_garbage_collect()` — `x86/beam_asm_global.cpp:100-152`, `arm/beam_asm_global.cpp:97-134`. Converts ARG3 (`HTOP + S_RESERVED + bytes`) to words, stashes the return address in `c_p->i`, `emit_enter_runtime<eStack|eHeap[,|eXRegs]>`, sets ARG1=`c_p`, `load_x_reg_array(ARG3)`, ARG4=`Live`, then `erts_garbage_collect_nobump(c_p, need, reg, Live, FCALLS)`; `emit_leave_runtime`, and jumps to `do_schedule` if `ERTS_PSFLG_EXITING`.
- **Allocation check = the inline `HAlloc` equivalent** (`emit_gc_test`/`emit_gc_test_preserve`): `lea ARG3,[HTOP + (Ns+Nh+S_RESERVED)*8]; cmp ARG3,E; jbe skip; mov_imm ARG4,Live; fragment_call(ga->get_garbage_collect())` (`x86/instr_common.cpp:109-175`; `arm/instr_common.cpp:90-158`). `S_RESERVED`/redzone reserves room for the return address + trace handler (`internal_doc/BeamAsm.md:148-159`). DEBUG builds poison `x` regs ≥ Live with `ERTS_HOLE_MARKER`. Callers: `emit_allocate_heap`/`emit_test_heap` (the `allocate`/`allocate_heap`/`test_heap` ops), `bs_*` (`x86/instr_bs.cpp:185,461,514,582,1761,3263`), map (`x86/instr_map.cpp:277`), native records (`x86/instr_records.cpp:205`), and the line-breakpoint prologue (`x86/beam_asm_module.cpp:258-288`).
- **GC after BIF/NIF**: inline `ERTS_IS_GC_DESIRED_INTERNAL` test (`F_FORCE_GC|F_DISABLE_GC`, `bin_vheap_sz` vs `off_heap.overhead`, `mbuf_sz` vs remaining heap) → `erts_gc_after_bif_call_lhf` (`x86/instr_bif.cpp:537-638`; `arm/instr_bif.cpp:488-567`; trap path `beam_jit_common.cpp:622-627,678-684`, plus `test_bin_vheap`/`gc_test` → `erts_garbage_collect_nobump` `:779-800`).
- **GC-aware map fragments** call `erts_gc_new_map`/`erts_gc_update_map_assoc`/`erts_gc_update_map_exact` directly from shared fragments (`x86/instr_map.cpp:240-253,568-656`).
- **No write barrier.** BEAM has no generational write barrier / card marking / remembered set and the JIT emits none; the collector is copying and relies on term immutability (no old→young pointers). The only "barrier" code in `beam/jit/` is instruction/memory barriers around code patching in `beam_jit_main.cpp` — unrelated to GC.
- **No `F_NEED_FULLSWEEP` handling**: fullsweep is decided inside `erts_garbage_collect`; the JIT never inspects the flag.
- **Return-address (CP) metadata**: the JIT builds function/line tables (`finish_line_table`, `asm_load.c:795-869`) and registers code ranges (`erts_update_ranges`, `asm_load.c:1172`) so stack *tracing* can resolve a CP → `ErtsCodeInfo`/line info. This is not used by GC (see above); CPs are raw word-aligned code pointers recognised by `is_CP`.

## List / Cons-cell Handling (quick reference)
Cons cell = 2 consecutive heap words: `CAR(c)=c[0]`, `CDR(c)=c[1]` (`../erl_term.h:243-244`); a list term is the cell address OR-ed with `TAG_PRIMARY_LIST` (0x1), so `list_val(p) == p - TAG_PRIMARY_LIST` (`../erl_term.h:73,235`); `NIL` is the immediate `0x3B` (`../erl_term.h:293`).
- **Accessors (both backends, inline)**: `getCARRef(Src)` = `Mem(Src, -TAG_PRIMARY_LIST)` and `getCDRRef(Src)` = `Mem(Src, -TAG_PRIMARY_LIST + sizeof(Eterm))` (`x86/beam_asm.hpp:276-284`, `arm/beam_asm.hpp:268-275`) — CAR at untagged offset 0, CDR at `sizeof(Eterm)` (8 bytes on 64-bit). `emit_ptr_val` only strips `TAG_LITERAL_PTR` (when defined); it deliberately keeps the primary tag.
- **Cons test**: bit 1 (`_TAG_PRIMARY_MASK - TAG_PRIMARY_LIST`) via `emit_test_cons`/`emit_is_cons`/`emit_is_not_cons` — x86 `test`+`jne` (`x86/beam_asm.hpp:887-907`), arm `tbnz`/`tbz` bit 1 (`arm/beam_asm.hpp:618-630`).
- **All CAR/CDR reads/writes are INLINE raw loads/stores**, never C helpers: `emit_get_list`/`emit_get_hd`/`emit_get_tl` (`x86/instr_common.cpp:353-386`, `arm/instr_common.cpp:274-317`), the `is_nonempty_list_get_{list,hd,tl}` fusions (`x86/instr_common.cpp:388-422`), `emit_bif_hd` (`x86/instr_guard_bifs.cpp:531-547`, `arm/instr_guard_bifs.cpp:773-792`), the `=:=` list walkers `emit_is_eq_exact_list_shared` (`x86/instr_common.cpp:1745-1774`, `arm/instr_common.cpp:1701-1731`), and the `apply/2` arg-list unpacker (`x86/instr_fun.cpp:291-311`, `arm/instr_fun.cpp:277-295`). List *segments* in bit syntax are handled in C (`beam_jit_bs_*`), not by cons reads here.
- **Construction is inline too**: `emit_put_cons` writes Hd/Tl to `[HTOP]`/`[HTOP+sizeof(Eterm)]` and tags `ARG2 = HTOP | TAG_PRIMARY_LIST` (`x86/instr_common.cpp:768-806`); arm `stp` then `sub dst,HTOP,#(2*word - TAG_PRIMARY_LIST)` (`arm/instr_common.cpp:707-721`). `emit_store_cons`/`emit_put_list2`/`emit_put_list_deallocate` bump HTOP by `Len*2` words. `combine_conses`/`append_cons` are the list-builder peephole (`x86/ops.tab:494-506`, `x86/generators.tab:389-407`). `put_list` emits NO heap check itself — the compiler guarantees a preceding `test_heap`/`allocate_heap` reserving 2 words (`../../../../lib/compiler/src/beam_ssa_codegen.erl:423`).
- **`length/1` is NOT inline**: guard and body are both special-cased to the trapping C helper `erts_trapping_length_1` (`x86/instr_bif.cpp:235-379`, `arm/instr_bif.cpp:198-330`; C impl `../erl_bif_guard.c:270-313`), which walks the list with the C term macros.
- **C-side helpers called from generated code**: `beam_jit_is_list_of_immediates` (`beam_jit_common.cpp:1371-1380`) and `beam_jit_build_argument_list` (`beam_jit_common.cpp:1296-1309`, `HAlloc` + `CONS`, 2 words/cons).
- **Type/assume info** never assumes a cons *layout*: ops specialize on `BeamTypeId::{List,Cons,Nil}` only to skip the NIL/cons test (e.g. arm `emit_is_nil` `arm/instr_common.cpp:1422-1428`; `exact_type<BeamTypeId::Cons>` in `emit_is_eq_exact`, x86:1849). There is NO `is_nonempty_list_maybe` opcode anywhere in the tree.

## Loader validation inventory (`asm_load.c` — the JIT loader backend)
Container-level validation belongs to `../beam_file.c` (`LoadAssert`/`LoadError` → "corrupt …" messages: chunk tags/sizes, atom/literal/type/register/arity/label ranges) and to `../beam_load.c:185-225` (module-name match, `max_opcode > MAX_GENERIC_OPCODE` / too-old-file). This directory only re-checks what the opcode/transform pipeline and the JIT's own tables depend on, and it rejects **exclusively** through `BeamLoadError0/1/2/3` (`../beam_load.h:77-99`) or a bare `beam_load_report_error` + `return 0`. Message envelope: `"<file>(<line>): Error loading [function M:F/A | module M][: op <name>][: <sign>]:\n  <fmt>\n"` (`../beam_load.c:372-415`; suppressed entirely when the module is a non-value, i.e. the `code:get_chunk/2` path).
Rejection sites (`asm_load.c`): duplicate lambda (`:157`), per-sign operand checks in `beam_load_emit_op` (`:381-576`), unknown primitive type (`:616`), too many functions (`:625`), too many arguments (`:637`), `beamasm_emit` failure (`:665`, unreachable — `emit()` always returns true), line-index/table overflow (`add_line_entry` `:328/:336`, callers `:674/:681/:690/:730`), debug_line index (`:719`), too few functions (`:741`), bad external-term attributes/compile-info (`:1086/:1103`).
`x86/`+`arm/` `instr_*.cpp` contain **no rejection path** and `beam_jit_main.cpp` none either; the only load-time failure modes there are aborts (see next section).

## Known loader gaps (reject-by-crash, or no check at all)
- No "label N not resolved" check, unlike the interpreter loader (`../emu/emu_load.c:492-497`): a referenced-but-never-defined label only trips the DEBUG-only "all labels bound" loop (`beam_jit_common.cpp:98-111` → `erts_exit(ERTS_ABORT_EXIT, "Label is not bound")`). In an `opt` build `ERTS_ASSERT` (always compiled in — `../sys.h:261`) on `code.flatten()`/`resolve_cross_section_fixups()` (`beam_jit_common.cpp:92-96`) aborts the VM via `erl_assert_error`→`abort()` instead of returning a load error.
- Export/locals label numbers are never range-checked: `../beam_file.c:374` only asserts `label >= 0` (lambda entries do check `:429`), and `beam_load_finalize_code` (`asm_load.c:1185`) feeds them straight to `beamasm_get_code` → `BeamModuleAssembler::getCode` (`x86/beam_asm_module.cpp:73-76`, `arm/…:74-77`), whose only guard is the DEBUG-only, off-by-one `ASSERT(label < rawLabels.size() + 1)` (correct bound is `< rawLabels.size()`). `rawLabels` is `resize(num_labels + 1)` with slots `0` and `num_labels` left as *invalid* asmjit Labels (`beam_jit_common.cpp:281,350-355`), so an out-of-range/undefined export label means an OOB `rawLabels[]` read and `getCode(Label)` on an invalid label (its `ASSERT(label.is_valid())` is at `beam_jit_common.cpp:143`).
- `op_i_debug_line_IIt`: `Sint index = a[1].val - 1` is only tested for `index >= item_count` (`asm_load.c:717-724`), so index `0` gives `-1` → `items[-1].location_index` OOB write.
- `ASSERT(stp->lambda_literals[i] != ERTS_SWORD_MAX)` (`asm_load.c:1231`) is DEBUG-only: a `num_free == 0` lambda whose fun literal is missing from the literal chunk indexes `beamfile_get_literal` with `0x7FFF…` → OOB.
- `emit_i_debug_line`'s `ASSERT(Live.get() <= MAX_ARG)` (`x86/instr_common.cpp:3379`) is DEBUG-only, so an oversized `Live` operand reaches GC as a bogus root count.
- Coverage writes use `function_number - 1` / `current_li - 1` unguarded (`asm_load.c:699,762,768`); latent only because `i_`-prefixed ops are not file-decodable (`../beam_file.c:2295` bounds opcodes by `MAX_GENERIC_OPCODE`).
- Trailing garbage after `int_code_end` is silently tolerated: `../beam_load.c:656-671` breaks out of the emit loop on `specific_op == -1` and closes the reader without reading further.

## Known Issues / Gotchas
- **Generated — do not edit**: `beam_asm_global.hpp` (from `$JIT_ARCH/beam_asm_global.hpp.pl`), `beamasm_emit.h`, `beamasm_protos.h`, `beam_opcodes.{c,h}`, `beam_hot/warm/cold.h` are produced by `beam_makeops`/perl into `$(TTF_DIR)`. Edit the `.tab`/`.pl` sources, never the output.
- `beam_asm_global.cpp` includes `beam_asm_global.hpp` twice-once via a macro trick: it `#define ERTS_BEAM_ASM_GLOBAL_WANT_STATIC_DEFS` before including `beam_asm.hpp` so the static map definitions are emitted in this TU only.
- `../../internal_doc/BeamAsm.md` "Description of each file" lists `$ARCH/beam_asm.cpp` — that file does NOT exist; init and the C↔C++ interface live in the top-level `beam_jit_main.cpp`. The doc's file list is otherwise a good map.
- Cross-compilation copies ALL asmjit headers into `$(TTF_DIR)/asmjit/` and compiles beam/jit sources with a precompiled header (`-x c++-header -include $(TTF_DIR)/asmjit/core.h`); `ASMJIT_PCH_OBJ`/`ASMJIT_PCH_SRC` rules are in `../Makefile.in`. Missing/renamed asmjit headers break this PCH path.
- x86 and arm diverge in real ways: arm needs veneers (`bind_veneer_target`) for out-of-range branches, has its own `ops.tab` entries, and its `BeamAssembler::GetArgReg`/register set differs; a naive copy between backends can be wrong.
- x86 `ops.tab` sets `FORBIDDEN_TYPES=hQ`; also `h`/`q` type operands are never allowed in specific ops. The `.tab` files use the shared beam_makeops mini-language (`=>`, `|`, predicates, `gen.*` generators, `$NewBeamOp` etc.).
- `emit_*` methods use asmjit `Label`s plus a fragment resolution mechanism (`resolve_fragment`, `_dispatchTable` thunks mapping `void(*)()` fragments to labels); calling a raw C function is done via `runtime_call<...>()` which also handles the enter/leave-runtime stack swap and (for x86) the simulated ABI.
- `ERTS_JIT_ABI_WIN32` can be defined on non-Windows to emit Windows-convention calls, which is the supported way to debug Windows-JIT-only bugs on Linux.
- Breakpoint-trampoline patching does exact opcode asserts (e.g. x86 `0xEB 0x06 0x90 0xE8`); changing prologue emission without updating `beam_asm.h` breaks tracing/NIF loading.
- The `x86/` and `arm/` opcode encodings differ for the same logical instruction, so pass/fail of one backend says nothing about the other — both must be tested.
- The arm register-backed `x` registers (see the GC section) are a hidden-root hazard: any code path that clobbers `x25-x28`/`x15-x16` outside the `x`-register API must `flush_var(s)` them before a GC or C call. x86 has no such hazard (its `RegisterCache` is write-through).

## Dependencies
- **asmjit**, vendored at `../../asmjit/` (built as a static lib); pinned commit in `../../asmjit.version` (`5fe1940275d04432da841896bac0a66cc2375551`). Built with `ASMJIT_EMBED=1 -DASMJIT_STATIC=1 -DASMJIT_NO_BUILDER -DASMJIT_NO_COMPILER -DASMJIT_NO_UJIT -DASMJIT_NO_DEPRECATED -DASMJIT_NO_FOREIGN`.
- A C++17 compiler and a 64-bit x86-64 or aarch64 target; two ABIs supported (System V and Win32).
- Optional: Linux `perf` (via `HAVE_LINUX_PERF_SUPPORT`, enabled by `+JPperf`), GDB JIT interface (`__jit_debug_register_code`, non-Windows/non-Apple), valgrind/asan flavors.

## Test Strategy
- There are NO tests inside this directory; they live in `../../test/` (erts/emulator/test).
- `../../test/jit_SUITE.erl` covers JIT-specific machinery: `perf` group (symbols, perf-map/annotate, `+JPperf` perf-directory handling), `+JMsingle`, named labels; it skips unless `erlang:system_info(emu_flavor) == jit`.
- Differential JIT-vs-interpreter testing is done by running the general emulator suites under both flavors via `-emu_flavor emu` / `erlang:system_flag(emu_flavor, ...)` (see e.g. `bs_match_int_SUITE`, `native_record_SUITE`, `erl_debugger_SUITE`).
- Exercise C-level JIT paths with `TYPE=debug` (+ `JIT_HARD_DEBUG`), `TYPE=valgrind`, `TYPE=asan`; ``make FLAVOR=emu`` / `--disable-jit` builds the interpreter for comparison, and both flavors can coexist.

  - `beam_jit_metadata.cpp` (~599) → GDB JIT interface + Linux `perf` JIT dump/map (`+JPperf`)
