# erts/emulator/ — BEAM Virtual Machine

## Intent
The BEAM virtual machine: the C/C++ program that executes Erlang code, plus its OS-integration layer, built-in drivers/NIFs, vendored third-party libraries, opcode code generators, VM test suites and internal design docs.
This directory is the sole producer of `$ERL_TOP/bin/$(TARGET)/beam*`, the executable that the `erl` shell script ultimately execs.
`Makefile.in` (~1600 lines) is the real, hand-edited build description; the sibling `Makefile` is generated by configure and is a thin wrapper around `$(ERL_TOP)/make/run_make.mk` + `$(ERL_TOP)/make/app_targets.mk`.
Sibling areas: `../lib_src/` (runtime support C libs), `../preloaded/` (Erlang modules linked into the VM), `../etc/` (launchers), `../include/`, `../epmd/`, `../doc/`.

## API Surface
Artifacts this node produces:
- **Emulator executable** `$(ERL_TOP)/bin/$(TARGET)/beam[$(TYPEMARKER)][.$(FLAVOR)]` — e.g. `beam.jit`, `beam.emu`, `beam.debug.jit`. When `FLAVOR` equals the configure result `@PRIMARY_FLAVOR@` the same binary is also produced under the canonical `beam$(TYPEMARKER).smp` name (`beam.smp`, `beam.debug.smp`). Win32 uses `.dll`/`.pdb`.
- **`libbeam.a` / `libbeam.lib`** (`EMULATOR_LIB`) — the emulator objects as an archive; installed into `erts-$(VSN)/lib` only when `RELEASE_LIBBEAM=yes`.
- **`erl_child_setup[$(TYPEMARKER)]`** (`UNIX_ONLY_BUILDS`, unix only) — helper process that spawns ports without forking the VM.
- **`beam.prof[$(TF_MARKER)]`** — the PGO-instrumented executable built when `PROFILE=generate`.
- **Installed public C API headers** (`release_spec` → `$RELEASE_PATH/usr/include` and `erts-$(VSN)/include`): `beam/erl_driver.h`, `beam/erl_nif.h`, `beam/erl_nif_api_funcs.h`, `beam/erl_drv_nif.h`, `sys/$(ERLANG_OSTYPE)/driver_int.h` (+ `sys/win32/erl_win_dyn_driver.h` on win32); `beam/erl_internal_test.h` → `include/internal`.
- **Preloaded-module blob**: `utils/make_preload` packs the `PRELOAD_BEAM` list into `preload.c` (unix) / `beams.rc` (win32), linked into the binary so a bootstrapped VM needs no files on disk.
- **Static driver/NIF registration**: generated `driver_tab.c` (`utils/make_driver_tab`) wires `drivers/` and `nifs/` into the VM (consumed by `beam/io.c`, `beam/erl_nif.c`).

Targets defined by `Makefile.in`:

| target | purpose |
| --- | --- |
| `all` (default) | executable + `libbeam` + `erl_child_setup`, then `ignore_cores` |
| `generate` | run all code generators; writes the `$(TTF_DIR)/GENERATED` stamp |
| `depend` | emit `$(TTF_DIR)/*.depend.mk` (`-include`d at the end of Makefile.in) |
| `test` | from `make/app_targets.mk` → `$(ERL_TOP)/make/test_target_script.sh` |
| `release_spec` / `release_docs_spec` | install into the release tree (`otp_release_targets.mk`) |
| `clean` | remove `$(GENERATE)`, `$(TARGET)/*`, `obj/$(TARGET)`, the 3PP obj dirs, then recurse into `../lib_src` |
| `compdb` | emit `clang -MJ` JSON fragments per source group; root `make compdb` concatenates them into `$ERL_TOP/compile_commands.json` |
| `format` / `format-check` | `clang-format` over `beam/jit/**` ONLY |
| `update_asmjit` | re-vendor asmjit from upstream (needs network + git; never run) |
| `check_emu_registers` | manual/unix: assert no `process_main` variable spills to `%rsp` |
| `docs` | intentionally empty — ERTS docs are built from `../doc/` |
| `info`, `gclean`, `dclean`, `dialyzer*` | inherited from `make/app_targets.mk` |

Driven from `ERL_TOP`: `make emulator`, `make emulator_test`, `make compdb`, `make format`, `make format-check`, `make depend`.

## Constraints
### The FLAVOR × TYPE matrix (the dominant build variable)
- `FLAVOR` ∈ {`jit`, `emu`}; defaults to `jit` iff the configure result `JIT_ENABLED=yes` (`JIT_ARCH` = `x86` or `arm`), otherwise `emu`. `make FLAVOR=jit` errors out if JIT was not configured.
- `TYPE` ∈ {`opt` (default), `debug`, `lcnt`, `valgrind`, `asan`, `gprof`, `frmptr`, `icount`, `gcov`}; each selects `TYPE_FLAGS` and a `TYPEMARKER` (`.debug`, `.gcov`, `.valgrind`, `.asan`, `.gprof`, `.lcnt`, `.frmptr`, `.icount`, empty for `opt`) that suffixes every artifact name.
- `PROFILE` ∈ {``, `generate`, `use`} adds `PROFILE_MARKER` (`_pg`/`_pu`) for PGO.
- All generated code and objects are per-flavor/type: `TTF_DIR = $(TARGET)/$(TYPE)/$(FLAVOR)`, `OBJDIR = obj/$(TTF_DIR)`. The same source is legitimately compiled into several of these trees, so which `config.h`/generated headers you see depends on the tree you inspect.
- Adding a new `TYPE` also requires updating `ERL_BUILD_TYPE_MARKER` in `sys/unix/sys_drivers.c`.
- `DIRTY_SCHEDULER_TEST=yes` → `-DERTS_DIRTY_SCHEDULERS_TEST` and `make_tables -dst yes`.

### Generated files — never edit
`$(TTF_DIR)/`: `beam_opcodes.{c,h}`, `beam_hot/warm/cold.h`, `beamasm_emit.h`, `beamasm_protos.h`, `beam_asm_global.hpp`, `erl_bif_table.{c,h}`, `erl_bif_list.h`, `erl_atom_table.{c,h}`, `erl_guard_bifs.c`, `erl_dirty_bif_wrap.c`, `erl_alloc_types.h`, `erl_compile_flags.h`, `driver_tab.c`, `erl_map.ycf.h`, `utils.ycf.h`, `erl_db_insert_list.ycf.h`, `preload.c`/`beams.rc`, `erl_poll.flbk.c`, and copies of the asmjit headers.
`$(TARGET)/`: `config.h`, `erl_version.h`, `erl_git_version.h` (rewritten on every make run), `erlang_dtrace.h`, plus the configured `Makefile`.
Edit the tracked generator *inputs* instead: `beam/{bif.tab,erl_dirty_bif.tab,atom.names,erl_alloc.types,predicates.tab,generators.tab,erlang_dtrace.d}` and every `*.tab` under `beam/emu/` and `beam/jit/{x86,arm}/`.

### Other
- Never hand-edit the configure output `Makefile`; `Makefile.in` is a plain `@VAR@`-substituted input, so no autoconf regeneration is involved.
- Vendored 3PP (`asmjit/`, `pcre/`, `ryu/`, `zlib/`, `zstd/`) is not OTP code: do not modify it, do not `clang-format` it, update only via its documented updater.
- Code must be warning-clean in every supported `FLAVOR`×`TYPE` combination (`WFLAGS` differ per type).

## Design Decisions
- **One source tree, two execution engines.** `beam/emu/` (portable C interpreter) and `beam/jit/` (BeamAsm, C++ on asmjit, x86_64/aarch64) implement the same opcode semantics; the instruction set is defined once in `.tab` files consumed by `utils/beam_makeops`. JIT is the default on supported platforms; the interpreter is the fallback and the semantic reference.
- **Opcode metamodel.** `lib/compiler/src/genop.tab` + `beam/predicates.tab` + `beam/generators.tab` + the flavor's `ops.tab` are the single source of truth; `beam_makeops` emits both the interpreter's code and the JIT's emit switch/prototypes. The compiler and the emulator share that generator.
- **OS differences are expressed by directory, not by `#ifdef`.** `drivers/{common,win32}`, `nifs/{common,unix,win32}`, `sys/{common,unix,win32}`; `ERLANG_OSTYPE` selects the OS subtree and cross-platform code lives in `common/`.
- **Third-party code is vendored and swappable.** Vendored copies keep the build hermetic; `--enable-builtin-ryu|zstd|zlib` (and `--enable-use-embedded-3pp-alternatives`) select system libraries instead. PCRE2 is always built from `pcre/` (no system alternative).
- **Yielding C functions.** `../lib_src/yielding_c_fun` source-to-source rewrites selected functions of `beam/erl_db.c`, `beam/erl_map.c`, `beam/utils.c` so long-running BIF work can trap/yield; it is built before the emulator and also shipped in `bootstrap/`.
- **PGO is a first-class build mode.** `PROFILE=generate` builds `beam.prof*` and runs `test/estone_SUITE` as the training workload; `PROFILE=use` rebuilds with the profile data. Top-level `make` drives this via `USE_PGO`.
- **Source→object wiring is explicit, not globbed.** What gets compiled is the explicit object lists in `Makefile.in` (`COMMON_OBJS`, `RUN_OBJS`, `JIT_OBJS`/`EMU_OBJS`, `OS_OBJS`, `NIF_OBJS`, `DRV_OBJS`, `ESOCK_*_OBJS`, `INIT_OBJS`, `CS_OBJ`, `LTTNG_OBJS`), not the `wildcard` vars — `BEAM_SRC`/`DRV_{COMMON,OSTYPE}_SRC`/`NIF_{COMMON,OSTYPE}_SRC`/`SYS_SRC`/`TARGET_SRC` feed only the `depend` and `compdb` targets. A `.c` file present in the tree but absent from the object lists is silently unbuilt; `beam/check_dead_sources.py --root erts` (STRICT tier, transitive closure) is the mechanical way to find such files. Deleting a `.c` therefore requires removing its `.o` from the explicit list. Exceptions: `asmjit/` (`ASMJIT_CPP`) and `zstd/` (`ZSTD_SRC`) sources are wildcarded, so deletions there auto-adjust; `pcre` (`PCRE_O`), `zlib` (`ZLIB_FILES`) and `ryu` (`RYU_FILES`) are explicit lists in their own `*.mk`.
- **The emulator is the first thing built in a bootstrap** — it depends only on `../lib_src` and the preloaded beams, not on `lib/*`.

## Known Issues / Gotchas
- A clean checkout has NO generated C/headers. "Missing" files such as `erl_bif_table.c`, `beam_opcodes.c`, `erl_alloc_types.h`, `beamasm_emit.h` or `config.h` are produced by configure + `make generate`; without a configured tree most sources cannot even be parsed.
- Build-output trees `$(TARGET)/`, `obj/` and `../bin/` are git-ignored and empty in a clean checkout — do not look for code there.
- `sys/common/erl_poll.c` is compiled twice when `ERTS_BUILD_FALLBACK_POLL=yes` (kernel-poll build vs. the `$(TTF_DIR)/erl_poll.flbk.c` fallback copy built with `-DERTS_NO_KERNEL_POLL_VERSION`).
- `test` here does NOT set `TEST_NEEDS_RELEASE` (unlike `erts/`), so emulator suites can run as soon as the emulator binary exists.
- `docs:` here is intentionally empty.
- `utils/gen_git_version` and `utils/make_compiler_flags` run as `$(shell …)` at make-parse time, so every make invocation rewrites `$(TARGET)/erl_git_version.h` / `$(TTF_DIR)/erl_compile_flags.h` in place; `$(ASMJIT_PCH_OBJ)` deliberately depends on `beam/erl_bif_info.c` so a new git SHA forces a rebuild.
- Both the flavor-marked binary (`beam.jit`/`beam.emu`) and the primary-flavor alias (`beam.smp`) land in `bin/$(TARGET)`; when in doubt check `erlang:system_info(emu_flavor)` / `emu_type`.
- Only `beam/jit/**` is `clang-format`-formatted (config: `beam/jit/.clang-format`); the rest of the emulator follows C90-ish Erlang/OTP C style. `format`/`format-check` use explicit globs — there is no `_ignored` list in this directory.
- `erts/.gitignore` still lists two generated paths inside the source tree (`emulator/beam/erl_db_insert_list.ycf.h`, `emulator/pcre/pcre2_match_loop_break_cases.inc`); the current rules write them into `$(TTF_DIR)`/`pcre/` instead — vestigial entries.

## Notes for Agents
- Read `internal_doc/` before touching scheduling, GC, tracing, code loading, ports or the opcode tables; `internal_doc/CONTEXT.md` maps document → governed sources → "read before doing X".
- To change an instruction, edit the `.tab` files (and the JIT's `instr_*.cpp` emit methods); read `internal_doc/beam_makeops.md` first. Never edit generated `beam_opcodes.*` / `beamasm_emit.h`.
- To add a driver or NIF: add the source AND add it to the explicit `DRV_OBJS`/`NIF_OBJS` lists in `Makefile.in`. The registration symbol is derived from the file base name (`foo_drv.c` → `foo_driver_entry`, `bar_nif.c` → `bar_nif_init`), so a rename silently breaks `driver_tab.c`.
- Building "just the emulator" still needs `../lib_src` (`$(ERTS_LIB)` recurses into `$(ERTS_LIB_DIR)`) and the `../preloaded` beams.
- Configure knobs that change this directory: `--enable/--disable-jit`, `--enable-builtin-{ryu,zstd,zlib}`, `--enable-use-embedded-3pp-alternatives`, `--enable-static-drivers`/`STATIC_DRIVERS`, `--enable-static-nifs`/`STATIC_NIFS`, `--disable-esock`, `--enable-dirty-schedulers`, `--enable-lock-check`, `--enable-encrypted-crash-dumps`.
- Dead-source analysis: `python3 erts/emulator/beam/check_dead_sources.py --root erts --write-report` (STRICT tier + transitive closure; report `erts/emulator/beam/dead_source_report.txt`, now tree-wide). The parity-gated removal plan and derived module order live in `beam/CONTEXT.md` `## Legacy C removal plan (parity-gated)`.

## Dependencies
- A configured tree: `erts/$(TARGET)/config.h` must exist.
- Build tools: C compiler, a C++ compiler when `FLAVOR=jit`, GNU make, Perl 5 (all code generators), POSIX sh; `git` optional (SHA header).
- Libraries: pthreads/`ethread`, librt, libm, ncurses/termcap, the configured zlib/zstd/ryu/PCRE2 or the vendored copies, optionally LTTng/DTrace, libsystemd.
- `../lib_src` must be built first; `utils/find_cross_ycf` locates `yielding_c_fun` in `bootstrap/` when cross-compiling.

## Test Strategy
- `make test ARGS="-suite gc_SUITE [-case tc]"` from here, or `make emulator_test` from `ERL_TOP`. Suites are Common Test; specs (`emulator.spec`, `emulator_smoke.spec`, `emulator_gh.spec` — the GitHub Actions subset, `emulator_bench.spec`, `emulator_trace.spec`, `emulator_node_container_SUITE.spec`) are the CI entry points. See `test/CONTEXT.md` for the suite → theme mapping.
- Deeper VM validation uses `TYPE=debug|valgrind|asan|lcnt` builds. `asan/suppress` is the LeakSanitizer suppression file (wired into `../etc/unix/cerl.src` via `LSAN_OPTIONS`); `asan/asan_logs_to_html` is an escript rendering ASAN logs produced with `ASAN_LOG_DIR` + `TS_RUN_EMU=asan`. `valgrind/suppress.standard` (+ `suppress.patched.3.6.0`) is the Valgrind suppression file used via `--suppressions=` in `cerl`.
- `test/estone_SUITE.erl` doubles as the PGO training workload (`estone_SUITE:pgo/0`).
- Coverage gap: there is no C unit-test framework; correctness is asserted through the Erlang-level suites plus the sanitizer/debug flavors.

## Routing Table
- `beam/` → VM core C sources & public headers (`erl_driver.h`/`erl_nif.h`/…), BIFs, GC, processes, ETS, allocators, code loading, distribution, tracing
  - `beam/jit/` → BeamAsm JIT (C++/asmjit) and its `x86/` + `arm/` backends, `ops.tab`/`instr_*.cpp`
  - `beam/emu/` → the C interpreter (`beam_emu.c`), `emu_load.c`, and all interpreter `.tab` files
- `drivers/` → built-in static drivers (`common/`: `inet_drv.c`, `ram_file_drv.c`; `win32/`: `registry_drv.c`)
- `nifs/` → built-in static NIFs (`common/` incl. the esock socket NIFs, `unix/`, `win32/`)
- `sys/` → OS abstraction layer: poll/check_io, mmap/mseg, timers, `main()`, ddll, `erl_child_setup`, per-OS `driver_int.h`
- `utils/` → build code generators (Perl/shell/escript): `beam_makeops`, `make_tables`, `make_preload`, `make_alloc_types`, `make_driver_tab`, `make_version`, `make_compiler_flags`, `gen_git_version`, `beam_emu_vars`, `find_cross_ycf`
- `test/` → the ~104 Common Test `*_SUITE.erl` for the VM plus the test spec files
- `internal_doc/` → authoritative VM design documents (`BeamAsm.md`, `GarbageCollection.md`, `beam_makeops.md`, …) + `assets/`
- `asan/` → LeakSanitizer suppression file + `asan_logs_to_html` log renderer (2 files + `suppress`)
- `valgrind/` → Valgrind suppression files (`suppress.standard`, `suppress.patched.3.6.0`)
- Vendored third-party (third-party copies — DO NOT modify, update only via the documented updater):
  - `asmjit/` → C++ codegen backend for the JIT (Zlib; SHA in `asmjit.version`, `make update_asmjit`)
  - `pcre/` → PCRE2 10.48 used by `beam/erl_bif_re.c` (`BSD-3-Clause`, OTP-patched for yielding; `README.pcre_update.md`)
  - `ryu/` → float→shortest-decimal (`d2s`) + STL `to_chars.h` glue (`README.ryu_update.md`, `update.sh`)
  - `zlib/` → zlib used by `beam/erl_zlib.c` and the zlib NIF (no automated updater)
  - `zstd/` → zstd used by `nifs/common/zstd_nif.c` (`update.sh`, `zstd.version`)
