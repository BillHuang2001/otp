# erts/include/ — ERTS C header export layer

## Intent
The layer of C headers that ERTS exports to the rest of the OTP tree (and, for a subset, to the
installed release). It exists so that code outside a single erts subproject — `erts/emulator/`,
`erts/lib_src/`, `erts/epmd/`, `erts/etc/`, plus `../../lib/common_test/` C test programs — can share
integer-size definitions, the ethread thread/atomic abstraction and a few runtime utility APIs.
Two tiers with different contracts:
- **semi-public** (this directory): `erl_int_sizes_config.h` (generated) and
  `erl_fixed_size_int_types.h` — installed to both `$RELEASE_PATH/usr/include` and
  `erts-$(VSN)/include`.
- **internal, explicitly unstable** (`internal/`): the ethread library and `erl_*` utility headers,
  installed only into `erts-$(VSN)/include/internal`. `internal/README` says verbatim they are
  "not for public use" and "may be changed at any time without prior notice".
This is a **header-only** tree: implementations live in `../lib_src/` (and, for the emulator's own
wrappers, `../emulator/beam/`).

**Not here (common confusion):** the user-facing NIF/driver API headers `erl_driver.h`, `erl_nif.h`,
`erl_drv_nif.h`, `erl_nif_api_funcs.h` live in `../emulator/beam/`, and `driver_int.h` /
`erl_win_dyn_driver.h` in `../emulator/sys/{unix,win32}/`. `../emulator/Makefile.in` `release_spec`
installs those to `$RELEASE_PATH/usr/include` and `erts-$(VSN)/include`, and separately installs
`../emulator/beam/erl_internal_test.h` into `erts-$(VSN)/include/internal`. Nothing in this directory
is part of the documented NIF/driver ABI.

## API Surface
- `erl_fixed_size_int_types.h` — `usgnd_int_8/16/32/64`, `sgnd_int_8/16/32/64`, `usgnd_int_max`,
  `sgnd_int_max` and the matching `*_FSTR` printf-length macros: fixed-width types independent of
  `int N_t` availability. Guards against `SIZEOF_*` mismatch by saving/undef'ing/rechecking around
  `#include "erl_int_sizes_config.h"`. **No in-tree consumer** — the file is `#include`d nowhere
  in-tree and no in-tree code references `usgnd_int_*`/`sgnd_int_*`; its only live reference is the
  install rule (`../lib_src/Makefile.in:434`, `RELEASE_INCLUDES`). It ships for out-of-tree
  embedder/driver code.
- `erl_int_sizes_config.h.in` — autoconf template (`SIZEOF_CHAR/SHORT/INT/LONG/LONG_LONG/VOID_P`).
  Configure writes `erts/include/$(TARGET)/erl_int_sizes_config.h` (AC_CONFIG_HEADERS,
  `../configure.ac:122`). Consumers: `erl_fixed_size_int_types.h`, `../../emulator/beam/erl_drv_nif.h`,
  and NIF test data. Also documented as a file end users copy alongside driver code
  (`../../lib/reltool/doc/guides/reltool_examples.md`).
- `internal/` — the ethread thread/atomic/mutex library headers, the `erl_printf.h` /
  `erl_printf_format.h` / `erl_misc_utils.h` / `erl_errno.h` runtime utilities, the per-host makefile
  fragments, and the per-architecture/per-implementation header sets. Full API surface, generated
  artefacts and install lists are documented in `internal/CONTEXT.md`.
- **Generated per-target directories** (git-ignored, absent in a clean checkout):
  `erts/include/$(TARGET)/` (from `erl_int_sizes_config.h.in`) and
  `erts/include/internal/$(TARGET)/` (`ethread_header_config.h`, `ethread.mk`, `erts_internal.mk`).
  `$(TARGET)` is the configure host triple (`x86_64-pc-linux-gnu`, `i686-pc-linux-gnu`, …) or `win32`;
  `.gitignore:40-49,81-82`.
- **Consumers / include path.** All four consumers add exactly `-I…/erts/include
  -I…/erts/include/$(TARGET) -I…/erts/include/internal -I…/erts/include/internal/$(TARGET)`:
  `../emulator/Makefile.in:882-883` (as `COMMON_INCLUDES`), `../lib_src/Makefile.in:152-154`,
  `../epmd/src/Makefile.in:41-43`, `../etc/common/Makefile.in:46-48`. `make/autoconf/otp.m4:3315`
  computes the same set as `DED_SYS_INCLUDE` for configure-time checks.
  **No C source under `../../lib/` includes these headers** — the only `lib/` reference is
  `../../lib/common_test/test_server/ts_erl_config.erl`, which reads the installed `.mk` fragments as
  data to build C test programs.
- **Install/export.** Performed by `../lib_src/Makefile.in` `release_spec` (~lines 432-481):
  `erl_int_sizes_config.h` + `erl_fixed_size_int_types.h` → `erts-$(VSN)/include` **and**
  `$RELEASE_PATH/usr/include`; `internal/` subset → `erts-$(VSN)/include/internal` (details and the
  exact list in `internal/CONTEXT.md`). `../emulator/Makefile.in:580-604` handles the NIF/driver
  headers and `erl_internal_test.h`.

## Constraints
- **Never hand-edit generated outputs.** `erl_int_sizes_config.h` and every file under
  `$(TARGET)/` are produced by `../configure` from the tracked `.in` templates (edit the `.in`, or
  edit `../configure.ac` / `make/autoconf/otp.m4` and run `./otp_build update_configure` from
  `ERL_TOP`).
- `internal/ethr_atomics.h` is tracked in git but machine-generated by
  `../lib_src/utils/make_atomics_api` — change the script and regenerate, never the file.
- Adding a header here means deciding its tier: this directory is the semi-public/exported one,
  `internal/` is the unstable one. Do not put emulator-internal headers here.
- Keep the generated `$(TARGET)` directories out of the repository (they are git-ignored by design;
  do not force-add them).

## Design Decisions
- **Semi-public root vs. unstable `internal/`.** Only two headers are exported to
  `$RELEASE_PATH/usr/include`; everything else is fenced into `internal/` with an explicit
  "may change without prior notice" README. This makes the stability boundary a *directory*
  boundary rather than a naming convention.
- **Integer sizes are configured, not assumed.** `erl_int_sizes_config.h` is a separate
  AC_CONFIG_HEADERS target from `../$(TARGET)/config.h` because driver/NIF code must be able to
  include it without pulling in the whole ERTS config; `erl_fixed_size_int_types.h` is the stable
  façade over it and self-checks for `SIZEOF_*` inconsistencies.
- **The NIF/driver API deliberately lives in `../emulator/beam/`, not here.** Those headers are the
  published ABI and are versioned/installed differently; keeping them next to the code that
  implements them avoids implying that `erts/include/` is the public include root.
- **`internal/<impl-or-arch>/` indirection** so the ethread implementation can be chosen at
  compile time by macros while include paths stay stable across GCC/MSVC/pthread builds, and so a
  port only adds a directory instead of adding `#ifdef`s to shared headers. Selection is done by
  conditional `#include` in `internal/ethread.h` — see `internal/CONTEXT.md` for the full chain.

## Known Issues / Gotchas
- **The public NIF/driver headers are not in this directory** (see Intent). Looking here for
  `erl_driver.h` / `erl_nif.h` wastes time; go to `../emulator/beam/`.
- **`internal/` is not public API** even though part of it is installed. `internal/README` governs;
  presence in `erts-$(VSN)/include/internal` is not an API commitment.
- **The `$(TARGET)` subdirectories are empty/absent in a clean checkout** — `erts/include/$(TARGET)`
  and `erts/include/internal/$(TARGET)` only exist after configure. `erl_fixed_size_int_types.h`
  cannot even be preprocessed without a configured tree.
- **Source layout ≠ installed layout**: in the release, the `.mk` fragments and
  `ethread_header_config.h` are flattened out of `internal/$(TARGET)/`, while the impl dirs keep
  their names. Paths valid in a source tree generally do not work against an installed tree.
- `erts/include/win32/` and `erts/include/internal/win32/` are the git-ignored output dirs for the
  Windows target triple — distinct from the tracked `internal/win/` (MSVC ethread headers).
- Two differently-generated headers carry overlapping macro sets: `config.h` (with
  `ETHR_HAVE_ETHREAD_DEFINES`, `ETHR_SMP_REQUIRE_NATIVE_IMPLS`) and
  `internal/$(TARGET)/ethread_header_config.h`. Grepping only this tree can miss an `ETHR_*`
  definition.

## Notes for Agents
- To find where a header goes: semi-public → here; ERTS-internal/unstable → `internal/`; NIF or
  driver ABI → `../emulator/beam/` (or `../emulator/sys/<os>/` for `driver_int.h`).
- Most of what you actually need for the ethread machinery (impl selection, per-arch dirs, generated
  files, install list, test suites) is in `internal/CONTEXT.md` — read that before grepping.
- Sizes/int-width questions trace back to `../configure.ac:122` (AC_CONFIG_HEADERS) and the
  `SIZEOF_*` AC_CHECK_SIZEOF probes, not to hand-written constants.
- Do not `git add -f` anything under a `$(TARGET)` directory.
- `internal/*.mk.in` are **makefile** fragments, not C headers — they become `internal/$(TARGET)/*.mk`
  consumed by `../lib_src/Makefile.in` and `../../lib/common_test/test_server/ts_erl_config.erl`.

## Dependencies
- A configured tree (GNU autoconf 2.72 via `make/autoconf/otp.m4`) is mandatory: header generation is
  part of `../configure`.
- C99/GNU C compiler; platform libraries only indirectly (the ethread layer's needs are documented in
  `internal/CONTEXT.md`).
- No external packages beyond what `../lib_src/` needs (libatomic_ops only if that ethread impl is
  selected).

## Test Strategy
- No test suites are owned by this directory. Coverage is indirect:
  - `../test/ethread_SUITE` and `../test/erl_print_SUITE` (plus their `*_data/` C programs, built via
    `Makefile.src` and `ts_erl_config.erl`) compile *against* these installed headers — the closest
    thing to a header smoke test.
  - `../emulator/test` and `../test` suites exercise the emulator/`lib_src` code that includes them.
  - `TYPE=debug|valgrind|asan` builds (and `ETHR_XCHK`, which `DEBUG` turns on via `ETHR_DEBUG`) are
    the practical way to exercise the `ETHR_ASSERT` paths in the ethread headers.
- A header change that breaks the include chain shows up at build time in all four consumers, not in
  a dedicated suite.

## Routing Table
- `internal/` → ERTS internal (unstable) header layer: ethread core + `erl_*` runtime utilities +
  per-host `.mk` fragments + per-arch/impl ethread headers (`gcc/`, `win/`, `libatomic_ops/`,
  `pthread/`, `x86_64/`, `i386/`, `ppc32/`, `sparc32/`, `sparc64/`, `tile/`).
  All of these are documented inside `internal/CONTEXT.md` (no per-subdirectory CONTEXT.md files).
- `erl_fixed_size_int_types.h`, `erl_int_sizes_config.h.in` → the semi-public headers described above
  (no separate CONTEXT.md needed).
- `../lib_src/` → implements everything declared in `internal/` and owns the `release_spec` that
  installs this tree (read-only from here; escalate writes to `../`).
- `../emulator/beam/` → user-facing NIF/driver headers (`erl_driver.h`, `erl_nif.h`,
  `erl_drv_nif.h`, `erl_nif_api_funcs.h`, `erl_internal_test.h`) and `erl_threads.h`, the emulator's
  wrapper over ethread (read-only; escalate writes to `../emulator/`).
- `../test/` → `ethread_SUITE`, `erl_print_SUITE` and their C data (read-only; escalate writes).
- `../configure.ac`, `make/autoconf/otp.m4` → generate the `$(TARGET)` headers and the `ETHR_*`
  substitution variables; never edit `../configure` directly.
