# erts/ — Erlang Runtime System

## Intent
Everything that is not an OTP application but is needed to run Erlang: the BEAM emulator (C/C++/assembly), the C runtime support libraries, the preloaded Erlang modules embedded in the emulator, the launcher/start scripts, the `epmd` daemon, the exported C headers (NIF/driver API) and the ERTS documentation.
`erts/` is built into the `erts` application directory `erts-$(VSN)` (see `vsn.mk`, `VSN = 17.1`) and is the last directory configured by the top-level `configure` (it depends on `make/` and all of `lib/`).
Sibling top-level areas: `../lib/` (OTP applications), `../make/` (shared build infrastructure), `../bootstrap/` (prebuilt bootstrap OTP), `../system/` (doc build), `../xcomp/` (cross-compile configs).

## API Surface
What `erts/` produces for the rest of OTP and for users:

- **Emulator binary** — `$ERL_TOP/bin/$(TARGET)/beam[<type-marker>][.<flavor>]` (e.g. `beam.smp`, `beam.jit`); the VM, produced by `erts/emulator` together with `libbeam.a`.
- **`erl_child_setup`** — helper process used to spawn ports without forking the VM (unix).
- **Launcher programs and scripts** — `$ERL_TOP/bin/{erl,cerl,escript,erlc,dialyzer,typer,ct_run,erl_call,start_erl,run_erl,to_erl,heart,inet_gethost,epmd}`. The shell scripts come from templates in `erts/etc/unix` (`erl.src.src`, `cerl.src`), the rest are C programs compiled from `erts/etc/common` and `erts/etc/unix`; `make local_setup` in `erts/` performs the templating/installation into `$ERL_TOP/bin`.
- **Boot scripts** — `$ERL_TOP/bin/start.script`, `start_sasl.script`, `start_clean.script`, `no_dot_erlang.script` (+ compiled `.boot`) generated from `erts/start_scripts/*.rel.src`.
- **Installed C headers** (`$RELEASE_PATH/usr/include` and `erts-*/include`): the NIF/driver API from `erts/emulator` `release_spec` — `erl_driver.h`, `erl_nif.h`, `erl_nif_api_funcs.h`, `erl_drv_nif.h` (from `erts/emulator/beam/`), `driver_int.h` (`erts/emulator/sys/$(OSTYPE)/`) and `erl_win_dyn_driver.h` on win32 — plus `erl_int_sizes_config.h` and `erl_fixed_size_int_types.h` from `erts/lib_src` `release_spec`. `erts-*/include/internal/` gets the ethread/printf headers (from `erts/include/internal/`) and `erl_internal_test.h` (from the emulator).
- **Static runtime libraries** — `liberts_internal` (printf/misc utils) and `libethread` (threads/atomics), built from `erts/lib_src` into `erts/lib/internal/$(TARGET)/`.
- **`erts` application** — `erts-$(VSN)/{ebin,bin,include,src,man,doc}`; `ebin/erts.app` is generated from `preloaded/src/erts.app.src`.
- **Configuration artifacts** (generated, not tracked): `erts/CONF_INFO`, `erts/$(TARGET)/config.h`, `erts/include/internal/$(TARGET)/ethread_header_config.h`, `erts/include/$(TARGET)/erl_int_sizes_config.h`.

## Constraints
- `erts/configure`/`config.h.in` are generated: edit `configure.ac` (plus `crypto.ac`) then run `./otp_build update_configure` from `ERL_TOP`. Never edit `configure` directly.
- `Makefile.in` files are the real sources; the tracked sibling `Makefile`s are thin wrappers including `$(ERL_TOP)/make/run_make.mk` (and `app_targets.mk` for the emulator), while configured per-target Makefiles are generated by configure.
- Two orthogonal build knobs (see `erts/emulator/Makefile.in`):
  - `FLAVOR` — `jit` (default where supported) or `emu` (interpreter only); selects `beam/jit/` vs `beam/emu/` and the executable/library name.
  - `TYPE` — `opt` (default), `debug`, `lcnt`, `valgrind`, `asan`, `gprof`, `frmptr`, `icount`, `gcov`; each maps to a `TYPEMARKER` appended to artifact names.
  Output goes to `$ERL_TOP/bin/$(TARGET)/` (git-ignored `bin/`) and `erts/emulator/$(TARGET)/<TYPE>/<FLAVOR>/`.
- The emulator must be buildable before `lib/*` exist in a bootstrap build — `erts/preloaded` and `erts/lib_src` are the only in-tree dependencies kept at that stage (plus `make/`).
- `erts/autoconf/` files are copies of `$ERL_TOP/make/autoconf/` master files and are auto-updated by `otp_build update_configure`; do not hand-edit.
- `crypto.ac` is the (large) OpenSSL/crypto configure fragment included from `configure.ac`.

## Design Decisions
- **Preloaded modules are compiled into the emulator binary**, not loaded from disk at boot: `erts/emulator/Makefile.in` lists `PRELOAD_BEAM` (erlang, init, erl_prim_loader, prim_*, atomics, counters, persistent_term, zlib, socket_registry, ...) and `utils/make_preload` turns them into `beams.o` (or a `.rc` resource on Windows) that is linked into the VM. Bootstrapping therefore needs no external module files.
- **`erlang.erl` is a stub**: the BIF module lives in `erts/preloaded/src/erlang.erl` but the implementations are C functions in `erts/emulator/beam/bif.c`/`bif.tab`.
- **`erts/lib_src/yielding_c_fun`** is a build-time compiler that rewrites C source into functions that can yield — the emulator's mechanism for long-running dirty BIFs/NIFs. It is both a build tool for the emulator and shipped in the bootstrap tree (`bootstrap/bin/yielding_c_fun`).
- **Cross-OS code is separated by subdirectory** rather than by many `#ifdef`s: `emulator/{drivers,nifs,sys}/{common,unix,win32[,vxworks]}`, `lib_src/{common,pthread,win}` and, for headers, `include/internal/<arch-or-impl>/`.
- **`erts/etc/` holds mostly sources and templates**: essentially all compile/link/install rules for that node live in `etc/common/Makefile.in`, including the `unix/` and `win32/` C files — a bare `make` in `etc/unix` or `etc/win32` builds almost nothing.
- **Third-party C sources are vendored** under `erts/emulator/` (`asmjit/`, `pcre/`, `zlib/`, `zstd/`, `ryu/`). `ryu`, `zstd` and `zlib` can be swapped for system libraries via `--enable-builtin-*` / `--enable-use-embedded-3pp-alternatives`; PCRE2 (`pcre/`) is always built from the in-tree copy. `erts/autoconf/vendor.info` and `emulator/asmjit.version` track the vendored packages.

## Known Issues / Gotchas
- `erts/obj/`, `erts/obj.debug/`, `erts/internal_doc/` (except `.gitignore`), `erts/lib/internal/` and `erts/emulator/*` build output trees are empty in a clean checkout — do not look for code there.
- The same logical name exists at several layers (e.g. `erts/test` vs `erts/emulator/test` vs `erts/epmd/test`); these are different test levels, not duplicates.
- `erts/Makefile` is tracked but matched by `erts/.gitignore`'s `/Makefile` rule, so **ripgrep skips it by default** — use `rg --no-ignore` when searching this directory.
- `erts/Makefile` has `.NOTPARALLEL:` — the top of the erts build is intentionally serialised while the sub-directories build in parallel.
- `erts/example/` is not built, installed or tested by the OTP build; only `example/time_compat.erl` is consumed (copied into the doc build).
- `erts/etc/unix/gdb-tools/` is not in the repository — it is fetched by `./otp_build download_gdb_tools` (version pinned in `make/gdb_tools_vsn`).
- **In-sandbox build verification is blocked.** From a clean checkout `erts/configure` first aborts because `$CONFIG_SHELL` names a nonexistent path (workaround: `env -u CONFIG_SHELL`) and then at `No curses library functions found` — no termcap/curses library is on the linker search path (that check is skippable with `--without-termcap`). No full `erts` configure/compile has been run in this sandbox, so dead-source/removal verdicts (see `emulator/beam/CONTEXT.md` `## Legacy C removal plan`) are mechanical reference-proofs, not build-proofs.

## Notes for Agents
- Configure is the only way to get `erts/$(TARGET)/config.h`; without a configured tree most C files cannot be compiled or even fully parsed.
- `erts/emulator/internal_doc/*.md` (BeamAsm.md, ThreadProgress.md, ProcessManagementOptimizations.md, PortSignals.md, CheckIO.md, NewLinking.tla) are the authoritative design notes for VM internals — read them before touching scheduling/GC/tracing code. They are published as docs by being referenced in place (`erts/doc/docs.exs` extras), not copied.
- `erts/emulator/utils/` contains Perl/shell/codegen tools invoked from the Makefiles (`beam_makeops`, `make_tables`, `make_preload`, `beam_emu_vars`, `beam_strip`, `make_alloc_types`, `make_compiler_flags`, `gen_git_version`, `find_cross_ycf`); they are output producers, so "missing" C files may be generated into `$(TARGET)/`.
- Large generated/derived sources to avoid editing: `beam/bif.tab` (consumed by `beam_makeops`), `beam/atom.names`, `config.h.in`, `include/internal/ethr_atomics.h`.
- Driver/NIF registration in the emulator is name-derived from the source file name (`foo_drv.c` → `foo_driver_entry`, `bar_nif.c` → `bar_nif_init`) via a generated table — renaming a driver/NIF file breaks registration silently.

## Dependencies
- GNU autoconf 2.72+ (m4 helpers in `../make/autoconf/otp.m4`), GNU make, a C compiler and, when JIT is enabled, a C++ compiler plus a supported CPU (x86_64, aarch64).
- Optional: OpenSSL (`crypto.ac`), ncurses/termcap, libsystemd, valgrind, gcov/gprof, LTTng, system zstd/zlib (PCRE2 is always in-tree).
- Windows builds additionally need the MSVC/mingw toolchain and `erts/etc/win32/`.

## Test Strategy
- Common Test suites driven through `make test` from `ERL_TOP` or from `erts/`:
  - `erts/test` — install/upgrade/system-level suites (`otp_SUITE`, `install_SUITE`, `upgrade_SUITE`, `erlexec_SUITE`, `run_erl_SUITE`, `erlc_SUITE`, `nt_SUITE`, `z_SUITE`, ...). `system.spec`, `system.dynspec`, `system_smoke.spec` are the test specs; run via `cd erts && make test`.
  - `erts/emulator/test` — the VM test suites (104 `*_SUITE.erl` for terms, GC, tracing, NIF/driver, ports, distribution, allocators, ...).
  - `erts/epmd/test` — `epmd_SUITE` (spec: `epmd.spec`, installed as `epmd_test`).
- `erts/Makefile` `test` target sets `TEST_NEEDS_RELEASE=true` and delegates to `$(ERL_TOP)/make/test_target_script.sh`, so a full release must exist before `erts`-level tests run.
- Root `Makefile.in` `TEST_DIRS` adds `erts/test`, `erts/epmd/test`, `erts/emulator/test` to the global test run (subject to `lib/SKIP-APPLICATIONS`).
- Debug/sanitizer flavors (`TYPE=debug|valgrind|asan|gcov|gprof`) are the intended way to exercise VM C code; `erts/emulator/asan/` and `erts/emulator/valgrind/` hold suppression/helper files.
- Some C-level suites build fixtures with `System_TEST` (`erts/test/ethread_SUITE`, `erl_print_SUITE`) against the headers in `erts/include`; these are the only automated coverage of `erts/lib_src` and `erts/include`.

## Routing Table
- `emulator/` → BEAM VM: `beam/` (term/process/GC/tracing C) with `beam/jit/` and `beam/emu/`, `drivers/`, `nifs/`, `sys/`, vendored 3PP (`asmjit/`, `pcre/`, `zlib/`, `zstd/`, `ryu/`), codegen `utils/`, `internal_doc/`, VM test suites, build targets/flavors
- `lib_src/` → runtime C support libraries producing `liberts_internal`/`libethread` (`common/`, `pthread/`, `win/`, `utils/make_atomics_api`, `yielding_c_fun/`)
- `include/` → C headers for other erts components; `internal/` ethread/printf/inline helpers and per-arch implementations (`erl_int_sizes_config.h.in`); note the public NIF/driver headers live in `emulator/beam/`, not here
- `preloaded/` → Erlang modules compiled into the VM (`src/`, git-tracked `ebin/`, `erts.app.src`), including the BIF stub `erlang.erl`
- `etc/` → runtime launchers and start-up programs (`common/` erlexec/erlc/escript/dialyzer/heart/inet_gethost + all the build rules, `unix/` run_erl/to_erl/shell templates/ETP gdb tools, `win32/` erl.exe/erlsrv/installer toolchains)
- `epmd/` → Erlang Port Mapper Daemon (`src/`, `test/`, `epmd.mk`)
- `start_scripts/` → boot-script templates (`*.rel.src`) → `$ERL_TOP/bin/start*.script|.boot`
- `test/` → erts-level install/upgrade/launcher/support-lib test suites and test specs
- `doc/` → ERTS documentation sources (`guides/`, `references/`, `docs.exs`) and the doc build
- `example/` → loose doc-sample NIFs/drivers (`matrix_nif`, `pg_async`, `pg_sync`, `next_perm`, ...); not built or tested
- `autoconf/` → local copies of `config.guess|sub`, `install-sh`, `vendor.info` (master: `../make/autoconf/`; read-only, regenerated by `otp_build update_configure`)
- `internal_doc/`, `obj/`, `obj.debug/`, `lib/internal/` → build-output/ignored placeholders; nothing to analyse
