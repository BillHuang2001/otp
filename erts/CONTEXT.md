# erts/ — Erlang Runtime System

## Intent
Everything that is not an OTP application but is needed to run Erlang: the BEAM emulator (C/C++/assembly), the C runtime support libraries, the preloaded Erlang modules embedded in the emulator, the launcher/start scripts, the `epmd` daemon, the exported C headers (NIF/driver API) and the ERTS documentation.
`erts/` is built into the `erts` application directory `erts-$(VSN)` (see `vsn.mk`, `VSN = 17.1`) and is the last directory configured by the top-level `configure` (it depends on `make/` and all of `lib/`).
Sibling top-level areas: `../lib/` (OTP applications), `../make/` (shared build infrastructure), `../bootstrap/` (prebuilt bootstrap OTP), `../system/` (doc build), `../xcomp/` (cross-compile configs).

## API Surface
What `erts/` produces for the rest of OTP and for users:

- **Emulator executables** — `$ERL_TOP/bin/$(TARGET)/beam.smp` (or `beam.jit`, `beam.<flavor>`); the VM. Built by `erts/emulator`.
- **`erl_child_setup`** — helper process for spawning ports without forking the VM (unix).
- **Launcher scripts** — `$ERL_TOP/bin/erl`, `cerl`, `escript`, `erlc`, `dialyzer`, `typer`, `ct_run`, `erl_call`, `start_erl`, `run_erl`, `to_erl`, `heart`, `inet_gethost`, `epmd`. Generated from `erts/etc/unix/*.src.src` by `make local_setup`.
- **Boot scripts** — `$ERL_TOP/bin/start.script`, `start_sasl.script`, `start_clean.script`, `no_dot_erlang.script` (+ compiled `.boot`) from `erts/start_scripts/*.rel.src`.
- **Public C API headers** (installed to `$RELEASE_PATH/usr/include` and `erts-*/include` by `erts/emulator` `release_spec`): `erl_driver.h`, `erl_nif.h`, `erl_nif_api_funcs.h`, `erl_drv_nif.h`, `driver_int.h` (per-OS), plus `erl_win_dyn_driver.h` on win32. Internal-only: `erts-*/include/internal/erl_internal_test.h`.
- **`erts` application** — `erts-$(VSN)/ebin/erts.app` (from `preloaded/src/erts.app.src`), preloaded beams, `bin/`, `include/`, `src/`, `man/`, `doc/`.
- **Configuration artifacts** (generated, not tracked): `erts/CONF_INFO`, `erts/$(TARGET)/config.h`, `erts/include/internal/$(TARGET)/ethread_header_config.h`, `erts/include/$(TARGET)/erl_int_sizes_config.h`.

## Constraints
- `erts/configure`/`config.h.in` are generated: edit `configure.ac` (and `crypto.ac`, `config.h.in` inputs) then run `./otp_build update_configure` from `ERL_TOP`. Never edit `configure` directly.
- `erts/emulator/Makefile.in` and `lib_src/Makefile.in` are the real sources; the sibling `Makefile` (generated by configure) is a thin wrapper including `$(ERL_TOP)/make/run_make.mk` + `app_targets.mk`.
- Two orthogonal build knobs (see `erts/emulator/Makefile.in`):
  - `FLAVOR` — `jit` (default where supported) or `emu` (interpreter only); selects `beam/jit/` vs `beam/emu/` and the executable/library name.
  - `TYPE` — `opt` (default), `debug`, `lcnt`, `valgrind`, `asan`, `gprof`, `frmptr`, `icount`, `gcov`; each maps to a `TYPEMARKER` appended to artifact names.
  Output goes to `$ERL_TOP/bin/$(TARGET)/` (git-ignored `bin/`) and `erts/emulator/$(TARGET)/<TYPE>/<FLAVOR>/`.
- The emulator must be buildable before `lib/*` exist in a bootstrap build — `erts/preloaded` and `lib_src` are the only Erlang/emulator dependencies kept at that stage.
- `erts/autoconf/` files are copies of `$ERL_TOP/make/autoconf/` master files and are auto-updated by `otp_build update_configure`; do not hand-edit.
- `crypto.ac` is the (large) OpenSSL/crypto configure fragment included from `configure.ac`.

## Design Decisions
- **Preloaded modules are compiled into the emulator binary**, not loaded from disk at boot: `erts/emulator/Makefile.in` lists `PRELOAD_BEAM` (erlang, init, erl_prim_loader, prim_*, atomics, counters, persistent_term, zlib, socket_registry, ...) and `utils/make_preload` turns them into `beams.o` (or a `.rc` resource on Windows) that is linked into the VM. Bootstrapping therefore needs no external module files.
- **`erlang.erl` is a stub**: the BIF module lives in `erts/preloaded/src/erlang.erl` but the implementations are C functions in `erts/emulator/beam/bif.tab`/`bif.c`.
- **`erts/lib_src/yielding_c_fun`** is a build-time compiler that rewrites C source into functions that can yield — the emulator's mechanism for long-running dirty BIFs/NIFs. It is both a build tool for the emulator and shipped in the bootstrap tree (`bootstrap/bin/yielding_c_fun`).
- **Cross-OS code is separated by subdirectory** rather than by many `#ifdef`s: `emulator/{drivers,nifs,sys}/{common,unix,win32[,vxworks]}` and, for headers, `include/internal/<arch-or-impl>/`.
- **Third-party C sources are vendored** under `erts/emulator/` (`asmjit/`, `pcre/`, `zlib/`, `zstd/`, `ryu/`) and can be replaced by system libraries via `--enable-builtin-*` / `--enable-use-embedded-3pp-alternatives` configure options; `erts/autoconf/vendor.info` and `emulator/asmjit.version` track them.

## Known Issues / Gotchas
- `erts/obj/`, `erts/obj.debug/`, `erts/internal_doc/` (except `.gitignore`), `erts/lib/internal/` and `erts/emulator/*` build output trees are empty in a clean checkout — do not look for code there.
- The same logical name exists at several layers (e.g. `erts/test` vs `erts/emulator/test` vs `erts/epmd/test`); the two are different test levels, not duplicates.
- `erts/Makefile` has `.NOTPARALLEL:` — the top of the erts build is intentionally serialised while the sub-directories build in parallel.

## Notes for Agents
- Configure is the only way to get `erts/$(TARGET)/config.h`; without a configured tree most C files cannot be compiled or even fully parsed.
- `erts/emulator/internal_doc/*.md` (BeamAsm.md, ThreadProgress.md, ProcessManagementOptimizations.md, PortSignals.md, CheckIO.md, NewLinking.tla) are the authoritative design notes for VM internals — read them before touching scheduling/GC/tracing code.
- `erts/emulator/utils/` contains Perl/shell/codegen tools invoked from the Makefiles (`beam_makeops`, `make_tables`, `make_preload`, `make_emu_vars`/`beam_emu_vars`, `beam_strip`, `make_alloc_types`, `make_compiler_flags`, `gen_git_version`, `find_cross_ycf`); some are generated-output producers, so "missing" C files may be generated into `$(TARGET)/`.
- Large generated/derived sources to avoid editing: `beam/bif.tab` (consumed by `beam_makeops`), `beam/atom.names`, `config.h.in`.

## Dependencies
- GNU autoconf 2.72+ (via `../make/autoconf/otp.m4`), GNU make, a C compiler and, when JIT is enabled, a C++ compiler plus a supported CPU (x86_64, aarch64).
- Optional: OpenSSL (`crypto.ac`), ncurses/termcap, libsystemd, valgrind, gcov/gprof, LTTng, zstd/zlib/pcre2 (or the embedded copies).
- Windows builds additionally need the MSVC/mingw toolchain and `erts/etc/win32/`.

## Test Strategy
- Common Test suites driven through `make test` from `ERL_TOP` or from `erts/`:
  - `erts/test` — install/upgrade/system-level suites (`otp_SUITE`, `install_SUITE`, `upgrade_SUITE`, `erlexec_SUITE`, `run_erl_SUITE`, `erlc_SUITE`, `nt_SUITE`, `z_SUITE`, ...). `system.spec`, `system.dynspec`, `system_smoke.spec` are the test specs.
  - `erts/emulator/test` — the VM test suites (~104 `*_SUITE.erl` for terms, GC, tracing, NIF/driver, ports, distribution, allocators, ...).
  - `erts/epmd/test` — `epmd_SUITE` (spec: `epmd.spec`).
- `erts/Makefile` `test` target sets `TEST_NEEDS_RELEASE=true` and delegates to `$(ERL_TOP)/make/test_target_script.sh`, so a full release must exist before `erts`-level tests run.
- Root `Makefile.in` `TEST_DIRS` adds `erts/test`, `erts/epmd/test`, `erts/emulator/test` to the global test run (subject to `lib/SKIP-APPLICATIONS`).
- Debug/sanitizer flavors (`TYPE=debug|valgrind|asan|gcov|gprof`) are the intended way to exercise VM C code; `erts/emulator/asan/` and `erts/emulator/valgrind/` hold suppression/helper files.

## Routing Table
- `emulator/` → BEAM VM: `beam/` (term/process/GC/tracing C code + `jit/` and `emu/` interpreter), `drivers/`, `nifs/`, `sys/`, vendored 3PP (`asmjit/`, `pcre/`, `zlib/`, `zstd/`, `ryu/`), codegen `utils/`, `internal_doc/`, VM test suites, supported build targets/flavors
- `lib_src/` → runtime C support libraries (`common/` erl_printf/erl_misc_utils/ethread, `pthread/`, `win/`, `utils/make_atomics_api`, `yielding_c_fun/`)
- `include/` → headers exported to other OTP components; `internal/` ethread/3PP/inline helpers, `erl_int_sizes_config.h.in`
- `preloaded/` → Erlang modules compiled into the VM (`src/`, `ebin/`, `erts.app.src`), including the BIF stub `erlang.erl`
- `etc/` → runtime launchers and start-up programs (`common/` erlexec/erlc/escript/inet_gethost, `unix/` run_erl/to_erl/heart/`erl.src.src`, `win32/` erlsrv/Install)
- `epmd/` → Erlang Port Mapper Daemon (`src/`, `test/`, `epmd.mk`)
- `start_scripts/` → boot-script templates (`*.rel.src`) → `$ERL_TOP/bin/start*.script|.boot`
- `test/` → erts-level install/upgrade/launcher test suites and test specs
- `doc/` → ERTS documentation (`guides/`, `references/`, `docs.exs`, `man1/`) and the doc build
- `example/` → example NIFs/drivers referenced by the docs (`matrix_nif`, `pg_async`, `pg_sync`, `next_perm`, ...)
- `autoconf/` → local copies of `config.guess|sub`, `install-sh`, `vendor.info` (master: `../make/autoconf/`; read-only, regenerated by `otp_build update_configure`)
- `internal_doc/`, `obj/`, `obj.debug/`, `lib/internal/` → build-output/ignored placeholders; nothing to analyse
