# erts/etc/win32/nsis — Windows NSIS installer for Erlang/OTP

## Intent
Build the *official* Windows installer for an Erlang/OTP release. Takes an already-built release tree (`otp_build release`) and turns it into a single self-extracting NSIS setup `.exe` that installs Erlang under `Program Files`, registers it in Add/Remove Programs, creates Start-menu shortcuts, sets up file associations, and bundles the MSVC runtime redistributable.
Leaf directory — no subdirectories. Siblings in the parent `../` (win32 launcher sources, `.rc`/`.ico` resources, `version.h.src`, `cygwin_tools`/`msys_tools`/`wsl_tools` shims) are *not* part of the installer.

## API Surface
**Build entry point:** `make release` in this directory (drives `release_spec`; `all` is an alias). Never invoked by the ordinary recursive OTP `make` — only by `otp_build installer_win32 [<release-dir>]` (see `otp_build`), which `cd`s here and runs `make TESTROOT=<dir> release`.

- **Installer output:** `${OUTFILEDIR}\otp_${WINTYPE}_${OTP_VERSION}.exe` (e.g. `otp_win64_30.0.exe`), written into `$(RELEASE_PATH)` (default `$ERL_TOP/release/win32`). Silent install via `/S`.
- **Installed layout** under `$INSTDIR` = `$PROGRAMFILES64\Erlang OTP` (win64) / `$PROGRAMFILES\Erlang OTP` (win32/arm64): `Install.exe`+`Install.ini`, `releases\`, `lib\`, `erts-${ERTS_VERSION}\`, `usr\`, optional `docs\` (documentation section), `Uninstall.exe`.
- **Components (NSIS sections):** `SecMSRedist` (MS VC++ redistributable, only if `HAVE_REDIST_FILE`), subsection "Erlang" = `SecErlangDev` (required, `SectionIn 1 RO`) + `SecErlangAssoc` (file associations), and `SecErlangDoc` (only if `HAVE_DOCS`).
- **Registry surface:** `HKLM\SOFTWARE\Ericsson\Erlang\${ERTS_VERSION}` (default value = install dir; also holds the Start-menu-folder name) with HKCU fallback; Add/Remove Programs at `…\CurrentVersion\Uninstall\Erlang OTP` (`DisplayName` "Erlang OTP <OTP_VERSION> (<ERTS_VERSION>)", `DisplayVersion`, `Publisher` "Ericsson AB", `UninstallString`, `NoModify`/`NoRepair` = 1), HKCU fallback. File assoc under `HKCR`: `.erl`→`ErlangSource` (+ `shell\compile` running `bin\erlc.exe`), `.hrl`→`ErlangHeader`, `.beam`→`ErlangBeam`.
- **Start menu:** `$SMPROGRAMS\$STARTMENU_FOLDER\{Erlang.lnk, Uninstall.lnk, Erlang Documentation.lnk}`; folder named `Erlang OTP <OTP_RELEASE> (x64|i386|arm64)`.
- **`erlang.nsh`** (generated, git-ignored) is the include that injects all release-specific `!define`s: `OTP_RELEASE`, `OTP_VERSION`, `OTP_VERSION_LONG`, `ERTS_VERSION`, `TESTROOT`, `OUTFILEDIR`, `WINTYPE`, `YEAR`, plus conditional `HAVE_CUSTOM_MODERN`, `HAVE_REDIST_FILE`+`REDIST_*`, `HAVE_DOCS`.

**Helper scripts (run at `make release` time, all POSIX sh/escript):**
- `find_redist.sh <win32|win64|arm64>` → prints path to the matching `vcredist_{x86,x64,arm64}.exe` (via `$VCToolsRedistDir` or by walking up from `cl.exe`/`rc.exe` in PATH, or a copy next to `$ERL_TOP`). Empty output = no redist bundled.
- `dll_version_helper.sh [-n] <msvcrt-dll>` → compiles a hello-world with `cl.exe`, then (on VC2010+) a helper calling `GetFileVersionInfo`/`VerQueryValue` to print the DLL's `FileVersion` string (or, with `-n`, its DLL name). Feeds `REDIST_DLL_VERSION` / `REDIST_DLL_NAME`.
- `vsn_number.escript <OTP_VERSION> <winpath-otp_version_tickets>` → normalizes the version to the ≥4-numeric-field form NSIS requires (`30.0`→`30.0.0.0`); emits `0.0.0.0` for rc/development builds (when `make/otp_version_tickets` doesn't start with `OTP-`).

## Constraints
- Requires NSIS ≥ 3.0.6 on PATH (`makensis.exe`); the Makefile hard-rejects `v2.*`, `v3.0`, `v3.01`. Under MSYS/MINGW the flag becomes `//V2`.
- Uses stock NSIS includes `MUI.nsh`, `WordFunc.nsh` (VersionCompare), `WinVer.nsh` — must exist in the NSIS installation.
- `custom_modern.exe` is a **checked-in binary** UI template (`MUI_UI`); it must stay compatible with the NSIS version in use.
- Must run against a *fully built* release tree (`releases/`, `lib/`, `erts-<VSN>/`, `usr/`, and optionally `docs/`) at `TESTROOT`; it does not build any Erlang code itself.
- `OTP_VERSION_LONG` must be exactly ≥4 numeric fields (see `vsn_number.escript`).
- Never hand-edit the generated `erlang.nsh`; it is regenerated by `release_spec` and removed by `clean`.

## Design Decisions
- **NSIS** chosen because it is free, scriptable, and supports the Modern UI plus custom components — the conventional Windows installer generator for OTP.
- **`custom_modern.exe` vendored** (a frozen R13B03-era binary) so the installer's UI keeps the Erlang-branded look and is independent of whatever MUI build ships with the NSIS version on the build host.
- **`dll_version_helper.sh` probes the real CRT DLL version** instead of reusing `version.h`/`OTP_VERSION`: the installer's `.onInit` runs on the *target* machine and must decide at install time whether the installed MSVC runtime is new enough (it compares the machine's DLL version against `REDIST_DLL_VERSION`), then toggles the `SecMSRedist` section between "present"/"needed". This is a runtime check, unrelated to the OTP version.
- **Redistributable bundled** so the installer is self-contained and works offline (mirrors the advice in `../INSTALL.txt` for the raw/zip distribution): the exe is copied to `$(RELEASE_PATH)/$(REDIST_TARGET)` and launched (`/q /norestart` when silent).
- **icacls hardening** in `SecErlangDev` strips inherited ACLs and grants only Administrators full control + Everyone read/execute, to reduce DLL-injection risk when installed outside `Program Files`.
- Both HKLM and HKCU registry branches are written (and deleted) so the installer works without admin rights and when the Start-menu page is skipped.

## Known Issues / Gotchas
- `erlang20.nsi` `!include`s `erlang.nsh`, which does not exist until the Makefile's `release_spec` target generates it — the `.nsi` cannot be compiled standalone.
- rc/development builds configure the installer's `VIProductVersion` as `0.0.0.0`; only real `OTP-*` releases get a numeric version.
- Components/list order matters: `SecMSRedist` is section index 0 and `.onInit` toggles it with `SectionGetFlags 0`.
- All Windows paths here go through `w32_path.sh` (`-d` for dirs, `-m` for the mixed form NSIS expects); if the helpers return `NOTFOUND` the corresponding feature is silently dropped from the installer.
- `make` clean only removes `erlang.nsh`; intermediate `hello.*`/`helper.*` files from the helper scripts are not tracked.

## Notes for Agents
- The build runs only on Windows (needs `makensis.exe`, `cl.exe`, `dumpbin.exe`, `w32_path.sh`) — it cannot be exercised on Linux/macOS. Do not try to build it here; read `Makefile` `release_spec` + `erlang20.nsi` to reason about behavior.
- When changing installed files/registry/associations, edit `erlang20.nsi`; when changing which `!define`s exist, edit the `release_spec` recipe in `Makefile`.
- `custom_modern.exe` is binary — treat as opaque asset.

## Dependencies
- NSIS 3.0.6+ (host install) with `makensis.exe`, `MUI.nsh`, `WordFunc.nsh`, `WinVer.nsh`.
- Microsoft Visual C++ toolchain (`cl.exe`, `dumpbin.exe`) and, for bundling, a `vcredist_{x86,x64,arm64}.exe` (via `$VCToolsRedistDir` or a copy beside `$ERL_TOP`).
- POSIX sh (cygwin/msys/wsl), `w32_path.sh`, and `escript` (invoked through `$ERL_TOP/bootstrap/bin/escript.exe`).

## Test Strategy
- No automated tests exist for this directory. Coverage is indirect and install-time only: the Windows CI workflow (`.github/workflows/reusable-build-windows.yaml`) installs NSIS 3.11.0 (`choco install nsis`), runs `./otp_build installer_win32`, and fails the build if no `otp*.exe` is produced (uploaded as the `otp_win32_installer` artifact).
- Gaps: nothing verifies the installed file tree, registry keys, Start-menu shortcuts, file associations, or the uninstaller; the `DllVersionGoodEnough` / redist-detection logic is only exercised on a real target machine.
