# erts/lib_src/utils/ — ethread atomics API code generator

## Intent
Holds the single tracked file `make_atomics_api` (2292 lines, ~69 KB, mode 0755), a standalone Erlang **escript** (`#!/usr/bin/env escript`, `-mode(compile)`, `%% @author Rickard Green`, created 2011) that *generates* the ethread atomic-memory-access API. It is a build-time **code generator for maintainers**, not a runtime component and not a service:
- Output 1 (public/internal header): `erts/include/internal/ethr_atomics.h` (~9.2 kLOC).
- Output 2 (implementation): `erts/lib_src/common/ethr_atomics.c` (~4.7 kLOC).

Both output paths are hard-coded relative to `$ERL_TOP`.

## API Surface
- `erts/lib_src/utils/make_atomics_api` — the only file here; an escript, no exports/modules.
- Running it (`ERL_TOP=/abs/path/to/otp <script>`, or from `$ERL_TOP` with `ERL_TOP=$PWD`) is its whole interface. It writes both output files and prints `Wrote: <path>` for each.
- It reads only the `ERL_TOP` environment variable; `main([])` calls `halt(1)` with `$ERL_TOP not set!` if unset (no command-line arguments are accepted — `main/1` only matches `[]`).
- Both generated files carry a `--------------- DO NOT EDIT THIS FILE! ---------------` banner naming this script.

## Constraints
- **Never hand-edit `erts/include/internal/ethr_atomics.h` or `erts/lib_src/common/ethr_atomics.c`.** All changes go into `make_atomics_api` and are regenerated. This is the single most important rule for this node.
- The generator is a *source-of-truth* script: it must stay in sync with the per-architecture backends and the macros its output references (`ETHR_*`), which live outside this directory (see See Also).
- The output files are **committed to git**, so a regeneration appears as a very large diff (13.9 kLOC across the two files) — expect and review it as such.
- Ordering constraints inside the script are load-bearing and documented by in-file comments (`?ATOMIC_OPS`): `cmpxchg` before `read`; `xchg` before `set`; `set` before `init`; `add_read` before `add`/`inc_read`/`dec_read`; `inc_read` before `inc`; `dec_read` before `dec`. Reordering silently changes the generated fallback chains (e.g. `set` is emitted as `xchg`, `add` as `add_read`).
- `comments()` stamps `Copyright Ericsson AB 2011-<current year>` from `erlang:date()`, and files are opened with explicit `latin1` encoding. Regenerating in a later calendar year (or with a different encoding assumption) perturbs the copyright line — expected, not a bug.
- When `erlang:system_info(schedulers_online) =/= 1`, the two output files are written by two monitored processes in parallel; a crash in either is not reported beyond a `badmatch`/DOWN reason.

## Design Decisions
- **Why generate at all:** the API is a Cartesian product of {op} × {memory-barrier variant} × {operand size} × {implementation backend}, plus a fallback path. Hand-writing it is infeasible; the script emits all combinations from compact tables.
  - Ops: `[cmpxchg, xchg, set, init, add_read, read, inc_read, dec_read, add, inc, dec, read_band, read_bor]`.
  - Double-word ops (narrower set): `[cmpxchg, set, read, init]` — `?DW_ATOMIC_OPS`, driven by `?DW_FUNC_MACRO` (`ETHR_DW_ATOMIC_FUNC__`) and `?DW_RTCHK_MACRO` (`ETHR_RTCHK_USE_NATIVE_DW_ATOMIC_IMPL__`).
  - Barrier variants: `[none, ddrb, rb, wb, acqb, relb, mb]`; `ddrb` (`?NON_NATIVE_BARRIERS`) is implemented in terms of `rb`/`none` depending on `ETHR_ORDERED_READ_DEPEND` (data-dependency-read barrier), all others are native.
  - Operand sizes: `?ATOMIC_SIZES = ["dword", "word", "32"]`; `atomic_context/1` maps each size to its type names, macro prefixes (`NATMC*`/`ATMC*`, `ETHR_HAVE_<size>_NATIVE_ATOMIC_OPS`, `ETHR_UNUSUAL_SINT_*_VAL__`) and whether an AMC fallback applies (`dword` and `word` yes, `32` no).
- **Native vs fallback:** each generated op body is a chain selected at compile time — `#if defined(<ETHR_HAVE_*_NATIVE_ATOMIC_OPS>)` → native macro; `#elif defined(ETHR_AMC_FALLBACK__)` → "Atomic Modification Counter" fallback; `#else` → spinlock fallback (`ETHR_ATOMIC_OP_FALLBACK_IMPL__` over a hashed `ethr_atomic_protection__` array, `?ETHR_ATMC_FLLBK_ADDR_BITS` 10 / `?ETHR_ATMC_FLLBK_ADDR_SHIFT` 6). The `#else` branch emits the exported symbol-implementation used when native ops are absent.
- **AMC fallback (`make_amc_fallback/0`, emitted in the .c via `c_top/0`)**: a 63-bit modification counter + 1-bit exclusive flag built on smaller native atomics (`ETHR_AMC_NO_ATMCS__` is 1 or 2 depending on whether 32- or 64-bit native atomics back it). In-file rationale: parallel reads, no cache-line invalidation for uncontended reads, single-cache-line invalidation for modifications — at the cost of more memory than the spinlock fallback.
- **Capability macros** (`ETHR_HAVE_ETHR_NATIVE_ATOMIC`, `ETHR_HAVE_ETHR_NATIVE_DW_ATOMIC`, `ETHR_HAVE_ETHR_NATIVE_SU_DW_ATOMIC`) gate the runtime introspection helpers `ethr_native_atomic*_ops(void)` / `ethr_have_native_dw_atomic(void)` emitted by `make_info_functions/0`; the generated header defines the `ETHR_NATMC*` macros that resolve each size to the available native width.
- The generated .h is also emitted for a "double word" runtime-tested path: `?DW_RTCHK_MACRO` emits `etl_*__` alias symbols that forward to the implementation when the runtime double-word check passes.

## Known Issues / Gotchas
- **There is no build rule that runs this script.** A repo-wide search for `make_atomics_api` finds it only in this file, the two generated files' banners, and `erts/CONTEXT.md`. It is **not** invoked by `make`, by `configure`, or by `./otp_build update_configure`. It is a manual, undocumented maintainer step (nothing in `HOWTO/` or `erts/doc/` references it). A future agent should not expect the generated files to refresh automatically.
- The generated .h is not a "public" installed header (it is `internal/`), but it *is* installed: `erts/lib_src/Makefile.in` lists it in `INTERNAL_RELEASE_INCLUDES`. The generated .c is compiled as part of `ETHREAD_LIB_SRC`.
- `erts/include/internal/ethr_atomics.h` and `erts/lib_src/common/ethr_atomics.c` are large, entirely generated C — reading them to understand behavior is a dead end; read this script and the per-arch backends instead.
- The 32-bit-sized ops use `ethr_native_atomic32`/`64` depending on availability; the 32-size context is *not* purely "32-bit" — `ETHR_HAVE_NATIVE_ATOMIC64` can back it (see `h_top/0`). Don't assume a one-to-one size↔width mapping when reasoning about the macros.

## Notes for Agents
- To change the atomics API: edit `make_atomics_api`, run it with `ERL_TOP` set, and commit the resulting `ethr_atomics.h` + `ethr_atomics.c` together with the script (git history shows they land in the same commits).
- The script only needs a working `escript`/Erlang (it uses `os`, `file`, `erlang:date`, `lists`, `filename` from stdlib) — it does **not** need a configured or built `$ERL_TOP/erts`, nor `config.h`. Any installed Erlang can run it; only the output path requires a source tree.
- The bulk of the file is quoted C template strings (`comments/0`, `h_top/0`, `c_top/0`, `make_amc_fallback/0`, `make_info_functions/0`). Read those to see literal generated output; read the `make_*`/`op_*`/`atomic_context/1` functions to see how combinations are composed.
- There are no subdirectories here.

## Dependencies
- A working `escript` (any Erlang/OTP installation) and the `ERL_TOP` environment variable pointing at the OTP source root.
- The correctness of the emitted C depends on macros/types defined elsewhere: `erts/include/internal/ethread.h`, `ethr_internal.h`, `ethr_optimized_fallbacks.h`, the per-arch `ethr_atomic.h`/`ethr_dw_atomic.h`/`ethr_membar.h` under `erts/include/internal/{gcc,i386,x86_64,ppc32,sparc32,sparc64,tile,win,libatomic_ops}/`, and the `ETHR_HAVE_*_NATIVE_ATOMIC_OPS` macros set by configure (`make/autoconf/otp.m4`, `ERL_FIND_ETHR_LIB`).

## Test Strategy
- No automated tests target this script. Verification is indirect: a correctly regenerated pair must (a) compile the ethread library (`erts/lib_src`, `ETHREAD_LIB_SRC`) and (b) pass the VM-level atomics tests in `erts/emulator/test` under `TYPE=debug` flavors. There is no generator-output diff/regeneration check in CI.
