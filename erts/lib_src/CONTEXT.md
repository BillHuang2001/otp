# erts/lib_src/ — ERTS low-level C support libraries & build-time code tools

## Intent
The C support layer of ERTS: the sources of the two lowest-level static libraries (`liberts_internal` — printf/OS utilities; `libethread` — the portable thread/mutex/event/atomics abstraction) plus two *build-time* tools that generate code for the tree (the `yielding_c_fun` source-to-source compiler and the `make_atomics_api` escript).
Everything here is built very early: `erts/emulator`, `erts/epmd`, `erts/etc/common` and the standalone test programs all link these libraries, and in a bootstrap build this directory (together with `../preloaded/`) is what makes the emulator buildable before `lib/*` exists.
The build is driven by `Makefile.in` (the sibling `Makefile` is a generated 4-line wrapper that only includes `$(ERL_TOP)/make/run_make.mk`).

## API Surface (what this directory produces)
- `../lib/internal/$(TARGET)/liberts_internal$(TYPE_SUFFIX).a` — from `common/{erl_printf_format,erl_printf,erl_misc_utils}.c`; thread-agnostic, usable before `ethr_init`.
- `../lib/internal/$(TARGET)/liberts_internal_r$(TYPE_SUFFIX).a` — same sources compiled reentrant (`THR_DEFS`); only built when `ETHR_LIB_NAME` is non-empty.
- `../lib/internal/$(TARGET)/libethread$(TYPE_SUFFIX).a` — from `common/{ethr_aux,ethr_atomics,ethr_mutex,ethr_cbf}.c` **plus** the OS half `$(ETHR_THR_LIB_BASE_DIR)/{ethread,ethr_event}.c` (`pthread/` or `win/`) **plus** `pthread/ethr_x86_sse2_asm.c` when `ETHR_X86_SSE2_ASM=yes`. On Windows the prefix/suffix differ (`ethread$(TYPE_SUFFIX).lib`).
- Stamp file `obj/$(TARGET)/$(TYPE)/MADE` — the *real* dependency other makefiles use (`DEPLIBS += .../obj/$(TARGET)/$(TYPE)/MADE` in `erts/emulator/Makefile.in`, and `erts/{epmd/src,etc/common}/Makefile.in` even re-invoke `cd erts/lib_src && $(MAKE) $(TYPE)`); its prerequisites are the YCF binary and all three libraries.
- `obj/$(TARGET)/$(TYPE)/depend.mk` — generated by the `depend` target (`$(CC) -MM` over all `*_SRC` variables); the top-level `Makefile.in` runs `make depend` here as part of the global dependency step (skipped when `ERTS_SKIP_DEPEND=true`).
- Build-time executables: `yielding_c_fun/bin/$(TARGET)/yielding_c_fun[.exe]` (see `yielding_c_fun/`) — used by `erts/emulator` and copied into `bootstrap/bin/` by the top-level `Makefile.in`; and `utils/make_atomics_api`, a *manual* maintainer escript that regenerates the atomics API in `../../include/internal/` and `common/`.
- `release_spec` installs the internal headers (`ethread.h`, `ethread_inline.h`, `ethr_mutex.h`, `ethr_optimized_fallbacks.h`, `ethr_atomics.h`, `erl_printf.h`, `erl_printf_format.h`, `erl_misc_utils.h`, `erl_errno.h`, the generated `$(TARGET)/{ethread,erts_internal,ethread_header_config}.mk|.h`, and the per-arch `{i386,x86_64,ppc32,sparc32,sparc64,tile,gcc,pthread,win,libatomic_ops}/` dirs) into `erts-$(VSN)/include/internal/`, and the libraries into `erts-$(VSN)/lib/internal/`.

## Constraints
- `Makefile.in` is the only hand-edited makefile; `Makefile` is generated by `./configure` (from `erts/configure.ac:3948`). Never edit `Makefile`.
- Library/object names are computed from the `$(TYPE)` knob (`opt|debug|lcnt|valgrind|asan|gprof|frmptr|icount|gcov` → `$(TYPE_SUFFIX)`); the C sources are listed explicitly in the `ERTS_INTERNAL_LIB_SRCS` / `ETHREAD_LIB_SRC` variables — there are no wildcards, so adding a `.c` file requires editing `Makefile.in`.
- One OS thread backend is chosen at configure time (`ETHR_THR_LIB_BASE_DIR` = `pthread` or `win`, set by `ERL_FIND_ETHR_LIB` in `../../make/autoconf/otp.m4`, called from `erts/configure.ac`); the other directory is not compiled. `pthread/` and `win/` must stay symbol-compatible.
- If no thread library was found, `ETHR_LIB_NAME` is empty and the whole `libethread`, both `_r` libraries and the compilation of `common/ethr_*.c` are skipped — `configure` treats that as fatal for the emulator, but `lib_src` itself still builds `liberts_internal`.
- Never hand-edit the generated files `common/ethr_atomics.c` and `../../include/internal/ethr_atomics.h`; change `utils/make_atomics_api` and regenerate. `common/ethr_atomics.c` is ~4.7 kLOC of the ~15 kLOC of C in this directory.
- Nothing here may depend on `erts/emulator/beam` internals beyond what the installed `../../include/internal/` headers declare: this code is compiled *for*, not into, the emulator.
- `../../include/internal/README` states these headers are explicitly not public API and may change without notice; the libraries likewise (`../lib/internal/README`).

## Design Decisions
- **ethread exists as an abstraction layer** so the runtime's synchronization primitives (mutexes, reader-group rwmutexes, condition variables, events, spinlocks, thread-specific events/TSE, thread names, monotonic time, and the atomics) have one interface (`ethread.h`) implemented on different thread libraries. The emulator calls the thin `erts_*` wrappers in `erts/emulator/beam/erl_threads.h`, so the underlying thread library can be replaced without touching VM code.
- **Per-OS split by directory, not `#ifdef`**: portable behaviour in `common/`, OS primitives in `pthread/`|`win/`; the same policy as `emulator/{drivers,nifs,sys}/{common,unix,win32}`.
- **Two libraries, one directory**: `liberts_internal` (printf + OS utilities) is deliberately separate from `libethread` so non-threaded tools can link the printf/OS half without pulling in threading, and the `_r` variants serve the reentrant (thread-aware) build.
- **The atomics API is generated** because it is a Cartesian product of op × memory-barrier variant × operand size × backend, and needs native/AMC/spinlock fallbacks plus runtime capability probing (`ethr_runtime__`, filled by `ethr_x86_cpuid__`) — see `utils/`.
- **YCF is a build-time source-to-source compiler, not a runtime trampoline**: the generated C is ordinary C (the C compiler still does register allocation and inlining), needs no platform-specific stack switching, and its suspended state is an explicit heap object that survives across scheduler threads and can be dropped explicitly. See `yielding_c_fun/`.
- **`yielding_c_fun/main_target.mk` lives in the tool's directory and is included by `Makefile.in`**: one rule set serves both the standalone build of the tool and the OTP build.

## Known Issues / Gotchas
- `erts/lib_src/obj/` and `erts/lib/internal/$(TARGET)/` are build outputs and empty in a clean checkout; do not look for sources or libs there.
- The archive rules for `$(ERTS_MD_LIB)`, `$(ERTS_MDd_LIB)`, `$(ERTS_MT_LIB)`, `$(ERTS_MTd_LIB)`, `$(ERTS_r_LIB)` and `$(ERTS_LIB)` in `Makefile.in` are inert: those variables are never defined anywhere in the tree. On Windows the `MD/MDd/MT/MTd` object dirs only select the MSVC CRT (`/MD`,`/MDd`,`/MT`,`/MTd`); the archives that actually get built are the ethread/erts_internal ones above.
- Reading `Makefile.in` top-to-bottom is misleading: the `$(TYPE)` cascade is a nine-level `ifeq` nest, and the `$(USING_VC)` branch duplicates the object/library rules for Windows.
- The two tools in this directory have no automatic invocation: `utils/make_atomics_api` is a manual step (nothing in `make`, `configure` or `otp_build` runs it) and `yielding_c_fun`'s own regression suite is not run by the OTP build or CI.
- `yielding_c_fun/bin/yielding_c_fun` (tracked) is a bash wrapper, not the compiler binary — the binary is `bin/yielding_c_fun.bin` (standalone) or `bin/$(TARGET)/yielding_c_fun[.exe]` (OTP build), both git-ignored.
- `pthread/ethr_x86_sse2_asm.c` is compiled **only** into the reentrant object dir (`obj/$(TARGET)/$(TYPE)/r`), and `pthread/ethread.c` + `ethr_event.c` are also only compiled there on POSIX (see `Makefile.in`); the plain (non-`r`) objects exist only for `common/erl_printf*.c`/`erl_misc_utils.c`.
- A stale path `erts/lib_src/yielding_c_fun/lib/simple_c_gc/**` is still listed in the no-warning list of `scripts/license-header.es`; that directory no longer exists.

## Notes for Agents
- There are no tests, sample programs or generated outputs inside this directory itself — anything runnable lives in `../test/` (Common Test) or in `yielding_c_fun/test/` (its own bash suite).
- To answer "where is symbol X implemented", check `common/` first, then the OS subdirectory selected by `ETHR_THR_LIB_BASE_DIR`; headers are all in `../../include/internal/` (never in this directory).
- Size overview: ~15 kLOC C here, of which ~12.5 kLOC in `common/` and ~2.2 kLOC in the OS halves; `yielding_c_fun/` is a separate ~200 kLOC tool.
- Build a single flavor with `make TYPE=debug` (or `lcnt`, `valgrind`, `asan`) from here; the emulator must then be built with the same `TYPE` to link against the matching `$(TYPE_SUFFIX)` libraries.

## Dependencies
- A configured tree: `../../include/internal/$(TARGET)/{ethread.mk,erts_internal.mk,ethread_header_config.h}` and `erts/$(TARGET)/config.h` are produced by `configure` (`erts/configure.ac:3946` maps `include/internal/$host/ethread.mk` from `ethread.mk.in`).
- GNU make; `makedepend`-style `$(CC) -MM` for the `depend` target.
- The thread library located by `ERL_FIND_ETHR_LIB` (pthreads or win32_threads; optional `libatomic_ops` via `--with-libatomic_ops`).
- `escript`/any Erlang for `utils/make_atomics_api` (no configured ERTS needed); clang for `yielding_c_fun`'s test suite; a C99 compiler and GNU make for the standalone YCF build.

## Test Strategy
- No test suite lives here. `libethread` and `liberts_internal` are covered by `../test/ethread_SUITE.erl` + `../test/ethread_SUITE_data/` and `../test/erl_print_SUITE.erl` + `../test/erl_print_SUITE_data/`, which compile standalone C programs against the built libraries using substitutions provided by `lib/common_test/test_server/ts_erl_config.erl` (`@erts_lib_internal_path@`, `@type_marker@`, the generated `ethread.mk`/`erts_internal.mk`) — so a configured *and* built tree is mandatory and they must run through `make test` in `erts/` (`TEST_NEEDS_RELEASE=true`).
- `yielding_c_fun` has its own standalone `test/test.sh` (golden-output comparison), runnable only via its `make test`; it is not wired into the OTP build or CI.
- Practical way to exercise this C code: build with `TYPE=debug` (assertions, `ETHR_XCHK`) or `TYPE=valgrind`/`TYPE=asan` and run the emulator suites in `../emulator/test`.

## Routing Table
- `common/` → portable sources of both libraries (`erl_printf*.c`, `erl_misc_utils.c`, `ethr_aux.c`, `ethr_atomics.c` (generated), `ethr_mutex.c`, `ethr_cbf.c`); the library-split and generated-file rules live there
- `pthread/` → POSIX/pthreads half of `libethread` (`ethread.c`, `ethr_event.c`, `ethr_x86_sse2_asm.c`)
- `win/` → Win32 half of `libethread` (`ethread.c`, `ethr_event.c`)
- `utils/` → `make_atomics_api`: the escript that generates the atomics API (a manual maintainer step)
- `yielding_c_fun/` → YCF, the build-time C-to-C yielding compiler (+ its own `test/` subtree with nested CONTEXT.md files)
- `Makefile.in` → the only place the library/object rules and `release_spec` are defined (read-only for child nodes)
- `../include/internal/` → all interfaces used here and the per-arch atomic backends (sibling — read-only, escalate writes to `../`)
- `../test/` → `ethread_SUITE`, `erl_print_SUITE` (sibling — read-only, escalate writes to `../`)
- `../emulator/` → primary consumer (links both libraries, invokes YCF; `beam/erl_threads.h` is the `erts_*` wrapper layer)
- `../../make/` → shared infra: `run_make.mk` (included by the generated `Makefile`), `autoconf/otp.m4` (`ERL_FIND_ETHR_LIB`)
