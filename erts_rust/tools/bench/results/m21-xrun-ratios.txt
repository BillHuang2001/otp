H. the budget-evaluation pass (NOT a timing source)
  results/m21-budgetprobe-all.json is one `--runtime all --quick` pass over the same four workloads,
  run only so the latency-budget rows that need BOTH sides in one report (the two `baseline` rust/sys
  `startup_ms` ratio rows) can be evaluated, and to give `bench compare` a single report carrying both
  sides (two single-side reports share no (workload,runtime) key, so the two-file mode reports every
  row `only-in-a`/`only-in-b`). It is runtime-major (all `sys` rows, then all `rust` rows), so it is
  subject to the documented ordering bias; every figure in sections A-F comes from the fourteen
  matched single-side passes. Its driver-printed verdict block is archived verbatim as
  results/m21-budgetprobe-all.txt, and its cross-runtime diff as results/m21-compare-cross-runtime.txt.
