D. reading notes
  - wall_ms p50/p99 are the summary quantiles over the 3 whole-process runs of one pass; the six
    per-round rows in B are the stability evidence, and the quoted cross-runtime figure is the
    MEDIAN OF THE SIX PER-ROUND RATIOS (section C `rust/sys` column), computed from the unrounded
    per-round values. It is not the ratio of the two medians — both are printed per project so a
    transcription can name which one it quotes (they differ: medians of ratios and ratios of
    medians are different estimators).
  - `tests_passed` is the deterministic work companion: 90 (jsone) / 79 (bbmustache) on BOTH sides
    of every round, so the identical suite ran under both runtimes.
  - `compile_ms` is the SAME external `erlc` (the system erlc named in each report notes) on both
    sides, so its rust/sys ratio is a compile-stage sanity check, not a runtime figure.
  - `peak_memory_bytes` is the max VmHWM observed across the 3 runs of a pass (the report note
    also carries the compile stage peak); it is a whole-process footprint, like-for-like here
    because both sides run the identical suite.
  - wall_ms and peak_memory_bytes are whole-program quantities: this session measures suite wall
    time, so there is no per-op/per-element normalisation to compare across the two sides.
  - `bbmustache wall_ms[p50]` sits on a 4-dp knife edge: the exact median of the six unrounded
    per-round ratios is 1.065225 (-> 1.0652), while averaging the six per-round values rounded as
    printed in B gives exactly 1.06525, which a decimal half-up formatter prints as 1.0653.
    The exact figure is the one quoted in C2; name the route if a transcription uses the other.
  - the host is shared and heavily loaded this session (see F): read the ratios and `tests_passed`
    rather than absolute wall times.
