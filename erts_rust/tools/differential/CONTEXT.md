# differential — Rust ERTS vs System ERTS Compatibility Gate

## Intent
The in-repo **differential-test harness** (Stage 0; `../../../ERTS_RUST_REWRITE_DEEPDIVE.md` §H): for each corpus case it runs the **real system ERTS** (the *oracle*) and the **Rust runtime** (`beam_rt`) and compares the **observable results**.
Five kinds of case (`CaseKind`): **expression** cases evaluate the same self-terminating probe under both runtimes; **environment-variable expression** cases (`EvalEnv`) spawn each runtime with an explicit environment so the `ERL_*FLAGS` merge (A.6) is pinnable; **module-run** cases compile an embedded Erlang module with `erlc` (optionally building a NIF `.so` next to it) and run one exported function; **environment-variable module-run** cases (`ModuleEnv`) are that shape plus an explicit environment (a `-pa {dir}` carried by `ERL_AFLAGS`) and helper modules compiled into the same temp dir, so the flag's *application* — not its recording — is observed; **command** cases (`Command`) spawn a **per-side** external program + argv (neither `-eval` nor `beam_rt run <module>`) and compare stdout + exit status — the non-CLI stage, used by the `dist/` group to pin a live two-node distribution loopback (A.5) by driving an external `dist_probe` helper against the oracle.
This is the *compatibility gate* of the rewrite (`../../../ERTS_RUST_REWRITE_EVALUATION.md` §G.7/§I): no behavior change ships without a differential case.
It is a pure **driver/observer** - it never modifies the runtime and never inspects its internals; the only contract with `beam_rt` is its documented external CLI (**A.6**), and it honors every shared convention in `../CONTEXT.md`.
Cargo **binary + library** crate `differential`: the library lets `cargo test` assert the harness itself (oracle golden checks, oracle-vs-oracle equality, diff detection); the binary is what a human or CI drives.

## Observable results (what is compared)
Per case, each runtime is observed and compared field-by-field:
1. **stdout bytes** (exact, byte-wise) — always compared.
2. **exit status** (the process exit code; `None` if signalled) — always compared.
3. **stderr bytes**, **classified** — compared for **expression** cases (`Observables::All`) through a narrow classifier: only the Rust runtime's documented one-line boot banner (`beam_rt <vsn> booted: …`, `compare::is_runtime_banner_line` / dropped by `compare::significant_stderr`) is ignored; every other stderr byte is compared exactly. Module-run and command cases (`Observables::StdoutAndExit`) do not compare stderr.
4. **`term_to_binary/1` of the evaluated result** — the probe *encodes* what it observes, so the canonical ETF bytes are a first-class diff field (A.2).
5. **exception class + reason** — surfaced because `erl -noshell -eval` prints **nothing** on an uncaught error; the harness always wraps the expression in `try … catch` (*Probe protocol*).
6. **selected `erlang:system_info/1` keys** — covered by corpus cases (A.8).

A Rust-side observation is a documented **capability gap**, not a difference, in either of two ways — both `SideResult::Unsupported`, so an unimplemented feature is `unsupported`, never `mismatch`:
1. its exit code is `3` (`runtime::UNSUPPORTED_EXIT_CODE`): the reason carries the runtime's first non-empty stderr line; or
2. a **probe-wrapped** (eval) case's probe *caught* the raise: the probe prints it as its single `exception <class> <reason>` stdout line and exits `1`, and `<reason>` (after stripping one pair of surrounding `'…'` quotes) follows the runtime's documented `unsupported` convention — recorded as `beam_rt: unsupported (caught by the probe): <stripped>`. Detection is deliberately narrow (`harness::caught_unsupported_reason`): only the documented `unsupported` prefix (with a following `:`/`_`/whitespace, or nothing) triggers it, so a genuine Erlang reason (`badarg`, `system_limit`, `function_clause`, …) stays an observation → `mismatch`. `RunPlan::probe_wrapped` is `true` only for `CaseKind::Eval`/`compare_expr`, `false` for module-run and command cases.

## Probe protocol (binding)
An **expression** case carries a plain Erlang expression, wrapped into a self-terminating probe:
- **`Probe::TermToBinary`** (default): `try (EXPR) of V -> io:format("ok ~w~n",[term_to_binary(V)]), halt(0) catch C:R -> io:format("exception ~w ~w~n",[C,R]), halt(1) end.`
- **`Probe::Value`**: same shape but prints `~w` of `V` (textual rendering, no ETF encode).

Success ⇒ one stdout line `ok <repr>`, exit `0`; failure ⇒ one line `exception <class> <reason>`, exit `1`.
Expression cases may add **extra argv** (e.g. `-<flag> <value>`) to exercise CLI flag parsing (A.6); argv is built once and given to **both** runtimes: `["-noshell", <extra…>, "-eval", <probe>]`.

A **module-run** case (`CaseKind::Module(ModuleRun)`) drives the two runtimes with **different** argv: oracle `["-noshell","-pa",<dir>,"-eval","io:format(\"~w~n\",[<mod>:<fun>(<args…>)]), halt(0)."]`; Rust runtime `["run","<dir>/<mod>.beam","<mod>:<fun>/<arity>",<int-args…>]` (its `run` action). A `ModuleEnv` case (`CaseKind::ModuleEnv { run, extra, env }`) drives the same per-side argv but its oracle argv carries **no** `-pa` (`ModuleRun::oracle_argv_env_only`): both runtimes are spawned with the case environment, its `{dir}` placeholder expanded to the compiled dir, so the directory reaches the code path **only** through the environment.

A **command** case (`CaseKind::Command(CommandRun)`) is the non-CLI stage: each side is a `CommandSpec { program: CommandProgram::{Oracle,Rust,Helper}, args: &[&str] }` driven with **its own** argv (`Oracle` = the resolved `erl`, `Rust` = the resolved `beam_rt`, `Helper` = the resolved `dist_probe`), and only stdout + exit status are compared. The oracle side is always `Oracle`; the Rust side may be `beam_rt` or the `dist_probe` helper (this is how the `dist/` group pins a live two-node distribution loopback, A.5). A side whose program is absent makes the case a loud `Verdict::Skipped` (a missing helper is never a pass).
The embedded source is compiled at run time with the system `erlc` into a unique temp dir (cleaned up afterwards); **stdout + exit status only** are compared.
A module-run case may carry `nif: Option<NifFixture>`: the fixture's artifacts (a `cc`-built `.so`, or a text file `<name>.so`) are materialized into the **same** temp dir as the `.beam`, so the embedded module self-locates them (`filename:dirname(code:which(?MODULE))`) and neither runtime's argv changes. A module-run golden is an **integer line** (the corpus invariant); a case whose observable would embed a volatile value (a temp-dir path in a `load_nif` message, a pid/port creation) classifies that observable into an integer instead.

## API Surface

### CLI (hand-rolled `std`-only arg parsing — **no `clap`**; `--help` usable on every subcommand)
- `differential run <case-id> [--json] [--out <dir>]` — run one corpus case both ways; print the comparison.
- `differential compare <expr> [--pa <dir>]… [--json] [--out <dir>]` — ad-hoc: evaluate an expression under both runtimes and compare.
- `differential suite [--strict] [--allowlist <file>] [--gaps <path>] [--json] [--out <dir>]` — run the whole built-in corpus. `--allowlist <file>` (requires `--strict`) is the known-gaps ratchet: it tolerates the gaps it records and fails on an unauthorized gap or a stale entry; `--gaps <path>` also writes the generated `GAPS.md`.
- `differential list [--by-contract] [--json] [--out <dir>]` — list corpus case ids + the contract each covers. `--by-contract` groups by contract id (A.1…A.9) with per-contract counts and ids; without it the output is byte-for-byte the plain listing.
- `differential --help` / `-h`; `differential <sub> --help`.
- **Exit codes (the binary):** `0` all executed cases agreed (skips/`unsupported` reported, not fatal); `1` ≥1 **mismatch**; `2` usage/env error. `--strict` escalates `unsupported`/`skipped` to failure; `--strict --allowlist <file>` instead tolerates only the gaps the allowlist records and fails (`1`) on an unauthorized gap or a stale entry. `gate.sh` (below) layers the `0/1/2/3` CI mapping on top; the binary's own contract is unchanged.
- `gate.sh` (executable, POSIX `sh`, repo-relative — no baked paths) — the **CI gate**. It builds `beam_rt` + `differential` via the committed `../../scripts/cargo.sh`, runs `suite --strict --allowlist <script_dir>/known-gaps.txt --json --out <tmpdir>`, and maps the written `report.json` (its top-level `summary` and `ratchet` blocks) to its own exit code.

### Library (`src/lib.rs`) — the public API `cargo test` asserts against
- `error` — `Error` (`Usage`/`Env`/`Io`, all → exit `2`), `Result<T>`. Tool-level errors are host-tool errors; BEAM exceptions are *observed **data*** (never the harness's own failure mode), so `beam_common::BeamError` does not model this crate's failures.
- `cli` — `Command` (`Run{case_id,…}`, `Compare{expr,pa,…}`, `Suite{strict,allowlist,gaps,…}`, `List{by_contract,json,out}`, `Help{…}`), `parse(args)`, `usage(topic)`.
- `allowlist` — the known-gaps allowlist: `AllowEntry{case_id,crate_name,reason}`, `Allowlist::parse(source,path)`/`load(path)`/`empty()`, `path()`/`entries()`/`len()`/`is_empty()`/`get(id)`/`contains(id)`. A malformed or duplicate entry is a loud `Error::Usage`, a read failure a loud `Error::Io` (both exit `2`).

## Runtime resolution (shared convention; no baked absolute paths without an overridable default)
- **Oracle** = `$ERTS_ORACLE` if set, else `erl` on `PATH`; missing -> loud `Error::Env` (exit 2).
- **Rust runtime** = `$BEAM_RT` if set (must exist, else `Error::Env`), else `<CARGO_MANIFEST_DIR>/../../target/{release,debug}/beam_rt`; neither present -> the Rust side reports `unsupported` (never a crash, never a fabricated pass). The profile order is **`release` before `debug` on purpose** (the real CLI and `gate.sh` want the fastest artifact present); that order is wrong under `cargo test` (only `debug` is rebuilt), so the **integration tests inject `$BEAM_RT`** pointing at the fresh debug runtime instead (see *Design Decisions*). The order itself is never changed.
- **Compiler (`erlc`)** = `$ERLC` if set (must exist, else `Error::Env`), else `erlc` on `PATH`; missing -> `Ok(None)`, so module-run cases are **skipped loudly** (`Verdict::Skipped`), never a silent pass.
- **Distribution helper (`dist_probe`)** = `$BEAM_DIST_PROBE` if set (must exist, else `Error::Env`), else `<CARGO_MANIFEST_DIR>/../../target/{release,debug}/dist_probe` (release before debug, mirroring the runtime); neither present -> the `dist/*` command cases' Rust side is absent and they are **skipped loudly** (`Verdict::Skipped` carrying `resolve_helper`'s reason), never a pass.
- **C toolchain (NIF cases only)** - `cc` = `$CC` (an existing executable, or a command on `PATH`), else `cc` on `PATH`. `erl_nif.h` is located by `resolve_erl_include()`: the oracle's `erl code:lib_dir(erts,include)`, then the `erts-*/include` sibling of the `erl` on `PATH` (the working probe - `code:lib_dir` alone returns a non-existent path here), then standard roots (`$ERL_TOP`, `/usr/lib/erlang`, …). Either missing -> `Build::Skipped(MISSING_CC_REASON | MISSING_ERL_NIF_REASON)` -> the case is `Verdict::Skipped` (never run, never reported as agreement, never a crash).
- Expression cases invoke both runtimes with the **same argv** (only the program path differs); module-run cases with per-side argv (*Probe protocol*); command cases with a fixed per-side program + argv (the oracle side is the resolved `erl`, the Rust side the resolved `beam_rt` or `dist_probe`).

## gate.sh — the checkable compatibility gate
`gate.sh` wraps `differential suite --strict --allowlist known-gaps.txt` for CI: from the repo root it runs `erts_rust/scripts/cargo.sh build --manifest-path erts_rust/Cargo.toml -p beam_rt -p beam_dist -p differential` (the `beam_dist` build produces the `dist_probe` helper the `dist/*` cases drive), then `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite --strict --allowlist <script_dir>/known-gaps.txt --json --out <tmpdir>`, and turns the report's **top-level `summary`** and **top-level `ratchet`** blocks into a CI exit code:

| Exit | Meaning |
|------|---------|
| `0`  | no mismatch, every non-agreeing case is an allowlisted capability gap, and the allowlist is fresh (no unauthorized gap, no stale entry) |
| `1`  | ≥1 **mismatch** — a real, observable behavioral divergence (including oracle-vs-its-own-golden corpus drift); also a top-level `summary` that cannot be parsed (fail loud) |
| `2`  | usage / environment error — a missing oracle, a build failure, a missing allowlist, a report that could not be produced, or a top-level `ratchet` block that cannot be parsed |
| `3`  | no mismatch, but the **ratchet must be updated**: ≥1 `unsupported`/`skipped` case is not in the allowlist (an unauthorized gap), or ≥1 allowlist entry did not reproduce as a gap (a stale entry) |

**Invariant:** an `unsupported` case (a capability gap the Rust runtime signals via its documented exit `3` / `beam_rt: unsupported: …` reason convention, or a missing `beam_rt`) is **never** reported as a mismatch. Exit `1` is reserved for a case whose runtime actually produced a *differing observable result*; a capability gap can only ever land in the `unsupported`/`skipped` buckets, so it causes exit `3` when it is **not** allowlisted and exit `0` when it is.
The `1`-vs-`3` distinction is read **solely** from the **top-level `summary`** and **top-level `ratchet`** objects (authoritative); the per-contract `by_contract` rollup — which also carries `mismatch` keys, at a deeper indent — is deliberately ignored. An unparsable summary **fails loud** (exit `1`) rather than risk a false pass (`0`); an unparsable ratchet block (an unexpected report shape) fails loud (exit `2`). The gate's unauthorized/stale **id lists** are restricted to genuine gaps (`unsupported`/`skipped`), so a `mismatch` can never be recorded as an "allowed" gap.
The binary's own `run`/`suite` exit codes are unchanged (`0` agree / `1` mismatch / `2` usage-env; a lenient `run` on an unsupported case stays `0`) — the `0/1/2/3` mapping belongs to the gate script only.

## Constraints
- **Honest reporting:** a side that cannot run is `unsupported` / `skipped(<reason>)` — **never** `pass`, and oracle observations are **never** fabricated. A case whose *oracle* disagrees with its golden is itself a failure (corpus drift), surfaced as a mismatch — the harness is self-testing.
- **No coupling to `crates/*` internals** (crate deps are `serde` + `serde_json` only). No `clap`; arg parsing is hand-rolled `std`. `unsafe` is **forbidden**.
- **Loud failures:** stderr messages + nonzero exit; never silently swallow an error. Machine-readable JSON, stable schema, written under the gitignored `out/` (or `--out <dir>`).
- Files target ~1000 lines; split by responsibility. Apache-2.0. The corpus group files are **data registries** (one embedded module/expression per case) and legitimately run past the soft target (see the routing table for the specific files); do not split them for line count alone. The `report` module is a directory module split by responsibility.
- The built-in corpus is the **conformance corpus** (1871 cases) and runs end to end in CI; keep it fast enough for that and reserve the heavy external suites (root §6) for milestones.
- **Never assert a golden whose output is order-unstable.** A `~w` rendering of a multi-key map (or any structure containing one) has a per-VM-start iteration order, so compare it structurally (`maps:size`, `lists:sort(maps:keys(M))`, single-key maps) instead. Same rule for pids/refs/ports/creation values that vary per VM start, and for a `load_nif` failure message that embeds a temp-dir path — assert a shape or classify into an integer, or use a deterministic decode→re-encode round-trip.

## Design Decisions
- **Probe wrapper is mandatory** because `erl -noshell -eval '<expr with uncaught error>'` emits no stdout and exits 1, so without it an exception is invisible to a stdout diff.
- **The environment-variable surface is a separate case kind, not a field on `Eval`/`Module`.** `CaseKind::EvalEnv { expr, extra_argv, env, probe }` is `Eval` plus an explicit `env: &'static [(name, value)]`, and `CaseKind::ModuleEnv { run, extra, env }` is the module-run counterpart (its `extra` helper modules are compiled into the same temp dir and its `env` values may embed `DIR_PLACEHOLDER`); both are **separate variants** so the existing `CaseKind::Eval`/`CaseKind::Module` literals stay untouched. An eval-env case's argv and observables/classification are identical to `Eval`; the only difference is the spawn path: `runtime::run_with_env(spec, argv, env)` sets each variable **on top of** the inherited environment (never cleared) so `$PATH`/`$TMPDIR` resolution is undisturbed. `harness::RunPlan` carries `env` (a **`Vec<(String, String)>`**, empty elsewhere) and `execute` always calls `run_with_env` (one spawn path); `Case::env()` is `&[]` for the non-env cases. The owned env exists because a `ModuleEnv` value embeds the compiled dir, known only after the compile: `runtime::own_env` converts a case's `'static` slice, `corpus::expand_env` substitutes `{dir}`.
- **The A.6 `ERL_*FLAGS` cases pin the merge order, and are oracle-derived.** `flags/env_*` covers `ERL_AFLAGS` prepended before the command line, `ERL_FLAGS` merged after it, a quoted `ERL_FLAGS` value surviving the tokenizer, the full `[ERL_AFLAGS] [command line] [ERL_FLAGS]` order, and `[ERL_FLAGS] [ERL_ZFLAGS]`; two `+P` cases make "a later source overrides an earlier one" *effective* via `erlang:system_info(process_limit)`.
- **`mismatch` is reserved for a runtime that produced a differing observable result** (classification is signal-based, never heuristic — the two signals are in *Observable results*). `verdict_with` must use the *same* `Observables` as the reported `diffs`, so a case can never show an empty diff list yet be a `Mismatch`.
- **Expression cases classify stderr; module-run cases do not.** `significant_stderr` drops only the documented boot banner (narrow by construction), so it can only ever drop a known banner, never fabricate agreement. `compare_observations_with` reports the classified buffers.
- **Golden per case** lets the harness self-test: the oracle must reproduce it while the Rust side reports whatever it really does. If the oracle stops matching its golden, that is real failure (drift), not a skip.
- **Volatile `system_info` keys use structural goldens** (`is_integer(process_count)` -> `true`, `is_list(otp_release)` -> `true`) and `version` -> `<<"17.1">>` (the frozen erts target). `otp_release` is deliberately **not** asserted by exact value: the oracle is OTP 29 while the rewrite targets OTP 30.
- **NIF cases are module-run cases, never `-eval` cases.** The oracle rejects any `erlang:load_nif/2` not called from its own NIF module (`bad_lib`), so `CaseKind::Eval` cannot observe load semantics.
- **NIF cases self-locate and self-classify.** The embedded module loads a suffix-less absolute path built from `filename:dirname(code:which(?MODULE))` (works in both runtimes, so the argv stays untouched), stubs **every** function in the NIF's `ErlNifFunc` table (the oracle refuses a partial stub set), calls the NIF through an **external** call (the Rust runtime intercepts only external dispatch), and maps the `{error,{Reason,_}}` tag to an **integer** so the golden never embeds the volatile temp-dir path. The `.so` is built with `cc -shared -fPIC -I<erl_nif.h> -o <dir>/<name>.so <c_source>` into the case's temp dir.
- **`--strict` escalates `unsupported`/`skipped` to a failure; `--allowlist <file>` turns that into a ratchet.** `--strict --allowlist <file>` tolerates only the gaps the file records: a non-agreeing case whose id is absent is an *unauthorized* gap, and an entry whose case did not reproduce as a gap is *stale* — either fails. The default (no flags) keeps capability gaps non-fatal. `--allowlist` requires `--strict`; a `mismatch` is never toleratable.
- **A golden is a stdout *line*, without the trailing newline**: `compare::check_golden` normalizes the observation with `normalize_probe_stdout` (strips one trailing `\n`, and a preceding `\r`) before comparing it to `Golden::stdout`.
- **Child spawns retry a bounded `ETXTBSY` only.** Every production spawn (`runtime::run`, `module_build::compile`, the C compile) goes through `runtime::output_with_retry`: a `#!/bin/sh` script is legitimately executed here, and when one thread `fork()`s while another holds a descriptor open **for writing** that script the kernel transiently refuses the `exec` with `ETXTBSY` (errno 26). The helper retries that one condition up to 6 attempts with a **doubling, capped** backoff (5 → 80 ms = 155 ms; `ErrorKind::ExecutableFileBusy`), then returns the **same** error so a surviving failure stays loud; every other error is returned unchanged.
- **Integration tests inject the freshly built debug runtime.** `tests/common/mod.rs::fresh_rust_runtime()` returns the `beam_rt` next to `CARGO_BIN_EXE_differential`, and every test that exercises the real runtime injects it as `$BEAM_RT` (or builds `harness::RuntimeContext{ oracle, rust: fresh_rust_spec() }`), so a **stale `target/release/beam_rt` can never shadow the fresh debug build**. The **suite** test also accounts for the runtime the **child** resolves: when the fresh debug sibling is absent but a workspace-default `target/{release,debug}/beam_rt` is resolvable, the child falls back to it and agreement **is** exercised (`agree >= 1`); the `agree == 0` branch is reached only when the child has no resolvable Rust runtime at all, or when `erlc` is missing — `tests/oracle.rs::an_absent_rust_runtime_reports_unsupported_never_agreement` guards the forced-absent path.
- **Test scratch dirs are worktree-local, never the ambient `$TMPDIR`.** `tests/common/mod.rs::scratch_root()` returns `CARGO_TARGET_TMPDIR` (`<worktree>/erts_rust/target/tmp`), and `tests/cli.rs` roots both its `Scratch` dirs and the child's `TMPDIR` there. `tests/oracle.rs` keeps `std::env::temp_dir()` for the `manifest_dir` *outside* `target/` (a `CARGO_TARGET_TMPDIR` base there would make the "absent Rust runtime" case find a real runtime).
- **Reports are always written** (`--out <dir>` sets the directory, default `out/`); `--json` only decides what goes to stdout. An ad-hoc `compare` asserts no golden, so its report carries `matched_golden: null`.
- **The per-contract rollup is purely additive and derived.** `RunReport.by_contract` maps each contract id present in the run to the same `Summary` shape as the top-level `summary` (a multi-contract case contributes to each, so the per-contract `total`s need not sum to `summary.total`). The `list` listing carries `by_contract` only with `--by-contract` (`serde(skip_serializing_if = "Option::is_none")`), so the plain `list` output is byte-for-byte unchanged. Schema ids are **not** bumped: both changes only add keys.
- **The `ratchet` block is likewise additive, and the allowlist drives the gate.** `RunReport.ratchet` is `Option<RatchetReport>` (`skip_serializing_if = "Option::is_none"`), so a run without an allowlist is byte-for-byte unchanged and the schema id is **not** bumped. `RatchetReport::classify` marks every `Unsupported`/`Skipped` case `allowed` or `unauthorized` (a `Mismatch` is never a gap) and counts the allowlist entries that did not reproduce (`stale`); `suite_exit_code` returns `1` iff `has_mismatch(report)` — which reads the **case verdicts**, not only `summary.mismatch`, so a mismatch can never be masked by a report summary — else (with a ratchet) iff `unauthorized`/`stale` is non-zero, else `0`.
- **`GAPS.md` is a generated document, never hand-edited**; `known-gaps.txt` is the source of truth. `--gaps <path>` renders the current gap table (each gap `allowed`/`unauthorized`, then the `stale` entries) via `ratchet::gaps_markdown`/`write_markdown`, and appends the hand-maintained `divergences.md` ledger of observed-but-unpinned divergences.
- **`erlc` (and NIF `.so`) compile results are memoized** in a process-local cache (keyed by compiler path + module + exact source, or by the C fixture), so the module-run cases replace dozens of spawns with a handful while every case still gets its **own** temp dir and unchanged argv. The cache stores the compiled `.beam` **bytes**, not a `CompiledModule`, precisely so each `CompiledModule` keeps removing its own temp dir on drop. A failed/absent compiler is never cached, so a compile failure stays a loud error on every call.
- **"Modules execute", not "modules load".** The crate-level *load* sweeps (`../crates/beam_loader/tests/real_modules.rs`, `../crates/beam_engine/tests/stdlib_sweep.rs`) prove real `.beam`s decode; this harness adds the **execute** dimension: the `mexec`/`mexec_extra` groups (tiny `erlc`-compiled wrappers calling a real system module), the `nif_so`/`nif_res`/`nif_abi`/`nif_abi_extra` groups (a compiled module that loads a real `cc`-built NIF `.so`), the `driver_c`/`driver_abi`/`driver_abi_extra` groups (a real C driver `.so` driven through the port lifecycle), and `tests/module_sweep.rs` (kept out of the default `suite`). Every outcome must be `Agree` or `Unsupported`/`Skipped` — never `Mismatch`.
- **The A.3/A.4 structural C-ABI check is load-bearing.** `tests/abi.rs` resolves the target's pointer size from `__SIZEOF_POINTER__` and synthesizes `erl_int_sizes_config.h`; it then `-fsyntax-only`-compiles a C TU that references the `enif_*`/`driver_*`/`erl_drv_*` surface **and** `_Static_assert`s the frozen `ERL_NIF_TERM`/struct sizes+offsets mirrored from `../crates/beam_abi` (read-only), plus self-tests that a bogus symbol and a wrong frozen size both fail. It skips **loudly** only when no C compiler / headers / integer sizes are discoverable.

## How to add a corpus case (the corpus is code, not a manifest)
- **The corpus is a Rust registry, not a directory scan or data file.** Each contract group is a module `src/corpus/<group>.rs` exposing `pub(crate) fn group() -> Vec<Case>`; `src/corpus/mod.rs::build_corpus()` concatenates them into a `OnceLock<Vec<Case>>`. A new group MUST be declared (`mod <group>;`) and appended in `build_corpus()`.
- **A case id is `<group>/<name>`, but its `<group>` segment is a *subdivision*, NOT the Rust file name** — one file may emit several prefixes (`ets_spec.rs` ⇒ `ets/…` + `ets_spec/…`; `bifs.rs` ⇒ `bifs/…` + `lists/…`; `terms.rs` ⇒ `terms/…` + `errors/…`; `printing.rs` ⇒ `print/…` + `float/…`; `phash.rs` ⇒ `phash/…` + `phash2/…`), so per-file counts are NOT derivable from id prefixes. Count a group's cases by its quoted `"<prefix>/<name>"` literals; only `wire_ids.rs` (`node_identity_cases()`) and `ets.rs` build cases in a loop.
- A `Case` is `{ id, description, contracts: &[Contract], kind: CaseKind, golden: Golden }`. `CaseKind::Eval { expr, extra_argv, probe }` gives both runtimes **identical** argv; `CaseKind::EvalEnv { expr, extra_argv, env, probe }` also spawns each runtime with an explicit `env` (the `ERL_*FLAGS` surface); `CaseKind::Module(ModuleRun { source, module, function, arity, args: &[i64], nif })` compiles the embedded module with `erlc` and drives the oracle (`-pa`+`-eval`) vs `beam_rt run` with **integer args only** (stdout + exit compared; stderr not); `CaseKind::ModuleEnv { run, extra, env }` is that shape plus the case environment (its `{dir}` placeholder expanded to the compiled dir) and **no** oracle `-pa`, with the `extra` helper modules compiled into the same dir; `CaseKind::Command(CommandRun { oracle, rust })` spawns each side's `CommandSpec { program: CommandProgram::{Oracle,Rust,Helper}, args }` with the case argv and compares stdout + exit status only (the non-CLI stage — `dist/` drives the external `dist_probe` helper for a live distribution loopback). `Golden { stdout: Option<&'static str>, exit_code }` is the **oracle's** expected output line (no trailing newline) - the corpus's own drift self-test.
- The two ABI contract ids are `Contract::NifAbi` (A.3) and `Contract::DriverAbi` (A.4).
- A **widened** group mirrors an existing one as a second block with its own id prefix (`nif_abi_extra.rs` ⇒ `nif_extra/…`, `driver_abi_extra.rs` ⇒ `driver_extra/…`, `mexec_extra.rs` ⇒ `mexec_extra/…`) and its own contract claim; it is an ordinary group to the registry.

### Adding an A.3 (NIF C ABI) case - needs no harness change
- Reuse the `nif_so` shape: a `CaseKind::Module` case carrying `Some(NifFixture::CompiledLibrary { name, c_source })`. `module_build::build` compiles the C with `cc -shared -fPIC -I<erts include>` into the case's own temp dir; the module self-locates `<dir>/<name>` (suffix-less, so both runtimes append `.so`).
- The `nif_abi`/`nif_abi_extra` groups widen this: one shared C library whose only `ErlNifFunc` entry is `probe/1`, driven by an integer selector through an **external** call — one new `enif_*` behaviour is one C `switch` case plus one corpus entry, and every golden stays a VM-stable integer.
- **Hard constraint: the C may only reference `enif_*` symbols the Rust runtime really defines.** Both runtimes `dlopen(RTLD_NOW)` the same `.so` and the host `erl_nif.h` declares each `enif_*` as a direct `extern` symbol, so a symbol the Rust runtime does not export makes the *Rust* load fail (`{error,{load_failed,…}}`) while the oracle loads it - a **mismatch**, not a capability gap. The exported set is the `pub extern "C" fn enif_*` in `../../crates/beam_abi/src/nif/enif/` (the slots `enif_api_table()` fills). A resource's **destructor** stays unpinnable: the oracle schedules it on a misc aux-work thread (`nif_resource_dtor_prologue`), unobservable inside the NIF call.
- Load rules a NIF case must honor (pinned by `nif_so`): call `erlang:load_nif/2` from the NIF module itself; stub **and export** every function in the library's `ErlNifFunc`; make the NIF calls **external**; classify the `{error,{Reason,_}}` tag to an integer (never print the path-bearing `Text`).

### Adding an A.4 (driver C ABI) case - no harness change
- The `driver_c` group loads a **real C driver `.so`**: a module-run case claims `Contract::DriverAbi` (allowed by `src/corpus/mod.rs::module_run_cases_are_registered_and_well_formed`, allow-list `BeamAsm|LanguageSemantics|OtpApps|NifAbi|DriverAbi|Build`) and carries `Some(NifFixture::CompiledLibrary { .. })`, compiled against the erts include dir (which also holds `erl_driver.h`). The module opens the driver as `open_port({spawn_driver, Dir ++ "/<name>"}, ...)`: the Rust runtime's `driver_lookup` treats a name containing `/` as the object path and validates the entry name against the file stem; the oracle needs the object pre-loaded with `erl_ddll:load_driver/2`, so `driver_c`'s `open/2` tries the path form and falls back to the loaded bare name. A working fixture pattern is `../../crates/beam_io/tests/fixtures/host_driver.c`. The `driver/*` group separately drives the **built-in `spawn`/`spawn_executable` drivers** through `open_port/2` (ids like `driver/spawn_driver_port_stream_read` name the *built-in spawn driver*, not `{spawn_driver, Name}`).
- The `driver_abi`/`driver_abi_extra` groups widen this: one shared C driver `.so` whose `output` callback dispatches on a one-byte `port_command/2` selector — an ABI check answering a single status byte, a `driver_output*` byte delivery (answered as the base-256 integer of the delivered bytes), or a `driver_select`/`driver_set_timer` arm answered later by `ready_input`/`ready_output`/`timeout` — so one new slot is one selector case.
- The driver echo round trip runs only once `beam_rt run` drives the full scheduler (`Runtime::run_scheduled`); a single engine pass never runs the scheduler's port half, so the receiver blocks and the CLI exits `3` with `beam_rt: unsupported: ... blocked` (a capability gap, never a mismatch, never a hang).

Exit `3` means the ratchet must be updated — an *unauthorized* gap or a *stale* entry — so a PR that changes capability coverage must refresh `known-gaps.txt` (the source of truth) **and** the generated `GAPS.md` in the same change.
- **A probe expression must not bind `V`, `C`, or `R`.** The probe wrapper binds `of V -> … catch C:R -> …`, so a user expression that also binds `V`/`C`/`R` makes the *oracle* fail to compile the wrapped expression (`unsafe_var`, empty stdout, exit 1) — a guaranteed false mismatch. Use other names (e.g. `Reason`, `Msg`).

  - ETS access control (`beam_ets`/`beam_bifs`): the mode is recorded at `ets:new/2` but not enforced for a non-owner (a private read returns `[]`, a protected/private write returns `true`), and `ets:info(T, owner)` is `undefined`.

  - CLI flags (`beam_rt`): plain `-extra`/`--` arguments are unusable through the harness; a repeated `-eval` is recorded verbatim vs `init:get_argument(eval)` -> `error`; an unbound `-eval` variable is a loud error vs silent.
  - Environment variables (`ERL_*FLAGS`): the merge *order* **is** pinned (`flags/env_*`); `ERL_OTP<sysver>_FLAGS` (29 vs 30) and an `-eval` carried by `ERL_FLAGS`/`ERL_AFLAGS` are deliberately not.
  - `+Q N` / `ERL_MAX_PORTS` → `system_info(port_limit)` **is** pinned (the `next_power_of_two` sizing matrix); `+Q legacy` / no `+Q` -> 65536.
  - `erlang:module_loaded/1` (`beam_bifs`): `module_loaded(lists)` is `true` vs `false`.
  - `erlang:trace_info/2` (`beam_bifs`): the `all`/`traced` selectors differ (`badarg` vs a value list); only `flags`/`tracer` agree.
  - `erlang:halt/1` (`beam_rt`): `halt([1,2])` prints nothing (exit 1) vs exiting with `beam_rt_dump:`; only `halt({bad})` -> `badarg` is pinned.
  - `+hmax` overflow (`beam_rt`): the oracle kills the process where the Rust evaluator raises `error:system_limit`; only the tiny bounded allocation case is pinned.
  - `erlang:memory/0,1` is pinned **structurally** (A.8): the 9-key order and count, `is_integer(memory(total))`, the selection shape and the unknown-key `badarg`; the volatile byte totals are never asserted.

- **What `beam_rt` must do for an expression case to reach `agree`:** the eval cases spawn `beam_rt -noshell <extra…> -eval <probe>` and compare **stdout + exit + stderr** against the oracle (module-run cases: stdout + exit only). `erl -eval` does **not** echo the value - the probe prints the single `ok …` / `exception <class> <reason>` line itself and `halt`s - so `beam_rt -eval` must likewise **not** auto-print the result and must evaluate the whole single-line `try (EXPR) of V -> … catch C:R -> … end.` wrapper. The module-run side uses `beam_rt run <file.beam> <mod>:<fun>/<arity> <args…>`, which must print `~w` of the result + a trailing newline.
- **Residual: the module/temp-dir helpers still root temp dirs at `std::env::temp_dir()`**, so the **in-process** tests (`tests/oracle.rs`, `tests/module_sweep.rs`) place `.beam`/`.so` temp dirs under the ambient `$TMPDIR`. Run them with a private `TMPDIR` where `$TMPDIR` is shared/cleaned (the `tests/cli.rs` child processes are already independent of it).
- **The compared observables are process I/O only.** `harness::execute` compares stdout + exit status (plus the classified stderr for `Eval`/`EvalEnv` cases); it never reads a file either runtime produced. A file artifact is observable only if the Erlang side reads it back and encodes it into stdout (e.g. `io:format("~w~n",[erlang:phash2(file:read_file(P))])`). A module-run temp dir materializes `<module>.erl` + `<module>.beam` (+ any `NifFixture`), and the module self-locates it with `filename:dirname(code:which(?MODULE))`.
- **No per-case timeout, and no `.beam`-byte assertion.** `runtime::run_with_env` calls `Command::output()` and blocks until the child exits (the `after 2000 ->` guards are case-level Erlang, not a harness guard), so a long-running case blocks the suite. No corpus case asserts a compiled `.beam`'s bytes or `beam_lib:chunks` output; the only byte-equality checks are the `module_build`/`nif_build` cache tests (the same compiler's output compared to itself).
- Build/test via the committed wrapper (read-only `$HOME`): `../../scripts/cargo.sh test --manifest-path ../../Cargo.toml -p differential`. Known deps (`serde`, `serde_json`) resolve **offline** — add no new crates.

## Test Strategy
- `#[cfg(test)]` unit tests in every core module: `cli` (arg parsing for `run`/`compare`/`suite --strict --allowlist --gaps`/`list --by-contract`, and `--help`); `allowlist` (parse: comments/blank lines, the trailing `\r`, whitespace-separated tokens, the malformed/duplicate usage errors, a missing-file `Io` error, the load round trip, `empty`); `ratchet` (the gap/unauthorized/stale classification, `has_mismatch`, `report_from_suite`, `suite_exit_code`, `gaps_markdown`); `runtime` (env injection incl. `own_env`, argv shapes, the bounded `ETXTBSY` retry); `compare` (the diff + golden logic, stderr classification, the `Unsupported`-vs-observation rules); `corpus` (registry well-formedness: unique ids, >=1 contract each, per-kind goldens, the module-run argv shape + contract allow-list, only an `EvalEnv`/`ModuleEnv` case sets an env, never an empty one, and `expand_env` substitutes `{dir}` in the values only); `module_build`/`nif_build` (erlc/cc resolution, a loud compile failure, temp-dir cleanup, the `erl_nif.h` locator, the `.so` build + cache, the skip reasons); `harness` (exit-3 classification, the unsupported reason, the eval probe shape, the caught-capability-gap classifier); and the per-group registry tests (`nif_so` integer classification, `ets`, `records` opcodes, `flags_apply`).
- `tests/common/mod.rs` is the shared support module for the integration tests (a `tests/` subdirectory module, so it is never its own test binary): `fresh_rust_runtime()`/`fresh_rust_spec()` and `scratch_root()`. `src/test_support.rs` is the `#[cfg(test)]`-only in-crate counterpart (a `Scratch` dir, a counting/fabricating compiler stub) shared by the `module_build`/`nif_build` tests.
- `tests/oracle.rs` integration: **oracle-backed** - the oracle reproduces the `{ok,42}` golden; every **expression** case reproduces its golden (the `EvalEnv` cases through `run_with_env`); every **module-run** case reproduces its golden under the oracle (compiled with `erlc`, its NIF fixture materialized by `module_build::build`, which reports `Build::Skipped` for a missing host tool), including the `ModuleEnv` cases (their helper modules compiled with `module_build::compile_extra_into`, their env's `{dir}` expanded via `corpus::expand_env`, the oracle argv carrying no `-pa`); oracle-vs-oracle on the same case => `Verdict::Agree`; a Rust runtime forced to a nonexistent path => `unsupported` (never `pass`). It builds an explicit `RuntimeContext` with the fresh runtime; these **skip with a loud note** (not a silent pass) when `erl`/`erlc`/`cc` is unavailable.
- **The transient-`ETXTBSY` retry (mechanism in *Design Decisions*) is covered deterministically.** On Linux, `exec`ing a file held open for writing returns `ETXTBSY` at the VFS level, so the tests hold the descriptor open and assert the retry is bounded + surfaces the error (`runtime::tests::output_with_retry_is_bounded_on_etxtbsy_and_surfaces_it`, `module_build::tests::a_compiler_that_cannot_be_exec_yet_is_a_loud_error_not_a_hang`), that it recovers once the writer releases, that any other error is returned unchanged and that a successful spawn passes through.
- `tests/cli.rs` drives the **binary** as a child process (so `$ERTS_ORACLE`/`$BEAM_RT`/`TMPDIR` can be injected without touching the test process environment) and locks in the exit-code contract (`0`/`1`/`2`), the `--help` surface, the `--out` report file and the `list` path that needs no runtime. Every default-resolution invocation injects `$BEAM_RT` = the fresh debug runtime. It also injects a fake `$BEAM_RT`: one printing a different stdout must still be `[MISMATCH]` (exit 1), one printing `beam_rt: unsupported: ...` and exiting `3` must be `unsupported` (exit 0 lenient, `1` under `--strict`). Oracle-dependent cases skip loudly when `erl` is unavailable.
- The suite assertion **never pins the current capability-gap count**: it checks the state-independent invariant that every case falls into exactly one verdict bucket (`agree + unsupported + skipped + mismatches == summary.total`) plus the branch-specific `agree >= 1` / `agree == 0`. The "is agreement possible" gate mirrors the runtime the **child** resolves (the injected fresh debug sibling **or** the workspace default via `runtime::resolve_rust_from(None, CARGO_MANIFEST_DIR)`).
- Gate: `cargo test -p differential` GREEN and `differential suite --json` runs end-to-end with every mismatching id listed in `tests/cli.rs`'s `KNOWN_RUNTIME_GAPS` (empty — zero mismatches today). The ratchet is exercised end to end against the real corpus with a fake exit-`3` runtime (`tests/cli.rs::the_ratchet_tolerates_only_the_recorded_gaps_end_to_end`: an allowlist recording every case id is exit `0`; a missing id plus a bogus id is exit `1` and names both in the generated `GAPS.md`). The CI gate is `gate.sh`.
- `tests/abi.rs` covers A.3/A.4 structurally (mechanism in *Design Decisions*) and skips loudly when no `cc`/`gcc`/`clang` is available (no `crates/*` dependency, no `unsafe`).
- `tests/module_sweep.rs` is the broad real-module **execute** sweep (**277 entries across 35 real system modules**: 273 `agree`, 4 honest `unsupported`), driven through `differential::harness` under both runtimes; every outcome is `Agree`/`Unsupported` (never `Mismatch`), with a per-module rollup; skips loudly without the oracle/`erlc`.
- The `corpus` registry tests assert all nine contracts A.1-A.9 are represented and that >=20 module-run (genuine-agreement) cases exist.
- The per-contract rollup, the `ratchet` key and the `list --by-contract` view are covered by `#[cfg(test)]` unit tests in `report/` (`by_contract` counts + a multi-contract case, the additive `ratchet` key omitted and unrendered without an allowlist, the contract-free `compare` rollup, the grouped listing keeping the plain output unchanged) and in `cli.rs` (the `--by-contract`/`--strict`/`--allowlist`/`--gaps` parsing, only `suite` taking the last two).

Harness / data:
- `tests/common/mod.rs` -> shared integration-test support: `fresh_rust_runtime()`/`fresh_rust_spec()` + `scratch_root()` + `corpus_run_lock()` (the process-wide mutex serializing the corpus-running `tests/cli.rs` bodies against epmd node-name contention)
- `tests/abi.rs` -> A.3/A.4 structural C-ABI check: `-fsyntax-only`-compiles a C TU referencing the `enif_*`/`driver_*`/`erl_drv_*` surface and `_Static_assert`s the frozen sizes/offsets, against the in-tree legacy C headers `erts/emulator/beam/{erl_nif.h,erl_driver.h}` (a manual mirror of `crates/beam_abi/src/layout.rs`); a missing header or compiler ⇒ a loud skip, never a failure.
- `tests/module_sweep.rs` -> the broad real-module **execute** sweep (277 entries / 35 real system modules; 273 `agree` + 4 `unsupported`) - asserts `Agree`/`Unsupported`, never `Mismatch`; skips loudly without the oracle
- `tests/oracle.rs` -> oracle-backed integration tests (golden reproduction for eval + module cases incl. the NIF fixtures, oracle-vs-oracle, missing Rust runtime)

The four tests that run the **real corpus** hold the process-wide `common::corpus_run_lock()` for their whole body, so at most one full sweep (hence one `-sname`/`-name` `erl`) runs at a time — two concurrent sweeps race for the same `epmd` node name, and the losing oracle then fails to reproduce `flags/sname_switch_value`'s golden, surfacing as a **spurious oracle-side mismatch**. Do not remove the lock.
- `gate.sh` -> the CI gate wrapper over `suite --strict --allowlist known-gaps.txt` implementing the `0/1/2/3` ratchet contract
- `known-gaps.txt` -> the committed known-gaps allowlist (one `<case-id> <owning-crate> <reason…>` per line; `#` comments and blank lines ignored) — the ratchet's source of truth
- `GAPS.md` -> the generated gaps document (`--gaps`), never hand-edited; it appends the hand-maintained `divergences.md` ledger of observed-but-unpinned divergences
- `divergences.md` -> the hand-maintained ledger of observed-but-unpinned divergences (surfaced through the generated `GAPS.md`)
- `out/` -> gitignored JSON report output (default `--out`)
