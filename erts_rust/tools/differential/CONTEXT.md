# differential — Rust ERTS vs System ERTS Compatibility Gate

## Intent
The in-repo **differential-test harness** (Stage 0; `../../../ERTS_RUST_REWRITE_DEEPDIVE.md` §H) and the rewrite's **compatibility gate** (`../../../ERTS_RUST_REWRITE_EVALUATION.md` §G.7/§I): for each corpus case it runs the **real system ERTS** (the *oracle*) and the **Rust runtime** (`beam_rt`) and compares the **observable results**. A pure **driver/observer** — it never modifies the runtime and never inspects its internals; the only contract with `beam_rt` is its documented external CLI (**A.6**). It honors every shared convention in `../CONTEXT.md`.
Cargo **binary + library** crate `differential`: the library lets `cargo test` assert the harness itself (oracle goldens, oracle-vs-oracle equality, diff detection); the binary is what a human or CI drives.

## Case kinds (`CaseKind`) — five, selected by how the argv is built
- **`Eval { expr, extra_argv, probe }`** — expression case: both runtimes get the **same** argv `["-noshell", <extra…>, "-eval", <probe>]`.
- **`EvalEnv { expr, extra_argv, env, probe }`** — `Eval` + an explicit `env` (the A.6 `ERL_*FLAGS` surface).
- **`Module(ModuleRun { source, module, function, arity, args, nif })`** — compile the embedded module with `erlc` (+ optional NIF fixture), then **per-side** argv: oracle `["-noshell","-pa",<dir>,"-eval",…]`, Rust `["run","<dir>/<mod>.beam","<mod>:<fun>/<arity>",<int-args>]`.
- **`ModuleEnv { run, extra, env }`** — `Module` + the case `env` (its `{dir}` placeholder expanded to the compiled dir) + `extra` helper modules in the same dir; the oracle argv carries **no** `-pa`, so the dir reaches the code path only through the environment.
- **`Command(CommandRun { oracle, rust, peer })`** — the **non-CLI stage**: each side is a `CommandSpec { program: CommandProgram::{Oracle,Rust,Helper}, args }` with **its own** argv, and only **stdout + exit status** are compared. The oracle side is always `Oracle`; the Rust side may be `beam_rt` or the external `dist_probe` helper (the `dist/` group, A.5 live two-node loopback). A command case carries **no** per-case env and **no** stdin.
- **`Command` + an optional peer leg (`peer: Option<PeerRun>`)** — a **second process of that side's own runtime**, never the other runtime (`PeerRun` has no program field), so a peer-carrying case is a two-VM **self-pair**: the side is the client and talks to a peer of its own program (the oracle leg pairs with an oracle peer, the Rust leg with a Rust peer). `PeerRun { args, ready_prefix }`; the peer's stdout is never a compared observable — only the client's is. One case uses it: `dist/live_self_pair_handshake_and_message`.
A side whose program is absent makes the case a loud `Verdict::Skipped`, never a pass — except the `dist_probe` helper, which the **binary** builds on demand once before reporting it missing (see *Runtime resolution*). A peer that never becomes ready is likewise a loud `Verdict::Skipped` naming the reason, never an `agree`.

## What is compared, and how a capability gap is classified
Fields: **stdout bytes** and **exit status** always; **stderr bytes** for expression cases only (`Observables::All`) via a narrow classifier that drops only the Rust boot banner `beam_rt <vsn> booted: …` (`compare::is_runtime_banner_line`/`significant_stderr` — so it can only drop a known banner, never fabricate agreement); the probe's encoded `term_to_binary/1` bytes; the exception class+reason; selected `system_info/1` keys. Module-run/command cases use `Observables::StdoutAndExit`.
A Rust-side gap is `SideResult::Unsupported` — **never** a `mismatch` — via exactly two signals:
1. the child exits `3` (`runtime::UNSUPPORTED_EXIT_CODE`); the reason is its first non-empty stderr line; or
2. an **eval** case's probe *caught* the raise and printed its single `exception <class> <reason>` line with a `<reason>` following the runtime's `unsupported` convention (`harness::caught_unsupported_reason` is deliberately narrow: only the `unsupported` prefix — with a following `:`/`_`/whitespace, or nothing — matches, so a genuine `badarg`/`function_clause`/… stays an observation ⇒ `mismatch`).
`RunPlan::probe_wrapped` is `true` only for `Eval`/`compare_expr`. `mismatch` is reserved for a runtime that produced a *differing observable result* (signal-based, never heuristic); `verdict_with` uses the same `Observables` as the reported diffs, so a case can never show an empty diff list yet be a `Mismatch`.

## Probe protocol (binding)
An expression case carries a plain Erlang expression, wrapped into a self-terminating probe:
- **`Probe::TermToBinary`** (default): `try (EXPR) of V -> io:format("ok ~w~n",[term_to_binary(V)]), halt(0) catch C:R -> io:format("exception ~w ~w~n",[C,R]), halt(1) end.`
- **`Probe::Value`**: same shape but prints `~w` of `V`.
Success ⇒ one line `ok <repr>`, exit `0`; failure ⇒ `exception <class> <reason>`, exit `1`. Expression cases may add extra argv to exercise CLI flags (A.6). A **golden** is the **oracle's** expected stdout **line** (no trailing `\n`); `compare::check_golden` normalizes via `normalize_probe_stdout`. Module-run goldens are **integer lines**; any volatile observable (a temp-dir path, a pid/port creation) is classified into an integer. A golden the *oracle* fails to reproduce is corpus drift ⇒ a mismatch (the harness is self-testing).

## API Surface
**CLI** (hand-rolled `std`-only parsing — **no `clap`**; `--help` on every subcommand):
- `run <case-id> [--json] [--out <dir>] [--out-file <path>]` — one case both ways (`--out-file` writes the report to exactly that path and skips the default `out/report.json`, so a parallel sweep gives each case its own file); `compare <expr> [--pa <dir>]…` — ad-hoc; `suite [--strict] [--allowlist <file>] [--gaps <path>]` — the whole corpus (`--allowlist` requires `--strict`; `--gaps` also writes `GAPS.md`); `merge --from <dir> [--allowlist <file>] [--gaps <path>] [--json] [--out <dir>] [--out-file <path>]` — fold the per-case reports a parallel `run --out-file` sweep produced into one suite-shaped report (deduped + sorted by id) and, with `--gaps`, write the **same** generated `GAPS.md` `suite --gaps` writes, **without re-running any case** (the cheap `GAPS.md`-refresh route, seconds not ~100 min); it never spawns a runtime or the `dist_probe` helper; `list [--by-contract]`.
- Binary exit codes: `0` every executed case agreed (skips/`unsupported` non-fatal), `1` ≥1 mismatch, `2` usage/env. `--strict` escalates gaps to failure; `--strict --allowlist <file>` (the ratchet) tolerates only the recorded gaps and fails (`1`) on an unauthorized gap or a stale entry.
- `gate.sh [--allowlist <file>]` — POSIX `sh`, repo-relative, no baked paths. Builds `beam_rt` + `beam_dist` + `differential` via `../../scripts/cargo.sh`, runs `suite --strict --allowlist <file> --json --out <tmpdir>`, then maps `report.json`'s **top-level** `summary` + `ratchet` to its own exit code (below). The allowlist **defaults to `<script_dir>/known-gaps.txt`** and is overridable with `--allowlist`; `--help` and unknown args are handled before anything is built.

**Library** — the public API is the `src/*.rs` modules listed in the *Routing Table* below (each line names the key items). Notable types: `Observables::{All,StdoutAndExit}`, `SideResult::{Observed,Unsupported}`, `Verdict::{Agree,Mismatch,Unsupported,Skipped}`, `Case`, and `RunReport` (serde `schema: "differential/1"` with additive top-level `by_contract` + `ratchet`).

## Runtime resolution (no baked absolute paths without an overridable default)
- **Oracle** = `$ERTS_ORACLE` else `erl` on PATH; missing ⇒ loud `Error::Env` (exit 2).
- **Rust runtime** = `$BEAM_RT` (must exist, else `Error::Env`) else `<CARGO_MANIFEST_DIR>/../../target/{release,debug}/beam_rt`; neither ⇒ the Rust side is `unsupported`. **`release` is preferred over `debug` on purpose**; that order is wrong under `cargo test` (only `debug` is rebuilt), so the integration tests inject `$BEAM_RT` at the fresh debug runtime. The order is never changed.
- **Compiler** = `$ERLC` (must exist, else `Error::Env`) else `erlc` on PATH; missing ⇒ `Ok(None)` ⇒ module-run cases `skip` loudly.
- **Distribution helper** = `$BEAM_DIST_PROBE` (must exist, else `Error::Env`) else `…/target/{release,debug}/dist_probe` (release before debug). If neither resolves, the **binary** (`runtime::ensure_helper`, for `run`/`suite` only, once per process) runs `../../scripts/cargo.sh build --manifest-path ../../Cargo.toml -p beam_dist` and re-resolves, so a bare `differential suite` never skips the `dist/*` cases for want of a build. `$DIFFERENTIAL_NO_BUILD` (non-empty) disables that build — the side is then a loud `Skipped` naming the reason, as is a *failed* build (with cargo's bounded stderr tail): never silent, never fatal. The library's `resolve_helper` (used by the integration tests, which inject `$BEAM_DIST_PROBE`) never builds.
- **C toolchain (NIF/driver cases)** = `$CC` else `cc`; `erl_nif.h` is located by `nif_build::resolve_erl_include()` (the oracle's `erl code:lib_dir(erts,include)`, then the `erts-*/include` sibling of the `erl` on PATH, then standard roots). Either missing ⇒ `Build::Skipped(...)` ⇒ the case `skips` (never agreement, never a crash).

## gate.sh — the checkable compatibility gate
`gate.sh` builds the runtime + harness, runs the corpus under `--strict --allowlist`, and reads the report's **top-level `summary`** and **top-level `ratchet`** to emit:
| Exit | Meaning |
|---|---|
| `0` | no mismatch, every non-agreeing case is an allowlisted gap, and the allowlist is fresh (no unauthorized gap, no stale entry) |
| `1` | ≥1 **mismatch** (a real divergence, incl. oracle-vs-golden drift); or an unparsable `summary` (fail loud) |
| `2` | usage/env error — missing oracle, build failure, missing allowlist, no report, or an unparsable `ratchet` block |
| `3` | no mismatch, but the **ratchet must be updated**: an unauthorized gap appeared, or an allowlist entry went stale |
**Invariant:** a capability gap (`unsupported`/`skipped`) is **never** a mismatch — it can only cause exit `3` (not allowlisted) or `0` (allowlisted). The `1`-vs-`3` split is read **solely** from the top-level `summary`/`ratchet`; the per-contract `by_contract` rollup (which repeats `mismatch` keys at a deeper indent) is deliberately ignored. The gate's unauthorized/stale id lists are restricted to genuine gaps, so a `mismatch` can never be recorded as "allowed". The binary's own codes are unchanged (`0/1/2`).

## Constraints
- **Honest reporting:** a side that cannot run is `unsupported`/`skipped(<reason>)` — never `pass`; oracle observations are never fabricated. Loud failures (stderr + nonzero exit), never a silent swallow. Machine-readable JSON (`differential/1`), written under the gitignored `out/` (or `--out`).
- **No coupling to `crates/*` internals** (deps: `serde`, `serde_json` only). No `clap`; hand-rolled `std` parsing. `unsafe` is **forbidden**.
- Files target ~1000 lines; split by responsibility. Apache-2.0 (the OTP header block on every `*.rs`). The corpus group files are **data registries** and legitimately run past the soft target; the `report` module is a directory module — do not split them for line count alone.
- The built-in **conformance corpus runs end to end in CI**; keep it fast, and reserve the heavy external suites (root §6) for milestones.
- **Never assert an order-unstable golden** (a multi-key-map `~w`, per-VM-start pids/ports/refs/creation values, a temp-dir-bearing `load_nif` message): assert a shape / `maps:size` / sorted keys, or classify into an integer.
## Design Decisions (load-bearing)
- **Probe wrapper is mandatory**: `erl -noshell -eval '<expr with uncaught error>'` emits no stdout and exits 1, so without it an exception is invisible to a stdout diff.
- **The env surface is a separate case kind, not a field on `Eval`/`Module`** (`EvalEnv`/`ModuleEnv` are new variants, so existing literals stay untouched). `runtime::run_with_env(spec, argv, env)` sets each var **on top of** the inherited env (never cleared) — there is **one spawn path** (`run` delegates to it, and `run_command_case`/`run_module_case` both go through `run_with_env` via `RunPlan`). `RunPlan.env` is an **owned** `Vec<(String,String)>` (empty elsewhere) because a `ModuleEnv` value embeds the compiled dir, known only after the compile (`runtime::own_env` converts the `'static` slice; `corpus::expand_env` substitutes `{dir}`).
- **Compile results are memoized** (process-local): `erlc` output keyed by compiler path + module + exact source, the NIF/driver `.so` by the C fixture. The cache stores **`.beam` bytes**, not a `CompiledModule`, so each case still gets its own temp dir (removed on drop). A failed/absent compiler is never cached, so a compile failure stays loud on every call.
- **The peer leg is a *self*-pair by construction, and its node names are per-invocation.** `PeerRun` deliberately has **no** program field: `runtime::spawn_peer` starts the peer from the side's **own** program (non-blocking, in its own process group via `process_group(0)`), so a cross-runtime pair is structurally impossible and the two compared runtimes still never coexist. Readiness is polled from a private scratch file against a bounded `PEER_READY_TIMEOUT` (60 s), and `PeerProcess`'s `Drop` kills + reaps + scrubs the peer on **every** path; a `PeerStart::NotReady` peer is a loud `Skipped`, never an `agree`. Node names come from `{nonce}` — `corpus::PEER_NONCE_PLACEHOLDER`, substituted by `corpus::expand_nonce`, derived by `runtime::peer_nonce` from the case id + pid + a per-process counter + the side — so a machine-global `epmd` name never collides across a parallel sweep. The substitution happens **only** for peer cases, so a peer-less case's argv and report stay byte-identical to before and the `differential/1` schema id is unchanged (there is no serialized peer field; the report renders the peer as a template).
- **Every child spawn goes through `runtime::output_with_retry`**, which retries **only** a transient `ETXTBSY` (a `#!/bin/sh` script executed while another thread holds a write fd): up to 6 attempts, doubling capped backoff (5→80 ms = 155 ms), then the same error; every other error is returned unchanged.
- **Reports are always written** (`--out` sets the dir, default `out/`; `--out-file` writes to an exact path instead and skips the default file); `--json` only decides stdout. An ad-hoc `compare` asserts no golden (`matched_golden: null`).
- **The `by_contract` and `ratchet` report keys are purely additive** (`skip_serializing_if`), so a run without an allowlist is byte-for-byte unchanged and the schema id is **not** bumped. `RatchetReport::classify` marks every `Unsupported`/`Skipped` case `allowed`/`unauthorized` (a `Mismatch` is never a gap) and counts non-reproducing entries `stale`; `suite_exit_code` returns `1` iff `has_mismatch(report)` — which reads the **case verdicts**, so a mismatch can never be masked by the summary — else `1` iff `unauthorized`/`stale` ≠ 0, else `0`.
- **`GAPS.md` is generated, never hand-edited** (`--gaps` renders the gap table via `ratchet::gaps_markdown`/`write_markdown` and appends the hand-maintained `divergences.md`); `known-gaps.txt` is the ratchet's source of truth.
- **`merge` reuses that one writer, so the gate's document has a cheap refresh route**: `suite --gaps` and `merge --gaps` both call `ratchet::write_gaps`, and `merge` folds a directory of per-case `run --out-file` reports (parsed back through a manual `Deserialize`, deduped by case id, sorted) into the same suite-shaped `RunReport` (`mode:"merge"`, `Summary::of` recomputed) **without re-running a case** — never spawning a runtime or the `dist_probe` helper. Its `RunReport` deserialization is hand-written because the frozen `&'static str` corpus fields would otherwise force a `'de: 'static` bound on derive; the report's serialized bytes and schema id are unchanged. Caution: do not pipe a `merge` run's long human report into a closed pipe (`head`) — SIGPIPE can kill it before the `--gaps` write.
- **"Modules execute", not "modules load"**: the crate-level *load* sweeps live in `../crates/beam_loader/tests/real_modules.rs` / `../crates/beam_engine/tests/stdlib_sweep.rs`; this harness adds the **execute** dimension (the `mexec`/`mexec_extra`/`nif_so`/`nif_res`/`nif_abi*`/`driver_c`/`driver_abi*`/`modules`/`gc` groups + `tests/module_sweep.rs`). Every outcome in those groups is `Agree` or `Unsupported`/`Skipped`; the corpus currently carries **no** `Mismatch` (see *Known Issues*).
- **The A.3/A.4 structural C-ABI check is load-bearing**: `tests/abi.rs` `-fsyntax-only`-compiles a C TU referencing the `enif_*`/`driver_*`/`erl_drv_*` surface and `_Static_assert`s the frozen sizes/offsets mirrored from `../crates/beam_abi`, against the in-tree `erts/emulator/beam/{erl_nif.h,erl_driver.h}`; it self-tests that a bogus symbol and a wrong frozen size both fail, and **skips loudly** only when no C compiler/headers are discoverable.
- **The compared observables are process I/O only** — the harness never reads a file either runtime produced (a file artifact is observable only if the Erlang side reads it back and encodes it into stdout). A module-run temp dir holds `<module>.erl` + `.beam` (+ any fixture) and the module self-locates it via `filename:dirname(code:which(?MODULE))`.
- **No per-case timeout and no `.beam`-byte assertion**: `runtime::run_with_env` blocks until the child exits (case-level `after 2000 ->` guards are Erlang, not a harness guard), and the only byte-equality checks are the compile-cache tests.

CI (`.github/workflows/erts_rust.yml`) is path-triggered on `erts_rust/**` (plus `workflow_dispatch`), runs `gate.sh`, and turns exit `0` into a passed job while `1`/`2`/`3` each fail it. Its oracle comes from `erlef/setup-beam` pinned at `otp-version: '28'`, one release below the OTP 29.1.1 / erts-17.1 every golden here is measured against — so a release-visible oracle difference surfaces as oracle-vs-golden drift (a `mismatch`) in CI only.
Because exit `3` is **blocking**, a capability-coverage change must refresh `known-gaps.txt` **and** the generated `GAPS.md` in the same change — whose committed revision is current (`total=3268 / entries=1 / allowed=1 / unauthorized=0 / stale=0`). **Refresh it cheaply**, never with a serial `suite --gaps` (>100 min): use the parallel per-case sweep plus `differential merge --from <dir> --allowlist known-gaps.txt --gaps GAPS.md` (seconds; the same `ratchet::write_gaps`). Caution: do **not** pipe `merge`'s long human report through `head`/a closed pipe — SIGPIPE can kill it before it writes `--gaps`; redirect or `tail` it.
- **How to drive the fast parallel sweep correctly** (the `gate.sh`-equivalent route — the whole 3268-case corpus in ≈9 min wall at 12-way on a loaded host, vs >100 min serial): `erts_rust/target/release/differential list | sed 's/ —.*//'` gives the ids; run each through a **plain `sh` worker script** taking the id as `$1` (`differential run "$1" --out-file "$OUT/$(printf '%s' "$1" | tr / _).json"` — the id's `/` **must** be flattened, because `merge` reads only the `*.json` files **directly** under `--from`) via `xargs -d '\n' -n 1 -P 12 sh worker.sh` (`xargs -P 12 bash -c '…'` mangles the positional args), then fold the directory with `differential merge --from <dir> --allowlist known-gaps.txt --gaps GAPS.md` (seconds, not hours). Run the sweep with **CWD = the repo root**: the seven `selfhost/` expression cases compile the **relative** path `lib/stdlib/src/*.erl`, so from any other directory *both* sides raise `{badmatch,error}` and the verdict is a `mismatch` (oracle-vs-golden drift) — an invocation artifact, not a divergence. Keep **one sweep at a time** (the `-sname`/`-name` cases and the self-pair's `epmd` names share a machine-global name space), give every case its **own private `TMPDIR`** (`$TMPBASE/<id>`; a collision with another agent's worktree shows up as a spurious exit `2`), record each worker's id as it finishes (so a non-zero exit localizes to the `k`-th appended line ⇒ chunk line `k+1`), and run each case under `setsid -w` (an Erlang VM can signal its own process group; without a session that SIGUSR1 kills the worker shell, and absent `setsid` the whole `xargs` driver, as rc-`138` cases that all pass serially).
- **A non-agreement seen only under parallel load is an environment artifact until a serial re-run says otherwise, and the serial re-run's report is what belongs in the folded set.** The observed class is a **closed, documented list**: `nif_so/load_info_reaches_the_load_callback` as `unsupported`; `selfhost/in_process_compile_dependent_pair` and `selfhost/compile_file_of_a_module_whose_moduledoc_lives_in_a_file` as a `mismatch` with a `signal` exit; `maps/iterator_undefined_order_visits_the_same_key_set` and `proc_signals/dt_spread_tag_true` as `unsupported: opcode: run: process blocked (no message available)`; and an exit `1` with empty stdout and `beam_rt: error boot script: the scheduler was still runnable after 10000 ms` on stderr. The class is load-proportional: a 12-way sweep of the 3268-case corpus surfaced members of it next to the one genuine gap, and **every one of them `agree`s 3/3 on a serial re-run**. Re-run every `signal`/exit-3/empty-stdout case serially before deciding `agree` vs a divergence.
- **A probe expression must not bind `V`, `C` or `R`** (the wrapper binds them) — use e.g. `Reason`/`Msg`, else the *oracle* fails to compile the wrapped expression (a guaranteed false mismatch).
- **Measuring a `Probe::Value` golden needs the oracle directly, not `compare`**: `differential compare <expr>` wraps the expression in `Probe::TermToBinary`, so its per-side stdout is the ETF image — a `Value` case's golden is the `~w` line, measured by running the oracle with the same wrapper by hand (`erl -noshell -eval 'try (EXPR) of V -> io:format("ok ~w~n",[V]), halt(0) catch C:R -> io:format("exception ~w ~w~n",[C,R]), halt(1) end.'`). That hand-run fails **silently** (no stdout, exit 1) when `EXPR` binds `V`/`C`/`R`, which is what makes a variable-name slip look like a runtime crash.
- **The `udp/` and `inet_control/` group tests fence off what must not be pinned.** `udp::tests::no_case_pins_a_measured_divergence` keeps the group on the **bare port BIFs** (no `gen_udp:send`/`gen_udp:recv`/`prim_inet` — the module-level socket API belongs to `inet_control/`), and it no longer demands a `port_close` before every `port_command` because the socket-less-port command **is** pinnable now (`udp/port_command_on_a_socket_less_port_kills_it`, `udp/port_command_with_a_caller_ref_prefix_keeps_the_port`). `inet_control::tests::no_case_pins_a_measured_divergence` rejects `port_command`/`prim_inet`/`os:cmd` (an externally injected datagram would need a non-POSIX sender and a host-dependent golden) and the framed active-mode read `{packet, 4}, {active, true}`; `gen_tcp:send` is now free to appear. `no_case_waits_on_a_message` bans `timer:sleep` and any **unbounded** `receive` but allows a bounded `receive … after N -> timeout end` (its oracle answer is the golden, and a non-delivery shows up as a visible `timeout` answer). Both groups pin their size (`assert_eq!(cases.len(), 32)` / `11`), so a data-path case lands together with the guard/size edits in the same change.
- **NIF/driver cases `skip` loudly when `cc`/`erl_nif.h` are absent**, like the `erlc`-less module cases.
- **Real runtime divergences — the owner-annotated ledger is `divergences.md`** (appended to the generated `GAPS.md`, organized per contract A.1–A.9 with the owning crate on each entry). It records the shapes a case must **not** pin (most yield a *plain* Erlang value/reason, so a case pinning one would be a `mismatch`) plus the few exit-3 capability gaps no case pins. Read it there — do not duplicate it here. - **A profile-coupled `system_info` key must be pinned by its profile-**invariant** shape/relation, never by a value.** `emu_type`/`debug_compiled` report the runtime's own build tier (`cfg!(debug_assertions)` ⇒ `debug`/`true` for a dev build, `opt`/`false` for an optimised one), and the harness resolves `target/{release,debug}/beam_rt` with **release first** — so a value golden would be a `mismatch` on any tree with no `target/release` artifact, i.e. exactly what `gate.sh` and a clean CI checkout build. `system_info/emu_type` therefore asserts `lists:member(…, [opt, debug])` **and** the `emu_type`/`debug_compiled` consistency invariant (golden `ok true`), and `corpus::system_info::tests::no_case_pins_a_build_flavour_value` fails the build if any case in that group regresses to a flavour-value golden. `build_type` is the same coupling kept as an honest exit-3 gap — never a hardcoded `opt`.

## Test Strategy
- **Unit tests** in every core module: `cli` (arg parsing incl. `suite --strict --allowlist --gaps`, `merge --from/--gaps/--out-file`, `run --out-file` (rejected by `compare`/`suite`/`list`), `list --by-contract`, `--help` per subcommand); `allowlist` (parse comments/blank/`\r`, malformed/duplicate/missing errors, load round trip); `ratchet` (classification, `has_mismatch`, `report_from_suite`, `suite_exit_code`, `gaps_markdown`, the merge→`gaps_markdown` fold); `report` (`write_json_to`↔`read_report_file` round trip); `runtime` (env injection, argv shapes, the bounded `ETXTBSY` retry, and the **eight peer-leg tests**: nonce stability/uniqueness per side and invocation, the ready-line matcher, a ready peer reaped on drop, no zombie left after an exit, a silent peer ⇒ `NotReady` + killed, an early exit ⇒ `NotReady`, an unspawnable program ⇒ `NotReady`); `compare` (diff + golden + stderr classification); `corpus` (registry well-formedness: unique ids, ≥1 contract, per-kind goldens, the module-run argv shape + contract allow-list, only an env case sets a non-empty env, `expand_env` substitutes `{dir}` in values only, a peer leg pairs only with a runtime side and every argv it spawns carries the nonce); `module_build`/`nif_build` (resolution, loud compile failure, temp-dir cleanup, the `.so` + cache, skip reasons); `harness` (exit-3 classification, the unsupported reason, the eval probe shape, the caught-gap classifier); the per-group registry tests.
- **Integration** (`tests/`): `oracle.rs` (**oracle-backed** — every case's *oracle* side reproduces its golden: eval incl. `EvalEnv`, module-run incl. `ModuleEnv` and NIF fixtures, and every `Command` case's oracle side; a peer-carrying case is given a peer of the oracle's **own** program with the nonce expanded, so "the golden is the oracle's own line" still holds; oracle-vs-oracle ⇒ `Agree`; a forced-absent Rust runtime ⇒ `unsupported`, never `pass`); `cli.rs` (drives the **binary** as a child: the exit-code contract, `--help`, `--out`, `merge --from` end to end incl. a generated `GAPS.md` from two `run --out-file` reports, `list`, injected `$BEAM_RT`/`$BEAM_DIST_PROBE`, a fake `$BEAM_RT` for mismatch-vs-unsupported, the allowlist ratchet against the real corpus, `--allowlist` without `--strict`, a missing allowlist, and `gate.sh`'s own arg handling); `abi.rs` (the A.3/A.4 structural check above); `module_sweep.rs` (the broad real-module **execute** sweep — 277 entries / 35 modules, all 277 `agree`; kept out of the default `suite`).
- **`tests/cli.rs` holds `common::corpus_run_lock()` for the whole body of every full-corpus test**: two cases (`-sname`/`-name`) register an `epmd` node name, so concurrent sweeps make the losing oracle fail to reproduce `flags/sname_switch_value`'s golden — a **spurious** mismatch. Do not remove the lock. (The self-pair `dist/*` case needs no lock: every name it uses is nonce-derived.)
- The suite assertion **never pins the current gap count**: it checks `agree + unsupported + skipped + mismatches == summary.total` plus a branch-specific `agree >= 1`/`agree == 0` (mirroring the runtime the **child** resolves). `tests/cli.rs::the_ratchet_tolerates_only_the_recorded_gaps_end_to_end` drives the ratchet end to end with a fake exit-`3` runtime (all-ids allowlist ⇒ 0; an omitted id + a bogus entry ⇒ 1, both named in the generated `GAPS.md`).
- **How to add a corpus case is a skill** — see `.agents/skills/differential-add-corpus-case.md` (enabled at this node).
