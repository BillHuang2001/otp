# differential — Rust ERTS vs System ERTS Compatibility Gate

## Intent
The in-repo **differential-test harness** (Stage 0; `../../../ERTS_RUST_REWRITE_DEEPDIVE.md` §H): for each corpus case it runs the **real system ERTS** (the *oracle*) and the **Rust runtime** (`beam_rt`), then compares the **observable results**.
Three kinds of case (`CaseKind`): **expression** cases evaluate the same self-terminating probe under both runtimes; **environment-variable expression** cases (`EvalEnv`) spawn each runtime with an explicit environment so the `ERL_*FLAGS` merge (contract A.6) is pinnable; **module-run** cases compile an embedded Erlang module with `erlc` (optionally building a NIF `.so` next to it) and run one exported function.
This is the *compatibility gate* of the rewrite (`../../../ERTS_RUST_REWRITE_EVALUATION.md` §G.7/§I): no behavior change ships without a differential case.
It is a pure **driver/observer** - it never modifies the runtime and never inspects its internals; the only contract with `beam_rt` is its documented external CLI (contract **A.6**), and it honors every shared convention in `../CONTEXT.md`.
Cargo **binary + library** crate named `differential`: the library lets `cargo test` assert the harness itself (oracle golden checks, oracle-vs-oracle equality, diff detection); the binary is what a human or CI drives.

## Observable results (what is compared)
Per case, each runtime is observed and compared field-by-field:
1. **stdout bytes** (exact, byte-wise) — always compared.
2. **exit status** (process exit code; `None` if signalled) — always compared.
3. **stderr bytes**, **classified** — compared for **expression** cases (`Observables::All`) through a narrow classifier: only the Rust runtime's documented one-line boot banner (`beam_rt <vsn> booted: …`, recognised by `compare::is_runtime_banner_line` / dropped by `compare::significant_stderr`) is ignored; every other stderr byte is still compared exactly. Module-run cases (`Observables::StdoutAndExit`) do not compare stderr at all.
4. **`term_to_binary/1` of the evaluated result** — the probe *encodes the result* it observes, so the canonical ETF bytes are a first-class diff field (contract A.2).
5. **exception class + reason** — surfaced because `erl -noshell -eval` prints **nothing** on an uncaught error; the harness always wraps the expression in `try … catch` (see *Probe protocol*).
6. **selected `erlang:system_info/1` keys** — covered by corpus cases (contract A.8).

A Rust-side observation is a documented **capability gap**, not a difference, in either of two ways — both classified `SideResult::Unsupported`, so an unimplemented feature is `unsupported`, never a `mismatch`:
1. its exit code is `3` (`runtime::UNSUPPORTED_EXIT_CODE`): the reason carries the runtime's first non-empty stderr line; or
2. a **probe-wrapped** (eval) case's probe *caught* the raise: the probe prints it as its single `exception <class> <reason>` stdout line and exits `1`, and `<reason>` (after stripping one pair of surrounding `'…'` quotes) follows the runtime's documented `unsupported` reason convention - recorded as `beam_rt: unsupported (caught by the probe): <stripped>`. Detection is deliberately narrow (`harness::caught_unsupported_reason`): only the documented `unsupported` prefix (with a following `:`/`_`/whitespace, or nothing) triggers it, so a genuine Erlang reason (`badarg`, `system_limit`, `function_clause`, `'erlang:open_port/2 is not a BIF'`, …) stays an observation → `mismatch`. The gate is explicit: `RunPlan::probe_wrapped` is `true` only for `CaseKind::Eval`/`compare_expr` and `false` for module-run cases (whose stdout is `~w` of a result).

## Probe protocol (binding)
An **expression** case carries a plain Erlang expression, wrapped into a self-terminating probe:

- **`Probe::TermToBinary`** (default): `try (EXPR) of V -> io:format("ok ~w~n",[term_to_binary(V)]), halt(0) catch C:R -> io:format("exception ~w ~w~n",[C,R]), halt(1) end.`
- **`Probe::Value`**: same shape but prints `~w` of `V` (textual rendering, no ETF encode).

Success ⇒ one stdout line `ok <repr>`, exit `0`. Failure ⇒ one line `exception <class> <reason>`, exit `1`.
Expression cases may add **extra argv** (e.g. `-<flag> <value>`) to exercise CLI flag parsing (A.6), and their argv is built once and given to **both** runtimes: `["-noshell", <extra…>, "-eval", <probe>]`.

A **module-run** case (`CaseKind::Module(ModuleRun)`) drives the two runtimes with **different** argv:
- oracle: `["-noshell", "-pa", <dir>, "-eval", "io:format(\"~w~n\",[<mod>:<fun>(<args…>)]), halt(0)."]`.
- Rust runtime: `["run", "<dir>/<mod>.beam", "<mod>:<fun>/<arity>", <int-args…>]` (its `run` action).
The embedded source is compiled at run time with the system `erlc` into a unique temp dir (cleaned up afterwards); stdout + exit status only are compared.
A module-run case may also carry a `nif: Option<NifFixture>`: the fixture's artifacts (a `cc`-built `.so`, or a text file named `<name>.so`) are materialized into the **same** temp dir as the `.beam`, so the embedded module can self-locate them (`filename:dirname(code:which(?MODULE))`) and neither runtime's argv changes. A module-run golden is an **integer line** (the corpus invariant); a case whose observable would embed a volatile value (a temp-dir path in a `load_nif` message, a pid/port creation) classifies that observable into an integer instead.

## API Surface

### CLI (hand-rolled `std`-only arg parsing — **no `clap`**; `--help` usable on every subcommand)
- `differential run <case-id> [--json] [--out <dir>]` — run one corpus case both ways; print the comparison.
- `differential compare <expr> [--pa <dir>]… [--json] [--out <dir>]` — ad-hoc: evaluate an expression under both runtimes and compare.
- `differential suite [--strict] [--allowlist <file>] [--gaps <path>] [--json] [--out <dir>]` — run the whole built-in corpus. `--allowlist <file>` (requires `--strict`) is the known-gaps ratchet: it tolerates the gaps it records and fails on an unauthorized gap or a stale entry; `--gaps <path>` also writes the generated `GAPS.md`.
- `differential list [--by-contract] [--json] [--out <dir>]` — list corpus case ids + the contract each covers. `--by-contract` groups by contract id (A.1…A.9) with per-contract case counts and ids; without it the output is byte-for-byte the plain listing.
- `differential --help` / `-h`; `differential <sub> --help`.
- **Exit codes (the binary):** `0` all executed cases agreed (skips/`unsupported` reported, not fatal); `1` ≥1 **mismatch**; `2` usage/env error. `--strict` escalates `unsupported`/`skipped` to failure; `--strict --allowlist <file>` instead tolerates only the gaps the allowlist records and fails (`1`) on an unauthorized gap or a stale entry. `gate.sh` (below) layers the `0/1/2/3` CI mapping on top; the binary's own contract is unchanged.
- `gate.sh` (executable, POSIX `sh`, repo-relative — no baked paths) — the **CI gate** wrapper. It builds `beam_rt` + `differential` via the committed `../../scripts/cargo.sh`, runs the corpus as `suite --strict --allowlist <script_dir>/known-gaps.txt --json --out <tmpdir>`, and maps the written `report.json` (its top-level `summary` and `ratchet` blocks) to its own exit code.

### Library (`src/lib.rs`) — the public API `cargo test` asserts against
- `error` — `Error` (`Usage`/`Env`/`Io`, all → exit `2`), `Result<T>`.
  Tool-level errors are host-tool errors; BEAM exceptions are *observed **data*** (never the harness's own failure mode), so `beam_common::BeamError` does not model this crate's failures.
- `cli` — `Command` enum (`Run{case_id,…}`, `Compare{expr,pa,…}`, `Suite{strict,allowlist,gaps,…}`, `List{by_contract,json,out}`, `Help{…}`), `parse(args)`, `usage(topic)`.
- `allowlist` — the known-gaps allowlist: `AllowEntry{case_id,crate_name,reason}`, `Allowlist::parse(source,path)`/`load(path)`/`empty()`, `path()`/`entries()`/`len()`/`is_empty()`/`get(id)`/`contains(id)`. A malformed or duplicate entry is a loud `Error::Usage`, a read failure a loud `Error::Io` (both exit `2`).
- `ratchet` — the ratcheted strict gate: `RatchetReport{allowlist,allowed,unauthorized,stale}` (`classify(cases,&Allowlist)`), `report_from_suite(&SuiteOutcome,&Allowlist) -> RunReport`, `suite_exit_code(&RunReport,strict) -> i32`, `gaps_markdown(&RunReport,&Allowlist) -> String`, `write_markdown(path,text)`.
- `runtime` — `UNSUPPORTED_EXIT_CODE` (`3`), `RuntimeId::{Oracle,Rust}`, `RuntimeSource::{Env,Path,WorkspaceDefault}`, `RuntimeSpec{id,program,source}`, `Observation{runtime,program,argv,stdout,stderr,exit_code}`, `resolve_oracle()`, `resolve_rust() -> Ok(Option<RuntimeSpec>)`, `resolve_rust_from(beam_rt,manifest_dir)`, `eval_argv(expr,extra)`, `run(spec,argv)`, `run_with_env(spec,argv,env)`, `output_with_retry`.
- `module_build` — the **Erlang** half of a module-run case: `MISSING_ERLC_REASON`, `resolve_erlc() -> Ok(Option<PathBuf>)`, `resolve_erlc_from(erlc,path)`, `CompiledModule{dir,beam}` (temp dir removed on drop), `compile(erlc,source,module)`, and the process-local `erlc` compile cache. It **re-exports** the C/NIF surface below, so `differential::module_build::{build, Build, NifFixture, resolve_cc, resolve_erl_include, MISSING_CC_REASON, MISSING_ERL_NIF_REASON}` are the public paths callers use.
- `nif_build` — the **C/NIF** half (crate-private module, re-exported through `module_build`): `MISSING_CC_REASON`, `MISSING_ERL_NIF_REASON`, `resolve_cc()`/`resolve_cc_from(cc,path)` (`$CC` else `cc`), `resolve_erl_include() -> Option<PathBuf>` (`erl_nif.h` locator, process-local cache), `NifFixture::{CompiledLibrary{name,c_source}, TextFileSo{name,contents}}`, `Build::{Compiled(CompiledModule), Skipped(&'static str)}`, `build(source,module,nif) -> Result<Build>` (compiles the `.beam`, materializes the fixture into the same temp dir, memoizes a built `.so`).
- `compare` — `Observables::{All,StdoutAndExit}`, `SideResult::{Observed(Observation),Unsupported{reason}}`, `FieldDiff{field,oracle,rust}`, `GoldenCheck{matched,diffs}`, `Verdict::{Agree,Mismatch,Unsupported,Skipped}`, `compare_observations`, `compare_observations_with(o,r,observables)`, `verdict`, `verdict_with(o,r,golden,observables)`, `check_golden(&Observation,&Golden) -> GoldenCheck`.
- `corpus` — `Contract` (A.1–A.9 ids + labels), `Probe`, `Golden{stdout,exit_code}`, `CaseKind::{Eval{expr,extra_argv,probe},EvalEnv{expr,extra_argv,env,probe},Module(ModuleRun)}`, `ModuleRun{source,module,function,arity,args,nif}` (+ `oracle_eval`/`oracle_argv`/`rust_argv`/`beam_path`), `Case{id,description,contracts,kind,golden}` (+ `eval`/`kind_label`/`expr`/`extra_argv`/`env`), `cases()`, `find_case(id)`, `probe_expr(expr,probe)`.
- `harness` — `RuntimeContext{oracle,rust}`, `resolve_context()`, `run_case(&Case) -> CaseOutcome`, `run_case_in(&RuntimeContext,&Case) -> CaseOutcome`, `compare_expr(expr,pa) -> CaseOutcome`, `run_suite(strict) -> SuiteOutcome`; `CaseOutcome` carries per-side `oracle_argv`/`rust_argv` and derives the `Verdict` + exit code.
- `report` — `CaseReport`, `RunReport` (serde, stable `schema: "differential/1"`; carries `summary`, an additive top-level `ratchet` — `Option<RatchetReport>`, present only when an allowlist drove the run — **and** an additive top-level `by_contract` map of contract id → `Summary`), `Summary` (`total/agree/mismatch/unsupported/skipped`), `ListReport` (+ optional `by_contract` array of `ContractGroup{id,label,total,case_ids}`, present only via `from_corpus_grouped`), `ListEntry.probe` (the case kind label: probe name or `"module-run"`), `render_list_grouped`, `write_json`, `render_human`.

## Runtime resolution (shared convention; no baked absolute paths without an overridable default)
- **Oracle** = `$ERTS_ORACLE` if set, else `erl` on `PATH`; missing -> loud `Error::Env` (exit 2).
- **Rust runtime** = `$BEAM_RT` if set (must exist, else `Error::Env`), else `<CARGO_MANIFEST_DIR>/../../target/{release,debug}/beam_rt`; neither present -> the Rust side reports `unsupported` (never a crash, never a fabricated pass). The profile order is **`release` before `debug` on purpose** (the real CLI and `gate.sh` want the fastest artifact present); that order is wrong under `cargo test` (only `debug` is rebuilt), so the **integration tests inject `$BEAM_RT`** pointing at the fresh debug runtime instead (see *Design Decisions*). The order itself is never changed.
- **Compiler (`erlc`)** = `$ERLC` if set (must exist, else `Error::Env`), else `erlc` on `PATH`; missing -> `Ok(None)`, so the module-run cases are **skipped loudly** (`Verdict::Skipped`), never a silent pass.
- **C toolchain (NIF cases only)** - `cc` = `$CC` if set (an existing executable, or a command found on `PATH`), else `cc` on `PATH`. `erl_nif.h` is located by `resolve_erl_include()`: the oracle's `erl code:lib_dir(erts,include)`, then the `erts-*/include` sibling of the `erl` on `PATH` (the working probe - `code:lib_dir` alone returns a non-existent path here), then standard roots (`$ERL_TOP`, `/usr/lib/erlang`, ...). Either missing -> `Build::Skipped(MISSING_CC_REASON | MISSING_ERL_NIF_REASON)` -> the case is `Verdict::Skipped` (never run, never reported as agreement, never a crash).
- Expression cases invoke both runtimes with the **same argv** (only the program path differs); module-run cases with per-side argv (see *Probe protocol*).

## gate.sh — the checkable compatibility gate
`gate.sh` wraps `differential suite --strict --allowlist known-gaps.txt` for CI. From the repo root it runs
`erts_rust/scripts/cargo.sh build --manifest-path erts_rust/Cargo.toml -p beam_rt -p differential`, then
`erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite --strict --allowlist <script_dir>/known-gaps.txt --json --out <tmpdir>`,
and turns the report's **top-level `summary`** and **top-level `ratchet`** blocks into a CI exit code:

| Exit | Meaning |
|------|---------|
| `0`  | no mismatch, every non-agreeing case is an allowlisted capability gap, and the allowlist is fresh (no unauthorized gap, no stale entry) |
| `1`  | ≥1 **mismatch** — a real, observable behavioral divergence (including oracle-vs-its-own-golden corpus drift); also a top-level `summary` that cannot be parsed (fail loud) |
| `2`  | usage / environment error — a missing oracle, a build failure, a missing allowlist, a report that could not be produced, or a top-level `ratchet` block that cannot be parsed |
| `3`  | no mismatch, but the **ratchet must be updated**: ≥1 `unsupported`/`skipped` case is not in the allowlist (an unauthorized gap), or ≥1 allowlist entry did not reproduce as a gap (a stale entry) |

**Invariant:** an `unsupported` case (a capability gap the Rust runtime signals via its documented exit `3` / `beam_rt: unsupported: …` reason convention, or a missing `beam_rt`) is **never** reported as a mismatch. Exit `1` is reserved for a case whose runtime actually produced a *differing observable result*; a capability gap can only ever land in the `unsupported`/`skipped` buckets, so it causes exit `3` when it is **not** allowlisted and exit `0` when it is.

The `1`-vs-`3` distinction is read **solely** from the report's **top-level `summary`** and **top-level `ratchet`** objects (authoritative); the per-contract `by_contract` rollup — which also carries `mismatch` keys, at a deeper indent — is deliberately ignored. If the summary cannot be parsed, the gate **fails loud** (exit `1`) rather than risk a false pass (`0`); if the ratchet block cannot be parsed (an unexpected report shape) it fails loud (exit `2`).

The binary's own `run`/`suite` exit codes are unchanged (`0` agree / `1` mismatch / `2` usage-env; a lenient `run` on an unsupported case stays `0`) — the `0/1/2/3` mapping belongs to the gate script only.

## Constraints
- **Honest reporting:** a side that cannot run is `unsupported` / `skipped(<reason>)` — **never** `pass`, and oracle observations are **never** fabricated. A case whose *oracle* disagrees with its golden is itself a failure (corpus drift), surfaced as a mismatch — the harness is self-testing.
- **No coupling to `crates/*` internals** (crate deps are `serde` + `serde_json` only). No `clap`; arg parsing is hand-rolled `std`. `unsafe` is **forbidden**.
- **Loud failures:** stderr messages + nonzero exit; never silently swallow an error.
- Machine-readable JSON, stable schema, written under the gitignored `out/` (or `--out <dir>`).
- Files target ~1000 lines; split by responsibility. Apache-2.0. The corpus group files are **data registries** (one embedded module/expression per case) and legitimately run past the soft target (`errors.rs`, `wire.rs`, `nif_abi.rs`, `driver_abi.rs`); do not split them for line count alone. The `report` module is a directory module split by responsibility (`report/{model,json,render}.rs`, each well under the target).
- The built-in corpus is the **conformance corpus** (1213 cases) and runs end to end in CI; keep it fast enough for that, and reserve the heavy external suites (root §6) for milestones.
- **Never assert a golden whose output is order-unstable.** A `~w` rendering of a multi-key map (or any structure containing one) has a per-VM-start iteration order, so compare it structurally (`maps:size`, `lists:sort(maps:keys(M))`, single-key maps) instead. Same rule for pids/refs/ports/creation values that vary per VM start, and for a `load_nif` failure message that embeds a temp-dir path — assert a shape or classify into an integer, or use a deterministic decode→re-encode round-trip.

## Design Decisions
- **Probe wrapper is mandatory** because `erl -noshell -eval '<expr with uncaught error>'` emits no stdout and exits 1, so without it an exception is invisible to a stdout diff.
- **The environment-variable surface is a third case kind, not a field on `Eval`.** `CaseKind::EvalEnv { expr, extra_argv, env, probe }` is `Eval` plus an explicit `env: &'static [(name, value)]`, kept a **separate variant** so the existing `CaseKind::Eval` literals stay untouched. Its argv and observables/classification are identical to `Eval` (`Observables::All`, `probe_wrapped: true`); the only difference is the spawn path: `runtime::run_with_env(spec, argv, env)` sets each variable **on top of** the inherited environment (never cleared) so `$PATH`/`$TMPDIR` resolution is undisturbed. `harness::RunPlan` carries `env` (`&[]` elsewhere) and `execute` always calls `run_with_env` (one spawn path); `Case::env()` is `&[]` for non-`EvalEnv` cases (the test `environment_cases_are_well_formed_and_never_carry_an_empty_env` pins that only `EvalEnv` may set one).
- **The A.6 `ERL_*FLAGS` cases pin the merge order, and are oracle-derived.** `flags/env_*` covers `ERL_AFLAGS` prepended before the command line, `ERL_FLAGS` merged after it, an `ERL_FLAGS` quoted value surviving the tokenizer, the full `[ERL_AFLAGS] [command line] [ERL_FLAGS]` order, and `[ERL_FLAGS] [ERL_ZFLAGS]`; two `+P` cases make "a later source overrides an earlier one" *effective* (not just a list order) by observing `erlang:system_info(process_limit)`.
- **`mismatch` is reserved for a runtime that produced a differing observable result** (classification is signal-based, never heuristic — the two signals are in *Observable results*). `verdict_with` must use the *same* `Observables` as the reported `diffs`, so a case can never show an empty diff list yet be a `Mismatch`.
- **Expression cases classify stderr; module-run cases do not.** `significant_stderr` drops only the documented boot banner (narrow by construction — *Observable results* #3), so it can only ever drop a known banner, never fabricate agreement. `compare_observations_with` reports the classified buffers, so a `stderr` `FieldDiff` shows the significant difference.
- **Golden per case** lets the harness self-test: the oracle must reproduce it while the Rust side reports whatever it really does. If the oracle stops matching its golden, that is real failure (drift), not a skip.
- **Volatile `system_info` keys use structural goldens** (`is_integer(process_count)` -> `true`, `is_list(otp_release)` -> `true`) and `version` -> `<<"17.1">>` (the frozen erts target). `otp_release` is deliberately **not** asserted by exact value: the oracle is OTP 29 while the rewrite targets OTP 30, so an exact string would be a guaranteed false mismatch.
- **NIF cases are module-run cases, never `-eval` cases.** The oracle rejects any `erlang:load_nif/2` not called from its own NIF module (`{error,{bad_lib,"load_nif/2 must be explicitly called from the NIF module. It cannot be called through apply/3."}}`), so `CaseKind::Eval` cannot observe load semantics.
- **NIF cases self-locate and self-classify.** The embedded module loads a suffix-less absolute path built from `filename:dirname(code:which(?MODULE))` (works in both runtimes, so `oracle_argv`/`rust_argv` stay untouched), stubs **every** function in the NIF's `ErlNifFunc` table (the oracle refuses a partial stub set), calls the NIF through an **external** call (the Rust runtime intercepts only external dispatch, so a local call runs the `erlang:nif_error` stub), and maps the `{error,{Reason,_}}` tag to an **integer** (`load_failed`/`bad_lib`/...) so the golden never embeds the volatile temp-dir path. The real `.so` is built with `cc -shared -fPIC -I<erl_nif.h> -o <dir>/<name>.so <c_source>` into the case's temp dir.
- **`--strict` escalates `unsupported`/`skipped` to a failure; `--allowlist <file>` turns that into a ratchet.** `--strict --allowlist <file>` tolerates only the gaps the file records: a non-agreeing case whose id is absent is an *unauthorized* gap, and an entry whose case did not reproduce as a gap is *stale* — either fails. The default (no flags) keeps capability gaps non-fatal. `--allowlist` requires `--strict`; a `mismatch` is never toleratable.
- **A golden is a stdout *line*, without the trailing newline**: `compare::check_golden` normalizes the observation with `normalize_probe_stdout` (strips one trailing `\n`, and a preceding `\r`) before comparing it to `Golden::stdout`, keeping a golden diff readable.
- **Child spawns retry a bounded `ETXTBSY` only.** Every production spawn (`runtime::run`, `module_build::compile`, the C compile) goes through `runtime::output_with_retry`. A `#!/bin/sh` script is legitimately executed here (`$ERTS_ORACLE`/`$BEAM_RT` may be a wrapper script; test stubs are scripts), and when one thread `fork()`s while another holds a descriptor open **for writing** that script, the kernel transiently refuses the `exec` with `ETXTBSY` ("Text file busy", errno 26) - a pure scheduling artifact. The helper retries that one condition up to 6 attempts with a **doubling, capped** backoff (5 -> 10 -> 20 -> 40 -> 80 ms = 155 ms; matching `ErrorKind::ExecutableFileBusy`, and errno 26 under `#[cfg(unix)]`), then returns the **same** error so a surviving failure stays loud; every other error is returned unchanged. A bounded retry of an understood transient race, not error swallowing.
- **Integration tests inject the freshly built debug runtime.** `tests/common/mod.rs::fresh_rust_runtime()` returns the `beam_rt` next to `CARGO_BIN_EXE_differential` (Cargo builds both into the same profile dir), and every test that exercises the real runtime injects it as `$BEAM_RT` (or builds `harness::RuntimeContext{ oracle, rust: fresh_rust_spec() }`), so a **stale `target/release/beam_rt` can never shadow the fresh debug build**. `CARGO_BIN_EXE_beam_rt` would name it directly, but Cargo defines that only for binaries of the package under test, so the sibling lookup is exact, not heuristic.
  The **suite** test also accounts for the runtime the **child** resolves: when the fresh debug sibling is absent but a workspace-default `target/{release,debug}/beam_rt` is resolvable, the child falls back to it and agreement **is** exercised (`agree >= 1`). The `agree == 0` branch is reached only when the child has no resolvable Rust runtime at all, or when `erlc` is missing - `tests/oracle.rs::an_absent_rust_runtime_reports_unsupported_never_agreement` guards the forced-absent path.
- **Test scratch dirs are worktree-local, never the ambient `$TMPDIR`.** `tests/common/mod.rs::scratch_root()` returns `CARGO_TARGET_TMPDIR` (`<worktree>/erts_rust/target/tmp`, private to this build), and `tests/cli.rs` roots both its `Scratch` dirs and the child's `TMPDIR` there, so the tests do not depend on a shared/volatile temp dir (a sandbox wiped `$TMPDIR` mid-run and flaked a fake-`$BEAM_RT` spawn with ENOENT). `tests/oracle.rs` keeps `std::env::temp_dir()` for the `manifest_dir` *outside* `target/` (a `CARGO_TARGET_TMPDIR` base there would make the "absent Rust runtime" case find a real runtime).
- **Reports are always written** (`--out <dir>` sets the directory, default `out/`); `--json` only decides what goes to stdout. An ad-hoc `compare` asserts no golden, so its report carries `matched_golden: null` (the Rust side always does).
- **The per-contract rollup is purely additive and derived.** `RunReport.by_contract` maps each contract id present in the run to the same `Summary` shape as the top-level `summary` (a multi-contract case contributes to each, so the per-contract `total`s need not sum to `summary.total`). The `list` listing carries `by_contract` only with `--by-contract` (`serde(skip_serializing_if = "Option::is_none")`), so the plain `list` output - human text and `differential/list/1` JSON - is byte-for-byte unchanged. Schema ids are **not** bumped: both changes only add keys.
- **The `ratchet` block is likewise additive, and the allowlist drives the gate.** `RunReport.ratchet` is `Option<RatchetReport>` (`skip_serializing_if = "Option::is_none"`), so a run without an allowlist is byte-for-byte unchanged and the schema id is **not** bumped. `RatchetReport::classify` marks every `Unsupported`/`Skipped` case `allowed` or `unauthorized` (a `Mismatch` is never a gap) and counts the allowlist entries that did not reproduce (`stale`); `suite_exit_code` returns `1` iff there is any `mismatch`, else (with a ratchet) iff `unauthorized`/`stale` is non-zero, else `0` (a clean allowlisted gap set is tolerated).
- **`GAPS.md` is a generated document, never hand-edited**; `known-gaps.txt` is the source of truth and is edited instead (an entry must be added deliberately). `--gaps <path>` renders the current gap table (each gap `allowed`/`unauthorized`, then the `stale` entries) via `ratchet::gaps_markdown`/`write_markdown`, and appends the hand-maintained `divergences.md` ledger of observed-but-unpinned divergences.
- **`erlc` (and NIF `.so`) compile results are memoized** in a process-local cache (keyed by compiler path + module + exact source, or by the C fixture). The module-run cases share only a few embedded sources, so this replaces dozens of spawns with a handful while every case still gets its **own** temp dir and unchanged argv. The cache stores the compiled `.beam` **bytes**, not a `CompiledModule`, precisely so each `CompiledModule` keeps removing its own temp dir on drop (pinned by `module_build`'s tests). A failed/absent compiler is never cached, so a compile failure stays a loud error on every call.
- **"Modules execute", not "modules load".** The crate-level *load* sweeps (`../crates/beam_loader/tests/real_modules.rs`, `../crates/beam_engine/tests/stdlib_sweep.rs`) prove real `.beam`s decode; this harness adds the **execute** dimension several ways: the `mexec` group (tiny `erlc`-compiled wrappers whose int-arg functions call a real system module), the `nif_so`/`nif_res`/`nif_abi` groups (a compiled module that loads a real `cc`-built NIF `.so` and calls into it), the `driver_c`/`driver_abi` groups (a real C driver `.so` driven through the port lifecycle), and `tests/module_sweep.rs` (kept out of the default `suite` to stay fast). Every outcome must be `Agree` or `Unsupported`/`Skipped` - never `Mismatch`.
- **The A.3/A.4 structural C-ABI check is load-bearing.** `tests/abi.rs` resolves the target's pointer size from `__SIZEOF_POINTER__` (a compiler-predefined macro) and synthesizes `erl_int_sizes_config.h`; it then `-fsyntax-only`-compiles a C TU that references the `enif_*`/`driver_*`/`erl_drv_*` surface **and** `_Static_assert`s the frozen `ERL_NIF_TERM`/struct sizes+offsets mirrored from `../crates/beam_abi` (read-only), plus self-tests that a bogus symbol and a wrong frozen size both fail. It skips **loudly** only when no C compiler / headers / integer sizes are discoverable.

## How to add a corpus case (the corpus is code, not a manifest)
- **The corpus is a Rust registry, not a directory scan or data file.** Each contract group is a module `src/corpus/<group>.rs` exposing `pub(crate) fn group() -> Vec<Case>`; `src/corpus/mod.rs::build_corpus()` concatenates them into a `OnceLock<Vec<Case>>`. A new group MUST be declared (`mod <group>;`) and appended in `build_corpus()`.
- **A case id is `<group>/<name>`, but its `<group>` segment is a *subdivision*, NOT the Rust file name** — one file may emit several prefixes (`ets_spec.rs` ⇒ `ets/…` + `ets_spec/…`; `bifs.rs` ⇒ `bifs/…` + `lists/…`; `terms.rs` ⇒ `terms/…` + `errors/…`; `printing.rs` ⇒ `print/…` + `float/…`; `phash.rs` ⇒ `phash/…` + `phash2/…`), so per-file counts are NOT derivable from id prefixes. Count a group's cases by its quoted `"<prefix>/<name>"` literals in the file (most groups list literal entries, several via a `case(id, …)`/table helper); only `wire_ids.rs` (`node_identity_cases()`) and `ets.rs` build cases in a loop.
- A `Case` is `{ id: "<group>/<name>" (globally unique), description, contracts: &[Contract], kind: CaseKind, golden: Golden }`. `CaseKind::Eval { expr, extra_argv, probe }` gives both runtimes **identical** argv; `CaseKind::EvalEnv { expr, extra_argv, env, probe }` does the same but also spawns each runtime with an explicit `env` (the `ERL_*FLAGS` surface - see *Design Decisions* and the `flags/env_*` cases); `CaseKind::Module(ModuleRun { source, module, function, arity, args: &[i64], nif })` compiles the embedded module with `erlc` and drives the oracle (`-pa`+`-eval`) vs `beam_rt run` with **integer args only** (stdout + exit compared; stderr not). `Golden { stdout: Option<&'static str>, exit_code }` is the **oracle's** expected output line (no trailing newline) - the corpus's own drift self-test.
- The two ABI contract ids are `Contract::NifAbi` (A.3) and `Contract::DriverAbi` (A.4).

### Adding an A.3 (NIF C ABI) case - needs no harness change
- Reuse the `nif_so` shape: a `CaseKind::Module` case carrying `Some(NifFixture::CompiledLibrary { name, c_source })`. `module_build::build` compiles the C with `cc -shared -fPIC -I<erts include>` into the case's own temp dir; the module self-locates `<dir>/<name>` (suffix-less, so both runtimes append `.so`).
- The `nif_abi` group widens this: one shared C library whose only `ErlNifFunc` entry is `probe/1`, driven by an integer selector through an **external** call — one new `enif_*` behaviour is one C `switch` case plus one corpus entry, and every golden stays a VM-stable integer.
- **Hard constraint: the C may only reference `enif_*` symbols the Rust runtime really defines.** On non-Windows the host `erl_nif.h` declares each `enif_*` as a direct `extern` symbol (`ERL_NIF_API_FUNC_DECL` => `ERL_NAPI_EXPORT extern ...`), and **both** runtimes `dlopen(RTLD_NOW)` the same `.so`; a symbol the Rust runtime does not export makes the *Rust* load fail (`{error,{load_failed,...}}`) while the oracle loads it - a **mismatch**, not a capability gap. The exported set is the `pub extern "C" fn enif_*` in `../../crates/beam_abi/src/nif/enif/` (the slots `enif_api_table()` fills). A resource's **destructor** stays unpinnable: the oracle schedules it on a misc aux-work thread (`nif_resource_dtor_prologue`), so it is unobservable inside the NIF call.
- Load rules a NIF case must honor (pinned by `nif_so`): call `erlang:load_nif/2` from the NIF module itself; stub **and export** every function in the library's `ErlNifFunc`; make the NIF calls **external**; classify the `{error,{Reason,_}}` tag to an integer (never print the path-bearing `Text`).

### Adding an A.4 (driver C ABI) case - no harness change
- The `driver_c` group loads a **real C driver `.so`**: a module-run case claims `Contract::DriverAbi` (allowed by `src/corpus/mod.rs::module_run_cases_are_registered_and_well_formed`, allow-list `BeamAsm|LanguageSemantics|OtpApps|NifAbi|DriverAbi`) and carries `Some(NifFixture::CompiledLibrary { .. })`, compiled against the erts include dir (which also holds `erl_driver.h`). The module opens the driver as `open_port({spawn_driver, Dir ++ "/<name>"}, ...)`: the Rust runtime's `driver_lookup` treats a name containing `/` as the object path and validates the entry name against the file stem; the oracle needs the object pre-loaded with `erl_ddll:load_driver/2` first, so `driver_c`'s `open/2` tries the path form and falls back to the loaded bare name. A working fixture pattern is `../../crates/beam_io/tests/fixtures/host_driver.c`. The group covers the port lifecycle (`start`/`stop`), `port_info`, the `port_command`->`output` callback, the echo round trip (selector `6`) and the three driver-registry fixtures (`7`/`8`/`9`, see *Routing Table*). The `driver/*` group separately drives the **built-in `spawn`/`spawn_executable` drivers** through `open_port/2` (ids like `driver/spawn_driver_port_stream_read` name the *built-in spawn driver*, not `{spawn_driver, Name}`).
- The `driver_abi` group widens this: one shared C driver `.so` whose `output` callback dispatches on a one-byte `port_command/2` selector — an ABI check answering a single status byte, a `driver_output*` byte delivery (answered as the base-256 integer of the delivered bytes), or a `driver_select`/`driver_set_timer` arm answered later by `ready_input`/`ready_output`/`timeout` — so one new slot is one selector case.
- The driver echo round trip runs only once `beam_rt run` drives the full scheduler (`Runtime::run_scheduled`); a single engine pass never runs the scheduler's port half, so the receiver blocks and the CLI exits `3` with `beam_rt: unsupported: ... blocked` (a capability gap, never a mismatch, never a hang).

  - **`erlang:statistics/1` counters (A.7, `proc_signals/statistics_*_unsupported`):** `reductions`, `runtime`, `context_switches`, `io` and `scheduler_wall_time` — the runtime serves only `wall_clock` and raises `beam_rt: unsupported: erlang:statistics/1: the \`<key>\` counter is not implemented` (exit 3).

  The NIF cases also degrade to `skipped` (not a failure) when `cc`/`erl_nif.h` is absent, exactly like the `erlc`-less module cases.
- **The A.4 driver-registry hooks answer.** `driver_c/driver_lock_driver_answers_the_ports_driver` and `driver_c/add_then_remove_driver_entry_reports_removed` (selectors `8`/`9`) `agree` (`1`): `lock_driver` -> `0` (the port's driver has a `dlopen` handle, matching the oracle's `prt->drv_ptr->handle == NULL`), `add_driver_entry`/`remove_driver_entry` -> `0`/`1` for a non-dynamic entry; both fixtures carry their answer over the `driver_output` byte channel.
- **`--strict`** exits `1` while any `unsupported`/`skipped`/`mismatch` remains; `--strict --allowlist <file>` exits `0` while every gap is recorded and the allowlist is fresh (`known-gaps.txt` → exit `0`), and `1` on an unauthorized gap or a stale entry. `tests/cli.rs` pins that a lenient (`run`) invocation on an unsupported case stays exit `0`.
- **The gate IS wired into CI.** `.github/workflows/erts_rust.yml` is a standalone, path-triggered workflow (`push`/`pull_request` on `erts_rust/**` or the workflow file, plus `workflow_dispatch`): it pins the Rust toolchain (from `erts_rust/rust-toolchain.toml`), installs an Erlang/OTP oracle via `erlef/setup-beam`, then runs `cargo build --workspace --all-targets`, `cargo test --workspace --no-fail-fast`, a non-blocking clippy, and finally `erts_rust/tools/differential/gate.sh`. With no `erl`/`erlc` on `PATH` it warns and skips (exit `0`). The `bench` driver is not wired into CI.
- **CI ratchet handoff (outstanding).** The workflow's gate step still maps `gate.sh` exit `3` to a **non-blocking warning** (`::warning:: … non-blocking`, `exit 0`) — the pre-ratchet policy; `1`/`2` already fail the job. Exit `3` now means the **ratchet must be updated** (an unauthorized gap or a stale `known-gaps.txt` entry), so the workflow must be changed to **fail the job** on exit `3`. The workflow file is outside this node's write scope; until it changes, the ratchet is enforced by `gate.sh` locally but not by CI.
- **A probe expression must not bind `V`, `C`, or `R`.** The probe wrapper binds `of V -> … catch C:R -> …`, so a user expression that also binds `V`/`C`/`R` makes the *oracle* fail to compile the wrapped expression (`unsafe_var`, empty stdout, exit 1) — a guaranteed false mismatch. Use other variable names (e.g. `Reason`, `Msg`).
- **The `ets` query surface IS pinned** (`src/corpus/ets_spec.rs`, 27 cases, all `agree` - the family list + the `ordered_set` arithmetic-key rule are in *Routing Table*). Still unimplemented (a plain `error:undef`, so never in the corpus): `slot/2`, `select_reverse/1,2,3`, `is_compiled_ms/1`, `internal_*`.
- **Real runtime divergences verified against the live runtimes — deliberately NOT in the corpus (each yields a *plain Erlang value/reason*, so it would be a `mismatch`; handoffs to the runtime nodes).** They close automatically if the runtime signals the gap via its documented exit `3` / `unsupported` reason convention instead:
  - **`binary:match/2,3` with no match (`beam_bifs`):** the oracle returns the atom `nomatch`; the Rust runtime fails with `beam_rt: term not found` (exit 1, empty stdout) — verified on `binary:match(<<"abcabc">>,<<"zz">>)`. The agreeing no-match shapes (`binary:matches/2` ⇒ `[]`, `binary:split/2` ⇒ the subject unchanged) ARE pinned in `binmatch.rs`.
  - **`lists:usort/2` with an ascending comparator (`beam_bifs`) — a WRONG RESULT:** `lists:usort(fun(A,B) -> A =< B end, [1,2,3])` is `[1,2,3]` in the oracle but `[1,1,3]` in the Rust runtime (an element duplicated, one lost), on the `-eval` AND the compiled-module path; the `<`/`>=`/`>` and always-true/always-false comparators agree. Suspected cause: the `Y < Z` branch of `crates/beam_bifs/src/lists.rs::ufsplit_1` (the Erlang clause makes the new first element Z *and* the new second the old Y). `lists/usort_2_degenerate` pins inputs where that branch is not taken.
  - **Plain `~w`/`io:format` float notation (`beam_bifs` printer):** the oracle switches to exponent notation below ~`1.0e-4` and at/above `1.0e5` (`{1.0e-5,1.0e5}` ⇒ `{1.0e-5,1.0e5}`) while the Rust runtime prints plain decimal (`{0.00001,100000.0}`). `float_to_list/2` and `float_to_binary/2` with the `short` option DO agree (pinned in `printing.rs`), so no case renders a tiny/huge float through `~w`.
  - **`~W` of a binary is depth-elided only at depth 1 (`beam_bifs` printer):** `~W <<1,2,3>> 2` is `<<1,...>>` in the oracle but `<<1,2,3>>` in the Rust runtime. `~P` (which routes through `io_lib_pretty`) agrees at every depth and `~W` agrees at depths 0/1/4 — only those are pinned.
  - **`math:erf/1`/`erfc/1` are not bit-exact (`beam_bifs`):** 1 ULP on `erf(1.0)`/`erf(-2.0)`, 1–5 ULP on `erfc/1` — so they are excluded from `math_bifs.rs`, where every other `math` BIF (including the double-double `atanh/1`) is pinned bit-exactly.
  - **ETS query surface (`beam_bifs`):** `ets:select/1` rejects the terminal `'$end_of_table'` sentinel (`badarg`); a continuation is a bare synthetic `Ref` where the oracle uses a table-type-specific tuple of refs (the corpus therefore asserts `element(1,_)`/`tuple_size/1` only) and is **single-use** in the Rust runtime; a `named_table` lookup by name (`ets:lookup(Name, Key)`) is `[{a,1}]` in the oracle but `badarg`; `ets:info/1,2` on a deleted table is `undefined` in the oracle but `badarg`; `ets:info(T, owner)` is the owner's pid in the oracle but `undefined` (see the ETS access-control entry below).
  - **NIF (`beam_abi`/`beam_rt`):** a `load_nif/2` path that **already ends in `.so`** — the oracle appends `.so` unconditionally (`…load_failed`), the Rust runtime de-duplicates the suffix and loads it; a **local** call to a NIF function inside the NIF module runs the `erlang:nif_error` stub (the Rust runtime intercepts only external dispatch); an Erlang module that does **not** stub every function in the NIF's `ErlNifFunc` table loads under the Rust runtime but is refused by the oracle (`{error,{bad_lib,"Function not found …"}}`). The `load_nif/2` failure shapes that DO agree (`load_failed`/`bad_lib`/`reload` + the success round trip) are all in `nif_so.rs`.
  - **Port / driver (`beam_rt`/`beam_io`):** the `{fd,…}` grammar is disjoint (the oracle requires the 3-tuple `{fd,In,Out}`, the Rust runtime implements the 2-tuple `{fd,N}`), so it is unpinnable; the `{line,N}` option returns `{eol,Line}` in the oracle but raw bytes; the `eof` option never delivers `eof`; `port_command(P,42)` (non-iodata) is `badarg` in the oracle but accepted; `port_info(P,registered_name)` is `[]` in the oracle but `badarg`; a `{spawn, Cmd}` whose command is missing exits `127` in both, but only the oracle writes the shell's stderr line (an eval case compares stderr). The agreeing shapes (empty name ⇒ `badarg`, a missing `spawn_executable` ⇒ `enoent`, the non-tuple/non-string name and unknown-option rejects) ARE pinned in `driver_ports.rs`. (Both runtimes run a `spawn` program through a shell — verified.)
  - **Wire codec (`beam_codec`):** legacy `PORT_EXT` (102) preserves the port id in the oracle but zeroes it in the Rust runtime.
  - **Maps (`beam_bifs`/`beam_term`):** a map with **more than 32 keys** cannot be *constructed* by the Rust runtime (`maps:from_list/1` and `maps:put/3` raise `error:system_limit` past 32 entries) where the oracle builds and encodes it; the 32-key edge agrees.
  - **Records (`beam_bifs`/`beam_engine`):** `records:update/4` with an unknown field is `{badfield,{{M,N},K}}` (a nested 2-tuple) in the oracle but `{badfield,{M,N},K}` (flat) in the Rust runtime; `put_record`'s compile-time *create* form is a typed `unsupported` (record-definition table unavailable); generic opcodes **192/193** (`get_record_elements_id`/`update_record_id`) cannot be emitted by the installed OTP-29 `erlc` (its compiler source has no such names) — `is_record_accessible` (190) **is** reachable from a single module (an external record name declared with `-import_record/2`).
  - **Exceptions (`beam_engine`/`beam_rt`):** calling a non-fun (`5(1)`) is `{badfun,5}` in the oracle but `badarg` in the Rust runtime.
  - **`erlang:exit(self(), normal)` (`beam_bifs`/`beam_rt`):** the oracle *ignores* a `normal` exit signal sent to the caller (`erlang:exit(self(), normal)` -> `true`), while the Rust runtime raises `exit:normal` — a plain differing result, so no case pins it (the agreeing `exit(Pid, normal)` shape for a *non-linked other* process IS pinned in `proc_control.rs`).
  - **ETS access control (`beam_ets`/`beam_bifs`):** the access mode is *recorded* at `ets:new/2` (`ets:info(T, protection)` agrees) but not *enforced* on a later access by a non-owner — a non-owner `ets:lookup/2` of a `private` table returns `[]` where the oracle raises `error:badarg`, and a non-owner `ets:insert/2` of a `protected`/`private` table returns `true` where the oracle raises. `ets:info(T, owner)` is the owner's pid in the oracle but `undefined` in the Rust runtime. The *allowed* half of the matrix IS pinned in `ets_access.rs`; the denial half is a handoff.
  - **Evaluator memory (`beam_rt` `-eval`):** a large iolist (`iolist_size(lists:duplicate(200000, <<0>>))`) is a size in the oracle but `error:out_of_memory` in the Rust runtime. Consequently `iolist_size/1`'s bignum promotion is **not expressible** through an observable program (it needs ≳2^59 byte references) and has no case.
  - **CLI flags (`beam_rt`):** plain arguments via `-extra`/`--` are unusable through the harness (the oracle treats the trailing `-eval <probe>` as a plain arg and hangs); a repeated `-eval` flag is recorded verbatim by the Rust runtime where `init:get_argument(eval)` returns `error` in the oracle; a bignum literal in `-eval` is an `unsupported` literal-parser gap; an unbound `-eval` variable is a loud Rust error vs silent oracle.
  - **Environment variables (`ERL_*FLAGS`) — two families are deliberately NOT pinned, each a plain differing result (a `mismatch`), never a capability gap.** (The merge *order* itself **is** pinned — see `flags/env_*` — so the harness extension is exercised; these are the parts that cannot be.)
    - **`ERL_OTP<sysver>_FLAGS`** — the OTP-29 oracle reads `ERL_OTP29_FLAGS` while `beam_rt` (OTP 30) reads `ERL_OTP30_FLAGS`; each runtime ignores the other's name, so an exact assertion on either is a guaranteed mismatch. Not in the corpus.
    - **An `-eval` carried by `ERL_FLAGS`/`ERL_AFLAGS`** — the oracle runs *every* `-eval` in merged order (so the `halt`ing command-line probe preempts the appended one), while the Rust runtime keeps only the **last** `-eval` (verified: an `ERL_FLAGS` `-eval "halt(7)."` yields oracle `ok 2`/exit `0` vs the Rust runtime's exit `7`). The `flags/env_*` cases therefore keep `ERL_AFLAGS`/`ERL_FLAGS` to *ordinary switches* (init arguments, or `+`-emulator flags observed through `system_info/1`), which is where the merge is observable and both runtimes agree.
  - **`+Q N` / `ERL_MAX_PORTS` → `system_info(port_limit)` IS pinned** (`flags/plus_q_*`, `flags/erl_max_ports_sets_port_limit`): `crates/beam_rt/src/info/limits.rs` reports `min(next_power_of_two(request), 134217727)` (default 65536), so the oracle-derived sizing matrix (`+Q 4096`→4096, `2000`→2048, `1025`→2048, `3000`→4096, `134217727`→134217727, `ERL_MAX_PORTS=3000`→4096) agrees. `+Q legacy` / no `+Q` → 65536 is pinned by `system_info/port_limit`.
  - **`erlang:module_loaded/1` (`beam_bifs`):** `module_loaded(lists)` is `true` in the oracle but `false` in the Rust runtime (the loader does not record a system module as loaded).
  - **`erlang:trace_info/2` (`beam_bifs`):** `trace_info(self(),all)` is `badarg` in the oracle but returns `[{flags,[]},{tracer,[]},{match_spec,[]},{traced,false}]` in the Rust runtime, and `trace_info(self(),traced)` is `{traced,false}` vs the oracle's `badarg`; only the `flags`/`tracer` selectors agree and are pinned in `system_info.rs`.
  - **`erlang:halt/1` argument validation (`beam_rt`):** `halt([1,2])` prints nothing (exit 1) in the oracle but exits with `beam_rt_dump:` in the Rust runtime; only the `halt({bad})` -> `badarg` shape is pinned.
  - **`+hmax` overflow (`beam_rt`):** under `+hmax 1048576`, `length(lists:seq(1,1000000))` kills the oracle process (no stdout, exit 1, `kill => true` default) while the Rust evaluator raises `error:system_limit`, so a `system_limit` boundary case is not pinnable; only the `+hmax*`/`+hms`/`+hmbs` acceptance with a tiny bounded allocation (`length(lists:seq(1,1000))` -> `1000`) is pinned in `flags.rs`.
  - **`erlang:memory/0,1` is pinned structurally** (`system_info/memory_*`, A.8): the 9-key order (`total,processes,processes_used,system,atom,atom_used,binary,code,ets`), the count 9, `is_integer(erlang:memory(total))`, the `[atom,total]` selection shape (`[K || {K,_} <- erlang:memory([atom,total])]` -> `[atom,total]`) and the unknown-key `badarg`; the volatile byte totals are never asserted. (`process_info/2` items with a documented deterministic default — `message_queue_len`, `messages`, `priority`, `dictionary`, `fullsweep_after`, … — *are* pinned in `system_info.rs`.)
- **NOT covered here (verified against the corpus sources):** `erl_debugger`, `atomics`, `counters`; `erts_debug` only through `size/1`; `net_kernel` (`dflag_unicode_io/1`); `prim_file` (`internal_normalize_utf8/1`); `re` (`compile/1,2`, `import/1`, `inspect/2`, `internal_run/4`, `run/2,3`, `version/0`); `erts_internal:*` only through `cmp_term/2` (`group_leader/2,3`, `port_*`, `trace*`, `purge_module/2`, `process_flag/3`, `garbage_collect/1`, `is_process_alive/2`, `scheduler_wall_time/1`, `atomics_new/2`, `counters_*` absent); `code:` only `get_path`/`which`/`lib_dir`/`all_loaded`/`objfile_extension`/`is_loaded`/`ensure_loaded`/`is_sticky`/`root_dir` (not the coverage/debug-info API); `os:` only `cmd/1` (not `set_signal/2`); `erl_ddll` only `load_driver/2` (not the `monitor`/`try_load`/`loaded_drivers` family); the extended `ets` API (`slot/2`, `select_reverse/1,2,3`, `*_lookup/*`, `give_away/3`, `rename/2`, `setopts/2`, `match_spec_run_r/3`) is absent. `erlang:open_port/2`, `port_close/1`, `port_command/2,3`, `port_info/1,2` *are* exercised (the `erlang` BIFs, never the `erts_internal:` forms).
- **What `beam_rt` must do for an expression case to reach `agree`:** the eval cases spawn `beam_rt -noshell <extra…> -eval <probe>` and compare **stdout + exit + stderr** against the oracle (module-run cases: stdout + exit only). `erl -eval` does **not** echo the value - the probe prints the single `ok …` / `exception <class> <reason>` line itself and `halt`s - so `beam_rt -eval` must likewise **not** auto-print the result (a second line breaks `Agree`) and must evaluate the whole single-line `try (EXPR) of V -> … catch C:R -> … end.` wrapper. The module-run side uses `beam_rt run <file.beam> <mod>:<fun>/<arity> <args…>`, which must print `~w` of the result + a trailing newline (the oracle prints the same via its `io:format("~w~n",…)`).
- **Residual: the module/temp-dir helpers still root temp dirs at `std::env::temp_dir()`.** That is normal production behaviour, but it means the **in-process** tests (`tests/oracle.rs`, `tests/module_sweep.rs`) place `.beam`/`.so` temp dirs under the ambient `$TMPDIR`. Run them with a private `TMPDIR` in an environment whose `$TMPDIR` is shared/cleaned (the `tests/cli.rs` child processes are already independent of it — see *Design Decisions*).

## Test Strategy
- `#[cfg(test)]` unit tests in every core module: `cli` (arg parsing for `run`/`compare`/`suite --strict --allowlist --gaps`/`list --by-contract`, and `--help`); `allowlist` (parse: comments/blank lines, the trailing `\r`, whitespace-separated tokens, the malformed/duplicate usage errors, a missing-file `Io` error, the load path/entries round trip, `empty`); `ratchet` (the gap/unauthorized/stale classification, `report_from_suite`, `suite_exit_code`, the `gaps_markdown` table incl. `|` escaping); `runtime` (env injection - `run` is `run_with_env(..., &[])`; argv shapes; the bounded `ETXTBSY` retry); `compare` (the pure diff + golden logic, stderr classification, the `Unsupported`-vs-observation rules); `corpus` (registry well-formedness: unique ids, >=1 contract each, per-kind goldens, the module-run argv shape + contract allow-list, only an `EvalEnv` case sets an env, never an empty one); `module_build`/`nif_build` (erlc/cc resolution, a loud compile failure, temp-dir cleanup, the `erl_nif.h` locator, the `.so` build + cache, the skip reasons); `harness` (exit-3 classification, the unsupported reason, the eval probe shape, and the caught-capability-gap classifier - its guard set is in *Observable results*); and the per-group registry tests (`nif_so` integer classification, `ets`, `records` opcodes).
- `tests/common/mod.rs` is the shared support module for the integration tests (a `tests/` subdirectory module, so it is never its own test binary): `fresh_rust_runtime()`/`fresh_rust_spec()` (the fresh debug `beam_rt`, so no test depends on a stale release build) and `scratch_root()` (a worktree-local `CARGO_TARGET_TMPDIR` scratch root). `src/test_support.rs` is the `#[cfg(test)]`-only in-crate counterpart (a `Scratch` dir, a counting/fabricating compiler stub) shared by the `module_build`/`nif_build` tests.
- `tests/oracle.rs` integration: **oracle-backed** - the oracle reproduces the `{ok,42}` golden; every **expression** case reproduces its golden (the `EvalEnv` cases through `run_with_env`, so the `ERL_*FLAGS` merge is oracle-verified too; the corpus must carry at least one); every **module-run** case reproduces its golden under the oracle (compiled with `erlc`, its NIF fixture materialized by `module_build::build`, which reports `Build::Skipped` for a missing host tool); oracle-vs-oracle on the same case => `Verdict::Agree`; a Rust runtime forced to a nonexistent path => `unsupported` (never `pass`). It builds an explicit `RuntimeContext` with the fresh runtime, so it cannot observe a stale release build; these **skip with a loud note** (not a silent pass) when `erl`/`erlc`/`cc` is unavailable.
- **The transient-`ETXTBSY` retry (mechanism in *Design Decisions*) is covered deterministically.** On Linux, `exec`ing a file held open for writing returns `ETXTBSY` at the VFS level, so the tests hold the descriptor open and assert the retry is bounded + surfaces the error (`runtime::tests::output_with_retry_is_bounded_on_etxtbsy_and_surfaces_it`, `module_build::tests::a_compiler_that_cannot_be_exec_yet_is_a_loud_error_not_a_hang`), that it *recovers* once the writer releases (`..._recovers_once_the_transient_writer_closes`), that a non-`ETXTBSY` error is returned unchanged, and that a successful spawn passes through. `tests/cli.rs::fake_runtime` flushes, `sync_all`s and **closes** its fake `$BEAM_RT` before it can be executed.
- `tests/cli.rs` drives the **binary** as a child process (so `$ERTS_ORACLE`/`$BEAM_RT`/`TMPDIR` can be injected without touching the test process environment) and locks in the exit-code contract (`0`/`1`/`2`), the `--help` surface, the `--out` report file and the `list` path that needs no runtime. Every default-resolution invocation injects `$BEAM_RT` = the fresh debug runtime. It also injects a fake `$BEAM_RT`: one printing a different stdout must still be `[MISMATCH]` (exit 1), one printing `beam_rt: unsupported: ...` and exiting `3` must be `unsupported` (exit 0 lenient, `1` under `--strict`). Oracle-dependent cases skip loudly when `erl` is unavailable.
- The suite assertion **never pins the current capability-gap count**: it checks the state-independent invariant that every case falls into exactly one verdict bucket (`agree + unsupported + skipped + mismatches == summary.total`) plus the branch-specific `agree >= 1` / `agree == 0`. The "is agreement possible" gate mirrors the runtime the **child** resolves (the injected fresh debug sibling **or** the workspace default via `runtime::resolve_rust_from(None, CARGO_MANIFEST_DIR)`), so the test is correct both when only a `release` `beam_rt` exists and when the fresh `debug` one exists.
- Gate: `cargo test -p differential` GREEN and `differential suite --json` runs end-to-end with every mismatching id listed in `tests/cli.rs`'s `KNOWN_RUNTIME_GAPS` (an *unexpected* mismatch fails the test; it is empty — today there are **zero** mismatches). The allowlist ratchet is exercised end to end against the real corpus with a fake exit-`3` runtime (`tests/cli.rs::the_ratchet_tolerates_only_the_recorded_gaps_end_to_end`: an allowlist recording every case id is exit `0`; a missing id plus a bogus id is exit `1` and names both in the generated `GAPS.md`). The CI gate is `gate.sh`.
- `tests/abi.rs` covers A.3/A.4 structurally (mechanism in *Design Decisions*) and skips loudly when no `cc`/`gcc`/`clang` is available (no `crates/*` dependency, no `unsafe`).
- `tests/module_sweep.rs` is the broad real-module **execute** sweep (72 entries across 14 real system modules), driven through `differential::harness` under both runtimes; every outcome is `Agree`/`Unsupported` (never `Mismatch`), with a per-module rollup; skips loudly without the oracle/`erlc`.
- The `corpus` registry tests assert all nine contracts A.1-A.9 are represented and that >=20 module-run (genuine-agreement) cases exist.
- The per-contract rollup, the `ratchet` key and the `list --by-contract` view are covered by `#[cfg(test)]` unit tests in `report/` (rollup counts per contract, a multi-contract case, the additive top-level `by_contract` JSON key, the additive `ratchet` key — omitted and unrendered without an allowlist — the contract-free `compare` rollup, and the grouped listing keeping the plain output unchanged) and in `cli.rs` (arg parsing for `--by-contract`, `--strict`, `--allowlist` and `--gaps`, including that only `suite` takes the last two).
