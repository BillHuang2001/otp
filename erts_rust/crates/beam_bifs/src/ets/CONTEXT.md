# `beam_bifs::ets` — the `ets:*` BIF bridge (`src/ets.rs` + `src/ets/`)

## Intent
The `ets:*` BIF surface of `beam_bifs`: the `TableRegistry` (handle → live `beam_ets::Table`, name → handle, forward- and reverse-continuation handles, compiled-spec handles) plus every registered `ets:*` BIF, built on `beam_ets`'s table semantics. The crate's `TableRegistry` is the M1 "runtime side" of ETS — the table state itself, the access matrix and the match-spec engine stay in `../beam_ets` (read-only).
Ground truth (read-only): `../../../erts/emulator/beam/erl_db_*.c`, `erl_db_util.c` and the compiled `ets.erl` wrappers.
`bif.tab` declares 59 `ets:*` keys: **57 are served here**, **2** C-interior ones (`internal_request_all/0`, `slot/2`) stay seam-backed typed `unsupported_bif` gaps in `../runtime/other.rs`. `fun2ms/1`/`repair_continuation/2` are **not** in `bif.tab` (pure `ets.erl` functions) and stay unregistered.

## API Surface
Keys by file (57 here):
- `src/ets.rs` (25): `new/2 delete/1,2 delete_all_objects/1 delete_object/2 first/1 info/1,2 insert/2 insert_new/2 last/1 lookup/2 lookup_element/3,4 member/2 next/2 prev/2 select/1,2,3 tab2list/1 take/2 update_counter/3,4 update_element/3`. It also owns the `TableRegistry` (`insert`/`remove`/`take`/`lookup_name`/`insert_name`/`remove_name`/`all_tids`/`contains`/`insert_profile`/`forget_profile`/`insert_spec`/`spec_raw`/continuations) and the shared helpers `take_table`/`take_table_gated`/`restore_table`/`copy_out`/`copy_out_list`/`key_or_end`.
- `src/ets/matches.rs` (10): `match/1,2,3 match_delete/2 match_object/1,2,3 select_count/2 select_delete/2 select_replace/2`, plus the shared `finish_chunk`/`resume_continuation`.
- `src/ets/specs.rs` (3): `match_spec_compile/1 match_spec_run/2 match_spec_run_r/3` (the opaque compiled-spec handle).
- `src/ets/extra.rs` (7): `safe_fixtable/2 whereis/1 update_element/4 is_compiled_ms/1 rename/2 internal_delete_all/2 internal_select_delete/2`.
- `src/ets/adopt.rs` (5): `all/0 setopts/2 give_away/3 foldl/3 foldr/3`.
- `src/ets/nav.rs` (4): `first_lookup/1 last_lookup/1 next_lookup/2 prev_lookup/2`.
- `src/ets/reverse.rs` (3): `select_reverse/1,2,3` (+ the reverse-continuation registry).
- `src/ets/resolve.rs`: no BIFs — `resolve_handle`/`resolve_handle_opt`, the owner bridge, `parse_options` and the `Gate` check (below).
- **`resolve_handle` (`src/ets/resolve.rs`) is THE single table-argument resolver**, shared by every table-taking BIF: a handle ref thing, or — for a table created with the `named_table` option — its **name atom**; anything else is `badarg` (the `{Name,Node}` distributed form is **not** a table argument in OTP 29). `ets:new/2` returns the **name atom** for a `named_table` and the handle ref otherwise.
- **The owner is recorded and every table-taking BIF is access-gated.** `ets:new/2` records `ctx.self_pid()` as the owner (`resolve::caller_owner` → `beam_ets::OwnerId`, the pid immediate bridged losslessly), and each BIF evaluates the **calling** process through the same bridge: owner ⇒ read+write; a non-owner ⇒ `public` both, `protected` read only, `private` neither. Every denial is `badarg` and leaves the table in the registry. `ets:info/1,2` is **not** gated.
- **`parse_options` reproduces the C `ets_new_2` accept/reject matrix** (`erl_db.c`): kinds `set`/`ordered_set`/`bag`/`duplicate_bag`, accesses `public`/`protected`/`private`, `named_table`, `compressed`, and the tuples `{keypos, N>0}`, `{read_concurrency, Bool}`, `{write_concurrency, Bool|auto|{debug_hash_fixed_number_of_locks, N}}`, `{heir, Pid|none}`, `{heir, Pid, Data}`, `{decentralized_counters, Bool}`. Repeated options follow last-wins **except** the bare `set`/`protected` atoms, which are NO-OPS (`erl_db.c:2710`); an `ordered_set` carrying the explicit lock count is `badarg` after the loop.
- **A `TableProfile` sidecar carries the effective `write_concurrency`/`decentralized_counters` rendering** that `beam_ets::TableInfo` cannot express, and SURVIVES a take/restore round-trip (`TableRegistry::take` keeps it); `ets:delete/1` drops it (`forget_profile`). `ets:info/2` prefers the profile for those two items and falls back to `TableInfo::decentralized_counters`/`TableInfo::write_concurrency` for a table inserted straight into the registry.
- **`ets:info/1,2` on an unknown or deleted table returns the bare atom `undefined`** (the oracle's `ets_info_1`); the resolution happens before the `Item` is looked at, so `ets:info(bogus, 42)` is `undefined` while `ets:info(T, 42)` on a live `T` is `badarg`. M1 deviation: the oracle distinguishes a tid from an ordinary `make_ref()` (the former `undefined`, the latter `badarg`), but the M1 handle is an ordinary ref thing, so a bare ref is `undefined` here too.
- **`ets:info/1,2` emits the oracle's full 15-field order** (`id, decentralized_counters, read_concurrency, write_concurrency, compressed, memory, owner, heir, name, size, node, named_table, type, keypos, protection`; `owner` and `heir` render the recorded pid terms — the atom `undefined` when unset). `ets:info(T, id)` returns the **tid reference** (`make_ref_thing(heap, info.id.raw())`; `is_reference/1` true, `Info =:= T`), not a bare integer. `TableInfo::entries` is reproduced by hand (it takes `&mut AtomTable` while `BifContext` borrows the atom table immutably).
- **`lookup_element/3,4` route a MULTI kind through the list forms.** `src/ets.rs` branches on `Table::kind().is_multi()`: `set`/`ordered_set` keep the scalar `lookup_element`/`lookup_element_or`; `bag`/`duplicate_bag` use `Table::lookup_element_all`/`lookup_element_all_or` and render the result as a **list** (`ets:lookup_element(Bag,1,2)` => `[a,b]`, `duplicate_bag` preserves duplicates). `/4` on an absent key returns the caller's `default` verbatim; `pos == 0`, an absent key on `/3`, and a present object shorter than `pos` are `badarg` — for every kind.
- **The `select` family carries continuations.** `select/1,2,3` (and the `match*`/`match_object*` `/1` forms) decode a continuation from a `Ref` thing (`CONTINUATION_ID_BASE = 1<<40`) into the registry's `continuations` map, run `beam_ets`'s `*_continue` forms, and re-render: `(results, None)` => the bare atom `'$end_of_table'` when `results` is empty, else `{Results, '$end_of_table'}`; `(results, Some(c))` => `{Results, ContinuationTerm}`. `limit == 0` is `badarg`; the spec construct form must be a 1-tuple holding the clause tuple.
- **`select_reverse/1,2,3` (`src/ets/reverse.rs`) is the descending variant.** For `ordered_set` the results come in **descending key order**; for `set`/`bag`/`duplicate_bag` the order is unspecified and **identical to `select`** (the C ignores the reverse flag for hash interiors), so `/2` runs `Table::select` and reverses the vector only for `ordered_set`. `beam_ets` exposes no reverse scan and `MatchContinuation` is opaque/forward-only, so a reverse continuation is held in a module-local registry (`REVERSE_CONTINUATION_ID_BASE = 1<<41`, entries `{table, raw_spec, position, limit}`) and a resume **recomputes** the full reverse-ordered list from the current table and slices it (no table-owned term is held across calls). Continuations are immutable (a resume mints a fresh entry — an M1 registry leak). `select/1` and `select_reverse/1` share one dispatcher, so the **stored direction** decides the walk (the oracle treats them as the same BIF).
- **`first_lookup/1`/`last_lookup/1`/`next_lookup/2`/`prev_lookup/2` (`src/ets/nav.rs`)** return `{Key, [Objects]}` or the bare atom `'$end_of_table'` (read-gated; a bad/unknown/deleted table is `badarg`). For a **hash** kind the oracle aliases them (`last_lookup == first_lookup`, `prev_lookup == next_lookup`); the BIF layer special-cases hash kinds without changing `beam_ets::Table::last`/`prev`. A hash kind with an absent anchor key (or the `'$end_of_table'` anchor) is `badarg`, matching `Table::next`/`prev`; an empty table is `'$end_of_table'`.
- **`rename/2` (`src/ets/extra.rs`)** is write-gated and delegates to `beam_ets::Table::rename(name, is_taken)`. A `named_table` rekeys the registry name map and returns the **new name atom** (`RenameOutcome::Named`); a table without `named_table` leaves the registry untouched and returns the **unchanged handle** (`RenameOutcome::Unnamed`). A non-atom name, an unknown/deleted table, and an already-taken name (including the table's own) are `badarg` with nothing changed. `ets:whereis(old)` becomes `undefined` after a named rekey.
- **`internal_delete_all/2`** returns the deleted-object count for a holder of `undefined`, else the holder term verbatim (the C trap protocol), and `internal_select_delete/2` returns the deleted-object count for a raw spec; both are write-gated and `badarg` on a bad table (checked before the holder/spec).
- **`match_spec_run_r/3` (`src/ets/specs.rs`)** runs a **compiled** spec handle over a proper list and PREPENDS each match onto `Acc` (so the output is the reversed match-prefix with `Acc` as the list tail); `[]` returns `Acc` verbatim; a non-list/improper list/raw spec/non-ref spec is `badarg`.
- **`ets:match_delete/2` returns the atom `true`, not a count** (a stdlib `ets.erl` function, not a BIF); `select_delete/2` returns a count and `select_replace/2` the number replaced, with **`bag` => `badarg`** checked before the spec.
- **The raw-vs-compiled spec rule is asymmetric (oracle-verified, must not be "fixed")**: the `select` family accepts **only a raw clause list** (a `match_spec_compile/1` handle is `badarg`), while `match_spec_run/2` and `match_spec_run_r/3` accept **only the compiled handle** (a raw list is `badarg`). `match_spec_compile/1` returns an on-heap `Ref` thing and stores the **raw** spec term; a raising match-spec body surfaces as the atom `EXIT`.
- **The adopted verbs (`src/ets/adopt.rs`):** `ets:all/0` (the registry's tids, sorted by ascending id), `ets:setopts/2` (`{heir, none|Pid|Pid,Data}`, owner-only; a dead heir is accepted and clears the heir), `ets:give_away/3` (a live, *different* pid, owner-only), and `ets:foldl/3`/`ets:foldr/3` (the stdlib wrappers over `first`/`next`/`last`/`prev` + `lookup`, the fun applied through the `FunCaller` seam; an **empty table returns `Acc0` without calling the fun**).
- Genuine remaining gaps (each a typed `unsupported_bif` or unregistered, never a wrong result): `ets:setopts/2`'s `{protection,_}` sub-option (whole call => typed gap; needs a `beam_ets` access setter — see the handoff below), `ets:slot/2` and `ets:internal_request_all/0` (seam-backed in `../runtime/other.rs`); `ets:fun2ms/1` and `ets:repair_continuation/2` are stdlib-only and stay unregistered. The M1 table id is a synthesized `Ref` thing.

## Guard-scoped views — not needed here (audited)
`beam_ets` also offers an escape-proof `SharedTable`/`TableRead`/`TableWrite`/`TableTerm` view layer, but this bridge deliberately uses the **raw, owned `Table`** primitives. That is sound: the `TableRegistry` owns `Table`s (not `SharedTable`), a BIF *takes* the table out, works on it and *restores* it, and every term derived from table storage is copied onto the caller's heap (`copy_out`/`copy_out_list` → `beam_message::copy_struct_simple`) before it is returned, so **no returned term aliases table storage**. A full audit of every table-derived `Eterm` return path in `ets.rs`/`nav.rs`/`reverse.rs`/`matches.rs`/`specs.rs`/`extra.rs`/`adopt.rs` found no escaping site, so no view adoption is required. (`key_objects` copies out just *after* `restore_table`, which is equally safe: the table is moved back into the registry, never dropped, and the arena never relocates.)

## Constraints
- Errors are `beam_common::{Result, BeamError}` only — `BadArg` for every argument/semantics failure (the oracle's own reason), `unsupported_bif` only for an uninstalled seam or a genuine capability gap. Never a panic, never a wrong result.
- `#![deny(unsafe_code)]` at the crate root; no `unsafe` here — raw term movement goes through `crate::access` and `beam_message::copy_struct_simple`.
- Table state, the access predicates and the match-spec engine are `beam_ets`'s; the metric/`info` field mapping, the handle registry and the option parsing are this module's. Never re-implement `beam_ets` semantics here.
- All term storage a `beam_ets::Table` hands back lives in a never-relocating bump arena, so a BIF may take the table out of the registry, work on it and restore it — even on the error path.
- Registration order: `crate::ets::register` (which calls the `matches`/`specs`/`extra`/`adopt`/`nav`/`reverse` sub-registers) runs BEFORE `crate::runtime::register`; `src/runtime/other.rs` now registers only `ets:internal_request_all/0` and `ets:slot/2`, so no `ets` key is shadowed.

## Handoff to beam_ets
- `ets:setopts/2`'s `{protection, public|protected|private}` sub-option cannot be served: a table's `Access` is set only at `TableOptions::build` time and there is **no** post-creation setter. Needed API: `beam_ets::Table::set_access(&mut self, access: Access)` — or a `SetOpt::Access(Access)` variant handled by `Table::setopts(caller, opt)` — carrying the same **owner write gate** `Table::setopts` already applies. Until then any call containing `{protection,_}` returns the typed `unsupported_bif` with the table untouched (never a wrong protection).
- Optional (not required): a native reverse select family (a `select_reverse_limit`/`select_reverse_continue` + a direction-carrying `MatchContinuation`) would let `src/ets/reverse.rs` drop the recompute-based reverse continuation. The current BIF-layer implementation is oracle-faithful for a non-mutated table.
