# `beam_bifs::ets` — the `ets:*` BIF bridge (`src/ets.rs` + `src/ets/`)

## Intent
The `ets:*` BIF surface of `beam_bifs`: the `TableRegistry` (handle → live `beam_ets::Table`, name → handle, continuation handles, compiled-spec handles) plus every registered `ets:*` BIF, built on `beam_ets`'s table semantics. The crate's `TableRegistry` is the M1 "runtime side" of ETS — the table state itself, the access matrix and the match-spec engine stay in `../beam_ets` (read-only).
Ground truth (read-only): `../../../erts/emulator/beam/erl_db_*.c`, `erl_db_util.c` and the compiled `ets.erl` wrappers.
59 `ets:*` keys in all: 46 served here, 13 C-interior ones seam-backed in `../runtime/other.rs` (see `../runtime/`).

## API Surface
Keys by file:
- `src/ets.rs` (25): `new/2 delete/1,2 delete_all_objects/1 delete_object/2 first/1 info/1,2 insert/2 insert_new/2 last/1 lookup/2 lookup_element/3,4 member/2 next/2 prev/2 select/1,2,3 tab2list/1 take/2 update_counter/3,4 update_element/3`. It also owns the `TableRegistry` (`insert`/`remove`/`take`/`lookup_name`/`insert_name`/`remove_name`/`all_tids`/`contains`/`insert_profile`/`forget_profile`/`insert_spec`/`spec_raw`/continuations) and the shared helpers `take_table`/`take_table_gated`/`restore_table`/`copy_out`.
- `src/ets/matches.rs` (10): `match/1,2,3 match_delete/2 match_object/1,2,3 select_count/2 select_delete/2 select_replace/2`, plus the shared `finish_chunk`/`resume_continuation`.
- `src/ets/specs.rs` (2): `match_spec_compile/1 match_spec_run/2` (the opaque compiled-spec handle).
- `src/ets/extra.rs` (4): `safe_fixtable/2 whereis/1 update_element/4 is_compiled_ms/1`.
- `src/ets/adopt.rs` (5): `all/0 setopts/2 give_away/3 foldl/3 foldr/3`.
- `src/ets/resolve.rs`: no BIFs — `resolve_handle`/`resolve_handle_opt`, the owner bridge, `parse_options` and the `Gate` check (below).
- **`resolve_handle` (`src/ets/resolve.rs`) is THE single table-argument resolver**, shared by every table-taking BIF: a handle ref thing, or — for a table created with the `named_table` option — its **name atom**; anything else is `badarg` (the `{Name,Node}` distributed form is **not** a table argument in OTP 29). `ets:new/2` returns the **name atom** for a `named_table` and the handle ref otherwise.
- **The owner is recorded and every table-taking BIF is access-gated.** `ets:new/2` records `ctx.self_pid()` as the owner (`resolve::caller_owner` → `beam_ets::OwnerId`, the pid immediate bridged losslessly), and each BIF evaluates the **calling** process through the same bridge: owner ⇒ read+write; a non-owner ⇒ `public` both, `protected` read only, `private` neither. Every denial is `badarg` and leaves the table in the registry. `ets:info/1,2` is **not** gated.
- **`parse_options` reproduces the C `ets_new_2` accept/reject matrix** (`erl_db.c`): kinds `set`/`ordered_set`/`bag`/`duplicate_bag`, accesses `public`/`protected`/`private`, `named_table`, `compressed`, and the tuples `{keypos, N>0}`, `{read_concurrency, Bool}`, `{write_concurrency, Bool|auto|{debug_hash_fixed_number_of_locks, N}}`, `{heir, Pid|none}`, `{heir, Pid, Data}`, `{decentralized_counters, Bool}`. Repeated options follow last-wins **except** the bare `set`/`protected` atoms, which are NO-OPS (`erl_db.c:2710`); an `ordered_set` carrying the explicit lock count is `badarg` after the loop.
- **A `TableProfile` sidecar carries the effective `write_concurrency`/`decentralized_counters` rendering** that `beam_ets::TableOptions` cannot express, and SURVIVES a take/restore round-trip (`TableRegistry::take` keeps it); `ets:delete/1` drops it (`forget_profile`).
- **`ets:info/1,2` on an unknown or deleted table returns the bare atom `undefined`** (the oracle's `ets_info_1`); the resolution happens before the `Item` is looked at, so `ets:info(bogus, 42)` is `undefined` while `ets:info(T, 42)` on a live `T` is `badarg`. M1 deviation: the oracle distinguishes a tid from an ordinary `make_ref()` (the former `undefined`, the latter `badarg`), but the M1 handle is an ordinary ref thing, so a bare ref is `undefined` here too.
- **The adopted verbs (`src/ets/adopt.rs`):** `ets:all/0` (the registry's tids, sorted by ascending id), `ets:setopts/2` (`{heir, none|Pid|Pid,Data}`, owner-only; a dead heir is accepted and clears the heir), `ets:give_away/3` (a live, *different* pid, owner-only), and `ets:foldl/3`/`ets:foldr/3` (the stdlib wrappers over `first`/`next`/`last`/`prev` + `lookup`, the fun applied through the `FunCaller` seam; an **empty table returns `Acc0` without calling the fun**).
- **`ets:info/1,2` emits the oracle's full 15-field order** (`id, decentralized_counters, read_concurrency, write_concurrency, compressed, memory, owner, heir, name, size, node, named_table, type, keypos, protection`; `owner` and `heir` render the recorded pid terms — the atom `undefined` when unset). `ets:info(T, id)` returns the **tid reference** (`make_ref_thing(heap, info.id.raw())`; `is_reference/1` true, `Info =:= T`), not a bare integer. `TableInfo::entries` is reproduced by hand (it takes `&mut AtomTable` while `BifContext` borrows the atom table immutably).
- **The `select` family carries continuations.** `select/1,2,3` (and the `match*`/`match_object*` `/1` forms) decode a continuation from a `Ref` thing (`CONTINUATION_ID_BASE = 1<<40`) into the registry's `continuations` map, run `beam_ets`'s `*_continue` forms, and re-render: `(results, None)` => the bare atom `'$end_of_table'` when `results` is empty, else `{Results, '$end_of_table'}`; `(results, Some(c))` => `{Results, ContinuationTerm}`. `limit == 0` is `badarg`; the spec construct form must be a 1-tuple holding the clause tuple.
- **The raw-vs-compiled spec rule is asymmetric (oracle-verified, must not be "fixed")**: the `select` family accepts **only a raw clause list** (a `match_spec_compile/1` handle is `badarg`), while `match_spec_run/2` accepts **only the compiled handle** (a raw list is `badarg`). `match_spec_compile/1` returns an on-heap `Ref` thing and stores the **raw** spec term; a raising match-spec body surfaces as the atom `EXIT`.
- **`lookup_element/3,4` are SCALAR-ONLY and therefore incomplete for `bag`/`duplicate_bag`.** Both call `beam_ets::Table::lookup_element`/`lookup_element_or` (`src/ets.rs`), which raise the typed `unsupported(MULTI_ELEMENT_SCALAR)` for a **present** key on a multi kind — while the oracle answers a **list** (`ets:lookup_element(Bag,1,2)` => `[a,b]`, `duplicate_bag` => `[a,a,b]`; an absent key is `default`/`badarg`). `beam_ets` already exposes the list-returning `Table::lookup_element_all`/`lookup_element_all_or`; the fix is to route a multi-kind present key through them and render the list. Untested today (`tests/ets_ops.rs`/`tests/ets_access.rs` exercise `set` only).
- **`ets:match_delete/2` returns the atom `true`, not a count** (a stdlib `ets.erl` function, not a BIF); `select_delete/2` returns a count and `select_replace/2` the number replaced, with **`bag` => `badarg`** checked before the spec.
- Not implemented (every one a typed gap, never a wrong result): `rename/2` (needs `beam_ets::Table::set_name`), `select_reverse/1,2,3` (needs a reverse select family), `match_spec_run_r/3` (needs `beam_ets::match_spec_run_r`), `setopts/2`'s `{protection, _}` (needs `beam_ets::Table::set_access`), plus `fun2ms/1`, `repair_continuation/2`, `slot/2`, the `first_lookup/1`/`last_lookup/1`/`next_lookup/2`/`prev_lookup/2` family and the `internal_*` helpers; the 13 C-interior runtime keys; the table id is a synthesized `Ref` thing.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only — `BadArg` for every argument/semantics failure (the oracle's own reason), `unsupported_bif` only for an uninstalled seam or a genuine capability gap. Never a panic, never a wrong result.
- `#![deny(unsafe_code)]` at the crate root; no `unsafe` here — raw term movement goes through `crate::access` and `beam_message::copy_struct_simple`.
- Table state, the access predicates and the match-spec engine are `beam_ets`'s; the metric/`info` field mapping, the handle registry and the option parsing are this module's. Never re-implement `beam_ets` semantics here.
- All term storage a `beam_ets::Table` hands back lives in a never-relocating bump arena, so a BIF may take the table out of the registry, work on it and restore it — even on the error path.
