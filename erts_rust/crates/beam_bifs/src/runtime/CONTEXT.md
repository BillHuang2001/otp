# `beam_bifs::runtime` — the runtime-coupled BIF families (`src/runtime/`, the `runtime_bif!` macro)

## Intent
Every registered BIF whose implementation needs the *running* runtime (Stage 5, Part I §A.7): process control, timers, code loading, system/nodes introspection, the ETS C interior, the `erts_debug`/`erl_debugger` tools, the `re` engine, the `erl_ddll` loader and the distribution machinery.
Most such BIFs bridge through the single `RuntimeHooks` seam (`erlang:memory/0,1` through `MemoryHook`); with no hook installed a call answers the typed `unsupported_bif` capability gap — never `undef`, never a fabricated value.
The seam families (`erlang` 76, `erts_internal` 56, `erts_debug` 20, `debugger` 13, `other` 28 — **193** registered family keys) forward to the single `RuntimeHooks` seam **except the 46 keys that have real implementations** — the five families' `REAL_BIFS`: `erlang` 3 (`erlang:is_builtin/3`, `erlang:term_to_iovec/1,2`), `erts_debug` 14 (`map_info/1`, `unaligned_bitstring/2`, `interpreter_size/0`, `disassemble/1`, `lcnt_clear/0`, `lcnt_collect/0`, `lcnt_control/1,2`, `get_internal_state/1`, `set_internal_state/2`, `size_shared/1`, `copy_shared/2` and the two collector stubs `erts_trace_cleaner:send_trace_clean_signal/1` / `erts_literal_area_collector:send_copy_request/3`), `debugger` 13 (the whole `erl_debugger` surface), `erts_internal` 2 (`erts_internal:ets_raw_first/1`, `erts_internal:ets_raw_next/2`) and `other` 14 (the 8 `re` engine keys + the 6 `erl_ddll` keys) — leaving **147** seam-forwarding keys, exactly the `RUNTIME_HOOKS_BIFS` roster.
`erlang:memory/0,1` read `MemoryHook`; the **13** `atomics`/`counters` resource-object keys and the whole self-contained `erl_ddll` surface — `format_error_int/1` (`src/runtime/ddll.rs`) plus the six loading/monitor keys (`src/runtime/ddll/{registry,live,info,monitor}.rs`) — are real too. The seven real `erl_ddll` keys are inside the 193/46 figures above (they are `other`-family keys), never extra keys.
Ground truth (read-only): the corresponding C in `../../../erts/emulator/beam/` (`erl_bif_*.c`, `bif.c`, `erl_time_sup.c`, `erl_db_*.c`, `erl_bif_atomics.c`, `erl_bif_counters.c`), plus `string:misc`/`global` semantics for the tools' surfaces.

## API Surface

## Keys served for real inside the seam families (21)
Twenty-one `bif.tab` keys that would otherwise forward to `RuntimeHooks` are implemented here as real `BifFn`s, each listed in its family's `REAL_BIFS` (a `pub(crate) const` asserted by that family's `register` and self-tested). Each is pure or self-contained — none needs Stage-5 state a BIF cannot reach.
- **`erlang:term_to_iovec/1,2`** (`erlang.rs`) — `term_to_binary`'s image as an iovec, over `beam_codec`. Oracle-verified quirks: the return is a **bare binary** when a non-zero compression level is selected (the C's `erts_term_to_binary_int` forces `iovec=0` when `level != 0`) and a **1-element list** at level 0; `[iovec]`/`[{fragment,1}]`/`[garbage]`/`[{compressed,10}]`/`[{minor_version,3}]` are `badarg`. Documented deviation: the oracle splits a large refc binary's payload into separate iovec elements (`term_to_iovec(binary:copy(<<1>>,65))` → byte sizes `[6,65]`); this runtime emits one contiguous image (same bytes, fewer segments).
- **`erlang:is_builtin/3`** (`erlang.rs`) — the C's `erts_is_builtin` (`beam_common.c:2359-2385`): **`bif.tab`-declaration membership ∪ {`erlang:apply/2,3`, `erlang:yield/0`}** (the latter hardcoded as "implemented as instructions as opposed to SNIFs"), **not** registry membership — the 82 stdlib fast paths the oracle reports `false` (`lists:map/2`, `io_lib:format/2`, `erlang:memory/0,1`, …) would be wrong values under a registry rule. The arity is truncated to 32 bits (the C's `int arity`). Lives on a `OnceLock`-cached sorted declaration set; an unreadable table → typed `unsupported_bif`.
- **`erts_debug:unaligned_bitstring/2`** (`erts_debug.rs`) — a pure bitstring transform over `crate::access`. Oracle-verified: `(<<>>, 1)` → `<<>>` (an empty source is not an error); only offsets `1..=7` are accepted (`0`/`8`/`9`, a non-small offset, a non-bitstring source ⇒ `badarg`). Documented deviation: the C returns a refc `ErlSubBits` whose bit pointer sits below the byte start, so `binary:referenced_byte_size/1` of the result (65) differs from this runtime's on-heap bitstring size; the bit pattern and shape agree.
- **`erts_debug:map_info/1`** (`erts_debug.rs`) — the HAMT node summary, built over a `crate::access` HAMT accessor (the crate's only term-access module): a 5-element list `[{depth,MaxDepth},{arrays,N,[]},{collisions,N,{16 bins}},{bitmaps,N,{16 bins}},{leafs,N,{18 bins}}]`, a flat map → `badarg`, a non-map → `{badmap,Term}`.
- **`erts_internal:ets_raw_first/1`** / **`erts_internal:ets_raw_next/2`** (`erts_internal.rs`) — the C declares them **plain aliases** of `ets:first/1`/`ets:next/2` (`erl_db_hash.c:4188`, `erl_db_tree.c:539`), not a storage-order walk, so they **delegate** to this crate's own `ets` family (`crate::ets::register`) and cannot drift from the `ets` verbs (equality holds for every table kind, a present/absent/non-integer key, and the terminating step).
- **The 8 `re` keys** (`../re/`, registered via `crate::re::register`) — `re:version/0`, `compile/1,2`, `run/2,3`, `internal_run/4`, `inspect/2`, `import/1` — are served by a self-contained in-crate regex engine written from scratch in safe Rust (**no third-party regex dependency, no `unsafe`**), not by the seam. The engine node owns the full contract (compiled-pattern term shape, capture semantics, option set, error behaviour, honest typed gaps): `../re/CONTEXT.md`.
- **The 6 `erl_ddll` state keys** (`ddll/{live,info,monitor}.rs`, registered via `crate::runtime::ddll::{live,info,monitor}::register`) — `loaded_drivers/0`, `try_load/3`, `try_unload/2` (the loading keys) plus `info/2`, `monitor/2`, `demonitor/1` (the introspection/monitor keys) — are real `BifFn`s over the thread-local loaded-driver registry, not the seam (see `## The erl_ddll loaded-driver registry`).

## Keys kept as typed gaps, with the blocking reason
Not every in-scope key can be closed without inventing a value; these stay the typed `unsupported_bif`, and the C reason is recorded in each registration's comment.
- **`erts_debug:size_shared/1`** (`erts_debug.rs`) — the C (`copy.c:319`) counts the words a term **shares** with others (literal-area subterms). This runtime models no shared/literal-area subterms (every term a BIF sees is built fresh on a process heap), so the oracle's non-zero results are unreachable and it could only ever answer `0` — a fabricated value for a sharing-measuring BIF. `copy_shared/2` is blocked on the same missing model.
- **`erts_internal:ets_super_user/1`** (`erts_internal.rs`) — the C (`erl_db.c:4717-4727`) takes a boolean, sets/clears `F_ETS_SUPER_USER` on the calling process and returns `ok`; the flag is consumed by the ETS access gate in `src/ets/*`. No per-process super-user concept exists for that gate to consult, so a faithful `ok` would be fabricated.
- **`erts_internal:gather_alloc_histograms/1`** / **`gather_carrier_info/1`** (`erts_internal.rs`) — the C (`erl_bif_info.c:5686-5738`) validates a 6-tuple argument then walks the allocator/carrier internals (`erts_alcu_gather_*`, the `ERTS_ALC_A_MIN..MAX` allocator-name atoms). `beam_alloc` exposes carriers but no public allocator-name list and no carrier-statistics walk, so a valid argument has no answer to give here; only `beam_rt` (which owns the allocator configuration) can serve them via the seam.

## The atomics/counters resource objects (`atomics.rs`, 13 keys, real)
The 13 `bif.tab` keys of the `atomics`/`counters` resource objects are implemented for real as plain `BifFn`s (registered last in `register`): `erts_internal:atomics_new/2`, `atomics:get/2`, `atomics:put/3`, `atomics:add/3`, `atomics:add_get/3`, `atomics:exchange/3`, `atomics:compare_exchange/4`, `atomics:info/1`, `erts_internal:counters_new/1`, `erts_internal:counters_get/2`, `erts_internal:counters_add/3`, `erts_internal:counters_put/3`, `erts_internal:counters_info/1`.

- **Representation.** The handle is an on-heap internal `Ref` thing whose id is drawn from `RESOURCE_ID_BASE = 1 << 52`, disjoint from every other reference id space in the crate (compiled patterns `1 << 32`, ETS continuations `1 << 40`, reverse continuations `1 << 41`, compiled specs `1 << 48`). The cells live in a module-local process-global registry — `static OnceLock<Mutex<HashMap<u64, Resource>>>` — exactly like the compiled-pattern (`src/binary.rs`) and ETS continuation/spec registries. A `Resource` is either `Atomics { signed, values: Vec<u64> }` or `Counters { values: Vec<i64> }`.
- **Semantics.** An `atomics` cell is a raw `u64`; `Opts` bit 0 (`OPT_SIGNED`) selects whether it is read/written as `i64` or `u64`, so one variant serves both. 64-bit arithmetic wraps (`wrapping_add`). `atomics_new/2` rejects a `0` element count (`badarg`) and an overflowing `cnt * 8` (`system_limit`), and reserves fallibly so an unservable size is `system_limit`, never an abort; `counters_new/1` rejects `0` (`badarg`) and a count above `COUNTERS_MAX_SIZE = (1 << 32) - 1` (`system_limit`).
- **Return conventions.** `get/2` the current value (rendered for signedness); `put/3`/`add/3` `ok`; `add_get/3` the **new** value; `exchange/3` the **previous** value; `compare_exchange/4` `ok` when the current cell equals `Expected` (as raw bits, storing `Desired`), otherwise the **actual** current value with nothing written. `counters_get/2` the signed value; `counters_add/3`/`counters_put/3` `ok` (`counters_put/3` requires a value that fits `i64`; `counters_add/3` accepts any `i64`- or `u64`-fitting increment as a wrapping add).
- **`info`.** `atomics:info/1` returns the flat map `#{max, memory, min, size}` in the oracle's canonical key order `max, memory, min, size`, where `max`/`min` are the signedness bounds (`i64::MAX`/`i64::MIN`, or `u64::MAX`/`0`) and `memory = 32 + 8 + 8 * N` (`erts_magic_ref2bin(ref)->orig_size`; exact for every `N`, no scheduler term). `erts_internal:counters_info/1` returns `#{memory, size}` in key order `memory, size`, where `memory = 32 + ATOMICS_PER_COUNTER * ceil(N / ATOMICS_PER_CACHE_LINE) * ERTS_CACHE_LINE_SIZE` with cache line 64. Here `ATOMICS_PER_COUNTER = available_parallelism() + 1` **models** the C's `erts_no_schedulers + 1` (`erl_bif_counters.c:50`): the real dependency is the emulator's normal-scheduler count, which a `BifFn` has no seam to read (`BifContext` carries none, and this crate may not depend on `beam_rt`, which owns `RuntimeConfig::emulator.schedulers`), so a `+S N` oracle — or a host whose `available_parallelism()` differs from the oracle's processor count — reports `N + 1` where this reports the host's parallelism + 1. The figure is an *approximation* by the oracle's own contract (`counters:info/1`: "Approximate memory consumption for the array in bytes"), never a fabricated exact value; verified on a 16-processor host: `N = 1..8 → 1120`, `9..16 → 2208`, `17..24 → 3296`, `64 → 8736`, `1000 → 136032`, and `erl +S 1` ⇒ `160`, `+S 2` ⇒ `224`, `+S 4` ⇒ `352`, `+S 8` ⇒ `608`.
- **Argument classes** reproduce C's `term_to_UWord` = `term_to_Uint` (`big.c:3505-3538`) on this 64-bit target: a **one-limb** non-negative bignum is a legal `Arity`/`Index`/`Opts` (a wider one is the C's `system_limit` at the arity/`Opts` positions), a negative bignum is `badarg`, and the index path collapses *every* conversion failure to `badarg` (C's `get_ref_ix` `&&` chain). Oracle-verified: `erts_internal:atomics_new(3, 1 bsl 59)` builds an unsigned array, `atomics_new(3, 2 bsl 63)`/`counters_new(1 bsl 59)` ⇒ `system_limit`, `-(1 bsl 59)` ⇒ `badarg`, `atomics:get(R, 1 bsl 63)` ⇒ `badarg`.
- **Scope.** Only the 13 `bif.tab` keys are registered here; the stdlib `atomics:new/2` and `counters:new/2` wrappers are pure Erlang (they call `erts_internal:atomics_new/2`/`counters_new/1`).
- **Known Milestone-1 caveat (leak).** Registry entries are **never reclaimed** — there is no off-heap finalizer for a resource object yet, so a handle that goes out of scope leaks its cells. This is the same bounded M1 leak as the `binary.rs` compiled-pattern and `ets` continuation/compiled-spec registries (crate `CONTEXT.md`).

## Handoff to `beam_abi` — `erl_ddll` and the driver loader
The driver loader is **not** the NIF loader. `beam_abi` exposes a real `dlopen`-based driver loader (`crates/beam_abi/src/driver/loader.rs`, `load(path, name) -> DriverLibrary`: validates the `ErlDrvEntry`, runs `start`, and on `Drop` runs `finish` + `dlclose`) that serves `erl_ddll`'s loading surface **inside this node** over the thread-local registry (`ddll/live.rs` + `ddll/registry.rs` — see `## The erl_ddll loaded-driver registry`).
- **Implemented for real** here: `erl_ddll:format_error_int/1` (the pure error-atom/code → message table in `src/runtime/ddll.rs`) and the 6 state keys `loaded_drivers/0`, `try_load/3`, `try_unload/2` (`src/runtime/ddll/live.rs`, over `dlopen`-backed `beam_abi::driver::loader`) + `info/2` (`src/runtime/ddll/info.rs`), `monitor/2`, `demonitor/1` (`src/runtime/ddll/monitor.rs`) — so **every** `erl_ddll` key is real and the family has **zero** `RuntimeHooks` seam keys.
- **Handoff — `beam_rt`'s native floor shadows the four list/load/unload/report keys.** `beam_rt/src/native/ddll.rs` intercepts `loaded_drivers/0`, `try_load/3`, `try_unload/2` and `info/2` **before** this crate's registry, answering from its own `crate::port::driver` name-keyed list (the one `open_port({spawn_driver, Name})` resolves a name against); on the runtime `erl_ddll:loaded_drivers()` is therefore `{ok,[]}` on a fresh VM, and the floor models no statically linked built-in, so up there `try_unload("tcp_inet",[])` is `{error,not_loaded}` and `info("tcp_inet",linked_in_driver)` is `badarg` where this node (and the oracle) answer `{error,linked_in_driver}` / `true`.
- **Handoff — the faithful shared registry is `beam_rt`'s port driver registry.** `beam_rt` (`crates/beam_rt/src/port/driver.rs`) keeps its own `thread_local` driver-entry table that backs `open_port({spawn_driver, Name})`. The registry this node owns is **separate**, so a driver `try_load`ed through `erl_ddll` here is **invisible** to that driver registry (and vice-versa): `open_port({spawn_driver, Name})` after a successful `erl_ddll:try_load/3` will not find it. Closing that means the two registries must become one (a `beam_rt`-owned table consulted by both) — a `beam_rt`-side change outside this node.

## The `erl_ddll` error table (`ddll.rs`, 1 key, real)
`erl_ddll:format_error_int/1` is the one self-contained `erl_ddll` key: a pure error-description → charlist translation, registered as a plain `BifFn` (not a `runtime_bif!` seam). Ground truth `erl_bif_ddll.c:813/1201/1709/1722` + `erl_unix_sys_ddll.c:286`.
- **A bare atom** resolves through the C's two sources in order: the Erlang-interface-only `switch` (9 atoms — `inconsistent`, `linked_in_driver`, `permanent`, `not_loaded`, `not_loaded_by_this_process`, `not_pending`, `already_loaded`, `pending_reload`, `pending_process`) and then the `errcode_tab` (9 atoms — `no_error`, `no_driver_init`, `driver_init_failed`, `bad_driver_name`, `driver_name_to_long`, `driver_incorrect_version`, `no_ddll_available`, `unspecified_error`, `symbol_not_found`); the messages are byte-exact, including the C's `"permanent an cannot"` / `"name to long"` typos. Any other atom is `badarg`.
- **A `{open_error, Code}`** (2-tuple, `Code` a **small** integer — a float, a bignum, a non-`open_error` tag or any other arity is `badarg`) maps through the fixed code table `0, -1..=-8`, then the UNIX `erts_sys_ddll_error` rule with an empty dynamic errcode table: `Code > -10` → `"Unspecified error"`, else `"Unknown dlload error"`. The C stores the code in a 32-bit `int`, so a small integer wider than 32 bits **truncates** first — observable and reproduced (`{open_error, 1 bsl 58}` → `"No error"`, `{open_error, 4294967295}` → `"No driver init in dynamic library"`).
- **Anything else** (a plain integer, a list, a binary, a `{open_error, NonSmallInt}`) is `badarg`.

## The `erl_ddll` loaded-driver registry (`ddll/registry.rs` + `ddll/{live,info,monitor}.rs`, 6 keys, real)
`loaded_drivers/0`, `try_load/3`, `try_unload/2` (`ddll/live.rs`), `info/2` (`ddll/info.rs`) and `monitor/2`/`demonitor/1` (`ddll/monitor.rs`) are real `BifFn`s (registered by the matching `register` and listed in its `REAL_BIFS`), not seam keys. They own a process-global **loaded-driver registry** over `beam_abi`'s `dlopen`-backed driver loader; the three statically linked built-ins' namespace is pinned crate-side and live-oracle in `../tests/erl_ddll.rs`.
- **The statically linked built-ins are modelled** as a pure constant, `registry::STATIC_DRIVERS` (`tcp_inet`, `udp_inet`, `ram_file_drv`) — the oracle's `driver_list` entries with `handle == NULL` (`erl_bif_ddll.c:282,545,728,743,752,775`). They are **not** registry entries (an entry owns a `DriverLibrary`); `is_static`/`static_names` are consulted by **all four** namespacing keys, so `try_load`/`try_unload` of one answers `{error,linked_in_driver}`, `info/2` of one takes the `handle == NULL` item branch, and `loaded_drivers/0` lists the three first.
- **The registry is `thread_local!`** (`static LOADED_DRIVERS: RefCell<Vec<(String, Loaded)>>`, insertion-ordered). `beam_abi::driver::DriverLibrary` holds raw pointers and is `!Send`, and this crate is `#![deny(unsafe_code)]`, so a `static OnceLock<Mutex<…>>` would require an `unsafe impl Send` — the exact pattern `beam_rt/src/port/driver.rs` uses for its own driver table. **Per-thread visibility** is the limit: a driver `try_load`ed on one thread is invisible to another. Every `beam_rt` BIF dispatch happens on one thread, so this is not observable there; a multi-threaded host would need the table to live in `beam_rt` (see the handoff above).
- **`try_load(Path, Name, Options)`** — a **name** is an atom or any `erts_iolist_size`/`erts_iolist_to_buf` shape (a byte-aligned binary, or a byte/nested-list io list — the C's `pick_list_or_atom`, `erl_bif_ddll.c:1789`); a **path** is a char-code list (nested, `erts_native_filename_need`'s walk), a byte-aligned binary or `[]`, and an **atom path** is `badarg` (the C's `erts_convert_filename_to_encoding` with `allow_atom = 0`, `allow_empty = 1`). The object is `<Path>/<Name>.so` (`beam_abi`'s loader appends `.so`). `Options` is a proper list of **2-tuples** — `{driver_options, [kill_ports]}` (`kill_ports` only, `ERL_DE_FL_KILL_PORTS`), `{monitor, pending_driver | pending}` and `{reload, pending_driver | pending}`; a bare `kill_ports` here is `badarg`, unlike `try_unload`'s list (`:198-249`). A static name answers `{error,linked_in_driver}`; a name already in the registry answers `{ok,already_loaded}` (raising its outstanding-load count, so a later `try_unload` is `pending_process`) without a second `dlopen`; a fresh successful load answers `{ok,loaded}`; a load failure answers `{error,ReasonTerm}` (see the mapping below). Atoms route through `ctx.intern_atom`, so a call works with **no** `AtomInterner` installed.
- **`try_unload(Name, Options)`** — options are a proper list whose elements are the bare flag `kill_ports` or `{monitor, pending_driver | pending}` (`:507-533`). A static name answers `{error,linked_in_driver}`; a name not in the registry answers `{error,not_loaded}`. A registered name drops one outstanding load and answers the C's **pending** status: `{ok,pending_process}` while another load remains, else `{ok,pending_driver}` — the 3-tuple `{ok,Status,Ref}` when `{monitor,_}` was given (`:583-620`); dropping the last load removes the entry and drops its `DriverLibrary` (the entry's `finish` then `dlclose`, matching the C's `do_unload_driver_entry` order).
- **`loaded_drivers()`** — `{ok,[Name,…]}` with every `Name` a **charlist**: the three statically linked built-ins (`tcp_inet`, `udp_inet`, `ram_file_drv`) first, then the `dlopen`ed drivers in load order.
- **The load-error mapping** (the objective's approximation of the C's `build_load_error_hp`, `erl_bif_ddll.c:1770`). `beam_abi::DriverLoadError` → the reason term: `Unspecified(_)` (a failed `dlopen`) → the 2-tuple `{open_error,-10}`; `NoDriverInit` → `no_driver_init`; `DriverInitFailed` → `driver_init_failed`; `BadDriverName` → `bad_driver_name`; `DriverIncorrectVersion` → `driver_incorrect_version`; `SymbolNotFound` → `symbol_not_found`. The C stores `-10 - <a growing index into a table of the `dlerror` string>`; `-10` is the first/common case, so a *specific* `dlopen` failure that would be `-11`… here reports `-10`. Nothing is fabricated: the failing case is always a real `{error,_}`.
- **Honest remaining gaps** (all documented in the submodules' rustdoc): (1) the C's pending-**reload** state machine is absent — `{reload,_}` on a driver this registry already holds answers the typed `unsupported_bif` gap, and `{reload,_}` on a non-existing driver is `{error,not_loaded}` (`:378-381`); (2) `not_loaded_by_this_process` is not enforced — the loading `ProcessId` is recorded in `Loaded` but a `try_unload` from another process is not refused; (3) the `already_loaded` arm's path/flags `inconsistent` check is not reproduced; (4) unload is **immediate** — the entry is removed at once and its `DriverLibrary` drops synchronously rather than through the C's scheduler-completed pending state machine; (5) a non-UTF-8 charlist path is `badarg` where the C would pass raw bytes to `dlopen`.
- **`info/2`** (`ddll/info.rs`) resolves the name and renders one item. For the three **statically linked built-ins** (`tcp_inet`/`udp_inet`/`ram_file_drv` — the C's `handle == NULL` drivers) the matrix is `linked_in_driver` → `true`, `permanent` → `false`, and `port_count`/`driver_options`/`processes`/`awaiting_load`/`awaiting_unload` → the **atom** `linked_in_driver` (`erl_bif_ddll.c:728,743,752,775`). For a driver in the registry: `linked_in_driver`/`permanent` → the atom `false`, `port_count` → `0`, `driver_options` → `[kill_ports]` iff loaded with that flag else `[]`, `processes` → `[{LoaderPid, Loads}]` (the loading process with its outstanding-load count — `1` after a single `try_load`, growing on each repeat), `awaiting_load`/`awaiting_unload` → `[]`. An unknown driver name **or** an unknown item atom → plain `badarg`.
- **`monitor/2`/`demonitor/1`** (`ddll/monitor.rs`) are a **state-only** pair: `monitor(driver, {Name, loaded|unloaded|unloaded_only})` mints a fresh internal `#Ref<…>` (id base `MONITOR_ID_BASE = 1 << 53`, disjoint from every other reference id space) and records `(ref_id, Name, item, ProcessId)` in a small registry; `demonitor/1` answers the atom `true` for any reference (and removes a recorded entry) and `badarg` for a non-reference. **Documented divergences:** the monitor's *notification* leg is not delivered (no notification is ever sent to the monitoring process), and the oracle's additional *state-dependent* `badarg` for `monitor(driver,{Name,loaded})` when the caller already uses that loaded name is not modelled — a ref is returned instead.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only; a missing/incomplete seam is the typed `unsupported_bif` capability gap, never a fabricated value and never `undef`.
- `#![deny(unsafe_code)]` at the crate root; nothing here needs `unsafe`.
- One `runtime_bif!` invocation per `(module, function, arity)` seam key; the seam is total, so a family module never branches on whether a hook is installed beyond forwarding. A handful of keys are the exception — they register a real `BifFn` (see `## Keys served for real inside the seam families`), as do `src/runtime/atomics.rs` (the resource objects) and `src/runtime/ddll.rs` (the error table + the `ddll/{registry,live,info,monitor}.rs` driver registry and all six state keys).
- The hook contract is fixed by `crate::context`: `RuntimeHooks::call(heap, atoms, module, function, args)`; `MemoryHook::memory() -> Vec<(&'static str, u64)>`.
