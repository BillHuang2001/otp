# `beam_bifs::runtime` — the runtime-coupled BIF families (`src/runtime/`, the `runtime_bif!` macro)

## Intent
Every registered BIF whose implementation needs the *running* runtime (Stage 5, Part I §A.7): process control, timers, code loading, system/nodes introspection, the ETS C interior, the `erts_debug`/`erl_debugger` tools, the `re` engine, the `erl_ddll` loader and the distribution machinery. Most such BIFs bridge through the single `RuntimeHooks` seam (`erlang:memory/0,1` through `MemoryHook`); with no hook installed a call answers the typed `unsupported_bif` capability gap — never `undef`, never a fabricated value.
The four seam families (`erlang` 77, `erts_internal` 56, `erts_debug` 18, `other` 44 — **195** family keys) forward to the single `RuntimeHooks` seam **except the 6 keys that now have real implementations** (`erlang:is_builtin/3`, `erlang:term_to_iovec/1,2`, `erts_debug:unaligned_bitstring/2`, `erts_internal:ets_raw_first/1`, `erts_internal:ets_raw_next/2`), leaving **189** seam-forwarding keys. `erlang:memory/0,1` read `MemoryHook`; the **13** `atomics`/`counters` resource-object keys and the self-contained `erl_ddll:format_error_int/1` are real too (`src/runtime/atomics.rs`, `src/runtime/ddll.rs`).
Ground truth (read-only): the corresponding C in `../../../erts/emulator/beam/` (`erl_bif_*.c`, `bif.c`, `erl_time_sup.c`, `erl_db_*.c`, `erl_bif_atomics.c`, `erl_bif_counters.c`), plus `string:misc`/`global` semantics for the tools' surfaces.

## API Surface
Keys by file:
- `src/runtime/mod.rs`: the module wiring, the `runtime_bif!` macro and the `register` order (`memory`, `erlang`, `erts_internal`, `erts_debug`, `other`, then `atomics` **last** so the real resource-object registrations win the last-registration-wins race).
- `src/runtime/memory.rs` (2): `erlang:memory/0,1` — the one family implemented against a real seam: `memory/0` renders the hook's `Vec<(&'static str, u64)>` as `{Key, Value}` in the hook's (oracle) key order — `total, processes, processes_used, system, atom, atom_used, binary, code, ets`; `memory/1` gives a plain integer for a single atom key, a `{K,V}` list in **requested** order for an atom list, and `badarg` for an unknown key or a malformed argument.
- `src/runtime/erlang.rs` (77): process control, timers, code loading, system/nodes introspection.
- `src/runtime/erts_internal.rs` (56): port/process-control/code-loading internals, the trace sessions, the distribution internals, `term_to_string`.
- `src/runtime/erts_debug.rs` (18): `interpreter_size`/`disassemble`/`lcnt_*`/`set_internal_state`/….
- `src/runtime/other.rs` (44): `erl_debugger` 13, `re` 8, `erl_ddll` 6, `code` 7 coverage, `ets` 2 (`internal_request_all/0`, `slot/2`), `erts_trace_cleaner` 2, `erts_literal_area_collector` 2, `prim_file`/`os`/`net_kernel`/`error_logger` 1 each.
- `src/runtime/atomics.rs` (13, **real implementations**, not seam-backed): the `atomics`/`counters` resource objects — see `## The atomics/counters resource objects`.
- `src/runtime/ddll.rs` (1, **real implementation**, not seam-backed): `erl_ddll:format_error_int/1` — see `## The erl_ddll error table`.
- `runtime_bif!(reg, "module", function, arity)` defines a block-scoped `fn` forwarding to `BifContext::call_runtime_bif(module, function, args)`, so one `register` body holds any number of keys (one source line per BIF); no `BifFn` per key in a table.
- **A seam-backed key answers the typed `unsupported_bif` unless a hook serves it** — no key is special-cased to a constant return, no fabricated value, no `undef`. `RuntimeHooks::call` is a single dispatcher: a partial adopter matches the keys it implements and returns `unsupported_bif` for the rest.
- **How many of the seam keys the live provider serves: 32** — the distinct keys its match arms bind (27 arms; three of them bind 3/2/3 keys through `|`) in `beam_rt`'s `RuntimeHooksBridge::call` (`crates/beam_rt/src/context/runtime_hooks.rs`). `beam_rt` installs that bridge for the **whole** `RUNTIME_HOOKS_BIFS` roster (`RuntimeContext::uses_runtime_hooks` *is* `beam_bifs::needs_runtime_hooks`), so every unserved seam key reaches its fallback arm and answers the same typed gap. The 32 served keys are (all members of `RUNTIME_HOOKS_BIFS`):`erlang` `start_timer/3,4`, `send_after/4`, `cancel_timer/2`, `function_exported/3`, `link/1`, `unlink/1`, `dt_spread_tag/1`, `dt_restore_tag/1`, `statistics/1`, the dynamic-tracing tag family `dt_get_tag/0`, `dt_get_tag_data/0`, `dt_put_tag/1`, `dt_append_vm_tag_data/1`, `dt_prepend_vm_tag_data/1`, `system_profile/0`, `check_old_code/1`, `finish_loading/1`, the three on-load hooks `call_on_load_function/1`, `has_prepared_code_on_load/1`, `finish_after_on_load/2` (21 `erlang` keys); `os:set_signal/2`; `net_kernel:dflag_unicode_io/1`; `erts_internal` `is_system_process/1`, `is_process_executing_dirty/1`, `erase_persistent_terms/0`; `erts_literal_area_collector:release_area_switch/0`; `erts_trace_cleaner:check/0`; `error_logger:warning_map/0`; `code` `coverage_support/0`, `get_coverage_mode/0`, `set_coverage_mode/1`. **Re-derive this figure by counting the match arms** (`awk`/grep the `RuntimeHooks::call` body) rather than trusting the number here — `beam_rt` adopts further keys over time, and a stale count is exactly the drift this bullet exists to prevent. (`beam_rt` also installs the `MemoryHook`, `crates/beam_rt/src/context/memory_hook.rs`, so the 2 `MemoryHook` keys `erlang:memory/0,1` are served — outside the seam families.) Registering the roster can only turn an `undef` into the honest `unsupported_bif`, never shadow a working result — `beam_rt`'s native floor is dispatched *before* the registry.

- **36 roster keys are registered but UNREACHABLE** — `beam_rt`'s native floor (`crates/beam_rt/src/native.rs::try_native`; `FLOOR_MODULES = [application, code, erlang, erts_internal, init, io, os, prim_file]`, no `ets`) is consulted **before** the registry and serves 25 `erlang` roster keys (`halt/2`, `make_ref/0`, `send_after/3`, `cancel_timer/1`, `spawn/3`, `spawn_link/3`, `spawn_opt/4`, `monitor/2,3`, `demonitor/1,2`, `exit/2,3`, `pre_loaded/0`, `module_loaded/1`, `nodes/0,1`, the four `seq_trace*`, `system_flag/2`, `system_info/1`, `trace_info/2`, `trace_delivered/1`) plus 11 `erts_internal` roster keys (`get_dflags/0`, `beamfile_chunk/2`, `beamfile_module_md5/1`, `get_creation/0`, `no_aux_work_threads/0`, `processes_next/1`, `term_to_string/2`, `group_leader/2,3`, `trace/3`, `trace_pattern/3`). Their `RuntimeHooks` registration never answers (the floor wins first); this is correct and never a fabricated value. No `ets:*` key is floor-shadowed.

## Keys served for real inside the seam families (6)
Six `bif.tab` keys that would otherwise forward to `RuntimeHooks` are implemented here as real `BifFn`s, each listed in its family's `REAL_BIFS` (a `pub(crate) const` asserted by that family's `register` and self-tested). Each is pure or self-contained — none needs Stage-5 state a BIF cannot reach.
- **`erlang:term_to_iovec/1,2`** (`erlang.rs`) — `term_to_binary`'s image as an iovec, over `beam_codec`. Oracle-verified quirks: the return is a **bare binary** when a non-zero compression level is selected (the C's `erts_term_to_binary_int` forces `iovec=0` when `level != 0`) and a **1-element list** at level 0; `[iovec]`/`[{fragment,1}]`/`[garbage]`/`[{compressed,10}]`/`[{minor_version,3}]` are `badarg`. Documented deviation: the oracle splits a large refc binary's payload into separate iovec elements (`term_to_iovec(binary:copy(<<1>>,65))` → byte sizes `[6,65]`); this runtime emits one contiguous image (same bytes, fewer segments).
- **`erlang:is_builtin/3`** (`erlang.rs`) — the C's `erts_is_builtin` (`beam_common.c:2359-2385`): **`bif.tab`-declaration membership ∪ {`erlang:apply/2,3`, `erlang:yield/0`}** (the latter hardcoded as "implemented as instructions as opposed to SNIFs"), **not** registry membership — the 82 stdlib fast paths the oracle reports `false` (`lists:map/2`, `io_lib:format/2`, `erlang:memory/0,1`, …) would be wrong values under a registry rule. The arity is truncated to 32 bits (the C's `int arity`). Lives on a `OnceLock`-cached sorted declaration set; an unreadable table → typed `unsupported_bif`.
- **`erts_debug:unaligned_bitstring/2`** (`erts_debug.rs`) — a pure bitstring transform over `crate::access`. Oracle-verified: `(<<>>, 1)` → `<<>>` (an empty source is not an error); only offsets `1..=7` are accepted (`0`/`8`/`9`, a non-small offset, a non-bitstring source ⇒ `badarg`). Documented deviation: the C returns a refc `ErlSubBits` whose bit pointer sits below the byte start, so `binary:referenced_byte_size/1` of the result (65) differs from this runtime's on-heap bitstring size; the bit pattern and shape agree.
- **`erts_internal:ets_raw_first/1`** / **`erts_internal:ets_raw_next/2`** (`erts_internal.rs`) — the C declares them **plain aliases** of `ets:first/1`/`ets:next/2` (`erl_db_hash.c:4188`, `erl_db_tree.c:539`), not a storage-order walk, so they **delegate** to this crate's own `ets` family (`crate::ets::register`) and cannot drift from the `ets` verbs (equality holds for every table kind, a present/absent/non-integer key, and the terminating step).

## Keys kept as typed gaps, with the blocking reason (5 in scope)
Not every in-scope key can be closed without inventing a value; these stay the typed `unsupported_bif`, and the C reason is recorded in each registration's comment.
- **`erts_debug:size_shared/1`** (`erts_debug.rs`) — the C (`copy.c:319`) counts the words a term **shares** with others (literal-area subterms). This runtime models no shared/literal-area subterms (every term a BIF sees is built fresh on a process heap), so the oracle's non-zero results are unreachable and it could only ever answer `0` — a fabricated value for a sharing-measuring BIF. `copy_shared/2` is blocked on the same missing model.
- **`erts_debug:map_info/1`** (`erts_debug.rs`) — summarises a HAMT map's node interior; walking that interior is confined to `crate::access` (the crate's only term-access `#[allow(unsafe_code)]` module) and no such accessor exists yet, so there is no faithful summary to build here. Oracle contract once unblocked: a 5-element list `[{depth,MaxDepth},{arrays,N,[]},{collisions,N,{16 bins}},{bitmaps,N,{16 bins}},{leafs,N,{18 bins}}]`, flat map → `badarg`, non-map → `{badmap,Term}`.
- **`erts_internal:ets_super_user/1`** (`erts_internal.rs`) — the C (`erl_db.c:4717-4727`) takes a boolean, sets/clears `F_ETS_SUPER_USER` on the calling process and returns `ok`; the flag is consumed by the ETS access gate in `src/ets/*`. No per-process super-user concept exists for that gate to consult, so a faithful `ok` would be fabricated.
- **`erts_internal:gather_alloc_histograms/1`** / **`gather_carrier_info/1`** (`erts_internal.rs`) — the C (`erl_bif_info.c:5686-5738`) validates a 6-tuple argument then walks the allocator/carrier internals (`erts_alcu_gather_*`, the `ERTS_ALC_A_MIN..MAX` allocator-name atoms). `beam_alloc` exposes carriers but no public allocator-name list and no carrier-statistics walk, so a valid argument has no answer to give here; only `beam_rt` (which owns the allocator configuration) can serve them via the seam.

## The atomics/counters resource objects (`atomics.rs`, 13 keys, real)
The 13 `bif.tab` keys of the `atomics`/`counters` resource objects are implemented for real as plain `BifFn`s (registered last in `register`): `erts_internal:atomics_new/2`, `atomics:get/2`, `atomics:put/3`, `atomics:add/3`, `atomics:add_get/3`, `atomics:exchange/3`, `atomics:compare_exchange/4`, `atomics:info/1`, `erts_internal:counters_new/1`, `erts_internal:counters_get/2`, `erts_internal:counters_add/3`, `erts_internal:counters_put/3`, `erts_internal:counters_info/1`.

- **Representation.** The handle is an on-heap internal `Ref` thing whose id is drawn from `RESOURCE_ID_BASE = 1 << 52`, disjoint from every other reference id space in the crate (compiled patterns `1 << 32`, ETS continuations `1 << 40`, reverse continuations `1 << 41`, compiled specs `1 << 48`). The cells live in a module-local process-global registry — `static OnceLock<Mutex<HashMap<u64, Resource>>>` — exactly like the compiled-pattern (`src/binary.rs`) and ETS continuation/spec registries. A `Resource` is either `Atomics { signed, values: Vec<u64> }` or `Counters { values: Vec<i64> }`.
- **Semantics.** An `atomics` cell is a raw `u64`; `Opts` bit 0 (`OPT_SIGNED`) selects whether it is read/written as `i64` or `u64`, so one variant serves both. 64-bit arithmetic wraps (`wrapping_add`). `atomics_new/2` rejects a `0` element count (`badarg`) and an overflowing `cnt * 8` (`system_limit`), and reserves fallibly so an unservable size is `system_limit`, never an abort; `counters_new/1` rejects `0` (`badarg`) and a count above `COUNTERS_MAX_SIZE = (1 << 32) - 1` (`system_limit`).
- **Return conventions.** `get/2` the current value (rendered for signedness); `put/3`/`add/3` `ok`; `add_get/3` the **new** value; `exchange/3` the **previous** value; `compare_exchange/4` `ok` when the current cell equals `Expected` (as raw bits, storing `Desired`), otherwise the **actual** current value with nothing written. `counters_get/2` the signed value; `counters_add/3`/`counters_put/3` `ok` (`counters_put/3` requires a value that fits `i64`; `counters_add/3` accepts any `i64`- or `u64`-fitting increment as a wrapping add).
- **`info`.** `atomics:info/1` returns the flat map `#{max, memory, min, size}` in the oracle's canonical key order `max, memory, min, size`, where `max`/`min` are the signedness bounds (`i64::MAX`/`i64::MIN`, or `u64::MAX`/`0`) and `memory = 32 + 8 + 8 * N` (`erts_magic_ref2bin(ref)->orig_size`; exact for every `N`, no scheduler term). `erts_internal:counters_info/1` returns `#{memory, size}` in key order `memory, size`, where `memory = 32 + ATOMICS_PER_COUNTER * ceil(N / ATOMICS_PER_CACHE_LINE) * ERTS_CACHE_LINE_SIZE` with cache line 64. Here `ATOMICS_PER_COUNTER = available_parallelism() + 1` **models** the C's `erts_no_schedulers + 1` (`erl_bif_counters.c:50`): the real dependency is the emulator's normal-scheduler count, which a `BifFn` has no seam to read (`BifContext` carries none, and this crate may not depend on `beam_rt`, which owns `RuntimeConfig::emulator.schedulers`), so a `+S N` oracle — or a host whose `available_parallelism()` differs from the oracle's processor count — reports `N + 1` where this reports the host's parallelism + 1. The figure is an *approximation* by the oracle's own contract (`counters:info/1`: "Approximate memory consumption for the array in bytes"), never a fabricated exact value; verified on a 16-processor host: `N = 1..8 → 1120`, `9..16 → 2208`, `17..24 → 3296`, `64 → 8736`, `1000 → 136032`, and `erl +S 1` ⇒ `160`, `+S 2` ⇒ `224`, `+S 4` ⇒ `352`, `+S 8` ⇒ `608`.
- **Argument classes** reproduce C's `term_to_UWord` = `term_to_Uint` (`big.c:3505-3538`) on this 64-bit target: a **one-limb** non-negative bignum is a legal `Arity`/`Index`/`Opts` (a wider one is the C's `system_limit` at the arity/`Opts` positions), a negative bignum is `badarg`, and the index path collapses *every* conversion failure to `badarg` (C's `get_ref_ix` `&&` chain). Oracle-verified: `erts_internal:atomics_new(3, 1 bsl 59)` builds an unsigned array, `atomics_new(3, 2 bsl 63)`/`counters_new(1 bsl 59)` ⇒ `system_limit`, `-(1 bsl 59)` ⇒ `badarg`, `atomics:get(R, 1 bsl 63)` ⇒ `badarg`.
- **Scope.** Only the 13 `bif.tab` keys are registered here; the stdlib `atomics:new/2` and `counters:new/2` wrappers are pure Erlang (they call `erts_internal:atomics_new/2`/`counters_new/1`).
- **Known Milestone-1 caveat (leak).** Registry entries are **never reclaimed** — there is no off-heap finalizer for a resource object yet, so a handle that goes out of scope leaks its cells. This is the same bounded M1 leak as the `binary.rs` compiled-pattern and `ets` continuation/compiled-spec registries (crate `CONTEXT.md`).

## Handoff to `beam_abi` — `erl_ddll` and the driver loader
The driver loader is **not** the NIF loader. `beam_abi` exposes a real `dlopen`-based driver loader (`crates/beam_abi/src/driver/loader.rs`, `load(path, name) -> DriverLibrary`: validates the `ErlDrvEntry`, runs `start`, and on `Drop` runs `finish` + `dlclose`). But the **live driver registry** and `open_port({spawn_driver, Name})` live in `beam_rt` (`crates/beam_rt/src/port/driver.rs`), and `beam_io::abi::DriverTable` is not on that path. So the seven `erl_ddll` keys split:
- **Implemented for real** (no loader registry): `erl_ddll:format_error_int/1` — a pure error-atom/code → message table in `src/runtime/ddll.rs` (see below).
- **Needs the live registry** (owned by `beam_rt`, so typed `unsupported_bif` from inside `beam_bifs` alone): `loaded_drivers/0`, `try_load/3`, `try_unload/2`, `monitor/2`, `demonitor/1`, `info/2`. (On the oracle `loaded_drivers()` → `{ok,["tcp_inet","udp_inet","ram_file_drv"]}`.)

## The `erl_ddll` error table (`ddll.rs`, 1 key, real)
`erl_ddll:format_error_int/1` is the one self-contained `erl_ddll` key: a pure error-description → charlist translation, registered as a plain `BifFn` (not a `runtime_bif!` seam). Ground truth `erl_bif_ddll.c:813/1201/1709/1722` + `erl_unix_sys_ddll.c:286`.
- **A bare atom** resolves through the C's two sources in order: the Erlang-interface-only `switch` (9 atoms — `inconsistent`, `linked_in_driver`, `permanent`, `not_loaded`, `not_loaded_by_this_process`, `not_pending`, `already_loaded`, `pending_reload`, `pending_process`) and then the `errcode_tab` (9 atoms — `no_error`, `no_driver_init`, `driver_init_failed`, `bad_driver_name`, `driver_name_to_long`, `driver_incorrect_version`, `no_ddll_available`, `unspecified_error`, `symbol_not_found`); the messages are byte-exact, including the C's `"permanent an cannot"` / `"name to long"` typos. Any other atom is `badarg`.
- **A `{open_error, Code}`** (2-tuple, `Code` a **small** integer — a float, a bignum, a non-`open_error` tag or any other arity is `badarg`) maps through the fixed code table `0, -1..=-8`, then the UNIX `erts_sys_ddll_error` rule with an empty dynamic errcode table: `Code > -10` → `"Unspecified error"`, else `"Unknown dlload error"`. The C stores the code in a 32-bit `int`, so a small integer wider than 32 bits **truncates** first — observable and reproduced (`{open_error, 1 bsl 58}` → `"No error"`, `{open_error, 4294967295}` → `"No driver init in dynamic library"`).
- **Anything else** (a plain integer, a list, a binary, a `{open_error, NonSmallInt}`) is `badarg`.

## `os:set_signal/2` — current state
`os:set_signal(Signal, Disposition)` is registered in this node as a bare `runtime_bif!` **seam key** in `./other.rs` (that file's `os` 1-key slot; the key is a member of the 195-key `RUNTIME_HOOKS_BIFS` roster). This node interprets **no** argument: the body only forwards to `BifContext::call_runtime_bif("os", "set_signal", args)`, so with no `RuntimeHooks` installed *every* argument shape answers the typed `unsupported_bif` — never `badarg` (a forward does not validate), never a fabricated `ok`. Pinned by `os_set_signal_is_a_roster_seam_key_forwarder` (`./other.rs`).
- **The provider (the arm) lives in `beam_rt`, not here.** `beam_bifs` owns only the seam key + the forward. `beam_rt`'s `RuntimeHooksBridge::call` has an `("os", "set_signal", 2)` arm (`crates/beam_rt/src/context/runtime_hooks.rs`), so under the live runtime the disposition **is installed for real** and the answer is the oracle's `ok` — or `badarg` for a `Signal`/`Disposition` name outside the accepted set.
- **The host wiring is `beam_rt/src/context/signal.rs` over `beam_io::signal::SignalFacility`.** The *mechanism* — the twelve POSIX signal numbers (`Signal::ALL`), the `sigaction(2)` install, the async-signal-safe trampoline and the self-pipe — is `beam_io::signal`'s (`crates/beam_io/src/signal.rs`; `set`/`disposition`/`read_fd`/`drain`), the crate that owns the `unsafe` this crate's `#![deny(unsafe_code)]` cannot. `beam_rt` adds the *runtime* half: **one** long-lived, process-global `SignalFacility` in a `thread_local` slot (an ERTS signal disposition is process-global and outlives the calling process, so a per-call facility — dropped, restoring the prior dispositions — would be wrong) plus the `set_signal` arm's argument validation (both args must be atoms of the caller's shared table; `Signal::from_name`/`Disposition::from_name` map the accepted names). The accepted surface is exactly the twelve `Signal::ALL` names and the three `Disposition::ALL` values; `sigkill`/`sigttin`/`sigttou`/`siginfo` are `badarg`, and `sigstop` (kernel-only, `sigaction(2)` refuses every disposition for it) answers `ok` without a syscall.
- **What the host must still implement (a `beam_rt` gap, not this node's): the notification leg.** This runtime boots no `erl_signal_server` process, and the facility's `read_fd` is registered with no poller and drained from no reactor loop, so a handled signal is recorded in the facility's bitmask and never sent as the 2-tuple `{notify, SignalName}` the oracle delivers to the registered `erl_signal_server`. Disposition *installation* is complete; only *delivery* is missing.
- **The differential corpus does not exercise this key** (`tools/differential`'s `os:` coverage is `cmd/1` only), so the live `ok`/`badarg` surface above is oracle-reasoned, not gate-pinned. A `set_signal` case would have to be added on the corpus side.
- **This node's seam contract:** an uninstalled `RuntimeHooks` must keep `os:set_signal/2` the typed `unsupported_bif`; the seam key must never interpret arguments, and no `os:*` arm belongs in `beam_bifs` (the provider is `beam_rt`'s).

## `re` — why the eight keys stay gap-backed
All 8 `re:*` keys (`compile/1,2`, `import/1`, `inspect/2`, `internal_run/4`, `run/2,3`, `version/0`) stay the typed `unsupported_bif`: a faithful `re` needs PCRE2, and the workspace licensing policy (Apache-2.0/MIT only) forbids adding a third-party regex engine. (On the oracle `re:version()` → `<<"10.47 2025-10-21">>`.)

## Constraints
- Errors are `beam_common::{Result, BeamError}` only; a missing/incomplete seam is the typed `unsupported_bif` capability gap, never a fabricated value and never `undef`.
- `#![deny(unsafe_code)]` at the crate root; nothing here needs `unsafe`.
- One `runtime_bif!` invocation per `(module, function, arity)` seam key; the seam is total, so a family module never branches on whether a hook is installed beyond forwarding. A handful of keys are the exception — they register a real `BifFn` (see `## Keys served for real inside the seam families`), as do `src/runtime/atomics.rs` (the resource objects) and `src/runtime/ddll.rs` (the error table).
- The hook contract is fixed by `crate::context`: `RuntimeHooks::call(heap, atoms, module, function, args)`; `MemoryHook::memory() -> Vec<(&'static str, u64)>`.

- `../CONTEXT.md` -> the crate root (Intent/API Surface/Constraints/Test Strategy/Routing Table)
