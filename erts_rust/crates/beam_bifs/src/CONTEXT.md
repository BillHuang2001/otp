# `beam_bifs` — In-Crate Module Contracts (`src/`)

## Intent
The per-module contracts of `beam_bifs`'s `src/` modules: for each module, what it registers plus its oracle-verified traps.
The crate root is `../CONTEXT.md` — roster census + pins, the frozen `BifRegistry`/`BifContext` API surface, constraints, typed capability gaps and handoffs.
Algorithm detail lives in each module's rustdoc and, for the sub-nodes (`ets/`, `re/`, `packet/`, `runtime/`, `unicode/`), in that node's own `CONTEXT.md`.

## Module contracts
One entry per module: what it registers plus its oracle-verified traps.
### `re` (`src/re/`) — the 8 `re:*` BIFs, served for real
All 8 declared keys are real `BifFn`s (`src/runtime/other.rs` calls `crate::re::register`) over a self-contained safe-Rust engine — **no third-party regex crate**, no `unsafe`, the compiled pattern's element 5 our own versioned image, never PCRE2's `#Ref<…>`.
`{newline,crlf}` is positional (only `\r\n`), `{newline,none}` is `badarg`; gaps: `./re/CONTEXT.md`.
### `records` (native records, `records.rs`) — 8 BIFs
OTP-29 native records over the frozen `beam_term::record` interior (ground truth `erl_record.c`); `create/4`'s cached definition word is the real `beam_term::hashing::compute_record_definition_hash` (recomputed — `phash2` unaffected).
`update/4` takes a flat **or** HAMT map, accepts `'_'` as the wildcard module/name, no-ops on an empty map, requires every key to name an existing field (`=:=`) in declaration order; `get_definition/2` needs `RecordSource` ⇒ `{#{is_exported => B}, Fields}` (none ⇒ `badarg`); `is_record/2` is true for a tuple **or** a native record, while the guard `erlang:is_record/1` is true only for a native record and `is_record/3` is **false** for one (it is not a tuple); structured reasons carry their term (`{badrecord,T}`, `{badfield,{{M,N},K}}`, `{badmap,M}`).
`create/4` fixture rules (oracle-verified): a repeated field name ⇒ `badarg`, an options map without `is_exported` ⇒ `badarg` (`create/3` does not exist), a non-atom module ⇒ `{badrecord,Name}`, a non-atom field key ⇒ `{badfield,{{M,N},Key}}`; the declaration order is exactly the argument order (not sorted) and no export gate applies — `#{is_exported => true}` for a module with no `.hrl` is accepted and only changes the definition word.
### Maps (`maps.rs`) — both representations, no pair-count ceiling
Flat (≤ `MAP_SMALL_MAP_LIMIT` = 32 distinct keys) **and** HAMT above it, both `beam_term::map`, so every reader (`map_get/2`/`map_size/1`/`is_map_key/2`, the `maps:*` BIFs, the printers, `records:update/4`) and producer handles either.
The writer matches ERTS (≤32 ⇒ flat in `erts_cmp_flatmap_keys` order, else a HAMT keyed by `erts_map_hash`), duplicates last-wins; key identity is exact (`=:=`), pair order is the *stored* order, a missing key/non-map raises `{badkey,K}`/`{badmap,M}`; `maps:with/2`/`without/2` (`error_type(M)` — the MAP alone decides) give `badarg` for non-list Keys, bare `function_clause` for improper Keys.
A **no-op** `put/3`/`update/3`/`remove/2` returns the argument map **term** (`Ok(args[2])` / `Ok(args[1])`) instead of a rebuilt copy, decided by **word** equality of the value (`Eterm`'s `==`, the C's `if (*vs == value)`, never `compare::eq`); `merge/2` follows ERTS's own arms (`erl_map.c:1256-1372`) in order — two word-identical map arguments ⇒ `args[0]` (`BIF_ARG_1 == BIF_ARG_2`), empty Map1 ⇒ `args[1]`, empty Map2 ⇒ `args[0]`, and **every key of Map1 present in Map2 ⇒ `args[1]`** (`if (n == n2) return map2;`, `:1368-1372`), a **key-set** test that never looks at the values, so `merge(#{a=>1},#{a=>99})` returns Map2 while `merge(#{a=>1,b=>2},#{a=>1})` (Map2 ⊂ Map1) builds a fresh map; a non-map argument raises `{badmap, Map}` in argument order, both map-ness checks running before any early return. Observable only through `erts_debug:same/2` (word equality); `=:=` cannot see it, and the identity is lost again on `beam_rt`'s result copy (`copy_result_fresh`). Pinned by `tests/maps_identity.rs` (matrix + compiled-module oracle cross-check, every row agreeing — no documented divergence).
The fun-taking fast paths (`map/2`/`fold/3`/`filter/2`/`foreach/2`) and `to_list/1` accept a **map *or* a `maps` iterator** (`maps:iterator/1,2`'s `[Path|Map]`, a `maps:next/1` `{K,V,Iter}` look-ahead, the atom `none` — not `[]`) through the one `walk_map_or_iter` (`maps.erl:948`), a `next/1` failure being `{badmap, <original argument>}`; `maps:iterator/2`, `filtermap/2`, `update_with/3,4`, `merge_with/3` are deliberately unregistered (the real `maps.beam` serves them); the HAMT `iterator/1`/`next/1` chunking differs from the C's (identical `{K,V,Next}` sequence).
### Exact integer arithmetic (`arith.rs`), the bit operators, `lists:sum/1`
`+ - * div rem abs` and unary `-`/`+` are arbitrary-precision (an out-of-60-bit result becomes a heap bignum via the **safe** `beam_codec::term::make_big`); `div`/`rem` Knuth D; `add_terms` shared with `lists:sum/1`; `int_from_mag`/`int_from_i64`/`int_from_f64` the single promotion path for every integer-producing BIF.
`+`/`-`/`*` short-circuit two small-int operands into machine arithmetic (`small_operand` → `checked_*` → `int_from_machine`) and materialize the result only after a `MIN_SMALL..=MAX_SMALL` test, so the fast path allocates nothing and a result that leaves the range takes the `Big` promotion route (`div`/`rem`/`abs`/the unaries/the bit operators stay on the `Big` path deliberately).The bit operators are **integer-only** (`1 band 1.0` ⇒ `badarith`), two's-complement arbitrary-precision; a negative count flips `bsl`⇄`bsr` (`8 bsl -2` ⇒ `2`); `bnot(A)` = `-A-1`; cap `BIG_ARITY_MAX = (1<<16)-1` limbs = 4_194_240 bits ⇒ `system_limit` (an oversized left shift is rejected before allocation).
### `math` (24 keys) / the strict booleans (`bool.rs`)
`math` are real BIFs over `f64` (coercion exactly as C `math_call_1`; a post-call domain error or overflow ⇒ `badarith`, never a wrong float); `atanh/1` bit-exact, `erf`/`erfc` approximate.
`bool`: `not/1`/`and/2`/`or/2`/`xor/2` are strict (`true`/`false` only, else `badarg`); `andalso`/`orelse` are **not** BIFs (the compiler lowers them to jumps).
### Comparison operators (`compare.rs`) — the node-aware term order
`==`/`/=`/`=:=`/`=/=`/`<`/`>`/`=<`/`>=`/`erts_internal:cmp_term/2` all go through `cmp_arith_node`/`cmp_exact_node`: `beam_term`'s `cmp*_with_local_node` when `BifContext::local_node()` names a node **and** `access::is_mixed_identity_pair` recognises the operand pair — the only case a mixed internal/external `pid`/`port`/`ref` pair is decided field by field instead of by the plain functions' documented class ladder.
The node is resolved once per BIF call (a `Copy` `LocalNodeId`), never per element: `convert.rs`'s `min/2`/`max/2` and `lists.rs`'s `sort/1`/`usort/1`/`keysort/2`/`keyfind/3`/`keysearch/3`/`keymember/3`/`max/1`/`min/1` thread the same value; `term_conv.rs`'s `is_integer/3` keeps the plain `cmp_arith` (all three operands are validated integers) and map/table key equality stays hash-based.
Pinned on the oracle: a non-distributed node is `nonode@nohost` with `erlang:system_info(creation)` 0 (the hookless `BifContext::local_node()` fallback), a mixed pid compares serial → number → node name + creation, a port by the node alone, a ref by the node then its ids; `tests/compare_local_node.rs` pins both the node-aware and the class-ladder answer for every ordering plus a fail-loud live `erl` transcript.
### `erlang:phash/2` + `phash2/1,2` (`compare.rs` — thin adapters)
The hashes are the LCA's compatibility-pinned `beam_term::hashing::{make_hash, make_hash2}` (transcriptions of `erl_term_hashing.c`); these BIFs only build the `Range` and reduce (`phash/2` = `1 + hash % Range`, `phash2/1` = `hash & 0x07FF_FFFF`, `phash2/2` = `hash % Range`; `Range = 0` ⇒ `hash + 1` / the whole hash; a non-integer/negative/`>0xFFFF_FFFF` Range is `badarg`), and every `TermError` maps to the typed `unsupported_bif`, never a `?`-collapsed `badarg`; goldens `tests/phash.rs`.
The only refusal a well-formed term can still reach is the identity gap the LCA's fun-identity provider closes: a `FunKind::Local` (`make_fun3`) fun needs a **fun-identity provider** on `make_hash`/`make_hash2` (the C mixes `fe->module`'s atom hvalue, `fe->index`, `fe->old_uniq`, `num_free` and the env — `erl_term_hashing.c:238-265`, `:1219-1245`), which `SeamFunIdentity` supplies from the `LocalFunIdentity` seam; the typed `unsupported_bif` is answered only when no seam can attribute the closure.
An internal reference is **not** a gap: `beam_term::hashing` mixes its own `id` word (`beam_term/src/hashing/common.rs::internal_ref_hash_word`, the C's `internal_ref_numbers(term)[0]` projection, `:288-290`, `:1454-1458`), so `TermError::RefIdentityUnavailable` still exists but is **unproduced**, and the pin is the range each reduction implies plus stability across repeats and distinctness across mints — never a number, because reference numbering is per-VM.
### List operators (`lists.rs`)
`'++'/2` requires a **proper-list LEFT operand** and uses the RIGHT **verbatim with no check** (`[1,2] ++ x` ⇒ `[1,2|x]`, an intentional bug-compatibility); `'--'/2` removes from the left the first remaining occurrence of each right element by **exact `=:=`**; the 45 registered keys = 5 declared + 40 `lists.erl` fast paths.
`seq/2,3` accepts **bignum bounds and bignum steps**: the all-small call keeps machine arithmetic (`seq_loop`'s count formula), and any other call goes to `seq2_wide`/`seq3_wide`, which reproduce `lists.erl:476-489`/`:532-553` with term arithmetic — the guards as `First =< Last + 1` / `First =< Last + Incr` (exact for a bignum) and a forward `seq_walk` by `Incr`, so `seq(B,B+2)` ⇒ `[B,B+1,B+2]`, `seq(B,B-1)` ⇒ `[]`, `seq(B,B,0)` ⇒ `[B]`, while a non-integer operand keeps its class (`seq/2` `function_clause`, `seq/3` `badarg`).
Comparison order is per function, pinned to the oracle: exact (`eq`) for `member/2`/`delete/2`/`keymember/3`/`keysearch/3`/`'--'/2`; arithmetic (`cmp_arith`, node-aware through `compare::cmp_arith_node`) for `keyfind/3`/`sort/1`/`usort/1`/`keysort/2`/`max/1`/`min/1`; `sort/2`/`usort/2`/`mapfoldl/3`/`mapfoldr/3` are faithful `lists.erl` ports over `BifContext::call_fun`, so a degenerate comparator reproduces the oracle's reversal (`lists:sort(fun(_,_) -> false end, [1,2,3])` ⇒ `[3,2,1]`, strict-key ties descending) and a non-2-tuple fun result raises `{badmatch, Value}`.
### iolist / bitstring BIFs (`binary.rs`, `binconv.rs`)
The **one** Unit-8 walk lives in `./iolist.rs` (`walk`/`byte_len`/`bytes`/`bytes_and_leaves`/`part_range`/`byte_list`), so `list_to_binary/1`, `iolist_to_binary/1` and `iolist_size/1` cannot drift apart; `list_to_bitstring/1` is the Unit-1 (bit-assembling) walk and `split_binary/2` the position-based `{Before,After}` split (distinct from `binary:split/2,3`).
`binary:compile_pattern/1` mirrors `maybe_binary_match_compile`: a non-empty byte-aligned binary (or list of them) in a module-local process-global registry, the handle an on-heap `Ref` thing, 1 "word" ⇒ `{bm,Ref}`, more ⇒ `{ac,Ref}` (**no** `am` tag); any other argument (an integer, an empty list/binary, an improper list, a non-binary element) is `badarg`.
### `erlang:convert_time_unit/3` (`time.rs`) — a stdlib fast path, not a `bif.tab` entry
The oracle implements it as Erlang code (`../../erts/preloaded/src/erlang.erl:5338-5384`), so it is registered here like the sibling `erlang:memory/0,1`; it closes `timer:tc/1,2,3,4`.
Body `TU * Time div FU` with an identity arm (`FU =:= TU` and an integer `Time` ⇒ `Time` unchanged, bignum included), the C floor for a negative `Time`, and bignum ratios re-entering the **registered** `'*'/2`/`'-'/2`/`'div'/2`; `native`/`perf_counter` are 1e9, every other atom its units-per-second ratio, a positive integer unit also accepted; `erlang.erl` wraps the body in `try … catch _:_ -> error_with_info(badarg, …)`, so **every** failure (an unknown/zero/negative/non-atom-non-integer unit, a non-integer `Time`, a product past the bignum cap) is `badarg` — never a wrong number.
### `zlib` (`src/zlib/`) — the six one-shot fast paths and the 19-key NIF-level stream surface
`zlib` contributes **25** registry keys, none a `bif.tab` entry, no `unsafe`.
`zlib`'s stream interface (`open`/`deflateInit`/`inflate`/`close`, `*_init`/`*_reset`) is written over 19 **non-exported local** functions of `zlib.beam` (`zlib.erl:100-106`, `open_nif/0` … `enqueue_nif/2`), registered here as a NIF-level surface (`stream/`, detail in `./zlib/CONTEXT.md`): an on-heap internal `Ref` handle over a process-global stream table, the caller-is-the-controller prologue, a queued-input pump driving `beam_deflate`'s streaming entry points, and an ETF-image stash.
The six one-shot convenience functions (`compress/1`, `uncompress/1`, `zip/1`, `unzip/1`, `gzip/1`, `gunzip/1`) are fast paths that intercept before the Erlang wrappers run; the wrappers stay the argument-validation layer and this crate never re-implements `arg_level`/`arg_bitsz`/`arg_mem`/`arg_strategy`/`arg_flush`/`arg_eos_behavior`.
All six take iodata (a bare integer, an atom, an element outside `0..=255`, a non-byte-aligned bitstring ⇒ `badarg`), every malformed stream is the bare-atom `error:data_error` (`badarg` only for non-iodata), and every byte — one-shot and stream alike — comes from `beam_deflate`, the workspace's one zlib 1.3.2 port.
`compress/1` emits one RFC 1950 stream at `Z_DEFAULT_COMPRESSION` (`beam_deflate::compress`, i.e. `MAX_WBITS` 15, `DEF_MEM_LEVEL` 8, `Z_DEFAULT_STRATEGY`); `uncompress/1` needs ≥ 8 bytes and inflates through `beam_deflate::decompress_bounded`, bounded by the format's own 1032:1 `expansion_limit` rather than an artificial ceiling.
Three framings, one deflate body: `compress/1`/`uncompress/1` are RFC 1950 at `Z_DEFAULT_COMPRESSION` (bounded by the format's own 1032:1 `expansion_limit`), `zip/1`/`unzip/1` the raw RFC 1951 pair (`zlib.erl` opens them with `-MAX_WBITS`), `gzip/1`/`gunzip/1` RFC 1952 with the encoder's own member framing (fixed header, no MTIME, `OS` 3, LE CRC-32/ISIZE) and every member header/trailer verified in one place.
**Byte-identical to the oracle:** block splits, block types, lazy-match decisions and code lengths included, because `beam_deflate` is a faithful port of `../../erts/emulator/zlib/{deflate,trees}.c`; the raw and gzip framings carry the very same body (`zlib::one_shot::tests::the_three_framings_agree_byte_for_byte`).
Evidence: `tests/zlib_oracle.rs` (fail-loud live oracle, three encoders, both round-trip directions) and `tests/zlib_stream.rs` (the 19 stream keys driven the way `zlib.erl` drives them), plus `beam_deflate`'s `#[ignore]`d env-gated corpus sweep (`BD_CORPUS` → `BD_OUT`, 742 deterministic inputs, 0 B … 4 MiB, byte-identical in all three framings).
Contract A.9 consequence: `compile:file/2` output is byte-identical to the oracle's — the one `lib/*/src` file whose literal table goes through `zlib:compress/1` compiles in-process to the oracle's own bytes, with every chunk md5 equal; figures and the whole transcript are `./zlib/CONTEXT.md`.
The ETF `COMPRESSED` image is the oracle's byte for byte: `term_to_binary(T,[compressed])` deflates through `beam_codec::compress` → `beam_deflate` (the zlib 1.3.2 level-6 port), and the C's budget rule decides the wrapper — the `[131][80][body_len:4 BE][zlib]` form is emitted only when `stream_len <= body_len - 5` (equality compresses), a `body_len < 5` always stays plain, and level `0` never pays for itself.
The stream surface's own contract — the 19 keys, the `badarg`/`not_on_controlling_process`/`not_initialized`/`already_initialized`/`stream_error`/`data_error`/bare-`error` classes, the tagged `{continue,_}`/`{finished,_}`/`{need_dictionary,_,_}` answers and `serves_local_call` — is `./zlib/CONTEXT.md`.
### The auxiliary BIF modules

- `calendar.rs` (+ `calendar/localtime.rs`) (9): the date/time family and the `posixtime`⇄`universaltime`⇄`localtime` conversions; only the timezone/DST ops live in the crate's **second** `#[allow(unsafe_code)]` module.
- `os_bif.rs` (13): the `os` env/pid/clock BIFs, `file:native_name_encoding/0` and the pure `prim_file` name helpers.
- `fun_info.rs` (5): `fun_info/1` (**the one fast path here** — `bif.tab` declares only `/2`) is the OTP-29 ten-key walk sharing `item_value` with `/2` and dropping every `{Key,undefined}` pair, and `/2` also gains the OTP-29 `pid` item; plus `fun_info_mfa/1`, `fun_to_list/1`, `make_fun/3`; `name` IS served for a `Local`/`Imported` fun (`Item::needs_identity(kind)`: `External` never, `Imported` `Name` only, `Local` `pid`/`new_uniq`/`index`/`uniq`/`module`/`name`), `function: None` leaving `name` the typed gap; `fun_info_mfa/1` answers `{Module,Function,Arity}` in **all three** arms — `External` from the term, `Local` from the seam's module + lambda name (`unsupported_bif` only when the seam answers `Ok(None)` or carries no function), `Imported` with the module from its wire image and the C's `mfa == NULL` `[]` function when no `FunT` entry resolves — its `Arity` coming from the frozen header (`beam_term::fun::fun_arity`), so a `mk(X) -> fun(Y,Z) -> …` closure reports `2`; `fun_to_list/1` renders the **true** arity where `fun_info/2`'s `arity` and `fun_info_mfa/1` read the header's 8-bit field (oracle-verified).

- `erts_internal.rs` (10): `erts_debug:same/2` (raw `Eterm`-word identity), `erts_debug:flat_size/1`, and eight `erts_internal` helpers (incl. the real `map_hashmap_children/1`).
- `modinfo.rs`/`persistent_term.rs`: the `ModuleInfo`/`PersistentTerm` BIFs; the BIF layer owns the rendering and the argument-decided `badarg` cases (a non-atom name, `undefined` as a name, a bad item spec, an absent `get/1` key, a `put_new/2` onto a conflicting key) *before* the hook; `get_module_info/2` takes exactly nine item atoms.
- `proc_reg.rs` — the **twelve** `ProcessHook` keys, `erlang:bump_reductions/1` included: `whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_info/1,2`, `process_flag/2`, `group_leader/0`, `bump_reductions/1`.

  `bump_reductions/1` is the one key whose answer is a **mutation**: `is_small` and non-negative else `badarg`, the charge capped at `beam_common::CONTEXT_REDS` exactly as the C does (`bif.c:5460-5462`), `true` on success, no hook ⇒ the typed gap.
  `is_process_alive/1` treats **every** external pid as the oracle's `badarg` (the old-incarnation `false` branch needs a dist table M1 lacks) — a documented omission, never a fabricated `false`.
- `match_spec.rs`/`packet/`: `erlang:match_spec_test/3` (the `table` dialect, returning the C's `{ok,Result,Flags,Errors}`/`{error,Errors}`) and `erlang:decode_packet/3` (argument validation + the 15-type switch) — **no valid packet type is a typed gap** (`./packet/CONTEXT.md`).
### `snifs.rs` — the generated `erlang:system_info(snifs)` roster (data, registers nothing)
The declared `bif.tab` surface **as data**: `SNIFS_TABLE_ORDER` holds one `Snif { module, function, arity }` per declaration in **`bif.tab` file order** (556 rows), and the public `snifs()` accessor yields them in the **oracle's list order** — `build_snifs_term` (`../../erts/emulator/beam/erl_bif_info.c:2764-2772`) conses `bif_table[0..BIF_SIZE]` forward onto the tail, so the answer is that table reversed.
**Generated data, never hand-edited:** `gen_snifs.escript` (beside it, the `gen_instructions.escript` convention) parses `erts/emulator/beam/bif.tab` with the grammar `bif_tab.rs` parses — quoted operator names stripped (`'+'` → `+`), `lo-hi` arity ranges expanded — and **aborts** on a dotted module name, which is exactly what the C's `is_snif_term` (`:2743`) filters; no row in this tree has one, so the roster is filter-free by construction rather than carrying a filter that could never fire.
Release skew is recorded, not "fixed": this tree (OTP 30) declares three rows an OTP-29 oracle lacks (`erlang:{pid,port,ref}_to_binary/1`), so a live OTP-29 oracle answers **553** rows. `../tests/snifs.rs` pins the length/first/last rows/dotted-free property, re-parses `bif.tab` and compares row for row (order included), and compares a live oracle's answer against the roster minus exactly those three rows.
### `erlang:raise/3`'s stacktrace forwarding (`convert.rs`)
`raise(Class, Reason, Stacktrace)` **decodes** its valid 3rd argument into the returned raise's `beam_common::StackTrace` (beside the `is_stacktrace` predicate the returned-`badarg` gate uses); the engine then renders a non-empty supplied trace **verbatim** in place of its own raise-snapshot trace (`beam_engine`'s supplied-frame latch), reproducing the oracle's `build_stacktrace`.
An element `{Module,Function,Arity[,Location]}` maps to a `StackFrame`: `Module`/`Function` read from the shared table by **name**, the 3rd element the `arity: u8` only for an integer in `0..=255`, an absent 4th element or `[]` a `location: None`, `Location` exactly `[{file,FileNameCharList},{line,N}]` (a char list of Unicode scalar values; `N` in `0..=u32::MAX`); `[]` decodes to the **empty** `StackTrace`, leaving the latch unarmed; the orthogonal `reason.rs` rule of `../CONTEXT.md` handles the reason, both arms carrying the decoded frames.
**Never fabricated.** A trace element the oracle echoes verbatim but a `StackFrame` cannot express — an `erl_eval`-style `{Fun,Args}`/`{Fun,Args,Location}` call frame, a 3rd element that is an argument list or any other non-`0..=255` value, an unnameable `Module`/`Function` atom, or a location not exactly the shapes above — is the typed `unsupported_bif` **raise**, never the returned `badarg` (the argument is valid, so it is a capability gap); the returned-`badarg` cases are untouched (a bad class, a non-list/improper/non-frame trace, a location that is not a list).
**How the C differs (ground truth `bif.c:1549-1696`).** The C *validates* the same element shapes (2-tuple `{Fun,Args}`, 3-tuple `{Fun,Args,Loc}` or `{M,F,A}`, 4-tuple `{M,F,A,Loc}`, a list-or-`[]` location, a proper list — anything else `return am_badarg`, `:1580-1624`) but then **stores the caller's list itself** as the raw trace: `c_p->ftrace = stacktrace` with no copy when no normalization is needed (`:1644`), else a copy where `{Fun,Args}` becomes `{Fun,Args,[]}` (`:1676-1678`) and `{M,F,A}` becomes `{M,F,A,[]}` (`:1679-1681`); the list is then wrapped `TUPLE3(make_big(StackTrace), ftrace, [])` (`:1688`) with `fvalue = value` and `EXF_SAVETRACE` cleared (`:1563-1573`). Two consequences for this crate's symbolic decode: (a) the `[]`-location normalization is done **at render time** by the engine's carve, not stored; (b) the C truncates a supplied trace to `erts_backtrace_depth`, **minimum one element** (`:1627-1637`) — this decode applies **no** depth cap, so a `+B`-style limit is not reproduced.
`error/2,3` and `nif_error/2` discard their argument list, so the engine's synthesized head frame never carries the C's `Args` slot (C stores `fvalue = {Reason, Args}`, `bif.c:1452`, `:1500`, `:1529`, and `build_stacktrace` prints those args in the top frame).
**A supplied trace REPLACES the derived one whole — add no frame of your own.** C's `build_stacktrace` short-circuits on `is_raised_exc(exc)` → `get_args_from_exc(exc)` (`beam_common.c:1211-1213`) *before* any frame lookup, so neither the raise site's own frame nor a synthesized callee head item may be consed in front of the supplied frames; the decode here stores them verbatim, in list order, and takes nothing from the calling context (only `ctx.atoms()` for the names, `ctx.intern_atom` for the returned `badarg`).
Oracle-verified decode/consumption facts (erts-17.1): `{m,f,1}` ⇒ `{m,f,1,[]}`; an **argument list** in the `A` slot is echoed verbatim (`raise(error,foo,[{m,f,[1,2],[]}])` ⇒ `[{m,f,[1,2],[]}]`) where this crate's `arity: u8` is the typed `unsupported_bif`; a supplied list longer than `erts_backtrace_depth` is **truncated to 8** (default limit), which `decode_stacktrace` does not do.
**Known divergence (downstream, `beam_engine`):** an **empty** supplied list decodes to an empty `StackTrace`, which is indistinguishable from "no trace supplied", so the non-empty latch test at `../beam_engine/src/interpreter/bif.rs:453-456` leaves the landed raise's cooked trace `raise_snapshot`-derived — but the oracle answers `try erlang:raise(error,foo,[]) catch _:_:S -> S end` with `S = []` (C stores the empty list as a raised exception too).
### The innermost BIF item's `cause` (`error_cause.rs`) — the other half of ERTS's `EXF_HAS_EXT_INFO`
`pub enum ErrorCause { Cause(Eterm), Undecided }` + `pub fn error_cause(ctx, module, function, args) -> Result<ErrorCause>` are the crate root + `prelude` surface (additive).
It models the `cause` half of the C's extension: the value a failing BIF stores in `c_p->fvalue`, which `build_stacktrace` packs beside `module` as `#{cause => Value, module => FormatModule}` (`beam_common.c:994-1000`).
`Undecided` is a deliberate third state, not a gap marker — "the oracle attaches no cause" and "this layer cannot tell" are different claims, and both degrade to today's one-pair `#{module => F}` map, so a host never asserts an absence it cannot support.
Two families are decided. The `ets` **table argument** (the C's `db_get_table_aux` split, `erl_db.c:280-310`/`:818-931`): an atom name no live table binds ⇒ `id`, a term that is neither an atom nor a tid ⇒ `type`, while a bound name, a reference (the M1 bare-ref/dead-tid ambiguity, `ets/resolve.rs`'s `resolve_handle_opt`) and a *live* table (whose later failure is BIF-specific) stay `Undecided`; it is gated by the 46-key `TABLE_ARGUMENT_BIFS` roster, whose 13-key complement `NON_TABLE_ARGUMENT_BIFS` (no argument, a *name* argument, a continuation, a non-BIF `ets.erl` fold) makes the two a partition of the 59 registered `ets` keys, pinned by `the_rosters_partition_the_registered_ets_keys`. And `erlang:register/2`'s three **pre-registry** refusals ⇒ `none` (the C's `c_p->fvalue = am_none`, `register.c:181-190`): a non-atom name, `undefined`, an id that is neither an internal pid nor an internal port — the state-dependent refusals (`notalive`/`registered_name`/a taken name) stay `Undecided`.
Measured oracle matrix (OTP 29.1.2 / erts-17.1.1, pinned row for row by `../tests/error_meta.rs`): `ets:lookup` with an unbound atom ⇒ `id`, with a non-tid ⇒ `type`; `ets:whereis/1` (a *name* argument) and the bit-syntax, conversion and `maps:*` BIFs publish **no** cause; `process_flag/2` (a bad flag), `erlang:send/3`, `spawn_opt/2,3` and `erlang:decode_packet/3` ⇒ `badopt`, `start_timer/3,4` (a bad or negative time) ⇒ `time`, `monitor/2` (a bad type) ⇒ `badtype` — the next, data-filling family, none of it claimed yet.
The **rendering** half is `beam_engine`'s (`../beam_engine/src/families/exceptions/bif_frame.rs` renders the one-pair map; the crate root's Handoffs states the extension sizing and the defaulted `ExecutionContext` method it needs), and `reason.rs` owns only the `error/2,3` argument/`error_info` payload — the `cause` half lives in `error_cause.rs` (below).
### The port BIFs (`port.rs`) — two spellings over one machinery, and the `PortHook` seam
A port is OS process + driver + port-table slot (Stage-5 machinery, never a BIF), so every port *operation* routes through the optional `PortHook` — `unsupported_bif` with none.
`PORT_INFO_1_ITEMS` is the C's 7-item `/1` roster (`name`, `links`, `id`, `connected`, `input`, `output`, `os_pid` — `erl_port.h:100-108`), and `REGISTERED_NAME_ITEM` is the separate *leading* slot the C skips when the port holds no name.
`item_name` names a hook pair's key (an atom of the caller's table, else `None`); `port_info_roster` folds a hook pair list into a `PortInfoRoster { registered_name, items }` — non-roster items and non-atom keys dropped, `registered_name` dropped when its value is `undefined`, survivors emitted in C roster order (never the hook's), and the **first** pair kept for a duplicated item.
`find_info_pair` is the C's `erts_bld_port_info` `=:=` item search over the whole pair list (a `/2`-only item such as `monitors` matches; a non-atom item matches nothing).
`port_argument` classifies a port argument as the C's `lookup_port` does, into `PortArgument { Port, Name, External, Other }`: an internal id, an atom (the C's `erts_whereis_name_to_id` name lookup, which the seam does not expose), a remote id (it can never name a port of *this* node's table), and anything else.
The split the two spellings draw on that machinery:
- `erlang:port_close/1`/`port_info/1,2` are the `erlang.erl`-**wrapper** spellings (`bif.tab` declares no `erlang` row) and **raise** `error:badarg`; `port_close/1` returns `true` (never `ok`), `port_info/1` emits its 7-item set in C roster order (`registered_name` excluded from those 7), `port_info/2` answers `{Item,Value}` or raises `badarg` for an item matching no pair.
- `erts_internal:port_close/1`/`port_info/1`/`port_info/2` are the C spellings (`erl_bif_port.c:384/486/543`) and return the status atoms as **values**: `badarg` for `/1` and **`badtype`** for `/2` on a non-port, `undefined` for a port the runtime no longer holds, `badarg` for an item the port does not report, `registered_name` **first** (the bare `[]` when the port holds no name).
- The argument-shape classification runs *before* the seam in both spellings; the atom (name) form is the typed `unsupported_bif` gap, because `PortHook` carries no name→port lookup.
`open_port/2` forwards `Name`/`Options` to the hook (which validates the grammar, incl. `open_port(_, [list])` ⇒ `badarg`); `list_to_port/1`/`port_to_list/1` are pure (`#Port<0.Num>`, bounded at `MAX_INTERNAL_PORT_NUMBER` = `(1 << PORT_DATA_SIZE) - 1`); `port_command/2,3` and `port_info/1,2` on a port the runtime does not hold go to `../beam_rt/src/native/port.rs`.

### Fun-taking `lists`/`maps`/`ets` BIFs (the `FunCaller` seam)
The 18 `lists`, 4 `maps` and 2 `ets` (`foldl/3`/`foldr/3`) fun-taking functions delegate to the optional `FunCaller` (a BIF cannot invoke a fun), the fun argument validated **exactly as the oracle's clause guards do, before any list/map inspection**: `lists` raises the bare `error:function_clause` for a non-fun or wrong-arity fun (the `lists.erl` head), `maps`' raise plain `error:badarg` (the `maps.erl` fallback clause); a **valid** fun with no hook is the typed `unsupported_bif`; `zipwith/3` raises `error:function_clause` on a length mismatch; `all/2`/`any/2` short-circuit; `maps:filter/2` treats a non-boolean result as `BadArg`.
`BifContext::call_fun` reaches the hook through `FunCaller::call_fun_with_tables`, `take`ing the `ets` registry out of itself and restoring it afterwards (the error path included), so a callee that runs `ets:*` — the fun of `ets:foldl/3`/`foldr/3` — receives the one live `&mut TableRegistry` (two live borrows are structurally impossible); the default body ignores `tables` and calls `call_fun`, so implementors running no nested `ets` code (incl. the in-crate test doubles) are unaffected.
**These 24 keys *are* the whole class** — they are exactly `hook_sets::FUN_CALLER_BIFS` / `needs_fun_caller` (root + `prelude` exported, `binary_search`-cheap), and no other registry key applies a caller-supplied fun: the printer's 2-arity map-order comparator stays the typed `unsupported_bif` (`print.rs`'s `MapOrder::Explicit` — the printer has no `FunCaller`), and `maps:iterator/2`, `maps:filtermap/2`, `maps:merge_with/3`, `maps:update_with/3,4`, `lists:filtermap/2`/`search/2`/`uniq/2`/`merge/3` are deliberately unregistered, so they already run as real `maps.beam`/`lists.beam` code; `proplists`/`ordsets`/`string`/`unicode`/`io`/`io_lib` register no fun-taking key at all (a hook that must avoid a *nested* application — a scheduled process cannot suspend inside one — has this one roster to consult).
### `erlang:term_to_binary/1,2` and `binary_to_term/1,2` (`binconv.rs`)
- **The decode table image is memoized** — `decode_term_bif` decodes into the per-thread `DECODE_SCRATCH` image of `ctx.atoms()`, so **no BIF clones the whole `AtomTable` per call** (revalidation is the O(1) `AtomSnapshot` witness below; `tests/decode_hot_path.rs` pins the steady-state allocation count as table-size-independent).
- **Options.** `compressed`/`{compressed,0..=9}` deflate a version-less body, wrapped `[131][80][len][zlib]` only when it fits the C's `body_len - 5` budget (bare atom = level 6); `{minor_version,0|1|2}` selects the tag set byte-identically; `iovec`/`fragment` ⇒ `badarg`; `[deterministic]` re-sorts every map into full term order.
  `[local]` writes the `[131][121][hash:4 BE][body]` image (`Encoder::with_local_ext`/`finish_local(hash)`), byte-identical to the oracle's apart from the four per-VM-start node bytes when `LocalNode::local_node_hash` is installed, else the typed `unsupported_bif` gap (never a fabricated hash); `[local,compressed]` deflates the *local body* (wrapper included); `[deterministic,local]`/unknown ⇒ `badarg`; `/3` does not exist (oracle `undef`).
- **`binary_to_term/2`** takes `safe`/`used` (the count includes the `131` byte); on a top-level `COMPRESSED` image `[used]` is the compressed image's own length (trailing bytes ignored *and* uncounted); `[safe]` is the **codec's** flag, fed as `DecodeOptions{ safe, local_node, local_hash: None }` through `decode_term_with_options_used`, so a wire atom **name** not already interned is `badarg` raised by the codec **before** any interning (C `erts_atom_get`) — nothing reaches the receiver's atom table — while the flag-free path still commits names via `AtomInterner`; the `[safe]` `EXPORT_EXT` **active-export** check (`external.c:5032-5036`) is the **codec's** check site, reached only when `BifContext::export_gate()` is `Some` (`export_gate` is read before `ctx.atom_and_heap()`, like the local-node identity); with no gate installed the half is unchecked, and the loaded-module registry that answers it is `beam_rt`'s `ExportGateBridge` (`../../beam_rt/src/context/export_gate.rs`), which installs the gate on every `binary_to_term/2` dispatch.
- **The local-node identity is installed on BOTH directions** (`LocalNode`): encoding yields a byte-exact `NEW_PID_EXT`/`V4_PORT_EXT`/`NEWER_REFERENCE_EXT`, and decoding demotes such a wire id to the INTERNAL form when it fits the M1 slot, so `binary_to_term(term_to_binary(self())) =:= self()` (and the `make_ref()` form) holds; an id that does not fit keeps the faithful **external**, byte-exact round-trip form.
- **The local-fun identity gathering (`term_image` + `local_fun_identities`) is what makes a compiled module's closure encode byte-identically.** The seam is consulted for the **top-level** term and its answer verified against every local fun the term holds — a term mixing two identities (the everyday "closure capturing another lambda" shape) is the codec's typed `unsupported_local_fun`, never one identity written into the other's slot — and when no identity was installed yet the encode failed on a **nested** local fun, the identity is recovered from the term and the encode retried once.
  Both walks run only for a term that holds a local fun, so a fun-free image pays nothing; the two honest residuals are the one-slot limit itself (`beam_codec` carries one `NEW_FUN_EXT` identity per encoder — the resolver seam it needs is a crate-root Handoff) and the `-eval` `erl_eval` template closure, which no seam can attribute.
- **Binary/bitstring payloads round-trip** (`BINARY_EXT`/`BIT_BINARY_EXT`, on-heap `ErlHeapBits` and off-heap refc `BinRef`/`ErlSubBits`, any nesting, under `compressed` and every `minor_version`); `unsupported_external_term` fires only for an internal pid/port/ref with no resolvable local node and for a non-Latin-1 atom under the Latin-1 flavour — never for a binary; a runtime-made `Local` fun encodes as its `NEW_FUN_EXT` image once `LocalFunIdentity` answers (asked only for a `Local` fun), else the typed `unsupported_local_fun`; `float_to_list/2`/`float_to_binary/2`'s `short` is the `sys_double_to_chars_short` port with the oracle's **exact-tie rule** (~738k doubles, 0 mismatches), as are `{decimals,N}`/`{scientific,N}`/`compact`.
### `io`/`io_lib` directive set and the printer (`src/io.rs`, `src/io_ts.rs`, `src/print.rs`)
- **Directives:** `~w ~p ~W ~P ~s ~ts ~c ~tc ~n ~~ ~i ~b ~B ~x ~X ~+ ~# ~e ~f ~g`, the `~k`/`~K` map-order modifiers (`~k` takes the order without consuming an argument, `~K` from the next one), prefix `-` (left adjust), width (`*`), precision (`.`/`*`), pad character and the `t`/`l` modifiers.
  `~+`/`~#` render the base with its own `Base#` prefix, sign first (`~.16#` of `-255` ⇒ `"-16#FF"`), and every integer directive renders arbitrary-precision values; `~c` takes the integer's **low byte**, `~tc` the **full code point verbatim**; `badarg`: `~d`, a base outside `2..=36`, too small a precision, a wrong arg type/count, unconsumed/trailing arguments, left-adjusted `~-<n>p`, `~P`/`~W` without a depth.
- **Format argument:** a list, a binary and an atom are all accepted (`format_items` mirrors `io_lib_format:scan/2`+`collect/2`); `1`/`{}`/`5`/`[1|2]`/`<<1:3>>` are `badarg`; `~s` (Latin-1) walks nested chardata like `~ts`, but `~s` of an atom with a code point >255 is `badarg` where `~ts` accepts; `io_lib:printable_list/1` is the oracle's proper-list-of-printable-latin1 rule (no unicode arm — `io:printable_range/0` reports `latin1`), the same rule as `~p`/`~P`'s printable-string test.
- **`io_lib:format/2,3`** return the oracle's DEEP segment list (literals as individual small ints, "small" controls splicing flat, every other control one sub-list element); `/3` ignores all options except `{chars_limit,N}` — implemented for `~w`/`~p`/`~W`/`~P` and **both** string arms, reproducing `control_limited`'s elision (`N < 4` ⇒ `"..."`, else the first `N-3` **grapheme clusters**); a negative limit is the byte-identical unlimited path.
- **The printer.** `src/print.rs` is the leaf renderer (registers no BIFs); `src/print/record.rs` is the shared native-record shape + the flat record writer; `src/print/pretty.rs` + `pretty/cind.rs` are the full `io_lib_pretty` port, and **`~W` stays on the flat path** (the C `control_limited($W,…)` is a flat depth renderer).
  Floats render through the same `format_short` port as `float_to_list(F,[short])`, atoms as `io_lib:write_atom_as_latin1/1`, non-byte-aligned bitstrings as leading bytes then `Value:K`, binaries/depth by `write_binary/3` + `io_lib:write1/4`, native records by the record section below; internal pids/ports/refs render, an **external** one is the typed gap, and a **fun** renders its `erlang:fun_to_list/1` text through the one shared `src/fun_info.rs::fun_text` — all three `FunKind`s (`Local` via the `LocalFunIdentity` seam), and only a `Local` fun the seam answers `Ok(None)` for (the `-eval`/`erl_eval` template closures) is the typed `unsupported_bif` gap.
  The per-element container walks are **iterative** in both paths (one native stack frame per *container*, byte-identical output), so a long flat container does not abort; nesting **depth** is still recursive.
- **Native records (`records:create/4` values) print `#Module:Name{field = value,…}`** under `~w`/`~W`/`~p`/`~P` and the `{chars_limit,N}` routes. `src/print/record.rs` is the one home of the shape — `record_parts` extracts `#Module:Name` (module/name/field atoms through the same `format_atom` quote rule, so `#'Weird Mod':'R R'{'a b' = 1}`), the declaration-order fields (`records:get_field_names/1`, never the sorted value order) and each `name = value`'s 3-char `" = "` length — and `flat_record_chunk` is the flat writer (`io_lib.erl`'s `write_record/4` → `write_record_1/5`); `src/print/pretty.rs` carries the template model's record/field half (`print_length_native_record/7` → `build_record`, `print_length_native_record_fields/8` → `record_fields_from`, `write/1`'s record/field clauses → `write_record_node`/`write_fields`/`write_field`, `pp_record`/`pp_fields_tail`/`pp_field`/`rec_indent`, `expand`'s record/field clauses) and `pretty/cind.rs` the `cind` half (`cind_record`/`cind_fields_tail`/`cind_field`/`cind_rec`); `tests/print_records.rs` is the pin (96 oracle rows, a 760-shape no-bare-`BadArg` matrix, a fail-loud live-`erl` comparison).
  - **Two depth accountings.** Flat: field names at `D`, values at `D-1`, each *later* field at `D-1` — so field `i` names at `D-i`, `~W 1` ⇒ `#m:r{...}`, `~W 0` ⇒ `...`, and a field-less record is `#m:r{}` at every positive depth; pretty: `print_length_native_record/7` enters the field sequence at `D-1` (names there, values at `D-2`, budget `T - (NameL+2)` with `NameL = len("#m:r")`), so **`~P D` shows `~W (D-1)`'s field count with the values one level deeper** (`~P 1`/`~P 2` ⇒ `#m:r{...}`, `~P 3` ⇒ one field).
  - **Single line iff `Len < Ll - Col`** (`io_lib_pretty.erl:159`); above it `TInd = while_fail([-1,4], cind/7, 1)` (`:164-167`, `:1590-1593`) then `pp/…` (`:248-249`; `pp_record` `:314-322`, `pp_fields_tail` `:324-340`, `pp_field` `:342-356`, `rec_indent` `:358-375`; `indent(N)` = N−1 spaces, `:1596-1606`). A record's continuation column is `len("#m:r")+1` (just under `{`) and `rec_indent` breaks a field onto its own line only when `TInd > 0 && RInd > TInd`, keeping it on the current line at `RInd` otherwise — so a narrow `Ll` yields `TInd` (4 spaces at `~16p`/`~20p` of the 12-field fixture, 1 at `~12p`/`~10p`/`~8p`) while a wide one (`-1`, the 80-column default, `~40p`) keeps the `len("#m:r")+1` column. `pp_field` re-runs the same rule with the field's `key_len` as `RInd`: it breaks after `" ="` at `TInd` in from the field's indent, else keeps `" = "` and continues at `key_len`; a value that is itself re-flowable breaks under its own bracket at that container's indent. `cind_rec`'s `Col =< Ll div 2` decides the `-1` arm, the 4-space form the 4, and 1 is the last resort (`:1531-1546`).
  - **`chars_limit`**: `io_lib:format/3` honours **only** `{chars_limit,N}` (`{column,_}`/`{line_length,_}` are silently ignored — the column is the directive's pseudo-arg `.C`, the line length its width `L`). `~w` with `N > 0` does **not** use `write1/4`: `io_lib.erl:609-620` routes it through `io_lib_pretty:intermediate/7` with `RecDefFun = fun(_,_) -> no end` and `Str=false`, then the flat `write/1`; `~p`/`~P` route `intermediate` through `print`. `intermediate` (`:823-831`) seeds `print_length` at depth 1 and grows via `find_upper`/`search_depth` (`:833-875`), so the elided form is the flat-depth-1 one and thresholds are exact rendered lengths; `N = 0` ⇒ `...`.
  - Divergences a fast path must reproduce: with `chars_limit` the same value is `[97,98,99]` under `~w`/`~W` but `"abc"` under `~p`/`~P`; a nested map elides as `#{}` under `~W` where `~P` gives `#{...}` at the same visible field count; a single-pair map in a record under `~W 2` gains a trailing `,...`; `~w` **never** inserts a newline at any depth or limit; a printable list field stays flat (`[97,98,99]`).
### The `%T` renderer (`src/print/c_printf.rs`) — `erlang:display/1`'s text
`pub fn term_text(ctx, term, precision) -> Result<String>` is `../../erts/emulator/beam/erl_printf_term.c::print_term`'s port and registers no BIFs; it is the crate's one **public** `%T` entry point (the outside caller is `beam_rt`); `term_conv.rs::display_1` is `term_text(ctx, term, i64::MAX)` + `"\r\n"` (`erlang:display/1` is `erts_printf("%.*T\n", INT_MAX, Term)` returning `true`).
- **The C's work stack, not a recursive walk.** `Item` collapses each C `(value, tag)` push into one variant (`Comma`/`Bar`/`CloseList`/`CloseTuple`/`Assoc`/`Equals`/`Term`/`OneCons`/`ArrayElem`), so the LIFO pop order — and therefore a budget stop landing mid-list at exactly the C's byte — is preserved; punctuation prints without consuming the budget.
- **What differs from `~w`/`~p` (deliberately):** no spaces around `=`/`=>`; native-record fields in the definition's **stored** (ascending atom-index) order, not declaration order; floats as `printf("%e")` with six fraction digits (`1.5` ⇒ `1.500000e+00`, `-0.0` ⇒ `-0.000000e+00`, where `~w` gives `1.5`); and the C `print_atom_name` atom rule — a reserved word is **not** quoted (`'and'` ⇒ `and`) while `@`, a leading uppercase letter or a space forces it (`a@b`/`A`/`a b` ⇒ quoted). Its printable-list rule quotes a printable latin-1 list and escapes only `"` and `\n` (a backslash is **not** escaped, where `~p` escapes it).
- **The budget is a byte budget (`dcount`), not a depth.** Every term item costs one unit; an atom also costs its byte length, and a printable list's per-character loop and a bitstring's per-byte loop may stop *after* writing — so the abandoned closing quote is reproduced (`term_to_string("hello", 6)` ⇒ `"hello"... `). A stop appends `"... "`; `precision = i64::MAX` (the C `INT_MAX` ⇒ `LONG_MAX`) never stops.
- **Errors stay typed:** `unsupported_bif` for an external pid/port/ref (its channel number is not in the frozen term) and for a `Local` fun with no `LocalFunIdentity` seam; `badarg` for a malformed native record. A fun renders through the same shared `fun_info::fun_text` the leaf printer uses.
- **Documented deviation:** the sink is a Rust `String`, so a byte `>= 16#80` of a printable list/binary is written as UTF-8 rather than latin-1 (every byte `<= 16#7F` is byte-identical); see `../CONTEXT.md`'s Divergences.
- **Pinned by** 8 in-module unit tests (every string measured from `erts_internal:term_to_string/2` on the oracle) and `../tests/print_records_c_printf.rs` (34 `%T`/`display` rows + 26 `~w`/`~p` mirror rows, a stored-order property computed from the term's own atom indices, a `badarg`-on-every-route negative, and a fail-loud live-oracle cross-check).
- **Served, not shadowed:** `erlang:display/1` reaches `display_1` on the runtime — `beam_rt`'s native floor has no `erlang:display/1` arm (`../beam_rt/src/native.rs` records it as deliberately not a floor entry), so this crate's registry key renders the `%T` text through the runtime's `OutputSink`, and `../beam_rt/tests/display_oracle.rs` cross-checks a native record / map / float / atom / printable list against the live `erl` byte for byte, CRLF terminator included. The one gap is the `>= 16#80` UTF-8-vs-latin-1 encoding of the bullet above, which needs a byte-oriented `OutputSink`.

## Per-BIF-call cost inventory (measured; read the ratios, never absolute latency)
- **Allocation pins** (`tests/{arith_alloc,binconv_alloc,term_ops_alloc,ets_insert_alloc}.rs`; `tests/decode_hot_path.rs` pins the steady-state decode allocation as table-size-independent): the two-small-int `+`/`-`/`*` fast path 0 alloc / 0 B, bignum promotion costing the single widened `Big`; `list_to_binary/1` 1 / 64 flat-64, 1 / 133 mixed, 0 / 0 empty, 13 / 2049 for a 200-deep nest (the spill `Vec` of an iterative walk); `length/1` 0 / 0 and 100-element `list_to_tuple/1` 1 / 800; `ets:insert/2` of one object 0 / 0.
- **`term_to_binary/1`/`binary_to_term/1`** over a 5-key map: encode = one `Vec<u8>` (the encoder's own writer, which `compressed_image` hands back on the compress-but-unprofitable revert) + the on-heap block, decode = one `Vec<u8>` + one `Vec<(Eterm,Eterm)>` + the map block, and no per-call `HashMap`/`HashSet`/`String`/`format!` — a 101-byte image 1 / 128 B encode and 4 / 285 B decode, a 4102-byte one 2 / 4102 B and 1 / 4102 B, `[local]` paying a second image buffer inside `beam_codec` (the codec Handoff).
- **Readers copy the whole payload out of the term by default** (`bits::bytes` → `access::binary_bytes`, `.to_vec()`); the borrowing `bits::with_bytes` is the zero-allocation exception with five call sites (`binconv.rs`'s `erlang:binary_part/2,3`, `binary.rs`'s `at/2`, `part/2,3`, `bin_to_list/2,3`, and the iolist walk). `binary:at/2` allocates nothing, `binary:part/2,3`/`erlang:binary_part/2,3`/`bin_to_list/2,3` copy out only the selected range, and `binary_to_list/1,3`/`bin_to_list/1` pay two buffers (the owned payload and the `Vec<Eterm>`) before the cons cells.
- **The `ets` copy-out is the measured `ets_copy` cost** (`tests/ets_table_alias.rs`): pooled-heap words per op are `lookup/2` of one `{k,42}` object 5 → 2, `tab2list/1` of 3 objects 15 → 6, `lookup_element/3` of a boxed element 3 → 0, a miss or empty result 0 → 0.
- **`byte_size/1`, `bit_size/1` and `length/1` are all three JIT-inlined** (the value half of the baseline tier's six-BIF inline set), so no size/length call crosses a BIF door there: `emqx_base62:decode/1` 76 999 → 62 484 instructions/call, a kernel crossing the door 16 times per call. `byte_size/1` rounds **up**, while `size/1` and `binary:referenced_byte_size/1` truncate; `bits::byte_size` is dead *and* alignment-requiring.
- **Unary `+`/`-` allocate** one `Vec` per small-int call, deliberately off the `+`/`-`/`*` fast path.
- **The decode scratch revalidates in O(1)** against a `beam_term::AtomSnapshot` witness taken from the shared table, so index-identity costs zero name reads; Θ(atom-table) reads run only for a replaced or shrunk table or a memo left longer by a failed/`safe` decode, and `beam_rt/src/nif.rs` shares the witness so both decoding hosts cannot drift.
- **The one home of each shared rule — extend it, never copy it:** byte lists → `iolist::byte_list`; iodata flattening → `iolist::{byte_len, bytes, bytes_and_leaves}` (the only byte walk — `io.rs`'s `iolist_to_chars` and `term_conv.rs::iolist_to_iovec_1` deliberately are not, see `iolist.rs`'s module doc); the `erts_binary_part` range rule → `iolist::part_range`; binary construction → `bits::make_binary` (the ~107-site builder) vs `binconv::make_bin` (the `list_to_binary` family, which adds the on-heap write).

## Heap lifetime — where this crate's terms point, and which of them can go stale
Every list/container this crate walks is a **BIF argument** (it lives on the caller's heap or on `ctx.heap()`, and the walk completes inside the call) — there is **no** walker over a container an *earlier* BIF call built and returned, and none over a registry value, on the `-eval`/`compile:file/2` route.
That is the crate-wide invariant a new walker must preserve: a returned container is handed to Erlang code and its words are only guaranteed valid until the host's result tail moves them, so re-reading one in a later call is the one hazard this crate can create.
- **On-heap `binary_to_term/1` only.** `decode_term_bif` installs no `OffHeapBinaries` host, so every bitstring it builds stays an `ErlHeapBits` block on `ctx.heap()` — a `beam_bifs`-built binary can never name a `RefcBinary` payload, hence `Machine::retain_refc_binaries` cannot free anything it returned. The off-heap payload producers are `beam_engine`'s `families/bitstrings/raw.rs::make_binary` and `beam_codec::term::make_refc_binary` (the decoder's `with_off_heap` path, which `beam_bifs` does not use); `bits.rs`'s placement policy is the statement of this.
- **Readers of an off-heap payload copy while the term is live:** `access::binary_bytes` (`to_vec`, then no read of the base for a zero-length window) and `access::with_binary_bytes` (a closure-scoped loan) — neither returns a pointer that outlives the call.
- **Raw `Eterm` stores must be deep copies, never a caller's words.** The two sound models are `binary.rs`'s compiled-pattern registry (`PatternTag` + `Vec<Vec<u8>>`) and `zlib/stream/mod.rs`'s `stash` (an ETF *image*, `Vec<u8>`); the two unsound ones are `TableRegistry::specs` (`ets.rs:364`, the caller's spec verbatim — see `./ets/CONTEXT.md`) and `beam_ets`'s `MatchContinuation.spec`/`Cursor::Anchor`, both `ets`-match-spec/select-only and off the compiler route.
- **Nested-call hazard shape** (real, off the compiler route today): an `Eterm` in a Rust local held across `ctx.call_fun`/`RuntimeHooks::call`/a nested `BifRegistry::call`, because the callee may allocate and a host may move or rewind the caller's region — `lists.rs`'s accumulator folds (`foldl3` at `:1305`, `map2` at `:1226`, `zipwith3` at `:1532`) and `runtime/erlang.rs`'s `term_to_iovec_2` (`:262-268` then `:321` re-walks `args[1]` after a nested `term_to_binary` dispatch) are the sites to re-check before this crate's fast paths are ever allowed to hold a container across a call.
