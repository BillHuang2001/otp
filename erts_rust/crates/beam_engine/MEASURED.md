# `beam_engine` — Measured Performance & Execution Coverage

Current-state measurement and execution-coverage evidence for `beam_engine`.
The numbers are current-state evidence, not a change log: re-run the cited command for the live figure.
**The sandbox is heavily oversubscribed**, so every figure below is wall-clock unless its section says it pins a core: a single sample is meaningless — read a **range over 3-4 runs** (or interleave two binaries) and never one number.

## Execution coverage
Measured by `tests/census.rs` (an executable census **and** regression gate over synthetic modules and the corpus):
- **108 `beam_loader::Instr` variants = 49 EXECUTED + 59 CLAIMED-BLOCKED + 0 UNCLAIMED** (31 core arms + 77 family-claimed); `unclaimed == 0` is asserted, so a regression fails the build. "Claimed-blocked" = a core arm or a family *owns* the variant but the probe operand returned a typed capability error (mostly degenerate-probe artifacts from atom-ish operands driven with `Operand::Nil`/empty tables). **`TestKind`: 25/25 executed, 0 unclaimed.**
- **Corpus reachability:** 1366/1366 installed `.beam` over **34 applications** load, 2,888,257 instructions, **zero unmodelled opcodes**; the 13 unused variants are the seven native-record variants (an OTP-29 feature this toolchain does not enable), `Deallocate` (every corpus `deallocate` is fused into `DeallocateReturn` by `beam_loader`), `BsTestTail2`, `SetTupleElement` (the corpus lowers no in-place tuple write: a general `setelement/3` builds a fresh tuple and a record update lowers to `update_record`), `ExecutableLine`, `DebugLine` and the `Generic` sentinel. Oracle-checked execution-breadth floors (asserted in-suite): happy-path **171/261 modules / 504 calls**, error-path **213/261 modules / 232 targets**.
- **The census is unchanged; the delta is operand/semantic shapes *inside* already-executed variants (~10 shapes), all on the oracle's path.** `<<Bignum/float>>` segments convert via `beam_term::number::big_to_f64`; `-native` integer/float field reads and `utf32-little` match/skip honour the flags (testing `BSF_LITTLE` alone would read a `-native` field big-endian — a **wrong** value); non-byte-aligned little-endian integer writes execute. Full list + tests: `src/families/CONTEXT.md`.
- **Every remaining gap is a typed error, pinned** (`tests/gaps.rs`; `tests/stdlib_sweep.rs::blocked_mechanisms_report_their_typed_error`; `tests/bitstrings_create_fail.rs`), and the exception reason atoms are seeded by the test host (`tests/support/mod.rs::SEED_ATOMS`, append-only so indices never shift; production `beam_rt` must do the same -- Handoffs #2).

## Measured (interpreter ns/instruction -- `tests/engine_bench.rs`)
Measured at this node's HEAD with `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test engine_bench -- --nocapture` (median of 5 samples per run).
- per-run **setup floor** (`Machine::reset` + run entry for a 2-instruction run): **~115-125 ns/run** in a quiet window (`setup/empty` is the noisiest row of all; a busy window reaches ~315).
- `dispatch/noop` (shared-label no-op loop): **2.2-2.5 ns/instr**; `dispatch/many-labels` **7.7-8.0**.
- `move/2` **4.2-4.7** ns/instr - `test/2` (no branch) **5.8-6.0** - `ctrl/2` (call/return chain) **3.8-3.9** - `branch-loop/2` (taken test + jump) **7.9-8.0** - `tail-loop/2` (test + `call_only`) **6.9-7.2** - real `erlc` `tailcall:even/1` **6.3-7.0**.
- **`list-walk/1 (recursive)`** -- the BIF-free 1,000,000-element recursive list walk (`sum([H|T]) -> H + sum(T); sum([]) -> 0.`, exactly `7 * N + 6` instructions/run, one small-int `'+'/2` per element, no term built and no heap requested): **5.4-5.7 ns/instr** in the quiet windows (a busy-window sample reads ~11). It is the most sensitive row for the per-call/per-return engine path (one `test` + `allocate` + `get_list` + `call` going down an element, `gc_bif` + `deallocate_return` coming back up), and the residual is mostly the arity-2 `gc_bif` `'+'/2` marshal (see the attribution below).
- `gc_bif` `'+'/2` **13.7-13.8 ns/instr** -- the most expensive instruction; the context's own BIF dispatch dominates it (see the attribution section below).
- the two **`gate/call+return`** and **`gate/call_only`** ns/instr rows (same-body twins of `ctrl/2`/`tail-loop/2`) prove the A.8 gate, latched once per run, costs ~0 ns/instr.

## Measured (engine-side per-BIF-call boundary -- `tests/bif_cost.rs`)
`... -p beam_engine --test bif_cost -- --nocapture` isolates the ENGINE's side of a BIF call (clean runs; the sandbox is noisy):
- arity-2 `gc_bif` (the `STACK_ARGS` stack-array path, trivial hook): **11-12 ns**; arity-0 `bif0` **7.5-11**; arity-9 (the reused `args_scratch` wide path) **44-50** -> slope ~**4.2 ns per argument**; `test_heap` -> one `ensure_heap` vtable call + root-set slice **1.7-2.4 ns**.
- `&mut dyn ExecutionContext::call_bif` round trip (trivial hook, 2 args) **~6.0 ns** (about half the arity-2 figure); `Module::atom_table.lookup` **~24 ns** / `Module::atom_name` **~1.4 ns** bound the uncached import fallback.
- **Allocation-free per call** (counting-global-allocator proof): 2048 and 4096 `gc_bif`s both give 4 allocations / 71 bytes per run.
- **Attribution:** the engine's own side is **~11-12 ns (<= 0.15%)** of the runtime's **~10.5 us** per registered BIF call, so **~99.85% is HOST-side** (`beam_rt`'s `ExecutionContext::call_bif`).

## Measured (the reserved-heap `MinimalContext` arena -- `tests/gc_arena.rs`)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test gc_arena -- --nocapture --test-threads=1`, same-body comparison against the pre-region shape (one `Box<[Eterm]>` per allocation) reproduced in the test, `N = 100 000` allocations of 4 words (3 200 000 bytes of payload). The **allocation counts are exact**; RSS is `/proc/self/statm` delta over the measured region (4 KiB pages), so it is indicative rather than exact (glibc reuses its arena):
- **reserved-heap region** (`beam_alloc::ReservedHeap`, committed lazily and grown in place): **2** heap allocations (**1** reservation region -- the 400 000-word payload fits well inside the ~4 MiB address-space reservation, so no second region is created), RSS **+611 pages ≈ 2.4 MiB**.
- **box-per-allocation**: **100 020** heap allocations, RSS **+2017 pages ≈ 7.9 MiB**.
- So the allocation **calls** fall ~50 000x (2 vs 100 020), and an allocation now costs essentially its payload: the region is reserved up front as *address space* (lazily faulted, so unused reservation costs no RSS) and grown by raising the committed limit in place. The structural suite pins the same shape: 10 000 x 4-word allocations come from ONE region grown in place (consecutive pairs exactly `words` apart), a pointer stays byte-identical across 5 000 later allocations, an oversized request triggers the fresh-region (`MoveRequired`) path while every earlier pointer stays valid, and a zero-word request stays non-null/aligned.
- **Caveat.** The figure is the `MinimalContext` *test* arena; the measured per-BIF interpreter path still allocates nothing per call (`tests/bif_alloc.rs`, above), and the production heap is `beam_rt`'s, not this arena.

## Measured (JIT tier micro-benchmark -- `tests/jit_bench.rs` over `src/jit/bench/**`)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test jit_bench -- --ignored --nocapture` (add `--features jit-cranelift` for the Cranelift column). Twelve workloads, `3000` timed runs each, warm-up excluded; a native tier compiles **once** outside the timed loop (excluded, and reported separately — 12 us-1.4 ms baseline, 0.3-120 ms Cranelift). `ns/op` is the **mean** and includes the per-run setup (`Machine::reset` + the label-map build).

Every workload **asserts the tiers agree** on its intended value (structural `beam_term::cmp`; the tiers have separate heaps) — never "the JIT is faster", which is environment-dependent (Part II §F: correctness-first mechanisms, not optimisers).

**`beam_rt` selects the tier per process** from `BEAM_RT_TIER` — unset/`auto`/`baseline` all select `Tier::BaselineJit` for **every** process entry, kept across pre-emptions and suspends, with `interpreter` the only kill switch — so these are still **ENGINE-Mechanism** figures, not end-to-end runtime figures. No module is barred from the baseline tier: the engine's `Step::Enter` in-machine module-context transfer is implemented and driver-mediated (pinned by `tests/jit_cross_module.rs`), so no per-module switch-safety predicate gates the JIT. `beam_rt`'s `-eval` root expression is a tree-walk evaluator with no `Machine`, so a selected native tier applies to module-run (`run <file.beam>`) and spawned-child slices, not to the `-eval` expression itself.

**Feature OFF** — interpreter -> baseline-jit (one coherent run, host loadavg ≈7.9; the sandbox is shared/high-load, so read the absolute ns/op as a range and the ratios as the signal):

| workload (category) | interpreter ns/op | baseline-jit ns/op | speed-up |
|---|---|---|---|
| `build/0` (tuple/list BUILDING: `put_tuple2`/`put_list`) | 13.0k | 9.3k | 1.39x |
| `map/2` (map build + get + put) | 10.2k | 8.5k | 1.20x |
| `select/1` (`select_val`-heavy branches) | 2.0k | 1.3k | 1.56x |
| `walk/2` (recursive non-allocating list walk) | 2.1k | 0.42k | 5.09x |
| `sum/1` (non-tail-recursive list sum; a Y-operand `'+'/2`) | 4.0k | 2.4k | 1.67x |
| `slice:fib/1 (20)` (real `.beam` fixture) | 1.26k | 0.42k | 2.96x |
| `kernel/2` (256 chained `gc_bif '+'/2`) | 3.3k | 0.55k | 5.93x |
| `wide/2` (256 steps over 8 x-registers) | 4.3k | 0.57k | 7.55x |
| `aggr/2` (128 steps of aggregate reads + `'*'/2`) | 7.3k | 2.2k | 3.27x |
| `cmp/2` (64 rounds of the eight comparison BIFs) | 6.8k | 1.5k | 4.59x |
| `cross/2` (cross-module `call_ext_last` ping-pong -- see the note below) | 6.9k | 6.7k | 1.03x |
| `call_ext/0` (256 declined `call_ext` BIFs in a loop) | 9.0k | 5.4k | 1.68x |

`cross/2` is the one workload whose baseline figure only reaches **parity** (≈1.03×): a `call_ext_last` is not inlined and a cross-module transfer cannot be linked (separate executable mappings, buffer-local `rel32` fixups), so every hop pays the caller's per-instruction deopt **plus** a driver-visible `switch_into` (context switch + the callee's literal/block resolution) and a fresh callee block entry -- the transfer is deliberately **un-amortised** by construction (the callee's blocks still run natively; only the transfer is not). Detail in `src/jit/bench/CONTEXT.md`.
**Feature ON** (`--features jit-cranelift`) — the Cranelift tier is reported **against the baseline tier** as a cost ratio; the per-workload table, the codegen cost and the verdict are in the `## Measured (optional Cranelift hot tier — default-OFF)` section below and in `src/jit/cranelift/CONTEXT.md` §"Measured verdict".
- **Cranelift is NOT a win** — a correctness-first mechanism over the **same** shared interpreter helper, not an optimiser.
- **Local tail-call linking (`call_last`/`call_only`)** removes one driver round-trip per local tail call: `slice:fib/1(20)` baseline-jit **665.6 -> 580.4 ns/op** (paired means over 6 runs, an older sample; re-run for the live figure). The Cranelift tier lowers the frame-less `call_only` the same way (`DISPATCH_REL` -> the `jump` lowering) and inlines `swap`; both are interpreter-identical and counted by `CompiledFunctions::{inlined_swap_count,inlined_tail_call_count}` (`tests/jit_cranelift.rs`).
- **Not done (honest):** `call_ext_last` executes on the baseline tier but as a driver-mediated transfer (a seal-time cross-module link is unsound -- separate executable mappings / buffer-local `rel32` fixups), so the transfer is not amortised; the frame-popping `call_last` stays on the helper in Cranelift (the pop is Rust-side `Machine` state); `PutTuple2`/`BsTestTail` deopt; residency is block-fixed. Both tiers allocate in the never-freed `MinimalContext` arena, so a term-building workload grows RSS with the iteration count (the run counts keep that bounded).
- **Native-tier observability (#9).** Every compiled block's PROLOGUE records its own `(func, pc)` via `Machine::set_current_code`, so `Machine::current_code` is block-exact even across linked chains; the store did **not materially regress** `jit_bench` (the per-workload deltas are within the sandbox drift, so quote a min-of-N and compare only same-run figures). A **traced** run (`ctx.trace_enabled()`) refuses native entry and runs the interpreter driver, so a traced tier-run is byte-identical to a traced interpreter run -- O(1) per run, zero cost when untraced.

## Measured (rooted-allocation memory bound -- `src/terms/alloc_tests.rs`)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --lib the_rooted_seam_bounds_peak_live_words_as_the_loop_grows -- --nocapture`. An allocation-heavy loop of `N` iterations runs **twice** over the same synthetic builders — once through an **UNROOTED** context (a fallback that hands out fresh words and never relocates, modelling a host that ignores `alloc_words_rooted`) and once through a **rooted** context that installs a mock **moving semi-space** collector behind `ExecutionContext::alloc_words_rooted` (it relocates every live root on each collection). Each loop keeps a small live set (a running accumulator), so the *retained* footprint should stay constant while the unrooted churn grows with `N`:

| N | BEFORE: unrooted words | AFTER: rooted live words | collections |
|---|---|---|---|
| 1 000 | 18 000 | 8 | 3 000 |
| 5 000 | 90 000 | 8 | 15 000 |
| 20 000 | 360 000 | 8 | 60 000 |
| 50 000 | 900 000 | 8 | 150 000 |

- The unrooted peak grows **exactly linearly** in `N` (18 x `N` words); the rooted live set stays **constant at 8 words** regardless of `N`, and a real collection fires **~3 per iteration** (`N * 3`). The test asserts `collections >= 3 * N`, `live < 64`, a strictly increasing unrooted series and a constant rooted series.
- **Real collection is demonstrated by a test** (not just counted): the live terms survive relocation and stay correct after every collection —
  - `tests/rooted_alloc.rs::a_moving_collector_relocates_the_live_operands_and_the_terms_stay_correct` runs the term-construction arms (`ralloc_tuple`/`ralloc_list`/`ralloc_build`) through the rooted seam under a `MovingContext` that moves the arena on each collection, and reads the built terms back (addresses changed, values intact);
  - `src/terms/alloc_tests.rs::the_mock_collector_relocates_a_root_across_every_collection` and `a_moving_collection_during_the_reserve_keeps_a_built_tuple_correct` pin the same for a `terms::make_*` builder.
- **The host side is the production runtime, not this mock.** The collector here is a **test mock** (a moving semi-space), while `beam_rt` overrides BOTH rooted doors — `ensure_heap_full` (`beam_rt/src/context/execution.rs:485`) and `alloc_words_rooted` (`:509`), reached through `beam_rt/src/runner/budget.rs:343`/`:396` — so an ordinary `beam_rt` run collects over the whole `RootSet` at exactly these admission points (see `INSTRUCTION_SURFACE.md` Handoff #11). This table is the mechanism-level evidence that the rooted seam bounds retained memory.

## Measured (interpreter hot-loop micro-optimizations)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test engine_bench -- --nocapture` (and `--test bif_cost` / `--test jit_bench -- --ignored`); BEFORE/AFTER are min-of-N interleaved runs — the host is heavily oversubscribed, so read them as ranges.
- **By-value step result** — `step_instruction`/`step_instruction_inner` return `Result<Step, Box<BeamError>>` (`src/interpreter/dispatch.rs`: a ~72 B `BeamError` becomes a 16 B register-returned value, the `Box` allocated only on the raise path), which improved every arithmetic/control row (`dispatch/noop` 5.5→3.2, `gc_bif '+'/2` 21.4→15.1, `tail-loop/2` 11.2→8.4, `list-walk/1` 10.7→9.5 ns/instr) while the allocation-dominated `jit_bench` rows (`map/2`/`aggr/2`/`build/0`) read ~1-7 % the *worse* (code layout on allocation-heavy paths).
- **Latched reduce gate** — `Machine::reduce_on` + the defaulted `ExecutionContext::wants_reduce` (default the conservative `true`; only a host whose `reduce` is the default no-op may return `false`): ~3-7 % on `ctrl/2`/`branch-loop/2`/`list-walk/1`/`tailcall:even/1`, ~12 % on `move/2`; `Machine::reductions()` is unchanged.
- **Register-file high-water mark** — `Machine::reset` refills only the **written** high-water mark of each register file (`x_mark`/`fr_mark`, raised by the conditional store in `set_x`/`set_fr`) and refills **both files in full** whenever a writer that cannot report its slots ran (the sticky, reset-consumed `regs_escaped` flag: `x_mut`/`fr_mut`/`with_roots`, plus `mark_regs_escaped()` when a native block returns). `setup/empty` ~259→~100 ns/run (~2.6×).
- **Single-traversal `build_label_map`** — one pass instead of two (entry buffer sized from the `Code` header's exact `label_count`, clamped) — `lists.beam` 10.6→6.5 µs, `string.beam` 9.5→6.0 µs, `tailcall.beam` 276→193 ns.
- **Declined on measurement (not carried):** devirtualizing the `bif`/`gc_bif` `&mut dyn ExecutionContext::call_bif` crossing — its measured ceiling is ~0.01-0.03 ns/call (the ~2.4 ns `bif_cost` attributes is the *host's own* hook body, not the vtable crossing); memoizing the `LabelMap` — every *sound* key (a full `Function::labels` traversal, or the `jit::cache` content fingerprint at ~141 µs for a 2048-instruction module) costs at least the single-pass build it would replace, and a cheaper key is unsound because `Module` is `Clone` with public fields; and a per-`func` cache of the resolved slice — it **costs** 20-40 % on the tight dispatch rows, because `module.functions.get(func)` is already a bounds check + one `imul` + an L1-resident load.

## Measured (baseline-JIT cold start — lazy per-function compilation)
The baseline tier's runtime path compiles **per function, lazily** (see `../CONTEXT.md` Intent): one sealed mapping per function, lowered on first entry of a `(func, pc)`, so a fresh `beam_rt` OS process pays only the functions it enters rather than the whole module. The eager whole-module layout (`JitBackend::compile`) is retained for the whole-module introspection surface and `jit_bench`.
- Repro shape (from the sibling `../beam_rt/PERF.md`): `beam_rt run <bslice_string.beam> bslice_string:str_length/1 '"hello"'` (`string:length/1` is ~7995 IR instructions). N=30 **interleaved** samples: default (baseline-JIT) **31.86–45.45 ms (min 31.86)** vs `BEAM_RT_TIER=interpreter` **25.51–40.48 ms (min 25.51)** → ~**1.22–1.25x**. The equivalent `tools/bench` `slice` workload read **31.97 ms default / 31.92 ms interpreter** (min-of-3). The eager whole-module compile it replaced measured **405.29 ms default / 33.68 ms interpreter** (~12.3x) on the same shape, so the cold-start regression is gone.
- **No hot-loop regression:** the eager/hot path is unchanged (`--test jit_bench -- --ignored`, all twelve workloads, within the ranges above; `--test engine_bench` interpreter figures unchanged — the change touches zero interpreter source).
- Caveat: `jit_bench` drives the **eager** artifact only, so it pins the eager/hot path, not the lazy path's per-entry cost.

## Measured (baseline-JIT cache lookup — no IR re-hash on a hit)
`CodeCache`'s key is the two-part `CacheKey`: the module half is `ModuleKey` — `Digest([u8; 16])`, the module's **load-time MD5** (`Module::checksum`) for a real `.beam`, read as a plain `Copy` with no hash and no allocation, else `Content { name, fingerprint }` over the whole-IR hash (`module_fingerprint`) for a synthetic all-zero-checksum module — and the second half is the atom namespace the code was lowered against (`Module::atom_table.snapshot()`), because the emitter bakes atom indices into the code. The variants hash their discriminant, so they can never cross-key. The whole-IR fingerprint costs ~2 µs for a tiny bench module and ~141 µs for a 2048-instruction one, and nothing on the run path recomputes it: the artifact stores it once (`CompiledModule::fingerprint`) and `CodeCache`'s address-keyed resolution memo is validated by a `Weak<Module>` liveness proof plus the memoized snapshot, so a slice entry/resume (`run_baseline_cached*`) and a cross-module `Step::Enter` probe are O(1). The tier-regression narrative is in `PERF.md`.
- Why the memo lives in the cache: `cross/2` resolves **2** module contexts per run, so 2 `cached_module_blocks` calls and 2 `module_fingerprint` calls per run; every other workload and the interpreter tier make none. A memo scoped to one `drive` call would see 2 distinct modules and 0 hits — the driver already dedups a context's blocks for a run (`DriverContext::callees`), so the memo must live in the cache to pay.
- Repro: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test jit_bench --no-run`, then `<jit_bench binary> --ignored --nocapture interpreter_versus`, BEFORE/AFTER **interleaved 3x** (same host, same path; loadavg ~1.0 before every run). ns/op baseline-jit min (median): `cross/2` **11100.9 (11170.7) → 6485.5 (6500.6) = 1.71x**, i.e. from *slower than* the interpreter (7594.5) to matching it (6771.2); `sum/1` 4391.4→4373.9, `walk/2` 399.1→400.4, `kernel/2` 513.4→515.5 (all unchanged within noise).
- Honest caveats: the gain is a driver-round-trip shape, so the native tier can at best **match** the interpreter on `cross/2` (it does); the AFTER binary's *interpreter* tier also reads faster on `kernel/2` (~4719→~3200) although the interpreter never touches `CodeCache` — a binary-level code-layout/TLS effect of the added code, present in every run of each binary and not attributable to this change.
- This is **not** the `LabelMap` memo DECLINED above: that was rejected because every *sound* key (a full `Function::labels` traversal, or exactly this content fingerprint) costs at least the single-pass build it would replace. Here the fingerprint is not a key to be recomputed — it is already stored once on the per-module compiled artifact, so the hit path is O(1) and never touches the IR.

## Measured (baseline-JIT register-cache traffic — the dirty-set spill)
The block register cache's traffic is measured **structurally** (emitted store/load counts, no timing) by the test-only counters in `src/jit/baseline/counters.rs`, driven by `src/jit/baseline/census.rs::the_register_cache_traffic_census_over_the_corpus_is_printed`.
One recorded pass reports **all three** spill models side by side — shipped **dirty-set**, replaced **written-set**, naive **whole-cache** — so the before/after store comparison is a single measurement.
Design and soundness argument: `PERF.md` (Batch 54) and `src/jit/baseline/emit/regs/CONTEXT.md`.
- Corpus (32 committed `erlc` fixtures + a 1321-module installed-OTP sample = 103 008 functions / 597 333 blocks / 3 585 490 IR instructions): spill stores **4 678 655** (written-set) → **1 594 678** (dirty-set) = **3 083 977 already-clean stores removed (−65.9 %)**; whole-cache model 5 578 219.
  Emitted bytes **341 653 629 → 320 065 790 (−6.32 %)**, exactly 7 B per removed store.
- `fill` loads are unchanged by the dirty-set rule (3 695 119 liveness-restricted vs 3 950 215 whole-cache); the shipped `fill` already was, and stays, the liveness one.
- Fixtures only: `code_len` 253 272 → 248 288 B; spill stores 342 (dirty) / 1 035 (written) / 1 473 (full-cache); 960 blocks / 3 650 IR instrs / 402 block cache slots / 318 block written slots.
- Two-process copy-bound probe (`src/jit/baseline/tests.rs::the_two_process_copy_bound_shape_is_measured_on_both_tiers`): spill stores **82 → 18** (`Helper` 58→14, `Exit` 24→4) against a 102 whole-cache model; emitted bytes 8 266 → 7 818; fill loads 69 (unchanged); 14 blocks / 70 IR instrs / 12 cached slots.
- The static deopt census is unchanged (3 113 483 instances / 119 840 deopts over 8 deopting variants): the rule changes only how many *stores* a spill emits, never which instruction deopts.
- **Two later code-quality levers cut the frame/prologue traffic further** (same deterministic census). A **variable-length native frame** (`src/jit/baseline/emit/mod.rs::native_frame_regs` + `frame_slot_len`, torn down by `emit/link.rs::emit_frame_teardown`) pushes only `rbx` plus the block's own cached machine registers — a block with no cache slots pushes nothing. ## Measured (optional Cranelift hot tier — default-OFF)
The Cranelift hot tier is a correctness-complete mechanism that stays **default-OFF**; its figures are ranges over independent runs, one timing process at a time, pinned to one core (`taskset -c 3`) on a shared 14-CPU sandbox whose `/proc/loadavg` reads ≈**9.5–10 at both ends of every run**, so only the ratios are signal (the authoritative verdict is `src/jit/cranelift/CONTEXT.md` §"Measured verdict").
Per-workload min-`ns/op` **cost** ratio, Cranelift ÷ baseline (`>1` = slower), from the in-crate `jit_bench` table (3000-run timed loop): `walk/2` **0.48×** (the only win), `slice:fib/1` 0.95, `aggr/2` 0.99, `call_ext/0` 1.07, `map/2` 1.08, `build/0` 1.17, `select/1` 1.24, `cmp/2` 1.25, `kernel/2` 1.36, `wide/2` 1.39, `cross/2` 1.45, `send_recv/2` 2.18, `sum/1` 2.50.
That table runs its tiers in a **fixed** order per workload (interpreter → baseline → Cranelift), so it is position-biased against Cranelift; the position-balanced ABBA harness (`src/jit/cranelift/bench.rs::cl_bench_cranelift_vs_baseline_interleaved`, 15 rounds × 2 samples/tier) brackets it with paired means over three runs — `aggr` 0.988–1.009× (tie), `arith/2` **1.616–1.621×**, `cmp` **1.364–1.422×**.
Cranelift's one-time compile is ≈**6.5–60×** the baseline's (cheapest on `walk/2` at ≈6.5×, dearest on `build/0` at ≈60×), which a tier whose whole point is being *hot* must earn on steady-state throughput — and outside `walk/2` it does not.
The verdict is unchanged and slightly reinforced: `jit-cranelift` stays **default-OFF** and is **not reachable end-to-end** through `beam_rt` — `beam_rt/src/runner/tier.rs` has no `Tier::Cranelift` selection (`BEAM_RT_TIER` maps only to `JitMode::{Auto,Interpreter,Baseline}`), so the `foreign` / `list_walk` / `gc_bound churn` workloads are not measurable through the runtime and the in-crate harness (`src/jit/bench/**`, `src/jit/cranelift/bench.rs`) measures synthetic modules instead.

## Foreign workload decomposition (in-process, release, `taskset -c 3`)
The workload is Cowboy's `cowboy_bstr:to_lower/1` over `<<"The Quick Brown Fox 0123456789">>` (30 bytes) — the `foreign` / `bstr_to_lower` bench case, which `../tools/bench/RESULTS.md` (m15) records at **338.4 ns/call** on the system ERTS against **13 344 ns/call** on the Rust runtime (**39.4×**; the `foreign` group spans 34.8×–86.3×).
The harness is `src/bench/` (`#[cfg(test)]`-only and in-process — no `beam_rt` boot and no scheduler in the timed loop): it compiles the real `cowboy_bstr.erl` with the system `erlc` into `$TMPDIR` and skips loudly when `erlc` is absent.
`./erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --lib -- --ignored --nocapture foreign_bstr_to_lower_decomposition`; the knobs are `BENCH_ITERS`, `BENCH_BATCH`, `BENCH_WARMUP` and `BENCH_TIER=interpreter|baseline|both`.
- **438 instructions per call** (~14.6 per character) and **0** `call_bif` calls: `char_to_lower/1` is a 27-clause pure-Erlang `select_val`, so no BIF is on the path.
- `alloc_words_rooted`: **62 calls / 295 words → 32 calls / 163 words** after the in-place `private_append`.
- The local-call seam is asked **61** times per call; `call_ext` requests are **0**.
- `ensure_heap`/`ensure_heap_full`: **0**, because the shape has no `test_heap`/`allocate_heap` and `Instr::Allocate` requests nothing — the GC admission door is never reached, so the gap is **not** GC cadence for this shape.
