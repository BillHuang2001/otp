# `beam_engine` — Measured Performance & Execution Coverage

Current-state measurement and execution-coverage evidence for `beam_engine`.
The numbers are current-state evidence, not a change log: re-run the cited command for the live figure.
**The sandbox is heavily oversubscribed**: every figure below is wall-clock unless its section says it pins a core, so read a **range over 3-4 runs** (or interleave two binaries) and never one number.
**Compare windows, not absolutes.** The recorded absolute ns differ from earlier entries in this file because the host differs — only ratios carry over between windows.

## Execution coverage
Measured by `tests/census.rs` (an executable census **and** regression gate over **64** valid-operand probe rows in `tests/support/probe/**` plus the whole installed corpus):
- **108 `beam_loader::Instr` variants = 95 EXECUTED + 13 ZERO-CORPUS + 0 GENUINE-GAP + 0 UNCLAIMED** (static family assignment: 31 core arms + 77 family-claimed), pinned by `EXECUTED_VARIANTS` = 95 / `ZERO_CORPUS_VARIANTS` = 13 / `GENUINE_GAP_VARIANTS` = 0, so a re-classification fails the build. `EXECUTED` = the instruction did what its row declared (fell through to the success sink, took its own `fail`/branch sink, suspended and resumed, or raised its **own** defined BEAM exception) with **valid operands** (a real tuple/list/map/binary/bitstring subject, an `allocate`d frame, an installed mailbox, a BIF/apply hook, a resolvable callee, a match context, the module's own `funs`/`recs`); `ZERO-CORPUS` = executed but never emitted by real compiler output. **`TestKind`: 25/25 executed, 0 unclaimed. No variant is unimplemented.**
- **Corpus reachability:** 1366/1366 installed `.beam` over **34 applications** load, 2,888,257 instructions, **zero unmodelled opcodes**; the **13** zero-occurrence variants are exactly the `ZERO_CORPUS` pin, which the census asserts **equal** to the live zero-occurrence set — the seven native-record opcodes (an OTP-29 feature this toolchain does not enable for these shapes), `Deallocate` (every corpus `deallocate` is fused into `DeallocateReturn` by `beam_loader::lower::fuse`), `BsTestTail2`, `SetTupleElement` (the corpus lowers no in-place tuple write: a general `setelement/3` builds a fresh tuple and a record update lowers to `update_record`), `ExecutableLine`, `DebugLine` and the `Generic` sentinel. Oracle-checked execution-breadth floors (asserted in-suite): happy-path **504 rows over 171 modules**, error-path **223 rows over 215 modules**, and **every one of the 727 rows is oracle-checked on each of the three tiers** (interpreter, baseline, Cranelift) — zero rows disagreed with the system oracle.
- **No variant is corpus-reachable and blocked.** The one genuine typed residual left in this instruction surface is `put_record/6`'s *create* form for a **foreign** module's record id (a typed `unsupported`, `tests/gaps.rs`), which no probe row and no corpus module needs.
- **Static weight ranking.** Measured **static** corpus occurrences (how often the whole installed OTP *contains* the variant — not how often it runs; the dynamic view is the next section): `GetTupleElement` **140 759**, `FuncInfo` **103 749**, `Call` **82 110**, `CallExt` **75 795**, `DeallocateReturn` **54 479**, `CallExtOnly` **36 692**, `InitYregs` **34 782**, `GetList` **33 005**, `CallLast` **25 778**, `CallExtLast` **20 659**. Every one of the ten executes.
- **Operand/semantic shapes *inside* already-executed variants (~10 shapes) are all on the oracle's path.** `<<Bignum/float>>` segments convert via `beam_term::number::big_to_f64`; `-native` integer/float field reads and `utf32-little` match/skip honour the flags (testing `BSF_LITTLE` alone would read a `-native` field big-endian — a **wrong** value); non-byte-aligned little-endian integer writes execute. Full list + tests: `src/families/CONTEXT.md`.
- **Every remaining gap is a typed error, pinned** (`tests/gaps.rs`; `tests/stdlib_sweep.rs::blocked_mechanisms_report_their_typed_error`; `tests/bitstrings_create_fail.rs`), and the exception reason atoms are seeded by the test host (`tests/support/mod.rs::SEED_ATOMS`, append-only so indices never shift; production `beam_rt` must do the same -- Handoffs #2).

## Real-`.beam` variant proofs (`tests/real_beam_variant_proofs.rs`)
The synthetic probe rows prove a variant *executes*; this suite proves it on **real compiler output** and against the **live ERTS oracle**, so a shape no `erlc` emits cannot pass as evidence about the compiler.
- **41 variants of that static weight ordering** are proven on real `erlc` output — from `GetTupleElement` (140 759 static corpus occurrences) down to `TryCaseEnd` (270) — **plus 8 further shapes** the rows reach en route (among them `Move`, `Trim`, `GcBif` and the `RecvMarker*` quartet). The **`RECORDED_PROOFS`** checklist holds all **49** names and is audited for coverage and uniqueness, so a proof cannot silently drop out.
- **The proof, once per row** (`tests/real_beam_variant_proofs/harness.rs`): drive a committed fixture (or an installed-OTP module) through the public entry `Machine::run_export`; assert `exec_census` observed the variant execute (`executed["<Variant>"] > 0`, sometimes exactly-N); assert the observable result equals the **live `erl` oracle** — string-compared through `harness::render`, or a committed oracle-derived value whose exact `erl` command is in the row's doc comment; report honestly whatever is unreachable.
- **Fixtures:** five committed `erlc` pairs — `vb_calls`, `vb_data`, `vb_funs`, `vb_exc`, `vb_bitstr` (`.erl` + `.beam`) — one per family group (`calls`/`data`/`funs`/`exceptions`/`bitstrings`), plus the `receive` group over the existing `recv` fixture.
- `Deallocate` is pinned at **exactly 0** on real compiler output — every corpus `deallocate` is fused with the following `return` into `DeallocateReturn` by the loader, so the positive form of that statement is a zero count, not a fixture.
- `Raise` is proven on a real compiled fixture, oracle-checked.
- The 13 `ZERO_CORPUS` shapes stay covered by the synthetic probe rows: no fixture can make the compiler emit them, so claiming real-`.beam` evidence for one would be a fabrication.
- The suite **skips loudly** when the OTP install / `erl` oracle is absent; `--nocapture` prints the proof table (55 tests).

## Measured (interpreter ns/instruction -- `tests/engine_bench.rs`)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test engine_bench -- --nocapture`, median of 5 samples per run:
- per-run **setup floor** (`Machine::reset` + run entry for a 2-instruction run): **~115-125 ns/run** in a quiet window (`setup/empty` is the noisiest row; a busy window reaches ~315).
- `dispatch/noop` (shared-label no-op loop): **2.2-2.5 ns/instr**; `dispatch/many-labels` **7.7-8.0**.
- `move/2` **4.2-4.7** - `test/2` (no branch) **5.8-6.0** - `ctrl/2` (call/return chain) **3.8-3.9** - `branch-loop/2` (taken test + jump) **7.9-8.0** - `tail-loop/2` (test + `call_only`) **6.9-7.2** - real `erlc` `tailcall:even/1` **6.3-7.0** (ns/instr).
- **`list-walk/1 (recursive)`** -- the BIF-free 1,000,000-element recursive list walk (`sum([H|T]) -> H + sum(T); sum([]) -> 0.`, exactly `7 * N + 6` instructions/run, one small-int `'+'/2` per element, no term built, no heap requested): **5.4-5.7 ns/instr** quiet (a busy window reads ~11). It is the most sensitive row for the per-call/per-return path (a `test` + `allocate` + `get_list` + `call` down an element, `gc_bif` + `deallocate_return` back up), and its residual is mostly the arity-2 `gc_bif` marshal (below).
- `gc_bif` `'+'/2` **13.7-13.8 ns/instr**, the most expensive instruction — the context's own BIF dispatch dominates it (below).
- the **`gate/call+return`** and **`gate/call_only`** rows (same-body twins of `ctrl/2`/`tail-loop/2`) prove the A.8 gate, latched once per run, costs ~0 ns/instr.

## Measured (engine-side per-BIF-call boundary -- `tests/bif_cost.rs`)
`... -p beam_engine --test bif_cost -- --nocapture` isolates the ENGINE's side of a BIF call:
- arity-2 `gc_bif` (the `STACK_ARGS` stack-array path, trivial hook): **11-12 ns**; arity-0 `bif0` **7.5-11**; arity-9 (the reused `args_scratch` wide path) **44-50** -> ~**4.2 ns per argument**; `test_heap` (one `ensure_heap` vtable call + root-set slice) **1.7-2.4 ns**.
- `&mut dyn ExecutionContext::call_bif` round trip (trivial hook, 2 args) **~6.0 ns** (about half the arity-2 figure); `Module::atom_table.lookup` **~24 ns** / `Module::atom_name` **~1.4 ns** bound the uncached import fallback.
- **Allocation-free per call** (counting-global-allocator proof): 2048 and 4096 `gc_bif`s both give 4 allocations / 71 bytes per run.
- **Attribution:** the engine's own side is **~11-12 ns (<= 0.15%)** of the runtime's **~10.5 us** per registered BIF call, so **~99.85% is HOST-side** (`beam_rt`'s `ExecutionContext::call_bif`).

## Measured (the reserved-heap `MinimalContext` arena -- `tests/gc_arena.rs`)
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test gc_arena -- --nocapture --test-threads=1`, same-body comparison against the pre-region shape (one `Box<[Eterm]>` per allocation) reproduced in the test, `N = 100 000` allocations of 4 words (3 200 000 bytes of payload). The **allocation counts are exact**; RSS is a `/proc/self/statm` delta over the measured region (4 KiB pages), so indicative rather than exact (glibc reuses its arena):
- **reserved-heap region** (`beam_alloc::ReservedHeap`, committed lazily and grown in place): **2** heap allocations (**1** reservation region -- the 400 000-word payload fits well inside the ~4 MiB address-space reservation, so no second region is created), RSS **+611 pages ≈ 2.4 MiB**.
- **box-per-allocation**: **100 020** heap allocations, RSS **+2017 pages ≈ 7.9 MiB**.
- So the allocation **calls** fall ~50 000x (2 vs 100 020) and an allocation costs essentially its payload: the region is reserved up front as *address space* (lazily faulted, so unused reservation costs no RSS) and grown by raising the committed limit in place. The structural suite pins the same shape: 10 000 x 4-word allocations come from ONE region grown in place (consecutive pairs exactly `words` apart), a pointer stays byte-identical across 5 000 later allocations, an oversized request takes the fresh-region (`MoveRequired`) path with earlier pointers still valid, and a zero-word request stays non-null/aligned.
- **Caveat.** The figure is the `MinimalContext` *test* arena; the measured per-BIF interpreter path still allocates nothing per call (`tests/bif_alloc.rs`, above), and the production heap is `beam_rt`'s, not this arena.

### The position-balanced ABBA cross-check
`crate::jit::cranelift::bench` (`--lib -- --ignored --nocapture cl_bench`): 15 rounds, 30 samples/tier, per-round **paired** ratios, three independent reps — `aggr` **0.938 / 0.943 / 0.939**, `arith` **1.625 / 1.623 / 1.611**, `cmp` **1.079 / 1.080 / 1.080**.
These are **cost** ratios, Cranelift ÷ baseline (`>1` = Cranelift slower), so the biased table's `cmp` **0.93** is corrected to **≈1.08**; `aggr` is a near-tie in both instruments and `arith/2` (a chained `gc_bif '+/2` kernel) is the shape Cranelift's per-function loop loses worst on.
- **`cross/2` is the one workload whose baseline figure only reaches parity**: a `call_ext_last` is not inlined and a cross-module transfer cannot be linked (separate executable mappings, buffer-local `rel32` fixups), so every hop pays the caller's per-instruction deopt **plus** a driver-visible `switch_into` (context switch + the callee's literal/block resolution) and a fresh callee block entry — deliberately **un-amortised**; the callee's blocks still run natively. Detail: `src/jit/bench/CONTEXT.md`.
- **Not done (honest):** `call_ext_last` runs on the baseline tier as a driver-mediated transfer (a seal-time cross-module link is unsound), the frame-popping `call_last` stays on the helper in Cranelift, `PutTuple2`/`BsTestTail` deopt, and residency is block-fixed; every tier allocates in the never-freed `MinimalContext` arena, so a term-building workload grows RSS with the iteration count (the run counts bound it).
- **Native-tier observability (#9).** Every compiled block's prologue records its own `(func, pc)` via `Machine::set_current_code`, so `Machine::current_code` is block-exact even across linked chains; the store did **not materially regress** `jit_bench` (deltas within sandbox drift). A **traced** run (`ctx.trace_enabled()`) refuses native entry and runs the interpreter driver, so a traced tier-run is byte-identical to a traced interpreter run — O(1) per run, zero cost when untraced.
- **`beam_rt` selects the tier per process** from `BEAM_RT_TIER`: unset/`auto`/`baseline` all select `Tier::BaselineJit` for **every** process entry, kept across pre-emptions and suspends; `interpreter` is the kill switch; **`cranelift`** (also spelled `jit-cranelift`, `Tier::name`'s own spelling) selects `Tier::Cranelift`, reachable only when the runtime was built with its `cranelift` Cargo feature (`cranelift = ["beam_engine/jit-cranelift"]`) — without that feature an explicit request is a **typed refusal** naming the feature, reported once at the CLI boundary before the boot sequence and exiting **3**, never a silent substitution of another tier. No module is barred: the engine's `Step::Enter` module-context transfer is implemented and driver-mediated (pinned by `tests/jit_cross_module.rs` across every tier in the roster), so no per-module switch-safety predicate gates a native tier. `beam_rt`'s `-eval` root expression is a tree-walk evaluator with no `Machine`, so a selected native tier applies to module-run (`run <file.beam>`) and spawned-child slices only.

## Measured (`binary_append` — the writable-append accumulator, paired A/B)
`erts_rust/tools/bench`'s `binary_append` expands a 16 KiB input into 64 KiB of output through **16 384 first-position `private_append` segments into one writable payload** — the compiler's accumulator squeeze (`bs_init_writable` + `private_append`) — so it prices the append/bitstring-build path and nothing else.
- **The append is already amortised O(1) and needed no restructuring.** A 1 KiB hint carries the payload through 64 KiB with **2 in-place grows + 4 moves**, 61 440 bytes copied in total, against a 536 903 680-byte copy-rebuild counterfactual (`src/families/bitstrings/create/grow_tests.rs`). The mechanism maps 1:1 onto the C's (`erts/emulator/beam/erl_bits.c`): a running write offset in the term (`ErlSubBits` end), `Machine::writable_payloads`, `RefcBinary::ensure_capacity` with a doubling (1.2x above 1 MiB) growth rule, and the two-word republish.
- **What the per-element cost actually was: the instruction, not the bytes.** A compiled comprehension re-enters one `bs_match` and one `bs_create_bin` per element, and each re-decoded the flat `[Type, Index, Unit, Flags, Value, Size]` / command-word descriptor list — an atom-name lookup and a `&str` match per segment, four bounds-checked operand reads, the flags decode — and the JIT artifact's instruction position was decoded again through a helper call. Per segment the rust side spent **≈61.6 ns** against the oracle's **≈5.2 ns**.
- **The fix is pre-resolution decided at *prepare* time, never by a per-execution predicate:** `bs_create_bin`/`bs_match` descriptors are decoded once per `(module image, function, code offset)` into a typed program (`src/families/bitstrings/create/prepared.rs`, `matching/prepared.rs`, cached by `programs.rs` — per module context, direct-mapped, re-validated by key + owner witness; a shape `prepare` declines is `Program::Generic` and runs the unchanged generic walk); a static 8/16/32/64-bit field stores with one `write_unaligned` + byte swap (`PreparedSeg::ByteInt`); one capacity reservation per instruction instead of one per segment; and the native tier emits the bitstring arm's position store inline instead of calling a helper.
- **Paired A/B** — one `bench` binary, `$BEAM_RT` selecting the build, `taskset -c 1`, alternating order every round, 6 matched rounds, 1-min load 4.7–9.0 (`OLD` = the base commit `984e4f9cfe` rebuilt from its own source in a detached worktree, never a stashed binary):
| rust-only metric | OLD | current | NEW/OLD | per-round |
|---|---|---|---|---|
| `binary_append` ns/call | 1 344 351–1 356 941 | **1 001 648–1 013 634** | **0.747×** | 0.750 0.747 0.747 0.745 0.746 0.752 |
- **Same-window cross-runtime** (3 alternating `--runtime all` rounds, load 4.6–5.4): `sys` 84 056 / 84 460 / 85 096 ns per call, `rust` 1 009 399 / 1 009 064 / 1 010 305 → **11.87–12.01×**. The same pair read ≈16.0× before the change (and 16.25× in the published m15 record), so the row moves by the paired 0.747× alone — the absolute ns are host-load artefacts.
- **Tier shape** (load 43–47): interpreter **1.58×** the baseline tier per call (2 278 084 vs 1 429 000 ns), so the gain is not tier-specific — the prepared programs are shared by every tier; only the position store is JIT-only. (`BEAM_RT_TIER` never changes a result: the fixture prints the same value on all three tiers and on the oracle.)

## Measured (baseline-JIT cache lookup — no IR re-hash on a hit)

The lever is therefore the **fixed per-transfer/per-frame sequence**, not more instruction inlining. Three changes were kept; the per-lever numbers (and the four rejected ones) are `src/jit/baseline/measure/CONTEXT.md`'s closed-lever table — this record is the campaign-level pair and its wall cross-check.

### The three kept levers
- **The entry table is folded and the transfer packs once** (`src/jit/baseline/emit/compile.rs::merge_sub_entries`, `src/jit/baseline/runtime.rs::{EntryTables,enter_in_block,commit_in_block_entry}`): every block-start slot is null-filled with the continuation sub-block entry at that pc as the last step of both artifact layouts, so `EntryTables::entry` is one bounds check + one load + one null test instead of two of each, and `commit_in_block_entry` takes the word the transfer already encoded (`Machine::set_current_code_word`) instead of a `(func, pc)` pair.
- **The return path stores no position of its own** (`jit_return`/`jit_deallocate_return`): the *returning* instruction's store was dead on a taken transfer, because `commit_in_block_entry` publishes the *target* immediately after it. A decline is republished by the driver's loop head, `Continuation::Halt` by the cold `halt_word`, and a frame error in `report_frame_error`. The store is not dropped, it **moves**, and `Machine::current_code` is still written exactly once per transfer by the transfer — which is what a resume and `process_info/2` read.
- **The charge goes through a run-cached `ReduceHook`** (`src/context.rs`, `runtime.rs::charge_reduce`): `reduce` is a host method reached through a `*mut dyn`, so every transfer paid a fat-pointer move plus a vtable load; the driver latches one monomorphised shim plus the host's thin data pointer per run (`ReduceHookSource` is blanket-implemented and `reduce_hook()` is defaulted, so this is an additive seam) and every charge is one indirect call. A runtime that carries no hook still charges through the `dyn` door, so neither the count nor the ordering a host observes depends on it.

**Deopt idempotency and pre-emption are untouched.** None of this is an inline arm: the changes are in the helpers the *driver* calls between blocks, so no instruction can deopt onto half-committed state and `jit_step_one`'s re-execution contract is not engaged. A taken transfer still publishes its target and bumps `reductions` **before** the charge answers, a refused charge still parks the machine exactly where a driver-side refusal parks it (its own `BeamError` in `JitRuntime::error`, `resume_entry` null, the position already published), and a decline still leaves the pre-existing target word in `rax` with nothing committed.

### Why moving the helpers' work into emitted code does not pay
- **L1's premise does not hold on real output.** The resumed continuation sub-block of `sum/1`/`walk/3` accesses **no Y slot**, so its prologue never emitted `emit_publish_y` and the alternate entry is never taken — while the publish had to move to the prologue *head* (bracketed by `push rdi`/`pop rdi`, because the prologue's frame pushes and `rt` slot come after it), costing **+1 instruction on every publishing prologue entry** and saving nothing. A post-publish alternate entry only helps a module whose continuation sub-blocks access Y slots.
- **L3 is real but below the floor.** The slimming is genuine (−10 B / −1 instruction on the linked exit, −19 B / −3 on the unlinked one, whose guard selected between two identical destinations) yet a tail exit occurs once per ~1 000 elements in this loop, so the effect cannot be resolved on this host.
- **The gate pays back what the call cost.** A rejected/accepted test over the verdict slab is ~13 emitted instructions (three dependent loads, two bounds/length tests, five branches) plus `ExitSpill::Done → Required` at the exits it displaces; the seam work it skips is ~5 instructions in an already-warm helper. On `Instr::Call` — the one hot site — the gate's ~15 instructions against ~5 skipped plus the extra register pressure inside the block's allocation window is the whole **+5.9 %**.
- **The reading is general:** the profile's 63 % "call/return and frame glue" is *spread across five small, perfectly predicted helpers*, not concentrated in an expensive callee. Eliminating a call whose body is 10–20 instructions, by emitting 13+ instructions on the same path, cannot win; the next lever has to remove **work** (e.g. the per-transfer `set_current_code` / `reductions` bookkeeping where the driver can prove it redundant, or `jit_allocate`'s `frames.push` + `stack.resize` body) or remove **transfers**, not relocate them.
The reverted commits are `c181940692` + `926b9905b0` (L1), `470751dad3` + `d3c05c64b5` (L3), `df41192719` (their merge, which served as the L1+L3 baseline for A and B), `aadf7713c0` (A) and `1e134ad4c3` (B); the tree was restored byte-for-byte to `bc7140386e` and the campaign's only surviving change is this record plus the crate `CONTEXT.md` constraint.
