# `beam_engine` — exhaustive test / fixture enumeration

Extracted from `CONTEXT.md`, which keeps only the strategy summary + the gate figures.
This file is documentation, not a change log.
Every count below is a local run of the gate command; **`#[ignore]`d tests are not run by `cargo test` and therefore not by CI.**
Two conventions hold throughout and are not repeated per suite: a suite needing the system `erlc`/`erl`/installed OTP library **skips loudly** when it is absent, and an "oracle" expectation is either a value baked in from a real `erl` run or a live per-assertion re-invocation (each suite says which, often quoting the command in an `oracle:` note).

## Per-tier full-corpus differential sweep (tier equality)
The tiers are compared with the system ERTS over the **whole** differential corpus, not only the in-crate tier corpora: every case `differential list` reports (**3439** cases, all nine contracts) is run once per execution tier, by setting `BEAM_RT_TIER` for the `beam_rt` child processes.
- **Tier selection.** `interpreter` → `BEAM_RT_TIER=interpreter`; `baseline` → unset (`JitMode::Auto` selects the native baseline tier); `cranelift` → `BEAM_RT_TIER=cranelift` against a `beam_rt` built with `--features cranelift` (built without a feature the runtime answers a typed refusal naming it, so a missing build can never pass as a substitute tier).
- **Oracle:** the system `erl`/`erlc` on `PATH`, OTP 29.1.1 / erts-17.1.
- **Result — the same line on all three tiers:** `total=3439 agree=3438 mismatch=0 unsupported=1 skipped=0`, `ratchet: entries=1 allowed=1 unauthorized=0 stale=0` (`known-gaps.txt`), i.e. the equivalent of `gate.sh` exit 0. The one `unsupported` is the recorded `wire/new_fun_ext_encode` gap, and `skipped=0` means the two-live-VM `dist`/`dist_extra`/`wire` cases and the boot cases ran on every tier (a peer VM inherits `BEAM_RT_TIER`). The claim lives in `CONTEXT.md` (Test Strategy), the recorded figures in `MEASURED.md`; corpus size and the serial-vs-parallel sweep policy are `../tools/differential/CONTEXT.md`'s.
- **Recipe (gate-equivalent, per case).** Build with `erts_rust/scripts/cargo.sh build --release --manifest-path erts_rust/Cargo.toml -p beam_rt -p differential` (the Cranelift tier builds `beam_rt` itself with `--features cranelift`), take every id from `differential list`, run `differential run <case-id> --json --out-file <dir>/<flat-id>.json` for each one at `xargs -P 12`, then fold the per-case reports with `differential merge --from <dir> --allowlist erts_rust/tools/differential/known-gaps.txt --json --out-file <report>`. A per-case `run` report is gate-equivalent because `compare.rs::verdict_with` folds the oracle-vs-golden drift check into every verdict; a serial `differential suite` boots every CLI case (~2.5 s each) and is not the practical route.
- **One gotcha:** the two case ids containing shell-special characters (`re/compile-error_a\` and `re/compile-error_a)`) must be run individually — `xargs` eats the trailing backslash.
- **Wall time is method context, never a claim:** baseline 281 s, interpreter 262 s, cranelift 626 s, on a shared host whose load average ran 3–25 through the sweeps; quote the summary line, never the wall times.

- **Per-BIF-call attribution** (`tests/bif_cost.rs`): isolates the ENGINE's side of a BIF call (clean runs; the sandbox is noisy) — the arity-2 `gc_bif` `STACK_ARGS` path, arity-0 `bif0`, the wide arity-9 `args_scratch` path and the `test_heap` root-set slice, the `&mut dyn ExecutionContext::call_bif` round trip, `Module::atom_table.lookup`/`Module::atom_name` — the engine's own share is ~11-12 ns (<= 0.15%) of the runtime's ~10.5 us per registered BIF call. - **Reductions / pre-emption** (`tests/reductions.rs`, 8 tests): a hand-built module whose body is a TIGHT NON-ALLOCATING loop (no `Allocate`/`TestHeap`, so `ensure_heap` — the engine's other charging point — is never reached) is driven through `Machine::run_export_outcome`: `Machine::reductions()` is `0` before any run and equals the **exact** number of interpreted instructions in the slice, `reset_reductions()` returns the discarded count and zeroes it, and a host `ExecutionContext` that overrides the defaulted `reduce(n)` hook records one charge per instruction (`n == 1`) and can PRE-EMPT the loop by returning its own typed error (asserted to fire after exactly N charges, with the run returning that error). A suspended `receive` charges its `wait` once and the resume starts a **fresh** slice, so no instruction is charged twice; `MinimalContext` keeps the no-op default while still counting.
- **Parked-receive deadline & `recv_marker_*` rejection** (`tests/wait_deadline.rs`, 10 tests): the `after T` shapes the compiler emits (`loop_rec Fail, Dst … Fail: wait_timeout ScanLabel, Time; timeout`): `Machine::wait_deadline` returns `Some(WaitDeadline { delay_ms: Some(20), resume: (func, pc+1) })` for `Operand::Integer(20)` (asserting `resume` is really the `timeout` instruction), reads a **Y-register** delay through the public `Machine::y`/`y_mut` (`delay_ms: Some(20)`), yields `delay_ms: None` (but a usable `resume`) for an `infinity`/non-integer delay, and is `None` for a bare `Wait` (`after infinity`) and before any run — while `wait_timeout` with the small-int `0` **falls through** to the `timeout` instruction (no suspend, C's `$NEXT0()` path). Plus the named marker rejection: every `recv_marker_*` opcode on a host that does not serve markers is the typed `unsupported_opcode: recv_marker_<op>: the host does not serve receive markers` (never a hang, never a silently skipped marker), a marker-capable host's own error survives verbatim, and a successful marker call leaves the register written and the run continuing.

- `tests/gc_roots.rs` -- the **root-set hand-off** (8 tests). A synthetic `gcroots_wait/0` (`allocate 2; Y0 = 0x1234; wait`) is suspended through `run_export_outcome` so the machine really has a live frame, then an `alloc_words`-only loop drives `Machine::alloc_rooted`: a mock context implementing `alloc_words_rooted` asserts the hook fires **once per allocation** and receives the machine's register slices and whole stack with the live `x(3)`/`fr(7)`/`Y(0)` values in them, and that the mutable slices write **back into the machine**.
