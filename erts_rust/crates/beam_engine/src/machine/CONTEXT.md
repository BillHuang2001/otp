# `beam_engine` — Machine state core (`src/machine/`)

## Intent
The process-state core of the Stage-1 engine: the register files, the Erlang stack, the call-frame and catch-frame stacks, the module-context registry, the run entries, and `Machine::drive` — the module-context-aware **dispatch loop that IS the interpreter's hot loop** (the `run_loop*` entries in `../interpreter/dispatch.rs` are thin wrappers over it).
Binding execution semantics and the frozen seams are one level up (`../CONTEXT.md`); per-opcode semantics are in `../INSTRUCTION_SURFACE.md`. This file owns what the **machine holds** and what a change to its state must not break.

## The `Machine`: state and ownership
- **Owned state.** the x-register file (`MAX_REGISTER = 1024`, C's `MAX_REG`), the float-register (FR) file (`MAX_FLOAT_REGISTER = 1024`, holding **`Eterm` term slots**), the Erlang stack, the call-frame stack, the exception catch-frame stack, the `refc_binaries` payload reservoir, the `writable_payloads` registry, the module-context registry plus the per-machine label-map cache and the per-context local-call verdict tables, the decoded literal-area binding, the reduction counter, the raise-time snapshot, the raise latches, the exception class atoms, the prepared-bitstring-program entry table, and three latched per-run gates (`trace_on`, `bif_in_machine_on`, `census_on`).
- **No process heap.** every `alloc_words`/`alloc_words_rooted`/`ensure_heap*` call allocates into the caller's `ExecutionContext` (`MinimalContext.heap: ContextHeap` here, `beam_rt`'s collector in production); the machine's non-term storage is `Arc<Module>`/`Arc<LiteralArea>` handles plus `Vec`s of words.
- **No `impl Drop for Machine`** (the crate's only `Drop` is `jit::emitter::CodeBuffer`): dropping a machine drops the `RefcBinary` handles, each freeing its payload only when it was the last reference (`beam_alloc/src/binary.rs`); `writable_payloads` is `(usize, usize)` metadata that frees nothing. `Machine::reset` frees no heap word and no payload, so a returned `Eterm` outlives a run but never outlives the `ExecutionContext` whose heap built it.
- **Nothing is ever released or shrunk.** the register/FR files are `NIL`-refilled over their *used extent* only (never `truncate`d, never reallocated once the length matches); `stack`/`frames`/`catch_frames`/`raise_snapshot`/`args_scratch`/`refc_binaries`/`writable_payloads`/the label-map entries all use `clear`/`truncate`/`pop`, which **keep capacity**, and no `shrink_to_fit`/`shrink_to`/`reserve_exact` exists anywhere in the crate — a machine's resident footprint is the high-water mark of the heaviest run it has executed, freed only by dropping the machine. `Machine::new` allocates both 1024-word register files (8 KiB each) eagerly.
- **The call/return path allocates nothing and looks nothing up.** the three buffers are reserved up front (`STACK_RESERVE_WORDS = 256`, `FRAMES_RESERVE = 256`, `CATCH_FRAMES_RESERVE = 8`, via `Vec::with_capacity` in `Machine::with_max_register`), so frame push/pop — every non-tail call on every tier — stays off `RawVec`'s growth arm; `reset` only clears them, so a deeper run's capacity survives. `push_frame_window(y_count)` hands back the frame base and the new Y window in one step; `pop_frame_checked` reads the frame top once (`Frame` is `Copy`, so the mismatched-`y_count` cold arm restores the identical frame); the executing `(func, pc)` is one packed `u64`. The floors are deliberately modest, so a deep recursion or a nested-`try` storm still grows by the usual doubling.
- **A nested run on the same machine is destructive**: `run_label_outcome` calls `reset()` and nothing saves the outer frame; `resume_outcome`/`run_loop` is the only state-preserving entry (no re-entrancy guard exists).

## The root-set contract (`with_roots` · `alloc_rooted` · `for_each_root{,_mut}`)
**The hardest invariant.** `RootSet { x, stack, fr, live }` = `x[0..used_x_extent()]` + **the WHOLE Erlang stack** + `fr[..used_fr_extent()]`. **There are no frame liveness maps**, so every Y slot of every live frame is a root, always.
- **One hand-off body.** `Machine::with_roots(live, f)` is the single root hand-off behind `alloc_rooted` (→ `ExecutionContext::alloc_words_rooted`) and `ensure_heap` (→ `ensure_heap_full`), hence behind every term-allocation and heap-admission door on every tier.
- **The width rule.** the handed prefix is `used_x_extent()`/`used_fr_extent()` = `max(mark, dirty)` clamped to the file length — never `RootSet::live`, which is a **hint only** (`live_len()` clamps it; `ALL_LIVE` is always safe). Soundness holds only while **every** writer reports: `set_x`/`set_fr` raise `mark`, `x_mut`/`fr_mut`/`with_roots` raise `dirty`, and the native driver notes the artifact's `CompiledModule::native_write_extent` **before** the block runs. Every slot at or beyond the extent is `NIL`, so it holds no term; that invariant — not a host promise — is what bounds the next `reset`. An under-reported extent leaves a live register unrooted, which surfaces as a stale word dereferenced later, not as a collector error.
- **`LOOSE_HEAP_TERMS = 5`.** the machine holds five heap terms the frozen `RootSet` cannot carry, in this fixed order: `raise_function_clause_args`, `pending_function_clause_args`, `pending_exception`'s reason, `pending_supplied_term`, `raise_supplied_term`. `with_roots` **parks** whichever are armed at the stack tail for the hand-off and **re-seats** each field from the slot the host wrote back, then truncates — unconditionally, so an `Err` out of the closure re-seats too (no `?` sits between the push and the truncate). A `None` read-back leaves its field untouched. With none armed the `RootSet` is handed over **unmodified** (the fast path). `Machine::loose_heap_terms`/`seat_loose_heap_terms` plus `with_parked_loose_terms` are the one place a future loose field is added.
- **Parking is unconditional**, even for an immediate reason no collector can move — one uniform rule instead of a tag test at the door. Consequence: the no-loose-term fast path is unavailable for the rest of a run that has caught an exception (`pending_exception` is cleared only by `reset`/the next raise); gate the reason slot on `beam_term::is_immediate` if a measurement ever shows that cost.
- **`pending_exception`'s reason is parked**, so a word a host reads from the field has already been relocated by every preceding collection — which is what makes `beam_rt`'s park publication (`Registers::extra_roots`, read back through `Machine::pending_exception_mut`) and `families::bitstrings::raw::payload_aliased_elsewhere` safe by construction. The reason is retained past landing (C clears `c_p->fvalue`), sound only because it stays rooted here.
- **Host round-trip invariant (publish at a park → scatter at the resume).** `roots.stack.len()` is `machine.stack.len() + armed_loose_terms`, and `armed_loose_terms` is **0..=5 and state-dependent**; nothing inside the engine mutates `x`/`stack`/the arm set while the machine is parked, so a publish/scatter pair is length-correct only while nothing touched the machine in between (no instruction, no raise landing, no `reset`). A host cannot compute that count (`loose_heap_terms`/`LOOSE_HEAP_TERMS`/the clause latches are private, and `stack_depth()` is unreachable inside the closure) and `roots.x.len()`/`roots.fr.len()` can only **grow** between the two calls — so round-trip `roots.stack` verbatim, record the published lengths, and treat a length mismatch as a contract violation, never as a licence to keep words the collector left stale.
- **A failed scatter is a dangling machine, not a refusal.** a width mismatch makes the host halt the process's future collections and resume anyway, while the from-space is already evacuated, so every `x`/`stack` word names freed memory and the first `terms::cons_head`/`get_list` on it faults inside `beam_term::list::car`. The engine contributes the width rule; turning it into an error is the host node's decision (`beam_rt`'s `resync_parked_roots`).
- **Two enumeration doors, one parking implementation.** `Machine::for_each_root(&self, impl FnMut(Eterm))` is the read-only census — exactly the pointer-bearing words of the hand-off, every `IMMED1` skipped by `beam_term::primary_tag`; `Machine::for_each_root_mut(&mut self, &mut impl FnMut(&mut [Eterm]) -> Result<()>)` is its relocating twin and IS one `with_roots` hand-off (same extents, same parking), visiting the `RootSet`'s three **disjoint** slices one at a time so the visitor cannot alias one root file while handed another. Both exclude `args_scratch`. Its error path is the parking's: the walk stops at the failing slice, the stack is truncated and all five fields re-seated, and only then does the visitor's `Err` travel on. A visitor may rewrite every word, so it must leave a `TAG_LITERAL_PTR` word alone and must treat every term as re-read afterwards (a raw `*mut Eterm` from before the visit is dead).
- **`args_scratch` is the one term vector that is not a root** — `mem::take`n out of the machine for the whole wide BIF dispatch (and for `trace_call`), hence invisible to both doors. That is sound only because the window **cannot collect**, and structurally so: `Machine::dispatch_bif_call` takes `&self` while both rooted doors take `&mut self` plus *this* machine's root slices, so the borrow checker forbids crossing one mid-window, and the marshalling's only heap door is the non-collecting `alloc_words`. Break any of those three legs and the argument words must be rooted. The buffer is reinstated **empty** on every exit path (no `?` between the take and the reinstall).
- **Nothing else stores a heap word.** `class_atoms: [Eterm; 3]` are atom **immediates**; CP slots are `Continuation::Address { context, func, pc }`/`Halt`; the raise snapshot and the resumption lists are `(u32, u32, u32)`; contexts hold `Arc<Module>`/`Arc<LabelMap>`; label-map keys are a digest + atom snapshot + address; verdict slots are `Cell<Verdict>`; and `RunOutcome` carries one returned `Eterm` plus `u32` addresses, so a park/resume window holds no term outside the registers/stack/FR file.

## API Surface (crate-internal; methods on `impl Machine`)
- **Registers & root set** (`registers.rs`): `x`/`x_mut`/`set_x`, `get_fr`/`set_fr`/`fr_mut` (bounds-checked → `bad_register`), `fr_mark()` (the live leading FR-slot count, the FR twin of the `x[0..live)` bound), `used_x_extent`/`used_fr_extent`, `stack_mut`, `with_roots`, `alloc_rooted`, `for_each_root`/`for_each_root_mut`, `register_count()`, `reset`.
- **Frames & continuation** (`frames.rs`): `push_frame`/`push_frame_window`, `pop_frame`/`pop_frame_checked`, `allocate*`/`deallocate*`/`trim`, the typed `Continuation` CP slot (`continuation` read-only, `take_continuation` read-and-clear, `set_continuation` write), `ensure_heap`, `resumption_contexts`/`resumption_addresses`/`raise_snapshot`.
- **Run entries** (`run.rs`): `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome`, plus the tier-aware `run_with_tier`/`run_export_outcome_with_tier`/`run_label_outcome_with_tier`/`resume_outcome_with_tier` (a slice that suspended on a native tier resumes on it; `Cranelift` is a typed error). `RunOutcome { Returned(Eterm), Wait { func, pc }, Suspend { func, pc } }` is re-exported at the crate root and matched **exhaustively** cross-crate (`beam_rt/src/boot/drive.rs`, `beam_rt/src/runner/run.rs`); there is no yield/pre-emption variant. `fold_outcome` is the non-blocking entries' single fold — `Wait` → `error::blocked()`, `Suspend` → `error::suspended()`. `run_export` resolves the export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return` and yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error.
- **Position & introspection** (`location.rs`): `current_code`/`current_function`/`current_location`/`current_stacktrace`/`current_module`/`active_context`/`initial_call`/`entry_call`, `wait_deadline`/`timeout_delay` (+ `WaitDeadline { delay_ms, resume }`), `y(k)`/`frame_depth()`/`stack_depth()`/`catch_frame_depth()`, `pending_exception()`/`pending_exception_mut()`/`pending_class()`, `raise_snapshot()`, `reductions()`/`reset_reductions()` — the engine half of `process_info/2`. The position is **one packed `u64`** (`func << 32 | pc`; `CURRENT_CODE_NONE = u64::MAX`, with a `func == u32::MAX` sentinel), so `set_current_code` is a single store and every reader goes through the unpacker.
- **`wait_deadline`** reads the `wait_timeout` at `current_code` (exact, because a blocking op is never JIT-inlined) in the module `active_context()` names — the callee's own module when the park is inside a cross-module callee, else the passed entry module — and reports the `timeout` continuation (`pc + 1`) the host re-enters when its own timer fires. `timeout_delay` accepts every operand shape the compiled `wait_timeout` can carry: an `Integer`/`Literal` delay, an `X`/`Y` register, and an `Operand::Typed { reg, .. }` unwrapped to its `X`/`Y` register (the annotation is a compiler hint, not a heap type). The engine arms no timer: a non-zero `wait_timeout` just suspends.
- **Contexts & verdicts** (`context.rs`, `local_callee.rs`): `current_context`/`register_context`/`switch_context`/`module_context`, `verdict_table`/`bind_entry_verdicts`/`invalidate_local_call_verdicts`.
- **Off-heap seams** (`mod.rs`, `offheap.rs`): `alloc_refc_binary`/`alloc_refc_binary_with_capacity`, `refc_binaries()`, `off_heap_overhead_bytes()`, `retain_refc_binaries(keep)`, `mark_writable`/`writable_capacity`/`writable_payload_count`/`grow_writable_payload`.
- **Bitstring programs** (`mod.rs`): `with_bitstr_programs` (the single hand-over seam) and `bind_entry_programs` (the run-boundary retention rule).

## The raise funnel, catch frames and the raise latches (`catch.rs`)
`throw`/`throw_error`/`throw_with_trace` are the raise/unwind entries the families call; `Machine::with_uncaught_frames` is the funnel's second half at the run boundary.
- **The snapshot is rebuilt before any unwind.** `throw_with_trace` records `raise_snapshot: Vec<(u32, u32, u32)>` — the **raising** frame from `current_code`/`current_context`, then every live caller from `resumption_contexts`, each in its own module context — before any unwind and before the early no-live-frame `Err(BeamError::Raise)` return, so the pre-unwind chain survives on the caught and the uncaught path alike. It is the engine's replacement for C's saved raw `StackTrace` (`c_p->ftrace`).
- **Two one-shot/live latch pairs, promoted at the landing.** `pending_function_clause_args` (armed by the raise site, so a propelling `Err` cannot leave a stale list) → `raise_function_clause_args` (the live state, consumed exactly once by the cooked-trace builders); `pending_supplied_trace: Option<StackTrace>` (armed only for **non-empty** symbolic frames — the `erlang:raise/3` trace-list shape) → `raise_supplied_trace`. A raise carrying no clause list clears the live one, so no later trace inherits a stale list.
- **A supplied trace is preserved; a derived one is built here.** The snapshot rebuild runs only when the raise supplied **neither** flavour: a supplied symbolic trace renders its own frames, and a supplied **term** (`pending_supplied_term` → `raise_supplied_term`, armed by `Machine::raise_supplied`, which `Instr::RawRaise` calls — the shape `sys_core_fold` folds `catch C:R:S -> erlang:raise(C,R,S)` into) renders the preserved chain of the raise being re-raised, so rebuilding would replace it with a re-raise-site chain (C's `raw_raise` stores the supplied trace and clears `EXF_SAVETRACE`). The supplied term is consumed exactly once: a **landed** raise publishes it as the handler's `x(2)`, an **uncaught** one renders it in `with_uncaught_frames`.
- **Landing clears the landing frame's continuation slot** (`set_continuation(Continuation::Halt)`), because the handler runs *in* that frame, which is therefore no longer suspended in the call that raised (C's `next_catch` drops the frames above the catch frame for the same reason).
- **The rooted read is split around the reservation.** `symbolic_stacktrace` makes one rooted reservation, so the clause list has a **read** half (`live_raise_function_clause_args()`, before it — the sizing needs only the list's move-invariant length) and a **consuming** half (`take_raise_function_clause_args()`, after it — the reservation may have moved the list, and `with_roots` re-seats the field); the re-seated list goes to the first frame's `A` slot, every outer frame keeps its declared arity, and the elements are carved **inside** the reservation, so no element word is held across a collection. `take_raise_supplied_trace()`/`take_raise_supplied_term()` are the same halves for their latches — the term latch's consumer is not `symbolic_stacktrace` (which returns an already-cooked list from the trace register verbatim, C's `is_raised_exc`) but the landed `x(2)` publication or the uncaught funnel.
- **`with_uncaught_frames` is the single attachment site for every raise kind**, called at the `step_instruction`/`drive` boundary, reporting the live supplied-symbolic latch if armed, else `snapshot_stacktrace` for the supplied-term case, else `raise_stacktrace`. It leaves a non-raise error, an already-framed raise and an **engine diagnostic** (a reason atom prefixed `unsupported_opcode: `, the `error::unsupported` sentinel) untouched.
- **`raise_stacktrace(entry_module, func, pc, first_frame_args)`** derives the symbolic frames (raising function, then every live caller innermost first), giving `first_frame_args` to the **raising** frame only.
- **Class atoms resolve through the live namespace.** `ensure_class_atoms(ctx, module)` resolves every still-unresolved `error`/`exit`/`throw` atom via the free `namespace_atom(ctx, module, name)` — `ctx.atoms(module)` (the host's live namespace seam) first, the module's load-time snapshot second, `None` if neither knows it — and installs it with `set_class_atom`; an installed atom is never overwritten, and the per-run `class_atoms_live` latch (cleared by `reset`) makes the body one `bool` test in steady state. `Machine::class_atom` answers the typed `unsupported("exceptions: no atom for the '<class>' exception class …")` — **never a substituted atom**. The `atoms` borrow is immutable and ends at the copied `Atom`, so the next `&mut ctx` call may follow immediately.

## A frame's continuation slot is consumed by whoever follows it
`Machine::take_continuation` is the **one** read-and-clear: it reads the current frame's `Continuation` slot and resets it to `Continuation::Halt` in the same step (C's `RETURN()` does `SET_I(cp_val(*E)); *E = NIL`). A slot means exactly one thing — *this frame is suspended inside a call and resumes at that address when the call returns* — so every reader may treat a non-`Halt` slot as a **live** caller.
- **Consumers** (each a `take_continuation` call site): `return_step` (`../interpreter/dispatch.rs`, the `return`/`deallocate_return` arm), `Machine::continuation_step` (`drive.rs`, the `Step` protocol's follow), and `jit_return`/`jit_deallocate_return` (`../jit/baseline/runtime.rs`, the native tier's twins).
- **A raise landing in a frame's catch handler clears that frame's slot too** (`throw_with_trace` ends its landing with `set_continuation(Continuation::Halt)`).
- **Read-only readers never reset it**: `continuation()` (test-only view), `resumption_contexts`/`resumption_addresses`, `raise_stacktrace`/`snapshot_stacktrace`, `current_stacktrace`.
- **Writers** arm it through `set_continuation`: `Instr::Call`, `call_ext*`, the `Apply*`/`call_fun` arms, and the baseline tier's `store_continuation` (`../jit/baseline/call.rs`). Consequence: a caller that already returned is never named a second time, so a derived stacktrace names the raising function once and thereafter only its live callers (C's `gather_stacktrace` likewise admits only words that still look like a CP).

## Module contexts (`context.rs`)
A `call_ext*` the host resolved through `resolve_external_call` executes the callee **in this machine**, so `(func, pc)` become indices into *another* module's table and the machine must remember which. `Contexts` registers/dedups a `ModuleContext { module: Arc<Module>, labels }` by `Arc::ptr_eq`; context `0` is the run's **entry** module, which the machine never owns (`entry_literals` records its literal area). `switch_context(id)` re-binds the literal area, and an unregistered id is the typed `error::unsupported`. `reset` clears the set; a **resume does not** (a suspended cross-module frame must still name its module). `Step::Enter` is the only way a run changes module context — all three producers switch at the driver: a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address` in another context, and a raise landing in another context's live catch frame. The native tier does it as a **driver-mediated round-trip** by design: a resolved transfer is not in the JIT inline set, so the block deopts one step, that step returns the `ENTER` block-ABI word, and the driver switches context and re-enters the callee's compiled blocks; a seal-time cross-module *link* is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`).

## The local-call verdict memo (`local_callee.rs`)
All five call sites (the interpreter's three local-call arms and the baseline tier's two helpers) route through `Machine::local_call_seam` (`../interpreter/dispatch.rs`), which consults `ExecutionContext::resolve_local_call`. What belongs to **this** node is the verdict table.
- **Memoized per callee function index, for the life of a run.** `Machine::verdict_table` resolves the executing context's `LocalVerdicts` (context `0` uses the machine-owned `Machine::entry_verdicts`), whose `Cell<Verdict>` slots are addressed **directly by the callee's function index** and sized to `module.functions.len()`. A repeat local call is one bounds-checked slot load and **no** host call; only `Verdict::Unknown` pays the out-of-line work (derive the callee's `(module, function, arity)` identity — a `Vec` index plus two `module.atom_name(..)`, no hash and no clone — ask, record).
- **Index-addressed, not a search**, because the slot a callee uses is a property of the *callee*, not of the call history: an alternating two-callee loop costs exactly what a single-callee loop costs, and nothing on the hot path branches on the previous call.
- **`Verdict`** is `Unknown` (no verdict, or no slot: the only answer that cannot fabricate one) / `Unnameable` (no function entry or an unresolvable name atom — the host is asked **zero** times) / `Served` / `Declined` (the host's earlier `false`: enter the callee in this machine). It is `#[repr(u8)]` with `Declined = 0`, `Unnameable = 1`, `Served = 2`, `Unknown = 3`, so the per-call test `enters_in_machine` is a range compare `(self as u8) < FIRST_NOT_IN_MACHINE` folded into the slot read (a missing slot answers `false`, i.e. ask the host); that ordering is pinned by `enters_in_machine_is_the_low_discriminant_range` and the folded read against the full read by `the_folded_slot_read_agrees_with_the_full_read`.
- **Caching the verdict is the faithful choice, not a shortcut.** the host predicate is a pure function of the triple (for `beam_rt`: `prim_tty`'s stubs plus `beam_bifs`' `zlib` table) and ERTS charges **nothing** for an intra-module call, so a per-call consultation would spend a reduction unit the oracle never charges.
- **Three invalidation doors; invalidation re-asks but re-derives nothing** (an identity is a pure function of an immutable module image and cannot go stale). An *installation* is the only thing that can change an answer: `erlang:load_nif/2` **arms** `Machine::local_call_invalidation_pending` (`Cell<bool>`, so the `&self` dispatch funnel keeps its receiver) at the one BIF funnel, gated on the `("erlang","load_nif",2)` triple (one arity compare on the cold path), and the seam clears every context's verdicts at its **next** local call; `Machine::reset` clears every table, `entry_verdicts` and the flag; and the public `Machine::invalidate_local_call_verdicts` is the door for a host whose answer set changes by any other means. Only verdicts are cleared — an `Unnameable` callee keeps its verdict.
- **A verdict must never reach compiled code.** `JitBackend::compile` is handed no `ExecutionContext` and the cross-run `CodeCache` is content-keyed and shared across runs, machines and hosts, so the memo is legitimate strictly as a **per-machine, per-run, invalidatable** cache.

## The label-map cache (`label_cache.rs`)
`build_label_map` is a whole-module value (one traversal per function plus the module's entire import table) and a pure function of the module's immutable content, so `Machine::label_map(&mut self, &Module)` / `label_map_arc(&mut self, &Arc<Module>)` answer a cached `Arc<LabelMap>` and build only on a miss; the map itself (a dense `Vec<Option<(func, pc)>>` of `Slots::{Dense, Sparse}`, plus the resolved import targets) is `../interpreter/CONTEXT.md`'s.
- **The key is identity, never content**: `Module::checksum()`'s `Digest` + `Module::atom_table`'s `AtomSnapshot` + the module address. The digest covers exactly the chunks the map derives from (`Code` label slots, `AtU8`/`ImpT` imports), the atom snapshot witnesses the namespace the import *names* were resolved against, and the address is what `LabelMap::imports_owner` checks — so a hit is byte-identical to a fresh build and the key may hold nothing runtime-mutable.
- **A bounded LRU**: `LABEL_MAP_CAPACITY` (32) `Entry { key, held, map, stamp }` in a `Vec`; `stamp` is a monotone use counter, a hit bumps it **in place** (the `Vec` is never reordered — a move-to-front would memmove up to `capacity` entries per probe), and a miss inserts as most-recently-used and evicts the smallest stamp with `swap_remove`, so only the eviction path scans. An eviction is only a performance event: the next probe rebuilds the identical map, never serves a stale one. Retention is bounded by `capacity × live machines`.
- **Route rules.** a synthetic image (all-zero checksum) is **never cached**; a second load of one `.beam` and a `Module::clone` each mint a fresh atom-table identity and so are a **miss** (one extra build, never a wrong map); the entries survive `Machine::reset`; the `Arc` route holds its handle so its address cannot be recycled, and a hit on a bare-route entry installs it.
- Pinned by `label_cache_tests.rs` over real `erlc` fixtures (the `interpreter::label_map_builds()` build tally, a second run of the same real module building none, an in-place replacement of a module's bytes) and by `label_cache.rs`'s own unit tests (key/route rules, the ABA case, the capacity-`C`-vs-1 alternation counts, eviction order, cached-vs-fresh equality over the whole label/import id range). Measured cost/saving: `../../MEASURED.md`.

## The prepared-bitstring-program entry table (`entry_programs`)
Compiled binary comprehensions re-enter a seam once per element, so the machine holds the prepared-program table for context `0` (`entry_programs: BitstrPrograms`) plus its image **witness** (`entry_programs_witness: Option<ProgramWitness>`), kept beside the table rather than inside it so a table and its provenance can never disagree.
- **`with_bitstr_programs`** is the single hand-over seam: it captures the context id **once**, `mem::replace`s the table out, runs the closure and files it back into the slot it came from — so the table a closure sees is the one that context already had (a missed file-back therefore shows up as a *re-prepare*, never as a wrong answer), an unregistered context gets a throwaway table that is dropped instead of filed back, and a nested run inside the closure cannot redirect the file-back.
- **`bind_entry_programs`** is the run-boundary retention rule: the table survives a `reset` only when the new run re-enters **the very image it was filled from** — same address, same content digest, same atom namespace (`ProgramWitness::describes`) — and never for a synthetic (all-zero-checksum) image; otherwise the table is cleared. Pinned by `program_tests.rs` through observable behaviour (a retained table answers the next execution; a re-prepare is the observable failure mode of a missed retention).

## The `refc_binaries` reservoir and its retention seam (`offheap.rs`)
`Machine::refc_binaries` is the machine's off-heap payload reservoir: it keeps every refc binary the machine built alive and address-stable, and `reset` never clears it (a returned term may still name a payload after the run that built it). Reclamation is therefore a **host** decision taken after a reachability sweep over the process roots, exposed as two infallible, allocation-free `pub` methods:
- `off_heap_overhead_bytes() -> usize` — the reservoir's **backing-store** bytes, the sum of `beam_alloc::RefcBinary::reserved_bytes()` over the handles. The reservation (not `len()`) is what a host charges for, matching `beam_gc::sweep_unreachable_binaries`/`beam_gc::BinVheap` accounting: an exactly-sized payload has `len() == capacity() == reserved_bytes()`, while a `bs_init_writable` accumulator holds a 4× reservation whose spare room is real memory. The consumer is words-based, so the host converts with `bytes / size_of::<Eterm>()` and compares against `beam_gc::BinVheap::triggered`'s floor.
- `retain_refc_binaries(keep: FnMut(*const u8) -> bool) -> usize` — drops every handle whose payload data pointer the predicate rejects, returning the number **released** (a released handle frees bytes only when it was the last one). `Vec::retain` never moves a payload, so retained payloads keep their exact `data_ptr` and compaction never invalidates a live `BinRef.val` (the frozen `beam_term::refc` contract); payloads are always found by `data_ptr` search, so the compaction is invisible to the writable doors. The same call prunes `writable_payloads` in lockstep.
- **The predicate is the caller's soundness assertion** — the engine cannot verify it, because the reservoir holds handles, not roots. A false reject frees a payload a live term still names (a dangling `BinRef.val`); a false accept is merely a leak. The intended use is `beam_gc::for_each_reachable_binary_payload`'s reachable set, after first **cloning** the handles the host keeps beyond the machine (the clone bumps the refcount, so the payload survives the drop).
- Engine-built refc binaries reach the host as a **handle, never as raw memory**: `families::bitstrings::raw::{make_writable, make_binary}` build the frozen 8-word `[BinRef][ErlSubBits]` pair and push each payload handle here, and the `send` arm plus the `erlang:send/2` special case hand the in-flight slice over through `send_message_with_off_heap`, so an engine-built refc binary survives both a return and a send. `refc_binaries()` is the read-only handle view a host clones into a copy's source off-heap table.

## The `writable_payloads` registry (`mod.rs`)
A side list of `(payload base, capacity in bytes)` for the off-heap payloads this machine allocated **for appending** (`bs_init_writable`'s backing store, C's `BIN_FLAG_WRITABLE` binary), deposited by `mark_writable(base, capacity)` and queried by `writable_capacity(base) -> Option<usize>` (a linear scan, newest entry preferred; no BEAM-heap allocation). The capacity recorded is the payload's **real** one, read back from its control header (`alloc_refc_binary_with_capacity`, a 4× `DEFAULT_RESERVATION_FACTOR` reservation), never the `bs_init_writable` hint — the frozen term layout carries no capacity word, so the capacity has to live beside the machine, and keying it per machine gives C's `erts_pin_writable_binary` property for free (a payload another process's copy points at is not in *this* list, so it is never written in place here).
- **Only `mark_writable` entries are writable**: an ordinary binary's payload length is never taken as a capacity (`refc_binaries` is *not* consulted). The list is never cleared by `reset` — a registry entry must never outlive the payload it names — and is pruned only by `retain_refc_binaries`, in the same call that releases the handle, so a lookup can never answer with a freed block's address or a stale capacity. `writable_payload_count()` reports the live registrations.
- **`grow_writable_payload(base, wanted_bytes)`** is the one widening door (`RefcBinary::ensure_capacity`, C's `GROW_PROC_BIN_SIZE` schedule) and it re-keys (`rekey_writable`) before returning: an `InPlace` outcome moves only the cached capacity, a `Moved` outcome moves the key to `PayloadRelocation::to` so a stale key can never answer for the freed block, and both restore the `len == capacity` handle invariant through `cover_writable_capacity` (C's `bin_size`; a relocation copies exactly `len()` bytes, so this is what keeps the appender's bytes alive). Every refusal — unregistered payload, shared handle, the `max_capacity` cap — folds into `Ok(None)` (the caller promotes to the copy-rebuild form), because each is a runtime condition with a correct fallback, not an internal fault. Republishing the two payload-naming words (`BinRef.val`, `ErlSubBits.base_flags`) over a moved base is the *caller's* job (`raw::InPlace::grow`): this door is safe Rust and never dereferences a term. It is consulted only on a shortfall.
- **A payload another party shares can no longer grow**: `beam_alloc`'s mutators refuse unless `refcount() == 1`, and `beam_rt`'s `adopt_escaped_binaries` clones every handle of a finished machine into its escaped-payload store, so a writable accumulator that survives a run boundary has `refcount() >= 2` and any later growth falls back to the copy-rebuild form (byte-correct, amortisation lost). An accumulator whose whole loop stays inside one run keeps growing.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only — no crate-local error enum, no panic, no `unwrap()` on runtime data; an unsupported opcode/operand/operand-shape is the documented `error::unsupported`, never a wrong result.
- Frozen term layout: `Machine` never reimplements term layout, ordering or hashing — construction/inspection go through `beam_term`, comparison through `beam_term::{cmp, eq, cmp_arith}`.
- The root-set contract above is binding: a change to any `Eterm`-typed `Machine` field must either be inside `x`/`fr`/`stack`, be one of the five parked loose terms, or be provably immediate/off-heap.
- `unsafe` only where the crate `CONTEXT.md` marks it, each block behind a `// SAFETY:` rationale.
- Files ~1000 lines, split by responsibility; a legitimately long file documents why.

## Test Strategy
Per-module `#[cfg(test)]` unit tests beside the code they cover; the cross-cutting integration suites live in the sibling node `../tests/` (`CONTEXT.md` there, enumeration in `../../TEST_NOTES.md`).
- Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --no-fail-fast` (green, warning-free), then the same with `--workspace`.
- Unit-test ownership: `tests.rs` (the end-to-end raise funnel — one synthetic module per raise kind, each asserting the propagated frames innermost-first, plus the caught-raise guard — and the local-call memo against a counting host), `root_tests.rs` (both enumeration doors' coverage, the immediate filter, their **parity** — a change to one door not mirrored in the other fails here — and the loose-term re-seating incl. the error path), `deadline_tests.rs` (the parked-`receive` deadline driven to completion on a real `erlc` module, cross-checked against `erl`, plus the cross-module-callee park), `label_cache_tests.rs`, `program_tests.rs`, `test_support.rs` (test-only `Fixture` synthetic-module builder and the cross-module `seam` context shared by `drive.rs`'s and `tests.rs`'s suites).
- Suites needing the system toolchain **skip loudly** when `erlc`/`erl` are absent: a green run without them proves nothing about oracle parity.

## Notes for Agents
- **`reset` is logical and only at a slice START.** `registers.rs`'s `Machine::reset` clears the register files (refilled with `NIL` over their used extent), `stack`, `frames`, `catch_frames`, the contexts (each registered context owns its module's verdict table), `entry_verdicts` and the pending-invalidation flag — the verdicts belong to the run that filled them, so a fresh run asks the host again — the raise snapshot, the pending exception, all four raise latch pairs, the exception-class atoms plus `class_atoms_live`, the execution-position fields and the trace/reduce gates. It does **not** clear `refc_binaries`, `writable_payloads`, the label-map cache, or `bif_in_machine_on` (latched per run by both drivers; only `Machine::new` ever sets it). The two off-heap rosters are released only by a host call to `retain_refc_binaries`. A **resume** resets nothing, so the contexts and the raise snapshot survive it.
- **`Machine::drive` owns the position** and folds every `Step` back into it, charging exactly one reduction per interpreted instruction **before** the instruction's effect through the defaulted `ExecutionContext::reduce`; it latches `bif_in_machine_on`, threads the run's entry module (context `0`) down to the one BIF funnel, re-binds the literal area exactly on a `Step::Enter` into a different context, folds the two parks (`Step::Wait` → `RunOutcome::Wait`, `Step::Suspend` → `RunOutcome::Suspend`, the un-applied BIF instruction re-executed on resume), and runs the raise funnel's second half over a raise that surfaced inside a cross-module callee. The native tier's driver charges the same hook once per **block entry** instead; both the charge contract and the pre-emption/parking rules are `../CONTEXT.md`'s.
- **Cross-node hazard, not this node's to fix:** a host that publishes the machine's roots into a process `Registers`, collects, and then re-publishes from `with_roots` again overwrites the relocated words with pre-collection ones (`with_roots` re-derives from `self.x`/`self.stack`, which no collection has touched while the machine is parked). Any such sequence must `resync` from the process root set first — `beam_rt`'s `resync_parked_roots` and the park/publish/resume protocol in `beam_rt/src/runner/CONTEXT.md`.
- A verdict, a rooting decision, or an inline-set shape may never be derived from ambient state at compile time (see the memo and `../jit/baseline/inlineset/CONTEXT.md`).
