# `beam_engine::families::bitstrings` — the bitstring / binary-syntax family

## Intent
Executes the whole `Bs*` opcode family of the frozen `beam_loader` IR: match entry, the match reads, the `bs_match` command interpreter, position ops, and construction (`bs_init_writable` / `bs_create_bin`).
Ground truth (read-only, never modify): `../../../../../../erts/emulator/beam/emu/bs_instrs.tab` (instruction bodies), `../../../../../../erts/emulator/beam/emu/generators.tab` + `macros.tab` (the generator macros, incl. `$NativeEndian` and `$FAIL_HEAD_OR_BODY`) and `../../../../../../erts/emulator/beam/erl_bits.c` (the `erts_bs_*` primitives).
The shared failure/label/operand helpers and the safe MSB-first bit arithmetic live in `mod.rs`.
The construction half's own node is `create/CONTEXT.md`; the matching half has no child `CONTEXT.md` and is described here.

## API Surface

### The family entry, its variant set, the result reader
- `mod.rs::exec` is **the only entry**: the router (`families::dispatch`) dispatches to it and the native baseline tier's `jit_bitstr` calls it directly.
  It installs the `error`/`exit`/`throw` class-atom anchor itself (`Machine::ensure_class_atoms` against the live `ctx.atoms(module)` namespace), so a caller that bypasses the router still gets a raise that lands; on the routed path that is one `bool` load and a not-taken branch.
  `Ok(Some(step))` = executed, `Ok(None)` = not this family's variant, `Err` = it raised.
- `mod.rs::claimed(&Instr) -> bool` is the family's **single statement** of its 20 variants — `bs_start_match3`/`4`, `bs_get_position`, `bs_set_position`, `bs_get_tail`, `bs_test_tail2`, `bs_get_integer2`, `bs_get_binary2`, `bs_skip_bits2`, `bs_match`, `bs_match_string`, `bs_get_float2`, `bs_get_utf8`/`16`/`32`, `bs_skip_utf8`/`16`/`32`, `bs_init_writable`, `bs_create_bin`.
  The router's arm, the tier's emitted arm (`jit/baseline/emit/block.rs`) and `jit_bitstr` all share it, so the three cannot disagree about ownership; `exec`'s `Ok(None)` contract is the authority it is pinned against (`jit/baseline/bitstr_tests.rs`).
  The predicate is purely syntactic, which is what lets the native tier decide at compile time and skip the decision at execution time.
- `raw::bit_size(t) -> Option<usize>` is the host-facing `erlang:bit_size/1` reader: a heap bits/binary takes its `size` word, a refc window **and** an `ErlSubBits` match context take `end - start` (exactly `erts_bin_bits_size`), and a non-bitstring — including a bare off-heap `BinRef` no `bs_start_match` has wrapped — is `None`, never a substituted size.
  It exists because a BIF in this crate cannot reach the family's `pub(super)` readers; it is re-exported once from `mod.rs` (`pub(crate) use raw::bit_size;`) for the in-crate harness floor `src/bench/counting.rs`.
  Its `#[allow(dead_code)]` is load-bearing: that floor sits behind `#[cfg(test)] mod bench;`, so a plain `--lib` build would otherwise warn; the external test host `tests/support/bifs.rs` still cannot reach it (`families`/`bitstrings` are only `pub(crate)`).
- `mod.rs::exec_calls() -> u64` is a `#[cfg(test)]`-gated per-thread counter: it lets a test observe that the router actually sent an instruction here without re-deriving the router's table.

### The subject model
One frozen triple, `(base, size, off)`, from `raw::heap_bits`: the subject's bit `i` (`0 <= i < size`) is bit `off + i` of the byte payload at `base`.
`off` is `0` for an on-heap `ErlHeapBits` and the refc window's start modulo 8 for a refc binary (`beam_term::bitstring_parts`), so a window that does **not** start on a byte boundary is readable bit-exactly.
`raw::subject_bytes` returns `(base, off)` with a slice covering every window bit, and every bit reader threads `off` into its own window-relative index.
A match context is an `ErlSubBits` over an on-heap binary, built by `raw::make_ctx`; its `orig` word is the subject it reads.
The only subject refused is a match context or bare off-heap binary reference with no readable payload — the typed `unsupported("bitstring: subject is not a readable binary")`.

### A field's flags arrive in TWO shapes — both must resolve `native`
- The standalone `bs_get_integer2`/`bs_get_float2`/`bs_get_utf*`/`bs_skip_utf*` opcodes carry a **raw `u32` flags operand** (`beam_loader`'s `lower/instr.rs` decodes it with `as_u32`; `beam_asm:flag_to_bit/1` encodes `little` as `16#02` and `native` as `16#10`), so `BSF_NATIVE` is a **live** flag, not a flag-table placeholder.
- The `bs_match`-command / `bs_create_bin` segment route carries a **literal flag-atom list**, normalized by `mod.rs::flag_bit` (which maps the `native` atom to the target order, C's `$NativeEndian`).
`matching/reads.rs::field_is_little(flags)` is the **single** place that resolves both `BSF_LITTLE` and `BSF_NATIVE` (little on a little-endian target, big otherwise), and every field reader (`read_integer_field_tracked`, `read_wide_integer_field`, `read_float_field`, `decode_utf16`, `decode_utf32`) goes through it.
Testing `BSF_LITTLE` alone silently reads a `-native` field big-endian — a wrong value, which is the defect the rule prevents.

### `mod.rs` — helpers, the `BitWriter` sink, the hot/cold splits
`mod.rs` owns the shared `fail_step`/`goto_label`, the operand helpers (`read_size`, `is_all`, `decode_flags`/`flag_bit` + the `BSF_*` bits), the safe bit arithmetic (`read_uint_be`/`read_uint_le`/`sign_extend`/`extract_bits`), the wide-integer (`> 64` bit) byte model, and the two-mode `BitWriter` sink (`Dest::Vec` copy-rebuild / `Dest::InPlace` writable accumulator).
- `BitWriter::push_le_groups` is the **single** little-endian layout rule: the field is `value mod 2^nbits`, laid out as little-endian byte groups written MSB-first, whose final partial group is the LOW remaining bits of the last byte at the current bit position (C's `fmt_small_le`/`fmt_big_le` + `restore_and_shift`).
  `push_uint_le` (a `u64`-sized field) and `push_wide_int`'s little branch both delegate to it.
- **Whole-byte fast paths** serve the byte-wise shapes the compiler emits (a `<<C:8>>` match field, a `<<Acc/binary,C>>` accumulator), whose per-bit route costs a `push_bit`/bit read per bit: `push_uint`/`push_uint_le`/`push_le_groups`/`push_wide_int` take a byte-at-a-time arm when the width is a whole number of bytes **and** the destination is byte-aligned, and `read_uint_be`/`extract_bits` do the same on the read side.
  Every range/width check runs **first**, so an out-of-range field keeps the oracle's error.
  The bit-at-a-time rule stands for every non-aligned shape, because a mid-byte destination needs `raw::InPlace::push_bit`'s byte-window handling (clearing an entered byte, masking the one byte the accumulator's window ends inside).
- `read_size` and `decode_flags` are **hot/cold split**: an `#[inline(always)]` shell answers the shape the compiler actually emits and forwards everything else to an `#[inline(never)]` body (`read_size_slow` / `decode_flags_slow`), so the caller folds the decode into a discriminant test instead of paying a call plus a `Result` returned through memory.
  `read_size`'s shell classifies a literal `Operand::Integer`/`Operand::Character` through `size_of_int` (`<<V:8>>` *is* `Operand::Integer(8)`, and the general read would materialise an integer term only to read the same value back); a runtime `size(Expr)` register, a literal-area term and every reject case go to `read_size_slow`, whose reject is the `#[cold] size_error` both halves share.
  `decode_flags`'s shell answers **both** spellings of "no flags" with a plain zero: `Operand::Nil` (the `a,0` form `bs_create_bin` segment flags and `'=:='` carry) and an `Operand::Literal` whose literal-area entry is the empty list — the `{literal,[]}` the compiler emits for every `bs_match` field (`{integer,4,{literal,[]},6,1,{x,4}}`).
  The second resolves through `Module::literal` (no `Machine` needed), so a matched field pays one discriminant test, one bounds-checked literal-area read and a `NIL` compare instead of a call, a `Result` through memory plus a `list_elements` walk.
  A non-empty flag-atom list (`little`/`signed`/`native`), a literal index the module does not have (`flags literal index out of range`) and a literal that is not a proper list of flag atoms (`BadArg`) all keep the full `decode_flags_slow` body and its typed errors.
  `is_all`/`flag_bit`/`small_value`/`sign_extend` and the hot `BitWriter` methods carry `#[inline]`.

### `raw.rs` — the family's one raw-heap carve
`raw.rs` is the family's **single** `#[allow(unsafe_code)]` module (`run_tests.rs` carries a local allow for the frozen readers its harness builds terms with); every `unsafe` block carries a `// SAFETY:` rationale.
It contains only the frozen-header dereferences — the subject triple (`heap_bits`, `subject_bytes`), the match context (`ctx_parts`/`inner_orig`/`make_ctx`/`set_ctx_start`/`set_ctx_end`), the bignum readers (`make_big`/`big_parts_safe`), result materialisation (`make_bits`/`make_binary`/`make_writable`), the writable-payload machinery (`writable_append_target`, `InPlace{grow,push_bit,write_byte_field,into_bytes}`, `payload_aliased_elsewhere`, `republish_over`, `write_payload_bit`/`write_bit_field`).
All term layout is forwarded to `beam_term::{bitstring, refc}`; a match context's interior is never re-derived by hand here.
- `make_binary` is the **size-dispatching** result entry: at/below `beam_term::refc::ERL_ONHEAP_BINARY_LIMIT` (64) bytes it builds an on-heap `ErlHeapBits` (`make_bits`), above it the 8-word `[BinRef][ErlSubBits]` pair over a payload from `Machine::alloc_refc_binary` — the same threshold C picks from `ERL_ONHEAP_BITS_LIMIT`.
  Every **match result** binary (`bs_get_tail`, `bs_get_binary2`, the `bs_match` `binary`/`get_tail` commands) goes through it, so a result of any size gets the frozen representation the limits prescribe.
- `make_bits` zeroes the **whole** reserved data region (padding bytes of the last data word included) before copying the payload and then masks the trailing partial byte, matching `beam_term::bitstring::write_heap_bits`' invariant.
- `big_parts_safe` is the production safe bignum reader; `is_refc_binary` is its `#[cfg(test)]`-only safe twin, because the node's test modules live under the crate-wide `#![deny(unsafe_code)]` and cannot call `beam_term`'s `unsafe` predicates themselves — the single dereference stays in this marked module.
- `write_bit_field` shares `write_payload_bit` with `InPlace::push_bit`, so the construction seam's field write and the family's own writer cannot disagree about a byte — one definition of the rule in this node.

### `programs.rs` — the prepared bitstring program cache
`Program::{Generic, Create, Match}` for one `(function, code offset)` (`program_key`), reached through `BitstrPrograms::get_or_prepare`.
One table per **module context** (a `Module::clone` or a second load of the same `.beam` is a different table), machine-owned and never part of the cross-run compiled-block cache; the tables live in a `Vec` parallel to `Contexts::entries` plus `Machine::entry_programs` for context `0`, **not** inside the shared `ModuleContext` an instruction could only reach through an `Arc`.
The table reaches the family through the single seam `Machine::with_bitstr_programs`, which hands it over by value (`Contexts::take_programs` for a registered context, the machine's own field for `0`, a dropped throwaway for an unregistered one) and files it back into the **same** slot on every ordinary exit.
The context id is captured once, so a nested run inside the family cannot redirect the file-back, and both halves are plain struct moves: no `Arc` clone, no `RefCell` guard, no atomic.
`Machine::reset` keeps the entry table; `Machine::bind_entry_programs` (from `enter_run`) **retains** it only when the run re-enters the very image it was filled from — same address, same `Module::checksum` digest, same atom snapshot (`ProgramWitness::describes`) — and never for an all-zero-checksum (hand-built) image, so a batch host that recycles the machine re-prepares nothing.
`prepare` is consulted once per `(function, code offset)` and its answer filed; a shape it declines is `Program::Generic`.
A **synthetic** image (all-zero `Module::checksum`, the documented marker of no content identity) never caches a `Match` program — it freely re-uses `(0, 0)` for many different descriptor lists, so a hit on another instruction's program would be a wrong answer, not merely a slow one — and keeps the generic walk (`matching/prepared.rs`'s guard; the `Create` route has no such guard and relies on the same key property holding).

### The construction seam (`create/seam.rs`, consumed by `src/jit/**`)
The one family-private surface a native `bs_create_bin` lowering codes against: the shape rules stay in the family, the emission rules stay in `src/jit/**`.
`create/CONTEXT.md` owns the full accept/decline rules and `seam.rs`'s module docs are authoritative for the `binary all` case; the contract this level records:
- `append_plan(module, segments) -> Option<AppendPlan>` — pure, takes no `Machine`.
  `AppendPlan { source, unit, tail_bits, fields, binary_all }`, `Field::{Bits { value, bits }, ConstBytes { bytes }}`.
  Accepted: a first `private_append` of the accumulator, then any mix of constant-width unsigned big-endian `integer` fields of `1..=64` bits (bit-granular widths **are** plannable) and `string` constants, `unit` in `1|2|4|8`.
  `binary_all: Some(source)` is the separate whole-binary tail shape: exactly one `binary all` segment as the plan's last and only field, with `fields` empty and `tail_bits` `0` — a field before it or any segment after it fixes no static offset, so the plan stays `None`.
  Declined: a literal-area value or accumulator operand, a `float`/UTF segment, a bignum or `dynamic` width, a zero-width field, a field wider than 64 bits, a signed/little/native field, and a first segment that is not a `private_append`.
- Every operand a plan or a door hands back is a **locatable** register — an x-register or an addressable `Y` slot, in the plain `Operand::X`/`Operand::Y` spelling and in the compiler's `Operand::Typed { reg: Reg::X|Reg::Y, .. }` one; `locatable_operand` is a pure classification with no `Machine`, and **the tier owns the `Y` frame-window guard**.
- `open_append(machine, src, tail_bits)` is the **byte-aligned** door's reference answer and stays `#[cfg(test)]`; `open_append_any(machine, src, tail_bits, unit)` is the **general** door for a plan carrying any bit-granular field.
  Two doors, not one loosened door: the byte-aligned route's `cursor + byte_offset` addressing holds only at a byte-aligned window end, so it must not pay the general route's per-position test; the bit-granular route needs the general door because a bit field leaves the window ending mid-byte.
  The general door is gated on C's append-**position** unit rule (`append_unit_allows`, `erts_bs_append_checked`): `unit <= 1` ungated, `unit == 8` requires `end % 8 == 0`, any other `unit` requires `end % unit == 0` — the same test the family applies to `src_bits % unit` at `start == 0`, so a shape the family raises `badarg` on is never reported writable.
- `write_bit_field(base, start_bit, cur_bit, value, nbits)` is the family's one bit-granular write rule: the low `nbits` bits of `value` MSB-first, an entered payload byte cleared first, the window-end byte masked, each bit OR-ed in at `7 - cur_bit % 8`; re-execution idempotent, `nbits <= 64`.
  `value` is a **small** integer's `small_value(word) as u64` (sign-extended, so a negative value's low bits are its two's complement); a **bignum** field is the tier's own refusal, because the family routes one through `BitWriter::push_wide_int`'s byte model, which the `u64` door does not model.
- A run-time door allocates nothing, mutates nothing and is safe to call speculatively; `None` is the universal fallback signal (run the family helper).
  A plan's static tail is checked for room **before** the first write, which is why the door is consulted for the whole plan.

## Design Decisions

### `append` / `private_append` — in place while the payload is writable
`create::assemble` walks the segment list into a `BitWriter` whose destination is `Dest::Vec` (the copy-rebuild form, a growable `Vec<u8>` materialised once by `raw::make_binary`) or `Dest::InPlace` (a `raw::InPlace` sink over a `bs_init_writable` payload).
The in-place mode is entered only for a `private_append` in the **first** segment position whose source is an off-heap refc binary with `start == 0` over a payload the machine registered through `Machine::mark_writable` (`raw::writable_append_target`); it writes the new bits at the payload's own window end and publishes the **same** `Eterm` with a widened `ErlSubBits.end` (`raw::set_ctx_end`) — C's `erts_bs_private_append_checked` writable arm.
The payload comes from `Machine::alloc_refc_binary_with_capacity` (`RefcBinary::with_capacity`, a 4x `DEFAULT_RESERVATION_FACTOR` reservation with the handle's `len == capacity` so a relocation copies every written byte), so most appends land in spare reservation.

**Growth keeps a build in place.** A write past the capacity asks the payload to widen: `raw::InPlace::grow` → `Machine::grow_writable_payload` → `beam_alloc::RefcBinary::ensure_capacity`.
An `InPlace { .. }` outcome commits capacity inside the existing reservation — the sink's cached capacity moves, the registry entry's capacity is refreshed, and it keeps writing at the same base.
A `Moved(rel)` outcome reallocates at `rel.to()`; `raw::republish_over` re-points the accumulator at the new base and the registry is re-keyed (`Machine::rekey_writable`).
The republish writes **exactly two words** — the `BinRef`'s `val` word and the `ErlSubBits`'s `base_flags` pointer word — and preserves every other word (`BinRef.next`, the `start`/`end` window, the `orig` back-pointer) and the flag bits packed into `base_flags`, so the same `Eterm` names the new payload.
It works on two **independent** blocks and never assumes they are adjacent: `beam_gc` copies an `ErlSubBits` as its own `ERL_SUB_BITS_SIZE` words and forwards its `orig` word as that block's child (`beam_gc/src/copy.rs`'s `move_size`), so a collection between two appends leaves the 3-word `BinRef` a separate allocation the collector may place anywhere in the to-space.
A whole-pair write (`beam_term::refc::write_refc_binary`, which writes one contiguous 8-word pair) would spill five words past the `BinRef` — never substitute it.
The door is consulted **only on a shortfall** (it scans the machine's payload roster), and `Machine::retain_refc_binaries` is deliberately not on the append path.
A **failed** build never bumps `end` at all — stricter than C, which bumps in its sizing pass.

**Promotion, not failure, covers what growth cannot do.** A payload `beam_alloc` will not relocate (a shared handle — C's `erts_pin_writable_binary` situation — or the `max_capacity` cap), a payload a second on-heap pair in this machine also names (`raw::payload_aliased_elsewhere`: a move frees the old block, so such a word would dangle), and a segment source that **overlaps** the payload all copy the already-written prefix out (`raw::InPlace::into_bytes`) and continue in `Dest::Vec`, so the result is byte-identical to the copy-rebuild path and the accumulator's window is left unbumped.
`push_bits_from` fast-paths whole bytes when both the source offset and the write position are byte-aligned and stays bit-exact per-bit otherwise, and it promotes on `source_overlaps` **before** any growth (order explicitly load-bearing).

**Two properties make the mutation unobservable outside the accumulator**, both pinned by `create/inplace_tests.rs`: writes land at bit offsets `>= end`, so a shorter window over the same payload (an earlier alias) reads exactly its own bits; and writability is **per machine** (`Machine::writable_payloads`), so another machine handed the same `Eterm` copy-rebuilds and never writes the creator's payload.
The amortisation is pinned structurally by `create/grow_tests.rs` from `RefcBinary::growth_counters`, asserting the *shape* rather than exact figures (≤ 12 moves, `bytes_copied ≤ 2×` the appended bytes, ≥ 1 in-place grow, exactly one payload handle), so a quadratic regression still fails it.
What stays unmodelled (typed results only, never a wrong value): `BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER` are not term flags, `binary:referenced_byte_size/1`'s capacity-vs-size answer (C's `apparent_size`) is absent, a copy-rebuild result is an ordinary non-writable refc binary, and the payload's `as_bytes()` reports the whole reservation rather than the bytes written — a `beam_alloc` `set_len_written`/high-water-word API would close that.

### Hot-path shaping (measured; do not re-open without the same evidence)
The router (`families/mod.rs`) and every family `exec` are inlined into one function, so a dispatched instruction must not add a call/ret pair per instruction; the two hottest dispatched instructions are routed straight to their bodies by the router.
`matching/mod.rs::exec` tests `Instr::BsMatch` **before** the 18-arm jump table and hands everything else to the outlined `exec_other`; both `#[inline(never)]` markers are load-bearing (without the outlining LLVM folds the pre-test back into the switch; without the outlined dispatcher the family entry grows past the inline budget and `families::dispatch` stops inlining it).
`matching/commands.rs` keeps its four cold command bodies (`skip`/`binary`/`get_tail`/`'=:='`) as out-of-line helpers reporting `CmdFlow { Done, Relocated, Fail }`, so `run_commands`' hot block holds only the `ensure_*`/`integer` arms, the capture and the `stale` re-read.
`create/segments.rs` does the same for `binary_segment`/`string_segment`/`float_segment`/`utf_segment` + `float_source`/`put_float`/`put_utf8`/`put_utf16`/`put_utf32` (`binary_segment` alone is `#[inline]`, a single call site on the accumulator hot path).
`create/prepared.rs::integer_non_small` is the `#[inline(never)]` cold half of the `ByteInt` arm.
Measured figures, per-workload counters, the profile breakdown and every **measured negative** (do not re-attempt: whole-operand-list slice patterns for the six `bs_match` shapes, inlining `match_ctx::read_ctx`/`reread_ctx`, testing `small_value` before `big_parts_safe`, inlining the four cold segment bodies) live in `../../../MEASURED.md` and `../../../PERF.md`.

## Constraints
- `#![deny(unsafe_code)]` crate-wide; `raw.rs` is the node's only non-test `#[allow(unsafe_code)]` module and every `unsafe` block carries a `// SAFETY:` rationale.
- Errors are `beam_common::{Result, BeamError}` only — no crate-local error enum, no `unwrap()` on runtime data, no panic, **never a wrong result**.
  A match failure branches to the instruction's fail label (or raises `{badmatch, Value}` when the label is `NO_FAIL`); a construction-segment failure raises the bare `SegReason` atom (`badarg` / `system_limit`), never the matching side's `fail_step`.
- The `{badmatch, Value}` tag resolves through `machine::namespace_atom` (the host's live `ctx.atoms(module)` first, the module's load-time snapshot second) via `crate::terms::badmatch_reason_rooted`; a name **neither** source knows is the typed `BeamError::BadMatch`, never a substituted index.
- Term construction/inspection is **only** `beam_term`; ordering uses `beam_term::{cmp, eq}`, never a reimplementation.
- Term-constructing arms allocate through the rooted seam (`raw::make_ctx`/`make_bits`/`make_binary`/`make_writable`/`make_big` → `crate::terms::reserve` → `Machine::alloc_rooted`) and re-read the context operand after an allocating read (`reread_ctx`), per the frozen **reserve, then read, then write** ordering.
- Files ~1000 lines; split by responsibility. `matching/mod.rs` holds only the opcode dispatch table plus the per-opcode arms; new match tests go to `matching/{tests,utf_tests,elision_tests,rooted}.rs`.
- Licensing Apache-2.0; every `*.rs` carries the OTP `// %CopyrightBegin% … // %CopyrightEnd%` header byte-exactly (the repo scanner enforces it).

## Test Strategy
Per-module `#[cfg(test)]` unit tests over hand-built operands and direct decoder calls (`raw_tests.rs`, `mod.rs`, `matching/{tests,utf_tests,elision_tests,rooted}.rs`, each `create/*_tests.rs`, `matching/prepared_tests.rs`, `create/prepared_tests.rs`), an end-to-end suite in `run_tests.rs` through the real public entries (`Machine::run_label`/`run_export`) over synthetic `beam_loader::Module`s + a `MinimalContext`, and live `erlc`/`erl` oracle cross-checks compiled from an inline source string at test time (they skip loudly when the toolchain is absent).
Every expected byte vector was taken from the system `erl` — never invented.
Gate: the whole-crate suite is authoritative — `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --no-fail-fast` must stay green, the build `... -p beam_engine --all-targets` warning-free, and this family's subset is `... -p beam_engine --lib families::bitstrings`; re-run them for the live counts.
The integration-suite enumeration is `../../../TEST_NOTES.md`.
**Differential evidence:** `erts_rust/tools/differential` was run per-case over the whole `binary/` group plus every bitstring/binary-shaped corpus id (80 cases: all `binary/*`, `bits/*`, `semantics/bit*`, `wire/bit_binary*`, `wire_extra/eval_wide_binary*`, the four `gc/*binary*` cases and `errors/*binary*`) — **80 agree / 0 mismatch / 0 unsupported / 0 skipped**.
**Corpus coverage hole (tools-owned):** no corpus case exercises a **bit-granular little-endian** integer write, a `float` segment, a `float-native` pattern or a `utf32-little` pattern (the `binary/bignum_*` LE cases are all byte-aligned 16/64-bit fields), so those shapes are covered only by this node's oracle-derived unit tests.

## Routing Table
Every entry below names something that exists, and both child directories have an entry.
- `mod.rs` → the family `exec` (the only entry, incl. the class-atom anchor), `claimed` (the 20-variant set), `exec_calls` (`#[cfg(test)]`), the shared `fail_step`/`goto_label`, the operand helpers (`read_size`/`read_size_slow`, `is_all`, `decode_flags`/`decode_flags_slow`/`flag_bit` + the `BSF_*` bits), the safe bit arithmetic (incl. the wide-integer byte model), and the `BitWriter` sink (`arm_room`, `ensure_room`, `push_bit`, `push_uint*`, `push_le_groups`, `push_wide_int`, `push_bits_from`, `push_byte_field`); its unit tests are the in-file `#[cfg(test)] mod tests`.
- `raw.rs` → the node's only `#[allow(unsafe_code)]` carves: the subject triple (`heap_bits`/`subject_bytes`), the match context (`ctx_parts`/`inner_orig`/`make_ctx`/`set_ctx_start`/`set_ctx_end`), the bignum readers (`make_big`/`big_parts_safe`), result materialisation (`make_bits`/`make_binary`/`make_writable`), `bit_size`, the writable-payload machinery (`writable_append_target`, `InPlace{grow,push_bit,write_byte_field,into_bytes}`, `payload_aliased_elsewhere`, `republish_over`, `write_payload_bit`/`write_bit_field`).
- `raw_tests.rs` → `raw`'s `#[cfg(test)]` suite, declared at the end of `raw.rs` as `#[cfg(test)] #[path = "raw_tests.rs"] mod tests;` so `super` is `raw` and its allow is inherited: the frozen-layout accessors, the size-dispatching result builders (incl. the zeroed-padding invariant), the growth/relocation/refusal matrix, and the split-pair canary cases proving a republish writes only the two pointer words (`a_republish_writes_only_the_two_payload_words_and_leaves_a_split_pairs_neighbour_intact`, `a_split_pairs_payload_move_keeps_the_next_append_in_place`, `a_second_pair_over_the_payload_refuses_the_move`).
- `programs.rs` → the prepared-program cache (`Program`, `program_key`, `BitstrPrograms::get_or_prepare`, `ProgramWitness`); the per-module-context table and the `Machine::with_bitstr_programs` hand-over described above.
- `run_tests.rs` → the `#[cfg(test)]` end-to-end + oracle suite (see Test Strategy).
- `matching/` (no child `CONTEXT.md` — the detail is this file plus the module docs):
  - `mod.rs` → `exec` for all match/position/`bs_match*` opcodes: the `BsMatch` pre-test ahead of the 18-arm table, the outlined `exec_other`, and `bs_get_integer2`'s allocation-witness re-read rule.
  - `match_ctx.rs` → match entry (`enter_match`, its `reuse` arm, `resolve_match4_fail`), the context readers (`read_ctx`/`reread_ctx`) and the position ops (`position_term`/`position_of`).
    The reuse arm returns the **same `Eterm`** the operand holds (C's `$Dst = context`), so a re-entered match costs no reservation; that is the per-element hot path of a binary comprehension, whose loop fun does `bs_start_match3 Ctx -> Dst` … `move Dst -> Ctx` (so `x(0)` *is* the context after the first iteration).
    The reuse predicate is `raw::ctx_parts(value).is_some()` after a `raw::heap_bits` miss, which is exactly C's `erl_sub_bits_is_match_context` because this engine never builds a non-match-context, non-refc `ErlSubBits`; identity is faithful (C re-reads neither `orig` nor `start`/`end`), and a `bs_start_match3`/`4`-resume whose `Dst` is its own `Src` stays a no-op.
    `BsGetPosition` publishes a **small integer** (`position_term` → `make_small`, C's `$Dst = make_small(sb->start)`, zero allocation); the whole-context snapshot survives only as the over-large-position fallback, and `position_of` accepts both forms.
  - `prepared.rs` → the pre-resolved `bs_match` command program: `prepare` folds the flat list once per `(module image, function, code offset, descriptor list)` into a `MatchProgram` of `MatchCmd` variants (the command atom *is* the variant; size/unit are plain `usize`s with `$BS_SAFE_MUL` already applied; flags are `BSF_*` bits).
    The walk calls the very bodies the generic walk calls, so the two routes cannot drift in semantics — only in where an operand was read.
    The straight-line `FastForm` covers `ensure_at_least` + `integer` runs whose fields are unsigned, big-endian and a whole number of bytes at most 8 wide: one window bounds check, one whole-byte load, one `x(Dst)` store and one context-position store per element, plus the one re-read a field's own allocation forces.
    Signed / `little` / `native` / non-byte-width / >8-byte fields keep the prepared command walk; anything `prepare` declines stays `Program::Generic` and runs `commands::run_commands` with its exact typed error.
    `prepared_tests.rs` is the prepared-versus-generic equivalence suite; `route_counts()` reports the fast/prepared/generic split for the tier's census.
  - `commands.rs` → the generic flattened `bs_match` command interpreter (`run_commands`) over `ensure_at_least`/`ensure_exactly`/`skip`/`integer`/`binary`/`get_tail`/`'=:='`, plus the `commit` write-back discipline and the four cold helpers.
    It captures the context term, its inner `orig` and the subject byte view **once** and re-derives them only after a command that can have allocated through the rooted seam: `integer` dirties only when the field did not fit a small integer, `binary`/`get_tail` always, `ensure_*`/`skip`/`'=:='` never; the rule is deliberately one-sided (a stale capture would be unsound, a redundant re-read only costs a read).
    Classification is `module.atom_name` (a `Vec` index) plus a length-discriminated `&str` match — a precomputed atom-id table would cost 7 hash probes per invocation and does not pay.
  - `reads.rs` → the fixed field readers (`read_integer_field_tracked`/`_untracked`, `read_wide_integer_field`, `read_float_field` + `f16_to_f32`, `decode_utf8`/`utf16`/`utf32`, `bit_at`, `bits_equal`), the shared `field_is_little` endianness resolver, and `may_have_allocated` (the allocation witness).
    `read_uint_le_bits` forwards a **byte-aligned** field to the shared whole-byte `read_uint_le` and keeps its bit-granular loop only for a mid-byte start.
  - `tests.rs` → unit tests for the pure decoders the match opcodes call, plus the instruction-level regressions for the empty-binary match, `bs_match_string` and the off-heap refc results.
  - `utf_tests.rs` → the match reads' endianness flags (`BsGetUtf32`/`BsSkipUtf32`, the raw-`BSF_NATIVE` float/integer/utf16 reads), oracle-derived.
  - `elision_tests.rs` → the allocation-aware re-read elision (a non-allocating list elaborates off one capture; a bignum `integer` still commits the full advance; `binary`/`get_tail` keep the always-re-read commit; `skip`/`'=:='` elide).
  - `rooted.rs` → rooted-allocation tests for the match path.
- `create/` → the construction side; **`create/CONTEXT.md` is its node record** (Intent, API Surface, Constraints, Test Strategy) and is authoritative for the seam's accept/decline rules.
  - `create/mod.rs` → `exec` (`bs_init_writable`, `bs_create_bin`) and `assemble` (the flat six-operand `[Type, Index, Unit, Flags, Value, Size]` walk); a non-integer value is the bare `badarg` at **every** width (checked before the width dispatch), and the `integer` arm routes a value to `push_wide_int` whenever `nbits > 64` **or** the value is a bignum, so a bignum is masked into a narrow field as C's `fmt_big_be`/`fmt_big_le` do.
  - `create/prepared.rs` → `prepare` folding the segment list once per `(module image, function, code offset)` into a `CreateProgram` of `PreparedSeg` variants, and `assemble_prepared` executing it.
    `PreparedSeg::ByteInt` is the direct-store form of an `integer` segment (a static whole-byte 8/16/32/64-bit width, either endianness) and `BitWriter::push_byte_field` its writer: a byte-aligned destination stores through `raw::InPlace::write_byte_field` or a const-length `extend_from_slice`, and only an unaligned position or a short in-place sink falls back to the bit-exact `push_uint`/`push_uint_le`, so the bytes cannot differ.
    `CreateProgram::reserve_after[i]` is the summed **static** bit width of every segment after `i` (`None` once one has a runtime width) — the figure `BitWriter::arm_room` needs for the one capacity reservation per instruction; `arm_room` **never grows**, and a shortfall still reaches the unchanged per-field `InPlace::grow`, so the growth schedule is the per-field route's.
  - `create/size.rs` → the segment size validation (`SegSize`/`segment_size`, `seg_nbits`, `float_nbits`) and the `SegReason` raise (`fail_seg`/`seg_fail`/`raise_seg_fail`); `segment_size` short-circuits a literal `Operand::Integer`/`Operand::Character` through `literal_segment_size`.
  - `create/segments.rs` → the per-segment sources and encoders (`segment_source`, `string_source`, `float_source`, `put_float`/`f64_to_f16`, `put_utf8/16/32`) and the cold-body host `SegOutcome`. The `float` source accepts a float, a small integer **or a bignum** (the nearest finite double via `beam_term::number::big_to_f64`); only a non-number or a magnitude overflowing a finite double is `badarg`.
  - `create/seam.rs` → the construction seam above (consumed by `src/jit/**` as `crate::families::bitstrings::create::seam`).
  - `create/{tests,prepared_tests,seam_tests,inplace_tests,grow_tests,wide_tests,le_tests,float_seg_tests}.rs` → the segment-encoder units, the prepared-versus-generic equivalence suite, the seam's accept/decline + both doors + the bit-granular write's agreement with `BitWriter`, the in-place window, the growth/relocation schedule's *shape*, the wide-integer masking, the bit-granular little-endian field, and the bignum `float` segment.

## Known Issues (each a typed result, never a wrong value unless stated)

### Remaining typed capability gaps
Each remaining site is a guard for a **malformed `.beam`** or an internal invariant the installed compiler cannot reach, verified by a `beam_disasm` census over the installed OTP (the `bs_match` instruction tags are exactly the 7 `run_commands` covers, `bs_start_match4` is never emitted, and no unknown flag atom or segment type appears).
- A segment list with no type atom, an unknown segment type, a `string` segment with an unknown/negative/overflowing/out-of-table `StrT` offset+size (or size `all`), an integer segment with size `all`, a truncated segment list, and a literal index out of range are typed `unsupported`/`badarg`.
- `bs_match_string` resolves its pattern with `module.strings.get(offset..)`: an offset **strictly beyond** the table is the typed `unsupported`, while an offset **exactly at** the end is a valid **empty** pattern (a 0-bit match succeeds).
- `read_size` refuses a negative, oversized or non-integer size operand (a **typed-register** size — `{tr,Reg,Type}`, what a runtime `size(Expr)` emits — is accepted through `read_operand`).
- `read_uint_le`/`read_uint_le_bits` refuse a non-byte-aligned little-endian field, but the refusal is **latent**: the bit-granular read route goes through `read_wide_integer_field`, so no compiled shape reaches them.
- `bs_get_float2`'s unsupported-size site, `make_bits`' `> 64`-byte branch, `make_big`'s zero-width-bignum guard and the short-byte-buffer guards are unreachable from production code (C returns `THE_NON_VALUE` for an unemitted size ⇒ a plain match failure; `make_binary` dispatches above the limit to the refc pair first; a bignum in a 0-bit field yields `<<>>`).
- A non-finite float result and a non-float FR slot remain the documented `badarith` failure; a bignum `float` segment that overflows a finite double remains `badarg` (C's `big_to_double < 0`).
- `system_limit` is modelled (`size*unit` overflow / the post-multiply sign bit / a positive-bignum size; a negative bignum size is `badarg`).

### Coverage hole (tools-owned)
No `tools/differential` case exercises a bit-granular little-endian integer write, a `float` segment, a `float-native` pattern or a `utf32-little` pattern — see Test Strategy; the owner is `tools/differential`, not this crate.

### Out-of-node findings (do not fix here)
- **`crates/beam_loader` — the `bs_match` command-list generator expansion.** C never interprets a flattened command list at run time: `emu/ops.tab:1102` + `emu/generators.tab:1096-1112` make the loader explode `bs_match` at load time into `i_bs_ensure_bits`/`i_bs_ensure_bits_unit`/`i_bs_read_bits`/`i_bs_eq`/`i_bs_extract_integer`/`i_bs_get_fixed_integer`/`i_bs_get_fixed_binary`/`i_bs_get_tail`/`i_bs_skip`/`i_bs_drop`, including fused shapes.
  Our loader preserves the raw list, so `run_commands` re-derives a load-time fact on **every** execution (a comprehension enters it once per byte); an in-family re-discovery of the shapes measured a **regression**, so the only route left is a pure semantics-preserving **hoist** — `Instr::BsMatch { commands: Vec<Operand> }` carrying a typed `Vec<PreparedCommand>` with the command tag, flags, size/unit and `Dst` already resolved.
  **OWNER: `crates/beam_loader`** (and `beam_engine/src/lib.rs` for the `Instr` variants).
- **`terms::number::make_integer_unrooted`** shows in the profile as CALL overhead, not allocation: its small-value arm is `make_small`, but the function is not inlined at its `src/operand.rs` call sites. **OWNER: the parent `src/` node.**
- **`Machine::reset` + `interpreter::build_label_map`** are entry-path rows in the parent's `run_label_outcome`/`reset` path: `reset` refills the run's used register extents once per run entry, and the label-map build happens once per machine per module (`Machine::label_map`'s cache). **OWNER: the parent `src/` node.**
- **`src/exec_census.rs`** costs one latched `bool` load and a branch per interpreted instruction while disabled (`Machine::census_on`); the instrument has no call site in this node. **OWNER: the parent `src/` node.**

## Notes for Agents
- **A test term must be allocated in a context that outlives its use.** `MinimalContext`'s region heap is pointer-stable and keeps earlier regions alive, but a context created in an inner block drops its arena when the block ends — an `Eterm` built in a throwaway context and then fed to a `Machine` (or a different context) is a use-after-free whose assertion passes only when the freed bytes still hold the term.
- `matching/reads.rs::field_is_little` is the one endianness rule for match reads; `mod.rs::BitWriter::push_le_groups` is the one for writes. Never test `BSF_LITTLE` alone, and never treat `BSF_NATIVE` as a placeholder.
- A construction-failure with a **nil** fail label is a **raise** (`fail_seg` → `raise_seg_fail`), matching C's `$FAIL_HEAD_OR_BODY` (a nil label falls to `goto find_func_info` → `handle_error`), and it IS reachable from compiled code (`<<1, X/binary, 2>>` emits a non-append `binary` segment with `{f,0}`); verified oracle-identical — do not "fix" it into a silent continue.
- A family's `Ok(None)` is **not** a silent no-op: it reaches the router's last arm and yields the unclaimed-opcode sentinel. No arm here claims a variant and then no-ops it.
- **The reachability wall is this node's own `mod` declarations, not the crate root.** `mod.rs` declares `pub(crate) mod create; mod matching; pub(crate) mod programs; pub(crate) mod raw; mod run_tests;`, so `exec`/`claimed`/`bit_size` and the `create::seam` surface ARE reachable from `src/jit/**` (`jit/baseline/bitstr.rs` and `emit/bitstr_inline/create.rs` do exactly that, which is why neither needs `#[allow(dead_code)]`).
  A private `mod` makes every body inside it unreachable regardless of the item's own visibility, so `matching/match_ctx.rs` (`enter_match`, `read_ctx`/`reread_ctx`, `position_term`/`position_of`) is a **declared** seam no tier can resolve, and a tier consumes `raw` only through the seam (`seam::write_bit_field` forwards the one `raw::write_bit_field` rule a tier needs).
  `create::assemble` is `pub(super)` on purpose: what a lowering consumes is the seam, never the walk or the family-private `Built` form. Opening a further seam means widening the **enclosing `mod` declaration** as well.
- **The seam decides *plannability*; a tier's shape predicate decides *emittability*.** A change here can silently widen or narrow what `jit/baseline/emit/bitstr_inline/create.rs` may emit — update both sides and the tier's pins (`jit/baseline/bs_create_bin_tests.rs`, `jit/baseline/foreign_kernel_tests.rs`) together.
- On the default (native baseline) tier sixteen of the 20 `claimed()` variants carry a native in-block arm (`jit/baseline/emit/bitstr_inline/mod.rs`, `SHAPE_COUNT = 16`) and never reach `exec`; the construction one reaches the `create::seam` doors instead.
  The other four (`bs_init_writable`, `bs_get_tail`, `bs_get_binary2`, `bs_get_float2`), and every instruction one of the sixteen refuses at compile time or declines through a run-time guard, arrive at `exec` through the `jit_bitstr` helper, which bypasses the router's variant re-match and nothing else.
  The per-shape predicates, guards and routes are the tier's own record: `../../jit/baseline/inlineset/CONTEXT.md`.
- **Measured workload shapes.** `tools/bench`'s four `foreign` cases execute `cowboy_bstr:to_lower/1`, `cowboy_bstr:capitalize_token/1`, `emqx_base62:encode/1` and `emqx_base62:decode/1` (inputs and loop counts in `tools/bench/src/workloads/foreign.rs`).
  Only 9 of the 20 variants occur there, and the recurring match shapes are four: whole-byte unsigned BE `[ensure_at_least 8 1, integer … 8 1]` (the prepared `FastForm`); a **6-bit** `integer … 6 1`; `[ensure_at_least 12 8, integer 6, integer 6]`; and `[ensure_exactly 0]`.
  Their per-call instruction and allocation counters, the build-site table and the tier deltas are measured figures — read them in `../../../MEASURED.md` / `../../../PERF.md`, not here.
