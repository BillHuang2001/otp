# `measure` — the baseline tier's measured record

## Intent
Every measured figure of the native baseline tier, the instrument that took it, its caveats and the levers that were measured and rejected, in one node so the tier's contract files stay readable.
The mechanisms live beside their code (`../runtime/`, `../emit/{prologue,regalloc,regs,link}/`); this file is the evidence that chose them and the negative results that must not be re-investigated.
Do not duplicate the records owned above this node: `../../../../../../tools/bench/RESULTS.md` is the canonical cross-runtime table, `../../../../MEASURED.md` the crate-level record (and the home of the headline `foreign`/inline-set A/B tables), `../../../../PERF.md` the tier performance snapshots, `../census/CONTEXT.md` the live corpus totals and every census table.

## Instrument and discipline (how any figure here was taken)
These rules are the contract for adding a figure; a number taken any other way is not evidence.
- Count **retired user instructions** with `perf stat -x, -e instructions:u`, matching the `cpu_core/instructions/u` line (this box is hybrid, so the `cpu_atom` line reads `<not counted>`); perf writes its report to stderr, so a pipeline needs `2>&1 >/dev/null |`.
- The counter is a virtualized PMU reading ≈**17×** the real retired-instruction count, so **only the ratio between two legs measured this way means anything**.
- A per-call figure is a per-rep **slope** `i(N1) − i(N0)` with N large enough that the work dominates the ≈7.05e9-unit boot intercept; never difference two independently minimized samples (run-to-run counts are bimodal on a loaded host — a clean mode plus a phase-dependent mode ~2–3 % higher).
- Sides are **interleaved with the order alternated** round by round, one process at a time, `taskset -c 3`, `/proc/loadavg` recorded at every round, and both the **min and the median** of the per-round ratio reported.
- A **paired same-session A/B** is the only load-robust timing figure on this host; a cross-session or cross-date pair of ratios is **not** evidence (the untouched oracle leg itself has drifted 20–32 % with load, which is enough to invert a conclusion).
- **Noise floor**: a fresh release build of the same tree measures within **0.01–0.04 %** of the binary under test on both counters, so a lever must clear the **0.3 % keep bar** on the counters — and, on a wall clock, clear the sys-side control's own drift (~±2 % on a `tools/bench` pair).
- Wall clock is not resolvable on this host at the 1–3 % effect size; the structural counters are deterministic and identical across repeats, so they are the evidence for a lever and a wall-clock A/B is quoted only as an honest negative.
- **The host is shared.** Quote the ratio and the deterministic counters (`instr_per_call`, `local_call_requests_per_call`, `driver_round_trips_per_call`, `step_one_per_call`, `deopt_count`, `case_*_ops/calls/elements`), never an absolute ns — and never a share across two trees without checking whether the rows that should not move moved with it.
- `perf record --clockid CLOCK_MONOTONIC` is required for any `perf report --time <t0>,<t1>` slicing; with the default clock the samples sit ~50 s off wall time and `--time` selects nothing.
- **Profile the baseline tier alone and exclude boot.** `../../../bench`'s `selected_tiers` takes `interpreter|baseline|both`, **defaults to `baseline`** and panics on anything else; a `both` profile is never valid for an attribution profile, because the interpreter leg is ~2.2× slower per call (8 322.9 vs 3 734.6 ns/call on `to_lower/1`) and so owns ~69 % of the samples — the rows it then puts in a top ten (`select::pair_eq`, `select::first_match`) are the interpreter's own `select_val` ladder, which the native tier inlines.
- An in-crate batch that builds a fresh `Machine`/context per run folds `AtomTable::fork`/`register_context`/`switch_context` into the marginal — that, not a real cost, is what a `drop_glue::<…>` or `*::prepared::prepare` row in such a profile is.
- A **foreign module needs `-pa <its dir>`** on the `beam_rt` command; without it the run is `error undef` and the counter measures boot only (a ~7.1e9 "per-call" figure is that failure, not a measurement).

## Closed levers (the evidence behind the current shape)
Each row is a paired ratio of retired instructions unless it names a deterministic counter; `list_walk` slopes are `i(9 000) − i(1 000)` / `i(4 000) − i(500)`, `foreign` `i(101 000) − i(1 000)`, `emqx_base62` `i(252 000) − i(2 000)`.

| lever | measured effect |

| the family helper stops boxing its `Ok` (`../family.rs`) | **−1.85 %** cycles on `foreign`; `objdump` of the symbol: 2 `malloc` + 3 `free` + 2 drop-glue calls → 0 `malloc` + 1 `free` |
| post-helper refill = `cacheable_writes(pc)`, not the block's | −0.104 % `foreign`, −0.20 % `emqx`, −0.028 % `list_walk`; mechanical: `fill_registers` **3 291 217 → 1 529 718 (−53.5 %)**, helper-site refills **−59.9 %**, emitted bytes **−3.91 % = exactly 7 B × 1 761 499** (one `mov r64,[rbx+disp32]` per removed refill); spill stores, block/cache-slot/written-slot counts and the allocation itself unchanged |

| elide a provably dead prologue `jit_publish_y` (`Allocation::prologue_publishes_y`) | **−2.33 %** `list_walk`, **−0.40 %** `foreign`; static split over the corpus: `y_blocks` 185 141, `publish` 132 908, **`elided` 52 233 (28.2 %)**; `y_invalidations` 544 282 untouched |
| variable-length native frame + live-in prologue fill | push/pop ops **7 167 996 → 2 707 930 (−62.2 %)**, emitted bytes **−4.39 %**, prologue loads **756 632 → 352 537 (−53.4 %)**; **no measurable throughput effect on this host** (honest negative, below) |

- The refill narrowing is purely syntactic and decided at allocation time: a helper call **is** the interpreter, so the only register a helper can have changed relative to the block's cache expectation is one written by the instruction at that `pc` — a guarded inline lowering that rejected to `jit_step_one`.
- Both seam levers buy instructions, not fewer consultations: `local_call_requests_per_call`, `driver_round_trips_per_call`, `block_entry_*`, `instr_per_call`, every static/deopt counter and `deopt_count` (empty) are unchanged by them.
- **The frame/fill levers are an honest negative on wall clock.** 9 paired rounds with the order reversed (`bench run --quick --runtime rust --workloads baseline,slice,foreign,list_walk,copy_bound,gc_bound`, load 8–123 recorded per run): every case's after/before ratio flips sign across rounds and each side's own spread is 1.5–5.2×, so no case clears the spread and the min-over-N ratios (0.86–1.98) are confounded — the two minima come from different rounds. The same harness *can* resolve a per-instruction difference (the tier ratio is stable and reproduces `tools/bench/RESULTS.md`; the default tier is cheaper on 9 of 10 cases), so a ≲2 % wall-clock effect is below this host's resolution — do not re-run that A/B expecting signal. Their evidence is the deterministic emitted-instruction/byte reduction.
- `jit_publish_y` = `JitRuntime::refresh_y_base` (re-derive `[y_base, y_end)` from `Machine::frames.last()` + `machine.stack.as_mut_ptr()`) **then** `Machine::set_current_code(func, pc)`.
- Removing **only** the position store gives 0.964147 / 0.964160 on `list_walk`, i.e. the store is **3.58 %** of the per-rep count; the inverse split is not valid (with no window published the emitted Y guard rejects, the tier deopts and the result is wrong). `perf annotate` of the 190-byte function: `#[cfg(test)]` counter probe ≈7.6 %, `frames.len()`/×32 ≈8 %, the frame deref + stack pointer + mul-add ≈42 %, the position store ≈18.3 %.
- The store is a **frozen** publication (`Machine::current_code` is what a resume and `process_info/2` read), so it is not a removal candidate — which is why the lever attacks the derivation (by not needing it) rather than the store.
- The frame-changing helpers re-publish the Y window themselves: `jit_allocate`/`jit_allocate_heap` from the `(y_base, y_count)` `Machine::push_frame_window` just computed (`JitRuntime::publish_y_window`, no derivation), `jit_trim`/`jit_deallocate` through `JitRuntime::refresh_y_base`; the emitted continue arm never calls `jit_refresh_y` for them.
- Honest attribution: about half of the measured refresh cost in a **test** build is the `#[cfg(test)]` structural counter probe (`Counters::record_publish_y` is `jit_publish_y`'s first statement), so the counter-borne saving is overstated relative to a production build; the sign and the mechanism are unaffected.
- **Flat profile** (`list_walk`, `perf record -e cpu_core/cycles/u -g --call-graph fp`, 73 945 samples, self time): `jit_allocate` 16.63 %, `Machine::local_call_seam` 11.25 % (sibling-owned), `jit_publish_y` 9.80 % (20.45 % before the publish gate), `enter_in_block` 8.74 %, `call::call_store_impl` 7.61 %, `jit_deallocate_return` 4.99 %, `family::jit_family` 4.95 %, `call::jit_call_store` 4.63 %, `jit_set_position` 4.37 % (the ranges the gate demoted off `jit_publish_y`), `CountingContext::resolve_local_call` 2.18 %, `CountingContext::reduce` 2.12 %. Shares inflate as the total shrinks, so compare only within one window; this reading predates the verdict table, so its seam rows price a once-per-call host consultation, and the seam's per-call residual today is one bounds-checked verdict-slot load plus the invalidation `Cell` read (`../../../machine/CONTEXT.md`). A second, differently-windowed `list_walk` baseline profile is `../../../bench/CONTEXT.md`'s.

## Rejected levers (measured; do not re-open)

### The range-crossing Y-window witness
A call's continuation is emitted as its own range `[pc+1, next continuation address)`, whose `Allocation` sees no `allocate` (it sits before the `call`), so `prologue_publishes_y` is true there and the sub-block publishes; `list_walk` has two such ranges per element (after `walk/3`'s `call sum/1` and after `sum/1`'s recursive `call`).
A **range-crossing witness** — a `JitRuntime` flag meaning "the published `[y_base, y_end)` already belongs to the frame the next range will run in", set wherever the window is derived and cleared wherever the frame or the position can change without republishing — removes most of those derivations: over the `jit::bench` workload set on this tier, `publish_y_skips = 325/640` (**51 %**) and `refresh_y_skips = 960/960` (**100 %**), i.e. **80 %** of the 1600 derivations.
It is still rejected, on two independent grounds.
1. **It is a net regression.** `list_walk` **+1.15 %** (min 1.011495 / median 1.011502, zero leg overlap) against `cowboy_bstr` **−0.05 %** (min 0.999229 / median 0.999515, legs overlapping — 4–6× below the 0.3 % keep bar). `list_walk`'s hot path is linked `call_last`/`call_only` chains, so `jit_tail_call` (which *must* clear — it pops a frame) charges a store per element while each successor prologue still derives: ≈+1 retired instruction per element. Only long-block code like `to_lower/1` reaches the skips, and there the effect is inside the noise.
2. **Its invalidation set cannot be made exhaustive in-node.** `../runtime.rs::fold_step` encodes `Step::Next` and `Step::Goto { pc: pc + 1 }` as the **same** block-ABI word, so a family raise whose catch handler is its own `pc + 1` is folded into an in-block continue; the block then runs off its end and `../emit/link.rs::emit_exit` links **straight into the handler block**, so no driver-loop iteration runs between `Machine::unwind_to_frame` (which truncates `machine.frames` *and* `machine.stack`) and the handler — a handler `Y` read then resolves through the destroyed frame's window (observed interpreter `11` vs this tier `59`).
- Binding consequence: the two emitted window derivations (the block prologue's publish and the gated in-block refresh after a family helper) are **both unconditional**, which is the frame discipline `../raise_tier_tests.rs` pins; any future lever that makes a window derivation, the `Machine::set_current_code` store or the reduction charge depend on prior state must close the `pc + 1` hole first (a family-`Goto` block-ABI word distinct from `encode_target(func, pc + 1)`, or an invalidation on that route, i.e. `../family.rs`/`../emit/family.rs` plus the shared `fold_step`).
- `y_prologue_publishes` vs `y_blocks` is therefore **not** a counter to move, and `jit_refresh_y` (the largest remaining in-node row, ~5 % of the `list_walk` share) shares the same blocker.

### The per-function published `EntryTables` slot (the artifact lookup is not a live lever)
The absolute ceiling for any shape of this lever is `CompiledModule::function`'s **inclusive** share, measured on the base binary (`release`, `churn/1` at N=200 000 so boot is ≈3 % of the process, `perf record -F 3000 -e cpu_core/cycles/u -g --call-graph dwarf`, 29 542 samples): **0.28 %** of the whole process (self 0.07 %), i.e. ≈0.38 % of the loop once boot is excluded — against `runtime::jit_local_call` 7.03 % and `Machine::local_call_seam` 5.23 % (sibling-owned).
Inside that 0.07 % self time the split is the out-of-line `call` plus the `RefCell` borrow guard first, the `Rc::clone` second, and `EntryTables::of` a rounding error; `churn` asks the artifact only ≈6 times per churn (three calls into another function — `build_list/2` twice, `build_bytes/2` once — and their three in-block continuation returns) against ≈768 same-function local-call entries that never touch it.
**The rejected shape**: one `Cell<PublishedFunction>` per module function, filled at the one publication point, so a repeat entry answered with one bounds-checked load of a `Copy` value (no `RefCell`, no `Rc`, compile-on-first-sight preserved, `EntryTables::NONE`'s `u32::MAX` marking "not compiled"). It works mechanically — `function`'s self time 0.07 % → 0.01 %, `native_entry_tables` inclusive 0.14 % → 0.09 %, `cross_function_entry` 0.15 % → 0.10 %, one artifact miss per function first entered and a hit per repeat — and still loses: paired `churn` retired-instruction slope `i(20 000) − i(0)` over 6 interleaved rounds read **min −0.096 % / median −0.043 %** (≈−495 units on a ≈1.14 M-unit slope), **7× below the 0.3 % keep bar** with the legs' 0.06–0.07 % spreads overlapping, and cycles showed nothing.
No variant can clear the bar: three of the six per-churn lookups are the compile-free hit path already costing ≈13 counter units each, and the rest of the transfer path is the **frozen skipped-iteration reproduction** (`set_current_code` → `reductions` bump → `ctx.reduce(1)?`) plus the `EntryTables` publication — the same conclusion the per-run in-block memo reached (`../runtime/CONTEXT.md`). The real per-call weight on this workload is `Machine::local_call_seam`, which the tier must not short-circuit.

### Entry-module resolution and the priming probe
Every `run_baseline_cached*` slice entry/resume resolves the entry module through `CodeCache::compiled_handle(&Module)` (`../../cache/mod.rs`), whose `ModuleKey::of` is a two-variant identity: `Digest([u8; 16])` = the module's **load-time MD5** (`Module::checksum`, a plain `Copy` — no hash, no allocation) for a real `.beam`, else `Content { name, fingerprint }` over the whole-IR hash (`module_fingerprint`, a full `Debug`-render hash of the decoded IR) for a synthetic all-zero-checksum `Module::default()`.
A real `.beam` therefore resolves with **zero** IR hashes on every slice, primed or not; the address memo (`cached_module_blocks` on the cross-module callee path, `cache::remember_module` on the entry path) is a redundant micro-optimisation on that digest path. The interpreter tier never touches the CodeCache.
The two-process copy-bound probe (`../tests.rs::the_entry_module_priming_is_measured_on_both_tiers`) runs **synthetic** modules, so unprimed they re-hash per slice (≈6.8× of interpreter) and primed ≈0.8× with zero hashes — both **single-run estimates, not pinned results** (that test asserts the `module_fingerprint` counts only; the authoritative tier ratios are `../../../../MEASURED.md`'s).
`remember_module` has **no production caller** (tests only); a host would call it once per module it enters, and the tier cannot pre-empt it (`compiled_handle` is called before any `baseline::run_compiled*` body). Deopt inlining — including the natively-lowered receive family and the family arm — does not move the wall clock on this shape: the deopt chain is cheap relative to that hash.
A same-function block entry re-resolves nothing: the driver hands the entry the function artifact its previous entry resolved (`DriverContext::entry_cached` for context 0, `CalleeCode::cached` per callee), so it costs the two-entry block-table probe with no `RefCell` probe and no `Rc::clone`; only an entry into a *different* function (a cross-function transfer, a call into another function, a fresh slice) re-resolves through `CompiledModule::native_entry_cached`.
The driver charges one reduction per **block entry** against the interpreter's one per **instruction** — a real unit divergence, but ≈1 ns per iteration.

### The bitstring program table's hand-over
Placing the prepared-program table in the registry's parallel `Vec` plus the context-`0` field (rather than a `RefCell` inside the shared `ModuleContext`), with the run-entry retention rule, read **+0.17 % to +0.34 %** retired-instruction slope against a control rebuilt from source at the base commit, alternated inside each round — code-layout noise. They are there for **mechanism** correctness (no atomic on the per-instruction path, no table destruction per run entry), never as a speedup; the neutral record is `../../../../MEASURED.md`'s.

## Whole-process and cross-runtime anchors (entry/call-path changes)
The reference point for an entry- or call-path change is `list_walk`'s **instructions per element**, and later steps are reported as **paired ratios** of retired user instructions (min / median of the per-round ratio, ≥5 rounds, sides interleaved with the order alternated, one process at a time), because no absolute charged-unit instrument exists any more — only the per-leg ratio is meaningful.
- **Current anchor: `list_walk` 502.2 instructions per element** — the last *absolute* reading; a fresh build of the same tree is within 0.01–0.04 % of the binary under test, so every effect in this file is 13–70× the noise floor.
- **Same-module cross-function continuation returns, tail-jumped in-block**, cost `list_walk` **+0.90 %** (497.1 → 502.2; min-of-slopes 1.0087 / median 1.0097, zero overlap, reproduced on two independent N pairs to 0.03 pp) and bought `to_lower/1` **−2.78 %**. It is kept for the foreign-code workloads, which is where the remaining ratio gap is; the `list_walk` cost is the cross-function entry probe that a same-function return also runs, and reclaiming it needs the same-function probe answered without touching the artifact — the rejected `EntryTables` slot above.
- **`to_lower/1`, whole-process instructions per call:** **126 812–126 842** (from 130 439–130 466; **−2.78 %**, spread 0.05 %, no overlap, per-rep slope at N = 50 000 → 450 000 with `-pa <bstr dir>`). The pure boot intercept is identical on both sides (7 036 182 170 vs 7 036 275 469, −0.0013 %), so the gain is per-call and the `EntryTables` publication in `enter_compiled_cached` costs no measurable startup.
- **Both transfer directions are linked; the per-call residual is the host-owned seam.** Round-trips are **3** per `to_lower/1` call (the slice entry plus the outermost call's own `enter_in_block`/`call_store_impl` round-trip) and **2** per `list_walk` call, with `block_entry_misses` `0`. `local_call_requests_per_call` counts host consultations, and the seam's verdict table holds it at one per **distinct callee per run**; what remains is `Machine::local_call_seam` (one bounds-checked slot load plus the invalidation `Cell` read per call), which lives outside this node (`../../../machine/CONTEXT.md`) and must not be short-circuited. The remaining in-node candidates are `jit_allocate` (a real heap/frame-admission door) and `enter_in_block`'s frozen skipped-iteration reproduction.
- **The in-crate decomposition harness** (`foreign_bstr_to_lower_decomposition`, release) reads `instr_per_call = 438.00`, `local_call_requests_per_call = 61.00`, `driver_round_trips_per_call = 3.00` — the deterministic figures to quote; its ns/call is both N- and load-dependent, so a cross-session absolute is meaningless. What remains on this workload is **not** call setup: 438 IR instructions for a 30-byte lowercase (≈14.6 per byte) is per-instruction execution cost, which is what the two `bs_*` inline sets below attack.
- **Cross-runtime ratios belong to `../../../../../../tools/bench/RESULTS.md`** — read them there, never a copy here. Both sides scale with host load, so the ratio is the comparable figure, an absolute ns is a same-window reading only, and `case_list_walk_elements` (100 M sys / 50 M rust) is the contention-immune anchor. The tier-vs-interpreter per-process effect reads 1.0–1.3× (`../../../../MEASURED.md`, N=30 interleaved sampling), and the untouched interpreter column has been seen to drift ~29 % across one 7-run set: quote a min-over-N and compare only figures from the same run set.

## The `foreign` byte-loop kernels: where the tier's cycles go
`tools/bench`'s four `foreign` cases (`cowboy_bstr:to_lower/1`, `cowboy_bstr:capitalize_token/1`, `emqx_base62:encode/1`, `emqx_base62:decode/1`) are **BIF-free compiled BEAM code**, not host dispatch: the decomposition harness reads `bif_calls_per_call = 0.00` for both Cowboy cases (`rooted_calls_per_call = 2.00`, `local_call_requests_per_call` 2–3, `driver_round_trips_per_call = 3.00`, `step_one`/`step_ext` `0`, `deopt_count` empty, `block_entry_misses = 0`), so the ratio is the **bitstring family's per-instruction cost** and any "BIF-call gap" framing of these four cases is wrong.
Measured on the runtime path (`to_lower/1` at N = 400 000, `cpu_core/cycles/u -F 2000`, `taskset -c 3`, self time) the prepared-program table already **hits**: `bitstrings::exec` 21.4 %, `matching::exec` 16.4 %, `exec_other` 7.6 %, `create::exec::{closure}` 4.6 %, `jit_bitstr` 4.1 %, and **no `drop_glue` rows at all** — the cost is inside the family, spread over ~20 symbols with no single >10 % hotspot (`exec`/`exec_other`/`create::exec` ≈41 % of self time on `to_lower`).
Each lever below is a **paired same-session A/B** over `tools/bench run --quick --runtime all --workloads foreign` with `$BEAM_RT` selecting the binary (the bench records it in `runtimes[].program`), `BENCH_TIER=baseline BEAM_RT_TIER=baseline`, `taskset -c 3`, one process at a time.
- **Lever 1 — the `bs_*` match/position shapes**, run inside a block instead of through one helper call per instruction per subject byte: 3 interleaved rounds, load 1.92–3.74 — `capitalize_token` **1.319×** (3 739.2 → 2 834.9 ns/call), `decode` **1.099×**, `encode` **1.071×**, `to_lower` **1.039×**, each reproducing to ≤0.6 % across the three rounds (spread 0.005 on `capitalize_token`). `to_lower` gains only 1.04× because its inner loop was already on the prepared fast form (one `integer` bind per byte), while `capitalize_token` spends its cycles on `bs_get_position`/`bs_set_position` plus three `bs_create_bin` shapes per element — exactly the position/`bs_match` bookkeeping the inline set removes.
- **Lever 2 — the `bs_create_bin` construction arm**: 6 interleaved rounds with the order rotated every round, load 1.88–3.22, 16.8–17.0 s per invocation — `encode` **1.0881×**, `decode` **1.0558×**, `to_lower` 1.0119×, `capitalize_token` 1.0032×.
- Per-round A/B vectors for Lever 2 (no-inline ÷ inline, measured inside the same round — the stability evidence): `to_lower` 1.0105 1.0052 1.0129 1.0206 1.0108 1.0161; `capitalize_token` 1.0076 1.0182 1.0035 1.0025 1.0084 0.9976; `encode` 1.0826 1.1027 1.0894 1.0770 1.1000 1.0817; `decode` 1.0637 1.0457 1.0270 1.0825 1.0474 1.0570. `encode` and `decode` clear the session floor in every one of the six rounds; `to_lower`'s 1.2 % and `capitalize_token`'s 0.3 % straddle 1.0 and are **not** claimed as effects.
- **The sys-side control measures the floor:** the *same* oracle binary ran in both legs, and its no-inline ÷ inline ratio reads `to_lower` 1.0081, `capitalize_token` 0.9802, `encode` 0.9955, `decode` 1.0097 — 0.2 % to 2.0 % per case with no code difference at all.
- The deterministic counters were **identical on all twelve runs** (`to_lower` 50 000, `capitalize_token` 40 000, `encode` 60 000, `decode` 60 000 calls), so they are the contention-immune anchor and only the paired A/B is quoted as a timing.
- **The seven match-context shapes beyond the classic set are coverage-only on these four kernels.** `beam_disasm` of the staged upstream sources (`cowboy_bstr.erl`, `emqx_base62.erl`) shows **zero** `bs_match_string`, `bs_skip_utf8`/`bs_get_utf8`, `bs_skip_utf16`/`bs_get_utf16` and `bs_skip_utf32`/`bs_get_utf32` instructions — OTP folds a binary literal ≤ 64 bits into `bs_match` — so every delta above comes from the construction arm's helper cut (no per-accumulator append-open door; `jit_write_bit_field` only for a field wider than 57 bits), never from the new shapes. Their gain would show on a real protocol/HTTP or serialization parser, which this workload family does not contain.
- A `bs_start_match3/4` **fresh** context stays helper-backed (a rooted 5-word `ErlSubBits` allocation); only the reuse/rebind path is inlined. `bs_get_binary2`, `bs_get_float2`, `bs_get_tail` and `bs_init_writable` also stay on the family.
- Method caveat: the bench's Rust-side `case_*_ns_per_call` is **N-dependent** (its own note records this), so only same-N comparisons are valid — every row above used one fixed N per case on both legs. A per-instruction C-like fast path inside the family remains the wrong lever: the family cost is spread thin across the prepared walk.

**The construction sites each kernel lowers** (deterministic, from `../foreign_kernel_tests.rs`'s cache-free compile of the staged upstream source — `SHAPE_CREATE_BIN`'s `inlined` delta plus the static-deopt census):
- `cowboy_bstr:capitalize_token/3` — **3 of 3** builds lower (`x` accumulators 1, `y` accumulators 2, const-bytes fields 1), `declined = 0`, `deopts = 0` of the 3 visited instances.
- `cowboy_bstr:to_lower/1`'s `-to_lower/1-` comprehension loop — **1 of 1**, on the **`Y`-slot** accumulator, `deopts = 0`.
- `emqx_base62:decode/2` — **2 of 6** visited instances lower, both **bit-granular** (`aligned = 0`), `declined = 4` (its non-append builds), `deopts = 0`.
- `emqx_base62:encode/2` — **3 of 3**, all on the `binary all` route, `declined = 0`, `deopts = 0`.

**A route's reachability is a run-time counter, never the static one.** The `binary all` door serves **any** byte-aligned bitstring window through the family's own `raw::heap_bits` accessor — the same definition of "the source's bytes" the `fallback` body reads, `HEADER_SUB_BITS` and `ErlHeapBits` both — which is what makes `emqx_base62:encode/2`'s `iolist_to_binary/1` result (a 4-byte on-heap `ErlHeapBits` binary) reachable: `deopt_count[BsCreateBin]` absent and `step_one_per_call` **1.00** (the kernel's own `BsStartMatch4`), against `5.00` — four whole-instruction interpreter re-executions plus `BsStartMatch4` — under an off-heap-refc-only gate. The static `deopts = 0` that `../foreign_kernel_tests.rs` prints is a **per-compile** counter that reads 0 for a family-served arm too, so it never proves a route reachable; the run-time `deopt_count[<variant>]`/`step_one_per_call` pair does.

**Helper calls a `bs_create_bin` build still pays per instruction** (from `../emit/bitstr_inline/`):
- The **aligned** route pays **exactly one** positioned `jit_append_cursor` call (`create_door::emit_append_cursor`): the accumulator's five `ErlSubBits`/`BinRef` words are proved in-block as refusal-only branches and the one call is the machine-private `&Machine` byte-cursor query. There is no append-open door on this route.
- The **bit-granular** route pays **one** positioned `jit_open_append_bin_any` (x-register accumulator) or `jit_open_append_bin_any_y` (`Y`-slot accumulator) call and then **no** per-field call whenever every field of the plan is at most `MAX_INLINE_FIELD_BITS` (57) bits (`create_field::emit_bit_field_store`).
- A bit-granular plan with **any field wider than 57 bits** keeps one `jit_write_bit_field` call per field (`create::emit_bit_fields`'s else arm); that helper is reachable only from there.
- The **`binary all` tail** pays **one** positioned `jit_append_binary_all` call (`create_binary::emit_binary_all`), which performs both the copy and the build's single window-end commit; the source may be an off-heap refc binary **or** an on-heap `ErlHeapBits` binary, and a non-bitstring source, a window not byte-aligned at both ends, an overlap with the accumulator's own payload or a short room answers `0` and hands the whole instruction to `fallback`.
- No route emits a per-field call on the aligned route (straight-line stores) and none emits a separate commit (the window end is one store, or folded into `jit_append_binary_all`).

## Known Issues
- **Wall clock is not resolvable on this host at the effect sizes the tier's levers produce** (≲2 %): the frame/fill and prologue-publish levers are therefore evidenced by deterministic counters only, and re-running their A/B expecting signal will not produce one. Quote the counters.
- **`jit_refresh_y` is the largest remaining in-node row and is not a live lever**: its removal is unsound until the `fold_step` `pc + 1` hole is closed (see the rejected range-crossing witness), and the same blocker forbids making any window derivation, the position store or the reduction charge conditional on prior state.
- **The flat profile's shares are single-window readings that inflate as the total shrinks**, and its seam rows predate the per-callee verdict table, so they price a once-per-call host consultation; the seam's per-call residual today is one slot load plus the invalidation `Cell` read. A second `list_walk` baseline profile with different shares is `../../../bench/CONTEXT.md`'s — the two are not to be averaged or compared row-by-row.
- **A static `deopts = 0` never proves a route reachable** — it reads 0 for a family-served arm too. Use the run-time `deopt_count[<variant>]` / `step_one_per_call` pair.
- **`remember_module` has no production caller** (tests only), and the tier cannot pre-empt it: `compiled_handle` runs before any `baseline::run_compiled*` body. A host would have to call it once per module it enters.
- **An off-heap-refc-only source gate makes the `binary all` route unreachable in practice** (`emqx_base62:encode/2`'s source is an on-heap `ErlHeapBits` binary); the door must keep reading bytes through the family's `raw::heap_bits`.
- **The figures here are provenance, not gates.** No test in this crate asserts a measured corpus count; the censuses assert liveness/consistency, and the corpus denominators (which kit, how many modules) belong to `../census/CONTEXT.md`.
- **A recorded pass's corpus denominator is that pass's**: a later corpus re-bases every counter, so never subtract one pass's total from another's — re-run the census for a comparable pair (`../census/CONTEXT.md`).
