# `baseline/inlineset` — what the tier inlines, and the rules each lowering obeys

## Intent
The authoritative per-shape record of the baseline tier's inline set: which instruction groups `emit_block` lowers in-block, the run-time guards each carries, the helper-backed families it routes natively without an interpreter step, and the invariants an added fast path must keep.
The emitter-side detail lives one level down in `../emit/CONTEXT.md` and `../emit/shapes/CONTEXT.md`; the driver, block ABI and helper inventory are `../runtime/CONTEXT.md`; every measured figure is `../measure/CONTEXT.md`.

## Key facts
- **Inline dispatch**: the per-instruction `match instr` in `emit_block`. Inlined groups: metadata no-ops,
  `Move` (in-bound x-registers, an addressable **`Y` slot** on either side behind the frame-window guard, a
  constant word, or a **literal-area term** behind the literal guard) / `Swap` (two `Loc` operands, a `Y`
  side via `emit_swap_y`), `InitYregs` (X/Y destinations), `Test` (the word-level predicates **and** the
  boxed-term header kinds, with a `Y`-slot source accepted), `SelectVal` (all-immediate alternatives, with a
  `Y`-slot scrutinee accepted), `SelectTupleArity` (a `Loc` tuple), cons readers (`GetList`/`GetHd`/`GetTl`,
  all destinations a `Loc`), `GetTupleElement` (a `Loc` source/destination), the destructive
  `SetTupleElement` (a `Loc` tuple), the small-int `gc_bif` arithmetic (`'+'/'-'/'*'`, the bitwise
  `band`/`bor`/`bsr`, and `div`/`rem` — an x-register **or Y-slot** operand/destination, behind the
  run-time frame-window guard), the 8 comparison BIFs, the named-BIF accessors (`erlang:hd/1`, `element/2` with a compile-time
  small-int index `>= 1`, `tuple_size/1` lowered in block through the aggregate read guards, and
  `erlang:byte_size/1`/`length/1` evaluated by the `bif_helper.rs::jit_bif_value` helper), `Jump`, the local
  tail calls (`CallLast` via `emit_tail_exit` for a compiled successor and `emit_tail_exit_to_driver` for a
  resolved-but-uncompiled one; `CallOnly` via `emit_exit`), the frame-preserving local `Call` (via
  `jit_call_store` + the `CALL_STORED` compare, then `emit_exit` when `Linker::is_compiled` holds the
  callee's block and `emit_in_block_call` on the lazy artifact's cross-function shape — see the in-block
  transfer bullet below), the cross-module calls
  (`CallExt`/`CallExtOnly`/`CallExtLast` via `emit_ext_call`), the receive-control family
  (`Send`/`LoopRec`/`LoopRecEnd`/`Wait`/`WaitTimeout`/`Timeout`/`RemoveMessage` via `emit::emit_receive` →
  `receive.rs::jit_receive`), the whole **family-owned surface** (`put_list`/`put_tuple2`, the native-record
  set, `make_fun3`/`call_fun`/`call_fun2`/`apply`/`apply_last`, the try/catch/raise set, the float set, the
  map set, `recv_marker_*` via `emit/family.rs::emit_family` → `family.rs::jit_family`; the whole bitstring
  family — the variants `families::bitstrings::claimed` names — via `emit/family.rs::emit_bitstr` →
  `bitstr.rs::jit_bitstr`, its own arm, which additionally emits the instruction's inline position store
  before the call because that helper does not store the position itself),
  the frame-discipline trio (`Deallocate` via `frame.rs::emit_deallocate`, `Return` via `::emit_return`,
  `DeallocateReturn` via `::emit_deallocate_return`), and the **heap / frame-admission** family
  (`allocate` via `heap.rs::emit_allocate`, `allocate_heap` via `::emit_allocate_heap`, `test_heap` via
  `::emit_test_heap`, `trim` via `::emit_trim`) — an inlined direct helper call that runs no interpreter
  step and hands the driver the helper's block-ABI word. The heap / frame-admission four are
  **non-terminating** (the interpreter's own arm returns `Step::Next`), so each continues in-block on the
  helper's `encode_target(func, pc + 1)` word and leaves the block with that word otherwise (always the
  `ERROR` of a failed admission or a failed trim); `allocate`/`trim` touch no x-register and emit **no**
  register refill (`emit_frame_change_continue`, which no longer takes an `Allocation` because the helper
  itself re-publishes the Y window, being the frame change), while
  `allocate_heap`/`test_heap` reach the host's heap-admission door — where a **collecting** host rewrites
  `machine.x` in place — and therefore refill; `allocate_heap` uses `emit_continue_check_helper_refresh`
  (the refill without an emitted `jit_refresh_y`, since it re-publishes inside the helper) and `test_heap`
  keeps `emit_continue_check` (its gated refresh survives — it changes no frame), each reaching that door
  **exactly once** per execution with the instruction's own `heap_need`/`live`. Everything else is the `_`
  arm; `FuncInfo` is deliberately there (it must deopt so a failed head clause raises `function_clause`)
  and `CallExt*` crosses modules via a driver round-trip by design.
- **The family-owned surface is one arm, except the bitstring family.** `emit_block` names every variant
  `crate::families::dispatch` claims and the core arms above do not, and routes each to
  `emit/family.rs::emit_family` → `family.rs::jit_family`, which runs the identical
  `crate::families::dispatch` call the interpreter's per-instruction step runs — so the lowering is
  interpreter-identical by construction and can never produce a different result. The emitted sequence is
  the shared helper contract (spill, call, continuation check), so the family arm is exactly as cheap as
  the receive arm, and every un-lowered instruction keeps its per-instruction deopt.
  The bitstring family is the exception: `bitstrings::claimed` routes its variants to
  `bitstr.rs::jit_bitstr` (a direct `families::bitstrings::exec` call, bypassing the router's variant
  re-match) instead, and sixteen `Bs*` shapes get their own native in-block arms from
  `../emit/bitstr_inline/` — the `## The bitstring inline set (sixteen shapes)` section below is their
  authoritative record.
- **Comparison-`test` lowering (in-block, no interpreter step).** The `Test` arm's `emit/test.rs::try_inline_test` falls through to `emit_test_helper` for a comparison the inline word/header subset declines, emitting a call to the `test_helper.rs::jit_test(rt, func, pc)` helper instead of a `jit_step_one` round trip: the six comparison kinds (`is_eq_exact`/`is_ne_exact`/`is_eq`/`is_ne`/`is_lt`/`is_ge`) at exactly two operands with a resolvable non-`NO_FAIL` fail label, whatever the operand kinds (a Y slot, a float register, a literal-area pointer, an immediate, an in-bound x-register, boxed-vs-boxed) — because a comparison must route through `beam_term`'s own `cmp`/`cmp_arith` (a boxed pointer is never word-compared; `is_eq_exact` is exact equality while `is_eq`/`is_ne`/`is_lt`/`is_ge` are the arithmetic comparison). The helper answers `TEST_TRUE`/`TEST_FALSE`; the block refills its cached x-registers and continues in-block on `TEST_TRUE`, branches to the instruction's resolved fail label on `TEST_FALSE`, and leaves any other word (the `ERROR` of a propagating read error) for the driver. A `NO_FAIL` `test` (which raises `function_clause`), an unresolved fail label, a non-comparison kind and an operand count other than two are deliberately not this lowering's and keep `jit_step_one` (the interpreter's own step).
- **Named-BIF lowering (`emit/bif.rs`, in-block, no interpreter step).** The `Instr::Bif` and `Instr::GcBif`
  arms try `emit/bif.rs::try_inline_bif` after the arithmetic and comparison shapes. Its predicates
  (`bif_shape`/`bif_uses_y`) are **purely syntactic** — the import's resolved names plus the operands'
  kinds, never the register allocation — so `emit/regalloc.rs::cacheable_touches`/`cacheable_writes` and
  `emit_block` always agree. Two routes: (a) the three pure accessors, each **reusing the aggregate
  read's own bytes** — `erlang:hd/1` is `aggregate::try_inline_get_hd`; `element/2` with a compile-time
  small-int index `>= 1` is `aggregate::try_inline_get_tuple_element` at `Index - 1` (whose
  `is_tuple` + `element < arity` guard *is* `1 =< Index =< tuple_size(T)`); `tuple_size/1` reuses
  `aggregate::emit_tuple_header_guard` and derives `make_small(arity)` from the header word it leaves
  behind — claimed from `Instr::Bif` only, which is how the corpus emits them; (b) `erlang:byte_size/1`
  and `length/1` (`Target::Value`), claimed from **either** variant (the corpus emits both as a collecting
  `{gc_bif,…}`), emitted as an `emit_helper_call` to `bif_helper.rs::jit_bif_value`, whose Rust body is the
  BIF's own semantics computed through the engine's own `read_operand`/`write_operand`:
  `bitstring_size(t).div_ceil(8)` — the byte size rounds **UP** (`byte_size(<<1:1>>)` is `1`) — and a
  proper-list count, each declining when the value would not fit a small integer. Small-int
  `band/2`/`bor/2`/`bsr/2` are lowered by `emit/arith.rs::fast_arith` instead (`band`/`bor` as a raw
  **tagged-word** `and_rr`/`or_rr`, exact for negatives with no untag/retag; `bsr` untag → `sar_ri` →
  range-check → retag, claiming only an **immediate** small-int count in `0..64`). `div/2`/`rem/2` are
  lowered by the same `emit/arith.rs::fast_arith` arm over the same tagged operand shapes: both untag
  with `sar`, test the divisor for zero **before** the `#DE` (a zero divisor, a float operand or a
  bignum falls back to the BIF), `cqo` + `idiv_rr`, then the quotient is range-checked against
  `MIN_SMALL`/`MAX_SMALL` (so `MIN_SMALL div -1` deopts to the exact bignum result) while the
  remainder is taken from `rdx` with no range check (`|rem| < |divisor|`). `intdiv/2` stays on the
  BIF (it floors, truncating would be a wrong result). No lowering here
  modifies the driver, the block ABI or a helper; `erlang:self/0` and `erlang:node/0` (the `bif0` pool)
  are host-owned (`self_pid`/`local_node` behind `ExecutionContext`) and still deopt — the `Bif0`
  variant has no arm at all.
- **Deopt sequence**: `emit_step_and_continue` = `emit_helper_call` (**spills first**, then `rdi` = the `rt` slot, the argument words in `rsi`/`rdx`/`rcx`/`r8`/`r9`, `call r11`) + the shared `emit_continue_check` (`cmp rax, encode_target(func,pc+1)`; equal ⇒ `fill` and fall through in-block, else `jcc Ne, done`). `emit_ext_call` (the `CallExt*` arm) reuses both: import resolution + frame discipline happen in `jit_ext_call` natively, and only the helper's `ENTER`/error/`Wait` words leave the block. Every compile-time refusal in `emit_block` routes through `emit_deopt`, which records the static-census deopt (test builds) and then runs `emit_step_and_continue`. The `bif_helper.rs::jit_bif_value` route reuses the same pair, so a value-BIF fast path, a declined value shape and a deopt are all the identical helper contract — the only difference is the word the helper returns.
- **The non-tail `call`'s callee entry is linked IN-BLOCK on the runtime path.** A compile-time `Linker::is_compiled` picks the transfer: a callee whose block is part of *this* compilation (the eager whole-module artifact, or a call inside the same function) keeps the linker's direct jump ([`emit_exit`]), while a **cross-function** callee the **lazy** per-function artifact has not compiled — the shape every cross-function non-tail call takes through `CodeCache::compiled_handle` — is emitted by `emit/link.rs::emit_in_block_call` after a call to `call.rs::jit_call_store_linked`. That helper stores the continuation **and** the seam probe first, then (on the seam's *declined* path only — a **served** callee must get neither a return address nor a transfer) resolves the callee's native block entry through `runtime.rs::enter_in_block`, the **same** resolver the return side uses (`return_word` → `enter_in_block` → `resume_in_block` → `resolve_resume_entry`/`cross_function_entry`), so the two in-block transfers can never drift. `enter_in_block` publishes the target entry in `JitRuntime::resume_entry` and reproduces the skipped driver iteration in the driver's own order — `Machine::set_current_code(func, pc)` of the **callee entry**, the `Machine::reductions` bump, then `ExecutionContext::reduce(1)?` — so a refused charge parks the machine exactly where a driver-side refusal parks it and the resumed slice runs each instruction exactly once; it then replaces the published `EntryTables` with the target function's. The emitted arm (`mov rdi,[rsp+RUNTIME_SLOT_DISP]` / `mov r11,[rdi+RUNTIME_RESUME_DISP]` / `test` / `je declined` / `emit_frame_teardown` / `jmp r11`) leaves **no** second spill (the helper call already spilled the dirty set) and performs a **tail** transfer, so Erlang non-tail recursion does not grow the native stack. Every decline — no artifact published, an address no block covers, a missing function, a failed lazy compile, an unsatisfied register-file bound, a served local-call, a **traced** run, `RefCell` re-entrancy, a refused `ctx.reduce` — leaves `resume_entry` null and puts the **pre-existing** `encode_target(target_func, target_pc)` word in `rax` (with `ERROR` for a refused charge), i.e. exactly the word the driver decoded before the transfer existed, with the continuation stored exactly once. The callee's own prologue re-publishes its position, so a mid-block resume stays exact. `call_ext*` deliberately keeps its driver round-trip: a cross-module transfer needs the driver-owned module-context registry (`Machine::switch_context`), the label-map/literal-area rebinding and per-callee artifact publication, and `JitRuntime::module`/`labels` are baked for one module (`ENTER` is the block ABI's only word for it). The Cranelift tier inherits `NativeCode::module_blocks`'s default `None` and is untouched. Test-only counters `Counters::in_block_calls`/`in_block_call_declines` price it.
- **Driver entry** (`run_native_outcome`, `run_native_label_outcome`): `enter_machine` (reset, seed `x[0..arity)`, `push_frame(0)`, `set_literals`, then the module-wide label map — **reused** from the artifact when it holds one (`RunLabels::Stored`, the map built with the artifact), built only otherwise (`RunLabels::Built`)) then `machine.enter_run(module, func)` then `drive`. The driver builds the `JitRuntime` (null literal base/end) and calls `rt.refresh_literals()` before the loop and again after every `Step::Enter`/`ENTER` arm, so the emitted literal guard always sees the active module's decoded literal area. `drive` latches `machine.trace_on`, `machine.bif_in_machine_on` (the cached `ExecutionContext::wants_bif_in_machine` answer, the same gate the interpreter's `Machine::drive` latches, so the in-machine BIF-dispatch door is taken identically on both tiers) **and** the reduction gate (`machine.reduce_on` = `wants_reduce()`, with `machine.reductions` zeroed at the entry — one `drive` call is one scheduling slice, the rule the interpreter's `Machine::drive` applies too), loops on `code.enter(rt, active_module, func, pc)`, and hands any address the tier has no compiled block for to one `Machine::step_instruction_with_entry(entry_module, …)` — `JitRuntime::entry_module` is the run's context-`0` module (never read by generated code), which the deopt helper threads to the BIF-dispatch funnel and the raise funnel.

  **Every driver-loop iteration charges one reduction unit at the block entry**, before `code.enter(...)`: the loop publishes the position with `Machine::set_current_code(func, pc)`, bumps `Machine::reductions` (saturating, in the same step as the hook, so the two always agree) and, when the latched gate is on, calls `ExecutionContext::reduce(1)?`. That is the native tiers' first and only pre-emption point; a host whose `reduce` is the default no-op declares `wants_reduce() == false` and pays one `bool` load per iteration and nothing else (byte-identical behaviour), while the engine-side counter is bumped either way, exactly as in `Machine::drive`. The position is load-bearing: the runner parks an exhausted machine at `Machine::current_code` and re-enters there, and at the block entry the published position **is** the address about to run with the block not yet executed, so a refusal parks exactly there and the resume replays no prefix (the address's instruction runs exactly once). A refusing charge from the call-resolution/BIF seams would instead refuse with the block's *entry* position current only **after** a prefix of the block had run, and the resume would replay that prefix (measured: `beam_rt -eval 'halt(0).'` then exits 3 with `unsupported: opcode: run: process blocked`), which is why those seams stay spend-only. One iteration is one **driver round-trip** — a natively executed block, or the per-instruction interpreter step the driver takes for an address no block covers — so the unit is a block entry, not an instruction: a synthetic loop that is one block per instruction is priced exactly like the interpreter (3 charges per iteration for `label`, `bif0`, `jump`), while a **natively linked local tail-call chain** (`call_last`/`call_only` linked between compiled blocks) never returns to the driver and is therefore priced **once** — `slice.beam`'s tail-recursive `fib/1` at n=18 costs **2** charges against the interpreter's **152**. That is the honest resolution limit of the block-entry charge and the tier's remaining pre-emption residual: such a chain is priced once and, having no refusing seam inside it, cannot end its slice. An **in-block continuation return** charges the very same unit in the very same order for the iteration it skips (`resume_in_block`, position store then bump then hook), so a tail-jumped return leaves `erlang:statistics(reductions)` and `process_info(_, reductions)` exactly as the round-trip path left them. Pinned by `tests/jit_reductions.rs`.
- **Compile-on-entry + layout-dependent register guard** (`enter_compiled_cached`): `CompiledModule::native_entry_cached(module, func, pc, &mut cached)` returns the block's entry together with the `highest_native_register` bound the artifact's layout requires (compiling the function first for a lazy artifact). The block is entered only when the running machine's `x` file covers that bound (`x.len() > bound`); otherwise, or when the address has no compiled block, `enter_compiled_cached` returns `None` and the driver takes exactly one interpreter step. `cached` is the driver's per-artifact `ResolvedFunction` handle (`DriverContext::entry_cached` for the context-`0` artifact, `CalleeCode::cached` per callee — one per artifact, because two artifacts are two mappings with independent function tables), so an entry that stays inside one function costs two `Vec` indexings with no `RefCell` borrow and no `Rc` clone, and only an entry into a **different** function re-resolves or lazily compiles it. The same iteration publishes the artifact itself (`JitRuntime::compiled`), which is what lets a continuation `return` resolve an entry in another function of the module without the driver; an interpreter-step iteration withdraws it. The bound is layout-dependent: an **eager** artifact reports the **whole-module** max (its seal-time links tail-call directly into other functions' blocks inside the one shared mapping, so the entered function's own bound would not cover the linked code), while a **lazy** artifact reports the entered **function's** own bound (each function owns its mapping; a cross-function *branch or tail call* still round-trips through the driver, which re-checks the target function's bound on its own entry, while a cross-function *continuation return* resolves and bound-checks the target in-block, see `return_word` above).
- **Resume driver** (`run_native_resume_outcome`, and its baseline-artifact wrapper `run_compiled_resume_outcome`): the **no-reset** counterpart of `run_compiled_outcome` (it does NOT call `enter_machine`). It mirrors `Machine::resume_outcome` — `machine.enter_run(module, func)`, the artifact's own label map (`compiled.labels()`, built once at compilation), then the shared `drive` entering the compiled block at the reported `(func, pc)` — so a slice suspended on the baseline tier resumes on it with interpreter-identical semantics. The reduction counter restarts per slice: the shared `drive` zeroes `machine.reductions` at its entry (one `drive` call is one scheduling slice, the interpreter loop's own rule) and `run_compiled_resume_outcome` additionally calls `machine.reset_reductions()` before entering, so a resumed slice's `Machine::reductions()` counts only that slice's own block entries, exactly as the interpreter's resume counts only its own instructions. A non-entry module context (a suspension inside a cross-module callee) is served the same way the interpreter's resume serves it: `drive` reads the context from `Machine::current_context`, lands in it (`switch_into` re-binds the callee's module, label map and literal area and resolves its blocks through `NativeCode::module_blocks`), and re-enters the callee's own `(func, pc)`.
- **Cross-module driver** (`drive`): a `Step::Enter` (from its own interpreter step, or the `ENTER` word a block hands back) switches context through `switch_into` — `Machine::switch_context`, re-bind module/labels/literals (`rt.refresh_literals()`), and the callee's blocks via `NativeCode::module_blocks` (the `BlockEntries` impl consults the per-thread `CodeCache`, staging the callee as a **lazy** artifact on first sight) — then continues in the callee's compiled code (its functions compiling on first entry), or on the per-instruction step when the tier has no blocks for it. The context switch is a driver round-trip by construction (each `CompiledModule`/`CompiledFunction` owns a separate executable mapping and `JitRuntime::module`/`labels` are baked for one module), but the `call_ext*` instruction itself is executed natively by `jit_ext_call`, so only the callee's entry goes back through the driver. A **traced** run refuses native entry and hands the slice to `Machine::drive`.
- **Variable-length native frame** (`emit/mod.rs::native_frame_regs` + `emit/mod.rs::frame_slot_len`, torn down by `emit/link.rs::emit_frame_teardown`). A block saves in its prologue, and restores in its teardown, **only** `rbx` (always: the `machine.x` base) plus the machine registers it actually holds as cache slots — not the canonical six-register callee-saved set (`emit/mod.rs::SAVED_REGISTERS`, still the canonical set the block ABI may touch, pinned against every per-block subset by a `debug_assert!` in `native_frame_regs`). The `rt` slot is sized `8` bytes when `1 + slots.len()` is even and `16` when odd, so `rsp` is 16-byte aligned at every helper call site for the pushes the block actually makes. A block with no cache slots (the majority) therefore performs **no** callee-saved push/pop at all. Deterministic corpus counters (`counters.rs`; one recorded pass, whose corpus definition and current size `../census/CONTEXT.md` owns): that pass's totals are `blocks = 597 333` and `ir_instrs = 3 585 490` (its corpus: the then-32 committed fixtures + a 1321-module installed-OTP sample = 1353 modules / 103 008 functions; the corpus as it stands is 1359 modules / 103 079 functions / 597 565 blocks / 3 586 410 range-instances), `cache_slots = 756 632`, push/pop ops **7 167 996 → 2 707 930** (−62.2 %: `blocks + cache_slots` per direction instead of `6 · blocks`), `emitted_bytes` **320 065 790 → 308 853 108** (−3.50 %), with `written_slots = 621 058`, the per-block cache-size histogram and every fill/spill **count** unchanged (the lever changes no register allocation). Throughput effect: **none measurable** — see `## Known Issues`.
- **The prologue loads only the block's live-in cache slots** (`Allocation::entry_fill`, produced by `emit/regalloc.rs` from the entry set of `emit/liveness.rs::fill_sets`, consumed by `emit/block.rs`'s prologue through `Allocation::entry_loads`). A cached register the block writes before it reads is never loaded at entry (that writing instruction sets it), and the per-block cache is self-contained — every block and continuation sub-block loads its own cache, so nothing is inherited from a predecessor's physical register. The read set is per-shape (`cacheable_reads` + each lowering's `reads()`), and a read-modify-write shape (`Swap`, an in-place destination that is also an operand) reports both sides as read, so the set is deliberately conservative; an absent table (a synthetic `Allocation` a unit test built directly) falls back to the whole cache. Deterministic corpus counters: prologue loads **756 632 → 352 537** (−53.4 %) and `emitted_bytes` **308 853 108 → 306 024 443** (−0.92 %), with `blocks`/`cache_slots`/`written_slots`/`ir_instrs` and both per-block histograms unchanged. Cumulative with the frame lever: push/pop ops 7 167 996 → 2 707 930, emitted bytes **320 065 790 → 306 024 443** (−4.39 %).
- **Block prologue position store / Y-window publish**: a **Y-free** block stores its entry position **inline** — `mov r10,[rdi+RUNTIME_CURRENT_CODE_DISP]` (`JitRuntime::current_code`, i.e. `&mut machine.current_code`), `mov r11, movabs pack_current_code(func, block_start_pc)`, `mov [r10], r11`; 24 B, three instructions, no helper call and no `rt`-slot reload — after its own frame-register pushes (`native_frame_regs`) and the `rt`-slot setup and before loading the cached x-registers, so a linked chain (which never returns to the driver) still advances `Machine::current_code` at block granularity. A block that must publish the window (`Allocation::prologue_publishes_y` — it touches a Y slot and not every one of those accesses follows an in-block `allocate`/`allocate_heap`/`trim`) calls `jit_publish_y(rt, func, pc)` **instead** — the same position store *plus* the current frame's Y-window refresh in one call, so publishing costs such a block nothing extra; a Y-touching block that fails the gate emits the plain position store, its publish having been dead work (see the next bullet).
- **Per-block Y-window publication** (the Y operand/destination axis every widened lowering shares). The window is the current top frame's `[y_base, y_end)` in `machine.stack`, held in `JitRuntime::{y_base,y_end}` at `RUNTIME_YBASE_DISP`/`RUNTIME_YEND_DISP`; `jit_publish_y`/`jit_refresh_y` refresh it via `JitRuntime::refresh_y_base`. A block "touches Y" exactly when `Allocation::y_last` is set (the highest pc whose instruction accesses a Y slot, derived from `arith::uses_y` — the union of every lowering's per-shape Y test); such a block's **prologue** publish is gated on `Allocation::prologue_publishes_y`, i.e. it publishes **unless every one of its Y accesses lies after an in-block `allocate`/`allocate_heap`/`trim`**. Those three helpers already call `JitRuntime::refresh_y_base` on their in-block continue arm (`Allocation::frame_republish_first` is the lowest pc of one, `Allocation::y_first` the lowest Y access), so the prologue's window would be overwritten before anything reads it and the block emits the plain inline position store (`emit_position_store`) instead (`prologue_publishes_y` is `y_first <= frame_republish_first`, else `true`). That is sound because a compiled block's control flow is **linear**: the block is entered only at its own start, and the only ways out of its middle are a branch/exit into another emitted range — each with **its own** prologue — or a continuation sub-block, itself a separate emitted range with its own `Allocation` and prologue. So reaching the block's first Y access necessarily executed that frame helper first, and the elided publish can never be read. It is **conservative by construction**: an `Allocation` whose analysis tables were not filled (a synthetic one a unit test built directly — `y_last` set but `y_first` absent) still publishes, so the only possible failure direction is a redundant publish, never a Y access against a window nothing published. Independently of the prologue gate, after an **in-block** helper call that changed **no** frame (`test_heap`, the deopt arm, `jit_family`, `jit_receive`, the value-BIF fast paths) a block emits `jit_refresh_y` **only when a later instruction of the block still accesses Y** (`Allocation::refresh_y_after(pc)` = `matches!(y_last, Some(last) if last > pc)`); a Y-free block keeps the plain position store and pays literally nothing. The **frame-changing** helpers (`jit_allocate`, `jit_allocate_heap`, `jit_trim`, `jit_deallocate`) re-publish the window **inside** the helper instead — they are the very parties that invalidate it, and `refresh_y_base` is a pure re-derivation from machine state — so no emitted `jit_refresh_y` follows them. The emitted guard is a pure rejection (`jae` to `jit_step_one`), and `y_base == y_end == null` (no live frame) rejects every slot, so the worst reachable state is "not yet published" (a deopt to the interpreter, which reads `machine.stack` itself) — never a stale window. An index the emitted `lea ... disp32` cannot address (`emit/operands.rs::y_addressable`) is refused at **compile** time. The lowerings that read or write the window are the small-int arith fast path, an inlined `Move`/`Swap` with a `Y` side, `InitYregs` with a `Y` destination, the cons/tuple readers and the `SetTupleElement` writer with a `Y` source/destination/tuple, `SelectTupleArity` with a `Y` tuple, and a `Y`-source `test`/`select_val`; each refuses the operand at compile time when the `Y` index is un-addressable, and each shares the guard emission in `emit/operands.rs` (`emit_guarded_y_address`/`_load`/`_store`, `Loc::load`/`guard_store`). Non-`Y` windows are never the access path: an instruction with a `Y` operand a given lowering does not claim deopts to the interpreter, which reads `machine.stack` itself. A Y slot is never charged to the x-register usage counts / `highest_native_register`.
- **Literal-source `Move` guard**: a `Move` whose source is a literal-area term is lowered behind a **run-time** check against `JitRuntime::literals_end` (never a baked pointer), because a cached block can outlive the `Arc<Module>` it was compiled for; a rejection deopts to the interpreter step, which reads the literal area itself.
- **Register-cache contract** (the `Allocation` and its spill/fill traffic live in `emit/regs.rs`).
  A block caches a **fixed** set of x-registers for its whole duration (`Allocation::slots`, the
  `emit/regalloc.rs` live-interval-ranked choice — an x-register is either *always* held in its
  machine register or *never* cached, so the two representations can never disagree).
  Both directions of the traffic are **partial**: `spill(buffer, allocation, site, pc)` stores back
  only `Allocation::spill_slots_at(pc)` — the cached registers **dirty at that pc**
  (`Allocation::spill_sets`, the `emit/regalloc.rs` forward dirty walk; the empty-table fallback is
  the whole `Allocation::written` set) — and `fill` reloads only `Allocation::fill_slots(pc)` — the
  registers the continuation can still observe, the block-local liveness of
  `emit/liveness.rs::fill_sets` unioned with the write set, `(live ∪ written) ∩ slots` — while the
  prologue load is the block's **live-in** slot set (`Allocation::entry_fill`, `FillSite::Prologue`), so a
  cached register the block writes before it reads is never loaded at entry.
  A cached register outside the spill set still holds exactly its `machine.x` value at every program
  point (so storing it would write back an unchanged word), and a cached register outside the fill
  set keeps a stale word that is only ever overwritten, never read (the write set is always in the
  fill set).
  Every helper-call `call_r` site (`emit/mod.rs::emit_helper_call`, which passes the instruction's
  own `pc` as the store pc, and `emit/link.rs`'s three exits `emit_exit`/`emit_tail_exit`/
  `emit_tail_exit_to_driver`, which carry a trailing `store_pc` separate from their branch target)
  spills first.
  Non-cached x-registers are addressed directly in `machine.x`.
- **Continuation sub-blocks — BOTH layouts.** A **continuation address** is the `pc + 1` a frame-preserving call stores in the live frame — one of `Instr::Call`, a non-tail `Instr::CallExt`, `Instr::CallFun`, `Instr::CallFun2` or `Instr::Apply` (`emit::stores_continuation`; the tail forms store no new continuation). The loader cuts a function into blocks only at `Instr::Label`s, so such an address generally lies **inside** a block. Both layouts lower one sub-block covering `[p, sub_block_end(...))` — the containing IR block's `end` capped at the next continuation address, so the ranges are disjoint and the total is linear — through the very same `emit_block` an IR block uses, so a sub-block is interpreter-identical by construction:
  - the **lazy** layout: `emit::compile_function` calls `emit_sub_blocks` after `emit_function`, storing the entry in `CompiledFunction::sub_entries`;
  - the **eager** layout: `emit::compile_module` calls `emit_shared_sub_blocks` **after every** IR block (so the block regions stay contiguous at the front of the shared mapping), storing the entry in `EagerLayout::sub_entries`.
  Both passes consult their `entries` table **first** and `sub_entries` second (a real block start always wins), so `Summary::block_count`/`code_map`/`code_address_range` keep describing IR blocks only; a sub-block reserves **no** entry label (nothing branches to a continuation address — the driver re-enters there after a deopt or a `Wait`) and it starts with a full block prologue. An address that is already a block start, or at/past the end of the function, needs no sub-block. **Both** passes derive the allocation for the range they emit — `allocate_registers_with_labels(module, labels, code, start, end)` — because an `Allocation` is entry-point-relative (`block_start`, the per-`pc` fill/spill tables, the live-in set): a sub-block is a fresh native function whose prologue loads only its own live-in cache, so the containing IR block's allocation would leave a register the block writes before `start` unloaded and would carry its dirty bits. The lazy pass folds the sub-block touches into the function `Summary` as a **superset**; the eager pass discards them, so the whole-module `Summary` stays exactly the IR blocks'. Both add `emit::sub_blocks_capacity_estimate` to the buffer estimate, so the extra code can never under-allocate the `CodeBuffer` (an under-estimate would be a `SystemLimit` compile error).


## The bitstring inline set (sixteen shapes)
Sixteen `Bs*` shapes are lowered **natively in-block, with no interpreter step**, by the shape module `../emit/bitstr_inline/` (`../emit/bitstr_inline/CONTEXT.md` owns its file layout and its shared emitters): fifteen match-context shapes that emit no helper call at all, plus the `bs_create_bin` construction shape, whose three routes carry one positioned helper call each and then that route's own writes -- straight-line byte stores (the byte-aligned route), in-block bit-field stores or a wide-field bit-write helper call (the bit-granular route), or one helper performing the copy and the build's only commit (the whole-binary route) -- see the authoritative `bs_create_bin` section below.
The fifteen helper-free shapes are `bs_get_position`, `bs_set_position`, `bs_test_tail2`, `bs_skip_bits2`, `bs_start_match3`, `bs_start_match4`, `bs_get_integer2`, a fully static `bs_match`, `bs_match_string`, `bs_skip_utf32`, `bs_get_utf32`, `bs_skip_utf16`, `bs_get_utf16`, `bs_skip_utf8` and `bs_get_utf8`.
Each `try_inline_bs_*` entry answers `Ok(false)` having emitted **zero bytes** when its `*_shape` predicate declines, and `emit/block.rs`'s sixteen arms sit **above** the `_ if bitstrings::claimed(instr) => emit_bitstr(...)` guard arm, so a decline falls through to `bitstr.rs::jit_bitstr` — the family's `jit_bitstr` helper, i.e. the behaviour every other `Bs*` variant keeps.
No shape's sequence allocates and none raises, so no moving collection can interleave inside one; the fifteen match-context shapes carry no `emit_position_store` and read the context block base once and reuse it, while the construction shape publishes its own instruction position through `emit_positioned_helper_call` because it calls a helper that may be entered.
Every guard that can reject a destination write (`Loc::guard_store` for a `Y` destination, the match-context guard) is emitted **before** that write, and a single-instruction shape commits its context `start` word **before** the destination register, because `Dst` may be the context register itself (`beam_asm:filter_essentials/1` compiles `ctx == dst == x(3)`); `bs_match` commits `start` once after its whole command list instead, so it accepts an aliasing destination only as that list's **last** command, and `bs_create_bin` commits its accumulator's window end after every payload write (the aligned route's byte stores and the bit-granular route's per-field bit writes alike).
A shape with more than one mutually exclusive success path still has **one** commit site: `bs_get_utf16` (BMP character vs surrogate pair) and `bs_get_utf8` (four lead-byte widths) each materialise their own bit length into `rcx` and jump to a single `commit` block that holds both the `start` write and — get form only — the bind, so "commits exactly once per execution" is structural rather than an argument about the paths happening to be exclusive.
A `fallback` is a **deopt** — `jit_step_one` re-executes the whole instruction with the same operands — so every lowering must be **re-execution idempotent**: a guard that can reach it runs while the machine is still un-mutated, which is why `bs_match` writes the context `start` word exactly once per path and never per command, and why every append door the construction routes use (`jit_append_cursor` on the aligned route, `jit_open_append_bin_any`/`jit_open_append_bin_any_y` on the bit-granular one, `jit_append_binary_all` on the whole-binary one) and a wide field's `jit_write_bit_field` **mutate nothing** (`../emit/bitstr_inline/CONTEXT.md`, pinned by `../bs_match_deopt_tests.rs` and `../bs_create_bin_tests.rs`).
A **fail** transfer mutates nothing, matching the family's own `fail_step`: `bs_match_string` and the six UTF opcodes write no word on any fail path (a truncated window, an invalid scalar, a surrogate, an overlong or malformed sequence, a pattern mismatch), so the resolved label's code observes the context exactly as the interpreter leaves it.
The shape predicates are the single decision: `emit/block.rs`, `emit/regalloc.rs`'s `cacheable_touches`/`cacheable_reads`/`cacheable_writes`/`is_inlined`, `emit/arith.rs::uses_y` and `emit/test/refusal_census.rs` all consult the same `*_shape` function, so an emitted register set and its refusal cannot disagree with the code that runs.

### `bs_get_position { ctx, dst }` — `position.rs::try_inline_bs_get_position`
- Predicate `get_position_shape(ctx, dst)`: `ctx` and `dst` are each an in-bound x-register or an addressable `Y` slot (`Loc::of`); nothing else.
- Run-time guards, in order: `dst`'s Y-window guard; the match-context guard (`is_boxed`, then `*boxed_val == HEADER_SUB_BITS`) → `fallback`; `start > MAX_SMALL` → `fallback`.
- Lowering: `make_small([ctx+16])` (`shl 4`, `or TAG_IMMED1_SMALL`) stored to `dst`.
- Fallback: one interpreter step — the family's whole-context snapshot, the only allocating `position_term` arm.

### `bs_set_position { ctx, pos }` — `position.rs::try_inline_bs_set_position`
- Predicate `set_position_shape(ctx, pos)`: `ctx` is a `Loc`; `pos` is a `Loc`, or a **constant** `Operand::Integer` in `0..=MAX_SMALL` or `Operand::Character` (`PosSource::{Loc, Constant}`) — a constant outside that range is `position_of`'s typed error.
- Run-time guards: the match-context guard → `fallback`; for a `Loc` source, `pos` is either a match context (boxed, header `== HEADER_SUB_BITS`, new start = `[pos+16]`) or a non-negative small integer (`(pos & IMMED1_MASK) == SMALL_TAG` and the biased value `>= 0`, else `fallback`).
- Commit: **one** word store to `[ctx+16]`, after every read (`ctx` may alias `pos`), with no destination register at all.
- Fallback: one interpreter step — the family's typed raise for a non-position term.

### `bs_test_tail2 { fail, ctx, bits }` — `tail.rs::try_inline_bs_test_tail2`
- Predicate `test_tail2_shape(labels, fail, ctx, bits)`: `ctx` is a `Loc`, `fail` is not `NO_FAIL`, and it resolves in the module's label map (the miss transfer needs its `(func, pc)` target).
- Run-time guards: the match-context guard → `fallback`; `end.saturating_sub(start) != bits` → `fail_arm`.
- `fail_arm` is the linker's exit to the resolved label with `ExitSpill::Required` — a terminator on that path only; the hitting path continues in-block.
- Fallback: one interpreter step — the family's `{badmatch,…}` raise, whose reason allocates, which is exactly why `NO_FAIL` is refused at compile time.

### `bs_skip_bits2 { fail, ctx, size, unit, flags }` — `tail.rs::try_inline_bs_skip_bits2`
- Predicate `skip_bits2_shape(...)`: `ctx` is a `Loc`; `size` is a **constant** `Operand::Integer` in `0..=MAX_SMALL` or `Operand::Character`; `size * unit` fits both `usize` and an `i64` immediate; `fail` is not `NO_FAIL` and resolves; `flags` is ignored because the family ignores it.
- Run-time guards: the match-context guard → `fallback`; `start.checked_add(nbits)` overflow (the carry flag) → `fail_arm`; `next > end` (**not** `>=`) → `fail_arm`.
- Commit: one word store to `[ctx+16]`; no destination register.
- Fallback: one interpreter step — a runtime `size`/`unit` (a register compare the sequence would not have) or a `NO_FAIL` raise.

### `bs_start_match3 { fail, bin, live, dst }` — `start_match.rs::try_inline_bs_start_match3`
- Predicate `start_match3_shape(labels, fail, bin, dst)`: `bin` and `dst` are each a `Loc`; `fail` classifies as `MatchFail::{Label, Family}` — `NO_FAIL` is `Family` (its `{badmatch, Subject}` reason allocates) and an unresolved label refuses.
- Run-time guards: `dst`'s Y-window guard **first**; then the subject classification — non-boxed → `miss`; header `== HEADER_SUB_BITS` → the `orig` check (a non-boxed `orig` is the hit; a boxed `orig` whose header is `HEADER_BIN_REF` is a refc window → `fallback`; anything else is the hit); header masked to `BITSTRING_TAG_MASK == HEAP_BITS_SUBTAG` → `fallback` (a fresh subject the family re-wraps through `make_ctx`); every other header → `miss`.
- Lowering: `mov <Dst>, <the subject word>` — a plain move, no reservation, because the family's hit arm is `write_operand(dst, value)`.
- `miss` takes the resolved label's linker exit, and a `MatchFail::Family` miss is the `fallback` step.

### `bs_start_match4 { fail, live, src, dst }` — `start_match.rs::try_inline_bs_start_match4`
- Predicate `start_match4_shape(module, labels, fail, src, dst)`: the same subject/destination `Loc` requirement; `fail` is decoded exactly as `resolve_match4_fail` decodes it — `Operand::Label` (`NO_FAIL` → `Family`, else resolved → `Label`), atom `"no_fail"` → `Family`, atom `"resume"` → `Resume`; any other atom, an unnameable atom id or another operand kind refuses.
- Run-time guards: the same `emit_start_match` body as `bs_start_match3`; a `Resume` shape has the **short** form — a single `header == HEADER_SUB_BITS` compare, whose miss is the `fallback` step (the family's `NO_FAIL` raise).
- Fallback: one interpreter step.

### `bs_get_integer2 { fail, ctx, live, size, unit, flags, dst }` — `integer.rs::try_inline_bs_get_integer2`
- Predicate `get_integer2_shape(...)`: `ctx` and `dst` are `Loc`; `size` is a **constant** (`Operand::Integer` in `0..=MAX_SMALL` or `Operand::Character`); `nbits = size * unit` passes `field_width_supported`; `flags` passes `field_is_unsupported`; `fail` is not `NO_FAIL` and resolves.
- Run-time guards, in order: `dst`'s Y-window guard; the match-context guard; `end.saturating_sub(start) < nbits` → `fail_arm` (the family's `fail_step`, never a raise); `emit_subject_view`'s subject classification → `fallback`; `emit_bit_extract`'s over-read guard and width guard → `fallback`.
- Lowering: `start + nbits` committed to `[ctx+16]` **before** `dst`, then `make_small` (zero allocation, the field is at most 32 bits) stored to `dst`.
- Fallback: one interpreter step — a **refc-window** subject (an `ErlSubBits` over a `BinRef`), a match-context subject, a bare `BinRef`, a literal-area subject and every non-bitstring, i.e. every form `emit_subject_view` does not classify as an on-heap `ErlHeapBits`.

### `bs_match_string { fail, ctx, bits, offset }` — `match_string.rs::try_inline_bs_match_string`
- Predicate `match_string_shape(labels, module, fail, ctx, bits, offset)` = `MatchStringShape::of(module, ctx, bits, offset)` (label-free: no `LabelMap`, so `emit/arith.rs::uses_y` derives the same answer as the emitter) plus the fail half — `NO_FAIL` and an unresolved label both refuse. `of`: `ctx` is a `Loc`; `Offset` names a byte **inside** the module's string table (an out-of-range offset is the family's own typed `unsupported`, which a predicate must not pre-empt); the compared pattern is at most `MAX_MATCH_BYTES = 64` bytes (the shape's code-size ceiling — one `movabs`–`cmp`–`jcc` triple per compared byte, budgeted by `BS_MATCH_STRING_PATH_BYTES`); and `Bits` does not exceed the table's remaining bit count, because `size > pattern.len() * 8` is the family's own always-fails branch. The `ceil(Bits / 8)` pattern bytes are **copied out** of the string table at compile time — never a pointer and never a bare offset, because a cached module's string area may be a different allocation.
- Run-time guards, in order: the match-context guard → `fallback`; `end.saturating_sub(start) < Bits` → `fail_arm`; `start % 8 != 0` → `fallback`; `emit_subject_view`'s subject classification → `fallback`; `start / 8 + ceil(Bits / 8) > num_bytes` → `fallback`.
- Lowering: one `movzx` byte load plus a `cmp` against a compile-time pattern byte and a `jne fail_arm` per **whole** pattern byte, then — for a `Bits` that is not a multiple of 8 — one final byte compared through a `Bits % 8` **high**-bits mask applied to both sides, then the single `start += Bits` commit. No destination: `writes()` is empty and the commit is a heap store into the context block, not an x-register write.
- Fallback: one interpreter step — a non-context, a non-byte-aligned `start` (the shape a preceding sub-byte `bs_skip_bits2`/`bs_get_integer2` produces, and the arm's legitimate-deopt row), a subject `emit_subject_view` refuses, an over-read, and `NO_FAIL`/an unresolved label.
- `fail_arm` is the resolved label's linker exit and writes nothing, matching the family's `fail_step`.

### `bs_skip_utf32 { fail, ctx, live, flags }` — `utf32.rs::try_inline_bs_skip_utf32`
- Predicate `skip_utf32_shape(labels, fail, ctx, flags)` = `Utf32Shape::of(ctx, flags)` plus the shared fail half (`NO_FAIL` and an unresolved label both refuse, since the raise's `{badmatch,…}` reason allocates). `of`: `ctx` is a `Loc`; `flags` does **not** ask for little/native endianness (`field_is_little`, i.e. `BSF_LITTLE` 2, or `BSF_NATIVE` 16 on this little-endian target) — this arm emits the big-endian read only, so the interpreter's own byte-swapping reader stays the one implementation of that form. `BSF_ALIGNED`/`BSF_EXACT`/`BSF_SIGNED` are lowered, because `decode_utf32` branches on the endianness alone.
- Run-time guards, in order: the match-context guard → `fallback`; `end.saturating_sub(start) < 32` → `fail_arm`; `emit_subject_view`'s subject classification → `fallback`; `start % 8 != 0` → `fallback`; `start / 8 + 4 > num_bytes` → `fallback`.
- Lowering: four `movzx` byte loads assembled most-significant byte first, two validity tests (`value > 0x10FFFF`; `value - 0xD800 <= 0x7FF` for the surrogate range, one subtract-and-compare), then the single `start += 32` commit. Nothing is bound.
- Fallback: one interpreter step — a non-context, a non-byte-aligned `start`, a subject `emit_subject_view` refuses, an over-read, `NO_FAIL`/an unresolved label.
- `fail_arm` covers both of the family's rejections — fewer than 32 remaining bits and an out-of-range or surrogate scalar — and writes nothing.

### `bs_get_utf32 { fail, ctx, live, flags, dst }` — `utf32.rs::try_inline_bs_get_utf32`
- `bs_skip_utf32`'s twin over the same shape type (`Utf32Shape` with `dst`), one predicate (`get_utf32_shape`) and one emitted body: it reads the same four bytes, carries the same guards and transfers to the same fail target. The one added compile-time condition is `dst` being a `Loc`.
- Run-time guards: `dst`'s frame-window guard **first** (before the match-context guard), then `bs_skip_utf32`'s chain.
- Lowering: the same read and validation, then the single `start += 32` commit, then the bind — `make_small(value)` (at most 21 bits), so nothing allocates. The commit precedes the destination store because `Dst` may be the context operand (`beam_asm:filter_essentials/1` compiles `ctx == dst`), and the commit goes through the block pointer the match-context guard left in `MOVE_SCRATCH` rather than a re-read of the now-overwritten operand.
- Fallback: `bs_skip_utf32`'s set plus a `Y` destination outside the published frame window.

### `bs_skip_utf16 { fail, ctx, live, flags }` — `utf16.rs::try_inline_bs_skip_utf16`
- Predicate `skip_utf16_shape(labels, fail, ctx, flags)` = `Utf16Shape::of(ctx, flags)` plus the shared fail half. `of`: `ctx` is a `Loc`; `flags` is big-endian (`decode_utf16` branches on endianness alone, so `BSF_ALIGNED`/`BSF_EXACT`/`BSF_SIGNED` are lowered and only `field_is_little` refuses).
- A character is **one or two** 16-bit words: a word outside `0xD800..=0xDFFF` is a BMP character consuming 16 bits, while a **high** surrogate (`0xD800..=0xDBFF`) consumes 16 more by requiring a following **low** one (`0xDC00..=0xDFFF`), decoding to `((w1 & 0x3FF) << 10 | (w2 & 0x3FF)) + 0x10000`.
- Run-time guards, in order: the match-context guard → `fallback`; `end.saturating_sub(start) < 16` → `fail_arm`; `emit_subject_view` → `fallback`; `start % 8 != 0` → `fallback`; `start / 8 + 2 > num_bytes` → `fallback`; then on the surrogate path only, `remaining < 32` → `fail_arm` and `start / 8 + 4 > num_bytes` → `fallback` — the pair gauges live on that path alone, so a BMP character at the very end of a subject is not forced to deopt because a *pair* would not have fit.
- Lowering: two mutually exclusive success paths — BMP (`len = 16`) and surrogate pair (`len = 32`) — converging on **one** `commit` block that performs the single `start += len` write; nothing is bound.
- Fallback: one interpreter step — a non-context, a non-byte-aligned `start`, a subject `emit_subject_view` refuses, an over-read on the taken path, `NO_FAIL`/an unresolved label.
- `fail_arm` covers the family's four malformed characters — fewer than 16 remaining bits, a lone **low** surrogate, a high surrogate with fewer than 32 bits remaining, and a high surrogate not followed by a low one — and writes nothing.

### `bs_get_utf16 { fail, ctx, live, flags, dst }` — `utf16.rs::try_inline_bs_get_utf16`
- `bs_skip_utf16`'s twin over the same shape type (`Utf16Shape` with `dst`), one predicate (`get_utf16_shape`) and one emitted body. The one added compile-time condition is `dst` being a `Loc`.
- Run-time guards: `dst`'s frame-window guard **first**, then `bs_skip_utf16`'s chain.
- Lowering: the same two paths and the same single `commit` block, whose body holds the `start` write **and** the bind (`make_small` of the BMP word or the composed astral scalar, at most 21 bits) — so there is exactly one commit site and one bind site per execution, and the commit still precedes the destination store for the `ctx == dst` aliasing case.
- Fallback: `bs_skip_utf16`'s set plus a `Y` destination outside the published frame window.

### `bs_skip_utf8 { fail, ctx, live, flags }` — `utf8.rs::try_inline_bs_skip_utf8`
- Predicate `skip_utf8_shape(labels, fail, ctx, flags)` = `Utf8Shape::of(ctx)` plus the shared fail half. `of` takes **no** flags: `decode_utf8` has no endianness to select and both UTF-8 family arms destructure `flags: _`, so **every** flags word is lowered.
- A character is one to four bytes and the **lead byte decides**: `0x00..=0x7F` is ASCII and stands alone, `0xC0..=0xDF` announces one continuation byte, `0xE0..=0xEF` two and `0xF0..=0xF4` three; `0x80..=0xBF` and `0xF5..=0xFF` can never lead.
- Run-time guards, in order: the match-context guard → `fallback`; `end.saturating_sub(start) < 8` → `fail_arm`; `emit_subject_view` → `fallback`; `start % 8 != 0` → `fallback`; the lead byte's own `start / 8 + 1 <= num_bytes` → `fallback`; then the taken path's `<len>*8` window check → `fail_arm` and its `start / 8 + len <= num_bytes` guard → `fallback`.
- Lowering: the lead byte is read once and classified into **four static paths** (0/1/2/3 continuation bytes) by a compare chain; each path runs its own fixed-count continuation reads with **static** shifts and masks and its own validity tests, and materialises the character's bit length into `rcx` before jumping to the single `commit` block. The one dynamic figure — `total` — drives the window check, the over-read guard and the commit, so no second classification is needed.
- Fallback: one interpreter step — a non-context, a non-byte-aligned `start`, a subject `emit_subject_view` refuses, an over-read on the taken path, `NO_FAIL`/an unresolved label.
- `fail_arm` covers all ten malformed characters `decode_utf8` rejects — a truncated lead byte, a continuation byte as the lead or a byte above `0xF4`, a sequence shorter than its lead announces, a non-continuation byte where one is required, an overlong form (`0xC0 0x80`, `0xE0 0x80 0x80`, `0xF0 0x80 0x80 0x80`), a surrogate code point, and a value above `0x10FFFF` — and writes nothing, never traps.

### `bs_get_utf8 { fail, ctx, live, flags, dst }` — `utf8.rs::try_inline_bs_get_utf8`
- `bs_skip_utf8`'s twin over the same shape type (`Utf8Shape` with `dst`), one predicate (`get_utf8_shape`) and one emitted body. The one added compile-time condition is `dst` being a `Loc`.
- Run-time guards: `dst`'s frame-window guard **first**, then `bs_skip_utf8`'s chain.
- Lowering: the same four paths and the same single `commit` block, whose body holds the `start` write **and** the bind (`make_small` of the decoded scalar, at most 21 bits) — one commit site and one bind site per execution, with the commit preceding the destination store for the `ctx == dst` aliasing case.
- Fallback: `bs_skip_utf8`'s set plus a `Y` destination outside the published frame window.

### `bs_match { fail, ctx, commands }` — `bs_match.rs::try_inline_bs_match`
- Predicate `bs_match_shape(labels, module, fail, ctx, commands)`: a **fully static** command list of `ensure_at_least`/`ensure_exactly`/`skip`/`integer`, every size/unit/stride a compile-time constant, every `ensure_at_least` unit a power of two, every `integer` field passing the tier's width and flag rules, at most one `Y` destination, and no `integer` destination that **is** the context slot except as the **last** command (mid-list it would overwrite the context term the fallback's re-execution re-reads; as the last command it is `beam_asm:filter_essentials/1`'s elided-context shape and stays accepted); `ctx` is a `Loc`, `fail` is not `NO_FAIL` and resolves.
- Run-time guards: each accepted `Y` destination's window guard first (at most one); the match-context guard; then per command in order — `ensure_at_least` tests `remaining % unit == 0` (masked) and `remaining >= size`, `ensure_exactly` tests `remaining == stride`, `skip` checks `checked_add` overflow then `> end`, and each `integer` repeats `bs_get_integer2`'s remaining/subject/extract guards. The running position lives in `rsi`, so every one of these guards runs while the context is untouched.
- Commit: `start` exactly once on the accepted path, after the last command, and once on `fail_arm` — where `rsi` already holds the **last successful** command's position, i.e. the family's own partial-progress state.
- Fallback: one interpreter step for the whole instruction, which is why no command may mutate the context before the last fallback-capable guard; `fail_arm` is the resolved label's linker exit.

### `bs_create_bin { dst, segments }` — `create.rs::try_inline_bs_create_bin`
- Predicate `CreateBinShape::of(module, dst, segments)`: **label-free** (it takes no `LabelMap` and no fail label) and purely syntactic, over the construction seam's `seam::append_plan`. The shape IS the compiler's linear accumulator build — the first segment a `private_append` of the accumulator itself, the remaining segments constant-width unsigned big-endian `integer` fields (`bits` in `1..=64`, a whole number of bytes or not — the widths alone pick the route; see the authoritative section below) and/or `string` constants — and the plan's field bit offsets must sum exactly to `tail_bits`. `dst`, `source` and every `Field::Bits` value resolve to a `Loc`: an in-bound x-register **or an addressable `Y` slot** (`operands.rs::y_addressable`), so `uses_y()` is `source.is_y() || dst.is_y() || any field value is a Y Loc`; a plan with more than `MAX_FIELDS = 16` fields or more than `MAX_TAIL_BYTES = 256` tail bytes refuses, the sequence being straight-line code.
- Run-time guards, in order: (1) `dst`'s frame-window guard (`Loc::guard_store`) — a rejected destination writes nothing; (2) the `Y` accumulator's frame-window guard (`Loc::guard_load`), **guard only** and before every write, because the post-helper re-reads of that slot address `y_base + k*8` directly; (3) one guarded load plus one `is_small` guard per `Field::Bits` value (`and` with `IMMED1_MASK`, `cmp` to `SMALL_TAG`) — a bignum is legal in a wide field and a non-integer is the family's `badarg`, so a non-small value must deopt, and every such guard runs before any write; (4) the route's positioned append-door call — the aligned route's inline refusal-only term-shape proof followed by one `jit_append_cursor` (`create_door.rs::emit_append_cursor`, which publishes the instruction's own `(func, pc)` inline and ends in its own `test rax, rax; jz fallback`), `jit_open_append_bin_any`/`jit_open_append_bin_any_y` for the bit-granular route, `jit_append_binary_all` for the whole-binary one (all through `emit_positioned_helper_call`, so the pre-call spill happens and the instruction's own `(func, pc)` is published), the accumulator crossing the block ABI as a **slot index** because `emit_helper_invoke` adds `movabs` immediates only — then `test rax, rax; jz fallback`, the **last up-front** guard, after which the bit-granular route's fields are in-block stores and only a field wider than `MAX_INLINE_FIELD_BITS` (57) bits issues a `jit_write_bit_field` call that re-checks its own room with the same `test rax, rax; je fallback`.
- Lowering, by route: the **aligned** route emits field byte stores at `cursor + field_offset` — a `Field::Bits` field is `nbytes` stores of `sar_ri(value_re_read, 4 + 8*(nbytes-1-i))` then `mov_mr8`; a `Field::ConstBytes` field is 8-byte `mov_ri` + `mov_mr` chunks then a `mov_ri` + `mov_mr8` byte tail, the bytes being **copies** of compile-time constants, never a `StrT` pointer (a cached module's string area may be a different allocation). The **bit-granular** route has no byte cursor at all: when every field of the plan is at most `MAX_INLINE_FIELD_BITS` (57) bits it writes them **in-block** (`create_field.rs::emit_bit_field_store`), keeping the door's payload base in a register, deriving the window end from the accumulator term once and storing each field's bytes straight-line at the absolute bit `end + field_offset_bits` with no per-field room re-query (the door's whole-plan `tail_bits` check is the only admission point), and only a plan carrying a wider field emits, per field and in order, one positioned `jit_write_bit_field(acc_slot, field_offset_bits, value_slot, nbits, flags)` — the flags words `WRITE_ACC_IN_Y`/`WRITE_VALUE_IN_Y` naming which machine file holds each term — whose helper re-derives the payload base and the window end from the general door, checks room for `field_offset_bits + nbits` and applies the family's own bit-granular write rule at that **absolute bit** position; the `ConstBytes` store above has no such form, which is why a mixed plan is refused at compile time. The **whole-binary** route is one positioned `jit_append_binary_all(acc_slot, src_slot, flags)` call whose helper copies the source and performs the build's single `ErlSubBits.end` store itself, so that route has no field phase and no tier-side commit. Every value is re-read after the helper, because the helper clobbers every caller-saved register: an x-register from `machine.x`, a `Y` slot through its **unguarded** four-instruction address re-derivation (once per field, not per byte) — sound because the up-front guard already proved the slot in frame and nothing between can move the frame. Then, on the aligned and bit-granular routes, the single window-end commit (`mov_mr` of `old_end + tail_bits` into `SUB_BITS_END_DISP`), emitted **inline**, after which nothing may fail; then the accumulator word (re-read the same way) into `dst` (its cache register, charged in `cacheable_writes`) and the in-block continue.
- **The mutation order is the whole correctness argument.** The family's build performs exactly one mutation beyond the field bytes, C's `sb->end = new_position`; committing that word *before* the payload stores would make the `fallback` (one whole-instruction interpreter step) append the tail a **second** time, because the window would already cover the bytes — a wrong result. So the commit is last, and every append door plus a wide field's `jit_write_bit_field` **mutate nothing** (`&Machine` throughout), so every guard that can reach `fallback` runs against the state the interpreter step will see; the payload bytes are written at the same offsets with the same values on every attempt, so a post-payload deopt re-produces them. On the whole-binary route the commit is the helper's own last act, after its own guards, so the same property holds through one call rather than through a block store.
- **The aligned route's field extraction is arithmetic (`sar_ri`), never logical (`shr_ri`).** The bit-granular route needs no such argument: `seam::write_bit_field` *is* the family's own write rule, bit for bit, so a bit field cannot disagree with the interpreter about a byte. The family hands `push_byte_field` the small value **sign-extended** to 64 bits (`small_value(field) as u64`), and the raw word's bit 63 is the small value's sign bit, so `sar` reproduces `(value as i64 as u64).to_be_bytes()`. An 8-byte field's top byte has shift count `60`, where a logical shift's zero fill would reach the stored low byte and write `-1` as `0F FF FF FF FF FF FF FF`; a non-negative field has bit 63 clear, so the two agree byte for byte and `sar` is unconditionally right. The count peaks at `4 + 8*7 = 60`, inside the encoding's one-byte immediate.
- Fallback: one interpreter step for the **whole** instruction. There is **no fail arm** — `bs_create_bin`'s `fail`-vs-`NO_FAIL` discrimination stays in the family, whose own value, fail transfer or raise is what the process observes.

### Deliberately left on `jit_bitstr`
A `bs_match` command list containing `binary`, `get_tail` or `=:=` declines the **whole** instruction: each builds a fresh term (`raw::make_binary` reserves unconditionally), so a moving collection could relocate the context block mid-list and the once-read block base would go stale.
`binary` matters most — its command group has the **same width** as `integer`'s, so a fall-through would read it as an integer field and bind an integer where a sub-binary is due, a wrong value rather than a refusal.
The tier's width rule `field_width_supported` accepts `nbits <= 16 || nbits == 32` (and `<= MAX_SMALL`), the widths `emit_bit_extract` covers — aligned 8/16/32 plus a bit-granular field under 16 bits — so a 17..=59-bit or a 64-bit field stays on the family.
A **runtime** (non-constant) `size`/`unit`/`stride` stays on the family: it would be a register compare the emitted sequence does not have.
An `ensure_at_least` **unit** that is not a power of two stays on the family: `remaining % unit` would no longer lower to a mask, and `unit == 0` is a division by zero.
A **literal-area subject** (`TAG_LITERAL_PTR` set), a **refc-window** subject (an `ErlSubBits` over a `BinRef`), a match-context subject, a bare `BinRef` and any non-bitstring subject stay on the family.
A **signed**, **little-endian**, or `native`-on-a-little-endian-host `flags` word stays on the family — the family's `erts_bs_get_integer_2` general reader, which sign-extends or byte-swaps.
`NO_FAIL` stays on the family wherever the shape has no `MatchFail::Family` arm (every field-extracting shape), because the raise's reason allocates; an **unresolved** fail label stays on the family and keeps its exact `unknown_label`.
A `bs_match` list with **more than one** `Y` destination stays on the family, because the sequence keeps one live Y address.
`bs_create_bin` is lowered only for the private-append construction shape — on whichever of its three routes the field widths and the tail pick, see the authoritative section below — and every other form stays on the family; `emit/test/refusal_census.rs`'s `create_bin_refusal(dst, segments)` attributes a refusal with a closed two-value vocabulary — `"literal-area subject"` when any operand is `Operand::Literal(_)`, else `"other"`, the honest catch-all, because the shape predicate answers a single `None`. The forms behind `"other"`:
- anything `seam::append_plan` answers `None` for: a **plain** (`private: false`) or later-position append, an append unit outside `1`/`2`/`4`/`8`, a `binary` segment that is not a whole-binary `all` tail, a `float` or `utf*` segment, an `all` or runtime (`Dynamic`) size or unit, a `little`/`signed`/`native` flag, a field of zero width or wider than a machine word, an unresolvable `StrT` window, or a plan with no fields;
- a fresh non-append `[integer 8]` shape — no private append means it allocates;
- an un-addressable accumulator, field value or `dst` — a literal-area operand, an out-of-bound x-register index, or a `Y` index the emitted `lea`'s `disp32` cannot address (`Loc::of`);
- more than `MAX_FIELDS` fields or more than `MAX_TAIL_BYTES` tail bytes;
- at run time, a non-small field value (the `is_small` guard), a `Y` destination or accumulator slot outside the published frame window (the slot guards, and `Machine::y` answering `None`), and an accumulator or source the route's own door refuses — `jit_append_cursor` on the aligned route (which also requires a byte-aligned window end), `seam::open_append_any` behind `jit_open_append_bin_any`/`_any_y` on the bit-granular one, `jit_append_binary_all` on the whole-binary one — whether for want of room, a target that is not this machine's writable accumulator, or a window end the plan's `unit` does not position-gate C's way (`append_unit_allows`: `unit == 8` needs `end_bits % 8 == 0`, any other `unit > 1` needs `end_bits % unit == 0`, `unit <= 1` ungated), plus, on the bit-granular route, one `jit_write_bit_field` refusal for a field wider than `MAX_INLINE_FIELD_BITS`; every one of those doors answers `0`;
- a field list whose **bit** offsets do not sum to the plan's `tail_bits`, the `end` commit would then publish a window over bits nobody wrote;
- a `Route::BitGranular` plan carrying a `Field::ConstBytes` (`string`) field — there is no straight-line constant copy at a non-byte-aligned position, so a mixed plan stays on the family's own loop rather than gaining a per-byte helper-call form.
`bs_get_binary2`, `bs_get_tail`, `bs_init_writable` and the float ops (`bs_get_float2`, `bs_put_float`, `bs_get_float`) have **no arm at all**.
Two of those are deliberate refusals rather than pending work, because both results **allocate** and no straight-line helper-free sequence can produce one:
- **`bs_get_binary2`** builds a sub-binary — an on-heap `ErlHeapBits`, or above `ERL_ONHEAP_BINARY_LIMIT` (64 bytes) the `[BinRef(3 words)][ErlSubBits(5 words)]` refc pair — through `raw::make_binary`'s rooted reserve-then-write seam, and the two parts must be allocated as the two objects `beam_gc::copy` sizes and moves separately (the `072ecd0745` defect: a single contiguous block writes past the allocation). A specialized helper would also buy nothing, because `bitstr.rs::jit_bitstr` already reaches `crate::families::bitstrings::exec` **directly** rather than through `crate::families::dispatch`, so an arm would not remove a dispatch step — it would only add minted machinery.
- **`bs_get_float2`** boxes the decoded float (`make_float_rooted`, an allocating heap-float reservation) and rebinds the match context in the same instruction, so it stays on the family for the same reason.
A refused shape is the tier's normal discipline rather than a gap: it emits zero bytes, records **zero** static deopts (a claimed shape falls through to the family route, not to the `_` deopt arm) and yields the interpreter's own result. A future arm for either would need the shape the construction arm already models: every guard first, one **positioned** helper call performing the rooted reserve → re-read → commit → write-dst discipline, and a fail path that mutates nothing.
Which refusals actually occur in the corpus is **measured**, not asserted here: `emit/test/refusal_census.rs` attributes every `Bs*` instance to inlined / refused-by-reason / no-arm, and `../census/CONTEXT.md` records the closed reason vocabulary and the accounting pin.
The reasons above that the census can see are the allocating command, the runtime size/unit/stride, the width rule, the flag rule, the second `Y` destination and — for `bs_create_bin` — its two closed buckets `literal-area subject` / `other`; the rest are structural (they change the emitted sequence rather than its attribution).
Each shape also has a `#[cfg(test)]` compile-time counter — `inlined(SHAPE_*)` in `../emit/bitstr_inline/mod.rs` — because what an inline arm needs pinning is its **emission decision**, not a run-time helper entry: the fifteen match-context shapes call no helper at all, so nothing else could observe them, and for the construction shape the counter is the one instrument that proves the arm ran for *either* route and that a refused plan emitted zero bytes.

## `bs_create_bin` -- three routes, one predicate (authoritative)

The arm lowers the compiler's linear accumulator build (`bs_init_writable` + a single
`bs_create_bin` whose first segment is `private_append`, i.e. the writable accumulator and
`binary all`). Its shape is `CreateBinShape`, whose `route()` picks one of two static field
sequences and whose `binary_all` member picks the third ahead of that split; all three share
the guard prefix and the accumulator-into-`dst` phase, and none allocates.

- **The picking rule, exactly.** A plan whose only segment after the accumulator is a
  whole-binary `binary all` tail is route (c). Otherwise `Route::Aligned` iff `tail_bits % 8 == 0`
  **and** every field's width is a multiple of 8 (`ConstBytes` fields always are). Everything
  else -- including a width below one byte and a non-multiple above one byte -- is
  `Route::BitGranular`. The static-field route is a function of the widths alone, so an exact
  byte-multiple width provably never leaves the aligned sequence.
- **The predicate's width range is `1..=64` bits** (`bits == 0` and `bits > 64` are refused:
  a zero-width field moves no cursor, and a wider value exceeds the one word the writer masks
  into the field). There is no "whole-byte only" rule: an accepted width below or above a whole number of bytes is what puts a plan on `Route::BitGranular`.
- **The three routes' helpers.** `Aligned`: the block proves the accumulator's term shape
  itself, as refusal-only branches over five frozen words
  (`create_door.rs::emit_append_cursor`), and then makes one `jit_append_cursor` call for the
  machine-private half (the cursor is `payload base + tail_bits/8`; `0` = refuse);
  `seam::open_append` is `#[cfg(test)]`, the reference answer that door is pinned against.
  `BitGranular`: `jit_open_append_bin_any` / `jit_open_append_bin_any_y` (they return the
  payload base, take the plan's `unit` and apply C's append-position gate), after which the
  fields are **in-block stores** (`create_field.rs::emit_bit_field_store`) whenever every field
  is at most `MAX_INLINE_FIELD_BITS` (57) bits; only a wider field costs one
  `jit_write_bit_field(src_slot, field_offset_bits, value_slot, nbits, flags) -> 1/0` call,
  which asks the seam once for room for `field_offset_bits + nbits` bits and then writes
  exactly those bits. `Whole-binary`: one
  `jit_append_binary_all(acc_slot, src_slot, flags) -> accumulator/0` call which copies the
  source and performs the build's **only** `ErlSubBits.end` store itself. Every helper takes
  `&Machine`, mutates nothing, and reports contention as `0`.
- **The guard order**: (1) the destination's frame window, (2) the source's frame window when
  the accumulator is a `Y` slot (plus, on route (c), when the appended source is one), (3) per
  bit field one guarded load + `is_small` (`IMMED1_MASK` vs `SMALL_TAG`), (4) the route's own
  door, whose `test rax,rax; je fallback` is the last up-front guard, then (5) on the
  bit-granular route a wide field's write, whose own `test rax,rax; je fallback` re-checks the
  room the seam just granted (a defensive duplicate for a consistent plan, kept because the
  helper is the only authority on writability). Every guard precedes every mutation, and on the
  aligned and bit-granular routes the only mutation is the single window-end commit after all
  fields.
- **`BitGranular` + `ConstBytes` is refused** by the predicate: there is no constant-bytes
  store on the bit-granular sequence, and mixing one would commit a window end from the
  aligned half before the bit fields' room check.
- **Refusal vocabulary is closed**: a refused plan emits zero bytes, records no static deopt and
  is the family's own path; no new typed error exists on this arm.

### Deliberate refusals

- **`binary all` in any position but the plan's last and only field** (a preceded or followed
  `binary all`) stays on the family: a run-time length fixes no static offset for itself or any
  later field.
  Accepted as the last and only one, its own bit offset is `0` (it starts at the accumulator's
  window end), so the destination position it lands on is static and route (c) lowers it — the
  copy and the build's single commit both inside the door, with no tier-side field phase and no
  tier-side commit.
- **A fresh non-append `[integer 8]`** (`emqx_base62:decode/2`'s temp `<<DecodeChar>>`,
  14x/call) stays on `jit_bitstr`: `raw::make_binary` **allocates** a fresh result (an on-heap
  `ErlHeapBits` or the refc pair) through the rooted seam, which a straight-line helper-free
  sequence cannot do without an admission point.
