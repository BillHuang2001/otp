# `beam_engine` native baseline JIT tier (`src/jit/baseline/`)

## Intent
The first `JitBackend` the engine builds: it lowers basic blocks of a `beam_loader::Module`
into real `extern "C"` x86-64 functions and runs them through a driver loop, deopting any
instruction it does not inline to exactly one interpreter step. Correctness-first mechanism, not an
optimiser (DeepDive §F): every natively-executed result is interpreter-identical by construction.
Backend behind `Tier::BaselineJit`; `jit-beamasm` aliases this tier.

The artifact (`CompiledModule`) comes in **two layouts**:
- **Eager** (`emit::compile_module`): every function lowered up front into **one** sealed
  `CodeBuffer`, with a whole-module block-entry table, so the seal-time `Linker` links a taken
  branch to a successor block of **another** function as a direct jump. Produced by
  `JitBackend::compile` and `CodeCache::get_or_compile`; the layout whole-module introspection and
  cross-function direct links need.
- **Lazy** (`code::CompiledModule::lazy`): nothing lowered up front; each function is lowered into
  its **own** sealed `CodeBuffer` on that function's first entry, driven through
  `NativeCode::enter(rt, module, func, pc)` → `CompiledModule::native_entry`. Produced by
  `CodeCache::compiled_handle` (the path behind `run_baseline_cached*` and
  `cached_module_blocks`), so a fresh process pays only for the functions it enters. A
  cross-function branch is absent from that function's block map, so the `Linker` emits the
  target's `(func, pc)` word and the driver compiles the target on entry.

## API Surface
- `code.rs` — `CompiledModule` (caller-owned artifact in the two layouts; `entry`, `native_entry`
  [the compile-on-entry point], `block_count`, `cached_registers`, `highest_cached_register`,
  `highest_native_register`, `code_len`, `code_address_range`, `code_map`, plus the two per-artifact
  derived values computed **once at creation**: `fingerprint` [the module's content hash, so a
  `CodeCache` hit never re-hashes the IR] and `labels` [the module-wide label map a run reuses
  instead of rebuilding]), plus the lazy layout's unit `CompiledFunction` (`buffer`, `entries` [IR-block
  starts], `sub_entries` [continuation sub-blocks], `summary`), the eager layout's parallel
  `EagerLayout::sub_entries` table, and the `Summary` register/block aggregate. `entry`/`native_entry`
  probe `entries` first and `sub_entries` second, so a real IR-block start always wins.
- `mod.rs` — `BaselineJit` (zero-sized `JitBackend`); the driver
  `run_compiled`/`run_compiled_outcome`/`run_compiled_label_outcome`, the no-reset
  `run_compiled_resume_outcome`, and the shared `enter_machine`/`run_native`/`run_native_outcome`/
  `run_native_label_outcome`/`drive`; the `RunLabels` enum (`Stored` = the artifact's map, `Built` =
  the per-run fallback); the `NativeCode` trait (`enter(rt, module, func, pc)` + `module_blocks` +
  `labels`) and its `BlockEntries` impl; `enter_compiled`/`block_entries`.
- `runtime.rs` — the block ABI (`HALT`/`ERROR`/`WAIT_BIT`/`ENTER`, `encode_target`/`decode_target`/`encode_wait`/`decode_wait`, `JitRuntime` — including its `entry_module` field, the run's context-`0` module handed to the BIF-dispatch and raise funnels and never read by generated code — `RUNTIME_{MACHINE,XREGS,YBASE,YEND}_DISP`) and the helpers: `jit_step_one` (per-instruction deopt → `Machine::step_instruction_with_entry`; a `Step::Enter` returns the `ENTER` word with the target in `JitRuntime::enter`), `jit_ext_call` (the native `call_ext`/`call_ext_only`/`call_ext_last` arm: import resolution through the host seam plus the variant's frame discipline — the `Continuation::Address{func, pc+1, context}` store, nothing, or `pop_frame_checked` — handed to the driver as `ENTER`), `jit_step_ext` (the `call_ext*` deopt carrying the host's **already-computed** seam answer into `Machine::call_ext_dispatch`, so a declined import is resolved **once**, not twice), `fold_step` (the single `Step`→block-ABI encoder both `jit_step_one` and `jit_step_ext` end in), `jit_tail_call` (`Machine::pop_frame_checked` for a linked local `call_last`), `jit_deallocate`/`jit_return`/`jit_deallocate_return` (the frame-discipline helpers: the checked pop and/or the continuation read, encoding the instruction's own outcome as the block-ABI word — sharing `return_word` for the continuation→word mapping and `report_frame_error` for the typed diagnostic, with the `FrameExitHelper`/`ReturnHelper` fn-pointer types), `jit_set_position` (`Machine::set_current_code`, the block prologue's position store), `jit_publish_y` (`jit_set_position` + `JitRuntime::refresh_y_base` in one call — a Y-accessing block's prologue publish) and `jit_refresh_y` (the gated post-helper window refresh).
- `test_helper.rs` — the comparison-`test` helper (`jit_test`, `TEST_TRUE`/`TEST_FALSE`): it resolves the instruction at `(func, pc)` in the active module and evaluates a two-operand comparison `test` through `beam_term`'s `cmp`/`cmp_arith`, reporting the outcome as a boolean (the block-ABI `ERROR` word on a propagating read error) and handing anything it does not own to `jit_step_one`.
- `emit/` — `compile.rs` (the compilation entry points `compile_module`/`compile_function`, `emit_function`,
  the continuation sub-block emitters `stores_continuation`/`sub_blocks_capacity_estimate`/`emit_sub_blocks`/
  `emit_shared_sub_blocks`, and the code-size estimates) and `mod.rs` (the per-instruction dispatch, the
  compiled-block shape and the helpers) + live-interval regalloc; `Allocation::y_last`/`refresh_y_after`
  and the Y-window publish/refresh emission; per file — `operands.rs`
  (`y_offset`/`y_addressable`/`y_register`), `arith.rs` (the Y operand/destination support + `uses_y`) and
  `regalloc.rs` (the `y_last` derivation, and the "a Y slot is not an x-register" rule). See `emit/CONTEXT.md`.

## Key facts
- **Inline dispatch**: the per-instruction `match instr` in `emit_block`. Inlined groups: metadata no-ops, `Move`/`Swap` (`Move` over in-bound x-registers **or an addressable `Y` slot on either side**, behind the run-time frame-window guard; `Swap` over two in-bound x-registers), `Test` (the word-level predicates **and** the boxed-term header kinds — see `emit/CONTEXT.md`), `SelectVal` (all-immediate), `SelectTupleArity`, cons readers (`GetList`/`GetHd`/`GetTl`), `GetTupleElement`, the destructive `SetTupleElement`, small-int `gc_bif` `'+'/'-'/'*'` (an x-register **or Y-slot** operand/destination, behind the run-time frame-window guard — see the Y-window fact below), the 8 comparison BIFs, `Jump`, local tail calls (`CallLast` via `emit_tail_exit`, `CallOnly` via `emit_exit`), the receive-control family (`Send`/`LoopRec`/`LoopRecEnd`/`Wait`/`WaitTimeout`/`Timeout`/`RemoveMessage` via `emit::emit_receive` → the `receive.rs::jit_receive` helper, which runs the same family body the interpreter's dispatch does and hands the driver the resulting block-ABI word), and the frame-discipline trio (`Deallocate` via `frame.rs::emit_deallocate`, `Return` via `::emit_return`, `DeallocateReturn` via `::emit_deallocate_return`) — an inlined direct helper call that runs no interpreter step and hands the driver the helper's block-ABI word. Everything else is the `_` arm.
- **Comparison-`test` lowering (in-block, no interpreter step).** The `Test` arm's `emit/test.rs::try_inline_test` falls through to `emit_test_helper` for a comparison the inline word/header subset declines, emitting a call to the `test_helper.rs::jit_test(rt, func, pc)` helper instead of a `jit_step_one` round trip: the six comparison kinds (`is_eq_exact`/`is_ne_exact`/`is_eq`/`is_ne`/`is_lt`/`is_ge`) at exactly two operands with a resolvable non-`NO_FAIL` fail label, whatever the operand kinds (a Y slot, a float register, a literal-area pointer, an immediate, an in-bound x-register, boxed-vs-boxed) — because a comparison must route through `beam_term`'s own `cmp`/`cmp_arith` (a boxed pointer is never word-compared; `is_eq_exact` is exact equality while `is_eq`/`is_ne`/`is_lt`/`is_ge` are the arithmetic comparison). The helper answers `TEST_TRUE`/`TEST_FALSE`; the block refills its cached x-registers and continues in-block on `TEST_TRUE`, branches to the instruction's resolved fail label on `TEST_FALSE`, and leaves any other word (the `ERROR` of a propagating read error) for the driver. A `NO_FAIL` `test` (which raises `function_clause`), an unresolved fail label, a non-comparison kind and an operand count other than two are deliberately not this lowering's and keep `jit_step_one` (the interpreter's own step).
- **Deopt sequence**: `emit_step_and_continue` = `emit_helper_call` (**spills first**, then `rdi` = the `rt` slot, the argument words in `rsi`/`rdx`/`rcx`/`r8`/`r9`, `call r11`) + the shared `emit_continue_check` (`cmp rax, encode_target(func,pc+1)`; equal ⇒ `fill` and fall through in-block, else `jcc Ne, done`). `emit_ext_call` (the `CallExt*` arm) reuses both: import resolution + frame discipline happen in `jit_ext_call` natively, and only the helper's `ENTER`/error/`Wait` words leave the block.
- **Driver entry** (`run_native_outcome`, `run_native_label_outcome`): `enter_machine` (reset, seed `x[0..arity)`, `push_frame(0)`, `set_literals`, then the module-wide label map — **reused** from the artifact when it holds one (`RunLabels::Stored`, the map built with the artifact), built only otherwise (`RunLabels::Built`)) then `machine.enter_run(module, func)` then `drive`. `drive` latches `machine.trace_on` **and** `machine.bif_in_machine_on` (the cached `ExecutionContext::wants_bif_in_machine` answer, the same gate the interpreter's `Machine::drive` latches, so the in-machine BIF-dispatch door is taken identically on both tiers), loops on `code.enter(rt, active_module, func, pc)`, and hands any address the tier has no compiled block for to one `Machine::step_instruction_with_entry(entry_module, …)` — `JitRuntime::entry_module` is the run's context-`0` module (never read by generated code), which the deopt helper threads to the BIF-dispatch funnel and the raise funnel. The driver itself charges **no** reduction (neither `Machine::reductions` nor `ExecutionContext::reduce` is touched anywhere in `mod.rs`/`runtime.rs`): the engine's per-instruction reduction accounting lives solely in the interpreter's own dispatch loop (`Machine::drive`), so under this tier the `reduce` hook is never called and `Machine::reductions()` stays 0/lower-bound (a host that still pre-empts an allocating loop does so through its `ensure_heap`/`ensure_heap_full` doors, which the deopted `test_heap`/`allocate_heap` reach).
- **Compile-on-entry + layout-dependent register guard** (`enter_compiled`): `CompiledModule::native_entry(module, func, pc)` returns the block's entry together with the `highest_native_register` bound the artifact's layout requires (compiling the function first for a lazy artifact). The block is entered only when the running machine's `x` file covers that bound (`x.len() > bound`); otherwise, or when the address has no compiled block, `enter_compiled` returns `None` and the driver takes exactly one interpreter step. The bound is layout-dependent: an **eager** artifact reports the **whole-module** max (its seal-time links tail-call directly into other functions' blocks inside the one shared mapping, so the entered function's own bound would not cover the linked code), while a **lazy** artifact reports the entered **function's** own bound (each function owns its mapping and a cross-function transfer round-trips through the driver, which re-checks the target function's bound on its own entry).
- **Resume driver** (`run_compiled_resume_outcome`): the **no-reset** counterpart of `run_compiled_outcome` (it does NOT call `enter_machine`). It mirrors `Machine::resume_outcome` — `reset_reductions()` at slice start (so the resumed slice's `Machine::reductions()` matches the interpreter's), `machine.enter_run(module, func)`, the artifact's own label map (`compiled.labels()`, built once at compilation), then the shared `drive` entering the compiled block at the reported `(func, pc)` — so a slice suspended on the baseline tier resumes on it with interpreter-identical semantics. A non-entry module context (a suspension inside a cross-module callee) is served the same way the interpreter's resume serves it: `drive` reads the context from `Machine::current_context`, lands in it (`switch_into` re-binds the callee's module, label map and literal area and resolves its blocks through `NativeCode::module_blocks`), and re-enters the callee's own `(func, pc)`.
- **Cross-module driver** (`drive`): a `Step::Enter` (from its own interpreter step, or the `ENTER` word a block hands back) switches context through `switch_into` — `Machine::switch_context`, re-bind module/labels/literals, and the callee's blocks via `NativeCode::module_blocks` (the `BlockEntries` impl consults the per-thread `CodeCache`, staging the callee as a **lazy** artifact on first sight) — then continues in the callee's compiled code (its functions compiling on first entry), or on the per-instruction step when the tier has no blocks for it. The context switch is a driver round-trip by construction (each `CompiledModule`/`CompiledFunction` owns a separate executable mapping and `JitRuntime::module`/`labels` are baked for one module), but the `call_ext*` instruction itself is executed natively by `jit_ext_call`, so only the callee's entry goes back through the driver. A **traced** run refuses native entry and hands the slice to `Machine::drive`.
- **Block prologue position store / Y-window publish**: a **Y-free** block calls `jit_set_position(rt, func, block_start_pc)` after the six saved-register pushes and the `rt`-slot setup and before loading the cached x-registers, so a linked chain (which never returns to the driver) still advances `Machine::current_code` at block granularity. A block whose code **accesses a Y slot** (`Allocation::y_last.is_some()`) calls `jit_publish_y(rt, func, pc)` **instead** — the same position store *plus* the current frame's Y-window refresh in one call, so publishing costs such a block nothing extra.
- **Per-block Y-window publication** (the Y operand/destination of the small-int arith fast path and of an inlined `Move`). The window is the current top frame's `[y_base, y_end)` in `machine.stack`, held in `JitRuntime::{y_base,y_end}` at `RUNTIME_YBASE_DISP`/`RUNTIME_YEND_DISP`; `jit_publish_y`/`jit_refresh_y` refresh it via `JitRuntime::refresh_y_base`. Publication is **per block and compile-time gated** on `Allocation::y_last` (the highest pc of a block whose instruction accesses Y, derived by `arith::uses_y`): a Y-accessing block publishes in its prologue (above) and, after an **in-block** helper call, emits `jit_refresh_y` **only when a later instruction of the block still accesses Y** (`Allocation::refresh_y_after(pc)` = `matches!(y_last, Some(last) if last > pc)`); a Y-free block keeps the plain position store and pays literally nothing. The emitted guard is a pure rejection (`jae` to `jit_step_one`), and `y_base == y_end == null` (no live frame) rejects every slot. An index the emitted `lea ... disp32` cannot address (`emit/operands.rs::y_addressable`) is refused at **compile** time. The only lowerings that read the window are the arith fast path and an inlined `Move` with a `Y` side (the two share the guard emission in `emit/operands.rs`): `uses_y` is exactly `fast_arith(...).uses_y() || (a `Move` whose `move_shape` is claimed and reads a `Y` slot)`. Every other instruction with a `Y` operand (`get_list`/`get_hd`/`get_tl`/…) is **not** a window access — it deopts to the interpreter, which reads `machine.stack` itself. A Y slot is never charged to the x-register usage counts / `highest_native_register`.
- **Register-cache contract** (the `Allocation` and its spill/fill traffic live in `emit/regs.rs`): a block caches a **fixed** set of x-registers for its whole duration (`Allocation::slots`, the `emit/regalloc.rs` live-interval-ranked choice — an x-register is either *always* held in its machine register or *never* cached, so the two representations can never disagree). Both directions of the traffic are **partial**: `spill` stores back only the block's **written** set (`Allocation::written`, the cached destination registers its inline lowerings may write — a static superset, derived by `regalloc.rs::cacheable_writes` from each shape's `writes()`), and `fill` reloads only `Allocation::fill_slots(pc)` — the registers the continuation can still observe, the block-local liveness of `emit/liveness.rs::fill_sets` unioned with the write set, `(live ∪ written) ∩ slots` — except the prologue load, which is always the whole cache (`FillSite::Prologue`). A cached register outside the spill set still holds exactly its `machine.x` value at every program point (so storing it would write back an unchanged word), and a cached register outside the fill set keeps a stale word that is only ever overwritten, never read (the write set is always in the fill set). Every `call_r` site (`emit/mod.rs`, `emit/link.rs`) spills first. Non-cached x-registers are addressed directly in `machine.x`.
- `FuncInfo` is NOT a metadata no-op: it must deopt so a failed head clause raises `function_clause`.
- **Continuation sub-blocks — BOTH layouts.** A **continuation address** is the `pc + 1` a frame-preserving call stores in the live frame — one of `Instr::Call`, a non-tail `Instr::CallExt`, `Instr::CallFun`, `Instr::CallFun2` or `Instr::Apply` (`emit::stores_continuation`; the tail forms store no new continuation). The loader cuts a function into blocks only at `Instr::Label`s, so such an address generally lies **inside** a block. Both layouts lower one sub-block covering `[p, containing_block.end)` through the very same `emit_block` an IR block uses — identical shape rules, guards and deopts, so a sub-block is interpreter-identical by construction — giving the driver a native entry there instead of one interpreter step per remaining instruction:
  - the **lazy** layout: `emit::compile_function` calls `emit_sub_blocks` after `emit_function`, storing the entry in `CompiledFunction::sub_entries`;
  - the **eager** layout: `emit::compile_module` calls `emit_shared_sub_blocks` **after every** IR block (so the block regions stay contiguous at the front of the shared mapping), storing the entry in `EagerLayout::sub_entries`.
  Both passes consult their `entries` table **first** and `sub_entries` second (a real block start always wins), so `Summary::block_count`/`code_map`/`code_address_range` keep describing IR blocks only; a sub-block reserves **no** entry label (nothing branches to a continuation address — the driver re-enters there after a deopt or a `Wait`) and it starts with a full block prologue. An address that is already a block start, or at/past the end of the function, needs no sub-block; a second call nested inside an earlier sub-block's range gets its own (the code is duplicated, correctness first). `emit_sub_blocks` runs after `emit_function`, so its code sits at the **end** of the per-function buffer and the `code_map` regions stay contiguous. The lazy register touches are folded into the function `Summary` as a **superset**; the eager pass deliberately reuses the **containing IR block's** allocation and discards its touches, so the whole-module `Summary` is untouched. Both add `emit::sub_blocks_capacity_estimate` to the buffer estimate, so the extra code can never under-allocate the `CodeBuffer` (an under-estimate would be a `SystemLimit` compile error).

## Known Issues
- **The tier's per-slice cost on a message-passing workload is the entry-module resolution, NOT the deopts — and for a real `.beam` that resolution is now O(1).** Every `run_baseline_cached*` slice entry/resume resolves the entry module through `CodeCache::compiled_handle(&Module)` (`../cache/mod.rs`), whose `ModuleKey::of` is a **two-variant** identity: `Digest([u8; 16])` = the module's **load-time MD5** (`Module::checksum`, read as a plain `Copy` — no hash, no allocation) for a real `.beam`, else `Content { name, fingerprint }` over the whole-IR hash (`module_fingerprint`, a full `Debug`-render hash of the decoded IR) for a synthetic all-zero-checksum `Module::default()`. A real `.beam` therefore resolves with **zero** IR hashes on every slice, primed or not, and only a synthetic module can fall to `module_fingerprint` per slice; the address memo (filled by `cached_module_blocks(&Arc<Module>)` on the cross-module *callee* path and by the host-facing `cache::remember_module(&Arc<Module>)` on the *entry* path) is a redundant micro-optimisation on that digest path. The interpreter tier never touches `CodeCache`. Measured by the two-process copy-bound probe (`tests.rs::the_entry_module_priming_is_measured_on_both_tiers`, both tiers named, with `/proc/loadavg` and the per-pass `module_fingerprint` count): the probe's **synthetic** modules take the `Content` fallback, so unprimed they re-hash per slice (≈6.8× the interpreter) and primed they read ≈0.8× with **zero** hashes — the tier's own work is parity-or-better and the whole gap is that hash; a real `.beam` needs no priming to reach the same zero-hash result (`cache/tests.rs::a_real_loaded_beam_never_rehashes_its_ir_on_any_entry_path`). A host still closes the synthetic gap by calling `remember_module` once per module it enters; the tier cannot pre-empt it (`compiled_handle` is called before any `baseline::run_compiled*` body). Deopt inlining — including the natively-lowered receive family — does **not** move the wall-clock on this shape: the deopt chain is cheap relative to that hash. (The lazy `native_entry` per-block lookup is an O(1) `RefCell` probe + `Rc::clone`, no hash/scan; the driver charging 0 reductions vs the interpreter's 1/instruction is a real tier divergence but ≈1 ns/instruction.)

## Constraints
- `#![allow(unsafe_code)]` on `mod.rs`/`runtime.rs`/`receive.rs`/`test_helper.rs` and `emit/*` (JIT zone); every `unsafe` block carries a `// SAFETY:` rationale.
- Never panic / never a wrong result: an unsupported shape is the typed `error::unsupported`.

## Test Strategy
`tests.rs` unit-tests the ABI encoding, the `#[repr(C)]` runtime layout, regalloc, the fast-path constants/arithmetic, the deopt/yield folding (a deopted `wait` folds to `RunOutcome::Wait`), and that a deopted collecting `test_heap` reaches the host's admission door exactly once and reloads the cached registers afterwards. It also pins that the comparison-`test` lowering leaves no `Test` entry in the two-process copy-bound probe's per-opcode `jit_step_one` table. `the_y_window_traffic_of_the_committed_fixtures_is_measured` first pins the Y-traffic instrument on a synthetic shape with known traffic (2 loads / 2 stores / 2 same-block slot reuses), then counts the 27 committed `erlc` fixtures: **12 guarded Y accesses over 235,977 emitted bytes**, 9 `Y`-touching blocks and **1** same-block slot reuse — the measured bound on what a per-block single-slot Y-value cache could save. Tier equivalence on real modules is in the crate's `tests/jit*.rs` (see `../CONTEXT.md`), which drive the **lazy** path through `Machine::run_with_tier`.

## Routing Table
- `code.rs` → the artifact in its two layouts (`CompiledModule`/`CompiledFunction` [`entries` + `sub_entries`]/`EagerLayout::sub_entries`/`Summary`) + the compile-on-entry point.
- `emit/` → the compilation entry points + the per-instruction emitters (`compile.rs` `compile_module`/`compile_function`/`emit_function` + the continuation sub-blocks `stores_continuation`/`sub_blocks_capacity_estimate`/`emit_sub_blocks`/`emit_shared_sub_blocks` + the code-size estimates; `mod.rs` dispatch + helpers, `move/test/select/aggregate/arith/compare/frame/link/operands/regalloc.rs`, `regs.rs` (the register cache: the `Allocation` + `spill`/`fill` + `SpillSite`/`FillSite`) — `frame.rs` is the frame-discipline trio `Deallocate`/`Return`/`DeallocateReturn`), the Y-window publish/refresh emission (`Allocation::y_last`/`refresh_y_after`), the `emit/operands.rs` Y readers (`y_offset`/`y_addressable`/`y_register`) plus the shared guarded-Y emission (`emit_guarded_y_address`/`emit_guarded_y_load`/`emit_guarded_y_store`), the `emit/arith.rs` + `emit/move.rs` Y operand/destination support (`uses_y`) and the `emit/regalloc.rs` `y_last` derivation; see its `CONTEXT.md`.
- `receive.rs` → the `jit_receive` `send`/receive-control helper; `runtime.rs` → block ABI + `jit_step_one`/`jit_ext_call`/`jit_tail_call`/`jit_deallocate`/`jit_return`/`jit_deallocate_return`/`jit_publish_y`/`jit_refresh_y`
  + `RUNTIME_YBASE_DISP`/`RUNTIME_YEND_DISP`; `tests.rs` → unit tests.
- `test_helper.rs` → the comparison-`test` helper (`jit_test`, `TEST_TRUE`/`TEST_FALSE`) + its `jit_step_one` fallback for anything it does not own.
- `counters.rs` → the `#[cfg(test)]` structural counters (`Counters`, `record_*`, `snapshot`): the `jit_step_one`/`jit_step_ext` deopts (a `Test` deopt is keyed by kind — `"Test(IsEqExact)"`, `"Test(IsTuple)"`, … — in `deopts_by_variant`, so which `test` shapes still deopt is readable per predicate), the driver round-trips, the prologue position/publish calls, and the **register-cache traffic** (`record_spill`/`record_fill`/`record_block`: per-block IR/byte/cache/write-set sizes + spill/fill stores by site), and the **Y-window traffic** (`record_y_access`/`record_y_invalidation`/`record_block`: emitted guarded `Y` loads/stores + their emitted bytes, `Y`-touching blocks, the in-block refresh sites, and the same-block `Y`-slot reuse count) — designed so **one recorded run yields both** the current written-set spill stores and the full-cache count the previous model would have emitted.
