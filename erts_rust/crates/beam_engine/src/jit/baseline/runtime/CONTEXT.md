# `runtime` — baseline block ABI, `JitRuntime` and the per-instruction helpers

## Intent
`../runtime.rs` owns the native baseline tier's block ABI, the `JitRuntime` struct every compiled block receives in `rdi`, and the helper set the emitters call.
Each helper performs exactly the `Machine` work the interpreter's own arm for that instruction performs, in the interpreter's own order, and hands the driver a block-ABI word, so a lowered instruction costs one helper call and never a `jit_step_one` deopt.
The driver, the two artifact layouts and the tier seam live one level up in `../mod.rs` and `../code.rs`; the emitters that *call* these helpers live in `../emit/`.

## The block ABI
- The target word is `encode_target(func, pc)` / `decode_target`; a suspended `receive` is `encode_wait` / `decode_wait` under `WAIT_BIT`.
- `HALT` = `-1` (the bottom frame returned; `x(0)` is the result), `ERROR` = `-2` (a typed `BeamError` is stored and the driver surfaces it), `ENTER` = `-3` (a cross-module transfer, its `(context, func, pc)` in `JitRuntime::enter`), `LOCAL_DECLINE` = `-4` (the local-call seam declined, so the call proceeds as an in-machine local call) and `SUSPEND` = `-5` (a BIF suspend: the un-applied instruction's address rides the driver-only `JitRuntime::suspend` side channel, because a `SUSPEND` word carries no address — exactly like `ENTER` — and the host's resume **re-executes** that instruction).
- `CALL_STORED` = `-5` is consumed **inside** the emitted block (the `Call` arm compares `rax` against it and branches to `done` on a mismatch), is disjoint from `HALT`/`ERROR`/`ENTER`/`LOCAL_DECLINE`/`WAIT_BIT`, and never reaches the driver's decoder.
- `TEST_TRUE`/`TEST_FALSE` are the comparison-`test` helper's two boolean answers.
- `encode_local_call(callee, arity)` packs the resolved `(function index, arity)` pair into one word so the five helper payload words still fit `emit_helper_call`'s argument registers; `LOCAL_CALL_ONLY`/`LOCAL_CALL_LAST` are the tail forms' kind words.

## `JitRuntime` (the `#[repr(C)]` layout generated code addresses)
- A block receives `rt` in `rdi` and holds `rbx` = `rt->x_regs`, the `machine.x` base.
- The field offsets are pinned constants: `RUNTIME_MACHINE_DISP`, `RUNTIME_XREGS_DISP`, `RUNTIME_YBASE_DISP`, `RUNTIME_YEND_DISP`, `RUNTIME_LITERALS_DISP`, `RUNTIME_LITERALS_END_DISP`, `RUNTIME_SLOT_DISP` (where the emitted code re-loads `rt` from) and `RUNTIME_RESUME_DISP` (the in-block transfer probe).
- `y_base`/`y_end` are the current top frame's Y window in `machine.stack`, refreshed by `JitRuntime::refresh_y_base` (a re-derivation from `Machine::frames.last()` + `machine.stack.as_mut_ptr()`) or, on a frame helper's own success arm, published from the `(y_base, y_count)` that helper's `Machine::push_frame_window` just computed (`JitRuntime::publish_y_window` — the same two stores without the frame-stack reload and the index scaling).
- `literals_base`/`literals_end` are the active module's decoded literal area, refreshed by `JitRuntime::refresh_literals`; `literal_bounds` exposes the pair.
- `entry_module` is the run's context-`0` module, handed to the BIF-dispatch and raise funnels and never read by generated code.
- `compiled` is the artifact the current iteration published, which is what lets a continuation `return` resolve an entry in another function of the module without the driver; an interpreter-step iteration withdraws it.
- `enter` carries a cross-module target, `resume_entry` an in-block transfer target, and `suspend` the address of an un-applied suspended BIF instruction (the driver-only side channel a `SUSPEND` word's address rides).

## The helpers (crate-visible; `crate::jit::baseline::runtime::…`)
- `jit_step_one` — the per-instruction deopt: it records the position and calls `Machine::step_instruction_with_entry`; a `Step::Enter` becomes the `ENTER` word with the target in `JitRuntime::enter`.
- `jit_ext_call` — the native `call_ext`/`call_ext_only`/`call_ext_last` arm: resolves the import through the host seam and applies the variant's frame discipline (the `Continuation::Address{func, pc+1, context}` store, nothing, or `pop_frame_checked`), handing the driver `ENTER`.
- `jit_step_ext` — the `call_ext*` deopt, carrying the host's **already-computed** seam answer into `Machine::call_ext_dispatch`, so a declined import is resolved **once**, not twice.
- `resolve_ext_entry` — the import→entry resolution `jit_ext_call` uses.
- `fold_step` — the single `Step`→block-ABI encoder both `jit_step_one` and `jit_step_ext` end in; `fold_ok_step`/`fold_err` are its **unboxed** split, so the family helper (`../family.rs::jit_family`) and the bitstring helper (`../bitstr.rs::jit_bitstr`) let the success path never box.
- `jit_local_call` / `probe_local_call` — the local-call *as-BIF* seam probe, answering `LOCAL_DECLINE`; it takes the whole resolution as block-ABI immediates (the `LocalCallHelper` type, the packed `encode_local_call(callee, arity)` word and the `LOCAL_CALL_ONLY`/`LOCAL_CALL_LAST` + `deallocate` pair), so it re-decodes no instruction and resolves no label, the re-derivation surviving only as a `debug_assert!` cross-check at zero release cost.
- `decorate` — the context-`0` `with_uncaught_frames` raise decoration the deopt and family helpers apply on their `Err` arm.
- `jit_tail_call` — the checked `Machine::pop_frame_checked` a linked local `call_last` performs.
- `jit_deallocate` / `jit_return` / `jit_deallocate_return` — the frame-discipline helpers: the checked pop and/or the continuation read, each encoding the instruction's own outcome as a block-ABI word, sharing `return_word` for the continuation→word mapping and `report_frame_error` for the typed diagnostic, with the `FrameExitHelper`/`ReturnHelper` fn-pointer types.
- `jit_allocate` / `jit_allocate_heap` / `jit_test_heap` / `jit_trim` — the **heap / frame-admission** family: the interpreter's own `Machine::push_frame_window` (the `allocate` helpers' push, which also hands back the new frame's `(y_base, y_count)` so the helper publishes the Y window from figures already in hand — `JitRuntime::publish_y_window`, no re-derivation) / `ensure_heap` / `trim` calls, in the interpreter's own order, each answering `encode_target(func, pc + 1)` or `report_frame_error`'s `ERROR`, with the `FrameSizeHelper`/`HeapNeedHelper`/`AllocateHeapHelper` fn-pointer types.
- `jit_set_position` — `Machine::set_current_code`, the block prologue's position store.
- `jit_publish_y` — `jit_set_position` **plus** `JitRuntime::refresh_y_base` in one call: a Y-accessing block's prologue publish.
- `jit_refresh_y` — the gated post-helper window refresh.
- `JitRuntime::refresh_literals` / `literal_bounds` — the literal-area publication `../emit/move.rs`'s literal guard reads.
- The fn-pointer type aliases are `NativeBlock`, `StepHelper`, `TailHelper`, `PositionHelper`, `RefreshHelper` and `LocalCallHelper`.

## The deopt sequence
- `emit_step_and_continue` (`../emit/mod.rs`) = `emit_helper_call` (**spills first**, then `rdi` = the `rt` slot, the argument words in `rsi`/`rdx`/`rcx`/`r8`/`r9`, `call r11`) plus the shared `emit_continue_check` (`cmp rax, encode_target(func, pc+1)`; equal ⇒ `fill` and fall through in-block, else `jcc Ne, done`).
- `emit_ext_call` (the `CallExt*` arm) reuses both: import resolution and frame discipline happen in `jit_ext_call` natively, and only the helper's `ENTER`/error/`Wait` words leave the block.
- Every compile-time refusal in `emit_block` routes through `emit_deopt`, which records the static-census deopt (test builds) and then runs `emit_step_and_continue`.
- The `../bif_helper.rs::jit_bif_value` route reuses the same pair, so a value-BIF fast path, a declined value shape and a deopt are the identical helper contract — the only difference is the word the helper returns.

## The driver loop and its reduction charge
- `run_native_outcome`/`run_native_label_outcome` call `enter_machine` (reset, seed `x[0..arity)`, `push_frame(0)`, `set_literals`, then the module-wide label map — **reused** from the artifact when it holds one (`RunLabels::Stored`, the map built with the artifact) and built only otherwise (`RunLabels::Built`)), then `machine.enter_run(module, func)`, then `drive`.
- The driver builds the `JitRuntime` (null literal base/end) and calls `rt.refresh_literals()` before the loop and again after every `Step::Enter`/`ENTER` arm, so the emitted literal guard always sees the active module's decoded literal area.
- `drive` latches `machine.trace_on`, `machine.bif_in_machine_on` (the cached `ExecutionContext::wants_bif_in_machine` answer, the same gate the interpreter's `Machine::drive` latches, so the in-machine BIF-dispatch door is taken identically on both tiers) and the reduction gate (`machine.reduce_on` = `wants_reduce()`), and zeroes `machine.reductions` at its entry because one `drive` call is one scheduling slice.
- The loop then calls `code.enter(rt, active_module, func, pc)` and hands any address the tier has no compiled block for to one `Machine::step_instruction_with_entry(entry_module, …)`; `JitRuntime::entry_module` is the run's context-`0` module, which the deopt helper threads to the BIF-dispatch funnel and the raise funnel.
- **Every driver-loop iteration charges one reduction unit at the block entry**, before `code.enter(...)`: the loop publishes the position with `Machine::set_current_code(func, pc)`, bumps `Machine::reductions` (saturating, in the same step as the hook so the two always agree) and, when the latched gate is on, calls `ExecutionContext::reduce(1)?`.
- That is the native tiers' first and only pre-emption point; a host whose `reduce` is the default no-op declares `wants_reduce() == false` and pays one `bool` load per iteration and nothing else (byte-identical behaviour), while the engine-side counter is bumped either way, exactly as in `Machine::drive`.
- The position is load-bearing: the runner parks an exhausted machine at `Machine::current_code` and re-enters there, and at the block entry the published position **is** the address about to run with the block not yet executed, so a refusal parks exactly there and the resume replays no prefix (the address's instruction runs exactly once).
- A charge refused from the call-resolution/BIF seams would refuse with the block's *entry* position current only **after** a prefix of the block had run, and the resume would replay that prefix (measured: `beam_rt -eval 'halt(0).'` exits 3 with `unsupported: opcode: run: process blocked`), which is why those seams stay spend-only.
- One iteration is one **driver round-trip** — a natively executed block, or the per-instruction interpreter step the driver takes for an address no block covers — so the unit is a block entry, not an instruction: a synthetic loop that is one block per instruction is priced exactly like the interpreter (3 charges per iteration for `label`, `bif0`, `jump`).
- A **natively linked local tail-call chain** (`call_last`/`call_only` linked between compiled blocks) never returns to the driver and is therefore priced **once**: `slice.beam`'s tail-recursive `fib/1` at n=18 costs **2** charges against the interpreter's **152**.
- That is the honest resolution limit of the block-entry charge and the tier's remaining pre-emption residual: such a chain is priced once and, having no refusing seam inside it, cannot end its slice.
- An **in-block continuation return** charges the very same unit in the very same order for the iteration it skips (`resume_in_block`, position store then bump then hook), so a tail-jumped return leaves `erlang:statistics(reductions)` and `process_info(_, reductions)` exactly as the round-trip path left them.
- Pinned by `tests/jit_reductions.rs`.

## Compile-on-entry and the layout-dependent register guard
- `enter_compiled_cached` calls `CompiledModule::native_entry_cached(module, func, pc, &mut cached)`, which returns the block's entry together with the `highest_native_register` bound the artifact's layout requires (compiling the function first for a lazy artifact).
- The block is entered only when the running machine's `x` file covers that bound (`x.len() > bound`); otherwise, or when the address has no compiled block, `enter_compiled_cached` returns `None` and the driver takes exactly one interpreter step.
- `cached` is the driver's per-artifact `ResolvedFunction` handle (`DriverContext::entry_cached` for the context-`0` artifact, `CalleeCode::cached` per callee — one per artifact, because two artifacts are two mappings with independent function tables), so an entry that stays inside one function costs two `Vec` indexings with no `RefCell` borrow and no `Rc` clone, and only an entry into a **different** function re-resolves or lazily compiles it.
- The bound is layout-dependent: an **eager** artifact reports the **whole-module** max (its seal-time links tail-call directly into other functions' blocks inside the one shared mapping, so the entered function's own bound would not cover the linked code), while a **lazy** artifact reports the entered **function's** own bound (each function owns its mapping; a cross-function *branch or tail call* still round-trips through the driver, which re-checks the target function's bound on its own entry, while a cross-function *continuation return* resolves and bound-checks the target in-block, see `return_word`).
- The same iteration publishes the artifact itself (`JitRuntime::compiled`), which is what lets a continuation `return` resolve an entry in another function of the module without the driver.

## The execution-position store set (`Machine::current_code`)
`Machine::set_current_code` (`src/machine/location.rs`, one word: `pack_current_code` puts `func` in the high half and `pc` in the low half of `Machine::current_code`, whose `func == u32::MAX` sentinel is `CURRENT_CODE_NONE`) is the **only** writer, and `src/jit/**` reaches it from exactly these sites:
- **Driver loop head** — `baseline/mod.rs`, `(func, pc)` of the address about to be entered, **before** the `reductions` bump, before `ctx.reduce(1)` and before `code.enter_cached`/`enter_compiled`. Both native tiers run this one loop (Cranelift enters it through `baseline::run_native*`), so this is the only per-iteration store.
- **Block / continuation-sub-block prologue** — emitted at `baseline/emit/prologue.rs` as `jit_publish_y` (when `Allocation::prologue_publishes_y()`; `runtime.rs` → `JitRuntime::refresh_y_base` plus the store) or as `jit_set_position` (otherwise), with `pc` = the block's start (a sub-block therefore stores its own post-call continuation). Runs after `code.enter`, inside the block.
- **Instruction-granular helpers** (each stores its own `(func, pc)` before touching the machine): `jit_step_one` → `step_instruction_with_entry` (`runtime.rs` → `interpreter/dispatch.rs`); `jit_step_ext` (before `call_ext_dispatch`); `jit_family` (`family.rs`; `jit_receive` is a thin wrapper); `jit_test` (`test_helper.rs`); the frame/heap family `jit_deallocate`, `jit_return`, `jit_deallocate_return`, `jit_allocate`, `jit_allocate_heap` (before `ensure_heap`), `jit_test_heap` (before `ensure_heap`) and `jit_trim`; and `jit_call_store`, on its **served** arm only (see below).
- **The return arms store a *second*, conditional position — the resumed continuation.** `jit_return`/`jit_deallocate_return` store the return's own `(func, pc)` for the pop, then `return_word` resolves the continuation through the shared `enter_in_block` → `resolve_resume_entry`: the published `EntryTables` answer a **same-function** entry with two `Vec` indexings and no artifact lookup, and anything else goes to `cross_function_entry`, which resolves the address in the artifact the driver published (`JitRuntime::compiled`) via `CompiledModule::native_entry_tables` and **checks the target function's own register-file bound in Rust** (a different function's bound is a different number, so the same-function soundness argument does not carry over). On a hit `enter_in_block` stores that `(func, pc)`, bumps `reductions` and offers `ctx.reduce(1)` — the skipped driver iteration's work in the driver's own order, so a refusal leaves the machine parked where a driver-side refusal would have — and, for a cross-function transfer, replaces the published tables with the target's before the emitted arm tail-jumps to the entry. On every other outcome (no artifact published, an uncompiled address, an unsatisfied bound) nothing is stored and the word goes back to the driver, which publishes at its loop head.
- **Sites that store NOTHING** (the position they run under is the last store above): `jit_ext_call` — `resolve_ext_entry` asks `ctx.resolve_external_call`, stores the `EXT_CALL` continuation and returns `ENTER` with no store; `jit_call_store`/`jit_call_store_linked` — the local-call seam is consulted in `call.rs` and `set_current_code(func, pc)` happens **only on the *served* arm** (where a raise from inside the seam's BIF must report at instruction granularity), while the store-and-link arm stores nothing itself — a **resolved** transfer's position is the callee entry `enter_in_block` stored just before the jump, and a **declined** one leaves the position to the driver's loop head; `jit_local_call`/`probe_local_call` — no store at all, so the local-call seam's `call_bif_named` (`dispatch.rs`) runs with a stale position; `jit_bif_value` (`bif_helper.rs`, declines to `jit_step_one`); `jit_tail_call`, whose callers spill and transfer (the successor prologue or the driver stores next).
Consequences (current behaviour, not a defect list): every stored position **is a real instruction boundary** (a block/sub-block start pc or an instruction pc), never a mid-instruction offset; but while a native block runs the position can be the **block entry** or an earlier helper's pc, because an inlined instruction stores nothing — so a resume from the block entry re-enters the block with its prefix unexecuted by construction (the driver published that entry immediately before `code.enter`), while a seam consulted *after* a prefix had run under a block-entry position would park on that entry. Host seams never observe a partially written `x`: `emit_helper_call` spills the dirty cache **before** the helper and the in-block guards reject **before** any store (`arith.rs`, `aggregate.rs`, `aggregate/list.rs`, `bif.rs`).

## The resume driver
- `run_native_resume_outcome` is the **`NativeCode`-generic no-reset resume seam** (it does NOT call `enter_machine`); `run_compiled_resume_outcome` is its baseline-artifact wrapper, and the Cranelift tier reaches the same seam with its own `CompiledEntries`.
- It mirrors `Machine::resume_outcome` — `machine.enter_run(module, func)`, the artifact's own label map (`compiled.labels()`, built once at compilation), then the shared `drive` entering the compiled block at the reported `(func, pc)` — so a slice suspended on the baseline tier resumes on it with interpreter-identical semantics.
- The reduction counter restarts per slice: the shared `drive` zeroes `machine.reductions` at its entry and `run_compiled_resume_outcome` additionally calls `machine.reset_reductions()` before entering, so a resumed slice's `Machine::reductions()` counts only that slice's own block entries, exactly as the interpreter's resume counts only its own instructions.
- A non-entry module context (a suspension inside a cross-module callee) is served the same way the interpreter's resume serves it: `drive` reads the context from `Machine::current_context`, lands in it (`switch_into` re-binds the callee's module, label map and literal area and resolves its blocks through `NativeCode::module_blocks`), and re-enters the callee's own `(func, pc)`.

## The cross-module transfer (`Step::Enter`)
- A `Step::Enter` — from the driver's own interpreter step, or the `ENTER` word a block hands back — switches context through `switch_into`: `Machine::switch_context`, re-bind module/labels/literals (`rt.refresh_literals()`), and the callee's blocks via `NativeCode::module_blocks`, whose `BlockEntries` impl consults the per-thread `CodeCache` and stages the callee as a **lazy** artifact on first sight.
- The driver then continues in the callee's compiled code (its functions compiling on first entry), or on the per-instruction step when the tier has no blocks for it.
- The context switch is a driver round-trip by construction: each `CompiledModule`/`CompiledFunction` owns a separate executable mapping and `JitRuntime::module`/`labels` are baked for one module.
- The `call_ext*` instruction itself is executed natively by `jit_ext_call`, so only the callee's entry goes back through the driver.
- A **traced** run refuses native entry and hands the slice to `Machine::drive`.

## The in-block transfer (a non-tail local call into an uncompiled function)
- A compile-time `Linker::is_compiled` picks the transfer: a callee whose block is part of *this* compilation (the eager whole-module artifact, or a call inside the same function) keeps the linker's direct jump (`emit_exit`), while a **cross-function** callee the **lazy** per-function artifact has not compiled — the shape every cross-function non-tail call takes through `CodeCache::compiled_handle` — is emitted by `emit/link.rs::emit_in_block_call` after a call to `call.rs::jit_call_store_linked`.
- That helper stores the continuation **and** runs the seam probe first (a **served** callee must get neither a return address nor a transfer), then, on the seam's *declined* path only, resolves the callee's native block entry through `enter_in_block`.
- `enter_in_block` is the **same** resolver the return side uses (`return_word` → `enter_in_block` → `resume_in_block` → `resolve_resume_entry`/`cross_function_entry`), so the two in-block transfers can never drift.
- `enter_in_block` publishes the target entry in `JitRuntime::resume_entry` and reproduces the skipped driver iteration in the driver's own order — `Machine::set_current_code(func, pc)` of the **callee entry**, the `Machine::reductions` bump, then `ExecutionContext::reduce(1)?` — so a refused charge parks the machine exactly where a driver-side refusal parks it and the resumed slice runs each instruction exactly once; it then replaces the published `EntryTables` with the target function's.
- `EntryTables::of` is the one place an `EntryTables` is built, used by both the driver's publication and a re-publication.
- `resume_in_block` answers a **same-function** entry from the published `EntryTables` (two `Vec` indexings, no artifact lookup) and hands anything else to `cross_function_entry`, which resolves the address through `CompiledModule::native_entry_tables` on the artifact the driver published in `JitRuntime::compiled` and checks **that function's** register-file bound in Rust (the same-function bound argument does not transfer to a different function's code).
- A hit tail-jumps to the entry with `JitRuntime::resume_entry` carrying it; every other outcome leaves the word for the driver.
- The emitted arm is `mov rdi,[rsp+RUNTIME_SLOT_DISP]` / `mov r11,[rdi+RUNTIME_RESUME_DISP]` / `test r11,r11` / `je declined` / `emit_frame_teardown` / `jmp r11`; it emits **no** second spill (the helper call already spilled the dirty set) and the transfer is a **tail** transfer, so Erlang non-tail recursion does not grow the native stack.
- Every decline — no artifact published, an address no block covers, a missing function, a failed lazy compile, an unsatisfied register-file bound, a served local-call, a **traced** run, `RefCell` re-entrancy, a refused `ctx.reduce` — leaves `resume_entry` null and puts the **pre-existing** `encode_target(target_func, target_pc)` word in `rax` (with `ERROR` for a refused charge), i.e. exactly the word the driver decoded before the transfer existed, with the continuation stored exactly once.
- The callee's own prologue re-publishes its position, so a mid-block resume stays exact.
- `call_ext*` keeps its driver round-trip: a cross-module transfer needs the driver-owned module-context registry (`Machine::switch_context`), the label-map/literal-area rebinding and per-callee artifact publication, and `JitRuntime::module`/`labels` are baked for one module (`ENTER` is the block ABI's only word for it).
- The Cranelift tier inherits `NativeCode::module_blocks`'s default `None` and is untouched.
- Test-only counters `Counters::in_block_calls`/`in_block_call_declines` price it, pinned by `../cross_tests.rs`; the measured effect is in `../measure/CONTEXT.md`.

## Constraints
- `#![allow(unsafe_code)]` covers `runtime.rs` (the JIT zone); every `unsafe` block carries a `// SAFETY:` rationale.
- Never panic and never produce a wrong result: a helper's failure is a typed `BeamError` stored behind the `ERROR` word, or the interpreter's own diagnostic.
- Files ~1000 lines; Apache-2.0 header byte-exact.

## Test Strategy
`../tests.rs` unit-tests the ABI encoding, the `#[repr(C)]` runtime layout, the deopt/yield folding (a deopted `wait` folds to `RunOutcome::Wait`), and the collecting `test_heap` admission reaching the host's door exactly once with the cached registers reloaded afterwards.
The reduction charge and the in-block transfer are pinned by `tests/jit_reductions.rs` and `../call_tests.rs` (see `../testing/CONTEXT.md` for the enumeration).

## Known Issues
- **A per-run memo for the cross-function in-block transfer is a measured net loss and is not in the tree.** `enter_in_block`'s cross-function arm (`resolve_resume_entry` → `cross_function_entry` → `CompiledModule::function`) re-resolves its target on every such transfer — `to_lower/1` asks the artifact **60.0** times per call. A 2-slot, artifact-keyed per-run memo answered **58** of those (resolutions 60.0 → 2.0 per call, `in_block_calls` / declines / `driver_round_trips_per_call` identical) and still lost: `list_walk` **+1.84 %** (min 1.018353 / median 1.018368, 3 paired rounds, zero leg overlap) against `to_lower` −0.18 % (1.001811 / 1.001813). `list_walk` cycles `walk/1 → walk/3 → sum/1` against two slots, so every transfer pays the scan and still misses, while its hot recursive `sum/1` call is same-function and never consults the memo at all; on a 3-function cycle no wider memo clears the 0.3 % bar. The residual in `enter_in_block` is therefore the **frozen skipped-iteration reproduction** (`set_current_code` → `reductions` bump → `ctx.reduce(1)?`) plus the `EntryTables` publication, not the artifact lookup — do not re-open it as an entry-resolution problem. That is now priced directly: on `gc_bound/churn` the artifact resolution is 0.07 % self / 0.28 % inclusive, and a per-function published-tables slot that removes it measures a −0.04 % median (**`../measure/CONTEXT.md`**). The instrument survives: `../counters.rs::Counters::{cross_function_resolutions, cross_function_memo_hits}` + `../cross_tests.rs` (both `#[cfg(test)]`, zero production cost).
- **The probed local call costs code size, and its remaining per-call cost is the seam itself.** Baking a tail call's resolution into the probe's block-ABI immediates removes the per-call instruction re-decode and label resolution (measured −0.41 % / −0.66 % retired instructions) but adds three immediate setups per probed site: **+0.78 % emitted bytes** corpus-wide, recovered to +0.47 % by the single-spill exit. Both are accepted trades, and neither changes a result. What is left on the shape is `Machine::local_call_seam` — the one seam the probe calls, which memoizes the host's verdict per callee function index in the executing module context's table (`LocalVerdicts`) so its per-call residual is **one bounds-checked slot load plus the lazily-armed invalidation `Cell` read** (`../../../machine/CONTEXT.md`) — and the tier must not short-circuit it (its own optimisation belongs to its owner, not to this node).
- **`runtime.rs` is above the ~1000-line guidance** because it is the block ABI plus every per-instruction helper, all reading the one `JitRuntime` layout; splitting it is a separate, parity-neutral refactor.
