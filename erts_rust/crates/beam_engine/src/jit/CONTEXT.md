# `beam_engine` JIT / execution-tier seam (`src/jit/`)

## Intent
The execution-tier seam of the engine: the `Tier`/`JitBackend` abstraction, the cross-run
compiled-block cache, the tiering policy, and two native backends (a baseline x86-64 tier and an
optional Cranelift hot tier) that execute `beam_loader`'s typed IR with **interpreter-identical
semantics**. These are correctness-first *mechanisms*, not optimisers (DeepDive §F); the baseline
tier is a genuine native path whose every un-lowered instruction deopts per-instruction to the
interpreter's own step. Block ABI, register cache, spill/root-set model and the per-instruction
deopt are the load-bearing contracts.

## API Surface (crate-visible; `beam_engine::jit::…`)
- `mod.rs` — `Tier { Interpreter, BaselineJit, Cranelift }` (`ALL`/`name`/`from_name`/`is_available`), `available_tiers()`, the `JitBackend` trait (`compile`/`run_compiled`/`run_export`), `CodeRegion`, feature gating (`jit-cranelift` default OFF; `jit-beamasm` aliases the baseline), and the feature-dispatched Cranelift entries (`run_cranelift{,_outcome,_label_outcome,_resume_outcome}`).
- `cache/` (`mod.rs` + `tests.rs`) — `CodeCache`, `ModuleKey`/`module_fingerprint`, thread-local `run_baseline_cached{,_outcome,_label_outcome,_resume_outcome}`, `cached_module_blocks`, `remember_module`, `baseline_code_map`. `CodeCache::get_or_compile` (and so `baseline_code_map`) always produces an **eager** artifact; `CodeCache::compiled_handle` — the path behind `run_baseline_cached*` and `cached_module_blocks` — stages a **lazy** artifact whose functions compile on first entry. `run_baseline_cached_resume_outcome` is the **resume** entry (backs `Machine::resume_outcome_with_tier` for the baseline tier): it reuses the cached artifact (staging uncached only on a `RefCell` re-entry) and delegates to the no-reset `baseline::run_compiled_resume_outcome`. **A HIT is O(1) and does not re-hash the IR**: the artifact stores its module's content fingerprint (`CompiledModule::fingerprint`, computed **once** at creation by both constructors), and `ModuleKey` is a private **two-variant** identity — `Digest([u8; 16])` (a real `.beam`'s **load-time MD5** [`Module::checksum`], read as a plain `Copy`: O(1), no hash, no allocation) or `Content { name, fingerprint }` (the `module_fingerprint` whole-IR content hash, never a pointer, for a synthetic `Module::default()` whose checksum is all-zero); the variants hash their discriminant so they can never cross-key, and two same-named, differently-bodied real modules carry different digests. `CodeCache` also keeps an address-keyed **resolution memo** whose entry is trusted only while its `Weak<Module>` still upgrades (a live `Module` cannot move out of its `Arc`), so a freed module's (possibly recycled) address is never trusted and the lookup falls back to `ModuleKey::of`; on the O(1) digest path the memo is a **redundant micro-optimisation** (the digest needs no liveness proof), retained because a host may call the priming API. The memo is a hint, never the authority — the memoized key is still verified against `entries` — and it is filled only where an `Arc<Module>` is available to downgrade: by `cached_module_blocks` (the cross-module *callee* route, which the driver already holds an `Arc` for) and by the host-facing priming API `remember_module`. `cache.rs` is split into `cache/mod.rs` (the cache) and `cache/tests.rs` (its unit tests) because the two together exceed the ~1000-line budget.
- **The entry path resolves the entry module in O(1), with no IR hash.** Every `run_baseline_cached*` slice entry/resume resolves the entry module through `CodeCache::compiled_handle(&Module)`, whose key comes from `ModuleKey::of`: for a real `.beam` that is the **load-time MD5 digest** — a `Copy` read with **zero** `module_fingerprint` calls — so the per-slice whole-IR re-hash that once made the default tier **dearer** than the interpreter on message-passing shapes (once per `receive` park and per resume) is gone with **no host change**; only a synthetic all-zero-checksum module falls to the `Content` content hash. `cache::remember_module(&Arc<Module>)` is retained as **belt-and-braces** for a host that owns its modules as `Arc<Module>` (the runtime's code server does): it derives the key once, stages the module's lazy artifact **only if no artifact is cached for that content** (an existing eager/lazy artifact is never replaced) and records the address-keyed `MemoEntry`, a hint redundant over the already-O(1) digest; it is infallible and a documented no-op while the thread-local cache is already borrowed (never a panic). Measured in-process on a **real loaded `.beam`** entry/resume probe (`cache/tests.rs::the_entry_and_resume_slice_cost_is_measured_on_both_tiers`: baseline **0.29×** the interpreter's ns/slice-entry, 0 IR hashes) and pinned by `cache/tests.rs::a_real_loaded_beam_never_rehashes_its_ir_on_any_entry_path` and `::remember_module_priming_makes_all_four_entry_paths_rehash_free`. A probe over **synthetic** (`Module::default()`, all-zero-checksum) modules takes the `Content` fallback and therefore understates this — the digest path needs a real `.beam`.
- `tiering.rs` — `TierPolicy { baseline_threshold, hot_threshold }` (interpret → baseline → hot; a policy only).
- `baseline/` — `BaselineJit`, `CompiledModule` (`entry`/`native_entry`/`block_count`/`cached_registers`/`highest_{cached,native}_register`/`code_len`/`code_address_range`/`code_map`, plus the per-function **continuation sub-block** table `CompiledFunction::sub_entries` / `EagerLayout::sub_entries`) in its two layouts (`code.rs`: **eager** = one whole-module mapping with cross-function direct links; **lazy** = one mapping per function, compiled on first entry), the block ABI (`runtime.rs`: `encode_target`/`decode_target`/`encode_wait`/`decode_wait`/`HALT=-1`/`ERROR=-2`/`WAIT_BIT`, the Y window `JitRuntime::{y_base,y_end}`), the drivers (`run_compiled{,_outcome,_label_outcome}`) plus the no-reset `run_compiled_resume_outcome`, and the `NativeCode` trait (`enter(rt, module, func, pc)` + `module_blocks`).
- `cranelift/` (feature `jit-cranelift`) — `CraneliftJit`, `CompiledFunctions`, `CodegenReport`, `run_resume_outcome` (a typed error — see below).
- `emitter/` — `CodeBuffer`, `Reg`, `Cond`, `Label`: the crate's **only** executable-memory mapping.

## Key contracts (frozen)
- **Block ABI**: `extern "C" fn(*mut JitRuntime) -> i64` returning `(func<<32|pc)` (`func < 2^31`), or a sentinel (`HALT`/`ERROR`/`WAIT_BIT`/`ENTER`). `rbx` = base of `machine.x`; up to 5 cached x-registers live in `r12`–`r15`+`rbp`; `rt` in a 24-byte stack slot. Every compiled block's **prologue** calls `jit_set_position(rt, func, block_start_pc)` so `Machine::current_code` advances at block granularity across a *linked* branch; a deopt (`jit_step_one`) and a `call_last` frame pop (`jit_tail_call`) record/keep the exact instruction position.
- **Two artifact layouts (eager / lazy) + compile-on-entry.** `CompiledModule` is either **eager** (`emit::compile_module`: every function lowered up front into one sealed mapping with a whole-module block-entry table, so the seal-time `Linker` links a taken branch to a successor block of **another** function as a direct jump) or **lazy** (`CompiledModule::lazy`: one sealed mapping per function, filled on that function's first entry). `JitBackend::compile`/`compile_module`/`CodeCache::get_or_compile` stay eager (whole-module introspection, cross-function direct links); `CodeCache::compiled_handle` (the `run_baseline_cached*` runtime path) and `cached_module_blocks` are lazy. The lazy path compiles through `NativeCode::enter(rt, module, func, pc)` → `CompiledModule::native_entry`, which returns the block's entry **and the register-file bound the layout requires**; the block is entered only when `machine.x.len() > bound`, else the driver takes one interpreter step. The bound is **layout-dependent**: an **eager** artifact reports the **whole-module** `highest_native_register` (its seal-time links tail-call directly into other functions' blocks inside the one shared mapping, so the entered function's own bound would not cover the linked code), while a **lazy** artifact reports the entered **function's** own bound (its seal-time `Linker` links only **intra-function** blocks: a cross-function target is absent from the per-function map, so the block returns the target's `(func, pc)` word to the driver, which compiles that function on entry and re-checks its own bound there).
- **Continuation sub-blocks (native entry at a non-block-start pc).** A **frame-preserving** call — `Instr::Call`, a non-tail `Instr::CallExt`, `Instr::CallFun`/`Instr::CallFun2`/`Instr::Apply` (`emit::compile::stores_continuation`; the tail forms store no new continuation) — writes its return address `pc + 1` into the live frame. `beam_loader` cuts an IR `Block` only at `Instr::Label`, so that continuation normally lies **inside** a block, where the driver would otherwise run the whole block tail `[pc+1, block.end)` one interpreter-step-per-instruction. **Both layouts** lower one **sub-block** covering `[pc+1, containing_block.end)` through the very same `emit_block` an IR block uses (identical shape rules, guards and deopts, so a sub-block is interpreter-identical by construction) and give the driver a native entry there: the **lazy** layout records each entry in `CompiledFunction::sub_entries[pc]` (after `emit_function`), the **eager** layout in `EagerLayout::sub_entries` (after every IR block). `entry`/`native_entry` probe `entries` (IR-block starts) **first** and `sub_entries` second, so a real block start always wins; a sub-block reserves **no** entry label and is **not** counted, so `Summary::block_count`/`code_map`/`code_address_range` keep describing IR blocks only. This is what closes the non-tail-recursion gap (the `sum/1` workload): the driver re-enters natively at the post-call continuation instead of paying a full round-trip per remaining instruction.
- **Deopt = one interpreter step.** Every un-lowered instruction (or an inline sequence whose run-time guard rejects) spills the block's **written** cached x-registers, calls `jit_step_one` → `Machine::step_instruction`, then continues **in-block** when the step advanced by exactly one (`Step::Next`) — refilling only the cached registers the continuation can still observe — any other outcome returns word to the driver. `FuncInfo` is a raise (`function_clause`), deliberately never a metadata no-op.
- **Root-set / spill**: a block caches a **fixed** set of ≤5 x-registers for its whole duration (an x-register is either *always* held in its machine register or *never* cached, so the two representations can never disagree). The exit spill **always leaves `machine.x` authoritative for every cached register** — it stores the block's **written** set (the cached registers its inline lowerings may write); a cached register the block never wrote already holds its `machine.x` value, so skipping it is a no-op. Non-cached registers are addressed directly in `machine.x`. Both `call_r` sites (`emit/mod.rs` and `emit/link.rs`) spill first, so a helper (hence `ensure_heap`/`alloc_words`) sees the interpreter's exact live root set; the post-helper `fill` is likewise partial (only the cached registers the continuation can still observe). Detail: `baseline/emit/CONTEXT.md` and `baseline/CONTEXT.md`.
- **`Step::Enter`** (cross-module context switch). A compiled block hands the resolved `(context, func, pc)` back to the shared driver with the `ENTER` block-ABI word (its per-instruction deopt, `jit_step_one`); the driver performs the switch exactly as `Machine::drive` does — `Machine::switch_context`, re-bind the active module, label map and literal area, and (through `NativeCode::module_blocks`, which for the tier's shared store compiles the callee on first sight) enter the callee's compiled blocks, or its documented per-instruction step when the tier has none. `call_ext*` is therefore not inlined: a cross-module transfer is a **driver round-trip by construction** (each `CompiledModule` owns a separate executable mapping with buffer-local `rel32` fixups, and `JitRuntime::module`/`labels` are baked for one module). A **traced** run (`ctx.trace_enabled()`) hands the whole slice to `Machine::drive` instead, since native code emits no trace events.
- **One host-seam resolution per `call_ext*`.** The native `jit_ext_call` helper resolves the import and asks the host's `ExecutionContext::resolve_external_call` **once**; on the host's decline (`Ok(None)`, the common BIF shape) it hands that already-computed answer to `jit_step_ext`, which drives the instruction through the frozen shared `Machine::call_ext_dispatch(..., seam = Some(None))` — whose `apply/3`/`send/2` special cases still run first and which never re-asks the host. The interpreter's own `call_ext*` arm passes `seam = None` (resolve internally, exactly as before). A host **error** (not a decline) still falls back to `jit_step_one`, which reproduces that error verbatim. Before the seam was consumed the same `call_ext` resolved the host seam **twice** (~30-100 ns/call); pinned by `baseline/tests.rs::the_baseline_tier_agrees_with_the_interpreter_on_the_declined_call_ext_seam_count` and measured by the `call_ext/0` workload.
- **Resume.** The baseline tier resumes a suspended process **without reset** (`run_compiled_resume_outcome`: `enter_run` + the shared `drive`, entering the compiled block at the reported `(func, pc)`), so a slice that suspended on the baseline tier resumes on it and stays interpreter-identical (same label map, same deopt, same reduction accounting at slice start). A resume in a **non-entry** module context (a suspension inside a cross-module callee) is served the same way the interpreter's resume serves it: the shared driver reads the context from `Machine::current_context`, lands in it (`switch_into` re-binds the callee's module, label map and literal area and resolves its blocks through `NativeCode::module_blocks`), and re-enters the callee's own `(func, pc)`. The Cranelift tier bakes each compiled function's entry `pc` in, so a mid-function suspension address is unserviceable: `cranelift::run_resume_outcome` returns the typed `unsupported("cranelift jit: cannot resume at an arbitrary pc …")` — never a silent fallback to the interpreter. The Cranelift tier inherits `NativeCode::module_blocks`'s default (`None`), so a cross-module callee it enters runs on the driver's per-instruction step; it does not accelerate the switch.
- `jit-cranelift` deps are optional/default-off; without the feature `cargo tree -p beam_engine` lists no `cranelift-*`.
- Never RWX: `mmap` RW then `mprotect` RX (`emitter`).

- **Y-slot operands are guarded by a published frame window.** A lowering that reads or writes a `Y`
  slot (an inlined `Move`, and the small-int arith fast path) addresses `machine.stack[y_base + k*8]`
  against the current frame's `[y_base, y_end)` held on `JitRuntime` (`RUNTIME_YBASE_DISP`/
  `RUNTIME_YEND_DISP`). The window is published in a **Y-touching** block's prologue (`jit_publish_y`,
  the position store fused with the refresh, so such a block pays nothing extra) and refreshed
  (`jit_refresh_y`) after an **in-block helper call** only when a later instruction of the block still
  touches `Y` (`Allocation::y_last`/`refresh_y_after`); a `Y`-free block keeps the plain position store
  and pays nothing, and the driver never refreshes. The emitted guard — and a null window — only ever
  *rejects* (branches to `jit_step_one`); an index the `lea ... disp32` cannot address is refused at
  compile time. Every other `Y`-operand instruction (`get_list`/`get_hd`/`get_tl`/…) is **not** a
  window access — it deopts to the interpreter, which reads `machine.stack` itself. A `Y` slot is never
  charged to the x-register usage counts / `highest_native_register`.
- **`set_tuple_element` is INLINED (not a deopt).** The tier emits the same `is_tuple` header guard the
  tuple read uses, then an `offset < arity` range guard and a **literal-area** guard, and finally the
  destructive store of the element word into the tuple's data word `8*(1+offset)` past the header —
  exactly the word `get_tuple_element` reads. It inlines only when the **target tuple is an in-bound
  x-register** and the **element operand is an immediate constant word or an in-bound x-register**; an
  element that must be heap-materialised (a bignum/float/literal operand) is not a lowered shape and
  deopts to the interpreter, which materialises it exactly. The literal-area guard is load-bearing: the
  interpreter refuses a `TAG_LITERAL_PTR` target with the typed `unsupported` (writing a module's shared
  constants would corrupt them), so an inline that skipped the bit would write shared storage and diverge
  from the interpreter — the guard only ever *rejects*, branching to the helper. The value is read into
  scratch, so no cached register is clobbered and no destination register is produced. Pinned by
  `tests/jit.rs::tuple_writes_match_the_interpreter_on_real_tuples`,
  `::the_tuple_write_is_inlined_and_caches_its_registers`, and the two rejected-target tests
  (`a_non_tuple_tuple_write_target_…`, `a_literal_area_tuple_write_target_…`).

## Constraints
- Errors are `beam_common::{Result, BeamError}` only; no panic, no `unwrap()` on loaded data, no wrong result — an un-lowered op is a typed `unsupported`.
- `unsafe` is confined to `baseline/{mod,runtime}.rs` + `baseline/emit/*` + `emitter/mod.rs` (+ feature-gated `cranelift/mod.rs`); each `unsafe` block carries a `// SAFETY:` rationale.
- **A *loaded* `Module` is immutable after load** — no production path mutates its fields (every post-load field write lives in a `#[cfg(test)]` fixture or a `tests/` tree; the code server stores `Arc<Module>` and only reads), so a content-derived module identity is stable. `Module::checksum` (`[u8;16]`, a `Copy`) is such an identity: it digests `AtU8`·`Code`·`StrT`·`ImpT`·`ExpT`·`FunT'`·`LitT`·`Meta`·`Recs`·`DbgB` (plus the obsolete `Atom`) and excludes `Line`/`LocT`/`Type`/`Attr`/`CInf`/`Docs`/`Dbgi`. The exclusions are safe for the cache: the baseline emitter reads only `functions`/`literals`/`strings`/export-import tables (all digested) and treats `Operand::Typed { reg, .. }` exactly like `X`/`Y(reg)` (`baseline/emit/operands.rs`), so a stripped-vs-unstripped pair with identical `Code` (same checksum, different `Type`) compiles to the same code. `Module::default()` carries an **all-zero** checksum, so synthetic (`Module::default()`-based) fixtures must NOT be identified by the checksum alone — they all collide on `[0u8;16]`.

## Known Issues (per-process cost attribution)
- **The entry path is O(1) on the key's own digest; only the cross-module path uses the address memo.** `CodeCache::compiled_handle` (`cache.rs`) resolves a module through `ModuleKey::of`: for a real `.beam` that is the module's **load-time MD5** (`Module::checksum`, read as a plain `Copy` — no hash, no allocation, no name lookup), so the `&Module`-only entry used by `run_baseline_cached{,_outcome,_label_outcome,_resume_outcome}` is O(1) on **every** entry and resume with no IR re-hash; only a synthetic all-zero-checksum module (`Module::default()`) falls to the `Content { name, fingerprint }` variant, whose `fingerprint` is a hash of the whole decoded IR (the cost there scales with module size — `../MEASURED.md`: ~2 µs tiny, ~141 µs at 2048 instructions). The address memo is therefore a **redundant micro-optimisation on the digest path**, retained for a host that uses the priming API; it is filled by `cached_module_blocks` (the cross-module `Arc<Module>` route → `remember`) and by `remember_module`, and its entry is trusted only while its `Weak<Module>` still upgrades. Pinned by `cache.rs::a_real_loaded_beam_never_rehashes_its_ir_on_any_entry_path` (0 fingerprints across all four entry paths), `cache.rs::a_dead_memo_entry_is_ignored_and_falls_back_to_the_content_hash` (content fallback = `before + 1`) and `cache.rs::a_memoized_lookup_does_not_rehash_the_ir` (the memoized cross-module path).
- **`cached_module_blocks` self-disables on `RefCell` re-entrancy** (`cache.rs`: `try_borrow_mut().ok()?` → `None`), silently making the driver run that callee on its per-instruction interpreter step — a documented perf cliff, never a correctness one.
- **The `jit_bench` harness is eager-only** (`JitBackend::compile`), so it pins the eager whole-module path and does **not** measure the lazy per-entry path the runtime uses; per-process/startup figures live in `../MEASURED.md` (`Measured (baseline-JIT cold start …)`) and the lazy path's correctness in `tests/jit_cache.rs`/`tests/jit_real_module.rs`.
- **Continuation sub-block emission is O(n²) in a long straight-line call-dense block** — detail in `baseline/emit/CONTEXT.md` (`## Continuation sub-blocks`); the synthetic single-block `measure_declined_call_ext` module (256 unrolled `CallExt`, `baseline/tests.rs`) is its observable worst case.

## Notes for Agents (measurement)
- The `tools/bench` `slice`-style system-module per-process rows drift with host load far more than the tier moves them: the baseline-vs-interpreter per-process effect is **1.0–1.3×** (`../MEASURED.md`, N=30 interleaved sampling; the `slice` workload itself read 31.97 ms default / 31.92 ms interpreter, min-of-3), and the untouched interpreter column drifted up to ~29 % across a fresh 7-run in-crate eager set. Quote a min-over-N and compare only figures from the same run set; a bare cross-date absolute on a shared host is not evidence.
