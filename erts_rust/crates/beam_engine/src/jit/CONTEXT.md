# `beam_engine` JIT / execution-tier seam (`src/jit/`)

## Intent
The execution-tier seam of the engine: the `Tier`/`JitBackend` abstraction, the cross-run compiled-block cache, the tiering policy, and two native backends (a baseline x86-64 tier and an optional Cranelift hot tier) that execute `beam_loader`'s typed IR with **interpreter-identical semantics**.
These are correctness-first *mechanisms*, not optimisers (Part II §F): the baseline tier is a genuine native path whose every un-lowered instruction deopts per-instruction to the interpreter's own step.
This node owns the tier seam, the cross-tier invariants and the routing table; each mechanism is specified in the child node the routing table names (block ABI and driver, artifact layouts, emitters, inline set, measurements, censuses, tests, cache).

## The tier seam (FROZEN -- dependents design against this)
- `Tier { Interpreter, BaselineJit, Cranelift }`: `Tier::ALL` (roster order, interpreter first), `name()`, `from_name()`, `is_available()`; `available_tiers()` = `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` iff the feature is on.
- `pub trait JitBackend` -- `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>` (the artifact is **caller-owned**, hence `&self`); plus the provided `run_export`. The interpreter is deliberately **not** a `JitBackend`.
- `CodeRegion` names an artifact's executable range; `mod.rs` also carries the feature-dispatched Cranelift entries `run_cranelift{,_outcome,_label_outcome,_resume_outcome}` (a typed `unsupported` when the feature is off).
- Feature **`jit-cranelift` is default OFF**, and "off" means the crate carries **no Cranelift dependency at all** (`cargo tree -p beam_engine` lists no `cranelift-*`); `jit-beamasm` aliases the baseline tier; `tiering.rs::TierPolicy { baseline_threshold, hot_threshold }` models the *interpret → baseline → hot* escalation as a **policy only** (no execution path consults it). The tier is nevertheless **runtime-selectable** through `beam_rt`: `BEAM_RT_TIER=cranelift` together with the runtime's `cranelift` Cargo feature (`= ["beam_engine/jit-cranelift"]`), and without the feature an explicit request is a typed refusal (CLI exit code 3) naming the feature, never a substitute tier.

## Tier entries and their rules (no silent fallbacks)
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`) is the **non-blocking** entry: `Interpreter` → `run_export`, `BaselineJit` → `cache::run_baseline_cached`, `Cranelift` → `run_cranelift`, else the typed `unsupported("jit-cranelift tier not built")`.
- `run_export_outcome_with_tier`/`run_label_outcome_with_tier` are its outcome-aware twins and `resume_outcome_with_tier` the **resume** twin: a suspended slice re-enters on the **same** tier, so the tier survives a `receive` park (the baseline resume driver resets nothing and also serves a slice parked in a **non-zero module context**).
- A non-blocking entry has no channel for a suspension: `RunOutcome::Wait` arrives as the typed `error::blocked()` and `RunOutcome::Suspend` as `error::suspended()` -- never a substituted value.
- A `receive` park crosses the block ABI as a `WAIT_BIT` word; a BIF suspend crosses it as `SUSPEND` (`-5`), with the **un-applied** instruction's address parked in the driver-only `JitRuntime::suspend` side channel, so the host's resume **re-executes** that instruction.
- `Tier::Cranelift` **resumes too**: `cranelift::run_resume_outcome` takes the retained artifact (`cache::handle`, an `Rc` held for the whole slice) and hands it to the shared generic no-reset seam `baseline::run_native_resume_outcome`, which zeroes the slice counter, re-binds the run entry, uses the artifact's stored `LabelMap` and drives the same `drive` loop from the parked `(func, pc)`. An address `is_enterable` rejects (a mid-block `pc`) takes the per-instruction interpreter step — the documented deopt, never a silent fallback to another tier.
- A **traced** run (`ctx.trace_enabled()`) refuses native entry and hands the whole slice to `Machine::drive`, because native code emits no trace events.

## Cross-tier invariants (the load-bearing contracts; detail one level down)
- **Block ABI.** `extern "C" fn(*mut JitRuntime) -> i64` returning `(func<<32|pc)` (`func < 2^31`) or a sentinel: `HALT`=`-1`, `ERROR`=`-2`, `ENTER`=`-3`, `LOCAL_DECLINE`=`-4`, `SUSPEND`=`-5`, plus `WAIT_BIT` and the in-block-only `CALL_STORED`. `rbx` = base of `machine.x`; up to 5 cached x-registers live in `r12`-`r15`+`rbp`; each block pushes its **own variable-length frame** (only the callee-saved machine registers it actually caches, plus an `8`/`16`-byte `rt` slot that keeps `rsp` 16-byte aligned). Detail: `baseline/runtime/CONTEXT.md`, `baseline/emit/prologue/CONTEXT.md`.
- **Deopt = exactly one interpreter step.** Every un-lowered instruction (or an inline whose run-time guard rejects) spills the block's **dirty** cached x-registers, calls `jit_step_one` → `Machine::step_instruction_with_entry` (`step_instruction` is the `#[cfg(test)]`-only single-module shorthand), and continues in-block only when the step advanced by exactly one (`Step::Next`), refilling exactly `cacheable_writes(pc)` ∩ slots; any other outcome returns a block-ABI word to the driver. So a tier is interpreter-identical for every supported opcode and the interpreter's exact error surfaces stand. `FuncInfo` deopts **deliberately** -- it is the failed-head-clause raise (`function_clause`), never a metadata no-op.
- **A `fallback` is a deopt, so an inline arm must be re-execution idempotent.** `fallback` runs exactly one interpreter step, which re-executes the *whole* instruction with the same operands and re-reads the machine's live state, so every run-time guard that can take it must run **before** any mutation the step would observe. `bs_match` therefore writes the match context's `start` word exactly once on the accepted path and once on its `fail_arm` — never per command — and its shape predicate declines a destination that **is** the context slot unless that command is the last one. A per-command commit would make a post-`skip` deopt re-run `ensure_exactly` against an already-shortened window — `{badmatch, Subject}` on a `<<_:2, F:6>>` match over a **one-byte** subject the family accepts (the per-character body of `emqx_base62:decode/2`) — a wrong result, the one outcome no tier may produce. Pins: `baseline/bs_match_deopt_tests.rs`; detail: `baseline/emit/bitstr_inline/CONTEXT.md`, `baseline/inlineset/CONTEXT.md`.
- **Reduction charge -- the native tiers' only pre-emption point.** One unit per **driver-loop iteration** (block entry), charged before `code.enter` by the one driver loop both `Tier::BaselineJit` and `Tier::Cranelift` run: the loop publishes `Machine::set_current_code(func, pc)` first, bumps the slice counter, then offers `ExecutionContext::reduce(1)?`, so a refusal parks on the not-yet-executed block entry and the resume applies it **exactly once**. A host whose `reduce` is the default no-op declares `wants_reduce() == false` and pays one `bool` load per iteration (byte-identical behaviour). Residual: a natively **linked local tail-call chain** never returns to the driver, so it is priced **once** and, having no refusing seam inside it, cannot end its slice -- `slice.beam`'s `fib/1` at n=18 costs **2** charges against the interpreter's **152**. Pin: `tests/jit_reductions.rs`.
- **In-block transfers (both directions) reproduce the skipped driver iteration** in the driver's own order (position store → `reductions` bump → `ctx.reduce(1)?`) and are **tail** transfers, so Erlang non-tail recursion does not grow the native stack; one shared resolver serves the `return` and the declined-seam `call` sides, and every decline falls back to the plain round-trip with the continuation already stored **exactly once**. `call_ext*` keeps its driver round-trip **by design**: a cross-module transfer needs the driver-owned module-context switch plus the label-map/literal-area rebinding and per-callee artifact publication, and `JitRuntime::module`/`labels` are baked for one module, so `ENTER` is the block ABI's only word for it. Detail: `baseline/runtime/CONTEXT.md`.
- **The register cache / root set.** A block caches a **fixed** set of ≤5 x-registers for its whole duration (an x-register is either *always* held in its machine register or *never* cached, so the two representations can never disagree), and every exit spill leaves `machine.x` authoritative for every cached register (it stores only the **dirty** set at that pc). Both helper-call sites spill first, so a helper (hence `ensure_heap`/`alloc_words`) sees the interpreter's exact live root set. Detail: `baseline/emit/regs/CONTEXT.md`.
- **`Y`-slot operands are guarded by a published frame window** (`JitRuntime::{y_base,y_end}` at `RUNTIME_YBASE_DISP`/`RUNTIME_YEND_DISP`); the emitted guard -- and a null window -- only ever *rejects* (to `jit_step_one`), and a `Y` index the `lea ... disp32` cannot address is refused at **compile** time. A `Y` slot is never charged to the x-register usage counts / `highest_native_register`. Detail: `baseline/inlineset/CONTEXT.md`, `baseline/emit/prologue/CONTEXT.md`.
- **One host-seam resolution per `call_ext*`.** `jit_ext_call` resolves the import and asks `ExecutionContext::resolve_external_call` **once**; on a decline it forwards that computed answer into `jit_step_ext`, which drives the instruction through the shared `Machine::call_ext_dispatch(..., seam = Some(None))` -- whose `apply/3`/`send/2` special cases still run first. A host **error** (not a decline) falls back to `jit_step_one`, which reproduces it verbatim. Pin: `baseline/tests.rs::the_baseline_tier_agrees_with_the_interpreter_on_the_declined_call_ext_seam_count`.
- **The seam's one run-time host consultation is the local-call seam** (`ExecutionContext::resolve_local_call`), and `Machine::local_call_seam` memoizes the callee identity and that verdict **per module context, addressed by the callee's own function index** (`LocalVerdicts`, one `Cell<Verdict>` slot per entry of `Module::functions`), so the host is consulted once per distinct callee and the per-call cost is one bounds-checked slot load (invalidated by `erlang:load_nif/2`, `Machine::reset` and `Machine::invalidate_local_call_verdicts`; detail: `../machine/CONTEXT.md`). Both tiers are pinned equal on the served and declined routes by `tests/local_call_seam.rs`, and the tier must not short-circuit the seam — nor bake a verdict into compiled code (`JitBackend::compile` is handed no `ExecutionContext`, and the cross-run `CodeCache` is shared).
- **The bitstring inline set is nine native `Bs*` shapes**, not one helper arm: `bs_match` (a fully static command list), `bs_get_integer2`, `bs_get_position`, `bs_set_position`, `bs_skip_bits2`, `bs_test_tail2` and `bs_start_match3`'s reuse form together with `bs_start_match4`'s reuse and `resume` forms lower to straight-line code through `baseline/emit/bitstr_inline/`, and the ninth — `bs_create_bin`'s **private-append construction** shape, the compiler's linear accumulator build — lowers the encoder hot loop in place.
  Both of its routes emit one positioned `emit_positioned_helper_call` to an append door, then that route's field writes, then one single window-end commit emitted **last** with only the destination store after it: `Route::Aligned` writes straight-line stores at `cursor + field_offset` (one byte store per field byte, `8`-byte `mov_ri`/`mov_mr` chunks for a `StrT` constant) and `Route::BitGranular` writes one positioned `jit_write_bit_field` per field, each behind its own refusal test.
  The append door is `jit_open_append_bin`/`jit_open_append_bin_any` for an x-register accumulator and `jit_open_append_bin_y`/`jit_open_append_bin_any_y` for a `Y` slot, the byte-aligned pair sharing the private body `open_append_cursor` and the general pair `open_append_any_cursor`; `jit_open_append_bin_any` is the general door (`seam::open_append_any`, gated on C's append-position rule — `end_bits % unit == 0`, ungated for `unit <= 1`) and `jit_open_append_bin` its byte-aligned twin (`seam::open_append`, gated on `end_bits % 8 == 0`), so a whole-byte plan keeps its straight-line stores.
  All four mutate nothing — the seam's two queries allocate nothing and write nothing — so every guard that can reach the `fallback` runs against the machine state the interpreter step sees.
  Each shape sits behind a purely syntactic `*Shape::of` predicate that emits **zero bytes** when it declines, so `emit_block`'s `_ if bitstrings::claimed(instr) => emit_bitstr` guard arm still owns it, and each carries run-time guards that branch to a local `fallback` running exactly one interpreter step -- never a fabricated value, never a destination written on a rejected path, with the up-front guard phase complete before the first payload write.
  The eight match-context shapes are allocation-free by construction (unsigned big-endian fields only, `nbits` bounded so the result is a small integer), so no moving collection can interleave inside one and the once-read context block base stays valid for the whole sequence; every allocating command (`binary`/`get_tail`/`=:=`), every runtime size/unit, and every signed, little-endian or wider field stays on the helper.
  The construction shape writes only into the accumulator's own payload bytes, at offsets it re-derives identically on every attempt, and its single mutation (the window-end commit) is emitted **last** -- a commit before the payload stores would make a later `fallback` (one whole-instruction interpreter step) append the tail twice, a wrong result. Its aligned-route field extraction is an **arithmetic** `sar_ri` because the family hands `push_byte_field` the small value sign-extended to 64 bits; a logical shift would corrupt a negative 8-byte field's top byte, and the bit-granular route extracts nothing at all (it hands the field to the family's own write rule).
  The construction shape lowers an **addressable `Y` slot** or an x-register accumulator, and `Y`-slot or x-register field values; the accumulator crosses the block ABI as a **slot index** to all four doors, because `emit/mod.rs::emit_helper_invoke` can add only `movabs` immediates to a helper — which is exactly what makes a `Y`-slot accumulator expressible.
  Every `Y` operand's frame-window guard is emitted **once, before any write**, and every post-helper `Y` re-read is unguarded behind it (the helper runs no interpreter step and only reads machine state, so the frame cannot move).
  `uses_y()` is `source.is_y() || dst.is_y() || any field value is_y()`, and `Y` slots are still excluded from `registers()`/`reads()`/`writes()` so they never reach the register cache or `highest_native_register`.
  Per-shape predicate, guards and refusal reasons: `baseline/inlineset/CONTEXT.md`.
- **Never RWX**: the emitter `mmap`s RW then `mprotect`s RX (`emitter/CONTEXT.md`).
- **Artifact identity = the module's load-time MD5 + the atom namespace.** A cache hit is O(1) and re-hashes no IR, sound because a loaded `Module` is immutable after load; the key, the namespace witness and the soundness precondition are `cache/CONTEXT.md`.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: no panic, no `unwrap()` on loaded data, no wrong result -- an un-lowered op or unmodelled shape is a typed `unsupported`.
- `unsafe` is confined to `baseline/{mod,runtime}.rs`, the `baseline/emit/*` emitters, `emitter/mod.rs` and the feature-gated `cranelift/mod.rs`; every `unsafe` block carries a `// SAFETY:` rationale.
- **A loaded `Module` is immutable after load** -- every post-load field write lives in a `#[cfg(test)]` fixture or a `tests/` tree -- so a content-derived identity is stable; `Module::default()` carries an **all-zero** checksum, so synthetic fixtures must never be identified by the checksum alone.
- Files ~1000 lines, split by responsibility; every `*.rs` carries the OTP Apache-2.0 header block byte-exactly.
- **Tier agreement is vacuous for an inline arm**, because a deopted instruction is executed by the interpreter on **both** sides: an arm that silently stopped lowering would still "agree". An arm is native only when a `#[cfg(test)]` emission counter shows it was emitted -- `inlined(SHAPE_*)`, defined beside the shapes in `baseline/emit/bitstr_inline/mod.rs` and read back over a cache-free compile by `emitted_shapes_for` in `baseline/bitstr_inline_tests.rs` -- and the static-deopt census (`static_deopts`, the same `baseline/bitstr_inline_tests.rs` instrument, over the compile's counter snapshot) shows **zero** deopts for its instruction, beside the value checked against the interpreter and the live `erl` — `baseline/bs_match_deopt_tests.rs` and `baseline/foreign_kernel_tests.rs` do exactly that on the `emqx_base62`/`cowboy_bstr` bench kernels.
- Gates and their current pass counts: `../TEST_NOTES.md`; the crate-level measured record: `../MEASURED.md`; the canonical cross-runtime table: `../../../tools/bench/RESULTS.md`.

## Known Issues (tier-level residuals, each with its owner)
- **Cranelift resumes, but does not transfer in-block**: its resume goes through the shared `baseline::run_native_resume_outcome`, and it inherits `NativeCode::module_blocks`'s default (`None`), so a cross-module callee it enters runs on the driver's per-instruction step. It stays default-OFF; the measured verdict and ratios are `cranelift/CONTEXT.md`.
- **The Cranelift resume path.** `emit_pc_entry_dispatch` compiles ONE native entry per IR function that dispatches the `pc` argument over `CompiledFunctions::enter_pcs`, `CompiledEntries::enter` accepts `(func, pc)`, and the thread-local artifact store keeps a `CompiledFunctions` (with its module-wide label map) mapped across a park — so a resumed slice re-enters natively at every `is_enterable` address. Detail: `cranelift/CONTEXT.md`.
- **No `Instr` variant raises a typed `unsupported` on the Cranelift tier.** The `emit_pc` match ends in a `_` arm that routes to `emit_helper_dispatch` → `jit_step_one`, i.e. exactly one interpreter step with the interpreter's own semantics and its own typed errors; `CallLast` (needs the Rust-side `pop_frame_checked`) and `Call` (frame-preserving) are among the deopting forms, so a call reaches a working path, never an error.
- **The baseline tier's static-deopt totals are prose-only, not pinned.** No test asserts a corpus count: the census entry points print tables and assert only liveness/consistency, so treat the recorded figures as provenance, not as a gate. The current record (`baseline/census/CONTEXT.md` owns the method and the corpus definition): **119 189** deopting instances of **3 114 364** visited instances = **3.83 %**, over **38** committed `tests/fixtures/*.beam` + **1321** installed-OTP modules = **1359 modules / 103 079 functions** in **597 565** blocks. By name: `FuncInfo` **103 079** (86.5 %, one per function, never executed) is the only instruction that unconditionally deopts on this tier, then `Bif` 10 014, `GcBif` 2 559, `Bif0` 3 205, `NifStart` 300, `Test(IsBoolean)` 17, `Test(IsFunction2)` 9, `OnLoad` 6 -- excluding `FuncInfo`, **16 110 / 3 011 285 = 0.54 %**; `Bif0`/`NifStart`/`OnLoad` have no arm, and `Generic` is a typed `unsupported_opcode` error rather than a step. Three denominators are in circulation and only one may carry a deopt fraction: raw IR (`function.code.len()`, never printed), Σ emitted-block ranges **3 586 410**, and visited instances **3 114 364** -- the 13.2 % gap between the last two is the emitter's **nine** terminator `break` sites in `emit/block.rs` (each sets `terminated = true` before breaking; the per-site list is `baseline/census/CONTEXT.md`'s) plus continuation sub-blocks re-covering a tail. Detail: `baseline/census/CONTEXT.md`.
- **`tests/jit_real_module.rs` is the oracle gate on the interpreter + baseline pair.** Its **504 breadth rows** (171 modules) **+ 232 error-path corpus rows** (215 modules) each drive **both** tiers, assert the two tiers agree under `beam_term::cmp`, and check *each* tier's own outcome against the baked oracle expectation (`tests/support/oracle.rs`: the `~w` value for the breadth corpus, the class + reason term for the error-path corpus via `verify_error`) -- **223** of the 232 error-path rows are oracle-checked, the other **9** being the fixture's own documented host gap (the same typed gap on both tiers, printed as `BLOCKED:` lines and counted), so **727 oracle-checked rows run on each of the interpreter and the baseline tier** (504 breadth + 223 error-path). No row disagrees with the oracle: tier agreement can no longer hide a shared mistake, and a regression that stops checking either tier fails the per-corpus floors. `tests/jit_cranelift_real.rs` carries the interpreter + Cranelift leg of the same per-tier evidence over the same two corpora (feature-gated).
- **`cached_module_blocks` self-disables on `RefCell` re-entrancy**, silently making the driver run that callee on its per-instruction step -- a documented performance cliff, never a correctness one (`cache/CONTEXT.md`).
- **The per-run memo for the cross-function in-block transfer is a measured net loss and is not in the tree** -- the residual there is the frozen skipped-iteration reproduction, not entry resolution (`baseline/runtime/CONTEXT.md`, `baseline/measure/CONTEXT.md`).
- **The `jit_bench` harness is eager-only**, so it pins the eager whole-module artifact and does not measure the lazy per-entry path the runtime uses (`bench/CONTEXT.md`).
- **`Machine::local_call_seam` is the host-owned top row of the profile** and must not be short-circuited from the tier (`baseline/measure/CONTEXT.md`).
- **A `NO_FAIL` `bs_match`'s raise reason is unsafe to compare — a `beam_term` gap, owned by that crate (upstream/out-of-node).** The family raises `{badmatch, Subject}` whose second element is a live **match context** (an `ErlSubBits` with `base_flags == 0`, windowing the subject); `beam_term`'s comparison and `bit_at` resolve bit data through that word, so comparing or reading such a term dereferences a null base — a non-unwinding abort, not a typed error. The in-crate `NO_FAIL` row (`baseline/bs_match_deopt_tests.rs::a_no_fail_match_raises_the_badmatch_reason_with_the_exact_subject`) therefore pins the reason's arity, its `badmatch` atom and the subject's bit-window size instead of comparing the term structurally.

## Routing Table
- `mod.rs` → the tier seam: `Tier`/`Tier::ALL`/`available_tiers`, `JitBackend`, `CodeRegion`, `run_cranelift*` and the feature gating.
- `tiering.rs` → `TierPolicy` (the interpret → baseline → hot escalation, a policy only).
- `cache/` → the cross-run compiled-block cache: `CodeCache`, `CacheKey`/`ModuleKey`, the thread-local `run_baseline_cached{,_outcome,_label_outcome,_resume_outcome}`, `cached_module_blocks`, `baseline_code_map`, `remember_module`; see `cache/CONTEXT.md`.
- `emitter/` → the x86-64 encoder + executable `CodeBuffer` (the crate's **only** executable-memory mapping); see `emitter/CONTEXT.md`.
- `cranelift/` → the optional Cranelift hot tier (feature `jit-cranelift`): `CraneliftJit`, `CompiledFunctions`, `CodegenReport`, `run_resume_outcome`, the inline set relative to the baseline and the measured default-OFF verdict; see `cranelift/CONTEXT.md`.
- `baseline/` → the native x86-64 baseline backend: `BaselineJit`, the two artifact layouts (eager / lazy + compile-on-entry), the drivers and the `NativeCode` trait, and the `NativeCode`-generic no-reset resume seam `run_native_resume_outcome` (which `run_compiled_resume_outcome` and the Cranelift tier both call); see `baseline/CONTEXT.md`.
- `baseline/runtime/` → the block-ABI words, the `JitRuntime` layout and offsets, every per-instruction helper, the driver loop and its reduction charge, the resume driver, the cross-module switch, the in-block transfer and the `Machine::current_code` store set; see `baseline/runtime/CONTEXT.md`.
- `baseline/emit/` → the compilation entry points + the continuation sub-blocks and the per-instruction emitters, with its own children `shapes/` (the lowering dispatch and the restricted shapes), `prologue/` (position store and Y-window publish/refresh), `regalloc/`, `regs/` (the register cache, dirty spill and partial fill), `link/` (exits, the frame teardown, the in-block transfer arm) and `test/`; see `baseline/emit/CONTEXT.md`.
- `baseline/emit/bitstr_inline/` → the nine native `Bs*` shapes (the eight match-context shapes plus `bs_create_bin`'s private-append construction build), their syntactic shape predicates, the shared subject view + big-endian bit extractor, and each shape's one-interpreter-step fallback; see `baseline/emit/bitstr_inline/CONTEXT.md`.
- `baseline/inlineset/` → the **authoritative** inline set (which groups are lowered in-block, the guards each carries) and the "do not re-open" levers; see `baseline/inlineset/CONTEXT.md`.
- `baseline/measure/` → every measured figure, its instrument and discipline, and the rejected alternatives; see `baseline/measure/CONTEXT.md`.
- `baseline/census/` → the test-only deopt / execution / code-size censuses and their gate commands; see `baseline/census/CONTEXT.md`.
- `baseline/testing/` → the in-node suite enumeration (`tests.rs`, `call_tests.rs`, `family_tests.rs`, `raise_tier_tests.rs`, the `bs_match` deopt-idempotency and foreign-kernel parity suites, …); see `baseline/testing/CONTEXT.md`.
- `bench/` → the in-crate thirteen-workload interpreter-vs-baseline harness (`pub mod bench`: `run_workloads_on(tier)` for one tier, `assert_tier_agreement` for all) plus the `support.rs` scaffolding shared with `cranelift/bench.rs`; see `bench/CONTEXT.md`.
