## Execution model (frozen semantics -- reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame** (`src/machine/frames.rs`): `allocate`/`allocate_heap`/... push `stack_need + 1` words -- a *continuation-pointer slot* then `stack_need` Y-registers (`y(k)` = the slot after the CP slot, C's `E[1+k]`); the CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), not a raw word. A CP is a code pointer into a **specific module context** (C's model: the code address itself identifies the module), so it is exact even for a frame-less function that stores a continuation into its caller's frame. `call` stores the continuation in the current frame's CP slot then jumps; `return` follows it -- `Machine::continuation_step` maps a `Halt` to `Step::Done`, an address in the current context to `Step::Goto`, and an address in another context to `Step::Enter` (one integer compare); a frame-less leaf reads the *caller's* CP slot; `deallocate(n)`/`call_last{n}`/`call_ext_last{n}` pop the frame (its `n` Y slots **and** the CP slot); reaching the bottom frame (`Continuation::Halt`) halts and yields `x(0)`.
- **Tail-call frame discipline (`call_ext_last`/`call_last`).** The frame is popped **after** the callee succeeds (C's `call_light_bif` asserts `E == c_p->stop` **across** the BIF call, `emu/ops.tab:964`), so a **raising** callee unwinds from the live frame and `handle_error`->`next_catch` reports *its own* reason, and a `Deallocate` left **stale** after a `trim` (`gap/1`'s stale `call_ext_last`) is never a frame-size artifact. On success the frame is popped and the caller's continuation followed (C's `deallocate_return D`); `call_last` resolves its target label **before** popping. `CallExt`/`CallExtOnly` (no fail label => every error is a raise) and `CallOnly` follow the same discipline (`tests/tailcall.rs`).
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`): discard the lowest `n` Y slots and renumber the survivors down; the `remaining` operand is JIT-only. `test_heap{heap_need, live}` calls `Machine::ensure_heap(heap_need.words(), live, ctx)` -- which hands the whole root set (`x[0..live)`, the whole stack **and the whole FR file**) to `ctx.ensure_heap_full` -- with the stack unchanged, and `allocate`/`allocate_heap` recover the word count via `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter/`, `src/machine/drive.rs`)
- The loop is `machine::drive::Machine::drive(module, labels, func, pc, ctx) -> Result<RunOutcome>`: it owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, and re-borrows `(active_module, active_labels)` **per iteration**. It holds the entry module **borrowed** (`&Module`, context `0`) and every entered module **owned** via its `Arc<ModuleContext>` handle, so a callee's module identity survives a suspension; it binds the starting context from `current_context()` (`0` for a fresh run, the blocked context for a resume), switches context + re-binds `literals` only on a `Step::Enter` whose context differs (so an intra-module `Step::Goto` costs nothing), and returns `RunOutcome::Wait`/`Returned`. It also latches the A.8 gate once per run.
- Each iteration reads `active_module.functions[func].code[pc]` and dispatches with a safe `match` (the IR is pre-decoded, so typed dispatch is equivalent to a jump table); core arms mutate `func`/`pc` in place, the catch-all calls `families::dispatch` and folds its `Step` back. `step_instruction` is shared by the interpreter loop and the JIT deopt helper.
- `Machine::enter_run` builds the module-wide `Label -> (function index, code index)` `LabelMap` (a missing label is `error::unknown_label`). The residual `Instr::Generic` opcodes go to `src/generic.rs` -- a **pure sentinel** (every one returns `error::unsupported(op.name())`); every opcode the interpreter executes has its own typed IR variant (e.g. `is_any_native_record` = `Instr::IsAnyNativeRecord`, executed by the records family).
- **The `call_ext*` / `return` / raise context transfers.** Each `CallExt`/`CallExtOnly`/`CallExtLast` arm first calls `resolve_call_ext_apply` (`dispatch.rs:689`), the `erlang:apply/3` special case: for an `erlang:apply/3` import (`import_arity == 3`; `erlang:apply/2` is `apply(Fun, Args)` and is not special-cased) it reproduces C's `fixed_apply` -> `apply()` register decode (`x(0)=Module`, `x(1)=Function`, `x(2)=Args`, the nested `apply of apply/3` unwrap, the argument-list walk -- `MAX_ARG` -> `error:system_limit`, a non-proper tail -> the catchable `badarg`) and hands the outcome to `families::funs::apply_target`; any other import returns `None`. Otherwise the arm resolves the import through `resolve_external_entry` (the per-run `LabelMap::import_target` for the `(module, function, arity)`, then `ctx.resolve_external_call`; a `Some` registers the callee context and resolves the entry label against the callee's own map). On `Some` they use the LOCAL discipline and report `Step::Enter`: `CallExt` = `Instr::Call` (stores `Continuation::Address{func, pc+1, context: current_context()}` in the current frame, i.e. the caller's context), `CallExtOnly` = `CallOnly` (no continuation change), `CallExtLast` = `CallLast` (the target is resolved **before** `pop_frame_checked(deallocate)`, and the arm applies the same `ImportFrame` discipline to a resolved `apply/3` target via `apply_import_target`). On `None` they are byte-identical to a plain `call_bif` dispatch. A **host BIF error** from the resolved target -- on the synchronous `call_bif` route or the `apply/3` route -- is routed through `Machine::raise_bif_error` (`ApplyTarget::Raised`), landing in the caller's live `try`/`catch`. `Instr::Return` emits `Step::Enter` when the target context differs; `throw_with_trace` emits `Step::Enter` when a live catch frame lives in another context; `ApplyLast` follows its (popped) frame's continuation through `Machine::continuation_step` and emits `Step::Enter` when that continuation's context differs from the running module's.

### Instruction surface -- **executed** (per-opcode edge-case detail lives in each `src/families/` module's docs; `tests/opcodes.rs` covers the rest)
**Core-loop arms.** Metadata/no-ops `Label`, `Line`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart`, `OnLoad` (`ops.tab` lists them with no body, so `Step::Next` is exact). `FuncInfo` raises class `error` with the **bare atom** `function_clause` from the running module's atom table (call args ride in the stacktrace, not the reason; a module lacking the atom is a typed `unsupported`) -- a function's callable entry label is the label *after* `func_info`, reachable only by a JUMP from a failed head-pattern/guard `fail` label, matching C's `i_func_info_IaaI`; the baseline JIT deopts it. The uncaught raise goes through the uniform funnel `Machine::with_uncaught_frames`, which attaches the frames `Machine::raise_stacktrace(entry_module, func, pc)` derives from the live call frames (the raising function first, each frame resolved in its own module context), so the bare-atom reason is still localizable; a caught raise is unaffected (the frames are metadata on the uncaught `Raise` only). `Move`/`Swap`/`InitYregs`. `Test` (**all** `TestKind`s) and `SelectVal` (exact `=:=` against each `(value, label)`, else `fail`, else -- `fail == NO_FAIL` -- class `error` with the bare atom `function_clause`). The control ops `Jump`/`Call`/`CallLast`/`CallOnly`/`CallExt`/`CallExtOnly`/`CallExtLast`/`Allocate`/`AllocateHeap`/`TestHeap`/`Deallocate`/`DeallocateReturn`/`Trim`/`Return` (frame discipline in sec. Registers, stack & frames; the rest match C), `GcBif`/`Bif0`/`Bif`, and the eight native-record variants. `Instr::Generic` executes **nothing** (see the dispatch loop). `DeallocateReturn(N)` is the loader's fused `deallocate N; return` superinstruction (`beam_loader::lower::fuse`): `pop_frame_checked(N)` then the shared `Machine::return_step` the plain `Return` arm also uses; `Deallocate`/`Return` stay live for hand-built modules that bypass the loader.
**Operands.** `X(n)`/`Y(n)` (bounds-checked -> `error::bad_register`), `Typed{reg, ty}` (annotation ignored), `FloatReg(n)` (the FR file), `Integer(i)`/`Character(c)` (a small int, else an exact bignum via `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil`; `Literal` (an index into the running module's decoded literal area) is read via `crate::operand::read_operand` (`Machine::literal`) while `Label`/`List`/`Allocation` are a typed `error::unsupported` there, and `write_operand` rejects every non-register destination.
**`GcBif`/`Bif` failure semantics.** Evaluate the arg operands, call `ctx.call_bif`: `Ok` stores into `dst`; `Err` with a live `fail` label **jumps to `fail`** (guard failure); `Err` with `fail == NO_FAIL` **raises** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`). **`Bif0`/`CallExt*` carry no fail label, so every error is a raise.**
**`raise_bif_error`.** A `BeamError::Raise` **carrying a live reason term** (`Raise::live_reason`, payload `Eterm`) is raised through `Machine::throw_with_trace(class, term, NIL)`: with a live catch frame it lands in the handler (`x(1)` = the term), else it propagates the term-carrying `Raise`. Every other case: with no live catch frame the error propagates as-is; with one, the error's BEAM atom name (`BeamError::as_atom()`) is resolved in the running module's atom table and raised with class `error`. An error the engine cannot name as a term (no atom, a `Raise` without a live slot, `TermNotFound`, `Io`) propagates unchanged, never substituted by a *different* atom.
**`Test` semantics.** Succeeds => fall through; fails => jump to `fail`, or -- when `fail == NO_FAIL` -- raise class `error` with the **bare atom** `function_clause`, resolved from the running module's own atom table by `raise_function_clause_no_fail` (matching C's `$FAIL_HEAD_OR_BODY`/`goto find_func_info`, `emu/macros.tab:266` + `i_func_info_IaaI`, which land the same bare reason). The installed `erlc` never emits `{f,0}` for `test`/`select_val`, so this is pinned from the C `FAIL`/`func_info` ground truth, not from an `erl` oracle; a module whose table cannot name the atom yields the honest typed `unsupported_opcode: test: no 'function_clause' atom in the module` (never a fabricated index). Comparison kinds: `IsLt`/`IsGe`/`IsEq`/`IsNe` use arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` exact equality (`cmp`). Type kinds: every `TestKind` the loader defines -- the type tests, `IsList`, `IsBoolean`, `IsFunction`/`IsFunction2`, `IsTaggedTuple`, `TestArity`.
**Family-claimed opcodes** (one `src/families/` module per family; the `exec`/`dispatch` contract is in the families seam above; edge-case semantics are in each module's own docs):
- `tuples.rs`: `PutTuple2`, `GetTupleElement`, `SetTupleElement`, `SelectTupleArity` (a non-tuple source or shape/arity mismatch takes `fail`; `{badmatch, Value}` only on the no-fail path; `SetTupleElement` writes `tuple_val(Tuple)[1 + offset]` **in place**, raising the read path's `{badmatch, Source}` for a non-tuple/out-of-range target and the typed `unsupported` for a term in a module's immutable literal area).
- `records/{mod,raw}.rs`: `UpdateRecord`, `IsAnyNativeRecord`, `IsNativeRecord`, `GetRecordElements`/`GetRecordElementsId`, `PutRecord`, `IsRecordAccessible`, `GetRecordField`, `UpdateRecordId` -- the whole family, `erl_record.c` branch for branch (incl. `PutRecord`'s *create* form, where `badfield` outranks a delayed `novalue`, and C's export/scope rules: `IsRecordAccessible` strict only when `scope = external`, else the `$MODULE` wildcard, and `GetRecordField` needs no export for an atom `Id`); a foreign-module id is `unsupported`.
- `lists.rs`: `PutList`, `GetList`, `GetHd`, `GetTl` (a non-cons source raises `{badmatch, Value}`).
- `funs/{mod,tests}.rs`: `MakeFun3` (arity = descriptor arity minus `num_free`), `CallFun` (fun in `x(arity)`, args `x(0..arity)`), `CallFun2`, `Apply` (M in `x(arity)`, F in `x(arity+1)`), `ApplyLast` (pop the frame first). `CallFun`/`CallFun2` consult the in-machine closure-apply seam `ExecutionContext::resolve_local_fun` **first** (the shared `call_fun`): on `Some((callee, label))` the engine copies the closure's free variables into `x(arity..arity + num_free)` (C's `reg[i + arity] = funp->env[i]` order -- arguments first, captures after), registers `callee` as a module context, resolves `label` against that module's **own** label map, stores the caller's return address in the live frame and reports `Step::Enter`, so a `receive`/raise inside the closure stays in *this* process; on the seam's `Ok(None)` default the value-returning `ExecutionContext::apply_fun` is the fallback (the fun kinds with no local label -- an external `fun M:F/A` and the `-eval` evaluator's closure). `Apply`/`ApplyLast` resolve their `M,F` target through the cross-module-call seam (`ExecutionContext::resolve_external_call`) **first**: on `Some((callee, label))` the callee is registered as a module context and entered **in this machine** -- `Apply` stores the **caller's** return address (`Continuation::Address { func, pc + 1, context: current_context() }`) in the live frame and reports `Step::Enter`, and `ApplyLast` reports `Step::Enter` on its already-popped frame (so the callee's `return` follows the caller's continuation); on the seam's `Ok(None)` default the target is the synchronous `call_bif` route, and `ApplyLast` then follows its (popped) frame's continuation context-aware via `Machine::continuation_step` (a tail apply must return into the **caller's** module, so a continuation in another module context yields `Step::Enter`, never a bare `Goto`). A non-atom `apply` target is `badarg`. Every raise from the applied target -- the `Apply`/`ApplyLast` host BIF error and the `call_fun`/`call_fun2` seam/fallback error alike -- routes through `Machine::raise_bif_error`, so it lands in a live `try`/`catch` (the `apply` path reports it as `ApplyTarget::Raised`) instead of escaping; the `call_ext*`-encoded `erlang:apply/3` shares `apply_target` through `resolve_call_ext_apply`, while `erlang:apply/2` is not special-cased.
- `exceptions/{mod,raise,stacktrace,tests}.rs`: `Badmatch`, `CaseEnd`, `TryCaseEnd`, `IfEnd`, `Badrecord`, `Raise` (re-raise with the handled class), `Try`/`Catch`, `TryCase`/`TryEnd`/`CatchEnd` (each consumes one catch frame), `BuildStacktrace`, `RawRaise` (both in Known Issues).
- `floats/{mod,arith,convert,tests}.rs`: `Fmove`, `Fconv`, `Fadd`/`Fsub`/`Fmul`/`Fdiv`, `Fnegate` (non-float operand / non-finite result -> `fail` when live, else `badarith`; `Fconv` converts a bignum via `beam_term::number::big_to_f64`, over-range -> `badarith`).
- `maps/{mod,read,write,tests}.rs`: `GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact` (both layouts read via `terms::map_entries`; keys via `beam_term::cmp` so `1` and `1.0` differ; a non-map source `fail`s on the compiled forms, else `{badmap, Source}`; built via `terms::make_map`, >32 keys -> hashmap).
- `bitstrings/{mod,raw}.rs` + `{matching,create}/*`: `BsStartMatch3`/`4`, `BsMatch`, `BsMatchString`, `BsTestTail2`, `BsGetTail`, `BsGetPosition`/`BsSetPosition`, `BsGetInteger2` (any width), `BsGetFloat2`, `BsGetBinary2`, `BsSkipBits2`, the UTF reads, `BsCreateBin` (integer/binary/float/utf8/16/32/string), `BsInitWritable` + an `append`/`private_append` segment in **any** position (seed-and-rebuild: the source's bits are concatenated at the point the segment appears). A result is an on-heap `ErlHeapBits` <=64 bytes else an off-heap refc binary; the match-context is an on-heap `ErlSubBits`-shaped box re-derived per opcode, so matching survives calls and branches.
- `receive.rs` (registered **last**; no term inspection -- every mailbox position/removal goes to the `Mailbox` seam): `Send` (deliver `x(1)` to `x(0)`, store **the message itself** in `x(0)`), `LoopRec` (candidate -> `Dst`, else `Fail`), `LoopRecEnd`, `Wait`, `WaitTimeout` (a small-int `0` falls through to `timeout`, else suspends like `wait`), `Timeout`, `RemoveMessage`, the four `RecvMarker*`.

### Raising opcodes and the catch-frame model (`families/exceptions/`, `src/machine/catch.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, which owns it) and blank their frame slot. A raise (a family's `throw`/`throw_error`, or `raise_bif_error`) records `pending_exception = (class, reason)` then consults the **innermost** live catch frame.
- To land, the machine unwinds the call-frame stack back to `CatchFrame::frame_index` (dropping every deeper frame's Y slots) and writes the handler registers exactly as C's `handle_error`: `x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace` (`NIL` at M1), `x(3) = class atom`; a landed raise returns `Ok(Step::Goto{func,pc})` when the handler is in the current context, else `Ok(Step::Enter{context,func,pc})` (the driver switches context so the callee's own `catch` handles a raise that crossed a cross-module call), and with no live catch frame (or an unresolved class atom) it stays the typed `Err(BeamError::Raise(..))` -- never a panic. The raise *reads* the innermost entry but **never pops it**; the handler opcode (`try_case`/`try_end`/`catch_end`) consumes exactly one entry (never both). `try_case` blanks its slot, requires the `THE_NON_VALUE` marker in `x(0)` and moves the class atom from `x(3)` into `x(0)`; `catch_end` leaves a normal result untouched but folds a landed exception into the caught term -- the thrown value for class `throw`, `{'EXIT',Reason}` otherwise.
- The class atoms (`error`/`exit`/`throw`) are pre-resolved per run by `Machine::ensure_class_atoms` through `machine::namespace_atom` (the host's live namespace first, the running module's snapshot second) and installed with `Machine::set_class_atom`; an atom neither source knows is never substituted by a *different* atom. `pending_class` is the class a `raise` opcode re-raises with (C's `i_raise` keeping `freason`).
- **The raise entry points (`src/machine/catch.rs`).** `Machine::throw`/`throw_error` are the uniform raise/unwind entries the families call; `Machine::throw_with_trace` is the same entry carrying the caller-built `trace` term (C's `x(2)`; `NIL` at M1). `throw_with_trace` also rebuilds the machine's **raise-time frame snapshot** (`Machine::raise_snapshot`) at its head -- the pre-unwind `(context, func, pc)` chain, the **raising** frame first then every live caller innermost-first -- *before* the catch-frame branch and `unwind_to_frame`, so it is refreshed on **both** the caught and the uncaught path (this is the engine's replacement for C's saved raw `StackTrace`, `c_p->ftrace`). The symbolic `StackTrace` a raise carries out when it leaves the machine **uncaught** (`Raise::stacktrace`) is attached not at the raise site but by the single funnel `Machine::with_uncaught_frames(err, entry_module, func, pc)` as the raise leaves the machine (at the `step_instruction` / `drive` boundary), so **every** raise kind -- a `throw`/`error`/`exit` `raw_raise` builder, a BIF error through `raise_bif_error`, the `func_info` failed-clause raise -- gets the same frames and no site derives them itself. `Machine::raise_stacktrace(&self, entry_module: Option<&Module>, func, pc)` derives those frames from the machine's live call frames -- the raising function first, then each caller, each resolved in **its own** module context -- which is what localizes a bare-atom reason (the `FuncInfo` arm above). The funnel attaches only to a `BeamError::Raise` that carries no frames yet and whose reason is not an engine diagnostic (`error::unsupported`), so a caught raise, an already-framed raise and an engine diagnostic are all returned unchanged. The stacktrace is **metadata only**: the landing registers, the reason and the pending class are untouched, so a caught raise behaves byte-identically with or without it.

## Design Decisions
- **Root-set contract made concrete, with both admission doors defaulted.** The primary admission point is the defaulted `ensure_heap_full(heap_need, roots)` over `RootSet`, which `Machine::ensure_heap` calls so the context gets the exact GC root set (`x[0..live)` + the whole stack + the whole FR file) and a Stage-4 collector can move terms in place without frame liveness maps; its default forwards to the frozen narrow `ensure_heap(heap_need, live, x_regs, stack)` with the FR file discarded, so an existing host is byte-identical. The **second** admission point is `alloc_words_rooted(n, roots)` over `RootSet` (`x`/`stack`/`fr`, all mutable, plus the `live` hint) -- the root hand-off for *term construction*, because `alloc_words` itself has neither an admission point nor roots; its default discards the roots and forwards to `alloc_words`, so an existing host is byte-identical. **Every in-crate term-construction arm routes through the second door** via the `terms::*_rooted` builders, which follow the frozen **reserve → read → write** discipline (`reserve` the block first with *exactly one* rooted allocation, then read operands from the machine's post-collection state, then write the header/element words); `src/terms/slack.rs` is the reserve seam and `src/terms/sink.rs` the `Sink` shape writer a multi-node build is carved from. `terms` is the crate's dedicated raw-heap accessor module (the per-family `raw` modules and the JIT encoder are the documented layout exceptions, listed in `CONTEXT.md`); every in-crate construction **arm** goes through a `*_rooted` twin, while the classic unrooted builders (`terms/{construct,number,map,fun,sink}.rs`, plus the four `&self` execution-position accessors in `src/machine/location.rs` that cannot lend `&mut` roots) are the host/test API and are reachable in production only from a caller that already cannot collect.
- **A typed frame CP slot rather than a raw stack word**, with a catch-frame stack mirroring C's `next_catch` + `c_p->catches` split, so the landing convention (`x(0..=3)`) and the bookkeeping live in one place.
- **JIT tiers off the critical path; compile failure a typed error.** Cranelift is optional (default OFF), so with it off neither the crate nor the build carries Cranelift at all; compilation is measurement-gated (sec. F) with a bounded-latency, cheap-deopt design, and `TierPolicy` is deliberately **not** wired into execution. A `CodeBuffer::seal` failure propagates out of `compile`/`run_export`, and an unresolved `Jump` target deopts so the interpreter's `unknown_label` surfaces. The measurement harness lives in `src/jit/bench` (a `pub mod bench`, driven by `tests/jit_bench.rs`); its ten workloads, method and caveats are in `src/jit/bench/CONTEXT.md`, the figures in `MEASURED.md`.
- **One driver for both native tiers, delegating per instruction rather than duplicating semantics.** A tier supplies its compiled-code lookup through the `NativeCode` trait (`enter(rt, func, pc) -> Option<i64>`); because `jit_step_one` *is* `Machine::step_instruction`, every tier is interpreter-identical for every supported opcode without a second implementation.
- **The cross-module call seam is additive and host-driven.** `resolve_external_call` (default `Ok(None)`) lets a host that owns loaded modules run a `call_ext*` **in the same machine**, so a `receive` inside the callee suspends the driving process (`RunOutcome::Wait`) instead of folding into `Err(error::blocked())`. The mechanism is C's model: a code pointer (the frame `Continuation`) carries its module context, so a `return`/raise can land in another module; the driver (`Machine::drive`) owns the `(func, pc)` position + its context and re-binds the literal area only on a `Step::Enter` to a different context. Modules are held as `Arc<Module>` handles deduped by `Arc::ptr_eq` (bounded by distinct modules, not call count) and cleared only by `reset` -- never by a resume, because a suspended cross-module frame must still name its module. The seam executes on the native baseline tier through a **driver-mediated module-context switch**: a resolved transfer is not in the JIT inline set, so the block deopts one step, that step hands the driver a `Step::Enter` (the `ENTER` block-ABI word), and the driver switches module context and re-enters the callee's compiled blocks (when the tier has them). A seal-time cross-module *link* is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`), so the transfer stays a driver round-trip by design.
- **Unsupported => `Raise` with reason atom `unsupported_opcode`** (a dedicated `BeamError` variant must not be added from here); the slice `.beam` fixture lives with `beam_loader` and is read by relative path.
- **The FR file stores `Eterm` term slots at M1** (C's is raw doubles), so `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is deferred.
- **M1 fun layout inlines the descriptor** (`uniq`, `index` after the header; no code pointers at M1) -- the same substitution as the external-pid `node` slot (`MAKE_FUN_HEADER` + `ErlFunThing`). `MinimalContext` fun application goes through an apply hook (no closure registry here), `build_stacktrace` cooks from the machine's **raise-time snapshot** (`Machine::raise_snapshot`) rather than the live call frames, and `update_record` always copies (the hint only authorises updating a unique/dead source).
- **Flat, integer-keyed hot-path state (safe Rust).** Jumps resolve through `LabelMap` -- a dense `Vec<Option<(func,pc)>>` (`Slots::{Dense,Sparse}`) built once per run by `Machine::enter_run` (the loader's label ids are dense: `lists.beam` has 1256 labels, max id 1256) -- so a jump is one array index. Each import's `call_bif` target is resolved **once per run** into an `ImportTable` of `ImportTarget { module, function, arity }` cached in `LabelMap` keyed by the owning `Module` address (a different module falls back to the free `import_target`). `GcBif`/`Bif`/`Bif0`/`CallExt` marshal arguments through a fixed-lane `STACK_ARGS = 2` stack array (the dominant arities build an exact-size slice LLVM can SROA); arities >= 3 reuse a per-`Machine` `args_scratch`, so a BIF call allocates **nothing** -- proved by `tests/bif_alloc.rs`. `read_operand` is inlined and ordered hot-first; `Machine::reset` refills the register/FR files in 128-byte chunks. None of this changes semantics: the reference point stays `Machine::step_instruction`.
- **Hot-path inlining is measurement-driven, never blanket.** An out-of-line helper returning `Result<_, BeamError>` (a 72-byte `Err`) forces its `Ok` through memory, so the interpreter's *small* hot helpers are `#[inline(always)]` — `read_operand`/`write_operand` (`src/operand.rs`), `test_arg` (`src/interpreter/test.rs`), `set_y` (`src/machine/frames.rs`) — while `step_instruction` and `eval_test` carry plain `#[inline]`. The same attribute is a **measured regression on large helpers**: `#[inline(always)]` on `exec_bif`/`call_import` costs ~20%, and caching the resolved `functions[func].code` slice across the dispatch loop costs ~19% (the extra live range across `&mut self` calls and the code bloat outweigh the saved `Vec::get`), so neither is applied. The residual per-instruction cost is structural, not a missed hint: the 64-byte `Instr` discriminant `match` in `step_instruction` (a mispredicted indirect jump), the `Result<Step>` loop plumbing, the double `Vec` bounds check (`functions.get`/`code.get`), and the arity-2 `gc_bif` marshal (the largest single leaf on the list walk).

## Known Issues / Intentional M1 gaps
- **The collecting host is `beam_rt`'s side, not an engine gap.** `MinimalContext` has an unbounded, never-freed reserved-heap-region arena, and `test_heap`/`allocate_heap` reach the full-root admission point (`ensure_heap_full`, a no-op there -- its default forwards to the no-op `ensure_heap`). The engine's own half is landed: **every** in-crate term-construction arm allocates through the rooted door (`alloc_words_rooted` / `Machine::alloc_rooted` / the `terms::*_rooted` builders), under the frozen reserve → read → write ordering, proved under a mock **moving** collector by `src/terms/alloc_tests.rs` (the rooted-vs-unrooted peak/retained live-words table) and `tests/rooted_alloc.rs`, with the root hand-off pinned by `tests/gc_roots.rs`. **`beam_rt`, the production heap, overrides both rooted doors** (`beam_rt/src/context/execution.rs`) -- it publishes the whole `RootSet` (every x slot, the whole stack, the whole FR file), runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a container in a region the collector does not scan -- so an ordinary `beam_rt` run collects at the engine's heap-admission point, conservatively gated (`beam_rt/src/context/gc.rs`: a process is pinned once a live float register is seen, halted on a collection error, and a global valve disables collection once an escaped runtime store holds an off-heap term). A collecting host must additionally root what the `RootSet` cannot carry: `Machine.pending_exception` (`src/machine/catch.rs`, reachable mutably through `Machine::pending_exception_mut`) and the `Eterm` arguments parked in `Machine.args_scratch`/the `exec_bif` stack array while a `call_bif` is in flight. Detail: `src/CONTEXT.md` (`## GC publication…`).
- **A captured stacktrace is engine-derived.** `raw_raise` is oracle-exact for all three classes and the unknown-class fall-through (`x(0) = badarg`, no raise); `build_stacktrace` cooks the symbolic list from the machine's **raise-time snapshot** (`Machine::raise_snapshot`), resolving each frame in its own module context, for both a non-`NIL` raw `x(0)` and a `NIL` `x(0)` at a catch where a raise was recorded (a `NIL` with no recorded raise still yields `NIL`, C's `get_trace_from_exc(NIL) == NULL`). The snapshot holds only the run's own interpreted frames and is therefore strictly partial (an empty snapshot, or one whose every frame is skipped, cooks to the empty list); it also cannot name a context-`0` frame when the handler runs in a non-zero context (a raise caught across a cross-module `call_ext`), so the residue is the **context-0-from-a-non-zero-handler** case. Because the trace is partial, `x(2)` stays `NIL` on the compiled path (see the family docs).
- **Nameable atoms required, resolved through the live namespace.** `catch_end` needs the `EXIT` atom, and a raise needs its reason/class atom; both are resolved through `machine::namespace_atom` = `ExecutionContext::atoms(module)` (the host's ONE live namespace) with the module's load-time snapshot as the fallback, so an atom interned into the shared namespace *after* the module loaded still lands the raise in a live catch frame. `Machine::ensure_class_atoms` (the first statement of `families::dispatch`, so both tiers pass it) pre-resolves `error`/`exit`/`throw` per run. A name **neither** source knows propagates as a typed error (`unsupported`, or the `BeamError` unchanged for `TermNotFound`/`Io`/an empty non-`Eterm` `live_reason`); no path ever substitutes a different atom.
- **Compiled arithmetic is oracle-exact on overflow.** `+ - * div rem` promote to exact bignums (compiled `gc_bif` goes through `ctx.call_bif` into `beam_bifs`); an out-of-range `Integer`/`Character` **operand** becomes an exact bignum via `terms::make_integer` (which the JIT's `constant_word` deopts).
- **A blocking `receive` needs a host mailbox** (Handoffs #1): with no mailbox each `Mailbox` call is a typed `unsupported("<method>")`, and a mailbox with no candidate **suspends** (`RunOutcome::Wait`, folded into `error::blocked` by plain `run_export`); a parked `wait_timeout` publishes its deadline through `Machine::wait_deadline` (the `timeout` continuation + the delay, read from a literal or a Y slot), but with no host timer it stays parked until a message arrives (only a small-int `0` falls through to `timeout`). A host that also **adopts the cross-module seam** (`resolve_external_call`) gets the suspension out of a `call_ext` callee too -- the callee runs in the same machine, so a `receive` inside it reports `RunOutcome::Wait` to the driving process instead of folding into an error (`tests/external_call.rs`).
- **Records.** The whole native-record set executes, including `PutRecord`'s *create* form for the running module's own records (`Src` the literal `nil`; the definition from `beam_loader::Module::{records,record,record_by_name}`, hashed with `beam_term::hashing::compute_record_definition_hash`). Only an `Id` naming a *foreign* module's record is a typed `unsupported`; a record-semantics failure branches to the instruction's `fail` label (`NO_FAIL` -> `unsupported("<instr>/no_fail")`). The installed `erlc` emits the native-record opcodes -- including the create form -- only for the explicit `-record #name{}` form (the legacy `-record(name,{})` form still lowers to a plain tuple), and the create form is verified **structurally** (`tests/records.rs`).
- **Bitstring gaps (each a typed result -- never a wrong value).** A refc-binary subject whose window is not byte-aligned **is** read: `raw::heap_bits` recovers `(base, size_bits, bit_off)` from the frozen `ErlSubBits` (`beam_term::bitstring_parts`), so the family reads the window's bits at whatever bit offset it starts (byte-aligned subjects start at offset 0 as before); the only subject it refuses is a match context or a bare off-heap binary reference (a typed `unsupported`). `bs_init_writable` builds a 0-bit refc binary over a `capacity`-byte payload registered as writable **on the machine** (`Machine::writable_payloads`; the frozen term layout carries no capacity word), and a **first-position** `private_append` over such a payload appends **in place** -- the same term with `ErlSubBits.end` bumped, zero allocation (C's `erts_bs_private_append_checked` writable arm). Every other shape (plain `append`, a later position, `start != 0`, an on-heap/foreign/non-registered source) copy-rebuilds byte-identically, and a build that outgrows the capacity promotes losslessly; because the payload never grows, such a loop is still O(n²) from that point (owner `beam_alloc`: a capacity-carrying payload). The `BIN_FLAG_*` flags and `binary:referenced_byte_size/1`'s capacity answer stay unmodelled (typed results only); an `append`/`private_append` segment in **any** position still concatenates the source's bits at the point it appears. `system_limit` is modelled (`size*unit` overflow / the post-multiply sign bit / a positive-bignum size; a negative bignum is `badarg`); a `float` segment of width 0 or invalid raises `badarg` (`tests/bitstrings_create_fail.rs`).
- **Literal operands.** Every installed module's `LitT` area (`EXPORT_EXT`/`NEW_FUN_EXT` fun literals, `>32`-key map literals, big integers) and wide (`>8`-byte) integer operands decode; a `Literal` index outside the running module's `LitT` table (or a read with no module bound) is the typed `operand: literal` error.
- **`y(k)` addressing and `trim` are equivalent to C's `E[1+k]`/`E += N` -- no off-by-one.** The engine keeps the continuation-pointer slot **out** of the stack (`Frame { continuation, y_base, y_count }`, so `y(k) = stack[y_base + k]`), whereas C keeps it at `E[0]` (`y(k) = E[1+k]`, `emu/macros.tab:142-147`); both discard the lowest `N` Y slots. The operands agree because the loader encodes `deallocate N` as `(N+1)` words and `deallocate` consumes the frame's **remaining** Y count -- post-`trim`, what the compiler emits (`gap/1`: `trim 1` -> `deallocate 0`). `pop_frame_checked` is deliberately **stricter** than C (which advances `E` unconditionally): a mismatch is a typed `unsupported`, never silent corruption (`tests/tailcall.rs`).
- **Map enumeration order is storage order, not canonicalized** (`erts_cmp_flatmap_keys`), affecting only `term_to_binary` byte comparison; a malformed hashmap node / `THE_NON_VALUE` / immediate item during a read is a typed `BadArg`. A missing key in a read instruction (`get_map_elements`/`has_map_fields`) with `fail == NO_FAIL` raises class `error` with the **bare atom** `function_clause` from the running module's own atom table -- the engine's single failed-clause definition `raise_function_clause_no_fail` (`src/interpreter/dispatch.rs`), shared with `func_info`/`test`/`select_val`; a module that cannot name the atom yields the honest typed `unsupported_opcode: maps: no 'function_clause' atom in the module`, never a fabricated index. The `{badmap,Source}` / `{badkey,Key}` raises of `put_map_assoc`/`put_map_exact` are unchanged (tag resolved from the module's own table, else a typed `unsupported`).
- **Reductions and pre-emption exist; the scheduler does not.** `Machine::drive` charges one reduction per interpreted instruction through the defaulted `ExecutionContext::reduce(n)` hook (`Ok(())`), **before** the instruction's body runs (`Machine::drive` records `(func, pc)` via `set_current_code` and charges the hook *before* `step_instruction`) and at a single call site **in that driver**, so the interpreter's charge is exactly one instruction (a **non-allocating** loop, which never reaches `ensure_heap`, is still pre-emptible). A host with a scheduler pre-empts by returning a **typed error** from `reduce`, which the run reports exactly like any other step failure; the pre-empted instruction is left **un-applied** and the machine parked on it (`Machine::current_code`), so a `Machine::resume_outcome` at that address applies it **exactly once**. `Machine::reductions()` reads the current slice's count (zeroed at slice entry; one `drive` call = one slice, so `resume_outcome` starts a fresh slice) and `Machine::reset_reductions()` returns it while zeroing it. There is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption is a fresh `drive` (`tests/reductions.rs`). The scheduler, run queues, trap handling and `ensure_heap` limits are Stage 5 (`beam_process`); stack growth is an unbounded `Vec`.
- **The native tiers charge the same hook once per driver-loop iteration.** The JIT driver (`src/jit/baseline/mod.rs::drive`, shared by `Tier::BaselineJit` and `Tier::Cranelift`) latches `Machine::reduce_on = ctx.wants_reduce()` and zeroes `Machine::reductions` at its entry (one `drive` call = one slice, as above), then at the top of every iteration publishes the position with `Machine::set_current_code(func, pc)`, bumps the slice counter and -- gate on -- calls `reduce(1)?`, all **before** `code.enter(...)`. An iteration is one **block entry**: a natively executed block, or the per-instruction interpreter step the driver takes for an address no block covers. That granularity is what makes the refusal a pre-emption -- the runner parks an exhausted machine at `Machine::current_code` and re-enters there, and at a block entry the published address *is* the one about to run with the block unexecuted, so the resume executes it exactly once. A refusing charge from the call-resolution/BIF seams would refuse with the block's entry position current only after part of the block had run and the resume would replay it (measured: `beam_rt -eval 'halt(0).'` exits 3 with `unsupported: opcode: run: process blocked`), so those seams stay spend-only. A host whose `reduce` is the default no-op pays one `bool` load per iteration; the counter is bumped either way. Residual: a **natively linked local tail-call chain** (`call_last`/`call_only` linked between compiled blocks) stays inside one driver entry, so it is priced once and, having no refusing seam inside it, cannot end its slice from inside -- `slice.beam`'s `fib/1` at n=18 costs 2 charges against the interpreter's 152 (`tests/jit_reductions.rs`).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after.** C fills `reg[i] = args[i]` for `i < arity` then `reg[i + arity] = funp->env[i]`, so a context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = captures -- *not* `free ++ args`. The `resolve_local_fun` seam route places the same free variables in the **engine** (the `call_fun` family copies them into `x(arity..)` before the `Step::Enter`), so a host answering the seam returns a lambda entry label that reads its captures from `x(arity..)`.

- **Atom comparison is name-exact end-to-end, through a defaulted live-namespace seam.** Every guard/`select_val`/map-key comparison site resolves atom *names* through the defaulted seam `ExecutionContext::atoms<'m>(&'m self, module: &'m Module) -> &'m AtomTable` (`Machine::eval_test`'s six comparison kinds + `is_boolean` in `src/interpreter/test.rs`, `Instr::SelectVal` in `src/interpreter/dispatch.rs`, the native baseline tier's `evaluate_comparison` in `src/jit/baseline/test_helper.rs`, and the map key ordering/lookup in `src/families/maps/{read,write}.rs`), so atom order matches the `<` BIF, which compares through `ctx.atoms()` — the runtime's ONE shared live table (`beam_bifs/src/compare.rs:104-121`). The seam's **default** is `&module.atom_table`, the **load-time snapshot** (`beam_rt/src/codeserver.rs:573` — `lower::build_module(&chunks, &raw, (*self.atoms).clone())`), which keeps every host that owns no shared namespace working; `beam_rt` **overrides** it with the live table in BOTH of its `ExecutionContext` impls — `RuntimeContext` (`beam_rt/src/context/execution.rs`) and the scheduled path's `BudgetContext` (`beam_rt/src/runner/budget.rs`, which must forward the seam explicitly because it forwards every method by hand). Without that override, an atom interned *after* a module was loaded is absent from the comparison table, and `beam_term::cmp_atoms` (`beam_term/src/compare.rs:356-363`) falls back to raw atom **index**, which has nothing to do with alphabetical order — a wrong guard branch with **no error surfaced**. Pinned by the oracle-cross-checked `src/interpreter/test.rs::tests::comparisons_order_atoms_by_name_through_the_shared_namespace` and `beam_rt/tests/atom_namespace.rs` (the real `sofs:drestriction/2` repro plus a guard over an atom interned after load via `binary_to_term`, on both the `RuntimeContext` and `BudgetContext` routes).
- **The `{tr,..}` typed-register operand is NOT implicated in the above — that path is correct.** `read_operand`/`read_operand_pure`/`write_operand` route `Operand::Typed { reg, .. }` to the underlying register and ignore the `Type` annotation (`src/operand.rs:74,162,193,201-215`), the baseline emitter's `x_register`/`y_register` do the same (`src/jit/baseline/emit/operands.rs:63-89`), and `{bif,element,{f,0},[{tr,{x,0},…},{x,5}],{x,6}}` therefore executes identically to the plain `{x,0}` form. The only engine sites that do **not** accept `Operand::Typed` are `Machine::timeout_delay` (`src/machine/location.rs:357-365`, returns `None` = "no deadline" for a typed delay register, so such a `wait_timeout` parks instead of timing out) and `eval_test_arity`'s arity operand (`src/interpreter/test.rs:202-211`, a typed error). The compiler only emits `tr` for modules compiled with type info.
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory.** `families::bitstrings::raw::{make_writable,make_binary}` build the frozen 8-word `[BinRef][ErlSubBits]` pair and push each payload handle onto `Machine::refc_binaries` (never cleared by `reset`); the `send` arm and the `erlang:send/2` special case hand the in-flight slice to the host through `send_message_with_off_heap`, and `beam_rt`'s runner parks the copied payload references in its destination off-heap table, so an engine-built refc binary survives both a **return** and a **send**. Residual: the host's memory accounting cannot yet enumerate these machine-held handles -- a measurement gap, not a correctness one. Pinned by `tests/stdlib_sweep.rs::sweep_base64_encodes_the_empty_binary`, `src/families/bitstrings/matching/mod.rs::empty_binary_bs_match_commands_and_the_writable_accumulator`, `src/families/receive.rs::send_forwards_the_machines_off_heap_binary_handles`.
- **`Instr::Allocate` skips C's heap check.** C's `allocate Ns Live` is `$AH(Ns,0,Live)` ≡ `GC_TEST(Ns+1,0,Live)` (`emu/instrs.tab:31-33`), so C **can** collect at every `allocate`; this crate's `Instr::Allocate` only pushes the frame, and the two in-crate admission arms are `AllocateHeap`/`TestHeap`. The divergence is conservative (the engine collects strictly *less* often, so it can never dangle a published root) but is why an engine run's young-heap occupancy differs from the oracle's.
- **The uncaught frames exist only for a `BeamError::Raise`.** `with_uncaught_frames` decorates **only** `BeamError::Raise`; `beam_common`'s reason variants (`BadArg`/`BadArith`/`BadArity`/`BadMatch`/`SystemLimit`) are **fieldless** and carry no `StackTrace` slot, so an uncaught BIF/op failure that travels as a bare variant exits the machine with **no frames at all**, while the same failure as a `Raise` is fully framed. Normalizing the bare variant into a `Raise` at this boundary was measured (semantically faithful) but broke **66 tests across 23 targets**, so it was **not forced**; the faithful alternative is a `StackTrace` slot on `beam_common`'s non-`Raise` variants (out of this crate's scope).
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by the engine's own opcode coverage -- so whole module families are recorded as host gaps, each asserting its EXACT typed error and never a fabricated value. All of `ets` is such a gap (`ets.erl`'s operation bodies are `erlang:nif_error(undef)` stubs); the map-BIF-backed `maps` exports and the map-dependent `proplists` ones and `string:list_to_integer/1` are gapped the same way. Owning crates: `beam_bifs` (BIF surface/seam adoption) and `beam_rt` (preloaded-module floor) -- NOT this crate. `proplists:to_map/1,2` on an `[atom | {K,V}]` list DOES execute and is pinned oracle-exact.
- **`call_fun`/`call_fun2` reports the oracle's structured reason for a malformed target, classified from the running module's own atom table.** The target shape is classified **before** the host seam, exactly as C's `call_fun` (`beam_common.c:1604-1622`) does: a target that is not a fun ⇒ `error:{badfun, Fun}` (`families/funs/mod.rs::raise_badfun`, C's `EXC_BADFUN`), and a fun whose header arity (`terms::fun_arity`, C's `fun_arity(funp)`) differs from the call's arity ⇒ `error:{badarity, {Fun, Args}}` (`raise_badarity`, C's `EXC_BADARITY`, `Args` the actual argument list). Both reasons are built through the rooted builders from the running module's atom table (the tag via `reason_atom`), never a fabricated or substituted atom. Residual: a module that cannot name the tag declines to the host *closure-apply* seam (`resolve_local_fun` ⇒ the value-returning `apply_fun` fallback), whose `Err` is routed through `Machine::raise_bif_error` -- so such an atom-poor module reproduces neither the structured reason nor a distinctive capability-gap sentinel; `beam_rt` seeds `badfun`/`badarity` in its core-atom set, so every real-runtime process takes the structured-reason path.
- **The `call_fun`/`call_fun2` free-variable copy is NOT a GC hazard (verified; do not re-open).** `families/funs/mod.rs` reads `terms::fun_free(fun)` then `set_x` for each; the source `fun` term stays published in `x(arity)`/the `call_fun2` operand, and there is **no admission point** between the read and the writes (`resolve_local_fun` is a non-collecting `&self` reader with the shipped host). The three doors that *can* collect are documented in `src/CONTEXT.md` (`## GC publication…`), together with the non-rooted engine→host calls. The real engine-relevant publication gap is the parked `pending_exception` reason term (bullet above), owned host-side.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node, and this section is the full detail.
1. **Receive/message + cross-module suspension (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome`, and drive a host **timer** for a non-zero `after` (the engine exposes the parked deadline through `Machine::wait_deadline`). A `receive` **inside a cross-module callee** suspends the caller through the cross-module call seam (Handoff #10). `resume_outcome(entry_module, func, pc, ctx)` must be called with the run's **entry** module (context `0`): `func`/`pc` are in the context the process blocked in, which the machine recovers from `Machine::context`.
4. **A *foreign* `PutRecord` create id.** `PutRecord`'s create form for the running module's own records is implemented here, and `records:get_definition/2` is served by `beam_rt`'s `RecordBridge` (`beam_rt/src/context/bridges.rs:26`); the only residual is an `Id` naming **another** module's record, a typed `unsupported`.
6. **`TestKind::TestArity` -- behaviourally equivalent to C, NOT a gap.** C's `test_arity` is an unguarded header compare, and since `tuple_val(p) == boxed_val(p)` the engine's `is_boxed(x) && ARITYVAL-header == arity` reads the same word and agrees for every boxed term; the only divergence is an *immediate* operand, where C's deref is UB and the engine safely returns `false` -- unreachable in well-formed code (the loader rewrites an immediate `test_arity` operand to a jump). Covered by `src/interpreter/test.rs` + `src/predicates.rs` tests.
7. **Map `NO_FAIL` `{badmap,Source}` / `{badkey,Key}` — closed for a seeding host; the residual is the unseeded loader.** With a host that interns the runtime's globally interned atoms before any load (`CORE_ATOMS` + the test host's `SEED_ATOMS` both seed `badmap`/`badkey`), the family raises the oracle's reason exactly. The residual is only the **unseeded** `beam_loader::load_file` path: the installed `erlc` interns `badmap` but **not** `badkey`, so a `put_map_exact` `NO_FAIL` raise there is the typed `unsupported_opcode: maps: no 'badkey' atom in the module`. Pinned both ways by `tests/maps.rs`. No engine seam resolves a tag outside the running module's table, and none should.
8. **JIT `call_ext_last` -- executes natively, by design a driver round-trip.** A **local** tail call (`call_last`/`call_only`) is linked natively; `call_ext_last` **executes** on the native baseline tier through the driver-mediated module-context transfer (a seal-time cross-module link is unsound). The residual cost is the per-transfer driver block-entry, measured by `src/jit/bench`'s `cross/2`.
9. **JIT adoption + the A.8 seam by `beam_rt` (owner `beam_rt`) -- ADOPTED.** `beam_rt/src/runner/run.rs` selects a tier at the process's first entry (default `Tier::BaselineJit` for **every** process entry, with `BEAM_RT_TIER=interpreter` the only kill switch), remembers it on the engine, routes the entry through `run_label_outcome_with_tier`, and resumes a parked slice through `resume_outcome_with_tier` on that **same** tier. The engine-side seam is **complete**. A natively-executed block records its own `(func, pc)` in its prologue, so `process_info/2`'s position is block-exact; a traced run refuses native entry. The `+JPperf` perf map (contract A.8) can be populated from `beam_engine::jit::cache::baseline_code_map(&module)`. **End-to-end evidence:** a gate run with `BEAM_RT_TIER=baseline` reports `total=1848 agree=1845 mismatch=0 unsupported=3 allowed=3` (exit 0), and the native cross-module / nested A->B->C / parked-then-resumed-slice / dynamic-`apply` shapes are pinned by `tests/jit_cross_module.rs`. Honest note: the forced tier reaches the module-run third of the corpus (566/1848); the `-eval` root expression is a tree-walk evaluator with no `Machine` and does not consult a tier.
10. **The cross-module call seam (owner `beam_rt`, the owner of `RuntimeContext`) -- ADOPTED.** LANDED and tested here (`tests/external_call.rs`, `tests/current_module.rs`) and adopted by `beam_rt`; the contract: `Some((arc, label))` for an import the host can run in this machine, `Ok(None)` otherwise (keeps the synchronous `call_bif` path -- `code:*` native floor, NIFs and everything else). `arc` must be the **SAME `Arc<Module>`** the host loaded the module with (`CodeServer::modules`, `codeserver.rs`; contexts dedup by `Arc::ptr_eq`); `label` is the export entry label (`arc.export(function_atom, arity)`, the label *after* `func_info`). `resume_outcome` takes the run's **ENTRY** module (context `0`); the suspended `(func, pc)` live in `Machine::context`. Regression repro (committed, `beam_rt`-owned): `../beam_rt/tests/proc_lib_start.rs` -- read it, do not edit `beam_rt` from here.
11. **The rooted doors are adopted by `beam_rt` (owner `beam_rt`).** `beam_rt` overrides both `alloc_words_rooted` and `ensure_heap_full`: it publishes the whole `RootSet` (every x slot, the whole stack and the whole FR file), runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a container in a region the collector does not scan. Detail: `beam_rt/src/context/CONTEXT.md`.
12. **The closure-apply seam (`resolve_local_fun`, owner `beam_rt`) -- ADOPTED.** `beam_rt/src/context/execution.rs:446` implements it as a thin wrapper over `RuntimeContext::local_fun_target`, returning `Some((target.module, target.label))` (clone the module `Arc`) and `Ok(None)` for the fun kinds with no local label, forwarded by `beam_rt/src/runner/budget.rs:257`. **The engine places the free variables itself** (into `x(arity..)`, C's `call_fun` order), so the host need not re-derive `LocalFunTarget.args`; a scheduled process's `call_fun`/`call_fun2` therefore enters a blocking closure in-machine.
13. **A built-in / static NIF library is served through the `resolve_local_call` seam -- ADOPTED (owner `beam_rt`).** The three **local** call arms (`Instr::Call`/`CallOnly`/`CallLast`) now consult `ExecutionContext::resolve_local_call` before returning their in-machine `Step::Goto`, and the native baseline tier probes the same seam at run time in `jit_local_call`; on a hit the engine marshals `x(0..arity)` and dispatches the callee through `call_bif` under the arm's own frame discipline (see the seam bullet in the API-Surface section). The motivation is ERTS's split module shape: the OTP compiler emits a **local** `call`/`call_only`/`call_last` for a **non-exported** same-module function but a self-qualified `call_ext` for an **exported** one, so `lib/kernel/src/prim_tty.erl`'s Erlang wrappers `init/1`/`reader_read/2`/`writer_loop/2` chain **locally** into the non-exported NIF stubs `tty_create/1`/`setlocale/1`/`setupterm_nif/0`/`read_nif/3`/`write_nif/2`/... (bodies `erlang:nif_error(undef)`), while only the exported `isatty/1` is reached by the caller's `call_ext`. So such a module's own Erlang runs in-machine and the host intercepts only the NIF stubs. **Correctness constraint:** `Ok(false)`, an absent resolver, and an un-nameable/missing function entry all leave the arm byte-identical to the pre-seam path (same continuation store, same `pop_frame_checked`, same trace emission, same `Step::Goto`), and the interpreter and native baseline tiers are pinned equal on both the served and the declined route (`tests/local_call_seam.rs`, incl. the eager-layout probe and the `CallLast` frame pop). The host side is landed too: `beam_rt/src/context/execution.rs:74` (`resolve_local_call`, delegating to `crate::native::prim_tty::serves_local_call`), forwarded by `beam_rt/src/runner/budget.rs:279`; no engine work is outstanding.
