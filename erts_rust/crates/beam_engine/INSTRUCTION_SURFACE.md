## Execution model (frozen semantics -- reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame** (`src/machine/frames.rs`): `allocate`/`allocate_heap`/... push `stack_need + 1` words -- a *continuation-pointer slot* then `stack_need` Y-registers (`y(k)` = the slot after the CP slot, C's `E[1+k]`); the CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), not a raw word. A CP is a code pointer into a **specific module context** (C's model: the code address itself identifies the module), so it is exact even for a frame-less function that stores a continuation into its caller's frame. `call` stores the continuation in the current frame's CP slot then jumps; `return` follows it -- `Machine::continuation_step` maps a `Halt` to `Step::Done`, an address in the current context to `Step::Goto`, and an address in another context to `Step::Enter` (one integer compare); a frame-less leaf reads the *caller's* CP slot; `deallocate(n)`/`call_last{n}`/`call_ext_last{n}` pop the frame (its `n` Y slots **and** the CP slot); reaching the bottom frame (`Continuation::Halt`) halts and yields `x(0)`.
- **Tail-call frame discipline (`call_ext_last`/`call_last`).** The frame is popped **after** the callee succeeds (C's `call_light_bif` asserts `E == c_p->stop` **across** the BIF call, `emu/ops.tab:964`), so a **raising** callee unwinds from the live frame and `handle_error`->`next_catch` reports *its own* reason, and a `Deallocate` left **stale** after a `trim` (`gap/1`'s stale `call_ext_last`) is never a frame-size artifact. On success the frame is popped and the caller's continuation followed (C's `deallocate_return D`); `call_last` resolves its target label **before** popping. `CallExt`/`CallExtOnly` (no fail label => every error is a raise) and `CallOnly` follow the same discipline (`tests/tailcall.rs`).
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`): discard the lowest `n` Y slots and renumber the survivors down; the `remaining` operand is JIT-only. `test_heap{heap_need, live}` calls `Machine::ensure_heap(heap_need.words(), live, ctx)` -- which hands the run's live root set (`x[..used_x_extent()]`, the whole stack and `fr[..used_fr_extent()]`, where each extent is `max(mark, dirty)` clamped to the file and the native driver notes the artifact's own `native_write_extent` before a block runs -- `src/machine/CONTEXT.md`) to `ctx.ensure_heap_full` -- with the stack unchanged, and `allocate`/`allocate_heap` recover the word count via `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter/`, `src/machine/drive.rs`)
- The loop is `machine::drive::Machine::drive(module, labels, func, pc, ctx) -> Result<RunOutcome>`: it owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, and re-borrows `(active_module, active_labels)` **per iteration**. It holds the entry module **borrowed** (`&Module`, context `0`) and every entered module **owned** via its `Arc<ModuleContext>` handle, so a callee's module identity survives a suspension; it binds the starting context from `current_context()` (`0` for a fresh run, the blocked context for a resume), switches context + re-binds `literals` only on a `Step::Enter` whose context differs (so an intra-module `Step::Goto` costs nothing), and returns `RunOutcome::Wait`/`Returned`. It also latches the A.8 gate once per run.
- Each iteration reads `active_module.functions[func].code[pc]` and dispatches with a safe `match` (the IR is pre-decoded, so typed dispatch is equivalent to a jump table); core arms mutate `func`/`pc` in place, the catch-all calls `families::dispatch` and folds its `Step` back. `step_instruction` is shared by the interpreter loop and the JIT deopt helper.
- `Machine::enter_run` builds the module-wide `Label -> (function index, code index)` `LabelMap` (a missing label is `error::unknown_label`). The residual `Instr::Generic` opcodes go to `src/generic.rs` -- a **pure sentinel** (every one returns `error::unsupported(op.name())`); every opcode the interpreter executes has its own typed IR variant (e.g. `is_any_native_record` = `Instr::IsAnyNativeRecord`, executed by the records family).
- **`call_ext*` / `return` / raise context transfers.** Each `CallExt`/`CallExtOnly`/`CallExtLast` arm first tries `resolve_call_ext_apply` (the `erlang:apply/3` special case, C's `fixed_apply` -> `apply()`), then `resolve_external_entry`; a resolved target uses the LOCAL frame discipline and reports `Step::Enter`, an unresolved one is byte-identical to a plain `call_bif`.
- A host BIF error on the synchronous `call_bif` route or on the `apply/3` route is routed through `Machine::raise_bif_error` (`ApplyTarget::Raised`), landing in the caller's live `try`/`catch`.
- `Instr::Return`, `throw_with_trace` and `ApplyLast` each emit `Step::Enter` when the continuation's context differs from the running module's.
- Per-arm detail (`ImportFrame`, `MAX_ARG` -> `error:system_limit`, the non-proper-tail `badarg`, the nested-apply unwrap): `src/interpreter/CONTEXT.md` sec. The `call_ext*` / `return` / raise context transfers.

### Instruction surface -- **executed** (per-opcode edge-case detail lives in each `src/families/` module's docs; `tests/opcodes.rs` covers the rest)
**No variant is unimplemented, and no corpus-reachable variant is blocked.** `tests/census.rs` pins the measured split of the **108** `beam_loader::Instr` variants as **95 EXECUTED + 13 ZERO-CORPUS + 0 GENUINE-GAP + 0 UNCLAIMED** (the constants `EXECUTED_VARIANTS = 95`, `ZERO_CORPUS_VARIANTS = 13`, `GENUINE_GAP_VARIANTS = 0`), and the **25** `TestKind`s as **25/25**; `unclaimed == 0` is asserted, and so is the equality of the `ZERO_CORPUS` pin with the live zero-occurrence set measured over the installed corpus.
Every row is a **valid-operand probe** (64 rows in `tests/support/probe/**`, each with a declared expectation) executed through `Machine::run_label_outcome`, so a row counts EXECUTED only when the variant really ran with operands that reach its body -- not when a degenerate operand made it fail early.
The whole installed corpus still loads: **1366/1366 `.beam` over 34 applications, 2,888,257 instructions**, zero unmodelled opcodes.
The 13 **ZERO-CORPUS** variants are implemented and tested but never emitted by this `erlc` (forward compatibility -- engine support is not drawn from corpus reachability): `BsTestTail2`, `Deallocate` (the loader's `beam_loader::lower::fuse` collapses every `deallocate` into `DeallocateReturn`), `DebugLine`, `ExecutableLine`, `Generic` (the sentinel), the seven OTP-29 native-record variants `GetRecordElements`, `GetRecordElementsId`, `GetRecordField`, `IsNativeRecord`, `IsRecordAccessible`, `PutRecord`, `UpdateRecordId`, plus `SetTupleElement` (the corpus lowers no in-place tuple write: `setelement/3` builds a fresh tuple).
**Core-loop arms.** Metadata/no-ops `Label`, `Line`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart`, `OnLoad` return `Step::Next` (no `ops.tab` body); `Move`/`Swap`/`InitYregs`, `Test` (every `TestKind`), `SelectVal`, the control ops (`Jump`/`Call*`/`Allocate*`/`TestHeap`/`Deallocate*`/`Trim`/`Return`), `GcBif`/`Bif0`/`Bif` and the eight native-record variants execute natively; `Instr::Generic` executes **nothing**.
`FuncInfo` raises class `error` with the **bare atom** `function_clause` from the running module's atom table (call args ride in the stacktrace, never the reason; a module lacking the atom is a typed `unsupported`) -- C's `i_func_info_IaaI`, and a function's callable entry label is the label *after* it, reachable only from a failed head-clause `fail` label.
`DeallocateReturn(N)` is the loader's fused `deallocate N; return` superinstruction (`beam_loader::lower::fuse`); `Deallocate`/`Return` stay live for hand-built modules that bypass the loader.
Per-opcode edge-case detail: `src/families/CONTEXT.md` sec. Per-opcode core-loop arms.
**Operands.** `X(n)`/`Y(n)` (bounds-checked -> `error::bad_register`), `Typed{reg, ty}` (annotation ignored), `FloatReg(n)` (the FR file), `Integer(i)`/`Character(c)` (a small int, else an exact bignum via `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil`; `Literal` (an index into the running module's decoded literal area) is read via `crate::operand::read_operand` (`Machine::literal`) while `Label`/`List`/`Allocation` are a typed `error::unsupported` there, and `write_operand` rejects every non-register destination.
**`GcBif`/`Bif` failure semantics.** Evaluate the arg operands, call `ctx.call_bif`: `Ok` stores into `dst`; `Err` with a live `fail` label **jumps to `fail`** (guard failure); `Err` with `fail == NO_FAIL` **raises** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`). **`Bif0`/`CallExt*` carry no fail label, so every error is a raise.**
**`raise_bif_error`.** A `BeamError::Raise` **carrying a live reason term** (`Raise::live_reason`, payload `Eterm`) is raised through `Machine::throw_with_trace(class, term, NIL)`: with a live catch frame it lands in the handler (`x(1)` = the term), else it propagates the term-carrying `Raise`. Every other case: with no live catch frame the error propagates as-is; with one, the error's BEAM atom name (`BeamError::as_atom()`) is resolved in the running module's atom table and raised with class `error`. An error the engine cannot name as a term (no atom, a `Raise` without a live slot, `TermNotFound`, `Io`) propagates unchanged, never substituted by a *different* atom.
**`Test` semantics.** Succeeds => fall through; fails => jump to `fail`, or -- when `fail == NO_FAIL` -- raise class `error` with the **bare atom** `function_clause`, resolved from the running module's own atom table by `raise_function_clause_no_fail` (matching C's `$FAIL_HEAD_OR_BODY`/`goto find_func_info`, `emu/macros.tab:266` + `i_func_info_IaaI`, which land the same bare reason). The installed `erlc` never emits `{f,0}` for `test`/`select_val`, so this is pinned from the C `FAIL`/`func_info` ground truth, not from an `erl` oracle; a module whose table cannot name the atom yields the honest typed `unsupported_opcode: test: no 'function_clause' atom in the module` (never a fabricated index). Comparison kinds: `IsLt`/`IsGe`/`IsEq`/`IsNe` use arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` exact equality (`cmp`). Type kinds: every `TestKind` the loader defines -- the type tests, `IsList`, `IsBoolean`, `IsFunction`/`IsFunction2`, `IsTaggedTuple`, `TestArity`.
**Family-claimed opcodes.** The `families` router owns **77** `Instr` variants across **nine** disjoint families (`tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive` -- `receive` last, after the funs family has resolved the target shape).
Every claimed variant has exactly one owner, so an unclaimed or declined variant falls to the router's last arm returning `error::unsupported("widened opcode not yet executed: <ops.tab name>")`.
Notable claims: `SetTupleElement` executes an **in-place** tuple write, `CallFun`/`Apply` consult the host seams before any fallback, and every raise a family produces routes through `Machine::raise_bif_error` (never a bare `badarg`).
The full per-family variant roster lives in `src/families/CONTEXT.md` sec. Per-family opcode ownership.

### Raising opcodes and the catch-frame model (`families/exceptions/`, `src/machine/catch.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, which owns it) and blank their frame slot; a raise records `pending_exception = (class, reason)` then consults the **innermost** live catch frame.
- To land, the machine unwinds to `CatchFrame::frame_index` and writes C's `handle_error` registers (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), reporting `Step::Goto` in the same context or `Step::Enter` across one; with no live frame (or an unresolvable class atom) the raise stays the typed `Err(BeamError::Raise)`, never a panic.
- A raise *reads* the innermost entry but **never pops it**; `try_case`/`try_end`/`catch_end` consume exactly one entry.
- Class atoms (`error`/`exit`/`throw`) are pre-resolved per run by `Machine::ensure_class_atoms` through `machine::namespace_atom` (the host's live namespace first, the module's snapshot second); an atom neither source knows is never substituted by a *different* atom, and `pending_class` is the class a `raise` opcode re-raises with.
- Detail (`catch_end` folding, the raise-time snapshot, `throw_with_trace`, `with_uncaught_frames`): `src/families/exceptions/CONTEXT.md` sec. The catch-frame landing convention and the raise entry points.

## Design Decisions
- **Root-set contract made concrete, with both admission doors defaulted.** The primary admission point is the defaulted `ensure_heap_full(heap_need, roots)` over `RootSet` (`x[..used_x_extent()]` + the whole stack + `fr[..used_fr_extent()]`), which `Machine::ensure_heap` calls; its default forwards to the frozen narrow `ensure_heap(heap_need, live, x_regs, stack)` with the FR file discarded.
- The **second** admission point is `alloc_words_rooted(n, roots)` -- the root hand-off for *term construction*, because `alloc_words` has neither an admission point nor roots; its default discards the roots and forwards to `alloc_words`.
- **Every in-crate term-construction arm routes through the second door** via the `terms::*_rooted` builders under the frozen **reserve -> read -> write** discipline, with `src/terms/slack.rs` the reserve seam and `src/terms/sink.rs` the multi-node shape writer.
- The classic unrooted builders plus the four `&self` execution-position accessors (`src/machine/location.rs`) are the host/test API, reachable in production only from a caller that already cannot collect.
- Detail: `src/CONTEXT.md` sec. Root-set contract.
- **A typed frame CP slot rather than a raw stack word**, with a catch-frame stack mirroring C's `next_catch` + `c_p->catches` split, so the landing convention (`x(0..=3)`) and the bookkeeping live in one place.
- **JIT tiers off the critical path; compile failure a typed error.** Cranelift is optional (default OFF), so with it off neither the crate nor the build carries Cranelift at all; compilation is measurement-gated (sec. F) with a bounded-latency, cheap-deopt design, and `TierPolicy` is deliberately **not** wired into execution. A `CodeBuffer::seal` failure propagates out of `compile`/`run_export`, and an unresolved `Jump` target deopts so the interpreter's `unknown_label` surfaces. The measurement harness lives in `src/jit/bench` (a `pub mod bench`, driven by `tests/jit_bench.rs`); its ten workloads, method and caveats are in `src/jit/bench/CONTEXT.md`, the figures in `MEASURED.md`.
- **One driver for both native tiers, delegating per instruction rather than duplicating semantics.** A tier supplies its compiled-code lookup through the `NativeCode` trait (`enter(rt, func, pc) -> Option<i64>`); because `jit_step_one` *is* `Machine::step_instruction`, every tier is interpreter-identical for every supported opcode without a second implementation.
- **The cross-module call seam is additive and host-driven.** `resolve_external_call` (default `Ok(None)`) lets a host that owns loaded modules run a `call_ext*` **in the same machine**, so a `receive` inside the callee suspends the driving process (`RunOutcome::Wait`) instead of folding into `Err(error::blocked())`.
- The mechanism is C's model: the frame `Continuation` carries its module context, so a `return`/raise can land in another module; `Machine::drive` owns the `(func, pc)` position plus its context and re-binds the literal area only on a `Step::Enter` to a different context.
- Modules are `Arc<Module>` handles deduped by `Arc::ptr_eq` (bounded by distinct modules, not call count) and cleared only by `reset` -- never by a resume, because a suspended cross-module frame must still name its module.
- On the native baseline tier the transfer is a **driver-mediated module-context switch** (a resolved transfer is not in the JIT inline set, so the block deopts one step and hands the driver `Step::Enter`); a seal-time cross-module *link* is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`), so the round-trip is by design.
- Detail: `src/machine/CONTEXT.md` sec. The cross-module call seam.
- **Unsupported => `Raise` with reason atom `unsupported_opcode`** (a dedicated `BeamError` variant must not be added from here); the slice `.beam` fixture lives with `beam_loader` and is read by relative path.
- **The FR file stores `Eterm` term slots at M1** (C's is raw doubles), so `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is deferred.
- **M1 fun layout inlines the descriptor** (`uniq`, `index` after the header; no code pointers at M1) -- the same substitution as the external-pid `node` slot (`MAKE_FUN_HEADER` + `ErlFunThing`). `MinimalContext` fun application goes through an apply hook (no closure registry here), `build_stacktrace` cooks from the machine's **raise-time snapshot** (`Machine::raise_snapshot`) rather than the live call frames, and `update_record` always copies (the hint only authorises updating a unique/dead source).
- **Flat, integer-keyed hot-path state (safe Rust).** Jumps resolve through a dense `LabelMap` built once per run, each import's `call_bif` target is resolved once per run into a cached `ImportTarget`, and `GcBif`/`Bif`/`Bif0`/`CallExt` marshal arguments through a fixed-lane stack array or a per-`Machine` scratch, so a BIF call allocates **nothing** (`tests/bif_alloc.rs`).
- None of this changes semantics: the reference point stays `Machine::step_instruction`.
- Detail (`Slots::{Dense,Sparse}`, the `Module`-address keying, the 128-byte reset refill): `src/machine/CONTEXT.md` sec. Flat, integer-keyed hot-path state.
- **Hot-path inlining is measurement-driven, never blanket.** An out-of-line helper returning `Result<_, BeamError>` (a 72-byte `Err`) forces its `Ok` through memory, so the interpreter's *small* hot helpers carry `#[inline(always)]` (`read_operand`/`write_operand`, `test_arg`, `set_y`) while `step_instruction` and `eval_test` carry plain `#[inline]`.
- The same attribute is a **measured regression on large helpers**: `#[inline(always)]` on `exec_bif`/`call_import` costs ~20%, and caching the resolved `functions[func].code` slice across the dispatch loop costs ~19%, so neither is applied.
- The residual per-instruction cost is structural, not a missed hint: the 64-byte `Instr` discriminant `match` (a mispredicted indirect jump), the `Result<Step>` loop plumbing, the double `Vec` bounds check, and the arity-2 `gc_bif` marshal.
- The full measurement narrative: `src/interpreter/CONTEXT.md` sec. Hot-path inlining.

## Known Issues / Intentional M1 gaps
- **There is no unimplemented corpus-reachable variant and no genuine execution gap: the measured split is 95 EXECUTED + 13 ZERO-CORPUS + 0 GENUINE-GAP + 0 UNCLAIMED.** The 13 ZERO-CORPUS rows are forward-compatibility work this `erlc` never emits, not gaps (`BsTestTail2`, `Deallocate`, `DebugLine`, `ExecutableLine`, `Generic`, `GetRecordElements`, `GetRecordElementsId`, `GetRecordField`, `IsNativeRecord`, `IsRecordAccessible`, `PutRecord`, `SetTupleElement`, `UpdateRecordId` -- see sec. Instruction surface); each still has a valid-operand probe in `tests/support/probe/**`, and 41 of the former weight-ordering rows are additionally proven on real compiler output against the live `erl` oracle (`tests/real_beam_variant_proofs.rs`).
  `put_record/6`'s **create** form (`Src == nil`) takes the running module's **own** records from `families/records/mod.rs` and another module's `{Module, Name}` id through the defaulted `ExecutionContext::foreign_record_definition(owner, name)` seam, whose `Ok(Some(def))` is the host's record table answering `erl_record.c::erts_record_find_entry`; the engine builds the instance only for an exported definition, and a non-exported one is the C's `error:{badrecord, Id}` raise (`erl_record.c:401-409`, via `beam_common.c::expand_error_value`).
  The residual is a host that answers `Ok(None)` -- no record table, or a defining module it cannot load -- which keeps the typed `error::unsupported("put_record: create: no record definition table for another module")`; the engine has **no `code:ensure_loaded/1` trap**, so the load-then-retry half is the host's `Ok(None)`, and a created instance stores no definition pointer (the M1 substitution).
  Pinned in `src/families/records/tests/` and `tests/gaps.rs`.
  Every remaining item in this section is a divergence in *fidelity* (a typed error, a snapshot ordering, a host-owned facility), never a wrong result and never an unimplemented opcode.
- **The collecting host is `beam_rt`'s side, not an engine gap.** `MinimalContext` has an unbounded, never-freed reserved-heap-region arena, and `test_heap`/`allocate_heap` reach the full-root admission point there as a no-op (its default forwards to the no-op `ensure_heap`).
- The engine's own half is landed: **every** in-crate term-construction arm allocates through the rooted door under the reserve -> read -> write ordering, proved under a mock **moving** collector by `src/terms/alloc_tests.rs` and `tests/rooted_alloc.rs`, with the root hand-off pinned by `tests/gc_roots.rs`.
- `beam_rt` overrides both rooted doors, publishes the whole `RootSet`, runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a region the collector does not scan; the machine's own loose `Eterm` fields (`Machine::loose_heap_terms` — the two clause latches and `Machine.pending_exception`'s reason) are parked at the stack tail by `Machine::with_roots`, so a collecting host must additionally root only the `Eterm` arguments parked in `Machine.args_scratch`/the `exec_bif` stack array while a `call_bif` is in flight.
- Detail: `src/CONTEXT.md` sec. Who owns the collecting host, `## GC publication`.
- **A captured stacktrace is engine-derived unless the raise supplied one.** `raw_raise` is oracle-exact for all three classes and the unknown-class fall-through (`x(0) = badarg`, no raise); a raise that **supplies** its trace (`raw_raise` reading `x(2)`, or cooking the preserved `raise_snapshot` chain once when `x(2)` is `NIL`) carries it as a real term through `Machine::raise_supplied` — a **landed** raise publishes it as the handler's `x(2)`, an **uncaught** one renders the preserved chain (no re-raise-site frame is ever derived). Otherwise `build_stacktrace` cooks the symbolic list from the machine's **raise-time snapshot** (`Machine::raise_snapshot`), resolving each frame in its own module context, for both a non-`NIL` raw `x(0)` and a `NIL` `x(0)` at a catch where a raise was recorded (a `NIL` with no recorded raise still yields `NIL`, C's `get_trace_from_exc(NIL) == NULL`); an already-cooked list in that register is returned verbatim (`is_list`, C's `is_raised_exc` arm). The derived snapshot holds only the run's own interpreted frames and is therefore strictly partial (an empty snapshot, or one whose every frame is skipped, cooks to the empty list); it also cannot name a context-`0` frame when the handler runs in a non-zero context (a raise caught across a cross-module `call_ext`), so the residue is the **context-0-from-a-non-zero-handler** case. `tests/stacktrace_frames.rs` pins the settled shapes on both tiers: `folded/0` → `[folded/0 @24]`, `refold/0` → `[g/1 @17, refold/0 @26]`, `inhandler2/0` → `[inhandler2/0 @28]`.
- **Nameable atoms required, resolved through the live namespace.** `catch_end` needs the `EXIT` atom, and a raise needs its reason/class atom; both are resolved through `machine::namespace_atom` = `ExecutionContext::atoms(module)` (the host's ONE live namespace) with the module's load-time snapshot as the fallback, so an atom interned into the shared namespace *after* the module loaded still lands the raise in a live catch frame. `Machine::ensure_class_atoms` (the first statement of `families::dispatch`, so both tiers pass it) pre-resolves `error`/`exit`/`throw` per run. A name **neither** source knows propagates as a typed error (`unsupported`, or the `BeamError` unchanged for `TermNotFound`/`Io`/an empty non-`Eterm` `live_reason`); no path ever substitutes a different atom.
- **Compiled arithmetic is oracle-exact on overflow.** `+ - * div rem` promote to exact bignums (compiled `gc_bif` goes through `ctx.call_bif` into `beam_bifs`); an out-of-range `Integer`/`Character` **operand** becomes an exact bignum via `terms::make_integer` (which the JIT's `constant_word` deopts).
- **A blocking `receive` needs a host mailbox** (Handoffs #1): with no mailbox each `Mailbox` call is a typed `unsupported("<method>")`, and a mailbox with no candidate **suspends** (`RunOutcome::Wait`, folded into `error::blocked` by plain `run_export`); a parked `wait_timeout` publishes its deadline through `Machine::wait_deadline` (the `timeout` continuation + the delay, read from a literal or a Y slot), but with no host timer it stays parked until a message arrives (only a small-int `0` falls through to `timeout`). A host that also **adopts the cross-module seam** (`resolve_external_call`) gets the suspension out of a `call_ext` callee too -- the callee runs in the same machine, so a `receive` inside it reports `RunOutcome::Wait` to the driving process instead of folding into an error (`tests/external_call.rs`).
- **Records.** The whole native-record set executes. `PutRecord`'s *create* form takes the running module's own records (`Src` the literal `nil`, from `beam_loader::Module::{records,record,record_by_name}`, hashed with `beam_term::hashing::compute_record_definition_hash`) and a *foreign* `{Module, Name}` id through `ExecutionContext::foreign_record_definition`, which requires an exported definition and enforces that even when `Module` is the running module (the atom-id form, C's `i_create_local_native_record`, does not).
- A host answering `Ok(None)` is the typed `unsupported` (no `code:ensure_loaded/1` trap in the engine, no definition pointer stored on the created instance); a record-semantics failure branches to the instruction's `fail` label (`NO_FAIL` -> `unsupported("<instr>/no_fail")`).
- The installed `erlc` emits the native-record opcodes -- including the create form -- only for the explicit `-record #name{}` form (the legacy `-record(name,{})` form still lowers to a plain tuple); verified structurally (`tests/records.rs`) and through the seam in `src/families/records/tests/` and `tests/gaps.rs`.
- Detail: `src/families/records/CONTEXT.md`.
- **Bitstring gaps (each a typed result -- never a wrong value).** A refc-binary subject is read at whatever **bit** offset its window starts (`raw::heap_bits` recovers `(base, size_bits, bit_off)` from the frozen `ErlSubBits`); the only refused subject is a match context or a bare off-heap binary reference (a typed `unsupported`).
- `bs_init_writable` builds a 0-bit refc binary over a capacity-carrying payload (a 4x `DEFAULT_RESERVATION_FACTOR` reservation, registered in `Machine::writable_payloads` because the frozen term layout carries no capacity word); a **first-position** `private_append` appends in place (zero allocation) and an outgrown payload **grows** (in place or by relocation), so the accumulator loop stays amortised (64 KiB from a 1 KiB hint: 2 grows + 4 moves, 61 440 bytes copied -- `create/grow_tests.rs`); every other shape copy-rebuilds byte-identically.
- `BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER` are not term flags, `binary:referenced_byte_size/1`'s capacity answer and a writable payload's `as_bytes()` high-water mark stay unmodelled (typed results only -- a `beam_alloc` `set_len_written` API would close the last one).
- `system_limit` is modelled (`size*unit` overflow / the post-multiply sign bit / a positive-bignum size; a negative bignum is `badarg`); a `float` segment of width 0 or invalid raises `badarg`.
- Full detail and residuals: `src/families/bitstrings/CONTEXT.md` sec. The typed bitstring / binary gaps, in full.
- **Literal operands.** Every installed module's `LitT` area (`EXPORT_EXT`/`NEW_FUN_EXT` fun literals, `>32`-key map literals, big integers) and wide (`>8`-byte) integer operands decode; a `Literal` index outside the running module's `LitT` table (or a read with no module bound) is the typed `operand: literal` error.
- **`y(k)` addressing and `trim` are equivalent to C's `E[1+k]`/`E += N` -- no off-by-one.** The engine keeps the continuation-pointer slot **out** of the stack (`Frame { continuation, y_base, y_count }`, so `y(k) = stack[y_base + k]`), whereas C keeps it at `E[0]` (`y(k) = E[1+k]`, `emu/macros.tab:142-147`); both discard the lowest `N` Y slots. The operands agree because the loader encodes `deallocate N` as `(N+1)` words and `deallocate` consumes the frame's **remaining** Y count -- post-`trim`, what the compiler emits (`gap/1`: `trim 1` -> `deallocate 0`). `pop_frame_checked` is deliberately **stricter** than C (which advances `E` unconditionally): a mismatch is a typed `unsupported`, never silent corruption (`tests/tailcall.rs`).
- **Map enumeration order is storage order, not canonicalized** (`erts_cmp_flatmap_keys`), affecting only `term_to_binary` byte comparison; a malformed hashmap node / `THE_NON_VALUE` / immediate item during a read is a typed `BadArg`. A missing key in a read instruction (`get_map_elements`/`has_map_fields`) with `fail == NO_FAIL` raises class `error` with the **bare atom** `function_clause` from the running module's own atom table -- the engine's single failed-clause definition `raise_function_clause_no_fail` (`src/interpreter/dispatch.rs`), shared with `func_info`/`test`/`select_val`; a module that cannot name the atom yields the honest typed `unsupported_opcode: maps: no 'function_clause' atom in the module`, never a fabricated index. The `{badmap,Source}` / `{badkey,Key}` raises of `put_map_assoc`/`put_map_exact` are unchanged (tag resolved from the module's own table, else a typed `unsupported`).
- **Reductions and pre-emption exist; the scheduler does not.** `Machine::drive` charges one reduction per interpreted instruction through the defaulted `ExecutionContext::reduce(n)` hook, **before** the instruction's body runs, so even a **non-allocating** loop (which never reaches `ensure_heap`) stays pre-emptible.
- A host with a scheduler pre-empts by returning a **typed error** from `reduce`; the pre-empted instruction is left **un-applied** and the machine parked on it (`Machine::current_code`), so `Machine::resume_outcome` applies it **exactly once**.
- `Machine::reductions()` reads the current slice's count (zeroed at slice entry; one `drive` call = one slice) and `Machine::reset_reductions()` returns it while zeroing it.
- There is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption a fresh `drive`; the scheduler, run queues, trap handling and heap limits are Stage 5 (`beam_process`), and stack growth is an unbounded `Vec`.
- Both tier drivers charge the same hook: the JIT driver latches `Machine::reduce_on` and zeroes the counter at its entry, then charges once per **block entry** (a natively executed block, or the per-instruction step for an address no block covers) -- the granularity that makes the refusal a genuine pre-emption, since at a block entry the published address is the one about to run with the block unexecuted.
- A refusing charge from the call-resolution/BIF seams would replay part of a block on resume, so those seams stay spend-only; a natively linked local tail-call chain stays inside one driver entry and cannot end its slice from inside (`slice.beam`'s `fib/1` at n=18 costs 2 charges against the interpreter's 152).
- Detail: `src/machine/CONTEXT.md` sec. Reductions and pre-emption.
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after.** C fills `reg[i] = args[i]` for `i < arity` then `reg[i + arity] = funp->env[i]`, so a context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = captures -- *not* `free ++ args`. The `resolve_local_fun` seam route places the same free variables in the **engine** (the `call_fun` family copies them into `x(arity..)` before the `Step::Enter`), so a host answering the seam returns a lambda entry label that reads its captures from `x(arity..)`.

- **Atom comparison is name-exact end-to-end, through a defaulted live-namespace seam.** Every guard/`select_val`/map-key comparison site resolves atom *names* through `ExecutionContext::atoms<'m>(&'m self, module: &'m Module) -> &'m AtomTable`, so atom order matches the `<` BIF, which compares through the runtime's ONE shared live table.
- The seam's **default** is `&module.atom_table`, the load-time snapshot, which keeps every host that owns no shared namespace working; `beam_rt` overrides it with the live table in BOTH `ExecutionContext` impls (`RuntimeContext` and the scheduled path's `BudgetContext`).
- Without that override an atom interned *after* a module loaded is absent from the comparison table and `beam_term::cmp_atoms` falls back to raw atom **index** -- a wrong guard branch with **no error surfaced**.
- The pinned sites, the override file:line map and both oracle-cross-checked repros: `src/CONTEXT.md` sec. The comparison atom-namespace seam.
- **The `{tr,..}` typed-register operand is NOT implicated in the above — that path is correct.** `read_operand`/`read_operand_pure`/`write_operand` route `Operand::Typed { reg, .. }` to the underlying register and ignore the `Type` annotation (`src/operand.rs:74,162,193,201-215`), the baseline emitter's `x_register`/`y_register` do the same (`src/jit/baseline/emit/operands.rs:63-89`), and `{bif,element,{f,0},[{tr,{x,0},…},{x,5}],{x,6}}` therefore executes identically to the plain `{x,0}` form. The only engine sites that do **not** accept `Operand::Typed` are `Machine::timeout_delay` (`src/machine/location.rs:357-365`, returns `None` = "no deadline" for a typed delay register, so such a `wait_timeout` parks instead of timing out) and `eval_test_arity`'s arity operand (`src/interpreter/test.rs:202-211`, a typed error). The compiler only emits `tr` for modules compiled with type info.
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory.** `families::bitstrings::raw::{make_writable,make_binary}` build the frozen 8-word `[BinRef][ErlSubBits]` pair and push each payload handle onto `Machine::refc_binaries` (never cleared by `reset`); the `send` arm and the `erlang:send/2` case hand the in-flight slice to the host through `send_message_with_off_heap`, so an engine-built refc binary survives both a **return** and a **send**.
- The host prices and prunes the reservoir through `Machine::off_heap_overhead_bytes()` (backing-store bytes; words = bytes / `size_of::<Eterm>()`) and `Machine::retain_refc_binaries(keep)`, which drops every handle a reachability predicate rejects and keeps a retained payload's `data_ptr` stable while the `writable_payloads` registry is pruned in lockstep.
- The predicate **is** the caller's soundness assertion: a false reject frees memory a live `BinRef.val` names, a false accept is only a leak.
- Detail and pinned tests: `src/machine/CONTEXT.md` sec. The off-heap (refc) binary handle.
- **`Instr::Allocate` skips C's heap check.** C's `allocate Ns Live` is `$AH(Ns,0,Live)` ≡ `GC_TEST(Ns+1,0,Live)` (`emu/instrs.tab:31-33`), so C **can** collect at every `allocate`; this crate's `Instr::Allocate` only pushes the frame, and the two in-crate admission arms are `AllocateHeap`/`TestHeap`. The divergence is conservative (the engine collects strictly *less* often, so it can never dangle a published root) but is why an engine run's young-heap occupancy differs from the oracle's.
- **The uncaught frames exist only for a `BeamError::Raise`.** `with_uncaught_frames` decorates **only** `BeamError::Raise`; `beam_common`'s reason variants (`BadArg`/`BadArith`/`BadArity`/`BadMatch`/`SystemLimit`) are **fieldless** and carry no `StackTrace` slot, so an uncaught BIF/op failure that travels as a bare variant exits the machine with **no frames at all**, while the same failure as a `Raise` is fully framed. Normalizing the bare variant into a `Raise` at this boundary was measured (semantically faithful) but broke **66 tests across 23 targets**, so it was **not forced**; the faithful alternative is a `StackTrace` slot on `beam_common`'s non-`Raise` variants (out of this crate's scope).
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by the engine's own opcode coverage -- so whole module families are recorded as host gaps, each asserting its EXACT typed error and never a fabricated value. All of `ets` is such a gap (`ets.erl`'s operation bodies are `erlang:nif_error(undef)` stubs); the map-BIF-backed `maps` exports and the map-dependent `proplists` ones and `string:list_to_integer/1` are gapped the same way. Owning crates: `beam_bifs` (BIF surface/seam adoption) and `beam_rt` (preloaded-module floor) -- NOT this crate. `proplists:to_map/1,2` on an `[atom | {K,V}]` list DOES execute and is pinned oracle-exact.
- **`call_fun`/`call_fun2` reports the oracle's structured reason for a malformed target, classified from the running module's own atom table.** The target shape is classified **before** the host seam, exactly as C's `call_fun` does: a non-fun target is `error:{badfun, Fun}` and a header-arity mismatch is `error:{badarity, {Fun, Args}}`, both built through the rooted builders (the tag via `reason_atom`), never a fabricated or substituted atom.
- Residual: a module that cannot name the tag declines to the host closure-apply seam, whose `Err` routes through `Machine::raise_bif_error`; `beam_rt` seeds `badfun`/`badarity`, so every real-runtime process takes the structured-reason path.
- Detail: `src/families/funs/CONTEXT.md` sec. The structured target-shape reasons.
- **The `call_fun`/`call_fun2` free-variable copy is NOT a GC hazard (verified; do not re-open).** `families/funs/mod.rs` reads `terms::fun_free(fun)` then `set_x` for each; the source `fun` term stays published in `x(arity)`/the `call_fun2` operand, and there is **no admission point** between the read and the writes (`resolve_local_fun` is a non-collecting `&self` reader with the shipped host). The three doors that *can* collect are documented in `src/CONTEXT.md` (`## GC publication…`), together with the non-rooted engine→host calls. The `pending_exception` reason term is a live root by construction — `Machine::with_roots` parks it at the stack tail (bullet above) — so the only remaining publication gap of that kind is host-side.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node, and this section is the full detail.
1. **Receive/message + cross-module suspension (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome`, and drive a host **timer** for a non-zero `after` (the engine exposes the parked deadline through `Machine::wait_deadline`). A `receive` **inside a cross-module callee** suspends the caller through the cross-module call seam (Handoff #10). `resume_outcome(entry_module, func, pc, ctx)` must be called with the run's **entry** module (context `0`): `func`/`pc` are in the context the process blocked in, which the machine recovers from `Machine::context`.
4. **A *foreign* `PutRecord` create id -- closed by a defaulted engine seam, residual only at the host.** `ExecutionContext::foreign_record_definition(owner, name)` (default `Ok(None)`) lets a host with a record table answer `erl_record.c::erts_record_find_entry`; the engine builds the instance only for an **exported** definition (a non-exported one is the C's `error:{badrecord, Id}` raise) and the `{Module, Name}` form enforces that even when `Module` is the running module.
The residual is a host answering `Ok(None)` -- no record table, or a defining module it cannot load -- which keeps the typed `error::unsupported("put_record: create: no record definition table for another module")`; the engine has no `code:ensure_loaded/1` trap, and a created instance stores no definition pointer (the M1 substitution).
Detail: `src/families/records/CONTEXT.md` sec. Handoff: a foreign `PutRecord` create id.
6. **`TestKind::TestArity` -- behaviourally equivalent to C, NOT a gap.** C's `test_arity` is an unguarded header compare, and since `tuple_val(p) == boxed_val(p)` the engine's `is_boxed(x) && ARITYVAL-header == arity` reads the same word and agrees for every boxed term; the only divergence is an *immediate* operand, where C's deref is UB and the engine safely returns `false` -- unreachable in well-formed code (the loader rewrites an immediate `test_arity` operand to a jump). Covered by `src/interpreter/test.rs` + `src/predicates.rs` tests.
7. **Map `NO_FAIL` `{badmap,Source}` / `{badkey,Key}` — closed for a seeding host; the residual is the unseeded loader.** With a host that interns the runtime's globally interned atoms before any load (`CORE_ATOMS` + the test host's `SEED_ATOMS` both seed `badmap`/`badkey`), the family raises the oracle's reason exactly. The residual is only the **unseeded** `beam_loader::load_file` path: the installed `erlc` interns `badmap` but **not** `badkey`, so a `put_map_exact` `NO_FAIL` raise there is the typed `unsupported_opcode: maps: no 'badkey' atom in the module`. Pinned both ways by `tests/maps.rs`. No engine seam resolves a tag outside the running module's table, and none should.
8. **JIT `call_ext_last` -- executes natively, by design a driver round-trip.** A **local** tail call (`call_last`/`call_only`) is linked natively; `call_ext_last` **executes** on the native baseline tier through the driver-mediated module-context transfer (a seal-time cross-module link is unsound). The residual cost is the per-transfer driver block-entry, measured by `src/jit/bench`'s `cross/2`.
9. **JIT adoption + the A.8 seam by `beam_rt` (owner `beam_rt`).** `beam_rt/src/runner/run.rs` selects a tier at the process's first entry (default `Tier::BaselineJit` for **every** process entry, with `BEAM_RT_TIER=interpreter` the only kill switch), remembers it on the engine, routes the entry through `run_label_outcome_with_tier`, and resumes a parked slice through `resume_outcome_with_tier` on that **same** tier.
The engine-side seam is **complete**: a natively-executed block records its own `(func, pc)` in its prologue so `process_info/2`'s position is block-exact, a traced run refuses native entry, and the `+JPperf` perf map (contract A.8) is populated from `beam_engine::jit::cache::baseline_code_map(&module)`.
Pinned shapes: native cross-module, nested A->B->C, parked-then-resumed slice, dynamic `apply` (`tests/jit_cross_module.rs`).
Scope limit: the forced tier reaches the module-run third of a gate corpus, because the `-eval` root expression is a tree-walk evaluator with no `Machine` and does not consult a tier.
10. **The cross-module call seam (owner `beam_rt`, the owner of `RuntimeContext`).** The contract: `Some((arc, label))` for an import the host can run in this machine, `Ok(None)` otherwise (keeping the synchronous `call_bif` path -- `code:*` native floor, NIFs and everything else).
`arc` must be the **SAME `Arc<Module>`** the host loaded the module with (`CodeServer::modules`; contexts dedup by `Arc::ptr_eq`), and `label` is the export entry label (`arc.export(function_atom, arity)`, the label *after* `func_info`).
`resume_outcome` takes the run's **ENTRY** module (context `0`); the suspended `(func, pc)` live in `Machine::context`.
Tests: `tests/external_call.rs`, `tests/current_module.rs`; regression repro (committed, `beam_rt`-owned): `../beam_rt/tests/proc_lib_start.rs` -- read it, do not edit `beam_rt` from here.
11. **The rooted doors are adopted by `beam_rt` (owner `beam_rt`).** `beam_rt` overrides both `alloc_words_rooted` and `ensure_heap_full`: it publishes the `RootSet` it is handed (the used X/FR prefixes plus the whole stack), runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a container in a region the collector does not scan. Detail: `beam_rt/src/context/CONTEXT.md`.
12. **The closure-apply seam (`resolve_local_fun`, owner `beam_rt`) -- ADOPTED.** `beam_rt/src/context/execution.rs:446` implements it as a thin wrapper over `RuntimeContext::local_fun_target`, returning `Some((target.module, target.label))` (clone the module `Arc`) and `Ok(None)` for the fun kinds with no local label, forwarded by `beam_rt/src/runner/budget.rs:257`. **The engine places the free variables itself** (into `x(arity..)`, C's `call_fun` order), so the host need not re-derive `LocalFunTarget.args`; a scheduled process's `call_fun`/`call_fun2` therefore enters a blocking closure in-machine.
13. **A built-in / static NIF library is served through the `resolve_local_call` seam -- ADOPTED (owner `beam_rt`).** The three **local** call arms (`Instr::Call`/`CallOnly`/`CallLast`) consult the seam before returning their in-machine `Step::Goto`, and the native baseline tier probes it at run time in `jit_local_call`; on a hit the engine marshals `x(0..arity)` and dispatches the callee through `call_bif` under the arm's own frame discipline.
The motivation is ERTS's split module shape: the OTP compiler emits a **local** call for a **non-exported** same-module function (so `prim_tty`'s wrappers chain locally into its `erlang:nif_error(undef)` NIF stubs and the host intercepts only those) and a self-qualified `call_ext` for an **exported** one.
**Correctness constraint:** `Ok(false)`, an absent resolver and an un-nameable/missing function entry all leave the arm byte-identical, and both tiers are pinned equal on the served and the declined route (`tests/local_call_seam.rs`).
The same keys also arrive as a fun (`zlib`'s `fun deflate_nif/4` in a record), which `beam_rt`'s `served_local_key` declines as a local_fun target and dispatches through `call_bif`.
Detail (the two host key sets, the `zlib` fun route): `src/interpreter/CONTEXT.md` sec. The `resolve_local_call` seam.
