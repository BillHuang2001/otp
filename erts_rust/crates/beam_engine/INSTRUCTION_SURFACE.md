## Execution model (frozen semantics -- reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame** (`src/machine/frames.rs`): `allocate`/`allocate_heap`/... push `stack_need + 1` words -- a *continuation-pointer slot* then `stack_need` Y-registers (`y(k)` = the slot after the CP slot, C's `E[1+k]`); the CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), not a raw word. A CP is a code pointer into a **specific module context** (C's model: the code address itself identifies the module), so it is exact even for a frame-less function that stores a continuation into its caller's frame. `call` stores the continuation in the current frame's CP slot then jumps; `return` follows it -- `Machine::continuation_step` maps a `Halt` to `Step::Done`, an address in the current context to `Step::Goto`, and an address in another context to `Step::Enter` (one integer compare); a frame-less leaf reads the *caller's* CP slot; `deallocate(n)`/`call_last{n}`/`call_ext_last{n}` pop the frame (its `n` Y slots **and** the CP slot); reaching the bottom frame (`Continuation::Halt`) halts and yields `x(0)`.
- **Tail-call frame discipline (`call_ext_last`/`call_last`).** The frame is popped **after** the callee succeeds (C's `call_light_bif` asserts `E == c_p->stop` **across** the BIF call, `emu/ops.tab:964`), so a **raising** callee unwinds from the live frame and `handle_error`->`next_catch` reports *its own* reason, and a `Deallocate` left **stale** after a `trim` (`gap/1`'s stale `call_ext_last`) is never a frame-size artifact. On success the frame is popped and the caller's continuation followed (C's `deallocate_return D`); `call_last` resolves its target label **before** popping. `CallExt`/`CallExtOnly` (no fail label => every error is a raise) and `CallOnly` follow the same discipline (`tests/tailcall.rs`).
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`): discard the lowest `n` Y slots and renumber the survivors down; the `remaining` operand is JIT-only. `test_heap{heap_need, live}` calls `Machine::ensure_heap(heap_need.words(), live, ctx)` -- which hands the whole root set (`x[0..live)`, the whole stack **and the whole FR file**) to `ctx.ensure_heap_full` -- with the stack unchanged, and `allocate`/`allocate_heap` recover the word count via `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter/`, `src/machine/drive.rs`)
- The loop is `machine::drive::Machine::drive(module, labels, func, pc, ctx) -> Result<RunOutcome>`: it owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, and re-borrows `(active_module, active_labels)` **per iteration**. It holds the entry module **borrowed** (`&Module`, context `0`) and every entered module **owned** via its `Arc<ModuleContext>` handle, so a callee's module identity survives a suspension; it binds the starting context from `current_context()` (`0` for a fresh run, the blocked context for a resume), switches context + re-binds `literals` only on a `Step::Enter` whose context differs (so an intra-module `Step::Goto` costs nothing), and returns `RunOutcome::Wait`/`Returned`. It also latches the A.8 gate once per run.
- Each iteration reads `active_module.functions[func].code[pc]` and dispatches with a safe `match` (the IR is pre-decoded, so typed dispatch is equivalent to a jump table); core arms mutate `func`/`pc` in place, the catch-all calls `families::dispatch` and folds its `Step` back. `step_instruction` is shared by the interpreter loop and the JIT deopt helper.
- `Machine::enter_run` builds the module-wide `Label -> (function index, code index)` `LabelMap` (a missing label is `error::unknown_label`). The residual `Instr::Generic` opcodes go to `src/generic.rs` -- a **pure sentinel** (every one returns `error::unsupported(op.name())`); every opcode the interpreter executes has its own typed IR variant (e.g. `is_any_native_record` = `Instr::IsAnyNativeRecord`, executed by the records family).
- **The `call_ext*` / `return` / raise context transfers.** The `CallExt`/`CallExtOnly`/`CallExtLast` arms first resolve the import through `resolve_external_entry` (the per-run `LabelMap::import_target` for the `(module, function, arity)`, then `ctx.resolve_external_call`; a `Some` registers the callee context and resolves the entry label against the callee's own map). On `Some` they use the LOCAL discipline and report `Step::Enter`: `CallExt` = `Instr::Call` (stores `Continuation::Address{func, pc+1, context: current_context()}` in the current frame, i.e. the caller's context), `CallExtOnly` = `CallOnly` (no continuation change), `CallExtLast` = `CallLast` (the target is resolved **before** `pop_frame_checked(deallocate)`). On `None` they are **byte-identical** to the old `call_bif` path. `Instr::Return` emits `Step::Enter` when the target context differs; `throw_with_trace` emits `Step::Enter` when a live catch frame lives in another context; `ApplyLast` follows its (popped) frame's continuation through `Machine::continuation_step` and emits `Step::Enter` when that continuation's context differs from the running module's.

### Instruction surface -- **executed** (per-opcode edge-case detail lives in each `src/families/` module's docs; `tests/opcodes.rs` covers the rest)
**Core-loop arms.** Metadata/no-ops `Label`, `Line`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart`, `OnLoad` (`ops.tab` lists them with no body, so `Step::Next` is exact). `FuncInfo` raises class `error` with the **bare atom** `function_clause` from the running module's atom table (call args ride in the stacktrace, not the reason; a module lacking the atom is a typed `unsupported`) -- a function's callable entry label is the label *after* `func_info`, reachable only by a JUMP from a failed head-pattern/guard `fail` label, matching C's `i_func_info_IaaI`; the baseline JIT deopts it. The uncaught raise goes through the uniform funnel `Machine::with_uncaught_frames`, which attaches the frames `Machine::raise_stacktrace(entry_module, func, pc)` derives from the live call frames (the raising function first, each frame resolved in its own module context), so the bare-atom reason is still localizable; a caught raise is unaffected (the frames are metadata on the uncaught `Raise` only). `Move`/`Swap`/`InitYregs`. `Test` (**all** `TestKind`s) and `SelectVal` (exact `=:=` against each `(value, label)`, else `fail`, else a raise when `fail == NO_FAIL`). The control ops `Jump`/`Call`/`CallLast`/`CallOnly`/`CallExt`/`CallExtOnly`/`CallExtLast`/`Allocate`/`AllocateHeap`/`TestHeap`/`Deallocate`/`DeallocateReturn`/`Trim`/`Return` (frame discipline in sec. Registers, stack & frames; the rest match C), `GcBif`/`Bif0`/`Bif`, and the eight native-record variants. `Instr::Generic` executes **nothing** (see the dispatch loop). `DeallocateReturn(N)` is the loader's fused `deallocate N; return` superinstruction (`beam_loader::lower::fuse`): `pop_frame_checked(N)` then the shared `Machine::return_step` the plain `Return` arm also uses; `Deallocate`/`Return` stay live for hand-built modules that bypass the loader.
**Operands.** `X(n)`/`Y(n)` (bounds-checked -> `error::bad_register`), `Typed{reg, ty}` (annotation ignored), `FloatReg(n)` (the FR file), `Integer(i)`/`Character(c)` (a small int, else an exact bignum via `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil`; `Literal` (an index into the running module's decoded literal area) is read via `crate::operand::read_operand` (`Machine::literal`) while `Label`/`List`/`Allocation` are a typed `error::unsupported` there, and `write_operand` rejects every non-register destination.
**`GcBif`/`Bif` failure semantics.** Evaluate the arg operands, call `ctx.call_bif`: `Ok` stores into `dst`; `Err` with a live `fail` label **jumps to `fail`** (guard failure); `Err` with `fail == NO_FAIL` **raises** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`). **`Bif0`/`CallExt*` carry no fail label, so every error is a raise.**
**`raise_bif_error`.** A `BeamError::Raise` **carrying a live reason term** (`Raise::live_reason`, payload `Eterm`) is raised through `Machine::throw_with_trace(class, term, NIL)`: with a live catch frame it lands in the handler (`x(1)` = the term), else it propagates the term-carrying `Raise`. Every other case: with no live catch frame the error propagates as-is; with one, the error's BEAM atom name (`BeamError::as_atom()`) is resolved in the running module's atom table and raised with class `error`. An error the engine cannot name as a term (no atom, a `Raise` without a live slot, `TermNotFound`, `Io`) propagates unchanged, never substituted by a *different* atom.
**`Test` semantics.** Succeeds => fall through; fails => jump to `fail`, or raise `error::unsupported("test/no_fail")` when `fail == NO_FAIL`. Comparison kinds: `IsLt`/`IsGe`/`IsEq`/`IsNe` use arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` exact equality (`cmp`). Type kinds: every `TestKind` the loader defines -- the type tests, `IsList`, `IsBoolean`, `IsFunction`/`IsFunction2`, `IsTaggedTuple`, `TestArity`.
**Family-claimed opcodes** (one `src/families/` module per family; the `exec`/`dispatch` contract is in the families seam above; edge-case semantics are in each module's own docs):
- `tuples.rs`: `PutTuple2`, `GetTupleElement`, `SelectTupleArity` (a non-tuple source or shape/arity mismatch takes `fail`; `{badmatch, Value}` only on the no-fail path).
- `records/{mod,raw}.rs`: `UpdateRecord`, `IsAnyNativeRecord`, `IsNativeRecord`, `GetRecordElements`/`GetRecordElementsId`, `PutRecord`, `IsRecordAccessible`, `GetRecordField`, `UpdateRecordId` -- the whole family, `erl_record.c` branch for branch (incl. `PutRecord`'s *create* form, where `badfield` outranks a delayed `novalue`, and C's export/scope rules: `IsRecordAccessible` strict only when `scope = external`, else the `$MODULE` wildcard, and `GetRecordField` needs no export for an atom `Id`); a foreign-module id is `unsupported`.
- `lists.rs`: `PutList`, `GetList`, `GetHd`, `GetTl` (a non-cons source raises `{badmatch, Value}`).
- `funs/{mod,tests}.rs`: `MakeFun3` (arity = descriptor arity minus `num_free`), `CallFun` (fun in `x(arity)`, args `x(0..arity)`), `CallFun2`, `Apply` (M in `x(arity)`, F in `x(arity+1)`), `ApplyLast` (pop the frame first). `Apply`/`ApplyLast` resolve their `M,F` target through the cross-module-call seam (`ExecutionContext::resolve_external_call`) **first**: on `Some((callee, label))` the callee is registered as a module context and entered **in this machine** -- `Apply` stores the **caller's** return address (`Continuation::Address { func, pc + 1, context: current_context() }`) in the live frame and reports `Step::Enter`, and `ApplyLast` reports `Step::Enter` on its already-popped frame (so the callee's `return` follows the caller's continuation); on the seam's `Ok(None)` default the target is the synchronous `call_bif` route, and `ApplyLast` then follows its (popped) frame's continuation context-aware via `Machine::continuation_step` (a tail apply must return into the **caller's** module, so a continuation in another module context yields `Step::Enter`, never a bare `Goto`). A non-atom `apply` target is `badarg`.
- `exceptions/{mod,raise,stacktrace,tests}.rs`: `Badmatch`, `CaseEnd`, `TryCaseEnd`, `IfEnd`, `Badrecord`, `Raise` (re-raise with the handled class), `Try`/`Catch`, `TryCase`/`TryEnd`/`CatchEnd` (each consumes one catch frame), `BuildStacktrace`, `RawRaise` (both in Known Issues).
- `floats/{mod,arith,convert,tests}.rs`: `Fmove`, `Fconv`, `Fadd`/`Fsub`/`Fmul`/`Fdiv`, `Fnegate` (non-float operand / non-finite result -> `fail` when live, else `badarith`; `Fconv` converts a bignum via `beam_term::number::big_to_f64`, over-range -> `badarith`).
- `maps/{mod,read,write,tests}.rs`: `GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact` (both layouts read via `terms::map_entries`; keys via `beam_term::cmp` so `1` and `1.0` differ; a non-map source `fail`s on the compiled forms, else `{badmap, Source}`; built via `terms::make_map`, >32 keys -> hashmap).
- `bitstrings/{mod,raw}.rs` + `{matching,create}/*`: `BsStartMatch3`/`4`, `BsMatch`, `BsMatchString`, `BsTestTail2`, `BsGetTail`, `BsGetPosition`/`BsSetPosition`, `BsGetInteger2` (any width), `BsGetFloat2`, `BsGetBinary2`, `BsSkipBits2`, the UTF reads, `BsCreateBin` (integer/binary/float/utf8/16/32/string), `BsInitWritable` + a **first** `append`/`private_append` (seed-and-rebuild). A result is an on-heap `ErlHeapBits` <=64 bytes else an off-heap refc binary; the match-context is an on-heap `ErlSubBits`-shaped box re-derived per opcode, so matching survives calls and branches.
- `receive.rs` (registered **last**; no term inspection -- every mailbox position/removal goes to the `Mailbox` seam): `Send` (deliver `x(1)` to `x(0)`, store **the message itself** in `x(0)`), `LoopRec` (candidate -> `Dst`, else `Fail`), `LoopRecEnd`, `Wait`, `WaitTimeout` (a small-int `0` falls through to `timeout`, else suspends like `wait`), `Timeout`, `RemoveMessage`, the four `RecvMarker*`.

### Raising opcodes and the catch-frame model (`families/exceptions/`, `src/machine/catch.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, which owns it) and blank their frame slot. A raise (a family's `throw`/`throw_error`, or `raise_bif_error`) records `pending_exception = (class, reason)` then consults the **innermost** live catch frame.
- To land, the machine unwinds the call-frame stack back to `CatchFrame::frame_index` (dropping every deeper frame's Y slots) and writes the handler registers exactly as C's `handle_error`: `x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace` (`NIL` at M1), `x(3) = class atom`; a landed raise returns `Ok(Step::Goto{func,pc})` when the handler is in the current context, else `Ok(Step::Enter{context,func,pc})` (the driver switches context so the callee's own `catch` handles a raise that crossed a cross-module call), and with no live catch frame (or an unresolved class atom) it stays the typed `Err(BeamError::Raise(..))` -- never a panic. The raise *reads* the innermost entry but **never pops it**; the handler opcode (`try_case`/`try_end`/`catch_end`) consumes exactly one entry (never both). `try_case` blanks its slot, requires the `THE_NON_VALUE` marker in `x(0)` and moves the class atom from `x(3)` into `x(0)`; `catch_end` leaves a normal result untouched but folds a landed exception into the caught term -- the thrown value for class `throw`, `{'EXIT',Reason}` otherwise.
- The class atoms (`error`/`exit`/`throw`) are installed from the running module's atom table (`Machine::set_class_atom`); an atom absent from the module is never substituted by a *different* atom. `pending_class` is the class a `raise` opcode re-raises with (C's `i_raise` keeping `freason`).
- **The raise entry points (`src/machine/catch.rs`).** `Machine::throw`/`throw_error` are the uniform raise/unwind entries the families call; `Machine::throw_with_trace` is the same entry carrying the caller-built `trace` term (C's `x(2)`; `NIL` at M1). The symbolic `StackTrace` a raise carries out when it leaves the machine **uncaught** (`Raise::stacktrace`) is attached not at the raise site but by the single funnel `Machine::with_uncaught_frames(err, entry_module, func, pc)` as the raise leaves the machine (at the `step_instruction` / `drive` boundary), so **every** raise kind -- a `throw`/`error`/`exit` `raw_raise` builder, a BIF error through `raise_bif_error`, the `func_info` failed-clause raise -- gets the same frames and no site derives them itself. `Machine::raise_stacktrace(&self, entry_module: Option<&Module>, func, pc)` derives those frames from the machine's live call frames -- the raising function first, then each caller, each resolved in **its own** module context -- which is what localizes a bare-atom reason (the `FuncInfo` arm above). The funnel attaches only to a `BeamError::Raise` that carries no frames yet and whose reason is not an engine diagnostic (`error::unsupported`), so a caught raise, an already-framed raise and an engine diagnostic are all returned unchanged. The stacktrace is **metadata only**: the landing registers, the reason and the pending class are untouched, so a caught raise behaves byte-identically with or without it.

## Design Decisions
- **Root-set contract made concrete, with both admission doors defaulted.** The primary admission point is the defaulted `ensure_heap_full(heap_need, roots)` over `RootSet`, which `Machine::ensure_heap` calls so the context gets the exact GC root set (`x[0..live)` + the whole stack + the whole FR file) and a Stage-4 collector can move terms in place without frame liveness maps; its default forwards to the frozen narrow `ensure_heap(heap_need, live, x_regs, stack)` with the FR file discarded, so an existing host is byte-identical. The **second** admission point is `alloc_words_rooted(n, roots)` over `RootSet` (`x`/`stack`/`fr`, all mutable, plus the `live` hint) -- the root hand-off for *term construction*, because `alloc_words` itself has neither an admission point nor roots; its default discards the roots and forwards to `alloc_words`, so an existing host is byte-identical. **Every in-crate term-construction arm routes through the second door** via the `terms::*_rooted` builders, which follow the frozen **reserve → read → write** discipline (`reserve` the block first with *exactly one* rooted allocation, then read operands from the machine's post-collection state, then write the header/element words); `src/terms/slack.rs` is the reserve seam and `src/terms/sink.rs` the `Sink` shape writer a multi-node build is carved from. `terms` is the only place that dereferences raw heap storage (the bitstring `raw` module is the documented layout exception); the only committed `alloc_words` caller left is the four `&self` execution-position accessors in `src/machine/location.rs`, which cannot lend `&mut` roots.
- **A typed frame CP slot rather than a raw stack word**, with a catch-frame stack mirroring C's `next_catch` + `c_p->catches` split, so the landing convention (`x(0..=3)`) and the bookkeeping live in one place.
- **JIT tiers off the critical path; compile failure a typed error.** Cranelift is optional (default OFF), so with it off neither the crate nor the build carries Cranelift at all; compilation is measurement-gated (sec. F) with a bounded-latency, cheap-deopt design, and `TierPolicy` is deliberately **not** wired into execution. A `CodeBuffer::seal` failure propagates out of `compile`/`run_export`, and an unresolved `Jump` target deopts so the interpreter's `unknown_label` surfaces. The measurement harness lives in `src/jit/bench` (a `pub mod bench`, driven by `tests/jit_bench.rs`); its nine workloads, method and caveats are in `src/jit/bench/CONTEXT.md`, the figures in `MEASURED.md`.
- **One driver for both native tiers, delegating per instruction rather than duplicating semantics.** A tier supplies its compiled-code lookup through the `NativeCode` trait (`enter(rt, func, pc) -> Option<i64>`); because `jit_step_one` *is* `Machine::step_instruction`, every tier is interpreter-identical for every supported opcode without a second implementation.
- **The cross-module call seam is additive and host-driven.** `resolve_external_call` (default `Ok(None)`) lets a host that owns loaded modules run a `call_ext*` **in the same machine**, so a `receive` inside the callee suspends the driving process (`RunOutcome::Wait`) instead of folding into `Err(error::blocked())`. The mechanism is C's model: a code pointer (the frame `Continuation`) carries its module context, so a `return`/raise can land in another module; the driver (`Machine::drive`) owns the `(func, pc)` position + its context and re-binds the literal area only on a `Step::Enter` to a different context. Modules are held as `Arc<Module>` handles deduped by `Arc::ptr_eq` (bounded by distinct modules, not call count) and cleared only by `reset` -- never by a resume, because a suspended cross-module frame must still name its module. The seam is interpreter-only: a resolved transfer is not in the JIT inline set, so `Step::Enter` on a native tier is a typed error, never a silently wrong block.
- **Unsupported => `Raise` with reason atom `unsupported_opcode`** (a dedicated `BeamError` variant must not be added from here); the slice `.beam` fixture lives with `beam_loader` and is read by relative path.
- **The FR file stores `Eterm` term slots at M1** (C's is raw doubles), so `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is deferred.
- **M1 fun layout inlines the descriptor** (`uniq`, `index` after the header; no code pointers at M1) -- the same substitution as the external-pid `node` slot (`MAKE_FUN_HEADER` + `ErlFunThing`). `MinimalContext` fun application goes through an apply hook (no closure registry here), `build_stacktrace` derives from the machine's live frames rather than a raise-time snapshot, and `update_record` always copies (the hint only authorises updating a unique/dead source).
- **Flat, integer-keyed hot-path state (safe Rust).** Jumps resolve through `LabelMap` -- a dense `Vec<Option<(func,pc)>>` (`Slots::{Dense,Sparse}`) built once per run by `Machine::enter_run` (the loader's label ids are dense: `lists.beam` has 1256 labels, max id 1256) -- so a jump is one array index. Each import's `call_bif` target is resolved **once per run** into an `ImportTable` of `ImportTarget { module, function, arity }` cached in `LabelMap` keyed by the owning `Module` address (a different module falls back to the free `import_target`). `GcBif`/`Bif`/`Bif0`/`CallExt` marshal arguments through a fixed-lane `STACK_ARGS = 2` stack array (the dominant arities build an exact-size slice LLVM can SROA); arities >= 3 reuse a per-`Machine` `args_scratch`, so a BIF call allocates **nothing** -- proved by `tests/bif_alloc.rs`. `read_operand` is inlined and ordered hot-first; `Machine::reset` refills the register/FR files in 128-byte chunks. None of this changes semantics: the reference point stays `Machine::step_instruction`.
- **Hot-path inlining is measurement-driven, never blanket.** An out-of-line helper returning `Result<_, BeamError>` (a 72-byte `Err`) forces its `Ok` through memory, so the interpreter's *small* hot helpers are `#[inline(always)]` — `read_operand`/`write_operand` (`src/operand.rs`), `test_arg` (`src/interpreter/test.rs`), `set_y` (`src/machine/frames.rs`) — while `step_instruction` and `eval_test` carry plain `#[inline]`. The same attribute is a **measured regression on large helpers**: `#[inline(always)]` on `exec_bif`/`call_import` costs ~20%, and caching the resolved `functions[func].code` slice across the dispatch loop costs ~19% (the extra live range across `&mut self` calls and the code bloat outweigh the saved `Vec::get`), so neither is applied. The residual per-instruction cost is structural, not a missed hint: the 64-byte `Instr` discriminant `match` in `step_instruction` (a mispredicted indirect jump), the `Result<Step>` loop plumbing, the double `Vec` bounds check (`functions.get`/`code.get`), and the arity-2 `gc_bif` marshal (the largest single leaf on the list walk).

## Known Issues / Intentional M1 gaps
- **The collecting host is the remaining GC step, not an engine gap.** `MinimalContext` has an unbounded, never-freed reserved-heap-region arena, and `test_heap`/`allocate_heap` reach the full-root admission point (`ensure_heap_full`, a no-op there -- its default forwards to the no-op `ensure_heap`). The engine's own half is landed: **every** in-crate term-construction arm allocates through the rooted door (`alloc_words_rooted` / `Machine::alloc_rooted` / the `terms::*_rooted` builders), under the frozen reserve → read → write ordering, proved under a mock **moving** collector by `src/terms/alloc_tests.rs` (the rooted-vs-unrooted peak/retained live-words table) and `tests/rooted_alloc.rs`, with the root hand-off pinned by `tests/gc_roots.rs`. **No crate overrides `alloc_words_rooted` yet** -- the production heap is `beam_rt`'s and still takes the default (roots discarded) -- so an ordinary `beam_rt` run does not collect; wiring `beam_gc` behind the rooted doors is `beam_rt`'s side (Handoffs #11).
- **A captured stacktrace is engine-derived.** `raw_raise` is oracle-exact for all three classes and the unknown-class fall-through (`x(0) = badarg`, no raise); `build_stacktrace` is oracle-exact for a `NIL` raw trace (the only compiler-emitted path) and otherwise substitutes a symbolic trace from the machine's **live** frames (Handoffs #3).
- **Nameable atoms required.** `catch_end` needs the `EXIT` atom; `raise_bif_error` can only raise a nameable error -- a BIF failure whose atom is absent from the running module's atom table (or a `BeamError` with no BEAM atom *and no live reason term*: `TermNotFound`, `Io`, an empty/non-`Eterm` `live_reason`) propagates unchanged (the `Module` reaches the interpreter read-only). Neither path ever substitutes a different atom.
- **Compiled arithmetic is oracle-exact on overflow.** `+ - * div rem` promote to exact bignums (compiled `gc_bif` goes through `ctx.call_bif` into `beam_bifs`); an out-of-range `Integer`/`Character` **operand** becomes an exact bignum via `terms::make_integer` (which the JIT's `constant_word` deopts).
- **A blocking `receive` needs a host mailbox** (Handoffs #1): with no mailbox each `Mailbox` call is a typed `unsupported("<method>")`, and a mailbox with no candidate **suspends** (`RunOutcome::Wait`, folded into `error::blocked` by plain `run_export`); a parked `wait_timeout` publishes its deadline through `Machine::wait_deadline` (the `timeout` continuation + the delay, read from a literal or a Y slot), but with no host timer it stays parked until a message arrives (only a small-int `0` falls through to `timeout`). A host that also **adopts the cross-module seam** (`resolve_external_call`) gets the suspension out of a `call_ext` callee too -- the callee runs in the same machine, so a `receive` inside it reports `RunOutcome::Wait` to the driving process instead of folding into an error (`tests/external_call.rs`).
- **Records.** The whole native-record set executes, including `PutRecord`'s *create* form for the running module's own records (`Src` the literal `nil`; the definition from `beam_loader::Module::{records,record,record_by_name}`, hashed with `beam_term::hashing::compute_record_definition_hash`). Only an `Id` naming a *foreign* module's record is a typed `unsupported`; a record-semantics failure branches to the instruction's `fail` label (`NO_FAIL` -> `unsupported("<instr>/no_fail")`). The installed `erlc` emits the native-record opcodes -- including the create form -- only for the explicit `-record #name{}` form (the legacy `-record(name,{})` form still lowers to a plain tuple), and the create form is verified **structurally** (`tests/records.rs`).
- **Bitstring gaps (each a typed result -- never a wrong value).** `raw::heap_bits` refuses a refc subject whose window is not byte-aligned. `bs_init_writable`/`append`/`private_append` are a copy-rebuild (`HANDOFF_bs_init_writable.md`): no amortised growth, the `BIN_FLAG_*` flags and `binary:referenced_byte_size/1`'s capacity answer are unmodelled, and a non-first `append`/`private_append` segment is a typed `unsupported`. `system_limit` is modelled (`size*unit` overflow / the post-multiply sign bit / a positive-bignum size; a negative bignum is `badarg`); a `float` segment of width 0 or invalid raises `badarg` (`tests/bitstrings_create_fail.rs`).
- **Literal operands.** Every installed module's `LitT` area (`EXPORT_EXT`/`NEW_FUN_EXT` fun literals, `>32`-key map literals, big integers) and wide (`>8`-byte) integer operands decode; a `Literal` index outside the running module's `LitT` table (or a read with no module bound) is the typed `operand: literal` error.
- **`y(k)` addressing and `trim` are equivalent to C's `E[1+k]`/`E += N` -- no off-by-one.** The engine keeps the continuation-pointer slot **out** of the stack (`Frame { continuation, y_base, y_count }`, so `y(k) = stack[y_base + k]`), whereas C keeps it at `E[0]` (`y(k) = E[1+k]`, `emu/macros.tab:142-147`); both discard the lowest `N` Y slots. The operands agree because the loader encodes `deallocate N` as `(N+1)` words and `deallocate` consumes the frame's **remaining** Y count -- post-`trim`, what the compiler emits (`gap/1`: `trim 1` -> `deallocate 0`). `pop_frame_checked` is deliberately **stricter** than C (which advances `E` unconditionally): a mismatch is a typed `unsupported`, never silent corruption (`tests/tailcall.rs`).
- **Map enumeration order is storage order, not canonicalized** (`erts_cmp_flatmap_keys`), affecting only `term_to_binary` byte comparison; a malformed hashmap node / `THE_NON_VALUE` / immediate item during a read is a typed `BadArg`. A missing map key with `fail == NO_FAIL` has no ground truth (the compiler always emits a fail label for the matching forms), so it is a typed `unsupported` rather than an invented reason.
- **Reductions and pre-emption exist; the scheduler does not.** `Machine::drive` charges one reduction per interpreted instruction through the defaulted `ExecutionContext::reduce(n)` hook (`Ok(())`), after the instruction succeeded and at a single call site, so the charge is exactly one instruction (a **non-allocating** loop, which never reaches `ensure_heap`, is still pre-emptible). A host with a scheduler pre-empts by returning a **typed error** from `reduce`, which the run reports exactly like any other step failure. `Machine::reductions()` reads the current slice's count (zeroed at slice entry; one `drive` call = one slice, so `resume_outcome` starts a fresh slice) and `Machine::reset_reductions()` returns it while zeroing it. There is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption is a fresh `drive` (`tests/reductions.rs`). The scheduler, run queues, trap handling and `ensure_heap` limits are Stage 5 (`beam_process`); stack growth is an unbounded `Vec`.
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after.** C fills `reg[i] = args[i]` for `i < arity` then `reg[i + arity] = funp->env[i]`, so a context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = captures -- *not* `free ++ args`.
