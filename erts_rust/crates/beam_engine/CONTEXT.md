# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** from `beam_loader` behind a three-tier execution seam: a direct-threaded **interpreter**, a **native x86-64 baseline tier** (the default for every process entry), and an optional **Cranelift hot tier** (`jit-cranelift` feature, default OFF).
Stage-1 engine half of Part II §H (IR contract §E, interpreter/JIT trade-offs §F; `../../CONTEXT.md` §4), on the critical path of the vertical slice: it loads a real `.beam` and runs it end to end.
It depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`/`beam_gc`, never on the Stage-5 runtime core -- BIF dispatch, fun application, heap/GC, process limits and pre-emption all sit behind `ExecutionContext` (implemented by `beam_rt`), which keeps the DAG acyclic and the engine testable with `MinimalContext`.
**Compile latency is a first-class correctness constraint**: every tier is a measurement-gated, correctness-first *mechanism*, never an optimiser that may change a result.
Ground truth (read-only): `../../erts/emulator/beam/emu/beam_emu.c`, `emu/*.tab`, and `beam_common.c`'s call/return/allocate/error/`next_catch` conventions.

**Where the detail lives.** This file is the crate-level contract. `INSTRUCTION_SURFACE.md` owns the exhaustive instruction surface, design decisions, the full known-gap and handoff lists; `MEASURED.md`/`PERF.md` own every measured figure; `TEST_NOTES.md` owns the test enumeration; each child `CONTEXT.md` owns its subsystem. Never restate their numbers here.

## API Surface (FROZEN -- the runtime and tests design against this)
Root re-exports; the seams, the machine and the tier roster also via `beam_engine::prelude::*` (the arena's measurement/reclaim types stay crate-root only).
The crate embeds NO BIF table: computation goes through `ExecutionContext::call_bif`, an in-machine callee through the resolver seams, and `apply`/`apply_fun` are the value-returning fallbacks.

### The typed block-IR seam (`beam_loader`)
Backends consume only `Module`/`Function`/`Block`/`Instr`/`Operand`/`TestKind`/`HeapNeed`: typed, block-structured IR with BEAM types, safepoints, failure/branch semantics (a `fail` label vs `NO_FAIL`), catch info and line/range tables.
A backend may assume exactly the frozen `RootSet` and nothing else about machine layout -- **no frame liveness map exists** -- and no `Instr` carries a backend-specific encoding.
Every park/resume address, stacktrace frame and code-map range is a `(func, pc)` into the loaded `Module`.

### The context seam (`src/context.rs`)
One `pub trait ExecutionContext` of `&mut self` methods over `Eterm`; **`src/context.rs` is authoritative for the signatures**, and every method is `Result`-returning except the pure-`&self` probes.
Groups: the BIF doors (`call_bif`, `wants_bif_in_machine`/`call_bif_in_machine`, the outcome-aware `call_bif_outcome`/`call_bif_in_machine_outcome`); the GC doors (`ensure_heap`/`ensure_heap_full`, `alloc_words`/`alloc_words_rooted`); `heap_available` (introspection only); `apply`/`apply_fun`/`apply_fun_outcome`; `send_message_with_off_heap`; the resolvers `resolve_external_call`/`resolve_local_fun`/`resolve_local_call`/`atom_name`; `atoms`; `reduce`/`wants_reduce`; `foreign_record_definition`; `trace_enabled`/`trace_event`.
`RootSet<'a> { x, stack, fr, live }` (`live` clamped, `ALL_LIVE = u32::MAX`); `TraceEvent` reports `Call`/`ReturnFrom`/`ReturnTo`.
- **THE ROOT-SET CONTRACT (the hardest invariant).** A collecting host overrides both rooted doors and relocates every term reachable from `roots.x[..roots.live_len()]`, **the whole `roots.stack`** (**NO frame liveness maps** -- `../../CONTEXT.md` §4) and **the whole `roots.fr`** (which holds `Eterm` slots), writing the moved terms back.
  `live` is only a hint (`ALL_LIVE` is always *safe*) and **nothing outside the root set survives**: a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation.
  The engine side is `Machine::with_roots`/`Machine::alloc_rooted` and **every in-crate construction arm routes through it**; `with_roots` also **parks the machine's five loose `Eterm` fields at the stack tail** (two function-clause latches, the pending exception's reason, the two supplied-trace latches -- `LOOSE_HEAP_TERMS = 5`) and re-seats them, so `RootSet` plus the stack carries every term the machine holds and no host enumerates `Machine` fields.
  The narrow door `ensure_heap(heap_need, live, x_regs, stack)` stays the frozen shape; `Machine::ensure_heap` calls the defaulted `ensure_heap_full(heap_need, roots)`. `alloc_words_rooted` is the construction door and defaults to `alloc_words` with roots discarded. Detail: `src/terms/CONTEXT.md`, `src/CONTEXT.md`.
- **The in-machine BIF door.** A host answering `true` to `wants_bif_in_machine` gets the live `Machine` and the run's **entry module** (context `0`) on every BIF dispatch and **must** override `call_bif_in_machine` (+ `_outcome` if its BIFs can wait). The probe is latched once per run into `Machine::bif_in_machine_on` by **both** drivers, every dispatch goes through `Machine::dispatch_bif_call`, and the default `false` keeps the plain path byte-identical. Gate: `tests/bif_in_machine.rs`.
- **`reduce(n)` is the reduction hook** (defaulted no-op), charged by both tier drivers: by `Machine::drive` once per interpreted instruction with `n = 1` **before** the body, and by the native driver once per driver-loop iteration (block-granular pre-emption).
  A host pre-empts by returning a **typed error**, leaving the instruction **un-applied** with the machine parked so `resume_outcome` applies it **exactly once**; `wants_reduce` latches per run (a host implementing `reduce` MUST stay `true`); there is **no `RunOutcome::Yield`** and no `ReduceOutcome`.
- **`apply`/`apply_fun`.** `apply` (default: `call_bif`) has **no engine call site** and **no park channel**, since every park address is a `(func, pc)` into a loaded `Module`. `apply_fun` is the fallback for `call_fun`/`call_fun2` (default `unsupported` -- no closure registry), consulted only after `resolve_local_fun` declines, entering with `x(0..arity)` = **arguments first, free variables after** (C's `call_fun` order), never `free ++ args`; both errors route through `Machine::raise_bif_error` into the caller's live `try`/`catch`.
- **`resolve_external_call` (`call_ext*`, dynamic `apply`).** `Some((callee_module, entry_label))` runs the callee **in this machine** (so a `receive`/raise inside it suspends/raises this process); `callee_module` must be the **shared** `Arc<Module>` (contexts dedup by `Arc::ptr_eq`), `entry_label` the export label after `func_info`; default `Ok(None)` keeps `call_bif`.
- **`resolve_local_fun` (`call_fun`/`call_fun2`).** Consulted **first**: `Some((callee_module, lambda_entry_label))` enters the lambda body, copying free variables into `x(arity..)` (C's `reg[i + arity] = funp->env[i]`) as `Step::Enter`; default `Ok(None)` keeps the `apply_fun_outcome` fallback, which may park instead of failing.
  The free-variable copy is sound under a *collecting* host because the target is **re-read after the seam**, not because no admission point intervenes (`tests/fun_seam_rooting.rs`).
- **`atom_name` (atom-*value* seam for `apply(M,F,A)`/`M:F(...)`).** Answers **owned** `Option<String>` so the caller can hold both across later `&mut` host calls; a non-atom or unnameable id is `BadArg`, never a substituted atom. Gate: `tests/apply_atom_value.rs`.
- **`atoms` (comparison atom-*namespace* seam).** `erts_cmp_atoms` compares names and falls back to the raw id for an unknown name, so this is the namespace for every comparison (six kinds + `is_boolean`, `SelectVal`, the baseline tier's `evaluate_comparison`, map-key equality) and, via `machine::catch::namespace_atom`, every raise's reason/class atom.
  The default `&module.atom_table` is the load-time snapshot, so a host owning ONE live namespace overrides it and gets order matching the `<` BIF; a name neither source knows is a typed error, never a substituted atom index.
  `fn atoms<'m>` borrows `*ctx` **immutably** (take it after the operand reads, never across a `&mut ctx` call); the JIT inline lowerings decline atom operands for order comparisons. Detail: `src/CONTEXT.md`.
- **`resolve_local_call` (local call *as* a BIF).** `Ok(true)` = the host serves `(Module,Function,Arity)`, so the engine marshals `x(0..arity)` and dispatches via `call_bif`; `Ok(false)` = the in-machine jump, mutating nothing. The compiler emits a **local** call for a **non-exported** same-module function, so a module's non-exported NIF stubs reach `call_bif` only through this seam.
  The host is consulted **once per distinct callee per run, never per call**: the answer is filed in an index-addressed verdict table (`Machine::verdict_table`/`LocalVerdicts`, one slot per `Module::functions` entry), so a repeat call is one slot load and an un-nameable callee costs zero consultations.
  The answer must be a pure function of `(module, function, arity)`; `Machine::invalidate_local_call_verdicts` serves a changing answer set and the engine arms it itself on `erlang:load_nif/2`. A verdict is **never** baked into compiled code (`JitBackend::compile` gets no `ExecutionContext`; the block cache is shared). Detail: `src/interpreter/CONTEXT.md`.
- **`foreign_record_definition(owner, name)` (`PutRecord`'s *create* form for another module's `{Module,Name}`).** `Ok(Some(def))` is the host record table; the instance is built only when `def.is_exported`, else the C's `error:{badrecord, Id}`. No `code:ensure_loaded/1` trap sits behind the door, so an unloaded defining module is its own `Ok(None)` and the typed `unsupported` stands. Pinned in `src/families/records/tests/`, `tests/gaps.rs`.
- **`call_ext*` special cases.** Only the import `erlang:apply/3` is special-cased (C's `fixed_apply`, arity 3 only): walk the list into `x(0..N)` -- past `MAX_ARG = 255` is `error:system_limit`, a non-proper tail the catchable `badarg`; `apply/2` stays on `call_bif`. `erlang:send/2`/`'!'/2` go through `send_message_with_off_heap`. Detail: `src/interpreter/CONTEXT.md`.
- **A.8 trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}`/`return_from`/`return_to`; the engine **reports only** (the host matches and builds terms). Emission is infallible (a traced run is byte-identical) and a **natively-executed JIT block does not trace**. Points: `src/interpreter/CONTEXT.md`.
- `pub type BifHook`/`ApplyHook`/`ExternalResolver`/`LocalFunResolver` are the bodies `MinimalContext` installs via `with_*`/`set_*`.
- **`MinimalContext`** -- the test/embedding context: an unbounded, pointer-stable **reserved-heap** arena (reserved up front, **grown in place**, so every handed-out pointer stays valid and unmoved), a pluggable BIF hook (`new()` rejects every BIF), optional apply hook, resolvers and mailbox.
  Its **measurement/mark/reclaim surface** (`src/context.rs` + `src/context/reclaim.rs`): `heap_stats()`, `heap_mark()`/`heap_mark_matches()` (a stale mark is `false`), `for_each_heap_region()` (each region's **written prefix** oldest first: raw words, do not interpret or keep the slice), Tier A `heap_rewind(mark)`, and Tier B `reclaim_heap(forward)` (+ `_with_capacity`, a Cheney compaction whose roots the **host** forwards).
  `used_words` is **cumulative demand** (`= live_words + released_words`), never live memory; a mark is a **precondition check, never a permission**, and neither tier decides liveness -- the caller asserts nothing reachable lies above the mark (A) or outside its forwarded roots (B). Detail: `src/context/CONTEXT.md`.
- **Root enumeration doors.** `Machine::for_each_root(&self, f)` is the read-only census of exactly what `with_roots` hands over (`x[..used_x_extent]`, the whole stack, `fr[..used_fr_extent]`, the five loose terms), skipping `IMMED1` by `beam_term::primary_tag`; `Machine::for_each_root_mut` is its relocating twin, implemented as ONE `with_roots` hand-off so the two cannot disagree.
  `args_scratch` is `mem::take`n for the whole wide dispatch and that window is **collection-free by construction** (`dispatch_bif_call` is `&self`; the marshal's only allocation is non-collecting `alloc_words`), pinned by `tests/bif_args_window.rs`.

### The supplied-stacktrace encoder (`src/supplied_stacktrace.rs`)
The **public** `beam_common::StackTrace` -> `Eterm` encoder for a host rendering a raise's explicitly **supplied** symbolic frames without a compiled handler (the tree-walking `-eval` route): `encode_supplied_stacktrace(module, ctx, frames)` and its `Machine::` twin.
Both cook `frames` into the oracle's `[{Module,Function,Arity,Location}]` list (innermost first; `Location` = `[{file,File},{line,N}]`, else `[]`) as ONE rooted reservation carved node-by-node.
**The atom source is the passed `module`'s table, by lookup only** (nothing is interned), so a shared-namespace host must pass a `Module` carrying that table; an unresolvable name is `error::unsupported`.

### The BIF suspend channel (host contract for a waiting BIF)
`call_bif_outcome`/`call_bif_in_machine_outcome` are the outcome-aware doors, both `Result<BifOutcome>` and both **defaulting** to the value as `BifOutcome::Return`, so a pre-channel host stays byte-identical; `Machine::dispatch_bif_call` takes exactly one per run, and a host that said `true` to `wants_bif_in_machine` must override the in-machine twin.
`Suspend` means the BIF did **not** complete and the instruction was **not** applied (no register written, no guard branch, no frame effect). The engine reports `RunOutcome::Suspend { func, pc }` **at the BIF instruction itself**; the host pumps its own waiting resource and the resume **re-executes the instruction with the same operands**, so the host must be re-execution safe (a suspending attempt must not consume a one-shot resource).
The engine holds **no** suspended state: the park is `(func, pc)` + registers + stack + FR file, exactly the frozen `RootSet`, so a moving collector may relocate the operands and the re-execution re-reads them (C's `c_arg_reg`/`arg_reg` equivalent).
A **non-blocking** entry folds a suspend into `error::suspended()` -- never `blocked()`, never a substituted value -- and **both native tiers report and resume it** (baseline: the `SUSPEND` (`-5`) block-ABI word; Cranelift: the same `run_native_resume_outcome` seam, where an address the artifact did not compile advances by the driver's per-instruction interpreter step). Gate: `tests/bif_suspend.rs`; the class-A/class-B rule (`erlang:apply/3` is the typed non-idempotent gap): `src/CONTEXT.md`.

### The closure-apply suspend channel
`apply_fun_outcome` returns `Result<FunOutcome>` (`Return(value)`/`Suspend`), **defaulting** to the value as `FunOutcome::Return` (an unimplemented `apply_fun` still answers `unsupported("apply_fun")`); it exists for a host that **interprets** the closure itself and cannot park its caller through a value-returning door.
`Suspend` means the application did not complete and the instruction was not applied; the engine parks on the `call_fun`/`call_fun2` instruction and the resume **re-consults this door with the same `fun` and `args`**, so the host must **continue** the pending application, never restart it. Gate: `tests/fun_suspend.rs`.

### The mailbox seam (receive/message family)
The mailbox lives in the Stage-5 runtime, never here. `pub trait Mailbox` is exactly nine `Result`-returning methods: `send_message`; the scan position `receive_next` (`None` = exhausted), `receive_skip` (`loop_rec_end`), `receive_remove` (`remove_message`), `receive_reset` (`timeout`); and `receive_marker_reserve`/`_bind`/`_use`/`_clear`.
`ExecutionContext` carries the **same nine names as defaulted methods** (`error::unsupported(...)`), so every implementor compiles unchanged. The engine **never inspects** a message or a marker (selection is the compiled code's job; a marker is opaque and only a separate *reference* reaches `_use`/`_clear`), and installing a mailbox does **not** change the non-blocking entries, which still surface `error::blocked`.
**`send_message_with_off_heap(to, message, src_binaries)`** is the `Instr::Send` entry *and* the `call_ext*` send entry: a tenth defaulted method whose default discards the source off-heap table the receiver-side copy needs for an engine-built refc binary.
**Ordering invariant:** the position calls take no candidate argument, so driving is correct only while the host's position is stable between the producing `loop_rec` and the consuming `remove_message`/`loop_rec_end`; a `receive` reaches `wait`/`wait_timeout` only via `loop_rec`'s `None` arm, so a re-entry sees only messages appended since. Host contract: FIFO with a **saturating** index (`beam_message::QueueCursor`, `beam_rt::MailboxState`). Full contract: `src/families/CONTEXT.md`; evidence: `tests/receive.rs`.

### The machine (`src/machine/*.rs`)
`Machine` is the process-state core: the x-register file (`MAX_REGISTER = 1024`), the FR file (`MAX_FLOAT_REGISTER = 1024`, holding `Eterm` slots), the Erlang stack, the call-frame and catch-frame stacks, the `refc_binaries` arena (never cleared by `reset`, host-prunable via `retain_refc_binaries`), the literal area, the **module-context registry** (one `ModuleContext { module: Arc<Module>, labels, verdicts }` per module, deduped by `Arc::ptr_eq`; context `0` = entry module + `entry_verdicts`), the reduction counter, `raise_snapshot`, the latched `trace_on` and the label-map cache.
The call/return path owns no allocation, lookup or unpacking: three buffers reserved up front (`STACK_RESERVE_WORDS`/`FRAMES_RESERVE`/`CATCH_FRAMES_RESERVE` = 256/256/8), `push_frame_window(y_count)` hands back the frame base and the new Y window in one step (what the baseline tier publishes through `JitRuntime::publish_y_window`), `pop_frame_checked` reads the frame top once, and the executing `(func, pc)` is one packed `u64`.
Run entries: `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` returning `RunOutcome { Returned(Eterm), Wait { func, pc }, Suspend { func, pc } }`, plus the tier-aware quartet.
The **uniform raise funnel**: `throw*` rebuilds the raise-time snapshot *before* any unwind, and an **uncaught** raise's symbolic `StackTrace` is attached by `Machine::with_uncaught_frames(err, entry_module, func, pc)` as it leaves the machine, so every raise kind gets the same frames.
Introspection: register/stack/frame/catch accessors, `pending_exception`(+`_mut`)/`pending_class`, `resumption_addresses`/`resumption_contexts`, `raise_snapshot`, `wait_deadline`, `reductions`/`reset_reductions`, and the position accessors (`current_code`/`current_function`/`current_location`/`current_stacktrace`/`current_module`/`initial_call`). Per-file roles: `src/machine/CONTEXT.md`.

### The `Step` protocol (`src/step.rs`)
`Step { Next, Goto { func, pc }, Enter { context, func, pc }, Wait { func, pc }, Suspend { func, pc }, Done }` -- a body returns the `Step` and never mutates the loop's `func`/`pc`/context.
`Next` = `pc + 1`; `Goto` = jump within the module; `Enter` = transfer into another module context (cross-module `call_ext*`, a `return` onto a `Continuation::Address`, or a raise landing in another context's catch frame) -- the driver switches context and re-binds the literal area exactly there; `Done` = yield `x(0)`.
`Wait` = the receive suspend -> `RunOutcome::Wait` (the JIT driver and `jit_step_one` fold it into `error::blocked()`); `Suspend` = the BIF suspend, whose reported address is the instruction itself (the JIT driver folds it into `error::suspended()`).
A raise is **not** a `Step`: it stays an `Err(BeamError)`, or the exception layer folds it into a `Goto`/`Enter` to a live catch handler.

### The families seam (`src/families/`)
Every `Instr` the core loop does not execute natively goes to `families::dispatch(...) -> Result<Step>`, which routes by the instruction's own variant to the single owning family; ownership is **disjoint and variant-complete** -- each of the **77** claimed variants has exactly one owner (`tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`).
`exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = executed, `Ok(None)` = not its variant, `Err` = it raised; an unowned or declined variant falls to `error::unsupported("widened opcode not yet executed: <ops.tab name>")`, so an unclaimed opcode is diagnosable from the error alone. Detail: `src/families/CONTEXT.md` and its children.

### Term helpers (`src/terms/`) -- the SAFETY-annotated builder/reader
The crate's single point of raw-heap access, over the `alloc_words`/`alloc_words_rooted` seam.
Each builder has a **classic** public form (`make_tuple`, `make_cons`, `make_list`, `badmatch_reason`, `make_heap_binary`, `make_float`, `make_integer`, `make_flatmap`, `make_map`, `make_fun`) allocating through plain `alloc_words` with materialized operands -- the frozen cross-crate signature `beam_rt`/`tests/**` consume, so **do not rename or re-signature** -- and a **`*_rooted` twin** reserving the block **before** reading operands (the reserve -> read -> write discipline). **Every in-crate construction arm uses the rooted twin**; `src/slack.rs` is the reserve/bump-carve and `src/sink.rs` the shape writer for a multi-node graph without a second allocation.
`make_map` builds any size: flat at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys, else a HAMT, duplicates last-wins. Readers take no `ctx` and answer `BadArg` on a wrong type or index, never panic; `map_entries` walks both map layouts.
`fun_arity` is the 8-bit header field (saturating at 255), `fun_true_arity` an external fun's real arity; `fun_local_key` is the `(uniq, index)` identity **both** encodings of one lambda share (`BadArg` for an `EXPORT_EXT` fun), so a `make_fun3` closure and a `NEW_FUN_EXT` image resolve with ONE lookup. Full API: `src/terms/CONTEXT.md`.

### Literal-area words -- a literal is passed BY REFERENCE (`Operand::Literal`)
Every resolution is a **single-word read** out of the module-owned area; the engine never rebuilds or copies a literal. `beam_loader::LiteralArea` decodes the `LitT` payloads once at load into a private `beam_alloc::Heap`, ORing `TAG_LITERAL_PTR` into every BOXED/LIST word and root.
The doors are `Machine::literal` and `Module::literal`, bound per **module context** (`literals`/`entry_literals`, re-bound by `switch_context`/`enter_run`), because the operand carries only an index. Writing a literal word into a **new** object stores the tagged pointer verbatim; a literal is never a destination, and an in-place write into a literal-area object is refused by `beam_term::is_literal`.
The baseline JIT emits a guarded raw load behind the same bounds check, baking only the index and re-reading the base from the published `JitRuntime` (a cached module's area may be a different allocation).
Consumers test the bit, never a registry, and comparisons need none (`cmp` dereferences). Host-side: `copy_struct` **shares** a literal, both collectors leave a literal pointer verbatim **by address range**, and `beam_rt`'s root/walk classifier rejects it by the bit.

### The JIT tier seam (`src/jit/`)
- **Tier selection.** `Tier { Interpreter, BaselineJit, Cranelift }` (`Tier::ALL` = roster order, interpreter first) with `name()`/`from_name()`/`is_available()`; `available_tiers()` = `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` with the feature.
  The **baseline tier is the default for every `beam_rt` process entry**, compiled lazily per function so a fresh process pays only the functions it enters; `BEAM_RT_TIER=interpreter` is the kill switch.
  Cranelift needs `BEAM_RT_TIER=cranelift` **together with** `beam_rt`'s `cranelift` feature; without the feature an explicit request is a typed refusal naming the feature, never a substitute tier.
- `pub trait JitBackend`: `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx)` (artifact is caller-owned, hence `&self`); plus the provided `run_export`. The interpreter is deliberately **not** a `JitBackend`.
- `Machine::run_with_tier` is the non-blocking tier entry; the `*_with_tier` outcome/resume twins re-enter a suspended slice on the SAME tier (so the tier survives a `receive` park) and `resume_outcome_with_tier` resumes on **every** tier through the no-reset seam `jit::baseline::run_native_resume_outcome`.
- `jit-cranelift` (default OFF) gates the optional deps (off => **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier; `tiering.rs`'s `TierPolicy` models *interpret -> baseline -> hot* escalation as a **policy only**.
- `src/jit/cache/` is the cross-run compiled-block cache keyed by `CacheKey` = `ModuleKey` (load-time MD5, else an IR fingerprint) **plus** `Module::atom_table.snapshot()`; two loaded copies of one `.beam` are two entries -- an extra compile at worst, never a wrong answer. `baseline_code_map(&Module)` feeds a host's `+JPperf` map.
- Block ABI, register picker, artifact layouts, continuation sub-blocks and the inlined shape set: `src/jit/CONTEXT.md`, `src/jit/baseline/CONTEXT.md`, `src/jit/baseline/inlineset/CONTEXT.md`, `src/jit/baseline/emit/CONTEXT.md` (authoritative).

### The execution-census instrument (`src/exec_census.rs`)
**Measurement-only**: on no execution path, changing no result, one thread-local `bool` load per hook while disabled. Surface: `enable`/`disable`/`is_enabled`, `reset`, `snapshot()`, `write_dump(section)`, `variant_name(&Instr)`.
**One recording site:** `Machine::step_instruction_inner` (shared by the interpreter's `drive` and the native tiers' deopt helper) calls `on_instruction` before the body and `on_error` only on an `Err(BeamError)` -- so a raising instruction counts as both, a caught raise as executed only, a **natively-inlined JIT instruction is not observed** (pin `Tier::Interpreter`), and a pre-emption is an error of the instruction it parked on. Blind spots: `MEASURED.md`.

### Error interop (`src/error.rs`)
Constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what)` (a `Raise` whose reason atom is `unsupported_opcode: <what>`), `bad_register(n)`/`unknown_label(l)` (`BadArg`), `blocked()` (what the non-blocking entries surface for a `receive` that would suspend) and `suspended()` (the same for a `BifOutcome::Suspend`).
`Step::Enter` runs on the native baseline tier as a **driver-mediated context switch**, a round-trip by design: a seal-time cross-module link is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`).

## Execution model (frozen semantics -- reproduce, don't reinvent)
Per-instruction/per-operand/per-family detail with the `ops.tab`/`beam_emu.c` references: `INSTRUCTION_SURFACE.md`'s `## Execution model`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, root set `x[0..live)`, plus the FR file; `allocate*` pushes a typed-`Continuation` CP slot then the Y slots (`y(k)` = the slot after it); the bottom `Halt` yields `x(0)`. A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason.
- **The dispatch loop** owns the `(func, pc)` position, the module context those indices belong to and the literal binding, folds every `Step` back into it, and charges one reduction per instruction. `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every executed opcode has its own typed IR variant (the residual `Instr::Generic` sentinel is a named typed error).
- **Failure semantics.** A `gc_bif`/`bif` error with a live `fail` label is a guard branch, with `NO_FAIL` a raise; `bif0`/`call_ext*` carry no fail label, so every error there is a raise. `FuncInfo` is **not** a no-op -- a failed head clause raises class `error` with the bare atom `function_clause` (C's `i_func_info_IaaI`).
- **Raising and catch frames.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + owning call frame + module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), reporting `Goto` or `Enter`; with no live frame or an unresolvable class atom it stays `Err(BeamError::Raise)`. A raise *reads* the entry but never pops it, and class atoms come from the running module's table via `atoms`, never a *different* atom.
- **A frame's continuation slot is consumed by whoever follows the address**, so a derived stacktrace names a returned caller only while it is still live: `Machine::take_continuation` reads the CP slot and resets it to `Continuation::Halt` in the same step (C's `RETURN()`), and a raise landing in a frame's catch handler clears that frame's slot too.
- **A supplied trace is a TERM; a derived trace comes from `raise_snapshot`.** `sys_core_fold` rewrites `catch C:R:S -> erlang:raise(C,R,S)` into `Instr::RawRaise`, so that arm reads `x(2)` (an enclosing landing published the cooked list there) and, when it is `NIL`, cooks the preserved snapshot chain **once** (rooted), then hands it to `Machine::raise_supplied`, whose one-shot latch `throw_with_trace` promotes to the live term instead of rebuilding the snapshot -- so the re-raised chain survives and **no re-raise-site frame is prepended**.
  A **landed** raise publishes that term as the handler's `x(2)`; an **uncaught** one renders the preserved chain through `with_uncaught_frames`. `symbolic_stacktrace` returns an already-cooked list from the trace register verbatim (C's `is_raised_exc`), then supplied symbolic frames, then the snapshot. The two `Option<StackTrace>` latches are metadata, the two term latches need no rooting, and `reset` clears all four. Detail: `src/families/exceptions/CONTEXT.md`.
- **Every tier decorates an uncaught raise**: the funnel runs on the interpreter's `drive`, and the baseline tier's three raise-carrying helpers (`jit_family`, `jit_bitstr`, `jit_test`) run it **unconditionally** with the true `entry_module` (their blocks never pass through `step_instruction`).

### Hot-path cost model (`test_heap` / `put_list`, default baseline tier)
Both are helper-call shapes: one `emit_helper_call` (dirty-set spill, `mov rdi,[rsp+RUNTIME_SLOT_DISP]`, one `movabs` per argument, `movabs r11,helper`, `call r11`) plus `emit_continue_check`.
`test_heap` -> `jit_test_heap` -> `Machine::ensure_heap` -> `with_roots` -> **one** `ensure_heap_full` virtual call; `put_list` -> `jit_family` -> the direct `lists::put_list` fast path -> `make_cons_rooted` -> `reserve` -> `Machine::alloc_rooted` -> **one** `alloc_words_rooted` virtual call, no Rust heap allocation per call.
**No heap-admission memoisation exists**: `heap_available` has no call site and there is no `if need <= cached` fast path, so every `test_heap` crosses the host door unconditionally -- which is why `with_roots`'s no-loose-term path is minimal (no allocation, no lock, two unconditional dirty-extent stores, one folded predicate test). Numbers: `MEASURED.md`.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError`; the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: construction/inspection only via `beam_term`, comparison only via `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- **The ROOT-SET contract is the hardest invariant**: `x[0..live)` + **the whole Erlang stack** + the whole FR file + the five parked loose terms, **NO frame liveness maps**; nothing outside it survives a collecting allocation.
- **DEOPT IDEMPOTENCY (the baseline tier's inline set).** A `fallback` is a **deopt**: `jit_step_one` re-executes the whole instruction with the same operands, so no inline arm may commit **any** machine state before its last fallback, and an arm that allocates or roots *inside* the instruction must **decline** rather than allocate mid-instruction.
  Concretely `bs_match` commits the match context's `start` word exactly once per path (never per command), and `bs_create_bin` commits its accumulator's window end **last**, after every payload store, with every door it calls mutating nothing -- so a post-payload deopt re-writes the same bytes at the same offsets.
  Pinned by `src/jit/baseline/{bs_match_deopt_tests,bs_create_bin_tests,bitstr_shapes_deopt_tests}.rs` (tier agreement + literal expectation + a once-only side effect + the emission instrument) and by `foreign_kernel_tests.rs` comparing the four `foreign` kernels' **outputs** on both tiers and the live oracle.
- **`unsafe` confinement.** `#![deny(unsafe_code)]` (`#![warn(missing_docs)]`); `unsafe` only in `src/predicates.rs`, `src/terms/*`, `src/families/bitstrings/raw.rs`, `src/families/records/raw.rs`, `src/jit/emitter/mod.rs` (the crate's **only** executable-memory mapping), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*`, feature-gated `src/jit/cranelift/mod.rs`, and `src/context.rs`'s region heap + `src/context/reclaim.rs` -- each `unsafe` block with a `// SAFETY:` rationale.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc`, `beam_gc` (+ `libc`); `cranelift-*` optional. `beam_alloc` serves the off-heap refc-binary payloads, `beam_gc` (wave 1 -> 4, downward, acyclic) the arena's Tier-B compaction.
- **Files ~1000 lines**, split by responsibility; a legitimately long file documents why. Licensing Apache-2.0.

## Known Issues (each a typed result, never a wrong value, unless stated)
Item-by-item ground truth: `INSTRUCTION_SURFACE.md`'s `## Known Issues`.
- **Pre-emption exists; scheduling does not.** The `reduce` hook is charged by both drivers; run queues, the scheduler and trap handling are Stage 5 (`beam_process`).
- **Records -- two open divergences.** The whole native-record set executes and `PutRecord`'s create form works for the module's own `Recs` and for a foreign `{Module,Name}` id. Open: `is_record_accessible`'s wildcard arm compares the definition module against the `Scope` **operand** where `emu/ops.tab:1675` substitutes `$MODULE`, and `put_record`-update / `update_record_id` / `get_record_field` raise `function_clause` where the C's `NO_FAIL` path raises `{badfield,…}`/`{badrecord,…}`. Detail: `src/families/records/CONTEXT.md`.
- **Bitstrings.** `bs_init_writable` builds 0 bits over a capacity-carrying refc payload (the `x(0)` hint, else `DEFAULT_WRITABLE_SIZE = 1024`) registered writable on the machine; a first-position `private_append` appends **in place** and an outgrown payload grows (amortised); every other shape promotes to the byte-identical copy-rebuild. Residuals are typed only (no term-level `BIN_FLAG_WRITABLE`/`_ACTIVE_WRITER`, no shrink-on-escape, unmodelled `binary:referenced_byte_size/1`). Detail: `src/families/bitstrings/CONTEXT.md`.
- **The bitstring families execute a *prepared* program**, pre-resolved once per `(module image, function, code offset)` (`create/prepared.rs`, `matching/prepared.rs`, a direct-mapped 64-slot cache keyed on the image's owner word); a declined shape is `Program::Generic` running the unchanged generic walk, so the typed-error surface is identical. The tables are machine-owned and reached through `Machine::with_bitstr_programs`. Detail: `src/families/bitstrings/CONTEXT.md`.
- **Contract A.9 rung L4 compiles `beam_flatten.erl` with the tree's own OTP-30 `compile.beam` and the emitted `Code` chunk is byte-identical to the OTP-29 `erlc` oracle's apart from one byte** -- the 17-byte artifact diff is `beam_dict:highest_opcode` (`reject_unsupported_versions/1` bumps it to `executable_line/2` = 183) plus the derived `-vsn`. The rung's "artifact DIFFERS" verdict is a **rung-baseline artefact** (two compiler versions compared byte-for-byte), not a runtime divergence.
- **L4's throughput, not its correctness, is the open A.9 blocker on this path:** in-process compiling the tree's own compiler sources is ~2 orders of magnitude too slow (a 17.7 KB synthetic 300-function module ~8.9 s vs `erlc`'s 0.20 s; `beam_ssa_dead.erl` 55 KB and `beam_types.erl` 75 KB exceed 150 s; `v3_core.erl` 193 KB exceeds the 900 s `BLOCKING_PUMP_DEADLINE`). Records are not the cause, and `v3_core.erl` is not oracle-comparable (the OTP-29 `erlc` rejects it).
- **Printing a native record is the wrong debugging instrument here.** `io_lib:format/2,3` is a `beam_bifs` native fast path (no `io_lib` frames in a trace) and its renderer has no `RECORD_SUBTAG` arm -- it falls through to `Err(badarg())`, so `~w`/`~p`/`~P`/`~tp` of a **native record** raises a bare `badarg` even though the real `io_lib_pretty:print/4` renders it. Print a shallow tag (`element(1,E)`-style) instead.
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order, and a `NO_FAIL` failure of `test`/`select_val`/a map read raises class `error` with the bare atom `function_clause` from the running module's own table.
- **A map `is_eq_exact` costs O(k log k) and two heap `Vec`s per comparison** (no map fast path in `eval_test`). Detail: `src/families/maps/CONTEXT.md`.
- **Small-int arithmetic (`+ - *`, `band`/`bor`/`bsr`) is inlined only by the native baseline tier**; the interpreter has no arithmetic fast path -- every `gc_bif` goes out through `exec_bif` -> `call_bif`. Compiled arithmetic is oracle-exact on overflow (`+ - * div rem` promote to exact bignums, as does an out-of-range integer operand).
- **A captured stacktrace is engine-derived unless the raise supplied one**, and nameable atoms are required (`catch_end` needs `EXIT`). **Uncaught** frames exist only for a `BeamError::Raise` -- `beam_common`'s fieldless reason variants carry no `StackTrace` slot.
- **A supplied EMPTY trace is indistinguishable from "no trace supplied"**, because `beam_common::Raise` carries no supplied-trace flag: `erlang:raise(error, boom, [])` equals a raise with no trace, so the engine cooks the derived chain where the oracle keeps `[]` (C's `is_raised_exc`).
  The fix is a `supplied_trace: bool` on `beam_common::Raise` plus two engine hunks; the engine plumbing is in place and the gap is **owned by the sibling `beam_common` node**. Pinned by `tests/raise_with_trace.rs::an_empty_supplied_trace_is_byte_identical_to_no_supplied_trace`.
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by this crate's opcode coverage; those crates are `beam_bifs`/`beam_rt`.
- **A synthetic module's never-cached label map costs one `Arc` allocation per `run_*` entry** (~+16 % of the `engine_bench` `setup/empty` floor); a real module (load-time digest) never takes that route.
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never raw memory** (`refc_binaries` + `send_message_with_off_heap`); `retain_refc_binaries(keep)` drops the handles a reachability predicate rejects and `off_heap_overhead_bytes()` reports the bytes feeding `beam_gc::BinVheap::triggered`.

## Memory footprint & heap wiring (figures in `MEASURED.md`)
**Nothing is freed except by a `Drop`**; the arena's regions are the one case a host can trigger that drop early.
- **Arena** (`MinimalContext`): a `Vec<ReservedHeap>` grown by `push`, trimmed only by `heap_rewind`/`reclaim_heap`. First reservation `HEAP_RESERVE_WORDS` = 4 MiB / 524 288 words with 64 KiB committed, each later region **double**; a region is one carrier `mmap`, lazily faulted, **nothing zero-fills it**, so RSS tracks the words handed out. `heap_available` = `usize::MAX`, `ensure_heap` a no-op, no collection.
- **`Machine`:** the two 1024-word register files are 8 KiB each, allocated eagerly; every other vector (`stack`, `frames`, `catch_frames`, `contexts`, `refc_binaries`, `args_scratch`, `label_maps.entries`) is `clear`/`truncate`d and **keeps capacity**, so the resident footprint is the high-water mark of the heaviest run. The label-map LRU is 32 entries per machine, each pinning its `Arc<Module>`; the host's pool holds up to 32 machines.
- **Baseline JIT:** one `CodeBuffer` per compiled function sized `function_capacity_estimate + sub_blocks + DEFAULT_CAPACITY` (64 KiB) rounded to pages, plus `entries`/`sub_entries` tables (16 B per instruction) and the label map. The per-thread `CODE_CACHE` has **no eviction** and `clear_baseline_cache` has **no production caller** (tests only), so on a long compile the emitted-code figure is monotone and this is the crate's largest resident accumulator.
- **Lowered IR** (`beam_loader::Module`): `Instr` pinned at 64 bytes, line table 8 B per instruction, a block 24 B -- roughly 72-80 KB per 1000 instructions; a label map is 8 B per label, **built per machine**.

### The arena is measurable and reclaimable on the host's terms
`beam_rt::Runtime::arena` is the production instance; `MinimalContext` reaches the heap through **three** methods only (`ensure_heap` no-op, `heap_available`, `alloc_words`) and does **not** override the rooted doors, which default onto `alloc_words` with roots discarded.
Tier A (`heap_rewind`) drops every region above the mark (the only path that releases a carrier `mmap`) and resets the survivor to `mark.used`; Tier B (`reclaim_heap`) builds a `beam_gc::FromSet` from the region grid, deposits a Cheney copy into a destination `ReservedHeap` reserved at the copy bound, then installs the survivor as the sole region. A post-copy memcpy into a right-sized survivor would be **unsound** (the relocator writes the destination address into every copied child slot), and `ReservedHeap::relocate` stays unused.
**Every refusal is decided before the first copy**: `BadArg` for a stale/foreign/forward mark, `heap_exhausted` for an undersized destination, `Ok(None)` when nothing is worth doing; an `Err` from the host's `forward` leaves the arena **defined empty**; both success paths bump the epoch. **`reset` alone reclaims no RSS** -- which is why both tiers *drop* regions; `args_scratch` and `refc_binaries` stay outside every root door.
`ContextHeap` has no per-allocation metadata, so `for_each_heap_region` hands out raw words only and the real tier relies on `beam_gc`'s canonical object sizing rather than a conservative word scan (`beam_gc`'s walker has none). The crate's second relocating heap is test-only (`terms/alloc_tests.rs`'s `MovingContext`). A nested-run watermark rewind does **not** bound the in-process-compile workload (the whole demand is spent inside one run). Detail: `src/context/CONTEXT.md`.
**The one production move-and-republish path is the writable-binary payload**, not a heap region: `raw::InPlace::grow` -> `Machine::grow_writable_payload` -> `republish_over` rewrites **exactly the two words naming the payload** (`BinRef.val`, `ErlSubBits.base_flags`) plus the registry key -- two independent writers at each block's own live address, no adjacency assumed, canary-proved in release by `bitstrings/raw_tests.rs`. It refuses when `payload_aliased_elsewhere` finds a second on-heap naming pair: reachable references enumerated, unknown holder => refuse.

### Heap admission & allocation wiring (the exact engine->host doors)
- **`test_heap`/`allocate_heap` -> `Machine::ensure_heap` -> `ensure_heap_full`** with the whole `RootSet` (x, stack **and fr**); the interpreter's two arms and the native tier's `jit_allocate_heap`/`jit_test_heap` are the only call sites and **the two tiers do not differ**, so a collecting host sees one admission point per execution with the same operands. The narrow `ensure_heap` has no engine call site; the `test_heap Live` operand is only a hint.
- **`Instr::Allocate` makes no heap request at all** (frame-only), which also skips C's heap check (C's `allocate` can collect) -- a conservative divergence; `gc_bif`/`bif`/`bif0`/`call_ext*` likewise leave term allocation to the host's `call_bif`.
- **All term allocation goes through `terms::reserve` -> `Machine::alloc_rooted` -> `alloc_words_rooted`** with the same full `RootSet`. The JIT **never inlines an allocation**: those opcodes are family-owned and routed to `jit_family`, one Rust call-back per built term on both tiers.
- **The one unrooted runtime allocation** is a non-small `Operand::Integer`/`Character` operand (`make_integer_unrooted` -> `ctx.alloc_words`); the classic `make_*` builders are `beam_rt`'s/tests' API, not the engine's own arms.
- **The engine makes no collection decision**: `arm_gc`, `should_collect` and `collection_debt` do not occur in this crate -- latch, occupancy test and collector are `beam_rt`'s; the engine's only capacity input is the `heap_need`/`n` it passes.
- **The off-heap `refc_binaries` resident figure is the host's reclamation cadence, denominated in reductions.** The reservoir is released only by a host decision (`retain_refc_binaries`, at `beam_rt`'s slice-boundary park), and a host slice is a fixed reduction budget (`beam_common::CONTEXT_REDS` = 4 000). This crate decides how many charged reductions work costs: the **refusing** seams are the `test_heap`/`allocate_heap` doors and `reduce` on an instruction handed back to the interpreter; a block that runs natively and reaches no admission door is charged **nothing** -- so the cheaper a loop becomes, the **more iterations one slice spans**, and a host pruning per slice retains proportionally more (a **bounded per-slice window, not a leak**).
  No rooting rule may be relaxed to shrink it: only the reachability walk tells a dead payload from one a live term names, and it needs the process's complete root set, which exists at the host's park.

### Heap-region ownership & invalidation
The engine owns exactly four kinds of raw memory: the arena's regions, the `Machine`'s word buffers, the off-heap `RefcBinary` handles (`refc_binaries` + `writable_payloads`), and the baseline tier's executable `CodeBuffer` mappings.
- **One `Drop` impl outside test code: `CodeBuffer`** (`munmap`); `ContextHeap`, `MinimalContext` and `Machine` have none, so the grid frees only when its `MinimalContext` drops and a machine's buffers only when the machine drops.
- **`Machine::reset` is logical, and only at a slice START** (`run_label_outcome`): it clears frames/catch frames/`contexts`/`local_callees`/`raise_snapshot` and refills the register files only when their length changes, and never touches `refc_binaries`/`writable_payloads`/`label_maps`. `resume_outcome` does not reset at all; an unwind only `truncate`s (capacity kept).
- **The arena's grid is registrable in `beam_gc::FromSet` only from inside `ContextHeap`** (no per-region pair in `ContextHeapStats`; no containment predicate on `ReservedHeap`/`Heap`), so `reclaim_heap` builds the from-set itself and hands the caller only the `Relocator`; the collector's substitute is `beam_rt`'s decline valve.
- **A returned `Eterm` may be a `TAG_LITERAL_PTR` word into the module's `Arc<LiteralArea>`**, and `reset` drops the machine's bindings, so it stays valid only while some `Arc<Module>` clone survives; nothing here enforces that.
- **A term produced in a `MinimalContext` arena dies with that context**: dropping it returns the carrier blocks to `beam_alloc`'s PROCESS-GLOBAL segment pool, where the next arena writes over them. Reading it afterwards is a use-after-free surfacing as a **wrong value** or the `invalid boxed header subtag` abort -- never a typed error; a test comparing terms from two runs must keep **both** hosts alive.
