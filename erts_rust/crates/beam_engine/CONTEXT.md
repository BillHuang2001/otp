# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step (interpreter-identical semantics), carrying **two layouts behind one `CompiledModule`** (an eager whole-module artifact and a lazy per-function artifact the runtime path uses, so a fresh process pays only the functions it actually enters).
The **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) is one Cranelift function per IR function over the same shared interpreter-backed helper.
All tiers are **measurement-gated** and off the critical path (Part II sec. F) -- correctness-first *mechanisms*, not optimisers.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end, with explicit dispatch arms for the core opcodes and a per-instruction-family seam (`src/families/`) for the rest.
The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC, process/stack limits and pre-emption all sit behind `ExecutionContext` (implemented by `beam_rt`), keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

**Where the detail lives.** This file is the crate-level *contract*: the frozen API seam, the binding execution semantics, the constraints, the test strategy, and summaries of the gaps/handoffs. The exhaustive per-opcode/per-operand/per-family surface, the engine's design decisions and the full M1 gap list are in `INSTRUCTION_SURFACE.md`; the subsystem detail is in the child `CONTEXT.md` files under `src/` (routing table below).

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: computation goes through `ExecutionContext::call_bif`, and an in-machine callee through the resolver seams (`resolve_external_call`/`resolve_local_fun`), with `ExecutionContext::apply`/`apply_fun` the value-returning fallbacks.

### The context seam (`src/context.rs`)
The frozen seam shape (default bodies shown as comments; the source is authoritative):
```rust
pub trait ExecutionContext {
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;
    fn ensure_heap_full(&mut self, heap_need: u32, roots: RootSet<'_>) -> Result<()>;         // default: forward to narrow ensure_heap
    fn heap_available(&self) -> usize;                                                       // default: usize::MAX
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;
    fn alloc_words_rooted(&mut self, n: usize, roots: RootSet<'_>) -> Result<*mut Eterm>;      // default: forward to alloc_words
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
    // nine defaulted Mailbox twins (send_message / receive_*); see the mailbox section below.
    fn send_message_with_off_heap(&mut self, to: Eterm, message: Eterm,
        src_binaries: &[beam_alloc::RefcBinary]) -> Result<()>;                                // default: forward to send_message
    fn resolve_external_call(&mut self, module: &str, function: &str, arity: u32)
        -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>>;                      // default: Ok(None)
    fn resolve_local_fun(&mut self, fun: Eterm, args: &[Eterm])
        -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>>;                      // default: Ok(None)
    fn reduce(&mut self, n: u32) -> Result<()>;                                                // default: no-op
    fn wants_reduce(&self) -> bool;                                                            // default: true (conservative)
    fn trace_enabled(&self) -> bool;                                                           // default: false (contract A.8)
    fn trace_event(&mut self, event: TraceEvent<'_>);                                          // default: no-op
}
/// The engine's mutable root set -- the hand-off `alloc_words_rooted`/`ensure_heap_full` receive.
pub struct RootSet<'a> { pub x: &'a mut [Eterm], pub stack: &'a mut [Eterm],
                         pub fr: &'a mut [Eterm], pub live: u32 }  // `live` clamped; ALL_LIVE = u32::MAX
pub enum TraceEvent<'a> {
    Call { module: &'a str, function: &'a str, arity: u32, args: &'a [Eterm] },
    ReturnFrom { module: &'a str, function: &'a str, arity: u32, value: Eterm },
    ReturnTo { module: &'a str, function: &'a str, arity: u32 },
}
```
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- **The GC root-set contract, in two doors.** `ensure_heap(heap_need, live, x_regs, stack)` is the frozen **narrow** admission point; `Machine::ensure_heap` (reached by `test_heap`/`allocate_heap`) calls the defaulted **`ensure_heap_full(heap_need, roots)`** over the whole [`RootSet`] (**including the FR file**, which holds `Eterm` term slots), whose default forwards to the narrow door (byte-identical for a host that predates it). `alloc_words_rooted(n, roots)` is the **term-construction** admission door (`alloc_words` itself has neither an admission point nor roots); its default discards the roots and forwards to `alloc_words`. A collecting host overrides both, relocates every term reachable from the roots, and writes moved terms back through `roots.x`/`roots.stack`/`roots.fr`. The frozen contract: the live roots are `roots.x[..roots.live_len()]`, **the whole** `roots.stack` (every Y slot of every live frame -- no frame liveness maps) and **the whole** `roots.fr` (a float register holds a term slot); `live` is only a hint (`RootSet::ALL_LIVE` is always *safe*). Nothing outside the root set survives: a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation.
- **The engine side of that hand-off is `Machine::with_roots` / `Machine::alloc_rooted`.** `with_roots(live, f)` lends the machine's own three files as one disjoint `RootSet`; **every in-crate term-construction arm routes through this seam** via the `terms::*_rooted` builders (the only `alloc_words` caller left is the four `&self` accessors in `src/machine/location.rs`). Detail: `src/terms/CONTEXT.md`, `src/CONTEXT.md`.
- **`reduce(n)` is the per-instruction reduction hook** (defaulted no-op). `Machine::drive` charges it **once per interpreted instruction** with `n = 1`, **before** the body runs, so a host with a scheduler enforces a time slice by returning a **typed error** -- the instruction is left **un-applied** with the machine parked on it, so a `Machine::resume_outcome` applies it **exactly once**. It is the only pre-emption point a **non-allocating** loop reaches. `wants_reduce` latches the decision once per run (a host that implements `reduce` MUST stay `true`); `Machine::reductions()`/`reset_reductions()` expose the slice count. There is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption a fresh `drive`. Detail: `src/machine/CONTEXT.md`.
- `apply` is the general synchronous `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the **value-returning fallback** for `call_fun`/`call_fun2` (default a typed `unsupported` -- the engine keeps no closure registry), consulted only after `resolve_local_fun` declines, entering the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables (C's `call_fun` order). Both seams' and the fallback's errors route through `Machine::raise_bif_error`, so a routable raise lands in the caller's live `try`/`catch`.
- **`resolve_external_call` -- the cross-module call seam (the `call_ext*` and dynamic `apply` route).** A host that owns loaded modules answers `Some((callee_module, entry_label))` for a `call_ext*` or `apply(M,F,A)` and the engine executes the callee **in the same machine** (so a `receive`/raise inside it suspends/raises this process, instead of routing through the synchronous `call_bif`); `callee_module` must be the **shared** `Arc<Module>` the host loaded it with (contexts dedup by `Arc::ptr_eq`), and `entry_label` is the export entry label (`callee_module.export(function, arity)`, the label *after* `func_info`). Default `Ok(None)` keeps the `call_bif` path. See Handoff #10.
- **`resolve_local_fun` -- the in-machine closure-apply seam (the `call_fun`/`call_fun2` route).** Consulted **first**: a host that owns the closure's defining module answers `Some((callee_module, lambda_entry_label))` and the engine enters the lambda body in this machine, copying the closure's free variables into `x(arity..)` (C's `reg[i + arity] = funp->env[i]` order) and reporting `Step::Enter`; a `receive`/raise inside the closure then suspends/raises this process. Default `Ok(None)` keeps the `apply_fun` fallback (for fun kinds with no local label: an external `fun M:F/A`, the `-eval` evaluator's closure). See Handoff #12.
- **`call_ext*` special cases (`Machine::resolve_call_ext_apply` / `resolve_call_ext_send`).** The three arms special-case the import `erlang:apply/3` (reproducing C's `fixed_apply` -> `apply()`: decode `x(0..2)`, unwrap the nested `apply of apply/3` shape in a loop, walk the argument list into `x(0..N)` -- past `MAX_ARG = 255` is `error:system_limit`, a non-proper tail the catchable `badarg`) and `erlang:send/2`/`'!'/2` (routed through `send_message_with_off_heap` with the machine's off-heap handles). **Only `apply/3`** is special-cased (matching C, whose `fixed_apply` handles only `arity == 3`); `erlang:apply/2` stays on the ordinary `call_bif` route. Detail: `src/interpreter/CONTEXT.md` (`call_ext_dispatch`, `ImportFrame`).
- **Contract A.8 execution-trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}` / `return_from` / `return_to` shapes; the engine **reports only** -- the host owns matching (`beam_rt`'s `PatternTable::matches`) and term building. Emission (`src/interpreter/trace.rs`, gated on `Machine::trace_on`): `Call` for a local callee on `call*` and for an import on `call_ext*` (**entry only**); at a live `Continuation::Address` return, `ReturnFrom` then `ReturnTo` (a `call_only`/`call_last` chain's `ReturnTo` names the **original** caller). Emission is infallible, so a traced run is byte-identical to an untraced one; **a natively-executed JIT block does not trace**.
- `pub type BifHook`/`ApplyHook`/`ExternalResolver`/`LocalFunResolver` -- the pluggable bodies a `MinimalContext` installs via `with_bif_hook`/`with_apply_hook`/`with_external_resolver`/`with_local_fun_resolver` (and the matching `set_*`).
- `MinimalContext` -- the test/embedding context: an unbounded heap, a **pluggable BIF hook** (`new()` rejects every BIF), an **optional apply hook**, **optional cross-module/local-closure resolvers** and an **optional mailbox**. Its heap is a pointer-stable **reserved-heap** arena -- a large address range reserved up front and **grown in place** as terms are built (so an allocation costs its payload only); on exhaustion a fresh, larger region starts and **every earlier region is kept alive**, so a handed-out pointer stays valid and **unmoved** (`relocate` is deliberately never used). It does **not** override `alloc_words_rooted`, so it stays the test/embedding heap rather than a collector. Detail: `src/CONTEXT.md`.

### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
```rust
pub trait Mailbox {
    fn send_message(&mut self, to: Eterm, message: Eterm) -> Result<()>;
    fn receive_next(&mut self) -> Result<Option<Eterm>>;   // candidate at the scan position (None = exhausted)
    fn receive_skip(&mut self) -> Result<()>;              // loop_rec_end (advance one)
    fn receive_remove(&mut self) -> Result<()>;            // remove_message (unlink the candidate, reposition at first)
    fn receive_reset(&mut self) -> Result<()>;             // timeout (reposition at first)
    fn receive_marker_reserve(&mut self) -> Result<Eterm>;
    fn receive_marker_bind(&mut self, marker: Eterm, reference: Eterm) -> Result<()>;
    fn receive_marker_use(&mut self, reference: Eterm) -> Result<()>;
    fn receive_marker_clear(&mut self, reference: Eterm) -> Result<()>;
}
```
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")`, so every implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- **The engine never inspects a message or a marker**: selection is the compiled code's job (the matching instructions between `loop_rec` and `loop_rec_end`), and a marker term is **opaque** (produced by `receive_marker_reserve`, handed back verbatim by `receive_marker_bind`; only a separate *reference* reaches `receive_marker_use`/`receive_marker_clear`). Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still surface the typed `error::blocked` (Handoff #1).
- **`send_message_with_off_heap(to, message, src_binaries)`** is the `Instr::Send` arm's entry **and** the `call_ext*` `erlang:send/2`/`'!'/2` case's entry: a tenth defaulted `ExecutionContext` method whose default **forwards to `send_message` and discards `src_binaries`**, so every existing implementor is byte-identical. `src_binaries` is the **source off-heap table** the receiver-side copy needs to resolve an engine-built off-heap (refc) binary in the message (a `bs_init_writable`/`bs_create_bin` result over `beam_term::refc::ERL_ONHEAP_BINARY_LIMIT` bytes). See the off-heap Known-Issues bullet.
- **Ordering invariant (the host contract this driving relies on).** `receive_skip`/`receive_remove`/`receive_reset` take **no candidate argument** -- the host acts on its **own** persistent scan position (`receive_remove` unlinks whatever is at that position, NOT the term the engine read into `Dst`) -- so the driving is correct only while that position is stable between the `loop_rec` that produced a candidate and the `remove_message`/`loop_rec_end` that consumes it; that holds by construction (between those two the engine issues no other seam call and never blocks). A `receive` reaches `wait`/`wait_timeout` **only** via `loop_rec`'s `None` arm (the scan is already **exhausted**), so a `resume_outcome` re-entry sees only messages appended since. Host contract: FIFO with a **saturating** scan index (`beam_message::QueueCursor` + `beam_rt::MailboxState`). Detail: `src/families/CONTEXT.md`, `tests/receive.rs`.

### The machine (`src/machine/{mod,registers,frames,catch,run,location,context,drive}.rs`)
`Machine` is the process-state core: the x-register file (`MAX_REGISTER = 1024`, C's `MAX_REG`), the float-register (FR) file (`MAX_FLOAT_REGISTER = 1024`, holding **`Eterm` term slots**), the Erlang stack, the call-frame and exception catch-frame stacks, the `refc_binaries` arena (never cleared by `reset`), the running module's decoded **literal area**, the **module-context registry** (`contexts` + `context` + `entry_literals`), the reduction counter, the **raise-time snapshot** `raise_snapshot`, and the latched A.8 gate `trace_on`.
- **Run entries (`run.rs`).** `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware; `RunOutcome { Returned(Eterm), Wait { func, pc } }`), plus the tier-aware `run_with_tier`/`run_export_outcome_with_tier`/`run_label_outcome_with_tier`/`resume_outcome_with_tier`. `run_export` resolves `function/arity`'s export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return`, yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error. The loop is `run_loop`/`run_loop_with_map` (`src/interpreter/dispatch.rs`), thin wrappers over `Machine::drive`.
- **The uniform raise funnel (`catch.rs`).** `throw`/`throw_error`/`throw_with_trace` are the raise/unwind entries the families call; `throw_with_trace` first **rebuilds the raise-time frame snapshot** (the **raising** frame from `current_code`/`current_context`, then every live caller innermost-first, each in its own module context) *before* any unwind, so it survives on **both** the caught and the uncaught path. The symbolic `StackTrace` an **uncaught** raise carries is attached not at the raise site but by the single funnel `Machine::with_uncaught_frames(err, entry_module, func, pc)` as the raise leaves the machine (at the `step_instruction`/`drive` boundary), so **every** raise kind gets the same frames -- only when `raise.stacktrace.is_empty()` and the reason is not an engine diagnostic. A **caught** raise carries no symbolic trace; the same raise-time snapshot is what `Instr::BuildStacktrace` cooks into the `try … catch C:R:S` binding.
- **Module contexts (`context.rs`).** A `call_ext*` the host resolved through `resolve_external_call` executes the callee **in this machine**, so `(func, pc)` are indices into *another* module's table and the machine must remember which. `Contexts` registers/dedups a `ModuleContext { module: Arc<Module>, labels }` by `Arc::ptr_eq` (context `0` is the run's **entry** module, which the machine never owns -- `entry_literals` records its literal area). `switch_context(id)` re-binds `literals` and an unregistered id is the typed `error::unsupported`. `reset` clears the set; a **resume does not** (a suspended cross-module frame must still name its module).
- **Introspection (read-only).** `x(n)`/`get_fr(n)`/`fr_mark()`/`y(k)`/`frame_depth()`/`stack_depth()`/`catch_frame_depth()`/`pending_exception()`/`pending_exception_mut()`/`pending_class()`/`resumption_addresses()`/`resumption_contexts()`/`raise_snapshot()`/`wait_deadline()`/`reductions()`/`reset_reductions()`, plus the execution-position accessors (`current_code`/`entry_call`/`current_function`/`initial_call`/`current_location`/`current_stacktrace`/`current_module`, the engine half of `process_info/2`). Per-file roles: `src/machine/CONTEXT.md`.

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func, pc }, Enter { context, func, pc }, Wait { func, pc }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`/context. `Next` = continue at `pc + 1`; `Goto` = jump **within the current module**; `Enter` = transfer to `(func, pc)` in another module context (a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address`, or a raise landing in another context's live catch frame) -- the driver switches context and re-binds the literal area exactly here; `Done` = finish and yield `x(0)`.
- `Wait` is the **suspend** signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto`/`Step::Enter` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which **routes by the instruction's own variant** to the single owning family -- a `match instr` that compiles to a jump table on the `Instr` discriminant. Family ownership is **disjoint** (each of the **77** claimed variants has exactly one owner: `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`).
- Each family exposes `pub(crate) fn exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = "executed", `Ok(None)` = "not this family's variant", `Err` = the family raised. A variant **no** family owns or one a family declines falls to the router's last arm: `error::unsupported("widened opcode not yet executed: <ops.tab name>")` (an unclaimed opcode is diagnosable from the error alone). Per-family variant ownership and gaps: `src/families/CONTEXT.md` and its child nodes.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,slack,sink,alloc_tests,tests}.rs`) -- the SAFETY-annotated builder/reader
The crate's single point of raw-heap access, over the `alloc_words`/`alloc_words_rooted` seam:
- Each builder comes in **two flavours**: the **classic** public builder (`make_tuple`, `make_cons`, `make_list`, `badmatch_reason`, `make_heap_binary`, `make_float`, `make_integer`, `make_flatmap`, `make_map`, `make_fun`) allocates through the plain `alloc_words` and takes already-materialized operands (the frozen cross-crate signature `beam_rt` and `tests/**` consume); its **`*_rooted` twin** takes `machine`/`ctx`/`live` plus a `read` closure and reserves the block **before** reading operands (the frozen reserve → read → write discipline), so a **moving** collector may relocate them in between. **Every in-crate construction arm uses the rooted twin.** `src/slack.rs` is the reserve/bump-carve (`reserve`/`reserve_slack`); `src/sink.rs` is the `Sink` shape writer a multi-node graph is carved from without a second allocation.
- `make_map(ctx, &[(Eterm, Eterm)], atoms)` is the **general map builder**: it reserves `beam_term::map::map_words_capacity(n)` and delegates to `write_map`, so it builds a map of ANY size -- a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys, else a **hashmap** (HAMT) -- collapsing duplicate keys last-wins. Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`, never a panic) cover the tuple/cons/list/float/map/binary accessors plus the fun readers (`is_fun`/`fun_arity`/`fun_num_free`/`fun_uniq`/`fun_index`/`fun_free`/`fun_true_arity`); `map_entries` walks both map layouts; `fun_arity` is the 8-bit header field (saturating at 255) while `fun_true_arity` returns an external fun's real arity. Full API and the `Slack`/`Sink` carve: `src/terms/CONTEXT.md`.

### The JIT tier seam (`src/jit/`)
- `Tier { Interpreter, BaselineJit, Cranelift }` (`Tier::ALL` = roster order, interpreter first) with `name()`/`from_name()`/`is_available()`; `available_tiers()` = `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` when the feature is on.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>` (the artifact is **caller-owned**, hence `&self`); plus the provided `run_export`. The interpreter is deliberately **not** a `JitBackend`.
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`) -- the **non-blocking** tier entries (`Result<Eterm>`; a suspend folds to `error::blocked()`): `Interpreter` -> `run_export`; `BaselineJit` -> `run_baseline_cached`; `Cranelift` -> `run_cranelift` when the feature is on, else the typed `unsupported("jit-cranelift tier not built")`. `run_export_outcome_with_tier`/`run_label_outcome_with_tier` are the **outcome-aware** twins and `resume_outcome_with_tier` the **resume** twin: a slice that suspended re-enters on the SAME tier, so the tier survives a `receive` park (the baseline resume driver does **not** reset the machine and serves a slice parked in a **non-zero module context** too). `Tier::Cranelift` cannot resume at an arbitrary mid-function `pc` (its `CompiledEntries` enter only at a function's entry `pc`), so it reports the honest typed `unsupported` -- never a silent interpreter fallback. A suspend crosses the block ABI as a `WAIT_BIT` word.
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier. `src/jit/tiering.rs`'s `TierPolicy` models the *interpret → baseline → hot* escalation as a **policy only** (nothing on an execution path consults it).
- `src/jit/cache.rs` is the **cross-run compiled-block cache**: the sound key is the private two-variant `ModuleKey` — `Digest([u8; 16])`, the module's **load-time MD5** (`Module::checksum`) for a real `.beam`, read as a plain `Copy` (no hash, no allocation), else `Content { name, fingerprint }`, where `module_fingerprint(&Module)` hashes the module's **decoded IR content** (deterministic, **never a pointer**) for an all-zero-checksum synthetic module; the fingerprint is computed **once at artifact creation** and stored on the artifact, so a cache hit never re-hashes the IR, and `CodeCache`'s address-keyed resolution memo is trusted only while its `Weak<Module>` still upgrades. `baseline_code_map(&Module)` exposes the **real** generated ranges for a host's `+JPperf` map. The cache is per-thread and backs `run_baseline_cached*`/`cached_module_blocks`.
- **The block ABI, the register picker, the two artifact layouts, the continuation sub-blocks and the baseline inlined shape set are documented in `src/jit/CONTEXT.md`, `src/jit/baseline/CONTEXT.md` and `src/jit/baseline/emit/CONTEXT.md`** (the authoritative source). Headline: every un-lowered instruction (or an inline whose run-time guard rejects) **deopts to one interpreter step** (`jit_step_one` == `Machine::step_instruction`), so a tier is interpreter-identical for every supported opcode and the interpreter's exact error surfaces stand; a **traced** run refuses native entry entirely.

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), and `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend.
- **`Step::Enter` executes on the native baseline tier via a driver-mediated context switch.** `call_ext*` is executed natively by `jit_ext_call` (import resolution through the host seam plus the variant's frame discipline); the cross-module *transfer* is not in the JIT inline set, so the resolved target is handed to the driver as a `Step::Enter` (carried out of a block as the `ENTER` block-ABI word). A **declined** import is not resolved twice (`jit_ext_call` forwards its `None` answer through `jit_step_ext` into the shared `Machine::call_ext_dispatch`). The driver switches module context and re-enters the callee's compiled blocks when the tier has them, else its per-instruction step -- a **driver round-trip by design** (a seal-time cross-module link is unsound: separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`). The Cranelift tier inherits `module_blocks -> None`, so a cross-module callee runs on its per-instruction step there. Detail: `src/jit/CONTEXT.md`.

## Execution model (frozen semantics -- reproduce, don't reinvent)
The binding semantics in brief; the exhaustive per-instruction/per-operand/per-family detail (with the `ops.tab`/`beam_emu.c` references and every edge case) is in `INSTRUCTION_SURFACE.md`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, the root set `x[0..live)`, plus the FR file; `allocate*` pushes a *continuation-pointer slot* then `stack_need` Y-slots (`y(k)` = the slot after the CP slot). The CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), exact even for a frame-less leaf; `deallocate`/`call_last`/`call_ext_last` pop the frame (Y slots **and** CP slot) and the bottom `Halt` yields `x(0)`. A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason, never a frame-size artifact.
- **The dispatch loop** (`src/machine/drive.rs` + `src/interpreter/`) owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, re-borrows the active module per iteration, re-binds the literal area only on a `Step::Enter` into a different context, charges one reduction per instruction, and runs the raise funnel's second half over a raise that surfaced inside a cross-module callee. `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every opcode the engine executes has its own typed IR variant (the residual `Instr::Generic` sentinel returns a named typed error).
- **The instruction surface.** Core-loop arms (the metadata no-ops, `func_info`, `move`/`swap`/`init_yregs`, `test`/`select_val`, the call/allocate/trim/return and `gc_bif`/`bif0`/`bif` control ops, the eight native-record variants) plus the opcodes the nine families claim; a `gc_bif`/`bif` error with a live `fail` label is a guard failure and with `NO_FAIL` a raise, while `bif0`/`call_ext*` carry no fail label, so every error there is a raise. `FuncInfo` is **not** a metadata no-op: a failed head clause raises class `error` with the bare atom `function_clause` (from the running module's own atom table), matching C's `i_func_info_IaaI`.
- **Raising and the catch-frame model.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + the owning call frame + its module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` register convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), unwinding the call-frame stack down to it, and reports `Step::Goto` (same context) or `Step::Enter` (another context); with no live frame, or an unresolvable class atom, it stays a typed `Err(BeamError::Raise)` -- never a panic. A raise *reads* the innermost entry but never pops it; the handler opcode (`try_case`/`try_end`/`catch_end`) consumes exactly one entry. The class atoms come from the running module's atom table and are never substituted by a *different* atom.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms/*`, `src/families/bitstrings/raw.rs`, `src/families/records/raw.rs`, `src/jit/emitter/mod.rs` (the crate's **only** executable-memory mapping), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*`, and -- feature-gated -- `src/jit/cranelift/mod.rs` (plus `src/context.rs`'s `MinimalContext` region heap). Every `unsafe` block carries a `// SAFETY:` rationale; registers/stack stay safe `Vec<Eterm>` indexing.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need.
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

## Known Issues / Intentional M1 gaps
The full list, each with its ground-truth detail, is in `INSTRUCTION_SURFACE.md`; the headline items:
- **The collecting host (`beam_rt`) adopts the rooted doors.** Every in-crate term-construction arm allocates through the rooted door (`alloc_words_rooted` / `Machine::alloc_rooted` / the `terms::*_rooted` builders) under the frozen reserve → read → write ordering, proved under a mock **moving** collector (`src/terms/alloc_tests.rs`, `tests/rooted_alloc.rs`, `tests/gc_roots.rs`). A collecting host must additionally root what the `RootSet` cannot carry: `Machine.pending_exception` (`src/machine/catch.rs`, reachable mutably through `Machine::pending_exception_mut`) and the `Eterm` arguments parked in `Machine.args_scratch`/the `exec_bif` stack array while a `call_bif` is in flight. Detail: `src/CONTEXT.md` (`## GC publication…`).
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory.** `families::bitstrings::raw::{make_writable,make_binary}` build the frozen 8-word `[BinRef][ErlSubBits]` pair and push each payload handle onto `Machine::refc_binaries` (never cleared by `reset`); the `send` arm and the `erlang:send/2` special case hand the in-flight slice to the host through `send_message_with_off_heap`, and `beam_rt`'s runner parks the copied payload references in its destination off-heap table, so an engine-built refc binary survives both a **return** and a **send**. Residual: the host's memory accounting cannot yet enumerate these machine-held handles -- a measurement gap, not a correctness one. Pinned by `tests/stdlib_sweep.rs::sweep_base64_encodes_the_empty_binary`, `src/families/bitstrings/matching/mod.rs::empty_binary_bs_match_commands_and_the_writable_accumulator`, `src/families/receive.rs::send_forwards_the_machines_off_heap_binary_handles`.
- **`Instr::Allocate` skips C's heap check.** C's `allocate Ns Live` is `$AH(Ns,0,Live)` ≡ `GC_TEST(Ns+1,0,Live)` (`emu/instrs.tab:31-33`), so C **can** collect at every `allocate`; this crate's `Instr::Allocate` only pushes the frame, and the two in-crate admission arms are `AllocateHeap`/`TestHeap`. The divergence is conservative (the engine collects strictly *less* often, so it can never dangle a published root) but is why an engine run's young-heap occupancy differs from the oracle's.
- **Pre-emption exists; scheduling does not (yet).** `Machine::drive` charges one reduction per interpreted instruction through the defaulted `ExecutionContext::reduce` hook, so a host can pre-empt a **non-allocating** loop by returning a typed error and the pre-empted instruction stays un-applied (resume applies it exactly once). The scheduler, run queues and trap handling are Stage 5 (`beam_process`); stack growth is an unbounded `Vec`.
- **A captured stacktrace is engine-derived** (the uncaught-raise funnel attaches a symbolic trace derived from the machine's live frames when the raw trace is `NIL`, and `build_stacktrace` cooks the raise-time `raise_snapshot` both for a non-`NIL` raw `x(0)` and for a `NIL` `x(0)` at a catch where a raise was recorded), and **nameable atoms are required**: `catch_end` needs `EXIT` and `raise_bif_error` can only raise an error it can name -- neither path ever substitutes a *different* atom.
- **The uncaught frames exist only for a `BeamError::Raise`.** `with_uncaught_frames` decorates **only** `BeamError::Raise`; `beam_common`'s reason variants (`BadArg`/`BadArith`/`BadArity`/`BadMatch`/`SystemLimit`) are **fieldless** and carry no `StackTrace` slot, so an uncaught BIF/op failure that travels as a bare variant exits the machine with **no frames at all**, while the same failure as a `Raise` is fully framed. Normalizing the bare variant into a `Raise` at this boundary was measured (semantically faithful) but broke **66 tests across 23 targets**, so it was **not forced**; the faithful alternative is a `StackTrace` slot on `beam_common`'s non-`Raise` variants (out of this crate's scope).
- **Records.** The whole native-record set executes, including `PutRecord`'s create form for the running module's own records; only a *foreign*-module record id is a typed `unsupported` (Handoff #4).
- **Bitstrings.** `bs_init_writable`/`append`/`private_append` is a copy-rebuild (`HANDOFF_bs_init_writable.md`), so a long append loop is O(n²) rather than amortised O(n), and the `BIN_FLAG_*` flags plus `binary:referenced_byte_size/1`'s capacity answer are unmodelled; every remaining bitstring gap is a typed result, never a wrong value.
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order (visible only in `term_to_binary` byte comparison), a `NO_FAIL` failure of `test`/`select_val`/a map read raises class `error` with the bare atom `function_clause` from the running module's own atom table (a module that cannot name it is the honest typed `unsupported_opcode: <site>: no 'function_clause' atom in the module`), and the installed `erlc` emits the native-record opcodes -- **including the create form** -- only for the explicit `-record #name{}` form.
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by the engine's own opcode coverage -- so whole module families are recorded as host gaps, each asserting its EXACT typed error and never a fabricated value. All of `ets` is such a gap (`ets.erl`'s operation bodies are `erlang:nif_error(undef)` stubs); the map-BIF-backed `maps` exports and the map-dependent `proplists` ones and `string:list_to_integer/1` are gapped the same way. Owning crates: `beam_bifs` (BIF surface/seam adoption) and `beam_rt` (preloaded-module floor) -- NOT this crate. `proplists:to_map/1,2` on an `[atom | {K,V}]` list DOES execute and is pinned oracle-exact.
- **Compiled arithmetic is oracle-exact on overflow** (`+ - * div rem` promote to exact bignums, and an out-of-range integer operand becomes an exact bignum).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after** (C fills `reg[i] = args[i]` then `reg[i + arity] = funp->env[i]`), never `free ++ args`.
- **`call_fun` collapses every host resolution error into a catchable `badarg`, destroying the capability-gap sentinel.** `families/funs/mod.rs:364` routes *every* `Err` from `resolve_local_fun` (and the `apply_fun` fallback at `:362`) through `Machine::raise_bif_error`, which maps any non-`Raise` `BeamError` to class `error` + its atom. A host that reports an unresolvable closure as a bare `BeamError::BadArg` (`beam_rt`'s `RuntimeContext::local_fun_target` does, for a non-fun and for a closure no loaded module defines) is therefore indistinguishable from a genuine program-level `badarg`, and a surrounding `try ... catch error:Reason` silently absorbs it. A capability gap should be reported as `error::unsupported(...)`, never `BeamError::BadArg`.
- **The `call_fun`/`call_fun2` free-variable copy is NOT a GC hazard (verified; do not re-open).** `families/funs/mod.rs` reads `terms::fun_free(fun)` then `set_x` for each; the source `fun` term stays published in `x(arity)`/the `call_fun2` operand, and there is **no admission point** between the read and the writes (`resolve_local_fun` is a non-collecting `&self` reader with the shipped host). The three doors that *can* collect are documented in `src/CONTEXT.md` (`## GC publication…`), together with the non-rooted engine→host calls. The real engine-relevant publication gap is the parked `pending_exception` reason term (bullet above), owned host-side.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node, and the full detail is in `INSTRUCTION_SURFACE.md`.
1. **Receive/message + cross-module suspension (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome`, and drive a host **timer** for a non-zero `after` (the engine exposes the parked deadline through `Machine::wait_deadline`). A `receive` **inside a cross-module callee** suspends the caller through the cross-module call seam (Handoff #10). `resume_outcome(entry_module, func, pc, ctx)` must be called with the run's **entry** module (context `0`): `func`/`pc` are in the context the process blocked in, which the machine recovers from `Machine::context`.
2. **Globally interned exception reason atoms (owner `beam_rt`).** The engine resolves a raise's reason atom (`badmatch`/`case_clause`/`function_clause`/`EXIT`/`badarg`/`badarith`/`system_limit`/`badmap`/`badkey`/`badrecord`/`undef`/...) from the running module's atom table and never substitutes a different atom, so ERTS's globally interned `error_atom` table must exist: `beam_rt::boot::CORE_ATOMS` carries the same tail as the test host's `SEED_ATOMS` (also the `file`/`line` atoms the location builders use) and is seeded before any module load. This is what makes gap #7 nameable; the residual there is the unseeded loader.
4. **`records:get_definition/2` and a *foreign* `PutRecord` create id.** `PutRecord`'s create form for the running module's own records is implemented here; `records:get_definition/2` is served by `beam_bifs`'s `RecordSource` seam, and an `Id` naming another module's record needs a code-server record table (`beam_rt`/`beam_bifs`), reported here as a typed `unsupported`.
5. **`beam_io`/`beam_rt`: `open_port({spawn_executable, <nonexistent>})`** -- the oracle raises `error:enoent` while `beam_io`'s `SpawnDriver` maps the spawn failure to `BeamError::Io`.
6. **`TestKind::TestArity` -- behaviourally equivalent to C, NOT a gap.** C's `test_arity` is an unguarded header compare, and since `tuple_val(p) == boxed_val(p)` the engine's `is_boxed(x) && ARITYVAL-header == arity` reads the same word and agrees for every boxed term; the only divergence is an *immediate* operand, where C's deref is UB and the engine safely returns `false` -- unreachable in well-formed code (the loader rewrites an immediate `test_arity` operand to a jump). Covered by `src/interpreter/test.rs` + `src/predicates.rs` tests.
7. **Map `NO_FAIL` `{badmap,Source}` / `{badkey,Key}` — closed for a seeding host; the residual is the unseeded loader.** With a host that interns the runtime's globally interned atoms before any load (`CORE_ATOMS` + the test host's `SEED_ATOMS` both seed `badmap`/`badkey`), the family raises the oracle's reason exactly. The residual is only the **unseeded** `beam_loader::load_file` path: the installed `erlc` interns `badmap` but **not** `badkey`, so a `put_map_exact` `NO_FAIL` raise there is the typed `unsupported_opcode: maps: no 'badkey' atom in the module`. Pinned both ways by `tests/maps.rs`. No engine seam resolves a tag outside the running module's table, and none should.
8. **JIT `call_ext_last` -- executes natively, by design a driver round-trip.** A **local** tail call (`call_last`/`call_only`) is linked natively; `call_ext_last` **executes** on the native baseline tier through the driver-mediated module-context transfer (a seal-time cross-module link is unsound). The residual cost is the per-transfer driver block-entry, measured by `src/jit/bench`'s `cross/2`.
9. **JIT adoption + the A.8 seam by `beam_rt` (owner `beam_rt`) -- ADOPTED.** `beam_rt/src/runner/run.rs` selects a tier at the process's first entry (default `Tier::BaselineJit` for **every** process entry, with `BEAM_RT_TIER=interpreter` the only kill switch), remembers it on the engine, routes the entry through `run_label_outcome_with_tier`, and resumes a parked slice through `resume_outcome_with_tier` on that **same** tier. The engine-side seam is **complete**. A natively-executed block records its own `(func, pc)` in its prologue, so `process_info/2`'s position is block-exact; a traced run refuses native entry. The `+JPperf` perf map (contract A.8) can be populated from `beam_engine::jit::cache::baseline_code_map(&module)`. **End-to-end evidence:** a gate run with `BEAM_RT_TIER=baseline` reports `total=1848 agree=1845 mismatch=0 unsupported=3 allowed=3` (exit 0), and the native cross-module / nested A->B->C / parked-then-resumed-slice / dynamic-`apply` shapes are pinned by `tests/jit_cross_module.rs`. Honest note: the forced tier reaches the module-run third of the corpus (566/1848); the `-eval` root expression is a tree-walk evaluator with no `Machine` and does not consult a tier.
10. **The cross-module call seam (owner `beam_rt`, the owner of `RuntimeContext`) -- ADOPTED.** LANDED and tested here (`tests/external_call.rs`, `tests/current_module.rs`) and adopted by `beam_rt`; the contract: `Some((arc, label))` for an import the host can run in this machine, `Ok(None)` otherwise (keeps the synchronous `call_bif` path -- `code:*` native floor, NIFs and everything else). `arc` must be the **SAME `Arc<Module>`** the host loaded the module with (`CodeServer::modules`, `codeserver.rs`; contexts dedup by `Arc::ptr_eq`); `label` is the export entry label (`arc.export(function_atom, arity)`, the label *after* `func_info`). `resume_outcome` takes the run's **ENTRY** module (context `0`); the suspended `(func, pc)` live in `Machine::context`. Regression repro (committed, `beam_rt`-owned): `../beam_rt/tests/proc_lib_start.rs` -- read it, do not edit `beam_rt` from here.
11. **The rooted doors are adopted by `beam_rt` (owner `beam_rt`).** `beam_rt` overrides both `alloc_words_rooted` and `ensure_heap_full`: it publishes the whole `RootSet` (every x slot, the whole stack and the whole FR file), runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a container in a region the collector does not scan. Detail: `beam_rt/src/context/CONTEXT.md`.
12. **The closure-apply seam (`resolve_local_fun`, owner `beam_rt`, the owner of `RuntimeContext`) -- the remaining `beam_rt` step.** The seam is LANDED and tested here; `beam_rt` closes it by implementing `ExecutionContext::resolve_local_fun` as a **thin wrapper over its existing `RuntimeContext::local_fun_target`**, returning `Some((target.module, target.label))` (clone the module `Arc`) and `Ok(None)` for the fun kinds with no local label. **The engine places the free variables itself** (into `x(arity..)`, C's `call_fun` order), so the host need not re-derive `LocalFunTarget.args`. Until then a scheduled process's `call_fun`/`call_fun2` still folds a blocking closure into the value-returning `apply_fun` fallback.
