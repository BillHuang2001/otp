# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step (interpreter-identical semantics), carrying **two layouts behind one `CompiledModule`** (eager whole-module and lazy per-function, so a fresh process pays only the functions it enters).
The **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) is one Cranelift function per IR function over the same shared interpreter-backed helper.
All tiers are **measurement-gated** and off the critical path (Part II sec. F) -- correctness-first *mechanisms*, not optimisers.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end, with explicit dispatch arms for the core opcodes and a per-instruction-family seam (`src/families/`) for the rest.
The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC, process/stack limits and pre-emption all sit behind `ExecutionContext` (implemented by `beam_rt`), keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

**Where the detail lives.** This file is the crate-level *contract*: the frozen API seam, the binding execution semantics, the constraints, the test strategy, and summaries of the gaps/handoffs. The exhaustive surface, the design decisions and the full M1 gap list are in `INSTRUCTION_SURFACE.md`; the subsystem detail is in the child `CONTEXT.md` files under `src/` (routing table below).

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: computation goes through `ExecutionContext::call_bif`, and an in-machine callee through the resolver seams (`resolve_external_call`/`resolve_local_fun`, plus `resolve_local_call` which lets a host serve a **local** callee *as* a BIF), with `ExecutionContext::apply`/`apply_fun` the value-returning fallbacks. `ExecutionContext::atom_name` resolves a runtime atom **value** against the host's live atom namespace.

### The supplied-stacktrace encoder (`src/supplied_stacktrace.rs`)
The **public** `beam_common::StackTrace` -> `Eterm` encoder, for a host that renders a raise's explicitly **supplied** symbolic frames without a compiled handler (the tree-walking `-eval` route of `beam_rt`).
Two entries over one carve (`families::exceptions::stacktrace::carve_supplied_frames`): the free `encode_supplied_stacktrace(module, ctx, frames)` and its `Machine::encode_supplied_stacktrace` twin (the same carve with THAT machine's root set).
Both cook `frames` into the oracle's `[{Module,Function,Arity,Location}]` list (innermost frame first; `Location` = `[{file,File},{line,N}]` when the frame has a location, else `[]`) as ONE rooted reservation carved node-by-node (moving-collector safe; the machine is only the reservation's root-set carrier).
**The atom source is the passed `module`'s atom table, by lookup only** (nothing is interned), so a host whose atoms live in a shared namespace must pass a `Module` carrying that table; an unresolvable name is the typed `error::unsupported`, never a substituted atom.
Pinned by `src/families/exceptions/tests/encoder.rs`.
### The context seam (`src/context.rs`)
The frozen seam shape is one `pub trait ExecutionContext` of `&mut self` methods over `Eterm`; **`src/context.rs` is authoritative for the exact signatures**, and every method is `Result`-returning except the pure-`&self` probes.
Method groups: the BIF door `call_bif` plus `wants_bif_in_machine`/`call_bif_in_machine` and the outcome-aware `call_bif_outcome`/`call_bif_in_machine_outcome`; the GC doors `ensure_heap`/`ensure_heap_full` and `alloc_words`/`alloc_words_rooted`; the introspection-only `heap_available`; `apply`/`apply_fun`/`apply_fun_outcome`; `send_message_with_off_heap`; the four resolvers `resolve_external_call`/`resolve_local_fun`/`resolve_local_call`/`atom_name`; the atom-namespace `atoms`; the reduction pair `reduce`/`wants_reduce`; the record-definition `foreign_record_definition`; and the A.8 pair `trace_enabled`/`trace_event`.
`RootSet<'a> { x, stack, fr, live }` is the mutable root set the two rooted doors receive (`live` clamped; `ALL_LIVE = u32::MAX`), and `TraceEvent` is the report enum `Call`/`ReturnFrom`/`ReturnTo`.
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- **The in-machine BIF door.** A host returning `true` from `wants_bif_in_machine` is handed the live `Machine` and the run's **entry module** (context `0`) on **every** BIF dispatch and **must** then override `call_bif_in_machine` (and `call_bif_in_machine_outcome` if its BIFs can wait).
  The probe is latched once per run into `Machine::bif_in_machine_on` by **both** drivers, every dispatch goes through the single `Machine::dispatch_bif_call` funnel, and the default `false` keeps the plain `call_bif` path byte-identical.
  Gate: `tests/bif_in_machine.rs`; detail: `src/machine/CONTEXT.md`.
- **The GC root-set contract, in two doors.** `ensure_heap(heap_need, live, x_regs, stack)` is the frozen **narrow** door; `Machine::ensure_heap` (reached by `test_heap`/`allocate_heap`) calls the defaulted **`ensure_heap_full(heap_need, roots)`** over the whole `RootSet` (**including the FR file**, which holds `Eterm` term slots), whose default forwards to the narrow door; `alloc_words_rooted(n, roots)` is the **term-construction** door (`alloc_words` itself has neither an admission point nor roots), whose default discards the roots and forwards to `alloc_words`.
  Frozen contract: a collecting host overrides both and relocates every term reachable from `roots.x[..roots.live_len()]`, **the whole** `roots.stack` (no frame liveness maps) and **the whole** `roots.fr`, writing the moved terms back; `live` is only a hint (`RootSet::ALL_LIVE` is always *safe*), and nothing outside the root set survives -- a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation. The engine side is `Machine::with_roots`/`Machine::alloc_rooted`, and **every in-crate term-construction arm routes through it**. `Machine::with_roots` also **parks the machine's loose `Eterm` fields at the stack tail** -- the two function-clause latches, the pending exception's reason and the two supplied-trace term latches (`Machine::loose_heap_terms`, `LOOSE_HEAP_TERMS = 5`) -- and re-seats them after the hand-off, so `RootSet` **plus the stack** carries every term the machine holds and no host enumeration of `Machine` fields is needed. Detail: `src/terms/CONTEXT.md`, `src/CONTEXT.md`.
- **`reduce(n)` is the reduction hook** (defaulted no-op), charged by `Machine::drive` **once per interpreted instruction** with `n = 1` **before** the body runs; a host with a scheduler pre-empts by returning a **typed error**, leaving the instruction **un-applied** with the machine parked on it so a `Machine::resume_outcome` applies it **exactly once** -- the only pre-emption point a **non-allocating** loop reaches.
  **Both tier drivers charge it** (the native ones once per driver-loop iteration), `wants_reduce` latches the decision once per run per driver (a host implementing `reduce` MUST stay `true`), and there is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption a fresh `drive`. Detail: `src/machine/CONTEXT.md`.
- `apply` is the general synchronous `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the **value-returning fallback** for `call_fun`/`call_fun2` (default a typed `unsupported` -- the engine keeps no closure registry), consulted only after `resolve_local_fun` declines, entering the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables (C's `call_fun` order).
  Both seams' and the fallback's errors route through `Machine::raise_bif_error`, so a routable raise lands in the caller's live `try`/`catch`.
  **`apply` has no outcome-aware twin and no park channel**: every `RunOutcome` park address is a `(func, pc)` into a loaded `Module`, so a tree-walking host reaches the engine through `apply_fun_outcome`; `ExecutionContext::apply` has **no engine call site** (`apply_target` dispatches through `dispatch_bif_call`).
- **`resolve_external_call` -- the cross-module call seam (`call_ext*` and dynamic `apply`).** A host that owns loaded modules answers `Some((callee_module, entry_label))` and the engine runs the callee **in this machine**, so a `receive`/raise inside it suspends/raises this process instead of routing through the synchronous `call_bif`.
  `callee_module` must be the **shared** `Arc<Module>` the host loaded it with (contexts dedup by `Arc::ptr_eq`) and `entry_label` the export entry label (the label *after* `func_info`); default `Ok(None)` keeps the `call_bif` path.
  See Handoff #10.
- **`resolve_local_fun` -- the in-machine closure-apply seam (`call_fun`/`call_fun2`).** Consulted **first**: a host that owns the closure's defining module answers `Some((callee_module, lambda_entry_label))` and the engine enters the lambda body here, copying the closure's free variables into `x(arity..)` (C's `reg[i + arity] = funp->env[i]` order) and reporting `Step::Enter`.
  Default `Ok(None)` keeps the `apply_fun_outcome` fallback (an external `fun M:F/A`, the `-eval` evaluator's closure), which may park the machine on the `call_fun`/`call_fun2` instruction instead of failing -- such a host must then **continue** the pending application.
  See Handoff #12.
- **`atom_name` -- the runtime atom-*value* seam (`apply(M,F,A)` / `M:F(...)`).** `Module::atom_name` indexes the module's **owned load-time snapshot**, so a module loaded early cannot name an atom interned *afterwards*; `families::funs::atom_name` resolves the runtime `M`/`F` **values** through this seam, returned **owned** (`Option<String>`) so the caller can hold both across the subsequent `&mut` host calls.
  A non-atom or an unnameable id is the typed `BeamError::BadArg`, never a substituted atom.
  Gate: `tests/apply_atom_value.rs`.
- **`atoms` -- the comparison atom-*namespace* seam (every guard/`select_val`/map-key comparison).** `erts_cmp_atoms` compares atom *names* and falls back to the raw atom id when a name is unknown to the supplied table, so this is the namespace every comparison resolves names through (`eval_test`'s six comparison kinds + `is_boolean`, `SelectVal`, the baseline tier's `evaluate_comparison`, map-key equality); the default `&module.atom_table` is byte-identical for every existing implementor, and a host owning ONE shared namespace overrides it so atom order matches the `<` BIF.
  `fn atoms<'m>` borrows `*ctx` **immutably** (take it after the operand reads, never across a `&mut ctx` call); the JIT inline lowerings decline atom operands for order comparisons. Gate: `src/interpreter/test.rs::comparisons_order_atoms_by_name_through_the_shared_namespace`; detail: `src/CONTEXT.md`.
- **`resolve_local_call` -- the local-call *as-BIF* seam (`Instr::Call`/`CallOnly`/`CallLast`).** Consulted in the interpreter's three local-call arms (before the in-machine `Step::Goto`) and by the native baseline tier's `jit_local_call` probe: **`Ok(true)` = the host serves this `(Module,Function,Arity)`**, so the engine marshals `x(0..arity)` and dispatches it through `call_bif` under the arm's own frame discipline; **`Ok(false)` = the in-machine jump**, byte-identical and mutating nothing.
  The OTP compiler emits a **local** call for a **non-exported** same-module function, so a module's non-exported NIF stubs (`erlang:nif_error(undef)` bodies) reach `call_bif` only through this seam; seam errors travel via `?`, `call_bif` errors route through `Machine::raise_bif_error`.
  **It is a RUN-TIME consultation, memoized nowhere** (the probe runs on every execution; only the callee *identity* is memoizable, and a host prices one reduction per consultation). Host contract and the `prim_tty`/`zlib` motivation: `src/interpreter/CONTEXT.md`; see Handoff #13.
- **`foreign_record_definition(owner, name)` -- the record-definition seam (`PutRecord`'s *create* form for another module's `{Module,Name}` id).** `Ok(Some(def))` is the host's record table answering `erl_record.c::erts_record_find_entry` and the engine builds the instance only when `def.is_exported` holds -- a non-exported definition is the C's `error:{badrecord, Id}` raise (`erl_record.c:401-409`).
  There is no `code:ensure_loaded/1` trap behind this door, so a defining module the host has not loaded is its own `Ok(None)`, which keeps the typed `error::unsupported("put_record: create: no record definition table for another module")`.
  Pinned in `src/families/records/tests/` and `tests/gaps.rs`.
- **`call_ext*` special cases (`Machine::resolve_call_ext_apply` / `_send`).** The three arms special-case the import `erlang:apply/3` (C's `fixed_apply` -> `apply()`: decode `x(0..2)`, unwrap the nested `apply of apply/3` shape, walk the argument list into `x(0..N)` -- past `MAX_ARG = 255` is `error:system_limit`, a non-proper tail the catchable `badarg`) and `erlang:send/2`/`'!'/2` (through `send_message_with_off_heap` with the machine's off-heap handles).
  **Only `apply/3`** is special-cased (C's `fixed_apply` handles only `arity == 3`); `erlang:apply/2` stays on the ordinary `call_bif` route.
  Detail: `src/interpreter/CONTEXT.md`.
- **Contract A.8 execution-trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}` / `return_from` / `return_to` shapes; the engine **reports only** -- the host owns matching and term building.
  Emission is infallible (a traced run is byte-identical to an untraced one) and **a natively-executed JIT block does not trace**; the exact emission points are in `src/interpreter/CONTEXT.md` sec. Contract A.8 trace emission.
- `pub type BifHook`/`ApplyHook`/`ExternalResolver`/`LocalFunResolver` -- the pluggable bodies a `MinimalContext` installs via the matching `with_*`/`set_*` builders.
- `MinimalContext` -- the test/embedding context: an unbounded pointer-stable **reserved-heap** arena (reserved up front, **grown in place**, so an allocation costs its payload only and every earlier region is kept alive, keeping a handed-out pointer valid and **unmoved**), a **pluggable BIF hook** (`new()` rejects every BIF), an **optional apply hook**, **optional cross-module/local-closure resolvers** and an **optional mailbox**.
- **The arena's measurement, mark and reclaim surface** (additive: no change to the allocation policy, the sizing or the growth rule) lives in `src/context.rs` beside `ContextHeap` plus the child module `src/context/reclaim.rs`, and is re-exported from `lib.rs`: `ContextHeapStats` (`regions`, `reserved_words`, `committed_words`, `used_words`, `live_words`, `released_words`, `peak_words`, `frontier_used`, `frontier_available`) from `MinimalContext::heap_stats(&self)`; `HeapMark` (`HeapMark::EMPTY`, `region()`, `base()`, `used()`) from `MinimalContext::heap_mark(&self)` with the typed predicate `MinimalContext::heap_mark_matches(&self, HeapMark) -> bool` (a stale -- replaced-region, forward or pre-reclaim-epoch -- mark is `false`); the census walk `MinimalContext::for_each_heap_region(&mut self, impl FnMut(&mut [Eterm]))`, which visits each region's **written prefix** `[0, used)`, oldest first, and whose visitor must neither interpret the words as terms (they are raw payload) nor keep the slice; and the two **host-driven** reclaim tiers -- Tier A `heap_rewind(&mut self, HeapMark) -> Result<HeapRewind>` (a mechanical prefix rewind: drop every region after the mark with a real `Drop`, then reset the survivor to `mark.used`) and Tier B `reclaim_heap(&mut self, impl FnMut(&mut beam_gc::Relocator<'_>) -> Result<()>) -> Result<Option<HeapReclaim>>` with its `reclaim_heap_with_capacity` twin (a full Cheney compaction whose roots the **host** forwards).
  `used_words` stays **cumulative demand**, never live memory (`= live_words + released_words`); the new `live_words` is the words currently handed out (it falls on a rewind) and `peak_words` is the summed per-region high-water over the regions still held.
  A mark is a **precondition check, never a permission**: it carries the frontier's region index, base address, used figure and an epoch, and both successful tiers bump the epoch, so every mark taken before a rewind or a reclaim is refused by both `heap_mark_matches` and `heap_rewind`. The crate itself never invokes either tier and neither makes a liveness decision -- the caller asserts that nothing reachable lies at or above the mark (Tier A) or outside the roots it forwards (Tier B).
  Detail: `src/context/CONTEXT.md`.
- `Machine::for_each_root(&self, impl FnMut(Eterm))` (`src/machine/mod.rs`, beside `with_roots`): the read-only enumeration of exactly the **pointer-bearing** root words `with_roots` hands over -- `x[..used_x_extent]`, the whole Erlang stack, `fr[..used_fr_extent]` and the five loose heap terms (the two failed-clause latches + the pending exception's reason + the two supplied-trace term latches) -- with every `IMMED1` word skipped by `beam_term::primary_tag`. It copies words (it cannot relocate: a collecting host still goes through `with_roots`'s mutable slices) and it does **not** cover `args_scratch`, which is `mem::take`n out of the machine for the whole wide dispatch — sound because that window is collection-free by construction (see the `ExecutionContext::call_bif` bullet in `src/CONTEXT.md`, pinned by `tests/bif_args_window.rs`).
  `MinimalContext` does **not** override `alloc_words_rooted`, so it stays the test/embedding heap rather than a collector.
- `Machine::for_each_root_mut(&mut self, &mut impl FnMut(&mut [Eterm]) -> Result<()>) -> Result<()>`: the **relocating twin** of that census, implemented as ONE `with_roots` hand-off so the two cannot disagree about what is rooted. It hands `&mut x[..used_x_extent]`, `&mut stack` (with the five loose terms parked at its tail) and `&mut fr[..used_fr_extent]` one slice at a time, re-seats the loose fields after the last slice **even when the visitor errors**, and keeps `args_scratch` out for the same reason. A prefix is contiguous, so an `IMM1` inside it is handed over too -- a relocating visitor (`beam_gc::Relocator::forward_roots`, `live_words_in`) leaves it byte-identical, and the `root_tests.rs` parity pins compare the pointer-word subsets instead.
  Detail: `src/CONTEXT.md`, `src/machine/CONTEXT.md`.

### The BIF suspend channel (the host contract for a waiting BIF)
`ExecutionContext` carries two **outcome-aware** BIF doors beside the value-returning ones -- `call_bif_outcome` (twin of `call_bif`) and `call_bif_in_machine_outcome` (twin of `call_bif_in_machine`) -- both returning `Result<BifOutcome>` and both **defaulting** to the value wrapped as `BifOutcome::Return`, so a host that predates the channel is byte-identical; `Machine::dispatch_bif_call` takes exactly one of them per run, and a host that answered `true` from `wants_bif_in_machine` must override the in-machine twin (the engine never reaches its `call_bif_outcome`).
`BifOutcome::Return(value)` is the ordinary answer; `BifOutcome::Suspend` means the BIF did **not** complete and the instruction was **not** applied (no register written, no guard branch taken, no frame effect).
The park/resume protocol: the engine reports `RunOutcome::Suspend { func, pc }` **at the BIF instruction itself**, the host pumps its own waiting resource, and `Machine::resume_outcome`/`resume_outcome_with_tier` re-enters there, re-executing the instruction and re-issuing the BIF with the **same operands** -- so the host must be re-execution safe on its own too (a suspending attempt must not consume a one-shot resource).
The engine holds **no** suspended-BIF state: the parked state is `(func, pc)` + the registers + the Erlang stack + the FR file, i.e. exactly the frozen `RootSet` a host is handed at every admission point, so a moving collector may relocate the operands and the re-execution re-reads the relocated words (the C equivalent is the `c_arg_reg`/`arg_reg` array).
A **non-blocking** entry folds a suspend into the typed `error::suspended()` -- never `error::blocked()`, never a substituted value -- and both tiers report and resume it (the baseline tier carries it out of a compiled block as the `SUSPEND` (`-5`) block-ABI word; `Tier::Cranelift` cannot resume at a mid-function `pc` and keeps its honest typed `unsupported`).
Gate: `tests/bif_suspend.rs`; the class-A/class-B rule (the `erlang:apply/3` route is the typed non-idempotent gap) and the tracing deviation: `src/CONTEXT.md` sec. The BIF suspend channel.
### The closure-apply suspend channel (the host contract for a waiting closure application)
`apply_fun_outcome` is the outcome-aware twin beside the value-returning `apply_fun`, returning `Result<FunOutcome>` (`Return(value)` / `Suspend`) and **defaulting** to the value wrapped as `FunOutcome::Return`, so a host that predates it is byte-identical (an unimplemented `apply_fun` still answers `unsupported("apply_fun")`).
It exists for a host that **interprets** the closure itself (a tree-walking `-eval` evaluator), which has no way to park its caller through a value-returning door.
`FunOutcome::Suspend` means the application did **not** complete and the instruction was **not** applied; the engine parks on the `call_fun`/`call_fun2` instruction (`Step::Suspend`, `RunOutcome::Suspend`) and the resume **re-consults this door with the same `fun` and `args`**, so the host must **continue** the pending application and never restart it -- stricter than `BifOutcome`, whose re-issued dispatch re-runs the BIF from its operands.
Gate: `tests/fun_suspend.rs`; the full contract: `src/CONTEXT.md`.
### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
`pub trait Mailbox` is exactly nine `Result`-returning methods: `send_message`; the scan position `receive_next` (the candidate at the position, `None` = exhausted), `receive_skip` (`loop_rec_end`), `receive_remove` (`remove_message`) and `receive_reset` (`timeout`); and the four marker calls `receive_marker_reserve`/`_bind`/`_use`/`_clear`.
- `ExecutionContext` carries the **same nine names as defaulted methods** (`error::unsupported("<method>")`), so every implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- **The engine never inspects a message or a marker** (selection is the compiled code's job; a marker term is **opaque**, and only a separate *reference* reaches `_use`/`_clear`); installing a mailbox does **not** change the non-blocking entries, which still surface `error::blocked` (Handoff #1).
- **`send_message_with_off_heap(to, message, src_binaries)`** is the `Instr::Send` arm's entry **and** the `call_ext*` `erlang:send/2`/`'!'/2` entry: a tenth defaulted method whose default forwards to `send_message` and discards `src_binaries`, the **source off-heap table** the receiver-side copy needs to resolve an engine-built off-heap (refc) binary.
- **Ordering invariant:** the three position calls take **no candidate argument**, so the driving is correct only while the host's own position is stable between the producing `loop_rec` and the consuming `remove_message`/`loop_rec_end` (true by construction); a `receive` reaches `wait`/`wait_timeout` **only** via `loop_rec`'s `None` arm, so a `resume_outcome` re-entry sees only messages appended since. Host contract: FIFO with a **saturating** scan index (`beam_message::QueueCursor` + `beam_rt::MailboxState`).
  The nine-method host contract in full: `src/families/CONTEXT.md`; driving evidence: `tests/receive.rs`.
### The machine (`src/machine/{mod,registers,frames,catch,run,location,context,drive}.rs`)
`Machine` is the process-state core: the x-register file (`MAX_REGISTER = 1024`, C's `MAX_REG`), the float-register (FR) file (`MAX_FLOAT_REGISTER = 1024`, holding **`Eterm` term slots**), the Erlang stack, the call-frame and exception catch-frame stacks, the `refc_binaries` arena (never cleared by `reset`, host-prunable through `retain_refc_binaries`), the running module's decoded **literal area**, the **module-context registry** (`contexts` + `context` + `entry_literals`; one `ModuleContext { module: Arc<Module>, labels }` per module, deduped by `Arc::ptr_eq`, context `0` = the run's entry module), the reduction counter, the **raise-time snapshot** `raise_snapshot`, the latched A.8 gate `trace_on`, and the per-module **label-map cache** (`label_maps`).
- **Run entries.** `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware; `RunOutcome { Returned(Eterm), Wait { func, pc }, Suspend { func, pc } }`), plus the tier-aware quartet; `run_export` resolves the export label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return` and yields `x(0)`, and a missing export/label is a typed error.
- **The uniform raise funnel.** `throw`/`throw_error`/`throw_with_trace` rebuild the raise-time frame snapshot *before* any unwind (so it survives the caught and the uncaught path), and the symbolic `StackTrace` an **uncaught** raise carries is attached by the single funnel `Machine::with_uncaught_frames(err, entry_module, func, pc)` as the raise leaves the machine, so **every** raise kind gets the same frames.
- **Introspection (read-only):** the register/stack/frame/catch accessors, `pending_exception`(+`_mut`)/`pending_class`, `resumption_addresses`/`resumption_contexts`, `raise_snapshot`, `wait_deadline`, `reductions`/`reset_reductions`, plus the execution-position accessors (`current_code`/`entry_call`/`current_function`/`initial_call`/`current_location`/`current_stacktrace`/`current_module`).
- **The label-map cache's identity key** (`checksum` digest + `AtomSnapshot` + module address; a synthetic image is never cached), `switch_context` and the per-file roles: `src/machine/CONTEXT.md` (`src/machine/label_cache.rs`).
### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func, pc }, Enter { context, func, pc }, Wait { func, pc }, Suspend { func, pc }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`/context. `Next` = continue at `pc + 1`; `Goto` = jump **within the current module**; `Enter` = transfer to `(func, pc)` in another module context (a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address`, or a raise landing in another context's live catch frame) -- the driver switches context and re-binds the literal area exactly here; `Done` = finish and yield `x(0)`.
- `Wait` is the **receive** suspend signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. `Suspend` is the **BIF** suspend signal (see *The BIF suspend channel*): the instruction was **not** applied, so the reported address is the instruction itself and the resume re-executes it; the JIT driver carries it as `SUSPEND` and folds it into `error::suspended()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto`/`Step::Enter` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which **routes by the instruction's own variant** to the single owning family -- a `match instr` that compiles to a jump table on the `Instr` discriminant. Family ownership is **disjoint** (each of the **77** claimed variants has exactly one owner: `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`).
- Each family exposes `pub(crate) fn exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = "executed", `Ok(None)` = "not this family's variant", `Err` = the family raised. A variant **no** family owns or one a family declines falls to the router's last arm: `error::unsupported("widened opcode not yet executed: <ops.tab name>")` (an unclaimed opcode is diagnosable from the error alone). Per-family variant ownership and gaps: `src/families/CONTEXT.md` and its child nodes.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,slack,sink,alloc_tests,tests}.rs`) -- the SAFETY-annotated builder/reader
The crate's single point of raw-heap access, over the `alloc_words`/`alloc_words_rooted` seam.
- Each builder comes in **two flavours**: the **classic** public builder (`make_tuple`, `make_cons`, `make_list`, `badmatch_reason`, `make_heap_binary`, `make_float`, `make_integer`, `make_flatmap`, `make_map`, `make_fun`) allocates through the plain `alloc_words` and takes already-materialized operands (the frozen cross-crate signature `beam_rt` and `tests/**` consume); its **`*_rooted` twin** takes `machine`/`ctx`/`live` plus a `read` closure and reserves the block **before** reading operands (the frozen reserve -> read -> write discipline), so a **moving** collector may relocate them in between. **Every in-crate construction arm uses the rooted twin**; `src/slack.rs` is the reserve/bump-carve and `src/sink.rs` the `Sink` shape writer a multi-node graph is carved from without a second allocation.
- `make_map(ctx, &[(Eterm, Eterm)], atoms)` builds a map of ANY size over `beam_term::map::map_words_capacity`: a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys, else a **hashmap** (HAMT), duplicate keys collapsing last-wins.
- Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`, never a panic) cover the tuple/cons/list/float/map/binary accessors plus the fun readers (`is_fun`/`fun_arity`/`fun_num_free`/`fun_uniq`/`fun_index`/`fun_free`/`fun_true_arity`); `map_entries` walks both map layouts; `fun_arity` is the 8-bit header field (saturating at 255) while `fun_true_arity` returns an external fun's real arity.
- Full API: `src/terms/CONTEXT.md`.
### Literal-area words -- a static literal is passed BY REFERENCE (`Operand::Literal`)
Every `Operand::Literal(idx)` resolution is a **single-word read** out of the module-owned area; the engine never rebuilds or copies a literal.
- The area is `beam_loader::LiteralArea`: the `LitT` payloads decoded **once at load** into a private `beam_alloc::Heap`, with `TAG_LITERAL_PTR` ORed into every BOXED/LIST word and root by `beam_term::literal::tag_literal_area` (`beam_loader/src/literal.rs:84-129`). `LiteralArea::get` is `self.terms.get(i).copied()` (`:134-136`) -- a word copy of a pointer, never a graph copy.
- The engine's two doors are `Machine::literal` -> `self.literals.as_ref()?.get(index)` (`machine/mod.rs:1052-1054`) and `Module::literal` (`beam_loader/src/ir.rs:425-427`); six read-only call sites (`operand.rs:80,163`, `families/floats/mod.rs:268`, `families/bitstrings/mod.rs:378`, `families/bitstrings/create/mod.rs:449`, `machine/location.rs:366`). Binding is per **module context** (`literals`/`entry_literals`, re-bound by `switch_context`/`enter_run` -- `machine/drive.rs:154-164`), because the operand carries only an index.
- Writing a literal word into a **new** object stores the tagged pointer verbatim (`terms/construct.rs:70-77` for `make_tuple`, `:87-96` for `make_cons`, `terms/map.rs:196` for maps) -- no site deep-copies a literal interior. A `Literal` is never a valid **destination** (`operand.rs:194`), and an in-place write into a literal-area object is refused by `beam_term::is_literal` (`terms/update.rs:66-72`).
- The baseline JIT loads the word too: the driver publishes the bound area's `(literals_base, literals_end)` (`jit/baseline/runtime.rs:233-261,437-485`) and the emitted sequence is `lea addr,[base+idx*8]; cmp addr,end; jae fallback; mov value,[addr]` -- a guarded raw load behind the same bounds check as `Machine::literal` (`jit/baseline/emit/move.rs:450-491`); the loaded word "stays a pointer into the shared, read-only literal area, never rebuilt and never copied" (`:470-471`). Only the **index** (a `disp32`) is baked into generated code; the area's base is re-read from the published `JitRuntime` on every access, because a cached module's area may be a different allocation (`jit/baseline/runtime.rs:237-247`).
- `MinimalContext`'s `ContextHeap` (`context.rs:1450-1478`) is a pure **pointer-stable bump arena**; it is only ever handed a literal word as an element/operand, never a literal's contents (the words it hands back are the ones a builder writes, e.g. `alloc_words` at `:1918-1926`). `src/terms/`, `src/context.rs` and `src/interpreter/` contain no literal-copy site.
- Consumers test the bit, never an area registry: `beam_term::literal::is_literal` = `(x.raw() & TAG_LITERAL_PTR) != 0` (`beam_term/src/tag.rs:57`, `literal.rs:41-43`). Comparisons need no test at all (`cmp` dereferences, so `select_val` decides a literal candidate on rung 4 -- `interpreter/select.rs:167-187`).
- Host-side consequences: a literal inside a copied graph is **shared**, not copied, by `beam_message::copy_struct` (`beam_message/src/copy.rs:254-275`), and both collectors leave a literal pointer verbatim by **address range**, not by the bit (`beam_gc/src/copy.rs:334-361` `Target::Foreign`, `beam_gc/src/space.rs:135-140`); `beam_rt`'s root/walk classifier additionally rejects it by the bit (`beam_rt/src/context/gc.rs:382-400`).
### The JIT tier seam (`src/jit/`)
- `Tier { Interpreter, BaselineJit, Cranelift }` (`Tier::ALL` = roster order, interpreter first) with `name()`/`from_name()`/`is_available()`; `available_tiers()` = `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` when the feature is on.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>` (the artifact is **caller-owned**, hence `&self`); plus the provided `run_export`. The interpreter is deliberately **not** a `JitBackend`.
- `Machine::run_with_tier(..., Tier)` is the **non-blocking** tier entry (`Result<Eterm>`; a suspend folds to `error::blocked()`), and `run_export_outcome_with_tier`/`run_label_outcome_with_tier`/`resume_outcome_with_tier` are its outcome-aware/resume twins: a suspended slice re-enters on the SAME tier, so the tier survives a `receive` park; `Tier::Cranelift` cannot resume at a mid-function `pc` and reports the honest typed `unsupported`, never a silent interpreter fallback.
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier, and `tiering.rs`'s `TierPolicy` models the *interpret -> baseline -> hot* escalation as a **policy only**.
- `src/jit/cache/` is the **cross-run compiled-block cache**, keyed by `CacheKey` = the module's `ModuleKey` (the **load-time MD5** for a real `.beam`, else a fingerprint over the decoded IR) **plus** `Module::atom_table.snapshot()`; two separately loaded copies of one `.beam` (or a `Module::clone`) are two entries -- an extra compile at worst, never a wrong answer. `baseline_code_map(&Module)` exposes the **real** generated ranges for a host's `+JPperf` map.
- Every un-lowered instruction (or an inline whose run-time guard rejects) **deopts to one interpreter step** (`jit_step_one` == `Machine::step_instruction_with_entry`), so a tier is interpreter-identical for every supported opcode and the interpreter's exact error surfaces stand; a **traced** run refuses native entry, and the seam's one **run-time** host consultation is the local-call seam (`tests/local_call_seam.rs`). **The block ABI, register picker, artifact layouts, continuation sub-blocks and inlined shape set are `src/jit/CONTEXT.md`, `src/jit/baseline/CONTEXT.md` and `src/jit/baseline/emit/CONTEXT.md` (authoritative).**
### The dynamic execution-census instrument (`src/exec_census.rs`)
`pub mod exec_census` -- a **measurement-only** per-variant counter: it is on no execution path, changes no result, and costs one thread-local `bool` load per hook while disabled.
Its surface is the gate `enable`/`disable`/`is_enabled`, `reset`, `snapshot()`, `write_dump(section)` (`$TMPDIR/beam_engine_exec_census_<section>.tsv`) and `variant_name(&Instr)` (`"Move"`, `"Test(IsEqExact)"`, ...); `Snapshot` carries the per-variant `executed`/`errors` maps, `first_error` per name and the two totals.

- **Consumers.** `src/jit/baseline/census.rs`'s runtime census, `tests/dynamic_census.rs` and `tests/real_beam_variant_proofs.rs`; `MEASURED.md` records the blind spots. Detail: `src/CONTEXT.md`.
### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend -- and `suspended()` = `unsupported("run: process suspended by a BIF (host must resume)")` -- the same for a BIF that answered `BifOutcome::Suspend`.
- **`Step::Enter` executes on the native baseline tier via a driver-mediated context switch** -- a **driver round-trip by design**, because a seal-time cross-module link is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`). Detail: `src/jit/CONTEXT.md`.
## Execution model (frozen semantics -- reproduce, don't reinvent)
The binding invariants; the exhaustive per-instruction/per-operand/per-family detail (with the `ops.tab`/`beam_emu.c` references) is `INSTRUCTION_SURFACE.md`'s `## Execution model`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, the root set `x[0..live)`, plus the FR file; `allocate*` pushes a typed-`Continuation` CP slot then the Y slots (`y(k)` = the slot after it), and the bottom `Halt` yields `x(0)`. A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason.
- **The dispatch loop** (`src/machine/drive.rs` + `src/interpreter/`) owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into it, re-binds the literal area only on a `Step::Enter` into a different context, and charges one reduction per instruction. `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every opcode the engine executes has its own typed IR variant (the residual `Instr::Generic` sentinel returns a named typed error).
- **Failure semantics.** A `gc_bif`/`bif` error with a live `fail` label is a guard branch and with `NO_FAIL` a raise, while `bif0`/`call_ext*` carry no fail label, so every error there is a raise; `FuncInfo` is **not** a no-op -- a failed head clause raises class `error` with the bare atom `function_clause` (C's `i_func_info_IaaI`).
- **Raising and the catch-frame model.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + the owning call frame + its module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` register convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), reporting `Step::Goto` (same context) or `Step::Enter` (another); with no live frame, or an unresolvable class atom, it stays a typed `Err(BeamError::Raise)`. A raise *reads* the innermost entry but never pops it; class atoms come from the running module's atom table, never substituted by a *different* atom.
## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms/*`, `src/families/bitstrings/raw.rs`, `src/families/records/raw.rs`, `src/jit/emitter/mod.rs` (the crate's **only** executable-memory mapping), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*`, and -- feature-gated -- `src/jit/cranelift/mod.rs` (plus `src/context.rs`'s `MinimalContext` region heap); every `unsafe` block carries a `// SAFETY:` rationale.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc`, `beam_gc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need; the `beam_gc` edge (wave 1 -> wave 4, downward/legal and acyclic — `beam_gc` never depends on `beam_engine`) is the arena's Tier-B compaction, i.e. `beam_gc`'s region-generic relocator over `beam_term`'s canonical object sizing.
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

- **Atom comparison is name-exact end-to-end** through the defaulted `atoms` live-namespace seam (`beam_rt` overrides the module's load-time snapshot with its ONE live table in both `RuntimeContext` and `BudgetContext`).
- **The `{tr,..}` typed-register operand is NOT implicated in the above -- that path is correct**: the operand readers/writers and the baseline emitter's `x_register`/`y_register` ignore the `Type` annotation; only `Machine::timeout_delay`/`eval_test_arity` reject a typed operand.
- **The collecting host (`beam_rt`) adopts the rooted doors**, and has **no** rooting obligation for the BIF argument window: the engine makes that window collection-free by construction (`Machine::dispatch_bif_call` is `&self`, both rooted doors need `&mut self` plus a `RootSet` borrowed from this machine, and the marshalling's only allocation is the non-collecting `alloc_words`), pinned by `tests/bif_args_window.rs`; the machine's own five loose `Eterm` fields need no host action -- `Machine::with_roots` parks them at the stack tail (see the GC root-set bullet above). Detail: `src/CONTEXT.md` (`## GC publication...`).
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory** (`Machine::refc_binaries` + `send_message_with_off_heap`); `Machine::retain_refc_binaries(keep)` drops the handles a reachability predicate rejects and `Machine::off_heap_overhead_bytes()` reports the backing-store bytes that feed `beam_gc::BinVheap::triggered`. Field-level detail: `src/machine/CONTEXT.md`.
- **Pre-emption exists; scheduling does not** (the defaulted `ExecutionContext::reduce` hook, charged by both tier drivers; the scheduler, run queues and trap handling are Stage 5, `beam_process`).
- **A synthetic module's never-cached label map costs one `Arc` allocation per `run_*` entry**: **+16 % of the `engine_bench` `setup/empty` floor**, `0/10` paired rounds in its favour; a real module (load-time digest) never takes that route (`MEASURED.md`).
- **A map `is_eq_exact` costs O(k log k) and two heap `Vec`s per comparison** (no map fast path in `eval_test`; `beam_term`'s `cmp_maps` collects and re-sorts both maps' pairs) -- detail: `src/families/maps/CONTEXT.md`.
- **Small-int arithmetic (`+ - *`, `band`/`bor`/`bsr`) is inlined only by the native baseline tier**; the **interpreter has no arithmetic fast path** -- every `gc_bif` goes out through `exec_bif` -> `ExecutionContext::call_bif` -- detail: `src/interpreter/CONTEXT.md`.
- **A captured stacktrace is engine-derived unless the raise supplied one** — a derived trace is cooked from the raise-time `raise_snapshot`, a supplied one (symbolic frames, or the trace term of a re-raised exception) is preserved verbatim and no re-raise-site frame is prepended — **and nameable atoms are required** (`catch_end` needs `EXIT`; no path substitutes a *different* atom). Detail: the supplied-trace bullet below and `src/families/exceptions/CONTEXT.md`.
- **The uncaught frames exist only for a `BeamError::Raise`** (`beam_common`'s reason variants are fieldless and carry no `StackTrace` slot).
- **Records.** The whole native-record set executes; `PutRecord`'s create form works for the running module's own `Recs` and for a **foreign** `{Module,Name}` id through `foreign_record_definition` (exported definitions only, else the C's `error:{badrecord, Id}` raise), with the `Ok(None)` host keeping the typed `unsupported` and no `code:ensure_loaded/1` trap. Two divergences in that family are open: `is_record_accessible`'s wildcard arm compares the definition module against the `Scope` **operand** where `emu/ops.tab:1675` substitutes `$MODULE`, and `put_record`-update / `update_record_id` / `get_record_field` raise `function_clause` where the C's `$FAIL_HEAD_OR_BODY` `NO_FAIL` path raises `{badfield,…}`/`{badrecord,…}`. Detail: `src/families/records/CONTEXT.md`, `tests/gaps.rs`.
- **Bitstrings.** `bs_init_writable` builds 0 bits over a capacity-carrying refc payload (the `x(0)` hint, else `DEFAULT_WRITABLE_SIZE = 1024`) registered writable **on the machine**; a **first-position** `private_append` appends **in place** and an outgrown payload **grows**, so the accumulator loop is amortised (64 KiB from a 1 KiB hint: 2 grows + 4 moves, 61 440 bytes copied -- `create/grow_tests.rs`); every other shape promotes to the byte-identical copy-rebuild.
- **Bitstring residuals are typed results only, never a wrong value** (no term-level `BIN_FLAG_WRITABLE`/`_ACTIVE_WRITER`, no shrink-on-escape, unmodelled `binary:referenced_byte_size/1`, `as_bytes()` reports the reservation); the full list and the `beam_alloc` `set_len_written` handoff: `src/families/bitstrings/CONTEXT.md`; detail also `INSTRUCTION_SURFACE.md`.
- **Contract A.9 rung L4 (`a9_selfhost_probe.sh ladder`) COMPILES `beam_flatten.erl` with the tree's own OTP-30 `compile.beam`, and the emitted `Code` chunk is byte-identical to the OTP-29 `erlc` oracle's apart from one byte.** The whole artifact diff is 17 bytes: `beam_dict:highest_opcode` (`beam_asm:reject_unsupported_versions/1` deliberately bumps it to `executable_line/2` = 183, which the OTP-29 compiler never does — a trivial OTP-29-compiled module reports 181) plus the `-vsn` attribute, which `beam_asm:module_md5/1` derives FROM the chunk binaries and therefore inherits that byte. The rung's "FAIL — an artifact was produced but it DIFFERS" verdict is a **rung-baseline artefact** (two compiler versions compared byte-for-byte; no OTP-30 `erl` exists on the host to give a same-version baseline), not a runtime divergence. The former `v3_core:ubody/2` crash no longer reproduces: `v3_core:module(Fs,[])` returns `{ok, #c_module{}, []}` and the minimal forms repro round-trips.
- **L4's throughput, not its correctness, is the open A.9 blocker on this path.** In-process compiling the tree's own compiler sources is ~2 orders of magnitude too slow: a 17.7 KB synthetic 300-function module takes **8.9 s** (`erlc` 0.20 s), `beam_ssa_dead.erl` (55 KB) and `beam_types.erl` (75 KB) exceed **150 s**, and `v3_core.erl` (193 KB) exceeds **900 s** (`BLOCKING_PUMP_DEADLINE`). Records are NOT the cause (a `-record` twin and a tuple twin take 8.9 s / 7.5 s). `v3_core.erl` is not oracle-comparable either — the OTP-29 `erlc` rejects it.
- **Printing a native record is the wrong debugging instrument here.** `io_lib:format/2,3` is a `beam_bifs` **native fast path** (`src/io.rs::format_lib_2` → `src/print/pretty.rs` → `src/print.rs::render_chunk`), so it contributes no `io_lib` frames to a trace, and `render_chunk` has no `RECORD_SUBTAG` arm — it falls through to `Err(badarg())` (`src/print.rs:655`), so `~w`/`~p`/`~P`/`~tp` of a **native record** raises a bare `badarg` even though the real `io_lib_pretty:print/4` on the same runtime renders it correctly. An AST dump through `~P` therefore fails silently before printing; print a shallow tag (`element(1,E)`-style) instead.
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order, and a `NO_FAIL` failure of `test`/`select_val`/a map read raises class `error` with the bare atom `function_clause` from the running module's own atom table.
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by the engine's own opcode coverage; the owning crates are `beam_bifs` and `beam_rt`, NOT this crate.
- **Compiled arithmetic is oracle-exact on overflow** (`+ - * div rem` promote to exact bignums, as does an out-of-range integer operand).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after**, never `free ++ args`.
- **The `call_fun`/`call_fun2` free-variable copy is sound for a *collecting* host because the target is re-read after the seam**, not because no admission point happens to intervene: `FunSource::read` re-derives `fun` immediately before `terms::fun_free` borrows it, `register_args` re-collects `x(0..arity)` for the `apply_fun_outcome` fallback, and nothing allocation-capable lies between the read and the `set_x` writes (`tests/fun_seam_rooting.rs` proves it under a seam that collects); the five loose term fields (incl. `pending_exception`'s reason) are likewise live roots by construction (`Machine::with_roots` parks them at the stack tail, see the GC root-set bullet), so the only remaining publication gap of that kind is host-side.

## Memory footprint inventory (what a long-lived runtime accumulates)
Byte figures are exact for a 64-bit word; **nothing here is freed except by a `Drop`** — the arena's regions are the one case a *host* can trigger that drop early (its two reclaim tiers); everything else waits for its owner.
- **`MinimalContext` arena** (`src/context.rs:1450-1577`): a `Vec<ReservedHeap>` that grows by `push` and is trimmed only through `heap_rewind`/`reclaim_heap`. First reservation `HEAP_RESERVE_WORDS` = 4 MiB / 524 288 words (`:1404`), committed 64 KiB (`:1410`), every later region reserved at **double** the previous (`:1566-1577`) → 4, 8, 16, 32, 64 MiB …; `ReservedHeap::new` takes the whole reservation as ONE dedicated carrier `mmap` (`beam_alloc/src/reserved_heap.rs:169-170` → `allocator/core.rs:240`), anonymous and lazily faulted, and **nothing zero-fills it** (`carrier.rs:53-58`; only `alloc_zeroed` writes). RSS therefore tracks the words actually handed out: `heap_available` = `usize::MAX` (`:1904`), `ensure_heap` a no-op (`:1893`), no collection. The arena's demand **is** observable — `heap_stats` reports the region count, the summed reserved/committed/used/live/peak words and the frontier's own figures, `heap_mark`/`heap_mark_matches` record and validate the allocation frontier, and `for_each_heap_region` walks every region's written prefix — and a host can now **bound** it: Tier A (`heap_rewind`) drops the regions above a mark with a real `Drop` (releasing their carriers) and Tier B (`reclaim_heap`) collapses the whole grid into one compacted region. Measured: 400 000 words → **+2.4 MiB RSS** inside one 4 MiB region (`MEASURED.md:61`).
  **What a reclaim now has**: the engine derives each region's `(base, used)` geometry itself, registers it in a `beam_gc::FromSet` (`FromSet::from_ranges`, the region-generic public door), deposits a Cheney copy into a destination `ReservedHeap` it then installs as the sole region, and drops the old grid; the roots are the **host's**, forwarded through the sink it passes in. **`reset` alone reclaims no RSS** — a region's carrier `mmap` is released only by `Drop` (`reserved_heap.rs:428-433` → `beam_alloc/src/carrier.rs:28-30`), which is why both tiers *drop* regions instead of rewinding them. `args_scratch` and `refc_binaries` stay outside every root door. Design/detail: `src/context/CONTEXT.md`.
- **`Machine`** (`src/machine/mod.rs:714`): the two 1024-word register files are **8 KiB each, allocated eagerly** (`registers.rs:39,49`, `:337-353`); every other vector (`stack`, `frames`, `catch_frames`, `contexts`, `refc_binaries`, `args_scratch`, `label_maps.entries`) is `clear`/`truncate`d and **keeps capacity** — the resident footprint is the high-water mark of the heaviest run the machine ever executed, freed only by dropping it (`src/machine/CONTEXT.md:252-258`). The label-map LRU is **32 entries per machine** (`label_cache.rs:160`), each pinning its `Arc<Module>` (`:199`), and the host's pool holds up to 32 machines.
- **Baseline JIT** (`src/jit/`): one `CodeBuffer` **per compiled function** (lazy layout, `baseline/emit/compile.rs:164-177`) sized `function_capacity_estimate + sub_blocks + DEFAULT_CAPACITY` (64 KiB, `emitter/mod.rs:108`) rounded up to pages — ≥64 KiB of *address space* per entered function, RSS = the pages the emitter writes (corpus: **306 024 443 emitted bytes / 3 113 483 instructions ≈ 98 B per IR instruction**, `MEASURED.md:147`). Each artifact also retains `entries` + `sub_entries` = **16 B per instruction** of block tables (`baseline/code.rs:155-176`) plus the module-wide label map. The per-thread `CODE_CACHE` is a `HashMap` with **no eviction** (`jit/cache/mod.rs:131,463`), so every module ever run on that thread stays mapped.
- **Lowered IR** (`beam_loader::Module`): `Instr` is pinned at **64 bytes** (`beam_loader/src/instr.rs:1205`), the line table adds 8 B per instruction (`ir.rs:186-192`), a block 24 B (`ir.rs:110-117`) → **≈ 72-80 KB per 1000 instructions**; a label map is 8 B/label (`interpreter/mod.rs:140`; `lists.beam` = 1257 labels / 247 functions, `erl_parse.beam` = 5600 / 918) and is **built per machine**, never shared across machines.

### The arena (`ContextHeap`) is measurable, and reclaimable on the host's terms
The production instance is `beam_rt::Runtime::arena: MinimalContext` (`beam_rt/src/runtime.rs:391`); `MinimalContext` reaches the heap through **three** methods only — `ensure_heap` (no-op, `context.rs:1893`), `heap_available` (`usize::MAX`, `:1904`) and `alloc_words` (`:1918`) — and does **not** override `alloc_words_rooted`/`ensure_heap_full` (`:1859`), so both rooted doors default onto `alloc_words` with the roots discarded.
- **Observable and, through `src/context/reclaim.rs`, reclaimable**: `ContextHeap::stats`/`mark`/`for_each_region` are the private half of `MinimalContext::heap_stats`/`heap_mark`/`heap_mark_matches`/`for_each_heap_region`, so the region count, the committed/used/live/peak words and the frontier position are all observable and every region's written prefix is walkable. Tier A (`heap_rewind`) is **purely mechanical**: it drops every region above the mark (real `Drop`, the only path that releases a carrier `mmap`) and resets the survivor to `mark.used` via `reset()` + `unsafe alloc_words(..)`; the caller asserts nothing reachable lies at or above the mark. Tier B (`reclaim_heap`) derives each region's `(base, used)`, builds a `beam_gc::FromSet`, deposits a Cheney copy straight into a destination `ReservedHeap` reserved at the copy **bound** (`Σ used`), then drops the whole old grid and installs the survivor as the sole region.
  A post-copy memcpy into a right-sized survivor would be **unsound**: the relocator's marker protocol writes the destination address into every copied child slot, so moving the copies again would strand every interior pointer.
  `ReservedHeap::relocate` (`:228`) stays deliberately unused (a rigid delta, not a compaction, and interior pointers cannot be identified without term knowledge).
- **Every refusal is decided before the first copy**: `BadArg` for a stale/foreign/forward mark, the typed `heap_exhausted` for a destination smaller than `Σ used`, `Ok(None)` when there is nothing worth doing; an `Err` from the host's `forward` leaves the arena in a **defined empty** state (the host then abandons the arena's words and its own roots). Both success paths bump the epoch, so every pre-call mark is refused by both tiers and by `heap_mark_matches`.
- **The engine exposes root enumeration that matches what it roots**: `Machine::for_each_root` (`machine/mod.rs`, beside `with_roots`, pinned by `machine/root_tests.rs`) enumerates the pointer-bearing words of `x[..used_x_extent]`, the whole stack, `fr[..used_fr_extent]` and the five loose heap terms — exactly what `with_roots` roots, since the complete `Eterm`-typed field set is `x`/`fr`/`stack` + 5 loose terms + `class_atoms` (immediates) + `args_scratch` (`src/CONTEXT.md`) — and its relocating twin `Machine::for_each_root_mut` hands the same coverage as mutable slices, one at a time, so a compaction can forward them. `args_scratch` is **taken out of the machine** for the whole `dispatch_wide` call (`interpreter/CONTEXT.md`), and that window cannot collect (`dispatch_bif_call` is `&self`), so it needs no enumeration — an invariant pinned by `tests/bif_args_window.rs`.
- `beam_rt`'s nearest complete enumeration is `RunnerState::gather_off_heap_roots` (`runner/entry.rs:488-515`): arena-stable spawn args + a fun entry + each parked **unpublished** machine's whole `RootSet`; it skips a *published* machine ("the process's registers hold the relocated truth"), which is a hole for the arena — a pinned/halted pid's fallback allocation leaves arena words in its registers.
- **The crate now contains two relocating heaps**: the production `ContextHeap::reclaim` (Tier B, off the hot path and never automatic) and the test mock `terms/alloc_tests.rs`'s `MovingContext` (`:257-441`) — a semi-space copying collector behind `alloc_words_rooted` with per-**allocation** block bookkeeping (`Block { offset, size }`, `:195-201`), root-set mark/trace, a compacting copy, a root rewrite, an interior-pointer rebase keyed only by "a list/boxed word whose address lands in a known block" (`pointer_addr`/`relocate_term`, `:185-227`) and poisoning of the vacated region. `ContextHeap` has no per-allocation metadata (so `for_each_heap_region` can hand out raw words only), which is why the real tier relies on `beam_gc`'s canonical object sizing instead of a conservative word scan.
- **The one production move-and-republish path is the writable-binary payload**, not a heap region: `raw::InPlace::grow` (`families/bitstrings/raw.rs:845-867`) → `Machine::grow_writable_payload` (`machine/mod.rs:1462`) → `republish_over` (`raw.rs:682`) rewrites the `[BinRef][ErlSubBits]` pair and the registry key, and refuses when `payload_aliased_elsewhere` (`raw.rs:654`) finds a second on-heap naming pair in `x`/`fr`/`stack`/`pending_exception`. That guard is the shape any arena compaction needs: reachable references enumerated, unknown holder ⇒ refuse.
- The two reclaim precedents live in `beam_rt`, not here: the pooled BIF heap's **mark + copy-out + `Heap::reset_to`** (`context/pool.rs:24-66`, `context/calls.rs:1480-1521`, `beam_alloc/src/heap.rs:92-150`) and the `-eval` store's **window + reachability descent + `pin`** (`eval/scratch.rs:54-115`). The arena's own tiers need neither: Tier A is a region-grid truncation, and Tier B drives `beam_gc`'s public region-generic relocator (`beam_gc::compact`/`Relocator`/`LinearDest`/`FromSet::from_ranges`) — that is what the `beam_engine → beam_gc` dependency edge (wave 1 → wave 4, acyclic) is for.
- `beam_gc`'s walker is **region-generic in algorithm but crate-private in plumbing**, and has **no conservative word scan** (a fabricated object start is unsound); a foreign region grid is unreachable from it today (`beam_gc/CONTEXT.md`) — `Runtime::for_each_off_heap_region`'s former complaint about the arena's missing word-range accessor (`beam_rt/src/runtime.rs:3009-3012`) is now answered by `MinimalContext::for_each_heap_region`, which hands out exactly that prefix (it is still only a *prefix* walk: the visitor gets raw words, not terms).
- **A nested-run watermark rewind does not bound this workload**: the `-eval` compile's whole 1.2e9-word demand is spent inside **one** run (`compile:file/2`'s machine; callees enter in-machine via `resolve_external_call`, and `beam_engine`'s fun/lists keys go through the pooled BIF heap), so a rewind at the run's exit is too late — the same compile on the **scheduled** route (a real process heap + the collector) reads `arena_words` **58 031** instead. See `MEASURED.md`.

## Heap admission & allocation wiring (the exact engine->host doors)
- **`test_heap`/`allocate_heap` -> `Machine::ensure_heap` (`src/machine/frames.rs`) -> `ExecutionContext::ensure_heap_full`** with the whole `RootSet` (x, stack **and fr**); the interpreter's two arms and the native tier's `jit_allocate_heap`/`jit_test_heap` are the only call sites and **the two tiers do not differ**, so a collecting host sees one admission point per execution with the same operands. The narrow `ensure_heap` has **no** engine call site, and the `test_heap Live` operand is only a hint (`RootSet::live_len`).
- **`Instr::Allocate` makes no heap request at all** (frame-only, `jit_allocate` -> `Machine::push_frame`), which also skips C's heap check (C's `allocate` can collect) -- a conservative divergence; `gc_bif`/`bif`/`bif0`/`call_ext*` likewise leave term allocation to the host's `call_bif`.
- **All term allocation goes through `terms::reserve` -> `Machine::alloc_rooted` -> `ExecutionContext::alloc_words_rooted`** with the same full `RootSet`. The JIT **never inlines an allocation**: those opcodes are family-owned and routed to `jit_family`, i.e. one Rust call-back per built term on both tiers; `rbx` is only the `machine.x` base, never a heap pointer.
- **The one unrooted runtime allocation** is a non-small `Operand::Integer`/`Character` operand (`terms::make_integer_unrooted` -> `ctx.alloc_words`); `alloc_words` has **no** admission point. The classic (unrooted) `make_*` builders are `beam_rt`'s/tests' API, not the engine's own arms.
- **The engine makes no collection decision.** `arm_gc`, `should_collect` and `collection_debt` have **no occurrence anywhere in this crate** -- the latch, the occupancy test and the collector are all `beam_rt`'s; the engine's only capacity input is the `heap_need`/`n` it passes, and `heap_available` is never consulted.
## Heap-region ownership & invalidation (what is freed, and when)
The engine owns exactly four kinds of raw memory: the arena's `Vec<ReservedHeap>` regions (`ContextHeap`), the `Machine`'s word buffers (`x`/`fr`/`stack`/`args_scratch` `Vec<Eterm>`), the off-heap `beam_alloc::RefcBinary` payload handles (`Machine::refc_binaries` + the `writable_payloads` registry), and the baseline tier's executable `CodeBuffer` mappings.
- **One `Drop` impl outside test code: `CodeBuffer`** (`src/jit/emitter/mod.rs:572-583`, `munmap` of its code mapping). `ContextHeap`, `MinimalContext` and `Machine` have **none**, so the arena's region grid is freed only when the owning `MinimalContext` drops (`Vec<ReservedHeap>` → `beam_alloc::ReservedHeap::drop`) and a machine's buffers only when the machine drops.
- **Only a `Drop` frees arena words, and only a host triggers it early.** `ContextHeap::new` appears only in `MinimalContext::with_bif_hook` (`src/context.rs:1937`) plus the test-only `with_geometry`; `regions` is `push`ed by growth and `truncate`d/`clear`ed by `heap_rewind`/`reclaim_heap`, whose dropped `ReservedHeap`s release their carriers. `ContextHeapStats::used_words` stays cumulative demand across both, and `live_words` is the live figure.
- **`Machine::reset` is logical, and only at a slice START** (`run_label_outcome`, `src/machine/run.rs:388`): it clears frames/catch frames/`contexts`/`local_callees`/`raise_snapshot` and refills the register files only when their length changes; it deliberately never touches `refc_binaries`/`writable_payloads`/`label_maps` (`src/machine/registers.rs:331-442`). `resume_outcome` does not reset at all, and an unwind only `truncate`s `frames`/`stack` (`src/machine/catch.rs:357,364`, capacity kept).
- **The one mid-life free of an engine-owned term region is the writable-binary relocation**: `Machine::grow_writable_payload`'s `Moved` arm frees the old payload block, refused while another on-heap pair aliases the payload (`payload_aliased_elsewhere`) so no live `BinRef.val` is left naming freed bytes, then republished (`src/families/bitstrings/raw.rs:845-862`).
- **The arena's grid is registrable in `beam_gc::FromSet` only from inside `ContextHeap`.** `ContextHeapStats` carries no per-region base/used pair and `ReservedHeap`/`Heap` have no `contains`-style predicate (and no shared trait), so `reclaim_heap` builds the from-set itself from the region grid it owns and hands the caller only the `Relocator`. Nothing else can register the grid, and the collector's own substitute for a containment test is `beam_rt`'s **decline** valve.
- **A returned `Eterm` may be a `TAG_LITERAL_PTR` word into the module's `Arc<LiteralArea>`.** `reset` drops the machine's own bindings (`literals`/`entry_literals` → `None`, `contexts.clear()`), so such a term stays valid only while some `Arc<Module>`/`SharedLiteralArea` clone survives; nothing in this crate enforces that.
## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence, each routed to its owning node; **`INSTRUCTION_SURFACE.md`'s `## Handoffs` is the item-by-item detail** (13 numbered items), and the `See Handoff #N` cross-references in this file name its numbering.
Still open: **#1** receive/message + cross-module suspension (`beam_rt`); **#6** `TestKind::TestArity`, behaviourally equivalent to C so not a gap; **#7** map `NO_FAIL` `{badmap,Source}`/`{badkey,Key}`, closed for a seeding host with only the unseeded `beam_loader` path remaining; **#8** JIT `call_ext_last`, which executes natively as a by-design driver round-trip.
**Closed by a defaulted engine seam, residual only at the host:** #4 a *foreign* `PutRecord` create id (`foreign_record_definition`, exported only, no `code:ensure_loaded/1` trap on the engine side).
**Adopted by `beam_rt`, no engine work outstanding:** #9 the baseline tier + the A.8 seam, #10 `resolve_external_call`, #11 the rooted doors, #12 `resolve_local_fun`, #13 `resolve_local_call`.
