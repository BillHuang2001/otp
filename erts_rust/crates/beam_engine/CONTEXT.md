# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step (interpreter-identical semantics), carrying **two layouts behind one `CompiledModule`** (eager whole-module and lazy per-function, so a fresh process pays only the functions it enters).
The **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) is one Cranelift function per IR function over the same shared interpreter-backed helper.
All tiers are **measurement-gated** and off the critical path (Part II sec. F) -- correctness-first *mechanisms*, not optimisers.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end, with explicit dispatch arms for the core opcodes and a per-instruction-family seam (`src/families/`) for the rest.
The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC, process/stack limits and pre-emption all sit behind `ExecutionContext` (implemented by `beam_rt`), keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

**Where the detail lives.** This file is the crate-level *contract*: the frozen API seam, the binding execution semantics, the constraints, the test strategy, and summaries of the gaps/handoffs. The exhaustive surface, the design decisions and the full M1 gap list are in `INSTRUCTION_SURFACE.md`; the subsystem detail is in the child `CONTEXT.md` files under `src/` (routing table below).

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: computation goes through `ExecutionContext::call_bif`, and an in-machine callee through the resolver seams (`resolve_external_call`/`resolve_local_fun`, plus `resolve_local_call` which lets a host serve a **local** callee *as* a BIF), with `ExecutionContext::apply`/`apply_fun` the value-returning fallbacks. `ExecutionContext::atom_name` resolves a runtime atom **value** against the host's live atom namespace.

### The supplied-stacktrace encoder (`src/supplied_stacktrace.rs`)
The **public** `beam_common::StackTrace` -> `Eterm` encoder, for a host that renders a raise's explicitly **supplied** symbolic frames without a compiled handler (the tree-walking `-eval` route of `beam_rt`).
Two entries over the engine's single carve (`families::exceptions::stacktrace::carve_supplied_frames`): the free `encode_supplied_stacktrace(module, ctx, frames)` (it builds a scratch `Machine`) and its `Machine::encode_supplied_stacktrace` twin (the same carve with THAT machine's root set).
Both cook `frames` into the oracle's `[{Module,Function,Arity,Location}]` list (innermost frame first; `Location` = `[{file,File},{line,N}]` when the frame has a location else `[]`) as ONE rooted reservation carved node-by-node (moving-collector safe; the machine is only the reservation's root-set carrier). **The atom source is the passed `module`'s atom table, by lookup only** (nothing is interned), so a host whose atoms live in a shared namespace must pass a `Module` carrying that table (an `AtomTable` clone preserves every index); an unresolvable name is the typed `error::unsupported`, never a substituted atom. Pinned by `src/families/exceptions/tests/encoder.rs`.

### The context seam (`src/context.rs`)
The frozen seam shape is one `pub trait ExecutionContext` of `&mut self` methods over `Eterm`, grouped as: the BIF door `call_bif` plus its in-machine twin pair `wants_bif_in_machine`/`call_bif_in_machine` and the two outcome-aware twins `call_bif_outcome`/`call_bif_in_machine_outcome` (the BIF suspend channel, below); the two GC doors `ensure_heap`/`ensure_heap_full` and `alloc_words`/`alloc_words_rooted`; the introspection-only `heap_available`; the value-returning `apply`/`apply_fun` plus `apply_fun`'s outcome-aware twin `apply_fun_outcome` (the closure-apply suspend channel, below, whose `Suspend` answer parks the machine on the `call_fun`/`call_fun2` instruction); `send_message_with_off_heap`; the four resolvers `resolve_external_call`/`resolve_local_fun`/`resolve_local_call`/`atom_name`; the atom-namespace `atoms`; the reduction pair `reduce`/`wants_reduce`; the record-definition `foreign_record_definition`; and the A.8 pair `trace_enabled`/`trace_event`.
Every one is `Result`-returning except the pure-`&self` probes; **`src/context.rs` is authoritative for the exact signatures.**
`RootSet<'a> { x, stack, fr, live }` is the mutable root set the two rooted doors receive (`live` clamped; `ALL_LIVE = u32::MAX`), and `TraceEvent` is the report enum `Call`/`ReturnFrom`/`ReturnTo`.
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- **The in-machine BIF-dispatch door (`wants_bif_in_machine` + `call_bif_in_machine`).** A host that returns `true` from the probe is handed the live `Machine` and the run's **entry module** (context `0`) on **every** BIF dispatch, so a BIF implementation can read the running process's position from *inside* the call; it **must** then override `call_bif_in_machine` (and `call_bif_in_machine_outcome` if its BIFs can wait -- see *The BIF suspend channel* below). The probe is latched once per run into `Machine::bif_in_machine_on` by **both** drivers, and every BIF dispatch goes through the single `Machine::dispatch_bif_call` funnel, so the door behaves identically on every tier; the default `false` keeps the plain `call_bif` path byte-identical. Tier-parity gate: `tests/bif_in_machine.rs`. Detail: `src/machine/CONTEXT.md`.
- **The GC root-set contract, in two doors.** `ensure_heap(heap_need, live, x_regs, stack)` is the frozen **narrow** admission point; `Machine::ensure_heap` (reached by `test_heap`/`allocate_heap`) calls the defaulted **`ensure_heap_full(heap_need, roots)`** over the whole [`RootSet`] (**including the FR file**, which holds `Eterm` term slots), whose default forwards to the narrow door (byte-identical for a host that predates it). `alloc_words_rooted(n, roots)` is the **term-construction** admission door (`alloc_words` itself has neither an admission point nor roots); its default discards the roots and forwards to `alloc_words`. A collecting host overrides both, relocates every term reachable from the roots, and writes moved terms back through `roots.x`/`roots.stack`/`roots.fr`. The frozen contract: the live roots are `roots.x[..roots.live_len()]`, **the whole** `roots.stack` (no frame liveness maps) and **the whole** `roots.fr`; `live` is only a hint (`RootSet::ALL_LIVE` is always *safe*). Nothing outside the root set survives: a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation.
- **The engine side of that hand-off is `Machine::with_roots` / `Machine::alloc_rooted`.** `with_roots(live, f)` lends the machine's own three files as one disjoint `RootSet`; **every in-crate term-construction arm routes through this seam** via the `terms::*_rooted` builders. Detail: `src/terms/CONTEXT.md`, `src/CONTEXT.md`.
- **`reduce(n)` is the reduction hook** (defaulted no-op): `Machine::drive` charges it **once per interpreted instruction** with `n = 1`, **before** the body runs, so a host with a scheduler enforces a time slice by returning a **typed error** -- the instruction is left **un-applied** with the machine parked on it, so a `Machine::resume_outcome` applies it **exactly once**. It is the only pre-emption point a **non-allocating** loop reaches. **Both tier drivers charge it**: the interpreter per interpreted instruction, the native tiers' shared driver (`src/jit/baseline/mod.rs::drive`, serving `Tier::BaselineJit` **and** `Tier::Cranelift`) once per **driver-loop iteration**. `wants_reduce` latches the decision once per run per driver (a host that implements `reduce` MUST stay `true`); each driver zeroes the slice counter at its entry, and `Machine::reductions()`/`reset_reductions()` expose it. There is **no `RunOutcome::Yield` and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption a fresh `drive`. Detail: `src/machine/CONTEXT.md`, `src/jit/baseline/CONTEXT.md`.
- `apply` is the general synchronous `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the **value-returning fallback** for `call_fun`/`call_fun2` (default a typed `unsupported` -- the engine keeps no closure registry), consulted only after `resolve_local_fun` declines, entering the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables (C's `call_fun` order). Its outcome-aware twin `apply_fun_outcome` (default: forward to `apply_fun`, wrapped as `FunOutcome::Return`) may instead answer `FunOutcome::Suspend`, which parks the machine on the `call_fun`/`call_fun2` instruction (`Step::Suspend` → `RunOutcome::Suspend`); because the resume re-consults the door with the same `fun` and `args`, such a host must **continue** the pending application, never restart it. Both seams' and the fallback's errors route through `Machine::raise_bif_error`, so a routable raise lands in the caller's live `try`/`catch`.
  **`apply` has no outcome-aware twin and no park channel.** Every `RunOutcome` park address (`Wait`/`Suspend`) is a `(func, pc)` into a loaded `Module`'s instruction stream, so a host whose continuation is not a BEAM `pc` (a tree-walking evaluator) reaches the engine through `apply_fun_outcome`, whose suspend is a park on the `call_fun`/`call_fun2` instruction it can be resumed at. `ExecutionContext::apply` has **no engine call site** (`apply_target` dispatches through `dispatch_bif_call`), so overriding it changes nothing on the execution path.
- **`resolve_external_call` -- the cross-module call seam (the `call_ext*` and dynamic `apply` route).** A host that owns loaded modules answers `Some((callee_module, entry_label))` for a `call_ext*` or `apply(M,F,A)` and the engine executes the callee **in the same machine** (so a `receive`/raise inside it suspends/raises this process, instead of routing through the synchronous `call_bif`); `callee_module` must be the **shared** `Arc<Module>` the host loaded it with (contexts dedup by `Arc::ptr_eq`), and `entry_label` is the export entry label (`callee_module.export(function, arity)`, the label *after* `func_info`). Default `Ok(None)` keeps the `call_bif` path. See Handoff #10.
- **`resolve_local_fun` -- the in-machine closure-apply seam (the `call_fun`/`call_fun2` route).** Consulted **first**: a host that owns the closure's defining module answers `Some((callee_module, lambda_entry_label))` and the engine enters the lambda body in this machine, copying the closure's free variables into `x(arity..)` (C's `reg[i + arity] = funp->env[i]` order) and reporting `Step::Enter`; a `receive`/raise inside the closure then suspends/raises this process. Default `Ok(None)` keeps the `apply_fun_outcome` fallback (for fun kinds with no local label: an external `fun M:F/A`, the `-eval` evaluator's closure), which is outcome-aware and may park the machine on the `call_fun`/`call_fun2` instruction instead of failing -- such a host must then continue the pending application. See Handoff #12.
- **`atom_name` -- the runtime atom-*value* resolution seam (the `apply(M,F,A)` / `M:F(...)` route).** `Module::atom_name` indexes the module's **owned load-time snapshot** of the shared atom table, so a module loaded early cannot name an atom interned *afterwards*; `families::funs::atom_name` resolves the runtime `M`/`F` atom **values** through this seam, so a host that owns the live namespace can answer where the snapshot cannot. The name is returned **owned** (`Option<String>`) so the caller can hold both across the subsequent `&mut` host calls. The default body is the module-local lookup only, so every existing implementor is byte-identical; a non-atom, or an id the host cannot name, is the typed `BeamError::BadArg`, never a substituted atom. Gate: `tests/apply_atom_value.rs`.
- **`atoms` -- the comparison atom-*namespace* seam (every guard/`select_val`/map-key comparison).** `beam_term`'s `erts_cmp_atoms` compares atom *names* and falls back to the raw atom id when a name is unknown to the supplied table, so a comparison over the running module's **load-time snapshot** silently orders by id for an atom interned into the shared namespace *afterwards*. This seam is the namespace every comparison resolves names through (`eval_test`'s six comparison kinds + `is_boolean`, `dispatch.rs`'s `SelectVal`, the baseline tier's `evaluate_comparison`, the map-key `lookup`/`position` equality). Default body is `&module.atom_table` -- byte-identical for every existing implementor; a host that owns ONE shared namespace overrides it so atom order matches the `<` BIF (the `sofs:restrict_n/5` divergence). `fn atoms<'m>` borrows `*ctx` **immutably**, so a site takes it after its operand reads and never holds it across a `&mut ctx` call; the JIT inline lowerings decline atom operands for order comparisons. Gate: `src/interpreter/test.rs::comparisons_order_atoms_by_name_through_the_shared_namespace`.
- **`resolve_local_call` -- the local-call *as-BIF* seam (the `Instr::Call`/`CallOnly`/`CallLast` route).** Consulted in the interpreter's three local-call arms (before the in-machine `Step::Goto`) and by the native baseline tier's `jit_local_call` probe, with `(module, function, arity)` recovered from the resolved target's `beam_loader::Function` (an un-nameable or missing entry is a decline). **`Ok(true)` = the host serves this `(Module,Function,Arity)`** -- the engine marshals `x(0..arity)` and dispatches it through `call_bif` under the arm's own frame discipline, exactly as an accepted `call_ext` import does. **`Ok(false)` = the in-machine jump**, byte-identical and mutating nothing. It matters because the OTP compiler emits a **local** call for a **non-exported** same-module function, so a module's non-exported NIF stubs (`erlang:nif_error(undef)` bodies) reach `call_bif` only through this seam. Errors from the seam travel via `?`; errors from `call_bif` route through `Machine::raise_bif_error`. See Handoff #13.
  **The seam is a RUN-TIME consultation, never a compile-time one, and its answer is memoized nowhere.** `JitBackend::compile(&mut self, &Module)` takes no `ExecutionContext` (`src/jit/mod.rs:245`), so a tier structurally cannot ask the host while lowering; the emitted probe (`emit/block.rs::emit_local_call_probe`, `jit/baseline/call.rs::store_continuation`) calls the seam on **every** execution of the block, and nothing caches the verdict — not a compiled block, not `src/jit/cache/`, not the block-ABI immediates, not `Module`/`Function`, not `Machine`. The answer may legitimately change mid-run (`erlang:load_nif/2`), so it is deliberately **not** required to be idempotent — only the callee *identity* (`local_callee_identity`) is memoizable — and a host must price one reduction per consultation (`src/jit/baseline/call.rs:73-77`); `src/jit/CONTEXT.md` forbids the tier short-circuiting the seam on its own.
- **`foreign_record_definition(owner, name)` -- the record-definition seam (the `PutRecord` *create* form for another module's `{Module,Name}` record id).**
  Default `Ok(None)`; `Ok(Some(def))` is the host's record table answering `erl_record.c::erts_record_find_entry`, and the engine builds the instance only when `def.is_exported` holds.
  A non-exported definition is the C's `error:{badrecord, Id}` raise (`erl_record.c:401-409`, via `beam_common.c::expand_error_value`).
  There is no `code:ensure_loaded/1` trap behind this door, so a defining module the host has not loaded is its own `Ok(None)`; the family then reports the typed `error::unsupported("put_record: create: no record definition table for another module")`. Pinned in `src/families/records/tests/` and `tests/gaps.rs`.
- **`call_ext*` special cases (`Machine::resolve_call_ext_apply` / `resolve_call_ext_send`).** The three arms special-case the import `erlang:apply/3` (reproducing C's `fixed_apply` -> `apply()`: decode `x(0..2)`, unwrap the nested `apply of apply/3` shape in a loop, walk the argument list into `x(0..N)` -- past `MAX_ARG = 255` is `error:system_limit`, a non-proper tail the catchable `badarg`) and `erlang:send/2`/`'!'/2` (routed through `send_message_with_off_heap` with the machine's off-heap handles). **Only `apply/3`** is special-cased (matching C, whose `fixed_apply` handles only `arity == 3`); `erlang:apply/2` stays on the ordinary `call_bif` route. Detail: `src/interpreter/CONTEXT.md` (`call_ext_dispatch`, `ImportFrame`).
- **Contract A.8 execution-trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}` / `return_from` / `return_to` shapes; the engine **reports only** -- the host owns matching and term building. Emission (`src/interpreter/trace.rs`, gated on `Machine::trace_on`): `Call` for a local callee on `call*` and for an import on `call_ext*` (**entry only**); at a live `Continuation::Address` return, `ReturnFrom` then `ReturnTo`. Emission is infallible, so a traced run is byte-identical to an untraced one; **a natively-executed JIT block does not trace**.
- `pub type BifHook`/`ApplyHook`/`ExternalResolver`/`LocalFunResolver` -- the pluggable bodies a `MinimalContext` installs via the matching `with_*`/`set_*` builders.
- `MinimalContext` -- the test/embedding context: an unbounded heap, a **pluggable BIF hook** (`new()` rejects every BIF), an **optional apply hook**, **optional cross-module/local-closure resolvers** and an **optional mailbox**. Its heap is a pointer-stable **reserved-heap** arena -- reserved up front and **grown in place**, so an allocation costs its payload only; on exhaustion a fresh, larger region starts and **every earlier region is kept alive**, so a handed-out pointer stays valid and **unmoved**. It does **not** override `alloc_words_rooted`, so it stays the test/embedding heap rather than a collector. Detail: `src/CONTEXT.md`.

### The BIF suspend channel (the host contract for a waiting BIF)
`ExecutionContext` carries two **outcome-aware** BIF doors, one beside each of the value-returning ones: `call_bif_outcome` (`call_bif`'s twin) and `call_bif_in_machine_outcome` (`call_bif_in_machine`'s twin).
Both return `Result<BifOutcome>` and both **default** to forwarding the value wrapped as `BifOutcome::Return`, so a host that predates the channel is byte-identical; `Machine::dispatch_bif_call` takes exactly one of them per run.
A host that answered `true` from `wants_bif_in_machine` is dispatched through the in-machine door only, so it must override `call_bif_in_machine_outcome` to make its BIFs able to wait -- the engine never reaches its `call_bif_outcome`.
`BifOutcome::Return(value)` is the ordinary answer; `BifOutcome::Suspend` means the BIF did **not** complete and the instruction was **not** applied (no destination register written, no guard-failure branch taken, no frame effect).
The park/resume protocol: the engine reports `RunOutcome::Suspend { func, pc }` **at the BIF instruction itself**, the host pumps its own waiting resource, and `Machine::resume_outcome`/`resume_outcome_with_tier` re-enters there -- re-executing the instruction, which re-issues the BIF with the **same operands**, so the caller sees *that* call's value and never a value the abandoned attempt computed.
The host side must be re-execution safe on its own too: a suspending attempt must not consume a one-shot resource.
The rooting argument: the engine holds **no** suspended-BIF state -- no `Machine` field, no saved argument vector, not even the BIF's identity -- because the parked state is `(func, pc)` plus the registers, the Erlang stack and the FR file, i.e. exactly the frozen `RootSet` (`x[..live]`, the whole stack, the whole FR file) a host is handed at every admission point, so a moving collector may relocate the operands and the re-execution re-reads the relocated words.
(The C equivalent is the process-private `c_arg_reg`/`arg_reg` array that `BIF_TRAP_N` writes, saved by `copy_out_registers` and restored by `copy_in_registers` -- `../../erts/emulator/beam/beam_common.c:306`/`:336`.)
**Class A vs class B**: a re-execution-idempotent site (pure operand reads, every write success-only) turns a suspend into the park, while the `erlang:apply/3` route -- which has already walked the argument list into `x(0..arity)` -- reports the typed `unsupported("bif suspend at a non-idempotent dispatch site: apply/3 rewrites x(0..arity)")` instead, because re-executing it would re-read clobbered registers and apply a different call.
Both tiers report and resume a suspend: the interpreter's driver folds `Step::Suspend` into `RunOutcome::Suspend` (`src/machine/drive.rs`) and the native baseline tier carries it out of a compiled block as the `SUSPEND` (`-5`) block-ABI word with its address in the `JitRuntime::suspend` side channel; `Tier::Cranelift` cannot resume at a mid-function `pc` and keeps its existing honest typed `unsupported`.
A **non-blocking** entry (`run_export`/`run_label` and the tiers' non-blocking run) folds a suspend into the typed `error::suspended()` -- never `error::blocked()`, never a substituted value.
Tracing deviation: a `call_ext*` arm emits its `call` event **before** the dispatch, so a suspend on a traced run re-emits that event when the instruction is re-executed.
Gate: `tests/bif_suspend.rs`.

### The closure-apply suspend channel (the host contract for a waiting closure application)
`apply_fun_outcome` is the outcome-aware twin beside the value-returning `apply_fun`, returning `Result<FunOutcome>` (`Return(value)` / `Suspend`) and **defaulting** to forwarding that value wrapped as `FunOutcome::Return`, so a host that predates it is byte-identical (an unimplemented `apply_fun` still answers `unsupported("apply_fun")`).
It exists for the same reason as the twin BIF channel, one level down: a host that **interprets** the closure itself (a tree-walking `-eval` evaluator) has no way to park its caller when the body must wait, and `apply_fun` can only answer a value or an error.
`FunOutcome::Suspend` means the application did **not** complete and the instruction was **not** applied; the engine parks on the `call_fun`/`call_fun2` instruction (`Step::Suspend`, `RunOutcome::Suspend`) and the resume **re-consults this door with the same `fun` and `args`**, so the host must **continue** the pending application and never restart it (an evaluator body is not re-execution idempotent) -- the one respect in which its contract is stricter than `BifOutcome`, whose re-issued dispatch re-runs the BIF from its operands.
Gate: `tests/fun_suspend.rs`.

### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
`pub trait Mailbox` is exactly nine `Result`-returning methods: `send_message`; the scan position `receive_next` (the candidate at the position, `None` = exhausted), `receive_skip` (`loop_rec_end`, advance one), `receive_remove` (`remove_message`, unlink the candidate then reposition at first) and `receive_reset` (`timeout`, reposition at first); and the four marker calls `receive_marker_reserve`/`receive_marker_bind`/`receive_marker_use`/`receive_marker_clear`.
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")`, so every implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- **The engine never inspects a message or a marker**: selection is the compiled code's job (the matching instructions between `loop_rec` and `loop_rec_end`), and a marker term is **opaque** (produced by `receive_marker_reserve`, handed back verbatim by `receive_marker_bind`; only a separate *reference* reaches `receive_marker_use`/`receive_marker_clear`). Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still surface the typed `error::blocked` (Handoff #1).
- **`send_message_with_off_heap(to, message, src_binaries)`** is the `Instr::Send` arm's entry **and** the `call_ext*` `erlang:send/2`/`'!'/2` case's entry: a tenth defaulted `ExecutionContext` method whose default **forwards to `send_message` and discards `src_binaries`**, so every existing implementor is byte-identical. `src_binaries` is the **source off-heap table** the receiver-side copy needs to resolve an engine-built off-heap (refc) binary in the message. See the off-heap Known-Issues bullet.
- **Ordering invariant (the host contract this driving relies on).** `receive_skip`/`receive_remove`/`receive_reset` take **no candidate argument** -- the host acts on its **own** persistent scan position, so the driving is correct only while that position is stable between the `loop_rec` that produced a candidate and the `remove_message`/`loop_rec_end` that consumes it; that holds by construction (between those two the engine issues no other seam call and never blocks). A `receive` reaches `wait`/`wait_timeout` **only** via `loop_rec`'s `None` arm (the scan is already **exhausted**), so a `resume_outcome` re-entry sees only messages appended since. Host contract: FIFO with a **saturating** scan index (`beam_message::QueueCursor` + `beam_rt::MailboxState`). Detail: `src/families/CONTEXT.md`, `tests/receive.rs`.

### The machine (`src/machine/{mod,registers,frames,catch,run,location,context,drive}.rs`)
`Machine` is the process-state core: the x-register file (`MAX_REGISTER = 1024`, C's `MAX_REG`), the float-register (FR) file (`MAX_FLOAT_REGISTER = 1024`, holding **`Eterm` term slots**), the Erlang stack, the call-frame and exception catch-frame stacks, the `refc_binaries` arena (never cleared by `reset`, host-prunable through `retain_refc_binaries`), the running module's decoded **literal area**, the **module-context registry** (`contexts` + `context` + `entry_literals`), the reduction counter, the **raise-time snapshot** `raise_snapshot`, the latched A.8 gate `trace_on`, and the per-module **label-map cache** (`label_maps`, `src/machine/label_cache.rs`).
- **The label-map cache (`label_cache.rs`).** `build_label_map` is a whole-module value (one traversal per function plus the module's entire import table) and a pure function of the module's immutable content, so `Machine::label_map(&mut self, &Module)` / `Machine::label_map_arc(&mut self, &Arc<Module>)` answer one cached `Arc<LabelMap>` and build only on a miss. The key is **identity, never content**: `Module::checksum()`'s `Digest` + `Module::atom_table`'s `AtomSnapshot` + the module address. A synthetic image (all-zero checksum) is **never cached**; a second load of one `.beam` and a `Module::clone` each mint a fresh atom-table identity and so are a **miss** (one extra build, never a wrong map); the entry survives `Machine::reset`, and the `Arc` route holds the handle so its address cannot be recycled. Pinned by `src/machine/label_cache_tests.rs` (the `interpreter::label_map_builds()` tally) over the seven `label_cache.rs` unit tests; measured in `MEASURED.md`'s label-map-cache section.
- **Run entries (`run.rs`).** `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware; `RunOutcome { Returned(Eterm), Wait { func, pc }, Suspend { func, pc } }`), plus the tier-aware `run_with_tier`/`run_export_outcome_with_tier`/`run_label_outcome_with_tier`/`resume_outcome_with_tier`. `run_export` resolves `function/arity`'s export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return`, yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error. The loop is `run_loop`/`run_loop_with_map` (`src/interpreter/dispatch.rs`), thin wrappers over `Machine::drive`.
- **The uniform raise funnel (`catch.rs`).** `throw`/`throw_error`/`throw_with_trace` are the raise/unwind entries the families call; `throw_with_trace` first **rebuilds the raise-time frame snapshot** (the **raising** frame from `current_code`/`current_context`, then every live caller innermost-first, each in its own module context) *before* any unwind, so it survives on **both** the caught and the uncaught path. The symbolic `StackTrace` an **uncaught** raise carries is attached not at the raise site but by the single funnel `Machine::with_uncaught_frames(err, entry_module, func, pc)` as the raise leaves the machine (at the `step_instruction`/`drive` boundary), so **every** raise kind gets the same frames -- only when `raise.stacktrace.is_empty()` and the reason is not an engine diagnostic. A **caught** raise carries no symbolic trace; the same raise-time snapshot is what `Instr::BuildStacktrace` cooks into the `try … catch C:R:S` binding.
- **Module contexts (`context.rs`).** A `call_ext*` the host resolved through `resolve_external_call` executes the callee **in this machine**, so `(func, pc)` are indices into *another* module's table and the machine must remember which. `Contexts` registers/dedups a `ModuleContext { module: Arc<Module>, labels }` by `Arc::ptr_eq` (context `0` is the run's **entry** module, which the machine never owns -- `entry_literals` records its literal area). `switch_context(id)` re-binds `literals` and an unregistered id is the typed `error::unsupported`. `reset` clears the set; a **resume does not** (a suspended cross-module frame must still name its module).
- **Introspection (read-only).** `x(n)`/`get_fr(n)`/`fr_mark()`/`y(k)`/`frame_depth()`/`stack_depth()`/`catch_frame_depth()`/`pending_exception()`/`pending_exception_mut()`/`pending_class()`/`resumption_addresses()`/`resumption_contexts()`/`raise_snapshot()`/`wait_deadline()`/`reductions()`/`reset_reductions()`, plus the execution-position accessors (`current_code`/`entry_call`/`current_function`/`initial_call`/`current_location`/`current_stacktrace`/`current_module`, the engine half of `process_info/2`). Per-file roles: `src/machine/CONTEXT.md`.

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func, pc }, Enter { context, func, pc }, Wait { func, pc }, Suspend { func, pc }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`/context. `Next` = continue at `pc + 1`; `Goto` = jump **within the current module**; `Enter` = transfer to `(func, pc)` in another module context (a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address`, or a raise landing in another context's live catch frame) -- the driver switches context and re-binds the literal area exactly here; `Done` = finish and yield `x(0)`.
- `Wait` is the **receive** suspend signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. `Suspend` is the **BIF** suspend signal (see *The BIF suspend channel*): the instruction was **not** applied, so the reported address is the instruction itself and the resume re-executes it; the JIT driver carries it as `SUSPEND` and folds it into `error::suspended()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto`/`Step::Enter` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which **routes by the instruction's own variant** to the single owning family -- a `match instr` that compiles to a jump table on the `Instr` discriminant. Family ownership is **disjoint** (each of the **77** claimed variants has exactly one owner: `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`).
- Each family exposes `pub(crate) fn exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = "executed", `Ok(None)` = "not this family's variant", `Err` = the family raised. A variant **no** family owns or one a family declines falls to the router's last arm: `error::unsupported("widened opcode not yet executed: <ops.tab name>")` (an unclaimed opcode is diagnosable from the error alone). Per-family variant ownership and gaps: `src/families/CONTEXT.md` and its child nodes.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,slack,sink,alloc_tests,tests}.rs`) -- the SAFETY-annotated builder/reader
The crate's single point of raw-heap access, over the `alloc_words`/`alloc_words_rooted` seam:
- Each builder comes in **two flavours**: the **classic** public builder (`make_tuple`, `make_cons`, `make_list`, `badmatch_reason`, `make_heap_binary`, `make_float`, `make_integer`, `make_flatmap`, `make_map`, `make_fun`) allocates through the plain `alloc_words` and takes already-materialized operands (the frozen cross-crate signature `beam_rt` and `tests/**` consume); its **`*_rooted` twin** takes `machine`/`ctx`/`live` plus a `read` closure and reserves the block **before** reading operands (the frozen reserve → read → write discipline), so a **moving** collector may relocate them in between. **Every in-crate construction arm uses the rooted twin.** `src/slack.rs` is the reserve/bump-carve; `src/sink.rs` is the `Sink` shape writer a multi-node graph is carved from without a second allocation.
- `make_map(ctx, &[(Eterm, Eterm)], atoms)` builds a map of ANY size over `beam_term::map::map_words_capacity`: a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys, else a **hashmap** (HAMT), duplicate keys collapsing last-wins. Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`, never a panic) cover the tuple/cons/list/float/map/binary accessors plus the fun readers (`is_fun`/`fun_arity`/`fun_num_free`/`fun_uniq`/`fun_index`/`fun_free`/`fun_true_arity`); `map_entries` walks both map layouts; `fun_arity` is the 8-bit header field (saturating at 255) while `fun_true_arity` returns an external fun's real arity. Full API: `src/terms/CONTEXT.md`.

### The JIT tier seam (`src/jit/`)
- `Tier { Interpreter, BaselineJit, Cranelift }` (`Tier::ALL` = roster order, interpreter first) with `name()`/`from_name()`/`is_available()`; `available_tiers()` = `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` when the feature is on.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>` (the artifact is **caller-owned**, hence `&self`); plus the provided `run_export`. The interpreter is deliberately **not** a `JitBackend`.
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`) -- the **non-blocking** tier entries (`Result<Eterm>`; a suspend folds to `error::blocked()`): `Interpreter` -> `run_export`; `BaselineJit` -> `run_baseline_cached`; `Cranelift` -> `run_cranelift` when the feature is on, else the typed `unsupported("jit-cranelift tier not built")`. `run_export_outcome_with_tier`/`run_label_outcome_with_tier` are the **outcome-aware** twins and `resume_outcome_with_tier` the **resume** twin: a slice that suspended re-enters on the SAME tier, so the tier survives a `receive` park (the baseline resume driver does **not** reset the machine and serves a slice parked in a **non-zero module context** too). `Tier::Cranelift` cannot resume at an arbitrary mid-function `pc` (a resume is handed no compiled artifact and the tier has no path that would compile and bind one at a parked address on demand), so it reports the honest typed `unsupported` -- never a silent interpreter fallback. A `receive` park crosses the block ABI as a `WAIT_BIT` word and a BIF suspend as the `SUSPEND` (`-5`) word with its address parked in `JitRuntime::suspend`.
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier. `src/jit/tiering.rs`'s `TierPolicy` models the *interpret → baseline → hot* escalation as a **policy only** (no execution path consults it).
- `src/jit/cache/` (`mod.rs` + `key.rs` + `tests.rs`) is the **cross-run compiled-block cache**, keyed by the two-part `CacheKey` — the module's `ModuleKey` (the **load-time MD5** for a real `.beam`, else a fingerprint over the decoded IR) **plus** `Module::atom_table.snapshot()`, an O(1) allocation-free witness of the atom namespace the code was lowered against (the baseline tier bakes atom **indices** into its emitted code). Two separately loaded copies of one `.beam` — or a `Module::clone`, since `AtomTable::clone` mints a **fresh** identity — are two entries (an extra compile at worst, never a wrong answer); a stale generation recompiles. `baseline_code_map(&Module)` exposes the **real** generated ranges for a host's `+JPperf` map. The cache is per-thread and backs `run_baseline_cached*`/`cached_module_blocks`. Detail: `src/jit/cache/CONTEXT.md`.
- **The block ABI, the register picker, the two artifact layouts, the continuation sub-blocks and the baseline inlined shape set are documented in `src/jit/CONTEXT.md`, `src/jit/baseline/CONTEXT.md` and `src/jit/baseline/emit/CONTEXT.md`** (the authoritative source). Headline: every un-lowered instruction (or an inline whose run-time guard rejects) **deopts to one interpreter step** (`jit_step_one` == `Machine::step_instruction_with_entry`), so a tier is interpreter-identical for every supported opcode and the interpreter's exact error surfaces stand; a **traced** run refuses native entry entirely. The tier seam's one **run-time** host consultation is the local-call seam (see the `resolve_local_call` bullet above); both tiers are pinned equal on the served and declined routes by `tests/local_call_seam.rs`.

### The dynamic execution-census instrument (`src/exec_census.rs`)
`pub mod exec_census` — a **measurement-only** per-variant counter: it is on no execution path, changes no result, and costs one thread-local `bool` load per hook while disabled.
Its surface is the gate `enable`/`disable`/`is_enabled`, `reset`, `snapshot()`, `write_dump(section)` (`$TMPDIR/beam_engine_exec_census_<section>.tsv`) and `variant_name(&Instr)` (`"Move"`, `"Test(IsEqExact)"`, …); `Snapshot` carries the per-variant `executed`/`errors` maps, `first_error` per name and the two totals.
- **One recording site.** `Machine::step_instruction_inner` — the single per-instruction funnel the interpreter's `Machine::drive` **and** the native tiers' deopt helper (`jit_step_one`) both pass through — calls `on_instruction` (before the body runs) and `on_error` (only on an `Err(BeamError)` out of the funnel), so a raising instruction counts as **both** executed and an error, a raise caught in a live `try`/`catch` counts as executed only, a natively-inlined JIT instruction is **not observed** (pin `Tier::Interpreter` for complete counts), and a pre-emption counts as an error of the instruction it parked on.
- **Consumers.** `src/jit/baseline/census.rs`'s runtime census prints it beside the deopt ranking, `tests/dynamic_census.rs` is the corpus-scale ranking and `tests/real_beam_variant_proofs.rs` asserts `executed["<Variant>"] > 0` per real-`.beam` proof. MEASURED.md records the blind spots.

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend -- and `suspended()` = `unsupported("run: process suspended by a BIF (host must resume)")` -- the same for a BIF that answered `BifOutcome::Suspend`.
- **`Step::Enter` executes on the native baseline tier via a driver-mediated context switch.** `call_ext*` is executed natively by `jit_ext_call` (import resolution through the host seam plus the variant's frame discipline); the cross-module *transfer* is not in the JIT inline set, so the resolved target is handed to the driver as a `Step::Enter` (carried out of a block as the `ENTER` block-ABI word). A **declined** import is not resolved twice (`jit_ext_call` forwards its `None` answer through `jit_step_ext` into the shared `Machine::call_ext_dispatch`). The driver switches module context and re-enters the callee's compiled blocks when the tier has them, else its per-instruction step -- a **driver round-trip by design** (a seal-time cross-module link is unsound: separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`); the Cranelift tier inherits `module_blocks -> None` and so always takes the per-instruction step there. Detail: `src/jit/CONTEXT.md`.

## Execution model (frozen semantics -- reproduce, don't reinvent)
The binding semantics in brief; the exhaustive per-instruction/per-operand/per-family detail (with the `ops.tab`/`beam_emu.c` references) is `INSTRUCTION_SURFACE.md`'s `## Execution model`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, the root set `x[0..live)`, plus the FR file; `allocate*` pushes a typed-`Continuation` CP slot then the Y slots (`y(k)` = the slot after it), and the bottom `Halt` yields `x(0)`. A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason.
- **The dispatch loop** (`src/machine/drive.rs` + `src/interpreter/`) owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into it, re-binds the literal area only on a `Step::Enter` into a different context, and charges one reduction per instruction. `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every opcode the engine executes has its own typed IR variant (the residual `Instr::Generic` sentinel returns a named typed error).
- **Failure semantics.** A `gc_bif`/`bif` error with a live `fail` label is a guard branch and with `NO_FAIL` a raise, while `bif0`/`call_ext*` carry no fail label, so every error there is a raise; `FuncInfo` is **not** a no-op -- a failed head clause raises class `error` with the bare atom `function_clause` (C's `i_func_info_IaaI`).
- **Raising and the catch-frame model.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + the owning call frame + its module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` register convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), reporting `Step::Goto` (same context) or `Step::Enter` (another); with no live frame, or an unresolvable class atom, it stays a typed `Err(BeamError::Raise)`. A raise *reads* the innermost entry but never pops it; class atoms come from the running module's atom table, never substituted by a *different* atom.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms/*`, `src/families/bitstrings/raw.rs`, `src/families/records/raw.rs`, `src/jit/emitter/mod.rs` (the crate's **only** executable-memory mapping), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*`, and -- feature-gated -- `src/jit/cranelift/mod.rs` (plus `src/context.rs`'s `MinimalContext` region heap); every `unsafe` block carries a `// SAFETY:` rationale.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need.
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

## Known Issues / Intentional M1 gaps
The full list, each with its ground-truth detail, is in `INSTRUCTION_SURFACE.md`; the headline items:
- **Atom comparison is name-exact end-to-end** through the defaulted `atoms` live-namespace seam (`beam_rt` overrides the module's load-time snapshot with its ONE live table in both `RuntimeContext` and `BudgetContext`).
- **The `{tr,..}` typed-register operand is NOT implicated in the above — that path is correct**: the operand readers/writers and the baseline emitter's `x_register`/`y_register` ignore the `Type` annotation; only `Machine::timeout_delay`/`eval_test_arity` reject a typed operand.
- **The collecting host (`beam_rt`) adopts the rooted doors**, and must additionally root what the `RootSet` cannot carry (`Machine.pending_exception`, the parked `call_bif` argument terms); detail: `src/CONTEXT.md` (`## GC publication…`).
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory** (`Machine::refc_binaries` + `send_message_with_off_heap`); `Machine::retain_refc_binaries(keep)` drops the handles a reachability predicate rejects and `Machine::off_heap_overhead_bytes()` reports the backing-store bytes that feed `beam_gc::BinVheap::triggered`. - **Pre-emption exists; scheduling does not** (the defaulted `ExecutionContext::reduce` hook, charged by both tier drivers; the scheduler, run queues and trap handling are Stage 5, `beam_process`). Detail: `INSTRUCTION_SURFACE.md`.
- **A synthetic module's never-cached label map costs one `Arc` allocation per `run_*` entry** (`Machine::label_map`/`label_map_arc` hand back an `Arc<LabelMap>`): **+16 % of the `engine_bench` `setup/empty` floor**, `0/10` paired rounds in its favour. A real module (load-time digest) never takes that route; measured in `MEASURED.md`'s label-map-cache section.
- **A map `is_eq_exact` costs O(k log k) and two heap `Vec`s per comparison.** `eval_test`'s `IsEqExact` is a plain `cmp(a, b, ctx.atoms(module))` (`src/interpreter/test.rs:69-72`) with no map fast path, and `beam_term::compare::cmp_maps` collects and re-sorts both maps' pairs (`beam_term/src/compare.rs:323-338` -> `map.rs:482-489` -> `collect_pairs`, which allocates a `Vec<(Eterm,Eterm)>` per map).
- **Small-int `'+'`/`'-'`/`'*'` and `band`/`bor`/`bsr` are inlined only by the native baseline tier** (`src/jit/baseline/emit/arith.rs::try_inline_gc_bif`, consulted at `emit/block.rs:423-455`); the **interpreter has no arithmetic fast path** — every `gc_bif` goes out through `exec_bif` -> `ExecutionContext::call_bif` (`src/interpreter/dispatch.rs:341-349`, `src/interpreter/bif.rs:74-135`). The only interpreter-side saving there is the stack-array argument marshalling (`bif.rs:39-53`, no `Vec`).
- **A captured stacktrace is engine-derived** (from the raise-time `raise_snapshot`; the uncaught funnel attaches the frames when the raw trace is `NIL`) **and nameable atoms are required** (`catch_end` needs `EXIT`; neither path substitutes a *different* atom).
- **The uncaught frames exist only for a `BeamError::Raise`** (`beam_common`'s reason variants are fieldless and carry no `StackTrace` slot).
- **Records.** The whole native-record set executes. `PutRecord`'s create form is built from the running module's own `Recs` for its own records, and for a **foreign** module's `{Module,Name}` id through the defaulted `ExecutionContext::foreign_record_definition(owner, name)` seam (`Ok(Some(def))` = the host's record table resolved it, `erl_record.c::erts_record_find_entry`), which the engine requires to be an **exported** definition — a non-exported one is the C's `error:{badrecord, Id}` raise (`erl_record.c:401-409`). The `{Module,Name}` form enforces that export requirement even when `Module` is the running module, while the atom-id form (C's `i_create_local_native_record`) has no such requirement. Residuals: a host that answers `Ok(None)` (no record table, or a defining module it cannot load) keeps the typed `error::unsupported("put_record: create: no record definition table for another module")`; the engine has **no `code:ensure_loaded/1` trap**, so loading a not-yet-loaded definition is the host's `Ok(None)` half; and a created instance stores no definition pointer (the same M1 substitution as the inlined fun descriptor and the external-pid `node` slot). Pinned in `src/families/records/tests/` and `tests/gaps.rs`.
- **Bitstrings.** `bs_init_writable` builds 0 bits over a capacity-carrying refc payload (the `x(0)` hint, else `DEFAULT_WRITABLE_SIZE = 1024`) registered writable **on the machine** (`Machine::writable_payloads` — the frozen term layout carries no capacity word); a **first-position** `private_append` appends **in place** and an outgrown payload **grows** (in place or by relocation, `Machine::grow_writable_payload`), so the accumulator loop is amortised (64 KiB from a 1 KiB hint: 2 grows + 4 moves, 61 440 bytes copied — `create/grow_tests.rs`). Every other shape (plain `append`, a later position, `start != 0`, an on-heap/foreign/non-registered source, a payload `beam_alloc` will not relocate) promotes to the byte-identical copy-rebuild. Detail: `INSTRUCTION_SURFACE.md`, `src/families/CONTEXT.md`.
- **Bitstring residual (typed results only, never a wrong value):** `BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER` are not term flags, `erts_pin_writable_binary`'s shrink-on-escape does not happen, `binary:referenced_byte_size/1`'s capacity-vs-size answer is unmodelled, and a writable payload's `as_bytes()` reports the whole reservation rather than the bytes written (a `beam_alloc` `set_len_written` API would close that — a handoff to `beam_alloc`).
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order, and a `NO_FAIL` failure of `test`/`select_val`/a map read raises class `error` with the bare atom `function_clause` from the running module's own atom table.
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`), never by the engine's own opcode coverage; the owning crates are `beam_bifs` and `beam_rt`, NOT this crate.
- **Compiled arithmetic is oracle-exact on overflow** (`+ - * div rem` promote to exact bignums, as does an out-of-range integer operand).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after**, never `free ++ args`.
- **The `call_fun`/`call_fun2` free-variable copy is NOT a GC hazard (verified; do not re-open)** (no admission point between the read and the writes); the real publication gap is the parked `pending_exception` reason term, owned host-side.

## Heap admission & allocation wiring (the exact engine→host doors)
- **`test_heap`/`allocate_heap` → `Machine::ensure_heap` (`src/machine/frames.rs`) → `ExecutionContext::ensure_heap_full`** with the whole `RootSet` (x, stack **and fr**); the interpreter's two arms and the native tier's `jit_allocate_heap`/`jit_test_heap` (`src/jit/baseline/runtime.rs`) are the only call sites and **the two tiers do not differ**, so a collecting host sees one admission point per execution with the same operands. The narrow `ensure_heap` has **no** engine call site (only its own default body or a host that overrides it reaches it), and the `test_heap Live` operand is only a hint (`RootSet::live_len`).
- **`Instr::Allocate` makes no heap request at all** (frame-only, `jit_allocate` → `Machine::push_frame`), which also skips C's heap check (C's `allocate` can collect) — a conservative divergence — so a loop with no `test_heap`/`allocate_heap` never reaches either admission door; `gc_bif`/`bif`/`bif0`/`call_ext*` likewise leave term allocation to the host's `call_bif`.
- **All term allocation goes through `terms::reserve` → `Machine::alloc_rooted` → `ExecutionContext::alloc_words_rooted`** with the same full `RootSet` (every `put_list`/`put_tuple2`/map/bitstring/float/fun/exception build). The JIT **never inlines an allocation**: those opcodes are family-owned and routed to `jit_family` → the same family body, i.e. one Rust call-back per built term on both tiers; `rbx` is only the `machine.x` base for the register cache, never a heap pointer.
- **The one unrooted runtime allocation** is a non-small `Operand::Integer`/`Character` operand (`terms::make_integer_unrooted` → `ctx.alloc_words`, `src/terms/number.rs`); `alloc_words` has **no** admission point. The classic (unrooted) `make_*` builders are `beam_rt`'s/tests' API, not the engine's own arms.
- **The engine makes no collection decision.** `arm_gc`, `should_collect` and `collection_debt` have **no occurrence anywhere in this crate** — the latch, the occupancy test and the collector are all `beam_rt`'s (`RuntimeContext::arm_gc`; the runner's `BudgetContext` arms exactly the three doors, taking the latch as the first statement of each). The engine's only capacity input is the `heap_need`/`n` it passes; `heap_available` is never consulted.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence, each routed to its owning node; **`INSTRUCTION_SURFACE.md`'s `## Handoffs` is the item-by-item detail**, and the `See Handoff #N` cross-references in this file name its numbering.
Still open: **#1** receive/message + cross-module suspension (`beam_rt`); **#6** `TestKind::TestArity`, behaviourally equivalent to C so not a gap; **#7** map `NO_FAIL` `{badmap,Source}`/`{badkey,Key}`, closed for a seeding host with only the unseeded `beam_loader` path remaining; **#8** JIT `call_ext_last`, which executes natively as a by-design driver round-trip.
**Closed by a defaulted engine seam, residual only at the host:** #4 a *foreign* `PutRecord` create id — `ExecutionContext::foreign_record_definition` supplies the `{Module,Name}` definition (exported only, else the C's `error:{badrecord,Id}` raise) and a host that answers `Ok(None)` keeps the typed `unsupported`, with no `code:ensure_loaded/1` trap on the engine side.
**Adopted by `beam_rt`, no engine work outstanding:** #9 the baseline tier + the A.8 seam, #10 `resolve_external_call`, #11 the rooted doors, #12 `resolve_local_fun`, #13 `resolve_local_call`.
