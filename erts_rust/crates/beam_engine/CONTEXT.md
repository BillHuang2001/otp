# `beam_engine` — Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** that runs a widened instruction set end to end (this crate's Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`) the native JIT tiers plug into. The **native baseline tier is built** (`src/jit/baseline/`: each basic block is lowered to a real x86-64 `extern "C"` function and an export runs through a driver loop that deopts to one interpreter step per instruction it does not lower natively). The **optional Cranelift hot tier is built too** (`src/jit/cranelift.rs`, behind the default-off **`jit-cranelift`** feature: each IR function becomes a real Cranelift function that loops natively over the function's control flow and delegates per-instruction semantics to the *same* shared interpreter-backed helper). All tiers stay **measurement-gated** and off the critical path (Part II §F): the native backends are correctness-first *mechanisms*, not optimisers — inlining and cross-run code caching are later work. The **tiering ladder** of §F is modelled by `src/jit/tiering.rs` (`TierPolicy`: interpret → baseline → hot thresholds with an availability downgrade) — a demonstrated *policy*, not wired into `Machine::run_with_tier` or the runtime.
Implements the Stage-1 engine half of Part II §H with the IR contract of §E and the interpreter/JIT trade-offs of §F (`../../CONTEXT.md` §4).
This crate is on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end.
The dispatch loop (`src/interpreter.rs`) has explicit arms for the core opcodes and routes every other instruction to a per-instruction-family seam (`src/families/`), so a whole opcode family is implemented inside its own module without touching the loop.

**The engine depends only on `beam_loader` (+ `beam_term`/`beam_common`)** — never on the Stage-5 runtime core.
Everything the runtime must supply (BIF dispatch, fun application, heap/GC, process/stack limits) is abstracted behind the [`ExecutionContext`] trait; `beam_rt` provides the concrete implementation.
This keeps the Stage-1/Stage-5 DAG acyclic and lets the engine be tested with a minimal context.

Ground truth (read-only, never modify): the interpreter dispatch `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies `../../erts/emulator/beam/emu/{instrs,macros,bif_instrs,select_instrs,arith_instrs,map_instrs,float_instrs,bs_instrs}.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

## API Surface (FROZEN — the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
**This crate does NOT embed a BIF table**: all computation goes through `ExecutionContext::call_bif`, and fun application through `ExecutionContext::apply_fun`.

### The context seam (`src/context.rs`)
```rust
pub trait ExecutionContext {
    /// Dispatch `module:function/arity`; failure is return-based `Err(BeamError)`.
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;

    /// Ensure `heap_need` words; the live root set is `x_regs[0..live)` + the whole `stack`.
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;

    /// Heap words currently available (introspection). Default: unbounded.
    fn heap_available(&self) -> usize { usize::MAX }

    /// Allocate `n` uninitialized words; valid only until the next `ensure_heap`/GC.
    /// Default: a typed `error::unsupported`.
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;

    /// The general `apply`/`call_ext` hook. Default: forwards to `call_bif`.
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;

    /// Apply a fun/closure value (the `call_fun`/`call_fun2` path). Default: `error::unsupported`.
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
}
```
- `call_bif` failure is an `Err(BeamError)` (a `BadArith`/`BadArg`/`Raise`/…): the engine turns it into a guard branch or a raise, never a panic.
- `ensure_heap(heap_need, live, x_regs, stack)` makes the root-set contract concrete: the live roots are `x_regs[0..live)` plus the whole `stack`; a real context (`beam_rt`, Stage 4/5) runs the collector here and may **move terms** in place, updating `x_regs`/`stack` without frame liveness maps.
- `alloc_words(n)` hands out a stable pointer to `n` **uninitialized** words, valid only until the next `ensure_heap`/GC (mirrors `HAlloc`/`heap_top`); the default body is a typed `error::unsupported`.
- `apply` is the general external-function hook (default forwards to `call_bif`), and `apply_fun` is the fun-application hook (default a typed `error::unsupported`, since the engine keeps no closure registry). A concrete context must enter the closure with `x(0..arity)` = the call arguments and `x(arity..)` = the closure's free variables — see Design Decisions.
- `pub type BifHook = Box<dyn FnMut(&str, &str, u32, &[Eterm]) -> Result<Eterm>>`.
- `pub type ApplyHook = Box<dyn FnMut(Eterm, &[Eterm]) -> Result<Eterm>>`.
- `MinimalContext` — the test/embedding context: an unbounded heap (`ensure_heap` is a no-op `Ok(())`), a **pluggable BIF hook** and an **optional apply hook**.
- `MinimalContext::new()` installs a default BIF hook that rejects every BIF with `error::unsupported`; `with_bif_hook(hook)`/`set_bif_hook(hook)` replace it.
- `MinimalContext::with_apply_hook(hook)`/`set_apply_hook(hook)` install the apply hook that serves `apply_fun`; without one `apply_fun` is a typed `error::unsupported`.
- `MinimalContext::alloc_words` hands out words from a pointer-stable arena (`Vec<Box<[Eterm]>>`); the boxes are never freed before the context drops, so a handed-out pointer stays valid for the context's lifetime.
- The context **owns the heap** and must outlive every boxed term the engine builds through it.

### The machine (`src/machine.rs`)
- `pub struct Machine` — the process-state core: the **x-register file**, the **float-register (FR) file**, the **Erlang stack**, the **call-frame stack** and the **exception catch-frame stack**.
- `pub const MAX_REGISTER: u32 = 1024;` — the x-register file size (`beam_emu.c` `MAX_REG` bound).
- `pub const MAX_FLOAT_REGISTER: u32 = 1024;` — the FR file size, mirroring C's `f_reg_array` (`FloatDef d[MAX_REG]`, `erl_process.h`; `MAX_REG = 1024`, `erl_vm.h:49`).
- The FR file (`fr: Vec<Eterm>`, (re)filled by `reset`) holds **`Eterm` term slots** at M1 (see Design Decisions).
- `Machine` also binds the **running module's decoded literal area** (`literals: Option<SharedLiteralArea>`, re-bound by `run_loop` from the `&Module` being executed, cleared by `reset`), exposed as `Machine::literal(index: u32) -> Option<Eterm>` (delegates to `LiteralArea::get`). The binding cannot go stale mid-run: labels are module-local and a cross-module call leaves the loop through `CallExt` into the host context, so the executing module is fixed for a run.- `Machine::new()` / `Machine::default()` / `Machine::with_max_register(u32)`; `get_fr(n) -> Option<Eterm>` / `set_fr(n, Eterm) -> Result<()>` are bounds-checked FR access (`bad_register` on overflow).
- `pub fn run_export(&mut self, module: &Module, function: Atom, arity: u32, args: &[Eterm], ctx: &mut dyn ExecutionContext) -> Result<Eterm>` — the primary entry: resolve `function/arity`'s export entry label, seed `x[0..arity]` from `args`, push the bottom frame, run to `return`, yield `x(0)`.
- `pub fn run_label(&mut self, module: &Module, label: Label, arity: u32, args: &[Eterm], ctx) -> Result<Eterm>` — run a raw entry label (used by `run_export`); a missing export/label is a typed error.
- The dispatch loop itself is `pub(crate) fn run_loop` / `run_loop_with_map` (implemented in `src/interpreter.rs`).
- Introspection (read-only): `x(n) -> Option<Eterm>`, `get_fr(n) -> Option<Eterm>`, `frame_depth() -> usize`, `stack_depth() -> usize`, `catch_frame_depth() -> usize`, `pending_exception() -> Option<(ExceptionClass, Eterm)>`, `pending_class() -> Option<ExceptionClass>`, `resumption_addresses() -> Vec<(u32, u32)>` (every live call frame's suspended `(func, pc)` CP slot, innermost first — used by `build_stacktrace`).
- `pub fn reset(&mut self)` restores the initial state: NIL-filled register and FR files, empty stack and frame stacks, no pending exception and no resolved class atoms.
- `pub struct CatchFrame { pub func: u32, pub pc: u32, pub frame_index: usize }` (+ `CatchFrame::new`) — one `try`/`catch` handler target: the handler's `(func, pc)` and the call frame that **owns** it (the frame the machine unwinds back to).
- `pub fn push_catch_frame(&mut self, frame: CatchFrame)` / `pub fn pop_catch_frame(&mut self) -> Option<CatchFrame>` — the public catch-stack accessors.
- `pub(crate) fn throw(&mut self, class, reason) -> Result<Step>` / `throw_error(reason) -> Result<Step>` / `throw_with_trace(class, reason, trace) -> Result<Step>` — **the one uniform raise/unwind entry point** the families call (see the exception model below).

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func: u32, pc: u32 }, Done }` — the control-flow contract between the dispatch loop and the instruction families.
- An instruction body performs its register/heap effect and then returns the `Step` telling the loop where to continue; it never mutates the loop's `func`/`pc` directly.
- `Step::Next` continues at `pc + 1`; `Step::Goto { func, pc }` jumps within the module; `Step::Done` finishes the run and yields `x(0)`.
- A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`.
- `dispatch` tries the eight families in a fixed order — `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings` — and returns the first family's `Step`.
- Each family exposes `pub(crate) fn exec(machine: &mut Machine, module: &Module, labels: &BTreeMap<Label, (u32, u32)>, instr: &Instr, func: u32, pc: u32, ctx: &mut dyn ExecutionContext) -> Result<Option<Step>>`.
- `Ok(Some(step))` means "this family executed the instruction"; `Ok(None)` means "not this family's variant"; `Err` means the family raised.
- When **no** family claims an instruction, `dispatch` returns `error::unsupported("widened opcode not yet executed: <name>")` — the documented sentinel prefix the loop emitted before the seam existed plus the instruction's `ops.tab` spelling (`instr_name`: the receive/message family, `bif0`/`bif`, `init_yregs`, `executable_line`/`debug_line`, else the generic `instruction`), so an unclaimed opcode is diagnosable from the error alone.
- The seam exists for **edit locality**: a family is implemented or extended entirely inside its own module, and adding a family is a one-line change in `families/mod.rs`.
- The `families/` module docs list each family's owned variants; keep that list and this crate's Routing Table in sync when a family changes.

### Term helpers (`src/terms.rs`) — the SAFETY-annotated builder/reader
Constructors take the seam (`ctx: &mut dyn ExecutionContext`, allocating via `alloc_words`):
- `make_tuple(ctx, &[Eterm]) -> Result<Eterm>` (arityval header + elements; empty → `tuple0`; > `MAX_ARITYVAL` → `SystemLimit`).
- `make_cons(ctx, head, tail) -> Result<Eterm>` (one header-less `[CAR,CDR]` cell; the tail need not be a list).
- `make_list(ctx, &[Eterm]) -> Result<Eterm>` (cons cells; empty → `NIL`).
- `badmatch_reason(ctx, module, value) -> Result<Eterm>` (`{badmatch, Value}`, the shared raise reason; `BeamError::BadMatch` when the module's atom table lacks `badmatch`).
- `make_float(ctx, f64) -> Result<Eterm>`.
- `make_flatmap(ctx, &[(Eterm, Eterm)]) -> Result<Eterm>` (>32 pairs → typed `unsupported("map > 32 pairs (no HAMT builder)")`; no crate in the rewrite implements the HAMT builder — see Known Issues).
- `make_fun(ctx, arity: u32, uniq: u64, index: u32, free: &[Eterm]) -> Result<Eterm>` (minimal local closure; M1 inlines the out-of-line fun-entry descriptor — see Design Decisions).
- `make_heap_binary(ctx, &[u8]) -> Result<Eterm>` (heap binary/bitstring, ≤64 bytes).

Readers (no `ctx`; wrong type / out-of-range → `BeamError::BadArg`):
`tuple_arity`, `tuple_element`, `cons_head`, `cons_tail`, `list_elements`, `float_value`, `map_entries` (flatmap **and** hashmap/HAMT — walks the frozen `erl_map.h` node tree), `binary_bytes`, `is_fun`, `fun_arity`, `fun_num_free`, `fun_uniq`, `fun_index`, `fun_free`.
Ownership model (documented at the module top): the context owns the heap, `alloc_words` hands out stable raw pointers, and **only this module dereferences them**.

### The JIT tier seam (`src/jit/mod.rs`)
- `pub enum Tier { Interpreter, BaselineJit, Cranelift }` (`Clone, Copy, Debug, PartialEq, Eq`; `Tier::ALL` is the roster order, interpreter first): `Tier::name() -> &'static str` (`"interpreter"` / `"baseline-jit"` / `"jit-cranelift"`), `Tier::from_name(&str) -> Option<Tier>` (unknown name ⇒ `None`, never a default tier) and `Tier::is_available() -> bool` (the tier is in this build's roster).
- `pub trait JitBackend` — the seam a **native** tier implements:
  ```rust
  pub trait JitBackend {
      type Compiled;
      fn name(&self) -> &'static str;
      fn available(&self) -> bool;
      fn compile(&mut self, module: &Module) -> Result<Self::Compiled>;
      /// Compile-once / run-many: run against a caller-owned artifact, no recompile.
      fn run_compiled(&self, compiled: &Self::Compiled, machine: &mut Machine, module: &Module,
                      function: Atom, arity: u32, args: &[Eterm],
                      ctx: &mut dyn ExecutionContext) -> Result<Eterm>;
      /// Provided: `compile` + `run_compiled` (the one-shot entry, one definition).
      fn run_export(&mut self, machine: &mut Machine, module: &Module, function: Atom,
                    arity: u32, args: &[Eterm], ctx: &mut dyn ExecutionContext) -> Result<Eterm> {
          let compiled = self.compile(module)?;
          self.run_compiled(&compiled, machine, module, function, arity, args, ctx)
      }
  }
  ```
  `&mut self` on `compile` because a backend owns its compile-time state (a code buffer/caches); `Compiled` is the backend's opaque per-module artifact. `run_compiled` takes `&self` because the artifact is **caller-owned** and the backend holds no per-run code state, so one compiled module can be run any number of times (on fresh `Machine`s) without recompiling; `run_export` is a **provided** method (single definition here, so no backend can drift) over `compile` + `run_compiled` and keeps its `&mut self` signature (`Machine::run_with_tier` is unaffected). Both entries share the driver setup identically (reset, seed `x[0..arity)`, push the bottom frame, bind `module.literals`, build the label map, resolve the export). The interpreter is deliberately **not** a `JitBackend` (nothing to compile).
- `pub fn available_tiers() -> &'static [&'static str]` — the tiers compiled into this build: exactly `["interpreter", "baseline-jit"]`, plus `"jit-cranelift"` when the **`jit-cranelift`** feature is enabled. Interpreter always first; the roster is a prefix of `Tier::ALL` mapped to `Tier::name`.
- `Machine::run_with_tier(..., tier: Tier) -> Result<Eterm>` (`src/machine.rs`) is the tier-selecting entry: `Interpreter` delegates to `run_export` (which stays the default interpreter entry), `BaselineJit` runs the `src/jit/baseline/` backend, `Cranelift` routes through `crate::jit::run_cranelift` to the `src/jit/cranelift.rs` backend when the `jit-cranelift` feature is on, and is a typed `error::unsupported("jit-cranelift tier not built")` when it is off — never a panic and never a silent fallback.
- Cargo features: **`jit-cranelift` (default OFF)** gates the optional Cranelift deps. With it off the crate builds and tests with **no Cranelift dependency at all** — the build and the vertical slice never depend on Cranelift codegen. `jit-beamasm` is a **documented alias for the baseline tier** (the baseline tier is in every build's roster, so the feature adds nothing; it is kept so `--features jit-beamasm` keeps working).
- `src/jit/tiering.rs` (`pub mod tiering;`, re-exported as `pub use tiering::{TierPolicy, DEFAULT_BASELINE_THRESHOLD, DEFAULT_HOT_THRESHOLD};`, also at the crate root) — the **tiering policy**: `TierPolicy { baseline_threshold, hot_threshold }` models the Part II §F *interpret → baseline → hot* escalation ladder a cheap per-function execution counter would drive. `TierPolicy::new(baseline, hot)` (**clamps `hot` up to `baseline`** so the ladder never inverts), `select(executions) -> Tier` (`Interpreter` below `baseline_threshold`, `BaselineJit` from there up to but excluding `hot_threshold`, `Cranelift` at/above it **when compiled in**, else downgraded to the hottest available tier at or below what the thresholds asked for — never an unavailable tier), `is_hot(executions)`, the `baseline_threshold()`/`hot_threshold()` accessors, and `Default` (baseline `1`, hot `10_000` = `DEFAULT_HOT_THRESHOLD`). This is a **demonstrated policy only**: nothing on an execution path consults it — `Machine::run_with_tier` still runs exactly the tier its caller names for the whole call, and neither backend recompiles or promotes mid-run. Installing the counter + promotion machinery is later work (Stage 1b).
- `src/jit/emitter.rs` is the encodable **building block** the native tiers are built on: an `#[allow(unsafe_code)]` x86-64 encoder plus an executable `CodeBuffer`. It exposes `Reg` (16 GPRs), `Cond` (16 condition codes), `Label`, `CodeBuffer::{new, with_capacity, label, bind, seal, is_sealed, len, capacity, code_ptr, as_fn_ptr}`, and the instruction set `mov_rr`/`mov_ri` (movabs)/`mov_rm`/`mov_mr`/`lea`, `add_rr`/`sub_rr`/`cmp_rr`/`test_rr`/`and_rr`/`or_rr`/`xor_rr`, `push_r`/`pop_r`, `jmp`/`jcc`/`call_label`/`call_r`/`ret`, `nop`/`int3`. Everything returns `beam_common::Result` (`Io` for a failed `mmap`/`mprotect`, `SystemLimit` for a full buffer or an unrepresentable `rel32`, `BadArg` for misuse: an unbound label at `seal`, a foreign/doubly-bound label, or emitting after sealing). The mapping is `mmap(PROT_READ|PROT_WRITE)` → `mprotect(PROT_READ|PROT_EXEC)` on `seal` (never RWX), released with `munmap` in `Drop`. It assumes the **System V AMD64** ABI and emits `REX.W` + the REX.R/B extension bits for `r8`–`r15`, the `SIB` byte an `rsp`/`r12` base forces, and a uniform `mod=10` `disp32`. It is the encoder the baseline tier's `emit.rs` builds every compiled basic block on (and its own `#[cfg(test)]` tests still call emitted code directly). **Length note:** the file is ~1120 lines only because its non-test encoder body (~730 lines) is followed by an in-module `#[cfg(test)]` suite (~390 lines) that executes real emitted code; it stays one cohesive encoder module (register/condition/label types + `CodeBuffer` + the instruction set + its tests), since splitting a single encoding responsibility would only fragment tightly coupled code.
- `src/jit/baseline/` — the **native baseline backend** (`pub mod baseline;`), split by responsibility across `mod.rs` (module docs, the path-stable re-exports, `BaselineJit`, `CompiledModule`, the driver), `runtime.rs` (the block ABI + `jit_step_one`) and `emit.rs` (the block emitter + register allocator), with the in-module tests in `tests.rs`. It exposes `BaselineJit` (a zero-sized selector implementing [`JitBackend`](../src/jit/mod.rs)): `compile` = `compile_module`, `run_compiled` delegates to the driver `run_compiled` on the caller-owned `&CompiledModule` (no recompile), and `run_export` is the provided one-shot over both:
  - **Block ABI.** Every compiled basic block is an `extern "C" fn(*mut JitRuntime) -> i64` returning the next control-flow target: `encode_target(func, pc) = (func as i64) << 32 | (pc as i64 & 0xFFFF_FFFF)` for a normal continuation, `HALT = -1` (the run finished → the driver yields `machine.finish()`), `ERROR = -2` (a propagating `BeamError` was stored in `rt.error`). `pub const fn encode_target` / `decode_target` are the codec (`decode_target` → `None` for any negative word); a valid target is always non-negative (`func < 2^31`).
  - **`JitRuntime`** — the `#[repr(C)]` runtime block a block receives: `machine: *mut Machine`, `x_regs: *mut Eterm` (the base of `machine.x`), `module: *const Module`, `labels: *const BTreeMap<Label, (u32, u32)>`, `ctx: *mut (dyn ExecutionContext + 'a)`, `error: Option<BeamError>`. Generated code loads **only** `x_regs` (offset `RUNTIME_XREGS_DISP = 8`); the rest is read by the helper. `x_regs` is a **separate field** because `[base + n*8]` must index the x-register *array*, not the `Vec` header at the struct's `machine` offset.
  - **`CompiledModule`** — the `compile` artifact: the sealed `CodeBuffer`, the `(func, pc) → *const u8` `entries` map, and `highest_cached_register`. Accessors: `entry(func, pc)`, `block_count()`, `highest_cached_register()`, `code_len()`, `code_address_range()`.
  - **`jit_step_one`** — the `extern "C"` **per-instruction deopt**: it is literally `Machine::step_instruction`, mapping `Step::Next → encode_target(func, pc+1)`, `Step::Goto → encode_target(f, p)`, `Step::Done → HALT`, `Err → store in rt.error` + `ERROR`. This is what gives the tier **full opcode coverage with interpreter-identical semantics**.
  - **Inlined natively** (no interpreter round-trip): the metadata no-ops (`Label`/`Line`/`FuncInfo`/`IntCodeEnd`/`ExecutableLine`/`DebugLine`); `Move { src, dst }` where `dst` is a cached x-register and `src` is a cached x-register or a constant (`Integer`/`Character`/`Atom`/`Nil` — the raw `Eterm` word from `make_small`/`make_atom`/`NIL`); `Jump` to a label the module defines (a constant return word). **Everything else** — any other instruction, a `Move` outside that set, and a `Jump` to an undefined label (so the interpreter's exact `unknown_label` surfaces) — goes to `jit_step_one`.
  - **Register allocation**: at most four x-registers, chosen in first-appearance order over the block's *shape*-inlinable `Move`s, are cached in `r12`–`r15`; `rbx` holds the `x_regs` base and `rt` lives in a 16-byte stack slot the prologue reserves. The prologue pushes `rbx`,`r12`–`r15` (five pushes keep `rsp` 16-byte aligned at the helper call) and loads the cached slots from `x_regs`; the **epilogue spills them back to `machine.x` at every block exit** — the whole liveness model, so any helper/GC sees the interpreter's exact root set `x[0..live)` + the whole stack with no liveness maps.
  - **Driver (`run_compiled`, the backend's `JitBackend::run_compiled`)** mirrors `run_label`'s setup (`reset`, seed `x[0..arity)`, `push_frame(0)`, `set_literals`, `build_label_map`, `resolve_label`), then loops: call the compiled block at `(func, pc)` if one exists and decode its word (`HALT → finish()`, `ERROR → Err(rt.error)`, `(f,p) → continue`), else take one `step_instruction` and fold its `Step`. A per-run `native_ok` guard refuses native entry when `machine.x.len() <= highest_cached_register` (the generated loads are unchecked), staying on the interpreter step. The driver takes `&CompiledModule`, so the artifact is compiled once and run any number of times.
- `src/jit/cranelift.rs` (`#[cfg(feature = "jit-cranelift")]`) — the **optional Cranelift hot backend**: `CraneliftJit` implementing [`JitBackend`] over the Cranelift JIT (`JITBuilder`/`JITModule`, host ISA). It builds **one Cranelift function per IR `Function`** with the signature `(I64 rt) -> I64` — the same block ABI as the baseline tier — which starts at the function's `entry_pc` (resolved from the module label map at compile time and baked in as a constant) and loops: call `jit_step_one(rt, FUNC_INDEX, pc)`; a negative word is `HALT`/`ERROR` and is returned unchanged; otherwise decode `(target_func, target_pc)` — a **different** function returns the word to the driver, the **same** function loops natively at the new `pc`. The helper is registered via `JITBuilder::symbol("jit_step_one", jit_step_one as *const () as *const u8)` and declared as a `Linkage::Import`. `CompiledFunctions` owns the `JITModule` (keeping the executable mapping alive) plus the `HashMap<u32 /*func index*/, *const u8 /*compiled entry*/>` and the per-function `entry_pc`; `CompiledEntries` is the tier's [`NativeCode`] lookup and enters a compiled function **only at its entry `pc`**. Per-instruction work is delegated to the helper: nothing is inlined natively yet (`run_export` compiles per call — no cross-run code cache in `run_with_tier`; a caller that runs a module repeatedly uses `compile` + `run_compiled`), so the tier is correct, measurably faster than the interpreter on `fib` but *slower* on the 256-op kernel because it inlines nothing yet and pays a `jit_step_one` call per instruction (see Measured), and it caches no compiled module across `run_with_tier` calls (see Known Issues).

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`).

## Execution model (frozen semantics — reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`, `:236-247`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame**: `allocate`/`allocate_heap`/… push a frame of **`stack_need + 1` words** — a *continuation-pointer slot* followed by `stack_need` Y-registers; `y(k)` is the slot after the CP slot (`E[1+k]`).
- The engine models the CP slot as a typed `Continuation` (`Address{func,pc}` or `Halt`) on the frame rather than a raw stack word; the Y slots live in the stack.
- `call` (non-tail) stores the continuation in the *current* frame's CP slot, then jumps.
- `return` reads the continuation from the *current* frame's CP slot and jumps there; a frame-less leaf (e.g. `add/2`) uses a bare `return` and reads the *caller's* CP slot.
- `deallocate(n)` / `call_last{n}` / `call_ext_last{n}` pop the frame (the `n` Y slots **and** the CP slot, via `pop_frame_checked`); a following `return` then reads the caller's CP slot.
- Reaching the **bottom frame** (`Continuation::Halt`) halts execution and yields `x(0)`.
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`, `E += n`): it **discards the lowest `n` Y slots** and renumbers the survivors down (`y(k) → y(k−n)`), which is exactly what the compiler's `beam_trim.erl` assumes (`Eliminated = [{y,N} || N <- seq(0, Trim-1)]`, `expand_recipe` remaps `Dst−Trim`). The `remaining` operand is JIT-only and ignored by the interpreter.
- `test_heap{heap_need, live}` calls `ctx.ensure_heap(heap_need.words(), live, x, stack)` and leaves the stack unchanged; `allocate`/`allocate_heap` recover the frame's word count through `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter.rs`)
- Each iteration reads `module.functions[func].code[pc]` (typed `Instr`) and dispatches with a safe `match` (no computed-goto; the IR is pre-decoded, so typed dispatch is equivalent to a jump table).
- Core arms mutate the loop's `func`/`pc` in place; the catch-all arm calls `families::dispatch` and folds its `Step` back via the local `apply_step!`-style mapping.
- The module-wide `Label -> (function index, code index)` map is built from every `Function::labels` (`build_label_map`), so a call/fail target may live in another function (the slice's `fib/1` tail-calls into `fib/3`); a missing label is `error::unknown_label`.
- `import_target` resolves an `ImportRef` to `(module name, function name, arity)` through `Module::imports` + `Module::atom_name`.
- The residual `Instr::Generic` opcodes (the loader's unmodelled set) are handled by `src/generic.rs` (`pub(crate) fn exec(machine, labels, op, operands) -> Result<Step>`): it executes `is_any_native_record` — the only Generic opcode the standard compiler emits (`ops.tab:1634` `is_any_native_record f xy`; C body `emu/instrs.tab:1323` `if (!is_record($Src)) $FAIL($Fail);`) — and returns `error::unsupported(op.name())` for everything else. A missing/failed operand decode is the same typed error, never a wrong result.

### Instruction subset — **executed by the core loop**
`Label`, `Line`, `FuncInfo`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart` (`nif_start`), `OnLoad` (`on_load`) — metadata/no-ops: they do not change control flow. `nif_start`/`on_load` are the compiler's markers at the head of a NIF stub / an `-on_load` function; the C emulator falls through both (`../../erts/emulator/beam/emu/ops.tab` lists them as bare opcodes with no body), so `Step::Next` is their exact semantics.
`Move`, `Swap`, `InitYregs` (`init_yregs` writes `NIL` into the listed Y registers).
`Test` (**all** `TestKind`s, see below), `SelectVal` (exact `=:=` match against each `(value, label)`, else `fail`, else a raise when `fail == NO_FAIL`).
`Jump`, `Call`, `CallLast`, `CallOnly`, `CallExt`, `CallExtOnly`, `CallExtLast`, `Allocate`, `AllocateHeap`, `TestHeap`, `Deallocate`, `Trim`, `Return`.
`GcBif`, `Bif0`, `Bif`.
`Instr::Generic { op, operands, .. }` executes exactly **one** opcode — `is_any_native_record` (via `src/generic.rs`); every other Generic opcode returns `error::unsupported(op.name())`.
- **`GcBif`/`Bif` failure semantics**: evaluate the arg operands, call `ctx.call_bif`. On `Ok`, store into `dst`. On `Err` with a live `fail` label, **jump to `fail`** (guard failure). On `Err` with `fail == NO_FAIL`, **raise** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`).
- **`Bif0`/`CallExt*` failure semantics**: these carry no fail label, so **every** error is a raise through `raise_bif_error`.
- **`raise_bif_error`**: with no live catch frame (or a `BeamError::Raise`), the error propagates unchanged. With a live catch frame, the error's BEAM atom name (`BeamError::as_atom()`: `badarg`/`badarith`/`badarity`/`badmatch`/`system_limit`/`out_of_memory`) is resolved in the running module's atom table, turned into a term and raised with class `error` — the class every BIF failure carries. An error the engine cannot name as a term (no atom, a `Raise`, `TermNotFound`, `Io`, or an atom absent from the module) propagates unchanged rather than being substituted by a *different* atom.
- **`Test` failure semantics**: the test *succeeds* ⇒ fall through; it *fails* ⇒ jump to `fail`, or raise `error::unsupported("test/no_fail")` when `fail == NO_FAIL`.
- **`Test` comparison kinds**: `IsLt`/`IsGe`/`IsEq`/`IsNe` compare `args[0]` vs `args[1]` with arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` use exact equality (`cmp`).
- **`Test` type kinds**: `IsInteger`, `IsFloat`, `IsNumber`, `IsAtom`, `IsPid` (internal or external), `IsReference` (internal or external), `IsPort` (internal or external), `IsNil`, `IsBinary`, `IsBitstr`, `IsList` (`[]` or a cons cell), `IsNonemptyList`, `IsTuple`, `IsMap`, `IsBoolean` (the atom `true`/`false`), `IsFunction`, `IsFunction2` (`args[0]` is a fun of `args[1]` arity), `IsTaggedTuple` (`args[0]` is a tuple of `args[1]` arity whose first element is `args[2]`), `TestArity` (`args[0]` is a tuple of `args[1]` arity).
- **`NifStart`/`OnLoad` are no-op markers** (see the executed subset above).

### Operand subset — **supported**
- `X(n)`, `Y(n)` (bounds-checked; out of range → `error::bad_register`).
- `Typed{reg, ty}` (read/write `reg`, ignore the type annotation).
- `FloatReg(n)` (read/write the [`Machine`] FR file; out of range → `bad_register`).
- `Integer(i)`/`Character(c)` (a small int when in range, an exact bignum otherwise — `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil` (`NIL`).

### Operand subset — **NOT supported by the general reader/writer**
- `Literal` (an index into the running module's decoded literal area) **is** read via `crate::operand::read_operand` (`Machine::literal`); only `Label`, `List` and `Allocation` are unsupported there → a typed `error::unsupported` from `read_operand`. `write_operand` rejects every non-register destination, `Literal` included (a literal has no addressable slot).

### Instruction families — **executed**
`families/tuples.rs`: `PutTuple2` (`put_tuple2`), `GetTupleElement` (`get_tuple_element`), `SelectTupleArity` (`select_tuple_arity` — a bad shape/arity raises `{badmatch, Value}` on the no-fail path).
`families/records.rs`: `UpdateRecord` (`update_record` — copy the `size`-arity source tuple and overwrite the element at each **1-based** `(offset, value)` pair, writing to `dst`). A non-tuple source, a size/arity mismatch, a non-integer offset, or an offset outside `1..=size` is a typed `unsupported`.
`families/lists.rs`: `PutList` (`put_list`), `GetList` (`get_list`), `GetHd` (`get_hd`), `GetTl` (`get_tl` — a non-cons source raises `{badmatch, Value}`).

A non-atom `apply` target is a `badarg` raise routed through `Machine::throw_error` (`raise_badarg`), which lands in a live catch frame or propagates as the typed `BeamError::BadArg`.
`families/exceptions.rs`: `Badmatch` (`{badmatch,V}`), `CaseEnd` (`{case_clause,V}`), `TryCaseEnd` (`{try_clause,V}`), `IfEnd` (`if_clause`), `Badrecord` (`{badrecord,V}`), `Raise` (re-raise with the class currently being handled), `Try`/`Catch` (push a catch frame), `TryCase`/`TryEnd`/`CatchEnd` (the handler opcodes, each consuming exactly one catch frame), `BuildStacktrace` (cook `x(0)`: `NIL` ⇒ `NIL`; a non-`NIL` raw trace ⇒ an engine-derived symbolic trace from the live frames), `RawRaise` (class `error`/`exit`/`throw` in `x(0)` ⇒ raise `x(1)` with trace `x(2)`; any other class ⇒ `x(0) = badarg` and fall through — see Known Issues).
`families/floats.rs`: `Fmove` (`fmove`), `Fconv` (`fconv`), `Fadd`/`Fsub`/`Fmul`/`Fdiv`, `Fnegate` (the FR file keeps `Eterm` slots; a non-float operand or a non-finite result is the instruction's arithmetic failure — a guard branch to `fail` when one is live, else a `badarith` raise routed through `Machine::throw_error` (`raise_badarith`), which lands in a live catch frame or propagates as the typed `BeamError::BadArith`).
`families/maps.rs`: `GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact`. `families/bitstrings/{mod,matching,create}.rs`: `BsStartMatch3`/`BsStartMatch4`, `BsMatch` (the flattened command list: `ensure_at_least`, `ensure_exactly`, `skip`, `integer`, `binary`, `get_tail`, `=:=`), `BsMatchString`, `BsTestTail2`, `BsGetTail`, `BsGetPosition`, `BsSetPosition`, `BsGetInteger2` (any width — ≤64 bits in a machine word, >64 as a `beam_term` bignum, big/little-endian and signed), `BsGetFloat2` (0/16/32/64 bits), `BsGetBinary2`, `BsSkipBits2`, the UTF reads/skips `BsGetUtf8`/`BsGetUtf16`/`BsGetUtf32` + `BsSkipUtf8`/`BsSkipUtf16`/`BsSkipUtf32`, and `BsCreateBin` (`integer` — any width —, `binary`, `float`, `utf8`/`utf16`/`utf32` and `string` segments; a `string` segment is a literal byte slice of the module's `StrT` table selected by the offset/size operands and appended at the current bit position, mirroring `erts_bs_put_string`, `../../erts/emulator/beam/erl_bits.c:1641`), plus `BsInitWritable` (a 0-bit refc binary over a 256/1024-byte payload) and a **first** `append`/`private_append` segment (seed-and-rebuild), and a result of any size — an on-heap `ErlHeapBits` up to 64 bytes, an off-heap refc binary above it.

### Raising opcodes and the catch-frame model (`families/exceptions.rs`, `src/machine.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, i.e. the frame that owns the handler) and blank their frame slot.
- A raise (a family's `throw`/`throw_error`, or `raise_bif_error` for a BIF/ext-call error) records `pending_exception = (class, reason)`, then consults the **innermost** live catch frame.
- To land, the machine unwinds the call-frame stack back to `CatchFrame::frame_index` (dropping the Y slots of every deeper frame) and writes the handler registers exactly as C's `handle_error` does: `x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace` (`NIL` at M1), `x(3) = class atom`.
- A landed raise returns `Ok(Step::Goto { func, pc })` for the handler; with no live catch frame (or an unresolved class atom) it returns the typed `Err(BeamError::Raise(..))` — never a panic.
- **The raise never pops the catch frame**: it *reads* the innermost entry and unwinds the call frames, but leaves the entry in place; the handler opcode that runs next (`try_case`/`try_end`/`catch_end`) consumes exactly one entry (on the normal or the exceptional path, never both).
- `try_case` blanks its frame slot, requires the `THE_NON_VALUE` marker in `x(0)`, and moves the class atom from `x(3)` into `x(0)`.
- `try_end` just blanks its frame slot; `catch_end` leaves a normal result untouched but folds a landed exception into the caught term — the thrown value for class `throw`, `{'EXIT',Reason}` otherwise.
- The class atoms (`error`/`exit`/`throw`) are installed from the running module's atom table before a raise (`Machine::set_class_atom`); an atom absent from the module is never substituted by a *different* atom (an uncaught raise still propagates as a typed error, and a caught raise fails with a typed `unsupported`).
- `pending_class` is the class a `raise` opcode re-raises with, reproducing C's `i_raise` keeping `freason`.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** — no crate-local error enum (workspace §3); an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` — the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`) with exactly **five** `#[allow(unsafe_code)]` modules:
  - `src/predicates.rs` — wraps the `beam_term` boxed-term predicates the `Test`/`test_arity` opcodes need (`is_integer`, `is_number`, `is_float`, `is_tuple`, `is_tuple_arity`, `is_map`, `is_binary`, `is_bitstring`, `is_internal_ref`, `is_external_pid`/`_port`/`_ref`), which are `unsafe fn` because they dereference a term's header word — there is no safe classifier.
  - `src/terms.rs` — the crate's single point of **raw-heap boxed-term construction/reading** behind the `ExecutionContext::alloc_words` seam (incl. the HAMT reader for `map_entries`).
  - `src/families/bitstrings/raw.rs` — the `ErlSubBits`/`ErlHeapBits` raw-layout accessors for the `bs_*` opcodes (reading a heap bitstring's data words, reading/writing the match-context fields, materialising a result bitstring with an explicit bit count, the off-heap refc payload allocation behind `make_binary`/`make_writable`, and the `>64`-bit bignum build/read helpers). A refc binary root is a readable subject (`heap_bits` accepts it via `beam_term::refc::is_refc_binary` + `beam_term::bitstring::bitstring_parts`).
  - `src/jit/emitter.rs` — the baseline JIT's x86-64 instruction encoder and the crate's **only executable-memory mapping** (`mmap` RW → `mprotect` RX on `seal`, `munmap` in `Drop`); carries a file-local `#![allow(unsafe_code)]` rather than a declaration-site attribute.
  - `src/jit/baseline/{mod,runtime,emit}.rs` — the baseline backend: it reconstructs `&mut Machine` / `&mut dyn ExecutionContext` / `&Module` / `&BTreeMap` from `JitRuntime`'s raw pointers (live, driver-owned, unaliased for the call) and invokes a block's entry as a transmuted `extern "C" fn` into the sealed mapping; each of the three files carries a file-local `#![allow(unsafe_code)]`.
  - Each `unsafe` block carries a `// SAFETY:` rationale (the term is a live machine word — an immediate is handled by the safe fast path first; a boxed term comes from `ctx.call_bif`/machine/`alloc_words` state, never unvalidated raw memory); registers/stack stay safe `Vec<Eterm>` indexing and `unsafe_op_in_unsafe_fn` stays clean.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 → wave 4, downward/legal) was added for the off-heap refc-binary payloads `bs_init_writable`/`append` need (`Machine::alloc_refc_binary`, held as `Machine::refc_binaries` and deliberately **never cleared by `reset`**) — a new layer-DAG edge escalated to the crate-layer node (`../`).
- **Files ~1000 lines**, split by responsibility; a legitimately long file (`tests/opcodes.rs`, the comprehensive synthetic-opcode module) documents why.
- Licensing Apache-2.0.

## Measured (micro-benchmark)
Run: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_engine --test jit_bench -- --nocapture` (add `--features jit-cranelift` for the feature-ON roster).
These are the honest current M1 numbers (`tests/jit_bench.rs`) measured on this machine — environment-dependent, and the tiers are **mechanisms, not optimisers**.
The timed loop is compile-once / run-many (`JitBackend::run_compiled` against a caller-held artifact, `N=5000` executions); the native tiers' one-time `compile` cost is measured separately and **excluded** from the timed loop.
- **Feature OFF** (`N=5000`): `slice:fib/1(20)` — interpreter **5876.7 ns/op** vs baseline-jit **3113.5 ns/op** (≈1.9× faster); `kernel/2` (256 chained `gc_bif '+'/2`) — interpreter **7642.6 ns/op** vs baseline-jit **633.5 ns/op** (≈12× faster).
- **Feature ON** (`--features jit-cranelift`): `fib` — interpreter **6846.5 ns/op**, baseline-jit **3118.8 ns/op** (≈2.2×), Cranelift **3881.2 ns/op** (≈1.8× faster than the interpreter); `kernel` — interpreter **6193.3 ns/op**, baseline-jit **629.9 ns/op** (≈10×), Cranelift **7459.3 ns/op** (≈1.2× *slower* than the interpreter, because the Cranelift tier inlines nothing yet and pays a `jit_step_one` call per instruction).
- One-time `compile` cost (excluded from the timed loop): baseline ≈23–265 µs, Cranelift ≈86–596 µs.

## Design Decisions
- **`ExecutionContext` seam with the root-set contract made concrete.** `call_bif` isolates BIF dispatch, `apply_fun` isolates fun application, and `ensure_heap(heap_need, live, &mut x, &mut stack)` hands the exact GC root set (`x[0..live)` + the whole stack, §4) to the context, so a Stage-4 collector can move terms in place without frame liveness maps. `MinimalContext` is the test/embedding impl with an unbounded heap.
- **A per-instruction-family seam keeps the loop small and edit-local.** The dispatch `match` has one arm per *core* opcode; the catch-all arm routes everything else to `families::dispatch`, so a whole opcode family is implemented without ever touching `interpreter.rs` again.
- **Safe `match`-based dispatch, not computed-goto.** The IR is pre-decoded (typed `Instr` per opcode with operands resolved at load time), so dispatch is one `match` arm per op — the direct-threaded *model* of §F, implemented without `unsafe`/`goto`. A future asm/JIT tier may use threaded code; the interpreter need not.
- **`Step` is the loop/family control-flow contract.** A family returns `Next`/`Goto`/`Done` and never mutates the loop's `func`/`pc`; a raise stays an `Err(BeamError)` (or is folded into a `Goto` by the exception layer).
- **A typed frame CP slot, not a raw stack word.** `allocate` reserves `stack_need + 1` words and the CP slot is modeled as a typed `Continuation` (`Address{func,pc}` or `Halt`) on the frame; the Y slots are the stack words. This reproduces the C frame exactly while staying type-safe.
- **The catch-frame stack mirrors C's `next_catch` + `c_p->catches` split.** A `CatchFrame` stores the handler location and the owning frame index; a raise reads the innermost entry and unwinds the call frames (C's `c_p->stop = prev`), while the handler opcode pops exactly one entry (C's `c_p->catches--`).
- **`Machine::throw` is the one raise/unwind entry point** every family calls, so the landing convention (`x(0..=3)`) and the catch/unwind bookkeeping live in exactly one place.
- **Module-wide label index.** `Call*`/`CallLast`/`CallOnly` targets and `fail` labels are module-local and can cross functions (`fib/1` → `fib/3`), so the machine builds a `Label -> (function index, code index)` map from `Module.functions[*].labels` per run (labels are module-unique code addresses).
- **A real tier seam, with the JIT tiers off the critical path.** `Tier`/`JitBackend`/`available_tiers` are the selection surface; `Machine::run_with_tier` routes `Interpreter` to `run_export`, `BaselineJit` to the `src/jit/baseline/` backend and `Cranelift` to the `src/jit/cranelift.rs` backend. Cranelift is an optional feature (default OFF); with it off the crate and the entire build/test flow carry no Cranelift codegen or dependency. JIT compilation is measurement-gated (Part II §F) with a bounded-latency, cheap-deopt design.
- **The tiering ladder is a policy type, deliberately not wired into execution.** `TierPolicy` (`src/jit/tiering.rs`) models §F's *interpret → baseline → hot* escalation and its per-function-counter thresholds, but no path consults it: `Machine::run_with_tier` still runs the one tier its caller names, and the backends do not promote mid-run. Its one substantive rule is availability: the selected tier is the *hottest tier at or below* what the thresholds ask for that `Tier::is_available`, so with `jit-cranelift` off a hot function stays on `BaselineJit` rather than naming a tier this build cannot run.
- **One driver for both native tiers.** `baseline::run_native` is the shared driver loop; a tier plugs in its compiled-code lookup through the [`NativeCode`] trait (`enter(rt, func, pc) -> Option<i64>`). The baseline tier answers for every compiled basic block (and refuses when the register file is too small), the Cranelift tier only at a function's entry `pc`. This is the Prevent-Duplication answer for the driver (the setup, the `HALT`/`ERROR`/`(func, pc)` folding and the interpreter-step fallback live once), and it is what makes the two tiers' observable semantics identical by construction.
- **The Cranelift tier delegates per instruction rather than duplicating semantics.** Its compiled function loops on the shared `jit_step_one` helper (the interpreter's own step), so it needs no second implementation of any opcode — the cheap-deopt boundary is "anything not inlined runs in the helper". Structurally this is the same correct-by-construction story as the baseline tier's deopt; inlining the trivial no-op/`move` instructions in Cranelift IR is the next task.
- **Per-instruction deopt is the baseline tier's whole coverage story.** `jit_step_one` *is* `Machine::step_instruction`, so the native tier has interpreter-identical semantics for every opcode the loader/compiler supports without a second implementation; a block's inline prefix runs natively and the first non-inlinable instruction is handed to the helper, after which the block exits. This is what lets the mechanism ship with full coverage while inlining grows later.
- **Block register allocation caches up to four x-registers (`r12`–`r15`) and spills at every block exit.** `rbx` is the `x_regs` base and `rt` lives in a reserved stack slot; the prologue loads the cached slots and the epilogue writes them back, so a helper/GC at any block boundary always sees the interpreter's exact root set `x[0..live)` + the whole stack — no liveness maps. The set is chosen from the block's *shape*-inlinable `Move`s in first-appearance order, so the inline prefix always has the registers it wants.
- **`JitRuntime` carries `machine` and `x_regs` separately.** Generated `[base + n*8]` addressing must be based on the x-register **array** (`machine.x`), not the `Vec` header at the struct's `machine` offset — a distinct field is the only correct way to expose it (this was the one SIGSEGV-class bug of the port). `machine.x` is fixed after `reset`, so caching its pointer for the whole driver call is sound.
- **A machine smaller than the highest cached register never enters native code.** The generated loads are unchecked, so `run_compiled`'s `native_ok` guard keeps such a run (`Machine::with_max_register(n)`) on the interpreter step rather than reading outside the array — the observable result is unchanged.
- **Compile failure is a typed error, never a silent fallback.** `CodeBuffer::seal`'s unbound-label/capacity failures propagate out of `compile`/`run_export`; an unresolved `Jump` target goes to the helper so the interpreter's exact `unknown_label` surfaces rather than an invented one.
- **Reuse the loader fixture; do not duplicate it.** The slice `.beam` lives with `beam_loader` (single source of truth for the oracle image); `beam_engine` reads it by relative path.
- **Unsupported ⇒ `Raise` with reason atom `unsupported_opcode`.** `beam_common::BeamError` has no dedicated variant and must not gain one from here; `error::unsupported` is the documented sentinel, consistent with "no silent swallowing, no panic".
- **The FR file stores `Eterm` term slots at M1.** The C float-register file is raw doubles (`FloatDef`), but the engine's operand seam is `Eterm`-typed, so a term-slot FR file lets `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is a deferred refinement.
- **Term construction lives behind `alloc_words` + `terms`.** The contract for a boxed term is the sole responsibility of `terms`, and its single `unsafe` module is the only place that dereferences raw heap storage; the bitstring family adds its own `raw` module for the two frozen bit layouts `terms` does not own.
- **M1 fun layout inlines the descriptor.** C's boxed fun points out-of-line at an `ErlFunEntry`/`Export` (code address + `uniq`/`index`); M1 has no code pointers, so `make_fun` inlines the descriptor as two words (`uniq`, `index`) after the header — the same documented "M1 substitution" pattern as the external-pid `node` slot (`erl_term.h` `MAKE_FUN_HEADER` + `erl_fun.h` `ErlFunThing`).
- **`MinimalContext` fun application goes through an apply hook.** The engine keeps no closure registry, so `call_fun`/`call_fun2` reach the host through `ExecutionContext::apply_fun`, whose default body is a typed `unsupported`; tests install an `ApplyHook` that knows the closures the fixture builds.
- **The HAMT reader lives in `terms.rs`.** The crate's designated raw-layout `unsafe` module owns `map_entries` for both the flatmap and the HAMT layouts (an explicit work stack bounded by `HAMT_MAX_LEVEL`, no hash function — keys are matched by `beam_term::cmp` afterwards); no builder is duplicated and no dependency edge to `beam_codec` was added.
- **A `build_stacktrace` trace is derived from the machine's live frames.** With no saved raw `StackTrace` object, the symbolic trace is reconstructed from the executing `(func, pc)` plus `Machine::resumption_addresses()` (the suspended call frames' CP slots), rather than a raise-time snapshot — the honest M1 substitute documented in Known Issues.
- **`update_record` always copies.** The compiler's `copy`/`reuse`/`inplace` hint only authorises an in-place update for a unique/dead source; a copy is observationally equivalent and needs no uniqueness analysis, so M1 ignores the hint.

## Known Issues / Intentional M1 gaps
- **No garbage collection.** `MinimalContext` has an unbounded, never-freed arena; `test_heap`/`allocate_heap` call `ensure_heap` (a no-op there). The real collector + heap sizing is Stage 4 (`beam_gc`); the engine allocates boxed terms only through `terms`/`alloc_words` (BIFs allocate through the context), and `MinimalContext` frees nothing until it drops.
- **`build_stacktrace`/`raw_raise` are executed, but a captured trace is engine-derived.** `raw_raise` is oracle-exact for all three classes (`error`/`exit`/`throw`) and for the unknown-class fall-through (`x(0) = badarg`, no raise). `build_stacktrace` is oracle-exact for a `NIL` raw trace — the only path a compiler-emitted program takes today, since `catch`/`try` land with `x(2) = NIL` and `catch_end` appends no stacktrace element; for a non-`NIL` trace it substitutes a symbolic trace derived from the machine's **live** call frames (`Machine::resumption_addresses`), not from a saved raw `StackTrace`, so unwound frames, out-of-run host frames, saved argument lists, and `error_info` entries are absent, and the innermost item always carries the arity.
- **`catch_end` needs the `EXIT` atom.** A module whose atom table lacks `EXIT` returns a typed `unsupported` rather than substituting a wrong atom.
- **`raise_bif_error` can only raise a nameable error.** A BIF failure whose atom is absent from the running module's atom table (or a `BeamError` with no BEAM atom: `Raise`, `TermNotFound`, `Io`) propagates unchanged, because the `Module` reaches the interpreter read-only (unlike C's global atom table).
- **Compiled bit/word operators are unregistered BIFs.** The compiler emits `band`/`bor`/`bxor`/`bnot`/`bsl`/`bsr` as `gc_bif` calls (no integer opcode exists in C either), so they reach `beam_bifs` through `ctx.call_bif` and fail with `error: erlang:<op>/<n> is not a BIF` — `crates/beam_bifs/src/arith.rs::register` registers only `+ - * / div rem abs` (binary/`+`/`-` unary). `tests/support/mod.rs` supplies `bsl/2`/`bsr/2` locally in the harness BIF floor, so engine tests mask the gap (see Handoffs #5).
- **Compiled arithmetic is oracle-exact on overflow by construction.** `+ - * div rem` overflow promotes to exact bignums: compiled `gc_bif` goes through the frozen `ctx.call_bif` seam into `beam_bifs`, which never overflows to `system_limit`. An out-of-range `Integer`/`Character` **operand** (what `erlc` emits for a small literal ≥ 2^59) is materialized by `terms::make_integer` as an exact bignum, and the JIT's `constant_word` deopts such an operand to the interpreter step instead of calling `make_small`. The remaining literal gap is upstream (a constant-folded ≥ 2^63 literal is a 9-byte operand the loader refuses — see Handoffs #3).
- **Message/receive opcodes are not executed.** `Send`, `LoopRec`, `LoopRecEnd`, `Wait`, `WaitTimeout`, `Timeout`, `RemoveMessage`, `RecvMarkerReserve/Bind/Clear/Use`, and every other named variant no family owns fall through `families::dispatch` to `unsupported("widened opcode not yet executed: <name>")` (the opcode's `ops.tab` spelling, so the rejected instruction is named). This is the **only remaining opcode family** the compiler emits for real modules (1273 `send` / 1850 `remove_message` / 766 `loop_rec` sites across the OTP tree) and it needs the Stage-5 mailbox (`beam_process`/`beam_message`), so it is a handoff, not an engine gap: the engine's crate deps are `beam_common`/`beam_term`/`beam_loader`/`beam_alloc`/`libc` and the `ExecutionContext` trait is frozen (see Handoffs).
- **The OTP-29 native-record opcodes are not lowered to typed IR** by `beam_loader`: `is_native_record`/`get_record_elements`/`put_record`/`is_record_accessible`/`get_record_field`/`get_record_elements_id`/`update_record_id` fall through to `Instr::Generic`, so the engine reports `unsupported(<opcode name>)` for them. `update_record` (the classic form) **is** executed, and `is_any_native_record` (the only one of the family the standard compiler actually emits — 13 sites in `erl_eval`/`io_lib`/`erl_types`/`dialyzer_codeserver`/`dbg_ieval`) **is** executed via `src/generic.rs`. The engine half of the rest needs the native-record term layout (`../../erts/emulator/beam/erl_record.{h,c}`) — a `beam_loader` + `beam_term` handoff (terminals need a constructible record term first).
- **Every other `Instr::Generic` opcode is `unsupported`**, carrying `Opcode::name()`; `is_any_native_record` is the sole exception.
- **Bitstring gaps (each a typed `unsupported`).** A ≤64-bit **unsigned** field whose value exceeds `MAX_SMALL` is a typed error (`make_small_checked`); only the `>64`-bit path builds a bignum. A `bs_create_bin` construct failure with `no_fail` reports a typed raise but not C's exact `badarg` reason (the engine routes through `fail_step`/`{badmatch, V}`). `raw::heap_bits` refuses a refc subject whose window does not start on a byte boundary. `bs_init_writable` and `append`/`private_append` are **implemented** as a copy-rebuild (see the bitstring section and `HANDOFF_bs_init_writable.md`); the honest divergences are no in-place amortised growth (an append loop is O(n²) not amortised O(n)) and the unmodelled `BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER` flags and `binary:referenced_byte_size/1`'s capacity answer. An `append`/`private_append` segment that is **not the first** is a typed `unsupported` (the compiler only emits it first).
- **Literal operands — a loader/data-codec decode gap plus an engine-side operand-seam limit.** The loader *does* decode the `LitT` area into terms (`Module::literal`), but its decode (`beam_codec::decode_term`) does not decode several ETF tags, so a module whose literal area holds one fails to **load** (symptom: `beam_rt` reports `unsupported: external_term`/`BadArg`/`SystemLimit` before any instruction runs). The sweep test (`tests/stdlib_sweep.rs`) measures this on the installed OTP tree: **41 of 261** stdlib+kernel+compiler `.beam` files fail to load — 35 with `unsupported_external_term` (an `EXPORT_EXT`/`NEW_FUN_EXT` external-fun literal; this blocks `maps`, `gen_server`, `gen_event`, `gen_statem`, `proc_lib`, `supervisor`, `logger`, `shell`, `json`, `epp`, `erl_scan`, `erl_pp`, `compile`, …), 4 with `SystemLimit` (an inlined big-integer instruction operand `beam_loader` does not model: `rand`, `disk_log`, `net`, `net_kernel`), 2 with `BadArg` from `lower::build_module` (`dets_v9`, `shell_docs`). All of these are `beam_loader`/`beam_codec` gaps, not this crate's — see Handoffs. On the engine side, a `Literal` index outside the running module's `LitT` table (or a literal read with no module bound) is the typed `operand: literal` error; the `floats` and `bitstrings` families additionally resolve their own literal operands directly through `Module::literal`.
- **Map construction is flat-map only; reads handle hashmaps.** `PutMapAssoc`/`PutMapExact` build via `make_flatmap`, capped at 32 pairs — a larger result is a typed `unsupported` because no crate in the rewrite implements a HAMT builder (it belongs in `beam_term`; `beam_codec` is a sibling the engine may not depend on). `terms::map_entries` walks the frozen `erl_map.h` HAMT node tree (explicit work stack, no hash function, keys matched by `beam_term::cmp`), so `GetMapElements`/`HasMapFields` read a hashmap source; a malformed node / `THE_NON_VALUE` / immediate item is a typed `BadArg`. Enumeration order is storage order, not canonicalized (`erts_cmp_flatmap_keys`), which affects only `term_to_binary` byte comparison, not map semantics. A >32-key **map literal** still fails to **load** (`beam_codec::decode` `Tag::Map` limit) — a separate `beam_codec`/`beam_loader` blocker.
- **A missing map key with `fail == NO_FAIL` has no ground truth** (the compiler always emits a fail label for the matching forms), so it is a documented typed `unsupported` rather than an invented exception reason.
- **`Fconv` carries no fail label and does not convert bignums.** A non-numeric source raises `badarith` through the catch machinery (`raise_badarith`: `Machine::throw_error` with the module's `badarith` atom), landing in a live catch frame or propagating the typed `BeamError::BadArith` when uncaught; a bignum source (no safe wide-integer → `f64` conversion yet) is a typed `unsupported`.
- **A failed function-clause guard is not a `function_clause` raise.** `func_info` is treated as a no-op, so a failed guard that jumps to a function's `func_info` label does not raise `function_clause` (the fixtures avoid that path deliberately).
- **Baseline tier: >4 cached x-registers go to the helper.** A block that touches more than `CACHE_REGISTERS.len()` (4) x-registers does not inline the extras — there is no spill-to-stack register allocator, so the un-cached `Move`s are handed to `jit_step_one` (always correct, just not native). Likewise a `Move` whose `src`/`dst` is a Y slot or a non-cached register, and a `Jump` to an undefined label, go to the helper.
- **Baseline tier: no cross-run code cache.** `run_export` compiles its module per call (`run_with_tier` builds a fresh backend per invocation), so a run through the tier entry recompiles every time; the compile-once / run-many entry ([`JitBackend::run_compiled`] on a caller-held artifact) is the way to amortize it, and *caching* compiled modules (plus the inlining/allocator quality) is still performance work deferred to a later task. The baseline tier is measurably faster than the interpreter on the benchmark workloads (≈1.9× on `fib(20)`, ≈12× on the 256-op kernel — see Measured); the Cranelift tier is faster on `fib` but slower on the kernel because it inlines nothing yet.
- **Baseline tier: only `Move`/`Jump`/metadata are inlined.** Every other instruction (including the whole arithmetic/BIF/call/exception surface) executes via `jit_step_one`, so the block-inline prefix is currently thin; `Tier::BaselineJit` yields interpreter-identical results by construction, not by duplicating instruction semantics.
- **No reductions / preemption / scheduler.** `run_*` executes to the function's `return`; process scheduling, reductions and trap handling are Stage 5 (`beam_process`).
- **`ensure_heap` underflow/limits are not enforced by the machine** — stack growth is an unbounded `Vec` in M1; a configurable stack limit + `system_limit` raise is a later refinement.
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, closure free variables after.** C (`../../erts/emulator/beam/beam_common.c:1631-1633`) fills `reg[i] = args[i]` for `i < arity` **then** `reg[i + arity] = funp->env[i]`, so a concrete context must enter the closure body with `x(0..arity)` = the call arguments and `x(arity..)` = the captures — *not* `free ++ args`. Getting this backwards is silent: a zero-capture lambda in `stdlib_lists`/`stdlib_more` cannot detect it (the two are equal), while `dict`'s capturing lambdas mis-read their arguments and loop forever (this exact bug lived in the `tests/support/mod.rs` host and is what a sweep run of `dict:store/3` exposed). The engine itself is agnostic — it calls `apply_fun(fun, args)` and the context lays out the registers.
- **Cross-crate duplications to avoid:** operand read/write, term comparison, the frame model, the HAMT reader and the bit-layout accessors live here; term construction/comparison must stay in `beam_term` (do not copy).

## Handoffs (opcodes/capabilities this crate cannot close alone)
These are the remaining execution gaps the standard compiler emits for real OTP modules plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node and the exact work. 1–4 are ranked by how many real modules they block; 5–7 are narrower (a BIF-registration set, a `beam_rt` wiring omission, a missing safe conversion).
1. **Receive/message family (`send`/`loop_rec`/`loop_rec_end`/`wait`/`wait_timeout`/`timeout`/`remove_message`/`recv_marker_reserve|bind|use|clear`) → Stage-5 `beam_process`/`beam_message`.** Highest impact (1850 `remove_message` / 1273 `send` / 766 `loop_rec` / 660 `loop_rec_end` / 468 `wait` / 466 `recv_marker_clear` / 1484 other recv-marker sites across the OTP tree). It is the concrete blocker of the differential A.9 corpus cases: `code:get_path/0` → `code:call/1` → `code_server:call/1` performs a `receive`, so the engine stops at `recv_marker_reserve` (verified by tracing `beam_rt -noshell -eval 'is_list(code:get_path())'`). Closing it needs (a) a mailbox seam the engine does not own (`ExecutionContext` is frozen this round) **and** (b) a live `code_server` process in `beam_rt` — engine opcodes alone cannot make those cases pass, so this is a `beam_process`/`beam_rt` handoff, not an engine gap.
2. **`beam_engine → beam_alloc` dependency edge (landed, escalated).** The engine now depends on `beam_alloc` (wave 0 → wave 4, directionally legal) to hold the off-heap refc-binary payloads `bs_init_writable`/`append` need. `bs_init_writable` + `bs_create_bin` `append`/`private_append` + `>64`-byte results are **implemented** (copy-rebuild). The crate-layer node must record the new edge; divergences are in `HANDOFF_bs_init_writable.md`.
3. **`beam_codec` literal decode (`EXPORT_EXT`/`NEW_FUN_EXT` external funs, binary ETF tags, >32-key map literals, inline big-int operands) → `beam_codec`/`beam_loader`.** Blocks **41 of 261** loadable stdlib/kernel/compiler modules (see Known Issues) — including `maps`, `gen_server`, `proc_lib`, `supervisor`, `logger`, `json`, `epp`, `erl_scan`, `compile`. This is a *load* gap, not an execution gap, but it removes far more real-module coverage than any opcode. The engine-side operand seam already carries out-of-range `Integer`/`Character` operands exactly (`[2^59, 2^63)` materializes as a bignum via `terms::make_integer`); what remains is the loader's own limit: `beam_loader/src/decode.rs::read_tagged` refuses an operand wider than 8 bytes (`count > 8` ⇒ `BeamError::SystemLimit`), and `erlc` emits a **9-byte** operand for a *constant-folded* literal ≥ 2^63 — so e.g. `f() -> 123456789012345678 * 98.` fails to **load** (`beam_rt: system_limit`; oracle `12098765323209876444`). Raising the loader's operand width (and `beam_codec`'s big-int literal decode) closes it; runtime, non-folded overflow arithmetic is already oracle-exact.
4. **`is_any_native_record` → a typed `beam_loader` `Instr` variant.** The engine already executes it (via `src/generic.rs`, `src/generic.rs::exec_is_any_native_record`), but it still arrives as `Instr::Generic { op, operands }`. The loader should lower `is_any_native_record f xy` to a typed variant (a `Test`-like guard: fail-branch iff `Src` is a record) so the engine's residual-`Generic` path can shrink to "nothing the compiler emits". The rest of the native-record family (`is_native_record`, `get_record_elements`, …) additionally needs a constructible native-record term in `beam_term` (`../../erts/emulator/beam/erl_record.{h,c}`).
5. **Bit/word-operator BIFs are unregistered → `beam_bifs`.** `crates/beam_bifs/src/arith.rs::register` registers `+ - * / div rem abs` (binary/`+`/`-` unary) only, so a compiled `band`/`bor`/`bxor`/`bnot`/`bsl`/`bsr` (all emitted as `gc_bif` — C has no integer opcode for them either) raises `error: erlang:<op>/<n> is not a BIF` on **every** tier. Registering the six operators with exact `erl` semantics (arbitrary-precision `band/bor/bxor/bsl/bsr`, `badarith` on a non-integer or a negative shift) closes the compiled-arithmetic surface; the engine needs no change (it already routes through `ctx.call_bif`). Note `tests/support/mod.rs` implements `bsl/2`/`bsr/2` locally in the harness BIF floor, which masks this gap in the engine's own tests — remove that shim once `beam_bifs` registers them.
6. **`RuntimeContext` does not wire a fun caller → `beam_rt`.** `crates/beam_rt/src/context.rs::call_registered` builds a `beam_bifs::BifContext` **without** `.with_fun_caller(...)` (`crates/beam_bifs/src/context.rs:196`), so a BIF that applies a fun (`lists:map/2`'s fast path) raises `error: unsupported_bif` instead of calling back into the runtime. Not an engine gap — it blocks `beam_rt::eval::tests::a_loaded_module_applies_an_eval_closure` (pre-existing, identical at this node's base commit `798cb73d2a`; reproduces only in the `--workspace` run).
7. **A safe bignum → `f64` conversion → `beam_term`.** Compiled `Fconv` with a bignum source is still a typed `unsupported` (`src/families/floats.rs:291`, `error::unsupported("fconv: bignum")`) where `erl` returns the inexact double (`big_to_double`). `beam_term::compare` already contains an unsafe wide-int→`f64` (`number_as_f64`, private); exposing it as a documented safe public API is the one missing piece, after which the `floats` family converts instead of erroring. Low impact (a bignum float conversion is rare in real modules) but it is a genuine compiled-vs-oracle divergence.
