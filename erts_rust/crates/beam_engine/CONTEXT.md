# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step (interpreter-identical semantics), with a cross-run compiled-block cache and a block linker (`src/jit/{cache.rs,baseline/emit/link.rs}`). It carries **two layouts behind one `CompiledModule`** (`src/jit/baseline/code.rs`): an **eager whole-module** artifact (produced by `JitBackend::compile`, keeping the whole-module introspection surface -- `block_count`/`cached_registers`/`code_address_range`/`code_map`) and a **lazy per-function** artifact (one sealed mapping per function, lowered on first entry of a `(func, pc)` and cached) that the runtime path (`run_baseline_cached*` / `cached_module_blocks`) uses, so a fresh process pays only the functions it actually enters instead of the whole module. The **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) is one Cranelift function per IR function over the same shared interpreter-backed helper. All tiers are **measurement-gated** and off the critical path (Part II sec. F) -- correctness-first *mechanisms*, not optimisers.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end, with explicit dispatch arms for the core opcodes and a per-instruction-family seam (`src/families/`) for the rest. The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC, process/stack limits and pre-emption all sit behind `ExecutionContext` (implemented by `beam_rt`), keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: computation goes through `ExecutionContext::call_bif`, and an in-machine callee through the resolver seams (`resolve_external_call`/`resolve_local_fun`), with `ExecutionContext::apply`/`apply_fun` the value-returning fallbacks.

### The context seam (`src/context.rs`)
```rust
pub trait ExecutionContext {
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;
    /// The full-root twin of `ensure_heap` (adds the FR file);
    /// `Machine::ensure_heap` calls THIS, its default forwarding to the narrow one.
    fn ensure_heap_full(&mut self, heap_need: u32, roots: RootSet<'_>) -> Result<()> {
        self.ensure_heap(heap_need, roots.live, roots.x, roots.stack)
    }
    fn heap_available(&self) -> usize { usize::MAX }
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;
    /// The rooted twin of `alloc_words`: the same request WITH the live root set.
    fn alloc_words_rooted(&mut self, n: usize, roots: RootSet<'_>) -> Result<*mut Eterm> {
        let _ = roots; self.alloc_words(n)
    }
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
    // ...the nine Mailbox twins (send_message / receive_*) are defaulted here too;
    //    they are documented in the mailbox section below.
    /// The `send` seam WITH the machine's off-heap payload handles (default: forward).
    fn send_message_with_off_heap(&mut self, to: Eterm, message: Eterm,
        src_binaries: &[beam_alloc::RefcBinary]) -> Result<()> { self.send_message(to, message) }
    /// Cross-module call seam: run the callee in THIS machine, or `None`.
    fn resolve_external_call(&mut self, module: &str, function: &str, arity: u32)
        -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>> { Ok(None) }
    /// In-machine closure-apply seam: run a `call_fun` closure's lambda HERE, or `None`.
    fn resolve_local_fun(&mut self, fun: Eterm, args: &[Eterm])
        -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>> { Ok(None) }
    /// The per-instruction reduction hook: charge `n` for the instruction about to execute.
    fn reduce(&mut self, n: u32) -> Result<()> { let _ = n; Ok(()) }
    /// Whether the host wants the per-instruction `reduce` charges at all: latched once per
    /// run into `Machine::reduce_on` (like the A.8 trace gate), so a host whose `reduce` is
    /// the default no-op pays a predictable branch instead of a vtable call. Defaults to the
    /// CONSERVATIVE `true` -- a host that implements `reduce` (e.g. `beam_rt`'s scheduler)
    /// MUST stay `true`, or its pre-emption charges would be silently dropped. The slice
    /// counter `Machine::reductions()` is still bumped every instruction regardless.
    fn wants_reduce(&self) -> bool { true }
    /// Contract A.8 execution-trace seam: a cheap gate + a defaulted no-op reporter.
    fn trace_enabled(&self) -> bool { false }
    fn trace_event(&mut self, event: TraceEvent<'_>) { let _ = event; }
}
/// The engine's mutable root set -- the hand-off `alloc_words_rooted` receives.
pub struct RootSet<'a> {
    pub x: &'a mut [Eterm],     // the whole X-register file; `x[..live_len()]` is live
    pub stack: &'a mut [Eterm], // the WHOLE Erlang stack
    pub fr: &'a mut [Eterm],    // the WHOLE float-register (FR) file (Eterm term slots)
    pub live: u32,              // live-X hint (clamped; `RootSet::ALL_LIVE` = all)
}
impl<'a> RootSet<'a> {
    pub const ALL_LIVE: u32 = u32::MAX;
    pub fn new(x: &'a mut [Eterm], stack: &'a mut [Eterm], fr: &'a mut [Eterm], live: u32) -> RootSet<'a>;
    pub fn live_len(&self) -> usize;            // `live` clamped to `x.len()`
    pub fn live_x(&self) -> &[Eterm];           // `x[..live_len()]`
    pub fn live_x_mut(&mut self) -> &mut [Eterm];
}
pub enum TraceEvent<'a> {
    Call { module: &'a str, function: &'a str, arity: u32, args: &'a [Eterm] },
    ReturnFrom { module: &'a str, function: &'a str, arity: u32, value: Eterm },
    ReturnTo { module: &'a str, function: &'a str, arity: u32 },
}
```
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- **The GC root-set contract, in two doors.** `ensure_heap(heap_need, live, x_regs, stack)` is the frozen **narrow** admission point; `Machine::ensure_heap` (reached by `test_heap`/`allocate_heap`) calls the defaulted **`ensure_heap_full(heap_need, roots)`**, which receives the whole [`RootSet`] (**including the FR file**, which holds `Eterm` term slots) and whose default forwards to the narrow `ensure_heap` with the FR file discarded -- so a host that predates the full door is byte-identical, and a host with a real collector overrides `ensure_heap_full` to run the collector over every live root at the primary admission point.
- **`alloc_words_rooted(n, roots)` is the term-construction admission door** (`alloc_words` itself has neither an admission point nor roots). Its **default discards the roots and forwards to `alloc_words`**, so every implementor that predates it is byte-identical; a collecting host overrides it, relocates every term reachable from the roots first, and writes any moved term back through `roots.x`/`roots.stack`/`roots.fr`. The **frozen contract**: the live roots are `roots.x[..roots.live_len()]`, **the whole** `roots.stack` (every Y slot of every live frame -- no frame liveness maps) and **the whole** `roots.fr` (a float register holds a term slot, so it can hold a heap pointer). `live` is only a hint: `live_len()` clamps it, so `RootSet::ALL_LIVE` is always *safe* for a copying collector. Nothing outside the root set survives: a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation.
- **The engine side of that hand-off is [`Machine::alloc_rooted`] / [`Machine::with_roots`].** `with_roots(live, f)` lends the machine's own three files as one disjoint `RootSet` (three separate `x_mut`/`stack_mut`/`fr_mut` borrows cannot coexist); `alloc_rooted(ctx, n, live)` calls `ctx.alloc_words_rooted(n, roots)`. The single-view accessors are `Machine::{x_mut, stack_mut, fr_mut}`. **Every in-crate term-construction arm routes through this seam** via the `terms::*_rooted` builders (see sec. Term helpers); the only `alloc_words` caller left in the crate is the four `&self` execution-position accessors in `src/machine/location.rs` (a `&self` caller cannot lend `&mut` roots).
- **`reduce(n)` is the per-instruction reduction hook** (defaulted no-op). `Machine::drive` charges it **once per interpreted instruction** with `n = 1`, **before** the instruction's body runs (C `beam_emu` `DISPATCH` order, where `FCALLS` is checked before the body), so a host with a scheduler enforces a time slice by returning a **typed error** from `reduce` (the run reports it exactly like any other step failure -- pre-empting, never a panic) and that error leaves the instruction **un-applied** with the machine parked on it (`Machine::current_code`), so a `Machine::resume_outcome` at that address applies it **exactly once**. It is the only pre-emption point a **non-allocating** loop reaches (`ensure_heap` is never called by one). `Machine::reductions()` reads the slice's count (one `drive` call = one scheduling slice, zeroed at entry; a **lower bound** under a native tier) and `Machine::reset_reductions()` returns it while zeroing it. There is **no `RunOutcome::Yield` variant and no `ReduceOutcome`**: pre-emption is an `Err` out of `reduce`, resumption is a fresh `drive` (`resume_outcome`).
- `apply` is the general synchronous `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the **value-returning fallback** for `call_fun`/`call_fun2` (default a typed `error::unsupported` -- the engine keeps no closure registry), consulted only after the in-machine `resolve_local_fun` seam declines, and entering the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables (C's `call_fun` order). Both the seam's and the fallback's errors are routed through `Machine::raise_bif_error`, so a routable raise from a nested closure application lands in the caller's live `try`/`catch`; a genuine capability gap stays the uncatchable typed error.
- **`resolve_external_call` -- the cross-module call seam (the `call_ext*` and `apply`/`apply_last` route).** A host that owns loaded modules may answer a `call_ext*` or a dynamic `apply(M,F,A)` `(module, function, arity)` with `Some((callee_module, entry_label))`, and the engine then executes the callee **in the same machine** (see sec. Module contexts) instead of routing the call through the synchronous `call_bif`. `callee_module` must be the **shared** `Arc<Module>` the host loaded the module with -- the engine keeps it alive for as long as a suspended frame can return into it, and dedups contexts by `Arc::ptr_eq`; `entry_label` is the **export entry label** (`callee_module.export(function, arity)`, the label *after* `func_info`), resolved against the callee's own label map and entered with `x(0..arity)` = the call arguments. The **default returns `Ok(None)`** ("I cannot run this callee in your machine"), keeping the synchronous `call_bif` path as the fallback, so every host is byte-identical. See Handoff #10.
- **`resolve_local_fun` -- the in-machine closure-apply seam (the `call_fun`/`call_fun2` route).** Consulted **first** by the `call_fun`/`call_fun2` family: a host that owns the closure's defining module answers `Some((callee_module, lambda_entry_label))` and the engine enters the lambda body **in this machine**, exactly as C's `call_fun` dispatches to the fun body's code in the same process. The call `args` stay in `x(0..arity)`, the engine copies the closure's free variables into `x(arity..)` (C's `reg[i + arity] = funp->env[i]` order) and stores the caller's continuation (`func`, `pc + 1`, current context) in the live frame, then reports `Step::Enter`; a `receive`/raise inside the closure therefore suspends/raises **this** process (instead of a fresh machine whose `Wait` surfaces at the call site as the typed `error::blocked()`). `callee_module` must be the **shared** `Arc<Module>` the host loaded the module with (module contexts dedup by `Arc::ptr_eq`); `lambda_entry_label` is the lambda's **`FunT` entry label**, resolved against the callee's own label map (an unknown label is `error::unknown_label`, never a jump into the wrong module). The **default returns `Ok(None)`** ("I cannot run this closure in your machine"), keeping the value-returning `apply_fun` fallback -- the fun kinds with no local label (an external `fun M:F/A` and the `-eval` evaluator's closure) -- byte-identical for a host without the seam. See Handoff #12.
- **`call_ext*` and the `erlang:apply/3` special case.** The `CallExt`/`CallExtOnly`/`CallExtLast` arms special-case the import `erlang:apply/3` (`Machine::resolve_call_ext_apply`), reproducing C's `fixed_apply` -> `apply()` (`../../erts/emulator/beam/beam_common.c`): decode `x(0) = Module`, `x(1) = Function`, `x(2) = Args`, unwrap C's nested `apply of apply/3` shape (`[erlang, apply, Inner]`) in a loop, walk the argument list into `x(0..N)` (a list past C's `MAX_ARG` = 255 is `error:system_limit`; a non-proper tail is the catchable `badarg`), place `Module`/`Function` at `x(N)`/`x(N+1)`, then dispatch through `families::funs::apply_target` under the arm's **own** frame discipline (the cross-module-call-seam route above; the `ImportFrame` shape). **Only `apply/3` is this special case**: the `erlang:apply/2` import (`apply(Fun, Args)`) is left on the ordinary `call_bif` route, matching C, whose `fixed_apply` special-cases only `arity == 3`. The point is that a *scheduled* process runs `proc_lib:init_p_do_apply/3`'s **non-tail** `{call_ext,3,{extfunc,erlang,apply,3}}` in-machine, so its callee can suspend through the ordinary `RunOutcome::Wait` path rather than folding into the uncatchable typed `error::blocked()` (the route the synchronous `call_bif` fallback takes on a non-pumpable machine).
- **Contract A.8 execution-trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}` / `{trace,Pid,return_from,{M,F,A},Ret}` / `{trace,Pid,return_to,{M,F,A}}` shapes; `trace_enabled()` is the cheap gate and `trace_event` the defaulted no-op reporter. The engine **reports only** -- the host owns matching (`beam_rt`'s `PatternTable::matches`) and term building. Emission (`src/interpreter/trace.rs`, wired in `src/interpreter/dispatch.rs`): `Call` for the local callee on `call`/`call_only`/`call_last` and for the import on `call_ext*` (**entry only**); at a live `Continuation::Address` `return`, `ReturnFrom` then `ReturnTo` (a `call_only`/`call_last` chain's `ReturnTo` names the **original** caller, oracle-probed). The gate is latched once per run into `Machine::trace_on`, so the hot path pays one `bool` load. Emission is infallible (an unresolvable name/index is skipped, never raised), so a traced run is byte-identical to an untraced one; **a natively-executed JIT block does not trace**.
- `pub type BifHook`/`ApplyHook`/`ExternalResolver`/`LocalFunResolver` -- the pluggable bodies of `call_bif`/`apply_fun`/`resolve_external_call`/`resolve_local_fun` a `MinimalContext` installs via `with_bif_hook`/`with_apply_hook`/`with_external_resolver`/`with_local_fun_resolver` (and the matching `set_*`).
- `MinimalContext` -- the test/embedding context: an unbounded heap (`ensure_heap` = `Ok(())`), a **pluggable BIF hook** (`new()` rejects every BIF), an **optional apply hook**, **optional cross-module and local-closure resolvers** and an **optional mailbox**. `alloc_words` hands out words from a pointer-stable **reserved-heap** arena (`src/context.rs`'s `ContextHeap`, backed by `beam_alloc::ReservedHeap`): a large address range (~4 MiB) is reserved up front (carriers `mmap`-backed, so reserved pages fault lazily) and **grown in place** (`GrowOutcome::GrewInPlace`) as terms are built, so an allocation costs its payload only; on reservation exhaustion (`GrowOutcome::MoveRequired`) a fresh, larger region is started and **every earlier region is kept alive**, so a handed-out pointer stays valid and **unmoved** for the life of the context (`relocate` is deliberately never used -- it would move the whole live block and invalidate the pointers already in registers/structures). It does **not** override `alloc_words_rooted`: it inherits the default (roots discarded → `alloc_words`), so it stays the test/embedding heap rather than a collector.

### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
```rust
pub trait Mailbox {
    fn send_message(&mut self, to: Eterm, message: Eterm) -> Result<()>;
    fn receive_next(&mut self) -> Result<Option<Eterm>>;
    fn receive_skip(&mut self) -> Result<()>;
    fn receive_remove(&mut self) -> Result<()>;
    fn receive_reset(&mut self) -> Result<()>;
    fn receive_marker_reserve(&mut self) -> Result<Eterm>;
    fn receive_marker_bind(&mut self, marker: Eterm, reference: Eterm) -> Result<()>;
    fn receive_marker_use(&mut self, reference: Eterm) -> Result<()>;
    fn receive_marker_clear(&mut self, reference: Eterm) -> Result<()>;
}
```
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")`, so every implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- **`send_message_with_off_heap(to, message, src_binaries: &[beam_alloc::RefcBinary])`** is the `Instr::Send` arm's entry (`src/families/receive.rs`): a tenth defaulted `ExecutionContext` method whose default **forwards to `send_message` and discards `src_binaries`**, so every existing implementor (all test contexts, `MinimalContext`) is byte-identical. The `send` arm calls it with the running machine's handles, `machine.refc_binaries()` (the machine is already a parameter of the family's `exec`, so no run-loop plumbing is needed). `src_binaries` is the **source off-heap table** the receiver-side copy needs to resolve an engine-built off-heap (refc) binary in the message: a `bs_init_writable`/`bs_create_bin` result over `beam_term::refc::ERL_ONHEAP_BINARY_LIMIT` bytes lives off the process heap, and the copy engine resolves it by data pointer through the copy's *source* off-heap table (`beam_message::OffHeapTable::binary_by_data_ptr`). The engine side is complete; a host with no off-heap payloads keeps the documented degradation (Handoff #1, and the off-heap Known-Issues bullet below).- `receive_next` is the *candidate* at the current scan position (`Ok(None)` = exhausted); `receive_skip` is `loop_rec_end` (advance one); `receive_remove` is `remove_message` (unlink the matched candidate, reposition at the first); `receive_reset` is `timeout` (reposition at the first). The engine **never inspects a message or a marker**: selection is the compiled code's job (the matching instructions between `loop_rec` and `loop_rec_end`), and a marker term is **opaque** (produced by `receive_marker_reserve`, handed back verbatim by `receive_marker_bind`; only a separate *reference* reaches `receive_marker_use`/`receive_marker_clear`). Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still surface the typed `error::blocked` (Handoff #1).
- **Ordering invariant (why the driving cannot reorder/double-examine, given a FIFO host).** `receive_skip`/`receive_remove`/`receive_reset` take **no candidate argument** -- the host acts on its **own** persistent scan position (`receive_remove` unlinks whatever is at the host's current position, NOT the term the engine read into `Dst`), so the engine's driving is correct only while that position is stable between the `loop_rec` that produced a candidate and the `remove_message`/`loop_rec_end` that consumes it. That holds by construction: between those two the engine issues **no other seam call** and never blocks (only the compiled pattern-match instructions run; the candidate lives solely in an x-register), so no host mutation can intervene.
- A `receive` reaches `wait`/`wait_timeout` (and thus blocks, `Step::Wait` -> `RunOutcome::Wait`) **only** via `loop_rec`'s `None` arm (`receive.rs`) -- i.e. the host scan is already **exhausted**. So a `resume_outcome` re-entry at the `wait` target's `loop_rec` re-reads from that exhausted position and sees only messages appended since: no examined message is re-read and none is skipped. Host contract this relies on: FIFO with a **saturating** scan index (`beam_message::QueueCursor` + `beam_rt::MailboxState`), pinned by `tests/receive.rs` (`scan_skips_a_non_matching_head_before_matching`, `a_suspended_receive_resumes_when_a_message_arrives`, `the_mailbox_repositions_the_scan_at_a_marker`).

### The machine (`src/machine/{mod,registers,frames,catch,run,location,context,drive}.rs`)
Per-file API detail lives in `src/machine/CONTEXT.md`; the load-bearing facts:
- `pub struct Machine` is the process-state core: the **x-register file**, the **float-register (FR) file**, the **Erlang stack**, the **call-frame stack**, the **exception catch-frame stack**, the `refc_binaries` arena (never cleared by `reset`), the running module's decoded **literal area** (`literals: Option<SharedLiteralArea>`, read via `Machine::literal(index)`), the **module-context registry** (`contexts: Contexts` + `context: u32` + the `entry_literals` binding; sec. Module contexts), the reduction counter, the **raise-time snapshot** `raise_snapshot: Vec<(context, func, pc)>` (the pre-unwind frame chain; sec. the uniform raise funnel), and the latched A.8 gate `trace_on`. `pub const MAX_REGISTER: u32 = 1024;` (the x-file, C's `MAX_REG`) and `pub const MAX_FLOAT_REGISTER: u32 = 1024;` (the FR file, C's `f_reg_array`; it holds **`Eterm` term slots**).
- `Machine::new()`/`default()`/`with_max_register(u32)`; `get_fr(n)`/`set_fr(n, Eterm)` are bounds-checked FR access (`bad_register` on overflow). `reset` refills both files in 128-byte chunks and clears the literals binding (incl. `entry_literals`), the context registry (`context = 0`), stacks, pending exception, resolved class atoms, `current_code`/`entry_call`, the raise snapshot and `trace_on`.
- `run.rs`: `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware), plus `resume_outcome_with_tier` (the tier-aware resume; `resume_outcome` stays the interpreter default, its 4-arg signature unchanged). `run_export` resolves `function/arity`'s export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return`, yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error. The loop is `pub(crate) fn run_loop`/`run_loop_with_map` (`src/interpreter/dispatch.rs`), thin wrappers over `Machine::drive`.
- Introspection (read-only): `x(n)`, `get_fr(n)`, `y(k)`/`y_mut(k)`, `frame_depth()`, `stack_depth()`, `catch_frame_depth()`, `pending_exception()`, `pending_class()`, `resumption_addresses()`/`resumption_contexts()` (every live call frame's suspended `(func, pc)` CP slot, innermost first, each with the module context it belongs to -- the live chain `current_stacktrace` resolves), `raise_snapshot()` (the **raise-time** pre-unwind `(context, func, pc)` chain, the **raising** frame first then every live caller innermost-first -- what `build_stacktrace` cooks from), `wait_deadline()` (the parked-receive `WaitDeadline`), `reductions()`, `reset_reductions()`.
- **Execution-position introspection (`src/machine/location.rs`)** -- the engine half of `process_info/2`'s position items. `Machine` records `current_code: Option<(u32, u32)>` (the last executed `(func, pc)`; on the interpreter it is exact at every suspension, since a blocking `wait` is never inlined, and a native baseline block sets it at block entry via `Machine::set_current_code` -- block-granular, and a traced run refuses native entry so it stays interpreter-exact) and `entry_call: Option<(u32, u32)>` (the run's entry `(func, arity)`). Accessors: `current_code()`/`entry_call()`, plus the oracle-shaped `current_function`/`initial_call` (`{M,F,A}`), `current_location` (`{M,F,A,[{file,F},{line,L}]}`) and `current_stacktrace` (the cooked list). `current_function`/`current_location`/`current_stacktrace` resolve the position against `current_module()` -- the module the machine is actually running in -- falling back to the passed entry module only when there is none (context `0`); `current_stacktrace` resolves **each** resumed frame in **its own** module context (via `Machine::resumption_contexts`). `initial_call` deliberately resolves against the passed entry module (it *is* the `$initial_call`). `pub fn Machine::current_module(&self) -> Option<Arc<Module>>` (`None` = "the run's entry module the caller passed") is the accessor. Honest by construction: no instruction interpreted => `None`/`NIL`; an out-of-range `func` => typed `unsupported`; a location the module cannot name => the typed error `build_stacktrace` already reports (Handoff #2).
- `pub struct CatchFrame { pub func: u32, pub pc: u32, pub frame_index: usize }` (+ `CatchFrame::new`) -- the handler's `(func, pc)` plus the call frame that **owns** it; the `pub(crate) context: u32` field is stamped by `push_catch_frame` from `current_context()` and is **not** part of the 3-arg `CatchFrame::new`. `push_catch_frame`/`pop_catch_frame` are the public accessors.
- **The uniform raise funnel (`src/machine/catch.rs`).** `Machine::throw`/`throw_error` are the raise/unwind entries the families call; `Machine::throw_with_trace(class, reason, trace)` is the same entry carrying the caller-built raw `trace` term (C's `x(2)`; `NIL` at M1). It also **rebuilds the machine's raise-time frame snapshot** (`Machine::raise_snapshot`) at its head -- the pre-unwind `(context, func, pc)` chain, the **raising** frame first then every live caller innermost-first -- *before* the catch-frame branch and `unwind_to_frame`, so the snapshot is refreshed on **both** the caught and the uncaught path; `Machine::reset` clears it and a resume preserves it. The symbolic [`StackTrace`] an **uncaught** raise carries is **not** a raise parameter: the single funnel **`Machine::with_uncaught_frames(err, entry_module, func, pc)`** attaches it as the raise leaves the machine (at the `step_instruction` / `drive` boundary), so **every** raise kind (a `throw`/`error`/`exit` builder, a BIF failure, the `func_info` failed-clause raise) gets the same frames -- and only when `raise.stacktrace.is_empty()` and the reason is not an engine diagnostic. `Machine::raise_stacktrace(&self, entry_module: Option<&Module>, func, pc)` derives them (raising function first, every live caller innermost first, each in its own module context). A **caught** raise never carries them out; the frames are metadata only, so a caught raise is byte-identical with or without them.
- **Module contexts (`src/machine/context.rs`).** A `call_ext*` the host resolved through `resolve_external_call` executes the callee **in this machine**, so `(func, pc)` are indices into *another* module's function table and the machine must remember which. `ModuleContext { module: Arc<Module>, labels: LabelMap }` is one enterable module (its label map built once at registration); `Contexts` is the registry (`register` dedups by `Arc::ptr_eq` and returns `id = index + 1`; `handle(id)` clones the `Arc` so the driver can hold it while the machine is `&mut`). Context `0` is the run's **entry** module, which the machine never owns (the driver borrows it) -- `entry_literals` records its literal area so `switch_context(0)` can restore it. `Machine::{current_context, register_context, switch_context, module_context}` are the accessors; `switch_context(id)` re-binds `literals` (a no-op when `id` is already current) and an unregistered id is the typed `error::unsupported("run: unknown module context")`. `reset` clears the whole set, a **resume does not** (a suspended cross-module frame must still name its module).

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func: u32, pc: u32 }, Enter { context: u32, func: u32, pc: u32 }, Wait { func: u32, pc: u32 }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`/context. `Next` = continue at `pc + 1`; `Goto` = jump **within the current module**; `Enter` = transfer to `(func, pc)` in module context `context` (a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address` in another context, or a raise landing in another context's live catch frame) -- the driver switches the context and re-binds the literal area exactly here; `Done` = finish and yield `x(0)`.
- `Wait` is the **suspend** signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later. The loop folds it into a `RunOutcome`; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto`/`Step::Enter` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which **routes by the instruction's own variant** to the single family that owns it — a `match instr` that compiles to a jump table on the `Instr` discriminant. Family ownership is **disjoint** (each of the **77** claimed variants has exactly one owning family: `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`). The tuple family owns `PutTuple2`/`GetTupleElement`/`SetTupleElement`/`SelectTupleArity`; `SetTupleElement` is the destructive in-place write (`tuple_val(Tuple)[1 + offset]`, `src/terms/update.rs`), whose non-tuple/out-of-range target raises the read path's `{badmatch, Source}` and whose literal-area target is a typed `unsupported`. The router, `dispatch` and `lists::exec` are `#[inline]`.
- Each family exposes `pub(crate) fn exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = "this family executed it", `Ok(None)` = "not this family's variant", `Err` = the family raised. A variant **no** family owns (a core-loop arm or metadata no-op) or one a family declines falls to the router's last arm, which returns `error::unsupported("widened opcode not yet executed: <ops.tab name>")`, so an unclaimed opcode is diagnosable from the error alone.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,slack,sink,alloc_tests,tests}.rs`) -- the SAFETY-annotated builder/reader
The per-file API, the two-builder design and the frozen reserve→read→write discipline are in `src/terms/CONTEXT.md`; the load-bearing facts:
- Each builder comes in **two flavours**: the **classic** public builder (`make_tuple`, `make_cons`, `make_list`, `badmatch_reason`, `make_heap_binary`, `make_float`, `make_integer`, `make_flatmap`, `make_map`, `make_fun`) allocates through the plain `alloc_words` and takes already-materialized operands (the frozen cross-crate signature `beam_rt` and `tests/**` consume); its **`*_rooted` twin** (`make_tuple_rooted`, `make_cons_rooted`, `make_list_rooted`, `badmatch_reason_rooted`, `make_heap_binary_rooted`, `make_float_rooted`, `make_integer_rooted`, `make_flatmap_rooted`, `make_map_rooted`, `make_fun_rooted`) takes `machine`/`ctx`/`live` plus a `read` closure and reserves the block **before** reading operands, so a **moving** collector may relocate them in between. `src/slack.rs` is the `Slack` bump-carve (`reserve`/`reserve_slack`); `src/sink.rs` is the `Sink` trait (`write_tuple_at`/`write_list_at`) a multi-node shape is carved from. **Every in-crate construction arm uses the rooted twin.**
- `make_map(ctx, &[(Eterm, Eterm)], atoms)` -- the **general map builder**: reserves `beam_term::map::map_words_capacity(n)` words and delegates to `beam_term::map::write_map`, so it builds a map of ANY size -- a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys, else a **hashmap** (HAMT) -- collapsing duplicate keys **last value wins**. `make_flatmap` serves flat-layout-only callers (`>32` pairs -> a typed `unsupported`).
- `make_fun`/`make_fun_rooted(arity, uniq, index, free)` build a minimal local closure (M1 inlines the out-of-line fun-entry descriptor).
- Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`) cover the tuple/cons/list/float/map/binary accessors plus the fun readers (`is_fun`/`fun_arity`/`fun_num_free`/`fun_uniq`/`fun_index`/`fun_free`/`fun_true_arity`); `map_entries` walks both map layouts. The engine only *builds* `FunKind::Local` closures, but the readers cover every kind: `fun_arity` is the 8-bit header field (what `is_function/2` and the C `fun_info(F, arity)` use, saturating at 255), while `fun_true_arity` (forwarding `beam_term::fun::fun_true_arity`) returns an **external** fun's real arity from descriptor word 3 of the widened `[header, module, function, arity]` descriptor — the value an encoder must emit. Every fun block size in the crate derives from `beam_term::fun::{fun_words, fun_desc_words, FUN_DESC_WORDS_LOCAL}`; no descriptor width is hard-coded. `badmatch_reason`/`badmatch_reason_rooted` build the shared `{badmatch, Value}` raise reason (a typed `BeamError::BadMatch` when the module lacks the atom).

### The JIT tier seam (`src/jit/`)
Per-file detail is in `src/jit/CONTEXT.md` (+ `baseline/`, `baseline/emit/`, `cranelift/`, `emitter/`); the load-bearing facts:
- `Tier { Interpreter, BaselineJit, Cranelift }` (`Tier::ALL` = roster order, interpreter first) with `name()`/`from_name()`/`is_available()`; `available_tiers()` = exactly `["interpreter", "baseline-jit"]` plus `"jit-cranelift"` when the feature is on.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module)`; `run_compiled(&self, &Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>`; and the provided `run_export`. `run_compiled` is `&self` because the artifact is **caller-owned**. The interpreter is deliberately **not** a `JitBackend`.
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`) -- the **non-blocking** tier entries (`Result<Eterm>`; a suspend folds to `error::blocked()`): `Interpreter` -> `run_export`; `BaselineJit` -> `run_baseline_cached`; `Cranelift` -> `run_cranelift` when the feature is on, else the typed `error::unsupported("jit-cranelift tier not built")`. `Machine::run_export_outcome_with_tier`/`run_label_outcome_with_tier` are the **outcome-aware** twins (`Result<RunOutcome>`, `Wait` included), and `Machine::resume_outcome_with_tier` is the **resume** twin: a slice that suspended (`RunOutcome::Wait`) re-enters on the SAME tier it was entered on, so the tier survives a `receive` park (the baseline resume driver does **not** reset the machine -- registers/stack/frames survive, and a resume in a **non-zero module context** -- a slice parked inside a cross-module callee -- is now served too, the driver re-entering the context the process blocked in). `Tier::Cranelift` cannot resume at an arbitrary mid-function `pc` (its `CompiledEntries` enter only at a function's entry `pc`), so it reports the honest typed `unsupported` -- never a silent fallback to the interpreter. A suspend crosses the block ABI as a `WAIT_BIT` word (`jit::baseline::{encode_wait,decode_wait,WAIT_BIT}`).
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier. `src/jit/tiering.rs`'s `TierPolicy` models the *interpret → baseline → hot* escalation as a **policy only** (nothing on an execution path consults it).
- `src/jit/cache.rs` -- the **cross-run compiled-block cache**: `module_fingerprint(&Module)` hashes the module's **decoded IR content** (deterministic, **never a pointer**), and `ModuleKey { name, fingerprint }` stops same-named/different-content collisions. `CodeCache` (`get_or_compile`/`run_export`/`contains`/`len`/`clear`) **owns** each `CompiledModule`; it is per-thread (`thread_local!`; `mmap` pointers make artifacts `!Send`/`!Sync`) and backs `run_baseline_cached`/`run_baseline_cached_outcome`. `baseline_code_map(&Module)` (and `CodeCache::code_map`) exposes the **real** generated ranges (`CodeRegion { start, size, name }` with an actual `CompiledModule::entry` start and a `<module>:<function>/<arity>/<pc>` name) for a host's `+JPperf` perf map -- never fabricated.
- `src/jit/emitter/*` -- the `#[allow(unsafe_code)]` x86-64 encoder + executable `CodeBuffer` both tiers build on: the crate's only `mmap` RW -> `mprotect` RX on `seal` (never RWX, `munmap` in `Drop`).
- `src/jit/baseline/` -- the **native baseline backend** (block ABI: `extern "C" fn(*mut JitRuntime) -> i64` returning `encode_target(func, pc) = func<<32 | pc` / `HALT = -1` / `ERROR = -2` / `ENTER = -3` (a driver-mediated module-context transfer -- see Error interop); `JitRuntime` carries `machine`, `x_regs`, `module`, `labels`, `ctx`, `error`, `enter`, and generated code loads **only** `x_regs`). `jit_step_one` *is* `Machine::step_instruction` folded into the block ABI and `jit_tail_call` is `Machine::pop_frame_checked`, so a tier is interpreter-identical for every supported opcode. A usage-weighted per-block register picker caches the five most-touched x-registers (`emit/regalloc.rs`); residency is block-fixed and the prologue/epilogue spill the residents at every block exit, so a helper/GC sees the interpreter's exact root set. Blocks are linked at `seal` (a taken branch to a compiled successor is a `rel32` fixup) -- including both **local tail calls**, `call_only{Dest}` and `call_last{Dest,Deallocate}`; an unlinkable exit returns to the driver for one interpreter step. `run_native_outcome` returns `RunOutcome` (a `WAIT_BIT` word / `Step::Wait` -> `RunOutcome::Wait`). The inline set is the metadata no-ops, `Move`/`Swap`, `Jump`, the `Test` family (the word tests **and** the boxed-term type/arity tests -- `emit/test.rs::test_plan`), all-immediate `SelectVal`, `SelectTupleArity`, the cons/tuple readers, the guarded small-int `'+'/2`/`'-'/2`/`'*'/2` `gc_bif` fast paths, the eight comparison BIFs, the local tail calls and the native `call_ext`/`call_ext_only`/`call_ext_last` arm (the `ENTER` word above); **everything else deopts** (a `Y`/`Literal` operand, an out-of-range register, a `NO_FAIL` test, a refused test shape, a non-immediate `SelectVal` case, `PutTuple2`, `BsTestTail`, `FuncInfo`, an unlinkable tail target, the `call`/`apply`/`call_fun`/exception surface), so the interpreter's exact error surfaces stand. Every compiled block's PROLOGUE records its own `(func, pc)` (`Machine::set_current_code`), so `current_code` stays block-exact even across linked chains, and a **traced** run (`ctx.trace_enabled()`) refuses native entry entirely and runs the interpreter driver, so a traced tier-run is byte-identical to a traced interpreter run.
  - `src/jit/cranelift/*` (`#[cfg(feature = "jit-cranelift")]`) -- the **optional Cranelift hot backend**: one Cranelift function per IR `Function` with the same block ABI and the entry `pc` baked in, inlining the **same cheap set as the baseline** where the two agree exactly and deopting the rest to `jit_step_one`; `report.rs` exposes a `CodegenReport`. `CompiledFunctions` owns the `JITModule`; `CompiledEntries` enters a function **only at its entry `pc`**.
- `src/jit/bench/` is a **`pub mod bench`** (not test-gated): the engine's single JIT-measurement harness (ten workloads split into the shapes the baseline **deopts** and the shapes it **inlines**, the timing loop, the reporting and the shared scaffolding the Cranelift ABBA harness consumes). `tests/jit_bench.rs` is a thin driver over it; see `src/jit/bench/CONTEXT.md` and `MEASURED.md`.

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), and `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend.
- **`Step::Enter` executes on the native baseline tier via a driver-mediated context switch.** A `call_ext*` resolved through `resolve_external_call` is not in the JIT inline set, so the block deopts one step; that step resolves the import through the seam and hands the driver a `Step::Enter` (carried out of a block as the `ENTER` block-ABI word). The baseline driver switches module context (reusing `Machine::switch_context` + the context registry + the literal rebind, exactly as `Machine::drive` does) and re-enters the callee's compiled blocks when the tier has them (`NativeCode::module_blocks`), else its per-instruction step -- so the transfer is a **driver round-trip by design**: a seal-time cross-module link is unsound (each `CompiledModule` owns a separate executable mapping, `rel32` fixups are buffer-local, and the entry module is baked into `JitRuntime`). `run_compiled_resume_outcome` likewise serves a slice parked inside a cross-module callee. The Cranelift tier inherits the defaulted `module_blocks -> None`, so a cross-module callee runs on its per-instruction step there.

## Execution model (frozen semantics -- reproduce, don't reinvent)
The binding semantics in brief; the exhaustive per-instruction/per-operand/per-family detail (with the `ops.tab`/`beam_emu.c` references and every edge case) is in `INSTRUCTION_SURFACE.md`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, the root set `x[0..live)`, plus the FR file; `allocate*` pushes a *continuation-pointer slot* then `stack_need` Y-slots (`y(k)` = the slot after the CP slot).
  The CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), so a continuation is exact even for a frame-less leaf that stores it in its caller's frame; `deallocate`/`call_last`/`call_ext_last` pop the frame (Y slots **and** CP slot) and the bottom `Halt` yields `x(0)`.
  A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason, never a frame-size artifact.
- **The dispatch loop** (`src/machine/drive.rs` + `src/interpreter/`) owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, re-borrows the active module per iteration, re-binds the literal area only on a `Step::Enter` into a different context, charges one reduction per instruction, and runs the raise funnel's second half over a raise that surfaced inside a cross-module callee.
  `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every opcode the engine executes has its own typed IR variant (the residual `Instr::Generic` sentinel returns a named typed error).
- **The instruction surface.** Core-loop arms (the metadata no-ops, `func_info`, `move`/`swap`/`init_yregs`, `test`/`select_val`, the call/allocate/trim/return and `gc_bif`/`bif0`/`bif` control ops, the eight native-record variants) plus the opcodes the nine families claim; a `gc_bif`/`bif` error with a live `fail` label is a guard failure and with `NO_FAIL` a raise, while `bif0`/`call_ext*` carry no fail label, so every error there is a raise.
- **Raising and the catch-frame model.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + the owning call frame + its module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` register convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), unwinding the call-frame stack down to it, and reports `Step::Goto` (same context) or `Step::Enter` (another context); with no live frame, or an unresolvable class atom, it stays a typed `Err(BeamError::Raise)` -- never a panic.
  A raise *reads* the innermost entry but never pops it; the handler opcode (`try_case`/`try_end`/`catch_end`) consumes exactly one entry.
  The class atoms come from the running module's atom table and are never substituted by a *different* atom.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms/*` (the raw-heap construction/reading point behind `alloc_words`/`alloc_words_rooted`), `src/families/bitstrings/raw.rs` (`ErlSubBits`/`ErlHeapBits` accessors + the off-heap refc payload), `src/families/records/raw.rs` (frozen-layout record accessors), `src/jit/emitter/mod.rs` (the x86-64 encoder and the crate's **only** executable-memory mapping), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*`, and -- feature-gated -- `src/jit/cranelift/mod.rs`. Every `unsafe` block carries a `// SAFETY:` rationale; registers/stack stay safe `Vec<Eterm>` indexing.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need (`Machine::alloc_refc_binary`, held as `Machine::refc_binaries`, **never cleared by `reset`**).
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

Headline: `tests/census.rs` gates **108 `beam_loader::Instr` variants = 49 EXECUTED + 59 CLAIMED-BLOCKED + 0 UNCLAIMED** (`unclaimed == 0` asserted; `TestKind` 25/25) and the whole 1366-`.beam` / 34-application corpus loads with **zero unmodelled opcodes**; the interpreter runs at single-digit ns/instruction and the engine's own per-BIF-call side is **~11-12 ns, <= 0.15%** of the host's ~10.5 us, with the baseline tier giving ~2-15x over the interpreter. The reserved-heap `MinimalContext` arena serves 100 000 x 4-word allocations from 2 heap allocations (1 in-place-grown region) instead of 100 020 (see `MEASURED.md`).
Full detail (census/corpus reachability, `engine_bench` ns/instruction rows, `bif_cost` per-call attribution, `jit_bench` speed-ups and caveats) is in the sibling `MEASURED.md`; every remaining execution gap is a typed error pinned in-suite (`tests/gaps.rs` etc.).

## Known Issues / Intentional M1 gaps
The headline M1 gaps; the full list, each with its ground-truth detail, is in `INSTRUCTION_SURFACE.md`.
- **The collecting host (`beam_rt`) adopts the rooted doors.** The engine's term-construction path allocates through `alloc_words_rooted` and the `*_rooted` builders follow the frozen reserve→read→write discipline (proved under a mock moving collector by `src/terms/alloc_tests.rs` and `tests/rooted_alloc.rs`), and `beam_rt` overrides both `alloc_words_rooted` and `ensure_heap_full` to run `beam_gc` over the whole `RootSet` at every admission point, so a scheduled `beam_rt` run collects.
A collecting host must additionally root what the `RootSet` cannot carry: `Machine.pending_exception: Option<(ExceptionClass, Eterm)>` (`src/machine/mod.rs`, set by `throw_with_trace`), the `Eterm` arguments parked in `Machine.args_scratch`/the `exec_bif` stack array (`src/interpreter/bif.rs`) while a `call_bif` is in flight. (`Machine.fr` is a root the full door already carries: `ensure_heap_full` receives it, and only the narrow default drops it.)
- **An engine-built off-heap (refc) binary reaches the host as a *handle*, never as raw memory.** `families::bitstrings::raw::{make_writable,make_binary}` build the frozen 8-word `[BinRef][ErlSubBits]` pair (a `bs_init_writable` accumulator, or any `bs_create_bin` result above `ERL_ONHEAP_BINARY_LIMIT`) and push each payload handle onto `Machine::refc_binaries` (enumerable through `Machine::refc_binaries()`; `Machine::reset` never clears it, so it is the reservoir that keeps a live machine-built binary's payload owned). The `send` arm (`src/families/receive.rs`) hands the in-flight slice to the host through the defaulted `ExecutionContext::send_message_with_off_heap`, supplying the **source off-heap table** the receiver copy needs, and the host consumes it: `beam_rt`'s runner passes `Machine::refc_binaries()` to `Runtime::stabilize_term_with`, whose copy parks the copied payload references in the host's **destination** table (`Runtime::eval_off_heap`). An engine-built refc binary therefore survives both a **return** and a **send** (`beam_rt run b.beam b:e/0` ⇒ `<<>>`).
  Residual: the host's memory accounting cannot yet *enumerate* these machine-held handles (`beam_rt/src/native/memory/mod.rs`), so their bytes are absent from its reported figures — a measurement gap, not a correctness one.
  The engine half is pinned by `tests/stdlib_sweep.rs::sweep_base64_encodes_the_empty_binary` (the real installed `base64:encode/1` on a 0-byte input), `src/families/bitstrings/matching/mod.rs::empty_binary_bs_match_commands_and_the_writable_accumulator` (the exact `bs_match {ensure_exactly,0}` / `ensure_at_least,48` / `bs_create_bin private_append` operands `base64.beam` uses) and `src/families/receive.rs::send_forwards_the_machines_off_heap_binary_handles` (the `send` arm forwards the machine's handles).
- **`Instr::Allocate` skips C's heap check.** C's `allocate Ns Live` is `$AH(Ns,0,Live)` ≡ `GC_TEST(Ns+1,0,Live)` (`../../erts/emulator/beam/emu/instrs.tab:31-33`, `emu/macros.tab:85-97,142-147`), and `GC_TEST` has no `Nh == 0` short-circuit, so C **can** collect at every `allocate`; this crate's `Instr::Allocate` only pushes the frame (`src/interpreter/dispatch.rs:472-478`). The two in-crate admission arms are therefore `AllocateHeap`/`TestHeap` (`src/interpreter/dispatch.rs:479-491`) only. The divergence is conservative — the engine collects strictly *less* often than C, so it can never dangle a published root — but it is a real GC point C has and the engine does not, and it is why an engine run's young-heap occupancy differs from the oracle's.
- **Pre-emption exists; scheduling does not (yet).** `Machine::drive` charges one reduction per interpreted instruction through the defaulted `ExecutionContext::reduce` hook (`Ok(())` by default), before the instruction's effect, so a host can pre-empt a **non-allocating** loop by returning a typed error and the pre-empted instruction stays un-applied (resume applies it exactly once); `Machine::reductions()`/`reset_reductions()` expose the slice count. The scheduler, run queues and trap handling are Stage 5 (`beam_process`); stack growth is an unbounded `Vec`.
- **A captured stacktrace is engine-derived** (the uncaught-raise funnel `Machine::with_uncaught_frames` attaches a symbolic trace derived from the machine's live frames when the raw trace is `NIL`, and `build_stacktrace` cooks the non-`NIL` arm from the raise-time `raise_snapshot`), and **nameable atoms are required**: `catch_end` needs `EXIT` and `raise_bif_error` can only raise an error it can name -- neither path ever substitutes a *different* atom.
- **Records.** The whole native-record set executes, including `PutRecord`'s create form for the running module's own records; only a *foreign*-module record id is a typed `unsupported` (Handoff #4).
- **Bitstrings.** `bs_init_writable`/`append`/`private_append` is a copy-rebuild (`HANDOFF_bs_init_writable.md`), so a long append loop is O(n²) rather than amortised O(n), and the `BIN_FLAG_*` flags plus `binary:referenced_byte_size/1`'s capacity answer are unmodelled; every remaining bitstring gap is a typed result, never a wrong value.
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order (visible only in `term_to_binary` byte comparison), a `NO_FAIL` failure of `test`/`select_val`/a map read raises class `error` with the bare atom `function_clause` from the running module's own atom table (a module that cannot name it is the honest typed `unsupported_opcode: <site>: no 'function_clause' atom in the module`), and the installed `erlc` emits the native-record opcodes -- **including the create form** `{put_record,{f,0},{atom,Rec},nil,...}` -- only for the explicit `-record #name{}` form (the legacy `-record(name,{})` form still lowers to a plain tuple), so the engine's create form is exercised **structurally** in `tests/records.rs`.
- **The stdlib module corpus is bounded by the mock test host's BIF floor** (`tests/support/bifs.rs`: the `erlang:*`/`lists:*` floor plus the typed `persistent_term:get/1,2` refusal), never by the engine's own opcode coverage -- so whole module families are recorded as host gaps, each asserting its EXACT typed error and never a fabricated value. All of `ets` is such a gap (`tests/stdlib_ets.rs`: `ets.erl` is a thin wrapper whose operation bodies are `erlang:nif_error(undef)` stubs, so every `ets:*` operation returns `BeamError::BadArg`; closing it needs an ETS seam built on `beam_ets` and served from the floor). The map-BIF-backed `maps` exports and the map-dependent `proplists` ones (`get_keys/1`, `split/2`, an arity-≥3-tuple `to_map/1,2`, `from_map/1` → `BeamError::Io` via the preloaded `erts_internal:map_next/3`), and `string:list_to_integer/1` (also preloaded `erts_internal`), are gapped the same way. Owning crates: `beam_bifs` (BIF surface / seam adoption) and `beam_rt` (preloaded-module floor) -- NOT this crate. `proplists:to_map/1,2` on an `[atom | {K,V}]` list DOES execute (the engine's `put_map_assoc` serves it) and is pinned oracle-exact.
- **Compiled arithmetic is oracle-exact on overflow** (`+ - * div rem` promote to exact bignums, and an out-of-range integer operand becomes an exact bignum).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after** (C fills `reg[i] = args[i]` then `reg[i + arity] = funp->env[i]`), never `free ++ args`.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node.
1. **Receive/message + cross-module suspension (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome`, and drive a host **timer** for a non-zero `after` (the engine exposes the parked deadline through `Machine::wait_deadline`). A `receive` **inside a cross-module callee** suspends the caller through the cross-module call seam (Handoff #10), which `beam_rt` has adopted: the callee runs in the same machine and its `Wait` reaches the driver. `resume_outcome(entry_module, func, pc, ctx)` must be called with the run's **entry** module (context `0`): `func`/`pc` are in the context the process blocked in, which the machine recovers from `Machine::context`.
2. **Globally interned exception reason atoms (owner `beam_rt`).** The engine resolves a raise's reason atom (`badmatch`/`case_clause`/`function_clause`/`EXIT`/`badarg`/`badarith`/`system_limit`/`badmap`/`badkey`/`badrecord`/`undef`/...) from the running module's atom table and never substitutes a different atom, so ERTS's globally interned `error_atom` table must exist here too: `beam_rt::boot::CORE_ATOMS` carries the same tail as the test host's `SEED_ATOMS` (also the `file`/`line` atoms the location builders use), and it is seeded before any module load. This is what makes gap #7 nameable for a host-loaded module; the residual there is the unseeded loader.
4. **`records:get_definition/2` and a *foreign* `PutRecord` create id.** `PutRecord`'s create form for the running module's own records is implemented here; `records:get_definition/2` is served by `beam_bifs`'s `RecordSource` seam, and an `Id` naming another module's record needs a code-server record table (`beam_rt`/`beam_bifs`), reported here as a typed `unsupported`.
5. **`beam_io`/`beam_rt`: `open_port({spawn_executable, <nonexistent>})`** -- the oracle raises `error:enoent` while `beam_io`'s `SpawnDriver` maps the spawn failure to `BeamError::Io`.
6. **`TestKind::TestArity` -- behaviourally equivalent to C, NOT a gap.** C's `test_arity` (`../../erts/emulator/beam/emu/ops.tab`) is an unguarded `*tuple_val(p) != Arity` header compare, and since `tuple_val(p) == boxed_val(p)` the engine's `is_boxed(x) && ARITYVAL-header == arity` (`src/predicates.rs::is_tuple_arity`) reads the same word and agrees for every boxed term (an equal-arity tuple passes; every other boxed term -- float/bignum/map/record/binary -- fails); it also equals production `BEAM_IS_TUPLE` and the fused `is_tuple_of_arity`. The only divergence is an *immediate* operand, where C's deref is UB and the engine safely returns `false` -- unreachable in well-formed code (the loader rewrites an immediate `test_arity` operand to a jump). Covered by unit tests in `src/interpreter/test.rs` + `src/predicates.rs`.
7. **Map `NO_FAIL` `{badmap,Source}` / `{badkey,Key}` — closed for a seeding host; the residual is the unseeded loader.** With a host that interns the runtime's globally interned atoms before any load -- `beam_rt::boot::CORE_ATOMS` and the test host (`tests/support/atoms.rs::SEED_ATOMS`) both seed `badmap`/`badkey`, and every module is built from a clone of that shared table -- the family raises the oracle's reason exactly (`{badmap, Source}` for a non-map source, `{badkey, Key}` for a `put_map_exact` miss). The residual is only the **unseeded** `beam_loader::load_file` path: its private table holds just what the compiler emitted -- the installed `erlc` interns `badmap` itself (its own `test,is_map` guard fail path builds `{badmap,X}`) but **not** `badkey` -- so a `put_map_exact` `NO_FAIL` raise there is the typed `unsupported_opcode: maps: no 'badkey' atom in the module` instead of a fabricated atom index. Pinned both ways by `tests/maps.rs::{exact_with_a_missing_key_raises_badkey, exact_with_a_missing_key_on_an_unseeded_module_is_the_typed_gap}` (the seeded host asserts the live `{badkey,a}` reason term, the unseeded one the exact typed gap). No engine seam resolves a tag outside the running module's table, and none should: an atom index is valid only against the table it is read with.
8. **JIT `call_ext_last` -- executes natively, by design a driver round-trip.** A **local** tail call (`call_last`/`call_only`) is linked natively (`emit/link.rs::emit_tail_exit` + `jit_tail_call`), and `call_ext_last` now **executes** on the native baseline tier through the driver-mediated module-context transfer (see Error interop) rather than a seal-time link -- a cross-module link is unsound (separate executable mappings, buffer-local `rel32` fixups, the entry module baked into `JitRuntime`). Straight-line blocks are linked and compiled modules reused across runs (`jit/cache.rs`); the residual cost is the per-transfer driver block-entry, measured by `src/jit/bench`'s `cross/2`.
9. **JIT adoption + the A.8 seam by `beam_rt` (owner `beam_rt`) -- ADOPTED.** `beam_rt/src/runner/run.rs` selects a tier at the process's first entry (`super::tier::select_entry_tier`, default `JitMode::Auto` -- the JIT only where `jit_is_switch_safe` proves the entry module free of a module-context switch), remembers it on the engine (`ProcessEngine::tier`), routes the entry through `run_label_outcome_with_tier`, and resumes a parked slice through `resume_outcome_with_tier` on that **same** tier. The engine-side seam is **complete** (`Machine::run_export_outcome_with_tier`/`run_label_outcome_with_tier` propagate `RunOutcome`, `Wait` included, and `Machine::resume_outcome_with_tier` re-enters a parked slice on the tier it was entered on). Residual non-behavioural note: a natively-executed block now records its own `(func, pc)` in its prologue (`Machine::set_current_code`), so a native run's `process_info/2` position is block-exact even across linked chains, and a traced run refuses native entry (it runs the interpreter driver), so it is byte-identical to a traced interpreter run. The `+JPperf` perf map (contract A.8) can be populated from `beam_engine::jit::cache::baseline_code_map(&module)`.
   **End-to-end evidence:** a gate run with `BEAM_RT_TIER=baseline` (which bypasses the predicate, so every module-run case executes on the native tier) reports `total=1848 agree=1845 mismatch=0 unsupported=3 allowed=3` (exit 0) -- no divergence -- and the native cross-module / nested A->B->C / parked-then-resumed-slice / dynamic-`apply` shapes are pinned end-to-end by `tests/jit_cross_module.rs` (real `erlc` fixtures, both tiers asserted equal). Honest coverage note: the forced tier reaches the module-run third of the corpus (566/1848); the `-eval` root expression (the rest) is a tree-walk evaluator with no `Machine` and does not consult a tier at all. `beam_rt`'s own `runner/tier.rs` still documents the `Step::Enter` seam as missing -- stale; the engine implements it (that text is owned by `beam_rt`).
10. **The cross-module call seam (owner `beam_rt`, the owner of `RuntimeContext`) -- ADOPTED.** The seam is LANDED and tested here (`tests/external_call.rs`, `tests/current_module.rs`) and adopted by `beam_rt` (it overrides `ExecutionContext::resolve_external_call`); the contract:
   - **Signature/return.** `fn resolve_external_call(&mut self, module: &str, function: &str, arity: u32) -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>>`. Return `Some((arc, label))` for an import the host can run in this machine, `Ok(None)` otherwise (keeps the synchronous `call_bif` path -- the `code:*` native floor, NIFs and everything else stay exactly as they are).
   - **`arc` must be the SAME `Arc<Module>`** the host loaded the module with -- `CodeServer`'s `modules: HashMap<String, Arc<Module>>` (`codeserver.rs`) -- because contexts dedup by `Arc::ptr_eq` and the engine holds the handle for as long as a suspended frame can return into the module.
   - **`label` is the export entry label**: `arc.export(function_atom, arity)` (the label *after* `func_info`), the exact label `run_export` enters.
   - **Resume contract.** `resume_outcome` must be called with the run's **ENTRY** module (`module` argument is context `0`); the suspended `(func, pc)` live in `Machine::context`, which the engine recovers itself.
   - **Regression repro (committed, `beam_rt`-owned):** `../beam_rt/tests/proc_lib_start.rs` pins the `FRONTIER` entries `proc_lib:start/4`, `proc_lib:start_link/4`, `cross`, `cross_hard`, which answer `{ok,pid}` through the adopted seam. Read that file; do not edit `beam_rt` from here.
11. **The rooted doors are adopted by `beam_rt` (owner `beam_rt`).** The engine's term-construction path is on the rooted seam (`Machine::alloc_rooted` + the `terms::*_rooted` builders, Handoff-free in-crate), and `ensure_heap` hands over the whole `RootSet` (x + stack + fr). `beam_rt` overrides both `alloc_words_rooted` and `ensure_heap_full`: it publishes the whole `RootSet` (every x slot -- the `live` hint is deliberately not a publication bound -- the whole stack and the whole FR file), runs `beam_gc` over it, writes the moved terms back, and declines a collection whose machine root reaches a container in a region the collector does not scan. Detail: `beam_rt/src/context/CONTEXT.md`.
12. **The closure-apply seam (`resolve_local_fun`, owner `beam_rt`, the owner of `RuntimeContext`) -- the remaining `beam_rt` step.** The seam is LANDED and tested here; `beam_rt` closes it by implementing `ExecutionContext::resolve_local_fun` as a **thin wrapper over its existing `RuntimeContext::local_fun_target`**, returning `Some((target.module, target.label))` (clone the module `Arc`) and `Ok(None)` for the fun kinds with no local label (an external `fun M:F/A`, the `-eval` closure). The host need not re-derive the combined `args`+free-variable ordering `local_fun_target` computes (`LocalFunTarget.args`): **the engine places the free variables itself** (into `x(arity..)`, C's `call_fun` order). Until then a scheduled process's `call_fun`/`call_fun2` still folds a blocking closure into the value-returning `apply_fun` fallback (the uncatchable typed `blocked()` on a non-pumpable machine).
