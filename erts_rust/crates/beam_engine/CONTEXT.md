# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step -- full opcode coverage, interpreter-identical semantics; a **cross-run compiled-block cache** (`src/jit/cache.rs`) and a **block linker** (`src/jit/baseline/emit/link.rs`) reuse and chain compiled blocks. The **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) makes one Cranelift function per IR function, inlining the same cheap set and otherwise looping natively on the *same* shared interpreter-backed helper. All tiers are **measurement-gated** and off the critical path (Part II sec. F): correctness-first *mechanisms*, not optimisers; `src/jit/tiering.rs` (`TierPolicy`) models that ladder as a *policy* only -- no execution path consults it.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end. The dispatch loop (`src/interpreter/`) has explicit arms for the core opcodes and routes every other instruction to a per-instruction-family seam (`src/families/`). The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC and process/stack limits all sit behind `ExecutionContext`, whose concrete implementation `beam_rt` provides -- keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: all computation goes through `ExecutionContext::call_bif`, fun application through `ExecutionContext::apply_fun`.

### The context seam (`src/context.rs`)
```rust
pub trait ExecutionContext {
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;
    fn heap_available(&self) -> usize { usize::MAX }
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
}
```
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- `ensure_heap(heap_need, live, x_regs, stack)` is the root-set contract: live roots are `x_regs[0..live)` + the whole `stack`; a real context (`beam_rt`) runs the collector and may **move terms** in place, updating `x_regs`/`stack` with no frame liveness maps.
- `heap_available()` is introspection (default unbounded); `alloc_words(n)` returns a stable pointer to `n` **uninitialized** words valid only until the next `ensure_heap`/GC (default a typed `error::unsupported`).
- `apply` is the general `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the `call_fun`/`call_fun2` hook (default a typed `error::unsupported` -- the engine keeps no closure registry); a concrete context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables.
- `pub type BifHook = Box<dyn FnMut(&str, &str, u32, &[Eterm]) -> Result<Eterm>>`; `pub type ApplyHook = Box<dyn FnMut(Eterm, &[Eterm]) -> Result<Eterm>>`.
- `MinimalContext` -- the test/embedding context: an unbounded heap (`ensure_heap` = `Ok(())`), a **pluggable BIF hook** (`new()` rejects every BIF; `with_bif_hook`/`set_bif_hook`), an **optional apply hook** and an **optional mailbox**. `alloc_words` hands out words from a pointer-stable arena whose boxes outlive every handed-out pointer; the context **owns the heap** and must outlive every boxed term built through it.

### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
```rust
pub trait Mailbox {
    fn send_message(&mut self, to: Eterm, message: Eterm) -> Result<()>;
    fn receive_next(&mut self) -> Result<Option<Eterm>>;
    fn receive_skip(&mut self) -> Result<()>;
    fn receive_remove(&mut self) -> Result<()>;
    fn receive_reset(&mut self) -> Result<()>;
    fn receive_marker_reserve(&mut self) -> Result<Eterm>;
    fn receive_marker_bind(&mut self, marker: Eterm, reference: Eterm) -> Result<()>;
    fn receive_marker_use(&mut self, reference: Eterm) -> Result<()>;
    fn receive_marker_clear(&mut self, reference: Eterm) -> Result<()>;
}
```
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")`, so `beam_rt::RuntimeContext`, a test `ModuleHost` and any other implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- `receive_next` is the *candidate* at the current scan position (`Ok(None)` = exhausted); `receive_skip` is `loop_rec_end` (advance one); `receive_remove` is `remove_message` (unlink the matched candidate, reposition at the first); `receive_reset` is `timeout` (reposition at the first). The engine never learns *which* message is current.
- **The engine never inspects a message or a marker.** Message selection is the compiled code's job (the `test`/`select_val`/`get_tuple_element` instructions between `loop_rec` and `loop_rec_end`); a marker term is **opaque** (produced by `receive_marker_reserve`, handed back verbatim by `receive_marker_bind`; only a separate *reference* reaches `receive_marker_use`/`receive_marker_clear`).
- **The `beam_rt` contract (Handoffs #1).** Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still surface the typed `error::blocked`.

### The machine (`src/machine/{mod,registers,frames,catch,run,location}.rs`)
- `pub struct Machine` -- the process-state core: the **x-register file**, the **float-register (FR) file**, the **Erlang stack**, the **call-frame stack**, the **exception catch-frame stack** and the `refc_binaries` arena.
- `pub const MAX_REGISTER: u32 = 1024;` (the x-register file size, C's `MAX_REG` bound); `pub const MAX_FLOAT_REGISTER: u32 = 1024;` (the FR file, mirroring C's `f_reg_array`). The FR file holds **`Eterm` term slots**; `reset` refills both files in 128-byte chunks.
- `Machine` binds the **running module's decoded literal area** (`literals: Option<SharedLiteralArea>`, re-bound by the run entry, cleared by `reset`), exposed as `Machine::literal(index: u32) -> Option<Eterm>`.
- `Machine::new()`/`default()`/`with_max_register(u32)`; `get_fr(n) -> Option<Eterm>`/`set_fr(n, Eterm) -> Result<()>` are bounds-checked FR access (`bad_register` on overflow).
- `run.rs`: `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware). `run_export` resolves `function/arity`'s export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return`, yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error. The loop is `pub(crate) fn run_loop`/`run_loop_with_map` (`src/interpreter/dispatch.rs`).
- Introspection (read-only): `x(n) -> Option<Eterm>`, `get_fr(n)`, `frame_depth()`, `stack_depth()`, `catch_frame_depth()`, `pending_exception()`, `pending_class()`, `resumption_addresses()` (every live call frame's suspended `(func, pc)` CP slot, innermost first -- used by `build_stacktrace`).
- **Execution-position introspection (`src/machine/location.rs`)** -- the engine half of `process_info/2`'s position items. `Machine` records `current_code: Option<(u32, u32)>` (the last *interpreted* `(func, pc)`, from `step_instruction`; exact at every suspension, since a blocking `wait` is never inlined) and `entry_call: Option<(u32, u32)>` (the run's entry `(func, arity)`); `reset` clears both plus the files, stacks, pending exception and resolved class atoms. Accessors: `current_code()`/`entry_call()`, plus the oracle-shaped `current_function`/`initial_call` (`{M,F,A}`), `current_location` (`{M,F,A,[{file,F},{line,L}]}`, via the exceptions family's `stacktrace_item`) and `current_stacktrace` (the cooked list, via `symbolic_stacktrace`). Honest by construction: no instruction interpreted => `None`/`NIL`; an out-of-range `func` => typed `unsupported`; a location the module cannot name (no `file`/`line` atom) => the typed error `build_stacktrace` already reports (Handoff #2).
- `pub struct CatchFrame { pub func: u32, pub pc: u32, pub frame_index: usize }` (+ `CatchFrame::new`) -- the handler's `(func, pc)` plus the call frame that **owns** it (the one the machine unwinds to); `push_catch_frame`/`pop_catch_frame` are the public accessors.
- `pub(crate) fn throw(&mut self, class, reason) -> Result<Step>` / `throw_error(reason)` / `throw_with_trace(class, reason, trace)` -- **the one uniform raise/unwind entry point** the families call (see the exception model below).

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func: u32, pc: u32 }, Wait { func: u32, pc: u32 }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`. `Next` = continue at `pc + 1`; `Goto` = jump within the module; `Done` = finish and yield `x(0)`.
- `Wait` is the **suspend** signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later. The loop folds it into a `RunOutcome`; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which tries the nine families in this fixed order -- `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive` -- and returns the first family's `Step`.
- Each family exposes `pub(crate) fn exec(machine, module, labels, instr, func, pc, ctx) -> Result<Option<Step>>`: `Ok(Some(step))` = "this family executed it", `Ok(None)` = "not this family's variant", `Err` = the family raised.
- When no family claims an instruction, `dispatch` returns `error::unsupported("widened opcode not yet executed: <name>")`, `<name>` being the instruction's `ops.tab` spelling, so an unclaimed opcode is diagnosable from the error alone. Every receive/message variant is claimed.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,tests}.rs`) -- the SAFETY-annotated builder/reader
`construct.rs` holds the tuple/cons/list/binary builders, `map.rs` the map builder/reader, `fun.rs` the fun builder/readers, `number.rs` the numeric helpers, `read.rs` the shared readers; constructors take the seam and allocate via `alloc_words`.
- `make_tuple(ctx, &[Eterm]) -> Result<Eterm>` (arityval header + elements; empty -> `tuple0`; > `MAX_ARITYVAL` -> `SystemLimit`); `make_cons(ctx, head, tail)` (one header-less `[CAR,CDR]` cell; the tail need not be a list); `make_list(ctx, &[Eterm])` (cons cells; empty -> `NIL`); `make_float(ctx, f64)`; `make_heap_binary(ctx, &[u8])` (heap binary/bitstring, <=64 bytes).
- `badmatch_reason(ctx, module, value) -> Result<Eterm>` (`{badmatch, Value}`, the shared raise reason; a typed `BeamError::BadMatch` when the module's atom table lacks `badmatch`).
- `make_map(ctx, &[(Eterm, Eterm)], atoms: &AtomTable) -> Result<Eterm>` -- the **general map builder**: reserves `beam_term::map::map_words_capacity(n)` words and delegates to `beam_term::map::write_map`, so it builds a map of ANY size -- a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys (keys in `erts_cmp_flatmap_keys` order), else a **hashmap** (HAMT) -- collapsing duplicate keys **last value wins**. `make_flatmap` serves flat-layout-only callers (`>32` pairs -> a typed `unsupported`); a safe `is_hashmap(t)` wrapper over `beam_term::is_hashmap` sits beside them.
- `make_fun(ctx, arity: u32, uniq: u64, index: u32, free: &[Eterm]) -> Result<Eterm>` (minimal local closure; M1 inlines the out-of-line fun-entry descriptor).
- Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`): `tuple_arity`, `tuple_element`, `cons_head`, `cons_tail`, `list_elements`, `float_value`, `map_entries` (both map layouts), `binary_bytes`, `is_fun`, `fun_arity`, `fun_num_free`, `fun_uniq`, `fun_index`, `fun_free`.

### The JIT tier seam (`src/jit/`)
- `src/jit/mod.rs`: `Tier { Interpreter, BaselineJit, Cranelift }` (`Clone, Copy, Debug, PartialEq, Eq`; `Tier::ALL` is the roster order, interpreter first), with `Tier::name() -> &'static str` (`"interpreter"`/`"baseline-jit"`/`"jit-cranelift"`), `Tier::from_name(&str) -> Option<Tier>` (unknown => `None`) and `Tier::is_available() -> bool`.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module) -> Result<Self::Compiled>`; `run_compiled(&self, &Self::Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>`; and the provided `run_export` = `compile` + `run_compiled`. `run_compiled` is `&self` because the artifact is **caller-owned**: one compiled module runs any number of times on fresh `Machine`s. The interpreter is deliberately **not** a `JitBackend` (nothing to compile).
- `available_tiers()`: exactly `["interpreter", "baseline-jit"]`, plus `"jit-cranelift"` when the `jit-cranelift` feature is on; interpreter always first.
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`): `Interpreter` -> `run_export`; `BaselineJit` -> `crate::jit::cache::run_baseline_cached`; `Cranelift` -> `crate::jit::run_cranelift` when the feature is on, else the typed `error::unsupported("jit-cranelift tier not built")` -- never a panic, never a silent fallback. These are the **non-blocking** entries (`Result<Eterm>`; a suspend folds to `error::blocked()`).
- `Machine::run_export_outcome_with_tier` / `Machine::run_label_outcome_with_tier` (`src/machine/run.rs`) -- the **outcome-aware** tier entries a host routes a process through: `Result<RunOutcome>` (`Wait` included), so a blocking `receive` under any tier is *reported*, never folded into an error. `Interpreter` -> `run_export_outcome`/`run_label_outcome`; `BaselineJit` -> `crate::jit::cache::run_baseline_cached_outcome`/`run_baseline_cached_label_outcome` over the outcome-aware driver `run_native_outcome`; `Cranelift` -> `run_cranelift_outcome` (feature-off = the typed error). A suspend crosses the block ABI as a `WAIT_BIT` word (`jit::baseline::{encode_wait,decode_wait,WAIT_BIT}`); the non-blocking entries above are unchanged (Handoff #9).
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier.
- `src/jit/tiering.rs`: `TierPolicy { baseline_threshold, hot_threshold }` models sec. F's *interpret -> baseline -> hot* escalation -- `select(executions) -> Tier` (`Default` = baseline `1`, hot `10_000`; at/above hot `Cranelift` when compiled in, else the hottest available tier). A **policy only** -- no execution path consults it.
- `src/jit/cache.rs` -- the **cross-run compiled-block cache**: `module_fingerprint(&Module) -> u64` hashes the module's **decoded IR content** (tables, instruction streams, literal words) -- deterministic, non-randomized, **never a pointer** -- and `ModuleKey { name, fingerprint }` (`name = Module::atom_name(Module::name)`) stops same-named/different-content collisions. `CodeCache` (`get_or_compile`/`run_export`/`contains`/`len`/`clear`) **owns** each `CompiledModule`, so a hit recompiles nothing, a miss compiles once; it is per-thread (`thread_local! CODE_CACHE`, raw `mmap` pointers making the artifacts `!Send`/`!Sync`) and backs `run_baseline_cached`/`run_baseline_cached_outcome` plus the `baseline_cache_*` accessors. `baseline_code_map(&Module) -> Result<Vec<CodeRegion>>` (and `CodeCache::code_map`) exposes the **real** generated code ranges to a host (e.g. `beam_rt`'s `+JPperf` perf map): `CodeRegion { start, size, name }` where `start` is an actual `CompiledModule::entry` pointer, `size` runs to the next block entry (last -> `code_address_range().1`) and `name` = `<module>:<function>/<arity>/<pc>` -- never a fabricated address.
- `src/jit/emitter/*` -- the `#[allow(unsafe_code)]` x86-64 encoder + executable `CodeBuffer` both tiers build on: label/bind/seal, the crate's only `mmap` RW -> `mprotect` RX on `seal` (never RWX, `munmap` in `Drop`), System V AMD64.
- `src/jit/baseline/` -- the **native baseline backend**: `BaselineJit` (a zero-sized `JitBackend`), `CompiledModule`, the driver, `runtime.rs` and `emit/*`.
  - Block ABI: an `extern "C" fn(*mut JitRuntime) -> i64` returning `encode_target(func, pc) = func<<32 | pc` / `HALT = -1` / `ERROR = -2` (a propagating `BeamError` in `rt.error`); `JitRuntime` (`#[repr(C)]`, `RUNTIME_XREGS_DISP = 8`) carries `machine`, `x_regs`, `module`, `labels`, `ctx`, `error`, and generated code loads **only** `x_regs`. `jit_step_one` *is* `Machine::step_instruction` folded into the block ABI -- full opcode coverage, interpreter-identical semantics; `jit_tail_call(rt, target, deallocate)` is `Machine::pop_frame_checked` folded into the same ABI.
  - **Register allocation** (`emit/regalloc.rs`): a usage-weighted per-block picker caches the five most-touched x-registers in `r12`-`r15`+`rbp`; every other one is addressed **directly in `machine.x`** (`[rbx + n*8]`, `rbx` = the `x_regs` base) -- residency is block-fixed, no rematerialization or eviction -- and the prologue/epilogue load and spill the residents at every block exit, so any helper/GC sees the interpreter's exact root set `x[0..live)` + the stack.
  - **Inlined natively** (`emit/*.rs`): the metadata no-ops; `Move`/`Swap`; `Jump` to a module label; the word-level `Test` subset (the type tests; guarded small-int `is_eq`/`is_ne`/`is_lt`/`is_ge`; `is_eq_exact`/`is_ne_exact` over small-int registers) with the fail branch; `SelectVal` (all-immediate cases); the guarded small-int `'+'/2`/`'-'/2`/`'*'/2` `gc_bif` fast paths (`'*'` range-checks the **untagged** product); the eight comparison BIFs; the aggregate readers `GetList`/`GetHd`/`GetTl`/`GetTupleElement`/`SelectTupleArity`; and the **local tail calls** `CallLast`/`CallOnly` into a compiled block. **Everything else deopts** (`Y`/`Literal` operands, out-of-range register indices, boxed-term `Test`s, non-immediate `SelectVal` cases, `PutTuple2`, `BsTestTail`, `FuncInfo`, unlinkable tail-call targets, the `call_ext_*`/`call`/`apply`/`call_fun`/exception surface), so the interpreter's exact error surfaces stand.
  - **Block linking** (`emit/link.rs`): `compile_module` reserves a `CodeLabel` per non-empty block **before** emitting and binds it at the entry, so a taken branch to a compiled successor is an ordinary `rel32` fixup resolved at `seal` -- no post-`seal` patching, W^X unchanged. A **linked exit** spills the residents (that spill is the root-set model), tears down the frame and `jmp`s to the successor entry; an **unlinkable/deopt exit** (not a block entry) spills and returns to the driver for one interpreter step. **Both local tail calls are linked**: `call_only{Dest}` is a bare dispatch (`$DISPATCH_REL`) with no frame pop, and `call_last{Dest,Deallocate}` goes through `Linker::emit_tail_exit` (spill, `call jit_tail_call`, frame teardown, `jmp` to the successor). `jit_tail_call` is literally `Machine::pop_frame_checked(deallocate)` (the interpreter's own `Instr::CallLast` call), so the frame discipline is interpreter-identical **by construction**: the frame stack is Rust-side `Machine` state a block cannot address, the target is resolved at **compile time** (labels are module-local), and the spill precedes the helper, so a stale/mismatched `Deallocate` gives the typed `rt.error` path instead of a corrupt frame. A target with no compiled block start is the typed `unsupported("jit: tail-call target has no compiled block")` and falls back to one interpreter step; `call_ext_last` (a BIF/ext call) still deopts.
  - **Driver (`run_compiled`)**: mirrors `run_label`'s setup, then loops on a flat `[func][pc]` block index (`HALT -> finish()`, `ERROR -> Err(rt.error)`, `(f,p) -> continue`), else takes one `step_instruction`; a per-run `native_ok` guard refuses native entry when `machine.x.len() <= highest_native_register` (the generated loads are unchecked). `run_native_outcome` is the same driver returning `RunOutcome` -- a `WAIT_BIT` block word (or a `Step::Wait`) becomes `RunOutcome::Wait{func,pc}` instead of `error::blocked()`.
  - `src/jit/cranelift/*` (`#[cfg(feature = "jit-cranelift")]`) -- the **optional Cranelift hot backend**: one Cranelift function per IR `Function` with the same block ABI and the entry `pc` baked in, inlining the **same cheap set as the baseline** where the two agree exactly and deopting everything else to `jit_step_one`; `report.rs` exposes a `CodegenReport`. `CompiledFunctions` owns the `JITModule` (keeping the mapping alive); `CompiledEntries` enters a function **only at its entry `pc`**.

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), and `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend.

## Execution model (frozen semantics -- reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame**: `allocate`/`allocate_heap`/... push `stack_need + 1` words -- a *continuation-pointer slot* followed by `stack_need` Y-registers, `y(k)` being the slot after the CP slot (`E[1+k]`). The CP slot is a typed `Continuation` (`Address{func,pc}` or `Halt`) on the frame, not a raw stack word.
- `call` (non-tail) stores the continuation in the *current* frame's CP slot, then jumps; `return` reads it from the *current* frame and jumps there, and a frame-less leaf (e.g. `add/2`) uses a bare `return` reading the *caller's* CP slot. `deallocate(n)`/`call_last{n}`/`call_ext_last{n}` pop the frame (its `n` Y slots **and** the CP slot); reaching the **bottom frame** (`Continuation::Halt`) halts execution and yields `x(0)`.
- **Tail-call frame discipline (`call_ext_last`/`call_last`).** The frame is popped **after** the callee succeeds, never before it runs (C's `call_light_bif` asserts `E == c_p->stop` **across** the BIF call, `emu/ops.tab:964`), so the frame is intact while the BIF runs. A **raising** callee therefore unwinds from the live frame and `handle_error`->`next_catch` reports *its own* reason, and a `Deallocate` operand the compiler left **stale** after a `trim` (e.g. `gap/1`'s stale `call_ext_last` after `trim 1`) is never rejected with a frame-size artifact. On **success** the frame is popped and the caller frame's continuation followed -- exactly C's `deallocate_return D`. `call_last` (a local jump) resolves its target label **before** popping, so a bad label cannot leave a torn-down frame behind. `CallExt`/`CallExtOnly` (no fail label => every error is a raise) and `CallOnly` follow the same discipline (`tests/tailcall.rs`).
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`, `E += n`): it **discards the lowest `n` Y slots** and renumbers the survivors down (`y(k) -> y(k-n)`), exactly what `beam_trim.erl` assumes; the `remaining` operand is JIT-only, ignored by the interpreter.
- `test_heap{heap_need, live}` calls `ctx.ensure_heap(heap_need.words(), live, x, stack)` and leaves the stack unchanged; `allocate`/`allocate_heap` recover the frame's word count through `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter/`)
- Each iteration reads `module.functions[func].code[pc]` and dispatches with a safe `match` (no computed-goto; the IR is pre-decoded, so typed dispatch is equivalent to a jump table). Core arms mutate `func`/`pc` in place; the catch-all arm calls `families::dispatch` and folds its `Step` back.
- `Machine::enter_run` builds the module-wide `Label -> (function index, code index)` `LabelMap`, so a call/fail target may live in another function; a missing label is `error::unknown_label`.
- The residual `Instr::Generic` opcodes (the loader's unmodelled set) go to `src/generic.rs`: a **pure sentinel** -- every one returns `error::unsupported(op.name())`, never a panic and never a wrong result. Every opcode the interpreter executes has its own typed IR variant (e.g. `is_any_native_record` is `Instr::IsAnyNativeRecord`, executed by the records family).

### Instruction subset -- **executed by the core loop**
`Label`, `Line`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart`, `OnLoad` -- metadata/no-ops that do not change control flow (`nif_start`/`on_load` are the compiler's markers at the head of a NIF stub / an `-on_load` function; `ops.tab` lists them with no body, so `Step::Next` is exact).
`FuncInfo` (`func_info`) -- the failed-clause raise, **not** a no-op: a function's callable entry label is the label *after* `func_info` (`Export.label == Function::entry_label`), so the only way in is a JUMP from a failed head-pattern/guard `fail` label. It raises class `error` with the **bare atom** `function_clause` from the running module's atom table (the call args ride in the stacktrace, not the reason) -- a module lacking the atom is a typed `unsupported`, never a substituted wrong atom, matching C's `i_func_info_IaaI`. The baseline JIT **deopts** it.
`Move`, `Swap`, `InitYregs` (`init_yregs` writes `NIL` into the listed Y registers).
`Test` (**all** `TestKind`s, below), `SelectVal` (exact `=:=` match against each `(value, label)`, else `fail`, else a raise when `fail == NO_FAIL`).
`Jump`, `Call`, `CallLast`, `CallOnly`, `CallExt`, `CallExtOnly`, `CallExtLast`, `Allocate`, `AllocateHeap`, `TestHeap`, `Deallocate`, `Trim`, `Return` -- the `*Last` arms' frame discipline is in sec. Registers, stack & frames, and `CallExt`/`CallExtOnly`/`CallOnly`/`Deallocate`/`Trim` match C.
`GcBif`, `Bif0`, `Bif`. The native-record family -- `Instr::IsAnyNativeRecord`, `IsNativeRecord`, `GetRecordElements`, `GetRecordElementsId`, `PutRecord`, `IsRecordAccessible`, `GetRecordField`, `UpdateRecordId` (see the records family). `Instr::Generic` executes **nothing** (see the dispatch loop).
- **`GcBif`/`Bif` failure semantics**: evaluate the arg operands, call `ctx.call_bif`. On `Ok`, store into `dst`. On `Err` with a live `fail` label, **jump to `fail`** (guard failure); on `Err` with `fail == NO_FAIL`, **raise** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`). **`Bif0`/`CallExt*` carry no fail label, so every error is a raise.**
- **`raise_bif_error`**: a `BeamError::Raise` **carrying a live reason term** (`Raise::live_reason`, payload `Eterm`) is raised through `Machine::throw_with_trace(class, term, NIL)`: with a live catch frame it lands in the handler (`x(1)` = the term), with none it propagates the term-carrying `Raise`. Every other case: with no live catch frame the error propagates as-is; with one, the error's BEAM atom name (`BeamError::as_atom()`) is resolved in the running module's atom table and raised with class `error`. An error the engine cannot name as a term (no atom, a `Raise` without a live slot, `TermNotFound`, `Io`) propagates unchanged, never substituted by a *different* atom.
- **`Test` failure semantics**: succeeds => fall through; fails => jump to `fail`, or raise `error::unsupported("test/no_fail")` when `fail == NO_FAIL`.
- **`Test` comparison kinds**: `IsLt`/`IsGe`/`IsEq`/`IsNe` compare `args[0]` vs `args[1]` with arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` use exact equality (`cmp`).
- **`Test` type kinds**: every `TestKind` the loader defines -- the type tests (a pid/ref/port counts internal or external), `IsList` (`[]` or a cons cell), `IsBoolean` (the atom `true`/`false`), `IsFunction`/`IsFunction2` (`args[0]` is a fun of `args[1]` arity), `IsTaggedTuple` (`args[0]` is a tuple of `args[1]` arity whose first element is `args[2]`) and `TestArity` (a tuple of `args[1]` arity -- Handoff #6).

### Operand subset
- **Supported**: `X(n)`/`Y(n)` (bounds-checked; out of range -> `error::bad_register`), `Typed{reg, ty}` (the type annotation is ignored), `FloatReg(n)` (the FR file), `Integer(i)`/`Character(c)` (a small int in range, an exact bignum otherwise -- `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil`.
- **`Literal`** (an index into the running module's decoded literal area) **is** read via `crate::operand::read_operand` (`Machine::literal`), while `Label`/`List`/`Allocation` are a typed `error::unsupported` there; `write_operand` rejects every non-register destination, `Literal` included (it has no addressable slot).

### Instruction families -- **executed** (each module's docs own its opcodes and every edge case)
- `families/tuples.rs`: `PutTuple2`, `GetTupleElement`, `SelectTupleArity` (a non-tuple source or a shape/arity mismatch takes the `fail` branch, exactly as C's `get_arity` falls through to `$FAIL`; `{badmatch, Value}` goes to the no-fail path only).
- `families/records/{mod,raw}.rs` + `records/tests/*`: the whole record family, `erl_record.c` branch for branch. `UpdateRecord` copies the `size`-arity source tuple and overwrites each **1-based** `(offset, value)` pair (copy-then-patch; the `copy`/`reuse`/`inplace` hint ignored). `IsAnyNativeRecord` succeeds iff `Src` is a native record (`predicates::is_record`, a header-subtag test), else branches to `Fail` (`NO_FAIL` -> `unsupported`). The seven typed native-record variants: `IsNativeRecord` (definition module+name `=:=` the atom operands); `GetRecordElements`/`GetRecordElementsId` (the `Id` discarded); `PutRecord`'s *update* form and `UpdateRecordId` (`Hint`/`Id` discarded) rebuild the instance with the listed fields replaced; `PutRecord`'s *create* form builds a fresh instance from the module's own `Recs` definition with the C `erl_create_local_native_record` error order (`badfield` outranks a delayed `novalue`; a foreign-module id is `unsupported`); `IsRecordAccessible` is strict when `scope = external` (must be exported), else the `$MODULE` wildcard; `GetRecordField` needs no export for an atom `Id` (`_` skips the name test), and does for `{Module,Name}`.
- `families/lists.rs`: `PutList`, `GetList`, `GetHd`, `GetTl` (a non-cons source raises `{badmatch, Value}`).
- `families/funs.rs`: `MakeFun3` (the closure's arity is the descriptor arity minus `num_free`), `CallFun` (fun in `x(arity)`, args `x(0..arity)`), `CallFun2`, `Apply` (M in `x(arity)`, F in `x(arity+1)`), `ApplyLast` (pops the frame first, then follows the continuation). A non-atom `apply` target is a `badarg` raise via `Machine::throw_error`.
- `families/exceptions/{mod,raise,stacktrace,tests}.rs`: `Badmatch` (`{badmatch,V}`), `CaseEnd` (`{case_clause,V}`), `TryCaseEnd` (`{try_clause,V}`), `IfEnd` (`if_clause`), `Badrecord` (`{badrecord,V}`), `Raise` (re-raise with the class currently being handled), `Try`/`Catch` (push a catch frame), `TryCase`/`TryEnd`/`CatchEnd` (the handler opcodes, each consuming exactly one catch frame), `BuildStacktrace`, `RawRaise` (both documented in Known Issues).
- `families/floats/{mod,arith,convert,tests}.rs`: `Fmove`, `Fconv`, `Fadd`/`Fsub`/`Fmul`/`Fdiv`, `Fnegate`. A non-float operand or a non-finite result is the instruction's arithmetic failure -- a guard branch to `fail` when one is live, else a `badarith` raise. `Fconv` (no fail label) converts a **bignum** faithfully (nearest double, ties to even) via the safe `beam_term::number::big_to_f64`; an over-range (>1024-bit) bignum raises `badarith`.
- `families/maps/{mod,read,write,tests}.rs`: `GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact`. Sources are read in **both** layouts (`terms::map_entries` walks a flat map and a hashmap/HAMT); key matching delegates to `beam_term::cmp`, so `1` and `1.0` are distinct keys; a non-map source is a `fail` jump on the compiled forms, else `{badmap, Source}`. **Construction** goes through `terms::make_map`, so a map past `MAP_SMALL_MAP_LIMIT` (32) keys becomes a **hashmap** (no cap).
- `families/bitstrings/{mod,raw}.rs` + `bitstrings/{matching,create}/*`: the whole `bs_*` set -- the match opcodes (`BsStartMatch3`/`4`, `BsMatch`, `BsMatchString`, `BsTestTail2`, `BsGetTail`, `BsGetPosition`/`BsSetPosition`), the readers (`BsGetInteger2` any width: <=64 bits in a machine word, >64 as a bignum, big/little-endian, signed; `BsGetFloat2` 0/16/32/64 bits; `BsGetBinary2`; `BsSkipBits2`; the UTF reads/skips) and the builders (`BsCreateBin` over `integer`/`binary`/`float`/`utf8`/`utf16`/`utf32`/`string`, the `string` one a literal byte slice of `StrT`; `BsInitWritable` and a **first** `append`/`private_append`, seed-and-rebuild). A result of any size is an on-heap `ErlHeapBits` <=64 bytes, else an off-heap refc binary; the match-context is an on-heap `ErlSubBits`-shaped boxed term re-derived at every opcode, so matching survives calls and branches.
- `families/receive.rs`: `Send` (deliver `x(1)` to `x(0)`, store **the message itself** in `x(0)`; no fail label, so a failure raises through the catch-aware `raise_bif_error`), `LoopRec` (`loop_rec Fail Dst` -- candidate -> `Dst`, else jump to `Fail`), `LoopRecEnd`, `Wait` (`Step::Wait`), `WaitTimeout` (a small-int `0` falls through to the following `timeout`, anything else suspends like `wait`), `Timeout` (`receive_reset`), `RemoveMessage` (`receive_remove`) and the four `RecvMarker*` opcodes. Registered **last**; it does no term inspection -- every mailbox position/removal is delegated to the `Mailbox` seam.

### Raising opcodes and the catch-frame model (`families/exceptions/`, `src/machine/catch.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, which owns the handler) and blank their frame slot.
- A raise (a family's `throw`/`throw_error`, or `raise_bif_error`) records `pending_exception = (class, reason)`, then consults the **innermost** live catch frame; with none it propagates as `Err(BeamError::Raise(..))` carrying that reason term in the raise's `live_reason` slot.
- To land, the machine unwinds the call-frame stack back to `CatchFrame::frame_index` (dropping the Y slots of every deeper frame) and writes the handler registers exactly as C's `handle_error` does: `x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace` (`NIL` at M1), `x(3) = class atom`; a landed raise returns `Ok(Step::Goto { func, pc })`, and with no live catch frame (or an unresolved class atom) the typed `Err(BeamError::Raise(..))` -- never a panic.
- **The raise never pops the catch frame**: it *reads* the innermost entry, unwinds the call frames but leaves the entry in place; the handler opcode that runs next (`try_case`/`try_end`/`catch_end`) consumes exactly one entry (normal or exceptional, never both). `try_case` blanks its frame slot, requires the `THE_NON_VALUE` marker in `x(0)`, and moves the class atom from `x(3)` into `x(0)`; `try_end` blanks its frame slot; `catch_end` leaves a normal result untouched but folds a landed exception into the caught term -- the thrown value for class `throw`, `{'EXIT',Reason}` otherwise.
- The class atoms (`error`/`exit`/`throw`) are installed from the running module's atom table before a raise (`Machine::set_class_atom`); an atom absent from the module is never substituted by a *different* atom (an uncaught raise still propagates as a typed error, a caught raise fails with a typed `unsupported`). `pending_class` is the class a `raise` opcode re-raises with (C's `i_raise` keeping `freason`).

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms.rs` (the raw-heap construction/reading point behind `alloc_words`), `src/families/bitstrings/raw.rs` (`ErlSubBits`/`ErlHeapBits` accessors + the off-heap refc payload), `src/families/records/raw.rs` (frozen-layout record accessors), `src/jit/emitter/mod.rs` (the x86-64 encoder and the crate's **only executable-memory mapping**), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*` (reconstructs `&mut Machine`/`&mut dyn ExecutionContext`/`&Module`/`&LabelMap` from `JitRuntime`'s live, unaliased pointers and calls a block entry as a transmuted `extern "C" fn`), and -- feature-gated -- `src/jit/cranelift/mod.rs`. Every `unsafe` block carries a `// SAFETY:` rationale; registers/stack stay safe `Vec<Eterm>` indexing.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need (`Machine::alloc_refc_binary`, held as `Machine::refc_binaries`, **never cleared by `reset`**).
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

## Design Decisions
- **Root-set contract made concrete; term construction behind one seam.** `call_bif`/`apply_fun` isolate BIF dispatch and fun application, and `ensure_heap(heap_need, live, &mut x, &mut stack)` hands the exact GC root set (`x[0..live)` + the stack) to the context, so a Stage-4 collector can move terms in place without frame liveness maps. `terms` owns the boxed-term contract and is the only place that dereferences raw heap storage (the bitstring `raw` module is the documented layout exception).
- **A typed frame CP slot rather than a raw stack word**, with a catch-frame stack mirroring C's `next_catch` + `c_p->catches` split, so the landing convention (`x(0..=3)`) and the bookkeeping live in one place.
- **JIT tiers off the critical path; compile failure a typed error.** Cranelift is optional (default OFF), so with it off neither the crate nor the build carries Cranelift at all; compilation is measurement-gated (sec. F) with a bounded-latency, cheap-deopt design, and `TierPolicy` is deliberately **not** wired into execution. A `CodeBuffer::seal` failure propagates out of `compile`/`run_export`, and an unresolved `Jump` target deopts to the helper so the interpreter's `unknown_label` surfaces.
- **One driver for both native tiers, delegating per instruction rather than duplicating semantics.** A tier supplies its compiled-code lookup through the `NativeCode` trait (`enter(rt, func, pc) -> Option<i64>`); because `jit_step_one` *is* `Machine::step_instruction`, every tier is interpreter-identical for every supported opcode without a second implementation.
- **Unsupported => `Raise` with reason atom `unsupported_opcode`** (a dedicated `BeamError` variant must not be added from here); the slice `.beam` fixture lives with `beam_loader` and is read by relative path.
- **The FR file stores `Eterm` term slots at M1** (C's is raw doubles), because the engine's operand seam is `Eterm`-typed and that lets `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is deferred.
- **M1 fun layout inlines the descriptor** (`uniq`, `index` after the header; no code pointers at M1) -- the same substitution as the external-pid `node` slot (`MAKE_FUN_HEADER` + `ErlFunThing`). `MinimalContext` fun application goes through an apply hook (no closure registry here), `build_stacktrace` derives from the machine's live frames rather than a raise-time snapshot, and `update_record` always copies (the hint only authorises updating a unique/dead source).
- **Flat, integer-keyed hot-path state (safe Rust).** Jumps resolve through `LabelMap` -- a dense `Vec<Option<(func,pc)>>` (`Slots::{Dense,Sparse}` keeps a sparse fallback for a non-dense label space) built once per run by `Machine::enter_run`, so a jump is one array index; the loader's label ids are dense (`lists.beam`: 1256 labels, max id 1256). Each import's `ExecutionContext::call_bif` target is resolved **once per run** into an `ImportTable` of `ImportTarget { module, function, arity }` cached in `LabelMap` keyed by the owning `Module` address (a different module falls back to the unchanged free `import_target`). `GcBif`/`Bif`/`Bif0`/`CallExt` marshal arguments through a fixed-lane `STACK_ARGS = 2` **stack** array. With 2 lanes the dominant arities (`bif0`/1/2 -- every comparison/arithmetic BIF) build an exact-size slice LLVM can SROA; arities >= 3 go through a per-`Machine` `args_scratch` buffer that is reused across calls (cleared, capacity retained), so a BIF call allocates **nothing** -- proved by `tests/bif_alloc.rs` (a counting global allocator asserts a 512- vs 1024-`gc_bif` chain and arity 8 vs 9 allocate identically). `read_operand` is inlined and ordered hot-first (`X`, `Integer`, `Nil`, `Y`, ...). `Machine::reset` refills the register/FR files in 128-byte chunks. None of this changes semantics: the reference point stays `Machine::step_instruction`.

## Known Issues / Intentional M1 gaps
- **No garbage collection.** `MinimalContext` has an unbounded, never-freed arena; `test_heap`/`allocate_heap` call `ensure_heap` (a no-op there). The real collector + heap sizing is Stage 4 (`beam_gc`); the engine allocates boxed terms only through `terms`/`alloc_words`.
- **`build_stacktrace`/`raw_raise` execute, but a captured trace is engine-derived.** `raw_raise` is oracle-exact for all three classes (`error`/`exit`/`throw`) and the unknown-class fall-through (`x(0) = badarg`, no raise); `build_stacktrace` is oracle-exact for a `NIL` raw trace (the only compiler-emitted path) and otherwise substitutes a symbolic trace from the machine's **live** frames (Handoffs #3).
- **`catch_end` needs the `EXIT` atom**: a module whose atom table lacks it returns a typed `unsupported` rather than substituting a wrong atom.
- **`raise_bif_error` can only raise a nameable error.** A BIF failure whose atom is absent from the running module's atom table (or a `BeamError` with no BEAM atom *and no live reason term*: `TermNotFound`, `Io`, an empty/non-`Eterm` `live_reason`) propagates unchanged -- the `Module` reaches the interpreter read-only.
- **Compiled arithmetic is oracle-exact on overflow.** `+ - * div rem` overflow promotes to exact bignums (compiled `gc_bif` goes through `ctx.call_bif` into `beam_bifs`, which never overflows to `system_limit`); an out-of-range `Integer`/`Character` **operand** (`erlc`'s encoding of a small literal >= 2^59) becomes an exact bignum via `terms::make_integer`, which the JIT's `constant_word` deopts.
- **A blocking `receive` needs a host mailbox** (Handoffs #1): with no mailbox each `Mailbox` call is a typed `unsupported("<method>")`, and a mailbox with no candidate **suspends** (`RunOutcome::Wait`, folded into `error::blocked` by plain `run_export`); with no host timer, `wait_timeout` suspends until a message arrives (only a small-int `0` falls through to `timeout`).
- **The native-record set executes, including `PutRecord`'s *create* form for the running module's own records** (`Src` the literal `nil`): the definition comes from `beam_loader::Module::{records,record,record_by_name}` and the instance carries the real `beam_term::hashing::compute_record_definition_hash`. Only an `Id` naming a *foreign* module's record is a typed `unsupported`; a record-semantics failure branches to the instruction's `fail` label (`NO_FAIL` -> a typed `unsupported("<instr>/no_fail")`). Native records are **not enabled in this toolchain** (absent from `erl_features`), so the create form is verified **structurally** (`tests/records.rs`), not differentially.
- **Bitstring gaps (each a typed result -- never a wrong value).** `raw::heap_bits` refuses a refc subject whose window is not byte-aligned. `bs_init_writable`/`append`/`private_append` are a copy-rebuild (`HANDOFF_bs_init_writable.md`): no amortised in-place growth, the `BIN_FLAG_*` flags and `binary:referenced_byte_size/1`'s capacity answer are unmodelled, and a non-first `append`/`private_append` segment is a typed `unsupported`. `system_limit` is modelled (`size*unit` overflow / the post-multiply sign bit / a positive-bignum size; a negative bignum is `badarg`); a `float` segment of width 0 or invalid raises `badarg` (`tests/bitstrings_create_fail.rs`).
- **Literal operands.** `beam_loader`/`beam_codec` decode the whole `LitT` area (incl. `EXPORT_EXT`/`NEW_FUN_EXT` fun literals, `>32`-key map literals, big integers) and wide (`>8`-byte) integer operands, so every installed module loads; a `Literal` index outside the running module's `LitT` table (or a read with no module bound) is the typed `operand: literal` error.
- **`y(k)` addressing and `trim` are equivalent to C's `E[1+k]`/`E += N` -- no off-by-one.** The engine keeps the continuation-pointer slot **out** of the stack (`Frame { continuation, y_base, y_count }`, so `y(k) = stack[y_base + k]`), whereas C keeps it at `E[0]` (`y(k) = E[1+k]`, `emu/macros.tab:142-147`) and `i_trim` does `E += N` (`emu/instrs.tab:593`); both discard the lowest `N` Y slots. The operands agree because the loader encodes `deallocate N` as `(N+1)` words (the `+1` being that CP slot) and `deallocate` consumes the frame's **remaining** Y count -- post-`trim`, what the compiler emits (`gap/1`: `trim 1` -> `deallocate 0`). `pop_frame_checked` is deliberately **stricter** than C (which advances `E` unconditionally): a mismatch is a typed `unsupported`, never silent corruption (`tests/tailcall.rs`).
- **Map enumeration order is storage order, not canonicalized** (`erts_cmp_flatmap_keys`), affecting only `term_to_binary` byte comparison; a malformed hashmap node / `THE_NON_VALUE` / immediate item during a read is a typed `BadArg`.
- **A missing map key with `fail == NO_FAIL` has no ground truth** (the compiler always emits a fail label for the matching forms), so it is a documented typed `unsupported` rather than an invented reason.
- **No reductions / preemption / scheduler.** `run_*` executes to the function's `return`; scheduling, reductions, trap handling and `ensure_heap` limits belong to Stage 5 (`beam_process`), and stack growth is an unbounded `Vec`.
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after.** C fills `reg[i] = args[i]` for `i < arity` then `reg[i + arity] = funp->env[i]`, so a context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = captures -- *not* `free ++ args`; the engine calls `apply_fun(fun, args)` and the context lays out the registers.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node.
1. **Receive/message (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome` and drive a host **timer** for a non-zero `after`; the differential A.9 cases additionally need a live `code_server` process.
2. **Globally interned exception reason atoms (owner `beam_rt`).** The engine resolves a raise's reason atom (`badmatch`/`case_clause`/`function_clause`/`EXIT`/`badarg`/`badarith`/`system_limit`/`badmap`/`badkey`/`badrecord`/`undef`/...) from the running module's atom table and never substitutes a different atom, so ERTS's globally interned `error_atom` table must exist here too: `beam_rt::boot::CORE_ATOMS` must gain the same tail (as the test host's `SEED_ATOMS` does). Root cause of the map `NO_FAIL` divergence below; **the same applies to the `file`/`line` atoms** the location builders use (ERTS names them from `am_file`/`am_line`).
3. **A raw `StackTrace` captured at raise time (owner `beam_engine`).** Closing the non-`NIL`-trace gap means snapshotting a raw `StackTrace` in `Machine::throw_with_trace`, threading it through every raise site (incl. `interpreter/`'s `FuncInfo` arm) and consuming it in `families/exceptions/`; synthesising a partial trace would be a silent wrong value.
4. **`records:get_definition/2` and a *foreign* `PutRecord` create id.** `PutRecord`'s create form for the running module's own records is implemented here (see Known Issues); `records:get_definition/2` is served by `beam_bifs`'s `RecordSource` seam, and an `Id` naming another module's record needs a code-server record table (`beam_rt`/`beam_bifs`), which this crate reports as a typed `unsupported`.
5. **`beam_io`/`beam_rt`: `open_port({spawn_executable, <nonexistent>})`** -- the oracle raises `error:enoent`, while `beam_io`'s `SpawnDriver` maps the spawn failure to `BeamError::Io`.
6. **`beam_engine` (minor): `TestKind::TestArity`** uses `is_tuple_arity` (an `ARITYVAL` header test) whereas C's `BEAM_IS_TUPLE` is only `is_boxed(Src)`; no known compiler emits `test_arity` on a non-tuple and `IsTaggedTuple` is behaviourally correct.
7. **Map `NO_FAIL`** (`put_map_assoc`/`put_map_exact` with a non-map source and `NO_FAIL`): the engine yields `unsupported_opcode: maps: no 'badmap' atom in the module` where C raises `{badmap, Source}` -- nameable only once #2 lands.
8. **JIT (not a correctness gap): ext tail-call linking.** A **local** tail call (`call_last`/`call_only`) into a compiled block is linked natively (`emit/link.rs::emit_tail_exit` + `jit_tail_call`), but `call_ext_last` still round-trips through the driver (it enters code outside the module's blocks); straight-line blocks are linked and compiled modules are reused across runs (`jit/cache.rs`), so the remaining block-entry cost is the `call_ext_*` tail surface.
9. **JIT adoption by `beam_rt` (owner `beam_rt`) -- this crate's half is landed.** The tiers are still not on `beam_rt`'s execution path: `beam_rt/src/runner.rs` calls the interpreter entries `run_export_outcome`/`resume_outcome` directly. The engine-side blocker is **closed**: `Machine::run_export_outcome_with_tier`/`run_label_outcome_with_tier` propagate `RunOutcome` (`Wait` included) out of a baseline-tier run (`run_baseline_cached_outcome` over `run_native_outcome`), so `beam_rt` now routes a process through a tier by calling the `*_with_tier` entries. Residual non-behavioural gap: a natively-executed block does not update `Machine::current_code`, so a tier-run process reports a coarser `process_info/2` execution position (no observable divergence today, because the executor runner does not read it). The `+JPperf` perf map (contract A.8) can be populated from `beam_engine::jit::cache::baseline_code_map(&module)`.
