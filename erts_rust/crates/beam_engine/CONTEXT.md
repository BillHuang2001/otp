# `beam_engine` — Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** that runs a widened instruction set end to end (this crate's Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`). The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and drives an export through a loop that deopts to one interpreter step for each instruction it does not lower natively, so it has full opcode coverage with interpreter-identical semantics. The **optional Cranelift hot tier** (`src/jit/cranelift.rs`, behind the default-off **`jit-cranelift`** feature) makes one Cranelift function per IR function, looping natively on the *same* shared interpreter-backed helper. All tiers are **measurement-gated** and off the critical path (Part II §F): the native backends are correctness-first *mechanisms*, not optimisers. `src/jit/tiering.rs` (`TierPolicy`: interpret → baseline → hot thresholds with an availability downgrade) models §F's ladder as a *policy* only — nothing on an execution path consults it.

Implements the Stage-1 engine half of Part II §H with the IR contract of §E and the interpreter/JIT trade-offs of §F (`../../CONTEXT.md` §4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end. The dispatch loop (`src/interpreter.rs`) has explicit arms for the core opcodes and routes every other instruction to a per-instruction-family seam (`src/families/`). **The engine depends only on `beam_loader` (+ `beam_term`/`beam_common`)** — never on the Stage-5 runtime core: everything the runtime supplies (BIF dispatch, fun application, heap/GC, process/stack limits) is abstracted behind `ExecutionContext`, whose concrete implementation `beam_rt` provides, keeping the Stage-1/Stage-5 DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies `../../erts/emulator/beam/emu/{instrs,macros,bif_instrs,select_instrs,arith_instrs,map_instrs,float_instrs,bs_instrs}.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

## API Surface (FROZEN — the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
**This crate does NOT embed a BIF table**: all computation goes through `ExecutionContext::call_bif`, fun application through `ExecutionContext::apply_fun`.

### The context seam (`src/context.rs`)
```rust
pub trait ExecutionContext {
    /// Dispatch `module:function/arity`; failure is return-based `Err(BeamError)`.
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;

    /// Ensure `heap_need` words; the live root set is `x_regs[0..live)` + the whole `stack`.
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;

    /// Heap words currently available (introspection). Default: unbounded.
    fn heap_available(&self) -> usize { usize::MAX }

    /// Allocate `n` uninitialized words; valid only until the next `ensure_heap`/GC.
    /// Default: a typed `error::unsupported`.
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;

    /// The general `apply`/`call_ext` hook. Default: forwards to `call_bif`.
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;

    /// Apply a fun/closure value (the `call_fun`/`call_fun2` path). Default: `error::unsupported`.
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
}
```
- `call_bif` failure is an `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/…); the engine turns it into a guard branch or a raise, never a panic.
- `ensure_heap(heap_need, live, x_regs, stack)` makes the root-set contract concrete: the live roots are `x_regs[0..live)` plus the whole `stack`; a real context (`beam_rt`, Stage 4/5) runs the collector here and may **move terms** in place, updating `x_regs`/`stack` with no frame liveness maps.
- `alloc_words(n)` returns a stable pointer to `n` **uninitialized** words, valid only until the next `ensure_heap`/GC (mirrors `HAlloc`/`heap_top`); the default body is a typed `error::unsupported`.
- `apply` is the general external-function hook (default forwards to `call_bif`); `apply_fun` is the fun-application hook (default typed `error::unsupported` — the engine keeps no closure registry). A concrete context must enter the closure with `x(0..arity)` = the call arguments and `x(arity..)` = the closure's free variables (see Known Issues).
- `pub type BifHook = Box<dyn FnMut(&str, &str, u32, &[Eterm]) -> Result<Eterm>>`; `pub type ApplyHook = Box<dyn FnMut(Eterm, &[Eterm]) -> Result<Eterm>>`.
- `MinimalContext` — the test/embedding context: an unbounded heap (`ensure_heap` = `Ok(())`), a **pluggable BIF hook** (`new()` installs "reject every BIF with `error::unsupported`"; `with_bif_hook`/`set_bif_hook` replace it), an **optional apply hook** (`with_apply_hook`/`set_apply_hook`) and an **optional mailbox**. Its `alloc_words` hands out words from a pointer-stable arena (`Vec<Box<[Eterm]>>`) whose boxes outlive every handed-out pointer. The context **owns the heap** and must outlive every boxed term the engine builds through it.

### The mailbox seam (`src/context.rs`) — the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the engine's crate deps stay `beam_common`/`beam_term`/`beam_loader`/`beam_alloc`/`libc`, the host supplies the mailbox through this gate, and the engine keeps **no** mailbox state of its own.
```rust
pub trait Mailbox {
    fn send_message(&mut self, to: Eterm, message: Eterm) -> Result<()>;
    fn receive_next(&mut self) -> Result<Option<Eterm>>;
    fn receive_skip(&mut self) -> Result<()>;
    fn receive_remove(&mut self) -> Result<()>;
    fn receive_reset(&mut self) -> Result<()>;
    fn receive_marker_reserve(&mut self) -> Result<Eterm>;
    fn receive_marker_bind(&mut self, marker: Eterm, reference: Eterm) -> Result<()>;
    fn receive_marker_use(&mut self, reference: Eterm) -> Result<()>;
    fn receive_marker_clear(&mut self, reference: Eterm) -> Result<()>;
}
```
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")` out of the box — so `beam_rt::RuntimeContext`, a test `ModuleHost` and any other implementor compile unchanged and opt in only to what they can serve. `MinimalContext::with_mailbox(Box<dyn Mailbox>)` / `set_mailbox(...)` install one (all nine forwarded through one private `mailbox_call` helper).
- `receive_next` is the *candidate* at the current scan position (`Ok(None)` = scan/mailbox exhausted); `receive_skip` is `loop_rec_end` (advance one), `receive_remove` is `remove_message` (unlink the matched candidate, reposition at the first), `receive_reset` is `timeout` (reposition at the first). The engine never learns *which* message is current.
- **The engine never inspects a message and never inspects a marker.** Message selection is the compiled code's job (the `test`/`select_val`/`get_tuple_element` instructions between `loop_rec` and `loop_rec_end`). A marker term is **opaque**: produced by `receive_marker_reserve`, stored in a register and handed back verbatim by `receive_marker_bind`; only a separate *reference* term reaches `receive_marker_use`/`receive_marker_clear`.
- **The `beam_rt` contract.** A host implements the nine methods over `beam_message::Queue` plus a marker/scan-position table, maps `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, and re-enters the suspended process with `Machine::resume_outcome` once a message arrives. Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still cannot suspend and still surface the typed `error::blocked`.

### The machine (`src/machine.rs`)
- `pub struct Machine` — the process-state core: the **x-register file**, the **float-register (FR) file**, the **Erlang stack**, the **call-frame stack** and the **exception catch-frame stack**.
- `pub const MAX_REGISTER: u32 = 1024;` (the x-register file size, `beam_emu.c` `MAX_REG` bound); `pub const MAX_FLOAT_REGISTER: u32 = 1024;` (the FR file, mirroring C's `f_reg_array`, `erl_vm.h:49`). The FR file (`fr: Vec<Eterm>`, refilled by `reset`) holds **`Eterm` term slots** at M1.
- `Machine` binds the **running module's decoded literal area** (`literals: Option<SharedLiteralArea>`, re-bound by `run_loop`, cleared by `reset`), exposed as `Machine::literal(index: u32) -> Option<Eterm>`. It cannot go stale mid-run: labels are module-local and a cross-module call leaves the loop through `CallExt` into the host context, so the executing module is fixed for a run.
- `Machine::new()` / `Machine::default()` / `Machine::with_max_register(u32)`; `get_fr(n) -> Option<Eterm>` / `set_fr(n, Eterm) -> Result<()>` are bounds-checked FR access (`bad_register` on overflow).
- `pub fn run_export(&mut self, module: &Module, function: Atom, arity: u32, args: &[Eterm], ctx: &mut dyn ExecutionContext) -> Result<Eterm>` — the primary entry: resolve `function/arity`'s export entry label, seed `x[0..arity]` from `args`, push the bottom frame, run to `return`, yield `x(0)`. `pub fn run_label(&mut self, module: &Module, label: Label, arity: u32, args: &[Eterm], ctx) -> Result<Eterm>` runs a raw entry label (used by `run_export`); a missing export/label is a typed error. The loop itself is `pub(crate) fn run_loop` / `run_loop_with_map` (`src/interpreter.rs`).
- Introspection (read-only): `x(n) -> Option<Eterm>`, `get_fr(n) -> Option<Eterm>`, `frame_depth() -> usize`, `stack_depth() -> usize`, `catch_frame_depth() -> usize`, `pending_exception() -> Option<(ExceptionClass, Eterm)>`, `pending_class() -> Option<ExceptionClass>`, `resumption_addresses() -> Vec<(u32, u32)>` (every live call frame's suspended `(func, pc)` CP slot, innermost first — used by `build_stacktrace`).
- `pub fn reset(&mut self)` restores the initial state: NIL-filled register and FR files, empty stack and frame stacks, no pending exception, no resolved class atoms.
- `pub struct CatchFrame { pub func: u32, pub pc: u32, pub frame_index: usize }` (+ `CatchFrame::new`) — one `try`/`catch` handler target: the handler's `(func, pc)` and the call frame that **owns** it (the frame the machine unwinds back to); `pub fn push_catch_frame(&mut self, frame: CatchFrame)` / `pub fn pop_catch_frame(&mut self) -> Option<CatchFrame>` are the public catch-stack accessors.
- `pub(crate) fn throw(&mut self, class, reason) -> Result<Step>` / `throw_error(reason) -> Result<Step>` / `throw_with_trace(class, reason, trace) -> Result<Step>` — **the one uniform raise/unwind entry point** the families call (see the exception model below).

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func: u32, pc: u32 }, Wait { func: u32, pc: u32 }, Done }` — the control-flow contract between the dispatch loop and the instruction families: an instruction body performs its effect and returns the `Step` telling the loop where to continue; it never mutates the loop's `func`/`pc`.
- `Next` continues at `pc + 1`; `Goto { func, pc }` jumps within the module; `Done` finishes the run and yields `x(0)`.
- `Wait { func, pc }` is the **suspend** signal a `receive` with no message available returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later. The loop folds it into a `RunOutcome`; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which tries the nine families in this fixed order — `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive` — and returns the first family's `Step`. Adding a family is a one-line change in `families/mod.rs`; the module docs list each family's owned variants.
- Each family exposes `pub(crate) fn exec(machine: &mut Machine, module: &Module, labels: &BTreeMap<Label, (u32, u32)>, instr: &Instr, func: u32, pc: u32, ctx: &mut dyn ExecutionContext) -> Result<Option<Step>>` — `Ok(Some(step))` = "this family executed it", `Ok(None)` = "not this family's variant", `Err` = the family raised.
- When **no** family claims an instruction, `dispatch` returns `error::unsupported("widened opcode not yet executed: <name>")`, `<name>` being the instruction's `ops.tab` spelling, so an unclaimed opcode is diagnosable from the error alone. Every receive/message variant is claimed.

### Term helpers (`src/terms.rs`) — the SAFETY-annotated builder/reader
Constructors take the seam (`ctx: &mut dyn ExecutionContext`, allocating via `alloc_words`):
- `make_tuple(ctx, &[Eterm]) -> Result<Eterm>` (arityval header + elements; empty → `tuple0`; > `MAX_ARITYVAL` → `SystemLimit`); `make_cons(ctx, head, tail)` (one header-less `[CAR,CDR]` cell; the tail need not be a list); `make_list(ctx, &[Eterm])` (cons cells; empty → `NIL`); `make_float(ctx, f64)`; `make_heap_binary(ctx, &[u8])` (heap binary/bitstring, ≤64 bytes).
- `badmatch_reason(ctx, module, value) -> Result<Eterm>` (`{badmatch, Value}`, the shared raise reason; `BeamError::BadMatch` when the module's atom table lacks `badmatch`).
- `make_map(ctx, &[(Eterm, Eterm)], atoms: &AtomTable) -> Result<Eterm>` — the **general map builder**: reserves `beam_term::map::map_words_capacity(n)` words and delegates to `beam_term::map::write_map`, so it builds a map of ANY size — a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys (keys in `erts_cmp_flatmap_keys` order), else a **hashmap** (HAMT) — collapsing duplicate keys **last value wins**, input pair order irrelevant. `make_flatmap(ctx, &[(Eterm, Eterm)]) -> Result<Eterm>` is kept for flat-layout-only callers (`>32` pairs → typed `unsupported("map > 32 pairs (use make_map)")`). A safe `is_hashmap(t) -> bool` wrapper over `beam_term::is_hashmap` is exposed beside them.
- `make_fun(ctx, arity: u32, uniq: u64, index: u32, free: &[Eterm]) -> Result<Eterm>` (minimal local closure; M1 inlines the out-of-line fun-entry descriptor).

Readers (no `ctx`; wrong type / out-of-range → `BeamError::BadArg`): `tuple_arity`, `tuple_element`, `cons_head`, `cons_tail`, `list_elements`, `float_value`, `map_entries` (flat map **and** hashmap/HAMT — walks the frozen `erl_map.h` node tree), `binary_bytes`, `is_fun`, `fun_arity`, `fun_num_free`, `fun_uniq`, `fun_index`, `fun_free`. Ownership model (module docs): the context owns the heap, `alloc_words` hands out stable raw pointers, and **only this module dereferences them**.

### The JIT tier seam (`src/jit/mod.rs`)
- `pub enum Tier { Interpreter, BaselineJit, Cranelift }` (`Clone, Copy, Debug, PartialEq, Eq`; `Tier::ALL` is the roster order, interpreter first): `Tier::name() -> &'static str` (`"interpreter"` / `"baseline-jit"` / `"jit-cranelift"`), `Tier::from_name(&str) -> Option<Tier>` (unknown ⇒ `None`, never a default tier), `Tier::is_available() -> bool`.
- `pub trait JitBackend` — the seam a **native** tier implements:
  ```rust
  pub trait JitBackend {
      type Compiled;
      fn name(&self) -> &'static str;
      fn available(&self) -> bool;
      fn compile(&mut self, module: &Module) -> Result<Self::Compiled>;
      /// Compile-once / run-many: run against a caller-owned artifact, no recompile.
      fn run_compiled(&self, compiled: &Self::Compiled, machine: &mut Machine, module: &Module,
                      function: Atom, arity: u32, args: &[Eterm],
                      ctx: &mut dyn ExecutionContext) -> Result<Eterm>;
      /// Provided: `compile` + `run_compiled` (the one-shot entry, one definition).
      fn run_export(&mut self, machine: &mut Machine, module: &Module, function: Atom,
                    arity: u32, args: &[Eterm], ctx: &mut dyn ExecutionContext) -> Result<Eterm> {
          let compiled = self.compile(module)?;
          self.run_compiled(&compiled, machine, module, function, arity, args, ctx)
      }
  }
  ```
  `&mut self` on `compile` (a backend owns its compile-time state: code buffer/caches), `&self` on `run_compiled` (the artifact is **caller-owned**; the backend holds no per-run code state, so one compiled module runs any number of times on fresh `Machine`s without recompiling). Both entries share the driver setup (reset, seed `x[0..arity)`, push the bottom frame, bind `module.literals`, build the label map, resolve the export). The interpreter is deliberately **not** a `JitBackend` (nothing to compile).
- `pub fn available_tiers() -> &'static [&'static str]` — the tiers compiled into this build: exactly `["interpreter", "baseline-jit"]`, plus `"jit-cranelift"` when the **`jit-cranelift`** feature is on. Interpreter always first; the roster is a prefix of `Tier::ALL` mapped to `Tier::name`.
- `Machine::run_with_tier(..., tier: Tier) -> Result<Eterm>` (`src/machine.rs`) selects: `Interpreter` delegates to `run_export` (which stays the default interpreter entry), `BaselineJit` runs the baseline backend, `Cranelift` routes through `crate::jit::run_cranelift` to the Cranelift backend when the feature is on and is a typed `error::unsupported("jit-cranelift tier not built")` when it is off — never a panic, never a silent fallback. Cargo features: **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (with it off the crate builds and tests with **no Cranelift dependency at all**); `jit-beamasm` is a documented alias for the baseline tier (already in every build's roster; kept so `--features jit-beamasm` keeps working).
- `src/jit/tiering.rs` (re-exported at the crate root): `TierPolicy { baseline_threshold, hot_threshold }` models §F's *interpret → baseline → hot* escalation a per-function execution counter would drive — `new(baseline, hot)` (clamps `hot` up to `baseline`), `select(executions) -> Tier` (below the baseline threshold `Interpreter`; up to but excluding the hot threshold `BaselineJit`; at/above it `Cranelift` **when compiled in**, else the hottest available tier — never an unavailable one), `is_hot(executions)`, `baseline_threshold()`/`hot_threshold()`, `Default` (baseline `1`, hot `10_000`), plus `DEFAULT_BASELINE_THRESHOLD`/`DEFAULT_HOT_THRESHOLD`. A **demonstrated policy only** — no execution path consults it; the counter + promotion machinery is Stage 1b.
- `src/jit/emitter/{mod,encode,tests}.rs` (a directory module) — the `#[allow(unsafe_code)]` x86-64 encoder + executable `CodeBuffer` both native tiers are built on: `mod.rs` owns the `Reg`/`Cond`/`Label` types, the `CodeBuffer` label/bind/seal API and the raw byte-emission primitives (the only `mmap` RW → `mprotect` RX on `seal`, never RWX; `munmap` in `Drop`), `encode.rs` holds the thin per-instruction encoders (mov/lea/arith/logic/shift/cmp/branch/call/ret), `tests.rs` the byte-level unit tests. `beam_common::Result` errors; System V AMD64 — module docs.
- `src/jit/baseline/` — the **native baseline backend** (`mod.rs` + `BaselineJit`/`CompiledModule`/driver, `runtime.rs` block ABI + `jit_step_one`, `emit/` (a directory module: `mod` + `move`/`select`/`test`/`arith`/`aggregate`/`regalloc`/`operands`), `tests.rs`); `BaselineJit` is a zero-sized `JitBackend` (`compile` = `compile_module`; `run_compiled` = the driver on the caller-owned `&CompiledModule`; `run_export` = the provided one-shot). The module docs own the byte-level detail; the contract is: a block is an `extern "C" fn(*mut JitRuntime) -> i64` returning `encode_target(func, pc) = func<<32 | pc` / `HALT = -1` (`machine.finish()`) / `ERROR = -2` (a propagating `BeamError` in `rt.error`); `JitRuntime` (`#[repr(C)]`) carries `machine`, `x_regs` (the base of `machine.x`, `RUNTIME_XREGS_DISP = 8`), `module`, `labels`, `ctx` and `error`, and generated code loads **only** `x_regs`; `CompiledModule` exposes `entry(func, pc)`, `block_count()`, `highest_cached_register()`, `highest_native_register()`, `cached_registers()`, `code_len()`, `code_address_range()`; and `jit_step_one` is literally `Machine::step_instruction` folded into the block ABI, which gives the tier **full opcode coverage with interpreter-identical semantics**.
  - **Inlined natively**: the metadata no-ops; `Move`/`Swap` (every x-register/constant shape, resident or direct `machine.x`); `Jump` to a module-defined label; the **word-level `Test` subset** — `is_nil`/`is_atom`/`is_list`/`is_nonempty_list`/`is_boolean` and the comparisons `is_eq_exact`/`is_ne_exact`/`is_eq`/`is_ne`/`is_lt`/`is_ge` (guarded small-int forms) — with the fail-label branch; `SelectVal` (a `cmp`/`jcc` chain when the scrutinee is an x-register/immediate and **every** case value is an immediate constant); the guarded small-int `erlang:'+'/2`/`'-'/2`/`'*'/2` `gc_bif` fast paths (`'*'` range-checks the **untagged** product against `[MIN_SMALL,MAX_SMALL]` — a tagged-word check would be wrong); and the **aggregate readers** `GetList`/`GetHd`/`GetTl` (cons-tag guard; CAR then CDR) and `GetTupleElement`/`SelectTupleArity` (boxed + `ARITYVAL` header + bounds guard). **Everything else deopts** — including a `Move`/`Swap` with a `Y`/`Literal` operand or an index `>= MAX_REGISTER`, the boxed-term `Test`s, a non-immediate `SelectVal` case, `PutTuple2` (needs heap allocation; stays on the interpreter helper), `FuncInfo`, and the whole call/exception surface — so the interpreter's exact error surfaces.
  - **Register allocation** (`emit/regalloc.rs`): a **usage-weighted per-block residency picker** counts each x-register's native touch points over the block (mirroring each lowering's own inlining decision) and caches the top **five** in `r12`–`r15` + `rbp` (ascending-index tie-break); every other x-register is addressed **directly in `machine.x`** (`[x_regs_base + n*8]`) — that *is* the fill/spill for "more live registers than fit" (membership is block-fixed, so the two representations can never disagree; there is no rematerialization and no intra-block eviction). `rbx` = the `x_regs` base, `rt` in a reserved 24-byte stack slot (`rbp` is released from frame-pointer duty — the emitter always encodes memory operands as disp32); the prologue pushes `rbx`,`rbp`,`r12`–`r15` and loads the resident slots, and the **epilogue spills them back to `machine.x` at every block exit** — the whole liveness model, so any helper/GC sees the interpreter's exact root set `x[0..live)` + the whole stack with no liveness maps.
  - **Driver (`run_compiled`)** mirrors `run_label`'s setup, then loops: look up the compiled block through a **flat `[func][pc]` index** (not a hash map) and fold its word (`HALT → finish()`, `ERROR → Err(rt.error)`, `(f,p) → continue`), else take one `step_instruction`. A per-run `native_ok` guard refuses native entry when `machine.x.len() <= highest_native_register` (the generated loads are unchecked), staying on the interpreter step. Any instruction the block does not inline runs through **`emit_step_and_continue`**: one `jit_step_one` (the interpreter's own `step_instruction`) then native continuation at `pc+1` when the helper advanced by one; any other outcome (`Goto`/`HALT`/`ERROR`/`Wait`) exits to the driver — so results stay interpreter-identical by construction.
- `src/jit/cranelift/` (`#[cfg(feature = "jit-cranelift")]`, a directory module) — the **optional Cranelift hot backend**: `mod.rs` (the `JitBackend` seam / `CraneliftJit` / `CompiledFunctions` / `CompiledEntries`), `codegen.rs` (one Cranelift function per IR `Function`, same `(I64 rt) -> I64` block ABI with the entry `pc` baked in at compile time, looping natively on `jit_step_one`'s returned target and returning the word to the driver when the target is a **different** function; a `pc`-block CFG), `shape.rs`/`inline.rs` (the inlined opcode shapes + the deopt-into-`jit_step_one` helper dispatch), `report.rs` (`CodegenReport` — test-visible codegen introspection incl. `inlined_gc_bif_ops()`), `tests.rs`. `CompiledFunctions` owns the `JITModule` (keeping the executable mapping alive) plus the per-function compiled entry/`entry_pc`, and `CompiledEntries` enters a function **only at its entry `pc`**. It inlines the **same cheap set as the baseline** where the two agree exactly — `Move`, the word-level `Test` subset, `SelectVal`, the small-int `'+'/'-'/'*'` `gc_bif` fast paths, and the `GetList`/`GetHd`/`GetTl`/`GetTupleElement`/`SelectTupleArity` reads — and deopts everything else to `jit_step_one` (see Measured).

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), and `blocked()` = `unsupported("run: process blocked (no message available)")` — the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend.

## Execution model (frozen semantics — reproduce, don't reinvent)
### Registers, stack & frames (`beam_emu.c`, `emu/macros.tab:116-147`, `:236-247`)
- **X registers**: `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`; the root set is `x[0..live)` (per `Instr::..{live}`).
- **Stack frame**: `allocate`/`allocate_heap`/… push `stack_need + 1` words — a *continuation-pointer slot* followed by `stack_need` Y-registers, `y(k)` being the slot after the CP slot (`E[1+k]`). The CP slot is modeled as a typed `Continuation` (`Address{func,pc}` or `Halt`) on the frame, not a raw stack word; the Y slots live in the stack.
- `call` (non-tail) stores the continuation in the *current* frame's CP slot, then jumps. `return` reads it from the *current* frame and jumps there; a frame-less leaf (e.g. `add/2`) uses a bare `return` and reads the *caller's* CP slot. `deallocate(n)` / `call_last{n}` / `call_ext_last{n}` pop the frame (its `n` Y slots **and** the CP slot, via `pop_frame_checked`), so a following `return` reads the caller's CP slot. Reaching the **bottom frame** (`Continuation::Halt`) halts execution and yields `x(0)`.
- `trim{n}` reproduces C's `i_trim` (`emu/instrs.tab:593`, `E += n`): it **discards the lowest `n` Y slots** and renumbers the survivors down (`y(k) → y(k−n)`), exactly what the compiler's `beam_trim.erl` assumes. The `remaining` operand is JIT-only, ignored by the interpreter.
- `test_heap{heap_need, live}` calls `ctx.ensure_heap(heap_need.words(), live, x, stack)` and leaves the stack unchanged; `allocate`/`allocate_heap` recover the frame's word count through `beam_loader::HeapNeed::words()`.

### The dispatch loop (`src/interpreter.rs`)
- Each iteration reads `module.functions[func].code[pc]` (typed `Instr`) and dispatches with a safe `match` (no computed-goto; the IR is pre-decoded, so typed dispatch is equivalent to a jump table). Core arms mutate the loop's `func`/`pc` in place; the catch-all arm calls `families::dispatch` and folds its `Step` back.
- The module-wide `Label -> (function index, code index)` map is built from every `Function::labels` (`build_label_map`), so a call/fail target may live in another function (the slice's `fib/1` tail-calls into `fib/3`); a missing label is `error::unknown_label`. `import_target` resolves an `ImportRef` to `(module name, function name, arity)` through `Module::imports` + `Module::atom_name`.
- The residual `Instr::Generic` opcodes (the loader's unmodelled set) go to `src/generic.rs` (`pub(crate) fn exec(op: Opcode) -> Result<Step>`): a **pure sentinel** — EVERY residual `Instr::Generic` opcode returns `error::unsupported(op.name())`, the documented typed error carrying the opcode's own `ops.tab` name, never a panic and never a silently wrong result. Every opcode the M1 interpreter executes has its own typed IR variant (e.g. `is_any_native_record` is `Instr::IsAnyNativeRecord`, executed by the records family).

### Instruction subset — **executed by the core loop**
`Label`, `Line`, `IntCodeEnd`, `ExecutableLine`, `DebugLine`, `NifStart` (`nif_start`), `OnLoad` (`on_load`) — metadata/no-ops that do not change control flow (`nif_start`/`on_load` are the compiler's markers at the head of a NIF stub / an `-on_load` function; `emu/ops.tab` lists them as bare opcodes with no body, so `Step::Next` is their exact semantics).
`FuncInfo` (`func_info`) — the failed-clause raise, **not** a no-op: a function's callable entry label is the label *after* `func_info` (`Export.label == Function::entry_label`), so a normal call never reaches it; the only way in is a JUMP from a failed head-pattern/guard `fail` label. It raises class `error` with the **bare atom** `function_clause` (the call arguments ride in the stacktrace, not the reason), resolved from the running module's atom table — a module whose table lacks the atom is a typed `unsupported`, never a substituted wrong atom — matching C's `i_func_info_IaaI` (`beam_emu.c:578-583`). Treating it as a no-op would fall through to the entry label and re-run the clause tests forever (the `proplists:get_value(a, undefined)` hang); the baseline JIT therefore **deopts** `FuncInfo` to `jit_step_one` rather than inlining it (`src/jit/baseline/emit/`).
`Move`, `Swap`, `InitYregs` (`init_yregs` writes `NIL` into the listed Y registers).
`Test` (**all** `TestKind`s, below), `SelectVal` (exact `=:=` match against each `(value, label)`, else `fail`, else a raise when `fail == NO_FAIL`).
`Jump`, `Call`, `CallLast`, `CallOnly`, `CallExt`, `CallExtOnly`, `CallExtLast`, `Allocate`, `AllocateHeap`, `TestHeap`, `Deallocate`, `Trim`, `Return`.
`GcBif`, `Bif0`, `Bif`. The native-record family — `Instr::IsAnyNativeRecord { fail, src }` (`is_any_native_record`), `Instr::IsNativeRecord`, `Instr::GetRecordElements`, `Instr::GetRecordElementsId`, `Instr::PutRecord`, `Instr::IsRecordAccessible`, `Instr::GetRecordField`, `Instr::UpdateRecordId` (see the records family). `Instr::Generic { op, operands, .. }` executes **nothing** (see the dispatch loop).
- **`GcBif`/`Bif` failure semantics**: evaluate the arg operands, call `ctx.call_bif`. On `Ok`, store into `dst`. On `Err` with a live `fail` label, **jump to `fail`** (guard failure); on `Err` with `fail == NO_FAIL`, **raise** via `raise_bif_error` (mirrors `FAIL_HEAD_OR_BODY`, `emu/macros.tab:266`). **`Bif0`/`CallExt*` carry no fail label, so every error is a raise.**
- **`raise_bif_error`**: a `BeamError::Raise` **carrying a live reason term** (`Raise::live_reason`, payload `Eterm` — the shape `beam_bifs` raises for a compound reason) is raised through the one uniform entry point `Machine::throw_with_trace(class, term, NIL)`, exactly like an instruction-level raise: with a live catch frame it lands in the handler (`x(1)` = the term), with none it propagates the term-carrying `Raise`. Every other case is unchanged: with no live catch frame the error propagates as-is, and with one the error's BEAM atom name (`BeamError::as_atom()`: `badarg`/`badarith`/`badarity`/`badmatch`/`system_limit`/`out_of_memory`) is resolved in the running module's atom table, turned into a term and raised with class `error` — the class every BIF failure carries. An error the engine cannot name as a term (no atom, a `Raise` without a live slot, `TermNotFound`, `Io`, or an atom absent from the module) propagates unchanged rather than being substituted by a *different* atom.
- **`Test` failure semantics**: succeeds ⇒ fall through; fails ⇒ jump to `fail`, or raise `error::unsupported("test/no_fail")` when `fail == NO_FAIL`.
- **`Test` comparison kinds**: `IsLt`/`IsGe`/`IsEq`/`IsNe` compare `args[0]` vs `args[1]` with arithmetic equality (`cmp_arith`); `IsEqExact`/`IsNeExact` use exact equality (`cmp`).
- **`Test` type kinds**: `IsInteger`, `IsFloat`, `IsNumber`, `IsAtom`, `IsPid`, `IsReference`, `IsPort` (each pid/ref/port accepted internal or external), `IsNil`, `IsBinary`, `IsBitstr`, `IsList` (`[]` or a cons cell), `IsNonemptyList`, `IsTuple`, `IsMap`, `IsBoolean` (the atom `true`/`false`), `IsFunction`, `IsFunction2` (`args[0]` is a fun of `args[1]` arity), `IsTaggedTuple` (`args[0]` is a tuple of `args[1]` arity whose first element is `args[2]`), `TestArity` (`args[0]` is a tuple of `args[1]` arity).

### Operand subset
- **Supported**: `X(n)`, `Y(n)` (bounds-checked; out of range → `error::bad_register`); `Typed{reg, ty}` (read/write `reg`, ignore the type annotation); `FloatReg(n)` (read/write the FR file; out of range → `bad_register`); `Integer(i)`/`Character(c)` (a small int when in range, an exact bignum otherwise — `terms::make_integer`), `Atom(a)` (`make_atom`), `Nil` (`NIL`).
- **Not supported by the general reader/writer**: `Literal` (an index into the running module's decoded literal area) **is** read via `crate::operand::read_operand` (`Machine::literal`); only `Label`, `List` and `Allocation` are unsupported there → a typed `error::unsupported`. `write_operand` rejects every non-register destination, `Literal` included (a literal has no addressable slot).

### Instruction families — **executed** (each module's docs own its opcodes and every edge case)
- `families/tuples.rs`: `PutTuple2`, `GetTupleElement`, `SelectTupleArity` (a bad shape/arity raises `{badmatch, Value}` on the no-fail path).
- `families/records/{mod,raw,tests}.rs`: the whole record family. `UpdateRecord` (copy the `size`-arity source tuple, overwrite the element at each **1-based** `(offset, value)` pair into `dst`; copy-then-patch, so a value aliasing `dst` reads the *original* tuple, and the `copy`/`reuse`/`inplace` hint is ignored — M1 never updates in place, observationally equivalent since `inplace` is emitted only for a unique/dead source); `Instr::IsAnyNativeRecord` (`is_any_native_record Fail Src` — succeed iff `Src` is a native record (`predicates::is_record`, a header-subtag test, not a tuple test), else branch to `Fail`; `NO_FAIL` → typed `unsupported("is_any_native_record/no_fail")`); and the **seven typed native-record variants** (`IsNativeRecord`, `GetRecordElements`, `GetRecordElementsId`, `PutRecord`, `IsRecordAccessible`, `GetRecordField`, `UpdateRecordId`). The native-record semantics reproduce `erl_record.c`/`emu/instrs.tab` branch for branch: `IsNativeRecord` = `erl_is_native_record` (definition module+name `=:=` the two atom operands); `GetRecordElements`/`GetRecordElementsId` read each listed `(field name, dst)` pair's value out of the record and fall through (the `Id` operand is **discarded** — `emu/ops.tab:1643` lowers `get_record_elements_id` to `i_get_record_elements`, so the two share one implementation); `PutRecord`'s *update* form (`Src` a register, `i_update_native_record`, `Id` discarded at `emu/ops.tab:1653`) and `UpdateRecordId` (`emu/ops.tab:1689`, `Hint`/`Id` discarded) rebuild the instance with the listed fields replaced (fresh copy, source identity reused; every update value is read before `dst` is written, so an aliased value still sees the original record); `IsRecordAccessible` is the strict `erl_is_record_accessible` when `scope` is the atom `external` (definition must be exported), else the `$MODULE` wildcard `erl_is_wildcard_record_accessible` (exported **or** created in that module); `GetRecordField` is `erl_get_local_record_field` for an atom `Id` (the record's name in the running module, no export requirement, an `_` name skips the name test) and `erl_get_record_field` for a `{Module,Name}` `Id` (which additionally requires the definition to be exported). All raw-layout access goes through the family's single `#[allow(unsafe_code)]` `raw` module forwarding to the frozen `beam_term::record` readers/writers (`record_definition`/`record_is_native`/`record_name_is`/`record_values`/`record_get`/`record_is_exported`/`record_definition_*`/`record_declaration_keys`/`write_record`/`record_block_words`) — the family never re-derives the layout.
- `families/lists.rs`: `PutList`, `GetList`, `GetHd`, `GetTl` (a non-cons source raises `{badmatch, Value}`).
- `families/funs.rs`: `MakeFun3` (the closure's arity is the descriptor arity − `num_free`), `CallFun` (fun in `x(arity)`, args `x(0..arity)`), `CallFun2` (fun is a `func` operand, `tag` hint ignored), `Apply` (M in `x(arity)`, F in `x(arity+1)`, args `x(0..arity)`), `ApplyLast` (pops the frame first, then follows the continuation). A non-atom `apply` target is a `badarg` raise through `Machine::throw_error`, landing in a live catch frame or propagating as the typed `BeamError::BadArg`.
- `families/exceptions.rs`: `Badmatch` (`{badmatch,V}`), `CaseEnd` (`{case_clause,V}`), `TryCaseEnd` (`{try_clause,V}`), `IfEnd` (`if_clause`), `Badrecord` (`{badrecord,V}`), `Raise` (re-raise with the class currently being handled), `Try`/`Catch` (push a catch frame), `TryCase`/`TryEnd`/`CatchEnd` (the handler opcodes, each consuming exactly one catch frame), `BuildStacktrace`, `RawRaise` (both documented in Known Issues).
- `families/floats.rs`: `Fmove`, `Fconv`, `Fadd`/`Fsub`/`Fmul`/`Fdiv`, `Fnegate`. The FR file keeps `Eterm` slots; a non-float operand or a non-finite result is the instruction's arithmetic failure — a guard branch to `fail` when one is live, else a `badarith` raise through `raise_badarith`, landing in a live catch frame or propagating as the typed `BeamError::BadArith`. `Fconv` (no fail label) with a **bignum** source converts faithfully — nearest double, ties to even — via the safe `beam_term::number::big_to_f64` (the `big_to_double` port); an over-range bignum (magnitude not representable as a finite double, e.g. >1024-bit) raises `badarith`.
- `families/maps.rs`: `GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact`. Sources are read in **both** layouts (`terms::map_entries` handles a flat map and a hashmap/HAMT); key matching delegates to `beam_term::cmp`, so `1` and `1.0` are distinct keys; a non-map source is a `fail` jump on the compiled forms, else `{badmap, Source}`. **Construction** goes through `terms::make_map`, so `PutMapAssoc`/`PutMapExact` build a **hashmap** once the map grows past `MAP_SMALL_MAP_LIMIT` (32) distinct keys — no cap and no `unsupported`.
- `families/bitstrings/{mod,matching,create,raw}.rs`: the whole `bs_*` set — `BsStartMatch3`/`BsStartMatch4`, `BsMatch` (the flattened command list: `ensure_at_least`, `ensure_exactly`, `skip`, `integer`, `binary`, `get_tail`, `=:=`), `BsMatchString`, `BsTestTail2`, `BsGetTail`, `BsGetPosition`, `BsSetPosition`, `BsGetInteger2` (any width — ≤64 bits in a machine word, >64 as a `beam_term` bignum, big/little-endian and signed), `BsGetFloat2` (0/16/32/64 bits), `BsGetBinary2`, `BsSkipBits2`, the UTF reads/skips (`BsGetUtf8`/`BsGetUtf16`/`BsGetUtf32`, `BsSkipUtf8`/`BsSkipUtf16`/`BsSkipUtf32`), `BsCreateBin` (`integer` — any width —, `binary`, `float`, `utf8`/`utf16`/`utf32` and `string` segments; a `string` segment is a literal byte slice of the module's `StrT` table appended at the current bit position, mirroring `erts_bs_put_string`, `erl_bits.c:1641`), `BsInitWritable` and a **first** `append`/`private_append` (seed-and-rebuild); a result of any size — an on-heap `ErlHeapBits` ≤64 bytes, an off-heap refc binary above it. The match-context is an on-heap boxed term in the C `ErlSubBits` shape `[HEADER_SUB_BITS, 0, start, end, orig]`, re-derived from the term at every opcode, so matching survives calls and branches without a side table.
- `families/receive.rs`: `Send` (deliver `x(1)` to `x(0)`, store **the message itself** in `x(0)`; no fail label, so a failure raises through the catch-aware `raise_bif_error`), `LoopRec` (`loop_rec Fail Dst` — candidate → `Dst`, else jump to `Fail`), `LoopRecEnd` (advance the scan, jump back), `Wait` (`Step::Wait` at the target), `WaitTimeout` (a small-int `0` falls through to the following `timeout`, anything else suspends like `wait`), `Timeout` (`receive_reset`), `RemoveMessage` (`receive_remove`), `RecvMarkerReserve`/`RecvMarkerBind`/`RecvMarkerUse`/`RecvMarkerClear`. The family is registered **last**; it performs no pattern matching and no term inspection — every mailbox position/removal is delegated to the `Mailbox` seam.

### Raising opcodes and the catch-frame model (`families/exceptions.rs`, `src/machine.rs`)
- `try`/`catch` (`Try`/`Catch`) push a `CatchFrame { func, pc, frame_index }` (the handler's location plus the **current** call frame, i.e. the frame owning the handler) and blank their frame slot.
- A raise (a family's `throw`/`throw_error`, or `raise_bif_error`) records `pending_exception = (class, reason)`, then consults the **innermost** live catch frame; with none it propagates as `Err(BeamError::Raise(..))` carrying that reason term in the raise's `live_reason` slot.
- To land, the machine unwinds the call-frame stack back to `CatchFrame::frame_index` (dropping the Y slots of every deeper frame) and writes the handler registers exactly as C's `handle_error` does: `x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace` (`NIL` at M1), `x(3) = class atom`.
- A landed raise returns `Ok(Step::Goto { func, pc })` for the handler; with no live catch frame (or an unresolved class atom) it returns the typed `Err(BeamError::Raise(..))` — never a panic.
- **The raise never pops the catch frame**: it *reads* the innermost entry and unwinds the call frames but leaves the entry in place; the handler opcode that runs next (`try_case`/`try_end`/`catch_end`) consumes exactly one entry (on the normal or the exceptional path, never both). `try_case` blanks its frame slot, requires the `THE_NON_VALUE` marker in `x(0)`, and moves the class atom from `x(3)` into `x(0)`; `try_end` just blanks its frame slot; `catch_end` leaves a normal result untouched but folds a landed exception into the caught term — the thrown value for class `throw`, `{'EXIT',Reason}` otherwise.
- The class atoms (`error`/`exit`/`throw`) are installed from the running module's atom table before a raise (`Machine::set_class_atom`); an atom absent from the module is never substituted by a *different* atom (an uncaught raise still propagates as a typed error, a caught raise fails with a typed `unsupported`). `pending_class` is the class a `raise` opcode re-raises with, reproducing C's `i_raise` keeping `freason`.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** — no crate-local error enum (workspace §3); an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` — the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`) with exactly **five** `#[allow(unsafe_code)]` modules — `src/predicates.rs` (the `beam_term` boxed-term predicate wrappers), `src/terms.rs` (the crate's single point of raw-heap boxed-term construction/reading behind `alloc_words`, incl. the map writer/reader for both frozen map layouts), `src/families/bitstrings/raw.rs` (the `ErlSubBits`/`ErlHeapBits` raw-layout accessors and the off-heap refc payload allocation), `src/jit/emitter/mod.rs` (the x86-64 encoder and the crate's **only executable-memory mapping**), and `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*` (the baseline backend reconstructs `&mut Machine`/`&mut dyn ExecutionContext`/`&Module`/`&BTreeMap` from `JitRuntime`'s live, driver-owned, unaliased pointers and calls a block's entry as a transmuted `extern "C" fn`). Every `unsafe` block carries a `// SAFETY:` rationale; registers/stack stay safe `Vec<Eterm>` indexing and `unsafe_op_in_unsafe_fn` stays clean. The SAFETY rationale, the exported predicate names and the per-module detail live in the module docs.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 → wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need (`Machine::alloc_refc_binary`, held as `Machine::refc_binaries`, deliberately **never cleared by `reset`**).
- **Files ~1000 lines**, split by responsibility; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

Cranelift is now faster than the interpreter on all four workloads (it previously lost `kernel/2` because it inlined nothing).
- One-time `compile` cost (excluded from the timed loop): baseline ≈31 / 251 / 268 / 1304 µs (fib/kernel/wide/aggr); Cranelift ≈1.4 / 22.6 / 25.8 / 122 ms.
- **Not done (honest):** no native block linking / **cross-run code cache** — the driver still round-trips per basic block, so `fib` (many small blocks) is block-entry-bound and benefits far less than the straight-line kernels; no rematerialization and no intra-block eviction (residency is block-fixed by design); `PutTuple2` stays on the interpreter helper in both tiers.

## Design Decisions
- **`ExecutionContext` seam with the root-set contract made concrete.** `call_bif`/`apply_fun` isolate BIF dispatch and fun application; `ensure_heap(heap_need, live, &mut x, &mut stack)` hands the exact GC root set (`x[0..live)` + the whole stack) to the context so a Stage-4 collector can move terms in place without frame liveness maps.
- **A per-instruction-family seam keeps the loop small and edit-local**, and **`Step` is the loop/family control-flow contract**: one `match` arm per *core* opcode, everything else to `families::dispatch`; a family returns `Next`/`Goto`/`Done`/`Wait` and never mutates the loop's `func`/`pc`, and a raise stays an `Err(BeamError)` or is folded into a `Goto` by the exception layer.
- **Safe `match`-based dispatch, not computed-goto.** The IR is pre-decoded (typed `Instr`, operands resolved at load time), so dispatch is one arm per op — the direct-threaded *model* of §F without `unsafe`/`goto`.
- **A typed frame CP slot, not a raw stack word**, and **a catch-frame stack mirroring C's `next_catch` + `c_p->catches` split**: a raise reads the innermost `CatchFrame` and unwinds the call frames (C's `c_p->stop = prev`), the handler opcode pops exactly one entry (C's `c_p->catches--`), and `Machine::throw` is the one raise/unwind entry point, so the landing convention (`x(0..=3)`) and the bookkeeping live in one place.
- **Module-wide label index.** `Call*` targets and `fail` labels are module-local and can cross functions (`fib/1` → `fib/3`), so each run builds a `Label -> (function index, code index)` map from `Module.functions[*].labels`.
- **A real tier seam, with the JIT tiers off the critical path.** Cranelift is an optional feature (default OFF), so with it off the crate and the build/test flow carry no Cranelift codegen or dependency; JIT compilation is measurement-gated (§F) with a bounded-latency, cheap-deopt design, and `TierPolicy` is a **policy type deliberately not wired into execution**.
- **One driver for both native tiers, both delegating per instruction rather than duplicating semantics.** The baseline driver holds the setup, the `HALT`/`ERROR`/`(func, pc)` folding and the interpreter-step fallback once; a tier plugs in its compiled-code lookup through the `NativeCode` trait (`enter(rt, func, pc) -> Option<i64>`) — the baseline tier for every compiled block (refusing when the register file is too small), Cranelift only at a function's entry `pc`. Because `jit_step_one` *is* `Machine::step_instruction`, every tier has interpreter-identical semantics for every supported opcode without a second implementation.
- **Block register allocation keeps a usage-weighted five-register residency and addresses the rest directly in `machine.x`.** `emit/regalloc.rs` picks the five most-touched x-registers and caches them in `r12`–`r15`+`rbp`; a non-resident register is read/written inline at `[rbx + x*8]`, which *is* the fill/spill for more live registers than fit — residency is fixed for the block, so the cached and in-memory representations can never disagree (no intra-block eviction, no rematerialization). `JitRuntime` carries `machine` and `x_regs` separately because generated `[base + n*8]` addressing must index the x-register **array**, not the `Vec` header, and `machine.x` is fixed after `reset`. The block-exit spill of the resident slots is the only liveness model, and `run_compiled`'s `native_ok` guard keeps a machine smaller than the highest natively addressed register on the interpreter step, leaving the observable result unchanged.
- **Compile failure is a typed error, never a silent fallback.** `CodeBuffer::seal`'s failures propagate out of `compile`/`run_export`; an unresolved `Jump` target goes to the helper so the interpreter's exact `unknown_label` surfaces.
- **Reuse the loader fixture; do not duplicate it.** The slice `.beam` lives with `beam_loader`; `beam_engine` reads it by relative path.
- **Unsupported ⇒ `Raise` with reason atom `unsupported_opcode`.** `beam_common::BeamError` has no dedicated variant and must not gain one from here.
- **The FR file stores `Eterm` term slots at M1** (the C file is raw doubles, `FloatDef`), because the engine's operand seam is `Eterm`-typed and a term-slot FR file lets `read_operand`/`write_operand` support `FloatReg` uniformly; the raw-double model is deferred.
- **Term construction lives behind `alloc_words` + `terms`** — `terms` owns the boxed-term contract and is the only place that dereferences raw heap storage; the bitstring family adds its own `raw` module for the two frozen bit layouts, and the map writer/reader lives in `terms` (layout choice delegated to `beam_term::map::write_map`), so no builder is duplicated.
- **M1 fun layout inlines the descriptor** (`uniq`, `index` as two words after the header) because M1 has no code pointers — the same documented "M1 substitution" pattern as the external-pid `node` slot (`erl_term.h` `MAKE_FUN_HEADER` + `erl_fun.h` `ErlFunThing`).
- **`MinimalContext` fun application goes through an apply hook** (the engine keeps no closure registry), and **a `build_stacktrace` trace is derived from the machine's live frames** (`Machine::resumption_addresses()`), not a raise-time snapshot — the honest M1 substitute documented in Known Issues.
- **`update_record` always copies.** The compiler's `copy`/`reuse`/`inplace` hint only authorises an in-place update for a unique/dead source; a copy is observationally equivalent and needs no uniqueness analysis.

## Known Issues / Intentional M1 gaps
- **No garbage collection.** `MinimalContext` has an unbounded, never-freed arena; `test_heap`/`allocate_heap` call `ensure_heap` (a no-op there). The real collector + heap sizing is Stage 4 (`beam_gc`); the engine allocates boxed terms only through `terms`/`alloc_words`.
- **`build_stacktrace`/`raw_raise` are executed, but a captured trace is engine-derived.** `raw_raise` is oracle-exact for all three classes (`error`/`exit`/`throw`) and the unknown-class fall-through (`x(0) = badarg`, no raise). `build_stacktrace` is oracle-exact for a `NIL` raw trace — today's only compiler-emitted path, since `catch`/`try` land with `x(2) = NIL` and `catch_end` appends no element; for a non-`NIL` trace it substitutes a symbolic trace derived from the machine's **live** call frames, not a saved raw `StackTrace`, so unwound frames, out-of-run host frames, saved argument lists and `error_info` entries are absent, and the innermost item always carries the arity.
- **`catch_end` needs the `EXIT` atom**: a module whose atom table lacks it returns a typed `unsupported` rather than substituting a wrong atom.
- **`raise_bif_error` can only raise a nameable error.** A BIF failure whose atom is absent from the running module's atom table (or a `BeamError` with no BEAM atom *and no live reason term*: `TermNotFound`, `Io`, or a `Raise` whose `live_reason` slot is empty or holds a non-`Eterm` payload) propagates unchanged, because the `Module` reaches the interpreter read-only.
- **Compiled arithmetic is oracle-exact on overflow by construction.** `+ - * div rem` overflow promotes to exact bignums, because compiled `gc_bif` goes through the frozen `ctx.call_bif` seam into `beam_bifs`, which never overflows to `system_limit`. An out-of-range `Integer`/`Character` **operand** (what `erlc` emits for a small literal ≥ 2^59) is materialized by `terms::make_integer` as an exact bignum, and the JIT's `constant_word` deopts such an operand to the interpreter step instead of calling `make_small`.
- **The receive/message family executes, but a blocking `receive` needs a host mailbox.** `families/receive.rs` delegates every mailbox position/removal to the nine-method `Mailbox` seam: with **no** mailbox each call is a typed `unsupported("<method>")`, and with a mailbox that has no candidate the run **suspends** (`RunOutcome::Wait`), which plain `run_export` folds into the typed `error::blocked`. There is **no host timer at M1**, so `wait_timeout` with a non-zero/`infinity` time suspends until a message arrives (only a small-int `0` falls through to `timeout`), and both native JIT tiers surface `error::blocked` for a genuine block. Closing the differential A.9 cases needs the host half — see Handoffs #1.
- **The native-record set is executed; `PutRecord`'s *create* form is the one gap.** All eight typed native-record variants execute in `families/records` (the branch-for-branch semantics live in the family docs above). The one capability gap is `PutRecord`'s **create** form (`Src` is the literal `nil`, `emu/ops.tab:1648` → `i_create_native_record`): C resolves the definition through the code server's record table (`erts_record_find_entry`, `erl_record.c:102-170`), a facility this runtime lacks, so it is a typed `unsupported("put_record: create (record definition table unavailable)")` — never a fabricated definition; the **update** forms need no table (the source instance carries its own definition); a record-semantics failure the C reports by branching jumps to the instruction's `fail` label, and a `NO_FAIL` label is the typed `unsupported("<instr>/no_fail")` — never a fall-through with a wrong result and never a fabricated `badrecord`/`badfield` reason. Owning node: a `beam_loader`/`beam_rt` handoff (a reachable record-definition table).
- **Every residual `Instr::Generic` opcode is `unsupported`**, carrying `Opcode::name()` — no exception.
- **Bitstring gaps (each a typed result — never a wrong value).** `raw::heap_bits` refuses a refc subject whose window does not start on a byte boundary. `bs_init_writable`/`append`/`private_append` are implemented as a copy-rebuild (see `HANDOFF_bs_init_writable.md`); the divergences are no amortised in-place growth (an append loop is O(n²)) and the unmodelled `BIN_FLAG_WRITABLE`/`BIN_FLAG_ACTIVE_WRITER` flags and `binary:referenced_byte_size/1`'s capacity answer. An `append`/`private_append` segment that is **not the first** is a typed `unsupported` (the compiler only emits it first). A ≤64-bit **unsigned** read field above `MAX_SMALL` now builds the exact bignum (the oracle's value, with the ≥2^63 sign-extension bug fixed); a `bs_create_bin` construct failure now raises the oracle's `error:badarg` (not `{badmatch,V}`); `system_limit` is modelled (a `size*unit` overflow / the post-multiply sign bit / a positive-bignum size ⇒ `error:system_limit`, a negative bignum ⇒ `badarg`); and a `float` segment of size 0 or an invalid width raises `badarg` (16/32/64 written) — all pinned term-for-term in `tests/bitstrings_create_fail.rs` / `tests/bitstrings_extra_big.rs`.
- **Literal operands.** `beam_loader`/`beam_codec` decode the whole `LitT` area (incl. `EXPORT_EXT`/`NEW_FUN_EXT` fun literals, `>32`-key map literals, big-integer literals) and wide (`>8`-byte) integer instruction operands, so **every** module in the installed stdlib/kernel/compiler tree loads. A `Literal` index outside the running module's `LitT` table (or a literal read with no module bound) is the typed `operand: literal` error; the `floats` and `bitstrings` families also resolve their own literal operands through `Module::literal`.
- **Map enumeration order is storage order, not canonicalized** (`erts_cmp_flatmap_keys`), affecting only `term_to_binary` byte comparison, not map semantics. A malformed hashmap node / `THE_NON_VALUE` / immediate item during a read is a typed `BadArg`.
- **A missing map key with `fail == NO_FAIL` has no ground truth** (the compiler always emits a fail label for the matching forms), so it is a documented typed `unsupported` rather than an invented exception reason.
- **Baseline tier: a real (but partial) inline prefix.** Inlined: metadata no-ops; `Move`/`Swap` (all x-register/constant shapes); `Jump`; the word-level `Test` subset; all-immediate `SelectVal`; the guarded small-int `'+'/'-'/'*'` `gc_bif`s; and the `GetList`/`GetHd`/`GetTl`/`GetTupleElement`/`SelectTupleArity` reads. Everything not inlined — the boxed-term `Test`s, `Y`/`Literal` operands, non-immediate `SelectVal` cases, `PutTuple2`, `FuncInfo`, and the whole call/exception surface — runs through `emit_step_and_continue` (one `jit_step_one`, then native continuation at `pc+1`), so `Tier::BaselineJit` yields interpreter-identical results by construction, not by duplicating instruction semantics. The Cranelift tier inlines the same cheap set.
- **Baseline tier: no cross-run code cache.** `run_export` compiles its module per call (`run_with_tier` builds a fresh backend per invocation), so a run through the tier entry recompiles every time; the compile-once / run-many entry (`JitBackend::run_compiled` on a caller-held artifact) is the way to amortize it, and *caching* compiled modules (plus deeper inlining) is still deferred performance work (see Measured for the speedups).
- **No reductions / preemption / scheduler.** `run_*` executes to the function's `return`; scheduling, reductions and trap handling are Stage 5 (`beam_process`), and `ensure_heap` underflow/limits are unenforced — stack growth is an unbounded `Vec` in M1 (a configurable limit + `system_limit` raise is a later refinement).
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, closure free variables after.** C (`../../erts/emulator/beam/beam_common.c:1631-1633`) fills `reg[i] = args[i]` for `i < arity` **then** `reg[i + arity] = funp->env[i]`, so a concrete context must enter the closure body with `x(0..arity)` = the call arguments and `x(arity..)` = the captures — *not* `free ++ args`. Getting this backwards is silent (a zero-capture lambda cannot detect it; a capturing one can loop forever); the engine is agnostic — it calls `apply_fun(fun, args)` and the context lays out the registers.
- **Cross-crate duplications to avoid:** operand read/write, term comparison, the frame model, the map/bitstring readers and the bit-layout accessors live here; term construction/comparison must stay in `beam_term` (do not copy).

## Handoffs (opcodes/capabilities this crate cannot close alone)
The remaining execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node and the exact work. #1 is the highest impact (many real modules).
1. **Receive/message family — the engine executes it; the mailbox host is the handoff.** `families/receive.rs` executes `send`/`loop_rec`/`loop_rec_end`/`wait`/`wait_timeout`/`timeout`/`remove_message`/`recv_marker_reserve|bind|use|clear` — the **last** opcode family the standard compiler emits for real modules — driving the nine-method `Mailbox` seam on `ExecutionContext` (every method defaulted to a typed `unsupported`). **What `beam_rt` must supply:** implement those nine methods over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter the suspended process with `Machine::resume_outcome(module, func, pc, ctx)`, and drive a host **timer** for a non-zero `after` (M1 suspends instead of timing out). Even with the mailbox, the differential A.9 cases (`code:get_path/0` → `code:call/1` → `code_server:call/1`) additionally need a live `code_server` process in `beam_rt`, so they remain a `beam_process`/`beam_rt` handoff, not an engine gap.
2. **`beam_rt` must globally intern the exception reason atoms.** The engine resolves a raise's reason atom (`badmatch`/`case_clause`/`if_clause`/`function_clause`/`EXIT`/`badarg`/`badarith`/`system_limit`/`badmap`/`badkey`/`badrecord`/`badfield`/`undef`/`notsup`/`noproc`/`timeout_value`/`file`/`line`/…) from the running module's atom table and NEVER substitutes a different atom — but the compiler does not carry them, so real ERTS's `error_atom[NUMBER_EXIT_CODES]` table (`erts/emulator/beam/beam_common.c:382-406`) must be interned globally. The test host already does this (`tests/support/mod.rs::SEED_ATOMS`); production `beam_rt::boot::CORE_ATOMS` must gain the same tail (**its own test `the_exception_atoms_are_appended_last` must be updated in the same change**). This is also the root cause of the map `NO_FAIL` divergence below.
3. **`beam_engine` itself (next pass): capture a raw `StackTrace` at raise time.** `build_stacktrace`/`catch_end` are oracle-exact only for a `NIL` raw trace (today's only compiler-emitted path); a non-`NIL` trace currently yields a symbolic trace derived from the machine's **live** frames. Closing it means snapshotting a raw `StackTrace` in `Machine::throw_with_trace` and threading it through every raise site (incl. `interpreter.rs`'s `FuncInfo` arm), then consuming it in `families/exceptions.rs`. Synthesising a partial trace would be a silent wrong value, so it is deliberately left a documented gap.
4. **A reachable record-definition table** (`beam_loader`/`beam_rt`): needed for `PutRecord`'s **create** form and `records:get_definition/2` (both typed `unsupported` today; the `Recs` chunk / code-server record table is unreachable from `beam_loader`).
5. **`beam_io`/`beam_rt`: `open_port({spawn_executable, <nonexistent>})`** — the oracle raises `error:enoent`, while `beam_io`'s `SpawnDriver` maps the spawn failure to `BeamError::Io`.
6. **`beam_engine` (minor, flagged): `TestKind::TestArity`** uses `is_tuple_arity` (requires an `ARITYVAL` header) whereas production C `BEAM_IS_TUPLE` (`emu/beam_emu.c:222-228`) is only `is_boxed(Src)`; no known compiler emits `test_arity` on a non-tuple and `IsTaggedTuple` is behaviourally correct, so it is left for a future pass.
7. **Map `NO_FAIL` limitation** (`put_map_assoc`/`put_map_exact` with a non-map source and `NO_FAIL`): the engine yields `unsupported_opcode: maps: no 'badmap' atom in the module` where C raises `{badmap, Source}` — again only nameable once the global atoms of #2 exist.
8. **JIT (not a correctness gap): no native block linking / cross-run code cache.** The driver round-trips per basic block, so block-entry-bound code (`fib`) benefits far less than straight-line kernels; a caller-held `JitBackend::run_compiled` artifact is the current way to amortise compilation (see Measured).
