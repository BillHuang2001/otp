# `beam_engine` -- Typed-IR Execution Engine (interpreter + JIT tiers)

## Intent
Executes the **frozen typed IR** produced by `beam_loader`: a **direct-threaded interpreter** over a widened instruction set (the Stage-1 deliverable), behind a real **execution-tier seam** (`src/jit/`: `Tier` / `JitBackend` / `available_tiers()` / `Machine::run_with_tier`).
The **native baseline tier** (`src/jit/baseline/`) lowers each basic block to a real x86-64 `extern "C"` function and deopts the rest to one interpreter step (interpreter-identical semantics), with a cross-run compiled-block cache and a block linker (`src/jit/{cache.rs,baseline/emit/link.rs}`); the **optional Cranelift hot tier** (`src/jit/cranelift/`, default-off `jit-cranelift` feature) is one Cranelift function per IR function over the same shared interpreter-backed helper. All tiers are **measurement-gated** and off the critical path (Part II sec. F) -- correctness-first *mechanisms*, not optimisers.
Implements the Stage-1 engine half of Part II sec. H (IR contract sec. E, interpreter/JIT trade-offs sec. F, `../../CONTEXT.md` sec. 4), on the **critical path of the vertical slice**: it loads a real `.beam` (via `beam_loader`) and runs it end to end, with explicit dispatch arms for the core opcodes and a per-instruction-family seam (`src/families/`) for the rest. The engine depends only on `beam_loader`/`beam_term`/`beam_common`/`beam_alloc`, never on the Stage-5 runtime core: BIF dispatch, fun application, heap/GC and process/stack limits all sit behind `ExecutionContext` (implemented by `beam_rt`), keeping the DAG acyclic and the engine testable with a minimal context.

Ground truth (read-only, never modify): `../../erts/emulator/beam/emu/beam_emu.c`, the instruction bodies in `../../erts/emulator/beam/emu/*.tab`, and the call/return/allocate, error and `next_catch` conventions of `../../erts/emulator/beam/beam_common.c`.

## API Surface (FROZEN -- the runtime and tests design against this)
Re-exported at the crate root and via `beam_engine::prelude::*`.
The crate embeds NO BIF table: all computation goes through `ExecutionContext::call_bif`, fun application through `ExecutionContext::apply_fun`.

### The context seam (`src/context.rs`)
```rust
pub trait ExecutionContext {
    fn call_bif(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn ensure_heap(&mut self, heap_need: u32, live: u32, x_regs: &mut [Eterm], stack: &mut [Eterm]) -> Result<()>;
    /// The full-root twin of `ensure_heap` (adds the FR file);
    /// `Machine::ensure_heap` calls THIS, its default forwarding to the narrow one.
    fn ensure_heap_full(&mut self, heap_need: u32, roots: RootSet<'_>) -> Result<()> {
        self.ensure_heap(heap_need, roots.live, roots.x, roots.stack)
    }
    fn heap_available(&self) -> usize { usize::MAX }
    fn alloc_words(&mut self, n: usize) -> Result<*mut Eterm>;
    /// The rooted twin of `alloc_words`: the same request WITH the live root set.
    fn alloc_words_rooted(&mut self, n: usize, roots: RootSet<'_>) -> Result<*mut Eterm> {
        let _ = roots; self.alloc_words(n)
    }
    fn apply(&mut self, module: &str, function: &str, arity: u32, args: &[Eterm]) -> Result<Eterm>;
    fn apply_fun(&mut self, fun: Eterm, args: &[Eterm]) -> Result<Eterm>;
    /// Cross-module call seam: run the callee in THIS machine, or `None`.
    fn resolve_external_call(&mut self, module: &str, function: &str, arity: u32)
        -> Result<Option<(Arc<beam_loader::Module>, beam_loader::Label)>> { Ok(None) }
    /// Contract A.8 execution-trace seam: a cheap gate + a defaulted no-op reporter.
    fn trace_enabled(&self) -> bool { false }
    fn trace_event(&mut self, event: TraceEvent<'_>) { let _ = event; }
}
/// The engine's mutable root set -- the hand-off `alloc_words_rooted` receives.
pub struct RootSet<'a> {
    pub x: &'a mut [Eterm],     // the whole X-register file; `x[..live_len()]` is live
    pub stack: &'a mut [Eterm], // the WHOLE Erlang stack
    pub fr: &'a mut [Eterm],    // the WHOLE float-register (FR) file (Eterm term slots)
    pub live: u32,              // live-X hint (clamped; `RootSet::ALL_LIVE` = all)
}
impl<'a> RootSet<'a> {
    pub const ALL_LIVE: u32 = u32::MAX;
    pub fn new(x: &'a mut [Eterm], stack: &'a mut [Eterm], fr: &'a mut [Eterm], live: u32) -> RootSet<'a>;
    pub fn live_len(&self) -> usize;            // `live` clamped to `x.len()`
    pub fn live_x(&self) -> &[Eterm];           // `x[..live_len()]`
    pub fn live_x_mut(&mut self) -> &mut [Eterm];
}
pub enum TraceEvent<'a> {
    Call { module: &'a str, function: &'a str, arity: u32, args: &'a [Eterm] },
    ReturnFrom { module: &'a str, function: &'a str, arity: u32, value: Eterm },
    ReturnTo { module: &'a str, function: &'a str, arity: u32 },
}
```
- `call_bif` dispatches `module:function/arity`; failure is a return-based `Err(BeamError)` (`BadArith`/`BadArg`/`Raise`/...) the engine turns into a guard branch or a raise, never a panic.
- `ensure_heap(heap_need, live, x_regs, stack)` is the **narrow** admission point (live roots `x_regs[0..live)` + the whole `stack`); `Machine::ensure_heap` (reached by `test_heap`/`allocate_heap`) no longer calls it directly -- it calls the defaulted **`ensure_heap_full(heap_need, roots)`**, which receives the whole [`RootSet`] (**including the FR file**, which holds `Eterm` term slots) and whose default forwards to the narrow `ensure_heap` with the FR file discarded. So a host that predates the full door is byte-identical, and a host with a real collector overrides `ensure_heap_full` to run the collector over every live root at the primary admission point. A real context (`beam_rt`) may **move terms** in place, updating `x_regs`/`stack`/`fr` with no frame liveness maps.
- `heap_available()` is introspection (default unbounded); `alloc_words(n)` returns a stable pointer to `n` **uninitialized** words valid only until the next `ensure_heap`/GC (default a typed `error::unsupported`).
- **`alloc_words_rooted(n, roots)` -- GC admission for term construction (the frozen root-set contract).** `alloc_words` has no admission point and no root access, so a host whose heap must be collected cannot collect while the engine builds a term (every `terms::make_*` goes through `alloc_words`) -- the measured symptom was `collections: 0` with RSS growing linearly in N. `alloc_words_rooted` is that admission point: it takes the [`RootSet`] and returns the same uninitialized-words pointer under exactly `alloc_words`' stability rule. The **default discards the roots and forwards to `alloc_words`**, so every existing implementor compiles and behaves byte-identically; a host with a real collector overrides it, runs the collector over the roots first, and writes any moved term back through `roots.x`/`roots.stack`/`roots.fr`. The **frozen contract**: the live roots are `roots.x[..roots.live_len()]`, **the whole** `roots.stack` (every Y slot of every live frame -- no frame liveness maps) and **the whole** `roots.fr` (the float-register file holds `Eterm` **term slots**, so a float register can hold a heap pointer and must be a root). `live` is only a hint: the engine hands over the whole X file and `live_len()` clamps it, so `RootSet::ALL_LIVE` (conservatively treat every register as live) is always *safe* for a copying collector. Nothing outside the root set survives: a raw `*mut Eterm` from a previous allocation is dead after the next collecting allocation.
- **The engine side of that hand-off is [`Machine::alloc_rooted`] / [`Machine::with_roots`].** `Machine::with_roots(live, f)` lends the machine's own three files as one disjoint `RootSet` (three separate `x_mut`/`stack_mut`/`fr_mut` calls cannot coexist); `Machine::alloc_rooted(ctx, n, live)` is the convenience wrapper that calls `ctx.alloc_words_rooted(n, roots)`. The single-view accessors are `Machine::{x_mut, stack_mut, fr_mut}`. (Reported, not done here: the `terms::make_*` call sites still allocate through the **unrooted** `alloc_words` -- see Handoffs.)
- `reduce(n)` is the defaulted **reduction hook** (`Ok(())`): the drive loop charges one reduction per interpreted instruction, so a host with a scheduler enforces a time slice by returning a typed error from `reduce` (the run then reports it like any other step failure -- pre-empting, never a panic). `Machine::reductions()` reads the running count and `Machine::reset_reductions()` returns it while zeroing it.
- `apply` is the general `apply`/`call_ext` hook (default forwards to `call_bif`); `apply_fun` is the `call_fun`/`call_fun2` hook (default a typed `error::unsupported` -- the engine keeps no closure registry); a concrete context enters the closure with `x(0..arity)` = arguments and `x(arity..)` = free variables.
- **`resolve_external_call` -- the cross-module call seam (the `call_ext*` and `apply`/`apply_last` route).** A host that owns loaded modules may answer a `call_ext*` or a dynamic `apply(M,F,A)` `(module, function, arity)` with `Some((callee_module, entry_label))`, and the engine then executes the callee **in the same machine** (see sec. Module contexts) instead of routing the call through the synchronous `call_bif`. The triple handed in is exactly the one `call_bif` receives (the declared import arity). `callee_module` must be the **shared** `Arc<Module>` the host loaded the module with -- the engine keeps it alive for as long as a suspended frame can return into it, and dedups contexts by `Arc::ptr_eq`; `entry_label` is the **export entry label** (`callee_module.export(function, arity)`, the label *after* `func_info`), i.e. the exact label `run_export` enters a called export at -- the engine resolves it against the callee's own label map and enters it with `x(0..arity)` = the call arguments (already in place: a `call_ext` reads them from `x(0..arity)`). The **default returns `Ok(None)`** ("I cannot run this callee in your machine"), which keeps the existing synchronous `call_bif` path as the fallback, so every existing host is byte-identical to before.
- **Contract A.8 execution-trace seam.** `TraceEvent` mirrors the oracle's `{trace,Pid,call,{M,F,Args}}` / `{trace,Pid,return_from,{M,F,A},Ret}` / `{trace,Pid,return_to,{M,F,A}}` shapes; `trace_enabled()` is the cheap gate and `trace_event` the defaulted no-op reporter. The engine **reports only** -- the host owns matching (`beam_rt`'s `PatternTable::matches`) and term building, so an unmatched function emits nothing while the engine still reports every event. Emission (`src/interpreter/trace.rs`, wired in `src/interpreter/dispatch.rs`): `Call` for the local callee on `call`/`call_only`/`call_last` and for the import on `call_ext*` (**entry only** -- the oracle emits no return events for a BIF/cross-module completion); at a live `Continuation::Address` `return`, `ReturnFrom` (the returning function, `value = x(0)`) then `ReturnTo` (the caller = the function at the return address) -- a `call_only`/`call_last` chain's `ReturnTo` names the **original** caller, never an intermediate (oracle-probed). The gate is **latched once per run** into `Machine::trace_on` at the driver entries (`interpreter::run_loop_with_map`, `jit::baseline::drive`), so the hot path pays one `bool` load and the single `trace_enabled()` vtable call happens once per run; cleared by `Machine::reset`. Emission is infallible (an unresolvable name/index is skipped, never raised), so a traced run is byte-identical to an untraced one. A **natively-executed JIT block does not trace** (only the per-instruction deopt path passes through the gated arms).
- `pub type BifHook = Box<dyn FnMut(&str, &str, u32, &[Eterm]) -> Result<Eterm>>`; `pub type ApplyHook = Box<dyn FnMut(Eterm, &[Eterm]) -> Result<Eterm>>`; `pub type ExternalResolver = Box<dyn FnMut(&str, &str, u32) -> Result<Option<(Arc<Module>, Label)>>>` -- the pluggable body of `resolve_external_call`, installable on a `MinimalContext` via `with_external_resolver`/`set_external_resolver` (unset => the trait's `Ok(None)` default).
- `MinimalContext` -- the test/embedding context: an unbounded heap (`ensure_heap` = `Ok(())`), a **pluggable BIF hook** (`new()` rejects every BIF; `with_bif_hook`/`set_bif_hook`), an **optional apply hook**, an **optional cross-module resolver** (`with_external_resolver`/`set_external_resolver`) and an **optional mailbox**. `alloc_words` hands out words from a pointer-stable **chunked** arena: requests are served as sub-slices of a 64 KiB chunk (`ARENA_CHUNK_WORDS = 8192`), a new chunk is started only when the current one cannot hold the request, and a request larger than a chunk gets a chunk of its own — so an allocation costs its payload only and the arena retains **one** `Box` per chunk, not per allocation. The chunks are boxed and never move (only the `Vec` of chunk handles grows), so a handed-out pointer stays stable, and the context **owns the heap** and must outlive every boxed term built through it. `MinimalContext` does **not** override `alloc_words_rooted`: it inherits the default (roots discarded → chunked `alloc_words`), so it stays the test/embedding heap rather than a collector.

### The mailbox seam (`src/context.rs`) -- the receive/message family's host interface
The mailbox lives in the Stage-5 runtime (`beam_process`/`beam_message`), never here: the host supplies it through this gate.
```rust
pub trait Mailbox {
    fn send_message(&mut self, to: Eterm, message: Eterm) -> Result<()>;
    fn receive_next(&mut self) -> Result<Option<Eterm>>;
    fn receive_skip(&mut self) -> Result<()>;
    fn receive_remove(&mut self) -> Result<()>;
    fn receive_reset(&mut self) -> Result<()>;
    fn receive_marker_reserve(&mut self) -> Result<Eterm>;
    fn receive_marker_bind(&mut self, marker: Eterm, reference: Eterm) -> Result<()>;
    fn receive_marker_use(&mut self, reference: Eterm) -> Result<()>;
    fn receive_marker_clear(&mut self, reference: Eterm) -> Result<()>;
}
```
- `ExecutionContext` carries the **same nine names as defaulted methods**, each returning the typed `error::unsupported("<method>")`, so `beam_rt::RuntimeContext`, a test `ModuleHost` and any other implementor compiles unchanged; `MinimalContext::with_mailbox`/`set_mailbox` install one.
- `receive_next` is the *candidate* at the current scan position (`Ok(None)` = exhausted); `receive_skip` is `loop_rec_end` (advance one); `receive_remove` is `remove_message` (unlink the matched candidate, reposition at the first); `receive_reset` is `timeout` (reposition at the first). The engine never learns *which* message is current, and **never inspects a message or a marker**: selection is the compiled code's job (the matching instructions between `loop_rec` and `loop_rec_end`), and a marker term is **opaque** (produced by `receive_marker_reserve`, handed back verbatim by `receive_marker_bind`; only a separate *reference* reaches `receive_marker_use`/`receive_marker_clear`). Installing a mailbox does **not** change the non-blocking entries: `run_export`/`run_label` still surface the typed `error::blocked` (Handoffs #1).

### The machine (`src/machine/{mod,registers,frames,catch,run,location,context,drive}.rs`)
- `pub struct Machine` -- the process-state core: the **x-register file**, the **float-register (FR) file**, the **Erlang stack**, the **call-frame stack**, the **exception catch-frame stack**, the `refc_binaries` arena (never cleared by `reset`), the running module's decoded **literal area** (`literals: Option<SharedLiteralArea>`, re-bound at a run entry and at every module-context switch, read via `Machine::literal(index: u32) -> Option<Eterm>`), the **module-context registry** (`contexts: Contexts` + `context: u32` + the `entry_literals` binding; see sec. Module contexts), and the latched A.8 gate `trace_on`. `pub const MAX_REGISTER: u32 = 1024;` (the x-file, C's `MAX_REG` bound) and `pub const MAX_FLOAT_REGISTER: u32 = 1024;` (the FR file, C's `f_reg_array`; it holds **`Eterm` term slots**).
- `Machine::new()`/`default()`/`with_max_register(u32)`; `get_fr(n) -> Option<Eterm>`/`set_fr(n, Eterm) -> Result<()>` are bounds-checked FR access (`bad_register` on overflow). `reset` refills both files in 128-byte chunks and clears the literals binding (incl. `entry_literals`), the context registry (`contexts.clear()`, `context = 0`), stacks, pending exception, resolved class atoms, `current_code`/`entry_call` and `trace_on`.
- `run.rs`: `run_export`/`run_label` (non-blocking) and `run_export_outcome`/`run_label_outcome`/`resume_outcome` (blocking-aware). `run_export` resolves `function/arity`'s export entry label, seeds `x[0..arity]` from `args`, pushes the bottom frame, runs to `return`, yields `x(0)`; `run_label` runs a raw entry label; a missing export/label is a typed error. The loop is `pub(crate) fn run_loop`/`run_loop_with_map` (`src/interpreter/dispatch.rs`).
- Introspection (read-only): `x(n) -> Option<Eterm>`, `get_fr(n)`, `frame_depth()`, `stack_depth()`, `catch_frame_depth()`, `pending_exception()`, `pending_class()`, `resumption_addresses()` (every live call frame's suspended `(func, pc)` CP slot, innermost first -- used by `build_stacktrace`).
- **Execution-position introspection (`src/machine/location.rs`)** -- the engine half of `process_info/2`'s position items. `Machine` records `current_code: Option<(u32, u32)>` (the last *interpreted* `(func, pc)`, from `step_instruction`; exact at every suspension, since a blocking `wait` is never inlined) and `entry_call: Option<(u32, u32)>` (the run's entry `(func, arity)`); `reset` clears both plus the files, stacks, pending exception and resolved class atoms. Accessors: `current_code()`/`entry_call()`, plus the oracle-shaped `current_function`/`initial_call` (`{M,F,A}`), `current_location` (`{M,F,A,[{file,F},{line,L}]}`, via the exceptions family's `stacktrace_item`) and `current_stacktrace` (the cooked list). `current_function`/`current_location`/`current_stacktrace` resolve the position against `current_module()` -- the module the machine is actually running in -- falling back to the passed entry module only when there is none (context `0`); `current_stacktrace` additionally resolves **each** resumed frame in **its own** module context (via `Machine::resumption_contexts`), because the exceptions family's `symbolic_stacktrace` builder takes a single module and would otherwise fabricate an outer frame. `initial_call` deliberately still resolves against the passed entry module (it *is* the `$initial_call`). `pub fn Machine::current_module(&self) -> Option<Arc<Module>>` (`None` = "the run's entry module the caller passed") is the accessor. Honest by construction: no instruction interpreted => `None`/`NIL`; an out-of-range `func` => typed `unsupported`; a location the module cannot name (no `file`/`line` atom) => the typed error `build_stacktrace` already reports (Handoff #2).
- `pub struct CatchFrame { pub func: u32, pub pc: u32, pub frame_index: usize }` (+ `CatchFrame::new`) -- the handler's `(func, pc)` plus the call frame that **owns** it (the one the machine unwinds to); the `pub(crate) context: u32` field (the module context the handler lives in) is stamped by `push_catch_frame` from `current_context()` and is **not** part of the public 3-arg `CatchFrame::new`. `push_catch_frame`/`pop_catch_frame` are the public accessors.
- `pub(crate) fn throw(&mut self, class, reason) -> Result<Step>` / `throw_error(reason)` / `throw_with_trace(class, reason, trace)` -- **the one uniform raise/unwind entry point** the families call (see the exception model below).
- **Module contexts (`src/machine/context.rs`).** A `call_ext*` the host resolved through `resolve_external_call` executes the callee **in this machine**, so `(func, pc)` are indices into *another* module's function table and the machine must remember which. `ModuleContext { module: Arc<Module>, labels: LabelMap }` is one enterable module (its label map built once at registration, keyed on the `Arc` address, so the per-run import cache works for a callee too); `Contexts` is the registry (`register` dedups by `Arc::ptr_eq` and returns `id = index + 1`, so a repeated/recursive call does not grow the list; `handle(id)` clones the `Arc` handle so the driver can hold it while the machine is `&mut`). Context `0` is the run's **entry** module, which the machine never owns (the driver borrows it) -- `entry_literals` records its literal area so `switch_context(0)` can restore it. `Machine::{current_context, register_context, switch_context, module_context}` are the accessors; `switch_context(id)` re-binds `literals` (a no-op when `id` is already current, so the hot path pays one integer compare) and an unregistered id is the typed `error::unsupported("run: unknown module context")`. `reset` clears the whole set, a **resume does not** (a suspended cross-module frame must still name its module).

### The `Step` protocol (`src/step.rs`)
- `pub(crate) enum Step { Next, Goto { func: u32, pc: u32 }, Enter { context: u32, func: u32, pc: u32 }, Wait { func: u32, pc: u32 }, Done }` -- the control-flow contract between the dispatch loop and the instruction families: an instruction body returns the `Step` and never mutates the loop's `func`/`pc`/context. `Next` = continue at `pc + 1`; `Goto` = jump **within the current module**; `Enter` = transfer to `(func, pc)` in module context `context` (a cross-module `call_ext*`, a cross-module `return` onto a `Continuation::Address` in another context, or a raise landing in another context's live catch frame) -- the driver switches the context and re-binds the literal area exactly here; `Done` = finish and yield `x(0)`.
- `Wait` is the **suspend** signal a `receive` with no message returns (`wait`, or `wait_timeout` with a non-zero time): the run reports `RunOutcome::Wait` and the process resumes at `(func, pc)` later. The loop folds it into a `RunOutcome`; the JIT driver and `jit_step_one` fold it into the same typed `error::blocked()`. A raise is **not** a `Step`: it stays an `Err(beam_common::BeamError)`, or the exception layer folds it into a `Step::Goto`/`Step::Enter` to a live catch handler.

### The families seam (`src/families/`)
- Every `Instr` the core loop does not execute natively is routed to `families::dispatch(machine, module, labels, instr, func, pc, ctx) -> Result<Step>`, which **routes by the instruction's own variant** to the single family that owns it — a `match instr` that compiles to a jump table on the `Instr` discriminant, so a dispatched instruction hands control straight to its owner. Family ownership is **disjoint** (each of the 76 claimed variants has exactly one owning family: `tuples`, `records`, `lists`, `funs`, `exceptions`, `floats`, `maps`, `bitstrings`, `receive`), which is what makes the route semantically identical to the original first-claim-wins probe order. The router, `dispatch` and `lists::exec` are `#[inline]`, so the per-family `match` folds into the dispatch loop's.
- Each family exposes `pub(crate) fn exec(...) -> Result<Option<Step>>`: `Ok(Some(step))` = "this family executed it", `Ok(None)` = "not this family's variant", `Err` = the family raised. A variant **no** family owns (a core-loop arm or metadata no-op) or one a family declines with `Ok(None)` (an unimplemented stub) falls to the router's last arm, which returns `error::unsupported("widened opcode not yet executed: <ops.tab name>")`, so an unclaimed opcode is diagnosable from the error alone. Every receive/message variant is claimed.

### Term helpers (`src/terms/{mod,construct,read,map,fun,number,tests}.rs`) -- the SAFETY-annotated builder/reader
`construct.rs` holds the tuple/cons/list/binary builders, `map.rs` the map builder/reader, `fun.rs` the fun builder/readers, `number.rs` the numeric helpers, `read.rs` the shared readers; constructors take the seam and allocate via `alloc_words`.
- `make_tuple(ctx, &[Eterm]) -> Result<Eterm>` (arityval header + elements; empty -> `tuple0`; > `MAX_ARITYVAL` -> `SystemLimit`); `make_cons(ctx, head, tail)` (one header-less `[CAR,CDR]` cell; the tail need not be a list); `make_list(ctx, &[Eterm])` (cons cells; empty -> `NIL`); `make_float(ctx, f64)`; `make_heap_binary(ctx, &[u8])` (heap binary/bitstring, <=64 bytes).
- `badmatch_reason(ctx, module, value) -> Result<Eterm>` (`{badmatch, Value}`, the shared raise reason; a typed `BeamError::BadMatch` when the module's atom table lacks `badmatch`).
- `make_map(ctx, &[(Eterm, Eterm)], atoms: &AtomTable) -> Result<Eterm>` -- the **general map builder**: reserves `beam_term::map::map_words_capacity(n)` words and delegates to `beam_term::map::write_map`, so it builds a map of ANY size -- a **flat** map at/below `MAP_SMALL_MAP_LIMIT` (32) distinct keys (keys in `erts_cmp_flatmap_keys` order), else a **hashmap** (HAMT) -- collapsing duplicate keys **last value wins**. `make_flatmap` serves flat-layout-only callers (`>32` pairs -> a typed `unsupported`); a safe `is_hashmap(t)` wrapper over `beam_term::is_hashmap` sits beside them.
- `make_fun(ctx, arity: u32, uniq: u64, index: u32, free: &[Eterm]) -> Result<Eterm>` (minimal local closure; M1 inlines the out-of-line fun-entry descriptor).
- Readers (no `ctx`; wrong type / out-of-range -> `BeamError::BadArg`) cover the tuple/cons/list/float/map/binary accessors plus the fun readers (`is_fun`/`fun_arity`/`fun_num_free`/`fun_uniq`/`fun_index`/`fun_free`); `map_entries` walks both map layouts.

### The JIT tier seam (`src/jit/`)
- `src/jit/mod.rs`: `Tier { Interpreter, BaselineJit, Cranelift }` (`Clone, Copy, Debug, PartialEq, Eq`; `Tier::ALL` = roster order, interpreter first), with `Tier::name() -> &'static str`, `Tier::from_name(&str) -> Option<Tier>` (unknown => `None`) and `Tier::is_available() -> bool`.
- `pub trait JitBackend` -- the seam a native tier implements: `type Compiled`; `name`/`available`; `compile(&mut self, &Module) -> Result<Self::Compiled>`; `run_compiled(&self, &Self::Compiled, machine, module, function: Atom, arity, args, ctx) -> Result<Eterm>`; and the provided `run_export` = `compile` + `run_compiled`. `run_compiled` is `&self` because the artifact is **caller-owned** (one compiled module runs any number of times on fresh `Machine`s). The interpreter is deliberately **not** a `JitBackend` (nothing to compile).
- `available_tiers()`: exactly `["interpreter", "baseline-jit"]`, plus `"jit-cranelift"` when the `jit-cranelift` feature is on; interpreter always first.
- `Machine::run_with_tier(..., Tier)` (`src/machine/run.rs`): `Interpreter` -> `run_export`; `BaselineJit` -> `crate::jit::cache::run_baseline_cached`; `Cranelift` -> `crate::jit::run_cranelift` when the feature is on, else the typed `error::unsupported("jit-cranelift tier not built")` -- never a panic or silent fallback. These are the **non-blocking** entries (`Result<Eterm>`; a suspend folds to `error::blocked()`).
- `Machine::run_export_outcome_with_tier` / `Machine::run_label_outcome_with_tier` (`src/machine/run.rs`) -- the **outcome-aware** tier entries a host routes a process through: `Result<RunOutcome>` (`Wait` included), so a blocking `receive` under any tier is *reported*, never folded into an error. `Interpreter` -> `run_export_outcome`/`run_label_outcome`; `BaselineJit` -> `run_baseline_cached_outcome`/`run_baseline_cached_label_outcome` over the driver `run_native_outcome`; `Cranelift` -> `run_cranelift_outcome` (feature-off = the typed error). A suspend crosses the block ABI as a `WAIT_BIT` word (`jit::baseline::{encode_wait,decode_wait,WAIT_BIT}`); the non-blocking entries above are unchanged (Handoff #9).
- Feature **`jit-cranelift` (default OFF)** gates the optional Cranelift deps (off => the crate carries **no Cranelift dependency at all**); `jit-beamasm` aliases the baseline tier.
- `src/jit/tiering.rs`: `TierPolicy { baseline_threshold, hot_threshold }` models sec. F's *interpret -> baseline -> hot* escalation -- `select(executions) -> Tier` (`Default` = baseline `1`, hot `10_000`; hot -> `Cranelift` when compiled in, else the hottest available); a policy only (see Design Decisions).
- `src/jit/cache.rs` -- the **cross-run compiled-block cache**: `module_fingerprint(&Module) -> u64` hashes the module's **decoded IR content** (deterministic, non-randomized, **never a pointer**), and `ModuleKey { name, fingerprint }` (`name = Module::atom_name(Module::name)`) stops same-named/different-content collisions. `CodeCache` (`get_or_compile`/`run_export`/`contains`/`len`/`clear`) **owns** each `CompiledModule` (a hit recompiles nothing); it is per-thread (`thread_local! CODE_CACHE`; `mmap` pointers make the artifacts `!Send`/`!Sync`) and backs `run_baseline_cached`/`run_baseline_cached_outcome` + the `baseline_cache_*` accessors. `baseline_code_map(&Module)` (and `CodeCache::code_map`) exposes the **real** generated ranges to a host (e.g. `beam_rt`'s `+JPperf` perf map): `CodeRegion { start, size, name }` with `start` an actual `CompiledModule::entry`, `size` to the next block entry and `name` = `<module>:<function>/<arity>/<pc>` -- never fabricated.
- `src/jit/emitter/*` -- the `#[allow(unsafe_code)]` x86-64 encoder + executable `CodeBuffer` both tiers build on: label/bind/seal, the crate's only `mmap` RW -> `mprotect` RX on `seal` (never RWX, `munmap` in `Drop`), System V AMD64.
- `src/jit/baseline/` -- the **native baseline backend** (`BaselineJit`, a zero-sized `JitBackend`, plus `CompiledModule`, the driver, `runtime.rs`, `emit/*`). Block ABI: `extern "C" fn(*mut JitRuntime) -> i64` returning `encode_target(func, pc) = func<<32 | pc` / `HALT = -1` / `ERROR = -2` (a propagating `BeamError` in `rt.error`); `JitRuntime` (`#[repr(C)]`, `RUNTIME_XREGS_DISP = 8`) carries `machine`, `x_regs`, `module`, `labels`, `ctx`, `error`, and generated code loads **only** `x_regs`. `jit_step_one` *is* `Machine::step_instruction` folded into the block ABI and `jit_tail_call(rt, target, deallocate)` is `Machine::pop_frame_checked` folded into it, so a tier is interpreter-identical for every supported opcode. A usage-weighted per-block register picker caches the five most-touched x-registers in `r12`-`r15`+`rbp` (`emit/regalloc.rs`); residency is block-fixed and the prologue/epilogue spill the residents at every block exit, so a helper/GC sees the interpreter's exact root set. Blocks are linked at `seal` (a `CodeLabel` reserved per non-empty block before emitting), so a taken branch to a compiled successor is a `rel32` fixup -- including both **local tail calls**, `call_only{Dest}` and `call_last{Dest,Deallocate}` (through `Linker::emit_tail_exit`); an unlinkable exit returns to the driver for one interpreter step. The driver (`run_compiled`) loops on a flat `[func][pc]` block index (`HALT -> finish()`, `ERROR -> Err(rt.error)`), else takes one `step_instruction`; `run_native_outcome` returns `RunOutcome` (a `WAIT_BIT` word / `Step::Wait` -> `RunOutcome::Wait{func,pc}`). The inline set is the metadata no-ops, `Move`/`Swap`, `Jump`, the word-level `Test` subset, all-immediate `SelectVal`, the guarded small-int `'+'/2`/`'-'/2`/`'*'/2` `gc_bif` fast paths, the eight comparison BIFs, the aggregate readers and the local tail calls; **everything else deopts** (a `Y`/`Literal` operand, an out-of-range register, a boxed-term `Test`, a non-immediate `SelectVal` case, `PutTuple2`, `BsTestTail`, `FuncInfo`, an unlinkable tail target, the `call_ext_*`/`call`/`apply`/`call_fun`/exception surface), so the interpreter's exact error surfaces stand.
  - `src/jit/cranelift/*` (`#[cfg(feature = "jit-cranelift")]`) -- the **optional Cranelift hot backend**: one Cranelift function per IR `Function` with the same block ABI and the entry `pc` baked in, inlining the **same cheap set as the baseline** where the two agree exactly (the metadata no-ops, `move`, `swap`, `jump`/`call_only`, the word-level `test` subset, the small-int `'±*'/2` and comparison BIFs, `select_val`, `select_tuple_arity`, and the tuple/list reads) and deopting the rest to `jit_step_one`; a `swap` reads both slots to SSA values before storing them exchanged (exact under aliasing) and `call_only` lowers like a `jump` (`call_last`'s frame pop stays on the helper -- it is Rust-side `Machine` state). `report.rs` exposes a `CodegenReport`; `CompiledFunctions` exposes `inlined_swap_count()`/`inlined_tail_call_count()` alongside the other inline-set observations. `CompiledFunctions` owns the `JITModule`; `CompiledEntries` enters a function **only at its entry `pc`**.

### Error interop (`src/error.rs`)
- Engine error constructors over `beam_common::BeamError` (never a crate-local enum): `unsupported(what: &str)` (a `Raise` with reason atom `unsupported_opcode: <what>`), `bad_register(n: u32)` (`BadArg`), `unknown_label(Label)` (`BadArg`), and `blocked()` = `unsupported("run: process blocked (no message available)")` -- the single definition of the typed error the **non-blocking** entries surface for a `receive` that would suspend.
- **`Step::Enter` is interpreter-only.** A `call_ext*` resolved through `resolve_external_call` is not in the JIT inline set (the `call_ext_*` surface always deopts), and both `jit_step_one` (`src/jit/baseline/runtime.rs`) and the baseline driver's `Step` match (`src/jit/baseline/mod.rs`) return the typed `unsupported("jit: module context switch outside the interpreter driver")` for a `Step::Enter` -- never a silently wrong block. So the seam works on `Tier::Interpreter` and is an honest typed error on the native tiers.

## Execution model (frozen semantics -- reproduce, don't reinvent)
The binding semantics in brief; the exhaustive per-instruction/per-operand/per-family detail (with the `ops.tab`/`beam_emu.c` references and every edge case) is in `INSTRUCTION_SURFACE.md`.
- **Registers, stack & frames.** `x[0..MAX_REGISTER)`, args in `x[0..arity)`, result in `x(0)`, the root set `x[0..live)`, plus the FR file; `allocate*` pushes a *continuation-pointer slot* then `stack_need` Y-slots (`y(k)` = the slot after the CP slot).
  The CP slot is a typed `Continuation` (`Address{func,pc,context}` or `Halt`), so a continuation is exact even for a frame-less leaf that stores it in its caller's frame; `deallocate`/`call_last`/`call_ext_last` pop the frame (Y slots **and** CP slot) and the bottom `Halt` yields `x(0)`.
  A tail call pops its frame **after** the callee succeeds, so a raising callee unwinds from the live frame with its own reason, never a frame-size artifact.
- **The dispatch loop** (`src/machine/drive.rs` + `src/interpreter/`) owns the `(func, pc)` position and the **module context** those indices belong to, folds every `Step` back into that position, re-borrows the active module per iteration, and re-binds the literal area only on a `Step::Enter` into a different context.
  `step_instruction` is shared by the interpreter loop and the JIT deopt helper, and every opcode the engine executes has its own typed IR variant (the residual `Instr::Generic` sentinel returns a named typed error).
- **The instruction surface.** Core-loop arms (the metadata no-ops, `func_info`, `move`/`swap`/`init_yregs`, `test`/`select_val`, the call/allocate/trim/return and `gc_bif`/`bif0`/`bif` control ops, the eight native-record variants) plus the opcodes the nine families claim; a `gc_bif`/`bif` error with a live `fail` label is a guard failure and with `NO_FAIL` a raise, while `bif0`/`call_ext*` carry no fail label, so every error there is a raise.
- **Raising and the catch-frame model.** `try`/`catch` push a `CatchFrame` (handler `(func, pc)` + the owning call frame + its module context); a raise records `pending_exception` and lands in the **innermost** live frame with C's `handle_error` register convention (`x(0) = THE_NON_VALUE`, `x(1) = reason`, `x(2) = trace`, `x(3) = class atom`), unwinding the call-frame stack down to it, and reports `Step::Goto` (same context) or `Step::Enter` (another context); with no live frame, or an unresolvable class atom, it stays a typed `Err(BeamError::Raise)` -- never a panic.
  A raise *reads* the innermost entry but never pops it; the handler opcode (`try_case`/`try_end`/`catch_end`) consumes exactly one entry.
  The class atoms come from the running module's atom table and are never substituted by a *different* atom.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** -- no crate-local error enum; an unsupported opcode/operand is a documented `BeamError` (`error::unsupported`), and the engine **never panics, never `unwrap()`s loaded data, never produces a wrong result**.
- **Frozen term layout**: term construction/inspection is **only** `beam_term` (`use beam_term::prelude::*;`); comparison uses `beam_term::{cmp, eq, cmp_arith}` -- the engine never reimplements term ordering.
- The crate is `#![deny(unsafe_code)]` (and `#![warn(missing_docs)]`); `unsafe` is confined to explicitly-marked modules: `src/predicates.rs`, `src/terms.rs` (the raw-heap construction/reading point behind `alloc_words`), `src/families/bitstrings/raw.rs` (`ErlSubBits`/`ErlHeapBits` accessors + the off-heap refc payload), `src/families/records/raw.rs` (frozen-layout record accessors), `src/jit/emitter/mod.rs` (the x86-64 encoder and the crate's **only executable-memory mapping**), `src/jit/baseline/{mod,runtime}.rs` + `src/jit/baseline/emit/*` (reconstructs `&mut Machine`/`&mut dyn ExecutionContext`/`&Module`/`&LabelMap` from `JitRuntime`'s live, unaliased pointers and calls a block entry as a transmuted `extern "C" fn`), and -- feature-gated -- `src/jit/cranelift/mod.rs`. Every `unsafe` block carries a `// SAFETY:` rationale; registers/stack stay safe `Vec<Eterm>` indexing.
- **Deps:** `beam_common`, `beam_term`, `beam_loader`, `beam_alloc` (+ `libc`); **`cranelift-*` are optional** behind the `jit-cranelift` feature (default off). The `beam_alloc` edge (wave 0 -> wave 4, downward/legal) exists for the off-heap refc-binary payloads `bs_init_writable`/`append` need (`Machine::alloc_refc_binary`, held as `Machine::refc_binaries`, **never cleared by `reset`**).
- **Files ~1000 lines**, split by responsibility into directory modules; a legitimately long file (`tests/opcodes.rs`) documents why. Licensing Apache-2.0.

## Known Issues / Intentional M1 gaps
The headline M1 gaps; the full list, each with its ground-truth detail, is in `INSTRUCTION_SURFACE.md`.
- **No garbage collection on the ordinary path.** `MinimalContext` has an unbounded, never-freed chunked arena and `ensure_heap_full` is a no-op there.
  The rooted allocation hook (`alloc_words_rooted` / `Machine::alloc_rooted`) exists and is tested, but the `terms::make_*` call sites still allocate through the unrooted `alloc_words`, so nothing in an ordinary run triggers a collection (Handoff #11).
- **A captured stacktrace is engine-derived** (a non-`NIL` raw trace is substituted by a symbolic trace from the machine's live frames, Handoff #3), and **nameable atoms are required**: `catch_end` needs `EXIT` and `raise_bif_error` can only raise an error it can name -- neither path ever substitutes a *different* atom.
- **Records.** The whole native-record set executes, including `PutRecord`'s create form for the running module's own records; only a *foreign*-module record id is a typed `unsupported` (Handoff #4).
- **Bitstrings.** `bs_init_writable`/`append` is a copy-rebuild (`HANDOFF_bs_init_writable.md`), a non-first `append`/`private_append` segment is a typed `unsupported`, and every other bitstring gap is a typed result, never a wrong value.
- **Snapshot-style divergences are typed errors, never wrong results:** map enumeration order is storage order (visible only in `term_to_binary` byte comparison), a map read with `fail == NO_FAIL` is `unsupported`, and native records are not enabled in this toolchain (so `put_record`'s create form is structurally, not oracle, verified).
- **Compiled arithmetic is oracle-exact on overflow** (`+ - * div rem` promote to exact bignums, and an out-of-range integer operand becomes an exact bignum).
- **No reductions / preemption / scheduler** (Stage 5, `beam_process`): `run_*` executes to the function's `return`, and stack growth is an unbounded `Vec`.
- **`apply_fun` must reproduce `call_fun`'s x-register order: arguments first, free variables after** (C fills `reg[i] = args[i]` then `reg[i + arity] = funp->env[i]`), never `free ++ args`.

## Handoffs (opcodes/capabilities this crate cannot close alone)
The execution gaps the standard compiler emits for real OTP modules, plus the host/foundation gaps behind a compiled-vs-oracle divergence; each names the owning node.
1. **Receive/message + cross-module suspension (owner `beam_rt`).** Implement the nine `Mailbox` methods (each defaulted here to a typed `unsupported`) over `beam_message::Queue` + a marker/scan-position table, map `RunOutcome::Wait` onto `beam_process::RunOutcome::Wait`, re-enter via `Machine::resume_outcome`, and drive a host **timer** for a non-zero `after`. A.9's differential coverage is boot/version observability only: the boot script stops at instruction 16, `{apply,{application,load,[{application,stdlib,Props}]}}`, with a structured `exit` reason (see Handoff #12 for the outstanding blocker). The exact call sites that must move to a rooted allocation (each has the machine in scope one frame up, which is where the hand-off belongs):
    - `src/terms/construct.rs:47` (`make_tuple`), `:68` (`make_cons`), `:136` (`make_heap_binary`);
    - `src/terms/number.rs:34` (`make_float`), `:63` (`make_integer`);
    - `src/terms/map.rs:46` (`make_flatmap`), `:72` (`make_map`);
    - `src/terms/fun.rs:75` (`make_fun`).
   These functions take `&mut dyn ExecutionContext` (never the `Machine`), so closing the loop needs either (a) threading a `&mut RootSet`/`&mut Machine` into them (signature change owned by the `terms`/families owners), or (b) having the allocating instruction arms call `Machine::alloc_rooted(ctx, n, live)` (the `live` count is the instruction's own `live` operand, so `test_heap`/`allocate_heap`/`gc_bif`/`put_tuple2`/`bs_create_bin` arms are the natural hosts). The bitstring and record builders allocate the same way and must move with them:
    - `src/families/bitstrings/raw.rs:184` (sub-bits), `:227` (bignum), `:272` (heap bits), `:326` and `:360` (refc bits);
    - `src/families/records/mod.rs:834` and `:965` (record block builders).
   Until these move, `gc_stats()`-style counters driven by `alloc_words` stay at zero, so an ordinary run still does not collect. Host side: `beam_rt` must override `alloc_words_rooted` to run `beam_gc` over `roots` and write moved terms back (the default discards the roots).
   - **The `ensure_heap` admission point now carries the FR file** (`Machine::ensure_heap`, `src/machine/frames.rs`): it hands the whole `RootSet` (x + stack + fr) to the defaulted `ExecutionContext::ensure_heap_full`, whose default forwards to the frozen narrow `ensure_heap(heap_need, live, x_regs, stack)` with the FR file discarded -- so a host predating the full door is byte-identical, and a host with a collector now sees every live root at the primary admission point (`tests/gc_roots.rs::the_ensure_heap_admission_point_hands_over_the_fr_file`, unit `machine::frames::tests::ensure_heap_hands_over_the_fr_file_at_the_full_root_door`). Only the **term-construction** path (`alloc_words`, above) still lacks roots.
12. **Closure entry argument order (owner `beam_rt`).**
   `RuntimeContext::local_fun_target` (`../beam_rt/src/context/mod.rs`) builds the vector a compiled local-closure body is entered with as **free variables then arguments** (`combined = fun_free(fun) ++ args`).
   ERTS enters with **arguments first, free variables after**: `erts/emulator/beam/beam_common.c:1631-1633` (`for (i = 0; i < fun_num_free(funp); i++) reg[i + arity] = funp->env[i];`) and the compiled body's own register layout -- `erlc -S` of `ae(Name) -> lists:foreach(fun({K,V}) -> {Name,K,V} end, [{a,1},{b,2}])` gives the lambda body `{function,'-ae/1-fun-0-',2,...}` with `{put_tuple2,{x,0},{list,[{x,1},{x,0}]}}`, i.e. the `{K,V}` argument in `x(0)` and the captured `Name` in `x(1)`, exactly this crate's `ExecutionContext::apply_fun` contract.
   A closure with **zero** capture is unaffected (which is why `lists:foreach(fun(X) -> ... end, L)` works), but any closure that captures a value *and* destructures its argument breaks: the oracle returns `ok` for `ae:ae(7)` while `beam_rt` raises `error:function_clause`.
   That is the failure that stops the A.9 boot chain inside `application_controller:add_env/2` (`lists:foreach(fun({K,V}) -> ets:insert(ac_tab, {{env,Name,K},V}) end, Env)`), so the boot script still halts at instruction 16, `{apply,{application,load,[{application,stdlib,Props}]}}`, with a structured `exit` reason (a `{noproc,{gen_server,call,...}}`-shaped reason -- no live registered `application_controller`).
   Fix is one line in `beam_rt` (arguments first, free variables after); the engine's own seam is correct.
