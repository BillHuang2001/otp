# `src/nif/` — NIF host layer (contract A.3)

## Intent
The **NIF C ABI host half**: every `enif_*` function a NIF `.so` imports, the `NifHost`/`NifEnv` seam those bodies are written against, the dynamic NIF loader and the `erlang:load_nif/2` load-time validation contract — over the frozen `nif::term`/`nif::types`/`nif::api` shapes owned by the crate root (`../CONTEXT.md` → *Frozen layout table*).
The boundary's *shape* is the parent's contract; its *behaviour* is this node's.

Ground truth (read-only, never modify): `erts/emulator/beam/erl_nif.h`, `erl_nif_api_funcs.h`, `erl_drv_nif.h`, `erts/emulator/beam/erl_nif.c`, and `erts/lib_src/common/erl_printf_format.c` for the `*printf` subset (paths are repo-root relative).

## The host seam (`nif::host`) — the runtime services behind the `enif_*` layer
The *internal* boundary the `enif_*` bodies are written against (not part of the C ABI; `nif::host.rs`).
- `pub trait NifHost` — **required** `heap() -> &mut beam_alloc::Heap`, `intern_atom(&str) -> Option<Eterm>`, `atom_name(Eterm) -> Option<String>`; **defaulted** (default = unsupported): `self_pid`, `term_to_binary`, `binary_to_term`, `binary_to_term_used`, `make_ref`, `existing_atom`, `atom_table`, `priv_data`, `system_info`, `unique_integer`, `consume_timeslice`, `is_process_alive`, `is_port_alive`, `is_current_process_alive`, `send`, `port_command`, `whereis_pid`, `whereis_port`, `monitor_process`, `monitor_process_result`, `demonitor_process`, `select`, `nif_yield_point`, `alloc_env`, `free_env`, `make_copy`, `dynamic_resource_call`, and `schedule_nif` — a **legacy** hook `enif_schedule_nif` no longer consults (it takes no `argv`, so it structurally cannot run a continuation; kept for source compatibility only). The ETF hooks give `beam_abi` **no** `beam_codec` edge.
  - `binary_to_term_used(&mut self, bytes: &[u8]) -> Option<(Eterm, usize)>` — the consumed-byte decode: the term plus the byte count `enif_binary_to_term` answers. Its **default forwards to `binary_to_term` and reports `bytes.len()`**, so a host that cannot report a count keeps the strict-whole-slice behaviour; `enif_binary_to_term` prefers it.
  - `monitor_process_result(&mut self, pid: Eterm) -> Option<NifMonitorResult>` — the three-way arming outcome (`Armed(Eterm)` with the internal reference, `NotAlive`, `NoDownCallback`); `None` means unsupported and `enif_monitor_process` falls back to the legacy `monitor_process` (whose `Some` counts as `Armed`, so no existing host changes behaviour).
- `pub struct NifEnv` — the env behind the C-facing opaque `*mut ErlNifEnv`: `new(&mut dyn NifHost)`, `new_typed::<H: NifHost + 'static>` (+ `host_as`/`with_host_as`), the **`&self`-receiver** accessors `host()`/`with_host(f)`/`heap()`/`as_ptr()`, `unsafe from_opaque(*mut ErlNifEnv) -> Option<&NifEnv>` (a **shared** reference, as `DriverEnv::from_port`), the `Cell<Option<Eterm>>` pending-exception slot, the pending-exception slot (`pending_exception`/`set_exception`/`clear`), and a **bounded per-call atom record** (`record_atom`; read back by `recorded_atom_name`/`recorded_atom`; `MAX_RECORDED_ATOMS = 256`, first-wins dedupe) — atoms commit lazily, so `NifHost::atom_name` (committed table only) cannot see one interned earlier in the *same* call. Re-exported as `beam_abi::{NifEnv, NifHost}`. `enif_clear_env` does **not** touch the exception slot (as the C, `erl_nif.c:700-723`).
- **Thread-local current-host stack + per-call atom record:** `NifEnv::new` pushes the host and its `Rc<RefCell<Vec<(Eterm, String)>>>` record; `Drop` pops exactly its own entry (an out-of-order drop restores the enclosing host). Readers `with_current_host<R>(f) -> Option<R>` (behind env-less `enif_alloc_env`) and `current_recorded_atom_name(atom) -> Option<String>` (innermost env wins; behind every env-less name resolution). Sound: `NifEnv` is `!Clone`/`!Send` (raw host pointer, never moved across threads), and the `Rc<RefCell<…>>` record stays readable while the env is borrowed — no `unsafe`, no `&mut` aliasing.
- **The thread-env factory** (`src/nif/thread_env.rs`, re-exported at `nif::{ThreadEnvHostFactory, install_thread_env_factory, clear_thread_env_factory, with_thread_env_host}`) — how a thread that is **not** inside a NIF call (an `enif_thread_create`d worker) reaches a real host. `pub trait ThreadEnvHostFactory: Send + Sync + 'static { fn open(&self) -> Option<Box<dyn NifHost>>; }` in a `Mutex<Option<…>>` (last-install-wins, a **poisoned lock yields `None`/`false` and never panics**), plus a **thread-local cache** of the host `open()` returned (a `NifHost` is `!Send`, so each thread opens its own; cross-thread sharing goes through the factory's own `Send + Sync` handles) stamped with a **global generation** bumped by every `install`/`clear`, so a superseded factory's host is dropped and re-opened instead of leaking into the next test. `with_thread_env_host<R>(f: impl FnOnce(&mut dyn NifHost) -> R) -> Option<R>` is the accessor (`None` with no factory, or when `open()` declines). `clear_thread_env_factory()` is the explicit teardown.

## `enif_*` functions (`src/nif/enif/`)
Every one is `#[no_mangle] pub unsafe extern "C"` with the exact signature of its matching `nif::api` field, driving the `NifEnv`/`NifHost` seam (`beam_term`, `beam_alloc::Heap`, `NifHost::intern_atom`). By family:
- **`mem`** — libc-backed `enif_alloc`/`enif_free`/`enif_realloc`; the binary family (`enif_alloc_binary`, `enif_realloc_binary`, `enif_release_binary`, `enif_make_new_binary`, `enif_make_binary`, `enif_make_sub_binary`, `enif_inspect_binary`, `enif_inspect_iolist_as_binary`); the ETF pair `enif_term_to_binary`/`enif_binary_to_term` via `NifHost` (the C's failure `0` without the hook). Binary I/O shapes are **oracle-exact** (`erl_nif.c`, `erts_inspect_iolist_as_binary`, `erts_copy_bits_fwd`, `erts_build_sub_bitstring`):
  - `enif_binary_to_term(env, data, len, &term, opts)` answers the **consumed byte count** of the first term (`erts_binary_to_term`'s `used`, the C's `return bp - data`), not `len`: a `term_to_binary(T) ++ junk` image answers `size_of(T)` and writes `T`; only a decode failure answers `0`. `opts` may be `0` or `ERL_NIF_BIN2TERM_SAFE` — anything else answers `0` **without** decoding (the C's `switch`). A null `data`/`term` answers `0`. The host seam is `NifHost::binary_to_term_used`; the term is written to `*term` only on success (the C also leaves its internal non-value there on failure, so a NIF must not read the operand after a `0` either way).
  - `enif_inspect_iolist_as_binary` — a byte integer only in head (CAR) position, a proper list, a byte-sized binary/bitstring, or the empty list; `[]`/`nil` **succeeds** (`size = 0`, non-NULL dummy `data` = `(unsigned char*)&bin->data`, `erl_nif.c:1400`); a bare integer, a non-nil non-list tail (`[1|2]`), a non-byte integer (`256`, `-1`) or a non-byte-sized bitstring (`<<1:7>>`) are **failures → `0`** (`size = 0`, `data = -1`).
  - `enif_inspect_binary` — a bit-offset, byte-sized bitstring ok (`TAIL_BITS(size) == 0` ⇒ `1`); an unaligned start is copied by `copy_bits_fwd` and handed back **owned** (null `__spare__[0]`, freed once by `enif_release_binary`).
  - `enif_make_sub_binary` — windows **any bitstring by bits**: offset `source_bit_offset + pos*8`, span `size` bits; `size == 0` ⇒ `<<>>` for any `pos`; ≤ `ERL_ONHEAP_BITS_LIMIT` (512) bits copies into an `ErlHeapBits`, above it an `ErlSubBits` window; `badarg` only for a non-bitstring source or `pos*8 + size*8 > source_bit_size` with `size > 0` (`checked_mul`).
- **`get`** — `enif_get_int/uint/long/ulong/double/list_cell/tuple/list_length/string/string_length/atom/atom_length`; the `ERL_NIF_UTF8` arm of `enif_get_string` is **byte-faithful** to `erts_unicode_list_to_buf` (`utils.c:2862-2942`): byte budget `len-1`, char budget `len`, an incompletely fitting multibyte char dropped **whole** — `buf[written] = '\0'` + negative `-(written+1)`, else `buf[0] = '\0'` + `0`; `enif_get_string_length` agrees.
- **`make`** — `enif_make_int/uint/long/ulong/double/atom(_len)/new_atom(_len)/existing_atom(_len)/string(_len)/list_cell/reverse_list/ref/tuple_from_array/list_from_array`; the four make-atom entry points **record** each interned atom on the env, `enif_make_existing_atom(_len)` consults that record first then `NifHost::existing_atom` (else `0` with `*atom` untouched); `enif_make_ref` raises `badarg` when `NifHost::make_ref` is absent.
- **`map`** — `enif_get_map_size`, `enif_get_map_value`, `enif_make_new_map`, `enif_make_map_from_arrays`, `enif_make_map_put`, `enif_make_map_update`, `enif_make_map_remove`. `enif_make_map_from_arrays` reproduces `erts_map_from_ks_and_vs`'s **duplicate-key refusal** (`erl_map.c`: `THE_NON_VALUE` on a duplicate): a duplicate anywhere in the key array writes `Eterm::non_value()` into `*map_out` (nothing when that pointer is null) and answers `0`; only a duplicate-free set builds the map and answers `1`. The basis is **`=:=`** (`compare::eq` — the flat-map writer's `erts_cmp(exact)` and the hash arm's `reject_dupkeys`), so `1` and `1.0` are **distinct** keys on both sides of the `MAP_SMALL_MAP_LIMIT = 32` flat/hash switch. The check is an all-pairs scan run **before** any allocation, and the no-duplicate path is unchanged (same content, same key order).
- **`pred`** — `enif_is_*`, `enif_compare`, `enif_is_identical`, `enif_hash`, `enif_term_type`, `enif_term_size`. `enif_compare` is the C's `CMP` = `erts_cmp(a, b, 0, 0)` (**arithmetic** mode: `enif_compare(1, 1.0) == 0`) and orders an atom pair by **name** (`erts_cmp_atoms`, `erl_utils.h:193-215`), each name resolved *current env atom record → `NifHost::atom_name` → raw atom index* — which is what makes in-call `enif_make_atom` atoms resolvable. `enif_is_identical` = `EQ` (exact mode); `enif_hash` = PHASH2 over the term word. Atom pairs are resolved at **top level** only — see *Known gaps*.
- **`proc`** — `enif_self`, `enif_get_local_pid`, `enif_get_local_port`, `enif_set_pid_undefined`, `enif_is_pid_undefined`, `enif_get_atom_cache_index`, `enif_max_atom_cache_index` (all `#[no_mangle]` + populated). `enif_make_pid`/`enif_compare_pids` are **not** slots and must not become any: on LP64 both are header macros (`erl_nif_api_funcs.h:655-658`, `#ifndef enif_make_pid` / `#define`) that expand inline next to `enif_compare`, so no NIF ever imports them, and the oracle's `beam.smp` exports exactly the same **176** `enif_*` dynamic symbols (`nm -D`) — adding one would break `tests/abi_conformance.rs`'s header-derivation set equality.
- **`process`** — `enif_monitor_process`/`demonitor_process`/`compare_monitors`/`make_monitor_term`, `enif_is_process_alive`/`is_current_process_alive`/`is_port_alive`, `enif_send`, `enif_port_command`, `enif_whereis_pid`/`whereis_port` (0 when the `NifHost` hook is absent), `enif_schedule_nif`. `enif_monitor_process` reproduces the C's three codes **in the C's order**: a resource type opened **without** a `down` callback answers `-1` *before* the pid is even looked at (`resources::resource_type_has_down` — crate-local knowledge, so `-1` is reachable with no host); a null/`undefined` target answers `1`; a monitor that could not be armed because the target is already dead answers `1`; success writes **the whole reference block** into the 32-byte `ErlNifMonitor` (`REF_THING_BYTES` = 32 = the entire payload: this tree's frozen 4-word `[header, node, serial, id]` internal-reference block, whose identity is the id word — so two monitors armed from different references stay distinct) and answers `0`; a caller-supplied C-layout 3-word `ErtsORefThing` is accepted at its own width with a zeroed tail (its packed `num[]` ids are inside the words copied), and any other header arity is refused (`ref_block_of`'s never-over-read rule). The arming host reports the outcome through `NifHost::monitor_process_result` ⇒ `NifMonitorResult::{Armed, NotAlive, NoDownCallback}`; an `Armed` term that is not an internal reference is refused (`1`) rather than stored. A successful arm also records the binding in the crate's monitor tree (`super::resources::record_monitor`, the C's `erts_monitor_tree_insert`, `erl_nif.c:3983-3986`, done before the block is stored) so `down` can be delivered later; a foreign `obj` (not one of this crate's live payload pointers) or a type without `down` is simply not tracked, and the answer stays `0` either way. `enif_demonitor_process` consults **its own tree first** (`super::resources::take_monitor`) and answers `0` when that removal succeeded, else falls back to `NifHost::demonitor_process` through the rebuilt reference term; `1` when neither found it (already gone / target dead) — the C's `:4043-4051`.
- **`schedule`** (`src/nif/enif/schedule.rs`, no `enif_*` slot of its own — `process` owns `enif_schedule_nif`) — the continuation trampoline. An explicit `Outcome { Value(Eterm), Reschedule(Continuation), Raised }` over a thread-local pending-continuation slot and nesting counter: a **nested** schedule records the continuation and answers the C's `THE_NON_VALUE` (`0`), the **outermost** call loops to `Value`/`Raised`, so a long self-rescheduling chain never grows the Rust stack. The refusals stay the C's, in the C's order (`argc > MAX_ARG` (255) first, then `argc < 0`, then a `flags` bit outside `ERL_NIF_DIRTY_JOB_{CPU,IO}_BOUND`, then null/non-UTF-8 `fun_name`, then null `fptr`, plus a null `argv` with `argc > 0`), each answering the `badarg` term the host turns into a raise. `argv` is passed straight to `fptr` — **nothing is copied**, the arguments live on the caller's env heap for the whole trampoline — and `fun_name` is **interned and never resolved** (measured `sched_ghost_name(99)` → `{ghost,99}`). `NifHost::nif_yield_point(flags)` runs once per iteration (the fair-preemption seam), and a thread-local dirty marker makes `enif_thread_type()` answer `ERL_NIF_THR_DIRTY_CPU_SCHEDULER` (2) / `..._IO` (3) for a dirty-flagged continuation — the thread identity stays the caller's, because no dirty pool exists here. A raise inside a continuation is **terminal** (checked before a recorded reschedule), leaves the pending exception on the env, and is attributed to the **scheduling** NIF with the original MFA/argv (the engine owns the stacktrace head, so no frame is fabricated this side of the seam). Substitution: the outer call returns the continuation's **value** where the C returns the `THE_NON_VALUE` trap marker — the Erlang-visible result is identical because the emulator only re-runs the trap.
- **`exception`** — `enif_make_badarg`, `enif_raise_exception`, `enif_has_pending_exception`, `enif_clear_env`.
- **`threads`** — the 34 mutex/cond/rwlock/tsd/thread slots: cast-and-forward facades over `crate::sync`; only `enif_thread_type` and `enif_thread_name`/`erl_drv_thread_name` (the `*_name` accessors) do more.
- **`ioq`** — `enif_ioq_create`/`destroy`/`enq_binary`/`enqv`/`size`/`deq`/`peek`/`peek_head` + `enif_inspect_iovec`/`enif_free_iovec`; a `VecDeque` of buffers preserving the vector *count* rule (one `SysIOVec` per non-empty enqueued buffer).
- **`mapiter`** — the seven `enif_map_iterator_*` slots over the frozen 56-byte `ErlNifMapIterator`, in the map's **storage order** (`hashmap_iterator_next`). The hash arm's `ErtsDynamicWStack` is a boxed pair list; `get_pair` answers the same sequence.
- **`time`** — `enif_monotonic_time`/`enif_time_offset`/`enif_convert_time_unit`/`enif_now_time`/`enif_cpu_time`/`enif_system_info`/`enif_getenv`/`enif_make_unique_integer`/`enif_consume_timeslice`/`enif_dlopen`/`enif_dlsym`; the monotonic-time / time-offset relation is reproduced and covered by Rust unit tests in `src/nif/enif/time.rs` (`monotonic_time_is_monotone_and_unit_consistent`, `monotonic_plus_offset_is_wall_time`) — there is no `erl`-oracle pin for `enif_time_offset/1`; `enif_system_info` (no env) reaches the host via `with_current_host` and prefers `NifHost::system_info`; `enif_make_unique_integer` prefers `NifHost::unique_integer`.
- **`resources`** — the eleven slots over a crate-internal type registry + a real refcounted allocation (`enif_open_resource_type`, `_x`, `init_resource_type`, `alloc_resource`, `release_resource`, `keep_resource`, `make_resource`, `make_resource_binary`, `get_resource`, `sizeof_resource`, `dynamic_resource_call`). A resource *term* is a reference **minted here** (`make_ref`, `None`), recorded by its **reference identity** — one private `term_key` helper (`TermKey::Ref(internal_ref_id)` for a frozen internal reference, `TermKey::Word` for every other term shape) drives both binding and lookup, so a `copy_struct` copy of a minted term resolves to the same object exactly as the C's pointer-identified magic ref does, and `ResourceRef` keeps the minted word so the release seam still enumerates what was minted. An exporting call (`enif_make_resource`/`enif_make_resource_binary`) takes **its own reference** as the C magic ref does, so a released-but-term-wrapped object stays alive and `enif_get_resource` keeps resolving it (oracle-verified). The term's reference is dropped by the **release seam** (next bullet) — the crate has no GC of its own, so only the host knows a term died. The destructor runs **synchronously** on whichever thread drops the last reference (the C schedules it on a misc aux-work thread): counts, ordering and the callback's environment/payload match the oracle, only the timing differs; the asynchronous form **cannot be reproduced safely** (`Send`, `*mut dyn NifHost`). `Registry` also carries the **monitor tree** `monitors: HashMap<MonitorId, MonitorBinding>` (`obj`, `ty`, and the recorded target pid word) behind the *same* mutex as `types`/`terms`/`objects` — a second lock would invert against `destroy`/`forget_object` — and `Registry::forget_object` cancels an object's monitors (`forget_monitors_for_object`, the C's `dtor_demonitor`, `erl_nif.c:2940-2948`) so a destroyed resource's monitors die silently with no `down`.
- **The explicit keep/unkeep seam** (`src/nif/enif/resources_keep.rs`, re-exported at `nif::enif::{keep_resource, unkeep_resource}`) — the env-free Rust half of the C's `enif_keep_resource`/`enif_release_resource` (`erts/emulator/beam/erl_nif.c:3177`/`:3164`), for a caller that has no `*mut ErlNifEnv` and is `#![deny(unsafe_code)]` (`beam_rt`).
  `pub fn keep_resource(obj: *mut c_void) -> bool` (`true` = a reference was taken) and `pub fn unkeep_resource(obj: *mut c_void) -> bool` (`true` = a reference was dropped) are the pair `enif_select`'s route needs: arm an interest ⇒ keep, stop/cancel ⇒ unkeep (the C's per-interest `enif_keep_resource(resource->data)`, `erts/emulator/sys/common/erl_check_io.c:1446`/`:1509`, released at `:1533`/`:1834`/`:2242`).
  Both are safe `pub fn` with `#[allow(clippy::not_unsafe_ptr_arg_deref)]` and the rationale inline (the `resource_term` pattern), and **neither is an `enif_*` slot**: no `#[no_mangle]`, no new C symbol, `ErlNifApi` stays at 176.
  A null handle ⇒ `false`; a pointer that is not a live payload of this crate (`with_registry(|r| r.object_type(obj))` ⇒ `None`) ⇒ `false`, and the helper **never dereferences** an unrecognised pointer (the C computes `DATA_TO_RESOURCE(obj)` unconditionally).
  `keep_resource` takes its reference with the guarded `retain_object_if_alive` (the C's `erts_refc_inc_unless(…, 0, 0)`, `erl_nif.c:3092-3096`) and answers `false` for an **already dying** object (count zero) rather than resurrecting it — the state the C asserts against with `ASSERT(!erts_dbg_is_resource_dying(resource))` (`erl_check_io.c:1261`).
  `unkeep_resource` drops its reference with the guarded `release_object_if_alive` (a `fetch_update` decrement, never a `fetch_sub`), so a concurrent destroy cannot underflow the count; the release that reaches zero runs the type's destructor **synchronously** (`destroy`, the crate's documented timing deviation) and frees the block.
  "An unkeep after destruction answers `false`" holds because `destroy` → `Registry::forget_object` unregisters the payload under the registry lock **before** the block is freed; `enif_release_resource`'s own frozen behaviour and semantics are unchanged.
  Honest residuals (documented in the module): the liveness set is keyed by payload **address**, so a stale pointer whose address a later `enif_alloc_resource` reused is indistinguishable (the registry's existing substitution hazard), and a **double** unkeep of a still-live object stays the C's caller error (the guard only refuses to underflow).
- **The resource `stop` callback and the pending-stop table** (`src/nif/enif/resources_stop.rs`, `#[path]`-included by `resources.rs`; the table in `src/nif/enif/stop.rs`; re-exported at `nif::enif::{resource_type_has_stop, call_resource_stop, record_pending_stop, run_pending_stops, pending_stop_count}`) — the ABI half of `erts_resource_stop` (`erl_nif.c:3032-3041`): a **nooproc message env** built from `ResourceType::host` exactly as `destroy` builds the `dtor` env, then `type->fn.stop(&env, obj, event, is_direct_call)`. `call_resource_stop` answers `true` only when this crate allocated the object, its type has a `stop`, and the callback ran; a null, foreign, already-freed or `stop`-less target answers `false` and is **never dereferenced** — the oracle SIGSEGVs there (`ASSERT(resource->type->fn.stop)`, `erl_check_io.c:1279`, compiled out in a release build), so this is a deliberate typed decision. `select`'s STOP arm drives it **after** `NifHost::select` answers (the host owns the poller and picks the verdict) and returns the host's code **unchanged**: `STOP_CALLED` ⇒ a direct call (`is_direct_call = true`); `STOP_SCHEDULED` ⇒ `record_pending_stop(obj, event)` parks the pair taking **one** `keep_resource` reference, and `run_pending_stops() -> usize` drains it with `is_direct_call = false` and gives that reference back; anything else (plain `0`, the `*_CANCELLED` bits, a negative refusal) calls nothing. Per-verdict reference accounting: `CALL_STOP` leaves the caller's reference alone, `CALL_STOP_AND_RELEASE` means the runtime already released the select's own, `STOP_SCHEDULED` is released by the drain. A second STOP for the same `(obj, event)` **steals** the parked entry (the C's `steal_pending_stop_nif`) — one reference, never a leak and never a double release. `STOP_SCHEDULED` is reachable only for a host that really defers the stop: on Linux/epoll an epoll-able fd is always synchronous, so `beam_rt`'s immediately-deregistering store faithfully answers `STOP_CALLED`. The balanced pin (measured on the oracle, reproduced in-crate) is 8 objects → 8 destructors across all four verdicts, each exactly once.
- **The resource `down`-delivery seam** (`src/nif/enif/resources_monitors.rs`, re-exported at `nif::enif::{deliver_resource_down, deliver_resource_down_id, resource_monitors, MonitorId}`) — the ABI half of `erts_fire_nif_monitor` (`erl_nif.c:3058-3115`). `MonitorId` is the **whole stored reference block** this tree carries — `[u8; REF_THING_BYTES]`, 32 bytes filling the `ErlNifMonitor` payload; the C's `ERTS_REF_THING_SIZE * sizeof(Eterm)` form of the same notion is 24 because the C's packed `num[]` ids hold its identity (`io.c:6994-7010`) — not the `Eterm` it was minted from: `MonitorId::from_term(Eterm) -> Option<MonitorId>`, `unsafe MonitorId::from_holder(*const ErlNifMonitor) -> Option<MonitorId>`, `MonitorId::bytes() -> [u8; 32]`. `deliver_resource_down(monitor: Eterm, pid: Eterm) -> bool` is the reference-term route (`false` for a non-reference term); `deliver_resource_down_id(monitor: MonitorId, pid: Eterm) -> bool` is the holder route a host takes when the minted reference lived on a NIF-call heap that is gone. Delivery (a) removes the binding **under the lock** — only one caller can ever take it, the C's unlink-before-call `:3091` — and answers `false` with no binding; (b) still under the lock requires the object to be a live registered payload and takes a **protective** reference with `retain_object_if_alive` (an increment that only lands on a non-zero count, the C's `erts_refc_inc_unless(...,0,0)` `:3092`; `false` is the C's `brefc == 0` case, `:3093-3096`, where `down` is *not* called); (c) releases the lock and only then runs the callback — `nif_pid = ErlNifPid { pid }`, `nif_mon = holder_from_block(id.bytes())`, env from the **type's** host exactly as `destroy` builds the `dtor` env (`:3105-3108`) — so a re-entrant `enif_*` call from `down` cannot deadlock; (d) drops the protective reference with `enif_release_resource(obj)` (`:3110`), which may synchronously run the `dtor`, the lock being released. Returns whether the callback ran. `resource_monitors() -> Vec<(MonitorId, Eterm)>` snapshots the armed monitors sorted by `MonitorId`; the pid is reconstructed with `Eterm::from_raw` and is an **identity** (compare raw words), readable only while its heap is alive — the `resource_terms()` caveat. A binding deliberately holds **no reference of its own**: holding one would keep a monitored resource alive past refcount zero, where the oracle destroys it and cancels the monitor without firing `down` (`run_resource_dtor`, `:2974-3030`); the protective inc-unless-zero is what keeps the block alive across the callback instead.
- **The resource-term release seam** (`src/nif/enif/resources_release.rs`, re-exported at `nif::enif::{release_resource_terms, resource_terms}`) — the sound way for a caller that owns the reachability decision to tell this crate "that term is dead". `resource_terms() -> Vec<Eterm>` snapshots the live term words (sorted, taken under the registry lock, which is released before returning); `release_resource_terms<F: Fn(Eterm) -> bool>(predicate) -> usize` snapshots, evaluates `predicate` **with no lock held**, then removes each unreachable binding under the lock and drops exactly one reference per removed binding outside it (through the very path `enif_release_resource` takes). **`predicate(term) == false` is the caller's soundness assertion**: a false "unreachable" for a readable term is a use-after-free, a false "reachable" is only a leak. Idempotent by term identity, so a repeated or concurrent prune releases a term exactly once (the binding removal is the structural guard) and a term whose object still holds a user reference is released once with no destructor run. Callers compare `Eterm::raw()` words rather than inspecting the terms (a term word is only meaningful while its heap is alive).
- **The resource-term minting seam** (`src/nif/enif/resources_term.rs`, re-exported at `nif::enif::resource_term`) — `pub fn resource_term(host: &mut dyn NifHost, obj: *mut c_void) -> Option<Eterm>` mints the resource **term** that designates a bare `void*` handle. Ground truth: the C's `prepare_select_msg` (`erts/emulator/sys/common/erl_check_io.c:699-767`) names a selected object by `erts_mk_magic_ref(&hp, &mp->hfrag.off_heap, &bin->binary)` (`:746`) inside the `{select, ResourceTerm, Ref, EventAtom}` tuple (`TUPLE4`, `:757`), and `enif_select`'s per-interest `enif_keep_resource(resource->data)` (`:1446`, `:1509`) is what keeps the object alive while the interest is armed. Semantics, in order: a null `obj` ⇒ `None`; `with_registry(|r| r.object_type(obj))` ⇒ `None` for a pointer this crate never allocated (the "not one of ours" rule `enif_get_resource` uses; the helper **never** dereferences an unrecognised pointer); `RESOURCE_REF_WORDS` words off `host.heap()` ⇒ `None` on exhaustion; the block is written by the **one** writer `write_resource_ref(hp) -> Option<Eterm>` (which `mint_resource_ref`, the `enif_make_resource` route, also calls; `None` = an unrepresentable reference id, and it then writes **no** word); `retain_object_if_alive(obj)` (the `erts_refc_inc_unless(…,0,0)` helper) ⇒ `false` means the count is already zero, i.e. the object is dying, so `None` — it **refuses to resurrect** (the C's `ASSERT(!erts_dbg_is_resource_dying(resource))`, `:1261`), the one deliberate difference from `enif_make_resource`'s unconditional retain; then `Registry::bind_term` + `release_evicted`, exactly as `enif_make_resource` does. It is `pub fn`, not `unsafe fn` (`#[allow(clippy::not_unsafe_ptr_arg_deref)]` with the rationale inline), so the caller contract is documented rather than a `# Safety` section: the returned term is a full resource term (`enif_get_resource` resolves it to `obj`, and the registry's identity key makes a `copy_struct` copy resolve too), it holds **one reference** on `obj` which the caller must drop through the reachability prune `release_resource_terms` or a deliberate `enif_release_resource`, and a term never released is only a leak. Like `enif_make_resource`, the mint's `id` is one draw from the **one** local reference-id space — `beam_common::next_ref_id()` via `resources.rs`'s `next_resource_ref_id`/`narrow_ref_id` — shared with `erlang:make_ref/0`, the NIF `make_ref`, monitors, aliases, timers, `seq_trace` references and `beam_process`'s process table, so a resource term never aliases a live plain reference; the draw is narrowed to the block's small-integer id slot **checked** (the bound is `beam_term::MAX_SMALL`), and an unrepresentable id is a typed refusal (`None`), never a wrapped one. Two calls on one object answer two distinct terms (fresh reference per call, as measured on the oracle).
- **`select`** — `enif_select`/`enif_select_x`: the C's argument handling and return codes, handed to `NifHost::select` (the poller is `beam_io`'s); `-1` when no host can service the request. The **complete documented flag set** is modelled and forwarded **bit-identically**: `ERL_NIF_SELECT_READ` `1<<0`, `WRITE` `1<<1`, `STOP` `1<<2`, `CANCEL` `1<<3`, `CUSTOM_MSG` `1<<4`, `ERROR` `1<<5` (`erts/emulator/beam/erl_drv_nif.h:56-61`), so `ERROR`/`STOP`/`CANCEL` reach the host as such and a host decodes the mode with `ErlNifSelectFlags::intersects` (`src/common.rs`, the C's `mode & FLAG` at `erl_check_io.c:1272`, `:1292-1300`, `:1470-1482`) into its poller's `readable`/`writable`/`error` interests. Two refusals are decided **before** the host is consulted, both answering `INT_MIN | ERL_NIF_SELECT_INVALID_EVENT`: an invalid (negative) event handle (`erl_check_io.c:1266`), and a mask carrying **no documented bit** (the C's `ASSERT(mode)`, `:1293` — a debug abort / release no-op-success in the C, refused here so the `retval < 0` idiom holds and no success is fabricated); a `CUSTOM_MSG`-only mask is documented (`:716-731`) and is forwarded, not refused, and `STOP`/`CANCEL` are forwarded too. Return codes (all the C's own, passed through from the host, since the host owns the poller): `0` accepted or nothing-cancelled (`:1464`, `:1467`, `:1470`); `INT_MIN | ERL_NIF_SELECT_INVALID_EVENT` (`:1266`); `INT_MIN | ERL_NIF_SELECT_NOTSUP` (`:1305`, the C's ERROR-bit-on-an-error-blind-poller case); `INT_MIN | ERL_NIF_SELECT_FAILED` (`:1433`); `ERL_NIF_SELECT_STOP_CALLED`/`_SCHEDULED` (`:1283`, `:1335`, `:1502`, `:1512`); `ERL_NIF_SELECT_{READ,WRITE,ERROR}_CANCELLED` (`:1472`, `:1477`, `:1482`). Every negative answer is `INT_MIN | bit`, so `retval < 0` is the failure idiom; this crate's own "not serviceable" answer stays `-1` (negative, so the same branch), pinned by `tests/nif_env.rs`; the `STOP` verdicts in the returned code drive the resource `stop` callback (see *The resource `stop` callback and the pending-stop table*).
- **`envs`** — `enif_alloc_env` reaches a host in **three documented steps**: (1) the current NIF call's host on this thread, (2) else the host a `ThreadEnvHostFactory` opened for this thread, (3) else `NULL` — never a crate-owned env, which could not intern into the runtime's atom table and would hand a NIF a *wrong* atom index; a current host whose `alloc_env` is unsupported falls through to step 2, `enif_free_env` (→ the owning host through the env itself; `NULL` and foreign pointers are no-ops — this crate never frees memory it did not allocate), `enif_make_copy` (`NifHost::make_copy`; `THE_NON_VALUE` when unsupported), `enif_priv_data` (`priv_data`, `NifLibrary::call`, `NifHost::priv_data`). A use-after-`enif_free_env` is a caller-contract violation the raw-pointer ABI cannot detect.
- **`variadic`** — the seven C-variadic slots via the C shim (see *The C-variadic shim*). `pub fn enif_api_table() -> &'static ErlNifApi` returns the `#[used] static ENIF_API` built by the family `populate` chain from `ErlNifApi::empty()`; the `#[used]` static keeps the `#[no_mangle]` symbols in the final link.

## Dynamic loader (`src/nif/loader.rs`)
`load(path, module, host, load_info) -> Result<NifLibrary, NifLoadError>` does `dlopen(path+".so", RTLD_NOW|RTLD_LOCAL)`, `dlsym("nif_init")` (fallback `_nif_init`), validates in the oracle's exact order (the table above) and invokes `entry.load`. `NifLibrary::call(env, name, arity, args)` looks the function up by `(name, arity)`, calls `fptr(env.as_ptr(), arity, args.as_ptr())`, and turns a pending env exception into `NifCallError::Raised`; for the call's duration it publishes the library's `priv_data` on a crate-private thread-local stack with the same push/pop-token discipline as the host stack — the only source of `enif_priv_data`'s `env->mod_nif->priv_data`. `Drop` runs `entry.unload` then `dlclose`. `Reload`/`Upgrade`/`OldCode` exist for surface completeness but `load()` never produces them (no module-instance / old-code state here).

## Symbol-export mechanism (load-bearing)
A NIF `.so` leaves `enif_*` and a driver `.so` leaves `driver_*`/`erl_drv_*` **undefined**; the dynamic linker binds them, at `dlopen(RTLD_NOW)`, against the **loading process's** dynamic symbol table, so `build.rs` emits `cargo::rustc-link-arg-tests=-Wl,--export-dynamic` for each `beam_abi` test binary. Proven: `nm -D --undefined-only test_nif.so` lists the used `enif_*` as `U` and `test_driver.so` lists its `driver_*`/`erl_drv_*` as `U`; the same names appear `T` in the test binary's `.dynsym`; loading the same `.so` from a process that does **not** export them fails with `undefined symbol: enif_make_int`. The `cargo::rustc-link-arg-bins` counterpart must **not** be emitted: this package has no `[[bin]]` target and cargo hard-errors on it.

## The C-variadic shim (mechanism)
- The seven slots (`enif_make_tuple`, `enif_make_list`, `enif_set_option`, `enif_fprintf`, `enif_snprintf`, `enif_vfprintf`, `enif_vsnprintf`) live in `csrc/nif_variadic.c`.
- Rust cannot read a `va_list`, so it *drives* the extraction: for the `*printf` family the shim calls `beam_abi_enif_fmt_analyze` (a Rust format-string parser), then pulls exactly the varargs the parser reported into a flat `u64` slot array and calls `beam_abi_enif_fmt_{snprintf,fprintf}`, which render the string — parser and extractor share one grammar, so they cannot disagree.
- The supported `*printf` subset is a faithful port of `erts/lib_src/common/erl_printf_format.c`; anything outside it returns a **negative error** (`-EINVAL`), never a wrong string.
- `build.rs` emits `cargo::rustc-check-cfg=cfg(beam_abi_variadic_shim)` unconditionally (so the cfg is known on the degraded path) and sets it only when the shim compiled.

## Known gaps (honest, never a wrong result)
The driver-side gaps are `../driver/CONTEXT.md`'s; the cross-cutting ones (undeclared header names, the malformed-term guard) are `../CONTEXT.md`'s.

- **A *copied* `enif_make_resource_binary` term does not resolve.** That term is an **on-heap** binary here (the C's is an off-heap magic binary, so a copy shares its `mb` pointer and keeps resolving); an on-heap binary carries no shared identity, so the registry keys it by raw word and `copy_struct`'s copy of it is a different term. A typed residual (`enif_get_resource` answers `C`'s `0`), never a wrong object.

- **`enif_alloc_env` answers `NULL`** only when **no host is reachable**: no live `NifEnv` on the thread (outside a NIF call) **and** no `ThreadEnvHostFactory` installed, or the current host's `alloc_env` is unsupported and no factory answers either. With a factory installed, a NIF-created thread opens its own host and gets a real message env. `beam_rt`'s `NifHostImpl` implements `alloc_env`/`free_env`/`make_copy` (`beam_rt/src/nif.rs`) over the one shared pooled BIF heap, so the runtime's message-env idiom works on the call path and `make_copy` is the identity (a crate-owned env would carry unusable atoms); `beam_rt` also supplies a factory (`Runtime::install_nif_thread_env`, a process-global opt-in — `beam_rt/src/runtime.rs`), so a runtime that has installed one serves a NIF-created thread's off-the-call-path request from that thread's own host; one that has not still answers `NULL`.
- **NIF host hooks the runtime does not implement.** `beam_rt`'s `NifHostImpl` answers every hook whose state it owns (atoms/atom table, ETF, refs, liveness, sends, `port_command`, monitors, `select`, message envs (`alloc_env`/`free_env`/`make_copy`), `unique_integer`, `system_info`, `self_pid`, `nif_yield_point`); the rest sit at their trait defaults — `priv_data`, `consume_timeslice`, `whereis_port`, `dynamic_resource_call`, plus the two legacy hooks (`monitor_process`, superseded by `monitor_process_result`; `schedule_nif`, which `beam_abi` never consults). Each remaining default and its exact reason are documented in `beam_rt/src/nif.rs` (*The remaining hooks — and exactly why*); `beam_abi`'s side is complete. The resource-term seam's caller half (`release_resource_terms` driven from the GC/park point with the engine's root set as the predicate) is likewise `beam_rt`'s.
- **No scheduler threads.** `enif_thread_type` reports only `ERL_NIF_THR_UNDEFINED` (foreign thread) or `ERL_NIF_THR_OTHER` (`sync::thread_create`), never a scheduler/dirty-scheduler type; `*_name` reproduces the C's `no_name` = `"unknown"` for a **live** NULL-named handle (`sync::no_name()`/`sync::thread_created_unnamed`, driver `erl_drv_thread.c:99,135`; `enif_*` forwards `erl_nif.c:2438-2441`) and answers `NULL` for a **foreign or already-joined** tid (the C's `drv_thr == 0` path, `erl_drv_thread.c:664-684`).
- **`sync::tsd_*` passes the key straight to pthreads unchecked** (no `used_tsd_keys[]` validation); an invalid/destroyed key makes `set`/`get` a safe no-op (`NULL`) where the C aborts.
- **`enif_ioq_is_empty` does not exist in this OTP tree** (`enif_ioq_*`, `api.rs`, `ioq.rs`, `enif_inspect_iovec`, `enif_free_iovec`).
- `enif_make_map_*`/`enif_compare`/`enif_is_identical`/`enif_hash` take no env; identical terms take a raw-word fast path. `enif_compare` resolves an atom pair by **name** — a *top-level* pair through `current_recorded_atom_name`/`NifHost::atom_name`, and a pair **nested** (tuple/list/map) inside a compound through the current host's atom table (`NifHost::atom_table`, a defaulted hook). Only with no host, or a host that exposes no table, does a nested pair fall back to `beam_term`'s raw atom-index order — pinned by `tests/nif_compare.rs::a_nested_atom_pair_orders_by_name`. Exact for non-atom keys.
- Integers: small ints + one-limb bignums; a wider value makes the accessor return `0`, never truncate.
- **On-heap vs off-heap refc binaries (F5-class, audited — not closable inside `beam_abi`).** `enif_alloc_binary`/`enif_make_new_binary`/`enif_make_binary` always build an **on-heap** binary (`ref_bin == NULL`, `orig_size`/`orig_bytes` only), where the oracle keeps the payload off-heap with an `ERL_REFC_BITS_SIZE` 8-word refc pair (`ERL_REFC_BITS_SIZE == 8`, `copy.c:219-242`). Measured against OTP 29.1.1 / erts-17.1: **agree** for `size ≤ ERL_ONHEAP_BINARY_LIMIT` (64 B) — 2/3/4/10 words for 0/1/10/64 B — and differ above (65 B: oracle 8 words / `flat_size` 64 vs **11 words / 88** here; the oracle's `b.ref_bin` is non-NULL at every `enif_alloc_binary` size); both are valid binaries of the same size/bytes, only the representation — and with it `enif_term_size`/`erts_debug:flat_size` — differs. Not closable here (`beam_alloc::RefcBinary`, `BinRef.val`, `beam_process`): closure touches `src/nif/host.rs`, `src/nif/enif/mem.rs`, `beam_rt`'s `impl NifHost for NifHostImpl` (`beam_rt/src/nif.rs`, `beam_rt/src/context/mod.rs:1677-1694`) and `beam_gc::OffHeap`; adjacent, `enif_release_binary` differs from the oracle only under `#ifdef DEBUG` (`erl_nif.c:1451-1461`). Pinned by the `mem.rs` unit tests and `tests/nif_bitslice.rs`/`tests/nif_subbin.rs`.

## Test Strategy
- **Per-family end-to-end tests** — each `tests/nif_*.rs` compiles a real C fixture at test time with the system `cc` against the system OTP headers and `dlopen`s it (`RTLD_NOW`) through this crate's own loader, so a single unresolved `enif_*` import fails the load; `nif_variadic.rs` is gated on `cfg(beam_abi_variadic_shim)` and `nif_threads.rs` carries the extended `*_name` matrix (`"unknown"`).
- **Oracle cross-checks that really run** (they skip loudly without `erl`/`erlc`/`cc`): `nif_threads.rs` loads the *same* fixture `.so` from the system Erlang and compares the printed tuple (`thread_type/0`); `nif_mapiter.rs`'s `the_oracle_agrees_on_the_flat_map_key_order` runs the real `erl` over `maps:from_list/1` → `maps:keys/1` and requires the fixture's C-side walk order to equal it; `nif_resource.rs`'s expected `load_status`/`roundtrip`/`roundtrip_value`/`post_release` tuples are the **measured oracle values** (OTP 29.1.1 / erts-17.1, `post_release/0` = `{1,42,0}`), and `dtor_probe/0` + `dtor_state/0` are **Rust-only** (the oracle's C `enif_release_resource(NULL)`/`enif_keep_resource(NULL)` dereference the operand and segfault); `nif_compare.rs`'s `the_same_fixture_agrees_under_the_erl_oracle` requires the Rust order points to equal the oracle's for the *same* fixture `.so`; `nif_priv_data.rs` cross-checks under `erl`/`erlc`; `nif_map_arrays.rs`'s `the_same_fixture_agrees_under_the_erl_oracle` pins the measured duplicate-key table (unique 3 → `{1,3}`, hash arm 40 → `{1,40}`, `1`+`1.0` → `{1,2}`, `7` twice → `{0,overwritten}`, 34-pair hash arm with `5` twice → `{0,overwritten}`, `=:=`-equal tuples → `{0,overwritten}`).
- The three seam drivers `nif_bin2term.rs`, `nif_monitor_codes.rs` and `nif_resource_release.rs` carry the same shape (Rust-side assertions plus a `the_same_fixture_agrees_*` oracle half) and belong to `tests/`. ## Notes for Agents
- `erts/emulator/beam/global.h` line ~57 holds the real `struct enif_environment_t` body — emulator-internal and **not** to be replicated: `ErlNifEnv` stays opaque here, its Rust analogue for a live call being `nif::host::NifEnv`, reached only through `as_ptr`/`from_opaque`.
- A NIF fixture must reference **only** `enif_*` slots the crate populates (`Some`), or `dlopen(RTLD_NOW)` fails on the unresolved import.
- **Term lifetime:** a term produced by a NIF lives on the host arena; keep the host (and the loaded library) alive while inspecting it, or read a use-after-free (see *Test Strategy*).
- The seven C-variadic slots need `csrc/nif_variadic.c` compiled (`build.rs` sets `cfg(beam_abi_variadic_shim)`); without a C compiler they are `None` and a `dlopen` that imports one fails loudly.
- A driver that lands in `tests/` writes `mod common;` (so `tests/common/mod.rs` must stay reachable), puts its fixture in `tests/fixtures/`, and builds the `.so` into `$TMPDIR` (not committed); run it with `../../../scripts/cargo.sh test -p beam_abi --test <name>` and check no `SKIP:` banner appears — the oracle half must really execute.
- **A NIF-loading test binary must export its symbols.** The fixture `.so` leaves `enif_*` undefined and the dynamic linker binds them against the *loading process*, which only works because `build.rs` emits `-Wl,--export-dynamic` for this crate's test targets. Any reproduction outside this package (a scratch crate, a `rustc` one-off) needs the same link argument, or every fixture load fails with `undefined symbol: enif_inspect_binary`.
- **The seams this node exposes for the runtime** (the `NifHost` ones are defaulted/additive, so no implementor has to change): `binary_to_term_used(bytes) -> Option<(Eterm, usize)>` behind `enif_binary_to_term`; `monitor_process_result(pid) -> Option<NifMonitorResult>` behind `enif_monitor_process` (arming — the runtime reports the minted internal reference here, which is what records the monitor binding); the free functions `nif::enif::{resource_terms, release_resource_terms}` for resource-term reclamation (a caller-owned reachability predicate — see *The release seam*'s warning); the free minting function `nif::enif::resource_term(host: &mut dyn NifHost, obj: *mut c_void) -> Option<Eterm>`, which turns the bare `*mut c_void` a `NifHost::select` request carries into the resource **term** the C's select notification names the object by (`erl_check_io.c:746`/`:757`) — the runtime mints it at delivery, then drops its reference through the prune; and the free delivery seam `nif::enif::{deliver_resource_down, deliver_resource_down_id, resource_monitors, MonitorId}`, which the runtime calls from its `'DOWN'` delivery point — `deliver_resource_down(monitor: Eterm, pid: Eterm) -> bool` with the `NifMonitorResult::Armed(term)` reference and the dead target's pid, or `deliver_resource_down_id(monitor: MonitorId, pid: Eterm) -> bool` when only the 32-byte `ErlNifMonitor` holder was kept (`MonitorId::from_holder`) — to run the resource type's `down` callback (see *The resource `down`-delivery seam*); and the free keep/unkeep pair `nif::enif::{keep_resource, unkeep_resource}`, which the runtime's `enif_select` route drives with the bare `*mut c_void` a `NifHost::select` request carries — arm an interest ⇒ `keep_resource(obj)`, stop/cancel the interest ⇒ `unkeep_resource(obj)` — because that route holds the object alive per interest with no environment and no `unsafe` (see *The explicit keep/unkeep seam*); `NifHost::nif_yield_point(flags)`, the per-iteration preemption point of the `enif_schedule_nif` trampoline; the **thread-env factory** `nif::{ThreadEnvHostFactory, install_thread_env_factory, clear_thread_env_factory}`, which the runtime installs so an `enif_thread_create`d NIF thread can obtain a real host (its `open()` must reach the **live** `AtomTable` and inject sends thread-safely — `beam_abi::driver::async_pool` is the existing model for the latter) instead of `enif_alloc_env()` answering `NULL`; and the **stop drain** `nif::enif::run_pending_stops()`, which a host whose poller really defers a stop calls from its poll loop, after which `enif_select`'s `STOP_SCHEDULED` answer is faithful (`beam_rt`'s store de-registers immediately, so it answers `STOP_CALLED` instead).
- **Do not probe `enif_demonitor_process(env, NULL, &zeroed)` under the oracle**: the system `erl` crashes on that shape (it dereferences the NULL pid). The measured demonitor values come from the legitimate shapes (`{0,1}` after the target died, `1` for an already-gone reference).
