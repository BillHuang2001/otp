# `src/driver/` — driver host layer (contract A.4)

## Intent
The **driver C ABI host half**: every `driver_*`/`erl_drv_*` function a driver `.so` imports, the `DriverHost`/`DriverEnv` seam those bodies drive, the safe `AsyncJob` runner, the dynamic driver loader with the `ErlDrvEntry` load contract, and the port-closing family's measured behaviour — over the frozen `driver::types`/`driver::api` shapes owned by the crate root (`../CONTEXT.md` → *Frozen layout table*).
The boundary's *shape* is the parent's contract; its *behaviour* is this node's.

Ground truth (read-only, never modify): `erts/emulator/beam/erl_driver.h`, `erts/emulator/beam/io.c`, `erts/emulator/beam/erl_port.h`, `erts/emulator/beam/erl_bif_ddll.c`, `erts/emulator/sys/unix/erl_unix_sys_ddll.c` (paths are repo-root relative).

## The driver host seam (`driver::host`) — the runtime services behind the `driver_*` layer
The *internal* boundary the `driver_*` bodies are written against (source `src/driver/host.rs`).
- `pub trait DriverHost` — **required** `heap() -> &mut beam_alloc::Heap`, `intern_atom(&str) -> Option<Eterm>`, `output(port, &[u8]) -> c_int`, `send_term(port, Option<Eterm>, Eterm) -> c_int`; **defaulted** (`-1`, `None`): `output2(port, header: &[u8], body: Option<&[u8]>) -> c_int` (the split-reply hook every `driver_output*` thunk routes through — see *The split hook*), `select`, `set_timer`, `cancel_timer`, `read_timer`, `r#async`, `connected_pid`, `caller_pid`, `port_term` (an `ErlDrvPort` handle → the port's **id term**; `io.c:7295-7303` `prt->common.id` — the hook that closes the `ERL_DRV_PORT` term-data operand, see *`driver_*` / `erl_drv_*` functions*), `binary_to_term` (the ETF decode behind `ERL_DRV_EXT2TERM`), the port-queue hooks `enq`/`pushq`/`deq`/`sizeq`/`peekq`, the attribute hooks `set_busy_port`/`set_control_flags`/`get_port_flags`, the failure/lifecycle hooks `failure`/`port_exit`/`busy_msgq_limits`/`init_ack`/`set_os_pid`/`async_port_key`, the monitor hooks `monitor_process`/`monitor_process_result`/`demonitor_process`/`get_monitored_process`, the PDL hooks `pdl_create`/`pdl_lock`/`pdl_unlock`/`pdl_get_refc`/`pdl_inc_refc`/`pdl_dec_refc`, the driver-registry hooks `add_driver_entry`/`remove_driver_entry`/`lock_driver`/`create_port`, `now`.
- **The split hook (`output2`).** The C never hands the port owner one flat byte string: every `driver_output2`/`driver_output_binary`/`driver_outputv` reply is `{Port,{data,Reply}}` with `Reply = [header | Body]` — the `hbuf`/`hlen` bytes as a list prefix and the `buf`/`len` bytes as the tail (`deliver_read_message`, `io.c:3363-3442`; `deliver_vec_message`, `:3502-3621`), which is observable to Erlang code (`[h…|<<tail>>]` vs a flattened list). `output2(port, header, body)` carries that boundary: `body: None` is the C's `buf == NULL` (**no** tail — a proper header-only list) and `body: Some(&[])` a **present, empty** tail (`<<>>` in `[binary]` port mode) — different terms. The C tests the **pointer**, never `len != 0`. **Default = byte-identical to a host that overrides only `output`:** exactly one `output` call carrying header-then-body (`None` counted as empty), no allocation when either side is empty, so a host that overrides only `output` keeps the old flattened result. Overriding `output2` is what preserves the split. Additive only — no `#[repr(C)]`/table/assert moved.
- **The three-way monitor hook.** `monitor_process(&mut self, pid) -> Option<ErlDrvMonitor>` is the **two-way compatibility subset** (`Some` ⇒ the C's `0`, `None` ⇒ `-1`) kept for source compatibility; the full three-way hook is `monitor_process_result(&mut self, pid) -> MonitorResult` and its **default delegates** to `monitor_process` (`Some(mon)` ⇒ `MonitorResult::Ok(mon)`, `None` ⇒ `MonitorResult::Error`), so an existing two-way implementor is unchanged. `pub enum MonitorResult { Ok(ErlDrvMonitor), NotAlive, Error }` (`#[derive(Debug, Clone, Copy)]` — `ErlDrvMonitor` has no `PartialEq`) is the driver A.4 monitor result — distinct from the NIF monitor family (`NifHost::monitor_process`/`enif_monitor_process`) — and mirrors the C's `0` / `> 0` / `< 0` reason codes (`io.c:7012-7038`): `Ok` ⇒ `0` (`ERL_DRV_MONITOR_OK`), `NotAlive` ⇒ `1` (`ERL_DRV_MONITOR_NOT_ALIVE`, `io.c:7031`), `Error` ⇒ `-1` (`ERL_DRV_MONITOR_ERROR`, `io.c:7020-7021`). `driver_monitor_process` maps the enum onto those three codes (and pins their signs with `const _: () = assert!(…)` in `src/driver/drv/pdl.rs`). Re-exported at the crate root (`beam_abi::MonitorResult`).
- `pub struct DriverEnv` — the env behind the C-facing opaque `*mut ErlDrvPort_`: `new(&mut dyn DriverHost)`, `host()`, `heap()`, `as_port()`, `unsafe from_port(*mut ErlDrvPort_) -> Option<&mut DriverEnv>`; **the `ErlDrvPort` a runtime passes to a driver callback *is* the `DriverEnv::as_port` pointer** (the `NifEnv` analogue); plus `pub fn decode_term_spec(&mut DriverEnv, &[ErlDrvTermData]) -> Option<Eterm>`, the reverse-Polish term-data decoder behind `erl_drv_output_term`/`erl_drv_send_term`.
- `pub fn is_invalid_port_handle(ErlDrvPort) -> bool` — the **one** non-handle predicate (`NULL` or the C's `ERTS_INVALID_ERL_DRV_PORT` sentinel), consulted by `DriverEnv::from_port` **and** `drv::env_for` so no C entry point dereferences either operand; the failure value the entry point then returns is the C's (`-1`/`0`).
- **Current-driver-host publication (`driver::current_host`).** `add_driver_entry`/`remove_driver_entry` carry no port operand, so `DriverEnv::from_port` cannot recover a host for them (they are meaningful only inside a driver callback); `beam_io` publishes the host for one callback via `pub fn with_current_host<R>(host: &mut dyn DriverHost, f: impl FnOnce() -> R) -> R` — a scoped guard in a thread-local `Cell<Option<*mut dyn DriverHost>>` that **always restores the previous host on exit** (`f`); with no host published the two entry-list slots answer `-1`/`0` without dereferencing their operand.
- `driver::drv` implements the `driver_*`/`erl_drv_*` functions and publishes them through `driver_api_table()`; `driver::loader` the dynamic loader / `ErlDrvEntry` contract (see *Dynamic loader*).

## `driver_*` / `erl_drv_*` functions (`src/driver/drv/`)
Every one is `#[no_mangle] pub unsafe extern "C"` with the exact signature of its matching `driver::api` field, landing in the `#[used] static DRIVER_API` published through `pub fn driver_api_table() -> &'static ErlDrvApi`. `EMPTY_DRIVER_API` is `unsafe { core::mem::zeroed() }` (the const-evaluable all-`None` base; `ErlDrvApi::empty()` is a plain `fn` and cannot initialise a `static`) — every pointer field is null-optimized, so the all-zero struct **is** the all-`None` table (a test pins that equality). Each family's behaviour and measured return codes live in that family file's module docs (`src/driver/drv/*.rs`; ground truth `io.c`):
- **`mem`** (host-free) — `driver_alloc`, `driver_free`, `driver_realloc`, `driver_alloc_binary`, `driver_realloc_binary`, `driver_free_binary`, `driver_binary_get_refc`, `inc_refc`, `dec_refc`, `driver_system_info`, `null_func`, `erl_errno_id`, `erl_drv_consume_timeslice`, `erl_drv_monotonic_time`, `erl_drv_time_offset`, `erl_drv_convert_time_unit`, `driver_dl_open`, `driver_dl_sym`, `driver_dl_close`, `driver_dl_error`, `erl_drv_putenv`, `erl_drv_getenv`, `driver_mk_term_nil`, `driver_term_nil`. `erl_errno_id` is **oracle-exact**: the ASCII-lowercased POSIX name from the C library's `strerrorname_np` (resolved once via `dlsym(RTLD_DEFAULT, …)`, no libc-version gate), a fixed table for the spellings that collide on this platform (`EAGAIN`/`EALREADY`/`EBUSY`/`ECONNREFUSED`/`EDEADLK`), and `errno_<N>` for anything unnamed — including `0`, which never reaches the lookup (`errno_map[0]` is pre-filled). A rendered form goes to a per-thread 30-byte buffer (`ERTS_UNKNOWN_ERRNO_BUF_SZ`), a table name to static storage, so every answer is NUL-terminated and valid until the next call on that thread. Pinned byte-identically under both runtimes by `tests/erl_errno_id.rs` (`0`/`ENOENT`/`EACCES`/`EAGAIN`/`EBUSY`/`ECONNREFUSED`/`EDEADLK`/`EINVAL`/`9999`/`-1`/`-4711`).

The term-data family (`driver_output_term`/`driver_send_term`/`erl_drv_output_term`/`erl_drv_send_term` over `decode_term_spec`, decoding **all 17 `ERL_DRV_*` tags** — `ERL_DRV_PID` accepts only an internal pid, `ERL_DRV_MAP` builds via `beam_term::map` (flat ≤ 32, else HAMT; duplicate keys refused), `ERL_DRV_EXT2TERM` routes through the defaulted `DriverHost::binary_to_term`); the port queries (`driver_mk_atom`, `driver_mk_port`, `driver_connected`, `driver_caller`); the select/timer/async group.

## The safe async-job runner (`src/driver/async_job.rs`)
`driver_async`'s last three operands (`async_invoke`, `async_data`, `async_free`, `erl_driver.h:605-607`) **are** a C async job. The driver-facing half is `driver_async` → `DriverHost::r#async`; the **host** half is `AsyncJob`, which closes the gap for a runtime that forbids `unsafe` (the sibling `beam_rt` is `#![deny(unsafe_code)]`). `pub type AsyncCallback = unsafe extern "C" fn(*mut c_void)`.
- `pub struct AsyncJob` — the single `unsafe` entry point `AsyncJob::new -> Option<AsyncJob>` (its `# Safety` section is the caller's promise that the three operands are a live C async job; `None` when `async_invoke` is `NULL` — nothing to run, the caller still owns the data). Everything after it is **safe**: `invoke(&self) -> *mut c_void` runs `(*async_invoke)(async_data)` and returns the data for `ready_async`; `finish(self)` runs `(*async_free)(async_data)` **exactly once** (the handle is consumed); `data()`/`has_invoke()`/`has_free()` inspect the operands without dereferencing them; `Drop` frees a still-held job **without** invoking it; `Debug` never touches the pointers.
- **Inert by default.** `DriverHost::r#async`, its signature and its `-1` default are **unchanged** — a host with no async pool keeps answering `-1` and opts in by constructing a job and running it (`+A 0`). Re-exported as `beam_abi::{AsyncJob, AsyncCallback}`. Owner of the *adoption* half (`beam_rt`): implement `DriverHost::r#async`, poll/drain `ready_async`, keep the driver object mapped while a job is outstanding, implement `driver_async_port_key`.

## Dynamic loader (`src/driver/loader.rs`)
`load(path, name) -> Result<DriverLibrary, DriverLoadError>` does `dlopen(path+".so", RTLD_NOW | RTLD_LOCAL)`, `dlsym("driver_init")` (fallback `_driver_init`), then validates the returned `ErlDrvEntry` in the oracle's exact order and runs its `init` callback — reproducing `do_load_driver_entry` (`erts/emulator/beam/erl_bif_ddll.c:1466-1533`), `erts_sys_ddll_load_driver_init` (`sys/unix/erl_unix_sys_ddll.c:216-228`) and `init_driver` (`io.c:7559-7621`). `DriverLibrary` exposes the entry (`entry()`), `name()`, `init()`, `finish()` and one wrapper per callback slot (`start`, `control`, `call`, `output`, `outputv`, `timeout`, `ready_input`, `ready_output`, `ready_async`, `flush`, `process_exit`, `stop_select`, `emergency_close`, `stop`); a `NULL` slot is `DriverCallError::AbsentCallback { callback }` (never a crash), so the caller applies whichever of the C's two behaviours matches the slot (a logging no-op, or a plain skip). `Drop` runs the `finish` callback then `dlclose`s the object. Failure variants and their reason atoms (`erl_bif_ddll.c:1709-1720`): `NoDriverInit` ⇒ `no_driver_init`, `DriverInitFailed` ⇒ `driver_init_failed` (a null entry **or** a vetoing `init`), `BadDriverName` ⇒ `bad_driver_name`, `DriverIncorrectVersion` ⇒ `driver_incorrect_version` (missing `ERL_DRV_EXTENDED_MARKER` or out-of-range version), `Unspecified` ⇒ `unspecified_error`; `SymbolNotFound` exists for surface completeness but `load()` never produces it.

## Documented deviations from the oracle
(each site's module docs carry the full rationale)
- `driver_mk_atom` returns the **name pointer** (the `ERL_DRV_ATOM` operand `decode_term_spec` interns), the C a pre-interned atom handle; `driver_mk_port` returns the **port handle pointer** (the `erl_drv_output_term`/`erl_drv_send_term` **port parameter** encoding), the C the port's id term (each pair round-trips). The **operand** form is not a deviation: a `{ERL_DRV_PORT, driver_mk_port(port)}` operand is resolved back to the port's id term through `DriverHost::port_term`, so the C idiom delivers the port term.
- `driver_mk_port(NULL)` returns `driver_term_nil` (is safe); the oracle does **not** null-check the operand and its VM exits on the spot (exit signal, empty stdout) — a deliberate, retained divergence, since that behaviour is an unpinnable probe hazard (`src/driver/drv/port.rs`).
- `driver_output_term`/`driver_send_term`/`erl_drv_output_term`/`erl_drv_send_term` return the host's code (`0` = delivered), the C `1`/`0`; the documented `< 0` idiom sees identical behaviour.
- `erl_drv_time_offset` returns `0` by construction (monotonic time is anchored on the system epoch); `erl_drv_consume_timeslice` always returns `0` (no port-timeslice accounting); `driver_system_info` returns without writing for a null `sip` or an `si_size` shorter than the first field group, where the C calls `erts_exit(ERTS_ERROR_EXIT, …)`.
- Refusals where the C would fault or over-read: a malformed/out-of-range request (`driver_output_binary`, `offset + len > orig_size`, `driver_outputv`, `skip`, `time_left`, `ErlIOVec`) refused with `-1`; a `NULL` `driver_name` is a typed `BadDriverName`; a `dlopen` failure lands in `Unspecified` carrying the loader's own `dlerror` text (the C renders an `{open_error, N}` code); the `.so` suffix is appended only when absent. No code-server/driver list or reload policy is consulted (only the *entry* validation).

## Oracle-measured: the port-closing family (`driver_failure*` / `driver_exit`)
Every spelling funnels through the C's single `driver_failure_term(ix, term, eof)` (`io.c:7196-7229`; entries at `io.c:7234`/`7258`/`7263`/`7273`/`7278`). The table below is **pinned end-to-end against the real ERTS** by `tests/driver_failure.rs` + `tests/fixtures/driver_failure.c` — the same `.so` under both runtimes, **one fresh VM and one fresh port per spelling** (a second `driver_failure_*` on the port a callback just terminated is a measured use-after-free in the C, `io.c`/`erl_port.h:735-747`, so it is never exercised) — measured on OTP 29.1.1 / erts-17.1. **Post-close observables** (the state a host must leave behind): after any of the seven closing spellings `port_info(P)` answers `undefined` and `port_close(P)` raises `error:badarg`; the invalid-port sentinel leaves the port **fully alive** (`port_info(P,name)` = `{name,"drvfail"}`, `port_close/1` = `true`) and makes `port_control/3` raise `error:badarg`, because a negative `control` return **is** the C's failure idiom — on that path the assertion is the *port's* fate, never the return. **The `eof` route's extra consequences are host obligations** (the enum/`DriverHost::failure` docs carry them; the fixture exercises neither, as it opens no `[line]` and no `[eof]` port): `eof=1` acks an async-open port (`init_ack_send_reply`), **flushes the line buffer** (`flush_linebuf_messages`, `io.c:3475-3499` — the only call site in the emulator; measured: a `[line]` port with a buffered partial line delivers `{Port,{data,{noeol,"partial"}}}` *before* the exit), and takes the **soft-eof** branch on a port opened with the `eof` option (`ERTS_PORT_SFLG_SOFT_EOF`, `erl_bif_port.c:996`): instead of closing it delivers `{Port,eof}` and the port **stays alive** (measured `port_info` intact, `port_close/1` = `true`). `PortFailure::Posix`'s atom is `erl_errno_id`'s answer, and that lookup **is exact** in this crate (the `mem` family above: the lowercase POSIX name or `errno_<N>`, `eacces` for `EACCES`, `errno_0` for `0`). What remains is the **seam shape**, not the mapping: the errno crosses as the raw `c_int` (`PortFailure::Posix(errno)`) and the host renders the reason atom by calling that same `erl_errno_id`, exactly as it does for `driver_exit`'s non-zero code (`io.c:7244-7253`). `driver_failure_atom` interns the raw bytes as **Latin-1** (measured: the single byte `0xE9` ⇒ `é`, the UTF-8 pair `0xC3 0xA9` ⇒ `'hÃ©llo'`; an empty name ⇒ `''`), i.e. the seam's UTF-8-only `PortFailure::Atom(&str)` is a real, documented divergence.
### The invalid-port operand: `NULL` is a crash, `(void*)-1` is the `-1` path
`ERTS_INVALID_ERL_DRV_PORT` is **`(struct _erl_drv_port *)(SWord)-1`**, never `NULL` (`erl_port.h:60-67`: "It would have been preferred to use NULL … not backward compatible"). Measured: `driver_failure_eof(NULL)`/`_atom`/`_posix`/`driver_failure(NULL,·)`/`driver_exit(NULL,·)` each **SIGSEGV the VM deterministically (3/3)** — only `ERTS_INVALID_ERL_DRV_PORT (-1)` returns `-1` (deterministic, port untouched). The one shared predicate `driver::host::is_invalid_port_handle` is what both recovery sites (`DriverEnv::from_port`, `drv::env_for`) consult, so **both** operands answer the C's failure value without a dereference: for the sentinel that is ABI fidelity (the C's own early return), for `NULL` it is a deliberate **safety divergence** (the C faults; a library function must not crash its host process). A stale handle from a fully-terminated port returns `-1` deterministically (3/3) when called from a *different* live port's callback, but calling a second `driver_failure_*` on a just-terminated port from the **same** callback **segfaults 3 of 4 runs** (`erl_port.h:735-747` documents the `ERTS_PORT_SFLGS_INVALID_DRIVER_LOOKUP` guard, but the state word is read out of freed memory) — both shapes are use-after-free and therefore **unpinnable**.
### Status of this crate's half
`lifecycle.rs` models every spelling onto `DriverHost::failure`/`port_exit` with the C's return codes (`0`/`-1`) and never touches a `NULL`/sentinel port. The seam's reasons are the C's own: `Eof` is the **eof route** — `driver_failure_eof` *and* `driver_failure(P, 0)` (the C's `eof` flag is `code == 0`, so the term is discarded) — and `Atom`/`Posix`/`Error` carry the **bare** atom / bare lowercase POSIX-name atom / bare integer the owner observes, never `{error,·}`. The family is pinned end-to-end on **both** runtimes by `tests/driver_failure.rs`: the fixture's seven `driver_*` imports are proven undefined in the `.so`, every command lands on exactly one hook with exactly that reason, the sentinel reaches none and answers `-1`, and a host without the hooks gets the C's `-1` for every spelling (so the return code is the host's, never a hardcoded success). `port_info`-side note: a `control` callback returning `< 0` (the documented `return ERL_DRV_ERROR_GENERAL` idiom) makes `port_control/3` raise `badarg` and leaves the port **alive**; `output`/`ready_input` are `void`-returning in erts-17.1, so that idiom applies only to `control`/`call`.

## Handoffs (host halves owned by other nodes)
- **`DriverHost::failure` / `port_exit` adoption — the port never closes on a runtime yet.** No production host implements either hook: `beam_rt`'s `DriverPort` (`beam_rt/src/port/driver.rs`) and `beam_io`'s `AbiHost` (`beam_io/src/abi/host.rs`) both sit on the `-1` trait defaults, so a loaded driver's `driver_failure_*` answers failure and nothing closes. `beam_rt` / `beam_io` therefore own the close, and the measured table above is the contract to reproduce: `unlink` the connected process **before** closing on the `port_exit` path, deliver the reason as the **bare** atom / bare integer / `normal` (never `{error,·}`), apply the `eof` route's extra consequences (linebuf flush, `[eof]` soft-eof with the port surviving), and leave `port_info(P)` = `undefined` and `port_close(P)` = `badarg` behind — with the invalid-port sentinel touching nothing. The sibling ledger still calls this family unpinnable and needs correcting by its owner (`erts_rust/tools/differential/src/corpus/driver_c.rs:132-141` records it under "measured divergences" and `erts_rust/tools/differential/GAPS.md:75-79` states "the close reason is a linked-port signal, not a VM-stable observable, so none is pinned"): it **is** VM-stable — byte-identical under a `trap_exit` owner *and* under a monitor, 16/16 measured probe lines — so what remains is `beam_rt`'s missing hook, not an unpinnable observable. Tools-owned: reported here, not edited from this crate.
- **`DriverHost::port_term` adoption — the last step for the `ERL_DRV_PORT` operand on a live runtime.** `decode_term_spec`'s `ERL_DRV_PORT` arm keeps the C's own path (`is_internal_port` ⇒ push the operand unchanged, `io.c:5744-5747`/`5969-5972`) and otherwise resolves the operand as an `ErlDrvPort` **handle** through the additive, defaulted `DriverHost::port_term(port) -> Option<Eterm>` hook (`None` = unknown handle ⇒ the spec is refused, the trait default). The two encodings are disjoint (a live handle is a non-null 8-aligned pointer, low bits 0, while `is_internal_port` is `x & 0xF == 0x7`), so resolution is unambiguous and safe. Both hosts must implement it, mapping a live handle to the port's id term:
  - `beam_rt`'s `DriverPort` (`beam_rt/src/port/driver.rs`, whose `impl DriverHost` also owns the driver-registry slots) — a `beam_process`/`beam_term` internal port term for the registered port.
  - `beam_io`'s `AbiHost` (`beam_io/src/abi/host.rs`) — likewise, over its `PortRegistry`. Until one does, a loaded C driver written the C way still delivers nothing on that runtime (measured: the receiver times out); the `beam_abi` half is complete and pinned (`tests/driver_port_term.rs`, `tests/fixtures/driver_port_term.c`). Measured against the real system ERTS (OTP 29.1.1 / erts-17.1) with that fixture: `erl_drv_output_term` with the operand ⇒ **`1`** and the owner receives **the port term itself** (`is_port(T), T =:= Port`), `erl_drv_send_term` ⇒ **`1`** and the connected process receives it, both nested in a tuple (`{tag, Port}`) ⇒ **`1`**, and a non-port operand (`1`) ⇒ **`-1`** with nothing delivered. This crate's host seam answers `0` for "delivered" (the documented deviation with the same `< 0` predicate), and the delivered terms are identical.
- **`DriverHost::output2` adoption — the only remaining step for a loaded C driver's split reply.** All four `driver_output*` thunks hand the split to `output2`; a host that does not override it gets the default (header-then-body joined into one `output` call), i.e. today's flattened result. Two hosts must implement it:
  - `beam_io`'s `AbiHost` (`beam_io/src/abi/host.rs`): `output2` = `match self.with_ctx(|ctx| ctx.deliver_read(header, body)) { Some(Ok(())) => 0, _ => -1 }` — the same `DriverContext::deliver_read` seam the in-tree drivers use, so the reply becomes one `port_task::ReadMessage { header, body }` (its `body: None` / `Some(vec![])` distinction is exactly the hook's). Its current `output` (`ctx.input().push`, a flat body-only read) then only serves direct `DriverHost::output` callers.
  - `beam_rt`'s `DriverPort` (`beam_rt/src/port/driver.rs`, `impl DriverHost for DriverPort`): it records replies in `outputs: Vec<Vec<u8>>` and `DriverPortAdapter::collect_outputs` pushes them through `ctx.input()`, so it must record `(header, Option<body>)` instead and deliver each split through `ctx.deliver_read(header, body)` — otherwise the runtime's loaded-driver path keeps the flattened shape the differential note in `erts_rust/tools/differential/src/corpus/driver_c.rs` records (`[97,98|<<99,100>>]` vs a flat `<<97,98,99,100>>`).

## Known gaps (honest, never a wrong result)
The NIF-side gaps are `../nif/CONTEXT.md`'s; the cross-cutting ones (undeclared header names, the malformed-term guard) are `../CONTEXT.md`'s.

- **`driver_outputv` with more than one remaining vector — the earlier vectors' nesting, never the bytes.** The seam carries one header byte stream and one tail, so only the **last** remaining vector can be the improper tail (exact, and every inet-driver read path is single-vector). In `[binary]` port mode the C makes each *preceding* vector its own binary cons cell (`[h… | <<v0>>, <<v1>>, …, <<vlast>>]`, `deliver_vec_message`, `io.c:3568-3614`) while this crate folds those bytes into the header's int list (`[h…, v0 bytes… | <<vlast>>`): the flattened byte sequence and `[list]` mode are identical, only the nesting of the earlier vectors differs. A malformed `ErlIOVec` (a declared `size` the vectors cannot satisfy) is refused `-1` instead of the C's over-read, and a null `buf` with a non-zero `len` is refused rather than dereferenced.
- **`driver_create_port` is the one driver-registry slot with no host half — a hard-coded failure sentinel.** The other three are served by `beam_rt`'s per-port `DriverHost` (`beam_rt/src/port/driver.rs`): `add_driver_entry`/`remove_driver_entry` (`:705`/`:711`) and `lock_driver` (`:724`, `io.c:7337`) over its own `DRIVER_ENTRIES` list, with its callback dispatch wrapped in `with_current_host` (the `publishing` helper, `:570`). No host supplies a live `PortRegistry`+`Poller`+driver-table reachable from a per-port `DriverHost`, so a `beam_rt` host answers the invalid-port sentinel (`:741-749`).
- **The `driver_binary_*_refc` trio refuses a NULL/foreign operand with `-1`** where the C would recover a bogus `Binary*` and crash (the count itself is oracle-exact).
- `driver_select`/`driver_set_timer`/`driver_cancel_timer`/`driver_read_timer`/`driver_async` forward to `DriverHost`, whose **defaults** report "unsupported" (`-1`/`None`): a host only records the request, so "the OS poller really woke the port" is a `beam_io`/`beam_rt` concern.
- **`driver_monitor_process`/`driver_demonitor_process`/`driver_get_monitored_process`** — the A.4 driver-monitor family. The **`beam_abi` half is complete**: all three C outcomes of `driver_monitor_process` are expressible (the three-way `DriverHost::monitor_process_result` / `MonitorResult` above — `0`/`1`/`-1`, `io.c:7012-7038`), the reason codes are honoured, the monitor's 24-byte identity is exposed safely (`monitor_identity`/`monitor_from_identity`), and `driver_compare_monitors` is a finished `memcmp`. The host half is owned by `beam_rt`/`beam_io`, which must implement `DriverHost::demonitor_process`/`get_monitored_process` and the monitor arming (registration, liveness, the per-port monitor tree) and fire `process_exit` (`io.c:6998-6999`, `:7065-7081`, `:7104-7118`, `:7150+`). **`beam_rt` should override `monitor_process_result`** instead of the two-way `monitor_process`: its `DriverPort` (`beam_rt/src/port/driver.rs:1112-1118`) currently returns `None` for both "no `process_exit`" and "the operand is not a local pid" — the first must stay `MonitorResult::Error` (`-1`, the C's `io.c:7055`) while the second must become `MonitorResult::NotAlive` (the C's `1`, `io.c:7031`), which the old `Option` hook could not express.
- **Three more `beam_rt`/`beam_io`-owned halves of the A.4 driver surface** (the operand handling and return-code mapping here are oracle-exact): `driver_pdl_create`'s per-port-stable handle (*`pdl`*), `driver_sizeq`'s empty-but-allocated queue answering `0` (*`queues`*), and `driver_async`'s `AsyncJob` (*The safe async-job runner*). The A.4 differential corpus exercises `beam_rt`'s `DriverPort` host, not `beam_io`'s `AbiHost`, so those fixes must land there.

## Test Strategy
- **Per-family end-to-end tests** — each `tests/driver_*.rs` compiles a real C fixture at test time with the system `cc` against the system OTP headers and `dlopen`s it (`RTLD_NOW`) through this crate's own loader, so a single unresolved `driver_*`/`erl_drv_*` import fails the load; `driver_binary_refc.rs` uses a dual-`driver_init`/`nif_init` fixture shared with the oracle run, and `driver_threads.rs` carries the extended `*_name` matrix (`"unknown"`).
- **Oracle cross-checks that really run** (they skip loudly without `erl`/`erlc`/`cc`): `driver_port_term.rs`, `erl_errno_id.rs` and `driver_failure.rs` run the *same* fixture `.so` under `erl_ddll:load_driver/2` + `open_port({spawn_driver,Name},[])` + `port_control/3` and compare the probe's printed lines with the **measured** oracle constants; `driver_failure.rs` additionally pins the closing family's `{'EXIT',Port,Reason}` (a `trap_exit` owner) and `{'DOWN',…,Reason}` (a monitor) plus the post-close `port_info`/`port_close` answers, deriving the expected reason from the `PortFailure` this crate hands the host so the two runtimes are cross-checked rather than compared with themselves.
- `driver_monitors.rs` cross-checks under `erl`/`erlc`, but its driver half prints a loud `SKIP:` in this sandbox (its ERTS exports `erlang:load_nif/2` but not `erlang:load_driver/2`), so the driver monitor expectations are pinned on the Rust side + the `io.c` ground truth.
- **`port_tests.rs` carries both halves of the `output2` contract**: a `SplitHost` (overrides `output2`, records `(header, body)`; its `output` records a "must stay empty" list) pins the split per entry point — `driver_output2` (three body shapes + a refused null-with-length + two replies staying two records), `driver_output` (null vs empty buffer), `driver_output_binary` (`H`+`cde`, zero-length range, over-read refusal), `driver_outputv` (last vector as tail, `skip` 0/5/8, a trailing zero-length vector ⇒ `Some(&[])`) — while `TestDriverHost` (no `output2` override, an `output` call counter) pins the **default** as byte-identical: exactly one `output` call carrying header-then-body for every shape.
- Gate: `../../../scripts/cargo.sh test -p beam_abi`; behavioural cross-checking against real ERTS is `erts_rust/tools/differential`'s job (sibling — read-only, escalate writes to this node).

## Notes for Agents
- The driver loader's ground truth is a different C file from the NIF's: `do_load_driver_entry` in `erts/emulator/beam/erl_bif_ddll.c` (the `errcode_tab` reason atoms included), `erts_sys_ddll_load_driver_init` in `erts/emulator/sys/unix/erl_unix_sys_ddll.c`, and `init_driver` in `erts/emulator/beam/io.c`; the term-data decoder mirrors `io.c`'s `ERTS_DDT_*`.
- A driver fixture must reference **only** `driver_*` slots the crate populates (`Some`), or `dlopen(RTLD_NOW)` fails on the unresolved import.
- `add_driver_entry`/`remove_driver_entry` have no port operand: they only work inside a callback that `beam_io::with_current_host` published, and answer the C's `-1`/`0` without dereferencing their operand.
- A `NULL` port operand is a **safety** divergence (the C faults); the `(ErlDrvPort)-1` sentinel is ABI fidelity (the C's own early return). Never widen either path to a dereference.
