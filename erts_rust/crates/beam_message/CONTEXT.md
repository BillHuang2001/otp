# `beam_message` — Copy Engine (`copy_struct`) & Messaging

## Intent
Owns the **copy half of the process memory model** — moving a term graph between two process heaps (`copy_struct`, plus the sharing-preserving `copy_struct_shared`) — and the data-level messaging built on it: the `Message` envelope, the per-process FIFO message `Queue`, `send`/`receive`, and the `HeapFragment`/`Fragments` model that homes a payload too large for the receiver's heap.
Implements Part II §C/§D (immutability bounds what may be shared; everything else is copied) and the Stage-3 row of Part II §H.
NOT here: the collector and the per-process heap (`beam_gc`, `beam_alloc`); the scheduler, selective-receive waiting, the save queue and signal ordering (`beam_process`); the `send`/`receive` BIF surface and pattern matcher (`beam_bifs`); the node registry itself (there is none in the workspace — see Design Decisions).
The send/receive **wake** is `beam_process`'s resume-on-send (`Process::deliver -> DeliverOutcome`, then `ProcessTable::drain_woken`/`Scheduler::resume_woken`); this crate supplies the data-level primitives the engine's receive family drives over the `Mailbox` seam.
Ground truth = the legacy C `erts/emulator/beam/`: `copy.c`, `erl_message.c`/`.h`, `erl_gc.c` (`OffHeap`/MSO sweep), `erl_node_tables.h` (node refcount). Read it; never modify it.
Per-module mechanisms, per-shape rules and C line citations: `src/CONTEXT.md`.
Per-test-file pins and the instrument recipes: `tests/CONTEXT.md`. Measured figures and repro commands: `PERF.md`.

## Inheritance (binding)
Obeys the crate-layer `../CONTEXT.md` contracts verbatim: frozen term layout (§2 — construct/inspect **only** through `beam_term`), return-based errors (§3 — `beam_common::Result<T>`, no panics, no crate-local error enum), `unsafe` confinement (marked modules, `# Safety`/`// SAFETY:`), `unsafe_op_in_unsafe_fn` clean, ~1000-line files, licensing Apache-2.0.
**Do not restate them here.**

## API Surface (the seam dependents design against)
Re-exported at the crate root and via `beam_message::prelude::*`; **per-module signatures, mechanisms and legacy-C provenance are in `src/CONTEXT.md`** — this section is only what a dependent must design against.

### Copying (`copy.rs`, `preflight.rs`, `share.rs`)
- `CopyContext::new(src: &OffHeapTable, dst: &mut OffHeapTable)` + `src_off_heap`/`dst_off_heap`/`dst_off_heap_mut` — the copy boundary, and **all** the source knowledge the copier has (no base/extent/heap identity).
- `copy_struct(term, to: &mut Heap, ctx) -> Result<Eterm>` — iterative **flat** copy of `term`'s graph through an explicit fix-up worklist (no native recursion, so a deep list cannot overflow the stack); it **shares** immediates, literal-area terms and `tuple0()`, and **copies** every other class (so a repeated subterm is duplicated).
  **Single-pass** whenever the destination off-heap table is empty (a dirty *heap* included): one copy traversal and no preflight at all; otherwise exactly **one** exact pricing walk, compared by the *caller* (`to.available() < needed`) — and a refusal writes nothing.
- `copy_struct_simple(term, to)` — the same over two throwaway tables (a graph with no off-heap references); `size_of_copy(term)` — `beam_term::size_object`, the flat **source** word count.
- `copy_struct_shared(term, to, ctx)` — the same policy with sharing preserved **once per source identity** (a from-space-address memo); the destination is sized as for `copy_struct`, the saving being in the words written.
- `preflight_words` (`pub(crate)`, the sole pricing entry point) and `shrink_warm_scratch()` (`pub`, the host's RSS lever after an outlier payload) — the price comes from `beam_term::size`'s policy walk on a **warm per-thread scratch**, with exactly two deltas from `size_object`: a literal-area subterm costs 0 destination words (and is not descended), and a no-handle refc binary costs its flattened window.
  `limit` is never consulted, a forged cycle is the typed `BadArg`, and the count is exact in both directions — which is what lets the typed refusal carry it.

### The envelope and the queue (`message.rs`)
- `Message` — payload + `from`/`token` + the off-heap objects it owns (the C `m[0]`/`m[1]`/`m[2]` plus the message's `off_heap`); builders `with_token`/`with_from`/`with_off_heap`/`with_binaries`/`with_nodes`/`with_fragments`, matching accessors plus `payload`/`fragments_mut`, and the relocation surface `with_payload`/`set_from`/`set_token`.
  A payload that fits the receiver heap lives **in that heap** with no fragments; a larger one lives in the message's `Fragments` and `payload()` points into them.
  Logical size: `heap_words()` — the sender copy-charge input, **heap words only** (an off-heap refc binary contributes just its 8-word handle); `logical_binary_bytes()` — the holder's virtual-binary-heap input, the summed `RefcBinary` payload lengths, `0` when none.
  **Envelope relocation invariant** (the GC-rooting surface): `payload` is relocatable via `with_payload`; `from`/`token` are relocatable in place (`set_from`/`set_token`); `off_heap`/`binaries` are **not terms** (refcounted handles over stable slots) ⇒ no relocation; `nodes` carries a sysname **atom** ⇒ immediate-required; `fragments` is not host-relocatable, the payload pointing *into* it, foreign to the collected nursery.
  So a host that stores a **heap** word in `from`/`token` must gather it as a GC root and scatter it back on every collection of the owning process; the immediate cases (a sender pid, a node atom, `NIL`) need no gather and are the only ones the enqueue tripwire admits.
- `Queue` — the per-process FIFO (a pure data structure, **no** scheduler coupling): `new`/`enqueue`/`dequeue`/`peek`/`len`/`is_empty`/`clear`/`iter`, plus the positional scan API `cursor()` (first message)/`cursor_at(position)`/`position`/`message_at`/`advance`/`remove_at` that the engine's candidate-by-candidate receive drives.
  **`QueueCursor` is a monotonic position, not a stable handle**: `advance` saturates past the end, every access is bounds-safe (`None` past the end), and `remove_at` shifts every later position down — so a cursor outstanding across a removal (including a *saved* one) is **stale**, and callers re-derive it with `Queue::cursor()`. The engine seam does exactly this: remove the match, then reset to the first message.
  The debug-only enqueue tripwire requires `from`/`token` to be genuine **immediates** (see above); `receive` uses the `pub(crate)` index-based `remove_index`.

### Sending, receiving and fragments (`mailbox.rs`, `fragment.rs`, `error.rs`)
- `send(from, term, to_heap, to_queue, ctx) -> Result<()>` — copy into the receiver heap, then drain **all three** destination off-heap categories into the `Message` (binaries, nodes, MSO handles); **atomic**: a payload that does not fit fails with `Alloc(AllocKind::Message)` leaving the heap, the destination table and the queue untouched.
- `send_fragmented(…, fragment_capacity_words)` — the fragment fallback (only `Alloc(Message)` triggers it), sized from that refusal's **own exact copier price** with `fragment_capacity_words` only a **floor**; the fragment carries its own off-heap table (the `ctx` destination table is unused on this path) and the enqueued `Message` owns the `Fragments` — one fragment per send, never a chain.
- `send_fragmented_after_refusal(from, term, to_queue, src_off_heap, fragment_capacity_words, requested_bytes)` — the route for a host that **already holds** the refusal: no receiver heap, no trial, no pricing walk. Its precondition is an **optimality** claim (the figure only decides the reservation), never a correctness one.
- `receive(queue, pred) -> Option<Message>` (remove and return the first match — the selective-receive skeleton) and `receive_ref` (non-destructive); waiting, `after` timeouts, the save queue and signal ordering are `beam_process`'s.
- `HeapFragment`/`Fragments` — a bump region with its own off-heap table and roots (`copy_root` refuses up front, so a refusal is never a partial write) and the ordered chain with `total_used_words`/`off_heap_overhead_bytes`.
  `Fragments::move_into(dst, dst_off_heap) -> Result<Vec<Eterm>>` is the one-shot move: every root re-copied into `dst` (fresh slots), refc binaries and MSO objects moving as **handles** (same `data_ptr`, refcount incremented, never deep-copied), the fragment's own references released only after the **whole chain** copied — so a mid-move failure leaves the chain intact and retryable.
- `is_message_heap_exhaustion(error)` — the **soft, recoverable** destination-message-heap classification (`Alloc` with `kind == AllocKind::Message`).

### The off-heap table and node identity (`off_heap.rs`, `node.rs`)
- `OffHeapTable` — a **slot-indexed** table of `beam_gc::MsoHandle`s (slot = the on-heap off-heap reference's `val` word) as a thin façade over `beam_gc::OffHeap`, plus the refc-binary and node lists that ride along with a copied message: `push`/`get`/`clone_slot` (refcount++), `push_binary`/`binary_at`/`binary_by_data_ptr` (resolves a `BinRef.val` to its owning handle), `push_node`/`node_by_identity`, and the `drain_*`/`into_handles` exits. `Drop` releases the node references it registered.
- **Ownership traps** (load-bearing for any pruning argument): `len`/`is_empty`/`iter`/`overhead_bytes` cover the **MSO list only** (`is_fully_empty` is the all-category test); `push_binary` **never deduplicates** and `binary_by_data_ptr` returns the first match; there is **no single-entry removal** — a binary list is pruned all-or-nothing (`drain_binaries`) or wholesale (`rollback`, sound only on a table that started empty); dropping an entry while a live `BinRef.val` names its `data_ptr` is a use-after-free; slots are stable and this table never sweeps.
- `NodeEntry` — a refcounted `(node atom term, creation)` identity (`new`/`node`/`creation`/`refcount`/`same_node`/`identity_eq`/`handle`), `Clone`-free by design: the count tracks *references registered in a table*, not handles.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only.** A destination-heap exhaustion ⇒ `BeamError::Alloc(AllocFailure::new(AllocKind::Message, words * size_of::<Eterm>()))`, recognisable through `is_message_heap_exhaustion`. **Never panic**, never a crate-local error enum, never `unwrap()` on runtime data.
- A malformed/unsupported term layout, a **non-term** (bare header word incl. `THE_NON_VALUE`), a **cyclic** forged graph, or an out-of-range MSO slot ⇒ `BeamError::BadArg` (typed, never a hang, never a partial write); a refc binary whose payload no held handle owns is **not** malformed — it is flattened.
- **`unsafe` is confined to `copy.rs` and `preflight.rs`** (the raw word read/write of the copy loop and the two raw-word reads refc-binary pricing needs) and the narrow `layout.rs` accessors; every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale; `share.rs`, `fragment.rs`, `off_heap.rs`, `message.rs`, `mailbox.rs`, `node.rs`, `error.rs` are safe Rust; `unsafe_op_in_unsafe_fn` stays clean.
- **Never assume a different `Eterm` layout** — read headers/words through `beam_term` accessors. The frozen word layouts (cons `[CAR,CDR]`, header words, `BinRef [thing_word,val,next]`, the `[BinRef(3)][ErlSubBits(5)]` refc pair, `ExternalThing [header,node,next,data]`) are the §2 contract; interiors that are not externally pinned are read through the owning accessors (e.g. the HAMT node shapes via `map_header_type`/`map_header_val`/`header_arity`), never re-derived.
- **`copy_struct_shared` reuses `copy.rs`'s `shallow` primitive** — the copy logic exists once.
- **Deps (`Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`, plus `beam_codec` (consumed only by `tests/{identity,fun}.rs`) and `libc` (declared, unused). No new external dependencies.
- Files target ~1000 lines; one responsibility per file. Licensing Apache-2.0.

## Design Decisions
- **Fidelity scope: a correct, iterative *tree* copy, not the C's single-allocation `htop`/`hbot` layout.** Each object is allocated *incrementally*, parent before child (so the outer-before-inner invariant `copy_ets_element` needs still holds), with an explicit worklist for fix-ups — no native recursion.
- **Sharing policy matches the C's tree copier.** Only immediates, literal-area terms (the `TAG_LITERAL_PTR` bit, tested *only* on a genuine term word) and the zero-arity tuple are shared; everything else is copied, so a repeated subterm is duplicated by design. The **message** path agrees (the C send uses the `*_litopt` forms with a stack literal area), so a payload that is a module literal costs the **outer** object only on both runtimes.
- **The capacity preflight is `beam_term::size`'s policy-parameterised walk on a warm per-thread scratch, and it is ONE walk.** The DFS, the per-shape interior table, the cycle verdict and the walk's own cost are `beam_term::size`'s; this crate keeps no walk of its own (the two pricing deltas and the exactness argument are in `src/CONTEXT.md`).
- **The pricing scratch is a thread-local, not a `CopyContext` field** — every `CopyContext` in the workspace is constructed per call, so a context field would be cold at each one — and it is **not a GC root holder**: it is cleared before each walk, holds stack steps and source addresses only, and is never registered or scanned.
- **An oversized message is priced once, not once per attempt** — the refusal's `AllocFailure::requested` **is** the copier's exact destination price, so the fragment is reserved from it directly; a stale figure costs only a less exact reservation.
- **The single-pass fast path is sound precisely because the destination off-heap table is empty** — the trial writes only the heap's unused tail and commits with one `alloc_words`, so a failed attempt needs no heap rewind (and `to.reset()` would be *wrong* on a dirty heap), and only `OffHeapTable::rollback` runs. The gate is the off-heap table's emptiness, **not** `to.used() == 0`.
- **Non-term and cyclic graphs are typed errors, never wrong results or hangs.** `is_shared` requires a genuine term word before testing the literal bit (otherwise a bare `HEADER` word would be mis-shared and cross the boundary undetected); a non-term then reaches `shallow`'s header arm ⇒ typed `BadArg`, writing nothing.
- **Allocation failure is `AllocKind::Message` — the message-heap contract, soft/recoverable** (a host may grow-and-retry, or raise `error:system_limit`). The kind stays `Message` deliberately: `beam_rt::RuntimeContext::deliver_message` keys on the raw kind as the oversized-message **retry trigger**, and this copy's destination *is* the message/receiver heap.
- **The sharing-preserving copier is opt-in and additive** (`copy_struct` keeps the C default's flat behaviour), and where the C keys sharing on the from-space address with destructive in-place markers, Rust keeps a real `HashMap` — no source-heap mutation. It preflights the *flat* count, a safe upper bound.
- **MSO is reused from `beam_gc`, never reimplemented** — the object, its atomic `RefCount`, `MsoHandle` and the per-process list are all `beam_gc::mso`'s, so `off_heap.rs` holds no duplicate MSO storage and invents neither an object model nor a refcounting scheme.
- **Off-heap reference term — the M1 encoding (documented substitution).** A standalone off-heap reference is the frozen `BinRef` container thing (3 words) with **`val` = the MSO slot index** into the owning process's `OffHeapTable` and **`next` unused (`0`)**; copying one resolves the source slot, **clones the handle** (refcount++), pushes it into the destination table and writes the **new** slot — the payload is never deep-copied.
- **Refc binaries share the payload; small binaries are copied by value.** The on-heap refc binary is the frozen 8-word pair `[BinRef(3)][ErlSubBits(5)]` tagged at the `ErlSubBits`, with **`BinRef.val` = the payload's first data byte** = `RefcBinary::data_ptr()` (always distinct from the standalone MSO container). Its copy resolves the owning `RefcBinary` handle from the **source table by that data pointer**, refcounts it into the destination binary list, writes a fresh pair with the window kept verbatim and the **same** payload pointer, and fixes the copied `ErlSubBits.orig` up to the **copied** `BinRef` — the fix-up an opaque-leaf treatment would leave dangling. A small `ErlHeapBits` binary has no navigable child and is copied verbatim.
- **A `SUB_BITS` match context, and a refc binary with no owning handle, are flattened rather than copied verbatim** — a fresh on-heap bitstring for the window `start..end`, so the copy carries no `base_flags`/`orig` pointer into the source heap, and nothing is registered (there is no handle to refcount).
- **External pid/port/reference nodes: refcounted per identity, modeled locally.** There is no node-registry crate and no `ErlNode *`, so the identity is `NodeEntry = (node atom term, creation)` plus an explicit atomic refcount (the same M1 substitution `beam_term::thing` documents) living on `OffHeapTable`, and the count is the number of references **the registering table** holds, deduped to one entry per distinct node.
- **The message-fragment move is a copy + release, not the C's in-place move markers** (a Rust term holds slot indices, not object pointers, so there is nothing to relink): the **net refcount is unchanged** — one increment from the copy, one decrement from the release. The fragment's backing `Heap` is a separate, never-moving allocation, so a root's address — and therefore `Message::payload` — stays valid as the `Message` moves.
- **Per-object sizing and the whole-graph count both come from the LCA** (`beam_term::layout::object_words`, and `beam_term::size` driven by `CopyPricing`), whose enumerators cover every HAMT node kind — so a hash map copies as a whole trie and a widened fun descriptor is sized and copied automatically.

## Test Strategy
- Per-module `#[cfg(test)] mod tests` (one per `src/` module) plus one `tests/*.rs` file per contract area; every file and its pinned claims is in `tests/CONTEXT.md`.
- **The destination-pricing walk is pinned equivalent to a bounded reference walk.** `src/copy_reference.rs` (`#[cfg(test)]`-gated) holds the bounded walk (`bounded_words_reference`/`is_acyclic_reference`/`preflight_words_reference`) as a test-only oracle, and five tests assert the shipped walk returns the *same* `Ok(n)` and the *same* rendered refusal over a **35-term corpus** covering every term class the copier prices (a refc binary handled and unhandled included, the two prices asserted *different* to prove the policy reads the `CopyContext`) at every limit `0..=count+2` and `usize::MAX`, that both walks refuse every forged cycle at every finite limit, and that the shipped walk also refuses a cycle **promptly at `usize::MAX`**.
  The two walks have no remaining pricing delta on any header — the shared empty-tuple guard is the same literal-tagged predicate on both sides, so a forged zero-arity `RECORD` header (reachable only through `make_record_header(0)`) costs its structural `arity + 1 == 1` word in both.
- Named pins: `a_one_word_short_destination_is_refused_before_any_write` (`sizing.rs`), `a_literal_child_costs_zero_destination_words_although_size_object_counts_its_interior` and `a_no_handle_refc_binary_costs_the_flattened_window_and_a_size_object_destination_is_refused` (`destination_pricing.rs` — the two pricing deltas), `a_refused_copy_into_a_dirty_heap_leaves_the_live_words_intact` (`single_pass.rs`), `a_rejected_send_is_a_total_no_op` (`queue.rs`), `a_failed_move_into_leaves_the_chain_intact` (`fragments.rs`).
- **Instruments** (all carry figures only into `PERF.md`, and assert correctness only — never a timing threshold, a walk count or an allocation count): `tests/traversals.rs` (the primary structural signal, plus `report_a_warm_preflight_allocates_nothing` for the cold→warm→shrunk-cold scratch contract, both tests serialised on a `MEASUREMENT_LOCK` because the counting `#[global_allocator]` is process-wide), `tests/counters.rs`, `tests/identity.rs` (correctness, no figure), `tests/perf.rs`, `tests/send_perf.rs`.
  Every counter window must be **identical** across `REPEATS`, so a stray allocation fails the run instead of inflating a count.
- Gate (GREEN required): `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_message` and `… build … --workspace --all-targets`; always through `../../scripts/cargo.sh` (`$HOME` is read-only), never `cd`, never touch `../../tools/`.
- This crate's tests are **all self-checks** (structural `compare::eq`, word-count arithmetic, refcounts, exact counters) — no test in `src/` or `tests/` invokes `erl`/`erlc`.
  Cross-checks against the real system ERTS belong to the sibling `../../tools/differential/` harness; its per-case route (`differential run <case-id> --out <dir under $TMPDIR> …`) over the messaging/copy/driver/wire families (`bifs`, `driver*`, `wire*`, `etf`, `binary`, `terms`, `maps`, `gc`, `fun_info`, `semantics`, `records`, `errors`, `decode_packet`) agrees with the OTP-29.1.1/erts-17.1 oracle, the only non-`agree` case being the recorded A.5 gap `wire/new_fun_ext_encode`. **Pass `--out`** (the default report dir is inside the sibling node) and note `run` takes no `--strict`.
- The workspace `cargo test` gate runs in CI (`.github/workflows/erts_rust.yml`, path-triggered on any `erts_rust/**` change or PR): workspace test command, non-blocking clippy, differential gate.

## Performance (measured)
Every figure and its caveat lives in `PERF.md` (`§2` the deterministic per-shape structural table = the primary signal, `§7` the bench A/B over `copy_bound`, `§10` what remains by owner); prefer ratios over absolutes. Summary of what it establishes:
- **One walk per send shape.** A **fit** costs one copy traversal and **no** pricing walk. A **refusal** costs one abandoned optimistic trial (nothing written) plus **one** exact pricing walk whose figure the typed `Alloc(Message)` carries; a fragmenting caller then adds **one** copy into the fragment, and a host holding the refusal via `send_fragmented_after_refusal` adds no second walk. A destination with a **non-empty** off-heap table is the one shape that prices *and* copies.
- **The pricing walk is allocation-free once the thread's scratch is warm** — a refusal's heap cost is then the copy's own fix-up worklist, **2 blocks / 192 B**, where a cold scratch pays **9 blocks / 1 452 B** (the walk's own 7 blocks / 1 260 B are the difference). The preflight's time share on a 4-word tuple is **17.8–20.2 ns** and the isolated `perf` probe retires **−9.0 %** instructions versus a binary without the retained scratch.
- **Per-message heap allocation is the fix-up worklist alone**, and it is not a wall-clock lever: for the `copy_bound` payload the copy step allocates 2 blocks / 192 B and the enqueue half 0; the first send into a **cold** mailbox pays one further 480 B block (the queue's first buffer, once per mailbox). An inline `MaybeUninit` worklist measured neutral on the payload and 17 % slower on a 10-cons list, so the `Vec` stays.
- **The whole `send` for the `copy_bound` payload is ≈ 200 ns in release**, and this crate is **≈ 13–19 %** of the `send_recv_plain` per-op cost (a lower bound — that workload performs two payload sends per op). The `gc_class/send_recv` two-process round trip improved **1.17×** at the same load (paired estimator; `copy_bound` is the flat control), i.e. 8.08× → 7.00× the re-measured system-ERTS denominator.
- The two-process `copy_bound` figures are **`beam_rt`'s**, not this crate's: the residual is the sender/receiver schedule's per-slice work, not a pass sleep. Measure this crate's share from `tests/send_perf.rs`, never from the two-process case; `etf_roundtrip` remains `beam_codec`'s.

## Known Issues / Intentional M1 gaps
Each entry names the crate/node that owns closing it; a gap another crate owns is restated as an adoptable signature in `## Handoffs`.
- **A destination with a non-empty off-heap table is the one shape that must price *and* copy, and it cannot be made single-pass yet** (owner: `beam_message`).
  The heap half exists (`beam_alloc::Heap::reset_to(used)` rewinds to a `used()` mark, keeps the live prefix, refuses a mark beyond it) but the off-heap half does not: `OffHeapTable::rollback` drains all three lists, so it is sound only on a table that started empty.
  Closing it needs an `OffHeapTable::checkpoint() -> OffHeapCheckpoint` / `rollback_to(&mut self, cp)` pair releasing exactly the entries pushed since the checkpoint.
- **One exact price and a fits/doesn't verdict still cost one walk each** (owner: `beam_term::size`). `preflight_words` needs one walk only because it runs the bounded walk unbounded; a caller wanting an exact count **and** a work limit pays `is_acyclic` on the `OverLimit` arm. A bounded fixed-stack cycle check would remove even that (the legacy C has no cycle check at all), provided a cyclic graph still yields a safe `BadArg`.
- **A pricing scratch retains its high-water-mark buffers** (owner: the host, via `beam_message::shrink_warm_scratch`): one enormous payload leaves the thread's buffers at that size for the thread's life, which is the price of the walk being allocation-free; `shrink_warm_scratch()` hands them back and changes no result.
- **A flattened no-handle refc binary may exceed `ERL_ONHEAP_BITS_LIMIT`** (owner: `beam_message` if the limit is ever enforced; until then the caller's registered handle is the guard). `copy_match_context` writes the window with `write_heap_bits` and does not enforce the on-heap limit (the C's `HEAP_BITSTRING` only asserts it), so a payload whose handle no source table holds lands as an on-heap bitstring larger than ERTS would ever build there; the copy stays correct and self-contained, only the term's shape is one the emulator does not produce.
- **No message-queue placement state and no auto-tuning: a mailbox is always on-heap** (owner: `beam_process`, with `beam_rt` for the flags that name it). This crate's `send` vs `send_fragmented` choice *is* the placement decision; no crate has the C's per-process `ERTS_MESSAGE_QUEUE_DATA_ON_HEAP`/`_OFF_HEAP` state, `erts_change_message_queue_management` or the static `SPO_ON_HEAP_MSGQ` sizing rule, and `+hmqd` does not exist as a CLI flag. `{message_queue_data, off_heap}` is accepted-and-ignored by `beam_rt`'s `spawn_opt`/`process_flag`, so `process_info(P, message_queue_data)` always answers the true current `on_heap`.
- **The logical-size surface is exposed but nothing charges it** (owner: `beam_rt`; both adoptions are in `## Handoffs`): no send site charges the sender's copy cost, and `Message::logical_binary_bytes()` never enters a process's binary virtual heap — the accounting that exists (`beam_gc::BinVheap`, driven per process by `beam_rt`'s `OffHeapReclaimer`) is fed from the machine's payload overhead instead.
- **A received message's off-heap families are retained, never reaped** (owner: `beam_rt::mailbox::MailboxState`, adopting `beam_process`'s existing sweep): the receiving host clones them into `MailboxState::retained_binaries`/`retained_off_heap`/`retained_nodes` (and `retained_fragments`) before the `Message` drops, and that state is never cleared, so a received payload stays alive until the runtime drops. `Process::sweep_off_heap_binaries_reachable` reclaims only the machine-built payloads registered in `owned_binaries`; a **fragmented** message is unaffected either way, its envelope lists being empty and its off-heap objects living in the fragment's table until `Fragments::move_into` hands them to the destination table.
- **No producer fills `Message.token`; it stays `NIL`** (owner: `beam_rt`): `with_token`/`set_token` and the relocation surface exist and `beam_process`'s collection already gathers and relocates the word, but nothing stamps a token (`beam_rt/src/seq_trace.rs` lists token propagation as deliberately out of scope — the send event is emitted from the sender's own token instead). Stamping one also needs this crate's debug-only enqueue tripwire relaxed, since a token tuple is a heap term.
- **The external EMQX messaging target is an honest skip** (owner: `tools/bench`): `RESULTS.md` records `emqx` → `skipped(emqx-requires-otp-28)` (the checkout pins OTP 28.5.0.7-2, the host is OTP 29.1.1), so it contributes no figure; the messaging category is measured in-repo by `copy_bound` (`Category::Messaging`, both runtimes).
- **A payload word that points into a fragment has no lifetime tie to it** (owner: any host of this crate; `beam_rt` today satisfies it by never releasing a `MailboxState`). `Message::payload` and `HeapFragment::copy_root`/`roots` hand the root out **by value** as a bare `Eterm` while the fragment's words live in a standalone `beam_alloc::Heap` block that `Heap`'s `Drop` frees the moment the `Fragments` chain drops (a dequeued/dropped `Message`, `Queue::clear`), so such a word is valid only while the owning `Message`/`Fragments` is alive. `HeapFragment::push_root` and `Message::with_payload` are safe but **unvalidated**: nothing checks that the word points into the region a later `move_into` reads. Moving a `Message` is fine — the block address is stable, only the `HeapFragment` struct moves.

## Handoffs
Gaps whose owner is another crate, each with the exact API this crate adopts once it appears (or the exact call site the owner must add).
- **The sender's copy charge** — owner `beam_rt`, with `beam_common` supplying the divisor. The C charges `min(msize / ERTS_MSG_COPY_WORDS_PER_REDUCTION, CONTEXT_REDS)` reds to the sender at queue time; `beam_common` hosts `CONTEXT_REDS` but no divisor, and no `beam_rt` send site charges anything. Adoptable shape: the existing `beam_process::Process::bump_reductions(&mut self, n: u64)` fed with `beam_common::CONTEXT_REDS.min(4 + Message::heap_words() / ERTS_MSG_COPY_WORDS_PER_REDUCTION) as u32` at every send site. No change needed here — `Message::heap_words()` is the input.
- **The message path never feeds the holder's virtual binary heap** — owner `beam_rt` (the accounting is `beam_gc`'s). `beam_gc::BinVheap` exists (`new` starts at the policy's `min_bin_vheap_words`; `triggered`/`record_collection` are the trigger and the post-collection re-seed) and `beam_rt`'s `OffHeapReclaimer` drives it from `Machine::off_heap_overhead_bytes()`; what is missing is the message half — `Message::logical_binary_bytes()` never enters that budget, no `bin_vheap_size`/`virtual_reds` figure is reported, and `beam_process::Process` models no binary vheap of its own.
- **Message-queue placement and auto-tuning** — owner `beam_process`. Adoptable shape: `pub enum MessageQueueData { OnHeap, OffHeap }`; `Process::set_message_queue_data`/`message_queue_data`; and the decision itself, `Process::plan_message_placement(&mut self, heap_free_words, payload_words) -> MessagePlacement` with `pub enum MessagePlacement { OnHeap, Fragment { capacity_words } }`. Consumers: `beam_rt`'s send path routes `Fragment` to `send_fragmented` and `OnHeap` to `send`; `spawn_opt`/`process_flag`/`+hmqd` store and parse the flag instead of accepting-and-ignoring it.
- **Token stamping** — owner `beam_rt`. At each send site, `Message::with_token(t)` with `t` the `{Flags,Label,Serial,From,Lastcnt}` tuple for a sender whose token has `seq_trace::FLAG_SEND` (`seq_trace.rs`'s `sequential_trace_token` already builds it). Prerequisite here: relax `debug_assert_enqueue_terms` (a token tuple is a heap term); `beam_process`'s `run_rooted_collection` already gathers and relocates the word.
- **Reaping a received message's off-heap families** — owner `beam_rt`, no new sibling signature needed. In `mailbox::MailboxState::remove_at`, register each `Message::binaries()` payload through `Process::register_off_heap_binary(binary) -> usize` (so `sweep_off_heap_binaries_reachable` reclaims it) and each `Message::off_heap()` handle through `Process::off_heap_mut()`, instead of only cloning them into the never-cleared `retained_*` vectors — which then become a per-scan cache rather than ownership.
- **A runnable `emqx` profile** — owner `tools/bench`: `Workload::probe` must answer `Probe::Ready` for `emqx` on the host it runs on (an OTP-28-matching runner image, or a checkout whose pin matches the host).
- **One walk yielding both the exact price and the fits/doesn't verdict** — owner `beam_term` (`src/size.rs`). Adoptable shape: `size_object_measured_with(a, limit, policy) -> Result<MeasuredSize, TermError>` with `enum MeasuredSize { Acyclic { words, fits }, Cyclic { words } }` — the walk **latches** "over limit" instead of returning early, so both answers come from one traversal and a limit stops being a work bound. A bounded fixed-stack cycle check would remove the second traversal entirely, provided `SizingPolicy::object_words` returning `Some(0)` for a cyclic graph stays a safe answer.
- **`send_recv` vs `send_recv_plain`** — owner `beam_codec`: the delta between those cases (`PERF.md` §6) is the worker's `binary_to_term(term_to_binary(T))` round trip, **not the copy** (the plain case's payload copies are 3 words, the literal being shared). Measure the codec's share before claiming any part of that pair.

## Notes for Agents
- **Rooting rules** (the correctness envelope of this crate's seam):
  (a) A raw `Eterm` in a long-lived slot **roots nothing** — `beam_process`'s collection gathers only each queued `Message`'s **payload**, which is why `from`/`token` must be immediates (the debug tripwire enforces it) and why a word pointing into a `Fragments` region is valid only while that `Message` lives.
  (b) A pointer-stable, never-scanned side store is **not** a scan root: `OffHeapTable`'s MSO/binary/node lists are refcounted handles (correct without scanning) and the preflight scratch holds stack steps and source addresses only — neither can keep a *term* alive.
  (c) An exempted move must **stabilize, never dangle**: the only exempted relocation surface is the envelope (`with_payload`/`set_from`/`set_token`), and the fragment block's address is stable, so moving the `Message`/`Fragments` never moves a payload's words.
  (d) A refcounted lease held across an allocation is **not a cheap borrow**: `RefcBinary`/`MsoHandle` clones bump a real refcount, and dropping one while a live `BinRef.val` still names its `data_ptr` is a use-after-free; `NodeEntry::handle()` is the observation-only case (registers no reference).
- **The copier takes the source as a bare `Eterm` and holds NO source-region knowledge.** `CopyContext` has exactly two fields (`src`/`dst` `OffHeapTable`), and the walk dereferences whatever the graph says; source-word guards are **tag tests only**, so a stale `LIST`/`BOXED`-tagged pointer into a reset/pooled `beam_alloc::Heap` or a `beam_ets::TermStore` passes every one of them.
- The crate's only region-membership test is **destination**-side: `HeapFragment::contains` (`hend - capacity`..`hend`). There is no source-side equivalent, and `beam_alloc::Heap` exposes no `base()`/live-region registry, so "is this word in a live term heap" is not askable anywhere in the workspace.
- `copy_match_context` flattens by reading `base_flags` as the payload **base pointer** and `start..end` as the extent, with no liveness or plausibility check — the fallback path dereferences a pointer whose owning handle need not exist.
- `copy_struct_shared`'s memo keys on the source **address**, so an address-coincident stale pointer aliases a real subterm's copy — wrong sharing, not a fault.
- **What the copier *does* guarantee: a completed copy is self-contained.** Every child slot `beam_term::layout::for_each_child_slot` reports (tuple/record elements, fun env, flatmap keys+values, HAMT slots, an `ErlSubBits`'s `orig`) is re-copied or fix-up'd and that enumeration covers every term class, so a **live** source graph yields a destination naming nothing outside it except the shared classes — provenance is unaskable, but a completed copy is not a leak.
- **The two verbatim survivors are the escape hatches**: `is_shared` returns a literal-tagged compound unchanged without descending it or recording a fix-up (so a literal-tagged word into non-permanent storage would cross verbatim), and the `PrimaryTag::Immed1` arm returns `src` unchanged. No producer tags anything but a module literal area today (`beam_term::literal::tag_literal_area`, called from `beam_loader`'s `LiteralArea::decode`).
- **`copy_struct_simple` *is* `copy_struct`** (two throwaway tables), so over a foreign source it **flattens** every refc binary (no handle in the empty source table ⇒ the window deep-copy) and refuses an MSO container with a typed `BadArg` (`clone_slot` → `None`); its local `dst` table drops at return, releasing only node references.
- The copier **never writes the source**: it writes the destination through `reserve`, plus — on the fast path only — the destination's *unwritten* tail, committed with one `alloc_words`. Destination `&mut Heap` + `&mut CopyContext` make one copy exclusive and non-reentrant by borrowck; there is no global copier state.
- **Identity is preserved only *within one call*.** `copy_struct_shared`'s memo is a local `HashMap` dropped at return and is not exposed, so copying a **root set** in N calls duplicates every subterm shared *between* roots — `Fragments::move_into` does exactly that (one `copy_struct`, one `CopyContext`, per root). Off-heap registrations are not deduped across calls either: every occurrence of an MSO object clones the handle into a **fresh** slot and every occurrence of a refc binary pushes another handle (`push_binary` never dedupes), so a re-copy into a live destination table grows it by one entry per occurrence and the only release is the wholesale `rollback`.
- **A constant-delta move is not something this crate can do.** Interior pointer words are rewritten only for a *copy* (fresh objects at fresh addresses); there is no delta-rebase pass and no `Target` seam a foreign region could implement (`CopyTarget` is `pub(crate)`). The workspace's cheap move primitive is `beam_alloc::ReservedHeap::relocate`, which returns a byte delta and leaves interior pointers to the caller; the descent set such a rebase must cover is exactly the one `tests/guards.rs` walks — cons/2 words, tuple/record elements, a fun's **env only**, flatmap keys+values, HAMT slots, an `ErlSubBits`'s `orig`, and a refc binary's on-heap pair (never the shared payload pointer).
