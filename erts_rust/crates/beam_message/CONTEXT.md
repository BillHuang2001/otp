# `beam_message` — Copy Engine (`copy_struct`) & Messaging
## Intent
Owns the **copy half of the process memory model** — moving a term graph between two process heaps (`copy_struct`, plus the sharing-preserving `copy_struct_shared`) — and the data-level messaging primitives built on it: the `Message` envelope, the per-process FIFO message **queue**, `send`/`receive`, and the **message-fragment model** (`HeapFragment`/`Fragments`) homing a payload too large for the receiver's heap.
Implements Part II §C/§D (the messaging/ETS copy boundary: *immutability bounds what may be shared; everything else is copied*) and the Stage-3 row of Part II §H.
Sibling responsibilities (NOT here): the collector and the per-process heap (`beam_gc`, `beam_alloc`); the scheduler / selective-receive waiting / save queue / signal ordering (`beam_process`); the `send`/`receive` BIF surface and pattern matcher (`beam_bifs`); the node registry itself (there is none in the workspace — see Design Decisions).
Ground truth = the legacy C `erts/emulator/beam/`: `copy.c` (`copy_struct_x`, `size_object_x`, `copy_shared_calculate`/`copy_shared_perform_x`, `erts_move_multi_frags`), `erl_message.c`/`.h` (`ErtsMessage`, `ErlHeapFragment`, the queue, `erts_try_alloc_message_on_heap`/`new_message_buffer`/`erts_link_mbuf_to_proc`), `erl_gc.c` (`OffHeap`/MSO sweep, `erts_copy_one_frag`), `erl_node_tables.h` (`erts_ref_node_entry`/`erts_deref_node_entry`). Read the C; never modify it.
## Inheritance (binding)
Obeys the crate-layer `../CONTEXT.md` contracts verbatim: frozen term layout (§2 — construct/inspect **only** through `beam_term`), return-based errors (§3 — `beam_common::Result<T>`, no panics, no crate-local error enum), `unsafe` confinement (marked modules, `# Safety`/`// SAFETY:`), `unsafe_op_in_unsafe_fn` clean, ~1000-line files, licensing Apache-2.0.
**Do not restate them here.**
## API Surface (the seam dependents design against)
Re-exported at the crate root (`src/lib.rs`) and via `beam_message::prelude::*`; the per-class copy mechanisms are in Design Decisions.
### `copy.rs` — the copy engine (the `unsafe` core)
- `pub struct CopyContext<'a>` — the copy boundary: the source process's off-heap table (resolving off-heap references) and the destination's (re-registering them).
  `CopyContext::new(src: &'a OffHeapTable, dst: &'a mut OffHeapTable) -> CopyContext<'a>`; `src_off_heap(&self)`, `dst_off_heap(&self)`, `dst_off_heap_mut(&mut self) -> &mut OffHeapTable` (the table `send` drains into the message).
- `pub fn copy_struct(term: Eterm, to: &mut beam_alloc::Heap, ctx: &mut CopyContext<'_>) -> Result<Eterm>` — iterative **flat** copy of `term`'s graph into `to` (an explicit worklist, no native recursion, so a deep list cannot overflow the stack), returning the copied root; it shares immediates and literal-area terms and copies every other class, per the per-class copy policy in Design Decisions.
  **Single-pass** (`try_copy_fast`) whenever the destination off-heap table is empty (a dirty *heap* included); otherwise the cycle-safe bounded `preflight_words(term, limit, ctx)` runs before any write, so a refusal writes nothing — the error classification is in Constraints.
- `pub fn copy_struct_simple(term: Eterm, to: &mut beam_alloc::Heap) -> Result<Eterm>` — `copy_struct` for empty off-heap tables (a graph with no off-heap references).
- `pub fn size_of_copy(term: Eterm) -> usize` — forwarder to `beam_term::size_object` (the flat word count), exposed so a caller can size a destination.
- `pub(crate) trait CopyTarget` + `struct TrialTarget` + `fn is_fast_path_eligible` / `fn try_copy_fast` — the destination abstraction: `Heap` reserves per object, `TrialTarget` bumps over the destination heap's unused tail `[to.hp(), hend)` (`free = to.available()`) counting `written` without touching `used`/`peak`; `is_fast_path_eligible` = `ctx.dst_off_heap().is_fully_empty()` (`is_fully_empty`/`rollback` are `pub(crate)` on `off_heap.rs`).
### `share.rs` — the sharing-preserving copier
- `pub fn copy_struct_shared(term: Eterm, to: &mut beam_alloc::Heap, ctx: &mut CopyContext<'_>) -> Result<Eterm>` — the sharing-preserving copier: `copy_struct`'s immediate/literal/off-heap-node policy and iterative worklist, but each compound subterm is materialised **once per source identity** through a `HashMap<usize, Eterm>` memo keyed on the from-space term address (immediates and literal-area terms are never memoised); the rationale is in Design Decisions.
  It preflights through the same `copy::preflight_words`, so the destination is sized as for `copy_struct` — the saving is in the words written.
### `fragment.rs` — the message-fragment model (`ErlHeapFragment`/`ErtsMessage` analogue)
- `pub struct HeapFragment` — a bump-allocated heap region plus its off-heap objects and its roots, mirroring the C `ErlHeapFragment` (`{ next; off_heap; alloc_size; used_size; mem[1]; }`).
  `new(capacity_words)` / `with_allocator(alloc, capacity_words)`; `heap()` / `heap_mut()` (the `mem[1..alloc_size]` region); `off_heap()` / `off_heap_mut()`; `used()` / `capacity()` / `available()`; `off_heap_overhead_bytes()` (the C `ErlOffHeap.overhead`); `push_root(Eterm)`, `roots() -> &[Eterm]` (the payload roots, `m[0]` pointing into `mem`), `contains(term) -> bool`.
  `copy_root(term: Eterm, src: &OffHeapTable) -> Result<Eterm>` — copies `term` from a process whose off-heap table is `src` into the fragment's heap, refcounts its off-heap references into the **fragment's** table (fresh slots), records the result as a root and returns it (the C `new_message_buffer` + the copy step of `erts_try_alloc_message_on_heap`); a fragment too small for the payload is refused up front, so it performs **no partial write** (roots stay empty, `used()` stays `0`).
- `pub struct Fragments` — an ordered chain of `HeapFragment`s (the C `ErlHeapFragment.next` chain): `new()`/`Default`, `is_empty()`, `len()`, `push(HeapFragment)`, `iter()`/`iter_mut()`, `total_used_words()` (the process message-buffer accounting — `used_size` summed), `off_heap_overhead_bytes()`.
  `move_into(dst: &mut Heap, dst_off_heap: &mut OffHeapTable) -> Result<Vec<Eterm>>` — the one-shot move entry point (the `erts_move_multi_frags`/`erts_copy_one_frag` analogue): each fragment in order copies each root with `copy_struct` (the fragment's table as source, `dst_off_heap` as destination), so the moved term references **fresh** slots; roots come back in chain order, refc binaries and MSO objects move as **handles** (the same `data_ptr`, refcount incremented, never deep-copied); the fragment's own references are released only after the **whole chain** copied, so a mid-move failure leaves every fragment intact and the move retryable with a larger `dst` + fresh `dst_off_heap` (the copy+release mechanism and the refcount accounting are in Design Decisions).
### `message.rs` — the envelope and the queue
- `pub struct Message` — the copied payload plus sender identity and the off-heap objects it owns.
  `Message::new(payload: Eterm, from: Eterm) -> Message` (token `NIL`, no off-heap objects, no fragments); builders `with_token(Eterm)`, `with_from(Eterm)`, `with_off_heap(Vec<MsoHandle>)`, `with_binaries(Vec<RefcBinary>)`, `with_nodes(Vec<NodeEntry>)`, `with_fragments(Fragments)`; accessors `payload() -> Eterm`, `from()`, `token()`, `off_heap() -> &[MsoHandle]`, `binaries() -> &[RefcBinary]`, `nodes() -> &[NodeEntry]`, `fragments() -> Option<&Fragments>`, `fragments_mut()`.
  Mirrors the C `ERL_MESSAGE_TERM`/`_TOKEN`/`_FROM` (`m[0]`/`m[1]`/`m[2]`) + the message's `off_heap`: a payload that fits the receiver heap lives **in that heap** with no fragments; a larger one lives in the message's `Fragments` (the `data.heap_frag`/`hfrag` of `ErtsMessage`) and `payload()` points into them.
  Logical-size surface (the C `size_object_litopt`/`bin_vheap` inputs a host needs): `heap_words() -> usize` — the sender copy-charge input, the payload graph's flat word count when heap-resident and the fragment chain's `total_used_words()` when fragmented, **heap words only**, so an off-heap refc binary contributes just its 8-word `[BinRef][ErlSubBits]` handle; and `logical_binary_bytes() -> usize` — the *holder's* virtual-binary-heap input, the summed `RefcBinary` payload lengths of `binaries()`, `0` when none.
  Rebuild-preserving `with_payload(Eterm) -> Message` keeps `from`, `token`, `off_heap`, `binaries`, `nodes` AND `fragments`: the relocation-safe rebuild a collector must use.
  **Envelope relocation invariant** (the GC-rooting surface): `payload` is relocatable, rebuilt with `with_payload`; `from` and `token` are relocatable, in place with `set_from(&mut self, Eterm)` / `set_token(&mut self, Eterm)` or as the builders `with_from`/`with_token`; `off_heap` (`Vec<MsoHandle>`) and `binaries` (`Vec<RefcBinary>`) are **not terms** (refcounted off-heap handles over stable slots) ⇒ no relocation; `nodes` carries a sysname **atom** ⇒ immediate-required; `fragments` is not host-relocatable, the payload pointing *into* the fragment region, foreign to the collected nursery.
  So a host that stores a **heap** word in `from`/`token` must gather it as a GC root and scatter it back through `set_from`/`set_token` on every collection of the owning process (with no such gather the word survives as a stale pointer into the evacuated from-space); the common immediate cases (a sender pid, a node atom, `NIL`) need no gather and are the only ones the enqueue tripwire admits.
- `pub struct Queue` — the per-process FIFO message queue (a pure data structure, **no** scheduler coupling): `new()`/`Default`, `enqueue(Message)`, `dequeue() -> Option<Message>`, `peek() -> Option<&Message>`, `len()`, `is_empty()`, `clear()`, `iter() -> impl Iterator<Item=&Message>`.
  **Positional scan cursor** (drives the engine's candidate-by-candidate receive): `cursor() -> QueueCursor` (first message), `cursor_at(position)`, `position(QueueCursor) -> usize`, `message_at(QueueCursor) -> Option<&Message>`, `advance(&mut QueueCursor)` (monotonic — saturates past the end), `remove_at(QueueCursor) -> Option<Message>`; all bounds-safe (`VecDeque::get`/`remove`), so a past-the-end cursor or an empty queue yields `None`.
  `pub(crate) remove_index(index: usize) -> Option<Message>` — index-based removal used by `mailbox::receive` (the public `remove_at` name belongs to the cursor API).
  **Enqueue tripwire** (`debug_assert_enqueue_terms`, debug-only): `enqueue` debug-asserts that the message's `from` **and** `token` are genuine values (`is_value`) and **immediates** (`is_immediate`), so a host that enqueues an un-relocated young-heap word — or a bare header word such as `THE_NON_VALUE` — fails loudly in tests instead of leaving a dangling word behind; cheap, and compiled out under `--release`.
  It is a deliberate narrowing of the C, which also permits a heap `token` tuple (`erl_message.c:388-390`) and a heap Info-tuple `from` (`erl_proc_sig_queue.c:2272`); a host opting into those must add a root-gather for the two words and deliberately relax the tripwire.
- `pub struct QueueCursor` — `Copy`/`Clone`/`Debug`/`Default` (position 0)/`PartialEq`/`Eq`; a **monotonic scan position** over a `Queue`, not a stable handle: `remove_at` shifts every later position, so a cursor outstanding across a removal is stale and callers re-derive one via `Queue::cursor()` (the engine does exactly this: remove the match, then reset to the first message).
### `mailbox.rs` — send / receive primitives (data level)
- `pub fn send(from: Eterm, term: Eterm, to_heap: &mut Heap, to_queue: &mut Queue, ctx: &mut CopyContext<'_>) -> Result<()>` — copies `term` into `to_heap`, then **drains all three** destination off-heap categories into the `Message` (`drain_binaries()` → `with_binaries`, `drain_nodes()` → `with_nodes`, `drain_handles()` → `with_off_heap`); the copy-into-the-receiver's-heap half of the C `erts_queue_message`/`copy_struct` path, the scheduler-signalling half being `beam_process`'s.
  **Atomic**: a payload that does **not** fit fails with `BeamError::Alloc(AllocKind::Message)` and leaves `to_heap`, the destination off-heap table and the queue untouched.
- `pub fn send_fragmented(from, term, to_heap, to_queue, ctx, fragment_capacity_words: usize) -> Result<()>` — like `send`, but a payload that does not fit the receiver's heap is copied into a `HeapFragment` instead of failing (the C `erts_try_alloc_message_on_heap`/`new_message_buffer` sender).
  Only `AllocKind::Message` triggers the fragment path (any other failure propagates unchanged, the receiver heap untouched); the fragment is sized to hold the whole payload (at least `fragment_capacity_words`, at least `size_object(term)`), `term` is copied against the **fragment's** off-heap table (so the fragment owns the payload's off-heap objects — `ctx`'s destination table is unused on this path, a fragment carrying its own `off_heap`, as C does), and the enqueued `Message` points into the fragment and owns the `Fragments`; one fragment per send.
- `pub fn receive<F: FnMut(&Message) -> bool>(queue: &mut Queue, pred: F) -> Option<Message>` — **remove and return** the first queued message whose payload satisfies `pred` (selective-receive skeleton); waiting, `after` timeouts, the save queue and signal ordering live in `beam_process`.
- `pub fn receive_ref<F: FnMut(&Message) -> bool>(queue: &Queue, pred: F) -> Option<&Message>` — non-destructive variant.
### `error.rs` — copy-failure classification (no crate-local error type)
- `heap_exhausted(words) -> BeamError` / `bad_term() -> BeamError` (`pub(crate)` constructors).
- `pub fn is_message_heap_exhaustion(error: &BeamError) -> bool` — re-exported at the crate root and in `prelude`; true iff `error` is `BeamError::Alloc(f)` with `f.kind == AllocKind::Message`, the **soft, recoverable** "the destination message heap could not hold the copied term" signal.
### `off_heap.rs` — the off-heap (MSO + binary + node) reference table
- `pub use beam_gc::MsoHandle;` — the off-heap object handle is **beam_gc's** (MSO object + atomic `RefCount`); this crate never re-implements nor re-stores MSO.
- `pub struct OffHeapTable` — a **slot-indexed** table of `MsoHandle`s (slot = the on-heap off-heap-reference's `val` word), a thin MSO-typed façade over `beam_gc::OffHeap` plus the **refc-binary** and **node** lists that ride along with a copied message.
  MSO API: `new()`/`Default` (manual — `beam_gc::OffHeap` is not `Default`), `push(MsoHandle) -> usize` (returns the slot), `get(slot) -> Option<&MsoHandle>`, `clone_slot(slot) -> Option<MsoHandle>` (**bumps the refcount**), `len()`, `is_empty()`, `iter()`, `overhead_bytes()`, `into_handles() -> Vec<MsoHandle>`, `drain_handles()`; untyped escape hatch `get_entry(slot) -> Option<&beam_gc::OffHeapEntry>`.
  Refc binaries: `push_binary(RefcBinary) -> usize`, `binary_at(slot) -> Option<RefcBinary>` (clone ⇒ refcount++), `binary_by_data_ptr(*const u8) -> Option<RefcBinary>` (clone; resolves an on-heap `BinRef.val` to its owning handle), `binaries() -> &[RefcBinary]`, `drain_binaries()`.
  Nodes: `push_node(NodeEntry) -> usize` (one entry per **distinct** node; a repeat counts another reference onto it), `nodes()`, `node_by_identity(Eterm, u32) -> Option<&NodeEntry>`, `drain_nodes()`; `Drop` releases every node reference the table registered.
  `into_handles`/`drain_handles` **clone-then-drop** each handle (refcount++ then refcount-- when the consumed list drops), because `beam_gc::OffHeap` has no move-out API — the net refcount is unchanged.
  Slots are stable and this table **never calls `beam_gc::OffHeap::sweep`** (reclamation is the collector's concern, not a read-only view's); only the append-only `insert`/`get`/`iter` path is used here.
### `node.rs` — external-thing node entries
- `pub struct NodeEntry` — a refcounted `(node, creation)` identity, the unit of `erts_ref_node_entry`/`erts_deref_node_entry`: `NodeEntry::new(node: Eterm, creation: u32)` (one reference); `node() -> Eterm`, `creation() -> u32`, `refcount() -> usize`, `same_node(&NodeEntry) -> bool`, `identity_eq(Eterm, u32) -> bool`, `handle() -> NodeEntry` (a second observation handle, registering no reference); `pub(crate) add_reference(&self)` / `pub(crate) release_all(&self)`.
  `Clone`-free by design: the count tracks *references registered in a table*, not handles.
### `layout.rs` — the copier's M1 identification/encoding helpers (`pub(crate)`)
- Off-heap container (`is_off_heap_container`/`is_off_heap_term`/`off_heap_slot`/`make_off_heap_container`), refc binary (`is_refc_binary_term`), match context (`is_match_context_term`) and external thing (`is_external_header`/`external_node_creation`); the canonical per-object/child-slot walk (`object_words`, `for_each_child_slot`, `for_each_sizing_child_slot`) is re-exported (`pub(crate) use`) from `beam_term::layout`, not defined here.
## Constraints
- **Errors: `beam_common::{Result, BeamError}` only.** A destination-heap exhaustion ⇒ `BeamError::Alloc(AllocFailure::new(AllocKind::Message, words * size_of::<Eterm>()))` — the **message-heap classification**, recognisable through `is_message_heap_exhaustion`. **Never panic**, never a crate-local error enum, never `unwrap()` on runtime data.
  A malformed/unsupported term layout, a **non-term** (bare header word incl. `THE_NON_VALUE`), a **cyclic** forged graph, or an out-of-range MSO slot ⇒ `BeamError::BadArg` (typed, never a hang, never a partial write); a refc binary whose payload no held handle owns is **not** malformed — it is flattened.
- **`unsafe` is confined to `copy.rs`** (raw word read/write in the copy loop) and the narrow `layout.rs` accessors; every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale; `share.rs`, `fragment.rs`, `off_heap.rs`, `message.rs`, `mailbox.rs`, `node.rs`, `error.rs` are safe Rust; `unsafe_op_in_unsafe_fn` stays clean.
- **Never assume a different `Eterm` layout** — read headers/words through `beam_term` accessors.
  The frozen word layouts (cons `[CAR,CDR]`, header words, `BinRef [thing_word,val,next]`, the `[BinRef(3)][ErlSubBits(5)]` refc pair, `ExternalThing [header,node,next,data]`) are the contract; interiors that are not externally pinned are read through the owning `beam_term` accessors (e.g. the HAMT node shapes via `map_header_type`/`map_header_val`/`header_arity`), never re-derived.
- **`copy_struct_shared` reuses `copy.rs`'s `shallow` primitive** — the copy logic exists once.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`; `beam_codec` and `libc` are declared there but are **unused** (no reference exists in `src/` or `tests/`). No new external dependencies.

## Design Decisions
- **Fidelity scope: a correct, iterative *tree* copy, not the C's single-allocation `htop`/`hbot` layout.** The C pre-sizes, bumps lists up from the heap base and boxed things down from the top so outer objects precede inner ones for `copy_ets_element`; this crate allocates each object *incrementally* (parent before child, so the outer-before-inner invariant still holds) with an **explicit worklist** for fix-ups — no native recursion.
- **The capacity preflight is cycle-safe and bounded.** A bare `beam_term::size_object` is unbounded, so a forged cyclic graph (a raw-write back-edge) would hang or OOM it before the copy started; `preflight_words(term, limit, ctx)` first runs the allocation-free `bounded_words`, mirroring *exactly* what `shallow`/`copy_refc_binary` allocate per object (so it is the copier's own word count, and equals `size_object` for every reachable shape) and returning `None` the moment it exceeds the destination's free words.
  It needs the `CopyContext` because one object's cost depends on the **source** table: a refc binary whose payload a held handle owns costs `ERL_REFC_BITS_SIZE`, else `heap_bits_size_words(size)` (`refc_binary_words` keeps that rule beside the flag it mirrors, so preflight and copy never disagree — `size_object` does not model the fallback).
  Only on `None` does it run `is_acyclic` (an iterative DFS with an on-path `HashSet<usize>`): cyclic ⇒ typed `BadArg`; acyclic ⇒ the same walk re-run **unbounded**, now provably terminating, giving the exact count (with `size_object` as the saturation fallback) — so a rejected graph always yields a count **above** `limit` and the refusal is total, never a partial write; every compound object contributes ≥2 words, so a cycle always overflows the bound first and the `HashSet` is never paid on the fitting path.
- **The single-pass fast path is sound precisely because the destination off-heap table is empty.** The trial writes only the heap's **unused tail** and commits once with `alloc_words`, so a failed attempt needs no heap rewind (and `to.reset()` would be *wrong* on a dirty heap — it would discard live `used` words); only `OffHeapTable::rollback` runs, sound because the table started empty. The gate is the off-heap table's emptiness, NOT `to.used() == 0`.
- **Non-term and cyclic graphs are typed errors, never wrong results or hangs.** The `is_shared` test requires a genuine term word before checking the literal bit (`is_boxed_term(term)`, or `is_list(term) && is_term_word(term)`), because `beam_term::is_boxed` mirrors the C bit trick that is also true for a bare `HEADER` word: without the guard a bare header word (e.g. `HEADER_SUB_BITS`, or `THE_NON_VALUE`) would be mis-shared as a literal and cross the boundary undetected; a non-term reaches `shallow`'s `PrimaryTag::Header` arm ⇒ typed `BadArg`, writing nothing.
- **Sharing policy matches the C's tree copier.** Only **immediates** (`is_immediate`), **literal-area terms** (a boxed/list word with the `TAG_LITERAL_PTR` bit, tested *only* on a genuine term word) and the zero-arity `HEADER_ARITYVAL` tuple (`beam_term::tuple0()`) are shared; everything else is copied — so `copy_struct` duplicates a repeated subterm, by design.
- **Allocation failure is `AllocKind::Message` — the message-heap contract.** It is **soft/recoverable**: a host may grow-and-retry, or raise `error:system_limit` (class `error`, reason atom `system_limit`, the atom the oracle raises for an exceeded hard runtime limit).
  The kind stays `Message` (not `Heap`) deliberately: `beam_rt::RuntimeContext::deliver_message` keys on the raw `AllocKind::Message` as the load-bearing oversized-message **retry trigger**, and this copy's destination *is* the message/receiver heap.
- **The sharing-preserving copier is opt-in and additive.** `copy_struct` keeps the C default's flat behaviour so existing dependents are unchanged; `copy_struct_shared` is the analogue of the C `copy_shared_calculate`/`copy_shared_perform_x` (state `erts_shcopy_t`), and where the C keys sharing on the from-space address with **destructive in-place markers**, Rust keeps a real `HashMap<usize, Eterm>` — no source-heap mutation.
  It preflights the *flat* word count, a safe upper bound: a caller sizes the destination heap as for `copy_struct`, and the saving is in the words written, not the accepted capacity.
- **MSO is reused from `beam_gc`, never reimplemented.** The off-heap object, its atomic `RefCount`, its `MsoHandle` and the per-process off-heap list are **entirely `beam_gc::mso`'s**; `beam_gc::OffHeap`'s slot-indexed read access (`insert`/`get`/`iter`) lets the copy boundary refcount the source's objects straight from the shared storage, so `off_heap.rs` holds **no duplicate MSO storage** and invents neither an object model nor a refcounting scheme (the `beam_message → beam_gc` edge is acyclic).
- **Off-heap reference term — the M1 encoding (documented substitution).** A standalone off-heap reference is the frozen `BinRef` container thing (`ERL_BIN_REF_SIZE = 3`) with **`val` = the MSO slot index** into the owning process's `OffHeapTable` and **`next` unused (`0`)**; copying one resolves the source slot, **clones the handle** (refcount++), pushes it into the destination table and writes the **new** slot — the payload is never deep-copied.
- **Refc binaries share the payload; small binaries are copied by value.** The on-heap **refc binary** is the frozen 8-word pair `[BinRef(3)][ErlSubBits(5)]` (tagged root = the `ErlSubBits`, `BinRef.val` = the payload's first data byte — always distinct from the standalone MSO container, which is a bare `HEADER_BIN_REF` thing); its copy (the C's `erts_refc_inc(&from_br->val->intern.refc, 2)`) resolves the owning `RefcBinary` handle from the source table by that data pointer, refcounts it into the destination binary list, allocates a fresh pair, keeps the window (`base_flags`/`start`/`end`) verbatim, reuses the **same** payload pointer in the copied `BinRef.val`, and fixes the copied `ErlSubBits.orig` up to the **copied** `BinRef` — the fix-up an opaque-leaf treatment of a `SUB_BITS` would leave dangling. An on-heap `ErlHeapBits` small binary has no navigable child and is copied verbatim (its words are opaque).
- **A `SUB_BITS` match context, and a refc binary with no owning handle, are flattened rather than copied verbatim.** A match context (its `orig` is *not* a `BinRef`) is flattened by `copy_match_context` into a fresh on-heap bitstring for the window `start..end`, so the copy carries no `base_flags`/`orig` pointer into the source heap, and the flattened window's data lies inside the destination; `beam_term::layout::object_words` sizes it `heap_bits_size_words(end - start)` and the sizing child-slot enumerator yields no child, so the preflight agrees with the copy.
  With no owning handle `copy_refc_binary` delegates to that same flattener (nothing is registered — there is no handle to refcount), which is sound because `write_refc_binary` sets the pair's `base_flags` word to the payload's data base (the same value `BinRef.val` holds), so `sub_bits_parts`/`bit_at` read the window verbatim; because the copy then costs `heap_bits_size_words(size)` rather than the 8-word pair, `bounded_words` decides a refc binary's cost from the **source** table (`refc_binary_words`) — the preflight is not independent of the `CopyContext`.
- **External pid/port/reference nodes: refcounted per identity, modeled locally.** Copying an external thing registers its node and copies the thing's words verbatim; there is no node-registry crate anywhere in the workspace and no `ErlNode *` to point at, so the identity is modeled as `NodeEntry = (node atom term, creation)` plus an explicit atomic refcount (the same M1 substitution `beam_term::thing` documents), and the node list lives **on `OffHeapTable`** (carried to the `Message` by `send`, exactly like the off-heap list).
  The count is the number of references **the registering table** holds — one per copied external thing, deduped to one list entry per distinct node (two references to the same node ⇒ one entry with count `2`); it is per-table structural bookkeeping rather than a global count because there is no registry to share it with, and a real registry would replace the atom with an `ErlNode *`.
- **The message-fragment move is a copy + release, not the C's in-place move markers.** A fragment's payload holds its off-heap references as **slot indices** into the owning table (the M1 encoding), so `move_into` cannot relink an object list the way the C `erts_move_multi_frags` does (C terms hold raw pointers to the objects, so only in-place move markers are needed); instead it copies each root with `copy_struct` (the fragment's table → `dst_off_heap`), re-registering every referenced object under a **fresh** destination slot, then releases the fragment's own references — the **net refcount is unchanged by the move** (one increment from the copy, one decrement from the release), exactly as the C relink leaves it.
  The fragment's backing `Heap` is a separate, never-moving allocation, so a root's address — and therefore `Message::payload` — stays valid as the `Message`, and hence the `Fragments`, is moved around.
- **Per-object sizing comes from the LCA; the whole-graph count is the copier's own.** `beam_term::layout::object_words` (re-exported by `layout.rs`) gives the *single-object* word count the incremental allocator needs — the same split as `beam_gc::copy`'s `move_size` — and `bounded_words` mirrors it (via the LCA's `for_each_sizing_child_slot`) to give the whole-graph count the copier will actually write; the crate keeps **no** local copy of the walk.
  `beam_term::size_object` remains the canonical flat count and equals `bounded_words` for every shape that can cross a copy boundary (incl. a `SUB_BITS` match context, whose `object_words` is the flattened window size) — the one exception being a refc binary the source table holds no handle for.
  The LCA's enumerators cover every HAMT node kind with the same `1 + header_arity + popcount(MAP_HEADER_VAL)` formulation, so a hash map copies as a whole trie and a widened fun descriptor (the 3-word `External` `[module, function, arity]` descriptor ⇒ a 4-word block) is sized and copied automatically, with no change in this crate.

## Performance (measured)
Every figure and its caveats are in `PERF.md`, reproduced by `tests/{perf,send_perf,counters}.rs` under the dev/`opt-level=1` profile on a shared/oversubscribed host — prefer ratios over absolutes.
- **The send path is single-traversal** (the real `send`/deliver path passes a fresh, empty `OffHeapTable`, so `copy_struct` takes `try_copy_fast`); only a destination with a **non-empty** off-heap table still costs the second traversal.
- **Per-message heap allocation is the fixup worklist alone.** For the exact `tools/bench` `copy_bound` payload — 70 words / 27 objects (21 cons cells + 6 headed) / 1120 B touched, 8.6 % header words, 2.59 words/object — the whole `beam_message::send` path allocates ≈ 2 heap blocks / 192 B per message (the copy engine's fixup worklist `Vec`); the enqueue half allocates 0, and a cold mailbox's first `VecDeque` buffer is once per mailbox, not per message.
- **The crate's own share of the `copy_bound` `send_recv` cost is ≈ 0.4 %:** `copy_struct` ≈ 267 ns and the whole `send` ≈ 305 ns against a measured ≈ 84 µs/op `send_recv_plain` workload.
- `tests/perf.rs` isolates the sizing walk's share of the two-traversal path (single-pass vs sized `copy_struct`); `PERF.md` carries that and the copy-vs-enqueue split.
## Known Issues / Intentional M1 gaps
- **A destination with a non-empty off-heap table is the only remaining two-traversal copy.** Serving it in one pass needs an **off-heap checkpoint API** — `OffHeapTable::rollback` drains all three lists (so it would discard pre-existing entries) and there is no `OffHeapTable::checkpoint()`/`rollback_to(...)`; a `beam_alloc::Heap::truncate(mark)` would only help an alternative design that writes straight into the heap. Both live outside this crate.
- **The `copy_bound` `send_recv` / `send_recv_plain` / `etf_roundtrip` gap is NOT in this crate.** This crate's own copy+send share is ≈ 0.4 % (above); the dominant measured cost of the two-process cases is a per-scheduler-pass 25 ms `std::thread::sleep` in `beam_rt` (`crates/beam_rt/src/runtime/scheduler.rs` — the pass-boundary `timer_wait`/sleep, with `PORT_POLL_SLICE` in `crates/beam_rt/src/port.rs`), owned by `beam_rt`, plus `beam_rt`'s per-slice root publish/resume fixed costs, while `etf_roundtrip` is `beam_codec`'s. Recorded so future agents do not re-investigate the copy path for it.
- **`beam_term::compare` has no structural arm for external pid/port/reference (nor for `RECORD_SUBTAG`).** It falls through to the deterministic `fallback_cmp` (same class ⇒ order by object arity, then raw term word), so a copy is never `=:=` its original for those two shapes and `compare::eq` cannot check a copied external thing / native record; the crate's tests assert structural equality through the `beam_term::thing` accessors instead. A fix belongs to `beam_term`.
- **`beam_term::size_object` is unbounded on a cyclic/forged graph** (and reports `0` for `THE_NON_VALUE` without panicking); the `beam_message` boundary is guarded by the cycle-safe `preflight_words`, but any other caller (beam_gc, beam_rt, tools) is exposed. A bound/cycle guard belongs in `beam_term` (`src/size.rs`).
- **A flattened no-handle refc binary becomes an on-heap `ErlHeapBits` that may exceed `ERL_ONHEAP_BITS_LIMIT`.** `copy_match_context` writes the window with `write_heap_bits` and does not enforce the on-heap limit (the C's `HEAP_BITSTRING` only asserts it), so a long off-heap payload whose handle no source table holds lands as an on-heap bitstring larger than ERTS would ever build there; the copy stays correct and self-contained, but the term's shape is not one the emulator produces. A caller that cares keeps the payload's handle registered in the off-heap table.
- **A fragment holds the whole payload; there is no automatic multi-fragment split.** One fragment is sized to the whole payload (`fragment_capacity_words.max(size_object(term))`) and the chain is built by the caller (`Fragments::push`); a size-bounded split, and the Stage-3 **message-queue auto-tuning** (replacing the static `SPO_ON_HEAP_MSGQ`/`+hmqd` on-/off-heap placement choice through `erts_change_message_queue_management`), are `beam_process`'s heap-management concerns — this crate's `send` vs `send_fragmented` choice *is* the placement decision itself.
- **The fragment path is driven by the siblings, not from here.** `beam_process::Process::deliver` calls `send` (a payload over its heap ⇒ `AllocKind::Message`); `beam_rt`'s `send_fragmented_message` (`src/context/send.rs`) catches that and calls `beam_message::send_fragmented` through `beam_process::Process::heap_and_mailbox_mut`, enqueuing a message that owns the chain, and `Process::heap_and_off_heap_mut` drives `Fragments::move_into` to move a fragment-resident payload onto the process heap; sibling tests exercise both (`beam_process/tests/split_borrow.rs`, `signal_fragment_fallback.rs`, `beam_rt/tests/eval_exempt_receiver_signal.rs`).
- **The logical-size surface is exposed but nothing charges it yet.** `Message::heap_words()` supplies the sender's copy-charge input (the C `msize = size_object_litopt(message)`; charge `4 + msize / ERTS_MSG_COPY_WORDS_PER_REDUCTION` (64 release) capped at `CONTEXT_REDS` — `bif.c:2742`/`:2862`, `erl_message.c:881-886`) and `Message::logical_binary_bytes()` the *holder's* virtual binary-heap input (`bin_vheap += orig_size / sizeof(Eterm)`, surfaced as `virtual_reds` — `erl_gc.c:3046,3051`, `erl_process.c:9678`); a host must apply both, and charging the holding process's virtual binary heap remains a separate mechanism this crate does not model.
- **A received message's off-heap lists are carried but not swept here.** `binaries()`/`nodes()` are the receiving process's off-heap references; the `Message`'s own `Drop` releases them and a host that takes ownership must sweep them, while a **fragmented** message leaves those lists empty, its payload's off-heap objects living in the fragment's `off_heap` table until `Fragments::move_into` hands them to the destination table.
- **`Message.token` is a plain field (`NIL` when absent).** The seq-trace / distribution-token machinery that fills it is `beam_dist`/`beam_rt`.
- **The bench's only messaging workload is an honest skip.** In `../tools/bench` the only `Category::Messaging` ("messaging/copy-bound") workload is `emqx`, which reports `skipped(emqx-requires-otp-28)`.
