# `beam_message` — Copy Engine (`copy_struct`) & Messaging
## Intent
Owns the **copy half of the process memory model** — moving a term graph between two process heaps (`copy_struct`, plus the sharing-preserving `copy_struct_shared`) — and the data-level messaging primitives built on it: the `Message` envelope, the per-process FIFO message **queue**, `send`/`receive`, and the **message-fragment model** (`HeapFragment`/`Fragments`) homing a payload too large for the receiver's heap.
Implements Part II §C/§D (the messaging/ETS copy boundary: *immutability bounds what may be shared; everything else is copied*) and the Stage-3 row of Part II §H.
Sibling responsibilities (NOT here): the collector and the per-process heap (`beam_gc`, `beam_alloc`); the scheduler / selective-receive waiting / save queue / signal ordering (`beam_process`); the `send`/`receive` BIF surface and pattern matcher (`beam_bifs`); the node registry itself (there is none in the workspace — see Design Decisions).
Ground truth = the legacy C `erts/emulator/beam/`: `copy.c` (the copier, `copy_shared_*`, `erts_move_multi_frags`), `erl_message.c`/`.h` (`ErtsMessage`, `ErlHeapFragment`, the queue, the message-buffer senders), `erl_gc.c` (`OffHeap`/MSO sweep, `erts_copy_one_frag`) and `erl_node_tables.h` (the node refcount). Read the C; never modify it.
## Inheritance (binding)
Obeys the crate-layer `../CONTEXT.md` contracts verbatim: frozen term layout (§2 — construct/inspect **only** through `beam_term`), return-based errors (§3 — `beam_common::Result<T>`, no panics, no crate-local error enum), `unsafe` confinement (marked modules, `# Safety`/`// SAFETY:`), `unsafe_op_in_unsafe_fn` clean, ~1000-line files, licensing Apache-2.0.
**Do not restate them here.**
## API Surface (the seam dependents design against)
Re-exported at the crate root (`src/lib.rs`) and via `beam_message::prelude::*`; the per-class copy mechanisms are in Design Decisions.
### `copy.rs` — the copy engine (the `unsafe` core)
- `pub struct CopyContext<'a>` — the copy boundary: the source process's off-heap table (resolving off-heap references) and the destination's (re-registering them).
  `CopyContext::new(src: &'a OffHeapTable, dst: &'a mut OffHeapTable) -> CopyContext<'a>`; `src_off_heap(&self)`, `dst_off_heap(&self)`, `dst_off_heap_mut(&mut self) -> &mut OffHeapTable` (the table `send` drains into the message).
- `pub fn copy_struct(term: Eterm, to: &mut beam_alloc::Heap, ctx: &mut CopyContext<'_>) -> Result<Eterm>` — iterative **flat** copy of `term`'s graph into `to` (an explicit worklist, no native recursion, so a deep list cannot overflow the stack), returning the copied root; it shares immediates and literal-area terms and copies every other class, per the per-class copy policy in Design Decisions.
  **Single-pass** (`try_copy_fast`) whenever the destination off-heap table is empty (a dirty *heap* included) — one copy traversal and no preflight at all; otherwise `preflight_words` prices the graph in exactly **one** unbounded walk before any write, the count is exact, and the *caller* compares it (`copy_struct` refuses when `to.available() < needed`; the retained `limit` parameter is not consulted), so a refusal writes nothing — the error classification is in Constraints.
- `pub fn copy_struct_simple(term: Eterm, to: &mut beam_alloc::Heap) -> Result<Eterm>` — `copy_struct` for empty off-heap tables (a graph with no off-heap references).
- `pub fn size_of_copy(term: Eterm) -> usize` — forwarder to `beam_term::size_object`, i.e. the flat **source** word count (the `litopt == NULL` answer), exposed so a caller can size a destination. It equals the copier's own destination price for a graph with no literal-area subterm and no refc binary whose payload no source handle owns; the copier itself prices through `preflight_words` (see Design Decisions), never through this.
- `pub(crate) trait CopyTarget` + `struct TrialTarget` + `fn is_fast_path_eligible` / `fn try_copy_fast` — the destination abstraction: `Heap` reserves per object, `TrialTarget` bumps over the destination heap's unused tail `[to.hp(), hend)` (`free = to.available()`) counting `written` without touching `used`/`peak`; `is_fast_path_eligible` = `ctx.dst_off_heap().is_fully_empty()` (`is_fully_empty`/`rollback` are `pub(crate)` on `off_heap.rs`).
- `pub(crate) fn shallow` / `fn shallow_unshared` — the shallow half (materialise one object, record a fix-up per non-shared child). `shallow` is the checked entry (the two root calls); `shallow_unshared` is the match body the worklist loops call, sound because a fix-up is only ever recorded for a child `push_fixup` already proved non-shared — the two must stay behaviourally identical for every term `is_shared` rejects.
### `share.rs` — the sharing-preserving copier
- `pub fn copy_struct_shared(term: Eterm, to: &mut beam_alloc::Heap, ctx: &mut CopyContext<'_>) -> Result<Eterm>` — the sharing-preserving copier: `copy_struct`'s immediate/literal/off-heap-node policy and iterative worklist, but each compound subterm is materialised **once per source identity** through a `HashMap<usize, Eterm>` memo keyed on the from-space term address (immediates and literal-area terms are never memoised); the rationale is in Design Decisions.
  It preflights through the same `copy::preflight_words`, so the destination is sized as for `copy_struct` — the saving is in the words written.
### `fragment.rs` — the message-fragment model (`ErlHeapFragment`/`ErtsMessage` analogue)
- `pub struct HeapFragment` — a bump-allocated heap region plus its off-heap objects and its roots, mirroring the C `ErlHeapFragment` (`{ next; off_heap; alloc_size; used_size; mem[1]; }`).
  `new(capacity_words)` / `with_allocator(alloc, capacity_words)`; `heap()` / `heap_mut()` (the `mem[1..alloc_size]` region); `off_heap()` / `off_heap_mut()`; `used()` / `capacity()` / `available()`; `off_heap_overhead_bytes()` (the C `ErlOffHeap.overhead`); `push_root(Eterm)`, `roots() -> &[Eterm]` (the payload roots, `m[0]` pointing into `mem`), `contains(term) -> bool`.
  `copy_root(term: Eterm, src: &OffHeapTable) -> Result<Eterm>` — copies `term` from a process whose off-heap table is `src` into the fragment's heap, refcounts its off-heap references into the **fragment's** table (fresh slots), records the result as a root and returns it (the C `new_message_buffer` + the copy step of `erts_try_alloc_message_on_heap`); a fragment too small for the payload is refused up front, so it performs **no partial write** (roots stay empty, `used()` stays `0`).
- `pub struct Fragments` — an ordered chain of `HeapFragment`s (the C `ErlHeapFragment.next` chain): `new()`/`Default`, `is_empty()`, `len()`, `push(HeapFragment)`, `iter()`/`iter_mut()`, `total_used_words()` (the process message-buffer accounting — `used_size` summed), `off_heap_overhead_bytes()`.
  `move_into(dst: &mut Heap, dst_off_heap: &mut OffHeapTable) -> Result<Vec<Eterm>>` — the one-shot move entry point (the `erts_move_multi_frags`/`erts_copy_one_frag` analogue): each fragment in order copies each root with `copy_struct` (the fragment's table as source, `dst_off_heap` as destination), so the moved term references **fresh** slots; roots come back in chain order, refc binaries and MSO objects move as **handles** (the same `data_ptr`, refcount incremented, never deep-copied); the fragment's own references are released only after the **whole chain** copied, so a mid-move failure leaves every fragment intact and the move retryable with a larger `dst` + fresh `dst_off_heap` (the copy+release mechanism and the refcount accounting are in Design Decisions).
### `message.rs` — the envelope and the queue
- `pub struct Message` — the copied payload plus sender identity and the off-heap objects it owns.
  `Message::new(payload: Eterm, from: Eterm) -> Message` (token `NIL`, no off-heap objects, no fragments); builders `with_token(Eterm)`, `with_from(Eterm)`, `with_off_heap(Vec<MsoHandle>)`, `with_binaries(Vec<RefcBinary>)`, `with_nodes(Vec<NodeEntry>)`, `with_fragments(Fragments)`; accessors `payload() -> Eterm`, `from()`, `token()`, `off_heap() -> &[MsoHandle]`, `binaries() -> &[RefcBinary]`, `nodes() -> &[NodeEntry]`, `fragments() -> Option<&Fragments>`, `fragments_mut()`.
  Mirrors the C `ERL_MESSAGE_TERM`/`_TOKEN`/`_FROM` (`m[0]`/`m[1]`/`m[2]`) + the message's `off_heap`: a payload that fits the receiver heap lives **in that heap** with no fragments; a larger one lives in the message's `Fragments` (the `data.heap_frag`/`hfrag` of `ErtsMessage`) and `payload()` points into them.
  Logical-size surface (the C `size_object_litopt`/`bin_vheap` inputs a host needs): `heap_words() -> usize` — the sender copy-charge input, the payload graph's flat word count when heap-resident and the fragment chain's `total_used_words()` when fragmented, **heap words only**, so an off-heap refc binary contributes just its 8-word `[BinRef][ErlSubBits]` handle; and `logical_binary_bytes() -> usize` — the *holder's* virtual-binary-heap input, the summed `RefcBinary` payload lengths of `binaries()`, `0` when none.
  Rebuild-preserving `with_payload(Eterm) -> Message` keeps `from`, `token`, `off_heap`, `binaries`, `nodes` AND `fragments`: the relocation-safe rebuild a collector must use.
  **Envelope relocation invariant** (the GC-rooting surface): `payload` is relocatable, rebuilt with `with_payload`; `from` and `token` are relocatable, in place with `set_from(&mut self, Eterm)` / `set_token(&mut self, Eterm)` or as the builders `with_from`/`with_token`; `off_heap` (`Vec<MsoHandle>`) and `binaries` (`Vec<RefcBinary>`) are **not terms** (refcounted off-heap handles over stable slots) ⇒ no relocation; `nodes` carries a sysname **atom** ⇒ immediate-required; `fragments` is not host-relocatable, the payload pointing *into* the fragment region, foreign to the collected nursery.
  So a host that stores a **heap** word in `from`/`token` must gather it as a GC root and scatter it back through `set_from`/`set_token` on every collection of the owning process (with no such gather the word survives as a stale pointer into the evacuated from-space); the common immediate cases (a sender pid, a node atom, `NIL`) need no gather and are the only ones the enqueue tripwire admits.
- `pub struct Queue` — the per-process FIFO message queue (a pure data structure, **no** scheduler coupling): `new()`/`Default`, `enqueue(Message)`, `dequeue() -> Option<Message>`, `peek() -> Option<&Message>`, `len()`, `is_empty()`, `clear()`, `iter() -> impl Iterator<Item=&Message>`.
  **Positional scan cursor** (drives the engine's candidate-by-candidate receive): `cursor() -> QueueCursor` (first message), `cursor_at(position)`, `position(QueueCursor) -> usize`, `message_at(QueueCursor) -> Option<&Message>`, `advance(&mut QueueCursor)` (monotonic — saturates past the end), `remove_at(QueueCursor) -> Option<Message>`; all bounds-safe (`VecDeque::get`/`remove`), so a past-the-end cursor or an empty queue yields `None`.
  `pub(crate) remove_index(index: usize) -> Option<Message>` — index-based removal used by `mailbox::receive` (the public `remove_at` name belongs to the cursor API).
  **Enqueue tripwire** (`debug_assert_enqueue_terms`, debug-only): `enqueue` debug-asserts that the message's `from` **and** `token` are genuine values (`is_value`) and **immediates** (`is_immediate`), so a host that enqueues an un-relocated young-heap word — or a bare header word such as `THE_NON_VALUE` — fails loudly in tests instead of leaving a dangling word behind; cheap, and compiled out under `--release`.
  It is a deliberate narrowing of the C, which also permits a heap `token` tuple (`erl_message.c:388-390`) and a heap Info-tuple `from` (`erl_proc_sig_queue.c:2272`); a host opting into those must add a root-gather for the two words and deliberately relax the tripwire.
- `pub struct QueueCursor` — `Copy`/`Clone`/`Debug`/`Default` (position 0)/`PartialEq`/`Eq`; a **monotonic scan position** over a `Queue`, not a stable handle: `remove_at` shifts every later position, so a cursor outstanding across a removal is stale and callers re-derive one via `Queue::cursor()` (the engine does exactly this: remove the match, then reset to the first message).
### `mailbox.rs` — send / receive primitives (data level)
- `pub fn send(from: Eterm, term: Eterm, to_heap: &mut Heap, to_queue: &mut Queue, ctx: &mut CopyContext<'_>) -> Result<()>` — copies `term` into `to_heap`, then **drains all three** destination off-heap categories into the `Message` (`drain_binaries()` → `with_binaries`, `drain_nodes()` → `with_nodes`, `drain_handles()` → `with_off_heap`); the copy-into-the-receiver's-heap half of the C `erts_queue_message`/`copy_struct` path, the scheduler-signalling half being `beam_process`'s.
  **Atomic**: a payload that does **not** fit fails with `BeamError::Alloc(AllocKind::Message)` and leaves `to_heap`, the destination off-heap table and the queue untouched.
- `pub fn send_fragmented(from, term, to_heap, to_queue, ctx, fragment_capacity_words: usize) -> Result<()>` — like `send`, but a payload that does not fit the receiver's heap is copied into a `HeapFragment` instead of failing (the C `erts_try_alloc_message_on_heap`/`new_message_buffer` sender).
  Only `AllocKind::Message` triggers the fragment path (any other failure propagates unchanged, the receiver heap untouched); the fragment is sized from the refusal's **own exact copier price** — `AllocFailure::requested / size_of::<Eterm>()` (`beam_term::size_object` is only the defensive fallback for a byte count that is not a whole, nonzero number of words) — with `fragment_capacity_words` a **floor** a caller may raise the reservation with, never a substitute for the price.
  So the sequence is one abandoned trial, one exact pricing walk and **one** copy into the fragment, with no re-copy and no second sizing walk.
  `term` is copied against the **fragment's** off-heap table (so the fragment owns the payload's off-heap objects — `ctx`'s destination table is unused on this path, a fragment carrying its own `off_heap`, as C does), and the enqueued `Message` points into the fragment and owns the `Fragments`; one fragment per send, never a chain.
- `pub fn receive<F: FnMut(&Message) -> bool>(queue: &mut Queue, pred: F) -> Option<Message>` — **remove and return** the first queued message whose payload satisfies `pred` (selective-receive skeleton); waiting, `after` timeouts, the save queue and signal ordering live in `beam_process`.
- `pub fn receive_ref<F: FnMut(&Message) -> bool>(queue: &Queue, pred: F) -> Option<&Message>` — non-destructive variant.
### `error.rs` — copy-failure classification (no crate-local error type)
- `heap_exhausted(words) -> BeamError` / `bad_term() -> BeamError` (`pub(crate)` constructors).
- `pub fn is_message_heap_exhaustion(error: &BeamError) -> bool` — re-exported at the crate root and in `prelude`; true iff `error` is `BeamError::Alloc(f)` with `f.kind == AllocKind::Message`, the **soft, recoverable** "the destination message heap could not hold the copied term" signal.
### `off_heap.rs` — the off-heap (MSO + binary + node) reference table
- `pub use beam_gc::MsoHandle;` — the off-heap object handle is **beam_gc's** (MSO object + atomic `RefCount`); this crate never re-implements nor re-stores MSO.
- `pub struct OffHeapTable` — a **slot-indexed** table of `MsoHandle`s (slot = the on-heap off-heap-reference's `val` word), a thin MSO-typed façade over `beam_gc::OffHeap` plus the **refc-binary** and **node** lists that ride along with a copied message.
  MSO API: `new()`/`Default` (manual — `beam_gc::OffHeap` is not `Default`), `push(MsoHandle) -> usize` (returns the slot), `get(slot) -> Option<&MsoHandle>`, `clone_slot(slot) -> Option<MsoHandle>` (**bumps the refcount**), `len()`, `is_empty()`, `iter()`, `overhead_bytes()`, `into_handles() -> Vec<MsoHandle>`, `drain_handles()`; untyped escape hatch `get_entry(slot) -> Option<&beam_gc::OffHeapEntry>`.
  Refc binaries: `push_binary(RefcBinary) -> usize`, `binary_at(slot) -> Option<RefcBinary>` (clone ⇒ refcount++), `binary_by_data_ptr(*const u8) -> Option<RefcBinary>` (clone; resolves an on-heap `BinRef.val` to its owning handle), `binaries() -> &[RefcBinary]`, `drain_binaries()`.
  **Scope + ownership traps** (load-bearing for any pruning argument): `len`/`is_empty`/`iter`/`overhead_bytes` cover the **MSO list only**, so a table holding refc binaries and no MSO handle still reports `is_empty() == true` (`is_fully_empty` is the all-category test).
  `push_binary` **never deduplicates** — two pushes of the same payload make two entries, each holding its own reference, and `binary_by_data_ptr` returns the **first** match, so a duplicate is never resolved and only `drain_binaries`/`rollback` can release it (the dedup that does exist is `beam_rt::Runtime::adopt_escaped_binaries`, keyed on `data_ptr`, i.e. the caller's).
  There is **no single-entry removal** (no `retain`/`remove`/`clear`/`sweep`): a binary list is pruned all-or-nothing (`drain_binaries`) or wholesale (`rollback`, `pub(crate)`, all three lists, sound only on a table that started empty), and an entry's release is its `RefcBinary` handle's `Drop`, so dropping an entry while a live on-heap `BinRef.val` still names its `data_ptr` is a use-after-free; a payload grown past its reservation was relocated (`GrowOutcome::Moved`), so an older `data_ptr` is stale even while the handle lives.
  Nodes: `push_node(NodeEntry) -> usize` (one entry per **distinct** node; a repeat counts another reference onto it), `nodes()`, `node_by_identity(Eterm, u32) -> Option<&NodeEntry>`, `drain_nodes()`; `Drop` releases every node reference the table registered.
  `into_handles`/`drain_handles` **clone-then-drop** each handle (refcount++ then refcount-- when the consumed list drops), because `beam_gc::OffHeap` has no move-out API — the net refcount is unchanged.
  Slots are stable and this table **never calls `beam_gc::OffHeap::sweep`** (reclamation is the collector's concern, not a read-only view's); only the append-only `insert`/`get`/`iter` path is used here.
### `node.rs` — external-thing node entries
- `pub struct NodeEntry` — a refcounted `(node, creation)` identity, the unit of `erts_ref_node_entry`/`erts_deref_node_entry`: `NodeEntry::new(node: Eterm, creation: u32)` (one reference); `node() -> Eterm`, `creation() -> u32`, `refcount() -> usize`, `same_node(&NodeEntry) -> bool`, `identity_eq(Eterm, u32) -> bool`, `handle() -> NodeEntry` (a second observation handle, registering no reference); `pub(crate) add_reference(&self)` / `pub(crate) release_all(&self)`.
  `Clone`-free by design: the count tracks *references registered in a table*, not handles.
### `layout.rs` — the copier's M1 identification/encoding helpers (`pub(crate)`)
- Off-heap container (`is_off_heap_container`/`is_off_heap_term`/`off_heap_slot`/`make_off_heap_container`), refc binary (`is_refc_binary_term`), match context (`is_match_context_term`) and external thing (`is_external_header`/`external_node_creation`); the canonical per-object/child-slot walk (`object_words`, `for_each_child_slot`, `for_each_sizing_child_slot`) is re-exported (`pub(crate) use`) from `beam_term::layout`, not defined here.
## Constraints
- **Errors: `beam_common::{Result, BeamError}` only.** A destination-heap exhaustion ⇒ `BeamError::Alloc(AllocFailure::new(AllocKind::Message, words * size_of::<Eterm>()))` — the **message-heap classification**, recognisable through `is_message_heap_exhaustion`. **Never panic**, never a crate-local error enum, never `unwrap()` on runtime data.
  A malformed/unsupported term layout, a **non-term** (bare header word incl. `THE_NON_VALUE`), a **cyclic** forged graph, or an out-of-range MSO slot ⇒ `BeamError::BadArg` (typed, never a hang, never a partial write); a refc binary whose payload no held handle owns is **not** malformed — it is flattened.
- **`unsafe` is confined to `copy.rs`** (raw word read/write in the copy loop) and the narrow `layout.rs` accessors; every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale; `share.rs`, `fragment.rs`, `off_heap.rs`, `message.rs`, `mailbox.rs`, `node.rs`, `error.rs` are safe Rust; `unsafe_op_in_unsafe_fn` stays clean.
- **Never assume a different `Eterm` layout** — read headers/words through `beam_term` accessors.
  The frozen word layouts (cons `[CAR,CDR]`, header words, `BinRef [thing_word,val,next]`, the `[BinRef(3)][ErlSubBits(5)]` refc pair, `ExternalThing [header,node,next,data]`) are the §2 contract; interiors that are not externally pinned are read through the owning accessors (e.g. the HAMT node shapes via `map_header_type`/`map_header_val`/`header_arity`), never re-derived.
- **`copy_struct_shared` reuses `copy.rs`'s `shallow` primitive** — the copy logic exists once.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`; `beam_codec` is used by `tests/identity.rs` (the `term_to_binary` byte-equality evidence) and `libc` is declared but unused. No new external dependencies.

## Design Decisions
- **Fidelity scope: a correct, iterative *tree* copy, not the C's single-allocation `htop`/`hbot` layout.** The C pre-sizes, bumps lists up from the heap base and boxed things down from the top so outer objects precede inner ones for `copy_ets_element`; this crate allocates each object *incrementally* (parent before child, so the outer-before-inner invariant still holds) with an **explicit worklist** for fix-ups — no native recursion.
- **The capacity preflight is `beam_term::size`'s policy-parameterised walk, driven by the copier's own `CopyPricing` `SizingPolicy` — and it is ONE walk.** `preflight_words` builds that policy over the `CopyContext` and calls `size_object_bounded_with(term, usize::MAX, …)`; the DFS, the per-shape interior table, the cycle verdict and the cost of the walk are `beam_term::size`'s, and the crate keeps no walk of its own.
  The copier's price differs from `size_object`'s source occupancy on exactly the two axes the trait exposes, one per method: `is_shared` is the copier's own predicate, so a **literal-area subterm costs 0 destination words** (the C `size_object_litopt` skip, `copy.c:105,119`; the message-heap charge uses that `litopt` form, `global.h:1136`, `erl_message.c:771,839`); `object_words` overrides the single shape `beam_term::layout::object_words` prices for the source heap while `copy_struct` writes something else — a **refc binary whose payload no source off-heap handle owns** costs its flattened window (`heap_bits_size_words(end - start)`, via `refc_binary_words`, which keeps that rule beside the flag it mirrors so preflight and copy never disagree), the one price that depends on `CopyContext`'s **source** table.  The count is **exact in both directions**: at `usize::MAX` the walk's running total saturates instead of passing the limit, so a graph that fits *and* one that does not both come back with the true destination price — which is what lets the typed refusal carry the exact figure.
  A cyclic (forged) graph is `TermGraphCyclic` ⇒ typed `BadArg` — the unbounded walk is precisely the mode whose DFS path set detects a back-edge, so it never hangs and needs no caller-side acyclicity pass.
  So the preflight is **one** walk at `O(objects visited)` time; its two per-walk heap allocations (`Vec<Step>` + the path-set `HashSet`) are priced in Known Issues.
  The `_limit` parameter is *not consulted*: it is kept only because the test-only bounded reference walk (`copy_reference`) is driven at every limit from `0` to past each graph's exact count, and the two walks' verdicts are compared.
- **The single-pass fast path is sound precisely because the destination off-heap table is empty.** The trial writes only the heap's **unused tail** and commits once with `alloc_words`, so a failed attempt needs no heap rewind (and `to.reset()` would be *wrong* on a dirty heap — it would discard live `used` words); only `OffHeapTable::rollback` runs, sound because the table started empty. The gate is the off-heap table's emptiness, NOT `to.used() == 0`.
- **Non-term and cyclic graphs are typed errors, never wrong results or hangs.** The `is_shared` test requires a genuine term word before checking the literal bit (`is_boxed_term(term)`, or `is_list(term) && is_term_word(term)`), because `beam_term::is_boxed` mirrors the C bit trick that is also true for a bare `HEADER` word: without the guard a bare header word (e.g. `HEADER_SUB_BITS`, or `THE_NON_VALUE`) would be mis-shared as a literal and cross the boundary undetected; a non-term reaches `shallow`'s `PrimaryTag::Header` arm ⇒ typed `BadArg`, writing nothing.
- **Sharing policy matches the C's tree copier.** Only **immediates** (`is_immediate`), **literal-area terms** (a boxed/list word with the `TAG_LITERAL_PTR` bit, tested *only* on a genuine term word) and the zero-arity `HEADER_ARITYVAL` tuple (`beam_term::tuple0()`) are shared; everything else is copied — so `copy_struct` duplicates a repeated subterm, by design.
  The **message** path agrees, so literal sharing is not a divergence: the C send builds a stack `erts_literal_area_t litarea` (`erl_message.c:722-723`, `INITIALIZE_LITERAL_PURGE_AREA` — `lit_purge_ptr` is NULL outside a code purge, `global.h:1119-1131`) and calls `size_object_litopt(message, &litarea)` / `copy_struct_litopt(message, msize, &hp, ohp, &litarea)` (`erl_message.c:771,797`, `:839,860`), so `litopt != NULL` and `copy.c:720,744,767` shares any `erts_is_literal` subterm. Only the `litopt == NULL` macros (`global.h:1135,1152`) deep-copy literals, and no send site uses them — so a payload that is a module literal costs the **outer** object only on both runtimes.
- **Allocation failure is `AllocKind::Message` — the message-heap contract.** It is **soft/recoverable**: a host may grow-and-retry, or raise `error:system_limit` (class `error`, reason atom `system_limit`, the atom the oracle raises for an exceeded hard runtime limit).
  The kind stays `Message` (not `Heap`) deliberately: `beam_rt::RuntimeContext::deliver_message` keys on the raw `AllocKind::Message` as the load-bearing oversized-message **retry trigger**, and this copy's destination *is* the message/receiver heap.
- **The sharing-preserving copier is opt-in and additive.** `copy_struct` keeps the C default's flat behaviour so existing dependents are unchanged; `copy_struct_shared` is the analogue of the C `copy_shared_calculate`/`copy_shared_perform_x` (state `erts_shcopy_t`), and where the C keys sharing on the from-space address with **destructive in-place markers**, Rust keeps a real `HashMap<usize, Eterm>` — no source-heap mutation.
  It preflights the *flat* word count, a safe upper bound: a caller sizes the destination heap as for `copy_struct`, and the saving is in the words written, not the accepted capacity.
- **MSO is reused from `beam_gc`, never reimplemented.** The off-heap object, its atomic `RefCount`, its `MsoHandle` and the per-process off-heap list are **entirely `beam_gc::mso`'s**; `beam_gc::OffHeap`'s slot-indexed read access (`insert`/`get`/`iter`) lets the copy boundary refcount the source's objects straight from the shared storage, so `off_heap.rs` holds **no duplicate MSO storage** and invents neither an object model nor a refcounting scheme (the `beam_message → beam_gc` edge is acyclic).
- **Off-heap reference term — the M1 encoding (documented substitution).** A standalone off-heap reference is the frozen `BinRef` container thing (`ERL_BIN_REF_SIZE = 3`) with **`val` = the MSO slot index** into the owning process's `OffHeapTable` and **`next` unused (`0`)**; copying one resolves the source slot, **clones the handle** (refcount++), pushes it into the destination table and writes the **new** slot — the payload is never deep-copied.
- **Refc binaries share the payload; small binaries are copied by value.** The on-heap **refc binary** is the frozen 8-word pair `[BinRef(3)][ErlSubBits(5)]` (tagged root = the `ErlSubBits`, `BinRef.val` = the payload's first data byte — always distinct from the standalone MSO container, which is a bare `HEADER_BIN_REF` thing); its copy (the C's `erts_refc_inc(&from_br->val->intern.refc, 2)`) resolves the owning `RefcBinary` handle from the source table by that data pointer, refcounts it into the destination binary list, allocates a fresh pair, keeps the window (`base_flags`/`start`/`end`) verbatim, reuses the **same** payload pointer in the copied `BinRef.val`, and fixes the copied `ErlSubBits.orig` up to the **copied** `BinRef` — the fix-up an opaque-leaf treatment of a `SUB_BITS` would leave dangling. An on-heap `ErlHeapBits` small binary has no navigable child and is copied verbatim (its words are opaque).
- **A `SUB_BITS` match context, and a refc binary with no owning handle, are flattened rather than copied verbatim.** A match context (its `orig` is *not* a `BinRef`) is flattened by `copy_match_context` into a fresh on-heap bitstring for the window `start..end`, so the copy carries no `base_flags`/`orig` pointer into the source heap, and the flattened window's data lies inside the destination; `beam_term::layout::object_words` sizes it `heap_bits_size_words(end - start)` and the sizing child-slot enumerator yields no child, so the preflight agrees with the copy.
  With no owning handle `copy_refc_binary` delegates to that same flattener (nothing is registered — there is no handle to refcount), which is sound because `write_refc_binary` sets the pair's `base_flags` word to the payload's data base (the same value `BinRef.val` holds), so `sub_bits_parts`/`bit_at` read the window verbatim; because the copy then costs `heap_bits_size_words(size)` rather than the 8-word pair, the preflight (`CopyPricing::object_words`) decides a refc binary's cost from the **source** table (`refc_binary_words`) — so the preflight is not independent of the `CopyContext`.
- **External pid/port/reference nodes: refcounted per identity, modeled locally.** Copying an external thing registers its node and copies the thing's words verbatim; there is no node-registry crate anywhere in the workspace and no `ErlNode *` to point at, so the identity is modeled as `NodeEntry = (node atom term, creation)` plus an explicit atomic refcount (the same M1 substitution `beam_term::thing` documents), and the node list lives **on `OffHeapTable`** (carried to the `Message` by `send`, exactly like the off-heap list).
  The count is the number of references **the registering table** holds — one per copied external thing, deduped to one list entry per distinct node (two references to the same node ⇒ one entry with count `2`); it is per-table structural bookkeeping rather than a global count because there is no registry to share it with, and a real registry would replace the atom with an `ErlNode *`.
- **The message-fragment move is a copy + release, not the C's in-place move markers.** A fragment's payload holds its off-heap references as **slot indices** into the owning table (the M1 encoding), so `move_into` cannot relink an object list the way the C `erts_move_multi_frags` does (C terms hold raw pointers to the objects, so only in-place move markers are needed); instead it copies each root with `copy_struct` (the fragment's table → `dst_off_heap`), re-registering every referenced object under a **fresh** destination slot, then releases the fragment's own references — the **net refcount is unchanged by the move** (one increment from the copy, one decrement from the release), exactly as the C relink leaves it.
  The fragment's backing `Heap` is a separate, never-moving allocation, so a root's address — and therefore `Message::payload` — stays valid as the `Message`, and hence the `Fragments`, is moved around.
- **Per-object sizing and the whole-graph count both come from the LCA.** `beam_term::layout::object_words` (re-exported by `layout.rs`) gives the *single-object* word count the incremental allocator needs — the same split as `beam_gc::copy`'s `move_size` — and the whole-graph walk is `beam_term::size`'s, driven by `CopyPricing`; the crate keeps **no** local copy of either.
  `beam_term::size_object` remains the canonical flat count, and the copier's price equals it for every shape that can cross a copy boundary (incl. a `SUB_BITS` match context, whose `object_words` is the flattened window size) — the exceptions being a literal-area subterm (0 destination words) and a refc binary the source table holds no handle for (its flattened window).
  The LCA's enumerators cover every HAMT node kind with the same `1 + header_arity + popcount(MAP_HEADER_VAL)` formulation, so a hash map copies as a whole trie and a widened fun descriptor (the 3-word `External` `[module, function, arity]` descriptor ⇒ a 4-word block) is sized and copied automatically, with no change in this crate.
## Test Strategy
- Per-module `#[cfg(test)] mod tests` (one per `src/` module) plus one `tests/*.rs` file per contract area — every file and its pinned claims is listed in the Routing Table.
- **The destination-pricing walk is pinned equivalent to the bounded reference walk.** `src/copy_reference.rs` holds that bounded walk (`bounded_words_reference`/`is_acyclic_reference`/`preflight_words_reference`) as a test-only oracle, and five `#[cfg(test)]` tests assert the shipped policy walk returns the *same* `Ok(n)` and the *same* rendered refusal for a **35-term corpus** covering every term class the copier prices — a refc binary **handled and unhandled** included, the two prices asserted *different* to prove the policy reads the `CopyContext` — at every limit `0..=count+2` and `usize::MAX`, that both walks refuse every forged cycle (self-referential cons/tuple, mutual cons cycle, a cycle behind a 100-cell valid prefix) at every finite limit, and that the shipped walk also refuses a cycle **promptly at `usize::MAX`**, the one mode in which the bounded walk can only report its own finite limit.

## Performance (measured)
Every figure and its caveat lives in `PERF.md`, reproduced by `tests/{traversals,counters,perf,send_perf}.rs` (`tests/identity.rs` holds the identity evidence, which carries no figure); prefer ratios over absolutes.
`PERF.md` §2 is the primary signal (the deterministic per-shape structural table — census vs written words, residency, blocks, bytes, the full size histogram), §7 is the scripted bench A/B over `copy_bound` (both runtimes and both binaries), and §10 is what remains by owner.
Never mix the recorded regimes: the structural and counter tables (§2/§3) are **deterministic** and load-independent (recorded in dev at `opt-level=1`; §3 is identical in release), the wall-clock tables (§4 release, §5 dev) are per-run means quoted beside their `best`, and the A/Bs (§7–§9) are **release** with `taskset -c 3` and interleaved sides — the profile the crate ships and the only one that can justify a copy-path change.
- **One walk per send shape** — the mechanism is API Surface's, the cost table `PERF.md` §2's.
  A **fit** costs one copy traversal and **no** pricing walk (`try_copy_fast` commits once into the destination's unused tail).
  A **refusal** costs one abandoned optimistic trial (nothing written — `used() == peak_used()`) plus **one** exact pricing walk whose figure the typed `Alloc(Message)` carries; a fragmenting caller then adds **one** copy into the fragment, sized from that same figure.
  A destination whose off-heap table is **non-empty** is the one shape that prices *and* copies (`tests/destination_pricing.rs` pins both routes).
- **Per-message heap allocation is the fix-up worklist alone, and it is not a wall-clock lever.** For the exact `tools/bench` `copy_bound` payload — 70 words / 27 objects (21 cons cells + 6 headed) / 1 120 B touched, 8.6 % header words, 2.59 words/object — the **copy step** allocates **2 blocks / 192 B** (the worklist `Vec`'s 64 B → 128 B growth) and the **enqueue half allocates 0**, so a warm `send` is 2 blocks / 192 B per message.
  The first send into a **cold** mailbox pays one further 480 B block — the queue's own first buffer, once per mailbox, never per message — which is the `3 blocks / 672 B` row `tests/traversals.rs` reports for the same payload's heap twin, against `1 block / 480 B` for the literal twin that needs no worklist (`PERF.md` §2/§3).
  Replacing the worklist with an inline `MaybeUninit` stack measured **neutral on the payload and 17 % slower on a 10-cons list** in release and worse in dev, so the `Vec` stays (`PERF.md` §8).
- **The whole `send` for the `copy_bound` payload is ≈ 200 ns in release** (5 runs at `taskset -c 3`, `/proc/loadavg` 29.5–36.4: mean 196.4–205.5 ns, median 198.8, best 176–179; quote the ≈ 200 with that band — `PERF.md` §4).
- **This crate is ≈ 13–19 % of the `send_recv_plain` per-op cost — a lower bound** (≈ 0.41 µs of two ≈ 206 ns payload sends per op, against this pass's 3.06 µs = 13 % and m17's 2.20 µs = 19 %; `PERF.md` §6), because that workload performs **two** payload sends per op (the request and the reply).
  The remaining ≈ 2.5 µs/op is outside this crate — `beam_rt`'s per-slice runner work and `beam_process`'s delivery path, enumerated in `PERF.md` §6/§10 — and attributing it needs counters inside the runner, not this file.
- **The two-process `copy_bound` figures are `beam_rt`'s, not this crate's.** The `send_recv` residual is the sender/receiver schedule's per-slice work (`../beam_rt/CONTEXT.md` and `../beam_rt/src/runner/CONTEXT.md` *Measured*), not a pass sleep (the pass wait is progress-aware and issues 0 `clock_nanosleep` on a `send_recv`-shaped run; `PORT_POLL_SLICE` is a non-destructive zero-timeout probe).
  Measure this crate's share from `tests/send_perf.rs` (§ Performance above), never from the two-process case; `etf_roundtrip` remains `beam_codec`'s.
## Known Issues / Intentional M1 gaps
Each entry names the crate/node that owns closing it; a gap another crate owns is restated as an adoptable signature in `## Handoffs`.
- **A destination with a non-empty off-heap table is the only remaining two-traversal copy** (owner: `beam_message`).
  The heap half exists — `beam_alloc::Heap::reset_to(used: usize) -> Result<()>` rewinds to a `used()` mark, keeps the live prefix and refuses a mark beyond it — but the off-heap half does not: `OffHeapTable::rollback` drains all three lists, so it is sound only on a table that started empty, and there is no `OffHeapTable::checkpoint() -> OffHeapCheckpoint` / `OffHeapTable::rollback_to(&mut self, cp: OffHeapCheckpoint)` pair that releases exactly the entries pushed since the checkpoint.
- **The destination-pricing preflight is one walk, and what it costs is `beam_term::size`'s two per-walk allocations** (owner: `beam_message`, with `beam_term::size`).
  `copy_struct` (`src/copy.rs`) reaches `preflight_words` on exactly two paths: a destination whose off-heap table is non-empty, and **any** destination after `try_copy_fast` fails — the common one, a container BIF result copied onto a nearly-full process nursery, which `beam_rt` then re-tries after `grow_nursery` (`beam_rt/src/context/calls.rs`).
  On that path a refusal of the 73-word `copy_bound` payload measures **10 blocks / 1 468 B**, and every block belongs to one of two producers: the copy's own trial fix-up `Vec<Fixup>` (2 blocks / 192 B — the same ladder a fit's copy half pays) and this walk's `Vec<Step>` stack plus its SipHash `HashSet<usize>` path set (`beam_term/src/size.rs:388-389`), which are the other **8 blocks / 1 276 B**; the full per-bucket histogram is `PERF.md` §2.
  The path set is the cycle detection, and the crate needs it only because a *forged* graph can point at its own ancestor: the walk is run unbounded so a back-edge is reported as the typed `BadArg` instead of hanging.
  Removing those allocations is `beam_term`'s (`## Handoffs`).
- **A flattened no-handle refc binary may exceed `ERL_ONHEAP_BITS_LIMIT`** (owner: `beam_message` if the limit is ever enforced; until then the caller's registered handle is the guard).
  `copy_match_context` writes the window with `write_heap_bits` and does not enforce the on-heap limit (the C's `HEAP_BITSTRING` only asserts it), so an off-heap payload whose handle no source table holds lands as an on-heap bitstring larger than ERTS would ever build there.
  The copy stays correct and self-contained — only the term's shape is one the emulator does not produce — so a caller that cares keeps the payload's handle registered in the off-heap table.
- **No message-queue placement state and no auto-tuning: a mailbox is always on-heap** (owner: `beam_process`, with `beam_rt` for the flags that name it).
  This crate's `send` vs `send_fragmented` choice *is* the placement decision; no crate has the C's per-process `ERTS_MESSAGE_QUEUE_DATA_ON_HEAP`/`_OFF_HEAP` state or its `erts_change_message_queue_management` / static `SPO_ON_HEAP_MSGQ` sizing rule as a replacement for `+hmqd` (which does not exist as a CLI flag).
  `{message_queue_data, off_heap}` is accepted-and-ignored by `beam_rt`'s `spawn_opt`/`process_flag`, so `process_info(P, message_queue_data)` always answers the true current `on_heap` (`beam_rt/M1_GAPS.md`).
- **The logical-size surface is exposed but nothing charges it** (owner: `beam_rt`; both adoptions are in `## Handoffs`): no send site charges the sender's copy cost, and `Message::logical_binary_bytes()` never enters a process's binary virtual heap — the accounting that exists (`beam_gc::BinVheap`, driven per process by `beam_rt`'s `OffHeapReclaimer`) is fed from the machine's payload overhead instead.
- **A received message's off-heap families are retained, never reaped** (owner: `beam_rt::mailbox::MailboxState`, adopting `beam_process`'s existing sweep — `## Handoffs`): the receiving host clones them into `MailboxState::retained_binaries`/`retained_off_heap`/`retained_nodes` (and `retained_fragments`) before the `Message` drops, and that state is never cleared, so a received payload stays alive until the runtime drops.
  `Process::sweep_off_heap_binaries_reachable` reclaims only the machine-built payloads registered in `owned_binaries`; a **fragmented** message is unaffected either way, its envelope lists being empty and its off-heap objects living in the fragment's `off_heap` table until `Fragments::move_into` hands them to the destination table.
- **No producer fills `Message.token`; it stays `NIL`** (owner: `beam_rt`, `## Handoffs`): `Message::with_token`/`set_token` and the relocation surface exist, and `beam_process`'s collection already gathers and relocates the word, but nothing stamps a token (`beam_rt/src/seq_trace.rs` lists token propagation as deliberately out of scope — the send event is emitted from the sender's own token instead).
  Stamping one also needs this crate's debug-only enqueue tripwire relaxed, since a token tuple is a heap term.
- **The external EMQX messaging target is an honest skip** (owner: `tools/bench`, `## Handoffs`): `../tools/bench/RESULTS.md` records `emqx` → `skipped(emqx-requires-otp-28)` (the checkout pins OTP 28.5.0.7-2, the host is OTP 29.1.1), so it contributes no figure; the messaging category is measured in-repo by the `copy_bound` workload (`Category::Messaging`, both runtimes).
- **A payload word that points into a fragment has no lifetime tie to it** (owner: any host of this crate; `beam_rt` today satisfies it by never releasing a `MailboxState`).
  `Message::payload` (`src/message.rs`) and `HeapFragment::copy_root`/`roots` hand the root out **by value** as a bare `Eterm`, while the fragment's words live in a standalone `beam_alloc::Heap` block that `Heap`'s `Drop` frees the moment the `Fragments` chain drops (a dequeued/dropped `Message`, `Queue::clear`).
  So such a word is valid only while the owning `Message`/`Fragments` is alive; the copy-out paths are `Fragments::move_into` and any `copy_struct` into a live heap, and `Message::with_payload` carries the same hazard in its docs.
  `HeapFragment::push_root` and `Message::with_payload` are safe but **unvalidated** entry points — nothing checks that the word points into the region a later `move_into` reads.
  Moving a `Message` (queue removal, a `Vec` reallocation) is fine: the block address is stable (only the `HeapFragment` struct moves).

## Handoffs
Gaps whose owner is another crate, each with the exact API this crate adopts once it appears (or the exact call site the owner must add where the API already exists).
- **The sender's copy charge** — owner `beam_rt`, with `beam_common` supplying the divisor.
  The C charges `min(msize / ERTS_MSG_COPY_WORDS_PER_REDUCTION, CONTEXT_REDS)` reds to the sender at queue time (`erl_message.c:881-886`); `beam_common` hosts `CONTEXT_REDS` but no `ERTS_MSG_COPY_WORDS_PER_REDUCTION` divisor, and no `beam_rt` send site charges anything (`src/context/send.rs` has no reduction charge; the runner's `process.bump_reductions(used)` accounts instruction use only).
  The adoptable shape is the existing `beam_process::Process::bump_reductions(&mut self, n: u64)` fed with `beam_common::CONTEXT_REDS.min(4 + Message::heap_words() / ERTS_MSG_COPY_WORDS_PER_REDUCTION) as u32` at every send site.
  No `beam_message` change is needed: `Message::heap_words()` is the input.
- **The message path never feeds the holder's virtual binary heap** — owner `beam_rt` (the accounting itself is `beam_gc`'s).
  The C's `bin_vheap_sz` trigger exists here as `beam_gc::BinVheap` (`new` starts at the policy's `min_bin_vheap_words`; `triggered`/`record_collection` are the trigger and the post-collection re-seed), and `beam_rt`'s per-process `OffHeapReclaimer` (`src/context/gc/bin_vheap.rs`) drives it from `Machine::off_heap_overhead_bytes()`.
  What is missing is the message half: `Message::logical_binary_bytes()` never enters that budget when a message becomes the process's, and no `bin_vheap_size`/`virtual_reds` figure is reported (`erl_gc.c:3046,3051`); `beam_process::Process` models no binary vheap of its own.
- **Message-queue placement and auto-tuning** — owner `beam_process`.
  `pub enum MessageQueueData { OnHeap, OffHeap }`; `Process::set_message_queue_data(&mut self, mode: MessageQueueData)`; `Process::message_queue_data(&self) -> MessageQueueData`; and the decision itself, `Process::plan_message_placement(&mut self, heap_free_words: usize, payload_words: usize) -> MessagePlacement` with `pub enum MessagePlacement { OnHeap, Fragment { capacity_words: usize } }` (the C `erts_change_message_queue_management`).
  Consumers: `beam_rt`'s send path routes `Fragment` to `beam_message::send_fragmented` and `OnHeap` to `beam_message::send`; `spawn_opt`/`process_flag`/`+hmqd` store and parse the flag instead of accepting-and-ignoring it.
- **Token stamping** — owner `beam_rt`.
  At each send site, `Message::with_token(t)` with `t` the `{Flags,Label,Serial,From,Lastcnt}` tuple for a sender whose token has `seq_trace::FLAG_SEND` (`seq_trace.rs`'s `sequential_trace_token` already builds it).
  Prerequisite here: this crate relaxes `debug_assert_enqueue_terms` (a token tuple is a heap term, which the tripwire rejects today); `beam_process`'s `run_rooted_collection` already gathers and relocates the word.
- **Reaping a received message's off-heap families** — owner `beam_rt`, no new sibling signature needed.
  In `mailbox::MailboxState::remove_at`, register each `Message::binaries()` payload through `Process::register_off_heap_binary(&mut self, binary: RefcBinary) -> usize` (so `Process::sweep_off_heap_binaries_reachable()` reclaims it) and each `Message::off_heap()` handle through `Process::off_heap_mut() -> &mut OffHeapTable`, instead of only cloning them into the never-cleared `retained_*` vectors — which then become a per-scan cache rather than ownership.
- **A runnable `emqx` profile** — owner `tools/bench`.
  `Workload::probe` must answer `Probe::Ready` for `emqx` on the host it runs on (an OTP-28-matching runner image, or a checkout whose `env.sh:3`/`.tool-versions:1` pin matches the host), so a session records a figure instead of `skipped(emqx-requires-otp-28)`.
- **One walk yielding both the exact price and the fits/doesn't verdict** — owner `beam_term` (`src/size.rs`).
  `preflight_words` needs **one** walk only because it runs the bounded walk unbounded (`size_object_bounded_with(term, usize::MAX, &policy)`, `size.rs:565`); any caller that wants an exact count **and** a work limit must pay `is_acyclic` (`size.rs:448`) on the `OverLimit` arm, i.e. **2 more hash tables**.
  Adoptable shape: `size_object_measured_with(a: Eterm, limit: usize, policy: &dyn SizingPolicy) -> Result<MeasuredSize, TermError>` with `enum MeasuredSize { Acyclic { words: usize, fits: bool }, Cyclic { words: usize } }` — the walk **latches** "over limit" instead of returning early, so the exact price and the fits/doesn't verdict come from one traversal and a limit stops being a work bound.
  Those two allocations are the 8 blocks / 1 276 B a refusal pays beyond the copy's fix-up worklist (Known Issues, `PERF.md` §2/§10); a **bounded fixed-stack** cycle check would remove both — the legacy C has no cycle check at all (it trusts acyclic heaps) — provided `SizingPolicy::object_words` returning `Some(0)` for a cyclic graph stays a safe answer.
- **The message path's pre-attempt + retry, and stale prose** — owner `beam_rt`.
  A refused *delivery* is **2 copy attempts + 1 pricing walk** (`PERF.md` §2): `src/context/send.rs`'s `deliver_into_mailbox` calls `ProcessTable::deliver` and only then `send_fragmented_message`, which calls `beam_message::send_fragmented(…, 0)`. The message-path analogue of the existing `copy_out_hint`/`hint_grow_gate` gate (`src/context/calls.rs:1313-1332`) is what would stop the first, always-doomed attempt.
  That node's prose still describes the retired 3-walk/multi-traversal path: `src/context/calls.rs:1280`, `:1316`, `:1389`, `src/context/runtime_context.rs:159`, `src/context/calls/tests.rs:190`, `:529`, `PERF_DISPATCH.md:252`, `:279`, `:387`, `src/bench/CONTEXT.md:242`, `:270`.
- **Control-signal fragment sizing** — owner `beam_process` (`src/ptab.rs:344`, `enqueue_fragment_payload`).
  `HeapFragment::new(size_object(payload) + 8)` walks the whole payload once just to size the fragment; adopting this crate's refusal-derived exact price (`AllocFailure::requested / size_of::<Eterm>()`, the `send_fragmented` route) removes that walk.
- **`send_recv` vs `send_recv_plain`** — owner `beam_codec`.
  The delta between those two cases (`PERF.md` §6) is the worker's `binary_to_term(term_to_binary(T))` round trip, **not the copy** — the plain case's payload copies are 3 words (the literal is shared). Measure the codec's share before claiming any part of that pair.

## Notes for Agents
- **The copier takes the source as a bare `Eterm` and holds NO source-region knowledge.** `copy_struct`/`copy_struct_simple`/`CopyContext::new` accept no base/extent/heap-identity for the source — `CopyContext` has exactly two fields, `src: &OffHeapTable` and `dst: &mut OffHeapTable` (`src/copy.rs:222-225`) — and the walk dereferences whatever the graph says (`src/copy.rs:527-543` for a cons, `:571-573` for a header, `:594-598` for `copy_nonoverlapping`).
  Source-word guards are **tag tests only** (`is_shared` at `src/copy.rs:267-275`, `primary_tag` dispatch at `:527`, the `PrimaryTag::Header` arm at `:614`), so a stale `LIST`/`BOXED`-tagged pointer into a reset/pooled `beam_alloc::Heap` or a `beam_ets::TermStore` passes every one of them.
- The crate's only region-membership test is **destination**-side: `HeapFragment::contains` (`src/fragment.rs:199`, `hend - capacity`..`hend`). There is no source-side equivalent, and `beam_alloc::Heap` exposes no `base()`/live-region registry, so "is this word in a live term heap" is not askable anywhere in the workspace.
- `copy_match_context` (`src/copy.rs:471-490`) flattens by reading `base_flags` as the payload **base pointer** and `start..end` as the extent, with no liveness or plausibility check on either — the fallback path dereferences a pointer whose owning handle need not exist.
- `copy_struct_shared`'s memo keys on the source **address** (`src/share.rs:70` via `copy::identity`), so an address-coincident stale pointer aliases a real subterm's copy — wrong sharing, not a fault.
- **What the copier *does* guarantee: a completed copy is self-contained.** Every child slot `beam_term::layout::for_each_child_slot` reports (tuple/record elements, fun env, flatmap keys+values, HAMT slots, an `ErlSubBits`'s `orig`) is re-copied or fix-up'd (`src/copy.rs:594-610`) and that enumeration covers every term class (`beam_term/src/layout.rs:227-320`), so a **live** source graph yields a destination naming nothing outside it except the shared classes below — provenance is unaskable, but a completed copy is not a leak.
- **The two verbatim survivors are the escape hatches.** `is_shared` returns a literal-tagged compound unchanged and neither descends it nor records a fix-up (`src/copy.rs:271-274`, `:298`), so a literal-tagged word into non-permanent storage would cross verbatim; and the `PrimaryTag::Immed1` arm returns `src` unchanged (`:616`). No producer tags anything but a module literal area today (`beam_term::literal::tag_literal_area`, called from `beam_loader`'s `LiteralArea::decode`).
- **`copy_struct_simple` *is* `copy_struct`** (`src/copy.rs:742-747`, two throwaway tables), so over a foreign source it **flattens** every refc binary (no handle in the empty source table ⇒ `refc_binary_words`/`copy_refc_binary` take the window deep-copy) and refuses an MSO container with a typed `BadArg` (`clone_slot` → `None`, `:548-556`); its local `dst` table drops at return, releasing only node references.
- The copier **never writes the source**: it writes the destination through `reserve`, plus — on the fast path only — the destination's *unwritten* tail `[hp, hp+available)`, committed with one `alloc_words` (`TrialTarget`, `:165-218`, `:664-666`). Destination `&mut Heap` + `&mut CopyContext` make one copy exclusive and non-reentrant by borrowck; there is no global copier state.
- **Identity is preserved only *within one call*.** `copy_struct_shared`'s memo is a local `HashMap` dropped at return (`src/share.rs:70`, `:82`) and is not exposed, so copying a **root set** in N calls duplicates every subterm shared *between* roots — `Fragments::move_into` (`src/fragment.rs:300-306`) does exactly that (one `copy_struct`, one `CopyContext`, per root). Nor are off-heap registrations deduped across calls: every occurrence of an MSO object clones the handle into a **fresh** slot and every occurrence of a refc binary pushes another handle (`src/copy.rs:548-555`, `:438`; `push_binary` never dedupes, `src/off_heap.rs:202-205`), so a re-copy into a live destination table grows it by one entry per occurrence and the only release is the wholesale `rollback` (`src/off_heap.rs:305-311`, sound only on an empty start).
- **A constant-delta move is not something this crate can do.** Interior pointer words are rewritten only for a *copy* (fresh objects at fresh addresses, `src/copy.rs:594-610`); there is no delta-rebase pass and no `Target` seam a foreign region could implement (`CopyTarget` is `pub(crate)`, `src/copy.rs:133`). The workspace's cheap move primitive is `beam_alloc::ReservedHeap::relocate` (`../beam_alloc/src/reserved_heap.rs:228-259`), which returns a byte delta and explicitly leaves interior pointers to the caller (`:217-227`); the descent set such a rebase must cover is exactly the one `tests/guards.rs:262-344` walks — cons/2 words, tuple/record elements, a fun's **env only**, flatmap keys+values, HAMT slots, an `ErlSubBits`'s `orig`, and a refc binary's on-heap pair (never the shared payload pointer).
