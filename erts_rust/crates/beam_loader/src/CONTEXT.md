# `beam_loader/src/` — Reader, Decoder, IR, Literal Area

## Intent
The crate's top layer: the container walk plus the **frozen public IR** (`Module` and friends) that `beam_engine` designs against, the opcode roster, the operand/instruction decoder, and the load-time materialization of literals, attributes and the checksum.
Routing: chunk byte layouts → `chunk/`; opcode→IR semantics and validation → `lower/`.
The FROZEN API surface is defined here; `chunk/` and `lower/` are internals behind it (except where a child exposes a public helper, noted at that node).

## API Surface (FROZEN — `beam_engine` designs against this)
Re-exported at the crate root and via `beam_loader::prelude::*`.
### Entry points (`load.rs`)
- `pub fn load(bytes: &[u8]) -> Result<Module>`; `pub fn load_file(path: impl AsRef<Path>) -> Result<Module>` (slurp + `load`). These are the *only* entry points; all intermediate types are public for inspection/testing.
### Identifiers (`ir.rs`, `operand.rs`)
- `pub type Atom = beam_term::Atom;` — an index into the crate-owned `AtomTable` (NOT the wire index).
- `pub struct Label(pub u32);` + `pub const NO_FAIL: Label = Label(0);` (the `f,0` failure sentinel).
- `pub enum Reg { X(u32), Y(u32) }`.
- `pub struct TypeIndex(pub u32);` — index into `Module.types`; `0` = the "any type" entry.
- `pub struct ImportRef(pub u32);` — index into `Module.imports`.
- `pub type LineRef = u32;` — index into `Module.line.items` (`items[0]` = undefined location).
- `pub enum Operand { X(u32), Y(u32), Integer(i64), Atom(Atom), Nil, Label(Label), Character(u32), FloatReg(u32), Literal(u32), Typed { reg: Reg, ty: TypeIndex }, List(Vec<Operand>), Allocation(Vec<AllocKind>), BigInteger { negative: bool, magnitude: Vec<u8> } }` — a *typed* `.beam` operand.
  - `Operand::BigInteger` is **decode-time-only** (the C `TAG_o` overflow state for an `i` operand wider than a machine word); `build_module` rewrites it to a synthesized `Operand::Literal` (a bignum literal), so a loaded `Module` never carries it.
  - `Operand::Literal(idx)` indexes the module's decoded `LiteralArea`, resolved through `Module::literal`.
- `pub struct AllocKind { pub kind: u32, pub number: u32, pub words: u32 }` — one decoded `z,3` entry, `words` per `marshal_allocation_list`: kind `0` (raw words) → `number`, kinds `1` (floats) / `2` (funs) / `3` (native records) → `2 × number` (`FLOAT_SIZE_OBJECT`/`ERL_FUN_SIZE`/`RECORD_INST_SIZE(0)`, all `2` on 64-bit).
- `pub enum HeapNeed { Words(u32), Alloc(Vec<AllocKind>) }` — the heap/stack-need operand of the frame instructions in *either* wire encoding, with `HeapNeed::words(&self) -> u32` (saturating total) and `HeapNeed::from_operand(&Operand) -> Result<HeapNeed>`; the field type of `Instr::TestHeap`, `Instr::AllocateHeap` and `Instr::Allocate`.
### Operand tags (`operand.rs` + `decode.rs`) — the authoritative table
Each operand = one *tag/length* byte then optional payload. Tag = `byte & 0x07` (a file carries only tags 0–7; tags 8–14 are loader-internal and never appear in a file):

| byte | tag | meaning | payload |
|---|---|---|---|
| 0 | `u` | untagged integer | varint magnitude |
| 1 | `i` | integer (sign-extended) | varint magnitude; fits a small int ⇒ `Integer` |
| 2 | `a` | atom index (0 ⇒ NIL) | varint index |
| 3 | `x` | X register | varint ≤ 1023 |
| 4 | `y` | Y register | varint ≤ 1023 |
| 5 | `f` | label (0 ⇒ `NO_FAIL`) | varint < label_count |
| 6 | `h` | character | (defined, never emitted by the compiler) |
| 7 | `z` | extended: sub-tag varint follows | see below |

The tag byte encodes a variable-length integer: if `byte & 0x08 == 0` the value is `byte >> 4` (0–15); else if `byte & 0x10 == 0` a 1-byte BE tail combines to 0–0x7FF; else `(byte>>5)+2` BE magnitude bytes; if `(byte>>5)==7` a `u`-tagged sub-varint gives `count = S+9` bytes.
`z` sub-tags: `1` = argument list (`u count` then `count` sub-operands → `Operand::List`); `2` = float register (`u` index → `Operand::FloatReg`); `3` = allocation list (`u count` then `count`×(`u kind`,`u number`) → `Operand::Allocation`); `4` = static literal (`u` index → `Operand::Literal`); `5` = **typed register `tr`** (nested `x`/`y` sub-operand then a `u` type index → `Operand::Typed`); `0` (obsolete float) and any other ⇒ `BadArg`.
**`tr` packing:** the file carries `reg | (type_index << 10)` conceptually, but the loader keeps reg and `TypeIndex` **separate** in `Operand::Typed`; if the `Type` table is a fallback the tag collapses to a plain `X`/`Y` operand (the type index is discarded).
### Structural bounds enforced at decode (`decode.rs`)
Mirrors the C reader's `LoadAssert`s — a construct the C rejects is a typed error here too, never a silently-accepted wrong value: a non-zero `f` label index `< label_count` (recursively inside a `z,1` list); `x`/`y` register index `< MAX_REG` (1024, `erl_vm.h:49`) and `z,2` float-register index `< MAX_REG`; `z,5` `tr` type index `< TypeTable.entries.len()` when the table is not a fallback; `z,3` allocation list `<= 4` entries, per-entry `number <= i32::MAX/3` and running word total `<= i32::MAX` ⇒ `SystemLimit`; a `z,1` argument list only in the instruction's final operand slot; a `z,4` static-literal index `< the file's own LitT count`, checked in `build_module` *before* synthesized literals are appended (covers `load`, `beam_rt`'s code-server path and `beam_engine`'s test support); a `z,4`/`h` magnitude that would truncate on the 32-bit `Operand` field ⇒ `SystemLimit` (never a silently-wrapped, different-but-valid index).
### The IR (`ir.rs` + the re-exported `instr.rs`)
- `pub struct Module { pub name: Atom, pub atoms: Vec<Atom>, pub atom_table: AtomTable, pub exports: Vec<Export>, pub locals: Vec<Export>, pub imports: Vec<Import>, pub functions: Vec<Function>, pub funs: Vec<FunDescriptor>, pub records: Vec<RecordDefinition>, pub code_version: CodeVersion, pub types: TypeTable, pub line: LineTable, pub literals: Arc<LiteralArea>, pub strings: Vec<u8>, pub attributes: Option<Vec<u8>>, pub attribute_table: SharedAttributeTable, pub compile_info: Option<Vec<u8>>, pub compile_info_table: SharedDecodedTerm, pub meta: Option<Vec<u8>>, pub meta_table: SharedDecodedTerm, pub checksum: [u8; 16] }`
  - Accessors: `atom_name`, `export(Atom,u32)`, `function(Atom,u32)`, `literal(u32)`, `literals()`, `checksum()`, `fun(u32)`, `funs()`, `records()`, `record(Atom)`, `record_by_name(&str)`, `attributes_term()`/`attribute_by_name(&str)`, `compile_info_term()`/`compile_info_by_name(&str)` (what `module_info(compile)` serves), `meta_term()`/`meta_by_name(&str)`; all `None` when the chunk is absent/malformed, never a panic.
  - `records` is the lowered `Recs` table (native-record definitions, declaration order); `record_by_name` resolves a *runtime* atom by looking its string up in the module's `atom_table` first (the `records:get_definition/2` lookup).
  - `atoms[i]` = the atom for wire index `i`; `atoms[0]` = `Atom::MAX` (NIL placeholder).
  - `Module` is `Clone` + `Debug` but **neither `Send` nor `Sync`** (it owns a `LiteralArea`, see below) — a loaded module stays on its loading thread.
  - Only `literals`/`attribute_table`/`compile_info_table`/`meta_table` are `Arc`-shared by a clone; `atoms`/`atom_table`/`exports`/`imports`/`functions`/`records` are **deep-copied**, and `beam_term::AtomTable::clone` is Θ(atoms) by design (`beam_term/src/atom.rs`), so `Module::clone` is Θ(module size), not O(1) — which is why `beam_rt`'s code server caches and hands out `Arc<Module>` (`beam_rt/src/codeserver.rs`) instead of cloning.
- `pub struct Export { pub function: Atom, pub arity: u32, pub label: Label }` — `label` = the function **entry label**; `Module.locals` holds one `Export` per `LocT` entry (the JIT-only local-function table; interpretation ignores it).
- `pub struct Import { pub module: Atom, pub function: Atom, pub arity: u32 }`.
- `pub struct Function { pub func_label: Label, pub entry_label: Label, pub module: Atom, pub name: Atom, pub arity: u32, pub code: Vec<Instr>, pub blocks: Vec<Block>, pub labels: BTreeMap<Label, usize> }` — `func_label` is the label **before** `func_info`, `entry_label` the one **after** it (what `Export.label` points to); `labels` maps every label in the function to its index in `code`; `blocks` is the label-delimited decomposition.
- `pub struct Block { pub label: Label, pub start: usize, pub end: usize }`.
- `pub struct CodeVersion { pub format_number: u32, pub max_opcode: u32, pub label_count: u32, pub function_count: u32 }` (from the `Code` header; `format_number` must be `0`).
- `pub struct TypeTable { pub entries: Vec<Type>, pub fallback: bool }`, `pub struct Type { pub raw: u16, pub lower: Option<i64>, pub upper: Option<i64>, pub unit: Option<u8> }`.
- `pub struct LineTable { pub flags: u32, pub instruction_count: u32, pub items: Vec<LineEntry>, pub files: Vec<String> }`, `pub struct LineEntry { pub file: u32, pub line: u32 }`.
- `pub struct FunDescriptor { pub function: Atom, pub arity: u32, pub label: Label, pub index: u32, pub num_free: u32, pub uniq: u32 }` — one `FunT` lambda descriptor; `Module::fun(i)` selects the entry whose `make_fun3`/`call_fun2` *fun-table index* is `i` (its position in `Module::funs`).
  - `function` is the `FunT` entry's **function atom** — the atom of the function whose body `label` names (`beam_dict:lambda_table/1`), i.e. exactly the name `erlang:fun_info(F, name)` reports: `mk` for a named local fun, the compiler-generated `'-anon/1-fun-0-'` for an anonymous `fun … end` (oracle-cross-checked by `tests/fun_name.rs`).
  - **`FunDescriptor.arity` is the lambda's FULL arity (captured free vars + exposed args), NOT the exposed arity** — the `ir.rs` field doc's "non-captured" wording is wrong. The exposed closure arity is `arity - num_free` (C: `lambda->arity - lambda->num_free` to `erts_fun_entry_put`, `asm_load.c:1223`/`emu_load.c:650`; the FunT `A` field is the underlying function's arity = free+args).
  - **`NEW_FUN_EXT` (`112`) six-field local-fun identity — where each field comes from.** The `make_fun3` closure term inlines only `[uniq:u64][index:u32]` (`beam_term::fun`), so the wire identity is derived by the runtime (`beam_rt`'s `local_fun_identity`, `context/bridges.rs`) from the *loaded* `Module`; the loader supplies everything but re-reading the file:
    - `module` → `Module.name` (atom; resolve in the caller's table).
    - `index` (new-style) → `FunDescriptor.index` = the `FunT` `index` field.
    - `uniq` (**16 bytes**) → **`Module::checksum()` / `Module.checksum: [u8;16]`** = the module MD5 (`beam->checksum`), NOT `FunDescriptor.uniq` (that is the 4-byte `old_uniq` — naming trap).
    - `old_uniq` → `FunDescriptor.uniq` (u32) = the `FunT` `old_uniq` field.
    - `old_index` → **the FunT table POSITION** (the C passes the loop index `i`, `asm_load.c:1220`/`emu_load.c:647`), not the `FunT` `index` field and not `FunDescriptor.label`. There is **no `old_index` field**; it is the vector position (`Module.funs().iter().position(..)`), which the loader preserves by keeping `funs` in FunT file order (`beam_rt::context::bridges::descriptor_position`).
    - `num_free` → `FunDescriptor.num_free`; free vars come from the term env. `arity` byte = `arity - num_free`.
  `funs` retains all six FunT fields (function/arity/label/index/num_free/old_uniq) and `attributes: Option<Vec<u8>>` retains the raw `Attr` bytes (`attribute_table` is the decoded term); the raw `FunT` bytes are not kept (nothing is lost) and `load()` drops the container bytes, so a byte-level consumer re-parses via `container::parse`. `checksum` is precomputed at load, so no `.beam` re-read is needed for the uniq.
- `pub struct RecordDefinition { pub name: Atom, pub is_exported: bool, pub fields: Vec<RecordField> }` — one `Recs` **native-record** definition (`-record #name{…}`), i.e. what `records:get_definition/2` serves as `{#{is_exported => Bool}, Fields}`. `fields` is in **declaration order** (file order — never sorted).
- `pub struct RecordField { pub name: Atom, pub default: Option<Eterm> }` — `None` is the file's **absent** sentinel (`u,0`), *distinct* from a default literally `0` (`i,0` ⇒ `Some(<small 0>)`); see Design Decisions.
### The module checksum (`checksum.rs`)
- `pub fn module_md5(raw: &[RawChunk<'_>]) -> Result<[u8; 16]>` — the 16-byte MD5 the C loader stores in `beam->checksum` and `beam_lib:md5/1` reports, over the **raw, unpadded payloads** of the chunk directory in the *fixed* order `Atom` (obsolete Latin-1; only if present) · `AtU8` · `Code` · `StrT` · `ImpT` · `ExpT` · `FunT'` · `LitT` · `Meta` · `Recs` · `DbgB`, with `Line`/`LocT`/`Attr`/`CInf`/`Type`/`Docs`/`Dbgi` excluded; an absent/empty chunk contributes nothing.
  - `FunT'` digests the 4-byte entry count then each 24-byte entry's first 20 bytes followed by 4 zero bytes (`OldUniq` forced to zero); a `FunT` that is not `4 + 24n` bytes ⇒ `BeamError::BadArg`.
  - The MD5 arithmetic is `beam_common::md5::digest` — the workspace's **one** RFC 1321 implementation — so this module owns only the chunk walk and the `FunT'` filtering; the crate exposes no MD5 of its own. Pass `Chunks::raw`.
### The literal area (`literal.rs`)
- `pub struct LiteralArea` — the `LitT` literals materialized into **one immutable heap** at load; private fields (`heap: Option<Heap>`, `terms: Vec<Eterm>`), manual `Debug` + `Default` (empty). API: `LiteralArea::empty()`, `decode(raw: &[Vec<u8>], atoms: &mut AtomTable) -> Result<LiteralArea>`, `get(&self, u32) -> Option<Eterm>` (root returned **by value**, so callers never hold a borrow of the roots `Vec`), `len`, `is_empty`, `terms(&self) -> &[Eterm]`, `heap(&self) -> Option<&beam_alloc::Heap>`.
- Decoding goes through `beam_codec::decode_term` into a private `beam_alloc::Heap`; an exhausted decode is retried (bounded) on a larger arena, a malformed payload is a typed `BeamError`.
- **`decode` literal-tags the decoded arena and its roots** before publishing: `beam_term::literal::tag_literal_area(heap.used_words_mut(), &mut terms)` — the safe form of the C load-time `erts_set_literal_tag` (`erts/emulator/beam/erl_term.c`) — so every BOXED/LIST word and every root carries `TAG_LITERAL_PTR` (an off-heap literal region the collector leaves alone).
- Tagging happens **only at this `decode` call site**; the shared `decode_terms`/`decode_terms_at_capacity` helpers stay untagged for `attributes.rs`'s `AttributeTable`, whose terms are ordinary heap terms.
- **Why the tagging matters (do not remove it).** An **untagged** live literal-area root makes `beam_rt`'s collector decline the collection (`context::gc::root_is_unscanned`), so a copy-bound loop whose only live root is a module literal never collects and its heap grows linearly. With tagging the loop collects (measured ≈0.33 GC/op, `heap_size` flat ≈700 words, flat peak RSS, vs a pre-tag linear `heap_size = 466 + 94·N`). See `beam_term/CONTEXT.md` (`literal.rs` / `TAG_LITERAL_PTR`) and `tools/bench`.
- `pub type SharedLiteralArea = Arc<LiteralArea>;` — the type of `Module.literals`; `LiteralArea` is **not `Send`/`Sync`** (it owns a raw-pointer `Heap`), and therefore neither is a loaded `Module`.
### The instruction vocabulary (`instr.rs`, re-exported by `ir.rs`)
- `pub enum Instr` — **108** variants: 107 named, typed variants covering the opcode families the compiler emits, plus the lossless fallback `Generic { op: Opcode, operands: Vec<Operand>, offset: u32 }`. Every variant's field order is the **file's** operand order (`emu/ops.tab`). Families: **framing** (`Label`, `Line`, `FuncInfo`, `IntCodeEnd`) · **moving** (`Move`, `Swap`) · **calls** (`Call`, `CallLast`, `CallOnly`, `CallExt`, `CallExtOnly`, `CallExtLast`, `Bif0`, `Bif`, `GcBif`, `CallFun`, `CallFun2`, `Apply`, `ApplyLast`) · **funs** (`MakeFun3 { index, dst, env }`, `index` = the `FunT` fun-table index) · **tests** (`Test`, `SelectVal`, `SelectTupleArity`, `Jump`) · **stack frames** (`Allocate`, `AllocateHeap`, `TestHeap`, `InitYregs`, `Deallocate`, `Trim`, `Return`, `DeallocateReturn` — the loader's only superinstruction) · **tuples** (`PutTuple2`, `GetTupleElement`, `SetTupleElement` — the OTP≤28 in-place write) · **lists** (`PutList`, `GetList`, `GetHd`, `GetTl`) · **maps** (`GetMapElements`, `HasMapFields`, `PutMapAssoc`, `PutMapExact`) · **records** (`UpdateRecord` + the OTP-29/30 native-record family 186-193: `IsAnyNativeRecord`, `IsNativeRecord`, `GetRecordElements`, `PutRecord`, `IsRecordAccessible`, `GetRecordField`, `GetRecordElementsId`, `UpdateRecordId`) · **exceptions** (`Badmatch`, `CaseEnd`, `IfEnd`, `Try`, `Catch`, `TryCase`, `TryEnd`, `TryCaseEnd`, `CatchEnd`, `Raise`, `Badrecord`, `BuildStacktrace`, `RawRaise`) · **floating point** (`Fmove`, `Fconv`, `Fadd`, `Fsub`, `Fmul`, `Fdiv`, `Fnegate`) · **messages/receive** (`Send`, `LoopRec`, `LoopRecEnd`, `Wait`, `WaitTimeout`, `Timeout`, `RemoveMessage`, `RecvMarker{Reserve,Bind,Clear,Use}`) · **binary syntax** (`bs_*`: `BsStartMatch3`, `BsStartMatch4`, `BsMatch`, `BsMatchString`, `BsGetTail`, `BsGetPosition`, `BsSetPosition`, `BsGetInteger2`, `BsGetFloat2`, `BsGetBinary2`, `BsSkipBits2`, `BsTestTail2`, `BsGet/SkipUtf8/16/32`, `BsInitWritable`, `BsCreateBin`) · **debug markers** (`ExecutableLine`, `DebugLine`, `NifStart`, `OnLoad`) · **fallback** (`Generic`).
  The exact field sets are in `src/instr.rs` — read that, not this summary. Notes worth keeping: `IsAnyNativeRecord` (186, the `erlang:is_record/1` guard) is a dedicated `Instr` variant rather than a `TestKind` (the engine matches exhaustively); `SetTupleElement.offset` / `UpdateRecord`'s fields are the file's raw compiler "Position" indices; `BsMatch.commands` and `BsCreateBin.segments` are the file's flattened sub-operand lists; `PutRecord`/`GetRecordField`/… carry the file's decoded operands verbatim.
- `pub enum TestKind` — the classification of the `is_*`/`test_arity` family (`IsLt, IsGe, IsEq, IsNe, IsEqExact, IsNeExact, IsInteger, IsFloat, IsNumber, IsAtom, IsPid, IsReference, IsPort, IsNil, IsBinary, IsBitstr, IsList, IsNonemptyList, IsTuple, IsMap, IsBoolean, IsFunction, IsFunction2, IsTaggedTuple, TestArity`) with `TestKind::from_opcode(Opcode) -> Option<TestKind>`; `Instr::Test` carries the kind + failure label + tested operands (`fail` is *not* in `args`). Semantics follow the C: `IsEq`/`IsNe` are **arithmetic** `==`/`!=`; `IsEqExact`/`IsNeExact` are **exact** `=:=`/`=/=`; `IsList` accepts `[]`, `IsNonemptyList` does not; `IsFunction2` is a fun of exact arity; `IsTaggedTuple` is a tuple of the given size whose element 0 is the tag.
- `pub type LineRef` / `pub use beam_term::Eterm;` are re-exported from `ir.rs` (the resolved type of `Module::literal`).
### The opcode roster (`opcode.rs`)
- `pub enum Opcode` — one variant per generic opcode (the full `genop.tab` roster), with `from_u8(u8) -> Option<Opcode>`, `as_u8`, `name(self) -> &'static str`, `arity(self) -> u8`. Complete and lossless so unmodelled instructions round-trip as `Instr::Generic`.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** — no crate-local error enum. Malformed/truncated container, bad magic, bad format number, unknown opcode tag, out-of-range atom/label/register index, structurally wrong operand, unsupported `z` sub-tag ⇒ `BeamError::BadArg`; a size/arity/count bound (arity > 255, more than `ERTS_BEAM_MAX_OPARGS`, negative chunk size, atom name not UTF-8-representable, an inline operand wider than 8 magnitude bytes) ⇒ `BeamError::SystemLimit`. **Never panic, never `unwrap()` on file data, never silently accept a malformed image.**
- **`unsafe` is forbidden in this crate** (`#![deny(unsafe_code)]`) — the loader is the *safe periphery*; zero-copy is achieved safely via `beam_codec::Reader::bytes(n) -> Result<&'a [u8]>`.
- **Reuse, don't duplicate.** The big-endian byte cursor is `beam_codec::Reader` (the BE-bounds LCA) — do **not** write a second BE reader.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_codec`, `beam_alloc`, `libc`. Adding a dependency edge requires reporting to the crate-layer node (`../../`).
- **Generated data is source, not output.** The opcode roster comes from `genop.tab`; the crate embeds a **regenerable** table — never hand-guess a byte value.
- **Files ~1000 lines**, one responsibility per file. `instr.rs` is one flat module — an enum cannot be split across submodules. Licensing Apache-2.0.

## Design Decisions
- **The opcode roster is embedded from `genop.tab`.** `Opcode` enumerates every generic opcode in `lib/compiler/src/genop.tab` (the checked-in, wire-frozen roster the compiler emits; `format_number` bumps when it changes). `opcode.rs` holds the name/number/arity table, derived verbatim via `^<n>: <name>/<arity>` with all entries kept so the mapping is bijective. **Regeneration:** re-read `genop.tab`; the numbers are the file's first field.
- **BIF operands are `ImpT` indices, NOT `bif.tab` numbers.** The `gc_bif*` BIF operand is a plain `u` = the index of `{module,function,arity}` in `ImpT`; the IR stores `ImportRef` and the engine resolves `Module.imports[bif]`. **CROSS-CRATE CONTRACT (binding on `beam_bifs`):** the engine/BIF layer keys BIFs by `(module, function, arity)` following real `bif.tab` naming — the loader does **not** know and must **not** encode `bif.tab` numbering. `Module.imports` is the single source of BIF identity.
- **`Instr` and `TestKind` live in `instr.rs`, re-exported from `ir.rs`.** The vocabulary is one large flat enum; `ir.rs` does `pub use crate::instr::*;`, so `crate::ir::Instr`, `crate::Instr` and `prelude::*` are unchanged.
- **`HeapNeed` preserves both need encodings.** `allocate`/`allocate_heap`/`test_heap` accept their word need as either a plain count or a `z,3` allocation list; `HeapNeed::words()` recovers the total for the heap-overflow check while `HeapNeed::Alloc` preserves the per-kind breakdown a JIT or precise allocator may want.
- **The literal area is write-once, so it is shared behind an `Arc`**, and its `beam_alloc::Heap` is one fixed carrier block that never reallocates (`heap.rs` `alloc_words`; `LiteralArea` exposes it only as `Option<&Heap>`, so no caller can `reset`/extend it). The `LiteralArea` *struct* moves into its `Arc` after decoding; the pointed-to words do not.
- **A decoded literal is *self-contained inside the one arena* — nothing in a literal term points out of it.** `decode` goes through `beam_codec::decode_term`, whose `Decoder` installs **no** `OffHeapBinaries` host, so `decode_bitstring` always takes the in-arena `make_bitstring` branch: a literal binary/bitstring stays an `ErlHeapBits` block whatever its size (`> ERL_ONHEAP_BINARY_LIMIT`/`ERL_ONHEAP_BITS_LIMIT` included) — no `BinRef`/refc payload is ever minted for a literal. Tuples/lists/floats/bignums are `Heap::tuple`/`Heap::cons`/`make_float`/`make_big` blocks; a map (flat or HAMT) is serialized wholly into the reservation by `beam_term::map::write_map` (its `TrieNode` is temporary Rust memory); a fun inlines its descriptor (`beam_term::fun`, the documented M1 substitution of the C `ErlFunEntry`/`Export` pointer), so no fun literal points at a table. Immediates carry no pointer; an atom is an index into `Module::atom_table`, the same table the literals are interned in (`build_module` decodes them *before* moving the table into the `Module`). Consequence: a literal `Eterm` handed to running code needs only the owning `Module` alive — hence `beam_engine` may refuse an in-place write (`terms/update.rs` `is_literal`) but never has to copy one out.
- **`beam_alloc` is the literal-materialization dependency.** `literal.rs` decodes into a `beam_alloc::Heap` (the in-workspace `beam_loader → beam_alloc` edge, no cycle); `beam_term::heap::Heap` remains a test arena only.
- **The checksum is computed inside `build_module`, from a retained raw chunk directory.** `chunk::parse` keeps the directory on `Chunks::raw` (`RawChunk` is `Copy`), and `build_module` calls `checksum::module_md5(&chunks.raw)` and stores it on `Module::checksum` — no signature change, so the public `load` and every manual sibling pipeline (`beam_rt`/`beam_engine`) get the digest for free. Stored as `[u8; 16]` rather than re-derived per query.
- **Atoms are interned in file order into a crate-owned `AtomTable`.** `Module.atoms[i]` maps the wire index to the interning `Atom`; `atoms[0]` = `Atom::MAX` (NIL). Interning into a *shared, `atom.names`-seeded* table (needed for preloaded/positional atoms) is `beam_rt`'s job. **Shared-table seam — no dedicated entry point exists:** `load`/`load_file` always build a *private* per-module table. To share, drive the pipeline manually: `container::parse` → `chunk::parse` → intern `chunks.atoms[1..]` (wire order) through the shared table into a `Vec<Atom>` → `decode::decode_stream(stream, &atoms, &code_version, &types)` → `lower::build_module(&chunks, &raw, table)`. **`build_module` takes the `AtomTable` by value and moves it into `Module.atom_table`**, so pass a *clone* of the shared table to keep the same numbering; every atom index in the IR then indexes the shared table.
- **The instruction decoder takes the atom map and the type table.** `decode_stream(stream, atoms, version, types)` and `decode_operand(r, atoms, types)` (loader-internal — *not* part of the frozen `ir`/`prelude`/`load` surface) resolve an `a` operand to the interned `Atom` at decode time and collapse a `z,5` `tr` via `types.fallback`, so `RawInstr` operands already hold interned atoms and `lower` never rewrites operands. `load` interns the `AtU8` names into a fresh `AtomTable` *before* decoding and passes the same table on to `build_module` (interning is idempotent).
- **Operand-encoding gotchas (oracle-verified).** A `label/1` operand is written with the **`u`** tag (an `Integer`, not an `f` `Label`); jump/failure targets (`call*`, `call_ext*`, test `fail`, `select_val` alternatives) use the `f` tag and are strict `Label`s. An `i` operand is sign-extended only in the explicit-count form (`read_tagged` `byte_count >= 2`); the 1-byte-tail form (values 16–0x7FF) is unsigned.
- **Wide integer instruction operands become synthesized literals.** A `u`/`i` operand whose magnitude does not fit a machine word is the C `TAG_o` overflow state; the decoder models it as `Operand::BigInteger`, and `build_module` appends a synthesized ETF bignum payload to the module's literal set and rewrites the operand to `Operand::Literal` — keeping `.beam`-wire concerns in `beam_loader` and needing no engine change (the engine resolves `Operand::Literal` via `Machine::literal`).
- **`Recs` field defaults are classified from the *raw* operand tag, and the record table keeps declaration order.** `records:get_definition/2` returns fields in declaration order and the file writes them that way, so neither `record::parse` nor `build_records` sorts them; records are likewise kept in file order. The *operand tag* — not the magnitude — carries the absent-vs-zero distinction: `u` (`u,0`) is the absent sentinel ⇒ `RawRecordDefault::Absent` ⇒ `RecordField.default == None`; `i` (`i,0`) is a real small-integer default of `0` ⇒ `Some(<small 0>)`. The shared decoder collapses both to `Operand::Integer`, so `chunk::record::parse` classifies defaults through the raw tag via `decode::read_tagged`. A wide `i` default stays a `BigInteger`; `build_records` appends its ETF payload to the synthesized-literal set (numbered after the file's own `LitT`) and `resolve_records` materializes it once the literal area is decoded.
- **Opcode arity is table-indexed and the decode vector is pre-sized (measurement-backed).** `decode.rs` builds a `OnceLock<[u8; 256]>` arity table derived from `Opcode::from_u8`/`arity` (the roster stays the single source of truth; a unit test pins all 256 bytes), turning the per-instruction arity scan into an array index; `decode_stream` pre-sizes its vector from `stream.len()/4`, capped so a crafted oversized `Code` chunk cannot force an unbounded reservation. Both are justified by the committed measurement in `tests/load_cost.rs` — re-measure there before optimizing further.

## Known Issues
- **A map-bearing `LitT` payload is NOT byte-preservable — do not assert a byte-exact round-trip for it.** The fixtures are compiled with `erlc +deterministic`, which writes a flat map's keys in **name-lexicographic** order (the `term_to_binary/2` `[deterministic]` option), while this crate — like ERTS's `binary_to_term/1` — **stores** a flat map's keys in `erts_cmp_flatmap_keys` order, which orders two atom keys by **atom-table index** (`erts/emulator/beam/erl_utils.h:267-272`; the normalization is inside `beam_codec`'s `MAP_EXT` decode → `beam_term::map::write_map`). The `nested/0` fixture literal therefore arrives with payload keys `bin, float, list` and is stored as `list, float, bin`, so `encode_term(decode_term(payload)) != payload` by construction. `tests/literals.rs` asserts Rust == ERTS's own `term_to_binary(binary_to_term(Payload))` for such literals instead; byte-exactness is only valid for a **map-free** literal. Faithful behaviour, not a defect — the two images denote the same term.
- **`Instr::Generic` fallback opcodes — 134 of 193 typed, 59 Generic.** 109 opcodes lower to a named `Instr` and the 25 `is_*`/`test_arity` opcodes to `Instr::Test`; the other 59 keep `Instr::Generic`. Those 59 are exactly the `-`-prefixed obsolete/transform-only entries the compiler never emits (`is_constant/2`, `make_fun2/1`, `allocate_zero/2`, the legacy `bs_*` forms, …), so the residual census over the whole installed OTP `lib` root (34 apps / ≈1366 modules) is **empty** (`tests/generic_census.rs` pins it) — a deliberate, lossless gap, never a wrong result.
- **Opcodes 192/193 are unreachable from the on-PATH OTP-29 `erlc`** (OTP-30 additions) — covered by `lower/instr.rs` unit tests only; every other variant, including the native-record family 186-191, `executable_line`/`debug_line` and `bs_test_tail2`, has a committed fixture proving reachability.
- **Files above the ~1000-line baseline:** `lower.rs` 2150, `decode.rs` 1680, `lower/instr.rs` 1288, `instr.rs` 1207. They are single-responsibility but large; split before growing them (an enum cannot be split, so `instr.rs` is the one that stays long by construction).
- **Atoms are interned into a fresh per-module `AtomTable`**, not a shared `atom.names`-seeded table; positional/global atom identity for preloaded modules is a `beam_rt` concern.
- **The oracle's only Erlang-observable rejection is the bare atom `badfile`** — from `code:load_binary/3`, `erlang:prepare_loading/2`, `code:load_abs/1` and `code:load_file/1` alike; `erts_internal:beamfile_module_md5/1` reports `undefined`. The detailed reason (`corrupt file header`, `invalid opcode`, `invalid label num 3 (0 < label < 3)`, `missing export table`, `no specific operation found`, …) exists **only** as an asynchronous legacy `error_logger` report to the caller's group leader, so no finer error class is expressible or needed here.

## Routing Table
- `lib.rs` → crate docs, module wiring, root re-exports, `prelude`; `error.rs` → loader error constructors over `BeamError` (`bad_file`, `truncated`, …).
- `load.rs` → the `load`/`load_file` orchestrator (container → chunks → decode → lower).
- `container.rs` → `FOR1` header + chunk directory walk, `ChunkId`, `Container::find`; `checksum.rs` → `module_md5` (fixed chunk order + `FunT` `OldUniq` zeroing) over `beam_common::md5::digest`.
- `opcode.rs` → `Opcode` enum + name/number/arity roster (from `genop.tab`); `operand.rs` → `Operand`/`Reg`/`TypeIndex`/`AllocKind`/`HeapNeed`; `decode.rs` → `Vec<RawInstr>` + the tagged-varint operand decoder + the derived `OnceLock` arity table.
- `instr.rs` → the typed instruction vocabulary (`Instr`, 108 variants) + `TestKind`; `ir.rs` → the IR data types (`Module`, `Function`, `Export`, `Import`, `FunDescriptor`, `RecordDefinition`/`RecordField`, `Block`, `LineTable`, `TypeTable`, …; `pub use crate::instr::*`).
- `literal.rs` → `LiteralArea`/`SharedLiteralArea` (decoded `LitT` heap, the literal-tagging call site, the arena-retry path); `decoded.rs` → `DecodedTerm`/`SharedDecodedTerm`; `attributes.rs` → `AttributeTable`/`SharedAttributeTable`.
- `lower.rs` → `build_module` + module assembly (functions, `Recs` lowering, synthesized literals, checksum); opcode→IR semantics, grouping, fusion and validation → `lower/`.
- `chunk/` → the `.beam` chunk parsers, chunk-level bounds and the `Recs` raw parser (`chunk/CONTEXT.md`).
- `lower/` → opcode → `Instr` mapping, `func_info` grouping, the `Deallocate`+`Return` fusion and post-lowering validation (`lower/CONTEXT.md`).
