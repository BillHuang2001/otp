# `beam_loader/src/lower/` — Opcode → Typed-IR Lowering

## Intent
Turns the decoded `RawInstr` stream into the typed, block-structured IR `beam_engine` consumes: opcode→`Instr` mapping, `func_info` function grouping, the one superinstruction rule, and the post-lowering validation rules.
Owns the *semantic* half of the loader; the byte/operand decode is `../decode.rs`, the IR data types are `../ir.rs` + `../instr.rs`, and module assembly is `../lower.rs` (`build_module`).
Ground truth: the `=>` transforms and opcode definitions in `../../../../erts/emulator/beam/emu/ops.tab` + `beam_load.c` + `beam_transform_helpers.c`, and `../../../../erts/emulator/beam/jit/asm_load.c` (validation asserts). Read them; never modify them.

## Pipeline (inside `build_module`)
1. `decode::decode_stream` → `Vec<RawInstr>` (`../decode.rs`); an instruction's operands are a `../raw.rs` `RawOperands` (inline up to three, spilled above that).
2. `validate::scan_operands` — ONE operand walk over the raw stream: it enforces the `z,4` static-literal bound against the file's own `LitT` count (before the synthesized bignums are appended) and counts the wide-integer operands (`OperandScan::big_integers`), so the rewrite below never re-reads an operand it does not rewrite.
3. `rewrite_wide_integers` — points every wide-integer operand at a synthesized static literal (a wide `Recs` default joins the same set through `build_records`), and copies nothing when the module has none.
4. `group::group_functions_checked` — ONE pass that produces the whole lowered module: it cuts the stream at the `func_info` boundaries (lowering only the `label`/`func_info` instructions a boundary needs), lowers each body with `lower::instr::lower_instr`, validates every instruction as it lands (`validate::validate_instr`, and `validate::DefinedLabels::define` for a label definition), applies the fuse rule (`fuse::fuses`) as each adjacent pair closes, and opens/closes the label-delimited blocks and the label → instruction-index map (`open_block`/`close_blocks`). Both of a body's allocations are sized exactly from the `ShapeAcc` that same cut-finding walk advances (`body_shape` is the whole-body reference definition of the same counts).
5. `validate::validate_module` — the only check that needs the grouped module: the declared `function_count` and each function's `func_info` arity. It walks no instructions.

`group::group_functions` (the unchecked split), `group::build_blocks` (the block/label derivation over an already-lowered body) and `validate::validate_code` (`#[cfg(test)]`-only: the standalone rule pass its own tests are written against) are the separate forms of the same results, for a caller that already holds functions it did not group.
They are implemented over the same `validate_instr`/`DefinedLabels`/`open_block` helpers as the checked route, so the two cannot drift.
A `Function`'s `labels` map and `blocks` therefore index exactly the fused vector the engine dispatches on, whichever route produced it.

## The per-body allocation rule (one exact allocation each, never a realloc)
- **`Function::code` and `Function::blocks` are allocated once, at their final length.** `group`'s cut-finding walk advances a `ShapeAcc` (the three arm hooks `label()`, `deallocate(idx)`, `ret(idx)`, plus `shape(len) -> BodyShape`) so each body's two counts — `instructions` = the fused length (the body minus its adjacent `deallocate`/`return` pairs) and `blocks` = the body's `label` count — are accumulated by the same walk that finds the `func_info` boundaries, with `ret` fusing only when its `deallocate` sits at `idx - 1`. `group::emit_fused` then fills both to `len == capacity`: it pushes the fused sequence (never the pre-fusion one) and opens one block per label as it goes.
- **`body_shape(body)` is the whole-body REFERENCE definition of those counts, not a pass in the emit loop.** It is one `windows(2)` pass over a live body, and `ShapeAcc` is the same fold expressed incrementally; only the debug asserts and the tests execute `body_shape`.
- **A body must never be sized for the post-fusion length and then filled with the pre-fusion sequence.** That overruns the capacity by exactly the fused-pair count and grows the vector to twice its final length, and a `shrink_to_fit` to repair it would put a second, transient copy of every function's instructions into the load peak — so the emit fuses as it lowers instead.
- **There is no `shrink_to_fit` on this path.** The exactness is a `debug_assert_eq!(code.len(), code.capacity())` in `group` plus `tests/real_modules.rs::slack_tables`, which asserts `len == capacity` for every function of all 1 366 installed modules — a drift is caught by the suite in any profile, and its only release-mode consequence would be slack (a memory regression), never a wrong instruction.
- **The retention, not the transient, is the boot peak.** Massif's peak snapshot (`--detailed-freq=1 --depth=12 --threshold=0.5`) carries one `Vec<Instr>` entry — the *retained* typed IR of the 99 modules a `-eval` boot loads, 304 212 instructions × `size_of::<Instr>() == 64` (18.57 MiB, 43.7 % of the boot heap). The resident set plateaus at its peak (`VmRSS` 64.68 MiB from t≈181 ms to exit on `-eval 'timer:sleep(300), halt().'`), so no load-time transient can move it.

## Rules
- **`instr.rs` is the whole semantic mapping.** Every opcode the compiler emits maps to one named `Instr`; every other opcode is preserved losslessly as `Instr::Generic { op, operands, offset }` (`offset` = the byte offset in the `Code` stream, for line/backtrace mapping). `Generic` is reached only from the single catch-all arm: every other arm either lowers to a named variant or returns a typed error on an operand-shape mismatch.
- **Two labels per function**, delimited by `func_info`: `label FuncLabel | [line] | func_info | label EntryLabel | body...`, with `Export.label` = `entry_label`.
- **`bs_create_bin`'s allocation operand accepts both encodings.** The compiler hoists a block's heap need into a preceding `bs_create_bin`, so that `z`-op operand can be a bare word count or a `z,3` allocation list; `lower_instr` decodes it through `HeapNeed` (exactly as `test_heap`/`allocate`) and takes `HeapNeed::words()` for the `u32` field.
- **A `put_record` create-form `Id` decodes to `Operand::Atom` (local) or `Operand::Literal(idx)` (foreign)** — measured, not inferred: the wire uses the `a` tag for the running module's own record and a `z,4` literal for a foreign one, whose term is the 2-tuple `{Module,Name}` (`erl_record.c:356-410` reads it with `boxed_val(id)`); `Operand` has no inline-tuple variant, so a literal index is the only representable form and `lower_instr` copies the operand verbatim — nothing narrows a `put_record` `Id` to an atom.
  Over the committed OTP-30 bootstrap corpus (`bootstrap/lib/{compiler,kernel,stdlib}/ebin`, 262 beams) the **2810** create forms split **889** `Operand::Atom` (each a record of the module's own `Recs`) + **1921** `Operand::Literal` (each a `{Owner,Name}` pair whose owner is in the corpus and whose record is `is_exported`) + **0** other shapes; an independent re-decode of the whole `Code` stream agrees instruction for instruction.
  **Trap:** `v3_core.beam` carries **583** create forms and **all 583 are local atoms** (its own `#imodule`/`#c_literal`/`#core`/… records), so an atom `Id` there is correct, not a mis-decode; the foreign form appears in `beam_ssa_opt` (110) and 40 other compiler modules.
  `Operand`'s derived `Debug` renders `Atom(Atom(4))` / `Literal(3)` (raw index, never a name), so no loader-side dump can print a `{Module,Name}` literal as an atom; the *engine*'s local-create error is the only message that names an atom.
- **Where each validation rule runs.** Grouping applies the per-instruction and per-label rules as each instruction lands: a label definition must satisfy `0 < label < label_count` and be unique across the whole module (`asm_load.c:512-529`, through `DefinedLabels` — a `Vec<bool>` over the declared label space, with a `BTreeSet` fallback above `MAX_INDEXED_LABELS = 1 << 22` and for a module with no `Code` header), every `ImportRef` must be `< Module.imports.len()` (`:532-548`), every `Line`/`ExecutableLine`/`DebugLine` `LineRef` must be `< Module.line.items.len()` (`:324-341`), and a `func_info` arity must be `<= MAX_ARG` (`:636-639`) ⇒ `SystemLimit`. `validate::validate_module` then adds the two module-wide checks: the `func_info` count must equal the header's `function_count` (`:625-629,737-743`) and each function's arity must fit `MAX_ARG`. The one *raw*-stream rule is `scan_operands`' `z,4` static-literal bound (pipeline step 2). A `label_count`/`function_count`/empty-item table of 0 (a hand-built module with no `Code` header) skips the corresponding rule.
- **The `FunT` rules live in `../lower.rs` (`build_module`), after grouping:** a `FunT` entry may neither repeat a label (`jit/asm_load.c:150-165`) nor use label 0 (`beam_file.c:429`), and its label must be one the module defines (`validate::DefinedLabelSet`, built once before the `FunT` loop and probed per entry).
- `tests/negative_ir.rs` pins each code-level rejection as an end-to-end `load()` failure beside an unmutated control, located by decoding a fixture and patching one operand in place.

## Constraints
- `beam_common::{Result, BeamError}` only; a construct the C rejects is a typed error here too, never a silently-accepted wrong value.
- `unsafe` forbidden (crate-wide).
- One responsibility per file; `lower.rs` (module assembly) is the only file here-adjacent part that runs long — keep new rules in the specific submodule.

## Design Decisions
- **Lowering is one peephole pass, not a full `ops.tab` transform.** An audit of the C transform surface (`beam_load.c` + the `=>` transforms in `emu/ops.tab`/`beam_transform_helpers.c`) concluded the current surface is **complete for correctness**: every load-time rewrite the C applies is performance-only (generic→specific selection, fusion, `select`-family sorting, key sorting, precomputed hashes, constant folding) or — for the data-dependent native-record/`Recs` resolution — reproduced at runtime by the engine. The sole genuine capability gap is the **foreign** native-record create form (a typed `unsupported` at the engine, never a wrong result).
- **`init_yregs` is preserved as its own instruction, not decomposed.** `Instr::InitYregs { registers }` keeps the file's Y list verbatim (each listed slot becomes `[]`/`NIL`); the emu `ops.tab` rewrites (`allocate`/`allocate_heap` + `init_yregs` ⇒ `i_allocate_zero`/`i_allocate_heap_zero`, else one `i_init` per Y) are performance-only and are deliberately not reproduced, so the obsolete roster opcodes `allocate_zero/2`, `allocate_heap_zero/3` and `init/1` (14/15/17) lower to `Instr::Generic`.
- **The fuse rule is stated once and applied by whichever route lowers the body.** `fuse::fuses` is that statement (an **adjacent** `Deallocate(N); Return` pair ⇒ `Instr::DeallocateReturn(N)`); `group::emit_fused` applies it while it lowers, `fuse::fuse_in_place` applies it to an already-lowered body (`fuse` is the owning-vector wrapper), so both produce the same vector. `Label` is the only branch target, so a pair can never cross a block, and everything else is carried through untouched — a hand-built module keeps its `Deallocate`/`Return`.
- **Basic blocks are label-delimited and derived from the fused vector**, so a `Function`'s `labels` map and `blocks` indexes agree with the vector the engine dispatches on.

## Known Issues
- **Looser than the C, deliberately:** an obsolete/transform-only roster opcode (`-allocate_zero/2`, `-is_constant/2`, `-make_fun2/1`; none has an `ops.tab` line) lowers to `Instr::Generic` instead of `PLEASE_RECOMPILE` (`beam_load.c:600-605`); an `f` target no `label` defines is accepted (a release-build C accepts it too) and surfaces as a typed execution error; the `bs_match` sub-instruction vocabulary is only the engine's typed `unsupported` (`beam_load.c:625-638`).
- **Stricter than the C:** a defined label 0 is refused (the C tests only `< 0 || >= label_count`, `asm_load.c:512-518`).
- **Which error a doubly-malformed stream reports:** the boundaries are located (and the boundary rules applied) before the bodies are lowered, so a stream that carries both a malformed `func_info` boundary and an unlowerable instruction names the boundary; a stream with one defect reports that defect, and every one of these is `BadArg` either way — the accept/reject verdict is unchanged. The checked route applies the per-instruction rules in stream order (as the C does while it emits code), so two independent failures in one image may be reported in the other order; both are `badfile` to Erlang.

## Notes for Agents
- Read `src/lower/instr.rs` for the per-opcode table; read `src/instr.rs` (`../instr.rs`) for the variant shapes and `../CONTEXT.md` for the vocabulary summary.

## Routing Table
- `instr.rs` → `lower_instr` (the opcode → `Instr` mapping, one arm per modelled opcode).
- `group.rs` → `group_functions`/`group_functions_checked` (the `func_info` boundary rule) + `ShapeAcc` (the incremental fused-length/block-count fold the cut-finding walk advances) + `body_shape` (the whole-body reference definition of those counts) + `emit_fused`/`push` (the lowering emit that fuses, validates and opens blocks as it goes) + `open_block`/`close_blocks` + `build_blocks` (the standalone block/label derivation).
- `fuse.rs` → `fuses` (the one statement of the `Deallocate`+`Return` rule, shared by `emit_fused` and `fuse_in_place`), `fuse_in_place` (the superinstruction rule over an already-lowered body) and `fuse`, its owning-vector wrapper.
- `validate.rs` → `scan_operands` (the raw-stream `z,4` static-literal bound + wide-integer count), `DefinedLabels` (the module-wide `Vec<bool>` label table and its fallback), `DefinedLabelSet` (the grouped-module label set `build_module` builds once and probes per `FunT` entry, with the same indexable bound and a `BTreeSet` fallback), `validate_instr` (per-instruction arity/import/line), `validate_module`/`validate_function_count`/`validate_arity`, and the `#[cfg(test)]`-only `validate_code`.
- `../../../tests/negative_ir.rs` → the code-level rejection suite that pins `validate.rs` (test node, read-only here).
