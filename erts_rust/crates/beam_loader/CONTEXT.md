# `beam_loader` — `.beam` Reader & Typed-IR Lowering Front-End

## Intent
Owns the `.beam` **container reader**, the **BEAM instruction decoder**, and the **lowering into the typed, block-structured IR** that `beam_engine` (wave-4 sibling) interprets.
Implements compatibility contract **A.2** (`.beam` binary surface, `../../CONTEXT.md` §1) and the Stage-1 loader half of Part II §E/§H (IR seam, §4 of `../CONTEXT.md`).
On the **critical path of the vertical slice** (load + run a real `.beam`), so container/instruction decode correctness is the highest priority.
Ground truth = the legacy C reader `../../erts/emulator/beam/beam_file.c` (container + operand decoding + function grouping), the operand-tag/opcode generator `../../erts/emulator/utils/beam_makeops`, the opcode roster `../../lib/compiler/src/genop.tab`, and the writer `../../lib/compiler/src/beam_asm.erl`. Read them; never modify them.

## API Surface (FROZEN — `beam_engine` designs against this)
Re-exported at the crate root and via `beam_loader::prelude::*`.
### Entry points (`src/load.rs`)
- `pub fn load(bytes: &[u8]) -> Result<Module>`; `pub fn load_file(path: impl AsRef<Path>) -> Result<Module>` (slurp + `load`). Both are the *only* entry points; all intermediate types are public for inspection/testing.
### Identifiers (`src/ir.rs`, `src/operand.rs`)
- `pub type Atom = beam_term::Atom;` — an index into the crate-owned `AtomTable` (NOT the wire index).
- `pub struct Label(pub u32);` + `pub const NO_FAIL: Label = Label(0);` (the `f,0` failure sentinel).
- `pub enum Reg { X(u32), Y(u32) }`.
- `pub struct TypeIndex(pub u32);` — index into `Module.types`; `0` = the "any type" entry.
- `pub struct ImportRef(pub u32);` — index into `Module.imports`.
- `pub type LineRef = u32;` — index into `Module.line.items` (`items[0]` = undefined location).
- `pub enum Operand { X(u32), Y(u32), Integer(i64), Atom(Atom), Nil, Label(Label), Character(u32), FloatReg(u32), Literal(u32), Typed { reg: Reg, ty: TypeIndex }, List(Vec<Operand>), Allocation(Vec<AllocKind>), BigInteger { negative: bool, magnitude: Vec<u8> } }` — a *typed* `.beam` operand.
  - `Operand::BigInteger` is **decode-time-only** (the C `TAG_o` overflow state for an `i` operand wider than a machine word); `lower::build_module` rewrites it to a synthesized `Operand::Literal` (a bignum literal), so a loaded `Module` never carries it.
  - `Operand::Literal(idx)` indexes the module's decoded `LiteralArea`, resolved through `Module::literal`.
- `pub struct AllocKind { pub kind: u32, pub number: u32, pub words: u32 }` — one decoded `z,3` entry, `words` per `marshal_allocation_list`: kind `0` (raw words) → `number`, kinds `1` (floats) / `2` (funs) / `3` (native records) → `2 × number` (`FLOAT_SIZE_OBJECT`/`ERL_FUN_SIZE`/`RECORD_INST_SIZE(0)`, all `2` on 64-bit).
- `pub enum HeapNeed { Words(u32), Alloc(Vec<AllocKind>) }` — the heap/stack-need operand of the frame instructions in *either* wire encoding, with `HeapNeed::words(&self) -> u32` (saturating word total) and `HeapNeed::from_operand(&Operand) -> Result<HeapNeed>`; the field type of `Instr::TestHeap { heap_need, live }`, `Instr::AllocateHeap { stack_need, heap_need, live }` and `Instr::Allocate { stack_need, live }`.
### The IR (`src/ir.rs` + the re-exported `src/instr.rs`)
- `pub struct Module { pub name: Atom, pub atoms: Vec<Atom>, pub atom_table: AtomTable, pub exports: Vec<Export>, pub locals: Vec<Export>, pub imports: Vec<Import>, pub functions: Vec<Function>, pub funs: Vec<FunDescriptor>, pub records: Vec<RecordDefinition>, pub code_version: CodeVersion, pub types: TypeTable, pub line: LineTable, pub literals: Arc<LiteralArea>, pub strings: Vec<u8>, pub attributes: Option<Vec<u8>>, pub attribute_table: SharedAttributeTable, pub compile_info: Option<Vec<u8>>, pub compile_info_table: SharedDecodedTerm, pub meta: Option<Vec<u8>>, pub meta_table: SharedDecodedTerm, pub checksum: [u8; 16] }`
  - Accessors: `atom_name(Atom)`, `export(Atom, u32)`, `function(Atom, u32)`, `literal(u32)`, `literals()`, `checksum()`, `fun(u32)`, `funs()`, `records()`, `record(Atom)`, `record_by_name(&str)`, `attributes_term()`/`attribute_by_name(&str)` (the decoded `Attr` list), `compile_info_term()`/`compile_info_by_name(&str)` (the decoded `CInf` list — what `module_info(compile)` serves), `meta_term()`/`meta_by_name(&str)` (the decoded `Meta` property list); all `None` when the chunk is absent/malformed, never a panic.
  - `records` is the lowered `Recs` table (native-record definitions, declaration order); `record_by_name` resolves a *runtime* atom by looking its string up in the module's `atom_table` first (the `records:get_definition/2` lookup).
  - `atoms[i]` = the atom for wire index `i`; `atoms[0]` = `Atom::MAX` (NIL placeholder). `Module` is `Clone` (cheap: `literals`/`attribute_table`/`compile_info_table`/`meta_table` are `Arc`-shared) and `Debug`, but **neither `Send` nor `Sync`** (see `src/literal.rs`) — a loaded module stays on its loading thread.
- `pub struct Export { pub function: Atom, pub arity: u32, pub label: Label }` — `label` = the function **entry label**; `Module.locals` holds one `Export` per `LocT` entry (byte-for-byte the `ExpT` layout — the JIT-only local-function table; interpretation ignores it, but the chunk is recognized and parsed rather than silently skipped).
- `pub struct Import { pub module: Atom, pub function: Atom, pub arity: u32 }`.
- `pub struct Function { pub func_label: Label, pub entry_label: Label, pub module: Atom, pub name: Atom, pub arity: u32, pub code: Vec<Instr>, pub blocks: Vec<Block>, pub labels: BTreeMap<Label, usize> }`.
  - `func_label` = the `label` **before** `func_info`; `entry_label` = the `label` **after** it (what `Export.label` points to).
  - `labels` maps every label in the function to its index in `code`; `blocks` is the label-delimited decomposition (`blocks[k]` is `code[start..end]` beginning at `blocks[k].label`).
- `pub struct Block { pub label: Label, pub start: usize, pub end: usize }`.
- `pub struct CodeVersion { pub format_number: u32, pub max_opcode: u32, pub label_count: u32, pub function_count: u32 }` (from the `Code` header; `format_number` must be `0`).
- `pub struct TypeTable { pub entries: Vec<Type>, pub fallback: bool }`, `pub struct Type { pub raw: u16, pub lower: Option<i64>, pub upper: Option<i64>, pub unit: Option<u8> }`.
- `pub struct LineTable { pub flags: u32, pub instruction_count: u32, pub items: Vec<LineEntry>, pub files: Vec<String> }`, `pub struct LineEntry { pub file: u32, pub line: u32 }`.
- `pub struct FunDescriptor { pub function: Atom, pub arity: u32, pub label: Label, pub index: u32, pub num_free: u32, pub uniq: u32 }` — one `FunT` lambda descriptor; `Module::fun(i)` selects the entry whose `make_fun3`/`call_fun2` *fun-table index* is `i` (its position in `Module::funs`).
  - `function` is the `FunT` entry's **function atom** — the atom of the function whose body `label` names (`beam_dict:lambda_table/1` resolves it through the module's local/export label tables), i.e. exactly the name `erlang:fun_info(F, name)` reports: `mk` for a named local fun (`fun mk/1`, a local non-exported function), the compiler-generated `'-anon/1-fun-0-'` for an anonymous `fun … end` (oracle-cross-checked by `tests/fun_name.rs`).
- `pub struct RecordDefinition { pub name: Atom, pub is_exported: bool, pub fields: Vec<RecordField> }` — one `Recs` **native-record** definition (`-record #name{…}`), i.e. what `records:get_definition/2` serves as `{#{is_exported => Bool}, Fields}`. `name` is the record-name atom; `fields` is in **declaration order** (the file order — never sorted).
- `pub struct RecordField { pub name: Atom, pub default: Option<Eterm> }` — `None` is the file's **absent** sentinel (`u,0`), *distinct* from a default literally `0` (`i,0` ⇒ `Some(<small 0>)`); see the `Recs` default rule under Design Decisions.
### The module checksum (`src/checksum.rs`)
- `pub fn module_md5(raw: &[RawChunk<'_>]) -> Result<[u8; 16]>` — the 16-byte MD5 the C loader stores in `beam->checksum` and `beam_lib:md5/1` reports. Digests the **raw, unpadded payloads** of the chunk directory in the *fixed* order `Atom` (obsolete Latin-1; only if present) · `AtU8` · `Code` · `StrT` · `ImpT` · `ExpT` · `FunT'` · `LitT` · `Meta` · `Recs` · `DbgB` — `Line`/`LocT`/`Attr`/`CInf`/`Type`/`Docs`/`Dbgi` excluded; an absent/empty chunk contributes nothing.
  - `FunT'` digests the 4-byte entry count then each 24-byte entry's first 20 bytes followed by 4 zero bytes (`OldUniq` forced to zero); a `FunT` that is not `4 + 24n` bytes ⇒ `BeamError::BadArg`. Duplicate ids keep the first occurrence, matching `Container::find`. Pass `Chunks::raw`.
- `pub fn md5(data: &[u8]) -> [u8; 16]` — a self-contained RFC 1321 MD5 (the crate-layer contract forbids a `beam_loader → beam_dist` edge). Pinned by the RFC 1321 §A.5 vectors + every padding boundary in `src/checksum.rs`; the module digest is cross-checked against `beam_lib:md5/1` in `tests/checksum.rs`.
- `Chunks::raw: Vec<RawChunk<'a>>` (`src/chunk/mod.rs`) retains the whole chunk directory (raw payloads, file order) so the digest — and any other byte-level consumer — sees every chunk, including ids the loader leaves unparsed (`DbgB`).
### The raw `Recs` chunk (`src/chunk/record.rs`)
- `pub fn record::parse(data: &[u8], atoms: &[String]) -> Result<Vec<RawRecord>>` — parses a `Recs` payload; `atoms` (the `AtU8` names, index 0 = NIL placeholder) recognizes the `true`/`false` export flag by name. A non-zero version currently yields an empty vector — the C instead rejects it (`BEAMFILE_READ_CORRUPT_RECORD_TABLE`), so this is an accept/reject divergence (see Known Issues); a negative count, a wrong opcode byte, a non-atom name, an odd field-list length, an unsupported operand tag or a truncated payload ⇒ `BeamError::BadArg`.
- `pub struct RawRecord { pub name: u32, pub is_exported: bool, pub fields: Vec<RawRecordField> }`, `pub struct RawRecordField { pub name: u32, pub default: RawRecordDefault }` — **wire** atom indices, not interned atoms; the lowered form is `Module.records`.
- `pub enum RawRecordDefault { Absent, Integer(i64), Atom(u32), Literal(u32), BigInteger { negative: bool, magnitude: Vec<u8> } }` — a field default in the exact form the file encodes it (`Absent` = `u,0`; `Atom(0)` = `nil`/`[]`; `Literal(i)` = a `z,4` index into the module's static `LitT`; `BigInteger.magnitude` is the BE two's-complement field). The parsed raw set is carried on `Chunks.records` (file order; empty when absent).
### The literal area (`src/literal.rs`)
- `pub struct LiteralArea` — the `LitT` literals materialized into **one immutable heap** at load time; private fields (`heap: Option<Heap>`, `terms: Vec<Eterm>`), manual `Debug` + `Default` (empty). API: `LiteralArea::empty()`, `decode(raw: &[Vec<u8>], atoms: &mut AtomTable) -> Result<LiteralArea>`, `get(&self, u32) -> Option<Eterm>`, `len`, `is_empty`, `terms(&self) -> &[Eterm]`, `heap(&self) -> Option<&beam_alloc::Heap>`.
  - Decoding goes through `beam_codec::decode_term` into a private `beam_alloc::Heap`; an exhausted decode is retried (bounded) on a larger arena, a malformed payload is a typed `BeamError`.
  - **`decode` literal-tags the decoded arena and its roots** before publishing: `beam_term::literal::tag_literal_area(heap.used_words_mut(), &mut terms)` — the safe form of the C load-time `erts_set_literal_tag` (`../../erts/emulator/beam/erl_term.c`) — so every BOXED/LIST word and every root carries `TAG_LITERAL_PTR` (an off-heap literal region the collector leaves alone).
  - Tagging happens **only at this `decode` call site**; the shared `decode_terms`/`decode_terms_at_capacity` helpers stay untagged for `attributes.rs`'s `AttributeTable`, whose terms are ordinary heap terms.
  - `pub type SharedLiteralArea = Arc<LiteralArea>;` — the type of `Module.literals`; `LiteralArea` is **not `Send`/`Sync`** (it owns a raw-pointer `Heap`), and therefore neither is a loaded `Module`.
- **Why the tagging matters (do not remove it).** An **untagged** live literal-area root makes `beam_rt`'s collector decline the collection (`context::gc::root_is_unscanned`), so a copy-bound loop whose only live root is a module literal never collects and its heap grows linearly. With tagging the loop collects (measured ≈0.33 GC/op, `heap_size` flat ≈700 words, flat peak RSS, vs a pre-fix linear `heap_size = 466 + 94·N`). See `../beam_term/CONTEXT.md` (`literal.rs` / `TAG_LITERAL_PTR`) and `../../tools/bench`.

- `pub enum Opcode` (`src/opcode.rs`) — one variant per generic opcode (the full `genop.tab` roster), with `from_u8(u8) -> Option<Opcode>`, `as_u8`, `name(self) -> &'static str`, `arity(self) -> u8`. Complete and lossless so unmodelled instructions round-trip as `Instr::Generic`.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** — no crate-local error enum. Malformed/truncated container, bad magic, bad format number, unknown opcode tag, out-of-range atom/label/register index, structurally wrong operand, unsupported `z` sub-tag ⇒ `BeamError::BadArg`; a size/arity/count bound (arity > 255, more than `ERTS_BEAM_MAX_OPARGS`, negative chunk size, atom name not UTF-8-representable, an inline operand wider than 8 magnitude bytes) ⇒ `BeamError::SystemLimit`. **Never panic, never `unwrap()` on file data, never silently accept a malformed image.**
- **`unsafe` is forbidden in this crate** (`#![deny(unsafe_code)]`) — the loader is the *safe periphery*; zero-copy is achieved safely via `beam_codec::Reader::bytes(n) -> Result<&'a [u8]>`.
- **Reuse, don't duplicate.** The big-endian byte cursor is `beam_codec::Reader` (the BE-bounds LCA) — do **not** write a second BE reader.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_codec`, `beam_alloc`, `libc`. Adding a dependency edge requires reporting to the crate-layer node (`../`).
- **Generated data is source, not output.** The operand-tag table and opcode roster come from the legacy generator/roster; the crate embeds a **regenerable** table — never hand-guess a byte value.
- **Files ~1000 lines**, one responsibility per file. `Instr` is one flat module (`src/instr.rs`) — an enum cannot be split across submodules. Licensing Apache-2.0.

## The wire format (verified against the OTP 29 / erts-17.1 oracle)
### Container (`src/container.rs`)
```
u32  "FOR1"                        // iff magic
u32  form_length                   // = file_size - 8 ; INCLUDES the 4-byte form type
u32  "BEAM"                        // iff FORM TYPE (not a chunk)
chunk entry * :  u8[4] chunk_id | u32 size | size bytes | (4 - size%4)%4 zero pad
```
`"BEAM"` is the form type, **there is no `BEAM` chunk**. The C's chunk walk is bounded by `form_length`, not by the file (`iff_init` requires `file_len >= 8 + form_length` and sets the chunk-view size to `form_length`), so **bytes past the form are ignored** and a `form_length` smaller than the file truncates the walk; this crate instead walks to the end of the buffer (see Known Issues). Unknown ids skipped; duplicate ids → first wins; order not significant. Chunk ids: `AtU8`, `Code`, `StrT`, `ImpT`, `ExpT`, `LocT` (JIT-only locals), `FunT`, `LitT`, `Attr`, `CInf`, `Line`, `Type`, `Meta`, `DbgB` (legacy emulator debug table, absent from modern modules), `Dbgi`, `Docs` (ExDoc), `Recs`, obsolete `Atom`. Each installed-corpus id is classified in `src/chunk/classify.rs` (`ChunkClass`) and enforced by `tests/chunks.rs` as parsed+exposed, parsed-as-raw, or tooling-only (with a reason); `Docs`, `DbgB`/`Dbgi` and the obsolete `Atom` are the tooling-only ids.
### Per-chunk layouts (`src/chunk/`) — see `src/chunk/<file>.rs` for each
- **`AtU8`** — `i32 count` (negative ⇒ varint lengths, real count = `-count`); then per atom a length (varint if long, else `u8`) + **UTF-8** bytes. Index 0 is reserved for NIL; index 1 is the module name; real atoms are `1..=count`. Total entries = `count+1`.
- **`Code`** — header `u32 head_size` (== 16; it counts the four header words that FOLLOW it, so the whole header is 20 bytes) then `u32 format_number` (== `BEAM_FORMAT_NUMBER` 0), `u32 max_opcode`, `u32 label_count`, `u32 function_count`; then the instruction stream. `max_opcode` must lie in `[169, 193]` — `169` = `swap/2` (`lib/compiler/src/genop.tab:611`), `193` = `MAX_GENERIC_OPCODE` (the last `genop.tab` entry, `update_record_id/7`); outside that window ⇒ `BadArg`, exactly as the C refuses an OTP-22-or-earlier or later-version image. The stream ends at `int_code_end/0` (genop 3), not at size exhaustion. Instruction = 1 opcode byte (`1..=max_opcode`) + `Opcode::arity` operands.
  The C decodes **any** opcode byte in `1..=MAX_GENERIC_OPCODE` regardless of the header's own `max_opcode` (that field is only the version gate); an in-range opcode that matches no specific operation is rejected later as `no specific operation found`.
- **`ExpT`** — `i32 count` × `{ i32 function_atom, i32 arity, i32 label }` (label = **entry** label).
- **`LocT`** — byte-for-byte the `ExpT` layout (the reader reuses the export-table parser, as the C does); the JIT-only local-function table, parsed into `Module.locals` and irrelevant to interpretation.
- **`ImpT`** — `i32 count` × `{ i32 module_atom, i32 function_atom, i32 arity }`.
- **`FunT`** (lambdas) — `i32 count` × `{ i32 function_atom, i32 arity, i32 label, i32 index, i32 num_free, i32 old_uniq }` (24-byte entries), parsed into `FunDescriptor`s on `Module.funs` (position = the `make_fun3` fun-table index); a descriptor whose `label` is not a label in the module ⇒ `BadArg`.
- **`Line`** — `u32 version` (must be 0, else the chunk is ignored), `u32 flags`, `u32 instr_count`, `u32 item_count`, `u32 name_count`; then a run of packed tagged items, then `name_count` × `{ i16 len, len bytes UTF-8 }`. `item_count` counts **only** the `TAG_i` ("line") items: the loop reads tagged items until `item_count` of them have been `TAG_i`; a `TAG_a <name_index>` sets the current file index and is consumed *in addition* (not counted); a `TAG_i <line>` emits a `LineEntry { file, line }`. `items[0]` is the undefined location `{0,0}`; `files[0]` is synthesized as `<module>.erl`. There is **no separate range-table chunk** — the runtime range table is synthesized at load from this table plus the function labels, so `Module.line` + per-function labels is the loader's complete line-info obligation.
- **`Type`** — `u32 version` (`4` current, `3` OTP 27/28; else fallback), `i32 count` (≥1, `entries[0]` = "any"), then per entry a `u16 type_word` (+ optional `i64 lower`, `i64 upper`, `u8 unit-1` gated by `type_word` bits 13-15). Absent/incompatible ⇒ a single "any" fallback entry. **Version 3** remaps each entry's bytes `b0`/`b1` into the v4-convention word: `extra_bits = (b0 << 1) & 0xE0`, `upper = b0 & 0x0F` (forced to `0x1F` when `0x0F`, so v3's all-ones `0xFFF` → the v4 "any" `0x1FFF`), `word = ((upper | extra_bits) << 8) | b1`. `Type::raw` always holds the reconstructed **v4-convention** word (`raw & 0x1FFF` = type union, `raw & 0xE000` = metadata flags).
- **`LitT`** — `u32 uncompressed_size` (`0` ⇒ records follow verbatim; non-zero ⇒ the rest of the chunk is a zlib (RFC 1950) stream inflating to exactly `uncompressed_size` bytes, which ARE the records), then `i32 count` × `{ i32 ext_size, ext_size bytes }` (Erlang external-term bytes). `src/chunk/literal.rs` handles **both** forms — the compressed form via the public `beam_codec::compress::decompress`, rejecting a length that disagrees with `uncompressed_size` — and parses the **framing** only (raw ETF payloads); `src/literal::LiteralArea` then decodes each payload into a term once at load time. Static literals are referenced by `Operand::Literal(idx)`.
- **`StrT` / `CInf` / `Attr` / `Meta` / `Docs` / `DbgB` / `Dbgi`** — `StrT` captured raw (`Module::strings`). `Attr`, `CInf` and `Meta` are each a single `term_to_binary` payload, **decoded into a term** once at load time into a private arena shared through an `Arc` (`crate::decoded::DecodedTerm`): `Attr` → the `[{Atom, Value}]` attribute list (`src/attributes.rs`) for `module_info(attributes)`; `CInf` → the compile-info list for `module_info(compile)`; `Meta` → the feature-metadata property list. Each raw payload stays on the module too (`Module::attributes`/`compile_info`/`meta`). `Docs`/`DbgB`/`Dbgi` are tooling-only ids deliberately **not** parsed: `Docs`/`Dbgi` are large and near-universal and eagerly materializing them would regress the measured module-load cost (`tests/load_cost.rs`); `DbgB` is kept only as raw bytes in `Chunks.raw`.
- **`Recs`** — `u32 version` (must be `0`; a non-zero version means "no records" — chunk-absent, *not* an error), `i32 record_count` (`≥ 0`; negative ⇒ `BadArg`), `i32 total_field_count` (informational; `≥ 0`), then `record_count` record entries EACH encoded as one BEAM instruction: an opcode byte that must be `Opcode::call_last` (5 — reused only because it has 3 operands), then operand 1 = the record-name **atom**, operand 2 = the `true`/`false` export-flag **atom**, operand 3 = a `z,1` **argument list** (`u` element count `N`, must be **even**, then `N/2` `(field-name atom, default)` pairs). Field defaults (raw tag, *not* via `decode_operand`): `u` = **no default** (the `make_catch(0)` sentinel), `i` = a signed small integer, a wide `i` = a signed **bignum**, `a` = an atom (`0` ⇒ `nil`), `z,4` = a `LitT` literal index. `src/chunk/record.rs` parses it into `Chunks.records`; the record's module is the module being loaded (the chunk carries none).
### Operand tags (`src/operand.rs` + `src/decode.rs`) — the authoritative table
Each operand = one *tag/length* byte then optional payload. Tag = `byte & 0x07` (3 bits ⇒ a file carries only tags 0–7; tags 8–14 are loader-internal and **never appear in a file**):

| byte | tag | meaning | payload |
|---|---|---|---|
| 0 | `u` | untagged integer | varint magnitude |
| 1 | `i` | integer (sign-extended) | varint magnitude; fits a small int ⇒ `Integer` |
| 2 | `a` | atom index (0 ⇒ NIL) | varint index |
| 3 | `x` | X register | varint ≤ 1023 |
| 4 | `y` | Y register | varint ≤ 1023 |
| 5 | `f` | label (0 ⇒ failure-sentinel `NO_FAIL`) | varint < label_count |
| 6 | `h` | character | (defined, never emitted by the compiler) |
| 7 | `z` | extended: sub-tag varint follows | see below |

The tag byte encodes a variable-length integer: if `byte & 0x08 == 0` the value is `byte >> 4` (0–15); else if `byte & 0x10 == 0` a 1-byte BE tail combines to 0–0x7FF; else `(byte>>5)+2` BE magnitude bytes; if `(byte>>5)==7` a `u`-tagged sub-varint gives `count = S+9` bytes.
`z` sub-tags: `1` = argument list (`u count` then `count` sub-operands → `Operand::List`); `2` = float register (`u` index → `Operand::FloatReg`); `3` = allocation list (`u count` then `count`×(`u kind`,`u number`) → `Operand::Allocation`); `4` = static literal (`u` index → `Operand::Literal`); `5` = **typed register `tr`** (a nested `x`/`y` sub-operand then a `u` **type index** → `Operand::Typed`); `0` (obsolete float) and any other ⇒ `BadArg`.
**`tr` packing:** the file carries `reg | (type_index << 10)` conceptually, but the loader keeps reg and `TypeIndex` **separate** in `Operand::Typed`. If the `Type` table is a fallback (absent/stripped) the tag collapses to a plain `X`/`Y` operand (the type index is discarded).
### Structural bounds enforced at decode (`src/decode.rs` / `src/lower.rs`)
Mirrors the C reader's `LoadAssert`s — a construct the C rejects is a typed error here too, never a silently-accepted wrong value: a non-zero `f` label index `< label_count` (recursively inside a `z,1` list); `x`/`y` register index `< MAX_REG` (1024, `erl_vm.h:49`) and `z,2` float-register index `< MAX_REG`; `z,5` `tr` type index `< TypeTable.entries.len()` when the table is not a fallback; `z,3` allocation list `<= 4` entries, per-entry `number <= i32::MAX/3` and running word total `<= i32::MAX` ⇒ `SystemLimit`; a `z,1` argument list only in the instruction's final operand slot; a `z,4` static-literal index `< the file's own LitT count`, checked in `build_module` *before* synthesized literals are appended (covers `load`, `beam_rt`'s code-server path and `beam_engine`'s test support); a `z,4`/`h` magnitude that would truncate on the 32-bit `Operand` field ⇒ `SystemLimit` (never a silently-wrapped, different-but-valid index).

## Design Decisions
- **The opcode roster is embedded from `genop.tab`.** `Opcode` enumerates every generic opcode in `../../lib/compiler/src/genop.tab` (the checked-in, wire-frozen roster the compiler emits; `format_number` bumps when it changes). `opcode.rs` holds the name/number/arity table, derived verbatim via `^<n>: <name>/<arity>` with all entries kept so the mapping is bijective. **Regeneration:** re-read `genop.tab`; the numbers are the file's first field.
- **BIF operands are `ImpT` indices, NOT `bif.tab` numbers.** The `gc_bif*` BIF operand is a plain `u` = the index of `{module,function,arity}` in `ImpT`; the IR stores `ImportRef` and the engine resolves `Module.imports[bif]`. **CROSS-CRATE CONTRACT (binding on the `beam_bifs` architect):** the engine/BIF layer keys BIFs by `(module, function, arity)` following real `bif.tab` naming — the loader does **not** know and must **not** encode `bif.tab` numbering. `Module.imports` is the single source of BIF identity.
- **`Instr` and `TestKind` live in `src/instr.rs`, re-exported from `ir.rs`.** The vocabulary is one large flat enum (an enum cannot be spread across submodules); `ir.rs` does `pub use crate::instr::*;`, so `crate::ir::Instr`, `crate::Instr` and `prelude::*` are unchanged.
- **`HeapNeed` preserves both need encodings.** `allocate`/`allocate_heap`/`test_heap` accept their word need as either a plain count or a `z,3` allocation list; `HeapNeed::words()` recovers the total for the heap-overflow check while `HeapNeed::Alloc` preserves the per-kind breakdown a JIT or precise allocator may want.
- **The literal area is write-once, so it is shared behind an `Arc`.** `LitT` literals are decoded once into one private `beam_alloc::Heap` and never mutated, so a `Module` clone is cheap; heap exhaustion while decoding is retried (bounded) on a larger arena. The `Send`/`Sync` consequence follows from the raw-pointer heap (see the API Surface note on `LiteralArea`).
- **The checksum is computed inside `build_module`, from a retained raw chunk directory.** `chunk::parse` keeps the directory on `Chunks::raw` (`RawChunk` is `Copy`), and `build_module` calls `checksum::module_md5(&chunks.raw)` and stores it on `Module::checksum` — no signature change, so the public `load` and every manual sibling pipeline (`beam_rt`/`beam_engine`) get the digest for free. It is stored as `[u8; 16]` rather than re-derived per query. (The in-tree MD5 is structural debt — see Known Issues.)
- **`beam_alloc` is the literal-materialization dependency.** `src/literal.rs` decodes through `beam_codec::decode_term` into a `beam_alloc::Heap` (the in-workspace `beam_loader → beam_alloc` edge, no cycle); `beam_term::heap::Heap` remains a test arena only.
- **Two function labels per function**, delimited by `func_info` instructions: `label FuncLabel | [line] | func_info | label EntryLabel | body...`, with `Export.label` = `entry_label` (see the API Surface).
- **Atoms are interned in file order into a crate-owned `AtomTable`.** `Module.atoms[i]` maps the wire index to the interning `Atom`; `atoms[0]` = `Atom::MAX` (NIL). Interning into a *shared, `atom.names`-seeded* table (needed for preloaded/positional atoms) is `beam_rt`'s job. **Shared-table seam — no dedicated entry point exists:** `load`/`load_file` always build a *private* per-module table. To share, drive the pipeline manually: `container::parse` → `chunk::parse` → intern `chunks.atoms[1..]` (wire order) through the shared table into a `Vec<Atom>` → `decode::decode_stream(stream, &atoms, &code_version, &types)` → `lower::build_module(&chunks, &raw, table)`. **`build_module` takes the `AtomTable` by value and moves it into `Module.atom_table`**, so pass a *clone* of the shared table to keep the same numbering; every atom index in the IR then indexes the shared table.
- **`z,5` `tr` is normalized to `reg` + `TypeIndex`**, so the interpreter may ignore the annotation and a JIT may consume it later; the `Type` chunk is parsed into `TypeTable` (with the fallback table).
- **`lower_instr` is the whole semantic mapping**: `src/lower/instr.rs` maps every opcode the compiler emits to one named `Instr` variant; every other opcode is preserved losslessly as `Instr::Generic { op, operands, offset }` (`offset` = byte offset in the `Code` stream).
- **Basic blocks are label-delimited.** `src/lower/group.rs` owns `group_functions` (the `func_info` boundary rule) and `build_blocks`; `src/lower.rs` owns `build_module` + module assembly. CFG construction is the engine's concern (see the `Function` fields in the API Surface).
- **The instruction decoder takes the atom map and the type table.** `decode_stream(stream, atoms, version, types)` and `decode_operand(r, atoms, types)` (loader-internal — *not* part of the frozen `ir`/`prelude`/`load` surface) resolve an `a` operand to the interned `Atom` at decode time and collapse a `z,5` `tr` via `types.fallback`, so `RawInstr` operands already hold interned atoms and `lower` never rewrites operands. `load` interns the `AtU8` names into a fresh `AtomTable` *before* decoding and passes the same table on to `build_module` (interning is idempotent).
- **Operand-encoding gotchas (oracle-verified).** A `label/1` operand is written with the **`u`** tag (an `Integer`, not an `f` `Label`); jump/failure targets (`call*`, `call_ext*`, test `fail`, `select_val` alternatives) use the `f` tag and are strict `Label`s. An `i` operand is sign-extended only in the explicit-count form (`read_tagged` `byte_count >= 2`); the 1-byte-tail form (values 16–0x7FF) is unsigned.
- **Wide integer instruction operands become synthesized literals.** A `u`/`i` operand whose magnitude does not fit a machine word is the C `TAG_o` overflow state; the decoder models it as `Operand::BigInteger`, and `lower::build_module` appends a synthesized ETF bignum payload to the module's literal set and rewrites the operand to `Operand::Literal` — keeping `.beam`-wire concerns in `beam_loader` and needing no engine change (the engine resolves `Operand::Literal` via `Machine::literal`).
- **`Recs` field defaults are classified from the *raw* operand tag, and the record table keeps declaration order.** (1) `records:get_definition/2` returns fields in **declaration order** and the file writes them that way, so neither `record::parse` nor `lower::build_records` sorts them; records are likewise kept in file order. (2) The *operand tag* — not the magnitude — carries the absent-vs-zero distinction: `u` (`u,0`) is the absent sentinel `make_catch(0)` ⇒ `RawRecordDefault::Absent` ⇒ `RecordField.default == None`; `i` (`i,0`) is a real small-integer default of `0` ⇒ `Some(<small 0>)`. The shared decoder collapses both to `Operand::Integer`, so `record::parse` classifies defaults through the raw tag via `decode::read_tagged` (`u` ⇒ absent; `i` ⇒ small integer or signed bignum; `a` ⇒ atom; `z,4` ⇒ static-`LitT` index). A wide `i` default stays a `BigInteger`; `build_records` appends its ETF payload to the synthesized-literal set (numbered after the file's own `LitT`) and `resolve_records` materializes it once the literal area is decoded.
- **The `bs_create_bin` allocation operand accepts both encodings.** The compiler hoists a block's heap need into a preceding `bs_create_bin`, so that `z`-op operand can be a bare word count or a `z,3` allocation list; `lower_instr` decodes it through `HeapNeed` (exactly as `test_heap`/`allocate`), taking `HeapNeed::words()` for the `u32` field.
- **Opcode arity is table-indexed and the decode vector is pre-sized (measurement-backed).** `src/decode.rs` builds a `OnceLock<[u8; 256]>` arity table derived from `Opcode::from_u8`/`arity` (the roster stays the single source of truth; a unit test pins all 256 bytes), turning the per-instruction arity scan into an array index; `decode_stream` pre-sizes its vector from `stream.len()/4`, capped so a crafted oversized `Code` chunk cannot force an unbounded reservation. Both are justified by the committed measurement in `tests/load_cost.rs` — re-measure there (and see `src/lower/group.rs`/`src/ir.rs`) before optimizing further.

## Known Issues / Intentional M1 gaps
- **A map-bearing `LitT` payload is NOT byte-preservable — do not assert a byte-exact round-trip for it.** The committed literals fixtures are compiled with `erlc +deterministic`, which writes a flat map's keys in **name-lexicographic** order (the `term_to_binary/2` `[deterministic]` option), while this crate — like ERTS's `binary_to_term/1` — **stores** a flat map's keys in `erts_cmp_flatmap_keys` order, which orders two atom keys by **atom-table index** (`erts/emulator/beam/erl_utils.h:267-272`; the normalization happens inside `beam_codec`'s `MAP_EXT` decode → `beam_term::map::write_map`). The `nested/0` fixture literal therefore arrives with payload keys `bin, float, list` and is stored as `list, float, bin`, so `encode_term(decode_term(payload)) != payload` by construction. `tests/literals.rs` asserts Rust == ERTS's own `term_to_binary(binary_to_term(Payload))` for such literals instead (`tests/literals.rs` + `tests/common/mod.rs` for the raw byte scan); a byte-exact assertion is only valid for a **map-free** literal. (Faithful behavior, not a defect: the two images denote the same term.)
- **`Instr::Generic` fallback opcodes — 134 of 193 typed, 59 Generic.** 109 opcodes lower to a named `Instr` and the 25 `is_*`/`test_arity` opcodes to `Instr::Test`; the other 59 keep `Instr::Generic`. Those 59 are exactly the `-`-prefixed obsolete/transform-only entries the compiler never emits (`is_constant/2`, `make_fun2/1`, `allocate_zero/2`, the legacy `bs_*` forms, …), so the residual census over the whole installed OTP `lib` root (34 apps / ≈1366 modules) is **empty** (`tests/generic_census.rs` pins it) — a deliberate, lossless gap, never a wrong result. `Generic` is reached only from the single catch-all in `src/lower/instr.rs`: every other arm either lowers to a named variant or returns a typed error on an operand-shape mismatch.
- **Previously-unexercised variants are fixture-proven reachable.** The on-PATH OTP-29 `erlc` DOES emit the native-record family (`nr_def`/`nr_use` lower 186-191 typed); `executable_line` (183) / `debug_line` (184) are reachable via `+line_coverage` / `+beam_debug_info` and `bs_test_tail2` (121) via `+no_ssa_opt`, each with a committed fixture and a typed-lowering test. Opcodes 192/193 stay unreachable (OTP-30 additions this `erlc` cannot emit) — covered by `src/lower/instr.rs` unit tests only. None falls back to `Generic`. Their *execution* is oracle-checked at the `../tools/differential` gate (`records.rs` `nr_native`, run under both runtimes through `beam_rt`); `beam_engine`'s suite covers them structurally only, and only `put_record/6`'s **foreign** create form is a typed `unsupported` there — the **local** form is built by the engine from the running module's own `Recs`.
- **Lowering is one peephole pass, not a full `ops.tab` transform.** `lower_instr` maps one decoded opcode to exactly one `Instr`; the only rewrite is `src/lower/fuse.rs`, which coalesces an **adjacent** `Deallocate(N); Return` pair into `Instr::DeallocateReturn(N)`, run *before* `build_blocks` (so a block's `start..end` indexes the same fused vector the engine dispatches on). `Label` is the only branch target, so the pair can never cross a block; everything else is copied through verbatim, so `Deallocate`/`Return` stay live for hand-built modules. An audit of the C transform surface (`beam_load.c` + the `=>` transforms in `emu/ops.tab`/`beam_transform_helpers.c`) concluded it is **complete for correctness**: every load-time rewrite the C applies is performance-only (generic→specific selection, fusion, `select`-family sorting, key sorting, precomputed hashes, constant folding) or — for the data-dependent native-record/`Recs` resolution — reproduced at runtime by the engine. The sole genuine capability gap is the **foreign** native-record create form (a typed `unsupported`, never a wrong result).
- **Mandatory chunks: only `AtU8` + `Code`.** `ImpT`/`ExpT` are optional here (`src/chunk/mod.rs`), yielding an empty table where the C refuses the image as `missing import/export table`.
- **`form_length` is not the chunk-walk bound.** The walk runs to EOF, so an image whose `form_length` is smaller than the file loads here where the C truncates the walk and rejects it, and bytes trailing the form are rejected here where the C ignores them.
- **Chunk-table checks the C reader performs and this crate does not** (accept/reject-only; the C's `BEAMFILE_READ_*` classes are logger text, so `BeamError::BadArg` is the matching observable and `SystemLimit` the crate's convention for arity/count bounds):
  (a) `ExpT`/`LocT`/`ImpT`/`FunT` **arity** is never bounded by `MAX_ARG` (255, `beam_file.c:335,373`); `src/lower.rs:85-157` copies it verbatim, so `module_info(exports)` can report an absurd arity;
  (b) an `ExpT` **label** is unvalidated (the C requires `label >= 0`, `beam_file.c:374`; a negative `i32` becomes a huge `u32` here);
  (c) **`Type`** entries get no semantic validation (`beam_types.c:44-82` rejects `flags == BEAM_TYPE_NONE`, a lower/upper bound without `INTEGER|FLOAT`, a unit without `BITSTRING`; `beam_file.c:690-691` requires `entries[0] == BEAM_TYPE_ANY`), and `count < 1` yields the *fallback* table where the C errors;
  (d) a **`Line`** item with a negative line number (`i,-1`) is accepted as line `4294967295` (the C asserts `val.word_value >= 0`, `beam_file.c:522`);
  (e) **atom names are never length-capped** (`atom.c:283-335`: > `MAX_ATOM_CHARACTERS` 255, > `MAX_ATOM_SZ_LIMIT` 1020 bytes or a full table ⇒ `corrupt atom table`);
  (f) **`DbgB` is never parsed**, so a corrupt version-1 body the C rejects (`beam_file.c:887-1057`) loads here (the payload is kept as raw bytes for the checksum only).
- **IR-level checks the C's `asm_load` performs and this crate does not** (typed error later, never a wrong result): duplicate `label` definitions (`jit/asm_load.c:512-529`; `lower/group.rs:151-156` silently keeps the last index); a `func_info` count that disagrees with the header's `function_count` (`asm_load.c:625-629,737-743`); a `func_info` arity above 255 (`:636-639`); an `e`/`b` import index past `ImpT` (`:532-548`; `beam_engine` resolves via `Module::imports.get` ⇒ typed execution error); the line/`debug_line` item indices (`:328-341,719-724`; the engine's `nearest_line` uses `.get()` ⇒ no location); the `bs_match` sub-instruction vocabulary (`beam_load.c:625-638`, backstopped only by the engine's typed `unsupported`).
- **Two deliberate leniencies.** An obsolete/transform-only roster opcode (`-allocate_zero/2`, `-is_constant/2`, `-make_fun2/1`; none has an `ops.tab` line) is `PLEASE_RECOMPILE` in the C (`beam_load.c:600-605`) but lowers here to `Instr::Generic`; a `FunT` entry may repeat a label (`asm_load.c:150-165`) where this loader requires only that each label exist (`lower.rs:145-148` — itself stricter than the C's `label > 0 && label < label_count`, `beam_file.c:429`).
- **Cases where this crate is STRICTER than the oracle** (accept/reject-only): `LocT` is always parsed (the C parses it only under `erts_jit_asm_dump`, `beam_file.c:1684`); `Attr`/`CInf`/`Meta` are decoded eagerly at load (the C defers to query time), so a malformed payload fails the load; a compressed `LitT` whose declared `uncompressed_size` exceeds the inflated length is rejected (the C inflates into a buffer of that size and uses zlib's actual returned length — only a too-*small* declaration fails, as `Z_BUF_ERROR`); a `Recs` `total_field_count` < 0 is rejected (informational, stored unchecked in the C). A `Recs` `version != 0` is **not** an error on either side (`beam_file.c:1333-1341` returns success with no records).
- **The oracle's only Erlang-observable rejection is the bare atom `badfile`** — from `code:load_binary/3`, `erlang:prepare_loading/2`, `code:load_abs/1` and `code:load_file/1` alike; `erts_internal:beamfile_module_md5/1` reports `undefined`. The detailed reason (`corrupt file header`, `invalid opcode`, `invalid label num 3 (0 < label < 3)`, `missing export table`, `no specific operation found`, …) exists **only** as an asynchronous legacy `error_logger` report to the caller's group leader, so no finer error class is expressible or needed. `beam_lib` is a chunk reader, not a loader: it accepts bad `format_number`/`max_opcode`/opcodes and returns `{error,beam_lib,{not_a_beam_file,_}}`/`{missing_chunk,_,Id}`/`{chunk_too_big,_}`/`{invalid_chunk,_,Id}` for container damage (and *raises* on a shortened `AtU8`); `code:get_object_code/1` returns raw bytes unvalidated.
- **The raw `DbgB` bytes are retained only transiently.** `Chunks::raw` carries them (for the module checksum) but they are dropped once `build_module` assembles the `Module`, so nothing downstream can reach the payload: `code:get_debug_info/1` parity (an A.8/introspection concern) would need it exposed on `Module` — a documented future gap.
- **Atoms are interned into a fresh per-module `AtomTable`**, not a shared `atom.names`-seeded table; positional/global atom identity for preloaded modules is a `beam_rt` concern.
- **The in-tree MD5 is structural debt.** `src/checksum.rs` carries a self-contained RFC 1321 MD5 because the layering contract forbids a `beam_loader → beam_dist` edge and no new external crate is allowed. `beam_dist` (`auth::md5`) and `beam_rt` (`context::bridges::module_md5`) ship the same primitive, so it belongs at a lowest-common-ancestor crate (`beam_common`), shared instead of triplicated — de-duplicating it is repo-root-owned; do **not** add a fourth copy.
