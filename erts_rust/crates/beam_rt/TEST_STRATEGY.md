The file doc records the verdict: on this default-scale live set the mark-region space copies **0.535×** the words (201 540 vs 376 610) and **0.527×** the objects at **4.467×** the mature occupancy (7 808 vs 1 748 words), **1.48×** the fullsweeps (289 vs 195) and **1.002×** the reported process memory (176 288 vs 175 864, the line cost landing in the **used** half: 92 624 vs 34 944 = 2.65×), over a cadence **0.949×** apart (558 vs 588 collections) at a **0.996×** allocation product (1 843 074 vs 1 851 024 young words, 0.43 % apart), so **Copying stays the right default**. Timings are never asserted.

## The in-process `compile:file/2` throughput harness (`examples/compile_bench.rs`)
**Command:** `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml --release -p beam_rt --example compile_bench -- [--source <path>]... [--repeat <n>] [--oracle]` — release profile, in the **foreground**: the default corpus's largest source alone is ~1 min.
It compiles each source **in process** through the production route (`Runtime::eval`'s `Mod:Func(Args)` dispatch into the real `compiler` application, whose blocking `receive`s the nested pump resumes — no `erlc` subprocess anywhere on the measured path) on a runtime booted the way the CLI boots one for an action (`-noshell` config + this release's own `bootstrap/bin/start.boot`), with the fixed option list `[no_spawn_compiler_process, deterministic, no_docs, {outdir, Dir}]`.
The default corpus is `lib/stdlib/src/ordsets.erl` (13 585 B), `lib/stdlib/src/maps.erl` (37 745 B), `lib/stdlib/src/string.erl` (103 287 B) and `lib/compiler/src/v3_core.erl` (193 385 B); `--source` replaces it (repeatable, order kept), `--repeat` takes the fastest of N fresh-runtime runs (a timing can only be perturbed upwards) and `--oracle` runs the system `erl` on the identical option list for the side-by-side columns.
Per source it prints the wall milliseconds around the one compile (the boot is timed separately and never inside it), the source throughput in `KB/s`, `erlang:statistics(garbage_collection)` as `{collections, words_reclaimed, 0}` **delta'd across the compile**, `erlang:memory(processes_used)`/`(binary)`/`(total)` in bytes and the written `.beam`'s size; the closing tables add three ratios against the smallest source (`size x`, `time x`, `time/byte x`) plus a `shape:` line, so a super-linear compile reads off at a glance (`time/byte x` flat at ≈1.00 = linear; growing with `size x` = quadratic).
**Reference run** — this host (`nproc` 16, 1-min `/proc/loadavg` 3.7–6.2 across the run), release profile, one sample per source, `--oracle` on:

| source | bytes | wall ms | KB/s | `gc={colls,words,0}` | `memory(total)` | oracle in-VM ms | rust/oracle in-VM |
|---|---|---|---|---|---|---|---|
| `ordsets.erl` | 13 585 | 512.9 | 26.5 | `{61,255668,0}` | 10 970 383 | 72.0 | 7.12x |
| `maps.erl` | 37 745 | 2 533.3 | 14.9 | `{111,761798,0}` | 11 054 960 | 117.0 | 21.65x |
| `string.erl` | 103 287 | 20 655.9 | 5.0 | `{352,1546190,0}` | 11 301 228 | 598.0 | 34.54x |
| `v3_core.erl` | 193 385 | 56 239.1 | 3.4 | `{473,2191171,0}` | 11 285 920 | 1 165.0 | 48.27x |

**The host is shared**, so an absolute wall time moves by ±100 % between runs; only the **ratios** (`size x`, `time x`, `time/byte x`), the `rust/oracle in-VM` ratio and the deterministic counters (`gc colls`, `gc words`, the artifact's byte count) are signal.
That reference run's shape: `v3_core.erl` is `14.24x` the smallest source and `109.66x` its wall time, i.e. **`time/byte x` grew `7.70x`** — clearly super-linear, and the number a future pass is judged by.
Dated snapshots of that table belong in [`PERF_HISTORY.md`](PERF_HISTORY.md); [`PERF.md`](PERF.md) holds the present-tree figures.
**`BEAM_RT_PERF_COUNTERS=1`** prints, on stderr at the end of a run, the census that explains a row's cost rather than describing it: the dispatch memo's hits/misses/cold/collisions and its 24 hottest `(module, function, arity)` keys (`src/context/calls/perf_counters.rs`), the machine pool's acquires/hits/fresh builds/evictions/distinct callees/peak rows (`src/context/machine_pool.rs`) and the root-walk calls/visits figures.
The harness **never asserts a duration** and is not a test: it exits 0 whatever the wall times (a slow compile is a result), 1 only when a compile itself fails (a `BeamError`, including the route's own 900 s `BLOCKING_PUMP_DEADLINE` on a source that cannot finish, or an answer other than `{ok, Module}`), a named source is unreadable, or `--oracle` was asked for with no `erl` on `$PATH` — and 2 on a malformed invocation.

## Running the suites and the gates
**Crate gate:** `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --no-fail-fast` (the count and the wall time move as tests are added — re-run it rather than quoting a figure).
A bare `cargo` from the repo root cannot resolve the workspace manifest (`erts_rust/Cargo.toml`) and the sandbox `$HOME` is read-only, hence the `scripts/cargo.sh` wrapper.
The `#[ignore]`d tests are measurement/corpus harnesses, never assertions that need a green run: `context::calls::tests::eval_route_pool_costs`, `context::gc_walk::tests::the_seeding_cost_of_an_in_process_compile` and the A.9 corpus sweeps — [`M1_GAPS.md`](M1_GAPS.md) / [`HANDOFF.md`](HANDOFF.md) *A.9 E0* — the one exception being the two **two-VM** suites (`dist_two_vm.rs`'s 2 tests, `dist_payload_matrix.rs`'s 9 legs), whose rows *are* assertions and are `#[ignore]`d only for cost (each spawns two VMs plus a private `epmd`), so they must be run explicitly with `-- --ignored`.
**The differential GATE is authoritative and is re-run, never quoted from memory:** `erts_rust/tools/differential/gate.sh` runs the corpus under both runtimes and reports the live per-contract split (the only recorded capability gap is `wire/new_fun_ext_encode`, A.5); the corpus and its allowlist live in the read-only sibling [`../tools/differential/`](../../tools/differential/).
**Gate-equivalent full-corpus sweep without `gate.sh`'s per-case boot:** `differential run <case-id> --out-file <dir>/<name>.json` per case in parallel (16-way ≈ 4 min for the 3122 cases), then `differential merge --from <dir> --allowlist ../tools/differential/known-gaps.txt`, which prints the same suite-shaped `summary:`/`ratchet:` lines and returns `suite --strict`'s own `0`/`1` exit code (`merge` re-runs nothing, so the per-case verdicts are the ones `run` folded in).
Two pitfalls: build `--bins` first so `target/debug/dist_probe` exists (otherwise each worker runs its own on-demand cargo build), and pass case ids as **argv** rather than inline `xargs -I` substitution — dozens of `re/*` ids carry `(`, `[`, `{`, `\`, `*`, so a substituted command line is a shell syntax error (`xargs -0 -n1 -P16 bash -c 'run_one "$1"' _`).
**The A.9 corpus sweep (`tests/selfhost_breadth.rs`, `#[ignore]`d and shard-resumable)** is the breadth harness: `BEAM_RT_BREADTH_APPS=a,b` / `_SHARD=i/n` / `_LIMIT` select the corpus, `_SCHEDULED=1` drives the spawned-compiler route, `_PA=a:b:c` puts one `-pa` group **before** `-noshell` (**absolute** dirs only — a relative dir silently runs the *system* compiler instead), `_COMPARE=artifact` requires only that an artifact was produced (the tree's OTP-30 compiler stamps `opcode_max` 183, so whole-file byte identity against an OTP-29 oracle is unsatisfiable by construction; `bytes` stays the default) while still reporting the byte relation, `_MAX_BYTES=<n>` pre-filters by source size (applied before shard/limit) and `_DEADLINE_S=<n>` bounds each child (default 900 s).
Shard every sweep into calls that fit the tool budget — a killed call leaves nothing — and check each shard's summary line before trusting its counts; run **2–3 concurrent `beam_rt` processes at most** (an 8-way run grows to ~15 GB RSS and is cgroup-OOM-killed). The census and the failure modes it found are [`CONTEXT.md`](CONTEXT.md) *A.9* / *Known Issues*.
**Oracle/test-harness contract (cross-cutting).** Every probe discovers `erl`/`erlc` by **filesystem only, never by running the tool** (`tests/support/mod.rs`, `PROBE_TIMEOUT = 30 s`), and a missing toolchain is always a **loud skip**, never a silent pass or a panic.
A bare `erl -noshell` never exits, so every oracle probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
**What a comparison is:** trimmed **stdout string** equality, exit codes, error atoms, `term_to_binary`/`.beam` **bytes** and key **order**.
**No test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle** — the GC suites read the runtime's **own** `Runtime::gc_stats()`.

## Test hygiene
**Scratch temp dirs come from one place**: `crate::context::test_support::scratch_dir(label)` — unique per call (label + pid + an atomic sequence + a per-process nonce) and self-removing on drop; a hand-rolled `temp_dir().join(format!("…_{pid}"))` collides with a concurrent test *process*.
**Oracle-order caveat:** `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure list's order is not stable (measured 117 × `c_m,b_m,a_m` vs 3 × `b_m,c_m,a_m` in 120 probes) — assert failure pairs as a **set**, never an ordered `vec!`.
`tests/fixtures/` is never handed to the oracle as a single `-pa`: each suite compiles what it needs into its own scratch directory and passes that instead.
