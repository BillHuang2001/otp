# `beam_rt` — Design Decisions

Companion to [`CONTEXT.md`](CONTEXT.md).
It holds the current-state design rationale and the binding invariants of the runtime glue, split out so
`CONTEXT.md` stays under the Context Tree per-file read limit.
It is documentation of the present state, not a change log.

## Design Decisions
* **A process's mature-GC strategy comes from its spawn `HeapPolicy` through `beam_gc`'s automatic rule.** The root process and every `spawn_process` child get `Runtime::default_spawn_policy()` (a clone of `self.config.heap.policy()`), from whose `initial_mature_words` the rule picks the copying space vs the mark-region (GenImmix) space (`IMMIX_BREAK_EVEN_WORDS = 2048`; the default 233 keeps copying). The runtime **cannot** pin a strategy: `ProcessTable::spawn` takes only a `HeapPolicy`, so no `GcConfig`/`MatureSelection` reaches the process path and the policy's mature size is the only lever. `HeapOptions` (`src/config.rs`) exposes it additively — `set_initial_mature_words`/`with_initial_mature_words`, `set_fullsweep_after`/`with_fullsweep_after` (host/test knobs; the emulator has **no** `+h`-style flag and `ERL_FULLSWEEP_AFTER` stays parsed-but-inert), and `GcStrategy` (`EmulatorDefault`/`Immix`) with `set_gc_strategy`/`with_gc_strategy` — the **default-OFF** host opt-in `BEAM_RT_GC_STRATEGY=immix` (`config::strategy_from_value` the pure parser; `strategy_env_default` reads the var **once** via `OnceLock`, exactly like `BEAM_RT_TIER`; `Runtime::new` applies it once to the owned `HeapOptions` **before** storing the config, so the root process, the native file service and every child inherit it). It is deliberately **not** an init argument and adds **no** CLI flag, and `RuntimeConfig::new`/`default` stay env-free. Immix is reached through the **automatic rule** (`MatureSource::Automatic`, no override) from the raised mature size — the honest equivalent of a pin. A test reads a live process's collector only through `Runtime::processes()` (`Process::collector() -> &AnyCollector`), as `tests/gc_strategy.rs` does.
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every loaded module is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use a separate `info_heap`, `reset()` per call. For a *scheduled* slice `ensure_heap_full` is the **collection point** — the full-root door `Machine::ensure_heap`/`test_heap` reaches, with its narrow twin `ensure_heap` behaving identically — both armed by `BudgetContext`; elsewhere it is a no-op on the unbounded arena. What *does* exhaust is the bounded BIF/eval heaps and, for a collected process, its young heap.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are preserved verbatim in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry; `main.rs` is a thin shim over `cli::run(argv)`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* (`#![deny(unsafe_code)]`), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid (`process_result`), copies it onto the pointer-stable `eval_heap` (never reset), and returns `Exit(normal)`. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The transport copy resolves the executing machine's and the received message's off-heap payloads into a runtime-owned table.** The return value and a raise's reason are copied with `Runtime::stabilize_term_with`/`try_stabilize_escaped_with`, which take the owning `SourcePayloads` (the refc-binary, MSO and node handles a term may reference) and clone its refc-binary and MSO handles into the copy's **source** `OffHeapTable` (refcount++), so an engine-built refc binary (`bs_init_writable` accumulator, any `bs_create_bin` past `ERL_ONHEAP_BINARY_LIMIT`) survives the trip out (`base64:encode(<<>>)` → `<<>>`). The MSO handles are pushed **in order**, so each lands on the same slot its container names. A **received** payload is a second source — the message envelope (`Message::binaries`/`off_heap`/`nodes`) — so `Runtime::source_payloads` unions the machine's `Machine::refc_binaries()` handles with the off-heap family the receiver's scan kept across the message drop (`MailboxState::retained_binaries`/`retained_off_heap`/`retained_nodes`). The node list is carried but **not** pushed into the source table (the copier registers a fresh `NodeEntry` per external thing and never reads a source node list, and `OffHeapTable::Drop` calls `release_all`, so pushing the retained handles would zero the shared count). The copy's **destination** table (`Runtime::eval_off_heap`, only ever grown, never reset) owns those refs, so it must outlive `eval_heap` and the copied terms. The empty-source `stabilize_term`/`try_stabilize_escaped` forms serve the runtime-level stores that have no handles in reach: a payload such a copy cannot resolve is **flattened** into a fresh on-heap bitstring, byte-faithfully and with nothing registered in the destination table, so the escape-store capability-gap valve no longer trips for it (it remains for an unresolvable MSO container or a malformed graph). A payload handle is **never** reconstructed from a raw `BinRef.val` data pointer — flattening reads the payload *bytes*, never mints a handle.
* **The host seams: nine bridges + three hooks** (enumerated in [`src/context/CONTEXT.md`](src/context/CONTEXT.md)). A bridge needing no runtime borrow is a cheap `Rc`/`RefCell` handle; the borrowing ones are made mutually exclusive by their `uses_*` predicates. `NodeIdentity` (a `Copy` atom) rides alongside every arm; `FunIdentityBridge`/`RuntimeMemory` are owned snapshots installed **only** on their consumer BIFs' arms.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw`).
* **Timers are a runtime-local deadline min-heap, not `beam_process::TimerService`.** That service runs on **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (owning `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas), so `src/timers.rs` is a min-heap the **scheduler loop** drains: monotonic deadlines, earlier first, `O(1)` cancellation via a lazy tombstone, sleep-to-earliest only when idle.
* **The persistent-term store keeps raw `Eterm` words but compares structurally.** The store (`src/context/persistent_term.rs`) pins the raw words of this node-global table and compares a key — and the `put_new/2` value — with `beam_term::compare::eq` (the C's exact `EQ`, `erl_bif_persistent.c:1015/726`). Raw storage is safe because every write to a runtime-level store goes through `Runtime::try_stabilize_escaped` (a copy onto the never-moved arena), which reports a **genuine** copy failure as `BeamError::SystemLimit` and trips `disable_gc` **only** for the off-heap-payload capability gap.
* **Oversized messages go through the heap-fragment model, driven by `beam_message`.** `RuntimeContext::send_fragmented_message` gets the receiver's heap + mailbox from `Process::heap_and_mailbox_mut()` and calls `beam_message::send_fragmented(from, message, heap, mailbox, &mut ctx, 0)`, then records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments`. The fallback is reached only when the receiver's own heap genuinely refuses the payload (a bounded `HeapPolicy` makes `Process::deliver`'s growth fail; an unbounded receiver absorbs it into its grown nursery). **`Fragments::move_into` is never called** — retention is the honest M1 behaviour. **A queued message survives a receiver collection intact:** `Process::run_rooted_collection` (`../../beam_process/src/process.rs:1166-1240`, the shared body of `collect`/`ensure_capacity`) roots each queued message's `[payload, from, token]` and re-installs all three (`set_from`/`set_token`/`with_payload`), and `with_payload` swaps only the payload, so the off-heap handles, refc binaries, node entries and the `Fragments` chain all travel the rebuild (a fragment-resident payload is `Foreign` to the collector, so it is left untouched).
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`. `allocated_areas`' 19 items derive from live state wherever a counterpart exists (`export_table`/`fun_table` from the modules' `ExpT`/`FunT` counts, `module_refs`/`loaded_code`/`atom_table`/`register_table`/`process_table`/`port_table`/`ets_misc` from the runtime's tables, `dist_table`/`node_table` from `Runtime::dist_node()`); only the counterpart-less items (`sys_misc`/`static`/`export_list`/`fun_list`/`bif_timer`/`external_alloc`) stay a documented `0`.
* **The exit observer only *records*; a scheduler pass drains.** A `ProcessExitObserver` can run while a runtime `RefCell` (the shared ETS/port registry) is already borrowed, so `EtsExitObserver` (`runtime/ets_owner.rs`) touches nothing but its own `OwnerIndex` cell: it pushes the dead pid and the drained `PortWatch` pairs and returns. `Runtime::{drain_ets_owner_exits, drain_port_monitor_exits}` discharge the obligations at a pass boundary with `try_borrow_mut`, **deferring** (never dropping, never panicking) on a live borrow.
* **The cross-module call seam is deepened, never broadened.** `resolve_external_call` stays behaviour-preserving everywhere it does not suspend, so the `Ok(None)` predicate grew (NIF modules, self-observing modules, an on-demand load, an unknown export) rather than the `Some` set. Suspending changes control flow, so a wrong `Some` is a correctness bug where a wrong `None` costs only a slower path.
* **The fun-image half of the `resolve_external_call` guard stays module-wide because the in-machine scheduled route is unsound for the whole module.** `compile.beam` imports `erlang:term_to_binary/1,2`, so the module-wide guard keeps every `compile:*` function on the synchronous `call_bif` → `run_export_blocking` route (a `RuntimeContext` whose `pump_once` refuses to pump) — the typed `blocked()` gap, never a wrong result. Per-function narrowing (`term_to_binary/1,2`/`external_size/1,2` guarded only in the importing function, `load_nif/2` still module-wide) would admit `compile:*` to a **scheduled**, non-`relocation_exempt` in-machine run, where a collection at the running machine's **own** heap-admission point relocates the heap against an incomplete root set: the machine's `x`/stack/FR are published into `beam_process::Registers` only at the admission points (`ensure_heap_full`, `alloc_words_rooted`) and the runner's park arm, **never** around `ExecutionContext::call_bif`, and a term the in-flight call chain holds outside them — outside every published root **and** outside the process's own root-reachable scanned graph, so not reachable by the two-phase valve — is not relocated. The corruption is a relocating-collection race (its word varies with timing; suppressing the collection with a large nursery, `+hms 4194304`, passes), reproducible on both tiers. The four collection doors are the slice machine's `ensure_heap`/`ensure_heap_full`/`alloc_words_rooted` and the runner's park arm, and every nested run is a different `RuntimeContext` whose latch is never armed **and** which is `relocation_exempt` for the whole application — so a `FunCaller` cannot fix it by pushing a BIF's locals into `Registers::extra_roots` (no collection runs in that window).
* **GC collects only at the two heap-admission points and the rooted allocation seam, behind a per-call latch.** The root set is the *executing machine's* whole `RootSet` (every x register, the whole stack and FR file), but a `RuntimeContext` is shared by nested runs (an external module call builds a new `Machine` on the same context), so a collection from a nested admission point would write the nested roots into the process's root set and dangle the outer machine's terms. Only the slice's own `BudgetContext` arms the latch, taken (`std::mem::take`) in each door (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`); every nested path is a plain `RuntimeContext` whose latch is never set. Beyond the rooted hand-off, a module with a float-family instruction is **never** collected over (the float guard) and an unresolvable call site (a fun entry, the `-eval` evaluator) is skipped — conservative, never wrong. A collection is also **declined** (`Ok(())`) whenever the machine's root set, **or the process's own root-reachable scanned graph**, reaches a container in an unscanned region — the pooled BIF heap (`Runtime::bif_heaps`), the arena, the `-eval` heap, a message fragment — so an unscanned root is never left pointing at relocated young words. The valve is **two-phase** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word and always runs; phase 2 descends the process's scanned young/mature graph (and the process's own root containers — registers, mailbox, dict, saved arguments, pending signals) and runs only when the process's per-pid descent latch is open. The latch (`GcState::foreign`, `Runtime::foreign_reachable`/`note_foreign_reachable`) is sticky and add-only, opened by every event that can put an unscanned container into the process's reachable graph — an engine arena fallback, a BIF/native-floor/NIF result built outside the process heap, a heap-fragment delivery, a spawn argument or entry fun not on the new process's own heap, the escape store — and pruned at the pass boundary for a gone process.
* **A process whose live terms the runtime cannot fully root is marked *relocation-exempt* while it runs them.** `RuntimeContext::with_relocation_exempt` (`src/context/mod.rs`) saves the process's mark, sets it, runs a closure and restores the previous mark on every path (nested-safe). While exempt, `Process::deliver` returns the copier's raw `Alloc(AllocKind::Message)` refusal instead of collecting, which `RuntimeContext::{deliver_message, deliver_in_table}` route to the heap-fragment fallback — so the message still arrives with no heap word moved under a term the root set cannot publish. The wrapped scopes are exactly those runtime locals: the `-eval` driver (`crate::eval::eval`, whose `Runtime::pump_scheduler` receive pump runs inside the scope), `run_export_blocking`/`run_label_blocking` (the fresh `Machine`'s `x`/stack) and `apply_fun` (the `-eval`-closure environment). The scheduled slice is deliberately **not** wrapped — the runner drives it with the `*_outcome_with_tier` entries, publishes a parked machine's roots (`publish_parked_roots`), and its `BudgetContext` arms the legitimate collection site.
* **The delivery seam consults the same unscanned-root valve as the admission doors.** `RuntimeContext::deliver_message_with_off_heap_inner` (`src/context/mod.rs`) calls `delivery_collection_is_unsound(receiver)` before handing the message to `ProcessTable::deliver`: `false` only for a process with no unpublished roots, otherwise the O(1) sticky `Runtime::foreign_reachable` latch (fast path) or the O(roots) `gc_walk::process_roots_are_unscanned` walk, whose hit is recorded through `note_foreign_reachable`. On `true` the delivery runs with the **receiver** marked relocation-exempt (`with_pid_relocation_exempt`; the older `with_relocation_exempt` delegates with `self.mailbox_pid`), so `Process::deliver` returns its raw refusal and the ordinary heap-fragment fallback delivers the message — no heap word moves under a container the collector cannot scan, and the shared body lives in `deliver_into_mailbox`. The scratch fields the walk borrows are moved out and back (`Runtime::take_walk_scratch`/`put_walk_scratch`) to keep the borrows disjoint.
* **A failed collection halts that process's collection, never the program.** `halt_process_gc` keeps the (unmoved) heap and allocation keeps falling back to the arena; `disable_gc` (the escape-store valve) freezes **every** process heap when a runtime-level store cannot be copied onto the arena.
* **The `receive` scan position is host state, per process, and survives a suspend/resume.** `beam_engine` keeps no mailbox state; the nine `beam_engine::Mailbox` methods (`src/context/mod.rs`) resolve the queue from the `Process` and the scan state from `Runtime::mailboxes: HashMap<ProcessId, MailboxState>` (`src/mailbox.rs`; `RuntimeContext::mailbox_parts`), so a `receive` parked as `RunOutcome::Wait` resumes at the `wait` target (its `loop_rec`) through `Machine::resume_outcome_with_tier` (`src/runner/run.rs`) with the cursor **intact** — the scan does not restart, so a matching message is never re-examined or skipped. `remove_message`/`timeout` reset the cursor to the first message exactly as the C `erts_msgq_unlink_msg_set_save_first`/`erts_msgq_set_save_first` (`../../erts/emulator/beam/erl_proc_sig_queue.h:2329-2381`). The key is the whole `ProcessId` incl. its bumped slot serial (`beam_process/ptab.rs`), so a reused slot never inherits a dead process's cursor. The only mailbox edit that can move a *parked* receiver's scan is a delivery (append at the tail, never invalidating the cursor); removal paths (`receive_remove`, the `-eval` `remove_mailbox_message`, `beam_process::demonitor_flush`) all act on the **running** process's own mailbox. **Latent caveat (reachability unproven):** `MailboxState.markers[].position` is a queue *index* captured at `reserve`, whereas the C keeps a recv marker as a queue *node*, so a removal at a lower index could leave the recorded index off by one — worth a differential case if the compiler's marker prologue is ever exercised.
