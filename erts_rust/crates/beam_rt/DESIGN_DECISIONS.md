# `beam_rt` — Design Decisions

Companion to [`CONTEXT.md`](CONTEXT.md).
It holds the current-state design rationale and the binding invariants of the runtime glue, split out so
`CONTEXT.md` stays under the Context Tree per-file read limit.
It is documentation of the present state, not a change log.

## Design Decisions
* **A process's mature-GC strategy comes from its spawn `HeapPolicy` through `beam_gc`'s automatic rule.** The root process and every `spawn_process` child get `Runtime::default_spawn_policy()` (a clone of `self.config.heap.policy()`), from whose `initial_mature_words` the rule picks the copying space vs the mark-region (GenImmix) space (`IMMIX_BREAK_EVEN_WORDS = 2048`; the default 233 keeps copying). The runtime **cannot** pin a strategy: `ProcessTable::spawn` takes only a `HeapPolicy`, so no `GcConfig`/`MatureSelection` reaches the process path and the policy's mature size is the only lever. `HeapOptions` (`src/config.rs`) exposes it additively — `set_initial_mature_words`/`with_initial_mature_words`, `set_fullsweep_after`/`with_fullsweep_after` (host/test knobs; the emulator has **no** `+h`-style flag and `ERL_FULLSWEEP_AFTER` stays parsed-but-inert), and `GcStrategy` (`EmulatorDefault`/`Immix`) with `set_gc_strategy`/`with_gc_strategy` — the **default-OFF** host opt-in `BEAM_RT_GC_STRATEGY=immix` (`config::strategy_from_value` the pure parser; `strategy_env_default` reads the var **once** via `OnceLock`, exactly like `BEAM_RT_TIER`; `Runtime::new` applies it once to the owned `HeapOptions` **before** storing the config, so the root process, the native file service and every child inherit it). It is deliberately **not** an init argument and adds **no** CLI flag, and `RuntimeConfig::new`/`default` stay env-free. Immix is reached through the **automatic rule** (`MatureSource::Automatic`, no override) from the raised mature size — the honest equivalent of a pin. A test reads a live process's collector only through `Runtime::processes()` (`Process::collector() -> &AnyCollector`), as `tests/gc_strategy.rs` does.
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every loaded module is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use a separate `info_heap`, `reset()` per call. For a *scheduled* slice `ensure_heap_full` is the **collection point** — the full-root door `Machine::ensure_heap`/`test_heap` reaches, with its narrow twin `ensure_heap` behaving identically — both armed by `BudgetContext`; elsewhere it is a no-op on the unbounded arena. What *does* exhaust is the bounded BIF/eval heaps and, for a collected process, its young heap.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are preserved verbatim in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry; `main.rs` is a thin shim over `cli::run(argv)`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* (`#![deny(unsafe_code)]`), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid (`process_result`), copies it onto the pointer-stable `eval_heap` (never reset), and returns `Exit(normal)`. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The transport copy resolves the executing machine's and the received message's off-heap payloads into a runtime-owned table.** The return value and a raise's reason are copied with `Runtime::stabilize_term_with`/`try_stabilize_escaped_with`, which take the owning `SourcePayloads` (the refc-binary, MSO and node handles a term may reference) and clone its refc-binary and MSO handles into the copy's **source** `OffHeapTable` (refcount++), so an engine-built refc binary (`bs_init_writable` accumulator, any `bs_create_bin` past `ERL_ONHEAP_BINARY_LIMIT`) survives the trip out (`base64:encode(<<>>)` → `<<>>`). The MSO handles are pushed **in order**, so each lands on the same slot its container names. A **received** payload is a second source — the message envelope (`Message::binaries`/`off_heap`/`nodes`) — so `Runtime::source_payloads` unions the machine's `Machine::refc_binaries()` handles with the off-heap family the receiver's scan kept across the message drop (`MailboxState::retained_binaries`/`retained_off_heap`/`retained_nodes`). The node list is carried but **not** pushed into the source table (the copier registers a fresh `NodeEntry` per external thing and never reads a source node list, and `OffHeapTable::Drop` calls `release_all`, so pushing the retained handles would zero the shared count). The copy's **destination** table (`Runtime::eval_off_heap`, only ever grown, never reset) owns those refs, so it must outlive `eval_heap` and the copied terms. The empty-source `stabilize_term`/`try_stabilize_escaped` forms serve the runtime-level stores that have no handles in reach: a payload such a copy cannot resolve is **flattened** into a fresh on-heap bitstring, byte-faithfully and with nothing registered in the destination table, so the escape-store capability-gap valve no longer trips for it (it remains for an unresolvable MSO container or a malformed graph). A payload handle is **never** reconstructed from a raw `BinRef.val` data pointer — flattening reads the payload *bytes*, never mints a handle.
* **The host seams: nine bridges + three hooks** (enumerated in [`src/context/CONTEXT.md`](src/context/CONTEXT.md)). A bridge needing no runtime borrow is a cheap `Rc`/`RefCell` handle; the borrowing ones are made mutually exclusive by their `uses_*` predicates. `NodeIdentity` (a `Copy` atom) rides alongside every arm; `FunIdentityBridge`/`RuntimeMemory` are owned snapshots installed **only** on their consumer BIFs' arms.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw`).
* **Timers are a runtime-local deadline min-heap, not `beam_process::TimerService`.** That service runs on **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (owning `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas), so `src/timers.rs` is a min-heap the **scheduler loop** drains: monotonic deadlines, earlier first, `O(1)` cancellation via a lazy tombstone, sleep-to-earliest only when idle.
* **The persistent-term store keeps raw `Eterm` words but compares structurally.** The store (`src/context/persistent_term.rs`) pins the raw words of this node-global table and compares a key — and the `put_new/2` value — with `beam_term::compare::eq` (the C's exact `EQ`, `erl_bif_persistent.c:1015/726`). Raw storage is safe because every write to a runtime-level store goes through `Runtime::try_stabilize_escaped` (a copy onto the never-moved arena), which reports a **genuine** copy failure as `BeamError::SystemLimit` and trips `disable_gc` **only** for the off-heap-payload capability gap.
* **Oversized messages go through the heap-fragment model, driven by `beam_message`.** `RuntimeContext::send_fragmented_message` gets the receiver's heap + mailbox from `Process::heap_and_mailbox_mut()` and calls `beam_message::send_fragmented(from, message, heap, mailbox, &mut ctx, 0)`, then records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments`. The fallback is reached only when the receiver's own heap genuinely refuses the payload (a bounded `HeapPolicy` makes `Process::deliver`'s growth fail; an unbounded receiver absorbs it into its grown nursery). **`Fragments::move_into` is never called** — retention is the honest M1 behaviour. **A queued message survives a receiver collection intact:** `Process::run_rooted_collection` (`../../beam_process/src/process.rs:1166-1240`, the shared body of `collect`/`ensure_capacity`) roots each queued message's `[payload, from, token]` and re-installs all three (`set_from`/`set_token`/`with_payload`), and `with_payload` swaps only the payload, so the off-heap handles, refc binaries, node entries and the `Fragments` chain all travel the rebuild (a fragment-resident payload is `Foreign` to the collector, so it is left untouched).
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`. `allocated_areas`' 19 items derive from live state wherever a counterpart exists (`export_table`/`fun_table` from the modules' `ExpT`/`FunT` counts, `module_refs`/`loaded_code`/`atom_table`/`register_table`/`process_table`/`port_table`/`ets_misc` from the runtime's tables, `dist_table`/`node_table` from `Runtime::dist_node()`); only the counterpart-less items (`sys_misc`/`static`/`export_list`/`fun_list`/`bif_timer`/`external_alloc`) stay a documented `0`.
* **The exit observer only *records*; a scheduler pass drains.** A `ProcessExitObserver` can run while a runtime `RefCell` (the shared ETS/port registry) is already borrowed, so `EtsExitObserver` (`runtime/ets_owner.rs`) touches nothing but its own `OwnerIndex` cell: it pushes the dead pid and the drained `PortWatch` pairs and returns. `Runtime::{drain_ets_owner_exits, drain_port_monitor_exits}` discharge the obligations at a pass boundary with `try_borrow_mut`, **deferring** (never dropping, never panicking) on a live borrow.
* **The cross-module call seam is deepened, never broadened.** `resolve_external_call` stays behaviour-preserving everywhere it does not suspend, so the `Ok(None)` predicate grew (NIF modules, self-observing modules, an on-demand load, an unknown export) rather than the `Some` set. Suspending changes control flow, so a wrong `Some` is a correctness bug where a wrong `None` costs only a slower path.
* **The fun-image half of the `resolve_external_call` guard narrows to the *function* that issues the fun-image call; `erlang:load_nif/2` stays module-wide.** `call_site_reading_imports` (`src/context/mod.rs`) classifies a module by its own imports (`CallSiteReadingImports::{LoadNif, FunImage, None}`): a module importing `erlang:load_nif/2` answers every call (that BIF's result depends on the call *instruction's* module, so no narrower scope is sound), a module importing `erlang:term_to_binary/1,2`/`erlang:external_size/1,2` guards only a function whose own body carries such an `ImportRef` (`function_calls_a_fun_image_bif`), and a module with no such import is never guarded. That admits every `compile:*` function whose own body issues no fun-image BIF to an in-machine run, where its blocking `receive` suspends through the ordinary `RunOutcome::Wait` path.
Both A.9 `selfhost/*` corpus cases agree with the oracle on both execution tiers.
The invariant behind them is the registered-BIF copy-out stated below: a BIF's container result is never left on the recyclable pooled BIF heap while running Erlang code can store it in a heap object.
The park-window relocation exemption and the host `CollectionGate` stand as their own decisions below: a collection that would relocate a process whose live roots the runtime does not fully hold is declined, never attempted.
* **GC collects only at the heap-admission doors, the rooted allocation seam and the reduction/yield-boundary door, behind a per-call latch.** The root set is the *executing machine's* whole `RootSet` (every x register, the whole stack and the FR file — whole from the in-slice heap-admission doors, only the live `fr_mark()` prefix from the park arm), but a `RuntimeContext` is shared by nested runs (an external module call builds a new `Machine` on the same context), so a collection from a nested admission point would write the nested roots into the process's root set and dangle the outer machine's terms. Only the slice's own `BudgetContext` arms the latch, taken (`std::mem::take`) in each of the three engine doors (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`); every nested path is a plain `RuntimeContext` whose latch is never set. The boundary door (`context/gc/reds_door.rs`) needs no arming latch: the runner reaches it only from its `Yield` arm, for a slice whose roots it has just published. Beyond the rooted hand-off, a module with a float-family instruction is **never** collected over (the float guard) and an unresolvable call site (a fun entry, the `-eval` evaluator) is skipped — conservative, never wrong. A collection is also **declined** (`Ok(())`) whenever the machine's root set, **or the process's own root-reachable scanned graph**, reaches a container in an unscanned region — the pooled BIF heap (`Runtime::bif_heaps`), the arena, the `-eval` heap, a message fragment — **that forwards a word the collector would follow or update**, so an unscanned root is never left pointing at relocated young words. The valve is **two-phase** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word and always runs; phase 2 descends the process's scanned young/mature graph (and the process's own root containers — registers, mailbox, dict, saved arguments, pending signals) and runs only when the process's per-pid descent latch is open. The latch (`GcState::foreign`, `Runtime::foreign_reachable`/`note_foreign_reachable`) is a hint, never a decision: opened by every event that can put an unscanned container into the process's reachable graph — an engine arena fallback, a BIF/native-floor/NIF result built outside the process heap, a heap-fragment delivery, a spawn argument or entry fun not on the new process's own heap, the escape store — pruned at the pass boundary for a gone process, and **closed** by `Runtime::close_foreign_reachable` when a door that published the machine's whole `RootSet` (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`) gets a `ValveVerdict::foreign_free` descent.
* **A registered BIF's container result is copied off its pooled heap and that heap is then rewound — a copy-out-then-rewind invariant over two destinations, gated three ways.** A container built on the pooled `Runtime::bif_heaps` (a `Target::Foreign` region the process's collector does not scan) is a root the unscanned-root valve declines over while it is live, so a churn loop that keeps such a result alive would grow peak memory with its iteration count. `RuntimeContext::call_registered` (`src/context/calls.rs`) therefore **moves** the result off the pool — onto the process's own young heap (`Process::heap_mut()`) when a process is running, onto the `-eval` store when one is not (the destination rule below) — and rewinds the pool with `Heap::reset_to(mark)` at the offset it read before the call, so the result is kept alive by the root set the engine already publishes (it lands in `x(0)` on return) and is relocated by a later collection, while the pool serves the next call from `mark`. Three parts of that are load-bearing rather than incidental. **(1) A naive `Heap::reset` is unsound.** The pool is shared: the native floor's reference minting (`src/native.rs`, `src/native/process.rs`), trace (`src/trace.rs`) and the ETS-owner sweep (`src/runtime/ets_owner.rs`) pop the same heaps and push them back **without** resetting them (the heap a reference or a spawned pid was just built on still holds that live term); any of the six escaping `DispatchHooks` arms the BIF ran may have stored a heap word into state that outlives the call (the process dictionary, the process/port registry, a NIF library's private data, a delivered message, the persistent-term store, the timer heap / reference space / link set); a raise may carry a live reason term (`beam_common::Raise::live_reason`) pointing into the heap; and a **reentrant** fun-applying call can have pushed an argument that lives on the very same heap into any of those seams. A rewind in any of those cases would recycle words another owner still holds and hand a later caller the *same* address for a *different* term. So the rewind targets the call's own start offset `mark` — `reset_to(mark)` frees exactly this call's words `[mark..used)` and keeps the words below it that another owner still holds — and it is applied only to a call the six escaping seams and reentrancy cannot have run on (the *safe arm*) **and** with an **`Ok`** result. **(2) The copy's source `OffHeapTable` is empty, deliberately.** With no payload owner, `beam_message`'s copier cannot share a refc binary's off-heap `RefcBinary` handle — `copy_refc_binary` resolves the payload through `ctx.src_off_heap().binary_by_data_ptr(val)` — so it **flattens** the binary's `[start,end)` window into a fresh, self-contained on-heap bitstring and registers nothing in the destination table: byte-faithful, no `[BinRef][ErlSubBits]` payload owner needed, no refcount lost. An off-heap **MSO** reference with no owner is the copier's typed `bad_term` instead, so the move answers `None` and the caller leaves both the result and the pool exactly as they were — a capability gap, never a dangling payload. **(3) A full nursery is met by `Process::grow_nursery`, not by a collection.** The copy runs inside a BIF call, where the machine's live x registers and Erlang stack are **not** published, so `Process::ensure_capacity`'s collect-first path would free live terms; `grow_nursery` retires the space it replaces and moves nothing, so it is the legal growth seam for a host holding an unpublished root set, followed by **one** retry over a fresh `CopyContext` (a refused first attempt takes `copy_struct`'s preflight path, which writes no destination word, so nothing needs unwinding). The **immediate** hot path is kept free by the container test: an immediate is neither boxed nor a cons and a literal lives in the frozen literal area, so such a result rewinds with **no** copy at all (`result_is_foreign_container`). A **NIF** result is not copied out (a deliberate M1 residual): it stays on the pooled heap and keeps declining a collection while it is live. **The second destination is the table-less route's `-eval` store.** With no scheduled process to move the result onto (`RuntimeContext::new`: the `-eval` evaluator and every single-pass `run_*` entry) `rehome_container_result` (`src/context/calls.rs`) picks `src/context/pool.rs::move_result_into_runtime_store`, which lands the copy on `Runtime::eval_heap` plus the **existing** escaped-payload table `Runtime::eval_off_heap` — the very store `Runtime::stabilize_term` already uses for that route's own terms, never a second one. It is the only sound destination there: it is pointer-stable and never moves (a region too small for the graph is **replaced** by `Runtime::grow_eval_heap` and every retired region stays alive), so the copy can sit in the evaluator's environment and be read back later in the same expression; it takes a complete graph copy, so the pool below `mark` is genuinely free to serve the next call; and the copy's off-heap handles are **adopted** into `Runtime::eval_off_heap`, with a refc binary flattened exactly as in (2) because the source table is empty here too.
* **A process whose live terms the runtime cannot fully root is marked *relocation-exempt* while it runs them.** `RuntimeContext::with_relocation_exempt` (`src/context/mod.rs`) saves the process's mark, sets it, runs a closure and restores the previous mark on every path (nested-safe). While exempt, `Process::deliver` returns the copier's raw `Alloc(AllocKind::Message)` refusal instead of collecting, which `RuntimeContext::{deliver_message, deliver_in_table}` route to the heap-fragment fallback — so the message still arrives with no heap word moved under a term the root set cannot publish. The wrapped scopes are exactly those runtime locals: the `-eval` driver (`crate::eval::eval`, whose `Runtime::pump_scheduler` receive pump runs inside the scope), `run_export_blocking`/`run_label_blocking` (the fresh `Machine`'s `x`/stack) and `apply_fun` (the `-eval`-closure environment). The scheduled slice's **running** window is deliberately not wrapped — the runner drives it with the `*_outcome_with_tier` entries and its `BudgetContext` arms the legitimate collection site — but its **parked** window is: the Wait park arm marks the pid relocation-exempt and the resume clears the mark, so a delivery or a `beam_process` signal cannot move that process's heap against the `regs` snapshot it published while parked, and the delivery takes the heap-fragment fallback instead. `publish_parked_roots` remains what the *pre-empted* window (`Yield`, never marked exempt) relies on and what the resume re-syncs the machine from.
* **The delivery seam consults the same unscanned-root valve as the admission doors.** `RuntimeContext::deliver_message_with_off_heap_inner` (`src/context/mod.rs`) calls `delivery_collection_is_unsound(receiver)` before handing the message to `ProcessTable::deliver`: `false` only for a process with no unpublished roots, otherwise the O(1) `Runtime::foreign_reachable` latch (fast path) or the O(roots) `gc_walk::process_roots_are_unscanned` walk, whose hit is recorded through `note_foreign_reachable`. On `true` the delivery runs with the **receiver** marked relocation-exempt (`with_pid_relocation_exempt`; the older `with_relocation_exempt` delegates with `self.mailbox_pid`), so `Process::deliver` returns its raw refusal and the ordinary heap-fragment fallback delivers the message — no heap word moves under a container the collector cannot scan, and the shared body lives in `deliver_into_mailbox`. The scratch fields the walk borrows are moved out and back (`Runtime::take_walk_scratch`/`put_walk_scratch`) to keep the borrows disjoint.
* **The signal sites' collection decision is the host's `CollectionGate`, with the same roots-incompleteness predicate as the admission-point valve.** `beam_process` exposes `CollectionGate` — an additive trait `{ fn declines_relocation(&mut self, receiver: &Process) -> bool; }` — as the host's half of the exhaustion policy, installed on the process table (`ProcessTable::set_collection_gate`) so it travels with the table into every scheduler pass; every `ptab.rs` signal site (`grow_receiver_for_signal`, `build_signal_message`, `copy_reason_onto`, `deliver_head_signal`, `enqueue_exit_signal`/`enqueue_down_signal`) OR-s it with the crate-owned `has_unpublished_roots` before a *collecting* `ensure_capacity`, so a receiver whose gathered roots reach a container in an unscanned region takes the no-relocation `Process::grow_nursery` / heap-fragment route instead. `beam_rt` implements it as `RuntimeCollectionGate` (`src/context/gc_walk.rs`, installed by `Runtime::new`) over the existing `root_is_unscanned` / `any_root_is_unscanned` incompleteness check — the same decision the admission-point valve makes — but it **owns its own `WalkScratch`**, never the runtime's admission-point scratch (`GcState::walk`): a signal site runs from a different borrow than an admission point and may even run while a machine is mid-collection, so aliasing the two would be a borrow violation. It is built over the runtime's **one** per-pid latch cell (`ForeignLatch`, `Rc<RefCell<HashSet<ProcessId, crate::hasher::FastBuildHasher>>>`): a **clear** bit answers `false` with **no** descent (the same one-way rule the admission-point doors and the delivery seam apply) and only an **open** bit descends — **correct** (the bit is opened by every event that can put an unscanned container into the receiver's reachable graph; the depth-≥2 foreign container is exactly what the cheap per-word phase misses) and **conservative** (declining a relocation only routes the notification to the byte-faithful heap-fragment fallback, never loses it). The runner's park-window `relocation_exempt` (`src/runner/run.rs`) is **deliberately kept beside the gate**: the gate declines only when an unscanned container is reachable from the receiver's *gathered* roots, whereas the exemption also covers a live term the host holds *outside* that published set (`ProcessEngine::args`, `ProcessEntry::Fun::fun`, `LocalFunTarget::args`, any live `Eterm` in host Rust state), which the walk cannot see. Pinned by `context::tests::the_installed_gate_declines_a_signal_driven_relocation_of_a_foreign_reachable_receiver` and `runner::tests::a_parked_process_stays_relocation_exempt_for_its_parked_window`.
* **A failed collection halts that process's collection, never the program.** `halt_process_gc` keeps the (unmoved) heap and allocation keeps falling back to the arena; `disable_gc` (the escape-store valve) freezes **every** process heap when a runtime-level store cannot be copied onto the arena.
* **A collection is declined only by a foreign container that forwards a *scanned* word.** A collector owes a container exactly two things — *follow* its children and *update* them on relocation — so a term that forwards nothing a relocation acts on imposes neither, and declining a collection because one is reachable is unnecessary work with an unbounded cost. `context/gc.rs::root_is_unscanned` therefore declines only when `word_region` answers `WordRegion::Foreign` **and** `forwards_scanned_word` finds a child for which `word_is_scanned` holds — the forwarding test driving `beam_term::layout::for_each_child_slot` (the same enumeration the copier and the walk use) and never a hand-rolled shape list, so a boxed shape added later is classified by construction and `ErlSubBits` stays in the declining set through its forwarded `orig` word, while a leaf, an all-immediate block, a tuple of immediates, a reference, a pid, a port, a float, a bitstring, an empty tuple and a null-or-unaligned word (`dereferenceable_pointer` rejects those before anything reads them) latch nothing. Two consequences are load-bearing. First, `make_ref/0`'s frozen all-immediates M1 block must not pin a loop's valve: were it a hazard, the first call would open the latch, `Process::collection_debt` would never settle, and the allocation doors' grow-the-nursery-and-retry path would grow the young-chain without bound (≈170 bytes per iteration on a two-process ping-pong, i.e. `memory(processes)` scaling linearly with the loop count). Second, a container the runtime owns in a region it cannot relocate and holds live across a loop only declines when it really forwards a scanned word, so such a loop keeps collecting, and a registered BIF's container result is not even a candidate any more: the copy-out re-homes it onto the process's scanned young heap. The latch the per-word phase feeds is **cleared**, not sticky: `Runtime::close_foreign_reachable` retires the pid's bit on the `ValveVerdict::foreign_free` descent of a door that handed the walk the machine's **whole** `RootSet` (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`), while the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` may only open it. Pinned by `context/gc/refs_plateau.rs::a_process_that_mints_a_reference_per_iteration_keeps_a_bounded_heap` (a reference-minting loop against a reference-free control at N and 2N), `gc.rs`'s `tests::a_foreign_leaf_is_not_unscanned_but_a_container_forwarding_a_young_word_is` and `only_a_foreign_container_forwarding_a_scanned_word_opens_the_descent_latch`, and the end-to-end `tests/foreign_root_loop.rs::a_loop_holding_the_statistics_result_keeps_collecting` + `the_fill_law_holds_and_its_phase_is_the_entry_frame` (a loop holding the re-homed `erlang:statistics/1` tuple live: the collector relocates it, and 17 words per iteration fill a 233-word nursery space once per 13 iterations).
* **The `receive` scan position is host state, per process, and survives a suspend/resume.** `beam_engine` keeps no mailbox state; the nine `beam_engine::Mailbox` methods (`src/context/mod.rs`) resolve the queue from the `Process` and the scan state from `Runtime::mailboxes: HashMap<ProcessId, MailboxState>` (`src/mailbox.rs`; `RuntimeContext::mailbox_parts`), so a `receive` parked as `RunOutcome::Wait` resumes at the `wait` target (its `loop_rec`) through `Machine::resume_outcome_with_tier` (`src/runner/run.rs`) with the cursor **intact** — the scan does not restart, so a matching message is never re-examined or skipped. `remove_message`/`timeout` reset the cursor to the first message exactly as the C `erts_msgq_unlink_msg_set_save_first`/`erts_msgq_set_save_first` (`../../erts/emulator/beam/erl_proc_sig_queue.h:2329-2381`). The key is the whole `ProcessId` incl. its bumped slot serial (`beam_process/ptab.rs`), so a reused slot never inherits a dead process's cursor. The only mailbox edit that can move a *parked* receiver's scan is a delivery (append at the tail, never invalidating the cursor); removal paths (`receive_remove`, the `-eval` `remove_mailbox_message`, `beam_process::demonitor_flush`) all act on the **running** process's own mailbox. **Latent caveat (reachability unproven):** `MailboxState.markers[].position` is a queue *index* captured at `reserve`, whereas the C keeps a recv marker as a queue *node*, so a removal at a lower index could leave the recorded index off by one — worth a differential case if the compiler's marker prologue is ever exercised.
