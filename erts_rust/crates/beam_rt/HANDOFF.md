# `beam_rt` — Cross-node Handoff Detail (asks owned by OTHER crates)
Per-owner asks behind the gap ledger in [`M1_GAPS.md`](M1_GAPS.md): the failing measurement, the shape of the needed seam, and the crate that owns it.
Every entry is typed today — a typed error or a documented own-state difference — never a wrong result.
A gap whose closure is entirely in this crate is NOT here; it is [`M1_GAPS.md`](M1_GAPS.md)'s.

* `beam_gc` — **the retained nursery chain escapes `max_heap_words`.** `Nursery::grow` (`beam_gc/src/nursery.rs:269-302`) sizes the fresh space with `HeapPolicy::next_words` (correctly clamped) but pushes the space it replaces onto `retired` unconditionally, and `Nursery::capacity_words` (`:190-192`) sums the whole chain, so `Collector::grow_nursery` (`beam_gc/src/collector.rs:347-349`) — hence `beam_process::Process::grow_nursery` (`beam_process/src/process.rs:1451-1454`) — can raise a process's heap to N × `max_heap_words`; `grow` must refuse a space that would take the chain past the cap (typed heap-exhaustion, surfaced by the `beam_rt` seams as `error::system_limit`) or drop a provably empty retired space. Failing measurement: [`M1_GAPS_GC.md`](M1_GAPS_GC.md) *Heap switches*'s `+hmax 20000` `grow3:main/1`.
* `beam_gc` — **the door's escalation.** `src/context/gc/reds_door.rs` drives `beam_process::Process::collect_kind(CollectionKind::Minor)` and escalates to the escalating `Process::collect()` only when that minor reports typed heap exhaustion (`beam_gc::Collector::collect_minor` refuses before copying a word when `mature.available_words() < nursery.used_words()`). Needed: `beam_gc::AnyCollector::collect_young(&mut self, roots: &mut [Eterm]) -> Result<Collection>` — a minor that **grows/reclaims the mature space** instead of refusing — which would let the door drop the escalation entirely ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC / heap model*).
* `beam_engine` — **the native tier's instruction-position store**: a refusing charge at a call seam needs each of the three sites to call `machine.set_current_code(func, pc)` *before* consulting the seam — `store_continuation` (`crates/beam_engine/src/jit/baseline/call.rs:181`, seam at `:210`, store only at `:232`), `probe_local_call` (`jit/baseline/runtime.rs:948`, which stores nothing) and `resolve_ext_entry` (`:818`) — exactly what `jit_step_ext` already does (`runtime.rs:574-576`) and `jit_test_heap` at `:1442`. Until then the BIF dispatch and the two call-resolution seams can only *price* their work (*Scheduler / runner*, [`M1_GAPS.md`](M1_GAPS.md)).
* `beam_engine` — **no BIF-suspend channel, so a busy port cannot be waited out from inside a scheduler slice.** The C's `port_command`/`send` on a busy port calls `erts_suspend` and yields the caller (`ERTS_BIF_YIELD3`, `erl_bif_port.c:220-231`, `bif.c:2578-2582`), re-running the BIF once the driver clears the bit. `ExecutionContext::call_bif` can only answer a value or an error, and the engine's sole suspend is the `receive` family's `Step::Wait`, so a caller whose `RuntimeContext::may_pump_scheduler()` is `false` (`for_process`, i.e. every compiled slice) cannot wait: `crate::port::busy_wait::issue` answers `PortWrite`'s typed gap `NO_PUMP_REASON` instead of fabricating `true`. Needed: an engine-level BIF suspend (`call_bif` → a `BifOutcome::{Value, Error, Suspend(Resume)}` the interpreter/JIT turns into a parked machine that the scheduler re-enters with the BIF's own resume continuation), which `src/runner/` would then hook to `beam_process`'s resume-on-event path. The waiting seam, its deadline and the routes that *do* pump are already in place, so closing this is an engine change alone (*The `-eval` vs scheduled asymmetry*, [`M1_GAPS.md`](M1_GAPS.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md) *Known Issues*).
* `beam_engine` — the stacktrace's top frame is duplicated: `Machine::throw_with_trace` (`src/machine/catch.rs:318-324`) pushes the raising frame from `Machine::current_code()` and again from `Machine::resumption_contexts()` (`machine/frames.rs:316-325`, the same function with a stale call-site CP), and `Machine::raise_stacktrace` (`machine/catch.rs:480-503`) too — a `proc_lib`/`gen_server` boot crash therefore mis-attributes `error:badarg` to the re-raise site. Owner: `beam_engine`.
* `beam_engine` — `build_stacktrace` drops entry-module frames when the handler lives in a non-zero module context: `families/exceptions/stacktrace.rs:163` plus the `context == 0` heuristic at lines 169-181 (`FrameOwner::Skip` for every context-0 frame when `handler_context != 0`), and the same heuristic in `Machine::current_stacktrace` (`machine/location.rs:238-241,261-268`) — `ent:g/0 -> mid3:run/0 -> callee:h/1 -> erlang:error(badarg)` caught in the callee's module keeps `[{callee,h,…},{mid3,run,0,…}]` and loses `{ent,g,0,…}`. Owner: `beam_engine`.
* `beam_engine` — `erlang:make_fun/3` works (`write_item` always emits the integer arity, `families/exceptions/stacktrace.rs:377-388`, and `beam_term::make_small` is total, `beam_term/src/immediate.rs:76`); residual: a `function_clause` `A`-slot prints the integer arity where the oracle prints the argument LIST (`[]` for a 0-arity caller). Owner: `beam_engine`.
* `beam_engine`/`beam_rt` — the in-machine execution-position door (`ExecutionContext::wants_bif_in_machine`/`call_bif_in_machine`) hands the host the live `&Machine` and the run's entry module on every BIF dispatch, so `erlang:process_info(self(), current_stacktrace)` and the other execution-position items come from the machine's own frames; a non-self query, a nested query while an outer door call is in flight, or a process with no such position falls through to `RunnerState` (typed gap). Owner: `src/context/position.rs` + `src/native/memory/`; the seam is `beam_engine`'s.
* `beam_engine` — a `MinimalContext` arena word/byte accessor so `erlang:memory/0,1`'s `processes`/`processes_used` can be real on the `-eval`/single-pass path.
* `beam_bifs` — the registered `io:format/2` `~p`/`~w` printer raises `badarg` on a term carrying a fun (`beam_bifs/src/io.rs`, driven by `src/format.rs`): `beam_rt -eval 'io:format("~p~n",[fun lists:reverse/1]),halt(0).'` → `beam_rt: badarg`, exit 1, vs the oracle's `fun lists:reverse/1`, exit 0, the nested `[{k,fun …}]` form likewise; the fun itself is sound (`erlang:make_fun/3` and `fun M:F/A` both work, `catch io:format(...)` → `{'EXIT',badarg}`).
