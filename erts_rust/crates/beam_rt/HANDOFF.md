# `beam_rt` — Cross-node Handoff Detail (asks owned by OTHER crates)
Per-owner asks behind the gap ledger in [`M1_GAPS.md`](M1_GAPS.md): the failing measurement, the shape of the needed seam, and the crate that owns it.
Every entry is typed today — a typed error or a documented own-state difference — never a wrong result.
A gap whose closure is entirely in this crate is NOT here; it is [`M1_GAPS.md`](M1_GAPS.md)'s.

* `beam_gc` — **a refused growth becomes an arena block, not a process kill.** `Nursery::grow` bounds the chain's summed capacity by `HeapPolicy::max_heap_words` and answers the typed heap-exhaustion error (`beam_gc/src/nursery.rs:333-345`), and `Process::grow_nursery` propagates it (`beam_process/src/process.rs:1747-1753`); the two `beam_rt` growth seams then serve the request from the pointer-stable arena instead of surfacing `error:system_limit` (`src/context/gc.rs::alloc_words`, `:1494-1510`), so the block sits outside the heap accounting that the `+hmax` verdict is computed from. Needed: a seam by which a capped process's unreachable request raises the C's `system_limit` rather than falling back.
* `beam_gc` — **`AnyCollector::collect_young`.** `src/context/gc/reds_door.rs` drives `beam_process::Process::collect_kind(CollectionKind::Minor)` and escalates to the escalating `Process::collect()` only when that minor reports typed heap exhaustion — `beam_gc::Collector::collect_minor` refuses before copying a word when `mature.available_words() < minor_room_words(roots)` (`beam_gc/src/collector.rs:240`), the same **live** promotion the kind choice tests (`minor_promotion_fits`, `:216`: the nursery fill when it already fits as a cheap short-circuit, else the exact `young_promotion_words` walk). Needed: `beam_gc::AnyCollector::collect_young(&mut self, roots: &mut [Eterm]) -> Result<Collection>` — a minor that **grows/reclaims the mature space** instead of refusing — which would let the door drop the escalation entirely ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC / heap model*).
* `beam_bifs`/`beam_rt` — **the nested-run seam needs a depth bound or a trampoline.** Every `BifContext::call_fun` enters a nested run on the *same* thread (29 Rust frames, ≈8.4 KB of stack per level) with no depth bound, so ≈996 live levels exhaust an 8 MiB stack and abort the runtime; `beam_rt`'s `MAIN_STACK_BYTES = 64 << 20` is a bound-raising mitigation, and the fix is the shape `beam_abi`'s `enif_schedule_nif` trampoline already has (iterate the nested application on a constant Rust stack, or charge a depth budget that raises the oracle's `system_limit`). The A.9-visible form is a clause head of many **variable** bitstring segments (`beam_core_to_ssa`'s `match/4`/`match_con/5` recursion), pinned by `tests/compile_file.rs::a_clause_head_with_256_variable_bitstring_segments_compiles_in_process`.
* `beam_engine` — **the native tier's instruction-position store**: a refusing charge at a call seam needs each of the three sites to call `machine.set_current_code(func, pc)` *before* consulting the seam — `store_continuation` (`crates/beam_engine/src/jit/baseline/call.rs:181`, seam at `:210`, store only at `:232`), `probe_local_call` (`jit/baseline/runtime.rs:948`, which stores nothing) and `resolve_ext_entry` (`:818`) — exactly what `jit_step_ext` already does (`runtime.rs:574-576`) and `jit_test_heap` at `:1442`. Until then the BIF dispatch and the two call-resolution seams can only *price* their work (*Scheduler / runner*, [`M1_GAPS.md`](M1_GAPS.md)).
* `beam_engine` — **a `MinimalContext` arena word/byte accessor** so `erlang:memory/0,1`'s `processes`/`processes_used` can be real on the `-eval`/single-pass path.
* `beam_io`/`beam_abi` — **the driver C-ABI residuals**, each a typed or own-state answer: `driver_async_port_key`'s fair key (`async_port_key` keeps the trait default, so the C ABI function answers its own `0`), per-registration `ErlDrvEvent` identity, and `erl_drv_monotonic_time`'s phase (`beam_abi/src/driver/drv/mem.rs` reads `CLOCK_MONOTONIC` from the system epoch where the oracle returns Erlang monotonic time).
* `beam_process`/`beam_message` — **the `SchedulerPool` adoption.** `Process::heap_and_off_heap_mut()`/`heap_and_mailbox_mut()` (`beam_process/src/process.rs:579`) makes the `beam_message::Fragments::move_into` call borrow-check; the blockers are an owning drain for the wake list and a `!Send`-friendly `SchedulerPool` for SMP adoption (`Runtime` holds `Rc`/`RefCell` tables and `*mut Eterm` heaps, so `beam_process`'s `unsafe impl Send` escape is unavailable). Until then this crate composes the public fragment primitives directly (`MailboxState::remove_at` retains the removed message's payloads, `src/mailbox.rs`), keeps slices off the `*_with_ports` scheduler forms (holding the port-registry borrow across interpreted code makes every port BIF a typed `unsupported`), and discharges those obligations at its round boundaries through the exit observer (`src/runtime/ets_owner.rs`).
* `beam_rt`/`beam_dist` — **the distribution spawn responder** (`DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`, hence `erpc`/`rpc:call`). The two sibling halves exist: `beam_process` owns the reservation surface (`ProcessTable::{reserve_remote, reserve_identity, spawn_reserved, cancel_reservation}`, `beam_process/src/reserve.rs`) and `beam_dist` models both opcodes. Missing: (a) this crate's **responder** — an arm that decodes an inbound `Delivery::SpawnRequest`'s `{MFA, Opts, args}` into a `ProcessEntry` and claims/installs the identity through the reservation entry points (`src/dist/inbound.rs`'s `SpawnRequest`/`SpawnReply` arms answer `DeliveryOutcome::Unsupported`); (b) a pending-spawn table keyed by `(peer, Ref)` for a reply to resolve into the waiting local parent; and (c) the `DOP_SPAWN_REPLY` channel in **both** directions — no `send_spawn*` exists in `beam_dist/src/{control,delivery}.rs` and `InboundSink` carries no reply channel.
