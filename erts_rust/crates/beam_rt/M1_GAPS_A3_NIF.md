# `beam_rt` — M1 gap ledger, contract A.3 (NIF)
The A.3 half of the gap ledger in [`M1_GAPS.md`](M1_GAPS.md): what `load_nif/2`, the `enif_*` host API and the NIF-resource lifecycle do not match yet.
Every entry is a typed capability gap, a typed refusal or a deferred answer — never a wrong result.

## NIF (A.3)
`load_nif/2` `dlopen`s the shared object and runs C NIF code; a load failure is the oracle's returned `{error, {Reason, Text}}`, never a raise.
`NifHostImpl` implements `beam_abi::NifHost`; the host's shared table reaches `NifHost::atom_table`, which is what makes the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by name.
`NifHostImpl` implements the runtime-independent hooks — `heap`/`intern_atom`/`atom_name`/`self_pid`, `term_to_binary`/`binary_to_term`/`binary_to_term_used` (ETF; the last is the consumed-byte form `enif_binary_to_term` answers with, so an image with trailing bytes decodes its first term where the strict form refuses), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is the runtime's real normal-scheduler count), `alloc_env`/`free_env`, `make_copy` as identity — plus, through the borrowed `NifHostServices` provider (`RuntimeNifServices`: the runtime, the pass's own process table and the calling module) threaded into the per-call host, `make_ref`, `whereis_pid`, `is_process_alive`/`is_current_process_alive`, `is_port_alive`, `port_command`, `send` (the C's `enif_send`: delivery through the runtime's own `RuntimeContext::send_message` → `ProcessTable::deliver` seam, so the message crosses the same `beam_message::copy_struct` boundary a BIF send uses, a receiver parked in `receive` is woken through resume-on-send, and the C's `1`/`0` are answered — a dead or unknown local pid is the C's `0`, which `erl_nif.c:876-877` deliberately does not fold into success), `local_fun_identity` (the `NEW_FUN_EXT` identity `enif_term_to_binary` needs for a local closure, from the same `FunIdentityBridge`/code-server module snapshot the `erlang:term_to_binary/1` BIF uses, so the image is byte-structural with the oracle's) and `monitor_process_result`/`demonitor_process` (`enif_monitor_process`/`enif_demonitor_process`: a live local target is armed with an internal reference minted from the runtime's own id space and registered as a plain reference, the `(monitor, target)` pair is recorded in `Runtime::nif_monitors` (`src/nif_monitor.rs`), and the process-exit observer fires the resource type's `down` callback on the target's death — the C's `erts_fire_nif_monitor` — through `beam_abi`'s exactly-once `deliver_resource_down_id`).
The monitor index is keyed by the same 24-byte reference block `beam_abi` stores in the caller's `ErlNifMonitor`, so it is no more granular than the ABI's own monitor table, and a **remote** pid is the C's `1` (no monitor arm across distribution).
A monitor whose resource type was destroyed while armed delivers no `down` (the C's `run_resource_dtor`) and is pruned from the index at the next arm.
The load/unload host lives in `Runtime::nifs` (it cannot borrow the runtime) with `services = None`, so every provider-backed hook stays at the trait default there except `enif_send`.
A `load` callback's `enif_send` is queued on the host (`NifHostImpl`'s load window, `with_load_sends`) and delivered by `NifBridge::load_nif` the moment the callback returns — still inside the `erlang:load_nif/2` call, so the message is in the receiver's mailbox before Erlang continues — and the callback's answer is the C's `1`.
The delivery runs on the runtime's own `RuntimeContext::send_message` seam over the **pass's** own process table, because the runtime's `processes` is a fresh empty placeholder for the whole of a pass.
A destination that names no **internal local** pid is the C's `0`, which is the same refusal `erts_proc_lookup` produces.
Two residuals remain, both reported rather than wrong: a **dead** local pid answers `1` where the C answers `0` (the liveness relation lives in the process table the load host cannot reach, and the drain reports the failed delivery on the debug-trace channel), and an `unload`/resource-`dtor` callback keeps the ABI's `0` (its window closed with the load callback, and nothing removes a registry entry, so the library is only ever dropped with the runtime — there is no drain point).
Hooks at the trait default, each needing host-unreachable runtime state: `priv_data` (`beam_abi`'s loader keeps the library's `void**`; the host answers the C's null); `consume_timeslice` (`false`: the running process's reduction budget is the slice's `BudgetProbe`, so a charge from here would be a second, uncoordinated accounting of the same quantum — and the hook's `bool` cannot express "unsupported"); `whereis_port` (`None`, provable: `erlang:register/2` refuses a port, so no atom can name one); `schedule_nif` (a **legacy hook `beam_abi` never consults**: the continuation trampoline runs the scheduled chain itself and hands the chain's own value back, so nothing here is implemented for it); `dynamic_resource_call` (needs a per-library `{module, name}`-keyed resource-type registry).
The one thing an `enif_schedule_nif` chain does ask the host for is `NifHost::nif_yield_point`, once per trampoline iteration, and it is a **documented no-op on both hosts** (`NifHostImpl` and the foreign-thread `ForeignHost`): a chain runs inside one BIF call on the engine's thread, the runtime must not re-enter its own scheduler from under a NIF (`context/nif_send.rs`'s `may_pump_scheduler = false` is the same fact), no reduction or timeslice primitive is host-reachable (`consume_timeslice` is itself a documented default), and the emulator information block reports `dirty_scheduler_support: 0`, so there is no dirty pool to hand a continuation to. The gap that leaves is **fairness, never correctness**: a self-rescheduling chain keeps its thread until it ends, where the oracle preempts it.
**A thread a NIF created gets a real host: the process-independent message-env host in `src/nif/thread_env.rs`.** `beam_abi`'s thread-env seam resolves a host for `enif_alloc_env` in three steps — the host of the call the calling thread is inside, else the host the installed `ThreadEnvHostFactory` opens for that thread, else `NULL` — and a thread a NIF created is never inside a call, so the factory is the only step that can serve it. `Runtime::install_nif_thread_env` installs `ThreadEnvFactory` (one `ForeignHost` per thread, serving `heap`/`intern_atom`/`atom_name`/`existing_atom`/`self_pid`/`alloc_env`/`free_env`/`make_copy`/`send`), `Runtime::clear_nif_thread_env` withdraws it, and the install is made by `cli::build_runtime` rather than `Runtime::new`: the factory slot is process-global and last-install-wins, while the crate's own suite builds many runtimes in one process, and a real invocation builds exactly one long-lived runtime — the shape that slot is for. The factory owns a **private** name→index space (`src/nif/atoms.rs`), so `enif_make_atom` on such a thread reserves an index there, and a foreign index is **never** a live index.
Atom identity crosses to the runtime **by name**: `ForeignHost::send` encodes the message as a complete ETF image, and the runtime's decoder interns those names into its live table as the image lands — which is why the fixture's receiver still matches its own `worker_atom` literal against the worker-interned atom (`=:=`).
A term built on a foreign host belongs to that host and must be sent from it; the one mix that could smuggle one in, an `enif_send` issued from the **call** path with a foreign-built term, is the typed refusal, because the call host encodes against the live table where a private index names no live atom.
`enif_make_existing_atom` on a foreign host answers within the private space only, so a name the runtime created earlier but the foreign space never saw answers `false` — an under-answer, never a wrong index.
Reserving indices in the **live** space instead is unsound: a mirrored index space cannot stay in step with the live table, and a re-anchor hands back an index that already names another atom.
**The one substitution, stated as a substitution and not as parity: an `enif_send` from a thread with no calling process is queued, not delivered inside the call.** The C's `env == NULL` means `c_p == NULL`, so the sender is `am_undefined` and the message is in the receiver's mailbox before `enif_send` returns (`erl_nif.c:1006`, `:876-877`). Here `ForeignHost::send` resolves the destination **word only** (an internal local pid, else the C's `0` — the same refusal `erts_proc_lookup` produces), encodes the message as a **complete ETF image** over the hub's scratch table with this node's identity installed, pushes a `ForeignSend` onto the shared `ForeignSends` queue and answers the C's `1`; the image is decoded against the **live** table and delivered — waking a receiver parked in `receive` through resume-on-send — at the runtime's next drain. The image is the only sound boundary, because the terms live on a heap this runtime does not own and carry the private space's atom indices: an ETF image crosses both **by name**, then the decoder installs this node's identity so a local pid/port/reference inside it demotes back to the internal id. An unencodable message, an undecodable image and a dead target are the typed refusal — skipped and counted on the debug-trace channel, never delivered as a fabricated term.
**Two drain sites, both `Runtime::drain_nif_thread_sends`.** `src/context/calls.rs`'s `try_call_nif`, once `services` is dropped and `CodeServer::intern_pending` has committed — so an atom the NIF (or the drained image) names is already in the shared table and no borrow is outstanding — is the place a NIF would have joined a worker thread: what that thread queued is in the mailbox **before the calling process resumes**. And `src/runtime/scheduler.rs`'s `scheduler_pass`, right after the port step and before `pump_dist`, so a send queued while no NIF call is in flight still lands, going round again exactly as a port message does. A message env's `from: None` is the C's `am_undefined` envelope sender — deliberately not the target, which no sender substitution would be truthful about. With no factory installed the whole drain is one `Option` test: no lock, no allocation, nothing observable.
**Typed gaps on the foreign-thread host** (each a typed `None`/`false`, never a wrong term): `atom_table` stays at the trait default, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order a **nested** atom by raw index rather than by name on that thread; `select`, monitors, the liveness answers (`enif_is_process_alive`/`enif_is_port_alive`/`enif_is_current_process_alive`), `whereis_pid`, `make_ref`, `unique_integer`, `system_info`, `term_to_binary`/`binary_to_term(_used)`, `port_command`, `priv_data`, `consume_timeslice` and the resource/dynamic-resource family all need state the host does not hold, so they keep their defaults; `self_pid` is `None` (the C's phony message-env proc with `ERTS_INVALID_PID`), which is why `from: None` means *no sender at all* here where it means the caller on a call host; a **remote** pid destination answers `false` where the C delivers over distribution (no `beam_dist` route on the host) — the one wrong answer in that module, recorded as a gap; a message carrying a local `make_fun3` closure cannot be encoded (typed `None`, the identity lives in a loaded module the host cannot reach); an atom the private space cannot name is unnameable (typed `None`); and a poisoned queue lock makes the host's `send` the typed refusal rather than a fabricated `1` (the runtime's own drain recovers a poisoned queue instead, the data behind it being a plain `Vec`).
The private space is append-only, so an index a foreign thread was handed keeps its name for the life of the hub: there is no re-anchor, no reconciliation with the live table, and no divergence counter (`src/nif/atoms.rs` carries the argument).

Nine of the ten are one mechanism: this runtime runs NIF calls on its own driver thread, not a registered scheduler thread, so `enif_thread_type()` answers `0` (`ERL_NIF_THR_UNDEFINED`) where the oracle answers `1` (`ERL_NIF_THR_NORMAL_SCHEDULER`) — the `enif_thread_type`-reporting probes only; the tenth is `sched_last_ret()`'s raw `THE_NON_VALUE` word, the trampoline's documented substitution (printed as a `note_` line, never compared). `probe_stop_nostop_type/0` is never driven: the C only `ASSERT`s that the `stop` callback exists, so a release oracle calls NULL and dies (measured SIGSEGV), which measures the oracle, not this runtime. The colocated unit suite `src/nif/thread_env_tests.rs` drives the host, the atom hub and the drain with no C toolchain and no oracle.
A second `load_nif` for a loaded module is `reload`; a NIF returning a non-term is caught by `try_call_nif` as a typed error, never an abort.
The `enif_select` registration/delivery half is `src/nif_select.rs` over `src/port/select.rs`'s one readiness store.
`enif_select`/`enif_select_x` are live: the mask `beam_abi` forwards verbatim is decoded with `ErlNifSelectFlags::intersects` into the runtime's one readiness store (`src/port/select.rs`, reached through `PortRegistry::arm_nif_select`/`stop_nif_select`/`cancel_nif_select`), the C's return codes are answered (`0` accepted, `ERL_NIF_SELECT_STOP_CALLED | <cleared>` for a `STOP`, `<cleared>` bits for a `CANCEL`, `INT_MIN | ERL_NIF_SELECT_FAILED` on a refused control op), and readiness mints the resource term at delivery time (`crate::nif::resource_term_for` → `beam_abi`'s `resource_term`, a refused/foreign/dying pointer delivering nothing rather than a fabricated term) and sends `{select, ResourceTerm, Ref, EventAtom}` — or the caller's own `ERL_NIF_SELECT_CUSTOM_MSG` term — to the `pid` operand or the calling process.
A registration holds **one reference per armed interest**, taken through `beam_abi`'s `keep_resource` at `arm` and given back **exactly once** at disarm (a `STOP`, a `CANCEL`, the dead-owner prune, or the store's own teardown — the registration owns it as a `SelectHold`, an RAII hold), so a NIF that arms a select and then releases its own reference still gets its notification, exactly as in the C (`erl_check_io.c:1446` keeps it, `:1533`/`:1834`/`:2242` give it back).
On the delivery path only, the interest's reference is released **after** the notification's resource term has been minted — the mint takes a reference of its own — so the object outlives the disarm that produced the event instead of being destroyed between the disarm and the mint.
A non-null object this runtime cannot keep alive (one it never allocated, or one already dying) is refused at arm time, so no interest is armed for an object no notification could name.
Pinned end to end by `tests/nif_select.rs`'s `enif_select_interest_reference_keeps_a_released_object_alive_until_readiness`, `enif_select_stop_releases_the_interests_reference_exactly_once` and `enif_select_interest_of_a_dead_owner_is_pruned_and_released`.
Residuals, each a **lost notification** rather than a wrong result. The resource type's `stop` callback **does** run: `beam_abi`'s `enif_select` (`nif::enif::select::service_stop_verdict`) reads back the code this layer answers and, for a `STOP_CALLED`, invokes the callback **synchronously** with `is_direct_call = true` — the C's scheduler-side call (`erl_check_io.c:1531`). `ERL_NIF_SELECT_STOP_SCHEDULED` (the verdict that *parks* a callback for a later drain) is therefore never reported: `PortRegistry::stop_nif_select` de-registers the descriptor immediately, so nothing is ever parked and `beam_abi`'s pending-stop table (`nif::enif::stop::run_pending_stops`) has nothing to run here — this runtime adds **no** drain call for it, because a poll-loop call would be a no-op pretending to be a hook. What is missing is only a host that *defers*, and the deferred arm belongs to the C's select/poll fallback driver, which this runtime does not have. And `ERL_NIF_SELECT_NOTSUP` is unreachable by construction, `Interest::ERROR` being a served caller-intent bit.
**The resource-term reclamation (the `enif_make_resource` reference drop) runs at three sites, and every decline is a leak rather than a dangle.** `src/context/gc/resources.rs::reclaim` is the scheduled site (the runner's `Yield` park arm, under `engine.parked_published`); `src/eval/reclaim/resource.rs::{prune_at_statement_boundary,prune_beyond}` are the two **non-park** sites the `-eval` route and every nested run need, because that route's action process is never enqueued and therefore never parks. All three share one descent (`src/eval/reclaim.rs::walk<R: Reach>`) and one two-tier match — a candidate's own raw word, then `beam_term::boxed::internal_ref_id`, because a `copy_struct` copy is a different word with the same identity.
Residuals, all but one a **leak of the object's host `malloc` block**, never a wrong term:
* the two non-park sites cannot enumerate their whole process, so each prunes only against a **frontier** (a snapshot of the candidate set at statement entry / run entry) and releases only candidates minted **inside** its own window — a resource minted before that window is retained even when nothing reachable names it, because a store the walk cannot see may hold it;
* consequently a runtime's **first** statement boundary records a frontier and releases nothing (a bounded one-statement leak; in the measured cadence shape it is zero, the first boundary following an `init/1` that mints nothing);
* a nested run that **fails** (`Err`) publishes no live set, so its epilogue prunes nothing — the resources minted inside it are retained;
* a candidate whose identity cannot be read (its mint block no longer holds a reference header) is recorded as **reached**, and so is one reached by the prune-only valve or by the parked-resource registry's word reuse (`Registry::bind_term` evicts a binding whose word a new mint reuses, so a re-minted word can look pre-frontier) — "cannot identify it" must never become "it is dead";
* a resource held only by a store outside the walk's root families — another process's heap, an ETS object, a `persistent_term` value — is not enumerated by any site, so its copy's reference identity reaches nothing and the object is **released** while the store still names it; closing the ETS half needs an object iterator over `beam_bifs::TableRegistry`, which it does not expose (a cross-crate ask, not made);
* there is **no region word scan** for resources (unlike the refc payload's `HEADER_BIN_REF` pattern): a resource's identity lives inside its 4-word block and the mint block itself stands in a runtime region, so a word-pattern scan would match every candidate every time; the descent is region-agnostic instead, so any live copy is reached from the named roots and a copy in a region nothing names is dead data.
**The walk's completeness rests on `Runtime::gather_off_heap_roots`**, whose families are the escaped closures' capture environments, the `seq_trace` tokens, every live process's complete published root set (its dictionary, its mailbox, its registers, its saved arguments, its pending signals), `pending_spawns`, the two `RunnerState::gather_off_heap_roots` sub-families (`src/runner/entry.rs`: an engine's un-consumed arena-stable arguments and entry fun, and an **un-published** parked machine's own root set, gated on the pid still being in the process table) and every pending timer **delivery** (`src/timers.rs`). The engine and timer families matter for a **resource** even though the stabilization that put their terms on the arena flattened the refc payload in them, and every family matters for one in general: a resource's identity is its reference id and a copy of it keeps that id, so the prune's second match tier recognises the copy and a family left out makes a live resource look unreachable. The two non-park sites inherit that same set as their root enumeration, and the park arm (`src/context/gc/resources.rs::reclaim`) additionally seeds its walk with it as a **separate host seed list** — never through gate 5, which classifies the process's own roots only, because every host store is a foreign region by construction and merging it there would decline every prune a resource program attempts.
**Only the families that are live during a scheduler pass reach the park arm.** A pass moves the process table (`Runtime::take_processes`, so the runtime's own is an equivalent empty placeholder) and `RunnerState` out of the runtime, so at the park arm the per-process family and both engine sub-families are empty and the host seed is exactly the escaped closures, the `seq_trace` tokens, `pending_spawns` and the pending timer deliveries; the executing process's own root set is that arm's **local** root list instead (it mirrors the process's registers, which `park_machine` published a moment earlier). The per-process and engine families are live at the two **non-park** sites (`src/eval/reclaim/resource.rs`), which run with the runtime's own tables — that is where a resource held by another process, or by an engine's not-yet-consumed arguments, is reached and retained. Two spawn routes contribute no root at all, deliberately: `Runtime::spawn_process`/`Runtime::spawn_fun_process` hand `RunnerState::spawn` an `arena_args == false` engine, because their arguments may still stand on a pooled BIF heap the copy-out rewinds per call — a resource handed in through them is not kept alive by any prune, the documented cost of those two routes.
**Test strategy: the two witnesses are read as a pair.** `is_resource/1` answers whether the term still designates its object (`enif_get_resource` resolving the binding, so a released term answers `0`), `dtor_count/0` whether the object was actually destroyed, and neither alone distinguishes a release whose object another reference still holds.
Every other decline — an exhausted walk budget, an unknown boxed header, a valve trip — retains **everything** for that walk, and the observed frontier still advances so a persistent decline costs one walk rather than one per call.
