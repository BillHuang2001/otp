# `beam_rt/tests/` — the A.5 (distribution) evidence

The routing half is pinned hermetically by `dist_delivery.rs` and `exit_remote.rs`, and the live half by the peer suites against a real `erl`; `dist.rs`, `node_cookie.rs` and `pid_roundtrip.rs` cover the accepting (listener) boundary, the cookie and the pid wire round trip.
* `dist_delivery.rs` (31 tests). Every test in the file's first part is **hermetic**: a client and a server `ConnectionDriver` are wired to each other and the client's `ConnectionDriver::take_output` bytes are shuttled by hand, so no socket, no `epmd` and no system `erl` is needed; the last one drives a real loopback TCP link into a running runtime through the scheduler pass (still hermetic).
  * The ordinary message families are asserted by their delivered effect: `DOP_SEND` into the addressed local mailbox (`an_inbound_send_reaches_the_addressed_local_mailbox`), `DOP_REG_SEND` to a registered name (`an_inbound_reg_send_reaches_a_registered_name`), an unknown name (`an_unknown_registered_name_is_no_such_process`), a pid on another node or incarnation (`a_pid_on_another_node_is_no_such_process_and_never_mis_delivered`) and a wire-borne reference alias (`an_alias_send_to_a_wire_borne_reference_is_unsupported_not_a_wrong_delivery`).
  * The wire-borne `Link`/`Exit` families are applied through a real wire (`the_routed_link_and_exit_families_are_applied_through_the_wire`); the inbound gate is on by default and toggleable (`inbound_routing_is_on_by_default_and_toggleable`, `a_nodeless_runtime_still_reports_no_inbound_traffic`); a real loopback link delivers through the scheduler pass (`a_real_loopback_link_delivers_through_the_scheduler_pass`).
  * A malformed control message and a forged `Link` from a third node each retire exactly their own link (`a_malformed_inbound_reg_send_is_refused_and_retires_its_link`, `a_forged_inbound_link_from_a_third_node_retires_its_link`) — the per-link **checked** drain (`Delivery::classify_validated` against that link's own `LinkIdentity`), never a wrong delivery.
  * The `(7)` group drives synthetic `Delivery` values straight into the public `LocalDeliverySink` over a standalone `ProcessTable`, pinning the routing table one family at a time: the ordinary families by mailbox delivery, and the **route-free receipt** families by the local state they install — `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref`/`demonitor_from_remote_ref`, `remote_monitor_down` and `set_group_leader_from_remote`.
  * `every_routed_inbound_family_routes_nothing_outbound` drives all **10** routed families (`Link`, `Exit`, `Link`, `UnlinkId` with `id == 0` — the **unchecked-view** spelling, see below — `UnlinkIdAck`, `Exit2`, `Monitor`, `Demonitor`, `MonitorExit`, `GroupLeader`) through a recording `DistSignalRouter` and asserts the log stays empty, so a receipt family installs (or drops) its local record and echoes **no** outbound `DOP_*`. A zero-id `DOP_UNLINK_ID` is **not** a deliverable wire form: `beam_dist`'s checked drain rejects it before any sink is called (`Delivery::classify_validated`'s `is_nonzero_uint`, the C's `dist.c:2291-2295`), and that production answer is pinned by `a_zero_id_inbound_unlink_id_is_refused_and_retires_only_its_link` (the offending link alone is retired; a second link to the same peer keeps delivering), so the unchecked view the `(7)` group drives serves only the local record removal.  * `every_unrouted_family_is_the_honest_unsupported` asserts **3** rows — the distributed-spawn family's `SpawnRequest` and `SpawnReply`, plus `Delivery::Other(Dop::Unlink)`, the one `DOP_*` recognised on the wire but refused outright (`dist.c:2277-2282`) — each `DeliveryOutcome::Unsupported` with an empty mailbox, so a future change must flip a row on purpose rather than by accident; the `UnlinkId` `id != 0` ack-owing half, a monitor DOWN for this node's own outgoing reference, an out-of-contract signal, an `AltactSig` priority/exit form and an unowned reference or non-ref target are their own cases.
  * `local_monitor_ref_image` (~:1027-1043) is the **canonical** `erts_set_ref_numbers` pack (the 18-bit reference number in `num[0]`, its bits 18..31 in `num[1]`, the rest in `num[2]`) and the exact inverse of the sink's unpack — byte-for-byte what `src/dist_client/signals.rs::monitor_ref_term` writes. Use this helper for **every** locally minted reference image; a hand-packed id with any other layout round-trips to a *different* id, so the outgoing remote monitor it names is never found. A peer-minted reference on a foreign node is written verbatim instead.
* `exit_remote.rs` (5 tests): remote `erlang:exit/2` end to end **hermetically** — two real `ProcessTable`s on either side of a real `beam_dist::ConnectionDriver` pair (the dialer's has a recording `DistSignalRouter`, the listener's carries its own `LocalIdentity` exactly as every drained link does), so the emitted signal, the wire codec and the recipient's route-free receipt are all pinned with no socket and no `epmd`: `kill` terminates the target through the wire (`a_remote_exit_kill_terminates_the_target_through_the_wire`), `kill` is untrappable even for a trapping target (`a_remote_exit_kill_is_untrappable_even_for_a_trapping_target`), `normal` leaves a non-trapping target alive (`a_remote_exit_normal_leaves_a_non_trapping_target_alive`), a trapping target receives `{'EXIT', …}` instead of dying (`a_trapping_target_receives_the_exit_message_instead_of_dying`) and a dead target is `NoSuchProcess` (`a_remote_exit_for_a_dead_target_is_no_such_process`).
* `dist_client.rs` (1 test): the **connecting** half against a real `erl -sname` peer — the runtime resolves the peer through `epmd`, drives the client side of the `'N'` handshake to `Established` (`Runtime::dist_connect`) and carries a real `DOP_REG_SEND` to a registered process on the peer (`Runtime::dist_send_reg_send`), asserted on the peer's own stdout rather than on this runtime's belief about what it sent.
* `live_inbound.rs` (3 tests): a real `erl` peer `DOP_REG_SEND`s into a **running local process** (`a_real_erl_peer_reg_sends_into_a_running_local_process`) and the same over the CLI boundary (`the_cli_node_receives_an_inbound_reg_send_from_a_real_erl_peer`, guarded by `the_fixture_beam_is_present`); the assertion is on the delivered term (the in-process return value, or the CLI `run` action's `~w~n`), never on a belief about what a peer sent.
  The committed fixture `dist_echo:wait/0`'s `after 20` loop is **load-bearing**: a bare `receive` with no deadline leaves the scheduler quiescent (an empty run queue, nothing to poll, no pending timer), so `Runtime::run_scheduled` stops with its honest `blocked` diagnostic before the peer's message can arrive, whereas each arm's re-armed deadline keeps a pass stepping so the distribution half (`pump_dist`) keeps polling for the inbound connection and message.
* `live_signals.rs` (5 tests): the **outbound signal** path against a real peer — the real `erlang:link/1` front door routes `DOP_LINK` and the router routes `DOP_EXIT` for the same pair to a real OTP node whose trapping process prints `LINKEXIT` (`a_bif_link_and_exit_reach_a_real_erl_peer`), the runtime-installed `beam_process::DistSignalRouter` seam keeps its own live proof (`a_router_routed_link_and_exit_reach_a_real_erl_peer`), and the byte-identical peer session with the link step skipped reports `NOLINKEXIT` as the real **negative control** (`without_the_link_the_exit_is_not_delivered`), which is what makes the `LINKEXIT` observation non-vacuous. The last two are the **inbound** monitor direction: a peer's `erlang:monitor(process, OurPid)` gets its `{'DOWN', …}` on the reference the **peer** minted once our process dies (`a_peer_monitor_of_our_process_receives_down_with_the_peer_minted_ref`), and the peer's `demonitor` suppresses it (`a_peer_demonitor_suppresses_the_down`).
* `live_remote_families.rs` (4 tests): two A.5 families proved live against a real `erl` peer, each with its own negative control, over `live_signals.rs`'s harness verbatim. **Outbound `unlink`**: `erlang:unlink/1` on a remote pid routes `{DOP_UNLINK_ID, Id, From, To}` (`dist.c:1472`), so the peer's trapping process no longer receives the `'EXIT'` our death would otherwise deliver (`an_unlink_stops_the_exit_a_real_erl_peer_would_otherwise_trap`) — and the byte-identical session **without** the unlink does receive it (`without_the_unlink_the_exit_reaches_the_trapping_peer`). **Inbound `DOP_ALIAS_SEND`**: a real peer sends to a local alias and the message lands in our mailbox (`a_real_erl_peer_sends_to_a_local_alias_and_the_message_lands_in_our_mailbox`), while without a live alias the same send is dropped (`without_a_live_alias_the_alias_send_is_dropped`).
* `live_remote_exit.rs` (2 live tests): remote `erlang:exit/2` against a real peer, whose own node decides what to do with the signal (`DOP_EXIT2`, `dist.c:1800`, **not** the link exit `DOP_EXIT`) — `exit(Peer, kill)` really kills the peer's process (`a_remote_exit_kill_really_kills_the_peers_process`) and `exit(Peer, normal)` leaves a non-trapping peer process alive (`a_remote_exit_normal_leaves_a_non_trapping_peer_process_alive`).
* `net_adm.rs` (1 live test): the connector BIFs (`net_adm`/`net_kernel` on a real peer) over a live peer (`the_connector_bifs_reach_a_real_peer`).
* `remote_send.rs` (8 tests): the non-node regression (`a_remote_name_destination_is_the_typed_capability_gap_on_a_plain_runtime`, `a_remote_pid_destination_is_refused_on_a_plain_runtime`), a malformed or unregistered destination (`a_malformed_or_unregistered_destination_is_badarg`), the **three-routes-agree** check — the compiled `Dest ! Msg`, the `erlang:send/2` BIF and the `-eval` `!` — over a remote name pair (`the_compiled_bang_the_bif_and_the_eval_send_agree_on_a_remote_name_pair`), the same-node arm (`a_same_node_name_pair_is_a_local_named_send`, `a_same_node_pair_with_an_unregistered_name_is_accepted_and_dropped`), and the live half: a compiled `{Name, PeerNode} ! Msg` delivered to a real peer and asserted on that peer's **stdout** (`a_compiled_bang_delivers_a_remote_name_destination_to_a_real_peer`), with `without_a_node_the_same_tuple_is_refused_and_nothing_is_delivered` as its negative control.
* `support/{dist,pair,fixture}.rs` — the **one** two-VM harness (no suite owns its own copy): `dist.rs` holds toolchain discovery, the timeout consts, `Scratch`, `PrivateEpmd`, `ChildVm` and `Harness` (`new`/`compile_fixture`/`spawn_runtime`/`spawn_peer`/`spawn_actor` with `PeerKind::{Oracle, Rust}`), `pair.rs` the responder/actor session, and `fixture.rs` the **one** Erlang fixture source (module `two_vm`) that both peer kinds run. Every child is `setsid -w`-isolated (an Erlang VM signals its **process group**, so a plain child could hit the test binary); `ChildVm::drop` sends `TERM`, waits a bounded grace, escalates to `KILL` and reaps; the daemonized `epmd` is reclaimed by its own `-port` argv (OTP's daemon refuses `STOP_REQ`/`KILL_REQ` from an ordinary client) and every child receives **only** `ERL_EPMD_PORT`. Toolchain discovery is filesystem-only (`support::find_on_path`/`require_oracle`); a missing tool, an `epmd` that does not come up or a missing `READY` line is a **loud skip**, never a silent pass. The fixture is compiled at test time into the test's own scratch dir (never committed, so `tests/fixtures/` is never passed to the peer as a `-pa`). Peer side of the protocol: our node runs the **responder** (`run <fixture.beam> two_vm:<responder>/1 "<peer node>"`), the peer runs the **actor** (`erl … -pa <scratch> -run two_vm <actor> "<our node>" -s init stop`, or the identical `beam_rt … run <fixture.beam> two_vm:<actor>/1 "<our node>"`), so one Erlang program is exercised against both peer implementations. A suite holding VMs declares the `Harness` **last** (and `Harness` declares the `epmd` before the scratch dir it `cd`'d into) — the drop order is load-bearing.
* `dist_two_vm.rs` (**opt-in**, 24 `#[ignore]`d tests) — rust ↔ real **`erl`**, the oracle-cross-checked half: two VMs alive at once on one private `epmd`, every observation a printed line compared term-for-term on both sides, every direction asserted from the side that *must* see it. Every asserted value is one a real OTP 29.1.1 `erl` printed with **both** sides an `erl`.
  * Exchange + node monitors: `the_oracle_pings_the_rust_node_and_a_message_crosses_each_way` (`net_adm:ping/1` → `pong`, one message each way compared term-for-term, then the runtime's `monitor_node` sees the peer halt) and `the_peer_watches_the_rust_node_go_down` (the peer's `monitor_node` sees the runtime's group killed).
  * The peer acts on **our** process and we die: `a_real_erl_peer_links_to_our_process_and_traps_our_exit` (`{'EXIT', OurPid, boom}`), `a_real_erl_peer_traps_our_exit_with_the_reason_term_it_asked_for` (the **reason term** `{shutdown,{custom,7}}` crosses, not merely the event), `a_real_erl_peer_unlinks_first_so_our_exit_is_not_delivered` (negative control: `NOEXIT`, and no `'EXIT'` anywhere in the peer transcript), `a_real_erl_peer_monitors_our_process_and_gets_the_peer_minted_down` (the DOWN carries the **peer-minted** reference — the receive clause binds the same `Ref`, so a different one times out), `a_real_erl_peer_demonitors_before_our_death_so_no_down_arrives` (`NODOWN`, the peer's reference occurring exactly once in its transcript).
  * **We** act on a peer process: `our_link_to_a_real_erl_process_traps_that_process_exit` (`erlang:link/1` → `{'EXIT', PeerPid, boom}`), `our_monitor_of_a_real_erl_process_receives_the_monitor_exit_down` (the inbound `DOP_MONITOR_P_EXIT` path, ref identity bound), `our_demonitor_of_a_real_erl_process_suppresses_the_down`, `our_remote_exit_kill_kills_a_real_erl_process` (`DOP_EXIT2`; the peer's own witness reports `killed`), `our_remote_exit_normal_leaves_a_real_erl_process_alive` (the peer's `VICTIM_ALIVE` proof of life), `a_real_erl_peer_sends_to_our_alias_and_the_message_lands_in_our_mailbox` (inbound `DOP_ALIAS_SEND`) and `we_send_to_a_real_erl_peers_alias_and_it_lands_in_the_peers_mailbox` (the symmetric alias direction).
  * The inbound `DOP_LINK` **as our own process reports it**: `a_real_erl_peers_link_shows_up_in_the_links_item_and_clears_on_unlink` — the peer links the victim, barriers (so our node has applied the link), then unlinks and barriers again, and the fixture's `peer_drives_links/1` responder answers each barrier with the victim's `process_info(Victim, links)` **shape** only (`length/1` plus one `is_pid/1` per entry; the pids are unprintable on both sides): `LINKS_FRESH 0 []` before the peer acts, `LINKS_LINKED 1 [true]` after the link, `LINKS_UNLINKED 0 []` after the unlink. The victim is never killed and answers a round-trip probe (`VICTIM_ALIVE`), so the emptied item cannot be explained by its death.
  * The **inbound-signal** families, where the peer arms the relationship and the assertion is what *our* process received (fixture section 5: `peer_link_death/1`, `peer_link_death_plain/1`, `peer_monitors/1`, `peer_exit2/1`): `a_real_erl_peers_death_travels_inbound_and_our_trapping_process_traps_its_compound_reason` (the peer's own `link/1`ed arm dies of `{boom,[1,2,3]}` and our trapping victim must trap that very term — `EXIT_REASON {boom,[1,2,3]}`, plus `EXIT_PID true` comparing the trapped sender with the pid the peer reported separately, and the peer's `LINKER_DOWN` proving its arm really died of the reason it chose), `a_real_erl_peers_death_travels_inbound_and_kills_our_non_trapping_process_with_its_reason` (the same link death against a non-trapping victim ⇒ `DOWN_REASON boom` read back through our own local monitor: never `noproc`, never `killed`), `a_real_erl_peers_monitor_of_our_process_gets_a_down_carrying_the_boxed_reason` (the peer's `erlang:monitor(process, OurPid)` ⇒ `MONITORED_BY 1 [true]` from *our* side, then the peer forwards the whole `{'DOWN', Ref, process, OurPid, {boom,[1,2,3]}}` back so every slot is asserted here: `DOWN_SIZE 5`, head, `is_reference/1`, `process`, our own pid `=:=`, and the reason term), `a_real_erl_peers_exit_calls_travel_inbound_and_split_the_matrix_by_trapping_and_kill` (inbound `DOP_EXIT2` — `erlang:exit(Pid, boom|kill)` against four of our processes ⇒ `EXIT2 plain_boom down boom`, `EXIT2 plain_kill down killed`, `EXIT2 trap_boom trapped boom from_peer=true` with the survivor probed alive (`TRAP_BOOM_ALIVE true`), `EXIT2 trap_kill down killed`: `kill` untrappable both ways, `boom` trapped by the trapping receiver and passed through unchanged to the non-trapping one).
  * The **peer-node-loss** family, where the peer's whole *node* goes away while a relationship with one of its processes stands (fixture section 6: `node_loss_monitor/1`, `node_loss_link_trapped/1`, `node_loss_link_plain/1`, `node_loss_reconnect/1` + the actors `actor_node_loss_target/1`/`actor_node_loss_survivor/1`): the peer confirms the relationship on **its own** side (`PEER_ARM_SEEN`, read from its `links`/`monitored_by` items) and then runs `init:stop()`, so OTP resolves it with the reason `noconnection` — `a_real_erl_peers_node_death_sends_our_monitor_a_down_with_noconnection` (a `{'DOWN', Ref, process, PeerPid, noconnection}` whose reference is the one `monitor/2` returned and whose tag is `process`), `a_real_erl_peers_node_death_sends_our_trapping_link_an_exit_with_noconnection` (`{'EXIT', PeerPid, noconnection}` into a trapping process, which stays alive), `a_real_erl_peers_node_death_kills_our_non_trapping_link_with_noconnection` (a non-trapping link holder dies of `noconnection`, read back through our own local monitor — never `noproc`, never `killed`) and the negative control `reconnecting_to_a_real_erl_peer_is_not_a_node_down` (both relationships armed on a **live** peer that we re-dial: a 3 s stepped window stays empty, and the link, the monitor and a round trip all still answer). There is no `ACTOR_DONE`/`{bye, …}` handshake in this family — the peer's node is what ended — so the closing assertions are the peer's own clean exit and the `run` action's `done`; every `receive` in it is a **stepped** 100 ms window (a single long `receive … after T` lets the `run` route's pass sleep to the deadline without ever pumping the distribution links). The oracle values are the ones a real OTP 29.1.1 `erl` prints with both sides an `erl`, and the runtime now emits all of them: every case in the family passes (the four `#[ignore]`d two-VM cases plus the rest of the binary — 24 passed / 0 failed).
  * Pid identity (the observable a broken inbound decode falsifies): `our_pid_survives_a_round_trip_through_a_real_erl_peer` — we send `self()`, the peer echoes the **exact** term, `Echoed =:= self()` prints `IDENTITY true`, with `SELF`/`SELF_NODE`/`ECHO_NODE` printed so a mismatch is diagnosable.* `dist_two_rust.rs` (**opt-in**, 12 `#[ignore]`d tests) — the same families between **two `beam_rt` nodes**, both spawned: `two_rust_nodes_ping_each_other` (this runtime's connector meets this runtime's acceptor; `pong` in **both** directions), `a_rust_peer_links_to_our_process_and_our_exit_reaches_it`, `our_monitor_of_a_rust_peer_process_receives_the_down`, `our_demonitor_of_a_rust_peer_process_suppresses_the_down` (negative control), `our_remote_exit_kill_kills_a_process_on_a_rust_peer`, `an_alias_created_on_one_rust_node_delivers_from_the_other`, `our_pid_survives_a_round_trip_through_a_rust_peer`, plus the five **inbound** cases (the peer acting on a process *our* node hosts, the mirror of the seven above and `dist_two_vm.rs`'s own inbound family): `a_rust_peers_death_travels_inbound_and_our_trapping_process_traps_its_compound_reason` (inbound `DOP_EXIT`, `EXIT_PID true` + the reason term `{boom,[1,2,3]}`), `a_rust_peers_death_travels_inbound_and_kills_our_non_trapping_process_with_its_reason` (the same link with `trap_exit` off, read back through our own local monitor), `a_rust_peers_exit_calls_travel_inbound_and_split_the_matrix_by_trapping_and_kill` (inbound `DOP_EXIT2` over the `{plain,kill}` × `{trapping,not}` matrix, `kill` untrappable both ways), and the two *record* families the next bullet details (`a_rust_peers_link_shows_up_in_the_links_item_and_clears_on_unlink`, `a_rust_peers_monitor_of_our_process_gets_a_down_carrying_the_boxed_reason`). The assertions are **equal in strength but different in shape**: a `beam_rt` peer cannot render a remote identifier (first Notes bullet below), so they assert **term identity** (`=:=`, `is_pid`, a bound receive pattern) and print booleans/atoms/reasons instead of canonical pid text.
  **All four measured rust↔rust inbound families are covered**, including the two whose claim is a *record* that must be visible ahead of the peer's next message (fixture responders `peer_drives_links/1` + actor `link_and_unlink/1`, and `peer_monitors/1` + actor `actor_monitor_down/1`, both already used by the real-`erl` cases): `a_rust_peers_link_shows_up_in_the_links_item_and_clears_on_unlink` drives the peer's `link/1` → a barrier → its `unlink/1` → a second barrier, and asserts the victim's `process_info(Victim, links)` item by **shape** — `LINKS_FRESH 0 []` (the baseline, before the peer acts), `LINKS_LINKED 1 [true]` (the peer's `DOP_LINK` recorded *before* the barrier it wrote right after the call), `LINKS_UNLINKED 0 []` (its `DOP_UNLINK_ID`), plus `VICTIM_ALIVE` (so the emptied item cannot be a dead process), `PEER_SAW links_reported`, `BYE done`, `HANDSHAKE_DONE`; and `a_rust_peers_monitor_of_our_process_gets_a_down_carrying_the_boxed_reason` drives the peer's `erlang:monitor/2` of a victim we host, asserts `MONITORED_BY 1 [true]` (our node really recorded the `DOP_MONITOR_P` **before** the victim died) and then every slot of the `{'DOWN', …}` the peer forwards back — `DOWN_SIZE 5`, `DOWN_HEAD true`, `DOWN_REF true`, `DOWN_KIND true`, `DOWN_OBJ true`, `DOWN_REASON {boom,[1,2,3]}` — with the peer's own `PEER_DOWN_REASON {boom,[1,2,3]}`. The ordering they rely on is **current behaviour**: a process-table control signal (`link`/`unlink`/`monitor`) leaves this runtime queued (`DistSignalRouter` → `DistClientInner::queue_signal`, flushed at the client's next `pump`), so `DistClient`'s three message sends (`send_reg_send`/`send_message_pid`/`send_alias`) drain the link's queued controls (`flush_queued_controls`) before writing their own frame — a control created earlier can therefore never be overtaken by a later message on the same link, matching ERTS, which writes a control synchronously under the link lock (`src/dist_client/CONTEXT.md`). The monitor family's **demonitor** sub-arm remains unmeasurable on a `beam_rt` peer: the fixture's `monitor_then_demonitor/1` renders the victim with `pid_text/1`, an uncatchable capability gap on a rust peer (exit 3) before the relationship is armed.
* `dist_two_vm_wire.rs` (**opt-in**, 1 `#[ignore]`d test; hermetic — no `erl`/`erlc`/`epmd`, so it never skips): `the_outbound_monitor_down_control_is_opcode_21_with_the_watched_process_first`. An in-process `Runtime` plus a test-side `beam_dist::ConnectionDriver::client` on a real socket: the peer monitors a local process (`DOP_MONITOR_P` carrying the peer's own reference), kills it (`DOP_EXIT2`), and the test **decodes the control bytes the runtime then wrote** — opcode **21** (`DOP_MONITOR_P_EXIT`), 5-element tuple, `terms[0]` the **watched** local pid (this node's name + creation, the dying process's num/serial), `terms[1]` the **watcher** peer pid, `terms[2]` the peer-minted reference echoed verbatim, `terms[3]` the reason — plus the negotiated `DFLAG` set (`0x6d07df7fbd`, including `DFLAG_HANDSHAKE_23`/`DFLAG_UNLINK_ID` and the rest of `dist.h`'s mandatory-26 set). The Erlang surface cannot disambiguate the two pid arguments nor the opcode, which is why this one assertion must be byte-level.
