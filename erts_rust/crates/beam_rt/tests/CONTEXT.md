# `beam_rt/tests/` — runtime integration suites (the executable + the `Runtime` façade)

## Intent
Black-box and glue-level end-to-end tests for the `beam_rt` runtime binary and its `Runtime`/`RuntimeContext` façade.
Two drivers are used throughout and they are NOT interchangeable:
* `Runtime::eval` / the CLI `-eval` action (`beam_rt -noshell -eval '<expr>'`) — the **single-pass** evaluator route; no scheduler slice.
* the CLI `run <file.beam> <mod>:<fun>/<arity> [args]` action (`Runtime::run_scheduled`) — a **scheduled process** on the real scheduler/poller/runner; also `runtime.run_function`/`run_module` (single-pass, `context.run_export`, caller-owned output sink).
Most suites run **both** runtimes (this one and the system `erl`/`erlc` oracle) and compare observable output; the oracle is the expected value.

## Running
A missing **toolchain** (`erl`, `erlc`, `cc`, `erl_driver.h`) is always a **loud skip** plus a `return`, never a silent pass (`support/mod.rs`'s `skip_loudly`/`require_oracle`).
A missing **committed fixture** is the other class — a repository defect, not a toolchain absence — and **fails** (`mailbox_rescan.rs`'s `Scratch::new`, `bif_entry_spawn.rs`'s staging, `port_failure.rs`'s `require_probe_beam`/`the_probe_image_is_committed`, `live_inbound.rs`'s `the_fixture_beam_is_present`), because a skip there would report green rows that compared nothing.
**Opt-in suites** are `#[ignore]`d and need `-- --ignored --nocapture`: the four two-VM files `dist_two_vm.rs` (rust ↔ real `erl`, 24 tests), `dist_two_rust.rs` (rust ↔ rust, 12), `dist_two_vm_wire.rs` (1, hermetic byte-level) and `dist_payload_matrix.rs` (9, the large-payload `HeapFragment` matrix), plus the corpus/measurement harnesses (`selfhost_breadth.rs`, `selfhost_bootstrap.rs`, `src/context/calls/tests.rs`, `src/context/gc_walk.rs`) and the one residual case in `inet_nested.rs`.
An `#[ignore]`d *worker* test that a non-ignored parent re-runs in a child process (`ref_id_space.rs`, `nif_resource_gc.rs`, `nif_resource_nested.rs`) is **not** an opt-in: it is driven by its parent and must not be run through `--ignored` beside the parent.
Run the pair suites **serially** (`--test-threads=1`): each test owns a private `epmd` and two VMs, so serial execution keeps a heavily loaded host from stretching the per-step bounds.
Wall-clock on a shared 8-core host: `dist_two_vm` ≈52–110 s, `dist_two_rust` ≈26–34 s, `dist_two_vm_wire` ≈0.4 s (37 tests; both VMs boot per case, so the figures move with host load).

## Cross-cutting conventions
* **A suite compiled into its own scratch directory is the only `-pa` either runtime gets.** The shared `tests/fixtures/` directory is never named as one, and each fixture is compiled or copied into a per-case directory holding only that module.
* **Byte-exact stdout probes pass `-noshell`** — except on the `run` action, which is **banner-free by construction**: `src/cli.rs`'s `parse_run_file` records the `noshell` init argument.
* **Three harness shapes, not one.** (a) a suite that compares against the system `erl` spawns it through `support::{require_oracle, resolve_oracle, oracle_eval, run_bounded}` or a file-local copy (the copies exist where the child's **exit code** must survive); (b) a suite that only needs `erlc` builds a fixture and compares against a pinned golden; (c) a suite with no toolchain drives `env!("CARGO_BIN_EXE_beam_rt")` or the in-process `Runtime`.
* **No suite compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory/0,1` value-for-value with the oracle.** The two oracle comparisons are `system_info_oracle.rs` (`system_info(garbage_collection)`, by value) and `runtime_hooks.rs` (`statistics(garbage_collection)`, by shape); every other GC suite reads the runtime's own `Runtime::gc_stats()`/`erlang:memory/1`.
* **A `beam_rt` node cannot render a remote identifier.** `pid_to_list/1` and `~p`/`~w` of an external pid or reference are typed capability gaps (exit 3, uncatchable), so the two-VM suites assert **term identity** (`=:=`, `is_pid`, a bound receive pattern), and `dist_two_vm_wire.rs` prints only ids it made up.
* **Two-VM fixture invariants are load-bearing**: every `receive` is deadline-bounded (a bare `receive` empties the run queue, the port set and the timer heap, so `run_scheduled` reports its honest `blocked`, exit 3, before the peer's term can arrive); the process that must die is a `spawn`ed child, never the run action's target; and our side never speaks first (an outbound send does not dial, `DistLinks::route_*` answers `no_link_error`).
* **The outbound monitor-down is always the plain `DOP_MONITOR_P_EXIT` (21)** form, never `DOP_PAYLOAD_MONITOR_P_EXIT`, even when the peer advertises `DFLAG_EXIT_PAYLOAD`.
* **The four `zlib` suites share one convention: six probe shapes, one golden** — `-eval` and the scheduled `run` route on both tiers, plus the oracle in both of its own shapes. Each is self-contained (a file-local oracle helper, so the probe's exit code and exact stdout survive) and compiles its source-only fixture into a per-fixture scratch directory.
* Interfaces every suite shares: `env!("CARGO_BIN_EXE_beam_rt")` (the built binary) and `support::{run_bounded, oracle_eval, require_oracle, skip_loudly, …}`.
* **An oracle probe must terminate**: the standard probe is `erl -noshell [-pa DIR] -eval EXPR -s init stop`, bounded through `support::run_bounded`/`support::PROBE_TIMEOUT` where the suite uses it.
* Scratch temp dirs come from `crate::context::test_support::scratch_dir(label)`; a hand-rolled `temp_dir().join(format!("…_{pid}"))` collides with a concurrent test *process*.

## Routing Table
One line per suite file: what it pins, and whether it needs the oracle (`erl`), a compiler (`erlc`/`cc`), or nothing beyond the built binary.

* `group_leader.rs` — group-leader inheritance, `group_leader/2` and the io-device default that follows it.
* `timers.rs` — the runtime timer heap behind `send_after`/`start_timer` (relative and `{abs,true}`) and `cancel_timer`.
* `read_timer.rs` — `erlang:read_timer/1,2` end to end (the hook `inet:timeout/1` needs): a live timer's remaining ms, `false` after it fires, and a read that is not a cancellation.
* `proc_seams.rs` — the `ProcessHook` seam behind the eleven process/name/global-state BIFs (`whereis`, `register`, `unregister`, `registered`, `is_process_alive`, `processes`, `ports`, `process_info`, `process_flag`, `group_leader`), nine of them served.

* `action_result.rs` — the action's returned term survives the action child's teardown, and the action leaves no process behind.
* `run_route_sleep.rs` — the `run` route's pass wait: no blocking wait while the round still ran slices, the anti-spin half for a parked `after T` (`pingpong.beam`).
* `boot_repeat.rs` — a second in-process `Runtime` boot must not run stale baseline-JIT compiled blocks.

### Inbound `-eval` route
The action's own process never becomes a scheduler slice: its `receive … after T` really waits through a mailbox scan, a non-blocking pump bounded by `RECEIVE_PUMP_SLICES = 64`, one port-poll slice and `Runtime::wait_for_timer`.
* `eval.rs` — the `-eval` evaluator against the differential corpus's `Eval` probes, pinning the golden values the corpus asserts.
* `eval_order.rs` — sub-expression evaluation order, oracle-cross-checked.
* `eval_bits.rs` — binary construction and matching in `-eval`: little-endian non-byte-aligned segments, `float`, `utf8/16/32`, wider-than-64-bit patterns and `unit:`.
* `bignum_bit_segment.rs` — both `<<…>>` implementations mask a bignum at **every** width: the `-eval` bit-buffer builder and the engine's `bs_create_bin`.
* `eval_region.rs` — the per-statement scratch window: a value held across twenty throwaway builds is never reclaimed (a `persistent_term` value, an environment binding, a mailbox message, and the family the descent cannot enumerate).
* `eval_pool_result.rs` — the BIF-result copy-out and pool rewind on the table-less route: a container used later prints correctly, a thousand calls stay at one call's high-water under `+hmax`, and one retained across sub-expressions survives.
* `eval_off_heap_reclaim.rs` — the escaped-payload store is pruned at each statement boundary, so an expression building `N` off-heap payloads holds `O(1)`.
* `eval_port_receive.rs` — a port frame drained by `-eval`'s `receive … after` lands in the owning mailbox rather than in the matcher, so non-matching frames survive for the next receive.
* `eval_spawn.rs` — a spawned `-eval` closure whose source was recorded is compiled into a synthetic `beam_rt_eval_fun_<index>` module, loaded with `code:load_binary/3` and run as a real `ProcessEntry::Export`, so it parks in a bare `receive` and in a nested `timer:sleep/1` and resumes on a message.
* `eval_exempt_receiver_signal.rs` — a `'DOWN'`/`'EXIT'` control signal aimed at the `-eval` route's relocation-exempt root, with a roomy and with a saturated nursery.
* `send.rs` — `erlang:send/2`/`erlang:'!'/2` over the `SendHook` seam (local, remote, port and alias destinations).
* `empty_binary_result.rs` — the `run` route prints an empty binary from both representations (an on-heap `<<>>` and an off-heap refc accumulator).
* `engine_off_heap_transport.rs` — a scheduled process's result and exit reason are copied off its dying heap with the refc payload handle resolved.

### Distribution (A.5)

## The off-heap refc-binary reclamation measurements (`off_heap_reclaim.rs`)
The measured shape behind the crate ledger's *engine's off-heap refc-binary reservoir is PRUNED at every pre-emption* bullet ([`../M1_GAPS_GC.md`](../M1_GAPS_GC.md) *GC / heap model* carries the mechanism's rates); every figure is a paired, deterministic measurement of this suite's own fixture, read with `/proc/loadavg` recorded around the run.

The cadence is the **pre-emption** cadence, not the park cadence: the call site is the runner's `Yield` arm (`src/runner/run.rs:1412`, whose gate `parked_published` is `!is_relocation_exempt()`), so a payload-building loop whose payloads land in the reservoir is bounded by the bin-vheap budget even when it never reaches a `receive` (measured: `4 144` bytes at N = 1 000 and `4 144` at N = 10 000 with 4 096-byte payloads; `65 584` / `65 584` at 65 536 B — one surviving payload, flat in N).
A **fun-loop** body's payloads are not in the reservoir at all — each lambda application is a nested `run_label_blocking` `Machine` whose reservoir is adopted into the runtime's escaped-payload store — so that store has its own two prune points (the next bullet), and the fun-loop envelope is a converged capacity: `377 104` bytes at both N = 1 000 and 10 000 with 4 096-byte payloads, `393 504` at both with 65 536-byte ones, against `4 144 000` → `41 440 000` and `65 584 000` → `655 840 000` without them.
Measured end to end by `tests/off_heap_reclaim.rs`, whose fixture's `discard(N, 4096)` builds and drops one 4096-byte engine-built off-heap payload per iteration and answers `erlang:memory(binary)` from the same process: **1 384 096** bytes at N = 1 000 and **2 747 472** at N = 10 000 (the 10× step adding 1 363 376, i.e. 1.30 MiB), against **4 144 000 → 41 440 000** with that one call site disabled — exactly `N × (4096 + 48)`, its 10× step adding 37 296 000 bytes (35.57 MiB) — with `VmHWM` **120.5 MiB** at N = 1 000 and **120.4 MiB** at N = 10 000 fixed against **121.8 → 158.8 MiB** in the A/B (the fixed figures are the runtime's constant boot cost; `/proc/loadavg` ≈ 22 on a shared host, deterministic across repeat runs).
The figure is a **sawtooth whose envelope does not move with N**: 10 000 iterations sampled every 1 000 answer `[1384096, 4144, 1392384, 12432, 1400672, 20720, 1408960, 29008, 1417248, 37296]` — a 1 417 248-byte peak (≈342 payloads) and a 4 144-byte trough (exactly one payload) — so the instantaneous value depends on where in the sawtooth it is sampled and the **envelope** is the invariant the suite asserts (bounded, never exact bytes); `retain(6000, 4096, 65536)` is the anti-dangle half, a 64 KiB payload surviving ~6 000 prunes **byte-exact** (md5, `=:=` a fresh rebuild, both ends) and still counted at 2 821 344 bytes while the churn around it is released.

## Notes for Agents
* **A `beam_rt` node cannot render a remote identifier.** `erlang:pid_to_list/1` of an external pid and `~p`/`~w` of an external pid or reference are typed capability gaps (`beam_bifs`' `external_channel_gap` → `error:unsupported_bif`, exit 3, and a capability gap is **uncatchable**, so a fixture's `try…catch` cannot rescue it). This is why the two-VM fixture never prints a pid/ref it did not mint, why `support/fixture.rs`'s `canonical_pid`/canonical-ref helpers normalize the peer's rendering instead, and why `dist_two_rust.rs` asserts term identity rather than text. `dist_two_vm_wire.rs` prints only ids it made up. A local identifier renders normally.
* **The two-VM fixture's invariants are load-bearing, not defensive**: every `receive` is deadline-bounded (a bare `receive` empties the run queue, the port set and the timer heap, so `run_scheduled` reports its honest `blocked`, exit 3, before the peer's term can arrive); the process that must die is a `spawn`ed child, never the run action's target (if the target exits, the runtime exits and the outbound `DOP_EXIT`/`DOP_MONITOR_P_EXIT` it just routed never reaches the socket); and our side never speaks first (an outbound send does not dial — `DistLinks::route_*` answers `no_link_error`), so the peer pings and greets `two_vm_peer` and retries on a bounded schedule because a `DOP_REG_SEND` to a not-yet-registered name is silently dropped (by the oracle too).
* **The outbound monitor-down is always the plain `DOP_MONITOR_P_EXIT` (21) form**, never `DOP_PAYLOAD_MONITOR_P_EXIT`, even when the peer advertises `DFLAG_EXIT_PAYLOAD` (`src/dist_client/client.rs::encode_signal`, the C's `erts_dsig_send_m_exit` at `dist.c:1497-1522`). That is a documented choice, so the payload form is deliberately unexercised by the wire suite.
* `scheduled_apply_seam.rs::a_scheduled_process_applies_a_blocking_closure_and_answers_the_oracle`, `eval_exempt_receiver_signal.rs::a_down_signal_reaches_the_eval_root_once_its_nursery_is_full` and `boot.rs::the_cli_boot_registers_a_live_logger_process` are **active passing pins** (the engine's `call_fun`/`call_ext erlang:apply/3` seams are live, `beam_process` carries a control signal to a relocation-exempt receiver through a heap fragment, and the boot suite drives the whole script — which boots to completion — before checking `logger`).
* Interfaces that all suites share: `env!("CARGO_BIN_EXE_beam_rt")` (the built binary) and `support::{run_bounded, oracle_eval, require_oracle, skip_loudly, ...}`.
* **Three harness shapes, not one.** (a) A suite that compares against the system `erl` spawns it — through `support::{require_oracle, resolve_oracle, oracle_eval, run_bounded}` or a file-local `oracle_eval`/`run_bounded`/`skip_loudly` copy (the local copies exist where the test needs the child's **exit code**, which `support::oracle_eval` folds away). The standard probe is `erl -noshell [-pa DIR] -eval EXPR -s init stop`, **bounded** (`support::PROBE_TIMEOUT`) only when it goes through `run_bounded*`; a bare `Command::new("erl").args(["-noshell","-eval",…]).output()` (`dist.rs`, `cli_flags.rs`, `cli_env.rs`, `boot.rs`, `nif.rs`, `driver.rs`, `system_info_oracle.rs`, `position.rs`) is **not** bounded and relies on the probe's own `halt(0).`/`-s init stop`. (b) A suite that only needs `erlc` as a compiler spawns it to build a fixture (no live comparison — the expected values are pinned goldens recorded from a prior oracle probe). (c) A suite with no system toolchain drives `env!("CARGO_BIN_EXE_beam_rt")` or the in-process `Runtime`/`RuntimeContext` and compares against hard-coded expected text. A missing toolchain is always a **loud** skip (`support::skip_loudly`/`require_oracle`, or a file-local `println!`/`eprintln!("SKIP …")` + `return`), never a silent pass; no suite `panic!`s on a *missing* toolchain (the local `run` helpers panic only when the **built binary** cannot run to completion).
* **A GC-counter comparison against the live oracle exists in exactly two places.** `system_info_oracle.rs` compares `system_info(garbage_collection)` for **value** against a live `erl` (`ORACLE_EQUAL_KEYS`); `runtime_hooks.rs` compares the `statistics(garbage_collection)` **shape** against a live `erl`. Every other GC suite (`gc_collect`, `gc_strategy`, `gc_immix_payload`, `heap_growth`, `persistent_term`, `garbage_collect`, `rss_bound`) reads only the runtime's own `Runtime::gc_stats()`/`erlang:memory/1`; the `support::require_oracle` call at their top gates the **system installation** (boot), not an oracle comparison. No suite compares `process_info(_, garbage_collection)` or `erlang:memory/0,1` value-for-value with the oracle (`process_info_items.rs` probes only the process-control items; `system_info(memory)` is in `SHAPE_ONLY_KEYS`).
* **A GC-accounting suite derives its bounds, never a pinned capacity.** `gc_collect.rs`'s nursery ceiling is `YOUNG_SHRINK_FACTOR × HeapPolicy::young_target_words(mature_capacity)` and its collection floor is `allocated / peak_capacity`; `heap_growth.rs` expects one collection per `peak_young_capacity / SPRAWL_WORDS` requests plus the settling one; `foreign_root_loop.rs` pins the 233-word `min_heap_size` floor and `rss_bound.rs` brackets a 10× `N` step against a 12 MiB slack. So a `beam_gc` sizing change moves them only through the policy arithmetic (`young_target_words(live) = next_words(2*live + need_reserve_words)`), and the two strategies are compared through their **allocation product**, `collections × mean sampled nursery capacity` — the young words the run's own heap doors admitted, within a derived 1 % (`gc_immix_payload.rs`) — rather than through their raw collection counts, because both feed the same quantity, a minor's exact promoted words, `GcStats::words_copied`, into the same nursery rule, while their minor/major mix differs: a minor sizes the nursery from the young live set once over, a fullsweep from the whole-heap live set twice over, and the mark-region minor escalates to a fullsweep on a line-granular would-not-fit check.
* **Byte-exact stdout probes pass `-noshell` — except on the `run` action.** Every CLI action but `-version` drives the default boot script, so on the ERTS-native actions — `-eval`, `-s`, `-run` and a bare shell — the booted kernel's `user`/`user_drv` prints the OTP slogan (`Erlang/OTP 30 [erts-17.1] [source] [64-bit]`) to stdout ahead of the action's own output unless the invocation is head-less; those probes pass `-noshell`, mirroring the oracle (which prints its own slogan plus an `Eshell` prompt without it). The `run <file.beam> Mod:Func/Arity` action is **banner-free by construction**: `src/cli.rs`'s `parse_run_file` records the `noshell` init argument, so a `run`-action assertion needs no `-noshell`.
* **The `process_info(P, binary)` roster is oracle-compared, shape-only, and the parked-child shapes are not in the suite.** `process_info_binary.rs` is the oracle-cross-checked suite for the **self** query (`self_payload/1` builds a 40 000-byte binary with compiled bitstring code and then asks for its own roster, the list form `[status, binary]` included), the empty row (`self_none/0`) and the other-pid row (`hold/1` + `probe/1`), reducing a roster to a canonical integer list (`[Count, IsPositiveInt, Size, Refc, …]`) because a payload pointer is an address: the oracle's rows are `[1,1,40000,1,40000]`, `[0]` and `[1,1,40000,1]`, and this runtime answers all three — the self row because the in-machine BIF door publishes the running slice's own roster (`src/context/position.rs::in_machine_off_heap_binaries`). Measured by hand on a parked child (a child that `binary:copy(<<0:2400>>)`-es a 300-byte payload — above the 64-byte on-heap limit — parks in `receive`, and its parent queries it, on the `run` route): (i) a payload a `beam_bifs` BIF built and one the target **received** through the copy engine are **absent** from the roster (`[]` where the oracle lists it), because nothing registers them, so one payload / the same payload stored twice / two payloads count **1/1/2** here against the oracle's **2/2/4**; (ii) a payload the program has **released** is listed by **both** sides in that shape — a child parked in a bare `receive` runs no collection and no prune, since the prune is the `Yield` arm's and the `Wait` arm parks under `ParkExemption::Always` and declines (`src/runner/run.rs`); a released payload does drop out once a slice-boundary prune really runs (`off_heap_reclaim.rs`). Neither is a gate mismatch: no corpus case asks for the item.
* **The four `zlib` suites share one convention: six probe shapes, one golden.** Each is self-contained — its own file-local oracle helper (`oracle`/`oracle_or_skip`, `theirs_eval`/`theirs_fixture`, `theirs_run`) mirroring `prim_tty.rs` rather than reaching into `support::oracle_eval`, so a probe's **exit code** and its exact stdout both survive — and every surface is probed in **six** shapes held against the same golden: `-eval` on the default and the interpreter tier, the scheduled `run` route on both tiers, and the oracle in both of its shapes (`erl -noshell -eval EXPR` and the oracle running the **same compiled fixture** under `-pa`). A tier or route divergence therefore fails by construction, and the golden is never a substitute for the oracle: both oracle shapes are asserted against it at run time. Fixtures are **source only** (`fixtures/zlib_stream.erl`, `fixtures/zlib_stream_levels_fixture.erl`, `fixtures/zlib_guards.erl`, `fixtures/zlib_guards_unnamed.erl`, `fixtures/zlib_one_shot_fixture.erl`), compiled at test time by the system `erlc` into a per-fixture scratch directory holding **only** that module (so it is also a safe single `-pa` for the oracle; `zlib_guards_unnamed.erl` needs its own directory or the named fixture's atoms would mask the defect), and a missing `erl`/`erlc` is a **loud** skip, never a silent pass.
