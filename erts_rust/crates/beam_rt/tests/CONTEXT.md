# `beam_rt/tests/` — runtime integration suites (the executable + the `Runtime` façade)

## Intent
Black-box and glue-level end-to-end tests for the `beam_rt` runtime binary and its `Runtime`/`RuntimeContext` façade.
Two drivers are used throughout, and they are NOT interchangeable:
* `Runtime::eval` / the CLI `-eval` action (`beam_rt -noshell -eval '<expr>'`) — the **single-pass** evaluator route; no scheduler slice.
* the CLI `run <file.beam> <mod>:<fun>/<arity> [args]` action (`Runtime::run_scheduled`) — a **scheduled process** on the real scheduler/poller/runner; also `runtime.run_function`/`run_module` (single-pass, `context.run_export`, caller-owned output sink).

Most suites run **both** runtimes (this one and the system `erl`/`erlc` oracle) and compare observable output; the oracle is the expected value. A missing toolchain is always a **loud skip**, never a silent pass (`support/mod.rs`). A missing **committed fixture** is the other class — a repository defect, not a toolchain absence — and **fails** (`mailbox_rescan.rs`'s `Scratch::new`, `bif_entry_spawn.rs`'s staging, `port_failure.rs`'s `require_probe_beam`/`the_probe_image_is_committed`, `live_inbound.rs`'s `the_fixture_beam_is_present`), because a skip there would report green rows that compared nothing.

## Running
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt [--test <suite>] [--no-fail-fast]`
(the sandbox `$HOME` is read-only — always go through the wrapper; the workspace manifest is `erts_rust/Cargo.toml`, never the repo root).
Suites that need the oracle skip **loudly** when `erl`/`erlc` are absent. `tests/fixtures/` must **never** be passed to the oracle as a single `-pa` (it holds a shadowing `lists.beam` — see below).
**Opt-in suites** are `#[ignore]`d and need `-- --ignored --nocapture` (they spawn whole VMs and take tens of seconds): the three **two-VM** files `dist_two_vm.rs` (rust ↔ real `erl`, 15 tests), `dist_two_rust.rs` (rust ↔ rust, 7 tests) and `dist_two_vm_wire.rs` (one hermetic byte-level test), plus the `#[ignore]`d measurement/corpus harnesses (`context::calls`, `context::gc_walk`, the A.9 sweeps, `dist_payload_matrix.rs`) and the one `#[ignore]`d residual case in `inet_nested.rs` (the `beam_io` accepted-socket arming gap).
**`--test` filtering does not build `examples/`**: `perf_bif.rs`/`perf_call.rs` drive the sibling `examples/perf_*` harness binaries and fail loudly when one is absent, so a chunked `--test <name>` run reports that as a missing example (`scripts/cargo.sh build --manifest-path erts_rust/Cargo.toml -p beam_rt --examples`), never as a runtime defect.
Run the pair suites **serially** (`--test-threads=1`): each test owns a private `epmd` and two VMs, so serial execution keeps a heavily loaded host from stretching the per-step bounds. `/usr/bin/time`-measured on an 8-core loaded host: `dist_two_vm` ≈32 s, `dist_two_rust` ≈20 s, `dist_two_vm_wire` ≈0.4 s (all 23 tests ≈54 s of test time, ≈86 s wall including both VM boots per case).

An in-process `Runtime` plus a test-side `beam_dist::ConnectionDriver::client` on a real socket: the peer monitors a local process (`DOP_MONITOR_P` carrying the peer's own reference), kills it (`DOP_EXIT2`), and the test **decodes the control bytes the runtime then wrote** — opcode **21** (`DOP_MONITOR_P_EXIT`), 5-element tuple, `terms[0]` the **watched** local pid (this node's name + creation, the dying process's num/serial), `terms[1]` the **watcher** peer pid, `terms[2]` the peer-minted reference echoed verbatim, `terms[3]` the reason — plus the negotiated `DFLAG` set (`0x6d07df7fbd`, including `DFLAG_HANDSHAKE_23`/`DFLAG_UNLINK_ID` and the rest of `dist.h`'s mandatory-26 set). The Erlang surface cannot disambiguate the two pid arguments nor the opcode, which is why this one assertion must be byte-level.

## The off-heap refc-binary reclamation measurements (`off_heap_reclaim.rs`)
The measured shape behind the crate ledger's *engine's off-heap refc-binary reservoir is PRUNED at every pre-emption* bullet ([`../M1_GAPS_GC.md`](../M1_GAPS_GC.md) *GC / heap model* carries the mechanism's rates); every figure is a paired, deterministic measurement of this suite's own fixture, read with `/proc/loadavg` recorded around the run.

The cadence is the **pre-emption** cadence, not the park cadence: the call site is the runner's `Yield` arm (`src/runner/run.rs:1214`, whose gate `parked_published` is `!is_relocation_exempt()`), so a payload-building loop whose payloads land in the reservoir is bounded by the bin-vheap budget even when it never reaches a `receive` (measured: `4 144` bytes at N = 1 000 and `4 144` at N = 10 000 with 4 096-byte payloads; `65 584` / `65 584` at 65 536 B — one surviving payload, flat in N).
A **fun-loop** body's payloads are not in the reservoir at all — each lambda application is a nested `run_label_blocking` `Machine` whose reservoir is adopted into the runtime's escaped-payload store — so that store has its own two prune points (the next bullet), and the fun-loop envelope is a converged capacity: `377 104` bytes at both N = 1 000 and 10 000 with 4 096-byte payloads, `393 504` at both with 65 536-byte ones, against `4 144 000` → `41 440 000` and `65 584 000` → `655 840 000` without them.
Measured end to end by `tests/off_heap_reclaim.rs`, whose fixture's `discard(N, 4096)` builds and drops one 4096-byte engine-built off-heap payload per iteration and answers `erlang:memory(binary)` from the same process: **1 384 096** bytes at N = 1 000 and **2 747 472** at N = 10 000 (the 10× step adding 1 363 376, i.e. 1.30 MiB), against **4 144 000 → 41 440 000** with that one call site disabled — exactly `N × (4096 + 48)`, its 10× step adding 37 296 000 bytes (35.57 MiB) — with `VmHWM` **120.5 MiB** at N = 1 000 and **120.4 MiB** at N = 10 000 fixed against **121.8 → 158.8 MiB** in the A/B (the fixed figures are the runtime's constant boot cost; `/proc/loadavg` ≈ 22 on a shared host, deterministic across repeat runs).
The figure is a **sawtooth whose envelope does not move with N**: 10 000 iterations sampled every 1 000 answer `[1384096, 4144, 1392384, 12432, 1400672, 20720, 1408960, 29008, 1417248, 37296]` — a 1 417 248-byte peak (≈342 payloads) and a 4 144-byte trough (exactly one payload) — so the instantaneous value depends on where in the sawtooth it is sampled and the **envelope** is the invariant the suite asserts (bounded, never exact bytes); `retain(6000, 4096, 65536)` is the anti-dangle half, a 64 KiB payload surviving ~6 000 prunes **byte-exact** (md5, `=:=` a fresh rebuild, both ends) and still counted at 2 821 344 bytes while the churn around it is released.

## Notes for Agents
* **A `beam_rt` node cannot render a remote identifier.** `erlang:pid_to_list/1` of an external pid and `~p`/`~w` of an external pid or reference are typed capability gaps (`beam_bifs`' `external_channel_gap` → `error:unsupported_bif`, exit 3, and a capability gap is **uncatchable**, so a fixture's `try…catch` cannot rescue it). This is why the two-VM fixture never prints a pid/ref it did not mint, why `support/fixture.rs`'s `canonical_pid`/canonical-ref helpers normalize the peer's rendering instead, and why `dist_two_rust.rs` asserts term identity rather than text. `dist_two_vm_wire.rs` prints only ids it made up. A local identifier renders normally.
* **The two-VM fixture's invariants are load-bearing, not defensive**: every `receive` is deadline-bounded (a bare `receive` empties the run queue, the port set and the timer heap, so `run_scheduled` reports its honest `blocked`, exit 3, before the peer's term can arrive); the process that must die is a `spawn`ed child, never the run action's target (if the target exits, the runtime exits and the outbound `DOP_EXIT`/`DOP_MONITOR_P_EXIT` it just routed never reaches the socket); and our side never speaks first (an outbound send does not dial — `DistLinks::route_*` answers `no_link_error`), so the peer pings and greets `two_vm_peer` and retries on a bounded schedule because a `DOP_REG_SEND` to a not-yet-registered name is silently dropped (by the oracle too).
* **The outbound monitor-down is always the plain `DOP_MONITOR_P_EXIT` (21) form**, never `DOP_PAYLOAD_MONITOR_P_EXIT`, even when the peer advertises `DFLAG_EXIT_PAYLOAD` (`src/dist_client/client.rs::encode_signal`, the C's `erts_dsig_send_m_exit` at `dist.c:1497-1522`). That is a documented choice, so the payload form is deliberately unexercised by the wire suite.
* `scheduled_apply_seam.rs::a_scheduled_process_applies_a_blocking_closure_and_answers_the_oracle`, `eval_exempt_receiver_signal.rs::a_down_signal_reaches_the_eval_root_once_its_nursery_is_full` and `boot.rs::the_cli_boot_registers_a_live_logger_process` are **active passing pins** (the engine's `call_fun`/`call_ext erlang:apply/3` seams are live, `beam_process` carries a control signal to a relocation-exempt receiver through a heap fragment, and the boot suite drives the whole script — which boots to completion — before checking `logger`).
* Interfaces that all suites share: `env!("CARGO_BIN_EXE_beam_rt")` (the built binary) and `support::{run_bounded, oracle_eval, require_oracle, skip_loudly, ...}`.
* **Three harness shapes, not one.** (a) A suite that compares against the system `erl` spawns it — through `support::{require_oracle, resolve_oracle, oracle_eval, run_bounded}` or a file-local `oracle_eval`/`run_bounded`/`skip_loudly` copy (the local copies exist where the test needs the child's **exit code**, which `support::oracle_eval` folds away). The standard probe is `erl -noshell [-pa DIR] -eval EXPR -s init stop`, **bounded** (`support::PROBE_TIMEOUT`) only when it goes through `run_bounded*`; a bare `Command::new("erl").args(["-noshell","-eval",…]).output()` (`dist.rs`, `cli_flags.rs`, `cli_env.rs`, `boot.rs`, `nif.rs`, `driver.rs`, `system_info_oracle.rs`, `position.rs`) is **not** bounded and relies on the probe's own `halt(0).`/`-s init stop`. (b) A suite that only needs `erlc` as a compiler spawns it to build a fixture (no live comparison — the expected values are pinned goldens recorded from a prior oracle probe). (c) A suite with no system toolchain drives `env!("CARGO_BIN_EXE_beam_rt")` or the in-process `Runtime`/`RuntimeContext` and compares against hard-coded expected text. A missing toolchain is always a **loud** skip (`support::skip_loudly`/`require_oracle`, or a file-local `println!`/`eprintln!("SKIP …")` + `return`), never a silent pass; no suite `panic!`s on a *missing* toolchain (the local `run` helpers panic only when the **built binary** cannot run to completion).
* **A GC-counter comparison against the live oracle exists in exactly two places.** `system_info_oracle.rs` compares `system_info(garbage_collection)` for **value** against a live `erl` (`ORACLE_EQUAL_KEYS`); `runtime_hooks.rs` compares the `statistics(garbage_collection)` **shape** against a live `erl`. Every other GC suite (`gc_collect`, `gc_strategy`, `gc_immix_payload`, `heap_growth`, `persistent_term`, `garbage_collect`, `rss_bound`) reads only the runtime's own `Runtime::gc_stats()`/`erlang:memory/1`; the `support::require_oracle` call at their top gates the **system installation** (boot), not an oracle comparison. No suite compares `process_info(_, garbage_collection)` or `erlang:memory/0,1` value-for-value with the oracle (`process_info_items.rs` probes only the process-control items; `system_info(memory)` is in `SHAPE_ONLY_KEYS`).
* **A GC-accounting suite derives its bounds, never a pinned capacity.** `gc_collect.rs`'s nursery ceiling is `YOUNG_SHRINK_FACTOR × HeapPolicy::young_target_words(mature_capacity)` and its collection floor is `allocated / peak_capacity`; `heap_growth.rs` expects one collection per `peak_young_capacity / SPRAWL_WORDS` requests plus the settling one; `foreign_root_loop.rs` pins the 233-word `min_heap_size` floor and `rss_bound.rs` brackets a 10× `N` step against a 12 MiB slack. So a `beam_gc` sizing change moves them only through the policy arithmetic (`young_target_words(live) = next_words(2*live + need_reserve_words)`), and the two strategies' cadences are compared with a tolerance (`gc_immix_payload.rs`) because the mark-region minor feeds a line-granular *upper* bound on the live set into that same rule.
* **Byte-exact stdout probes pass `-noshell` — except on the `run` action.** Every CLI action but `-version` drives the default boot script, so on the ERTS-native actions — `-eval`, `-s`, `-run` and a bare shell — the booted kernel's `user`/`user_drv` prints the OTP slogan (`Erlang/OTP 30 [erts-17.1] [source] [64-bit]`) to stdout ahead of the action's own output unless the invocation is head-less; those probes pass `-noshell`, mirroring the oracle (which prints its own slogan plus an `Eshell` prompt without it). The `run <file.beam> Mod:Func/Arity` action is **banner-free by construction**: `src/cli.rs`'s `parse_run_file` records the `noshell` init argument, so a `run`-action assertion needs no `-noshell`.
* **The `process_info(P, binary)` roster is oracle-compared, shape-only, and three measured divergences remain.** `process_info_binary.rs` is the oracle-cross-checked suite for the **self** query (`self_payload/1` builds a 40 000-byte binary with compiled bitstring code and then asks for its own roster, the list form `[status, binary]` included), the empty row (`self_none/0`) and the other-pid row (`hold/1` + `probe/1`), reducing a roster to a canonical integer list (`[Count, IsPositiveInt, Size, Refc, …]`) because a payload pointer is an address: the oracle's rows are `[1,1,40000,1,40000]`, `[0]` and `[1,1,40000,1]`. The **parked-child** probe (a child that `binary:copy(<<0:2400>>)`-es a 300-byte payload — above the 64-byte on-heap limit — parks in `receive`, and its parent queries it, on the `run` route) still differs in three shapes. (i) **Counting**: one payload / the same payload stored twice / two payloads ⇒ the oracle answers **2/2/4** entries, this runtime **1/1/2** (one entry per distinct payload). (ii) A payload the program has **released** can still be listed (`[{Ptr,300,1}]` where the oracle answers `[]`) in that shape — a child parked in a bare `receive`: the prune is the `Yield` arm's and the `Wait` arm declines (that window publishes no root set), so nothing prunes that reservoir while the child stays parked; a released payload **does** drop out once a slice-boundary prune really runs (a yielding process whose binary virtual heap is over its budget) — see `off_heap_reclaim.rs`. (iii) A payload the target **received** through the copy engine is **missing** (`[]` where the oracle lists it) — the `beam_message` handoff: nothing auto-registers a copy-engine payload. None of the three is a gate mismatch: no corpus case asks for the item.
* **The four `zlib` suites share one convention: six probe shapes, one golden.** Each is self-contained — its own file-local oracle helper (`oracle`/`oracle_or_skip`, `theirs_eval`/`theirs_fixture`, `theirs_run`) mirroring `prim_tty.rs` rather than reaching into `support::oracle_eval`, so a probe's **exit code** and its exact stdout both survive — and every surface is probed in **six** shapes held against the same golden: `-eval` on the default and the interpreter tier, the scheduled `run` route on both tiers, and the oracle in both of its shapes (`erl -noshell -eval EXPR` and the oracle running the **same compiled fixture** under `-pa`). A tier or route divergence therefore fails by construction, and the golden is never a substitute for the oracle: both oracle shapes are asserted against it at run time. Fixtures are **source only** (`fixtures/zlib_stream.erl`, `fixtures/zlib_stream_levels_fixture.erl`, `fixtures/zlib_guards.erl`, `fixtures/zlib_guards_unnamed.erl`, `fixtures/zlib_one_shot_fixture.erl`), compiled at test time by the system `erlc` into a per-fixture scratch directory holding **only** that module (so it is also a safe single `-pa` for the oracle; `zlib_guards_unnamed.erl` needs its own directory or the named fixture's atoms would mask the defect), and a missing `erl`/`erlc` is a **loud** skip, never a silent pass.
