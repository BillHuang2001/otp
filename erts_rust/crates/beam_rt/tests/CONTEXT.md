# `beam_rt/tests/` — runtime integration suites (the executable + the `Runtime` façade)

## Intent
Black-box and glue-level end-to-end tests for the `beam_rt` runtime binary and its `Runtime`/`RuntimeContext` façade.
Two drivers are used throughout, and they are NOT interchangeable:
* `Runtime::eval` / the CLI `-eval` action (`beam_rt -noshell -eval '<expr>'`) — the **single-pass** evaluator route; no scheduler slice.
* the CLI `run <file.beam> <mod>:<fun>/<arity> [args]` action (`Runtime::run_scheduled`) — a **scheduled process** on the real scheduler/poller/runner; also `runtime.run_function`/`run_module` (single-pass, `context.run_export`, caller-owned output sink).

Most suites run **both** runtimes (this one and the system `erl`/`erlc` oracle) and compare observable output; the oracle is the expected value. A missing toolchain is always a **loud skip**, never a silent pass (`support/mod.rs`).

## Running
`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt [--test <suite>] [--no-fail-fast]`
(the sandbox `$HOME` is read-only — always go through the wrapper; the workspace manifest is `erts_rust/Cargo.toml`, never the repo root).
Suites that need the oracle skip **loudly** when `erl`/`erlc` are absent. `tests/fixtures/` must **never** be passed to the oracle as a single `-pa` (it holds a shadowing `lists.beam` — see below).

## File I/O coverage (current state)
The **read** path is exercised on both routes; the **write** path is exercised in-process:
* `file_server.rs` (`Runtime::eval`, single-pass `-eval` route): `file:read_file/1` returns the bytes (`reading_an_existing_file_returns_its_bytes`), `file:open(P,[read])` on a missing path ⇒ `{error,enoent}` / on a directory ⇒ `{error,eisdir}`, `file:list_dir/1`, `filelib:is_dir|is_file|is_regular/wildcard` (absent path ⇒ `false`/`[]` agree with the oracle; an **existing** path ⇒ `true` via `beam_io::fs_access`).
* `io_scan.rs`: the `-eval`-route reads (`file:read/2`, `io:scan_erl_exprs/4`, `io:parse_erl_exprs/4`, the `dflag_unicode_io/1` probe) **and** the **buffered-read sequences** — a test-time-compiled `ioseq` fixture whose `file:read/2` is interleaved with `file:read_line/1` and `file:position/2` (bare `cur` and `{cur, N}`), plus an `eof` control. Each sequence line is asserted three-way equal to a pinned value on the **scheduled** `run` route, the **pumped** `-eval` route and the live oracle, so a divergence confined to one route is a mismatch.
* `scheduled_io_device.rs`: a **scheduled** process completes io-device round trips (`io:getopts/1`, `io:setopts/2`, `io:scan_erl_form/4`), each line oracle-cross-checked.
* The **write path** runs in-process through `compile_file.rs`: `compile:file/2` writes its artifact via the native `file_server_2` (write-mode `file:open/2` + the `{put_chars,Enc,Chars}` io-device request reaching `std::fs::File::write_all`). A **direct** write-mode open / `file:write/2` probe is not driven separately.

## Application-level call chains (current state)
`compile_file.rs` drives the real `compiler` application in-process (`compile:forms/2` and `compile:file/2`); no test drives `syntax_tools`, `eunit`, `xref`, `dialyzer` or `edoc`. The other deepest chains exercised are:
* `proc_lib_start.rs` — `run` action, `proc_lib:start[_link]/4` → `proc_lib:sync_start/2` (a different kernel module), oracle `{ok,pid}`.
* `multimodule.rs` — single-pass `run_function`/`run_module`: a compiled fixture calling `lists:reverse/1`, `maps:get/2`, `ordsets:from_list|to_list/1` (a real stdlib module loaded on demand) and `binary:part/3`.
* `io_scan.rs` — the `{get_until,…}` io-device request drives the real `erl_scan:tokens/4` (and `erl_parse` via `io:parse_erl_exprs/4`) on the engine.
* `boot.rs` — the real `bootstrap/bin/start.boot` chain, which boots **all 22** directives to completion (ending at the final `{progress,started}`, index 21) with CLI `-boot` exit **0** and empty stdout/stderr.
* The drive is the CLI's boot-script drive, which **every** CLI action except `-version` performs (not only `-boot`): the script is the explicit `-boot FILE` value when given, else the literal default `start` (`src/cli.rs::DEFAULT_BOOT_SCRIPT`), resolved to `<Root>/bin/start.boot`.
* On a plain `-eval`/`run` route the resolved script is therefore the **installation's own** `bin/start.boot`, not this repo's committed `bootstrap/bin/start.boot`.
* Directive 20 `{apply,{c,erlangrc,[]}}` — the call that loads `c.beam` and reaches `file:open($HOME/.erlang,[read])` through the booted `kernel_sup`'s own `file_server_2` child — is reached and answered.
* `a9_native_floor.rs`'s `init:script_id/0` coverage reports the **loaded** script's real header on the CLI routes, because the script is loaded before the action's own start instruction runs.

## Distribution (A.5) evidence
The routing half is pinned hermetically by `dist_delivery.rs` and the live half by four peer suites against a real `erl`; `dist.rs`, `node_cookie.rs` and `pid_roundtrip.rs` cover the accepting (listener) boundary, the cookie and the pid wire round trip.
* `dist_delivery.rs` (31 tests). Every test in the file's first part is **hermetic**: a client and a server `ConnectionDriver` are wired to each other and the client's `ConnectionDriver::take_output` bytes are shuttled by hand, so no socket, no `epmd` and no system `erl` is needed; the last one drives a real loopback TCP link into a running runtime through the scheduler pass (still hermetic).
  * The ordinary message families are asserted by their delivered effect: `DOP_SEND` into the addressed local mailbox (`an_inbound_send_reaches_the_addressed_local_mailbox`), `DOP_REG_SEND` to a registered name (`an_inbound_reg_send_reaches_a_registered_name`), an unknown name (`an_unknown_registered_name_is_no_such_process`), a pid on another node or incarnation (`a_pid_on_another_node_is_no_such_process_and_never_mis_delivered`) and a wire-borne reference alias (`an_alias_send_to_a_wire_borne_reference_is_unsupported_not_a_wrong_delivery`).
  * The wire-borne `Link`/`Exit` families are applied through a real wire (`the_routed_link_and_exit_families_are_applied_through_the_wire`); the inbound gate is on by default and toggleable (`inbound_routing_is_on_by_default_and_toggleable`, `a_nodeless_runtime_still_reports_no_inbound_traffic`); a real loopback link delivers through the scheduler pass (`a_real_loopback_link_delivers_through_the_scheduler_pass`).
  * A malformed control message and a forged `Link` from a third node each retire exactly their own link (`a_malformed_inbound_reg_send_is_refused_and_retires_its_link`, `a_forged_inbound_link_from_a_third_node_retires_its_link`) — the per-link **checked** drain (`Delivery::classify_validated` against that link's own `LinkIdentity`), never a wrong delivery.
  * The `(7)` group drives synthetic `Delivery` values straight into the public `LocalDeliverySink` over a standalone `ProcessTable`, pinning the routing table one family at a time: the ordinary families by mailbox delivery, and the **route-free receipt** families by the local state they install — `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref`/`demonitor_from_remote_ref`, `remote_monitor_down` and `set_group_leader_from_remote`.
  * `every_routed_inbound_family_routes_nothing_outbound` drives all **10** routed families (`Link`, `Exit`, `Link`, `UnlinkId` with `id == 0`, `UnlinkIdAck`, `Exit2`, `Monitor`, `Demonitor`, `MonitorExit`, `GroupLeader`) through a recording `DistSignalRouter` and asserts the log stays empty, so a receipt family installs (or drops) its local record and echoes **no** outbound `DOP_*`.
  * `every_unrouted_family_is_the_honest_unsupported` asserts **3** rows — the distributed-spawn family's `SpawnRequest` and `SpawnReply`, plus `Delivery::Other(Dop::Unlink)`, the one `DOP_*` recognised on the wire but refused outright (`dist.c:2277-2282`) — each `DeliveryOutcome::Unsupported` with an empty mailbox, so a future change must flip a row on purpose rather than by accident; the `UnlinkId` `id != 0` ack-owing half is its own case (`an_inbound_unlink_id_without_an_ack_is_delivered_and_one_owing_an_ack_is_unsupported`), as are a monitor DOWN for this node's own outgoing reference (`a_monitor_down_for_our_own_outgoing_reference_fires_or_is_dropped`), an out-of-contract signal (`an_out_of_contract_signal_is_unsupported_not_substituted`), an `AltactSig` priority/exit form (`an_altact_sig_priority_or_exit_signal_is_unsupported`) and an unowned reference or non-ref target (`an_unowned_reference_is_dropped_and_a_non_ref_target_is_unsupported`).
* `dist_client.rs` (1 test): the **connecting** half against a real `erl -sname` peer — the runtime resolves the peer through `epmd`, drives the client side of the `'N'` handshake to `Established` (`Runtime::dist_connect`) and carries a real `DOP_REG_SEND` to a registered process on the peer (`Runtime::dist_send_reg_send`), asserted on the peer's own stdout rather than on this runtime's belief about what it sent.
* `live_inbound.rs` (3 tests): a real `erl` peer `DOP_REG_SEND`s into a **running local process** (`a_real_erl_peer_reg_sends_into_a_running_local_process`) and the same over the CLI boundary (`the_cli_node_receives_an_inbound_reg_send_from_a_real_erl_peer`, guarded by `the_fixture_beam_is_present`); the assertion is on the delivered term (the in-process return value, or the CLI `run` action's `~w~n`), never on a belief about what a peer sent.
  The committed fixture `dist_echo:wait/0`'s `after 20` loop is **load-bearing**: a bare `receive` with no deadline leaves the scheduler quiescent (an empty run queue, nothing to poll, no pending timer), so `Runtime::run_scheduled` stops with its honest `blocked` diagnostic before the peer's message can arrive, whereas each arm's re-armed deadline keeps a pass stepping so the distribution half (`pump_dist`) keeps polling for the inbound connection and message.
* `live_signals.rs` (3 tests): the **outbound signal** path against a real peer — the real `erlang:link/1` front door routes `DOP_LINK` and the router routes `DOP_EXIT` for the same pair to a real OTP node whose trapping process prints `LINKEXIT` (`a_bif_link_and_exit_reach_a_real_erl_peer`), the runtime-installed `beam_process::DistSignalRouter` seam keeps its own live proof (`a_router_routed_link_and_exit_reach_a_real_erl_peer`), and the byte-identical peer session with the link step skipped reports `NOLINKEXIT` as the real **negative control** (`without_the_link_the_exit_is_not_delivered`), which is what makes the `LINKEXIT` observation non-vacuous.
* `net_adm.rs` (1 live test): the connector BIFs (`net_adm`/`net_kernel` on a real peer) over a live peer (`the_connector_bifs_reach_a_real_peer`).
* `remote_send.rs` (8 tests): the non-node regression (`a_remote_name_destination_is_the_typed_capability_gap_on_a_plain_runtime`, `a_remote_pid_destination_is_refused_on_a_plain_runtime`), a malformed or unregistered destination (`a_malformed_or_unregistered_destination_is_badarg`), the **three-routes-agree** check — the compiled `Dest ! Msg`, the `erlang:send/2` BIF and the `-eval` `!` — over a remote name pair (`the_compiled_bang_the_bif_and_the_eval_send_agree_on_a_remote_name_pair`), the same-node arm (`a_same_node_name_pair_is_a_local_named_send`, `a_same_node_pair_with_an_unregistered_name_is_accepted_and_dropped`), and the live half: a compiled `{Name, PeerNode} ! Msg` delivered to a real peer and asserted on that peer's **stdout** (`a_compiled_bang_delivers_a_remote_name_destination_to_a_real_peer`), with `without_a_node_the_same_tuple_is_refused_and_nothing_is_delivered` as its negative control.
* The peer-less loopback that wires the outbound distribution client into the runtime's scheduler pass lives in the sibling module `src/runtime/scheduler/tests.rs::the_outbound_distribution_client_is_wired_and_driven_by_the_runtime`.

## Notes for Agents
* `scheduled_apply_seam.rs::a_scheduled_process_applies_a_blocking_closure_and_answers_the_oracle` and `eval_exempt_receiver_signal.rs::a_down_signal_reaches_the_eval_root_once_its_nursery_is_full` are **active** positive pins (the engine's `call_fun`/`call_ext erlang:apply/3` seams are closed, and `beam_process` carries a control signal to a relocation-exempt receiver through a heap fragment). `boot.rs::the_cli_boot_registers_a_live_logger_process` is an **active** passing pin: it drives the whole script (which boots to completion) before checking `logger`.
* Interfaces that all suites share: `env!("CARGO_BIN_EXE_beam_rt")` (the built binary) and `support::{run_bounded, oracle_eval, require_oracle, skip_loudly, ...}`.
* **Three harness shapes, not one.** (a) A suite that compares against the system `erl` spawns it — through `support::{require_oracle, resolve_oracle, oracle_eval, run_bounded}` or a file-local `oracle_eval`/`run_bounded`/`skip_loudly` copy (the local copies exist where the test needs the child's **exit code**, which `support::oracle_eval` folds away). The standard probe is `erl -noshell [-pa DIR] -eval EXPR -s init stop`, **bounded** (`support::PROBE_TIMEOUT`) only when it goes through `run_bounded*`; a bare `Command::new("erl").args(["-noshell","-eval",…]).output()` (`dist.rs`, `cli_flags.rs`, `cli_env.rs`, `boot.rs`, `nif.rs`, `driver.rs`, `system_info_oracle.rs`, `position.rs`) is **not** bounded and relies on the probe's own `halt(0).`/`-s init stop`. (b) A suite that only needs `erlc` as a compiler spawns it to build a fixture (no live comparison — the expected values are pinned goldens recorded from a prior oracle probe). (c) A suite with no system toolchain drives `env!("CARGO_BIN_EXE_beam_rt")` or the in-process `Runtime`/`RuntimeContext` and compares against hard-coded expected text. A missing toolchain is always a **loud** skip (`support::skip_loudly`/`require_oracle`, or a file-local `println!`/`eprintln!("SKIP …")` + `return`), never a silent pass; no suite `panic!`s on a *missing* toolchain (the local `run` helpers panic only when the **built binary** cannot run to completion).
* **A GC-counter comparison against the live oracle exists in exactly two places.** `system_info_oracle.rs` compares `system_info(garbage_collection)` for **value** against a live `erl` (`ORACLE_EQUAL_KEYS`); `runtime_hooks.rs` compares the `statistics(garbage_collection)` **shape** against a live `erl`. Every other GC suite (`gc_collect`, `gc_strategy`, `gc_immix_payload`, `heap_growth`, `persistent_term`, `garbage_collect`, `rss_bound`) reads only the runtime's own `Runtime::gc_stats()`/`erlang:memory/1`; the `support::require_oracle` call at their top gates the **system installation** (boot), not an oracle comparison. No suite compares `process_info(_, garbage_collection)` or `erlang:memory/0,1` value-for-value with the oracle (`process_info_items.rs` probes only the process-control items; `system_info(memory)` is in `SHAPE_ONLY_KEYS`).
* **Byte-exact stdout probes pass `-noshell` — except on the `run` action.** Every CLI action but `-version` drives the default boot script, so on the ERTS-native actions — `-eval`, `-s`, `-run` and a bare shell — the booted kernel's `user`/`user_drv` prints the OTP slogan (`Erlang/OTP 30 [erts-17.1] [source] [64-bit]`) to stdout ahead of the action's own output unless the invocation is head-less; those probes pass `-noshell`, mirroring the oracle (which prints its own slogan plus an `Eshell` prompt without it). The `run <file.beam> Mod:Func/Arity` action is **banner-free by construction**: `src/cli.rs`'s `parse_run_file` records the `noshell` init argument, so a `run`-action assertion needs no `-noshell`.
