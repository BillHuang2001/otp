# `beam_rt` — M1 gap ledger, contract A.4 (ports, drivers, the send family)
The A.4 half of the gap ledger in [`M1_GAPS.md`](M1_GAPS.md): the port/driver surface, its residuals and the send family's shapes.
Every entry is a typed capability gap or a measured own-state difference — never a wrong result.

## Ports, drivers and the send family (A.4)
Read path: one `{Port, {data, Data}}` per driver read, at the width the child wrote (`binary`→up to `beam_io`'s `READ_CHUNK`, 64 KiB, per `read(2)`; `list`→char list); child stderr is inherited by default (never port data) while `stderr_to_stdout` duplicates fd 2 onto fd 1 so its diagnostics arrive as port data in true write order.
A read's `Data` is shaped by the driver call's **own** `hbuf`/`buf` split, which `beam_io`'s `ReadMessage` carries: a `[binary]` port delivers the bare binary for a header-less read, `[H1..Hh|<<Body>>]` when the call carried both halves (an empty body ⇒ `[…|<<>>]`), the proper `[H1..Hh]` for a `NULL` body and `[]` for a read of nothing; a `[list]` port gets every byte flat.
A `dlopen`ed driver's split reaches the owner intact (`DriverHost::output2` records both halves, `DriverContext::deliver_read` carries them as one read, `StreamShape::Data` renders it), so `[72,68,82|<<"abc">>]` is oracle-identical.
A **built-in** driver port's reads carry the C's split wherever its driver states one: `ram_file_drv` hands its reply up through `beam_io`'s `DriverContext::deliver_read` (`beam_io/src/drivers/ram_file.rs:477`), one read per `driver_output*` call, so its whole reply matrix is the oracle's terms on both streams — the improper `[2,0,0,0,2|<<97,98>>]` on a `[binary]` port, the flat `[2,0,0,0,2,97,98]` on a `[list]` one, and proper lists for `OK`/`NUMBER`/`ERROR` (`ram_file_drv.c:181-230` `driver_output2(hbuf,len,NULL,0)`, `:448-489` `driver_output_binary`).
A **header-less** read of a built-in driver port reports `StreamShape::DriverOutput` and renders as list elements on either stream — exact for `ram_file_drv`'s header-only replies, and the residual for the two in-tree producers still on `beam_io`'s flat `DriverContext::input` sink, `tcp_inet`'s and `udp_inet`'s passive `recv` verb (`beam_io/src/drivers/inet/{async,udp}.rs`), whose body-only payload arrives as list elements where the C answers a binary on a `[binary]` port.
Two read residuals: a frame's derived **header prefix** never reaches the input counters — the C charges a call's `hlen` once per `driver_output*` call (`io.c:6403`) while `beam_io` stamps that call's header on every frame it produced and this node charges each frame's **content** bytes only (`src/port.rs`, the `take_line_notifications` arm), so one `driver_output2("HDR",3,"ab\ncd\nef",8)` on a `[binary,line]` port answers `input` 4 here against the oracle's 11 (the two frames' bytes are byte-identical); and a **raw**-mode read of nothing (`driver_output(NULL,0)`) is dropped where the oracle delivers `{Port,{data,[]}}` — a proper empty list even on a `[binary]` port — because `src/port.rs::fold_notifications` skips `ReadMessage::is_empty` (a read of nothing in **line** mode is silent on both sides).
Detail: [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
`{spawn_driver, Name}` resolves the name against the emulator's **static** driver set (`beam_io::STATIC_SPAWN_DRIVERS`: `tcp_inet`/`udp_inet`/`ram_file_drv`) before any `dlopen`, as the C does (`io.c:599-628`) — `fd`/`efile` (this crate's internal drivers) and an invented name are `badarg` exactly as on the oracle — then the loaded-driver list and the object-path search.
A driver port's `driver_output` reaches its owner as `{Port, {data, Data}}`, and a driver-emitted `erl_drv_output_term`/`erl_drv_send_term` term reaches the connected process or an explicit destination (`TermQueue` drain); an `ERL_DRV_PORT` operand of either resolves through `DriverHost::port_term` to this host's own live internal port term (an unknown or gone handle answers `None`, which `beam_abi` renders `-1` — never a fabricated port).
A driver that closes its **own** port (`driver_failure*`, `driver_exit`) is a port-closing request, not a return value: `beam_io` latches it from inside the callback, runs its own teardown and queues the term-free `PortFailure`, which `PortRegistry::take_failures` hands to `src/port/failure.rs` at every driver-callback drain point — behind the one `src/port/completion.rs::drain_io_completions` call the completion channel already uses, so the channel needs no drain site of its own.
`src/port/failure.rs::fail_port` runs `PortRegistry::close`'s bookkeeping minus the two steps `beam_io` already performed, so the owner and every monitor get the failure's **own** reason: `normal` for `driver_failure_eof`/`driver_failure(P,0)`, the driver's atom name (`driver_failure_atom(P,"boom")` ⇒ `boom`), the POSIX name (`driver_failure_posix(P,EACCES)` ⇒ `eacces`) or a bare integer (`driver_failure(P,7)` ⇒ `7`).
`driver_exit` (which unlinks first, `io.c:7244`) sends the linked owner **nothing** while every monitor still gets its `'DOWN'`; only `normal` leaves a non-trapping owner alive, any other reason terminating it.
A read the failing callback wrote first is delivered **before** the exit (from the recipient snapshot `fail_port` records, consumed once and cleared on a recycled number), and the failed port is as gone as a closed one (`port_info/1` ⇒ `undefined`, `port_close/1` ⇒ `error:badarg`).
Pinned by `tests/port_failure.rs` (10 tests across both delivery routes, 9 of them oracle-cross-checked, the tenth guarding the committed probe image) and `src/port/failure_e2e_tests.rs` (one row per oracle opcode).
Residual: a non-UTF-8 `driver_failure_atom` name (`beam_abi` answers `-1`; the seam's reason is a `String`).
The driver C ABI is live for 35 of the 45 `DriverHost` hooks — `driver_select`, `driver_set_timer`, the `OUTPUT` port task (drain through the single write path, then `ready_output`), `control`, `ERL_DRV_USE`'s `stop_select`, the driver-private queue (`driver_enq`/`pushq`/`deq`/`sizeq`/`peekq`), `driver_pdl_create`, the port state flags (`get_port_flags`/`set_control_flags`), the C async-job pool (`async_pool`), the `ERL_DRV_PORT` resolution (`port_term`) and the process-monitor family (`driver_monitor_process`/`_demonitor_process`/`_get_monitored_process`, `monitor_process_result` answering three-way from the published `ProcessLiveness` view); the other 10 keep the frozen trait default; per-hook contract: [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
The C async-job pool is driven end to end (`driver_async` returns the positive job id, or `0` for `+A 0`'s in-line run; the port round drains the pool, each port's drive point calls the driver's `ready_async` or its `async_free`, and a port closed with jobs in flight keeps its library mapped until they are gone — see `src/port/CONTEXT.md`).
Typed gaps: `driver_async_port_key` (`async_port_key` keeps the trait default, so the C ABI function answers its own `0` — `beam_abi/src/driver/drv/lifecycle.rs:540-548` — and never a derived fair key); a `control` reply answered from the driver's own memory (needs a safe copy helper on `beam_abi`); a driver arming more than one registration per direction (typed `unsupported`).
`erlang:port_control/3` is gated on the **driver's own** `control` callback (`PortMeta::has_driver_control` = `beam_io::Driver::has_control()`, captured when the port opens; no driver-name table): a driver with none — and every internal `spawn`/`spawn_executable`/`fd` port — is the oracle's `error:badarg` for every verb (the C's `prt->drv_ptr->control != NULL`, `io.c:4035`).
`{exit_status, N}` cannot exist for a driver port, so it is not a gap: the only reporter is the emulator-internal `driver_report_exit` (`erts/emulator/beam/io.c:5554`), which `erl_driver.h` does not declare, so `beam_io::Driver::take_exit_status` answering `Ok(None)` is the complete truth and `open_port` refuses `[exit_status]` for any port whose name resolves to a registered driver — `{spawn, Name}` and `{spawn_driver, Name}` alike — with the oracle's `badarg` before a port id is consumed (`io.c:625-628`).
`port_info(Port, os_pid)` follows the driver's own `erl_drv_set_os_pid` and is `undefined` until the driver calls it (`io.c:2971`, `io.c:386`), exactly as the oracle answers.
`stderr_to_stdout` is accepted and inert for a driver port on the oracle (it only requires `use_stdio`, which defaults true), which is what this runtime does; the `{spawn_driver, …}` merge itself already works.
The numeric→named `inet` control-opcode bridge (`beam_io`) is adopted end to end: nine datagram/option/`recv`/`send`/`close`/accept/interface/name-service families through `erlang:port_control/3` agree byte-for-byte with the oracle (`src/port/inet_matrix_tests.rs`).
`PACKET_REQ_RECV`'s asynchronous receive slot is an ordinary agreement row: its op id is `[1] ++ <<Id:16/big>>` on both runtimes (`the_datagram_async_receive_slot_matches_the_oracle`).
A `{inet_async, …}` completion also reaches a **nested** caller — the `-eval`/`-s`/`-run`/boot route, which owns the pass but is not a scheduled process — because such a `receive` is sat out by `RuntimeContext::wait_for_port_event` (and by the `-eval` bare receive's port branch) over the blocking pass, bounded by `PORT_EVENT_DEADLINE`: `src/port/CONTEXT.md` *The nested port wait*.
On that route `gen_tcp:accept/1,2` ⇒ `{ok, Port}`, a passive `gen_tcp:recv/2,3` whose data arrives after the read is armed ⇒ `{ok, Data}` (an accepted socket and a connect-side one), `gen_tcp:shutdown/2` ⇒ `ok`, and `gen_tcp:connect/2,3,4` plus a passive receive against an external server ⇒ `{ok, Data}` all agree with the oracle; an `accept` with no client ends in the typed `unsupported: port event: … within the 5 s bound` (exit 3) rather than a hang.
Residual, `beam_io`-owned and a **divergence** rather than a typed gap: a passive read on an **accepted** socket whose data was buffered before the read op was armed produces no port event, so the wait ends only at the peer's close and answers `{error,closed}` where the oracle answers `{ok, Data}` (the connect-side socket with the same pre-buffered data answers `{ok, Data}`).
Residual shapes stay typed with the oracle's answer beside them: an `INET_REQ_OPEN` of a non-`AF_INET` family (oracle `[1]`, here `[0]eafnosupport`) and `INET_REQ_FDOPEN`(13) on a port that already holds a socket (oracle `[1]`, here `[0]einval` — the C overwrites `desc->s` and leaks the live socket, `inet_drv.c:5242-5251`), both pinned with their oracle columns by `src/port/inet_matrix_tests.rs::the_documented_datagram_residuals_stay_typed`; `INET_REQ_IGNOREFD`(28) and `TCP_REQ_SENDFILE`(45) are typed refusals on a *connected* stream (`beam_io`'s `drivers/inet/mod.rs`), while a listener-state probe of both is an ordinary oracle-compared row (`[0]enotconn`, their `IS_CONNECTED` guard).
`{packet, N}` framing (`N ∈ {1,2,4}`; anything else `badarg`, `stream` cancels, `line`+`packet` `badarg`) and `line`/`{line, N}` framing (bare `line` ⇒ `512`; mutually exclusive with `{packet, N}` and with `stderr_to_stdout` unless `use_stdio`) are adopted end to end for the `spawn`/`spawn_executable`/`fd` family (`src/port/packet.rs`, `src/port.rs`), the port flags reporting line vs binary independently; a **driver** port is not framed by the emulator (its `packet` option belongs to the driver), matching the oracle, and `{packet,1}` over 255 bytes / `{packet,2}` over 65535 are the typed `unsupported` gaps where the C kills the port with `einval`.
`erl_ddll` is served (A.4) from one loaded-driver view (`src/native/ddll.rs` over the registry `src/port/driver.rs` keeps — the same list `open_port({spawn_driver, Name})` resolves against, `Name` doubling as the object-path/`<name>.so` search): `loaded_drivers/0` lists the three static built-ins first, then the dynamically loaded names in load order, a static name's `try_load`/`try_unload` answer `{error,linked_in_driver}`, and `monitor/2`/`demonitor/1`/`format_error/1` fall through to `beam_bifs`.
Ports match the oracle's observable shape (one `{Port,{data,Data}}` per driver read at the width the child wrote — *Read path* above — and `connected` false only at `port_close/1`), the `line`/`{line,N}` stream option is adopted end to end, and `port_command/2,3` runs `beam_io`'s decision table (`erl_bif_port.c:168-235`, `io.c:1731/1763-1769`): `[force]` refused as `notsup` without the driver's `SOFT_BUSY`, honoured with it, a busy port blocking the caller (or `false` for `[nosuspend]` with nothing queued), and the busy/`[force]` test taken **before** the iodata is converted, as the C does.
A socket's `{active, true|N|once}` input is delivered as the oracle's own messages — `{tcp,S,Data}` / `{udp,S,{A,B,C,D},Port,Data}` / `{tcp_passive,S}` / `{udp_passive,S}` / `{tcp_closed,S}` / `{tcp_error,S,Reason}`, `Data` binary or charlist per the port's effective `mode`, the `{packet,N}` header stripped and the datagram source decoded big-endian out of `beam_io`'s packed address — to the **owning** process through `beam_io::PortRegistry::take_active_inputs`, drained at the same six points as the completion channel and delivered through the ordinary mailbox path (so a blocked receiver is woken).
An **accepted** socket inherits the listener's option block (`{packet,…}`/`{packet_size,…}`/`{header,…}`/`{mode,…}`/watermarks/…) by **struct copy** inside the driver — `PortRegistry::driver_as::<TcpInetDriver>(listener)` → `TcpInetDriver::from_accepted(fd, listener)`, the C's own `tcp_inet_copy` route, with no `port_control` replay — while `{active,…}` is left to `prim_inet:accept_opts/3` exactly as the C does.
The send family serves `erlang:send/2,3` and `erlang:'!'/2` (`SendBridge`) to a **local** pid / registered name / alias reference, to a remote pid, a remote `{Name, Node}` and a remote alias (*Distribution and the node (A.5)*, [`M1_GAPS.md`](M1_GAPS.md)), and to a **port** (`SendDestination::Port`, one classifier shared with the compiled `Dest ! Msg` instruction and the `-eval` `!` operator).
The BIF route cannot see the sending machine's in-flight refc-binary handles, so a term the machine *just* built off-heap **flattens** ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC / heap model*).
The port arm is the C's `do_send`/`port_common` block (`bif.c:2551-2613`), which does **not** write the message: it hands it to `erts_port_command` (`io.c:3981-4013`), which recognises `{InternalPid, {command, Data}}` (a write) and `{InternalPid, close}` (a close) and treats **everything else as a bad port signal** — logged and dropped, with the send reporting success.
So a plain payload (`P ! <<"a">>`) writes nothing and answers the message, a dead port id answers the message, and non-iodata `Data` answers the message — all verified against the oracle, none of them `badarg` (`badarg` is `port_command`'s answer for a dead port and for non-iodata); `erlang:send/3` answers `ok` for every one of those shapes, and `[nosuspend]` on a busy port answers the atom `nosuspend` when the payload really is a command.
A busy port's command takes the shared `crate::port::busy_wait` wait (see the `port_command` rows above); `SendBridge::send_with_options` folds `PortSend::Write(Suspended)` into `nosuspend`, `Write(Written)`/`Dropped` into `Ok`.
Residuals, each a typed error or a documented drop: **a busy port no driver ever clears** expires into `busy_wait::DEADLINE_REASON` on both routes (the C suspends the caller for ever; a sliced `port_command` caller parks and is re-run instead of gaping), while the **`send`/inline-`!`** route still cannot park (that instruction carries no suspend latch) ⇒ `busy_wait::NO_PUMP_REASON`; `{InternalPid, {connect, NewPid}}` is the C's ownership transfer (`io.c:4006-4009` → `set_port_connected`, `io.c:2334-2362`), a real capability gap retained as `PortMessage::Drop` for three reasons — the C answers the port its own `{Port, connected}` message through port **signals** (a `&mut ProcessTable` the send seam does not carry), it sets `connected` **without creating a link**, and it accepts a **dead** pid while requiring `is_internal_pid(New)` and `ERTS_PORT_GET_CONNECTED(prt) == from`; `{InternalPid, close}` **really closes the port** here where the oracle's own arm leaves it alive (the C's `erts_port_exit` intent is what this follows); a `Name ! Data` where `Name` is a **registered port** is still `badarg` (the classifier's `&ProcessTable` cannot resolve a port name without a new cross-crate seam), and a **remote** port term whose node slot names this node is the final `badarg` rather than the C's drop-and-log (`bif.c:2544-2560`).
Monitor shape: *Port monitors (A.4)*, *`beam_io` / `beam_abi` lifecycle* ([`HANDOFF.md`](HANDOFF.md)).

## Port monitors (A.4)
`erlang:monitor/2` on a port records an incoming entry on the port; a watcher that dies first is swept through the same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so a port never keeps a monitor for a dead process (`tests/port_monitor_cleanup.rs` is the discriminating white-box pin; a *surviving* watcher's monitor is kept).
`erlang:port_info(Port, monitors)` reads the always-empty `PortMeta.monitors` — the oracle returns `[]` even with a live watcher, so that matches and must not change.
