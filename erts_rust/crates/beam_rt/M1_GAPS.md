# `beam_rt` — Known M1 Gaps & Cross-Node Handoff Detail
Per-item detail behind [`CONTEXT.md`](CONTEXT.md)'s condensed `Known Issues / Intentional M1 gaps` bullets, plus cross-node handoffs and GC-relocation hazards.
Every gap is typed capability gap or measured own-state difference—never wrong result.
## Dispatch, atoms and module introspection
* Shared-`AtomTable` cloning. `call_registered`/`try_call_nif` commit pending names via `code_server.atoms_mut()` (`Rc::make_mut`) only when `PendingInterner::is_empty()` is false; the port/persistent-term/NIF handles hold the strong count at 2+, so only an interning call pays the copy.
* Two `get_module_info` divergences. `exports` uses `Module::exports` order, not oracle's global ERTS export-table order (`erl_bif_info.c:8434-8471`), so differential test compares unordered set; `get_module_info(M, ...)` raises `badarg` for module not loaded here (`lists` diverges by module-load state, not seam).
* `erlang:module_loaded/1` is truthful to *this* runtime's loaded set (`preloaded() || CodeServer::is_loaded`; `CodeServer::load` memoizes into same map); residual: boot-set size—oracle ~109 modules vs 22 preloaded `.beam`s, so `module_loaded(lists)` is `false` until `lists` loads (`tests/module_loaded.rs`).
## Own-state answers (differ by construction, not bugs)
* `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)`, `persistent_term`/`get_module_info` figures. `erlang:whereis(init)` agrees (root process; oracle `<0.0>`).
* Minor divergences (all outside this node unless noted). `persistent_term:info/0`'s `memory` is our own word total (`count` exact). The process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})`→`undefined` here vs `1` in oracle. `register/2` of internal PORT id = typed gap. `process_flag(save_calls, <non-integer>)` returns previous value where oracle raises `badarg` (`bif.c:1911`).
## Placeholders where a truthful source exists
* `NodeIdentity`'s creation is fixed `0` (`src/context/bridges.rs`) where live `crate::dist::DistNode::creation()` exists, so internal pid/port image encodes creation `0` on wired node; node atom beside it *is* runtime's live `Runtime::local_node()`, stamped on every `call_registered` arm.
* Flag-driven `system_info` literals (`src/info/system.rs`: `port_parallelism`, `break_ignored`, `modified_timing_level`, `halt_flush_timeout`; `src/info/limits.rs`: `dist_buf_busy_limit`, `delayed_node_table_gc`) report their default: no A.6 CLI arm preserves driving flag (`+spp`/`+B`/`+T`/`-shutdown_time`/`+zdbbl`/`+zdntgc`), and `cli.rs::record_unmodeled` drops unmodeled `+flag`.
* `process_info(P, last_calls)` answers `false` although runtime holds real `save_calls` flag (`beam_process::Process::save_calls`).
## Process-control families (`src/native/`)
`erlang:monitor/2,3` serves process target (pid, registered name, or `{Name, Node}` pair on this node) and port target: port monitor is recorded on live port table (`PortRegistry::port_table_mut`→`ProcessTable::monitor_port_term_with_tag`, table `open_port/2` allocates from), so its `{'DOWN', Ref, port, Port, Reason}` fires on port close.
`erlang:monitor/3`'s `{tag, T}` option is served on both paths for immediately-representable tag; heap-resident tag is `beam_process`'s typed `error::unsupported_tag`.
Monitor gaps: named port monitor `monitor(port, Name)` (`error::named_port_monitor`; local registry resolves names to processes only) and remote `{Name, Node}` monitor (A.5).
`exit/2,3` matches oracle except internal port target answers `true` without closing port, and foreign/decoded reference or ETS id is `badarg` vs oracle's `true`.
`spawn_opt`'s `{scheduler, N}`/`{async_dist, B}` stay `unsupported`; every other option is applied.
## ETS ownership
`ets:new/2` records caller as owner (`beam_ets::Table::set_owner`) and installs parsed `{heir, …}`; `ets:info(T, owner)`/`heir` render recorded pids (`undefined` when unset), `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner.
`ets:give_away/3` cannot deliver its `{'ETS-TRANSFER', Tid, FromPid, GiftData}` message: the send arm is selected by `beam_bifs::SEND_HOOK_BIFS`, which omits the key, so the fallback arm installs no `SendHook` and `adopt.rs`'s `ctx.sender().is_none()` gate raises the typed `unsupported` (exit 3; the oracle hands the gift over, exit 0).
The fix is the roster key alone (a `beam_bifs` edit); this crate needs no change — `uses_send_hook` delegates to `beam_bifs::needs_send_hook`, the memo keys on the `(m,f,a)` triple, `uses_send_hook` wins over no other gated arm, and `safe_to_rewind` already excludes `hooks.send_hook`.
A dead owner's table is reclaimed through `beam_process` `ProcessExitObserver` seam: observer records dead pid, and `Runtime::drain_ets_owner_exits` releases every table it owned—dropped, or handed to its heir with oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for 2-tuple `{heir, Pid}` form, which carries no data; arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`).
`tests/ets_owner.rs` oracle-cross-checks flows.
The public owner→handle roster is authority, so *unnamed* tables are reclaimed too: `beam_bifs::TableRegistry::handles_owned_by(TableRegistry::owner_of(dead))` lists every live table dead pid owned (its handle is registry key, reachable from no public term otherwise); `ets:new/2`-time index is unioned in only for `named_table`'s registered name, released with `TableRegistry::remove_name`.
An unnamed table's tid in transfer message is our own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`, fresh `RefAllocator` walked to handle, runtime's ref id space differing from `beam_bifs`'s).
Remaining live gap: `ets:setopts/2`'s gift data. `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs `{heir, …}` option through `beam_ets::Table::setopts`, which stores gift term verbatim where `beam_ets::Table::install_heir` (table-owned deep copy) is meant; drain then hands term aliasing dead heap to `{'ETS-TRANSFER', …, Data}` message.
Fix belongs in `beam_bifs` (or `beam_ets`, by making `setopts` copy); `Runtime::own_heir_gift` mitigates `ets:new/2` path only and records failed `Table::install_heir` on owner index (logged, then returned as typed error by next `drain_ets_owner_exits` *after* every death is discharged), so failed copy is never silently dropped.
A monitor whose watching process is dead is swept by same drain (`ProcessExit::ets_monitors`).
## Port monitors (A.4)
`erlang:monitor/2` on port records incoming entry on port; watcher that dies first is swept through same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so port never keeps monitor for dead process (`tests/port_monitor_cleanup.rs` is discriminating white-box pin; *surviving* watcher's monitor is kept).
`erlang:port_info(Port, monitors)` reads always-empty `PortMeta.monitors`—oracle returns `[]` even with live watcher, so that matches and must not change.
## `process_info/1,2`
Heap items read target process's own policy (`Process::collector().policy()`), so `spawn_opt` min-heap / `fullsweep_after` / `max_heap_size` is observable.
Two `max_heap_size`-map divergences: key order is `kill, error_logger, include_shared_binaries, size` (oracle: `error_logger, include_shared_binaries, kill, size`), and per-map flags go unhonoured.
~28 items answer from own state (catalog `src/native/CONTEXT.md`); four execution-position items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) answer for scheduled process (parked one probed from another process; executing one for its own query from compiled code, through in-machine BIF door), and are omitted for process this runtime gave no position (fun-bodied process with no resolved local target, never-scheduled pid, direct/no-machine caller); `catchlevel` follows same rule.
Two door residuals: `initial_call` is machine's entry MFA where oracle answers `{erlang,apply,2}` for some spawn shapes (fun-valued spawn, start instruction); published slot is runtime-wide, so nested fun-applied run inside its window reads *outer* machine's position for that pid.
Any other valid oracle item it cannot answer (`magic_ref`, `priority_messages`,...) is typed `unsupported`.
`registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact; `total_heap_size` is 466 (oracle 233); `memory`/`reductions`/`group_leader` are own figures.
A pid not in table→`undefined`; unknown item or non-pid→`badarg`.
`trace`/`message_queue_data`/`last_calls` read real state: `trace` serves live per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])`, oracle's integer shape translated from this runtime's internal bits by `src/trace.rs::flags_to_atoms`); `message_queue_data`/`last_calls` report real placement/saved-calls state (`on_heap`/`false`).
One divergence left: `process_flag(message_queue_data, off_heap)` is accepted-and-ignored, so such process reports `on_heap` (per-process storage in `beam_process` is cross-crate handoff).
## Printing
The `io` device request wrappers are served by native floor (`src/native/io.rs`): `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:put_chars/1,2`.
Each wraps `io.erl`'s `o_request/2`, posting `{io_request, …}` to request's device—caller's `group_leader()`, which is the root process both for the root process itself and for the action route's spawned child (`../src/runtime.rs::as_action_process` gives it the root's group leader)—and blocking for `{io_reply, …}`; `execute_request/3` answers `{error, calling_self}` for that self-device, so floor answers device question itself and renders through registered `io_lib:format/2`, letting installed compiler's `catch`-handler diagnostic (`io:fwrite("Function: ~w/~w\n", …)`) carry its real reason.
Device rules and per-key detail: `src/native/CONTEXT.md` *The `io` device floor*; stdout/stderr/exit-code differential is `tests/io_device.rs`, in-process compile diagnostic probe `tests/io_diagnostic_unmask.rs`.
Two residuals: live non-stdio device pid is typed `unsupported` (BIF cannot block on `{io_request, …}` round trip); `io:put_chars/1,2` accepts and ignores its device, so `io:put_chars(standard_error, …)` lands on stdout where oracle writes fd 2.
The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects non-byte-aligned bitstring (or container past ~80 columns) with `badarg`; corpus reads such values via `bit_size/1`/`is_list`.
## Scheduler / runner
A blocked receiver resumes on sender (send→wake→resume), due `send_after/3` timer, or fired `receive ... after T` deadline.
`src/runner/` returns `RunOutcome::Yield` once per-slice budget is spent, keeping parked `Machine` at `current_code` and letting scheduler re-enqueue, so hot loop is pre-empted and second runnable process interleaves (`tests/preempt.rs`).
The budget is charged per interpreted instruction through engine's `ExecutionContext::reduce` hook (*before* instruction's body runs) and, on either tier, at machine's heap-admission points (`ensure_heap`/`ensure_heap_full`).
`RuntimeContext::wants_reduce()` is `false`, so only runner's `BudgetContext` charges—non-budgeted single-pass/nested paths skip hook call—and non-allocating loop is pre-empted on interpreter tier like allocating one.
Residual gap: native baseline tier never crosses per-instruction hook, so such loop is charged only at deopt or heap-admission boundary, and natively linked tail loop is not pre-empted mid-block.
Other gaps: `receive ... after T` whose delay is `after infinity` or not statically positive integer (Y-register slot) parks; capability gap is uncatchable on runner path.
## Execution tier (`src/runner/tier.rs`)
The tier defaults to `JitMode::Auto`: every process's first entry runs on native baseline JIT.
No per-module predicate guards it—engine's baseline driver handles module-context switch (`Step::Enter` via `switch_into`)—and one host obligation (cross-module seam is idempotent, native `call_ext*` arm re-consulting it through interpreter-step fallback) is enforced in `RuntimeContext::resolve_external_call`.
`BEAM_RT_TIER` (`auto` default / `baseline` / `interpreter`) overrides it; `interpreter` is kill switch.
The tier chosen at that first entry is remembered on process (`ProcessEngine::tier`), and every later slice—reduction-budget pre-emption or `receive` park—resumes on it through `Machine::resume_outcome_with_tier`, so native-tier process is never demoted mid-life.
Measured figures and commands: `src/runner/tier.rs`, `TEST_STRATEGY.md`.
## NIF (A.3)
`load_nif/2` `dlopen`s shared object and runs C NIF; load failure is oracle's returned `{error, {Reason, Text}}`, never raise.
`NifHostImpl` implements runtime-independent hooks—`heap`/`intern_atom`/`atom_name`/`self_pid`, `term_to_binary`/`binary_to_term` (ETF), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is runtime's real normal-scheduler count), `alloc_env`/`free_env`, `make_copy` as identity—plus, through borrowed `NifHostServices` provider (`RuntimeNifServices`: runtime's reference-id allocator, reference registry, name table and port registry) threaded into per-call host, `make_ref`, `whereis_pid`, `is_process_alive`/`is_current_process_alive`, `is_port_alive`, `port_command`.
The load/unload host lives in `Runtime::nifs` (it cannot borrow runtime) with `services = None`, so every provider-backed hook stays trait default there.
Hooks at trait default, each needing host-unreachable runtime state: `priv_data` (`beam_abi`'s loader keeps library's `void**`; host answers C's null); `consume_timeslice` (`false`: provider holds process table immutably, and hook's `bool` cannot express "unsupported"); `send` (`None` ⇒ `enif_send` answers `0`; most damaging remaining gap—needs mutable process table plus copy context); `whereis_port` (`None`, provable: `erlang:register/2` refuses port, so no atom can name one); `monitor_process`/`demonitor_process` (monitors key on process watcher; NIF resource has no process identity); `select` (new poller/notification subsystem, not wiring); `schedule_nif` (`badarg`; no dirty schedulers, no scheduling trampoline); `dynamic_resource_call` (needs per-library `{module, name}`-keyed resource-type registry).
A second `load_nif` for loaded module is `reload`; NIF returning non-term is caught by `try_call_nif` as typed error, never abort.
## Funs
`fun M:F/A` builds real `FunKind::External` (`EXPORT_EXT`); compiled-module `make_fun3` closure gets its five identity fields from `FunIdentityBridge`, so `term_to_binary/1` is byte-exact (module-scoped to caller).
An `erl_eval` lambda stays honest `unsupported: local_fun` (its oracle image closes over `erl_eval.erl` internals); no wrong encoding is emitted.
`binary_to_term/2` `[safe]` implements only the atom-name half of the C's decode check, so an `EXPORT_EXT` (113) naming a non-**active** export is accepted where the oracle raises `badarg` (C requires `erts_active_export_entry(mod,name,arity)`, `external.c:5032-5036`); `beam_codec` records the gap (`../../beam_codec/src/decode/options.rs`).
Verified erts-17.1 vs this runtime: `fun lists:reverse/3` (loaded module, non-exported arity) and `fun zzz_nonexistent:foo/1` ⇒ oracle `error:badarg` / here the fun; `fun lists:reverse/1` (a real export) ⇒ both accept, and with no `[safe]` both accept the nonexistent module.
Not closable here — `[safe]` rides `beam_bifs::binconv::decode_term_bif`'s `DecodeOptions`, while this crate's own decode hosts carry no `safe` (`NifHost::binary_to_term(bytes)` has no opts; `enif_binary_to_term` drops its `_opts`, `../../beam_abi/src/nif/enif/mem.rs:805`), so a native-floor arm would duplicate the registry BIF and a post-decode walk is not the C's decode-time predicate.
Closing it needs an active-export predicate threaded into `beam_codec`'s decode: a new defaulted `beam_bifs::BifContext` seam (e.g. `is_active_export(module,function,arity)`) that `binconv::decode_term_bif` installs on `DecodeOptions`/`Decoder` (which is `Copy`, so a trait object cannot ride it) and `decode_export` (`../../beam_codec/src/decode/fun.rs:79`) consults, implemented here from `CodeServer::is_loaded` + the loaded `Module::exports`. Corpus-unobserved: the `[safe]` cases use a valid export (`wire_extra/b2t_safe_export_fun_image`/`_call`) or the atom-name half (`wire_extra/b2t_safe_nested_new_atom_reject`, `bin2term/safe_*`).

## Ports, drivers and the send family (A.4)
Read path: one `{Port, {data, Data}}` per driver read, at width child wrote (`binary`→up to `beam_io`'s `READ_CHUNK`, 64 KiB, per `read(2)`; `list`→char list).
Child stderr inherited by default, never port data; `stderr_to_stdout` duplicates fd 2 onto fd 1, so its diagnostics arrive as port data in true write order.
`connected` flips to `false` only at `port_close/1`; `os:cmd/1` stays runtime-native host spawn.
`{spawn_driver, Name}` resolves name against built-in driver table (`tcp_inet`/`fd`/`efile`) before any `dlopen`, as C does (`io.c:599-628`); unknown name→`badarg`.
A driver port's `driver_output` reaches its owner as `{Port, {data, Data}}`; driver-emitted `erl_drv_output_term`/`erl_drv_send_term` term reaches connected process or explicit destination (`TermQueue` drain is wired end to end).
`driver_select` is real; `driver_set_timer` arms for every attached port.
An `OUTPUT` port task always drains port's output queue through single write path, *then* runs entry's `ready_output` as write-readiness notification.
The driver's `control` callback routes behind `erlang:port_control/3`; `ERL_DRV_USE`'s `stop_select` fires on cancel/deselect handback.
The driver-private queue (`driver_enq`/`driver_pushq`/`driver_deq`/`driver_sizeq`/`driver_peekq`), `driver_pdl_create`, port state flags (`get_port_flags`; `set_control_flags`) and process-monitor family (`driver_monitor_process`/`_demonitor_process`/`_get_monitored_process` over per-port monitor tree, `monitor_process_result`'s three-way answer from published `ProcessLiveness` view) are implemented—27 of 41 `DriverHost` hooks.
Typed gaps: `driver_async` (no async pool; `Runtime` is `!Send`, `invoke`/`free` pair `unsafe`, `async_port_key` default `-1`); `control` reply answered from driver's own memory (needs safe copy helper on `beam_abi`); NULL driver reply with `PORT_CONTROL_FLAG_BINARY` set (`<<>>` where C answers `[]`); OS child (`os_pid` `undefined` for driver port, `take_exit_status` always `Ok(None)`); built-in (`spawn`/`spawn_executable`/`fd`) port's `port_control/3` answering `[]` where oracle raises `badarg` (owned by `beam_io`'s default `Driver::control`); driver arming more than one registration per direction (typed `unsupported`).
`line`/`{line, N}` framing is adopted (A.4): `open_port/2` decodes option into `PortOptions::line` (bare `line` ⇒ `512`; `{line, N}` ⇒ positive small integer, else `badarg`; mutually exclusive with `{packet, N}` and with `stderr_to_stdout` unless `use_stdio`); `PortRegistry::register` arms `beam_io`'s `set_line_mode`; port-task round's `take_line_notifications()` is delivered as oracle's `{Port,{data,{eol|noeol,Data}}}` frames, and `StreamType::port_flags` reports `PORT_FLAG_BINARY`/`PORT_FLAG_LINE` independently (`[line]` ⇒ `2`, `[binary]` ⇒ `1`, `[binary,line]` ⇒ `3`).
`erl_ddll` is served (A.4) from one loaded-driver view: `loaded_drivers/0`/`try_load/3`/`try_unload/2`/`info/2` come from native floor (`src/native/ddll.rs`) over one name-keyed loaded-driver registry `src/port/driver.rs` keeps—same list `open_port({spawn_driver, Name})` resolves against—while `monitor/2`/`demonitor/1`/`format_error/1` fall through to `beam_bifs`.
`loaded_drivers/0` lists the three statically-linked built-ins (`tcp_inet`/`udp_inet`/`ram_file_drv`) first, then the dynamically loaded names in load order — matching the oracle; a static name's `try_load`/`try_unload` answer `{error,linked_in_driver}` and its `info/2` takes the C's `handle == NULL` item branch. With no `erl_ddll:load_driver/*` `Name` doubles as `open_port` search (`/`-containing name is object path, driver name = its file stem; else `<name>.so`).
The send family serves `erlang:send/2` and `erlang:'!'/2` (`SendBridge`); `erlang:send(Port, Data)` needs port write path, and distributed `{Name, Node}` send is contract A.5—both raise `unsupported: …`, never fabricated value.
Monitor shape follows *Port monitors (A.4)* and *`beam_io` / `beam_abi` lifecycle*.
## Distribution and the node (A.5)
`-name`/`-sname` make runtime distributed node: `DistNode` binds wildcard listener, publishes to `epmd` best-effort (failed publish is recorded, never fatal) and completes server-side `'N'` handshake against real OTP peer (`tests/dist.rs`).
Gaps: no `net_kernel` protocol; distributed-spawn family (`SpawnRequest`/`SpawnReply`), `Delivery::Other(_)` and ack-owing `UnlinkId` half stay typed `Unsupported`; `node/0` and node atom pid image carries do reflect live `-name`/`-sname` node, but `NodeIdentity` reports creation `0` (*Placeholders*), so decoded local id is external (see `beam_codec`/`beam_bifs` handoff).
`DOP_SEND`/`DOP_REG_SEND` reach local mailboxes through `LocalDeliverySink`, as do route-free receipt families (link/exit/unlink/monitor/demonitor/group-leader), each emitting no outbound `DOP_*`, gated by `Runtime::inbound_delivery` (default ON; `Runtime::allow_inbound_delivery` turns it off).
No Erlang-level distribution subtree runs on `-sname`/`-name` node: native floor answers `erl_distribution:start_link/0,1` with `ignore` (distribution is native `DistNode` CLI binds and publishes to `epmd`), so `kernel_sup` skips `net_sup`.
Measured on `-sname` node: `whereis(net_sup)`/`whereis(net_kernel)`/`whereis(auth)` are `undefined` here vs pids on oracle, while `whereis(kernel_sup)`/`whereis(application_controller)`/`whereis(logger)` are pids on both, `whereis(timer_server)` is `undefined` on both, and `node()`/`is_alive()` agree.
Mechanism: `src/native/CONTEXT.md` *The Erlang-level distribution supervisor*.
## Timers
`send_after/3` answers `#Ref<>`; `cancel_timer(Pending)` remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)`/bad time or destination `badarg`.
`send_after/3`/`cancel_timer/1` are native-floor capabilities; `send_after/4`, `cancel_timer/2`, `start_timer/3,4` (both relative form and `{abs, true}` absolute form, whose delay is computed from registered `erlang:monotonic_time/0` against oracle's `start_time`/`end_time` millisecond window), `function_exported/3`, `link/1`/`unlink/1` and `os:set_signal/2` come from `RuntimeHooksBridge`.
Unimplemented: `erlang:system_info/2`, `read_timer/1,2` and roster keys this bridge does not serve (`delete_module/1`/`purge_module/2`, `port_get_data/1`/`port_set_data/2`, `term_to_iovec/1,2`, `erlang:is_builtin/3`, `bump_reductions/1`, `loaded/0`, …), each typed `unsupported` gap.
`timer:apply_after/4` schedules through booted `timer_server` (`kernel_sup` child started on demand through `timer:do_start/0`) with `{abs, true}` timer arm, so `is_reference(timer:apply_after(50,erlang,self,[]))` prints `false` on both runtimes with exit 0 (call returns `{ok,Ref}`).
## Memory and statistics
`erlang:memory/0,1` (`MemoryHook` seam) is adopted: `RuntimeMemory` (`src/context/memory_hook.rs`) returns nine oracle keys in oracle order with `total = processes + system`, every figure measured (process heaps from `ProcessTable`'s collectors, atoms from shared `Rc<AtomTable>`, binaries from `beam_alloc::registry`, `code` from loaded `.beam` sizes, `ets` from `TableRegistry`, `system` = those plus remaining allocator live bytes excluding `Standard`/`EHeap`) and snapshotted at construction; `memory/1` answers in requested order, `badarg` for unknown key.
`erlang:statistics/1` is partly served: `run_queue`, `run_queues`, `run_queue_lengths(_all)`, `total_run_queue_lengths(_all)`, `wall_clock`, `reductions`/`exact_reductions` (node-global cumulative counter bumped at real reduction charge site), `context_switches` (real process-switch counter), `io` (`{{input,N},{output,N}}` from real port byte counters), `garbage_collection` (`{GCs, WordsReclaimed, 0}` from live collectors' counters), `runtime` (`{Total, SinceLastCall}` user-CPU milliseconds from runtime's one long-lived `beam_io::cpu_time::RuntimeClock`, whose anchor persists for runtime's whole lifetime) and `scheduler_wall_time`/`scheduler_wall_time_all` ⇒ `undefined` (switch `erts_internal:scheduler_wall_time/1` records, armed or not, but no per-scheduler wall time is sampled, so tuple list is never fabricated).
Gaps: `statistics/0` is not served, and per-scheduler keys this runtime lacks (`total_active_tasks`/`total_active_tasks_all`/`active_tasks`/`active_tasks_all`—scheduler's current-process flag—and `microstate_accounting`—no MSACC accounting) are typed `unsupported`; every other `RuntimeHooks` family is unserved too.
## GC / heap model
`DEFAULT_HEAP_WORDS` is `1 << 24` (16 Mi words of lazily-mapped address space).
Term-construction heaps (BIF-heap pool + `-eval` heap) are bump arenas sized `config.heap_words`; `+hmax N` caps that capacity (`runtime.rs::term_heap_words`); `system_limit` translation runs after copy engine's retry, so `deliver_message` matches raw `AllocKind::Message` for heap-fragment retry.
This crate does drive `beam_gc`: *scheduled* process allocates on its own young heap and is collected at `ExecutionContext::ensure_heap`/`ensure_heap_full` (sharing `collect_or_grow`; latter is the full-root door `test_heap` reaches; armed by the slice's `BudgetContext`, its roots are the x file's pointer-bearing prefix, the whole Erlang stack and the FR file's live leading prefix), pinned by `tests/gc_collect.rs`, reported by `Runtime::gc_stats()`; every other context no-ops on unbounded arena.
Measured limits: a workload allocating only through `ExecutionContext::alloc_words` (no `test_heap` admission point, as real Cowboy `cowboy_bstr`-style code does) is never collected — the door grows the nursery and retries the bump, falling back to the pointer-stable arena only when growth cannot reach the request, and the retained `Process::collection_debt` is turned into a real collection by the *next* admission point — so such a workload reaches the term heap's hard limit with no collection at all (`collections: 0`); a live float register is never left unrooted (the full-root doors publish the machine's live leading FR prefix, `Machine::fr_mark()`, and a live FR slot holds a boxed float term, so it lies inside the x file's pointer-bearing bound); failed collection halts that process's collection rather than failing program.

**Retained-space caution:** `Process::grow_nursery` retires the space it replaces and that chain is collapsed only by a real collection, so a *genuinely* present foreign root **with** children keeps a process's capacity growing with its admission-point count (a `beam_process` policy matter — `Process`'s `should_collect` ignores the chain). A **childless** foreign boxed leaf does not: the unscanned-root valve exempts it (`context/gc.rs::foreign_boxed_has_copy_children`), so a reference-minting loop runs at a flat `memory(processes)` of 6.91 MB across N = 20 000 / 200 000 / 1 000 000, against the oracle's 13.7 MB and the pre-exemption 13.77 / 43.26 / 170.09 MB (`context/gc/refs_plateau.rs`).
Term-heap capacity remains hard limit for anything not collected: both exhaustion classes become `error::system_limit` via `error::enforce_term_heap_limit`—`AllocKind::Heap` (per-process bump allocator) and `AllocKind::Message` (copy engine's destination-heap exhaustion, classified by `beam_message::is_message_heap_exhaustion`)→CLI `beam_rt: system_limit`, exit 1.
On-demand heap growth is adopted at engine's heap-admission point and on `beam_process` message-delivery path: `src/context/gc.rs::ensure_heap`/`ensure_heap_full` run collector's `Process::ensure_capacity` growth whenever heap-size policy can reach request (`HeapPolicy::next_words(need, 0) >= need`), and plain `Process::collect` otherwise—so `test_heap` request larger than nursery is admitted by growing it in place (`tests/heap_growth.rs`), while bounded `+hmax N` policy request cannot reach is refused before collecting (collection runs, allocation falls back to arena).
`Process::deliver` grows nursery same way for refused message copy; that refusal is what reproduces raw `AllocKind::Message` `deliver_message` keys its heap-fragment fallback on, and relocation-exempt receiver skips retry entirely.
Allocation outside admission point uses bounded `beam_alloc::Heap` arenas that never move (`BifContext::heap()`, `Runtime::eval_heap`), so BIF's *intermediate* terms are invisible to `roots` and cannot be collected; call overflowing such heap raises `error::system_limit`.
The one growth seam outside admission point is pooled BIF-heap frontier: on table-less (`-eval`/nested) route—no process heap to move container result onto—`RuntimeContext::take_bif_frontier` retires near-full region and continues in larger one (capped only by explicit `+hmax`), so long table-less compilation grows its result store instead of hitting fixed `DEFAULT_HEAP_WORDS` cap.
### The BIF-result copy-out
A registered BIF builds its result on runtime's pooled 16 MiB `Runtime::bif_heaps` (`Runtime::take_bif_heap`)—`Target::Foreign`, unscanned by process collector—so container left there is root unscanned-root valve declines over while live.
`RuntimeContext::call_registered` (`src/context/calls.rs`) therefore moves result onto running process's own young heap (`Process::heap_mut()`, collector-scanned) and rewinds pool to call's pre-offset, so result lands in `x(0)` (engine-published root) and later collections relocate it.
The copy is `beam_message::copy_struct` with empty source `OffHeapTable`; full nursery is met by `Process::grow_nursery(hint)` (inside BIF call machine's x registers and stack are unpublished, so collecting `Process::ensure_capacity` would free live terms) and one retry, hint being copier's preflight count from refusal (`AllocFailure::requested / size_of::<Eterm>()`, so growth costs no second graph walk).
One `OffHeapTable`/`CopyContext` pair serves both attempts, and retry is reached only for `beam_message::is_message_heap_exhaustion`; every other refusal legal BIF result can produce (malformed-graph `badarg`, `AllocKind::Heap`/`LiveObject` failure, raised reason) is permanent, so move answers `None` without growing space (`src/context/calls.rs::tests::{a_permanent_copy_refusal_grows_no_nursery_and_writes_nothing, an_exhaustion_refusal_grows_the_nursery_and_the_retry_copies}`).
The empty source table is load-bearing: with no payload owner copier flattens refc binary's window into self-contained on-heap bitstring (byte-faithful, no refcount lost), and off-heap MSO reference with no owner is copier's typed `bad_term`, so move answers `None`—pool unrewound, result left as it was, never dangling payload.
The rewind is `Heap::reset_to(mark)` at `heap.used()` read *before* call, so it frees only this call's own words `[mark..used)` and keeps whatever previous owner holds below `mark` (pool is shared with native-floor reference minting, trace and ETS-owner sweep, which return heap *unreset*).
It applies only when move is safe and complete—no escaping `DispatchHooks` arm (`dict`/`process_hook`/`nif_loader`/`send_hook`/`persistent_term`/`runtime_hooks`, each letting term built on `ctx.heap()` escape into state outliving call), no reentrant fun-applying call, `Ok` result (raise may carry `live_reason` term pointing into this heap, so error path never rewinds), scheduled process (`mailbox_table` is `Some`), container result (`result_is_foreign_container`; immediate is unboxed and literal lives in frozen literal area, so such result rewinds with no copy), and move that succeeded.
Residuals: NIF result is not copied out (deliberate M1 residual), so it stays on pooled heap and keeps declining collection while live; escaping `DispatchHooks` arm and error result also leave their container on pooled (`Target::Foreign`) heap; on `-eval`/no-scheduled-process shape there is no process to move onto, so pooled frontier instead grows (`RuntimeContext::take_bif_frontier`, capped only by explicit `+hmax`); nested cross-module run (`RuntimeContext::run_export`) never reaches collection point.
Pinned by `src/context/tests.rs` (`a_bif_container_result_is_moved_onto_the_process_heap_and_the_pool_is_rewound`, `an_immediate_result_rewinds_the_pool_without_a_copy`, `an_escaping_arm_neither_moves_the_result_nor_rewinds_the_pool`, `a_bif_result_on_the_process_heap_lets_the_churn_loop_be_collected`, `a_partially_used_pool_is_rewound_to_the_callers_mark`, `an_escaping_arm_does_not_rewind_a_partially_used_pool`).
### `ets_copy` peak RSS
`copy_bound/ets_copy`'s peak RSS is linear in N (94.68 MiB at N = 100 000, ≈99 words per iteration), structural limit of BIF-result copy-out above, not ETS adopt path: `safe_to_rewind` is `true` for `ets:*` and pooled heap is rewound.
It tracks BIF calls, not floats and not ETS table state (float-free ETS loop of same shape grows identically; float-carrying churn loop with no ETS is flat).
The loop's heap traffic is copy-out, which cannot collect (machine's x registers / Erlang stack are unpublished at BIF call), so full nursery is met by `Process::grow_nursery(hint)` (`src/context/calls.rs::move_result_into_process_heap`) and retired young space is retained, capacity accumulating linearly; no real collection is reached either—`ensure_heap_full` returns at `!process.should_collect(heap_need)` (`src/context/gc.rs`), its `test_heap` prefixes being tiny (233-word default nursery, `beam_gc/src/policy.rs`), and `alloc_words_rooted` is never entered (BIF, not engine, builds result).
The caller-module float guard is not mover (relaxing it at two FR-publishing GC doors changes nothing here and contradicts pinned float-collection contract, `tests/gc_collect.rs`).
Closing it needs either `beam_process` seam that can shrink/reuse retired young space or `beam_engine`/runner seam that publishes driving machine's roots at BIF call so copy-out can collect—both sibling-crate changes; the retained-nursery lever is the same one the `beam_message` copy-out bullet below describes.
Figures and bisection: `PERF.md` *COPY-OUT-CUT*.

## OTP-lifecycle survey
Method: self-contained `.erl` fixtures compiled by system `erlc` (OTP 29.1.1 / erts-17.1, oracle) into `$TMPDIR`, each exporting arity-0 probes, run three ways: `erl -noshell -pa <fix> -eval 'io:format("~w~n",[M:F()])' -s init stop` (oracle), `erts_rust/target/debug/beam_rt -noshell -pa <fix> run <fix>/M.beam M:F/0` (scheduled process) and `… beam_rt -noshell -pa <fix> -eval '…'` (the spawned action process, which pumps scheduler). Exit 0 = success, 1 = runtime error, 3 = capability gap.

### The `-eval` vs scheduled asymmetry
The `-eval` action process pumps scheduler and can suspend blocking call; scheduled process (`run`) parks at its own top-level `receive`.
Both routes deliver `receive … after T` timeout, including one reached through nested run (cross-module call or fun application), and `receive` waiting for message resumes correctly on both.
A scheduled slice is *running*, not runnable (`beam_process::Scheduler::slice_begin` flips pid to `ProcessState::Running`), so signal- or delivery-driven collection of it is declined (*GC-relocation hazards*) and no such collection moves its heap against incomplete root snapshot.
A `spawn`ed `-eval` closure is run synchronously to completion, so it is not nested run that suspends: evaluator (`src/eval/mod.rs`, `apply_eval_closure`) drives closure to its end before spawning expression continues, and evaluator's `receive … after T` arm polls port poller once and falls straight through to `after` body (M1 has no host timer to block on).
A `-eval` child that "parks" therefore returns and terminates before parent's next statement—hence async-completion shape for live, blocked target is pinned only on scheduled route (`tests/garbage_collect.rs`). Owner: `src/eval/mod.rs`'s `receive`—`after T` deadline must be waited out (or spawned `-eval` child otherwise kept alive).
## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers running process's own young heap (capacity refusal met by no-relocation `Process::grow_nursery` and one retry) and falls back to pointer-stable `Runtime::arena`; roster below splits *at risk* from *safe*—what moving heap would dangle is raw `Eterm` pinned outside GC root set.
`Process::regs` is snapshot, not live mirror of running machine.
`publish_roots_full`/`scatter_roots_full` (`context/gc.rs`) copy the x file's **pointer-bearing prefix** and the whole stack into `process.regs` (FR words appended after stack words, bounded by `fr_count`—`beam_process::Registers` has no FR container) at every full-root heap-admission point (`gc::ensure_heap_full`/`alloc_words_rooted`; the bound is `gc.rs::machine_root_bounds`) or a **publishing** (non-exempt) park (`publish_parked_roots`, live prefix `Machine::fr_mark()`, recorded on `ProcessEngine::fr_published` for resume, plus parked machine's live `pending_exception` as `extra_roots` word); an **exempt** park publishes nothing at all (the parked machine stays authoritative) — between those points snapshot is stale by up to one slice, so collection rooted in it reaches machine's x/stack/FR and nothing else—Rust local or un-published `Machine` field is not in root set.
The engine's `live` count is ignored (over-approximating copying collector's root set is always safe).
Three collect triggers differ in exposure. The admission-point collection *is* publish/collect/scatter hand-off (safe). The delivery-driven (`Process::deliver`→`ensure_capacity`→`run_rooted_collection` over `self.regs`) and signal-driven ones (`ptab.rs`'s `terminate_with_ports`→…→`grow_receiver_for_signal`→`ensure_capacity`) fire outside admission and are refused for receiver with unpublished roots: `Process::has_unpublished_roots()` (= `relocation_exempt || state == Running`, `process.rs:1098`) is tested *first* by every caller, so refused delivery becomes heap-fragment delivery and refused ptab signal goes to `enqueue_fragment_signal`; `beam_rt` adds second refusal on that seam (`RuntimeContext::deliver_message_with_off_heap_inner` asks `delivery_collection_is_unsound` and marks receiver relocation-exempt on `true`)—fifth collection site; every send routes through `deliver_message_with_off_heap` (`src/context/mod.rs:590`), marking sender's own pid exempt.
A signal to running process is deferred; to parked one, declined by park-window exemption below; to woken-but-not-yet-resumed (`Runnable`) receiver—A.9 `selfhost/*` class—declined by host collection gate every `ptab.rs` signal site asks (OR-ed with `has_unpublished_roots`) before *collecting* `ensure_capacity`, installed as `RuntimeCollectionGate` (`context/gc_walk.rs`, same roots-incompleteness walk as admission-point valve, built over the runtime's shared per-pid latch cell so a clear bit is an O(1) `false` with no descent) in `Runtime::new`.
The `Yield` arm, third out-of-admission trigger, is exempt exactly when its slice ended with a live FR prefix (`fr_count > 0`) and not otherwise: an exempt (and every Wait) park publishes nothing and its `Runtime::serve_gc_request` is declined by the exemption it just set, while a non-exempt park publishes the machine's roots first, then serves the request.
The residual exposure is live term held outside `process.regs`—Rust local, or engine `Machine` field with no extra-root publication—hence `relocation_exempt` (`self()`, wrapped `-eval`/nested-`Machine` scope, parked window).
A parked machine's `pending_exception` is published as `extra_roots` word at a **publishing** park (`runner/run.rs::publish_parked_roots`) and read back on that resume (`RuntimeContext::resync_parked_roots(pid, machine, fr_count)`); an exempt park publishes nothing and its resume re-syncs nothing, and the parked window carries the exemption, so that publication is never licence for park-window collection.
Still outside root set: `Raise::live_reason`'s reason term between raise and its stabilization (`try_stabilize_escaped`, `runner/run.rs:662`).
The post-slice pin scan (`runner/run.rs`) reads `Machine::fr_mark()` once per slice, pins pid iff it is `> 0`, and passes the same count to the park as its `fr_count`; a pinned (exempt) park publishes nothing and the parked machine keeps its own live FR prefix, so no live FR term is lost.
A collection is DECLINED whenever root—or container process's scanned graph reaches—lives in region collector does not scan (unscanned-root valve): `RuntimeContext::call_registered` (`src/context/mod.rs`) hands `beam_bifs` runtime's pooled 16 MiB `Runtime::bif_heaps`, and `context::gc::alloc_words`'s fallback hands blocks out of `Runtime::arena`, both `Target::Foreign` to collector (`beam_gc/src/copy.rs`: pointer outside `FromSet` is left as-is and not scanned).
The valve (`context/gc.rs::root_is_unscanned` + `src/context/gc_walk.rs`) calls term safe iff it is immediate, literal, or pointer process's collector scans (any nursery space, incl. one `grow_nursery` retired, or mature space); each of three admission points (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`), runner's park arm (`Runtime::serve_gc_request`) and delivery seam (`delivery_collection_is_unsound`) declines (`Ok(())`) collection whose root set reaches anything else, while unrooted `context::gc::alloc_words` keeps its arena fallback.
Both allocation doors try the running process's own young heap first: on a non-forced capacity refusal `context::gc::alloc_words` and `context::gc::alloc_words_rooted` (the rooted engine path) call `Process::grow_nursery` and retry the bump **before** consulting the valve and the arena. Growth relocates nothing (legal against any root set) and leaves `Process::collection_debt`, which the next admission point's occupancy test turns into a real collection; only a growth that cannot reach the request, and a forced request, still reach the valve and the arena.
The valve spans machine roots caller publishes (`x`/stack/FR) and process's own root-set containers (`Process::collect`'s registers, mailbox, dict, saved arguments and pending signals), and it *descends* through scanned graph, so foreign container reached at depth ≥ 2 is found.
The descent is gated on sticky, add-only per-pid latch (`Runtime::foreign_reachable`/`note_foreign_reachable` over `GcState::foreign`), opened by every event that can put unscanned container into graph—engine's arena fallback (`note_gc_fallback`), BIF / native-floor / NIF result built outside process heap (`open_gate_for_foreign_result`), heap-fragment delivery (`send_fragmented_message`), spawn argument or entry fun not on new process's own heap (`note_spawn_foreign_roots`), escape store / `stabilize_term` (`note_escaped_store_roots`), and valve itself on hit—and pruned at pass boundary for process i.e. gone (`Runtime::prune_gc_requests`).
The holder it was built for is `Runtime::bif_heaps`: container registered BIF built there (`erlang:'++'/2`, `lists:append/2`, `lists:reverse/1`, `lists:filter/2`, `ctx.tuple(…)`) writes caller's heap `Eterm`s verbatim, and scheduled process's container result leaves pool (*The BIF-result copy-out*), so holder is reached through unrewound paths (NIF result, escaping `DispatchHooks` arm's result, `-eval`/nested shape, error result) at depth ≥ 2 below scanned root.
Verified end to end: `beam_rt run w.beam w:f9/0` renders oracle's exact `~w` at exit 0, and `tests/gc_run.rs` passes; descent is pinned by `src/context/tests.rs::{the_valve_declines_a_foreign_container_nested_in_a_scanned_container, …_a_deeply_nested_foreign_container, …_collects_when_the_nested_graph_is_fully_scanned}` (first two fail with descent forced off).
* At risk (raw `Eterm` outside root set): `Runtime::persistent_terms` (`context/persistent_term.rs`), `Runtime::trace`'s `MatchSpec::Functions`, `Runtime::seq_trace`'s `Token{label,from}`, `Runtime::eval_closures` `FunBody.env`, `Runtime::timers` `TimerAction::Deliver`; `MailboxState.markers[].reference` and `NameSpec.inline_options` need check. A spawn argument or entry fun (`ProcessEngine.args`/`entry:Fun{fun}`, `PendingSpawn.args`) and stored escape-store term also sit outside those roots, but each opens descent latch (`note_spawn_foreign_roots`, `note_escaped_store_roots`). Safe: `RunnerState.exits`/`results` (stabilized `eval_heap` copy), `references`/`Timers.refs` keys, ETS (own arena), `RuntimeContext` (no `Eterm` field), `dist`/`port` structs, `PortMeta`.
* Envelope/retained payloads: `Process::run_rooted_collection` (`beam_process/src/process.rs:1166-1240`) roots each queued message's `payload`, `from` and `token` and re-installs all three (`set_from`/`set_token`/`with_payload`), so heap `from`/`token` relocates too; envelope's `off_heap`/`binaries`/`nodes` families and `MailboxState::remove_at` retained copies are refcounted Rust handles (not young-heap `Eterm` words), so moving heap can neither move nor dangle them, and `with_payload` carries `Fragments` chain across. `beam_process`'s `deliver_down_message` sets `Message.from` to target pid's `to_eterm()` (immediate) and carries named monitor's `{Name,Node}` in body, so `run_rooted_collection` relocates it with payload.
* The arena allocation source here: `Runtime::alloc_words` (`runtime.rs`→`self.arena`), fallback `RuntimeContext::alloc_words` reaches after young-heap refusal and `grow_nursery`, also reached by `runner/budget.rs`'s forwarded `alloc_words` and by `Runtime::materialize`/`charlist`; mailbox `Queue` payloads are copied in by `copy_struct`.
