# `beam_rt` — Known M1 Gaps & Cross-Node Handoff Detail
Per-item detail behind [`CONTEXT.md`](CONTEXT.md)'s condensed `Known Issues / Intentional M1 gaps` bullets, plus cross-node handoffs and GC-relocation hazards.
Every gap is a typed capability gap or a measured own-state difference — never a wrong result.
## Dispatch, atoms and module introspection
* Shared-`AtomTable` cloning: `call_registered`/`try_call_nif` commit pending names via `code_server.atoms_mut()` (`Rc::make_mut`) only when `PendingInterner::is_empty()` is false; the port/persistent-term/NIF handles hold the strong count at 2+, so only an interning call pays the copy.
* `get_module_info`'s `exports` uses `Module::exports` order, not the oracle's global ERTS export-table order (`erl_bif_info.c:8434-8471`), so the differential test compares it as an unordered set.
* `get_module_info(M, …)` raises `badarg` for a module not loaded here (`lists` diverges by module-load state, not by seam).
* `erlang:module_loaded/1` is truthful to *this* runtime's loaded set (`preloaded() || CodeServer::is_loaded`; `CodeServer::load` memoizes into the same map); residual: boot-set size — oracle ~109 modules vs 22 preloaded `.beam`s — so `module_loaded(lists)` is `false` until `lists` loads (`tests/module_loaded.rs`).
## Own-state answers (differ by construction, not bugs)
`erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)` and the `persistent_term`/`get_module_info` figures answer from own state; `erlang:whereis(init)` agrees (root process; oracle `<0.0>`).
Minor divergences (all outside this node unless noted):
* `persistent_term:info/0`'s `memory` is our own word total (`count` exact).
* The process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})` → `undefined` here vs `1` in the oracle.
* `register/2` of an internal PORT id is a typed gap.
* `process_flag(save_calls, <non-integer>)` returns the previous value where the oracle raises `badarg` (`bif.c:1911`).
## Placeholders where a truthful source exists
* `NodeIdentity`'s creation is a fixed `0` (`src/context/bridges.rs`) where a live `crate::dist::DistNode::creation()` exists, so an internal pid/port image encodes creation `0` on a wired node; the node atom beside it *is* the runtime's live `Runtime::local_node()`, stamped on every `call_registered` arm.
* The flag-driven `system_info` literals that report their default (`port_parallelism`, `break_ignored`, `modified_timing_level`, `halt_flush_timeout`, `dist_buf_busy_limit`, `delayed_node_table_gc`), because no A.6 CLI arm preserves the driving flag: [`src/info/CONTEXT.md`](src/info/CONTEXT.md).
* `process_info(P, last_calls)` answers `false` although the runtime holds the real `save_calls` flag (`beam_process::Process::save_calls`).
## Process-control families (`src/native/`)
`erlang:monitor/2,3` serves a process target (pid, registered name, or `{Name, Node}` pair on this node) and a port target: the port monitor records on the live port table (`PortRegistry::port_table_mut`→`ProcessTable::monitor_port_term_with_tag`, the table `open_port/2` allocates from), so its `{'DOWN', Ref, port, Port, Reason}` fires on port close.
`erlang:monitor/3`'s `{tag, T}` option is served on both paths for an **immediate** (atom/integer/pid/port) or **module-literal** tag; a **heap-resident** tag — a term built on a process heap, neither immediate nor literal — is `beam_process`'s typed `error::unsupported_tag` (`is_heap_independent`, the acceptance rule the C's plain-value monitor record needs).
Monitor gaps: a named port monitor `monitor(port, Name)` (`error::named_port_monitor`; the local registry resolves names to processes only) and a remote `{Name, Node}` monitor (A.5).
`exit/2,3` matches the oracle except that an internal port target answers `true` without closing the port, and a foreign/decoded reference or ETS id is `badarg` vs the oracle's `true`.
`spawn_opt`'s `{scheduler, N}`/`{async_dist, B}` stay `unsupported`; every other option is applied.
## ETS ownership
`ets:new/2` records the caller as owner (`beam_ets::Table::set_owner`) and installs the parsed `{heir, …}`; `ets:info(T, owner)`/`heir` render the recorded pids (`undefined` when unset), `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner.
A dead owner's table is reclaimed through the `beam_process` `ProcessExitObserver` seam: the observer records the dead pid and `Runtime::drain_ets_owner_exits` releases every table it owned — dropped, or handed to its heir with the oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for the 2-tuple `{heir, Pid}` form, which carries no data; arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`).
`tests/ets_owner.rs` oracle-cross-checks the flows.
The public owner→handle roster is the authority, so *unnamed* tables are reclaimed too: `beam_bifs::TableRegistry::handles_owned_by(TableRegistry::owner_of(dead))` lists every live table the dead pid owned (its handle is the registry key, reachable from no public term otherwise), and the `ets:new/2`-time index is unioned in only for `named_table`'s registered name (released with `TableRegistry::remove_name`).
An unnamed table's tid in a transfer message is our own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`, a fresh `RefAllocator` walked to the handle — the runtime's ref id space differs from `beam_bifs`'s).
Drains, heir-gift failure policy and `Runtime::own_heir_gift`: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *`ets_owner.rs`*.
Remaining live gap — `ets:setopts/2`'s gift data: `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs the `{heir, …}` option through `beam_ets::Table::setopts`, which stores the gift term verbatim where `beam_ets::Table::install_heir` (a table-owned deep copy) is meant, so the drain then hands a term aliasing the dead heap to the `{'ETS-TRANSFER', …, Data}` message.
The fix belongs in `beam_bifs` (or `beam_ets`, by making `setopts` copy); `Runtime::own_heir_gift` mitigates the `ets:new/2` path only, the recorded failure surfacing as a typed error from the next drain, so a failed copy is never silently dropped.
A monitor whose watching process is dead is swept by the same drain (`ProcessExit::ets_monitors`).
## Port monitors (A.4)
`erlang:monitor/2` on a port records an incoming entry on the port; a watcher that dies first is swept through the same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so a port never keeps a monitor for a dead process (`tests/port_monitor_cleanup.rs` is the discriminating white-box pin; a *surviving* watcher's monitor is kept).
`erlang:port_info(Port, monitors)` reads the always-empty `PortMeta.monitors` — the oracle returns `[]` even with a live watcher, so that matches and must not change.
## `process_info/1,2`
The item catalog and the per-item own-state answers are [`src/native/CONTEXT.md`](src/native/CONTEXT.md)'s; ~28 items answer from real state, and the divergences are:
* Heap items read the target's own policy (`Process::collector().policy()`), so `spawn_opt`'s min-heap / `fullsweep_after` / `max_heap_size` is observable; the `max_heap_size` map's key order is `kill, error_logger, include_shared_binaries, size` (oracle `error_logger, include_shared_binaries, kill, size`) and its per-map flags go unhonoured.
* `memory`/`reductions`/`group_leader` are own figures; `total_heap_size` is 466 (oracle 233); `registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact (a pid not in the table → `undefined`; an unknown item or a non-pid → `badarg`).
* The four execution-position items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) answer for a scheduled process, and are omitted for one this runtime gave no position (a fun-bodied process with no resolved local target, a never-scheduled pid, a direct/no-machine caller); `catchlevel` follows the same rule. Residuals: `initial_call` is the machine's entry MFA where the oracle answers `{erlang,apply,2}` for some spawn shapes (fun-valued spawn, start instruction), and the slot is runtime-wide, so a nested fun-applied run inside its window reads the *outer* machine's position.
* `trace` serves the live per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])`, the oracle's integer shape translated from this runtime's internal bits by `src/trace.rs::flags_to_atoms`); `last_calls` reports the real saved-calls state (`false`).
* `message_queue_data` answers `on_heap`, this runtime's real *current* placement (`beam_message::Queue` is always heap-resident), so the only divergence is an explicit `process_flag(message_queue_data, off_heap)` (or `spawn_opt`'s `{message_queue_data, off_heap}`), accepted and changing nothing — honouring it needs per-process placement storage in `beam_process::Process`.
* Any other valid oracle item it cannot answer (`magic_ref`, `priority_messages`, …) is typed `unsupported`.
## Printing
The `io` device request wrappers are served by the native floor (`src/native/io.rs`): `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:put_chars/1,2`.
Each wraps `io.erl`'s `o_request/2`, posting `{io_request, …}` to the request's device — the caller's `group_leader()`, the root process both for the root process itself and for the action route's spawned child (`src/runtime.rs::as_action_process`) — and blocking for `{io_reply, …}`; `execute_request/3` answers `{error, calling_self}` for that self-device, so the floor answers the device question itself and renders through the registered `io_lib:format/2`.
Device rules and per-key detail: `src/native/CONTEXT.md` *The `io` device floor*; stdout/stderr/exit-code differential: `tests/io_device.rs`; in-process compile diagnostic probe: `tests/io_diagnostic_unmask.rs`.
Two residuals: a live non-stdio device pid is typed `unsupported` (a BIF cannot block on the `{io_request, …}` round trip); `io:put_chars/1,2` accepts and ignores its device, so `io:put_chars(standard_error, …)` lands on stdout where the oracle writes fd 2.
The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (or a container past ~80 columns) with `badarg`; the corpus reads such values via `bit_size/1`/`is_list`.
## Scheduler / runner
A blocked receiver resumes on a sender (send→wake→resume), a due `send_after/3` timer, or a fired `receive ... after T` deadline.
`src/runner/` returns `RunOutcome::Yield` once the per-slice budget is spent, keeping the parked `Machine` at `current_code` and letting the scheduler re-enqueue, so a hot loop is pre-empted and a second runnable process interleaves (`tests/preempt.rs`).
`RuntimeContext::wants_reduce()` is `false`, so only the runner's `BudgetContext` charges (a non-budgeted single-pass/nested path skips the hook call); the charge sites are the per-instruction `ExecutionContext::reduce` hook (*before* the instruction's body runs) and, on either tier, the heap-admission points (`ensure_heap`/`ensure_heap_full`).
Residual gap: the native baseline tier never crosses the per-instruction hook, so such a loop is charged only at a deopt or a heap-admission boundary, and a natively linked tail loop is not pre-empted mid-block.
Other gaps: a `receive ... after T` whose delay is `after infinity` or not a statically positive integer (a Y-register slot) parks; a capability gap is uncatchable on the runner path.
## Execution tier (`src/runner/tier.rs`)
The tier defaults to `JitMode::Auto` (the native baseline tier for every process's first entry), with no per-module predicate guarding it — the engine's baseline driver handles the module-context switch (`Step::Enter` via `switch_into`) — and the one host obligation (the cross-module seam is idempotent, the native `call_ext*` arm re-consulting it through the interpreter-step fallback) enforced in `RuntimeContext::resolve_external_call`.
The tier chosen at that first entry is remembered on the process (`ProcessEngine::tier`), and every later slice — reduction-budget pre-emption or `receive` park — resumes on it through `Machine::resume_outcome_with_tier`, so a native-tier process is never demoted mid-life.
Measured figures and commands: `src/runner/tier.rs`, `TEST_STRATEGY.md`.
## NIF (A.3)
`load_nif/2` `dlopen`s the shared object and runs C NIF code; a load failure is the oracle's returned `{error, {Reason, Text}}`, never a raise.
`NifHostImpl` implements the runtime-independent hooks — `heap`/`intern_atom`/`atom_name`/`self_pid`, `term_to_binary`/`binary_to_term` (ETF), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is the runtime's real normal-scheduler count), `alloc_env`/`free_env`, `make_copy` as identity — plus, through the borrowed `NifHostServices` provider (`RuntimeNifServices`: the runtime's reference-id allocator, reference registry, name table and port registry) threaded into the per-call host, `make_ref`, `whereis_pid`, `is_process_alive`/`is_current_process_alive`, `is_port_alive` and `port_command`.
The load/unload host lives in `Runtime::nifs` (it cannot borrow the runtime) with `services = None`, so every provider-backed hook stays at the trait default there.
Hooks at the trait default, each needing host-unreachable runtime state: `priv_data` (`beam_abi`'s loader keeps the library's `void**`; the host answers the C's null); `consume_timeslice` (`false`: the provider holds the process table immutably, and the hook's `bool` cannot express "unsupported"); `send` (`None` ⇒ `enif_send` answers `0`; the most damaging remaining gap — needs a mutable process table plus copy context); `whereis_port` (`None`, provable: `erlang:register/2` refuses a port, so no atom can name one); `monitor_process`/`demonitor_process` (monitors key on a process watcher; a NIF resource has no process identity); `select` (a new poller/notification subsystem, not wiring); `schedule_nif` (`badarg`; no dirty schedulers, no scheduling trampoline); `dynamic_resource_call` (needs a per-library `{module, name}`-keyed resource-type registry).
A second `load_nif` for a loaded module is `reload`; a NIF returning a non-term is caught by `try_call_nif` as a typed error, never an abort.
## Funs
`fun M:F/A` builds a real `FunKind::External` (`EXPORT_EXT`); a compiled-module `make_fun3` closure gets its five identity fields from `FunIdentityBridge`, so `term_to_binary/1` is byte-exact (module-scoped to the caller).
An `erl_eval` lambda stays an honest `unsupported: local_fun` (its oracle image closes over `erl_eval.erl` internals); no wrong encoding is emitted.
`binary_to_term/2` `[safe]` implements only the atom-name half of the C's decode check, so an `EXPORT_EXT` (113) naming a non-**active** export is accepted where the oracle raises `badarg` (the C requires `erts_active_export_entry(mod,name,arity)`, `external.c:5032-5036`); `beam_codec` records the gap (`../../beam_codec/src/decode/options.rs`).
Verified erts-17.1 vs this runtime: `fun lists:reverse/3` (a loaded module, non-exported arity) and `fun zzz_nonexistent:foo/1` ⇒ oracle `error:badarg` / here the fun; `fun lists:reverse/1` (a real export) ⇒ both accept, and with no `[safe]` both accept the nonexistent module.
Not closable here — `[safe]` rides `beam_bifs::binconv::decode_term_bif`'s `DecodeOptions`, while this crate's own decode hosts carry no `safe` (`NifHost::binary_to_term(bytes)` has no opts; `enif_binary_to_term` drops its `_opts`, `../../beam_abi/src/nif/enif/mem.rs:805`), so a native-floor arm would duplicate the registry BIF and a post-decode walk is not the C's decode-time predicate.
Closing it needs an active-export predicate threaded into `beam_codec`'s decode: a new defaulted `beam_bifs::BifContext` seam (e.g. `is_active_export(module,function,arity)`) that `binconv::decode_term_bif` installs on `DecodeOptions`/`Decoder` (which is `Copy`, so a trait object cannot ride it) and `decode_export` (`../../beam_codec/src/decode/fun.rs:79`) consults, implemented here from `CodeServer::is_loaded` + the loaded `Module::exports`.
Corpus-unobserved: the `[safe]` cases use a valid export (`wire_extra/b2t_safe_export_fun_image`/`_call`) or the atom-name half (`wire_extra/b2t_safe_nested_new_atom_reject`, `bin2term/safe_*`).
## Reference aliases
A send to a reference that is not a live alias is a typed `badarg` where the C silently drops it; `monitor(process, self(), [{alias,_}])` registers where the C clears it for a self-monitor; the bare-reference and monitor/alias id spaces are bridged by provenance.
Unclosable residual: reference identity — a bare reference and a monitor/alias reference with equal ids are `=:=`. Detail: `src/runtime/CONTEXT.md`.
## Ports, drivers and the send family (A.4)
Read path: one `{Port, {data, Data}}` per driver read, at the width the child wrote (`binary`→up to `beam_io`'s `READ_CHUNK`, 64 KiB, per `read(2)`; `list`→char list).
Child stderr is inherited by default, never port data; `stderr_to_stdout` duplicates fd 2 onto fd 1, so its diagnostics arrive as port data in true write order.
`connected` flips to `false` only at `port_close/1`; `os:cmd/1` stays a runtime-native host spawn.
`{spawn_driver, Name}` resolves the name against the emulator's **static** driver set (`beam_io::STATIC_SPAWN_DRIVERS`: `tcp_inet`/`udp_inet`/`ram_file_drv`) before any `dlopen`, as the C does (`io.c:599-628`); `fd`/`efile` are this crate's internal drivers and are `badarg` here exactly as on the oracle, an invented name too — then the loaded-driver list and the object-path search.
A driver port's `driver_output` reaches its owner as `{Port, {data, Data}}`, and a driver-emitted `erl_drv_output_term`/`erl_drv_send_term` term reaches the connected process or an explicit destination (`TermQueue` drain wired end to end).
The driver C ABI is live: `driver_select` real, `driver_set_timer` armed for every attached port, an `OUTPUT` port task always draining the output queue through the single write path *then* running the entry's `ready_output` as a write-readiness notification, the `control` callback behind `erlang:port_control/3`, `ERL_DRV_USE`'s `stop_select` on cancel/deselect handback, and the driver-private queue (`driver_enq`/`pushq`/`deq`/`sizeq`/`peekq`), `driver_pdl_create`, the port state flags (`get_port_flags`/`set_control_flags`) and the process-monitor family (`driver_monitor_process`/`_demonitor_process`/`_get_monitored_process` over the per-port monitor tree, `monitor_process_result`'s three-way answer from the published `ProcessLiveness` view) — 28 of the 41 `DriverHost` hooks.
Typed gaps: `driver_async` (no async pool; `Runtime` is `!Send`, the `invoke`/`free` pair is `unsafe`, `async_port_key` defaults to `-1`); a `control` reply answered from the driver's own memory (needs a safe copy helper on `beam_abi`); a NULL driver reply with `PORT_CONTROL_FLAG_BINARY` set (`<<>>` where the C answers `[]`); an OS child (`os_pid` `undefined` for a driver port, `take_exit_status` always `Ok(None)`); a driver arming more than one registration per direction (typed `unsupported`).
`erlang:port_control/3` is gated on the **driver's own** `control` capability (`PortMeta::has_driver_control` = `beam_io::Driver::has_control()`, the ABI adapter answering the loaded entry's own `control` slot, captured into the port's metadata **when the port is opened** — the boxed driver then moves into the port registry, unreachable — no driver-name table is involved): a driver with no `control` callback — and every internal `spawn`/`spawn_executable`/`fd` port — is the oracle's `error:badarg` for every verb (the C's `prt->drv_ptr->control != NULL`, `io.c:4035`), while a control-bearing driver still answers.
The numeric→named `inet` control-opcode bridge (`beam_io`) is adopted end to end: **160** datagram/option/`recv`/`send`/`close`/interface/name-service shapes through `erlang:port_control/3` agree byte-for-byte with the oracle (`src/port/inet_matrix_tests.rs`, eight families, one port-state sequence per family on both runtimes) — including `INET_REQ_SUBSCRIBE`'s three answers (`[1]`, `[1,1,0,0,0,0]`, `badarg`), `FDOPEN`'s pre-adoption check (`[0]` + the descriptor's own errno), `getservbyname`/`getservbyport`, `GETIFLIST`/`IFGET`/`IFSET`/`GETIFADDRS` and `getopts`' truncate-and-continue (`inet_drv.c:9734-9741`).
Residual shapes stay typed with the oracle's answer recorded beside them: `PACKET_REQ_RECV`'s async op-id (the synchronous read-now substitution — oracle `[1,0,0]`, this runtime `[1]`) and an `INET_REQ_OPEN` of a non-`AF_INET` family (oracle `[1]`, this runtime `[0]eafnosupport`); three shapes are typed gaps no oracle column can pin — `FDOPEN`'s adoption form, `ignorefd` (28) and `tcp_sendfile` (45) on a *connected* stream — each asserted to name its request, never a fabricated reply.
`{packet, N}` framing is adopted (A.4) for the `spawn`/`spawn_executable`/`fd` family (`src/port/packet.rs`): `N ∈ {1,2,4}` (anything else `badarg`, `stream` cancels, `line`+`packet` `badarg`) is a big-endian length header on the way out (written even for an empty payload) and packet reassembly on the way in (one `{Port,{data,…}}` per complete packet, a partial packet buffered across reads and dropped at end of stream, a zero-length packet as an empty payload), both counters counting payload bytes only.
A **driver** port is not framed by the emulator (its `packet` option belongs to the driver), matching the oracle; `{packet,1}` over 255 bytes / `{packet,2}` over 65535 are the typed `unsupported` gaps where the C kills the port with `einval`.
`line`/`{line, N}` framing is adopted (A.4) too: `open_port/2` decodes the option into `PortOptions::line` (bare `line` ⇒ `512`; `{line, N}` a positive small integer, else `badarg`; mutually exclusive with `{packet, N}` and with `stderr_to_stdout` unless `use_stdio`), the port-task round's `take_line_notifications()` is delivered as the oracle's `{Port,{data,{eol|noeol,Data}}}` frames, and `StreamType::port_flags` reports `PORT_FLAG_BINARY`/`PORT_FLAG_LINE` independently (`[line]` ⇒ `2`, `[binary]` ⇒ `1`, `[binary,line]` ⇒ `3`).
The driver hook table, the driver-private queue, `TermQueue` and the framing/reassembly layers: [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
`erl_ddll` is served (A.4) from one loaded-driver view: `loaded_drivers/0`/`try_load/3`/`try_unload/2`/`info/2` come from the native floor (`src/native/ddll.rs`) over the one name-keyed loaded-driver registry `src/port/driver.rs` keeps — the same list `open_port({spawn_driver, Name})` resolves against — while `monitor/2`/`demonitor/1`/`format_error/1` fall through to `beam_bifs`.
`loaded_drivers/0` lists the three statically-linked built-ins (`tcp_inet`/`udp_inet`/`ram_file_drv`) first, then the dynamically loaded names in load order, matching the oracle; a static name's `try_load`/`try_unload` answer `{error,linked_in_driver}` and its `info/2` takes the C's `handle == NULL` branch.
With no `erl_ddll:load_driver/*`, `Name` doubles as the `open_port` search (a `/`-containing name is an object path, driver name = its file stem; else `<name>.so`).
The send family serves `erlang:send/2` and `erlang:'!'/2` (`SendBridge`); `erlang:send(Port, Data)` needs the port write path and a distributed `{Name, Node}` send is contract A.5 — both raise `unsupported: …`, never a fabricated value.
Monitor shape: *Port monitors (A.4)* and *`beam_io` / `beam_abi` lifecycle*.
## Distribution and the node (A.5)
`-name`/`-sname` make the runtime a distributed node: `DistNode` binds a wildcard listener, publishes to `epmd` best-effort (a failed publish is recorded, never fatal) and completes the server-side `'N'` handshake against a real OTP peer (`tests/dist.rs`).
Gaps: no `net_kernel` protocol; the distributed-spawn family (`SpawnRequest`/`SpawnReply`), `Delivery::Other(_)` and the ack-owing `UnlinkId` half stay typed `Unsupported`; `node/0` and the node atom pid image do reflect the live `-name`/`-sname` node, but `NodeIdentity` reports creation `0` (*Placeholders*), so a decoded local id is external (see the `beam_codec`/`beam_bifs` handoff).
`DOP_SEND`/`DOP_REG_SEND` reach local mailboxes through `LocalDeliverySink`, as do the route-free receipt families (link/exit/unlink/monitor/demonitor/group-leader), each emitting no outbound `DOP_*`, gated by `Runtime::inbound_delivery` (default ON; `Runtime::allow_inbound_delivery` turns it off).
No Erlang-level distribution subtree runs on a `-sname`/`-name` node: the native floor answers `erl_distribution:start_link/0,1` with `ignore` (distribution is the native `DistNode` the CLI binds and publishes to `epmd`), so `kernel_sup` skips `net_sup`.
Measured on a `-sname` node: `whereis(net_sup)`/`whereis(net_kernel)`/`whereis(auth)` are `undefined` here vs pids on the oracle, while `whereis(kernel_sup)`/`whereis(application_controller)`/`whereis(logger)` are pids on both, `whereis(timer_server)` is `undefined` on both, and `node()`/`is_alive()` agree. Mechanism: `src/native/CONTEXT.md` *The Erlang-level distribution supervisor*.
## Timers
`send_after/3` answers `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)`/a bad time or destination `badarg`.
`send_after/3`/`cancel_timer/1` are native-floor capabilities; `send_after/4`, `cancel_timer/2`, `start_timer/3,4` (relative, and `{abs,true}` whose delay is computed from registered `erlang:monotonic_time/0` against the oracle's `start_time`/`end_time` millisecond window), `function_exported/3`, `link/1`/`unlink/1` and `os:set_signal/2` come from `RuntimeHooksBridge`.
Unimplemented: `erlang:system_info/2`, `read_timer/1,2` and every other roster key the bridge does not serve (`delete_module/1`/`purge_module/2`, `port_get_data/1`/`port_set_data/2`, `term_to_iovec/1,2`, `erlang:is_builtin/3`, `bump_reductions/1`, `loaded/0`, …), each a typed `unsupported` gap — the served/closable/not-closable split is [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Closable host-seam keys*.

## GC / heap model
`DEFAULT_HEAP_WORDS` is `1 << 24` (16 Mi words of lazily-mapped address space).
Term-construction heaps (BIF-heap pool + `-eval` heap) are bump arenas sized `config.heap_words`; `+hmax N` caps that capacity (`runtime.rs::term_heap_words`); the `system_limit` translation runs after the copy engine's retry, so `deliver_message` matches a raw `AllocKind::Message` for the heap-fragment retry.
This crate does drive `beam_gc`: a *scheduled* process allocates on its own young heap and is collected at `ExecutionContext::ensure_heap`/`ensure_heap_full` (both share `collect_or_grow`; the latter is the full-root door `test_heap` reaches, armed by the slice's `BudgetContext`), pinned by `tests/gc_collect.rs` and reported by `Runtime::gc_stats()`; every other context no-ops on the unbounded arena.
Measured limit: a workload allocating only through `ExecutionContext::alloc_words` (no `test_heap` admission point, as real Cowboy `cowboy_bstr`-style code does) is not collected by *that* door — it grows the nursery and retries the bump (arena only when growth cannot reach it), and `Process::collection_debt` becomes a real collection at the *next* admission point — so with no boundary pre-emption either, it reaches the term heap's hard limit with no collection at all (`collections: 0`). The **reduction/yield-boundary door** (`src/context/gc/reds_door.rs`, from the runner's `Yield` arm) is the site that collects such a loop: it fires once per `REDS_BOUNDARY_MIN_REDS` reductions over a nursery **seven eighths** occupied (the C's `ERTS_VBUMP_ALLOC_REDS` "allocation area exhausted" rule; retuned from 1/2 after the `gc_bound` churn shape was measured to pay +0.69 % collections and +8.9 % majors/call at 1/2, and exactly 0 at 7/8), so a shape that pre-empts is collected where it previously ran forever — measured 0 → 0.005 collections/call on `etf_roundtrip` at a flat 376-word nursery against 3.58 M words door-off, and its cost on every other hot shape (all per-call, ON vs OFF from one build) is [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*. Optional cross-node handoff (recorded, not required): the only residue of the old cost is `ets_copy` on the **interpreter** tier (`collections/call` +0.000400, `major/call` +0.000600 against the door-off 0.000100, down from +0.000800 at 1/2) — 16 extra collections over 40 000 calls. Removing it needs a **policy-kind** collection request ("collect young-only unless a fullsweep is due"): `beam_process::Process::collect()` (`src/collector.rs`) picks minor-vs-major from `beam_gc`'s own policy, so the door at `src/context/gc/reds_door.rs` cannot say "young only". The needed API is `Process::collect_kind(CollectionKind::Minor)` (or a `Collector::collect_young()` entry) that the door passes `CollectionKind::Minor` unless `BeamGcPolicy::fullsweep_due` — a `beam_process`/`beam_gc` change, not an in-crate one, and measured to be worth 0.0006 majors/call on one interpreter-tier shape.
A second collection site on a shape that already collects per iteration costs more than its hit rate: on `gc_bound` churn the door adds +0.048 collections/call (+0.69 %) but +8.9 % `major`/call (1.497 → 1.631), because its action is a full `Process::collect()` rather than a young-only collection (the numbers, the mechanism and the candidate policy fix are the *Measured* section's finding; owner: `beam_rt` runner/GC policy with `beam_gc` for the which-collection choice).
A live float register is never left unrooted (the full-root doors publish the machine's live leading FR prefix, `Machine::fr_mark()`, so it lies inside the x file's pointer-bearing bound); a failed collection halts that process's collection, never the program.

**Retained-space caution:** `Process::grow_nursery` retires the space it replaces and only a real collection collapses that chain, so a *genuinely* present foreign root **with** children keeps a process's capacity growing with its admission-point count (a `beam_process` policy matter — `should_collect` ignores the chain).
A **childless** foreign boxed leaf does not: the unscanned-root valve exempts it (`context/gc.rs::foreign_boxed_has_copy_children`), so a reference-minting loop runs at a flat `memory(processes)` of 6.91 MB across N = 20 000 / 200 000 / 1 000 000, against the oracle's 13.7 MB and the pre-exemption 13.77 / 43.26 / 170.09 MB (`context/gc/refs_plateau.rs`).
Term-heap capacity stays the hard limit for anything not collected: both exhaustion classes become `error::system_limit` via `error::enforce_term_heap_limit` — `AllocKind::Heap` (the per-process bump allocator) and `AllocKind::Message` (the copy engine's destination-heap exhaustion, classified by `beam_message::is_message_heap_exhaustion`) → CLI `beam_rt: system_limit`, exit 1.
On-demand growth is adopted at the admission point and on the `beam_process` delivery path: `ensure_heap`/`ensure_heap_full` run `Process::ensure_capacity` when the policy can reach it (`HeapPolicy::next_words(need, 0) >= need`), plain `Process::collect` otherwise — so a `test_heap` request larger than the nursery is admitted by growing it in place (`tests/heap_growth.rs`), while a bounded `+hmax N` request it cannot reach is refused *before* collecting (the collection runs, the allocation falls back to the arena); `Process::deliver` grows the nursery the same way for a refused message copy (the raw `AllocKind::Message` `deliver_message` keys its heap-fragment fallback on), and a relocation-exempt receiver skips the retry entirely.
Allocation outside an admission point uses bounded `beam_alloc::Heap` arenas that never move (`BifContext::heap()`, `Runtime::eval_heap`), so a BIF's *intermediate* terms are invisible to `roots` and cannot be collected; a call overflowing such a heap raises `error::system_limit`.
The one growth seam outside an admission point is the pooled BIF-heap frontier on the table-less (`-eval`/nested) route — `RuntimeContext::take_bif_frontier` retires a near-full region and continues in a larger one (capped only by an explicit `+hmax`) ([`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *The pooled BIF-heap frontier*).
### The BIF-result copy-out
A registered BIF builds its result on the runtime's pooled 16 MiB `Runtime::bif_heaps` (`Runtime::take_bif_heap`) — `Target::Foreign`, unscanned by the process collector — so a container left there is a root the valve declines over while it is live.
`RuntimeContext::call_registered` (`src/context/calls.rs`) therefore moves the result onto the running process's own young heap (`Process::heap_mut()`, collector-scanned) — or, with no scheduled process, onto the runtime's long-lived `-eval` store (`src/context/pool.rs::move_result_into_runtime_store`) — and rewinds the pool to the call's pre-offset, so the result lands in `x(0)` (an engine-published root) — but only when the move is safe and complete: no escaping `DispatchHooks` arm (`dict`/`process_hook`/`nif_loader`/`send_hook`/`persistent_term`/`runtime_hooks`, each letting a `ctx.heap()` term escape into state outliving the call), no reentrant fun-applying call, an `Ok` result (a raise may carry a `live_reason` term pointing into this heap, so the error path never rewinds), a copy that succeeded (a refusal leaves both untouched) and a container result (`result_is_foreign_container`; an immediate is unboxed and a literal lives in the frozen literal area, so such a result rewinds uncopied).
An empty source table is load-bearing: an ownable refc binary flattens to a self-contained on-heap bitstring (byte-faithful), while an ownerless off-heap MSO reference is the copier's typed `bad_term`, so the move answers `None` — pool unrewound, never a dangling payload.
Residuals: a NIF result is not copied out (deliberate M1 residual), so it stays on the pooled heap and keeps declining collection while live; an escaping `DispatchHooks` arm and an error result also leave their container on the pooled (`Target::Foreign`) heap; on the table-less route the `-eval` store absorbs a kept result's words and only ever grows; a nested cross-module run (`RuntimeContext::run_export`) never reaches a collection point.
Closing this needs either a `beam_process` seam that can shrink/reuse retired young space or a `beam_engine`/runner seam that publishes the driving machine's roots at a BIF call so the copy-out can collect — both sibling-crate changes, reported not worked around.
Arms, the per-attempt fresh `OffHeapTable`, the `grow_nursery` hint and the rewind's soundness: [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Per-call cost of a registered call* / *The table-less arm and its store*.
Pinned by `src/context/tests.rs` (`a_bif_container_result_is_moved_onto_the_process_heap_and_the_pool_is_rewound`, `an_immediate_result_rewinds_the_pool_without_a_copy`, `an_escaping_arm_neither_moves_the_result_nor_rewinds_the_pool`, `a_bif_result_on_the_process_heap_lets_the_churn_loop_be_collected`, `a_partially_used_pool_is_rewound_to_the_callers_mark`, `an_escaping_arm_does_not_rewind_a_partially_used_pool`).
### `ets_copy` peak RSS
`copy_bound/ets_copy`'s peak RSS is linear in N (**94.68 MiB at N = 100 000, ≈99 words per iteration**) — a structural limit of the copy-out above, not of the ETS adopt path: `safe_to_rewind` is `true` for `ets:*` and the pooled heap is rewound, so it tracks BIF calls, not floats and not ETS table state (a float-free ETS loop of the same shape grows identically; a float-carrying churn loop with no ETS is flat).
The copy-out cannot collect (the machine's x registers / Erlang stack are unpublished at a BIF call), so a full nursery is met by `Process::grow_nursery(hint)` (`src/context/calls.rs::move_result_into_process_heap`) and the retired young space is retained, the capacity accumulating linearly; no real collection is reached (`ensure_heap_full` returns at `!process.should_collect(heap_need)`, its `test_heap` prefixes being tiny against a 233-word default nursery, and `alloc_words_rooted` is never entered).
The caller-module float guard is not the mover (relaxing it at the two FR-publishing GC doors changes nothing here and contradicts the pinned float-collection contract, `tests/gc_collect.rs`).
Closing it needs the same two sibling-crate seams as *The BIF-result copy-out*; figures and bisection: `PERF_DISPATCH.md` *COPY-OUT-CUT*.
## Heap switches
`+hms`/`+hmbs` set `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000`→1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1.
`+hmax N` reaches the policy the process actually runs under on **every** route: the CLI value (`src/cli.rs` → `HeapOptions::set_max_heap_words` → `RuntimeConfig::heap`) is cloned by `Runtime::default_spawn_policy`/the boot-time spawns (`src/runtime.rs`) into the `beam_process::Process` the collector owns, and `spawn_opt`'s `{max_heap_size,…}` is installed by `SpawnOptions::policy` (`src/native/process.rs`) on the same field; `Runtime::new`'s `EmulatorDefault`/`Immix` resolution rewrites only `initial_mature_words`. Both are observable: `process_info(P, max_heap_size)` and `system_info(max_heap_size)` report the oracle's map.
What `+hmax` does **not** bound is the nursery **chain**. `beam_gc`'s `Nursery::grow` clamps the space it *installs* to `HeapPolicy::max_heap_words` but **retains** the space it replaces (`beam_gc/src/nursery.rs:269-302`), and only a collection collapses the chain (`:329`); the reported `heap_size` is the chain's summed capacity (`:190-192`). A loop that reaches no heap-admission point (`test_heap`/`allocate_heap`) therefore appends one retired space per exhaustion and its `heap_size` grows linearly with N, past the cap by orders of magnitude: `grow3:main/1` (`list_to_tuple(lists:seq(1,400))` per iteration, no `test_heap`) reads `{heap_size, 1 268 309}` at N = 1 000, `{heap_size, 25 008 309}` at N = 20 000 and `{heap_size, 62 508 309}` at N = 50 000 under `+hmax 20000`, with `collections` stuck at 19 (the entry round only) — against the oracle's flat `{heap_size,1598},{total_heap_size,2585},{collections,20342}` at `+hmax 0` and an exit-1 empty-output kill under `+hmax 20000`. The two seams that grow without being able to collect are `src/context/gc.rs::alloc_words` (the unrooted engine sink) and `src/context/calls.rs::move_result_into_process_heap` (the BIF-result copy-out); both are unrooted by construction, so the cumulative ceiling is `beam_gc`'s to enforce — see *Cross-node handoff detail*.
`process_flag(max_heap_size, #{size=>N,…})` and the legacy `process_flag(max_heap_size, N)` are **not** implemented: both answer `badarg` (exit 1) where the oracle succeeds and returns the previous map (`#{error_logger=>true,include_shared_binaries=>false,kill=>true,size=>0}`), so a program setting its own ceiling gets a raised error rather than a silently ignored cap.
## CLI `run` argument tokens
`beam_rt run <beam> <m>:<f>/<a> <arg…>` materializes an integer token with `beam_term::make_small` (`src/runtime.rs::materialize`, reached from `src/cli.rs::parse_arg_term`'s `i64` arm) without a range check: a token above `MAX_SMALL` (`2^59 - 1`) aborts on the `debug_assert` in a debug build (`beam_term/src/immediate.rs:77`, exit 101) and is silently truncated to a wrong small int in a release build — `… bm:mk64/1 576460752303423488` prints `<<248,0,0,0,0,0,0,0>>` where the oracle prints `<<8,0,0,0,0,0,0,0>>`, a wrong result, the one class the runtime forbids.
The fix belongs in those two files: range-check the parse and build a bignum (or reject the token), via `beam_term::try_make_small` + the bignum writer — the same range check `src/cli.rs` applies to `+hmax` (`src/cli.rs:778`).
`tests/bignum_bit_segment.rs` documents the hazard and reaches the same segment through a string token instead; the `-eval` route is unaffected (its integer literals are exact bignums).
## Cross-node handoff detail

### The `-eval` vs scheduled asymmetry
The `-eval` action process pumps the scheduler and can suspend a blocking call; a scheduled process (`run`) parks at its own top-level `receive`.
A scheduled slice is *running*, not runnable (`beam_process::Scheduler::slice_begin` flips the pid to `ProcessState::Running`), so a signal- or delivery-driven collection of it is declined (*GC-relocation hazards*).
A `spawn`ed `-eval` closure is run synchronously to completion, so it is not a nested run that suspends: the evaluator (`src/eval/mod.rs`, `apply_eval_closure`) drives the closure to its end before the spawning expression continues, and the context it is applied on is the slice's own (`may_pump_scheduler` false), so a `receive … after T` **inside the closure** scans the mailbox, makes one port-poller pass and takes its `after` body.
The `-eval` action's **own** `receive … after T` runs outside any slice and spends its window on three message sources — a mailbox rescan, a bounded scheduler pump (`RECEIVE_PUMP_SLICES = 64`) and `Runtime::wait_for_timer`, the runtime's **timer heap** (`erlang:send_after/3`/`timer:apply_after/4`); the wait sleeps to the earliest pending deadline (or the window end) and fires it, so a due deadline delivers its message and a bare `receive _ -> ok after 300 -> ok end` takes its 300 ms.
A `-eval` child that "parks" therefore returns and terminates before the parent's next statement — hence the async-completion shape for a live, blocked target is pinned only on the scheduled route (`tests/garbage_collect.rs`).
## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers the running process's own young heap (a capacity refusal met by a no-relocation `Process::grow_nursery` and one retry) and falls back to the pointer-stable `Runtime::arena`; the roster below splits *at risk* from *safe* — what a moving heap would dangle is a raw `Eterm` pinned outside the GC root set.
`Process::regs` is a snapshot, not a live mirror: `publish_roots_full`/`scatter_roots_full` (`context/gc.rs`) copy the x file's **pointer-bearing prefix**, the whole stack and the FR prefix (bounded by `fr_count`) at every full-root admission point (`gc::ensure_heap_full`/`alloc_words_rooted`, bound `gc.rs::machine_root_bounds`) or at a **publishing** (non-exempt) park, so a collection rooted in it reaches x/stack/FR and nothing else — a Rust local or un-published `Machine` field is not in the root set; the engine's `live` count is ignored (over-approximating a copying collector's root set is always safe).
Snapshot mechanics, the per-trigger refusal chain (`run_rooted_collection`, `Runtime::serve_gc_request`, the gate's latch cell) and the full *at risk* / *safe* roster: [`IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *What a MOVING engine heap would invalidate*.
Three collect triggers differ in exposure. The admission-point collection *is* the publish/collect/scatter hand-off (safe).
The delivery- and signal-driven ones fire outside admission and are refused for a receiver with unpublished roots (`Process::has_unpublished_roots()` = `relocation_exempt || state == Running`, `process.rs:1098`, tested *first* by every caller: a refused delivery becomes a heap-fragment delivery, a refused ptab signal goes to `enqueue_fragment_signal`), and `beam_rt` adds a second refusal through `delivery_collection_is_unsound` — the fifth collection site; a signal to a woken-but-not-yet-resumed (`Runnable`) receiver is declined by the host collection gate `RuntimeCollectionGate`.
The `Yield` pre-emption arm is exempt exactly when its slice ended with a live FR prefix (`fr_count > 0`): an exempt (and every Wait) park publishes nothing and its `Runtime::serve_gc_request` is declined by the exemption it just set, while a non-exempt park publishes first, then serves.
The residual exposure is a live term held outside `process.regs` — a Rust local, or an engine `Machine` field with no extra-root publication — hence `relocation_exempt` (`self()`, the wrapped `-eval`/nested-`Machine` scope, the parked window; the five wrapped scopes and the parked/slice pin rules are [`IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Relocation exemption* / *What a MOVING engine heap would invalidate*).
A collection is DECLINED whenever a root — or a container the scanned graph reaches — lives in a region the collector does not scan (the unscanned-root valve): `RuntimeContext::call_registered` (`src/context/mod.rs`) hands `beam_bifs` the pooled 16 MiB `Runtime::bif_heaps`, and `context::gc::alloc_words`'s fallback hands blocks out of `Runtime::arena`, both `Target::Foreign` (`beam_gc/src/copy.rs`: a pointer outside `FromSet` is left as-is, unscanned).
The valve's two phases (`root_is_unscanned`, then the `gc_walk.rs` descent under the sticky, add-only per-pid latch, finding a foreign container at depth ≥ 2), its latch's open sites and pass-boundary prune, and its per-admission cost are [`IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *The unscanned-root valve — two phases* / *Debt/valve cost of the admission doors*. The roots it spans are the machine roots the caller publishes (`x`/stack/FR) plus the process's own root-set containers (`Process::collect`'s registers, mailbox, dict, saved arguments and pending signals).
Each of the three admission points (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`), the runner's park arm (`Runtime::serve_gc_request`) and the delivery seam (`delivery_collection_is_unsound`) declines (`Ok(())`) a collection whose root set reaches anything else, while unrooted `context::gc::alloc_words` keeps its arena fallback.
Both allocation doors try the owner's young heap first (a non-forced capacity refusal `Process::grow_nursery`s and retries the bump) **before** the valve and the arena; growth relocates nothing (legal against any root set) and leaves the `Process::collection_debt` the next admission point's occupancy test turns into a real collection, so only an unreachable or forced request reaches the valve.
The latch's raison d'être is `Runtime::bif_heaps`: a container a registered BIF built there (`erlang:'++'/2`, `lists:append/2`, `lists:reverse/1`, `lists:filter/2`, `ctx.tuple(…)`) writes the caller's heap `Eterm`s verbatim, and a scheduled process's container result leaves the pool (*The BIF-result copy-out*), so the holder is reached through the unrewound paths (a NIF result, an escaping `DispatchHooks` arm's result, the `-eval`/nested shape, an error result) at depth ≥ 2 below a scanned root.
Verified end to end: `beam_rt run w.beam w:f9/0` renders the oracle's exact `~w` at exit 0 and `tests/gc_run.rs` passes; the descent is pinned by `src/context/tests.rs::{the_valve_declines_a_foreign_container_nested_in_a_scanned_container, …_a_deeply_nested_foreign_container, …_collects_when_the_nested_graph_is_fully_scanned}` (the first two fail with the descent forced off).
