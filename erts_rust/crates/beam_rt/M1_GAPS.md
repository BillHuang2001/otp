# `beam_rt` — Known M1 Gaps & Cross-Node Handoff Detail

Per-item detail behind [`CONTEXT.md`](CONTEXT.md)'s condensed `Known Issues / Intentional M1 gaps` bullets, cross-node handoffs and GC-relocation hazards.
Every gap is a typed capability gap or a measured own-state difference — never a wrong result.
Present-state documentation, not a change log.

## Dispatch, atoms and module introspection
* **Shared-`AtomTable` cloning.** `call_registered`/`try_call_nif` commit pending names via `code_server.atoms_mut()` (`Rc::make_mut`) only when `PendingInterner::is_empty()` is false; the port/persistent-term/NIF handles hold the strong count at 2+, so an unconditional clone copies the table per call, and only a really-interning call pays the copy-on-write.
* **Two `get_module_info` divergences.** `exports` uses `Module::exports` order, not the oracle's global ERTS export-table order (`erl_bif_info.c:8434-8471`), so the differential test compares an unordered set; `get_module_info(M, ...)` raises `badarg` for a module not loaded here (`lists` diverges by module-load state, not seam).
* **`erlang:module_loaded/1`** is truthful to *this* runtime's loaded set (`preloaded() || CodeServer::is_loaded`; `CodeServer::load` memoizes into the same map); the only residual is boot-set size — oracle ~109 modules vs this runtime's 22 preloaded `.beam`s, so `module_loaded(lists)` stays `false` until `lists` loads (`tests/module_loaded.rs`).

## Own-state answers (differ by construction, not bugs)
* `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)`, the `persistent_term`/`get_module_info` figures. `erlang:whereis(init)` does agree (the root process; oracle `<0.0>`).
* **Minor divergences (all outside this node unless noted).** `persistent_term:info/0`'s `memory` is this runtime's own word total (`count` exact). The process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})` → `undefined` here vs `1` in the oracle. `register/2` of an internal PORT id = typed gap. `process_flag(save_calls, <non-integer>)` returns the previous value where the oracle raises `badarg` (`bif.c:1911`).

## Placeholders where a truthful source exists
* **`NodeIdentity`'s creation is a fixed `0`** (`src/context/bridges.rs`) where a live `crate::dist::DistNode::creation()` exists, so an internal pid/port image still encodes creation `0` on a wired node; the node atom beside it *is* the runtime's live `Runtime::local_node()`, stamped on every `call_registered` arm.
* **Flag-driven `system_info` literals** (`src/info/system.rs`: `port_parallelism`, `break_ignored`, `modified_timing_level`, `halt_flush_timeout`; `src/info/limits.rs`: `dist_buf_busy_limit`, `delayed_node_table_gc`) report their default — no A.6 CLI arm preserves the driving flag (`+spp`/`+B`/`+T`/`-shutdown_time`/`+zdbbl`/`+zdntgc`), and `cli.rs::record_unmodeled` drops an unmodeled `+flag`, leaving no state to derive from.
* **`process_info(P, last_calls)`** answers `false` although the runtime holds the real `save_calls` flag (`beam_process::Process::save_calls`).

## Process-control families (`src/native/`)
`erlang:monitor/2,3` serves a process target (a pid, a registered name, or a `{Name, Node}` pair on this node) and a port target: a port monitor is recorded on the runtime's live port table (`PortRegistry::port_table_mut` → `ProcessTable::monitor_port_term_with_tag`, the table `open_port/2` allocates from), so its `{'DOWN', Ref, port, Port, Reason}` fires when the port closes.
`erlang:monitor/3`'s `{tag, T}` option is served on both paths for an immediately-representable tag; a heap-resident tag is `beam_process`'s typed `error::unsupported_tag`.
Two monitor gaps remain: a named port monitor `monitor(port, Name)` (`error::named_port_monitor` — the local registry resolves names to processes only) and a remote `{Name, Node}` monitor (contract A.5).
`exit/2,3` matches the oracle except an internal port target answers `true` without closing the port, and a foreign/decoded reference or ETS id is `badarg` vs the oracle's `true`.
`spawn_opt`'s `{scheduler, N}`/`{async_dist, B}` stay `unsupported`; every other option is applied for real.

## ETS ownership
`ets:new/2` records the calling process as owner (`beam_ets::Table::set_owner`) and installs the parsed `{heir, …}`; `ets:info(T, owner)`/`heir` render the recorded pids (`undefined` when unset), `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner.
A dead owner's table is reclaimed through the `beam_process` `ProcessExitObserver` seam: the observer records the dead pid, and `Runtime::drain_ets_owner_exits` releases every table it owned — dropped, or handed to its heir with the oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for the 2-tuple `{heir, Pid}` form, which carries no data; an arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`).
`tests/ets_owner.rs` oracle-cross-checks the flows.
The public owner→handle roster is the authority, so *unnamed* tables are reclaimed too: `beam_bifs::TableRegistry::handles_owned_by(TableRegistry::owner_of(dead))` lists every live table recorded as owned by the dead pid (its handle is the registry key, reachable from no public term otherwise); the `ets:new/2`-time index is unioned in only for a `named_table`'s registered name, released with `TableRegistry::remove_name`.
An unnamed table's tid in the transfer message is this runtime's own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`, a fresh `RefAllocator` walked to the handle, the runtime's ref id space differing from `beam_bifs`'s).
**Remaining live gap: `ets:setopts/2`'s gift data.** `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs an `{heir, …}` option through `beam_ets::Table::setopts`, which stores the gift term verbatim where `beam_ets::Table::install_heir` (a table-owned deep copy) is meant; the drain then hands a term still aliasing the dead heap to a `{'ETS-TRANSFER', …, Data}` message (the `ets:new/2` build path copies, so creation is safe).
Fix belongs in `beam_bifs` (or `beam_ets`, by making `setopts` copy); `Runtime::own_heir_gift` mitigates the `ets:new/2` path only and records a failed `Table::install_heir` on the owner index (logged, then returned as the typed error by the next `drain_ets_owner_exits` *after* every death is discharged), so a failed copy is never silently dropped.
A monitor whose watching process is dead is swept by the same drain (`ProcessExit::ets_monitors`).

## Port monitors (A.4)
`erlang:monitor/2` on a port records an incoming entry on the port; a watcher that dies first is swept through the same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so a port never keeps a monitor for a dead process (`tests/port_monitor_cleanup.rs` is the discriminating white-box pin; a *surviving* watcher's monitor is kept).
`erlang:port_info(Port, monitors)` reads the always-empty `PortMeta.monitors` — the oracle returns `[]` even with a live watcher, so that matches and must not change.

## `process_info/1,2`
Heap items read the target process's own policy (`Process::collector().policy()`), so a `spawn_opt` min-heap / `fullsweep_after` / `max_heap_size` is observable.
Two `max_heap_size`-map divergences remain: this runtime's key order is `kill, error_logger, include_shared_binaries, size` (oracle: `error_logger, include_shared_binaries, kill, size`), and the per-map flags go unhonoured.
~28 items answer from own state (catalog `src/native/CONTEXT.md`); the four execution-position items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) answer for a scheduled process (a parked one probed from another process; the executing one for its own query from compiled code, through the in-machine BIF door) and are omitted for a process this runtime gave no position (a fun-bodied process with no resolved local target, a never-scheduled pid, a direct/no-machine caller); `catchlevel` follows the same rule.
Two door residuals: `initial_call` is the machine's entry MFA where the oracle answers `{erlang,apply,2}` for some spawn shapes (a fun-valued spawn, a start instruction); the published slot is runtime-wide, so a nested fun-applied run inside its window reads the *outer* machine's position for that pid.
Any other valid oracle item it cannot answer (`magic_ref`, `priority_messages`, ...) is the typed `unsupported`.
`registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact; `total_heap_size` is 466 (vs the oracle's 233); `memory`/`reductions`/`group_leader` are own figures.
A pid not in the table → `undefined`; an unknown item or a non-pid → `badarg`.
`trace`/`message_queue_data`/`last_calls` read real state: `trace` serves the live per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])`, the oracle's integer shape translated from this runtime's internal bits by `src/trace.rs::flags_to_atoms`'s table); `message_queue_data`/`last_calls` report real placement/saved-calls state (`on_heap`/`false`).
One divergence left: `process_flag(message_queue_data, off_heap)` is accepted-and-ignored, so such a process still reports `on_heap` (per-process storage in `beam_process` is a cross-crate handoff).

## Printing
The `io` device request wrappers are served by the native floor (`src/native/io.rs`): `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:put_chars/1,2`.
Each wraps `io.erl`'s `o_request/2`, posting `{io_request, …}` to the request's device — the caller's `group_leader()`, i.e. itself for this runtime's own root process — and blocking for `{io_reply, …}`; `execute_request/3` answers `{error, calling_self}` for that self-device, so the floor answers the device question itself and renders through the registered `io_lib:format/2`, letting the installed compiler's `catch`-handler diagnostic (`io:fwrite("Function: ~w/~w\n", …)`) carry its real reason.
Device rules and per-key detail: `src/native/CONTEXT.md` *The `io` device floor*; the stdout/stderr/exit-code differential is `tests/io_device.rs`, the in-process compile diagnostic probe `tests/io_diagnostic_unmask.rs`.
Two residuals: a live non-stdio device pid is the typed `unsupported` (a BIF cannot block on the `{io_request, …}` round trip); `io:put_chars/1,2` still accepts and ignores its device, so `io:put_chars(standard_error, …)` lands on stdout where the oracle writes fd 2.
The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (or a container past ~80 columns) with `badarg`; the corpus reads such values via `bit_size/1`/`is_list`.
A segment wider than 64 bits is *unsupported*; a bignum is `system_limit`.

## Scheduler / runner
A blocked receiver resumes on a sender (send→wake→resume), a due `send_after/3` timer, or a fired `receive ... after T` deadline.
`src/runner/` returns `RunOutcome::Yield` once the per-slice budget is spent, keeping the parked `Machine` at `current_code` and letting the scheduler re-enqueue, so a hot loop is pre-empted and a second runnable process interleaves (`tests/preempt.rs`).
The budget is charged per interpreted instruction through the engine's `ExecutionContext::reduce` hook (charged *before* the instruction's body runs) and, on either tier, at the machine's heap-admission points (`ensure_heap`/`ensure_heap_full`).
`RuntimeContext::wants_reduce()` is `false`, so only the runner's `BudgetContext` charges — the non-budgeted single-pass/nested paths skip the hook call — and a non-allocating loop is pre-empted on the interpreter tier just like an allocating one.
Residual gap: the native baseline tier never crosses the per-instruction hook, so such a loop is charged only at a deopt or a heap-admission boundary, and a natively linked tail loop is not pre-empted mid-block.
Other gaps: a `receive ... after T` whose delay is `after infinity` or not a statically positive integer (a Y-register slot) still parks; a capability gap is uncatchable on the runner path.

## Execution tier (`src/runner/tier.rs`)
The tier defaults to `JitMode::Auto`: every process's first entry runs on the native baseline JIT.
No per-module predicate guards it — the engine's baseline driver handles the module-context switch (`Step::Enter` via `switch_into`) — and the one host-side obligation (the cross-module seam must be idempotent, the native `call_ext*` arm re-consulting it through the interpreter-step fallback) is enforced in `RuntimeContext::resolve_external_call`.
`BEAM_RT_TIER` (`auto` default / `baseline` / `interpreter`) overrides it, `interpreter` the kill switch.
The tier chosen at that first entry is remembered on the process (`ProcessEngine::tier`), and every later slice — a reduction-budget pre-emption or a `receive` park — resumes on it through `Machine::resume_outcome_with_tier`, so a native-tier process is never demoted mid-life.
Measured figures and commands: `src/runner/tier.rs`, `TEST_STRATEGY.md`.

## NIF (A.3)
`load_nif/2` really `dlopen`s the shared object and runs the C NIF; a load failure is the oracle's returned `{error, {Reason, Text}}`, never a raise.
`NifHostImpl` implements the runtime-independent hooks — `heap`/`intern_atom`/`atom_name`/`self_pid`, `term_to_binary`/`binary_to_term` (ETF), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is this runtime's real normal-scheduler count), `alloc_env`/`free_env`, `make_copy` as the identity — plus, through the borrowed `NifHostServices` provider (`RuntimeNifServices`: the runtime's reference-id allocator, reference registry, name table and port registry) threaded into the per-call host, `make_ref`, `whereis_pid`, `is_process_alive`/`is_current_process_alive`, `is_port_alive`, `port_command`.
The load/unload host lives in `Runtime::nifs` (it cannot borrow the runtime) with `services = None`, so every provider-backed hook stays the trait default there.
Hooks still at the trait default, each needing runtime state the host cannot reach: `priv_data` (`beam_abi`'s loader keeps the library's `void**`, so the host answers the C's null); `consume_timeslice` (`false`: the provider holds the process table immutably and the hook's `bool` cannot express "unsupported"); `send` (`None` ⇒ `enif_send` answers `0` — the most damaging remaining gap, needing a mutable process table plus a copy context); `whereis_port` (no atom can name a port here — `erlang:register/2` refuses a port — so `None` is provable); `monitor_process`/`demonitor_process` (monitors are keyed by a process watcher and a NIF resource has no process identity); `select` (a new poller/notification subsystem, not a wiring gap); `schedule_nif` (`badarg`; no dirty schedulers and no scheduling trampoline); `dynamic_resource_call` (needs a per-library `{module, name}`-keyed resource-type registry).
A second `load_nif` for a loaded module is `reload`; a NIF returning a non-term is caught by `try_call_nif` as a typed error, never an abort.

## Funs
`fun M:F/A` builds a real `FunKind::External` (`EXPORT_EXT`); a compiled-module `make_fun3` closure gets its five identity fields from `FunIdentityBridge`, so `term_to_binary/1` is byte-exact (module-scoped to the caller).
An `erl_eval` lambda stays the honest `unsupported: local_fun` (its oracle image closes over `erl_eval.erl` internals); no wrong encoding is emitted.

## Reference aliases
A send to a reference that is not a live alias is the typed `badarg` where the C silently drops it; `monitor(process, self(), [{alias,_}])` registers where the C clears the mapping for a self-monitor; the bare-reference and monitor/alias id spaces are bridged by provenance.
Unclosable residual: reference identity — a bare reference and a monitor/alias reference with equal ids are `=:=`.
Fuller detail: `src/runtime/CONTEXT.md`.

## Ports, drivers and the send family (A.4)
Read path: one `{Port, {data, Data}}` per driver read, at the width the child wrote (`binary` → up to `beam_io`'s `READ_CHUNK`, 64 KiB, per `read(2)`; `list` → a char list).
Child stderr inherited by default, never port data; `stderr_to_stdout` duplicates fd 2 onto fd 1, so its diagnostics arrive as port data in true write order.
`connected` flips to `false` only at `port_close/1`; `os:cmd/1` stays the runtime-native host spawn.
`{spawn_driver, Name}` resolves the name against the built-in driver table (`tcp_inet`/`fd`/`efile`) before any `dlopen`, exactly as the C does (`io.c:599-628`); an unknown name → `badarg`.
A driver port's `driver_output` reaches its owner as `{Port, {data, Data}}`; a driver-emitted `erl_drv_output_term`/`erl_drv_send_term` term reaches the connected process or the explicit destination (the `TermQueue` drain is wired end to end).
`driver_select` is real; `driver_set_timer` arms for every attached port.
An `OUTPUT` port task always drains the port's output queue through the single write path, *then* runs the entry's `ready_output` as the write-readiness notification.
The driver's `control` callback routes behind `erlang:port_control/3`; `ERL_DRV_USE`'s `stop_select` fires on the cancel/deselect handback.
The driver-private queue (`driver_enq`/`driver_pushq`/`driver_deq`/`driver_sizeq`/`driver_peekq`), `driver_pdl_create`, the port state flags (`get_port_flags`; `set_control_flags`) and the process-monitor family (`driver_monitor_process`/`_demonitor_process`/`_get_monitored_process` over the per-port monitor tree, `monitor_process_result`'s three-way answer from the published `ProcessLiveness` view) are implemented — 27 of the 41 `DriverHost` hooks.
Typed gaps: `driver_async` (no async pool; `Runtime` is `!Send`, the `invoke`/`free` pair `unsafe`, `async_port_key` default `-1`); a `control` reply the driver answered from its own memory (needs a safe copy helper on `beam_abi`); a NULL driver reply with `PORT_CONTROL_FLAG_BINARY` set (`<<>>` where the C answers `[]`); an OS child (`os_pid` is `undefined` for a driver port, `take_exit_status` always `Ok(None)`); a built-in (`spawn`/`spawn_executable`/`fd`) port's `port_control/3` answering `[]` where the oracle raises `badarg` (owned by `beam_io`'s default `Driver::control`); a driver arming more than one registration per direction (the typed `unsupported`).
`line`/`{line, N}` framing is adopted (A.4): `open_port/2` decodes the option into `PortOptions::line` (bare `line` ⇒ `512`; `{line, N}` ⇒ a positive small integer, else `badarg`; mutually exclusive with `{packet, N}` and with `stderr_to_stdout` unless `use_stdio`); `PortRegistry::register` arms `beam_io`'s `set_line_mode`; the port-task round's `take_line_notifications()` is delivered as the oracle's `{Port,{data,{eol|noeol,Data}}}` frames, and `StreamType::port_flags` reports `PORT_FLAG_BINARY`/`PORT_FLAG_LINE` independently (`[line]` ⇒ `2`, `[binary]` ⇒ `1`, `[binary,line]` ⇒ `3`).
`erl_ddll` is served (A.4) from one loaded-driver view: `loaded_drivers/0`/`try_load/3`/`try_unload/2`/`info/2` come from the native floor (`src/native/ddll.rs`) over the one name-keyed loaded-driver registry `src/port/driver.rs` keeps — the same list `open_port({spawn_driver, Name})` resolves against — while `monitor/2`/`demonitor/1`/`format_error/1` fall through to `beam_bifs`.
`loaded_drivers/0` reports this runtime's own (empty) set where the oracle lists its statically-linked `tcp_inet`/`udp_inet`/`ram_file_drv`; with no `erl_ddll:load_driver/*` a `Name` doubles as the `open_port` search (a `/`-containing name is the object path, driver name = its file stem; else `<name>.so`).
The send family serves `erlang:send/2` and `erlang:'!'/2` (the `SendBridge`); `erlang:send(Port, Data)` needs the port write path, and the distributed `{Name, Node}` send is contract A.5 — both raise `unsupported: …`, never a fabricated value.
Monitor shape follows *Port monitors (A.4)* and *`beam_io` / `beam_abi` lifecycle*.

## Distribution and the node (A.5)
`-name`/`-sname` make the runtime a distributed node: `DistNode` binds a wildcard listener, publishes to `epmd` best-effort (a failure is recorded, never fatal) and completes the server-side `'N'` handshake against a real OTP peer (`tests/dist.rs`).
Gaps: no `net_kernel` protocol; the distributed-spawn family (`SpawnRequest`/`SpawnReply`), `Delivery::Other(_)` and the ack-owing `UnlinkId` half stay typed `Unsupported`; `node/0` and the node atom a pid image carries do reflect the live `-name`/`-sname` node, but `NodeIdentity` reports creation `0` (*Placeholders*), so a decoded local id is still external (see the `beam_codec`/`beam_bifs` handoff).
`DOP_SEND`/`DOP_REG_SEND` already reach local mailboxes through `LocalDeliverySink`, as do the route-free receipt families (link/exit/unlink/monitor/demonitor/group-leader), each emitting no outbound `DOP_*`, gated by `Runtime::inbound_delivery` (default ON; `Runtime::allow_inbound_delivery` turns it off).
No Erlang-level distribution subtree runs on a `-sname`/`-name` node: the native floor answers `erl_distribution:start_link/0,1` with `ignore` (this runtime's distribution is the native `DistNode` the CLI binds and publishes to `epmd`), so `kernel_sup` skips `net_sup`.
Measured on a `-sname` node: `whereis(net_sup)`/`whereis(net_kernel)`/`whereis(auth)` are `undefined` here vs pids on the oracle, while `whereis(kernel_sup)`/`whereis(application_controller)`/`whereis(logger)` are pids on both, `whereis(timer_server)` is `undefined` on both, and `node()`/`is_alive()` agree.
Mechanism: `src/native/CONTEXT.md` *The Erlang-level distribution supervisor*.

## Timers
`send_after/3` answers a `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)`/a bad time or destination `badarg`.
`send_after/3`/`cancel_timer/1` are native-floor capabilities; `send_after/4`, `cancel_timer/2`, `start_timer/3,4` (both the relative form and the `{abs, true}` absolute form, whose delay is computed from the registered `erlang:monotonic_time/0` against the oracle's `start_time`/`end_time` millisecond window), `function_exported/3`, `link/1`/`unlink/1` and `os:set_signal/2` come from the `RuntimeHooksBridge`.
Unimplemented: `erlang:system_info/2`, `read_timer/1,2` and the roster keys this bridge does not serve (`delete_module/1`/`purge_module/2`, `port_get_data/1`/`port_set_data/2`, `term_to_iovec/1,2`, `erlang:is_builtin/3`, `bump_reductions/1`, `loaded/0`, …), each the typed `unsupported` gap.
`timer:apply_after/4` schedules through the booted `timer_server` (a `kernel_sup` child started on demand through `timer:do_start/0`) with the `{abs, true}` timer arm, so `is_reference(timer:apply_after(50,erlang,self,[]))` prints `false` on both runtimes with exit 0 (the call returns `{ok,Ref}`).

## Memory and statistics
`erlang:memory/0,1` (the `MemoryHook` seam) is adopted: `RuntimeMemory` (`src/context/memory_hook.rs`) returns the nine oracle keys in oracle order with `total = processes + system`, every figure measured (process heaps from the `ProcessTable`'s collectors, atoms from the shared `Rc<AtomTable>`, binaries from `beam_alloc::registry`, `code` from loaded `.beam` sizes, `ets` from the `TableRegistry`, `system` = those plus the remaining allocator live bytes excluding `Standard`/`EHeap`) and snapshotted at construction; `memory/1` answers in the requested order, `badarg` for an unknown key.
`erlang:statistics/1` is partly served: `run_queue`, `run_queues`, `run_queue_lengths(_all)`, `total_run_queue_lengths(_all)`, `wall_clock`, `reductions`/`exact_reductions` (a node-global cumulative counter bumped at the real reduction charge site), `context_switches` (a real process-switch counter), `io` (`{{input,N},{output,N}}` from real port byte counters), `garbage_collection` (`{GCs, WordsReclaimed, 0}` from the live collectors' counters), `runtime` (`{Total, SinceLastCall}` user-CPU milliseconds from the runtime's one long-lived `beam_io::cpu_time::RuntimeClock`, whose anchor persists for the runtime's whole lifetime) and `scheduler_wall_time`/`scheduler_wall_time_all` ⇒ `undefined` (the switch `erts_internal:scheduler_wall_time/1` records, armed or not, but no per-scheduler wall time is sampled, so the tuple list is never fabricated).
Gaps: `statistics/0` is not served, and the per-scheduler keys this runtime genuinely lacks (`total_active_tasks`/`total_active_tasks_all`/`active_tasks`/`active_tasks_all` — a scheduler's current-process flag — and `microstate_accounting` — no MSACC accounting) are the typed `unsupported`; every other `RuntimeHooks` family is unserved too.

## GC / heap model
`DEFAULT_HEAP_WORDS` is `1 << 24` (16 Mi words of lazily-mapped address space).
Term-construction heaps (BIF-heap pool + `-eval` heap) are bump arenas sized `config.heap_words`; `+hmax N` really caps that capacity (`runtime.rs::term_heap_words`); the `system_limit` translation runs after the copy engine's retry, so `deliver_message` still matches the raw `AllocKind::Message` for the heap-fragment retry.
This crate does drive `beam_gc`: a *scheduled* process allocates on its own young heap and is collected at `ExecutionContext::ensure_heap`/`ensure_heap_full` (sharing `collect_or_grow`; the latter is the full-root door `test_heap` reaches, handing over the FR file too; armed by the slice's `BudgetContext`, roots = `x[0..live)` plus the Erlang stack), pinned by `tests/gc_collect.rs`, reported by `Runtime::gc_stats()`; every other context no-ops on the unbounded arena.
Measured limits: a workload allocating only through `ExecutionContext::alloc_words` (no `test_heap` admission point, as real Cowboy `cowboy_bstr`-style code does) always falls back to the pointer-stable arena and is never collected (`collections: 0`, `fallbacks` ≈ 620·N at N=10 000); `Machine`'s float-register file is not mirrored by this crate's root publish; a failed collection halts that process's collection rather than failing the program.
Term-heap capacity remains the hard limit for anything not collected: both exhaustion classes become `error::system_limit` via `error::enforce_term_heap_limit` — `AllocKind::Heap` (the per-process bump allocator) and `AllocKind::Message` (the copy engine's destination-heap exhaustion, classified by `beam_message::is_message_heap_exhaustion`) → CLI `beam_rt: system_limit`, exit 1.
On-demand heap growth is adopted at the engine's heap-admission point and on the `beam_process` message-delivery path: `src/context/gc.rs::ensure_heap`/`ensure_heap_full` run the collector's `Process::ensure_capacity` growth whenever the heap-size policy can reach the request (`HeapPolicy::next_words(need, 0) >= need`), and a plain `Process::collect` otherwise — so a `test_heap` request larger than the nursery is admitted by growing it in place (`tests/heap_growth.rs`), while a bounded `+hmax N` policy the request cannot reach is refused before collecting (the collection still runs, the allocation falls back to the arena).
`Process::deliver` grows the nursery the same way for a refused message copy; that refusal is what reproduces the raw `AllocKind::Message` `deliver_message` keys its heap-fragment fallback on, and a relocation-exempt receiver skips the retry entirely.
Allocation outside the admission point uses bounded `beam_alloc::Heap` arenas that never move (`BifContext::heap()`, `Runtime::eval_heap`), so a BIF's *intermediate* terms are invisible to `roots` and cannot be collected; a call overflowing such a heap still raises `error::system_limit`.
The one growth seam outside the admission point is the pooled BIF-heap frontier: on the table-less (`-eval`/nested) route — no process heap being available to move a container result onto — `RuntimeContext::take_bif_frontier` retires a near-full region and continues in a larger one (capped only by an explicit `+hmax`), so a long table-less compilation grows its result store instead of hitting the fixed `DEFAULT_HEAP_WORDS` cap.

### The BIF-result copy-out — a registered BIF's container result moves onto the process's scanned heap
A registered BIF builds its result on the runtime's pooled 16 MiB `Runtime::bif_heaps` (`Runtime::take_bif_heap`) — `Target::Foreign`, unscanned by the process collector — so a container left there is a root the unscanned-root valve declines over while live.
`RuntimeContext::call_registered` (`src/context/calls.rs`) therefore moves the result onto the running process's own young heap (`Process::heap_mut()`, collector-scanned) and rewinds the pool to the call's pre-offset, so the result lands in `x(0)` (an engine-published root) and later collections relocate it.
The copy is `beam_message::copy_struct` with an empty source `OffHeapTable`; a full nursery is met by `Process::grow_nursery(hint)` (the no-relocation seam — inside a BIF call the machine's x registers and stack are unpublished, so a collecting `Process::ensure_capacity` would free live terms) and one retry, the hint being the copier's preflight count from the refusal (`AllocFailure::requested / size_of::<Eterm>()`, so growth costs no second graph walk).
One `OffHeapTable`/`CopyContext` pair serves both attempts, and the retry is reached only for `beam_message::is_message_heap_exhaustion`; every other refusal a legal BIF result can produce (the malformed-graph `badarg`, an `AllocKind::Heap`/`LiveObject` failure, a raised reason) is permanent, so the move answers `None` without growing a space (`src/context/calls.rs::tests::{a_permanent_copy_refusal_grows_no_nursery_and_writes_nothing, an_exhaustion_refusal_grows_the_nursery_and_the_retry_copies}`).
The empty source table is load-bearing: with no payload owner the copier flattens a refc binary's window into a self-contained on-heap bitstring (byte-faithful, no refcount lost), and an off-heap MSO reference with no owner is the copier's typed `bad_term`, so the move answers `None` — pool unrewound, result left exactly as it was, never a dangling payload.
The rewind is `Heap::reset_to(mark)` at the `heap.used()` read *before* the call, so it frees only this call's own words `[mark..used)` and keeps whatever a previous owner holds below `mark` (the pool is shared with native-floor reference minting, trace and the ETS-owner sweep, which return a heap *unreset*).
It applies only when the move is safe and complete — no escaping `DispatchHooks` arm (`dict`/`process_hook`/`nif_loader`/`send_hook`/`persistent_term`/`runtime_hooks`, each letting a term built on `ctx.heap()` escape into state outliving the call), no reentrant fun-applying call, an `Ok` result (a raise may carry a `live_reason` term pointing into this heap, so the error path never rewinds), a scheduled process (`mailbox_table` is `Some`), a container result (`result_is_foreign_container`; an immediate is unboxed and a literal lives in the frozen literal area, so such a result rewinds with no copy), and a move that succeeded.
Residuals: a NIF result is not copied out (a deliberate M1 residual), so it stays on the pooled heap and keeps declining a collection while live; an escaping `DispatchHooks` arm and an error result also leave their container on the pooled (`Target::Foreign`) heap; on the `-eval`/no-scheduled-process shape there is no process to move onto, so the pooled frontier instead grows (`RuntimeContext::take_bif_frontier`, capped only by an explicit `+hmax`); a nested cross-module run (`RuntimeContext::run_export`) never reaches a collection point.
Pinned by `src/context/tests.rs` (`a_bif_container_result_is_moved_onto_the_process_heap_and_the_pool_is_rewound`, `an_immediate_result_rewinds_the_pool_without_a_copy`, `an_escaping_arm_neither_moves_the_result_nor_rewinds_the_pool`, `a_bif_result_on_the_process_heap_lets_the_churn_loop_be_collected`, `a_partially_used_pool_is_rewound_to_the_callers_mark`, `an_escaping_arm_does_not_rewind_a_partially_used_pool`).

### `ets_copy` peak RSS — the copy-out's retained young space, not the ETS adopt path
`copy_bound/ets_copy`'s peak RSS is linear in N (94.68 MiB at N = 100 000, ≈99 words per iteration), a structural limit of the BIF-result copy-out above, not the ETS adopt path: `safe_to_rewind` is already `true` for `ets:*` and the pooled heap is already rewound.
It tracks BIF calls, not floats and not ETS table state (a float-free ETS loop of the same shape grows identically; a float-carrying churn loop with no ETS is flat).
The loop's heap traffic is the copy-out, which cannot collect (the machine's x registers / Erlang stack are unpublished at a BIF call), so a full nursery is met by `Process::grow_nursery(hint)` (`src/context/calls.rs::move_result_into_process_heap`) and the retired young space is retained, capacity accumulating linearly; no real collection is reached either — `ensure_heap_full` returns at `!process.should_collect(heap_need)` (`src/context/gc.rs`), its `test_heap` prefixes being tiny (a 233-word default nursery, `beam_gc/src/policy.rs`), and `alloc_words_rooted` is never entered (the BIF, not the engine, builds the result).
The caller-module float guard is not the mover (relaxing it at the two FR-publishing GC doors changes nothing here and contradicts the pinned float-collection contract, `tests/gc_collect.rs`).
Closing it needs either a `beam_process` seam that can shrink/reuse a retired young space or a `beam_engine`/runner seam that publishes the driving machine's roots at the BIF call so the copy-out can collect — both sibling-crate changes; the `beam_message` clean-destination ceiling below is the same lever.
Figures and bisection: `PERF.md` *COPY-OUT-CUT*.

## CLI `run` argument tokens
`beam_rt run <beam> <m>:<f>/<a> <arg…>` materializes an integer token with `beam_term::make_small` (`src/runtime.rs::materialize`, reached from `src/cli.rs::parse_arg_term`'s `i64` arm) without a range check: a token above `MAX_SMALL` (`2^59 - 1`) aborts on the `debug_assert` in a debug build (`beam_term/src/immediate.rs:77`, exit 101) and is silently truncated to a wrong small int in a release build — `… bm:mk64/1 576460752303423488` prints `<<248,0,0,0,0,0,0,0>>` where the oracle prints `<<8,0,0,0,0,0,0,0>>`, a wrong result, the one class the runtime forbids.
Fix belongs in those two files: range-check the parse and build a bignum (or reject the token), via `beam_term::try_make_small` + the bignum writer — the same range check `src/cli.rs` already applies to `+hmax` (`src/cli.rs:778`).
`tests/bignum_bit_segment.rs` documents the hazard and reaches the same segment through a string token instead; the `-eval` route is unaffected (its integer literals are exact bignums).

## OTP-lifecycle survey — what a scheduled process can and cannot do today
Method: self-contained `.erl` fixtures compiled by the system `erlc` (OTP 29.1.1 / erts-17.1, the oracle) into `$TMPDIR`, each exporting arity-0 probes, run three ways: `erl -noshell -pa <fix> -eval 'io:format("~w~n",[M:F()])' -s init stop` (oracle), `erts_rust/target/debug/beam_rt -noshell -pa <fix> run <fix>/M.beam M:F/0` (scheduled process) and `… beam_rt -noshell -pa <fix> -eval '…'` (runtime root process, which pumps the scheduler). Exit 0 = success, 1 = runtime error, 3 = capability gap.

### Works today (oracle-identical)
`code:which/1`, `code:get_object_code/1` (the oracle's path-based `{Module,Binary,Filename}`, cross-checked against `erl`'s own `mod_to_bin/3` read), `code:load_file/1` (then `module_loaded/1` true), `application:get_key/1,2`, `application:loaded_applications/0`, `application:which_applications/0`, `error_logger:warning_map/0` (a `RuntimeHooks` bridge).
An OTP-behaviour child comes up and survives: `proc_lib:start_link/3`, `gen_server:start_link/2,3` (unnamed and `{local,Name}`), `gen_server:start/2,3` and `supervisor:start_link/2` all return a live `{ok, Pid}` (`is_process_alive/1` true).
A `spawn`/`spawn_link` child whose entry function blocks in a `receive` parks and is resumed (`spawn(M,F,[])` with the blocking receive at the top level of `M:F`, incl. via a cross-module call, `erlang:apply(M,F,[])`, or a local fun).
Local fun application with free variables works while the closure's body completes without a suspension; a closure that is the process *entry* is driven in-machine by the runner.
`gen_server:cast/2` returns `ok` (a plain `!`). Plain `!`/`receive`, `erlang:monitor(process,P)` (arity 2) and `erlang:monitor(process,P,Options)` with a `{tag,T}` and/or `{alias,Mode}` option work.
`gen_server:call/2,3` and `gen:call/3,4` work for a finite timeout as well as `infinity` — for a pid *and* a registered `{local,Name}` — because `gen:do_call/4`'s finite-timeout clause (`lib/stdlib/src/gen.erl:251`, `erlang:monitor(process, Process, [{alias,demonitor}])`) and the `erlang:send/3 [noconnect]` it uses are both served; `sys:get_state/1` and the `sys:*` requests work too.
A `receive … after T` that must time out delivers its timeout on every route, including through a nested run.
The whole-file `file` family completes from a scheduled process (`read_file/1`, `write_file/2`, `open/2` read/write, `close/1`, `list_dir/1`, `get_cwd/0`, `consult/1`, `read_file_info/1`/`read_link_info/1` — an existing path answers `read_write` — and `filelib:is_file/1`), and the incremental io-device read path agrees with the oracle on both routes (pure `read/2`, pure `read_line/1`, and the mixed order), the device being buffer-first.
The one documented divergence left is `{get_chars,…}` on a `{encoding,unicode}` device, which counts bytes where the oracle counts characters (`src/native/file_server/CONTEXT.md`).

### Confirmed failing — root cause and repro
1. **`logger`/`error_logger` reports are emitted but reach no native logger sink.** A booted runtime has a live `logger` process and the `logger` ETS config table exists (`ets:whereis(logger)` is a `#Ref{}`), so `logger:info/1,2`, `warning/1`, `error/1` and `error_logger:info_msg/1,2`, `error_msg/2` all answer `ok`; the residual is that the `lg:*` test helpers still depend on a native logger ETS floor this runtime does not provide.
2. **`application:start/1,2`, `application:stop/1`, `application:ensure_all_started/1` reach a live controller but only the boot script's own applications are startable.** `application_controller` is a live PID on every CLI route, so a request is answered rather than failing `noproc`; a start for an application the resolved boot script did not load still fails (measured: `ensure_all_started(crypto)` → `{error,{crypto,{"no such file or directory","crypto.app"}}}` on this host), the native floor answering only the read-only queries (items in "Works today"). Repro: `ap:start_sasl/0`, `ap:start_syntax/0`, `ap:ensure_syntax/0`.

### The `-eval` vs scheduled asymmetry
The `-eval` root process pumps the scheduler and can suspend a blocking call; a scheduled process (`run`) parks at its own top-level `receive`.
Both routes deliver a `receive … after T` timeout, including one reached through a nested run (a cross-module call or a fun application), and a `receive` waiting for a message resumes correctly on both.
A scheduled slice is *running*, not merely runnable (`beam_process::Scheduler::slice_begin` flips the pid to `ProcessState::Running`), so a signal- or delivery-driven collection of it is declined (*GC-relocation hazards*) and no such collection moves its heap against an incomplete root snapshot.
A `spawn`ed `-eval` closure is run synchronously to completion, so it is not a nested run that suspends: the evaluator (`src/eval/mod.rs`, `apply_eval_closure`) drives the closure to its end before the spawning expression continues, and the evaluator's `receive … after T` arm polls the port poller once and falls straight through to the `after` body (M1 has no host timer to block on).
A `-eval` child that "parks" therefore returns and terminates before the parent's next statement — hence the async-completion shape for a live, blocked target is pinned only on the scheduled route (`tests/garbage_collect.rs`). Owner: `src/eval/mod.rs`'s `receive` — the `after T` deadline must actually be waited out (or a spawned `-eval` child otherwise kept alive).

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers the running process's own young heap (a capacity refusal met by a no-relocation `Process::grow_nursery` and one retry) and falls back to the pointer-stable `Runtime::arena`; the roster below splits *at risk* from *safe* — what a moving heap would dangle is a raw `Eterm` pinned outside the GC root set.
`Process::regs` is a snapshot, not a live mirror of the running machine.
`publish_roots_full`/`scatter_roots_full` (`context/gc.rs`) copy every x register, the whole stack and the machine's float-register file into `process.regs` (FR words appended after the stack words, bounded by a `fr_count` — `beam_process::Registers` has no FR container) only at a heap-admission point (`gc::ensure_heap_full`, the whole file) or a park (`publish_parked_roots`, the live prefix `Machine::fr_mark()`, recorded on `ProcessEngine::fr_published` for the resume, plus the parked machine's live `pending_exception` as an `extra_roots` word); between those points the snapshot is stale by up to one slice, so a collection rooted in it reaches the machine's x/stack/FR and nothing else — a Rust local or an un-published `Machine` field is not in the root set at all.
The engine's `live` count is ignored (over-approximating a copying collector's root set is always safe).
Three collect triggers differ in exposure. The admission-point collection *is* the publish/collect/scatter hand-off (safe). The delivery-driven (`Process::deliver` → `ensure_capacity` → `run_rooted_collection` over `self.regs`) and signal-driven ones (`ptab.rs`'s `terminate_with_ports` → … → `grow_receiver_for_signal` → `ensure_capacity`) fire outside an admission and are refused for a receiver with unpublished roots: `Process::has_unpublished_roots()` (= `relocation_exempt || state == Running`, `process.rs:1098`) is tested *first* by every caller, so a refused delivery becomes a heap-fragment delivery and a refused ptab signal goes to `enqueue_fragment_signal`; `beam_rt` adds a second refusal on that seam (`RuntimeContext::deliver_message_with_off_heap_inner` asks `delivery_collection_is_unsound` and marks the receiver relocation-exempt on `true`) — the fifth collection site; every send routes through `deliver_message_with_off_heap` (`src/context/mod.rs:590`), marking the sender's own pid exempt.
A signal to the running process is deferred; to a parked one, declined by the park-window exemption below; to a woken-but-not-yet-resumed (`Runnable`) receiver — the A.9 `selfhost/*` class — declined by the host collection gate every `ptab.rs` signal site asks (OR-ed with `has_unpublished_roots`) before a *collecting* `ensure_capacity`, installed as `RuntimeCollectionGate` (`context/gc_walk.rs`, the same roots-incompleteness walk as the admission-point valve) in `Runtime::new`.
The `Yield` arm, the third out-of-admission trigger, is *not* exempt: it publishes the machine's roots, then serves `Runtime::serve_gc_request`; the Wait arm's `serve_gc_request` is declined by the exemption it just set. Mechanism: `EPP_SCHEDULED_ROUTE_FINDINGS.md`.
The residual exposure is a live term held outside `process.regs` — a Rust local, or an engine `Machine` field with no extra-root publication — hence `relocation_exempt` (a `self()`, the wrapped `-eval`/nested-`Machine` scope, the parked window).
A parked machine's `pending_exception` is published as an `extra_roots` word at the park (`runner/run.rs::publish_parked_roots`) and read back on resume (`RuntimeContext::resync_parked_roots(pid, machine, fr_count)`); the parked window carries the exemption, so that publication is never a licence for a park-window collection.
Still outside the root set: `Raise::live_reason`'s reason term between a raise and its stabilization (`try_stabilize_escaped`, `runner/run.rs:662`).
The post-slice pin scan (`runner/run.rs`) reads `Machine::fr_mark()` once per slice, pins the pid iff it is `> 0`, and passes the same count as `publish_parked_roots`' `fr_count`, so a park publishes exactly the live FR prefix and never loses a live FR term.
A collection is DECLINED whenever a root — or a container the process's scanned graph reaches — lives in a region the collector does not scan (the unscanned-root valve): `RuntimeContext::call_registered` (`src/context/mod.rs`) hands `beam_bifs` the runtime's pooled 16 MiB `Runtime::bif_heaps`, and `context::gc::alloc_words`'s fallback hands blocks out of `Runtime::arena`, both `Target::Foreign` to the collector (`beam_gc/src/copy.rs`: a pointer outside the `FromSet` is left as-is and not scanned).
The valve (`context/gc.rs::root_is_unscanned` + `src/context/gc_walk.rs`) calls a term safe iff it is an immediate, a literal, or a pointer the process's collector scans (any nursery space, incl. one a `grow_nursery` retired, or the mature space); each of the three admission points (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`), the runner's park arm (`Runtime::serve_gc_request`) and the delivery seam (`delivery_collection_is_unsound`) declines (`Ok(())`) a collection whose root set reaches anything else, while the unrooted `context::gc::alloc_words` keeps its arena fallback.
The valve spans the machine roots the caller publishes (`x`/stack/FR) and the process's own root-set containers (`Process::collect`'s registers, mailbox, dict, saved arguments and pending signals), and it *descends* through the scanned graph, so a foreign container reached at depth ≥ 2 is found.
The descent is gated on a sticky, add-only per-pid latch (`Runtime::foreign_reachable`/`note_foreign_reachable` over `GcState::foreign`), opened by every event that can put an unscanned container into the graph — the engine's arena fallback (`note_gc_fallback`), a BIF / native-floor / NIF result built outside the process heap (`open_gate_for_foreign_result`), a heap-fragment delivery (`send_fragmented_message`), a spawn argument or entry fun not on the new process's own heap (`note_spawn_foreign_roots`), the escape store / `stabilize_term` (`note_escaped_store_roots`), and the valve itself on a hit — and pruned at the pass boundary for a process that is gone (`Runtime::prune_gc_requests`).
The holder it was built for is `Runtime::bif_heaps`: a container a registered BIF built there (`erlang:'++'/2`, `lists:append/2`, `lists:reverse/1`, `lists:filter/2`, `ctx.tuple(…)`) writes the caller's heap `Eterm`s verbatim, and a scheduled process's container result leaves the pool (*The BIF-result copy-out*), so the holder is reached through the unrewound paths (a NIF result, an escaping `DispatchHooks` arm's result, the `-eval`/nested shape, an error result) at depth ≥ 2 below a scanned root.
Verified end to end: `beam_rt run w.beam w:f9/0` renders the oracle's exact `~w` at exit 0, and `tests/gc_run.rs` passes; the descent is pinned by `src/context/tests.rs::{the_valve_declines_a_foreign_container_nested_in_a_scanned_container, …_a_deeply_nested_foreign_container, …_collects_when_the_nested_graph_is_fully_scanned}` (the first two fail with the descent forced off).
* **At risk (a raw `Eterm` outside the root set):** `Runtime::persistent_terms` (`context/persistent_term.rs`), `Runtime::trace`'s `MatchSpec::Functions`, `Runtime::seq_trace`'s `Token{label,from}`, `Runtime::eval_closures` `FunBody.env`, `Runtime::timers` `TimerAction::Deliver`; `MailboxState.markers[].reference` and `NameSpec.inline_options` still need a check. A spawn argument or entry fun (`ProcessEngine.args`/`entry:Fun{fun}`, `PendingSpawn.args`) and a stored escape-store term also sit outside those roots, but each opens the descent latch (`note_spawn_foreign_roots`, `note_escaped_store_roots`). Safe: `RunnerState.exits`/`results` (the stabilized `eval_heap` copy), `references`/`Timers.refs` keys, ETS (own arena), `RuntimeContext` (no `Eterm` field), `dist`/`port` structs, `PortMeta`.
* **Envelope/retained payloads:** `Process::run_rooted_collection` (`beam_process/src/process.rs:1166-1240`) roots each queued message's `payload`, `from` and `token` and re-installs all three (`set_from`/`set_token`/`with_payload`), so a heap `from`/`token` relocates too; the envelope's `off_heap`/`binaries`/`nodes` families and the `MailboxState::remove_at` retained copies are refcounted Rust handles (not young-heap `Eterm` words), so a moving heap can neither move nor dangle them, and `with_payload` carries the `Fragments` chain across. `beam_process`'s `deliver_down_message` sets `Message.from` to the target pid's `to_eterm()` (an immediate) and carries a named monitor's `{Name,Node}` in the body, so `run_rooted_collection` relocates it with the payload.
* **The arena allocation source here:** `Runtime::alloc_words` (`runtime.rs` → `self.arena`), the fallback `RuntimeContext::alloc_words` reaches after a young-heap refusal and a `grow_nursery`, also reached by `runner/budget.rs`'s forwarded `alloc_words` and by `Runtime::materialize`/`charlist`; mailbox `Queue` payloads are copied in by `copy_struct`.
