## Own-state answers (differ by construction, not bugs)
Minor divergences: `persistent_term:info/0`'s `memory` is our own word total (`count` exact); the process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})` → `undefined` here vs `1` in the oracle; `register/2` of an internal PORT id is a typed gap; `process_flag(save_calls, <non-integer>)` returns the previous value where the oracle raises `badarg` (`bif.c:1911`).
Also differ by construction: `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures — `whereis(init)` **does** agree.
## Dispatch, atoms and module introspection
`call_registered`'s wired path is allocation-free: every decode seam reuses a per-thread memoized `AtomTable` image and the atom-intern commit is append-only (`CodeServer::intern_pending`, copy-on-write only while a handle is outstanding), so a `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work, not the dispatch — [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Per-call cost of a registered call*.
An inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from` — an immediate-only, uncopied, unrooted slot where the plain `DOP_SEND*` forms pass the wire's `''` — a typed divergence from the C: `src/runtime.rs`'s envelope rule, pinned by `tests/dist_delivery.rs`'s *envelope regression* (*Distribution and the node (A.5)*).
`erlang:get_module_info/1,2` diverges on two items: `exports` order is this runtime's export list where the oracle reports global export-table order (compared as a set), and a module this runtime has not loaded is `badarg` — [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *`ModuleInfoBridge`*.
## Placeholders where a truthful source exists
* `NodeIdentity`'s creation is a fixed `0` (`src/context/bridges.rs`) where a live `crate::dist::DistNode::creation()` exists, so an internal pid/port image encodes creation `0` on a wired node; the node atom beside it *is* the runtime's live `Runtime::local_node()`, stamped on every `call_registered` arm.
* The flag-driven `system_info` literals report their default (`port_parallelism`, `break_ignored`, `modified_timing_level`, `halt_flush_timeout`, `dist_buf_busy_limit`, `delayed_node_table_gc`) — no A.6 CLI arm preserves the driving flag ([`src/info/CONTEXT.md`](src/info/CONTEXT.md)).
* `process_info(P, last_calls)` answers `false` although the runtime holds the real `save_calls` flag (`beam_process::Process::save_calls`).
## Process-control families (`src/native/`)
`monitor/3`'s option list is parsed as the C's `erts_monitor_opts` (`bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias; a `{alias,_}` on a **port** monitor or on a **remote** target propagates the typed `unsupported` (`tests/alias.rs`).
`erlang:monitor/2,3` serves a process target (pid, registered name, or `{Name, Node}` on this node) and a port target: the port monitor records on the live port table (`PortRegistry::port_table_mut` → `ProcessTable::monitor_port_term_with_tag`, the table `open_port/2` allocates from), so its `{'DOWN', Ref, port, Port, Reason}` fires on port close.
`monitor/3`'s `{tag, T}` option is served on both paths for an **immediate** (atom/integer/pid/port) or **module-literal** tag; a **heap-resident** tag is `beam_process`'s typed `error::unsupported_tag` (`is_heap_independent`, the acceptance rule the C's plain-value monitor record needs).
Monitor gaps: a named port monitor `monitor(port, Name)` (`error::named_port_monitor`; the local registry resolves names to processes only) and a remote `{Name, Node}` monitor (A.5).
Also typed gaps: `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or an ETS id.
## ETS ownership
`ets:new/2` records the caller as owner (`beam_ets::Table::set_owner`) and installs the parsed `{heir, …}`; `ets:info(T, owner)`/`heir` render the recorded pids (`undefined` when unset), `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner.
A dead owner's table is reclaimed through the `beam_process` `ProcessExitObserver` seam: the observer records the dead pid and `Runtime::drain_ets_owner_exits` releases every table it owned — dropped, or handed to its heir with the oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for the 2-tuple `{heir, Pid}` form, which carries no data; arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`).
The public owner→handle roster is the authority, so *unnamed* tables are reclaimed too: `beam_bifs::TableRegistry::handles_owned_by(TableRegistry::owner_of(dead))` lists every live table the dead pid owned (its handle is the registry key), the `ets:new/2`-time index being unioned in only for `named_table`'s registered name (released with `TableRegistry::remove_name`); an unnamed table's tid in a transfer message is our own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`, a fresh `RefAllocator` walked to the handle — the runtime's ref id space differs from `beam_bifs`'s).
Drains, heir-gift failure policy and `Runtime::own_heir_gift`: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *`ets_owner.rs`*.
Remaining live gap — `ets:setopts/2`'s gift data: `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs the `{heir, …}` option through `beam_ets::Table::setopts`, which stores the gift term verbatim where `beam_ets::Table::install_heir` (a table-owned deep copy) is meant, so the drain hands a term aliasing the dead heap to the `{'ETS-TRANSFER', …, Data}` message.
The fix belongs in `beam_bifs` (or `beam_ets`, by making `setopts` copy); `Runtime::own_heir_gift` mitigates the `ets:new/2` path only, the recorded failure surfacing as a typed error from the next drain, so a failed copy is never silently dropped.
A monitor whose watching process is dead is swept by the same drain (`ProcessExit::ets_monitors`).

## `process_info/1,2`
The item catalog and the per-item own-state answers are [`src/native/CONTEXT.md`](src/native/CONTEXT.md)'s; ~28 items answer from real state, and the divergences are:
* Heap items read the target's own policy (`Process::collector().policy()`), so `spawn_opt`'s min-heap / `fullsweep_after` / `max_heap_size` is observable; the `max_heap_size` map's key order is the oracle's (`error_logger, include_shared_binaries, kill, size`). `memory`/`reductions`/`group_leader` are own figures; `total_heap_size` is 466 (oracle 233); `registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact (a pid not in the table → `undefined`; an unknown item or a non-pid → `badarg`).
* The four execution-position items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) answer for a scheduled process, and are omitted for one this runtime gave no position (a fun-bodied process with no resolved local target, a never-scheduled pid, a direct/no-machine caller); `catchlevel` follows the same rule. Residuals: `initial_call` is the machine's entry MFA where the oracle answers `{erlang,apply,2}` for some spawn shapes (fun-valued spawn, start instruction), and the slot is runtime-wide, so a nested fun-applied run inside its window reads the *outer* machine's position.
* `trace` serves the live per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])`, the oracle's integer shape translated from this runtime's internal bits by `src/trace.rs::flags_to_atoms`); `last_calls` reports the real saved-calls state (`false`).
* `message_queue_data` answers `on_heap`, this runtime's real *current* placement (`beam_message::Queue` is always heap-resident); the only divergence is an explicit `process_flag(message_queue_data, off_heap)` (or `spawn_opt`'s form), accepted and changing nothing — honouring it needs per-process placement storage in `beam_process::Process`. Any other valid oracle item it cannot answer (`magic_ref`, `priority_messages`, …) is typed `unsupported`.
* The `binary` item is the **deduped union** of the target's **engine reservoir** (`RunnerState::reservoir_at` — the machine's `refc_binaries`, the one holder of what its compiled bitstring code built, pruned at the runner's pre-emption (`Yield`) arm whenever the process's binary virtual heap triggers so a payload it released drops out — `src/context/gc/bin_vheap.rs`) and whatever a host registered on the PCB's own off-heap table (empty in production: the runner registers nothing). Nothing mirrors the reservoir onto the process, which is what keeps `beam_gc::OffHeap`'s never-compacted slot space and its O(slots) `overhead_bytes`/`sweep` walks off the per-call path. Residual: a `process_info(self(), binary)` issued from inside the running slice cannot see a payload that slice has just built — the pass holds the running machine out of `RunnerState` for the whole slice — an omission, never a dangle (the reservoir owns the payload either way). `process_info(P, binary)` never reports the runtime's escaped-payload store (`Runtime::eval_off_heap`): that store is not pid-attributable and is pruned separately (`src/eval/reclaim.rs`).
Nothing mirrors the reservoir onto the process, so every `foreign` case's per-call cost is flat in N — a slot per payload per slice, for a compiled loop building off-heap refc binaries, is what would make it grow in N (`src/runner/CONTEXT.md` *Measured*); the residual is dispatch/heap-management at matched N, and the literal-area-tagging / valve / nursery-chain mechanism ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC / heap model*, *GC-relocation hazards*) is not a per-call term either. Ratios: [`PERF.md`](PERF.md) *off-heap mirror*.
The `max_heap_size` item is served from the shared parser's **whole** setting ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *Heap switches*), not from a per-item re-parse.
`process_info(P, garbage_collection)`'s `minor_gcs` is `Collector::minor_since_major`, **not** a collection total: every fullsweep resets it to `0`, so it can sit flat while the process collects once per iteration (`src/native/memory/mod.rs` reads the live `process.collector().minor_gcs()`). The monotone totals are `Runtime::gc_stats().collections` (published as `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}`) and `beam_gc::AnyCollector::stats()`.
`erlang:memory(binary)` is the separate `binary_alloc` live-bytes figure (`src/context/memory_hook.rs`), so it reflects a release.
## Printing
The `io` device request wrappers are served by the native floor (`src/native/io.rs`): `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:put_chars/1,2`, each wrapping `io.erl`'s `o_request/2` — posting `{io_request, …}` to the request's device, the caller's `group_leader()` (the root process both for the root process itself and for the action route's spawned child, `src/runtime.rs::as_action_process`), and blocking for `{io_reply, …}`; `execute_request/3` answers `{error, calling_self}` for that self-device, so the floor answers the device question itself and renders through the registered `io_lib:format/2`. Device rules and per-key detail: `src/native/CONTEXT.md` *The `io` device floor*; `tests/io_device.rs` (stdout/stderr/exit codes), `tests/io_diagnostic_unmask.rs` (compile diagnostics).
Two residuals: a live non-stdio device pid is typed `unsupported` (a BIF cannot block on the `{io_request, …}` round trip); `io:put_chars/1,2` accepts and ignores its device, so `io:put_chars(standard_error, …)` lands on stdout where the oracle writes fd 2. The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (or a container past ~80 columns) with `badarg`; the corpus reads such values via `bit_size/1`/`is_list`.
## Scheduler / runner
A blocked receiver resumes on a sender (send→wake→resume), a due `send_after/3` timer, or a fired `receive ... after T` deadline.
`src/runner/` returns `RunOutcome::Yield` once the per-slice budget is spent, keeping the parked `Machine` at `current_code` and letting the scheduler re-enqueue, so a hot loop is pre-empted and a second runnable process interleaves (`tests/preempt.rs`).
`RuntimeContext::wants_reduce()` is `false`, so only the runner's `BudgetContext` (`src/runner/budget.rs`) charges; a non-budgeted single-pass/nested path skips the hook.
Two kinds of charge: a **refusing** `BudgetProbe::charge()` — the per-instruction `ExecutionContext::reduce` hook (before the instruction's body runs) and the heap-admission points (`ensure_heap`/`ensure_heap_full`, reached on the native tier through `jit_test_heap`) — and a **pricing** `BudgetProbe::spend()`, which consumes one unit while the slice still has one and is a silent no-op otherwise and never sets `exhausted`: only `charge()` ends a slice.
`spend()` prices the BIF dispatch (`call_bif`/`call_bif_in_machine`, one unit *after* the dispatch) and the two call-resolution seams (`resolve_external_call`/`resolve_local_call`, one unit *before* the forward), so the budget — and `statistics(reductions)`/`process_info(_, reductions)` with it — reflects BIF/call work as the C's own reduction count does.
Why pricing and not refusing: a refusal at a call seam is a **wrong result**, not a pre-emption — the native baseline tier publishes `Machine::current_code` at **block** granularity (`crates/beam_engine/src/jit/baseline/runtime.rs:993`), and its call paths consult the seam before storing any position of their own (`store_continuation` consults it at `crates/beam_engine/src/jit/baseline/call.rs:210` and stores only at `:232`; `probe_local_call` at `runtime.rs:948`; `resolve_ext_entry` at `runtime.rs:818`), so a refusal parks at **block entry** and the resume re-executes the block prefix (measured with a refusing `charge()?`: `beam_rt -eval 'halt(0).'` and `beam_rt run slice.beam` both exited 3 with `unsupported: opcode: run: process blocked (no message available)`).
Residual gap: a **non-allocating BIF-and-call-only loop still ends no slice** on the native tier — it crosses neither the per-instruction hook nor a heap-admission door, so its `heap_size` still tracks N — and a natively linked tail loop is still not pre-empted mid-block. What the pricing buys is a budget that really drains, so a shape that does reach a refusing seam yields more often (measured `heap_growth`: `yields` 3/7/18/37/74 at N = 5 000/10 000/25 000/50 000/100 000, with the identity `collections == N + yields` holding exactly — `tests/heap_growth.rs::expected_collections`).
**The closing handoff is a six-line `beam_engine` change** (owner: that crate, so it is not made here): in the baseline driver loop (`crates/beam_engine/src/jit/baseline/mod.rs:947`, the top of `drive`'s `loop`) publish the address being entered (`Machine::set_current_code(func, pc)`) and then `ctx.reduce(1)?` behind the existing `wants_reduce()` gate **before** `code.enter(...)`. That is sound where a refusing *seam* is not: the published position **is** the address about to run and the block has not executed yet, so a refusal parks exactly there and the resume re-runs the same block from its first instruction — no prefix is replayed, and `BudgetProbe::charge()` then ends the slice from the `reduce` hook as it already does for the interpreter. Only after that does a native block end a slice of its **own**: `tests/runner/tests/slice_charging.rs`'s third pin reads the run **epilogue**'s one `Yield` today, and a same-shape fixture with no epilogue seam ends zero slices.
Measured on the native tier: the pricing makes the budget truthful — `reductions == 5N + 9` on the BIF-and-call fixture, saturating at a flat **4 006** = the 4 000-unit budget plus a 6-unit epilogue, at `slices=2 yields=1 collections=1` on the 233-word collector floor (a same-shape fixture with no epilogue seam ends zero slices) — and 800 iterations fit one 4 000-unit slice (`src/runner/tests/slice_charging.rs`).
The interpreter tier (`reds_boundary`), N = 2 000 → 10 slices / 9 yields / 9 collections / 1 major / `heap_size` 610 and N = 20 000 → 90 / 89 / 89 / 1 / 610.
Other gaps: a `receive ... after T` whose delay is `after infinity` or not a statically positive integer (a Y-register slot) parks; a capability gap is uncatchable on the runner path.
A scheduled round trip that cannot pump inside a slice folds into the typed `blocked()` gap → **exit 3** `unsupported: run: process blocked (no message available)` (`src/context/pump.rs::pump_once`, `../beam_engine/src/error.rs:75-77`).
**An allocate-and-abandon loop is collector-bound, never arena-bound**: the churn shape allocates on the running process's own young heap (GROWTH-only `Process::grow_nursery` + the BIF-result copy-out, never collecting), so a flat `heap_size`/`erlang:memory(processes)` is a **converged capacity** and the collector's per-iteration Cheney traversals *are* the per-op cost; `peak_young_spaces == 1` (young capacity 233 words for `churn` / 610 for `heap_growth`), and the per-iteration collection/major rates are the **measured tables** of `src/runner/tests/{boundary_cost,reds_door}.rs` (≈7.6728–7.6730 collections per iteration and one major per iteration plus a fixed 514, never a closed form — `src/runner/CONTEXT.md` *Measured*, [`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC / heap model*).
## Execution tier (`src/runner/tier.rs`)
The tier defaults to `JitMode::Auto` (native baseline for every process's first entry), compiled lazily per function on first entry of a `(func, pc)`; the `BEAM_RT_TIER` environment variable overrides it (with `interpreter` the only kill switch), and there is no per-module predicate guarding it — the engine's baseline driver handles the module-context switch (`Step::Enter` via `switch_into`) — and the one host obligation (the cross-module seam is idempotent, the native `call_ext*` arm re-consulting it through the interpreter-step fallback) is enforced in `RuntimeContext::resolve_external_call`.
The tier chosen at that first entry is remembered on the process (`ProcessEngine::tier`), and every later slice — reduction-budget pre-emption or `receive` park — resumes on it through `Machine::resume_outcome_with_tier`, so a native-tier process is never demoted mid-life. Measured figures and commands: `src/runner/tier.rs`, `TEST_STRATEGY.md`.

## Funs
`fun M:F/A` builds a real `FunKind::External` (`EXPORT_EXT`); a compiled-module `make_fun3` closure gets its five identity fields from `FunIdentityBridge`, so `term_to_binary/1` is byte-exact (module-scoped to the caller).
An `erl_eval` lambda stays an honest `unsupported: local_fun` (its oracle image closes over `erl_eval.erl` internals); no wrong encoding is emitted.
`binary_to_term/2` `[safe]` implements only the atom-name half of the C's decode check, so an `EXPORT_EXT` (113) naming a non-**active** export is accepted where the oracle raises `badarg` (the C requires `erts_active_export_entry(mod,name,arity)`, `external.c:5032-5036`); `beam_codec` records the gap (`../../beam_codec/src/decode/options.rs`).
Not closable in place: `[safe]` rides `beam_bifs::binconv::decode_term_bif`'s `DecodeOptions` while this crate's own decode hosts carry no `safe` (`NifHost::binary_to_term(bytes)` has no opts; `enif_binary_to_term` drops its `_opts`, `../../beam_abi/src/nif/enif/mem.rs:805`), so a native-floor arm would duplicate the registry BIF and a post-decode walk is not the C's decode-time predicate. It needs an active-export predicate threaded into `beam_codec`'s decode — a new defaulted `beam_bifs::BifContext` seam (e.g. `is_active_export(module,function,arity)`) installed on `DecodeOptions`/`Decoder` (which is `Copy`, so a trait object cannot ride it) and consulted by `decode_export` (`../../beam_codec/src/decode/fun.rs:79`), implemented here from `CodeServer::is_loaded` + the loaded `Module::exports`.

## Distribution and the node (A.5)
The **responder half is complete and a system-ERTS node can use it**: `-name`/`-sname` make the runtime a distributed node, `DistNode` binds a wildcard listener, publishes to `epmd` best-effort (a failed publish is recorded, never fatal) and runs `'n'`/`'N'`+flags+challenge+creation+name → `'r'` → `'a'` → `DriverState::Established` against a real OTP peer (`tests/dist.rs`, `tests/live_inbound.rs`, `tests/dist_two_vm.rs`).
A **hidden and a non-hidden** peer are both accepted, never an error: `DistConnection::peer_visibility` records which, and the advertised set is `dist.rs::advertised_flags(hidden) = preferred_flags() | DFLAG_PUBLISHED`.
A refusal status the responder generates (`snot_allowed` on a bad flag set, `AcceptDecision::Refuse(status)`) is written **before** the link is closed, and every error path closes the connection (`DistConnection::pump` flushes, *then* propagates `step()`; `DistConnection::close`; `DistNode::retire`/`retire_at`) — no half-open silent socket.
`epmd`'s address is `ERL_EPMD_PORT` (`127.0.0.1:<port>`, or a bare port, or a `host:port` pair) when set, else `beam_dist`'s `EPMD_DEFAULT_ADDR`, for the node's own registration **and** every lookup this crate performs (`dist/node.rs::epmd_addr`, `dist_client/client.rs::connect_addr`).
**One node→link table serves both halves** (`src/dist/links.rs::DistLinks`, shared into the process-table `DistRouter` by `DistClientInner::share_links_with`), so `erlang:send/2` to a remote **pid**, a remote registered **`{Name, Node}`** and a remote **alias reference** each emit `DOP_SEND`/`DOP_SEND_SENDER`/`DOP_REG_SEND`/`DOP_ALIAS_SEND` on the established link in **either** direction; no link to that node is the typed `distribution: no established connection to node <name>` (exit 1), never a silent drop, and an explicit dial runs first (`Runtime::dist_ensure_link*`).
A payload's own local identifiers go on the wire in their external form through `dist/externalize.rs::PayloadArena::externalize` (`holds_local_id` gates it allocation-free), so `Peer ! {reply, self()}` encodes instead of failing with `beam_codec`'s `unsupported_external_term`.
`DOP_SEND`/`DOP_SEND_SENDER`/`DOP_REG_SEND`/`DOP_ALIAS_SEND` reach local mailboxes through `LocalDeliverySink`, as do the route-free receipt families (link/exit/unlink/monitor/demonitor/group-leader and the monitor-`DOWN` family), each emitting no outbound `DOP_*` (the C's own `break; /* Done */` receipt), gated by `Runtime::inbound_delivery` (default ON; `Runtime::allow_inbound_delivery` turns it off); a payload the transport copy reports as `Alloc` is re-sent fragmented instead of dropped (`LocalDeliverySink::enqueue_fragmented`).
**`net_adm:ping/1` answers `pong`**: a runtime-native `net_kernel` service process is spawned `Runnable` and registered as `net_kernel` on every node route (`src/native/net_kernel.rs`; drained by `Runtime::service_net_kernel`, an additive scheduler-pass step), and it answers `gen:call/4`'s `'$gen_call'` `{is_auth, Node}` request (`lib/kernel/src/net_adm.erl:101-111`) with `yes` to **either** `From` spelling (`{Pid,[alias|Ref]}` ⇒ `Ref ! {[alias|Ref], yes}`; `{Pid,Ref}` ⇒ `Pid ! {Ref, yes}`), and `no` for a node this runtime does not own; every other `net_kernel` request is the typed `unsupported` gap rather than a dropped call that would park the caller in an untimed `receive`.
`erlang:monitor_node/2` is served from the native floor (`src/native/net/monitor.rs::monitor_node_2` over `Runtime::monitor_node_add`/`_remove` and the per-pass `service_node_monitors`), delivering `{nodedown, Node}`/`{nodeup, Node}` with the C's no-replay rule and firing on link retirement.
Remaining A.5 gaps, each typed — never a wrong value:
* The distributed-spawn family — `DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY` (`SpawnRequest`/`SpawnReply`) and `Delivery::Other(_)` — stays `Unsupported`, so `rpc:call/4,5` (which is `erpc`: a remote spawn plus a monitor) and `spawn(Node, M, F, A)` are capability gaps; the missing seam is a `beam_process` remote reservation API (*Cross-node handoffs* below).
* The ack-owing `UnlinkId` half (`id != 0`) stays `Unsupported`; `id == 0` is `Delivered`.
* `erlang:monitor_node/3` (the `Info`-carrying form) is a typed `unsupported`.
* `erlang:monitor(process, {Name, Node})` naming **another** node is a typed `unsupported` (`src/native/process/monitor.rs::named_node_target` resolves names on this node only), so a remote **name** monitor has no `DOWN`; a remote **pid** monitor works in both directions.
* No Erlang-level distribution subtree runs on a `-sname`/`-name` node: the native floor answers `erl_distribution:start_link/0,1` with `ignore`, so `kernel_sup` skips `net_sup`. Measured on a `-sname` node `whereis(net_kernel)` is a live pid (this crate's service) while `whereis(net_sup)`/`whereis(auth)` are `undefined` here vs pids on the oracle; `whereis(kernel_sup)`/`whereis(application_controller)`/`whereis(logger)` are pids on both, `whereis(timer_server)` is `undefined` on both, and `node()`/`is_alive()` agree. Mechanism: `src/native/CONTEXT.md` *The Erlang-level distribution supervisor*.
* `node/0` and the node atom pid image do reflect the live `-name`/`-sname` node, but `NodeIdentity` reports creation `0` (*Placeholders*), so a decoded local id is external (see the `beam_codec`/`beam_bifs` handoff).
* A `~w`/`~p` of a term holding a **foreign** pid is `beam_codec`'s typed `unsupported_external_term` (`beam_codec/src/error.rs:43`), so a peer's pid cannot be printed.
* A payload whose local identifier hides in a leaf `holds_local_id` does not descend — a >32-pair hash map, a fun environment, a native record's fields — keeps that same honest refusal rather than risking a wrong term.
## Timers
`erlang:send_after/3` and `cancel_timer/1` are native-floor capabilities; `start_timer/3,4` (relative and `{abs,true}`), `read_timer/1,2`, `function_exported/3`, `link/1`/`unlink/1`, `os:set_signal/2` and `erlang:delete_module/1` come from the `RuntimeHooksBridge`.
`send_after/3` answers `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)`/a bad time or destination `badarg`.
`erlang:read_timer/1,2` is served from the runtime's own timer heap (a non-`{async,Bool}` option list is the oracle's `badarg`) (`Timers::remaining`, the read-only twin of `cancel`): a **pending** timer reads its remaining milliseconds, truncated (`inet:timeout(5000)` reads `4999` on both runtimes, and the read neither cancels nor moves the deadline); a reference with no live timer (fired, cancelled, `make_ref/0`, a monitor reference) reads `false`; a non-reference, or a reference this runtime did not mint, is `badarg`. `/2` accepts only `{async, boolean()}` (last occurrence wins) and answers `ok`, queueing the `{read_timer, TRef, TimeLeft}` reply, while `{abs, true}`/`{info, _}`/an unknown form is `badarg` — the C's `parse_bif_timer_options` with `NULL` out-parameters.
Consequence: `inet:timeout/1` (its primitive) works, so `gen_tcp:connect/2,3,4` answers the oracle's shapes — `{error, econnrefused}` for a closed loopback port, `ok` against an in-runtime listener.
Unimplemented: `erlang:system_info/2` and every other roster key the bridge does not serve (`bump_reductions/1`, `loaded/0`, …), each a typed `unsupported` gap — the served/closable split is [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Closable host-seam keys*.
`timer:apply_after/4` schedules through the booted `timer_server` (a `kernel_sup` child started on demand through `timer:do_start/0`) with the `{abs, true}` timer arm, so `is_reference(timer:apply_after(50,erlang,self,[]))` prints `false` on both runtimes with exit 0 (the call returns `{ok,Ref}`).

## CLI `run` argument tokens
`run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2).
`beam_rt run <beam> <m>:<f>/<a> <arg…>` materializes an integer token with `beam_term::make_small` (`src/runtime.rs::materialize`, reached from `src/cli.rs::parse_arg_term`'s `i64` arm) without a range check: a token above `MAX_SMALL` (`2^59 - 1`) aborts on the `debug_assert` in a debug build (`beam_term/src/immediate.rs:77`, exit 101) and is silently truncated to a wrong small int in a release build — `… bm:mk64/1 576460752303423488` prints `<<248,0,0,0,0,0,0,0>>` where the oracle prints `<<8,0,0,0,0,0,0,0>>`, a wrong result, the one class the runtime forbids.
The fix belongs in those two files: range-check the parse and build a bignum (or reject the token), via `beam_term::try_make_small` + the bignum writer — the same range check `src/cli.rs` applies to `+hmax` (`src/cli.rs:778`).
`tests/bignum_bit_segment.rs` documents the hazard and reaches the same segment through a string token instead; the `-eval` route is unaffected (its integer literals are exact bignums).
## A.7/A.9 boot
`code:*`/`init:*`/`application:*` are preloaded-module surface (contract A.7), so the `boot/*` differential cases that touch `code:*` are **shape-only** — parsing and executing the script, not the code server's answers.
Boot-path measurement: `-eval 'halt(0).'` ≈ **0.34 s wall / 0.33 s CPU**, 927 filesystem stats (**2** on `os.beam`, since `Runtime::find_module_file` answers an already-loaded module from `CodeServer::loaded_path`) — [`PERF.md`](PERF.md).
A booted runtime leaves a live `logger_server` registered as `logger` — a second `logger_server:start_link/0` reports `{error,{already_started,Pid}}`, matching the oracle — and the script's tail blockers are served **in-node** from the native floor (`RuntimeContext::try_native`) or runtime state. Detail: [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md), [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
A process entry naming a host-served MFA is **dispatched, never entered as that module's code**: `ProcessEntry::Export` asks `RuntimeContext::host_serves` (runtime-native floor ∪ a loaded NIF module ∪ a registered `beam_bifs` key) on its **first** entry only and runs a hit through `call_bif` with the BIF's value as `x(0)` — what makes a fired `timer:apply_after/4` deliver its message and `spawn(erlang,abs,[-3])` yield `3`; a resolvable module's export keeps the label route (a nested `run_export` cannot park a blocking callee). Pinned by `tests/bif_entry_spawn.rs` and `src/boot/bootscript.rs`'s dispatch case; detail [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
A CPU-starved boot drive trips `DRIVE_DEADLINE` (`src/boot/drive.rs:85`, 10 s) → `beam_rt: error boot script: the scheduler was still runnable after 10000 ms`, **exit 1** with empty stdout (measured: 60 hogs on one core → wall 13.3 s, exit 1; 30 hogs → 8.9 s, exit 0) — a real exit code, not a signal.

## OTP-lifecycle survey
### Works today (oracle-identical)
`code:which/1`, `code:get_object_code/1` (the oracle's path-based `{Module,Binary,Filename}`), `code:load_file/1` (then `module_loaded/1` true), `code:delete/1` (the live `code_server` round trip: `true`, the module gone from the store, the server and the native `code:*` floor still answering — `tests/code_delete_live.rs`), `erlang:delete_module/1` (see *The code store* below), `application:get_key/1,2`, `application:loaded_applications/0`, `application:which_applications/0`, `error_logger:warning_map/0`.
A `spawn`/`spawn_link` child whose entry blocks in `receive` parks and resumes (`spawn(M,F,[])`, via a cross-module call, `erlang:apply(M,F,[])` or a local fun); local fun application with free variables works while the body completes without suspension; a `receive … after T` that must time out delivers on every route, including through a nested run.
Plain `!`/`receive`, `erlang:monitor(process,P)` and `monitor(process,P,Options)` with a `{tag,T}` and/or `{alias,Mode}` work, as do `sys:get_state/1`/`sys:*`; `gen_server:call/2,3` and `gen:call/3,4` work for a finite timeout and `infinity`, for a pid *and* a registered `{local,Name}`, because `gen:do_call/4`'s finite-timeout clause (`lib/stdlib/src/gen.erl:251`) and its `erlang:send/3 [noconnect]` are both served.
The whole-file `file` family completes from a scheduled process (`read_file/1`, `write_file/2`, `open/2` read/write, `close/1`, `list_dir/1`, `get_cwd/0`, `consult/1`, `read_file_info/1`/`read_link_info/1` — an existing path answers `read_write` — and `filelib:is_file/1`), and the incremental io-device read path agrees on both routes (buffer-first device); the one divergence is `{get_chars,…}` on an `{encoding,unicode}` device, which counts bytes where the oracle counts characters (`src/native/file_server/CONTEXT.md`).
### Confirmed failing — root cause and repro
1. `logger`/`error_logger` reports are emitted but reach no native logger sink: a booted runtime has a live `logger` process and the `logger` ETS config table (`ets:whereis(logger)` is a `#Ref{}`), so `logger:info/1,2`, `warning/1`, `error/1`, `error_logger:info_msg/1,2` and `error_msg/2` all answer `ok`, but the `lg:*` helpers need a native logger ETS floor this runtime does not provide.
2. `application:start/1,2`, `application:stop/1` and `application:ensure_all_started/1` reach the live controller (a live pid on every CLI route, so the request is answered rather than `noproc`), but only the boot script's own applications are startable — `ensure_all_started(crypto)` → `{error,{crypto,{"no such file or directory","crypto.app"}}}`, the native floor answering only the read-only queries above. Repro: `ap:start_sasl/0`, `ap:start_syntax/0`, `ap:ensure_syntax/0`.
### The `-eval` vs scheduled asymmetry
The `-eval` action process pumps the scheduler and can suspend a blocking call; a scheduled process (`run`) parks at its own top-level `receive`, and a scheduled slice is *running*, not runnable (`beam_process::Scheduler::slice_begin` sets `ProcessState::Running`), so a signal- or delivery-driven collection of it is declined ([`M1_GAPS_GC.md`](M1_GAPS_GC.md) *GC-relocation hazards*).
A `spawn`ed `-eval` closure runs synchronously to completion in the evaluator (`src/eval/mod.rs`, `apply_eval_closure`) on the slice's own context (`may_pump_scheduler` false), so a `receive … after T` **inside** it scans the mailbox, makes one port-poller pass and takes its `after` body; the action's **own** `receive … after T` runs outside any slice over three sources — a mailbox rescan, a bounded pump (`RECEIVE_PUMP_SLICES = 64`) and `Runtime::wait_for_timer` — so a `-eval` child that "parks" returns and terminates before the parent's next statement, and the async-completion shape for a live blocked target is pinned only on the scheduled route (`tests/garbage_collect.rs`).
### The code store — `delete_module/1` unloads, `purge_module/2` is `notsup` outside the purger, and the floor serves `purge/1`/`soft_purge/1`
`code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure list's order is not stable (measured 117 × `c_m,b_m,a_m` vs 3 × `b_m,c_m,a_m` in 120 probes) — assert failure pairs as a **set**, never an ordered `vec!`. `tests/fixtures/` must not be passed to the oracle as a single `-pa`: it contains a `lists.beam` that shadows stdlib.
`erlang:delete_module/1` is served from the `RuntimeHooks` bridge (`badarg` for a non-atom, the atom `undefined` for a name the store does not hold, `true` plus a real `CodeServer::forget_module` unload for one it holds), and so is `erts_internal:purge_module/2` — the `error:notsup` raise, through the same `notsup()` helper as `erts_literal_area_collector:release_area_switch/0`.
That `notsup` is the oracle's answer for a caller **other than the code purger**: the C raises it only `if (BIF_P != erts_code_purger)` (`../../erts/emulator/beam/beam_bif_load.c:2088-2092`), so the registered purger process reaches the real prepare/complete purge behind the same BIF (the machinery has existed since OTP 19.1; nothing was removed in OTP 29). A **direct** caller of `erts_internal:purge_module/2` therefore still gets the oracle's `notsup` (measured for an atom, an unloaded atom and a non-atom), and stays that way.
`code:purge/1` and `code:soft_purge/1` do **not** go through that path any more: both are served from the runtime-native floor (`src/native/code.rs`), so the live `code_server` never sees the request and **survives** it. This runtime keeps **no old-code slot** ever (`erlang:delete_module/1` really unloads, a reload replaces the live entry), so nothing can be purged and nobody can be running old code; the honest answers are the oracle's own constants for that state, measured on OTP 29.1.1 / `erts-17.1`: `code:purge(Mod)` ⇒ `false` for a loaded module, an unloaded atom and a module just deleted, `code:soft_purge(Mod)` ⇒ `true` for all three, and both raise the bare-atom `error:function_clause` for a non-atom (`code.erl:722`/`code.erl:740`'s `is_atom/1` guard; `42` and `[]` measured) — with `is_pid(whereis(code_server))`, `code:all_loaded/0` and `code:is_loaded/1` still answering after **every** call (`tests/code_delete_live.rs`).
Residuals, both documented rather than fabricated: no `erts_code_purger` process exists here (`erlang:whereis(erts_code_purger)` ⇒ `undefined`; the oracle's ⇒ `<0.1.0>`, and it is in `PRELOADED_MODULE_NAMES` only because that list is the oracle's), and the guard raise carries **no** `.beam` frames — a caught `function_clause` renders as `{function_clause,[]}` where the oracle's carries `code:soft_purge/1`'s frame (the crate's `function_clause` convention: a native floor arm never fabricates a wrapper stacktrace).
`code:delete/1` — the live-server round trip — is unaffected and agrees on both routes (`tests/code_delete_live.rs`, seven oracle-cross-checked tests, the purge matrix among them).
This runtime keeps **no old-code slot**, so a delete really unloads where the oracle only retires the module into old code: measured on OTP 29.1.1 / `erts-17.1`, the oracle's `erlang:delete_module(lists)` answers `true` and leaves the module in the store (`code:is_loaded/1` still `{file, …}`, `code:all_loaded/0` still lists it, `erlang:check_old_code/1` now `true`, `erlang:module_loaded/1` still `true`; the same rows for a scratch module read `{true, false, true, {file, …}}` — the delete's own retirement column, pinned by the suite), while here `module_loaded/1` and `code:is_loaded/1` answer `false`, `code:all_loaded/0` drops the entry and `check_old_code/1` stays `false` (the path-based `code:which/1` still answers the on-disk `.beam`, exactly as for a module that was never loaded).
The two consequences that follow: a **second** `erlang:delete_module/1` is the oracle's `error:badarg` plus an `=ERROR REPORT==== … Module lists must be purged before deleting` on the oracle and the unheld `undefined` here, and this runtime emits **no** report at all (it has no logger sink); `code:delete/1` answers `true` then `false` on **both** runtimes (the server's own `moddb` record is what the second call misses).
The reasoning and the full measured column are [`src/context/runtime_hooks.rs`](src/context/runtime_hooks.rs)'s module docs and `RuntimeHooksBridge::delete_module`; the pinned rows are `tests/code_delete_live.rs` (the direct BIF's two old-code rows are asserted as this runtime's own state, the rest cross-checked against the live oracle).
### The expected-module-name check on every name-based load route
`CodeServer::load` decodes the image and refuses it **before caching** when the object code's own module name differs from the requested one — the C's `check_module_name` (`../../erts/emulator/beam/beam_load.c:185-187`) — so `code:load_file(M)` ⇒ `{error,badfile}`, `code:ensure_modules_loaded([M])` ⇒ `{error,[{M,badfile}]}` and `code:ensure_loaded(M)` ⇒ `{error,badfile}`, exactly as `code:load_binary/3` already answered.
That one check covers every route that carries a requested name: the three `code:*` forms, the boot script's `{primLoad,…}` directives and the on-demand load of an external call all end there, and the refused image is cached under neither name. `CodeServer::load_path` (the CLI `run` route and the slice fixture) deliberately keeps own-name semantics — an explicit file has no requested name to check against. Residual: the oracle's `beam_load.c(186) … module name in object code is <Real>` ERROR REPORT is not modelled (its value is). Pinned by `tests/code_load_file.rs` and `src/native/code.rs`'s units.
### The `spawn(M,F,A)` reason surfacing — documented eager resolution
The oracle's `spawn`/`spawn_link`/`spawn_monitor(M,F,A)` do **no** loading at spawn time: the spawn succeeds and the **child** dies when it applies the MFA, so a `<Name>.beam` whose object code names another module (or no file at all) answers `true` and `{'DOWN',Ref,process,Pid,{undef,[{Name,F,Args,[]}]}}` (measured on OTP 29.1.1 / `erts-17.1` with a `mismatch.beam` really holding `mymod`: `spawn_monitor(mismatch,id,[7])` ⇒ that `'DOWN'`, plus the node's own `beam_load.c(186) … module name in object code is mymod` report; `spawn_monitor(nosuchmod_xyz,f,[1])` ⇒ the same shape).
This runtime resolves the export entry **eagerly**, at `Runtime::resolve_export_entry` (the code-path search, the load and the export check — the same route `spawn_export_child_with_policy` takes from inside a slice), so the identical load failure raises at the **spawn site**: `catch spawn_monitor(mismatch,id,[7])` ⇒ `{'EXIT',{undef,[{erlang,spawn_monitor,[mismatch,id,[7]],[]}]}}` (measured), never a `'DOWN'`; `spawn(mymod, nosuchfun, [])` raises the same way where the oracle spawns and the child dies.
Closing it needs two pieces this runtime does not have: a **lazily resolved** export entry (a dead-on-arrival child that resolves its module at its first slice) and the ERTS **exit-reason** shape the dead child carries (`{undef, Stacktrace}`), where the runner's reason translation (`src/runner/reason.rs::exit_reason`) renders a bare atom or a live reason term only.
It stays a typed, documented gap rather than a fabricated agreement; the reasoning is `Runtime::resolve_export_entry`'s rustdoc.

## Test-harness scratch dirs
Scratch temp dirs come from one place: `crate::context::test_support::scratch_dir(label)` — unique per call (the label plus the pid, an atomic sequence and a per-process nonce) and self-removing on drop. A hand-rolled `temp_dir().join(format!("…_{pid}"))` collides with a concurrent test *process*.
