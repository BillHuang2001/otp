# `beam_rt` — Known M1 Gaps & Cross-Node Handoff Detail
Per-item detail behind [`CONTEXT.md`](CONTEXT.md)'s condensed `Known Issues / Intentional M1 gaps` bullets, plus cross-node handoffs and GC-relocation hazards.
Every gap is a typed capability gap or a measured own-state difference — never a wrong result.
## Own-state answers (differ by construction, not bugs)
Minor divergences: `persistent_term:info/0`'s `memory` is our own word total (`count` exact); the process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})` → `undefined` here vs `1` in the oracle; `register/2` of an internal PORT id is a typed gap; `process_flag(save_calls, <non-integer>)` returns the previous value where the oracle raises `badarg` (`bif.c:1911`).
## Placeholders where a truthful source exists
* `NodeIdentity`'s creation is a fixed `0` (`src/context/bridges.rs`) where a live `crate::dist::DistNode::creation()` exists, so an internal pid/port image encodes creation `0` on a wired node; the node atom beside it *is* the runtime's live `Runtime::local_node()`, stamped on every `call_registered` arm.
* The flag-driven `system_info` literals report their default (`port_parallelism`, `break_ignored`, `modified_timing_level`, `halt_flush_timeout`, `dist_buf_busy_limit`, `delayed_node_table_gc`) — no A.6 CLI arm preserves the driving flag ([`src/info/CONTEXT.md`](src/info/CONTEXT.md)).
* `process_info(P, last_calls)` answers `false` although the runtime holds the real `save_calls` flag (`beam_process::Process::save_calls`).
## Process-control families (`src/native/`)
`erlang:monitor/2,3` serves a process target (pid, registered name, or `{Name, Node}` on this node) and a port target: the port monitor records on the live port table (`PortRegistry::port_table_mut` → `ProcessTable::monitor_port_term_with_tag`, the table `open_port/2` allocates from), so its `{'DOWN', Ref, port, Port, Reason}` fires on port close.
`monitor/3`'s `{tag, T}` option is served on both paths for an **immediate** (atom/integer/pid/port) or **module-literal** tag; a **heap-resident** tag is `beam_process`'s typed `error::unsupported_tag` (`is_heap_independent`, the acceptance rule the C's plain-value monitor record needs).
Monitor gaps: a named port monitor `monitor(port, Name)` (`error::named_port_monitor`; the local registry resolves names to processes only) and a remote `{Name, Node}` monitor (A.5).
## ETS ownership
`ets:new/2` records the caller as owner (`beam_ets::Table::set_owner`) and installs the parsed `{heir, …}`; `ets:info(T, owner)`/`heir` render the recorded pids (`undefined` when unset), `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner.
A dead owner's table is reclaimed through the `beam_process` `ProcessExitObserver` seam: the observer records the dead pid and `Runtime::drain_ets_owner_exits` releases every table it owned — dropped, or handed to its heir with the oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for the 2-tuple `{heir, Pid}` form, which carries no data; arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`).
The public owner→handle roster is the authority, so *unnamed* tables are reclaimed too: `beam_bifs::TableRegistry::handles_owned_by(TableRegistry::owner_of(dead))` lists every live table the dead pid owned (its handle is the registry key), the `ets:new/2`-time index being unioned in only for `named_table`'s registered name (released with `TableRegistry::remove_name`); an unnamed table's tid in a transfer message is our own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`, a fresh `RefAllocator` walked to the handle — the runtime's ref id space differs from `beam_bifs`'s).
Drains, heir-gift failure policy and `Runtime::own_heir_gift`: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *`ets_owner.rs`*.
Remaining live gap — `ets:setopts/2`'s gift data: `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs the `{heir, …}` option through `beam_ets::Table::setopts`, which stores the gift term verbatim where `beam_ets::Table::install_heir` (a table-owned deep copy) is meant, so the drain hands a term aliasing the dead heap to the `{'ETS-TRANSFER', …, Data}` message.
The fix belongs in `beam_bifs` (or `beam_ets`, by making `setopts` copy); `Runtime::own_heir_gift` mitigates the `ets:new/2` path only, the recorded failure surfacing as a typed error from the next drain, so a failed copy is never silently dropped.
A monitor whose watching process is dead is swept by the same drain (`ProcessExit::ets_monitors`).
## Port monitors (A.4)
`erlang:monitor/2` on a port records an incoming entry on the port; a watcher that dies first is swept through the same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so a port never keeps a monitor for a dead process (`tests/port_monitor_cleanup.rs` is the discriminating white-box pin; a *surviving* watcher's monitor is kept). `erlang:port_info(Port, monitors)` reads the always-empty `PortMeta.monitors` — the oracle returns `[]` even with a live watcher, so that matches and must not change.
## `process_info/1,2`
The item catalog and the per-item own-state answers are [`src/native/CONTEXT.md`](src/native/CONTEXT.md)'s; ~28 items answer from real state, and the divergences are:
* Heap items read the target's own policy (`Process::collector().policy()`), so `spawn_opt`'s min-heap / `fullsweep_after` / `max_heap_size` is observable; the `max_heap_size` map's key order is the oracle's (`error_logger, include_shared_binaries, kill, size`). `memory`/`reductions`/`group_leader` are own figures; `total_heap_size` is 466 (oracle 233); `registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact (a pid not in the table → `undefined`; an unknown item or a non-pid → `badarg`).
* The four execution-position items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) answer for a scheduled process, and are omitted for one this runtime gave no position (a fun-bodied process with no resolved local target, a never-scheduled pid, a direct/no-machine caller); `catchlevel` follows the same rule. Residuals: `initial_call` is the machine's entry MFA where the oracle answers `{erlang,apply,2}` for some spawn shapes (fun-valued spawn, start instruction), and the slot is runtime-wide, so a nested fun-applied run inside its window reads the *outer* machine's position.
* `trace` serves the live per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])`, the oracle's integer shape translated from this runtime's internal bits by `src/trace.rs::flags_to_atoms`); `last_calls` reports the real saved-calls state (`false`).
* `message_queue_data` answers `on_heap`, this runtime's real *current* placement (`beam_message::Queue` is always heap-resident); the only divergence is an explicit `process_flag(message_queue_data, off_heap)` (or `spawn_opt`'s form), accepted and changing nothing — honouring it needs per-process placement storage in `beam_process::Process`. Any other valid oracle item it cannot answer (`magic_ref`, `priority_messages`, …) is typed `unsupported`.
* The `binary` item is the **deduped union** of the target's **engine reservoir** (`RunnerState::reservoir_at` — the machine's `refc_binaries`, the one holder of what its compiled bitstring code built, pruned at the runner's pre-emption (`Yield`) arm whenever the process's binary virtual heap triggers so a payload it released drops out — `src/context/gc/bin_vheap.rs`) and whatever a host registered on the PCB's own off-heap table (empty in production: the runner registers nothing). Nothing mirrors the reservoir onto the process, which is what keeps `beam_gc::OffHeap`'s never-compacted slot space and its O(slots) `overhead_bytes`/`sweep` walks off the per-call path. Residual: a `process_info(self(), binary)` issued from inside the running slice cannot see a payload that slice has just built — the pass holds the running machine out of `RunnerState` for the whole slice — an omission, never a dangle (the reservoir owns the payload either way). `process_info(P, binary)` never reports the runtime's escaped-payload store (`Runtime::eval_off_heap`): that store is not pid-attributable and is pruned separately (`src/eval/reclaim.rs`).
## Printing
The `io` device request wrappers are served by the native floor (`src/native/io.rs`): `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:put_chars/1,2`, each wrapping `io.erl`'s `o_request/2` — posting `{io_request, …}` to the request's device, the caller's `group_leader()` (the root process both for the root process itself and for the action route's spawned child, `src/runtime.rs::as_action_process`), and blocking for `{io_reply, …}`; `execute_request/3` answers `{error, calling_self}` for that self-device, so the floor answers the device question itself and renders through the registered `io_lib:format/2`. Device rules and per-key detail: `src/native/CONTEXT.md` *The `io` device floor*; `tests/io_device.rs` (stdout/stderr/exit codes), `tests/io_diagnostic_unmask.rs` (compile diagnostics).
Two residuals: a live non-stdio device pid is typed `unsupported` (a BIF cannot block on the `{io_request, …}` round trip); `io:put_chars/1,2` accepts and ignores its device, so `io:put_chars(standard_error, …)` lands on stdout where the oracle writes fd 2. The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (or a container past ~80 columns) with `badarg`; the corpus reads such values via `bit_size/1`/`is_list`.
## Scheduler / runner
A blocked receiver resumes on a sender (send→wake→resume), a due `send_after/3` timer, or a fired `receive ... after T` deadline.
`src/runner/` returns `RunOutcome::Yield` once the per-slice budget is spent, keeping the parked `Machine` at `current_code` and letting the scheduler re-enqueue, so a hot loop is pre-empted and a second runnable process interleaves (`tests/preempt.rs`).
`RuntimeContext::wants_reduce()` is `false`, so only the runner's `BudgetContext` (`src/runner/budget.rs`) charges; a non-budgeted single-pass/nested path skips the hook.
Two kinds of charge: a **refusing** `BudgetProbe::charge()` — the per-instruction `ExecutionContext::reduce` hook (before the instruction's body runs) and the heap-admission points (`ensure_heap`/`ensure_heap_full`, reached on the native tier through `jit_test_heap`) — and a **pricing** `BudgetProbe::spend()`, which consumes one unit while the slice still has one and is a silent no-op otherwise and never sets `exhausted`: only `charge()` ends a slice.
`spend()` prices the BIF dispatch (`call_bif`/`call_bif_in_machine`, one unit *after* the dispatch) and the two call-resolution seams (`resolve_external_call`/`resolve_local_call`, one unit *before* the forward), so the budget — and `statistics(reductions)`/`process_info(_, reductions)` with it — reflects BIF/call work as the C's own reduction count does.
Why pricing and not refusing: a refusal at a call seam is a **wrong result**, not a pre-emption — the native baseline tier publishes `Machine::current_code` at **block** granularity (`crates/beam_engine/src/jit/baseline/runtime.rs:993`), and its call paths consult the seam before storing any position of their own (`store_continuation` consults it at `crates/beam_engine/src/jit/baseline/call.rs:210` and stores only at `:232`; `probe_local_call` at `runtime.rs:948`; `resolve_ext_entry` at `runtime.rs:818`), so a refusal parks at **block entry** and the resume re-executes the block prefix (measured with a refusing `charge()?`: `beam_rt -eval 'halt(0).'` and `beam_rt run slice.beam` both exited 3 with `unsupported: opcode: run: process blocked (no message available)`).
Residual gap: a **non-allocating BIF-and-call-only loop still ends no slice** on the native tier — it crosses neither the per-instruction hook nor a heap-admission door, so its `heap_size` still tracks N — and a natively linked tail loop is still not pre-empted mid-block. What the pricing buys is a budget that really drains, so a shape that does reach a refusing seam yields more often (measured `heap_growth`: `yields` 3/7/18/37/74 at N = 5 000/10 000/25 000/50 000/100 000, with the identity `collections == N + yields` holding exactly — `tests/heap_growth.rs::expected_collections`).
**The closing handoff is a six-line `beam_engine` change** (owner: that crate, so it is not made here): in the baseline driver loop (`crates/beam_engine/src/jit/baseline/mod.rs:947`, the top of `drive`'s `loop`) publish the address being entered (`Machine::set_current_code(func, pc)`) and then `ctx.reduce(1)?` behind the existing `wants_reduce()` gate **before** `code.enter(...)`. That is sound where a refusing *seam* is not: the published position **is** the address about to run and the block has not executed yet, so a refusal parks exactly there and the resume re-runs the same block from its first instruction — no prefix is replayed, and `BudgetProbe::charge()` then ends the slice from the `reduce` hook as it already does for the interpreter. Only after that does a native block end a slice of its **own**: `tests/runner/tests/slice_charging.rs`'s third pin reads the run **epilogue**'s one `Yield` today, and a same-shape fixture with no epilogue seam ends zero slices.
Measured on the native tier: the pricing makes the budget truthful — `reductions == 5N + 9` on the BIF-and-call fixture, saturating at a flat **4 006** = the 4 000-unit budget plus a 6-unit epilogue, at `slices=2 yields=1 collections=1` on the 233-word collector floor (a same-shape fixture with no epilogue seam ends zero slices) — and 800 iterations fit one 4 000-unit slice (`src/runner/tests/slice_charging.rs`).
The interpreter tier (`reds_boundary`), N = 2 000 → 10 slices / 9 yields / 9 collections / 1 major / `heap_size` 610 and N = 20 000 → 90 / 89 / 89 / 1 / 610.
Other gaps: a `receive ... after T` whose delay is `after infinity` or not a statically positive integer (a Y-register slot) parks; a capability gap is uncatchable on the runner path.
## Execution tier (`src/runner/tier.rs`)
The tier defaults to `JitMode::Auto` (native baseline for every process's first entry), with no per-module predicate guarding it — the engine's baseline driver handles the module-context switch (`Step::Enter` via `switch_into`) — and the one host obligation (the cross-module seam is idempotent, the native `call_ext*` arm re-consulting it through the interpreter-step fallback) is enforced in `RuntimeContext::resolve_external_call`.
The tier chosen at that first entry is remembered on the process (`ProcessEngine::tier`), and every later slice — reduction-budget pre-emption or `receive` park — resumes on it through `Machine::resume_outcome_with_tier`, so a native-tier process is never demoted mid-life. Measured figures and commands: `src/runner/tier.rs`, `TEST_STRATEGY.md`.
## NIF (A.3)
`load_nif/2` `dlopen`s the shared object and runs C NIF code; a load failure is the oracle's returned `{error, {Reason, Text}}`, never a raise.
`NifHostImpl` implements the runtime-independent hooks — `heap`/`intern_atom`/`atom_name`/`self_pid`, `term_to_binary`/`binary_to_term`/`binary_to_term_used` (ETF; the last is the consumed-byte form `enif_binary_to_term` answers with, so an image with trailing bytes decodes its first term where the strict form refuses), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is the runtime's real normal-scheduler count), `alloc_env`/`free_env`, `make_copy` as identity — plus, through the borrowed `NifHostServices` provider (`RuntimeNifServices`: the runtime, the pass's own process table and the calling module) threaded into the per-call host, `make_ref`, `whereis_pid`, `is_process_alive`/`is_current_process_alive`, `is_port_alive`, `port_command`, `send` (the C's `enif_send`: delivery through the runtime's own `RuntimeContext::send_message` → `ProcessTable::deliver` seam, so the message crosses the same `beam_message::copy_struct` boundary a BIF send uses, a receiver parked in `receive` is woken through resume-on-send, and the C's `1`/`0` are answered — a dead or unknown local pid is the C's `0`, which `erl_nif.c:876-877` deliberately does not fold into success), `local_fun_identity` (the `NEW_FUN_EXT` identity `enif_term_to_binary` needs for a local closure, from the same `FunIdentityBridge`/code-server module snapshot the `erlang:term_to_binary/1` BIF uses, so the image is byte-structural with the oracle's) and `monitor_process_result`/`demonitor_process` (`enif_monitor_process`/`enif_demonitor_process`: a live local target is armed with an internal reference minted from the runtime's own id space and registered as a plain reference, the `(monitor, target)` pair is recorded in `Runtime::nif_monitors` (`src/nif_monitor.rs`), and the process-exit observer fires the resource type's `down` callback on the target's death — the C's `erts_fire_nif_monitor` — through `beam_abi`'s exactly-once `deliver_resource_down_id`).
The monitor index is keyed by the same 24-byte reference block `beam_abi` stores in the caller's `ErlNifMonitor`, so it is no more granular than the ABI's own monitor table, and a **remote** pid is the C's `1` (no monitor arm across distribution).
A monitor whose resource type was destroyed while armed delivers no `down` (the C's `run_resource_dtor`) and is pruned from the index at the next arm.
The load/unload host lives in `Runtime::nifs` (it cannot borrow the runtime) with `services = None`, so every provider-backed hook stays at the trait default there except `enif_send`.
A `load` callback's `enif_send` is queued on the host (`NifHostImpl`'s load window, `with_load_sends`) and delivered by `NifBridge::load_nif` the moment the callback returns — still inside the `erlang:load_nif/2` call, so the message is in the receiver's mailbox before Erlang continues — and the callback's answer is the C's `1`.
The delivery runs on the runtime's own `RuntimeContext::send_message` seam over the **pass's** own process table, because the runtime's `processes` is a fresh empty placeholder for the whole of a pass.
A destination that names no **internal local** pid is the C's `0`, which is the same refusal `erts_proc_lookup` produces.
Two residuals remain, both reported rather than wrong: a **dead** local pid answers `1` where the C answers `0` (the liveness relation lives in the process table the load host cannot reach, and the drain reports the failed delivery on the debug-trace channel), and an `unload`/resource-`dtor` callback keeps the ABI's `0` (its window closed with the load callback, and nothing removes a registry entry, so the library is only ever dropped with the runtime — there is no drain point).
Hooks at the trait default, each needing host-unreachable runtime state: `priv_data` (`beam_abi`'s loader keeps the library's `void**`; the host answers the C's null); `consume_timeslice` (`false`: the running process's reduction budget is the slice's `BudgetProbe`, so a charge from here would be a second, uncoordinated accounting of the same quantum — and the hook's `bool` cannot express "unsupported"); `whereis_port` (`None`, provable: `erlang:register/2` refuses a port, so no atom can name one); `schedule_nif` (`badarg`; no dirty schedulers, no scheduling trampoline); `dynamic_resource_call` (needs a per-library `{module, name}`-keyed resource-type registry).
A second `load_nif` for a loaded module is `reload`; a NIF returning a non-term is caught by `try_call_nif` as a typed error, never an abort.
`enif_select`/`enif_select_x` are live: the mask `beam_abi` forwards verbatim is decoded with `ErlNifSelectFlags::intersects` into the runtime's one readiness store (`src/port/select.rs`, reached through `PortRegistry::arm_nif_select`/`stop_nif_select`/`cancel_nif_select`), the C's return codes are answered (`0` accepted, `ERL_NIF_SELECT_STOP_CALLED | <cleared>` for a `STOP`, `<cleared>` bits for a `CANCEL`, `INT_MIN | ERL_NIF_SELECT_FAILED` on a refused control op), and readiness mints the resource term at delivery time (`crate::nif::resource_term_for` → `beam_abi`'s `resource_term`, a refused/foreign/dying pointer delivering nothing rather than a fabricated term) and sends `{select, ResourceTerm, Ref, EventAtom}` — or the caller's own `ERL_NIF_SELECT_CUSTOM_MSG` term — to the `pid` operand or the calling process.
A registration holds **one reference per armed interest**, taken through `beam_abi`'s `keep_resource` at `arm` and given back **exactly once** at disarm (a `STOP`, a `CANCEL`, the dead-owner prune, or the store's own teardown — the registration owns it as a `SelectHold`, an RAII hold), so a NIF that arms a select and then releases its own reference still gets its notification, exactly as in the C (`erl_check_io.c:1446` keeps it, `:1533`/`:1834`/`:2242` give it back).
On the delivery path only, the interest's reference is released **after** the notification's resource term has been minted — the mint takes a reference of its own — so the object outlives the disarm that produced the event instead of being destroyed between the disarm and the mint.
A non-null object this runtime cannot keep alive (one it never allocated, or one already dying) is refused at arm time, so no interest is armed for an object no notification could name.
Pinned end to end by `tests/nif_select.rs`'s `enif_select_interest_reference_keeps_a_released_object_alive_until_readiness`, `enif_select_stop_releases_the_interests_reference_exactly_once` and `enif_select_interest_of_a_dead_owner_is_pruned_and_released`.
Residuals, each a **lost notification** rather than a wrong result: the resource type's `stop` callback has no seam on this side, so `ERL_NIF_SELECT_STOP_SCHEDULED` is never reported; and `ERL_NIF_SELECT_NOTSUP` is unreachable by construction, `Interest::ERROR` being a served caller-intent bit.
**The resource-term reclamation (the `enif_make_resource` reference drop) runs at three sites, and every decline is a leak rather than a dangle.** `src/context/gc/resources.rs::reclaim` is the scheduled site (the runner's `Yield` park arm, under `engine.parked_published`); `src/eval/reclaim/resource.rs::{prune_at_statement_boundary,prune_beyond}` are the two **non-park** sites the `-eval` route and every nested run need, because that route's action process is never enqueued and therefore never parks. All three share one descent (`src/eval/reclaim.rs::walk<R: Reach>`) and one two-tier match — a candidate's own raw word, then `beam_term::boxed::internal_ref_id`, because a `copy_struct` copy is a different word with the same identity.
Residuals, all but one a **leak of the object's host `malloc` block**, never a wrong term:
* the two non-park sites cannot enumerate their whole process, so each prunes only against a **frontier** (a snapshot of the candidate set at statement entry / run entry) and releases only candidates minted **inside** its own window — a resource minted before that window is retained even when nothing reachable names it, because a store the walk cannot see may hold it;
* consequently a runtime's **first** statement boundary records a frontier and releases nothing (a bounded one-statement leak; in the measured cadence shape it is zero, the first boundary following an `init/1` that mints nothing);
* a nested run that **fails** (`Err`) publishes no live set, so its epilogue prunes nothing — the resources minted inside it are retained;
* a candidate whose identity cannot be read (its mint block no longer holds a reference header) is recorded as **reached**, and so is one reached by the prune-only valve or by the parked-resource registry's word reuse (`Registry::bind_term` evicts a binding whose word a new mint reuses, so a re-minted word can look pre-frontier) — "cannot identify it" must never become "it is dead";
* a resource held only by a store outside the walk's root families — another process's heap, an ETS object, a `persistent_term` value — is not enumerated by any site, so its copy's reference identity reaches nothing and the object is **released** while the store still names it; closing the ETS half needs an object iterator over `beam_bifs::TableRegistry`, which it does not expose (a cross-crate ask, not made);
* there is **no region word scan** for resources (unlike the refc payload's `HEADER_BIN_REF` pattern): a resource's identity lives inside its 4-word block and the mint block itself stands in a runtime region, so a word-pattern scan would match every candidate every time; the descent is region-agnostic instead, so any live copy is reached from the named roots and a copy in a region nothing names is dead data.
**The walk's completeness rests on `Runtime::gather_off_heap_roots`**, whose families are the escaped closures' capture environments, the `seq_trace` tokens, every live process's complete published root set (its dictionary, its mailbox, its registers, its saved arguments, its pending signals), `pending_spawns`, the two `RunnerState::gather_off_heap_roots` sub-families (`src/runner/entry.rs`: an engine's un-consumed arena-stable arguments and entry fun, and an **un-published** parked machine's own root set, gated on the pid still being in the process table) and every pending timer **delivery** (`src/timers.rs`). The engine and timer families matter for a **resource** even though the stabilization that put their terms on the arena flattened the refc payload in them, and every family matters for one in general: a resource's identity is its reference id and a copy of it keeps that id, so the prune's second match tier recognises the copy and a family left out makes a live resource look unreachable. The two non-park sites inherit that same set as their root enumeration, and the park arm (`src/context/gc/resources.rs::reclaim`) additionally seeds its walk with it as a **separate host seed list** — never through gate 5, which classifies the process's own roots only, because every host store is a foreign region by construction and merging it there would decline every prune a resource program attempts.
**Only the families that are live during a scheduler pass reach the park arm.** A pass moves the process table (`Runtime::take_processes`, so the runtime's own is an equivalent empty placeholder) and `RunnerState` out of the runtime, so at the park arm the per-process family and both engine sub-families are empty and the host seed is exactly the escaped closures, the `seq_trace` tokens, `pending_spawns` and the pending timer deliveries; the executing process's own root set is that arm's **local** root list instead (it mirrors the process's registers, which `park_machine` published a moment earlier). The per-process and engine families are live at the two **non-park** sites (`src/eval/reclaim/resource.rs`), which run with the runtime's own tables — that is where a resource held by another process, or by an engine's not-yet-consumed arguments, is reached and retained. Two spawn routes contribute no root at all, deliberately: `Runtime::spawn_process`/`Runtime::spawn_fun_process` hand `RunnerState::spawn` an `arena_args == false` engine, because their arguments may still stand on a pooled BIF heap the copy-out rewinds per call — a resource handed in through them is not kept alive by any prune, the documented cost of those two routes.
**Test strategy: the two witnesses are read as a pair.** `is_resource/1` answers whether the term still designates its object (`enif_get_resource` resolving the binding, so a released term answers `0`), `dtor_count/0` whether the object was actually destroyed, and neither alone distinguishes a release whose object another reference still holds.
Every other decline — an exhausted walk budget, an unknown boxed header, a valve trip — retains **everything** for that walk, and the observed frontier still advances so a persistent decline costs one walk rather than one per call.

## The resource-identity collision (closable only in `beam_abi`)
A NIF **resource term** is minted as an ordinary internal reference — `[hdr(3, REF_SUBTAG), small(0) node, small(0) serial, small(id)]` (`../../beam_abi/src/nif/enif/resources.rs`, `mint_resource_ref` → `write_resource_ref`), byte-identical to every plain reference this tree mints (`beam_term::boxed::write_internal_ref`'s frozen contract, also used by `beam_bifs`'s `make_ref_thing` and `beam_process`'s `MonitorRef::to_eterm`).
So the prune's second match tier — which recognises a **copy** of a resource by its reference id — cannot distinguish such a copy from an unrelated plain reference whose id happens to equal a live resource's.
The two id spaces are independent dense counters (`beam_abi`'s private static starts at 1, `beam_process::RefAllocator` at 0), so a collision is ordinary rather than exotic, and its consequence is that a reachable plain reference **retains** a dead resource term: a leak, never a dangle.
Measured on `tests/nif_resource_nested.rs`'s `dropped/2` legs, whose answer is `{dtor_count, live_count}`: `{1,9}` at N = 10 and `{164,36}` at N = 200, where the oracle answers `{10,0}` and `{200,0}`.
Those two legs assert the shared shape `dtor + live == N`, that every retained object still resolves (its `retained/2` companion answers `{1,9,9}` / `{164,36,36}` through the fixture's marker probe), that the prune really ran (`prunes == N`, `declines == 0`), and the **retention ratchet** `live <= 9` / `live <= 36` (`assert_dropped` with `LIVE_CEILING_N10`/`LIVE_CEILING_N200`, which `tests/nif_resource_nested.rs` will replace with the exact `{10,0}` / `{200,0}` equality once the collision closes).
The pending-timer family is what makes it observable there: with that family removed the same suite is fully green (10/10), but `tests/nif_resource_gc.rs::a_resource_named_only_by_a_pending_timer_survives_the_park_prune` then fails — so the family has to stay, and the collision is documented instead of traded away.
**The closure is a `beam_abi` change, not a `beam_rt` one**: mint the resource as a *distinct thing*, as ERTS does (`erts/emulator/beam/erl_term.h`'s `ERTS_MAGIC_REF_THING_HEADER`/`is_magic_ref_thing`), or give the host **one** shared reference-id allocator so the two spaces cannot collide. Nothing inside `beam_rt` can close it — every discriminating byte lives in the minted block, which `beam_rt` only reads.

## Ports, drivers and the send family (A.4)
Read path: one `{Port, {data, Data}}` per driver read, at the width the child wrote (`binary`→up to `beam_io`'s `READ_CHUNK`, 64 KiB, per `read(2)`; `list`→char list); child stderr is inherited by default (never port data) while `stderr_to_stdout` duplicates fd 2 onto fd 1 so its diagnostics arrive as port data in true write order.
A read's `Data` is shaped by the driver call's **own** `hbuf`/`buf` split, which `beam_io`'s `ReadMessage` carries: a `[binary]` port delivers the bare binary for a header-less read, `[H1..Hh|<<Body>>]` when the call carried both halves (an empty body ⇒ `[…|<<>>]`), the proper `[H1..Hh]` for a `NULL` body and `[]` for a read of nothing; a `[list]` port gets every byte flat.
A `dlopen`ed driver's split reaches the owner intact (`DriverHost::output2` records both halves, `DriverContext::deliver_read` carries them as one read, `StreamShape::Data` renders it), so `[72,68,82|<<"abc">>]` is oracle-identical.
A **built-in** driver port (`ram_file_drv`/`tcp_inet`/`udp_inet`) reports `StreamShape::DriverOutput` instead — the in-tree drivers hand bytes up through `beam_io`'s flat `DriverContext::input()`, which cannot name the entry point — so a `DATA` reply's improper binary tail renders as a proper list of the same bytes.
Two read residuals: a line-mode read's `hlen` is charged once per **frame** where the C charges it once per call (`beam_io` stamps it on every frame the call completed), and a zero-byte read is dropped where the oracle delivers `{data,[]}`/`{data,<<>>}`. Detail: [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
`{spawn_driver, Name}` resolves the name against the emulator's **static** driver set (`beam_io::STATIC_SPAWN_DRIVERS`: `tcp_inet`/`udp_inet`/`ram_file_drv`) before any `dlopen`, as the C does (`io.c:599-628`) — `fd`/`efile` (this crate's internal drivers) and an invented name are `badarg` exactly as on the oracle — then the loaded-driver list and the object-path search.
A driver port's `driver_output` reaches its owner as `{Port, {data, Data}}`, and a driver-emitted `erl_drv_output_term`/`erl_drv_send_term` term reaches the connected process or an explicit destination (`TermQueue` drain); an `ERL_DRV_PORT` operand of either resolves through `DriverHost::port_term` to this host's own live internal port term (an unknown or gone handle answers `None`, which `beam_abi` renders `-1` — never a fabricated port).
A driver that closes its **own** port (`driver_failure*`, `driver_exit`) is a port-closing request, not a return value: `beam_io` latches it from inside the callback, runs its own teardown and queues the term-free `PortFailure`, which `PortRegistry::take_failures` hands to `src/port/failure.rs` at every driver-callback drain point — behind the one `src/port/completion.rs::drain_io_completions` call the completion channel already uses, so the channel needs no drain site of its own.

## Distribution and the node (A.5)
The **responder half is complete and a system-ERTS node can use it**: `-name`/`-sname` make the runtime a distributed node, `DistNode` binds a wildcard listener, publishes to `epmd` best-effort (a failed publish is recorded, never fatal) and runs `'n'`/`'N'`+flags+challenge+creation+name → `'r'` → `'a'` → `DriverState::Established` against a real OTP peer (`tests/dist.rs`, `tests/live_inbound.rs`, `tests/dist_two_vm.rs`).
A **hidden and a non-hidden** peer are both accepted, never an error: `DistConnection::peer_visibility` records which, and the advertised set is `dist.rs::advertised_flags(hidden) = preferred_flags() | DFLAG_PUBLISHED`.
A refusal status the responder generates (`snot_allowed` on a bad flag set, `AcceptDecision::Refuse(status)`) is written **before** the link is closed, and every error path closes the connection (`DistConnection::pump` flushes, *then* propagates `step()`; `DistConnection::close`; `DistNode::retire`/`retire_at`) — no half-open silent socket.
`epmd`'s address is `ERL_EPMD_PORT` (`127.0.0.1:<port>`, or a bare port, or a `host:port` pair) when set, else `beam_dist`'s `EPMD_DEFAULT_ADDR`, for the node's own registration **and** every lookup this crate performs (`dist/node.rs::epmd_addr`, `dist_client/client.rs::connect_addr`).

## GC / heap model
`DEFAULT_HEAP_WORDS` is `1 << 24` (16 Mi words of lazily-mapped address space); term-construction heaps (BIF-heap pool + `-eval` heap) are bump arenas sized `config.heap_words`, `+hmax N` caps that capacity (`runtime.rs::term_heap_words`), and the `system_limit` translation runs after the copy engine's retry (`deliver_message` keys its heap-fragment fallback on a raw `AllocKind::Message`).
This crate does drive `beam_gc`: a *scheduled* process allocates on its own young heap and is collected at `ExecutionContext::ensure_heap`/`ensure_heap_full` (both share `collect_or_grow`; the latter is the full-root door `test_heap` reaches, armed by the slice's `BudgetContext`), pinned by `tests/gc_collect.rs` and reported by `Runtime::gc_stats()`; every other context no-ops on the unbounded arena.
Measured limit: a workload allocating only through `ExecutionContext::alloc_words` (no `test_heap` admission point, as real Cowboy `cowboy_bstr`-style code does) is not collected by *that* door — it grows the nursery and retries the bump (arena only when growth cannot reach it), and `Process::collection_debt` becomes a real collection at the *next* admission point — so on the **default** (native baseline) tier, which never pre-empts it, it reaches the term heap's hard limit with no collection at all (`collections: 0`; `heap_size` 3 074 841 / 29 485 327 words at N = 2 000 / 20 000).
The **reduction/yield-boundary door** (`src/context/gc/reds_door.rs`, from the runner's `Yield` arm) is the site that collects such a loop: it fires once per `REDS_BOUNDARY_MIN_REDS` (one `CONTEXT_REDS` slice) reductions over a nursery **seven eighths** occupied (the C's `ERTS_VBUMP_ALLOC_REDS` "allocation area exhausted" rule), so on the interpreter tier the no-admission shape collects once per ~17.8-reduction iteration with `heap_size` converged at 610 words (flat in N, one young space) instead of climbing, and `etf_roundtrip` goes 0 → 0.005 collections/call at a flat 376-word nursery.
Its cost on every other hot shape (per-call, ON vs OFF from one build) is [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*; its pins (`src/runner/tests/{reds_door,boundary_cost}.rs`) are bands re-derived from measurement — 17..=20 reds/iteration, `minor_gcs` (8, 88), converged `heap_size` 610, `checks_per_call` 0.40..0.50 and a door rate of `checks/9..=checks/7` (899 checks / 113 door collections at N = 2 000, 4 499 / 552 at N = 10 000).
The door collects with `Process::collect_kind(CollectionKind::Minor)` (`src/context/gc/reds_door.rs`) and escalates to the escalating `Process::collect()` only when that minor reports typed heap exhaustion — `beam_gc::Collector::collect_minor` requires `mature.available_words() >= nursery.used_words()` up front and copies nothing otherwise — so escalate-only-on-cannot-fit is the rule and a cadence fullsweep no longer comes from the door (*Cross-node handoff detail*).
Its per-iteration rates are the measured 3-row `MEASURED` table in `src/runner/tests/boundary_cost.rs`: ≈7.6728–7.6730 collections per iteration and one major per iteration plus a fixed 514 (1.2570 / 1.1285 / 1.0514 per iteration at N = 2 000/4 000/10 000).
A live float register is never left unrooted (the full-root doors publish the machine's live leading FR prefix, `Machine::fr_mark()`, so it lies inside the x file's pointer-bearing bound); a failed collection halts that process's collection, never the program.
**Retained-space caution:** `Process::grow_nursery` retires the space it replaces and only a real collection collapses that chain (`should_collect` ignores it), so a *genuinely* present foreign root **with** children keeps a process's capacity growing with its admission-point count (a `beam_process` policy matter — *Cross-node handoff detail*); a container that forwards **no scanned word** is inert under the valve's two-fact rule (*GC-relocation hazards*), so a reference-minting loop runs at a flat `memory(processes)` of 6.91 MB across N = 20 000 / 200 000 / 1 000 000, against the oracle's 13.7 MB (`context/gc/refs_plateau.rs`).
Term-heap capacity stays the hard limit for anything not collected: both exhaustion classes become `error::system_limit` via `error::enforce_term_heap_limit` — `AllocKind::Heap` (the per-process bump allocator) and `AllocKind::Message` (the copy engine's, classified by `beam_message::is_message_heap_exhaustion`) → CLI `beam_rt: system_limit`, exit 1.
On-demand growth is adopted at the admission point and on the `beam_process` delivery path: `ensure_heap`/`ensure_heap_full` run `Process::ensure_capacity` when the policy can reach it (`HeapPolicy::next_words(need, 0) >= need`), plain `Process::collect` otherwise, so a `test_heap` request larger than the nursery is admitted by growing it in place (`tests/heap_growth.rs`) while a bounded `+hmax N` request it cannot reach is refused *before* collecting (the allocation falls back to the arena); `Process::deliver` grows the nursery the same way for a refused message copy, and a relocation-exempt receiver skips the retry entirely.
Allocation outside an admission point uses bounded `beam_alloc::Heap` arenas that never move (`BifContext::heap()`, `Runtime::eval_heap`), so a BIF's *intermediate* terms are invisible to `roots`; a call overflowing such a heap raises `error::system_limit`. The one growth seam outside an admission point is the pooled BIF-heap frontier on the table-less (`-eval`/nested) route — `RuntimeContext::take_bif_frontier` retires a near-full region and continues in a larger one (capped only by an explicit `+hmax`) ([`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *The pooled BIF-heap frontier*).
### The BIF-result copy-out and `ets_copy`'s peak RSS
`RuntimeContext::call_registered` (`src/context/calls.rs`) moves an `Ok` container result **unconditionally on a process route** (`move_container = self.mailbox_table.is_some() || safe_to_rewind`) onto that process's own **scanned** young heap (`move_result_into_process_heap`, landing the copy in `x(0)`): the pooled 16 MiB `Runtime::bif_heaps` (`Target::Foreign`) is unscanned and a later call's rewind recycles it, so a heap object storing such a result (`compile:debug_info_chunk/1` holding `lists:filter/2`'s output in a tuple) would dangle.
A reference-holding graph is never moved and never rewound (`graph_holds_reference`): a reference's identity is its address, so a copy would no longer be the timer `erlang:cancel_timer/1,2` names — `badarg`, hence a `kernel_sup` crash. The walk that decides it is hash-free and allocation-free (an inline worklist, no visited set, a visit budget), ≈1.0 µs cheaper per container-returning BIF than the `HashSet` walk it replaced — [`../PERF_DISPATCH.md`](../PERF_DISPATCH.md) *WALK-CUT*.
The pool **rewind** to the call's pre-offset is the gated half — `safe_to_rewind` (no escaping `DispatchHooks` arm, no reentrant fun-applying call) **and** a succeeded move — so an `Err` result (a raise's live reason term points into this heap), a non-rewindable call and a failed re-home never rewind, the last because its words are still handed out.
The **table-less (`-eval`) route keeps the move gated** on `safe_to_rewind`, into the never-reset store: no collector exists there and a non-rewindable call never rewinds, so an unconditional move would only duplicate the result into an arena a long in-process compile exhausts.
The rule is load-bearing, not defensive: a container result left on the recyclable pool while Erlang code stores it in a heap object becomes a dangling boxed argument at the next rewind (the `invalid boxed header subtag`/SIGSEGV class), which is the shape `selfhost/in_process_compile_file_no_spawn_deterministic` exercises.
Residuals: a NIF result is not copied out (deliberate M1); an escaping `DispatchHooks` arm and an error result leave their container on the pool; the `-eval` store only grows; a nested run (`RuntimeContext::run_export`) never collects.
The copy-out cannot collect (a BIF call leaves the machine's x registers / Erlang stack unpublished), so the nursery is grown through the no-relocation `Process::grow_nursery` seam — **predictively** from the learned `RuntimeContext::copy_out_hint` (the copier's own reported shortfall) whenever the young space cannot hold it, and on a refusal for the first copy of each context or a graph bigger than the hint — and the retired young space is retained; hence `copy_bound/ets_copy`'s peak RSS growing linearly in N on the **default** tier, where neither `alloc_words_rooted` nor the boundary door collects (the interpreter tier's does). The measured mechanism, the figures and the refuted leads (the ETS adopt path, the caller-module float guard) are [`../PERF_DISPATCH.md`](../PERF_DISPATCH.md) *`ets_copy` peak RSS*.
The hint's residual: it is per `RuntimeContext`, so the first copy-out of each context still learns by refusing — **754 refusals per 250 000 ops ≈ 13 ns/op (0.4 %)**, down from 83 067 (0.332/op); removing it needs a `Runtime`-owned pid→hint map with cleanup on process death. What it bought: `copy_bound/ets_copy` **0.605×** on a paired A/B — [`PERF.md`](PERF.md) *The copy-out's learned size hint*.
Closing any of it needs a `beam_process` seam that can shrink/reuse retired young space or a `beam_engine`/runner seam that publishes the driving machine's roots at a BIF call so the copy-out can collect — sibling-crate changes, reported not worked around; the readable-word guard, the `grow_nursery` hint and the six `src/context/tests.rs` pins: [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *Per-call cost of a registered call* / *The table-less arm and its store*.
### The scratch-heap lifetime and the dangling-boxed-argument class
`erlang:system_info/1` hands its value **off** the reset-per-call scratch region: `Runtime::system_info`/`format_with` rewind it through `Runtime::reset_info_scratch`, which refuses to recycle a region a live term may occupy (`Runtime::info_heap_tainted`, a one-way taint valve latched when a relocation is refused), and the one value handed to Erlang code is relocated by `RuntimeContext::relocate_off_scratch` through the copy-out machinery above — onto the running process's scanned young heap, or the never-reset store on the table-less `-eval` route. A retained `system_info/1` value is therefore sound, pinned oracle-cross-checked by `tests/system_info_retained.rs` (the `epp:predef_macros/2` shape: `A = system_info(version), system_info(allocated_areas), system_info(machine)` answers `"17.1"`, and the `otp_release` form runs instead of dying).
The class it closes — `beam_term::ops::class`'s `invalid boxed header subtag 0x39` abort (`../beam_term/src/ops.rs:194`, reached `beam_bifs::lists::member` → `compare::cmp_impl` → `RuntimeContext::call_registered` from the baseline-JIT `jit_ext_call`) — has **no reproducer left**. `0x39`'s low two bits are `01` (`TAG_PRIMARY_LIST`), so no header constructor can produce it (`_make_header` = `(size<<6)+subtag`, every subtag `…00`; ERTS reserves only `0xF`, `../../erts/emulator/beam/erl_term.h:149,308`): the word read at `*boxed_val(x)` is a non-literal cons-cell pointer, i.e. a **dangling boxed argument** — a rooting/lifetime defect, never a `beam_term` classifier gap. It was seen twice on the in-process-compile path (`selfhost/in_process_compile_dependent_pair`, `selfhost/compile_file_of_a_module_whose_moduledoc_lives_in_a_file`); the shared-region recycle mechanism such a pointer needs is gone, and the two named cases ran **320** loaded differential times with **0** signals. Closure therefore rests on removing the mechanism and on the retained-value pin, **not** on a reproducer.
The differential sweep has **no per-case timeout** (`../tools/differential/src/runtime.rs:661-712`; `Observation.exit_code: None` = signal, `compare.rs:280-284,391-395`), so a `signal` verdict is still a real abnormal child exit and must be investigated as a fresh lifetime defect rather than dismissed as flake.
## Heap switches
`+hms`/`+hmbs` set `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000`→1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1.
`+hmax N` reaches the policy the process actually runs under on **every** route: the CLI value (`src/cli.rs` → `HeapOptions::set_max_heap_words` → `RuntimeConfig::heap`) is cloned by `Runtime::default_spawn_policy`/the boot-time spawns (`src/runtime.rs`) into the `beam_process::Process` the collector owns, and `spawn_opt`'s `{max_heap_size,…}` is installed by `SpawnOptions::policy` (`src/native/process.rs`) on the same field; `Runtime::new`'s `EmulatorDefault`/`Immix` resolution rewrites only `initial_mature_words`. Both are observable through `process_info(P, max_heap_size)` and `system_info(max_heap_size)`.
What `+hmax` does **not** bound is the nursery **chain**: `beam_gc`'s `Nursery::grow` clamps the space it *installs* to `HeapPolicy::max_heap_words` but **retains** the space it replaces (`beam_gc/src/nursery.rs:269-302`), only a collection collapses the chain (`:329`), and the reported `heap_size` is the chain's summed capacity (`:190-192`). A loop reaching no heap-admission point (`test_heap`/`allocate_heap`) therefore appends one retired space per exhaustion on the **default** tier — where it never pre-empts and so never reaches the reduction/yield-boundary door (`src/context/gc/reds_door.rs`) — so `grow3:main/1` (`list_to_tuple(lists:seq(1,400))` per iteration) reads 1 268 309 / 25 008 309 / 62 508 309 words at N = 1 000 / 20 000 / 50 000 under `+hmax 20000` with `collections` stuck at 19, against the oracle's flat `{heap_size,1598},{total_heap_size,2585},{collections,20342}` at `+hmax 0` and its exit-1 empty-output kill under `+hmax 20000`. Both unrooted growth seams (`src/context/gc.rs::alloc_words`, `src/context/calls.rs::move_result_into_process_heap`) make the cumulative ceiling `beam_gc`'s to enforce (*Cross-node handoff detail*).
`process_flag(max_heap_size, Map|Int)` and `spawn_opt`'s `{max_heap_size, Map}` share **one** parser (`src/native/process.rs::max_heap_setting` building `src/config.rs::MaxHeapSetting`, re-exported from `beam_process::{MaxHeapFlags, MaxHeapSetting}`): a bare integer or a map with a mandatory `size` and the three boolean keys `kill`/`error_logger`/`include_shared_binaries`, the previous setting answered as the oracle's four-key map in the C's construction order (`error_logger, include_shared_binaries, kill, size`, `erl_gc.c:3807-3822`), and the `badarg` matrix — a missing `size`, a `size` below the process's **own** `min_heap_words` (`MaxHeapSetting::violates_floor`), a non-integer/negative/float `size`, a non-boolean flag, a non-map value — leaving the previous setting untouched.
Both routes install the **whole** setting, flags included, on the PCB (`Process::set_max_heap_size`); it is caller-scoped (a child spawned later is born with the default map) and read back by `process_info(P, max_heap_size)`/`garbage_collection` (`tests/max_heap_flag.rs`).
The bound **is enforced** on the **prospective post-collection capacity**, never occupancy: every collection/admission and `serve_gc_request` drains the verdict (`src/context/gc.rs::drain_max_heap_verdict` — the ERTS `=ERROR REPORT====` block on **stderr**, exactly **once** per killing breach, printed before the `Kill` is latched, the C's report-then-kill order, `erl_gc.c:3744-3803`), and `src/runner/run.rs::take_max_heap_kill` turns the latch into `RunOutcome::Exit(<bare atom killed>)` on the returned/wait/err/yield paths, so the ordinary `terminate` propagates `{'EXIT',Pid,killed}`/`'DOWN' … killed` (`tests/max_heap_enforce.rs`).
Residuals, pinned there: (a) the report is on **stderr** with the bare `=ERROR REPORT====` header where the oracle's `logger` writes to **stdout** with `==== <timestamp> ===`; (b) 7 of the C's 9 fields (`GC Info`, `Stacktrace` omitted, never fabricated); (c) a latched `Kill` is performed at the runner's **next slice boundary**, so the victim may run the rest of its slice; (d) the `-eval` action process is never enqueued, so a verdict latched there is never drained; (e) `+hmax` does not bound the growth-retired nursery **chain** (*Cross-node handoff detail*); (f) `include_shared_binaries`' off-heap figure is the **last pre-emption's** surviving payload bytes, published by the `Yield`-arm reclamation (`Process::set_off_heap_binary_bytes`, `src/context/gc/bin_vheap.rs:456`): a slice's freshly built payloads are charged only after its pre-emption, a process that has not pruned yet falls back to the PCB's own roster-derived sum (empty in production, so nothing), and once the override exists it **replaces** that sum rather than adding to it — the C's `bin_old_vheap` term is absent too, so the charge is a small under-estimate, never an over-estimate (`beam_process::MaxHeapUsage::charged_words`).
## CLI `run` argument tokens
`beam_rt run <beam> <m>:<f>/<a> <arg…>` materializes an integer token with `beam_term::make_small` (`src/runtime.rs::materialize`, reached from `src/cli.rs::parse_arg_term`'s `i64` arm) without a range check: a token above `MAX_SMALL` (`2^59 - 1`) aborts on the `debug_assert` in a debug build (`beam_term/src/immediate.rs:77`, exit 101) and is silently truncated to a wrong small int in a release build — `… bm:mk64/1 576460752303423488` prints `<<248,0,0,0,0,0,0,0>>` where the oracle prints `<<8,0,0,0,0,0,0,0>>`, a wrong result, the one class the runtime forbids.
The fix belongs in those two files: range-check the parse and build a bignum (or reject the token), via `beam_term::try_make_small` + the bignum writer — the same range check `src/cli.rs` applies to `+hmax` (`src/cli.rs:778`).
`tests/bignum_bit_segment.rs` documents the hazard and reaches the same segment through a string token instead; the `-eval` route is unaffected (its integer literals are exact bignums).

## OTP-lifecycle survey
### Works today (oracle-identical)
`code:which/1`, `code:get_object_code/1` (the oracle's path-based `{Module,Binary,Filename}`), `code:load_file/1` (then `module_loaded/1` true), `code:delete/1` (the live `code_server` round trip: `true`, the module gone from the store, the server and the native `code:*` floor still answering — `tests/code_delete_live.rs`), `erlang:delete_module/1` (see *The code store* below), `application:get_key/1,2`, `application:loaded_applications/0`, `application:which_applications/0`, `error_logger:warning_map/0`.
A `spawn`/`spawn_link` child whose entry blocks in `receive` parks and resumes (`spawn(M,F,[])`, via a cross-module call, `erlang:apply(M,F,[])` or a local fun); local fun application with free variables works while the body completes without suspension; a `receive … after T` that must time out delivers on every route, including through a nested run.
Plain `!`/`receive`, `erlang:monitor(process,P)` and `monitor(process,P,Options)` with a `{tag,T}` and/or `{alias,Mode}` work, as do `sys:get_state/1`/`sys:*`; `gen_server:call/2,3` and `gen:call/3,4` work for a finite timeout and `infinity`, for a pid *and* a registered `{local,Name}`, because `gen:do_call/4`'s finite-timeout clause (`lib/stdlib/src/gen.erl:251`) and its `erlang:send/3 [noconnect]` are both served.
The whole-file `file` family completes from a scheduled process (`read_file/1`, `write_file/2`, `open/2` read/write, `close/1`, `list_dir/1`, `get_cwd/0`, `consult/1`, `read_file_info/1`/`read_link_info/1` — an existing path answers `read_write` — and `filelib:is_file/1`), and the incremental io-device read path agrees on both routes (buffer-first device); the one divergence is `{get_chars,…}` on an `{encoding,unicode}` device, which counts bytes where the oracle counts characters (`src/native/file_server/CONTEXT.md`).
### Confirmed failing — root cause and repro
1. `logger`/`error_logger` reports are emitted but reach no native logger sink: a booted runtime has a live `logger` process and the `logger` ETS config table (`ets:whereis(logger)` is a `#Ref{}`), so `logger:info/1,2`, `warning/1`, `error/1`, `error_logger:info_msg/1,2` and `error_msg/2` all answer `ok`, but the `lg:*` helpers need a native logger ETS floor this runtime does not provide.
2. `application:start/1,2`, `application:stop/1` and `application:ensure_all_started/1` reach the live controller (a live pid on every CLI route, so the request is answered rather than `noproc`), but only the boot script's own applications are startable — `ensure_all_started(crypto)` → `{error,{crypto,{"no such file or directory","crypto.app"}}}`, the native floor answering only the read-only queries above. Repro: `ap:start_sasl/0`, `ap:start_syntax/0`, `ap:ensure_syntax/0`.
### The `-eval` vs scheduled asymmetry
The `-eval` action process pumps the scheduler and can suspend a blocking call; a scheduled process (`run`) parks at its own top-level `receive`, and a scheduled slice is *running*, not runnable (`beam_process::Scheduler::slice_begin` sets `ProcessState::Running`), so a signal- or delivery-driven collection of it is declined (*GC-relocation hazards*).
A `spawn`ed `-eval` closure runs synchronously to completion in the evaluator (`src/eval/mod.rs`, `apply_eval_closure`) on the slice's own context (`may_pump_scheduler` false), so a `receive … after T` **inside** it scans the mailbox, makes one port-poller pass and takes its `after` body; the action's **own** `receive … after T` runs outside any slice over three sources — a mailbox rescan, a bounded pump (`RECEIVE_PUMP_SLICES = 64`) and `Runtime::wait_for_timer` — so a `-eval` child that "parks" returns and terminates before the parent's next statement, and the async-completion shape for a live blocked target is pinned only on the scheduled route (`tests/garbage_collect.rs`).
### The code store — `delete_module/1` unloads, `purge_module/2` is `notsup` outside the purger, and the floor serves `purge/1`/`soft_purge/1`
`erlang:delete_module/1` is served from the `RuntimeHooks` bridge (`badarg` for a non-atom, the atom `undefined` for a name the store does not hold, `true` plus a real `CodeServer::forget_module` unload for one it holds), and so is `erts_internal:purge_module/2` — the `error:notsup` raise, through the same `notsup()` helper as `erts_literal_area_collector:release_area_switch/0`.
That `notsup` is the oracle's answer for a caller **other than the code purger**: the C raises it only `if (BIF_P != erts_code_purger)` (`../../erts/emulator/beam/beam_bif_load.c:2088-2092`), so the registered purger process reaches the real prepare/complete purge behind the same BIF (the machinery has existed since OTP 19.1; nothing was removed in OTP 29). A **direct** caller of `erts_internal:purge_module/2` therefore still gets the oracle's `notsup` (measured for an atom, an unloaded atom and a non-atom), and stays that way.
`code:purge/1` and `code:soft_purge/1` do **not** go through that path any more: both are served from the runtime-native floor (`src/native/code.rs`), so the live `code_server` never sees the request and **survives** it. This runtime keeps **no old-code slot** ever (`erlang:delete_module/1` really unloads, a reload replaces the live entry), so nothing can be purged and nobody can be running old code; the honest answers are the oracle's own constants for that state, measured on OTP 29.1.1 / `erts-17.1`: `code:purge(Mod)` ⇒ `false` for a loaded module, an unloaded atom and a module just deleted, `code:soft_purge(Mod)` ⇒ `true` for all three, and both raise the bare-atom `error:function_clause` for a non-atom (`code.erl:722`/`code.erl:740`'s `is_atom/1` guard; `42` and `[]` measured) — with `is_pid(whereis(code_server))`, `code:all_loaded/0` and `code:is_loaded/1` still answering after **every** call (`tests/code_delete_live.rs`).
Residuals, both documented rather than fabricated: no `erts_code_purger` process exists here (`erlang:whereis(erts_code_purger)` ⇒ `undefined`; the oracle's ⇒ `<0.1.0>`, and it is in `PRELOADED_MODULE_NAMES` only because that list is the oracle's), and the guard raise carries **no** `.beam` frames — a caught `function_clause` renders as `{function_clause,[]}` where the oracle's carries `code:soft_purge/1`'s frame (the crate's `function_clause` convention: a native floor arm never fabricates a wrapper stacktrace).
`code:delete/1` — the live-server round trip — is unaffected and agrees on both routes (`tests/code_delete_live.rs`, seven oracle-cross-checked tests, the purge matrix among them).
This runtime keeps **no old-code slot**, so a delete really unloads where the oracle only retires the module into old code: measured on OTP 29.1.1 / `erts-17.1`, the oracle's `erlang:delete_module(lists)` answers `true` and leaves the module in the store (`code:is_loaded/1` still `{file, …}`, `code:all_loaded/0` still lists it, `erlang:check_old_code/1` now `true`, `erlang:module_loaded/1` still `true`; the same rows for a scratch module read `{true, false, true, {file, …}}` — the delete's own retirement column, pinned by the suite), while here `module_loaded/1` and `code:is_loaded/1` answer `false`, `code:all_loaded/0` drops the entry and `check_old_code/1` stays `false` (the path-based `code:which/1` still answers the on-disk `.beam`, exactly as for a module that was never loaded).
The two consequences that follow: a **second** `erlang:delete_module/1` is the oracle's `error:badarg` plus an `=ERROR REPORT==== … Module lists must be purged before deleting` on the oracle and the unheld `undefined` here, and this runtime emits **no** report at all (it has no logger sink); `code:delete/1` answers `true` then `false` on **both** runtimes (the server's own `moddb` record is what the second call misses).
The reasoning and the full measured column are [`src/context/runtime_hooks.rs`](src/context/runtime_hooks.rs)'s module docs and `RuntimeHooksBridge::delete_module`; the pinned rows are `tests/code_delete_live.rs` (the direct BIF's two old-code rows are asserted as this runtime's own state, the rest cross-checked against the live oracle).
### The expected-module-name check on every name-based load route
`CodeServer::load` decodes the image and refuses it **before caching** when the object code's own module name differs from the requested one — the C's `check_module_name` (`../../erts/emulator/beam/beam_load.c:185-187`) — so `code:load_file(M)` ⇒ `{error,badfile}`, `code:ensure_modules_loaded([M])` ⇒ `{error,[{M,badfile}]}` and `code:ensure_loaded(M)` ⇒ `{error,badfile}`, exactly as `code:load_binary/3` already answered.
That one check covers every route that carries a requested name: the three `code:*` forms, the boot script's `{primLoad,…}` directives and the on-demand load of an external call all end there, and the refused image is cached under neither name. `CodeServer::load_path` (the CLI `run` route and the slice fixture) deliberately keeps own-name semantics — an explicit file has no requested name to check against. Residual: the oracle's `beam_load.c(186) … module name in object code is <Real>` ERROR REPORT is not modelled (its value is). Pinned by `tests/code_load_file.rs` and `src/native/code.rs`'s units.
### The `spawn(M,F,A)` reason surfacing — documented eager resolution
The oracle's `spawn`/`spawn_link`/`spawn_monitor(M,F,A)` do **no** loading at spawn time: the spawn succeeds and the **child** dies when it applies the MFA, so a `<Name>.beam` whose object code names another module (or no file at all) answers `true` and `{'DOWN',Ref,process,Pid,{undef,[{Name,F,Args,[]}]}}` (measured on OTP 29.1.1 / `erts-17.1` with a `mismatch.beam` really holding `mymod`: `spawn_monitor(mismatch,id,[7])` ⇒ that `'DOWN'`, plus the node's own `beam_load.c(186) … module name in object code is mymod` report; `spawn_monitor(nosuchmod_xyz,f,[1])` ⇒ the same shape).
This runtime resolves the export entry **eagerly**, at `Runtime::resolve_export_entry` (the code-path search, the load and the export check — the same route `spawn_export_child_with_policy` takes from inside a slice), so the identical load failure raises at the **spawn site**: `catch spawn_monitor(mismatch,id,[7])` ⇒ `{'EXIT',{undef,[{erlang,spawn_monitor,[mismatch,id,[7]],[]}]}}` (measured), never a `'DOWN'`; `spawn(mymod, nosuchfun, [])` raises the same way where the oracle spawns and the child dies.
Closing it needs two pieces this runtime does not have: a **lazily resolved** export entry (a dead-on-arrival child that resolves its module at its first slice) and the ERTS **exit-reason** shape the dead child carries (`{undef, Stacktrace}`), where the runner's reason translation (`src/runner/reason.rs::exit_reason`) renders a bare atom or a live reason term only.
It stays a typed, documented gap rather than a fabricated agreement; the reasoning is `Runtime::resolve_export_entry`'s rustdoc.
## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers the running process's own young heap (a capacity refusal met by a no-relocation `Process::grow_nursery` and one retry) and falls back to the pointer-stable `Runtime::arena`, so what a moving heap would dangle is a raw `Eterm` pinned **outside** the GC root set.
`Process::regs` is a snapshot, not a live mirror: `publish_roots_full`/`scatter_roots_full` (`context/gc.rs`) copy the x file's **pointer-bearing prefix**, the whole stack and the FR prefix (bounded by `fr_count`) at every full-root admission point (`gc::ensure_heap_full`/`alloc_words_rooted`, bound `gc.rs::machine_root_bounds`) or at a **publishing** (non-exempt) park, so a collection reaches x/stack/FR and nothing else — a Rust local or an un-published `Machine` field is not in the root set, and the engine's `live` count is ignored.
The admission-point collection *is* the publish/collect/scatter hand-off (safe); the delivery- and signal-driven ones are refused for a receiver with unpublished roots (`Process::has_unpublished_roots()` = `relocation_exempt || state == Running`, `beam_process/src/process.rs:1098`, tested *first* by every caller — a refused delivery becomes a heap-fragment delivery, a refused ptab signal goes to `enqueue_fragment_signal`), `beam_rt` adds `delivery_collection_is_unsound`, and `RuntimeCollectionGate` declines a woken-but-not-yet-resumed (`Runnable`) receiver; an exempt (and every Wait) park publishes nothing and its `serve_gc_request` is declined, while a non-exempt park publishes first. The `Yield` arm is exempt exactly when the slice ended with a live FR prefix (`fr_count > 0`), and the residual exposure is a live term outside `process.regs` — hence `relocation_exempt` (`self()`, the wrapped `-eval`/nested-`Machine` scope, the parked window).
A collection is also DECLINED when a root — or a container the scanned graph reaches — lies in an unscanned region (the unscanned-root valve): `RuntimeContext::call_registered` hands `beam_bifs` the pooled 16 MiB `Runtime::bif_heaps` and `gc::alloc_words`'s fallback hands blocks out of `Runtime::arena`, both `Target::Foreign` (`beam_gc/src/copy.rs` leaves a pointer outside `FromSet` as-is). Its two phases (`root_is_unscanned`, then the `gc_walk.rs` descent under the per-pid latch) span the published machine roots plus the process's own root-set containers (`Process::collect`'s registers, mailbox, dict, saved arguments, pending signals); a refusal needs *both* an unscanned region (`gc::word_region` → `WordRegion::Foreign`) and a child the collector would follow or update (`forwards_scanned_word` → `word_is_scanned`), so a reference, pid, port, float, bitstring, empty tuple and an all-immediate block are inert. The latch's raison d'être is `Runtime::bif_heaps` — a container a registered BIF built there (`erlang:'++'/2`, `lists:append/2`, `lists:reverse/1`, `lists:filter/2`, `ctx.tuple(…)`) writes the caller's heap `Eterm`s verbatim, so its holder is reachable only through the unrewound paths (a NIF result, an escaping `DispatchHooks` arm, the `-eval`/nested shape, an error result) at depth ≥ 2 below a scanned root; `beam_rt run w.beam w:f9/0` renders the oracle's exact `~w` at exit 0.
All five decline sites (the three admission points, `Runtime::serve_gc_request`, `delivery_collection_is_unsound`) answer `Ok(())`, and both allocation doors try the owner's young heap first (a non-forced refusal `grow_nursery`s and retries the bump) **before** the valve and the arena, leaving the `Process::collection_debt` the next admission point's occupancy test turns into a real collection.
Refusal chain (`run_rooted_collection`, `serve_gc_request`, the gate's latch cell), latch open/close sites and per-admission cost, the five wrapped scopes/pin rules and the *at risk*/*safe* roster: [`IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *What a MOVING engine heap would invalidate* / *Relocation exemption* / *The unscanned-root valve — two phases* / *Debt/valve cost of the admission doors*; descent pins: `src/context/tests.rs::{the_valve_declines_a_foreign_container_nested_in_a_scanned_container, …_a_deeply_nested_foreign_container, …_collects_when_the_nested_graph_is_fully_scanned}`.
