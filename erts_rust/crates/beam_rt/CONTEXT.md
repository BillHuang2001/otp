# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture — `main.rs`, the **CLI flag surface** (**A.6**), **`system_info/1`** + `erlang:process_info/2` (**A.8**) and the **boot sequence** (`src/boot/{preloaded,bootscript,drive}.rs`), which loads the 22 preloaded `.beam`s and runs the real `bootstrap/bin/start.boot` to completion (`{progress,started}`, **A.7**); every action but `-version` drives that script, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — every optional `beam_bifs` host seam, the **A.4 runtime side of ports**, the **runtime-local timer deadlines** (`src/timers.rs`) and the **distributed node** (A.5: `src/dist/` accepting, `src/dist_client/` connecting).
The vertical slice runs on a test-only `MinimalContext` at the engine level (`../beam_engine/tests/slice.rs`) and through this crate's real glue (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`, terms/heaps → `beam_term`/`beam_alloc`, pids → `beam_process`, modules → `beam_loader`, execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half and `DistClient` the *connecting* half, sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (`Runtime::dist_ensure_link`).

### `malloc.rs` — the allocator's free-page release
`beam_rt::release_free_pages()` is the crate's single allocator lever (`libc::malloc_trim(0)` on glibc, an honest `None` elsewhere), called **once per process** from `src/main.rs` after the `"beam_rt-driver"` thread is joined — the only quiescent *and* complete point.
The runtime is not torn down at exit (`ExitTeardown::Leak`), so it finds a largely **live** arena and returns little: **capacity is not RSS**, and peak `VmHWM` is untouched.
`BEAM_RT_MEM_TRACE` prints the answer as one `[rt-mem] heap-release=…` line and nothing depends on it.

### Crash reports (`src/report.rs`) — an abnormal termination's `=ERROR REPORT====` block
One report per process that dies from an uncaught **`error`-class** exception (an uncaught `throw` is promoted to `{nocatch, V}` and reports too), written to **stdout** in the default handler's shape — the `logger_formatter` legacy header, `Error in process <Pid> with exit value:` and the `{Reason, Stacktrace}` term through the one `~p` printer (`Runtime::format_term`) — and silent, matching the oracle, for an `exit`-class reason (`exit/1`, `normal`, `shutdown`, `killed`, hence every link/monitor/`exit/2` propagation), a trapped `{'EXIT', …}`, a normal return, and the process the `run` action itself waits for.
The one call site is the runner's termination arm, and the stacktrace is the raise's own (`beam_common::StackTrace`); a report that cannot be built or written goes to `debug_trace`, never into the termination's own outcome.
Honest gaps: the header timestamp is **UTC** (the oracle renders local time), the block is written by `src/report.rs` itself rather than through `logger`, and there is no SASL `supervisor`/`gen_server` report, no `erlang:error/2,3` arglist (`error_info`) form and no `max_heap_size` report.
The handler set behind `logger` is the oracle's `[default]` (`logger_std_h` over `standard_io`), registered by the boot's own `logger:add_handler/3` after the last directive, so `get_handler_ids/0` and `get_primary_config/0` agree on every route and `init:restart/0` keeps exactly one handler — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The default logger handler*.
### The death-path reason — the bare one and the signalled one (`src/runner/reason.rs`)
A process that dies of an uncaught raise has **two** reasons: the **bare** one (`exit_reason`, the raise's own reason untouched by its class — what the report is given and `RunnerState::errors` classifies by) and the **signalled** one (`signalled_reason`, ERTS's *exit value* — the term `RunOutcome::Exit` hands to `ProcessTable::terminate`, hence what a linked peer's `{'EXIT', Pid, R}` and a monitor's `{'DOWN', Ref, process, Pid, R}` carry, locally and over `DOP_EXIT`/`DOP_MONITOR_P_EXIT`).
The rule: `error` class ⇒ `{Reason, Stacktrace}`; uncaught `throw` ⇒ `{{nocatch, Value}, Stacktrace}`; `exit` class ⇒ the reason **bare** (`bye`, `normal`, `shutdown`, `kill`, including every propagation); a `max_heap_size` kill ⇒ the bare atom `killed`; a non-raise `BeamError` (plumbing: no class, no stacktrace) ⇒ the bare interned `Display` text, because inventing an empty trace would fabricate a shape the oracle never produces.
Both come from the one definition `crate::report::exit_value`, so report and signal can never disagree about one death; the rooting, the private heap and every degradation (`signalled_or_bare`, the flattened off-heap reason) are [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *The death-path reason — bare vs signalled*.
Measured against the oracle (a compiled module with `trap_exit` + `spawn_link`): `erlang:error(boom)` ⇒ `{boom,[{died,boom,0,[{file,"died.erl"},{line,18}]}]}`, `throw({ball,1})` ⇒ `{{nocatch,{ball,1}},[{died,thr,0,[{file,"died.erl"},{line,19}]}]}`, and `exit`/`normal`/`shutdown`/`kill` ⇒ the bare atom — byte-identical on both sides.
## The atom index space — `src/atom_seed.rs`
The runtime's **one** shared `AtomTable` starts from `erts/emulator/beam/atom.names`, interned in **file order**: `CodeServer::new` calls `crate::atom_seed::seed`, and it is the only seed source that runs before any module loads.
The file is embedded with `include_str!` (compile-time, never read at run time) because it is the committed C-side source data that *defines* ERTS' atom index order — a `beam_rt` binary then needs no installed `$ERL_TOP`, and a missing tree cannot silently produce a partly seeded table; it is the workspace's only cross-tree `include_str!`.
`beam_term::AtomTable::seed_from_atom_names` does the parse (grammar: `atom <name>+`, quoted `CName='printname'`, `#` comments); interning is idempotent, so the file's repeated names (`infinity`, `timeout`, `normal`, `call`, `false`, `true`, …) keep their first index — 773 names on 740 lines are **763 distinct** indices.
Atom **comparison** is by name (OTP 26+, hence `lists:sort/1` is alphabetical), but the **storage** order of a flat map's key tuple follows the atom **index** — which is what orders `maps:keys/1`, a `~p`-rendered map and `term_to_binary/1`'s `MAP_EXT` key sequence. That is the observable this seed closes.
`boot::seed_core_atoms` stays the **append-after-the-seed** step it always was: `CORE_ATOMS`, `info_atoms()`, `PORT_INFO_ATOMS` and `SignalAtoms` are interned by name afterwards, idempotent, so a name the file already lists keeps the file's index and only the rest (the `os_type` group `unix`/`linux`/`win32`/`nt`, `preloaded`, `bad_name`, the `+sbt` spellings, …) is appended. The whole seed is **1 234 distinct names**.
The remaining ordering residual is the file itself: this tree's `atom.names` is the OTP-30-rc0 file, so an older host oracle can differ past a name that was inserted/reordered between the releases — measured: `'+'` precedes `'*'` in this file while an OTP-29.1.2 oracle orders map keys `["*","+"]`, and two names **outside** the file (`a`, `b` in `#{b=>1,a=>2}`) have no file-fixed relative index at all, so the oracle answers that pair differently depending on what its boot interned first.
What was verified: 37 sample pairs (file order ≠ alphabetical order, spread over the whole file) compiled into 2-key map literals and run under the oracle all agreed with this file's order, and every name in the pinned verification rows sits in `atom.names` lines 44-543.
Pinned by `tests/atom_seed_order.rs` (the `maps:keys/1` row, two `~p` renderings, the `MAP_EXT` bytes, an index-order guard that needs no oracle, and `atom_count` = this runtime's own table length) and by `src/atom_seed.rs`'s unit tests (file order, quoted/empty atoms, duplicates, idempotency, append-only).

## Host-side term stores — owned copy vs raw word (the rule that makes a store sound)
- **A raw `Eterm` in a long-lived slot roots nothing** — a term that can outlive one instruction (a raise reason, a pending reply, a parked value, a cache entry) must be copied onto a scanned heap or explicitly stabilized before its owner's heap can be relocated.
- **A pointer-stable, never-scanned store (the arena, `alloc_words`) is the wrong home for a container whose children live on a scanned young heap** — the copier gives it `Target::Foreign` and never descends.
- **An exempted heap-growth or move must "refuse ⇒ stabilize, never dangle"**, and **an `Rc` lease held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow.**
A stored term is self-contained only if it went through `Runtime::stabilize_term`/`try_stabilize_escaped` (a copy onto the `eval_heap` + `eval_off_heap` store), was built on the pointer-stable arena, or was built on a pooled BIF heap the escaping `runtime_hooks` arm froze; every store is **pointer-pinned**, so the one thing it cannot survive is a **move** of the region it names — done only where nothing executes, rewriting every stored word through `Runtime::for_each_root_family_mut`.
The per-store roster (owned copies / immediate-only / deliberate raw words) and the move's two instants: [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) *Host-side term stores*, `src/context/IMPLEMENTATION.md`, [`src/runtime/roots/CONTEXT.md`](src/runtime/roots/CONTEXT.md).
## The runtime-native BIF floor (`src/native/`)
The floor serves the BIFs that are really *runtime* operations — process/port tables, code server, atoms, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file`/`prim_buffer` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry, and **a native entry never duplicates a registry one**; an unclaimed call returns `None`.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`), and `io`/`prim_tty`/`prim_file`/`prim_buffer` are **key-granular** (`floor_keys`), so only the enumerated keys are refused in-machine.
`application:*` is deliberately **not** a floor namespace: every key of it is a one-line `lib/kernel/src/application.erl` delegation to the live `application_controller` the boot script starts, which answers from the `ac_tab` it really populates.
The floor owns the process/name/global-state arms (`ProcessBridge`'s only implementation), `process_info/1,2` (`src/native/memory/`), `monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` with the reference-alias send destination (`src/context/alias.rs::alias_destination`, on **both** send seams) and `garbage_collect/0,1` — **no BIF may collect**, so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true` where the root set is owned.
`erlang:apply/2` is a floor key with real `apply(Fun, Args)` semantics (`src/native.rs` → `src/context/apply.rs::apply_2`, faithful to C's `apply_fun`): `apply/2,3` are the two keys ERTS implements as *instructions*, so they appear in **no** `bif.tab` line and `beam_bifs` has no implementation. The floor arm matters whenever the argument list is not a literal — `beam_ssa_codegen` emits `call_fun` for a literal list but `call_ext_only 2 {extfunc,erlang,apply,2}` for a variable one (a list built by a `case`), and the previous `apply(Mod, Fun)` reading answered `badarg` there (`tests/apply_two_args.rs`).
`prim_tty` and `prim_buffer` are built-in libraries: `is_builtin_library` answers their `erlang:load_nif/2` load (the C's `STATIC_ERLANG_NIF`, so nothing is `dlopen`ed) and `NifRegistry::is_loaded/1` stays **`false`**, which is what keeps their Erlang wrappers enterable in-machine.
**`code:*` reads and the code path are the floor over `CodeServer`**: the floor owns the **one** authoritative path store — readers **and** the `add_path*`/`del_path` mutators — and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store*).
`process_flag/2`'s three heap-sizing flags `min_heap_size`, `min_bin_vheap_size` and `fullsweep_after` are served as per-process bookkeeping (`ProcessHook::process_flag_2`, `src/context/process_bridge.rs`; store `Runtime::heap_flags`, read back by `src/native/memory/`): `is_small` + `>= 0` or `badarg`, the **old** value returned, the new one rounded through the emulator's grain (`beam_gc::next_heap_size` — the C's `erts_next_heap_size`: Fibonacci+1 to index 23, then 20 %, `H_MIN_SIZE` 233 / `BIN_VH_MIN_SIZE` 46422 floors) with `fullsweep_after` narrowed to `u16` (setting `100000` reads back `34464`).
**Nothing sizes a heap from the stored value**, so a process's `heap_size` stays at its birth capacity: measured with `process_flag(min_heap_size, 200000)`, the oracle reports `heap_size` 6772 immediately and 318187 after `erlang:garbage_collect/0` while this runtime reports 233 throughout, and both read the flag back as 318187 (the emulator grain).
`beam_gc` exposes the adoption seam already (`beam_gc::HeapPolicy::{set_min_heap_words, set_min_bin_vheap_words, set_fullsweep_after}`, `crates/beam_gc/src/{policy,flags}.rs`); the missing half is `beam_process::Process::collector_mut(&mut self) -> &mut AnyCollector` beside `collector()` (`crates/beam_process/src/process.rs:1453`), so no store site can reach the collector's policy — a sibling-crate ask recorded in `src/context/CONTEXT.md`, never a silent ignore.
`Runtime::new` starts exactly **four** runtime-owned, never-enqueued `Runnable` processes (the `init` stand-in `<0.0.0>`, the root process `<0.1.0>` every action runs as, the `erl_prim_loader` stand-in and the `file_server_2` service), and `call_bif`'s last resort is the **`erlang` namespace**: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y` (exit 3), any other unclaimed name the bare `error::undef` — `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` and its drift guard are the authority.
`dets` works end to end on this floor — `open_file/insert/sync/lookup/match_object/close` agree with the oracle byte-for-byte, **including the `.dets` file bytes** (`tests/dets.rs`, `tests/prim_buffer.rs`), which is what the `prim_buffer` stubs and `flatten_iodata`'s binary improper tail buy.
The module list, `floor_keys`, the `prim_buffer`/`prim_file` descriptors and read-ahead queue, the `io` device classes and the dispatch index: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **four** built-in key sets — `prim_tty`'s 20 stub keys, `zlib`'s 19 stream keys, `prim_file`'s one key `advise_nif/4` and `prim_buffer`'s two unexported stubs `peek_head/1`/`copying_read/2` — from a module-name equality short circuit plus a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash (the `prim_tty` and `zlib` sets are what `beam_bifs::serves_local_call` exposes).
`prim_file`'s key is what `prim_file:advise/4`'s own body chains into at `prim_file.erl:433`, so `file:sendfile/5`'s wrapper sees the oracle's `{error,badarg}` instead of the stub's `erlang:nif_error(undef)` — `src/native/prim_file/advise.rs`, which also decomposes the **descriptor argument** exactly as the oracle's `prim_file.erl:274-280` over `get_fd_data/1` does (`advise_descriptor`: a non-3-tuple or wrong-tag argument ⇒ `error:function_clause`, a `Data` that is not a map or lacks `owner`/`handle` ⇒ `error:{badmatch, Data}`, a non-controlling owner ⇒ `error:not_on_controlling_process`, and only an *unresolvable handle* on a well-shaped descriptor stays the `{error,badarg}` **value**); `prim_buffer`'s two keys arrive as LOCAL `call`s inside `prim_buffer.erl` (its exported stubs come in by `call_ext`) and both routes converge on the one `prim_buffer_call`.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`) serves the **record-held** shape of the `zlib` set: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body — oracle-identical at every level 0–9 through the real preloaded `zlib.beam` (`tests/zlib_{stream_levels,stream_dict,guards,one_shot}.rs`).
## The synthesized BIF stacktrace item's extension (no runtime-side classification)
The engine's `families/exceptions/bif_frame.rs` decides the `[{error_info, #{module => FormatModule}}]` location extension from **its own closed table plus the raise's reason** (`format_module(module).is_some()` and the reason not being a bare `function_clause`), so this crate contributes no classification of a failing name and no seam for one.
A `beam_bifs` **stdlib fast path** therefore keeps its module's extension exactly like a declared `bif.tab` BIF (OTP's sources re-raise through `error_with_info/2`), measured on the oracle as `lists:seq(1,2,0)` ⇒ `{lists,seq,[1,2,0],[{file,"lists.erl"},{line,541},{error_info,#{module => erl_stdlib_errors}}]}` — this runtime reproduces the module/function/arglist/extension and leaves the source position as the documented residual (G *A BIF that raises publishes no callee stacktrace item*).
## The CLI switch surface (A.6)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (no interactive shell) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod F [Tok…]` | the ERTS Start instruction: `Mod:F(['Tok', …])` — **arity 1**, one argument, the collected tokens as **atoms** (`-s Mod F` ⇒ `Mod:F()`, arity 0), result **discarded**; a numeric token is a **name** (`-s mod f 1 2` ⇒ `['1','2']`) |
| `-run Mod F [Tok…]` | the same single-list shape with every token a plain **string**: `-run Mod F a b` ⇒ `Mod:F(["a","b"])` (`[[49],[50]]` for `1 2`), result **discarded** |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse order), `-pz` **tails** it (behind the system `ebin`s), on **every** route |
| `+S Total[:Online]` | normal scheduler counts via the C's `sscanf("%d:%d")` → `sscanf(":%d")` cascade: the total → `emulator.schedulers`, the online half → `online_schedulers`; `+SP`/`+SDcpu`/`+SDPcpu`/`+SDio` are validated and preserved verbatim (inert here) |
| every value-taking `+` switch | accepts its value **attached or separate** (`+S1` ≡ `+S 1`, `+sbtu`, `+A0`), the C's `get_arg` rule — the form the real `erlc` passes |
| `-extra …` / `-- …` | **ends the switch surface**: every remaining token is a **plain argument** (`RuntimeConfig::plain_args`) that `init:get_plain_arguments/0` answers as a list of strings — never an init argument, never a Start instruction; split per **entity** (`ERL_OTP30_FLAGS`/`ERL_AFLAGS`/argv/`ERL_FLAGS`/`ERL_ZFLAGS`) at that entity's first `-extra`, and `--` collects until the next switch-looking token |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A<n>` / `+P<n>` / `+Q<n>` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes`; max port count → `RuntimeConfig::max_ports` with `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+sbt<type>` / `+K<true\|false>` | scheduler bind type (`u`/`db`/`s`/`ps`/`ts`/`tnnps`/`nnps`/`nnts`/`ns`, an unknown type the C's rejection) and the kernel-poll switch, both preserved verbatim |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking driver/port round trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* **The `-s`/`-run` vector is ERTS's one collected list** (never one token at a time), and the OTP `erlc` C front end drives this runtime unchanged — `ERLC_EMULATOR=<beam_rt> erlc …` exits 0 with a byte-identical artifact (`tests/erlc_emulator.rs`, `tests/cli_compact_flags.rs`, `tests/cli_plain_args.rs`); the exact argv, the `instruction_args` rule and the init-argument recording rule (every `-` flag is an init argument, an unmodeled one **data** not a usage error) are [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md) § *The supported switches (the exact A.6 surface)*.
### The `-eval` route (`src/eval/`)
`-eval` walks the Erlang **expression** subset `erl_eval`-style — arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3).
`receive … after T` scans the running process's **real mailbox**, pumps the scheduler non-blockingly (`RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass and spends the remaining window on the timer heap through `Runtime::wait_for_timer`; a port round's messages are **delivered into that mailbox** before any clause is tried.
A closure `erlang:spawn/1` starts is **compiled** (`src/eval/compile.rs`) from its recorded source into a synthetic `beam_rt_eval_fun_<index>` module (`compile:file/2` in process, then `code:load_binary/3`), so the child is an ordinary `ProcessEntry::Export` that really parks on a bare `receive` or a `timer:sleep/1`; the result — a decline included — is cached per closure index on `Runtime::eval_compiled`.
**Fun application has an explicit nesting budget, because the walker's continuation is the native Rust stack**: `src/eval/nesting.rs` routes to the tree walker while this thread's remaining native stack is at least `WALK_STACK_RESERVE` **and** the nesting is within `WALK_APPLY_LIMIT = 512`, to the **compile route** past either bound, and to the typed `unsupported: eval fun application: …` gap once `COMPILED_APPLICATION_LIMIT = 16` compiled applications are nested; a context inside a scheduler slice cannot compile and refuses instead of pumping — `tests/eval_deep_recursion.rs`.
Residuals: a `spawn` from inside a running engine keeps the tree-walking entry, a **declined** compile keeps that closure's gaps, and `receive … after infinity` is a typed gap — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Known Issues*.
**A raise caught in `-eval` now carries a derived raise-site item** (`src/eval/trace.rs`): one `{CalleeModule, CalleeFunction, A, Location}` per call that returned a raise, `A` = the raise's `Raise::saved_args` payload when `error/2,3` supplied one (else the evaluated argument list) and `Location` = `[]` or `[{error_info,Map}]`; a supplied `erlang:raise/3` trace is echoed **verbatim** and never gains a derived item. Measured: `catch erlang:error(boom,[1,2])` ⇒ `{'EXIT',{boom,[{erlang,error,[1,2],[]}]}}` (the oracle's A slot is `[1,2]` too, its identity `erl_eval:do_apply/7`). The residual is **identity, not payload**: the `erl_eval`/`init` frame chain, its arities and its `erl_eval.erl` source positions are OTP-source facts a walker with no `erl_eval` port would have to fabricate, and for `error/1,2,3` the item names the raise site where C's `non_bif_stacktrace` names the caller. The `[{error_info,#{module => FormatModule}}]` extension needs `beam_engine`'s `format_module` (a `pub(crate)` closed table — reported seam).
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure: a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation (a missing operand of a *known* switch, a malformed `run` spec or numeric value, a stray positional) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
`unsupported` is emitted for a `-eval` expression outside the grammar, a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`), and is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`); the convention is a raise whose **reason atom starts with `unsupported`**, of which `src/error.rs::unsupported_reason` is the **single** interpreter, classified through `ExitReason::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call**, or the engine cannot land it in a catch frame: `src/context/calls.rs::name_raise_reason_atom` appends it (append-only, at `PendingInterner`'s predicted index) on the **one** funnel every failed call passes — **every** atom-reasoned error is named, a capability gap included, so `try … catch` in compiled code observes a typed gap instead of dying (`tests/gap_raise_catch.rs`, [`src/context/calls/CONTEXT.md`](src/context/calls/CONTEXT.md)).
A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` renders it through `format_term_w`, so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1).
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **90** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and `error:badarg` for any other key; the **25** keys the oracle accepts but this runtime's facilities lack raise the honest `unsupported` gap, and the two sets partition the oracle's 115 accepted names (`tests/system_info_oracle.rs`; the pins are `SUPPORTED_KEYS.len() == 90` / `UNSUPPORTED_KEYS.len() == 25` in `src/info.rs`).
`snifs` is **supported**: it answers this tree's own 556-row `beam_bifs::snifs()` roster in `bif.tab`-reversed order (the C's `build_snifs_term`), and its 465 distinct names extend the boot atom vocabulary through `info::info_atoms()`, so no name is invented at materialization — its oracle comparison is **shape-only** because an OTP-29 oracle answers 553 rows (the three OTP-30-only `*_to_binary/1` rows are the whole difference).
The per-key catalog is [`src/info/CONTEXT.md`](src/info/CONTEXT.md).
## Constraints
* **Errors are return-based** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`, with no crate-local error enum, no `panic!`/`unwrap()` on runtime data and no silent swallowing; CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`, never stderr writes.
* **`#![deny(unsafe_code)]` with eleven per-module exemptions**, each carrying a `// SAFETY:` rationale at every site — `src/malloc.rs`, `src/nif.rs`, `src/context/{calls,gc,gc_walk}.rs` + `src/context/gc/{bin_vheap,valve_bounds}.rs`, `src/eval/reclaim.rs` + `src/eval/reclaim/resource.rs`, `src/eval/native_stack.rs` (the walker's stack-headroom probe over glibc's pthread attributes), `src/runtime/reclaim/{compact,holder}.rs` (the store move).
* **Call down, never duplicate** — the `~p` printer is **not** re-implemented; `format.rs` drives the registered `io:format/2` BIF.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner** — reachable from `Machine::refc_binaries()` or `Runtime::eval_off_heap`; the transport copy resolves one of them into its **source** table so the destination **shares** the handle, and a source table that cannot name the owner makes `beam_message`'s copier **flatten** the window into a fresh on-heap bitstring as the **last resort** only.
* **A live heap serves its own builds; the arena is a refusal-only fallback** — `alloc_words_rooted` serves a nested run from the running process's scanned young heap, the arena answers only a table-less context or a refused growth, and inside a relocation-exempt window the copy-out `stabilize`s instead of growing; **a park that skips root publication holds the relocation exemption**, the three runner park arms taking the one `park_window` entry point that writes the flag in both directions — [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md).
### The one process-lifetime `Rc<AtomTable>` lease
**Never hold a `CodeServer::atoms_handle()` across an intern** — [`src/codeserver.rs`](src/codeserver.rs) states the rule on the method: `atoms_mut()` is `Rc::make_mut` and `intern_pending()` falls back to it, so an `Rc<AtomTable>` clone held **across** an intern deep-clones the whole shared table and drops the copy; only **one** holder lives long enough to matter — a loaded NIF library's stored host (`src/nif.rs`'s `NifEntry::host`, alive for the process's life). A `{spawn_driver, Name}` port's host is **not** a holder: its view is a **lease** on the `DriverAtoms` record, opened by `PortRegistry::open_driver_atom_view` only for the window in which driver code runs and closed (re-entrant, depth-counted) by `close_driver_atom_view`; a built-in-driver or `{spawn, …}` port creates **no** host, so the code server is sole owner there.
The two production sites taking a handle — `src/native/prim_file.rs::build_descriptor`, `src/native/net/nodes.rs::nodes_2` — **intern first and take the handle last**; the port delivery builders intern **through `src/port.rs`'s `intern_reuse`** (look the name up on the shared table first, reach `atoms_mut()` only for a genuine miss); and the borrow-workaround clones (`src/eval/mod.rs`, `src/native/memory/mod.rs`, `src/native/erts_internal.rs`) each wrap a `make_map` that takes `&AtomTable` and cannot intern. `RuntimeContext` itself holds **no** atom handle — [`src/context/CONTEXT.md`](src/context/CONTEXT.md) § *The atom namespace and the one lifetime `Rc<AtomTable>` lease*.

## Known Issues / Intentional M1 gaps
**Every gap is a typed capability gap or a measured own-state difference — never a wrong result.** The full catalogue is the ledger index: **`G`** = [`M1_GAPS.md`](M1_GAPS.md), **`GC`** = [`M1_GAPS_GC.md`](M1_GAPS_GC.md), **`A3`** = [`M1_GAPS_A3_NIF.md`](M1_GAPS_A3_NIF.md), **`A4`** = [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md); each line names the section that owns the detail.
* **Own state and introspection** — `processes/0`, `ports/0`, `port_count`, the boot-set size and `process_info` contents differ by construction (`process_info/1,2` answers ~28 items, `port_info(P, monitors)` stays `[]`, `minor_gcs` is `minor_since_major`, `process_info(P, binary)` is the reservoir ∪ PCB union while `erlang:memory(binary)` is separate, and a non-byte-aligned `-eval` result cannot be printed) — G *Own-state answers*, *`process_info/1,2`*, *Printing*.
* **Process control and ETS** — a named port monitor, a remote `{Name,Node}` monitor, `spawn_opt` options and `exit/2,3` on an internal port/foreign ref are gaps; ETS owner tracking and owner-death reclamation are live on both install routes, the table-alias boundary being a witness `Cell<bool>` rather than an address check — G *Process-control families*, *ETS ownership*.
* **Scheduler and tier** — single-threaded; a BIF-and-call-only loop ends no slice on the native tier (fairness) and a BIF-nested fun application is unbounded in depth (the driver thread's stack is the bound). `JitMode::Auto` is **phase-scoped**: the interpreter during the boot phase, the native baseline tier in steady state, a boot-entered process upgraded one-way at its first post-boot slice boundary, a pinned `BEAM_RT_TIER` phase-independent; the pre-emption residual (a natively linked tail loop with no allocation never pre-empts) is steady-state only and an upgraded process's code ranges are absent from `+JPperf` (diagnostic-only) — G *Scheduler / runner*, *Execution tier*, [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md).
* **Funs and `-eval`** — a compiled module's local fun encodes faithfully while an `erl_eval` lambda stays `unsupported: local_fun` (A3, G *Funs*); `-eval` fun application compiles past 512 walked applications and otherwise answers the typed `unsupported` gap ([`src/eval/CONTEXT.md`](src/eval/CONTEXT.md)).
* **A.3 (NIF)** — every residual is a typed refusal or a deferred answer (plain callback-visible host state, a private-atom-space thread host, `nif_yield_point` a fairness no-op) — A3, [`src/nif/CONTEXT.md`](src/nif/CONTEXT.md); **A.4 (ports)** — message shapes and driver-port behaviour match the oracle, while a registered port name, a remote port term, an unreachable remote destination and a send to a non-alias reference (typed `badarg`; the C drops it) stay gaps — A4, [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **A.5 (distribution)** — no Erlang-level distribution subtree, every inbound family is a route-free receipt, and an inbound `DOP_SEND_SENDER*` does not pass the wire sender pid as the mailbox `from` — G *Distribution and the node*.
* **GC / heap model** — four collection points (three heap-admission doors); the unscanned-root valve declines only where relocation is genuinely unsafe; the engine's refc-binary reservoir is pruned at every pre-emption and `Runtime::eval_off_heap` at two points, every gate a decline so the residual is a **leak, never a dangle**; `+hmax` is a cumulative ceiling over user processes only and `max_heap_size` is **ENFORCED** — GC *GC / heap model*, *The BIF-result copy-out*, *Heap switches*.
* **Printing, `eunit` and boot** — `io` output has **three** routes (the direct sink for the runtime's own stream, OTP's own `io.erl` in-machine for any other **live** leader so nothing can double-send, a synchronous file device) over a **14**-key floor, so `eunit:test/1` runs OTP's own framework: `jsone` **90/90** and `bbmustache` **79/79**, stdout and stderr byte-identical to the OTP 29.1.2 oracle; an `io` output call on a live non-stream device inside a **scheduler slice** is the typed `unsupported` gap and a nested run that may not pump folds a file-device round trip to `blocked` — G *Printing*, [`src/context/io_route.rs`](src/context/io_route.rs).
* **Boot (A.7/A.9), timers, CLI** — a booted runtime leaves a live `logger_server` registered as `logger`, the script's tail blockers are served in-node, and a process entry naming a host-served MFA is dispatched rather than entered; self-hosted compilation runs in ONE invocation via the committed OTP-30 bootstrap compiler with a documented >60 KB residual (G *A.7/A.9 boot*, *A.9 E0*, [`EPP_SCHEDULED_ROUTE_FINDINGS.md`](EPP_SCHEDULED_ROUTE_FINDINGS.md)). `send_after/3`/`cancel_timer/1` and the `RuntimeHooksBridge` timer/link/module keys are floor capabilities while `system_info/2` and the other `RuntimeHooks` keys are gaps (G *Timers*); `-smp disable`, `-setcookie` and the `-eval`/`-s`/`-run` subsets diverge ([`src/cli/CONTEXT.md`](src/cli/CONTEXT.md)), flag-driven `system_info` literals report their defaults (G *Placeholders*), and two load-sensitive failure shapes exist, both real exit codes, never a signal (G *Scheduler / runner*, *A.7/A.9 boot*).
* **A blocking NIF `-on_load` hook (e.g. `crypto:on_load/0`) now completes on the scheduled/`-eval` route, not just `run`.** `crypto:on_load/0` blocks on `application:load(crypto)` → `gen_server:call`, so on a non-pumpable scheduler slice it defers; the deferral is drained on a pumpable context (`context/pump.rs`) and `load_and_run` (`context/calls.rs`) suspends the machine until the hook has loaded the NIF, so `crypto:strong_rand_bytes/1` and `erlang:function_exported/3` answer like the oracle (khepri `projections` 134/0) instead of `{nif_not_loaded,…}`/`false` — A.3. Residual: a `crypto` frame in `build_stacktrace` is an uncatchable `unsupported_opcode` — A3.
* **`erlang:apply/2`'s floor arm is oracle-equivalent in value and in the C's `expand_error_value` shapes** (`{badfun, Fun}`, `{badarity, {Fun, Args}}` over `Raise::live_reason`); the one residual is `beam_engine`'s, where `badarg`/`system_limit` keep the caller frame where the oracle arms the BIF item (`../beam_engine/src/interpreter/dispatch.rs:975`) — `tests/apply_two_args.rs`.
* **A no-op map update keeps the argument's identity**: `maps:put/3` of a value-identical key, `maps:update/3`, `maps:remove/2` of an absent key and `maps:merge/2` with `#{}` hand the argument back, as do the compiled `put_map_assoc`/`put_map_exact` instructions (the C's `found_key` arm, `../../erts/emulator/beam/erl_map.c:2208-2213`), so `erts_debug:same/2` answers the oracle's `true`.
* **A `run`-route process is bounded by `RUN_DEADLINE`** (60 s of wall clock from `run_scheduled`'s start, no flag or env override), exiting 1 with `beam_rt: error run: … did not terminate within 60000 ms`; a `run` argument token above `MAX_SMALL` is materialized by `make_small` with **no** range check (`src/runtime.rs::materialize`), so a debug build aborts on the assert and a release build truncates — G *CLI `run` argument tokens*.
* **A `sendfile` extent past `MAX_SENDFILE_BYTES` = 16 MiB** is a typed `unsupported` gap, served above the driver as a userspace copy — A4, `src/native/prim_file/sendfile.rs`.

## The scheduled path and the per-BIF-call cost (read before optimizing the glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, at `RUN_STEP_SLICES` passes per round and `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS`, so per-pass costs amortize while **per-slice** costs dominate a long run; the per-pass/per-slice/per-round inventory (each with its pinning test) is [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *The scheduled path's fixed costs*, with the per-workload cost in [`src/runner/MEASURED.md`](src/runner/MEASURED.md).
A registered BIF call is priced in retired instructions, of which this crate owns the routing (`call_bif`'s NIF → floor → memo draw), the `BifContext` build and arm selection and the tail — the rest is `beam_engine`'s dispatch, `src/runner/budget.rs`'s forwarding triple, or the BIF body; **the remaining cost is mostly NOT this node's**, and the ranked levers with their owners are [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *The per-BIF-call cost, on one page*.
The dispatch prologue is priced through **one** `beam_bifs::hook_flags::flags()` probe per memo miss: `DispatchHooks::from_flags` permutes the 14 hook bits onto the roster's own bits (a `const`-checked permutation, plus `src/context/dispatch/roster_tests.rs` diffing it key-by-key against the twelve now-test-only `uses_*` predicates), so a miss no longer pays twelve table probes.
The memo itself is **recycled across the contexts of one runtime** (`Runtime::memo_pool`, `MEMO_POOL_DEPTH = 4`, `src/context/memo_pool.rs`), because a context is built per scheduler slice and a process that parks on `receive` re-enters with a fresh one — recycling is what makes a park-heavy loop pay the prologue once, not per resume; every input is immutable for the life of the runtime, and a reused slot is a hit only for a field-for-field equal key.
The BIF-result copy-out short-circuits its reference walk for a **reference-free root** (`root_is_reference_free`, a positive whitelist in `src/context/calls.rs`) and its `Walklist` no longer memsets its 64 inline slots, so a `term_to_binary/1`-shaped result is re-homed with no walk at all.
Measured on `copy_bound` (paired, `cpu_core/instructions/u`, `taskset -c 3`, median of 5 alternating rounds, instructions/op, before → after): `send_recv` 57 746 → 46 391 (−19.7 %), `send_recv_plain` 27 948 → 22 131 (−20.8 %), `etf_roundtrip` 18 603 → 18 543 (−0.3 %), `ets_copy` 16 008 → 16 072 (+0.4 %); the harness reads −24.6 % / −26.5 % ns/op on the two messaging rows and −3.9 % / −0.1 % on the copy rows (loads 6–14).
A handle built in `call_registered` must still be gated by a `uses_*` predicate, and the `DispatchMemo` **hit** path — not the prologue — is what to price.
Price a further change with `examples/perf_call.rs` (per-call) and the paired N-vs-0 protocol in [`TEST_STRATEGY.md`](TEST_STRATEGY.md) — never a single-pass wall time.
## The Erlang stack on the runtime side (this crate's write surface)
- **No Y slot is ever built here**: the engine materializes them (`push_frame_window` `resize`s `Machine::stack` to `y_base + y_count`, and `Eterm::default()` **is** `NIL`).
- The only production writes into `Machine::stack` from this crate are the GC hand-off: `publish_roots_full` pushes `roots.stack` + the live FR prefix into the **process** root set (`src/context/gc.rs`) and `scatter_roots_full` copies the relocated words back; everything else is a read (`gather_off_heap_roots`/`for_each_parked_machine_root_mut`/`for_each_engine_census` in `src/runner/entry.rs`, `publish_nested_roots` in `src/context/pump.rs`).
- A fresh slice's stack is **empty, not pre-filled** (`Machine::new()` is `Vec::with_capacity(STACK_RESERVE_WORDS)`, `Machine::reset` `clear`s it), which is what the nested-run pool's release contract relies on (`src/context/machine_pool.rs`); no production path reads `Frame::continuation`, and execution-position items go through `Machine::{current_function,current_location,current_stacktrace,catch_frame_depth}` — [`src/context/CONTEXT.md`](src/context/CONTEXT.md) § *The Erlang stack on the runtime side*.
## Startup footprint (a minimal `-noshell -eval 'halt().'` boot) — where the bytes are
The bare boot peaks at **48.53 MiB** `VmHWM` (5 interleaved randomized rounds), **0.817×** a contemporaneous 59.45 MiB oracle boot and within 0.05 MiB of the 48.48 MiB `BEAM_RT_TIER=interpreter` ceiling — the phase rule captures 99.3 % of the interpreter-boot advantage while steady state keeps the native tier — with boot wall/CPU p50 122.8 ms / 116.1 ms against the oracle's 133.7 / 128.1 (`new`/`oracle` paired medians 0.910 wall, 0.903 CPU).
**Capacity is not RSS**: the peak is allocator-visible (massif: 35.3 MiB heap + 1.6 MiB overhead), ≈24 MiB of it `beam_loader`'s lowering and ≈3.1 MiB the atom store's copy-on-write shard generations, while both 128 MiB boot reservations sit at 12–48 kB resident; **the 99 `.beam` files a bare boot opens (5.80 MiB) retain ≈20 MiB of IR**, 70 executing at least once and 29 never (≈5.8 MiB of dead IR).
The per-tier instrument table, the massif site decomposition, the per-workload peak-RSS rows, the `90.1`/`128.9` MiB compute-run correction and every caveat are **[`STARTUP_COST.md`](STARTUP_COST.md)** § *Where the bytes are — the minimal-run footprint*, § *Instructions are not time* and § *The 99 boot-loaded modules and what they retain*, with the loader's side in [`../beam_loader/CONTEXT.md`](../beam_loader/CONTEXT.md); `tests/rss_bound.rs` bounds the boot peak at 120 MiB.

**No test pins a host-dependent version literal**: the tree's frozen values (`system_info(version)` `17.1`) are goldens asserted unconditionally and the installation's own `.app` versions (`application:loaded_applications/0`/`which_applications/0`/`get_key/2` report the **loaded release's**, so this checkout's `bootstrap/bin/start.boot` gives `stdlib` `8.1` where an OTP-29 oracle answers `8.1.1`) are compared with the live oracle, names/descriptions/orders included; the two release literals are pinned only in `tests/a9_native_floor.rs` (`KERNEL_VSN`/`STDLIB_VSN`) and `tests/system_info_retained.rs` tolerates exactly the oracle's own erts patch string — so a host whose oracle is a different patch release is green rather than red.
**The differential GATE is authoritative and is re-run, never quoted from memory** (`erts_rust/tools/differential/gate.sh`; the only recorded capability gap is `wire/new_fun_ext_encode`, A.5), and **no test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle**.
