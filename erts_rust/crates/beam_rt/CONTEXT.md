# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns:
`main.rs` and the **CLI flag surface** (**A.6**);
the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the OTP boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded scheduler drives (`src/boot/drive.rs`), which run the real `bootstrap/bin/start.boot` to its final `{progress,started}` (**A.7**);
**`system_info/1`** + `erlang:process_info/2` (**A.8**);
the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable);
the **A.4 runtime side of ports** (`open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s);
the **runtime-local timer deadlines** behind `erlang:send_after/3` and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
and the **distributed node** (A.5 phases 1–2, `src/dist.rs`): the bound listener, best-effort `epmd` registration and the server-side `'N'` handshake, which **completes** against a real OTP peer.

The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`; observability/perf detail → [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md); M1-gap/handoff detail → [`M1_GAPS.md`](M1_GAPS.md).

### `dist.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the runtime's *listening* half: `start(configured, cookie)` **binds** a wildcard listener (`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error) and the first `pump()` **publishes** the node to `epmd` (`ALIVE2_REQ`).
Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/`is_short_name()`, `port()`, `creation()`, `is_registered()`/`is_alive()`/`registration_error()` (recorded, never raised), `connections()`, `is_idle()`, `last_link_error()`.
`NodeName::parse` splits a `-name`/`-sname` value into `full`, `advertised` (the full `node@host` name in **both** cases — a peer resolves it with `list_to_existing_atom/1` and aborts on a bare short name) and `epmd` (the short name for `-sname`, verbatim for `-name`); a bare value's host is `local_hostname()`.
`resolve_cookie(init_args)` = `-setcookie`, else `$HOME/.erlang.cookie`, else `nocookie`.
`DistConnection` wraps one accepted socket in a **server-side** `beam_dist::ConnectionDriver` (`'N'` → `'s'`/`'S'` → `'r'` → `'a'`); `pump()` registers once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections non-blocking, then steps every link under a per-link `DIST_READ_SLICE` (25 ms) read timeout, so one pump can never stall the scheduler (a link's protocol/write failure **retires** it and records why).
`dispatch_inbound(atoms, sink)` drains every **established** link's queued inbound `DOP_*` through a `beam_dist::InboundSink`.
`LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes `Delivery::Send` to a **local** pid (`NoSuchProcess` for another node/creation or an unknown pid) and `Delivery::RegSend` via `ProcessTable::whereis`, both through `deliver_simple` (so a blocked receiver is woken), while the link/exit/monitor/alias/`Other` families stay the typed `Unsupported`.
The scheduler pass drives it from `Runtime::dispatch_dist_inbound`, **gated by `Runtime::allow_inbound_delivery`** (default OFF, so the differential corpus is byte-identical).

### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`.
`NifRegistry`: `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**), `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`; a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner` and holding `Some(&'a mut dyn NifHostServices)` (the reference/name/process/port provider); `alloc_env`/`free_env` are real and `make_copy` is the **identity**.
All six state-needing `NifHostServices` hooks are live on a call — `make_ref`, `whereis_pid` and the two process-liveness answers plus the two **port** relations `is_port_alive`/`port_command` (`RuntimeNifServices` over the runtime's `&RefCell<PortRegistry>`), proven end to end through a compiled `.c` NIF (`tests/nif.rs::enif_port_hooks_answer_the_real_port_registry`); only the load/unload host, which cannot borrow the runtime, leaves them the trait default.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry. The child modules, the dispatch table (the source of truth) and every implemented/not-implemented BIF live in **`src/native/CONTEXT.md`**; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry — `os:env/0` is served by `beam_bifs::os_bif::os_env_0` (the floor owns only `os:cmd/1`), and `sys`/`os`/`prim_file` keys the floor lacks fall through the same way.
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form (so `ProcessBridge`'s keys/items only satisfy the seam, unit-tested directly).
**`erlang:garbage_collect/0,1` are served from the floor** (`src/native/erts_internal.rs`, contract A.7). **No BIF may collect** — the root set a collection relocates is the *executing machine's* `x[0..live)` plus its Erlang stack, which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`. The request is then served at the two sites that *do* own that root set (the engine's heap-admission point, `src/context/gc.rs::ensure_heap`, and the runner's park arms, `src/runner/run.rs` → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first (`src/runtime/scheduler.rs::prune_gc_requests`), so `Runtime::gc_stats().collections` moves only when a collection really ran; a request the valves refuse (a pinned/relocation-exempt process, the escape-store valve) is dropped with the counters untouched. `/1`'s contract is the oracle's exactly (a live local pid ⇒ `true` and a request for *that* pid, a well-formed but absent internal pid ⇒ `false` with nothing recorded, anything else — an external/wire pid included — `badarg`), while `/2`'s `{async, ReqId}` system-task form stays a typed gap. Oracle cross-checks and the observable-evidence test are in `tests/garbage_collect.rs`; the full contract is in [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**`code:` is the native floor, not a live `code_server`.** `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7) the oracle serves from `init.beam`/`code.beam`/`application.beam`; `beam_rt` ships **no** live `code_server.beam` (its *state* is `CodeServer`), the `boot/*` differential cases touching `code:*` are **shape-only**, and a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**
**Two server processes are native state, not scheduled code.** The runtime's root process (registered as `init`; it is what every action runs as) and the native **`file_server_2` service** (`src/native/file_server.rs`, contract A.9) are spawned `Runnable` with no engine and are **never enqueued**, so the runner never executes them; their mailboxes are drained by the scheduler pass (`Runtime::service_file_requests`) and the replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery all work. Detail in [`src/native/CONTEXT.md`](src/native/CONTEXT.md) and [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`.
Membership in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` means exactly **an OTP `erlang` BIF the oracle exports and serves but this runtime does not serve**; a name the oracle itself rejects as `undef` must never be listed, so it falls through to the bare `undef`/exit 1 the oracle raises.
The **effective** gap set is `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` **intersected with what the live registry does not own** (the `erts_internal:`-hosted calls).
Drift guard: `error::tests::{known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry,the_effective_gap_set_never_shadows_the_registry,a_name_the_otp_release_does_not_export_is_not_a_curated_gap,a_reclassified_name_exits_1_and_a_newly_curated_one_exits_3}`.

## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path (before / after `-pz` dirs) |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — `src/dist.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). Outside the grammar is a **capability gap** (exit 3).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2). **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**

## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`).
A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason).
So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap.
Strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **67** atom keys plus two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the 15 oracle-accepted keys naming facilities this runtime lacks raise the honest `unsupported` gap. **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node (`RuntimeConfig::default()` is `nonode@nohost`).
`start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants: every erts-17.1 build answers the same pair, so a drop-in runtime must define exactly those values, and `end_time` exceeds the 60-bit small range so it materializes as a bignum (both re-probed in `tests/system_info_oracle.rs`).
`context_reductions` is answered as `4000`, the canonical ERTS reduction quantum `beam_common::CONTEXT_REDS` — `src/info/schedulers.rs` re-uses that constant and declares **no** local copy (the residual `beam_io::port_task::CONTEXT_REDS` and `beam_process::scheduler::DEFAULT_REDUCTIONS_PER_SLICE` transcriptions belong to their own crates).

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2079 lines of production; its ~2190-line unit suite lives in `src/port/tests.rs`).

## Design Decisions
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every loaded module is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use a separate `info_heap`, `reset()` per call. For a *scheduled* slice `ensure_heap` is the **collection point** (armed by `BudgetContext`); for every other context it is a no-op on the unbounded arena. What *does* exhaust is the bounded BIF/eval heaps and, for a collected process, its young heap.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are preserved verbatim in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry rather than re-implementing arithmetic/printing; `main.rs` is a thin shim over `cli::run(argv)`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* (`#![deny(unsafe_code)]`, may not alias), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid (`process_result`), copies it onto the pointer-stable `eval_heap` (never reset) via `stabilize_term`, and returns `Exit(normal)`. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The host seams: nine bridges + three hooks** (enumerated in [`src/context/CONTEXT.md`](src/context/CONTEXT.md)). Every bridge that needs no runtime borrow is a cheap `Rc`/`RefCell` handle; the ones that must borrow are made mutually exclusive by their `uses_*` predicates. `NodeIdentity` (a `Copy` atom) rides alongside every arm; `FunIdentityBridge` and `RuntimeMemory` are owned snapshots installed **only** on their consumer BIFs' arms.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw`).
* **Timers are a runtime-local deadline min-heap, not `beam_process::TimerService`.** That service is driven by **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (it owns `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas), so `src/timers.rs` is a min-heap the **scheduler loop** drains: monotonic deadlines, earlier first, `O(1)` cancellation via a lazy tombstone, sleep-to-earliest only when idle.
* **The persistent-term store keeps raw `Eterm` words but compares structurally.** The store (`src/context/persistent_term.rs`) pins the raw words of this node-global table and compares a key — and the `put_new/2` value — with `beam_term::compare::eq` (the C's exact `EQ`, `erl_bif_persistent.c:1015/726`), so a boxed key matches a structurally equal but distinct term. Raw storage is safe because every write to a runtime-level store goes through `Runtime::try_stabilize_escaped` (a copy onto the never-moved arena), which reports a **genuine** copy failure as the honest `BeamError::SystemLimit` and trips the global GC valve (`disable_gc`) **only** for the off-heap-payload capability gap, so no process heap is ever moved again.
* **Oversized messages go through the heap-fragment model, driven by `beam_message`.** `RuntimeContext::send_fragmented_message` obtains the receiver's heap + mailbox from `Process::heap_and_mailbox_mut()` and calls `beam_message::send_fragmented(from, message, heap, mailbox, &mut ctx, 0)`, then records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments` so a just-bound payload stays valid. The fallback is reached only when the receiver's own heap genuinely refuses the payload — a bounded `HeapPolicy` makes `Process::deliver`'s on-demand growth fail, whereas an unbounded receiver would absorb the payload into its grown nursery instead. **`beam_message::Fragments::move_into` is never called** — retention is the honest M1 behaviour (accessor detail in [`M1_GAPS.md`](M1_GAPS.md)). **The retention only protects a *removed* message.** A fragment message still *queued* when a collection runs on its receiver has its `Fragments` dropped: `beam_process`'s `Process::run_rooted_collection` (`../../beam_process/src/process.rs:925-976`, the shared body of `collect`/`ensure_capacity`) drains the whole mailbox and rebuilds each `Message` via `Message::new(payload, from).with_token(..).with_off_heap(..)`, which carries neither `fragments` nor `binaries`/`nodes` — so the fragment's backing heap is freed while the queued payload still points into it. `beam_rt` reaches it through `deliver_message`/`deliver_in_table` (`Process::deliver` → `ensure_capacity` on a refused copy) and through the scheduled slice's `ensure_heap` collection, whenever a fragment message is queued; the fix belongs to `beam_process` (preserve the three lists, or add a payload setter). `beam_rt`'s own `MailboxState` logic is otherwise correct (only this node's cursor/fragment semantics are unaffected by the bug).
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`. `allocated_areas`' 19 items are derived from live state wherever a counterpart exists (`export_table`/`fun_table` from the loaded modules' `ExpT`/`FunT` counts, `module_refs`/`loaded_code`/`atom_table`/`register_table`/`process_table`/`port_table`/`ets_misc` from the runtime's tables, `dist_table`/`node_table` from `Runtime::dist_node()`); only the genuinely counterpart-less items (`sys_misc`/`static`/`export_list`/`fun_list`/`bif_timer`/`external_alloc`) stay a documented `0` (detail in `src/info/CONTEXT.md`).
* **The exit observer only *records*; a scheduler pass drains.** A `ProcessExitObserver` can be invoked while a `RefCell` the runtime owns is already borrowed (a BIF holds the shared ETS/port registry for its whole call), so `EtsExitObserver` (`runtime/ets_owner.rs`) touches nothing but its own `OwnerIndex` cell: it pushes the dead pid and the drained `PortWatch` pairs and returns. `Runtime::{drain_ets_owner_exits, drain_port_monitor_exits}` discharge the obligations at a scheduler-pass boundary with `try_borrow_mut`, **deferring** (never dropping, never panicking) on a live borrow.
* **The cross-module call seam is deepened, never broadened.** `resolve_external_call` must stay behaviour-preserving everywhere it does not suspend, so the `Ok(None)` predicate grew (NIF modules, self-observing modules, an on-demand load, an unknown export) rather than the `Some` set. Suspending changes control flow, so a wrong `Some` is a correctness bug where a wrong `None` costs only a slower path.
* **GC collects only at `ensure_heap`, behind a per-call latch.** The root set is the *executing machine's* `x[0..live)` + Erlang stack, but a `RuntimeContext` is shared by nested runs (an external module call builds a new `Machine` on the same context), so a collection driven from a nested admission point would write the nested roots into the process's root set and leave the outer machine's terms dangling. Only the slice's own `BudgetContext` arms the latch and `context/gc.rs` takes it (`std::mem::take`); every nested path is a plain `RuntimeContext` whose latch is never set. `Machine::fr` holds *terms* and is outside the root set, so a module containing a float-family instruction is never collected over and an unresolvable call site (a fun entry, the `-eval` evaluator) is skipped — conservative, never wrong.
* **A process whose live terms the runtime cannot fully root is marked *relocation-exempt* while it runs them.** `RuntimeContext::with_relocation_exempt` (`src/context/mod.rs`) saves the process's mark, sets it, runs a closure and restores the previous mark on every path (nested-safe save/restore). While exempt, `Process::deliver` returns the copier's raw `Alloc(AllocKind::Message)` refusal instead of collecting, which `RuntimeContext::{deliver_message, deliver_in_table}` route to the heap-fragment fallback — so the message still arrives with no heap word moved under a term the root set cannot publish. The wrapped scopes are exactly those runtime locals: the `-eval` driver (`crate::eval::eval`, whose `Runtime::pump_scheduler` receive pump runs inside the scope), `run_export_blocking`/`run_label_blocking` (the fresh `Machine`'s `x`/stack) and `apply_fun` (the `-eval`-closure environment). The scheduled slice is deliberately **not** wrapped — the runner drives it with the `*_outcome_with_tier` entries, publishes a parked machine's roots (`publish_parked_roots`), and its `BudgetContext` arms the admission point that is the legitimate collection site.
* **A failed collection halts that process's collection, never the program.** The pre-collector runtime was an unbounded arena that could not fail at a heap-admission point, so `halt_process_gc` keeps the (unmoved) heap and allocation keeps falling back to the arena; `disable_gc` (the escape-store valve) freezes **every** process heap when a runtime-level store cannot be copied onto the arena — keeping the store exactly as correct as before the collector existed.
* **The `receive` scan position is host state, per process, and survives a suspend/resume.** `beam_engine` keeps no mailbox state; the nine `beam_engine::Mailbox` methods (`src/context/mod.rs`) resolve the message queue from the `Process` and the scan state from `Runtime::mailboxes: HashMap<ProcessId, MailboxState>` (`src/mailbox.rs`; `RuntimeContext::mailbox_parts`), so a `receive` parked as `RunOutcome::Wait` resumes at the `wait` target (its `loop_rec`) through `Machine::resume_outcome_with_tier` (`src/runner/run.rs`) with the cursor **intact** — the scan does not restart from the first message, so a matching message is never re-examined or skipped across a wake; `remove_message`/`timeout` reset the cursor to the first message exactly as the C `erts_msgq_unlink_msg_set_save_first`/`erts_msgq_set_save_first` (`../../erts/emulator/beam/erl_proc_sig_queue.h:2329-2381`). The key is the whole `ProcessId` including its bumped slot serial (`beam_process/ptab.rs`), so a reused slot never inherits a dead process's cursor. The only mailbox edit that can move a *parked* receiver's scan is a delivery (append at the tail, never invalidating the cursor); removal paths (`receive_remove`, the `-eval` `remove_mailbox_message`, `beam_process::demonitor_flush`) all act on the **running** process's own mailbox. **Latent caveat (reachability unproven):** `MailboxState.markers[].position` is a queue *index* captured at `reserve`, whereas the C keeps a recv marker as a queue *node*, so a removal at a lower index could leave the recorded index off by one — worth a differential case if the compiler's marker prologue is ever exercised.

## Known Issues / Intentional M1 gaps
Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
**The per-item detail behind each line is in [`M1_GAPS.md`](M1_GAPS.md); the contract-specific gaps are also in the owning child `CONTEXT.md`.**
* **Registered-BIF dispatch** commits pending names through `code_server.atoms_mut()` (`Rc::make_mut`) only when the interner is non-empty, so the shared `AtomTable` is never deep-cloned per call.
* **No interactive shell; the node is otherwise passive** — `-noshell` only, and the inbound link/exit/monitor/alias families stay typed `Unsupported`.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order (compared as a set), and `badarg` for a module not loaded here.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures — `whereis(init)` **does** agree.
* **Process-control gaps** (`src/native/`) — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual gap is `ets:setopts/2`'s gift-data aliasing.
* **A dead *watcher*'s incoming port monitor is swept** (A.4); `port_info(Port, monitors)` stays `[]`, matching the oracle.
* **`process_info/1,2`** answers ~28 items from real state; the four execution-position items only for a scheduled module-export process, the `max_heap_size` map's key order/flags diverge, and `process_flag(message_queue_data, off_heap)` is accepted-and-ignored (a cross-crate handoff).
* **A non-byte-aligned `-eval` result cannot be printed** — the registered `io:format` `~w`/`~p` printer rejects it (and a container past ~80 columns) with `badarg`.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget.** Gaps: a loop without an allocation has no admission point, a non-statically-readable `receive … after T` delay still parks, and a capability gap is uncatchable on the runner path.
* **Execution tier defaults to `JitMode::Auto`** (`src/runner/tier.rs`) with the chosen tier remembered per process across slices, `BEAM_RT_TIER` overriding it; the residual engine gap is the JIT driver's lack of an in-machine module-context switch.
* **CLI divergences and subset gaps** (`-smp disable` accepted, `-setcookie` unmodeled, `-eval`/`-s`/`-run` subsets) live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
* **NIF loading is live** (`load_nif/2` really `dlopen`s) and the host hooks are implemented; the hooks still at the trait default are `priv_data`, `consume_timeslice`, `send`, `whereis_port`, `monitor_process`/`demonitor_process`, `select`, `schedule_nif` and `dynamic_resource_call`.
* **`NEW_FUN_EXT`** — a compiled module's local fun encodes faithfully; an `erl_eval` lambda stays the honest `unsupported: local_fun`.
* **Ports match the oracle's observable shape** — one `{Port,{data,Data}}` per driver read at the width the child wrote, stderr inherited by default and merged under `stderr_to_stdout`, `connected` false only at `port_close/1`.
* **The send family** serves `erlang:send/2` and `erlang:'!'/2`; `erlang:send(Port, Data)` and the distributed `{Name, Node}` send stay typed gaps, never a fabricated value.
* **Driver ports (A.4) load and drive a real C driver end to end** (delivered `driver_output`/driver-emitted terms, a real `driver_select`, `driver_set_timer` for every attached port, the always-drain-then-notify `OUTPUT` task, `control` behind `port_control/3`, `ERL_DRV_USE`'s firing `stop_select`); the typed gaps are `driver_async`, an OS child (`os_pid`), a `control` reply the driver answered from **its own memory**, and a `NULL` reply pointer with `PORT_CONTROL_FLAG_BINARY` set (`<<>>` where the C answers `[]`) — detail in [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **`erlang:send_after/3`/`cancel_timer/1` are native-floor capabilities**; `/4`, `/2`, `start_timer/3,4`, `function_exported/3`, `link/1`/`unlink/1` and `os:set_signal/2` come from the `RuntimeHooksBridge`, while `erlang:system_info/2`, `read_timer/1,2`, `start_timer`'s absolute form and every other `RuntimeHooks` key are unimplemented.
* **The runtime drives `beam_gc`, but only through the engine's heap-admission point** — an `alloc_words`-only workload is never collected, a module with a float-family instruction is never collected over, and a failed collection halts that process's collection rather than failing the program.
* **The term-heap capacity is still the hard limit** for anything not collected: both `AllocKind::Heap` and `AllocKind::Message` exhaustion become `error:system_limit`, `DEFAULT_HEAP_WORDS` is `1 << 24`, and `+hmax N` is a **real** cap.
* **`erlang:memory/0,1` are adopted** with measured figures; **`erlang:statistics/1` is partly served** (`run_queue`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io`, `garbage_collection`, `runtime`) with the per-scheduler/msacc keys and `statistics/0` staying typed gaps.
* **The heap switches are modelled** (`+hms`/`+hmbs`/`+hmax*`), but some rejection details are not: a malformed value is exit 2 where the oracle exits 1.
* **On-demand heap growth is adopted only on the `beam_process` message-delivery path**; `beam_rt`'s own allocation paths do not grow, so heap exhaustion there still raises `error:system_limit`.
* **Placeholders where a truthful source exists** — `NodeIdentity`'s creation is a fixed `0`, `init:get_argument(bindir)` answers `error`, the flag-driven `system_info` literals report their defaults, and some oracle-accepted `system_info` keys are in neither key set (a `badarg` partition gap); all detailed in [`M1_GAPS.md`](M1_GAPS.md).

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam funnels into ONE pointer-stable `Runtime::arena` (`MinimalContext`, chunked but never moved), which is why the stores below are safe today; routing `alloc_words` onto a per-process **moving** heap would dangle every store that pins a raw engine-arena `Eterm` outside the GC root set.
**`Process::regs` is a snapshot, not a live mirror of the running machine.** The engine writes its own `Machine::x`/`fr`/`stack`; `publish_roots` (`context/gc.rs:162`) copies `x[..live]` + the whole stack into `process.regs` **only** at a heap-admission point (`gc::ensure_heap`) or a park (`publish_parked_roots`), and `scatter_roots` writes the relocated words back there. Between those points the process's registers are stale by up to one slice of instructions, so any collection that runs **mid-slice** relocates against an incomplete root set. The three collect triggers differ in exposure: the admission-point collection is exactly the publish/collect/scatter hand-off (safe, the machine's own slices are the roots); the **delivery-driven** collection (`Process::deliver` → `ensure_capacity`, `beam_process/src/process.rs:749`, plus `ptab.rs:171/196`) and the park arm's `Runtime::serve_gc_request` (`runtime/gc.rs:255`) fire **outside** an admission and are gated only by `relocation_exempt` — so a non-exempt process that is mid-instruction and triggers a delivery-driven collect (a self-send whose payload does not fit; the ungated exit cascade) has its live `x`/`stack` relocated out from under it. `Machine::fr`, `Machine::pending_exception: Option<(ExceptionClass, Eterm)>` and the `Raise::live_reason` reason term are NOT in `Registers::gather_roots` at all (the first two are mitigated by the float-free `module_may_be_collected` guard + the post-slice pin scan at `runner/run.rs:382-386`, the third by `try_stabilize_escaped` at the record site `runner/run.rs:491`).
* **At risk:** `Runtime::persistent_terms` (`context/persistent_term.rs`), `Runtime::trace`'s `MatchSpec::Functions` (`trace.rs`), `Runtime::seq_trace`'s `Token{label,from}` (`seq_trace.rs`), `Runtime::eval_closures` `FunBody.env` (`eval/mod.rs`), `Runtime::timers` `TimerAction::Deliver` (`timers.rs`), `Runtime::runner_state`'s `ProcessEngine.args`/`entry:Fun{fun}` (`runner/entry.rs`), `Runtime::pending_spawns` `PendingSpawn.args` (`runtime.rs`); `MailboxState.markers[].reference` (`mailbox.rs`) and `NameSpec.inline_options` (`port.rs`) still need a check. Safe: `RunnerState.exits`/`results` (the stabilized `eval_heap` copy), `references`/`Timers.refs` keys, ETS (its own arena), `RuntimeContext` (no `Eterm` field), `dist`/`port` structs, `PortMeta`.
* **Envelope fields the collector does *not* re-root:** `Process::run_rooted_collection` (`../../beam_process/src/process.rs:939`) roots a queued message's `payload()` only, so `Message.from`/`Message.token` are carried raw — every `from` this crate passes is an immediate (`RuntimeContext::send_message`'s `self.mailbox_pid.to_eterm()`, `context/mod.rs:2081`; `port.to_eterm()`; the `system` atom) and every `token` is `NIL` (this crate never calls `with_token`), so nothing here can dangle.
* **A non-immediate `from` does exist in the sibling `beam_process`:** a **named** monitor's `'DOWN'` sets `Message.from` to a `{Name,Node}` tuple built on the *receiver's own* young heap (`../../beam_process/src/ptab.rs:1902-1919`), which the payload root set relocates without updating the `from` copy.
* **The one allocation source here:** `Runtime::alloc_words` (`runtime.rs` → `self.arena`), also reached by `RuntimeContext::alloc_words`, `runner/budget.rs`, `Runtime::materialize`/`charlist`; the mailbox `Queue` payloads are copied in by `copy_struct` and their heap is `beam_message`'s to confirm.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate**: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper). **The compatibility gate**: `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes), or manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `Boot` boots first** (`Runtime::boot_if_needed` → `boot::load_preloaded`), which resolves the system code path via `CodeServer::add_system_paths` → `system_ebins` (memoized in a `OnceLock`, i.e. once per OS process) then loads the 22 preloaded `.beam`s — even for a self-contained module with an explicit `-pa DIR`.
* **The system code path is resolved NATIVELY, from the filesystem** (`codeserver.rs::resolve_system_ebins`): `$ERTS_STDLIB_DIR` when set, else `native_system_ebins` reads the *standard OTP installation layout* — `<root>/lib/<app>-<vsn>/ebin`, or an OTP source tree's `<root>/lib/<app>/ebin`, and the `erts` application at `<root>/lib/erts-<vsn>/ebin`, `<root>/erts-<vsn>/ebin` or `<root>/erts/preloaded/ebin`. A candidate root is accepted only when it really holds the probe module (`lists.beam` decides — stdlib is the hard requirement, `kernel`/`erts` are best-effort, exactly as in the oracle's answer), and the directories keep the `SYSTEM_APPS` order (`stdlib`, `kernel`, `erts`). Candidate roots, most specific first: the `erl` on `$PATH` — **resolved to a filesystem path and never executed**, so the installation this runtime is meant to be interchangeable with wins — then this executable's ancestors (an OTP source tree above `erts_rust/target/…`), then `$ERL_TOP`, then `/usr/lib/erlang`, `/usr/local/lib/erlang`, `/usr/lib64/erlang`, `/opt/erlang`; every seed is also tried as `<seed>/lib/erlang` (the `--prefix` release root, e.g. the Nix store layout).
* **The system `erl` is only *run* as the documented LAST RESORT** (`codeserver.rs::erl_system_ebins`, the `erl -noshell -eval 'code:lib_dir(...)'` probe). It is kept because no filesystem probe can see *every* installation: a version manager (`asdf`, `kerl`) may expose a **shim script** on `$PATH` while keeping the release under a layout reachable from neither the shim nor this executable, and a wrapper `erl` may live outside the release it starts. Asking `erl` is authoritative, and a path is never fabricated: if neither probe produces a stdlib the resolution fails with the typed `cannot locate the system code path: …` error (exit 1). Consequence: a normal installation pays **no** `erl` start-up (measured on this host: `run …slice.beam slice:add/2 2 3` in 0.116 s total, where the spawn alone costs ≈0.5 s).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes.** The CLI prints only class+reason, so one `undef` arises from (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), and (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the system modules `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as an `erlang:nif_error(undef|undefined)` stub, so any key the floor and the registry do not serve **raises** `error:undef`/`error:undefined` (exit 1) for *every* argument; registering the key can only change exit 1 → 3 (`unsupported: ...`), never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate; measure with `examples/perf_bif.rs` before and after any change to the dispatch prologue (figures in `TRACE_AND_PERF.md`).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call`, plus the whole-file-descriptor family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs` — the exact list is in `src/native/CONTEXT.md`), so an interpreted `raw_file_io`/`file_io_server` can open, read, write, seek and close a real OS file; the open handles live in a **`Runtime`-owned `open_files: HashMap<u64, std::fs::File>`** (`src/runtime.rs`, keyed by a reference id from `Runtime::refs_mut()` — never a `thread_local!`). The remaining `prim_file` NIF family (`sync`/`truncate`/`advise`/`pread`/`pwrite`/`write_file/2`/`list_dir`/…) stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the **native `file_server_2` service** (`src/native/file_server.rs`, registered at construction — its served server/io-device requests are listed in `src/native/CONTEXT.md`). The io-device read path is complete: `net_kernel:dflag_unicode_io/1` is served (the atom `true` for a local pid — `RuntimeHooksBridge::dflag_unicode_io`) and the io-device reply tags are paired (`io_request`→`io_reply`, `file_request`→`file_reply`), so `file:read/2`, `file:read_line/1`, `io:scan_erl_exprs/4` and `io:parse_erl_exprs/4` complete and agree with the oracle (`tests/io_scan.rs`) — the `{get_until,…}`/`{get_line,…}` requests are served by `src/native/file_server/{get_until,get_line}.rs`, the device's read loop driving an engine-backed `beam_io::io_device::Continuation` that runs the real `erl_scan:tokens/4`. `beam_io`'s `EfileDriver`/`FdDriver` are implemented and tested but **never constructed by this runtime** (only `SpawnDriver` is) and do open/read/write only. `os:set_signal/2` **is** served from the `RuntimeHooks` bridge (`src/context/signal.rs`): one process-global `beam_io::SignalFacility` in a `thread_local`, registered with the poller under a sentinel key (`src/port/watch.rs`), mirroring the oracle's `{ok, OldDisposition}` answers; the port pump then delivers a caught signal's `{notify, Signal}` (the emulator itself, `system`, as the sender) to the process registered as `erl_signal_server`, dropped when none is registered (matching the C).

## Handoffs (owned by OTHER nodes)
Each line is the owner + the outstanding work; the long-form detail is in [`M1_GAPS.md`](M1_GAPS.md) under `Cross-node handoff detail`.
* **Differential gate status** — **no case disagrees**; the sole `unsupported` is `wire/new_fun_ext_encode` (an `erl_eval` lambda's `NEW_FUN_EXT` identity — structurally unclosable). The live rollup and the allowlist state are owned by [`../tools/differential/CONTEXT.md`](../tools/differential/CONTEXT.md); re-run `gate.sh` for the current figure.
* **A.7/A.9 boot** — completes (the real `start.boot` runs to `{progress,started}`); the residual gaps are `beam_engine`'s `fold_outcome` folding a callee's `Wait` into `error::blocked()` on the non-blocking entries and whatever the started applications still need from `beam_bifs`. Detail: [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) + [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **The native `file_server_2` service** — its served server/io-device request surface (the `{get_until,…}`/`{get_line,…}` io requests included) and every typed per-request gap are tabled in [`src/native/CONTEXT.md`](src/native/CONTEXT.md); a process-**alias** reply tag is the typed `unsupported`.
* **`beam_process` / `beam_message`** — an owning drain for the wake list and a `!Send`-friendly `SchedulerPool` for SMP adoption; the split heap+mailbox borrow already exists.
* **`beam_engine`** — an in-machine module-context switch in the baseline JIT driver, a `MinimalContext` arena word/byte accessor so `erlang:memory/0,1`'s process figures can be real on the single-pass path, and an allocation-admission root-set hook for `ExecutionContext::alloc_words`.
* **`beam_bifs` / `src/context`** — feed `NodeIdentity` from `Runtime::dist_node()` so `erlang:node/0` and the node-valued `system_info` items reflect a live `-sname`/`-name` node.
* **Distribution, phase 2** — the inbound link/exit/monitor/alias `DOP_*` families need a `beam_process` remote-peer seam (plus an alias table); `DOP_SEND`/`DOP_REG_SEND` already reach local mailboxes, and a live-peer loop past the handshake needs the `FragmentAssembler` receive-buffer coupling.
* **`beam_io` / `beam_abi`** — finish the driver-port lifecycle: `driver_async` needs a `beam_abi::DriverHost` seam that can fire `ready_async` (`beam_rt` is `#![deny(unsafe_code)]`) plus a safe reply-copy helper for a `control` reply the driver answered from its own memory, and a per-registration `ErlDrvEvent` identity; `erl_drv_monotonic_time`'s phase differs because `beam_abi` reads `CLOCK_MONOTONIC` from the system epoch.
* **`beam_bifs` — the `ets:setopts/2` heir gift copy and the tid-ref mint** — `setopts_2` stores the gift term verbatim where `Table::install_heir` is meant, and an unnamed table's tid ref is minted locally (`runtime::ets_owner::tid_ref_thing`).
* **`beam_gc` — peak RSS still grows in N** — `resize_nursery` feeds `young_after_collection` the pre-reset used count and `young_after_collection` steps one growth-table entry up instead of settling on the C's fixed point; the sizing policy is `beam_gc`'s, not a `beam_rt` lever.
* **`beam_io` — the port table sits behind one `RefCell`** — the `ids` port-number table shares the live ports' single `RefCell`, so the runtime cannot hand the process and port tables out as disjoint borrows and does not route its slices through `Scheduler::run_ready_with_ports`; a split accessor over the id table would unblock it.
* **`beam_bifs` — the registry dispatch cost and the hook-set drift risk** — the per-lookup owned-`String` key tuples (`contains` + `lookup` on the dispatch path) are the largest attributable residual; a borrowed-key `lookup(&str, &str, u32)` would remove them. This crate's `uses_*` gates delegate to `beam_bifs::hook_sets`' exported `needs_*`/`*_BIFS` tables, so a new consumer is picked up automatically (no per-crate drift).
