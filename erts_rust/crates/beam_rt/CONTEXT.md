# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture. It owns:
`main.rs` and the **CLI flag surface** (**A.6**);
the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the OTP boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded scheduler drives (`src/boot/drive.rs`), which execute the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at the final `{progress,started}` (directive index 21 of 22) (**A.7**);
every CLI action but `-version` drives that script before its own start instruction (`-eval`/`-s`/`-run`/`run`/bare `-noshell`, and `-boot FILE` with the flag's own value), so a silent action exits **0** with **empty stdout and empty stderr**;
`whereis(kernel_sup)`, `whereis(application_controller)` and `whereis(logger)` are live PIDs on every driving route, `whereis(timer_server)` stays `undefined` (OTP starts it lazily through `kernel_sup` via `timer:do_start/0`), and `application:*` listings include `kernel` and `stdlib`;
the tail's blockers are served **in-node** by the native floor (`RuntimeContext::try_native`) or runtime state, every other call falling through to the registry unchanged: `process_flag` for the bare `monitor_nodes` atom and the `{monitor_nodes,Opts}` tuple flag, `erlang:nodes/2`, `prim_tty:tty_select/2` over the port poller, `process_flag(message_queue_data, on_heap|off_heap)`, `erlang:system_flag(system_logger,_)`, `erts_internal:scheduler_wall_time/1` and the `erlang:hibernate/0` instruction;
the per-link detail is in `M1_GAPS.md` (*A.7/A.9 boot*) and [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md);
**`system_info/1`** + `erlang:process_info/2` (**A.8**);
the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable);
the **A.4 runtime side of ports** (`open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s);
the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and `{abs,true}` absolute) and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
and the **distributed node** (A.5 phases 1–2): the **accepting** half (`src/dist.rs` + the inbound `LocalDeliverySink` in `src/dist/inbound.rs`) and the **connecting** half in `src/dist_client.rs` (the outbound client handshake + the `DistSignalRouter` that turns a locally-initiated link/monitor/exit into wire `DOP_*`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)
Per-child API surface detail lives in the child nodes' own `CONTEXT.md`; the entries below are the crate-level summary + pointer.
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces, the scheduler-pass family drives processes → ports → timers → distribution in bounded steps, and `RuntimeRunner` implements `beam_process::ProcessRunner`; full API surface in [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking and the NIF-dispatch order; full API surface in [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver.rs`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump, and `port_info/1,2`'s **real cumulative per-port byte totals** for `input`/`output`), the native-floor `erlang:port_control/3` (the driver's `control` callback behind `PortRegistry::port_control`) and the runtime's own driver C-ABI host for `{spawn_driver, Name}`; full API surface in [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
### `dist.rs` + `dist/` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener bound by `start`, published to `epmd` by the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half. Both production inbound drives (`dispatch_inbound`/`dispatch_dist_client_inbound`) drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`, the C's `dep != external_pid_dist_entry(from)` check), so a malformed or forged control message is an `Err` that **retires that one link** rather than reaching the `beam_dist::InboundSink`.
`LocalDeliverySink` (the inbound sink, `src/dist/inbound.rs`) routes the ordinary message families (`Send`/`RegSend`/`AliasSend`/plain `AltactSigSend`) plus the route-free receipt families (`Link`; the `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` group; `UnlinkId`/`UnlinkIdAck`; `Monitor`/`Demonitor` via `monitor_from_remote_ref`/`demonitor_from_remote_ref`; `MonitorExit`/`PayloadMonitorExit` for a DOWN whose reference this node minted; `GroupLeader`) through `ProcessTable`'s inbound (receipt) primitives, each emitting **no** outbound `DOP_*`; a peer `DOP_MONITOR_P` is recorded as a `RemoteWatcher` keyed by the **whole** peer-minted wire reference (`RemoteWatcherRef::Remote(RemoteRef)`, all-immediate), and `DOP_DEMONITOR_P` removes exactly that record. The **only** families still typed `DeliveryOutcome::Unsupported` are the distributed-spawn family (`SpawnRequest`/`SpawnReply`), `Delivery::Other(_)`, and the `UnlinkId` `id != 0` ack-owing half (`id == 0` is `Delivered`). The pass is gated by `Runtime::inbound_delivery` (default **ON**), early-returning unless the runtime is a distribution node with an established link.
Accessors, `NodeName::parse`, `resolve_cookie`, the pump budgets, the envelope rule, the `DistRouter` install site and the per-family routing table (each family → its receipt API): [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md); the sink/node child node: [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; `NifRegistry` offers `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**) and `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`: a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, holding `Some(&'a mut dyn NifHostServices)`; `alloc_env`/`free_env` are real and `make_copy` is the **identity**. The host **exposes that shared table** through `NifHost::atom_table`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by its name, not its interned index. All six state-needing `NifHostServices` hooks are live on a call (`make_ref`, `whereis_pid`, the two liveness answers, the port relations `is_port_alive`/`port_command`); only the load/unload host leaves them the trait default — `M1_GAPS.md` *NIF (A.3)*.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The dispatch table (the source of truth) and every implemented/not-implemented BIF live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (11 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry — `os:env/0` is served by `beam_bifs::os_bif::os_env_0` (the floor owns only `os:cmd/1`).
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form.
**`erlang:monitor/2,3`/`demonitor/1,2`, `erlang:alias/1`/`unalias/1` and the reference-alias send destination are served from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed exactly as the C's `erts_monitor_opts` (`erts/emulator/beam/bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias. A **send destination** that is such a reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams; a `{alias,_}` on a **port** monitor or a **remote** target propagates `beam_process`'s typed `unsupported`. Evidence (`tests/alias.rs`): [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
**`erlang:garbage_collect/0,1` are served from the floor** (`src/native/erts_internal.rs`, contract A.7). **No BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet` (every x register, the Erlang stack and the FR file), which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`; the request is served only at the sites that *do* own that root set (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first, so `Runtime::gc_stats().collections` moves only when a collection really ran. `/2`'s `get_gc_opts/2` grammar and its residual (the **asynchronous** `{garbage_collect, ReqId, Result}` completion is not sent): [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**`code:*` reads and the code path are the native floor over `CodeServer`, alongside a live `code_server` process.** A booted runtime starts the real `code_server.beam` — `whereis(code_server)` is a live, registered, `waiting` pid on every boot-driven route (the booted `kernel_sup` starts it) and its `{code_call, From, Req}` → `{code_server, Reply}` wire is live — and `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7) the oracle serves from `init.beam`/`code.beam`/`application.beam`; the `boot/*` differential cases touching `code:*` are **shape-only**. The floor owns the **one** authoritative path store ([`CodeServer`](crate::CodeServer)) for the path *readers* (`code:get_path/0`, `load_file/1`, `which/1`, `get_object_code/1`, `ensure_loaded/1`, `where_is_file/1`) **and** the *mutators* (`add_patha/1,2`, `add_pathz/1,2`, `add_path/1,2`, `del_path/1` — `native::code::path`), so the path this runtime searches and the path it reports cannot disagree. The path mutators still **un-migrated** (`set_path/1,2`, `add_paths/1,2`, `add_pathsz/1,2`, `add_pathsa/1,2`, `del_paths/1`, `stick_dir/1`, `unstick_dir/1`) are ordinary `code.erl` bodies that edit the live server's **second** store, so their edits are invisible to the floor's readers (`code:add_paths([D])` answers `ok` while `code:get_path/0` omits `D`). **`src/native/code.rs`'s `code:*` behaviour must not change.**
**The A.9 floor surface is the installation view.** `init:get_argument/1` answers the four automatic flags (`root`/`home` from the runtime's own state, `progname` by the C rule, `bindir` from `CodeServer::bindir()`'s `erts-<vsn>/bin`) and `init:script_id/0` reports the **loaded** boot script's `{Name, Vsn}` — the header of the script the runtime resolved and ran, i.e. the installation's own `bin/start.boot` on the default route (measured `{"Erlang/OTP","29"}` against this host's OTP-29 install) — on every CLI route that drives one, i.e. every action but `-version`; the typed gap survives only for a host-built runtime that drives none; `code:lib_dir/2` joins the app directory with the subdir; the `application` view serves `get_all_key/1`/`get_key/1,2`/`get_application/0,1` from the parsed `.app` resource; `erlang:module_loaded/1` is truthful to *this* runtime's loaded set, so `module_loaded(kernel)` stays `false`. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**Three server processes are native state, not scheduled code.** The runtime's root process (registered as `init`) and the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery all work. A third native process, the **`erl_prim_loader`** stand-in (`src/runtime.rs`, A.7/A.9), is spawned the same shape and registered under the loader's own name on **every** route that builds a runtime (nothing in `bootstrap/bin/start.boot` claims it), so `erlang:whereis(erl_prim_loader)` answers a live pid as the oracle's booted node does. The `file_server_2` service is **spawned unregistered on every route that drives a boot script** — every CLI action but `-version`, plus an explicit `-boot FILE` — so the booted `kernel_sup`'s own `file_server_2` child owns the name; `Runtime::new` gates the decision on `RuntimeConfig::drives_a_boot_script()` and registers it only when the runtime drives none. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` means exactly **an OTP `erlang` BIF the oracle exports and serves but this runtime does not**; the effective gap set is that list intersected with what the live registry does not own. Drift guard: `error::tests::{known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry,the_effective_gap_set_never_shadows_the_registry,a_name_the_otp_release_does_not_export_is_not_a_curated_gap,a_reclassified_name_exits_1_and_a_newly_curated_one_exits_3}`.
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). Outside the grammar is a **capability gap** (exit 3).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2). **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap. The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` exceeds the 60-bit small range, so it materializes as a bignum); `context_reductions` is answered as `4000`, the canonical ERTS quantum `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2079 lines of production; its ~2190-line unit suite lives in `src/port/tests.rs`) and `src/runtime.rs` (~2280 lines — the façade is also the colocated home of its own unit tests).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle. When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer. Flattening is the graceful **last resort** for an unresolvable payload, never a substitute for adopting handles: the send path unions three source families (`src/context::send_source`) so a resolvable payload takes the SHARE route.

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (by the section named after each bullet); the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **The `term_to_binary`/`binary_to_term` round-trip cost is the codec's own per-call work, not `beam_rt`'s dispatch.** The wired path is allocation-free (a pooled BIF heap, an atom commit only when a call really interns a name, and a code-server-cached fun-identity snapshot), and every ETF **decode** seam decodes into a **per-thread memoized image** of the shared `AtomTable` (`DECODE_SCRATCH` + `prefix_matches` + `with_decode_scratch`), so no call pays an O(table) clone — `M1_GAPS.md` *Dispatch, atoms and module introspection*.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers the running scheduled process's own **young heap** (a no-relocation `Process::grow_nursery` + retry on a capacity refusal) and falls back to the pointer-stable `Runtime::arena`; what a future **moving** heap would dangle is a raw `Eterm` pinned outside the GC root set — the at-risk/safe roster is in `M1_GAPS.md`.
A **parked** (`Waiting`) process is relocation-exempt for its whole parked window — the runner's Wait park arm sets the mark (`src/runner/run.rs`) and the resume clears it — so a delivery- or signal-driven collection of a parked (or just-woken) process is declined and the delivery takes the ordinary heap-fragment fallback. That exemption **complements** the installed host collection gate (`src/context/gc_walk.rs`'s `RuntimeCollectionGate`, installed on the runtime's process table by `Runtime::new`): the gate declines only when an **unscanned container is reachable from the receiver's gathered roots**, whereas the exemption refuses *any* relocation for the parked window — also covering a live term the host holds **outside** that gathered set (the runner's own entry terms and any live `Eterm` in host Rust state). The `Yield` pre-emption arm is *not* exempt.
The full hazard analysis — the `Process::regs` snapshot semantics, the three collect triggers and their exposure, the delivery/park arms, the unscanned-root valve, and the at-risk/safe store roster — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *GC-relocation hazards*.
## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate**: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper). **The compatibility gate**: `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes), or manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script), which resolves the system code path via `CodeServer::add_system_paths` → `system_ebins` (memoized in a `OnceLock`, i.e. once per OS process) then loads the 22 preloaded `.beam`s — even for a self-contained module with an explicit `-pa DIR`.
* **The system code path is resolved NATIVELY, from the filesystem; the system `erl` is only *run* as the documented LAST RESORT.** The acceptance probe (`lists.beam` decides), the installation layout shapes, the candidate-root order and the `erl -noshell -eval 'code:lib_dir(...)'` fallback are in [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*. Consequence: a normal installation pays **no** `erl` start-up for the resolution itself. **The boot-script drive on every action is not free** — it runs `bootstrap/bin/start.boot` (all 22 directives) before the action's own instruction, so start-up cost (and the Rust-vs-oracle advantage) is characterised in `PERF.md`.
* **Whole-process startup is ~0.44 s (release) and CPU-bound — the fixed waits are gone.** The `-eval` receive pump keeps `TIMER_PUMP_SLICE = 100 ms` (`src/runtime/scheduler.rs`), but the **boot drive** calls `Runtime::pump_scheduler_boot`, whose `TimerWait::ImminentWithin(TIMER_PUMP_SLICE)` sleeps only when the earliest pending deadline is **within** the window (and only once per pass) — so a boot with a 1 s / 1 h `gen_server` `WaitTimeout` pending issues **0** `clock_nanosleep` calls and never busy-spins, while a boot-spawned process parked on a short `receive … after T` (T ≤ 100 ms) is still slept to and resumed (`src/boot/drive.rs`). A blocking `run`-route round is likewise free: `PortRegistry::has_nothing_to_poll` (`src/port.rs`) reports an **armed-but-idle** `os:set_signal/2` `handle` disposition as nothing-to-poll — only a *caught, undrained* signal counts (`SignalWatch::has_pending_signal`, a zero-timeout poller probe) — so `Runtime::is_quiescent` holds and `run_scheduled` returns instead of sleeping `PORT_POLL_SLICE` (25 ms) per round. Measured (release, this host): `-eval 'halt(0).'` ≈ 0.44 s, `-eval` with a real expression ≈ 0.43 s, `run <slice.beam> slice:add/2 2 3` ≈ 0.47 s, 0 `clock_nanosleep`, and `strace -f -e trace=newfstatat,statx` shows **927** stats (**2** on `os.beam`): `Runtime::find_module_file` (`src/runtime.rs`) answers an already-loaded module from `CodeServer::loaded_path` instead of re-walking the code path. The residual ~0.44 s is engine CPU work (the oracle's own `-eval` boot is ~0.14 s).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes.** The CLI prints only class+reason, so one `undef` arises from (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), and (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the system modules `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as such a stub, so any key the floor and the registry do not serve **raises** (exit 1) for *every* argument; registering the key can only change exit 1 → 3, never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate and every per-call input the prologue derives belongs in the 8-slot dispatch memo; measure with `examples/perf_call.rs` before and after any change to the prologue (`examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch at all). The prologue is memoized (`dispatch_slot` hashes the key's name bytes with an avalanche multiply, the resolved `BifFn` is invoked directly with no second `BifRegistry::lookup`, and `try_call_nif` short-circuits on an empty NIF registry) and the copy-out is one well-informed retry. Per-call dispatch and copy-out figures live in [`PERF.md`](PERF.md) (*DISPATCH-CUT* / *COPY-OUT-CUT*).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call` + the whole-fd family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs`), so an interpreted `raw_file_io`/`file_io_server` can open/read/write/seek/close a real OS file, backed by the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`); the rest of the `prim_file` family stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service on every route where it owns the name (the exception is any route that drives a boot script, the default `start` included: there the booted `kernel_sup`'s own `file_server` child owns it). The io-device read path is complete (`file:read/2`/`read_line/1`/`io:scan_erl_exprs/4`/`io:parse_erl_exprs/4` agree with the oracle — `tests/io_scan.rs`) and `os:set_signal/2` is served from the `RuntimeHooks` bridge. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work — the differential gate, A.7/A.9 boot, the native `file_server_2` service, `beam_process`/`beam_message`, `beam_engine`, the node identity, `beam_io`/`beam_abi`, the send path's caller-machine handle plumbing (`beam_engine`/`beam_bifs`), `beam_bifs`' `ets:setopts/2` and registry dispatch cost, and the port-table borrow — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *Cross-node handoffs*.
**Inbound distribution's remaining `Unsupported` families each need a new sibling API**, precisely:
the distributed-spawn family needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender plus the reservation bookkeeping a `DOP_SPAWN_REQUEST` keys into), and `Delivery::Other(_)` (the C kills the connection outright, `dist.c:2277-2282`) is the link driver's.
`beam_process`'s route-free receipt primitives (all present, none echoing a `DOP_*`): `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)`/`demonitor_from_remote_ref(watched, reference: RemoteRef)` (the peer-minted wire-reference spellings; the `MonitorRef` ones stay for an internal ref), `remote_monitor_down`, `set_group_leader_from_remote`.
`beam_dist` — a reply channel on `InboundSink` (the `DOP_EXIT`/`DOP_MONITOR_P_EXIT` `noproc` replies and the `DOP_UNLINK_ID_ACK` cannot be emitted at all: the drain counts only `Delivered`), a connection/peer identity on the sink (the C's arms need the peer's sysname for the envelope and the connection id for the origin checks), and a local-node identity in `decode_control` (inbound references decode as pure external, so a wire reference cannot key an alias or a monitor DOWN). The invalid-message **connection-kill** path is adopted (`Delivery::classify_validated` + the `*_checked` drain, see the API Surface above).
**Routing an inbound creation family through the nearest public `beam_process` entry point would be WRONG today**: those entry points are the *local-initiated outbound* half and route a `DOP_*` through the installed `DistSignalRouter`, whose auto-echo the C's inbound receipt arms never send (`dist.c:2258` `break; /* Done */`).
