# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture — `main.rs`, the **CLI flag surface** (**A.6**), **`system_info/1`** + `erlang:process_info/2` (**A.8**) and the **boot sequence** (`src/boot/{preloaded,bootscript,drive}.rs`), which loads the 22 preloaded `.beam`s and runs the real `bootstrap/bin/start.boot` to completion (`{progress,started}`, **A.7**); every action but `-version` drives that script, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — every optional `beam_bifs` host seam, the **A.4 runtime side of ports**, the **runtime-local timer deadlines** (`src/timers.rs`) and the **distributed node** (A.5: `src/dist/` accepting, `src/dist_client/` connecting).
The vertical slice runs on a test-only `MinimalContext` at the engine level (`../beam_engine/tests/slice.rs`) and through this crate's real glue (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`, terms/heaps → `beam_term`/`beam_alloc`, pids → `beam_process`, modules → `beam_loader`, execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**), sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (`Runtime::dist_ensure_link`); a `-name`/`-sname` node also runs the native `net_kernel` service, so a peer's `net_adm:ping/1` answers `pong`.
Both inbound drives drain every established link through `beam_dist`'s per-link checked path, and `LocalDeliverySink` routes the message and receipt families through `ProcessTable`'s inbound primitives (gated by `Runtime::inbound_delivery`, default **ON**); peer loss fires `noconnection`, the event-vs-control ordering rule holds on both halves, and `Runtime::dist_connect` is idempotent — `tests/dist_two_vm{,_rust,_wire}.rs`.
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`Runtime` holds the `!Send` `NifRegistry` (`new()` anchors the `enif_*` codegen unit; `is_loaded`/`insert`/`lookup` — **the dispatch predicate** — and `call`), each entry pairing the loaded library with a stored `NifHostImpl` host whose **field order is load-bearing** (the library's `Drop` runs the C `unload` against the erased host pointer).

A NIF-created thread runs on `src/nif/thread_env.rs`'s **process-independent** `ForeignHost` (one per thread, a **private** name→index atom space, `send` queueing a complete ETF image that `drain_nif_thread_sends` decodes by **name** at `try_call_nif` and `scheduler_pass`); `build.rs` emits `-Wl,--export-dynamic`, which is what publishes the `enif_*` symbols a real NIF's `dlopen` needs — [`src/nif/CONTEXT.md`](src/nif/CONTEXT.md), `tests/nif.rs`, `tests/nif_a3_*.rs`, `M1_GAPS_A3_NIF.md`.

### `malloc.rs` — the allocator's free-page release
`beam_rt::release_free_pages()` is the crate's single allocator lever (`libc::malloc_trim(0)` on glibc, an honest `None` elsewhere), called **once per process** from `src/main.rs` after the `"beam_rt-driver"` thread is joined — the only quiescent *and* complete point.
The runtime is not torn down at exit (`ExitTeardown::Leak`), so it finds a largely **live** arena and returns little: **capacity is not RSS**, and peak `VmHWM` is untouched.
`BEAM_RT_MEM_TRACE` prints the answer as one `[rt-mem] heap-release=…` line and nothing depends on it.

### Crash reports (`src/report.rs`) — an abnormal termination's `=ERROR REPORT====` block
One report per process that dies from an uncaught **`error`-class** exception (an uncaught `throw` is promoted to `{nocatch, V}` and reports too), written to **stdout** in the default handler's shape — the `logger_formatter` legacy header, `Error in process <Pid> with exit value:` and the `{Reason, Stacktrace}` term through the one `~p` printer (`Runtime::format_term`) — and silent, matching the oracle, for an `exit`-class reason (`exit/1`, `normal`, `shutdown`, `killed`, hence every link/monitor/`exit/2` propagation), a trapped `{'EXIT', …}`, a normal return, and the process the `run` action itself waits for.
The one call site is the runner's termination arm; a report that cannot be built or written goes to `debug_trace`, never into the termination's own outcome.
Honest gaps: the header timestamp is **UTC** (the oracle renders local time), the handler set is **not** read from `kernel.app.src`, no SASL `supervisor`/`gen_server` report and no `max_heap_size` report — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The default logger handler*.
### The death-path reason — the bare one and the signalled one (`src/runner/reason.rs`)
A process that dies of an uncaught raise has **two** reasons: the **bare** one (`exit_reason`, the raise's own reason untouched by its class — what the report is given and `RunnerState::errors` classifies by) and the **signalled** one (`signalled_reason`, ERTS's *exit value* — the term `RunOutcome::Exit` hands to `ProcessTable::terminate`, hence what a linked peer's `{'EXIT', Pid, R}` and a monitor's `{'DOWN', Ref, process, Pid, R}` carry, locally and over `DOP_EXIT`/`DOP_MONITOR_P_EXIT`).
The rule: `error` class ⇒ `{Reason, Stacktrace}`; uncaught `throw` ⇒ `{{nocatch, Value}, Stacktrace}`; `exit` class ⇒ the reason **bare** (`bye`, `normal`, `shutdown`, `kill`, including every propagation); a `max_heap_size` kill ⇒ the bare atom `killed`; a non-raise `BeamError` (plumbing: no class, no stacktrace) ⇒ the bare interned `Display` text, because inventing an empty trace would fabricate a shape the oracle never produces.
Both come from the one definition `crate::report::exit_value`, so report and signal can never disagree about one death; the rooting, the private heap and every degradation (`signalled_or_bare`, the flattened off-heap reason) are [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *The death-path reason — bare vs signalled*.
Measured against the oracle (a compiled module with `trap_exit` + `spawn_link`): `erlang:error(boom)` ⇒ `{boom,[{died,boom,0,[{file,"died.erl"},{line,18}]}]}`, `throw({ball,1})` ⇒ `{{nocatch,{ball,1}},[{died,thr,0,[{file,"died.erl"},{line,19}]}]}`, and `exit`/`normal`/`shutdown`/`kill` ⇒ the bare atom — byte-identical on both sides.
## Host-side term stores — owned copy vs raw word (the rule that makes a store sound)
- **A raw `Eterm` in a long-lived slot roots nothing**: a term that can outlive one instruction must be copied onto a scanned heap or explicitly stabilized before its owner's heap can be relocated.
- **A pointer-stable, never-scanned store (the arena, `alloc_words`) is the wrong home for a container whose children live on a scanned young heap** — the copier gives it `Target::Foreign` and never descends.
- **An exempted heap-growth or move must "refuse ⇒ stabilize, never dangle"**, and **an `Rc` lease held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow.**
A stored term is self-contained only if it went through `Runtime::stabilize_term`/`try_stabilize_escaped` (a copy onto the `eval_heap` + `eval_off_heap` store), was built on the pointer-stable arena, or was built on a pooled BIF heap the escaping `runtime_hooks` arm froze; every store is **pointer-pinned**, so the one thing it cannot survive is a **move** of the region it names — done only where nothing executes, rewriting every stored word through `Runtime::for_each_root_family_mut`.
The per-store inventory (owned copies / immediate-only / deliberate raw words) and the move's two instants: [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) *Host-side term stores*, `src/context/IMPLEMENTATION.md`.
## The runtime-native BIF floor (`src/native/`)
The floor serves the BIFs that are really *runtime* operations — process/port tables, code server, atoms, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file`/`prim_buffer` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry, and **a native entry never duplicates a registry one**; an unclaimed call returns `None`.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`), and `io`/`prim_tty`/`prim_file`/`prim_buffer` are **key-granular** (`floor_keys`), so only the enumerated keys are refused in-machine.
`application:*` is deliberately **not** a floor namespace: every key of it is a one-line `lib/kernel/src/application.erl` delegation to the live `application_controller` the boot script starts, which answers from the `ac_tab` it really populates.
The floor owns the process/name/global-state arms (`ProcessBridge`'s only implementation), `process_info/1,2` (`src/native/memory/`), `monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` with the reference-alias send destination (`src/context/alias.rs::alias_destination`, on **both** send seams) and `garbage_collect/0,1` — **no BIF may collect**, so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true` where the root set is owned.
`prim_tty` and `prim_buffer` are built-in libraries: `is_builtin_library` answers their `erlang:load_nif/2` load (the C's `STATIC_ERLANG_NIF`, so nothing is `dlopen`ed) and `NifRegistry::is_loaded/1` stays **`false`**, which is what keeps their Erlang wrappers enterable in-machine.
**`code:*` reads and the code path are the floor over `CodeServer`**: the floor owns the **one** authoritative path store — readers **and** the `add_path*`/`del_path` mutators — and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store*).
`Runtime::new` starts exactly **four** runtime-owned, never-enqueued `Runnable` processes (the `init` stand-in `<0.0.0>`, the root process `<0.1.0>` every action runs as, the `erl_prim_loader` stand-in and the `file_server_2` service), and `call_bif`'s last resort is the **`erlang` namespace**: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y` (exit 3), any other unclaimed name the bare `error::undef` — `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` and its drift guard are the authority.
`dets` works end to end on this floor — `open_file/insert/sync/lookup/match_object/close` agree with the oracle byte-for-byte, **including the `.dets` file bytes** (`tests/dets.rs`, `tests/prim_buffer.rs`), which is what the `prim_buffer` stubs and `flatten_iodata`'s binary improper tail buy.
The module list, `floor_keys`, the `prim_buffer`/`prim_file` descriptors and read-ahead queue, the `io` device classes and the dispatch index: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **four** built-in key sets — `prim_tty`'s 20 stub keys, `zlib`'s 19 stream keys, `prim_file`'s one key `advise_nif/4` and `prim_buffer`'s two unexported stubs `peek_head/1`/`copying_read/2` — from a module-name equality short circuit plus a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash (the `prim_tty` and `zlib` sets are what `beam_bifs::serves_local_call` exposes).
`prim_file`'s key is what `prim_file:advise/4`'s own body chains into at `prim_file.erl:433`, so `file:sendfile/5`'s wrapper sees the oracle's `{error,badarg}` instead of the stub's `erlang:nif_error(undef)` — `src/native/prim_file/advise.rs`; `prim_buffer`'s two keys arrive as LOCAL `call`s inside `prim_buffer.erl` (its exported stubs come in by `call_ext`) and both routes converge on the one `prim_buffer_call`.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`) serves the **record-held** shape of the `zlib` set: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body — oracle-identical at every level 0–9 through the real preloaded `zlib.beam` (`tests/zlib_{stream_levels,stream_dict,guards,one_shot}.rs`).
## The synthesized BIF stacktrace item's extension (no runtime-side classification)
The engine's `families/exceptions/bif_frame.rs` decides the `[{error_info, #{module => FormatModule}}]` location extension from **its own closed table plus the raise's reason** (`format_module(module).is_some()` and the reason not being a bare `function_clause`), so this crate contributes no classification of a failing name and no seam for one.
A `beam_bifs` **stdlib fast path** therefore keeps its module's extension exactly like a declared `bif.tab` BIF (OTP's sources re-raise through `error_with_info/2`), measured on the oracle as `lists:seq(1,2,0)` ⇒ `{lists,seq,[1,2,0],[{file,"lists.erl"},{line,541},{error_info,#{module => erl_stdlib_errors}}]}` — this runtime reproduces the module/function/arglist/extension and leaves the source position as the documented residual (G *A BIF that raises publishes no callee stacktrace item*).
## The CLI switch surface (A.6)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (no interactive shell) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod F [Tok…]` | the ERTS Start instruction: `Mod:F(['Tok', …])` — **arity 1**, one argument, the collected tokens as **atoms** (`-s Mod F` ⇒ `Mod:F()`, arity 0), result **discarded**; a numeric token is a **name** (`-s mod f 1 2` ⇒ `['1','2']`) |
| `-run Mod F [Tok…]` | the same single-list shape with every token a plain **string**: `-run Mod F a b` ⇒ `Mod:F(["a","b"])` (`[[49],[50]]` for `1 2`), result **discarded** |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse order), `-pz` **tails** it (behind the system `ebin`s), on **every** route |
| `+S Total[:Online]` | normal scheduler counts via the C's `sscanf("%d:%d")` → `sscanf(":%d")` cascade: the total → `emulator.schedulers`, the online half → `online_schedulers`; `+SP`/`+SDcpu`/`+SDPcpu`/`+SDio` are validated and preserved verbatim (inert here) |
| every value-taking `+` switch | accepts its value **attached or separate** (`+S1` ≡ `+S 1`, `+sbtu`, `+A0`), the C's `get_arg` rule — the form the real `erlc` passes |
| `-extra …` / `-- …` | **ends the switch surface**: every remaining token is a **plain argument** (`RuntimeConfig::plain_args`) that `init:get_plain_arguments/0` answers as a list of strings — never an init argument, never a Start instruction; split per **entity** (`ERL_OTP30_FLAGS`/`ERL_AFLAGS`/argv/`ERL_FLAGS`/`ERL_ZFLAGS`) at that entity's first `-extra`, and `--` collects until the next switch-looking token |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A<n>` / `+P<n>` / `+Q<n>` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes`; max port count → `RuntimeConfig::max_ports` with `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+sbt<type>` / `+K<true\|false>` | scheduler bind type (`u`/`db`/`s`/`ps`/`ts`/`tnnps`/`nnps`/`nnts`/`ns`, an unknown type the C's rejection) and the kernel-poll switch, both preserved verbatim |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking driver/port round trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* **The `-s`/`-run` vector is ERTS's one collected list** (never one token at a time), and the OTP `erlc` C front end drives this runtime unchanged — `ERLC_EMULATOR=<beam_rt> erlc …` exits 0 with a byte-identical artifact; the exact argv, the `instruction_args` rule and the init-argument recording rule (every `-` flag is an init argument, an unmodeled one **data** not a usage error) are [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
### The `-eval` route (`src/eval/`)
`-eval` walks the Erlang **expression** subset `erl_eval`-style — arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3).
`receive … after T` scans the running process's **real mailbox**, pumps the scheduler non-blockingly (`RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass and spends the remaining window on the timer heap through `Runtime::wait_for_timer`; a port round's messages are **delivered into that mailbox** before any clause is tried.
A closure `erlang:spawn/1` starts is **compiled** (`src/eval/compile.rs`) from its recorded source into a synthetic `beam_rt_eval_fun_<index>` module (`compile:file/2` in process, then `code:load_binary/3`), so the child is an ordinary `ProcessEntry::Export` that really parks on a bare `receive` or a `timer:sleep/1`; the result — a decline included — is cached per closure index on `Runtime::eval_compiled`.
**Fun application has an explicit nesting budget, because the walker's continuation is the native Rust stack**: `src/eval/nesting.rs` routes to the tree walker while this thread's remaining native stack is at least `WALK_STACK_RESERVE` **and** the nesting is within `WALK_APPLY_LIMIT = 512`, to the **compile route** past either bound, and to the typed `unsupported: eval fun application: …` gap once `COMPILED_APPLICATION_LIMIT = 16` compiled applications are nested; a context inside a scheduler slice cannot compile and refuses instead of pumping — `tests/eval_deep_recursion.rs`.
Residuals: a `spawn` from inside a running engine keeps the tree-walking entry, a **declined** compile keeps that closure's gaps, and `receive … after infinity` is a typed gap — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Known Issues*.
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure: a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation (a missing operand of a *known* switch, a malformed `run` spec or numeric value, a stray positional) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`), and is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`); the convention is a raise whose **reason atom starts with `unsupported`**, `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call**, or the engine cannot land it in a catch frame: `src/context/calls.rs::name_raise_reason_atom` appends it (append-only, at `PendingInterner`'s predicted index) on the **one** funnel every failed call passes, so a module that never spells the atom still catches `error:R` as the oracle does — **every** atom-reasoned error is named, a capability gap included (`tests/gap_raise_catch.rs`).
A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` renders it through `format_term_w`, so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1).
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **89** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and `error:badarg` for any other key; the **26** keys the oracle accepts but this runtime's facilities lack raise the honest `unsupported` gap, and the two sets partition the oracle's 115 accepted names (`tests/system_info_oracle.rs`; the pins are `SUPPORTED_KEYS.len() == 89` / `UNSUPPORTED_KEYS.len() == 26` in `src/info.rs`).
`snifs` is **supported**: it answers this tree's own 556-row `beam_bifs::snifs()` roster in `bif.tab`-reversed order (the C's `build_snifs_term`), and its 465 distinct names extend the boot atom vocabulary through `info::info_atoms()`, so no name is invented at materialization — its oracle comparison is **shape-only** because an OTP-29 oracle answers 553 rows (the three OTP-30-only `*_to_binary/1` rows are the whole difference).
The per-key catalog is [`src/info/CONTEXT.md`](src/info/CONTEXT.md).
## Constraints
* **Errors are return-based** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`, with no crate-local error enum, no `panic!`/`unwrap()` on runtime data and no silent swallowing; CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`, never stderr writes.
* **`#![deny(unsafe_code)]` with eleven per-module exemptions**, each carrying a `// SAFETY:` rationale at every site — `src/malloc.rs`, `src/nif.rs`, `src/context/{calls,gc,gc_walk}.rs` + `src/context/gc/{bin_vheap,valve_bounds}.rs`, `src/eval/reclaim.rs` + `src/eval/reclaim/resource.rs`, `src/eval/native_stack.rs` (the walker's stack-headroom probe over glibc's pthread attributes), `src/runtime/reclaim/{compact,holder}.rs` (the store move).
* **Call down, never duplicate** — the `~p` printer is **not** re-implemented; `format.rs` drives the registered `io:format/2` BIF.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner** — reachable from `Machine::refc_binaries()` or `Runtime::eval_off_heap`; the transport copy resolves one of them into its **source** table so the destination **shares** the handle, and a source table that cannot name the owner makes `beam_message`'s copier **flatten** the window into a fresh on-heap bitstring as the **last resort** only.
* **A live heap serves its own builds; the arena is a refusal-only fallback** — `alloc_words_rooted` serves a nested run from the running process's scanned young heap, the arena answers only a table-less context or a refused growth, and inside a relocation-exempt window the copy-out `stabilize`s instead of growing; **a park that skips root publication holds the relocation exemption**, the three runner park arms taking the one `park_window` entry point that writes the flag in both directions — [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md).
### The one process-lifetime `Rc<AtomTable>` lease
**Never hold a `CodeServer::atoms_handle()` across an intern** — [`src/codeserver.rs`](src/codeserver.rs) states the rule on the method: `atoms_mut()` is `Rc::make_mut` and `intern_pending()` falls back to it, so an `Rc<AtomTable>` clone held **across** an intern deep-clones the whole shared table and drops the copy; only **one** holder lives long enough to matter — a loaded NIF library's stored host (`src/nif.rs`'s `NifEntry::host`, alive for the process's life).
A `{spawn_driver, Name}` port's host (`src/port/driver.rs`'s `DriverPort`) is **not** a holder: its view is a **lease** on the `DriverAtoms` record the port layer shares with it, opened by `PortRegistry::open_driver_atom_view` only for the window in which driver code runs and closed by `close_driver_atom_view` (re-entrant, depth-counted), so between windows an intern taken anywhere — the port round's `commit_driver_atoms` included — appends **in place** (`Rc::get_mut`).
A **built-in**-driver port (`ram_file_drv`/`tcp_inet`/`udp_inet`) and a `{spawn, …}` port create **no** host, so the code server is sole owner there; the two production sites taking a handle — `src/native/prim_file.rs::build_descriptor`, `src/native/net/nodes.rs::nodes_2` — **intern first and take the handle last**, the port delivery builders intern through `src/port.rs`'s `intern_reuse` (lookup first, `atoms_mut()` only for a genuine miss), and `RuntimeContext` itself holds **no** atom handle — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `src/port/tests.rs`.

## Known Issues / Intentional M1 gaps
**Every gap is a typed capability gap or a measured own-state difference — never a wrong result; detail lives in the ledger each line names: `G` = [`M1_GAPS.md`](M1_GAPS.md), `GC` = [`M1_GAPS_GC.md`](M1_GAPS_GC.md), `A3` = [`M1_GAPS_A3_NIF.md`](M1_GAPS_A3_NIF.md), `A4` = [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md).**

* An **OTP-shipped NIF library's `load` callback vetoes** (`../beam_abi/src/nif/loader.rs`): `crypto.so`/`asn1rt_nif.so` never load, so every `crypto:*` call answers `{nif_not_loaded,module,crypto,line,N}` and `cowboy_websocket`'s handshake can only answer `500`; `build_stacktrace` then cannot resolve a `crypto` frame's atoms from the *running* module's table, so that raise is a fatal, uncatchable `unsupported_opcode` — A3.

* BIF-nested fun application is unbounded in depth; the driver thread's stack is the only bound — G *Scheduler / runner*.
* `term_to_binary`/`binary_to_term` cost is the codec's own work, not `beam_rt` dispatch; `get_module_info`'s `exports` order and its `badarg` for a module not loaded here are the same family — G *Dispatch, atoms and module introspection*.

* Process-control gaps: named port monitor, remote `{Name,Node}` monitor, `spawn_opt` options, `exit/2,3` on an internal port/foreign ref; a `{tag, Tag}` user tag is nevertheless honoured for **every** term shape (a reference included), not only an immediate or literal — G *Process-control families*, `src/native/process/monitor.rs`.

* A `run` argument token above `MAX_SMALL` (`2^59 - 1`) is materialized with `make_small` and **no range check** (`src/runtime.rs::materialize`, from `src/cli.rs::parse_arg_term`): a debug build aborts on the `debug_assert`, a release build truncates to a wrong small int — the one class the runtime forbids — G *CLI `run` argument tokens*.
* Single-threaded scheduler; a BIF-and-call-only loop ends no slice on the native tier (fairness), and an allocate-and-abandon loop is collector-bound, never arena-bound; two other load-sensitive failure shapes exist — both real exit codes, neither a signal — G *Scheduler / runner* / *A.7/A.9 boot*.

## The scheduled path and the per-BIF-call cost (read before optimizing the glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, at `RUN_STEP_SLICES` passes per round and `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS`, so per-pass costs amortize while **per-slice** costs dominate a long run; the inventory (each with its pinning test) is [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *The scheduled path's fixed costs*, with the per-workload cost in [`src/runner/MEASURED.md`](src/runner/MEASURED.md).
A registered BIF call is ≈430 retired instructions, of which this crate owns the routing (`call_bif`'s NIF → floor → memo draw, ≈83), the `BifContext` build and arm selection (≈223) and the tail (`finish_registered_call`'s copy-out, gate and rewind, ≈127) — the rest is `beam_engine`'s dispatch, `src/runner/budget.rs`'s forwarding triple, or the BIF body; the ranked levers with their owners are [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *The per-BIF-call cost, on one page*.
A handle built in `call_registered` must be gated by a `uses_*` predicate, and the `DispatchMemo` hit path, not the prologue, is what to price (`examples/perf_call.rs`).
## The Erlang stack on the runtime side (this crate's write surface)
- **No Y slot is ever built here**: the engine materializes them (`push_frame_window` `resize`s `Machine::stack` to `y_base + y_count`, and `Eterm::default()` **is** `NIL`).
- The only production writes into `Machine::stack` from this crate are the GC hand-off: `publish_roots_full` pushes `roots.stack` + the live FR prefix into the **process** root set (`src/context/gc.rs`) and `scatter_roots_full` copies the relocated words back; everything else is a read (`gather_off_heap_roots`/`for_each_parked_machine_root_mut`/`for_each_engine_census` in `src/runner/entry.rs`, `publish_nested_roots` in `src/context/pump.rs`).
- A fresh slice's stack is **empty, not pre-filled** (`Machine::new()` is `Vec::with_capacity(STACK_RESERVE_WORDS)`, `Machine::reset` `clear`s it), which is what the nested-run pool's release contract relies on (`src/context/machine_pool.rs`); no production path reads `Frame::continuation`, and execution-position items go through `Machine::{current_function,current_location,current_stacktrace,catch_frame_depth}`.

* `src/lib.rs` → crate docs, `#![deny(unsafe_code)]`, module wiring, root re-exports, `prelude`.
* `src/error.rs` → `BeamError` constructors, halt helpers, `unsupported_reason`, `live_reason_term`, `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` + its drift guard.
* `src/config.rs` / `src/cli.rs` / `src/cli/` → the A.6 config/parser/driver + the four `EXIT_*` codes; child `src/cli/start.rs` = the `-s`/`-run` argument vector (`instruction_args`).
* `src/codeserver.rs` → `CodeServer` (the **one** shared `Rc<AtomTable>`, the module cache, the **one authoritative** code-path store, `bindir()`); child `src/codeserver/path.rs` = the **release-layout derivation** — [`src/codeserver/CONTEXT.md`](src/codeserver/CONTEXT.md).
* `src/boot.rs` → `PreloadedModules` (A.7) + `CORE_ATOMS` + the banner, over `src/boot/{preloaded,bootscript,drive}.rs`; `PRELOADED_MODULE_NAMES` is the oracle's exact list and order, `CORE_ATOMS`'s tail groups are **append-only**.
* `src/port.rs` (+ `src/port/tests.rs` and the eleven siblings) → the A.4 `PortHook` provider, `{spawn_driver, Name}` routing, the completion/failure/active-input/peer-close channels, the per-port inet option mirror — [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* `src/port/driver/` → the driver C ABI host (`driver.rs`/`state.rs`/`monitor.rs`): dispatch, the drain-then-notify write path, `control`, `fire_stop_select`, the driver-atom commit — [`src/port/driver/CONTEXT.md`](src/port/driver/CONTEXT.md).
* `src/port/select/` → the runtime's **one** readiness store behind `enif_select` — [`src/port/select/CONTEXT.md`](src/port/select/CONTEXT.md).
* `src/dist.rs` → the accepting half over `dist/` (the **one** shared `DistLinks`, the inbound `LocalDeliverySink`) — [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md); `src/dist_client/` → the connecting half (handshake, signal queue, quiescence account, `DistRouter`) — [`src/dist_client/CONTEXT.md`](src/dist_client/CONTEXT.md).
* `src/info.rs` + `src/info/` → the A.8 introspection surface; `src/info/CONTEXT.md` is the per-key catalog and `src/info/snifs_atoms.rs` the static-NIF roster's atom vocabulary.
* `src/context/` → the concrete `ExecutionContext` glue — the collection doors/valves under `gc/`, the copy-out's destination containment (`calls/dest.rs`), the BIF-frontier reservation (`calls/frontier.rs`) — [`src/context/CONTEXT.md`](src/context/CONTEXT.md), `IMPLEMENTATION.md` holding the remaining seam detail.
* `src/context/send.rs` → the **one** send-destination classifier (`classify_send_destination`/`SendDestination` + `resolve_send_destination`/`deliver_remote`/`deliver_to_port`), used by all three send routes.
* `src/timers.rs` → the deadline min-heap, its `{abs,true}` window pinned to `info::time`'s `START_TIME`/`END_TIME`.
* `src/trace.rs` / `src/seq_trace.rs` / `src/crash_dump.rs` / `src/perf_map.rs` / `src/debug_trace.rs` → the observability modules (A.8) and the env-gated diagnostics — `TRACE_AND_PERF.md`.
* `src/nif.rs` / `src/nif/` / `src/nif_{select,send,monitor}.rs` / `build.rs` → the live NIF libraries (A.3), the `NifHostServices` provider, the NIF-thread host's **private** atom space, the `enif_select` arm and the `--export-dynamic` link arg — [`src/nif/CONTEXT.md`](src/nif/CONTEXT.md).
* `src/native.rs` (+ `src/native/`) → the runtime-native BIF floor, incl. `file_server_2`, the `prim_buffer` byte queues, the `prim_file` read-ahead queue and the registered `net_kernel` service — [`src/native/CONTEXT.md`](src/native/CONTEXT.md) is the dispatch index and drift guard.
* `src/eval/` → the `-eval` evaluator (`mod`/`ast`/`parse`/`scratch`/`reclaim`), the fun-application nesting budget (`nesting.rs`) and the native-stack probe (`native_stack.rs`) — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work is in **[`HANDOFF.md`](HANDOFF.md)**, one bullet per owning crate with the blocking code site: `beam_gc`'s refused-growth arena fallback (`AnyCollector::collect_young`), `beam_engine`'s `set_current_code` in the three call seams + its `MinimalContext` arena-words accessor + its `put_map_assoc` no-op short-circuit, `beam_process`/`beam_message`'s `SchedulerPool` adoption, `beam_io`'s async-port-key and monotonic-time phase residual, the nested-run depth bound, and the distribution spawn responder.
**Inbound distribution's remaining `Unsupported` families are this crate's own half, not a missing sibling API**: `beam_process` already owns the `ProcessTable` remote-reservation primitives and `beam_dist` models both opcodes, so the distributed-spawn family (`DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`, hence `erpc`/`rpc:call`) lacks (i) a sink responder decoding `{MFA, Opts, args}` into a reservation + a process install, (ii) a pending-spawn table keyed by `(peer, Ref)`, and (iii) a `DOP_SPAWN_REPLY` channel; the link driver's `Delivery::Other(_)` kill and `beam_dist`'s **local-node identity in `encode_control_cached`** are the remaining codec ask — [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md) *Missing sibling APIs*.
