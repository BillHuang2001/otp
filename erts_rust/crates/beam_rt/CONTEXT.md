# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs`, the **CLI flag surface** (**A.6**) and **`system_info/1`** + `erlang:process_info/2` (**A.8**).
It owns the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded drives (`src/boot/drive.rs`) — which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**); every CLI action but `-version` drives it before its own start instruction, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** adapting the engine's seams onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable), the **A.4 runtime side of ports** (`open_port/2` decoding, `port_info`, the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s), the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and `{abs,true}`) and a finite `receive … after T` (`src/timers.rs`, advanced only by the scheduler loop), and the **distributed node** (A.5 phases 1–2: the accepting half `src/dist.rs` + `src/dist/` — the inbound `LocalDeliverySink` in `src/dist/inbound.rs` — the connecting half `src/dist_client/`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` on the first `pump()` via `ALIVE2_REQ`); `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**).
Both halves share **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket**, and a send to a node with no link **dials it first** (`Runtime::dist_ensure_link`); our own ids are externalized on the way out (`src/dist/externalize.rs`).
A `-name`/`-sname` node also runs the native `net_kernel` service (`src/native/net_kernel.rs`), so a real peer's `net_adm:ping/1` answers `pong`.
Both inbound drives drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`), so a malformed or forged control message **retires that one link** instead of reaching the sink.
`LocalDeliverySink` routes the message and route-free receipt families through `ProcessTable`'s inbound primitives (each emitting **no** outbound `DOP_*`); only `SpawnRequest`/`SpawnReply`, `Delivery::Other(_)` and the `UnlinkId` `id != 0` ack-owing half (`id == 0` is `Delivered`) stay typed `Unsupported`, and the pass is gated by `Runtime::inbound_delivery` (default **ON**) — per-family routing table, pump budgets, the envelope rule, `NodeName::parse`/`resolve_cookie` and the `DistRouter` install site: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — precedes the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; the registry offers `new()` (anchors the `enif_*` codegen unit), `is_loaded`, `insert`, `lookup` (**the dispatch predicate**) and `call`.
All **eleven** state-needing `NifHostServices` hooks are live on a call — `make_ref`, `whereis_pid`, the two liveness answers, the port relations `is_port_alive`/`port_command`, `select` (`enif_select`'s registration/delivery half, `src/nif_select.rs` over `src/port/select.rs`'s one readiness store, so a real `pipe(2)` descriptor is armed with the runtime's own poller and `{select, ResourceTerm, Ref, ready_input}` is delivered through the ordinary send path), `send`, `local_fun_identity` and the monitor pair `monitor_process_result`/`demonitor_process` (`Runtime::nif_monitors`, `src/nif_monitor.rs`) — and only the load/unload host leaves them at the trait default.
`build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`) — [`M1_GAPS.md`](M1_GAPS_A3_NIF.md) *NIF (A.3)* is the residual ledger.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The dispatch table (the source of truth), every implemented/not-implemented BIF and the drift guard live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
**`process_info/1,2` stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form.
**`monitor/2,3`/`demonitor/1,2`, `alias/1`/`unalias/1` and the reference-alias send destination come from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed as the C's `erts_monitor_opts` (`bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias; as a **send destination** that reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams, and a `{alias,_}` on a **port** monitor or a **remote** target propagates the typed `unsupported` (`tests/alias.rs`).
**`erlang:garbage_collect/0,1` come from the floor** (`src/native/erts_internal.rs`, A.7): **no BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet`, which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`, served only where the root set is owned (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first.
**`code:*` reads and the code path are the floor over `CodeServer`, alongside a live `code_server` process** (started by the booted `kernel_sup` on every boot-driven route; `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7), so the `boot/*` cases touching `code:*` are **shape-only**). The floor owns the **one** authoritative path store for the path readers **and** the mutators `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1`; the un-migrated mutators edit the live server's second, floor-invisible store, so **`src/native/code.rs`'s `code:*` behaviour must not change** (store rule, key list and `code:ensure_modules_loaded/1`'s rationale: `src/native/CONTEXT.md`).
**Every name-based load ends at `CodeServer::load`'s expected-module-name check** — the C's `check_module_name` (`beam_load.c:185-187`), run before caching, so a `<M>.beam` that really holds another module is the oracle's `{error,badfile}` (`{error,[{M,badfile}]}` from `ensure_modules_loaded/1`) and is cached under neither name, on `code:load_file/1`, `ensure_loaded/1`, `ensure_modules_loaded/1`, the boot script's `{primLoad,…}` and the on-demand external-call load alike; `CodeServer::load_path` (the CLI `run` route and the slice fixture) keeps own-name semantics.
**`erlang:delete_module/1` is served** beside the `check_old_code/1` arm (non-atom ⇒ `badarg`, a name the store does not hold ⇒ the atom `undefined`, a held one ⇒ a real `CodeServer::forget_module` unload and `true`, the code server surviving), with `code:purge/1` ⇒ `false` and `code:soft_purge/1` ⇒ `true` from the floor (this runtime has no old-code slot), and `erts_internal:purge_module/2` is the oracle's own `error:notsup` — `M1_GAPS.md` *The code store* / *The expected-module-name check on every name-based load route*.
**The A.9 installation view is catalogued in `src/native/CONTEXT.md`**: `init:get_argument/1`'s four automatic flags (`root`/`home`/`progname`/`bindir`), `init:script_id/0`, `code:lib_dir/2`, the `application` view and `erlang:module_loaded/1`'s truthfulness to *this* runtime's loaded set (so `module_loaded(kernel)` stays `false`).
**Three server processes are native state, not scheduled code**: the root process (registered as `init`), the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) and the **`erl_prim_loader`** stand-in (`src/runtime.rs`, A.7/A.9) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery work and `erlang:whereis(erl_prim_loader)` answers a live pid on **every** route (nothing in `bootstrap/bin/start.boot` claims it). The `file_server_2` service is spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus `-boot FILE`), so the booted `kernel_sup`'s own child owns the name; `Runtime::new` registers it only when the runtime drives none.
**`erlang`-namespace fallback**: `call_bif` consults the floor, then the registry, then the `erlang` namespace — a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`; `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (intersected with what the live registry does not own) and its drift guard are the authority.
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **two** built-in key sets — `prim_tty`'s 20 stub keys and `zlib`'s 19 stream keys — answering from a module-name equality short circuit followed by a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`, with `local_fun_target` declining such a target) serves the **record-held** shape of the same two sets: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body.
The `zlib` stream API is therefore live end to end through the real preloaded `zlib.beam` — `open/0` … `close/1` — and oracle-identical at every level 0–9, pinned by `tests/zlib_stream_levels.rs`, `tests/zlib_stream_dict.rs`, `tests/zlib_guards.rs` and `tests/zlib_one_shot.rs` (**29** tests, 27 of them oracle-cross-checked and 2 golden self-consistency checks that need no `erl`).
`set_controlling_process/2` carries **no** stream-state precondition (the C's `set_controller_nif` validates arguments, checks ownership, overwrites the pid), so a closed, an ended and a fresh stream all answer `ok` on both runtimes — `tests/zlib_guards.rs::setting_the_controlling_process_on_a_closed_stream_agrees_on_every_route_and_tier`.
Per-module detail: `src/context/CONTEXT.md` (both indirections), `src/native/CONTEXT.md` (`prim_tty`), `../beam_bifs/src/zlib/CONTEXT.md` (the 19 keys).
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`/`src/dist/`, the connecting half in `src/dist_client/`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar: the Erlang **expression** subset (`src/eval/{parse,ast,mod}.rs`) walked `erl_eval`-style, its arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**), and a **quoted atom** a distinct `Tok::QuotedAtom` (an atom that merely *spells* a keyword — `'receive'`, `'end'`, `'not'` … — is a plain atom, and a quoted call head is an ordinary call).
  Outside the grammar is a **capability gap** (exit 3) — the grammar, the quoted-atom rule and the named-fun-form rejection: [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2.
  `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2).
  **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`).
A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call.** `BeamError::Raise` carries an `ExitReason::Atom` as a **name**, and the engine can only land such a raise in a catch frame when its `atoms()` namespace resolves the name (`beam_engine/src/interpreter/bif.rs`'s `raise_error`); a name nothing has interned therefore escaped every `try … catch`. `src/context/calls.rs::name_raise_reason_atom` closes that on the **one** funnel every failed call passes (`call_bif`'s error arm): it appends the reason atom to the shared table (append-only, at `PendingInterner`'s predicted index, via `CodeServer::intern_pending`), so a module that never spells the atom still catches `error:R` exactly as the oracle does — the shape a `zlib` guard (`not_initialized`, `stream_error`, `already_initialized`, `not_on_controlling_process`) raises. Deliberately **not** interned: a capability gap (`crate::error::unsupported_reason`) — which is what keeps exit 3 uncatchable — and any reason with no nameable atom.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason).
So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` exceeds the 60-bit small range, so it materializes as a bignum); `context_reductions` is answered as `4000`, the canonical ERTS quantum `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented.
  The pre-existing (not restructured) oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md) *File-size overages*.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle.
  When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer; flattening is the **last resort** for an unresolvable payload, never a substitute for adopting handles (the send path unions three source families, `src/context::send_source`, so a resolvable payload takes the SHARE route).

* **A `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work, not `beam_rt`'s dispatch** — the wired path is allocation-free and the atom-intern commit is append-only — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **No interactive shell** — no Erlang-level distribution subtree runs (`net_sup`/`auth` stay `undefined`; the distribution is this crate's native `DistNode` plus the `net_kernel` service), and the inbound message/link/exit/unlink/monitor/demonitor/monitor-down/group-leader families route through `beam_process`'s **route-free receipt** primitives, never echoing a `DOP_*` — [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md) *Known A.5 gaps and residuals*.
* **An inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** (an immediate-only, uncopied, unrooted slot) — a typed divergence from the C — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order (compared as a set), and `badarg` for a module not loaded here — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures (`whereis(init)` **does** agree) — `M1_GAPS.md` *Own-state answers*.
* **`process_info(P, binary)`** reads the target's engine reservoir as the oracle's `{Ptr, Size, Refc}` tuples (`[]` when none), so it follows the reservoir's pre-emption-arm prune, while `erlang:memory(binary)` is the separate `binary_alloc` live-bytes figure — `M1_GAPS.md` *`process_info/1,2`*.
* **Process-control gaps** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id — `M1_GAPS.md` *Process-control families*.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual is `ets:setopts/2`'s gift-data aliasing — `M1_GAPS.md` *ETS ownership*.
* **`process_info/1,2`** answers ~28 items from real state (`message_queue_data, off_heap` is accepted-and-ignored); `port_info(Port, monitors)` stays `[]`, matching the oracle; a non-byte-aligned `-eval` result (or a container past ~80 columns) cannot be printed by the registered `io:format` `~w`/`~p` printer — `M1_GAPS.md` *`process_info/1,2`* / *Port monitors (A.4)* / *Printing*.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget** (a refusing `BudgetProbe::charge` plus a pricing, never-refusing `BudgetProbe::spend`), and the residual is that a non-allocating BIF-and-call-only loop ends no slice of its own on the native tier — [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Known Issues*, `M1_GAPS.md` *Scheduler / runner*.
* **`process_info(P, garbage_collection)`'s `minor_gcs` is `Collector::minor_since_major`, NOT a collection total** — every fullsweep resets it to `0`; the monotone totals are `Runtime::gc_stats().collections` and `beam_gc::AnyCollector::stats()`.
* **An allocate-and-abandon loop is collector-bound, never arena-bound** — a flat `heap_size`/`erlang:memory(processes)` is a **converged capacity**, the collector's per-iteration Cheney traversals *are* the per-op cost, and every per-iteration rate is a **measured table, never a closed form** — [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*.
* **Execution tier defaults to `JitMode::Auto`** (`src/runner/tier.rs`) — the native baseline tier for every process entry, compiled **lazily per function** on first entry of a `(func, pc)`; `BEAM_RT_TIER` overrides it (`interpreter` is the kill switch) — [`PERF.md`](PERF.md), `M1_GAPS.md` *Execution tier*.
* **CLI divergences and subset gaps** (`-smp disable` accepted, `-setcookie` unmodeled, the `-eval`/`-s`/`-run` subsets) live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
* **NIF loading is live** (`load_nif/2` really `dlopen`s); every `NifHostServices` hook is live on a call and only the load/unload host leaves them at the trait default; a compiled module's local fun encodes faithfully, an `erl_eval` lambda stays `unsupported: local_fun` — [`M1_GAPS_A3_NIF.md`](M1_GAPS_A3_NIF.md), `M1_GAPS.md` *Funs*.
* **A socket's `{active, true|N|once}` input is delivered as the oracle's own messages** — `{tcp,S,Data}` / `{udp,S,{A,B,C,D},Port,Data}` / `{tcp_passive,S}` / `{udp_passive,S}` / `{tcp_closed,S}` / `{tcp_error,S,Reason}`, `Data` binary or charlist per the port's effective `mode`, the `{packet,N}` header stripped and the datagram source decoded big-endian out of `beam_io`'s packed address — to the **owning** process through `beam_io::PortRegistry::take_active_inputs`, drained at the same six points as the completion channel and delivered through the ordinary mailbox path (so a blocked receiver is woken); an **accepted** socket inherits the listener's option block (`{packet,…}`/`{packet_size,…}`/`{header,…}`/`{mode,…}`/watermarks/…) through the C's `tcp_inet_copy` record replay, while `{active,…}` is left to `prim_inet:accept_opts/3` exactly as the C does.
* **Ports match the oracle's observable shape** — one `{Port,{data,Data}}` per driver read at the width the child wrote, stderr inherited or merged under `stderr_to_stdout`, `connected` false only at `port_close/1`, the `line`/`{line,N}` stream option adopted end to end, and `port_command/2,3` running `beam_io`'s decision table (`[force]` refused as `notsup` without the driver's `SOFT_BUSY`, honoured with it, a busy port waited out in bounded scheduler rounds then re-issued, `false` for `[nosuspend]` with nothing queued; the busy/`[force]` test taken **before** the iodata is converted) — [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **A driver that closes its own port is a full closer** — `driver_failure*`/`driver_exit` run `PortRegistry::close`'s teardown, so the owner and every monitor get the failure's **own** reason while `driver_exit` sends the linked owner nothing, the port is as gone as a closed one, and a read the failing callback wrote is delivered first (pinned by `tests/port_failure.rs`: 10 tests, 9 oracle-cross-checked) — [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md).
* **The send family** serves `erlang:send/2,3`/`erlang:'!'/2`, including a **reference-alias**, a **remote** destination and a **port**; an unreachable remote destination stays a typed gap, and the BIF route cannot see the sending machine's in-flight refc-binary handles, so a term the machine *just* built off-heap **flattens** — [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md), [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *Known Issues*.
* **Reference aliases: the honest residuals** — a send to a reference that is **not a live alias** is the typed `badarg` (the C silently drops it), `monitor(process, self(), [{alias,_}])` registers where the C clears it, and the **unclosable residual** is reference **identity** (a bare reference and a monitor/alias reference with equal ids are `=:=`, closing which needs the two allocators unified) — `M1_GAPS.md` *Reference aliases*, [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **Driver ports (A.4) load and drive a real C driver end to end**, with **32 of the 43** `DriverHost` hooks live; the monitor view is a **per-round snapshot**, and the typed gaps are `driver_async`, a `control` reply from the driver's own memory, a `NULL` reply with `PORT_CONTROL_FLAG_BINARY`, a driver arming **more than one** registration per direction, and a non-UTF-8 `driver_failure_atom` name.
  **A driver port owns no OS child, and that is a fact rather than a gap**: `[exit_status]` is refused with `badarg` before a port id is consumed, `{exit_status,N}` cannot exist (its only reporter is not declared in `erl_driver.h`), and `port_info(Port, os_pid)` is `undefined` until the driver's own `erl_drv_set_os_pid` — both pinned against the oracle by [`src/port/exit_status_matrix_tests.rs`](src/port/exit_status_matrix_tests.rs) — [`M1_GAPS_A4_PORTS.md`](M1_GAPS_A4_PORTS.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **`erlang:send_after/3`/`cancel_timer/1` are native-floor capabilities**; `/4`, `/2`, `start_timer/3,4` (incl. `{abs,true}`), `read_timer/1,2` (what makes `inet:timeout/1` and `gen_tcp:connect/2,3,4` work), `function_exported/3`, `link/1`/`unlink/1`, `os:set_signal/2` and `erlang:delete_module/1` come from the `RuntimeHooksBridge`, while `erlang:system_info/2` and every other `RuntimeHooks` key it does not serve are unimplemented — `M1_GAPS.md` *Timers*.
* **The runtime drives `beam_gc` at four collection points, three of them heap-admission doors** (`src/context/gc.rs`, reached only where *code* allocates) plus the reduction/yield-boundary door (`src/context/gc/reds_door.rs`, from the runner's `Yield` arm). A float-family module is collected over **only** at the two full-root doors, a failed collection halts that process's collection rather than failing the program, the **term-heap capacity is the hard limit** for anything not collected, and on-demand growth is adopted at both doors and on the message-delivery path.
  The **boundary door** is what makes a BIF-only loop collectable (a **7/8** young-space occupancy watermark, the machine's **whole** `RootSet` published, young-only first then escalate on that minor's typed heap exhaustion); on the **default (native-baseline) tier it is unreachable** — a natively linked block crosses neither the reduction hook nor an admission door — a fairness defect as much as a GC one; every fire count and per-N rate is a **measured table, never a closed form** — `M1_GAPS.md` *GC / heap model*, [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*.
* **The unscanned-root valve declines a collection only where relocation is genuinely unsafe** — `root_is_unscanned` is a **two-fact** predicate (an **unscanned** region **and** at least one **scanned** pointer forwarded), so a foreign all-immediate block or a null/unaligned word is **inert**; the per-pid latch is cleared only from the doors that hand the walk the machine's **whole `RootSet`**, never by the narrow `ensure_heap`, the park arm, the off-heap prune or the `RuntimeCollectionGate` — `M1_GAPS.md` *GC / heap model*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
  Consequences: a reference-minting loop keeps `erlang:memory(processes)` **flat** (6.91 MB at N = 20 k / 200 k / 1 M, below the oracle's 13.7 MB) and a loop holding a **registered-BIF result container** live still collects, the copy-out putting the held container on the process's own **scanned** young heap (`tests/foreign_root_loop.rs`).
* **The engine's off-heap refc-binary reservoir is PRUNED at every pre-emption, not accumulated** — `Machine::refc_binaries` holds payloads outside every heap the collector owns, and the runner's `Yield` arm reclaims every payload its just-published roots no longer reach once the **binary virtual heap** triggers.
  The release moves nothing (a retained payload keeps its `data_ptr`), the **prune-only** valve is strictly stronger than the collection one, and every gate is a **decline** — the residual is a **leak, never a dangle**.
  Mechanism, valves and residuals: [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *The off-heap refc-binary reclamation*; the call site and its per-slice cost: [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *The off-heap refc-binary reclamation at the slice boundary*; the measured envelope (reservoir, fun-loop and end-to-end ladders, the A/B and the anti-dangle half): [`tests/CONTEXT.md`](tests/CONTEXT.md) *The off-heap refc-binary reclamation measurements*; its effect on `emqx_base62:encode/1`: [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*. `erlang:memory(binary)` is `binary_alloc`'s live bytes, so it reflects a release; `erlang:process_info(P, binary)` is the per-process roster.
* **The runtime's escaped-payload store (`Runtime::eval_off_heap`) is PRUNED at two points** (`src/eval/reclaim.rs`): the `-eval` driver's depth-0 statement boundaries and the nested-run epilogue that adopts a finished nested `Machine`'s handles. No eval root lies in a scanned region, so the prune is its own region-agnostic reachability walk; refusal is **doubt ⇒ decline** (an exhausted walk budget, an unknown boxed header) plus a `refcount() > 1` belt, and the trigger is O(1).
  The nested point prunes only the handles **its own run adopted** (sweeping the whole store there corrupts live data), so a payload an earlier run built is retained for the store's lifetime, a bounded leak; the store is not pid-attributable, so no per-pid off-heap-binary figure is published from it — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md), [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **The NIF-resource prune (the reference an `enif_make_resource` term owns) runs at three sites, on one shared reachability descent** — the runner's `Yield` park arm (the one point with a published *complete* root set) and the two **non-park** sites (`src/eval/reclaim/resource.rs`, needed because the `-eval` action process is never enqueued and so never parks), which release only candidates minted **inside their own window**; the steady state is **O(1)**.
  Every gate declines to *retain everything*, so the residual is always a bounded leak, never a destroyed live resource, and its completeness depends on `Runtime::gather_off_heap_roots` covering every store that can name a resource. The **identity match is imprecise** at every site (a plain reference with a colliding id retains a dead resource — a leak, never a dangle; the closure is a `beam_abi` change) — [`M1_GAPS_A3_NIF.md`](M1_GAPS_A3_NIF.md) *The resource-identity collision*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *The NIF-resource-term prune (A.3)*, [`PERF.md`](PERF.md) *The NIF-resource prune's two non-park sites*.
* **`erlang:memory/0,1` are adopted**; **`erlang:statistics/1` is partly served** (its `garbage_collection` key carries the runtime's **real** node-global counters, with the per-scheduler/msacc keys and `statistics/0` typed gaps); **the heap switches are modelled** — `+hms`/`+hmbs`/`+hmax*` land on the process's `beam_gc::HeapPolicy` (CLI **and** `spawn_opt`), observable through `process_info(P, max_heap_size)`/`system_info(max_heap_size)`; `+hmax` does **not** bound the growth-retired nursery **chain** (a `beam_gc` handoff) — `M1_GAPS.md` *Memory and statistics* / *Heap switches*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *GC accounting*.
* **`max_heap_size` is ENFORCED, end to end**, on the **prospective post-collection capacity**, never occupancy: one shared parser serves `process_flag(max_heap_size, Map|Int)` and `spawn_opt`'s map form, the whole setting (flags included) lands on the PCB, and a breach becomes the ERTS `=ERROR REPORT====` block plus a `Kill` latch the runner turns into a bare-atom `killed` exit (`{'EXIT',Pid,killed}`/`'DOWN' … killed`).
  Residuals, pinned: the report goes to **stderr** with the bare header where the oracle's `logger` writes to stdout with a timestamp; **7 of the C's 9 fields** (never fabricated); a latched `Kill` is performed at the runner's **next slice boundary**; the `-eval` action process is never enqueued, so a verdict latched there is never drained; and `+hmax` does not bound the growth-retired nursery **chain** — `tests/max_heap_enforce.rs` (12 oracle-cross-checked cases), `tests/max_heap_flag.rs`, `M1_GAPS.md` *Heap switches*.
* **`+hmax` bounds user processes, never the runtime's own boot processes** — boot-spawned processes get an uncapped policy inside the `Runtime::booting` window, while the action process and `erlang:spawn*` children keep the user bound, so a genuine over-cap allocation on the `-eval` route reports `beam_rt: system_limit` (exit 1). Residual: at `+hmax ≤ 1024` the boot's own **term construction** still fails and `src/boot/drive.rs` maps it to `blocked()` → exit 3 — `M1_GAPS.md` *Heap switches*.
* **A.9 self-hosted compile: the full *chain* runs in ONE invocation** (`tests/selfhost_chain.rs`) — **772 sources / 34 apps**, of which the oracle itself compiles **755**, and all **755** are byte-identical, 0 in-process failures, 0 over the 900 s bound. **No full self-hosted build** yet — [`HANDOFF.md`](HANDOFF.md) *A.9 E0* (the ledger, the narrowed single-source run, the corpus' parallelism hazard and the staged `#[ignore]`d chain), [`EPP_SCHEDULED_ROUTE_FINDINGS.md`](EPP_SCHEDULED_ROUTE_FINDINGS.md).
* **There is no io server; the `io` device floor serves the request wrappers**, so the installed compiler's `catch`-handler diagnostics surface; residuals: a live non-stdio device pid is the typed `unsupported`, and `io:put_chars/1,2` accepts-and-ignores its device — `M1_GAPS.md` *Printing*, [`src/native/CONTEXT.md`](src/native/CONTEXT.md) *The `io` device floor*.
* **A process entry naming a host-served MFA is dispatched, never entered as that module's code** — `ProcessEntry::Export` asks `RuntimeContext::host_serves` on its **first** entry only and runs a hit through `call_bif`, while a resolvable module's export keeps the label route — pinned by `tests/bif_entry_spawn.rs` and `src/boot/bootscript.rs`'s dispatch case — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every `foreign` case's per-call cost is flat in N**: the machine's reservoir is never mirrored onto the process's never-compacted off-heap slots — a slot per payload per slice is what would make the cost grow in N; the residual is dispatch/heap-management at matched N, and the literal-area-tagging / valve / nursery-chain mechanism is not a per-call term either — [`PERF.md`](PERF.md) *off-heap mirror*, `M1_GAPS.md` *`process_info/1,2`*.
* **Placeholders where a truthful source exists** — `NodeIdentity`'s **creation** is a fixed `0` (the node atom itself is the runtime's live `Runtime::local_node()`), and the flag-driven `system_info` literals report their defaults because no CLI arm preserves the driving flag — `M1_GAPS.md` *Placeholders*.
* **A booted runtime leaves a live `logger_server` registered as `logger`** — a second `logger_server:start_link/0` reports `{error,{already_started,Pid}}`, matching the oracle — and the script's tail blockers are served **in-node** from the native floor or runtime state — [`HANDOFF.md`](HANDOFF.md) *A.7/A.9 boot*, [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md), [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **A registered-BIF result is re-homed and the pool rewound** (**load-bearing**: the copy makes it collectable) — onto the process heap, else the table-less (`-eval`) store; residuals — a NIF result, an escaping `DispatchHooks` arm and an error leave their container on the pool, and the copy-out cannot collect — while the store's own growth is bounded by the per-statement window — `M1_GAPS.md` *The BIF-result copy-out* / *The `-eval` store's statement window*, [`src/context/IMPLEMENTATION.md`](src/context/IMPLEMENTATION.md) *The table-less arm and its store*.
* **The copy-out learns a payload's size and grows the nursery *before* copying**, which makes the *successful first attempt* the common path instead of a refused attempt plus a five-traversal sizing walk; `hint == 0` reproduces the refusal path exactly (a fresh empty destination table per attempt, the permanent-non-exhaustion short-circuit, `safe_to_rewind`, and the `max_heap_words` ceiling's bare-shortfall fallback). Measured: `copy_bound/ets_copy` **0.605×** on a paired A/B, refusals 0.332 → 0.003 per op — [`PERF.md`](PERF.md) *The copy-out's learned size hint*.
* **The scratch-heap lifetime defect this class of failure needs is closed, and pinned** — `erlang:system_info/1` hands its value off the reset-per-call scratch region (a rewind that refuses to recycle a region a live term may occupy, plus a copy-out of the value handed to Erlang code), so a retained value is sound (`tests/system_info_retained.rs`) — `M1_GAPS.md` *The scratch-heap lifetime and the dangling-boxed-argument class*.
* **`beam_term::ops::class`'s `invalid boxed header subtag 0x39` abort has no reproducer left** — a dangling boxed argument, never a classifier gap, and its mechanism is gone — `M1_GAPS.md` *The scratch-heap lifetime and the dangling-boxed-argument class*.
* **Two other load-sensitive failure shapes exist — both real exit codes, neither a signal.** A CPU-starved boot drive trips `DRIVE_DEADLINE` (`src/boot/drive.rs:85`, 10 s) → `beam_rt: error boot script: the scheduler was still runnable after 10000 ms`, **exit 1** with empty stdout (measured: 60 hogs on one core → wall 13.3 s, exit 1; 30 hogs → 8.9 s, exit 0); and a scheduled round trip that cannot pump inside a slice folds into the typed `blocked()` gap → **exit 3** `unsupported: run: process blocked (no message available)` (`src/context/pump.rs::pump_once`, `../beam_engine/src/error.rs:75-77`).

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate and the differential gate.** The commands, the `#[ignore]`d-harness rule, the authoritative-gate rule and the gate-equivalent full-corpus sweep with its two pitfalls are in [`TEST_STRATEGY.md`](TEST_STRATEGY.md) *Running the suites and the gates*; the hygiene rules (one `scratch_dir` source, oracle-order failure sets, the fixture `lists.beam`, a probe that must terminate) are its *Test hygiene* section.
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script): the 22 preloaded `.beam`s load even for a self-contained module with an explicit `-pa DIR`, and the system code path is resolved natively from the filesystem — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*.
* **Whole-process startup is a measured ≈0.34 s wall / ≈0.33 s CPU (release) with 0 `clock_nanosleep`, and the boot path issues 927 filesystem stats.** The figures, the filesystem-stat breakdown and the imminent-only poll budget that keeps the boot path's live-but-idle `inet_gethost` child from costing wall time are in [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *Measured: startup cost and the poll budget*, [`PERF.md`](PERF.md) *The boot path's one live-but-idle port, and the poll budget*.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates — `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as such a stub, so any key the floor and the registry do not serve **raises** (exit 1) for *every* argument; registering the key can only change exit 1 → 3.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch and copy-out cost are first-class concerns** — the `uses_*` gating + 8-slot dispatch-memo rule, the measure-with-`perf_call`-before-and-after procedure (`perf_bif`'s inlined `pc:*` loop **cannot** measure registry dispatch), the **149 ns/call** copy-out with its `binary_to_term/1` 508 ns decomposition (82 + 218 + 149 + 59) and why it is architectural rather than slack, and the hash-free reference walk — [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md) *Performance measurement*, [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *DISPATCH-CUT* / *COPY-OUT-CUT* / *WALK-CUT*.
* **`erlang:statistics/1` is a `RuntimeHooks` key, so its container result is never re-homed onto the process heap** (`call_registered` sets `safe_to_rewind = false`): the tuple stays in an unscanned region — inert under the valve unless it forwards a *scanned* word. `DEFAULT_HEAP_WORDS` never causes a zero collection count: it sizes the runtime's **term-construction** heaps (BIF pool + `-eval` heap, `term_heap_words`), while a process nursery comes from `heap.policy()` (`min_heap_size` 233 → first `heap_size` 843) — `M1_GAPS.md` *The BIF-result copy-out*.
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`**, over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`): the served `prim_file:*` roster is the authoritative [`src/native/CONTEXT.md`](src/native/CONTEXT.md) *`prim_file:*`* (**35** entries — the **16**-entry figure beside it under-counts the fd half), the unclaimed rest falls through to `prim_file.beam`'s `erlang:nif_error(undef)`, the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service wherever it owns the name, the io-device read path is complete (`tests/io_scan.rs`) and `os:set_signal/2` comes from the `RuntimeHooks` bridge — [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **The unscanned-root descent's remaining cost is its *invocation count*, not its visited set** — the per-walk visited table is near-optimal (1.25–1.45 probes/insert, ~5 grows over a whole `pool.erl` compile), so cutting the invocation count and the caller's per-edge `root_is_unscanned`/`for_each_child_slot` cost is `src/context/gc.rs` / `beam_engine` policy; the per-walk **allocation** is gone (`WalkScratch`), and the per-pid latch is **closed only by the three whole-`RootSet` doors** on `ValveVerdict::foreign_free`, never by the park arm or a signal gate (`gc_walk.rs`'s module docs, [`src/context/CONTEXT.md`](src/context/CONTEXT.md)).
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call instead of re-entering the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`) with `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000` (`beam_process`), so per-pass costs amortize ×1000 and **per-slice** costs dominate a long run.
The measured per-pass / per-slice / per-round inventory — the fresh `ProcessTable` per pass, the progress-aware pass wait (a ready `run` issues **0** `clock_nanosleep`, a parked `receive … after T` is still slept to), the per-slice machine/context/timer churn, the `crate::hasher` word-mixing maps, the occupancy short-circuit and per-round drains, each with its `file:line` and its pinning test — is in **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, as is the per-workload cost of that path ([`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*); the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.
