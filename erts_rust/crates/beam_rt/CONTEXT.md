# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture. It owns:
* `main.rs` and the **CLI flag surface** — contract **A.6**;
* the **boot sequence** — all 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`) plus the OTP boot-script reader/executor (`src/boot/bootscript.rs`) — contract **A.7**;
* **`system_info/1`** + `erlang:process_info/2` — the runtime introspection surface, contract **A.8**;
* the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid (the key deliverable);
* the **A.4 runtime side of ports**: `open_port/2`'s `Name`/`Options` term decoding + `port_info` over `beam_io`'s registry and poller, **and** the driver C ABI host (`src/port/driver.rs`) that `dlopen`s a real C driver `.so` and drives its callbacks (the child/driver lifecycle is `beam_io`'s);
* the **runtime-local timer deadlines** behind `erlang:send_after/3` **and** a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
* the **distributed node** (contract **A.5**, phase 1 — `src/dist.rs`): the bound distribution listener, the best-effort `epmd` registration and the server-side `'N'` handshake, which **completes** against a real OTP peer.

This crate is the vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` makes the same thing happen through the real glue and the executable end to end (`Runtime::run_function`/`run_module`).

It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`. Legacy C ground truth (read-only) lives under `../../erts/` (the file list is in the Routing Table).

## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)

### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, dist) and the scratch `info_heap`.
The **scheduler-pass family** — `run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`run_scheduled`, the shared pass body, the wake absorption and the port/timer/distribution halves — lives in the child [`src/runtime/scheduler.rs`](src/runtime/scheduler.rs) (+ its `tests.rs`); every entry point is still an inherent method on `Runtime`.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (A.7: loads the 22 preloaded `.beam`s for real, idempotent), `boot_from_script(path)` (A.7: read + execute an OTP `{script,…}` boot script), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (returns x(0)), `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` — loads the file (cached under its **own** name), `spawn_process`es the export (reusing that cached module, so no code-path search) and pumps the **full** scheduler in **bounded** steps (`RUN_STEP_SLICES` = 1000 slices, `TimerWait::AtMost(PORT_POLL_SLICE)`) until the process returns (its `x(0)`), **raises** (the original `BeamError` is returned via `take_process_error`), is quiescent (empty run queue + no live port + no pending timer ⇒ the single-pass `beam_engine::blocked` diagnostic, so a bare `wait` keeps its fast answer), or outlives the wall-clock `RUN_DEADLINE` (60 s, an honest "did not terminate" diagnostic). `pub(crate) take_process_error(pid) -> Option<BeamError>` recovers the raise the runner recorded, so the CLI's `unsupported_reason`/`halt_status`/`reported_reason` classification (an `unsupported` MUST stay exit 3) is byte-identical to the single-pass path. `RuntimeContext::enter_module(module)` gives a scheduled process its call-site module (the engine's `run_export_outcome` path does not set it), so `erlang:load_nif/2`, the records bridge and `LocalFunIdentity` behave the same in both paths.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (the `spawn/1` fun path), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)` (the reason term once raised), `run_queue_len()`; the run/pump entry points are in `scheduler.rs` (`run_scheduler` never hangs — send→wake→resume in one call).
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)` (the `~p` printer).
* **timers/dist accessors**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()` (`node@host`, `None` when not a node); the scheduler side — `fire_due_timers` (delivers due `send_after/3` messages, queues fired finite `receive … after T` resumes), `note_fragment_wake` (the heap-fragment wake list), `pump_dist` — is in `scheduler.rs`.

### `runner.rs` — the `beam_process::ProcessRunner` (the scheduler's execution seam)
`RuntimeRunner<'a>{runtime, state}` implements `beam_process::ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v`, `Exit(normal)`; `Wait{func,pc}` → park + `Waiting` + `Wait`; `Err(e)` → record the reason term in `RunnerState::exits` and the original `BeamError` in `RunnerState::errors`, then `Exit(<reason term>)` (never panics). `RunnerState` holds an engine per pid plus the `results`/`exits` maps. A `Wait` also **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`parked_receive_timeout`/`timeout_delay`: an `Operand::Integer`/`Literal` or a still-live X-register): the handle lives in `ProcessEngine::parked_timeout`, a fired deadline resumes the process at the `timeout` instruction with no message delivered, and a message-wake cancels the handle.

### `context/` — the concrete `ExecutionContext` (the glue module: `mod.rs` + `bridges.rs` + `fun_identity.rs` + `tests.rs`, plus the test-only `test_support.rs`)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink` is a cloneable `Rc<RefCell<..>>` handle; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler` and `current_module`. Methods: `new`, `with_output`, `heap_available()`, `for_process(runtime, table, pid)` (runs **as** that pid — the scheduler seam), `pid()` (the mailbox owner / `self/0`), `pub(crate) eval_heap()`, `enter_module(module)`, `run_export(module, function, arity, args)`.
`impl ExecutionContext`:
* `call_bif` → `try_call_nif` → `try_native` (the floor) → `BifRegistry::contains` → `call` (a `BifContext` over shared atoms / pooled heap / self_pid / output / `PendingInterner` + a `RuntimePorts` + a `NodeIdentity` + a `FunIdentityBridge` + exactly ONE of the FIVE bridges); else `module=="erlang"` → `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef`; else load the module file → `code_server.load` → `run_export`. The three borrow-free riders + exactly **one** bridge are the only place the engine's seam meets the Stage-5 core (keeps the DAG acyclic).
* `apply_fun` → external `fun M:F/A` via `call_bif`; `-eval` closure (`EVAL_FUN_UNIQ`) via `apply_eval_closure`; else the module's `FunDescriptor{uniq,index}` then `Machine::run_label`.
* `ensure_heap` → `heap_available() >= heap_need` else `BeamError::SystemLimit` (no GC).
`send_message` copies into the receiver's heap (`ProcessTable::deliver_simple`); a payload larger than that heap retries through the **heap-fragment** model (see Design Decisions).

### The five host-seam bridges (`context/bridges.rs`), the two borrow-free hooks, and the local-fun identity (`context/fun_identity.rs`)
`call_registered` installs exactly **one** of five bridges (each needs a borrow the others cannot co-exist with), selected by its own `uses_*` predicate; the two **borrow-free** hooks (`NodeIdentity`, `FunIdentityBridge`) ride alongside **every** arm:
* **`NifBridge`** (`beam_bifs::NifLoader`; `("erlang","load_nif",2)`) — checked **before** the filesystem, so a second `load_nif` for a module that already has a library is `NifLoadError::Reload` (the oracle's rule since OTP 20); a load failure is mapped variant-for-variant by `map_load_error` and **returned**, never raised.
* **`RecordBridge`** (`beam_bifs::RecordSource`; `("records","get_definition",2)`) — answers from the **loaded module's** `Recs` chunk (`Module::record_by_name`), each field atom name-resolved through the module's own atom table. An unloaded module or an undeclared record ⇒ `Ok(None)` ⇒ the oracle's plain `badarg` (C: `erl_record.c:1342-1403`); an unresolvable field atom is a typed `TermNotFound`.
* **`DictBridge`** (`beam_bifs::DictHook`; the five process-dictionary BIFs) — over the **running process's** `beam_process::Dict` (the scheduler pass's table, else the runtime's); a missing pid is `error::no_mailbox`, never a panic.
* **`FunBridge`** (`beam_bifs::FunCaller`; every other call) — delegates to the **existing** `RuntimeContext::apply_fun` over `&mut Runtime`; carries a clone of the caller's `SharedSink` (a nested `io:format` reaches the caller's sink), the mailbox identity, the scheduler-pump permission and `current_module`, and **no** `TableRegistry` (installed **only** for a call that cannot apply a fun argument).
* **`SendBridge`** (`beam_bifs::SendHook`; `("erlang","send",2) | ("erlang","!",2)`) — one `beam_bifs` impl (`beam_bifs/src/proc.rs`) delegating to the **existing** `RuntimeContext::send_message` → `ProcessTable::deliver_simple` (delivery is never re-implemented). Matched to the oracle: the return value **is** the message term; a send to a pid with no process succeeds silently (`do_send` folds `TermNotFound` into success); a non-pid-like destination is `badarg`; a registered name is delivered. So **`erlang:send/2` and `erlang:'!'/2` are served**; the compiled `Dest ! Msg` operator still uses the `send` instruction.
* **`NodeIdentity`** (`beam_bifs::LocalNode`; every arm) — the fixed local node `(nonode@nohost, creation 0)`; feeds `beam_codec`'s `Encoder::with_local_node`, so `term_to_binary/1` of an **internal** pid emits `NEW_PID_EXT` (`88`) and of an internal port `V4_PORT_EXT` (`120`).
* **`FunIdentityBridge`** (`beam_bifs::LocalFunIdentity`; every arm) — the `NEW_FUN_EXT` (`112`) identity of a **compiled module's** local (`make_fun3`) fun, which the term does not carry. A fully **owned snapshot** (the caller module's `Arc<Module>` + source `.beam` path + the node atom), so it holds no runtime borrow and can be installed while the runtime is mutably borrowed by `FunBridge`/`SendBridge`. Its `local_fun_identity(term)` answers `Ok(None)` — never an error — for a non-local-fun argument, a context with no calling module (the `-eval` evaluator), and an unreadable/unparsable `.beam`; otherwise it derives the identity (`bridges.rs`'s `local_fun_identity`/`module_md5`: module atom + module MD5 + `old_index`/`old_uniq` from the module's `FunT` + the fixed `<0.0.0>` creator), so a compiled module's closure encodes byte-exactly like the oracle.

### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` is `Clone` over `Rc<RefCell<{ base: usize, names: Vec<String> }>>`: `new(base)` roots it at the shared table's length before the call, `commit(&AtomTable)` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers). `load_nif/2`'s two writers (the BIF, the C `load` callback through `enif_make_atom`) share the cell. `run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess).
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable **pooled BIF heap** and the per-call `PendingInterner` is committed **after the registry borrow is released**. `NifCallError::Raised(reason)` → `error::nif_raised` (a **live-reason-term** raise); `UnknownFunction` → bare `error::undef`; a miss is a perfect no-op (`Ok(None)`). **Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif` — `tests/nif.rs`'s caller is deliberately a *separate* module.

### `port.rs` — the `PortHook` provider (contract A.4)
Public: `PORT_INFO_ATOMS` (incl. `registered_name`), `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver}`, `StreamType{List,Binary}` (list is the default), `RuntimePorts` (the `beam_bifs::PortHook` impl: `open_port/2`, `port_close/1`, `port_info/1,2`) built from `Rc<RefCell<PortRegistry>>` + the shared `Rc<AtomTable>` + the owning `ProcessId`.
`PortRegistry` (private `{poller, registry, meta, heap}`): `new()` (anchors the `driver_*` codegen unit), `is_live`/`contains`, `write_command(id, bytes)`, `len()`/`is_empty()` (live ports = `system_info(port_count)`), `ids()` (port-number order = `erlang:ports/0`), `close(id)`, the `{spawn_driver,…}` routing `driver_lookup(name)`, and private `register`/`pump(timeout) -> Vec<PortEvent>`/`take_due_exit_statuses`/`take_driver_outputs`/`info`. `PortMeta`/`PortEvent` carry the per-port metadata and the `Data`/`Exited` events. Consumers: `Runtime::deliver_port_messages(table, timeout)` and the `-eval` trio `poll_port_messages`/`port_data_message`/`port_exit_message`.
`Runtime` owns it as an `Rc<RefCell<PortRegistry>>` (the ETS pattern) because `FunBridge` needs `&mut Runtime` at the same time; a nested borrow is a typed capability gap, never a panic. `SpawnDriver` is the **single** OS-child implementation; this crate owns only the **term decoding** of `open_port/2`'s `Name`/`Options` (into a term-free `SpawnSpec`/`SpawnOptions`) and the `PortMeta`.
`pump` is the single message producer: it polls in `PORT_POLL_SLICE` (25 ms) slices, each clamped by the earliest driver deadline (`beam_io::PortRegistry::next_deadline`), runs the scheduled port tasks, harvests each driver's `driver_output` and reports `PortEvent::{Data,Exited}`. `deliver_port_messages` DELIVERS each `{Port,{data,..}}`/`{Port,{exit_status,..}}` into the **owning** process's mailbox and returns the count. `close`/`PortHook::close_port` call `beam_io`'s `notify_port_exit(…, Closed)` **before** `registry.close(...)`.

### `port/driver.rs` — the driver C ABI host (contract A.4)
`Driver{library: DriverLibrary, host: Box<DriverPort>}` pairs a `dlopen`ed driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops, mirroring `crate::nif`). `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_` — the port handle **is** the per-port `DriverEnv`'s address: it owns a driver-private term arena, the shared `AtomTable` + a `PendingInterner`, and the owning `ProcessId`; it implements the output/term-data/pid services and captures every `driver_output`/`send_term` payload. `load_driver(candidates, name)` tries each candidate (the loader appends the `.so` suffix) and reports the **last** typed error. It implements the four `DriverHost` registry hooks with the C's exact codes: `add_driver_entry`/`remove_driver_entry` over an in-crate thread-local driver-entry registry mirroring the C's `driver_list` (`add` records and returns `0`; `remove` ⇒ `1`/`0`/`-1` per `io.c:7698`, `-1` for a dynamically loaded entry), `lock_driver` keyed off the port's own load state (`0` loaded, `-1` statically linked, `io.c:7324`), and `create_port` = the C invalid-port sentinel (an honest unsupported). Every driver callback that can reach the two port-less slots (`add`/`remove_driver_entry`) runs under `beam_abi::with_current_host`, so those slots reach this host.
`DriverPortAdapter` is the **port lifecycle** the host alone lacks — a `beam_io::Driver` over a loaded C driver: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, kept alive in a `Box` that never moves), `output` hands the port's queued bytes to the driver's `output` callback and queues the `driver_output` reply as the port's **input** (surfaced by `take_driver_outputs` as `{Port,{data,Data}}`), `stop` runs the entry's `stop`, and the `Driver` drop runs `finish` + `dlclose`.
`PortRegistry::new` anchors `beam_abi`'s driver codegen unit (`black_box(beam_abi::driver::drv::driver_api_table())`) so `build.rs`'s `-Wl,--export-dynamic` has the `driver_*`/`erl_drv_*` symbols to publish. `open_port({spawn_driver, Name}, Options)` is routed here (`PortName::SpawnDriver`); an unknown or empty driver name is the oracle's `error:badarg`, never a fabricated port.

### `dist.rs` — the distributed node (contract A.5, phase 1)
`DistNode` is the runtime's *listening* half of Erlang distribution — the smallest thing that makes `beam_rt` a **reachable node**: `start(configured, cookie)` **binds** a wildcard listener (`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error), and the first `pump()` **publishes** the node to `epmd` (`ALIVE2_REQ`; the socket lives for the node's life). Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/`is_short_name()`, `port()`, `creation()`, `is_registered()`/`is_alive()`/`registration_error()` (recorded, never raised — a `-sname`/`-name` runtime with no `epmd` keeps a bound-but-unregistered listener), `connections()`, `is_idle()`, `last_link_error()`.
`NodeName::parse(configured)` splits a `-name`/`-sname` value into the three wire forms: `full`, `advertised` — **always** the full `node@host` name, in **both** the `-name` and `-sname` cases (a real peer resolves the name with `list_to_existing_atom/1` and aborts the socket on a bare short name), and `epmd` (the short name for a `-sname`, verbatim for `-name`). A bare value's host is `local_hostname()` (`/proc/sys/kernel/hostname`, else `$HOSTNAME`). `resolve_cookie(init_args)` = `-setcookie`, else `$HOME/.erlang.cookie`, else the fixed `DEFAULT_COOKIE` (`nocookie`).
`DistConnection` wraps one accepted socket in a **server-side** `beam_dist::ConnectionDriver` (`ConnectionDriver::server(advertised, cookie, creation)`, driven `'N'` → `'s'`/`'S'` → `'r'` → `'a'`): `state()`, `is_established()`, `is_live()`, `peer_name()`, `peer_creation()`, `bytes()`.
`pump()` registers once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) pending connections into links (non-blocking socket), then steps every link under a per-link **read timeout of `DIST_READ_SLICE` (25 ms)**, so one pump can never stall the scheduler. A link's protocol/write failure **retires** it and records why (`last_link_error`), never raising; only the listener's own `accept` failure propagates.
`dispatch_inbound(atoms, sink)` (Phase 2) drains every **established** link's queued inbound `DOP_*` through a `beam_dist::InboundSink` and returns the count; a link-level decode/classification failure **retires** that link (`last_link_error`), never aborting the pass. `LocalDeliverySink` (`impl beam_dist::InboundSink`, holding `&mut ProcessTable` + this node's identity) routes `Delivery::Send` to a **local** pid (`NoSuchProcess` for another node/creation or an unknown pid — never a lookup by slot number alone) and `Delivery::RegSend` via `ProcessTable::whereis`; `Send`/`RegSend` deliver through `ProcessTable::deliver_simple` (so a blocked receiver is woken by resume-on-send), while the link/exit/monitor/alias/`Other` families stay the honest typed `Unsupported` (`beam_process`'s `Links`/`Monitors` take only local `ProcessId`s). The scheduler pass drives it from `Runtime::dispatch_dist_inbound` **gated by `Runtime::allow_inbound_delivery`** (default OFF, so the differential corpus is byte-identical) and exposes `Runtime::dispatch_inbound(&mut Heap, &mut ConnectionDriver)` for an explicit hop.

### `nif.rs` — the live NIF libraries (contract A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`. `NifRegistry`: `new()` (anchors the `enif_*` codegen unit), `is_loaded(module)` (the oracle's `reload` condition), `insert`, `lookup(module,function,arity) -> bool` (**the dispatch predicate**; a miss is a no-op), `call(..) -> Result<Eterm, NifCallError>`. `NifHostImpl{heap, atoms, interner, self_pid}` implements `beam_abi::NifHost`; `map_load_error` maps `NifLoadError` → `beam_bifs`'s variant-for-variant. A NIF **call** runs on a **fresh** per-call `NifHostImpl`, sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner` with the load-time host.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`, via `nm -D`). **Typed gap:** the host leaves `term_to_binary`/`binary_to_term`/`make_ref` at the `NifHost` defaults (`None`).

### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`
`config.rs`: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` (`max_ports: Option<usize>` is the requested port-table size: `+Q`, else the clamped `ERL_MAX_PORTS`) with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs` (ordered flag → occurrences), `HeapOptions`/`MaxHeapFlags`. `cli.rs`: `USAGE`, `EXIT_OK/EXIT_RUNTIME/EXIT_USAGE/EXIT_UNSUPPORTED` (= 0/1/2/3), `parse(&[String])` (pure, excludes argv[0]), `parse_with_env(&args, &ProcessEnv)` (merges `ERL_*FLAGS`), `run(Vec<String>) -> i32`; the emulator-flag validators (incl. `parse_max_ports() -> Result<Option<usize>>`) and the `ERL_*` surface live in `src/cli/{flags,vars,env}.rs` (see `src/cli/CONTEXT.md`). `boot.rs` (A.7): `PreloadedModules` + `mod preloaded`/`mod bootscript` (see `src/boot/CONTEXT.md`). `info/` (A.8): `SUPPORTED_KEYS` (**63** atom keys) + `UNSUPPORTED_KEYS` (19), `INFO_ATOMS`, `InfoValue` + `to_eterm(heap, atoms)`, `system_info_value(key, rt)`, `tuple_key_value(tag,arg)`, `allocator_report(name)`/`effective_policy(base)` (see `src/info/CONTEXT.md`). `format.rs`: `term_to_string`/`term_to_string_w` (drives `io:format/2`).

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap, and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry. `try_native`'s dispatch table (`../native.rs`) is the source of truth; the child modules (`init`/`code`/`process`/`port`/`memory`/`application`/`erts_internal`/`prim`) and every implemented/not-implemented BIF are documented in **`src/native/CONTEXT.md`**. `beam_bifs` owns the *registry* surface (`bif.tab`); a native entry never duplicates one, and a call the floor does not claim returns `None` (falls through). Two namespaces are wholly floor-owned: `erts_internal` (14 BIFs, incl. `term_type/1`, `get_dflags/0`, `beamfile_chunk/2`, `beamfile_module_md5/1`, `no_aux_work_threads/0`) and `prim_file` (11 entries, incl. `get_cwd/0,1`, `read_file/1`, and the file-system set `delete/1`, `rename/2`, `make_dir/1`, `del_dir/1`, `read_link/1`, `make_link/2`, `make_symlink/2`, `altname/1`).

### `code:` is the native floor, not a live `code_server`
`code:*`, `init:*` and `application:*` are **preloaded-module surface** (A.7): the oracle serves them from `init.beam`/`code.beam`/`application.beam`, written against process/message machinery M1 does not run. `beam_rt` ships **no** live `code_server.beam` — OTP's real one needs `monitor`/`register`/`spawn_link`/`send`, a host **timer**, `make_ref/0`, named-ETS resolution and `persistent_term`/`filename`/`erl_prim_loader`, all outside this crate — and its *state* already lives in `CodeServer`. The `boot/*` differential cases touching `code:*` are **shape-only** and already satisfy; a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**

### `erlang`-namespace fallback and the known-unimplemented list
`call_bif` consults the floor, then the `beam_bifs` registry, then falls back for the `erlang` namespace. A **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises the capability gap `unsupported: erlang:X/Y …` (exit 3); any other unclaimed name raises the bare `error::undef`. The **effective** gap set is the curated static list (`error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) **intersected with what the live registry does not own**, so a `beam_bifs` change that registers a listed name can never shadow the registry. Drift guard: `error::tests::the_effective_gap_set_never_shadows_the_registry`.

## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | print the version banner (OTP `30.0-rc0` / erts `17.1`) and exit 0 |
| `-noshell` | run head-less (M1 default; accepted, no interactive shell exists) |
| `-eval Expr` | evaluate a **general Erlang expression** (`erl_eval`-style) and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args...]` | apply `Mod:Func(a, b, …)` (Arguments are **atoms**); the result is **discarded**; exit 0 on success |
| `-run Mod Func [Args...]` | same, but Arguments are plain **strings** (Erlang char lists); result **discarded** |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path (before / after `-pz` dirs) |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | select the scheduler model; recorded as an init argument (M1 runs single-threaded) |
| `+A N` | async-thread pool size → preserved verbatim in `emulator.extra_emulator_flags` |
| `+P N` | max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports` (`legacy` ⇒ the default table); observable through `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms N` / `+hmbs N` / `+hmax N` / `+hmaxk\|el\|ib B` | GC heap policy (`beam_gc::HeapPolicy`), rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 phase 1: a bound listener + `epmd` registration + the accepting handshake — see `src/dist.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [int-arg…]` | **the vertical slice**: load the file, run it as a **scheduled process** through `Runtime::run_scheduled` (the full scheduler: run queue, ports, timers, distribution — so a blocking workload such as a driver/port echo round-trip is resumed by a later pass), **print** the result (`~w~n`). Bounded by `RUN_DEADLINE`; a process with nothing left that could wake it keeps the single-pass `beam_engine::blocked` answer |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s, and list/map/**binary** comprehensions (incl. a binary generator). An `erl_eval`-style tree-walk evaluates it, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry** (only `and`/`or`/`xor`/`not`/`andalso`/`orelse`/`++`/`--` stay special forms). Binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**); a map literal uses the sorted `make_map`. Outside the grammar is a **capability gap** (exit 3).
* **Every command-line flag is an init argument.** Each recognized switch *and* each unrecognized `-flag`/`+flag` is recorded as an `InitArgs` occurrence — the source of `init:get_argument/1`. An unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is a usage error (exit 2).
* `run` argument grammar (each `ARG` token): a **signed integer** → `ArgTerm::Int`; a **double-quoted string** → `ArgTerm::Str` (char list); a **list** → `ArgTerm::List`; otherwise a bare atom → `ArgTerm::Atom`. The count must equal the arity (else exit 2); a `-`/`+`-prefixed non-integer token is a usage error. `run`, `-s` and `-run` resolve modules through `code_paths` (`-pa`/`-pz`) + the system stdlib (M1 searches for `<Mod>.beam`).
* **The full switch surface lives in `src/cli/CONTEXT.md`** — the emulator flags `+S`/`+A`/`+P`/`+Q`/`+K`/`+sbt`/`+hms`/`+hmbs`/`+hmax*`/`+M*`, the init flags `-config`/`-boot`/`-setcookie`/`-emu_flavor`, the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge, and the `ERL_*` inventory (`ERL_MAX_PORTS`/`ERL_INETRC`/`ERL_CRASH_DUMP`/`ERL_CRASH_DUMP_SECONDS`/`ERL_ROOTDIR`/…). A `+`-flag is an emulator flag (validated, into `extra_emulator_flags`); every recognized switch is recorded as an init argument.

## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`), or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable**: `src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal` (like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it — it escapes as the exit-3 line, never a false `error`. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (the `beam_common::Raise` convention); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise`, which recovers a bare-atom reason so it is still classified by name). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap. Strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them. The surface answers **63** atom keys plus **two tuple keys** — `{allocator, A}` and `{wordsize, internal|external}`, dispatched through `info::tuple_key_value` (an unknown word/tag is the oracle's `badarg`) — and returns the oracle's `error:badarg` for any other key; the 19 oracle-accepted keys naming facilities this runtime does not have raise the honest `unsupported` capability gap, never a fabricated value (the full list is in `src/info/CONTEXT.md`). `{wordsize,external}` = 8 and `context_reductions` = 4000 (the C's `CONTEXT_REDS` interface constant) now match the oracle.
**The per-key catalog — the implemented/unsupported/badarg classification, the self-derived-vs-oracle-equal split, the atom discipline and the oracle-comparison test — lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).** `src/info.rs` is a thin parent (`InfoValue` + `to_eterm`, `SUPPORTED_KEYS`/`UNSUPPORTED_KEYS`, `INFO_ATOMS`, the `system_info_value` dispatcher, `allocator_report`) and the per-key logic lives in `src/info/{system,limits,schedulers,memory,unsupported}.rs`.

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2453 lines; production half ~1470).

## Design Decisions
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every module it loads is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns (`RuntimeContext` only borrows it); `system_info`/`format_term` use a separate `info_heap`, `reset()` per call.
* **`ensure_heap` without GC.** M1 has no engine collector: `ensure_heap` checks capacity and returns `BeamError::SystemLimit` when short (default 64 Ki words); growth-by-collection is Stage 4.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are **preserved verbatim** in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry rather than re-implementing arithmetic/printing; **`main.rs` is a thin shim** over `cli::run(argv)`. `system_info` returns `Eterm` via `InfoValue`, computed heap-independently, so the keys are unit-testable without a heap.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* of the runtime (`#![deny(unsafe_code)]`, may not alias), so `run_pass` **moves** both out (`take_processes`/`put_processes`), runs the scheduler and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`. `Runtime::scheduler` persists across passes.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid in `RunnerState::results` (`process_result`) and returns `RunOutcome::Exit(normal)`, after `stabilize_term` copies it onto the pointer-stable `eval_heap` (never reset) — a mailbox value points into the process's own heap. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The host seams: the five bridges + the two borrow-free hooks.** `FunBridge` delegates to the **existing** `RuntimeContext::apply_fun` (so `lists:map(fun(X) -> X*X end, [1,2,3])` → `[1,4,9]`) and `SendBridge` to the existing `send_message` (a BIF send is the same delivery path as the `send` instruction). Because the `BifContext` holds no runtime borrow, every resource is a non-runtime-borrowing clone (`Rc<BifRegistry>`, an `Rc<AtomTable>`, an `Rc<RefCell<TableRegistry>>`, a **pooled** `beam_alloc::Heap`, the disjoint `output` field); the port subsystem's `Rc<RefCell<PortRegistry>>` and the node's `Option<DistNode>` field exist for the same reason.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw` with a live reason).
* **Timers are a runtime-local deadline heap, not `beam_process::TimerService`.** That service is driven by **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (it owns `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas). So the wheel degenerates to a min-heap (`src/timers.rs`) the **scheduler loop** drains: monotonic deadlines, earlier first, equal keeping insertion order, `O(1)` cancellation via a lazy tombstone, and sleep-to-earliest only when idle.
* **Oversized messages go through the heap-fragment model, composed in-crate.** `beam_message::send_fragmented` wants the receiver's **heap** and **mailbox** at once, but `Process` exposes them only through two `&mut self` accessors, so `RuntimeContext::send_fragmented_message` composes the same public fragment primitives directly and records the wake on `Runtime::note_fragment_wake`. `MailboxState::remove_at` retains a removed message's `Fragments` so a just-bound payload stays valid.
* **The driver port handle is the environment's address.** A driver callback receives an `ErlDrvPort` that **is** its per-port `DriverEnv`; `DriverPortAdapter` `Box`es the host (and the environment *before* `as_port()`), so the raw pointer stays valid and stable across callbacks. The `Driver`'s field order is load-bearing (the library drops before its host, so `finish` still sees a live host).
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`.

## Known Issues / Intentional M1 gaps
* **No interactive shell; the node completes the `'N'` handshake but is otherwise passive.** `-noshell` is the only mode. `-name`/`-sname` really bind a distribution listener and register with `epmd` (best-effort; a failure is recorded in `DistNode::registration_error`, never fatal), and the scheduler pass pumps inbound connections through `beam_dist::ConnectionDriver::server` (`src/dist.rs`, A.5 phase 1) — a **real OTP 29 peer completes the handshake** (`tests/dist.rs`, in-process and through the real binary). Remaining gaps: inbound `DOP_*` is never delivered, there is no `net_kernel` protocol, and `node/0`/`system_info` do **not** reflect the live node.
* **Preloaded modules load for real; positional atom indices are still not the oracle's.** `boot()` loads all 22 preloaded `.beam`s from the erts app `ebin` (see `src/boot/CONTEXT.md`), but the atom table is seeded with `CORE_ATOMS` + `INFO_ATOMS` (not the full `atom.names`), so preloaded positional atom indices are not reproduced.
* **Answers that read *this* runtime's own state differ from the oracle by construction** — not bugs, and must not be "fixed" to a run-time figure: `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)` and `erlang:module_loaded/1`. `erlang:whereis(init)` **does** agree (the root process; oracle `<0.0.0>`); `erlang:registered/0` is on the known-unimplemented list.
* **A non-byte-aligned `-eval` result cannot be *printed*.** The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (and a container past its ~80-column limit) with `badarg` — a **`beam_bifs` printer gap outside this crate**; the corpus probes read such values through `bit_size/1`/`is_list`, so they are unaffected. Other limits: a construction **or** pattern segment wider than 64 bits is *unsupported*; a bignum is `system_limit`.
* **Scheduler is single-threaded; a few M1 process gaps.** A blocked receiver **is** resumed by a sender (send→wake→resume), **by a due `send_after/3` timer**, or **by a fired `receive … after T` deadline**. Remaining gaps: **no reduction pre-emption** (`budget` not enforced; `Yield` never returned); a compiled `receive … after T` whose delay is **not statically readable** (a **Y-register** variable or `after infinity`) still parks (see the `beam_engine` handoff); a **capability gap is uncatchable** on the runner path.
* **`-smp disable` is an honest divergence.** The oracle rejects it (`Argument '-smp disable' not supported. Use "+S 1" instead.`) while `beam_rt` accepts it (the A.6 adoption mandate: every emulator switch parses and is recorded as an init argument). `-smp` sets `FeatureFlags::smp` + `init:get_argument(smp)`; `+S N` is the effective count → `emulator.schedulers`, observable through `system_info(schedulers)` (M1 runs single-threaded).
* **`-setcookie` is unmodeled and `EmulatorConfig::cookie` is never populated.** The CLI (`src/cli.rs`) has no `-setcookie` arm, so it lands as an ordinary init argument named `setcookie`; `dist::resolve_cookie` reads that occurrence (else `$HOME/.erlang.cookie`, else the fixed `nocookie` bytes) and `Runtime::new` passes them to `DistNode::start`, while `beam_common::RuntimeConfig::cookie` stays `None`.
* **`-eval`/`-s`/`-run` are documented subsets.** Supported: the expression subset (`-eval` prints nothing), the **send operator**, a **bare `receive`** driving a spawned sender, the **spawn probes** and a bounded scheduler pump. Remaining gaps (typed errors in `src/eval/mod.rs`): a `receive` that never receives, a `receive` inside a spawned process, and `after infinity`. Real `erl` start-script processing / `-init_debug` are absent.
* **NIF loading is live, with honest typed gaps (A.3).** `erlang:load_nif/2` really `dlopen`s the shared object and runs the C NIF through `try_call_nif`; a load failure is the oracle's **returned** `{error, {Reason, Text}}`, never a raise. Typed gaps: the host leaves `term_to_binary`/`binary_to_term`/`make_ref` at the `NifHost` defaults; a second `load_nif` for a module that already has a library is `reload`.
* **`NEW_FUN_EXT`: a compiled module's local fun encodes faithfully; an `erl_eval` lambda stays a typed gap.** `fun M:F/A` builds a real `FunKind::External` term (`term_to_binary` → `EXPORT_EXT`). For a **compiled-module** `make_fun3` closure, [`FunIdentityBridge`] supplies the five `NEW_FUN_EXT` identity fields the term does not carry, so `term_to_binary/1` of such a closure is byte-exact to the oracle (`context/fun_identity.rs`'s oracle test drives the real `term_to_binary` BIF; `context/bridges.rs`'s test pins the derivation). The lookup is module-scoped to the **caller**, so a local fun that escaped its defining module and is encoded from another one reports the capability gap. An **`erl_eval` lambda (the `-eval` path) remains unclonable**: its oracle image is a closure over `erl_eval.erl`'s arity-specialized `expr/6` lambda whose identity fields come from erl_eval internals (the module's `FunT` and its `Info` tuple, holding the fun clause in `erl_parse` abstract format), which no identity seam can derive faithfully — fabricating them is forbidden. It therefore stays the honest typed `unsupported: local_fun` (the `wire/new_fun_ext_encode` corpus case, the gate's single `unsupported`); no wrong encoding is emitted.
* **Ports match the oracle's observable shape; the gaps are these.** The read path is thin (only **stdout** polled, stderr discarded, one `Read::read` per readiness); `connected` flips to `false` only at `port_close/1` and `eof` is inert; a `binary`-stream read wider than 64 bytes is the typed *unsupported* gap. `os:cmd/1` stays the runtime-native host spawn.
* **The send family: `erlang:send/2` and `erlang:'!'/2` are served (the `SendBridge`); two destinations are still typed gaps.** `erlang:send(Port, Data)` needs the port write path (the oracle also drops a send to an unknown/closed port **silently**, where `port_command/2` raises `badarg`), and the distributed `{Name, Node}` send is contract A.5. Both raise `unsupported: …`, never a fabricated value or a wrong `badarg`.
* **Driver ports (A.4) load and drive a real C driver end to end, with typed gaps.** A `{spawn_driver, Name}` port's `driver_output` **is** delivered to its owner as `{Port, {data, Data}}` (the adapter queues the reply as the port's input, the scheduler pass's port half harvests it, the blocked owner is woken) — pinned end to end through the real binary's `run` action by `tests/driver.rs::the_run_action_drives_the_scheduler_and_echoes_a_driver_port`. The driver's own **event and timer** requests are real too (`a_driver_select_and_a_driver_timer_both_reach_the_owner`, verified against the system `erl`): `driver_select` registers the descriptor with the runtime's one poller (exact for one registration per direction — a typed `unsupported` when a driver arms several), `driver_set_timer`'s deadline is mirrored into the port's `TIMEOUT` task (cleared before the callback, so a re-arming callback wins), and `driver_cancel_timer`/`driver_read_timer` answer the C's codes. Remaining typed gaps: `driver_async` (no async pool; `Runtime` is `!Send`), `port_control/3` not reaching `control`, a captured `send_term`, `ERL_DRV_USE`'s `stop_select`, no OS child (`os_pid` is `undefined`). **Documented M1 extension:** with no `erl_ddll:load_driver/*`, the `Name` doubles as the *search* (a `/`-containing name is the object path, driver name = its file stem; else `<name>.so`, `./<name>`).
* **`erlang:send_after/3` / `cancel_timer/1` are runtime capabilities; the rest of the timer family is still gaps.** `send_after` answers a `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)` `badarg`, a bad time/destination `badarg`. Still unimplemented: `start_timer/3,4`, `send_after/4`, `cancel_timer/2`, `erlang:system_info/2`.
* **`process_info/1,2` is a full introspection surface with honest typed gaps.** `process_info/2` answers ~27 items from this runtime's real state (`registered_name`, `status`, `message_queue_len`, `messages`, `links`, `monitors`, `dictionary`, `trap_exit`, `priority`, `group_leader`, the heap/stack/reduction items, `garbage_collection`, the min/max heap and `message_queue_data`/`trace` items … — full catalog in `src/native/CONTEXT.md`); a valid oracle item it cannot answer (`current_function`, `current_stacktrace`, `initial_call`, `catchlevel`, `magic_ref`, `priority_messages`, `binary`, …) raises the typed `unsupported`, never a fabricated value. The oracle `registered_name` wrapping is exact: `{registered_name,Name}` when registered and the **bare** `[]` (unregistered) in the `/2`-atom form, `{registered_name,Name|[]}` in the list form, omitted by `/1` for an unregistered process; **`process_info/1`** answers the fixed `pi_1_keys` order (a registered process first, an unregistered one 16 items). Documented divergences: `total_heap_size` is **466** (vs the oracle's 233; this collector pre-allocates a 233-word mature generation), `memory`/`reductions` are this runtime's own figures, `group_leader` is this runtime's root pid; `garbage_collection` is the oracle's five-item proplist (non-hardcoded). A pid not in the table is `undefined`; an unknown/non-atom item or a non-pid is `badarg`.
* **Heap has no GC** — a runaway allocation returns `SystemLimit`.
* **No whole-system memory introspection.** `erlang:memory/0,1` and `erlang:statistics/1` are **not** registered BIFs (exit 1); the memory numbers it *does* answer are `process_info/2`'s heap items, `system_info(allocated_areas)` / `{allocator, A}` and `ets:info(T, memory)`.
* **The heap switches are modelled; some rejection details are not.** `+hms`/`+hmbs` set a `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000` → 1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1, and the oracle's `atoi`/`ErtsStrToSint` laxness is not reproduced.

## Handoffs (owned by OTHER nodes)
`tools/differential/gate.sh` re-measured at this node's HEAD: **`total=600 agree=599 mismatch=0 unsupported=1 skipped=0`** (gate exit 3 = the one remaining honest capability gap, `wire/new_fun_ext_encode` — a lambda's `NEW_FUN_EXT` image; see Known Issues).
* **A.7 boot — the real `start.boot` stops honestly at `application:load/1`.** `Runtime::boot_from_script` loads every `preLoaded`/`primLoad` module and runs the directive sequence until instruction 16 (`{apply,{application,load,[…]}}`), which needs the `application_controller` this runtime lacks, and returns a typed `BeamError` there; instructions 17–21 are unreached. `prim_file` serves 11 entries and `erts_internal` 13 BIFs natively; every other `prim_*`/`erts_internal` BIF is itemised in `src/native/CONTEXT.md`. The `records/*` corpus cases **agree**, served by the `RecordBridge`; remaining `wire/*` encode/decode asks live in `beam_codec`/`beam_bifs`.
* **`beam_process` / `beam_message` — a split borrow over a process's heap + mailbox, and an owning drain for the wake list.** `Process::heap_mut`/`mailbox_mut` are two separate `&mut self` accessors, so `beam_message::send_fragmented` (needing the receiver's heap **and** mailbox at once) cannot be driven from here: `RuntimeContext::send_fragmented_message` composes the fragment primitives itself and records the wake on `Runtime::note_fragment_wake`. A split borrow plus a drain yielding the woken pids would delete both workarounds (and `MailboxState::retained_fragments`).
* **`beam_process` — a `!Send`-friendly `SchedulerPool`.** SMP adoption means replacing the runtime's single-threaded `Scheduler::new()`+`enqueue`+`run_ready` loop with `beam_process::SchedulerPool`, but `Runtime` is `!Send` (it holds `Rc`/`RefCell` registries, the `CodeServer`'s `Rc<AtomTable>`, `*mut Eterm` heaps, `Rc<FunBody>` closures and a `dyn DistSignalRouter`), so `beam_process`'s `unsafe impl Send` escape is unavailable (`beam_rt` is `#![deny(unsafe_code)]`) and `Arc<Mutex<Runtime>>` does not help (`Mutex<T>: Send` needs `T: Send`). Forward paths: (a) a `?Send`/calling-thread `SchedulerPool` variant in `beam_process`, or (b) Send-ify the runtime across `beam_alloc`/`beam_engine`/`beam_dist`.
* **`beam_engine` — a deadline on the block outcome / a `Machine` Y-register accessor.** `RunOutcome::Wait { func, pc }` carries no deadline, so the runner recovers the receive delay by scanning the parked function's IR for the owning `wait_timeout` (`runner::parked_receive_timeout`) — which works only for a **statically readable** operand (literal/`Literal`/X-register). A **Y-register** `after T` is unreadable because `Machine` exposes no stack read, so the process parks instead of timing out. The engine reporting the deadline (or exposing the Y-register) would delete the IR scan and cover the variable case.
* **`beam_bifs` / `src/context` — `node/0` and the `NodeIdentity` wiring.** `NodeIdentity` answers the fixed `nonode@nohost`/creation `0`, so a **live** `-sname`/`-name` node is invisible to `erlang:node/0` and the node-valued `system_info` items; `erlang:node/0` is not registered at all (bare `error::undef`). Feeding the identity from `Runtime::dist_node()` is what makes the node real to the language.
* **Distribution, phase 2 — inbound `DOP_*` into a mailbox.** A link's decoded control messages (`DOP_REG_SEND`/`DOP_SEND`) stay queued in the driver; delivering them means resolving `{node,name}`/`{node,pid}` to a local process and `deliver`-ing the payload through `beam_process` (the same resume-on-send path a port message takes).
* **`beam_io` — the remainder of the driver-port lifecycle.** `DriverPortAdapter` supplies the port lifecycle a loaded C driver needs; what is still owed is everything else the C host answers — the `async` default, `port_control/3` reaching the driver's `control`, a delivered `send_term`, `ERL_DRV_USE`'s `stop_select`, and an `ErlDrvEvent` with a **per-registration** identity (a `beam_io` port task carries only the port key, so a driver arming several descriptors per direction is a typed `unsupported`) — see the driver-port gaps in Known Issues.
* **`beam_io` — `open_port({spawn_executable, <a DIRECTORY path e.g. /tmp>}, [])` diverges.** The oracle returns a **port**; `beam_rt` raises `error:eacces`, because `SpawnDriver` surfaces `Command::spawn()`'s synchronous `EACCES`. A non-executable regular file, and a missing `{spawn, …}` command, both match the oracle at `error:eacces`.
* **`beam_engine` — name the rejected opcode.** Kernel `code.beam`'s `code_server:call/1` executes `recv_marker_reserve/1` (also `recv_marker_bind`, `send`, `loop_rec`, `remove_message`), which no family claims; it falls to the generic `Err(error::unsupported("widened opcode not yet executed"))` at `beam_engine/src/families/mod.rs`, which does **not** name the instruction. Diagnostic-quality, not a gate blocker.
