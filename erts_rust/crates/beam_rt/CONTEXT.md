# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture. It owns: `main.rs` and the **CLI flag surface** (**A.6**); the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the OTP boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded scheduler drives (`src/boot/drive.rs`), which run the real `bootstrap/bin/start.boot` to its final `{progress,started}` (**A.7**); **`system_info/1`** + `erlang:process_info/2` (**A.8**); the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable); the **A.4 runtime side of ports** (`open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s); the **runtime-local timer deadlines** behind `erlang:send_after/3` and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop; and the **distributed node** (A.5 phases 1–2, `src/dist.rs`): the bound listener, best-effort `epmd` registration and the server-side `'N'` handshake, which **completes** against a real OTP peer.

The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`). It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`; observability/perf detail → [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md); M1-gap/handoff detail → [`M1_GAPS.md`](M1_GAPS.md).

## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)

Per-child API surface detail lives in the child nodes' own `CONTEXT.md`; the entries below are the crate-level summary + pointer.
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces, the scheduler-pass family drives processes → ports → timers → distribution in bounded steps, and `RuntimeRunner` implements `beam_process::ProcessRunner`; full API surface in [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking and the NIF-dispatch order; full API surface in [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver.rs`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump) and the runtime's own driver C-ABI host for `{spawn_driver, Name}`; full API surface in [`src/port/CONTEXT.md`](src/port/CONTEXT.md).

### `dist.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the runtime's *listening* half: `start(configured, cookie)` **binds** a wildcard listener (`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error) and the first `pump()` **publishes** the node to `epmd` (`ALIVE2_REQ`). Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/`is_short_name()`, `port()`, `creation()`, `is_registered()`/`is_alive()`/`registration_error()` (recorded, never raised), `connections()`, `is_idle()`, `last_link_error()`.
`NodeName::parse` splits a `-name`/`-sname` value into `full`, `advertised` (the full `node@host` name in **both** cases — a peer resolves it with `list_to_existing_atom/1` and aborts on a bare short name) and `epmd` (the short name for `-sname`, verbatim for `-name`); a bare value's host is `local_hostname()` (`/proc/sys/kernel/hostname`, else `$HOSTNAME`). `resolve_cookie(init_args)` = `-setcookie`, else `$HOME/.erlang.cookie`, else `nocookie`.
`DistConnection` wraps one accepted socket in a **server-side** `beam_dist::ConnectionDriver` (`'N'` → `'s'`/`'S'` → `'r'` → `'a'`). `pump()` registers once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections non-blocking, then steps every link under a per-link `DIST_READ_SLICE` (25 ms) read timeout, so one pump can never stall the scheduler; a link's protocol/write failure **retires** it and records why (only the listener's own `accept` failure propagates).
`dispatch_inbound(atoms, sink)` drains every **established** link's queued inbound `DOP_*` through a `beam_dist::InboundSink` and returns the count. `LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes `Delivery::Send` to a **local** pid (`NoSuchProcess` for another node/creation or an unknown pid) and `Delivery::RegSend` via `ProcessTable::whereis`, both through `deliver_simple` (so a blocked receiver is woken); the link/exit/monitor/alias/`Other` families stay the typed `Unsupported`. The scheduler pass drives it from `Runtime::dispatch_dist_inbound`, **gated by `Runtime::allow_inbound_delivery`** (default OFF, so the differential corpus is byte-identical).

### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`. `NifRegistry`: `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**), `call`. `NifHostImpl<'a>` implements `beam_abi::NifHost`; a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner` and holding `Some(&'a mut dyn NifHostServices)` (the `make_ref`/`whereis_pid` provider); `alloc_env`/`free_env` are real and `make_copy` is the **identity**.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).

### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`
`config.rs`: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs` (ordered flag → occurrences), `HeapOptions`/`MaxHeapFlags`.
`cli.rs`: `USAGE`, the four `EXIT_*` codes, `parse`/`parse_with_env` (merges `ERL_*FLAGS`), `run(Vec<String>) -> i32`.
`boot.rs` (A.7): `PreloadedModules`, `PRELOADED_MODULE_NAMES`, `CORE_ATOMS`. `info/` (A.8): `SUPPORTED_KEYS` (**63**)/`UNSUPPORTED_KEYS` (19), `INFO_ATOMS`, `InfoValue` + `to_eterm`, `system_info_value`, `tuple_key_value`, `allocator_report`/`effective_policy`. `format.rs`: `term_to_string`/`_w` (drives `io:format/2`). **Per-module detail: `src/{cli,info,boot}/CONTEXT.md`.**

### Observability (`trace.rs` · `seq_trace.rs` · `crash_dump.rs` · `perf_map.rs`, contract A.8)
Process tracing, sequential tracing, the ERTS-format crash-dump writer behind `erlang:halt`, the `+JPperf` JIT symbol map, the **execution-trace seam** (`call`/`return_from`/`return_to` over `beam_engine`'s `ExecutionContext::trace_event`, live on both the single-pass and the scheduled paths) and the `examples/perf_bif.rs` dispatch-overhead harness are detailed in **[`TRACE_AND_PERF.md`](TRACE_AND_PERF.md)**. ## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry. The child modules, the dispatch table (the source of truth) and every implemented/not-implemented BIF live in **`src/native/CONTEXT.md`**; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form (so `ProcessBridge`'s keys/items only satisfy the seam, unit-tested directly).
**`code:` is the native floor, not a live `code_server`.** `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7) the oracle serves from `init.beam`/`code.beam`/`application.beam`; `beam_rt` ships **no** live `code_server.beam` (its *state* is `CodeServer`), the `boot/*` differential cases touching `code:*` are **shape-only**, and a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**
**Two server processes are native state, not scheduled code.** The runtime's root process (registered as `init`; it is what every action runs as) and the native **`file_server_2` service** (`src/native/file_server.rs`, contract A.9) are spawned `Runnable` with no engine and are **never enqueued**, so the runner never executes them; their mailboxes are drained by the scheduler pass (`Runtime::service_file_requests`) and the replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery all work. Detail in [`src/native/CONTEXT.md`](src/native/CONTEXT.md) and [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. The **effective** gap set is `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` **intersected with what the live registry does not own** (the `erts_internal:`-hosted calls). Drift guard: `error::tests::{known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry,the_effective_gap_set_never_shadows_the_registry}`.

## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path (before / after `-pz` dirs) |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — `src/dist.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). Outside the grammar is a **capability gap** (exit 3).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2). **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**

## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap. Strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them. The surface answers **63** atom keys plus two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the 19 oracle-accepted keys naming facilities this runtime lacks raise the honest `unsupported` gap. **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).** `context_reductions` is answered as `4000`, the canonical ERTS reduction quantum `beam_common::CONTEXT_REDS` — `src/info/schedulers.rs` re-uses that constant and declares **no** local copy (the residual `beam_io::port_task::CONTEXT_REDS` and `beam_process::scheduler::DEFAULT_REDUCTIONS_PER_SLICE` transcriptions belong to their own crates).

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2453 lines; production half ~1470).

## Design Decisions
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every loaded module is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use a separate `info_heap`, `reset()` per call. For a *scheduled* slice `ensure_heap` is now the **collection point** (armed by `BudgetContext`; see Design Decisions); for every other context it is a no-op on the unbounded arena. What *does* exhaust is the bounded BIF/eval heaps and, for a collected process, its young heap.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are preserved verbatim in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry rather than re-implementing arithmetic/printing; `main.rs` is a thin shim over `cli::run(argv)`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* (`#![deny(unsafe_code)]`, may not alias), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid (`process_result`), copies it onto the pointer-stable `eval_heap` (never reset) via `stabilize_term`, and returns `Exit(normal)`. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The host seams: nine bridges + three hooks** (enumerated in [`src/context/CONTEXT.md`](src/context/CONTEXT.md)). Every bridge that needs no runtime borrow is a cheap `Rc`/`RefCell` handle; the ones that must borrow are made mutually exclusive by their `uses_*` predicates. `NodeIdentity` (a `Copy` atom) rides alongside every arm; `FunIdentityBridge` and `RuntimeMemory` are owned snapshots installed **only** on their consumer BIFs' arms.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw`).
* **Timers are a runtime-local deadline min-heap, not `beam_process::TimerService`.** That service is driven by **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (it owns `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas), so `src/timers.rs` is a min-heap the **scheduler loop** drains: monotonic deadlines, earlier first, `O(1)` cancellation via a lazy tombstone, sleep-to-earliest only when idle.
* **The persistent-term store keeps raw `Eterm` words but compares structurally.** The store (`src/context/persistent_term.rs`) pins the raw words of this node-global table and compares a key — and the `put_new/2` value — with `beam_term::compare::eq` (the C's exact `EQ`, `erl_bif_persistent.c:1015/726`), so a boxed key matches a structurally equal but distinct term. Raw storage is safe because every write to a runtime-level store goes through `Runtime::try_stabilize_escaped` (a copy onto the never-moved arena), which reports a **genuine** copy failure as the honest `BeamError::SystemLimit` and trips the global GC valve (`disable_gc`) **only** for the off-heap-payload capability gap, so no process heap is ever moved again.
* **Oversized messages go through the heap-fragment model, driven by `beam_message`.** `RuntimeContext::send_fragmented_message` obtains the receiver's heap + mailbox from `Process::heap_and_mailbox_mut()` and calls `beam_message::send_fragmented(from, message, heap, mailbox, &mut ctx, 0)`, then records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments` so a just-bound payload stays valid. The fallback is reached only when the receiver's own heap genuinely refuses the payload — a bounded `HeapPolicy` makes `Process::deliver`'s on-demand growth fail, whereas an unbounded receiver would absorb the payload into its grown nursery instead. **`beam_message::Fragments::move_into` is never called** — retention is the honest M1 behaviour (accessor detail in [`M1_GAPS.md`](M1_GAPS.md)). **The retention only protects a *removed* message.** A fragment message still *queued* when a collection runs on its receiver has its `Fragments` dropped: `beam_process`'s `Process::run_rooted_collection` (`../../beam_process/src/process.rs:925-976`, the shared body of `collect`/`ensure_capacity`) drains the whole mailbox and rebuilds each `Message` via `Message::new(payload, from).with_token(..).with_off_heap(..)`, which carries neither `fragments` nor `binaries`/`nodes` — so the fragment's backing heap is freed while the queued payload still points into it. `beam_rt` reaches it through `deliver_message`/`deliver_in_table` (`Process::deliver` → `ensure_capacity` on a refused copy) and through the scheduled slice's `ensure_heap` collection, whenever a fragment message is queued; the fix belongs to `beam_process` (preserve the three lists, or add a payload setter). `beam_rt`'s own `MailboxState` logic is otherwise correct (only this node's cursor/fragment semantics are unaffected by the bug).
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`. `allocated_areas`' 19 items are derived from live state wherever a counterpart exists (`export_table`/`fun_table` from the loaded modules' `ExpT`/`FunT` counts, `module_refs`/`loaded_code`/`atom_table`/`register_table`/`process_table`/`port_table`/`ets_misc` from the runtime's tables, `dist_table`/`node_table` from `Runtime::dist_node()`); only the genuinely counterpart-less items (`sys_misc`/`static`/`export_list`/`fun_list`/`bif_timer`/`external_alloc`) stay a documented `0` (detail in `src/info/CONTEXT.md`).
* **The exit observer only *records*; a scheduler pass drains.** A `ProcessExitObserver` can be invoked while a `RefCell` the runtime owns is already borrowed (a BIF holds the shared ETS/port registry for its whole call), so `EtsExitObserver` (`runtime/ets_owner.rs`) touches nothing but its own `OwnerIndex` cell: it pushes the dead pid and the drained `PortWatch` pairs and returns. `Runtime::{drain_ets_owner_exits, drain_port_monitor_exits}` discharge the obligations at a scheduler-pass boundary with `try_borrow_mut`, **deferring** (never dropping, never panicking) on a live borrow.
* **The cross-module call seam is deepened, never broadened.** `resolve_external_call` must stay behaviour-preserving everywhere it does not now suspend, so the `Ok(None)` predicate grew (NIF modules, self-observing modules, an on-demand load, an unknown export) rather than the `Some` set. Suspending changes control flow, so a wrong `Some` is a correctness bug where a wrong `None` costs only a slower path.
* **GC collects only at `ensure_heap`, behind a per-call latch.** The root set is the *executing machine's* `x[0..live)` + Erlang stack, but a `RuntimeContext` is shared by nested runs (an external module call builds a new `Machine` on the same context), so a collection driven from a nested admission point would write the nested roots into the process's root set and leave the outer machine's terms dangling. Only the slice's own `BudgetContext` arms the latch and `context/gc.rs` takes it (`std::mem::take`); every nested path is a plain `RuntimeContext` whose latch is never set. `Machine::fr` holds *terms* and is outside the root set, so a module containing a float-family instruction is never collected over and an unresolvable call site (a fun entry, the `-eval` evaluator) is skipped — conservative, never wrong.
* **A process whose live terms the runtime cannot fully root is marked *relocation-exempt* while it runs them.** `RuntimeContext::with_relocation_exempt` (`src/context/mod.rs`) saves the process's mark, sets it, runs a closure and restores the previous mark on every path (nested-safe save/restore). While exempt, `Process::deliver` returns the copier's raw `Alloc(AllocKind::Message)` refusal instead of collecting, which `RuntimeContext::{deliver_message, deliver_in_table}` route to the heap-fragment fallback — so the message still arrives with no heap word moved under a term the root set cannot publish. The wrapped scopes are exactly those runtime locals: the `-eval` driver (`crate::eval::eval`, whose `Runtime::pump_scheduler` receive pump runs inside the scope), `run_export_blocking`/`run_label_blocking` (the fresh `Machine`'s `x`/stack) and `apply_fun` (the `-eval`-closure environment). The scheduled slice is deliberately **not** wrapped — the runner drives it with the `*_outcome_with_tier` entries, publishes a parked machine's roots (`publish_parked_roots`), and its `BudgetContext` arms the admission point that is the legitimate collection site.
* **A failed collection halts that process's collection, never the program.** The pre-collector runtime was an unbounded arena that could not fail at a heap-admission point, so `halt_process_gc` keeps the (unmoved) heap and allocation keeps falling back to the arena; `disable_gc` (the escape-store valve) freezes **every** process heap when a runtime-level store cannot be copied onto the arena — keeping the store exactly as correct as before the collector existed.

## Known Issues / Intentional M1 gaps
Every gap below is a typed capability gap or a measured own-state difference — never a wrong result. **The per-item detail is in [`M1_GAPS.md`](M1_GAPS.md).**
* **The registered-BIF path avoids deep-cloning the shared `AtomTable`** — pending names commit via `code_server.atoms_mut()` (`Rc::make_mut`) only when `PendingInterner::is_empty()` is false.
* **No interactive shell; the node completes the `'N'` handshake but is otherwise passive.** `-noshell` is the only mode; `-name`/`-sname` bind a listener, register with `epmd` best-effort (a failure is recorded, never fatal) and complete the handshake with a real OTP 29 peer (`tests/dist.rs`). Gaps: no `net_kernel` protocol, the link/monitor/alias inbound families stay typed `Unsupported` (no remote-peer seam in `beam_process`), and `node/0`/`system_info` do **not** reflect the live node.
* **Two `get_module_info` divergences** — `exports` order vs the oracle's **global ERTS export-table** order (the test compares it as a set), and `badarg` for a module not loaded here.
* **Answers that read *this* runtime's own state differ by construction** — not bugs: `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size, the `process_info` heap/reduction figures. `erlang:whereis(init)` **does** agree (the root process; oracle `<0.0.0>`).
* **Adopted process-control families keep typed gaps (`src/native/`)** — `erlang:monitor/2,3` serves a **process** target and a **port** target (routed through `PortRegistry::port_table_mut` → `ProcessTable::monitor_port_term_with_tag`) and `monitor/3`'s `{tag,T}` is served on both paths for an immediately-representable tag (`error::unsupported_tag` for a heap-resident one); the remaining gaps are a **named** port monitor (`error::named_port_monitor`) and a remote `{Name, Node}` monitor. `spawn_opt`'s `{scheduler, N}`/`{async_dist, B}` stay `unsupported` (every other option is applied for real); `exit/2,3` matches the oracle except an internal **port** target and a foreign reference/ETS id. A dead watcher's **incoming** port monitor is swept by `drain_port_monitor_exits`.
* **ETS owner tracking and owner-death reclamation are live for a `named_table` and an *unnamed* table.** `ets:new/2` records the calling process as the owner and installs the parsed heir through `beam_ets::Table::new` (a table-owned deep copy); `ets:info(T, owner)`/`heir` render the recorded pids (`undefined` when unset); `ets:setopts/2`/`ets:give_away/3` are registered, and `private`/`protected` access is enforced per owner. A dead owner's table is released through the `ProcessExitObserver` + `drain_ets_owner_exits` drain, whose **authority** is the public `beam_bifs::TableRegistry::handles_owned_by` roster — so an *unnamed* table is reclaimed too (its handle is the registry key and is reachable from no public term otherwise), unioned with the index built at `ets:new/2` time, which supplies only a `named_table`'s registered name (released via `remove_name`). The table is dropped, or handed to its heir with the oracle's `{'ETS-TRANSFER', Tid, FromPid, Data}` (silent for the `{heir, Pid}` 2-tuple form, which carries no data; an arity-3 `{heir, Pid, undefined}` *does* transfer `undefined`); the tid is the table's **name atom** for a `named_table`, this runtime's own ref thing (`src/runtime/ets_owner.rs::tid_ref_thing`) for an unnamed one. `tests/ets_owner.rs` oracle-cross-checks the four flows. The remaining live gap is `ets:setopts/2`'s gift-data aliasing — the BIF routes `{heir,…}` to the non-copying `beam_ets::Table::setopts` where `install_heir` (a table-owned deep copy) is meant (owner `beam_bifs`/`beam_ets`). `Runtime::own_heir_gift` no longer swallows its copy result: a failed `Table::install_heir` is logged and recorded on the owner index, and the next `drain_ets_owner_exits` returns it as the typed error *after* discharging every death — a failed copy is never silently dropped.
* **A dead *watcher*'s incoming port monitor is swept (A.4).** `erlang:monitor/2` on a port records an incoming entry on the port; when the watcher dies first the runtime sweeps it through the same observer payload (`ProcessExit::port_monitors`) + `drain_port_monitor_exits`, so a port never keeps a monitor for a process that no longer exists (`tests/port_monitor_cleanup.rs` is the discriminating white-box pin; a *surviving* watcher's monitor is kept). `erlang:port_info(Port, monitors)` still reads the always-empty `PortMeta.monitors` — the oracle returns `[]` even with a live watcher, so that matches and must not change.
* **`process_info/1,2` answers ~28 items from this runtime's real state** (catalog in `src/native/CONTEXT.md`); the four **execution-position** items are answered only for a scheduled process whose entry is a module export, and the `max_heap_size` map's key order and per-map flags diverge. The `trace`/`last_calls`/`message_queue_data` items are no longer hard-coded: `trace` serves the **live** per-process ERTS tracee-flag bitmask (`0` untraced, `1024` after `erlang:trace(P,true,[call])` — the oracle's own integer shape, translated from this runtime's internal bits via `src/trace.rs::flags_to_atoms`'s table); `message_queue_data`/`last_calls` report this runtime's real placement/saved-calls state (`on_heap`/`false` — the queue is heap-resident and no calls are saved), documented rather than framed as a missing subsystem. The one divergence: `process_flag(message_queue_data, off_heap)` is accepted-and-ignored, so such a process still reports `on_heap` (needs per-process storage in `beam_process` — a cross-crate handoff).
* **A non-byte-aligned `-eval` result cannot be *printed*** — the registered `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (or a container past ~80 columns) with `badarg`; the corpus reads such a value via `bit_size/1`/`is_list`.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget** (one reduction per heap-admission point, `ensure_heap`). A blocked receiver is resumed by a sender (send→wake→resume), a due `send_after/3` timer, or a fired `receive ... after T` deadline. Gaps: a loop **without** an allocation has no admission point; a `receive ... after T` with a **non-statically-readable** delay (Y-register or `after infinity`) still parks; a **capability gap is uncatchable** on the runner path.
* **The runner's execution tier defaults to `JitMode::Auto`** (`runner::tier`) — the native baseline JIT runs a process's **first** entry exactly where `jit_is_switch_safe` proves the entry module free of a module-context switch (no `Apply`/`ApplyLast`, every `CallExt*` target provably synchronous), the interpreter otherwise; `BEAM_RT_TIER` (`auto` default / `baseline` / `interpreter`) overrides it. The tier chosen at that first entry is **remembered on the process** (`ProcessEngine::tier`) and every later slice — a pre-emption on the reduction budget or a `receive` park — resumes on it through `Machine::resume_outcome_with_tier`, so a native-tier process is not demoted to the interpreter mid-life (a `Tier::Interpreter` process is unchanged). Measured: **10.648 s → 0.079 s** on a non-allocating tail loop, **0.296 s → 0.205 s** on allocating tree recursion, and **0.180 s → 0.086 s** (≈2.1×) on the committed `preempt:alloc_loop/1` allocating loop (which pre-empts repeatedly and now keeps the JIT across every slice), with the full suite at mismatch 0 on the new default. Residual engine gap: the JIT driver has no in-machine module-context switch; detail in [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md).
* **CLI divergences and subset gaps live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md)** — `-smp disable` is accepted where the oracle rejects it; `-setcookie` is unmodeled; `-eval`/`-s`/`-run` are documented subsets.
* **NIF loading is live; the host hooks are implemented, with one honest typed gap (A.3)** — `load_nif/2` really `dlopen`s the shared object; a load failure is the oracle's **returned** `{error, {Reason, Text}}`, never a raise. `NifHostImpl` implements the runtime-dependent hooks: `term_to_binary`/`binary_to_term` (ETF), `existing_atom`, `unique_integer`, `system_info` (whose `scheduler_threads` is this runtime's **real** normal-scheduler count) and — via a borrowed `NifHostServices` provider (`RuntimeNifServices`) threaded in at the **per-call** host — `make_ref` and `whereis_pid`. The **load/unload** host (moved into `Runtime::nifs`, so it cannot borrow the runtime) carries `services = None`, so those two stay the typed `None` there. A second `load_nif` for a loaded module is `reload`; a NIF returning a non-term is a typed error, never an abort.
* **`NEW_FUN_EXT`: a compiled module's local fun encodes faithfully; an `erl_eval` lambda stays the honest `unsupported: local_fun`** (its oracle image closes over `erl_eval.erl` internals); no wrong encoding is emitted.
* **Ports match the oracle's observable shape; the read path is thin** (only **stdout** polled, stderr discarded) — `connected` flips to `false` only at `port_close/1`, and a `binary`-stream read wider than 64 bytes is the typed *unsupported* gap. `os:cmd/1` stays the runtime-native host spawn.
* **The send family serves `erlang:send/2` and `erlang:'!'/2` (the `SendBridge`)**; `erlang:send(Port, Data)` (needs the port write path) and the distributed `{Name, Node}` send (contract A.5) stay typed gaps, never a fabricated value.
* **Driver ports (A.4) load and drive a real C driver end to end, with typed gaps** — a `{spawn_driver, Name}` port's `driver_output` (and a driver-emitted `erl_drv_output_term`/`send_term` term) **is** delivered to its owner as `{Port, {data, Data}}`/the term; `driver_select` is real and `driver_set_timer` arms for every attached port (the C substitutes a no-op `no_timeout_callback`, so `-1` only fires for an invalid port); an `OUTPUT` port task (`DriverPortAdapter::ready_output`) **always** drains the port's output queue through the single write path (`DriverPortAdapter::output` → the entry's `outputv`/`output`, the C's `port_command` delivery, `io.c:1782`/`io.c:1597`) and *then* runs the entry's `ready_output` slot, when declared, as the write-**readiness** notification (the C's `ERTS_PORT_TASK_OUTPUT` arm, `erl_port_task.c:1793-1797`) — never as a second write path — so a queued `port_command` buffer reaches the driver whether or not the driver armed a writable fd (the write-armed descriptor is captured before the write, because `output`/`outputv` may re-arm with `driver_select`; `dispatch_ready` keeps only fd resolution and `notify_ready` runs the callback); `driver_async` (no async pool; `Runtime` is `!Send`), `port_control/3` reaching `control`, a captured `send_term`, `ERL_DRV_USE`'s `stop_select` and an OS child (`os_pid`) are not.
* **`erlang:send_after/3`/`cancel_timer/1` are native-floor capabilities; `/4`, `/2`, `start_timer/3,4`, `function_exported/3` and `link/1`/`unlink/1` come from the `RuntimeHooksBridge`** — `erlang:system_info/2`, `read_timer/1,2`, `start_timer`'s absolute form and every other `RuntimeHooks` key are unimplemented.
* **The runtime drives `beam_gc`, but only through the engine's heap-admission point.** A *scheduled* process allocates on its own young heap and is collected in `ExecutionContext::ensure_heap` (armed by the slice's own `BudgetContext`, roots = `x[0..live)` + the Erlang stack); `tests/gc_collect.rs` pins it and `Runtime::gc_stats()` reports the counters. The limits are honest and measured: a workload that allocates through `ExecutionContext::alloc_words` (no `test_heap` admission point, as real Cowboy `cowboy_bstr`-style code does) always falls back to the pointer-stable arena, so it is never collected (`collections: 0`, `fallbacks` ≈ 620·N at N=10 000) — the collector would need an allocation-admission hook there — `Machine` now exposes `with_roots`/`x_mut`/`stack_mut`, but `ExecutionContext::alloc_words` carries no root set (see Handoff to `beam_engine`). A module whose code contains a float-family instruction is never collected over (the crate's `publish_roots`/`scatter_roots` mirror only `x`/stack, so the float-register file would not be relocated; the verdict is cached per module name), and a failed collection halts that process's collection rather than failing the program.
* **The term-heap capacity is still the hard limit** for anything not collected: both exhaustion classes become `error::system_limit` via `error::enforce_term_heap_limit` — `AllocKind::Heap` (the per-process bump allocator) **and** `AllocKind::Message` (the copy engine's destination-heap exhaustion, classified by `beam_message::is_message_heap_exhaustion`) → CLI `beam_rt: system_limit`, exit 1. `DEFAULT_HEAP_WORDS` is `1 << 24`; `+hmax N` is a **real** cap.
* **`erlang:memory/0,1` are adopted** — the `MemoryHook` seam (`src/context/memory_hook.rs`) returns this runtime's real, **measured** figures (the nine oracle keys in oracle order, `total = processes + system`), snapshotted at construction on the `uses_memory_hook` arm; `memory/1` answers in the requested order and `badarg` for an unknown key. `erlang:statistics/0,1` are partly served: `statistics/1` answers `run_queue`, `wall_clock`, `reductions`/`exact_reductions` (a node-global cumulative counter bumped at the real reduction charge site), `context_switches` (a real process-switch counter) and `io` (`{{input,N},{output,N}}` from real port byte counters), **`runtime` (`{Total, SinceLastCall}` user-CPU milliseconds from the runtime's one long-lived `beam_io::cpu_time::RuntimeClock`, whose anchor persists for the runtime's whole lifetime)**, and `scheduler_wall_time` ⇒ `undefined` (never enabled); the scheduler/msacc keys stay the typed gap, and `statistics/0` is not served.
* **The heap switches are modelled; some rejection details are not** — `+hms`/`+hmbs` set a `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000` → 1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1.
* **On-demand heap growth is adopted only on the `beam_process` message-delivery path.** For a **non-exempt** receiver, `Process::deliver` retries a refused `AllocKind::Heap`/`Message` copy after `Process::ensure_capacity` grows the nursery on demand; a bounded `HeapPolicy::max_heap_words` makes that growth refuse (fail-fast), and the refusal is what forces the heap-fragment fallback (`src/mailbox.rs`'s fragment test spawns a 1024-word receiver for exactly this reason). A **relocation-exempt** receiver (see Design Decisions) skips the collect-and-grow retry entirely — its raw refusal reaches the same heap-fragment fallback. `beam_rt`'s own allocation paths do **not** grow — the engine `ensure_heap` hook is a no-op and the BIF heaps cache raw `hp` — so heap exhaustion there still raises `error:system_limit`.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam funnels into ONE pointer-stable `Runtime::arena` (`MinimalContext`, chunked but never moved), which is why the stores below are safe today; routing `alloc_words` onto a per-process **moving** heap would dangle every store that pins a raw engine-arena `Eterm` outside the GC root set.
* **At risk:** `Runtime::persistent_terms` (`context/persistent_term.rs`), `Runtime::trace`'s `MatchSpec::Functions` (`trace.rs`), `Runtime::seq_trace`'s `Token{label,from}` (`seq_trace.rs`), `Runtime::eval_closures` `FunBody.env` (`eval/mod.rs`), `Runtime::timers` `TimerAction::Deliver` (`timers.rs`), `Runtime::runner_state`'s `ProcessEngine.args`/`entry:Fun{fun}` (`runner/entry.rs`), `Runtime::pending_spawns` `PendingSpawn.args` (`runtime.rs`); `MailboxState.markers[].reference` (`mailbox.rs`) and `NameSpec.inline_options` (`port.rs`) still need a check. Safe: `RunnerState.exits`/`results` (the stabilized `eval_heap` copy), `references`/`Timers.refs` keys, ETS (its own arena), `RuntimeContext` (no `Eterm` field), `dist`/`port` structs, `PortMeta`.
* **The one allocation source here:** `Runtime::alloc_words` (`runtime.rs` → `self.arena`), also reached by `RuntimeContext::alloc_words`, `runner/budget.rs`, `Runtime::materialize`/`charlist`; the mailbox `Queue` payloads are copied in by `copy_struct` and their heap is `beam_message`'s to confirm.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate**: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper). **The compatibility gate**: `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes), or manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `Boot` boots first** (`Runtime::boot_if_needed` → `boot::load_preloaded`), which resolves the system code path via `CodeServer::add_system_paths` → `system_ebins` (memoized in a `OnceLock`, i.e. once per OS process) then loads the 22 preloaded `.beam`s — even for a self-contained module with an explicit `-pa DIR`.
* **The system code path is resolved NATIVELY, from the filesystem** (`codeserver.rs::resolve_system_ebins`): `$ERTS_STDLIB_DIR` when set, else `native_system_ebins` reads the *standard OTP installation layout* — `<root>/lib/<app>-<vsn>/ebin`, or an OTP source tree's `<root>/lib/<app>/ebin`, and the `erts` application at `<root>/lib/erts-<vsn>/ebin`, `<root>/erts-<vsn>/ebin` or `<root>/erts/preloaded/ebin`. A candidate root is accepted only when it really holds the probe module (`lists.beam` decides — stdlib is the hard requirement, `kernel`/`erts` are best-effort, exactly as in the oracle's answer), and the directories keep the `SYSTEM_APPS` order (`stdlib`, `kernel`, `erts`). Candidate roots, most specific first: the `erl` on `$PATH` — **resolved to a filesystem path and never executed**, so the installation this runtime is meant to be interchangeable with wins — then this executable's ancestors (an OTP source tree above `erts_rust/target/…`), then `$ERL_TOP`, then `/usr/lib/erlang`, `/usr/local/lib/erlang`, `/usr/lib64/erlang`, `/opt/erlang`; every seed is also tried as `<seed>/lib/erlang` (the `--prefix` release root, e.g. the Nix store layout).
* **The system `erl` is only *run* as the documented LAST RESORT** (`codeserver.rs::erl_system_ebins`, the old `erl -noshell -eval 'code:lib_dir(...)'` probe). It is kept because no filesystem probe can see *every* installation: a version manager (`asdf`, `kerl`) may expose a **shim script** on `$PATH` while keeping the release under a layout reachable from neither the shim nor this executable, and a wrapper `erl` may live outside the release it starts. Asking `erl` is authoritative, and a path is never fabricated: if neither probe produces a stdlib the resolution fails with the typed `cannot locate the system code path: …` error (exit 1). Consequence: a normal installation pays **no** `erl` start-up, so `beam_rt ... run ...` is no longer contaminated by one (measured on this host: `run …slice.beam slice:add/2 2 3` in 0.116 s total, where the removed spawn alone costs ≈0.5 s).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes.** The CLI prints only class+reason, so one `undef` arises from (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), and (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the system modules `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as an `erlang:nif_error(undef|undefined)` stub, so any key the floor and the registry do not serve **raises** `error:undef`/`error:undefined` (exit 1) for *every* argument; registering the key can only change exit 1 → 3 (`unsupported: ...`), never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate; measure with `examples/perf_bif.rs` before and after any change to the dispatch prologue (figures in `TRACE_AND_PERF.md`).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call`, plus the whole-file-descriptor family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs` — the exact list is in `src/native/CONTEXT.md`), so an interpreted `raw_file_io`/`file_io_server` can open, read, write, seek and close a real OS file; the open handles live in a **`Runtime`-owned `open_files: HashMap<u64, std::fs::File>`** (`src/runtime.rs`, keyed by a reference id from `Runtime::refs_mut()` — never a `thread_local!`). The remaining `prim_file` NIF family (`sync`/`truncate`/`advise`/`pread`/`pwrite`/`write_file/2`/`list_dir`/…) stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the **native `file_server_2` service** (`src/native/file_server.rs`, registered at construction — its served server/io-device requests are listed in `src/native/CONTEXT.md`). The device-read path `file:read/2` (`io:request/2`) IS reachable: `net_kernel:dflag_unicode_io/1` is served (the atom `true` for a local pid — `RuntimeHooksBridge::dflag_unicode_io`) and the io-device reply tags are paired (`io_request`→`io_reply`, `file_request`→`file_reply`), so `file:read/2`, `io:scan_erl_exprs/4` and `io:parse_erl_exprs/4` complete and agree with the oracle (`tests/io_scan.rs`); `file:read_line/1` still stops at the unimplemented `{get_line,…}` request. The `{get_until,…}` request (`io:parse_erl_exprs`/`scan_erl_exprs`) IS served end to end by `src/native/file_server/get_until.rs` — the device's read loop drives an engine-backed `beam_io::io_device::Continuation` that runs the real `erl_scan:tokens/4` (see `src/native/CONTEXT.md`). `beam_io`'s `EfileDriver`/`FdDriver` are implemented and tested but **never constructed by this runtime** (only `SpawnDriver` is) and do open/read/write only. `os:set_signal/2` **is** served from the `RuntimeHooks` bridge (`src/context/signal.rs`): one process-global `beam_io::SignalFacility` in a `thread_local`, registered with the poller under a sentinel key (`src/port/watch.rs`), mirroring the oracle's `{ok, OldDisposition}` answers; the port pump then delivers a caught signal's `{notify, Signal}` (the emulator itself, `system`, as the sender) to the process registered as `erl_signal_server`, dropped when none is registered (matching the C).

## Handoffs (owned by OTHER nodes)
`erts_rust/tools/differential/gate.sh` at this node's HEAD: **`total=1320 agree=1319 mismatch=0 unsupported=1 skipped=0 allowed=1 unauthorized=0 stale=1`** — **no case disagrees**; `gate.sh` reports exit `3` only because one allowlist entry must be dropped (**one** recorded gap has closed and gone stale), so re-run it for the live per-contract split. The one `unsupported` is an honest capability gap, never a `mismatch`: `wire/new_fun_ext_encode` (an `erl_eval` lambda's `NEW_FUN_EXT` identity — `erl_eval` internals, structurally unclosable; see [`M1_GAPS.md`](M1_GAPS.md)). The stale entry is `proc_signals/statistics_runtime_unsupported` (`erlang:statistics(runtime)` is now served from the runtime's one long-lived `beam_io::cpu_time::RuntimeClock`); dropping it is a `tools/differential` ratchet update, owned outside this node.
* **A.7/A.9 boot — COMPLETES.** `Runtime::boot_from_script` executes the real `bootstrap/bin/start.boot` (OTP 30 / erts-17.1, **22 instructions**) **to completion**: the last is instruction 21, `{progress,started}`, and the CLI `-boot` action exits **0** with empty stdout/stderr for every path form of the boot-file value, so the differential case `boot/proc_lib_start_link_blocks_the_boot_path` now **agrees** with the oracle (full analysis + repro in [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md); boot-stop observability is `boot::BootStop` + `Runtime::boot_from_script_reporting`, a harness entry a happy-path boot never reaches). Remaining gaps, owner per link: (1) **`beam_engine`** — on the non-blocking entries `fold_outcome` folds a callee's `Wait` into `error::blocked()` (the scheduled path uses the outcome-aware entries); (2) **`beam_rt`'s `src/native/file_server.rs`** — `io:request/2` reaches the io-device **read** path (`file:read/2`, `io:scan_erl_exprs/4`, `io:parse_erl_exprs/4`) and completes; `file:read_line/1` still needs the `{get_line,…}` io-device request, which is unimplemented;(3) **`beam_rt`'s `src/native/init.rs`** — `init:get_arguments/0` omits the oracle's automatic `root`/`bindir`/`progname`/`home` entries, so a `RuntimeConfig::default()` runtime stops earlier (index 16); (4) **`beam_bifs`** — whatever the started applications still need past the above. `prim_file` serves 16 entries (incl. the whole-file-descriptor `open`/`read`/`write`/`close`/`position` family in `src/native/prim_file.rs`) and `erts_internal` 14 BIFs natively; the rest are itemised in `src/native/CONTEXT.md`. **`-boot FILE` drives the boot script:** the `Boot` action (`src/cli.rs::drive`) calls `Runtime::boot()` (22 preloaded `.beam`s) and then `Runtime::boot_from_script(&path)` (`run_boot_script`, resolving the value through `boot_file_argument`/`boot_file_root`/`resolve_boot_file`; a missing script is the typed `cannot get bootfile`). A plain start (`-s`/`-run`/`-eval`/`run`) keeps the preloaded-only floor.
* **The native `file_server_2` service is the server/io-device side the boot path needs** (`src/native/file_server.rs`) — it answers the `{'$gen_call',{Pid,Tag},Request}` form with `{Tag, Reply}` to `Pid` (a `From` tag that is a process **alias**, OTP 24+'s fast local-`infinity` path, is a typed `unsupported`) and serves the server requests `lib/kernel/src/file.erl` issues (`{open,Name,ModeList}` → `{ok,IoPid}` or `{error,Reason}` with `enoent` for a missing path / `eisdir` for a directory / `einval` for an empty name / `badarg` for a non-list mode list / else the host errno; `read_file`, `list_dir`, `delete`, `rename`, `make_dir`, `del_dir`, `read_link`, `make_link`, `make_symlink`, `altname`, `get_cwd`) plus the io-device requests `close`/`sync`/`datasync`/`truncate`/`{position,At}`/`{get_chars,…}`/`{put_chars,…}`; every other command is the typed `unsupported`, never a fabricated reply. The wire tables and the module docs are the source of truth: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **`{get_until, …}` (the io request `io:parse_erl_exprs`/`scan_erl_exprs` use) IS served** (`src/native/file_server/get_until.rs`): the device's read loop drives an engine-backed `beam_io::io_device::Continuation` that loads `Mod` and runs `Mod:Func(Cont, Data, XtraArgs…)` (`erl_scan:tokens/4`) on the interpreter, decoding `{more, Cont}` / `{done, Reply, Buf}` and stashing `Buf` as the device's `State#state.buf`. The library-level path is live end to end — `io:request/2`'s `net_kernel:dflag_unicode_io/1` probe is served and the io-device reply tags are paired — so `io:scan_erl_exprs/4`/`io:parse_erl_exprs/4` complete and agree with the oracle (`tests/io_scan.rs`); `file:read_line/1`'s `{get_line,…}` is the residual gap. Remaining typed gaps of the request itself are in [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **`beam_process` / `beam_message`** — a split heap+mailbox borrow, an owning drain for the wake list and a `!Send`-friendly `SchedulerPool`; detail in [`M1_GAPS.md`](M1_GAPS.md). The `*_with_ports` forms now exist (`Scheduler::{run_slice,run_ready}_with_ports` and `ProcessTable::{service_signals,terminate}_with_ports`), so the seam for a death/termination sweep that must also clean a dying port's monitors is present; this crate does not route its slices through them, because holding the port-registry borrow across interpreted code turns every port BIF into the typed `unsupported` (see `Runtime::with_port_table`), so the pass discharges the same obligations at its round boundaries through the exit observer (`runtime/ets_owner.rs`) instead.
* **`beam_engine`** — (a) an **in-machine module-context switch** in the baseline JIT driver — a `Step::Enter` there is the typed `unsupported("jit: module context switch outside the interpreter driver")`, which is exactly why `runner::tier::jit_is_switch_safe` must refuse a module containing an `Apply`/`ApplyLast` or a `CallExt*` whose target is not provably synchronous (the cross-module `resolve_external_call` seam, incl. `Instr::Apply`/`ApplyLast` via `families/funs::apply_target`, is otherwise adopted); (b) a `MinimalContext` **arena word/byte accessor** (the arena is chunked but exposes none), so `erlang:memory/0,1`'s `processes`/`processes_used` can be real on the `-eval`/single-pass path; (c) an **allocation-admission root-set hook** — `Machine` now exposes `with_roots`/`x_mut`/`stack_mut` and a per-instruction `reduce` hook, but `ExecutionContext::alloc_words` carries no root set, so an `alloc_words`-only workload is never collected.
* **`beam_bifs` / `src/context`** — feed `NodeIdentity` from `Runtime::dist_node()` so `erlang:node/0` and the node-valued `system_info` items reflect a live `-sname`/`-name` node.
* **Distribution, phase 2** — the inbound link/exit/monitor/alias `DOP_*` families need a `beam_process` **remote-peer** seam (plus an alias table); `DOP_SEND`/`DOP_REG_SEND` already reach local mailboxes, and a live-peer loop past the handshake needs the `FragmentAssembler` receive-buffer coupling.
* **`beam_io` / `beam_abi`** — finish the driver-port lifecycle: `driver_async` needs a `beam_abi::DriverHost` seam that can fire `ready_async` (`beam_rt` is `#![deny(unsafe_code)]`), and `erl_drv_monotonic_time`'s phase differs because `beam_abi` reads `CLOCK_MONOTONIC` from the system epoch; detail in [`M1_GAPS.md`](M1_GAPS.md).
* **`beam_bifs` — the registry dispatch cost and the hook-set drift risk.** The per-lookup owned-`String` key tuples (`contains` + `lookup` on the dispatch path) are the largest attributable residual; a borrowed-key `lookup(&str, &str, u32)` would remove them. This crate's `uses_*` gates now delegate to `beam_bifs::hook_sets`' exported `needs_*`/`*_BIFS` tables, so a new consumer is picked up automatically (no per-crate drift). `RUNTIME_HOOKS_BIFS` has 195 entries (`hook_sets.rs`'s `assert_eq!`).
* **`beam_bifs` — the `ets:setopts/2` heir gift copy and the tid-ref mint.** The owner→handle roster **exists** (`TableRegistry::handles_owned_by` + `owner_of`), so a dead owner's **unnamed** table is now reclaimed through it (see the Known Issues ETS bullet). The remaining live gap is `ets:setopts/2`'s gift-data aliasing: `beam_bifs`'s `src/ets/adopt.rs::setopts_2` installs `{heir, …}` through the non-copying `beam_ets::Table::setopts` where `Table::install_heir` (a table-owned deep copy) is meant — the runtime can mitigate only the `ets:new/2` path (`Runtime::own_heir_gift`). Separately, this runtime materializes an unnamed table's tid reference through its own `runtime::ets_owner::tid_ref_thing` (a fresh `RefAllocator` walked to the handle, because the runtime's ref id space differs from `beam_bifs`'s); a shared mint (`beam_bifs::access::make_ref_thing` widened to `pub`, or a `MonitorRef::from_id(u64)`) would remove that loop.
* **`beam_gc` — peak RSS still grows in N.** The retained set grows because `beam_gc`'s `resize_nursery` feeds `young_after_collection` the **pre-reset** used count, and `young_after_collection` (`src/policy.rs`) steps one growth-table entry upward (`next_words(…, 1)`) rather than settling on the C's fixed point, so a process under sustained allocation steps up once per collection and never reaches a steady state (`collect_major`'s transient is ≈2×). `memory(system)` is flat, so no `beam_rt` change is the lever — the sizing policy is `beam_gc`'s.
* **`beam_io` — the port table sits behind one `RefCell`.** `Runtime::with_port_table` is the short-borrow seam and the quiescence predicate reads `PortRegistry::has_nothing_to_poll`, but `beam_io::PortRegistry` keeps its `ids` port-number table private behind the same single `RefCell` as the live ports, so the runtime cannot hand the process table and the port table out as disjoint borrows and therefore cannot route its slices through `Scheduler::run_ready_with_ports` (a cross-crate handoff, not a bug); a split accessor over the id table would unblock it.
