# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs`, the **CLI flag surface** (**A.6**) and **`system_info/1`** + `erlang:process_info/2` (**A.8**).
It owns the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded drives (`src/boot/drive.rs`) — which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**); every CLI action but `-version` drives it before its own start instruction, so a silent action exits **0** with empty stdout and stderr (tail blockers, live `whereis` facts: `M1_GAPS.md` *A.7/A.9 boot*).
It owns the **concrete `ExecutionContext` glue** adapting the engine's seams onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable), the **A.4 runtime side of ports** (`open_port/2` decoding, `port_info`, the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s), the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and `{abs,true}`) and a finite `receive … after T` (`src/timers.rs`, advanced only by the scheduler loop), and the **distributed node** (A.5 phases 1–2: the accepting half `src/dist.rs` + the inbound `LocalDeliverySink` in `src/dist/inbound.rs`, the connecting half `src/dist_client.rs`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)
Per-child API detail lives in the child nodes' own `CONTEXT.md`; each entry is a crate-level summary + pointer.
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces; the pass family drives processes → ports → timers → distribution in bounded steps; `RuntimeRunner` implements `beam_process::ProcessRunner` — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking, the NIF-dispatch order, the **lent-`TableRegistry` propagation** into a nested fun application (a nested `ets:*` inside a `lists:foldl` fun reaches the folded table) and `NodeIdentity`'s **real local-node hash** (`node_hash.rs`, so a `term_to_binary(T,[local])` image is real) — [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver.rs`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump, `port_info`'s **real cumulative per-port byte totals**), the native-floor `erlang:port_control/3` (the driver's `control` callback behind `PortRegistry::port_control`) and the driver C-ABI host for `{spawn_driver, Name}` (a built-in name resolved before `dlopen`) — [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
### `dist.rs` + `dist/` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` on the first `pump()` via `ALIVE2_REQ`); `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**).
Both inbound drives drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`), so a malformed or forged control message **retires that one link** instead of reaching the sink.
`LocalDeliverySink` routes the message and route-free receipt families through `ProcessTable`'s inbound primitives (each emitting **no** outbound `DOP_*`); only `SpawnRequest`/`SpawnReply`, `Delivery::Other(_)` and the `UnlinkId` `id != 0` ack-owing half (`id == 0` is `Delivered`) stay typed `Unsupported`. The pass is gated by `Runtime::inbound_delivery` (default **ON**); per-family routing table, pump budgets, the envelope rule, `NodeName::parse`/`resolve_cookie` and the `DistRouter` install site: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — precedes the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; the registry offers `new()` (anchors the `enif_*` codegen unit), `is_loaded`, `insert`, `lookup` (**the dispatch predicate**) and `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`: a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, holding `Some(&'a mut dyn NifHostServices)`; `alloc_env`/`free_env` are real, `make_copy` is the **identity**, and the shared table reaches `NifHost::atom_table`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by name. All six state-needing `NifHostServices` hooks are live on a call (`make_ref`, `whereis_pid`, the two liveness answers, the port relations `is_port_alive`/`port_command`); only the load/unload host leaves them the trait default — `M1_GAPS.md` *NIF (A.3)*. `build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`, `mailbox.rs`
`config.rs` type shapes: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs`, `HeapOptions`/`MaxHeapFlags`/`GcStrategy` (`EmulatorDefault`/`Immix`) and `RuntimeConfig::with_heap_options`; the rest are catalogued by the Routing Table below (**per-module detail: `src/{cli,info,boot}/CONTEXT.md`**).
### Observability (`trace.rs` · `seq_trace.rs` · `crash_dump.rs` · `perf_map.rs`, contract A.8)
Process tracing, sequential tracing, the ERTS-format crash-dump writer behind `erlang:halt`, the `+JPperf` JIT symbol map, the **execution-trace seam** (`call`/`return_from`/`return_to` over `beam_engine`'s `ExecutionContext::trace_event`, live on both the single-pass and the scheduled paths) and the three per-call overhead harnesses (`examples/perf_bif.rs` inlineable fixture BIFs, `examples/perf_call.rs` registered-BIF dispatch, `examples/perf_copy_out.rs` the BIF-result copy-out) — **[`TRACE_AND_PERF.md`](TRACE_AND_PERF.md)**. ## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The dispatch table (the source of truth), every implemented/not-implemented BIF and the drift guard live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
**`process_info/1,2` stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form.
**`monitor/2,3`/`demonitor/1,2`, `alias/1`/`unalias/1` and the reference-alias send destination come from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed as the C's `erts_monitor_opts` (`bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias; as a **send destination** that reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams, and a `{alias,_}` on a **port** monitor or a **remote** target propagates the typed `unsupported` (`tests/alias.rs`).
**`erlang:garbage_collect/0,1` come from the floor** (`src/native/erts_internal.rs`, A.7): **no BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet`, which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`, served only where the root set is owned (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first.
**`code:*` reads and the code path are the floor over `CodeServer`, alongside a live `code_server` process** (started by the booted `kernel_sup` on every boot-driven route; `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7), so the `boot/*` cases touching `code:*` are **shape-only**). The floor owns the **one** authoritative path store for the path readers **and** the mutators `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1`; the un-migrated mutators edit the live server's second, floor-invisible store, so **`src/native/code.rs`'s `code:*` behaviour must not change** (store rule, key list and `code:ensure_modules_loaded/1`'s rationale: `src/native/CONTEXT.md`).
**The A.9 installation view is catalogued in `src/native/CONTEXT.md`**: `init:get_argument/1`'s four automatic flags (`root`/`home`/`progname`/`bindir`), `init:script_id/0`, `code:lib_dir/2`, the `application` view and `erlang:module_loaded/1`'s truthfulness to *this* runtime's loaded set (so `module_loaded(kernel)` stays `false`).
**Three server processes are native state, not scheduled code**: the root process (registered as `init`), the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) and the **`erl_prim_loader`** stand-in (`src/runtime.rs`, A.7/A.9) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery work and `erlang:whereis(erl_prim_loader)` answers a live pid on **every** route (nothing in `bootstrap/bin/start.boot` claims it). The `file_server_2` service is spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus `-boot FILE`), so the booted `kernel_sup`'s own child owns the name; `Runtime::new` registers it only when the runtime drives none.
**`erlang`-namespace fallback**: `call_bif` consults the floor, then the registry, then the `erlang` namespace — a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`; `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (intersected with what the live registry does not own) and its drift guard are the authority.
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar: the Erlang **expression** subset (`src/eval/{parse,ast,mod}.rs`) walked `erl_eval`-style, its arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**), and a **quoted atom** a distinct `Tok::QuotedAtom` (an atom that merely *spells* a keyword — `'receive'`, `'end'`, `'not'` … — is a plain atom, and a quoted call head is an ordinary call).
  Outside the grammar is a **capability gap** (exit 3) — the grammar, the quoted-atom rule and the named-fun-form rejection: [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2.
  `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2).
  **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`).
A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason).
So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` exceeds the 60-bit small range, so it materializes as a bignum); `context_reductions` is answered as `4000`, the canonical ERTS quantum `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented.
  The pre-existing (not restructured) oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md) *File-size overages*.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle.
  When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer; flattening is the **last resort** for an unresolvable payload, never a substitute for adopting handles (the send path unions three source families, `src/context::send_source`, so a resolvable payload takes the SHARE route).

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (by the section named after each bullet); the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **A `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work, not `beam_rt`'s dispatch** — the wired path is allocation-free and every decode seam uses a per-thread memoized `AtomTable` image; the atom-intern commit is append-only (`CodeServer::intern_pending`, copy-on-write only for an outstanding handle) — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **No interactive shell; the node is otherwise passive** — the message families and the inbound link/exit/unlink/monitor/demonitor/monitor-down/group-leader families route through `beam_process`'s **route-free receipt** primitives (*Handoffs*), each mirroring the C's `break; /* Done */`, never echoing a `DOP_*` — `M1_GAPS.md` *Distribution and the node (A.5)*.
* **An inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** (an immediate-only, uncopied, unrooted slot; the plain `DOP_SEND*` forms pass the wire's `''`) — a typed divergence from the C — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order (compared as a set), and `badarg` for a module not loaded here — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures (`whereis(init)` **does** agree) — `M1_GAPS.md` *Own-state answers*.
* **`process_info(P, binary)`** is served from the target's own off-heap refc-binary roster as the oracle's `{Ptr, Size, Refc}` tuples (`[]` when none); a `process_info(self(), binary)` inside the running slice can omit a payload that slice just built (a safe roster omission) — `M1_GAPS.md` *`process_info/1,2`*.
* **Process-control gaps** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id — `M1_GAPS.md` *Process-control families*.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual is `ets:setopts/2`'s gift-data aliasing — `M1_GAPS.md` *ETS ownership*.
* **`process_info/1,2`** answers ~28 items from real state (the `max_heap_size` map's key order/flags diverge; `message_queue_data, off_heap` is accepted-and-ignored); `port_info(Port, monitors)` stays `[]`, matching the oracle; a non-byte-aligned `-eval` result (or a container past ~80 columns) cannot be printed by the registered `io:format` `~w`/`~p` printer — `M1_GAPS.md` *`process_info/1,2`* / *Port monitors (A.4)* / *Printing*.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget** — the **refusing** `BudgetProbe::charge` (the per-instruction `reduce` hook and the two heap-admission doors, so a non-allocating loop IS pre-emptible on the interpreter tier) plus the **pricing**, never-refusing `BudgetProbe::spend` (one unit after `call_bif`/`call_bif_in_machine`, one before `resolve_external_call`/`resolve_local_call`), so a **native baseline block's** budget reflects its work (`reductions == 5N + 9` on the BIF-and-call fixture, saturating at a flat **4 006** = the 4 000 budget + a 6-unit epilogue). The residual: a **non-allocating BIF-and-call-only loop still ends no slice of its own** on the native tier (its one `Yield` is the epilogue's — `slices=2 yields=1 collections=1`, and a same-shape fixture with no epilogue ends zero slices), and a call seam cannot yet refuse (a refusal there parks at block entry — a `beam_engine` handoff) — `src/runner/CONTEXT.md` *Known Issues*, `M1_GAPS.md` *Scheduler / runner*.
* **`process_info(P, garbage_collection)`'s `minor_gcs` is `Collector::minor_since_major`, NOT a collection total** — every fullsweep resets it to `0`, so it can sit flat while the process collects once per iteration (`native/memory/mod.rs` reads the live `process.collector().minor_gcs()`). The monotone totals are `Runtime::gc_stats().collections` (published as `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}`) and `beam_gc::AnyCollector::stats()`.
* **An allocate-and-abandon loop is collector-bound, never arena-bound** — the churn shape allocates on the running process's own young heap (GROWTH-only `Process::grow_nursery` + the BIF-result copy-out, never collecting), so a flat `heap_size`/`erlang:memory(processes)` is a **converged capacity** and the collector's per-iteration Cheney traversals *are* the per-op cost; the counter relations are `src/runner/CONTEXT.md`'s (`collections == 7N − 1`, `major == 3N / 2`, `peak_young_spaces == 1`, young capacity 233 words for `churn` / 610 for `heap_growth`).
* **Execution tier defaults to `JitMode::Auto`** (`src/runner/tier.rs`) — the native baseline tier for every process entry, compiled **lazily per function** on first entry of a `(func, pc)`; `BEAM_RT_TIER` overrides it (`interpreter` is the kill switch) — [`PERF.md`](PERF.md), `M1_GAPS.md` *Execution tier*.
* **CLI divergences and subset gaps** (`-smp disable` accepted, `-setcookie` unmodeled, the `-eval`/`-s`/`-run` subsets) live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
* **NIF loading is live** (`load_nif/2` really `dlopen`s); eight `NifHostServices` hooks stay at the trait default (`M1_GAPS.md` *NIF (A.3)*); a compiled module's local fun encodes faithfully, an `erl_eval` lambda stays `unsupported: local_fun` — `M1_GAPS.md` *Funs*.
* **Ports match the oracle's observable shape** (one `{Port,{data,Data}}` per driver read at the width the child wrote, stderr inherited or merged under `stderr_to_stdout`, `connected` false only at `port_close/1`), the `line`/`{line,N}` stream option is adopted end to end, and `port_command/2,3` consults the driver's busy state so `[force]`/`[nosuspend]` answer as the oracle does — `M1_GAPS.md` *Ports, drivers and the send family (A.4)*, [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **The send family** serves `erlang:send/2`/`erlang:'!'/2`, including a **reference-alias** and a **remote** destination; `erlang:send(Port, Data)` and an unreachable remote destination stay typed gaps, and the BIF route cannot see the sending machine's in-flight refc-binary handles, so a term the machine *just* built off-heap **flattens** — `M1_GAPS.md` *Ports, drivers and the send family (A.4)*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *Known Issues*.
* **Reference aliases: the honest residuals** — a send to a reference that is **not a live alias** is the typed `badarg` (the C silently drops it); `monitor(process, self(), [{alias,_}])` registers where the C clears it for a self-monitor; the **unclosable residual** is reference **identity** (a bare reference and a monitor/alias reference with equal ids are `=:=`, closing which needs the two allocators unified) — `M1_GAPS.md` *Reference aliases*, [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **Driver ports (A.4) load and drive a real C driver end to end**; the monitor view is a **per-round snapshot**, and the typed gaps are `driver_async`, an OS child, a `control` reply from the driver's own memory, a `NULL` reply with `PORT_CONTROL_FLAG_BINARY`, and a driver arming **more than one** registration per direction — `M1_GAPS.md` *Ports, drivers and the send family (A.4)*, [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **`erlang:send_after/3`/`cancel_timer/1` are native-floor capabilities**; `/4`, `/2`, `start_timer/3,4` (incl. `{abs,true}`), `function_exported/3`, `link/1`/`unlink/1` and `os:set_signal/2` come from the `RuntimeHooksBridge`, while `erlang:system_info/2`, `read_timer/1,2` and every other `RuntimeHooks` key are unimplemented — `M1_GAPS.md` *Timers*.
* **The runtime drives `beam_gc` at four collection points, three of them heap-admission doors.** `ensure_heap`/`ensure_heap_full`/`alloc_words_rooted` (`src/context/gc.rs`) are reached only where *code* allocates (`test_heap`/`allocate_heap`); the fourth, `src/context/gc/reds_door.rs::collect_at_reds_boundary` from the runner's `Yield` arm, needs no request. A float-family module is collected over **only** at the two full-root doors (the narrow `ensure_heap` door hands over just an x prefix and the stack), a failed collection halts that process's collection rather than failing the program, the **term-heap capacity is the hard limit** for anything not collected, and on-demand growth is adopted at both doors and on the message-delivery path — `M1_GAPS.md` *GC / heap model*.
  **The boundary door is what makes a BIF-only loop collectable**: a body allocating solely through registered BIFs emits no admission instruction and the copy-out can only *grow* the nursery, so on the doors alone its `heap_size` (the chain of retired spaces) climbs with N (`collections` 0). Its gates are a **reduction interval** (`REDS_BOUNDARY_MIN_REDS`, at most one collection per pre-emption) and a **7/8** young-space occupancy watermark (the C's `ERTS_VBUMP_ALLOC_REDS` rule); it publishes the machine's **whole** `RootSet` (`ALL_LIVE`), never the pointer prefix, because the resume scatters `ALL_LIVE` back. On the allocation-shaped hot shapes its ration is what keeps it off the per-call path: measured on the `gc_bound churn` shape it fires on **105 / 214 / 533** of **904 / 1 809 / 4 524** boundary checks at N = 2 000 / 4 000 / 10 000 (one in 8.61 / 8.45 / 8.49 — 0.75 % of the run's own collections) while the shape's per-call rate stays flat at 6.9820 / 6.9830 / 6.9840 collections and 1.4978 / 1.4979 / 1.4980 majors and its nursery chain stays one 609-word space. The door-ON vs door-OFF `Δ` itself (formerly quoted as "exactly inert, one build") is **not verified any more**: it needs a door-disabled build, i.e. a throwaway `#[cfg(test)]` early return in `src/context/gc/reds_door.rs`. Counters `src/runner/CONTEXT.md` *Measured*, pinned by `src/runner/tests/{reds_door,boundary_cost}.rs`.
  **On the default (native-baseline) tier this door is unreachable, and the residual is a fairness defect as much as a GC one**: a natively linked block crosses neither the per-instruction reduction hook nor an admission door, and `spend` only makes its budget truthful (`reductions == 5N + 9`) — such a loop never exhausts a slice of its own accord, and the one `Yield` it reads is the run epilogue's (`run` reads `slices=2 yields=1 collections=1 major=1`, a flat 4 006 charge and `heap_size` on the 233-word collector floor; a same-shape fixture with no epilogue seam reads `slices=1 yields=0`), where `BEAM_RT_TIER=interpreter` reads 10 slices / 9 yields / 9 collections / 1 major / 36 018 reductions and the same 233-word heap — `M1_GAPS.md` *Scheduler / runner*, pinned by `src/runner/tests/slice_charging.rs`.
  **The door's collection is a young-only minor first, and escalates to a full `collect` only when the promotion cannot fit** (`src/context/gc/reds_door.rs:306-308`): `Process::collect_kind(CollectionKind::Minor)` (`beam_process/src/process.rs:1585`, over the rooted-collection seam) evacuates the nursery only and reports typed heap exhaustion *before copying a word* when the mature space cannot absorb it; that refusal is met with the escalating `Process::collect` (grow, and fullsweep if the growth is still short), because halting on it would disable collection for the rest of the process's life. So a cadence fullsweep no longer comes from the door itself — it comes only from the mature generation being unable to take the promotion. Handoff: `beam_gc::AnyCollector::collect_minor` — a young-only collection that *grows* the mature space instead of refusing — would remove the escalation entirely (owner `beam_gc`; `beam_rt/src/context/gc/reds_door.rs`'s own comment names it) — `M1_GAPS.md` *GC / heap model*, `src/runner/CONTEXT.md` *Measured*.
* **The unscanned-root valve declines a collection only where relocation is genuinely unsafe.** `context/gc.rs::root_is_unscanned` is a **two-fact** predicate — the word lies in an **unscanned** region (`word_region` → `WordRegion::{Scanned,Foreign}`) **and** it forwards at least one **scanned** pointer (`forwards_scanned_word` over `beam_term::layout::for_each_child_slot`) — so a foreign leaf or all-immediate block (a `make_ref/0` block, a ref/pid/port block, a float, a bitstring, the empty tuple, a tuple of immediates) is **inert**, as is a **null or unaligned** word (`dereferenceable_pointer`). The per-pid latch (`GcState::foreign`) is cleared only from the doors that hand the walk the machine's **whole `RootSet`** (`ensure_heap_full`, `alloc_words_rooted`, `reds_door`) and only on `ValveVerdict::foreign_free`; the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` may **open** it but never clear it — `M1_GAPS.md` *GC / heap model*.
  Consequences: a reference-minting loop keeps `erlang:memory(processes)` **flat** (6.91 MB at N = 20 k / 200 k / 1 M, below the oracle's 13.7 MB — `context/gc/refs_plateau.rs`) and a loop holding one **foreign-rooted container** live still collects (`tests/foreign_root_loop.rs`: `(N + 6)/17 <= collections <= (N + 6)/17 + (1 + slices/50)` on a flat 233-word heap — the fill law as an exact floor plus the measured per-pre-emption boundary surcharge, whose ladder runs 0 / 0 / 0 / 1 / 0 / 1 / 3 / 5 / 6 at N = 5 000 … 200 000 over 9 … 350 slices and is irregular in the slice count, so it is bounded by a rate and not by a flat figure).
* **`erlang:memory/0,1` are adopted**; **`erlang:statistics/1` is partly served**, its `garbage_collection` key carrying the runtime's **real** node-global counters `{collections, reclaimed, 0}`, with the per-scheduler/msacc keys and `statistics/0` typed gaps; **the heap switches are modelled** — `+hms`/`+hmbs`/`+hmax*` land on the process's `beam_gc::HeapPolicy` (CLI **and** `spawn_opt`'s `{max_heap_size,…}`), observable through `process_info(P, max_heap_size)`/`system_info(max_heap_size)`; `+hmax` does **not** bound the growth-retired nursery **chain** (`beam_gc::Nursery::grow` defect — handoff) — `M1_GAPS.md` *Memory and statistics* / *Heap switches*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *GC accounting*.
* **`process_flag(max_heap_size, Map|Int)` is implemented, and its bound is not enforced.** One shared parser `src/native/process.rs::max_heap_setting` → `src/config.rs::MaxHeapSetting` (keys `size`/`kill`/`error_logger`/`include_shared_binaries`, a bare integer as `size`, the caller-only scope, the oracle's previous-value answer in the C's key order `error_logger, include_shared_binaries, kill, size`, and the `badarg` matrix — missing `size`, a `size` below the process's own `min_heap_size` floor, a non-integer/negative/float `size`, a non-boolean flag, a non-map value) serves both this BIF and `spawn_opt`, stored per pid in `Runtime::max_heap` and read by `process_info(P, max_heap_size)`/`garbage_collection`. Residuals: **no kill at `size` and no `error_logger` report** (no policy setter on `beam_process::Process`/`beam_gc::AnyCollector` — handoff `beam_process::Process::set_max_heap_size(&mut self, size: usize, flags: MaxHeapFlags)`), and `spawn_opt`'s `{max_heap_size, Map}` **flags are still dropped** (only `.size` is kept) — `tests/max_heap_flag.rs`, `M1_GAPS.md` *Heap switches*.
* **A.9 self-hosted compile: the first real self-hosted *chain* runs in ONE invocation** (`tests/selfhost_chain.rs`: a single `-eval` compiles an installed stdlib module in process, adds its outdir to the code path, loads and calls the fresh `.beam`, byte-identical to the oracle), and the in-process chain compiles **all 86 of the 86** `lib/stdlib/src/*.erl` the oracle itself compiles byte-identically; **no full self-hosted build** yet — `M1_GAPS.md` *A.9 E0*, [`EPP_SCHEDULED_ROUTE_FINDINGS.md`](EPP_SCHEDULED_ROUTE_FINDINGS.md).
* **There is no io server; the `io` device floor serves the request wrappers**, so the installed compiler's `catch`-handler diagnostics are no longer masked; residuals: a live non-stdio device pid is the typed `unsupported`, and `io:put_chars/1,2` accepts-and-ignores its device — `M1_GAPS.md` *Printing*, [`src/native/CONTEXT.md`](src/native/CONTEXT.md) *The `io` device floor*.
* **A process entry naming a host-served MFA is dispatched, never entered as that module's code.** `ProcessEntry::Export` asks `RuntimeContext::host_serves` (runtime-native floor ∪ a loaded NIF module ∪ a registered `beam_bifs` key) on its **first** entry only and runs a hit through `call_bif` with the BIF's value as `x(0)` — what makes a fired `timer:apply_after/4` deliver its message (`timer_server:do_apply/2` spawns `erlang:send/2`) and `spawn(erlang,abs,[-3])` yield `3`; a resolvable module's export keeps the label route (a nested `run_export` cannot park a blocking callee). Pinned by `tests/bif_entry_spawn.rs` and `boot::bootscript::an_apply_directive_naming_a_host_served_bif_is_dispatched_not_entered` — [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md), [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **The `foreign`/`emqx_base62:encode` per-call marginal is flat in N and equal to the reference tree's**: `beam_loader`'s literal-area tagging keeps the driver's literal-area binary off-heap, so the unscanned-root valve does not fire, collections run and the retired-nursery chain stays collapsed; the *other three* `foreign` sub-cases read 1.25×–1.60× dearer than a tree whose allocation-shaped loop runs **zero** collections and retains an unbounded heap — HEAD's memory management, not dispatch cost. Figures: [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*.
* **Placeholders where a truthful source exists** — `NodeIdentity`'s **creation** is a fixed `0` (the node atom itself is the runtime's live `Runtime::local_node()`), and the flag-driven `system_info` literals report their defaults because no CLI arm preserves the driving flag — `M1_GAPS.md` *Placeholders*.
* **A booted runtime leaves a live `logger_server` registered as `logger`** — a second `logger_server:start_link/0` reports `{error,{already_started,Pid}}`, matching the oracle — and the script's tail blockers are served **in-node** from the native floor (`RuntimeContext::try_native`) or runtime state — `M1_GAPS.md` *A.7/A.9 boot*, [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md), [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **A registered-BIF result is re-homed and the pool rewound** (**load-bearing**: the copy makes it collectable) — onto the process heap, else the table-less (`-eval`) store; residuals — a NIF result, an escaping `DispatchHooks` arm and an error leave their container on the pool, the store absorbs a kept result's words and only grows, and the copy-out cannot collect — `M1_GAPS.md` *The BIF-result copy-out*, `src/context/IMPLEMENTATION.md` *The table-less arm and its store*.

* **Run the crate gate** `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper), and the compatibility gate `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes; manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`).

* **Oracle-order caveat:** `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure list's order is not stable (measured 117 × `c_m,b_m,a_m` vs 3 × `b_m,c_m,a_m` in 120 probes) — assert failure pairs as a **set**, never an ordered `vec!`. `tests/fixtures/` must not be passed to the oracle as a single `-pa`: it contains a `lists.beam` that shadows stdlib.
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script): the system code path is resolved natively from the filesystem (`CodeServer::add_system_paths` → `system_ebins`, a `OnceLock`; the system `erl` is only the documented LAST RESORT — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*) and the 22 preloaded `.beam`s load even for a self-contained module with an explicit `-pa DIR`.
* **Whole-process startup is ~0.44 s (release), CPU-bound, and issues 0 `clock_nanosleep`.** The boot drive's `TimerWait::ImminentWithin(TIMER_PUMP_SLICE)` sleeps only when the earliest pending deadline is **within** the window (`src/boot/drive.rs`), so a 1 s / 1 h `gen_server` `WaitTimeout` never sleeps nor busy-spins while a short `receive … after T` (T ≤ 100 ms) is still slept to and resumed; a blocking `run`-route round is likewise free because `PortRegistry::has_nothing_to_poll` (`src/port.rs`) treats an **armed-but-idle** `os:set_signal/2` disposition as nothing-to-poll. Figures — `-eval 'halt(0).'` ≈ 0.44 s, `run <slice.beam> slice:add/2 2 3` ≈ 0.47 s, 927 filesystem stats (**2** on `os.beam`, since `Runtime::find_module_file` answers an already-loaded module from `CodeServer::loaded_path`) — in [`PERF.md`](PERF.md).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates — `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as such a stub, so any key the floor and the registry do not serve **raises** (exit 1) for *every* argument; registering the key can only change exit 1 → 3.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** `call_registered` runs per call, so any handle built there must be gated by a `uses_*` predicate and every per-call input the prologue derives belongs in the 8-slot dispatch memo; measure with `examples/perf_call.rs` before and after a prologue change (`examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch) — [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md) *Dispatch cost*, [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *DISPATCH-CUT* / *COPY-OUT-CUT*.
* **The copy-out is a measured 149 ns/call, and it is *architectural*, not slack.** `examples/perf_copy_out.rs` splits `binary_to_term/1`'s **508 ns** as prologue 82 + `beam_codec` decode 218 + **copy-out 149** + residual 59 (`term_to_binary/1` is 252; the copier alone 142 ≈ **2.1 ns per copied word**) on the published `etf_roundtrip` payload. It is a *second* full traversal the C runtime never pays (its BIFs allocate on the process heap via `HAlloc`), so with today's pooled-BIF-heap shape roughly none of it is removable inside `beam_rt`: eliding it means handing the pooled region over as a **scanned nursery space** (`Nursery`'s space/retired chain and `collapse`, `HeapSpace`/carrier ownership, `Runtime::{take,put}_bif_heap`) — **owner `beam_gc` + `beam_process`**, a cross-crate handoff — [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md) *The BIF-result copy-out*.
* **`erlang:statistics/1` is a `RuntimeHooks` key, so its container result is never re-homed onto the process heap** (`call_registered` sets `safe_to_rewind = false`): the tuple stays in an unscanned region — inert under the valve unless it forwards a *scanned* word. `DEFAULT_HEAP_WORDS` never causes a zero collection count: it sizes the runtime's **term-construction** heaps (BIF pool + `-eval` heap, `term_heap_words`), while a process nursery comes from `heap.policy()` (`min_heap_size` 233 → first `heap_size` 843) — `M1_GAPS.md` *The BIF-result copy-out*.
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call` + the whole-fd family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs`) over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`); the rest of the family stays **unclaimed** (fall-through to `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service wherever it owns the name. The io-device read path is complete (`file:read/2`/`read_line/1`/`io:scan_erl_exprs/4`/`io:parse_erl_exprs/4` — `tests/io_scan.rs`) and `os:set_signal/2` comes from the `RuntimeHooks` bridge — [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **The unscanned-root descent's remaining cost is its *invocation count*, not its visited set.** It is reached per heap-admission through the baseline JIT's `jit_test_heap`; `src/context/gc_walk.rs`'s per-walk visited table is near-optimal (1.25–1.45 probes/insert, ~5 grows over a whole `pool.erl` compile) and its Fibonacci probe mix wins the paired A/B (12 % cheaper on `timer.erl`, 37 % dearer on `ordsets.erl`), so cutting the invocation count — and the caller's per-edge `root_is_unscanned`/`for_each_child_slot` cost — is `src/context/gc.rs` / `beam_engine` policy; the per-walk reset cannot become a cross-walk memo (heap addresses are reused after a collection). The per-walk **allocation** is gone (`WalkScratch`), and the per-pid latch is **closed only by the three whole-`RootSet` doors** (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`) on `ValveVerdict::foreign_free` — never by the park arm or a signal gate, which run for a process whose `x`/stack are unpublished (an *exempt* park publishes nothing, so a clear there could hide a foreign container; `gc_walk.rs`'s module docs).
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call instead of re-entering the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`) with `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000` (`beam_process`), so per-pass costs amortize ×1000 and **per-slice** costs dominate a long run.
The measured per-pass / per-slice / per-round inventory — the fresh `ProcessTable` per pass, the progress-aware pass wait (a ready `run` issues **0** `clock_nanosleep`, a parked `receive … after T` is still slept to), the per-slice machine/context/timer churn, the `crate::hasher` word-mixing maps, the occupancy short-circuit and per-round drains, each with its `file:line` and its pinning test — is in **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, as is the per-workload cost of that path ([`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*).
The per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.

**Oracle/test-harness contract (cross-cutting).** Every probe discovers `erl`/`erlc` by **filesystem only, never by running the tool** (`tests/support/mod.rs`, `PROBE_TIMEOUT = 30 s`), and a missing toolchain is always a **loud skip**, never a silent pass or a panic.
Comparisons are trimmed **stdout string** equality, exit codes, error atoms, `term_to_binary`/`.beam` **bytes** and key **order**.
**No test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle** — the GC suites read the runtime's **own** `Runtime::gc_stats()`.
