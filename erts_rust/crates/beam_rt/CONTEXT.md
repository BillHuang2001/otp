# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns the **CLI flag surface** (A.6 — per-switch and `ERL_*FLAGS` detail in the child node `src/cli/CONTEXT.md`), the **boot sequence** + **preloaded-module registry skeleton** (A.7), **`system_info/1`** + `erlang:process_info/2` (A.8), the **concrete `ExecutionContext` glue** (the key deliverable), the **A.4 runtime side of ports** (`open_port/2` decoding + `port_info` over `beam_io`'s registry/poller, plus the driver C ABI host `src/port/driver.rs`), the **runtime-local timer deadlines** behind `erlang:send_after/3` and a finite `receive … after T` (`src/timers.rs`), and the **distributed node** (A.5 phase 1 — `src/dist.rs`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); this crate does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
Depends on **all** crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`. Legacy C ground truth (read-only) lives under `../../erts/`.

## API Surface (FROZEN — re-exported at the crate root and `beam_rt::prelude::*`)

### `runtime.rs` — the façade
`Runtime` owns every table (config, atoms, processes + mailboxes, BIF heaps, scheduler/runner state, ETS/port/NIF registries, refs, timers, dist) and the scratch `info_heap`.
* boot/config: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (idempotent), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`.
* the slice: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)), `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* spawning/scheduling: `spawn_process`, `spawn_fun_process`, `enqueue_process(pid)` (idempotent), `run_one_slice()`, `run_slices(max)`, `run_scheduler()` (never hangs; send→wake→resume in one call), `process_result(pid)`, `process_exit(pid)` (the reason term once raised), `run_queue_len()`.
* refs/introspection: `refs_mut()` — the one ref id space behind `make_ref`/monitors/timers; `system_info(key)`, the heap-free `system_info_value(key)`, `eval(expr)`, `format_term(term, module)`.
* timers/dist: `timers_mut()`, `fire_due_timers(table)` (a due `send_after/3` → the target's mailbox + wake; a fired finite `receive … after T` → resume), `note_fragment_wake(pid)`, `dist_node()`, `node_name()`; `pump_dist()` is the scheduler pass's distribution half.

### `runner.rs` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>` implements `run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Waiting` + `Wait`; `Err(e)` → record `exit_reason(e)` + `Exit(<reason term>)` (never panics). `RunnerState` holds an engine per pid plus the `results`/`exits` maps.
A `Wait` **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`parked_receive_timeout`/`timeout_delay`: an `Operand::Integer`/`Literal` or a live X-register) — the handle lives in `ProcessEngine::parked_timeout`; a fired deadline resumes at the `timeout` instruction with no message delivered, and a message-wake cancels it.

### `context/` — the concrete `ExecutionContext` (`mod.rs` + `bridges.rs` + `tests.rs`)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink` = a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler` and `current_module`; methods `new`, `with_output`, `heap_available()`, `for_process(runtime, table, pid)` (runs **as** that pid — the scheduler seam), `pid()`, `eval_heap()`, `run_export(...)`.
* `call_bif` → `try_call_nif` → `try_native` (the floor) → `BifRegistry::contains` → `call` (a `BifContext` over shared atoms / pooled heap / self_pid / output / `PendingInterner` + `RuntimePorts` + `NodeIdentity` + exactly ONE of the FIVE bridges); else `module=="erlang"` → `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef`; else load the module file → `code_server.load` → `run_export`. The only place the engine's seam meets the Stage-5 core (acyclic DAG).
* `apply_fun` → external `fun M:F/A` via `call_bif`; an `-eval` closure (`EVAL_FUN_UNIQ`) via `apply_eval_closure`; else the module's `FunDescriptor{uniq,index}` then `Machine::run_label`.
* `ensure_heap` → `heap_available() >= heap_need` else `BeamError::SystemLimit` (no GC).
`send_message` copies into the receiver's heap (`ProcessTable::deliver_simple`); a payload larger than that heap retries through the **heap-fragment** model.

### The five host-seam bridges (`context/bridges.rs`)
`call_registered` installs exactly **one** of five bridges (each needs a borrow the others cannot co-exist with), selected by its own `uses_*` predicate; `NodeIdentity` (no borrow) rides alongside.
* `NifBridge` (`beam_bifs::NifLoader`; `("erlang","load_nif",2)`) — checked **before** the filesystem; a second `load_nif` for a module with a library is `NifLoadError::Reload`; a failure is mapped variant-for-variant by `map_load_error` and **returned**, never raised.
* `RecordBridge` (`beam_bifs::RecordSource`; `("records","get_definition",2)`) — answers from the **loaded module's** `Recs` chunk (`Module::record_by_name`), each field atom name-resolved through the module's own atom table; an unloaded module or undeclared record ⇒ `Ok(None)` ⇒ the oracle's plain `badarg` (`erl_record.c:1342-1403`), an unresolvable field atom a typed `TermNotFound`.
* `DictBridge` (`beam_bifs::DictHook`; the five process-dictionary BIFs) — over the **running process's** `beam_process::Dict` (the scheduler pass's table, else the runtime's); a pid the table lacks is `error::no_mailbox`; the pool/arena are pointer-stable (no GC), so a stored term cannot dangle.
* `FunBridge` (`beam_bifs::FunCaller`; every other call) — delegates to the **existing** `RuntimeContext::apply_fun`; carries a clone of the caller's `SharedSink`, inherits the mailbox identity, the scheduler-pump permission and `current_module`, and carries **no** `TableRegistry`.
* `SendBridge` (`beam_bifs::SendHook`; `("erlang","send",2) | ("erlang","!",2)`) — delegates to the **existing** `RuntimeContext::send_message`. Oracle-matched: the return value **is** the message term, a send to a pid with no process succeeds silently, a non-pid-like destination is `badarg`, a registered name is delivered.
* `NodeIdentity` (`beam_bifs::LocalNode`; in **every** arm) — the fixed `nonode@nohost`, creation `0`, feeding `beam_codec`'s `Encoder::with_local_node`, so `term_to_binary/1` of an internal pid emits `NEW_PID_EXT` (`88`) and of an internal port `V4_PORT_EXT` (`120`).
`bridges.rs` also holds the `#[allow(dead_code)]` **local-fun identity** helpers (`local_fun_identity`/`module_md5`) — byte-exact but unwired.

### `PendingInterner` · NIF dispatch
`PendingInterner` (`Clone` over `Rc<RefCell<{base, names}>>`): `new(base)` roots it at the shared table's length, `commit(&AtomTable)` interns the recorded names at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup; `load_nif/2`'s two writers (the BIF, the C `load` callback through `enif_make_atom`) share the cell.
`run_export` **sets** `current_module` (restoring it after); the BIF sees it through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess).
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` as BEAM dispatch does; its term lives in the pointer-stable **pooled BIF heap** and the per-call `PendingInterner` is committed **after** the registry borrow is released. `NifCallError::Raised(reason)` → `error::nif_raised` (a live-reason-term raise), `UnknownFunction` → bare `error::undef`, a miss → a perfect no-op. **Interception is at external dispatch only** — a *local* `call` inside the NIF's own module never reaches `call_bif`.

### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS` (incl. `registered_name`), `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver}`, `StreamType{List,Binary}` (list default), `RuntimePorts` (the `PortHook` impl: `open_port/2`, `port_close/1`, `port_info/1,2`) built from `Rc<RefCell<PortRegistry>>` + the shared `Rc<AtomTable>` + the owning `ProcessId`.
`PortRegistry`: `new()` (anchors the `driver_*` codegen unit), `is_live`/`contains`, `write_command`, `len()`/`is_empty()` (= `system_info(port_count)`), `ids()` (port-number order = `erlang:ports/0`), `close(id)`, the `{spawn_driver,…}` routing `driver_lookup(name)`, plus private `register`/`pump(timeout) -> Vec<PortEvent>`/`take_due_exit_statuses`/`take_driver_outputs`/`info`; consumers are `Runtime::deliver_port_messages` and the `-eval` trio `poll_port_messages`/`port_data_message`/`port_exit_message`.
`Runtime` owns it as an `Rc<RefCell<..>>` (the ETS pattern) because `FunBridge` needs `&mut Runtime` at the same time; a nested borrow is a typed capability gap, never a panic. `SpawnDriver` is the **single** OS-child implementation — this crate owns only the **term decoding** of `open_port/2`'s `Name`/`Options` (into a term-free `SpawnSpec`/`SpawnOptions`) and the `PortMeta`.
`pump` is the single message producer: it polls in `PORT_POLL_SLICE` (25 ms) slices, each clamped by the earliest driver deadline (`beam_io::PortRegistry::next_deadline`), runs the scheduled port tasks, harvests each driver's `driver_output` and reports `PortEvent::{Data,Exited}`. `deliver_port_messages` delivers each `{Port,{data,..}}`/`{Port,{exit_status,..}}` into the **owning** process's mailbox and returns the count. `close`/`PortHook::close_port` call `beam_io`'s `notify_port_exit(…, Closed)` **before** `registry.close(...)`.

### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a `dlopen`ed driver with its host (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops).
`DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_` — the port handle **is** the per-port `DriverEnv`'s address: it owns a driver-private term arena, the shared `AtomTable` + a `PendingInterner`, and the owning `ProcessId`, implements the output/term-data/pid services and captures every `driver_output`/`send_term` payload. `load_driver(candidates, name)` tries each candidate and reports the **last** typed error.
`DriverPortAdapter` is the **port lifecycle** the host alone lacks — a `beam_io::Driver` over a loaded C driver: `start` runs the entry's `start`, `output` hands the port's queued bytes to the driver's `output` callback and queues the `driver_output` reply as the port's **input** (surfaced by `take_driver_outputs` as `{Port,{data,Data}}`), `stop` runs the entry's `stop`, and the `Driver` drop runs `finish` + `dlclose`.
`PortRegistry::new` anchors `beam_abi`'s driver codegen unit so `build.rs`'s `-Wl,--export-dynamic` has the `driver_*`/`erl_drv_*` symbols to publish. `open_port({spawn_driver, Name}, Options)` is routed here; an unknown or empty driver name is the oracle's `error:badarg`.

### `dist.rs` — the distributed node (A.5, phase 1)
`DistNode` is the runtime's *listening* half: `start(configured, cookie)` **binds** a wildcard listener (`DIST_LISTEN_ADDR`, OS-assigned port; unbindable ⇒ a start-up error) and the first `pump()` **publishes** the node to `epmd` (`ALIVE2_REQ`); accessors `node_name()`/`advertised_name()`/`epmd_name()`/`is_short_name()`, `port()`, `creation()`, `is_registered()`/`is_alive()`/`registration_error()` (recorded, never raised), `connections()`, `is_idle()`, `last_link_error()`.
`NodeName::parse` splits a `-name`/`-sname` value into `full` (`node@host`), `advertised` (full for `-name`, short for `-sname`) and `epmd` (short for `-sname`, verbatim for `-name`); a bare value's host is `local_hostname()` (`/proc/sys/kernel/hostname`, else `$HOSTNAME`). `resolve_cookie(init_args)` = the `setcookie` init argument (the `-setcookie` switch), else `$HOME/.erlang.cookie`, else `DEFAULT_COOKIE` (`nocookie`).
`DistConnection` wraps one accepted socket in a **server-side** `beam_dist::ConnectionDriver` (`ConnectionDriver::server(advertised, cookie, creation)`, driven `'N'` → `'s'`/`'S'` → `'r'` → `'a'`).
`pump()` registers once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections into links, then steps every link under a per-link read timeout of `DIST_READ_SLICE` (25 ms); a link's protocol/write failure **retires** it and records why (`last_link_error`), never raising — only the listener's own `accept` failure propagates.

### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl>}` (**field order is load-bearing**: `lib`'s `Drop` runs the C `unload` against the erased host pointer, so it drops *before* the boxed host) and `NifRegistry{libs}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; `NifRegistry` offers `new()` (anchors the `enif_*` codegen unit), `is_loaded(module)` (the oracle's `reload` condition), `insert`, `lookup(module,function,arity) -> bool` (**the dispatch predicate**) and `call(..) -> Result<Eterm, NifCallError>`.
`NifHostImpl{heap, atoms, interner, self_pid}` implements `beam_abi::NifHost`; `map_load_error` maps `NifLoadError` → `beam_bifs`'s variant-for-variant; a NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`; with the anchor on `beam_abi`'s `enif_*` codegen unit they publish the symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`, via `nm -D`). **Typed gap:** the host leaves `term_to_binary`/`binary_to_term`/`make_ref` at the `NifHost` defaults (`None`).

### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info.rs`, `format.rs`
`config.rs`: `RuntimeConfig{emulator, code_paths, heap_words, heap, action, init_args}`, `Action{Boot,Version,Eval,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs` (ordered flag → occurrences), `HeapOptions`, `MaxHeapFlags{kill,error_logger,include_shared_binaries}`.
`cli.rs`: `USAGE`, the four `EXIT_*` codes, the **pure** `parse(&[String])`, `parse_with_env(args, env)` (merges `ERL_*FLAGS`) and the `run(Vec<String>) -> i32` driver.
`boot.rs` (A.7): `PreloadedModules`. `info.rs` (A.8): `SUPPORTED_KEYS` (16 atom keys), `INFO_ATOMS`, `InfoValue` + `to_eterm(heap, atoms)`, `system_info_value(key, rt)`, `allocator_report(name)`/`effective_policy(base)`. `format.rs`: `term_to_string`/`term_to_string_w` (drives `io:format/2`).

## The runtime-native BIF floor (`src/native/`)
The BIFs that are really *runtime* operations (they read/write the runtime's own state), served **before** the `beam_bifs` registry from `RuntimeContext::try_native` (a directory module; its dispatch table is the source of truth for what is native):
* `native.rs` — `try_native`, the shared helpers (`string_list`/`atom_name`/`atom`/`charlist`/`render`/`write_output`/`chars_to_string`), plus `halt/0,1`, `display/1`, `io:put_chars/1,2`, `erlang:apply/2,3`, `erlang:system_info/1` (and its `{allocator, A}` 2-tuple → `info::allocator_report`), `erlang:send_after/3` + `cancel_timer/1`, `erlang:process_info/2`, `os:cmd/1`.
* `native/init.rs` — `init:get_argument/1`, `get_arguments/0`, `get_plain_arguments/0`, `get_status/0` (→ `{starting, started}`).
* `native/code.rs` — `code:get_path/0`, `all_loaded/0`, `which/1`, `is_loaded/1` (→ `{file,Path}` / `preloaded` / `false`), `is_sticky/1` (bool; `/2` is `error:undef`), `ensure_loaded/1` (→ `{module,Mod}` / `{error,nofile}`), `lib_dir/0,1`, `root_dir/0`.
* `native/process.rs` — `self/0`, `make_ref/0`, `monitor/2` + `demonitor/1,2`, `spawn/1,2,3`, `spawn_link/1,2,3`, `spawn_opt/2,3,4`, `ports/0`, `processes/0`, `pre_loaded/0` (the oracle's exact list *and* order), `group_leader/0`, `whereis/1`, `register/2`, `unregister/1`, `module_loaded/1`; `whereis(init)` is the runtime's own root process (oracle `<0.0.0>`).
* `native/port.rs` — `port_command/2,3` (the port's write stream: a child's `stdin`, a `{fd,N}` port's adopted descriptor, or a C driver port's `output` callback; `Data` must be Erlang **iodata at the top level** — a bare integer is `badarg`, an integer *element* of an iolist is a byte, so `port_command(P,[42])` → `true`; `[force]` → `error:notsup`) and the `port_info/1,2` mapping, which owns the two answers a `PortHook` pair list cannot express: `undefined` for a closed/unknown port and the bare `[]` for a live, **unregistered** port's `registered_name`.
* `native/memory.rs` — `erlang:process_info/2` for `garbage_collection` (the oracle's five-item proplist, `max_heap_size` its flag **map**), `heap_size` and `total_heap_size`, off the live process's `beam_gc` collector; `undefined` for a pid not in the table, `badarg` for a bad item/argument.
* `native/application.rs` — `application:get_env/1,2,3`, `get_all_env/1`, `get_key/2`, `loaded_applications/0`, `which_applications/0`, over a minimal native app view (`.app` files through `CodeServer` + a recursive-descent term-text parser). **Honest deviation:** `get_all_env(kernel)` reports the `.app`'s **declared** env only — seven pairs (oracle: nine; `logger`/`connect_all` are injected by kernel's app start and are *not* fabricated); the pairs agree key-for-key, the order differs.
* `native/test_support.rs` — the floor's shared test fixtures.
`beam_bifs` owns the *registry* surface (`bif.tab`: arithmetic, comparison, type tests, term ops, `lists`/`maps`/`binary`, `io:format`, `ets`, `records`, …); a native entry must never duplicate one, and a call the floor does not claim returns `None` and falls through.

### `code:` is the native floor, not a live `code_server`
`code:*`, `init:*` and `application:*` are **preloaded-module surface** (A.7): the oracle serves them from `init.beam`/`code.beam`/`application.beam`, written against process/message machinery M1 does not run. `beam_rt` ships **no** live `code_server.beam` — OTP's real one needs `monitor`/`register`/`spawn_link`/`send`, a host **timer**, `make_ref/0`, named-ETS resolution and `persistent_term`/`filename`/`erl_prim_loader` — and its *state* already lives in `CodeServer`. The `boot/*` differential cases touching `code:*` are **shape-only**; a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**

### `erlang`-namespace fallback and the known-unimplemented list
`call_bif` consults the floor, then the `beam_bifs` registry, then falls back for the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises the capability gap `unsupported: erlang:X/Y …` (exit 3), any other unclaimed name raises the bare `error::undef`. The **effective** gap set is the curated `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` **intersected with what the live registry does not own**, so a `beam_bifs` change that registers a listed name can never shadow the registry (drift guard: `error::tests::the_effective_gap_set_never_shadows_the_registry`).

## CLI subset (contract A.6)
The **exact** switch surface, the `ERL_*FLAGS` merge, the init-argument rule, the exit-code contract and the divergences live in the child node **`src/cli/CONTEXT.md`**.
In brief: `cli::parse` is pure, `cli::parse_with_env` merges the environment (the driver uses `parse_with_env(&args, &ProcessEnv)`); a **`-`-switch** (recognized or not) is recorded as an init argument, a **`+`-flag** is an emulator flag and is **not**, and the `-eval`/`-s`/`-run` Start instructions are **not**; `-eval` is a general-expression `erl_eval`-style subset; the `run` argument grammar is `int`/`atom`/`"string"`/`[list]`; `run <file.beam> <mod>:<func>/<arity> [arg…]` loads, runs and prints.

## Exit codes & the `unsupported` signal
Four exit codes (the differential harness keys off them; `src/cli/CONTEXT.md` has the table): `0` (`EXIT_OK`) success · `1` (`EXIT_RUNTIME`) a genuine runtime error, printed `beam_rt: <error>` · `2` (`EXIT_USAGE`) a malformed invocation, printed `beam_rt: <error>` + `USAGE` · `3` (`EXIT_UNSUPPORTED`) a capability gap, printed as exactly one line `beam_rt: unsupported: <reason>` (no `USAGE`).
Unsupported is emitted for a `-eval` expression outside the grammar, a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`); the reason is a raise whose **atom starts with `unsupported`**, interpreted only by `src/error.rs::unsupported_reason` (classification uses `ExitReason::as_atom`, not `BeamError::as_atom`). A capability gap is **uncatchable**: `src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal` (like `halt`), so the harness's `try … catch` probe cannot swallow it.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise`). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1).

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap. Strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them. An unknown key — atom or tuple — is `Err(BeamError::BadArg)` (the oracle's `error:badarg`).
| Key | Value |
|---|---|
| `version` | `Str` `"17.1"` (`beam_common::version::ERTS_VERSION`) |
| `otp_release` | `Str` `"30"` (the major of `OTP_VERSION`) |
| `system_architecture` | `Str` the target triple from `std::env::consts` |
| `system_version` | `Str` `"Erlang/OTP {major} [erts-{erts}] [source] [{bits}-bit]"` |
| `nif_version` | `Str` `"2.18"` from `beam_abi::{ERL_NIF_MAJOR_VERSION,ERL_NIF_MINOR_VERSION}` |
| `wordsize` | `Int` `8` |
| `logical_processors` | `Int` `available_parallelism()` |
| `process_count` | `Int` the process table's length |
| `port_count` | `Int` the **live** ports (`PortRegistry::len`) |
| `os_type` | `Tuple` `{unix,linux}` (or `{win32,nt}`) |
| `threads` | `Bool` atom `true`/`false` |
| `emu_flavor` | `Atom` the `-emu_flavor` value (`jit` default, else `emu`/`smp`) |
| `schedulers` | `Int` an explicit `+S N` wins, else `available_parallelism()`; always `> 0` |
| `alloc_util_allocators` | `List` the ten alloc-util allocator names from `beam_alloc::registry::alloc_util_allocators()`, in the oracle's order |
| `allocated_areas` | `List` the oracle's 19 items in order, every value **derived from this runtime's own state** (`atom_space` is `{atom_space,B,B}`, the table items count live entries, items with no counterpart are `0`) |
| `garbage_collection` | `List` the 4 emulator-wide knobs `[{max_heap_size,0},{min_bin_vheap_size,46422},{min_heap_size,233},{fullsweep_after,65535}]`; `max_heap_size` is the **bare integer** here, unlike the `process_info/2` flag map |
| `{allocator, A}` (a **tuple** key) | `List` of `{Key,Value}` rows via `beam_alloc::stats::AllocatorInfo::from_stats` over a live `registry::all_stats()` snapshot; `A` outside the ten names ⇒ `badarg` |
`INFO_ATOMS` (`src/info.rs`) is the surface's complete atom vocabulary (the value atoms of the keys above, the `{allocator,…}` row names and the `process_info/2` item names + `undefined`); `seed_core_atoms` interns it, because `InfoValue::to_eterm` resolves through the runtime's atom table and reports `TermNotFound` rather than inventing a term. Add any new atom-valued key's atom to `INFO_ATOMS`.

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates.
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2453 lines; production half ~1470) and `src/info.rs` (~1261; production half ~610).

## Design Decisions
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every module it loads is interned into it and `call_bif` hands `BifContext` that same table, so a BIF-built atom is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns (`RuntimeContext` only borrows it); `system_info`/`format_term` use a separate `info_heap`, reset per call.
* **`ensure_heap` without GC.** M1 has no engine collector: `ensure_heap` checks capacity and returns `BeamError::SystemLimit` when short (default 64 Ki words); growth-by-collection is Stage 4.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are **preserved verbatim** in `emulator.extra_emulator_flags` (and a `-`-flag is recorded); `-eval`/`run` reuse the BIF registry rather than re-implementing arithmetic/printing; **`main.rs` is a thin shim** over `cli::run(argv)`; `parse` is pure, so the `ERL_*FLAGS` surface is confined to `parse_with_env` + the `env` module.
* **The scheduler moves the table and the runner state out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* of the runtime (`#![deny(unsafe_code)]`, may not alias), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid in `RunnerState::results` (`process_result`) and returns `RunOutcome::Exit(normal)`, after `stabilize_term` copies it onto the pointer-stable `eval_heap`. A **raising** process records the mapped reason term in `RunnerState::exits` and exits with that term.
* **The host seams: the five bridges + `NodeIdentity`.** `FunBridge` delegates to the **existing** `RuntimeContext::apply_fun` (`lists:map(fun(X) -> X*X end, [1,2,3])` → `[1,4,9]`); `SendBridge` likewise delegates to `send_message`, so a BIF send is the same path as the `send` instruction. Because the `BifContext` holds no runtime borrow, every resource is a non-borrowing clone (`Rc<BifRegistry>`, an `Rc<AtomTable>`, an `Rc<RefCell<TableRegistry>>`, a **pooled** `beam_alloc::Heap` via `take_bif_heap`/`put_bif_heap`, the disjoint `output` field, the `Rc<RefCell<PortRegistry>>`, the plain `Option<DistNode>`).
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw` with a live reason).
* **Timers are a runtime-local deadline heap, not `beam_process::TimerService`.** That service runs on **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (it owns `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas). The wheel therefore degenerates to a min-heap (`src/timers.rs`) the **scheduler loop** drains: monotonic deadlines, earlier first, equal keeping insertion order, `O(1)` cancellation via a lazy tombstone, sleep-to-earliest only when idle.
* **Oversized messages go through the heap-fragment model, composed in-crate.** `beam_message::send_fragmented` wants the receiver's **heap** and **mailbox** at once, but `Process` exposes them only through two `&mut self` accessors, so `RuntimeContext::send_fragmented_message` composes the same public fragment primitives directly and records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments` so a just-bound payload stays valid.
* **The driver port handle is the environment's address.** A driver callback receives an `ErlDrvPort` that **is** its per-port `DriverEnv`; `DriverPortAdapter` `Box`es the host (and the environment *before* `as_port()`), so the raw pointer stays valid across callbacks.
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`.

## Known Issues / Intentional M1 gaps
* **No interactive shell; distribution is a *listening* node only.** `-noshell` is the only mode. `-name`/`-sname` bind a listener and register with `epmd` (best-effort; a failure is recorded in `DistNode::registration_error`, never fatal), and the scheduler pass pumps inbound connections through `beam_dist::ConnectionDriver::server`. Gaps: no link reaches `Established`, inbound `DOP_*` is never delivered, there is no `net_kernel` protocol, and `node/0`/`system_info` do **not** reflect the live node.
* **Preloaded modules are a name-set skeleton.** Boot does **not** load preloaded `.beam`s; the atom table is seeded with `CORE_ATOMS` + `INFO_ATOMS` (not the full `atom.names` ordering), so preloaded positional atom indices are not reproduced. The erts app's `ebin` **is** on the code path, so preloaded modules load from disk on demand.
* **Answers that read *this* runtime's own state differ from the oracle by construction** — not bugs, and must not be "fixed" to a run-time figure: `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)`, `erlang:module_loaded/1`. `erlang:whereis(init)` **does** agree (the root process; oracle `<0.0.0>`); `erlang:registered/0` is on the known-unimplemented list.
* **Scheduler is single-threaded; a few M1 process gaps.** A blocked receiver **is** resumed by a sender (send→wake→resume), **by a due `send_after/3` timer** or **by a fired `receive … after T` deadline**. Remaining gaps: **no reduction pre-emption** (`budget` not enforced, `Yield` never returned); a compiled `receive … after T` whose delay is **not statically readable** (a **Y-register** variable or `after infinity`) still parks; a **capability gap is uncatchable** on the runner path; the heap has **no GC**, so a runaway allocation returns `SystemLimit`.
* **`-eval`/`-s`/`-run` are documented subsets.** Supported: the expression subset (`-eval` prints nothing), the **send operator**, a **bare `receive`** driving a spawned sender, the **spawn probes** and a bounded scheduler pump. Gaps (typed errors in `src/eval/mod.rs`): a `receive` that never receives, a `receive` inside a spawned process, `after infinity`; real `erl` start-script processing / `-init_debug` are absent. A non-byte-aligned `-eval` result cannot be **printed** — the registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (and a container past its ~80-column limit) with `badarg` (a `beam_bifs` gap outside this crate), so the corpus probes read such values through `bit_size/1`/`is_list`; a construction **or** pattern segment wider than 64 bits is *unsupported* and a bignum is `system_limit`.
* **NIF loading is live, with honest typed gaps (A.3).** `erlang:load_nif/2` really `dlopen`s the shared object and runs the C NIF through `try_call_nif`; a load failure is the oracle's **returned** `{error, {Reason, Text}}`, never a raise. Typed gaps: the host leaves `term_to_binary`/`binary_to_term`/`make_ref` at the `NifHost` defaults; a second `load_nif` for a module with a library is `reload`.
* **`NEW_FUN_EXT`: a compiled-module identity is derived (oracle-proven) but unwired; an `erl_eval` lambda has no image.** `fun M:F/A` builds a real `FunKind::External` term (`term_to_binary` → `EXPORT_EXT`). For a **compiled-module** `make_fun3` closure, `bridges.rs` derives the five `NEW_FUN_EXT` identity fields the term lacks (byte-exact to the oracle), but the encoder has no fun-identity seam (`binconv.rs::encode_body`) to feed them in (see the `beam_bifs` handoff). An **`erl_eval` lambda** needs `erl_eval`'s own MD5/fun-index/creator/env and stays the honest typed `unsupported: local_fun` (the `wire/new_fun_ext_encode` corpus case).
* **Ports match the oracle's observable shape; the gaps are these.** The read path is thin (only **stdout** polled, stderr discarded, one `Read::read` per readiness); `connected` flips to `false` only at `port_close/1`, `eof` is inert, a `binary`-stream read wider than 64 bytes is the typed *unsupported* gap, and `os:cmd/1` stays the runtime-native host spawn. The **send family** serves `erlang:send/2`/`erlang:'!'/2` (the `SendBridge`) with two typed gaps: `erlang:send(Port, Data)` (the oracle drops a send to an unknown/closed port **silently**, where `port_command/2` raises `badarg`) and the distributed `{Name, Node}` send (A.5).
* **Driver ports (A.4) load and drive a real C driver end to end, with typed gaps.** A `{spawn_driver, Name}` port's `driver_output` **is** delivered to its owner as `{Port, {data, Data}}` (`tests/driver.rs`), and the driver's **event and timer** requests are real too: `driver_select` registers the descriptor with the runtime's one poller (exact for one registration per direction — a typed `unsupported` when a driver arms several), and `driver_set_timer`'s deadline is mirrored into the port's `TIMEOUT` task and clamps the poll round (cleared before the callback, so a re-arming callback wins). Remaining typed gaps: `driver_async` keeps the `-1` default (no async pool; `Runtime` is `!Send`), `port_control/3` does not reach the driver's `control`, a decoded `send_term` is captured in `DriverPort::sent`, `ERL_DRV_USE`'s `stop_select` never fires, and the port has no OS child (`os_pid` is `undefined`). **Documented M1 extension:** with no `erl_ddll:load_driver/*`, the `Name` doubles as the *search* (a `/`-containing name is the object path, driver name = its file stem; else the name itself, `<name>.so`, `./<name>`).
* **The timer family is mostly gaps.** `erlang:send_after/3` answers a `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)` `badarg`, a bad time/destination `badarg`. Still unimplemented: `start_timer/3,4`, `send_after/4`, `cancel_timer/2`, `erlang:system_info/2`.
* **GC observables: `process_info/2` answers three items, with one documented divergence.** `garbage_collection` is the oracle's five-item proplist (non-hardcoded) and `heap_size` agrees (233), but `total_heap_size` reports **466** (vs the oracle's 233) because this collector pre-allocates a 233-word mature generation. A pid not in the table is `undefined`; an unknown/non-atom item or a non-pid is `badarg`; `erlang:process_info/1` remains unimplemented.
* **No whole-system memory introspection.** `erlang:memory/0,1` and `erlang:statistics/1` are **not** registered BIFs (exit 1); the memory numbers it *does* answer are `process_info/2`'s heap items, `system_info(allocated_areas)` / `{allocator, A}` and `ets:info(T, memory)`.
* **The heap switches are modelled; some rejection details and the CLI divergences are not.** `+hms`/`+hmbs` set a `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000` → 1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1. The remaining CLI/emulator divergences (the malformed-value exit code, the `ErtsStrToSint` laxness, `-emu_flavor`, `+K`, `-M*`/`+M*`, and `-smp disable` — which the oracle rejects with `Use "+S 1" instead.` while `beam_rt` accepts it) are recorded in `src/cli/CONTEXT.md`.

## Handoffs (owned by OTHER nodes)
`differential suite` last measured **`total=541 agree=540 mismatch=0 unsupported=1 skipped=0`**; the one `unsupported` is `wire/new_fun_ext_encode` (A.5). The `records/*` cases **agree** (the `RecordBridge`); remaining `wire/*` encode/decode asks live in `beam_codec`/`beam_bifs`.
* **`beam_bifs` — a fun-identity seam on the ETF encode path.** `binconv.rs::encode_body` is the **only** `beam_codec::Encoder` construction point and `BifContext` carries no fun identity, so `bridges.rs`'s `local_fun_identity`/`module_md5` stay `#[allow(dead_code)]` and a compiled-module `FunKind::Local` fun is typed `unsupported: local_fun`. Threading an `Option<beam_codec::FunIdentity>` into the encoder's fun arm (which `beam_rt` can fill from the loaded module) wires it in without touching `beam_codec`.
* **`beam_process` — a `!Send`-friendly `SchedulerPool`.** SMP adoption means replacing the runtime's single-threaded `Scheduler::new()`+`enqueue`+`run_ready` loop with `beam_process::SchedulerPool`, but `Runtime` is `!Send` (it holds `Rc`/`RefCell` registries, the `CodeServer`'s `Rc<AtomTable>`, `*mut Eterm` heaps, `Rc<FunBody>` closures and a `dyn DistSignalRouter`). `beam_rt` is `#![deny(unsafe_code)]`, so `beam_process`'s `unsafe impl Send` escape is unavailable. Forward paths: (a) a `?Send`/calling-thread `SchedulerPool` variant, or (b) Send-ify the runtime across `beam_alloc`/`beam_engine`/`beam_dist`.
* **`beam_process` / `beam_message` — a split borrow over a process's heap + mailbox, and an owning drain for the wake list.** `Process::heap_mut`/`mailbox_mut` are two separate `&mut self` accessors, so `beam_message::send_fragmented` (needing the receiver's heap **and** mailbox at once) cannot be driven from here. A split borrow plus a drain yielding the woken pids would delete the in-crate fragment composition, the `Runtime::note_fragment_wake` record and `MailboxState::retained_fragments`.
* **`beam_engine` — a deadline on the block outcome / a `Machine` Y-register accessor.** `RunOutcome::Wait { func, pc }` carries no deadline, so the runner recovers the receive delay by scanning the parked function's IR for the owning `wait_timeout` (`runner::parked_receive_timeout`) — which works only for a **statically readable** operand (literal/`Literal`/X-register); a **Y-register** `after T` is unreadable because `Machine` exposes no stack read. The engine reporting the deadline (or exposing the Y-register) would delete the IR scan and cover the variable case.
* **`beam_dist` — the server-side `'N'` handshake rejects a real peer with a typed `badarg`.** The **single** blocker for a real handshake: `ConnectionDriver::server` fails an inbound `'N'` from a real OTP 29 peer, so `DistNode::pump` retires the link (`last_link_error`) and it never reaches `Established`. Everything on this crate's side (`src/dist.rs`) is in place and exercised end to end (`tests/dist.rs`).
* **`beam_bifs` / `src/context` — `node/0` and the `NodeIdentity` wiring.** `NodeIdentity` answers the fixed `nonode@nohost`/creation `0`, so a **live** `-sname`/`-name` node is invisible to `erlang:node/0` and the node-valued `system_info` items; `erlang:node/0` is not registered at all (bare `error::undef`; `node/1` is on the known-unimplemented list). Feeding the identity from `Runtime::dist_node()` is what makes the node real to the language.
* **Distribution, phase 2 — inbound `DOP_*` into a mailbox.** A link's decoded control messages (`DOP_REG_SEND`/`DOP_SEND`) stay queued in the driver; delivering them means resolving `{node,name}`/`{node,pid}` to a local process and `deliver`-ing the payload through `beam_process` (the same resume-on-send path a port message takes). Nothing is decoded on the critical path, so an undecodable message can never fail a scheduler pass.
* **`beam_io` — the remainder of the driver-port lifecycle.** `DriverPortAdapter` supplies the port lifecycle a loaded C driver needs; `select` and the timer family are wired to the poller, and what is still owed is everything else the C host answers: `async` (no async pool — `Runtime` is `!Send`), a decoded `send_term`, `port_control/3` reaching the driver's `control`, `ERL_DRV_USE`'s `stop_select`, an `ErlDrvEvent` with a **per-registration** identity (a port task carries only the port key, so a driver arming several descriptors per direction is a typed `unsupported`), and a self-exiting child. **`open_port({spawn_executable, <a DIRECTORY path e.g. /tmp>}, [])` diverges:** the oracle returns a **port**, `beam_rt` raises `error:eacces` (`SpawnDriver` surfaces `Command::spawn()`'s synchronous `EACCES`); a non-executable regular file and a missing `{spawn, …}` command both match the oracle at `error:eacces`.
* **`beam_engine` — name the rejected opcode.** Kernel `code.beam`'s `code_server:call/1` executes `recv_marker_reserve/1` (also `recv_marker_bind`, `send`, `loop_rec`, `remove_message`), which no family claims; it falls to the generic `Err(error::unsupported("widened opcode not yet executed"))` at `beam_engine/src/families/mod.rs`, which does **not** name the instruction. Diagnostic-quality, not a gate blocker.
