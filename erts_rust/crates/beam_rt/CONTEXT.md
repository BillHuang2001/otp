# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture — `main.rs`, the **CLI flag surface** (**A.6**), **`system_info/1`** + `erlang:process_info/2` (**A.8**) and the **boot sequence** (`src/boot/preloaded.rs`, `src/boot/bootscript.rs`, `src/boot/drive.rs`) that loads the 22 preloaded `.beam`s for real and runs the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**).
Every CLI action but `-version` drives that script before its own start instruction, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — including every optional `beam_bifs` host seam (the key deliverable), the **A.4 runtime side of ports**, the **runtime-local timer deadlines** behind `erlang:send_after/3,4`/`start_timer/3,4` and a finite `receive … after T` (`src/timers.rs`), and the **distributed node** (A.5: `src/dist.rs` + `src/dist/` accepting, `src/dist_client/` connecting).
The vertical slice runs on a test-only `MinimalContext` at the engine level (`../beam_engine/tests/slice.rs`) and through this crate's real glue and executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`, terms/heaps → `beam_term`/`beam_alloc`, pids → `beam_process`, modules → `beam_loader`, execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` on the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**), sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (a send to a link-less node dials it first, `Runtime::dist_ensure_link`); a `-name`/`-sname` node also runs the native `net_kernel` service (`src/native/net_kernel.rs`), so a real peer's `net_adm:ping/1` answers `pong`.
Both inbound drives drain every established link through `beam_dist`'s per-link checked path and `LocalDeliverySink` routes the message and route-free receipt families through `ProcessTable`'s inbound primitives, the pass being gated by `Runtime::inbound_delivery` (default **ON**) — per-family routing table, the pump budgets, the envelope rule and the `DistRouter` install site: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
Both inbound relationship families are therefore observable locally: a peer's `link/1` through `process_info(P, links)` (`src/native/memory/mod.rs::links_value`, the local link set plus the recorded remote partners as external pids) and its `monitor/2` through `process_info(P, monitored_by)` — two-live-VM evidence in `tests/dist_two_vm.rs` (`a_real_erl_peers_link_shows_up_in_the_links_item_and_clears_on_unlink`).
**Peer loss fires the operator's node-down semantics (A.5).** A link retired because it **died** records its peer in the runtime's one shared `LostPeers` cell (`src/dist/links.rs`), from **both** halves (inbound `DistNode::retire_at`, outbound `DistClientInner::retire`).
The recording test is the `was_established` **latch** each link sets inside its own `pump` the moment the driver reports `Established` — not `is_established()`, which the discovering pump has already moved to `Closed`/`Failed` (the latch is what makes a dying established link recordable at all).
`Runtime::service_lost_dist_peers` (the pass step after `dispatch_dist_client_inbound`, `src/runtime/scheduler.rs`) skips a peer any link still names in **any** handshake state (`DistLinks::link_names`, so a re-connect is a non-event), declines an unnameable peer (`AtomTable::lookup`), interns `noconnection` and calls `ProcessTable::node_down`, so a monitor gets `{'DOWN',Ref,process,PeerPid,noconnection}`, a trapping link `{'EXIT',PeerPid,noconnection}`, a non-trapping link dies with `noconnection`; a failed handshake and a graceful close/drop record nothing, and `Runtime::service_node_monitors` (`monitor_node/2`'s `{nodedown,Node}`) is a separate path that cannot double-fire.
`Runtime::dist_connect` is **idempotent**: a peer already established on either half answers `Ok(())` without dialling, because a second `'N'` link to a peer that dialled us is a simultaneous-connection collision the peer resolves by killing one — the defect that once made `net_adm:ping/1` answer `pang` for a live peer.
Two-live-VM evidence: `tests/dist_two_vm.rs` (24 `#[ignore]`d cases — link/unlink observability, monitor/demonitor, `exit/2`, aliases, identity round trip, the four inbound-signal cases, the four peer-node-loss cases) and `tests/dist_two_rust.rs` (12 — the seven outbound/round-trip cases plus all **inbound** ones, where the peer acts on a process *we* host: inbound `DOP_LINK` recorded in the victim's `links` item ahead of a barrier, the peer's `erlang:monitor/2` recorded in `monitored_by` with its `DOP_MONITOR_P_EXIT` `{'DOWN',…}` read back, inbound `DOP_EXIT` with a compound reason into a trapping victim, the same link death into a non-trapping one, and the inbound `DOP_EXIT2` `{plain,kill}` × `{trapping,not}` matrix with `kill` untrappable).
**A control signal is never overtaken by a later message on the same link** (ERTS's synchrony, `dist.c`'s `erts_dsig_send_*` writing under the link lock): the router only *queues* (`DistClientInner::queue_signal` — `route` runs inside the process table and has no atom table), so every message write drains the queue first (`DistClient::flush_queued_controls` in `src/dist_client/client.rs`, called by all three sends before they materialise a term on the scratch heap), and `DistClient::pump` flushes at every pass. Both halves of the pair are therefore ordered: a barrier sent right after a `link`/`monitor` cannot outrun it, and a `DOP_MONITOR_P` always lands while the target is alive (`LocalDeliverySink::resolve_live` would otherwise drop it, so no `DOP_MONITOR_P_EXIT` would ever be emitted).
* **the busy-port park** (`src/port/busy_wait.rs`) → `PortWrite::Parked` (busy test before any queueing, payload unconsumed) → `RuntimeContext::request_suspend` → `BifOutcome::Suspend` → the runner parks and re-runs the BIF, the wait start keyed `(pid, port)` on the `Runtime` so a re-park keeps the *first* attempt's `BUSY_PORT_DEADLINE` — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `tests/port_busy.rs`.
* **the nested port wait** (`RuntimeContext::wait_for_port_event`) → a nested (`-eval`/`-s`/`-run`/boot) passive socket operation sits out its `{inet_async, …}` over the blocking pass, completing through the driver's async-op queue and the completion channel under `crate::port::PORT_EVENT_DEADLINE` — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `tests/inet_nested.rs`.
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: `lib`'s `Drop` runs the C `unload` against the erased host pointer, so it precedes the boxed host) and the `!Send` `NifRegistry` (`new()` anchors the `enif_*` codegen unit; `is_loaded`/`insert`/`lookup` — **the dispatch predicate** — and `call`) are `Runtime`'s `Rc<RefCell<..>>`.
A NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by name; all **eleven** state-needing `NifHostServices` hooks (select, send, the monitor pair, …) are live on a call.
`enif_schedule_nif` chains run through `beam_abi`'s iterative constant-Rust-stack trampoline (`beam_abi/src/nif/enif/schedule.rs`), and an `enif_select` STOP verdict runs the resource type's own `stop` callback (`beam_abi::nif::enif::call_resource_stop`) — synchronously on `STOP_CALLED` with the caller keeping its reference, or parked for `run_pending_stops()` on `STOP_SCHEDULED` with one kept reference released at the drain.
`src/nif/thread_env.rs` is the **process-independent ("message env") host** a thread a NIF created (`enif_thread_create`) runs on: `ThreadEnvFactory` (one `ForeignHost` per thread) draws every atom from a **private** name→index space (`src/nif/atoms.rs`), and `ForeignHost::send` queues a **complete ETF image** carrying this node's identity, so an atom reaches the live table by **name** when the decoder interns it.
`Runtime::install_nif_thread_env`/`clear_nif_thread_env` own the factory slot (installed from `cli::build_runtime`, the slot being process-global while the suite builds many runtimes per process), and `Runtime::drain_nif_thread_sends` decodes a queued image against the **live** table at `src/context/calls.rs`'s `try_call_nif` and at `src/runtime/scheduler.rs`'s `scheduler_pass`.
`nif_yield_point` is a no-op on both hosts, so a self-rescheduling chain keeps its thread until it ends (a fairness bound, never a wrong result); the load/unload host runs with `services = None` (only the callback-scoped `enif_send` window answers there) and `upgrade` is not modelled (a second `load_nif/2` is the oracle's `reload` refusal).
`build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
Evidence and per-item typed gaps: the oracle-cross-checked `tests/nif_a3_{thread_env,schedule,resource_stop}.rs`, `src/nif/thread_env_tests.rs` and `M1_GAPS_A3_NIF.md` *NIF (A.3)* (which carries the observation tally: the `enif_thread_type()` driver-thread answer and `enif_schedule_nif`'s raw return word account for every remaining divergence).

### `malloc.rs` — the allocator's free-page release (one call, from `main.rs` after the join)
`beam_rt::release_free_pages()` is the crate's single allocator lever (`libc::malloc_trim(0)` on glibc, an honest `None` elsewhere), called **once per process** from `src/main.rs`'s `run_on_driver_stack` after the `"beam_rt-driver"` thread has been joined.
That is the only quiescent *and* complete point: the driver thread still holds most of the run's memory until it exits — a trim from inside `cli::run` after the runtime it built has been dropped recovers ~16 MB of the ~75 MB the process then keeps.
Measured exit RSS after the trim: bare boot **118 100 → 23 192 kB**, `compiler/cerl_clauses.erl` **372 MB peak → 21 MB**, `stdlib/src/orddict.erl` **363 MB peak → 30.6 MB**, `kernel/src/inet_parse.erl` **7.8 GB peak → 23.0 MB** (release build, in-process `compile:file/2`, `no_spawn_compiler_process`, OTP-30 bootstrap compiler first on `-pa`).
Peak `VmHWM` is **unchanged by the lever** (it only returns free pages at exit): the run's high-water is live at the time.
**Capacity is not RSS.** `beam_alloc::Heap::new` is a lazy `mmap` that touches only a 16-byte block header plus a 64-byte segment header, so a 128 MiB region sits at 12–48 kB RSS; region size shows up in `VmSize` and `erlang:system_info({allocator,std_alloc})`, and RSS moves only when pages are written.
The pooled BIF heap is the demonstration: `cerl_clauses` ends with **27 regions / 20 185 088 words = 161 MB** of reservation against `bif_peak_used_words` = 28 916 words (**226 kB**) ever written — the same 27 regions cost **3.62 GB** when every level was seeded at `bif_heap_words`, so the depth-aware seed cut reservation **22×** while moving no RSS of its own.
Census, arena/heap layout and the rejected placements are `src/malloc.rs`'s module docs, the measured note `src/CONTEXT.md`'s routing entry.
`BEAM_RT_MEM_TRACE` prints the call's answer as one `[rt-mem] heap-release=…` line; it stays silent otherwise and no behaviour depends on it.

## Host-side term stores — owned copy vs raw word (the rule that makes a store sound)
A stored term is self-contained only if it went through [`Runtime::stabilize_term`]/`try_stabilize_escaped` (a copy onto the `eval_heap` + `eval_off_heap` store: `eval_heap`'s regions are reclaimed only by `src/runtime/reclaim.rs`, at a site where nothing is executing and only where no reachable term stands, and `eval_off_heap` is only ever grown — its payloads are released by the reachability prune, never by the region pass); a word built on the pointer-stable **arena** (`Runtime::alloc_words`, i.e. any table-less `RuntimeContext`) stays valid because its regions never move and the region pass rewinds it only above a mark taken where nothing reachable stands above it, so a still-reachable word keeps its address; and a word built on the **pooled BIF heap** only because the escaping `runtime_hooks` arm sets `safe_to_rewind = false`.
- **Owned copies** (stabilized before storing): `persistent_term` key+value (`src/context/calls.rs`), a timer's `TimerAction::Deliver.message` (`src/context/runtime_hooks.rs`, `src/native.rs`), a trace `MatchSpec::Functions` (`src/native/erts_internal/trace.rs`), the `enif_select` payload (`src/nif_select.rs`), `port_set_data`'s data, a pending spawn's entry fun + args, `RunnerState.exits`/`results`, and **a raise's live reason term** — `Runtime::stabilize_error_live_reason` at the two escape boundaries (the runner's raise arm, `Runtime::as_action_process`) copies it off the dying process heap / recyclable pooled BIF region before the error is recorded or handed to the CLI.
- **Immediate-only**: a timer's `from` (a pid), `node_monitors`' node terms (atoms), `monitor_nodes`' bitmask, `open_files`/`prim_tty_handles` (ids), a mailbox `Marker.term` (a small int).
- **Raw words, deliberately**: `references`/`Timers::refs` **keys** — a reference's identity *is* its address, minted on the pooled BIF heap by `src/native/process.rs::reference_term`/`mint_timer_ref` — `eval_closures`' `FunBody.env` (written by the evaluator, on the arena or on `eval_heap`; `env_terms` is an off-heap-payload census, not a copy — and `CompiledClosure.captures` below is a **second copy of the same words**), the mailbox marker's bound `reference`, `TraceTables`' `MatchSpec::Functions` words behind the documented "a stabilized copy flattens a payload" exemption, `Runtime::in_machine`'s five `InMachinePosition` words (`src/context/position.rs:106-114`, published into `runtime.rs:649` immediately before a nested `call_bif` and cleared immediately after — sound only because "no collection can run while a BIF call is in flight", so a compaction admission inside a dispatch would need them re-derived), and `seq_trace`'s `Token.label`, which is stored **unstabilized** (see `SeqTrace::gather_off_heap_roots`) so its word can outlive the heap it was written on.
- A literal word is self-contained: `beam_loader`'s `LiteralArea` owns its payloads for the life of the owning `Arc<Module>`, and no literal is ever rebuilt on the arena — but `erlang:delete_module/1` does drop that `Arc`, so a *stored* literal word can outlive its area.
- **These stores are POINTER-PINNED, so a MOVE of the region one names is the only thing they cannot survive — and the runtime moves a region only where nothing is executing.** The store move (`src/runtime/reclaim/compact.rs`, `src/runtime/CONTEXT.md` *The region-reclaim pass*) runs at exactly two such instants (the `-eval` statement boundary and the driver exit) and is this inventory turned into a **relocation** inventory: each stored word is rewritten through `Runtime::for_each_root_family_mut`, the mutable twin of the value gather; every `Eterm`-keyed map (`Eterm`'s `Hash`/`Eq` are the raw word) is re-derived or is provably out of reach — `SelectWatch::by_fd_handle` is rebuilt by `PortRegistry::rekey_select_handles`, while `Runtime::references`, `Timers::refs` and `TimerWakeTargets::deliver` need no re-keying because each of their keys is minted on a **pooled BIF heap**, a different region family; and the address-valued bookkeeping is re-anchored (`eval::scratch::Window::base` and the pass's cursor are recomputed and the statement window is dropped, while `gc_walk::Visited` is generation-scoped and cannot outlive its walk).
  What stays pinned: the **arena** is never moved, only rewound above a mark (Tier A, `MinimalContext::heap_rewind`); the pooled BIF heaps are never moved or freed, only rewound to a call's mark; and a store word held by an **in-run** holder — a nested run's machine, the evaluator's Rust-frame terms — is in no door's reach at any in-run point (the Phase-2 blocker: `src/eval/CONTEXT.md` *Phase 2*, `src/context/CONTEXT.md` *Reclaim*).
  Two facts a compaction design must carry and no single child node records: (a) `Runtime::eval_compiled`'s `CompiledClosure.captures` (`src/eval/compile.rs:123`, filled at `:195`) is a **word copy of `FunBody.env`** that `Runtime::gather_off_heap_roots` never walks — the payload census reaches it transitively, a moving store must update it in lockstep (the mutable walk does, as `RootFamily::EvalCompiledCaptures`); (b) the whole `-eval` driver runs under `with_relocation_exempt` (`src/eval/mod.rs:459`), so on that route every growth a *collection* would need is refused and its terms live on `eval_heap`/the arena until the driver returns — the store move can therefore act only at a statement boundary or after the driver, never inside a nested run.
The per-store inventory: `src/context/IMPLEMENTATION.md` (*at-risk roster*), the per-node relocation inventories in `src/CONTEXT.md`, `src/runtime/CONTEXT.md`, `src/eval/CONTEXT.md`, `src/port/CONTEXT.md`, `src/dist*/CONTEXT.md` and `src/native/CONTEXT.md`.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one and an unclaimed call returns `None`.
**`src/native/CONTEXT.md` is the dispatch table** (the source of truth), the implemented/not-implemented BIF index and the drift guard.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
The floor owns the **process/name/global-state arms** (`ProcessBridge`'s only implementation), `process_info/1,2` (`src/native/memory/`, which the `ProcessHook` seam cannot express because of the `{dictionary, K}` item form), `monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` with the reference-alias send destination (`src/native/process/`: a monitor's reference doubles as an alias, resolving through `src/context/alias.rs::alias_destination` on **both** send seams) and `erlang:garbage_collect/0,1` (`src/native/erts_internal.rs`) — **no BIF may collect**, so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true` where the root set is owned.
**`code:*` reads and the code path are the floor over `CodeServer`**, alongside a live `code_server` process: the floor owns the **one** authoritative path store — the readers **and** the `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1` mutators — so **`src/native/code.rs`'s `code:*` behaviour must not change**, and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store*).
`Runtime::new` starts exactly **three** runtime-owned, never-enqueued `Runnable` processes (the `init` root, the `erl_prim_loader` stand-in and the `file_server_2` service — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)), and `call_bif`'s last resort is the **`erlang` namespace**: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`, with `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` and its drift guard the authority.
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **two** built-in key sets — `prim_tty`'s 20 stub keys and `zlib`'s 19 stream keys — from a module-name equality short circuit plus a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`, with `local_fun_target` declining such a target) serves the **record-held** shape of the same two sets: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body.
The `zlib` stream API is live end to end through the real preloaded `zlib.beam`, oracle-identical at every level 0–9, and `set_controlling_process/2` carries **no** stream-state precondition, so a closed, an ended and a fresh stream all answer `ok` — `tests/zlib_{stream_levels,stream_dict,guards,one_shot}.rs`.
Detail: `src/context/CONTEXT.md` (both indirections), `src/native/CONTEXT.md` (`prim_tty`), `../beam_bifs/src/zlib/CONTEXT.md` (the 19 keys).

| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse order), `-pz` **tails** it (behind the system `ebin`s), on **every** route |
| `+S Total[:Online]` | the normal scheduler counts, read with the C's `sscanf("%d:%d")` → `sscanf(":%d")` cascade: the total → `emulator.schedulers`, the optional online half → `online_schedulers`; the `+SP`/`+SDcpu`/`+SDPcpu`/`+SDio` sub-forms are validated and preserved verbatim (inert here) |
| every value-taking `+` switch | accepts its value **attached or separate** (`+S1` ≡ `+S 1`, `+sbtu`, `+A0`, `+P65536`, `+sbwtlong`), the C's `get_arg` rule — that is the form the real `erlc` passes; per-switch value grammars (digit-prefix vs symbolic) are [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md)'s |
| `-extra …` / `-- …` | plain arguments → `init:get_plain_arguments/0` (a list of strings), never an init argument. Split per **entity** (`ERL_OTP30_FLAGS`, `ERL_AFLAGS`, argv, `ERL_FLAGS`, `ERL_ZFLAGS`) at that entity's first `-extra`, whose whole tail is plain; `--` collects until the next switch-looking token (`-`/`+`) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A<n>` / `+P<n>` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q<n>` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+sbt<type>` | scheduler bind type, preserved verbatim (`u`/`db`/`s`/`ps`/`ts`/`tnnps`/`nnps`/`nnts`/`ns`); an unknown type is the C's rejection |
| `+K<true\|false>` | kernel-poll switch, preserved verbatim |
| `-extra [token…]` | **ends the switch surface**: every remaining token is a **plain argument** (`RuntimeConfig::plain_args`), which `init:get_plain_arguments/0` answers; nothing after it is an init argument or a Start instruction |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking driver/port round trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* **A `+`-switch with a value takes it attached or separated** (the C's `get_arg`): `+S1` ≡ `+S 1`, `+A0` ≡ `+A 0`, `+P65536` ≡ `+P 65536`, `+Q1024` ≡ `+Q 1024`, `+sbtu` ≡ `+sbt u`, and `+SP`/`+SDcpu`/`+SDPcpu`/`+SDio` are the validated-but-inert percentage/dirty-scheduler sub-forms — [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md) *The `+`-switch value rule*.
* **The OTP `erlc` C front end drives this runtime unchanged**: `ERLC_EMULATOR=<beam_rt> erlc +deterministic -o <D> <src>` (argv `+S1 +sbtu +A0 +P 65536 +Q 1024 -noinput -mode minimal -boot no_dot_erlang -s erl_compile compile_cmdline -extra …`) exits 0 and its artifact is **byte-identical** to the plain oracle `erlc`'s; the route needs the attached `+`-forms above and the `-extra` plain-argument list (`erl_compile:compile_cmdline/0` reads it).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`) and an unmodeled switch is **data, not a usage error**; a `+` emulator switch and a plain (`-extra`/`--`) argument are the two exceptions — neither is an init argument. The full switch surface, the per-`+`-switch value grammar, `RuntimeConfig::plain_args`, the `run` action's `ARG` token kinds (`M1_GAPS.md` *CLI `run` argument tokens*) and the `ERL_AFLAGS`/`ERL_FLAGS`/`ERL_ZFLAGS` merge are [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md)'s.
### The `-eval` route (`src/eval/`)
`-eval` walks the Erlang **expression** subset `erl_eval`-style — arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3), per the grammar, quoted-atom and named-fun-form rules [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) states.
`receive … after T` scans the running process's **real mailbox**, pumps the scheduler non-blockingly (`RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass and spends the remaining window on the runtime's timer heap through `Runtime::wait_for_timer`; a port round's messages are **delivered into that mailbox** before any clause is tried, so the scan stays selective and an unmatched frame stays queued.
A closure `erlang:spawn/1` starts is **compiled** (`src/eval/compile.rs`) from its own recorded source text into a synthetic `beam_rt_eval_fun_<index>` module (`compile:file/2` in process, then `code:load_binary/3`), so the child is an ordinary `ProcessEntry::Export` that really parks on a bare `receive` or a `timer:sleep/1` and is resumed by a later send; the result — a decline included — is cached per closure index on `Runtime::eval_compiled`.
Residuals: a `spawn` made from inside a running engine (`src/native/process.rs::spawn_in_pass`) keeps the tree-walking entry, where a bare `receive` is the typed gap and a parking callee folds into `beam_engine::blocked()`; a **declined** compile keeps that closure's gaps; `receive … after infinity` is a typed gap — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Known Issues*.
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`), and is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so a self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call**, or the engine cannot land it in a catch frame: `src/context/calls.rs::name_raise_reason_atom` appends it (append-only, at `PendingInterner`'s predicted index) on the **one** funnel every failed call passes, so a module that never spells the atom still catches `error:R` as the oracle does — the shape a `zlib` guard raises; a capability gap is deliberately **not** interned there, which is what keeps exit 3 uncatchable.
A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export`, so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears).
**The per-key catalog — every served key, its own-state source and the `dist`/`dist_ctrl`/`start_time`/`end_time`/`context_reductions` specifics — lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`, with no crate-local error enum, no `panic!`/`unwrap()` on runtime data and no silent swallowing; CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))` instead of stderr writes.
* **`unsafe`-free by default, with per-module exemptions.** The crate is `#![deny(unsafe_code)]` and the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`); ten modules carry their own `#[allow(unsafe_code)]` with a `// SAFETY:` rationale at every site — `src/malloc.rs` (one `libc::malloc_trim(0)`), `src/nif.rs`, `src/context/{calls,gc,gc_walk}.rs` and `src/context/gc/{bin_vheap,valve_bounds}.rs`, `src/eval/reclaim.rs` + `src/eval/reclaim/resource.rs`, and `src/runtime/reclaim/compact.rs` (the store move: `beam_gc`'s `FromSet`/`LinearDest`/`Relocator` over raw region pointers, where the caller's completeness claim is the safety contract).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility, `#![warn(missing_docs)]`, every public item documented; oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`), and the transport copy resolves one of them into its **source** table so the destination **shares** the handle.
  A source table that cannot name the owner makes `beam_message`'s copier **flatten** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful and sound, a refc binary's `base_flags` word carrying its payload pointer — as the **last resort** only (the send path unions three source families, so a resolvable payload takes the SHARE route).
* **A live heap serves its own builds; the pointer-stable arena is a refusal-only fallback.** `src/context/gc.rs::alloc_words_rooted`'s **unarmed** arm (every nested run — a cross-module callee's second `Machine`, an applied fun, the `-eval` evaluator) serves the block from the running process's **scanned young heap** whenever its context names a process; `Runtime::alloc_words` (the arena: nothing ever scans it, its regions never move, and the region pass rewinds it only above a mark where nothing reachable stands) answers only a genuinely table-less context (`-eval`/single-pass, the boot drive, a pinned or halted pid) or a refused growth. `beam_gc`'s copier leaves a `Target::Foreign` container verbatim **without descending**, so a container built in the arena would keep a stale child word once any collection relocates its young-heap children — the `invalid boxed header subtag` abort class. The complementary half: **a young-space replacement needs a complete root set** — `gc.rs::may_replace_young_space` is the single predicate every growth site consults, so inside a relocation-exempt window (whose roots are unpublished by construction) the copy-out `stabilize`s onto the store instead of growing ("refuse ⇒ stabilize, never dangle"), and every collapse door refuses an exempt process outright. Pinned by `src/context/gc.rs`'s unarmed-arm case, `src/context/calls/exempt_window_tests.rs`, `tests/nested_run_allocation_heap.rs` and `tests/path_length_independence.rs`; the rule in prose: [`src/context/CONTEXT.md`](src/context/CONTEXT.md), [`src/context/gc/CONTEXT.md`](src/context/gc/CONTEXT.md).
* **A park that skips root publication holds the relocation exemption.** The three runner park arms (`Yield`/`Suspend`/`Wait`) go through the **one** entry point `src/runner/run.rs::park_window`, deriving a single `exempt` value from a `ParkExemption` argument and writing the process flag from it in **both** directions; `park_machine` is its private publication half. Skipping publication without the exemption would let the next `serve_gc_request` collect the space the parked machine's only-copy terms live in, so the two halves are structurally un-splittable. A served `erlang:garbage_collect` request also short-circuits the boundary door behind it (which would otherwise re-publish pre-collection words over the relocated registers). Pinned by `src/runner/tests.rs`'s three park cases; detail: [`src/runner/CONTEXT.md`](src/runner/CONTEXT.md).

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md), under the section named after each bullet or the sibling ledger that section's stub names; the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **Fun application nested from a BIF is unbounded in depth; the driver thread's stack size is the only bound.** Every `beam_bifs` `BifContext::call_fun` enters a **nested run on the same thread** (`src/context/bridges.rs`'s `FunBridge::nested` (which clones `current_module`) → `RuntimeContext::apply_fun` → `pump::run_label_blocking` → a pooled `Machine`) at **29 Rust frames and ≈8.4 KB of thread stack per level**, and nothing caps the depth: `machine_pool::MAX_CALLEE_DEPTH = 32` is that pool's per-callee *idle-machine* cap and `BLOCKING_PUMP_DEADLINE` bounds wall time, not nesting, so ≈**996** live levels exhaust an 8 MiB stack (28 964 Rust frames measured) and abort the whole runtime (`fatal runtime error: stack overflow, aborting`, exit 134).
  `src/main.rs` therefore runs `cli::run` on a named `"beam_rt-driver"` thread with `MAIN_STACK_BYTES = 64 << 20` (≈7 900 levels, ~8× what the deepest legitimate compile needs) — a **bound-raising mitigation, not a fix**; the real fix is bounding/trampolining the seam the way `beam_abi`'s `enif_schedule_nif` trampoline does.
  Minimal reproducer (aborts at N=1000, fine at 900; `ulimit -s 65536` makes N=5000 pass; `BEAM_RT_TIER=interpreter` unchanged; a fun applied from *Erlang* code, `g(F) -> F()`, does not nest): `-module(deepnest). -export([f/1]). f(0) -> ok; f(N) -> lists:foldr(fun(_X, A) -> f(N-1), A end, ok, [x]).`
  The A.9-visible form is `beam_core_to_ssa`'s match-tree recursion — `match/4` (`foldr`) and `match_con/5`/`do_match_value/5` (`mapfoldl`) spend one Erlang-level fun application per decision-tree level (499 `mapfoldl3` + 497 `foldr3` frames for one 256-segment case), so a clause head of many **variable** bitstring segments overflows while `to_core`/`erl_lint` stay fine: `f(<<V0:8,…,V255:8>>) -> ok; f(_) -> no.` aborts at 256 and is fine at 224 (2 clauses × 768 *literal* segments: 640 fine; a single 8 000-literal-segment clause is fine because `combine_lit_pat`/`build_bin_seg` squeeze it). `lib/ssl/src/ssl_srp_primes.erl`'s five literal SRP-prime patterns compile under the 64 MiB stack; pinned by `tests/compile_file.rs::a_clause_head_with_256_variable_bitstring_segments_compiles_in_process`, which fails at `8 << 20`.
  The deepest backtrace frame is incidental — the GC valve walk (`context/gc_walk.rs::Walk::seed` / `context/gc.rs::forwards_word_matching`) is an iterative `scratch.pending` worklist, a victim of the exhausted stack.
* **A `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work, not `beam_rt`'s dispatch** — the wired path is allocation-free — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **No interactive shell** — no Erlang-level distribution subtree runs (`net_sup`/`auth` stay `undefined`), and every inbound family takes the C's route-free receipt, never echoing a `DOP_*` — `M1_GAPS.md` *Distribution and the node (A.5)*.
* **An inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** — a typed divergence from the C — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order, and `badarg` for a module not loaded here — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **Own-state answers differ by construction** (not bugs) — `processes/0`, `ports/0`, `port_count`, the `module_loaded/1` boot-set size and the `process_info` figures — `M1_GAPS.md` *Own-state answers*.
* **`process_info(P, binary)`** answers the oracle's `{Ptr, Size, Refc}` tuples from the deduped union of the target's engine reservoir (`RunnerState::reservoir_at` for another pid, the in-machine door for the executing one) and its PCB off-heap table, `erlang:memory(binary)` being the separate `binary_alloc` figure — `M1_GAPS.md` *`process_info/1,2`*.
* **Process-control gaps** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}` and `exit/2,3` against an internal port or a foreign reference — `M1_GAPS.md` *Process-control families*.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included), and the gift copy boundary holds on both install routes: `ets:new/2`'s creation-time `{heir, Pid, Data}` is copied by `Table::new`'s build path, `ets:setopts/2` installs through `Table::install_heir` (`beam_bifs/src/ets/adopt.rs:308`), and the `{'ETS-TRANSFER', Tid, FromPid, Data}` message the drain builds on the pooled BIF heap (`src/runtime/ets_owner.rs:616`) is deep-copied into the heir's mailbox — `M1_GAPS.md` *ETS ownership*.
* **The `ets` table-alias boundary is a witness `Cell<bool>`, not an address check.** `RuntimeContext::call_registered` creates **one stack `Cell` per dispatch** (`src/context/calls.rs:449`), installs it on every `BifContext` arm, and copies an aliased container out **before** `heap.reset_to(mark)`; a nested call re-enters `call_registered` and gets its own cell, so the outer answer is never confused.
  Nothing range-checks a result against a table's `TermStore` — the witness is the only signal — so a BIF handing back table words **without** `copy_out`/`copy_out_list` is silently un-copied, and `result_is_foreign_container` (`calls.rs:1131`) classifies by tag, not by provenance.

  The hard invalidation point is `TermStore::reset` — `ets:delete_all_objects/1` on an unfixed table (`beam_ets/src/table/mod.rs:773`) and `Drop for TermStore` (`beam_ets/src/store/mod.rs:848`), which `ets:delete/1` reaches because `delete_1` drops the `Table` it took (`beam_bifs/src/ets.rs:846`).
* **`process_info/1,2`** answers ~28 items from real state, `port_info(Port, monitors)` stays `[]`, and a non-byte-aligned `-eval` result cannot be printed by the registered `io:format` printer — `M1_GAPS.md` *`process_info/1,2`* / *Printing*.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget** — a refusing `BudgetProbe::charge`, a pricing `BudgetProbe::spend`; a BIF-and-call-only loop ends no slice of its own on the native tier — a fairness defect, never a wrong result — `M1_GAPS.md` *Scheduler / runner*.
* **`process_info(P, garbage_collection)`'s `minor_gcs` is `Collector::minor_since_major`, NOT a collection total** (a fullsweep resets it to `0`); the monotone totals are `Runtime::gc_stats().collections`/`beam_gc::AnyCollector::stats()` — `M1_GAPS.md` *`process_info/1,2`*.
* **An allocate-and-abandon loop is collector-bound, never arena-bound** — the per-op cost is the collector's own Cheney traversals, and on the **native** (default) tier a flat `heap_size`/`erlang:memory(processes)` is a converged capacity — `M1_GAPS.md` *Scheduler / runner*.
* **A tail loop of registered-BIF calls leaves the reported heap capacity flat.** `total_heap_size` reads **466 words** (`heap_size` 233) after 300 000 `integer_to_list/1` calls and the same 466 after 600 000, against 233/233 at N=1 — a copy-out result is re-homed onto the process heap and the pooled BIF region is rewound, so nothing is retained per call.
  The chain-sum machinery those figures come from is still what `process_info(P, total_heap_size)`, `erlang:memory(processes)` and `MaxHeapUsage::heap_words` (what `max_heap_size` compares, `beam_process/src/max_heap.rs`) report: `Nursery::grow`/`install` **retire** the space they replace and only `collapse` frees it (`beam_gc/src/nursery.rs`), so a growth that no collection follows lengthens the chain — the state `Process::collection_debt` names, settled by the next collecting door.
  That chain is **not** what an in-process `compile:file/2` retains on either route: the copy-out seam it needs is guarded by `mailbox_table.as_deref_mut()?` (`calls.rs:1490`) on the table-less `-eval` route, and on the `run <file>` route the compile's own work happens in nested runs whose context also carries `mailbox_table: None`/`gc_armed: false` (`src/context/bridges.rs`) — after a completed `cerl_clauses` compile the process reads `total_heap_size` **12 788** / `heap_size` **6 016** words (`run`) and **233** words (`-eval`).
  The compile's host memory is not a count of `heap_words`-sized reservations either: the `bif_heaps` pool is **depth-sized** (128 MiB for the outermost call, 1 MiB per nested level, self-tuned to `2 ×` an observed peak), so an in-process `cerl_clauses` compile ends at **6** regions / 133 MB of reservation against **5 397** words ever written (`BEAM_RT_MEM_TRACE=1`).
  Reservation is not RSS: a region is a lazy `mmap`, so that 133 MB is invisible in RSS and `erlang:memory(total)` stays blind to it (~5.8 MB after the compile) because those regions are `AllocType::Standard`.
  What does move RSS is written pages, measured on the `run` route with the tree's OTP-30 bootstrap compiler first on `-pa`: peak `VmHWM` **424 MB** (`cerl_clauses`, in-process) / **307 MB** (`orddict`), against **121 MB** for a bare boot.
  `inet_parse` (37 KB) completes only with the compiler **inside** the calling process (`no_spawn_compiler_process`): **7.81–8.22 GB** peak / ~17 s on the `-eval` route under the tree OTP-30 bootstrap compiler (`5 203–5 260 MB` / 12.1–12.6 s under the system OTP-29 one), while the default form (a spawned compiler child) outlives the 900 s blocking deadline; the `run` route never finishes it (`RUN_DEADLINE`, 60 s, exit 1 — 222 400 kB peak with the compiler in-process, 670 720 kB with the spawned child, 219 680 kB under the tree compiler).
  `dbg_iload` does not complete at all and reaches **813 MB** at the 25 s cap.
  Two mechanisms carry the multi-GB figures and both are still open: the `-eval` store's **retired chain** (4.63 GB, 59 % of the peak — fully written and resident) and the `beam_engine`-owned **arena** (2.85 GB of written pages over 16.18 GB reserved, 37 %) — the measured per-mapping split, both mechanisms' bound rule and the missing APIs are [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *The bound …* + *Reclaim …*.
  The full attribution, the per-route table and the sound-vs-unsound reclaim list are [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *Host-memory retention …* + *What is still unbounded …* + *Reclaim …*.
* **A nested fun application's nursery chain is bounded by the debt gate.** A host BIF that applies a fun argument (`lists:foldl/3`, `maps:map/2`, …) enters the runtime through `FunBridge::nested` → `apply_fun` → a **second machine** whose context is `gc_armed == false` while the pid is marked relocation-exempt (`src/context/runtime_context.rs` `with_relocation_exempt`, entered at `src/context/pump.rs` `run_export_blocking`/`run_label_blocking` and `src/context/execution.rs`'s `apply_fun`), so no collapsing collection door can fire for the duration while that run's registered-BIF copy-outs keep growing the young heap through the **no-collect** `Process::grow_nursery` seam.
  `src/context/execution.rs`'s `resolve_external_call` therefore declines the `lists`/`maps` fun-applying keys while the calling process carries collection debt (`nests_a_fun_apply` ∧ `calling_process_has_collection_debt`, the roster being `beam_bifs::needs_fun_caller`), so the call is entered **in-machine on the caller's own armed machine** and the debt door collapses the chain as it grows.
  The two `ets` folds deliberately stay on the synchronous path (their bodies reach a gated `lists` key internally), and a table-less (`-eval`) context reads no debt, so the gate is inert there.
  Measured with `BEAM_RT_GC_TRACE=1` over a 25 s `dbg_iload` window on the `run` route: `chain_spaces` peaks at **6** with **17 121 896** chain-summed used words and peak `VmHWM` **813 MB** (system OTP-29 compiler), or **10** / **37 189 421** words and **690 MB** (tree OTP-30 bootstrap compiler).
  What the gate does **not** cover: a nested run entered while the caller owes no debt, a key outside the `lists`/`maps` roster, and a fun applied from a context with no process table.
* **The two long-lived term regions are reclaimed wherever nothing is executing; a single in-flight statement still pays the full peak.** `src/runtime/reclaim.rs` runs **one** reachability descent at two non-running sites (the `-eval` statement boundary and the driver exit) and does three things with it: rewind the arena above its mark (`MinimalContext::heap_rewind`, Tier A), drop a whole-dead `eval_heap_retired` region (its `Heap::drop` frees the carrier), and evacuate a partially live one into one fresh region through `beam_gc`'s `Relocator` behind a **post-move verification** that keeps every source on a hit. Measured on a single `inet_parse` compile: the retired chain **19 → 1** regions (603 193 147 words reclaimed) and 11 arena regions recovered; on a **two**-compile `-eval` the peak falls **3.07 GB (−19.0 %)** (16 175 512 → 13 109 804 kB), and that win is the arena rewind while the store chain stays additive there (`store_compactions=0`, the move refused by the verification).
  What is **not** bounded is the peak *inside* one in-process `compile:file/2` (8 197 644 kB for `inet_parse`, unchanged within 0.03 %): the store still retains the copy-out volume since the last reclaimable boundary — region-capped at `MAX_EVAL_HEAP_WORDS` (256 MiB) but not chain-capped, because a retired region is full and never rewritable — and `arena_words` reads **1 328 036 633** (10.6 GB of cumulative demand over 7 045 408 calls) on that run. Peak RSS is therefore ≈ copy-out volume + arena written pages + O(1) — 4.63 + 2.85 + 0.23 GB for `inet_parse`.
  The binding holder is the **in-flight machine stack together with the evaluator's Rust-frame root set**: `Runtime::in_machine` is a single slot (`runtime.rs:652`), a parent machine's `&mut` is a Rust local of `src/context/pump.rs`, and the driver's `Env` is a `HashMap` in another frame — no `&mut` reachability exists for either at any of the three Phase-2 points, so `with_relocation_exempt` stays. Detail: [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Phase-2 blocker*, [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *The region-reclaim pass*, [`src/context/CONTEXT.md`](src/context/CONTEXT.md) *Reclaim …*.
* **The `-eval` store's written volume, not the region pass, is what one long statement costs in RSS.** A single `-eval` statement that compiles a module in process writes ~27 MB into `Runtime::eval_heap` (the 128 MiB seed region): `smaps` at the peak shows the store's one mapping (`size=131 080 kB`) holding **26 916–27 988 kB** of written pages, while under the pre-window binary the same mapping never rises above ~2 MB. The writer is the exempt-window stabilize arm of the process-route copy-out (`src/context/calls.rs` → `src/context/pool.rs`, which copies the graph into the store because a relocation-exempt window may not replace the young space), not `src/runtime/reclaim.rs`: the pass's own A/B switch (`BEAM_RT_REGION_RECLAIM=off|arena|nomove|store-whole|store|all`) moves peak RSS by at most **580 kB** on that workload, and its exit counters read `store_compactions=0 store_regions_dropped=0 store_move_declines=0` with `arena_reclaims=2` releasing 285 words. Per-writer detail and the ranked sound options for a future fix: [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **The store's written prefix inside one statement is bounded by the statement's copy-out volume, not by program history.** Nothing may rewind it mid-statement — `pin_window_if_store_written` latches the statement window with a transient pin on the first store write and the window's rewind refuses, and a region pass is refused while a machine is in flight — so the two reclaim points are the next top-level statement (`Site::Boundary`) and the driver exit (`Site::Exit`). Growth is by copy-out shortfall (doubling, clamped by `MAX_EVAL_HEAP_WORDS = 1<<25` words per region); a measured single-statement compile writes ~27 MB of a 128 MiB seed and replaces no region (`eval_heap_retired_regions=0`). The figure is therefore a peak that the following boundary gives back, and it does not grow with the number of statements already run.
* **A user process's nursery is live-set sized and flat in N** (not a gap; the rules are `beam_gc`'s `HeapPolicy::young_minor_target_words`/`young_target_words`, one × the round's own `GcStats::words_copied` plus the reserve, and the shrink/keep band around it): `reds_boundary`'s boundary `heap_size` is a flat **987** = `young_target_words(401)` = `next_words(2·401+64)` on both tiers — a fixed point of both the fullsweep and the minor keep rule — the interpreter control reads the **233**-word floor (`young_minor_target_words(0)`), and `churn` holds a flat **2 585**-word nursery (the last growth-table entry below the `YOUNG_SHRINK_FACTOR` ceiling `8 × 376`) and a flat **6 772**-word mature region at every N — [`src/runner/MEASURED.md`](src/runner/MEASURED.md).
* **Execution tier defaults to `JitMode::Auto`** (`src/runner/tier.rs`), compiled lazily per function, `BEAM_RT_TIER` over it — `M1_GAPS.md` *Execution tier*.
* **CLI divergences and subset gaps** (`-smp disable` accepted, `-setcookie` unmodeled, the `-eval`/`-s`/`-run` subsets) live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
* **NIF loading is live** (`load_nif/2` really `dlopen`s) and every `NifHostServices` hook is live on a **call** (a thread a NIF created runs on its own process-independent host, next bullet) — `M1_GAPS_A3_NIF.md` *NIF (A.3)*; a compiled module's local fun encodes faithfully, an `erl_eval` lambda stays `unsupported: local_fun` — `M1_GAPS.md` *Funs*.
* **A NIF-created thread has a real host** — `src/nif/thread_env.rs` (`ForeignHost`/`ThreadEnvFactory`, installed by `Runtime::install_nif_thread_env` from `cli::build_runtime`, torn down by `clear_nif_thread_env`), with atom creation landing in the factory's **private** name→index space (`src/nif/atoms.rs`) and the name crossing into the live table only in the drained ETF image, and `enif_send` drained by `Runtime::drain_nif_thread_sends` at `try_call_nif` and at the scheduler pass's port step.
  Its `enif_send` is a **documented substitution, not parity**: the message is queued at `enif_send` time (answering the C's `1`), then decoded against the live table and delivered — a parked receiver woken through resume-on-send — at the runtime's next drain, where the C delivers synchronously inside the call; an unencodable image, an undecodable one and a dead target are skipped and counted, never a fabricated term.
  Its typed gaps (each a typed `None`/`false`) are the nested-atom name order (`atom_table` is `None`), select/monitors/liveness/`make_ref`/`system_info`/the codec hooks, a remote pid destination (the C's `1` where this answers `false`), a local `make_fun3` closure in the message, an unnameable atom, and `enif_make_existing_atom` answering within the private space only (a name the runtime created but the foreign space never saw is `false` — an under-answer, never a wrong index) — `M1_GAPS_A3_NIF.md` *Typed gaps on the foreign-thread host*.
  Pinned by `src/nif/thread_env_tests.rs` (host + hub + drain, no toolchain) and the three oracle-cross-checked suites `tests/nif_a3_{thread_env,schedule,resource_stop}.rs` (35 observations: 25 agree, 10 divergences — nine the `enif_thread_type()` driver-thread answer, one `enif_schedule_nif`'s raw return word).
* **`enif_schedule_nif` chains run, and `nif_yield_point` is a documented no-op** on both hosts: a chain runs inside one BIF call on the engine's thread, the runtime must not re-enter its scheduler from under a NIF, no reduction primitive is host-reachable and `dirty_scheduler_support` is `0` — so a self-rescheduling chain keeps its thread until it ends, a **fairness** gap, never a wrong result.
* **A socket's `{active, true|N|once}` input arrives as the oracle's own messages** to the **owning** process through the mailbox path, and an **accepted** socket inherits the listener's option block by struct copy in the driver — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*.
* **Ports match the oracle's observable shape**, the `line`/`{line,N}` stream option is adopted, and `port_command/2,3` runs `beam_io`'s decision table — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*, [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **A nested (`-eval`/`-s`/`-run`/boot) passive socket operation really waits for its `{inet_async, …}`** — a passive `gen_tcp:recv/2,3`, a `gen_tcp:accept/1,2` and a `gen_udp:recv/2,3` are sat out by `RuntimeContext::wait_for_port_event` over the blocking pass, bounded by `crate::port::PORT_EVENT_DEADLINE`; the residual is `beam_io`'s accepted-socket pre-buffered read — [`src/port/CONTEXT.md`](src/port/CONTEXT.md) *The nested port wait*, `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*.
* **A driver that closes its own port is a full closer** — the owner and every monitor get the failure's **own** reason and the port is as gone as a closed one — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*.
* **The send family** serves `erlang:send/2,3`/`erlang:'!'/2`, including a **reference-alias**, a **remote** destination and a local **port** id — the port arm is the C's `do_send`/`port_common` block handing the term to `erts_port_command`, where only `{InternalPid, {command, Data}}` writes while every other payload answers the message — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*.
  A registered **port name** and a **remote** port term stay typed gaps, as does an unreachable remote destination.
* **Reference aliases: the honest residuals** — a send to a reference that is **not a live alias** is the typed `badarg` (the C silently drops it), and reference **identity** stays unclosable — `M1_GAPS.md` *Reference aliases*.
* **Driver ports (A.4) load and drive a real C driver end to end**, with **35 of the 45** `DriverHost` hooks live and the rest typed gaps — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*, [`src/port/driver/CONTEXT.md`](src/port/driver/CONTEXT.md).
  **A driver port owns no OS child, and that is a fact rather than a gap** — `[exit_status]` is the oracle's `badarg`, `{exit_status,N}` cannot exist, and `port_info(Port, os_pid)` follows `erl_drv_set_os_pid` — [`src/port/exit_status_matrix_tests.rs`](src/port/exit_status_matrix_tests.rs).
* **`erlang:send_after/3`/`cancel_timer/1` are native-floor capabilities**, as are the `RuntimeHooksBridge`'s timer/link/module keys; `erlang:system_info/2` and every other unserved `RuntimeHooks` key are typed gaps — `M1_GAPS.md` *Timers*.
* **The runtime drives `beam_gc` at four collection points, three of them heap-admission doors** (`src/context/gc.rs` + `src/context/gc/reds_door.rs`); a failed collection halts that process's collection, never the program — `M1_GAPS_GC.md` *GC / heap model*.
  The **boundary door** is what makes a BIF-only loop collectable, and on the **default (native-baseline) tier it is unreachable** — a fairness defect as much as a GC one — `M1_GAPS_GC.md` *GC / heap model*, `M1_GAPS.md` *Scheduler / runner*.
* **The unscanned-root valve declines a collection only where relocation is genuinely unsafe** — `context/gc.rs::root_is_unscanned` is a **two-fact** predicate, so a foreign leaf, an all-immediate block or a null/unaligned word is inert — `M1_GAPS_GC.md` *GC / heap model*.
  Consequence: a reference-minting loop keeps `erlang:memory(processes)` flat, and a loop holding one registered-BIF result container live still collects — `M1_GAPS_GC.md` *GC / heap model*.
* **The engine's off-heap refc-binary reservoir is PRUNED at every pre-emption, not accumulated** — the release moves nothing, **every gate is a decline so the residual is a leak, never a dangle**, and the measured envelope is **flat in N** — `tests/off_heap_reclaim.rs`, `M1_GAPS_GC.md` *GC / heap model*.
* **The runtime's escaped-payload store (`Runtime::eval_off_heap`) is PRUNED at two points** — refusal is **doubt ⇒ decline**, the nested point prunes only the handles its own run adopted, and the store publishes no per-pid figure — `M1_GAPS_GC.md` *GC / heap model*.
* **`erlang:memory/0,1` are adopted**; **`erlang:statistics/1` is partly served** (its `garbage_collection` key carries the real node-global counters), the per-scheduler/msacc keys and `statistics/0` being typed gaps; **the heap switches are modelled** through `beam_gc::HeapPolicy`, and `+hmax N` **is** a cumulative ceiling on the nursery chain — a growth may only claim `max_heap_words - capacity_words()`, the verdict compares the chain sum (`beam_process::MaxHeapUsage::heap_words`), and an over-cap allocation answers `error:system_limit` (measured: a 833 259-word live term under `+hmax 50000` exits 1, the same term under `+hmax 1000000` succeeds at `total_heap_size` 833 259) — `M1_GAPS_GC.md` *Heap switches*.
  Residual: a growth **refused** at an unrooted seam (`context/gc.rs::alloc_words`, `context/calls.rs::move_result_into_process_heap`) falls through to the pointer-stable arena instead of raising, so that block sits outside the heap accounting the verdict is computed from — `M1_GAPS_GC.md` *Heap switches*.
* **`max_heap_size` is ENFORCED, end to end** — `src/native/process.rs::max_heap_setting` serves `process_flag` and `spawn_opt`, a breach is the ERTS `=ERROR REPORT====` block plus a `Kill` latch, and the check is on the **prospective post-collection capacity**, never occupancy; the residuals are the stderr-only report and **7 of the C's 9 fields** — `M1_GAPS_GC.md` *Heap switches*.
* **`+hmax` bounds user processes, never the runtime's own boot processes** — `Runtime::system_spawn_policy`/`default_spawn_policy` hand boot-spawned processes an uncapped policy inside the `Runtime::booting` window, so an over-cap `-eval` allocation is `beam_rt: system_limit` (exit 1); at `+hmax ≤ 1024` the boot's own term construction still fails and is mapped to `blocked()` → exit 3 — `M1_GAPS_GC.md` *Heap switches*.
* **A.9 self-hosted compile in ONE invocation, driven by the tree's own committed OTP-30 bootstrap compiler.** With the bootstrap compiler first on the path (`-pa` **absolute** `bootstrap/lib/compiler/ebin bootstrap/lib/kernel/ebin bootstrap/lib/stdlib/ebin`, in that order — a relative dir silently runs the *system* compiler instead), the scheduled route compiles **651 of the 653** oracle-compilable sources of the `lib/*/src/*.erl` **≤60 KB stratum** (6 shards, all completed: 667 attempted, 14 of them failing on the oracle too); the ≤30 KB stratum is 505/505. The one remaining residual is `debugger/dbg_iload`'s `system_limit` — a host-region/typed-limit residual (see *Known Issues* below), not a compiler/loader/engine gap — and `ssl/ssl_srp_primes`, the former SIGABRT, compiles in ~50 s under `MAIN_STACK_BYTES`.
  The **121** sources **>60 KB** are not attempted: the tree compiler costs **600–1000×** the oracle (`erlc` 0.197–1.259 s vs 2.2–235 s) and its cost is content-driven rather than size-linear (13.8 KB → 2.5 s, 54.7 KB → 235 s), with `BLOCKING_PUMP_DEADLINE`'s 900 s the hard ceiling. `kernel/inet_parse` (37 KB, in the swept stratum) is the same family's other in-tree instance: on the **`-eval`** route it completes in ~17 s at a **7.81–8.22 GB** peak `VmHWM` under the tree compiler (12.6 s / 5.26 GB system), and on the **scheduled** `run` route it does not finish inside `RUN_DEADLINE` (60 s) — the compile's cost is content-driven, not size-linear; under a `1<<24`-word `max_heap_size` it answers `lint_module`/`system_limit` in 912 ms.
  With the **system** OTP-29 compiler the same route is byte-identical over **755/772** (17 fail on the oracle too). Tree-vs-oracle artifacts: the `Code` instruction stream is **identical**, `opcode_max` is **183 vs 181** (the deliberate `lib/compiler/src/beam_asm.erl:99-103` `executable_line/2` reservation), and the `Attr` `-vsn`/`FunT` `uniq` words follow mechanically from `module_md5` over the `Code` header — verified on `beam_flatten`, `cerl_clauses` and `beam_lib` (the >30 KB one, whose remaining code deltas are exactly four OTP-30-vs-29 codegen shapes).
  **No full self-hosted build** — the runtime does not build *itself* into a release — `M1_GAPS.md` *A.9 E0*, [`EPP_SCHEDULED_ROUTE_FINDINGS.md`](EPP_SCHEDULED_ROUTE_FINDINGS.md).
* **There is no io server; the `io` device floor serves the request wrappers.**
  An **explicit `self()`** device is `execute_request/3`'s first clause and raises the oracle's `error:calling_self`, on every device-taking entry point (an atom registered to the caller is the same class).
  An **omitted** default device writes to the caller's output stream — the documented substitution that keeps the installed compiler's `io:fwrite/2` diagnostics printing.
  `io:format/3`/`io:fwrite/3` are `(Device, Format, Args)`: OTP has no options-taking `io:format/3`, so an `io:format(Format, Args, Options)`-shaped call is the bare `function_clause` on the oracle and here (the `{chars_limit,_}` options are `io_lib:format/3`'s, real `io_lib` code).
  A live non-stdio device pid (neither the caller nor its group leader nor `standard_error`) stays the typed `unsupported` — `M1_GAPS.md` *Printing*.
* **A process entry naming a host-served MFA is dispatched, never entered as that module's code** — `ProcessEntry::Export` asks `RuntimeContext::host_serves` on its **first** entry only and runs a hit through `call_bif`, a resolvable module's export keeping the label route — `M1_GAPS.md` *A.7/A.9 boot*.
* **Every `foreign` case's per-call cost is flat in N** — the machine's reservoir is never mirrored onto the process's never-compacted off-heap slots; the residual is dispatch/heap-management at matched N — [`PERF.md`](PERF.md) *off-heap mirror*, `M1_GAPS.md` *`process_info/1,2`*.
* **Placeholders where a truthful source exists** — the flag-driven `system_info` literals report their defaults — `M1_GAPS.md` *Placeholders*.
* **A booted runtime leaves a live `logger_server` registered as `logger`** (a second `logger_server:start_link/0` reports `{error,{already_started,Pid}}`), and the script's tail blockers are served in-node — `M1_GAPS.md` *A.7/A.9 boot*, [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md).
* **A registered-BIF result is re-homed and the pool rewound** (**load-bearing**: the copy makes it collectable) — onto the process heap, else the table-less (`-eval`) store; a NIF result, an escaping `DispatchHooks` arm and an error leave their container on the pool — `M1_GAPS_GC.md` *The BIF-result copy-out*.
* **The copy-out learns a payload's size and grows the nursery *before* copying** — `RuntimeContext::copy_out_hint`, spent through `hint_grow_gate`, makes the *successful first attempt* the common path; measured `copy_bound/ets_copy` **0.605×**, refusals 0.332 → 0.003 per op — `M1_GAPS_GC.md` *The BIF-result copy-out*.
* **The scratch-heap lifetime defect this class of failure needs is closed, and pinned** — `erlang:system_info/1` hands its value off the reset-per-call scratch region, so a retained value is sound (`tests/system_info_retained.rs`) — `M1_GAPS_GC.md` *The scratch-heap lifetime and the dangling-boxed-argument class*.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate** `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper) and the compatibility gate `erts_rust/tools/differential/gate.sh`; [`TEST_STRATEGY.md`](TEST_STRATEGY.md) holds the commands and the gate-equivalent sweep.
* **Test hygiene** — scratch temp dirs come from `crate::context::test_support::scratch_dir(label)` (unique per call, self-removing; a hand-rolled `temp_dir().join(format!("…_{pid}"))` collides with a concurrent test *process*); `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure pairs are asserted as a **set**; `tests/fixtures/` is never handed to the oracle as a single `-pa` (a suite passes its own scratch directory instead); and every oracle probe must terminate (`-s init stop` plus `tests/support/mod.rs`'s bounded poll/kill).
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script), the system code path coming from the native filesystem probe — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export`, (d) the library body being the stub `erlang:nif_error(undef)`, which dominates — `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as a stub, so a key neither the floor nor the registry serves **raises** (exit 1) for *every* argument and registering it only changes exit 1 → 3.
* **The real `erlc` front end drives this runtime** (contract A.6+A.9): `ERLC_EMULATOR=<beam_rt> erlc …` compiles a module and writes a `.beam` **byte-identical** to the system `erlc`'s, with **byte-identical** stderr diagnostics (a warning ⇒ exit 0 with the artifact, a compile error ⇒ exit 1 with none). Its argv — `+S1 +sbtu +A0 +P 65536 +Q 1024 -noinput -mode minimal -boot no_dot_erlang -s erl_compile compile_cmdline -extra <files…>` — is the A.6 surface's acceptance test (`tests/erlc_emulator.rs`, `tests/cli_compact_flags.rs`, `tests/cli_plain_args.rs`).
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` plus the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Measuring a long compile (or any long workload) live, without touching source.** Compile a throwaway driver with the system `erlc`, `spawn_opt(Fun, [monitor, {max_heap_size, Cap}])` the workload, and poll it from the parent — `process_info(P, [current_function, total_heap_size, heap_size])` really tracks the running module's progress (`beam_ssa:used_instr/1` → `beam_ssa_opt:record_opt/2` → `gb_trees:update_1/3`), so "slow" is distinguishable from "stuck"; then `beam_rt -noshell -pa bootstrap/lib/{compiler,kernel,stdlib}/ebin run <driver.beam> mod:fun/0`. `-eval`'s own process is *not* capped, while a `spawn_opt`ed/spawned process honours `max_heap_size` — the same compile therefore succeeds one way and raises `system_limit` the other.
  Sample RSS from bash by polling `/proc/<pid>/status` (there is no `/usr/bin/time` on this host), always `ulimit -c 0`, one compile at a time; a helper script needs `#!/usr/bin/env bash` (only `bash` from the Nix store exists, not `/bin/bash`) and should avoid `date`/`awk` inside it (use `read` on `/proc/.../status`).
* **Dispatch cost is a first-class concern.** `call_registered` runs per call, so a handle built there must be gated by a `uses_*` predicate and every per-call prologue input belongs in the 8-slot dispatch memo; measure with `examples/perf_call.rs` (`examples/perf_bif.rs`'s `pc:*` inlines to a `gc_bif` and **cannot** measure registry dispatch) — [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *DISPATCH-CUT* / *COPY-OUT-CUT* / *WALK-CUT*.
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`**, over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`) — [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md).
* **Whole-process startup is ~0.34 s (release), CPU-bound, issuing 0 `clock_nanosleep`**, the boot path's one live-but-idle port costing the drive no wall time — [`PERF.md`](PERF.md) *The boot path's one live-but-idle port, and the poll budget*.
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call; the granularity is `RUN_STEP_SLICES = 1000` (`src/runtime/scheduler.rs`) with `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000` (`beam_process`), so per-pass costs amortize ×1000 while **per-slice** costs dominate a long run.
The measured per-pass / per-slice / per-round inventory (the fresh `ProcessTable`, the progress-aware pass wait, the per-slice machine/context/timer churn, the `crate::hasher` maps, the occupancy short-circuit, each with its pinning test) is **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, with the per-workload cost in [`src/runner/MEASURED.md`](src/runner/MEASURED.md).

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work is in **[`HANDOFF.md`](HANDOFF.md)**, one bullet per owning crate: the `beam_gc` refused-growth arena fallback and its `AnyCollector::collect_young`; the nested-run depth bound (`beam_bifs`/`beam_rt`); `beam_engine`'s `set_current_code` in the three call seams and its `MinimalContext` arena-words accessor; `beam_io`'s async-port-key and monotonic-time phase residual; the `SchedulerPool` adoption (`beam_process`/`beam_message`); and the distribution spawn responder.
**Inbound distribution's remaining `Unsupported` families are this crate's own half, not a missing sibling API.** `beam_process` already owns the reservation surface — `ProcessTable::{reserve_remote, reserve_identity, spawn_reserved, cancel_reservation}` (`beam_process/src/ptab.rs`, `src/reserve.rs`, pinned by its `tests/reserve_remote.rs`) — and `beam_dist` models both opcodes, so the distributed-spawn family (`DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`, hence `erpc`/`rpc:call`) lacks (i) a sink responder decoding a request's `{MFA, Opts, args}` into a reservation + a process install, (ii) a pending-spawn table keyed by `(peer, Ref)` for a reply to resolve into the waiting parent, and (iii) a `DOP_SPAWN_REPLY` channel — `InboundSink` has none, in either direction.
