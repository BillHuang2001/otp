# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture — `main.rs`, the **CLI flag surface** (**A.6**), **`system_info/1`** + `erlang:process_info/2` (**A.8**) and the **boot sequence** (`src/boot/{preloaded,bootscript,drive}.rs`), which loads the 22 preloaded `.beam`s for real and runs the real `bootstrap/bin/start.boot` to completion (`{progress,started}`, **A.7**); every CLI action but `-version` drives that script, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — every optional `beam_bifs` host seam, the **A.4 runtime side of ports**, the **runtime-local timer deadlines** (`src/timers.rs`) and the **distributed node** (A.5: `src/dist/` accepting, `src/dist_client/` connecting).
The vertical slice runs on a test-only `MinimalContext` at the engine level (`../beam_engine/tests/slice.rs`) and through this crate's real glue (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`, terms/heaps → `beam_term`/`beam_alloc`, pids → `beam_process`, modules → `beam_loader`, execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**), sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (`Runtime::dist_ensure_link`); a `-name`/`-sname` node also runs the native `net_kernel` service, so a peer's `net_adm:ping/1` answers `pong`.

### `nif.rs` — the live NIF libraries (A.3), and `build.rs`

A NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, with all **eleven** state-needing `NifHostServices` hooks live; `enif_schedule_nif` chains run through `beam_abi`'s constant-stack trampoline, and an `enif_select` STOP verdict runs the resource type's `stop` callback.
`src/nif/thread_env.rs` is the **process-independent host** a NIF-created thread (`enif_thread_create`) runs on: one `ForeignHost` per thread drawing every atom from a **private** name→index space (`src/nif/atoms.rs`), `send` queueing a complete ETF image so an atom reaches the live table by **name**; `Runtime::install_nif_thread_env`/`clear_nif_thread_env` own the process-global factory slot and `drain_nif_thread_sends` decodes at `try_call_nif` and `scheduler_pass`.
`build.rs` emits `-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen` needs — `tests/nif.rs`, `tests/nif_a3_*.rs`, `M1_GAPS_A3_NIF.md`.

### `malloc.rs` — the allocator's free-page release
`beam_rt::release_free_pages()` is the crate's single allocator lever (`libc::malloc_trim(0)` on glibc, an honest `None` elsewhere), called **once per process** from `src/main.rs` after the `"beam_rt-driver"` thread is joined — the only quiescent *and* complete point; the runtime is not torn down at exit (`ExitTeardown::Leak`), so it finds a largely **live** arena and returns little and peak `VmHWM` is untouched, and **capacity is not RSS** (`beam_alloc::Heap::new` is a lazy `mmap`).
`BEAM_RT_MEM_TRACE` prints the answer as one `[rt-mem] heap-release=…` line and nothing depends on it; figures in `src/malloc.rs`'s module docs.

## Host-side term stores — owned copy vs raw word (the rule that makes a store sound)
- **A raw `Eterm` in a long-lived slot roots nothing.** A term that can outlive one instruction — a raise reason, a pending reply, a parked value, a cache entry — must be copied onto a scanned heap or explicitly stabilized before its owner's heap can be relocated.
- **A pointer-stable, never-scanned store (the arena, `alloc_words`) is the wrong home for a container whose children live on a scanned young heap** — the copier gives it `Target::Foreign` and never descends, leaving the container verbatim while relocating the children out from under it.
- **An exempted heap-growth or move must "refuse ⇒ stabilize, never dangle"** — a door that cannot copy refuses, and the refusing path first makes its roots publishable.
- **An `Rc` lease held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow.**
A stored term is self-contained only if it went through `Runtime::stabilize_term`/`try_stabilize_escaped` (a copy onto the `eval_heap` + `eval_off_heap` store), was built on the pointer-stable arena, or was built on a pooled BIF heap the escaping `runtime_hooks` arm froze; every store is **pointer-pinned**, so the one thing it cannot survive is a **move** of the region it names — done only where nothing is executing (`-eval` statement boundary, driver exit), rewriting every stored word through `Runtime::for_each_root_family_mut`.
The inventories and the roster in `src/context/IMPLEMENTATION.md` are [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) *Host-side term stores — owned copy vs raw word*.
## The runtime-native BIF floor (`src/native/`)
The floor serves the BIFs that are really *runtime* operations — process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; **a native entry never duplicates a registry one** and an unclaimed call returns `None`. **`src/native/CONTEXT.md` is the dispatch table** (the source of truth), the implemented/not-implemented BIF index and the drift guard.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
The floor owns the process/name/global-state arms (`ProcessBridge`'s only implementation), `process_info/1,2` (`src/native/memory/`), `monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` with the reference-alias send destination (`src/context/alias.rs::alias_destination`, on **both** send seams) and `garbage_collect/0,1` — **no BIF may collect**, so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true` where the root set is owned.
**`code:*` reads and the code path are the floor over `CodeServer`**: the floor owns the **one** authoritative path store — readers **and** the `add_path*`/`del_path` mutators — and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store*).
`Runtime::new` starts exactly **four** runtime-owned, never-enqueued `Runnable` processes (the `init` stand-in `<0.0.0>`, the root process `<0.1.0>` every action runs as, the `erl_prim_loader` stand-in and the `file_server_2` service), and `call_bif`'s last resort is the **`erlang` namespace**: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y` (exit 3), any other unclaimed name the bare `error::undef` — `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` and its drift guard are the authority.
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **two** built-in key sets — `prim_tty`'s 20 stub keys and `zlib`'s 19 stream keys — from a module-name equality short circuit plus a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash (the same predicate `beam_bifs::serves_local_call` exposes).

### The `-eval` route (`src/eval/`)
`-eval` walks the Erlang **expression** subset `erl_eval`-style — arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3).
`receive … after T` scans the running process's **real mailbox**, pumps the scheduler non-blockingly (`RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass and spends the remaining window on the timer heap through `Runtime::wait_for_timer`; a port round's messages are **delivered into that mailbox** before any clause is tried.
A closure `erlang:spawn/1` starts is **compiled** (`src/eval/compile.rs`) from its recorded source into a synthetic `beam_rt_eval_fun_<index>` module (`compile:file/2` in process, then `code:load_binary/3`), so the child is an ordinary `ProcessEntry::Export` that really parks on a bare `receive` or a `timer:sleep/1`; the result — a decline included — is cached per closure index on `Runtime::eval_compiled`.
Residuals: a `spawn` from inside a running engine (`src/native/process.rs::spawn_in_pass`) keeps the tree-walking entry, a **declined** compile keeps that closure's gaps, and `receive … after infinity` is a typed gap — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Known Issues*.
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure: a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation (a missing operand of a *known* switch, a malformed `run` spec or numeric value, a stray positional) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`), and is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`).
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call**, or the engine cannot land it in a catch frame: `src/context/calls.rs::name_raise_reason_atom` appends it (append-only, at `PendingInterner`'s predicted index) on the **one** funnel every failed call passes, so a module that never spells the atom still catches `error:R` as the oracle does — a capability gap is deliberately **not** interned there, which keeps exit 3 uncatchable.
A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` renders it through `format_term_w` (`runner/reason.rs::exit_reason`, `cli.rs::run_file`, `context/mod.rs::run_export`), so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1).
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks raise the honest `unsupported` gap, and the two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs`) — **the per-key catalog is [`src/info/CONTEXT.md`](src/info/CONTEXT.md)**.
## Constraints
* **Errors are return-based** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`, with no crate-local error enum, no `panic!`/`unwrap()` on runtime data and no silent swallowing; CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`, never stderr writes.
* **`#![deny(unsafe_code)]` with ten per-module exemptions**, each carrying a `// SAFETY:` rationale at every site — `src/malloc.rs`, `src/nif.rs`, `src/context/{calls,gc,gc_walk}.rs` + `src/context/gc/{bin_vheap,valve_bounds}.rs`, `src/eval/reclaim.rs` + `src/eval/reclaim/resource.rs`, `src/runtime/reclaim/compact.rs` (the store move).
* **Call down, never duplicate** — the `~p` printer is **not** re-implemented; `format.rs` drives the registered `io:format/2` BIF.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner** — reachable from `Machine::refc_binaries()` or `Runtime::eval_off_heap`; the transport copy resolves one of them into its **source** table so the destination **shares** the handle, and a source table that cannot name the owner makes `beam_message`'s copier **flatten** the window into a fresh on-heap bitstring as the **last resort** only.
* **A live heap serves its own builds; the arena is a refusal-only fallback** — `alloc_words_rooted` serves a nested run from the running process's scanned young heap, the arena answers only a table-less context or a refused growth, and inside a relocation-exempt window the copy-out `stabilize`s instead of growing — [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) *A live heap serves its own builds*.
* **A park that skips root publication holds the relocation exemption** — the three runner park arms take the one `park_window` entry point and write the flag in both directions, so the halves are un-splittable — [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) *A park that skips root publication*.
### The one process-lifetime `Rc<AtomTable>` lease
**Never hold a `CodeServer::atoms_handle()` across an intern** — [`src/codeserver.rs`](src/codeserver.rs) states the rule on the method: `atoms_mut()` is `Rc::make_mut` and `intern_pending()` falls back to it, so an `Rc<AtomTable>` clone held **across** an intern deep-clones the whole shared table and drops the copy; only **one** holder lives long enough to matter — a loaded NIF library's stored host (`src/nif.rs`'s `NifEntry::host`, alive for the process's life).
A `{spawn_driver, Name}` port's host (`src/port/driver.rs`'s `DriverPort`) is **not** a holder: its view is a **lease** on the `DriverAtoms` record the port layer shares with it, opened by `PortRegistry::open_driver_atom_view` only for the window in which driver code runs and closed by `close_driver_atom_view` (re-entrant, depth-counted).
That window is the whole rule: between windows no driver port owns a handle, so an intern taken anywhere — the port round's `commit_driver_atoms` included — appends **in place** (`Rc::get_mut`); inside a window no intern can occur (the table/registry is borrowed for the whole drive), so the lease costs nothing and can never cause a copy.
A **built-in**-driver port (`ram_file_drv`/`tcp_inet`/`udp_inet`) and a `{spawn, …}` port create **no** host, so the code server is sole owner there; the transient `RuntimePorts` leases (`src/port/busy_wait.rs`, `src/native/port.rs::port_info_pairs`) are lookup-only.
The two production sites taking a handle — `src/native/prim_file.rs::build_descriptor`, `src/native/net/nodes.rs::nodes_2` — **intern first and take the handle last**, so no atom index moves.
The port delivery builders (`port_data_message_shaped`, `port_line_message`, `port_exit_message`, `signal_notify_message`, `select_message` and the `src/port/{completion,peer_closed,active_input,exit}.rs` siblings) intern **through `src/port.rs`'s `intern_reuse`**, which looks the name up on the shared table first and reaches `atoms_mut()` only for a genuine miss — the ports' vocabulary being the one place a per-message intern is unavoidable.
`RuntimeContext` itself holds **no** atom handle, and the borrow-workaround clones (`src/eval/mod.rs`, `src/native/memory/mod.rs`'s `max_heap_size_map`, `src/native/erts_internal.rs`) each wrap a `make_map` that takes `&AtomTable` and cannot intern — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `src/port/tests.rs`.

* `term_to_binary`/`binary_to_term` cost is the codec's own work, not `beam_rt` dispatch — G *Dispatch, atoms and module introspection*.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate** `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails; the sandbox `$HOME` is read-only, hence the wrapper) and the compatibility gate `erts_rust/tools/differential/gate.sh` — [`TEST_STRATEGY.md`](TEST_STRATEGY.md) holds the commands and the gate-equivalent sweep.
* **Test hygiene** — scratch dirs come from `crate::context::test_support::scratch_dir(label)`; `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure pairs are asserted as a **set**; `tests/fixtures/` is never handed to the oracle as a single `-pa`; every oracle probe must terminate (`-s init stop` plus `tests/support/mod.rs`'s bounded poll/kill).
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script), the system code path coming from the native filesystem probe — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md).
* **`beam_rt: error undef` is overloaded — four causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing, (c) an **arity mismatch** in `run_export`, (d) the library body being the stub `erlang:nif_error(undef)`, which dominates — such a key **raises** (exit 1) for *every* argument, and registering it only changes exit 1 → 3.
* **Probing dispatch empirically** — `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` plus the exit code asks what the NIF → floor → registry → module-load order does today; the long-workload recipe is [`TEST_STRATEGY.md`](TEST_STRATEGY.md) *Measuring a long workload live*.
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`**, over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`) — [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **Measure in retired instructions, not wall clock** — pin a P-core and read `cpu_core/instructions` (a from-source rebuild is instruction-identical but 2–4 % apart in wall, so a stashed binary is never a control); quote no figure without reading the owning record's *Measurement discipline* — [`STARTUP_COST.md`](STARTUP_COST.md), [`PERF.md`](PERF.md), [`PERF_DISPATCH.md`](PERF_DISPATCH.md), [`PERF_HISTORY.md`](PERF_HISTORY.md), [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md).
## The scheduled path and the per-BIF-call cost (read before optimizing the glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, at `RUN_STEP_SLICES` passes per round and `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS`, so per-pass costs amortize while **per-slice** costs dominate a long run; the per-pass/per-slice/per-round inventory (each with its pinning test) is [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *The scheduled path's fixed costs*, with the per-workload cost in [`src/runner/MEASURED.md`](src/runner/MEASURED.md).
A registered BIF call is priced in retired instructions, of which this crate owns the routing (`call_bif`'s NIF → floor → memo draw), the `BifContext` build and arm selection and the tail — the rest is `beam_engine`'s dispatch, `src/runner/budget.rs`'s forwarding triple, or the BIF body; **the remaining cost is mostly NOT this node's**, and the ranked levers with their owners are [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *The per-BIF-call cost, on one page*.
A handle built in `call_registered` must be gated by a `uses_*` predicate, and the `DispatchMemo` hit path, not the prologue, is what to price (`examples/perf_call.rs`).

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work is in **[`HANDOFF.md`](HANDOFF.md)**, one bullet per owning crate: the `beam_gc` refused-growth arena fallback and its `AnyCollector::collect_young`; the nested-run depth bound (`beam_bifs`/`beam_rt`); `beam_engine`'s `set_current_code` in the three call seams and its `MinimalContext` arena-words accessor; `beam_io`'s async-port-key and monotonic-time phase residual; the `SchedulerPool` adoption; the distribution spawn responder.
**Inbound distribution's remaining `Unsupported` families are this crate's own half, not a missing sibling API**: `beam_process` already owns the `ProcessTable` remote-reservation primitives and `beam_dist` models both opcodes, so the distributed-spawn family (`DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`, hence `erpc`/`rpc:call`) lacks (i) a sink responder decoding `{MFA, Opts, args}` into a reservation + a process install, (ii) a pending-spawn table keyed by `(peer, Ref)`, and (iii) a `DOP_SPAWN_REPLY` channel; the link driver's `Delivery::Other(_)` kill and `beam_dist`'s **local-node identity in `encode_control_cached`** are the remaining codec ask — [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md) *Missing sibling APIs*.
