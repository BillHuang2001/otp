# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs`, the **CLI flag surface** (**A.6**) and **`system_info/1`** + `erlang:process_info/2` (**A.8**).
It owns the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded drives (`src/boot/drive.rs`) — which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**); every CLI action but `-version` drives it before its own start instruction, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** adapting the engine's seams onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable), the **A.4 runtime side of ports** (`open_port/2` decoding, `port_info`, the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s), the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and `{abs,true}`) and a finite `receive … after T` (`src/timers.rs`, advanced only by the scheduler loop), and the **distributed node** (A.5 phases 1–2: the accepting half `src/dist.rs` + `src/dist/` — the inbound `LocalDeliverySink` in `src/dist/inbound.rs` — the connecting half `src/dist_client/`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.

### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` on the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**), sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (a send to a link-less node dials it first, `Runtime::dist_ensure_link`); a `-name`/`-sname` node also runs the native `net_kernel` service (`src/native/net_kernel.rs`), so a real peer's `net_adm:ping/1` answers `pong`.
Both inbound drives drain every established link through `beam_dist`'s per-link checked path and `LocalDeliverySink` routes the message and route-free receipt families through `ProcessTable`'s inbound primitives, the pass being gated by `Runtime::inbound_delivery` (default **ON**) — per-family routing table, the pump budgets, the envelope rule and the `DistRouter` install site: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
Both inbound relationship families are therefore observable locally: a peer's `link/1` through `process_info(P, links)` (`src/native/memory/mod.rs::links_value`, the local link set plus the recorded remote partners as external pids) and its `monitor/2` through `process_info(P, monitored_by)` — two-live-VM evidence in `tests/dist_two_vm.rs` (`a_real_erl_peers_link_shows_up_in_the_links_item_and_clears_on_unlink`).
**Peer loss fires the operator's node-down semantics (A.5).** A link retired because it **died** records its peer in the runtime's one shared `LostPeers` cell (`src/dist/links.rs`), from **both** halves (inbound `DistNode::retire_at`, outbound `DistClientInner::retire`).
The recording test is the `was_established` **latch** each link sets inside its own `pump` the moment the driver reports `Established` — not `is_established()`, which the discovering pump has already moved to `Closed`/`Failed` (the latch is what makes a dying established link recordable at all).
`Runtime::service_lost_dist_peers` (the pass step after `dispatch_dist_client_inbound`, `src/runtime/scheduler.rs`) skips a peer any link still names in **any** handshake state (`DistLinks::link_names`, so a re-connect is a non-event), declines an unnameable peer (`AtomTable::lookup`), interns `noconnection` and calls `ProcessTable::node_down`, so a monitor gets `{'DOWN',Ref,process,PeerPid,noconnection}`, a trapping link `{'EXIT',PeerPid,noconnection}`, a non-trapping link dies with `noconnection`; a failed handshake and a graceful close/drop record nothing, and `Runtime::service_node_monitors` (`monitor_node/2`'s `{nodedown,Node}`) is a separate path that cannot double-fire.
`Runtime::dist_connect` is **idempotent**: a peer already established on either half answers `Ok(())` without dialling, because a second `'N'` link to a peer that dialled us is a simultaneous-connection collision the peer resolves by killing one — the defect that once made `net_adm:ping/1` answer `pang` for a live peer.
Two-live-VM evidence: `tests/dist_two_vm.rs` (24 `#[ignore]`d cases — link/unlink observability, monitor/demonitor, `exit/2`, aliases, identity round trip, the four inbound-signal cases, the four peer-node-loss cases) and `tests/dist_two_rust.rs` (12 — the seven outbound/round-trip cases plus all **inbound** ones, where the peer acts on a process *we* host: inbound `DOP_LINK` recorded in the victim's `links` item ahead of a barrier, the peer's `erlang:monitor/2` recorded in `monitored_by` with its `DOP_MONITOR_P_EXIT` `{'DOWN',…}` read back, inbound `DOP_EXIT` with a compound reason into a trapping victim, the same link death into a non-trapping one, and the inbound `DOP_EXIT2` `{plain,kill}` × `{trapping,not}` matrix with `kill` untrappable).
**A control signal is never overtaken by a later message on the same link** (ERTS's synchrony, `dist.c`'s `erts_dsig_send_*` writing under the link lock): the router only *queues* (`DistClientInner::queue_signal` — `route` runs inside the process table and has no atom table), so every message write drains the queue first (`DistClient::flush_queued_controls` in `src/dist_client/client.rs`, called by all three sends before they materialise a term on the scratch heap), and `DistClient::pump` flushes at every pass. Both halves of the pair are therefore ordered: a barrier sent right after a `link`/`monitor` cannot outrun it, and a `DOP_MONITOR_P` always lands while the target is alive (`LocalDeliverySink::resolve_live` would otherwise drop it, so no `DOP_MONITOR_P_EXIT` would ever be emitted).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — precedes the boxed host) and the `!Send` `NifRegistry` (`new()` anchors the `enif_*` codegen unit; `is_loaded`/`insert`/`lookup` — **the dispatch predicate** — and `call`) are `Runtime`'s, as `Rc<RefCell<..>>`.
A NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner` and holding `Some(&'a mut dyn NifHostServices)`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by name; all **eleven** state-needing `NifHostServices` hooks are live on a call (`select`, `send`, the monitor pair and the rest — `M1_GAPS_A3_NIF.md` *NIF (A.3)*), only the load/unload host leaving them the trait default.
`src/nif/thread_env.rs` is the **process-independent ("message env") host** a thread a NIF created (`enif_thread_create`) runs on: `ThreadEnvFactory` (what `beam_abi`'s thread-env seam opens a `ForeignHost` from, one per thread) draws every atom from the factory's **private** name→index space (`src/nif/atoms.rs`, empty at construction), and `ForeignHost::send` queues a **complete ETF image** with this node's identity installed instead of delivering inside the call, so an atom reaches the live table by **name** when the runtime's decoder interns it and a foreign index is never a live index — the one documented substitution, stated in its module docs.
`Runtime::install_nif_thread_env`/`clear_nif_thread_env` own the factory slot (installed from `cli::build_runtime`, **not** `Runtime::new`, because the slot is process-global and last-install-wins while the suite builds many runtimes per process), and `Runtime::drain_nif_thread_sends` decodes a queued image against the **live** table and delivers it through the runtime's own send seam at its two drain sites: `src/context/calls.rs`'s `try_call_nif` (so a joined worker's message is in the mailbox before the calling process resumes) and `src/runtime/scheduler.rs`'s `scheduler_pass`, right after the port step and before `pump_dist`.
`build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`, `mailbox.rs`
`config.rs` type shapes: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs`, `HeapOptions`/`GcStrategy` (`EmulatorDefault`/`Immix`), the `beam_process::{MaxHeapFlags, MaxHeapSetting}` re-exports and `RuntimeConfig::with_heap_options` — per-module detail: `src/{cli,info,boot}/CONTEXT.md`.
### Observability (`trace.rs` · `seq_trace.rs` · `crash_dump.rs` · `perf_map.rs`, contract A.8)
Process tracing, sequential tracing, the ERTS-format crash-dump writer behind `erlang:halt`, the `+JPperf` JIT symbol map, the **execution-trace seam** (`call`/`return_from`/`return_to` over `beam_engine`'s `ExecutionContext::trace_event`, live on both the single-pass and the scheduled paths) and the three per-call overhead harnesses (`examples/perf_bif.rs`, `examples/perf_call.rs`, `examples/perf_copy_out.rs`) — emitted vs deferred events, per-module routing and figures: **[`TRACE_AND_PERF.md`](TRACE_AND_PERF.md)**.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, an unclaimed call returns `None`, and the six process/name/global-state arms are `ProcessBridge`'s only implementation. The dispatch table (the source of truth), every implemented/not-implemented BIF and the drift guard live in **`src/native/CONTEXT.md`**.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
**`process_info/1,2` stay on the floor** (`src/native/memory/`), sharing their value builders with `ProcessBridge` so the two paths never drift, because the `ProcessHook` seam cannot express the `{dictionary, K}` item form.
**`monitor/2,3`/`demonitor/1,2`, `alias/1`/`unalias/1` and the reference-alias send destination come from the floor** (`src/native/process/`): a monitor's own reference doubles as an alias, and as a **send destination** that reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams.
**`erlang:garbage_collect/0,1` come from the floor** (`src/native/erts_internal.rs`, A.7): **no BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet`, which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`, served only where the root set is owned (`Runtime::serve_gc_request`).
**`code:*` reads and the code path are the floor over `CodeServer`**, alongside a live `code_server` process: the floor owns the **one** authoritative path store — the readers **and** the `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1` mutators — so **`src/native/code.rs`'s `code:*` behaviour must not change**, and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store* / *The expected-module-name check on every name-based load route*).
`Runtime::new` starts exactly **three** runtime-owned `Runnable`, never-enqueued processes — the `init` root, the `erl_prim_loader` stand-in and the `file_server_2` service — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md) *the runtime's own processes*.
**`erlang`-namespace fallback**: `call_bif` consults the floor, then the registry, then the `erlang` namespace — a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`; `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (intersected with what the live registry does not own) and its drift guard are the authority.
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **two** built-in key sets — `prim_tty`'s 20 stub keys and `zlib`'s 19 stream keys — answering from a module-name equality short circuit followed by a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`, with `local_fun_target` declining such a target) serves the **record-held** shape of the same two sets: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body.
The `zlib` stream API is therefore live end to end through the real preloaded `zlib.beam` — `open/0` … `close/1` — and oracle-identical at every level 0–9, pinned by `tests/zlib_stream_levels.rs`, `tests/zlib_stream_dict.rs`, `tests/zlib_guards.rs` and `tests/zlib_one_shot.rs` (**29** tests, 27 of them oracle-cross-checked and 2 golden self-consistency checks that need no `erl`).
`set_controlling_process/2` carries **no** stream-state precondition (the C's `set_controller_nif` validates arguments, checks ownership, overwrites the pid), so a closed, an ended and a fresh stream all answer `ok` on both runtimes — `tests/zlib_guards.rs::setting_the_controlling_process_on_a_closed_stream_agrees_on_every_route_and_tier`.
Per-module detail: `src/context/CONTEXT.md` (both indirections), `src/native/CONTEXT.md` (`prim_tty`), `../beam_bifs/src/zlib/CONTEXT.md` (the 19 keys).
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`/`src/dist/`, the connecting half in `src/dist_client/`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` walks the Erlang **expression** subset `erl_eval`-style — its arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3): the grammar, the quoted-atom rule and the named-fun-form rejection are [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md)'s.
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`) and an unmodeled switch is **data, not a usage error**; the full switch surface, the `run` action's `ARG` token kinds and what is *not* recorded live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md) (`M1_GAPS.md` *CLI `run` argument tokens* for the token materialization), together with the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge.
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`).
A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call.** `BeamError::Raise` carries an `ExitReason::Atom` as a **name**, and the engine can only land such a raise in a catch frame when its `atoms()` namespace resolves the name (`beam_engine/src/interpreter/bif.rs`'s `raise_error`); a name nothing has interned therefore escaped every `try … catch`. `src/context/calls.rs::name_raise_reason_atom` closes that on the **one** funnel every failed call passes (`call_bif`'s error arm): it appends the reason atom to the shared table (append-only, at `PendingInterner`'s predicted index, via `CodeServer::intern_pending`), so a module that never spells the atom still catches `error:R` exactly as the oracle does — the shape a `zlib` guard (`not_initialized`, `stream_error`, `already_initialized`, `not_on_controlling_process`) raises. Deliberately **not** interned: a capability gap (`crate::error::unsupported_reason`) — which is what keeps exit 3 uncatchable — and any reason with no nameable atom.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason).
So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog — every served key, its own-state source, the `dist`/`dist_ctrl`/`start_time`/`end_time`/`context_reductions` specifics and the per-key rationale — lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented.
  The pre-existing (not restructured) oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md) *File-size overages*.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle.
  When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer; flattening is the **last resort** for an unresolvable payload, never a substitute for adopting handles (the send path unions three source families, `src/context::send_source`, so a resolvable payload takes the SHARE route).
## Design Decisions
The design rationale and binding invariants of the runtime glue — the mature-GC `HeapPolicy` source, the one shared atom table, heap lifetime, the scheduler's table move, exit-reason handling, the transport copy's off-heap payload resolution, the host-seam bridges + hooks, the timer min-heap, the persistent-term store, the heap-fragment model, the GC-collection sites with the relocation-exempt valve, the host `CollectionGate`, the BIF-result copy-out/rewind and the `receive` scan position — are in **[`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md)**.

## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call instead of re-entering the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`) with `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000` (`beam_process`), so per-pass costs amortize ×1000 and **per-slice** costs dominate a long run.
The measured per-pass / per-slice / per-round inventory — the fresh `ProcessTable` per pass, the progress-aware pass wait (a ready `run` issues **0** `clock_nanosleep`, a parked `receive … after T` is still slept to), the per-slice machine/context/timer churn, the `crate::hasher` word-mixing maps, the occupancy short-circuit and per-round drains, each with its `file:line` and its pinning test — is in **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, as is the per-workload cost of that path ([`src/runner/MEASURED.md`](src/runner/MEASURED.md)); the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.
