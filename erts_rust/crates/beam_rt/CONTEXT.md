# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs`, the **CLI flag surface** (**A.6**) and **`system_info/1`** + `erlang:process_info/2` (**A.8**).
It owns the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the OTP boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded scheduler drives (`src/boot/drive.rs`) — which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**); every CLI action but `-version` drives that script before its own start instruction (`-eval`/`-s`/`-run`/`run`/bare `-noshell`, and `-boot FILE`), so a silent action exits **0** with **empty stdout and empty stderr** (the tail's in-node blockers and the live `whereis` facts: *A.7/A.9 boot* in [`M1_GAPS.md`](M1_GAPS.md)).
It owns the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable).
It owns the **A.4 runtime side of ports** — `open_port/2`'s `Name`/`Options` decoding, `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` (the child/driver lifecycle is `beam_io`'s).
It owns the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and the `{abs,true}` absolute form) and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop.
It owns the **distributed node** (A.5 phases 1–2): the **accepting** half (`src/dist.rs` + the inbound `LocalDeliverySink` in `src/dist/inbound.rs`) and the **connecting** half (`src/dist_client.rs`).
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)

* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking, the NIF-dispatch order, the **lent-`TableRegistry` propagation** into a nested fun application (a nested `ets:*` inside a `lists:foldl`/`foldr`/`map` fun reaches the folded table) and `NodeIdentity`'s **real local-node hash** (`node_hash.rs`, so a `term_to_binary(T,[local])` image is real) — [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver.rs`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump, `port_info/1,2`'s **real cumulative per-port byte totals** for `input`/`output`), the native-floor `erlang:port_control/3` (the driver's `control` callback behind `PortRegistry::port_control`) and the runtime's own driver C-ABI host for `{spawn_driver, Name}` (a built-in name resolved before `dlopen`) — [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
### `dist.rs` + `dist/` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener bound by `start`, published to `epmd` on the first `pump()` via `ALIVE2_REQ`); `DistClient` is the *connecting* half (the outbound client handshake + the `DistRouter`, installed on the runtime's **process table** so a locally-initiated link/monitor/exit emits real `DOP_*` bytes).
Both inbound drives drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`, the C's `dep != external_pid_dist_entry(from)` check), so a malformed or forged control message **retires that one link** instead of reaching the sink.
`LocalDeliverySink` routes the message families and the route-free receipt families through `ProcessTable`'s inbound primitives (each emitting **no** outbound `DOP_*`); the only families still typed `Unsupported` are `SpawnRequest`/`SpawnReply`, `Delivery::Other(_)` and the `UnlinkId` `id != 0` ack-owing half (`id == 0` is `Delivered`).
The pass is gated by `Runtime::inbound_delivery` (default **ON**).
The per-family routing table (each family → its receipt API), the pump budgets, the envelope rule, `NodeName::parse`/`resolve_cookie` and the `DistRouter` install site are in [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md); the sink/node child node is [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`.
`NifRegistry` offers `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**) and `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`: a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, holding `Some(&'a mut dyn NifHostServices)`; `alloc_env`/`free_env` are real and `make_copy` is the **identity**.
The host **exposes that shared table** through `NifHost::atom_table`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by its name, not its interned index.
All six state-needing `NifHostServices` hooks are live on a call (`make_ref`, `whereis_pid`, the two liveness answers, the port relations `is_port_alive`/`port_command`); only the load/unload host leaves them the trait default — `M1_GAPS.md` *NIF (A.3)*.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`, `mailbox.rs`
`config.rs` type shapes: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs`, `HeapOptions`/`MaxHeapFlags`/`GcStrategy` (`EmulatorDefault`/`Immix`) and `RuntimeConfig::with_heap_options`.
`cli.rs`/`cli/`, `boot.rs`, `info/`, `format.rs` and `mailbox.rs` are catalogued by the Routing Table below; **per-module detail: `src/{cli,info,boot}/CONTEXT.md`.**

Process tracing, sequential tracing, the ERTS-format crash-dump writer behind `erlang:halt`, the `+JPperf` JIT symbol map, the **execution-trace seam** (`call`/`return_from`/`return_to` over `beam_engine`'s `ExecutionContext::trace_event`, live on both the single-pass and the scheduled paths) and the three per-call overhead harnesses `examples/perf_bif.rs` (inlineable fixture BIFs), `examples/perf_call.rs` (registered-BIF dispatch) and `examples/perf_copy_out.rs` (the BIF-result copy-out, with the `binary_to_term`/`term_to_binary` split and the copier's own cost) are detailed in **[`TRACE_AND_PERF.md`](TRACE_AND_PERF.md)**.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`.
The dispatch table (the source of truth), every implemented/not-implemented BIF and the drift guard live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
**`process_info/1,2` stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form.
**`monitor/2,3`/`demonitor/1,2`, `alias/1`/`unalias/1` and the reference-alias send destination come from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed as the C's `erts_monitor_opts` (`bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias; as a **send destination** that reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams, and a `{alias,_}` on a **port** monitor or a **remote** target propagates the typed `unsupported` (`tests/alias.rs`).
**`erlang:garbage_collect/0,1` come from the floor** (`src/native/erts_internal.rs`, A.7): **no BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet`, which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`; the request is served only where the root set is owned (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first, so `Runtime::gc_stats().collections` moves only when a collection really ran.
**`code:*` reads and the code path are the floor over `CodeServer`, alongside a live `code_server` process** (started by the booted `kernel_sup` on every boot-driven route; `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7), so the `boot/*` cases touching `code:*` are **shape-only**).
The floor owns the **one** authoritative path store for the path readers **and** the mutators `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1`; the un-migrated mutators edit the live server's second, floor-invisible store, so **`src/native/code.rs`'s `code:*` behaviour must not change** (the store rule, its key list and `code:ensure_modules_loaded/1`'s rationale: `src/native/CONTEXT.md`).
**The A.9 installation view is catalogued in `src/native/CONTEXT.md`**: `init:get_argument/1`'s four automatic flags (`root`/`home`/`progname`/`bindir`), `init:script_id/0`, `code:lib_dir/2`, the `application` view and `erlang:module_loaded/1`'s truthfulness to *this* runtime's loaded set (so `module_loaded(kernel)` stays `false`).
**Three server processes are native state, not scheduled code**: the root process (registered as `init`), the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) and the **`erl_prim_loader`** stand-in (`src/runtime.rs`, A.7/A.9) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery work and `erlang:whereis(erl_prim_loader)` answers a live pid on **every** route (nothing in `bootstrap/bin/start.boot` claims it).
The `file_server_2` service is **spawned unregistered on every route that drives a boot script** (every CLI action but `-version`, plus `-boot FILE`), so the booted `kernel_sup`'s own child owns the name; `Runtime::new` registers it only when the runtime drives none.
**`erlang`-namespace fallback**: `call_bif` consults the floor, then the registry, then the `erlang` namespace — a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`; `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (intersected with what the live registry does not own) and its drift guard are the authority.
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar: the Erlang **expression** subset (`src/eval/{parse,ast,mod}.rs`) walked `erl_eval`-style, its arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**), and a **quoted atom** a distinct `Tok::QuotedAtom` (an atom that merely *spells* a keyword — `'receive'`, `'end'`, `'not'` … — is a plain atom, and a quoted call head is an ordinary call).
  Outside the grammar is a **capability gap** (exit 3) — the grammar, the quoted-atom rule and the named-fun-form rejection: [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2.
  `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2).
  **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`).
A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason).
So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` exceeds the 60-bit small range, so it materializes as a bignum); `context_reductions` is answered as `4000`, the canonical ERTS quantum `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented.
  The pre-existing (not restructured) oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md) *File-size overages*.
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle.
  When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer; flattening is the **last resort** for an unresolvable payload, never a substitute for adopting handles (the send path unions three source families, `src/context::send_source`, so a resolvable payload takes the SHARE route).

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (by the section named after each bullet); the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **A `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work, not `beam_rt`'s dispatch** — the wired path is allocation-free and every decode seam uses a per-thread memoized `AtomTable` image — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **The atom-intern commit is append-only** (`CodeServer::intern_pending`, copy-on-write only for an outstanding handle) — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **No interactive shell; the node is otherwise passive** — the message families and the inbound link/exit/unlink/monitor/demonitor/monitor-down/group-leader families route through `beam_process`'s **route-free receipt** primitives (*Handoffs*), each mirroring the C's `break; /* Done */`, never echoing a `DOP_*` — `M1_GAPS.md` *Distribution and the node (A.5)*.
* **An inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** (an immediate-only, uncopied, unrooted slot; the plain `DOP_SEND*` forms pass the wire's `''`) — a typed divergence from the C — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order (compared as a set), and `badarg` for a module not loaded here — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures (`whereis(init)` **does** agree) — `M1_GAPS.md` *Own-state answers*.
* **`process_info(P, binary)`** is served from the target's own off-heap refc-binary roster as the oracle's `{Ptr, Size, Refc}` tuples (`[]` when none); a `process_info(self(), binary)` inside the running slice can omit a payload that slice just built (a safe roster omission) — `M1_GAPS.md` *`process_info/1,2`*.
* **Process-control gaps** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id — `M1_GAPS.md` *Process-control families*.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual is `ets:setopts/2`'s gift-data aliasing — `M1_GAPS.md` *ETS ownership*.
* **`process_info/1,2`** answers ~28 items from real state (the `max_heap_size` map's key order/flags diverge; `message_queue_data, off_heap` is accepted-and-ignored); `port_info(Port, monitors)` stays `[]`, matching the oracle; a non-byte-aligned `-eval` result (or a container past ~80 columns) cannot be printed by the registered `io:format` `~w`/`~p` printer — `M1_GAPS.md` *`process_info/1,2`* / *Port monitors (A.4)* / *Printing*.

* **`process_info(P, garbage_collection)`'s `minor_gcs` is `Collector::minor_since_major`, NOT a collection total** — read it as "minors since the last fullsweep", never as "did GC run": every fullsweep resets it to `0`, so it can sit flat (e.g. `6`) while the process collects once per iteration; `native/memory/mod.rs` reads the live `process.collector().minor_gcs()` and its module docs still claim "today always `0`: this runtime runs no GC" — a stale comment, not the behaviour.

* **The runtime drives `beam_gc`, but only through the engine's heap-admission point.** An `alloc_words`-only workload is never collected (a capacity refusal grows the nursery and retries the bump before it falls back to the pointer-stable arena); a float-family module is collected over **only** at the two full-root doors (the narrow `ensure_heap` door gets just an x prefix and the stack and so refuses a float-using call site, while `ensure_heap_full`/`alloc_words_rooted` hand over the x file's pointer-bearing prefix and the FR file's live leading prefix), and a failed collection halts that process's collection rather than failing the program.
  The **term-heap capacity is the hard limit** for anything not collected (`+hmax N` is a **real** cap); on-demand growth is adopted at the admission point at both allocation doors (leaving the `Process::collection_debt` the next admission point turns into a real collection) and on the message-delivery path — `M1_GAPS.md` *GC / heap model*.
  **The debt is settled only by a door, so a loop that reaches none is never collected.** `ensure_heap`/`ensure_heap_full` are reached only by `test_heap`/`allocate_heap`; `alloc_words_rooted`'s capacity refusal is met by `Process::grow_nursery` + a retried bump that **returns** (`src/context/gc.rs:1366-1373`), leaving its `process.collect()` (`:1472`) unreachable unless the growth itself fails, and `alloc_words` has no collection branch. A workload whose loop emits no admission instruction therefore shows `statistics(garbage_collection) == {0,0,0}`, `minor_gcs == 0` and a **chain-summed** `heap_size` climbing with N (the retired spaces are never collapsed) — use `erlang:garbage_collect/0,1` or an added `test_heap` to tell that shape apart from a decline.
* **The unscanned-root valve exempts a childless foreign boxed container.** `context/gc.rs::root_is_unscanned` answers `foreign && (is_list(t) || foreign_boxed_has_copy_children(t))`, the child test driving the canonical `beam_term::layout::for_each_child_slot` (the enumerator the copier and the walk use), so a leaf a BIF hands back — a shape `layout::sizing_child_slots` gives **no** slot (`make_ref/0`'s frozen all-immediates M1 block, a ref/pid/port block, a float, a bitstring, the empty tuple) — does not open the sticky per-pid descent latch, while a container **with** children (and `SUB_BITS_SUBTAG`, whose forwarded `orig` word keeps it declining) still does — a collector owes a container only *follow* and *update*, and a leaf imposes neither.

* **A process entry naming a host-served MFA is dispatched, never entered as that module's code.** `ProcessEntry::Export` asks `RuntimeContext::host_serves` (runtime-native floor ∪ a loaded NIF module ∪ a registered `beam_bifs` key) on its **first** entry only and runs a hit through `call_bif` with the BIF's value as `x(0)` — which is what makes a **fired `timer:apply_after/4` deliver its message** (`timer_server:do_apply/2` spawns `erlang:send/2`) and what makes `spawn(erlang,abs,[-3])` yield `3`.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's allocation doors — `alloc_words` and `alloc_words_rooted` (`src/context/gc.rs`) — prefer the running scheduled process's own **young heap** (a no-relocation `Process::grow_nursery` + retry on a capacity refusal) and fall back to the pointer-stable `Runtime::arena` only when the growth cannot reach the request; what a future **moving** heap would dangle is a raw `Eterm` pinned outside the GC root set — the at-risk/safe roster is in `M1_GAPS.md`.
A **parked** (`Waiting`) process is relocation-exempt for its whole parked window — the runner's Wait park arm sets the mark (`src/runner/run.rs`) and the resume clears it — so a delivery- or signal-driven collection of a parked (or just-woken) process is declined and the delivery takes the ordinary heap-fragment fallback.
That exemption **complements** the installed host collection gate (`src/context/gc_walk.rs`'s `RuntimeCollectionGate`, installed on the runtime's process table by `Runtime::new`): the gate declines only when an **unscanned container is reachable from the receiver's gathered roots**, whereas the exemption refuses *any* relocation for the parked window — also covering a live term the host holds **outside** that gathered set.
The `Yield` pre-emption arm is exempt exactly when its slice ended with a live FR prefix (`fr_count > 0`) and not otherwise.
An **exempt** park does **not** publish its roots at all (`src/runner/run.rs::park_machine` returns early and clears `ProcessEngine::parked_published`): nothing can relocate the heap for the whole exempt window, so the parked machine stays the authoritative root set and the resume re-syncs only for a **publishing** (non-exempt) park.
The full hazard analysis is in **[`M1_GAPS.md`](M1_GAPS.md)** under *GC-relocation hazards*.

* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), (d) the library body being the stub `erlang:nif_error(undef)`.
  Cause (d) dominates: the system modules `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as such a stub, so any key the floor and the registry do not serve **raises** (exit 1) for *every* argument; registering the key can only change exit 1 → 3, never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate and every per-call input the prologue derives belongs in the 8-slot dispatch memo; measure with `examples/perf_call.rs` before and after a prologue change (`examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch at all) — prologue/copy-out figures and the reproduction recipes: [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md) *Dispatch cost*, [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *DISPATCH-CUT* / *COPY-OUT-CUT*.
* **The copy-out is a measured 149 ns/call, and it is *architectural*, not slack.** `examples/perf_copy_out.rs` splits `binary_to_term/1`'s **508 ns** call as dispatch prologue 82 + `beam_codec` decode 218 + **copy-out 149** + residual 59 (`term_to_binary/1` is 252; the copier alone 142 ≈ **2.1 ns per copied word**) on the published `etf_roundtrip` payload.
  It is a *second* full traversal of a graph the decoder already wrote, and the C runtime pays none of it (its BIFs allocate straight on the process heap via `HAlloc`), so with today's pooled-BIF-heap shape roughly **none** of that 149 ns is removable inside `beam_rt`: eliding it means handing the pooled region over as a **scanned nursery space** (region ownership transfer — `Nursery`'s space/retired chain and `collapse`, `HeapSpace`/carrier ownership, `Runtime::{take,put}_bif_heap` giving the region away for good) — **owner `beam_gc` + `beam_process`**, a cross-crate handoff.
  The in-crate slack that did exist is gone (the eager per-call off-heap drain scaffolding; the growth hint is the copier's own preflight shortfall, no second `size_object` walk) — harness and caveats: [`TRACE_AND_PERF.md`](TRACE_AND_PERF.md) *The BIF-result copy-out*.
* **A probe that keeps a `RuntimeHooks`-served BIF's container result live across a loop measures ZERO collections — a probe artifact, never a runtime gap.**
  `erlang:statistics/1` is a `RuntimeHooks` key (`beam_bifs/src/hook_sets.rs:451`; 172 keys), so `call_registered` sets `safe_to_rewind = false` (`src/context/calls.rs:398-404`) and its 3-tuple `{Collections, Reclaimed, 0}` is **never re-homed** onto the process young heap (`rehome_container_result`, calls.rs:778 — the re-home branch is skipped, the pool is not rewound): it stays on the pooled BIF heap, a region the copying collector does not scan.
  While such a term is live in an x register / stack slot the door's valve declines (`context/gc.rs:314-328`, `foreign_boxed_has_copy_children` over `layout::for_each_child_slot`), `Runtime::note_foreign_reachable` (`runtime/gc.rs:644`, called at gc.rs:1103) opens the per-pid latch **add-only**, and every later admission point only grows the nursery (`collect_or_grow` / `Process::grow_nursery`) — so `statistics(garbage_collection)` reads 0 new collections, `minor_gcs` 0, and `heap_size` climbs **linearly** with N.
  Measured (debug `beam_rt run`, `$TMPDIR` probe modules, N = 100 000, `mk(N,Acc)->mk(N-1,[N|Acc])`): holding `{G0,_,_} = erlang:statistics(garbage_collection)` across the loop → **0** collections, `heap_size` 318 037; the identical loop reading `element(1, …)` (a small int) or a helper `g() -> element(1, erlang:statistics(…))` → **862** collections, `heap_size` 233; a self-built `{G0, G0+1, 0}` held across → 862.
  The latch does not outlive the foreign root: hold the same tuple inside a **separate function** and the following loop collects again (862).
  So a GC probe must read `element(N, erlang:statistics(…))` — or a helper returning the integer — and never keep the whole tuple live across the measured loop; `erlang:process_info/1,2` is served by the native floor first and *is* safe to hold (862).
  The allocate-and-abandon (`churn`) shape really collects through the CLI: `list_to_binary`/`list_to_tuple` per iteration reads `statistics(garbage_collection)` = **7·N + 18** (N = 1 000 / 3 000 / 10 000 → 7 018 / 21 018 / 70 018) with `heap_size` flat at 1 596, and `process_info(_, garbage_collection)`'s `minor_gcs` = 3 — that key is minors **since the last fullsweep** (`beam_gc`'s `minor_since_major`), never a collection total.
  A **BIF-only** loop (no `test_heap`) reaches no admission point, so an `erlang:garbage_collect/0` inside it is never served (`loop(N) -> _ = erlang:garbage_collect(), loop(N-1)` at N = 1000 reports 19 collections total — the entry's own).
  `DEFAULT_HEAP_WORDS` is never the cause of a zero count: it sizes the runtime's **term-construction** heaps (BIF pool + `-eval` heap, `term_heap_words`, src/runtime.rs), while the process nursery comes from `heap.policy()` (`min_heap_size` 233 → first `heap_size` 843).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call` + the whole-fd family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs`) over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`); the rest of the family stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service wherever it owns the name.
  The io-device read path is complete (`file:read/2`/`read_line/1`/`io:scan_erl_exprs/4`/`io:parse_erl_exprs/4` agree with the oracle — `tests/io_scan.rs`) and `os:set_signal/2` comes from the `RuntimeHooks` bridge — detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **The unscanned-root descent's remaining cost is its *invocation count*, not its visited set.** It is reached per heap-admission through the baseline JIT's `jit_test_heap`; `src/context/gc_walk.rs`'s per-walk visited table is near-optimal (1.25–1.45 probes/insert, ~5 grows over a whole `pool.erl` compile), and a paired A/B on `timer.erl`/`ordsets.erl` keeps its Fibonacci probe mix (the address-bit-poor old probe is 12 % cheaper on `timer.erl`, 37 % dearer on `ordsets.erl`), so cutting the invocation count — and the caller's per-edge `root_is_unscanned`/`for_each_child_slot` cost — is `src/context/gc.rs` / `beam_engine` policy, outside `gc_walk`; the per-walk reset cannot become a cross-walk memo (heap addresses are reused after a collection).
  The per-walk **allocation** is gone (`Registers`/`SavedArgs`/`SignalQueue` gather into a reused `WalkScratch`; the mailbox/dict families seed straight from their iterators), and **re-closing the per-pid latch after a clean descent is unsound as posed** — a descent is exhaustive only over the roots it was handed, and the park arm and the signal gate run for a process whose `x`/stack are unpublished (an *exempt* park publishes nothing), so a clear can hide a foreign container (counterexample and the sound-version requirements in `gc_walk.rs`'s module docs).
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call instead of re-entering the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`), so per-pass costs amortize ×1000 and **per-slice** costs dominate a long run (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000`, `beam_process`).
The measured per-pass / per-slice / per-round inventory — the fresh `ProcessTable` per pass, the progress-aware pass wait (a ready `run` issues **0** `clock_nanosleep`, a parked `receive … after T` is still slept to), the per-slice machine/context/timer churn, the `crate::hasher` word-mixing maps, the occupancy short-circuit and per-round drains, each with its `file:line` and its pinning test — is in **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, as is the per-workload cost of that path ([`src/runner/CONTEXT.md`](src/runner/CONTEXT.md) *Measured*).
The per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.
## Test Strategy
The crate's test strategy — the colocated unit suites, the seam/GC/owner-death suites, the one-per-contract integration suites and the per-call overhead harness — is in **[`TEST_STRATEGY.md`](TEST_STRATEGY.md)**; the per-suite routing and the distribution (A.5) evidence are in **[`tests/CONTEXT.md`](tests/CONTEXT.md)**.
Measured: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --no-fail-fast` = **1908 passed / 0 failed / 1 ignored** (103 targets incl. doc-tests, ~9 min warm; re-run for the current figure). The single `#[ignore]`d test is the A.9 in-process stdlib compile sweep.
**The differential GATE is authoritative and is re-run, never quoted from memory**: `erts_rust/tools/differential/gate.sh` runs the corpus under both runtimes and reports the live per-contract split (the only recorded capability gap is `wire/new_fun_ext_encode`, A.5); the corpus and its allowlist live in the read-only sibling `../tools/differential/`.
**Oracle/test-harness contract (cross-cutting).** Every probe discovers `erl`/`erlc` by **filesystem only, never by running the tool** (`tests/support/mod.rs`, `PROBE_TIMEOUT = 30 s`), and a missing toolchain is always a **loud skip**, never a silent pass or a panic.
Comparisons are trimmed **stdout string** equality, exit codes, error atoms, `term_to_binary`/`.beam` **bytes** and key **order**.
**No test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle** — the GC suites read the runtime's **own** `Runtime::gc_stats()`.
