# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs` and the **CLI flag surface** (**A.6**); the **boot sequence** (the 22 preloaded `.beam`s loaded for real, `src/boot/preloaded.rs`; the OTP boot-script reader/executor `src/boot/bootscript.rs` and its bounded scheduler drives `src/boot/drive.rs`) which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at the final `{progress,started}` (**A.7**); every CLI action but `-version` drives that script before its own start instruction (`-eval`/`-s`/`-run`/`run`/bare `-noshell`, and `-boot FILE`), so a silent action exits **0** with **empty stdout and empty stderr** (the tail's in-node blocker list and the live `whereis` facts are under *A.7/A.9 boot* in `M1_GAPS.md`);
**`system_info/1`** + `erlang:process_info/2` (**A.8**);
the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable);
the **A.4 runtime side of ports** (`open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s);
the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and the `{abs,true}` absolute form) and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
and the **distributed node** (A.5 phases 1–2): the **accepting** half (`src/dist.rs` + the inbound `LocalDeliverySink` in `src/dist/inbound.rs`) and the **connecting** half in `src/dist_client.rs`.
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)
Per-child API surface detail lives in the child nodes' own `CONTEXT.md`; the entries below are the crate-level summary + pointer.
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces; the scheduler-pass family drives processes → ports → timers → distribution in bounded steps; `RuntimeRunner` implements `beam_process::ProcessRunner` — full API surface in [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking, the NIF-dispatch order, the **lent-`TableRegistry` propagation** into a nested fun application (a nested `ets:*` inside a `lists:foldl`/`foldr`/`map` fun reaches the folded table) and `NodeIdentity`'s **real local-node hash** (`node_hash.rs`, so a `term_to_binary(T,[local])` image is real) — full API surface in [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver.rs`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump, and `port_info/1,2`'s **real cumulative per-port byte totals** for `input`/`output`), the native-floor `erlang:port_control/3` (the driver's `control` callback behind `PortRegistry::port_control`) and the runtime's own driver C-ABI host for `{spawn_driver, Name}` (a built-in name resolved before `dlopen`) — full API surface in [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
### `dist.rs` + `dist/` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener bound by `start`, published to `epmd` by the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (the outbound client handshake + the `DistRouter`, the `beam_process::DistSignalRouter` installed on the runtime's **process table** so a locally-initiated link/monitor/exit emits real `DOP_*` bytes).
Both production inbound drives (`dispatch_inbound`/`dispatch_dist_client_inbound`) drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`, the C's `dep != external_pid_dist_entry(from)` check), so a malformed or forged control message is an `Err` that **retires that one link** rather than reaching the `beam_dist::InboundSink`.
`LocalDeliverySink` (the inbound sink, `src/dist/inbound.rs`) routes the ordinary message families (`Send`/`RegSend`/`AliasSend`/plain `AltactSigSend`) plus the route-free receipt families (`Link`; the `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` group; `UnlinkId`/`UnlinkIdAck`; `Monitor`/`Demonitor`; `MonitorExit`/`PayloadMonitorExit` for a DOWN whose reference this node minted; `GroupLeader`) through `ProcessTable`'s inbound (receipt) primitives, each emitting **no** outbound `DOP_*`; a peer `DOP_MONITOR_P` is recorded as a `RemoteWatcher` keyed by the **whole** peer-minted wire reference, and `DOP_DEMONITOR_P` removes exactly that record.
The **only** families still typed `DeliveryOutcome::Unsupported` are the distributed-spawn family (`SpawnRequest`/`SpawnReply`), `Delivery::Other(_)`, and the `UnlinkId` `id != 0` ack-owing half (`id == 0` is `Delivered`); the pass is gated by `Runtime::inbound_delivery` (default **ON**), early-returning unless the runtime is a distribution node with an established link (`src/dist.rs` holds `NodeName`/`DistNode`/`DistConnection`/`resolve_cookie`/`NONODE_NAME`).
Accessors, `NodeName::parse`, `resolve_cookie`, the pump budgets, the envelope rule, the `DistRouter` install site and the per-family routing table (each family → its receipt API): [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md); the sink/node child node: [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; `NifRegistry` offers `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**) and `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`: a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, holding `Some(&'a mut dyn NifHostServices)`; `alloc_env`/`free_env` are real and `make_copy` is the **identity**. The host **exposes that shared table** through `NifHost::atom_table`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by its name, not its interned index. All six state-needing `NifHostServices` hooks are live on a call (`make_ref`, `whereis_pid`, the two liveness answers, the port relations `is_port_alive`/`port_command`); only the load/unload host leaves them the trait default — `M1_GAPS.md` *NIF (A.3)*.
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`, `mailbox.rs`
`config.rs`: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs`, `HeapOptions`/`MaxHeapFlags`/`GcStrategy` (`EmulatorDefault`/`Immix`; the `BEAM_RT_GC_STRATEGY` host opt-in) and `RuntimeConfig::with_heap_options`; `cli.rs`: `USAGE`, the four `EXIT_*` codes, `parse`/`parse_with_env` (merges `ERL_*FLAGS`), `run(Vec<String>) -> i32`; `boot.rs` (A.7): `PreloadedModules`/`PRELOADED_MODULE_NAMES`/`CORE_ATOMS`; `info/` (A.8): the `system_info` key surface; `format.rs`: `term_to_string`/`_w` (drives the registered `io:format/2`); `mailbox.rs`: `RuntimeContext`'s nine `beam_engine::Mailbox` seam methods over the process's `beam_message::Queue` + the per-pid `MailboxState`. **Per-module detail: `src/{cli,info,boot}/CONTEXT.md`.**

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The dispatch table (the source of truth), every implemented/not-implemented BIF and the drift guard live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (11 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry — `os:env/0` is served by `beam_bifs::os_bif::os_env_0` (the floor owns only `os:cmd/1`). The floor's drift guard is **table-driven over every key-granular namespace** (`native::tests::every_floor_arm_key_is_refused_and_every_key_granular_list_is_exact`; 6 key-granular + 8 module-wide namespaces), so a floor key listed without a matching arm fails the suite.
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form.
**`erlang:monitor/2,3`/`demonitor/1,2`, `erlang:alias/1`/`unalias/1` and the reference-alias send destination are served from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed exactly as the C's `erts_monitor_opts` (`erts/emulator/beam/bif.c:701-756`) into a `beam_process::MonitorOptions`, so the monitor's own reference doubles as an alias; a **send destination** that is such a reference resolves to its owner through `src/context/alias.rs::alias_destination` on **both** send seams, and a `{alias,_}` on a **port** monitor or a **remote** target propagates `beam_process`'s typed `unsupported` (`tests/alias.rs`).
**`erlang:garbage_collect/0,1` are served from the floor** (`src/native/erts_internal.rs`, A.7). **No BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet` (every x register, the Erlang stack and the FR file), which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`; the request is served only at the sites that *do* own that root set (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first, so `Runtime::gc_stats().collections` moves only when a collection really ran.
**`code:*` reads and the code path are the native floor over `CodeServer`, alongside a live `code_server` process** (started by the booted `kernel_sup` on every boot-driven route; `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7), so the `boot/*` cases touching `code:*` are **shape-only**). The floor owns the **one** authoritative path store ([`CodeServer`](crate::CodeServer)) for the path readers **and** mutators `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1` (`native::code::path`); the **un-migrated** mutators (`set_path/1,2`, `add_paths/1,2`, `add_pathsz/1,2`, `add_pathsa/1,2`, `del_paths/1`, `stick_dir/1`, `unstick_dir/1`) edit the live server's **second** store, invisible to the floor. `code:ensure_modules_loaded/1` is a floor key (`src/native/code.rs`), so a compiled module's `call_ext` never reaches that second store — which crashes the server — mirroring `code.erl`'s remainder (deduped+sorted, `nofile` unlocated / `badfile` unloadable). **`src/native/code.rs`'s `code:*` behaviour must not change.** Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**The A.9 floor surface is the installation view.** `init:get_argument/1` answers the four automatic flags (`root`/`home` from the runtime's own state, `progname` by the C rule, `bindir` from `CodeServer::bindir()`'s `erts-<vsn>/bin`); `init:script_id/0` reports the **loaded** boot script's `{Name, Vsn}` on every CLI route that drives one (every action but `-version`); `code:lib_dir/2` joins the app directory with the subdir; the `application` view serves `get_all_key/1`/`get_key/1,2`/`get_application/0,1` from the parsed `.app` resource; `erlang:module_loaded/1` is truthful to *this* runtime's loaded set, so `module_loaded(kernel)` stays `false`. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**Three server processes are native state, not scheduled code.** The runtime's root process (registered as `init`), the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) and the **`erl_prim_loader`** stand-in (`src/runtime.rs`, A.7/A.9) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery all work, and `erlang:whereis(erl_prim_loader)` answers a live pid on **every** route (nothing in `bootstrap/bin/start.boot` claims it). The `file_server_2` service is **spawned unregistered on every route that drives a boot script** (every CLI action but `-version`, plus `-boot FILE`), so the booted `kernel_sup`'s own child owns the name; `Runtime::new` registers it only when the runtime drives none. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` means exactly **an OTP `erlang` BIF the oracle exports and serves but this runtime does not**; the effective gap set is that list intersected with what the live registry does not own (drift guard: `error::tests` — `src/error.rs`).
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). A **quoted atom** is a distinct `Tok::QuotedAtom`, so an atom that merely *spells* a keyword (`'receive'`, `'end'`, `'not'`, `'after'`, `'when'`, `'catch'`, `'of'`) is a plain atom — never a reserved word or operator — and a quoted call head (`erlang:'addition'(1,2)`) is an ordinary call (`fun 'foo'/0` and `fun 'erlang':'+'/2` parse; the named-fun form `fun 'foo'(X) -> X end` is rejected as the oracle rejects it). Outside the grammar is a **capability gap** (exit 3) — detail: [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2). **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap. The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` exceeds the 60-bit small range, so it materializes as a bignum); `context_reductions` is answered as `4000`, the canonical ERTS quantum `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2079 lines of production; its ~2190-line unit suite lives in `src/port/tests.rs`), `src/runtime.rs` (~2280 lines — the façade is also the colocated home of its own unit tests), `src/context/calls.rs` (~1272 lines of production, plus an inline `#[cfg(test)] mod notes` tail — the BIF-dispatch + BIF-result-copy-out machinery; its unit suite lives in `src/context/calls/tests.rs`), `src/native/file_server.rs` (~1207 lines of production — the io-device request dispatch table; its unit suite lives in `src/native/file_server/tests.rs`) and `src/runtime/scheduler.rs` (~1288 lines of production, plus a small inline borrow/quiescence test module — the runtime scheduler pass family; its suite is `src/runtime/scheduler/tests.rs`).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle. When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer. Flattening is the graceful **last resort** for an unresolvable payload, never a substitute for adopting handles: the send path unions three source families (`src/context::send_source`) so a resolvable payload takes the SHARE route.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's allocation doors — `alloc_words` and `alloc_words_rooted` (`src/context/gc.rs`) — prefer the running scheduled process's own **young heap** (a no-relocation `Process::grow_nursery` + retry on a capacity refusal) and fall back to the pointer-stable `Runtime::arena` only when the growth cannot reach the request; what a future **moving** heap would dangle is a raw `Eterm` pinned outside the GC root set — the at-risk/safe roster is in `M1_GAPS.md`.
A **parked** (`Waiting`) process is relocation-exempt for its whole parked window — the runner's Wait park arm sets the mark (`src/runner/run.rs`) and the resume clears it — so a delivery- or signal-driven collection of a parked (or just-woken) process is declined and the delivery takes the ordinary heap-fragment fallback. That exemption **complements** the installed host collection gate (`src/context/gc_walk.rs`'s `RuntimeCollectionGate`, installed on the runtime's process table by `Runtime::new`): the gate declines only when an **unscanned container is reachable from the receiver's gathered roots**, whereas the exemption refuses *any* relocation for the parked window — also covering a live term the host holds **outside** that gathered set. The `Yield` pre-emption arm is *not* exempt. The full hazard analysis is in **[`M1_GAPS.md`](M1_GAPS.md)** under *GC-relocation hazards*.

## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`. A bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass` → `note_pending_spawn` → `absorb_pending_spawns`), and every slice's end absorbs the wake list (`beam_process/src/scheduler.rs:435`), so a synchronous two-process ping-pong never empties the run queue and stays in **one** `run_ready` call (`run_ready_inner`, `scheduler.rs:513` `while !self.run_queue.is_empty()`) — it does **not** re-enter the pass boundary per iteration. The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`), so per-pass costs are amortized ×1000 and **per-slice** costs dominate a long run (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000`, `beam_process`).
- **Per pass:** `take_processes` (`src/runtime/scheduler.rs:1166`) builds a **fresh empty `ProcessTable`** (11 `HashMap::new()` + `Vec`s + `RefAllocator`, `ptab.rs:543`) and `mem::replace`s the runtime's table with it; `Scheduler::new()` replaces the old scheduler (`:597`); `put_processes` is a plain assignment.
- **Per pass: the pass wait is progress-aware, so a ready `run` never sleeps.** The pass bottom can `std::thread::sleep` (`src/runtime/scheduler.rs:818`) under the `run` route's `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)` (`:410`); `timer_wait` takes the sleep only when the round that just ended ran **zero** slices (`let progressed = round_slices > 0;`, `:866`) **and** a deadline exists that `TimerWakes::can_wake(run_wake_pid)` can wake (`src/runtime/timer_wakes.rs:123`); the slept amount is `remaining.min(25 ms)` and the policy permits **one** sleep per pass (`:153`). Measured: a `send_recv`-shaped `run` issues **0** `clock_nanosleep` (`strace -f -e trace=clock_nanosleep -T`), the anti-spin half is intact (a parked `receive … after T` is still slept to), and the `send_recv_plain` residual is per-slice work, **not** a per-pass sleep. The boot drives' `ImminentWithin` policy is unchanged. Pinned by `src/runtime/scheduler/tests.rs::{the_run_route_never_sleeps_a_poll_slice_while_it_still_has_slices_to_run, the_run_route_still_sleeps_to_a_parked_receive_timeout, the_idle_only_wait_policy_skips_the_wait_when_the_round_ran_slices}`.
- **Per slice:** engine moved out of/into a `HashMap` (`src/runner/run.rs:383`, `:817`/`:936`); a fresh `RuntimeContext` incl. `DispatchMemo::default()` (8 slots, `src/context/dispatch.rs:42`) (`src/runner/run.rs:444`); `ctx.enter_module` allocates a `String` (`src/context/runtime_context.rs:501`); `publish_parked_roots` (`src/runner/run.rs:807`/`:929`) / `resync_parked_roots` (`src/context/runtime_context.rs:419`) `copy_from_slice` the whole x file (1024 words) plus the stack (`src/context/gc.rs:370`/`:415`); `schedule_receive_timeout`/`cancel_receive_timeout`/`take_timer_resume` add+remove a timer-heap entry and a `TimerWakes` entry (`src/runtime.rs:1119`/`:1138`/`:1148`) — a finite `receive … after T` pays this on **every** iteration; `slice_begin`/`slice_end` (`scheduler.rs:664`/`:737`) and the capacity-retaining wake sweep (`drain_woken_scratch_into`, `:813`) run per boundary.
- **Per slice, O(heap)/O(#mailbox) only when triggered:** the heap-admission seam (`src/context/gc.rs::ensure_heap`) short-circuits on occupancy (`:581`) but still pays a `current_module` **`String` clone** (`:555`) and two valve lookups on *every* admission point; the O(live-objects) descent (`any_root_is_unscanned`) is gated per-pid on the shared latch (`foreign_reachable`, `:597`), and the process table's `RuntimeCollectionGate::declines_relocation` (`src/context/gc_walk.rs`) is built over the **same** latch cell (`ForeignLatch`) so a clear bit answers `false` with no descent (O(1) per delivery) — both only on a collection/refusal.
- **Per round (cheap here):** `service_file_requests` allocates one `Vec::with_capacity(1+devices+retired)` (`src/native/file_server.rs:321`); `deliver_port_messages` early-returns `Ok(0)` on `has_nothing_to_poll()` with no live port (`src/port.rs:2566`, no poll sleep); each dist half is one `Option` match with no node.
- **Out of this node:** the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work — the differential gate, A.7/A.9 boot, the native `file_server_2` service, `beam_process`/`beam_message`, `beam_engine`, the node identity, `beam_io`/`beam_abi`, the send path's caller-machine handle plumbing (`beam_engine`/`beam_bifs`), `beam_bifs`' `ets:setopts/2` and registry dispatch cost, and the port-table borrow — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *Cross-node handoffs*.
**Inbound distribution's remaining `Unsupported` families each need a new sibling API**: the distributed-spawn family needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender plus the reservation bookkeeping a `DOP_SPAWN_REQUEST` keys into), and `Delivery::Other(_)` (the C kills the connection outright, `dist.c:2277-2282`) is the link driver's.
`beam_process`'s route-free receipt primitives (all present, none echoing a `DOP_*`): `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)`/`demonitor_from_remote_ref(watched, reference: RemoteRef)` (the peer-minted wire-reference spellings; the `MonitorRef` ones stay for an internal ref), `remote_monitor_down`, `set_group_leader_from_remote`.
`beam_dist` still needs a reply channel on `InboundSink` (the `DOP_EXIT`/`DOP_MONITOR_P_EXIT` `noproc` replies and the `DOP_UNLINK_ID_ACK` cannot be emitted at all: the drain counts only `Delivered`), a connection/peer identity on the sink (the C's arms need the peer's sysname for the envelope and the connection id for the origin checks), and a local-node identity in `decode_control` (inbound references decode as pure external, so a wire reference cannot key an alias or a monitor DOWN). The invalid-message **connection-kill** path is adopted (`Delivery::classify_validated` + the `*_checked` drain, see the API Surface above).
**Routing an inbound creation family through the nearest public `beam_process` entry point would be WRONG today**: those entry points are the *local-initiated outbound* half and route a `DOP_*` through the installed `DistSignalRouter`, whose auto-echo the C's inbound receipt arms never send (`dist.c:2258` `break; /* Done */`).
