# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture.
It owns `main.rs` and the **CLI flag surface** (**A.6**); the **boot sequence** (the 22 preloaded `.beam`s loaded for real, `src/boot/preloaded.rs`; the boot-script reader/executor `src/boot/bootscript.rs` and its bounded scheduler `src/boot/drive.rs`) which executes the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at the final `{progress,started}` (**A.7**); every CLI action but `-version` drives that script before its own start instruction (`-eval`/`-s`/`-run`/`run`/bare `-noshell`, and `-boot FILE`), so a silent action exits **0** with **empty stdout and empty stderr**;
**`system_info/1`** + `erlang:process_info/2` (**A.8**);
the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable);
the **A.4 runtime side of ports** (`src/port/`): `open_port/2`'s `Name`/`Options` decoding, `port_info` over `beam_io`'s registry and poller, the driver C ABI host, and four lanes on top — the **retained-events lane** (a built-in `{spawn_driver,Name}` port replies from its `output` callback into the port input queue, which the `write_command` task round harvests destructively: the bytes fold into `PortRegistry::pending_events` and are reported exactly once by the next `pump`, counted for both `port_info(P,input)` and `erlang:statistics(io)`), the **port signal lane** (`'EXIT'` to a trapping link and `'DOWN'` to every watcher on close, snapshotted at `close` and delivered when the round reports `Closed`), the **port BIF surface** (`port_connect/2` on both the `erlang:` floor and `erts_internal:` bridge spellings over one `port::ops::connect`, `port_set_data/2`/`port_get_data/1`, and the name registry behind `whereis/1`/`registered/0`/`unregister/1`) and the **`port_info` item surface** (`queue_size`/`memory`/`monitored_by`/`locking`/`parallelism`, `/1` an explicit `PORT_INFO_1_ITEMS` allowlist) — detail in [`src/port/CONTEXT.md`](src/port/CONTEXT.md);
the **runtime-local timer deadlines** behind `erlang:send_after/3,4`, `erlang:start_timer/3,4` (relative and `{abs,true}`) and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
and the **distributed node** (A.5 phases 1–2): the **accepting** half (`src/dist.rs` + the inbound `LocalDeliverySink` in `src/dist/inbound.rs`) and the **connecting** half in `src/dist_client.rs`.
The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)
Per-child API surface detail lives in the child nodes' own `CONTEXT.md`; the entries below are the crate-level summary + pointer.
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces; the scheduler-pass family drives processes → ports → timers → distribution in bounded steps; `RuntimeRunner` implements `beam_process::ProcessRunner` — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking, the **lent-`TableRegistry` propagation** into a nested fun application and `NodeIdentity`'s **real local-node hash** (`node_hash.rs`) — [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs`, `src/port/`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-task round, the retained-events lane, `port_info/1,2` with its derived items and **real cumulative per-port byte totals**) and the driver C-ABI host, whose `{spawn_driver, Name}` routing resolves a built-in name before `dlopen`; siblings `ops.rs` (the per-port side table: data term, registered name, link set, owner transfer), `exit.rs` (the `'EXIT'`/`'DOWN'` lane and its pull-based delivery on both routes), `info_extras.rs` (the `port_info` derivations), `driver.rs` (+ `driver/{state,monitor}.rs`), `{watch,tty}.rs` (the `os:set_signal/2` and `prim_tty:tty_select/2` delivery halves) — [`src/port/CONTEXT.md`](src/port/CONTEXT.md).
* **the port BIF floor** (`src/native/port.rs`) → the `port_connect/2` floor arm (the `erlang:` spelling of the one `port::ops::connect`), `port_info/1` for a **registered** port (leading `{registered_name,Name}`, which `beam_bifs`'s filter would otherwise drop) and the five `/2`-only items behind `PORT_INFO_1_ITEMS`' explicit `/1` roster — the C's `ERTS_PORT_INFO_1_ITEMS` and nothing else, so no `/2`-only pair can leak into `/1`.
### `dist.rs` + `dist/` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener bound by `start`, published to `epmd` by the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (the outbound handshake + the `DistRouter`, the `beam_process::DistSignalRouter` installed on the runtime's **process table** so a locally-initiated link/monitor/exit emits real `DOP_*` bytes).
Both production inbound drives drain every **established** link through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity`), so a malformed or forged control message is an `Err` that **retires that one link** rather than reaching the `beam_dist::InboundSink`; `LocalDeliverySink` (`src/dist/inbound.rs`) routes the ordinary message families plus the route-free receipt families through `ProcessTable`'s receipt primitives, each emitting **no** outbound `DOP_*`, and records a peer `DOP_MONITOR_P` as a `RemoteWatcher` keyed by the **whole** peer-minted wire reference.
The **only** families still typed `DeliveryOutcome::Unsupported` are the distributed-spawn family, `Delivery::Other(_)` and the `UnlinkId` `id != 0` ack-owing half; the pass is gated by `Runtime::inbound_delivery` (default **ON**) — the per-family routing table and accessors are in [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), the sink in [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: `lib`'s `Drop` runs the C `unload` against the erased host pointer) and `NifRegistry` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; `NifRegistry` offers `new` (anchors the `enif_*` codegen unit), `is_loaded`, `insert`, `lookup` (**the dispatch predicate**) and `call`.
A NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by its name, not its interned index; every state-needing `NifHostServices` hook is live on a call and only the load/unload host leaves them the trait default.
`build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with that anchor publishes the symbols a real NIF's `dlopen(RTLD_NOW)` needs.
### `config.rs`, `cli.rs`, `cli/`, `boot.rs`, `info/`, `format.rs`, `mailbox.rs` (A.6/A.7/A.8)
`config.rs` defines `EmulatorConfig = beam_common::config::RuntimeConfig` (`Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs`, `HeapOptions`/`MaxHeapFlags`/`GcStrategy`); `cli.rs` the `USAGE` text, `parse`/`parse_with_env` (`ERL_*FLAGS` merge) and `run(Vec<String>) -> i32`; `boot.rs` `PreloadedModules`/`PRELOADED_MODULE_NAMES`/`CORE_ATOMS`; `info/` the `system_info` key surface; `format.rs` `term_to_string`/`_w` over the registered `io:format/2`; `mailbox.rs` the nine `beam_engine::Mailbox` seam methods. **Per-module detail: `src/{cli,info,boot}/CONTEXT.md`.**
Observability (`trace.rs` · `seq_trace.rs` · `crash_dump.rs` · `perf_map.rs`): process and sequential tracing, the ERTS-format crash-dump writer behind `erlang:halt`, the `+JPperf` JIT symbol map, the **execution-trace seam** (`call`/`return_from`/`return_to` over `ExecutionContext::trace_event`, on both paths) and the three per-call harnesses — **[`TRACE_AND_PERF.md`](TRACE_AND_PERF.md)**; emitted events are `send`, `'receive'` (on enqueue), the `{seq_trace, Label, {send, …}}` event and the execution family, with `spawn`/`exit`/`register`/`unregister`/`in`/`out` deferred.
## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations (process/port tables, code server, atoms, the application view, the parsed command line, the timer heap, the preloaded `erts_internal`/`prim_file` surface) from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one and an unclaimed call returns `None`. The dispatch table (the source of truth), the roster, the drift guard and the curated gaps are **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` (11 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry, and the table-driven drift guard fails the suite on a floor key listed without a matching arm.
**Four namespaces deliberately stay on the floor**: `process_info/1,2` (the two `ProcessHook` names it claims, sharing `ProcessBridge`'s value builders, because the seam cannot express `{dictionary, K}`); `erlang:monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` plus the reference-alias send destination; `erlang:garbage_collect/0,1`; and `code:*`. **No BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet`, which a BIF does not own — so `garbage_collect` records **one** request through `Runtime::request_gc` and answers the oracle's `true`, served only where that root set is owned (the engine's heap-admission points and the runner's park arms → `Runtime::serve_gc_request`).
**`code:*` and the code path are the floor over `CodeServer`, alongside a live `code_server` process** (started by the booted `kernel_sup` on every boot-driven route; `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7), so the `boot/*` cases touching them are **shape-only**). The floor owns the **one** authoritative path store for the readers and the mutators `add_patha`/`add_pathz`/`add_path`/`del_path`; the un-migrated mutators edit the live server's **second** store, invisible to the floor, so `code:ensure_modules_loaded/1` is a floor key and a compiled module's `call_ext` never reaches that store — which crashes the server. **`src/native/code.rs`'s `code:*` behaviour must not change.**
**The A.9 floor surface is the installation view** (`init:get_argument/1`'s four automatic flags, `init:script_id/0`'s **loaded** script, `code:lib_dir/2`, the `application` view from the parsed `.app` resource, `erlang:module_loaded/1` truthful to *this* runtime so `module_loaded(kernel)` stays `false`) — [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**Three server processes are native state, not scheduled code.** The root process (registered as `init`), the native **`file_server_2` service** (`src/native/file_server.rs`, A.9) and the **`erl_prim_loader`** stand-in (`src/runtime.rs`) are spawned `Runnable` with no engine and are **never enqueued**; the file service's mailbox is drained by the scheduler pass (`Runtime::service_file_requests`) and its replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/delivery all work, `erlang:whereis(erl_prim_loader)` answers a live pid on **every** route, and the service is spawned unregistered on every route that drives a boot script so the booted `kernel_sup`'s own child owns the name.
**`erlang`-namespace fallback.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` means exactly **an OTP `erlang` BIF the oracle exports and serves but this runtime does not**; the effective gap set is that list intersected with what the live registry does not own (drift guard: `error::tests`).
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — before the boot script and before anything runs |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). A **quoted atom** is a distinct `Tok::QuotedAtom`, so an atom that merely *spells* a keyword (`'receive'`, `'end'`, `'not'`, `'after'`, `'when'`, `'catch'`, `'of'`) is a plain atom, and a quoted call head (`erlang:'addition'(1,2)`) is an ordinary call. Outside the grammar is a **capability gap** (exit 3) — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity. The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar, a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term**: a raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`), recovered by `src/error.rs::live_reason_term` and rendered through `format_term_w` — so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap. The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` are served for a **non-distributed** runtime (the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]`) and fall back to the typed gap as soon as this runtime *is* a node; `start_time`/`end_time` are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (`end_time` materializes as a bignum); `context_reductions` is answered as `4000`, the canonical `beam_common::CONTEXT_REDS`.
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates.
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **A closed port's number is retired only when `beam_io` mints its `Closed` report**, so nothing may call `ProcessTable::port_closed` (whose first step frees the number): port-death signalling snapshots the relations in `PortRegistry::close` and delivers at the `Closed` point (`src/port/exit.rs`).
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured), each a dispatch table or façade whose suite lives in its own sibling: `src/port.rs` (~3.3 k lines of production; unit suite `src/port/tests.rs` ~3.6 k, siblings `ops.rs`/`exit.rs`/`info_extras.rs`/`ram_file_matrix_tests.rs`), `src/runtime.rs` (~2.3 k, tests colocated), `src/context/calls.rs` (~1.3 k), `src/native/file_server.rs` (~1.2 k, the io-device request dispatch table), `src/runtime/scheduler.rs` (~1.3 k, the scheduler pass family), `src/context/gc.rs` (~2.8 k incl. inline tests, ~1.9 k of production) and `src/context/gc_walk.rs` (~1.7 k: ~1.0 k of production — the module docs carry the soundness argument and the latch-clearing refutation — plus the root-set pinning suite, colocated because it drives the private `Walk`/`WalkScratch` types).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle. When the source table cannot name the owner, `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer. Flattening is the **last resort** for an unresolvable payload, never a substitute for adopting handles: the send path unions three source families (`src/context::send_source`) so a resolvable payload takes the SHARE route.

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (by the section named after each bullet); the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **Dispatch and atom-state footings** — a `term_to_binary`/`binary_to_term` round-trip's cost is the codec's own per-call work (the dispatch path is allocation-free and every decode seam uses a per-thread memoized `AtomTable` image), the atom-intern commit is **append-only** (`CodeServer::intern_pending`), `get_module_info` diverges on `exports` order (compared as a set) and answers `badarg` for a module not loaded here, and **an inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** (an immediate-only, uncopied, unrooted slot; the plain `DOP_SEND*` forms pass the wire's `''`) — `M1_GAPS.md` *Dispatch, atoms and module introspection*.
* **No interactive shell; the node is otherwise passive** — the inbound message and receipt families route through `beam_process`'s **route-free receipt** primitives (see *Handoffs*), each mirroring the C's `break; /* Done */` rather than echoing a `DOP_*` — `M1_GAPS.md` *Distribution and the node (A.5)*.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures (`whereis(init)` **does** agree) — `M1_GAPS.md` *Own-state answers*.
* **`process_info/1,2`** answers ~28 items from real state (the `max_heap_size` map's key order/flags diverge; `message_queue_data, off_heap` is accepted-and-ignored) and its `binary` item serves the target's own off-heap refc-binary roster as the oracle's `{Ptr, Size, Refc}` tuples (`[]` when none), so inside the running slice it can omit a payload that slice just built; a non-byte-aligned `-eval` result (or a container past ~80 columns) cannot be printed by the registered `~w`/`~p` printer — `M1_GAPS.md` *`process_info/1,2`* / *Printing*.
* **Process-control gaps** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id — `M1_GAPS.md` *Process-control families*.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual is `ets:setopts/2`'s gift-data aliasing — `M1_GAPS.md` *ETS ownership*.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget** (per interpreted instruction and at the heap-admission points, so a non-allocating loop IS pre-emptible on the interpreter tier); the **native baseline tier's** linked blocks never cross the per-instruction hook — `M1_GAPS.md` *Scheduler / runner*.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's allocation doors — `alloc_words` and `alloc_words_rooted` (`src/context/gc.rs`) — prefer the running scheduled process's own **young heap** (a no-relocation `Process::grow_nursery` + retry on a capacity refusal) and fall back to the pointer-stable `Runtime::arena` only when the growth cannot reach the request; what a future **moving** heap would dangle is a raw `Eterm` pinned outside the GC root set — the at-risk/safe roster is in `M1_GAPS.md`.
A **parked** (`Waiting`) process is relocation-exempt for its whole parked window — the runner's Wait park arm sets the mark (`src/runner/run.rs`) and the resume clears it — so a delivery- or signal-driven collection of a parked (or just-woken) process is declined and the delivery takes the ordinary heap-fragment fallback. That exemption **complements** the installed host collection gate (`src/context/gc_walk.rs`'s `RuntimeCollectionGate`, installed on the runtime's process table by `Runtime::new`): the gate declines only when an **unscanned container is reachable from the receiver's gathered roots**, whereas the exemption refuses *any* relocation for the parked window — also covering a live term the host holds **outside** that gathered set. The `Yield` pre-emption arm is exempt exactly when its slice ended with a live FR prefix (`fr_count > 0`) and not otherwise. An **exempt** park does **not** publish its roots at all (`src/runner/run.rs::park_machine` returns early and clears `ProcessEngine::parked_published`): nothing can relocate the heap for the whole exempt window, so the parked machine stays the authoritative root set and the resume re-syncs only for a **publishing** (non-exempt) park. The full hazard analysis is in **[`M1_GAPS.md`](M1_GAPS.md)** under *GC-relocation hazards*.

* **Oracle-order caveat:** `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure list's order is not stable (measured 117 × `c_m,b_m,a_m` vs 3 × `b_m,c_m,a_m` in 120 probes) — assert failure pairs as a **set**, never as an ordered `vec!`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script): it resolves the system code path via `CodeServer::add_system_paths` → `system_ebins` (a `OnceLock`, once per OS process) and loads the 22 preloaded `.beam`s — even for a self-contained module with an explicit `-pa DIR`.
* **The system code path is resolved NATIVELY, from the filesystem; the system `erl` is only *run* as the documented LAST RESORT** — the `lists.beam` acceptance probe, the layout shapes, the candidate-root order and the fallback are in [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*, so a normal installation pays **no** `erl` start-up for the resolution itself.
* **Whole-process startup is ~0.44 s (release) of engine CPU work** (the oracle's `-eval` boot is ~0.14 s). The wait a blocked pass pays is **mechanism-agnostic** — the timer sleep, or the port poll's blocking `epoll_wait(PORT_POLL_SLICE)` while a live port exists (a booted kernel keeps `inet_gethost` open) — so read it as bounded, never as one syscall name. The boot drive's `TimerWait::ImminentWithin(TIMER_PUMP_SLICE)` sleeps only when the earliest pending deadline is **within** the window, so a pending 1 s / 1 h `gen_server` `WaitTimeout` never sleeps and never busy-spins while a parked `receive … after T` (T ≤ 100 ms) is still slept to — [`PERF.md`](PERF.md).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export`, (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the preloaded `code`/`erl_ddll`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` modules ship every non-Erlang function as such a stub, so any key the floor and the registry do not serve **raises** (exit 1) for *every* argument; registering the key can only change exit 1 → 3.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key.
* **Dispatch cost and the copy-out are measured, not slack.** `call_registered` runs per call: gate any handle built there behind a `uses_*` predicate and put every per-call prologue input in the 8-slot dispatch memo (measure with `examples/perf_call.rs`; `examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and cannot measure registry dispatch). The copy-out is a *second* full traversal of a graph the decoder already wrote — which the C runtime does not pay, its BIFs allocating straight on the process heap via `HAlloc` — removable only by handing the pooled BIF region over as a **scanned nursery space**, a `beam_gc` + `beam_process` handoff — [`PERF.md`](PERF.md).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call` + the whole-fd family in `src/native/prim_file.rs`) over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`); the rest of the family stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service — [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
* **The unscanned-root descent's remaining cost is its *invocation count*, not its visited set.** It is reached per heap-admission through the baseline JIT's `jit_test_heap` and its per-walk visited table is near-optimal (1.25–1.45 probes/insert), so cutting the invocation count is a `src/context/gc.rs` / `beam_engine` policy question; the per-walk reset cannot become a cross-walk memo (heap addresses are reused after a collection) and the per-walk **allocation** is gone (`WalkScratch`). **Re-closing the per-pid latch after a clean descent is unsound as posed:** a descent is exhaustive only over the roots it was handed, and the park arm and the signal gate run for a process whose `x`/stack are unpublished — counterexample in `src/context/gc_walk.rs`'s module docs.
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`. A bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass` → `note_pending_spawn` → `absorb_pending_spawns`), and every slice's end absorbs the wake list (`beam_process/src/scheduler.rs`), so a synchronous two-process ping-pong never empties the run queue and stays in **one** `run_ready` call — it does **not** re-enter the pass boundary per iteration. The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs`), so per-pass costs are amortized ×1000 and **per-slice** costs dominate a long run (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000`, `beam_process`).
- **Per pass:** `take_processes` builds a **fresh empty `ProcessTable`** (11 `HashMap::new()` + `Vec`s + `RefAllocator`, `ptab.rs`) and `mem::replace`s the runtime's table with it; `Scheduler::new()` replaces the old scheduler; `put_processes` is a plain assignment.
- **Per pass: both halves of the wait are progress-aware, so a ready `run` never blocks.** The pass bottom can `std::thread::sleep` under the `run` route's `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)`; `timer_wait` takes the sleep only when the round that just ended ran **zero** slices (`let progressed = round_slices > 0;`) **and** a deadline exists that `TimerWakes::can_wake(run_wake_pid)` can wake (`src/runtime/timer_wakes.rs`); the slept amount is `remaining.min(25 ms)` and the policy permits **one** sleep per pass. The **port half** takes the same flag: `deliver_port_messages` gets the poll's full `PORT_POLL_SLICE` only for a round that ran nothing and `Duration::ZERO` for a progressed round — without that, a booted kernel's live `inet_gethost` port keeps `has_nothing_to_poll()` false and **every** pass stalls a full 25 ms in `epoll_wait` (measured: 1063 blocking waits / 26.9 s over a 20 000-round `send_recv` ping-pong, versus 6 / 137 ms once a progressed round polls without blocking). Both halves are pinned structurally, never by wall clock: `src/runtime/scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing` (the test-only `BLOCKING_PORT_ROUNDS` counter) and end-to-end by `tests/run_route_sleep.rs`, which asserts the **property** — no blocking wait that grows with the work, a parked `receive … after T` still waited to — never one syscall name.
- **Per slice:** engine moved out of/into a `HashMap` (`src/runner/run.rs`); a fresh `RuntimeContext` incl. `DispatchMemo::default()` (8 slots, `src/context/dispatch.rs`); `ctx.enter_module` allocates a `String`; the park hand-off (`src/runner/run.rs::park_machine` → `publish_parked_roots`, and the resume's `resync_parked_roots`) `copy_from_slice` the whole x file (1024 words) plus the stack (`src/context/gc.rs`) — **skipped entirely for an exempt park** (every `Wait` park, and a `Yield` arm whose slice ended with a live FR prefix), where the parked machine stays the authoritative root set (see *GC-relocation hazards*); `schedule_receive_timeout`/`cancel_receive_timeout`/`take_timer_resume` add+remove a timer-heap entry and a `TimerWakes` entry — a finite `receive … after T` pays this on **every** iteration, and the `Timers` heap reclaims a cancellation it does not hold at its head by rebuilding past a watermark (`COMPACT_SLACK = 64`, `src/timers.rs`: only once tombstones outnumber live entries), so a cancelled deadline is never a permanent tombstone; every pid/Eterm-keyed collection the hot path touches is `crate::hasher`'s word-mixing map, not SipHash (`TimerWakes`, `Runtime::{timer_resumes,group_leaders,async_dist,monitor_nodes}`, `RunnerState`'s `engines`/`results`/`exits`/`errors`, the mailbox map and the reachability latch); `slice_begin`/`slice_end` and the capacity-retaining wake sweep (`drain_woken_scratch_into`) run per boundary.
- **Per slice, O(heap)/O(#mailbox) only when triggered:** the heap-admission seam (`src/context/gc.rs::ensure_heap`) short-circuits on occupancy but still pays a `current_module` **`String` clone** and two valve lookups on *every* admission point; the O(live-objects) descent (`any_root_is_unscanned`) is gated per-pid on the shared latch (`foreign_reachable`), and the process table's `RuntimeCollectionGate::declines_relocation` (`src/context/gc_walk.rs`) is built over the **same** latch cell (`ForeignLatch`) so a clear bit answers `false` with no descent (O(1) per delivery) — both only on a collection/refusal.
- **Per round (cheap here):** `service_file_requests` allocates one `Vec::with_capacity(1+devices+retired)`; `deliver_port_messages` early-returns `Ok(0)` on `has_nothing_to_poll()` with no live port (no poll sleep); each dist half is one `Option` match with no node.
- **Out of this node:** the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work — the differential gate, A.7/A.9 boot, the native `file_server_2` service, `beam_process`/`beam_message`, `beam_engine`, the node identity, `beam_io`/`beam_abi`, the send path's caller-machine handle plumbing, `beam_bifs`' `ets:setopts/2` and registry dispatch cost, and the port-table borrow — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *Cross-node handoffs*.
**Inbound distribution's remaining `Unsupported` families each need a new sibling API**: the distributed-spawn family a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender plus the reservation bookkeeping a `DOP_SPAWN_REQUEST` keys into), and `Delivery::Other(_)` (the C kills the connection outright) the link driver's; `beam_dist` still needs a reply channel on `InboundSink` (the `DOP_EXIT`/`DOP_MONITOR_P_EXIT` `noproc` replies and the `DOP_UNLINK_ID_ACK` cannot be emitted: the drain counts only `Delivered`), a connection/peer identity on the sink, and a local-node identity in `decode_control`.
`beam_process`'s route-free receipt primitives (all present, none echoing a `DOP_*`): `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref`/`demonitor_from_remote_ref` (the peer-minted wire-reference spellings), `remote_monitor_down`, `set_group_leader_from_remote`.
**Routing an inbound creation family through the nearest public `beam_process` entry point would be WRONG today**: those entry points are the *local-initiated outbound* half and route a `DOP_*` through the installed `DistSignalRouter`, whose auto-echo the C's inbound receipt arms never send.
