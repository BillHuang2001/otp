# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture. It owns:
`main.rs` and the **CLI flag surface** (**A.6**);
the **boot sequence** — the 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`), the OTP boot-script reader/executor (`src/boot/bootscript.rs`) and its bounded scheduler drives (`src/boot/drive.rs`), which run the real `bootstrap/bin/start.boot` to its final `{progress,started}` (**A.7**);
**`system_info/1`** + `erlang:process_info/2` (**A.8**);
the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid, including every optional `beam_bifs` host seam (the key deliverable);
the **A.4 runtime side of ports** (`open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, and the driver C ABI host `src/port/driver.rs` — the child/driver lifecycle is `beam_io`'s);
the **runtime-local timer deadlines** behind `erlang:send_after/3` and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
and the **distributed node** (A.5 phases 1–2): the **accepting** half in `src/dist.rs` and the **connecting** half in `src/dist_client.rs` (the outbound client handshake + the `DistSignalRouter` that turns a locally-initiated link/monitor/exit into wire `DOP_*`).

The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`); `beam_rt` does the same through the real glue and the executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`.

### `dist.rs` / `dist_client.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the *accepting* half (a wildcard listener bound by `start`, published to `epmd` by the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half. `dispatch_inbound`/`dispatch_dist_client_inbound` drain every **established** link's queued inbound `DOP_*` through `beam_dist`'s **per-link checked** path (`ConnectionDriver::dispatch_inbound_checked` → `Delivery::classify_validated` against **that link's own** `LinkIdentity` — the C's `dep != external_pid_dist_entry(from)` check), so a malformed or forged control message is an `Err` that **retires that one link** (reason recorded) rather than reaching the `beam_dist::InboundSink`; `LocalDeliverySink` routes the ordinary message families (`Send`/`RegSend`/`AliasSend`/plain `AltactSigSend`) plus the route-free receipt families (`Link`; the `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` group; `UnlinkId`/`UnlinkIdAck`; `MonitorExit`/`PayloadMonitorExit` for a DOWN whose reference this node minted; `GroupLeader`) through `ProcessTable`'s inbound (receipt) primitives, each emitting **no** outbound `DOP_*`; `Monitor`/`Demonitor`, the distributed-spawn family and `Other(_)` return the typed `DeliveryOutcome::Unsupported` with the still-missing API named at the arm, and the pass is **gated by `Runtime::inbound_delivery`** (default **ON**), early-returning unless the runtime **is** a distribution node **with** an established link. Accessors, `NodeName::parse`, `resolve_cookie`, the pump budgets (`MAX_ACCEPTS_PER_PUMP`/`DIST_READ_SLICE`/`DIST_CONNECT_TIMEOUT`), the envelope rule, the `DistRouter` install site and the per-family `Unsupported` table: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` — whose `Drop` runs the C `unload` against the erased host pointer — goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`; `NifRegistry` offers `new()` (anchors the `enif_*` codegen unit), `is_loaded` (the oracle's `reload` condition), `insert`, `lookup` (**the dispatch predicate**) and `call`.
`NifHostImpl<'a>` implements `beam_abi::NifHost`: a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner` and holding `Some(&'a mut dyn NifHostServices)`; `alloc_env`/`free_env` are real and `make_copy` is the **identity**. The host **exposes that shared table** through `NifHost::atom_table`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` reach the runtime's atom names and an atom **nested** in a tuple/list orders and hashes by its name (the C's `erts_cmp_atoms`) rather than by its raw interned index — pinned by `src/nif.rs`'s `the_host_exposes_its_atom_table_so_nested_atoms_order_by_name`. All six state-needing `NifHostServices` hooks are live on a call — `make_ref`, `whereis_pid`, the two process-liveness answers and the two **port** relations `is_port_alive`/`port_command` (`RuntimeNifServices` over the runtime's `&RefCell<PortRegistry>`, proven end to end through a compiled `.c` NIF: `tests/nif.rs::enif_port_hooks_answer_the_real_port_registry`); only the load/unload host, which cannot borrow the runtime, leaves them the trait default (hook-by-hook detail in `M1_GAPS.md` *NIF (A.3)*).
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The child modules, the dispatch table (the source of truth) and every implemented/not-implemented BIF live in **`src/native/CONTEXT.md`**; the six process/name/global-state arms the registry owns are absent from the floor, so `ProcessBridge` is their only implementation.
`native::FLOOR_MODULES` gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a `beam_bifs` registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry — `os:env/0` is served by `beam_bifs::os_bif::os_env_0` (the floor owns only `os:cmd/1`).
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift; `try_native` intercepts them first because the seam cannot express the `{dictionary, K}` item form (so `ProcessBridge`'s keys/items only satisfy the seam, unit-tested directly).
**`erlang:monitor/2,3`/`demonitor/1,2`, `erlang:alias/1`/`unalias/1` and the reference-alias send destination are served from the floor** (`src/native/process/`): `monitor/3`'s option list is parsed exactly as the C's `erts_monitor_opts` (`erts/emulator/beam/bif.c:701-756`) into a `beam_process::MonitorOptions` passed through the `*_with_options` monitor entry points, so the monitor's own reference doubles as an alias. A **send destination** that is such a reference resolves to its owner through the shared helper `src/context/alias.rs::alias_destination` on **both** send seams — `erlang:send/2`/`'!'/2` (the `SendBridge`) and the **compiled** `Dest ! Msg` (`ExecutionContext::send_message_with_off_heap`, the one `gen_server:reply` uses) — a `reply_demonitor` alias being consumed after a successful delivery (`ProcessTable::alias_reply_delivered`); a `{alias,_}` on a **port** monitor or a **remote** target propagates `beam_process`'s typed `unsupported`. Accepted option shapes and the oracle-cross-checked evidence (`tests/alias.rs` — a real `gen_server:start_link` + `gen_server:call/2` on a pid and on a registered name): [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
**`erlang:garbage_collect/0,1` are served from the floor** (`src/native/erts_internal.rs`, contract A.7). **No BIF may collect** — the root set a collection relocates is the *executing machine's* whole `RootSet` (every x register, the whole Erlang stack and the FR file — whole from the in-slice heap-admission doors, only the live `fr_mark()` prefix from the park arm), which a BIF does not own — so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true`; the request is served at the sites that *do* own that root set (the engine's heap-admission points and rooted allocation seam, `src/context/gc.rs::{ensure_heap, ensure_heap_full, alloc_words_rooted}`, and the runner's park arms, `src/runner/run.rs` → `Runtime::serve_gc_request`) and pruned at the pass boundary for a process that terminated first (`src/runtime/scheduler.rs::prune_gc_requests`), so `Runtime::gc_stats().collections` moves only when a collection really ran (a valve-refused request is dropped with the counters untouched). `/1`'s contract, `/2`'s `get_gc_opts/2` option grammar and its one residual (the **asynchronous completion** — the oracle later sends the caller `{garbage_collect, ReqId, Result}`, whereas here the request joins the same one latch and no completion message is sent), with oracle cross-checks in `tests/garbage_collect.rs`: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**`code:` is the native floor, not a live `code_server`.** `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7) the oracle serves from `init.beam`/`code.beam`/`application.beam`; `beam_rt` ships **no** live `code_server.beam` (its *state* is `CodeServer`), the `boot/*` differential cases touching `code:*` are **shape-only**, and a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**
**The A.9 floor surface is the installation view.** `init:get_argument/1` answers the four automatic flags — `root`/`home` from the runtime's own state, `progname` by the C rule (`$PROGNAME` else the compile-time `erl`), `bindir` from `CodeServer::bindir()`'s `erts-<vsn>/bin` — and `init:script_id/0` reports the **loaded** boot script's `{Name, Vsn}` (a precise typed gap on the default `-eval`/`run` path, where none is loaded); `code:lib_dir/2` joins the app directory with the subdir; the `application` view serves `get_all_key/1`/`get_key/1,2`/`get_application/0,1` from the parsed `.app` resource; `filelib`'s existence probes agree on an **absent** path (the stat-failure path of `file:read_file_info/1`/`read_link_info/1`) while an existing-path success is the typed `access(2)` gap; `erlang:module_loaded/1` is truthful to *this* runtime's loaded set, so `module_loaded(kernel)` stays `false`. Detail: [`src/native/CONTEXT.md`](src/native/CONTEXT.md).
**Two server processes are native state, not scheduled code.** The runtime's root process (registered as `init`; it is what every action runs as) and the native **`file_server_2` service** (`src/native/file_server.rs`, contract A.9) are spawned `Runnable` with no engine and are **never enqueued**, so the runner never executes them; their mailboxes are drained by the scheduler pass (`Runtime::service_file_requests`) and the replies deliver through the ordinary mailbox path, so `whereis`/`monitor`/message delivery all work. Detail in [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` means exactly **an OTP `erlang` BIF the oracle exports and serves but this runtime does not** (a name the oracle itself rejects as `undef` must never be listed); the **effective** gap set is that list **intersected with what the live registry does not own** (the `erts_internal:`-hosted calls). Drift guard: `error::tests::{known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry,the_effective_gap_set_never_shadows_the_registry,a_name_the_otp_release_does_not_export_is_not_a_curated_gap,a_reclassified_name_exits_1_and_a_newly_curated_one_exits_3}`.

## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path (before / after `-pz` dirs) |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5 — the accepting half in `src/dist.rs`, the connecting half in `src/dist_client.rs`) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry**; binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). Outside the grammar is a **capability gap** (exit 3).
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`): an unmodeled switch is **data, not a usage error**; only a **stray positional argument** (outside `run`) is exit 2. `run`'s `ARG` tokens: a **signed integer** → `ArgTerm::Int`, a **double-quoted string** → `ArgTerm::Str`, a **list** → `ArgTerm::List`, else a bare atom; the count must equal the arity (else exit 2). **The full switch surface and the `ERL_OTP<vsn>_FLAGS` → `ERL_AFLAGS` → cmdline → `ERL_FLAGS` → `ERL_ZFLAGS` merge live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).**

## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks (or whose truthful own-state value cannot match the oracle's) raise the honest `unsupported` gap. The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears). **The per-key catalog lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
`dist`/`dist_ctrl` (`src/info/dist.rs`) are served for a **non-distributed** runtime — the oracle's own `<<"=node:'nonode@nohost'\n=no_distribution\n">>` and `[]` — and fall back to the typed gap as soon as this runtime *is* a node (`RuntimeConfig::default()` is `nonode@nohost`); `start_time`/`end_time` (`src/info/time.rs`) are the **ERTS monotonic-time interface constants** (`-576460752000000000` / `8646911283000000000`), **not** measured instants (every erts-17.1 build answers that pair, and `end_time` exceeds the 60-bit small range so it materializes as a bignum — both re-probed in `tests/system_info_oracle.rs`); `context_reductions` is answered as `4000`, the canonical ERTS reduction quantum `beam_common::CONTEXT_REDS` (`src/info/schedulers.rs` re-uses that constant and declares **no** local copy — the residual `beam_io::port_task::CONTEXT_REDS` and `beam_process::scheduler::DEFAULT_REDUCTIONS_PER_SLICE` transcriptions belong to their own crates).

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2079 lines of production; its ~2190-line unit suite lives in `src/port/tests.rs`) and `src/runtime.rs` (~2280 lines — the façade is also the colocated home of its own unit tests).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`); the transport copy resolves one of them into its **source** table and the destination **shares** the handle. When the source table cannot name the owner (an empty or unresolvable source), `beam_message`'s copier **flattens** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful, and sound because a refc binary's own `base_flags` word carries its payload data pointer. Flattening is therefore the graceful **last resort** for an unresolvable payload, never a substitute for adopting handles: the send path unions three source families (`src/context::send_source`) precisely so a resolvable payload takes the SHARE route.

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (by the section named after each bullet); the contract-specific gaps are also in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **The `term_to_binary`/`binary_to_term` round-trip cost is the codec's per-call work, not `beam_rt`'s dispatch.** `beam_rt`'s own wired path is allocation-free: the BIF heap is pooled (`Runtime::take_bif_heap`/`put_bif_heap`, rewound on a safe arm), the shared `AtomTable` is only committed when a call actually interns a name (`calls.rs`'s `pending.is_empty()` guard over `Rc::make_mut`), and the `FunIdentityBridge`'s loaded-module snapshot is the code server's **cached** one (`CodeServer::fun_module_snapshot`, rebuilt only when `loaded_generation` moves on a module load, so a call costs an `Rc` clone and one name lookup instead of a walk of the module cache; gated by `beam_bifs::LOCAL_FUN_IDENTITY_BIFS`). The per-op cost is in `beam_bifs`: `binary_to_term/1,2` deep-clones the **whole shared `AtomTable` on every call** (`beam_bifs/src/binconv.rs:1099` `ctx.atoms().clone()`, because the decoder takes `&mut`). The table holds the union of the 22 preloaded modules' atoms (their per-module `AtU8` counts sum to ≈2,720 before dedup).
* **Registered-BIF dispatch** commits pending names through `code_server.atoms_mut()` (`Rc::make_mut`) only when the interner is non-empty, so the shared `AtomTable` is never deep-cloned per call.
* **No interactive shell; the node is otherwise passive** — `-noshell` only. The ordinary message families plus the inbound link/exit/unlink/monitor/demonitor/monitor-down/group-leader families are routed through `beam_process`'s **route-free receipt** primitives (`record_remote_link`/`apply_remote_exit_signal`/`unlink_from_remote`/`unlink_ack_from_remote`/`monitor_from_remote_ref`/`demonitor_from_remote_ref`/`remote_monitor_down`/`set_group_leader_from_remote`), none of which emits an outbound `DOP_*` (each mirrors the C's `break; /* Done */`); a peer's `DOP_MONITOR_P` is recorded as a `RemoteWatcher` keyed by the whole **peer-minted** wire reference (`RemoteWatcherRef::Remote(RemoteRef)`, all-immediate), so two peer references never collapse. The distributed-spawn family and `Delivery::Other(_)` stay typed `Unsupported`, each naming its still-missing API at the arm (see *Handoffs*).
* **Inbound `DOP_SEND_SENDER*` must not pass the wire sender pid as the mailbox `from`** — the API Surface *envelope rule* above: `beam_message::Message::from` is neither copied nor gathered as a GC root, so it must be an immediate (`crates/beam_message/src/message.rs:397-416`), and the decode arena (`DistNode::dispatch_heap`) is reset on every drain; the C's own `ERL_MESSAGE_FROM` for a distribution message is the peer **node atom** `dist_entry->sysname`, never the sender (`erts/emulator/beam/erl_message.c:307`); for the plain `DOP_SEND*` forms (no sender pid on the wire) `envelope_from` passes the wire's own `''` atom through — a typed divergence from the C, which stores the peer sysname there.
* **`get_module_info` divergences** — `exports` order vs the oracle's global export-table order (compared as a set), and `badarg` for a module not loaded here.
* **Own-state answers differ by construction** (not bugs): `processes/0`, `ports/0`, `port_count`, the `persistent_term`/`get_module_info` figures, the `module_loaded/1` boot-set size and the `process_info` heap/reduction figures — `whereis(init)` **does** agree. The **loaded-module set** is the same kind of difference: `code:is_loaded/1` is load-state-based here — a truthful `{file,Path}`/`{file,preloaded}` only for the 22 preloaded modules plus whatever the module cache really loaded, and the atom `false` otherwise — while `code:which/1` and `code:get_object_code/1` are path-based (`code:get_object_code/1` answers the `{Module,Binary,Filename}` triple, or the atom `error`, for any module findable on the code path whether or not it is loaded). That is the oracle's own split, but a differential case pinning a `{file,_}` pair for a non-preloaded module must `code:ensure_loaded/1` it first.
* **`process_info(P, binary)` is served** from the target's `Process::off_heap_binaries()` roster, filled by the runner's **per-slice registration seam** (`src/runner/run.rs` registers the slicing machine's `Machine::refc_binaries()` reservoir onto the owning `Process` on every slice outcome; `beam_process`'s reachability sweep prunes it at each rooted collection), and rendered by `src/native/memory/binary.rs` as the oracle's list of `{Ptr, Size, Refc}` tuples (`[]` when none). `Ptr` is this runtime's own payload address (materialized as a bignum) and `Refc` its own refcount, so cross-runtime comparison is structural, not by value. A `process_info(self(), binary)` issued *inside* the running slice can omit a payload that same slice just built — a safe roster omission, never a dangling term (the machine's reservoir is the lifetime holder). `Runtime::eval_off_heap` payloads are pid-less and are **not** attributed to any process.
* **Process-control gaps** (`src/native/`) — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, and `exit/2,3` against an internal port / a foreign reference or ETS id.
* **ETS owner tracking and owner-death reclamation are live** (heir transfer included, for a `named_table` **and** an unnamed one); the residual gap is `ets:setopts/2`'s gift-data aliasing.
* **Port monitors (A.4)**: a dead *watcher*'s incoming port monitor is swept; `port_info(Port, monitors)` stays `[]`, matching the oracle. **`process_info/1,2`** answers ~28 items from real state (the four execution-position items only for a scheduled module-export process; the `max_heap_size` map's key order/flags diverge; `process_flag(message_queue_data, off_heap)` is accepted-and-ignored). **A non-byte-aligned `-eval` result cannot be printed**: the registered `io:format` `~w`/`~p` printer rejects it (and a container past ~80 columns) with `badarg`.
* **Scheduler is single-threaded; the runner pre-empts on the reduction budget.** The budget is charged **per interpreted instruction** through the engine's `ExecutionContext::reduce` hook (charged *before* the instruction's body runs, so the resume applies its effect exactly once) **and**, on either tier, at the machine's heap-admission points (`ensure_heap`/`ensure_heap_full`, reached by `test_heap`/`allocate_heap`), so a **non-allocating** loop IS pre-emptible on the interpreter tier; `RuntimeContext::wants_reduce()` is `false` and the runner's `BudgetContext` is the one host declaring `true`. The residual is the **native baseline tier** (a compiled block never crosses the per-instruction hook, so a natively linked tail loop is not pre-empted mid-block); a non-statically-readable `receive … after T` delay still parks, and a capability gap is uncatchable on the runner path — `M1_GAPS.md` *Scheduler / runner*.
* **Execution tier defaults to `JitMode::Auto`** (`src/runner/tier.rs`): the native baseline tier for **every** process entry, the tuned tier remembered per process across slices, with `BEAM_RT_TIER` (`auto`/`baseline`/`interpreter`) overriding it. No per-module predicate gates the choice (the engine's baseline driver handles the module-context switch, `switch_into` on a `Step::Enter`) and the one host obligation — an idempotent cross-module seam, since the native `call_ext*` arm re-consults `RuntimeContext::resolve_external_call` through its interpreter-step fallback — is enforced there. Its cost is a **one-shot cold-start compile**, now small: **lazily per function** on first entry of a `(func, pc)` (the eager whole-module `JitBackend::compile` survives only for the whole-module introspection surface and `jit_bench`), into a thread-local compiled-function cache, so a single-shot CLI process pays only the functions it enters (`slice/string_str_length` ≈ **1.2×** the interpreter figure whole-process, was ≈ 12× eager). Figures: [`PERF.md`](PERF.md), `M1_GAPS.md` *Execution tier*.
* **CLI divergences and subset gaps** (`-smp disable` accepted, `-setcookie` unmodeled, `-eval`/`-s`/`-run` subsets) live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).

The `line` grammar (bare `line` ⇒ the oracle's `512`; `{line,N}` ⇒ a positive small integer else `badarg`; mutually exclusive with `{packet,N}` and with `stderr_to_stdout` unless `use_stdio`) and the rest: [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `M1_GAPS.md` *Ports, drivers and the send family (A.4)*.

Msg` instruction's `send_message_with_off_heap` arm carries the machine's handles today). * **A registered-BIF result is moved onto the running process's scanned heap, and the pooled BIF heap is then rewound.** `RuntimeContext::call_registered` (`src/context/calls.rs`) copies a **container** result off the pooled (`Target::Foreign`) heap onto `Process::heap_mut()` (`beam_message::copy_struct` over an **empty** source table; `Process::grow_nursery` + one retry on a full nursery) and rewinds the pool with `Heap::reset_to(mark)` — the offset `heap.used()` read *before* the call — so a scheduled process's BIF-churn loop is **collected** (`Runtime::gc_stats().collections` moves) rather than falling back to the never-freed `Runtime::arena`.
  `reset_to(mark)` frees exactly `[mark..used)` (this call's own words) and keeps whatever a previous owner holds below `mark` — the pool is shared with the native floor, trace and the ETS-owner sweep, which return a heap *unreset*. Rewind only when the move is **safe and complete**: no escaping `DispatchHooks` arm or reentrant call, an `Ok` result, a scheduled process, and a copy that succeeded. **Residuals:** a NIF result, the `-eval` shape, an escaping arm and an error all leave their container on the pooled heap; a nested cross-module run never reaches a collection point — `M1_GAPS.md` *GC / heap model*.

## GC-relocation hazards (what a MOVING engine heap would invalidate)
The engine's `alloc_words` seam prefers the running scheduled process's own **young heap** (a no-relocation `Process::grow_nursery` + retry on a capacity refusal) and falls back to the pointer-stable `Runtime::arena`; what a future **moving** heap would dangle is a raw `Eterm` pinned outside the GC root set — the at-risk/safe roster is in `M1_GAPS.md`.
A **parked** (`Waiting`) process is relocation-exempt for its whole parked window — the runner's **Wait park arm** sets the mark (`src/runner/run.rs`) and the **resume** clears it — so a delivery- or signal-driven collection of a parked (or just-woken, not-yet-resumed) process is declined and the delivery takes the ordinary heap-fragment fallback. That exemption is **complementary to — not the sole mitigation over —** the installed host collection gate (`src/context/gc_walk.rs`'s `RuntimeCollectionGate`, installed on the runtime's process table by `Runtime::new`, so it travels with the table into every pass): the gate declines only when an **unscanned container is reachable from the receiver's gathered roots**, whereas the exemption refuses *any* relocation for the parked window — also covering a live term the host holds **outside** that gathered set (the runner's own entry terms and any live `Eterm` in host Rust state), which the walk cannot see. The `Yield` pre-emption arm is *not* exempt: it publishes the machine's roots first and then serves any pending forced-GC request.
The full hazard analysis — the `Process::regs` snapshot semantics, the three collect triggers and their exposure, the delivery/park arms, the unscanned-root valve, and the at-risk/safe store roster — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *GC-relocation hazards*.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate**: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper). **The compatibility gate**: `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes), or manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `Boot` boots first** (`Runtime::boot_if_needed` → `boot::load_preloaded`), which resolves the system code path via `CodeServer::add_system_paths` → `system_ebins` (memoized in a `OnceLock`, i.e. once per OS process) then loads the 22 preloaded `.beam`s — even for a self-contained module with an explicit `-pa DIR`.
* **The system code path is resolved NATIVELY, from the filesystem; the system `erl` is only *run* as the documented LAST RESORT.** The acceptance probe (`lists.beam` decides), the installation layout shapes, the candidate-root order and the `erl -noshell -eval 'code:lib_dir(...)'` fallback are in [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*. Consequence: a normal installation pays **no** `erl` start-up (measured on this host: `run …slice.beam slice:add/2 2 3` in 0.116 s total, where the spawn alone costs ≈0.5 s).
* **An oracle probe must terminate.** A bare `erl -noshell` never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill.
* **`beam_rt: error undef` is overloaded — four distinct causes.** The CLI prints only class+reason, so one `undef` arises from (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), and (d) the library body being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the system modules `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as an `erlang:nif_error(undef|undefined)` stub, so any key the floor and the registry do not serve **raises** `error:undef`/`error:undefined` (exit 1) for *every* argument; registering the key can only change exit 1 → 3 (`unsupported: ...`), never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate; measure with `examples/perf_bif.rs` before and after any change to the dispatch prologue (figures in `TRACE_AND_PERF.md`).
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`.** **16** `prim_file:*` entries are served (`src/native/prim.rs::prim_file_call` + the whole-fd family `open/2` `read/2` `write/2` `close/1` `position/2` in `src/native/prim_file.rs`), so an interpreted `raw_file_io`/`file_io_server` can open/read/write/seek/close a real OS file, backed by the `Runtime`-owned `open_files`/`open_files_mut` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`); the rest of the `prim_file` family stays **unclaimed** (fall-through to the preloaded `prim_file.beam`'s `erlang:nif_error(undef)`), and the `file.beam` wrappers' `gen_server` calls are answered by the native `file_server_2` service. The io-device read path is complete (`file:read/2`, `file:read_line/1`, `io:scan_erl_exprs/4`, `io:parse_erl_exprs/4` agree with the oracle — `tests/io_scan.rs`) and `os:set_signal/2` is served from the `RuntimeHooks` bridge (one process-global `beam_io::SignalFacility`; the caught signal's `{notify, Signal}` reaches `erl_signal_server`, dropped when none is registered). Entry lists, the reply-tag pairing + `dflag_unicode_io`, the `{get_until,…}`/`{get_line,…}` serving modules and the `EfileDriver`/`FdDriver` gap: [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md), [`src/context/CONTEXT.md`](src/context/CONTEXT.md), [`src/port/CONTEXT.md`](src/port/CONTEXT.md).

**Distribution (A.5) evidence.** `tests/dist_delivery.rs` (31: per-family routing — the message families, the wire-borne `Link`/`Exit` cases, and the newly routed receipt families with a recording-router "no outbound `DOP_*`" check — plus `every_unrouted_family_is_the_honest_unsupported` over the 5 remaining shapes), `tests/dist_client.rs` (a live outbound `DOP_REG_SEND` to a real `erl -sname` peer), `tests/live_inbound.rs` (3: in-process and CLI-subprocess inbound delivery — the `dist_echo` fixture's `after 20` loop is load-bearing because a bare `receive` leaves the run queue empty), `tests/live_signals.rs` (3: the real `erlang:link/1` front door + the router seam + a real negative control), `tests/net_adm.rs` (1 live), `tests/remote_send.rs` (8: the non-node regression, the three-routes-agree check, the same-node case and a live compiled `{Name, PeerNode} ! Msg` asserted on the peer's stdout), and a loopback in `src/runtime/scheduler/tests.rs`.
Measured: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --no-fail-fast` = **1576 passed / 0 failed / 0 ignored** across 82 binaries; `-p beam_dist -p beam_process -p beam_bifs --no-fail-fast` = **2449 passed / 0 failed / 1 ignored** across 145 binaries.
**The differential GATE is authoritative and is re-run, never quoted from memory**: `erts_rust/tools/differential/gate.sh` currently reports `total=2163 agree=2161 mismatch=0 unsupported=2 skipped=0 allowed=2 unauthorized=0 stale=0` → **exit 0**; the only two non-agreeing cases are the recorded capability gaps `wire/new_fun_ext_encode` and `boot_extra/init_script_id_names_the_running_otp_release` (the `known-gaps.txt` allowlist). The corpus lives in the read-only sibling `../tools/differential/` — a case there is owned by the `tools` node, not this crate.

**Oracle/test-harness contract (cross-cutting).** Every toolchain probe discovers `erl`/`erlc` by **filesystem only, never by running the tool** (`tests/support/mod.rs::{resolve_oracle,require_oracle}` + `support::oracle_eval`, `erl -noshell [-pa DIR] -eval EXPR -s init stop`, bounded by `PROBE_TIMEOUT = 30 s`), and a missing toolchain is always a **loud skip** (`skip_loudly`), never a silent pass or a panic. Comparisons are trimmed **stdout string** equality, exit codes, error atoms, `term_to_binary`/`.beam` **bytes** and key **order**. **No test compares live GC counters, `process_info(_, garbage_collection)` figures or `erlang:memory` figures against the oracle**: the only live-oracle GC comparisons are `system_info(garbage_collection)`'s value (`tests/system_info_oracle.rs`) and the `statistics(garbage_collection)` shape `{true,true,0}` (`tests/runtime_hooks.rs`), while `tests/{gc_strategy,gc_immix_payload,gc_collect,gc_run,heap_growth,garbage_collect}.rs` read the runtime's **own** `Runtime::gc_stats()`. The unbounded in-module probe copies and the per-suite comparison roster: [`tests/CONTEXT.md`](tests/CONTEXT.md), [`TEST_STRATEGY.md`](TEST_STRATEGY.md).

## Handoffs (owned by OTHER nodes)
The outstanding cross-node work — the differential gate, A.7/A.9 boot, the native `file_server_2` service, `beam_process`/`beam_message`, `beam_engine`, the node identity, `beam_io`/`beam_abi`, the send path's caller-machine handle plumbing (`beam_engine`/`beam_bifs`), `beam_bifs`' `ets:setopts/2` and registry dispatch cost, and the port-table borrow — is in **[`M1_GAPS.md`](M1_GAPS.md)** under *Cross-node handoffs*.
**Inbound distribution's remaining `Unsupported` families each need a new sibling API**, precisely:
the distributed-spawn family needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender plus the reservation bookkeeping a `DOP_SPAWN_REQUEST` keys into), and `Delivery::Other(_)` (the C kills the connection outright, `dist.c:2277-2282`) is the link driver's.
`beam_process`'s route-free receipt primitives (all present, none echoing a `DOP_*`): `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)`/`demonitor_from_remote_ref(watched, reference: RemoteRef)` (the peer-minted wire-reference spellings; the `MonitorRef` ones stay for an internal ref), `remote_monitor_down`, `set_group_leader_from_remote`.
`beam_dist` — a reply channel on `InboundSink` (the `DOP_EXIT`/`DOP_MONITOR_P_EXIT` `noproc` replies and the `DOP_UNLINK_ID_ACK` cannot be emitted at all: the drain counts only `Delivered`), a connection/peer identity on the sink (the C's arms need the peer's sysname for the envelope and the connection id for the origin checks), and a local-node identity in `decode_control` (inbound references decode as pure external, so a wire reference cannot key an alias or a monitor DOWN). The invalid-message **connection-kill** path this entry used to request now exists and is adopted (`Delivery::classify_validated` + the `*_checked` drain, see the API Surface above).
**Routing an inbound creation family through the nearest public `beam_process` entry point would be WRONG today**: those entry points are the *local-initiated outbound* half and route a `DOP_*` through the installed `DistSignalRouter`, whose auto-echo the C's inbound receipt arms never send (`dist.c:2258` `break; /* Done */`).
