# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)

## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture. It owns:
* `main.rs` and the **CLI flag surface** — contract **A.6**;
* the **boot sequence** — all 22 preloaded `.beam`s loaded for real (`src/boot/preloaded.rs`) plus the OTP boot-script reader/executor (`src/boot/bootscript.rs`) — contract **A.7**;
* **`system_info/1`** + `erlang:process_info/2` — the runtime introspection surface, contract **A.8**;
* the **concrete `ExecutionContext` glue** adapting the engine's seam types onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — including every optional `beam_bifs` host seam (the key deliverable);
* the **A.4 runtime side of ports**: `open_port/2`'s `Name`/`Options` decoding + `port_info` over `beam_io`'s registry and poller, **and** the driver C ABI host (`src/port/driver.rs`, `dlopen` + callback driving; the child/driver lifecycle is `beam_io`'s);
* the **runtime-local timer deadlines** behind `erlang:send_after/3` and a finite `receive … after T` (`src/timers.rs`), advanced only by the scheduler loop;
* the **distributed node** (A.5, phases 1–2 — `src/dist.rs`): the bound listener, the best-effort `epmd` registration and the server-side `'N'` handshake, which **completes** against a real OTP peer.

The vertical slice: the engine-level slice runs on a test-only `MinimalContext` (`../beam_engine/tests/slice.rs`), and `beam_rt` makes the same thing happen through the real glue and the executable end to end (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but must **call down, never duplicate**: BIFs → `beam_bifs`; terms/heaps → `beam_term`/`beam_alloc`; pids/process table → `beam_process`; modules → `beam_loader`; execution → `beam_engine`. Legacy C ground truth (read-only) is under `../../erts/` (files in the Routing Table).

## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)

### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, the node-global `persistent_terms` store, dist) and the scratch `info_heap`.
The **scheduler-pass family** — `run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`run_scheduled`, the shared pass body, the wake absorption and the port/timer/distribution halves — lives in the child `src/runtime/scheduler.rs` (+ its `tests.rs`); every entry point is still an inherent method on `Runtime`.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (A.7: loads the 22 preloaded `.beam`s, idempotent), `boot_from_script(path)` (A.7: read + execute an OTP `{script,…}` boot script), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)); `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` loads the file, `spawn_process`es the export and pumps the **full** scheduler in bounded steps (`RUN_STEP_SLICES` = 1000, `TimerWait::AtMost(PORT_POLL_SLICE)`) until it returns (`x(0)`), **raises** (`take_process_error` returns the original `BeamError`), is quiescent (empty run queue + no live port + no pending timer ⇒ the single-pass `beam_engine::blocked` answer), or outlives `RUN_DEADLINE` (60 s). Exit-code classification (`unsupported` MUST stay exit 3) is byte-identical to the single-pass path; `enter_module(module)` gives the scheduled process its call-site module, so `load_nif/2`, the records/module-info bridges and `LocalFunIdentity` behave the same in both paths.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (`spawn/1`), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)`, `run_queue_len()`; the run/pump entry points live in `scheduler.rs` (`run_scheduler` never hangs — send→wake→resume in one call).
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)`.
* **timers/dist**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()`; the scheduler side — `fire_due_timers`, `note_fragment_wake`, `pump_dist` — is in `scheduler.rs`.

### `runner.rs` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Waiting` + `Wait`; `Err(e)` → record the reason term in `RunnerState::exits` and the original `BeamError` in `RunnerState::errors`, then `Exit(<reason term>)` (never panics). `RunnerState` holds an engine per pid plus the `results`/`exits` maps. A `Wait` **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`Operand::Integer`/`Literal` or a live X-register): the handle lives in `ProcessEngine::parked_timeout`, a fired deadline resumes at the `timeout` instruction delivering nothing, and a message-wake cancels it.

### `context/` — the concrete `ExecutionContext` (the glue)
Files: `mod.rs` + `bridges.rs` + `fun_identity.rs` + `process_bridge.rs` + `module_info.rs` + `persistent_term.rs` + `memory_hook.rs` + `runtime_hooks.rs` + `tests.rs`, plus the test-only `test_support.rs`.
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module` and `engines`. Methods: `new`, `with_output`, `heap_available()`, `for_process(runtime, table, pid)` (runs **as** that pid — the scheduler seam), `pid()`, `pub(crate) eval_heap()`, `enter_module(module)`, `run_export(module, function, arity, args)`.
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → `call_registered` (the `beam_bifs` registry) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (the order is `context/mod.rs::call_bif`, lines ~1040–1078).

**Registry precedence (gotcha for new `beam_bifs` registrations).** The native floor runs *before* the registry, so a `beam_bifs` entry for a key the floor already serves can never shadow it. The registry runs *before* the external-module load, so for any **non-`erlang`** name a registration **does** shadow the fallback (a currently-working export would be replaced), and for an `erlang:*` name it flips the unregistered answer (bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) to whatever the BIF returns; verify per-key that no module-load result is lost. `apply_fun` -> external `fun M:F/A` via `call_bif` (the `-eval` closure `EVAL_FUN_UNIQ` via `apply_eval_closure`; else the module's `FunDescriptor{uniq,index}` then `Machine::run_label`). `ensure_heap` -> `heap_available() >= heap_need` else `BeamError::SystemLimit` (no GC). `send_message` copies into the receiver's heap (`ProcessTable::deliver_simple`); an oversized payload retries through the **heap-fragment** model.

### `call_registered` — nine dispatch arms, two borrow-free hooks, the port provider
`call_registered` builds **one** `BifContext` and installs on **every** arm the atom interner (`PendingInterner`), the port provider (`RuntimePorts`), the memory provider (`RuntimeMemory`) and the two borrow-free hooks `NodeIdentity` + `FunIdentityBridge`; the shared `TableRegistry` is installed **unless** an argument is a fun (a fun argument can re-enter and reach `ets:*`, so the `RefCell` must stay free). Exactly **one** bridge is then selected, first-match, by its own `uses_*` predicate:
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1` (the last two via `get_all`/`erase_all`); a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — eleven BIFs (`whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_info/1,2`, `process_flag/2`, `group_leader/0`) over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>` (`src/context/process_bridge.rs`), reusing `src/native/memory`'s item vocabulary; the floor intercepts `process_info/1,2` first, so the bridge serves the other **nine**.
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; an unloaded module or undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`erlang:'!'/2` delegating to `RuntimeContext::send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR (`src/context/module_info.rs`).
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store; a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow (`src/context/persistent_term.rs`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`) -- the runtime-coupled `beam_bifs` `RuntimeHooks` seam, serving **exactly seven** keys: `start_timer/3,4` (deliver `{timeout, TRef, Msg}`), `send_after/4`, `cancel_timer/2`, `function_exported/3` (this runtime's loaded-module set **or** the live BIF registry) and `link/1`/`unlink/1` (the `ProcessTable` link set; a remote pid is the typed gap). It holds `&mut Runtime` **plus** a `&mut ProcessTable`, so it is its own mutually exclusive arm (`src/context/runtime_hooks.rs`); every other `RuntimeHooks` key answers the typed `unsupported_bif` gap (`{abs, true}` on a timer too, since the heap is a relative `Instant` deadline heap). `timeout` is a `boot::CORE_ATOMS` seed (the bridge cannot intern: the shared table is borrowed immutably for the whole call).
* **`FunBridge`** (`FunCaller`; the fallback) — the existing `RuntimeContext::apply_fun` over `&mut Runtime`; carries a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`, and **no** `TableRegistry`.
`NodeIdentity` answers the fixed `(nonode@nohost, creation 0)` for `beam_codec`'s `Encoder::with_local_node`, so `term_to_binary/1` of an internal pid emits `NEW_PID_EXT` (`88`) and of an internal port `V4_PORT_EXT` (`120`).
`FunIdentityBridge` supplies the `NEW_FUN_EXT` (`112`) identity of a **compiled module's** local (`make_fun3`) fun, which the term does not carry: an owned snapshot (the caller module's `Arc<Module>` + `.beam` path + the node atom) holding no runtime borrow, so it installs alongside any arm; `Ok(None)` — never an error — for a non-local-fun argument, a context with no calling module (the `-eval` evaluator) or an unreadable `.beam`, otherwise the identity (`bridges.rs::local_fun_identity`/`module_md5`: module atom + module MD5 + `old_index`/`old_uniq` from the module's `FunT` + the fixed `<0.0.0>` creator), so a compiled module's closure encodes byte-exactly.
The nine arms + two hooks are the **only** place the engine's seam meets the Stage-5 core (keeps the Stage-1/Stage-5 DAG acyclic).

### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` is `Clone` over `Rc<RefCell<{ base: usize, names: Vec<String> }>>`: `new(base)` roots it at the shared table's length before the call, `commit(&AtomTable)` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers); `load_nif/2`'s two writers (the BIF, the C `load` callback via `enif_make_atom`) share the cell. `run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess).
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable **pooled BIF heap** and the per-call `PendingInterner` is committed **after the registry borrow is released**. `NifCallError::Raised(reason)` → `error::nif_raised` (a live-reason-term raise); `UnknownFunction` → bare `error::undef`; a miss is a no-op (`Ok(None)`). **Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif`.

### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS` (incl. `registered_name`), `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver}`, `StreamType{List,Binary}` (list default), `RuntimePorts` (the `beam_bifs::PortHook` impl: `open_port/2`, `port_close/1`, `port_info/1,2`) built from `Rc<RefCell<PortRegistry>>` + the shared `Rc<AtomTable>` + the owning `ProcessId` (the `Rc<RefCell<..>>` is the ETS pattern — `FunBridge` needs `&mut Runtime` at the same time; a nested borrow is a typed gap, never a panic).
`PortRegistry` (private `{poller, registry, meta, heap}`): `new()` (anchors the `driver_*` codegen unit), `is_live`/`contains`, `write_command`, `len`/`is_empty` (= `system_info(port_count)`), `ids()` (= `erlang:ports/0`), `close`, the `{spawn_driver,…}` `driver_lookup(name)`, and private `register`/`pump(timeout) -> Vec<PortEvent>`/`take_due_exit_statuses`/`take_driver_outputs`/`info`. Consumers: `Runtime::deliver_port_messages(table, timeout)` + the `-eval` trio `poll_port_messages`/`port_data_message`/`port_exit_message`.
`SpawnDriver` is the **single** OS-child implementation (this crate owns only `open_port/2`'s `Name`/`Options` decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`). `pump` is the single message producer: it polls in `PORT_POLL_SLICE` (25 ms) slices clamped by the earliest driver deadline, runs the port tasks, harvests each driver's `driver_output`, and reports `PortEvent::{Data,Exited}`; `deliver_port_messages` DELIVERS each `{Port,{data,..}}`/`{Port,{exit_status,..}}` into the **owning** process's mailbox. `close` calls `beam_io`'s `notify_port_exit(…, Closed)` **before** `registry.close(...)`.

### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a `dlopen`ed driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops, as in `crate::nif`). `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_`; the handle **is** the per-port `DriverEnv`'s address (a driver-private term arena, the shared `AtomTable` + a `PendingInterner`, the owning `ProcessId`, the output/term-data/pid services, capturing every `driver_output`/`send_term`). `load_driver(candidates, name)` tries each candidate (the loader appends `.so`) and reports the **last** typed error. The `DriverHost` registry hooks carry the C's exact codes: `add_driver_entry`/`remove_driver_entry` (`add` returns `0`; `remove` `1`/`0`/`-1` per `io.c:7698`), `lock_driver` keyed off the port's load state (`io.c:7324`) and `create_port` = the invalid-port sentinel.
`DriverPortAdapter` is the **port lifecycle** the host alone lacks — a `beam_io::Driver` over a loaded C driver: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, kept alive in a `Box` that never moves), `output` hands the port's queued bytes to the driver's `output` callback and queues the `driver_output` reply as the port's **input** (surfaced by `take_driver_outputs` as `{Port,{data,Data}}`), `stop` runs the entry's `stop`, and the drop runs `finish` + `dlclose`.
`PortRegistry::new` anchors `beam_abi`'s driver codegen unit (`black_box(beam_abi::driver::drv::driver_api_table())`) so `build.rs`'s `-Wl,--export-dynamic` publishes the `driver_*`/`erl_drv_*` symbols. `open_port({spawn_driver, Name}, Options)` routes here (`PortName::SpawnDriver`); an unknown or empty driver name is the oracle's `error:badarg`.

### `dist.rs` — the distributed node (A.5, phases 1–2)
`DistNode` is the runtime's *listening* half: `start(configured, cookie)` **binds** a wildcard listener (`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error) and the first `pump()` **publishes** the node to `epmd` (`ALIVE2_REQ`). Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/`is_short_name()`, `port()`, `creation()`, `is_registered()`/`is_alive()`/`registration_error()` (recorded, never raised), `connections()`, `is_idle()`, `last_link_error()`.
`NodeName::parse(configured)` splits a `-name`/`-sname` value into the wire forms: `full`, `advertised` (the full `node@host` name in **both** cases — a peer resolves it with `list_to_existing_atom/1` and aborts on a bare short name) and `epmd` (the short name for `-sname`, verbatim for `-name`); a bare value's host is `local_hostname()` (`/proc/sys/kernel/hostname`, else `$HOSTNAME`). `resolve_cookie(init_args)` = `-setcookie`, else `$HOME/.erlang.cookie`, else `nocookie`.
`DistConnection` wraps one accepted socket in a **server-side** `beam_dist::ConnectionDriver` (`'N'` → `'s'`/`'S'` → `'r'` → `'a'`): `state()`, `is_established()`, `is_live()`, `peer_name()`, `peer_creation()`, `bytes()`. `pump()` registers once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections non-blocking, then steps every link under a per-link read timeout of `DIST_READ_SLICE` (25 ms), so one pump can never stall the scheduler; a link's protocol/write failure **retires** it and records why (only the listener's own `accept` failure propagates).
`dispatch_inbound(atoms, sink)` drains every **established** link's queued inbound `DOP_*` through a `beam_dist::InboundSink` and returns the count. `LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes `Delivery::Send` to a **local** pid (`NoSuchProcess` for another node/creation or an unknown pid) and `Delivery::RegSend` via `ProcessTable::whereis`, both through `deliver_simple` (so a blocked receiver is woken); the link/exit/monitor/alias/`Other` families stay the honest typed `Unsupported` (`beam_process`'s `Links`/`Monitors` take only local `ProcessId`s). The scheduler pass drives it from `Runtime::dispatch_dist_inbound` **gated by `Runtime::allow_inbound_delivery`** (default OFF, so the differential corpus is byte-identical); `Runtime::dispatch_inbound(&mut Heap, &mut ConnectionDriver)` exposes an explicit hop.

### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl>}` (**field order is load-bearing**: Rust drops in declaration order, so `lib` -- whose `Drop` runs the C `unload` against the erased host pointer -- goes *before* the boxed host) and `NifRegistry{libs: HashMap<String,NifEntry>}` (owned by `Runtime` as `Rc<RefCell<..>>`) are `!Send`. `NifRegistry`: `new()` (anchors the `enif_*` codegen unit), `is_loaded(module)` (the oracle's `reload` condition), `insert`, `lookup(module,function,arity) -> bool` (**the dispatch predicate**), `call(..) -> Result<Eterm, NifCallError>`. `NifHostImpl{heap, atoms, interner, self_pid, envs}` implements `beam_abi::NifHost`; a NIF **call** runs on a **fresh** per-call host sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`; `alloc_env`/`free_env` are real and `make_copy` is the **identity** (the message env shares the host heap + atom table, so no word-level copy is needed).
`build.rs` emits `cargo::rustc-link-arg-bins=-Wl,--export-dynamic` **and** `…-tests=…`, and `NifRegistry::new` anchors `beam_abi`'s `enif_*` codegen unit — together they publish the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (proof: `tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`, via `nm -D`). **Typed gaps:** `term_to_binary`/`binary_to_term`/`make_ref` stay at the `NifHost` defaults; a NIF that returns a non-term is rejected by `try_call_nif` with the typed `error: "NIF returned a non-value term"` rather than letting a bare header word reach the engine's term comparison.

`config.rs`: `EmulatorConfig = beam_common::config::RuntimeConfig`; `RuntimeConfig{emulator, code_paths, heap_words, heap, max_ports, init_args, action, env}` with `Action{Boot,Version,Eval,String,Apply,Run,RunFile}`, `ArgTerm{Int,Atom,Str,List}`, `InitArgs` (ordered flag → occurrences), `HeapOptions`/`MaxHeapFlags`.
`cli.rs`: `USAGE`, the four `EXIT_*` codes, `parse`/`parse_with_env` (merges `ERL_*FLAGS`), `run(Vec<String>) -> i32`.
`boot.rs` (A.7): `PreloadedModules`, `PRELOADED_MODULE_NAMES`, `CORE_ATOMS`. `info/` (A.8): `SUPPORTED_KEYS` (**63**)/`UNSUPPORTED_KEYS` (19), `INFO_ATOMS`, `InfoValue` + `to_eterm`, `system_info_value`, `tuple_key_value`, `allocator_report`/`effective_policy`. `format.rs`: `term_to_string`/`_w` (drives `io:format/2`). **Per-module detail: `src/{cli,info,boot}/CONTEXT.md`.**

### Observability: `trace.rs` · `seq_trace.rs` · `crash_dump.rs` · `perf_map.rs` (contract A.8)
Files: `src/trace.rs`, `src/seq_trace.rs`, `src/crash_dump.rs`, `src/perf_map.rs`.
* **`trace.rs`** — ordinary process tracing: `TraceFlags`/`TraceEntry`/`TraceState` (the per-pid flag + tracer table; pure, no runtime borrow) and the `PatternTable` of `{M,F,A}` `trace_pattern` entries; the BIF half is `erlang:trace_info/2` (`flags`/`tracer`/`match_spec`/`traced`/`all`), `erlang:trace_delivered/1`, `erts_internal:trace/3` and `erts_internal:trace_pattern/3`. `RuntimeContext::emit_trace_event` is the single emitter (tracer lookup, `silent` flag, the discard rule, the `trace_ts` flavour, delivery through the internal bypass so an event never traces itself).
* **`seq_trace.rs`** — sequential tracing: the per-process `Token` (`{Flags, Label, Serial, From, Lastcnt}`), the node-global serial clock, the `FLAGS`/`flag_bit`/`decode_flags`/`encode_flags` bitmask, the four `erlang:seq_trace*/seq_trace_print*` BIFs and the `reset_seq_trace` arm of `erlang:system_flag/2`; `RuntimeContext::seq_trace_message`/`seq_trace_send_message` build the `{seq_trace, Label, …}` events (a system tracer is never configured, so `SeqTrace::tracer` stays `None` and the term is built and dropped, exactly as the oracle does).
* **`crash_dump.rs`** — the ERTS-format crash-dump writer behind `erlang:halt`: `snapshot(&Runtime, slogan, seconds) -> DumpInput` + `write_dump(path, dump)` reproduce the oracle's section vocabulary and order (`=erl_crash_dump:0.5` … `=end`), and `crash_dump_path(&ErlEnv)` reads `ERL_CRASH_DUMP`/`ERL_CRASH_DUMP_SECONDS`. Two documented safe-Rust substitutions for the oracle's raw words: `=proc_stack` renders the engine X registers and `=proc_heap` the reachable boxed terms, line-oriented as `=I<hex>`/`=<words>:<hex>`.
* **`perf_map.rs`** — the `+JPperf`-gated JIT symbol map: `PerfFlag` parses the C's accumulating value grammar, `PerfMapConfig` honours `+JPperfdirectory` and `ERL_SYM_MAP_FILE` (default `/tmp`), and `PerfMap::new` creates `perf-<pid>.map`/`jit-<pid>.dump` when the runtime is constructed. **No range is ever fabricated** — the interpreter exposes no native code ranges, so the map is well-formed and empty and `PerfMap::record` is the single hook a future JIT-tier runtime calls.

**Emitted vs deferred trace events.** *Emitted*: the `send` event (`{trace, Sender, send, Msg, To}`), the `'receive'` event (`{trace, Receiver, 'receive', Msg}`, on **enqueue**, gated on the receiver's flag) and the sequential-trace `{seq_trace, Label, {send, …}}` event (the sender's token carries `FLAG_SEND`). *Deferred* — deliberately unemitted rather than emitted with an unpinned shape: `spawn`, `exit`, `register`/`unregister`, `in`/`out` and `call`/`return_to`/`return_from` (no engine spawn/exit/call hook exists yet; `PatternTable::matches` is the predicate such a hook will call).
**The `tracer == tracee` discard rule.** `emit_trace_event` drops an event whose tracer **is** the tracee — mirroring `erts/emulator/nifs/common/erl_tracer_nif.c:143-146` ("Only generate trace for when tracer != tracee") — so a process that traces itself (`erlang:trace(self(), true, [send])`) observes none of its own events. A `silent` tracee and a tracer the process table no longer holds are dropped the same way, never as an error.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations -- the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface -- from `RuntimeContext::try_native`, **before** the `beam_bifs` registry. The child modules (`init`/`code`/`process`/`port`/`memory`/`application`/`erts_internal`/`prim`), the dispatch table (the source of truth) and every implemented/not-implemented BIF live in **`src/native/CONTEXT.md`**; a native entry never duplicates a registry one, and an unclaimed call returns `None`. The six process/name/global-state arms the registry now owns (`ports/0`, `processes/0`, `group_leader/0`, `whereis/1`, `register/2`, `unregister/1`) are absent from the floor, so `ProcessBridge` is their only implementation.
**`process_info/1,2` deliberately stay on the floor** (`src/native/memory/`) — the two `ProcessHook` names it still claims, sharing the **same** value builders with `ProcessBridge` so the paths never drift. Not a gap: the seam cannot express the `{dictionary, K}` item form and the floor resolves item-name atoms on the fly, so `try_native` intercepts them first and `ProcessBridge`'s `process_info_keys`/`process_info_item` only satisfy the seam (unit-tested directly).
**`code:` is the native floor, not a live `code_server`.** `code:*`/`init:*`/`application:*` are preloaded-module surface (A.7) that the oracle serves from `init.beam`/`code.beam`/`application.beam`, written against process/message machinery M1 does not run: `beam_rt` ships **no** live `code_server.beam` (its *state* is `CodeServer`), the `boot/*` differential cases touching `code:*` are **shape-only** and already satisfy, and a future live server must reproduce the `{code_call, From, Req}` → `{code_server, Reply}` wire. **`src/native/code.rs`'s `code:*` behaviour must not change.**
**`erlang`-namespace fallback and the known-unimplemented list.** `call_bif` consults the floor, then the registry, then the `erlang` namespace: a **known** unimplemented OTP `erlang` BIF (`error::is_known_unimplemented_bif`) raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`. The **effective** gap set is `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS` **intersected with what the live registry does not own**, and since `beam_bifs` registers **every** declared `bif.tab` key it is now only the residue with no `erlang`-module entry of that exact `(module, function, arity)` -- the `erts_internal:`-hosted calls (`port_control/3`, `process_flag/3`, `suspend_process/1`, `system_monitor/1`, `garbage_collect/1`, ...). Drift guard: `error::tests::{known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry,the_effective_gap_set_never_shadows_the_registry}`.

## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell exists) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path (before / after `-pz` dirs) |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → preserved verbatim in `emulator.extra_emulator_flags`; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |

| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking workload such as a driver/port echo round-trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* `-eval` grammar (`src/eval/{parse,ast,mod}.rs`): the Erlang **expression** subset — literals in every base, lists/tuples/maps/binaries, the full operator set with precedence, `case`/`if`/`begin`/`try`/`catch`/`receive`, `fun`s and list/map/**binary** comprehensions — walked `erl_eval`-style, dispatching arithmetic/comparison/**bit operators** to the **`beam_bifs` `erlang` registry** (only `and`/`or`/`xor`/`not`/`andalso`/`orelse`/`++`/`--` stay special forms); binary segments accumulate a bit buffer (byte-aligned ⇒ a **binary**, else a **bitstring**). Outside the grammar is a **capability gap** (exit 3).

## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`). A capability gap is **uncatchable**: `src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal` (like `halt`), so the harness's self-terminating `try … catch` probe cannot swallow it. The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**Structured raise reasons render as the real term.** A raise may carry an opaque live reason whose payload is an `Eterm` (the `beam_common::Raise` convention); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export` (`name_atom_raise` recovers a bare-atom reason so it is still classified by name). So `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.

## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap. Strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them. The surface answers **63** atom keys plus **two tuple keys** (`{allocator, A}`, `{wordsize, internal|external}`, dispatched through `info::tuple_key_value`; an unknown word/tag is the oracle's `badarg`) and returns `error:badarg` for any other key; the 19 oracle-accepted keys naming facilities this runtime does not have raise the honest `unsupported` capability gap. **The per-key catalog and the `src/info/{system,limits,schedulers,memory,unsupported}.rs` split live in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**

## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`. **No crate-local error enum**, **no `panic!`/`unwrap()` on runtime data**, **no silent swallowing**. CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))`.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility; `#![warn(missing_docs)]`, every public item documented. Pre-existing oversize (not restructured): `src/port.rs` (~2453 lines; production half ~1470).

## Design Decisions
* **One shared atom table (the code server's).** `CodeServer` owns **one** `Rc<AtomTable>` (copy-on-write on intern); every module it loads is interned into it and `call_bif` hands `BifContext` that same table, so an atom a BIF builds is an index the engine compares and the printer names for **every** loaded module. Indices are insertion-ordered and never renumber.
* **Heap lifetime.** `Runtime` **owns** the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use a separate `info_heap`, `reset()` per call. **`ensure_heap` without GC:** M1 has no engine collector, so it returns `BeamError::SystemLimit` when short (default 64 Ki words); growth-by-collection is Stage 4.
* **CLI is a documented subset, never a silent no-op.** Unmodeled emulator flags are **preserved verbatim** in `emulator.extra_emulator_flags`; `-eval`/`run` reuse the BIF registry rather than re-implementing arithmetic/printing; **`main.rs` is a thin shim** over `cli::run(argv)`; `system_info` returns `Eterm` via `InfoValue`, computed heap-independently, so the keys are unit-testable without a heap.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field* (`#![deny(unsafe_code)]`, may not alias), so `run_pass` **moves** both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`; `Runtime::scheduler` persists across passes.
* **A process's exit reason is not its return value.** BEAM terminates a normally-returning process with `normal`, discarding `x(0)`; the runner **records** the value per pid (`process_result`), copies it onto the pointer-stable `eval_heap` (never reset) via `stabilize_term`, and returns `Exit(normal)`. A **raising** process records the mapped reason term and the original `BeamError` and exits with that term.
* **The host seams: nine bridges + two borrow-free hooks.** Every bridge is a **cheap, non-runtime-borrowing handle** wherever it can be (`Rc<BifRegistry>`, an `Rc<AtomTable>`, an `Rc<RefCell<TableRegistry>>`, a **pooled** `beam_alloc::Heap`, the `Rc<RefCell<PortRegistry>>`/`Rc<RefCell<PersistentTermStore>>`/`Option<DistNode>` fields, the disjoint `output` field); the bridges that must hold a borrow (`FunBridge`/`SendBridge`/`NifBridge`/`ModuleInfoBridge` → `&mut`/`&Runtime`; `DictBridge`/`ProcessBridge`/`RuntimeHooksBridge` → `&mut Runtime` + `&mut ProcessTable`) are made mutually exclusive by their `uses_*` predicates, and `NodeIdentity`/`FunIdentityBridge` are owned snapshots that ride alongside every arm.
* **`nif_error` raises the live reason term.** `beam_bifs`' `erlang:nif_error/1,2` build a `Structured` reason carrying no `Eterm`; `src/eval/mod.rs` intercepts them and raises `Flow::Raise { class: Error, reason: <the argument term> }`, so the **exact** term survives and the raise stays catchable (the same path serves `error`/`exit`/`throw`).
* **Timers are a runtime-local deadline heap, not `beam_process::TimerService`.** That service is driven by **one background thread** whose sink must be `Send + Sync`, but `Runtime` is `!Send` (it owns `Rc`/`RefCell` tables, a `dlopen`ed NIF registry, pointer-stable arenas). So the wheel degenerates to a min-heap (`src/timers.rs`) the **scheduler loop** drains: monotonic deadlines, earlier first, equal keeping insertion order, `O(1)` cancellation via a lazy tombstone, and sleep-to-earliest only when idle.
* **The persistent-term store keeps raw `Eterm` words but compares structurally.** Persistent terms are a node-global key/value table outside every process heap; the store (`src/context/persistent_term.rs`) pins the raw words and compares a key — and the `put_new/2` stored value — with `beam_term::compare::eq` (the C's exact `EQ`, `erl_bif_persistent.c:1015/726`), so a boxed key (tuple/list/map/binary) matches a structurally equal but distinct term. Raw storage is safe because M1 has no GC and every heap is pointer-stable for the runtime's life; Stage 4's collector must register this store as a root.
* **Oversized messages go through the heap-fragment model, composed in-crate.** `beam_message::send_fragmented` wants the receiver's **heap** and **mailbox** at once, but `Process` exposes them only through two `&mut self` accessors, so `RuntimeContext::send_fragmented_message` composes the same public fragment primitives directly and records the wake on `Runtime::note_fragment_wake`; `MailboxState::remove_at` retains a removed message's `Fragments` so a just-bound payload stays valid.
* **Allocator/GC introspection is measured, never hardcoded.** `allocated_areas`, `{allocator, A}` and `process_info/2`'s heap items read *this* runtime's own counters/collector (`beam_alloc::registry`, `beam_gc`), so the figures are real (if smaller than the oracle's) and a missing counterpart is an honest `0`.

## Known Issues / Intentional M1 gaps
* **The registered-BIF path avoids deep-cloning the shared `AtomTable`.** `call_registered`/`try_call_nif` commit pending names through `code_server.atoms_mut()` (`Rc::make_mut`) **only when `PendingInterner::is_empty()` is false** -- the port/persistent-term/NIF handles keep the strong count at 2+, so an unconditional clone would copy the whole table per call. A call that really interns (`binary_to_term`/`list_to_atom`/`binary_to_atom`/`load_nif`) still pays the copy-on-write by design and lands its names at the predicted indices.
* **No interactive shell; the node completes the `'N'` handshake but is otherwise passive.** `-noshell` is the only mode; `-name`/`-sname` bind a listener and register with `epmd` (best-effort, a failure recorded never fatal) and a real OTP 29 peer completes the handshake (`tests/dist.rs`). Gaps: no `net_kernel` protocol, the link/monitor/alias inbound families stay typed `Unsupported` (no remote-peer seam in `beam_process`), and `node/0`/`system_info` do **not** reflect the live node.
* **The two `get_module_info` divergences.** `exports` comes from `ModuleInfoBridge` in `Module::exports` order where the oracle's is the **global ERTS export-table** order (`erl_bif_info.c:8434-8471`), so the differential test compares it as an unordered set; and `get_module_info(M, ...)` raises `badarg` for a module this runtime has not loaded, so a query for e.g. `lists` diverges by module-load state, not by seam.
* **Minor known divergences (all outside this node unless noted).** `persistent_term:info/0`'s `memory` is this runtime's own accounting (the flat heap-word total of the stored terms; `count` is exact). The process dictionary keys by raw `Eterm` word identity (`beam_process::Dict`), so `erlang:put({a},1), erlang:get({a})` is `undefined` here vs `1` in the oracle (`DictBridge` only forwards). `register/2` of an internal PORT id is a typed gap (`ProcessTable` registers pids only). `process_flag(save_calls, <non-integer>)` returns the previous value where the oracle raises `badarg` (`bif.c:1911`).
* **Answers that read *this* runtime's own state differ from the oracle by construction** — not bugs: `erlang:processes/0`, `erlang:ports/0`, `system_info(port_count)`, `erlang:module_loaded/1` and the `persistent_term`/`get_module_info` figures above. `erlang:whereis(init)` **does** agree (the root process; oracle `<0.0.0>`).
* **A non-byte-aligned `-eval` result cannot be *printed*.** The registered `beam_bifs` `io:format` `~w`/`~p` printer rejects a non-byte-aligned bitstring (and a container past its ~80-column limit) with `badarg` -- a **`beam_bifs` gap outside this crate**; the corpus probes read such values through `bit_size/1`/`is_list`. A construction **or** pattern segment wider than 64 bits is *unsupported*; a bignum is `system_limit`.
* **Scheduler is single-threaded; a few M1 process gaps.** A blocked receiver **is** resumed by a sender (send->wake->resume), by a due `send_after/3` timer, or by a fired `receive ... after T` deadline. Gaps: **no reduction pre-emption** (`budget` not enforced); a compiled `receive ... after T` whose delay is **not statically readable** (a **Y-register** variable or `after infinity`) still parks (see the `beam_engine` handoff); a **capability gap is uncatchable** on the runner path.
* **CLI divergences and subset gaps live in [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).** `-smp disable` is accepted where the oracle rejects it; `-setcookie` is unmodeled; `-eval`/`-s`/`-run` are documented subsets.
* **NIF loading is live, with honest typed gaps (A.3).** `load_nif/2` really `dlopen`s the shared object and runs the C NIF; a load failure is the oracle's **returned** `{error, {Reason, Text}}`, never a raise. The extra-environment family works end to end (`alloc_env` hands out a live message env, `make_copy` is the identity, `free_env` releases it — `nif_res/alloc_env_roundtrip` agrees with the oracle). `term_to_binary`/`binary_to_term`/`make_ref` remain at the `NifHost` defaults; a second `load_nif` for a loaded module is `reload`; a NIF that returns a non-term is caught by `try_call_nif` as a typed error, never an abort.
* **`NEW_FUN_EXT`: a compiled module's local fun encodes faithfully; an `erl_eval` lambda stays a typed gap.** `fun M:F/A` builds a real `FunKind::External` term (`EXPORT_EXT`); for a **compiled-module** `make_fun3` closure `FunIdentityBridge` supplies the five identity fields, so `term_to_binary/1` is byte-exact to the oracle (module-scoped to the **caller**). An **`erl_eval` lambda** stays unclonable (its oracle image closes over `erl_eval.erl`'s arity-specialized `expr/6` lambda, whose identity fields are erl_eval internals no seam can derive faithfully), so it stays the honest `unsupported: local_fun`; no wrong encoding is emitted.
* **Ports match the oracle's observable shape; the gaps are these.** The read path is thin (only **stdout** polled, stderr discarded, one `Read::read` per readiness); `connected` flips to `false` only at `port_close/1` and `eof` is inert; a `binary`-stream read wider than 64 bytes is the typed *unsupported* gap. `os:cmd/1` stays the runtime-native host spawn.
* **The send family: `erlang:send/2` and `erlang:'!'/2` are served (the `SendBridge`); two destinations are still typed gaps.** `erlang:send(Port, Data)` needs the port write path, and the distributed `{Name, Node}` send is contract A.5. Both raise `unsupported: …`, never a fabricated value or a wrong `badarg`.
* **Driver ports (A.4) load and drive a real C driver end to end, with typed gaps.** A `{spawn_driver, Name}` port's `driver_output` **is** delivered to its owner as `{Port, {data, Data}}`, and the driver's event/timer requests are real (`driver_select` registers with the runtime's one poller -- exact for one registration per direction, else typed `unsupported`; `driver_set_timer` mirrors into the port's `TIMEOUT` task). Typed gaps: `driver_async` (no async pool; `Runtime` is `!Send`), `port_control/3` not reaching `control`, a captured `send_term`, `ERL_DRV_USE`'s `stop_select`, no OS child (`os_pid` is `undefined`). **Documented M1 extension:** with no `erl_ddll:load_driver/*`, the `Name` doubles as the *search* (a `/`-containing name is the object path, driver name = its file stem; else `<name>.so`).
* **`erlang:send_after/3` / `cancel_timer/1` are runtime capabilities (the native floor); `/4`, `/2`, `start_timer/3,4`, `function_exported/3` and `link/1`/`unlink/1` come from the `RuntimeHooksBridge`.** `send_after` answers a `#Ref<>`; `cancel_timer(Pending)` the remaining ms, `cancel_timer(Fired|Cancelled|unknown-ref)` `false`, `cancel_timer(non-ref)`/a bad time or destination `badarg`. Unimplemented: `erlang:system_info/2`, `read_timer/1,2`, `start_timer`'s absolute form, and every other `RuntimeHooks` key.
* **`process_info/1,2` answers ~28 items from this runtime's real state** (catalog in `src/native/CONTEXT.md`). The four **execution-position** items (`current_function`/`initial_call`/`current_location`/`current_stacktrace`) are answered only for a scheduled process whose entry is a module export (`RunnerState::engine_at` -> the engine's read-only `Machine` accessors); otherwise they are the honest omission/`unsupported`, and a valid oracle item it cannot answer (`catchlevel`, `magic_ref`, `priority_messages`, `binary`, ...) raises the typed `unsupported`. `registered_name`'s wrapping and `process_info/1`'s fixed `pi_1_keys` order are exact; `total_heap_size` is **466** (vs the oracle's 233, this collector pre-allocating a 233-word mature generation) and `memory`/`reductions`/`group_leader` are this runtime's own figures. A pid not in the table is `undefined`; an unknown/non-atom item or a non-pid is `badarg`.
* **Heap has no GC: the term-heap capacity *is* the limit, and exhaustion raises `system_limit`.** `DEFAULT_HEAP_WORDS` is `1 << 24` (16 Mi words of lazily-mapped *address space*: bare startup stays ~17.8 MB, the 1M-element compute loop peaks at ~32.9 MB). The term-construction heaps (the BIF-heap pool + the `-eval` heap) are plain bump arenas sized `config.heap_words`; `+hmax N` is a **real** cap on that capacity (`runtime.rs::term_heap_words`). Heap exhaustion (`BeamError::Alloc(AllocKind::Heap)`) is translated by `error::enforce_term_heap_limit` into the emulator's own **`error:system_limit`** raise (CLI: `beam_rt: system_limit`, exit 1) at the BIF / native-floor / `stabilize_term` boundaries. `lists:seq/2`/`lists:sum/1` etc. are `beam_bifs`-registered BIFs building on that pool (`take_bif_heap`), not on the unbounded engine arena (`beam_engine::MinimalContext`). **This crate drives no collector**: its only `beam_gc` use is `HeapPolicy`/`next_heap_size`/`DEFAULT_MIN_HEAP_WORDS` (`config.rs`, `info.rs::effective_policy`) plus read-only `HeapInfo`/`HeapObservable` for `process_info`; the Stage-4 growth path is the `beam_gc` seam (`Collector::ensure_capacity`, `GcConfig::growable()`) applied where `ensure_heap` already threads the root set (`x_regs[0..live]` ++ stack).
* **`erlang:memory/0,1` are adopted -- the `MemoryHook` seam returns this runtime's real figures.** `beam_bifs` renders the pairs the optional `MemoryHook` trait supplies (`memory/0` in the given order, `memory/1` in the requested order with `badarg` for an unknown key). `beam_rt` installs `RuntimeMemory` (`src/context/memory_hook.rs`) on **every** `call_registered` arm (a cheap handle-based struct that must not borrow `&mut Runtime`, which the `FunBridge` arm already holds). `memory()` returns the nine oracle keys in oracle order (`total, processes, processes_used, system, atom, atom_used, binary, code, ets`) with `total = processes + system`, and every figure is **measured**: `processes`/`processes_used` from the `ProcessTable`'s collectors, `atom`/`atom_used` from the shared `Rc<AtomTable>`, `binary` from `beam_alloc::registry`, `code` from the loaded `.beam` sizes, `ets` from the `TableRegistry`, and `system` = those four + the remaining allocator live bytes (excluding `Standard`/`EHeap` to avoid double-counting process heaps). Figures are snapshotted at construction because the shared ETS `RefCell` is held mutably for the rest of the call. `erlang:statistics/0,1` and the other `RuntimeHooks` families stay unadopted gaps.
* **The heap switches are modelled; some rejection details are not.** `+hms`/`+hmbs` set a `beam_gc::HeapPolicy` rounded through the growth table (`+hms 1000` -> 1598), `+hmax*` the `max_heap_size` map; a malformed value is exit 2 where the oracle exits 1.

## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate**: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper).
* **The compatibility gate**: `erts_rust/tools/differential/gate.sh` (debug build of `beam_rt` + `differential`, then the corpus under both runtimes), or manually `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml -q -p differential -- suite`.
* **`tests/fixtures/` must not be passed to the oracle as a single `-pa`** — it contains a `lists.beam` that shadows stdlib.
* **Every action other than `Boot` boots first** (`Runtime::boot_if_needed` -> `boot` -> `boot::load_preloaded`), which resolves the system code path via `CodeServer::add_system_paths` -> `system_ebins`: this **spawns the system `erl`** once per OS process (`erl -noshell -eval '...code:lib_dir...'`, `codeserver.rs`, memoized in a `OnceLock`) and then loads the 22 preloaded `.beam`s -- even for a self-contained module with an explicit `-pa DIR`. Set `$ERTS_STDLIB_DIR` to skip the spawn entirely, so any `beam_rt ... run ...` timing includes (exactly one) `erl` start-up.
* **An oracle probe must terminate.** A bare `erl -noshell` starts a long-running node and never exits, so every probe appends `-s init stop` and runs through `tests/support/mod.rs`'s bounded poll/kill (see Test Strategy).
* **`beam_rt: error undef` is overloaded -- four distinct causes.** The CLI prints only class+reason, so one `undef` arises from (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export` (`src/context/mod.rs:463`), and (d) the library body itself being the stub `erlang:nif_error(undef)`. Cause (d) dominates: the system OTP modules `code` / `erl_ddll` / `erts_debug` / `erts_internal` / `atomics` / `ets` / `re` / `os` / `net_kernel` / `prim_file` / `error_logger` ship every non-Erlang function as a `erlang:nif_error(undef|undefined)` stub, so any key the floor and the registry do not serve **raises** `error:undef`/`error:undefined` (exit 1) for *every* argument; registering the key can only change exit 1 -> 3 (`unsupported: ...`), never shadow a working result.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` + the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order actually does for a key today.

## Handoffs (owned by OTHER nodes)
`tools/differential/gate.sh`, measured at this node's HEAD: **`total=665 agree=664 mismatch=0 unsupported=1 skipped=0`** (gate exit 3, from the one remaining capability gap). The lone `unsupported` is `wire/new_fun_ext_encode` — an `erl_eval` lambda's `NEW_FUN_EXT` identity (erl_eval internals; see Known Issues). No case mismatches.
* **A.7 boot** — `Runtime::boot_from_script` runs the real `start.boot` directives only until instruction 16 (`{apply,{application,load,…}}`), which needs the `application_controller` this runtime lacks (17–21 unreached). `prim_file` serves 11 entries and `erts_internal` 14 BIFs natively (incl. `beamfile_module_md5/1`); the rest are itemised in `src/native/CONTEXT.md`.
* **`beam_process` / `beam_message`** — a split borrow over a process's heap + mailbox and an owning drain for the wake list; either would delete `RuntimeContext::send_fragmented_message`'s in-crate fragment composition and `MailboxState::retained_fragments`.
* **`beam_process`** — a `!Send`-friendly `SchedulerPool` for SMP adoption: `Runtime` holds `Rc`/`RefCell` tables, `*mut Eterm` heaps, `Rc<FunBody>` closures and a `dyn DistSignalRouter`, so `beam_process`'s `unsafe impl Send` escape is unavailable in an `#![deny(unsafe_code)]` crate.
* **`beam_engine`** — a deadline on `RunOutcome::Wait` (or a `Machine` Y-register accessor). Today the runner recovers the receive delay by scanning the parked function's IR, which cannot read a **Y-register** `after T`, so that process parks instead of timing out.
* **`beam_bifs` / `src/context`** — feed `NodeIdentity` from `Runtime::dist_node()` so `erlang:node/0` and the node-valued `system_info` items reflect a live `-sname`/`-name` node (`erlang:node/0` is currently unregistered ⇒ bare `error::undef`).
* **Distribution, phase 2** — the inbound `DOP_LINK`/`DOP_EXIT`/`DOP_EXIT2`/`DOP_MONITOR_P`/`DOP_DEMONITOR_P`/`DOP_MONITOR_P_EXIT`/`DOP_ALIAS_SEND` families need a `beam_process` **remote-peer** seam (`Links`/`Monitors` accept only local `ProcessId`s) plus an alias table; `DOP_SEND`/`DOP_REG_SEND` already reach local mailboxes. A live-peer loop past the handshake also needs the `FragmentAssembler` receive-buffer coupling.
* **`beam_io`** — finish the driver-port lifecycle (the `async` default, `port_control/3` reaching `control`, a delivered `send_term`, `ERL_DRV_USE`'s `stop_select`, and a **per-registration** `ErlDrvEvent` identity), and revisit `open_port({spawn_executable, <a DIRECTORY path>}, [])` (oracle: a port; here: `error:eacces`).
* **`beam_engine`** — name the rejected opcode: kernel `code.beam`'s `code_server:call/1` executes `recv_marker_reserve/1` (also `recv_marker_bind`/`send`/`loop_rec`/`remove_message`), which falls to the generic unnamed `unsupported("widened opcode not yet executed")` at `beam_engine/src/families/mod.rs`. Diagnostic-quality only.
