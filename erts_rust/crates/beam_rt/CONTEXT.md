# `beam_rt` — Rust ERTS Runtime Binary (boot · CLI · `system_info` · runtime glue)
## Intent
Top of the workspace: produces the `beam_rt` executable and is the only crate that sees the whole picture — `main.rs`, the **CLI flag surface** (**A.6**), **`system_info/1`** + `erlang:process_info/2` (**A.8**) and the **boot sequence** (`src/boot/preloaded.rs`, `src/boot/bootscript.rs`, `src/boot/drive.rs`) that loads the 22 preloaded `.beam`s for real and runs the real `bootstrap/bin/start.boot` (22 instructions) **to completion**, ending at `{progress,started}` (**A.7**).
Every CLI action but `-version` drives that script before its own start instruction, so a silent action exits **0** with empty stdout and stderr.
It owns the **concrete `ExecutionContext` glue** onto the real `beam_bifs` registry / `beam_alloc` heap / `beam_process` pid — including every optional `beam_bifs` host seam (the key deliverable), the **A.4 runtime side of ports**, the **runtime-local timer deadlines** behind `erlang:send_after/3,4`/`start_timer/3,4` and a finite `receive … after T` (`src/timers.rs`), and the **distributed node** (A.5: `src/dist.rs` + `src/dist/` accepting, `src/dist_client/` connecting).
The vertical slice runs on a test-only `MinimalContext` at the engine level (`../beam_engine/tests/slice.rs`) and through this crate's real glue and executable (`Runtime::run_function`/`run_module`).
It depends on **all** other crates (wave 6) but **calls down, never duplicates**: BIFs → `beam_bifs`, terms/heaps → `beam_term`/`beam_alloc`, pids → `beam_process`, modules → `beam_loader`, execution → `beam_engine`.
## API Surface (FROZEN — the runtime façade; re-exported at the crate root and `beam_rt::prelude::*`)
* **the runtime façade, the scheduler-pass family and the runner** (`src/runtime.rs`, `src/runtime/`, `src/runner/`) → `Runtime` owns every table and the slice/spawn/introspection/timer/dist surfaces; the pass family drives processes → ports → timers → distribution in bounded steps; `RuntimeRunner` implements `beam_process::ProcessRunner` — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md).
* **the concrete `ExecutionContext` glue** (`src/context/`) → `RuntimeContext` + the **one** `impl ExecutionContext` (`call_bif`'s order `try_call_nif` → `try_native` → dispatch memo → `call_registered` → external-module load), the nine gated bridge arms, `PendingInterner`/caller-module tracking, the **BIF suspend channel** (`BifOutcome::Suspend`, so a parked machine re-executes the *unapplied* BIF), the **lent-`TableRegistry`** propagation into a nested fun application and the **real local-node hash** (`node_hash.rs`) — [`src/context/CONTEXT.md`](src/context/CONTEXT.md).
* **the A.4 port layer** (`src/port.rs` + `src/port/driver/`) → the `PortHook` provider (`open_port/2` decoding, `PortRegistry`/poller, the port-message pump, `port_info`'s **real cumulative byte totals**), the native-floor `erlang:port_control/3` behind `PortRegistry::port_control` and the driver C-ABI host for `{spawn_driver, Name}` (a built-in name resolved before `dlopen`) — [`src/port/CONTEXT.md`](src/port/CONTEXT.md) · [`src/port/driver/CONTEXT.md`](src/port/driver/CONTEXT.md) · [`src/port/select/CONTEXT.md`](src/port/select/CONTEXT.md).
* **the busy-port park** (`src/port/busy_wait.rs`) → `PortWrite::Parked` (busy test before any queueing, payload unconsumed) → `RuntimeContext::request_suspend` → `BifOutcome::Suspend` → the runner parks and re-runs the BIF, the wait start keyed `(pid, port)` on the `Runtime` so a re-park keeps the *first* attempt's `BUSY_PORT_DEADLINE` — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `tests/port_busy.rs`.
* **the nested port wait** (`RuntimeContext::wait_for_port_event`) → a nested (`-eval`/`-s`/`-run`/boot) passive socket operation sits out its `{inet_async, …}` over the blocking pass, completing through the driver's async-op queue and the completion channel under `crate::port::PORT_EVENT_DEADLINE` — [`src/port/CONTEXT.md`](src/port/CONTEXT.md), `tests/inet_nested.rs`.
### `dist.rs` + `dist/` / `dist_client/` — the distributed node (A.5)
`DistNode` is the *accepting* half (a wildcard listener published to `epmd` on the first `pump()` via `ALIVE2_REQ`) and `DistClient` the *connecting* half (outbound handshake + the `DistRouter` on the **process table**), sharing **one** node→link table (`src/dist/links.rs::DistLinks`), so a locally-initiated `link`/`monitor`/`exit` or a plain send reaches a peer **whichever side opened the socket** (a send to a link-less node dials it first); a `-name`/`-sname` node runs the native `net_kernel` service, so a real peer's `net_adm:ping/1` answers `pong`.
Both inbound drives drain every established link through `beam_dist`'s per-link checked path and `LocalDeliverySink` routes the message and route-free receipt families through `ProcessTable`'s inbound primitives, gated by `Runtime::inbound_delivery` (default **ON**) — per-family routing table and pump budgets: [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md), [`src/dist/CONTEXT.md`](src/dist/CONTEXT.md).
### `nif.rs` — the live NIF libraries (A.3), and `build.rs`
`NifEntry{lib, host: Box<NifHostImpl<'static>>}` (**field order is load-bearing**: `lib`'s `Drop` runs the C `unload` against the erased host pointer, so it precedes the boxed host) and the `!Send` `NifRegistry` (`new()` anchors the `enif_*` codegen unit; `is_loaded`/`insert`/`lookup` — **the dispatch predicate** — and `call`) are `Runtime`'s `Rc<RefCell<..>>`.
A NIF **call** runs on a **fresh** per-call `NifHostImpl` sharing the runtime's **one** `Rc<AtomTable>` + the in-flight `PendingInterner`, so the env-less `enif_compare`/`enif_is_identical`/`enif_hash` order and hash a **nested** atom by name; all **eleven** state-needing `NifHostServices` hooks (select, send, the monitor pair, …) are live on a call.
`enif_schedule_nif` chains run through `beam_abi`'s iterative constant-Rust-stack trampoline (`beam_abi/src/nif/enif/schedule.rs`), and an `enif_select` STOP verdict runs the resource type's own `stop` callback (`beam_abi::nif::enif::call_resource_stop`) — synchronously on `STOP_CALLED` with the caller keeping its reference, or parked for `run_pending_stops()` on `STOP_SCHEDULED` with one kept reference released at the drain.
`src/nif/thread_env.rs` is the **process-independent ("message env") host** a thread a NIF created (`enif_thread_create`) runs on: `ThreadEnvFactory` (one `ForeignHost` per thread) draws every atom from a **private** name→index space (`src/nif/atoms.rs`), and `ForeignHost::send` queues a **complete ETF image** carrying this node's identity, so an atom reaches the live table by **name** when the decoder interns it.
`Runtime::install_nif_thread_env`/`clear_nif_thread_env` own the factory slot (installed from `cli::build_runtime`, the slot being process-global while the suite builds many runtimes per process), and `Runtime::drain_nif_thread_sends` decodes a queued image against the **live** table at `src/context/calls.rs`'s `try_call_nif` and at `src/runtime/scheduler.rs`'s `scheduler_pass`.
`nif_yield_point` is a no-op on both hosts, so a self-rescheduling chain keeps its thread until it ends (a fairness bound, never a wrong result); the load/unload host runs with `services = None` (only the callback-scoped `enif_send` window answers there) and `upgrade` is not modelled (a second `load_nif/2` is the oracle's `reload` refusal).
`build.rs` emits `cargo::rustc-link-arg-{bins,tests}=-Wl,--export-dynamic`, which with `NifRegistry::new`'s anchor publishes the `enif_*` symbols a real NIF's `dlopen(RTLD_NOW)` needs (`tests/nif.rs::the_binary_exports_the_enif_symbols_a_nif_imports`).
Evidence and per-item typed gaps: the oracle-cross-checked `tests/nif_a3_{thread_env,schedule,resource_stop}.rs`, `src/nif/thread_env_tests.rs` and `M1_GAPS_A3_NIF.md` *NIF (A.3)* (which carries the observation tally: the `enif_thread_type()` driver-thread answer and `enif_schedule_nif`'s raw return word account for every remaining divergence).

`config.rs` type shapes: `EmulatorConfig = beam_common::config::RuntimeConfig`, with `RuntimeConfig`, `Action`, `ArgTerm`, `InitArgs`, `HeapOptions`/`GcStrategy`, the `beam_process::{MaxHeapFlags, MaxHeapSetting}` re-exports and `RuntimeConfig::with_heap_options` — the shapes are `src/cli/CONTEXT.md`'s, alongside `src/{info,boot}/CONTEXT.md`.

## The runtime-native BIF floor (`src/native/`) — see `src/native/CONTEXT.md`
The floor serves the BIFs that are really *runtime* operations — the process/port tables, code server, atoms, the application view, the parsed command line, the timer heap and the preloaded `erts_internal`/`prim_file` surface — from `RuntimeContext::try_native`, **before** the `beam_bifs` registry; a native entry never duplicates a registry one and an unclaimed call returns `None`.
**`src/native/CONTEXT.md` is the dispatch table** (the source of truth), the implemented/not-implemented BIF index and the drift guard.
`native::FLOOR_MODULES` (14 names) gates only `resolve_external_call` (in-machine cross-module entry), **not** `call_bif`'s dispatch: a registry key in a floor module's namespace that `try_native` has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s — the floor owns only `os:cmd/1`).
The floor owns the **process/name/global-state arms** (`ProcessBridge`'s only implementation), `process_info/1,2` (`src/native/memory/`, which the `ProcessHook` seam cannot express because of the `{dictionary, K}` item form), `monitor/2,3`/`demonitor/1,2`/`alias/1`/`unalias/1` with the reference-alias send destination (`src/native/process/`: a monitor's reference doubles as an alias, resolving through `src/context/alias.rs::alias_destination` on **both** send seams) and `erlang:garbage_collect/0,1` (`src/native/erts_internal.rs`) — **no BIF may collect**, so a servable call records **one** request through `Runtime::request_gc` and answers the oracle's `true` where the root set is owned.
**`code:*` reads and the code path are the floor over `CodeServer`**, alongside a live `code_server` process: the floor owns the **one** authoritative path store — the readers **and** the `add_patha/1,2`/`add_pathz/1,2`/`add_path/1,2`/`del_path/1` mutators — so **`src/native/code.rs`'s `code:*` behaviour must not change**, and every name-based load ends at `CodeServer::load`'s expected-module-name check (`M1_GAPS.md` *The code store*).
`Runtime::new` starts exactly **three** runtime-owned, never-enqueued `Runnable` processes (the `init` root, the `erl_prim_loader` stand-in and the `file_server_2` service — [`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)), and `call_bif`'s last resort is the **`erlang` namespace**: a **known** unimplemented OTP `erlang` BIF raises `unsupported: erlang:X/Y ...` (exit 3), any other unclaimed name the bare `error::undef`, with `src/error.rs`'s `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` and its drift guard the authority.
## The local-call seam (a module's own non-exported NIF stubs, A.7)
`ExecutionContext::resolve_local_call` (`src/context/execution.rs`) serves **two** built-in key sets — `prim_tty`'s 20 stub keys and `zlib`'s 19 stream keys — from a module-name equality short circuit plus a fixed `(name, arity)` table test, so the predicate allocates nothing and touches neither the registry nor a hash.
`src/context/apply.rs` (`served_local_key` + `apply_non_local_fun`, with `local_fun_target` declining such a target) serves the **record-held** shape of the same two sets: `zlib.erl` stores `fun deflate_nif/4` in a `#zlib_opts{}` record and applies it, so `deflate/3`, `inflate/3` and `safeInflate/2` reach the served key through a local `make_fun3` closure instead of entering its `erlang:nif_error(undef)` body.
The `zlib` stream API is live end to end through the real preloaded `zlib.beam`, oracle-identical at every level 0–9, and `set_controlling_process/2` carries **no** stream-state precondition, so a closed, an ended and a fresh stream all answer `ok` — `tests/zlib_{stream_levels,stream_dict,guards,one_shot}.rs`.
Detail: `src/context/CONTEXT.md` (both indirections), `src/native/CONTEXT.md` (`prim_tty`), `../beam_bifs/src/zlib/CONTEXT.md` (the 19 keys).
## CLI subset (contract A.6 — the *exact* supported surface; anything else is *unsupported*, exit 3)
| Switch | Meaning in `beam_rt` |
|---|---|
| `-version`, `--version` | the version banner (OTP `30.0-rc0` / erts `17.1`), exit 0 |
| `-noshell` | run head-less (M1 default; no interactive shell) |
| `-eval Expr` | evaluate a general Erlang expression and print **nothing**; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` (arguments are **atoms**); result **discarded** |
| `-run Mod Func [Args…]` | as `-s`, but arguments are plain **strings** (char lists) |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (the group in reverse order), `-pz` **tails** it (behind the system `ebin`s), on **every** route |
| `+S N[:N]` | normal scheduler count → `emulator.schedulers` (first number) |
| `-smp enable\|disable\|auto` | scheduler model, recorded as an init argument (M1 runs single-threaded) |
| `+A N` / `+P N` | async-thread pool size → `emulator.extra_emulator_flags` verbatim; max process count → `emulator.max_processes` |
| `+Q N` | max port count → `RuntimeConfig::max_ports`; `system_info(port_limit)` = `min(next_power_of_two(request), 134217727)`, default `65536` |
| `+hms`/`+hmbs`/`+hmax`/`+hmaxk\|el\|ib` | GC heap policy (`beam_gc::HeapPolicy`) rounded through the growth table; visible in `garbage_collection` |
| `-name N` / `-sname N` | node name → `emulator.node_name`; **makes the runtime a distributed node** (A.5) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | **the vertical slice**: run the file as a **scheduled process** via `Runtime::run_scheduled` (the full scheduler, so a blocking driver/port round trip is resumed by a later pass) and **print** the result (`~w~n`); bounded by `RUN_DEADLINE` |
* **Every command-line flag is an init argument** (the source of `init:get_argument/1`) and an unmodeled switch is **data, not a usage error**; the full switch surface, the `run` action's `ARG` token kinds (`M1_GAPS.md` *CLI `run` argument tokens*) and the `ERL_AFLAGS`/`ERL_FLAGS`/`ERL_ZFLAGS` merge are [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md)'s.
### The `-eval` route (`src/eval/`)
`-eval` walks the Erlang **expression** subset `erl_eval`-style — arithmetic/comparison/**bit operators** dispatched to the **`beam_bifs` `erlang` registry**, binary segments accumulating a bit buffer — and anything outside the grammar is a **capability gap** (exit 3), per the grammar, quoted-atom and named-fun-form rules [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) states.
`receive … after T` scans the running process's **real mailbox**, pumps the scheduler non-blockingly (`RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass and spends the remaining window on the runtime's timer heap through `Runtime::wait_for_timer`; a port round's messages are **delivered into that mailbox** before any clause is tried, so the scan stays selective and an unmatched frame stays queued.
A closure `erlang:spawn/1` starts is **compiled** (`src/eval/compile.rs`) from its own recorded source text into a synthetic `beam_rt_eval_fun_<index>` module (`compile:file/2` in process, then `code:load_binary/3`), so the child is an ordinary `ProcessEntry::Export` that really parks on a bare `receive` or a `timer:sleep/1` and is resumed by a later send; the result — a decline included — is cached per closure index on `Runtime::eval_compiled`.
Residuals: a `spawn` made from inside a running engine (`src/native/process.rs::spawn_in_pass`) keeps the tree-walking entry, where a bare `receive` is the typed gap and a parking callee folds into `beam_engine::blocked()`; a **declined** compile keeps that closure's gaps; `receive … after infinity` is a typed gap — [`src/eval/CONTEXT.md`](src/eval/CONTEXT.md) *Known Issues*.
## Exit codes & the `unsupported` signal (the stable external contract)
The CLI exposes **four** exit codes; the differential harness keys off this mapping.
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | genuine runtime error (a load/execute/BIF failure, e.g. a missing `.beam`, an `undef`, BIF `system_limit`) | `beam_rt: <error>` |
| `2` (`EXIT_USAGE`) | malformed invocation / usage error (a missing operand of a *known* switch, a malformed `run` spec, a stray positional argument, a malformed numeric switch value) | `beam_rt: <error>` then [`USAGE`] |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no [`USAGE`]) |
Unsupported is emitted for a `-eval` expression outside the grammar (`src/eval/parse.rs`), a BEAM-engine gap (`unsupported_opcode…`) or a `beam_bifs` gap (`unsupported_bif`), and is **uncatchable** (`src/eval/mod.rs`'s `flow_from_error` turns it into `Flow::Fatal`, like `halt`), so a self-terminating `try … catch` probe cannot swallow it.
The convention is a raise whose **reason atom starts with `unsupported`**; `src/error.rs::unsupported_reason` is the **single** interpreter of it, and classification uses `ExitReason::as_atom`, not `BeamError::as_atom`.
**A raise's reason atom is named in the shared atom table before the raise leaves the call**, or the engine cannot land it in a catch frame: `src/context/calls.rs::name_raise_reason_atom` appends it (append-only, at `PendingInterner`'s predicted index) on the **one** funnel every failed call passes, so a module that never spells the atom still catches `error:R` as the oracle does — the shape a `zlib` guard raises; a capability gap is deliberately **not** interned there, which is what keeps exit 3 uncatchable.
A raise may carry an opaque live reason whose payload is an `Eterm` (`beam_common::Raise`); `src/error.rs::live_reason_term` recovers it and renders it through `format_term_w` — used by `runner/reason.rs::exit_reason`, `cli.rs::run_file` and `context/mod.rs::run_export`, so `beam_rt run <m>.beam m:badkey/0` → `beam_rt: error {badkey,nokey}` (exit 1), never a placeholder.
## `system_info/1` keys (contract A.8)
`InfoValue` is the heap-free source of truth; `Runtime::system_info` materializes it on the scratch heap, and strings are Erlang **strings** (lists of char small-ints) exactly as the oracle returns them.
The surface answers **88** supported keys plus the two tuple keys (`{allocator, A}`, `{wordsize, internal|external}` via `info::tuple_key_value`; an unknown word/tag is `badarg`) and returns `error:badarg` for any other key; the **27** oracle-accepted keys naming facilities this runtime lacks raise the honest `unsupported` gap.
The two sets partition the oracle's 115 accepted names, so a `badarg` where the oracle answers a value can only come from an unclassified key (`tests/system_info_oracle.rs` fails if one appears).
**The per-key catalog — every served key, its own-state source and the `dist`/`dist_ctrl`/`start_time`/`end_time`/`context_reductions` specifics — lives in [`src/info/CONTEXT.md`](src/info/CONTEXT.md).**
## Constraints
* **Errors are return-based, workspace-wide** (`../CONTEXT.md` §3): every fallible API returns `beam_common::Result`, with no crate-local error enum, no `panic!`/`unwrap()` on runtime data and no silent swallowing; CLI diagnostics are `BeamError::Raise(Raise::error(ExitReason::atom(msg)))` instead of stderr writes.
* **`unsafe`-free.** The whole crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Call down, never duplicate.** The `~p` printer is **not** re-implemented — `format.rs` drives the registered `io:format/2` BIF.
* **Frozen term layout** (`../CONTEXT.md` §2): terms are built/inspected only through `beam_term`.
* **Files ~1000 lines**, split by responsibility, `#![warn(missing_docs)]`, every public item documented; oversize files are catalogued in [`src/CONTEXT.md`](src/CONTEXT.md).
* **A live `[BinRef][ErlSubBits]` pair must always have a live payload owner.** A term carrying an off-heap refc payload is reachable either from the building `Machine::refc_binaries()` or from the runtime's escaped-payload store (`Runtime::eval_off_heap`), and the transport copy resolves one of them into its **source** table so the destination **shares** the handle.
  A source table that cannot name the owner makes `beam_message`'s copier **flatten** the binary's `[start,end)` window into a fresh on-heap bitstring — byte-faithful and sound, a refc binary's `base_flags` word carrying its payload pointer — as the **last resort** only (the send path unions three source families, so a resolvable payload takes the SHARE route).

## Known Issues / Intentional M1 gaps
**Per-item detail is in [`M1_GAPS.md`](M1_GAPS.md) (whose intro names the sibling ledgers) under the section named after each bullet, and in the owning child `CONTEXT.md`.** Every gap below is a typed capability gap or a measured own-state difference — never a wrong result.
* **Dispatch and introspection** — a `term_to_binary`/`binary_to_term` round-trip costs the codec's own per-call work, an inbound `DOP_SEND_SENDER*` does not pass the wire sender pid as the mailbox `from`, `get_module_info`'s `exports` order is not the oracle's global table order (an unloaded module is `badarg`), and flag-driven `system_info` literals report their defaults — `M1_GAPS.md` *Dispatch, atoms and module introspection* / *Placeholders where a truthful source exists*.
* **Own-state and `process_info` figures differ by construction, not by bug** — `processes/0`, `ports/0`, `port_count`, the `persistent_term` figures, the `module_loaded/1` boot-set size, `process_info`'s heap/reduction/binary items (`{Ptr,Size,Refc}` from the engine reservoir) and its `garbage_collection` `minor_gcs` (`Collector::minor_since_major`; a fullsweep resets it, the monotone totals being `Runtime::gc_stats().collections`/`beam_gc::AnyCollector::stats()`), with `port_info(Port, monitors)` staying `[]` — `M1_GAPS.md` *Own-state answers* / *`process_info/1,2`*.
* **Printing** — no io server exists (the `io` device floor serves the request wrappers, a live non-stdio device pid is the typed `unsupported`, `io:put_chars/1,2` accepts-and-ignores its device) and a non-byte-aligned `-eval` result cannot be printed — `M1_GAPS.md` *Printing*.
* **Process-control and ETS residuals** — a *named* port monitor, a remote `{Name, Node}` monitor, `spawn_opt`'s `{scheduler,N}`/`{async_dist,B}`, `exit/2,3` against an internal port or a foreign reference, and `ets:setopts/2`'s gift-data aliasing (owner tracking, owner-death reclamation and heir transfer are live) — `M1_GAPS.md` *Process-control families* / *Port monitors (A.4)* / *ETS ownership*.
* **Scheduler and runner** — single-threaded, pre-empting on the reduction budget (a refusing `BudgetProbe::charge`, a pricing `BudgetProbe::spend`); a BIF-and-call-only loop ends no slice of its own on the native tier (a fairness defect) and an allocate-and-abandon loop is collector-bound rather than arena-bound, a flat `heap_size` being a converged capacity — `M1_GAPS.md` *Scheduler / runner*.
* **Timers, execution tier and CLI subset** — `erlang:send_after/3`/`cancel_timer/1` and the `RuntimeHooksBridge`'s timer/link/module keys are native-floor capabilities while `erlang:system_info/2` and every other unserved `RuntimeHooks` key are typed gaps (`M1_GAPS.md` *Timers*); the tier defaults to `JitMode::Auto` (`src/runner/tier.rs`), compiled lazily per function with `BEAM_RT_TIER` over it (*Execution tier*); and `-smp disable` is accepted, `-setcookie` unmodeled, the `-eval`/`-s`/`-run` subsets partial — [`src/cli/CONTEXT.md`](src/cli/CONTEXT.md).
* **Funs and reference aliases** — a compiled module's local fun encodes through the `LocalFunIdentity` seam while an `erl_eval` lambda stays `unsupported: local_fun`; a send to a reference that is **not** a live alias is the typed `badarg` (the C silently drops it) and reference **identity** stays unclosable — `M1_GAPS.md` *Funs* / *Reference aliases*.
* **Distribution (A.5)** — no interactive shell exists, so no Erlang-level distribution subtree runs (`net_sup`/`auth` stay `undefined`), and every inbound family takes the C's route-free receipt, never echoing a `DOP_*` — `M1_GAPS.md` *Distribution and the node (A.5)*.
* **A.3 residuals, each a typed refusal or a deferred answer** — the foreign-thread host's gaps (private atom space, a remote pid destination answering `false`, the queued-then-drained `enif_send`), the load/unload host's `services = None`, the no-op `nif_yield_point` and the unmodelled `upgrade` — `M1_GAPS_A3_NIF.md` *NIF (A.3)*.
* **A.4 residuals, each a typed error** — a busy-port command from the shared `send` route and the inline `!` cannot park (`busy_wait::NO_PUMP_REASON`), a registered **port name**, a **remote** port term and an unreachable remote destination stay typed gaps, and `beam_io`'s accepted-socket pre-buffered read is the nested wait's residual; a driver port drives a real C driver with **35 of the 45** `DriverHost` hooks live and owns no OS child by fact — `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*, [`src/port/exit_status_matrix_tests.rs`](src/port/exit_status_matrix_tests.rs).
* **GC / heap model.** The runtime drives `beam_gc` at four collection points, three of them heap-admission doors, and a failed collection halts that process's collection, never the program; the **boundary door** that makes a BIF-only loop collectable is unreachable on the **default (native-baseline) tier**, a fairness defect as much as a GC one.
  The unscanned-root valve declines only where relocation is unsafe (`context/gc.rs::root_is_unscanned` is a **two-fact** predicate) and the descent's cost is its *invocation count*, `src/context/gc_walk.rs`'s per-walk table already allocation-free — `src/context/gc.rs`/`beam_engine` policy.
  Both off-heap stores are **pruned, never accumulated** — the engine's refc-binary reservoir at every pre-emption (**every gate is a decline, so the residual is a leak, never a dangle**) and `Runtime::eval_off_heap` at two points — `tests/off_heap_reclaim.rs`, `M1_GAPS_GC.md` *GC / heap model*.
  `erlang:memory/0,1` are adopted and `erlang:statistics/1` partly served (its `garbage_collection` key carries the real node-global counters), the per-scheduler/msacc keys and `statistics/0` being typed gaps — *Memory and statistics*.
* **Heap switches** — `beam_gc::HeapPolicy::initial_heap_words` is the single authority for the nursery both collector constructors install, so `+hms`/`+hmbs` and `spawn_opt`'s `{min_heap_size,N}` (floored by `+hms`) size and report as the oracle does (`tests/min_heap_size.rs`), while `+hmax` does **not** bound the grown nursery **chain**; `max_heap_size` is enforced end to end (a breach is the ERTS `=ERROR REPORT====` block plus a `Kill` latch, on the **prospective post-collection capacity**), its residuals the stderr-only report and **7 of the C's 9 fields**, and `+hmax` bounds user processes, never the runtime's own boot processes, so an over-cap `-eval` allocation is `beam_rt: system_limit` (exit 1) — `M1_GAPS_GC.md` *Heap switches*.
* **A.9 self-hosted compile** — the full *chain* runs in ONE invocation over every `lib/*/src/*.erl` (**772 sources / 34 apps**) and **755/772** compile the way the oracle compiles them, byte-identical; there is **no full self-hosted build** — `M1_GAPS.md` *A.9 E0*, [`EPP_SCHEDULED_ROUTE_FINDINGS.md`](EPP_SCHEDULED_ROUTE_FINDINGS.md) (compiler bootstrap: Stage 2).
* **A.7/A.9 boot** — a process entry naming a host-served MFA is dispatched, never entered as that module's code, a booted runtime leaves a live `logger_server` registered as `logger`, and a CPU-starved boot drive trips `DRIVE_DEADLINE` (exit 1) while a scheduled round trip that cannot pump inside a slice folds into `blocked()` (exit 3) — both real exit codes, neither a signal — `M1_GAPS.md` *A.7/A.9 boot* / *Scheduler / runner*, [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md).
* **The BIF-result copy-out is architectural** — a registered-BIF result is re-homed and the pool rewound (**load-bearing**: the copy makes it collectable), the learned `copy_out_hint` growing the nursery *before* copying (**0.605×** on `copy_bound/ets_copy`); `erlang:system_info/1` hands its value off the reset-per-call scratch region, so a retained value is sound (`tests/system_info_retained.rs`) — `M1_GAPS_GC.md` *The BIF-result copy-out* / *The scratch-heap lifetime and the dangling-boxed-argument class*.
* **Every `foreign` case's per-call cost is flat in N** — the machine's reservoir is never mirrored onto the process's never-compacted off-heap slots — [`PERF.md`](PERF.md) *off-heap mirror*.
## Notes for Agents
* **Read `../CONTEXT.md` and the two `../../ERTS_RUST_REWRITE_*.md` design docs before changing the glue**; this crate is where the Stage-1 engine meets the Stage-5 core.
* **Run the crate gate** `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails — the workspace manifest is `erts_rust/Cargo.toml`; the sandbox `$HOME` is read-only, hence the wrapper) and the compatibility gate `erts_rust/tools/differential/gate.sh`; [`TEST_STRATEGY.md`](TEST_STRATEGY.md) holds the commands and the gate-equivalent sweep.
* **Test hygiene** — scratch temp dirs come from `crate::context::test_support::scratch_dir(label)` (unique per call, self-removing; a hand-rolled `temp_dir().join(format!("…_{pid}"))` collides with a concurrent test *process*); `code:ensure_modules_loaded/1` is **parallel** in OTP, so its failure pairs are asserted as a **set**; `tests/fixtures/` must not be passed to the oracle as a single `-pa` (its `lists.beam` shadows stdlib); and every oracle probe must terminate (`-s init stop` plus `tests/support/mod.rs`'s bounded poll/kill).
* **Every action other than `-version` boots first and then drives the boot script** (`Runtime::boot_if_needed` → `boot::load_preloaded`, then the resolved script), the system code path coming from the native filesystem probe — [`src/boot/CONTEXT.md`](src/boot/CONTEXT.md) *The system code path resolution*.
* **`beam_rt: error undef` is overloaded — four distinct causes**: (a) `<module>.beam` on no code-path directory, (b) the export missing from the loaded module, (c) an **arity mismatch** in `run_export`, (d) the library body being the stub `erlang:nif_error(undef)`, which dominates — `code`/`erl_ddll`/`erts_debug`/`erts_internal`/`atomics`/`ets`/`re`/`os`/`net_kernel`/`prim_file`/`error_logger` ship every non-Erlang function as a stub, so a key neither the floor nor the registry serves **raises** (exit 1) for *every* argument and registering it only changes exit 1 → 3.
* **Probing dispatch empirically.** `-eval` prints nothing on success (exit 0) and `beam_rt: error <Reason>` (1) / `beam_rt: unsupported: <Reason>` (3) otherwise, so `beam_rt -eval '<M>:<F>(<args>)'` plus the exit code is the cheapest way to ask what the NIF → floor → registry → module-load order does for a key today.
* **Dispatch cost is a first-class concern.** `call_registered` runs per call, so a handle built there must be gated by a `uses_*` predicate and every per-call prologue input belongs in the 8-slot dispatch memo; measure with `examples/perf_call.rs` (`examples/perf_bif.rs`'s `pc:*` inlines to a `gc_bif` and **cannot** measure registry dispatch) — [`PERF_DISPATCH.md`](PERF_DISPATCH.md) *DISPATCH-CUT* / *COPY-OUT-CUT* / *WALK-CUT*.
* **File I/O is a `std::fs`/`std::env` native floor, not `beam_io`**, over the `Runtime`-owned `open_files` map (keyed by `Runtime::refs_mut()`, never a `thread_local!`) — [`src/native/CONTEXT.md`](src/native/CONTEXT.md), [`src/native/file_server/CONTEXT.md`](src/native/file_server/CONTEXT.md).
* **Whole-process startup is ~0.34 s (release), CPU-bound, issuing 0 `clock_nanosleep`**, the boot path's one live-but-idle port costing the drive no wall time — [`PERF.md`](PERF.md) *The boot path's one live-but-idle port, and the poll budget*.
## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`, and a bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass`), so a synchronous two-process ping-pong stays in **one** `run_ready` call; the granularity is `RUN_STEP_SLICES = 1000` (`src/runtime/scheduler.rs`) with `DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000` (`beam_process`), so per-pass costs amortize ×1000 while **per-slice** costs dominate a long run.
The measured per-pass / per-slice / per-round inventory (the fresh `ProcessTable`, the progress-aware pass wait, the per-slice machine/context/timer churn, the `crate::hasher` maps, the occupancy short-circuit, each with its pinning test) is **[`src/runtime/CONTEXT.md`](src/runtime/CONTEXT.md)** *The scheduled path's fixed costs*, with the per-workload cost in [`src/runner/MEASURED.md`](src/runner/MEASURED.md).
