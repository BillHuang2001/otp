# `beam_rt` — Observability & Performance Detail

Companion to [`CONTEXT.md`](CONTEXT.md). It holds the current-state detail for the observability
modules (`src/trace.rs`, `src/seq_trace.rs`, `src/crash_dump.rs`, `src/perf_map.rs`), the
execution-trace seam, and the per-call performance-measurement harness — split out so `CONTEXT.md`
stays under the Context Tree per-file read limit. It is documentation of the present state, not a
change log.

## Observability modules (contract A.8)
* **`trace.rs`** — ordinary process tracing: `TraceFlags`/`TraceEntry`/`TraceState` (the per-pid flag + tracer table) and the `PatternTable` of `{M,F,A}` `trace_pattern` entries; the BIF half is `erlang:trace_info/2` (`flags`/`tracer`/`match_spec`/`traced`/`all`), `trace_delivered/1`, `erts_internal:trace/3` and `trace_pattern/3`. `RuntimeContext::emit_trace_event` is the single emitter (tracer lookup, `silent` flag, the discard rule, the `trace_ts` flavour, delivery through the internal bypass).
* **`seq_trace.rs`** — sequential tracing: the per-process `Token` (`{Flags, Label, Serial, From, Lastcnt}`), the node-global serial clock, the `FLAGS`/`flag_bit`/`decode_flags`/`encode_flags` bitmask, the four `erlang:seq_trace*/seq_trace_print*` BIFs and the `reset_seq_trace` arm of `system_flag/2`; `seq_trace_message`/`seq_trace_send_message` build the `{seq_trace, Label, …}` events (no system tracer is ever configured, so `SeqTrace::tracer` stays `None`).
* **`crash_dump.rs`** — the ERTS-format crash-dump writer behind `erlang:halt`: `snapshot(&Runtime, slogan, seconds) -> DumpInput` + `write_dump(path, dump)` reproduce the oracle's section vocabulary and order (`=erl_crash_dump:0.5` … `=end`); `crash_dump_path(&ErlEnv)` reads `ERL_CRASH_DUMP`/`ERL_CRASH_DUMP_SECONDS`. Two safe-Rust substitutions: `=proc_stack` renders the engine X registers, `=proc_heap` the reachable boxed terms.
* **`perf_map.rs`** — the `+JPperf`-gated JIT symbol map: `PerfFlag` parses the C's accumulating value grammar, `PerfMapConfig` honours `+JPperfdirectory`/`ERL_SYM_MAP_FILE` (default `/tmp`), `PerfMap::new` creates `perf-<pid>.map`/`jit-<pid>.dump` at construction. **No range is ever fabricated** — every line is a real cached range: when `+JPperf` is enabled the runner feeds `beam_engine::jit::cache::baseline_code_map` for the process's module into `PerfMap::record` (the single hook); with `+JPperf` off nothing is recorded and the map is well-formed but empty. A map/compile error is routed to `PerfMap::note_diagnostic`, never into the run.

**Emitted vs deferred trace events.** *Emitted*: `send`, `'receive'` (on **enqueue**, gated on the receiver's flag), the sequential-trace `{seq_trace, Label, {send, …}}` event (the sender's token carries `FLAG_SEND`), and the whole **execution family** — `call`, `return_from`, `return_to` — produced by `src/context/trace.rs`. *Deferred* (unemitted rather than an unpinned shape): `spawn`, `exit`, `register`/`unregister`, `in`/`out`; `PatternTable::matches` is the predicate such a hook calls.

## The execution-trace seam (`src/context/trace.rs`, contract A.8)
`beam_engine` already reports every call/return it executes — `ExecutionContext::trace_enabled` (latched once per run into `Machine::trace_on`) then `ExecutionContext::trace_event(TraceEvent::{Call,ReturnFrom,ReturnTo})` — and this crate is its one consumer: the two trait methods live in `src/context/mod.rs` (Rust allows one impl block per trait per type) and delegate to `RuntimeContext::{execution_trace_enabled, execution_trace_event}` in `src/context/trace.rs`. That module decides *matching* (the installed `erlang:trace_pattern/3` table) and builds + delivers each event through the single emit point `emit_trace_event`. Semantics are the oracle's: the process `call` flag gates the whole family (`[return_to]` alone reports nothing); `local`/`global` are mutually exclusive pattern flags and a `[local]` pattern fires for every entry (a `[global]` one only for an external dispatch); `return_from` needs a `{return_trace}`/`{exception_trace}` match-spec **action** in the match function's body (`MatchAll`/a bare atom arm nothing); `return_to` is armed at the **traced local call** and reported when the callee returns, naming the caller (which needs no pattern of its own — the arm is threaded between the engine's paired `ReturnFrom`/`ReturnTo` through a `thread_local!` slot, legitimate because `Runtime` is `!Send`); the `arity` flag swaps the `call` event's third element from the argument list to the bare arity; a pattern-level `silent` suppresses the event on top of the process `silent` flag. The seam is live on **both** execution paths: the single-pass `Machine::run*`/`Runtime::run_function`/`run_module` entry *and* a **scheduled** process, because `src/runner/budget.rs`'s `BudgetContext` forwards `trace_enabled`/`trace_event` to the slice's real `RuntimeContext` like every other method. A scheduled process therefore reports its `call`/`return_from`/`return_to` events for every call/return instruction its tier helper-executes (its first entry runs on the baseline tier; a resumed `receive` continues through the interpreter's dispatch loop, where the arms live) — an instruction a native tier **inlines** (a linked local tail call) is not reported, the documented tier limitation, never a wrong result. Both paths are covered end to end by `tests/trace_call.rs`.

**Documented divergence.** `TraceEvent::Call` does not carry the call kind, so "an external dispatch" is approximated as `callee_module != current_module` (`current_module` is the module whose code is executing; `None`, the `-eval` evaluator, counts as "differs"). A `[global]`-only pattern matching a call written `?MODULE:F(...)` — a `call_ext` whose callee module *is* the current module — is therefore **under-reported**; the whole `[local]` surface, every cross-module `[global]` entry and the no-pattern case agree. Shapes and semantics are cross-checked against the live OTP 29.1.1/erts-17.1 oracle (the `silent` pattern flag is OTP-30-only and not locally probe-able).

**The `tracer == tracee` discard rule.** `emit_trace_event` drops an event whose tracer **is** the tracee (mirroring `erl_tracer_nif.c:143-146`); a `silent` tracee and a tracer no longer in the process table are dropped the same way, never as an error.

## Performance measurement

### Per-call overhead regression harness
**`examples/perf_bif.rs`** (run `erts_rust/scripts/cargo.sh run --manifest-path erts_rust/Cargo.toml --release -p beam_rt --example perf_bif`): compiles `pc:add/2`/`pc:loop/2` with `erlc` and reports the marginal ns/call as a **two-point slope** `(t(N2)-t(N1))/(N2-N1)` (default N1=16M/N2=64M, best-of-5 + a warm-up per point), cancelling process start-up exactly; a non-positive slope auto-scales then fails loudly rather than reporting noise. `N-1`/`N+1` are `gc_bif` **instructions** the baseline tier inlines natively, so the figure is the native-loop cost (~2.5 ns/iter), NOT a BIF round trip (a non-inlinable BIF like `trunc/1` is ~116 ns/iter). `$PERF_BASELINE_ADD_NS`/`$PERF_BASELINE_LOOP_NS` add a delta/speedup column.

### Dispatch cost (registered-BIF path)
The registered-BIF path (`call_registered`) runs per call, so any handle built there must be gated by a `uses_*` predicate — a snapshot that walks the code server / process table / ETS registry, or clones the caller module, is a per-call cost. Measured: ~116 ns/call for a non-inlinable BIF (e.g. `trunc/1`), against ~10.6 µs before the `RuntimeMemory`/`FunIdentityBridge` handles were gated; the residual is dominated by `beam_bifs`'s per-lookup owned-`String` registry keys (see the `beam_bifs` Handoff in `CONTEXT.md`). An inlinable `gc_bif` arithmetic op in a tail loop is natively compiled at ~2.5 ns/iteration by the baseline tier. Measure with `examples/perf_bif.rs` before and after any change to the dispatch prologue.
