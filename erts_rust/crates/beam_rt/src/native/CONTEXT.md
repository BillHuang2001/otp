# `beam_rt/src/native/` — the runtime-native BIF floor
## Intent
The BIFs that are really **runtime** operations, served *before* the `beam_bifs` registry (which owns only the static `bif.tab` surface — term ops, `lists`/`maps`/`binary`, `io:format`, `ets`): the process/port tables, the code server, the atom table, the application view, the parsed command line, the timer heap and the module container loader.
`init:*`/`code:*`/`application:*`/`erts_internal:*` are **preloaded-module surface** (contract A.7) whose real `.beam` bodies want process/message machinery this runtime does not run.
`RuntimeContext::try_native` is a *fall-through* layer: every entry returns `Option<Result<Eterm>>`, `None` meaning "not a native BIF", after which `call_bif` (`../context/mod.rs`) tries the registry (or loads the module) — nothing here duplicates a registry BIF, and no unclaimed call is answered with a fabricated value.
**This file is the dispatch index**: the implemented surface, the not-implemented index and the drift guards; per-family mechanics live in the child nodes (`memory/`, `process/`, `erts_internal/`, `file_server/`, `net/`, `code/`).
## API Surface
### The dispatch (source of truth: `../native.rs`)
`RuntimeContext::try_native(module, function, arity, args) -> Option<Result<Eterm>>` — **one match arm per native call**, plus one arm for the whole `erts_internal` namespace (`erts_internal_call`), one for `prim_file` (`prim_file_call`) and one for `erl_ddll` (`ddll_call`).
`call_bif`'s order: **loaded NIF → floor (`try_native`) → `beam_bifs` registry → on-demand external-module load**; a key in the `erlang` namespace none of those claims is the capability gap (`unsupported: …`, CLI exit 3) or the bare `error:undef` (`../error.rs`).
`FLOOR_MODULES: [&str; 14]` = `application`, `code`, `erl_ddll`, `erl_distribution`, `erl_prim_loader`, `erlang`, `erts_internal`, `init`, `io`, `net_adm`, `net_kernel`, `os`, `prim_file`, `prim_tty` — each a module the code server can **also** load as a `.beam`, so the list gates `RuntimeContext::resolve_external_call`, which must answer `Ok(None)` for all of them (entering the body would run it *instead of* the host).
It does **not** gate `call_bif`'s dispatch: a `beam_bifs` registry key in a floor namespace the floor has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s, the floor owns only `os:cmd/1`; `erlang:display/1` is `beam_bifs`'s `%T` renderer).
Membership is the **namespace** set; `floor_keys` decides whether a whole namespace is refused or only the keys it enumerates (`io`/`prim_tty`/`application`/`code`/`init`/`erl_distribution` key-granular, every other floor namespace module-wide).
Drift guards: `native.rs::tests::every_floor_module_is_a_real_try_native_arm` (the namespace set) plus the **table-driven** `every_floor_arm_key_is_refused_and_every_key_granular_list_is_exact` (every `try_native` arm must satisfy `floor_shadows`, every `floor_keys` list must enumerate **exactly** its namespace's parsed arm keys, an unlisted key must stay enterable, and every namespace must be classified `KEY_GRANULAR_NAMESPACES`/`MODULE_WIDE_NAMESPACES` — a new arm or namespace fails loudly), and `../error.rs`'s `never_shadow_the_registry` pair.
### The preloaded-module surfaces (contract A.7)
Every entry reads the runtime's own state; the crate-level A.9 view is `../CONTEXT.md`'s, and each module's per-entry ground truth is its own rustdoc.
`init.rs`: `fetch_loaded/0` ⇒ `[]` (the oracle's post-boot value); `get_plain_arguments/0` ⇒ the strings of `RuntimeConfig::plain_args`, which the CLI splits out of `-extra`/`--` per merge entity and which is never an init argument, so `init:get_arguments/0` carries no entry for `extra` or the plain values; `init:stop/1`, `init:boot/1` and the `root`/`home`/`progname`/`bindir` automatic flags answer as the oracle does.
**`init:script_id/0`** reports `{Name, Release}` with the **release always this runtime's own** (`beam_common::otp_version().major`, the source `erlang:system_info(otp_release)` answers from) and the **name the loaded boot script's own header name** (`RELEASE_NAME` = `"Erlang/OTP"` as the empty-name fallback) — never the script's `Vsn`, which would name the consumed installation's release and make `init:script_id() =:= {"Erlang/OTP", otp_release}` false off the own-tree routes; no loaded script ⇒ the typed `unsupported: init:script_id/0 (no boot script has been loaded)` gap.
`code.rs` + `code/path.rs` — the `code:*` path/load readers and the path mutators over the ONE authoritative `CodeServer` store: [`code/CONTEXT.md`](code/CONTEXT.md).
`loader.rs` — the `erl_prim_loader` floor: `get_loader_config/0` ⇒ the emulator's default `{efile,undefined}` config (so `name_split/2` makes every client-side operation a plain `prim_file` delegation), `set_loader_config/1`/`set_path/1` accepted and discarded, `get_path/0` ⇒ this runtime's real code path, and the `list_dir`/`read_file`/`*_file_info`/`get_cwd` entries ⇒ the `prim_file` floor; the archive half stays unclaimed (module rustdoc).
`application.rs` — a minimal native `.app` view (`get_env/1,2,3`, `get_all_env/1`, `get_all_key/1`, `get_key/1,2`, `get_application/0,1`, `loaded_applications/0`, `which_applications/0`): `get_application/0` is always `undefined`, and `app_env_props` reads the `.app` resource's `env` list **verbatim**, so kernel's start-time `logger`/`connect_all` injections are absent.

### `erlang:garbage_collect/0,1,2` (A.7) — the on-demand collection
Bodies in `erts_internal.rs`, arms in `../native.rs::try_native`; `erlang` is a floor namespace, so its `.beam` wrappers are un-enterable and the floor owns all three arities (per-argument probe table in `erts_internal.rs`'s rustdoc, argument contract in [`process/CONTEXT.md`](process/CONTEXT.md)).
**No BIF may collect** — the root set a collection relocates is the **executing machine's** `x[0..live)` plus its Erlang stack, which a BIF running *inside* the engine does not own — so a servable call records a **request** via `Runtime::request_gc` and answers the oracle's `true`, served only where that root set is owned (the engine's heap-admission point `../../context/gc.rs::ensure_heap`, which bypasses only the occupancy test and never the safety valves, and the runner's park arms `../../runner/run.rs` → `Runtime::serve_gc_request`); a request is recorded **only** for a **scheduled slice**, so `Runtime::gc_stats().collections` moves only when a collection really ran.
The async form's follow-up `{garbage_collect, ReqId, GCResult}` is recorded by `Runtime::request_gc_async` and delivered into the requester's mailbox at a **scheduler-pass boundary** (`../../runtime/gc.rs::deliver_gc_completions`).
### `erlang:spawn_monitor/1,2,3,4` — an `erlang.erl` wrapper, not a `bif.tab` BIF
The four arities are `erlang:spawn_opt(…, [monitor])` behind `erlang.erl`'s own guards, so no registry entry — and nothing in the known-unimplemented list — claims them and the floor owns the whole family: a guard violation is the oracle's `badarg`, the `Node` forms on another node are the typed distributed-spawn gap, and the monitor is installed before the child's first schedulable moment (`../tests/spawn_monitor.rs`; detail [`process/CONTEXT.md`](process/CONTEXT.md)).
### `erlang:process_info/1,2` (A.8) — `memory/` (+ `../tests/process_info_binary.rs`)
A **runtime** operation served before the registry, read out of this runtime's own `beam_process` table.

The item catalog, the per-item own-state sources, the honest `unsupported` set and the divergences are [`memory/CONTEXT.md`](memory/CONTEXT.md)'s, and `memory/mod.rs`'s module docs are the authoritative per-item table; `process_info(Pid, garbage_collection)` is **never** compared against a live oracle.

### `prim_file:*` (A.7) — `prim.rs` (path half) + `prim_file.rs` (fd half)
`RuntimeContext::prim_file_call(function, arity, args) -> Option<Result<Eterm>>` over the host file system (`std::fs`/`std::env`); `prim_file` is a **preloaded** module whose BIFs are the C `prim_file_nif.c` NIFs, and the floor claims only the subset whose whole observable contract is pinned byte-for-byte against the oracle — everything else returns `None`, falling through to the preloaded `.beam` (an honest `erlang:nif_error(undef)`).
**Served — 35 of the 41 `(name, arity)` keys the dispatch arms** (per-entry ground truth: each module's rustdoc): the **path half** (`prim.rs`) `get_cwd/0,1`, `read_file/1`, `delete/1`, `rename/2`, `make_dir/1`, `del_dir/1`, `read_link/1`, `make_link/2`, `make_symlink/2`, `altname/1`, `list_dir/1`, `list_dir_all/1`, `read_file_info/1,2`, `read_link_info/1,2`; the **fd half** (`prim_file.rs`) `open/2`, `read/2`, `write/2`, `close/1`, `position/2`, `pread/2,3`, `pwrite/2,3`, `truncate/1`, `sync/1`, `datasync/1`, `write_file/2`, `set_cwd/1`, `ipread_s32bu_p32bu/3`, `get_handle/1`, `read_handle_info/1,2`.
**Invariants.** Every path-only entry is a direct NIF call wrapped by `try … catch error:badarg -> {error,badarg}` in `prim_file.erl`, so a **bad path is always the value `{error,badarg}`, never a raise**; the C's errno REMAPs are reproduced explicitly (`unlink` `EISDIR`→`EPERM`; `rename`/`rmdir` `ENOTEMPTY`→`EEXIST`, and the process's own non-empty cwd → `EINVAL`); `encode_path/1` takes a **binary** (bytes verbatim, a NUL ⇒ badarg) or an **iolist of code points** flattened iteratively with an explicit stack and encoded UTF-8, so nesting depth cannot exhaust the Rust stack.
`open/2` hands out the oracle's `{file_descriptor, prim_file, Data}` map shape, follows the C's flag derivation (`read`→`O_RDONLY`; `write` alone→`O_TRUNC|O_WRONLY|O_CREAT`; read+write→`O_RDWR|O_CREAT`; `append`→`O_APPEND` and no `O_TRUNC`), silently ignores every unmodelled option exactly as the C does, and **serves** a `directory`-mode open; its descriptor build interns every name it needs **before** taking the shared atom table's handle (an intern under a live handle deep-clones the whole table — [`../../CONTEXT.md`](../../CONTEXT.md) *The one process-lifetime `Rc<AtomTable>` lease*), and that order is part of the observable contract (the descriptor map's key order).
**Typed gaps** (explicit `unsupported`, never a silent wrong value): `write_file_info/2,3`, `advise/4`, `allocate/3`, `read_line/1`, `file_desc_to_ref/2`.
**Deliberately unclaimed** because the fall-through already reaches the oracle's own answer (an arm would *create* a divergence): `copy/2`, `write_file/3`, `delayed_close/1`, `sendfile/8`, `internal_get_nif_resource/1`; `copy/3` works (pure Erlang).
**Divergences:** `read/2` does **not** reproduce read-ahead; `get_handle/1`'s fd *number* is this runtime's own; a path built from a file's raw bytes goes through `beam_codec::term::make_binary` on the pointer-stable `eval_heap` (no 64-byte limit).
### `prim_tty:*` (A.7) — the built-in NIF library — `prim_tty.rs`
ERTS serves `prim_tty` from its **static NIF table** (`erts/emulator/nifs/common/prim_tty_nif.c`, `is_static_nif_module`), so `erlang:load_nif("prim_tty", …)` never `dlopen`s a shared object; `prim_tty.rs::is_builtin_library` is the ONE resolution source `NifBridge`'s `NifLoader::load_nif` consults **before** touching the filesystem (`../context/bridges.rs`), so `prim_tty:load/0` answers `ok` and nothing enters the NIF registry (`NifRegistry::is_loaded("prim_tty")` stays `false`, keeping the module's Erlang wrappers enterable in-machine).
**Two routes, one implementation.** `prim_tty.rs::NIF_KEYS` (20 keys) is the whole `-nifs` surface of `lib/kernel/src/prim_tty.erl`: the **exported** stubs (`isatty/1`, `write_nif/2`, …) travel `floor_keys("prim_tty")` → `call_bif` → `try_native` → `RuntimeContext::prim_tty_call`, while the **non-exported LOCAL stubs** (`tty_create/1`, `tty_init/2`, … — the compiler emits a LOCAL `call`) reach the SAME implementation through `ExecutionContext::resolve_local_call` (`../context/execution.rs` → `prim_tty::serves_local_call`).
**Served faithfully** (per-entry ground truth: the module rustdoc): `isatty/1` (a real `IsTerminal` probe), `tty_create/1` (an opaque round-trippable handle), `tty_init/2`, `tty_encoding/1` ⇒ `utf8`, `setlocale/1` ⇒ `primitive`, `sizeof_wchar/0` ⇒ `4`, `tty_window_size/1`, `tty_is_open/2`, `write_nif/2`/`read_nif/3`, `tty_select/2` (the C's `enif_get_resource` check **before** anything is armed, then a one-shot read interest on the C's hardcoded fd `0` through the port layer's one select store — [`../port/select.rs`](../port/select.rs) — answering `ok`), and the no-`HAVE_TERMCAP` family (`setupterm_nif/0`, `tinfo_nif/0`, `tiget{num,flag,str}_nif/1`, `tputs_nif/2`) ⇒ `{error,enotsup}`.
**Typed capability gaps** (never a fabricated value): `isprint/1`, `wcwidth/1`, `wcswidth/1` (libc's width tables have no faithful safe-std equivalent); the **terminal-present** arm of `tty_window_size/1` (`TIOCGWINSZ` unavailable in safe std) and the **raw-mode** arm of `tty_init/2` (no safe-std termios).
**Fidelity deviation, honestly recorded — not oracle parity:** the oracle is built **with** termcap (a full terminfo map), where this runtime answers the C's no-`HAVE_TERMCAP` arm — ncurses terminfo state is not reproducible from safe Rust, and that arm is non-raising, which `prim_tty:init/1`'s `setupterm() =:= ok` check requires.
### `erl_ddll:*` — one loaded-driver list (A.4) — `ddll.rs`
`RuntimeContext::ddll_call(function, arity, args) -> Option<Result<Eterm>>`; `beam_bifs` registers six `erl_ddll` keys over its **own** loaded-driver registry, which this crate's port machinery never reads, so the floor serves the four list/load/unload/report keys from the **one** name-keyed registry the ports really use (`../port/driver.rs`'s `LOADED_DRIVERS`) — `erl_ddll:loaded_drivers/0` **is** the list `open_port({spawn_driver, Name})` resolves a name against.
Dispatched before `call_registered`, those four keys **shadow** `beam_bifs`'s same-named registry keys; `monitor/2`, `demonitor/1` and `format_error/1` deliberately return `None` and stay with `beam_bifs` — claiming them would duplicate its `errint`→text table and mint monitor references against a driver list the monitor machinery does not read.
Oracle answers: `loaded_drivers/0` ⇒ `{ok,[Name,…]}` (each a charlist: the three **statically linked** built-ins first — `tcp_inet`, `udp_inet`, `ram_file_drv` — then the dynamically loaded names in load order); `try_load/3` ⇒ `{ok,loaded}`/`{ok,already_loaded}`/`{error,{open_error,-10}}`/`{error,Reason}`; `try_unload/2` ⇒ `ok`/`{error,not_loaded}`; `info/2` ⇒ the item value of a **known** name, `badarg` otherwise; a **statically linked** name answers `{error,linked_in_driver}` to both load and unload, and its `info/2` takes the C's `handle == NULL` item branch; an `errcode_tab` reason becomes the **bare reason atom** and a failed `dlopen` `{open_error,-10}` (mirroring `beam_bifs`'s `load_error_tuple`); a malformed argument or option is `badarg`, never a fabricated result.
**The three statically linked built-ins are one derived view** — `port::driver::static_drivers()`, the C `driver_list` entries with `handle == NULL`, whose membership is `beam_io::STATIC_SPAWN_DRIVERS` (also the gate `open_port({spawn_driver, Name})` resolves against) and whose *arrangement* is `DRIVER_TAB_ORDER`.
**Divergences** (own-state, never a fabricated value): `open_port({spawn_driver, Name})` auto-`dlopen`s an unloaded name where the oracle answers `badarg`; `try_unload/2` is an immediate `ok` rather than the C's pending-state machine; opening a `try_load`ed driver re-`dlopen`s the object, so the entry's `init` runs once per open rather than once per load; a loaded driver's monitor subscription is not delivered.
### `file_server_2` — the native file service (A.9)
`file_server.rs` + `file_server/` own the runtime-native **file service**: the `file_server_2` service process (never enqueued, drained by the scheduler-pass step `Runtime::service_file_requests`), its per-`open` native io-devices, and the `gen_server`/`file`/`io` request/reply wire.
`Runtime::new` consults `RuntimeConfig::drives_a_boot_script()`: whenever it holds (every CLI action but `-version`, plus an explicit `-boot FILE`) the service is spawned **unregistered** (`FileServices::start_unclaimed`), because that route's booted `kernel_sup` starts OTP's own `file_server_2` child and owns the name; a runtime driving no boot script registers it under the atom `file_server_2` (`FileServices::start`).
**The process model, the scheduler-pass step, the served-request surface (`{write_file,…}`/write-mode `{open,…}`/`{get_until,…}`/`{get_line,…}`, the `getopts`/`setopts` read-mode surface and the `{read_handle_info, Opts}` reader), the wire tables and the tests are [`file_server/CONTEXT.md`](file_server/CONTEXT.md)'s.**
### The runtime-native `net_kernel` service (A.5) — `net_kernel.rs`
`net_kernel.rs` owns the runtime-native **`net_kernel` service**: a `beam_process::Process` spawned `Runnable`, registered as `net_kernel` and never enqueued, drained by the scheduler-pass step `Runtime::service_net_kernel` right after `service_file_requests`.
**It exists only on a distributed node** — `Runtime::new` starts it when its `dist` half is `Some` (a `-name`/`-sname` config) and leaves it `None` otherwise, so a non-distributed runtime registers no name and spawns no process.
**Dispatch table (one entry):** `{'$gen_call', From, {is_auth, _Node}}` is answered the atom **`yes`** (`net_kernel.erl` answers unconditionally — the request carries the *caller's* node, so a comparison would answer `no`); a malformed `{is_auth}` (arity ≠ 2) and the bare atom are answered `no`.
**Every other request is the typed `unsupported: net_kernel: <request> is not served` gap**, never a silent drop — a dropped `gen:call` parks its caller in an untimed `receive`, which is the defect this service removes; and that gap is **fatal to the whole node**, not to one caller (`service_net_kernel` returns the `Err` and the pass breaks on it), unlike a malformed *transport* frame, which only retires that one link.
**The reply reproduces `gen:reply/2`'s three clauses:** `{To,[alias|Ref]}`/`{To,[[alias|Ref]|_]}` send `{Tag, Reply}` to `Ref` through `Runtime::dist_send_alias` (the outbound `DOP_ALIAS_SEND`), the tag echoed unchanged; any other `{To, Tag}` delivers `{Tag, Reply}` to `To` — a local pid through `RuntimeContext::deliver_in_table` (a dead caller's `TermNotFound` dropped, as `gen:reply/2`'s `catch` does), a remote pid through `Runtime::dist_send_message_pid`; a reply tag naming a reference on THIS node takes `DistLinks::route_alias`'s **external**-destination typed error rather than a local delivery.
### The `io` device floor (`io.rs`) — the request wrappers, served natively
`io:put_chars/1,2`, `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2` and `io:format/3` are `io.erl` wrappers over `o_request/2` whose device is the caller's `group_leader()` — here the runtime's root process, which runs no io server — so the floor serves them itself, answering the device question through `RuntimeContext::io_device`/`io_stream` and rendering through the **registered** `io_lib:format/2`, so the request never leaves the runtime (`../M1_GAPS.md` *Printing*).
The device classes (shared by **every** device-taking arm, `io:put_chars/1,2` included): omitted / `standard_io` / `user` / the caller's **group-leader pid** ⇒ the process's output stream (**explicitly** `Device::Stream` — the omitted case is the documented substitution that keeps the installed compiler's `io:fwrite/2` diagnostics printing); the caller **itself** (`self()`, classified **first**) or an atom **registered to the caller** ⇒ `error:calling_self`; `standard_error` (or its registered pid) ⇒ **fd 2**; another **live** device pid ⇒ the typed `unsupported` (a BIF may not block on the round trip); an **unregistered** atom ⇒ `error:badarg`; a non-atom/non-pid ⇒ the bare `function_clause`; the device is resolved **before** the payload is read.
That order is what keeps `erlc`'s diagnostics on stderr: `erl_compile.erl`'s `compile_cmdline1/0` sets `group_leader(whereis(standard_error), self())` in its worker and `compile.erl` prints with the omitted device, so a warning and a compile error both land on fd 2 with stdout empty, byte-identical to the system `erlc`.
**`io:format/3` / `io:fwrite/3` are `(Device, Format, Args)`, never options-taking**: OTP has no such arity, so `io:format("~p~n",[[1,2]],[])` passes the format string as the device and is the bare `function_clause` on the oracle and here; the `{chars_limit,_}` options belong to `io_lib:format/3`.
Pinned end to end against the live oracle by `../../tests/io_device.rs` (the device differential, the arity matrix, the `calling_self` entry-point matrix) and `../../tests/io_diagnostic_unmask.rs`, plus `io.rs`'s colocated fd-2 probe whose child half runs in its own OS process.
## Constraints
- **`#![deny(unsafe_code)]`** — the crate-wide rule covers this whole floor; terms are built and read only through `beam_engine::terms`, `beam_codec::term`, `beam_loader::container` and `beam_term`, and the parent's `render` drives the registered `io:format/2` printer rather than a private one.
- **Return-based errors** (`../CONTEXT.md` §3): `Option<Result<Eterm>>`, never a crate-local error enum, never `panic!`/`unwrap()` on runtime data, never a silent swallow; a "value atom" answer the C *returns* (`badarg`, `big`, `no_integer`, `not_a_list`) is `Ok(atom)`.
- **Consulted before the registry.** A native entry must never shadow or duplicate a `beam_bifs` BIF, with one deliberate exception: the four `erl_ddll` list/load/unload/report keys shadow `beam_bifs`'s same-named registry keys, so the driver list `open_port({spawn_driver, Name})` reads and the one `erl_ddll` reports stay a single view. The `erlang`-namespace fallback classifies a known-unimplemented name as the capability gap (`unsupported: …`, CLI exit 3) and anything else as the bare `error:undef`.
- **The floor's `CodeServer` owns the ONE authoritative code path**, so `code.rs`'s behaviour must not change: a live `code_server` process does run on the boot-driven routes but keeps a second path store, so the floor serves the path readers **and** the `code/path.rs` mutators out of `CodeServer` (the store this runtime really searches), and only the un-migrated `code.erl` mutators edit that second store ([`code/CONTEXT.md`](code/CONTEXT.md)).
- **The child nodes own their families' detail** — `memory/`, `process/`, `erts_internal/`, `file_server/`, `net/`, `code/` — and the dispatch table stays `../native.rs`'s alone: a child doc may name its own arms but never a second dispatch list.
- **Files ~1000 lines of production code**, every public item documented; the pre-existing oversize files (`application.rs`, `process.rs`, `prim.rs`, `prim_file.rs`, `erts_internal.rs`) are single-responsibility and kept whole.
## Term lifetime and rooting (the four workspace rules, and this floor's roster)
A raw `Eterm` in a long-lived slot **roots nothing**: any term that can outlive one instruction — a raise reason, a pending reply, a parked value, a cache entry — must be copied onto a scanned heap or explicitly stabilized before its owner's heap can relocate.
A pointer-stable, never-scanned store (the arena, `alloc_words`) is the **wrong home** for a container whose children live on a scanned young heap: the copier gives such a container `Target::Foreign` and never descends, so the container survives verbatim while the children move out from under it.
When a heap move is *exempted*, the correct fallback is **refuse ⇒ stabilize, never leave dangling** — a door that cannot copy must refuse, and the refusing path must first make its roots publishable.
A lease (an `Rc` handle over a shared store) held across an allocation is a deep copy or a dangling hazard, never a cheap borrow: hence **never hold a `CodeServer::atoms_handle()` across an intern** (`codeserver.rs` states it on the method — `atoms_mut()` is `Rc::make_mut`, so a clone held *across* an intern deep-clones the whole shared table and drops the copy), and the port delivery builders intern through `src/port.rs`'s `intern_reuse`, which looks the name up on the shared table first and reaches `atoms_mut()` only for a genuine miss (`../port/CONTEXT.md`).
The floor's own roster, on top of those rules:
- **No `Eterm` field lives at runtime lifetime** in `src/native.rs` + `src/native/**`: every `Eterm`/`Vec<Eterm>`/`Option<Eterm>` field is per-call — `memory`'s `Snapshot`, `file_server/get_until.rs`'s `EngineContinuation`, `net_kernel.rs`'s `ReplyTarget` — except `prim_file.rs`'s `Descriptor::owner`, a heap-free internal-pid immediate that can never dangle.
- **Every *runtime*-level store the floor writes is stabilized first** (`Runtime::try_stabilize_escaped`/`stabilize_term`, i.e. a deep copy on `eval_heap`, or a heap-free immediate): the timer message, the async-`garbage_collect` `ReqId`, `trace_pattern`'s `MatchSpec::Functions`, `tty_select/2`'s handle **and** reference, and the spawn family's entry fun + arguments when spawned **inside** a slice. The out-of-pass spawn `fun`/`args` stay **arena words**, sound only because that arm is reached only from a table-less context (`owns_process_table()` is `mailbox_table.is_none()`), which allocates on the never-relocated, never-reset arena — a pooled BIF region is **not** such a heap, since a call rewinds it once its container result has been copied out.
- **The one un-stabilized cross-call store the floor's arms reach** is `erlang:seq_trace/2`'s label (`seq_trace.rs::set_label` records the caller's word verbatim): the token family is an off-heap-payload root but not a relocation root, so a label on a collected heap is the sibling node's gap, not a store this floor owns.
- Per-store detail — which `Runtime` field, which region, whether the store is a gather root — is [`../CONTEXT.md`](../CONTEXT.md) *Runtime-level term stores* and `../context/IMPLEMENTATION.md`'s at-risk roster.
## Reply-term regions and the mixed-region rule
The floor never copies out and never rewinds: `context/calls.rs::call_bif_routed` returns the `try_native` result at the floor arm **before** the registered-BIF copy-out cascade and before `call_registered`'s `heap.reset_to(mark)`, so a floor term reaches Erlang exactly as the arm built it.
Four regions are reachable here:
- **Arena** (`Runtime::alloc_words`, `context/gc.rs::alloc_words`'s table-less tail) — pointer-stable: no region of it ever moves, and `src/runtime/reclaim.rs` `heap_rewind`s it to the pass's recorded mark once nothing reachable stands at or above it. Every `RuntimeContext::new(&mut *self)` helper in this node is table-less, so `ctx.atom`/`ctx.charlist`/`terms::make_tuple`/`terms::make_list`/`prim_file_call` land here, as does `EngineContinuation::call`'s engine run (`file_server/get_until.rs`, whose `Machine` owns no term heap).
- **`eval_heap`** — pointer-stable and the node's one *recyclable* region (`eval/scratch.rs` rewinds it at an `-eval` top-level statement boundary; `Runtime::grow_eval_heap` replaces it with the old region **retired**, dropped whole once a pass proves no reachable term stands in it). `beam_codec::term::make_binary` writes an **on-heap** bitstring, so a reply binary's store cost is ∝ its byte length — the node's one length-sensitive placement (`file_server.rs`'s `{get_chars,…}`/`{read,…}` data, `prim_file.rs`, `prim.rs`, `code.rs`, `erts_internal.rs`). It **cannot grow** (a plain `&mut beam_alloc::Heap`, so an insufficient region is a typed `BeamError::Alloc`; the only growth site is `move_result_into_runtime_store`).
- **`info_heap`** — the reset-per-call scratch (`Runtime::reset_info_scratch`, gated by `info_heap_tainted`), whose only callers are `native.rs`'s `system_info_tuple`/`render` and, outside this node, `runtime.rs` and `eval/compile.rs`; no `file_server`/`prim_file`/`code` arm touches it.
- **Pooled BIF heap** — three sites take one (`process.rs`'s `mint_timer_ref`/`reference_term`, `prim_tty.rs`'s `tty_select`) and put it back **without** a copy-out: safe by **identity**, not by copying (a reference's identity is its address; the next taker's `mark = used()` sits above those words; `take_bif_frontier` retires an exhausted region instead of freeing it). A future `Heap::reset()` on any production pool path would dangle every timer reference, monitor reference and `make_ref/0` value at once.
**The mixed-region rule — the one hazard shape a new reply builder must be checked against.** A graph whose parent came from the **arena** while its children came from the young heap dangles after the next collection: the collector leaves an out-of-from-set pointer verbatim while it evacuates and collapses the nursery chain the children lived in. `alloc_words`'s arena fallback calls `Runtime::note_gc_fallback`, which opens that process's descent gate — mitigation, not a guarantee: it covers a block reachable as a live **root**, not one reachable only through another unscanned holder. `prim.rs::prim_list_dir` is the floor's one reply that builds such a graph in a call.
**Consequence:** a `file_server_2` reply container is arena-built and cannot dangle; a reply **binary** is `eval_heap`-resident and recyclable only through the `-eval` statement window, which the `run <beam> m:f/0` route never takes.
## Known Issues
Every entry is a typed capability gap or a measured own-state difference — never a wrong result; per-item detail is the named ledger's.
- **`get_until`/`get_line` run the user continuation on a bare `Machine` and bypass the nested-run window latch** — `machine.run_export_outcome` is called directly instead of `run_export_blocking`/`run_label_blocking`, the two sites that call `Runtime::pin_window_if_store_written`; such a run is table-less (`gc_armed == false`) so it can neither collect nor rewind, but the latch it skips is what pins a holder the `-eval` descent cannot enumerate.
- **`process_info(Pid, messages)` and `process_info(Pid, dictionary)` republish the TARGET process's raw words** — the reply **cells** are built on `alloc_words` while the **element** words come verbatim from the target's heap, so a later collection of the target leaves them dangling; the fix shape is the sibling `links_value`/`monitored_by_value` builders (a private `beam_alloc::Heap`, `rehome_container_result`, `BeamError::SystemLimit` on refusal) — [`memory/CONTEXT.md`](memory/CONTEXT.md).
- **`process_info(Pid, {dictionary, Key})` matches by raw word** instead of term equality, so a non-immediate key never matches the way the oracle's `eq` would.
- **Pooled-BIF-heap mints are protected by ordering, never by a copy** — `mint_timer_ref`/`mint_reference`/`reference_term`/`attach_monitor` do `take_bif_heap` → write → `put_bif_heap` with no rewind and hand the reference word into the three **address-identity** `Eterm`-keyed maps (`Runtime::references`, `Timers::refs`, `TimerWakes::deliver`).
- **`KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (`../error.rs`) is a curated set of 17 `(function, arity)` pairs over 10 names** (`set_cookie/2`, `disconnect_node/1`, `port_call/3`, `spawn_request/1..5`, `process_flag/3`, `process_display/2`, `suspend_process/1,2`, `system_monitor/0,1,2`, `load_module/2`, `localtime_to_universaltime/1`); a pair belongs there **iff** the oracle exports and serves it and this runtime does not, since curating an `undef` name would answer its exit-1 "no such function" with an exit-3 gap. Drift guards: `../error.rs`'s `known_unimplemented_bifs_are_capability_gaps…`/`the_effective_gap_set_never_shadows_the_registry` suites and `native.rs`'s `every_floor_module_is_a_real_try_native_arm`.
- **The Erlang-level distribution supervisor is `ignore`** — `erl_distribution:start_link/0,1` cannot start the Erlang socket stack, and the only registered-name divergence is `net_sup`/`auth` (`undefined` here, live pids on the oracle): [`net/CONTEXT.md`](net/CONTEXT.md), `../M1_GAPS.md` *Distribution and the node (A.5)*.
- **`read_file_info/1,2`, `read_link_info/1,2`, `read_handle_info/1,2` and `list_dir/1,2` ARE served** (a real 14-tuple `#file_info{}`, `access` from real `access(2)` probes; `../../tests/a9_native_floor.rs`), and the `file_server_2` `{read_handle_info, Opts}` request — what `epp:parse_file/2` reads for `-moduledoc({file,…})` — is served by the same builder; `prim.rs`'s module-doc *Not served* section is stale on exactly these keys.
- **`code:`/`application:` divergences** — a found-but-unreadable `get_object_code/1` candidate is reported as a diagnostic rather than the atom `error`; `load_file/1` answers `{error,nofile}` for a non-sticky module outside `stdlib`/`kernel`/`erts`; the logger report is omitted (the sticky refusal, a corrupt image and the expected-name refusal, whose `{error,badfile}` value **is** produced); `application:get_application/1`'s non-pid non-atom argument is the bare `function_clause` where the oracle's `is_pid/1` clause answers `undefined` — [`code/CONTEXT.md`](code/CONTEXT.md).
- **`erlang:module_loaded/1` answers this runtime's own loaded set** (`../tests/module_loaded.rs`), and `context/process_bridge.rs`'s `process_flag(error_handler, A)` accepts an atom where the oracle raises `badarg` (owner `context/`); every other constant is a truthful default or derives from real state.
## Test Strategy
- **The crate gate** — `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt` (a bare `cargo` from the repo root fails: the workspace manifest is `erts_rust/Cargo.toml`, and the sandbox `$HOME` is read-only, hence the wrapper).
- **Unit tests** are colocated per module (`#[cfg(test)] mod tests`) and drive the floor through the crate's own dispatch (`test_support::call` ⇒ `RuntimeContext::call_bif` ⇒ `try_native`), so the *served surface* is pinned, not an internal function; fixtures live once in `test_support.rs`.
  The per-family suites are their child docs' — `memory/CONTEXT.md` (incl. its oracle-probe bounds and the never-a-live-oracle `garbage_collection` rule), `process/CONTEXT.md`, `erts_internal/CONTEXT.md`, `file_server/CONTEXT.md`, `net/CONTEXT.md` and `code/CONTEXT.md`.
- **Oracle values** are quoted in each test's doc comment (re-verified against the system `erl`, OTP 29.1.1 / erts-17.1), and where the runtime answers a typed capability gap the oracle answers a value, the test pins the `unsupported` outcome with a `// documented divergence:` comment. `get_dflags/0` is pinned by byte-comparing the built term's `term_to_binary/1` image; `prim.rs`'s file-system entries run against a real per-test scratch dir; fixtures needing a real `.beam` or the system Erlang skip **loudly** (`system_runtime()` / the file-local `lists_beam()`).
- **The only external toolchains ever spawned in this node are `erl` and `erlc`** — no `escript`/`cc`/`gcc`/`clang` invocation exists under `src/native/`, and `erlc` appears in exactly one place (`memory/binary_e2e.rs`, which compiles its end-to-end fixture at test time). Every live-oracle comparison compares the oracle's **stdout** (`~p`/`~w`/`~s` rendering) or its exit status; none compares `term_to_binary` bytes.
- **The suites that spawn the live `erl` oracle in-process** (skip **loudly** when absent): `code.rs`'s `oracle_probe` (`$ERTS_ORACLE` else `$PATH`, argv `-noshell -eval … -s init stop`), `prim.rs`'s `run_oracle`, `file_server/tests.rs`'s `compare_with_oracle` and `file_server/get_line/tests.rs`'s `run_oracle` (all `$ERTS_ORACLE` else `$PATH`, bounded 30 s); `file_server/get_until/tests.rs` spawns nothing.
- Cross-crate integration (CLI/exit codes, the preloaded `boot/*` corpus, `-eval`) is pinned by the `../tests/` suites: this node's A.9 native-floor surface by `a9_native_floor.rs`; the `init:*` termination/reboot family and `code:load_file/1`'s real load by `native_init.rs` and `code_load_file.rs` (which also pins the same expected-name refusal on the call-like routes); plus the `code/*`, `io_*`, `prim_tty`, `module_loaded` and `scheduled_io_device` suites their child docs list.
