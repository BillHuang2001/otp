# `beam_rt/src/native/` — the runtime-native BIF floor
## Intent
The BIFs that are really **runtime** operations, served *before* the `beam_bifs` registry (which owns only the static `bif.tab` surface — term ops, `lists`/`maps`/`binary`, `io:format`, `ets`): the process/port tables, the code server, the atom table, the parsed command line, the timer heap and the module container loader.
`init:*`/`code:*`/`erts_internal:*` are **preloaded-module surface** (contract A.7) whose real `.beam` bodies want process/message machinery this runtime does not run.
`application:*` is **not** a floor namespace any more: it was withdrawn when the boot path started a **live `application_controller`** (see *The `application` namespace*).
`RuntimeContext::try_native` is a *fall-through* layer: every entry returns `Option<Result<Eterm>>`, `None` meaning "not a native BIF", after which `call_bif` (`../context/mod.rs`) tries the registry or loads the module — nothing here duplicates a registry BIF, and no unclaimed call is answered with a fabricated value.
**This file is the dispatch index**: the implemented surface, the not-implemented index and the drift guards; per-family mechanics live in the child nodes (`memory/`, `process/`, `erts_internal/`, `file_server/`, `net/`, `code/`).
## API Surface
### The dispatch (source of truth: `../native.rs`)
`RuntimeContext::try_native(module, function, arity, args) -> Option<Result<Eterm>>` — **one match arm per native call**, plus one arm for the whole `erts_internal` namespace (`erts_internal_call`), one for `prim_file` (`prim_file_call`) and one for `erl_ddll` (`ddll_call`).
`call_bif`'s order: **loaded NIF → floor (`try_native`) → `beam_bifs` registry → on-demand external-module load**; a key in the `erlang` namespace none of those claims is the capability gap (`unsupported: …`, CLI exit 3) or the bare `error:undef` (`../error.rs`).
`FLOOR_MODULES: [&str; 14]` = `code`, `erl_ddll`, `erl_distribution`, `erl_prim_loader`, `erlang`, `erts_internal`, `init`, `io`, `net_adm`, `net_kernel`, `os`, `prim_buffer`, `prim_file`, `prim_tty` — each a module the code server can **also** load as a `.beam`, so the list gates `RuntimeContext::resolve_external_call`, which must answer `Ok(None)` for all of them (entering the body would run it *instead of* the host).
It does **not** gate `call_bif`'s dispatch: a `beam_bifs` registry key in a floor namespace the floor has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s, the floor owns only `os:cmd/1`; `erlang:display/1` is `beam_bifs`'s `%T` renderer).
Membership is the **namespace** set; `floor_keys` decides whether a whole namespace is refused or only the keys it enumerates (`io`/`prim_tty`/`prim_buffer`/`code`/`init`/`erl_distribution` key-granular, every other floor namespace module-wide).
`application` is in **neither** table: the floor owns no key of it, so no call into it is refused and the whole namespace is entered in-machine.
Drift guards: `native.rs::tests::every_floor_module_is_a_real_try_native_arm` (the namespace set) plus the **table-driven** `every_floor_arm_key_is_refused_and_every_key_granular_list_is_exact` (every arm must satisfy `floor_shadows`, every `floor_keys` list must enumerate **exactly** its namespace's parsed arm keys, an unlisted key must stay enterable, and every namespace must be classified `KEY_GRANULAR_NAMESPACES`/`MODULE_WIDE_NAMESPACES`), and `../error.rs`'s `never_shadow_the_registry` pair.
### The preloaded-module surfaces (contract A.7)
Every entry reads the runtime's own state; the crate-level A.9 view is `../CONTEXT.md`'s, and each module's per-entry ground truth is its own rustdoc.
`init.rs`: `fetch_loaded/0` ⇒ `[]` (the oracle's post-boot value); `get_plain_arguments/0` ⇒ the strings of `RuntimeConfig::plain_args`, which the CLI splits out of `-extra`/`--` per merge entity and which is never an init argument, so `init:get_arguments/0` carries no entry for `extra` or the plain values; `init:stop/1`, `init:boot/1` and the `root`/`home`/`progname`/`bindir` automatic flags answer as the oracle does.
`init:restart/0` clears the system before it re-boots (`Runtime::clear_system`): every process but the calling action and the runtime's own `init`/`erl_prim_loader`/`file_server_2`/`net_kernel` services is terminated `shutdown`, so the re-run script's `{kernelProcess, …}` directives register onto free names and the ports/io-devices those processes owned are released with them; the residuals (no code unload, a borrowed port registry, the pid-keyed probe maps) are on `Runtime::restart`, and a restart from inside a scheduler slice is the typed `unsupported` gap.
**`init:script_id/0`** reports `{Name, Release}` with the **release always this runtime's own** (`beam_common::otp_version().major`, the source `erlang:system_info(otp_release)` answers from) and the **name the loaded boot script's own header** (`RELEASE_NAME` = `"Erlang/OTP"` as the empty-name fallback) — never the script's `Vsn`, which names the consumed installation's release; no loaded script ⇒ the typed `unsupported: init:script_id/0 (no boot script has been loaded)` gap.
`code.rs` + `code/path.rs` — the `code:*` path/load readers and the path mutators over the ONE authoritative `CodeServer` store: [`code/CONTEXT.md`](code/CONTEXT.md).
`loader.rs` — the `erl_prim_loader` floor: `get_loader_config/0` ⇒ the emulator's default `{efile,undefined}` config (so `name_split/2` makes every client-side operation a plain `prim_file` delegation), `set_loader_config/1`/`set_path/1` accepted and discarded, `get_path/0` ⇒ this runtime's real code path, and the `list_dir`/`read_file`/`*_file_info`/`get_cwd` entries ⇒ the `prim_file` floor; the archive half stays unclaimed (module rustdoc).
### The `application` namespace — the LIVE `application_controller`, no floor
There is **no `application` floor**: the module is a set of `lib/kernel/src/application.erl` one-line delegations to the `application_controller` the boot script's directive 14 really starts (`../../boot/drive.rs`), which registers the name, creates the public named ETS table `ac_tab`, `load`s kernel and then **starts** kernel and stdlib through `handle_call({start_application, …})`. So the server's `ac_tab` is the whole `application:*` answer, on every route a user can reach:
- `get_env/1,2,3`, `get_all_env/1`, `get_key/1,2`, `get_all_key/1` are **plain function calls** reading `ac_tab` with `ets:lookup_element`/`ets:match` (`application_controller.erl:345-460`) — no `gen_server` round trip, so nothing suspends; the `kernel` environment they report is the *running* one (nine pairs: the file's seven plus the `logger`/`connect_all` injections).
- `get_application/0,1` resolves the `{application_master, App}` entries (`:461-485`), a **pid** argument taking `application.erl:1047-1050`'s `is_pid/1` clause (a `-noshell` process's group leader names no application, so `undefined`), and `loaded_applications/0` is an `ets:select` over `{loaded, App}` (`:300-306`), reporting `kernel` then `stdlib`.
- `which_applications/0` **is** a `gen_server:call` (`:295-296` → `handle_call` `:904`) whose `S#state.running` is really populated here, because the script's `start_boot/2` directives reach `handle_call({start_application, …})` (`:697`); it answers the oracle's two triples in the oracle's order, `[{stdlib,…},{kernel,…}]`.
**No floor may shadow it**: `set_env/4` is a `gen_server:call` into the controller, so a `get_env/2` answered anywhere but the caller's own `ac_tab` read is stale (`set_env(kernel, K, V), get_env(kernel, K)` ⇒ `undefined`), and a `.app`-file reader reports the file's 7 `kernel` pairs where the running node has 9.
**The one remaining difference is a version, not a value**: the default route loads **this runtime's own** release's boot script, which embeds this checkout's `stdlib` version (`8.1`) where the oracle's embeds its installation's (`8.1.1`) — the same relationship `init:script_id/0` pins (`{"Erlang/OTP","30"}` here, `"29"` there). `kernel`'s version coincides (`11.0.4`), and every name/description/order is oracle-identical.
Residual: an `application:*` call on a route that boots **no** script (the in-process `Runtime::with_defaults`, and only that) has no `ac_tab` and the controller's `ets:lookup_element` raises `badarg` — there is no oracle analogue (every `erl` boots), and the test suite's `application:*` assertions therefore run on the built binary's booted route (`tests/a9_native_floor.rs`'s `agrees_on_the_booted_route`).
### The boot path (`bootstrap/bin/start.boot`, 22 directives): what the floor serves
Every `-eval`/`-s`/`-run`/`-boot` action boots first (`../../cli.rs` `boot_then` → `run_boot_script`), and the script's two process directives are settled by `resolve_external_call` and then **entered as their module's own `.beam` code** (`../../boot/drive.rs::apply_boot_call`, `start_kernel_process`): `heart:start/0` (index 12), `logger_server:start_link/0` (13), `application_controller:start/1` (14), `application:load/1` (16), `application:start_boot/2` (18, 19) and `c:erlangrc/0` (20) have **no `try_native` arm** and are not registry BIFs, and none of `heart`/`logger_server`/`application_controller`/`application`/`c` is in `FLOOR_MODULES`.
The floor is therefore reached *from inside* that real kernel code, on keys the booted servers really call: `init:fetch_loaded/0`, `init:get_argument/1` and `init:code_path_choice/0` (`lib/kernel/src/code_server.erl:100,548,673`), `code:where_is_file/1` (`application_controller:make_appl/1`), and the `prim_file:*` fd/path half behind `c:erlangrc/0`'s `file:open/2`.
`application:get_env/2`, `application:get_key/2` and `application:get_all_env/1` (`application_controller.erl:709,1822,1790`; `kernel.erl:206,286,336`) are **not** floor calls any more: they are the controller's own `ac_tab` reads, in the caller's process.
Two consequences bind any boot-path claim: `application:get_env/2` answers the live `ac_tab` (so kernel's start-time `logger`/`connect_all` injections ARE visible), and the file `c:erlangrc/0` opens is served by the booted `kernel_sup`'s own real `file_server_2` child (`lib/kernel/src/kernel.erl:117`), the native service being spawned unregistered on every script-driving route (`file_server.rs::start_unclaimed`).
### The process-control families (route through `beam_process`) — `process.rs` + `process/`
The monitor/alias/reference bookkeeping, `exit/2,3`, the spawn family, the registry/`whereis` surface and the node surface route through `beam_process`'s tables.
Each name resolves in the **process** table first and the **port** registry second, so a registered port answers `whereis`/`registered`.
Per-family oracle contracts — `spawn_opt`'s whole `max_heap_size` setting and its validate-every-option-before-the-child-exists rule, the `process_flag(monitor_nodes|{monitor_nodes,Opts},Bool)` claim, `hibernate/0` and the process/scheduler-control gaps — are [`process/CONTEXT.md`](process/CONTEXT.md)'s; the node set, the connector and `monitor_node/2` are [`net/CONTEXT.md`](net/CONTEXT.md)'s.
### `erlang:garbage_collect/0,1,2` (A.7) — the on-demand collection
Bodies in `erts_internal.rs`, arms in `../native.rs::try_native`; `erlang` is a floor namespace, so its `.beam` wrappers are un-enterable and the floor owns all three arities (per-argument probe table in `erts_internal.rs`'s rustdoc, argument contract in [`process/CONTEXT.md`](process/CONTEXT.md)).
**No BIF may collect** — the root set a collection relocates is the **executing machine's** `x[0..live)` plus its Erlang stack, which a BIF running *inside* the engine does not own — so a servable call records a **request** via `Runtime::request_gc` and answers the oracle's `true`, served only where that root set is owned (the engine's heap-admission point `../../context/gc.rs::ensure_heap`, which bypasses only the occupancy test and never the safety valves, and the runner's park arms `../../runner/run.rs` → `Runtime::serve_gc_request`); a request is recorded **only** for a **scheduled slice**, so `Runtime::gc_stats().collections` moves only when a collection really ran.
The async form's follow-up `{garbage_collect, ReqId, GCResult}` is recorded by `Runtime::request_gc_async` and delivered into the requester's mailbox at a **scheduler-pass boundary** (`../../runtime/gc.rs::deliver_gc_completions`).
### `erlang:spawn_monitor/1,2,3,4` — an `erlang.erl` wrapper, not a `bif.tab` BIF
The four arities are `erlang:spawn_opt(…, [monitor])` behind `erlang.erl`'s own guards, so no registry entry — and nothing in the known-unimplemented list — claims them and the floor owns the whole family: a guard violation is the oracle's `badarg`, the `Node` forms on another node are the typed distributed-spawn gap, and the monitor is installed before the child's first schedulable moment (`../tests/spawn_monitor.rs`; detail [`process/CONTEXT.md`](process/CONTEXT.md)).
### `erlang:process_info/1,2` (A.8) — `memory/` (+ `../tests/process_info_binary.rs`)
A **runtime** operation served before the registry, read out of this runtime's own `beam_process` table.
Load-bearing summary: `/2`'s three argument forms (an item atom, a list of items, `{dictionary,Key}`) and `/1`'s fixed 17-item `PI_1_KEYS` order; `registered_name` is **bare** in the atom form and **wrapped** in the list form, and is the truth of the **queried** process (never the caller's); `binary` is the live off-heap refc-binary roster as `{Ptr,Size,Refc}` triples; `garbage_collection` is the 5-item proplist in `beam_gc::GARBAGE_COLLECTION_KEYS` order; `links`/`monitored_by` are each a **union of two stores** (the local `Process` half plus `ProcessTable::remote_links`/`remote_watchers`, rendered as external pids and copied out through `rehome_container_result`), so a real peer's `link/1`/`monitor/2` is observable.
The item catalog, the per-item own-state sources, the honest `unsupported` set and the divergences are [`memory/CONTEXT.md`](memory/CONTEXT.md)'s, and `memory/mod.rs`'s module docs are the authoritative per-item table; `process_info(Pid, garbage_collection)` is **never** compared against a live oracle.

### `prim_file:*` (A.7) — `prim.rs` (path half) + `prim_file.rs` (fd half)
`RuntimeContext::prim_file_call(function, arity, args) -> Option<Result<Eterm>>` over the host file system (`std::fs`/`std::env`); `prim_file` is a **preloaded** module whose BIFs are the C `prim_file_nif.c` NIFs, and the floor claims only the subset whose whole observable contract is pinned byte-for-byte against the oracle — everything else returns `None`, falling through to the preloaded `.beam` (an honest `erlang:nif_error(undef)`).
**Served — 39 of the 43 `(name, arity)` keys the dispatch arms**, plus the module's **local, non-exported** stub `advise_nif/4` (reached only through `ExecutionContext::resolve_local_call`); **typed gaps** are `write_file_info/2,3`, `allocate/3` and `file_desc_to_ref/2`.
detail: [`prim_file/CONTEXT.md`](prim_file/CONTEXT.md) — the served-key list, the errno/invariant rules, `open/2`'s flag derivation, `flatten_iodata`, the `prim_buffer` read-ahead queue and `read_line/1`, `advise`/`sendfile`, and the divergences.
### `prim_tty:*` (A.7) — the built-in NIF library — `prim_tty.rs`
ERTS serves `prim_tty` from its **static NIF table** (`erts/emulator/nifs/common/prim_tty_nif.c`, `is_static_nif_module`), so `erlang:load_nif("prim_tty", …)` never `dlopen`s a shared object; `prim_tty.rs::is_builtin_library` is the ONE resolution source `NifBridge`'s `NifLoader::load_nif` consults **before** the filesystem (`../context/bridges.rs`), so `load/0` answers `ok` and nothing enters the NIF registry (`NifRegistry::is_loaded("prim_tty")` stays `false`, keeping the Erlang wrappers enterable in-machine).
**Two routes, one implementation.** `prim_tty.rs::NIF_KEYS` (20 keys) is the whole `-nifs` surface of `lib/kernel/src/prim_tty.erl`: the **exported** stubs (`isatty/1`, `write_nif/2`, …) travel `floor_keys("prim_tty")` → `call_bif` → `try_native` → `RuntimeContext::prim_tty_call`, while the **non-exported LOCAL stubs** (`tty_create/1`, `tty_init/2`, …) reach the same implementation through `ExecutionContext::resolve_local_call` → `prim_tty::serves_local_call`.
**Served faithfully** (per-entry ground truth: the module rustdoc): `isatty/1` (a real `IsTerminal` probe), `tty_create/1` (an opaque round-trippable handle), `tty_init/2`, `tty_encoding/1` ⇒ `utf8`, `setlocale/1` ⇒ `primitive`, `sizeof_wchar/0` ⇒ `4`, `tty_window_size/1`, `tty_is_open/2`, `write_nif/2`/`read_nif/3`, `tty_select/2` (the C's `enif_get_resource` check **before** anything is armed, then a one-shot read interest on fd `0` through [`../port/select.rs`](../port/select.rs), answering `ok`), and the no-`HAVE_TERMCAP` family (`setupterm_nif/0`, `tinfo_nif/0`, `tiget{num,flag,str}_nif/1`, `tputs_nif/2`) ⇒ `{error,enotsup}`.
**Typed capability gaps** (never a fabricated value): `isprint/1`, `wcwidth/1`, `wcswidth/1` (libc's width tables have no faithful safe-std equivalent); the **terminal-present** arm of `tty_window_size/1` (`TIOCGWINSZ` unavailable in safe std) and the **raw-mode** arm of `tty_init/2` (no safe-std termios).
**Fidelity deviation** (not oracle parity): the oracle is built **with** termcap, where this runtime answers the C's no-`HAVE_TERMCAP` arm — ncurses terminfo state is not reproducible from safe Rust, and that arm is non-raising, which `prim_tty:init/1`'s `setupterm() =:= ok` check requires.
### `prim_buffer:*` (A.7) — the built-in NIF library — `prim_buffer.rs`
ERTS serves `prim_buffer` from its **static NIF table** (`erts/emulator/nifs/common/prim_buffer_nif.c`), so `erlang:load_nif("prim_buffer", …)` never `dlopen`s a shared object: `prim_buffer.rs::is_builtin_library` joins `prim_tty.rs`'s in the ONE resolution source `NifBridge`'s `NifLoader::load_nif` consults **before** the filesystem (`../context/bridges.rs`), so `prim_buffer:load/0` answers `ok`, nothing enters the NIF registry (`NifRegistry::is_loaded("prim_buffer")` stays **`false`**), and the module's Erlang wrappers stay enterable in-machine.
**Nine stubs, key-granular.** `new/0`, `size/1`, `write/2`, `skip/2`, `find_byte_index/2`, `try_lock/1`, `unlock/1` are the exported NIF surface and reach `RuntimeContext::prim_buffer_call` through `floor_keys("prim_buffer")` → `call_bif` → `try_native`; `peek_head/1` and `copying_read/2` are **not exported** (only `read/2`/`read_iovec/2`'s own bodies apply them), so they are reachable only from those bodies and from `prim_file`'s read-ahead. `read/2`, `read_iovec/2` and `wipe/1` are **Erlang bodies** that must keep running, so `floor_keys` enumerates the seven stub keys rather than refusing the namespace: the three bodies enter, reach `copying_read`/`peek_head` in-module, and `wipe/1` is `skip(RBuf, size(RBuf))`.
**The queue is the `prim_buffer` surface**: a `PrimBuffer` is the C's 2 KiB write accumulator (small writes coalesce; a write of at least `ACCUMULATOR_SIZE/2` keeps its own queue element, so `read_iovec` after one 2048-byte and one 10-byte write is `[2048,10]`, never `[2058]`), `read/2(B, 0)` is `<<>>`, a count past the end is `{error,badarg}` with the buffer untouched, `find_byte_index/2` answers `{ok,Index}`/`not_found` (a needle outside `0..=255` is `badarg`), `try_lock/1` is `acquired`/`busy`, `unlock/1` without the lock is `error:lock_order_violation`, and `new/0` is a **reference** handle. `read/2`'s payload is built with `beam_codec::term::make_binary`, so a chunk above the 64-byte on-heap limit is an off-heap binary rather than a refused one.
### `erl_ddll:*` — one loaded-driver list (A.4) — `ddll.rs`
`RuntimeContext::ddll_call(function, arity, args) -> Option<Result<Eterm>>`; `beam_bifs` registers six `erl_ddll` keys over its **own** loaded-driver registry, which this crate's port machinery never reads, so the floor serves the four list/load/unload/report keys from the **one** name-keyed registry the ports really use (`../port/driver.rs`'s `LOADED_DRIVERS`) — `loaded_drivers/0` **is** the list `open_port({spawn_driver, Name})` resolves a name against.
Dispatched before `call_registered`, those four keys **shadow** `beam_bifs`'s same-named keys; `monitor/2`, `demonitor/1` and `format_error/1` deliberately return `None` and stay with `beam_bifs` — claiming them would duplicate its `errint`→text table and mint monitor references against a driver list the monitor machinery does not read.
Oracle answers: `loaded_drivers/0` ⇒ `{ok,[Name,…]}` (charlists: the three **statically linked** built-ins first — `tcp_inet`, `udp_inet`, `ram_file_drv` — then the loaded names in load order); `try_load/3` ⇒ `{ok,loaded}`/`{ok,already_loaded}`/`{error,{open_error,-10}}`/`{error,Reason}`; `try_unload/2` ⇒ `ok`/`{error,not_loaded}`; `info/2` ⇒ a **known** name's item value, `badarg` otherwise; a **statically linked** name answers `{error,linked_in_driver}` to both load and unload, and its `info/2` takes the C's `handle == NULL` item branch; an `errcode_tab` reason is the **bare reason atom** and a failed `dlopen` `{open_error,-10}`; a malformed argument or option is `badarg`, never a fabricated result.
**The three statically linked built-ins are one derived view** — `port::driver::static_drivers()`, the C `driver_list` entries with `handle == NULL`, membership `beam_io::STATIC_SPAWN_DRIVERS` (also the `open_port({spawn_driver, Name})` gate), arrangement `DRIVER_TAB_ORDER`.
**Divergences** (own-state, never a fabricated value): `open_port({spawn_driver, Name})` auto-`dlopen`s an unloaded name where the oracle answers `badarg`; `try_unload/2` is an immediate `ok` rather than the C's pending-state machine; opening a `try_load`ed driver re-`dlopen`s the object, so the entry's `init` runs once per open rather than once per load; a loaded driver's monitor subscription is not delivered.
### `file_server_2` — the native file service (A.9)
`file_server.rs` + `file_server/` own the runtime-native **file service**: the `file_server_2` service process (never enqueued, drained by the scheduler-pass step `Runtime::service_file_requests`), its per-`open` native io-devices, and the `gen_server`/`file`/`io` request/reply wire.
`Runtime::new` consults `RuntimeConfig::drives_a_boot_script()`: whenever it holds (every CLI action but `-version`, plus an explicit `-boot FILE`) the service is spawned **unregistered** (`FileServices::start_unclaimed`), because that route's booted `kernel_sup` starts OTP's own `file_server_2` child and owns the name; a runtime driving no script registers it under the atom `file_server_2` (`FileServices::start`).
**The process model, the scheduler-pass step, the served-request surface (`{write_file,…}`/write-mode `{open,…}`/`{get_until,…}`/`{get_line,…}`, the `getopts`/`setopts` read-mode surface and the `{read_handle_info, Opts}` reader), the wire tables and the tests are [`file_server/CONTEXT.md`](file_server/CONTEXT.md)'s.**
### The runtime-native `net_kernel` service (A.5) — `net_kernel.rs`
`net_kernel.rs` owns the runtime-native **`net_kernel` service**: a `beam_process::Process` spawned `Runnable`, registered as `net_kernel` and never enqueued, drained by the scheduler-pass step `Runtime::service_net_kernel` right after `service_file_requests`.
**It exists only on a distributed node** — `Runtime::new` starts it when its `dist` half is `Some` (a `-name`/`-sname` config) and leaves it `None` otherwise, so a non-distributed runtime registers no name and spawns no process.
**Dispatch table (one entry):** `{'$gen_call', From, {is_auth, _Node}}` is answered the atom **`yes`** (`net_kernel.erl` answers unconditionally — the request carries the *caller's* node, so a comparison would answer `no`); a malformed `{is_auth}` (arity ≠ 2) and the bare atom are answered `no`.
**Every other request is the typed `unsupported: net_kernel: <request> is not served` gap**, never a silent drop — a dropped `gen:call` parks its caller in an untimed `receive`, the defect this service removes — and that gap is **fatal to the whole node** (`service_net_kernel` returns the `Err` and the pass breaks on it), unlike a malformed *transport* frame, which retires only that one link.
**The reply reproduces `gen:reply/2`'s three clauses:** `{To,[alias|Ref]}`/`{To,[[alias|Ref]|_]}` send `{Tag, Reply}` to `Ref` through `Runtime::dist_send_alias` (the outbound `DOP_ALIAS_SEND`, tag echoed unchanged); any other `{To, Tag}` delivers `{Tag, Reply}` to `To` — a local pid through `RuntimeContext::deliver_in_table` (a dead caller's `TermNotFound` dropped, as `gen:reply/2`'s `catch` does), a remote pid through `Runtime::dist_send_message_pid`; a reply tag naming a reference on THIS node takes `DistLinks::route_alias`'s **external**-destination typed error rather than a local delivery.
### The `io` device floor (`io.rs`) — the stream and file-device routes, served natively
The floor covers **14** keys (`io:put_chars/1,2`, `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2`, `io:format/3`, `io:request/1,2`, `io:requests/1,2`) and routes every output call to one of **three** paths: the floor's own direct sink for a stream leader, OTP's own `io.erl` body in-machine for any other live leader, and the native file service for a file device.
detail: [`io/CONTEXT.md`](io/CONTEXT.md) — the device classifier and its answers, the file-device request surface, the `(Device, Format, Args)` arity truth, the byte conversion and the pinning suites; the key table and the measured routing table are [`../context/io_route.rs`](../context/io_route.rs)'s.
## Constraints
- **`#![deny(unsafe_code)]`** — the crate-wide rule covers this whole floor; terms are built and read only through `beam_engine::terms`, `beam_codec::term`, `beam_loader::container` and `beam_term`, and the parent's `render` drives the registered `io:format/2` printer rather than a private one.
- **Return-based errors** (`../CONTEXT.md` §3): `Option<Result<Eterm>>`, never a crate-local error enum, never `panic!`/`unwrap()` on runtime data, never a silent swallow; a "value atom" answer the C *returns* (`badarg`, `big`, `no_integer`, `not_a_list`) is `Ok(atom)`.
- **Consulted before the registry.** A native entry must never shadow or duplicate a `beam_bifs` BIF, with one deliberate exception: the four `erl_ddll` list/load/unload/report keys shadow `beam_bifs`'s same-named registry keys, so the driver list `open_port({spawn_driver, Name})` reads and the one `erl_ddll` reports stay a single view. The `erlang`-namespace fallback classifies a known-unimplemented name as the capability gap (`unsupported: …`, CLI exit 3) and anything else as the bare `error:undef`.
- **The floor's `CodeServer` owns the ONE authoritative code path**: a live `code_server` process does run on the boot-driven routes but keeps a second path store, so the floor serves the path readers **and** the `code/path.rs` mutators out of `CodeServer` (the store this runtime really searches), and only the un-migrated `code.erl` mutators edit that second store ([`code/CONTEXT.md`](code/CONTEXT.md)).
- **The child nodes own their families' detail** — `memory/`, `process/`, `erts_internal/`, `file_server/`, `net/`, `code/` — and the dispatch table stays `../native.rs`'s alone: a child doc may name its own arms but never a second dispatch list.
- **Files ~1000 lines of production code**, every public item documented; the oversize files (`process.rs`, `prim.rs`, `prim_file.rs`, `erts_internal.rs`) are single-responsibility and kept whole.
## Term lifetime and rooting (the four workspace rules, and this floor's roster)
A raw `Eterm` in a long-lived slot **roots nothing**: any term that can outlive one instruction — a raise reason, a pending reply, a parked value, a cache entry — must be copied onto a scanned heap or explicitly stabilized before its owner's heap can relocate.
A pointer-stable, never-scanned store (the arena, `alloc_words`) is the **wrong home** for a container whose children live on a scanned young heap: the copier gives such a container `Target::Foreign` and never descends, so the container survives verbatim while the children move out from under it.
When a heap move is *exempted*, the correct fallback is **refuse ⇒ stabilize, never leave dangling** — a door that cannot copy must refuse, and the refusing path must first make its roots publishable.
A lease (an `Rc` handle over a shared store) held across an allocation is a deep copy or a dangling hazard, never a cheap borrow: hence **never hold a `CodeServer::atoms_handle()` across an intern** (`atoms_mut()` is `Rc::make_mut`, so a clone held *across* an intern deep-clones the whole shared table and drops the copy), and the port delivery builders intern through `src/port.rs`'s `intern_reuse` (lookup first, `atoms_mut()` only for a genuine miss).
The floor's own roster, on top of those rules:
- **No `Eterm` field lives at runtime lifetime** in `src/native.rs` + `src/native/**`: every `Eterm`/`Vec<Eterm>`/`Option<Eterm>` field is per-call — `memory`'s `Snapshot`, `file_server/get_until.rs`'s `EngineContinuation`, `net_kernel.rs`'s `ReplyTarget` — except `prim_file.rs`'s `Descriptor::owner`, a heap-free internal-pid immediate that can never dangle.
- **Every *runtime*-level store the floor writes is stabilized first** (`Runtime::try_stabilize_escaped`/`stabilize_term`, i.e. a deep copy on `eval_heap`, or a heap-free immediate): the timer message, the async-`garbage_collect` `ReqId`, `trace_pattern`'s `MatchSpec::Functions`, `tty_select/2`'s handle **and** reference, and the spawn family's entry fun + arguments when spawned **inside** a slice. The out-of-pass spawn `fun`/`args` stay **arena words**, sound only because that arm is reached from a table-less context (`owns_process_table()` is `mailbox_table.is_none()`) — a pooled BIF region is **not** such a heap, since a call rewinds it once its container result has been copied out.
- **The one un-stabilized cross-call store the floor's arms reach** is `erlang:seq_trace/2`'s label (`seq_trace.rs::set_label` records the caller's word verbatim): the token family is an off-heap-payload root but not a relocation root, so a label on a collected heap is the sibling node's gap, not a store this floor owns.
- Per-store detail — which `Runtime` field, which region, whether the store is a gather root — is [`../CONTEXT.md`](../CONTEXT.md) *Runtime-level term stores* and `../context/IMPLEMENTATION.md`'s at-risk roster.
## Global vs per-call state — what this floor allocates
Binding for anyone asking "what does the floor cost at boot / hold for the runtime's life?".
- **The floor owns no heap-allocated global state of its own**: every module here is a set of functions over `Runtime`/`ProcessTable`/`CodeServer` state, and `../native.rs` carries only `FLOOR_MODULES` (14 `&'static str`) plus `floor_keys`' static slices (io 14, prim_tty 20, prim_buffer 9, init 11, code 27, erl_distribution 2 key pairs).
- **Two runtime-lifetime structs** exist because a service process needs an owner handle: `FileServices` (`file_server.rs:181-197` — the `file_server_2` pid, the io-device `HeapPolicy`, `devices: HashMap<ProcessId, Device>`, and the never-pruned `retired: HashSet<ProcessId>`) and `NetKernelService` (`net_kernel.rs:107-110` — one `ProcessId`, distributed nodes only).
- **Per-open state belongs to a process, not the floor**: `open/2` spawns one io-device `Process` (233-word nursery) per open and stores a `Device` (`file_server.rs:572-575`; a `std::fs::File`, an encoding, and a read-ahead `buf: Vec<u8>` bounded by the 8192-byte chunk at `file_server.rs:888`); `prim_file:open/2` keeps the raw handle in `Runtime::open_files: HashMap<u64, std::fs::File>` (`../runtime.rs:1128`); `prim_tty` handles live in `Runtime::prim_tty_handles: HashMap<u64, i32>` (`../runtime.rs:1136`); the `save_calls` ring is per pid in `Runtime::saved_calls` with a lazy `VecDeque` of `min(capacity, 64)` (`memory/last_calls.rs:104-112`).
- **The floor keeps no module→path index and no `.beam` image cache**: `CodeServer::find_file` (`../codeserver.rs:516`) is a linear scan of the 36-entry path doing one `is_file()` per entry on **every** `code:which/1`, `code:get_object_code/1`, `code:where_is_file/1` and on-demand load; beside `modules: HashMap<String, Arc<Module>>` the store adds only `module_paths` (one entry per file-loaded module) and `module_files` (a memory load), `read_image` decodes and drops its bytes, and `code:get_object_code/1` (`code.rs:233`) re-reads the file and materializes it on `eval_heap`, so repeated calls grow that store, never a cache.
- **The four runtime-owned service processes never take an engine `Machine`** (they are never enqueued, so `RunnerState::spawn_with_stability` never runs for them): each costs one PCB (~8.2 KiB of inline `XRegs`) plus its 233+233-word collector inside a shared carrier.
- **Static tables stay small**: `INFO_ATOMS` 92 names, `CORE_ATOMS` 77, `PORT_INFO_ATOMS` 17, `prim_tty::NIF_KEYS` 20 pairs, `prim::ERRNO_NAMES` 42, `memory::PI_1_KEYS` 17, `memory::IMPLEMENTED_ITEMS` 39; no `OnceLock`, no `Box::leak`, no static allocation exists under `src/native/` (the only `static`s are `AtomicUsize` test counters).
- **Long-lived process-wide statics the floor reads but does not own**: the system-ebin `OnceLock` memo (`../codeserver.rs:1025`) and the driver tables `DRIVER_ENTRIES`/`LOADED_DRIVERS` (`../port/driver.rs:1404,1442`, empty at boot; `ddll.rs` reports the latter).
## Reply-term regions and the mixed-region rule
The floor never copies out and never rewinds: `context/calls.rs::call_bif_routed` returns the `try_native` result at the floor arm **before** the registered-BIF copy-out cascade and `call_registered`'s `heap.reset_to(mark)`, so a floor term reaches Erlang exactly as the arm built it.
Four regions are reachable here:
- **Arena** (`Runtime::alloc_words`, `context/gc.rs::alloc_words`'s table-less tail) — pointer-stable: no region of it ever moves, and `src/runtime/reclaim.rs` `heap_rewind`s it to the pass's recorded mark once nothing reachable stands at or above it. Every `RuntimeContext::new(&mut *self)` helper here is table-less, so `ctx.atom`/`ctx.charlist`/`terms::make_tuple`/`terms::make_list`/`prim_file_call` land here, as does `EngineContinuation::call`'s engine run (`file_server/get_until.rs`, whose `Machine` owns no term heap).
- **`eval_heap`** — pointer-stable and the node's one *recyclable* region (`eval/scratch.rs` rewinds it at an `-eval` top-level statement boundary; `Runtime::grow_eval_heap` replaces it with the old region **retired**). `beam_codec::term::make_binary` writes an **on-heap** bitstring, so a reply binary's store cost is ∝ its byte length — the node's one length-sensitive placement (`file_server.rs`'s `{get_chars,…}`/`{read,…}` data, `prim_file.rs`, `prim.rs`, `code.rs`, `erts_internal.rs`). It **cannot grow** (a plain `&mut beam_alloc::Heap`, so an insufficient region is a typed `BeamError::Alloc`; the only growth site is `move_result_into_runtime_store`).
- **`info_heap`** — the reset-per-call scratch (`Runtime::reset_info_scratch`, gated by `info_heap_tainted`), whose only callers are `native.rs`'s `system_info_tuple`/`render` and, outside this node, `runtime.rs` and `eval/compile.rs`; no `file_server`/`prim_file`/`code` arm touches it.
- **Pooled BIF heap** — three sites take one (`process.rs`'s `mint_timer_ref`/`reference_term`, `prim_tty.rs`'s `tty_select`) and put it back **without** a copy-out: safe by **identity**, not by copying (each reference-keyed registry names the word it minted — `Runtime::references`, `Timers::refs`/`refs_by_id`, `TimerWakes::deliver`; the next taker's `mark = used()` sits above them, and `take_bif_frontier` retires an exhausted region instead of freeing it). A `Heap::reset()` on any production pool path would dangle every timer reference, monitor reference and `make_ref/0` value at once.
**The mixed-region rule — the one hazard shape a new reply builder must be checked against.** A graph whose parent came from the **arena** while its children came from the young heap dangles after the next collection: the collector leaves an out-of-from-set pointer verbatim while it evacuates the chain the children lived in. `alloc_words`'s arena fallback calls `Runtime::note_gc_fallback`, opening that process's descent gate — mitigation, not a guarantee: it covers a block reachable as a live **root**, not one reachable only through another unscanned holder. `prim.rs::prim_list_dir` is the floor's one reply that builds such a graph in a call.
**Consequence:** a `file_server_2` reply container is arena-built and cannot dangle; a reply **binary** is `eval_heap`-resident and recyclable only through the `-eval` statement window, which the `run <beam> m:f/0` route never takes.
## `inet:getaddr/1,2` on a *string* — the resolver works; a copied timer reference resolves by identity
`inet:getaddr("127.0.0.1", inet)` ⇒ `{ok,{127,0,0,1}}`, `inet:getaddr("::1", inet6)` ⇒ `{ok,{0,0,0,0,0,0,0,1}}`, an unresolvable name ⇒ `{error,nxdomain}` with no report block and a live resolver, and a real name is answered by the `inet_gethost` OS-child program.
The route is the kernel's own: `getaddrs_tm/3` (`lib/kernel/src/inet.erl:3966-3990`) short-circuits only **tuple** addresses, so `inet:getaddr/2` (`:2836` → `:2853`) hands every string, numeric included, to `gethostbyname_tm` → `inet_gethost_native:getit/2`; `inet:parse_address/1` is the pure-parse path and agrees as well.
What it stands on is outside this node: `inet_gethost_native.erl:365-368` mints `TimerRef = erlang:start_timer(Timeout, self(), RID)` into an `ets` row and `:270-275` cancels the **copy** it reads back out, so the timer BIFs must recognise a reference by its **id**, not by its term's address — `../timers.rs`'s `refs_by_id` (written in lockstep with `refs`) and `../runtime.rs::local_reference` do.
`inet_gethost_native_sup` is a `temporary` child of `kernel_safe_sup`, so a worker that died on that `badarg` would never be restarted and every later lookup would answer `nxdomain` for the node's life; `tests/timer_ref_identity.rs` pins `is_pid(whereis(inet_gethost_native_sup))` after an `nxdomain` as well as the answers.
The floor still serves none of it, and should not: `inet`/`inet_gethost_native` are ordinary `.beam` bodies (the inet stack has no `prim_inet` NIF stubs at all, below), `erlang:cancel_timer/2` is a `beam_bifs` `RuntimeHooks` key a floor arm would duplicate, and a `getaddr/1,2` arm that parsed numeric strings itself would mask a future divergence instead of exposing it.
## Namespace audit — every remaining floor namespace stays, and why
Every key of **all 14** `FLOOR_MODULES` namespaces was put to the oracle one by one (pinned by `../../tests/a9_native_floor.rs::the_kept_floor_namespaces_agree_with_the_oracle`), and **no key qualifies for withdrawal**: a key stays either because its OTP body needs a facility this runtime does not run, or because it reads the *live server's* state, deliberately not the state this runtime keeps.
- `code` (27 keys, `code/`) — the floor owns the **one** authoritative path store (`CodeServer`), while the `code.erl` bodies call into the live `code_server`'s *separate* store (`code:add_patha(Dir), code:load_file(M)` ⇒ `{error,nofile}` through a body; `is_loaded/1` reads that server's ETS `moddb`), which on a non-booted runtime (`Runtime::with_defaults`, the shape this node's own suites use) does not exist at all.
- `code:which/1` is the closest candidate — its body composes `is_loaded/1` + `where_is_file/1` — and stays floored because it re-derives the path from that second store; the floor agrees on all nine probes (`lists`/`dets`/`erlang` ⇒ `preloaded`, a missing name ⇒ `non_existing`, `42`/`"lists"`/`<<"lists">>` ⇒ `function_clause`).
- `code:get_mode/0` derives from the `-mode` init argument (the body reads `persistent_term:get(code_server)`, published here only as a side effect of the in-machine `code_server:init/3` a boot runs); `interactive`/`embedded` agree on `-eval` and on `-mode embedded`. `code:is_sticky/2` has no OTP body to shadow (the release has no such function), so the arm reproduces the oracle's `undef`.
- `init` (11 keys, `init.rs`) — every key is `request(...)`/`init ! ...` against the live `init` process, which this runtime does not enqueue (`get_status`, `script_id`, `fetch_loaded` and `code_path_choice` do answer through their bodies on a booted runtime, but each parks on that process first).
- `io` (14 keys, `io.rs`) — the device surface; `../context/io_route.rs` already routes every non-stream device to `io.erl`'s own body.
- `os:cmd/1` — the body needs a port plus the `unix:cmd` driver helper; measured, un-flooring it is *worse* (`os:cmd("")` blocks: exit 3 on the `-eval` route).
- `net_adm:ping/1` — a remote `gen:call` to the peer's `net_kernel`; the floor answers `pang`/`pong` from the node's own link table. `net_kernel:connect_node/1` — the `net_kernel` request protocol (`request({connect, …})`), answered from the same table. `erl_distribution:start_link/0,1` — a `supervisor:start_link` of the Erlang socket stack, which is `ignore` here.
- `prim_tty` (20 NIF keys), `erlang` (75 arms), `erts_internal` (19 keys), `prim_file` (43 keys), `erl_prim_loader`, `erl_ddll` — NIF-stub and emulator-internal surfaces (`erlang:nif_error(undefined)`) with no Erlang body to fall back to.
## Known Issues
Every entry is a typed capability gap or a measured own-state difference — never a wrong result; per-item detail is the named ledger's.
- **The floor's non-atom guard raises `badarg` where the OTP body's own `is_atom` guard raises `function_clause`** — `code:which/1`, `is_loaded/1`, `is_sticky/1`, `get_object_code/1`, `ensure_loaded/1`, `load_file/1` (`code.erl:1781`/`:755`/`:1015`/`:778`/`:774`/`:891`), `net_adm:ping/1` and `net_kernel:connect_node/1`; `code:lib_dir/1` answers the value `{error,bad_name}` where `code.erl:927`'s `when is_atom(App) ; is_list(App)` guard makes a non-atom `function_clause`, and the non-atom list/atom pair (`code:lib_dir("stdlib")`) is the same class — a floor arm *can* raise `function_clause` (`prim.rs::function_clause`), so this is a measured divergence, not an impossibility.
- **`init:get_argument/1` on a non-atom flag is `badarg`** where the oracle answers the atom `error` (an *unloaded* `init` flag is `error` on both).
- **`os:cmd/1` drops the child's stderr and re-encodes a non-ASCII argument** — the oracle opens the port with `stderr_to_stdout` (`os.erl:598`) so `os:cmd("echo out; echo boom >&2")` is `"out\nboom\n"` (here `"out\n"`), and `os:cmd("printf 'caf\303\251\n'")` is `[195,131,194,169]` on the floor's side because `chars_to_string` encodes the code points as UTF-8 before the shell sees them (the oracle passes the same bytes through unchanged). Merging stderr properly needs one shared write end for both streams (an `unsafe` `pipe(2)`, which `#![deny(unsafe_code)]` keeps out of this crate).
- **`get_until`/`get_line` run the user continuation on a bare `Machine`** (`run_export_outcome`, not the `run_export_blocking`/`run_label_blocking` sites that call `Runtime::pin_window_if_store_written`): the run is table-less (`gc_armed == false`), so it can neither collect nor rewind, but the skipped latch is what pins a holder the `-eval` descent cannot enumerate.
- **`process_info(Pid, messages)` and `process_info(Pid, dictionary)` republish the TARGET process's raw words** — the reply **cells** are built on `alloc_words` while the **element** words come verbatim from the target's heap, so a later collection of the target leaves them dangling; the fix shape is the sibling `links_value`/`monitored_by_value` builders (a private `beam_alloc::Heap`, `rehome_container_result`, `BeamError::SystemLimit` on refusal) — [`memory/CONTEXT.md`](memory/CONTEXT.md).
- **`process_info(Pid, {dictionary, Key})` matches by raw word** instead of term equality, so a non-immediate key never matches the way the oracle's `eq` would.
- **Pooled-BIF-heap mints are protected by ordering, never by a copy** — `mint_timer_ref`/`mint_reference`/`reference_term`/`attach_monitor` do `take_bif_heap` → write → `put_bif_heap` with no rewind and hand the reference word into the `Eterm`-keyed maps (`Runtime::references`, `Timers::refs`, `TimerWakes::deliver`) — the first and the third are **address-identity**, so a rewind would dangle them, while `Timers` keeps an id-keyed index (`refs_by_id`) that would still name the timer by a garbage word.
- **`KNOWN_UNIMPLEMENTED_ERLANG_BIFS` (`../error.rs`) is a curated set of 17 `(function, arity)` pairs over 10 names** (`set_cookie/2`, `disconnect_node/1`, `port_call/3`, `spawn_request/1..5`, `process_flag/3`, `process_display/2`, `suspend_process/1,2`, `system_monitor/0,1,2`, `load_module/2`, `localtime_to_universaltime/1`); a pair belongs there **iff** the oracle exports and serves it and this runtime does not, since curating an `undef` name would answer its exit-1 "no such function" with an exit-3 gap. Drift guards: `../error.rs`'s two `known_unimplemented_*` suites; the static-NIF roster itself is `../info/CONTEXT.md`'s.
- **The Erlang-level distribution supervisor is `ignore`** — `erl_distribution:start_link/0,1` cannot start the Erlang socket stack, and the only registered-name divergence is `net_sup`/`auth` (`undefined` here, live pids on the oracle): [`net/CONTEXT.md`](net/CONTEXT.md), `../M1_GAPS.md` *Distribution and the node (A.5)*.
- **`#file_info{}` is built from real host state** — the 14-tuple with `access` from real `access(2)` probes, shared by `read_file_info/1,2`/`read_link_info/1,2`/`read_handle_info/1,2` and by the `file_server_2` `{read_handle_info, Opts}` request that `epp:parse_file/2` reads for `-moduledoc({file,…})` (`../../tests/a9_native_floor.rs`).
- **`code:` divergences** — a found-but-unreadable `get_object_code/1` candidate is reported as a diagnostic rather than the atom `error`; `load_file/1` answers `{error,nofile}` for a non-sticky module outside `stdlib`/`kernel`/`erts`; the logger report is omitted (the sticky refusal, a corrupt image and the expected-name refusal, whose `{error,badfile}` value **is** produced) — [`code/CONTEXT.md`](code/CONTEXT.md).
- **`erlang:module_loaded/1` answers this runtime's own loaded set** (`../tests/module_loaded.rs`), and `context/process_bridge.rs`'s `process_flag(error_handler, A)` accepts an atom where the oracle raises `badarg` (owner `context/`); every other constant is a truthful default or derives from real state.

- `io.rs` (+ `io/`) → the `io` **device** floor: the `o_request/2` device model, the argument-aware `io_device_needs_the_protocol` half of the routing rule, the file-device arm into `file_server.rs`'s `serve_io_request`, the byte conversion (`io/convert.rs`) and the stream devices (`io/request.rs`) — [`io/CONTEXT.md`](io/CONTEXT.md)
- `memory/` → `erlang:process_info/1,2` (`mod.rs` dispatch + item builders, `binary.rs` the `binary` roster, `last_calls.rs` the `save_calls` ring), `memory/tests.rs` and `memory/binary_e2e.rs` — [`memory/CONTEXT.md`](memory/CONTEXT.md)
- `process/` → the process-control families (`process/monitor.rs` `monitor/2,3`+`demonitor/1,2`+aliases, `process/exit.rs` the exit-signalling surface) with the sibling `../process.rs`, `../node.rs` and `../group_leader.rs` — [`process/CONTEXT.md`](process/CONTEXT.md)
- `net/` → the node set, the connector and the Erlang-supervisor floor (`nodes.rs`, `connector.rs`, `monitor.rs`, `tests.rs`) — [`net/CONTEXT.md`](net/CONTEXT.md); the `node_monitors` store and the `service_node_monitors` pass step are `../runtime.rs`/`../runtime/scheduler.rs`'s
- `code/` → `code/path.rs`'s four mutators and the readers/normalisation rules the ONE `CodeServer` store answers — [`code/CONTEXT.md`](code/CONTEXT.md)
- `erts_internal.rs` → the `erts_internal` floor (`erts_internal_call`) + its unit tests — [`erts_internal/CONTEXT.md`](erts_internal/CONTEXT.md)
- `erts_internal/trace.rs` → the `erts_internal:trace/3` + `:trace_pattern/3` bodies over `crate::trace` (no colocated tests — `../tests/trace*.rs`)
- `prim.rs` → the path half of the `prim_file` floor (`prim_file_call`): `encode_path`/`collect_path` and the `errno`→atom table + its unit tests
- `prim_file.rs` (+ `prim_file/`) → the file-descriptor half of the `prim_file` floor, incl. the `directory`-mode `open/2`, and the three children `prim_file/{advise,sendfile,readahead}.rs` — [`prim_file/CONTEXT.md`](prim_file/CONTEXT.md)
- `prim_buffer.rs` → the built-in `prim_buffer` NIF library: `is_builtin_library` + the nine stub keys (seven exported, two non-exported) over the write-accumulator/queue the `prim_file` read-ahead drives; oracle suite `../../tests/prim_buffer.rs`
- `prim_tty.rs` → the built-in `prim_tty` NIF library: `is_builtin_library` + the `NIF_KEYS`/`prim_tty_call` stubs both routes converge on; oracle suite `../../tests/prim_tty.rs`; `tty_select/2`'s arming half is [`../port/select.rs`](../port/select.rs)
- `ddll.rs` → the `erl_ddll:*` loaded-driver list over `../port/driver.rs`'s one name-keyed registry + its unit tests
- `loader.rs` → the `erl_prim_loader` floor: the loader config, `get_path/0` and the `prim_file` delegations (module docs carry the table and the archive-half gaps)
- `file_server.rs` (+ `file_server/`) → the native `file_server_2` service, its io-devices, the request/reply wire and the read/write/getopts surfaces, with its `get_until/tests.rs`/`get_line/tests.rs` sub-suites ([`file_server/CONTEXT.md`](file_server/CONTEXT.md)); the pass step is `../runtime/scheduler.rs`'s
- `net_kernel.rs` → the registered `net_kernel` service process (distributed nodes only) and the `gen:reply/2` reply routing; the pass step is `Runtime::service_net_kernel`
- `init.rs` → the `init` automatic flags, the plain arguments, `init:script_id/0` and the termination/reboot family
- *(no `application.rs`)* → the whole `application:*` namespace is `lib/kernel/src/application.erl` delegating to the live `application_controller`; the `.app`-resource floor and its `ResourceParser` were withdrawn (see *The `application` namespace*)
- `process.rs` / `port.rs` → the spawn/registry/`whereis` surface (each name resolved in the **process** table first, the **port** registry second) and the port surface (`port_connect/2`, `port_command/2,3`, `port_control/3`, `port_info/1,2`) — contracts A.4/A.7/A.8/A.9
- `node.rs` → the node/cookie surface (`is_alive/0`, `get_cookie/0`, `set_cookie/2`)
- `test_support.rs` → the shared fixtures
- `../context/mod.rs` / `../context/bridges.rs` → `call_bif`/`try_native`'s caller and the host seams, and `module_md5` (the `.beam` digest `beamfile_module_md5/1` serves)
- `../runtime.rs`, `../codeserver.rs`, `../boot.rs`, `../port.rs`, `../timers.rs`, `../dist.rs` → the runtime state these BIFs read (owned elsewhere); `../error.rs` → `unsupported`/`undef`/`halt`/`live_reason_term` and the known-unimplemented list
- `../../../../erts/emulator/beam/` → legacy C ground truth (read-only)
## Not implemented — the `erts_internal` / `prim_*` BIFs left falling through
Every name not in a table above answers `None` and falls through to the `beam_bifs` registry then a real module load — an honest failure, never a fabricated value.
This list is the one index of the unserved keys; the per-key reasons are [`erts_internal/CONTEXT.md`](erts_internal/CONTEXT.md) *Not served* and [`process/CONTEXT.md`](process/CONTEXT.md) *Not served*.
- **The `erts_internal` families left falling through** — the A.5 distribution primitives, the debugger half of tracing, microstate accounting, the system-task/system-monitor pair, `purge_module/2` plus the literal-area handshake, the ETS raws (`ets_lookup_binary_info/2`, `ets_raw_first/1`, `ets_raw_next/2`, `ets_super_user/1`), the allocation/IO introspection set (`gather_alloc_histograms/1`, `gather_carrier_info/1`, `gather_io_bytes/2`, `crasher/6`) and the process/scheduler controls (`process_display/2`, `suspend_process/1,2`, `await_result/1`, `flush_monitor_messages/3`); served elsewhere: `atomics_*`/`counters_*`, `erase_persistent_terms/0`, `map_hashmap_children/1`/`map_next/3` — except that the `net_kernel` name is this crate's native service, so a peer's `gen:call` `{is_auth, Node}` is answered here.
- **The port-BIF family** (`open_port/2`, `port_call/3`, `port_close/1`, `port_connect/2`, `port_command/3`, `port_control/3`, `port_info/1,2`) is served by `../port.rs` (the `PortHook` seam) and by the sibling [`port.rs`](port.rs): `port_connect/2` delegates to `../port/ops.rs`'s `connect`, `port_command/2,3`'s whole `erts_port_output` outcome matrix (the busy-port wait included) is one `busy_wait::issue` call, and `erts_internal:port_*` goes through the `beam_bifs` `RuntimeHooks` seam, as do `erlang:port_set_data/2`/`port_get_data/1` over `../port/ops.rs`'s `PortExtras`.
- **The inet stack is NOT a floor-entry gap — `prim_inet` has no NIF stubs at all** (`open/4`, `sendto/4`, `getstat/2` and `ctl_cmd/3` are ordinary Erlang driving `open_port({spawn_driver,"tcp_inet"|"udp_inet"},[binary])`, `port_control/3` and `port_command/2`), so `gen_tcp`/`gen_udp`/`inet`/`inet_db`/`inet_config` run as interpretable `.beam` bodies and never touch `try_native`; their only floor contact is the port BIFs. The stubs only exist in `prim_net`/`prim_socket` (`erlang:nif_error(notsup)`), which the `inet` backend never reaches.
- **A live `inet_db` gen_server exists on every boot-driven route** — `kernel_sup`'s child, whose `init/1` creates six named ETS tables and arms the hourly refresh timer — so `db_get` and `lookup_socket/1` (`port_get_data`) answer; the boot itself opens and closes a UDP socket in `inet_config:init/0`.
- **Where the socket entry points stand** — `gen_udp:open/2`, `gen_tcp:listen/2` (the `[binary]` form included), the `inet:getopts/setopts` round trip, `inet:getstat/1,2`, `gen_udp:send/4` + `recv/3` and `gen_tcp:connect/2,3,4` all reach this node end to end; what remains is render-side, never a socket result: a completion's recipient is recorded per operation, and a post-`open_port/2` `{mode,…}` cannot re-render a payload staged before it — [`../port/CONTEXT.md`](../port/CONTEXT.md) *Known Issues*, `M1_GAPS_A4_PORTS.md`.
- **`prim_*` preloaded driver modules** — the **39** `prim_file` keys listed above are all that is served; every other `prim_file` key and all of `erl_prim_loader`, `prim_inet`, `prim_socket`, `prim_net`, `prim_zip`, `prim_eval` fall through to a preloaded-`.beam` load whose `-nifs()` entry needs the matching host; `prim_zip:splitter/3` (pure Erlang) is **not** claimed; the raw-syscall `fallocate`/`chmod`/`chown`/`utimes` floor is a **missing `beam_io` facility** (`advise` needs none — it is served as a hint, `posix_fadvise(2)` never being called).
## Handoffs (owned by OTHER nodes)
Every native BIF's per-call `try_native` arm is registered in `../native.rs`, guarded by the two drift tests above.
The `file_server_2` service answers a **scheduled** process's `gen_server:call` — a `run` process's `file:read/2`/`file:read_line/1`/`io:*` suspend and resume through the ordinary `RunOutcome::Wait` (`../../tests/scheduled_io_device.rs`).
