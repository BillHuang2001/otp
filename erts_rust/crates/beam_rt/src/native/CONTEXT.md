# `beam_rt/src/native/` — the runtime-native BIF floor
## Intent
The BIFs that are really **runtime** operations: they read/write this runtime's own state (process table, port registry, code server, atom table, application view, parsed command line, timer heap, module container loader), served *before* the `beam_bifs` registry, which owns only the static `bif.tab` surface (term ops, `lists`/`maps`/`binary`, `io:format`, `ets`, …).
`init:*`/`code:*`/`application:*`/`erts_internal:*` are **preloaded-module surface** (contract A.7) whose real `.beam` bodies want process/message machinery this runtime does not run.
The floor is a *fall-through* layer: every entry returns `Option<Result<Eterm>>`, `None` meaning "not a native BIF", after which `RuntimeContext::call_bif` (`../context/mod.rs`) tries the registry (or loads the module); nothing here duplicates a registry BIF, and no unclaimed call is answered with a fabricated value.
Each family's contract lives in the child node that owns it — `memory/` (`process_info`), `process/` (the process-control families), `erts_internal/` (`erts_internal:*`) and `file_server/` (`file_server_2`) — and the sections below are this node's index plus the detail for the families with no child node.
## API Surface
### The dispatch (source of truth: `../native.rs`)
`RuntimeContext::try_native(module, function, arity, args) -> Option<Result<Eterm>>` — **one match arm per native call**, plus one arm for the whole `erts_internal` namespace (`erts_internal_call`) and one for `prim_file` (`prim_file_call`).
`call_bif`'s order: **loaded NIF → floor (`try_native`) → `beam_bifs` registry → on-demand external-module load**; a key in the `erlang` namespace none of those claims is the capability gap (`unsupported: …`, CLI exit 3) or the bare `error:undef` (`../error.rs`).
`FLOOR_MODULES: [&str; 14]` (`native.rs:140`) = `application`, `code`, `erl_ddll`, `erl_distribution`, `erl_prim_loader`, `erlang`, `erts_internal`, `init`, `io`, `net_adm`, `net_kernel`, `os`, `prim_file`, `prim_tty` — each a module the code server can **also** load as a `.beam`, so the list gates `RuntimeContext::resolve_external_call`, which must answer `Ok(None)` for all of them (entering the body would run it *instead of* the host).
It does **not** gate `call_bif`'s dispatch: a `beam_bifs` registry key in a floor namespace the floor has no arm for still reaches the registry (`os:env/0` is `beam_bifs`'s; the floor owns only `os:cmd/1`), since membership is the **namespace** set and `floor_keys` decides whether a whole namespace is refused or only the keys it enumerates (`io`/`prim_tty`/`application`/`code`/`init`/`erl_distribution` key-granular).
Drift guards: `native.rs::tests::every_floor_module_is_a_real_try_native_arm` (the namespace set) plus the **table-driven** `native.rs::tests::every_floor_arm_key_is_refused_and_every_key_granular_list_is_exact` (every `(module, function, arity)` `try_native` has an arm for must satisfy `floor_shadows`, every `floor_keys` list must enumerate **exactly** its key-granular namespace's parsed arm keys, an unlisted key must stay enterable, and every namespace must be classified in `KEY_GRANULAR_NAMESPACES`/`MODULE_WIDE_NAMESPACES` — so a new arm or namespace fails loudly, never silently), and `../error.rs`'s `never_shadow_the_registry` pair.
### The preloaded-module surfaces (contract A.7)
Every entry reads the runtime's own state; the crate-level A.9 view (the automatic `get_argument/1` flags, `script_id/0`, the `stop`/`restart`/`boot` family, `lib_dir/2`, the `application` view) is `../CONTEXT.md`'s and each module's per-entry ground truth its own rustdoc (`init.rs`/`code.rs`/`application.rs`).
Kept here: `fetch_loaded/0` ⇒ `[]` (the oracle's post-boot value, the loader's list observable only before the code server consumes it, `init.erl:718-722`); `init:stop/1` ⇒ `ok` for a non-negative integer status, the `erlang:halt/1` crash-dump slogan for a byte list (incl. `[]`), `badarg` otherwise (incl. `normal`); `init:boot/1` resolves its BootArgs' `-boot <Script>` (default `$ROOT/start`, `init.erl:1257-1258`) through `cli::resolve_boot_file_for` and executes it, answering `ok` where the real one never returns.
`code`'s lookups rest on different bases: `where_is_file/1` is the code server's **non-module** path search (`code_server.erl:1469-1486`), `which/1`/`get_object_code/1` are **path**-based (load state first — the recorded file, or `preloaded` — then a code-path search, so an unloaded-but-findable module such as `dets` still has one; `get_object_code/1` ⇒ `{Module,Binary,Filename}`, else the atom `error`), and `is_loaded/1` is **load-state**-based (`false` unless preloaded or really loaded here, else `{file,Beam}`) — `code:ensure_loaded/1` closes the difference.
`load_file/1` really loads (`{module,M}`) with the oracle's `{error,sticky_directory|nofile|badfile}` vocabulary, and `<Name>.beam` whose **object code names another module** is that `badfile` on **every** file route — the loader's expected-name check lives in the one `CodeServer::load`, so `load_file/1` ⇒ `{error,badfile}`, `ensure_loaded/1` ⇒ `{error,badfile}` and `ensure_modules_loaded/1` ⇒ `{error,[{Name,badfile}]}`, with the image loaded under neither name (`code:which/1` still answers the path; oracle-verified with a `bogus.beam` really holding `realname`, and only the oracle's own `beam_load.c` error report is omitted here); `load_binary/3` reproduces `code.erl:667-688` clause for clause — the guard fails as the **bare-atom `function_clause`** raise, never this floor's usual `badarg` (the oracle's `is_list/1` accepts the **empty** list, which `beam_term::is_list` does not, so `is_nil` covers it), `modp(File)` is `{error,badarg}` for a proper list with a non-integer element and `function_clause` for an **improper** one, `erlang:prepare_loading/2` is `{error,badfile}` for an empty/garbage image **or one whose own module name is not `Mod`**, the sticky check (after the image validates) is `{error,sticky_directory}`, and success registers the image under `Mod` with **`File` recorded verbatim** (`CodeServer::insert_loaded`/`recorded_name`: an atom filename is reported as the atom — `code:which/1` ⇒ `cover_compiled` — and the empty list as `[]`); `get_mode/0` reads `interactive`/`embedded` from the `-mode` init argument; `priv_dir/1` = `lib_dir(App, priv)` (joined, never `stat`ed; `{error,bad_name}` for an unknown name); a non-list `File` raises the bare-atom `function_clause`.
`ensure_modules_loaded/1` is the whole-list form: `prepare_ensure/2` demands a **proper list of atoms** (a non-list, an improper list or a non-atom element raises the bare-atom `function_clause`); the names neither preloaded nor already loaded are `lists:usort`-ed, each located by the same `module_file` lookup and loaded through `CodeServer::load`; only failures are listed — `ok`, else `{error,[{Name,nofile|badfile}]}` in **reverse** of the sorted order (the oracle's `do_par_recv/3` prepends each result as it arrives); `badfile` is a `.beam` found on the path that fails to load — a corrupt image or one whose **object code names another module** (`CodeServer::load`'s expected-name check), the two shapes the oracle reports identically; **Accepted residual:** for either the oracle also logs an `=ERROR REPORT==== …` line (the corrupt image's `corrupt file header`, the name mismatch's `beam_load.c … module name in object code is <Real>`), and this runtime emits only the value, never an invented report. Like `ensure_loaded/1`, it is served through the floor's own `try_native` arm **and** is listed in `floor_keys("code")`, so it is a floor key on **both** routes — a **compiled** module's `call_ext` is refused the in-machine `code.beam` body (which reaches the live `code_server` process and its second path store, where a module that store cannot find crashes the server) and reaches this implementation instead; pinned end to end on the `run` route by `../../tests/code_ensure_modules_loaded.rs`.
**`application`** (`application.rs`) — a minimal native `.app` view (`get_env/1,2,3`, `get_all_env/1`, `get_all_key/1`, `get_key/1,2`, `get_application/0,1`, `loaded_applications/0`, `which_applications/0`): `get_application/0` is always `undefined`; `/1`'s non-pid non-atom argument is the bare `function_clause` where the oracle's `is_pid/1` clause answers `undefined` for a pid; `app_env_props` reads the `.app` resource's `env` list **verbatim**, so kernel's start-time `logger`/`connect_all` injections are absent (`application:get_env(kernel,connect_all)` is `undefined` here vs `{ok,true}` on the oracle).
### The process-control families (route through `beam_process`) — `process.rs` + `process/` (+ `node.rs`, `net/`, `group_leader.rs`)
The monitor/alias/reference bookkeeping (`monitor/2,3`, `demonitor/1,2`, `alias/0,1`, `unalias/1`), `exit/2,3`, the spawn family (`spawn_opt`, `spawn_monitor/1,2,3,4`), the registry/`whereis` surface and the node surface route through `beam_process`'s tables.
Their per-family oracle contracts — `spawn_opt`'s whole `max_heap_size` setting, the `process_flag(monitor_nodes|{monitor_nodes,Opts},Bool)` claim, `monitor_node/2`'s `Runtime::node_monitors` store, `nodes/2`'s real per-link `connection_id`, `hibernate/0`, and the process/scheduler-control gaps — are [`process/CONTEXT.md`](process/CONTEXT.md)'s.
Load-bearing summary: `spawn_opt` validates EVERY option before the child exists and runs from a normal context **or inside a scheduler slice** (`RuntimeContext::spawn_in_pass` + `Runtime::absorb_pending_spawns`, `../tests/spawn_from_slice.rs`); `exit/3` takes only the bare `priority` atom, and a self-directed exit is raised directly or delivered as `{'EXIT', self(), R}` to a trapping caller; `monitor_node/3` and a remote-`{Name,Node}` monitor are typed gaps.
Each name resolves in the **process** table first and the **port** registry second, so a registered port answers `whereis`/`registered`.
### `erlang:garbage_collect/0,1,2` (A.7) — the on-demand collection
Bodies in `erts_internal.rs`, arms in `../native.rs::try_native`; `erlang` is a floor namespace, so its `.beam` wrappers are un-enterable and the floor owns all three arities, with the per-argument oracle probe table in `erts_internal.rs`'s rustdoc and the argument contract in [`process/CONTEXT.md`](process/CONTEXT.md).
**No BIF may collect** — the root set a collection relocates is the **executing machine's** `x[0..live)` plus its Erlang stack, which a BIF running *inside* the engine does not own — so a servable call records a **request** via `Runtime::request_gc` and answers the oracle's `true`, served only where that root set is owned (the engine's heap-admission point `../../context/gc.rs::ensure_heap`, which bypasses only the occupancy test and never the safety valves, and the runner's park arms `../../runner/run.rs` → `Runtime::serve_gc_request`).
A request is recorded **only** for a **scheduled slice**, so `Runtime::gc_stats().collections` moves only when a collection really ran; the async form's follow-up `{garbage_collect, ReqId, GCResult}` message is never sent (no system-task protocol here), never faked.
### `erlang:spawn_monitor/1,2,3,4` — an `erlang.erl` wrapper, not a `bif.tab` BIF
The four arities (`erlang.erl:10667`/`:10686`/`:10706`/`:10874`) are `erlang:spawn_opt(…, [monitor])` behind `erlang.erl`'s own guards, so no registry entry — and nothing in the known-unimplemented list — claims them and the floor owns the whole family.
A guard violation is the oracle's `badarg`, the `Node` forms on another node are the typed distributed-spawn gap, and the monitor is installed before the child's first schedulable moment (`../tests/spawn_monitor.rs`; detail [`process/CONTEXT.md`](process/CONTEXT.md)).
### `erlang:process_info/1,2` (A.8) — `memory/` (+ `../tests/process_info_binary.rs`)
A **runtime** operation served before the registry, read out of this runtime's own `beam_process` table.
The item catalog, the per-item own-state sources, the honest `unsupported` set and the divergences are [`memory/CONTEXT.md`](memory/CONTEXT.md)'s; `memory/mod.rs`'s module docs are the authoritative per-item table.
Load-bearing summary: `/2`'s three argument forms (an item atom, a list of items, `{dictionary,Key}`) and `/1`'s fixed 17-item `PI_1_KEYS` order; `registered_name` is **bare** in the atom form and **wrapped** in the list form, and is the truth of the **queried** process (never the caller's), which is what makes the `-eval`/`-s`/`-run` action routes agree with the oracle.
`binary` is the live off-heap refc-binary roster as `{Ptr,Size,Refc}` triples; `garbage_collection` is the 5-item proplist in `beam_gc::GARBAGE_COLLECTION_KEYS` order; `max_heap_size` reads the explicit setting else the birth default (`+hmax`); execution-position items come from the root frame, the in-machine BIF door, then `RunnerState`.
`process_info(Pid, garbage_collection)` is NEVER compared against a live oracle (the child doc names the hard-coded pin).
### `erts_internal:*` (A.7) — `erts_internal.rs` (+ `erts_internal/trace.rs`)

The served set (19 keys), the per-BIF oracle contracts (`get_dflags/0`'s byte-exact record, `beamfile_chunk/2`, `beamfile_module_md5/1`, `map_to_tuple_keys/1`, the integer parsers, `is_process_alive/1,2`, `process_flag/3`, `no_aux_work_threads/0`, `processes_next/1`, `term_to_string/1,2`, `trace/3`/`trace_pattern/3`, `group_leader/2,3`, `garbage_collect/1`), the `term_type/1` divergence and every reason an `erts_internal` family is left falling through are [`erts_internal/CONTEXT.md`](erts_internal/CONTEXT.md)'s.
### `prim_file:*` (A.7) — `prim.rs` (path half) + `prim_file.rs` (fd half)
`RuntimeContext::prim_file_call(function, arity, args) -> Option<Result<Eterm>>`; `prim_file` is a **preloaded** module whose BIFs are the C `prim_file_nif.c` NIFs, and the floor claims the subset whose whole observable contract is pinned byte-for-byte against the oracle, over the host file system (`std::fs`/`std::env`); everything else returns `None`, falling through to the preloaded `.beam` (an honest `erlang:nif_error(undef)`). **Served (35 of the 41 `(name, arity)` keys `prim_file_call` arms, 6 more typed gaps; ground truth per entry in each module's rustdoc):** the **path half** (`prim.rs`) `get_cwd/0,1`, `read_file/1`, `delete/1`, `rename/2`, `make_dir/1`, `del_dir/1`, `read_link/1`, `make_link/2`, `make_symlink/2`, `altname/1`, `list_dir/1`, `list_dir_all/1` (`prim.rs:337`), `read_file_info/1,2`, `read_link_info/1,2`; the **fd half** (`prim_file.rs`) `open/2`, `read/2`, `write/2`, `close/1`, `position/2`, `pread/2,3`, `pwrite/2,3`, `truncate/1`, `sync/1`, `datasync/1`, `write_file/2`, `set_cwd/1`, `ipread_s32bu_p32bu/3`, `get_handle/1`, `read_handle_info/1,2`.
**Invariants.** Every path-only entry is a direct NIF call wrapped by `try … catch error:badarg -> {error,badarg}` in `prim_file.erl`, so a **bad path is always the value `{error,badarg}`, never a raise**; the C's errno REMAPs are reproduced explicitly (`unlink` `EISDIR`→`EPERM`; `rename` `ENOTEMPTY`→`EEXIST` and an old path of exactly `/`→`EINVAL`; `rmdir` `ENOTEMPTY`→`EEXIST` and, when that names the process's own non-empty cwd by ino/dev, `EINVAL`).
The path contract (from `encode_path/1`): a **binary** (its bytes verbatim; a NUL ⇒ badarg) or an **iolist** of code points (nested lists flattened; a nested **binary** ⇒ badarg; a NUL, a non-scalar code point, a non-integer element or an improper tail ⇒ badarg) encoded as UTF-8 and walked iteratively with an explicit stack, so nesting depth cannot exhaust the Rust stack; the `errno`→atom map is the C's (the POSIX name lower-cased, with the C's own `errno_<n>` form outside the table).
`open/2` hands out the oracle's `{file_descriptor, prim_file, Data}` map shape and follows the C's flag derivation (`read`→`O_RDONLY`; `write` alone→`O_TRUNC|O_WRONLY|O_CREAT`; read+write→`O_RDWR|O_CREAT`; `append`→`O_APPEND` and no `O_TRUNC`; plus `exclusive`, `sync`, `{read_ahead,S}`); every unmodelled option is silently ignored, exactly as the C does; a `directory`-mode open is **served** (a real `O_DIRECTORY` plus the post-open type checks, with `skip_type_check` skipping them).
**Divergences:** `read/2` does **not** reproduce read-ahead (`prim_buffer` is never called — its only export is `on_load/0`); `get_handle/1`'s fd *number* is this runtime's own; a path built from a file's raw bytes goes through `beam_codec::term::make_binary` on the pointer-stable `eval_heap` (no 64-byte limit, unlike `beam_engine::terms::make_heap_binary`).
**Typed gaps** (explicit `unsupported`, never a silent wrong value): `write_file_info/2,3`, `advise/4`, `allocate/3`, `read_line/1` (its Erlang body drives the `prim_buffer:*` resource NIFs, all `undef`), `file_desc_to_ref/2`. **Deliberately unclaimed** because the oracle answers the same (an arm would *create* a divergence): `copy/2`, `write_file/3`, `delayed_close/1` (unexported ⇒ `error:undef`), `sendfile/8` (`{error,enotsup}`/`badarg`), `internal_get_nif_resource/1` (no NIF-resource model); `copy/3` works (pure Erlang).
### `prim_tty:*` (A.7) — the built-in NIF library — `prim_tty.rs`
ERTS serves `prim_tty` from its **static NIF table** (`erts/emulator/nifs/common/prim_tty_nif.c`, `is_static_nif_module`, `erts/emulator/beam/erl_nif.c`), so `erlang:load_nif("prim_tty", …)` never `dlopen`s a shared object; this runtime mirrors that — `prim_tty.rs::is_builtin_library` is the ONE resolution source `crate::context::NifBridge`'s `NifLoader::load_nif` consults **before** touching the filesystem (`../context/bridges.rs`), so `prim_tty:load/0` answers `ok` and nothing enters the NIF registry (`NifRegistry::is_loaded("prim_tty")` stays `false`, so the module's Erlang wrappers stay enterable in-machine).
**Two routes, one implementation.** `prim_tty.rs::NIF_KEYS` (20 keys) is the whole `-nifs` surface of `lib/kernel/src/prim_tty.erl`: the **exported** stubs (`isatty/1`, `write_nif/2`, `read_nif/3`, … — reached by `call_ext`) travel `floor_keys("prim_tty")` → `call_bif` → `try_native` → `RuntimeContext::prim_tty_call`, while the **non-exported LOCAL stubs** (`tty_create/1`, `tty_init/2`, … — the compiler emits a LOCAL `call`/`call_only` for each) reach the SAME implementation through `ExecutionContext::resolve_local_call` (`../context/execution.rs`, delegating to `prim_tty::serves_local_call`).
**Served faithfully:** `isatty/1` (a real `IsTerminal` probe of the std stream); `tty_create/1` (an opaque round-trippable `#Ref<…>` handle in `Runtime::prim_tty_handles`; `stdin`, a non-std atom and an unknown handle are `badarg`); `tty_init/2` (a non-terminal ofd answers the C's `{error,enotsup}` for a `raw` request, `ok` otherwise); `tty_encoding/1` → `utf8`; `setlocale/1` → `primitive`; `sizeof_wchar/0` → `4`; `tty_window_size/1` and `tty_is_open/2` (a `/proc/self/fd/N` liveness probe on Linux, `true` elsewhere); `write_nif/2` and `read_nif/3` (real stdout/stderr writes, a bounded 1024-byte-capped stdin read); `tty_select/2` (the C's `enif_get_resource` check **before** anything is armed, then a one-shot read interest on the C's hardcoded fd `0` through the port layer's one select store — [`../port/select.rs`](../port/select.rs), whose `arm_tty_select` is the `tty_select_nif` argument list — with `enif_select`'s answer discarded, answering the atom `ok`); the no-`HAVE_TERMCAP` family `setupterm_nif/0`, `tinfo_nif/0`, `tigetnum_nif/1`, `tigetflag_nif/1`, `tigetstr_nif/1`, `tputs_nif/2` → `{error,enotsup}`.
**Typed capability gaps** (never a fabricated value): `isprint/1`, `wcwidth/1`, `wcswidth/1` (libc's locale/Unicode width tables have no faithful safe-std equivalent — `libc::wcwidth` is `unsafe`); the **terminal-present** arm of `tty_window_size/1` (`TIOCGWINSZ` unavailable in safe std) and the **raw-mode** arm of `tty_init/2` (no safe-std termios).
**Fidelity deviation, recorded honestly — not oracle parity.** The system oracle is built **with** termcap (its `tinfo()` a full terminfo map, `tigetnum($k)` → `-1`, `tigetflag` → `false`, `tigetstr` → `{'EXIT',{badarg,…}}`, `tputs` → `{ok,<<"clear">>}`), where this runtime answers the C's no-`HAVE_TERMCAP` arm (`{error,enotsup}`, returned *before* inspecting any argument) for that whole family: ncurses terminfo state is not reproducible from safe Rust, and the arm is non-raising, which `prim_tty:init/1`'s `setupterm() =:= ok` check requires.
### `erl_ddll:*` — one loaded-driver list (A.4) — `ddll.rs`
`RuntimeContext::ddll_call(function, arity, args) -> Option<Result<Eterm>>`; `beam_bifs` registers six `erl_ddll` keys over its **own** loaded-driver registry, which this crate's port machinery never reads, so the floor serves the four list/load/unload/report keys from the **one** name-keyed registry the ports really use ([`crate::port::driver`](../port/driver.rs)'s `LOADED_DRIVERS`, filled by `record_driver_loaded` from an `erl_ddll:try_load/3` and by `note_driver_opened` from an `open_port({spawn_driver, …})`) — `erl_ddll:loaded_drivers/0` **is** the list `open_port({spawn_driver, Name})` resolves a name against.
Dispatched before `call_registered`, those four keys **shadow** `beam_bifs`'s same-named registry keys; `monitor/2`, `demonitor/1` and `format_error/1` deliberately return `None` and stay with `beam_bifs` — claiming them would duplicate its `errint`→text table and mint monitor references against a driver list the monitor machinery does not read.
| BIF | Oracle answer |
|---|---|
| `erl_ddll:loaded_drivers/0` | `{ok, [Name, …]}` — each name a charlist: the three **statically linked** built-ins first (`tcp_inet`, `udp_inet`, `ram_file_drv`, that order), then the dynamically loaded names in load order |
| `erl_ddll:try_load/3` | `{ok,loaded}` / `{ok,already_loaded}` / `{error,{open_error,-10}}` / `{error,Reason}`; a statically linked name → `{error,linked_in_driver}` |
| `erl_ddll:try_unload/2` | `ok` / `{error,not_loaded}`; a statically linked name → `{error,linked_in_driver}` |
| `erl_ddll:info/2` | the item value of a **known** name (a statically linked one takes the `handle == NULL` branch below); `badarg` for an unknown name or item |
**Error mapping** (mirroring `beam_bifs`'s `load_error_tuple`): a `DriverLoadError` whose reason is a fixed `errcode_tab` code becomes the **bare reason atom**; a failed `dlopen` becomes `{open_error, -10}` (`ERL_DE_DYNAMIC_ERROR_OFFSET`); a malformed argument or option is `badarg`, never a fabricated result.
**The three statically linked built-ins are one derived view** — `port::driver::static_drivers()`, the C `driver_list` entries with `handle == NULL` (`tcp_inet`/`udp_inet`/`ram_file_drv`), whose membership is `beam_io::STATIC_SPAWN_DRIVERS` (also the gate `open_port({spawn_driver, Name})` resolves against) and whose *arrangement* is `DRIVER_TAB_ORDER`: they are listed FIRST by `loaded_drivers/0`, a static name's `try_load/3`/`try_unload/2` answers `{error,linked_in_driver}` (`erl_bif_ddll.c:281-285`, `:545-547`), and its `info/2` takes the C's `handle == NULL` item branch (`erl_bif_ddll.c:728,743,752,775`) — `linked_in_driver` → `true`, `permanent` → `false`, and `port_count`/`driver_options`/`processes`/`awaiting_load`/`awaiting_unload` → the ATOM `linked_in_driver` (any other item `badarg`).
A **dynamically** loaded driver's answers are unchanged (load order, `linked_in_driver` → `false`, `port_count` → `0`, `processes` → `[{Pid,1}]`).
**Divergences** (own-state, never a fabricated value): `open_port({spawn_driver, Name})` auto-`dlopen`s an unloaded name (a `/`-containing name is the object path, the driver name its file stem) where the oracle answers `badarg`; `try_unload/2` is an immediate `ok` rather than the C's `{ok,pending_process}`/`{ok,pending_driver}` state machine (forgetting an entry only drops it from the list — a live port keeps its driver working); opening a `try_load`ed driver re-`dlopen`s the object, so the entry's `init` runs once per open rather than once per load; a loaded driver's monitor subscription is not delivered.
### `file_server_2` — the native file service (A.9)
`file_server.rs` + `file_server/` own the runtime-native **file service**: the `file_server_2` service process (never enqueued, drained by the scheduler-pass step `Runtime::service_file_requests` in `../runtime/scheduler.rs`), its per-`open` native io-devices, and the `gen_server`/`file`/`io` request/reply wire.
`Runtime::new` consults `RuntimeConfig::drives_a_boot_script()`: whenever it holds (every CLI action but `-version`, plus an explicit `-boot FILE`) the service is spawned **unregistered** (`FileServices::start_unclaimed`), because that route's booted `kernel_sup` starts OTP's own `file_server_2` child and owns the name; a runtime driving no boot script registers it under the atom `file_server_2` (`FileServices::start`).
**The process model, the scheduler-pass step, the served-request surface (`{write_file,…}`/write-mode `{open,…}`/`{get_until,…}`/`{get_line,…}`, the `getopts`/`setopts` read-mode surface and the `{read_handle_info, Opts}` `#file_info{}` reader), the wire tables and the tests are [`file_server/CONTEXT.md`](file_server/CONTEXT.md)'s.**
### The runtime-native `net_kernel` service (A.5) — `net_kernel.rs`
`net_kernel.rs` owns the runtime-native **`net_kernel` service**: a `beam_process::Process` spawned `Runnable`, registered as `net_kernel` and never enqueued, drained by the scheduler-pass step `Runtime::service_net_kernel` right after `service_file_requests`.
**It exists only on a distributed node** — `Runtime::new` starts it when its `dist` half is `Some` (a `-name`/`-sname` config) and leaves `None` otherwise, so a non-distributed runtime registers no name and spawns no process.
**Dispatch table (one entry):** `{'$gen_call', From, {is_auth, _Node}}` on the registered `net_kernel` service is answered the atom **`yes`** (`net_kernel.erl:1229-1230` answers unconditionally — the request carries the *caller's* node, `net_adm.erl:104-108`, so a comparison would answer `no`); a malformed `{is_auth}` (arity ≠ 2) and the bare atom are answered `no`.
**Every other request is the typed `unsupported: net_kernel: <request> is not served` gap**, never a silent drop — a dropped `gen:call` parks its caller in an untimed `receive`, which is the defect this service removes.
That gap is **fatal to the whole node**, not to one caller: `service_net_kernel` returns the `Err` and `../runtime/scheduler.rs`'s pass breaks on it, so a peer that addresses any non-`{'$gen_call', From, Request}` term (a plain `hello`), a malformed `From`, or an unserved request to the registered `net_kernel` name terminates the runtime with `beam_rt: unsupported: …` (exit 3) — unlike a malformed *transport* frame, which only retires that one link (see `../dist/CONTEXT.md`).
**The reply reproduces `gen:reply/2`'s three clauses** (`gen.erl:547-553`): `{To,[alias|Ref]}` and `{To,[[alias|Ref]|_]}` send `{Tag, Reply}` to `Ref` through `Runtime::dist_send_alias` (the outbound `DOP_ALIAS_SEND`), with the tag echoed unchanged (the nested form echoes the whole outer list); any other `{To, Tag}` delivers `{Tag, Reply}` to `To` — a local pid through `RuntimeContext::deliver_in_table` (a dead caller's `TermNotFound` is dropped, as `gen:reply/2`'s `catch` does), a remote pid through `Runtime::dist_send_message_pid`.
**A reference on this node is not a local alias** (this runtime keeps no local alias table), so it takes the send path's own typed error rather than a fabricated delivery.
### The `io` device floor (`io.rs`) — the request wrappers, served natively
`io:put_chars/1,2`, `io:nl/0,1`, `io:fwrite/1,2,3`, `io:write/1,2` and `io:format/3` are `io.erl` wrappers over `o_request/2` (`io.erl:160-207`) whose device is the caller's `group_leader()` — this runtime's own root process, so `execute_request/3` answers `{error, calling_self}` (rationale: `../M1_GAPS.md` *Printing*) — and the floor serves them itself, answering the device question through `RuntimeContext::io_device`/`io_stream` and rendering through the **registered** `io_lib:format/2` (the implementation `io.erl`'s own server calls for a `{format, …}` request), so the request never leaves the runtime.
The device rules (oracle OTP 29.1.1 / erts-17.1; shared by **every** device-taking arm, `io:put_chars/1,2` included): omitted / `standard_io` (`request/3` rewrites it to `group_leader()`) / `user` / the caller's **own** group-leader pid ⇒ the process's output stream; `standard_error` (or its registered pid) ⇒ **fd 2**; another **live registered** device pid ⇒ the typed `unsupported` (a BIF may not block on the round trip); an **unregistered** atom ⇒ `error:badarg`; a non-atom/non-pid ⇒ the bare `function_clause`; the device is resolved **before** the character/format payload is read. Pinned end to end against the live oracle by `../../tests/io_device.rs` (the device differential) and `../../tests/io_diagnostic_unmask.rs` (the installed compiler's `catch`-handler diagnostic prints rather than raising `error:calling_self`).
## Constraints
- **`#![deny(unsafe_code)]`** — the crate-wide rule covers this whole floor. Terms are built and read only through `beam_engine::terms` (heap-seam builders/readers), `beam_codec::term` (`&mut beam_alloc::Heap` materializers), `beam_loader::container` (read-only container parsing) and `beam_term`; the parent's `render` drives the registered `io:format/2` printer rather than a private one.
- **Return-based errors** (workspace `../CONTEXT.md` §3): `Option<Result<Eterm>>`, never a crate-local error enum, never `panic!`/`unwrap()` on runtime data, never a silent swallow. A "value atom" answer the C *returns* (`badarg`, `big`, `no_integer`, `not_a_list`) is `Ok(atom)`.
- **Consulted before the registry.** A native entry must never shadow or duplicate a `beam_bifs` BIF, with one deliberate exception: the four `erl_ddll` list/load/unload/report keys shadow `beam_bifs`'s same-named registry keys so that the driver list `open_port({spawn_driver, Name})` reads and the one `erl_ddll` reports stay a single view (see the `erl_ddll:*` section). The `erlang`-namespace fallback classifies a known-unimplemented name as the capability gap (`unsupported: …`, CLI exit 3) and anything else as the bare `error:undef`.
- **`code:*` is the native floor, and the floor's `CodeServer` owns the ONE authoritative code path** — `code.rs`'s behaviour must not change (see `../CONTEXT.md`; a live `code_server` process does run on the boot-driven routes, but it keeps a second path store, so the floor serves the path readers **and** the `code/path.rs` mutators out of `CodeServer` — the store this runtime really searches — and only the un-migrated `code.erl` mutators still edit that second store).
- **The child nodes own their families' detail** — `memory/`, `process/`, `erts_internal/`, `file_server/` — and the dispatch table stays `../native.rs`'s alone: a child doc may name its own arms but never a second dispatch list.
- **Files ~1000 lines of production code.** The pre-existing oversize files (`application.rs`, `process.rs`, `prim.rs`, `prim_file.rs` — **no colocated tests**, its fd half exercised through `prim.rs` — and `erts_internal.rs`, its tracing half split into `erts_internal/trace.rs`) are single-responsibility and kept whole; every public item documented.
## Test Strategy
- **Unit tests** are colocated per module (`#[cfg(test)] mod tests`) and drive the floor through the crate's own dispatch (`test_support::call` ⇒ `RuntimeContext::call_bif` ⇒ `try_native`), so the *served surface* is pinned, not an internal function; fixtures live once in `test_support.rs`.
  The per-family suites are their child docs' — `memory/CONTEXT.md` (`process_info`, its oracle-probe bounds, the never-a-live-oracle `garbage_collection` rule), `process/CONTEXT.md`, `erts_internal/CONTEXT.md` and `file_server/CONTEXT.md`.
- **Oracle values** are quoted in each test's doc comment (re-verified against the system `erl`, OTP 29.1.1 / erts-17.1), and where the runtime answers a typed capability gap the oracle answers a value, the test pins the `unsupported` outcome with a `// documented divergence:` comment. `get_dflags/0` is pinned by byte-comparing the built term's `term_to_binary/1` image; `prim.rs`'s file-system entries run against a real per-test scratch dir; fixtures needing a real `.beam` or the system Erlang skip **loudly** (`system_runtime()` / the file-local `lists_beam()`).
- **The only external toolchains ever spawned in this node are `erl` and `erlc`** — no `escript`/`cc`/`gcc`/`clang` invocation exists under `src/native/`, and `erlc` appears in exactly one place (`memory/binary_e2e.rs`, which compiles its end-to-end fixture at test time so no path-dependent artifact is committed). Every live-oracle comparison compares the oracle's **stdout** (`~p`/`~w`/`~s` rendering) or its exit status; none compares `term_to_binary` bytes.
- **Suites that spawn the live `erl` oracle in-process** (skip **loudly** when absent). Unless annotated with `$ERTS_ORACLE`, a site resolves `erl` by a **bare `$PATH` lookup only**; the `memory/` sites' bounds are `memory/CONTEXT.md`'s, and the rest are:
  * `code.rs`'s `oracle_probe` (over `oracle_erl()`, `$ERTS_ORACLE` else `$PATH`, `.output()`, **unbounded**, argv `-noshell -eval … -s init stop`) — loud skip via `skip_oracle_loudly()` (no arg); gated first by `system_runtime()`.
  * `prim.rs`'s `run_oracle` (over `resolve_oracle()`, `$ERTS_ORACLE` else `$PATH`, bounded 30 s / 10 ms poll) — loud skip via `skip_oracle_loudly(why)` (takes a reason string); `the_unserved_prim_file_entries_are_typed_capability_gaps` does NOT spawn the oracle.
  * `file_server/tests.rs`'s `oracle_render`/`compare_with_oracle` (`$ERTS_ORACLE` else `$PATH`, bounded 30 s / 20 ms poll) and `file_server/get_line/tests.rs`'s `run_oracle` (over `resolve_oracle()`, same convention and bound) — both print a multi-line SKIPPED banner; `file_server/get_until/tests.rs` spawns **nothing** (every oracle value there quoted in a doc comment).
- Cross-crate integration (CLI/exit codes, the preloaded `boot/*` corpus, `-eval`) is pinned by the `../tests/` suites: this node's A.9 native-floor surface (`application:get_all_key/1`, `get_key/1,2`, `get_application/0,1`; `init:get_argument/1`'s automatic flags; `init:script_id/0`; `code:lib_dir/2`; the `filelib` existence probes) by `a9_native_floor.rs`; the `init:*` termination/reboot family and `code:load_file/1`'s real load by `native_init.rs` and `code_load_file.rs` (which also pins the same expected-name refusal on the call-like routes: the bare `error:undef` on `-s`/`-run` and at a `spawn(M,F,A)` entry); `code:delete/1`'s live-server round trip on the `-eval` and scheduled routes by `code_delete_live.rs`; and `code:load_binary/3`'s guard/`modp`/`badfile`/sticky/valid-image shapes plus its recorded-filename `which`/`is_loaded`/`all_loaded` observations by `code_load_binary.rs` (oracle-cross-checked; the oracle's own refusal **report** on stdout is matched *within* its stdout).

## Not implemented — the `erts_internal` / `prim_*` BIFs left falling through
Every name not in a table above answers `None` and falls through to the `beam_bifs` registry then a real module load — an honest failure, never a fabricated value.
This list is the one index of the unserved keys; the reasons for the `erts_internal` families are [`erts_internal/CONTEXT.md`](erts_internal/CONTEXT.md)'s and for the process/scheduler controls [`process/CONTEXT.md`](process/CONTEXT.md)'s.
- **The `erts_internal` distribution primitives (A.5 phase 2)** — the connection/channel-negotiation, dist-spawn and dynamic-node-name family: needs the controller protocol, a live node identity and remote spawn. The **`net_kernel` name itself is held** by this crate's native service (`net_kernel.rs`), so a peer's `gen:call` `{is_auth, Node}` is answered here.
- **Tracing, debugger half only** — `trace_session_create/3`, `trace_session_destroy/1`, `trace/4`, `trace_pattern/4`, `trace_info/3`, `notify_breakpoint_hit/3`, the `erts_debug`/`erl_debugger` breakpoint entries, `erts_trace_cleaner:*`: the **process-tracing core IS served**, and the `/4` + `trace_info/3` surfaces would add a flag/match-spec dimension `crate::trace` does not expose.
- **Microstate accounting / scheduler wall time** — needs per-scheduler run-time accounting (the runtime is single-threaded); `erts_internal:scheduler_wall_time/1` itself **is served** by the `RuntimeHooks` bridge.

The connect is the one that also needed the timer surface: `inet:timeout/1` reads the socket's deadline through `erlang:read_timer/1`, which the `RuntimeHooks` bridge now serves, so a closed loopback port answers `{error,econnrefused}` and an in-runtime listener `ok`, as the oracle does. The remaining residuals are *shapes* of the inet data path (the async-op queue's op-id substitution, a completion's recipient), never a wrong socket result — [`../port/CONTEXT.md`](../port/CONTEXT.md) *Known Issues*, `M1_GAPS_A4_PORTS.md` *Ports, drivers and the send family (A.4)*.
- **`prim_*` preloaded driver modules** — the **35** `prim_file` keys listed above are all that is served; every other `prim_file` key and all of `erl_prim_loader`, `prim_inet`, `prim_socket`, `prim_net`, `prim_zip`, `prim_buffer`, `prim_eval` fall through to a preloaded-`.beam` load on the code path whose `-nifs()` entry needs the matching host; `prim_zip:splitter/3` (pure Erlang, error paths not reproduced) is **not** claimed, though `file_server.rs` *does* serve `{list_dir,Name}` over `std::fs::read_dir`; the raw-syscall `fadvise`/`fallocate`/`chmod`/`chown`/`utimes` floor is a **missing `beam_io` facility**.
## Known Issues
### Curated gaps (`../error.rs`; oracle OTP 29.1.1 / erts-17.1)
A `(function, arity)` belongs in `KNOWN_UNIMPLEMENTED_ERLANG_BIFS` **iff** it is an OTP `erlang` BIF the oracle **exports and serves** but this runtime does **not**; a name the oracle itself rejects as `undef` must never be listed (curating one would answer its exit-1 "no such function" with an exit-3 gap).
The set is 17 `(function, arity)` pairs over 10 names: `set_cookie/2` (already served by the floor, inert), `disconnect_node/1`, `port_call/3`, `spawn_request/1,2,3,4,5`, `process_flag/3`, `process_display/2`, `suspend_process/1,2`, `system_monitor/0,1,2`, `load_module/2`, `localtime_to_universaltime/1`.
Most are closable via an `erlang.erl` wrapper arm over an `erts_internal:*` primitive the floor already serves or a registered BIF (`erlang:process_flag/3` ⇒ the **served** `erts_internal:process_flag/3`; `erlang:localtime_to_universaltime/1` ⇒ the **registered** `/2`); the rest need a new facility. Drift guards: `../error.rs`'s `known_unimplemented_bifs_are_capability_gaps_and_never_shadow_the_registry` + `the_effective_gap_set_never_shadows_the_registry`, and `native.rs`'s `every_floor_module_is_a_real_try_native_arm`.
### The Erlang-level distribution supervisor (`erl_distribution:start_link/0,1`)
`kernel_sup`'s distribution child is `{erl_distribution, start_link, []}` (`kernel.erl:262-268`), the same entry `erl_distribution:start/1` invokes from `net_kernel:start/1`; both start a supervisor whose children are the **Erlang socket stack** (`net_kernel:protocol_childspecs/0`, `erl_epmd`, `auth`, `net_kernel`), which cannot run here — no `prim_inet`/`inet_tcp` driver exists and the distribution is the native `crate::dist::DistNode` the CLI binds and publishes to `epmd` itself.
Both keys answer the atom **`ignore`** (how `erl_distribution` expresses "nothing to start": `do_start_link([]) -> ignore` with no `-sname`/`-name` argument) and both are in `floor_keys("erl_distribution")`, so the namespace is key-granular (`init/1`, `start/1`, `stop/0` stay ordinary `.beam` bodies); the measured registered-name divergence is only `net_sup`/`auth` (`undefined` here, live pids on the oracle), because **`net_kernel` IS registered** on a distributed node — by this crate's own `net_kernel` service (`net_kernel.rs`), spawned `Runnable` and drained by `Runtime::service_net_kernel`, which is what answers a real peer's `net_adm:ping/1` (`gen:call` `{is_auth, Node}` ⇒ `yes`) — in `../M1_GAPS.md` *Distribution and the node (A.5)*.
### Recorded gaps and fabricated values
- **`read_file_info/1,2`, `read_link_info/1,2` and `read_handle_info/1,2` ARE served** — trust the `prim_file:*` served list above rather than `prim.rs`'s module-doc "Not served" list — as a real 14-tuple `#file_info{}` whose `access` comes from real `access(2)` probes (`beam_io::path_access` for the path forms, `beam_io::process_credentials` + the mode bits for the handle form); pinned by `tests/a9_native_floor.rs::filelib_existence_probes_on_an_existing_path_agree_with_the_oracle`.
The `file_server_2` **io-device** request `{read_handle_info, Opts}` (`file_io_server.erl:335-342` — what `file:path_open/3`'s non-raw device and `epp`'s `-moduledoc({file,…})` read send) is served by the same builder over the open device's own `Metadata`, so `epp:parse_file/2` completes on such a module.
- **`code:`/`application:` divergences** — a found-but-unreadable `get_object_code/1` candidate is reported as a diagnostic rather than the atom `error`; `load_file/1` answers `{error,nofile}` for a non-sticky module outside `stdlib`/`kernel`/`erts`; the logger report is omitted — for the sticky refusal, for a corrupt image and for `beam_load.c`'s expected-name refusal, whose `{error,badfile}` value **is** produced on every file route; `application:get_application/1`'s non-atom divergence is in the `application` bullet above; the differential corpus' `is_loaded(lists)` cases `ensure_loaded` first.
- `erlang:module_loaded/1` answers this runtime's **own** loaded set — smaller than the oracle's, since an app outside the preloaded `primLoad` batches is not yet loaded here (`../tests/module_loaded.rs`); `../context/process_bridge.rs`'s `process_flag(error_handler, A)` accepts an atom where the oracle raises `badarg` (owner `context/`); every other constant is a truthful default or derives from real state.
