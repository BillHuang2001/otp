# `beam_rt::runtime` — the `Runtime` façade, the scheduler-pass family and the `ProcessRunner`

## Intent
`../runtime.rs` is the `Runtime` façade: the one type that owns every runtime table and the runtime-level operations the CLI, the boot path and the `-eval` evaluator call (`run_function`/`run_module`/`run_scheduled`, the spawn API, `system_info`, `eval`, `format_term`, `refs_mut`, the timer/distribution accessors).
`../runtime/scheduler.rs` (+ `scheduler/tests.rs`) is the **scheduler-pass family**: it drives processes, ports, timers and distribution in bounded steps (the distribution half is **four** steps — the server pump/inbound and the connector's pump/inbound).
`../runner/` (a sibling directory) is the `beam_process::ProcessRunner` each scheduled process runs through; it is documented here because it is the scheduler's own instrument.
`gc.rs` holds the runtime-level GC state, accounting and safety valves, and `ets_owner.rs` the `ProcessExitObserver` host with the two owner-death drains.

## API Surface
### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, the node-global `persistent_terms` store, the native `file_server_2` service — `file_services`, spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus an explicit `-boot FILE`), registered as `file_server_2` otherwise — dist) and the scratch `info_heap`.
The **scheduler-pass family** (`run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`pump_scheduler_boot`/`run_scheduled`, the shared pass body, wake absorption, the port/timer/distribution halves — `pump_dist`/`dispatch_dist_inbound` for the accepting node and `pump_dist_client`/`dispatch_dist_client_inbound` for the connector) lives in `src/runtime/scheduler.rs` (+ `tests.rs`), but every entry point stays an inherent `Runtime` method.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (idempotent; A.7), `boot_from_script(path)` (A.7), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)); `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` loads the file, `spawn_process`es the export and pumps the **full** scheduler in bounded steps (`RUN_STEP_SLICES` = 1000, `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE)`) until the process returns (`x(0)`), **raises** (`take_process_error` returns the original `BeamError`), is quiescent (`scheduler.rs:415`: `ran == 0 && delivered == 0 && is_quiescent()` → the typed `beam_engine::blocked()`), or outlives `RUN_DEADLINE` (60 s); exit-code classification matches the single-pass path. `is_quiescent` (`scheduler.rs:455`) is exactly three conjuncts: `run_queue_len() == 0`, `PortRegistry::has_nothing_to_poll()` (no live port, no armed `tty_select/2` interest *and* no **fired, undrained** signal self-pipe — an armed-but-idle `handle` disposition is not pending work, see [`../port/CONTEXT.md`](../port/CONTEXT.md)), `timers.next_deadline().is_none()`. The `:348` abort is the **only** early exit a bounded pass can reach: the pass sleeps at most **once** (`TimerWait::allows` → `AtMost(_) | AtMostWhenIdle(_) | ImminentWithin(_) => waits == 0`, `scheduler.rs:153`), so `scheduler_pass` always returns `Ok((ran, delivered))` and control reaches the quiescence test.
* **the boot-drive step**: `pump_scheduler_boot(max_slices) -> Result<u64>` is `pump_scheduler` with an **imminent-only** sleep policy (`TimerWait::ImminentWithin(TIMER_PUMP_SLICE = 100 ms)`, `scheduler.rs:74`): the pass sleeps exactly the remaining time when the earliest pending deadline is **within** the window and returns **without sleeping** otherwise (`timer_wait`'s `ImminentWithin` arm, `scheduler.rs:1121`). It is the only entry the boot drives (`../boot/drive.rs`) call — `pump_scheduler` keeps `TimerWait::AtMost` for the `-eval` receive pump, whose bounded-100 ms semantics its `receive` loop relies on, and `run_scheduled` uses the progress-aware `TimerWait::AtMostWhenIdle` (below). Due timers are unaffected (`fire_due_timers` runs before the wait) and a boot-spawned process parked on a short `receive … after T` (T ≤ the window) is still slept to and resumed. The debug trace logs every decision (`timer wait: policy=… remaining=… wait=…`) behind `BEAM_RT_BOOT_TRACE`.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (`spawn/1`), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)`, `run_queue_len()`.
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)`.
* **timers/dist**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()`, and the connector accessors (`dist_client()`, `dist_connected_nodes()`, `dist_connect(peer)`, `dist_send_reg_send`, `dist_send_message_pid`); the scheduler half (`fire_due_timers`, `note_fragment_wake`, `pump_dist`/`dispatch_dist_inbound`, `pump_dist_client`/`dispatch_dist_client_inbound`) is in `scheduler.rs`.
* **the native file service**: the `file_services` field (`FileServices`: the `file_server_2` service process + its live io-devices; `Runtime::new` spawns it **unregistered** whenever `RuntimeConfig::drives_a_boot_script()` holds — every CLI action but `-version`, plus an explicit `-boot FILE` — and registers it under that name otherwise) and `service_file_requests(&mut ProcessTable) -> Result<usize>`, the scheduler-pass step that services them — see [`../native/CONTEXT.md`](../native/CONTEXT.md)'s `file_server.rs` subsection.
* **the runtime's own processes**: `Runtime::new` starts exactly **three** processes, all of them the runtime's own and none spawned by user code — the root process (registered as `init`), the native **`erl_prim_loader`** stand-in (a `beam_process::Process` born `Runnable` and never enqueued, registered under the loader's own name on **every** route that builds a runtime, so `erlang:whereis(erl_prim_loader)` answers a live pid as the oracle's booted node does) and the native `file_server_2` service (above, registered only where it owns the name). The loader's *functions* stay on the native floor (`../native/loader.rs`).

### `runner/` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Wait`; `Err(e)` → record the reason term + the original `BeamError` in `RunnerState`, then `Exit(<reason term>)`. `RunnerState` holds an engine per pid plus the `results`/`exits` maps. **Every park publishes the parked machine's whole live root set into the process — and its live pending-exception reason as the process's extra root — and every resume re-syncs the machine from the process's authoritative root set** (`run.rs::publish_parked_roots` / `resume_from_process_roots`), so a collection driven while the process is parked — `Process::deliver`'s exit cascade is **not** gated by `gc_process_enabled` — can never relocate its heap against a partial root set and leave a stale word in `x` or in the machine's pending-exception slot. A `Wait` **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`Operand::Integer`/`Literal` or a live X-register); a fired deadline resumes at `timeout` delivering nothing and a message-wake cancels it.
Split by responsibility: `runner/entry.rs` (`ProcessEntry`/`ProcessEngine`/`RunnerState`), `runner/run.rs` (`RuntimeRunner` + its `ProcessRunner` impl — one reduction slice), `runner/budget.rs` (`BudgetProbe`/`BudgetContext`), `runner/reason.rs` (`normal`/`exit_reason`/`parked_receive_timeout`/`timeout_delay`), `runner/perf.rs` (`record_baseline_code`) and `runner/tests.rs`; `runner/mod.rs` re-exports the three cross-crate names (`ProcessEntry`, `RunnerState`, `RuntimeRunner`).

### `gc.rs` — the runtime-level GC state
`GcStatsSnapshot` (`gc_stats`) reports collections/failures/halted pids/valve trips **and the `reclaimed` word counter** (words reclaimed by collections), advanced by `Runtime::note_gc_reclaimed(words)` from `serve_gc_request`'s Ok arm and the three collection sites in `../context/gc.rs` (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`), which is what backs `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}` (the full detail of that key lives in [`../context/CONTEXT.md`](../context/CONTEXT.md) and [`../../M1_GAPS.md`](../../M1_GAPS.md) *Memory and statistics*); `GcState` holds the **pin** set (a pid whose heap must not move), the **halt** set (a pid whose collection failed, or whose root-set sizes changed) and the global **valve** (`disabled`, plus the first reason and a trip counter).
`try_stabilize_escaped(term) -> Result<Eterm>` is the **one** escape-store stabilization: it copies a runtime-level store's term onto the pointer-stable arena when a heap may move, propagates a **genuine** copy failure (`BeamError::SystemLimit` — the term does not fit the arena) and trips the valve (`disable_gc`) **only** for the documented off-heap-payload capability gap (an unresolvable **MSO** container, or a malformed graph — a refc binary whose payload no source table owns is **flattened** on-heap instead, `stabilize_term`), returning the original term then. Every runtime-level store goes through it — the pending spawns (`note_pending_spawn`, `runtime.rs`), the native message/function stores (`native.rs`, `native/erts_internal.rs`), the `RuntimeHooks` store (`context/runtime_hooks.rs`) and the runner's exit-reason call site (`runner/run.rs`). Its **machine-aware** sibling `try_stabilize_escaped_with(term, &SourcePayloads)` keeps those two failure classes byte-for-byte but builds the copy's *source* off-heap table from the caller's `SourcePayloads` (the executing machine's `refc_binaries()` unioned with the pid's mailbox-retained handles, `Runtime::source_payloads` / `Runtime::stabilize_term_with`) instead of using the empty one — it pushes the refc-binary handles (`push_binary`) and the MSO handles **in order** (`push`, so each lands on its container term's slot), while the node identities it carries are surfaced but never pushed (the copier re-derives a fresh `NodeEntry` per external thing). So the one caller that holds the machine which built the term (the runner's exit-reason arm, `runner/run.rs`) **shares** a term carrying an **engine-built off-heap binary or MSO container** — one refcount, no materialized copy — where the empty table must flatten the refc binary. `try_stabilize_escaped` is exactly `try_stabilize_escaped_with(term, &SourcePayloads::default())`. `halt_process_gc`/`disable_gc`/`gc_enabled`/`gc_process_enabled(pid)` are the mutators/queries the scheduler and the stores use; a process whose heap may not move is marked **relocation-exempt per slice** on the `Process` itself (the runner's post-slice FR valve), never through a runtime-level pin.
The collection gate is the **two-phase unscanned-root valve** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word and always runs; phase 2 descends the process's root-reachable scanned graph and runs only when the per-pid descent latch `GcState::foreign` is open (`Runtime::foreign_reachable`/`note_foreign_reachable`, sticky and add-only, opened by every event that can put an unscanned container into the process's reachable graph and pruned in `prune_gc_requests`). The reused descent scratch is `GcState::walk` (`WalkScratch`, `Runtime::walk_scratch()`). The **same valve is installed on the process table** as the `beam_process::CollectionGate` host seam (`context/gc_walk.rs::RuntimeCollectionGate`, installed by `Runtime::new`, always descending, owning its own scratch), so the `beam_process` signal sites — which hold only `&mut ProcessTable` — decide identically to the admission points. The gate is a *table* field, so it travels with the table into every scheduler pass.

### `ets_owner.rs` — the `ProcessExitObserver` host and the two drains
`OwnerIndex` (additive, shared with `Runtime`) records, in death order, the dead pids waiting for a drain and the append-only `(PortId, MonitorRef)` `PortWatch` pairs.
`EtsExitObserver` is the `beam_process::ProcessExitObserver`: it pushes the dead pid and its drained `PortWatch` pairs and returns (no BIF borrows the index).
`Runtime::drain_ets_owner_exits` discharges the ETS obligations (delete a dead owner's indexed tables, honour an installed heir), and `Runtime::drain_port_monitor_exits` sweeps the dangling incoming port monitors; both take the borrow with `try_borrow_mut` and **defer** to the next drain on a live borrow — never a panic, never a dropped obligation.
**A failed heir-gift deep copy is never swallowed.** `Runtime::adopt_created_table` re-owns a fresh table's creation-time gift through the fallible `Table::install_heir`; `Runtime::own_heir_gift` returns that error (a `try_borrow_mut` miss, an unknown handle, a missing heir and an arity-2 heir are all `Ok(())`, not failures) and the one policy `Runtime::report_heir_gift_failure` handles it: logged immediately (`beam_error!`, the policy `beam_process`'s exit-observer uses for a panicking observer) **and** recorded in the owner index, so the next `drain_ets_owner_exits` returns it as the typed error it is (`badarg` for a term outside `beam_ets`'s copyable subset, `out_of_memory` for an exhausted store). The successful `ets:new/2` stays successful: the table exists and its gift term is table-owned (the creation-time gift was deep-copied by `Table::new`'s build path before the re-ownership is attempted), and `install_heir` leaves the current heir untouched on failure.

## Constraints
* **`unsafe`-free** (`#![deny(unsafe_code)]`) and return-based errors ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible API returns `beam_common::Result`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field*, so `run_pass` moves both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value** — see the parent node's Design Decisions.
* **Heap lifetime**: `Runtime` owns the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use the separate `info_heap`, reset per call.
* **A pid with no registered engine aborts the whole pass — so a runtime-owned service must never be enqueued.** `ProcessEntry` (`../runner/entry.rs`) has exactly two variants (`Export{module,function,arity}`, `Fun{fun,target}`), and `RuntimeRunner::run` returns the typed `error::unknown_process_entry(pid)` for a pid with no `ProcessEngine` (`../runner/run.rs:208`); `scheduler_pass` propagates it with `break Err(err)` (`scheduler.rs:700`), so an enqueued pid without an engine fails the pass — it is **not** skipped. The escape is the pattern `Runtime::self_pid` (registered as `init`) already uses: create the process with `ProcessTable::spawn(policy)` (born `ProcessState::Runnable`, `insert`ed, **not** enqueued) + `ProcessTable::register(name, pid)`, and leave it `Runnable`. Then `whereis`/`monitor(process,Name)` resolve it, a send lands in its mailbox, and it is never run: only `Waiting`/`Suspended` are woken by a delivery (`Process::wake`, `../../beam_process/src/process.rs:462`), so a `Runnable` service never reaches a run queue's wake list. The runtime's native **`file_server_2` service** (`FileServices`, `../native/file_server.rs`) is exactly such a service — spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus an explicit `-boot FILE`), where the booted `kernel_sup` owns the name, and registered otherwise: `scheduler_pass` calls `Runtime::service_file_requests` as an **additive step right after the run queue drains** (the same place the port half runs), which drains the service's and its io-devices' mailboxes and replies via `ProcessTable::deliver_simple`, then calls `scheduler.resume_woken`; each delivered reply is counted into the pass's `delivered` so a serviced-only pass never looks like "nothing happened" and a boot-path caller resumes. The runtime's own **`erl_prim_loader`** stand-in (`../runtime.rs`) is the same shape — spawned `Runnable` and never enqueued, registered under its own name on **every** route that builds a runtime (nothing in `start.boot` claims it, so it never conflicts).
* **Files ~1000 lines**, split by responsibility; every public item documented (`#![warn(missing_docs)]`).

## Port-aware scheduling (A.4) — design decision & handoff
The pass runs the **port-less** `Scheduler::run_ready` (its port half, `Runtime::deliver_port_messages` + the one persistent poller, owns the polling), and discharges the port-aware slice's obligations **at the pass boundary**, where the port registry is free:
* **covered** — a process that died in the slices just run had its recorded outgoing `(PortId, MonitorRef)` `PortWatch` pairs swept by `Runtime::drain_port_monitor_exits` (`ets_owner.rs`) — the same end state a port-aware termination reaches for its *incoming* entries.
* **covered** — `Runtime::drain_driver_monitor_exits(&mut self, &ProcessTable)` runs immediately before `deliver_port_messages`, sweeping every live C-driver port's monitor tree (`PortRegistry::note_driver_monitor_exits`) and marking each watched pid the table no longer holds, so the same round's port-task probe fires the entry's `process_exit`; it is a scan of the live `ProcessTable`, not a second `set_process_exit_observer` (the single observer slot stays `EtsExitObserver`), and it defers with `Ok(0)` on a live registry borrow.
* **not covered** — `ProcessTable::port_closed(&mut self, ports, port, reason)` (a *closing* port notifying its monitors/links). It can only run **at the close site, while the id is still in the table**: `beam_io::PortRegistry::close` releases the id (`ids.release`), and `beam_process::PortTable::close` is `BadArg` afterwards, so a post-hoc drive from a pass boundary is impossible. That site is `crate::port`'s close path (`RuntimePorts`, reached from `beam_bifs`'s `PortHook::close_port`), outside this node.
`Runtime::with_port_table(&self, &mut ProcessTable, f)` is the intended **short-borrow seam** for such a caller (it `Rc::clone`s the port field, so the returned `RefMut` borrows the clone and both tables can be borrowed at once; a nested borrow stays the typed `unsupported`, never a panic). The `beam_process::PortTable` seam itself is **sufficient as-is** — `port_closed`/`monitor_port*`/`terminate_with_ports` already take the two tables as disjoint parameters.
**Two routes must not be retried; both are unsound by construction:**
1. **Holding the `Rc<RefCell<PortRegistry>>` borrow across `run_ready_with_ports`.** `open_port`/`port_command`/`port_close` executed *inside* a slice (`RuntimePorts::registry_mut`) `try_borrow_mut` the same cell, so a held borrow degrades every in-slice port BIF to the typed `unsupported` gap; the exercised path is the `run <file.beam>` action and the `event_driver`/`port_recv` fixtures, which open and write ports from inside a scheduled slice.
2. **`mem::replace`-ing the `PortTable` out and leaving a placeholder.** `PortTable` has no `Clone`, and `beam_io::PortRegistry::open`/`register` `insert` into the table they were given, so a nested `open_port` during a slice would silently **overwrite** a live port's `Port`/`PortMeta` (the placeholder being empty does not free number 0) — silent corruption, which this crate forbids.
**Crate change that would make the literal routing (or the port-close drive) sound:** the port table must be reachable as a **handle both the scheduler window and the nested BIF paths share**, not as a field inside the same `RefCell` whose borrow the slice must hold — e.g. `beam_io::PortRegistry` exposing `ids` as its own `Rc<RefCell<PortTable>>` (a slice borrows *that* cell and an in-slice BIF borrows it too, failing only on a genuine re-entry), and/or `beam_io`'s close path driving `ProcessTable::port_closed` at its close site with the process table in hand, **before** `ids.release(id)`.

### Process termination — where a scheduled process is reclaimed, and what is missing for a dying process's owned ports
**A normally-returning scheduled process is reclaimed by `beam_process`'s schedule-out, not by any `beam_rt` code.** `RuntimeRunner::run` (`../runner/run.rs`, the `Ok(EngineRunOutcome::Returned(value))` arm) records the `x(0)` value and returns `beam_process::RunOutcome::Exit(normal(self.runtime))`; `Scheduler::run_slice_inner` (`../../beam_process/src/scheduler.rs:394`) then dispatches to `slice_end`/`slice_end_with_ports`, whose `Exit` arm calls `ProcessTable::terminate`/`terminate_with_ports` — that reclaim is what makes `processes().get(pid)` answer `None` afterwards (`../../tests/scheduler.rs:107,207`). The mechanism runs **only** for a pid the scheduler dequeued, so a `Runnable` process that was **never enqueued** — the `-eval`/`-s`/`-run` action child — is ended by its **own** teardown instead: `../runtime.rs::as_action_process` first copies an `Ok` result onto the pointer-stable store (`Runtime::stabilize_term_with` over `Runtime::source_payloads`, exactly as the runner does for a scheduled process's `x(0)`, so the term outlives the heap that built it) and then calls `ProcessTable::terminate` with the `normal` reason the runner's `RunOutcome::Exit(normal)` carries — `beam_rt`'s pass runs the **port-less** `Scheduler::run_ready`, so the `None`-ports `ProcessTable::terminate` branch is the one it mirrors. It must be `terminate`, not a silent `ProcessTable::remove`: the removal would skip the death itself (the exit observer/ETS-owner drain, the name/link/monitor teardown) and the result copy is what keeps the returned `Eterm` from dangling (`../../tests/action_result.rs`). `ProcessTable::spawn` installs a **naked** process (no serial link, no monitor, no group leader); `Runtime::spawn_process_with_policy` adds only a group-leader entry, and `as_action_process` calls `spawn` + `set_group_leader` — so nothing binds the action child to `init`. (The runtime's root process does **not** trap exits: nothing ever calls `set_trap_exit(true)` on `self_pid`.)
**No path in `beam_rt` closes a dying process's *owned* ports.** `ProcessTable::terminate_into` drains the dying process's links, monitors and port *monitors* and resolves their peers, but it never closes a port the process **owns** (in the oracle a normal exit closes them with reason `normal`). `ProcessTable::port_closed(&mut ports, id, reason)` is the API that would notify a closing port's monitors/links, and it is called today **only from `beam_process` tests** — never from production `beam_rt`. Closing exactly one pid's ports would require enumerating them: the authoritative owner table is `beam_process::PortTable` (`beam_io::PortRegistry::port_table_mut()` / `RuntimePorts::port_table_mut()`), which stores `owners: HashMap<PortId::number, ProcessId>` with a forward `owner(id) -> Option<ProcessId>` but **no reverse `owner → [PortId]` index and no allocated-id iterator**; a caller would need a new reverse index (or an id iterator) and then, per owned port, the runtime close path (`RuntimePorts::close` / `PortHook::close_port`, `../port.rs`) plus `ProcessTable::port_closed`.

## Distribution (A.5) — inbound validation and the unrouted families
**Every inbound delivery is validated against its own link.** Both production inbound drives — the
accepting node (`dispatch_dist_inbound` → `dist::DistNode::dispatch_inbound`) and the connector
(`dispatch_dist_client_inbound` → `dist_client::DistClient::dispatch_inbound`) — drain each link through
`beam_dist::ConnectionDriver::dispatch_inbound_checked`, so a control message is checked against **that**
link's own `peer_name()`/`our_name()` identity (the per-link `LinkIdentity`) before it can reach a
mailbox: `beam_dist`'s `Delivery::classify_validated` reproduces the C's per-opcode `invalid_message`
shape checks (`dist.c`) plus the per-link anti-spoof check `dep != external_pid_dist_entry(from)`. The
identity is interned into the **same** `AtomTable` the message was decoded against, so the node
comparison is a raw term `==`. A validation failure is an `Err` — a **link-level** failure that never
reaches `beam_dist::InboundSink`: the drive retires (kills) **just that link**
and records the reason in `DistNode::last_link_error`, the C's `invalid_message` connection kill, never a
pass failure. The check cannot live in `LocalDeliverySink`: one sink is built per pass and shared by
every link, so it has no peer to compare a `From` against.
`Runtime::dispatch_inbound` (the explicit single-driver seam) deliberately stays on the *classify-only*
`ConnectionDriver::dispatch_inbound`: its caller supplies an arbitrary hand-built driver whose handshake
names need not be this runtime's node identity, so a per-link check there would judge a message against a
*foreign* identity. It is the semantic view, not a wire drive.

**`LocalDeliverySink` routes the message families plus the route-free receipt families; the rest is the
honest `DeliveryOutcome::Unsupported`**, with the still-missing API named at its arm (`../dist.rs`'s
`LocalDeliverySink::deliver`). `beam_process` exposes the **outbound** relationship entry points
(`ProcessTable::link_term`/`unlink_term`/`monitor_term_with_options`/`demonitor`/`send_exit_term`, each
routing a `DistSignal` through the installed `DistSignalRouter`) **and** the **route-free receipt**
counterparts, which install/drop the local record and then follow the C's `break; /* Done */` (`dist.c:2258`)
without echoing the opcode it received:

| Inbound family (C arm) | Receipt API used (or the still-missing API) |
|---|---|
| `Link` (`DOP_LINK`, `dist.c:2224-2275`) | **routed** — `record_remote_link(to: ProcessId, remote: RemotePid)` (record-only; the C never echoes one) |
| `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` (`dist.c:2760`/`:2824`) | **routed** — `apply_remote_exit_signal(to, from: RemotePid, reason, untrappable)` (`untrappable = true` for the `Exit2`/`PayloadExit2` family) |
| `UnlinkId`/`UnlinkIdAck` (OTP-26+ handshake, `dist.c:2284`/`:2315`) | **partially routed** — `unlink_from_remote(..)`/`unlink_ack_from_remote(..)`; an inbound `DOP_UNLINK_ID` with `id != 0` owes a `DOP_UNLINK_ID_ACK` this sink has **no reply channel** to emit, so the link record is dropped and the wire half is reported the typed `Unsupported` (`id == 0` owes no ack and is `Delivered`) |
| `Monitor`/`Demonitor` (`DOP_MONITOR_P`/`DOP_DEMONITOR_P`, `dist.c:2341`/`:2415`) | **routed** — `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)` records the incoming watcher and `demonitor_from_remote_ref(watched, reference: RemoteRef)` removes exactly that record, both keyed by the **whole** peer-minted wire reference (`RemoteWatcherRef::Remote(RemoteRef)`, all-immediate, so two peer-minted references never collapse) |
| `MonitorExit`/`PayloadMonitorExit` (`dist.c:2700-2714`) | **routed** for a DOWN whose reference *this* node minted (the wire image inverts to the recorded `MonitorRef`) — `remote_monitor_down(watcher, watched: RemotePid, reference, reason)`; a name-targeted DOWN or a foreign reference stays `Unsupported` |
| `GroupLeader` (`DOP_GROUP_LEADER`, `dist.c:2889`) | **routed** — `set_group_leader_from_remote(to, from: RemotePid)` |
| `SpawnRequest`/`SpawnReply` (`dist.c:2902-3093`) | **still a typed gap** — needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender + the reservation bookkeeping); a `beam_rt` CLI process serves no spawn requests and holds no reservations |
| `Other(Dop::Unlink)` | **still a typed gap** — `DOP_UNLINK` is not a v6 opcode; the C's `invalid_message` arm kills the connection (`dist.c:2277-2282`), which the link driver owns, so the sink reports "recognised, not routed" |

Evidence for the validated path: `../../tests/dist_delivery.rs`'s
"(6b) Every inbound delivery is validated against **its own link**" — a forged `DOP_REG_SEND` (`From` a
non-pid) and a `DOP_LINK` whose `From` names a third node are each refused, reach no mailbox and retire
their link with a recorded `last_link_error`, while a well-formed message on the same link still delivers.

### The node's public surface (both halves)
`DistNode` is the *accepting* half: `start(configured, cookie)` **binds** a wildcard listener
(`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error) and the first `pump()`
**publishes** the node to `epmd` (`ALIVE2_REQ`). Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/
`is_short_name()`/`port()`/`creation()`/`is_registered()`/`is_alive()`/`registration_error()` (recorded,
never raised)/`connections()`/`is_idle()`/`last_link_error()`. `NodeName::parse` splits a `-name`/`-sname`
value into `full`, `advertised` (the full `node@host` name in **both** cases — a peer resolves it with
`list_to_existing_atom/1` and aborts on a bare short name) and `epmd` (the short name for `-sname`,
verbatim for `-name`; a bare value's host is `local_hostname()`); `resolve_cookie(init_args)` is
`-setcookie`, else `$HOME/.erlang.cookie`, else `nocookie`. `DistConnection` wraps one accepted socket in
a **server-side** `beam_dist::ConnectionDriver` (`'N'` → `'s'`/`'S'` → `'r'` → `'a'`); `pump()` registers
once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections non-blocking, then steps every link under a
per-link `DIST_READ_SLICE` (25 ms) read timeout, so one pump can never stall the scheduler (a link's
protocol/write failure **retires** it and records why). The scheduler pass drives it from
`Runtime::dispatch_dist_inbound`, **gated by `Runtime::inbound_delivery`** (default **ON**); the pass
early-returns unless the runtime **is** a distribution node **and** that node has an established link, so a
`nonode@nohost` run pays one bool test per pass and allocates nothing.
The **envelope rule**: the mailbox `from` is always an **immediate** (`envelope_from` — the sender peer's
node atom when the wire carried a sender pid, otherwise the word the peer put on the wire, `''` for the
plain `DOP_SEND*` forms); a non-immediate is refused, because `beam_message` gathers only each queued
message's payload as a GC root. `LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes
`Delivery::Send`/`RegSend` through `ProcessTable::deliver_simple` (which wakes a blocked receiver; an
unregistered name / a non-pid `to` follow the oracle's RegSend/Send arms) and `Delivery::AliasSend`
through the table's alias resolution (consuming a `reply_demonitor` alias after a successful delivery; an
unknown/inactive reference is the oracle's silent drop), plus the **plain** `Delivery::AltactSigSend`
message sub-cases.

`DistClient` / `ClientLink` / `DistClientInner` / `DistRouter` (`../dist_client.rs`) are the *connecting*
half: `connect`/`connect_addr` dial a peer and run the **client** `beam_dist::ConnectionDriver` handshake
(`DIST_CONNECT_TIMEOUT`); `pump` is the one place a live `DOP_*` is encoded (atom-table encode + socket
write), with `send_reg_send`/`send_message_pid`/`is_connected_to_node`/`connected_nodes`/`last_error` as
its accessors; `DistRouter` implements `beam_process::DistSignalRouter` — it materialises a signal's terms
on a stable scratch heap and queues `{node, Dop, args}`, which `pump` then drains — and is installed on
the **`ProcessTable`** (`../runtime.rs`), not the `Runtime`, because the table is moved out for every pass.
There is **no** `{setup,…}`/`{nodeup,…}` control exchange in OTP distribution: after the final `$a`
handshake ACK the link carries `DOP_*` immediately, and node-up is local bookkeeping
(`net_kernel:mark_nodeup`). Driven from `Runtime::pump_dist_client` and
`Runtime::dispatch_dist_client_inbound`.

## Known Issues
* **Quiescence blind spot: a retired native io-device is never drained again.** `scheduler_pass`'s native-service step drains exactly `FileServices::server()` + `file_services.devices.keys()` (`../native/file_server.rs`). When `serve_file_message` sees `retire == true` it does `file_services.devices.remove(&service)`, so a still-live device pid holding a queued request vanishes from the drain list. The reply is never delivered, the parked sender is never woken, and on the next pass `ran == 0 && delivered == 0 && is_quiescent()` holds — `run_scheduled` then returns `beam_engine::blocked()` (exit 3) even though a wake source still has work. `is_quiescent` is not itself wrong; the wrongly-holding premise is "no drainable service has work" while a *retired* device does. Reproduced with `epp:parse_file/2` from a scheduled `run` process. The `retire` flag itself is a false positive: `get_until::EngineContinuation::apply` sets `raised = true` on **any** `Err`, including the typed gaps `unsupported("… continuation suspended in a receive")` (`../native/file_server/get_until.rs:317-319`) and `unsupported("… returned neither {more,Cont} nor {done,Result,Buf}")`, not only on a genuine scan raise (observed genuine raise: `error:function_clause` in `erl_scan:options/1` from `erl_scan:tokens/4`). Fix belongs in `../native/file_server.rs` (keep draining a retired pid, or reproduce the OTP close-handshake ordering), **not** in this node.
* **`delivered` does not count ordinary Erlang `send`.** Only port/timer/file-service/ETS/dist deliveries are counted (`scheduler.rs:719-849`), so a pass whose only progress is a plain message wake can look like `delivered == 0`.
* **The `run` route's pass wait is progress-aware; a pass that still has slices to run never sleeps.** `pump_run_to_completion` passes `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)` (`scheduler.rs:410`) and `timer_wait` returns `None` for it whenever the round that just ended **ran at least one slice** — `let progressed = round_slices > 0;` (`scheduler.rs:866`), fed by the round's own `run_ready` count — so the arm is `(!progressed).then(|| remaining.min(max))` (`scheduler.rs:1118`), still gated by `TimerWakes::can_wake(run_wake_pid)`.
  The guard is what keeps a budget-exhausted pass from sleeping: `run_ready_inner` breaks at the pass's slice budget (`RUN_STEP_SLICES`, `beam_process/src/scheduler.rs:514`) with the run queue still non-empty, so such a pass would otherwise sleep a full 25 ms immediately before its own budget check ends it — pure waste on a single-threaded pass.
  The unchanged half is the anti-spin sleep, pinned by three `scheduler/tests.rs` cases: `the_run_route_still_sleeps_to_a_parked_receive_timeout` (a `receive … after 20` on the `run` route still sleeps to its deadline — counter ≥ 1, i.e. it sleeps rather than spins — and still resumes on the timed-out path), `the_run_route_never_sleeps_a_poll_slice_while_it_still_has_slices_to_run` (`pass_sleeps() == 0` while the target is runnable) and `the_idle_only_wait_policy_skips_the_wait_when_the_round_ran_slices` (the policy table itself).
  The counter is the test-only per-thread `PASS_SLEEPS` (`pass_sleeps`/`reset_pass_sleeps`), so both halves are pinned structurally, never by wall clock.
  Measured on a `send_recv:plain/1` ping-pong (`receive … after 30000`), N = 20000: **0 `clock_nanosleep`** on both the default native-baseline tier and `BEAM_RT_TIER=interpreter`.
  The `tools/bench` figure for the `copy_bound` case `send_recv_plain` predates the progress-aware wait and is due for a refresh (owner `tools/bench`).
