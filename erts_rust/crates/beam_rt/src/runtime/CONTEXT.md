# `beam_rt::runtime` — the `Runtime` façade, the scheduler-pass family and the `ProcessRunner`

## Intent
`../runtime.rs` is the `Runtime` façade: the one type that owns every runtime table and the runtime-level operations the CLI, the boot path and the `-eval` evaluator call (`run_function`/`run_module`/`run_scheduled`, the spawn API, `system_info`, `eval`, `format_term`, `refs_mut`, the timer/distribution accessors).
`../runtime/scheduler.rs` (+ `scheduler/tests.rs`) is the **scheduler-pass family**: it drives processes, ports, timers and distribution in bounded steps.
`../runner/` (a sibling directory) is the `beam_process::ProcessRunner` each scheduled process runs through; it is documented here because it is the scheduler's own instrument.
`gc.rs` holds the runtime-level GC state, accounting and safety valves, and `ets_owner.rs` the `ProcessExitObserver` host with the two owner-death drains.

## API Surface
### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, the node-global `persistent_terms` store, the native `file_server_2` service — `file_services` — dist) and the scratch `info_heap`.
The **scheduler-pass family** (`run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`run_scheduled`, the shared pass body, wake absorption, the port/timer/distribution halves) lives in `src/runtime/scheduler.rs` (+ `tests.rs`), but every entry point stays an inherent `Runtime` method.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (idempotent; A.7), `boot_from_script(path)` (A.7), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)); `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` loads the file, `spawn_process`es the export and pumps the **full** scheduler in bounded steps (`RUN_STEP_SLICES` = 1000, `TimerWait::AtMost(PORT_POLL_SLICE)`) until the process returns (`x(0)`), **raises** (`take_process_error` returns the original `BeamError`), is quiescent (empty run queue, **nothing left to poll** — no live port *and* no registered signal watch, `PortRegistry::has_nothing_to_poll()` — and no pending timer deadline), or outlives `RUN_DEADLINE` (60 s); exit-code classification matches the single-pass path.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (`spawn/1`), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)`, `run_queue_len()`.
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)`.
* **timers/dist**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()`; the scheduler half (`fire_due_timers`, `note_fragment_wake`, `pump_dist`) is in `scheduler.rs`.
* **the native file service**: the `file_services` field (`FileServices`: the registered `file_server_2` process + its live io-devices) and `service_file_requests(&mut ProcessTable) -> Result<usize>`, the scheduler-pass step that services them — see [`../native/CONTEXT.md`](../native/CONTEXT.md)'s `file_server.rs` subsection.

### `runner/` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Wait`; `Err(e)` → record the reason term + the original `BeamError` in `RunnerState`, then `Exit(<reason term>)`. `RunnerState` holds an engine per pid plus the `results`/`exits` maps. **Every park publishes the parked machine's whole live root set into the process, and every resume re-syncs the machine from the process's authoritative root set** (`run.rs::publish_parked_roots` / `resume_from_process_roots`), so a collection driven while the process is parked — `Process::deliver`'s exit cascade is **not** gated by `gc_process_enabled` — can never relocate its heap against a partial root set and leave a stale word in `x`. A `Wait` **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`Operand::Integer`/`Literal` or a live X-register); a fired deadline resumes at `timeout` delivering nothing and a message-wake cancels it.
Split by responsibility: `runner/entry.rs` (`ProcessEntry`/`ProcessEngine`/`RunnerState`), `runner/run.rs` (`RuntimeRunner` + its `ProcessRunner` impl — one reduction slice), `runner/budget.rs` (`BudgetProbe`/`BudgetContext`), `runner/reason.rs` (`normal`/`exit_reason`/`parked_receive_timeout`/`timeout_delay`), `runner/perf.rs` (`record_baseline_code`) and `runner/tests.rs`; `runner/mod.rs` re-exports the three cross-crate names (`ProcessEntry`, `RunnerState`, `RuntimeRunner`).

### `gc.rs` — the runtime-level GC state
`GcStatsSnapshot` (`gc_stats`) reports collections/failures/halted pids/valve trips; `GcState` holds the **pin** set (a pid whose heap must not move), the **halt** set (a pid whose collection failed, or whose root-set sizes changed) and the global **valve** (`disabled`, plus the first reason and a trip counter).
`try_stabilize_escaped(term) -> Result<Eterm>` is the **one** escape-store stabilization: it copies a runtime-level store's term onto the pointer-stable arena when a heap may move, propagates a **genuine** copy failure (`BeamError::SystemLimit` — the term does not fit the arena) and trips the valve (`disable_gc`) **only** for the documented off-heap-payload capability gap, returning the original term then. Every runtime-level store goes through it — the pending spawns (`note_pending_spawn`, `runtime.rs`), the native message/function stores (`native.rs`, `native/erts_internal.rs`), the `RuntimeHooks` store (`context/runtime_hooks.rs`) and the runner's exit-reason call site (`runner/run.rs`). Its **machine-aware** sibling `try_stabilize_escaped_with(term, src_binaries)` keeps those two failure classes byte-for-byte but builds the copy's *source* off-heap table from a running machine's payload handles (`Runtime::stabilize_term_with`) instead of using the empty one — so the one caller that holds the machine which built the term (the runner's exit-reason arm, `runner/run.rs`) stabilizes a term carrying an **engine-built off-heap binary** correctly instead of tripping the valve over a payload the empty table could not resolve. `try_stabilize_escaped` is exactly `try_stabilize_escaped_with(term, &[])`. `pin_process`/`halt_process_gc`/`disable_gc`/`gc_enabled`/`gc_process_enabled(pid)` are the mutators/queries the scheduler and the stores use.

### `ets_owner.rs` — the `ProcessExitObserver` host and the two drains
`OwnerIndex` (additive, shared with `Runtime`) records, in death order, the dead pids waiting for a drain and the append-only `(PortId, MonitorRef)` `PortWatch` pairs.
`EtsExitObserver` is the `beam_process::ProcessExitObserver`: it pushes the dead pid and its drained `PortWatch` pairs and returns (no BIF borrows the index).
`Runtime::drain_ets_owner_exits` discharges the ETS obligations (delete a dead owner's indexed tables, honour an installed heir), and `Runtime::drain_port_monitor_exits` sweeps the dangling incoming port monitors; both take the borrow with `try_borrow_mut` and **defer** to the next drain on a live borrow — never a panic, never a dropped obligation.
**A failed heir-gift deep copy is never swallowed.** `Runtime::adopt_created_table` re-owns a fresh table's creation-time gift through the fallible `Table::install_heir`; `Runtime::own_heir_gift` returns that error (a `try_borrow_mut` miss, an unknown handle, a missing heir and an arity-2 heir are all `Ok(())`, not failures) and the one policy `Runtime::report_heir_gift_failure` handles it: logged immediately (`beam_error!`, the policy `beam_process`'s exit-observer uses for a panicking observer) **and** recorded in the owner index, so the next `drain_ets_owner_exits` returns it as the typed error it is (`badarg` for a term outside `beam_ets`'s copyable subset, `out_of_memory` for an exhausted store). The successful `ets:new/2` stays successful: the table exists and its gift term is table-owned (the creation-time gift was deep-copied by `Table::new`'s build path before the re-ownership is attempted), and `install_heir` leaves the current heir untouched on failure.

## Constraints
* **`unsafe`-free** (`#![deny(unsafe_code)]`) and return-based errors ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible API returns `beam_common::Result`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field*, so `run_pass` moves both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value** — see the parent node's Design Decisions.
* **Heap lifetime**: `Runtime` owns the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use the separate `info_heap`, reset per call.
* **A pid with no registered engine aborts the whole pass — so a runtime-owned service must never be enqueued.** `ProcessEntry` (`../runner/entry.rs`) has exactly two variants (`Export{module,function,arity}`, `Fun{fun,target}`), and `RuntimeRunner::run` returns the typed `error::unknown_process_entry(pid)` for a pid with no `ProcessEngine` (`../runner/run.rs:108`); `scheduler_pass` propagates it with `break Err(err)` (`scheduler.rs:533`), so an enqueued pid without an engine fails the pass — it is **not** skipped. The escape is the pattern `Runtime::self_pid` (registered as `init`) already uses: create the process with `ProcessTable::spawn(policy)` (born `ProcessState::Runnable`, `insert`ed, **not** enqueued) + `ProcessTable::register(name, pid)`, and leave it `Runnable`. Then `whereis`/`monitor(process,Name)` resolve it, a send lands in its mailbox, and it is never run: only `Waiting`/`Suspended` are woken by a delivery (`Process::wake`, `../../beam_process/src/process.rs:402`), so a `Runnable` service never reaches a run queue's wake list. The runtime's native **`file_server_2` service** (`FileServices`, `../native/file_server.rs`) is exactly such a service: `scheduler_pass` calls `Runtime::service_file_requests` as an **additive step right after the run queue drains** (the same place the port half runs), which drains the service's and its io-devices' mailboxes and replies via `ProcessTable::deliver_simple`, then calls `scheduler.resume_woken`; each delivered reply is counted into the pass's `delivered` so a serviced-only pass never looks like "nothing happened" and a boot-path caller resumes.
* **Files ~1000 lines**, split by responsibility; every public item documented (`#![warn(missing_docs)]`).

## Port-aware scheduling (A.4) — design decision & handoff
The pass runs the **port-less** `Scheduler::run_ready` (its port half, `Runtime::deliver_port_messages` + the one persistent poller, owns the polling), and discharges the port-aware slice's obligations **at the pass boundary**, where the port registry is free:
* **covered** — a process that died in the slices just run had its recorded outgoing `(PortId, MonitorRef)` `PortWatch` pairs swept by `Runtime::drain_port_monitor_exits` (`ets_owner.rs`) — the same end state a port-aware termination reaches for its *incoming* entries.
* **not covered** — `ProcessTable::port_closed(&mut self, ports, port, reason)` (a *closing* port notifying its monitors/links). It can only run **at the close site, while the id is still in the table**: `beam_io::PortRegistry::close` releases the id (`ids.release`), and `beam_process::PortTable::close` is `BadArg` afterwards, so a post-hoc drive from a pass boundary is impossible. That site is `crate::port`'s close path (`RuntimePorts`, reached from `beam_bifs`'s `PortHook::close_port`), outside this node.
`Runtime::with_port_table(&self, &mut ProcessTable, f)` is the intended **short-borrow seam** for such a caller (it `Rc::clone`s the port field, so the returned `RefMut` borrows the clone and both tables can be borrowed at once; a nested borrow stays the typed `unsupported`, never a panic). The `beam_process::PortTable` seam itself is **sufficient as-is** — `port_closed`/`monitor_port*`/`terminate_with_ports` already take the two tables as disjoint parameters.
**Two routes must not be retried; both are unsound by construction:**
1. **Holding the `Rc<RefCell<PortRegistry>>` borrow across `run_ready_with_ports`.** `open_port`/`port_command`/`port_close` executed *inside* a slice (`RuntimePorts::registry_mut`) `try_borrow_mut` the same cell, so a held borrow degrades every in-slice port BIF to the typed `unsupported` gap; the exercised path is the `run <file.beam>` action and the `event_driver`/`port_recv` fixtures, which open and write ports from inside a scheduled slice.
2. **`mem::replace`-ing the `PortTable` out and leaving a placeholder.** `PortTable` has no `Clone`, and `beam_io::PortRegistry::open`/`register` `insert` into the table they were given, so a nested `open_port` during a slice would silently **overwrite** a live port's `Port`/`PortMeta` (the placeholder being empty does not free number 0) — silent corruption, which this crate forbids.
**Crate change that would make the literal routing (or the port-close drive) sound:** the port table must be reachable as a **handle both the scheduler window and the nested BIF paths share**, not as a field inside the same `RefCell` whose borrow the slice must hold — e.g. `beam_io::PortRegistry` exposing `ids` as its own `Rc<RefCell<PortTable>>` (a slice borrows *that* cell and an in-slice BIF borrows it too, failing only on a genuine re-entry), and/or `beam_io`'s close path driving `ProcessTable::port_closed` at its close site with the process table in hand, **before** `ids.release(id)`.

## Test Strategy
* `scheduler/tests.rs`: the bounded pass family (step budgets, wake absorption, the port/timer/distribution halves) over a real `Runtime`.
* `scheduler.rs`'s own in-file pins: the quiescence predicate (an idle runtime is quiescent; installing a `Signal::SigUsr1` handle disposition makes a **portless** runtime non-quiescent until it is restored) and the short-borrow seam (`with_port_table` hands the two tables out; a nested call is the typed `unsupported: the port table is already in use`).
* `gc.rs` units: the pin/halt/valve sets, `gc_stats`, and the escape-store stabilization: `try_stabilize_escaped` on a copyable term (the copy, the valve closed), on an un-copyable one (the honest `SystemLimit`, **no** valve trip), plus `note_pending_spawn`'s `Result` (recorded with arena copies, or recorded nowhere on the honest failure).
* `ets_owner.rs` units: append-only port-watch recording, the take-for-a-drain contract, the two drains (incl. the deferred-borrow path), and the five **heir-gift-failure** tests — `own_heir_gift` no longer swallows the fallible `Table::install_heir` deep copy: a failure is logged via `beam_common::beam_error!` *and* recorded in `OwnerIndex::gift_failures`, so the next `drain_ets_owner_exits` returns it as the typed `BeamError` after discharging every death (the failed copy leaving the table's heir untouched, and a clean hand-off recording nothing).
* `../runner/tests.rs`: the one-slice `ProcessRunner` contract, `RunnerState` bookkeeping, receive-deadline arming and the exit-reason mapping.
* Integration (`../../tests/`): `port_wake.rs` (a port wake resumed through the scheduler), `proc_lib_start.rs` (the cross-module `receive` suspend seam), `file_server.rs` (the native `file_server_2` service driven over real temporary files/directories, oracle-cross-checked), `position.rs`, `boot.rs` (the real `start.boot` to completion), and the `run`-action suites (`cli.rs`, `slice.rs`).

## Routing Table
* `../runtime.rs` → the `Runtime` façade (boot wiring, code server + module cache, the slice, the spawn API, the timer/distribution accessors, `stabilize_term`/`stabilize_term_with` + their destination off-heap table `eval_off_heap`, `materialize_args`, `system_info`, `eval`, `format_term`, `refs_mut`, and the `file_services` field).
* `scheduler.rs` (+ `scheduler/tests.rs`) → the scheduler-pass family (one pass = processes → ports → timers → distribution, in bounded steps; the native-service step `service_file_requests` runs right after the run queue drains) + the `Runtime::with_port_table` short-borrow seam for port-aware `beam_process` operations.
* `gc.rs` → `GcState` + `gc_stats`/`GcStatsSnapshot` + the pin/halt/valve sets + `try_stabilize_escaped`/`try_stabilize_escaped_with`.
* `ets_owner.rs` → the `ProcessExitObserver` host (`OwnerIndex`/`EtsExitObserver`) + `Runtime::drain_ets_owner_exits`/`drain_port_monitor_exits`.
* `../runner/` → the `ProcessRunner` (`mod.rs`/`entry.rs`/`run.rs`/`budget.rs`/`reason.rs`/`perf.rs`/`tests.rs`), re-exporting `crate::runner::{ProcessEntry, RunnerState, RuntimeRunner}`.
* `../context/gc.rs` → the engine's heap-admission point (`ExecutionContext::ensure_heap`) that drives this state.
* `../boot/CONTEXT.md`, `../cli/CONTEXT.md`, `../info/CONTEXT.md` → the boot, A.6 and A.8 surfaces layered on the façade.
