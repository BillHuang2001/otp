# `beam_rt::runtime` — the `Runtime` façade, the scheduler-pass family and the `ProcessRunner`

## Intent
`../runtime.rs` is the `Runtime` façade: the one type owning every runtime table and the runtime-level operations the CLI, the boot path and the `-eval` evaluator call.
`scheduler.rs` (+ `scheduler/`) is the **scheduler-pass family** — one pass = processes → ports → timers → distribution in bounded steps — [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md); `reclaim.rs` + `reclaim/` is the **region-reclaim pass** ([`reclaim/CONTEXT.md`](reclaim/CONTEXT.md)); `roots.rs` + `roots/` is the **mutable root door** ([`roots/CONTEXT.md`](roots/CONTEXT.md)).
`gc.rs` holds the runtime-level GC state and valves; `ets_owner.rs` the `ProcessExitObserver` host; `retention.rs` the retention accounting; `arena_census.rs` its env-gated attribution; `timer_wakes.rs` the `run` route's wait predicate; `executing.rs` the runtime's own root execution frame.
`../runner/` is a sibling `beam_process::ProcessRunner`, routed here because it is the scheduler's own instrument.

## API Surface
### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, `persistent_terms`, `file_services`, dist) and the scratch `info_heap`.
The pass family's entry points live in `scheduler.rs` but stay inherent `Runtime` methods; their five `TimerWait` policies and `is_quiescent` are [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md).
* **boot/config**: `new`, `with_defaults`, `boot()` (idempotent, A.7), `boot_from_script`, `is_booted`, `config`, `load_module`, `module`, `preloaded*`.
* **the slice**: `run_function` (x(0)) and `run_module(module, function, arity, args, out)`.
* **the `run` action**: `run_scheduled` loads the file, spawns the export and pumps the full scheduler under `RUN_STEP_SLICES` = 1000 / `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE)` until the target returns (`x(0)`), raises (the original `BeamError`), goes quiescent (→ `beam_engine::blocked()`), or outlives `RUN_DEADLINE` (60 s).
* **the bounded pumps**: `pump_scheduler` (blocking, `AtMost(TIMER_PUMP_SLICE = 100 ms)`) serves the `-eval` bare `receive`, the busy-port wait and the nested cross-module pump's port half; `pump_scheduler_now` (`ImminentWithin(ZERO)`) is what the `-eval` `after T` loop re-enters per port-poll slice; `pump_scheduler_boot` is imminent-only; `wait_for_timer(until, …)` never outlives the caller's deadline.
* **the `-s`/`-run` action**: `run_named` resolves through the code path and runs a freshly spawned, unregistered action process under the `RootAction::Module` frame; a found-but-refused image is the bare `error::undef` (`error::call_load_failure`).
* **spawning**: `spawn_process`, `spawn_fun_process`, `resolve_export_entry` (resolved **eagerly**, so a failed load raises at the spawn), `enqueue_process` (idempotent), `process_result`, `process_exit`, `run_queue_len`.
* **refs/introspection**: `refs_mut()` (**THE** ref-id space: `make_ref` + monitors + timers), `system_info`/`system_info_value`, `eval(expr)` (A.6), `format_term`.
* **timers/dist**: `timers_mut`, `dist_node`, `node_name` and the connector accessors (`dist_client`, `dist_connected_nodes`, `dist_connect`, `dist_send_reg_send`, `dist_send_message_pid`, `dist_send_alias`); `dist_connect` is **idempotent** and a send to an unconnected peer dials it once.
* **node monitors / peer loss (A.5)**: `node_monitors` holds `monitor_node/2`'s per-pid latches and `service_node_monitors` delivers only the diff as a plain `{nodeup|nodedown, Node}` 2-tuple; `lost_dist_peers` is one shared recorder both halves put a **retired established** link into, drained by `service_lost_dist_peers` into `ProcessTable::node_down(node, noconnection)`.
* **the native file service**: `file_services` (`file_server_2` + its io-devices) and `service_file_requests` — [`../native/CONTEXT.md`](../native/CONTEXT.md).
* **the runtime's own processes**: exactly **four**, none user-spawned — the `init` stand-in (`init_pid`, the table's first identity, so it renders `<0.0.0>` and is `parent` of everything the runtime did not see spawned), the root process (`self_pid`, `<0.1.0>`, every action's process), the `erl_prim_loader` stand-in and the native `file_server_2` service; all born `Runnable` and never enqueued, and only the root process carries no registered name.

### `runner/` — the `ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` records `v` and answers `Exit(normal)`; `Wait{func,pc}` parks and answers `Wait`; `Err(e)` records the reason term and the original `BeamError`, then answers `Exit(<reason term>)`.
`RunnerState` holds an engine per pid plus the pid-keyed `results`/`exits`/`errors` maps (all `crate::hasher` maps, probed only by pid).
The park/resume hand-off, `park_machine`, `BudgetProbe`, the exit-reason mapping and the per-file split are [`../runner/CONTEXT.md`](../runner/CONTEXT.md); measured cost in [`../runner/MEASURED.md`](../runner/MEASURED.md).

### `gc.rs` — the runtime-level GC state
`GcStatsSnapshot` (`gc_stats`) reports collections/failures/halted pids/valve trips **and** the `reclaimed` word counter, advanced by `Runtime::note_gc_reclaimed` from `serve_gc_request`'s Ok arm, the three collection sites in `../context/gc.rs` and the boundary door (`../context/gc/reds_door.rs`); it backs `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}`.
`GcState` holds the **pin** set (a heap that must not move), the **halt** set (a failed collection, or changed root-set sizes), the global **valve** (`disabled`, first reason, trip counter) and the per-pid `foreign` latch plus the reused `walk: WalkScratch`.
`try_stabilize_escaped(term)` is the **one** escape-store stabilization, with three outcomes: a copy onto the pointer-stable store; a **flatten** of an unresolvable refc binary (byte-faithful on-heap); and a propagated `BeamError::SystemLimit` (the term does not fit the arena) — the valve trips **only** for the documented off-heap capability gap (an unresolvable MSO container or a malformed graph), never for a genuine copy failure.
`try_stabilize_escaped_with(term, &SourcePayloads)` is the machine-aware sibling: the caller's source table replaces the empty one, so an engine-built off-heap binary/container is **shared** (one refcount) where the empty form must flatten; `try_stabilize_escaped` is exactly `_with(term, &SourcePayloads::default())`.
Because the copy keeps a NIF resource's **reference identity**, `Runtime::gather_off_heap_roots` counts the pending timer deliveries, the stable engine arguments/entry fun and an unpublished parked machine's root set beside the escaped closures, `seq_trace` tokens, `pending_spawns` and every live process's dict/mailbox/registers/saved args/signals — a family left out makes a live resource look unreachable.
The collection gate is the **two-phase unscanned-root valve** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word, always runs, and declines only for a foreign container forwarding a **scanned** word (a leaf — a `make_ref/0` reference, a float, a pid, a pooled tuple of immediates — latches nothing); phase 2 descends the root-reachable scanned graph only while the per-pid `foreign` bit is open, over the reused `WalkScratch`.
`Runtime::close_foreign_reachable` retires the latch from the **three** doors handing the walk the machine's whole `RootSet`; the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` signal sites may only open it.
The same valve is installed on the process table as `beam_process::CollectionGate` (`context/gc_walk.rs::RuntimeCollectionGate`) over the **one** shared `ForeignLatch` cell, so a signal site decides in `O(1)` and the valve travels with the table into every pass.
**The forced-request probe is split for codegen:** `gc_request_pending` is `#[inline]` (the `is_empty()` compare lands in each caller's frame) in front of `gc_requested_contains`, `#[inline(never)]`, keeping the SipHash probe out of the doors' prologues — `lto = "thin"` with `codegen-units = 1` would otherwise inline it across crates, and re-inlining costs ≈0.8 % of `bench_gc_bound:churn/1`'s retired instructions.

### `ets_owner.rs` — the `ProcessExitObserver` host and the two drains
`OwnerIndex` (shared with `Runtime`) records, in death order, the dead pids awaiting a drain and the append-only `(PortId, MonitorRef)` `PortWatch` pairs; `EtsExitObserver` pushes the dead pid and its drained pairs and returns (no BIF borrows the index).
`drain_ets_owner_exits` discharges the ETS obligations (delete a dead owner's indexed tables, honour an installed heir) and `drain_port_monitor_exits` sweeps the dangling incoming port monitors; both take the borrow with `try_borrow_mut` and **defer** to the next drain on a live borrow — never a panic, never a dropped obligation.
**A failed heir-gift deep copy is never swallowed.** `own_heir_gift` re-owns a fresh table's creation-time gift through the fallible `Table::install_heir`, and `report_heir_gift_failure` both logs it (`beam_error!`) and records it, so the next `drain_ets_owner_exits` returns the typed error (`badarg` outside `beam_ets`'s copyable subset, `out_of_memory` for an exhausted store); the `ets:new/2` stays successful and `install_heir` leaves the current heir untouched on failure.

### `retention.rs` / `arena_census.rs` / `timer_wakes.rs` / `executing.rs`
`retention.rs` publishes the four long-lived regions as `Runtime::retention_stats() -> RetentionStats` (a pure read nothing consults): arena demand counters, the pooled BIF heap's regions/words/capacity/peak-use plus its loan count and seed, the `-eval` store's current and retired capacity, and the escaped off-heap store's handle count; `BEAM_RT_MEM_TRACE` prints one line of it after the boot and on the way out of `cli::run`.
**`eval_heap_words` is `Heap::capacity()`, blind to `used()`** — a store-write regression does not move it (read `Runtime::eval_region_stats`); `arena_words` is **cumulative demand**, so a rewind never lowers it.
`timer_wakes.rs` is `TimerWakes`: which pending deadline can wake which process (the handle→target map plus the reference-term-keyed `deliver` map). `executing.rs` is the runtime's own **root execution frame**, the source of `process_info(self(), current_function | initial_call | current_location | catchlevel)` outside a live machine.

## Constraints
* **`unsafe`-free** (`#![deny(unsafe_code)]`) and return-based errors ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible API returns `beam_common::Result`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`** — a pass needs `&mut Runtime` **and** `&mut ProcessTable` at once while the table is a *field* — and restores both whatever the outcome ([`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *the scheduler moves the table*); **a process's exit reason is not its return value**.
* **Heap lifetime**: `Runtime` owns the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use the separate `info_heap`, rewound per call by `reset_info_scratch`, which **refuses** once `info_heap_tainted` is latched, and `erlang:system_info/1` leaves it through `RuntimeContext::relocate_off_scratch` — pinned by `tests/system_info_retained.rs`.
* **A run-queue pid with no engine entry point is a recorded typed diagnostic, never an aborted pass.** `RuntimeRunner::run` takes the pid's `ProcessEngine` out of `RunnerState::engines`; for one it never registered (`RunnerState::contains`) it records an `UnrunnableProcess`, **restores the process to `Runnable`** (`slice_begin` had set it `Running`, which also changes `has_unpublished_roots`) and answers `Wait`; `absorb_fragment_wakes` skips such a pid and `enqueue_process` rejects it with the typed `error::unknown_process_entry`.
  That is why the runtime's own services are safe: a never-enqueued service is created with `ProcessTable::spawn(policy)` (born `Runnable`, `insert`ed, **not** enqueued) + `register(name, pid)`; only `Waiting`/`Suspended` are woken by a delivery, so it never runs.
* **Files ~1000 lines**, split by responsibility; every public item documented (`#![warn(missing_docs)]`).

## Term lifetime and rooting — the four rules
(i) **A raw `Eterm` in a long-lived slot roots nothing.** Any term that can outlive one instruction must be copied onto a scanned heap or explicitly stabilized (`Runtime::stabilize_term`/`stabilize_term_with`, `try_stabilize_escaped[_with]`, `for_each_root_family_mut`) before the owner's heap can be relocated.
(ii) **A pointer-stable, never-scanned store is the wrong home for a container whose children live on a scanned young heap.** The arena (`Runtime::alloc_words`, `MinimalContext`) is never scanned and never collected, so the collector leaves a container standing there verbatim while it relocates the children out from under it — a term built there that names heap objects must be stabilized, not assumed to pin them.
(iii) **A refused growth or a refused move means "refuse ⇒ stabilize, never dangle".** A declined collection leaves the allocation to the pointer-stable arena, a declined prune retains the whole reservoir (a leak, never a dangle), and a declined store move keeps both regions (`MoveOutcome::KeptBoth`) — every refusal keeps the old words valid.
(iv) **A lease (an `Rc` handle) held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow** — see `../../CONTEXT.md` *The one process-lifetime `Rc<AtomTable>` lease* and `../port.rs`'s `open_driver_atom_view`/`commit_driver_atoms` window.

## Every site that can relocate a process heap
Heap relocation is **not** confined to the runner's slice: any path that reaches a rooted collection moves a process's young objects, so each must either publish that process's root set or decline.
All of them share ONE root set — `Process::regs` + each mailbox message's `payload`/`from`/`token` + dict + saved args + pending-signal queue, gathered/scattered by `run_rooted_collection` (`../../beam_process/src/process.rs`).
* the three heap-admission doors — `../context/gc.rs::ensure_heap`, `ensure_heap_full`, `alloc_words_rooted` (the *running* process: publish → collect → scatter);
* the reduction/yield-boundary door — `gc/reds_door.rs::collect_at_reds_boundary` (refuses `is_relocation_exempt` outright, then its interval and occupancy gates);
* `Runtime::serve_gc_request`, from the runner's Yield arm and its Wait arm;
* **message delivery**, i.e. the *receiver's* heap — `ProcessTable::deliver` → `Process::deliver`, reachable from `RuntimeContext::deliver_in_table` and hence from every pass-boundary step;
* **the exit cascade** — `ProcessTable::enqueue_exit_signal` → `copy_reason_onto` → `grow_receiver_for_signal`, from `terminate`/`terminate_into`; deliberately **not** gated by `gc_process_enabled`, only by `has_unpublished_roots()`/the gate.
All of them refuse when **`Process::has_unpublished_roots()` — `relocation_exempt || state == Running`**; the delivery seam adds `RuntimeContext::delivery_collection_is_unsound`.
The `foreign_reachable` latch is only ever a **descent** short-circuit, and `close_foreign_reachable` runs only from the three whole-`RootSet` doors.
**Recorded residual:** `serve_gc_request`'s `Err(_) => halt_process_gc` discards the `BeamError`, so a genuine collection failure becomes a silent halt (only the `errors` counter and the `halted` set record it).

## The inter-slice window's relocating doors
A `Yield` park with a **dead** FR prefix publishes the machine's whole root set into the process's `Registers` and leaves the process **not** relocation-exempt, so every site that delivers into the parked pid between slices may collect over those registers — all through `deliver_in_table` → `ProcessTable::deliver` → `Process::deliver`, gated by `has_unpublished_roots()` plus `delivery_collection_is_unsound`.
An **exempt** park (a live FR prefix) publishes nothing, so those sites refuse; a dead-FR `Wait` park is collectable like the `Yield` park; inside a slice the process is `Running`, so `slice_begin`'s `service_signals` and every in-slice delivery take the fragment route.
The machine is stale from the moment one of these doors collects until the matching resume scatters (`resume_from_process_roots` → `resync_parked_roots` → `scatter_roots_full`); a resume that cannot scatter (`scatter_roots_full` answers `false` when the relocated x-prefix or the stack-plus-FR length disagrees with what the park published) calls `halt_process_gc(pid)` and keeps its pre-collection words.
**The `Yield` arm's door order is load-bearing.** `serve_gc_request` runs first, over the root set the park just published, and the boundary door is `else`-gated on its `request_collected` answer (`runner/run.rs`) — the boundary door re-publishes **from the machine**, whose `x`/`stack` are pre-collection words by then, so it is skipped outright whenever that collection happened. Never move the boundary door ahead of `serve_gc_request`, and never run both.

## Host-side cached term words
The node holds **two** term-carrying fields; nothing else under `runtime/` caches an `Eterm` (`scheduler.rs`, `executing.rs`, `retention.rs`, `arena_census.rs`, `roots.rs`, `reclaim.rs` and the whole ETS/port owner index are term-free).
* `GcState::async_completions[].req_id` — the caller's `{async, ReqId}` term, run through `stabilize_term` before it is recorded, so it outlives both the caller's young heap and the pooled BIF region the option list was parsed from. **Its destination is `Runtime::eval_heap`** (the `-eval` store; `Runtime::arena` is the *other* region, reached only by `alloc_words`). Lifetime: the `erlang:garbage_collect/2` call → the next boundary `deliver_gc_completions`; the word is **relocatable** (the store copy is its only home, and `eval::scratch::pin` latches the statement window so it cannot be rewound).
* `TimerWakes::deliver` — keyed by the timer's **reference term**, a boxed 4-word ref thing minted on a **pooled BIF heap**. `Eterm`'s `PartialEq`/`Hash` are the raw word, so this key is **address identity, not content**: moving that region would dangle it *and* break every later `cancel_timer`/`is_timer_ref` lookup. Lifetime: schedule → fire/cancel. The payload terms (`from`/`message`) are not here — they are `eval_heap` copies in `Timers::pending`.
`GcState::scratch: Vec<Eterm>` is **not** a term store: the all-`NIL` placeholder fill `context::gc::bump` hands `Heap::tuple`, never a root, only ever grown and **never reset** — a compaction can ignore it.
The `{'ETS-TRANSFER', Tid, FromPid, Data}` the owner drain builds shows the same discipline: the tuple is built on the **pooled BIF heap**, `Data` is the table-owned gift out of `beam_ets`'s never-relocating store, and `deliver_in_table` **deep-copies** it into the heir's mailbox, so no word survives the drain.

## The off-heap refc-binary reclamation point
The loop has **exactly ONE reclamation point** — the runner's park (`Yield`) arm, whose `reclaim_off_heap_binaries` calls `context/gc/bin_vheap.rs::reclaim`.
That call runs `beam_gc::for_each_reachable_binary_payload` over the **process's** registers (never the machine's term words), then `Machine::retain_refc_binaries(predicate)` over the reservoir handles those roots name, then `Process::set_off_heap_binary_bytes(machine.off_heap_overhead_bytes())`.
Nothing else reclaims; `has_unpublished_roots()` is deliberately **not** a gate there — every other gate (the relocation exemption, the runtime valves, the bin-vheap trigger, the unscanned-root valve, the reachability walk) is a decline.
A declined prune retains the whole reservoir, so a refusal is a **leak, never a dangle**; the `Wait` arm and a `BifOutcome::Suspend` park reach **no** prune, so a process parked since building payloads keeps them until it is next pre-empted.
Algorithm, accounting model (`BinVheap`, `HeapFootprint`) and per-shape measurements: [`../context/gc/CONTEXT.md`](../context/gc/CONTEXT.md), [`../../../beam_gc/CONTEXT.md`](../../../beam_gc/CONTEXT.md).

## The pass's exact step order
`scheduler_pass` is one loop body: before the first round it boots once, moves the process table/scheduler/runner state out (the runner holds `&mut Runtime` while the scheduler holds `&mut ProcessTable`), absorbs the caller's wake list (`resume_first`) and the fragment wake list, and each round derives its own budget (`max_slices - ran`; `Some(0)` ends the pass at the top).
Per round, in order: `run_ready` (consumes the round budget) → round accounting (`statistics(context_switches)`, the `progressed` flag) → `prune_gc_requests` (a dead requester) → `deliver_gc_completions` (the `{async, ReqId}` half) → the native services (`service_file_requests` A.9, then `service_net_kernel`) → `drain_port_monitor_exits` → `drain_ets_owner_exits` → `absorb_pending_spawns` (counts nothing) → `absorb_fragment_wakes` (yields `woke`) → `drain_driver_monitor_exits` → `deliver_port_messages` (the **port half**) → `drain_nif_thread_sends` (the **foreign-thread NIF half**, A.3) → the distribution block (`pump_dist` A.5 accept, `bind_dist_peers`, `service_node_monitors`, `dispatch_dist_inbound`, `pump_dist_client` (which also flushes queued controls), `dispatch_dist_client_inbound`, `service_lost_dist_peers`) → `fire_due_timers` (the **timer half**, with `absorb_timer_wakes` inside this arm) → a round that absorbed a fragment wake goes round again, else `timer_wait` decides the pass's sleep (one more wait to the earliest deadline, or `None` ends the pass).
Every delivering step counts into `delivered` and continues; `pump_dist`, `pump_dist_client` and the two monitor drains only add to the tally and fall through.
The runner state, scheduler and process table are restored into the `Runtime` whatever the loop's `Result` says.
The per-step contract, the three outbound byte-write moments and the quiescence interaction: [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md).

## Re-entrancy
`scheduler_pass` extracts every mutable table before its first round (`take_processes` replaces `self.processes` with a fresh empty `ProcessTable::new`, plus `mem::replace` on `scheduler` and `mem::take` on `runner_state`) and restores them unconditionally at the end, so a pass invoked *from inside a slice* would drive those three placeholders and have its writes silently discarded by the outer restore; `run_ready` is therefore handed `&mut table` / `&mut scheduler` / `RuntimeRunner::new(self, &mut state)` explicitly — the state is threaded, never re-read from `Runtime`.
**The guard is cooperative only.** `RuntimeContext::may_pump_scheduler` (`false` in `for_process*`) is checked at exactly one site, `pump_once`'s first line (→ the typed `blocked()`); no `in_pass` flag, debug assertion or `RefCell` exists, so a nested `scheduler_pass` would corrupt silently. The port registry's `try_borrow_mut` and `is_quiescent`'s `Err ⇒ not quiescent` are the only borrow-level brakes.
`&mut Runtime` is owned by the `RuntimeContext` for the whole slice, so a mid-slice `pump_scheduler` does not typecheck as written; the executing pid's engine is out of `RunnerState::engines` while its `Process` is `Running`, so every delivery into it takes the fragment route and no collection may move its heap.
**Every service step is separately callable** — `service_file_requests`, `deliver_port_messages`, `fire_due_timers`, `deliver_gc_completions`, `service_net_kernel`, `service_node_monitors`, `pump_dist`/`pump_dist_client` and the non-delivering drains each take `&mut self` and at most `&mut ProcessTable`; the wake-list bookkeeping (`absorb_*`, `drain_ets_owner_exits`, `&mut Scheduler`) belongs to the outer `Scheduler` the context cannot reach.

## Distribution (A.5)
**Every inbound delivery is validated against its own link.** Both drives (`dispatch_dist_inbound` → `DistNode::dispatch_inbound`, `dispatch_dist_client_inbound` → `DistClient::dispatch_inbound`) drain through `beam_dist::ConnectionDriver::dispatch_inbound_checked`, which checks a control message against that link's own `peer_name()`/`our_name()` (`LinkIdentity`) — `Delivery::classify_validated` reproduces the C's per-opcode shape checks plus the anti-spoof `dep != external_pid_dist_entry(from)`, in the **same** atom table the message was decoded against.
A validation failure is an `Err` that never reaches the sink: the drive retires **just that link** and records `last_link_error` (the C's `invalid_message`), never a pass failure.
The check cannot live in `LocalDeliverySink`, which is shared by every link; `Runtime::dispatch_inbound` stays classify-only for a caller supplying a hand-built driver whose handshake names need not be this node's identity.
`LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes `Delivery::Send`/`RegSend`/`AliasSend` and the plain `AltactSigSend` sub-cases, plus the **route-free receipt** families (link, exit/exit2, monitor/demonitor, monitor-exit, group-leader, the `UnlinkId`/`UnlinkIdAck` pair) through `beam_process`'s receipt primitives, echoing no `DOP_*` it received; `beam_process` also exposes the **outbound** relationship entry points (`link_term`/`unlink_term`/`monitor_term_with_options`/`demonitor`/`send_exit_term`).
**The envelope rule:** the mailbox `from` is always an **immediate** (`envelope_from` — the sender peer's node atom when the wire carried a sender pid, else the wire word, `''` for the plain `DOP_SEND*` forms), because `beam_message` gathers only each queued message's payload as a GC root.
**Typed gaps:** `SpawnRequest`/`SpawnReply` (the reservation surface exists; missing is this crate's responder, a pending-spawn table keyed by `(peer, Ref)` and a `DOP_SPAWN_REPLY` channel — `InboundSink` has none), `Other(Dop::Unlink)` (not a v6 opcode), and the ack-owing `DOP_UNLINK_ID` half (`id != 0`), whose record is dropped while the wire half reports `Unsupported`; an `id == 0` inbound `DOP_UNLINK_ID` is a **wire error** refused before any sink call.
The pass drives both halves gated by `Runtime::inbound_delivery` (default **ON**), early-returning unless the runtime is a distribution node with an established link.
There is **no** `{setup,…}`/`{nodeup,…}` control exchange: after the `$a` ACK the link carries `DOP_*` immediately and node-up is local bookkeeping.
Both halves' own API: [`../dist/CONTEXT.md`](../dist/CONTEXT.md) / [`../dist_client/CONTEXT.md`](../dist_client/CONTEXT.md); the per-family table: [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md).
## Port-aware scheduling (A.4)
The pass runs the **port-less** `Scheduler::run_ready` and discharges the port-aware slice's obligations at the pass boundary, where the registry is free.
Covered there: the two monitor drains (`drain_port_monitor_exits` for a dead process's outgoing `(PortId, MonitorRef)` pairs, `drain_driver_monitor_exits` for every live C-driver's tree just before `deliver_port_messages`), so the round's port-task probe fires the driver's `process_exit`; the single `ProcessTable` observer slot stays `EtsExitObserver`.
**Not covered: `ProcessTable::port_closed`** — a closing port notifying its monitors/links — which can only run **at the close site, while the id is still in the table** (`PortRegistry::close` releases the id, `PortTable::close` is then `BadArg`); that site is `crate::port`'s close path, outside this node.
`Runtime::with_port_table(&self, &mut ProcessTable, f)` is the intended short-borrow seam (`Rc::clone`s the port field so both tables are borrowable; a nested borrow is the typed `unsupported`, never a panic).
**Two routes are unsound and must not be retried:** holding the `Rc<RefCell<PortRegistry>>` borrow across `run_ready_with_ports` (in-slice port BIFs `try_borrow_mut` the same cell and degrade to `unsupported`), and `mem::replace`-ing the `PortTable` out (no `Clone`; `open`/`register` insert into the table they were given, so a nested `open_port` overwrites a live port).
The crate change that would make either sound: `beam_io::PortRegistry` exposing `ids` as its own `Rc<RefCell<PortTable>>`, and/or its close path driving `ProcessTable::port_closed` **before** `ids.release(id)`.
**A dying process's owned ports are closed by nobody in `beam_rt`:** `terminate_into` drains links, monitors and port *monitors*, never an owned port, and `PortTable` has no reverse `owner → [PortId]` index (only a forward `owner(id)`, no id iterator), so a closer must add that index.
A normally-returning scheduled process is reclaimed by `beam_process`'s schedule-out (`slice_end` → `ProcessTable::terminate`); a never-enqueued `Runnable` service by its own teardown (`Runtime::as_action_process` stabilizes the result, then `terminate`s).
Detail and measured evidence: [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md), [`../port/CONTEXT.md`](../port/CONTEXT.md).

## The region-reclaim pass
Two mechanisms over the runtime's two long-lived term regions, both at **non-running sites** only (nothing is executing, so every store can be enumerated and rewritten): the whole-region actions of `reclaim.rs` and the evacuation move of `reclaim/compact.rs`.
**Phase 1a — whole-region actions, no word moves:** drop an `eval_heap_retired` region whose descent proves it whole-dead, reset the current region's dead prefix (`reset_to(cursor)`), and the arena's `Tier A` `heap_rewind`.
**Phase 1b — the evacuation move:** a partially live retired region is evacuated into a fresh destination, installed as the current store while the old region is reset and retired or dropped; its precondition is the caller's **completeness claim** — every stored word is enumerated through the mutable root door (`roots.rs`, 23 families), and a word the destination cannot take leaves a `KeptBoth` obligation rather than a hole.
`BEAM_RT_REGION_RECLAIM` (`all`/`store`/`store-whole`/`arena`/`nomove`/`off`) is the A/B kill switch and can only disable an **action**, never a correctness guard.
Thresholds and the `R_*` decline list (a `R_PIN` reason headed, so a declined move is attributable), with the whole measured record — where the retention is, what the pass costs, the two `[rt-mem] exit` lines, artifact identity, the Phase-2 blocker and the "what the pass does not cost" matrix: [`reclaim/CONTEXT.md`](reclaim/CONTEXT.md).
### What refuses the move — a parked machine's used extent
`store_move_hit` names `Family(ProcessDict, 1)` on the two-statement workload, and **that attribution is a measurement artifact**: `attribute_hit` reports the first candidate whose descent records a range hit, while `BEAM_RT_STORE_TRACE=1` re-descends every slot and shows the dictionary slot's graph names **no** word inside a candidate range.
What actually refuses is the walk meeting an unparseable word, reachable from exactly **two** corpus slots — `RootFamily::ParkedMachine[0]` and `[8]`, both holding the same word (2 of 4 039) — the idle blocked engine set whose machines the corpus over-approximates and walks in full (`x` prefix + the whole Erlang stack + the FR prefix, **no frame liveness map**), so a dead word in that extent coinciding with a candidate range refuses the move for the whole pass.
This is the Phase-2 blocker in measured form, not a missing writable slot; an "any engine parked ⇒ decline" gate is **not** the fix (every engine is parked at a statement boundary, so it would make `store_compactions` structurally unreachable while buying no soundness).
The unknown-boxed-header refusal is the same shape: `reclaim_last_decline_header` `0x0a`/`0x2a` with `0x2a & 0b11 == TAG_PRIMARY_BOXED` — a boxed **term** word where a header belongs, from the same released-region residue; no legal `BoxedTag` is ≡ 2 (mod 4), so dereferencing further would treat a pointer as an object.
### Measured A/B: the pass on a two-statement `-eval`
A single-statement `-eval` cannot show the win — its peak is reached before either non-running site runs; two compiles in ONE expression put a statement boundary between them.
The two-statement `inet_parse` run is **−3.07 GB (−19.0 %) in peak `VmHWM`** off→on and `cerl_clauses` **−33.8 MB (−6.1 %)**, with nothing measurable on a single statement: the win is the **arena rewind**, not the store (`arena_reclaims=1`, `store_compactions=0`).
The `inet_parse` peak rows are not reproducible on a shared host — the **counters** are the host-independent evidence.
The table, the exact `[rt-mem] exit` lines and the measurement recipe are [`reclaim/CONTEXT.md`](reclaim/CONTEXT.md).
## The runtime-level mutable root door — `roots.rs`
`Runtime::for_each_root_family_mut` is the *moving* twin of `Runtime::gather_off_heap_roots` (which only answers liveness): it hands a visitor the writable `Eterm` slots of every host-side root family, one slice at a time, tagged with a `RootFamily`; `for_each_root_mut` is the family-blind form.
Both are `pub(crate)`, both answer `beam_common::Result<()>`, and the door **decides nothing**: it collects nothing, retains nothing, prunes nothing, and every per-owner enumerator lives in the owner's own module (`roots/process.rs` composes `beam_process`'s `gather_roots`/`scatter_roots` pairs plus the mailbox rebuild, so no sibling crate is edited); its **two production callers** are the region-reclaim pass plus the parity suite `root_tests.rs`.
The traversal is a **fixed 18-step order over 23 `RootFamily` variants**, and `RootFamily::in_value_gather()` is the machine-checkable **11 true / 12 false** split against the value gather; the step table, the per-variant reasons, the visitor contract and the completeness argument are [`roots/CONTEXT.md`](roots/CONTEXT.md).

## The arena allocation attribution census
`arena_census.rs` is the **attribution** census that goes with `retention.rs`: *which* requests produced the arena's demand, on the same env-gated, zero-cost-when-off terms.
`BEAM_RT_ARENA_TRACE` arms it (`Runtime::arena_census_report`, `[rt-arena]`); the record is a power-of-two size histogram, the ten largest single requests with a backtrace each, an inside/outside nested-run-window split, and a per-window delta histogram; the thread-local `State` is reached through a `Window` guard, so the report needs no borrow of the runtime, and the retained top ten holds at most ten backtraces (the unpaired-close guard keeps a nested window from leaking its delta).
**Capacity is not RSS.** An arena request lands in the lazily-`mmap`ed region: a reservation shows up in `VmSize` and in `{allocator,std_alloc}`, while RSS moves only when pages are written — and `RetentionStats::arena_words` is cumulative **demand** (a rewind never lowers it), so read the two together before concluding anything about memory.

## The scheduled path's fixed costs
`run_scheduled` drives **one** target pid after `boot_if_needed`, at `RUN_STEP_SLICES` = 1000 rounds of slices (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS` = 4000), so per-pass costs amortize while **per-slice** costs dominate a long run.
A bare `spawn(fun …)` child is created *inside* a slice (`native/process.rs::spawn_in_pass` → `note_pending_spawn` → `absorb_pending_spawns`) and every slice's end absorbs the wake list, so a synchronous two-process ping-pong never empties the run queue and stays in **one** `run_ready` call — it does **not** re-enter the pass boundary per iteration.
Two of this node's own per-slice costs are worth naming: a finite `receive … after T` pays a timer-heap add+remove and a `TimerWakes` entry on **every** iteration, and `Timers` reclaims a non-head cancellation by rebuilding past a watermark (`compact` once `heap.len() > 2 * pending.len() + COMPACT_SLACK` = 64), so a cancelled deadline is never a permanent tombstone.
The measured per-pass / per-slice / per-round inventory (the fresh empty `ProcessTable` each pass builds and discards, the progress-aware pass wait, the per-slice machine/context churn, the `crate::hasher` maps, the heap-admission seam's occupancy short-circuit with its `current_module` clone) is [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md) *The scheduled path's fixed costs*, with the per-workload cost in [`../runner/MEASURED.md`](../runner/MEASURED.md).

## Known Issues
* **`absorb_fragment_wakes` enqueues a pid only when four conditions hold:** in the table, `Runnable`, not already queued, and `RunnerState::contains` — the last keeps a runtime-owned never-enqueued service off the queue (such a service is *born* `Runnable` and never runs). A refused pid gets the typed `UnrunnableProcess` diagnostic instead of breaking the pass. The note substitutes for the table's wake list, so it is recorded **only on a real wake**; the descent gate `note_foreign_reachable` is unconditional for a fragment, because its payload sits where the receiver's collector does not scan.
* **Quiescence blind spot: a retired native io-device is never drained again.** The native-service step drains exactly `FileServices::server()` + `file_services.devices.keys()`, and a `retire == true` `serve_file_message` removes the device — so a still-live device pid holding a queued request vanishes from the drain list, its reply is never delivered, the parked sender never woken, and the next pass sees `ran == 0 && delivered == 0 && is_quiescent()` and answers the typed `blocked()` (exit 3) though a wake source still has work. The `retire` flag is itself a false positive (`EngineContinuation::apply` sets `raised = true` on **any** `Err`). Fix belongs in `../native/file_server.rs`, **not** in this node.
* **A *live port* alone keeps a pass non-quiescent.** `PortRegistry::has_nothing_to_poll` is false while any port's metadata exists, so a `run`-route process parked on a message only a port can produce never takes the `blocked()` abort and keeps stepping (sleeping `PORT_POLL_SLICE` on a round that ran nothing) until the port answers or `RUN_DEADLINE` expires — which is what a driver-side async reply relies on. The port round is drained **only** at the `deliver_port_messages` boundary on the scheduled route.
* **The port half's block is per *zero-slice round*, and only the boot drive's policy may shorten it.** `port_timeout` is `Duration::ZERO` for a round that ran a slice or still holds pending heap-fragment wakes (a delivery that did not fit the receiver's heap takes `context::send`'s fragment fallback, whose `note_fragment_wake` channel is absorbed later in the same round), and — for an `ImminentWithin(_)` pass only — when no port owes a reply (`awaits_port_reply`) and no driver holds an async operation (`ports_awaiting_async`), which keeps the boot's live-but-idle `inet_gethost` child off the poll budget. The `run` route and the `-eval` **bare** receive keep the unconditional blocking poll because a child there may speak unprompted (`halt/N` makes **zero** passes). Detail: [`scheduler/CONTEXT.md`](scheduler/CONTEXT.md) *The progress-aware wait (both halves)*.
* **`delivered` does not count ordinary Erlang `send`.** Only port/timer/file-service/ETS/dist deliveries are counted, so a pass whose only progress is a plain message wake can look like `delivered == 0`.
* **A dying process's owned ports are closed by no path here, and `PortTable` has no reverse `owner → [PortId]` index** — the crate change owed is in *Port-aware scheduling*. Both are capacity gaps, never a wrong result.
