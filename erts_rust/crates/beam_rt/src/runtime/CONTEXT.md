# `beam_rt::runtime` — the `Runtime` façade, the scheduler-pass family and the `ProcessRunner`

## Intent
`../runtime.rs` is the `Runtime` façade: the one type that owns every runtime table and the runtime-level operations the CLI, the boot path and the `-eval` evaluator call (`run_function`/`run_module`/`run_scheduled`, the spawn API, `system_info`, `eval`, `format_term`, `refs_mut`, the timer/distribution accessors).
`../runtime/scheduler.rs` (+ `scheduler/tests.rs`) is the **scheduler-pass family**: it drives processes, ports, timers and distribution in bounded steps (the distribution half is **four** steps — the server pump/inbound and the connector's pump/inbound).
`../runner/` (a sibling directory) is the `beam_process::ProcessRunner` each scheduled process runs through; it is documented here because it is the scheduler's own instrument.
`gc.rs` holds the runtime-level GC state, accounting and safety valves, and `ets_owner.rs` the `ProcessExitObserver` host with the two owner-death drains.

## API Surface
### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, the node-global `persistent_terms` store, the native `file_server_2` service — `file_services`, spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus an explicit `-boot FILE`), registered as `file_server_2` otherwise — dist) and the scratch `info_heap`.
The **scheduler-pass family** (`run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`pump_scheduler_boot`/`run_scheduled`, the shared pass body, wake absorption, the port/timer/distribution halves — `pump_dist`/`bind_dist_peers`/`dispatch_dist_inbound` for the accepting node and `pump_dist_client`/`dispatch_dist_client_inbound` for the connector) lives in `src/runtime/scheduler.rs` (+ `tests.rs`), but every entry point stays an inherent `Runtime` method.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (idempotent; A.7), `boot_from_script(path)` (A.7), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)); `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` loads the file, `spawn_process`es the export and pumps the **full** scheduler in bounded steps (`RUN_STEP_SLICES` = 1000, `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE)`) until the process returns (`x(0)`), **raises** (`take_process_error` returns the original `BeamError`), is quiescent (`scheduler.rs:504`: `ran == 0 && delivered == 0 && is_quiescent()` → the typed `beam_engine::blocked()`), or outlives `RUN_DEADLINE` (60 s); exit-code classification matches the single-pass path. `is_quiescent` (`scheduler.rs:590`) is four terms: `run_queue_len() == 0`, `PortRegistry::has_nothing_to_poll()` (no live port, no armed `tty_select/2` interest *and* no **fired, undrained** signal self-pipe — an armed-but-idle `handle` disposition is not pending work, see [`../port/CONTEXT.md`](../port/CONTEXT.md)), the timer term (`timers.next_deadline().is_none()`, or for the `run` route only a deadline that could wake its one target, `timer_wake_targets.can_wake`), and the **distribution** term: no accepted node holding a live link (`DistNode::is_idle`) and no client holding any link, handshaking or established (`DistClient::has_links`, which reports a borrowed cell as "has links" — work in flight, so the pass keeps pumping) **or** owing the wire work it has already accepted (`DistClient::has_pending_outbound`: a queued routed signal, or bytes a link's driver has not written).
A `run`-route process parked on a bare `receive` with a live distribution link therefore keeps pumping (the peer's `DOP_*` can arrive and wake it) and is bounded by `RUN_DEADLINE`'s "did not terminate" diagnostic instead of exiting 3 through `beam_engine::blocked()`.
A runtime with no node name carries neither half (`None`) and a node with no link answers idle, so a non-distributed runtime is quiescent exactly as before. A bounded pass cannot sleep its way out of ending: it sleeps at most **once** (`TimerWait::allows` → `AtMost(_) | AtMostWhenIdle(_) | ImminentWithin(_) => waits == 0`, `scheduler.rs:149`) and its round budget's `Some(0)` exit (:848) ends it at the top, so it returns `Ok((ran, delivered))` and control reaches the quiescence test.
* **the boot-drive step**: `pump_scheduler_boot(max_slices) -> Result<u64>` is `pump_scheduler` with an **imminent-only** sleep policy (`TimerWait::ImminentWithin(TIMER_PUMP_SLICE = 100 ms)`, `scheduler.rs:74`): the pass sleeps exactly the remaining time when the earliest pending deadline is **within** the window and returns **without sleeping** otherwise (`timer_wait`'s `ImminentWithin` arm, `scheduler.rs:1524`). It is the only entry the boot drives (`../boot/drive.rs`) call — `pump_scheduler` keeps `TimerWait::AtMost` for the `-eval` receive pump, whose bounded-100 ms semantics its `receive` loop relies on, and `run_scheduled` uses the progress-aware `TimerWait::AtMostWhenIdle` (below). Due timers are unaffected (`fire_due_timers` runs before the wait) and a boot-spawned process parked on a short `receive … after T` (T ≤ the window) is still slept to and resumed. The debug trace logs every decision (`timer wait: policy=… remaining=… wait=…`) behind `BEAM_RT_BOOT_TRACE`. Its sibling `wait_for_timer(until, max_slices) -> Result<bool>` is the `-eval` `receive … after T` wait (`../eval/mod.rs`): it sleeps to `min(earliest pending deadline, until)` (or `until` with nothing pending) and then runs one bounded `pump_scheduler_boot`, returning whether anything ran or was delivered, so a due timer fires and delivers its message inside the caller's window.
* **the `-s`/`-run` action**: `run_named(module, function, arity, args) -> Result<Eterm>` resolves the module through the code path (the system library `ebin`s included) and runs it as a freshly spawned, unregistered action process under the `RootAction::Module` frame; a **found-but-refused** image is the bare `error:undef` here exactly as at a call site (`error::call_load_failure`, the classifier `../context/calls.rs` uses), never the loader's `module name in object code is …` diagnostic.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (`spawn/1`), `resolve_export_entry(module, function, arity) -> Result<ProcessEntry>` (a `spawn*` `M:F/A` entry: code-path search, load and export check, classified like a call and resolved **eagerly**, so a failed load raises at the spawn where the oracle spawns and the child dies — `M1_GAPS.md` *The `spawn(M,F,A)` reason surfacing*), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)`, `run_queue_len()`.
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)`.
* **timers/dist**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()`, and the connector accessors (`dist_client()`, `dist_connected_nodes()`, `dist_connect(peer)`, `dist_send_reg_send`, `dist_send_message_pid`, `dist_send_alias`); each of the three outbound send entries **dials an unconnected peer once** (`dist_ensure_link`/`dist_dial_name`/`dist_peer_is_local`) before the shared routing lookup, so a send — not a prior `net_adm:ping/1` — opens the link, and a runtime with no client or an already-linked/failed peer behaves exactly as before (an unreachable peer still answers `no_link_error`) — see [`../dist/CONTEXT.md`](../dist/CONTEXT.md); the scheduler half (`fire_due_timers`, `note_fragment_wake`, `pump_dist`/`dispatch_dist_inbound`, `pump_dist_client`/`dispatch_dist_client_inbound`) is in `scheduler.rs`.
* **node monitors (A.5)**: the `node_monitors: FastHashMap<ProcessId, Vec<NodeMonitorLatch>>` store — `erlang:monitor_node/2`'s subscriptions (the C's `ERTS_MON_TYPE_NODE` chain, **not** the `monitor_nodes` flag store above), each latch the node's atom term plus its `saw_connected` state — with `monitor_node_add(pid, node, saw_connected)` (the C's idempotent set: no duplicate, no refcount) / `monitor_node_remove(pid, node)` (drops an emptied pid entry), the pure diff `node_monitor_transitions(latches, established, name_of) -> Vec<(Eterm, up)>` (the four-state table: `up` only on not-seen→present, `down` only on seen→absent, nothing in either steady state, and an unnameable node inert) and the pass step `service_node_monitors(&mut ProcessTable) -> Result<usize>`, which turns each transition into the plain 2-tuple `{nodeup|nodedown, Node}` and delivers it exactly like `deliver_gc_completions` (arena-built message, `RuntimeContext::deliver_in_table`, emulator `from`). It is the **one** pid-keyed runtime map that is iterated on purpose (over the subscribers only); `Ok(0)` with no allocation when nobody subscribed, and on a `nonode@nohost` runtime every latch stays silent. The BIF body is `../native/net.rs::monitor_node_2`; `erlang:monitor_node/3` stays a typed gap.
  `Timers` probes with the crate's own `FastHashMap` and reclaims a non-head cancellation with a **watermark heap rebuild** (`Timers::compact`, run by `prune_cancelled` once `heap.len() > 2 * pending.len() + COMPACT_SLACK`), so a finite `receive … after T` cancelled by a real message does not leave one permanent tombstone per iteration: the heap stays bounded by the pending count plus `COMPACT_SLACK`.
  The `TimerWakes` `deliver`/`resume` mirror (`runtime/timer_wakes.rs`) and the façade's `timer_resumes`/`group_leaders`/`async_dist`/`monitor_nodes` bookkeeping maps are `crate::hasher` collections too — each is only probed by an internal id (or an order-independent `any()` scan), never iterated for an observable order.
* **the native file service**: the `file_services` field (`FileServices`: the `file_server_2` service process + its live io-devices; `Runtime::new` spawns it **unregistered** whenever `RuntimeConfig::drives_a_boot_script()` holds — every CLI action but `-version`, plus an explicit `-boot FILE` — and registers it under that name otherwise) and `service_file_requests(&mut ProcessTable) -> Result<usize>`, the scheduler-pass step that services them — see [`../native/CONTEXT.md`](../native/CONTEXT.md)'s `file_server.rs` subsection.
* **the runtime's own processes**: `Runtime::new` starts exactly **three** processes, all of them the runtime's own and none spawned by user code — the root process (registered as `init`), the native **`erl_prim_loader`** stand-in (a `beam_process::Process` born `Runnable` and never enqueued, registered under the loader's own name on **every** route that builds a runtime, so `erlang:whereis(erl_prim_loader)` answers a live pid as the oracle's booted node does) and the native `file_server_2` service (above, registered only where it owns the name). The loader's *functions* stay on the native floor (`../native/loader.rs`).

### `runner/` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Wait`; `Err(e)` → record the reason term + the original `BeamError` in `RunnerState`, then `Exit(<reason term>)`. `RunnerState` holds an engine per pid plus the `results`/`exits` maps — its four pid-keyed maps (`engines`/`results`/`exits`/`errors`) are the crate's own `FastHashMap`: each is only ever probed by pid and never iterated for an observable order, so the cheaper probe changes no verdict. **Every park publishes the parked machine's whole live root set into the process — and its live pending-exception reason as the process's extra root — and every resume re-syncs the machine from the process's authoritative root set** (`run.rs::publish_parked_roots` / `resume_from_process_roots`), so a collection driven while the process is parked — `Process::deliver`'s exit cascade is **not** gated by `gc_process_enabled` — can never relocate its heap against a partial root set and leave a stale word in `x` or in the machine's pending-exception slot. A `Wait` **arms a receive deadline** when the parked `wait_timeout`'s delay is statically readable (`Operand::Integer`/`Literal` or a live X-register); a fired deadline resumes at `timeout` delivering nothing and a message-wake cancels it.
Split by responsibility: `runner/entry.rs` (`ProcessEntry`/`ProcessEngine`/`RunnerState`), `runner/run.rs` (`RuntimeRunner` + its `ProcessRunner` impl — one reduction slice), `runner/budget.rs` (`BudgetProbe`/`BudgetContext`), `runner/reason.rs` (`normal`/`exit_reason`/`parked_receive_timeout`/`timeout_delay`), `runner/perf.rs` (`record_baseline_code`) and `runner/tests.rs`; `runner/mod.rs` re-exports the three cross-crate names (`ProcessEntry`, `RunnerState`, `RuntimeRunner`).

### `gc.rs` — the runtime-level GC state
`GcStatsSnapshot` (`gc_stats`) reports collections/failures/halted pids/valve trips **and the `reclaimed` word counter** (words reclaimed by collections), advanced by `Runtime::note_gc_reclaimed(words)` from `serve_gc_request`'s Ok arm, the three collection sites in `../context/gc.rs` (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`) and the boundary door (`../context/gc/reds_door.rs`), which is what backs `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}` (the full detail of that key lives in [`../context/CONTEXT.md`](../context/CONTEXT.md) and [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md) *Memory and statistics*); `GcState` holds the **pin** set (a pid whose heap must not move), the **halt** set (a pid whose collection failed, or whose root-set sizes changed) and the global **valve** (`disabled`, plus the first reason and a trip counter).
`try_stabilize_escaped(term) -> Result<Eterm>` is the **one** escape-store stabilization: it copies a runtime-level store's term onto the pointer-stable arena when a heap may move, propagates a **genuine** copy failure (`BeamError::SystemLimit` — the term does not fit the arena) and trips the valve (`disable_gc`) **only** for the documented off-heap-payload capability gap (an unresolvable **MSO** container, or a malformed graph — a refc binary whose payload no source table owns is **flattened** on-heap instead, `stabilize_term`), returning the original term then. Every runtime-level store goes through it — the pending spawns (`note_pending_spawn`, `runtime.rs`), the native message/function stores (`native.rs`, `native/erts_internal.rs`), the `RuntimeHooks` store (`context/runtime_hooks.rs`) and the runner's exit-reason call site (`runner/run.rs`). Its **machine-aware** sibling `try_stabilize_escaped_with(term, &SourcePayloads)` keeps those two failure classes byte-for-byte but builds the copy's *source* off-heap table from the caller's `SourcePayloads` (the executing machine's `refc_binaries()` unioned with the pid's mailbox-retained handles, `Runtime::source_payloads` / `Runtime::stabilize_term_with`) instead of using the empty one — it pushes the refc-binary handles (`push_binary`) and the MSO handles **in order** (`push`, so each lands on its container term's slot), while the node identities it carries are surfaced but never pushed (the copier re-derives a fresh `NodeEntry` per external thing). So the one caller that holds the machine which built the term (the runner's exit-reason arm, `runner/run.rs`) **shares** a term carrying an **engine-built off-heap binary or MSO container** — one refcount, no materialized copy — where the empty table must flatten the refc binary. `try_stabilize_escaped` is exactly `try_stabilize_escaped_with(term, &SourcePayloads::default())`. `halt_process_gc`/`disable_gc`/`gc_enabled`/`gc_process_enabled(pid)` are the mutators/queries the scheduler and the stores use; a process whose heap may not move is marked **relocation-exempt per slice** on the `Process` itself (the runner's post-slice FR valve), never through a runtime-level pin. Because the stabilizing copy keeps a NIF resource's **reference identity**, the reclamation's root enumeration `Runtime::gather_off_heap_roots` counts the pending timer **deliveries** (`Timers::gather_off_heap_roots`) and the stable engine **arguments and entry fun** plus an un-published parked machine's own root set (`RunnerState::gather_off_heap_roots`'s two sub-families) as root families beside the escaped closures' environments, the `seq_trace` tokens, `pending_spawns` and every live process's dictionary, mailbox, registers, saved arguments and signals — a family left out makes a live resource look unreachable. Only the families that survive a scheduler pass's two table moves are live at the park arm (the pass takes the process table and `RunnerState` out of the runtime) — `M1_GAPS_A3_NIF.md` *NIF (A.3)*.
The collection gate is the **two-phase unscanned-root valve** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word and always runs (a foreign container that forwards **no** word a relocation would follow or update is inert and declines nothing — a `make_ref/0` reference, a float, a pid, a pooled-BIF tuple of immediates — so such a root never opens the latch, while a foreign container forwarding a scanned word does); phase 2 descends the process's root-reachable scanned graph and runs only when the per-pid descent bit `GcState::foreign` is open (`Runtime::foreign_reachable`/`note_foreign_reachable`, opened by every event that can put an unscanned container into the process's reachable graph, pruned in `prune_gc_requests` and **closed** by `Runtime::close_foreign_reachable` on `ValveVerdict::foreign_free`, from the **three** doors that hand the walk the machine's whole `RootSet` — `ensure_heap_full`, `alloc_words_rooted` and `gc/reds_door.rs`; the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` signal sites hand over less than the whole set, so they may only open the latch). The reused descent scratch is `GcState::walk` (`WalkScratch`, `Runtime::walk_scratch()`). The **same valve is installed on the process table** as the `beam_process::CollectionGate` host seam: `Runtime::new` builds a `context/gc_walk.rs::RuntimeCollectionGate` **over the runtime's one shared per-pid latch cell** (`ForeignLatch` — the very `GcState::foreign` cell the admission points use) through `RuntimeCollectionGate::from`, so a signal site decides in `O(1)` while the pid's bit is clear and descends only when it is open; the gate still **owns its own scratch** (`WalkScratch`, never the admission-point one). The `beam_process` signal sites — which hold only `&mut ProcessTable` — therefore decide identically to the admission points. The gate is a *table* field, so it travels with the table into every scheduler pass.

### `ets_owner.rs` — the `ProcessExitObserver` host and the two drains
`OwnerIndex` (additive, shared with `Runtime`) records, in death order, the dead pids waiting for a drain and the append-only `(PortId, MonitorRef)` `PortWatch` pairs.
`EtsExitObserver` is the `beam_process::ProcessExitObserver`: it pushes the dead pid and its drained `PortWatch` pairs and returns (no BIF borrows the index).
`Runtime::drain_ets_owner_exits` discharges the ETS obligations (delete a dead owner's indexed tables, honour an installed heir), and `Runtime::drain_port_monitor_exits` sweeps the dangling incoming port monitors; both take the borrow with `try_borrow_mut` and **defer** to the next drain on a live borrow — never a panic, never a dropped obligation.
**A failed heir-gift deep copy is never swallowed.** `Runtime::adopt_created_table` re-owns a fresh table's creation-time gift through the fallible `Table::install_heir`; `Runtime::own_heir_gift` returns that error (a `try_borrow_mut` miss, an unknown handle, a missing heir and an arity-2 heir are all `Ok(())`, not failures) and the one policy `Runtime::report_heir_gift_failure` handles it: logged immediately (`beam_error!`, the policy `beam_process`'s exit-observer uses for a panicking observer) **and** recorded in the owner index, so the next `drain_ets_owner_exits` returns it as the typed error it is (`badarg` for a term outside `beam_ets`'s copyable subset, `out_of_memory` for an exhausted store). The successful `ets:new/2` stays successful: the table exists and its gift term is table-owned (the creation-time gift was deep-copied by `Table::new`'s build path before the re-ownership is attempted), and `install_heir` leaves the current heir untouched on failure.

## Constraints
* **`unsafe`-free** (`#![deny(unsafe_code)]`) and return-based errors ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible API returns `beam_common::Result`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`.** A pass needs `&mut Runtime` **and** `&mut ProcessTable` at once, but the table is a *field*, so `run_pass` moves both out (`take_processes`/`put_processes`) and puts them back whatever the outcome; the runner likewise takes the pid's `Machine` out of its `HashMap`.
* **A process's exit reason is not its return value** — see the parent node's Design Decisions.
* **Heap lifetime**: `Runtime` owns the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use the separate `info_heap`, rewound per call by `Runtime::reset_info_scratch`.
  That rewind **refuses** once `Runtime::info_heap_tainted` is latched (a one-way valve, set when a relocation off the region is refused), so a live term is never recycled under itself, and `erlang:system_info/1` — the one value handed **out** to Erlang code — leaves the region through `RuntimeContext::relocate_off_scratch` (the registered-BIF container copy-out: the running process's scanned young heap, else the never-reset table-less `-eval` store). A retained `system_info/1` value is therefore sound, pinned by `tests/system_info_retained.rs`.
* **A run-queue pid with no engine entry point is a recorded typed diagnostic, never an aborted pass.** `RuntimeRunner::run` (`../runner/run.rs`) takes the pid's `ProcessEngine` out of `RunnerState::engines` to run a slice; when a pid was enqueued that this runtime never registered an engine for (`RunnerState::contains`, `../runner/entry.rs`), the runner records one `UnrunnableProcess` (pid, `ProcessState`, `in_run_queue`, priority, and the registered name when the table holds one) in `RunnerState::unrunnable`, **restores the process to `Runnable`** (`slice_begin` had set it `Running`, which also changes `Process::has_unpublished_roots`) and returns `RunOutcome::Wait`, so the pid leaves the run queue and no slice is fabricated; the pass then continues normally. The record is first-write-wins per pid (a pid is diagnosed once, never per pass) and surfaces as a `[rt-trace]` line through `crate::debug_trace` when tracing is on — nothing is swallowed and nothing aborts. The **enqueue** side refuses the same pid: `Runtime::absorb_fragment_wakes` skips one the pass's `RunnerState` does not know, and `Runtime::enqueue_process` (`../runtime.rs`) already rejects one with the typed `error::unknown_process_entry`.
  The other half of the rule is unchanged and is why the runtime's own services are safe: a runtime-owned, never-enqueued service is created with `ProcessTable::spawn(policy)` (born `ProcessState::Runnable`, `insert`ed, **not** enqueued) + `ProcessTable::register(name, pid)` — `init`/`Runtime::self_pid`, the `erl_prim_loader` stand-in, the `file_server_2` service, the registered `net_kernel` service and the `-eval`/`-s`/`-run` action child. Then `whereis`/`monitor(process,Name)` resolve it, a send lands in its mailbox, and it is never run: only `Waiting`/`Suspended` are woken by a delivery (`Process::wake`, `../../beam_process/src/process.rs:462`), so such a service never reaches a run queue's wake list, and a heap-fragment delivery notes a wake **only** when that same `wake()` answered `true` (see `../dist/CONTEXT.md`). The runtime's native **`file_server_2` service** (`FileServices`, `../native/file_server.rs`) is exactly such a service — spawned **unregistered** on every route that drives a boot script (every CLI action but `-version`, plus an explicit `-boot FILE`), where the booted `kernel_sup` owns the name, and registered otherwise: `scheduler_pass` calls `Runtime::service_file_requests` as an **additive step right after the run queue drains** (the same place the port half runs), which drains the service's and its io-devices' mailboxes and replies via `ProcessTable::deliver_simple`, then calls `scheduler.resume_woken`; each delivered reply is counted into the pass's `delivered` so a serviced-only pass never looks like "nothing happened" and a boot-path caller resumes. The runtime's own **`erl_prim_loader`** stand-in (`../runtime.rs`) is the same shape — spawned `Runnable` and never enqueued, registered under its own name on **every** route that builds a runtime (nothing in `start.boot` claims it, so it never conflicts).
* **Files ~1000 lines**, split by responsibility; every public item documented (`#![warn(missing_docs)]`).

## Every site that can relocate a process heap (the soundness inventory)
Heap relocation is **not** confined to the runner's slice: any path that reaches a rooted collection moves a
process's young objects, so each must either publish that process's root set or decline. All of them share
ONE root set — `Process::regs` + each mailbox message's `payload`/`from`/`token` + dict + saved args +
pending-signal queue, gathered/scattered by `run_rooted_collection`
(`../../beam_process/src/process.rs:1695-1762`):
* the three heap-admission doors — `../context/gc.rs::ensure_heap:1034`, `ensure_heap_full:1252`,
  `alloc_words_rooted:1568` (the *running* process; publish → collect → scatter);
* the reduction/yield-boundary door — `../context/gc/reds_door.rs::collect_at_reds_boundary:176`
  (refuses `is_relocation_exempt` at `:216`, then the interval/occupancy gates at `:191`/`:234`);
* `Runtime::serve_gc_request` (`gc.rs:507`), called from the runner's Yield arm (`../runner/run.rs:1241`)
  and Wait arm (`:1392`);
* **message delivery**, i.e. the *receiver's* heap — `ProcessTable::deliver`
  (`../../beam_process/src/ptab.rs:858`, gate consulted at `:879-896`) → `Process::deliver`
  (`../../beam_process/src/process.rs:1150`, `ensure_capacity:1621` on the retry). Reachable from
  `RuntimeContext::deliver_in_table` (`../context/send.rs:528`), hence from every pass-boundary step:
  `deliver_gc_completions`, `service_file_requests`, `drain_ets_owner_exits`, `deliver_port_messages`,
  `fire_due_timers`, `dispatch_dist_inbound`/`dispatch_dist_client_inbound`;
* **the exit cascade** — `ProcessTable::enqueue_exit_signal` (`ptab.rs:2645`) → `copy_reason_onto`
  (`ptab.rs:331`) → `grow_receiver_for_signal` (`ptab.rs:192`), reached from `terminate`/`terminate_into`;
  deliberately **not** gated by `gc_process_enabled`, only by `has_unpublished_roots()`/the gate.
All of them refuse when `Process::has_unpublished_roots()`
(`../../beam_process/src/process.rs:1370` = `relocation_exempt || state == Running`); the delivery seam
adds the receive-side valve `RuntimeContext::delivery_collection_is_unsound` (`../context/send.rs:476`).
The `foreign_reachable` latch is only ever a **descent** short-circuit — with it clear each valve still
classifies every root word — and `close_foreign_reachable` runs only from the three whole-`RootSet` doors.
**Recorded residual:** `serve_gc_request`'s `Err(_) => halt_process_gc` (`gc.rs:573-576`) discards the
`BeamError` itself, so a genuine collection failure becomes a silent halt (only the `errors` counter and
the `halted` set record it).

## Port-aware scheduling (A.4) — design decision & handoff
The pass runs the **port-less** `Scheduler::run_ready` (its port half, `Runtime::deliver_port_messages` + the one persistent poller, owns the polling), and discharges the port-aware slice's obligations **at the pass boundary**, where the port registry is free:
* **covered** — a process that died in the slices just run had its recorded outgoing `(PortId, MonitorRef)` `PortWatch` pairs swept by `Runtime::drain_port_monitor_exits` (`ets_owner.rs`) — the same end state a port-aware termination reaches for its *incoming* entries.
* **covered** — `Runtime::drain_driver_monitor_exits(&mut self, &ProcessTable)` runs immediately before `deliver_port_messages`, sweeping every live C-driver port's monitor tree (`PortRegistry::note_driver_monitor_exits`) and marking each watched pid the table no longer holds, so the same round's port-task probe fires the entry's `process_exit`; it is a scan of the live `ProcessTable`, not a second `set_process_exit_observer` (the single observer slot stays `EtsExitObserver`), and it defers with `Ok(0)` on a live registry borrow.
* **not covered** — `ProcessTable::port_closed(&mut self, ports, port, reason)` (a *closing* port notifying its monitors/links). It can only run **at the close site, while the id is still in the table**: `beam_io::PortRegistry::close` releases the id (`ids.release`), and `beam_process::PortTable::close` is `BadArg` afterwards, so a post-hoc drive from a pass boundary is impossible. That site is `crate::port`'s close path (`RuntimePorts`, reached from `beam_bifs`'s `PortHook::close_port`), outside this node.
`Runtime::with_port_table(&self, &mut ProcessTable, f)` is the intended **short-borrow seam** for such a caller (it `Rc::clone`s the port field, so the returned `RefMut` borrows the clone and both tables can be borrowed at once; a nested borrow stays the typed `unsupported`, never a panic). The `beam_process::PortTable` seam itself is **sufficient as-is** — `port_closed`/`monitor_port*`/`terminate_with_ports` already take the two tables as disjoint parameters.
**Two routes must not be retried; both are unsound by construction:**
1. **Holding the `Rc<RefCell<PortRegistry>>` borrow across `run_ready_with_ports`.** `open_port`/`port_command`/`port_close` executed *inside* a slice (`RuntimePorts::registry_mut`) `try_borrow_mut` the same cell, so a held borrow degrades every in-slice port BIF to the typed `unsupported` gap; the exercised path is the `run <file.beam>` action and the `event_driver`/`port_recv` fixtures, which open and write ports from inside a scheduled slice.
2. **`mem::replace`-ing the `PortTable` out and leaving a placeholder.** `PortTable` has no `Clone`, and `beam_io::PortRegistry::open`/`register` `insert` into the table they were given, so a nested `open_port` during a slice would silently **overwrite** a live port's `Port`/`PortMeta` (the placeholder being empty does not free number 0) — silent corruption, which this crate forbids.
**Crate change that would make the literal routing (or the port-close drive) sound:** the port table must be reachable as a **handle both the scheduler window and the nested BIF paths share**, not as a field inside the same `RefCell` whose borrow the slice must hold — e.g. `beam_io::PortRegistry` exposing `ids` as its own `Rc<RefCell<PortTable>>` (a slice borrows *that* cell and an in-slice BIF borrows it too, failing only on a genuine re-entry), and/or `beam_io`'s close path driving `ProcessTable::port_closed` at its close site with the process table in hand, **before** `ids.release(id)`.

### Process termination — where a scheduled process is reclaimed, and what is missing for a dying process's owned ports
**A normally-returning scheduled process is reclaimed by `beam_process`'s schedule-out, not by any `beam_rt` code.** `RuntimeRunner::run` (`../runner/run.rs`, the `Ok(EngineRunOutcome::Returned(value))` arm) records the `x(0)` value and returns `beam_process::RunOutcome::Exit(normal(self.runtime))`; `Scheduler::run_slice_inner` (`../../beam_process/src/scheduler.rs:394`) then dispatches to `slice_end`/`slice_end_with_ports`, whose `Exit` arm calls `ProcessTable::terminate`/`terminate_with_ports` — that reclaim is what makes `processes().get(pid)` answer `None` afterwards (`../../tests/scheduler.rs:107,207`). The mechanism runs **only** for a pid the scheduler dequeued, so a `Runnable` process that was **never enqueued** — the `-eval`/`-s`/`-run` action child — is ended by its **own** teardown instead: `../runtime.rs::as_action_process` first copies an `Ok` result onto the pointer-stable store (`Runtime::stabilize_term_with` over `Runtime::source_payloads`, exactly as the runner does for a scheduled process's `x(0)`, so the term outlives the heap that built it) and then calls `ProcessTable::terminate` with the `normal` reason the runner's `RunOutcome::Exit(normal)` carries — `beam_rt`'s pass runs the **port-less** `Scheduler::run_ready`, so the `None`-ports `ProcessTable::terminate` branch is the one it mirrors. It must be `terminate`, not a silent `ProcessTable::remove`: the removal would skip the death itself (the exit observer/ETS-owner drain, the name/link/monitor teardown) and the result copy is what keeps the returned `Eterm` from dangling (`../../tests/action_result.rs`). `ProcessTable::spawn` installs a **naked** process (no serial link, no monitor, no group leader); `Runtime::spawn_process_with_policy` adds only a group-leader entry, and `as_action_process` calls `spawn` + `set_group_leader` — so nothing binds the action child to `init`. (The runtime's root process does **not** trap exits: nothing ever calls `set_trap_exit(true)` on `self_pid`.)
**No path in `beam_rt` closes a dying process's *owned* ports.** `ProcessTable::terminate_into` drains the dying process's links, monitors and port *monitors* and resolves their peers, but it never closes a port the process **owns** (in the oracle a normal exit closes them with reason `normal`). `ProcessTable::port_closed(&mut ports, id, reason)` is the API that would notify a closing port's monitors/links, and it is called today **only from `beam_process` tests** — never from production `beam_rt`. Closing exactly one pid's ports would require enumerating them: the authoritative owner table is `beam_process::PortTable` (`beam_io::PortRegistry::port_table_mut()` / `RuntimePorts::port_table_mut()`), which stores `owners: HashMap<PortId::number, ProcessId>` with a forward `owner(id) -> Option<ProcessId>` but **no reverse `owner → [PortId]` index and no allocated-id iterator**; a caller would need a new reverse index (or an id iterator) and then, per owned port, the runtime close path (`RuntimePorts::close` / `PortHook::close_port`, `../port.rs`) plus `ProcessTable::port_closed`.

## The pass's exact step order, and when outbound distribution bytes are written
`scheduler_pass` (`scheduler.rs:816`) is one loop body.
Before the first round it boots the runtime once (`boot_if_needed`, :822), moves the process table, the scheduler and the runner state out so the runner can hold `&mut Runtime` while the scheduler holds `&mut ProcessTable` (:823-825), absorbs the caller's pre-pass wake list when `resume_first` is set (`Scheduler::resume_woken`, :835-837) and absorbs the heap-fragment wake list (`absorb_fragment_wakes`, :840).
Each round first derives its own budget, `max_slices - ran` (:847); a budget already at `Some(0)` ends the pass there, at the top (:848).
The order **per round** is:
1. the **run queue** — `scheduler.run_ready` (:853) consumes the round's budget.
2. the round's accounting: `note_context_switches` (:878) credits the executed slices to `statistics(context_switches)`, and the round's `progressed` flag with the port step's timeout is derived from its own slice count (:904-911), so a round that ran slices polls the ports without blocking.
3. `prune_gc_requests` (:920) drops a `garbage_collect` request whose process died in the slices just run.
4. `deliver_gc_completions` (:929) — the `{async, ReqId}` half of `erlang:garbage_collect/2`; counts into `delivered`, `resume_woken`, `continue`.
5. `service_file_requests` (:946) — the native-service half (the `file_server_2` service and its io-devices, contract A.9); counts into `delivered`, `resume_woken`, `continue`.
6. `service_net_kernel` (:961, body `native/net_kernel.rs:206`) — the `net_kernel` service's mailbox; counts into `delivered`, `resume_woken`, `continue`.
7. `drain_port_monitor_exits` (:976) — the dead watchers' `(port, reference)` pairs; delivers nothing, so it falls through.
8. `drain_ets_owner_exits` (:983) — the ETS owner-death obligation; counts into `delivered`, `continue`.
9. `absorb_pending_spawns` (:993) — a child an `erlang:spawn*` created during the slices just run; `continue` when it enqueued one.
10. `absorb_fragment_wakes` (:999) — the fragment counterpart of the table's own wake list, yielding the round's `woke` count.
11. `drain_driver_monitor_exits` (:1008) — marks every `driver_monitor_process` target the table no longer holds, so the round's port tasks below fire the driver's `process_exit`; delivers nothing, so it falls through.
12. `deliver_port_messages` (:1016) — the **port half**: what a live port produced, delivered into the owning process's mailbox; counts into `delivered`, `resume_woken`, `continue`.
13. `drain_nif_thread_sends` (:1046) — the **foreign-thread NIF half** (contract A.3), immediately after the port step and before `pump_dist`: an external producer the runtime does not drive (a thread a NIF created through `enif_thread_create`, like the OS child behind a port) queues a message through `enif_send` that must land in the target's mailbox and resume its receiver, so the runtime asks it for work once per round; on `> 0` it counts into `delivered`, `resume_woken`s the woken receiver and `continue`s so that receiver runs (it composes with the distribution half below rather than short-circuiting it, since a delivery is only tallied and the round simply restarts), and it costs one `Option` test for a runtime with no factory installed.
14. `pump_dist` (:1057) — the accepting node's handshake/accept step (contract A.5); adds to the tally only, and falls through.
15. `bind_dist_peers` (:1068) — binds every freshly established accepted link to its peer's node atom term; falls through.
16. `service_node_monitors` (:1080) — the `erlang:monitor_node/2` `{nodeup, Node}`/`{nodedown, Node}` transitions observed after the peer binding (:1071-1079); counts into `delivered`, `resume_woken`, `continue`.
17. `dispatch_dist_inbound` (:1093) — routes what the accepted links decoded; counts into `delivered`, `resume_woken`, `continue`.
18. `pump_dist_client` (:1107) — the connector's outbound step, which also flushes the controls the process layer's `DistSignalRouter` queued; adds to the tally only, and falls through.
19. `dispatch_dist_client_inbound` (:1116) — routes what the outbound links decoded; counts into `delivered`, `resume_woken`, `continue`.
20. `fire_due_timers` (:1128) — the **timer half**: every `erlang:send_after/3` message whose deadline passed, plus every fired finite `receive … after T` deadline (`absorb_timer_wakes`); counts into `delivered`, `resume_woken`, `continue`.
21. a round that absorbed a fragment wake (`woke > 0`, :1141) goes round again, and otherwise `timer_wait` (:1149) decides the pass's sleep: a policy that allows one more wait sleeps to the earliest pending deadline and `continue`s, and `None` (:1159) ends the pass.
Every step that yields `Ok(n>0)` and counts into `delivered` `continue`s back to the run queue, **except** `pump_dist` (:1057), `pump_dist_client` (:1107) and the two monitor drains (:976, :1008), which only add to the tally (if anything) and fall through; `timer_wait` → `None` (:1159) ends the pass, and `budget == Some(0)` (:848) ends it at the top.
The pass's own outcome is restored unconditionally: the runner state, the scheduler and the process table go back into the runtime whatever the loop's `Result` says (:1162-1166).
**Outbound bytes are written at three different moments.** (a) `Runtime::dist_send_reg_send`/`dist_send_message_pid`/`dist_send_alias` (`../runtime.rs:4170`/`4198`/`4230`) and anything else reaching `DistLinks::route_control`/`route_message`/`route_alias` (`../dist/links.rs:318`/`345`/`391`) write **synchronously inside the call** (`DistConnection::send_control` → `flush_output`, `../dist/connection.rs:229`). (b) A signal the **process layer** routes (`DistSignalRouter::route`, `../dist_client/router.rs:49`) only materialises onto the client's scratch heap and pushes onto `DistClientInner::pending` (`../dist_client/client.rs:862`); its bytes are written by `flush_pending` (`client.rs:739`), whose **only** caller is `DistClient::pump` (`client.rs:358`) — reached from the pass at `pump_dist_client` (`scheduler.rs:1427`) and from `Runtime::dist_connect`'s handshake loop (`../runtime.rs:4040`). (c) `DistNode::pump` (`../dist/node.rs:299`) drives the **accepted** links' handshake/reads only and writes no queued control.
So a routed signal queued in a slice is normally written **later in the same pass** (the round's remaining steps reach `pump_dist_client`), but a round that `continue`s at any step above, or a pass that ends first, defers it to the **next** pass: there is no drain at the pass tail and none before a `break`.
The quiescence test sees a link **and** what the wire is still owed: `DistClient::has_links` (`client.rs:495`) reads `DistLinks::is_idle`, and `DistClient::has_pending_outbound` (`client.rs`) reads the outbound queue plus either half's driver output. A `pending` control therefore keeps a pass alive by itself until `pump_dist_client` flushes it — which matters precisely when its node's link was **retired** between queueing and the flush: the flush is what discovers that and drops the item with a recorded `last_error`.

## Distribution (A.5) — inbound validation and the unrouted families
**Every inbound delivery is validated against its own link.** Both production inbound drives — the
accepting node (`dispatch_dist_inbound` → `dist::DistNode::dispatch_inbound`) and the connector
(`dispatch_dist_client_inbound` → `dist_client::DistClient::dispatch_inbound`) — drain each link through
`beam_dist::ConnectionDriver::dispatch_inbound_checked`, so a control message is checked against **that**
link's own `peer_name()`/`our_name()` identity (the per-link `LinkIdentity`) before it can reach a
mailbox: `beam_dist`'s `Delivery::classify_validated` reproduces the C's per-opcode `invalid_message`
shape checks (`dist.c`) plus the per-link anti-spoof check `dep != external_pid_dist_entry(from)`. The
identity is interned into the **same** `AtomTable` the message was decoded against, so the node
comparison is a raw term `==`. A validation failure is an `Err` — a **link-level** failure that never
reaches `beam_dist::InboundSink`: the drive retires (kills) **just that link**
and records the reason in `DistNode::last_link_error`, the C's `invalid_message` connection kill, never a
pass failure. The check cannot live in `LocalDeliverySink`: one sink is built per pass and shared by
every link, so it has no peer to compare a `From` against.
`Runtime::dispatch_inbound` (the explicit single-driver seam) deliberately stays on the *classify-only*
`ConnectionDriver::dispatch_inbound`: its caller supplies an arbitrary hand-built driver whose handshake
names need not be this runtime's node identity, so a per-link check there would judge a message against a
*foreign* identity. It is the semantic view, not a wire drive.

**`LocalDeliverySink` routes the message families plus the route-free receipt families; the rest is the
honest `DeliveryOutcome::Unsupported`**, with the still-missing API named at its arm (`../dist.rs`'s
`LocalDeliverySink::deliver`). `beam_process` exposes the **outbound** relationship entry points
(`ProcessTable::link_term`/`unlink_term`/`monitor_term_with_options`/`demonitor`/`send_exit_term`, each
routing a `DistSignal` through the installed `DistSignalRouter`) **and** the **route-free receipt**
counterparts, which install/drop the local record and then follow the C's `break; /* Done */` (`dist.c:2258`)
without echoing the opcode it received:

| Inbound family (C arm) | Receipt API used (or the still-missing API) |
|---|---|
| `Link` (`DOP_LINK`, `dist.c:2224-2275`) | **routed** — `record_remote_link(to: ProcessId, remote: RemotePid)` (record-only; the C never echoes one) |
| `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` (`dist.c:2760`/`:2824`) | **routed** — `apply_remote_exit_signal(to, from: RemotePid, reason, untrappable)` (`untrappable = true` for the `Exit2`/`PayloadExit2` family) |
| `UnlinkId`/`UnlinkIdAck` (OTP-26+ handshake, `dist.c:2284`/`:2315`) | **partially routed** — `unlink_from_remote(..)`/`unlink_ack_from_remote(..)`; an inbound `DOP_UNLINK_ID` with `id != 0` owes a `DOP_UNLINK_ID_ACK` this sink has **no reply channel** to emit, so the link record is dropped and the wire half is reported the typed `Unsupported` (`id == 0` owes no ack and is `Delivered`) |
| `Monitor`/`Demonitor` (`DOP_MONITOR_P`/`DOP_DEMONITOR_P`, `dist.c:2341`/`:2415`) | **routed** — `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)` records the incoming watcher and `demonitor_from_remote_ref(watched, reference: RemoteRef)` removes exactly that record, both keyed by the **whole** peer-minted wire reference (`RemoteWatcherRef::Remote(RemoteRef)`, all-immediate, so two peer-minted references never collapse) |
| `MonitorExit`/`PayloadMonitorExit` (`dist.c:2700-2714`) | **routed** for a DOWN whose reference *this* node minted (the wire image inverts to the recorded `MonitorRef`) — `remote_monitor_down(watcher, watched: RemotePid, reference, reason)`; a name-targeted DOWN or a foreign reference stays `Unsupported` |
| `GroupLeader` (`DOP_GROUP_LEADER`, `dist.c:2889`) | **routed** — `set_group_leader_from_remote(to, from: RemotePid)` |
| `SpawnRequest`/`SpawnReply` (`dist.c:2902-3093`) | **still a typed gap** — needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender + the reservation bookkeeping); a `beam_rt` CLI process serves no spawn requests and holds no reservations |
| `Other(Dop::Unlink)` | **still a typed gap** — `DOP_UNLINK` is not a v6 opcode; the C's `invalid_message` arm kills the connection (`dist.c:2277-2282`), which the link driver owns, so the sink reports "recognised, not routed" |

Evidence for the validated path: `../../tests/dist_delivery.rs`'s
"(6b) Every inbound delivery is validated against **its own link**" — a forged `DOP_REG_SEND` (`From` a
non-pid) and a `DOP_LINK` whose `From` names a third node are each refused, reach no mailbox and retire
their link with a recorded `last_link_error`, while a well-formed message on the same link still delivers.

### The node's public surface (both halves)
`DistNode` is the *accepting* half: `start(configured, cookie)` **binds** a wildcard listener
(`DIST_LISTEN_ADDR`, OS-assigned port; an unbindable address is a start-up error) and the first `pump()`
**publishes** the node to `epmd` (`ALIVE2_REQ`). Accessors: `node_name()`/`advertised_name()`/`epmd_name()`/
`is_short_name()`/`port()`/`creation()`/`is_registered()`/`is_alive()`/`registration_error()` (recorded,
never raised)/`connections()`/`is_idle()`/`last_link_error()`. `NodeName::parse` splits a `-name`/`-sname`
value into `full`, `advertised` (the full `node@host` name in **both** cases — a peer resolves it with
`list_to_existing_atom/1` and aborts on a bare short name) and `epmd` (the short name for `-sname`,
verbatim for `-name`; a bare value's host is `local_hostname()`); `resolve_cookie(init_args)` is
`-setcookie`, else `$HOME/.erlang.cookie`, else `nocookie`. `DistConnection` wraps one accepted socket in
a **server-side** `beam_dist::ConnectionDriver` (`'N'` → `'s'`/`'S'` → `'r'` → `'a'`); `pump()` registers
once, accepts up to `MAX_ACCEPTS_PER_PUMP` (8) connections non-blocking, then steps every link under a
per-link `DIST_READ_SLICE` (25 ms) read timeout, so one pump can never stall the scheduler (a link's
protocol/write failure **retires** it and records why). The scheduler pass drives it from
`Runtime::dispatch_dist_inbound`, **gated by `Runtime::inbound_delivery`** (default **ON**); the pass
early-returns unless the runtime **is** a distribution node **and** that node has an established link, so a
`nonode@nohost` run pays one bool test per pass and allocates nothing.
The **envelope rule**: the mailbox `from` is always an **immediate** (`envelope_from` — the sender peer's
node atom when the wire carried a sender pid, otherwise the word the peer put on the wire, `''` for the
plain `DOP_SEND*` forms); a non-immediate is refused, because `beam_message` gathers only each queued
message's payload as a GC root. `LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes
`Delivery::Send`/`RegSend` through `ProcessTable::deliver_simple` (which wakes a blocked receiver; an
unregistered name / a non-pid `to` follow the oracle's RegSend/Send arms) and `Delivery::AliasSend`
through the table's alias resolution (consuming a `reply_demonitor` alias after a successful delivery; an
unknown/inactive reference is the oracle's silent drop), plus the **plain** `Delivery::AltactSigSend`
message sub-cases.

`DistClient` / `ClientLink` / `DistClientInner` / `DistRouter` (`../dist_client.rs`) are the *connecting*
half: `connect`/`connect_addr` dial a peer and run the **client** `beam_dist::ConnectionDriver` handshake
(`DIST_CONNECT_TIMEOUT`); `pump` is the one place a live `DOP_*` is encoded (atom-table encode + socket
write), with `send_reg_send`/`send_message_pid`/`is_connected_to_node`/`connected_nodes`/`last_error` as
its accessors; `DistRouter` implements `beam_process::DistSignalRouter` — it materialises a signal's terms
on a stable scratch heap and queues `{node, Dop, args}`, which `pump` then drains — and is installed on
the **`ProcessTable`** (`../runtime.rs`), not the `Runtime`, because the table is moved out for every pass.
There is **no** `{setup,…}`/`{nodeup,…}` control exchange in OTP distribution: after the final `$a`
handshake ACK the link carries `DOP_*` immediately, and node-up is local bookkeeping
(`net_kernel:mark_nodeup`). Driven from `Runtime::pump_dist_client` and
`Runtime::dispatch_dist_client_inbound`.

## Known Issues
* **`absorb_fragment_wakes` enqueues a pid only when it is a live `Runnable` process the pass's `RunnerState` can actually run.** Its gates are "still in the table", "`ProcessState::Runnable`", "not already in a run queue" (`scheduler.rs`) **and `RunnerState::contains`** — the last one is what keeps a runtime-owned never-enqueued service (`init`/`Runtime::self_pid`, the `erl_prim_loader` stand-in, the `file_server_2` service, the registered `net_kernel` service, the `-eval`/`-s`/`-run` action child) off the queue: such a service is *born* `Runnable` and never runs, so `Runnable` alone is not a "should be scheduled" test. A refused pid gets the same typed `UnrunnableProcess` diagnostic the runner records (see the Constraints rule above) instead of breaking the pass. The note itself is the fragment path's substitute for `ProcessTable`'s wake list, so it is recorded **only on a real wake** — by `../dist/inbound.rs::enqueue_fragmented` through `fragment_deliveries: Vec<(ProcessId, bool)>` and by the local send path's `if woken { … }` (`../context/send.rs::send_fragmented_message`); the descent gate `note_foreign_reachable` is unconditional for a fragment, because its payload sits where the receiver's collector does not scan. Pinned by `runtime::scheduler::tests::a_fragment_note_for_an_engine_less_pid_does_not_take_the_pass_down` and `…::a_fragment_note_alone_does_not_enqueue_a_parked_receiver`.
* **Quiescence blind spot: a retired native io-device is never drained again.** `scheduler_pass`'s native-service step drains exactly `FileServices::server()` + `file_services.devices.keys()` (`../native/file_server.rs`). When `serve_file_message` sees `retire == true` it does `file_services.devices.remove(&service)`, so a still-live device pid holding a queued request vanishes from the drain list. The reply is never delivered, the parked sender is never woken, and on the next pass `ran == 0 && delivered == 0 && is_quiescent()` holds — `run_scheduled` then returns `beam_engine::blocked()` (exit 3) even though a wake source still has work. `is_quiescent` is not itself wrong; the wrongly-holding premise is "no drainable service has work" while a *retired* device does. Reproduced with `epp:parse_file/2` from a scheduled `run` process. The `retire` flag itself is a false positive: `get_until::EngineContinuation::apply` sets `raised = true` on **any** `Err`, including the typed gaps `unsupported("… continuation suspended in a receive")` (`../native/file_server/get_until.rs:317-319`) and `unsupported("… returned neither {more,Cont} nor {done,Result,Buf}")`, not only on a genuine scan raise (observed genuine raise: `error:function_clause` in `erl_scan:options/1` from `erl_scan:tokens/4`). Fix belongs in `../native/file_server.rs` (keep draining a retired pid, or reproduce the OTP close-handshake ordering), **not** in this node.
* **A *live port* alone keeps a pass non-quiescent.** `PortRegistry::has_nothing_to_poll` (`../port.rs:1470-1476`) is `meta.is_empty() && pending_events.is_empty() && pending_port_signals.is_empty() && !tty.is_armed() && !watch.has_pending_signal()`, so while any port's metadata exists it answers `false` and `is_quiescent` (`scheduler.rs:535`) answers `false` — a `run`-route process parked on a message only a port can produce therefore never takes the `blocked()` abort (`pump_run_to_completion`, `scheduler.rs:495`) and keeps stepping (sleeping `PORT_POLL_SLICE` on a round that ran nothing) until the port answers or `RUN_DEADLINE` expires. That is what a driver-side asynchronous reply (an `{inet_reply, …}`-style term drained at the `deliver_port_messages` boundary, `scheduler.rs:885`) relies on; the port round is drained **only** there on the scheduled route (the sole production caller of `../port.rs:3089`).
* **The port half's block is per *zero-slice round*, and only the boot drive's policy may shorten it.** `port_timeout` is `Duration::ZERO` for a round that ran a slice (`progressed`), and otherwise `PORT_POLL_SLICE` inside `PortRegistry::pump` (the blocking `epoll_wait(…, 25)`) — **except** under `TimerWait::ImminentWithin(_)` while no port owes a reply (`Runtime::awaits_port_reply`, i.e. `PortRegistry::awaits_port_reply`: some port with `output > input`), which is what keeps the boot's live-but-idle `inet_gethost` child from costing a poll slot per step (`../port/CONTEXT.md` *Measured*; [`../../PERF.md`](../../PERF.md) *The boot path's one live-but-idle port, and the poll budget*). A table that cannot be borrowed stays patient, so the gate only ever shortens a wait it can justify, and the `run`/`-eval` routes keep the unconditional blocking poll because a child there may speak unprompted.
  A boot-drive step (`pump_scheduler_boot` → `drive_scheduler`, `../boot/drive.rs:299-314`; the `{kernelProcess,…}` bursts, `:267`) that ends a `{apply,…}`'s drive still *polls* once as soon as *any* port is live — the gated timeout only makes that poll non-blocking — where the same step costs nothing at all before the first `open_port` (`has_nothing_to_poll()` ⇒ `deliver_port_messages` early-returns, `port.rs:3335-3343`).
  On the `-eval` action route `halt/N` makes **zero** passes (`Runtime::eval` → `as_action_process`, `../runtime.rs:2981-3086`: no pump at all), so the eval route contributes no polls of its own; its only pump sites are a `receive` (`../eval/mod.rs:1363,1399,1422`).
* **`delivered` does not count ordinary Erlang `send`.** Only port/timer/file-service/ETS/dist deliveries are counted (`scheduler.rs:719-849`), so a pass whose only progress is a plain message wake can look like `delivered == 0`.
* **The `run` route's pass wait is progress-aware; a pass that still has slices to run never sleeps.** `pump_run_to_completion` passes `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)` (`scheduler.rs:410`) and `timer_wait` returns `None` for it whenever the round that just ended **ran at least one slice** — `let progressed = round_slices > 0;` (`scheduler.rs:866`), fed by the round's own `run_ready` count — so the arm is `(!progressed).then(|| remaining.min(max))` (`scheduler.rs:1118`), still gated by `TimerWakes::can_wake(run_wake_pid)`.
  The guard is what keeps a budget-exhausted pass from sleeping: `run_ready_inner` breaks at the pass's slice budget (`RUN_STEP_SLICES`, `beam_process/src/scheduler.rs:514`) with the run queue still non-empty, so such a pass would otherwise sleep a full 25 ms immediately before its own budget check ends it — pure waste on a single-threaded pass.
  The unchanged half is the anti-spin sleep, pinned by three `scheduler/tests.rs` cases: `the_run_route_still_sleeps_to_a_parked_receive_timeout` (a `receive … after 20` on the `run` route still sleeps to its deadline — counter ≥ 1, i.e. it sleeps rather than spins — and still resumes on the timed-out path), `the_run_route_never_sleeps_a_poll_slice_while_it_still_has_slices_to_run` (`pass_sleeps() == 0` while the target is runnable) and `the_idle_only_wait_policy_skips_the_wait_when_the_round_ran_slices` (the policy table itself).
  The counter is the test-only per-thread `PASS_SLEEPS` (`pass_sleeps`/`reset_pass_sleeps`), so both halves are pinned structurally, never by wall clock.
  Measured on a `send_recv:plain/1` ping-pong (`receive … after 30000`), N = 20000: **0 `clock_nanosleep`** and, with the port half progress-aware, **6** blocking waits in total (≈ 137 ms, the boot's own idle rounds) instead of one 25 ms `epoll_wait` stall per pass, on both the default native-baseline tier and `BEAM_RT_TIER=interpreter`.
  The **port half** is progress-aware by the same flag: `scheduler_pass` computes `progressed` from the round's own slice count *before* the port half and hands `deliver_port_messages` `PORT_POLL_SLICE` only for a round that ran nothing, `Duration::ZERO` for a progressed round (it still polls — a driver may have bytes queued — it just does not block). Without that, a live `inet_gethost` port keeps `has_nothing_to_poll()` false and every pass stalls the full 25 ms, which cost a 20 000-round ping-pong 1063 blocking waits / 26.9 s. Pinned by `scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing` (the test-only `BLOCKING_PORT_ROUNDS` counter) and end-to-end by `tests/run_route_sleep.rs`.
  The `tools/bench` figure for the `copy_bound` case `send_recv_plain` predates the progress-aware wait and is due for a refresh (owner `tools/bench`).
* **What still costs a decline: a *foreign container that forwards a word*.** The valve has **five** doors — `ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the park arm's `serve_gc_request` and `context/gc/reds_door.rs`'s reduction/yield-boundary door — and each runs the **per-word** classification phase plus, once the pid's foreign-reachability bit is set, an `O(live)` descent of the process's root-reachable scanned graph; the walk itself is the sibling `../context/gc_walk.rs`. A foreign container that forwards **nothing scanned** declines nothing — `context/gc.rs::forwards_scanned_word` decides that, over the same `beam_term::layout::for_each_child_slot` enumeration the collector uses — so a loop that mints a reference per iteration (`make_ref/0`'s M1 block) keeps its latch **closed**, its nursery drained and its heap flat (pinned by `context/gc/refs_plateau.rs`: a ref-minting loop against a reference-free control, at N and 2N, and by `../../tests/foreign_root_loop.rs`: a loop holding a BIF container result — a *scanned* root, since the process-route copy-out re-homes it — against its control, with equal collection counts at N = 5 000 … 200 000). A foreign container that **does** forward a scanned word — a door's `runtime.alloc_words` **arena** fallback holding a young list, a pooled-BIF tuple holding one, a message fragment — is the genuine hazard: it declines at every valve call while it is reachable, which is why the engine's **rooted** door meets a young-heap bump refusal with `Process::grow_nursery` (the no-relocation seam, which leaves `Process::collection_debt` for the next occupancy test) and a retried bump **before** the valve/arena path, keeping the term on the reclaimable heap; and dropping it lets the next full admission door retire the latch on a foreign-free descent. Current per-iteration dispatch and profile figures live in [`PERF.md`](../../PERF.md).

## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`.
A bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass` → `note_pending_spawn` → `absorb_pending_spawns`), and every slice's end absorbs the wake list (`beam_process/src/scheduler.rs:435`), so a synchronous two-process ping-pong never empties the run queue and stays in **one** `run_ready` call (`run_ready_inner`, `scheduler.rs:513` `while !self.run_queue.is_empty()`) — it does **not** re-enter the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`), so per-pass costs are amortized ×1000 and **per-slice** costs dominate a long run (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000`, `beam_process`).
- **Per pass:** `take_processes` (`src/runtime/scheduler.rs:1166`) builds a **fresh empty `ProcessTable`** (11 `HashMap::new()` + `Vec`s + `RefAllocator`, `ptab.rs:543`) and `mem::replace`s the runtime's table with it; `Scheduler::new()` replaces the old scheduler (`:597`); `put_processes` is a plain assignment.
- **Per pass: the pass wait is progress-aware, so a ready `run` never sleeps.** The pass bottom can `std::thread::sleep` (`src/runtime/scheduler.rs:818`) under the `run` route's `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)` (`:410`); `timer_wait` takes the sleep only when the round that just ended ran **zero** slices (`let progressed = round_slices > 0;`, `:866`) **and** a deadline exists that `TimerWakes::can_wake(run_wake_pid)` can wake (`src/runtime/timer_wakes.rs:123`); the slept amount is `remaining.min(25 ms)` and the policy permits **one** sleep per pass (`:153`).
  Measured: a `send_recv`-shaped `run` issues **0** `clock_nanosleep` (`strace -f -e trace=clock_nanosleep -T`), the anti-spin half is intact (a parked `receive … after T` is still slept to), and the `send_recv_plain` residual is per-slice work, **not** a per-pass sleep; the boot drives' `ImminentWithin` policy is unchanged.
  Pinned by `src/runtime/scheduler/tests.rs::{the_run_route_never_sleeps_a_poll_slice_while_it_still_has_slices_to_run, the_run_route_still_sleeps_to_a_parked_receive_timeout, the_idle_only_wait_policy_skips_the_wait_when_the_round_ran_slices}` and end-to-end by `tests/run_route_sleep.rs` (0 `clock_nanosleep` on a 200 000-round two-process ping-pong, ≥1 for a parked `after 20`); the measured per-case cost of that path is in [`../runner/MEASURED.md`](../runner/MEASURED.md) *The run route's sleep accounting*.
- **Per slice:** engine moved out of/into a `HashMap` (`src/runner/run.rs:383`, `:817`/`:936`); a fresh `RuntimeContext` incl. `DispatchMemo::default()` (8 slots, `src/context/dispatch.rs:42`) (`src/runner/run.rs:444`); `ctx.enter_module` allocates a `String` (`src/context/runtime_context.rs:501`); the park hand-off (`src/runner/run.rs::park_machine` → `publish_parked_roots`, and the resume's `resync_parked_roots`, `src/context/runtime_context.rs`) `copy_from_slice` the whole x file (1024 words) plus the stack (`src/context/gc.rs`) — **skipped entirely for an exempt park** (every `Wait` park, and a `Yield` arm whose slice ended with a live FR prefix), where the parked machine stays the authoritative root set (see [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md) *GC-relocation hazards*); `schedule_receive_timeout`/`cancel_receive_timeout`/`take_timer_resume` add+remove a timer-heap entry and a `TimerWakes` entry (`src/runtime.rs:1175`/`:1194`/`:1204`) — a finite `receive … after T` pays this on **every** iteration, and the `Timers` heap reclaims a cancellation the heap does not hold at its head by rebuilding past a watermark (`COMPACT_SLACK = 64`, `src/timers.rs:332`: a rebuild runs only once tombstones outnumber live entries), so a cancelled deadline is never a permanent tombstone.
  Every pid/Eterm-keyed collection the hot path touches is `crate::hasher`'s word-mixing map, not SipHash (`TimerWakes::{deliver,resume}`, `Runtime::{timer_resumes,group_leaders,async_dist,monitor_nodes}`, `RunnerState`'s `engines`/`results`/`exits`/`errors`, the mailbox map and the reachability latch); `slice_begin`/`slice_end` (`scheduler.rs:664`/`:737`) and the capacity-retaining wake sweep (`drain_woken_scratch_into`, `:813`) run per boundary.
- **Per slice, O(heap)/O(#mailbox) only when triggered:** the heap-admission seam (`src/context/gc.rs::ensure_heap`) short-circuits on occupancy (`:581`) but still pays a `current_module` **`String` clone** (`:555`) and two valve lookups on *every* admission point; the O(live-objects) descent (`any_root_is_unscanned`) is gated per-pid on the shared latch (`foreign_reachable`, `:597`), and the process table's `RuntimeCollectionGate::declines_relocation` (`src/context/gc_walk.rs`) is built over the **same** latch cell (`ForeignLatch`) so a clear bit answers `false` with no descent (O(1) per delivery) — both only on a collection/refusal.
- **Per round (cheap here):** `service_file_requests` allocates one `Vec::with_capacity(1+devices+retired)` (`src/native/file_server.rs:321`); `deliver_port_messages` early-returns `Ok(0)` on `has_nothing_to_poll()` with no live port (`src/port.rs:2566`, no poll sleep); each dist half is one `Option` match with no node.
- **Out of this node:** the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.
## Routing Table
* `../runtime.rs` → the `Runtime` façade (boot wiring, code server + module cache, the slice, the spawn API, the timer/distribution accessors, `stabilize_term`/`stabilize_term_with` + their destination off-heap table `eval_off_heap`, `materialize_args`, `system_info`, `eval`, `format_term`, `refs_mut`, the `file_services` field, and the runtime's own `init`/`erl_prim_loader` process registrations).
* `scheduler.rs` (+ `scheduler/tests.rs`) → the scheduler-pass family (one pass = processes → ports → timers → distribution, in bounded steps — the five distribution steps being `pump_dist`/`bind_dist_peers`/`dispatch_dist_inbound`/`pump_dist_client`/`dispatch_dist_client_inbound`, with the node-monitor step `service_node_monitors` right after `bind_dist_peers`; the native-service step `service_file_requests` runs right after the run queue drains) + the `Runtime::with_port_table` short-borrow seam for port-aware `beam_process` operations.
* `gc.rs` → `GcState` (the pin/halt/valve sets, the `foreign` per-pid descent latch — a shared `Rc<RefCell<HashSet<ProcessId, FastBuildHasher>>>` cell (`ForeignLatch`) the installed `RuntimeCollectionGate` also holds a clone of; a verdict-only set of internal pids, so it probes with the crate's own deterministic `hasher::FastBuildHasher` rather than `RandomState`'s SipHash, and its `#[cfg(test)]` `latch_counters` count every probe / insert / fresh insert — the `walk: WalkScratch`) + `gc_stats`/`GcStatsSnapshot` (incl. the `reclaimed` word counter, advanced by `note_gc_reclaimed`) + `try_stabilize_escaped`/`try_stabilize_escaped_with` + `foreign_reachable`/`note_foreign_reachable`/`walk_scratch`.
* `ets_owner.rs` → the `ProcessExitObserver` host (`OwnerIndex`/`EtsExitObserver`) + `Runtime::drain_ets_owner_exits`/`drain_port_monitor_exits`.
* `../runner/` → the `ProcessRunner` (`mod.rs`/`entry.rs`/`run.rs`/`budget.rs`/`reason.rs`/`tier.rs`/`perf.rs`/`tests.rs`), re-exporting `crate::runner::{ProcessEntry, RunnerState, RuntimeRunner}`.
* `../context/gc.rs` → the engine's heap-admission point (`ExecutionContext::ensure_heap`) that drives this state; `../context/gc_walk.rs` → the two-phase valve's reachability walk (`any_root_is_unscanned`/`process_roots_are_unscanned` + `WalkScratch`) and the `CollectionGate` host seam (`RuntimeCollectionGate`).
* `../boot/CONTEXT.md`, `../cli/CONTEXT.md`, `../info/CONTEXT.md` → the boot, A.6 and A.8 surfaces layered on the façade.
