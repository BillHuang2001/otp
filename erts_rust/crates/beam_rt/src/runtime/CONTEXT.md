# `beam_rt::runtime` — the `Runtime` façade, the scheduler-pass family and the `ProcessRunner`

## Intent
`../runtime.rs` is the `Runtime` façade: the one type that owns every runtime table and the runtime-level operations the CLI, the boot path and the `-eval` evaluator call (`run_function`/`run_module`/`run_scheduled`, the spawn API, `system_info`, `eval`, `format_term`, `refs_mut`, the timer/distribution accessors).
`../runtime/scheduler.rs` (+ `scheduler/tests.rs`) is the **scheduler-pass family**: it drives processes, ports, timers and distribution in bounded steps (the distribution half is **four** steps — the server pump/inbound and the connector's pump/inbound).
`../runner/` (a sibling directory) is the `beam_process::ProcessRunner` each scheduled process runs through; it is documented here because it is the scheduler's own instrument.
`gc.rs` holds the runtime-level GC state, accounting and safety valves, and `ets_owner.rs` the `ProcessExitObserver` host with the two owner-death drains.
`retention.rs` is the **retention accounting**: `RetentionStats` (one snapshot of the four never-freed storage regions — arena demand counters, the pooled BIF heap's regions/words/capacity/peak-use plus its nested-call loan count and seed, the `-eval` store's current and retired capacity, the escaped off-heap store's handle count) and its `Runtime::retention_stats()` accessor, plus the one-line `Display` form `BEAM_RT_MEM_TRACE` prints.

## API Surface
### `runtime.rs` — the façade
`Runtime` owns every table (config, atom table, processes + mailboxes, BIF heaps, scheduler + runner state, ETS/port/NIF registries, refs, timers, the node-global `persistent_terms` store, `file_services`, dist) and the scratch `info_heap`.
`retention.rs` publishes the four never-freed regions' figures as `Runtime::retention_stats() -> RetentionStats` (a pure read, no allocation, nothing in the runtime consults it); `BEAM_RT_MEM_TRACE` prints one line of it after the boot and again on the way out of `cli::run`.
The **scheduler-pass family** (`run_one_slice`/`run_slices`/`run_scheduler`/`pump_scheduler`/`pump_scheduler_now`/`pump_scheduler_boot`/`run_scheduled`, the shared pass body, wake absorption, the port/timer/distribution halves) lives in `src/runtime/scheduler.rs` (+ `tests.rs`), but every entry point stays an inherent `Runtime` method.
* **boot/config**: `new(RuntimeConfig)`, `with_defaults()`, `boot()` (idempotent; A.7), `boot_from_script(path)` (A.7), `is_booted()`, `config()`, `load_module(path)`, `module(name)`, `preloaded()`, `preloaded_loaded()`/`is_preloaded_loaded(name)`.
* **the slice**: `run_function(path, function, arity, args) -> Result<Eterm>` (x(0)); `run_module(module, function, arity, args, out: &mut dyn OutputSink)`.
* **the CLI `run` action**: `run_scheduled(path, function, arity, args) -> Result<Eterm>` loads the file, `spawn_process`es the export and pumps the **full** scheduler in bounded steps (`RUN_STEP_SLICES` = 1000, `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE)`) until the process returns (`x(0)`), **raises** (`take_process_error` returns the original `BeamError`), is quiescent (`scheduler.rs:504`: `ran == 0 && delivered == 0 && is_quiescent()` → the typed `beam_engine::blocked()`), or outlives `RUN_DEADLINE` (60 s); exit-code classification matches the single-pass path. `is_quiescent` (`scheduler.rs:590`) is four terms: an empty run queue; `PortRegistry::has_nothing_to_poll()` (no live port, no armed `tty_select/2` interest *and* no **fired, undrained** signal self-pipe — an armed-but-idle `handle` disposition is not pending work, [`../port/CONTEXT.md`](../port/CONTEXT.md)); the timer term (`timers.next_deadline().is_none()`, or for the `run` route only a deadline that could wake its one target, `timer_wake_targets.can_wake`); and the **distribution** term: no accepted node holding a live link (`DistNode::is_idle`) and no client holding any link, handshaking or established (`DistClient::has_links`, which reports a borrowed cell as "has links") **or** owing the wire work it has already accepted (`DistClient::has_pending_outbound`: a queued routed signal, or bytes a link's driver has not written).
A `run`-route process parked on a bare `receive` with a live distribution link therefore keeps pumping (a peer's `DOP_*` can arrive and wake it), bounded by `RUN_DEADLINE`'s "did not terminate" diagnostic instead of exiting 3 through `beam_engine::blocked()`; a runtime with no node name carries neither half (`None`) and a node with no link answers idle, so a non-distributed runtime is quiescent as before. A bounded pass cannot sleep its way out of ending: it sleeps at most **once** (`TimerWait::allows` → `AtMost(_) | AtMostWhenIdle(_) | ImminentWithin(_) => waits == 0`, `scheduler.rs:149`) and its round budget's `Some(0)` exit (:848) ends it at the top, so it returns `Ok((ran, delivered))` and control reaches the quiescence test.
* **the bounded pumps**: `pump_scheduler(max_slices) -> Result<u64>` is the **blocking** bounded step (`TimerWait::AtMost(TIMER_PUMP_SLICE = 100 ms)`, `scheduler.rs:74`): a zero-slice round sleeps `min(nearest deadline, 100 ms)` in its timer half and one `PORT_POLL_SLICE` in its port half. Its callers are the `-eval` **bare** `receive`, where that sleep is what lets a runnable child deliver (`../eval/mod.rs`), the busy-port wait's pump (`../port/busy_wait.rs`, `BUSY_PORT_PUMP_SLICES`) and the nested cross-module pump's port half (`../context/pump.rs`, `RUN_EXPORT_PUMP_SLICES`). `pump_scheduler_now(max_slices)` is the same pass under `TimerWait::ImminentWithin(Duration::ZERO)` — the **non-blocking** pump the `-eval` `receive … after T` loop re-enters every port-poll slice, so an `after T` window ends on its own deadline (`ImminentWithin` also zeroes the port half whenever no port owes a reply) — [`../eval/CONTEXT.md`](../eval/CONTEXT.md).
* **the boot-drive step**: `pump_scheduler_boot(max_slices)` is `pump_scheduler` under the **imminent-only** policy (`TimerWait::ImminentWithin(TIMER_PUMP_SLICE = 100 ms)`, `scheduler.rs:74`; `timer_wait`'s arm, `scheduler.rs:1524`): sleep exactly the remaining time when the earliest deadline is **within** the window, return **without sleeping** otherwise; due timers are unaffected (`fire_due_timers` runs first) and a boot process parked on a short `receive … after T` is still slept to and resumed — [`../boot/CONTEXT.md`](../boot/CONTEXT.md). `BEAM_RT_BOOT_TRACE` logs every decision (`timer wait: policy=… remaining=… wait=…`). Its sibling `wait_for_timer(until, max_slices) -> Result<bool>` is the `-eval` `receive … after T` wait (`../eval/mod.rs`): sleep to `min(earliest pending deadline, until)`, then one bounded pass under `TimerWait::ImminentWithin(until - now)`, so a pass may only sleep on a deadline due before `until` and the call never outlives the caller's deadline; it answers whether anything ran or was delivered.
* **the `-s`/`-run` action**: `run_named(module, function, arity, args) -> Result<Eterm>` resolves the module through the code path (the system library `ebin`s included) and runs it as a freshly spawned, unregistered action process under the `RootAction::Module` frame; a **found-but-refused** image is the bare `error:undef` here exactly as at a call site (`error::call_load_failure`, the classifier `../context/calls.rs` uses), never the loader's `module name in object code is …` diagnostic.
* **spawning/scheduling**: `spawn_process(module, function, args)`, `spawn_fun_process(fun, args)` (`spawn/1`), `resolve_export_entry(module, function, arity) -> Result<ProcessEntry>` (a `spawn*` `M:F/A` entry: code-path search, load and export check, classified like a call and resolved **eagerly**, so a failed load raises at the spawn where the oracle spawns and the child dies — `M1_GAPS.md` *The `spawn(M,F,A)` reason surfacing*), `enqueue_process(pid)` (idempotent), `process_result(pid)`, `process_exit(pid)`, `run_queue_len()`.
* **refs/introspection**: `refs_mut() -> &mut RefAllocator` (**THE** ref id space — `make_ref` + monitors + timers), `system_info(key)`, `system_info_value(key)` (heap-free source of truth), `eval(expr)` (A.6 `-eval`), `format_term(term, module)`.
* **timers/dist**: `timers_mut() -> &mut Timers`, `dist_node()`, `node_name()`, and the connector accessors (`dist_client()`, `dist_connected_nodes()`, `dist_connect(peer)`, `dist_send_reg_send`, `dist_send_message_pid`, `dist_send_alias`); `dist_connect` is **idempotent** — a peer already established on **either** half returns `Ok(())` and dials nothing (a second `'N'` handshake is a simultaneous-connection collision the peer kills one half of), which is why `net_adm:ping/1` against a peer that dialled *us* answers `pong`; each of the three outbound send entries **dials an unconnected peer once** (`dist_ensure_link`/`dist_dial_name`/`dist_peer_is_local`) before the shared routing lookup, so a send — not a prior `net_adm:ping/1` — opens the link, and a runtime with no client or an already-linked/failed peer behaves as before (an unreachable peer still answers `no_link_error`) — [`../dist/CONTEXT.md`](../dist/CONTEXT.md); the scheduler half (`fire_due_timers`, `note_fragment_wake`, the five dist steps) is in `scheduler.rs`.
* **node monitors (A.5)**: the `node_monitors: FastHashMap<ProcessId, Vec<NodeMonitorLatch>>` store — `erlang:monitor_node/2`'s subscriptions (the C's `ERTS_MON_TYPE_NODE` chain, **not** the `monitor_nodes` flag store), each latch the node's atom term plus its `saw_connected` state — with `monitor_node_add(pid, node, saw_connected)` (the C's idempotent set: no duplicate, no refcount) / `monitor_node_remove(pid, node)`, the pure diff `node_monitor_transitions(latches, established, name_of) -> Vec<(Eterm, up)>` (`up` only on not-seen→present, `down` only on seen→absent, nothing in either steady state, an unnameable node inert) and the pass step `service_node_monitors(&mut ProcessTable) -> Result<usize>`, which delivers each transition as the plain 2-tuple `{nodeup|nodedown, Node}` exactly like `deliver_gc_completions` (arena-built message, `RuntimeContext::deliver_in_table`, emulator `from`). It is the **one** pid-keyed runtime map iterated on purpose (over subscribers only): `Ok(0)` with no allocation when nobody subscribed, and on a `nonode@nohost` runtime every latch stays silent. The BIF body is `../native/net.rs::monitor_node_2`; `erlang:monitor_node/3` stays a typed gap.
* **peer loss (A.5)**: `lost_dist_peers: LostPeers` is **one** shared `Rc<RefCell<Vec<String>>>` (`../dist/links.rs`), created in `new` before either half and installed with `DistNode::use_lost_peers`/`DistClient::use_lost_peers`, so either half can be the observer. Both halves record the `node@host` of a peer whose link they retired **as dead** — and **only** for a link that **had** established (`retire_at`/`DistClientInner::retire` ask `was_established`, the pump-set latch, **not** `is_established`: the pump that finds the death is the call that moves the driver to `Closed`/`Failed`, so the live state is `false` for every dying link; a graceful `DistNode` drop, `DistClient::close` or `connect_addr`'s replace records nothing), because a link that never handshook was never a node down. The retirement sites only *record*: they run inside a pump, which holds no process table. `service_lost_dist_peers(&mut ProcessTable) -> Result<usize>` is the drain — `Ok(0)` after one borrow and one `is_empty` when nothing was lost (every non-distributed run); otherwise each name is skipped when `dist_link_names` (`DistClient::link_names` over both halves, **any** handshake state) still lists it, so a **re-connect** is a non-event and fires nothing; declined when the shared `AtomTable::lookup` cannot resolve it (never a fabricated atom); else `noconnection` is interned and `ProcessTable::node_down(node, noconnection)` runs. Complementary to `service_node_monitors`, which is unchanged and does not double-fire: that step delivers `{nodedown, Node}` to `erlang:monitor_node/2` subscribers, this one discharges the **process** relationships (a remote monitor's `{'DOWN', Ref, process, PeerPid, noconnection}`, a trapping remote link's `{'EXIT', PeerPid, noconnection}`, a non-trapping one's termination).
  `Timers` probes with the crate's own `FastHashMap` and reclaims a non-head cancellation with a **watermark heap rebuild** (`Timers::compact` once `heap.len() > 2 * pending.len() + COMPACT_SLACK`), so a finite `receive … after T` cancelled by a real message leaves no permanent tombstone per iteration.
* **the native file service**: the `file_services` field (`FileServices`: the `file_server_2` service process + its live io-devices) and `service_file_requests(&mut ProcessTable) -> Result<usize>`, the scheduler-pass step that services them — [`../native/CONTEXT.md`](../native/CONTEXT.md)'s `file_server.rs` subsection.
* **the runtime's own processes**: `Runtime::new` starts exactly **three**, none user-spawned — the root process (`init`), the **`erl_prim_loader`** stand-in (born `Runnable`, never enqueued, registered on **every** route, so `erlang:whereis(erl_prim_loader)` answers a live pid) and the native `file_server_2` service; the loader's *functions* stay on the native floor (`../native/loader.rs`).

### `runner/` — the `beam_process::ProcessRunner`
`RuntimeRunner<'a>{runtime, state}` implements `ProcessRunner::run(pid, table, budget) -> Result<RunOutcome>`: `Returned(v)` → record `v` + `Exit(normal)`; `Wait{func,pc}` → park + `Wait`; `Err(e)` → the reason term + the original `BeamError` recorded in `RunnerState`, then `Exit(<reason term>)`. `RunnerState` holds an engine per pid plus the pid-keyed `results`/`exits`/`errors` maps — all four the crate's own `FastHashMap`, each probed only by pid and never iterated for an observable order.
Everything else about this instrument — the park/resume root hand-off (`publish_parked_roots`/`resume_from_process_roots`, `RootSet::ALL_LIVE`, the FR-prefix window, the parked pending-exception reason as an extra root), `park_machine`, `BudgetProbe`/`BudgetContext`, receive-deadline arming, the exit-reason mapping and the per-file split (`entry.rs`/`run.rs`/`budget.rs`/`reason.rs`/`tier.rs`/`perf.rs`/`tests.rs`, with `mod.rs` re-exporting the three cross-crate names) — is its own node's: [`../runner/CONTEXT.md`](../runner/CONTEXT.md); the measured per-workload cost of that path is [`../runner/MEASURED.md`](../runner/MEASURED.md).

### `gc.rs` — the runtime-level GC state
`GcStatsSnapshot` (`gc_stats`) reports collections/failures/halted pids/valve trips **and the `reclaimed` word counter**, advanced by `Runtime::note_gc_reclaimed(words)` from `serve_gc_request`'s Ok arm, the three collection sites in `../context/gc.rs` (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`) and the boundary door (`../context/gc/reds_door.rs`) — backing `erlang:statistics(garbage_collection)`'s `{collections, reclaimed, 0}` (detail: [`../context/CONTEXT.md`](../context/CONTEXT.md), [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md) *Memory and statistics*). `GcState` holds the **pin** set (a pid whose heap must not move), the **halt** set (a pid whose collection failed, or whose root-set sizes changed) and the global **valve** (`disabled`, plus the first reason and a trip counter).
`try_stabilize_escaped(term) -> Result<Eterm>` is the **one** escape-store stabilization: it copies a runtime-level store's term onto the pointer-stable arena when a heap may move, propagates a **genuine** copy failure (`BeamError::SystemLimit` — the term does not fit the arena) and trips the valve (`disable_gc`) **only** for the documented off-heap-payload capability gap (an unresolvable **MSO** container, or a malformed graph — a refc binary whose payload no source table owns is **flattened** on-heap instead, `stabilize_term`), returning the original term then. Every runtime-level store goes through it — the pending spawns (`note_pending_spawn`, `runtime.rs`), the native message/function stores (`native.rs`, `native/erts_internal.rs`), the `RuntimeHooks` store (`context/runtime_hooks.rs`) and the runner's exit-reason call site (`runner/run.rs`). `try_stabilize_escaped_with(term, &SourcePayloads)` is the **machine-aware** sibling, differing only in building the copy's *source* off-heap table from the caller's `SourcePayloads` (`Runtime::source_payloads`/`Runtime::stabilize_term_with`) rather than the empty one, so the one caller holding the machine that built the term (the runner's exit-reason arm) **shares** an engine-built off-heap binary or MSO container — one refcount, no materialized copy — where the empty table must flatten the refc binary; `try_stabilize_escaped` is exactly `try_stabilize_escaped_with(term, &SourcePayloads::default())` (handle-pushing, node-list and destination-table rules: [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *the transport copy*). `halt_process_gc`/`disable_gc`/`gc_enabled`/`gc_process_enabled(pid)` are the mutators/queries; a process whose heap may not move is marked **relocation-exempt per slice** on the `Process` itself (the runner's post-slice FR valve), never through a runtime-level pin. Because the copy keeps a NIF resource's **reference identity**, `Runtime::gather_off_heap_roots` counts the pending timer **deliveries** (`Timers::gather_off_heap_roots`) and the stable engine **arguments and entry fun** plus an un-published parked machine's own root set (`RunnerState::gather_off_heap_roots`'s two sub-families) as root families beside the escaped closures' environments, the `seq_trace` tokens, `pending_spawns` and every live process's dictionary, mailbox, registers, saved arguments and signals — a family left out makes a live resource look unreachable, and only the families that survive a pass's two table moves are live at the park arm — `M1_GAPS_A3_NIF.md` *NIF (A.3)*.
The collection gate is the **two-phase unscanned-root valve** (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs`): phase 1 classifies every root word and always runs; phase 2 descends the process's root-reachable scanned graph and runs only when the per-pid descent bit `GcState::foreign` is open, and the reused descent scratch is `GcState::walk` (`WalkScratch`, `Runtime::walk_scratch()`). Phase 1 declines only for a foreign container that forwards a **scanned** word, so a leaf (a `make_ref/0` reference, a float, a pid, a pooled-BIF tuple of immediates) latches nothing; `Runtime::close_foreign_reachable` retires the latch on a `ValveVerdict::foreign_free` descent from the **three** doors that hand the walk the machine's whole `RootSet` (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`), while the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` signal sites may only open it. The **same valve is installed on the process table** as the `beam_process::CollectionGate` host seam — `context/gc_walk.rs::RuntimeCollectionGate`, built by `Runtime::new` over the **one** shared `ForeignLatch` cell so a signal site decides in `O(1)` while the pid's bit is clear, owning its own `WalkScratch`, travelling with the table into every pass, because the `beam_process` signal sites hold only `&mut ProcessTable` — [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *The signal sites' collection decision is the host's `CollectionGate`* and *A collection is declined only by a foreign container that forwards a scanned word*.

### `ets_owner.rs` — the `ProcessExitObserver` host and the two drains
`OwnerIndex` (additive, shared with `Runtime`) records, in death order, the dead pids waiting for a drain and the append-only `(PortId, MonitorRef)` `PortWatch` pairs.
`EtsExitObserver` is the `beam_process::ProcessExitObserver`: it pushes the dead pid and its drained `PortWatch` pairs and returns (no BIF borrows the index).
`Runtime::drain_ets_owner_exits` discharges the ETS obligations (delete a dead owner's indexed tables, honour an installed heir), and `Runtime::drain_port_monitor_exits` sweeps the dangling incoming port monitors; both take the borrow with `try_borrow_mut` and **defer** to the next drain on a live borrow — never a panic, never a dropped obligation.
**A failed heir-gift deep copy is never swallowed.** `Runtime::adopt_created_table` re-owns a fresh table's creation-time gift through the fallible `Table::install_heir`; `Runtime::own_heir_gift` returns that error (a `try_borrow_mut` miss, an unknown handle, a missing heir and an arity-2 heir are all `Ok(())`) and the one policy `Runtime::report_heir_gift_failure` handles it: logged immediately (`beam_error!`, the policy `beam_process`'s exit-observer uses for a panicking observer) **and** recorded in the owner index, so the next `drain_ets_owner_exits` returns it as the typed error it is (`badarg` for a term outside `beam_ets`'s copyable subset, `out_of_memory` for an exhausted store). The successful `ets:new/2` stays successful: the table exists and its gift term is table-owned (the creation-time gift was deep-copied by `Table::new`'s build path before the re-ownership is attempted), and `install_heir` leaves the current heir untouched on failure.

## Constraints
* **`unsafe`-free** (`#![deny(unsafe_code)]`) and return-based errors ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible API returns `beam_common::Result`.
* **The scheduler moves the table (and the runner state) out of the `Runtime`** — `run_pass`'s `take_processes`/`put_processes`, restored whatever the outcome, because a pass needs `&mut Runtime` **and** `&mut ProcessTable` at once while the table is a *field*; the runner likewise takes the pid's `Machine` out of its `HashMap`. Rationale: [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *the scheduler moves the table*.
* **A process's exit reason is not its return value** — [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *a process's exit reason*.
* **Heap lifetime**: `Runtime` owns the process heap so a returned `Eterm` stays valid after `run_*` returns; `system_info`/`format_term` use the separate `info_heap`, rewound per call by `Runtime::reset_info_scratch`, which **refuses** once `Runtime::info_heap_tainted` is latched, and `erlang:system_info/1` leaves the region through `RuntimeContext::relocate_off_scratch` (the copy-out: the running process's scanned young heap, else the never-reset table-less `-eval` store) — [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *Heap lifetime*; pinned by `tests/system_info_retained.rs`.
* **A run-queue pid with no engine entry point is a recorded typed diagnostic, never an aborted pass.** `RuntimeRunner::run` (`../runner/run.rs`) takes the pid's `ProcessEngine` out of `RunnerState::engines`; when a pid was enqueued that this runtime never registered an engine for (`RunnerState::contains`, `../runner/entry.rs`), the runner records one `UnrunnableProcess` (pid, `ProcessState`, `in_run_queue`, priority, registered name when the table holds one) in `RunnerState::unrunnable`, **restores the process to `Runnable`** (`slice_begin` had set it `Running`, which also changes `Process::has_unpublished_roots`) and returns `RunOutcome::Wait`, so the pid leaves the run queue and no slice is fabricated. The record is first-write-wins per pid and surfaces as a `[rt-trace]` line through `crate::debug_trace`. The **enqueue** side refuses the same pid: `Runtime::absorb_fragment_wakes` skips one the pass's `RunnerState` does not know, and `Runtime::enqueue_process` (`../runtime.rs`) rejects one with the typed `error::unknown_process_entry`.
  The other half is why the runtime's own services are safe: a runtime-owned, never-enqueued service is created with `ProcessTable::spawn(policy)` (born `Runnable`, `insert`ed, **not** enqueued) + `ProcessTable::register(name, pid)` — `init`/`Runtime::self_pid`, the `erl_prim_loader` stand-in, the `file_server_2` service, the registered `net_kernel` service and the `-eval`/`-s`/`-run` action child. `whereis`/`monitor(process,Name)` resolve it and a send lands in its mailbox, but it never runs: only `Waiting`/`Suspended` are woken by a delivery (`Process::wake`, `../../beam_process/src/process.rs:462`), so it never reaches a run queue's wake list, and a heap-fragment delivery notes a wake **only** when that same `wake()` answered `true` (`../dist/CONTEXT.md`). `scheduler_pass` calls `Runtime::service_file_requests` as an **additive step right after the run queue drains** (the service's and its io-devices' mailboxes, replying via `ProcessTable::deliver_simple` + `scheduler.resume_woken`), and each delivered reply counts into `delivered`, so a serviced-only pass never looks like "nothing happened".
* **Files ~1000 lines**, split by responsibility; every public item documented (`#![warn(missing_docs)]`).

## Every site that can relocate a process heap (the soundness inventory)
Heap relocation is **not** confined to the runner's slice: any path that reaches a rooted collection moves a
process's young objects, so each must either publish that process's root set or decline. All of them share
ONE root set — `Process::regs` + each mailbox message's `payload`/`from`/`token` + dict + saved args +
pending-signal queue, gathered/scattered by `run_rooted_collection`
(`../../beam_process/src/process.rs:1695-1762`):
* the three heap-admission doors — `../context/gc.rs::ensure_heap:1034`, `ensure_heap_full:1252`,
  `alloc_words_rooted:1568` (the *running* process; publish → collect → scatter);
* the reduction/yield-boundary door — `../context/gc/reds_door.rs::collect_at_reds_boundary:176`
  (refuses `is_relocation_exempt` at `:216`, then the interval/occupancy gates at `:191`/`:234`);
* `Runtime::serve_gc_request` (`gc.rs:507`), called from the runner's Yield arm (`../runner/run.rs:1241`)
  and Wait arm (`:1392`);
* **message delivery**, i.e. the *receiver's* heap — `ProcessTable::deliver`
  (`../../beam_process/src/ptab.rs:858`, gate consulted at `:879-896`) → `Process::deliver`
  (`../../beam_process/src/process.rs:1150`, `ensure_capacity:1621` on the retry). Reachable from
  `RuntimeContext::deliver_in_table` (`../context/send.rs:528`), hence from every pass-boundary step:
  `deliver_gc_completions`, `service_file_requests`, `drain_ets_owner_exits`, `deliver_port_messages`,
  `fire_due_timers`, `dispatch_dist_inbound`/`dispatch_dist_client_inbound`;
* **the exit cascade** — `ProcessTable::enqueue_exit_signal` (`ptab.rs:2645`) → `copy_reason_onto`
  (`ptab.rs:331`) → `grow_receiver_for_signal` (`ptab.rs:192`), reached from `terminate`/`terminate_into`;
  deliberately **not** gated by `gc_process_enabled`, only by `has_unpublished_roots()`/the gate.
All of them refuse when `Process::has_unpublished_roots()`
(`../../beam_process/src/process.rs:1370` = `relocation_exempt || state == Running`); the delivery seam
adds the receive-side valve `RuntimeContext::delivery_collection_is_unsound` (`../context/send.rs:476`).
The `foreign_reachable` latch is only ever a **descent** short-circuit — with it clear each valve still
classifies every root word — and `close_foreign_reachable` runs only from the three whole-`RootSet` doors.
**Recorded residual:** `serve_gc_request`'s `Err(_) => halt_process_gc` (`gc.rs:573-576`) discards the
`BeamError` itself, so a genuine collection failure becomes a silent halt (only the `errors` counter and
the `halted` set record it).

## Port-aware scheduling (A.4) — design decision & handoff
The pass runs the **port-less** `Scheduler::run_ready` (its port half, `Runtime::deliver_port_messages` + the one persistent poller, owns the polling), and discharges the port-aware slice's obligations **at the pass boundary**, where the port registry is free:
* **covered** — a process that died in the slices just run had its recorded outgoing `(PortId, MonitorRef)` `PortWatch` pairs swept by `Runtime::drain_port_monitor_exits` (`ets_owner.rs`) — the same end state a port-aware termination reaches for its *incoming* entries.
* **covered** — `Runtime::drain_driver_monitor_exits(&mut self, &ProcessTable)` runs immediately before `deliver_port_messages`, sweeping every live C-driver port's monitor tree (`PortRegistry::note_driver_monitor_exits`) and marking each watched pid the table no longer holds, so the same round's port-task probe fires the entry's `process_exit`; it is a scan of the live `ProcessTable`, not a second `set_process_exit_observer` (the single observer slot stays `EtsExitObserver`), and it defers with `Ok(0)` on a live registry borrow.
* **not covered** — `ProcessTable::port_closed(&mut self, ports, port, reason)` (a *closing* port notifying its monitors/links). It can only run **at the close site, while the id is still in the table**: `beam_io::PortRegistry::close` releases the id (`ids.release`), and `beam_process::PortTable::close` is `BadArg` afterwards, so a post-hoc drive from a pass boundary is impossible. That site is `crate::port`'s close path (`RuntimePorts`, reached from `beam_bifs`'s `PortHook::close_port`), outside this node.
`Runtime::with_port_table(&self, &mut ProcessTable, f)` is the intended **short-borrow seam** for such a caller (it `Rc::clone`s the port field, so the returned `RefMut` borrows the clone and both tables can be borrowed at once; a nested borrow stays the typed `unsupported`, never a panic). The `beam_process::PortTable` seam itself is **sufficient as-is** — `port_closed`/`monitor_port*`/`terminate_with_ports` already take the two tables as disjoint parameters — per-port detail in [`../port/CONTEXT.md`](../port/CONTEXT.md).
**Two routes must not be retried; both are unsound by construction:** (1) **holding the `Rc<RefCell<PortRegistry>>` borrow across `run_ready_with_ports`** — `open_port`/`port_command`/`port_close` executed *inside* a slice (`RuntimePorts::registry_mut`) `try_borrow_mut` the same cell, so a held borrow degrades every in-slice port BIF to the typed `unsupported` gap (the exercised path is the `run <file.beam>` action and the `event_driver`/`port_recv` fixtures, which open and write ports from inside a scheduled slice); (2) **`mem::replace`-ing the `PortTable` out and leaving a placeholder** — `PortTable` has no `Clone` and `beam_io::PortRegistry::open`/`register` `insert` into the table they were given, so a nested `open_port` during a slice would silently **overwrite** a live port's `Port`/`PortMeta` (an empty placeholder does not free number 0).
**Crate change that would make the literal routing (or the port-close drive) sound:** the port table must be reachable as a **handle both the scheduler window and the nested BIF paths share** — e.g. `beam_io::PortRegistry` exposing `ids` as its own `Rc<RefCell<PortTable>>` (a slice borrows *that* cell and an in-slice BIF borrows it too, failing only on a genuine re-entry), and/or `beam_io`'s close path driving `ProcessTable::port_closed` at its close site with the process table in hand, **before** `ids.release(id)`.

### Process termination — where a scheduled process is reclaimed, and what is missing for a dying process's owned ports
**A normally-returning scheduled process is reclaimed by `beam_process`'s schedule-out, not by any `beam_rt` code.** `RuntimeRunner::run` (`../runner/run.rs`, the `Ok(EngineRunOutcome::Returned(value))` arm) records the `x(0)` value and returns `beam_process::RunOutcome::Exit(normal(self.runtime))`; `Scheduler::run_slice_inner` (`../../beam_process/src/scheduler.rs:394`) dispatches to `slice_end`/`slice_end_with_ports`, whose `Exit` arm calls `ProcessTable::terminate`/`terminate_with_ports` — the reclaim that makes `processes().get(pid)` answer `None` afterwards (`../../tests/scheduler.rs:107,207`). That runs **only** for a pid the scheduler dequeued, so a **never-enqueued** `Runnable` process (the `-eval`/`-s`/`-run` action child) is ended by its **own** teardown: `../runtime.rs::as_action_process` first copies an `Ok` result onto the pointer-stable store (`Runtime::stabilize_term_with` over `Runtime::source_payloads`, exactly as the runner does for a scheduled `x(0)`, so the term outlives the heap that built it) and then calls `ProcessTable::terminate` with the `normal` reason — the `None`-ports branch, since `beam_rt`'s pass runs the **port-less** `Scheduler::run_ready`. It must be `terminate`, not a silent `ProcessTable::remove` (which would skip the death itself: the exit observer/ETS-owner drain, the name/link/monitor teardown), and the result copy is what keeps the returned `Eterm` from dangling (`../../tests/action_result.rs`). `ProcessTable::spawn` installs a **naked** process (no serial link, no monitor, no group leader); `Runtime::spawn_process_with_policy` adds only a group-leader entry and `as_action_process` calls `spawn` + `set_group_leader`, so nothing binds the action child to `init` (the runtime's root process does **not** trap exits: nothing calls `set_trap_exit(true)` on `self_pid`).
**No path in `beam_rt` closes a dying process's *owned* ports.** `ProcessTable::terminate_into` drains the dying process's links, monitors and port *monitors* and resolves their peers, but never closes a port the process **owns** (the oracle closes them with reason `normal`). `ProcessTable::port_closed(&mut ports, id, reason)` would notify a closing port's monitors/links, and it is called today **only from `beam_process` tests** — never from production `beam_rt`. Closing exactly one pid's ports needs an enumeration of them: the authoritative owner table is `beam_process::PortTable` (`beam_io::PortRegistry::port_table_mut()` / `RuntimePorts::port_table_mut()`), which stores `owners: HashMap<PortId::number, ProcessId>` with a forward `owner(id) -> Option<ProcessId>` but **no reverse `owner → [PortId]` index and no allocated-id iterator**; a caller needs a new reverse index (or id iterator) and then, per owned port, the runtime close path (`RuntimePorts::close` / `PortHook::close_port`, `../port.rs`) plus `ProcessTable::port_closed`.

## The pass's exact step order, and when outbound distribution bytes are written
`scheduler_pass` (`scheduler.rs:816`) is one loop body.
Before the first round it boots the runtime once (`boot_if_needed`, :822), moves the process table, the scheduler and the runner state out so the runner can hold `&mut Runtime` while the scheduler holds `&mut ProcessTable` (:823-825), absorbs the caller's pre-pass wake list when `resume_first` is set (`Scheduler::resume_woken`, :835-837) and absorbs the heap-fragment wake list (`absorb_fragment_wakes`, :840).
Each round derives its own budget, `max_slices - ran` (:847); a budget already at `Some(0)` ends the pass there, at the top (:848).
The order **per round** is:
1. the **run queue** — `scheduler.run_ready` (:853) consumes the round's budget.
2. the round's accounting: `note_context_switches` (:878) credits the executed slices to `statistics(context_switches)`, and the round's `progressed` flag plus the port step's timeout derive from its own slice count (:904-911), so a round that ran slices polls the ports without blocking.
3. `prune_gc_requests` (:920) drops a `garbage_collect` request whose process died in the slices just run.
4. `deliver_gc_completions` (:929) — the `{async, ReqId}` half of `erlang:garbage_collect/2`.
5. `service_file_requests` (:946) — the native-service half (`file_server_2` + its io-devices, A.9).
6. `service_net_kernel` (:961, body `native/net_kernel.rs:206`) — the `net_kernel` service's mailbox.
7. `drain_port_monitor_exits` (:976) — the dead watchers' `(port, reference)` pairs; delivers nothing.
8. `drain_ets_owner_exits` (:983) — the ETS owner-death obligation.
9. `absorb_pending_spawns` (:993) — a child an `erlang:spawn*` created during the slices just run.
10. `absorb_fragment_wakes` (:999) — the fragment counterpart of the table's own wake list; yields the round's `woke` count.
11. `drain_driver_monitor_exits` (:1008) — marks every `driver_monitor_process` target the table no longer holds, so the round's port tasks below fire the driver's `process_exit`; delivers nothing.
12. `deliver_port_messages` (:1016) — the **port half**: what a live port produced, delivered into the owning process's mailbox.
13. `drain_nif_thread_sends` (:1149) — the **foreign-thread NIF half** (A.3), right after the port step and before `pump_dist`: a thread a NIF created (`enif_thread_create`) queues a message through `enif_send` that must land in the target's mailbox and resume its receiver, so the runtime asks it for work once per round; with no factory installed it is one `Option` test.
14. `pump_dist` (:1160) — the accepting node's handshake/accept step (A.5); adds to the tally only, and falls through.
15. `bind_dist_peers` (:1171) — binds each freshly established accepted link to its peer's node atom term; falls through.
16. `service_node_monitors` (:1183) — the `erlang:monitor_node/2` `{nodeup, Node}`/`{nodedown, Node}` transitions observed after the peer binding.
17. `dispatch_dist_inbound` (:1196) — routes what the accepted links decoded.
18. `pump_dist_client` (:1210) — the connector's outbound step, which also flushes the controls the process layer's `DistSignalRouter` queued; adds to the tally only, and falls through.
19. `dispatch_dist_client_inbound` (:1219) — routes what the outbound links decoded.
20. `service_lost_dist_peers` (:1239) — the **peer-loss half** (A.5): drains the shared `LostPeers` recorder (a dead **established** link, either half) into `ProcessTable::node_down` — a remote monitor's `{'DOWN',Ref,process,PeerPid,noconnection}`, a remote link's `{'EXIT',PeerPid,noconnection}`/termination; a name `DistLinks::link_names` still lists (any handshake state — a re-connect) fires nothing, an unresolvable name is a decline, and the step sits after both inbound drains and before the timer half. `Ok(0)` with no allocation when nothing was lost.
21. `fire_due_timers` (:1251) — the **timer half**: every `erlang:send_after/3` message whose deadline passed, plus every fired finite `receive … after T` deadline (`absorb_timer_wakes`).
22. a round that absorbed a fragment wake (`woke > 0`, :1264) goes round again, else `timer_wait` (:1272) decides the pass's sleep: a policy allowing one more wait sleeps to the earliest pending deadline and `continue`s, and `None` (:1281) ends the pass.
Steps 4-6, 8, 12, 13 and 16-21 count into `delivered` and `continue` back to the run queue; **except** `pump_dist` (:1160), `pump_dist_client` (:1210) and the two monitor drains (:1079, :1111), which only add to the tally (if anything) and fall through.
The pass's own outcome is restored unconditionally: the runner state, the scheduler and the process table go back into the runtime whatever the loop's `Result` says (:1162-1166).
**Outbound bytes are written at three moments.** (a) `Runtime::dist_send_reg_send`/`dist_send_message_pid`/`dist_send_alias` (`../runtime.rs:4170`/`4198`/`4230`) and anything else reaching `DistLinks::route_control`/`route_message`/`route_alias` (`../dist/links.rs:318`/`345`/`391`) write **synchronously inside the call** (`DistConnection::send_control` → `flush_output`, `../dist/connection.rs:229`). (b) A signal the **process layer** routes (`DistSignalRouter::route`, `../dist_client/router.rs:49`) only materialises onto the client's scratch heap and pushes onto `DistClientInner::pending` (`../dist_client/client.rs:862`); `flush_pending` (`client.rs:739`) writes its bytes, and its **only** caller is `DistClient::pump` (`client.rs:358`) — reached at `pump_dist_client` (`scheduler.rs:1427`) and from `Runtime::dist_connect`'s handshake loop (`../runtime.rs:4040`). (c) `DistNode::pump` (`../dist/node.rs:299`) drives the **accepted** links' handshake/reads only and writes no queued control.
So a routed signal queued in a slice is normally written **later in the same pass**, but a round that `continue`s at any step above, or a pass that ends first, defers it to the **next** pass: no drain at the pass tail and none before a `break`.
The quiescence test sees a link **and** what the wire is still owed (`DistClient::has_links`, `client.rs:495`, reads `DistLinks::is_idle`; `DistClient::has_pending_outbound` reads the outbound queue plus either half's driver output), so a `pending` control keeps a pass alive until `pump_dist_client` flushes it — precisely when its node's link was **retired** between queueing and the flush, where the flush drops the item with a recorded `last_error` ([`../dist_client/CONTEXT.md`](../dist_client/CONTEXT.md)).

## Distribution (A.5) — inbound validation and the unrouted families
**Every inbound delivery is validated against its own link.** Both production inbound drives (the accepting node's `dispatch_dist_inbound` → `dist::DistNode::dispatch_inbound`, the connector's `dispatch_dist_client_inbound` → `dist_client::DistClient::dispatch_inbound`) drain each link through `beam_dist::ConnectionDriver::dispatch_inbound_checked`, so a control message is checked against **that** link's own `peer_name()`/`our_name()` identity (the per-link `LinkIdentity`) before it can reach a mailbox: `beam_dist`'s `Delivery::classify_validated` reproduces the C's per-opcode `invalid_message` shape checks (`dist.c`) plus the per-link anti-spoof check `dep != external_pid_dist_entry(from)`, the identity interned into the **same** `AtomTable` the message was decoded against so the node comparison is a raw term `==`. A validation failure is an `Err` — a **link-level** failure that never reaches `beam_dist::InboundSink`: the drive retires (kills) **just that link** and records the reason in `DistNode::last_link_error` (the C's `invalid_message` connection kill), never a pass failure; the check cannot live in `LocalDeliverySink`, built once per pass and shared by every link, which has no peer to compare a `From` against.
`Runtime::dispatch_inbound` (`../dist.rs`, the explicit single-driver seam) deliberately stays on the *classify-only* `ConnectionDriver::dispatch_inbound`: its caller supplies an arbitrary hand-built driver whose handshake names need not be this runtime's node identity, so a per-link check there would judge a message against a *foreign* identity — it is the semantic view, not a wire drive.

**`LocalDeliverySink` routes the message families plus the route-free receipt families; the rest is the honest `DeliveryOutcome::Unsupported`**, with the still-missing API named at its arm (`../dist.rs`'s `LocalDeliverySink::deliver`). `beam_process` exposes the **outbound** relationship entry points (`ProcessTable::link_term`/`unlink_term`/`monitor_term_with_options`/`demonitor`/`send_exit_term`, each routing a `DistSignal` through the installed `DistSignalRouter`) **and** the **route-free receipt** counterparts, which install/drop the local record and then follow the C's `break; /* Done */` (`dist.c:2258`) without echoing the opcode it received:

| Inbound family (C arm) | Receipt API used (or the still-missing API) |
|---|---|
| `Link` (`DOP_LINK`, `dist.c:2224-2275`) | **routed** — `record_remote_link(to: ProcessId, remote: RemotePid)` (record-only; the C never echoes one) |
| `Exit`/`Exit2`/`PayloadExit`/`PayloadExit2` (`dist.c:2760`/`:2824`) | **routed** — `apply_remote_exit_signal(to, from: RemotePid, reason, untrappable)` (`untrappable = true` for the `Exit2`/`PayloadExit2` family) |
| `UnlinkId`/`UnlinkIdAck` (OTP-26+ handshake, `dist.c:2284`/`:2315`) | **partially routed** — `unlink_from_remote(..)`/`unlink_ack_from_remote(..)`; an inbound `DOP_UNLINK_ID` with `id != 0` owes a `DOP_UNLINK_ID_ACK` this sink has **no reply channel** to emit, so the link record is dropped and the wire half is reported the typed `Unsupported` (`id == 0` owes no ack and is `Delivered`) |
| `Monitor`/`Demonitor` (`DOP_MONITOR_P`/`DOP_DEMONITOR_P`, `dist.c:2341`/`:2415`) | **routed** — `monitor_from_remote_ref(watched, watcher, reference: RemoteRef, kind)` records the incoming watcher and `demonitor_from_remote_ref(watched, reference: RemoteRef)` removes exactly that record, both keyed by the **whole** peer-minted wire reference (`RemoteWatcherRef::Remote(RemoteRef)`, all-immediate, so two peer-minted references never collapse) |
| `MonitorExit`/`PayloadMonitorExit` (`dist.c:2700-2714`) | **routed** for a DOWN whose reference *this* node minted (the wire image inverts to the recorded `MonitorRef`) — `remote_monitor_down(watcher, watched: RemotePid, reference, reason)`; a name-targeted DOWN or a foreign reference stays `Unsupported` |
| `GroupLeader` (`DOP_GROUP_LEADER`, `dist.c:2889`) | **routed** — `set_group_leader_from_remote(to, from: RemotePid)` |
| `SpawnRequest`/`SpawnReply` (`dist.c:2902-3093`) | **still a typed gap** — needs a `beam_process` spawn-responder/reservation API (a `DOP_SPAWN_REPLY` sender + the reservation bookkeeping); a `beam_rt` CLI process serves no spawn requests and holds no reservations |
| `Other(Dop::Unlink)` | **still a typed gap** — `DOP_UNLINK` is not a v6 opcode; the C's `invalid_message` arm kills the connection (`dist.c:2277-2282`), which the link driver owns, so the sink reports "recognised, not routed" |

Evidence for the validated path: `../../tests/dist_delivery.rs`'s "(6b) Every inbound delivery is validated against **its own link**" — a forged `DOP_REG_SEND` (`From` a non-pid) and a `DOP_LINK` whose `From` names a third node are each refused, reach no mailbox and retire their link with a recorded `last_link_error`, while a well-formed message on the same link still delivers.

### The node's public surface (both halves)
Both halves' own API is a sibling node's: `DistNode` (bind, `epmd` publish, the link pump, `NodeName::parse`, `resolve_cookie`) — [`../dist/CONTEXT.md`](../dist/CONTEXT.md) — and `DistClient`/`DistRouter` (dial + client handshake under `DIST_CONNECT_TIMEOUT`, `pump` as the one place a live `DOP_*` is encoded, the router installed on the **`ProcessTable`** because the table is moved out for every pass) — [`../dist_client/CONTEXT.md`](../dist_client/CONTEXT.md).
The scheduler pass drives the two inbound halves from `Runtime::dispatch_dist_inbound` / `Runtime::dispatch_dist_client_inbound`, **gated by `Runtime::inbound_delivery`** (default **ON**): the pass early-returns unless the runtime **is** a distribution node **and** a half has an established link, so a `nonode@nohost` run pays one bool test per pass and allocates nothing.
The **envelope rule**: the mailbox `from` is always an **immediate** (`envelope_from` — the sender peer's node atom when the wire carried a sender pid, otherwise the word the peer put on the wire, `''` for the plain `DOP_SEND*` forms); a non-immediate is refused, because `beam_message` gathers only each queued message's payload as a GC root. `LocalDeliverySink` (`&mut ProcessTable` + this node's identity) routes `Delivery::Send`/`RegSend`/`AliasSend` and the **plain** `Delivery::AltactSigSend` message sub-cases — the per-family delivery semantics (a woken receiver, an unregistered name, an inactive reference, a consumed `reply_demonitor` alias): [`../dist/CONTEXT.md`](../dist/CONTEXT.md).
There is **no** `{setup,…}`/`{nodeup,…}` control exchange in OTP distribution: after the final `$a` handshake ACK the link carries `DOP_*` immediately, and node-up is local bookkeeping (`net_kernel:mark_nodeup`).

## Known Issues
* **`absorb_fragment_wakes` enqueues a pid only when it is a live `Runnable` process the pass's `RunnerState` can actually run.** Its gates are "still in the table", "`ProcessState::Runnable`", "not already in a run queue" (`scheduler.rs`) **and `RunnerState::contains`** — the last one keeps a runtime-owned never-enqueued service off the queue, since such a service is *born* `Runnable` and never runs, so `Runnable` alone is not a "should be scheduled" test. A refused pid gets the same typed `UnrunnableProcess` diagnostic the runner records (Constraints) instead of breaking the pass. The note itself substitutes for `ProcessTable`'s wake list, so it is recorded **only on a real wake** — by `../dist/inbound.rs::enqueue_fragmented` through `fragment_deliveries: Vec<(ProcessId, bool)>` and by the local send path's `if woken { … }` (`../context/send.rs::send_fragmented_message`); the descent gate `note_foreign_reachable` is unconditional for a fragment, because its payload sits where the receiver's collector does not scan. Pinned by `runtime::scheduler::tests::a_fragment_note_for_an_engine_less_pid_does_not_take_the_pass_down` and `…::a_fragment_note_alone_does_not_enqueue_a_parked_receiver`.
* **Quiescence blind spot: a retired native io-device is never drained again.** `scheduler_pass`'s native-service step drains exactly `FileServices::server()` + `file_services.devices.keys()` (`../native/file_server.rs`); `serve_file_message` with `retire == true` does `file_services.devices.remove(&service)`, so a still-live device pid holding a queued request vanishes from the drain list — the reply is never delivered, the parked sender never woken, and the next pass sees `ran == 0 && delivered == 0 && is_quiescent()`, so `run_scheduled` returns `beam_engine::blocked()` (exit 3) though a wake source still has work. `is_quiescent` is not itself wrong; the wrongly-holding premise is "no drainable service has work" while a *retired* device does. Reproduced with `epp:parse_file/2` from a scheduled `run` process. The `retire` flag itself is a false positive: `get_until::EngineContinuation::apply` sets `raised = true` on **any** `Err`, including the typed gaps `unsupported("… continuation suspended in a receive")` (`../native/file_server/get_until.rs:317-319`) and `unsupported("… returned neither {more,Cont} nor {done,Result,Buf}")`, not only on a genuine scan raise (observed: `error:function_clause` in `erl_scan:options/1` from `erl_scan:tokens/4`). Fix belongs in `../native/file_server.rs` (keep draining a retired pid, or reproduce the OTP close-handshake ordering), **not** in this node.
* **A *live port* alone keeps a pass non-quiescent.** `PortRegistry::has_nothing_to_poll` (`../port.rs:1470-1476`) is `meta.is_empty() && pending_events.is_empty() && pending_port_signals.is_empty() && !tty.is_armed() && !watch.has_pending_signal()`, so while any port's metadata exists it answers `false` and `is_quiescent` (`scheduler.rs:535`) answers `false` — a `run`-route process parked on a message only a port can produce therefore never takes the `blocked()` abort (`pump_run_to_completion`, `scheduler.rs:495`) and keeps stepping (sleeping `PORT_POLL_SLICE` on a round that ran nothing) until the port answers or `RUN_DEADLINE` expires. That is what a driver-side asynchronous reply (an `{inet_reply, …}`-style term drained at the `deliver_port_messages` boundary, `scheduler.rs:885`) relies on; the port round is drained **only** there on the scheduled route (the sole production caller of `../port.rs:3089`).
* **The port half's block is per *zero-slice round*, and only the boot drive's policy may shorten it.** `port_timeout` is `Duration::ZERO` for a round that ran a slice (`progressed`), else `PORT_POLL_SLICE` inside `PortRegistry::pump` (the blocking `epoll_wait(…, 25)`) — **except** under `TimerWait::ImminentWithin(_)` while neither port predicate holds: no port owes a reply (`Runtime::awaits_port_reply` = `PortRegistry::awaits_port_reply`, some port with `output > input`) and no driver holds one of its own asynchronous operations (`Runtime::ports_awaiting_async` = `PortRegistry::awaits_async_completion`, the socket read's half) — which is what keeps the boot's live-but-idle `inet_gethost` child off the poll budget (`../port/CONTEXT.md` *Measured*; [`../../PERF.md`](../../PERF.md) *The boot path's one live-but-idle port, and the poll budget*). A table that cannot be borrowed stays patient, so the gate only shortens a wait it can justify; the `run` route and the `-eval` **bare** receive keep the unconditional blocking poll because a child there may speak unprompted (the `-eval` `after T` arm runs under `ImminentWithin(0)` and waits port-side itself, in `poll_port_messages`). A boot-drive step (`pump_scheduler_boot` → `drive_scheduler`, `../boot/drive.rs:299-314`; the `{kernelProcess,…}` bursts, `:267`) still *polls* once as soon as *any* port is live — the gated timeout only makes it non-blocking — where the same step costs nothing before the first `open_port` (`has_nothing_to_poll()` ⇒ `deliver_port_messages` early-returns, `port.rs:3335-3343`). On the `-eval` route `halt/N` makes **zero** passes (`Runtime::eval` → `as_action_process`), so its pump sites are a `receive` (`../eval/mod.rs`), the busy-port wait (`../port/busy_wait.rs`) and a nested cross-module callee's port half (`../context/pump.rs`).
* **`delivered` does not count ordinary Erlang `send`.** Only port/timer/file-service/ETS/dist deliveries are counted (`scheduler.rs:719-849`), so a pass whose only progress is a plain message wake can look like `delivered == 0`.
* **The `run` route's pass wait is progress-aware; a pass that still has slices to run never sleeps.** `pump_run_to_completion` passes `TimerWait::AtMostWhenIdle(PORT_POLL_SLICE = 25 ms)` (`scheduler.rs:410`) and `timer_wait` returns `None` for it whenever the round that just ended **ran at least one slice** — `let progressed = round_slices > 0;` (`scheduler.rs:866`), fed by the round's own `run_ready` count — so the arm is `(!progressed).then(|| remaining.min(max))` (`scheduler.rs:1118`), still gated by `TimerWakes::can_wake(run_wake_pid)`. The guard keeps a budget-exhausted pass from sleeping: `run_ready_inner` breaks at the pass's slice budget (`RUN_STEP_SLICES`, `beam_process/src/scheduler.rs:514`) with the run queue still non-empty, so such a pass would otherwise sleep a full 25 ms immediately before its own budget check ends it. The anti-spin half is unchanged, pinned by `the_run_route_still_sleeps_to_a_parked_receive_timeout` (a `receive … after 20` still sleeps to its deadline — counter ≥ 1 — and resumes on the timed-out path), `the_run_route_never_sleeps_a_poll_slice_while_it_still_has_slices_to_run` (`pass_sleeps() == 0` while the target is runnable) and `the_idle_only_wait_policy_skips_the_wait_when_the_round_ran_slices` (the policy table), all in `scheduler/tests.rs`; the counter is the test-only per-thread `PASS_SLEEPS` (`pass_sleeps`/`reset_pass_sleeps`), so both halves are pinned structurally, never by wall clock.
  Measured on a `send_recv:plain/1` ping-pong (`receive … after 30000`), N = 20000: **0 `clock_nanosleep`** and, with the port half progress-aware, **6** blocking waits in total (≈ 137 ms, the boot's own idle rounds) instead of one 25 ms `epoll_wait` stall per pass, on both the default native-baseline tier and `BEAM_RT_TIER=interpreter`. The **port half** is progress-aware by the same flag: `scheduler_pass` computes `progressed` before the port half and hands `deliver_port_messages` `PORT_POLL_SLICE` only for a round that ran nothing, `Duration::ZERO` for a progressed round (it still polls — a driver may have bytes queued — it just does not block); without that, a live `inet_gethost` port keeps `has_nothing_to_poll()` false and every pass stalls the full 25 ms, which cost a 20 000-round ping-pong 1063 blocking waits / 26.9 s. Pinned by `scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing` (the test-only `BLOCKING_PORT_ROUNDS` counter) and end-to-end by `tests/run_route_sleep.rs`. The `tools/bench` figure for the `copy_bound` case `send_recv_plain` does not reflect this wait (owner `tools/bench`).
* **What still costs a decline: a *foreign container that forwards a word*.** The valve has **five** doors — `ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the park arm's `serve_gc_request` and `context/gc/reds_door.rs`'s reduction/yield-boundary door — each running the **per-word** classification phase plus, once the pid's foreign-reachability bit is set, an `O(live)` descent of its root-reachable scanned graph (the walk itself is `../context/gc_walk.rs`). A container that forwards **nothing scanned** (`context/gc.rs::forwards_scanned_word` over `beam_term::layout::for_each_child_slot`) declines nothing — so a `make_ref/0`-per-iteration loop keeps its latch closed and its heap flat, and a young term met by a `Process::grow_nursery` retried bump stays on the reclaimable heap **before** the valve/arena path; one that **does** forward a scanned word declines at every valve call while reachable, and dropping it lets the next full admission door retire the latch on a foreign-free descent. Rule, one-way clearing and pins: [`DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md) *A collection is declined only by a foreign container that forwards a scanned word*; here `context/gc/refs_plateau.rs` (a ref-minting loop against a reference-free control, at N and 2N) and `../../tests/foreign_root_loop.rs` (a loop holding a BIF container result — a *scanned* root, since the process-route copy-out re-homes it — with equal collection counts at N = 5 000 … 200 000). Per-iteration dispatch/profile figures: [`../../PERF.md`](../../PERF.md).

## The scheduled path's fixed costs (read before optimizing this crate's glue)
`run_scheduled` (the CLI `run` action) drives **one** target pid after `boot_if_needed`.
A bare `spawn(fun …)` child is created *inside* a slice (`src/native/process.rs::spawn_in_pass` → `note_pending_spawn` → `absorb_pending_spawns`), and every slice's end absorbs the wake list (`beam_process/src/scheduler.rs:435`), so a synchronous two-process ping-pong never empties the run queue and stays in **one** `run_ready` call (`run_ready_inner`, `scheduler.rs:513` `while !self.run_queue.is_empty()`) — it does **not** re-enter the pass boundary per iteration.
The pass granularity is `RUN_STEP_SLICES = 1000` slices (`src/runtime/scheduler.rs:99`), so per-pass costs are amortized ×1000 and **per-slice** costs dominate a long run (`DEFAULT_REDUCTIONS_PER_SLICE = CONTEXT_REDS = 4000`, `beam_process`).
- **Per pass:** `take_processes` (`src/runtime/scheduler.rs:1166`) builds a **fresh empty `ProcessTable`** (11 `HashMap::new()` + `Vec`s + `RefAllocator`, `ptab.rs:543`) and `mem::replace`s the runtime's table with it; `Scheduler::new()` replaces the old scheduler (`:597`); `put_processes` is a plain assignment.
- **Per pass: the pass wait is progress-aware, so a ready `run` never sleeps** — the sleep (`src/runtime/scheduler.rs:818`, `TimerWait::AtMostWhenIdle`, `:410`) is taken only for a round that ran **zero** slices with a deadline `TimerWakes::can_wake(run_wake_pid)` can wake (`src/runtime/timer_wakes.rs:123`), is `remaining.min(25 ms)`, and is permitted **once** per pass (`:153`). The measured figures, the anti-spin pins and the bench caveat are the `Known Issues` bullet above; the per-case cost of this path is [`../runner/MEASURED.md`](../runner/MEASURED.md) *The run route's sleep accounting*.
- **Per slice:** the machine/context churn (engine moved out of/into its map, a fresh `RuntimeContext` incl. `DispatchMemo`, `enter_module`'s `String`, the park hand-off's `copy_from_slice` of the x file plus the stack, skipped entirely for an exempt park) is [`../runner/CONTEXT.md`](../runner/CONTEXT.md) *Per-slice (not per-instruction) host cost*; the parked machine stays the authoritative root set in an exempt window (see [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md) *GC-relocation hazards*). This node's own per-slice addition is the receive-deadline bookkeeping: `schedule_receive_timeout`/`cancel_receive_timeout`/`take_timer_resume` add+remove a timer-heap entry and a `TimerWakes` entry (`src/runtime.rs:1175`/`:1194`/`:1204`) — a finite `receive … after T` pays this on **every** iteration, and the `Timers` heap reclaims a non-head cancellation by rebuilding past a watermark (`COMPACT_SLACK = 64`, `src/timers.rs:332`: a rebuild runs only once tombstones outnumber live entries), so a cancelled deadline is never a permanent tombstone.
  Every pid/Eterm-keyed collection the hot path touches is `crate::hasher`'s word-mixing map, not SipHash (`TimerWakes::{deliver,resume}`, `Runtime::{timer_resumes,group_leaders,async_dist,monitor_nodes}`, `RunnerState`'s `engines`/`results`/`exits`/`errors`, the mailbox map and the reachability latch); `slice_begin`/`slice_end` (`scheduler.rs:664`/`:737`) and the capacity-retaining wake sweep (`drain_woken_scratch_into`, `:813`) run per boundary.
- **Per slice, O(heap)/O(#mailbox) only when triggered:** the heap-admission seam (`src/context/gc.rs::ensure_heap`) short-circuits on occupancy (`:581`) but still pays a `current_module` **`String` clone** (`:555`) and two valve lookups on *every* admission point; the O(live-objects) descent (`any_root_is_unscanned`) is gated per-pid on the shared latch (`foreign_reachable`, `:597`), and the process table's `RuntimeCollectionGate::declines_relocation` (`src/context/gc_walk.rs`) is built over the **same** latch cell (`ForeignLatch`) so a clear bit answers `false` with no descent (O(1) per delivery) — both only on a collection/refusal.
- **Per round (cheap here):** `service_file_requests` allocates one `Vec::with_capacity(1+devices+retired)` (`src/native/file_server.rs:321`); `deliver_port_messages` early-returns `Ok(0)` on `has_nothing_to_poll()` with no live port (`src/port.rs:2566`, no poll sleep); each dist half is one `Option` match with no node.
- **Out of this node:** the per-slice machine re-entry/resume (`beam_engine`'s `resume_outcome*`) is a sibling node's cost.
