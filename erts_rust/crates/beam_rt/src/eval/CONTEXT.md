# `beam_rt::eval` — the `-eval` Erlang expression evaluator (`mod.rs` walker · `ast.rs` tree · `parse.rs` lexer/parser · `scratch.rs` statement window)

## Intent
The `-eval` evaluator (contract A.6): a lexer + Pratt parser (`parse.rs`) over an untyped AST (`ast.rs`) plus an `erl_eval`-style tree-walking evaluator (`mod.rs`) that `-eval Expr` runs.
It is driven by the CLI `-eval` action: `cli.rs::run`'s `Action::Eval(expr)` arm boots the runtime then calls `Runtime::eval` (`../runtime.rs`), which builds a `RuntimeContext` and calls `eval` here (`../runtime.rs::eval` → `crate::eval::eval`). `eval` is also re-exported at the crate root (`pub use crate::eval::eval;`) and in `prelude`.
Reused beyond the CLI: the evaluator's own closures can escape **into loaded modules** — `RuntimeContext::apply_fun` (`../context/mod.rs`, the `!External` fun arm) delegates a fun whose `uniq` is `EVAL_FUN_UNIQ` to `apply_eval_closure`, and the closure bodies live on `Runtime::eval_closures` (`Vec<Rc<FunBody>>`, so `lists:map(fun(X) -> X*X end, …)` applies one). `Runtime::eval` itself is used throughout the crate's tests as an expression/literal builder (e.g. `rt.eval("[call]")`).
The evaluator owns **no** term layout, arithmetic or printer: it dispatches down (`beam_term`/`beam_engine::terms`/`beam_bifs`) and inherits the lower crates' exact `erl` semantics.
**A BIF's container result outlives the call.** The evaluator runs with no scheduled process, so a registered BIF's result cannot be copied onto a process heap; `call_registered`'s copy-out therefore takes the table-less arm (`context/pool.rs::move_result_into_runtime_store`), copying a container result onto the runtime's pointer-stable `Runtime::eval_heap` (with any escaped payload adopted into `Runtime::eval_off_heap`) and only then rewinding the pooled BIF heap to that call's mark. So a term built by one sub-expression and read by a later one — `L = lists:seq(1,50), {hd(L), length(L)}` — is valid for the run's life, and repeated calls do not march the shared pool to its cap. The routes, the soundness argument, the measured trade and the `+hmax` capacity effect are in [`../context/CONTEXT.md`](../context/CONTEXT.md) and [`../context/IMPLEMENTATION.md`](../context/IMPLEMENTATION.md#the-table-less-arm-and-its-store); the oracle cross-check is [`../../tests/eval_pool_result.rs`](../../tests/eval_pool_result.rs).

## The escaped off-heap payload store and its prune point (`reclaim.rs`)
`Runtime::eval_off_heap` **owns** every off-heap `RefcBinary` payload a term on this route names, and `Runtime::eval_heap` is the pointer-stable region those terms stand on.
`src/eval/reclaim.rs` is that store's reclamation: `prune(runtime, extra)` walks the reachable payloads from an explicit root list and rewrites the store with the survivors.
The **one call point** is `Evaluator::run_top_level` (`mod.rs`), which evaluates the top-level statements of the expression itself and calls `Evaluator::prune_escaped` **between** them — the only moment at which the evaluator's live term set is exactly its `Env` plus the value the statement just reduced (both are handed over as `extra`).
A recursion-depth test inside the walker would not be equivalent: the same statement list is reached from `case`/`try`/fun clause bodies, whose subject terms and partially built containers are live and unnamed.
`Reclaim::prune` is enabled only by the `-eval` driver (`Evaluator::prune`); `apply_eval_closure` builds a fresh evaluator with `prune: false`, because its caller's terms are live and unnameable from there.
The resource half of this same node (`reclaim/resource.rs` — `prune_at_statement_boundary` at the `-eval` statement boundary and `prune_beyond` at a nested run's epilogue) inherits whatever root set `Runtime::gather_off_heap_roots` publishes, which is what makes the pending timer **deliveries**, every live process's registers/saved-args/signals and an engine's un-consumed arguments reachable for it too — this route runs with the runtime's own process table and `RunnerState`, so *every* family is live here (the park arm is the site where the per-pid families are empty).
### The root enumeration (`Runtime::gather_off_heap_roots`)
Whole regions are read **word by word** — `eval_heap`, each retired generation, every pooled BIF heap and the `info` scratch heap — so a `[BinRef][ErlSubBits]` pair cannot hide behind a container on a region this walk cannot read.
Named live sets are enumerated beside them: the evaluator's `Env` + reduced value (the caller's `extra`), `eval_closures[].env` (via `FunBody::env_terms`), the seq-trace tokens (`seq_trace::gather_off_heap_roots` — `set_label`/`set_from` store their term **unstabilized**), every live process's dictionary entries, mailbox messages, registers, saved arguments and pending signals, `Runtime::pending_spawns` (args + a `ProcessEntry::Fun`'s fun), an engine's un-consumed arena-stable arguments (plus its fun term) and an un-published parked machine's own root set (`RunnerState::gather_off_heap_roots`), and every pending timer **delivery** (`Timers::gather_off_heap_roots`).
Terms that **cannot** name a payload are deliberately not rooted for the payload half: `persistent_term` values, `trace` match specs, ETS (a deep copy re-materializes the window as on-heap sub-bits) and `references` (an all-immediate leaf) — and a term the schedule/store stabilization copied onto the arena (a pending timer's message, an engine's un-consumed argument) names no payload either, though both of those *are* enumerated, for the resource half's sake.
### The trigger and the refusal rule
The trigger is `O(1)` per call: the store's handle count (`Vec::len`) is compared with the count the last prune or observation saw, and the `O(handles)` byte figure is re-derived **only** when it moved.
Past `STORE_BUDGET_WORDS = 46 422` words (the BEAM default `min_bin_vheap_words`) the walk runs, and the store is rewritten `drain_binaries()` → retain live-or-shared → `push_binary` (which also de-duplicates by `data_ptr`).
The refusal rule is exactly: **an exhausted `WALK_VISIT_BUDGET` (`1 << 20`) or an unknown boxed header declines the whole prune**; a handle whose `refcount() > 1` is retained.
The global collection valve (`Runtime::gc_enabled`) is **not** a guard — it says "this runtime stopped *moving* process heaps", while this prune moves nothing, and the `-eval` route does not trip it (`reclaim::tests::the_eval_route_does_not_trip_the_collection_valve`).
`Runtime::any_engine_ever` is a **diagnostic**, not a decline condition: every route registers `{kernelProcess,…}` engines during boot, and a term an engine holds always brings its own payload handle (`Machine::refc_binaries`), which the `refcount() > 1` belt retains.
Every residual is therefore a **leak, never a dangle**.
### Known issues
Nothing here blocks the prune: the `-eval` route's store is bounded end to end (`../tests/eval_off_heap_reclaim.rs`) and the `run` route's nested-call payloads are bounded by the nested epilogue's **scoped** prune (`../context/pump.rs::adopt_nested_payloads`, which releases only the handles the finished run itself adopted).
A declined walk retains the whole store (the documented leak).
A payload an **earlier** nested run built is retained for the store's lifetime, so the fun-loop envelope converges on a capacity rather than a trough: measured `377 104` bytes at both N = 1 000 and 10 000 with 4 096-byte payloads and `393 504` at both with 65 536-byte ones, against `4 144 000` → `41 440 000` before.
`apply_eval_closure` never prunes: its caller's terms are live and unnameable from this node.
A raise from a nested run takes the plain adopt path — its reason term rides `Raise`'s live-reason slot, not the frozen root set — so that run's payloads are retained.
The `eval_heap` **region** is bounded by the statement window (`scratch.rs`, below): the words a discarded statement copied are reclaimed at the boundary before the next statement.
One residual remains, by construction: a **single giant statement** is inherently retained (its value *is* the result, so no boundary can see it dead) — the regions `Runtime::grow_eval_heap` retires are reclaimed by the sibling **region-reclaim pass** (`../runtime/reclaim.rs`, *The region-reclaim pass* below), which drops whole-dead retired regions at the same two sites and **evacuates** the partially live ones into a fresh region (the move), so what a one-statement run keeps is its *live* set rather than the volume it copied — with the one caveat the move's `R_PIN` decline states: when `compile:file/2` has stabilised a term into the runtime-lifetime store, the move declines *before* it starts and the partially live regions stay.
The `-eval` store's per-pid figure is never published (`Process::set_off_heap_binary_bytes` stays the runner's park-arm prune's): the store is not pid-attributable.
The reachability descent in `reclaim.rs` duplicates the shape of `RuntimeContext::graph_holds_reference` (`../context/calls.rs`); de-duplicating them is a deferral (that node owns the helper).
`beam_engine::MinimalContext`'s `ContextHeap` (`../../beam_engine/src/context.rs`) exposes `heap_mark`/`heap_mark_matches`/`for_each_heap_region`/`heap_rewind`, and `../runtime/reclaim.rs` is their production caller (Tier A: a rewind to the window's mark, never a move); before that pass runs, a pair on the arena is reached through `eval_heap`/`Env`/`eval_closures`, which is why the arena was not a hole for store-owned payloads.

## The statement window on the term store (`scratch.rs`, `scratch/tests.rs`)
`Runtime::eval_heap` is a pointer-stable bump arena that never gives a word back, and `Runtime::grow_eval_heap` retires its replaced region into `Runtime::eval_heap_retired` for ever — so the store a `-eval` run's container results are copied onto (`../context/pool.rs::move_result_into_runtime_store`) is, without a rewind, the **total volume the run ever copied** rather than its live set.
`scratch.rs` rewinds the dead prefix of the current region at the boundary **before** every top-level statement (`Evaluator::reset_scratch`, called from each `run_top_level` arm; the `-eval` driver's `prune` flag plus depth 0 is the gate, exactly as for `prune_escaped`): a comma sequence discards every statement's value but the last, so at that instant the live set is the evaluator's `Env` plus the named root families and nothing else.
The window `[mark, used)` is reclaimed only after the **same** reachability descent the escaped-payload prune uses (`reclaim::walk` with a `WindowProbe` sink over `Runtime::gather_off_heap_roots` plus the `Env`) found no word inside it.
Every refusal keeps **every** word: a descent that cannot complete, a replaced region, a mark above the frontier, a reached word, and a refused rewind all **decline**.
`scratch::pin` latches the window (advancing its mark, never resetting) for a step the descent cannot enumerate — `Runtime::stabilize_term`/`stabilize_term_with` and `../port/completion.rs::decode_caller_tag` (**`PinKind::Lifetime`**: the store still names the word after the driver returns), and `apply_eval_closure` plus the two nested-run sites in `../context/pump.rs` (`scratch::pin_transient`, **`PinKind::Transient`**: the machine that holds them is dropped inside the statement, and the pump latches only when the run actually **wrote** on the store — `Runtime::pin_window_if_store_written`, `../runtime.rs`). The classification never changes this module's own behaviour: any pin makes the window unresettable and advances its mark; it exists so `../runtime/reclaim.rs` can honour a lifetime pin at the exit site too.
**A nested-run site that writes on the store without latching is the one way a recycled word can still be named.** `../native/file_server/get_until.rs` (`EngineContinuation::call`) builds its own `Machine::new()` and drives `run_export_outcome` with no `pin_window_if_store_written`, yet it runs *inside* an `-eval` statement (the `{get_until,…}` route `epp`/`compile` take) while the window is open — so its machine roots are invisible to the next statement boundary's descent, and a term it hands to a holder outside `Runtime::gather_off_heap_roots` can be recycled.
`../boot/drive.rs` builds a `Machine::new()` the same way, but boot completes before `scratch::open` takes its mark, so its words lie *below* every window and are never candidates.
`MIN_WINDOW_WORDS` (1 024 words = 8 KiB) is the smallest window worth a descent; below it the mark stays where it is and the window keeps growing, so a small window is deferred, never lost.
Figures, the OFF control and the oracle cross-check (`../../tests/eval_region.rs`) are in [`../../PERF.md`](../../PERF.md) *The `-eval` statement window*; the 7 asserting pins are `scratch/tests.rs`.
Residual: a single giant statement is inherently retained (its value is the result). The retired chain a giant statement leaves behind is the region-reclaim pass's job, not this window's.
The window is `Some` for the **whole** driver run (`scratch::open` at `mod.rs:464` … `scratch::close` at `:501`), i.e. it is open while a nested module body runs, but a **reset** only happens at a boundary *before* a top-level statement — so a one-statement `-eval` (the `compile:file/2` shape) never resets at all: `run_top_level`'s single-expression arm takes one boundary before the statement, and `close` drops the window **without** resetting it (it runs the exit-site region-reclaim pass, which is handed the driver's own live terms and is exactly what reclaims that shape's retired chain).
**The engine's own term store is bounded by the region-reclaim pass, not by this window.** On the `-eval` route `mailbox_table` is `None`, so `context/gc.rs`'s `runtime.alloc_words(n)` → `Runtime::arena` (`beam_engine::MinimalContext::ContextHeap`), a `Vec` of `ReservedHeap` regions; only the *BIF container results* and the native file/prim replies land on `eval_heap`. A big compile therefore retains in two places: the second is this window's (and `Runtime::eval_region_stats`'s), the first is `../runtime/reclaim.rs`'s **arena action** — a Tier-A `heap_rewind` to the mark the window opened at, taken only when the descent found nothing reachable at or above it. Its live figure is `beam_engine::ContextHeapStats::live_words` (`reclaim::RegionReclaimStats::arena_words_reclaimed` is the cumulative released one); `Runtime::alloc_words`'s own `arena_words` counter is *cumulative demand* and is not lowered by a rewind.

## The region-reclaim pass (`../runtime/reclaim.rs`, `../runtime/reclaim/tests.rs`)
The statement window above owns the **current** region's `[mark, used)` prefix. The sibling pass owns the other two things a `-eval` run retains, and it runs at the **same two instants** (`scratch::open` opens both windows, `scratch::boundary` and `scratch::close` each run one pass) over **one** descent (`eval::reclaim::walk` with a `RangeProbe` sink, plus `Runtime::gather_off_heap_roots`).
**Two mechanisms, and one of them moves words** —
- **Phase 1a, whole-region actions** (`../runtime/reclaim.rs`): a *retired* region the window created whose words the descent proved dead is **dropped whole** (its `Heap::drop` frees the carrier — `store_regions_dropped`/`store_words_reclaimed`), and the current region's dead window is `reset_to(cursor)`. The **arena** (**Tier A**) is `heap_rewind`-ed to the mark the window opened at once nothing reachable stands at or above it (`arena_reclaims`/`arena_words_reclaimed`/`arena_regions_dropped`); Tier B's `reclaim_heap` is deliberately not used for it — its `forward` closure is fallible and an `Err` abandons the caller's roots.
- **Phase 1b, the evacuation move** (`../runtime/reclaim/compact.rs`): the *interleaved* shape Phase 1a cannot act on — one live word retaining a whole region — is evacuated instead. Every word reachable from the runtime's **mutable** corpus (`Runtime::for_each_root_mut`'s eighteen families plus this node's own live terms, handed over as `MoveSlots`) is copied into **one** fresh right-sized destination region through `beam_gc`'s `FromSet`/`LinearDest`/`Relocator`, and the roots are rewritten in place, so a moved store region leaves the evaluator's terms naming the destination. It is attempted only when the candidates hold ≥ `MIN_WINDOW_WORDS` (1 024 words = 8 KiB), **at least half** of their words are dead (the exact `beam_gc::live_words_in` count over the same corpus, which is the `words_copied` the copier will report, so the destination is sized from a real figure), and the move releases at least one region; below a threshold it is **skipped** silently and the whole-region action still runs. A fired move is `store_compactions` + 1 and owns both the copy and the drop.
The move's **completeness precondition** is a post-move *verification*: the same descent re-runs from the forwarded roots over the OLD ranges, and **any hit** (or a copy that failed mid-way) keeps **BOTH** — the destination is installed as a *retired* store region so the copies the rewritten roots name stay valid, every source region stays installed, nothing dangles, the move's own counters record the decline (`store_move_declines`/`store_move_last_decline`, reason `R_VERIFY_HIT`) and the pass does **not** fall through to the whole-region drop (`pass` matches `Moved | KeptBoth => {}` vs `Skipped | Declined => store_action(…)`), because the descent that just failed is known incomplete for exactly those ranges. A source object the corpus never enumerated is untouched, and the next pass re-classifies every region on fresh evidence. A hit is **attributed** rather than merely counted (`compact.rs::verification_owner` → `MoveHitOwner`, published as `store_move_hit` / `store_move_hit_family` / `store_move_hit_slot`): the caller's `MoveSlots` are re-walked one at a time, then the corpus family by family through `Runtime::for_each_root_family_mut`, so the reason names `CallerSlot(i)` / `Family(family, slot)`, or `OutsideCorpus` when no slot reproduces the hit.
The **move's decline list** (`compact.rs`'s `R_*` constants, each recorded with both regions left usable): the move switch is off (`R_SWITCH`); **`R_PIN`** — a *runtime-lifetime* store latched the window (`scratch::pin`, `PinKind::Lifetime`: the `stabilize_term` family and `../port/completion.rs::decode_caller_tag`), which may name a word in a region a move would evacuate and has no writable slot, so doubt is a refusal at **both** sites; a recorded raise's live reason word whose **address** stands inside a candidate range (`R_REASON` — a reader and no writable slot); a destination that could not be allocated or would exceed the store's ceiling (`R_DEST_ALLOC`/`R_DEST_CEILING`); a destination that cannot reserve the live set, refused **before** the first word moves (`R_CAPACITY`); a copy or destination scan that failed after the first word (`R_COPY`/`R_SCAN`); an incomplete corpus enumeration (`R_ENUMERATION`); the verification hit. **`R_PIN` is empirically necessary, not conservative-by-accident:** with the pin check bypassed the post-move verification HITS on `cerl_clauses` (a live word really does stand in an old region) and the compile then fails with `system_limit` — the incomplete corpus is real.
The whole-region pass's own **decline list** (each a `&'static str` on `RegionReclaimStats::reclaim_last_decline`, and every one leaves both regions byte-identical): the switch is off; no reclaim window is open; a withheld live term (a `Flow::Fatal` whose `BeamError` may carry a live reason word and exposes no mutable accessor); `Runtime::in_machine` set; no statement window is open; a runtime-lifetime pin at the boundary; a transient pin **at the boundary only** (a machine in flight is dead by the exit); a walk decline; a refused rewind. A **recorded** raise is not a decline: its live reason word is pulled out by `RunnerState::for_each_error_live_reason` and joins the descent's corpus, so a region holding one is retained **on evidence** (the moving mechanism cannot rewrite it, which is what `R_REASON` is for).
Two guards tie it to this module: a **lifetime** pin registers its region with the pass (`scratch::pin` → `reclaim::note_lifetime_store`: the current region may not be reset for the rest of its life as the current region, and every region retired from then on is excluded), and the window's mark is the pass's **current-region floor** — the two mechanisms never reset below each other.
What it buys, **measured** (release build, `BEAM_RT_MEM_TRACE=1`, the tree OTP-30 bootstrap compiler first on `-pa`): a one-statement `-eval` (the `compile:file/2` shape) has no second boundary, so its replaced chain is dead the moment the run's result is the only live term, and the exit-site pass collapses it with **one** descent and no move — `inet_parse` recovers **18 of its 19** retired store regions (**603 193 147** words) and rewinds the arena **11** regions, with `reclaim_declines=0`; `cerl_clauses` (1.1 s) had nothing left to drop. What survives in both workloads is **one retired 16 777 216-word region plus the 33 554 432-word current region**, and it survives because `store_compactions` is **0**: the move declined at its first check with `R_PIN`, because `compile:file/2` stabilises terms into the runtime-lifetime store the statement window cannot enumerate. A workload that retains a region does so because of the `R_PIN` decline, not because a move was attempted and failed. The exact `[rt-mem] exit` lines, their reading and the artifact-identity check are `../runtime/CONTEXT.md`'s.
The switch is `BEAM_RT_REGION_RECLAIM` (`all`/`store`/`store-whole`/`arena`/`nomove`/`off`) plus `Runtime::set_region_reclaim_enabled`; like the window's own it can only *disable* an action, never a guard. Figures and the pinned unit tests: `../runtime/CONTEXT.md`, `../runtime/reclaim/tests.rs`.
### Phase 2 — reclaiming *during* a nested compile: blocked (the residual)
Everything above runs at the two **non-running** sites. A compile's own words are written while it runs, and none of the three points inside a nested `compile:file/2` can carry a move:
- **POINT A — the nested-run exit** (`../context/pump.rs::run_export_blocking` :268 / `run_label_blocking` :356, inside `with_relocation_exempt`, sequence :283-307 / :369-388). The CURRENT machine's `&mut` is a Rust local between `machine_pool::acquire` (:294/:376) and `machine_pool::release` (:306/:387), so `Machine::for_each_root_mut` *is* callable there and `adopt_nested_payloads` (:450) already publishes `RootSet::ALL_LIVE` (:509) — but `RuntimeContext` holds no machine field (`../context/runtime_context.rs:48-165`), the **parent**/in-flight machines are unreachable (`Runtime::in_machine` is a single `Option<InMachinePosition>` position slot, `../runtime.rs:662`; a parent machine lives only on the enclosing epilogue's Rust frame; `FunBridge::nested` builds a **fresh** context per applied fun), and this node's own live terms — the `Env` (`HashMap<String, Eterm>`, `mod.rs:200`), `Evaluator::terms`, `list`, `Flow::Raise{reason}`, the match-arm locals — are Rust locals of a *different* frame with no `&mut` slot (and a rehash gives no stable one). The smallest additive seam is therefore a runtime-owned stack of in-flight machine holders (`*mut Machine` + a re-seed rule) pushed/popped at those two epilogues and surfaced as a `RootFamily`, **plus** `Env` index-stabilisation (`Vec<Option<Eterm>>` keyed by a name index — a rewrite of the env plumbing, not a seam), **plus** a mutable `Raise::live_reason` accessor in `beam_common`.
- **POINT B — the store-growth point** (`../runtime.rs::grow_eval_heap` :2558 — `&mut self`, no context and no machine) **and** the arena frontier rollover (`ContextHeap::alloc`, `beam_engine/src/context.rs:1544` — grow-in-place, else a doubled fresh region, `relocate` never called there, so the arena has no dead-and-droppable suffix). Same parent/`Env` findings as POINT A, and `grow_eval_heap` is provably too late for a *move*: the words it retires are already intermixed with live ones in the same `used` prefix.
- **POINT C — the engine heap-admission safepoint** (`ExecutionContext::ensure_heap`, `../context/gc.rs:1055`; `ensure_heap_full` :1273). The machine's roots arrive **as arguments** (`RootSet{live,x,stack,fr}`) and the context holds no `*mut Machine`, so `Machine::for_each_root_mut` is not callable from inside it; parents are unreachable; and `ensure_heap` returns `Ok(())` immediately when `armed == false` — which is **every** nested machine — while `ensure_heap_full` bails at `current_module.is_none()` (:1294), so the point never fires for a nested run.
A move there is not merely inconvenient: `beam_engine::MinimalContext::reclaim_heap`'s `forward` is fallible and an `Err` leaves the arena **empty** with the epoch bumped (`beam_engine/src/context/reclaim.rs:544`+), its `FromSet` cannot span the store, so a store↔arena term graph cannot be relocated by one relocator, and several holders have no `&mut Eterm` slot at all (the `Env` as a `HashMap`, the evaluator's accumulators, `Flow::Raise{reason}`, `RunnerState::errors`' `BeamError` — which is why the move declines by **address** when a recorded reason word stands inside a candidate range).
**Conclusion, stated plainly:** the single-compile **peak** is *not* bounded by this change, and the binding holder is the **in-flight machine stack together with the evaluator's Rust-frame root set** — the two things no `&mut` reachability exists for at any of the three points. The exile window (`with_relocation_exempt`, `mod.rs:459`) therefore stays exactly where it is. What *is* bounded today is what the two committed mechanisms deliver at the two non-running sites: the retired store chain collapses and the arena is rewound, measured above.
## API Surface
### Entry points (`mod.rs`)
- `pub fn eval(ctx: &mut RuntimeContext<'_>, expr: &str) -> Result<Eterm>` — the crate-root-re-exported entry point: parses `expr`, tree-walks it in a fresh `Env`, and returns the value term on the process heap (valid for the runtime's lifetime). The whole driver runs inside `ctx.with_relocation_exempt(..)`, so an evaluation's Rust-local terms (the `Env`, reply terms) are never moved by a delivery-driven collection while the receive pump runs.
- `pub(crate) fn apply_eval_closure(ctx, fun, index, args) -> Result<Eterm>` — applies a stored evaluator closure by `index`, called from `RuntimeContext::apply_fun` when a loaded module applies a fun stamped `EVAL_FUN_UNIQ`. `BadArg` when no closure is stored at `index`.
- `pub(crate) const EVAL_FUN_UNIQ: u64 = 0x6265_616d_7274_0001` — the sentinel `uniq` stamped into every fun this evaluator builds, so such a fun is recognisable and resolvable.
- `pub(crate) struct FunBody { kind: FunKind, env: Env }` — a closure body (`FunKind::Local { name, clauses }` + its captured `env`), pushed onto `Runtime::eval_closures` by `register_fun`.
- `parse::parse(src) -> Result<Expr>` (`parse.rs`) and the AST (`ast.rs`) are reachable only inside this module (`mod ast; mod parse;` are private).
- Internal to `mod.rs`: `Evaluator` (the walker), `Flow { Raise{class,reason,origin,head}, Fatal }` + `EResult`/`Env`, `finish` (the module's **only** terminal conversion of a `Flow::Raise` into a `BeamError`; it attaches a non-atom reason to the raise's live-reason slot), the `BitBuf` MSB-first binary builder, and `operator_bif`/`read_bits_be`/`read_bits_le`/`sign_extend`/`mask_bits`/`trim_digits`/`integer_segment_is_little` helpers.

### Grammar coverage (`parse.rs` + `ast.rs`)
The **expression** subset of Erlang (`erl_eval`'s input) with Erlang's exact precedence/associativity (`binop_of`'s binding powers mirror `erl_parse.yrl`; `catch` lowest, then `=`/`!`, `orelse`, `andalso`, the comparison family, `++`/`--`, additive, multiplicative, then prefix operators):
- literals in every base (`Base#Digits`, radix 2..=36), floats (with exponent), atoms (bare and quoted), strings, chars (`$a`, escapes incl. `\xHH`, `\x{…}`, octal, the named escapes), lists (incl. improper `[1,2|3]`), tuples, maps, binaries;
- variables (`X`, `_`, `_Name`) and `Pattern = Expr` matching;
- `case`/`if`/`begin`/`try`/`catch`/`receive`;
- `fun`s (anonymous `fun(…)->…end`, named self-recursive `fun F(…)->…end`, captured `fun f/A` / `fun M:F/A`);
- list, map and binary comprehensions (with `<-` generators, `<=` binary generators, and filters), incl. the `<<…>>` template form the parser records as a single segment;
- prefix/postfix call application: an auto-imported local call `f(Args)`, a remote call `m:f(Args)`, and a call of a fun-valued expression `(fun…end)(Args)`.
A trailing `.` is tolerated by the parser, and the CLI strips one (`cli.rs::strip_trailing_dot`).
The lexer keeps **quoted** atoms distinct from bare words: `'case'` is a `Tok::QuotedAtom` while `case` is a `Tok::Atom`, mirroring OTP's scanner (`erl_scan:string("case")` → `{'case',1}`, `erl_scan:string("'case'")` → `{atom,1,'case'}`).
A quoted atom is **always** an atom — never a keyword, never an infix operator and never a variable — so `is_atom`/`eat_atom`/`expect_atom` (the `of`/`end`/`when`/`after`/`catch` guards and `parse_prefix`'s `not`/`bnot`/`catch`) and `binop_of` match only the bare variant, while `expect_atom_name` (a function/module name after `:` and the names in `fun M:F/A`) accepts both.
`'when'`, `'of'`, `'end'`, `'case'`, `'receive'`, `'fun'`, `'begin'`, `'try'`, `'after'`, `'catch'` and `'not'` therefore parse as plain `Expr::Atom`s in every position (primary, argument, tuple element, map key, clause pattern/body, comprehension element), and a quoted atom is not a terminator (`'end'`/`'of'` do not close a `case`).
A quoted *call head* is always a function call: `after_atom(…, quoted = true)` emits `Expr::Remote("erlang", Name, Args)` (an auto-imported local call is exactly `erlang:Name/Arity`), so `'abs'(-1)` is still `erlang:abs/1` and `'Foo'(1)` reaches the oracle's `undef` instead of a fun-valued-variable `variable "Foo" is unbound`.
`fun 'foo'/0` and `fun 'erlang':'+'/2` stay fun references, while `fun 'foo'(X) -> X end` is a syntax error (Erlang requires the named-fun form's name to be a *variable*), and out-of-grammar `1 'and' 2` is the typed capability gap it is on the oracle (a syntax error), never `1 and 2`.
Integers are exact up to `i128`; a literal past `i128` is a typed capability gap.
The binary-segment parse modes (`in_segment` for `/` as a type specifier rather than division, `no_remote` for a `try` clause's `Class:Reason` head) are the parser's two context flags.
Semantics inherited from the lower crates (nothing re-implemented): arithmetic/comparison/bit operators are **`erlang` BIFs** dispatched through `RuntimeContext::call_bif` (so `1/0` ⇒ `error:badarith` and the six bit operators get their bignum semantics); a call is a `call_bif` (the load-on-demand stdlib path); terms are built through `beam_engine::terms`/`beam_codec::term`; terms are inspected only through `beam_term`/`beam_engine::terms`. The operators the `beam_bifs` surface deliberately does **not** own — `and`/`or`/`xor`/`not`/`andalso`/`orelse` (Erlang special forms) and `++`/`--` — are implemented here with the oracle's error behaviour (`not 5` ⇒ `error:badarg`). The raise helpers (`error/1,2`, `exit/1`, `throw/1`, `nif_error/1,2`) and `apply/2,3` are served here so a **live reason term** survives (the atom-only `beam_common::ExitReason` cannot carry one); an unresolved call target additionally yields a raise carrying the synthesized **callee head trace item** (`Flow::Raise.head`). `erlang:raise/3` is deliberately **not** served here: it must validate its class *and* its stacktrace argument and forward the decoded trace, so the call falls through to the registered `beam_bifs::convert::raise_3` BIF (an invalid shape is that BIF's **returned** `badarg` atom — a value, never a raise — and a valid one raises with the decoded `StackTrace` attached).

### Binary segments (`<<…>>`) — construction and pattern matching
Both directions are implemented and oracle-cross-checked; the pure bit work lives in three sibling modules so `mod.rs` does not carry it (`bits.rs` = construction encoders, `bits_decode.rs` = field decoders, `bits_match.rs` = the little-endian match reader).
- **Construction, integers** (`Evaluator::append_segment` + `bits::integer_le_image`): a segment of **any** width from a small int or an exact bignum, in two's complement, big- or little-endian (`native` is little-endian here) — `little` is laid out **byte-wise**: the `n_bits / 8` whole bytes least-significant first, then the value's next byte's **low** `n_bits % 8` bits pushed into the high bits of the final partial byte (`<<-300:12/little>>` = `<<212,14:4>>`, `<<255:12/little>>` = `<<255,0:4>>`).
- **Construction, `float`**: `:16`/`:32`/`:64` (default `64`), either endianness, the value rounded half-to-even (`bits::f64_to_f16`/`f64_to_f32_bits`/`float_bytes`); an integer value is accepted and converted (`<<(1 bsl 64):64/float>>` = 2^64 as a double); `signed` is accepted and ignored.
- **Construction, utf**: `utf8`/`utf16`/`utf32` from a code-point integer, an astral code point becoming a surrogate pair and `utf16-little` swapping **each 2-byte unit**; a lone surrogate, a code point past `16#10FFFF` or a negative value is `error:badarg`, exactly as on the oracle.
- **Pattern matching** (`Evaluator::match_binary_segments` + `bits_decode.rs` + `bits_match.rs`): integer segments of **any** width (exact; `signed` sign-extends within the segment width; a value past the 60-bit small range is a real bignum, never `system_limit`), `float` (`:16`/`:32`/`:64`, default `64`), and `utf8`/`utf16`/`utf32` (consuming 1–4 bytes / 2 or 4 bytes / 4 bytes).
- **The absolute rule:** an invalid, truncated or out-of-range pattern field is a **match failure** (`Ok(None)` → `false`), never a raise — a malformed UTF sequence, a lone surrogate, a value past `16#10FFFF`, a float width ∉ {16,32,64} and fewer bits than the segment needs all simply do not match.
A `<<…>>` pattern must consume the subject exactly, so `case <<255,…,255>> (9 bytes) of <<A:65>> -> A end` is `case_clause` (65 of 72 bits), not a gap.
- **A literal string is one segment per character**, expanded in the parser (`parse::parse_segment_expanded`), so construction, matching and the comprehensions all see one shape: `<<"abc">>` is three 8-bit integer segments, and a utf-typed or sized string keeps its kind/size per character (`<<"abc"/utf16>>` = `<<0,97,0,98,0,99>>`, `<<"abc":16>>` = `<<0,97,0,98,0,99>>`). A *variable* holding a list with a utf kind stays the oracle's `error:badarg`.

### Capability gap (anything outside the grammar)
Everything outside the grammar is a typed capability gap: the parser (and a few evaluator arms) raise a `BeamError` built by `crate::error::bad_eval`/`error::unsupported`, whose reason atom starts with `unsupported` (the `unsupported:` convention). `Evaluator::flow_from_error` turns it into `Flow::Fatal`, so a raise from the evaluated expression's own `try … catch` cannot swallow it — it propagates out and the CLI exits **3** with one `beam_rt: unsupported: <reason>` line (`crate::error::unsupported_reason` is the single classifier). `erlang:halt/0,1` is likewise `Flow::Fatal` (uncatchable), so `… halt(0) catch … end` terminates with status 0. Genuine `error`/`exit`/`throw` raises (and BIF structured reasons like `{badmap,M}`, `{badkey,K}`, `{case_clause,V}`, `{bad_generator,X}`) stay fully catchable, with their live reason term preserved.

## Constraints
- **`unsafe`-free**: the crate is `#![deny(unsafe_code)]`; this node contains no `unsafe` (term layout is never touched here).
- **Return-based errors, no silent swallowing** (`../CONTEXT.md` §3): the public entry points return `beam_common::Result`; the internal walker carries its own `Flow` signal, converted once by `finish`. No crate-local error enum, no `panic!`/`unwrap()` on runtime data.
- **Call down, never duplicate**: arithmetic/comparison/bit operators and every call go through `RuntimeContext::call_bif` (the `beam_bifs` `erlang` registry / load-on-demand stdlib); terms are built/inspected only through `beam_term` (+ `beam_engine::terms` / `beam_codec::term`); the `~w`/`~p` printer is not re-implemented here.
- **`Flow::Fatal` is the uncatchable channel** (halt + capability gap); only `BeamError::Raise` becomes a catchable `Flow::Raise`.
- Files ~1000 lines: `mod.rs` is one cohesive unit (the `Evaluator`, the entry points and the `#[cfg(test)]` suite); `ast.rs`/`parse.rs` are the tree and the lexer/parser, and the bit-string machinery is three further files (`bits.rs`, `bits_decode.rs`, `bits_match.rs`) split by direction — construction / field decode / match read — rather than growing `mod.rs`.

## Known Issues (typed capability gaps — never wrong results)
- `receive` **without** an `after` clause is a typed `unsupported` when nothing can deliver: with no window to bound a wait on, nothing more can be done — unless a live port's driver holds **one of its own asynchronous operations** (`Runtime::ports_awaiting_async`: a passive `gen_tcp:recv/2,3`, an `accept`, a datagram read), which owes the receive a `{inet_async, …}` only a later port round can produce; that wait is sat out here over the blocking pass, reading the same three progress signals and the same `crate::port::PORT_EVENT_DEADLINE` (5 s of consecutive no-progress rounds) as the compiled route's `RuntimeContext::wait_for_port_event`. With `after T` the evaluator scans the running process's **real mailbox**, pumps the scheduler **non-blockingly** (bounded by `RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass, and spends the remaining time on the runtime's **timer heap** (`Runtime::wait_for_timer` — sleep to the earliest pending deadline, or the window end, then one bounded pass), so `spawn(fun() -> Self ! hello end), receive M -> M after 1000 -> …` works end to end and a due `erlang:send_after/3`/`timer:apply_after/4` deadline fires and delivers inside the window. Every message a port round produces for this process is **delivered into its mailbox** through the runtime's one delivery path (`RuntimeContext::poll_port_messages_into_mailbox`), never tried against the clauses inline, so the `receive` is selective over port frames exactly as the oracle's is. A bare `receive` **inside an in-slice spawned process** — a closure `spawn`ed from running loaded code, which keeps the tree-walking entry (see the compile bullet below) — is also `unsupported` (it runs inside a scheduler slice and may not re-enter the scheduler), and `receive … after infinity` maps to `infinity`'s "block forever" as a typed gap.
- **`receive … after T` ends on its own deadline, with one port-poll slice of pickup latency.** The `after` arm of `Evaluator::receive` scans the running process's **real mailbox** first, then tests the deadline, then pumps the scheduler **non-blockingly** (`Runtime::pump_scheduler_now`, bounded by `RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass over `remaining.min(PORT_POLL_SLICE)` and spends the remaining time on the runtime's **timer heap** (`Runtime::wait_for_timer` — sleep to the earliest pending deadline or the window end, then one bounded pass) — all within one iteration, and the loop goes round to rescan the mailbox before it ever runs the `after` body. So a closed window pays no pump, no poll and no sleep, and a message that arrived at the boundary still wins over the `after` body. Measured on the CLI route against the oracle (`erlang:monotonic_time(millisecond)` deltas): `after 1|25|50|100|300|1000` → **1|25|50|100|300|1000** (oracle 2|26|51|101|301|1001), `spawn(fun() -> P ! late end)` then `receive late … after 300` → `{msg,0}`, `erlang:send_after(100, …)` → `{msg,100}`. A port round's messages are **delivered into the running process's mailbox** (through `RuntimeContext::poll_port_messages_into_mailbox`, the same `deliver_message` path the scheduler route uses) before any clause is tried, so the clause matching is the loop head's own mailbox scan: a frame no clause matches **stays queued** for a later `receive`, and the frames drained in the same round as a matching one are not discarded with it (the corpus cases `driver/line_full_line_noeol_flush` and the selective half of the same family are the evidence). A delivery sends the loop straight back to the scan — no poll, no wait — so a matched frame is picked up immediately. The one residual is by construction: a message arriving in the **timer heap** is picked up by the next iteration, i.e. within `PORT_POLL_SLICE` (25 ms). Pinned by `eval::tests::{an_after_window_fires_on_its_own_deadline, a_message_that_beats_the_deadline_is_picked_up_promptly}` (wall clock) and `…::{a_long_after_window_is_waited_out_in_port_poll_slices, a_sub_slice_after_window_never_loops}` (iteration counts). The bare-receive arm keeps the blocking `pump_scheduler` — there the sleeps are what give a runnable child time to deliver, and there is no deadline to be late for.
- **A spawned `-eval` closure is compiled into a synthetic module and runs as a real process entry.** `compile.rs::entry_for` takes the closure's own source text — sliced verbatim out of the `-eval` expression by the parser (`FunBody::source`) — and emits `-module(beam_rt_eval_fun_<index>). -export([run/<k+A>]). run(<capture names…>, BeamRtArg1…N) -> (<closure source text, verbatim>)(BeamRtArg1…N).`, compiles it **in process** (`compile:file/2` with `binary`, `no_spawn_compiler_process`, `return_errors`, `return_warnings` over a uniquely named temp `.erl`, removed on drop) and loads it with `code:load_binary/3`; the spawn then creates an ordinary `ProcessEntry::Export`, so a bare `receive` parks the child, a later send resumes it, and a nested `timer:sleep/1` parks it too.
  Three conventions make it faithful: a capture is the generated entry's parameter and keeps the **captured variable's own name**, so the embedded body reads it (name-sorted, so the parameter order is deterministic, and the spawn's own arguments follow the captures); embedding the *text* rather than printing the AST lets the compiler derive the free variables, the optional self-recursion name (`fun F(N) -> … F(N-1) … end`) and every nested fun; and a capture the body appears to rebind is a **match** against it, exactly as erl_eval's clause binding behaves.
  `CompiledClosure` is cached on `Runtime::eval_compiled` by the closure's index — a decline included — so a repeat spawn costs one map probe (measured: a second spawn of the same closure adds **0 ms**) and an uncompilable closure is never re-compiled.
  Cost, measured on the CLI route as `erlang:monotonic_time(millisecond)` deltas in the debug runtime: the **first** compile in a fresh runtime costs **154 ms** (loading the compiler's own modules dominates) and each further distinct closure **41-42 ms**; whole-invocation wall `749-898 ms` → `933-951 ms` for one spawned closure. Because the first spawn pays that compile, a **pickup** bound is measured only on children that carry none — a compiled-MFA child (`spawn(erlang, send, [Self, late])`) and the closure's **second** spawn (the cache hit) — while the cold span is pinned apart, against its own compile budget (`eval::tests::COLD_CLOSURE_COMPILE_BUDGET`, 2 s against the 154-353 ms measured).
  Every failure — no recorded source, a compile error, an unloadable image, no reachable compiler — **declines** to the tree-walking entry, so its typed gaps are unchanged rather than replaced by a wrong value: a body with an **undefined variable** cannot compile, so the child dies with `variable "UndefinedVar" is unbound` (the oracle rejects the whole `-eval` expression at *parse* time instead — exit 1, no stdout — so this case is not oracle-comparable).
  The residual is the **in-slice** spawn: a `spawn` made from inside a running engine (`../native/process.rs::spawn_in_pass`, i.e. from loaded code) may not re-enter the scheduler, so it keeps the tree-walking `ProcessEntry::Fun { target: None }` — there a bare `receive` reports `unsupported: receive (no after clause) inside a spawned process` (`mod.rs`'s `None` arm) and a parking callee folds into `beam_engine::blocked()`, because the nested `Machine` is driven by a context with `may_pump_scheduler() == false` (`../context/pump.rs`).
  The engine-side half of a *resumable* walker exists anyway — `beam_engine::FunOutcome::{Return, Suspend}` plus the defaulted `ExecutionContext::apply_fun_outcome`, consulted at the `call_fun`/`call_fun2` closure seam's `Ok(None)` arm (`../../beam_engine/src/families/funs/mod.rs`, pinned by `../../beam_engine/tests/fun_suspend.rs`) — and it is what an in-machine closure application would use; nothing on the spawn route needs it now.
- `catch Expr` folds **by class**, exactly like `erl_eval`: `throw` yields the reason, `exit` yields `{'EXIT', Reason}`, and `error` yields `{'EXIT', {Reason, Stacktrace}}` — always a 2-tuple, even for a non-atom reason. A `try … catch Class:Reason:Stacktrace` clause's third pattern is matched against the same cooked trace. `Evaluator::cook_supplied_trace` renders it from two sources, innermost first: the raise's **synthesized callee head item** (`Flow::Raise.head`) and the supplied `erlang:raise/3` frames through `beam_engine::encode_supplied_stacktrace` (a clone of the shared `AtomTable` as the atom source).
  The head item is consed **in front of** the supplied list (`make_cons`, `mod.rs:1857`), which the oracle never does (C's `build_stacktrace` returns a supplied trace before any frame lookup) — latent, because `head` exists only for the bare `undef` while an `erlang:raise/3` flow carries `head: None`, and `beam_engine`'s own compiled-code cook takes the *opposite* precedence (a live supplied trace suppresses the synthesized `undef` item).
- **An `undef` carries the missing callee's head item.** When an unresolved call target makes `CallBif` answer the bare `error:undef`, the evaluator's own call site (`Evaluator::call` / `apply_value`) synthesizes `{TargetModule, TargetFunction, ArgList, Location}`, with the call's **real** evaluated argument list and `Location = []` (the callee does not exist, so there is no source position) — the same item the engine's compiled-code path builds (`beam_engine::families::exceptions::callee`) and the one OTP's `logger_server:call_h/4` matches on. It is built only from that site's own callee identity and arguments; **no `erl_eval`/`init` frame is fabricated** (there is no `erl_eval` port here), so the walker's cooked trace is the head item followed by `[]`. `/2`'s fun form contributes the item only for an **external** `fun m:f/A` (a local/imported fun's term carries no module to name). `is_unresolved_undef`-style gating: only the bare `undef` — class `error` with the reason **atom** `undef` — and only when no head item is present yet, so a re-raise through a non-matching `try` keeps it. A raise carrying no head item and no supplied trace (`erlang:error/1`, an arithmetic error) renders an **empty** trace, because the tree-walker gathers none beyond the head item.
- A **utf pattern segment carrying an explicit `:Size`/`unit:`** is a typed `unsupported`: the oracle rejects such a segment *syntactically* (`<<C:8/utf8>>` is a syntax error), so no differential case can exist and no value may be fabricated.
- A **non-final unsized** `binary`/`bitstring` pattern segment is a typed `unsupported` (Erlang requires such a segment to be last).
- The `-eval` CLI action's own uncaught raise is rendered with its real reason term: `finish` populates the live-reason slot, `Runtime::eval` stabilizes that term at the action process's escape boundary (`Runtime::stabilize_error_live_reason` — the action child's heap dies right after), and the CLI's `Action::Eval` arm routes the failure through `cli.rs`'s `reported_reason`, exactly as `Action::Boot` and the `run` action do. So `beam_rt -noshell -eval 'erlang:error({badkey, binary:copy(<<"abc">>)})'` prints `beam_rt: error {badkey,<<97,98,99>>}` (exit 1), never the `<structured reason>` placeholder. Pinned end to end by `../../tests/structured_reason_lifetime.rs`.
- A non-empty list's clause `apply_closure` with no matching arity is `BadArity`.
- `erlang:alias/0`, NIF/driver dispatch, `open_port` and every other host facility behave as the lower crates specify — this node only *calls* them.

Compaction consequences (binding):
- **The `Env` chain is the evaluator's only host-side root set, and it lives in Rust locals/parameters, never in the `Evaluator`.** `Evaluator` (`mod.rs:536-553`) has exactly `ctx`, `depth`, `prune` — no `env` field. The driver owns `env` (`mod.rs:416`) and clones it per clause/guard/`case`/`if`/`try`/`receive`/comprehension (`mod.rs:1319,1371,1388,1399,1429,1456,1551,1647,1721,1896,2000,2031,2432`). Only the root `env` is ever republished (as `extra` at the prune/window boundary); a clause-local clone is invisible to every root enumeration.
- **`FunBody.env` and `CompiledClosure.captures` are ONE slot, not two families.** `compile.rs`'s "no new root family" claim holds only while they stay word-identical; a compaction must rewrite both in lockstep or a later spawn reads a stale word.
- **`scratch::Window::base` and `RangeProbe`'s ranges are address identities** (`scratch.rs`, `Window::base` and `RangeProbe::new`'s `ranges` slices, fed from `../runtime/reclaim.rs`'s `Cursor` and the arena's `for_each_heap_region` base addresses): a moved region must recompute them or force a `decline` — never leave them stale (a stale `base` fails the `base != base` test and declines safely; a stale range can answer a false *miss*, which is why the move **re-anchors** both the pass's cursor (`reclaim::advance_cursor`) and the statement window (`ScratchState::stop`, which drops the window so the next statement opens a fresh one above the destination) rather than leaving either naming a region it evacuated).
- **`reclaim.rs`'s two halves differ under compaction:** `collect_region_payloads` (`:439-446`) only *pattern-matches* the `HEADER_BIN_REF` word and reads `window[1].raw()` as a value (sound if `BinRef.val` tracks the payload), while `walk` (`:458-538`) *dereferences* every boxed/list word — so any walk taken across a move must run on rewritten words.
- **Two locations the store move cannot reach:** the arena (`Runtime::alloc_words` → `beam_engine::MinimalContext::ContextHeap`; `Tier A` rewinds it but never moves a word, and `Tier B`'s `reclaim_heap` is refused on this route — see `../runtime/reclaim.rs` *Why Tier A and not Tier B*) and a nested run's `Machine` roots (`context/pump.rs` under `with_relocation_exempt`, deliberately absent from `Runtime::gather_off_heap_roots` **and** from `Runtime::for_each_root_mut`, whose completeness claim holds only at a non-running site — that absence is the Phase-2 blocker below).
- **Two of the node's root holders have a MUTABLE seam, and so do the evaluator's own live terms.** `FunBody::for_each_root_mut` (`mod.rs`) and `CompiledClosure::for_each_root_mut` (`compile.rs`) hand a visitor the writable capture words, and `FunBody` derives `Clone` for the runtime's `Rc::make_mut` clone-on-write split (`Runtime::for_each_root_family_mut` reaches them as `EvalClosureEnv`/`EvalCompiledCaptures`, `../runtime/roots.rs`; sound because that walk runs only at a non-running site, see `../runtime/CONTEXT.md`); `scratch::boundary`/`scratch::close` take `env: &mut Env` + `extra: &mut [Eterm]` and build the move's `MoveSlots` from those very slots (`scratch.rs:526,454`), so a moved region leaves the evaluator's bindings naming the destination. The node's **pruning** sinks stay read-only: `reclaim::prune`/`prune_scoped` take `extra: &[Eterm]` (`reclaim.rs:325,350`), `resource::prune_beyond`/`prune_at_statement_boundary` the same (`reclaim/resource.rs:360,439`), `reclaim::walk(roots: &[Eterm])` (`reclaim.rs:458`) and `Reach::word(&mut self, term: Eterm)` (`reclaim.rs:246`, `scratch.rs:388`, `reclaim/resource.rs:283`) — the only mutation there is the walk's own `work: Vec<Eterm>` (`reclaim.rs:459`). The cache side stays behind `Rc`/a map (`Runtime::eval_closures: Vec<Rc<FunBody>>` (`runtime.rs:898`), `Runtime::eval_compiled: FastHashMap<u32, Option<CompiledClosure>>` (`runtime.rs:910`)), whose entries are **cloned out** (`compile.rs:164,173`) and whose `FunBody` is `Rc`-cloned before an application (`mod.rs:516`) — which is exactly why the seam is `Rc::make_mut`, not `iter_mut` — and a **clause-local `Env` clone plus the evaluator's other Rust-stack locals remain unenumerable** (the `Env`-chain bullet above: they are stack frames in another frame, and the whole driver runs under `with_relocation_exempt`).

## Notes for Agents
### The evaluation-order contract (sub-expressions run in `erl_eval`'s order)
The evaluator evaluates a construct's sub-expressions **left-to-right in source order**, exactly as `erl_eval` does:
- a **list**'s elements left-to-right, **then** its optional tail;
- a **tuple**'s elements left-to-right;
- a **map field**'s key before its value, with fields in source order;
- a **binary segment**'s value before its size;
- **call** arguments in order; `++`/`--` left operand before right;
- a **comprehension**'s template once per generated element in generator order.
Order is observable only through a side effect (an `io:format/2` in an element), so it is pinned by the spy-closure probes in `mod.rs::tests::literals_evaluate_their_sub_expressions_in_source_order` and in `../../tests/eval_order.rs` (the latter cross-checks the **system `erl`** prints the same bytes).
The list's **cons chain** is only *built* right-to-left after the values are already evaluated (`Evaluator::list` collects the element values, then folds them onto the tail) — this does not change the list's *value*, only the order the side effects ran in. Do not describe the current order as "right-to-left".
### Other facts
- The evaluator keeps its environment in Rust locals, so its terms are **not** in a collection's root set; the whole `eval` driver therefore runs under `RuntimeContext::with_relocation_exempt` (see `../context/CONTEXT.md`), which is exactly when a reply to this pid could arrive.
- A fun built here is recorded in `Runtime::eval_closures` and can escape into a loaded module; `fun M:F/A` is **not** a closure — it is the real `EXPORT_EXT` term (no `uniq`), applied through the host's ordinary dynamic call.
- `../CONTEXT.md` (this crate) describes the CLI surface and exit codes; `../runtime/CONTEXT.md` owns `Runtime::eval`/`eval_closures`; `../context/CONTEXT.md` documents `apply_fun`'s dispatch to `apply_eval_closure`.

### Bit-string invariants
- A `<<…>>` **pattern** failure is `Ok(None)`/`false`, never a raise: Erlang's rule is that an unreadable field (wrong width, too few bits, malformed UTF, out of range) simply does not match. Do not "improve" one into `error:badarg`.
- `read_bits_le` is a thin delegation to `bits_match::read_little_endian_bits`; keep that single implementation, and keep it the exact inverse of the construction path's `bits::integer_le_image` (byte-wise, with the trailing partial field entering *above* the whole bytes).
- A **non-atom** raise reason is attached to the raise's live-reason slot by `finish` — the module's only terminal conversion, so every raise site is covered. A consumer that wants to *render* the reason must go through `crate::error::live_reason_term`; printing `BeamError`'s `Display` directly shows the `<structured reason>` placeholder.
