# `beam_rt::eval` — the `-eval` Erlang expression evaluator (`mod.rs` walker · `ast.rs` tree · `parse.rs` lexer/parser)

## Intent
The `-eval` evaluator (contract A.6): a lexer + Pratt parser (`parse.rs`) over an untyped AST (`ast.rs`) plus an `erl_eval`-style tree-walking evaluator (`mod.rs`) that `-eval Expr` runs.
It is driven by the CLI `-eval` action: `cli.rs::run`'s `Action::Eval(expr)` arm boots the runtime then calls `Runtime::eval` (`../runtime.rs`), which builds a `RuntimeContext` and calls `eval` here (`../runtime.rs::eval` → `crate::eval::eval`). `eval` is also re-exported at the crate root (`pub use crate::eval::eval;`) and in `prelude`.
Reused beyond the CLI: the evaluator's own closures can escape **into loaded modules** — `RuntimeContext::apply_fun` (`../context/mod.rs`, the `!External` fun arm) delegates a fun whose `uniq` is `EVAL_FUN_UNIQ` to `apply_eval_closure`, and the closure bodies live on `Runtime::eval_closures` (`Vec<Rc<FunBody>>`, so `lists:map(fun(X) -> X*X end, …)` applies one). `Runtime::eval` itself is used throughout the crate's tests as an expression/literal builder (e.g. `rt.eval("[call]")`).
The evaluator owns **no** term layout, arithmetic or printer: it dispatches down (`beam_term`/`beam_engine::terms`/`beam_bifs`) and inherits the lower crates' exact `erl` semantics.
**A BIF's container result outlives the call.** The evaluator runs with no scheduled process, so a registered BIF's result cannot be copied onto a process heap; `call_registered`'s copy-out therefore takes the table-less arm (`context/pool.rs::move_result_into_runtime_store`), copying a container result onto the runtime's pointer-stable `Runtime::eval_heap` (with any escaped payload adopted into `Runtime::eval_off_heap`) and only then rewinding the pooled BIF heap to that call's mark. So a term built by one sub-expression and read by a later one — `L = lists:seq(1,50), {hd(L), length(L)}` — is valid for the run's life, and repeated calls do not march the shared pool to its cap. The routes, the soundness argument, the measured trade and the `+hmax` capacity effect are in [`../context/CONTEXT.md`](../context/CONTEXT.md) and [`../context/IMPLEMENTATION.md`](../context/IMPLEMENTATION.md#the-table-less-arm-and-its-store); the oracle cross-check is [`../../tests/eval_pool_result.rs`](../../tests/eval_pool_result.rs).

## API Surface
### Entry points (`mod.rs`)
- `pub fn eval(ctx: &mut RuntimeContext<'_>, expr: &str) -> Result<Eterm>` — the crate-root-re-exported entry point: parses `expr`, tree-walks it in a fresh `Env`, and returns the value term on the process heap (valid for the runtime's lifetime). The whole driver runs inside `ctx.with_relocation_exempt(..)`, so an evaluation's Rust-local terms (the `Env`, reply terms) are never moved by a delivery-driven collection while the receive pump runs.
- `pub(crate) fn apply_eval_closure(ctx, fun, index, args) -> Result<Eterm>` — applies a stored evaluator closure by `index`, called from `RuntimeContext::apply_fun` when a loaded module applies a fun stamped `EVAL_FUN_UNIQ`. `BadArg` when no closure is stored at `index`.
- `pub(crate) const EVAL_FUN_UNIQ: u64 = 0x6265_616d_7274_0001` — the sentinel `uniq` stamped into every fun this evaluator builds, so such a fun is recognisable and resolvable.
- `pub(crate) struct FunBody { kind: FunKind, env: Env }` — a closure body (`FunKind::Local { name, clauses }` + its captured `env`), pushed onto `Runtime::eval_closures` by `register_fun`.
- `parse::parse(src) -> Result<Expr>` (`parse.rs`) and the AST (`ast.rs`) are reachable only inside this module (`mod ast; mod parse;` are private).
- Internal to `mod.rs`: `Evaluator` (the walker), `Flow { Raise{class,reason,origin,head}, Fatal }` + `EResult`/`Env`, `finish` (the module's **only** terminal conversion of a `Flow::Raise` into a `BeamError`; it attaches a non-atom reason to the raise's live-reason slot), the `BitBuf` MSB-first binary builder, and `operator_bif`/`read_bits_be`/`read_bits_le`/`sign_extend`/`mask_bits`/`trim_digits`/`integer_segment_is_little` helpers.

### Grammar coverage (`parse.rs` + `ast.rs`)
The **expression** subset of Erlang (`erl_eval`'s input) with Erlang's exact precedence/associativity (`binop_of`'s binding powers mirror `erl_parse.yrl`; `catch` lowest, then `=`/`!`, `orelse`, `andalso`, the comparison family, `++`/`--`, additive, multiplicative, then prefix operators):
- literals in every base (`Base#Digits`, radix 2..=36), floats (with exponent), atoms (bare and quoted), strings, chars (`$a`, escapes incl. `\xHH`, `\x{…}`, octal, the named escapes), lists (incl. improper `[1,2|3]`), tuples, maps, binaries;
- variables (`X`, `_`, `_Name`) and `Pattern = Expr` matching;
- `case`/`if`/`begin`/`try`/`catch`/`receive`;
- `fun`s (anonymous `fun(…)->…end`, named self-recursive `fun F(…)->…end`, captured `fun f/A` / `fun M:F/A`);
- list, map and binary comprehensions (with `<-` generators, `<=` binary generators, and filters), incl. the `<<…>>` template form the parser records as a single segment;
- prefix/postfix call application: an auto-imported local call `f(Args)`, a remote call `m:f(Args)`, and a call of a fun-valued expression `(fun…end)(Args)`.
A trailing `.` is tolerated by the parser, and the CLI strips one (`cli.rs::strip_trailing_dot`).
The lexer keeps **quoted** atoms distinct from bare words: `'case'` is a `Tok::QuotedAtom` while `case` is a `Tok::Atom`, mirroring OTP's scanner (`erl_scan:string("case")` → `{'case',1}`, `erl_scan:string("'case'")` → `{atom,1,'case'}`).
A quoted atom is **always** an atom — never a keyword, never an infix operator and never a variable — so `is_atom`/`eat_atom`/`expect_atom` (the `of`/`end`/`when`/`after`/`catch` guards and `parse_prefix`'s `not`/`bnot`/`catch`) and `binop_of` match only the bare variant, while `expect_atom_name` (a function/module name after `:` and the names in `fun M:F/A`) accepts both.
`'when'`, `'of'`, `'end'`, `'case'`, `'receive'`, `'fun'`, `'begin'`, `'try'`, `'after'`, `'catch'` and `'not'` therefore parse as plain `Expr::Atom`s in every position (primary, argument, tuple element, map key, clause pattern/body, comprehension element), and a quoted atom is not a terminator (`'end'`/`'of'` do not close a `case`).
A quoted *call head* is always a function call: `after_atom(…, quoted = true)` emits `Expr::Remote("erlang", Name, Args)` (an auto-imported local call is exactly `erlang:Name/Arity`), so `'abs'(-1)` is still `erlang:abs/1` and `'Foo'(1)` reaches the oracle's `undef` instead of a fun-valued-variable `variable "Foo" is unbound`.
`fun 'foo'/0` and `fun 'erlang':'+'/2` stay fun references, while `fun 'foo'(X) -> X end` is a syntax error (Erlang requires the named-fun form's name to be a *variable*), and out-of-grammar `1 'and' 2` is the typed capability gap it is on the oracle (a syntax error), never `1 and 2`.
Integers are exact up to `i128`; a literal past `i128` is a typed capability gap.
The binary-segment parse modes (`in_segment` for `/` as a type specifier rather than division, `no_remote` for a `try` clause's `Class:Reason` head) are the parser's two context flags.
Semantics inherited from the lower crates (nothing re-implemented): arithmetic/comparison/bit operators are **`erlang` BIFs** dispatched through `RuntimeContext::call_bif` (so `1/0` ⇒ `error:badarith` and the six bit operators get their bignum semantics); a call is a `call_bif` (the load-on-demand stdlib path); terms are built through `beam_engine::terms`/`beam_codec::term`; terms are inspected only through `beam_term`/`beam_engine::terms`. The operators the `beam_bifs` surface deliberately does **not** own — `and`/`or`/`xor`/`not`/`andalso`/`orelse` (Erlang special forms) and `++`/`--` — are implemented here with the oracle's error behaviour (`not 5` ⇒ `error:badarg`). The raise helpers (`error/1,2`, `exit/1`, `throw/1`, `nif_error/1,2`) and `apply/2,3` are served here so a **live reason term** survives (the atom-only `beam_common::ExitReason` cannot carry one); an unresolved call target additionally yields a raise carrying the synthesized **callee head trace item** (`Flow::Raise.head`). `erlang:raise/3` is deliberately **not** served here: it must validate its class *and* its stacktrace argument and forward the decoded trace, so the call falls through to the registered `beam_bifs::convert::raise_3` BIF (an invalid shape is that BIF's **returned** `badarg` atom — a value, never a raise — and a valid one raises with the decoded `StackTrace` attached).

### Binary segments (`<<…>>`) — construction and pattern matching
Both directions are implemented and oracle-cross-checked; the pure bit work lives in three sibling modules so `mod.rs` does not carry it (`bits.rs` = construction encoders, `bits_decode.rs` = field decoders, `bits_match.rs` = the little-endian match reader).
- **Construction, integers** (`Evaluator::append_segment` + `bits::integer_le_image`): a segment of **any** width from a small int or an exact bignum, in two's complement, big- or little-endian (`native` is little-endian here) — `little` is laid out **byte-wise**: the `n_bits / 8` whole bytes least-significant first, then the value's next byte's **low** `n_bits % 8` bits pushed into the high bits of the final partial byte (`<<-300:12/little>>` = `<<212,14:4>>`, `<<255:12/little>>` = `<<255,0:4>>`).
- **Construction, `float`**: `:16`/`:32`/`:64` (default `64`), either endianness, the value rounded half-to-even (`bits::f64_to_f16`/`f64_to_f32_bits`/`float_bytes`); an integer value is accepted and converted (`<<(1 bsl 64):64/float>>` = 2^64 as a double); `signed` is accepted and ignored.
- **Construction, utf**: `utf8`/`utf16`/`utf32` from a code-point integer, an astral code point becoming a surrogate pair and `utf16-little` swapping **each 2-byte unit**; a lone surrogate, a code point past `16#10FFFF` or a negative value is `error:badarg`, exactly as on the oracle.
- **Pattern matching** (`Evaluator::match_binary_segments` + `bits_decode.rs` + `bits_match.rs`): integer segments of **any** width (exact; `signed` sign-extends within the segment width; a value past the 60-bit small range is a real bignum, never `system_limit`), `float` (`:16`/`:32`/`:64`, default `64`), and `utf8`/`utf16`/`utf32` (consuming 1–4 bytes / 2 or 4 bytes / 4 bytes).
- **The absolute rule:** an invalid, truncated or out-of-range pattern field is a **match failure** (`Ok(None)` → `false`), never a raise — a malformed UTF sequence, a lone surrogate, a value past `16#10FFFF`, a float width ∉ {16,32,64} and fewer bits than the segment needs all simply do not match.
A `<<…>>` pattern must consume the subject exactly, so `case <<255,…,255>> (9 bytes) of <<A:65>> -> A end` is `case_clause` (65 of 72 bits), not a gap.
- **A literal string is one segment per character**, expanded in the parser (`parse::parse_segment_expanded`), so construction, matching and the comprehensions all see one shape: `<<"abc">>` is three 8-bit integer segments, and a utf-typed or sized string keeps its kind/size per character (`<<"abc"/utf16>>` = `<<0,97,0,98,0,99>>`, `<<"abc":16>>` = `<<0,97,0,98,0,99>>`). A *variable* holding a list with a utf kind stays the oracle's `error:badarg`.

### Capability gap (anything outside the grammar)
Everything outside the grammar is a typed capability gap: the parser (and a few evaluator arms) raise a `BeamError` built by `crate::error::bad_eval`/`error::unsupported`, whose reason atom starts with `unsupported` (the `unsupported:` convention). `Evaluator::flow_from_error` turns it into `Flow::Fatal`, so a raise from the evaluated expression's own `try … catch` cannot swallow it — it propagates out and the CLI exits **3** with one `beam_rt: unsupported: <reason>` line (`crate::error::unsupported_reason` is the single classifier). `erlang:halt/0,1` is likewise `Flow::Fatal` (uncatchable), so `… halt(0) catch … end` terminates with status 0. Genuine `error`/`exit`/`throw` raises (and BIF structured reasons like `{badmap,M}`, `{badkey,K}`, `{case_clause,V}`, `{bad_generator,X}`) stay fully catchable, with their live reason term preserved.

## Constraints
- **`unsafe`-free**: the crate is `#![deny(unsafe_code)]`; this node contains no `unsafe` (term layout is never touched here).
- **Return-based errors, no silent swallowing** (`../CONTEXT.md` §3): the public entry points return `beam_common::Result`; the internal walker carries its own `Flow` signal, converted once by `finish`. No crate-local error enum, no `panic!`/`unwrap()` on runtime data.
- **Call down, never duplicate**: arithmetic/comparison/bit operators and every call go through `RuntimeContext::call_bif` (the `beam_bifs` `erlang` registry / load-on-demand stdlib); terms are built/inspected only through `beam_term` (+ `beam_engine::terms` / `beam_codec::term`); the `~w`/`~p` printer is not re-implemented here.
- **`Flow::Fatal` is the uncatchable channel** (halt + capability gap); only `BeamError::Raise` becomes a catchable `Flow::Raise`.
- Files ~1000 lines: `mod.rs` is one cohesive unit (the `Evaluator`, the entry points and the `#[cfg(test)]` suite); `ast.rs`/`parse.rs` are the tree and the lexer/parser, and the bit-string machinery is three further files (`bits.rs`, `bits_decode.rs`, `bits_match.rs`) split by direction — construction / field decode / match read — rather than growing `mod.rs`.

## Known Issues (typed capability gaps — never wrong results)
- `receive` **without** an `after` clause is a typed `unsupported` when nothing runnable can deliver: with no window to bound a wait on, nothing more can be done. With `after T` the evaluator scans the running process's **real mailbox**, pumps the scheduler (bounded by `RECEIVE_PUMP_SLICES = 64`), takes one port-poller pass, and spends the remaining time on the runtime's **timer heap** (`Runtime::wait_for_timer` — sleep to the earliest pending deadline, or the window end, then one bounded pass), so `spawn(fun() -> Self ! hello end), receive M -> M after 1000 -> …` works end to end and a due `erlang:send_after/3`/`timer:apply_after/4` deadline fires and delivers inside the window. A bare `receive` **inside a spawned process** is also `unsupported` (it runs inside a scheduler slice and may not re-enter the scheduler), and `receive … after infinity` maps to `infinity`'s "block forever" as a typed gap.
- `catch Expr` folds **by class**, exactly like `erl_eval`: `throw` yields the reason, `exit` yields `{'EXIT', Reason}`, and `error` yields `{'EXIT', {Reason, Stacktrace}}` — always a 2-tuple, even for a non-atom reason. A `try … catch Class:Reason:Stacktrace` clause's third pattern is matched against the same cooked trace. `Evaluator::cook_supplied_trace` renders it from two sources, innermost first: the raise's **synthesized callee head item** (`Flow::Raise.head`) and the supplied `erlang:raise/3` frames through `beam_engine::encode_supplied_stacktrace` (a clone of the shared `AtomTable` as the atom source).
- **An `undef` carries the missing callee's head item.** When an unresolved call target makes `CallBif` answer the bare `error:undef`, the evaluator's own call site (`Evaluator::call` / `apply_value`) synthesizes `{TargetModule, TargetFunction, ArgList, Location}`, with the call's **real** evaluated argument list and `Location = []` (the callee does not exist, so there is no source position) — the same item the engine's compiled-code path builds (`beam_engine::families::exceptions::callee`) and the one OTP's `logger_server:call_h/4` matches on. It is built only from that site's own callee identity and arguments; **no `erl_eval`/`init` frame is fabricated** (there is no `erl_eval` port here), so the walker's cooked trace is the head item followed by `[]`. `/2`'s fun form contributes the item only for an **external** `fun m:f/A` (a local/imported fun's term carries no module to name). `is_unresolved_undef`-style gating: only the bare `undef` — class `error` with the reason **atom** `undef` — and only when no head item is present yet, so a re-raise through a non-matching `try` keeps it. A raise carrying no head item and no supplied trace (`erlang:error/1`, an arithmetic error) renders an **empty** trace, because the tree-walker gathers none beyond the head item.
- A **utf pattern segment carrying an explicit `:Size`/`unit:`** is a typed `unsupported`: the oracle rejects such a segment *syntactically* (`<<C:8/utf8>>` is a syntax error), so no differential case can exist and no value may be fabricated.
- A **non-final unsized** `binary`/`bitstring` pattern segment is a typed `unsupported` (Erlang requires such a segment to be last).
- The `-eval` CLI action's own uncaught raise is still printed through `BeamError`'s `Display`, so its stderr keeps the `<structured reason>` placeholder even though `finish` now populates the live-reason slot — that action arm does not go through `cli.rs`'s `reported_reason` (`src/cli.rs`, `Action::Eval`/`Apply`/`Run`; owner: the `beam_rt` CLI node, also recorded in `../M1_GAPS.md`). The slot itself IS live: a **process** that dies of an evaluator `{case_clause,V}` renders the real term through `runner/reason.rs::exit_reason`, and every catch site already had the term.
- A non-empty list's clause `apply_closure` with no matching arity is `BadArity`.
- `erlang:alias/0`, NIF/driver dispatch, `open_port` and every other host facility behave as the lower crates specify — this node only *calls* them.

## Routing Table

- `ast.rs` → the untyped AST: `Expr` (used for both expressions and patterns) plus `BinOp`/`UnOp`/`Seg`/`SegKind`/`Endian`/`Clause`/`CatchClause`/`FunClause`/`Try`/`Receive`/`Qual`/`MapField` and `is_var_name`.
- `bits.rs` → the **construction** encoders (`integer_le_image`, `float_bytes`/`f64_to_f16`/`f64_to_f32_bits`, `utf16_bytes`/`utf32_bytes`/`utf_segment_has_width`) — pure functions, no evaluator, heap or runtime error type.
- `bits_decode.rs` → the **pattern** field decoders (`decode_float` b16/b32/b64, `decode_utf8`/`decode_utf16`/`decode_utf32` → code point + bits consumed, `read_integer_limbs` of any width) — `None` on any invalid/truncated/unrepresentable field (always a match failure at the call site), pure functions, no evaluator or heap.

- `parse.rs` → the `Lexer` (`Tok::Atom` for a bare word/keyword vs `Tok::QuotedAtom` for a quoted atom, all bases, floats, strings/chars + escapes, comments), the Pratt `Parser` (`parse`, the `in_segment`/`no_remote` context flags, all control forms), the string-literal binary-segment expansion (`parse_segment_expanded`), plus the colocated unit suite.

## Notes for Agents
### The evaluation-order contract (sub-expressions run in `erl_eval`'s order)
The evaluator evaluates a construct's sub-expressions **left-to-right in source order**, exactly as `erl_eval` does:
- a **list**'s elements left-to-right, **then** its optional tail;
- a **tuple**'s elements left-to-right;
- a **map field**'s key before its value, with fields in source order;
- a **binary segment**'s value before its size;
- **call** arguments in order; `++`/`--` left operand before right;
- a **comprehension**'s template once per generated element in generator order.
Order is observable only through a side effect (an `io:format/2` in an element), so it is pinned by the spy-closure probes in `mod.rs::tests::literals_evaluate_their_sub_expressions_in_source_order` and in `../../tests/eval_order.rs` (the latter cross-checks the **system `erl`** prints the same bytes).
The list's **cons chain** is only *built* right-to-left after the values are already evaluated (`Evaluator::list` collects the element values, then folds them onto the tail) — this does not change the list's *value*, only the order the side effects ran in. Do not describe the current order as "right-to-left".
### Other facts
- The evaluator keeps its environment in Rust locals, so its terms are **not** in a collection's root set; the whole `eval` driver therefore runs under `RuntimeContext::with_relocation_exempt` (see `../context/CONTEXT.md`), which is exactly when a reply to this pid could arrive.
- A fun built here is recorded in `Runtime::eval_closures` and can escape into a loaded module; `fun M:F/A` is **not** a closure — it is the real `EXPORT_EXT` term (no `uniq`), applied through the host's ordinary dynamic call.
- `../CONTEXT.md` (this crate) describes the CLI surface and exit codes; `../runtime/CONTEXT.md` owns `Runtime::eval`/`eval_closures`; `../context/CONTEXT.md` documents `apply_fun`'s dispatch to `apply_eval_closure`.

### Bit-string invariants
- A `<<…>>` **pattern** failure is `Ok(None)`/`false`, never a raise: Erlang's rule is that an unreadable field (wrong width, too few bits, malformed UTF, out of range) simply does not match. Do not "improve" one into `error:badarg`.
- `read_bits_le` is a thin delegation to `bits_match::read_little_endian_bits`; keep that single implementation, and keep it the exact inverse of the construction path's `bits::integer_le_image` (byte-wise, with the trailing partial field entering *above* the whole bytes).
- A **non-atom** raise reason is attached to the raise's live-reason slot by `finish` — the module's only terminal conversion, so every raise site is covered. A consumer that wants to *render* the reason must go through `crate::error::live_reason_term`; printing `BeamError`'s `Display` directly shows the `<structured reason>` placeholder.
