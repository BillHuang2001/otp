# `beam_rt::context` — implementation detail (dispatch, tables, GC-relocation seam)
Mechanics-level companion to [`CONTEXT.md`](CONTEXT.md), which keeps the Intent, API Surface, Constraints and Routing Table.
This file holds the per-concern detail that is not tied to one subsystem: the root-set/relocation seams, the at-risk roster, the in-machine execution-position door, the in-machine call/fun seams, the send-destination/alias mechanics, the per-call cost of a registered call, the closable host-seam roster and the A.9 compile sweep.
The subsystem detail lives in the four children — [`calls/CONTEXT.md`](calls/CONTEXT.md) (dispatch · bridges · interners), [`gc/CONTEXT.md`](gc/CONTEXT.md) (heap doors · valves · off-heap prunes), [`pool/CONTEXT.md`](pool/CONTEXT.md) (the BIF-result copy-out and the term stores) and [`pump/CONTEXT.md`](pump/CONTEXT.md) (the nested-run pump, the machine pool, host memory) — and every pinned heading below keeps its summary here with a pointer where the body moved.

### The pooled BIF-heap frontier — `take_bif_frontier`
Both pool-consuming call sites (`call_registered`, `try_call_nif`) take their allocation frontier through `take_bif_frontier` rather than `Runtime::take_bif_heap` directly, because the pool is shared and the region handed back may be nearly exhausted (`available() < capacity() / BIF_HEAP_GROWTH_DIVISOR`, 16).
Growth is by **region replacement** — never relocation, never a retry: the exhausted region is pushed back and a fresh, larger one becomes this call's frontier before the bump, doubled (`saturating_mul(2)`), doubled from the region's **own** capacity (no `Runtime::bif_heap_words` floor) and capped by a configured `+hmax`.
Detail: [`pool/CONTEXT.md`](pool/CONTEXT.md).

### The table-less arm and its store
`RuntimeContext`'s copy-out has **two** destinations, chosen by who is running (`calls.rs::rehome_container_result`): a scheduled process gets the result on its own **scanned** young heap (`move_result_into_process_heap`), while the **table-less** route (the `-eval` evaluator, `-s`/`-run` and every single-pass `run_*` entry) copies it onto the runtime's long-lived `Runtime::eval_heap` + `Runtime::eval_off_heap` store (`pool.rs::move_result_into_runtime_store`).
That store grows by **region retirement** (`Runtime::grow_eval_heap`), so the rewind it licenses is sound only for a `safe_to_rewind` call that succeeded, and a reference-holding graph is neither moved nor rewound; the regions it retires are reclaimed by `src/runtime/reclaim.rs` alone, at the two sites where nothing is executing (the `-eval` statement boundary and the driver exit), where a whole-dead region is dropped and a partially live one is evacuated into one fresh region with every root rewritten.
The copy, the rewind's soundness argument, the growth/refusal rules and the measured counter deltas: [`pool/CONTEXT.md`](pool/CONTEXT.md).

### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity)` is the **only** producer of a registered call's dispatch answer: a direct-mapped per-context memo of `DISPATCH_MEMO_SLOTS = 128` slots, each an inline `Option<Box<DispatchEntry>>` holding `{bif: Option<BifFn>, hooks: DispatchHooks}`, so a fresh per-applied-fun context carries ~1 KiB of `None` slots and allocates a box only on a miss.
`hooks` is `DispatchHooks(u16)` — **one bit per `uses_*` predicate**, so no predicate runs per call and the whole answer (16 bytes) crosses the call boundaries in registers; a one-entry MRU hint sits in front of the slot hash and answers only after full field-for-field key equality; `bif` is the `BifRegistry` lookup the caller then invokes **directly**.
The one mutable input — the **NIF registry** — is deliberately not memoized (`call_bif` runs `try_call_nif` first on every call), so a cached answer can never go stale.
Slot hash, the miss/collision rules, hit/miss cost and the measured figures: [`calls/CONTEXT.md`](calls/CONTEXT.md#the-dispatch-memo--dispatchhooks); the pinned summary is [`CONTEXT.md`](CONTEXT.md#the-dispatch-memo--dispatchhooks).

## Closable host-seam keys (`runtime_hooks.rs`)

### Relocation exemption (the cross-crate GC correctness seam)
`with_relocation_exempt<T>(&mut self, f: impl FnOnce(&mut Self) -> Result<T>) -> Result<T>` runs `f` with the context's process (`self.mailbox_pid`) marked relocation-exempt through `ProcessTable::{is,set}_relocation_exempt`, so a delivery-driven `Process::deliver` collect can never recycle words this crate holds **outside** the process's own containers (Rust-local term handles, an unpublished `Machine`); it is **nested-safe** (it saves the previous mark, sets `true`, restores on every path — `TermNotFound` on the save means "no process", so nothing is exempted — and the closure's error wins).
Wrapped scopes (exactly five): `crate::eval::eval` (the whole `-eval` driver body), `run_export_blocking`, `run_label_blocking`, `apply_fun` (the `-eval`-closure arm) and `deliver_message_with_off_heap` (exempting the **sending** context's own pid, so a self-send whose payload does not fit routes to the heap-fragment fallback; a delivery to a *different* process is unaffected).
The **scheduled slice is deliberately not wrapped**: the runner drives its own outcome entry points directly, publishes parked roots, and its armed admission point (`ensure_heap`/`ensure_heap_full`) stays the legitimate collection site ([`../../DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md)).
Separately, the runner opens its **own per-slice exemption** for a process whose FR prefix is live when a slice ends: `RuntimeRunner::run` marks the process relocation-exempt when `Machine::fr_mark() > 0` (`src/runner/run.rs` `process.set_relocation_exempt(true)`) and the next slice entry clears it (`set_relocation_exempt(pid, false)`), so the inter-slice window (where a delivery-driven collect could otherwise recycle a live float word) is guarded while a running slice collects normally — a bounded, decline-only guard, so `Runtime::gc_stats().pinned` stays 0 and a float-using loop's `collections` scale with N. The narrow door's caller-module float guard is a separate, in-slice concern (see [`CONTEXT.md`](CONTEXT.md) *Known Issues*).
The two other nested-`Machine` sites (`boot::drive::apply_boot_call`, `native::file_server::EngineContinuation::call`) are safe *only* on a `RuntimeContext::new` context (`mailbox_table == None`, which forces every allocation onto the pointer-stable arena); moving either onto a `for_process*` context would make it a delivery-collect hole for a mid-run process.
`deliver_in_table(runtime, table, to, from, message) -> Result<()>` is the pass-boundary entry to the same `deliver_message` semantics for the runtime's own delivery steps (used by `Runtime::service_file_requests`, `deliver_port_messages`, `fire_due_timers` and `drain_ets_owner_exits`); its context's pid is the **receiver**, so the copy's source is `send_source(None, …)` → `Runtime::off_heap_source`, and an exempt receiver's raw `Alloc(AllocKind::Message)` refusal routes to `send_fragmented_message_after_refusal`'s heap-fragment fallback — spending the refusal's own exact price, so nothing is re-priced — instead of propagating.
### What a MOVING engine heap would invalidate — the at-risk roster
`Process::regs` is a snapshot, not a live mirror: `publish_roots_full`/`scatter_roots_full` (`gc.rs`) copy the x file's **pointer-bearing prefix** and the whole stack into it (FR words after the stack words, bounded by `fr_count` — `beam_process::Registers` has no FR container) at every full-root admission point (`gc::ensure_heap_full`/`alloc_words_rooted`, bound `gc.rs::machine_root_bounds`) or at a **publishing** (non-exempt) park (`../runner/run.rs::publish_parked_roots`: live prefix `Machine::fr_mark()`, recorded on `ProcessEngine::fr_published` for the resume, plus the parked machine's live `pending_exception` as an `extra_roots` word).
An **exempt** park publishes nothing (the parked machine stays authoritative), so between those points the snapshot is stale by up to one slice; the engine's `live` count is ignored (over-approximating a copying collector's root set is always safe).
A parked machine's `pending_exception` is read back on the resume (`RuntimeContext::resync_parked_roots(pid, machine, fr_count)`); an exempt park publishes and re-syncs nothing, and the parked window carries the exemption, so that publication is never licence for a park-window collection.
The post-slice pin scan (`../runner/run.rs`) reads `Machine::fr_mark()` once per slice, pins the pid iff it is `> 0`, and passes the same count to the park as its `fr_count`; a pinned (exempt) park publishes nothing and the parked machine keeps its own live FR prefix, so no live FR term is lost.
Still outside the root set: `Raise::live_reason`'s reason term between the raise and its stabilization (`try_stabilize_escaped`, `../runner/run.rs:662`).
* At risk (a raw `Eterm` outside the root set): `Runtime::persistent_terms` (`persistent_term.rs`), `Runtime::trace`'s `MatchSpec::Functions`, `Runtime::seq_trace`'s `Token{label,from}`, `Runtime::eval_closures` `FunBody.env`, `Runtime::timers` `TimerAction::Deliver`; `NameSpec.inline_options` needs a check (`MailboxState.markers[].reference` is a reference, not a heap term).
A spawn argument or entry fun (`ProcessEngine.args`/`entry:Fun{fun}`, `PendingSpawn.args`) and a stored escape-store term also sit outside those roots, but each opens the descent latch (`note_spawn_foreign_roots`, `note_escaped_store_roots`).
Safe: `RunnerState.exits`/`results` (a stabilized `eval_heap` copy), `references`/`Timers.refs` keys, ETS (own arena), `RuntimeContext` (no `Eterm` field), the `dist`/`port` structs, `PortMeta`.
* Envelope/retained payloads: `Process::run_rooted_collection` (`beam_process/src/process.rs:1166-1240`) roots each queued message's `payload`, `from` and `token` and re-installs all three (`set_from`/`set_token`/`with_payload`), so a heap `from`/`token` relocates too; the envelope's `off_heap`/`binaries`/`nodes` families and `MailboxState::remove_at`'s retained copies are refcounted Rust handles (not young-heap `Eterm` words), so a moving heap can neither move nor dangle them, and `with_payload` carries the `Fragments` chain across.
`beam_process`'s `deliver_down_message` sets `Message.from` to the target pid's `to_eterm()` (an immediate) and carries the named monitor's `{Name,Node}` in the body, so `run_rooted_collection` relocates it with the payload.
* The arena allocation source: `Runtime::alloc_words` (`../runtime.rs`→`self.arena`), the **refusal-only** fallback this node's `alloc_words` reaches after a young-heap refusal and `grow_nursery`, and the home of a genuinely **table-less** context; also reached by `../runner/budget.rs`'s forwarded `alloc_words`, by `alloc_words_rooted`'s own no-table/no-call-site/disabled-pid refusals, and by `Runtime::materialize`/`charlist`; mailbox `Queue` payloads are copied in by `copy_struct`.
  `alloc_words_rooted`'s `armed == false` arm is deliberately **not** one of those: a nested run re-entered from a scheduled slice keeps the pass's `ProcessTable` and drops only the latch, so that arm delegates to `alloc_words` and builds on the running process's **scanned** young heap.
  The reason the distinction matters: a container in the arena is `Target::Foreign` to `beam_gc`'s copier — left verbatim and **never descended** — so its young-heap children would be relocated out from under it.
* The collect triggers and their refusals. The admission-point collection *is* the publish/collect/scatter hand-off (safe).
The delivery-driven (`Process::deliver`→`ensure_capacity`→`run_rooted_collection` over `self.regs`) and signal-driven ones (`ptab.rs`'s `terminate_with_ports`→…→`grow_receiver_for_signal`→`ensure_capacity`) fire outside admission and are refused for a receiver with unpublished roots: `Process::has_unpublished_roots()` (= `relocation_exempt || state == Running`, `beam_process/src/process.rs:1098`) is tested *first* by every caller, so a refused delivery becomes a heap-fragment delivery and a refused ptab signal goes to `enqueue_fragment_signal`.
`beam_rt` adds a second refusal (`RuntimeContext::deliver_message_with_off_heap_inner` asks `delivery_collection_is_unsound` and marks the receiver exempt on `true`) — the fifth collection site — and every send routes through `deliver_message_with_off_heap` (`src/context/mod.rs:590`), marking the sender's own pid exempt.
A signal to a running process is deferred; to a parked one, declined by the park-window exemption; to a woken-but-not-yet-resumed (`Runnable`) receiver — the A.9 `selfhost/*` class — declined by the host collection gate every `ptab.rs` signal site asks (OR-ed with `has_unpublished_roots`) before *collecting* `ensure_capacity`: `RuntimeCollectionGate` (`gc_walk.rs`, the admission-point valve's roots-incompleteness walk over the runtime's shared per-pid latch cell, so a clear bit is an O(1) `false`), installed in `Runtime::new`.
The `Yield` arm, the third out-of-admission trigger, is exempt exactly when its slice ended with a live FR prefix (`fr_count > 0`): an **exempt** park publishes nothing and its `Runtime::serve_gc_request` is declined by the exemption it just set, while every other park — a dead-FR `Wait` park included — publishes first, then serves.
### The unscanned-root valve — two phases
At each of the five collection sites the valve **declines** (`Ok(())`) any collection whose roots — or process-side scanned graph — reach a foreign container **that forwards a word the collector would follow or update**; a foreign container forwarding **nothing scanned** is inert, and the per-pid descent latch is **not** sticky (opened on a hazard, closed only by the three whole-root doors, never by a site handing over less than the whole root set).
A decline costs a collection and nothing else (the allocation falls back to the pointer-stable arena); the two phases, the five sites and `note_gc_fallback`: [`gc/CONTEXT.md`](gc/CONTEXT.md).

### The nested blocking pump and its bounds
`run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver, one `pump_once` round per wait.
For an ordinary (no-deadline) parking, `pump_once` first asks whether a live port's driver still holds **one of its own asynchronous operations** (`Runtime::ports_awaiting_async` ← `PortRegistry::awaits_async_completion` ← `beam_io::Driver::has_pending_async`): if so the wait is `wait_for_port_event`, otherwise it advances the scheduler by `RUN_EXPORT_PUMP_SLICES` (64) slices through `Runtime::pump_scheduler_boot` — the **imminent-only** wait policy, so a round whose only pending deadline is far out returns unslept instead of stalling the caller — and a pump reporting that nothing ran ends the drive with the honest `beam_engine::blocked()` gap.
`wait_for_port_event` is the socket half: a passive `gen_tcp:recv/2,3`, an `accept` and a datagram read are answered by a `{inet_async, …}` only a later port round can produce, so the round is `Runtime::pump_scheduler` (the pass's blocking policy — it really waits in the poller) and a resume re-scans the mailbox at the reported `(func, pc)`.
Its bound is `crate::port::PORT_EVENT_DEADLINE` (5 s, the read's analogue of `busy_wait::BUSY_PORT_DEADLINE`), a window over **consecutive** rounds without progress that `crate::port::restart_port_event_window` re-arms on every round that made some, so a workload whose completions keep arriving is never cut short while a port that never answers reports `PORT_EVENT_DEADLINE_REASON` (exit 3) instead of hanging the single-threaded runtime — the outer `BLOCKING_PUMP_DEADLINE` still caps a peer that stays runnable for ever.
A round is progress when any of three signals moves, and each is necessary: the pass **executed a slice**; the pass **delivered a port message** (`Runtime::port_events_delivered`, the monotone count `Runtime::deliver_port_messages` bumps at its one site) — the one the other two are blind to, because the completion is delivered by the port half in a round that ran no slice and a nested machine is not in the run queue; or **no live port still holds an asynchronous operation** (`Runtime::ports_awaiting_async`), the "nobody could answer me any more" gate, which keeps its exact meaning because a listener's standing accept interest legitimately keeps it true.
The wait arms, latches and consumes nothing — the operation was queued once by the machine's own control call and a resume only re-scans — so a re-park waits on the same operation rather than issuing a second one (a second `TCP_REQ_RECV` would be the driver's `ealready`).
The same three signals and the same window rule are on the `-eval` tree-walker's bounded bare-`receive` branch (`../eval/mod.rs`).
The engine arms no timer for a `wait_timeout` and a nested run is not a scheduled process, so for a statically readable finite `after T` `pump_once` recovers the deadline through `Machine::wait_deadline` and, on an empty run queue, sleeps `min(remaining, DEADLINE_PUMP_SLEEP)` (5 ms) and re-pumps until the wall clock reaches `start + T`, then resumes at the `timeout` continuation (a message arriving first wins).
The loop ends on return, on a step reporting `Ok(None)`, or at the `BLOCKING_PUMP_DEADLINE` (900 s) cap — the nested counterpart of the boot drive's `DRIVE_DEADLINE`, reported as a typed `error::message(...)` and sized to clear the heaviest legitimate workload on this route with headroom: an in-process compile of a real `lib/stdlib/src` module, whose measured `user` cost reaches ≈ 155 s (`qlc.erl`; wall up to ≈ 188 s on a loaded host) under the debug runtime.
That cap is the **only** bound on the ordinary slice-pumped wait: a forward-progress trip on `Machine::reductions` was considered and rejected as unsound, because the awaited machine's own counter says nothing about the process it waits on, so "re-scans its mailbox with ~0 charged reductions" is equally the signature of a legitimate busy peer (`gen_server:call` to a server computing for minutes) and would replace a result the oracle answers with this runtime's own error; a progress-gated bound that also required "the pump reported nothing ran" would never fire at all, since that *is* the loop's `Ok(None)` exit.
The `BLOCKING_PUMP_DEADLINE` path is exercised only through the injectable `limit`.
### The in-machine execution-position door — `position.rs`
A process's execution-position items (`process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel`) are read out of the `beam_engine::Machine` that owns its frame (see `../native/memory`).
The scheduler **takes the executing process's machine out** of `RunnerState` for the whole slice, so the runner-state view that answers *every other* pid cannot see the caller's own machine — the case `gen_server`'s `?STACKTRACE()` macro needs.
`beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine` seam (funnelled through `Machine::dispatch_bif_call` on **both** tiers) hands an opted-in host the live `&Machine` and the run's entry module on every BIF dispatch; `position.rs` opts in narrowly — `in_machine_probe` answers `true` (latched **once per run**) and `dispatch_in_machine` rejects every dispatch that is not an `erlang:process_info/1,2` with one string compare.
**Only** for such a query whose first argument **is** the executing process does it read the five machine-sourced values once (`machine_position`, against the run's entry module) and publish them in the runtime-owned slot `Runtime::in_machine` for the duration of the nested `call_bif`, clearing it immediately after.
The same slot publishes the machine's **off-heap roster** (`InMachinePosition::off_heap_binaries`, the reservoir's `(addr, size, refc)` triples) and it is filled **only when the query names `binary`**, so a query for any other item pays one name test and no roster read; `RuntimeContext::in_machine_off_heap_binaries` is its reader.
`../native/memory`'s `position_value`/`catchlevel_value` consult that slot first via `in_machine_value` (the published terms need no root set — no collection can run while a BIF call is in flight — so the window is exactly one nested `call_bif`), and its `snapshot` takes the published roster as the **reservoir half** of the `binary` item for that pid, falling back to `RunnerState::reservoir_at` for every other pid; one shared `binary_value` builder renders both, so the two paths cannot drift.
Everything else (another pid, a nested query while an outer door call is in flight, a pid-less argument, a name the machine does not source, a machine with no such position) falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated; both overrides live in `execution.rs`, and the runner's `BudgetContext` carries them onto the **scheduled** path.
### Per-call cost of a registered call
**`erlang:term_to_binary/1,2` and `erlang:binary_to_term/1,2` are dominated by two host costs, not the dispatch prologue.**
1. *Decode:* every `binary_to_term` reuses a per-thread scratch image of the live atom table, proven index-identical in **O(1)** through the append-only witness (`beam_term::AtomTable::snapshot`/`appended_since`), so the steady state reads **no** atom name; the index-by-index `prefix_matches` survives only as the fallback for a table the witness cannot vouch for (a replaced/cloned table, or a memo left ahead/behind). Both `beam_rt` decode hosts adopt it — the `../nif.rs` NIF/driver mirror (`with_decode_scratch`, measured on the booted table: **2 024** atoms, **0** name comparisons per steady-state decode where the blind walk read **2 024**) and the ordinary BIF path in the sibling `beam_bifs/src/binconv.rs`. `term_to_binary` (encode) never touches the scratch.
2. *Copy-out:* every container result (an encoded binary, a decoded map) is moved off the pooled BIF heap at the tail of `call_registered` (`move_container`: unconditionally on a process route, only when `safe_to_rewind` on the table-less one), by whichever re-home arm matches the route (`calls.rs::rehome_container_result`): `move_result_into_process_heap` for a scheduled process (onto its young heap) or `pool.rs::move_result_into_runtime_store` for the table-less route (onto `Runtime::eval_heap` — see [the table-less arm](#the-table-less-arm-and-its-store)). Both hand the copier a **fresh, empty, per-attempt** `OffHeapTable` as its destination so the single-traversal path is always taken, then adopt the local table's off-heap references into the runtime-lifetime `eval_off_heap` on success only (a refusal adopts nothing) — one family at a time and only for a family whose list holds an entry, so a result with no off-heap reference pays three emptiness tests and no drain; a result the destination cannot hold pays one `grow_nursery` (process arm) or one `grow_eval_heap` (store arm) — sized from the copier's own preflight shortfall, so no extra graph walk — and one second single-traversal attempt, while a permanent refusal returns `None` without growing.
The **process** arm grows with headroom (`GROW_HEADROOM_FACTOR` × the shortfall, floored at `GROW_MIN_WORDS` = 1024 words, which the growth table rounds up to ≥1598) so one growth serves many copies of the same size instead of the next few refusing again — the C's own discipline of installing `next_heap_size(need, 0)` rather than the bare need (`erl_gc.c:1879-1888`); a `max_heap_size` ceiling that refuses the larger request falls back to the bare shortfall (`needed.max(256)`), so a reachable growth never becomes a failure.
### The learned copy-out hint — `copy_out_hint` + `hint_grow_gate` (the copy-bound fix)
The process arm is **hinted**: the largest graph this context has been refused for is remembered (`RuntimeContext::copy_out_hint`, learned from the copier's own shortfall) and a destination with fewer free words than the hint (plus a margin) is grown — through the NO-RELOCATION `Process::grow_nursery` — **before** the attempt, so a copy-bound loop does not pay a refusal's five-traversal sizing walk per op.
`hint == 0` (a context's first copy-out) is the unchanged grow-and-retry fallback.
Constants, the measurement narrative and the churn-shape schedule shift: [`pool/CONTEXT.md`](pool/CONTEXT.md).

### The pointer-bearing prefix bound of the full-root doors
Both in-slice heap-admission doors (`ensure_heap_full`, `alloc_words_rooted`) hand the executing machine's root set over at a **pointer-bearing-prefix bound** computed by `machine_root_bounds` → `pointer_prefix_len` (`gc.rs`): one past the last boxed-or-list word (`is_boxed(w) || is_list(w)`, i.e. `(w & TAG_PRIMARY_MASK) != TAG_PRIMARY_IMMED1`) of the `x` file and of the `fr` file, or `0` for a file of immediates.
The Erlang stack is always handed over whole.
The bound is a pure **work-skip** that cannot change a decision: an omitted word is an immediate, which no collection relocates and no reachability test reads (`root_is_unscanned` answers `false` for it), so the valve can never see a word the hand-off does not carry, and vice versa.
The FR file is bounded the same way and carries **no** float guard: `module_uses_floats` is deliberately **not** applied at these two doors, so a live float register is relocated like any other root and a float-using call site collects exactly like a float-free one.
The bound is computed **after** the occupancy/collection-debt/forced short-circuit in each door, so only an admission point that is actually committed to collecting pays for it.
### Debt/valve cost of the admission doors
Both heap-admission doors OR the occupancy test with the collector's collection debt, and each pays the valve's own descent on top; the aggregate widths per geometry, the two-tier scanned test's exact-predicate equivalence and the door-by-door cost table: [`gc/CONTEXT.md`](gc/CONTEXT.md).
### What the doors do NOT decide
The full-root doors decide **whether** a collection may run — each one's own short-circuit (occupancy/`collection_debt`/forced at the admission doors, the reduction interval and the 7/8 occupancy watermark at `gc/reds_door.rs`) — and never *what* is collected; the collection kind, the mature-generation policy and the heap sizing are `beam_gc`'s.
Which door sees which workload shape, and what a door cannot see: [`gc/CONTEXT.md`](gc/CONTEXT.md).

### The A.9 in-process-compile sweep
Measured on this host (`BEAM_RT_SWEEP_SHARD=0/6`…`5/6` in parallel): the oracle compiles **86 of the 96** `lib/stdlib/src/*.erl` sources.
The other 10 `-include` a header that does not sit in the source's own directory, which this option list (no `-I`) cannot resolve — an oracle-side limit, not this runtime's.
All 86 compile in-process **byte-identically**.
The sweep's body runs on a dedicated thread with a 32 MiB stack (`SWEEP_STACK_BYTES`), so the deepest sources compile exactly as they do on the real CLI route's ~8 MiB main thread; no environment stack variable is needed, and the thread's panic payload is re-raised with `std::panic::resume_unwind` so an assertion message survives the boundary.
### The node hash (A.2) — `node_hash.rs`
`term_to_binary(Term, [local])` must stamp the node's `LOCAL_EXT` (`121`) image, whose first four payload bytes are the VM's node hash; `beam_bifs`' `binconv.rs` (`encode_image`/`plain_image_of`) asks the `LocalNode` seam for it and, on `None`, returns the typed `unsupported_bif` gap ([`CONTEXT.md`](CONTEXT.md) *The node hash*).
The C computes it **once per VM start** in `erts_late_init_external` (`erts/emulator/beam/external.c`): a buffer of `time_offset(8 LE bytes) || hostname || pid-string` hashed by the Bob-Jenkins **block hash** seeded with `(Uint32)(mtime & 0xffffffff)`, stored in a `static Uint32 local_node_hash` — **per-start and node-local by design**, hence never byte-comparable across runtimes.
`node_hash.rs` reproduces that shape from real process/host state, self-contained under this node and stable for the whole OS process.
* `node_hash() -> u32` — the **one** value per OS process (`static HASH: OnceLock<u32>`), mixing `clock_nanos().to_le_bytes() || hostname() || std::process::id().to_string()` with the seed `clock_nanos() as u32`.
  `clock_nanos()` is the wall-clock reading in nanoseconds since the epoch (the C's monotonic clock is unreachable without a clock dependency, and a pre-epoch system clock only makes that field `0`, the hash still mixing host and pid).
* `hostname()` resolves from real host state with no new dependency: `/proc/sys/kernel/hostname`, then `HOSTNAME`, then `COMPUTERNAME`, else the empty string — the C's own answer when `sys_get_hostname` fails.
* `block_hash(bytes, seed) -> u32` is a self-contained port of the C's `erts_block_hash_init`/`erts_block_hash` (`erts/emulator/beam/erl_term_hashing.c`): 12-byte blocks, `HCONST = 0x9e3779b9`, the 9-round `MIX`, the buffer's full length added into `c`, the descending-shift tail fold, a final `MIX` answering `c`.
`NodeIdentity`'s `LocalNode::local_node_hash` returns `Some(node_hash())`; `beam_codec`'s `Encoder::finish_local(hash)` writes `[VERSION_MAGIC][LOCAL_EXT:121][hash:4 BE][body]`.
**A differential case covering `[local]` must MASK the four hash bytes** and compare the rest (the value differs per VM start on **both** runtimes); `../tools/differential` (read-only sibling) still records `[local]` as an honest gap — adding the case is theirs.

### The aliased `ets` copy-out in the tail
`call_registered`'s result tail reads the `ets` table-alias witness (`alias.get()`) before it looks at the result and splits three ways: an immediate/literal result is never copied, an aliased container is copied **unconditionally and before** `heap.reset_to(mark)` (a refused copy surfaces the typed `SystemLimit` rather than the un-copied term), and the non-aliased cascade is unchanged.

### The in-machine call and fun seams — `resolve_external_call` · `resolve_local_fun` · `resolve_local_call`
`resolve_external_call` returns `Some((arc, label))` only for an import runnable in the caller's machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It loads an uncached callee on demand (`find_module_file` + `code_server.load`) and returns `Ok(None)` — keeping the synchronous `call_bif` path byte-for-byte — for a floor-served name (`native::floor_shadows`, **key-granular**: `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label.
`callee_observes_its_call_site` is **module-wide** for `erlang:load_nif/2` and **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, which must stay synchronous so the function cannot park with an unpublished `Machine::pending_exception`; the seam **exempts a built-in NIF library** (`native::prim_tty::is_builtin_library`, A.7's `prim_*` family), which registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the gap.
A fun or external fun with **no in-machine entry** keeps the value-returning `apply_fun` fallback: an **external** fun (`fun M:F/A`) has no closure but its identity *is* the callee's `M:F/A`, so `external_fun_target` resolves it to that module's export label through this same seam, under the same refusals.
`local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure — `module` the code server's cached `Arc<Module>`, `label` the lambda's `FunT` entry label.
`imported_fun_target` gives a `NEW_FUN_EXT`-decoded closure (`FunKind::Imported`, the wire image `binary_to_term(term_to_binary(F))` produces) the same entry on the C's own key `(module, index, arity, uniq[16])`, `erl_fun.c::fun_cmp`: the term's module atom → the cached `Arc<Module>` (else an on-demand load), the image's 16-byte `uniq` required to equal `Module::checksum()` so a stale image never binds to a recompiled module's lambda, and `beam_term::fun::fun_local_key` supplying the `(old_uniq, index)` pair (`beam_asm.erl`'s `finalize_fun_table/2` stamps the 27-bit MD5 prefix into each `FunT` entry's `old_uniq`) that the descriptor search turns into the lambda's entry.
Both encodings converge on the private `closure_target`, which holds the arity guard, the served-local-stub decline and the free-vars-then-args layout **once**; its order is load-bearing — the **arity guard precedes the served-key decline** (a wrong argument count is `BadArity` whatever the descriptor names) and the served test precedes the one allocation.
An applied imported closure answers one of three classes: a **genuine** descriptor (an `(old_uniq, index)` pair naming a real `FunT` entry of a module whose `checksum()` equals the image's `uniq`) applies normally; an identity naming **no lambda** of a loaded module is the C's `EXC_BADFUN` — this seam answers `beam_engine::error::bad_fun` and the engine's `raise_badfun` expands it into the oracle's `{badfun, F}` (`beam_common.c:750-772`), which must be the engine's half because the fun reaches the seam as a bare `Eterm` that cannot be held across the tuple's allocation; a fun whose module atom has **no loadable code** is `error:undef` whose reason is the bare atom and whose innermost cooked-stacktrace item is the applied fun — this seam answers `beam_engine::error::undefined_lambda` and `call_fun`'s `raise_bif_error_with_head` cooks the `{Fun, ArgList, []}` item.
Both markers carry a `()` live-reason payload, so `is_bad_fun`/`is_undefined_lambda` are typed discriminators and a **user** `erlang:error(badfun)`/`error(undef)` — the same class and atom without a payload — is never expanded.
All three application routes reach that one `call_fun` seam — the compiled `G(A)`/`G(A1,A2)` (`Instr::CallFun` in the caller's machine), the fun-applying BIFs (`lists:map/2`) and `erlang:apply/2` — so all three answer identically on both execution tiers; `../../tests/decoded_fun_badfun.rs` pins the matrix (bad index `999999`/`4294967295`, a flipped `uniq` byte, an unloadable module atom, plus the genuine-image control and the image's own index written back) against the system `erl` and on `BEAM_RT_TIER=interpreter`.
**The fun-in-record indirection** (`served_local_key` + `apply_non_local_fun`): a named local fun with `num_free == 0` whose descriptor names a key this host **serves** (`beam_bifs::serves_local_call`, the same predicate `resolve_local_call` consults) is declined by `local_fun_target` and dispatched by `apply_non_local_fun` through `call_bif`, so `zlib.erl`'s record-held `fun deflate_nif/4` (applied from `dequeue_next_chunk/2`) reaches the registered BIF instead of its `erlang:nif_error(undef)` stub. The declining path stays allocation-free — a `num_free` test, two `O(1)` reads of the defining module's own atom table and the predicate's module-name equality.
`resolve_local_call` is **not** `host_serves`: it answers `native::prim_tty::serves_local_call` else `beam_bifs::serves_local_call` — two fixed `(name, arity)` key sets (prim_tty's 20 `NIF_KEYS` stubs, `beam_bifs`' 19 `zlib` stream stubs) each gated by a module-name equality, so it reads no runtime state and hashes nothing.
`host_serves`/`host_serves_given` is the **single** source of truth for "the host serves this MFA": `host_serves` computes it (the entry arm's form) and `host_serves_given` takes it from the caller, which is how the external-call seam spends the memo's `bif.is_some()` — that field *is* `BifRegistry::contains` — instead of a second lookup per `call_ext*`.
`host_serves`'s NIF arm is module-granular (`NifRegistry::is_loaded`, not `lookup`), so a mid-run `load_nif/2` **does** flip it for every key of that module — the one runtime-mutable input either seam has.
`BudgetContext` forwards all three seams (`resolve_external_call`, `resolve_local_fun`, `resolve_local_call`), so the scheduled path gets the same in-machine entries as a bare context.
### Send destinations — provenance classification, the alias routes and the remote arm (A.5)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One helper serves **all three** entry points — `alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying by **provenance first** through `Runtime::local_reference(to)`: `Some(Some(_))` (a monitor/alias reference) is looked up via `table.resolve_alias`, `Some(None)` (a bare `make_ref`/timer/`seq_trace` reference) is never an alias, and unknown provenance `None` (a decoded copy) falls back to `MonitorRef::from_eterm(to)`.
The BIF route reaches it through `SendBridge::resolve` and consumes the reference through the **same** table after delivery; the compiled `Dest ! Msg` route uses the inherent `resolve_send_destination` (not a trait method) and consumes it right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` compiles to.
`classify_send_destination`/`SendDestination` (`Local`/`RemotePid`/`RemoteAlias`/`RemoteName`/`Port`/`Dropped`) is the **one** classifier behind all three routes; `resolve_send_destination`/`deliver_remote`/`deliver_to_port` act on its answer, and `resolve_send_target` is a `#[cfg(test)]`-only local wrapper.
Both producers draw from **one** monotone process-wide id space (`beam_common::next_ref_id`), so no id is ever issued twice and provenance adds the **kind** of reference, not its uniqueness.
**The remote alias arm**: an **external reference** whose node slot is not `Runtime::local_node()` classifies as `RemoteAlias { to }` and `deliver_remote` transmits it as `Runtime::dist_send_alias` → `{DOP_ALIAS_SEND, From, To} -- Msg` (`dist.c:2563`) — a **distinct wire form**, because the peer looks the reference up in its own alias table instead of delivering to a process, which is what makes a remote `gen` call answerable (`gen:reply/2`, `lib/stdlib/src/gen.erl:549-556`, replies to the alias reference the caller put in `From`).
The arm sits **after** the live-local-alias and external-pid tests, so a live alias here still classifies `Local` and an external pid still `RemotePid`; a reference naming **this** node that is not a live alias keeps its `Err(beam_error::BadArg)` (the C silently drops it), and on a runtime with no node every reference keeps that same `badarg`.
The peer's `DFLAG_ALIAS` is required (else the typed `did not negotiate DFLAG_ALIAS`), while a reference naming no live alias **on the peer** is the peer's own silent drop — the oracle's measured behaviour (OTP 29.1.1 returns the message and delivers nothing), not ours.
**`nif_send.rs`**'s `deliver(runtime, mailbox, from, to, msg) -> bool` is the arm behind `enif_send` (A.3): it classifies through the shared classifier and runs this module's own `send_message` on a nested `RuntimeContext` (the sender as mailbox owner, `may_pump_scheduler` always `false`), so the message crosses the BIF send's copy boundary and a parked receiver wakes through resume-on-send; a dead/unknown local pid, a rejected destination or a failed copy answers `false` (the C's `0`).
That dead-pid `false` is decided **before** the seam, because the seam itself reports an internal pid no process backs as `!`'s silent success (`bif.c:2478-2480`) — the C's `erts_proc_lookup` gate belongs to the NIF ABI, not the operator's semantics.
`send_message_with_off_heap` is the **one** definition of the dead-destination policy, still emitting the `send` trace event and deliberately not the enqueue-time `receive` one, and every other send route inherits it.
**`send_source` is the one place a delivery builds the copy's source off-heap table — keep both paths going through it**: `send_message_with_off_heap` passes `Some(self.mailbox_pid)` (the full three-family union), `deliver_message` passes `None` (store-only, keeping the empty-source fast path so a plain on-heap message still builds no table).
`deliver_into_mailbox` is the crate's one delivery door and it *holds* a refusal, so it calls `send_fragmented_message_after_refusal` with that failure's own `AllocFailure::requested` (no trial copy, no `size_object`-class pricing walk); `send_fragmented_message` is the **no-refusal** shape and has no in-crate caller; both end in the shared `finish_fragment_delivery` tail (the receiver's wake, the unconditional descent-gate note, the real-wake-only wake note).
C arms reproduced: `send_altact_message` (`bif.c`) + `handle_altact_msg` (`erl_proc_sig_queue.c`); `dist.c:2563` for the alias frame.
