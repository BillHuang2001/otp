# `beam_rt::context` — implementation detail (dispatch, tables, GC-relocation seam)

Mechanics-level companion to [`CONTEXT.md`](CONTEXT.md), which keeps the Intent, API Surface, Constraints and Routing Table; this file holds the per-concern detail: the dispatch memo, the pooled BIF-heap frontier, `PendingInterner`, the runtime-hooks served/closable rosters, the truthful fixed answers, the GC relocation-exemption seam, the two-phase unscanned-root valve, the admission-door debt/valve cost, the nested-pump bounds, the per-call cost breakdowns and the A.9 in-process-compile sweep measurement.

### The pooled BIF-heap frontier — `take_bif_frontier`
Both pool-consuming call sites (`call_registered`, `try_call_nif`) take their allocation frontier through `take_bif_frontier` rather than `Runtime::take_bif_heap` directly.
The pool is shared, so the region handed back may be **nearly exhausted** — `available() < capacity() / BIF_HEAP_GROWTH_DIVISOR` (16). That is reachable on the **table-less** route (the `-eval` evaluator and every single-pass nested run): with no scheduled process `move_result_into_process_heap` answers `None`, so a container result is never copied off the pool and the pool is never rewound — every container a BIF builds stays on the region it was built on for the run's whole life, whose bump pointer would otherwise march to the fixed capacity and hand the next call `error:system_limit` for a reason unrelated to any live set.
Growth is by **region replacement** — never relocation, never a retry: the exhausted region is pushed back (`Runtime::put_bif_heap`) and a fresh, larger one becomes this call's frontier *before* the BIF runs, so every word a caller still owns stays valid at its own address and no BIF is re-invoked and no side effect repeated.
The new capacity is the old doubled (`saturating_mul(2)`), floored at `Runtime::bif_heap_words` and capped by a configured `+hmax` (`heap_options().policy().max_heap_words`; `0` = no cap); where the cap leaves no room (`computed <= capacity()`) the region is returned as it is, so an explicit `+hmax` still yields the same `error::system_limit`.
`call_registered` reads its per-call `mark = heap.used()` **after** the helper (a freshly grown region starts at 0); a nested call may be handed a region an outer call retired — the same check applies there, and `mark = used()` still keeps a rewind from recycling words another caller owns.
### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity) -> DispatchAnswer` is the **only** producer of a registered call's dispatch answer; it is memoized in a per-context **direct-mapped 8-slot** `DispatchMemo` (the slot from `dispatch_slot` over the key's **name bytes** and the arity).
`DispatchAnswer` is `{ bif: Option<BifFn>, hooks: DispatchHooks }`: `bif` is `registry.lookup(module, function, arity)` — the implementation the caller then **invokes directly** (no second lookup); `contains` **is** `lookup(…).is_some()` (`beam_bifs/src/registry.rs:189`, pinned equal by that crate's `contains_always_agrees_with_lookup`), so `call_registered` is reached only on `Some`.
`hooks` is one boolean per `uses_*` predicate — the eight mutually-exclusive arm selectors plus the build gates (`fun_identity`, `memory_hook`) — computed by `DispatchHooks::of`, the **only** place the `binary_search`es over `beam_bifs`' `&'static` `needs_*` rosters run; `call_registered` selects its arm and optional handles from `hooks.*` instead of re-running the predicates.
A **miss** computes and stores; a **slot collision** overwrites, and the evicted key recomputes on its next call — an eviction costs work, never a result.
`dispatch_slot` hashes the key's **bytes** (FNV-1a over `module`, a `0xFF` separator, `function`, then the arity) and avalanches with a fixed multiply, so same-length keys span distinct slots (`ets:insert/2` and `ets:lookup/2` do not collide); the constant is **chosen**, not derived, so the measured hot key set occupies distinct slots. Eight slots is the binding limit: more than eight hot keys still collide somewhere, costing the whole prologue on every miss — never a wrong answer; enlarging the table means changing the churn assertion in `tests.rs` (`../../PERF.md` *DISPATCH-CUT*).
**Why a cached answer cannot go stale.** Both inputs are immutable for the life of the runtime: the `needs_*` rosters are `&'static` tables with pure membership predicates, and `registry` is an `Rc<BifRegistry>` built once at boot (nothing calls `Rc::make_mut`/`Rc::get_mut` on it); the one runtime-mutable input — the NIF registry `load_nif/2` grows — is deliberately **not** memoized, since `call_bif` runs `try_call_nif` first on **every** call, so a library loaded mid-slice wins immediately (`../../tests/nif.rs`).
The memo lives on the `RuntimeContext`, so it is exactly as long-lived as one run; a nested run builds a fresh context with an empty memo.
**Two prologue costs are gone.** (a) The **second registry lookup** — `call_bif_routed` hands the already-resolved `BifFn` to `call_registered`, and `invoke_registered` reproduces `BifRegistry::call`'s arity check so the error path is unchanged. (b) The **NIF probe** — `try_call_nif` short-circuits on `NifRegistry::is_empty()`.
### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` keeps its `{base, names}` state **inline** (`InternerState::Inline(RefCell<…>)`) and allocates only when `share` promotes it into a shared `Rc<RefCell<…>>`: `new(base)` roots it at the shared table's length, `commit` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers).
An ordinary registered/NIF call has a **single** writer, so it never shares and allocates nothing; `load_nif/2`'s two writers (the BIF and the C `load` callback via `enif_make_atom`) call `share()` and get two handles over one cell, so both agree on `base + <names recorded>` and the caller's single `commit` lands every name at its predicted index; `share` is the only way to obtain a second handle (`PendingInterner` implements no public `Clone`).
`run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess). `call_registered` clones the caller's module only in the NIF-loading, `send` and fun-caller arms (which need an owned `String`).
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable pooled BIF heap and the per-call `PendingInterner` is committed **after the registry borrow is released**. `NifCallError::Raised(reason)` → `error::nif_raised`; `UnknownFunction` → bare `error::undef`; a miss is `Ok(None)`.
The per-call host gets a `RuntimeNifServices` provider built from **disjoint** field borrows of the runtime (`refs`/`references`/`processes`/`ports`; `processes` is the caller's mailbox table on a scheduler slice), so the host's `make_ref`/`whereis_pid` hooks **and** its `is_port_alive`/`port_command` port hooks (a `try_borrow` ⇒ the typed `None` on a live borrow) are live; the registry `Rc` is cloned and the heap taken **before** those borrows, so the call itself never borrows `self.runtime`.
**Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif`.
## Closable host-seam keys (`runtime_hooks.rs`)
`uses_runtime_hooks` gates the **whole** 172-key roster (`../beam_bifs/src/hook_sets.rs`'s `assert_eq!` pins it at 172), so any roster key already reaches the bridge; a key is closable when its backing data lives behind that bridge's borrows (or `Runtime`'s owned tables: code server, timers, registry) with **no** new cross-crate dependency. Oracle answers are from the system `erl` (OTP 29.1.1 / erts-17.1).
The bridge holds `&mut Runtime` **plus** `Option<&mut ProcessTable>`, which is why it is an arm of its own (`timeout` is a `boot::CORE_ATOMS` seed and the shared table is borrowed immutably for the whole call).
* **Served today** — the timer family (`start_timer/3,4` ⇒ `{timeout,TRef,Msg}`; `send_after/4` incl. the `{abs,true}` form; `cancel_timer/2`); `function_exported/3` (the declared `bif.tab` surface plus the registry extras, **or** the loaded module's export table); `link/1`/`unlink/1` (the `ProcessTable` link set — a **local** pid through `ProcessTable::link`/`unlink`, a **remote** pid through `link_term`/`unlink_term` to the installed `DistSignalRouter`, the only gap being a peer with no established link); `os:set_signal/2`; `net_kernel:dflag_unicode_io/1`; `erts_internal:scheduler_wall_time/1` (arms/disarms the node-global sampling switch, answering the **previous** state; it drives no sampling, so `statistics(scheduler_wall_time)` stays `undefined`); `erts_internal:erase_persistent_terms/0`; and `statistics/1` (`run_queue`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io`, `garbage_collection`).
  Every other key it answers is a **fixed oracle-absent value** (next section); every remaining roster key is the typed `unsupported_bif` (the closable ones below) or is served **earlier** by the native floor (the `alias/0,1`/`unalias/1` trio, the four `erl_ddll` keys); a key outside the roster is bare `error::undef`.
* **Closable today** — `erlang:bump_reductions/1` (the node-global reduction counter; range-validate a small int ≥ 0 else `badarg`); `erlang:read_timer/1,2` (`crate::timers::Timers`; `is_timer_ref` distinguishes a non-ref from a fired ref and `cancel` already computes the remaining `Duration`, so closing needs a read-only accessor that does **not** consume the entry; `/2` accepts **only** `{async,Bool}`); `erlang:delete_module/1` (needs a `CodeServer` removal op and the `undefined` atom interned); `erlang:is_builtin/3` (the borrowed `registry`, restricted to the **declared `bif.tab`** set so a stdlib fast path is never a false `true` — `is_builtin(lists,map,2)` ⇒ `false` on the oracle).
* **Closable on a condition** — `erlang:loaded/0` (needs every name's atom already interned via `atoms.lookup`, never intern; answers this runtime's own small module set); `erts_internal:port_info/1,2` (`PortMeta` already records `command` and `os_pid`; `RuntimePorts::port_info` is the production implementation).
* **NOT closable — genuine, correctly-typed gaps (do not "close")** — `alias/0,1`/`unalias/1` and the four `erl_ddll` keys are on the roster but the native floor serves them (not gaps); `statistics(active_tasks|active_tasks_all|total_active_tasks|total_active_tasks_all)` needs a scheduler current-process flag the Scheduler does not record; `statistics(microstate_accounting)` needs MSACC machinery; `erts_internal:gather_carrier_info/1`/`ets_super_user/1` need allocator/pid-domain introspection; the six `re:*` keys need a regex engine (a missing subsystem); `erts_debug:*` (18) / `erl_debugger:*` (13) are unmodelled facilities; `erts_internal:prepare_loading/2` is not a fabricatable value; and `erlang:system_info/1`/`system_flag/2` are on the roster but the native floor intercepts them before the registry, so no bridge work can affect them.

### Relocation exemption (the cross-crate GC correctness seam)
`with_relocation_exempt<T>(&mut self, f: impl FnOnce(&mut Self) -> Result<T>) -> Result<T>` runs `f` with the context's process (`self.mailbox_pid`) marked relocation-exempt through `ProcessTable::{is,set}_relocation_exempt`, so a delivery-driven `Process::deliver` collect can never recycle words this crate holds **outside** the process's own containers (Rust-local term handles, an unpublished `Machine`); it is **nested-safe** (it saves the previous mark, sets `true`, restores on every path — `TermNotFound` on the save means "no process", so nothing is exempted — and the closure's error wins).
Wrapped scopes (exactly five): `crate::eval::eval` (the whole `-eval` driver body), `run_export_blocking`, `run_label_blocking`, `apply_fun` (the `-eval`-closure arm) and `deliver_message_with_off_heap` (exempting the **sending** context's own pid, so a self-send whose payload does not fit routes to the heap-fragment fallback; a delivery to a *different* process is unaffected).
The **scheduled slice is deliberately not wrapped**: the runner drives its own outcome entry points directly, publishes parked roots, and its armed admission point (`ensure_heap`/`ensure_heap_full`) stays the legitimate collection site ([`../../DESIGN_DECISIONS.md`](../../DESIGN_DECISIONS.md)).
Separately, the runner opens its **own per-slice exemption** for a process whose FR prefix is live when a slice ends: `RuntimeRunner::run` marks the process relocation-exempt when `Machine::fr_mark() > 0` (`src/runner/run.rs` `process.set_relocation_exempt(true)`) and the next slice entry clears it (`set_relocation_exempt(pid, false)`), so the inter-slice window (where a delivery-driven collect could otherwise recycle a live float word) is guarded while a running slice collects normally — a bounded, decline-only guard, so `Runtime::gc_stats().pinned` stays 0 and a float-using loop's `collections` scale with N. The narrow door's caller-module float guard is a separate, in-slice concern (see [`CONTEXT.md`](CONTEXT.md) *Known Issues*).
The two other nested-`Machine` sites (`boot::drive::apply_boot_call`, `native::file_server::EngineContinuation::call`) are safe *only* on a `RuntimeContext::new` context (`mailbox_table == None`, which forces every allocation onto the pointer-stable arena); moving either onto a `for_process*` context would make it a delivery-collect hole for a mid-run process.
`deliver_in_table(runtime, table, to, from, message) -> Result<()>` is the pass-boundary entry to the same `deliver_message` semantics for the runtime's own delivery steps (used by `Runtime::service_file_requests`, `deliver_port_messages`, `fire_due_timers` and `drain_ets_owner_exits`); its context's pid is the **receiver**, so the copy's source is `send_source(None, …)` → `Runtime::off_heap_source`, and an exempt receiver's raw `Alloc(AllocKind::Message)` refusal routes to `send_fragmented_message`'s heap-fragment fallback instead of propagating.
### The unscanned-root valve — two phases
Phase 1 (`root_is_unscanned`, always run) calls a term safe exactly when it is an **immediate**, a **literal** or a pointer the collector **scans** (any nursery space, current or growth-retired, or the mature generation).
Phase 2 (`gc_walk.rs`) descends the process's scanned graph and root containers under the sticky per-pid latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found; the single-level test it replaces could only see a root's *own* address.
The valve is consulted at each of the four collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the runner's park arm `Runtime::serve_gc_request`); declining costs a collection and nothing else — the allocation falls back to the pointer-stable arena — so it can never turn a working program into a failing one, and the fallback count is `note_gc_fallback`'s.
The gate a `beam_process` signal site consults is built from the runtime's **one** shared latch cell (`RuntimeCollectionGate::from(latch)`), so a decision is `O(1)` while the pid's bit is clear; the no-latch `RuntimeCollectionGate::new()` form (which always descends) is `#[cfg(test)]`-only.
A term in a foreign region (pooled BIF heap, arena, `-eval` heap, message fragment) declines the collection — **except** a registered-BIF result, which `call_registered` copies onto the running process's heap and rewinds the pool to the call's own `mark`, making it a scanned root rather than a foreign holder.
### The nested blocking pump and its bounds
`run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver, one `pump_once` round per wait.
For an ordinary (no-deadline) parking, `pump_once` advances the scheduler by `RUN_EXPORT_PUMP_SLICES` (64) slices through `Runtime::pump_scheduler_boot` — the **imminent-only** wait policy, so a round whose only pending deadline is far out returns unslept instead of stalling the caller — and a pump reporting that nothing ran ends the drive with the honest `beam_engine::blocked()` gap.
The engine arms no timer for a `wait_timeout` and a nested run is not a scheduled process, so for a statically readable finite `after T` `pump_once` recovers the deadline through `Machine::wait_deadline` and, on an empty run queue, sleeps `min(remaining, DEADLINE_PUMP_SLEEP)` (5 ms) and re-pumps until the wall clock reaches `start + T`, then resumes at the `timeout` continuation (a message arriving first wins).
The loop ends on return, on a step reporting `Ok(None)`, or at the `BLOCKING_PUMP_DEADLINE` (900 s) cap — the nested counterpart of the boot drive's `DRIVE_DEADLINE`, reported as a typed `error::message(...)` and sized to clear the heaviest legitimate workload on this route with headroom: an in-process compile of a real `lib/stdlib/src` module, whose measured `user` cost reaches ≈ 155 s (`qlc.erl`; wall up to ≈ 188 s on a loaded host) under the debug runtime.
That cap is the **only** bound: a forward-progress trip on `Machine::reductions` was considered and rejected as unsound, because the awaited machine's own counter says nothing about the process it waits on, so "re-scans its mailbox with ~0 charged reductions" is equally the signature of a legitimate busy peer (`gen_server:call` to a server computing for minutes) and would replace a result the oracle answers with this runtime's own error; a progress-gated bound that also required "the pump reported nothing ran" would never fire at all, since that *is* the loop's `Ok(None)` exit.
The deadline path is exercised only through the injectable `limit`.
### Per-call cost of a registered call
**`erlang:term_to_binary/1,2` and `erlang:binary_to_term/1,2` are dominated by two host costs, not the dispatch prologue.**
1. *Decode:* every `binary_to_term` reuses a per-thread scratch image of the live atom table, proven index-identical in **O(1)** through the append-only witness (`beam_term::AtomTable::snapshot`/`appended_since`), so the steady state reads **no** atom name; the index-by-index `prefix_matches` survives only as the fallback for a table the witness cannot vouch for (a replaced/cloned table, or a memo left ahead/behind). Both `beam_rt` decode hosts adopt it — the `../nif.rs` NIF/driver mirror (`with_decode_scratch`, measured on the booted table: **2 024** atoms, **0** name comparisons per steady-state decode where the blind walk read **2 024**) and the ordinary BIF path in the sibling `beam_bifs/src/binconv.rs`. `term_to_binary` (encode) never touches the scratch.
2. *Copy-out:* every container result (an encoded binary, a decoded map) is deep-copied onto the process's young heap by `calls.rs::move_result_into_process_heap` (invoked at the `safe_to_rewind` arm of `call_registered`), which hands the copier a **fresh, empty, per-attempt** `OffHeapTable` as its destination so the single-traversal path is always taken, then adopts the local table's drained references into the runtime-lifetime `eval_off_heap` on success only (a refusal adopts nothing); a result the nursery cannot hold pays one `grow_nursery` — sized from the copier's own preflight shortfall, so no extra graph walk — and one second single-traversal attempt, while a permanent refusal returns `None` without growing.
**The dispatch prologue, hit and miss.** A **hit** is `dispatch_slot`'s FNV byte fold over the two names plus three field compares — allocation-free — after which `call_registered` pays only O(1) handles: five `Rc` clones (atom table, ETS registry, port registry, plus the two inside `RuntimePorts::new`), a pooled-heap `Vec::pop`/`push` (`Runtime::take_bif_heap`/`put_bif_heap`), an **inline** `PendingInterner` (no `Rc`/`RefCell`/`Vec` allocation until `share`), one `try_borrow_mut` on the ETS cell, the `reset_to(mark)` rewind, and the copy-out decision. A **miss** additionally pays `BifRegistry::lookup`'s two nested-`HashMap` SipHash lookups + a linear arity scan, ten `binary_search`es over `&'static` rosters (`DispatchHooks::of`) and **two `String` heap allocations** (`module.to_string()`/`function.to_string()` in `dispatch`).
**Genuinely O(1)/allocation-free per call:** the dispatch memo, `take_bif_frontier` + `reset_to(mark)`, the `Rc::clone`s, the intern-commit guard, and — for `term_to_binary` only — the `Rc`-cached fun-module snapshot plus one caller-first `position()` scan in `FunIdentityBridge::new`.
**The copy-out is skipped for an immediate result.** `result_is_foreign_container` is false for a small integer/atom/literal, so such a result rewinds the pool with **no** copy; only a boxed/cons non-literal reaches `move_result_into_process_heap`. So `term_to_binary/1` copies (its binary result is a container) while `binary_to_term/1` decoding to a small int does not. `term_to_binary`/`external_size`/`fun_info` additionally build `FunIdentityBridge::new` on every call — an `Rc` clone of the cached snapshot plus a caller-first `position()` scan that is O(loaded modules) — and `binconv.rs`'s term encoder reads the seam once per encode even for a non-fun argument.
**A small-int arithmetic `gc_bif` never reaches this node on the default tier.** `beam_engine`'s baseline JIT inlines a guarded small-int `erlang:'+'/2`/`'-'/2`/`'*'/2` inside the compiled block (`beam_engine/src/jit/baseline/emit/arith.rs::try_inline_gc_bif`), so the operation is native and `ExecutionContext::call_bif` is never called; a deopt runs one interpreter step (`jit_step_one`), not a direct BIF call. Every `call_ext*` does reach this node (the host declines `resolve_external_call` for a registered key), so a loop's `call_ext` BIFs — not its arithmetic — pay the prologue.
### Debt/valve cost of the admission doors
`collection_debt()` is folded into both doors' occupancy OR, so a growth-retired chain makes the full door evaluate `any_root_is_unscanned` on **every** admission point even when the *current* space has room.
The per-word `root_is_unscanned` reaches `Collector::young_contains`/`Nursery::contains`, which iterates **every** space of the nursery chain, so a retired-space pointer costs O(chain length); the chain is collapsed only by a real collection (`Nursery::collapse`).
### The A.9 in-process-compile sweep
Measured on this host (`BEAM_RT_SWEEP_SHARD=0/6`…`5/6` in parallel): the oracle compiles **86 of the 96** `lib/stdlib/src/*.erl` sources.
The other 10 `-include` a header that does not sit in the source's own directory, which this option list (no `-I`) cannot resolve — an oracle-side limit, not this runtime's.
All 86 compile in-process **byte-identically**.
The sweep's body runs on a dedicated thread with a 32 MiB stack (`SWEEP_STACK_BYTES`), so the deepest sources compile exactly as they do on the real CLI route's ~8 MiB main thread; no environment stack variable is needed, and the thread's panic payload is re-raised with `std::panic::resume_unwind` so an assertion message survives the boundary.
