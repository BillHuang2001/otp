# `beam_rt::context::pool` — the BIF-result copy-out, the pooled heap frontier and the term stores

## Intent

The destination side of a registered call: where a `beam_bifs` result term is copied to, and what owns the
memory it lands in.
It owns the pooled BIF heap and its frontier, the two copy-out destinations (a scheduled process's own scanned
young heap, or the runtime-lifetime `eval_heap` + `eval_off_heap` store for a table-less route), the learned
`copy_out_hint` gate, and the `ets` table-alias witness that decides whether an aliased result is copied at all.
The dispatch itself is [`../calls/CONTEXT.md`](../calls/CONTEXT.md)'s; the collection doors are
[`../gc/CONTEXT.md`](../gc/CONTEXT.md)'s.

## API Surface

### The pooled BIF-heap frontier — `take_bif_frontier`
Both pool-consuming call sites (`call_registered`, `try_call_nif`) take their allocation frontier through `take_bif_frontier` rather than `Runtime::take_bif_heap` directly.
The pool is shared, so the region handed back may be **nearly exhausted** — `available() < capacity() / BIF_HEAP_GROWTH_DIVISOR` (16). The frontier is the pool's own capacity, so a route that keeps a result on the region would march the bump pointer to the fixed capacity and hand a later call `error:system_limit` for a reason unrelated to any live set; that is why **both** routes move a container result off the pool — the scheduled process onto its young heap unconditionally, the table-less route onto the runtime store only when the call may rewind, so the copy licenses that rewind (see [the table-less arm](#the-table-less-arm-and-its-store)).
Growth is by **region replacement** — never relocation, never a retry: the exhausted region is pushed back (`Runtime::put_bif_heap`) and a fresh, larger one becomes this call's frontier *before* the BIF runs, so every word a caller still owns stays valid at its own address and no BIF is re-invoked and no side effect repeated.
The new capacity is the old doubled (`saturating_mul(2)`), floored at `Runtime::bif_heap_words` and capped by a configured `+hmax` (`heap_options().policy().max_heap_words`; `0` = no cap); where the cap leaves no room (`computed <= capacity()`) the region is returned as it is, so an explicit `+hmax` still yields the same `error::system_limit`.
`call_registered` reads its per-call `mark = heap.used()` **after** the helper (a freshly grown region starts at 0); a nested call may be handed a region an outer call retired — the same check applies there, and `mark = used()` still keeps a rewind from recycling words another caller owns.

### The table-less arm and its store
`call_registered`'s tail decides the copy-out off `move_container = self.mailbox_table.is_some() || safe_to_rewind` and then calls `calls.rs::rehome_container_result`, which picks the destination by **who is running**:
* a scheduled process (`mailbox_table.is_some()`) → `move_result_into_process_heap`, an `Ok` container result onto its own **scanned** young heap (bit-for-bit unchanged), **unconditionally**: the pooled BIF heap is a region no process collector scans and a later call's rewind recycles, so a result Erlang code stores inside a heap object — a tuple, a map, a longer list; `compile:debug_info_chunk/1` storing `lists:filter/2`'s result in a tuple — would dangle there;
* the **table-less** route (`RuntimeContext::new` — the `-eval` evaluator, `-s`/`-run` and every single-pass `run_*` entry, no scheduled process) → `pool.rs::move_result_into_runtime_store`, the result onto the runtime's long-lived store, **only when `safe_to_rewind`**: no process collector exists there and a non-rewindable call never rewinds, so an unconditional move would only duplicate the result into the runtime-lifetime store (measurably exhausting the term-heap arena on a long in-process compile).

**A reference-holding graph is never moved and never rewound** (`RuntimeContext::graph_holds_reference`): a reference's identity is its **address** (the M1 internal reference is a four-word all-immediate block, `Runtime::references` is a `HashMap<Eterm, _>` and `Timers::is_timer_ref` keys on the term word), so a copy would stop being the timer it names, `erlang:cancel_timer/1,2` would answer `badarg`, and `gen_server:cancel_timer/1` would turn that into a `kernel_sup` crash.
The walk reads only readable terms: a non-term word (`beam_term::tag::is_term_word`), a boxed word that is not a dereferenceable term (`beam_term::boxed::is_boxed_term`) and a null/unaligned pointer (`super::gc::dereferenceable_pointer`, `pub(super)`) are skipped, never dereferenced — `is_boxed`/`is_list` are the C bit tricks and accept bare header words including `THE_NON_VALUE`.

**A payload no source table owns does not refuse the move.** `copy_result_fresh`'s own flattening turns an ownerless refc binary into a self-contained on-heap bitstring (byte-faithful) on both routes, so only an unresolvable off-heap container (an MSO reference with no owner) makes the copier refuse — and then the result stays on the pool with the rewind cleared, never a dangling payload.

**Which route rewinds at which granularity.** Both rewind the pooled region with `heap.reset_to(mark)` — `mark` is the call's own frontier, so a pooled region a caller reached part-used still keeps the words that caller owns.
The rewind is gated on all of `safe_to_rewind` (no escaping `DispatchHooks` arm — `dict`/`process_hook`/`nif_loader`/`send_hook`/`persistent_term`/`runtime_hooks` — and no reentrant fun-applying call), an **`Ok`** result (a raise may carry a live reason term — `beam_common::Raise::live_reason` — that points into this heap) and a move that ran and succeeded (or an immediate result, which is copied nowhere); a failed re-home returns early, leaves the result on the pool and the pool at the call's own offset, grows nothing, and also clears the rewind, because that call's words are still handed out.

**Evidence.** `selfhost/in_process_compile_file_no_spawn_deterministic` agrees with the oracle, and it is the shape that fails without the process-route move: a container result left on the recyclable pool while Erlang code stores it in a heap object is a dangling boxed argument at the next rewind (`unsupported: external_term` or an `invalid boxed header subtag` abort).

**What the store owns.** Three `Runtime` fields, all pointer-stable and none of them ever moved or freed: `eval_heap` (`beam_alloc::Heap`, the copy destination and the evaluator's own long-lived term space), `eval_heap_retired` (the generations `grow_eval_heap` replaced, kept so every word they handed out stays valid) and `eval_off_heap` (`beam_message::OffHeapTable`, the destination off-heap table — an escaped binary/refc payload a copied term carries). `move_result_into_runtime_store` deep-copies through a **fresh, empty, per-attempt** `OffHeapTable` (so `copy_struct` always takes its single-traversal fast path regardless of what `eval_off_heap` already holds), and only on success **adopts** that table's drained handles into `eval_off_heap` and calls `note_escaped_store_roots` (opening the reading pid's valve gate for a container). On an exhaustion refusal it calls `grow_eval_heap(shortfall.max(256))` once and retries; any other refusal returns `None` with no growth and no rewind.

**The store is rewound between top-level `-eval` statements** (`src/eval/scratch.rs`): `Evaluator::reset_scratch` runs the boundary before each statement of a `-eval` driver run, and it reclaims the dead prefix `[mark, used)` of the current region via the `src/eval/reclaim.rs::walk` descent over `Runtime::gather_off_heap_roots` plus the evaluator's `Env` (a `WindowProbe` sink; nothing is dereferenced, a reached word's *address* is compared with the window). The **pin family** — `Runtime::stabilize_term`/`stabilize_term_with`, `src/port/completion.rs::decode_caller_tag`, `apply_eval_closure` — and the **two nested-run latch sites** (`src/context/pump.rs`, latching through `Runtime::pin_window_if_store_written` only when the run actually wrote on the store) are what keep a window the descent cannot enumerate from being reset, so a pinned or declined window retains one statement's words (a bounded leak) and never a live term's. `eval_heap_retired` is still never freed, and the `-eval` action process is never enqueued, so no runner outcome family holds a word across a boundary here.

**Why the rewind is sound.** (a) It runs only after `copy_result_fresh` returned a complete copy, so no live word a caller can still reach lies above `mark`; (b) the destination is a *different* region from the pool — `eval_heap` is pointer-stable, a growth replaces the region rather than moving it (the old one is retired) and its only rewind is the statement window's, which runs against a published complete root set — so a copied term is valid for the runtime's life; (c) the copy's off-heap handles are adopted into `eval_off_heap`, so a copied binary's payload has a live owner instead of dangling; (d) the words the store retains for one call are the copy of exactly the graph the pool previously retained in place, so the store's growth is the same retention moved one region over, never a superset of it.

**Measured (the trade, quantified).** `calls/tests.rs::eval_route_pool_costs` (`#[ignore]`d; one fresh child process per row via `BEAM_RT_EVAL_POOL_CHILD`, `taskset -c 3`, 15 interleaved A/B samples per row alternating the two copy-out variants — every counter below is **identical across all 15 samples**, so it is deterministic, and no wall time is used as evidence). `pool` is the pool's cumulative first-touch high-water (Σ `peak_used`, which survives a rewind); `store` is `eval_heap.used()` committed in the child, which also carries the evaluator's own comprehension list, so the copy-out's own retention is `store_after − store_before`. `/proc/loadavg` before the sweep `1.76 5.13 13.85`, after `1.70 5.06 13.78`.

Read honestly, the trade is: **the pool retains none of a run's container results** (bulk high-water 1.58M / 3.15M / 6.30M → 50k / 100k / 200k — the per-call shape, not the run's total), and **exactly that many words sit in the never-reset store** (`store_after − store_before` equals the pool's own high-water had it retained them, to the word, in every row). First-touch minor faults **do not go down** — the totals are the same graph copied to a different region, and the store column is marginally higher (≈1.14–1.19×) because the store grows by region replacement where the pool grows in place. What the copy buys is not faults but **capacity independence**: the pool is one fixed region shared by every call, so a long enough table-less run retaining its results there would march it to the cap and answer `error:system_limit` for a reason unrelated to any live set, whereas under the copy the live data sits in a grow-only store and the pool is available to the next call. That is observable under an explicit cap: the 1000-container-call expression (`tests/eval_pool_result.rs`) answers `system_limit` at `+hmax 2048/4096/8192/16384` when the results stay on the pool and `1000` from `+hmax 4096` up under the copy (`+hmax` caps `eval_heap` and the pool alike through `term_heap_words`).

### The learned copy-out hint — `copy_out_hint` + `hint_grow_gate` (the copy-bound fix)
The copy-out above is cheap when the destination fits and **expensive when it does not**: `try_copy_fast` has already run, so recovering the size costs `preflight_words` → `beam_term::size::size_object_bounded_with` (a `HashSet`-backed walk) → the acyclicity check (two more sets) → `size_object_with` — five traversals of the graph and three hash tables — to *learn a number the exhaustion error already carries for free* (`copy_shortfall_words`).
The `copy_bound/ets_copy` loop met that path on **0.332 of its ops**, because every collection collapses the nursery back to its 142–233-word floor while the result in flight is 73 words on top of the loop's own ≈66-word payload: the grown space cannot survive (`Nursery::collapse` re-installs `young_after_collection`, and `should_shrink(cap, need) = cap > 4*need && cap > min_heap_words` shrinks it for a tiny live set), so the once-per-slice-then-stable growth of the previous fix (`GROW_HEADROOM_FACTOR`) was undone by the very next collection.
The fix is therefore **not** a bigger growth but a **hint**: `RuntimeContext::copy_out_hint` (a context field, `runtime_context.rs`) records the largest graph this slice has been refused for (`self.copy_out_hint.max(copy_shortfall_words(&error))`, learned inside the existing refusal arm), and `hint_grow_gate` (`calls.rs`) spends it **before** the next attempt — when `process.heap_mut().available() < hint + max(hint/4, COPY_OUT_HINT_MARGIN_MIN = 32)`, it grows through `Process::grow_nursery` (`COPY_OUT_HINT_MIN_WORDS = 8` is the "nothing learned / trivial" guard). The growth is legal inside a BIF call because `grow_nursery` is the **NO-RELOCATION** seam (it retires the space it replaces and moves no live term — a collecting `ensure_capacity` would free live terms with the machine's roots unpublished); a `max_heap_size` refusal degrades to the bare hint and then simply returns, so the ordinary refusal → grow → retry path still runs and a ceiling can only cost the pre-copy opportunity.
`hint == 0` (a context's first copy-out) behaves exactly as before, and the whole refusal fallback — fresh empty per-attempt destination table, permanent-refusal short-circuit, ceiling fallback — is unchanged.
**Measured** (`copy_bound/ets_copy` shape, 250 000 ops, `taskset -c 3`, 3 alternating paired rounds, same binary, hint disabled vs enabled): refusals **83 067 → 754** (0.332 → 0.003 per copy-out), the hint gate's growths **0 → 83 387**, the collection cadence *unchanged* (**83 289 → 84 158** `ensure_heap_full` collections, 160 → 162 at the reds boundary; narrow/rooted doors never fire), mean `available()` at the copy-out **277 → 190** words, **1 638** contexts in both arms (**155** copy-outs per context) — and wall **1.30/1.15/1.17 s → 0.82/0.84/0.82 s**, i.e. **4 680 → 3 280 ns/op** (median), peak RSS 115.9 MB → 115.5 MB. Each avoided refusal is worth **≈4.2 µs** (350 ms over 82 313).
The pin is `calls/tests.rs::a_collecting_default_process_copies_every_result_without_refusing` — a **default-policy** process driven through the real admission cadence (`Process::collect_if_needed`, i.e. occupancy OR `collection_debt`) between copy-outs, asserting `refusals * 8 <= copies` **and** that the gate is what serves them — with its control `without_the_learned_hint_the_same_cadence_refuses_again` (the same cadence with the hint zeroed every op: ≈1.0 refusals/op, `hint_grows == 0`), which is what makes the pin unfakeable.
A **per-process** hint (a `Runtime`-owned map keyed by pid, `src/runtime.rs` — outside this node) would remove the once-per-slice learning refusal: 754 residual refusals ≈ 3.2 ms of that run, i.e. ≈13 ns/op (0.4 %).
**What the gate costs a shape that is not copy-bound.** The `gc_bound` churn loop copies out a 257-word tuple (`list_to_tuple/1`) and a 256-byte binary (`list_to_binary/1`) per iteration, so the gate grows its nursery **before** the copy instead of after a refusal.
The shape genuinely needs that headroom — a 257-word result plus the loop's own payload does not fit a nursery at the rule's floor — so what the gate moves is the growth **event**, not its size: `Process::grow_nursery` retires the space it replaces (a no-relocation *retire*, never a move), and the retired space is one collection debt settled by the next heap-admission door's `collection_debt()` arm.
That settlement runs `Nursery::collapse`, which sizes the nursery from the round's own **young live set** (`HeapPolicy::young_after_collection`: target `young_minor_target_words(live) = next_words(live + need_reserve_words)`, kept anywhere inside `[target, YOUNG_SHRINK_FACTOR (8) × target]`), so the shape's schedule is a fixed point of that rule and flat in N: at N = 2 000 / 4 000 / 10 000 it measures **3 468 / 169**, **6 939 / 337** and **17 341 / 838** collections and majors over 2 001 / 4 001 / 10 001 calls — **1.7331 / 1.7343 / 1.7339** collections and **0.0845 / 0.0842 / 0.0838** majors per call — on one young space of **1 220** words capacity (1 065 of them used) and a mature generation of **4 185** words capacity (4 068 used).
The shape's live set is ~158 words, so `young_minor_target_words(158)` is 233 and the 1 220-word capacity sits inside the keep band `[233, 1 864]`, which is why the capacity is constant in N while the collection count climbs at a constant per-call rate.
The gate's own wall-time delta on this shape needs a gate-disabled build, so none is claimed here; the authoritative rows, their denominators and their caveats are [`../../runner/MEASURED.md`](../../runner/MEASURED.md) and [`../../runner/tests/boundary_cost.rs`](../../runner/tests/boundary_cost.rs)'s `MEASURED` table.
**The dispatch prologue, hit and miss.** A **hit** is `dispatch_slot`'s FNV byte fold over the two names plus three field compares — allocation-free — after which `call_registered` pays only O(1) handles: five `Rc` clones (atom table, ETS registry, port registry, plus the two inside `RuntimePorts::new`), a pooled-heap `Vec::pop`/`push` (`Runtime::take_bif_heap`/`put_bif_heap`), an **inline** `PendingInterner` (no `Rc`/`RefCell`/`Vec` allocation until `share`), one `try_borrow_mut` on the ETS cell, the `reset_to(mark)` rewind, and the copy-out decision. A **miss** additionally pays `BifRegistry::lookup`'s two nested-`HashMap` SipHash lookups + a linear arity scan, ten `binary_search`es over `&'static` rosters (`DispatchHooks::of`) and **two `String` heap allocations** (`module.to_string()`/`function.to_string()` in `dispatch`).
**Genuinely O(1)/allocation-free per call:** the dispatch memo, `take_bif_frontier` + `reset_to(mark)`, the `Rc::clone`s, the intern-commit guard, and — for `term_to_binary` only — the `Rc`-cached fun-module snapshot plus one caller-first `position()` scan in `FunIdentityBridge::new`.
**The copy-out is skipped for an immediate result.** `result_is_foreign_container` is false for a small integer/atom/literal, so such a result rewinds the pool with **no** copy; only a boxed/cons non-literal reaches `rehome_container_result`. So `term_to_binary/1` copies (its binary result is a container) while `binary_to_term/1` decoding to a small int does not. `term_to_binary`/`external_size`/`fun_info` additionally build `FunIdentityBridge::new` on every call — an `Rc` clone of the cached snapshot plus a caller-first `position()` scan that is O(loaded modules) — and `binconv.rs`'s term encoder reads the seam once per encode even for a non-fun argument.
**A small-int arithmetic `gc_bif` never reaches this node on the default tier.** `beam_engine`'s baseline JIT inlines a guarded small-int `erlang:'+'/2`/`'-'/2`/`'*'/2` inside the compiled block (`beam_engine/src/jit/baseline/emit/arith.rs::try_inline_gc_bif`), so the operation is native and `ExecutionContext::call_bif` is never called; a deopt runs one interpreter step (`jit_step_one`), not a direct BIF call. Every `call_ext*` does reach this node (the host declines `resolve_external_call` for a registered key), so a loop's `call_ext` BIFs — not its arithmetic — pay the prologue.

### The `ets` table-alias witness and the aliased copy-out (`calls.rs`)
`call_registered` declares **one** `let alias = std::cell::Cell::new(false);` per dispatch and installs it on **all ten** `BifContext` chains (`.with_table_aliasing(&alias)`), so `beam_bifs`' `ets` copy-out helpers hand back the table's own terms and set the cell (a nested call re-enters and gets its own cell).
`aliased = alias.get()` is read **before** the result block; the tail's rule is three-way:
* an **immediate/literal** result is never copied (`rewind = safe_to_rewind`), even though the helper set the cell for it;
* an **aliased container** is copied **unconditionally** through `rehome_container_result` **and before** `heap.reset_to(mark)` — the `graph_holds_reference` exemption is deliberately not consulted, because those words live in `beam_ets`'s `TermStore` (whose `free` recycles exact-fit runs) rather than the pool, and a `select`/chunked-shaped result mixes table objects with a pool-built spine/tuple that the rewind would recycle under the copier;
* a **refused** aliased copy never returns the un-copied term: it surfaces the typed `BeamError::SystemLimit` (the class `enforce_term_heap_limit` maps an allocation refusal to), leaving the pool un-rewound.
`heap.reset_to(mark)`/`put_bif_heap` still run on every path and `x(0)` always gets the copied term.
`notes::alias_marks`/`alias_snapshot`/`alias_copy_pool` (the copy site's `(mark, used)`) make all of it deterministic; `used > mark` is the ordering witness.
Measured (release `beam_rt` vs the pre-change binary, `tools/bench`'s paired `case_ets_copy_ns_per_op`, 250 000 ops, one core): the clean per-op levels are disjoint — old **2926–3261** ns/op vs new **2382–2624** ns/op (≥ **11.5 %** gap), best estimate **−11 % … −27 %, centred ≈ −16 %**; the structural figure is `ets:lookup/2` of one `{k,42}` object **5 → 2** words written, `tab2list/1` of three objects **15 → 6**, `lookup_element/3` of a boxed element **3 → 0**, a miss **0 → 0** (`../../../beam_bifs/CONTEXT.md`).
`etf_roundtrip` and `list_walk` show no move outside the ±4 % noise band; `send_recv`/`send_recv_plain`/`gc_bound` churn flip sign across rounds and are inconclusive — the shared host ran at 21–64 loadavg on 14 cores, so only 1 of 5 pre-registered rounds passes a strict load filter and the clean **level ranges** are the evidence, never a single round's ratio.
Oracle evidence: all **95** differential `ets` corpus cases agree (`differential run <case-id>` per case, then `merge` — `total=95 agree=95 mismatch=0 unsupported=0`), and the crate gate `cargo test -p beam_rt --lib -- context::` is **268 passed / 0 failed / 3 ignored**.

## Known Issues

Every entry is a typed capability gap, a measured own-state difference or a documented divergence, never a wrong
result.

* **An `ets`-read reference is copied, so it keeps its identity but not its `-eval`-route timer registration.** `graph_holds_reference`'s exemption does not apply to an aliased result (memory safety wins), while `beam_term::compare::cmp_refs` compares internal references by payload words, so `R =:= element(2, hd(ets:lookup(T, k)))` is `true` and agrees with the oracle (`calls/alias_tests.rs::an_aliased_reference_result_is_copied_and_stays_identical`).
  An address-keyed consumer of a *timer* reference read back out of an `ets` table diverges on the `-eval` route — measured with the pre-change binary too, so it is not caused by this seam: `erlang:cancel_timer/1` on that reference answers `badarg` where the oracle answers the remaining milliseconds, because `erlang:send_after/3` is a native-floor capability whose timer table is not resolvable from the `-eval` store (`M1_GAPS.md` *Timers*).

The measurement narrative behind these entries is in [`../../../M1_GAPS.md`](../../../M1_GAPS.md) and [`../../../PERF.md`](../../../PERF.md); every entry is a typed capability gap or a measured own-state difference, never a wrong result.

* **The learned copy-out hint sets the `gc_bound` churn shape's growth events, and a sibling's measured table sits on top of that.**
  The gate grows the nursery **before** a copy-out instead of after a refusal, so the churn loop (which copies out a 257-word `list_to_tuple/1` result per iteration) takes a `Process::grow_nursery` **retire** wherever the destination would not fit — one retired space is one collection debt, settled by the next heap-admission door's `collection_debt()` arm, and the retired chain is one young space at every measured N.
  The settling collection sizes the nursery from the round's own **young live set** (`HeapPolicy::young_after_collection`: target `young_minor_target_words(live) = next_words(live + need_reserve_words)`, kept anywhere inside `[target, YOUNG_SHRINK_FACTOR (8) × target]`), so the shape's schedule is a fixed point of that rule and flat in N: at N = 2 000 / 4 000 / 10 000 it measures **3 468 / 169**, **6 939 / 337** and **17 341 / 838** collections and majors over 2 001 / 4 001 / 10 001 calls — **1.7331 / 1.7343 / 1.7339** collections and **0.0845 / 0.0842 / 0.0838** majors per call — on one young space of **1 220** words capacity (1 065 used) and **4 185** mature words (4 068 used), the keep-band fixed point of the shape's ~158-word live set (`young_minor_target_words(158) = 233`, band `[233, 1 864]`).
  The gate's own wall-time delta on this shape needs a gate-disabled build and is not claimed; the row-by-row authority is `src/runner/tests/boundary_cost.rs::MEASURED` and `src/runner/MEASURED.md`, whose figures each row's own printed counters re-derive. Numbers: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-learned-copy-out-hint--copy_out_hint--hint_grow_gate-the-copy-bound-fix).

* **The copy-out is a second full traversal the C runtime never pays** — it is architectural, not slack; the
  measured split, the learned hint and the cross-crate handoff that would elide it are

## Test Strategy

The suites below read the `#[cfg(test)] mod notes` structural counters — `note_alias_mark`/`note_alias_copy`/
`note_alias_copy_pool`/`note_alias_refusal`, surfaced as `alias_marks`/`alias_snapshot`/`alias_copy_pool`, the copy
site's `(mark, used)` — so a change in ordering is observable.
The non-aliased cascade beside them (`result_is_foreign_container` / `graph_holds_reference` / `move_container`) is
unchanged, and `reset_to`/`put_bif_heap` run on every path.

* Colocated units in `tests.rs` + `test_support.rs`: the `uses_*` predicates (incl. their pairwise disjointness and the `uses_memory_hook`/`uses_fun_identity`/`uses_export_gate` gates), the `install_tables` rule (`tables_capable_names_exactly_the_table_registry_seam_consumers`), `RecordBridge` over a loaded module's `Recs`, `NodeIdentity`'s internal-pid `NEW_PID_EXT` encoding, `FunIdentityBridge`'s clean-miss contract, the nested-BIF seams, `PendingInterner` and the export gate's six cases.
  `a_table_less_context_grows_its_pooled_bif_region_instead_of_exhausting_it` pins the frontier growth (it fails with the growth branch disabled).

* **`calls/alias_tests.rs` → the aliased copy-out suite (6 cases).** `an_ets_result_survives_the_tables_own_storage_being_recycled` (a skipped copy returns the re-inserted equal-size object), `an_aliased_container_is_copied_before_the_pool_is_rewound` (`marks>=1`, `copies>=1`, `refusals==0`, copy site `used > mark` — a tail that rewound first records `used == mark`), `a_chunked_select_result_is_copied_out_whole` (the mixed table-object/pool-spine shape), `an_aliased_immediate_is_never_copied_out`, `an_aliased_reference_result_is_copied_and_stays_identical`, and `ets_read_shapes_agree_with_the_oracle` (8 read verbs + the `setelement/3`-mutates-nothing case against the live `erl`).

* **The copy-out is pinned by five cases in `calls/tests.rs`** reading the `#[cfg(test)] mod notes` structural counters: `the_copy_out_always_hands_the_copier_an_empty_destination_table`, `a_refused_copy_adopts_nothing_into_the_runtime_store` and `an_exhaustion_refusal_grows_the_nursery_and_the_retry_copies`; plus the learned-hint pair — `a_collecting_default_process_copies_every_result_without_refusing` (a DEFAULT-policy process driven through the real admission/collection cadence, `Process::collect_if_needed` between copy-outs, asserting `refusals * 8 <= copies` while collections really happen and the gate is what serves the copies) and its control `without_the_learned_hint_the_same_cadence_refuses_again` (the hint zeroed every op: ≈1.0 refusals/op, no gate growths), so the pin cannot be satisfied by anything but the hint.
