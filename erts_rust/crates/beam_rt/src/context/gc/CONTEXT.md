# `beam_rt::context::gc` — heap doors, allocation seams and the off-heap prunes

## Intent

The GC/heap half of the concrete `ExecutionContext`: where a scheduled process's memory comes from, when a collection may run, and how off-heap payloads are released.
It owns the five collection sites with their no-relocation growth/retry discipline and the allocation seams' valve-free bump fast arm, the per-word unscanned-root classifier with the reachability walk that gates every collection and prune, and the two off-heap prunes (the machine's refc-binary reservoir and the NIF resource terms).
The seam-level contract is [`../CONTEXT.md`](../CONTEXT.md)'s; the root-set/relocation seam is [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md)'s.

## API Surface

### The off-heap refc-binary reclamation — `gc/bin_vheap.rs`
A process's off-heap refc binaries live in the machine's reservoir (`Machine::refc_binaries`), outside every heap the collector owns, so a collection can never sweep them: they are **pruned separately**, at the slice boundary.
`gc/bin_vheap.rs` owns that point — `OffHeapReclaimer` is a process's binary virtual heap (the C `p->bin_vheap_sz` through `beam_gc::BinVheap`, plus the observed `MSO(p).overhead`) and `reclaim(runtime, table, pid, machine, slot)` is the prune.
`observe` is `O(1)` while the reservoir's handle count has not moved (the engine only ever appends between prunes), so `Machine::off_heap_overhead_bytes` — `O(reservoir)` — is read only when the count moved or once per triggered prune, never on the per-slice path.
`triggered()` is the C's `off_heap.overhead > bin_vheap_sz` (strictly greater, bytes turned into words by truncating division), and `record_collection` reproduces the C's `p->bin_vheap_sz = next_vheap_size(...)` / `MSO(p).overhead = bin_vheap` pair from the payload that survived.
The release is `Machine::retain_refc_binaries` with `live(p) || shared(p)`, where `live` is what `beam_gc::for_each_reachable_binary_payload` reports over the process's roots and `shared` is every payload at `RefcBinary::refcount() > 1`.
It **moves nothing** — a retained payload keeps its exact `data_ptr`, so no live on-heap `BinRef` is invalidated — and the `shared` set is the belt for the second owners this process's roots do not describe (the send path's envelope clone, `Runtime::eval_off_heap`, a writable accumulator).
The state is per process engine (`ProcessEngine::off_heap`), built lazily from `process.collector().policy()` so a `+hms`/`+hbm*` policy is honoured, and it dies with the machine.
**Every gate is a decline**, i.e. the whole reservoir is retained and `Ok(0)` is returned — a leak, never a dangle: the pid is not in the caller's table; `Process::is_relocation_exempt()`; `!Runtime::gc_process_enabled(pid)`; the bin vheap has not triggered; the collection valve `valve_verdict` declines; the **prune-only** valve `gc_walk.rs::reaches_an_unscanned_word` declines; or the reachability walk returns a typed error (traced, then declined).
Both valve declines open the per-pid descent latch (`Runtime::note_foreign_reachable`) exactly as a declined collection does, and **neither closes** it — closing stays with the three doors that hand the walk the machine's whole `RootSet`.
`Process::has_unpublished_roots()` is deliberately **not** a gate: it is `true` for a `ProcessState::Running` process, which a pre-empted process still is, so consulting it would disable the point entirely; the correct pair is `is_relocation_exempt()` plus the park's own `parked_published` flag.
Afterwards `Process::set_off_heap_binary_bytes` republishes the surviving figure, so `max_heap_size`'s `include_shared_binaries` charge sees real bytes.
A released payload's bytes leave `binary_alloc`, so `erlang:memory(binary)` — `memory_hook.rs`'s `allocator_live_bytes(AllocType::Binary)`, read live on every call — reflects the release; that is a **different** observable from `erlang:process_info(P, binary)`, which is the per-process roster (`../native/memory/binary.rs`).
**A second, disjoint reclamation covers the `-eval` route's escaped store** — `src/eval/reclaim.rs`, reached from `Evaluator::prune_escaped` at the tree-walker's depth-0 statement boundaries (`eval/mod.rs`). It is not this arm: different store (`Runtime::eval_off_heap`, not a `Machine` reservoir), different trigger (handle count moved **and** summed `reserved_bytes` > `STORE_BUDGET_WORDS` = 46 422 words, the C's `BIN_VH_MIN_SIZE`) and different roots.
Its guards: the **named live sets** (evaluator env + reduced value, escaped closures' envs, `seq_trace` tokens, every process's dict + mailbox, pending spawns) are walked as terms — they may decline; the runtime's **term regions** (`eval_heap` + retired, pooled BIF heaps, `info_heap`) are scanned as **word images** ([`Runtime::for_each_off_heap_region`](../../runtime.rs)) by the `HEADER_BIN_REF` pattern only, dereferencing nothing, and are **never** pushed as roots (a region interleaves heap objects with the raw payload words of on-heap binaries — `binary:copy(<<1>>, 40000)`'s `0x01` bytes read as `0x0101_0101_0101_0101`, low bits `TAG_PRIMARY_LIST`, which dereferences to a `SIGSEGV` in `walk` — the shape `base64:encode(binary:copy(<<1>>, 40000))` produces on its fourth `-eval` statement, i.e. the first whose summed payload bytes cross the budget); any doubt (visit budget, unknown boxed header) **declines** the whole prune; `RefCount > 1` ⇒ retain.
Measured with `tests/eval_off_heap_reclaim.rs`: 20 evals × 6 throw-away `base64:encode(binary:copy(<<1>>, 40000))` builds (120 payloads) stay at **≤ 327 680 bytes / ≤ 5 handles**, sawtooth, with **23 prunes** and 0 declines; the same loop with the reclaim off (`Runtime::set_eval_prune_enabled(false)`) reaches **7 864 320 bytes / 120 handles** — exactly one per build.
The `run` route's nested-call payloads are covered by a third entry point on the same store: the nested-run epilogue (`context/pump.rs` → `RuntimeContext::adopt_nested_payloads` → `Runtime::prune_off_heap`) adopts every handle the finished machine built, publishes that machine's **own** root set (its X registers, its whole Erlang stack and its FR file through `Machine::with_roots(RootSet::ALL_LIVE)`, plus the term it is about to return), and prunes against it unioned with the guards above — the guards, the root build and the walk are the same code, and the gate is `O(1)` (`Runtime::off_heap_prune_pending`, one handle-count compare in the steady state, so a hot lambda application pays nothing).
That prune releases **only** the handles the run itself adopted; an out-of-scope entry is retained unconditionally, because a nested site can name one machine's roots while the *enclosing* machines of the same process hold terms this crate cannot see — measured: sweeping the whole store there makes `lists:map/2` over 200 engine-built 40 000-byte binaries return **190 corrupted elements**, against 0 when it sweeps only its own handles.
Uncovered, each a leak and never a dangle: `apply_eval_closure` (never prunes: its caller's terms are live and unnameable), the engine arena (`beam_engine::MinimalContext`'s `ContextHeap` has no word-range accessor) — covered only nominally, because the region scan finds a `[BinRef][ErlSubBits]` pair by its own header wherever it stands — and the `eval_heap` **region** (the region, not the payload store), whose growth is bounded by the statement window that `../eval/scratch.rs` runs before each top-level `-eval` statement — with two residuals by construction, a single giant statement (its value *is* the result) and a growth whose region the sibling `src/runtime/reclaim.rs` pass has not yet proven dead.
A nested run that **raised** takes the plain adopt path and leaves the store alone: a raise's reason term rides `beam_common::Raise`'s live-reason slot rather than the frozen root set, so no root can name it.

The one call site, its per-slice cost and the residuals: [`../../runner/CONTEXT.md`](../../runner/CONTEXT.md) *The off-heap refc-binary reclamation at the slice boundary*; the criterion's mechanics: `gc_walk.rs`'s module docs.
The measured envelope this point produces — the N-step figures, the sawtooth ladder, the A/B and RSS pair and the retained-payload half — is [`../../../CONTEXT.md`](../../../CONTEXT.md) *Known Issues / Intentional M1 gaps*'s off-heap bullet; the suite is [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs).
The end-to-end effect on a real workload — `emqx_base62:encode/1` on the unmodified EMQX module, `PRE-FIX` vs `POST-FIX` vs the oracle — is [`../../runner/MEASURED.md`](../../runner/MEASURED.md) *The off-heap reclamation end to end*.

### The NIF-resource-term prune (A.3) — `gc/resources.rs`
`reclaim(runtime, table, pid)` is the caller half of `beam_abi`'s resource-release seam: it drops the reference every resource **term** took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs (`beam_abi/src/nif/enif/resources_release.rs` documents the soundness contract — a false "unreachable" is a use-after-free).
The **scheduled** site is the runner's `Yield` park arm, immediately after the off-heap refc-binary prune and under the same `engine.parked_published` gate; an exempt (`Wait`) park publishes nothing and both prunes decline, and the routes that never park (`-eval`, a nested run) are served by the two non-park sites in `../eval/reclaim/resource.rs`.
Gates, all declines: an empty `resource_terms()` (one registry read, no walk), the process is in the table, `!Process::is_relocation_exempt()`, `Runtime::gc_process_enabled(pid)`, and the prune-only valve `gc_walk.rs::reaches_an_unscanned_word` — classified over the **process's own** roots only, never the host root sources, which are a *separate* seed set handed to the reachability walk because every host word is a `WordRegion::Foreign` root and folding them into the valve would decline every prune a resource program attempts.
The walk (`gc_walk.rs::reachable_resource_words`) then collects every reachable candidate word **or reference identity** — a resource term is an internal reference, so a `copy_struct` copy (the send path, ETS) is a different word with the same id, and matching the word alone would free an object a live copy still designates.
Residuals: a candidate whose identity cannot be read is kept; the cadence is the park cadence (a target that returns immediately never parks, and the `-eval` route never parks at all); a resource held only by a store no site enumerates — a `persistent_term` value, an ETS object — is released, because the host root sources are exactly the families `Runtime::gather_off_heap_roots` publishes (the escaped closures' environments, the `seq_trace` tokens, `pending_spawns`, every pending timer **delivery**, every live process's dictionary/mailbox/registers/saved-args/signals, and an engine's un-consumed arena-stable arguments plus an un-published parked machine's root set); the two per-pid families are empty **at this arm** — a pass moves the process table (`take_processes`, an equivalent empty placeholder) and `RunnerState` out of the runtime — so they are live only at the two non-park sites (`../eval/reclaim/resource.rs`), and the executing process's own roots are the arm's **local** list; and the identity match is by reference **identity** (the `id` word, which every local reference producer draws from one shared space), so a copy of a resource term is reached wherever it is reachable from — a copy in a region nothing names stays dead data.
Detail, ground truth and the residual list: `gc/resources.rs`'s module docs; the pinning suite is [`../../../tests/nif_resource_gc.rs`](../../../tests/nif_resource_gc.rs).

### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` (`runtime_hooks.rs::garbage_collection`) answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's **node-global cumulative** counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran, and `reclaimed` (in words) is advanced by each collection site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`, never an estimate.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`, where the oracle's are per-scheduler accumulators of a far larger emulator: the quantities match, the magnitudes do not.
The five collection sites and the accounting detail: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#erlangmemory01-and-erlangstatistics1).

### `erlang:memory/0,1` and `erlang:statistics/1`
`erlang:memory/0,1` (`MemoryHook` seam) is adopted: `RuntimeMemory` (`memory_hook.rs`) returns nine oracle keys in oracle order with `total = processes + system`, every figure measured (process heaps from `ProcessTable`'s collectors, atoms from the shared `Rc<AtomTable>`, binaries from `beam_alloc::registry`, `code` from loaded `.beam` sizes, `ets` from `TableRegistry`, `system` = those plus the remaining allocator live bytes excluding `Standard`/`EHeap`) and snapshotted at construction; `memory/1` answers in the requested order, `badarg` for an unknown key.
`erlang:statistics/1` is partly served — `run_queue`, `run_queues`, `run_queue_lengths(_all)`, `total_run_queue_lengths(_all)`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io` and `garbage_collection` (`{GCs, WordsReclaimed, 0}` from the node-global cumulative counters) — while `scheduler_wall_time`/`scheduler_wall_time_all` ⇒ `undefined` (no per-scheduler wall time is sampled, so the tuple list is never fabricated).
Gaps: `statistics/0`, the per-scheduler key family (`active_tasks*`/`total_active_tasks*`/`microstate_accounting`) and every other `RuntimeHooks` family — see *Closable host-seam keys* above.

### The allocation seams — the bump fast arm and the doors' gate order
`alloc_words_rooted` (`gc.rs:1781`) has a **fast arm** ahead of every collector valve: after the forced-request peek, when the context has both `mailbox_table` and `current_module`, it takes the pid's own `&mut Process` and serves the block with `plain_bump` (`gc.rs:281`) — one arityval header word plus `n - 1` placeholders filled from `static PLAIN_BUMP_FILL: [Eterm; 32]` of `NIL` immediates (`PLAIN_BUMP_FILL_WORDS = 32`, `gc.rs:247`).
Those placeholders are **not** GC roots: an immediate names no region, and the engine overwrites them before the block they pad is reachable — the same contract the pooled scratch slice has.
The arm builds no `Result<_, BeamError>` (both of `bump`'s refusals are plain comparisons, so no error variant materialises) and calls **no** `Runtime::gc_process_enabled`; a `None` from `plain_bump` is not a swallowed error but "not the fast case", and the caller re-enters the real `bump` on the cold path where the error is handled exactly as before.
**Why skipping the valve is sound**: pinning and halting constrain *collections* and *growth* — both of which move or retire a space — while a bump moves nothing, so the valves cannot change a bump's answer; a pinned or halted process therefore keeps allocating on its own (never collected, never grown, so never collapsed) **scanned** young heap instead of being pushed to the pointer-stable arena, which is also strictly better for the unscanned-root valve, since an arena block is a container no collection may descend into.
The forced-request peek is what keeps the arm honest: an armed `erlang:garbage_collect` request bypasses the bump and takes the collection path, so a request is never carried silently to the pass boundary.
Everything the arm declines — no room for `n`, `n` past the static fill (`PLAIN_BUMP_FILL_WORDS + 1` words), or a forced request — falls through to the unchanged cold path: `grow_nursery` with the retried `bump`, `may_replace_young_space` at every growth site, `machine_root_bounds`, `valve_verdict`, the once-only `take_gc_request`, `scatter_roots_full` and the arena fallback.
The engine's per-cons-cell reservation is two words (one placeholder), so the static fill covers it with two orders of magnitude of headroom; a larger block simply takes the cold path and fills from `Runtime::gc_scratch`.
**`ensure_heap_full`'s gates are cost-ordered** (`gc.rs:1369`): the occupancy/`collection_debt` snapshot is taken first and returns before any valve read (`:1427-1433`), `gc_request_pending` is read only where it can change the answer and re-read for `forced` (`:1437`), and the collector valve keeps its own place after the root-width bound (`:1473`).
The order is verdict-identical: `churn` at N = 20 000 reports **46 089** collections through `erlang:statistics(garbage_collection)`.
**Measured** on `bench_gc_bound:churn/1 20000`, against the same shape with the fast arm removed: `gc_process_enabled` runs **46 979** times from this module, where consulting the valves per rooted allocation makes it 31 052 161 — and it takes no profile samples (1.08 % of self time in that shape), so the read is off the per-term path.
The admission count is unchanged at 15.5 M `ensure_heap_full` + 15.5 M `alloc_words_rooted` (mean 2 words per rooted allocation), and the fast arm serves **99.9999 %** of them.
The run retires **6.15 %** fewer instructions, and its paired wall-clock median over 5 alternating rounds is **5.27 %** lower (band 0.943–0.974).
On the foreign workloads instructions retired are **2.78 %** lower on `emqx_base62:decode` and **0.13 %** lower on each of `cowboy_bstr:to_lower` and `capitalize_token`.

### Cheap heap doors: the hot entry / cold continuation split (measured — do not re-derive)
Both full-root doors are **two functions**: an `#[inline]` hot entry that decides "nothing to do" and a `#[cold] #[inline(never)]` continuation holding everything that acts — `ensure_heap_full` → `gc::ensure_heap_full_commit`, `alloc_words_rooted` → `gc::alloc_words_rooted_commit`.
The lever is the one wave 2 used on the dispatch frontier (`context/calls.rs`'s `take_bif_frontier` + `grow_bif_frontier`), and for the same reason: a frame LLVM must keep reachable from **one** prologue is a tax on every caller, so valves, `machine_root_bounds`, `valve_verdict`, `take_gc_request`, `scatter_roots_full`, `ensure_capacity`/`collect_or_grow` and the arena fallbacks no longer sit in the same function as the bump.
The continuation **re-derives** what it needs (pid, `call_site_known`, `forced`, the `&mut Process`) instead of receiving a borrow from the hot entry: a `&mut` escaping into a non-inlined callee recreates exactly the frame the split removes. That costs one extra `ProcessTable::get_mut` on a path taken once per ~331 admissions — not measurable.
The gate **order** is unchanged (latch → request → valves → caller module → commit-once) because the hot entry's short-circuit is a **precondition** of the continuation, never a decision the continuation re-makes: every re-read is a pure read of the same instant.
`plain_bump`'s fill is a **constant-length** slice for `n ∈ {1,2,3}` (`PLAIN_BUMP_FILL_ONE`/`_TWO`, `gc.rs`), not `&PLAIN_BUMP_FILL[..n - 1]`: the runtime-length copy lowered to a **GOT-indirect `memcpy@GLIBC` call** on the per-cons-cell (`n == 2`) path, which `perf annotate` attributed 1.95 % of the whole `churn` run to (`non_null.rs:1650`). A larger request keeps the dynamic fill — it is already on the cold side of the length test and `memcpy` is the right lowering there.
The forced-request peek stays **inlined**. Outlining it was tried and **rejected on measurement**: `#[inline(never)] fn forced_gc_request` costs 26.22 G against 26.01 G inlined on `churn` at N = 20 000 (+0.78 %), because `gc_request_pending`'s own body is one `is_empty` load after inlining, so a call is dearer than the spills it avoids.
`#[inline(always)]` on the three `ExecutionContext` heap-door impls (`execution.rs`) was also tried and **rejected**: 26.04 G against 26.01 G (+0.1 %), i.e. the bloat in `runner/budget.rs`'s impl outweighs the trampoline it removes. Plain `#[inline]` (a 6-instruction trampoline: latch take + call) is what ships.

**Measured** (`bench_gc_bound:churn/1 20000`, `taskset -c 2 perf stat -e instructions:u`, `cpu_core/instructions` only — this hybrid CPU emits two PMU instances): control **26.447 G**, new **26.015 G** = **−1.63 %** raw, **−1.82 %** on the marginal (`N=20000` minus `N=0` ≈ 2.68 G), spread 0.04 % over 3 alternating reps. Of which: the door split alone ≈ −0.46 %, the constant fill ≈ −0.8 %, and the inlined peek the last ≈ −0.4 %. A rebuild of the control from its own source is **bit-identical**, so there is no two-build spread to subtract.
**The collection cadence is unchanged**: `churn` at N = 20 000 reports `erlang:statistics(garbage_collection)` `{48013, 37294061, 0}` on both binaries, and the `BEAM_RT_PERF_COUNTERS=1` per-key dispatch table is identical key for key.
**Remaining per-admission cost, by owner** (all outside this node, so each is a report rather than a fix): `beam_alloc::Heap::tuple` → `bump::tuple_at` is ~27 instructions of the reservation (1.63 % of the run in `churn`) — a *safe* `Heap` primitive that writes the header and placeholders and returns the base **without** building a `Result<Eterm>` would bound it; `ProcessTable::get_mut` is probed twice per admission (`imul $0x23e0` + serial + state test, ~8–10 instructions each) and the raw-pointer memo needed to halve it is **refused** (an eleventh `unsafe` exemption); and the doors' own 7-push/pop frame (~14 instructions) stays because the inlined `gc_request_pending` puts a SipHash `contains` call in the same body — splitting `runtime/gc.rs::gc_request_pending` into a cheap `is_empty` inline plus an outlined `contains` would remove it (≈0.8 % bound), but that file is a sibling and must not be edited from here.

### The unscanned-root valve — two phases
Phase 1 (`root_is_unscanned`, always run) declines over a term only when **both** facts hold: the term is a container in a region the collector does not **scan** (`word_region` → `WordRegion::Foreign` — the pooled BIF heaps, the `-eval` heap, the pointer-stable arena, a message fragment) **and** at least one word it forwards is a pointer the collector *does* scan (`forwards_scanned_word` → `word_is_scanned`: any nursery space, current or growth-retired, or the mature generation). Everything else is inert and declines nothing: an **immediate**, a **literal**, and a word no live term can be at (null or unaligned — `dereferenceable_pointer` rejects those before anything reads them) name no region; and a foreign leaf, all-immediate block, tuple of immediates, reference, pid, port, float, bitstring or empty tuple forwards no word a relocation would follow or update. `forwards_word_matching` drives the same `beam_term::layout::for_each_child_slot` enumeration the copier and phase 2 use, so the valve cannot disagree with the collector about which words an object forwards — `SUB_BITS_SUBTAG`'s `orig` word *is* forwarded, so an `ErlSubBits` over a live word declines while the same shape over a literal is inert. This is what keeps `make_ref/0`'s all-immediates M1 block (an `INTERNAL_REF_WORDS` leaf on the pooled BIF heap) from pinning a loop's valve.
Those three **term-only** tests have their own entry point, `gc::result_may_be_foreign(term)` — the same `gc.rs::foreign_shape_pointer` the region classifier continues from, so the two can never disagree — for the one caller that has a candidate word *before* it has a `Process`: the BIF-result gate `RuntimeContext::open_gate_for_foreign_result`, which runs once per successful `call_bif` and shape-tests the result before probing the process table. `gc/valve_bounds.rs::the_result_shape_test_is_the_region_classifiers_own_prelude` pins the agreement over every word shape (immediates, a literal, a fabricated container pointer, a heap boxed term, a heap cons) on both collector kinds.
Phase 2 (`gc_walk.rs`) descends the process's scanned graph and root containers under the per-pid descent latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found; the per-word phase alone sees only a root's *own* address.
The valve is consulted at each of the five collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the runner's park arm `Runtime::serve_gc_request`, and `gc/reds_door.rs`'s reduction/yield-boundary door) — at `alloc_words_rooted` on its **cold path only**, since a block the bump fast arm serves returns before it (see [the allocation seams](#the-allocation-seams--the-bump-fast-arm-and-the-doors-gate-order)); declining costs a collection and nothing else — the allocation falls back to the pointer-stable arena — so it can never turn a working program into a failing one, and the fallback count is `note_gc_fallback`'s.
The latch's two halves split by **root-set completeness**: a door that hands the walk the machine's *whole* `RootSet` (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`) **closes** the pid's bit on a `ValveVerdict::foreign_free` descent (`Runtime::close_foreign_reachable`), while the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` signal sites hand over less than the whole set — `ensure_heap` cannot see the FR file, and an *exempt* park publishes nothing — so they may only **open** it.
The gate a `beam_process` signal site consults is built from the runtime's **one** shared latch cell (`RuntimeCollectionGate::from(latch)`), so a decision is `O(1)` while the pid's bit is clear; the no-latch `RuntimeCollectionGate::new()` form (which always descends) is `#[cfg(test)]`-only.
A term in a foreign region (pooled BIF heap, arena, `-eval` heap, message fragment) declines the collection only when it forwards a scanned word — **not** a foreign term that forwards nothing (see phase 1 above) — and never a registered-BIF result, which `call_registered` copies onto the running process's heap and rewinds the pool to the call's own `mark`, making it a scanned root rather than a foreign holder.

### The root-set hand-off widths (no clamp ever binds; one width per door)
Every door takes the machine's own slices from `Machine::with_roots`, which hands `x[..used_x_extent()]` / `fr[..used_fr_extent()]` (`beam_engine/src/machine/mod.rs:857-863`), and `used_extent = mark.max(dirty).min(len)` (`beam_engine/src/machine/registers.rs:108-110`), so `used_fr_extent() >= fr_mark()`.
The reds door's `let fr_count = fr_count.min(roots.fr.len())` (`gc/reds_door.rs:252`) therefore never binds: the runner passes `engine.machine.fr_mark()` (`runner/run.rs:1221`, `:1295`, `:1313`), which is always inside the handed slice.
`publish_roots_full`/`scatter_roots_full` apply the *same* clamp (`gc.rs:801`, `:846`), so one hand-off's two halves can never disagree on the published FR length — the `false`-halts-collection-forever hazard the door's doc warns about is unconstructible from these call sites.
The **x** width is the one a door deliberately chooses: `ensure_heap_full`/`alloc_words_rooted` publish `roots.x` in full (`publish_roots_full` ignores `RootSet::live`), while the narrow `ensure_heap` publishes `x_regs.len().min(MAX_REG)` over an x-only slice and no FR file (`gc.rs:1177-1183`, `publish_roots`).

### Debt/valve cost of the admission doors
`collection_debt()` is folded into both doors' occupancy OR, so a growth-retired chain makes `ensure_heap_full` evaluate `any_root_is_unscanned` on **every** admission point even when the *current* space has room; `alloc_words_rooted` reaches the valve only where its bump fast arm declines (no room for `n`, a block past the static fill, or a forced request).
The per-word `root_is_unscanned` classifies in **three stages**, cheapest first (`gc.rs::word_region`: `foreign_shape_pointer` → `in_heap_block` → `outside_bounds`).
Stage zero is **term-only** and needs no `Process`: `is_pointer_bearing` (an immediate exits here — the commonest word by far), the literal-area tag (a frozen code constant never points into a movable heap), then `dereferenceable_pointer` (rejects null/unaligned, which no live term word is). `result_may_be_foreign` is that prelude alone, for the one caller that has a candidate word before it has a `Process` (the BIF-result gate).
Stage one is the current mutator block `[base, hend)` — the answer for nearly every live root, and it is tested **before** the aggregate, so nothing it accepts pays for `outside_bounds`. Its two bounds are **hoisted out of the walk**: `Walk::begin`/`begin_resource` derive a `Copy` geometry companion (the block's `[base, hend)` beside the `ScannedBounds` the caller already read) and thread it down, so the per-word path is two register compares instead of three `Process`→`Heap` loads (`heap.used()`/`hp()`/`hend()`). The standalone entry points (`root_is_unscanned`, `word_region`, `word_is_scanned`) stay thin wrappers that derive the geometry themselves, so out-of-walk callers are unchanged.
Stage two is the collector's **aggregate geometry**: `AnyCollector::scanned_bounds()` is read once (`O(1)`, allocation-free — the nursery chain's half is cached inside the chain, the mature half is two reads) and `ScannedBounds::definitely_unscanned` answers for every address outside it with two compares.
Only what the aggregate cannot decide — a growth-retired nursery space, the mature generation, a hole between two scanned regions — reaches the exact tests `outside_scanned_ordered`, in the order that answers a real graph fastest: `AnyCollector::mature_contains` **first** (an address in the mature generation then answers without consulting the nursery at all), and the nursery half only when a growth retired a space — with `young_space_count() == 1` that one space *is* the mutator block stage one already rejected (`HeapSpace::contains` is `[base, top)` ⊂ `[base, hend)`), so the whole half is `false` by construction and costs nothing. `!young_contains(p) && !mature_contains(p)` is commutative, so the reordering cannot change an answer; a `debug_assert` re-derives it from the reference `outside_scanned_exactly` on every debug build (which is how the whole lib suite, including the in-process stdlib compiles, checks the shortcut against the oracle rather than trusting it). Where the nursery half does run, it is `Collector::young_contains`/`Nursery::contains` in **O(log #spaces)** (the current space is tested directly, since it is the only space whose `top` moves, and a retired-space address is resolved through the ordered `BTreeMap<base, top>` containment index `retired_regions`, `range(..=addr).next_back()` — exactly the predicate `spaces().any(|s| s.contains(ptr))` because the retired regions are disjoint).
The reject is sound in **one** direction only: the aggregate is the covering interval of every scanned region's **reserved** extent, so `definitely_unscanned == true` proves both exact tests would answer `false` while `may_contain == true` claims nothing, and a fast *accept* is never taken.
On the boot workload the aggregate decides almost nothing: `tier2_share` is **0.968** (1 847 171 of the 1 909 104 classified container words fall through to the exact tests, and 1 847 133 of those are found *scanned*), which is why the mature-first order and the single-space shortcut are what the exact half is shaped around.
The chain is collapsed only by a real collection (`Nursery::collapse`), so a growth-retired chain keeps `ensure_heap_full` evaluating `any_root_is_unscanned` on every admission point (see `collection_debt()`); the allocation seam's own per-term path is the valve-free bump, so a debt-carrying process pays no descent per built term.
Measured aggregate widths (`gc/valve_bounds.rs::the_aggregate_span_is_reported_for_both_collector_kinds`, which prints the live figure per geometry — the absolute width is allocator-placement fact and moves between runs, so the shape, not the exact count, is what generalizes): a fresh process spans on the order of **500** words on the copying strategy (233-word nursery + 233-word mature + the gap) and low thousands with the `BEAM_RT_GC_STRATEGY=immix` mature opt-in (a 2048-word mark-region mature at a different offset); a growth that retires a nursery space widens both, and a collection that resizes the nursery collapses the chain and installs a space elsewhere — a representative run printed 469 / 2284 fresh, 848 / 2662 grown and 3489 / 5304 collected (copying / immix).Every region this runtime really produces outside the collector — the pooled BIF heap ([`Runtime::take_bif_heap`](../../runtime.rs)) and the pointer-stable arena ([`Runtime::alloc_words`](../../runtime.rs)) — lies outside all of them, so the reject fires for all four foreign shapes the valve meets (tuple, cons, `ErlSubBits`, `make_ref/0`'s leaf) on both strategies; the interval is **not** monotone (a collection collapses the chain and installs a space sized from the live set), which is why the bounds are re-read rather than cached.
Profile cost, `perf record` on 24× in-process `compile:file("lib/stdlib/src/ordsets.erl")` samples (`taskset -c 3`): `Nursery::contains` self time is **0.043 %** of samples (the exact tests the reject removes are 0.06 points of it), `root_is_unscanned` self time is **0.39 %** and `Walk::run` **0.44 %** — the skipped exact tests and the added bounds read are the same order, so the filter is neutral on this workload; on a reference-minting `send`/`receive` loop at 200 000 iterations it is **0.3 % fewer instructions** and **0.5 % fewer branches**, and no sample moved a valve decision (the counters are below).
The valve's **decisions** are unchanged by construction and are pinned twice: `gc/valve_bounds.rs::the_two_tier_test_matches_the_exact_predicate_in_every_region` asserts `root_is_unscanned` equals the pre-filter expression (kept verbatim as the oracle) for the current space, a growth-retired space, the mature generation, the pooled BIF heap, the arena, an immediate, a tagged literal, the inert foreign leaf and a foreign container forwarding a scanned word, on **both** collector kinds; and `the_filter_does_not_change_a_collections_counters` asserts a fixed root set collects identically every time. End to end, 8 in-process compiles of `ordsets.erl` report `erlang:statistics(garbage_collection)` `{63, 1268177, 0}` and `{heap_size, 233}`/`{total_heap_size, 466}` on both binaries.
The valve accessors in `../runtime/gc.rs` (`gc_process_enabled`, `gc_request_pending`, `foreign_reachable`) test `is_empty()` before hashing, so an empty valve set costs no hash — and none of them is on the per-term bump path, which is why `gc_process_enabled` runs 46 979 times per `churn` run rather than once per rooted allocation (see [the allocation seams](#the-allocation-seams--the-bump-fast-arm-and-the-doors-gate-order)).

### The descent's measured cost shape — the invocation census (`gc_valve_trace.rs`)
`BEAM_RT_VALVE_TRACE=1` turns on a release-mode census (silent and free when unset: one `OnceLock<bool>` read hoisted per walk into `Walk::traced`/`Visited::traced` and threaded down as a `bool`, so no per-word path probes the environment). It prints one `[rt-valve]` block on stderr at the driver thread's exit: per-door call/descent/counts, a **per-pid** block (admissions, needs, capacities, chain/available/occupancy/debt, grew-vs-collapse-only, words copied and reclaimed, descents ÷ collections), the `Visited` insert/revisit/probe/grow figures, the seeded root words by family and the tier1/tier2 split. It never changes a verdict — it only observes — and the whole campaign below was steered by it.
Measured on the **minimal run** (`beam_rt -noshell -eval 'halt().'`, 99 `.beam` images, whole cost is the boot drive; `-version` drives no boot script and reaches 0 calls):
- **543 valve calls / 542 descents / 1 phase-1-only / 0 declined / 21 `foreign_free`.** Doors: `EnsureHeapFull` 418, `CollectionGate` 116 (holds 20 of the 21 closures), `RedsBoundary` 9; `EnsureHeap`, `AllocWordsRooted` and both prunes are **0** here.
- **1 900 260 objects visited**, `visited_peak` 8 209, **mean 3 506 per descent**; **1 925 805 inserts, 8 649 revisits, 1.045 probes per insert, 7 grows**. Roots seeded are only **22 092 words** (96.9 % registers), so the cost is entirely the **descent**, not the seeding.
- **The descent count is 1:1 with collections, not with the workload.** 542 descents against 427 collections overall, and **1.015 for the one process that dominates** (`<0.10.0>`: 404 of 542 descents, 398 of 427 collections). Admissions are exactly **1:1** with collections — no invocation is paid without a collection behind it. The other 25 processes are short-lived (1–9 collections each, ≤487 visited) and cannot explain the volume.
- So there are **two** levers, and they are different sizes: *how often* a collection runs (a `beam_gc` policy artefact — see [the shrink/grow oscillation](#why-the-boot-runs-427-collections--the-shrinkgrow-oscillation-the-count-is-a-beam_gc-policy-artefact) below, worth ≈13.5–15.4 % of the whole run) and *per-object cost within* one collection (this node's, largely taken by the landings below).
- The census also exposes the trigger mix, which is a `beam_gc` policy question rather than a valve one: of 427 admissions **165 were occupancy-driven and 262 `collection_debt`-driven**, and 237 of 427 left the nursery capacity unchanged (collapse-only) against 190 that grew it, with a mean 1 322 free words available at admission.

What the census's cost figures then bought, and where the floor is:
- **The valve is the second-largest single mechanism of the minimal run after module loading.** An ablation that turns the descent off entirely (`descend = false`) measures **−26 %** of retired instructions on the pre-optimisation tree; three verdict-neutral landings — the mature-first ordered exact test, the hoisted `Geometry`, and moving `Visited`'s room-making path out of the insert hot path — took the run **−3.17 %** in instruction terms (paired 5 rounds, spread 0.14 pp, noise floor ±0.1 %). Post-change sampled self time for this node is **≈17.5 %**, of which the walk proper is `Visited::insert` 8.6 / `Walk::seed` 4.0 / `Walk::run` 2.0; `word_region` no longer reaches the 0.5 % line. Quote the instruction delta, not the sample share, for the landings — the two are different units.
- **`Walk::seed`'s self share is not seeding.** It is `Walk::expand` inlined at the seed loop's call site: an ablation of the seed loop's per-word classification (a `#[inline(never)]` duplicate behind `black_box`) sizes the honest phase-1 work at **≤1.36 M instructions = 0.069 %** of the run, ~14× below the ±0.1 % noise floor, against a 4.0 % bucket. Machine roots, never counted before, are 18 741 words (phase 1 total 40 833). Do not optimise the seed loop.
- **`Visited::insert` is memory-bound, not instruction-bound.** `perf annotate` puts 59 % of its samples on the single slot-array load of a random probe into the 16-byte-slot table, at 1.045 probes/insert. That share is stall-weighted sample attribution, not work — the census's probe count is already near-optimal, and right-sizing the table back down was measured and rejected (it halved cache traffic but raised probes/insert 1.42→1.69, costing ~9 % more cycles end to end; the rationale is in `gc_walk.rs`'s `Visited` docs).
- **Per-walk memoisation across walks is unsound**, not merely unmeasured: a heap address is reused as soon as its object is collected, so one walk's visit says nothing about the next, and the generation-stamped reset is what makes reusing the table free.
- **The four `src/runner/` collection/reduction pins are stale and belong to that node** (bisected to a `beam_engine` local-call-verdict memo), not to the valve.

### What the doors do NOT decide
The full-root doors decide **whether** a collection may run: each one's own short-circuit — occupancy/`collection_debt`/forced at the admission doors, the reduction interval and the 7/8 occupancy watermark at `gc/reds_door.rs` — then the valve (`root_is_unscanned` over the roots the caller handed over). They do not decide **how often** it runs — the collector's own **post-collection nursery sizing** does, and that belongs to `beam_gc` (`Nursery::collapse` ← `HeapPolicy::young_after_collection`).
The distinction is what makes the A/B evidence in `tests.rs` readable.
The fullsweep path sizes both generations from the **exact live set** the round kept: the nursery through `Nursery::collapse_after_fullsweep` → `HeapPolicy::young_after_fullsweep` (`young_target_words(live) = 2 × live + need_reserve_words`), and the mature generation through `HeapPolicy::mature_after_fullsweep` → `mature_target_words(live, young_occupancy) = MATURE_TARGET_LIVE_MULTIPLE (2) × need_after_fullsweep(live, young_occupancy)` (`beam_gc/src/collector.rs::collect_major`, the immix majors likewise).
The C applies **two** rules to one heap: `major_collection` sizes it from the pre-copy young usage (`erts/emulator/beam/erl_gc.c:1866`), and `adjust_after_fullsweep` then **shrinks** it to `2 * need_after` once `4 * need_after < HEAP_SIZE`, with `need_after` the **live** set plus the caller's need plus `S_RESERVED` (`erl_gc.c:2062-2098`).
The two steps collapse into that one live-set decision here, because a nursery's occupancy is bounded by its own capacity (`Nursery::used_words() <= Nursery::capacity_words()`), so the pre-copy figure can never signal growth beyond the live set.
**Measured consequence** on the `ets_copy` allocate-and-abandon loop of [`tests.rs`](../tests.rs) (`gcab_*`: `payload/1` builds a small map, `ets:insert/2` + `ets:lookup/2` validate it, one table and one key per process): the rows' magnitudes are the collector's, so the case pins the invariants this node owns rather than an absolute count — `pinned == 0` on every row, and a collection count that grows strictly with `N`: more than **4×** over the ~8× step for `gcab_free` and its float-literal twin `gcab_lit`, and strictly more for the float-using `gcab_flt`.
The literal-root control `gclit` (a constant payload the compiler folds into the module's literal area) is the discriminating twin of `gcab_free`: its collections are non-zero and strictly more at the larger `N` with `pinned == 0` and `fallbacks == 0`, which is what pins a tagged literal-area root as a literal the collector does not scan rather than a foreign container the valve would decline.
Each row prints its own counts (`gc-ab <module>: N=… collections … major … pinned … fallbacks …`), so the figures are re-derived by running the case (`erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --lib -- the_post_slice_float_pin_plateaus_a_float_using_loops_collections --nocapture`; the literal-root twin is `a_tagged_literal_root_is_scanned_and_the_loop_collects`) and are deliberately not quoted here.
The valve is **not** the cause of that cadence, and neither is the runner's per-slice FR exemption: the `gcab_flt` rows assert `fallbacks_at(ValveDeclined) == 0` (no allocation falls back on a valve decline) and `ensure_heap_full.hits == 0` (the full admission door declines no collection), with `pinned == 0` throughout, so every collection that runs is one the gate allowed.
The `heap_growth` control (`src/runner/tests.rs::the_heap_growth_workloads_per_call_counters_are_flat_in_n`) is the pure engine-allocation shape, and its cadence is `collections == 1 + N / K` with `K` derived from the row's own measured peak capacity: the 401-word `test_heap` request fits the settled **843**-word nursery twice (`2 × 401 = 802`), so `K == 2` and the counts are **2 501 / 5 001 / 12 501 / 25 001 / 50 001** at N = 5 000 / 10 000 / 25 000 / 50 000 / 100 000, with `peak_young_spaces == 1`, `debt_boundaries == 0` and `major` **0** on every row (each collection is a minor whose promotion fits the mature region, so none escalates to a fullsweep).
The `+ 1` is the collection the run takes before its first iteration — a fresh process starts on the collector's 233-word floor, smaller than a single 401-word request — and the boundary door adds nothing, because a slice prices exactly 800 iterations (a multiple of `K`) so a boundary collection lands where the following admission would have collected anyway.
The relation re-derives from each row instead of a quoted count, so a `beam_gc` sizing change moves the settled capacity, `K` and the expected count together rather than breaking the pin silently.

### Why the boot runs 427 collections — the shrink/grow oscillation (the count is a `beam_gc` policy artefact)
The minimal run (`beam_rt -noshell -eval 'halt().'`) takes **427 collections, 100 % of them on the scheduled route** (the `-eval`/`-version` routes are structurally inert — table-less contexts never reach a door). The count is **not** a live-set property and **not** this node's to set; it is a two-step loop between the copy-out growth seam and the collector's post-collection sizing.
1. **The trigger mix says so.** 262 of 427 admissions are `collection_debt`-driven with a mean **1 322 words free** in the current space, and 237 of 427 leave the capacity unchanged. `<0.10.0>` (the boot drive's process) owns **398** of the 427.
2. **The growth seam manufactures the debt.** Every one of the **179** `[rt-heap] copy-out grow` firings (`BEAM_RT_GC_TRACE=1`) is that pid's, all with `chain_spaces=1`; `src/context/calls.rs::hint_grow_gate` grows before a copy-out that would not fit (`hint >= COPY_OUT_HINT_MIN_WORDS = 8`, request `= hint + max(hint/4, 32)`), and `Process::grow_nursery` is the **no-relocation** seam — it **retires** the space it replaces, so `collection_debt()` (`Nursery::retains_old_spaces()`, i.e. `space_count() > 1`) becomes true.
3. **The debt is settled only by a collection, and that collection shrinks to the floor.** The next admission door collects; `Nursery::collapse` then installs `HeapPolicy::young_after_collection(capacity, live)` = `young_minor_target_words(live)` = **233** words, because the boot process's young live set is ~220 words. The observed capacity ladder between successive gate firings cycles down and back up — `2586 → 376 → 986 → 233 → 609 → 1596 → 376 → 1974 → …` (hints 8/10/92/138/180/182/186/194) — which is an oscillation, not a working set.
4. **A 233-word nursery cannot fit the next copy-out, so the gate fires again** ⇒ new growth ⇒ new debt ⇒ another collection. 398 turns of that loop on one pid.
5. **The legacy C refuses to shrink a small young heap; this runtime does not.** `erts/emulator/beam/erl_gc.c:1517-1529` (`do_minor`): `if ((HEAP_SIZE(p) > 3000) && (4 * need_after < HEAP_SIZE(p)) && …)` — *"Excessively large heaps should be shrunk, but don't even bother on reasonable small heaps … unless the heap size is substantial, we don't want to shrink."* `HeapPolicy::young_after_collection` (`beam_gc/src/policy.rs`) shrinks whenever `capacity_words > YOUNG_SHRINK_FACTOR (8) × target`, i.e. above **1 864** words at a 233-word target, with **no floor**. The file's own fullsweep rule already has one (`HeapPolicy::should_shrink` is gated by `heap_words > self.min_heap_words`); the minor's rule has none.

**Measured cost of the count** (`taskset -c 2`, `cpu_core/instructions:u` only — the hybrid CPU emits two PMU instances — 5 alternating paired rounds per row, control spread ±0.15 %, new ±0.05 %, load 0.04–0.21; `VmHWM` from `RUSAGE_CHILDREN`). Each row floors the *same* quantity the C's rule preserves — the nursery's target — through `+hms`, which is a **surrogate** for the missing shrink floor:

| `+hms` | collections | (debt-driven) | words copied | words reclaimed | instructions | Δ | `VmHWM` |
|---|---|---|---|---|---|---|---|
| none (control) | **427** | 262 | 128 316 | 661 006 | 1 980.5 M | — | 116.3 MB |
| 1 000 | **91** | 50 | 66 721 | 689 104 | 1 714.8 M | **−13.48 %** | 114.0 MB |
| 3 000 | **41** | 16 | 62 353 | 684 134 | 1 674.8 M | **−15.44 %** | 113.1 MB |
| 8 000 | **13** | 5 | 45 900 | 634 739 | 1 644.6 M | **−16.96 %** | 114.0 MB |

So the count is **not** the right policy: −13.5…−15.4 % of the whole minimal-run instruction floor, with **less** copying (128 316 → 62 353 words), essentially unchanged reclamation, and a slightly **lower** `VmHWM` (the win is copy + descent, not memory traded for speed). Cycles at 3 000: 736.9 M → 672.3 M (**−8.8 %**). The 1 000 row has the *patch's* dynamics (a grown capacity is **kept** — 2 586 words — because the gate moves to 8 000, instead of being forced up to a floor) and the 3 000 row its ceiling, so the C-faithful fix below is expected at **≈91 → ≈41 collections, −13.5…−15.4 %**; re-measure after landing rather than quoting either row as the result.

**Why this node cannot fix it.** Nothing in `src/context/gc.rs` settles the debt without a copy or avoids the shrink:
- `collection_debt()` is `retains_old_spaces()` and the **only** clearer is a collection; `Process::ensure_capacity(need)`'s post-collection growth is capped by `Nursery::grow`'s remembered `live_target_words` (`max(one_step, live_target)`), so the door cannot buy a larger space after the collapse;
- inflating the door's `need` to do so would break `heap_exhausted(need)`'s fail-fast for a `+hmax` process (a spurious `system_limit` on a small request) **and** silently override a user's `+hms`, moving `heap_size` — an oracle-shaped answer;
- a debt collection is never "nothing to collect" during the oscillation (a retired space holds live words by definition), and the genuinely empty case is already free: `Nursery::grow` re-adopts an empty retired space (`empty_retired_for`/`readopt_retired`), consuming no budget and adding no chain space;
- deferring the debt term at the two admission doors is refuted outright by `context/tests.rs::the_collection_debt_forces_a_collection_the_occupancy_test_would_not`, and it lengthens the retired chain — every capacity figure quoted in this file is a **chain sum**, so a deferral moves `heap_size`/`total_heap_size` in N.

**The change required, owned by `beam_gc/src/policy.rs`** (the C's floor, nothing else):
```rust
/// The C's own refusal to shrink a *small* young heap — `erl_gc.c:1527`, `do_minor`:
/// `HEAP_SIZE(p) > 3000` gates the whole shrink branch ("Excessively large heaps should be
/// shrunk, but don't even bother on reasonable small heaps").
pub const MINOR_SHRINK_FLOOR_WORDS: usize = 3000;

pub fn young_after_collection(&self, capacity_words: usize, live_words: usize) -> usize {
    let target = self.young_minor_target_words(live_words);
    let shrink = capacity_words > YOUNG_SHRINK_FACTOR.saturating_mul(target)
        && capacity_words > MINOR_SHRINK_FLOOR_WORDS;
    if shrink || capacity_words < target { target } else { capacity_words }
}
```
plus the `young_after_collection` rustdoc amended ("a capacity above `YOUNG_SHRINK_FACTOR` × the target installs the target" → "… **and** above `MINOR_SHRINK_FLOOR_WORDS`"). `nursery_floor_words`' invariant ("no collection can leave a nursery below this figure") is untouched: the keep branch already requires `capacity >= target`.
**Blast radius of that patch, by band:** a capacity ≤ 1 864 words was never shrinkable, so every figure below it stands unchanged — `233` (`src/runner/tests/slice_charging.rs`), `843` (`tests/foreign_root_loop.rs`, `src/runner/tests.rs`'s `heap_growth` control), `987` (`src/runner/tests/reds_door.rs`), and the differential corpus' only by-value case (`bif_extra/process_info_spawned_exact_item_values`, a fresh spawn's `{heap_size,233}`/`{total_heap_size,233}`). The band the patch changes is **(1 864, 3 000]**, which is exactly where `src/runner/tests/boundary_cost.rs`'s `MEASURED_YOUNG_CAPACITY = 2_585` sits — that row and its `MEASURED` count ladder must be re-derived by the node that owns them, as must the ratio-based `context/tests.rs::the_copy_bound_ping_pong_grows_the_nursery_instead_of_declining_the_valve`.

### Pins that depend on the doors' collection POLICY (read before changing the debt term)
A door-policy change — deferring/skipping a `collection_debt()`-driven collection, changing which door collapses a retired chain — has a blast radius wider than this node; these are the sites to re-derive. Grouped by the property each one buys.
- **The debt term exists at three sites, not two.** `ensure_heap` (`gc.rs` `let debt = process.collection_debt()`), `ensure_heap_full` (same), **and the reduction/yield-boundary door** `gc/reds_door.rs::collect_at_reds_boundary` (`if !occupied && !debt { return }`). The boundary door still collapses the chain once per pre-emption, so a deferral confined to the two admission doors leaves the `peak_young_spaces == 1` pins reachable; touching the boundary door breaks them harder.
- **The one direct pin of the debt→collection implication** is `context/tests.rs::the_collection_debt_forces_a_collection_the_occupancy_test_would_not` — it drives `ensure_heap_full(0, …)` (occupancy can never fire), fabricates debt through `Process::grow_nursery`, and asserts `after.collections == before.collections + 1` **and then `!collection_debt()`**. Any deferral of the debt term contradicts it outright.
- **`collection_debt()` false after an admission door** is otherwise unpinned workspace-wide; the only sibling assertions are `context/calls/exempt_window_tests.rs`'s two `!collection_debt()` checks, which ride the exempt-window allocation seam (a different path).
- **`young_space_count() == 1` / `peak_young_spaces == 1` after a collection** is pinned at slice boundaries by `src/runner/tests.rs::the_heap_growth_workloads_per_call_counters_are_flat_in_n` (`(peak_young_spaces, debt_boundaries) == (1, 0)`, the node's only debt-false pin), `src/runner/tests/boundary_cost.rs`, `src/runner/tests/reds_door.rs`, `src/runner/tests/slice_charging.rs` and `tests/gc_collect.rs`. `gc.rs::outside_scanned_ordered`'s `young_space_count() == 1` fast path is a **correctness** shortcut that rides the same property, not a pin.
- **The `debt` valve counter is tallied only in the `#[cold] ensure_heap_full_commit` continuation** (a `#[cfg(test)]` re-read of `Process::collection_debt`/`should_collect`), so a policy that short-circuits earlier moves `valve_counters`/`BEAM_RT_VALVE_TRACE` figures even where the collection cadence is unchanged; `context/tests.rs::the_copy_bound_ping_pong_grows_the_nursery_instead_of_declining_the_valve` reads them (`full.occupancy + full.debt >= full.reached`, `full.debt > 0` iff `full.hits > 0`).
- **Settled nursery capacity is a `beam_gc::HeapPolicy` fixed point, not a door decision** (`Nursery::collapse` → `young_after_collection`, keeping any capacity in `[young_minor_target_words(live), YOUNG_SHRINK_FACTOR × target]`), so a changed collection *cadence* changes which fixed point is reached — every exact capacity figure quoted below and in the sibling docs (`2 585`, `843`, `987`, `233`, and the exact ladders in `src/runner/tests/boundary_cost.rs`, `src/runner/tests/reds_door.rs`, `tests/foreign_root_loop.rs`) is downstream of that.
- **Structural inertness this node can rely on:** both admission doors return early on `!gc_armed`, `current_module.is_none()` and `mailbox_table.is_none()`, so the whole `-eval` route, every nested run and the boot drive's table-less contexts never reach them — no `-eval`-driven suite and no `-eval` differential corpus case can observe a door-policy change.

### The collector's share of the in-process `compile:file/2` path (measured — do not re-derive)
The doors are **not** a first-order cost of running the real OTP compiler in-process, and the per-collection arithmetic that looks like collector-bound copying comes from reading `words_reclaimed` as a live-set figure.
Measured on this host (release profile, `beam_rt -noshell -eval` running `compile:file(Src,[no_spawn_compiler_process,deterministic,no_docs,{outdir,D}])`), each source compiled **twice** back to back: baseline, and with `+hms 20000000` (a floor large enough that no collection runs at all — `erlang:statistics(garbage_collection)` then reports `{0,0,0}`).

|---|---|---|---|---|---|
| `lib/stdlib/src/ordsets.erl` (13 585 B) | 577 ms | `{562, 969 321, 0}` | 61 | 565 ms | ≤ 2.1 % |
| `lib/stdlib/src/maps.erl` (37 745 B) | 3 041 ms | `{612, 1 475 440, 0}` | 111 | 3 056 ms | ≈ 0 (the `+hms` row is *slower*) |

The **boot floor is `{501, 713 680, 0}`** (`-eval` that compiles nothing), so only 61/111/351 of the reported collections belong to the compile itself — the column is a run total, not a compile figure.
Turning the collector off entirely does not buy time on the two larger compiles: a pre-sized 20 M-word nursery costs page faults, zeroing and cache, and the collector's own cycles are **0.06 %** of the run (`perf record -F 997`, 28 852 samples: `beam_gc::copy::Copier::forward_one` 0.01 %, `Nursery::contains` 0.02 % + 0.03 %; no `beam_gc` collect symbol reaches 0.01 %).
**Why "852 collections × a 175 000-word live set" overstates the copying:** `GcStats::words_reclaimed` is survivor-adjusted, so a round's input is `words_copied + words_reclaimed`, and `collect_minor` ends in `Nursery::collapse` → `HeapPolicy::young_after_collection(capacity, stats.words_copied)` — the nursery target is re-derived from the round's own **young live set** after every minor, so it tracks that live set and converges rather than re-walking a growing one.
The large `erlang:memory(processes_used)` figure a compile ends on (376 KB for `string.erl`) is the **mature capacity** a fullsweep sized at `mature_target_words` (≈2 × the whole-heap live set) — capacity, never a per-collection copy volume.
The `-eval` body is an ordinary spawned child under `Runtime::default_spawn_policy()` (`config.heap.policy()` when not booting), so `+hms`/`+hbm*`/`+hmax` **do** reach the process that runs the compile; `{0,0,0}` above is that proof, and a small-floor A/B (`+hms` 10 000 / 100 000 / 1 000 000) moves the same compile by <2 %.
Consequence for policy work: neither a growth-on-admission step nor a "skip a collection that would reclaim little" rule is supported by measurement — the collector is already the cheap part of this path, and either rule would trade a documented flat-`heap_size` invariant for nothing.
**Where the compile's time actually is** (same profile, each owner is another node — escalate there, do not fix here): `beam_engine::interpreter::build_label_map` **25.2 %** (the whole-module `LabelMap` cache in `beam_engine/src/machine/label_cache.rs` misses on nearly every freshly compiled module), `<RuntimeContext>::call_registered` **14.0 %** (`src/context/calls.rs` + `dispatch.rs`), libc allocation churn **≈19 %** (`_int_malloc` 6.7 %, `_int_free_create_chunk` 3.6 %, `cfree` 2.8 %, `malloc` 2.3 %, `unlink_chunk` 2.1 %, `memset` 1.4 %), `beam_term::map::write_map` **6.7 %** plus its canonical-order `Vec` sort 3.2 %, `beam_term::compare::cmp_impl` **3.0 %**.
**Recipe** (re-derives every figure above): the two-run A/B *is* the measurement — `… -noshell -eval 'T0 = erlang:monotonic_time(millisecond), {ok,_} = compile:file(SRC, […, {outdir, D}]), io:format("~p ~p~n", [erlang:monotonic_time(millisecond) - T0, erlang:statistics(garbage_collection)]), init:stop().'` with and without `+hms 20000000`, then `perf record -F 997` + `perf report -i <data> --stdio -s symbol` for the cycle split.
There is **no in-tree collection tracer** and none is needed for this question; an unwired one would be dead code.

### Which seam allocates where, and what the latch is (read before touching a heap seam)
- **No heap pointer is cached** — not on the context, not on the machine.
  `alloc_words`/`alloc_words_rooted` re-derive `process.heap_mut()` → `Heap::hp()` on **every** call (`gc.rs::bump`), so nothing can inherit a stale `*mut Eterm` after a collection; the pointer a call returns is uninitialized storage valid only until the next admission point or collecting allocation (`Machine::alloc_rooted` docs), which is why the engine re-reads live terms out of `x`/`stack`/`fr` after any allocating read (`reread_ctx`).
- **`gc_armed` is a per-call *permission* bit, not a "collection is due" flag.** Its only armer is the slice's `BudgetContext` (`../runner/budget.rs`): `ensure_heap`, `ensure_heap_full` and `alloc_words_rooted` arm it, while **`alloc_words` (the unrooted seam) does not** — that seam never collects (its refusal path is the no-relocation `Process::grow_nursery` + retried bump **only while `may_replace_young_space` holds**, then the runtime arena).
- **A young-space replacement is legal only while the process's root set is complete** — the rule, its one predicate, its four sites and the arena's refusal-only role are [*A young-space replacement needs a complete root set …*](#a-young-space-replacement-needs-a-complete-root-set-and-a-live-heap-must-serve-its-own-builds) below. The **only** space replacements that fire inside the A.9 in-process `compile:file/2` route's exempt windows are the two copy-out sites (`hint_grow_gate` 58×, the post-refusal growth 12×); the allocation-seam guards are the conservative answer, and their reach differs by seam: the **rooted** seam's refusal is unreachable in every measured run of that route, while the **unrooted** seam's is reached **exactly once per compile** (a 15-word request against a 233-word young space with 10 free, inside an exempt window — the request then falls through to the arena); no collection runs inside an exempt window either (1 143 `ensure_heap_full` + 19 `reds_boundary` collections all report `exempt=false`).
  Whether a collection is *due* is the door's own test, made inside `ensure_heap_full`/`alloc_words_rooted`: `forced || should_collect(heap_need) || collection_debt()`, then the unscanned-root valve, then `collect_or_grow`.
  The **pure** gates ahead of that test are ordered cheapest-first, because they sit on a per-call path and none of them decides anything the others do not: `ensure_heap_full` reads `armed`, then `mailbox_pid`, then the two **context fields** (`current_module`, `mailbox_table` — a discriminant each) and only then `Runtime::gc_request_pending`/`gc_process_enabled` (valve-set probes) and the process-table lookup. Every one of those early returns is `Ok(())` with **no** runtime mutation on the paths the reordering moved it across — `take_gc_request` still runs only on the `!gc_process_enabled` branch, exactly where it ran before — so the order is a cost decision, never a verdict one. `alloc_words_rooted` keeps its own order (`call_site_known` is already its cheapest gate, and its `take_gc_request` sits on the same `!gc_process_enabled` branch).
  `call_ext`/`call_import` reach **none** of the three arming doors (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`), so the engine-side path adds no collection point either.
- **The runtime-native floor route has no copy-out and no pool rewind** (`calls.rs:1142-1146` returns before both), so a floor result stays in whatever region the arm built it in. An arm that materializes on `Runtime::info_heap` (`erlang:system_info/1`, `format_term`) rewinds that region through `Runtime::reset_info_scratch` at its own entry (`runtime.rs`, `native.rs`), which refuses once `Runtime::info_heap_tainted` is latched — so a refused relocation can never be recycled under a live term. `erlang:system_info/1` alone hands a value **out** to Erlang code, so it relocates it first with `RuntimeContext::relocate_off_scratch` (the registered-BIF container copy-out: the running process's scanned young heap, else the table-less `-eval` store), and a retained value is sound (`tests/system_info_retained.rs`).
- **Four regions, never interchangeable**:
  1. the process's own `beam_gc` young heap (`process.heap_mut()` — the only *scanned* region, target of both alloc seams *and* of the process-route BIF copy-out);
  2. the runtime's pointer-stable `arena` (`Runtime::alloc_words`, unscanned — the refusal-only fallback);
  3. the pooled `beam_alloc::Heap` regions (`Runtime::take_bif_heap`/`put_bif_heap`, where a registered BIF/NIF builds its result, and which `call_registered` rewinds to that call's `mark` once the result has been copied out);
  4. the **table-less store** (`Runtime::eval_heap`, its off-heap payload owner `Runtime::eval_off_heap`, and its retired regions `Runtime::eval_heap_retired` — the `-eval`/single-pass copy-out's destination; pointer-stable, grown only by region replacement, with `eval_heap`'s regions reclaimed only by the region-reclaim pass at a site where nothing is executing and `eval_off_heap` only ever grown).

### A young-space replacement needs a complete root set, and a live heap must serve its own builds

Three rules about the collector's scan boundary; `gc.rs`'s rustdoc on `may_replace_young_space`, `alloc_words` and `alloc_words_rooted` is the source of truth and states each one where it applies.

- **A young-space replacement is legal only while the process's root set is complete.** [`may_replace_young_space`](../../gc.rs) is the single predicate (`!Process::is_relocation_exempt()`), and all four growth sites consult it — the two allocation seams below and the copy-out's two sites in `../calls.rs`. A growth only **retires** the space it replaces (a word it handed out stays addressable at its original address); only a **collection** collapses the chain, and every collapse door refuses an exempt process. So a growth taken inside an exempt window would buy addressability a later collapse revokes, for words only the window's Rust-side handles name.
- **A container built while the process's heap is live must be built *on* that heap.** The collector classifies the pointer-stable arena `Target::Foreign` (`beam_gc/src/copy.rs`) and never descends into it, so a container built there while the process young heap is live has its young-heap children relocated out from under it by the next collection — a stale word that then reads whatever the recycled carrier holds. Hence `alloc_words_rooted`'s **unarmed** branch delegates to `alloc_words` (every nested run — a cross-module callee's second machine, an applied fun, the `-eval` evaluator — serves the running process's own scanned young heap), and the arena is a **refusal-only fallback**: a request the young heap cannot meet even after a growth, plus the genuinely table-less contexts (`-eval`/single-pass, the boot drive), which have no process heap at all.
- **A copy-out that cannot fit inside an exempt window is stabilized, never left dangling.** It is copied onto the runtime's pointer-stable store (`../calls.rs::move_result_into_runtime_store`; *refuse ⇒ stabilize*), so the call still licenses its pool rewind; `None` is a **permanent** refusal only (a malformed graph, an unresolvable off-heap container) and leaves the result on the never-rewound pooled BIF heap.

## Known Issues

Every gate above declines rather than guessing, so the residual of a declined collection or prune is a **leak**,
never a dangling pointer.
The measured envelopes and their narratives live in [`../../../M1_GAPS_GC.md`](../../../M1_GAPS_GC.md).

* **The minimal run's 427 collections are a shrink/grow oscillation, and the fix is `beam_gc`'s, not this node's** — worth **−13.5…−15.4 %** of the whole run (measured surrogate) with *less* copying and a lower `VmHWM`. `src/context/calls.rs::hint_grow_gate` grows the nursery before a copy-out, `Process::grow_nursery` retires the space (setting `collection_debt`), the next door collects, and `HeapPolicy::young_after_collection` shrinks the result to the 233-word floor — which cannot fit the next copy-out. The legacy C refuses to shrink a young heap below 3 000 words; `young_after_collection` has no such floor. Mechanism, the `+hms` sweep, why no `beam_rt`-side lever is sound and the exact required patch: [Why the boot runs 427 collections](#why-the-boot-runs-427-collections--the-shrinkgrow-oscillation-the-count-is-a-beam_gc-policy-artefact).

* **On the in-process compile path the walk costs ~30× the collector.** `perf record` over a `string.erl` compile puts the reachability descent this node runs before a collection or prune at `gc_walk::Visited::insert` 1.65 % + `Walk::seed` 0.25 % + `Walk::run` 0.12 % ≈ **2 %** of cycles, against the copier's **0.06 %** — so a future collection-path optimization here belongs to the walk's bookkeeping, not the copy loop. The valve is not negotiable for that reason: it is the arena fallback's soundness gate, and its only lever is its own gate order (`word_is_scanned`'s tier-one current-block test answers nearly every live root before the aggregate or exact tests).

* **The float guard lives on the narrow door alone; the full doors are FR-safe.** `ensure_heap_full` publishes each register file up to its pointer-bearing prefix and the whole stack, so a live float register relocates like any other root; the **narrow** `ensure_heap` (x prefix + stack only) keeps its `module_uses_floats` guard but is not on the engine's path today, and every door refuses a run with **no** caller module (a fun entry, the `-eval` evaluator) rather than guess one.
  Bound and door short-circuits: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-pointer-bearing-prefix-bound-of-the-full-root-doors).

* **Both heap-admission doors OR the occupancy test with the collector's collection debt.** `Process::grow_nursery` retires the young space it replaces instead of freeing it, so a growth-shaped workload keeps its whole allocation history resident until a real collection evacuates it; the doors collect when `forced || should_collect(need) || collection_debt()`, and `should_collect` stays the **occupancy test alone** (pinned by its own unit tests).

* **Only `ensure_heap`/`ensure_heap_full` reach `collect_or_grow`; the two allocation seams short-circuit past the collect.** `alloc_words_rooted`'s non-forced path serves the bump, a **capacity** refusal grows the nursery and retries, and `process.collect()` is reached only when that growth/retry *fails*; the unrooted `alloc_words` has no collection branch at all.
  Consequence, load-bearing for any heap-growth measurement: a loop emitting **no** `test_heap`/`allocate_heap` (`ensure_heap_full`'s only callers) reaches no collecting admission door, so only the **reduction/yield-boundary** door can collect it — `gc/reds_door.rs::collect_at_reds_boundary`, from the runner's `Yield` arm over the published whole `RootSet`, gated by a per-pid `REDS_BOUNDARY_MIN_REDS` interval and a **7/8** occupancy watermark OR-ed with the collection debt.
  That door runs the kind-pinned `Process::collect_kind(CollectionKind::Minor)` — a young-only collection — and escalates to the escalating `Process::collect()` only when the pinned minor reports typed heap exhaustion (the mature space cannot absorb the nursery, nothing copied), so a cadence fullsweep no longer comes from the door itself; on the **default** (native baseline JIT) tier it still fires only where a slice really ends (`../../M1_GAPS.md` *Scheduler / runner*).

* **The heap observables are CAPACITY summed over the nursery chain, so a GC-bound loop's flat `heap_size`/`total_heap_size`/`memory(total)` prove a *collapsed* chain, not the absence of growth.** `process_info(P, heap_size)` → `Nursery::capacity_words()` summed over the current **and every retired** space (`beam_gc/src/nursery.rs:225`); `total_heap_size` adds the mature capacity (`memory_hook.rs:132-174`).
  A churn loop's steady state is the copy-out gate's `grow_nursery` **retire** (a nursery too small for the result in flight) → the next heap-admission door's `collection_debt()` arm → `collect_or_grow` → `Nursery::collapse` sizing the nursery from the round's own **young live set**, which **keeps** any capacity inside `[young_minor_target_words(live), YOUNG_SHRINK_FACTOR × that target]` — so the geometry is constant in N *because the shape's live set is*, a fixed point of the rule rather than a coincidence, while `Runtime::gc_stats().collections`/`reclaimed` climb at a constant per-call rate.
  `grow_nursery` alone moves **no** counter, and `process_info(P, garbage_collection)`'s `minor_gcs` is `minor_since_major` (reset on every fullsweep, `beam_gc/src/collector.rs:326`), never a total — the discriminating counters are `gc_stats()` and `Collector::young_space_count()`.
  The boundary door contributes the pre-emption's own collection and nothing more; its firing rate, the per-shape collections/major rates and its share of a run's own collections are **measured** in [`../../runner/tests/boundary_cost.rs`](../../runner/tests/boundary_cost.rs) and [`../../runner/tests/reds_door.rs`](../../runner/tests/reds_door.rs), not asserted as a closed-form law.

* **The off-heap prune's residual is a LEAK, never a dangle — in the shapes below.** A process that parks in `Wait` (a `receive` that never wakes) never reaches the prune: that window is relocation-exempt and publishes nothing, so the machine stays the authoritative root set and the reservoir lives until the machine drops with the process (a process that wakes and yields again prunes then).
  A declined prune — any gate, the two valves and a failed reachability walk included — retains the whole reservoir.
  The `-eval`/single-pass route never prunes **the off-heap refc-binary reservoir** at all: its machine is not in `RunnerState` and allocates on the pointer-stable arena, whose park arm publishes nothing.
  That is not the store this route prunes: `Runtime::eval_off_heap`, the escaped-payload store a nested run adopts a finished machine's handles into, IS swept — at the `-eval` driver's depth-0 statement boundaries (`../eval/reclaim.rs`) and at the nested-run epilogue (`pump.rs::adopt_nested_payloads`).
  The cadence is the **pre-emption** cadence (the `Yield` arm, `../runner/run.rs:1412`), so a payload-building loop whose payloads land in the machine's reservoir is bounded by the bin-vheap budget even if it never reaches a `receive`: measured `4 144` bytes at N = 1 000 and `4 144` at N = 10 000 (4 096-byte payloads), `65 584` / `65 584` at 65 536 B — one surviving payload, flat in N.
  A **fun-loop** body (`lists:foldl/3`/`lists:foreach/2`) never reaches *this* arm — each lambda application is a nested `run_label_blocking` `Machine` whose reservoir is adopted into `Runtime::eval_off_heap` when it drops (`../context/pump.rs`, `../runtime.rs`) — but that store is pruned at the nested epilogue, so the envelope is a converged capacity: measured `377 104` bytes at both N = 1 000 and N = 10 000 with 4 096-byte payloads and `393 504` at both with 65 536-byte ones, against `4 144 000` → `41 440 000` (exactly `N × (Bytes + 48)`) before, because an out-of-scope payload is retained. The witnesses are [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs)'s `a_retained_off_heap_binary_survives_the_fun_loop_byte_exactly` (anti-dangle) and its (green, un-`#[ignore]`d) `the_fun_loop_envelope_is_bounded_by_the_bin_vheap_budget`, plus [`../../../tests/eval_off_heap_reclaim.rs`](../../../tests/eval_off_heap_reclaim.rs)'s nested anti-dangle case.
  The per-slice price of the point itself is one cached observation on a non-triggered bin vheap.

* **A slice's live float register is handled by a per-slice relocation exemption — never a permanent pin** (the guard and its decline-only bounds are [`../../runner/CONTEXT.md`](../../runner/CONTEXT.md)'s; the measured plateau is [`../../runner/MEASURED.md`](../../runner/MEASURED.md)'s).
  This node's half: the valve does **not** decline a float root — the engine's FR model holds *terms* built on the executing process's own young heap, so `fr[0]` is a **scanned** root (`tests.rs::a_live_float_term_in_fr_is_a_scanned_root`).

* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** It is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it — but `Machine::with_roots` parks it (with the two failed-clause argument latches and the two supplied-trace term latches, `const LOOSE_HEAP_TERMS = 5`) at the tail of the Erlang stack for the duration of every allocation that may collect and re-seats it from the slot the host wrote back, so it is a root **in slice** on every tier; across a park, `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (relocated in place) and `resync_parked_roots` reads it back into `pending_exception_mut()` and clears the extra roots.

* **The arena fallback is kept sound by a two-phase unscanned-root valve.** At each of the five collection sites the valve **declines** (`Ok(())`) any collection whose roots — or process-side scanned graph — reach a foreign container **that forwards a word the collector would follow or update**; a foreign container forwarding **nothing scanned** is inert, and the per-pid descent latch is **not** sticky (opened on a hazard, closed only by the three whole-root doors, never by a site handing over less than the whole root set).
  A decline costs a collection and nothing else (the allocation falls back to the pointer-stable arena); the two phases, the five sites and `note_gc_fallback`: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-unscanned-root-valve--two-phases).
  The off-heap prune runs the same valve and then its own stronger one, and opens the latch on either decline without ever closing it (see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)).

* **A module-literal root does not decline the collection: `beam_loader` load-time tags the literal area.** A constant payload is folded into the module's **literal area**, so the loop's only live root `x(0)` at its `test_heap` site IS that literal pointer; `LiteralArea::decode` calls `beam_term::literal::tag_literal_area` — the safe form of the C load-time `erts_set_literal_tag` — before publishing, so every literal root carries `TAG_LITERAL_PTR` **set** and `gc.rs::root_is_unscanned` classifies it by the C's bare-bit `erts_is_literal` rule: an immutable, never-moved region, so the valve **passes** and a constant-payload loop's `collections` scale with N.
  Tagging also removes a shared-literal corruption hazard: an untagged literal is silently **writable** (`beam_engine/src/terms/update.rs::set_tuple_element` refuses an in-place tuple write only when `is_literal` holds).

* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path** — there is no `Process` to sum (it allocates on `Runtime::arena`, whose `Arena` exposes no word accessor, so both are an honest `0`); closing it needs a `MinimalContext` arena-words accessor plumbed through `Runtime` (owner `beam_engine`).

* `gc/` → the admission seam's child modules: `reds_door.rs` (the reduction/yield-boundary collection door the runner's `Yield` arm reaches, a whole-`RootSet` door that closes the descent latch), `bin_vheap.rs` (the off-heap refc-binary reclamation point — `reclaim` + `OffHeapReclaimer`, see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)), `valve_bounds.rs` (the aggregate-vs-exact scan-bound equivalence suite) and `refs_plateau.rs` (the reference-minting heap plateau).

* `gc_walk.rs` → the unscanned-root reachability walk (`any_root_is_unscanned`/`process_roots_are_unscanned`, the reusable `WalkScratch`, `ForeignLatch`) + `RuntimeCollectionGate`, the `beam_process::CollectionGate` host seam; the one traversal serves **three** criteria (`enum Criterion { Collection, PayloadPrune, ResourcePrune }`, `Walk::begin(scratch, bounds, criterion)`), the three collection doors pass `Criterion::Collection`, the off-heap prune reaches `Criterion::PayloadPrune` only through `reaches_an_unscanned_word` (see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)) and the NIF-resource prune reaches `Criterion::ResourcePrune` through `reachable_resource_words`; the two phases: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-unscanned-root-valve--two-phases).
* `gc_valve_trace.rs` → the invocation census behind `BEAM_RT_VALVE_TRACE` (per-door, per-pid, `Visited` probes/grows, seeded roots by family, tier1/tier2 split): the instrument [the descent's cost shape](#the-descents-measured-cost-shape--the-invocation-census-gc_valve_tracers) records. Observes only — no verdict, no count and no behaviour depends on it, and the env read is hoisted once per walk.


* `gc/resources.rs` → the NIF-resource-term prune's caller half; the soundness contract is `beam_abi`'s
  (`src/nif/enif/resources_release.rs`), the pinning suite [`../../../tests/nif_resource_gc.rs`](../../../tests/nif_resource_gc.rs).
* `gc/refs_plateau.rs` → the reference-minting heap plateau witness: such a loop keeps `erlang:memory(processes)` flat, because every minted reference is an immediate-like term with no heap growth.
* `gc/valve_bounds.rs` → the word-classifier oracle: the two-tier scanned test (`word_is_scanned`/`outside_bounds`) over the collector's own bounds, aggregate widths per geometry, and the exact-predicate equivalence pins.
* `gc/reds_door.rs` → the reduction/yield-boundary door the runner's `Yield` arm reaches: a whole-`RootSet` door that closes the per-pid descent latch, running the kind-pinned `Process::collect_kind(CollectionKind::Minor)` and escalating to `Process::collect()` only on typed heap exhaustion.
* The runtime-level GC state/accounting/valves are [`../../runtime/`](../../runtime/CONTEXT.md)'s; the root-set
  completeness seam and the at-risk roster are [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md)'s.
