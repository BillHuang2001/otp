# `beam_rt::context::gc` — heap doors, allocation seams and the off-heap prunes

## Intent
The GC/heap half of the concrete `ExecutionContext`: where a scheduled process's memory comes from, when a collection may run, and how off-heap payloads are released.
It owns the five collection sites and their no-relocation growth/retry discipline, the allocation seams' valve-free bump fast arm, the two-phase unscanned-root valve with its reachability walk, and the two off-heap prunes (the machine's refc-binary reservoir, the NIF resource terms).
It owns **no heap, no collector and no sizing law**: the strategy-agnostic collector, `HeapPolicy` and every size decision are `beam_gc`'s ([`../../../../beam_gc/CONTEXT.md`](../../../../beam_gc/CONTEXT.md)); the seam-level contract is [`../CONTEXT.md`](../CONTEXT.md)'s, the root-set/relocation seam [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md)'s, and every measured figure [`MEASURED.md`](MEASURED.md)'s — this file states conclusions, not numbers.

## API Surface

### The five collection sites and the gate order
Five places can start a collection: `ensure_heap` (narrow: x prefix + stack), `ensure_heap_full` (the engine's `test_heap`/`allocate_heap` door), `alloc_words_rooted` (**cold path only** — a block its bump fast arm serves returns first), the runner's park arm `Runtime::serve_gc_request`, and `reds_door.rs::collect_at_reds_boundary`.
Only `ensure_heap`/`ensure_heap_full` reach `collect_or_grow`; `alloc_words_rooted`'s non-forced path serves the bump and a **capacity** refusal grows the nursery and retries (`process.collect()` only when that fails), and the unrooted `alloc_words` has **no** collection branch at all.
Due-ness is the door's own test — `forced || should_collect(heap_need) || collection_debt()` → the unscanned-root valve → `collect_or_grow` — behind the gate order `latch → request → valves → caller module → commit-once`, cost-ordered (pure gates first: `armed`, `mailbox_pid`, `current_module`, `mailbox_table`, then `gc_request_pending`/`gc_process_enabled`, then the process-table lookup).
Every early return is `Ok(())` with no runtime mutation (`take_gc_request` runs only on the `!gc_process_enabled` branch), so the order is a cost decision, never a verdict one.
`should_collect` is the occupancy test **alone**; `collection_debt()` — `Nursery::retains_old_spaces()`, i.e. `space_count() > 1` — is OR-ed in because `Process::grow_nursery` **retires** the space it replaces, so a growth-shaped workload keeps its allocation history resident until a real collection evacuates it.
`call_ext`/`call_import` reach **none** of the arming doors, so a loop emitting no `test_heap`/`allocate_heap` is collectable only by the **boundary** door: the runner's `Yield` arm over the published whole `RootSet`, gated by a per-pid `REDS_BOUNDARY_MIN_REDS` interval and a **7/8** occupancy watermark OR-ed with the debt. It runs the kind-pinned `Process::collect_kind(CollectionKind::Minor)` and escalates to `Process::collect()` only on typed heap exhaustion, so no cadence fullsweep comes from it.

### Which collector the policy resolves to, and the sizing laws
The context holds an `AnyCollector`, never a concrete `Collector`: the mature generation is whichever strategy `GcConfig::mature_choice` resolves to from `beam_gc::selection::select_mature(mature_words)` — `MatureKind::Immix` at or above `IMMIX_BREAK_EVEN_WORDS = 8 × BLOCK_WORDS = 2 048` words, `MatureKind::Copying` below.
Its **only** input is `HeapPolicy::initial_mature_words`, **233** by default, so a plain runtime is the copying collector; no `+h`-style switch touches that field (`+hms`/`+hmbs`/`+hmax`/`+hmaxk`/`+hmaxel`/`+hmaxib` are the whole heap-flag surface), and the mark-region mature generation is reached only through the host/test knob `BEAM_RT_GC_STRATEGY=immix`, which raises the field to `IMMIX_BREAK_EVEN_WORDS` — through the rule, never an explicit pin — reported by `AnyCollector::mature_choice`.
Both strategies satisfy the same door contract: `scanned_bounds()`, `young_contains`/`mature_contains`, `collect_kind`, `Collection::stats`.
The sizing laws are `beam_gc::HeapPolicy`'s (re-derive from `beam_gc/src/policy.rs`, never from a figure): `need_reserve_words = 64`, `YOUNG_TARGET_LIVE_MULTIPLE = 2`, `YOUNG_SHRINK_FACTOR = 8`, `MINOR_SHRINK_FLOOR_WORDS = 3 000`.
- Every size is rounded through the curated growth table (`next_heap_size`, the C `erts_init_gc` table) then clamped by `min_heap_words`/`max_heap_words` in `next_words`, so `+hms` floors every space a policy produces and a capped policy's target *is* the cap.
- Minor target `young_minor_target_words(live) = next_words(live + need + reserve)`; fullsweep young target `young_target_words(live) = next_words(2 × (live + need) + reserve)`; `young_after_collection(capacity, live)` keeps a capacity inside `[target, max(MINOR_SHRINK_FLOOR_WORDS, 8 × target)]` and installs the target outside it (the 3 000-word floor is the C's refusal to shrink a *small* young heap, `erl_gc.c:1517-1529`).
- `need_after_fullsweep(live, young_occupancy) = live + young_occupancy + reserve`, `mature_target_words(live, young_occupancy) = next_words(2 × need_after)`; the multiple is the number of minor promotions one mature space is sized for.
- **The occupancy input is the CLAMPED young occupancy, never the nursery capacity**: both fullsweeps compute `young_occupancy = nursery.used_words().min(young_after_fullsweep(nursery.capacity_words(), live))`. Substituting the capacity bakes the process's dead-word history into the next mature space, which the following fullsweep measures again — the feedback ratchet gated by `beam_gc/tests/mature_capacity_feedback.rs` — while the clamp keeps the term's purpose (a whole nursery of promotion room) and makes it allocation-history independent.
- Every target is a function of the measured **live set**, which is what makes it converge; one derived from the mature space's own occupancy or capacity is not a fixed point, because a generational heap is *full* when the cadence fires, so such a rule steps the growth table once per fullsweep without bound.

### The allocation seams — the valve-free bump fast arm
`alloc_words_rooted` has a **fast arm** ahead of every collector valve: after the forced-request peek, when the context has both `mailbox_table` and `current_module`, it takes the pid's own `&mut Process` and serves the block with `plain_bump` — one arityval header word plus `n - 1` placeholders from `static PLAIN_BUMP_FILL: [Eterm; 32]` of `NIL` immediates (`PLAIN_BUMP_FILL_WORDS = 32`), a **constant-length** slice for `n ∈ {1,2,3}` (`PLAIN_BUMP_FILL_ONE`/`_TWO`) and the dynamic fill from `Runtime::gc_scratch` above that.
Those placeholders are **not** GC roots (an immediate names no region, and the engine overwrites them before the block is reachable), and the arm builds no `Result<_, BeamError>`: a `None` from `plain_bump` is "not the fast case", never a swallowed error.
The arm calls **no** `Runtime::gc_process_enabled`, and that is sound: pinning and halting constrain *collections* and *growth*, both of which move or retire a space, while a bump moves nothing — so a pinned or halted process keeps allocating on its own **scanned** young heap instead of the pointer-stable arena, which is also better for the valve, since an arena block is a container no collection may descend into.
The forced-request peek keeps the arm honest (an armed `erlang:garbage_collect` request bypasses the bump into the collection path).
Everything the arm declines (no room for `n`, a block past the static fill, a forced request) falls through to the unchanged cold path: `grow_nursery` with the retried `bump`, `may_replace_young_space` at every growth site, `machine_root_bounds`, `valve_verdict`, the once-only `take_gc_request`, `scatter_roots_full`, the arena fallback.
**Both full-root doors are split hot/cold**: an `#[inline]` entry deciding "nothing to do" and a `#[cold] #[inline(never)]` continuation holding everything that acts (`ensure_heap_full_commit`, `alloc_words_rooted_commit`) that re-derives what it needs instead of receiving a borrow, so no frame is kept alive on the hot path; the gate **order** is unchanged, the hot entry's short-circuit being a *precondition* of the continuation. Lever sizes and rejected alternatives: [`MEASURED.md`](MEASURED.md).

### The unscanned-root valve — two phases, one walk
The valve is the arena fallback's soundness gate: it **declines** (`Ok(())`, no collection) whenever a collection could relocate a scanned word that a region the collector does not scan still names.
Phase 1 (`root_is_unscanned`) declines over a term only when **both** hold: it is a container in an unscanned region (`word_region` → `WordRegion::Foreign` — pooled BIF heaps, the `-eval` heap, the pointer-stable arena, a message fragment) **and** at least one word it forwards is a pointer the collector *does* scan (any nursery space, current or retired, or the mature generation).
Everything else is inert — an immediate, a tagged literal, a null/unaligned word `dereferenceable_pointer` rejects, a foreign leaf, an all-immediate block, a reference, pid, port, float, bitstring or empty tuple — because `forwards_word_matching` drives the same `beam_term::layout::for_each_child_slot` enumeration the copier uses, so the valve cannot disagree with the collector; `SUB_BITS_SUBTAG`'s `orig` word *is* forwarded, so an `ErlSubBits` over a live word declines while the same shape over a literal is inert.
The three term-only tests have their own entry point, `result_may_be_foreign(term)` (the same `foreign_shape_pointer` the classifier continues from), for the one caller holding a candidate word *before* it has a `Process`: the BIF-result gate `RuntimeContext::open_gate_for_foreign_result`, once per successful `call_bif`.
Phase 2 (`gc_walk.rs`) descends the process's scanned graph and root containers under the per-pid descent latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found where phase 1 sees only a root's own address.
Classification is three stages, cheapest first: stage 0 term-only (`is_pointer_bearing`, the literal-area tag, `dereferenceable_pointer`), stage 1 the current mutator block `[base, hend)` with its bounds hoisted into a `Copy` geometry companion, stage 2 the collector's aggregate `AnyCollector::scanned_bounds()` (one `O(1)` read, decided by `ScannedBounds::definitely_unscanned` in two compares) — and only what the aggregate cannot decide reaches the exact tests, whose order, `retired_regions` index and `young_space_count() == 1` shortcut are `gc.rs`'s module docs'.
The reject is sound **one way only** (the aggregate covers every scanned region's *reserved* extent, so `definitely_unscanned` proves both exact tests false while `may_contain` claims nothing; a fast *accept* is never taken), a `debug_assert` re-derives it from `outside_scanned_exactly`, and the bounds are re-read because the interval is **not monotone**.
The latch splits by **root-set completeness**: a whole-`RootSet` door (`ensure_heap_full`, `alloc_words_rooted`, the reds door) **closes** the pid's bit on `ValveVerdict::foreign_free`, while the narrow `ensure_heap` (no FR file), the park arm and the `RuntimeCollectionGate` signal sites may only **open** it (`RuntimeCollectionGate::from(latch)`, one shared cell, `O(1)` while clear; the no-latch `RuntimeCollectionGate::new()` is `#[cfg(test)]`-only).
A decline costs a collection and nothing else (the allocation falls back to the arena, counted by `note_gc_fallback`), so it can never turn a working program into a failing one; a registered-BIF result is **not** a foreign holder, because `call_registered` copies it onto the process heap and rewinds the pool to the call's `mark`; and `../../runtime/gc.rs`'s accessors test `is_empty()` before hashing, none of them on the per-term bump path.
**A module literal does not decline**: `beam_loader` tags the literal area at load (`tag_literal_area`), so a literal root classifies as an immutable never-moved region — which also removes a corruption hazard, since an untagged literal is silently writable (`set_tuple_element` refuses an in-place tuple write only when `is_literal` holds).
**The hand-off widths never clamp**: every door slices through `Machine::with_roots` (`used_extent = mark.max(dirty).min(len)`, so `used_fr_extent() >= fr_mark()`) and `publish_roots_full`/`scatter_roots_full` apply the *same* clamp, so the reds door's `fr_count.min(roots.fr.len())` never binds and the "`false` halts collection forever" hazard is unconstructible. Only the **x** width is a door's choice: both full doors publish `roots.x` in full (`publish_roots_full` ignores `RootSet::live`), while the narrow `ensure_heap` publishes `x_regs.len().min(MAX_REG)` over an x-only slice and no FR file — so a live float register is a **scanned** root on the full doors, and only the narrow door keeps its `module_uses_floats` guard (not on the engine's path). Every door refuses a run with **no** caller module rather than guess one.
Census, profile shares and aggregate widths: [`MEASURED.md`](MEASURED.md).

### The off-heap refc-binary reservoir prune (`bin_vheap.rs`)
A process's off-heap refc binaries live in the machine's reservoir (`Machine::refc_binaries`), outside every heap the collector owns, so a collection can never sweep them: they are pruned separately at the pre-emption boundary — the runner's `Yield` park arm and **nowhere else**.
`OffHeapReclaimer` is a process's binary virtual heap (the C `p->bin_vheap_sz` through `beam_gc::BinVheap`, plus the observed `MSO(p).overhead`), `reclaim(runtime, table, pid, machine, slot)` is the prune, and the state is per engine (`ProcessEngine::off_heap`), built lazily from `process.collector().policy()` so a `+hms`/`+hbm*` policy is honoured and dying with the machine.
`observe` is `O(1)` while the reservoir's handle count has not moved (the engine only ever appends between prunes), so `Machine::off_heap_overhead_bytes` — `O(reservoir)` — is read only when the count moved or once per triggered prune, never on the per-slice path; `triggered()` is the C's `off_heap.overhead > bin_vheap_sz` (strictly greater, bytes to words by truncating division; 46 422 words fresh, the C `BIN_VH_MIN_SIZE`), and `record_collection` reproduces the C's `p->bin_vheap_sz = next_vheap_size(..)` / `MSO(p).overhead = bin_vheap` pair from the payload that survived.
The release is `Machine::retain_refc_binaries` with `live(p) || shared(p)`: `live` from `beam_gc::for_each_reachable_binary_payload` over the process's roots, `shared` every payload at `RefcBinary::refcount() > 1` — the belt for second owners the process's roots do not describe (the send path's envelope clone, `Runtime::eval_off_heap`, a writable accumulator).
It **moves nothing** (a retained payload keeps its exact `data_ptr`, so no live on-heap `BinRef` is invalidated), and `Process::set_off_heap_binary_bytes` republishes the surviving figure — the bin-vheap figure `max_heap_size`'s `include_shared_binaries` charges.
**Every gate is a decline** — pid not in the caller's table, `is_relocation_exempt()`, `!gc_process_enabled(pid)`, the bin vheap untriggered, the collection valve declining, the prune-only valve declining, or the walk returning a typed error: the whole reservoir is retained and `Ok(0)` returned, a **leak and never a dangle**, and both valve declines open the per-pid descent latch (neither closes it).
`Process::has_unpublished_roots()` is deliberately **not** a gate — it is `true` for a `ProcessState::Running` process, which a pre-empted one still is — the correct pair is `is_relocation_exempt()` plus the park's own `parked_published` flag.
**The prune is park-gated and the budget gates it, never causes one**: a `Wait` arm and a `BifOutcome::Suspend` park reach no prune and nothing reads `triggered()` to *ask* for a reclaim, so one slice's dead garbage is bounded by the **slice length** (a count of iterations, hence payload-size proportional), and a process under the trigger releases nothing between parks.
The C's envelope is its bin-vheap budget and this arm's is the slice — a **capacity residual, not a leak**, closable only by ending the slice on the trigger (a `runner`/`beam_engine` seam).
**The reference-thing exemption is the one narrowing of the prune-only valve**: `gc_walk.rs::is_inert_reference` excludes a reference block from `Criterion::PayloadPrune`'s hit set, because a reference's payload words are terms or packed `u32` ids — never a term reference and never a `BinRef.val` pointer — so it can name no payload; without it, any process holding one live `make_ref/0`, `monitor/2` or `alias/1` reference (or an unnamed ETS tid) declined at every park.
At a park the reservoir is pruned **whole** (`retained_by_live = retained_by_shared = 0` at every park of every shape measured), so a park-reaching loop's peak is one pre-emption window, never a sum over parks.
A released payload's bytes leave `binary_alloc`, so `erlang:memory(binary)` (`memory_hook.rs::allocator_live_bytes(AllocType::Binary)`) reflects it — a **different** observable from `erlang:process_info(P, binary)`, the per-process roster (`../native/memory/binary.rs`).
Figures, the suite [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs) and the call site's per-slice cost ([`../../runner/CONTEXT.md`](../../runner/CONTEXT.md)): [`MEASURED.md`](MEASURED.md).

### The NIF-resource-term prune (`resources.rs`)
`reclaim(runtime, table, pid)` is the caller half of `beam_abi`'s resource-release seam: it drops the reference every resource **term** took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs exactly once (the soundness contract — a false "unreachable" is a use-after-free — is `beam_abi/src/nif/enif/resources_release.rs`'s).
The **scheduled** site is the runner's `Yield` park arm immediately after the refc-binary prune, under the same `engine.parked_published` gate; an exempt park and a `Wait` arm decline, and the routes that never park (`-eval`, a nested run) are served by the two non-park sites in `../eval/reclaim/resource.rs`.
Gates, all declines: an empty `resource_terms()` (one registry read, no walk), the process being in the table, `!is_relocation_exempt()`, `gc_process_enabled(pid)`, and the prune-only valve classified over the **process's own** roots only — never the host root sources, since every host word is a `WordRegion::Foreign` root and folding them in would decline every prune a resource program attempts.
`reachable_resource_words` collects every reachable candidate word **or reference identity**, because a resource term is an internal reference: a `copy_struct` copy (the send path, ETS) is a different word with the same id, and matching the word alone would free an object a live copy still designates.
Residuals: an unreadable identity is kept; the cadence is the park cadence; a resource held only by a store no site enumerates (a `persistent_term` value, an ETS object) is released, because the host root sources are exactly the families `Runtime::gather_off_heap_roots` publishes; and the two per-pid families are empty **at this arm** (a pass moves the process table and `RunnerState` out of the runtime), so they are live only at the two non-park sites.
Detail and the pinning suite [`../../../tests/nif_resource_gc.rs`](../../../tests/nif_resource_gc.rs): `resources.rs`'s module docs.

### The sibling-store prunes (`-eval` and the nested run) — a different store
`Runtime::eval_off_heap` is the escaped-payload store, swept at two points — `../eval/reclaim.rs` (`Evaluator::prune_escaped`, the tree-walker's depth-0 statement boundaries) and the nested-run epilogue (`pump.rs` → `RuntimeContext::adopt_nested_payloads` → `Runtime::prune_off_heap`) — with a different trigger (handle count moved **and** summed `reserved_bytes` > `STORE_BUDGET_WORDS` = 46 422) and different roots.
Its guards: the **named live sets** (evaluator env + reduced value, escaped closures' envs, `seq_trace` tokens, every process's dict + mailbox, pending spawns) are walked as terms and may decline, while the runtime's **term regions** (`eval_heap` + retired, pooled BIF heaps, `info_heap`) are scanned as **word images** only (`for_each_off_heap_region`, the `HEADER_BIN_REF` pattern, dereferencing nothing) and **never** pushed as roots — a region interleaves heap objects with the raw payload words of on-heap binaries, which read as `TAG_PRIMARY_LIST` and `SIGSEGV` in `walk`; any doubt (visit budget, unknown boxed header) declines the whole prune, `RefCount > 1` ⇒ retain.
The nested epilogue adopts only the handles the finished machine built, publishes that machine's **own** root set (`Machine::with_roots(RootSet::ALL_LIVE)` plus the term about to return) and prunes against it unioned with the guards under an `O(1)` gate (`Runtime::off_heap_prune_pending`); an out-of-scope entry is retained unconditionally, because the *enclosing* machines of the same process hold terms this crate cannot see (sweeping the whole store there corrupts live binaries). A nested run that **raised** takes the plain adopt path and leaves the store alone (its reason rides `beam_common::Raise`'s live-reason slot).
Uncovered, each a leak and never a dangle: `apply_eval_closure`, the engine arena (`ContextHeap` has no word-range accessor, so only nominally covered by the region scan) and the `eval_heap` **region** (bounded by `../eval/scratch.rs`'s statement window — one giant statement whose value *is* the result, and a growth `../runtime/reclaim.rs` has not yet proven dead).
Store shapes and windows: [`../CONTEXT.md`](../CONTEXT.md) *The `-eval` route's term storage*; the nested-run pump: [`../pump/CONTEXT.md`](../pump/CONTEXT.md).

### GC accounting — `statistics(garbage_collection)`, `memory/0,1`, `statistics/1`
`erlang:statistics(garbage_collection)` (`runtime_hooks.rs::garbage_collection`) answers `{collections, reclaimed, 0}` — the C `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's **node-global cumulative** counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran and `reclaimed` (words) is advanced by each site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`, never an estimate.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`: the quantities match the oracle's, the magnitudes do not.
`erlang:memory/0,1` (`MemoryHook`) returns nine oracle keys in oracle order with `total = processes + system`, every figure measured and snapshotted at construction; `memory/1` answers in the requested order and `badarg` for an unknown key. Key sources: `memory_hook.rs`.
`erlang:statistics/1` is partly served — the `run_queue*`/`total_run_queue_lengths*` family, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io`, `garbage_collection` — while `scheduler_wall_time(_all)` ⇒ `undefined` (nothing is sampled). Gaps: `statistics/0`, the per-scheduler family (`active_tasks*`/`total_active_tasks*`/`microstate_accounting`) and every other `RuntimeHooks` family (`../runtime_hooks.rs`).

### The four regions, `gc_armed`, and the rooting rules
**No heap pointer is cached** — the seams re-derive `process.heap_mut()` → `Heap::hp()` per call, so a returned pointer is uninitialized storage valid only until the next admission point, which is why the engine re-reads live terms out of `x`/`stack`/`fr` after any allocating read (`reread_ctx`).
**`gc_armed` is a per-call *permission* bit, not a "collection is due" flag.** Its only armer is the slice's `BudgetContext` (`../../runner/budget.rs`); `ensure_heap`, `ensure_heap_full` and `alloc_words_rooted` arm it, and **`alloc_words` does not** — that seam never collects (its refusal path is the no-relocation `grow_nursery` + retried bump **only while `may_replace_young_space` holds**, then the runtime arena).
**Four regions, never interchangeable**: (1) the process's own `beam_gc` young heap — the only *scanned* region; (2) the pointer-stable `arena` (`Runtime::alloc_words`, unscanned, refusal-only fallback); (3) the pooled `beam_alloc::Heap` regions (`take_bif_heap`/`put_bif_heap`, rewound to the call's `mark` once a result is copied out); (4) the **table-less store** (`eval_heap` + `eval_off_heap` + retired regions, the `-eval`/single-pass destination, grown only by region replacement and reclaimed only where nothing executes). Per-region accounting: [`../CONTEXT.md`](../CONTEXT.md) *The `-eval` route's term storage*.
**The four rooting rules** (seam form: [`../CONTEXT.md`](../CONTEXT.md) *Term lifetime — the four rules this node's seams obey*):
- **(a) A raw `Eterm` in a long-lived slot roots nothing.** Anything that can outlive one instruction must be copied onto a heap a collector scans, or explicitly stabilized (`stabilize_term`/`stabilize_term_with` → the `eval_heap` store), *before* the owner's heap can be relocated.
- **(b) A pointer-stable, never-scanned store is the wrong home for a container whose children live on a scanned young heap.** The copier relocates exactly the words in its *from* set and classifies every other address `Target::Foreign`, leaving the reference verbatim **without descending** — so the container survives un-moved while its young-heap children are relocated out from under it and it keeps stale words. Hence `alloc_words_rooted`'s **unarmed** branch delegates to `alloc_words`, and the arena is a **refusal-only fallback**: a request the young heap cannot meet even after a growth, plus genuinely table-less contexts (`-eval`/single-pass, the boot drive).
- **(c) Refuse ⇒ stabilize, never dangle.** An exempted growth/move falls back to copying the graph onto the pointer-stable store rather than leaving a word pointing at a region that may move or be freed; a `None` from the copy-out therefore means only a **permanent** refusal (malformed graph, unresolvable off-heap container, an ungrowable store), and the result then stays on the never-rewound pooled BIF heap — leak, never dangle.
- **(d) A lease (an `Rc` handle) held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow** — the one instance that matters is `CodeServer::atoms_handle()` ([`../CONTEXT.md`](../CONTEXT.md) *The one process-lifetime `Rc<AtomTable>` lease*).
**A young-space replacement is legal only while the process's root set is complete**: `may_replace_young_space` (`!Process::is_relocation_exempt()`) is the single predicate, consulted by exactly four growth sites (the two allocation seams and the copy-out's two sites in `../calls.rs`). A growth only **retires** the space it replaces, while only a **collection** collapses the chain and every collapse door refuses an exempt process — so a growth inside an exempt window would buy addressability a later collapse revokes, for words only the window's Rust-side handles name. On the A.9 in-process `compile:file/2` route only the two copy-out sites replace a space inside an exempt window, no collection runs there, and the unrooted seam's refusal is reached once per compile ([`MEASURED.md`](MEASURED.md)).
The runtime-native floor route has **no copy-out and no pool rewind**: a floor result stays where its arm built it, an arm on `info_heap` rewinds at its own entry (`reset_info_scratch`, refusing once `info_heap_tainted` latches), and `erlang:system_info/1` alone hands a value to Erlang code, so it relocates it first through `relocate_off_scratch` ([`../../../tests/system_info_retained.rs`](../../../tests/system_info_retained.rs)).

### What the doors do NOT decide
The doors decide **whether** a collection may run; the collector's own post-collection sizing decides **how often** (`Nursery::collapse` ← `HeapPolicy::young_after_collection`/`young_after_fullsweep`, `beam_gc`'s).
On the minimal run that sizing owns the count entirely: a shrink/grow oscillation between the copy-out growth seam (`../calls.rs::hint_grow_gate`, request `= hint + max(hint/4, 32)` for `hint >= COPY_OUT_HINT_MIN_WORDS = 8`) and `young_after_collection`'s keep-band — `grow_nursery` retires the space (setting `collection_debt`), the next door collects, the policy keeps or shrinks the capacity, and a space too small for the next copy-out fires the gate again.
Nothing here settles the debt without a copy or avoids the shrink: the debt's only clearer is a collection, `ensure_capacity`'s post-collection growth is capped by `Nursery::grow`'s remembered `live_target_words`, inflating the door's `need` breaks `heap_exhausted(need)`'s fail-fast for a `+hmax` process *and* overrides a user's `+hms`, and deferring the debt term contradicts `../tests.rs::the_collection_debt_forces_a_collection_the_occupancy_test_would_not` besides lengthening the chain — every capacity figure is a **chain sum**, so a deferral moves `heap_size`/`total_heap_size` in N. Figures and the blast-radius roster: [`MEASURED.md`](MEASURED.md).

## Constraints

* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data. A `None` from `plain_bump` or a `false` from a valve is an outcome, never an error.
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`; this node's `gc.rs`, `gc_walk.rs`, `gc/bin_vheap.rs` and `gc/valve_bounds.rs` carry their own `#![allow(unsafe_code)]` with a `// SAFETY:` rationale at each site (the walk reads raw region pointers, and the caller's completeness claim is its safety contract).
* **A reclamation is an optimization, never a correctness lever**: every gate of every prune declines rather than guessing, so a declined collection's or prune's residual is a **leak**, never a dangling pointer — never weaken a gate to make a figure look better.
* **Never fabricate a counter or a figure**: `collections`/`reclaimed` come from real collections and `memory` keys from real allocations, and a `system_info`/`statistics` key this runtime does not sample answers `undefined` or a typed gap rather than a plausible number.
* **`beam_gc` owns every sizing decision and every collector internal** — this node may not re-derive a size, cache a bound that can move, or edit a sibling (`../../runtime/gc.rs` included); a change the analysis needs in `beam_gc` is escalated, never worked around here.
* **One sentence per line**, and every new fact goes to the node that owns it: a `beam_gc` sizing property to `beam_gc`, a runner park-arming property to `../../runner/`, a measurement to [`MEASURED.md`](MEASURED.md). `gc.rs` and `gc_walk.rs` are one cohesive concern each and are not restructured ([`../../CONTEXT.md`](../../CONTEXT.md) *File-size overages*).

## Known Issues
Every entry is a typed gap, a measured own-state difference or a documented divergence — never a wrong result. Ledgers: [`../../../M1_GAPS_GC.md`](../../../M1_GAPS_GC.md), [`MEASURED.md`](MEASURED.md).
* **The off-heap reservoir's residual is a LEAK, never a dangle, in three shapes**: a `Wait` park (a `receive` that never wakes) reaches no prune, so the reservoir lives until the machine drops; a declined prune retains the whole reservoir; and the `-eval`/single-pass route never prunes the **reservoir** at all (its machine is not in `RunnerState` and allocates on the arena), though the `eval_off_heap` store it owns is swept at the two points above.
* **A slice that never pre-empts reaches no prune — the one UNBOUNDED shape.** A linked chain charges **no reduction per link** on the default tier (`Linker::emit_tail_exit`; `jit/baseline/runtime.rs::jit_tail_call` is only the checked frame pop) and a BIF/`call_ext` only *spends*, so a self-recursive tail loop whose body builds a binary plus BIF calls runs its whole computation inside one slice — no park, no prune, reservoir linear in the loop count — where `max_heap_size`/`+hmax` bound nothing (they charge through `set_off_heap_binary_bytes` **at the prune**).
  The repair is a charge on the linked tail exit/block entry, a `beam_engine` change this node cannot make: a host-side BIF-dispatch charge cannot substitute (the engine parks at block granularity, so a mid-block refusal re-executes the block's prefix) and a mid-slice prune is unsound (a running machine's roots are unpublished). `BEAM_RT_TIER=interpreter` is the honest mitigation.
* **A fun-loop body never reaches the reservoir arm**: each lambda application is a nested `run_label_blocking` machine whose reservoir is adopted into `Runtime::eval_off_heap` when it drops, so the envelope is a converged capacity and an out-of-scope payload is retained (the anti-dangle half, [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs)).
* **Heap observables are CAPACITY summed over the nursery chain**: `heap_size` sums the current **and every retired** space, `total_heap_size` adds the mature capacity, and `grow_nursery` alone moves **no** counter — so a flat figure proves a *collapsed* chain, not the absence of growth; `process_info(P, garbage_collection)`'s `minor_gcs` is `minor_since_major` (reset on every fullsweep), never a total. The discriminating counters are `gc_stats()` and `Collector::young_space_count()`.
* **A monotone `erlang:memory(binary)` ladder is a slice phase, not a leak** — a fixed-offset read samples the same point of the cycle; the two tests of a real leak are a trough that grows with the **park count** and a peak that grows with the iteration count at **zero** parks.
* **The walk, not the copy loop, is the collection path's cost**, and the doors are **not** a first-order cost of running the OTP compiler in-process — the arithmetic that looks collector-bound comes from reading `words_reclaimed` as a live-set figure (it is survivor-adjusted; a round's input is `words_copied + words_reclaimed`). Figures: [`MEASURED.md`](MEASURED.md).
* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path** — no `Process` to sum and the arena exposes no word accessor; closing it needs a `MinimalContext` arena-words accessor plumbed through `Runtime` (owner `beam_engine`).
* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window** — a machine field the closed `RootSet` shape cannot carry, so `Machine::with_roots` parks it (with the two failed-clause argument latches and the two supplied-trace latches, `const LOOSE_HEAP_TERMS = 5`) at the tail of the Erlang stack and re-seats it from the slot the host wrote back; across a park `../../runner/run.rs::publish_parked_roots` publishes it **first** of `Registers::extra_roots`, and `resync_parked_roots` reads it back and clears them.
* **Per-walk memoisation across walks is unsound** — a heap address is reused as soon as its object is collected, so the generation-stamped reset is what makes reusing the table free.
* **The `../../runner/` collection/reduction pins belong to that node**, not to the valve — their per-iteration prices are `beam_engine`'s charge stream.
* **Fixture rule for a reservoir witness**: the feeding shape is an **inline** `bs_create_bin`/`bs_init_writable` in the loop body — a binary built in a **callee** and *returned* does not accumulate in the engine reservoir (the compaction is on the return path).

## Test Strategy
Colocated units plus integration suites; **no test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle**.
* **Growth seam** — [`../../../tests/heap_growth.rs`](../../../tests/heap_growth.rs): a `test_heap 401 1`-scale request reaches peak nursery capacity with `fallbacks == 0`, and a `+hmax` below the request still falls back to the arena and completes; three colocated cases cover `alloc_words_rooted`'s forced-`garbage_collect` handling (served, consumed exactly once, a declined forced request left armed), and the bump arm's decline side is `../tests.rs::a_rooted_allocation_whose_bump_is_refused_grows_the_nursery_instead_of_declining` and `…_is_declined_when_a_live_root_lives_in_an_unscanned_region`, plus the per-door counter census.
* **Valve** — pinned twice in `valve_bounds.rs`: `the_two_tier_test_matches_the_exact_predicate_in_every_region` (the pre-filter expression kept verbatim as the oracle over the current space, a growth-retired space, the mature generation, the pooled BIF heap, the arena, an immediate, a tagged literal, the inert foreign leaf and a foreign container forwarding a scanned word, on **both** collector kinds) and `the_filter_does_not_change_a_collections_counters`; plus `the_result_shape_test_is_the_region_classifiers_own_prelude` and `the_aggregate_span_is_reported_for_both_collector_kinds`.
* **Door policy** — `../tests.rs::the_collection_debt_forces_a_collection_the_occupancy_test_would_not` is the **one** direct pin of the debt→collection implication (it drives `ensure_heap_full(0, …)`, fabricates debt through `Process::grow_nursery`, then asserts `collections + 1` and `!collection_debt()`); `collection_debt()` false after an admission door is otherwise unpinned, the only sibling assertions being `../calls/exempt_window_tests.rs`'s two exempt-window checks. `peak_young_spaces == 1` / `debt_boundaries == 0` is pinned at slice boundaries by `../../runner/tests.rs::the_heap_growth_workloads_per_call_counters_are_flat_in_n`, `../../runner/tests/{boundary_cost,reds_door,slice_charging}.rs` and [`../../../tests/gc_collect.rs`](../../../tests/gc_collect.rs). The `debt` valve counter is tallied only in `#[cold] ensure_heap_full_commit` (a `#[cfg(test)]` re-read), so an earlier short-circuit moves `valve_counters`/`BEAM_RT_VALVE_TRACE` figures even at an unchanged cadence.
* **Literal roots and plateaus** — `../tests.rs::a_tagged_literal_root_is_scanned_and_the_loop_collects` (the constant-payload twin of `copy_bound/ets_copy` plus a heap-built twin), `refs_plateau.rs::a_process_that_mints_a_reference_per_iteration_keeps_a_bounded_heap`, [`../../../tests/foreign_root_loop.rs`](../../../tests/foreign_root_loop.rs).
* **Off-heap prune**, colocated in `bin_vheap.rs`: the trigger's strict inequality, `record_collection`'s re-size/re-prime, every gate declining without releasing, a clean-root prune releasing everything unreachable, a scanned-root payload retained, the two foreign declines and the `refcount() > 1` belt. Fixture rule: a nested `for_process` machine builds on the process's **scanned** young heap, so a fixture's *returned* term is a retention rather than a decline, and every decline case constructs its root.
* **End-to-end** — [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs) (`a_retained_off_heap_binary_survives_the_fun_loop_byte_exactly` is the anti-dangle gate), [`../../../tests/eval_off_heap_reclaim.rs`](../../../tests/eval_off_heap_reclaim.rs), and the boundary door's rates in `../../runner/tests/{boundary_cost,reds_door}.rs`.
* Crate gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --lib --no-fail-fast`; the integration half is `tests/{heap_growth,off_heap_reclaim,eval_off_heap_reclaim,foreign_root_loop}.rs`. Wall-clock-sensitive neighbours (boot-drive/CLI suites) can fail on a loaded host — re-run before calling a failure a regression.

## Notes for Agents

* **Read `beam_gc/CONTEXT.md` and `beam_gc/src/policy.rs` before touching a size, and [`MEASURED.md`](MEASURED.md) before re-deriving any figure** — the sizing laws are re-derivable from source, the measurements are not.
* **Measure in retired instructions on a pinned core** (`taskset -c 2 perf stat -e instructions:u`, `cpu_core/instructions` only — the hybrid CPU emits two PMU instances), paired and alternating, with a from-source rebuild as the control: a stashed binary is never a control ([`../../../STARTUP_COST.md`](../../../STARTUP_COST.md) *Measurement discipline*).
* **A door change has a blast radius wider than this node**: re-read the pins above before deferring the debt term, moving a collapse between doors, or adding a growth site (`may_replace_young_space` covers exactly four).
* **Diagnostics are env-gated and silent by default**: `BEAM_RT_VALVE_TRACE` (the valve census, stderr at driver exit), `BEAM_RT_GC_TRACE` (`[rt-heap]`, one line per copy-out nursery growth: pid, hint, request, available, young capacity, chain-summed used words, space count, debt flag, exempt flag), `BEAM_RT_MEM_TRACE` (`[rt-mem]`, `RetentionStats` and the trim's answer), `BEAM_RT_TIER`, `BEAM_RT_REGION_RECLAIM`, `BEAM_RT_PERF_COUNTERS`. Nothing may emit unconditionally and nothing may depend on them.
* **`gc.rs` is this node's production module root** (the doors, the classifier, the alloc seams, the root hand-offs); `gc/` holds the three prune/door children whose subject is separable plus the two test-only suites — do not add a child file here for something the production root already owns.
* Scratch temp dirs come from `crate::context::test_support::scratch_dir(label)`, never a hand-rolled `temp_dir()` path — a concurrent test **process** collides.
