# `beam_rt::context::gc` — heap doors, allocation seams and the off-heap prunes

## Intent

The GC/heap half of the concrete `ExecutionContext`: where a scheduled process's memory comes from, when a collection may run, and how off-heap payloads are released.
It owns the five collection sites with their no-relocation growth/retry discipline, the per-word unscanned-root classifier with the reachability walk that gates every collection and prune, and the two off-heap prunes (the machine's refc-binary reservoir and the NIF resource terms).
The seam-level contract is [`../CONTEXT.md`](../CONTEXT.md)'s; the root-set/relocation seam is [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md)'s.

## API Surface

### The off-heap refc-binary reclamation — `gc/bin_vheap.rs`
A process's off-heap refc binaries live in the machine's reservoir (`Machine::refc_binaries`), outside every heap the collector owns, so a collection can never sweep them: they are **pruned separately**, at the slice boundary.
`gc/bin_vheap.rs` owns that point — `OffHeapReclaimer` is a process's binary virtual heap (the C `p->bin_vheap_sz` through `beam_gc::BinVheap`, plus the observed `MSO(p).overhead`) and `reclaim(runtime, table, pid, machine, slot)` is the prune.
`observe` is `O(1)` while the reservoir's handle count has not moved (the engine only ever appends between prunes), so `Machine::off_heap_overhead_bytes` — `O(reservoir)` — is read only when the count moved or once per triggered prune, never on the per-slice path.
`triggered()` is the C's `off_heap.overhead > bin_vheap_sz` (strictly greater, bytes turned into words by truncating division), and `record_collection` reproduces the C's `p->bin_vheap_sz = next_vheap_size(...)` / `MSO(p).overhead = bin_vheap` pair from the payload that survived.
The release is `Machine::retain_refc_binaries` with `live(p) || shared(p)`, where `live` is what `beam_gc::for_each_reachable_binary_payload` reports over the process's roots and `shared` is every payload at `RefcBinary::refcount() > 1`.
It **moves nothing** — a retained payload keeps its exact `data_ptr`, so no live on-heap `BinRef` is invalidated — and the `shared` set is the belt for the second owners this process's roots do not describe (the send path's envelope clone, `Runtime::eval_off_heap`, a writable accumulator).
The state is per process engine (`ProcessEngine::off_heap`), built lazily from `process.collector().policy()` so a `+hms`/`+hbm*` policy is honoured, and it dies with the machine.
**Every gate is a decline**, i.e. the whole reservoir is retained and `Ok(0)` is returned — a leak, never a dangle: the pid is not in the caller's table; `Process::is_relocation_exempt()`; `!Runtime::gc_process_enabled(pid)`; the bin vheap has not triggered; the collection valve `valve_verdict` declines; the **prune-only** valve `gc_walk.rs::reaches_an_unscanned_word` declines; or the reachability walk returns a typed error (traced, then declined).
Both valve declines open the per-pid descent latch (`Runtime::note_foreign_reachable`) exactly as a declined collection does, and **neither closes** it — closing stays with the three doors that hand the walk the machine's whole `RootSet`.
`Process::has_unpublished_roots()` is deliberately **not** a gate: it is `true` for a `ProcessState::Running` process, which a pre-empted process still is, so consulting it would disable the point entirely; the correct pair is `is_relocation_exempt()` plus the park's own `parked_published` flag.
Afterwards `Process::set_off_heap_binary_bytes` republishes the surviving figure, so `max_heap_size`'s `include_shared_binaries` charge sees real bytes.
A released payload's bytes leave `binary_alloc`, so `erlang:memory(binary)` — `memory_hook.rs`'s `allocator_live_bytes(AllocType::Binary)`, read live on every call — reflects the release; that is a **different** observable from `erlang:process_info(P, binary)`, which is the per-process roster (`../native/memory/binary.rs`).
**A second, disjoint reclamation covers the `-eval` route's escaped store** — `src/eval/reclaim.rs`, reached from `Evaluator::prune_escaped` at the tree-walker's depth-0 statement boundaries (`eval/mod.rs`). It is not this arm: different store (`Runtime::eval_off_heap`, not a `Machine` reservoir), different trigger (handle count moved **and** summed `reserved_bytes` > `STORE_BUDGET_WORDS` = 46 422 words, the C's `BIN_VH_MIN_SIZE`) and different roots.
Its guards: the **named live sets** (evaluator env + reduced value, escaped closures' envs, `seq_trace` tokens, every process's dict + mailbox, pending spawns) are walked as terms — they may decline; the runtime's **term regions** (`eval_heap` + retired, pooled BIF heaps, `info_heap`) are scanned as **word images** ([`Runtime::for_each_off_heap_region`](../../runtime.rs)) by the `HEADER_BIN_REF` pattern only, dereferencing nothing, and are **never** pushed as roots (a region interleaves heap objects with the raw payload words of on-heap binaries — `binary:copy(<<1>>, 40000)`'s `0x01` bytes read as `0x0101_0101_0101_0101`, low bits `TAG_PRIMARY_LIST`, which dereferences to a `SIGSEGV` in `walk`; that was the measured fault, on the fourth `-eval` of `base64:encode(binary:copy(<<1>>, 40000))`, i.e. the first statement whose summed payload bytes crossed the budget); any doubt (visit budget, unknown boxed header) **declines** the whole prune; `RefCount > 1` ⇒ retain.
Measured with `tests/eval_off_heap_reclaim.rs`: 20 evals × 6 throw-away `base64:encode(binary:copy(<<1>>, 40000))` builds (120 payloads) stay at **≤ 327 680 bytes / ≤ 5 handles**, sawtooth, with **23 prunes** and 0 declines; the same loop with the reclaim off (`Runtime::set_eval_prune_enabled(false)`) reaches **7 864 320 bytes / 120 handles** — exactly one per build.
The `run` route's nested-call payloads are covered by a third entry point on the same store: the nested-run epilogue (`context/pump.rs` → `RuntimeContext::adopt_nested_payloads` → `Runtime::prune_off_heap`) adopts every handle the finished machine built, publishes that machine's **own** root set (its X registers, its whole Erlang stack and its FR file through `Machine::with_roots(RootSet::ALL_LIVE)`, plus the term it is about to return), and prunes against it unioned with the guards above — the guards, the root build and the walk are the same code, and the gate is `O(1)` (`Runtime::off_heap_prune_pending`, one handle-count compare in the steady state, so a hot lambda application pays nothing).
That prune releases **only** the handles the run itself adopted; an out-of-scope entry is retained unconditionally, because a nested site can name one machine's roots while the *enclosing* machines of the same process hold terms this crate cannot see — measured: sweeping the whole store there makes `lists:map/2` over 200 engine-built 40 000-byte binaries return **190 corrupted elements**, against 0 when it sweeps only its own handles.
Uncovered, each a leak and never a dangle: `apply_eval_closure` (never prunes: its caller's terms are live and unnameable), the engine arena (`beam_engine::MinimalContext`'s `ContextHeap` has no word-range accessor) — covered only nominally, because the region scan finds a `[BinRef][ErlSubBits]` pair by its own header wherever it stands — and the `eval_heap` **region** (the region, not the payload store), whose growth is bounded by the statement window that `../eval/scratch.rs` runs before each top-level `-eval` statement — with two residuals by construction, a single giant statement (its value *is* the result) and the retired regions `Runtime::grow_eval_heap` never frees.
A nested run that **raised** takes the plain adopt path and leaves the store alone: a raise's reason term rides `beam_common::Raise`'s live-reason slot rather than the frozen root set, so no root can name it.

The one call site, its per-slice cost and the residuals: [`../../runner/CONTEXT.md`](../../runner/CONTEXT.md) *The off-heap refc-binary reclamation at the slice boundary*; the criterion's mechanics: `gc_walk.rs`'s module docs.
The measured envelope this point produces — the N-step figures, the sawtooth ladder, the A/B and RSS pair and the retained-payload half — is [`../../../CONTEXT.md`](../../../CONTEXT.md) *Known Issues / Intentional M1 gaps*'s off-heap bullet; the suite is [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs).
The end-to-end effect on a real workload — `emqx_base62:encode/1` on the unmodified EMQX module, `PRE-FIX` vs `POST-FIX` vs the oracle — is [`../../runner/CONTEXT.md`](../../runner/CONTEXT.md) *Measured*.

### The NIF-resource-term prune (A.3) — `gc/resources.rs`
`reclaim(runtime, table, pid)` is the caller half of `beam_abi`'s resource-release seam: it drops the reference every resource **term** took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs (`beam_abi/src/nif/enif/resources_release.rs` documents the soundness contract — a false "unreachable" is a use-after-free).
The **scheduled** site is the runner's `Yield` park arm, immediately after the off-heap refc-binary prune and under the same `engine.parked_published` gate; an exempt (`Wait`) park publishes nothing and both prunes decline, and the routes that never park (`-eval`, a nested run) are served by the two non-park sites in `../eval/reclaim/resource.rs`.
Gates, all declines: an empty `resource_terms()` (one registry read, no walk), the process is in the table, `!Process::is_relocation_exempt()`, `Runtime::gc_process_enabled(pid)`, and the prune-only valve `gc_walk.rs::reaches_an_unscanned_word` — classified over the **process's own** roots only, never the host root sources, which are a *separate* seed set handed to the reachability walk because every host word is a `WordRegion::Foreign` root and folding them into the valve would decline every prune a resource program attempts.
The walk (`gc_walk.rs::reachable_resource_words`) then collects every reachable candidate word **or reference identity** — a resource term is an internal reference, so a `copy_struct` copy (the send path, ETS) is a different word with the same id, and matching the word alone would free an object a live copy still designates.
Residuals: a candidate whose identity cannot be read is kept; the cadence is the park cadence (a target that returns immediately never parks, and the `-eval` route never parks at all); a resource held only by a store no site enumerates — a `persistent_term` value, an ETS object — is released, because the host root sources are exactly the families `Runtime::gather_off_heap_roots` publishes (the escaped closures' environments, the `seq_trace` tokens, `pending_spawns`, every pending timer **delivery**, every live process's dictionary/mailbox/registers/saved-args/signals, and an engine's un-consumed arena-stable arguments plus an un-published parked machine's root set); the two per-pid families are empty **at this arm** — a pass moves the process table (`take_processes`, an equivalent empty placeholder) and `RunnerState` out of the runtime — so they are live only at the two non-park sites (`../eval/reclaim/resource.rs`), and the executing process's own roots are the arm's **local** list; and the identity match is by reference **identity** (the `id` word, which every local reference producer draws from one shared space), so a copy of a resource term is reached wherever it is reachable from — a copy in a region nothing names stays dead data.
Detail, ground truth and the residual list: `gc/resources.rs`'s module docs; the pinning suite is [`../../../tests/nif_resource_gc.rs`](../../../tests/nif_resource_gc.rs).

### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` (`runtime_hooks.rs::garbage_collection`) answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's **node-global cumulative** counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran, and `reclaimed` (in words) is advanced by each collection site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`, never an estimate.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`, where the oracle's are per-scheduler accumulators of a far larger emulator: the quantities match, the magnitudes do not.
The five collection sites and the accounting detail: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#erlangmemory01-and-erlangstatistics1).

### `erlang:memory/0,1` and `erlang:statistics/1`
`erlang:memory/0,1` (`MemoryHook` seam) is adopted: `RuntimeMemory` (`memory_hook.rs`) returns nine oracle keys in oracle order with `total = processes + system`, every figure measured (process heaps from `ProcessTable`'s collectors, atoms from the shared `Rc<AtomTable>`, binaries from `beam_alloc::registry`, `code` from loaded `.beam` sizes, `ets` from `TableRegistry`, `system` = those plus the remaining allocator live bytes excluding `Standard`/`EHeap`) and snapshotted at construction; `memory/1` answers in the requested order, `badarg` for an unknown key.
`erlang:statistics/1` is partly served — `run_queue`, `run_queues`, `run_queue_lengths(_all)`, `total_run_queue_lengths(_all)`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io` and `garbage_collection` (`{GCs, WordsReclaimed, 0}` from the node-global cumulative counters) — while `scheduler_wall_time`/`scheduler_wall_time_all` ⇒ `undefined` (no per-scheduler wall time is sampled, so the tuple list is never fabricated).
Gaps: `statistics/0`, the per-scheduler key family (`active_tasks*`/`total_active_tasks*`/`microstate_accounting`) and every other `RuntimeHooks` family — see *Closable host-seam keys* above.

### The unscanned-root valve — two phases
Phase 1 (`root_is_unscanned`, always run) declines over a term only when **both** facts hold: the term is a container in a region the collector does not **scan** (`word_region` → `WordRegion::Foreign` — the pooled BIF heaps, the `-eval` heap, the pointer-stable arena, a message fragment) **and** at least one word it forwards is a pointer the collector *does* scan (`forwards_scanned_word` → `word_is_scanned`: any nursery space, current or growth-retired, or the mature generation). Everything else is inert and declines nothing: an **immediate**, a **literal**, and a word no live term can be at (null or unaligned — `dereferenceable_pointer` rejects those before anything reads them) name no region; and a foreign leaf, all-immediate block, tuple of immediates, reference, pid, port, float, bitstring or empty tuple forwards no word a relocation would follow or update. `forwards_word_matching` drives the same `beam_term::layout::for_each_child_slot` enumeration the copier and phase 2 use, so the valve cannot disagree with the collector about which words an object forwards — `SUB_BITS_SUBTAG`'s `orig` word *is* forwarded, so an `ErlSubBits` over a live word declines while the same shape over a literal is inert. This is what keeps `make_ref/0`'s all-immediates M1 block (an `INTERNAL_REF_WORDS` leaf on the pooled BIF heap) from pinning a loop's valve.
Phase 2 (`gc_walk.rs`) descends the process's scanned graph and root containers under the per-pid descent latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found; the per-word phase alone sees only a root's *own* address.
The valve is consulted at each of the five collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the runner's park arm `Runtime::serve_gc_request`, and `gc/reds_door.rs`'s reduction/yield-boundary door); declining costs a collection and nothing else — the allocation falls back to the pointer-stable arena — so it can never turn a working program into a failing one, and the fallback count is `note_gc_fallback`'s.
The latch's two halves split by **root-set completeness**: a door that hands the walk the machine's *whole* `RootSet` (`ensure_heap_full`, `alloc_words_rooted`, `gc/reds_door.rs`) **closes** the pid's bit on a `ValveVerdict::foreign_free` descent (`Runtime::close_foreign_reachable`), while the narrow `ensure_heap`, the park arm and the `RuntimeCollectionGate` signal sites hand over less than the whole set — `ensure_heap` cannot see the FR file, and an *exempt* park publishes nothing — so they may only **open** it.
The gate a `beam_process` signal site consults is built from the runtime's **one** shared latch cell (`RuntimeCollectionGate::from(latch)`), so a decision is `O(1)` while the pid's bit is clear; the no-latch `RuntimeCollectionGate::new()` form (which always descends) is `#[cfg(test)]`-only.
A term in a foreign region (pooled BIF heap, arena, `-eval` heap, message fragment) declines the collection only when it forwards a scanned word — **not** a foreign term that forwards nothing (see phase 1 above) — and never a registered-BIF result, which `call_registered` copies onto the running process's heap and rewinds the pool to the call's own `mark`, making it a scanned root rather than a foreign holder.

### Debt/valve cost of the admission doors
`collection_debt()` is folded into both doors' occupancy OR, so a growth-retired chain makes the full door evaluate `any_root_is_unscanned` on **every** admission point even when the *current* space has room.
The per-word `root_is_unscanned` classifies in **two tiers** (`gc.rs::word_is_scanned` / `outside_bounds`).
Tier one is the current mutator block (`in_heap_block`, two loads on the space the mutator is already writing) — the answer for nearly every live root, and it is tested **first**, so nothing it accepts pays for tier two.
Tier two is the collector's **aggregate geometry**: `AnyCollector::scanned_bounds()` is read once (`O(1)`, allocation-free — the nursery chain's half is cached inside the chain, the mature half is two reads) and `ScannedBounds::definitely_unscanned` answers for every address outside it with two compares.
Only what the aggregate cannot decide — a growth-retired nursery space, the mature generation, a hole between two scanned regions — reaches the exact tests: `Collector::young_contains`/`Nursery::contains`, which answers in **O(log #spaces)** (the current space is tested directly, since it is the only space whose `top` moves, and a retired-space address is resolved through the ordered `BTreeMap<base, top>` containment index `retired_regions`, `range(..=addr).next_back()` — exactly the predicate `spaces().any(|s| s.contains(ptr))` because the retired regions are disjoint), then `AnyCollector::mature_contains`.
The reject is sound in **one** direction only: the aggregate is the covering interval of every scanned region's **reserved** extent, so `definitely_unscanned == true` proves both exact tests would answer `false` while `may_contain == true` claims nothing, and a fast *accept* is never taken.
The chain is collapsed only by a real collection (`Nursery::collapse`), so a growth-retired chain keeps the full door evaluating `any_root_is_unscanned` on every admission point (see `collection_debt()`).
Measured aggregate widths (`gc/valve_bounds.rs::the_aggregate_span_is_reported_for_both_collector_kinds`, which prints the live figure per geometry — the absolute width is allocator-placement fact and moves between runs, so the shape, not the exact count, is what generalizes): a fresh process spans on the order of **500** words on the copying strategy (233-word nursery + 233-word mature + the gap) and low thousands with the `BEAM_RT_GC_STRATEGY=immix` mature opt-in (a 2048-word mark-region mature at a different offset); a growth that retires a nursery space widens both, and a collection that resizes the nursery collapses the chain and installs a space elsewhere — a representative run printed 469 / 2284 fresh, 848 / 2662 grown and 3489 / 5304 collected (copying / immix).Every region this runtime really produces outside the collector — the pooled BIF heap ([`Runtime::take_bif_heap`](../../runtime.rs)) and the pointer-stable arena ([`Runtime::alloc_words`](../../runtime.rs)) — lies outside all of them, so the reject fires for all four foreign shapes the valve meets (tuple, cons, `ErlSubBits`, `make_ref/0`'s leaf) on both strategies; the interval is **not** monotone (a collection collapses the chain and installs a space sized from the live set), which is why the bounds are re-read rather than cached.
Profile cost, `perf record` on 24× in-process `compile:file("lib/stdlib/src/ordsets.erl")` samples (`taskset -c 3`, interleaved A/B against the pre-filter binary): `Nursery::contains` self time **0.103 % → 0.043 %** of samples (the exact tests the reject removes) while `root_is_unscanned` self time stays **0.40 % → 0.39 %** and `Walk::run` **0.44 % → 0.44 %** — the skipped exact tests and the added bounds read are the same order, so the filter is neutral on this workload; on a reference-minting `send`/`receive` loop at 200 000 iterations it is **0.3 % fewer instructions** and **0.5 % fewer branches**, and no sample moved a valve decision (the counters are below).
The valve's **decisions** are unchanged by construction and are pinned twice: `gc/valve_bounds.rs::the_two_tier_test_matches_the_exact_predicate_in_every_region` asserts `root_is_unscanned` equals the pre-filter expression (kept verbatim as the oracle) for the current space, a growth-retired space, the mature generation, the pooled BIF heap, the arena, an immediate, a tagged literal, the inert foreign leaf and a foreign container forwarding a scanned word, on **both** collector kinds; and `the_filter_does_not_change_a_collections_counters` asserts a fixed root set collects identically every time. End to end, 8 in-process compiles of `ordsets.erl` report `erlang:statistics(garbage_collection)` `{63, 1268177, 0}` and `{heap_size, 233}`/`{total_heap_size, 466}` on both binaries.
The valve accessors in `../runtime/gc.rs` (`gc_process_enabled`, `gc_request_pending`, `foreign_reachable`) test `is_empty()` before hashing, so an empty valve set costs no hash.

### What the doors do NOT decide
The full-root doors decide **whether** a collection may run: each one's own short-circuit — occupancy/`collection_debt`/forced at the admission doors, the reduction interval and the 7/8 occupancy watermark at `gc/reds_door.rs` — then the valve (`root_is_unscanned` over the roots the caller handed over). They do not decide **how often** it runs — the collector's own **post-collection nursery sizing** does, and that belongs to `beam_gc` (`Nursery::collapse` ← `HeapPolicy::young_after_collection`).
The distinction is what makes the A/B evidence in `tests.rs` readable.
The fullsweep path feeds `collapse` the young **occupancy the round observed before the copy** (`beam_gc/src/collector.rs::collect_major`, the immix majors likewise), and `young_after_collection` keeps or grows the capacity unless `capacity > 4 * demand` — so a fullsweep-installed nursery is sticky at whatever size the no-relocation growth seam (`Process::grow_nursery`) last stepped it to.
The C applies **two** rules to one heap: `major_collection` sizes it from the pre-copy young usage (`erts/emulator/beam/erl_gc.c:1866`), and `adjust_after_fullsweep` then **shrinks** it to `2 * need_after` once `4 * need_after < HEAP_SIZE`, with `need_after` the **live** set plus the caller's need plus `S_RESERVED` (`erl_gc.c:2062-2098`).
Feeding a pre-copy occupancy into the collapse implements the first rule only, so the shrink half has no live-set input on that path.
**Measured consequence** on the `ets_copy` allocate-and-abandon loop of [`tests.rs`](../tests.rs) (`gcab_*`, `~13 k` words per iteration): collections at N = 5 000 / 40 000 are **8 → 10 965** for `gcab_free` (0.27/op at the large count — the oracle's own 0.25/op), **1 155 → 12 821** for `gcab_lit`, but **9 → 11** for the float-using `gcab_flt` (every one a fullsweep), where the same loop on the system ERTS reports `minor_gcs` **406 → 3 244** through `process_info(P, garbage_collection)` — linear in `N` in every row.
The valve is **not** the cause of any of it, and neither is the runner's per-slice FR exemption: the counters read `hits == 0` at every door and `fallbacks(ValveDeclined) == 0` on every row, and `pinned == 0` throughout, so the collections that do run are the ones the gate allowed and the ones that are missing were never offered.
The `heap_growth` control (`src/runner/tests.rs`) is the same effect in miniature: the admission door is reached once per iteration — the 401-word request never fits the space the previous collection installed — plus the boundary door's one per pre-emption, i.e. `collections == N + yields` at every measured N (5 000 … 100 000), against the oracle's `minor_gcs == N` exactly.
Restoring the oracle cadence is a `beam_gc` sizing change (give the fullsweep collapse the post-copy **live** demand, as `adjust_after_fullsweep` does); until it lands, the `gcab_*`/`gclit` cases assert the invariants this node owns — the valve declines nothing, nothing is pinned, the loop keeps collecting and the counts grow strictly with `N` — and not the oracle's magnitude.

### Which seam allocates where, and what the latch is (read before touching a heap seam)
- **No heap pointer is cached** — not on the context, not on the machine.
  `alloc_words`/`alloc_words_rooted` re-derive `process.heap_mut()` → `Heap::hp()` on **every** call (`gc.rs::bump`), so nothing can inherit a stale `*mut Eterm` after a collection; the pointer a call returns is uninitialized storage valid only until the next admission point or collecting allocation (`Machine::alloc_rooted` docs), which is why the engine re-reads live terms out of `x`/`stack`/`fr` after any allocating read (`reread_ctx`).
- **`gc_armed` is a per-call *permission* bit, not a "collection is due" flag.** Its only armer is the slice's `BudgetContext` (`../runner/budget.rs`): `ensure_heap`, `ensure_heap_full` and `alloc_words_rooted` arm it, while **`alloc_words` (the unrooted seam) does not** — that seam never collects (its refusal path is the no-relocation `Process::grow_nursery` + retried bump, then the runtime arena).
  Whether a collection is *due* is the door's own test, made inside `ensure_heap_full`/`alloc_words_rooted`: `forced || should_collect(heap_need) || collection_debt()`, then the unscanned-root valve, then `collect_or_grow`.
  `call_ext`/`call_import` reach **none** of the three arming doors (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`), so the engine-side path adds no collection point either.
- **The runtime-native floor route has no copy-out and no pool rewind** (`calls.rs:1142-1146` returns before both), so a floor result stays in whatever region the arm built it in. An arm that materializes on `Runtime::info_heap` (`erlang:system_info/1`, `format_term`) rewinds that region through `Runtime::reset_info_scratch` at its own entry (`runtime.rs`, `native.rs`), which refuses once `Runtime::info_heap_tainted` is latched — so a refused relocation can never be recycled under a live term. `erlang:system_info/1` alone hands a value **out** to Erlang code, so it relocates it first with `RuntimeContext::relocate_off_scratch` (the registered-BIF container copy-out: the running process's scanned young heap, else the table-less `-eval` store), and a retained value is sound (`tests/system_info_retained.rs`).
- **Four regions, never interchangeable**:
  1. the process's own `beam_gc` young heap (`process.heap_mut()` — the only *scanned* region, target of both alloc seams *and* of the process-route BIF copy-out);
  2. the runtime's pointer-stable `arena` (`Runtime::alloc_words`, unscanned — the fallback);
  3. the pooled `beam_alloc::Heap` regions (`Runtime::take_bif_heap`/`put_bif_heap`, where a registered BIF/NIF builds its result, and which `call_registered` rewinds to that call's `mark` once the result has been copied out);
  4. the **table-less store** (`Runtime::eval_heap`, its off-heap payload owner `Runtime::eval_off_heap`, and its retired regions `Runtime::eval_heap_retired` — the `-eval`/single-pass copy-out's destination; pointer-stable, never `reset`, grown only by region replacement, and retained for the run's life because Milestone 1 has no collector on it).

## Known Issues

Every gate above declines rather than guessing, so the residual of a declined collection or prune is a **leak**,
never a dangling pointer.
The measured envelopes and their narratives live in [`../../../M1_GAPS_GC.md`](../../../M1_GAPS_GC.md).

* **The float guard lives on the narrow door alone; the full doors are FR-safe.** `ensure_heap_full` publishes each register file up to its pointer-bearing prefix and the whole stack, so a live float register relocates like any other root; the **narrow** `ensure_heap` (x prefix + stack only) keeps its `module_uses_floats` guard but is not on the engine's path today, and every door refuses a run with **no** caller module (a fun entry, the `-eval` evaluator) rather than guess one.
  Bound and door short-circuits: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-pointer-bearing-prefix-bound-of-the-full-root-doors).

* **Both heap-admission doors OR the occupancy test with the collector's collection debt.** `Process::grow_nursery` retires the young space it replaces instead of freeing it, so a growth-shaped workload keeps its whole allocation history resident until a real collection evacuates it; the doors collect when `forced || should_collect(need) || collection_debt()`, and `should_collect` stays the **occupancy test alone** (pinned by its own unit tests).

* **Only `ensure_heap`/`ensure_heap_full` reach `collect_or_grow`; the two allocation seams short-circuit past the collect.** `alloc_words_rooted`'s non-forced path serves the bump, a **capacity** refusal grows the nursery and retries, and `process.collect()` is reached only when that growth/retry *fails*; the unrooted `alloc_words` has no collection branch at all.
  Consequence, load-bearing for any heap-growth measurement: a loop emitting **no** `test_heap`/`allocate_heap` (`ensure_heap_full`'s only callers) reaches no collecting admission door, so only the **reduction/yield-boundary** door can collect it — `gc/reds_door.rs::collect_at_reds_boundary`, from the runner's `Yield` arm over the published whole `RootSet`, gated by a per-pid `REDS_BOUNDARY_MIN_REDS` interval and a **7/8** occupancy watermark OR-ed with the collection debt.
  That door runs the kind-pinned `Process::collect_kind(CollectionKind::Minor)` — a young-only collection — and escalates to the escalating `Process::collect()` only when the pinned minor reports typed heap exhaustion (the mature space cannot absorb the nursery, nothing copied), so a cadence fullsweep no longer comes from the door itself; on the **default** (native baseline JIT) tier it still fires only where a slice really ends (`../../M1_GAPS.md` *Scheduler / runner*).

* **The heap observables are CAPACITY summed over the nursery chain, so a GC-bound loop's flat `heap_size`/`total_heap_size`/`memory(total)` prove a *collapsed* chain, not the absence of growth.** `process_info(P, heap_size)` → `Nursery::capacity_words()` summed over the current **and every retired** space (`beam_gc/src/nursery.rs:154`); `total_heap_size` adds the mature capacity (`memory_hook.rs:132-174`).
  A churn loop's steady state is bump refusal → `Process::grow_nursery` → the next admission door's `collection_debt()` → `collect_or_grow` → `Nursery::collapse`, so the geometry is constant in N while `Runtime::gc_stats().collections`/`reclaimed` climb; `grow_nursery` alone moves **no** counter, and `process_info(P, garbage_collection)`'s `minor_gcs` is `minor_since_major` (reset on every fullsweep, `beam_gc/src/collector.rs:283`), never a total — the discriminating counters are `gc_stats()` and `Collector::young_space_count()`.
  The boundary door contributes the pre-emption's own collection and nothing more; its firing rate, the per-shape collections/major rates and the young-space peaks (door-on vs door-off) are **measured** in [`../../runner/tests/boundary_cost.rs`](../../runner/tests/boundary_cost.rs) and [`../../runner/tests/reds_door.rs`](../../runner/tests/reds_door.rs), not asserted as a closed-form law.

* **The off-heap prune's residual is a LEAK, never a dangle — in the shapes below.** A process that parks in `Wait` (a `receive` that never wakes) never reaches the prune: that window is relocation-exempt and publishes nothing, so the machine stays the authoritative root set and the reservoir lives until the machine drops with the process (a process that wakes and yields again prunes then).
  A declined prune — any gate, the two valves and a failed reachability walk included — retains the whole reservoir.
  The `-eval`/single-pass route never prunes **the off-heap refc-binary reservoir** at all: its machine is not in `RunnerState` and allocates on the pointer-stable arena, whose park arm publishes nothing.
  That is not the store this route prunes: `Runtime::eval_off_heap`, the escaped-payload store a nested run adopts a finished machine's handles into, IS swept — at the `-eval` driver's depth-0 statement boundaries (`../eval/reclaim.rs`) and at the nested-run epilogue (`pump.rs::adopt_nested_payloads`).
  The cadence is the **pre-emption** cadence (the `Yield` arm, `../runner/run.rs:1214`), so a payload-building loop whose payloads land in the machine's reservoir is bounded by the bin-vheap budget even if it never reaches a `receive`: measured `4 144` bytes at N = 1 000 and `4 144` at N = 10 000 (4 096-byte payloads), `65 584` / `65 584` at 65 536 B — one surviving payload, flat in N.
  A **fun-loop** body (`lists:foldl/3`/`lists:foreach/2`) never reaches *this* arm — each lambda application is a nested `run_label_blocking` `Machine` whose reservoir is adopted into `Runtime::eval_off_heap` when it drops (`../context/pump.rs`, `../runtime.rs`) — but that store is pruned at the nested epilogue, so the envelope is a converged capacity: measured `377 104` bytes at both N = 1 000 and N = 10 000 with 4 096-byte payloads and `393 504` at both with 65 536-byte ones, against `4 144 000` → `41 440 000` (exactly `N × (Bytes + 48)`) before, because an out-of-scope payload is retained. The witnesses are [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs)'s `a_retained_off_heap_binary_survives_the_fun_loop_byte_exactly` (anti-dangle) and its (green, un-`#[ignore]`d) `the_fun_loop_envelope_is_bounded_by_the_bin_vheap_budget`, plus [`../../../tests/eval_off_heap_reclaim.rs`](../../../tests/eval_off_heap_reclaim.rs)'s nested anti-dangle case.
  The per-slice price of the point itself is one cached observation on a non-triggered bin vheap.

* **A slice's live float register is handled by a per-slice relocation exemption — never a permanent pin** (the guard, its decline-only bounds and the measured plateau are [`../../runner/CONTEXT.md`](../../runner/CONTEXT.md)'s).
  This node's half: the valve does **not** decline a float root — the engine's FR model holds *terms* built on the executing process's own young heap, so `fr[0]` is a **scanned** root (`tests.rs::a_live_float_term_in_fr_is_a_scanned_root`).

* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** It is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it; `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (relocated in place) and `resync_parked_roots` reads it back into `pending_exception_mut()` and clears the extra roots.

* **The arena fallback is kept sound by a two-phase unscanned-root valve.** At each of the five collection sites the valve **declines** (`Ok(())`) any collection whose roots — or process-side scanned graph — reach a foreign container **that forwards a word the collector would follow or update**; a foreign container forwarding **nothing scanned** is inert, and the per-pid descent latch is **not** sticky (opened on a hazard, closed only by the three whole-root doors, never by a site handing over less than the whole root set).
  A decline costs a collection and nothing else (the allocation falls back to the pointer-stable arena); the two phases, the five sites and `note_gc_fallback`: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-unscanned-root-valve--two-phases).
  The off-heap prune runs the same valve and then its own stronger one, and opens the latch on either decline without ever closing it (see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)).

* **A module-literal root does not decline the collection: `beam_loader` load-time tags the literal area.** A constant payload is folded into the module's **literal area**, so the loop's only live root `x(0)` at its `test_heap` site IS that literal pointer; `LiteralArea::decode` calls `beam_term::literal::tag_literal_area` — the safe form of the C load-time `erts_set_literal_tag` — before publishing, so every literal root carries `TAG_LITERAL_PTR` **set** and `gc.rs::root_is_unscanned` classifies it by the C's bare-bit `erts_is_literal` rule: an immutable, never-moved region, so the valve **passes** and a constant-payload loop's `collections` scale with N.
  Tagging also removes a shared-literal corruption hazard: an untagged literal is silently **writable** (`beam_engine/src/terms/update.rs::set_tuple_element` refuses an in-place tuple write only when `is_literal` holds).

* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path** — there is no `Process` to sum (it allocates on `Runtime::arena`, whose `Arena` exposes no word accessor, so both are an honest `0`); closing it needs a `MinimalContext` arena-words accessor plumbed through `Runtime` (owner `beam_engine`).

## Test Strategy

* `gc.rs`'s growth seam is pinned by [`../../../tests/heap_growth.rs`](../../../tests/heap_growth.rs) (a `test_heap 401 1`-scale request reaches peak nursery capacity with `fallbacks == 0`; a `+hmax` below the request still falls back to the arena and completes).
  The forced-`garbage_collect` handling of `alloc_words_rooted` by three colocated cases (`…serves_a_forced_request_a_bump_would_have_answered`, `…consumes_the_forced_request_exactly_once`, `…leaves_a_declined_forced_request_armed`).

* **The literal-root collection behaviour** is pinned by `tests.rs::a_tagged_literal_root_is_scanned_and_the_loop_collects` over the constant-payload twin of the bench's `copy_bound/ets_copy` shape and a heap-built twin: the tagged literal root passes the valve and is indistinguishable from the heap-built one, which is the point.
  The decline side is the general valve cases (a live root in an unscanned region, the nesting pair, `an_ordinary_young_only_root_set_is_never_declined`), the **inertness** rule its own pair, and the end-to-end plateaus `refs_plateau::a_process_that_mints_a_reference_per_iteration_keeps_a_bounded_heap` and [`../../../tests/foreign_root_loop.rs`](../../../tests/foreign_root_loop.rs).
  The scanned filter is `gc/valve_bounds.rs`; measured widths: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#debtvalve-cost-of-the-admission-doors).

* **The off-heap prune's suite is colocated with its module** ([`gc/bin_vheap.rs`](../gc/bin_vheap.rs)): `the_trigger_is_strictly_greater_than_the_budget`, `record_collection_resizes_the_budget_and_reprimes_the_observation`, `every_valve_declines_without_releasing_anything`, `a_prune_with_clean_roots_releases_every_payload_nothing_reaches`, `a_payload_a_scanned_root_reaches_is_retained`, the two foreign declines (`a_live_term_the_collector_cannot_scan_declines_the_prune`, `a_foreign_child_of_a_scanned_root_declines_the_prune` — asserting the collection valve passes exactly what the prune refuses) and the `refcount() > 1` belt (`a_payload_another_handle_holds_survives_the_prune`).
  The suite's own reading caveat — a machine driven outside the runner's armed latch allocates on the pointer-stable arena, so a *fixture's returned* term is a decline rather than a retention, which is why the positive halves install their own roots — is in the module docs; the end-to-end `erlang:memory(binary)`/RSS witness is [`../../../tests/off_heap_reclaim.rs`](../../../tests/off_heap_reclaim.rs), its figures [`../../../CONTEXT.md`](../../../CONTEXT.md)'s off-heap bullet.
  **Fixture-authoring note for a reservoir witness**: the reservoir-feeding shape is an **inline** `bs_create_bin`/`bs_init_writable` in the loop body, which is what that suite builds. A binary built in a **callee** and *returned* does not accumulate in the engine reservoir — the compaction is on the reservoir on the return path — so a witness written that way never exercises the prune (a measured observation, owned by the `beam_engine` node).

* The valve's decline side, its inertness rule and the aggregation widths are `gc/valve_bounds.rs`'s own units.
* The boundary door's firing rate and the per-shape collections/major rates are measured in [`../../runner/tests/boundary_cost.rs`](../../runner/tests/boundary_cost.rs) and [`../../runner/tests/reds_door.rs`](../../runner/tests/reds_door.rs), never asserted as a closed-form law.

## Routing Table

Each entry is the module's one-line purpose; the mechanics companion is [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md).

  It also re-exports the off-heap prune (`pub(crate) use bin_vheap::{reclaim, OffHeapReclaimer}`), the runtime-side counterpart of the collection doors.

* `gc/` → the admission seam's child modules: `reds_door.rs` (the reduction/yield-boundary collection door the runner's `Yield` arm reaches, a whole-`RootSet` door that closes the descent latch), `bin_vheap.rs` (the off-heap refc-binary reclamation point — `reclaim` + `OffHeapReclaimer`, see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)), `valve_bounds.rs` (the aggregate-vs-exact scan-bound equivalence suite) and `refs_plateau.rs` (the reference-minting heap plateau).

* `gc_walk.rs` → the unscanned-root reachability walk (`any_root_is_unscanned`/`process_roots_are_unscanned`, the reusable `WalkScratch`, `ForeignLatch`) + `RuntimeCollectionGate`, the `beam_process::CollectionGate` host seam; the one traversal serves **two** criteria (`enum Criterion { Collection, PayloadPrune }`, `Walk::begin(scratch, bounds, criterion)`), the three collection doors pass `Criterion::Collection` and the off-heap prune reaches `Criterion::PayloadPrune` only through `reaches_an_unscanned_word` (see [the section above](#the-off-heap-refc-binary-reclamation--gcbin_vheaprs)); the two phases: [`IMPLEMENTATION.md`](../IMPLEMENTATION.md#the-unscanned-root-valve--two-phases).


* `gc/resources.rs` → the NIF-resource-term prune's caller half; the soundness contract is `beam_abi`'s
  (`src/nif/enif/resources_release.rs`), the pinning suite [`../../../tests/nif_resource_gc.rs`](../../../tests/nif_resource_gc.rs).
* `gc/refs_plateau.rs` → the reference-minting heap plateau witness: such a loop keeps `erlang:memory(processes)` flat, because every minted reference is an immediate-like term with no heap growth.
* `gc/valve_bounds.rs` → the word-classifier oracle: the two-tier scanned test (`word_is_scanned`/`outside_bounds`) over the collector's own bounds, aggregate widths per geometry, and the exact-predicate equivalence pins.
* `gc/reds_door.rs` → the reduction/yield-boundary door the runner's `Yield` arm reaches: a whole-`RootSet` door that closes the per-pid descent latch, running the kind-pinned `Process::collect_kind(CollectionKind::Minor)` and escalating to `Process::collect()` only on typed heap exhaustion.
* The runtime-level GC state/accounting/valves are [`../../runtime/`](../../runtime/CONTEXT.md)'s; the root-set
  completeness seam and the at-risk roster are [`../IMPLEMENTATION.md`](../IMPLEMENTATION.md)'s.
