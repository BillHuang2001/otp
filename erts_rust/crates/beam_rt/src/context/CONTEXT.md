# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → dispatch memo → `call_registered` → external-module load), the nine bridge arms, the dispatch memo (`dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), caller-module tracking, the **lent-`TableRegistry` propagation into a nested fun application**, the **in-machine execution-position door** (`position.rs`) and the node's real `LOCAL_EXT` hash (`node_hash.rs`).
The nine `beam_engine::Mailbox` seam methods live in [`../mailbox.rs`](../mailbox.rs); the scheduler/runner that drives this glue in [`../runtime/`](../runtime/CONTEXT.md).
Mechanics-level companion: [`IMPLEMENTATION.md`](IMPLEMENTATION.md) — the root-set/relocation seams, the at-risk roster, the execution-position door, the per-call cost and the closable host-seam roster.
The three subsystem children carry the rest: [`calls/CONTEXT.md`](calls/CONTEXT.md) (dispatch · bridges · interners), [`gc/CONTEXT.md`](gc/CONTEXT.md) (heap doors · valves · off-heap prunes) and [`pool/CONTEXT.md`](pool/CONTEXT.md) (the BIF-result copy-out and the term stores).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module`, `engines`, `suspend_requested`, `gc_armed`, `dispatch_memo` and `lent_tables`.
Its methods: `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`lent_tables` is set only by `FunBridge::nested`; `new`/`with_output`/`for_process` set it `None`.
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`calls.rs`'s `call_bif_routed`).
`wants_reduce` returns `false` (the default `reduce` is a no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext`.
**The BIF suspend channel** (`beam_engine::BifOutcome`): `call_bif_outcome`/`call_bif_in_machine_outcome` are overridden to run the value-returning route first (`Err` propagated unchanged, never converted) and then fold the `suspend_requested` latch — `take`n unconditionally, so no stale bit can leak into the next dispatch — into `BifOutcome::Suspend`, which makes the engine park on the **unapplied** BIF instruction and re-execute it on resume. `suspend_requested` is a per-call permission bit like `gc_armed`: constructed `false` at every context construction site and armed by exactly **one** arm, the native floor's `erlang:port_command/2,3` on a busy port whose caller may not pump (`crate::port::busy_wait::PortWrite::Parked`) — never by the shared `send` route, which the inline `Instr::Send` also reaches (a latch set there would be taken by the next dispatch). The runner's `BudgetContext` forwards both doors (pricing only a `Return`) — without that the scheduled path would fall back to the trait default and never suspend.
**No `ets:*` key is intercepted or re-implemented in `beam_rt`**: `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the `beam_bifs` registry shadowed by nothing.
The one `ets`-family special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` through the **same** `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation (`runtime::ets_owner::adopt_created_table`).
**`resolve_external_call` — the in-machine cross-module call seam.** `RuntimeContext` overrides it so a `call_ext*` callee runs **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4`/`start_link/4` answer `{ok,pid}`, [`../../tests/proc_lib_start.rs`](../../tests/proc_lib_start.rs)) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It loads an uncached callee on demand (`find_module_file` + `code_server.load`) and returns `Ok(None)` (keeping the synchronous `call_bif` path byte-for-byte) for a floor-served name (`native::floor_shadows`, **key-granular**: `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label.
**The one exception to the `host_serves` refusal is the fun-applying class inside a slice**: `apply::prefers_module_code_for_fun_apply(may_pump_scheduler(), module, function, arity)` is `!can_pump && beam_bifs::needs_fun_caller(..)`, and a `true` answer enters the module's own code instead, so the caller's fun runs in the caller's machine and a blocking `receive` suspends the process rather than folding into `blocked()` (see *Known Issues*).
`callee_observes_its_call_site` is **module-wide** for `erlang:load_nif/2` and **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, which must stay synchronous so the function cannot park with an unpublished `Machine::pending_exception`.
The seam **exempts a built-in NIF library** (`crate::native::prim_tty::is_builtin_library`, A.7's `prim_*` family) from the module-wide verdict: it registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the `blocked()` gap.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure (`module` = the **same** `Arc<Module>` the code server caches; `label` = the lambda's `FunT` entry label).
A fun with no local closure goes to `external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`) has no closure but its identity *is* the callee's `M:F/A`, so it resolves to that module's export label through the cross-module seam's **own** `resolve_external_call`, under the same refusals; `Ok(None)` remains for the fun kinds with no in-machine entry (the `-eval` closure `EVAL_FUN_UNIQ`, a **served** local stub key — see below — and any external fun the resolver refuses), keeping the value-returning `apply_fun` fallback byte-identical.
**The fun-in-record indirection (`served_local_key`, `apply.rs`).** A **named local** `fun` (`fun deflate_nif/4`, a `FunKind::Local` term with `num_free == 0`) whose descriptor names a function this host **serves** as a local-call key (`beam_bifs::serves_local_call`, the same predicate `resolve_local_call` consults) is declined by `local_fun_target` and dispatched by `apply_non_local_fun` through `call_bif`, so the wrapper's record-held fun reaches the registered BIF rather than its `erlang:nif_error(undef)` stub — that is what makes OTP's `zlib` stream API (`erts/preloaded/src/zlib.erl:414-425` stores `fun deflate_nif/4` in `#zlib_opts{}`, applied from `dequeue_next_chunk/2`) work end to end. The declining path stays allocation-free: a `num_free` test, two `O(1)` reads of the defining module's **own** atom table and the predicate's module-name equality, no registry/hash lookup. An applied-arity mismatch is the bare `BadArity`, never a dispatch with a wrong frame.
The engine consults the seam **first**: on `Some` it places the closure's free variables in `x(arity..)` (C's order — flagged as a possible `gen_server` init mis-entry, see *Notes for Agents*) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch`.
Entering an external fun in the calling process (as C's `call_fun` does) is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`).
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context`, and `reset` — not `resume_outcome` — clears contexts; a fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier`.
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap: both allocation seams meet a **capacity** refusal of the bump with the no-relocation `Process::grow_nursery` and a retried bump (and only then fall back), while the unrooted `alloc_words` is handed no root set and **never collects**.
`alloc_words_rooted` additionally collects over the machine's handed-in root set when the retried bump still fails or a forced request bypassed it.
The engine's doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect and grow the nursery to fit an oversized request (`Process::ensure_capacity`, when `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to `Process::collect()`) — see *Known Issues* for the arena fallback and its soundness valve.
**Registry precedence (gotcha).** The native floor runs *before* the registry (a `beam_bifs` entry can never shadow a floor-served key) and the registry *before* the external-module load; a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`.
### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity)` is the **only** producer of a registered call's dispatch answer: a direct-mapped per-context memo of `DISPATCH_MEMO_SLOTS = 128` slots (`dispatch.rs:53`, the count grew from 8 because `compile:file/2`'s 241-key hot set evicted itself at 8) holding a boxed `{bif: Option<BifFn>, hooks: DispatchHooks}` per slot — the slots are inline (`slots: [Option<Box<DispatchEntry>>; 128]`), so a fresh per-applied-fun context carries ~1 KiB of `None` slots and allocates a box only on a miss, where `hooks` is **one boolean per `uses_*` predicate** (the eight mutually-exclusive bridge-arm selectors plus the `fun_identity`/`memory_hook`/`export_gate` build gates) and `bif` is the `BifRegistry` lookup the caller then invokes **directly** (no second lookup); `call_registered` is reached only on `Some`.
A cached answer can never go stale: the one mutable input, the **NIF registry**, is deliberately not memoized (`call_bif` runs `try_call_nif` first on every call).
Slot hash, the miss/collision rules, hit/miss cost, pooled BIF heap and `PendingInterner`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-dispatch-memo--dispatchhooks).
### In-machine execution-position door (`position.rs`)
`position.rs` serves a process's execution-position items (`process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel`) out of the `Machine` that owns its frame, through `beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine` seam; the same published window carries the machine's off-heap roster (`(addr, size, refc)` triples) so `process_info(self(), binary)` lists the payload the running slice just built, read only when the query names `binary`.
Everything else — another pid, a nested query, a pid-less argument, an unsourced name — falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated.
Mechanics and the root-set window: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-in-machine-execution-position-door--positionrs).

### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One helper serves **all three** entry points — `alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying by **provenance first** through `Runtime::local_reference(to)`: a monitor/alias reference `Some(Some(_))` is looked up via `table.resolve_alias`, a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias, and unknown provenance `None` (a decoded or received copy) falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`.
* the BIF route (`erlang:send/2`, `'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery;
* the compiled `Dest ! Msg` route — `resolve_send_destination` (inherent, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteAlias`/`RemoteName`) and `deliver_remote` transmits it over the connection the runtime is a node on, and a **port** destination (`SendDestination::Port`) whose write is `deliver_to_port`; `resolve_send_target` is a `#[cfg(test)]`-only local wrapper.
Both producers are handles onto **one** monotone process-wide id space (`beam_common::next_ref_id`; `Runtime::refs` for `make_ref`/timers/`seq_trace`, the `ProcessTable`'s allocator for monitors/aliases), so no id is ever issued twice and provenance adds the **kind** of reference, not its uniqueness; the typed-`badarg`-vs-silent-drop divergence and the provenance bridge are in the module docs and the crate `Known Issues`.
C arm reproduced: `send_altact_message` (`bif.c`) + `handle_altact_msg` (`erl_proc_sig_queue.c`).
### The remote alias send arm (`send.rs` · contract A.5)
An **external reference** whose node slot names a node other than `Runtime::local_node()` classifies as `SendDestination::RemoteAlias { to }` (`remote_alias_destination`), and `deliver_remote` transmits it as `Runtime::dist_send_alias` → `{DOP_ALIAS_SEND, From, To} -- Msg` (`dist.c:2563`).
It is a **distinct wire form**, not a `DOP_SEND`: the peer must look the reference up in its own alias table instead of delivering to a process, which is why the control message's `To` is the reference term itself.
It is what makes a **remote `gen` call** answerable: `gen:reply/2` (`../lib/stdlib/src/gen.erl:549-556`) replies to the alias reference the caller put in `From` (`{CallerPid, [alias | MonitorRef]}`), so without this arm such a call could never receive its reply.
The arm sits **after** the live-local-alias test and the external-pid test, so a live alias on this node still classifies as `Local { reference: Some(..) }` and an external pid still classifies as `RemotePid`.
A reference naming **this** node that is not a live alias keeps its `Err(BeamError::BadArg)`, and on a runtime with no node (`dist_client()` is `None`) every reference keeps that same `badarg`, so a non-distributed runtime's observable behaviour is unchanged.
The peer's `DFLAG_ALIAS` is required (a link without it is the typed `did not negotiate DFLAG_ALIAS` error), while a reference naming no live alias **on the peer** is the peer's own silent drop — the oracle's measured behaviour (OTP 29.1.1 returns the message and delivers nothing), not ours.
### `call_registered` — the gated dispatch arms, the lent/held `TableRegistry`
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook — and then selects exactly **one** bridge, first-match, from the `DispatchHooks` the caller's `dispatch` memo computed, because each bridge owns a different runtime borrow and they cannot co-exist.
The `TableRegistry` comes from the live `&mut` a `BifContext::call_fun` **lent** the bridge (installed for every nested call, exclusive by construction) or, failing that, from the shared cell **held** exactly when `install_tables = !reentrancy_capable(args) || tables_capable(module, function, arity)`; `try_borrow_mut` (never `borrow_mut`) is the rule, so an unexpected outer borrow degrades to "no ETS", never a panic.
The result's copy-out and rewind are [`pool/CONTEXT.md`](pool/CONTEXT.md)'s; the per-arm detail, the `lent` exclusivity argument and the arm roster: [`calls/CONTEXT.md`](calls/CONTEXT.md).
### The nine bridges
Exactly **one** bridge is selected, first-match, from `DispatchHooks`: `DictBridge` (`DictHook`), `ProcessBridge` (`ProcessHook`), `NifBridge` (`NifLoader`), `RecordBridge` (`RecordSource`), `SendBridge` (`SendHook`), `ModuleInfoBridge` (`ModuleInfo`; `erlang:get_module_info/1,2` from the loaded module's IR), `PersistentTermBridge` (`PersistentTerm`), `RuntimeHooksBridge` (`RuntimeHooks`; 40 of the 143-key `RUNTIME_HOOKS_BIFS` roster served, the other 103 answering the typed `unsupported: <module>:<function>/<arity>`) and `FunBridge` (`FunCaller`; the fallback), with the `[safe]` export gate as the eleventh `DispatchHooks` entry.
Per-arm API surface: [`calls/CONTEXT.md`](calls/CONTEXT.md).
The record table has **two** consumers over the one lookup `records::loaded_record`: `RecordBridge`'s `RecordSource`, consulted by exactly one key (`beam_bifs::RECORD_SOURCE_BIFS` = `records:get_definition/2`) through `BifContext::record_definition`, and `ExecutionContext::foreign_record_definition` (`records.rs`), the native-record *instruction* path — a `put_record` create whose `Id` names another module's `{Module,Name}` record: the owner is loaded and the lookup retried when the code server does not hold it, and the definition's `is_exported` flag is returned **unfiltered** (the engine applies the C's gate and raises `error:{badrecord, Id}`).
The `Recs` data has no table of its own: it lives in each cached `Arc<Module>` (`CodeServer::modules`, `module_handle`) and comes back through `Module::records()`/`record()`/`record_by_name()`.
### The `[safe]` export gate — `export_gate.rs` (the 16th `BifContext` seam)
`ExportGateBridge` implements `beam_codec::ExportGate`; its `is_export_active(m,f,a)` is the shared `runtime_hooks.rs::is_active_export` helper **OR** `registry.contains(m,f,a)` — the registry disjunct exists because this runtime's code server holds only the 22 preloaded modules.
It runs on its own mutually-exclusive arm for exactly `erlang:binary_to_term/2` (`beam_bifs::EXPORT_GATE_BIFS`); the flag-free form never consults it.
Evidence: [`../../tests/safe_binary_to_term.rs`](../../tests/safe_binary_to_term.rs); detail [`calls/CONTEXT.md`](calls/CONTEXT.md).
### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's node-global cumulative counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran and `reclaimed` (in words) is advanced by each collection site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`: the quantities match the oracle's, the magnitudes do not.
Detail: [`gc/CONTEXT.md`](gc/CONTEXT.md).

### The off-heap refc-binary reclamation — `gc/bin_vheap.rs`
A process's off-heap refc binaries live in the machine's reservoir (`Machine::refc_binaries`), outside every heap the collector owns, so a collection can never sweep them: they are **pruned separately** at the slice boundary by `OffHeapReclaimer::reclaim` (`reclaim(runtime, table, pid, machine, slot)`), the C's `p->bin_vheap_sz` through `beam_gc::BinVheap`.
`triggered()` is the C's `off_heap.overhead > bin_vheap_sz` (strictly greater); `record_collection` reproduces the C's `p->bin_vheap_sz = next_vheap_size(...)` / `MSO(p).overhead = bin_vheap` pair from the payload that survived.
The release is `Machine::retain_refc_binaries` with `live(p) || shared(p)`, where `live` is `beam_gc::for_each_reachable_binary_payload` over the process's roots and `shared` is every payload at `RefcBinary::refcount() > 1`; it **moves nothing**, so no live on-heap `BinRef` is invalidated.
**Every gate is a decline** — a leak, never a dangle: the pid is not in the caller's table; `Process::is_relocation_exempt()`; `!Runtime::gc_process_enabled(pid)`; the bin vheap has not triggered; the collection valve `valve_verdict` declines; the prune-only valve `gc_walk.rs::reaches_an_unscanned_word` declines; or the reachability walk returns a typed error.
Two further entry points sweep the `-eval` route's escaped store (`Runtime::eval_off_heap`, a different store with different triggers): the tree-walker's depth-0 statement boundaries (`../eval/reclaim.rs`) and the nested-run epilogue (`RuntimeContext::adopt_nested_payloads`).
Gates, per-slice cost, measured envelope and the residuals: [`gc/CONTEXT.md`](gc/CONTEXT.md), [`../runner/CONTEXT.md`](../runner/CONTEXT.md) *The off-heap refc-binary reclamation at the slice boundary* and [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md).
### The NIF-resource-term prune (A.3) — `gc/resources.rs`
`reclaim(runtime, table, pid)` is the caller half of `beam_abi`'s resource-release seam: it drops the reference every resource **term** took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs exactly once.
The scheduled site is the runner's `Yield` park arm; the routes that never park are served by the two non-park sites in `../eval/reclaim/resource.rs`; the reachability walk matches a word **or** a reference identity, because a `copy_struct` copy is a different word with the same id.
Detail, gates and the residual list: [`gc/CONTEXT.md`](gc/CONTEXT.md); the pinning suite is [`../../tests/nif_resource_gc.rs`](../../tests/nif_resource_gc.rs).
### The node hash (A.2) — `node_hash.rs`
`NodeIdentity`'s `LocalNode::local_node_hash` answers the **one** per-OS-process `OnceLock<u32>` mixing a nanosecond clock reading, `hostname()` and the pid, hashed by a self-contained port of the C's Bob-Jenkins `block_hash`, so `term_to_binary(Term, [local])` stamps a real `LOCAL_EXT` (`121`) image instead of the typed gap.
Mechanics: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-node-hash-a2--node_hashrs).

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with one `#![allow(unsafe_code)]` per marked module and a `// SAFETY:` rationale at each site — this node's `gc.rs`, `gc_walk.rs`, `gc/bin_vheap.rs`, `gc/valve_bounds.rs` (the word classifier and the reachability descent), `calls.rs` (the copy-out walk) and `eval/reclaim.rs` + `eval/reclaim/resource.rs` (the off-heap prune), plus `../nif.rs` and `../malloc.rs`; the glue otherwise uses only the safe peripheries of the lower crates.
* **Return-based errors, no silent swallowing** ([`../../../CONTEXT.md`](../../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Never fabricate a value**: a seam answer is either real state or the typed gap — `NodeIdentity` reports the runtime's **live** creation (`Runtime::node_creation()`), and the node hash is a genuine per-process computation, never a constant.
* **A reclamation is an optimization, never a correctness lever**: every gate of the off-heap prune declines rather than guessing, so its residual is a leak — never a payload freed while a live `BinRef` still names it.
* **A lent `&mut TableRegistry` is exclusive by construction**; the shared cell is never consulted while one is lent, and `try_borrow_mut` (never `borrow_mut`) is the only way this node touches it.
* **Dispatch cost is first-class**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (an input that can change during a run — the NIF registry — must stay out).
  Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) (figures in [`../../PERF.md`](../../PERF.md)); `../../examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch.
## Known Issues
Every entry here is a typed capability gap, a measured own-state difference or a documented divergence — never a wrong result.
The GC/heap-model ledger is [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md), the call-path gaps are [`calls/CONTEXT.md`](calls/CONTEXT.md)'s, the copy-out and `ets`-alias gaps are [`pool/CONTEXT.md`](pool/CONTEXT.md)'s and the heap-door/off-heap-prune gaps are [`gc/CONTEXT.md`](gc/CONTEXT.md)'s.

* **The "no collection can run while a BIF call is in flight" invariant is a conjunction of facts, not an enforced guard** — the BIF route (`call_bif` → `try_call_nif` → `try_native` → dispatch memo → `call_registered`) reaches no `context/gc.rs` door (`BifContext` exposes only the pooled pointer-stable `Heap`), and `gc_armed` is `take`n at each door's first statement (`execution.rs:472,486,510`), armed only by `BudgetContext` immediately before a forward.
  Both halves are structural: the latch is **unreadable** inside the dispatch (`call_registered`'s destructure discards it) and the machine is handed as `&self`, so no arm can consult it and the engine cannot mutate the register file mid-call.
  Two term holders ride that window with **no root set covering them**: the marshalled argument copy (a `[Eterm; 2]` stack array / `Machine::args_scratch`) and `InMachinePosition`'s five `Eterm`s published in `Runtime::in_machine` (`position.rs`), which `alloc_words` places on the process's **scanned young heap**; the roster `off_heap_binaries` beside them is plain `(usize, usize, usize)` data, so it holds no term and needs no root set.
  `Machine::pending_exception` is a third holder, and unlike the two above it **is** parked: `Machine::with_roots` parks the machine's loose heap terms (the two failed-clause argument latches, this reason and the two supplied-trace term latches, `const LOOSE_HEAP_TERMS = 5`) at the tail of the Erlang stack for the closure's duration and re-seats them from the slots the host wrote back (`beam_engine/src/machine/mod.rs`), a funnel every in-slice collection door passes through, and across a park window it rides `Registers::extra_roots` (`runner/run.rs:656-662`); the copy-out is **not** a collection site (`calls.rs:964-1006`: `grow_nursery` + one retry), and the one in-call collection that exists — a delivery's `Process::deliver` on the receiver — is refused for the running process by the sender/receiver relocation exemption (`send.rs:352-502`).
* **A park window is re-published by up to three sequential steps, and `serve_gc_request` relocates the process registers in between two of them.** The runner's `Yield` arm runs `park_machine` (publish, `runner/run.rs:744`) → `Runtime::serve_gc_request` (`:1305`) → `collect_at_reds_boundary` (`:1313`, which re-publishes `machine.with_roots(ALL_LIVE)` at `gc/reds_door.rs:288`) → `reclaim_off_heap_binaries` (`:1321`).
  `serve_gc_request` gates on `is_relocation_exempt` only — **not** on `has_unpublished_roots` (`runtime/gc.rs:507-578`) — so for a non-exempt (publishing) window it really can collect and relocate `process.registers()` in place while the parked `Machine`'s own `x`/`stack`/`fr` keep their pre-relocation words.
  `serve_gc_request`'s `bool` answer is discarded at all three call sites (`run.rs:1305`, `:1464`, `:1541`), so nothing re-syncs the machine before the next step re-publishes it.
  The doors' length contract itself is robust (`publish_roots_full` can only answer `false` from `x_mut().set_live`, since `Vec::push` cannot drop a word, so its `stack().len() == roots.stack.len() + fr_count` test is an identity; a collection preserves both slice lengths), so a `false` is not the mechanism a stale word comes from — a **re-publish from a stale machine** is.
  `reaches_an_unscanned_word` (`gc_walk.rs:385-402`) seeds **only** the caller's `roots` iterable and never calls `Walk::seed_process_roots`, so the prune-only valve's coverage is exactly the list `bin_vheap::reclaim` builds (`gc/bin_vheap.rs:395-407`); under `Criterion::PayloadPrune` any pointer-bearing `WordRegion::Foreign` word is an immediate hit (`gc_walk.rs:937-942`), and it always descends (`descend` is not a parameter).
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap** — the call goes `call_bif` → `run_export_blocking` (a pooled `Machine` on the same pid under a `for_process*` context, so `may_pump_scheduler()` is `false`) and `pump_once` returns `Ok(None)` on its first line, folding the parked callee into the uncatchable `beam_engine::blocked()` whether or not its `receive` carries an `after T`.
* **`erlang:fun_info/1,2` reads the `LocalFunIdentity` seam, and its `name` item comes from two wiring sites here.** `bridges.rs::local_fun_identity` attaches the `FunT` entry's `function` to the derived `FunIdentity` for a compiled `make_fun3` fun (`with_function`; introspection-only, so the `term_to_binary` bytes are unchanged); `fun_identity.rs::imported_identity` resolves a decoded `NEW_FUN_EXT` fun's `name` from the loaded module named by its own `module` atom.
  Residual: an imported fun whose **defining module is not loaded** is the typed `unsupported_bif` gap where the oracle reports `{name,[]}` (C `mfa == NULL ⇒ NIL`) — never a fabricated name; pinned by `an_imported_funs_unloaded_defining_module_is_the_typed_gap_not_an_empty_name`.
* **The `NEW_FUN_EXT` identity seam is installed on every encode path; which `Ok(None)` branches are LIVE decides where `unsupported_local_fun` (exit 3, CLI reason `local_fun`) still bites.** `uses_fun_identity` (`dispatch.rs:511`) covers `erlang:term_to_binary/1,2` + `erlang:external_size/1,2` (`beam_bifs::LOCAL_FUN_IDENTITY_BIFS`) and the introspection pair, `call_registered` installs `FunIdentityBridge` on **every** dispatch arm, and `nif.rs`'s `enif_term_to_binary` derives through the same `fun_identity_for`. Live gaps: (a) an `-eval` lambda (`eval/mod.rs`'s `EVAL_FUN_UNIQ` sentinel + `eval_closures` index matches no loaded `FunT` — the recorded `wire/new_fun_ext_encode`); (b) a module loaded through `code:load_binary/3` (`insert_loaded` removes its path ⇒ `fun_module_snapshot` skips it, so `descriptor_position` is never consulted); (c) a module whose `.beam` was deleted after it loaded (`std::fs::read(path)` fails ⇒ the deliberate `Ok(None)`). Not fun-reachable: the `zlib` stash encoder (`beam_bifs/src/zlib/stream/lifecycle.rs:133` — its internal `-nifs` only ever carry `{Kind,Output}` state, the user-facing `getStash`/`setStash` are gone from `zlib.erl`), `crash_dump`/`persistent_term`/`seq_trace` (no encoder at all), and the NIF-created-thread host (`nif/thread_env.rs:255` never installs one; its whole `enif_term_to_binary` hook is unsupported). The outbound `dist` payload rewrite (`dist/externalize.rs:227`) and `beam_dist`'s own control encoder both build their `Encoder` with **no** fun identity, so a `make_fun3` fun addressed to a remote pid/name is a typed refusal where the oracle encodes it.
* **The fun-image half of `callee_observes_its_call_site` is per-function** (see *API Surface*): it admits `compile:*` to the in-machine route on the **scheduled** path; a signal-driven collection there is declined by the runner's **park-window relocation exemption**, with the evidence owed to `beam_process`'s signal sites ([`../../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../../EPP_SCHEDULED_ROUTE_FINDINGS.md)).
* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly; the `erlang:ports/0` typed gap (a `try_borrow` failure) is reachable only on a **nested** path, because `call_registered` hands the arm a **separate `Rc` clone** of the port registry, so production `ports/0` works.
  `register/2` with a **port id** is a typed gap (the table registers pids only), `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg`, and `process_flag(error_handler, Atom)` always answers `error_handler`.
  `process_flag(max_heap_size, Map|Int)` parses through the **same** parser as `spawn_opt`'s option (`native/process.rs::max_heap_setting`) and stores the setting per pid in `Runtime::max_heap`; the `badarg` matrix, the previous-value answer in the C's key order and the **caller-only** scope are oracle-pinned by `tests/max_heap_flag.rs`. The bound **is enforced** on the **prospective post-collection capacity**: the verdict is drained at every collection/admission and at `serve_gc_request` (`gc.rs::drain_max_heap_verdict`, an ERTS `=ERROR REPORT====` on stderr once per killing breach) before latching `Kill`, which `runner/run.rs::take_max_heap_kill` turns into `RunOutcome::Exit(<bare atom killed>)`. Residuals (`tests/max_heap_enforce.rs`): stderr vs the oracle's stdout `logger` stream, 7 of the C's 9 fields, a kill at the next slice boundary, and an `-eval` verdict never drained — `M1_GAPS_GC.md` *Heap switches*.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles**, so a term the *running* machine just built off-heap and forwards from a BIF callee **flattens** (a correct but unshared copy); only the compiled `Dest ! Msg` instruction carries them.
  `send_source` unions the three families a *delivery* can resolve (`extra`, the runtime's escaped-payload store, the sender's mailbox-retained families) but the BIF route passes `extra = &[]` (the in-flight `Machine` is out of `RunnerState.engines` for the whole slice, and neither `ExecutionContext::call_bif` nor `SendHook::send` carries a handle parameter); closing it needs a sibling change in `beam_engine`/`beam_bifs`.
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives** — `beam_process`'s `copy_reason_onto`/`enqueue_down_signal`/`enqueue_exit_signal` pre-test `has_unpublished_roots()` and the host's `CollectionGate`, hand the raw `Alloc` refusal back with **no** collect, grow or retry, and turn the `{'DOWN',…}`/`{'EXIT',…}` into a fresh `HeapFragment`.
  The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*); pinned by [`../../tests/eval_exempt_receiver_signal.rs`](../../tests/eval_exempt_receiver_signal.rs).
* **A fun-applying registry key is entered as the module's own code whenever the context cannot re-enter the scheduler, so the apply suspends the process.** `apply::prefers_module_code_for_fun_apply(can_pump, module, function, arity)` is `!can_pump && beam_bifs::needs_fun_caller(..)`, and `resolve_external_call` consults it around its `host_serves` refusal.
  The class is `beam_bifs::FUN_CALLER_BIFS` (24 keys: 18 `lists`, 4 `maps`, 2 `ets`), every one of which has a real Erlang body in this checkout, so the in-machine route resolves; `beam_bifs::needs_fun_caller` is the single source of truth, so the roster cannot drift.
  Inside a slice the host implementation applies the caller's fun through a **nested** run inheriting `may_pump_scheduler() == false`, whose `pump_once` cannot advance (`pump.rs:578-580`), folding the fun into `Err(beam_engine::blocked())` (`pump.rs:146-153`); the module's own body applies the fun through `call_fun` → `resolve_local_fun`, i.e. in the caller's machine, so a blocking `receive` suspends the **process** (`RunOutcome::Wait` → runner park → resume-on-send).
  The fast path stays for every context that can pump (`-eval`, the boot drive, a nested run outside a slice), where the nested run suspends and resumes correctly.
* **No apply shape folds into the typed `blocked()` gap: the fun application is entered in-machine whatever applied it.**
  Measured on a scheduled process whose wake can only come from a later slice — `pump/fun_apply_matrix.rs`'s `every_apply_shape_answers_the_oracle_when_the_child_needs_a_later_slice`, whose two-hop spawn chain leaves nothing in the mailbox while the fun is applied — `erlang:apply(lists, flatmap, [F, L])`, `erlang:apply(Fun, [F, L])` with `Fun = fun lists:flatmap/2`, `erlang:apply(F, [L])` with `F` the blocking closure, `Apply(F, [L])` and a direct `lists:flatmap(F, L)` all answer the oracle's `{[43],[{recv,1,42}]}`.
  The routing is the compiler's and the loader's: `erlang:apply/3` is a `call_ext` the engine lowers onto its `i_apply` family, whose `apply_target` resolves the callee through `resolve_external_call` **first**; `erlang:apply/2` is lowered by the compiler to `call_fun`, and a direct variable-fun application is `call_fun` too, both of which consult `resolve_local_fun` first (an `` `-eval` `` closure declines there, an external `fun M:F/A` resolves through `external_fun_target` to the same cross-module seam), so the seam decides in every one of those shapes.
  What still gaps is only a fun or callee with **no in-machine entry** — the `` `-eval` `` evaluator's closure (`EVAL_FUN_UNIQ`), a served local stub key, and an external fun whose module or export cannot be loaded (`tests::resolve_local_fun_declines_the_fun_kinds_it_cannot_claim`) — plus any host key that applies a caller-supplied fun without being a `FUN_CALLER_BIFS` row.
  Such a fun's blocking `receive` raises the reason atom `unsupported_opcode: run: process blocked (no message available)` (`../beam_engine/src/error.rs:37-41`, `:75-77`), which a caller observing a child's exit reason (`spawn_monitor` + `receive {'DOWN',…} -> Rep`) surfaces as an ordinary value instead of an `{ok|error, …}` tuple.
  Nothing in this node can deliver the reply a nested run awaits: mid-slice `Runtime::processes`/`scheduler`/`runner_state` live in the pass's locals and the context owns `&mut Runtime` for the whole slice, so a nested pass that runs the run queue is impossible rather than merely unsafe.
  A probe of these shapes must be woken by a **runnable process's message**: the `run` route waits only for the deadline that can wake the process it was asked for (`../runtime/scheduler.rs`'s `is_quiescent`/`timer_wait` over `set_run_wake_pid`), so a child's own `receive after T` stalls the pass for a reason unrelated to the fun application.

## Notes for Agents
- **The measured per-call cost of the in-process `compile:file/2` route (A.9), descending** — callgrind on `lib/stdlib/src/ordsets.erl`, 3.10 G Ir, release profile: the `gc_walk` valve descent **~24–26 %** (the full-graph `Walk::run` alone 15.65 %, reached 499× from the collection doors, because the BIF-result copy-out opens the descent latch on every process so each admission door re-walks), libc `malloc`/`free` **~22.6 %** (~1.9 M `malloc` and ~2.06 M `free` calls), `build_label_map` **~3.3 %** after the machine pool (22 745 `module_fingerprint` calls — the callee set exceeds the pool's 32 affinity slots), and SipHash **~7.1 %** (dominated by `beam_engine::jit::cache::key::HashWriter::write_str`, 3.89 M calls).
  Read the **ratios**, never the absolute times: on a loaded host the same binary measured 1 090–2 036 ms for `ordsets` (load average 16.7–29.6).
  Which door fires is a route fact: the **top-level** `-eval` context is table-less (`RuntimeContext::new` sets `mailbox_table: None`, `gc_armed: false`), so `heap_available`/`alloc_words` answer the never-reclaimed `Runtime::arena` (`gc.rs::heap_available`) and the in-slice doors do not run — but every **nested** run executes under `for_process`, so it allocates from the pid's real young heap and its collection doors (hence the valve descent above) do run.
  A nested run therefore also takes the **in-machine seam, not `run_export`**: a plain `call_ext` between interpreted modules goes `interpreter/dispatch.rs`'s `resolve_external_entry` → `resolve_external_call`, and `run_export` is reached only from a declined call, a top-level entry, or a fun application (`execution.rs` → `run_label_blocking`); `run_export`'s `current_module` `String` allocation is therefore not a per-`call_ext` cost.
- **Layout: `mod.rs` is root-only plumbing over concern-scoped submodules** (module `//!` overview + submodule map, `mod …;` declarations, crate-visible re-exports, `#[cfg(test)]`-gated name plumbing; no logic).
  Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs`, its methods delegating to inherent helpers in the sibling that owns the concern.
  Five siblings exceed the ~1000-line target — `runtime_hooks.rs`, `calls.rs`, `gc.rs`, `pump.rs`, `bridges.rs` — each one cohesive pre-existing concern documented at its own top; `tests.rs` is the node's shared unit suite and `calls/tests.rs` the colocated suite for `calls.rs`, and the names `tests.rs`/`pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]` (`DispatchMemo` alone stays ungated).
- **Every nested cross-module run reuses a recycled `Machine` on the tier-less interpreter entries, and never touches `jit::cache`.** `run_export_blocking` and `run_label_blocking` (`pump.rs`) take their machine from the thread-local pool in `machine_pool.rs` — a **module-affine slot table** (one `Slot` per callee image, `MAX_CALLEE_SLOTS = 96`, each holding a `VecDeque` stack capped at `MAX_CALLEE_DEPTH = 32`, the whole table capped at `MAX_POOLED_MACHINES = 32` with the least-recently-used **callee** giving up its idle machines) — and hand it back at the run's epilogue, so `acquire` is one `FastHashMap` probe plus a `pop_back` and no scan or `Machine` memmove.
  **The pool's ceiling is measured, and it is not the label-map cost.** It answers 99.5 % of acquires from an entry (ordsets: 14 932/15 007 hits, 75 fresh builds, 44 distinct callees, peak depth 13; maps 76 865/76 966, 101 fresh; string 501 576/501 915, 339 fresh), and a 128-machine ceiling was measured **worse** (+2.7 % user CPU on `string.erl`, identical `build_label_map` census) because the extra idle machines pin one-entry label caches that can never be reused. The per-callee slot table buys an O(1) probe and no live-callee eviction; it buys no time.
  The residual is a `beam_engine` property: the label cache holds **one** entry and `Machine::reset` clears the context registry, so every run re-registers its in-machine callees through `label_map_arc` and rebuilds each one's whole-module map. Measured share of the fills that are the pool's own bare route: **8 %** (ordsets: 4 733 misses of 15 109 probes against 59 277 fills); the other **92 %** is that per-callee-per-run `Arc` route (string.erl: 1 925 467 of 1 934 350 builds). Removing it needs a multi-entry `LabelMaps` (or a context registry surviving `reset`) in `beam_engine` — no pool shape reaches it.
  `release` `reset()`s the machine before pushing it and `debug_assert!`s both off-heap reservoirs empty; the drain itself is the epilogue's (`Machine::retain_refc_binaries(|_| false)` in `adopt_nested_payloads`, after `Runtime::adopt_escaped_binaries` has taken every handle), so a recycled machine carries no term and owns no payload.
  Affinity is a **hint, never an identity claim**: `label_cache.rs` keys its entry on the image's digest + atom namespace + address, so a stale hint costs one build exactly as no pool would and can never answer with another module's map.
  A run's own resumes still reuse the same machine (`Machine::resume_outcome`). Entry is `Machine::run_export_outcome`/`run_label_outcome`, which delegate to the tier-free `run_loop`/`run_loop_with_map` → `Machine::drive`; **no `Tier` is passed anywhere on this path**, so a nested callee never runs on the default baseline JIT and `BEAM_RT_TIER` does not change its tier (`run_export_outcome_with_tier`/`resume_outcome_with_tier` are the runner slice's). `beam_engine::jit::cache::remember_module` has **no production caller**; only the runner slice entry (`../runner/run.rs:952` `select_entry_tier` → the `*_with_tier` entries) compiles into / reads the cache. The module handle is the code server's cached `Arc<Module>` (`resolve_local_fun`/`resolve_external_call`'s `module_handle`, and `call_bif`'s `CodeServer::load` at `calls.rs:1642-1658`), never a per-call `Module` clone — `CodeServer::load`'s `module.clone()` (`../../codeserver.rs:718`) is an `Arc` handle clone.
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned` driver, capped by `BLOCKING_PUMP_DEADLINE` (900 s) — the nested counterpart of the boot drive's `DRIVE_DEADLINE`; the wait policy and the rejected forward-progress alternative: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-nested-blocking-pump-and-its-bounds).
- **A nested `receive` that a live port's own asynchronous operation will answer is sat out, not gaped.** `pump_once` hands such a wait to `wait_for_port_event` when `Runtime::ports_awaiting_async` reports a queued operation (a passive `gen_tcp:recv/2,3`, an `accept`, a datagram read), which drives the blocking pass until one of **three** progress signals moves — an executed slice, a delivered port message (`Runtime::port_events_delivered`), or no live port owing an asynchronous answer — and is bounded by `crate::port::PORT_EVENT_DEADLINE` (5 s of consecutive no-progress rounds, re-armed on every round that made some).
  The wait arms, latches and consumes nothing, so a re-park waits on the same queued operation and never issues a second one; the `-eval` bare receive's port branch applies the same three signals and the same window rule.
  Detail and the residual (`beam_io`'s accepted-socket pre-buffered read): [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-nested-blocking-pump-and-its-bounds), [`../port/CONTEXT.md`](../port/CONTEXT.md) *The nested port wait*.
- **Closure application is entered in-machine through the `resolve_local_fun` seam for a context the engine drives directly**; the engine's `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper**, which forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process enters in-machine and is resumed by a real send, and a same-module local `call` the host serves is dispatched through `call_bif` instead of being jumped into the module's non-exported Erlang stub body.
  Pinned by [`../../tests/scheduled_apply_seam.rs`](../../tests/scheduled_apply_seam.rs); the A.9 case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle.
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it, so it needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` passes `Some(self.mailbox_pid)` (the full three-family union); `deliver_message` passes `None` (store-only), because its context is built `for_process` the **receiver** and `None` keeps the empty-source fast path, so a plain on-heap message still builds no table.

## A term that outlives its heap — the unscanned-region rule and the young-space replacement invariant
A fault in `beam_term::list::car` (a cons whose pointer lands in **unmapped** memory) is not a classifier bug: some region holding that cell was `munmap`ed while a term still named it.
Only two kinds of region on this crate's routes actually return pages: a `beam_alloc::Heap` block at/above the single-block-carrier threshold (512 KiB = 65 536 words) is a dedicated mapping that `Drop` unmaps, and a **process nursery** space reaches that size once a compile-sized live set grows it (`crates/beam_alloc/CONTEXT.md`).
Everything else on the route only rewinds or retires, so it can never dangle: `bif_heaps` (`take_bif_frontier` puts back, never frees), `eval_heap` + `eval_heap_retired` (`grow_eval_heap` retires, never frees), `info_heap` (`reset_info_scratch` is a bump rewind behind the `info_heap_tainted` latch, and `erlang:system_info/1` relocates off it first), `gc_scratch`, the `-eval` statement window (`eval_heap.reset_to`, pinned by every `stabilize_term`), the engine arena (its regions never move and are rewound above `src/runtime/reclaim.rs`'s mark once nothing reachable stands there — it can never dangle, and nothing scans it either: that is the rule stated below) and the port completion channel (arena-built).
`hint_grow_gate`/`move_result_into_process_heap` (`calls.rs`) call the **no-relocation** `Process::grow_nursery` and so move no term.
A young-space **replacement is legal only while the process's root set is complete** (`!Process::is_relocation_exempt()`): a replacement **retires** the young space it replaces and keeps every handed-out word addressable at its original address only until the next **collection collapses the chain**, and that collection runs at a non-exempt admission door whose root set cannot name the words a relocation-exempt window holds on the Rust side.
[`gc.rs::may_replace_young_space`](gc.rs) is the one predicate every growth site consults — **all four of them**, so **no replacement can fire inside an exempt window**:
`hint_grow_gate` is reached only under `if republishable` (`calls.rs:1552-1553`) and the post-refusal growth only in the `else` of `if !republishable` (`calls.rs:1586`, the growth at `:1628`), so both copy-out sites are shut while the process is exempt;
the two allocation seams guard their own `grow_nursery` (`gc.rs:1561`, `gc.rs:1723`) and fall through to the pointer-stable arena;
and `Process::ensure_capacity` **collects before it grows** (`../../../beam_process/src/process.rs:1707-1712`), so it — like `Process::collect`/`collect_kind` — refuses an exempt process outright (`process.rs:1625`, `:1672`, `:1708`), while `collect_if_needed`/`deliver`/`ptab::grow_receiver_for_signal` pre-test `has_unpublished_roots`.
**`Process::grow_nursery` is consequently the ONE young-space replacement seam with no exempt guard** (`process.rs:1747`: it moves no term, so an exempt host may call it), and the whole no-relocation discipline rests on that decomposition — a growth only *retires*, only a **collection** collapses the chain, and every collapse door refuses an exempt process.
A copy that does not fit inside a window is **stabilized**, not refused: `move_result_into_process_heap` copies it onto the runtime's pointer-stable, never-reset store (`calls.rs::move_result_into_runtime_store`, the destination the table-less route already uses) and returns that copy, so the call licenses its pool rewind exactly as on the non-exempt route — **refuse ⇒ stabilize, never dangle**.
`None` therefore means only a **permanent** refusal (the copier's malformed-graph `badarg`, an unresolvable off-heap container, a store that could not be grown); the result then stays on the never-rewound pooled BIF heap — **leak, never dangle** (`calls/CONTEXT.md`).
**The `exempt=` field of the `[rt-heap]` copy-out growth line (`calls.rs:2137`) is the discriminator for any claim that a copy-out growth happens inside a window**: a line reading `exempt=true` means the guard's `process` is not the pid the window marked, and no such line means no copy-out growth ran in a window.
**Why a dangling target reads as garbage instead of faulting**: the free is `Nursery::collapse`'s — a collapsed space's `HeapSpace` is dropped (`../../../beam_gc/src/nursery.rs:575-583`), its carrier segment goes to the allocator's **reuse cache**, and a re-served segment keeps the previous owner's bytes (`../../../beam_alloc/src/carrier.rs:53-55`), so a stale word pointing into a *later-mapped* young space lands in that space's unwritten tail and reads leftover data (invisible in RSS; `MALLOC_PERTURB_` cannot change it — it is not glibc memory).
Per the beam_gc audit, the retired space itself is safe: `add_to_from_set` covers every space and `Nursery::collapse` runs only after a collection whose from-set contained them — such a defect is therefore always an **incomplete root set at a collection door**, never the free.
**The rule every allocation seam on this crate's routes obeys: a container built while the process's young heap is live must be built on that heap.**
`beam_gc`'s copier relocates exactly the words in its *from* set and classifies every other address as `Target::Foreign`, leaving the reference verbatim **without descending** (`../../../beam_gc/src/copy.rs:240`, `:280` — the boxed and list arms of `forward_slot`, over `classify_boxed`/`classify_cons`), so a container in a region no collector scans is invisible to it: the young-heap children it names are relocated by the next collection while the container keeps the stale words.
The **pointer-stable arena** (`Runtime::alloc_words`, `../runtime.rs:2377`) is such a region, so it is a **refusal-only** fallback and the home of a genuinely **table-less** context: the unrooted seam `gc.rs::alloc_words` — handed no root set, so it may neither collect nor hand a collection roots — reaches the arena only after a young-heap capacity refusal, a `Process::grow_nursery` and a retried bump, and `gc.rs::alloc_words_rooted` reaches it only with no process table, no call site (`current_module`), a process whose collection is disabled or halted, or a young heap that cannot meet the request even after the same grow-and-retry.
Its **`armed == false` arm is not one of those**: a nested run re-entered from a scheduled slice keeps the pass's `ProcessTable` (`bridges.rs:186`) and drops only the latch (`:195`), so its engine builds belong on the running process's **scanned** young heap, and that arm delegates to `alloc_words` (`gc.rs:1668`) rather than jumping at `Runtime::alloc_words`.
Any seam that hands out a block therefore has to answer **"which heap, and does some collector scan it?"** — a word handed out of an unscanned region is a root no collection can update, and the unscanned-root valve (`root_is_unscanned`) is that same fact read as an admission test.
What a live process still draws from the arena is measured rather than assumed: `Runtime::retention_stats()`'s `arena_words`/`arena_allocs`, plus the env-gated attribution census `BEAM_RT_ARENA_TRACE` (`../runtime/arena_census.rs`: a size histogram, the largest requests with backtraces, and an inside/outside nested-run word split).
**Four candidate mechanics are excluded by measurement**, so none needs re-running: the copy-out sites' own destination handling (grow, re-grow, stabilize — every arm lands the graph either on a scanned heap or on the never-freed store), the pooled BIF heap's rewind/reuse (`put_bif_heap` is a bare push and the copy-out re-homes before any rewind), `note_escaped_store_roots` (it latches `foreign_reachable` and moves no term), and exempt-window **growth** at either allocation seam (lifting both `may_replace_young_space` guards drives the exempt arena fallback to **zero** and changes no outcome — growth is the no-relocation seam, so it cannot be what un-roots a container).
`RuntimeContext::new`'s `mailbox_table: None` is therefore not this class's home either: `beam_rt run` drives a **scheduled slice** (`for_process_with_engines`, `mailbox_table: Some`), and the in-slice **nested** run an in-process `compile:file/2` performs carries the pass's table too (`bridges.rs:186`) — an arena block there comes from a seam ignoring a table it holds, not from a context without one.
A word of this class can only be held by a region no collector scans, so an audit of a **new** one belongs at the seams that keep raw words outside the published root set: the runner's park publication (`../runner/CONTEXT.md`) and `beam_io`'s flat `DriverContext::input()` sink (`../../../beam_io/CONTEXT.md`) — links only; none is demonstrated to hold an un-relocated word.
## Where a BIF result's words actually live (the three regions, and who may recycle them)
A registered BIF builds on the pooled region (`call_registered`'s `take_bif_frontier`, `calls.rs:253`), and the tail either copies the container out (`rehome_container_result`) and rewinds to `mark` (`calls.rs:1052`) or leaves it on the region with `rewind == false` — never both.
`put_bif_heap` (`runtime.rs:2353`) is a bare `push`: **no reset, no free, no move**, so the *only* invalidation of a pool word in the whole crate is that one `Heap::reset_to(mark)`, and it is gated only on `safe_to_rewind` (`calls.rs:421-427`, a hand-maintained seven-conjunct roster of escaping `DispatchHooks` arms) ∧ a successful copy.
A store that keeps a pool word **without** being one of those arms is therefore a use-after-rewind, and `move_container == false` (`calls.rs:938`) disables the copy too — so on the table-less route an `!safe_to_rewind` call keeps its words only because nothing rewinds.
**The roster is `DispatchHooks`-shaped, so it cannot see a store that is not a hook.** The one known instance is `beam_bifs`' `TableRegistry.specs` (`beam_bifs/src/ets.rs:364`), where `ets:match_spec_compile/1` stores its `raw = args[0]` **verbatim** (`beam_bifs/src/ets/specs.rs:120,135`) — no copy, no witness, no stabilisation — and `ets:match_spec_run/2,3` walks it back through `beam_ets::compile` (`beam_ets/src/select/mod.rs:222-228`, `car`/`cdr`). The BIF is not `reentrant`, sets none of the six escaping hooks, so `safe_to_rewind` is **true** and `calls.rs:1052` rewinds the pool under a spec that was built there; on the **process** route the same word is a caller-heap cons that the collector relocates, and `specs.rs:87-90`'s soundness claim ("a process heap is a never-relocating bump arena") does not hold for a scheduled process. `TableRegistry.specs` is also absent from `Runtime::gather_off_heap_roots` (`runtime.rs:2996-3047`), so `eval/scratch.rs`'s window descent cannot see it either. Any new runtime-global side table that keeps a caller word must be either a `safe_to_rewind` conjunct or a `gather_off_heap_roots` family.The **native floor is not on the pooled region**: `try_native` runs on the `RuntimeContext` and builds through `ExecutionContext::alloc_words` → `gc.rs:1536-1578`, i.e. the process's scanned young heap in a slice and the never-reclaimed arena otherwise. (The inline comments at `calls.rs:1738` and `calls.rs:1816-1817` claim the opposite and are stale — the two regions have opposite lifetime properties, so reasoning from them gives a wrong model.)
The third reset-per-call region is `Runtime::info_heap` (`runtime.rs:2245`, `reset_info_scratch`, 4 096 words), reset at the start of every `system_info`/`format_term` call and latched never-reset-again by `taint_info_scratch` (`runtime.rs:2257`) when `relocate_off_scratch` declines to re-home a retained value.
## Host-memory retention on the table-less route — where the words actually accumulate
An in-process `compile:file/2` runs on `RuntimeContext::new` (`mailbox_table: None`, `gc_armed:
false`, `runtime_context.rs:204,208`), so **no collector reclaims anything** on this route.
Nothing here is per-`RuntimeContext`: a context is a borrow-only struct over `&'a mut Runtime`
(`runtime_context.rs:198-287`), so it owns no heap at all and dropping it frees only its inline
`dispatch_memo` slots and the boxes a miss put in them.
Of the four runtime-level stores, the pooled BIF heap is **sized by need** (depth-sized and reused) and the escaped off-heap store is genuinely bounded, while two grow with the workload until `src/runtime/reclaim.rs` bounds them: the `-eval` store (each region clamped at `MAX_EVAL_HEAP_WORDS` = 256 MiB, the **chain** not clamped) and the `beam_engine` arena (region-rewound above the pass's mark).
A *reserved* region's capacity is never what moves RSS: only written pages are resident — and a **retired** store region is fully written, so its words are resident (both facts measured, next section).
Per-mechanism detail is [`pool/CONTEXT.md`](pool/CONTEXT.md)'s; this is the cross-store attribution.

### The bound: the store's copy-out volume plus the arena's written words (measured)
The `inet_parse` `-eval` peak (`VmHWM` **7.81 GB**, ~17 s, tree OTP-30 bootstrap compiler first on `-pa`) splits, per-mapping from `/proc/<pid>/smaps` plus an `LD_PRELOAD` `mallinfo2` sampler, as:

| share | mechanism | figure |
|---|---|---|
| 59 % | the `-eval` store's **retired** chain (`eval_heap_retired`) | 4.63 GB: 19 mappings (18 × 256 MiB + 1 × 128 MiB) each at `Rss ≥ 90 %` of `Size` — **fully written and resident** — matching `eval_heap_retired_regions=19` / `eval_heap_retired_words=620 756 992` |
| 37 % | **arena written pages** | 2.85 GB touched of **16.18 GB** reserved (the doubling chain 8192/4096/2048/1024/512/256/128/64/32/16 MB at `Rss ≪ Size`) |
| 2.4 % | glibc std-heap in use | 0.185 GB, flat from ~1.4 s to the end (`malloc_trim(0)` releases 1 byte) |
| 1 % | pooled BIF heap (1.2 MB written of 169 MB), JIT code, file-backed mappings, stacks | ≈0.12 GB |

Both mechanisms are **resident**, not merely reserved: `grow_eval_heap` retires a region only once `available() < needed`, so a retired region is ~fully written, and the arena's written pages are the term-build reservations `put_map_assoc → make_map_rooted → slack::reserve` actually filled.
`arena_words` (**1 328 040 494** words = 10.6 GB of **cumulative** demand over 7 047 134 calls) is an upper bound on the arena's resident bytes, not a figure in them: the demand is 69.67 % in 101 367 requests of 4 097–16 384 words (mean 11 442), whose `map_words_capacity(n) = 21n + 18` reservation is a deliberate upper bound while the written map is `3n + 2·nodes` ≈ 3.7 words/pair, and `write_map` never touches `[written_end, capacity)`.

**The bound rule — what each mechanism retains, and why.**
- **The store retains the copy-out volume since the last reclaimable statement boundary.** Every container result of a call that may rewind is deep-copied onto it, so one call's licence to rewind one pooled region becomes `n` store words; each region is capped at `MAX_EVAL_HEAP_WORDS` (256 MiB) but the *chain* has no cap, because a retired region is **full and never rewritable** — growth always replaces, never relocates or reuses. `src/runtime/reclaim.rs` drops such a region **whole** once a reachability descent proves no live term stands in it (Phase 1a: no word ever moves).
  The window that would reclaim a dead prefix is pinned by the first nested run that writes the store (`Runtime::pin_window_if_store_written` → `eval::scratch::pin`), so a compile — one `-eval` statement made of store-writing nested runs — only ever advances it.
- **The arena retains every word it ever handed out.** `ContextHeap` is a `Vec<ReservedHeap>` that only grows: an exhausted region is kept, unmoved, and a fresh doubled one becomes the frontier, so a table-less compile's whole term-build graph accumulates there until `src/runtime/reclaim.rs` rewinds the region above its recorded mark (a word still reachable from the pass's roots refuses the rewind).
  `MinimalContext::heap_stats()` reports the census (`regions`/`reserved_words`/`committed_words`/`used_words`/`peak_words` + the frontier pair) and `heap_mark()`/`heap_mark_matches()` detect a replaced frontier, but `used_words` is cumulative demand, never live memory.
- **Therefore peak RSS ≈ copy-out volume + arena written words + O(1)** — for `inet_parse` 4.63 + 2.85 + 0.23 GB.
  Both terms grow with the workload itself, and neither is a policy a flag can move.
- **The third mechanism IS bounded: the exempt-window nursery chain.** `Process::grow_nursery` is unreachable on the **table-less** route — `move_result_into_process_heap` returns at `let table = mailbox_table.as_deref_mut()?;` before `hint_grow_gate` — and on a **scheduled** route a big compile's child reaches it only inside a nested `apply_fun`/`run_*_blocking` subtree where the pid is **relocation-exempt**, so every collapsing collection door declines and a growth request that cannot be honoured lengthens the chain instead of collecting.
  `resolve_external_call` therefore declines the fun-applying stdlib fast paths (`beam_bifs::needs_fun_caller`'s `lists`/`maps` roster) while the calling process carries collection debt, entering the call in the caller's own **armed** machine so the debt door collapses the chain as it grows; the two `ets` folds stay synchronous (their bodies reach a gated `lists` key internally) and the gate is inert on a context with no process table.
  What it does **not** cover: a nested run entered while the caller owes no debt, and a fun-applying key outside the roster.

### Host memory: the touched pages, measured (RSS attribution)
Measured on the release binary with the OTP-30 bootstrap compiler first on `-pa`, via
`-eval 'compile:file("…/lib/compiler/src/cerl_clauses.erl",[no_spawn_compiler_process,deterministic,no_docs,{outdir,…}])'`:
peak VmRSS **372–380 MB**, wall ~1.0 s, sampled from `/proc/<pid>/smaps` and cross-checked with
`strace -f -k` and an `LD_PRELOAD` `malloc_stats`/`mallinfo2` shim.
That peak's attribution:
- **`Heap::new` does NOT touch its region, so region *sizing* alone can never move RSS.**
  `Heap::with_allocator` is `alloc.alloc_bytes(bytes)` (`beam_alloc/src/heap.rs:64-66`) and the `mseg`
  carrier writes only a 16-byte `BlockHdr` (`BLOCK_HEADER_SIZE = UNIT_SIZE`) plus a 64-byte
  `MsegHeader` (`beam_alloc/src/mseg/header.rs:39`), so the two 128 MiB bootstrap reservations —
  `bif_heaps: vec![Heap::new(heap_words)?]` (`runtime.rs:1447`) and `eval_heap: Heap::new(heap_words)?`
  (`:1460`) — sit at **12–48 kB RSS** all through boot.
  Only the caller's own writes into a region make pages resident.
- **The large fully-resident anonymous mappings are glibc thread-arena heaps, not beam regions.**
  `strace -f -k` attributes them to `alloc_new_heap` ← `arena_get2` ← `__libc_malloc` (an
  `mmap(2 × 64 MiB, PROT_NONE)` followed by a 64-MiB-aligned `mprotect`), and their first words decode
  as glibc's `heap_info { ar_ptr, prev, size = 0x4000000, mprotect_size }`, the `prev` chain linking the
  heaps.
  At boot they are 64 MiB + 31 MiB resident = **95 MB** of the 115 MB boot floor; during the
  cerl_clauses compile three of them reach 64 348 + 63 772 + 56 792 kB ≈ **185 MB**.
- **Those std-heap pages are a capacity high-water, not live data.**
  An `LD_PRELOAD` `malloc_stats()` at exit reports `Arena 1: system bytes = 192 802 816` (183.9 MB)
  against `in use bytes = 219 216` (214 kB), and `malloc_trim(0)` releases **1 byte** — the driver
  thread's single arena keeps its freed pages mapped.
  `GLIBC_TUNABLES=glibc.malloc.arena_max=1` does not change the total (peak 380 924 kB) and only re-lays
  the mappings out, so the total is the runtime's std-allocation high-water, not an arena-count artefact.
- **`eval_heap` is the one runtime heap that really fills on this route.**
  Its 128 MiB region goes 46 708 → 104 440 → 131 080 kB resident (fully touched) during the compile,
  then `grow_eval_heap` retires it (`eval_heap_retired_regions = 1`, `eval_heap_words = 33 554 432` =
  256 MiB across two regions) and the retired 128 MB stays mapped and resident — **~128 MB of the
  ~380 MB peak** is `beam_rt`'s own, held until `src/runtime/reclaim.rs`'s pass proves the region dead or the `Runtime` drops.
- **`+hmax` sizes only the two boot-time regions.** It shrinks the pool's outermost region and `eval_heap`'s
  seed, and leaves the boot-only RSS unchanged (94 276 → 94 424 kB), because at boot both `Heap`s are
  untouched.
  It does **not** bound growth: `eval_heap_ceiling()` deliberately ignores the policy and `take_bif_frontier`
  applies `max_heap_words` only as a cap on one geometric step, so the flag's RSS effect exists only where a
  region actually fills.- **The `[rt-mem] exit` census alone is misleading.** For cerl_clauses it reads
  `arena_words = 5 133 195` (~39 MB) and `bif_words = 20 185 088` (161 MB of *reservation*, with
  `bif_peak_used_words = 12 953`), and neither resident mechanism above is attributable from it: the
  glibc heap is outside `beam_alloc` entirely, and the eval store is reported as **capacity**
  (`eval_heap_words` + `eval_heap_retired_regions`), not as touched pages.

### Reclaim: what is sound without a collection, and what is not
Ranked by the measured peak; items 1–3 have **landed**, 4–5 are what is left, and every remaining item is a sibling-crate API rather than a `beam_rt` policy.
1. **LANDED — the per-level region is sized by need, not by `heap_words`.** `bif_heaps`' outermost region is `bif_heap_words`, a nested one `NESTED_BIF_HEAP_SEED_WORDS` (1 MiB, self-tuned to `2 ×` an observed peak), and `take_bif_frontier` grows geometrically from the region's own capacity: `cerl_clauses` 3.62 GB → 161 MB at an identical 27 regions.
2. **LANDED — the eval store's growth is clamped** at `MAX_EVAL_HEAP_WORDS` (256 MiB); a refusal is the typed `system_limit` that leaves the store untouched, and it is deliberately **not** tied to `+hmax` (the flag must not turn a large compile into an error).
3. **BOUNDED BY THE REGION-RECLAIM PASS — `eval_heap`'s retired chain** (the figures and the mechanism are the section above's).
   Only the "did the store get pinned" test would let it shrink, and `pin_window_if_store_written` pins it on the first store-writing nested run (`resets == 0`), so a compile pins it immediately: `inet_parse` ends with **19** regions / 620 756 992 words — 4.63 GB, **resident**, 59 % of the peak — under the tree compiler, and **9** / 285 212 672 words (2.18 GB) under system OTP-29.
   Nothing in that chain can be freed, retargeted or reused, and the reason is *not* the pooled BIF heap's (`calls.rs:177-179`'s `take_bif_frontier` accounts for the pool, not the store): `Runtime::eval_heap` is **pointer-stable for the runtime's lifetime** — a host-side term store keeps raw store words (`Runtime::stabilize_term`'s contract) — and an in-flight `Machine` holds arena/store words that no door enumerates during a call, so a drop or a relocation would have to prove that no reachable word lies at or above the region it retires.
4. **STILL OPEN and `beam_rt`-adjacent — the arena.** Truncating an older `ReservedHeap` needs a reachability proof (a later region can hold terms whose cons cells live in an earlier one), i.e. a GC.
   Its census now exists (`MinimalContext::heap_stats`, `heap_mark`/`heap_mark_matches`, `for_each_heap_region`), as does the per-machine root walk (`Machine::for_each_root`); what does not is `ContextHeap::reclaim`/`MinimalContext::reclaim_heap` and a collect-with-extra-roots entry.
   Its measured size is `arena_words` itself: 58 031 words after an in-process `cerl_clauses` compile (the `run` route), 5 133 683 / 1 328 040 494 words after a `-eval` `cerl_clauses` / `inet_parse` compile (and 2.85 GB of written pages at the `inet_parse` peak).
5. **GATED — the exempt window's nursery chain** (the section above): `resolve_external_call`'s debt gate routes the `lists`/`maps` fun-applying keys in-machine on the caller's armed machine while the caller owes a collection, so the chain is collapsed as it grows.
   The residual is the exempt window itself (`Process::collect_with` at the three `apply_fun`/`run_*_blocking` sites), which a nested run entered while the caller owes **no** debt still opens.
6. **UNSOUND — `eval_heap`/arena `reset_to` at a `-eval` statement boundary for a compile.** A compile is *one* statement and the evaluator's environment holds live values built on the arena, so a statement-boundary reset inside it would either do nothing (no boundary) or drop live values; the existing `eval/mod.rs` reset is correctly gated on `depth != 0` for this reason.

**What closing items 3–4 needs, and why every route is blocked today.** The owner of that work is a **collect-with-extra-roots** API: a **relocatable** arena/store, writable root enumeration across parked and in-flight machines, and `beam_gc`'s walker made region-generic (`beam_gc::copy::collect(from, to, roots)` today moves one `HeapSpace` into another with `&mut [Eterm]` roots).
Each route to it is blocked by a present-day invariant:
- **Relocation is impossible for both stores** — the arena's and the store's words are pointer-stable by contract, because a host-side term store keeps the word.
- **The root set is enumerable only at a statement boundary** (`depth == 0`, which a compile never reaches: it is one statement whose evaluator environment holds live arena terms) **and at the engine's `RootSet` hand-off points** (`Machine::with_roots`, which parks the five loose heap-term slots and hands mutable register/stack slices).
- **A nested run is relocation-exempt** (`with_relocation_exempt`), so no collection may fire inside it — which is exactly where a compile's words are built.
- **`Machine::for_each_root` is `&self`** and hands out copies: it censuses one machine's roots but cannot write a moved word back.

Truncation is not a weaker form of the missing entry point — it is a different operation, and the difference is what decides this.
A window rewind is `eval_heap.reset_to(mark)` gated by the read-only `reclaim::walk`/`WindowProbe` descent in `src/eval/scratch.rs`, so it can reclaim only the **contiguous suffix** `[mark, used)` and only when nothing reachable stands inside it: a mark below the live set is declined (`"a live term stands inside the window"`), and a mark above it would drop live words.
On this route the compiler's live results **interleave** with dead ones, so no mark separates them and closing the bound needs **compaction (relocation)** rather than truncation — which is why a read-only `Machine::for_each_root` is necessary but not sufficient.
The itemised sibling APIs, with their status: `Machine::for_each_root` (`&self`, a census) and `Machine::for_each_root_mut` (`beam_engine/src/machine/mod.rs:1159`, `&mut self`, hands out `&mut [Eterm]` slices for `x`/`stack`/`fr` via `RootSet::ALL_LIVE`) — **exist**; `MinimalContext::heap_stats`/`heap_mark`/`heap_mark_matches`/`for_each_heap_region` and `MinimalContext::{heap_rewind,reclaim_heap,reclaim_heap_with_capacity}` (+ `HeapMark::region/base`, `ContextHeapStats::live_words`) — **exist** (`beam_engine/src/context/reclaim.rs:452/516/544`, `src/context.rs:2264`), and `beam_gc`'s `Relocator`/`LinearDest`/`FromSet::from_ranges`/`live_words_in`/`compact` are its already-wired consumer; a collect-with-extra-roots entry on `beam_process::Process`/`beam_gc::Collector` (`Process::collect` takes no extra roots) — **missing**; a `Runtime`-reachable handle to an **in-flight** machine (whose `&mut` lives on the Rust stack of `pump.rs`'s `run_export_blocking`/`run_label_blocking`, and which is `machine_pool::release`d before `pin_window_if_store_written` runs) — **missing**, and it is the only seam that would let the existing reclaim APIs be *called* from a nested run — the wiring at `pump.rs`'s two epilogues (after `adopt_nested_payloads`, while `machine: &mut Machine` is still a local) and `execution.rs`'s `apply_fun` — **missing**.
