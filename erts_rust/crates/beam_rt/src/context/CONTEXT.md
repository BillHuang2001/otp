# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → the dispatch memo → `call_registered` → external-module load), the nine bridge arms, the per-context dispatch memo (`RuntimeContext::dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), the caller-module tracking and the **in-machine execution-position door** (`position.rs`).
The nine `beam_engine::Mailbox` seam methods live one level up in [`../mailbox.rs`](../mailbox.rs); this node owns the `ExecutionContext` half of the glue, and the runtime-level scheduler/runner that drives it lives in [`../runtime/`](../runtime/CONTEXT.md).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module` and `engines`; methods `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off — given the published FR-prefix count, see `gc.rs`).
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set, which is what `ets:new/2`'s bookkeeping gate keys off) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`execution.rs`'s `call_bif` → `calls.rs`'s `call_bif_routed`).
`RuntimeContext::wants_reduce` returns `false` (the trait's default `reduce` is the no-op here, so the per-instruction reduction-hook call is skipped on every non-budgeted run); the one host declaring `true` and charging a slice budget is the runner's `BudgetContext` (`src/runner/budget.rs`).
**No `ets:*` key is intercepted or re-implemented in `beam_rt`** — the one `ets`-family special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` (the only key it treats specially) through the **same** `call_registered` registry implementation as every other `ets:*` key, then observes the created `named_table` to index it for owner-death reclamation (a `before`/`after` `lookup_name` delta → `runtime::ets_owner::adopt_created_table`). `try_native` has **no** `ets` arm, `FLOOR_MODULES` excludes `ets`, and no NIF backs it, so **every** `ets:*` key reaches the `beam_bifs` `ets` registry (`crates/beam_bifs/src/ets.rs`) and is shadowed by nothing.
**`resolve_external_call` — the in-machine cross-module call seam (adopted).** `RuntimeContext` overrides `ExecutionContext::resolve_external_call`, so a `call_ext`/`call_ext_only`/`call_ext_last` callee runs **in the caller's machine** (the engine stores the caller's return address then enters the callee's export label) instead of recursing through `call_bif` → `run_export`. That is what lets a `receive` inside a cross-module callee **suspend** — `proc_lib:start/4`/`proc_lib:start_link/4` answer `{ok,pid}` (`../tests/proc_lib_start.rs`) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning the `Module` is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; the call args are already in `x(0..arity)` and an unknown label is the typed `unknown_label`.
It performs `find_module_file` + `code_server.load` **on demand** for an uncached callee, and returns `Ok(None)` (preserving the synchronous `call_bif` path byte-for-byte) for a name the native floor serves (`native::floor_shadows` — **key-granular**: practically every name in a `FLOOR_MODULES` namespace is refused, except `io`, where the floor owns only `io:put_chars/1,2`, so every other `io:*` (`io:getopts/1`, `io:setopts/2`, `io:scan_erl_form/4`, …) is an ordinary `lib/stdlib/src/io.erl` body entered in-machine so its blocking `receive` can suspend the process), a NIF-loaded module (`beam_engine` owns that dispatch), a `beam_bifs` registry key, a module whose callee observes its own call site (`callee_observes_its_call_site` — **module-wide** for `erlang:load_nif/2`, which reads `current_module`, which an in-machine callee never re-enters `RuntimeContext` to update, and a local call inside the module can reach the loader while a local `call` never re-consults the seam; the seam **exempts a built-in NIF library** from that module-wide verdict (`crate::native::prim_tty::is_builtin_library`, contract A.7's `prim_*` family): a statically linked library is resolved from ERTS's static NIF table and registers nothing, so its `load_nif` has no identity to protect and refusing it would only fold the wrappers' blocking `receive` into the `blocked()` gap; **per-function** for `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, whose fun image no longer reads the call site but which stay on the synchronous route as a conservative guard against the **function issuing the call** parking with an unpublished `Machine::pending_exception`), a foreign-pid/unknown export, and an unknown label.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `RuntimeContext` implements `ExecutionContext::resolve_local_fun` in two steps. First the shared `RuntimeContext::local_fun_target` lookup: `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure — `module` is the **same** `Arc<Module>` the code server caches (the engine dedups module contexts by `Arc::ptr_eq`) and `label` is the lambda's `FunT` entry label. When that finds no local closure the fun is handed to `RuntimeContext::external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`, the `EXPORT_EXT` encoding) is not a closure but its whole identity *is* the callee's `M:F/A`, so it resolves to that module's **export label** through the cross-module seam's **own** `ExecutionContext::resolve_external_call` and is therefore admitted in-machine under exactly the same refusals (a floor-served name, a loaded NIF library, a registered `beam_bifs` key, a `callee_observes_its_call_site` callee, a non-exported name — and an apply whose argument count disagrees with the fun's arity — each answer `Ok(None)`). `Ok(None)` therefore remains for the fun kinds with no in-machine entry: the `-eval` closure (`EVAL_FUN_UNIQ`) and any external fun the resolver refuses. C's `call_fun` enters an external fun's code in the calling process the same way; entering it here is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`) instead of folding into the nested run's `blocked()` gap — see [`../boot/CONTEXT.md`](../boot/CONTEXT.md). The engine consults the seam **first** in its `call_fun`/`call_fun2` arms: on `Some` it places the closure's free variables in `x(arity..)` (C's `call_fun` order) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process (`RunOutcome::Wait`) and a raise lands in the caller's live `try`/`catch`; `Ok(None)` keeps the value-returning `apply_fun` fallback byte-identical. The engine, not this host, places the free variables, so `local_fun_target`'s combined `args ++ free` list is used here only for resolution/validation.
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context` and `reset` — not `resume_outcome` — clears contexts. A fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier` (`../tests/fun_entry_receive.rs`).
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap — `alloc_words_rooted` is the engine's term-building admission point, which collects over the machine's whole handed-in root set when that bump fails, while the unrooted `alloc_words` **never collects** (it is handed no root set); the engine's heap-admission doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect there and **grow** the nursery to fit a request larger than it (the collector's `Process::ensure_capacity` seam, driven whenever the process's heap-size policy can reach the request via `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to a plain `Process::collect()`, preserving the pre-growth behaviour exactly). The unrooted `alloc_words` meets a **capacity** refusal by growing the nursery through `Process::grow_nursery` — a no-relocation growth (retention moves nothing, so it is legal for a caller that cannot publish roots) — and retrying the bump once; a growth that cannot reach the request, a retry that still does not fit, and a non-capacity refusal all fall back to the pointer-stable runtime arena byte-for-byte.
**Registry precedence (gotcha for new `beam_bifs` registrations).** The native floor runs *before* the registry, so a `beam_bifs` entry for a key the floor already serves can never shadow it; the registry runs *before* the external-module load, so for a **non-`erlang`** name a registration **does** shadow the fallback while for an `erlang:*` name it flips the unregistered answer (bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) to whatever the BIF returns. The `apply_fun` and `send_message*` seams that `call_bif` reaches are described under `apply.rs`/`send.rs` in the routing table.

### In-machine execution-position door (`position.rs`)
A process's execution-position items — `erlang:process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` and `catchlevel` — are read out of the [`Machine`](beam_engine::Machine) that owns its frame (see `../native/memory`), and the scheduler **takes the executing process's machine out** of [`RunnerState`](crate::runner::RunnerState) for the whole slice to drive it, so the runner-state view that answers *every other* pid cannot see the caller's own machine: `erlang:process_info(self(), current_stacktrace)` used to be the typed `unsupported: process_info: current_stacktrace` gap. That is `gen_server:handle_common_reply/5`'s `?STACKTRACE()` macro, so it tore down any `gen_server` reaching a `terminate/2`.
`beam_engine`'s defaulted [`ExecutionContext::wants_bif_in_machine`]/[`ExecutionContext::call_bif_in_machine`] seam (declared in `../beam_engine/src/context.rs`, funnelled through `Machine::dispatch_bif_call` on **both** execution tiers) closes it: a host that opts in is handed the live `&Machine` and the run's entry module on every BIF dispatch. `position.rs` is that opt-in, and it is deliberately narrow.
`RuntimeContext::in_machine_probe` answers `true` (the engine latches the answer **once per run**, so opting in costs one `bool` load per dispatch); `RuntimeContext::dispatch_in_machine` then rejects every dispatch that is not an `erlang:process_info/1,2` with a single string compare and — **only** for a query whose first argument **is the executing process** (`pid == self.pid()`) — reads the five machine-sourced values once (`machine_position`, against the run's entry module: a `Machine` borrows context `0` rather than owning it) and publishes them in the runtime-owned slot `Runtime::in_machine` for the duration of the nested [`ExecutionContext::call_bif`], clearing it immediately after (no `?` between the set and the clear, so the slot cannot outlive the call that needs it). `../native/memory`'s `position_value`/`catchlevel_value` consult that slot first through `RuntimeContext::in_machine_value`. The published terms need no root set: no collection can run while a BIF call is in flight (the engine publishes no root set at a BIF dispatch — `context/gc.rs`), so the window is exactly one nested `call_bif`.
Everything else — another pid, a nested query while an outer door call is in flight, a pid-less first argument, a name the machine does not source, or a machine with no such position — falls straight through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated. The two overrides live in `execution.rs`; the wrapper that carries them onto the **scheduled** path is the runner's `BudgetContext` ([`../runner/CONTEXT.md`](../runner/CONTEXT.md)).

### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives. One shared helper serves **all three** entry points — `alias.rs::alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying the destination by **provenance first** through `Runtime::local_reference(to)`; the module docs carry the full arm-by-arm rule (a monitor/alias reference `Some(Some(reference))` is the only shape looked up via `table.resolve_alias`; a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias; unknown provenance `None` — a decoded or received copy — falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`):
* the BIF route (`erlang:send/2`, `erlang:'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery (the nested `RuntimeContext` is block-scoped so the borrows stay strictly resolve `&self` → deliver `&mut` → consume `&mut`);
* the compiled `Dest ! Msg` route — `RuntimeContext::resolve_send_destination` (an inherent method, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events; this is what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` (`../lib/stdlib/src/gen_server.erl:549-553`) compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteName`) and `RuntimeContext::deliver_remote` transmits it over the connection the runtime is a node on; the local-only `RuntimeContext::resolve_send_target` is now a `#[cfg(test)]` wrapper beside it.
The C arm reproduced is `send_altact_message` (`../../erts/emulator/beam/bif.c:2478-2492`) + `handle_altact_msg` (`../../erts/emulator/beam/erl_proc_sig_queue.c:6009-6112`). The two reference id spaces are **bridged, not unified** (`Runtime::refs` for `make_ref/0`/timers/`seq_trace`; the `ProcessTable`'s own allocator for monitors/aliases). The typed-`badarg`-vs-silent-drop divergence and the residual reference-**identity** hazard are in the module docs and the crate `Known Issues`.

### `call_registered` — nine dispatch arms, the gated seam handles, the port provider
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook; the shared `TableRegistry` is installed **unless** an argument is a fun (a fun argument can re-enter and reach `ets:*`, so the `RefCell` must stay free). Exactly **one** bridge is then selected, first-match, from the [`DispatchHooks`](#the-dispatch-memo--dispatchhooks) the caller's [`dispatch`](#the-dispatch-memo--dispatchhooks) memo computed — one boolean per `uses_*` predicate, so no predicate runs per call:
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1`; a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — nine BIFs (`whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_flag/2`, `group_leader/0`; `process_info/1,2` is intercepted by the floor first) over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>` (`src/context/process_bridge.rs`); the per-process `erlang:group_leader/2` and `erts_internal:group_leader/2,3` are served by the floor (`src/native/group_leader.rs`).
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised. Its long-lived host is built with `services = None` (it is moved into the runtime's `NifRegistry` and so cannot borrow the runtime) and with `crate::info::schedulers_count(runtime)` as its `scheduler_threads`, so a `load`/`unload` callback's `system_info` stays honest and every `NifHostServices` hook — `make_ref`, `whereis_pid`, `is_process_alive`, `is_port_alive`, `port_command` — stays the typed default there, never a fabricated value.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; an unloaded module or undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`erlang:'!'/2` delegating to `RuntimeContext::send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered; a **reference alias** destination is delivered to the alias **owner** — see the alias bullet below).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR.
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store; a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow. The store keeps raw `Eterm` words (safe while the runtime's heaps stay pointer-stable; a runtime-level store whose term must survive a heap move instead stabilizes its writes through `Runtime::try_stabilize_escaped`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`; `src/context/runtime_hooks.rs`) — serves a subset of the 172-key roster (`beam_bifs::RUNTIME_HOOKS_BIFS`): `start_timer/3,4` (delivers `{timeout, TRef, Msg}`), `send_after/4`, `cancel_timer/2`, `function_exported/3` (the **`erts_is_builtin` half** — the declared `bif.tab` surface plus the `erlang`-namespace registry extras — OR the loaded module's own export table; the `beam_bifs` registry is *not* the source of truth for any other module, because it also carries the stdlib *fast paths*, real *Erlang* functions such as `lists:map/2` that `erts_is_builtin` does not know), `link/1`/`unlink/1` (the `ProcessTable` link set; a **remote** pid routes through `ProcessTable::link_term`/`unlink_term` to the installed `DistSignalRouter`, the only remaining gap being a peer with no established link), `os:set_signal/2` (`signal.rs`), `net_kernel:dflag_unicode_io/1` (the io-device read path's unicode fast-path probe: the atom `true` for a local pid, `badarg` for a non-pid, the typed gap for a remote pid), the dynamic-tracing tag family (`dt_spread_tag/1`/`dt_restore_tag/1` identity, `dt_get_tag/0`/`dt_get_tag_data/0`/`dt_put_tag/1` ⇒ `undefined`, `dt_append_vm_tag_data/1`/`dt_prepend_vm_tag_data/1` ⇒ the argument), `system_profile/0`, `check_old_code/1`, `finish_loading/1`, the three on-load hooks (⇒ `badarg`), `erts_internal:is_system_process/1`/`is_process_executing_dirty/1` (⇒ `false`), `erts_internal:erase_persistent_terms/0` (⇒ `true`, and really clears the store), `erts_literal_area_collector:release_area_switch/0` (raises `error:notsup`), `erts_trace_cleaner:check/0` (⇒ `false`), `error_logger:warning_map/0` (⇒ `warning`), `code:coverage_support/0`/`get_coverage_mode/0`/`set_coverage_mode/1` and `erlang:statistics/1` (`run_queue`, `wall_clock`, the cumulative counter pairs `reductions`/`exact_reductions` and `context_switches`, `io`, and `scheduler_wall_time` ⇒ `undefined`; the remaining valid statistics keys are the typed `unsupported` gap — per-key catalog below). Every other roster key — incl. `read_timer/1,2` — is the typed `unsupported_bif` gap (or served **earlier** in the dispatch order by the native floor: `alias/0,1`/`unalias/1`, and the four `erl_ddll` list/load/unload/report keys `loaded_drivers/0`/`try_load/3`/`try_unload/2`/`info/2`, whose `monitor/2`/`demonitor/1` counterparts stay with the registry), and a key outside the roster is bare `error::undef`. It holds `&mut Runtime` **plus** a `&mut ProcessTable`, so it is its own arm. `timeout` is a `boot::CORE_ATOMS` seed (the bridge cannot intern: the shared table is borrowed immutably for the whole call).
* **`FunBridge`** (`FunCaller`; the fallback) — `RuntimeContext::apply_fun` over `&mut Runtime`, carrying a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`, and **no** `TableRegistry`.
`NodeIdentity` answers this runtime's **own** node — `Runtime::local_node()` (the live `node@host` atom on a `-name`/`-sname` node, else `nonode@nohost`), creation `0` — for `beam_codec`'s `Encoder::with_local_node`, emitting `NEW_PID_EXT` (`88`) for an internal pid and `V4_PORT_EXT` (`120`) for an internal port. The **decode** direction is wired: `beam_bifs::binconv::decode_term_bif` installs this runtime's `local_node` identity on `beam_codec`'s decoder (`Decoder::with_local_node`), which demotes a local-node `NEW_PID_EXT`/`V4_PORT_EXT` to the internal id, so `binary_to_term(term_to_binary(self())) =:= self()`.
`FunIdentityBridge` supplies the `NEW_FUN_EXT` (`112`) identity of a **compiled module's** local (`make_fun3`) fun from the code server's **cached** loaded-module snapshot (`CodeServer::fun_module_snapshot` — every loaded module with a `.beam` path, name-sorted, rebuilt only when a module is loaded/reloaded and shared through an `Rc`), scanned **caller-first** via an index into that snapshot, plus the node atom: `Ok(None)` — never an error — for a non-local-fun argument, a context with no calling module (the `-eval` evaluator) or an unreadable `.beam`, otherwise module atom + module MD5 + `old_index`/`old_uniq` from `FunT` + the fixed `<0.0.0>` creator (`bridges.rs::local_fun_identity`/`module_md5`). Built only on the `uses_fun_identity` arm (`erlang:term_to_binary/1,2`, `erlang:external_size/1,2`).
`RuntimeMemory` (the `MemoryHook`) is built only on the `uses_memory_hook` arm (`erlang:memory/0,1`); ungated its `code_bytes` snapshot (a `CodeServer::loaded()` clone+sort plus a `std::fs::metadata` per module) would cost ~13 µs on **every** registered call.

### The dispatch memo · `DispatchHooks`
`RuntimeContext::dispatch(module, function, arity) -> DispatchAnswer` is the **only** producer of a registered call's dispatch answer, and its result is memoized in a per-context **direct-mapped 8-slot** memo (`DispatchMemo`; the slot comes from `dispatch_slot` over the key's **name bytes** and the arity). `DispatchAnswer` is `{ bif: Option<BifFn>, hooks: DispatchHooks }`:
* `bif` is `Runtime::registry.lookup(module, function, arity)` — the implementation the caller then **invokes directly** (`call_bif_routed` passes it to `call_registered`, which calls `invoke_registered`; no second lookup); `contains` **is** `lookup(…).is_some()` (`crates/beam_bifs/src/registry.rs:189`, pinned equal by that crate's `contains_always_agrees_with_lookup`), so the lookup is the only registry call on the path **and the memo is never consulted as a registry** — `call_registered` is reached only when `lookup` answered `Some`;
* `hooks` is one boolean per `uses_*` predicate — the eight mutually-exclusive arm selectors plus the two build gates (`fun_identity`, `memory_hook`) — computed by `DispatchHooks::of`, the **only** place the `binary_search`es over `beam_bifs`' `&'static` `needs_*` rosters run. `call_registered` selects its arm and its two optional handles from `hooks.*` instead of re-running the predicates per call.
A **miss** computes the answer and stores it; a **slot collision** overwrites, and the evicted key recomputes on its next call — an eviction costs work, never a result.
`dispatch_slot` hashes the key's **bytes** (FNV-1a over `module`, a `0xFF` separator, `function`, then the arity) and avalanches the result with a fixed multiply (high bits), so same-length keys no longer collide **by construction**: `ets:insert/2` and `ets:lookup/2` now occupy different slots and an insert/lookup loop **hits**. The memo still has only eight slots, so a workload with more than eight hot keys still collides somewhere, and a collision costs the whole prologue (`registry.lookup` + the ten `needs_*` `binary_search`es + two `String` allocations) on every miss — never a wrong answer. The avalanche constant is **chosen**, not derived, so that the crate's measured hot key set (`lists:reverse/1`, `erlang:length/1`, `ets:insert/2`, `ets:lookup/2`, the `erlang` arithmetic rows) occupies distinct slots — the 8-slot table is the binding limit, and enlarging it means changing the churn assertion in `src/context/tests.rs` (`PERF.md`, the `DISPATCH-CUT` snapshot, records both the chosen constant and the 2.3× path-C regression that a naive byte hash caused).
**Two further prologue costs are gone.** (a) The **second registry lookup**: `call_bif_routed` uses `dispatch.bif` to hand the already-resolved `BifFn` to `call_registered`, and `invoke_registered` reproduces `BifRegistry::call`'s arity check so the error path is byte-for-byte unchanged. (b) The **NIF probe**: `try_call_nif` short-circuits on `NifRegistry::is_empty()`, so an empty registry costs one `RefCell` borrow and a length compare instead of a third `HashMap<String,_>` SipHash pass.
**Why a cached answer can never go stale.** Both inputs are immutable for the life of the runtime: `beam_bifs`' `needs_*` rosters are `&'static` tables and the predicates are pure membership tests over them, and `Runtime::registry` is an `Rc<BifRegistry>` built once at boot — `BifRegistry::register` takes `&mut self` and is boot-time only, and nothing in this crate ever calls `Rc::make_mut`/`Rc::get_mut` on it. The one **runtime-mutable** dispatch input is the NIF registry that `erlang:load_nif/2` grows; it is deliberately **not** memoized — `call_bif` still runs `try_call_nif` first on **every** call, so a library loaded mid-slice wins immediately (`../../tests/nif.rs` loads a real `.so` and pins that precedence). The memo lives on the `RuntimeContext`, so it is exactly as long-lived as one run: a nested run (`FunBridge`/`SendBridge`) builds a fresh context with an empty memo, and every `RuntimeContext::new`/`with_output`/`for_process` starts empty too, so no cross-context staleness question arises.

### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` keeps its `{base, names}` state **inline** (`InternerState::Inline(RefCell<…>)`) and allocates only when `PendingInterner::share` promotes it into a shared `Rc<RefCell<…>>` (`InternerState::Shared`): `new(base)` roots it at the shared table's length, `commit` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers). The ordinary registered/NIF call has a **single** writer, so it never shares and allocates nothing; `load_nif/2`'s two writers (the BIF, the C `load` callback via `enif_make_atom`) call `share()` and get two handles over one cell, so both agree on `base + <names recorded>` and the caller's single `commit` lands every name at exactly its predicted index. `share` is the only way to obtain a second handle — `PendingInterner` deliberately implements no public `Clone`, so the inline no-allocation path cannot be bypassed and no call hands out state whose sharing is invisible at the call site. `run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess). `call_registered` does **not** clone the caller's module for every call: the field is borrowed only for the pre-destructure fun-identity snapshot and moved out of the destructure, so only the NIF-loading, `send` and fun-caller arms (which need an owned `String`) clone it.
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable pooled BIF heap and the per-call `PendingInterner` is committed **after the registry borrow is released**. `NifCallError::Raised(reason)` → `error::nif_raised`; `UnknownFunction` → bare `error::undef`; a miss is `Ok(None)`. The per-call host is handed a `crate::nif::RuntimeNifServices` provider built from **disjoint** field borrows of the runtime (`refs`/`references`/`processes`/`ports`; `processes` is the caller's mailbox table when it runs a scheduler slice), so the host's `make_ref`/`whereis_pid` hooks **and** its `is_port_alive`/`port_command` port hooks (over the `Rc<RefCell<PortRegistry>>`, a `try_borrow` ⇒ the typed "cannot answer" `None` on a live borrow) are live; the registry `Rc` is cloned and the heap taken **before** those borrows, so the call itself never borrows `self.runtime`, and the borrows are released (`host.into_heap()` + `drop(services)`) before the heap/interner work reuses it. **Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif`.

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with two narrowly-scoped `#[allow(unsafe_code)]` exceptions (`gc_walk.rs`'s sanctioned `beam_term::layout` object-walk; `../nif.rs`'s `enif_compare`/`enif_hash` `unsafe extern "C"` calls). The glue otherwise uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Dispatch cost is a first-class concern**: `call_bif`/`call_registered` run per call, so every handle built there must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the registry/roster prologue derives belongs in the [`dispatch`](#the-dispatch-memo--dispatchhooks) memo (any input that can change during a run — the NIF registry — must stay out of it). The registered-BIF figure is the interleaved min-of-N slope over a non-inlinable fixture recorded in [`../../PERF.md`](../../PERF.md) by [`../../examples/perf_call.rs`](../../examples/perf_call.rs) — `../../examples/perf_bif.rs`'s own `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch at all (its banner says so); see [`../../TRACE_AND_PERF.md`](../../TRACE_AND_PERF.md) for the `perf_bif` harness itself.

## Known Issues
* **A float-using call-site module never reaches a collection, so its loop's garbage lands in the never-freed arena and peak RSS grows with the iteration count.** The collection chain is gated **first** by the caller-module float test, before the unscanned-root valve: `gc.rs::ensure_heap` (`:543`), `ensure_heap_full` (`:693`) and `alloc_words_rooted` (`:916`) all `return Ok(())`/fall back when `!module_may_be_collected(runtime, name)`, and `module_uses_floats` (`gc.rs:130`) is `true` for any module whose IR contains `Fmove`/`Fconv`/`Fadd`/`Fsub`/`Fmul`/`Fdiv`/`Fnegate` — which a **float literal** reaches, because a constant is loaded with `fmove {float,K} {fr,N}` (`../beam_engine/src/families/floats/mod.rs:247-253`). `beam_gc`'s default nursery is **233 words** (`HeapPolicy::default().initial_young_words`, `../../../beam_gc/src/policy.rs:147`) with `max_heap_words == 0` (unbounded), so the nursery fills within one iteration and every later `alloc_words_rooted` refusal takes the arena fallback (`gc.rs:916-919` → `Runtime::alloc_words` → the never-reset `MinimalContext` region heap, `runtime.rs:1068`). The guard is a documented **conservative extra** at the two doors that publish the whole FR file (`publish_roots_full`; see `gc.rs:471-479`, `:648-651`, `:871-874` and `beam_engine`'s `frames.rs:475` test), and only the narrow door genuinely needs it. **Scope:** this is the genuinely float-using-module gap only. `copy_bound/ets_copy`'s own RSS growth is a **different** mechanism — the BIF-result copy-out retaining retired young space, tracked per BIF call and independent of floats (relaxing this guard changed nothing: 94.68 → 95.02 MiB) — recorded in [`../M1_GAPS.md`](../M1_GAPS.md) *GC / heap model*.
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap.** A cross-module call the engine cannot enter in-machine ([`resolve_external_call`](#the-dispatch-memo--dispatchhooks)) goes through `call_bif` → `run_export` → [`run_export_blocking`](#api-surface) — a fresh `Machine` on the same pid under a `RuntimeContext` built by `for_process*` (`may_pump_scheduler() == false`). [`pump_once`](#api-surface) then returns `Ok(None)` **on its first line**, so the parked callee folds into `beam_engine::blocked()` (an uncatchable capability gap) regardless of whether its `receive` carries an `after T` (the pump check refuses it: `REFUSED (may_pump=false)`). `resolve_external_call` refuses a callee per [`callee_observes_its_call_site`](#api-surface) — **module-wide** over `erlang:load_nif/2`, **per-function** over the fun-image imports (`erlang:term_to_binary/1,2`/`erlang:external_size/1,2`) — so a `compile:*` function whose own body does not issue a fun-image BIF is admitted in-machine and its `receive` can suspend, while a function that does (e.g. `compile.beam`'s debug/`Docs`-chunk builder) takes the out-of-line nested run instead — both A.9 `selfhost/*` compile cases **agree** with the oracle on both execution tiers. Nothing here is a wrong result.
* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** The reason is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it — but `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (`beam_process`'s `gather_roots`/`scatter_roots` relocate it in place) and `RuntimeContext::resync_parked_roots` reads the relocated word back into `Machine::pending_exception_mut()` and clears the extra roots. A delivery-driven receiver-heap collection in the park window therefore relocates the reason with the heap instead of leaving the machine's slot on a dead from-space word. The publish/resume pair roots the reason across the park window; the A.9 `selfhost/*` compile cases now **agree** with the oracle on both execution tiers.
* **The fun-image half of [`callee_observes_its_call_site`](#api-surface) is per-function; both A.9 `selfhost/*` corpus cases agree on both tiers.** With `erlang:term_to_binary/1,2`/`erlang:external_size/1,2` guarded only in the function that issues the call (`erlang:load_nif/2` stays module-wide), `compile:*` is admitted to the in-machine route on the **scheduled** path, and `selfhost/in_process_compile_file_no_spawn_deterministic` plus `selfhost/scheduled_process_compile_file_deterministic` **agree** with the oracle on both the interpreter and the baseline tier. The corruption those cases once showed was a *signal-driven* collection — the monitor-DOWN branch of `beam_process`'s process-termination cascade (`crates/beam_process/src/ptab.rs` → `enqueue_down_signal` → `copy_reason_onto` → `grow_receiver_for_signal` → `Process::ensure_capacity`) relocating a woken watcher's heap against a `regs` snapshot that is not its whole live root set — and it is declined by the runner's **park-window relocation exemption** (the Wait park arm sets the mark, the resume clears it), so the delivery takes the ordinary heap-fragment fallback. Mechanism, measurement and the decline predicate still owed to `ptab.rs`'s signal sites: [`../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../EPP_SCHEDULED_ROUTE_FINDINGS.md); rationale: [`../DESIGN_DECISIONS.md`](../DESIGN_DECISIONS.md).
* **`alloc_words` grows the nursery before falling back to the arena, and the two-phase unscanned-root valve is what keeps the fallback sound.** For a **collectable** slice process whose own young bump fails with a **capacity** refusal (`BeamError::Alloc`), `context/gc.rs::alloc_words` calls `Process::grow_nursery` — the **no-relocation** growth seam, which retires the space it replaces and moves no live term, so it is legal for a caller handed **no** root set (it never collects) — and **retries the bump**; only a growth the policy ceiling cannot reach, a retry that still does not fit, or a **non-capacity** refusal (an impossible request past `MAX_ARITYVAL`) falls back to the pointer-stable arena, and that fallback is what `note_gc_fallback` counts. The arena block is a container in a region the collector does not scan, which the valve keeps sound: it **declines** (`Ok(())`) a collection whose root set — or whose process-side scanned graph — reaches such a container, at each of the four collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted` and the runner's park arm `Runtime::serve_gc_request`). The valve is **two-phase** (`context/gc.rs::root_is_unscanned` + [`gc_walk.rs`](#routing-table)): the per-word phase always runs and calls a term safe exactly when it is an **immediate**, a **literal**, or a pointer the process's collector **scans** — **any** nursery space (the current one or one a growth retired) or the mature generation; the descent runs only under the process's sticky per-pid latch (`Runtime::foreign_reachable`), so a foreign container reached at depth ≥ 2 (a young cons whose element is a pooled-BIF-heap container whose element is a nursery pointer) is found. A term in a foreign region (the pooled BIF heap, the arena, the `-eval` heap, a message fragment) therefore declines the collection — **except** a registered-BIF result: `call_registered` copies it onto the running process's heap and rewinds the pool to the call's own `mark` (`Heap::reset_to`, so a shared pool keeps the words a previous caller owns), so a registered-BIF container result is a scanned root rather than a foreign holder (see `calls.rs`; whether a given loop then *reaches* a collection is separate — a small-`test_heap` loop does not, `PERF.md` *COPY-OUT-CUT*).
* **`erlang:memory/0,1` reports `0` on the `-eval`/single-pass path.** `memory_hook.rs::RuntimeMemory::new` sums each live process's collector capacity (nursery + mature) for `processes` and its **used** words — nursery *and* mature (`collector.young().used_words() + collector.mature_used_words()`) — for `processes_used`, so the scheduled path counts both generations of a long-lived process. The `-eval`/single-pass path has no `Process` — it allocates on `Runtime::arena` (a `beam_engine::MinimalContext`) whose private `Arena` exposes no byte/word accessor — so its `processes`/`processes_used` are an honest `0`; making that half real needs a new `MinimalContext` arena-words accessor plumbed through `Runtime` (owner: `beam_engine`).

* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly (`process_bridge.rs:176-343`). The `erlang:ports/0` typed gap (`process_bridge.rs:213-220`, a `try_borrow` failure) is reachable only on a **nested** path: in `call_registered` the arm hands the bridge a **separate `Rc` clone** of the port registry (the provider takes one at `calls.rs:263`, the bridge another at `calls.rs:305`), so no borrow is held on the bridge's clone during an ordinary call and production `erlang:ports/0` works. The two divergences, both unit-pinned: `register/2` with a **port id** is a typed gap (`process_bridge.rs:184-189`; the table registers pids only), and `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg` (`process_bridge.rs:302-322`, test comment at `604-605`); `process_flag(error_handler, Atom)` always answers the atom `error_handler` (no error-handler state, `process_bridge.rs:323-331`). No other method serves stale or placeholder data.
* **`NodeIdentity` carries this runtime's live node atom but a hard-coded creation `0`.** The atom comes from `Runtime::local_node()` (`bridges.rs`), so `node/0` and a pid's `NEW_PID_EXT` image name a `-name`/`-sname` node correctly; the `epmd`-assigned creation is not carried (`NodeIdentity` holds only the node atom, and its shape is pinned by a colocated unit test).
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles.** `send_source(Some(self.mailbox_pid), extra)` unions the three families a *delivery* can resolve — `extra`, the runtime's escaped-payload store and the sender's mailbox-retained families (`Runtime::source_payloads`) — but the BIF route (`SendBridge` → `ExecutionContext::send_message`) reaches it with `extra = &[]`, because no machine handle is observable there: the in-flight `Machine` is removed from `RunnerState.engines` for the whole slice (`runner/run.rs:169`), `BudgetContext` wraps only `&mut RuntimeContext` plus its probe (`runner/budget.rs:169-174`; the in-machine door hands it a `&Machine` for an `erlang:process_info/1,2` self query alone, never a machine handle on the `call_bif`/`SendHook` path), `ExecutionContext::call_bif`/`SendHook::send` carry no handle parameter (`../beam_engine/src/context.rs:304`, `../beam_bifs/src/context.rs:146,164`), and `Machine.refc_binaries` is a plain `Vec` field (`../beam_engine/src/machine/mod.rs:241`, accessor ~`567`). So a term the *running* machine just built with an off-heap payload and forwards from a BIF callee **flattens** (a correct but unshared copy) — only the compiled `Dest ! Msg` instruction's `send_message_with_off_heap` arm currently carries the machine's handles. Closing it needs a sibling change: thread the sender's handles into `ExecutionContext::call_bif`/`SendHook::send` (or expose `Machine::refc_binaries` through a shared cell a context can observe mid-run).
* **An enqueue-time control signal refused by the receiver's full nursery is keyed on the receiver's *unpublished roots* — a crate-owned, gate-independent condition — and on the installed host gate's decline; either way it is built into a heap fragment and the message arrives.** The refusal is specific to a receiver with unpublished roots (`Process::has_unpublished_roots()` = `relocation_exempt || state == ProcessState::Running`, `process.rs:1130`) **or** to a receiver the host's `CollectionGate` declines, and it is **gate-independent** — the exemption is the crate's own condition, not the gate's: `copy_reason_onto` (`../../beam_process/src/ptab.rs:323-350`) pre-tests both and hands the raw `Alloc` refusal back with **no** collect, **no** grow and **no** retry. `enqueue_down_signal` (`ptab.rs:2527`) and `enqueue_exit_signal` (`ptab.rs:2479`) key the heap-fragment route on exactly that refusal, building the `{'DOWN',…}`/`{'EXIT',…}` the queue would have materialised on a scratch arena and copying it whole into a fresh `HeapFragment` (`deliver_down_fragment`/`deliver_exit_fragment`), so the DOWN **arrives** (the death is processed *and* the notification delivered) with the receiver's heap neither collected nor grown. A receiver the installed gate declines never reaches the relocating `copy_reason_onto` at all — the gate is consulted by `ProcessTable::deliver` and every signal site. The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*, and terminating the receiver is the caller's cascade, not a message). `beam_rt` arms the exemption through `with_relocation_exempt` (`runtime_context.rs:318`): the **`-eval`/nested route** wraps the whole eval driver (`eval/mod.rs:332`) — including the receive pump that waits for a spawned child's DOWN — while the **scheduled `run` route** arms it for a PARKED process (the `Wait` park arm, `src/runner/run.rs`). Both routes deliver the waiting parent's DOWN even on a saturated nursery, pinned by `../../tests/eval_exempt_receiver_signal.rs`.

## Notes for Agents
- **The node's layout: `mod.rs` is root-only plumbing over concern-scoped submodules.** `mod.rs` holds the module `//!` overview + submodule map, the `mod …;` declarations, the crate-visible re-exports and the `#[cfg(test)]`-gated name plumbing, and defines no logic; the routing table below names each sibling's concern. Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs` and its methods delegate to inherent helpers in the sibling that owns the concern. Three siblings exceed the ~1000-line target — `runtime_hooks.rs`, `gc.rs` and `bridges.rs` — each one cohesive pre-existing concern documented at its own top, and `tests.rs` is the node's deliberately single shared unit suite. The names `tests.rs` and `pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]`, so both stay byte-identical; `DispatchMemo` alone stays ungated because `bridges.rs` uses `super::DispatchMemo::default()`. The crate's `pub` surface (and every `crate::context::…` path) is unchanged by the split.
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver (`pump.rs`), one `pump_once` round per wait. For an ordinary (no-deadline) parking, `pump_once` advances the scheduler by `RUN_EXPORT_PUMP_SLICES` slices and a pump that reports nothing ran ends the drive with the honest `beam_engine::blocked()` gap. The engine arms no timer for a `wait_timeout` and a nested run is not a scheduled process, so for a statically readable finite `after T` the deadline is the nested run's own to wait out: `pump_once` recovers it through `Machine::wait_deadline` and, on an empty run queue, sleeps `min(remaining, DEADLINE_PUMP_SLEEP)` and re-pumps until the wall clock reaches `start + T`, then resumes at the `timeout` continuation (a message arriving first wins; a re-park at a different suspension goes back to the driver) — bounded by `delay_ms` alone, so it is never delivered early. The loop ends on return, on a step reporting `Ok(None)` (the typed `blocked()` gap), or at the `BLOCKING_PUMP_DEADLINE` (10 s) cap — the safety net for a process that stays runnable forever, reported as the typed `error::message("blocking pump: the scheduler was still runnable after N ms")`. The cap is the nested counterpart of the boot drive's `DRIVE_DEADLINE` and is deliberately generous so no legitimate single-pass/`-eval`/boot workload is affected; the deadline path is exercised only through the injectable `limit` parameter.
- **Closure application is entered in-machine through the `resolve_local_fun` seam — for a context the engine drives directly.** The engine's `call_fun`/`call_fun2` arms consult `ExecutionContext::resolve_local_fun` **first**; `RuntimeContext` implements it as a thin wrapper over `local_fun_target` (see the API surface above), so a `.beam` local closure is entered in the **calling** machine, a `receive` inside it suspends *this* process (`RunOutcome::Wait`), and a raise lands in the caller's live `try`/`catch`. That holds for every route whose machine runs on the bare `RuntimeContext` — the single-pass/`-eval`/boot routes. The engine's `Ok(None)` fallback (the `-eval` closure, or an external fun the resolver refuses) is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking` (the label-addressed twin of `run_export_blocking`), so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper, not the bare `RuntimeContext`.** That wrapper forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process (`beam_rt run m.beam m:f/0`) enters in-machine, suspends through `RunOutcome::Wait`, and is resumed by a real send, and a same-module local `call` the host serves is dispatched as a BIF through `call_bif` (`RuntimeContext::resolve_local_call` → `crate::native::prim_tty::serves_local_call`, contract A.7's built-in `prim_*` library) instead of being jumped into the module's non-exported Erlang stub body. Pinned by `../../tests/scheduled_apply_seam.rs`. Discriminator: the `#[cfg(test)] mod blocking_fun_apply` in `pump.rs` (a blocking local closure applied through a **second** module, so fun inlining cannot turn the `call_fun` into a direct call) drives `apply_fun`/`run_label_blocking` directly, so its pumpable phase passes while its `for_process` control phase keeps the typed `blocked` gap. The A.9 differential-gate case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle; its per-directive detail is in [`../boot/CONTEXT.md`](../boot/CONTEXT.md).
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it. It needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` calls it with `Some(self.mailbox_pid)` (the sender: the full three-family union) and `deliver_message` with `None` (store-only). `deliver_message`'s context is built `for_process` the **receiver** by `deliver_in_table`, so that constant `None` is deliberate — unioning `self.mailbox_pid` there would resolve against the *receiver's* retained families. `None` (no handle in any family) preserves the empty-source fast path, so a plain on-heap message still builds no table.

### Relocation exemption (the cross-crate GC correctness seam)
`RuntimeContext::with_relocation_exempt<T>(&mut self, f: impl FnOnce(&mut Self) -> Result<T>) -> Result<T>` runs `f` with the context's process (`self.mailbox_pid`) marked relocation-exempt through `beam_process`'s `ProcessTable::{is,set}_relocation_exempt`, so a delivery-driven `Process::deliver` collect can never recycle words this crate holds **outside** the process's own containers (Rust-local term handles, an unpublished `Machine`). It is **nested-safe**: it saves the previous mark, sets `true`, runs `f`, and restores on every path (`TermNotFound` on the save means "no process — nothing to exempt"); the closure's error wins. Wrapped scopes (exactly five): `crate::eval::eval` (the whole `-eval` driver body, so its `Runtime::pump_scheduler` receive pump runs inside), `run_export_blocking` (a fresh `Machine` on the context's pid), `run_label_blocking` (the fun-bridge / local-closure nested run), `apply_fun` (the `-eval`-closure arm) and `deliver_message_with_off_heap` (exempting the **sending** context's own pid, so a self-send whose payload does not fit routes to the heap-fragment fallback rather than collecting the running process; a delivery to a *different* process is unaffected). The **scheduled slice is deliberately not wrapped**: the runner drives `run_export_outcome_with_tier`/`run_label_outcome_with_tier` directly, publishes parked roots, and its armed admission point (`gc.rs::ensure_heap`/`ensure_heap_full`) stays the legitimate collection site. Rationale: [`../DESIGN_DECISIONS.md`](../DESIGN_DECISIONS.md).
The two other nested-`Machine` sites in the crate are **deliberately outside** this pattern — `boot::drive::apply_boot_call` (`../boot/drive.rs`, a boot `{apply, …}` directive) and `native::file_server::EngineContinuation::call` (`../native/file_server/get_until.rs`, the io-device continuation) — and are safe *only* because each drives its machine on a `RuntimeContext::new` context (`mailbox_table == None`), which forces every allocation onto the pointer-stable arena (`gc.rs::alloc_words`'s `None` arm) and short-circuits `gc::ensure_heap_full` before any publish (`gc.rs`'s `None => return Ok(())`); their terms are therefore `Target::Foreign` and never moved, and a delivery to their pid is exempted as the **receiver** through the pass-boundary `deliver_in_table`. Neither calls `publish_parked_roots` at its `RunOutcome::Wait` park, so moving either onto a `for_process*` (process-table) context would make it a delivery-collect hole for a mid-run process.
`RuntimeContext::deliver_in_table(runtime, table, to, from, message) -> Result<()>` is the pass-boundary entry to the same `deliver_message` semantics for the runtime's own delivery steps (which hold `runtime` and `table` apart): it builds `RuntimeContext::for_process(runtime, table, to)` and delivers, so an exempt receiver's raw `Alloc(AllocKind::Message)` refusal routes to `send_fragmented_message`'s heap-fragment fallback instead of propagating. Its context's pid is the **receiver**, so `deliver_message` resolves the copy's source against the runtime's escaped-payload store alone (`send_source(None, …)` → `Runtime::off_heap_source`) — the constant `None` is what keeps the sender-family union off this path (a pass-boundary delivery has no sending machine, and pulling the *receiver's* retained families in would describe the wrong process). Used by `Runtime::service_file_requests` (`../native/file_server.rs`), `Runtime::deliver_port_messages` (`../port.rs`), `Runtime::fire_due_timers` (`../runtime/scheduler.rs`) and `Runtime::drain_ets_owner_exits` (`../runtime/ets_owner.rs`).
