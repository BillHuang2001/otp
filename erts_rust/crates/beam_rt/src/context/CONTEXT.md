# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heaps and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order, the nine bridge arms, the dispatch memo, the atom-interner discipline, caller-module tracking, the lent-`TableRegistry` propagation into a nested fun application, the in-machine execution-position door and the node's real `LOCAL_EXT` hash.
It is the **only** place the engine's seam meets the Stage-5 core, which keeps the Stage-1/Stage-5 dependency DAG acyclic; Rust forbids a second `impl ExecutionContext` (E0119), so the seam is **one** block in `execution.rs` whose every method delegates to an inherent helper in the sibling that owns the concern.
The nine `beam_engine::Mailbox` seam methods live in [`../mailbox.rs`](../mailbox.rs); the scheduler/runner that drives this glue in [`../runtime/`](../runtime/CONTEXT.md).
Children: [`calls/CONTEXT.md`](calls/CONTEXT.md) (dispatch · bridges · interners), [`gc/CONTEXT.md`](gc/CONTEXT.md) (heap doors · valves · off-heap prunes), [`pool/CONTEXT.md`](pool/CONTEXT.md) (the BIF-result copy-out and the term stores), [`pump/CONTEXT.md`](pump/CONTEXT.md) (the nested-run pump, the machine pool, host memory); mechanics in [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

## API Surface

### `RuntimeContext<'a>` — fields and constructors
A context is a **borrow-only** struct over `&'a mut Runtime` holding `output` (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`, `mailbox_table: Option<&'a mut ProcessTable>`, `may_pump_scheduler`, `current_module`, `engines`, `suspend_requested`, `gc_armed`, `dispatch_memo` and `lent_tables`.
It owns no heap at all, so dropping it frees only its inline `dispatch_memo` slots and the boxes a miss put in them.
Constructors/accessors: `new`, `with_output`, `heap_available()`, `for_process`/`for_process_with_engines` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `arm_gc`, `process_table`/`process_table_mut`, `owns_process_table`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`lent_tables` is set only by `FunBridge::nested`; `new`/`with_output`/`for_process` set it `None`.
`wants_reduce` returns `false` (the default `reduce` is a no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext`.

### `call_bif` — the dispatch order, and the precedence gotcha
`call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → `dispatch` (the memoized registry implementation + hook roster) → `call_registered` (the `beam_bifs` registry) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export`.
**The native floor runs *before* the registry** (a `beam_bifs` entry can never shadow a floor-served key) and the registry *before* the external-module load; a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`.
**No `ets:*` key is intercepted or re-implemented here**: `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the registry shadowed by nothing.
The one `ets` special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` through the same `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation.

### The BIF suspend channel (`beam_engine::BifOutcome`)
`call_bif_outcome`/`call_bif_in_machine_outcome` run the value-returning route first (`Err` propagated unchanged, never converted) and then fold the `suspend_requested` latch into `BifOutcome::Suspend`, which parks the engine on the **unapplied** BIF instruction and re-executes it on resume.
The latch is `take`n unconditionally, so no stale bit can leak into the next dispatch.
`suspend_requested` is a per-call **permission** bit like `gc_armed`: `false` at every construction site, armed by exactly **one** arm — the native floor's `erlang:port_command/2,3` on a busy port whose caller may not pump (`../port/busy_wait.rs::PortWrite::Parked`) — and never by the shared `send` route, which the inline `Instr::Send` also reaches.
The runner's `BudgetContext` forwards both doors (pricing only a `Return`); without that the scheduled path would fall back to the trait default and never suspend.

### The in-machine call and fun seams — `resolve_external_call` · `resolve_local_fun` · `resolve_local_call` · `host_serves`
`resolve_external_call` runs a `call_ext*` callee **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4` answers `{ok,pid}`, [`../../tests/proc_lib_start.rs`](../../tests/proc_lib_start.rs)) instead of folding into the uncatchable `error::blocked()`.
Its `Some((arc, label))` carries the **same** `Arc<Module>` the code server caches (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and the label *after* `func_info`; an unknown label is the typed `unknown_label`.
`Ok(None)` — keeping the synchronous path byte-for-byte — covers a floor-served name (key-granular `native::floor_shadows`; `io` is the one floor namespace owning only `io:put_chars/1,2`), a NIF-loaded module, a registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label; an uncached callee is loaded on demand.
`resolve_local_fun` enters a `make_fun3` local closure **and** a `NEW_FUN_EXT`-decoded one (`imported_fun_target`, on the C key `(module, index, arity, uniq[16])` with the `uniq` required to equal `Module::checksum()`, so a stale image never binds to a recompiled lambda) **in the calling machine**, so a blocking `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch` — what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend it.
**The fun-in-record indirection** (`served_local_key`) declines a named local fun whose descriptor names a host-served key, so `apply_non_local_fun` reaches the registered BIF — how `zlib.erl`'s record-held `fun deflate_nif/4` avoids its `erlang:nif_error(undef)` stub.
`resolve_local_call` is **not** `host_serves` — it answers two fixed `(name, arity)` key sets (`prim_tty`'s 20 stubs, `beam_bifs`' 19 `zlib` stream stubs), module-name-gated, so it reads no runtime state.
**`host_serves`/`host_serves_given` is the single "the host serves this MFA" predicate**; `host_serves_given` lets a caller spend the memo's `bif.is_some()` (that field *is* `BifRegistry::contains`) instead of a second lookup per `call_ext*`, and the NIF arm is module-granular, so a mid-run `load_nif/2` flips it — the one runtime-mutable input either seam has.
Full mechanics (both descriptor caches, `closure_target`'s load-bearing order, the `badfun`/`undefined_lambda` expansion, `callee_observes_its_call_site`'s module-wide vs per-function split, the `BudgetContext` forwarding of all three seams): [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

### The atom namespace and the one lifetime `Rc<AtomTable>` lease
`execution.rs`'s `atom_name`/`atoms` answer the runtime's **live** shared table, so guard/`select_val`/map-key comparisons order atoms by name instead of by raw index when a name is missing from a module's load-time snapshot.
**Never hold a `CodeServer::atoms_handle()` across an intern** — `atoms_mut()` is `Rc::make_mut`, so a clone held across an intern deep-clones the whole shared table and drops the copy.
Only one holder lives long enough to matter: a loaded NIF library's stored host (`../nif.rs`'s `NifEntry::host`, one per `erlang:load_nif/2`); a `{spawn_driver, Name}` port's host is a **depth-counted lease** opened only for the window in which driver code runs, so no intern can occur while it is held.
The transient borrow-workaround clones (`../eval/mod.rs`'s map builders, `../native/memory/mod.rs`'s `max_heap_size_map`, `../native/erts_internal.rs`'s `map`) each wrap a `make_map` that takes `&AtomTable` and cannot intern, and intern first, take the handle last.
`RuntimeContext` itself holds **no** atom handle.

### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity)` is the **only** producer of a registered call's dispatch answer: a direct-mapped per-context memo of `DISPATCH_MEMO_SLOTS = 128` inline `Option<Box<DispatchEntry>>` slots holding `{bif: Option<BifFn>, hooks: DispatchHooks}` — a fresh per-applied-fun context carries ~1 KiB of `None` slots and allocates a box only on a miss.
`hooks` is **one bit per `uses_*` predicate** packed into `DispatchHooks(u16)`, so the answer is 16 bytes and crosses its call boundaries in registers; `bif` is the registry lookup the caller invokes **directly**, and `call_registered` is reached only on `Some`.
The roster is the single source of truth: `of()` destructures an array of the same predicates **exhaustively** (adding or removing an arm fails to compile), and a `const _: ()` assertion proves the bits pairwise distinct against the `ANY_MASK` fold.
A cached answer can never go stale: the one mutable input, the **NIF registry**, is deliberately not memoized (`try_call_nif` runs first on every call); a one-entry MRU hint (`DispatchMemo::last`) answers only after the memo's own **full field-for-field key equality**.
The BIF-result gate `open_gate_for_foreign_result` is **shape-tested before the process-table probe** (`gc::result_may_be_foreign`), so an immediate result never reads the process. Slot hash, miss/collision rules and hit cost: [`calls/CONTEXT.md`](calls/CONTEXT.md), [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

### `call_registered` — the gated arms, the lent/held `TableRegistry`, and the nine bridges
Two paths: the hook-free arm, **99.91 %** of registered calls, builds exactly **one** `BifContext`, while every other case runs `#[cold] #[inline(never)] call_registered_full`'s ten-arm chain; both share one prologue and one tail (`finish_registered_call`), so inputs, copy-out, rewind and the intern commit cannot drift.
Every arm installs the cheap handles (`PendingInterner`, `RuntimePorts`, the `Copy` `NodeIdentity`) and then selects exactly **one** bridge, first-match, from the `DispatchHooks` the memo computed — each bridge owns a different runtime borrow, so they cannot co-exist.
The `TableRegistry` is the live `&mut` a `BifContext::call_fun` **lent** the bridge (exclusive by construction) or, failing that, the shared cell **held** when `install_tables = !reentrancy_capable(args) || tables_capable(module, function, arity)`; `try_borrow_mut` (never `borrow_mut`) is the rule, so an unexpected outer borrow degrades to "no ETS", never a panic.
The nine bridges (`DictBridge`, `ProcessBridge`, `NifBridge`, `RecordBridge`, `SendBridge`, `ModuleInfoBridge`, `PersistentTermBridge`, `RuntimeHooksBridge`, `FunBridge` — the fallback) each have a routing entry below; the `[safe]` export gate is the eleventh `DispatchHooks` entry, on its own arm for exactly `erlang:binary_to_term/2`, over `is_active_export OR registry.contains` (the disjunct exists because the code server holds only the 22 preloaded modules).
The record table has **two** consumers over the one lookup `records::loaded_record` — `RecordBridge`'s `RecordSource` (one key, `records:get_definition/2`) and `ExecutionContext::foreign_record_definition` (the native-record *instruction* path, which loads the owner and retries and returns `is_exported` **unfiltered**, since the engine applies the C's gate and raises `error:{badrecord, Id}`); `Recs` has no table of its own — it lives in each cached `Arc<Module>` and comes back through `Module::records()`/`record()`/`record_by_name()`.
Per-arm surface, `RuntimeHooksBridge`'s served/gap split (40 of the 140 keys) and the `lent` exclusivity argument: [`calls/CONTEXT.md`](calls/CONTEXT.md); the copy-out and rewind: [`pool/CONTEXT.md`](pool/CONTEXT.md).

### The in-machine execution-position door (`position.rs`) and the node hash (`node_hash.rs`)
`position.rs` serves `process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel` out of the `Machine` that owns the frame (via `beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine`), and the same published slot carries the `(addr, size, refc)` off-heap roster so `process_info(self(), binary)` lists the payload the running slice just built; everything else falls through to `call_bif`, so no frame is ever fabricated.
`node_hash.rs` answers the **one** per-OS-process `OnceLock<u32>` mixing a nanosecond clock reading, `hostname()` and the pid, hashed by a self-contained port of the C's Bob-Jenkins `block_hash`, so `term_to_binary(Term, [local])` stamps a real `LOCAL_EXT` (`121`) image instead of the typed gap. Mechanics: [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

### Send destinations — aliases (`alias.rs`) and the remote arm (`send.rs`, A.5)
A `send` destination that is an **internal reference** resolves as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives — **one helper, `alias_destination`, serves all three entry points**, classifying by **provenance first** through `Runtime::local_reference(to)`, so a bare `make_ref`/timer/`seq_trace` reference is never an alias and unknown provenance (a decoded copy) falls back to `MonitorRef::from_eterm`.
`classify_send_destination`/`SendDestination` (`Local`/`RemotePid`/`RemoteAlias`/`RemoteName`/`Port`/`Dropped`) is the **one** classifier behind all three routes (the compiled `Dest ! Msg`, the `-eval` `!` and `SendBridge::resolve`), and every reference mints from the **one** `beam_common::next_ref_id` space, so provenance adds the **kind** of reference, not its uniqueness.
**The remote alias arm** (`RemoteAlias { to }`) is a **distinct wire form** — `{DOP_ALIAS_SEND, From, To} -- Msg`, the peer looking the reference up in its own alias table rather than delivering to a process — which is what makes a remote `gen` call answerable; it sits **after** the live-local-alias and external-pid tests, needs the peer's `DFLAG_ALIAS`, and on a runtime with no node every reference keeps the typed `badarg`.
**`send_source` is the one place a delivery builds the copy's source off-heap table** — `send_message_with_off_heap` passes `Some(mailbox_pid)` (the full three-family union) and is the **one** definition of the dead-destination policy, `deliver_message` passes `None` (store-only), and `nif_send.rs`'s `deliver(...) -> bool` is the `enif_send` arm over a nested `RuntimeContext` with `may_pump_scheduler` always `false`. C arms reproduced: `send_altact_message`/`handle_altact_msg` (`bif.c`, `erl_proc_sig_queue.c`), `dist.c:2563`; mechanic detail: [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

### The receive-scan signal prefix (`execution.rs`)
`receive_next` applies the **receive-applicable prefix** of an exhausted scan's signal queue through the public `ProcessTable::service_receive_signals` and re-reads the scan — the C `i_loop_rec` fetch (`emu/msg_instrs.tab:80-112` → `erts_proc_sig_fetch`, `erl_proc_sig_queue.c:7729`) — so a process's own trapped `'EXIT'` and its own monitor `'DOWN'` need no extra scheduling round.
The drain is FIFO, discards an ignored exit, and stops before the first `Terminate` head, which (with everything behind it) stays the runner park arm's.

### GC accounting and the two off-heap prunes
`erlang:statistics(garbage_collection)` answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape — from the node-global counters on `Runtime::gc_stats()`, which count this runtime's own work since *its* start (the quantities match the oracle's, the magnitudes do not).
**The refc-binary reclamation** (`gc/bin_vheap.rs`) is the one reclamation point for off-heap payloads: a process's refc binaries live in `Machine::refc_binaries`, outside every heap the collector owns, so they are **pruned separately** at the slice boundary by `OffHeapReclaimer::reclaim(...)` (the C's `p->bin_vheap_sz` through `beam_gc::BinVheap`), whose release is `Machine::retain_refc_binaries` with `live(p) || shared(p)` — `live` from `beam_gc::for_each_reachable_binary_payload` over the process's roots, `shared` from `Refcount > 1`.
That release **moves nothing**, so no live on-heap `BinRef` is invalidated, and **every gate is a decline — a leak, never a dangle**; the bin-vheap budget gates the prune and can never cause one.
Two further entry points sweep the `-eval` route's escaped store (`Runtime::eval_off_heap`, a different store with different triggers): the tree-walker's depth-0 statement boundaries (`../eval/reclaim.rs`) and the nested-run epilogue (`adopt_nested_payloads`).
**The NIF-resource-term prune** (`gc/resources.rs`) drops the reference every resource term took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs exactly once; the walk matches a word **or** a reference identity, because a `copy_struct` copy is a different word with the same id.
Gates, per-slice cost, measured envelope and residuals: [`gc/CONTEXT.md`](gc/CONTEXT.md), [`../runner/CONTEXT.md`](../runner/CONTEXT.md), [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md); pinning suite [`../../tests/nif_resource_gc.rs`](../../tests/nif_resource_gc.rs).

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with one `#![allow(unsafe_code)]` per marked module and a `// SAFETY:` rationale at each site — this node's `gc.rs`, `gc_walk.rs`, `gc/bin_vheap.rs`, `gc/valve_bounds.rs`, `calls.rs` and `../eval/reclaim.rs` + `../eval/reclaim/resource.rs`, plus `../nif.rs` and `../malloc.rs`; the glue otherwise uses only the safe peripheries of the lower crates.
* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Never fabricate a value**: a seam answer is either real state or the typed gap — `NodeIdentity` reports the runtime's **live** creation (`Runtime::node_creation()`), and the node hash is a genuine per-process computation, never a constant.
* **A reclamation is an optimization, never a correctness lever**: every gate of the off-heap prune declines rather than guessing.
* **A lent `&mut TableRegistry` is exclusive by construction**; the shared cell is never consulted while one is lent, and `try_borrow_mut` (never `borrow_mut`) is the only way this node touches it.
* **Dispatch cost is first-class**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (an input that can change during a run — the NIF registry — must stay out).
  Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) ([`../../PERF.md`](../../PERF.md), [`../../PERF_DISPATCH.md`](../../PERF_DISPATCH.md)); `perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch.

### Term lifetime — the four rules this node's seams obey
**(a) A raw `Eterm` in a long-lived slot roots nothing.** Any term that can outlive one instruction must be copied onto a heap a collector scans, or explicitly stabilized (`Runtime::stabilize_term`/`stabilize_term_with` → the `eval_heap` store), before the owner's heap can be relocated.
**(b) A pointer-stable, never-scanned store is the wrong home for a container whose children live on a scanned young heap.** `beam_gc`'s copier relocates exactly the words in its *from* set and classifies every other address as `Target::Foreign`, leaving the reference verbatim **without descending** (`beam_gc/src/copy.rs:240`/`:280`), so the container survives un-moved while its young-heap children are relocated and it keeps stale words.
The **pointer-stable arena** (`Runtime::alloc_words`) is such a region: a **refusal-only** fallback and the home of a genuinely **table-less** context; any seam handing out a block must answer *"which heap, and does some collector scan it?"*, and the unscanned-root valve (`root_is_unscanned`) is that same fact read as an admission test.
**(c) Refuse ⇒ stabilize, never dangle.** When a heap growth/move is exempted, the fallback is to copy the graph onto the pointer-stable store, never to leave a word pointing at a region that may move or be freed; a `None` from the copy-out therefore means only a **permanent** refusal (malformed graph, unresolvable off-heap container, a store that could not be grown), and the result then stays on the never-rewound pooled BIF heap — **leak, never dangle**.
**(d) A lease (an `Rc` handle) held across an allocation is a deep-copy or a dangling hazard, never a cheap borrow** — see *The atom namespace* above for the one instance that matters.
Which seam allocates where (the four never-interchangeable regions, and `gc_armed` as a per-call **permission** bit rather than a "collection is due" flag): [`gc/CONTEXT.md`](gc/CONTEXT.md); the relocation-exemption windows and the truthful-fixed-answer roster: [`IMPLEMENTATION.md`](IMPLEMENTATION.md).

## Known Issues
Every entry is a typed capability gap, a measured own-state difference or a documented divergence — never a wrong result.
The heap-model ledger is [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md); call-path gaps are [`calls/CONTEXT.md`](calls/CONTEXT.md)'s, copy-out and `ets`-alias gaps [`pool/CONTEXT.md`](pool/CONTEXT.md)'s, heap-door and off-heap-prune gaps [`gc/CONTEXT.md`](gc/CONTEXT.md)'s and nested-run gaps [`pump/CONTEXT.md`](pump/CONTEXT.md)'s.

* **The "no collection can run while a BIF call is in flight" invariant is a conjunction of facts, not an enforced guard.** The BIF route reaches no `context/gc.rs` door (`BifContext` exposes only the pooled pointer-stable `Heap`), the latch is **unreadable** inside the dispatch and the machine is handed as `&self`; the argument copy is a stack array / `Machine::args_scratch` and `position.rs`'s five `Eterm`s ride the process's **scanned** young heap, so no term is unrooted.
  `Machine::pending_exception` **is** parked: `Machine::with_roots` parks the machine's loose heap terms (`LOOSE_HEAP_TERMS = 5`) at the tail of the Erlang stack and re-seats them from the slots the host wrote back — the funnel every in-slice collection door passes through — and across a park window it rides `Registers::extra_roots` first.
* **A park window is re-published by up to three sequential steps, and `serve_gc_request` relocates the process registers in between two of them.** The `Yield` arm runs `park_machine` → `Runtime::serve_gc_request` → `collect_at_reds_boundary` (which re-publishes `machine.with_roots(ALL_LIVE)`) → `reclaim_off_heap_binaries`.
  `serve_gc_request` gates on `is_relocation_exempt` only — **not** on `has_unpublished_roots` — so for a publishing window it can relocate `process.registers()` while the parked `Machine`'s `x`/`stack`/`fr` keep pre-relocation words, and its `bool` answer is discarded at all three call sites, so nothing re-syncs the machine.
  The doors' length contract is robust (`publish_roots_full` can only answer `false` from `x_mut().set_live`), so a **re-publish from a stale machine** is the mechanism, not a `false`.
* **`reaches_an_unscanned_word` seeds only the caller's `roots` iterable** (never `Walk::seed_process_roots`), so the prune-only valve's coverage is exactly the list `bin_vheap::reclaim` builds; under `Criterion::PayloadPrune` a pointer-bearing `WordRegion::Foreign` word is an immediate hit **unless it is a reference thing** (`is_inert_reference`), and it always descends.
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap** — no apply shape is in this class (every one enters in-machine now); only a fun or callee with no in-machine entry is — [`pump/CONTEXT.md`](pump/CONTEXT.md).
* **A fun-applying registry key is entered as the module's own code whenever the context cannot re-enter the scheduler, so the apply suspends the process.** The class is `beam_bifs::FUN_CALLER_BIFS` (24 keys, every one with a real Erlang body in this checkout) and `needs_fun_caller` is the single source of truth (evaluated once per key by `DispatchHooks::of` as the verdict-only `FUN_CALLER` bit), so the roster cannot drift; the two `ets` folds stay synchronous deliberately.
* **`erlang:fun_info/1,2`'s `name` item comes from two wiring sites here** — `bridges.rs::local_fun_identity` (the `FunT` entry's `function`, introspection-only so the `term_to_binary` bytes are unchanged) and `fun_identity.rs::imported_identity` (a decoded `NEW_FUN_EXT` fun's own `module` atom); an imported fun whose **defining module is not loaded** is the typed `unsupported_bif` gap where the oracle reports `{name,[]}`.
* **The `NEW_FUN_EXT` identity seam is installed on every encode path; which `Ok(None)` branches are LIVE decides where `unsupported_local_fun` (exit 3, reason `local_fun`) still bites** — (a) an `-eval` lambda (`EVAL_FUN_UNIQ` matches no loaded `FunT`; the recorded `wire/new_fun_ext_encode`), (b) a module loaded through `code:load_binary/3` (`insert_loaded` drops its path), (c) a module whose `.beam` was deleted after it loaded.
  Not fun-reachable: the `zlib` stash encoder, `crash_dump`/`persistent_term`/`seq_trace` (no encoder at all) and the NIF-created-thread host; the outbound `dist` payload rewrite and `beam_dist`'s control encoder build their `Encoder` with **no** fun identity, so a `make_fun3` fun addressed to a remote pid/name is a typed refusal where the oracle encodes it.
* **`ProcessBridge` reads real state; one typed gap and two documented divergences** — `erlang:ports/0`'s `try_borrow` gap is reachable only on a **nested** path (`call_registered` hands the arm a separate `Rc` clone), `register/2` with a **port id** is a typed gap, `process_flag(save_calls, V)` returns the previous value where the oracle raises `badarg`, and `process_flag(error_handler, Atom)` always answers `error_handler`.
  `process_flag(max_heap_size, Map|Int)` shares `spawn_opt`'s parser and stores per pid; the bound **is enforced** on the prospective post-collection capacity, drained at every collection/admission and at `serve_gc_request`, with one ERTS `=ERROR REPORT====` on stderr per killing breach before latching `Kill`.
  Residuals ([`../../tests/max_heap_enforce.rs`](../../tests/max_heap_enforce.rs)): stderr vs the oracle's stdout `logger` stream, 7 of the C's 9 fields, a kill at the next slice boundary, and an `-eval` verdict never drained.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles**, so a term the *running* machine just built off-heap and forwards from a BIF callee **flattens** (correct but unshared); only the compiled `Dest ! Msg` instruction carries them, and closing the BIF route needs a sibling change (`call_bif`/`SendHook::send` carry no handle parameter).
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives** — `beam_process` pre-tests `has_unpublished_roots()` and the host's `CollectionGate`, hands the raw refusal back with **no** collect/grow/retry; only an **exit** signal to a **non-trapping** receiver still surfaces it.
* **Reference aliases: the honest residuals** — a send to a reference that is **not** a live alias is the typed `badarg` (the C silently drops it), and reference **identity** stays unclosable.
* **The fun-applying debt gate is a scheduling-policy lever, not a correctness one** — it collapses the retired-nursery chain by entering the callee in the caller's armed machine, and covers neither a nested run entered while the caller owes no debt nor a fun-applying key outside the roster — [`pump/CONTEXT.md`](pump/CONTEXT.md).
* **The fun-image half of `callee_observes_its_call_site` is per-function**: it admits `compile:*` to the in-machine route on the **scheduled** path, and a signal-driven collection there is declined by the runner's **park-window relocation exemption**, with evidence owed to `beam_process`'s signal sites ([`../../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../../EPP_SCHEDULED_ROUTE_FINDINGS.md)).

## Test Strategy
Every suite here is colocated (`tests.rs` + `test_support.rs`, plus the per-concern siblings `calls/*.rs`, `gc/tests.rs`, `pool/tests.rs`, `pump/*.rs`) or an integration suite under [`../../tests/`](../../tests/CONTEXT.md); per-suite routing and evidence are per child node: [`calls/CONTEXT.md`](calls/CONTEXT.md), [`gc/CONTEXT.md`](gc/CONTEXT.md), [`pool/CONTEXT.md`](pool/CONTEXT.md), [`pump/CONTEXT.md`](pump/CONTEXT.md).
**No test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle.**
Hard-pinned here: the node hash (`block_hash_is_deterministic_and_genuinely_mixing`, `node_hash_is_stable_within_an_os_process`, `term_to_binary_local_is_a_real_image_end_to_end`, `a_local_image_is_stable_across_two_evaluations`, `a_local_image_round_trips_an_internal_pid`) — while `beam_bifs`' own `term_to_binary_local_is_a_typed_gap` (a context with **no** `LocalNode` hook) must stay green and unshadowed.
Reference-space provenance is four `alias.rs` cases: the fabrication guard (a `MonitorRef::from_id` reference carrying a live alias's id is the typed `badarg` on `resolve_send_target` **and** both send seams, while the id lookup still resolves it), a table-minted alias resolving while a plain monitor reference is rejected, `local_reference`'s four provenance arms, and runtime-space vs process-table mints never sharing an id — plus [`../../tests/reference_ids.rs`](../../tests/reference_ids.rs) and [`../../tests/ref_id_space.rs`](../../tests/ref_id_space.rs).
The remote alias arm is five `tests.rs` cases over a real `-name` node fixture that skips loudly when no listener can bind; the `NEW_FUN_EXT`-decoded closure is four `tests.rs` cases over one `erlc`-gated `dfun` fixture, `../../tests/decoded_fun_badfun.rs` pins the badfun/undef matrix on both tiers, and the fun-applying seam's matrix is `pump/fun_apply_matrix.rs`; the `erlc` front-end regression is [`../../tests/erlc_emulator.rs`](../../tests/erlc_emulator.rs).
Per-module units live beside their arm (`process_bridge.rs`, `module_info.rs`, `persistent_term.rs`, `memory_hook.rs`, `../nif.rs`); integration suites are `proc_seams.rs`, `module_info.rs`, `persistent_term.rs`, `nif.rs`, `driver.rs`, the two trace suites, `pid_roundtrip.rs`, the process-control family and `position.rs`.
Crate gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --lib --no-fail-fast`; the boot-drive/CLI suites are wall-clock sensitive (`DRIVE_DEADLINE`) and can fail on a heavily loaded host — re-run before calling a failure a regression.

## Notes for Agents
* **Layout: `mod.rs` is root-only plumbing** — module `//!` overview + submodule map, `mod …;` declarations, crate-visible re-exports, `#[cfg(test)]` name plumbing; no logic.
  Siblings past the ~1000-line target (`runtime_hooks.rs`, `calls.rs`, `gc.rs`, `pump.rs`, `bridges.rs`) are one cohesive pre-existing concern each, documented at their own top; `tests.rs` is the node's shared unit suite, `calls/tests.rs` the colocated suite for `calls.rs`.
* **Every nested cross-module run reuses a recycled `Machine` from `machine_pool.rs` and never touches `jit::cache`.** Entry is `Machine::run_export_outcome`/`run_label_outcome` → the tier-free `run_loop`/`run_loop_with_map` → `Machine::drive`; **no `Tier` is passed anywhere on this path**, so a nested callee never runs on the default baseline JIT and `BEAM_RT_TIER` does not change its tier; `jit::cache::remember_module` has **no production caller**. The module handle is the code server's cached `Arc<Module>`, never a per-call `Module` clone — [`pump/CONTEXT.md`](pump/CONTEXT.md).
* **Both nested waits sit out a finite answer themselves**: `run_export_blocking`/`run_label_blocking` drive a suspended callee through `pump_until_returned` under `BLOCKING_PUMP_DEADLINE` (900 s), and `pump_once` hands a wait that a live port's own asynchronous operation will answer to `wait_for_port_event` under `crate::port::PORT_EVENT_DEADLINE` (5 s of consecutive no-progress rounds) — the wait arms and consumes nothing — [`pump/CONTEXT.md`](pump/CONTEXT.md), [`../port/CONTEXT.md`](../port/CONTEXT.md) *The nested port wait*.
* **Which door fires is a route fact.** The **top-level** `-eval` context is table-less (`mailbox_table: None`, `gc_armed: false`), so `heap_available`/`alloc_words` answer the never-reclaimed `Runtime::arena` and the in-slice doors do not run; every **nested** run executes under `for_process`, so it allocates from the pid's real young heap and its doors do run.
  A nested run therefore takes the **in-machine seam, not `run_export`**: a plain `call_ext` between interpreted modules goes `interpreter/dispatch.rs`'s `resolve_external_entry` → `resolve_external_call`, and `run_export` is reached only from a declined call, a top-level entry or a fun application, so its `current_module` `String` allocation is not a per-`call_ext` cost.
* **Closure application is entered in-machine through `resolve_local_fun` when the engine drives the context directly**; the `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes.
* **Measure per-call cost in retired instructions, never wall clock, and pin a P-core** — the two-point ablation estimator, the per-line sibling attribution and every lever measured-and-rejected are [`../../PERF_DISPATCH.md`](../../PERF_DISPATCH.md)'s, so read it before re-deriving anything; use `BEAM_RT_PERF_COUNTERS=1` over a known key mix, and price the **hit** path (the memo answers ~99 % of calls). Nothing on this path allocates per term: `BifContext` is a stack value, `take_bif_frontier`'s inlined arm is a `Vec::pop`, `RuntimePorts::new` is an `Rc::clone`, and the copy-out is what re-homes a container onto a scanned heap.
* **Startup and run-level measurement discipline** (the two-build wall-clock floor, marginal estimators, instruction-vs-wall): [`../../STARTUP_COST.md`](../../STARTUP_COST.md), [`../../PERF.md`](../../PERF.md).
