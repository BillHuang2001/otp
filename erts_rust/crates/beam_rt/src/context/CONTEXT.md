# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → dispatch memo → `call_registered` → external-module load), the nine bridge arms, the dispatch memo (`dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), caller-module tracking, the **lent-`TableRegistry` propagation into a nested fun application**, the **in-machine execution-position door** (`position.rs`) and the node's real `LOCAL_EXT` hash (`node_hash.rs`).
The nine `beam_engine::Mailbox` seam methods live in [`../mailbox.rs`](../mailbox.rs); the scheduler/runner that drives this glue in [`../runtime/`](../runtime/CONTEXT.md).
Mechanics-level companion: [`IMPLEMENTATION.md`](IMPLEMENTATION.md) — the root-set/relocation seams, the at-risk roster, the execution-position door, the per-call cost and the closable host-seam roster.
The three subsystem children carry the rest: [`calls/CONTEXT.md`](calls/CONTEXT.md) (dispatch · bridges · interners), [`gc/CONTEXT.md`](gc/CONTEXT.md) (heap doors · valves · off-heap prunes) and [`pool/CONTEXT.md`](pool/CONTEXT.md) (the BIF-result copy-out and the term stores).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module`, `engines`, `gc_armed`, `dispatch_memo` and `lent_tables`.
Its methods: `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`lent_tables` is set only by `FunBridge::nested`; `new`/`with_output`/`for_process` set it `None`.
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`calls.rs`'s `call_bif_routed`).
`wants_reduce` returns `false` (the default `reduce` is a no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext`.
**No `ets:*` key is intercepted or re-implemented in `beam_rt`**: `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the `beam_bifs` registry shadowed by nothing.
The one `ets`-family special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` through the **same** `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation (`runtime::ets_owner::adopt_created_table`).
**`resolve_external_call` — the in-machine cross-module call seam.** `RuntimeContext` overrides it so a `call_ext*` callee runs **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4`/`start_link/4` answer `{ok,pid}`, [`../../tests/proc_lib_start.rs`](../../tests/proc_lib_start.rs)) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It loads an uncached callee on demand (`find_module_file` + `code_server.load`) and returns `Ok(None)` (keeping the synchronous `call_bif` path byte-for-byte) for a floor-served name (`native::floor_shadows`, **key-granular**: `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label.
`callee_observes_its_call_site` is **module-wide** for `erlang:load_nif/2` and **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, which must stay synchronous so the function cannot park with an unpublished `Machine::pending_exception`.
The seam **exempts a built-in NIF library** (`crate::native::prim_tty::is_builtin_library`, A.7's `prim_*` family) from the module-wide verdict: it registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the `blocked()` gap.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure (`module` = the **same** `Arc<Module>` the code server caches; `label` = the lambda's `FunT` entry label).
A fun with no local closure goes to `external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`) has no closure but its identity *is* the callee's `M:F/A`, so it resolves to that module's export label through the cross-module seam's **own** `resolve_external_call`, under the same refusals; `Ok(None)` remains for the fun kinds with no in-machine entry (the `-eval` closure `EVAL_FUN_UNIQ`, a **served** local stub key — see below — and any external fun the resolver refuses), keeping the value-returning `apply_fun` fallback byte-identical.
**The fun-in-record indirection (`served_local_key`, `apply.rs`).** A **named local** `fun` (`fun deflate_nif/4`, a `FunKind::Local` term with `num_free == 0`) whose descriptor names a function this host **serves** as a local-call key (`beam_bifs::serves_local_call`, the same predicate `resolve_local_call` consults) is declined by `local_fun_target` and dispatched by `apply_non_local_fun` through `call_bif`, so the wrapper's record-held fun reaches the registered BIF rather than its `erlang:nif_error(undef)` stub — that is what makes OTP's `zlib` stream API (`erts/preloaded/src/zlib.erl:414-425` stores `fun deflate_nif/4` in `#zlib_opts{}`, applied from `dequeue_next_chunk/2`) work end to end. The declining path stays allocation-free: a `num_free` test, two `O(1)` reads of the defining module's **own** atom table and the predicate's module-name equality, no registry/hash lookup. An applied-arity mismatch is the bare `BadArity`, never a dispatch with a wrong frame.
The engine consults the seam **first**: on `Some` it places the closure's free variables in `x(arity..)` (C's order — flagged as a possible `gen_server` init mis-entry, see *Notes for Agents*) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch`.
Entering an external fun in the calling process (as C's `call_fun` does) is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`).
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context`, and `reset` — not `resume_outcome` — clears contexts; a fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier`.
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap: both allocation seams meet a **capacity** refusal of the bump with the no-relocation `Process::grow_nursery` and a retried bump (and only then fall back), while the unrooted `alloc_words` is handed no root set and **never collects**.
`alloc_words_rooted` additionally collects over the machine's handed-in root set when the retried bump still fails or a forced request bypassed it.
The engine's doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect and grow the nursery to fit an oversized request (`Process::ensure_capacity`, when `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to `Process::collect()`) — see *Known Issues* for the arena fallback and its soundness valve.
**Registry precedence (gotcha).** The native floor runs *before* the registry (a `beam_bifs` entry can never shadow a floor-served key) and the registry *before* the external-module load; a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`.
### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity)` is the **only** producer of a registered call's dispatch answer: a direct-mapped 8-slot per-context memo of `{bif: Option<BifFn>, hooks: DispatchHooks}`, where `hooks` is **one boolean per `uses_*` predicate** (the eight mutually-exclusive bridge-arm selectors plus the `fun_identity`/`memory_hook`/`export_gate` build gates) and `bif` is the `BifRegistry` lookup the caller then invokes **directly** (no second lookup); `call_registered` is reached only on `Some`.
A cached answer can never go stale: the one mutable input, the **NIF registry**, is deliberately not memoized (`call_bif` runs `try_call_nif` first on every call).
Slot hash, the miss/collision rules, hit/miss cost, pooled BIF heap and `PendingInterner`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-dispatch-memo--dispatchhooks).
### In-machine execution-position door (`position.rs`)
`position.rs` serves a process's execution-position items (`process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel`) out of the `Machine` that owns its frame, through `beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine` seam; the same published window carries the machine's off-heap roster (`(addr, size, refc)` triples) so `process_info(self(), binary)` lists the payload the running slice just built, read only when the query names `binary`.
Everything else — another pid, a nested query, a pid-less argument, an unsourced name — falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated.
Mechanics and the root-set window: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-in-machine-execution-position-door--positionrs).

### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One helper serves **all three** entry points — `alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying by **provenance first** through `Runtime::local_reference(to)`: a monitor/alias reference `Some(Some(_))` is looked up via `table.resolve_alias`, a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias, and unknown provenance `None` (a decoded or received copy) falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`.
* the BIF route (`erlang:send/2`, `'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery;
* the compiled `Dest ! Msg` route — `resolve_send_destination` (inherent, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteAlias`/`RemoteName`) and `deliver_remote` transmits it over the connection the runtime is a node on, and a **port** destination (`SendDestination::Port`) whose write is `deliver_to_port`; `resolve_send_target` is a `#[cfg(test)]`-only local wrapper.
Both producers are handles onto **one** monotone process-wide id space (`beam_common::next_ref_id`; `Runtime::refs` for `make_ref`/timers/`seq_trace`, the `ProcessTable`'s allocator for monitors/aliases), so no id is ever issued twice and provenance adds the **kind** of reference, not its uniqueness; the typed-`badarg`-vs-silent-drop divergence and the provenance bridge are in the module docs and the crate `Known Issues`.
C arm reproduced: `send_altact_message` (`bif.c`) + `handle_altact_msg` (`erl_proc_sig_queue.c`).
### The remote alias send arm (`send.rs` · contract A.5)
An **external reference** whose node slot names a node other than `Runtime::local_node()` classifies as `SendDestination::RemoteAlias { to }` (`remote_alias_destination`), and `deliver_remote` transmits it as `Runtime::dist_send_alias` → `{DOP_ALIAS_SEND, From, To} -- Msg` (`dist.c:2563`).
It is a **distinct wire form**, not a `DOP_SEND`: the peer must look the reference up in its own alias table instead of delivering to a process, which is why the control message's `To` is the reference term itself.
It is what makes a **remote `gen` call** answerable: `gen:reply/2` (`../lib/stdlib/src/gen.erl:549-556`) replies to the alias reference the caller put in `From` (`{CallerPid, [alias | MonitorRef]}`), so without this arm such a call could never receive its reply.
The arm sits **after** the live-local-alias test and the external-pid test, so a live alias on this node still classifies as `Local { reference: Some(..) }` and an external pid still classifies as `RemotePid`.
A reference naming **this** node that is not a live alias keeps its `Err(BeamError::BadArg)`, and on a runtime with no node (`dist_client()` is `None`) every reference keeps that same `badarg`, so a non-distributed runtime's observable behaviour is unchanged.
The peer's `DFLAG_ALIAS` is required (a link without it is the typed `did not negotiate DFLAG_ALIAS` error), while a reference naming no live alias **on the peer** is the peer's own silent drop — the oracle's measured behaviour (OTP 29.1.1 returns the message and delivers nothing), not ours.
### `call_registered` — the gated dispatch arms, the lent/held `TableRegistry`
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook — and then selects exactly **one** bridge, first-match, from the `DispatchHooks` the caller's `dispatch` memo computed, because each bridge owns a different runtime borrow and they cannot co-exist.
The `TableRegistry` comes from the live `&mut` a `BifContext::call_fun` **lent** the bridge (installed for every nested call, exclusive by construction) or, failing that, from the shared cell **held** exactly when `install_tables = !reentrancy_capable(args) || tables_capable(module, function, arity)`; `try_borrow_mut` (never `borrow_mut`) is the rule, so an unexpected outer borrow degrades to "no ETS", never a panic.
The result's copy-out and rewind are [`pool/CONTEXT.md`](pool/CONTEXT.md)'s; the per-arm detail, the `lent` exclusivity argument and the arm roster: [`calls/CONTEXT.md`](calls/CONTEXT.md).
### The nine bridges
Exactly **one** bridge is selected, first-match, from `DispatchHooks`: `DictBridge` (`DictHook`), `ProcessBridge` (`ProcessHook`), `NifBridge` (`NifLoader`), `RecordBridge` (`RecordSource`), `SendBridge` (`SendHook`), `ModuleInfoBridge` (`ModuleInfo`; `erlang:get_module_info/1,2` from the loaded module's IR), `PersistentTermBridge` (`PersistentTerm`), `RuntimeHooksBridge` (`RuntimeHooks`; 40 of the 143-key `RUNTIME_HOOKS_BIFS` roster served, the other 103 answering the typed `unsupported: <module>:<function>/<arity>`) and `FunBridge` (`FunCaller`; the fallback), with the `[safe]` export gate as the eleventh `DispatchHooks` entry.
Per-arm API surface: [`calls/CONTEXT.md`](calls/CONTEXT.md).
### The `[safe]` export gate — `export_gate.rs` (the 16th `BifContext` seam)
`ExportGateBridge` implements `beam_codec::ExportGate`; its `is_export_active(m,f,a)` is the shared `runtime_hooks.rs::is_active_export` helper **OR** `registry.contains(m,f,a)` — the registry disjunct exists because this runtime's code server holds only the 22 preloaded modules.
It runs on its own mutually-exclusive arm for exactly `erlang:binary_to_term/2` (`beam_bifs::EXPORT_GATE_BIFS`); the flag-free form never consults it.
Evidence: [`../../tests/safe_binary_to_term.rs`](../../tests/safe_binary_to_term.rs); detail [`calls/CONTEXT.md`](calls/CONTEXT.md).
### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's node-global cumulative counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran and `reclaimed` (in words) is advanced by each collection site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`: the quantities match the oracle's, the magnitudes do not.
Detail: [`gc/CONTEXT.md`](gc/CONTEXT.md).

### The off-heap refc-binary reclamation — `gc/bin_vheap.rs`
A process's off-heap refc binaries live in the machine's reservoir (`Machine::refc_binaries`), outside every heap the collector owns, so a collection can never sweep them: they are **pruned separately** at the slice boundary by `OffHeapReclaimer::reclaim` (`reclaim(runtime, table, pid, machine, slot)`), the C's `p->bin_vheap_sz` through `beam_gc::BinVheap`.
`triggered()` is the C's `off_heap.overhead > bin_vheap_sz` (strictly greater); `record_collection` reproduces the C's `p->bin_vheap_sz = next_vheap_size(...)` / `MSO(p).overhead = bin_vheap` pair from the payload that survived.
The release is `Machine::retain_refc_binaries` with `live(p) || shared(p)`, where `live` is `beam_gc::for_each_reachable_binary_payload` over the process's roots and `shared` is every payload at `RefcBinary::refcount() > 1`; it **moves nothing**, so no live on-heap `BinRef` is invalidated.
**Every gate is a decline** — a leak, never a dangle: the pid is not in the caller's table; `Process::is_relocation_exempt()`; `!Runtime::gc_process_enabled(pid)`; the bin vheap has not triggered; the collection valve `valve_verdict` declines; the prune-only valve `gc_walk.rs::reaches_an_unscanned_word` declines; or the reachability walk returns a typed error.
Two further entry points sweep the `-eval` route's escaped store (`Runtime::eval_off_heap`, a different store with different triggers): the tree-walker's depth-0 statement boundaries (`../eval/reclaim.rs`) and the nested-run epilogue (`RuntimeContext::adopt_nested_payloads`).
Gates, per-slice cost, measured envelope and the residuals: [`gc/CONTEXT.md`](gc/CONTEXT.md), [`../runner/CONTEXT.md`](../runner/CONTEXT.md) *The off-heap refc-binary reclamation at the slice boundary* and [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md).
### The NIF-resource-term prune (A.3) — `gc/resources.rs`
`reclaim(runtime, table, pid)` is the caller half of `beam_abi`'s resource-release seam: it drops the reference every resource **term** took at `enif_make_resource` once nothing reachable from the process's complete root set names it, so the resource type's destructor runs exactly once.
The scheduled site is the runner's `Yield` park arm; the routes that never park are served by the two non-park sites in `../eval/reclaim/resource.rs`; the reachability walk matches a word **or** a reference identity, because a `copy_struct` copy is a different word with the same id.
Detail, gates and the residual list: [`gc/CONTEXT.md`](gc/CONTEXT.md); the pinning suite is [`../../tests/nif_resource_gc.rs`](../../tests/nif_resource_gc.rs).
### The node hash (A.2) — `node_hash.rs`
`NodeIdentity`'s `LocalNode::local_node_hash` answers the **one** per-OS-process `OnceLock<u32>` mixing a nanosecond clock reading, `hostname()` and the pid, hashed by a self-contained port of the C's Bob-Jenkins `block_hash`, so `term_to_binary(Term, [local])` stamps a real `LOCAL_EXT` (`121`) image instead of the typed gap.
Mechanics: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-node-hash-a2--node_hashrs).

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with two narrowly-scoped exceptions (`gc_walk.rs`'s `beam_term::layout` object-walk; `../nif.rs`'s `enif_compare`/`enif_hash` `unsafe extern "C"` calls); the glue otherwise uses only the safe peripheries of the lower crates.
* **Return-based errors, no silent swallowing** ([`../../../CONTEXT.md`](../../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Never fabricate a value**: a seam answer is either real state or the typed gap — `NodeIdentity` reports the runtime's **live** creation (`Runtime::node_creation()`), and the node hash is a genuine per-process computation, never a constant.
* **A reclamation is an optimization, never a correctness lever**: every gate of the off-heap prune declines rather than guessing, so its residual is a leak — never a payload freed while a live `BinRef` still names it.
* **A lent `&mut TableRegistry` is exclusive by construction**; the shared cell is never consulted while one is lent, and `try_borrow_mut` (never `borrow_mut`) is the only way this node touches it.
* **Dispatch cost is first-class**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (an input that can change during a run — the NIF registry — must stay out).
  Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) (figures in [`../../PERF.md`](../../PERF.md)); `../../examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch.
## Known Issues
Every entry here is a typed capability gap, a measured own-state difference or a documented divergence — never a wrong result.
The GC/heap-model ledger is [`../../M1_GAPS_GC.md`](../../M1_GAPS_GC.md), the call-path gaps are [`calls/CONTEXT.md`](calls/CONTEXT.md)'s, the copy-out and `ets`-alias gaps are [`pool/CONTEXT.md`](pool/CONTEXT.md)'s and the heap-door/off-heap-prune gaps are [`gc/CONTEXT.md`](gc/CONTEXT.md)'s.

* **The "no collection can run while a BIF call is in flight" invariant is a conjunction of facts, not an enforced guard** — the BIF route (`call_bif` → `try_call_nif` → `try_native` → dispatch memo → `call_registered`) reaches no `context/gc.rs` door (`BifContext` exposes only the pooled pointer-stable `Heap`), and `gc_armed` is `take`n at each door's first statement (`execution.rs:472,486,510`), armed only by `BudgetContext` immediately before a forward.
  Both halves are structural: the latch is **unreadable** inside the dispatch (`call_registered`'s destructure discards it) and the machine is handed as `&self`, so no arm can consult it and the engine cannot mutate the register file mid-call.
  Two term holders ride that window with **no root set covering them**: the marshalled argument copy (a `[Eterm; 2]` stack array / `Machine::args_scratch`) and `InMachinePosition`'s five `Eterm`s published in `Runtime::in_machine` (`position.rs`), which `alloc_words` places on the process's **scanned young heap**; the roster `off_heap_binaries` beside them is plain `(usize, usize, usize)` data, so it holds no term and needs no root set.
  `Machine::pending_exception` is a third, deliberately **not** parked by `with_roots` and rooted explicitly only in the park window via `Registers::extra_roots` (`runner/run.rs:527-540`); the copy-out is **not** a collection site (`calls.rs:964-1006`: `grow_nursery` + one retry), and the one in-call collection that exists — a delivery's `Process::deliver` on the receiver — is refused for the running process by the sender/receiver relocation exemption (`send.rs:352-502`).
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap** — the call goes `call_bif` → `run_export_blocking` (a fresh `Machine` on the same pid under a `for_process*` context, so `may_pump_scheduler()` is `false`) and `pump_once` returns `Ok(None)` on its first line, folding the parked callee into the uncatchable `beam_engine::blocked()` whether or not its `receive` carries an `after T`.
* **`erlang:fun_info/1,2` reads the `LocalFunIdentity` seam, and its `name` item comes from two wiring sites here.** `bridges.rs::local_fun_identity` attaches the `FunT` entry's `function` to the derived `FunIdentity` for a compiled `make_fun3` fun (`with_function`; introspection-only, so the `term_to_binary` bytes are unchanged); `fun_identity.rs::imported_identity` resolves a decoded `NEW_FUN_EXT` fun's `name` from the loaded module named by its own `module` atom.
  Residual: an imported fun whose **defining module is not loaded** is the typed `unsupported_bif` gap where the oracle reports `{name,[]}` (C `mfa == NULL ⇒ NIL`) — never a fabricated name; pinned by `an_imported_funs_unloaded_defining_module_is_the_typed_gap_not_an_empty_name`.
* **The fun-image half of `callee_observes_its_call_site` is per-function** (see *API Surface*): it admits `compile:*` to the in-machine route on the **scheduled** path; a signal-driven collection there is declined by the runner's **park-window relocation exemption**, with the evidence owed to `beam_process`'s signal sites ([`../../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../../EPP_SCHEDULED_ROUTE_FINDINGS.md)).
* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly; the `erlang:ports/0` typed gap (a `try_borrow` failure) is reachable only on a **nested** path, because `call_registered` hands the arm a **separate `Rc` clone** of the port registry, so production `ports/0` works.
  `register/2` with a **port id** is a typed gap (the table registers pids only), `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg`, and `process_flag(error_handler, Atom)` always answers `error_handler`.
  `process_flag(max_heap_size, Map|Int)` parses through the **same** parser as `spawn_opt`'s option (`native/process.rs::max_heap_setting`) and stores the setting per pid in `Runtime::max_heap`; the `badarg` matrix, the previous-value answer in the C's key order and the **caller-only** scope are oracle-pinned by `tests/max_heap_flag.rs`. The bound **is enforced** on the **prospective post-collection capacity**: the verdict is drained at every collection/admission and at `serve_gc_request` (`gc.rs::drain_max_heap_verdict`, an ERTS `=ERROR REPORT====` on stderr once per killing breach) before latching `Kill`, which `runner/run.rs::take_max_heap_kill` turns into `RunOutcome::Exit(<bare atom killed>)`. Residuals (`tests/max_heap_enforce.rs`): stderr vs the oracle's stdout `logger` stream, 7 of the C's 9 fields, a kill at the next slice boundary, and an `-eval` verdict never drained — `M1_GAPS_GC.md` *Heap switches*.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles**, so a term the *running* machine just built off-heap and forwards from a BIF callee **flattens** (a correct but unshared copy); only the compiled `Dest ! Msg` instruction carries them.
  `send_source` unions the three families a *delivery* can resolve (`extra`, the runtime's escaped-payload store, the sender's mailbox-retained families) but the BIF route passes `extra = &[]` (the in-flight `Machine` is out of `RunnerState.engines` for the whole slice, and neither `ExecutionContext::call_bif` nor `SendHook::send` carries a handle parameter); closing it needs a sibling change in `beam_engine`/`beam_bifs`.
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives** — `beam_process`'s `copy_reason_onto`/`enqueue_down_signal`/`enqueue_exit_signal` pre-test `has_unpublished_roots()` and the host's `CollectionGate`, hand the raw `Alloc` refusal back with **no** collect, grow or retry, and turn the `{'DOWN',…}`/`{'EXIT',…}` into a fresh `HeapFragment`.
  The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*); pinned by [`../../tests/eval_exempt_receiver_signal.rs`](../../tests/eval_exempt_receiver_signal.rs).
## Test Strategy
The suites' routing, the per-suite evidence and the measurement harnesses are per child node: [`calls/CONTEXT.md`](calls/CONTEXT.md) (dispatch, bridges, interners), [`gc/CONTEXT.md`](gc/CONTEXT.md) (heap doors, valves, off-heap prunes) and [`pool/CONTEXT.md`](pool/CONTEXT.md) (copy-out, `ets` aliasing).
Every suite here is colocated (`tests.rs` + `test_support.rs`) or an integration suite under [`../../tests/`](../../tests/CONTEXT.md); no test compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle.

* **The node hash**: `block_hash_is_deterministic_and_genuinely_mixing`, `node_hash_is_stable_within_an_os_process`, `term_to_binary_local_is_a_real_image_end_to_end`, `a_local_image_is_stable_across_two_evaluations` and `a_local_image_round_trips_an_internal_pid`.
  `beam_bifs`' own `term_to_binary_local_is_a_typed_gap` (a context with **no** `LocalNode` hook) stays green and must not be shadowed.
* **Reference-space provenance + the one-id-space invariant** (`alias.rs`, four cases): the mandatory guard (a bare reference **fabricated** through `MonitorRef::from_id` to carry a live alias's id is the typed `badarg` on `resolve_send_target` **and** both `send` seams, while the id-based lookup still resolves it — a local mint can no longer produce such a pair), a table-minted alias resolving while a plain monitor reference is rejected, `local_reference`'s four provenance arms, and the positive invariant that mints from the runtime's ref space and from the process table never share an id (so they are never `=:=`), an equal-id pair being reachable only by fabrication.
  The integration companion [`../../tests/reference_ids.rs`](../../tests/reference_ids.rs) drives every public mint route × the consumer paths the oracle can answer, and [`../../tests/ref_id_space.rs`](../../tests/ref_id_space.rs) proves the three real producers (NIF resources, the process table, the runtime's own space) draw from one monotone source.
* **The remote alias arm** (`tests.rs`, five cases over a real `-name` node fixture that skips loudly when no listener can bind): `a_remote_reference_classifies_as_a_remote_alias` (an external reference for `peer@localhost` ⇒ `RemoteAlias` carrying the term verbatim, and nothing delivered locally), `an_external_pid_still_classifies_as_a_remote_pid` (an external pid keeps the earlier arm), `a_reference_on_this_node_that_is_not_a_live_alias_is_badarg` (the local-node rule survives on a node, on all three send entry points), `a_live_local_alias_still_classifies_as_a_local_delivery` (`Local { reference: Some(..) }` — the new arm shadows nothing) and `a_remote_reference_on_a_non_distributed_runtime_is_still_badarg` (`dist_client()` is `None` ⇒ the unchanged `badarg`).
* Per-module units in `process_bridge.rs`, `module_info.rs`, `persistent_term.rs`, `memory_hook.rs` and `../nif.rs`: the `ProcessHook` methods over a real `Runtime` (incl. the already-borrowed `ports` registry ⇒ typed gap), the `ModuleInfo` item decode, the persistent-term semantics, the `MemoryHook`'s nine keys in oracle order, and the `NifHostImpl` hooks.
* Integration suites (routed in [`../../tests/`](../../tests/CONTEXT.md)): `proc_seams.rs`, `module_info.rs`, `persistent_term.rs`, `nif.rs`, `driver.rs`, the two trace suites, `pid_roundtrip.rs`, the process-control family and `position.rs` (the execution-position door's oracle comparison), each driven through `-eval` and cross-checked against the live oracle.
* **The A.9 in-process-compile sweep** (`pump.rs`'s `#[ignore]`d `every_stdlib_source_compiles_in_process_like_the_oracle`) enumerates every `lib/stdlib/src/*.erl` from the filesystem, gives each source a fresh boot-script-driven runtime and compiles it through the `-eval` route, pinning the **set**, the **count** and the **bytes** against the oracle's own compilable set; `BEAM_RT_SWEEP_SHARD=i/n` shards the corpus across parallel runs (a malformed value is a loud failure), and the sweep body runs on a 32 MiB stack (`SWEEP_STACK_BYTES`) with its panic payload re-raised via `std::panic::resume_unwind`.
  The measured set/count and the oracle-side `-I` limit: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-a9-in-process-compile-sweep).
* Run the crate gate `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt --lib --no-fail-fast`.
  The boot-drive/CLI suites are wall-clock sensitive (`DRIVE_DEADLINE`) and can fail on a heavily loaded host — re-run before calling a failure a regression.
## Notes for Agents
- **Layout: `mod.rs` is root-only plumbing over concern-scoped submodules** (module `//!` overview + submodule map, `mod …;` declarations, crate-visible re-exports, `#[cfg(test)]`-gated name plumbing; no logic).
  Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs`, its methods delegating to inherent helpers in the sibling that owns the concern.
  Five siblings exceed the ~1000-line target — `runtime_hooks.rs`, `calls.rs`, `gc.rs`, `pump.rs`, `bridges.rs` — each one cohesive pre-existing concern documented at its own top; `tests.rs` is the node's shared unit suite and `calls/tests.rs` the colocated suite for `calls.rs`, and the names `tests.rs`/`pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]` (`DispatchMemo` alone stays ungated).
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned` driver, capped by `BLOCKING_PUMP_DEADLINE` (900 s) — the nested counterpart of the boot drive's `DRIVE_DEADLINE`; the wait policy and the rejected forward-progress alternative: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-nested-blocking-pump-and-its-bounds).
- **Closure application is entered in-machine through the `resolve_local_fun` seam for a context the engine drives directly**; the engine's `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper**, which forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process enters in-machine and is resumed by a real send, and a same-module local `call` the host serves is dispatched through `call_bif` instead of being jumped into the module's non-exported Erlang stub body.
  Pinned by [`../../tests/scheduled_apply_seam.rs`](../../tests/scheduled_apply_seam.rs); the A.9 case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle.
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it, so it needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` passes `Some(self.mailbox_pid)` (the full three-family union); `deliver_message` passes `None` (store-only), because its context is built `for_process` the **receiver** and `None` keeps the empty-source fast path, so a plain on-heap message still builds no table.
- **Per-call cost is a first-class concern of this node** — the dispatch prologue's hit/miss costs, the two Θ-shaped codec costs, the copy-out/rewind shape and the BIFs that never reach `call_bif`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#per-call-cost-of-a-registered-call).
