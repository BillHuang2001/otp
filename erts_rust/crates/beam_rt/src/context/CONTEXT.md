# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → the dispatch memo → `call_registered` → external-module load), the nine bridge arms, the per-context dispatch memo (`RuntimeContext::dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), the caller-module tracking and the **in-machine execution-position door** (`position.rs`).
The nine `beam_engine::Mailbox` seam methods live one level up in [`../mailbox.rs`](../mailbox.rs); the runtime-level scheduler/runner that drives this glue lives in [`../runtime/`](../runtime/CONTEXT.md).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module` and `engines`; methods `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`calls.rs`'s `call_bif_routed`).
`RuntimeContext::wants_reduce` returns `false` (the default `reduce` is the no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext` (`src/runner/budget.rs`).
**No `ets:*` key is intercepted or re-implemented in `beam_rt`.** `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the `beam_bifs` `ets` registry (`crates/beam_bifs/src/ets.rs`) shadowed by nothing; the one `ets`-family special case is *bookkeeping, not interception* — `call_bif` routes `ets:new/2` through the **same** `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation (`runtime::ets_owner::adopt_created_table`).
**`resolve_external_call` — the in-machine cross-module call seam.** `RuntimeContext` overrides it so a `call_ext*` callee runs **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4`/`start_link/4` answer `{ok,pid}`, `../tests/proc_lib_start.rs`) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It performs `find_module_file` + `code_server.load` **on demand** for an uncached callee, and returns `Ok(None)` (preserving the synchronous `call_bif` path byte-for-byte) for a floor-served name (`native::floor_shadows`, **key-granular** — `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site (`callee_observes_its_call_site` — **module-wide** for `erlang:load_nif/2`, **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, kept synchronous so the function cannot park with an unpublished `Machine::pending_exception`), a foreign/unknown export and an unknown label.
The seam **exempts a built-in NIF library** (`crate::native::prim_tty::is_builtin_library`, A.7's `prim_*` family) from the module-wide verdict: it registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the `blocked()` gap.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `RuntimeContext::local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure (`module` = the **same** `Arc<Module>` the code server caches; `label` = the lambda's `FunT` entry label).
A fun with no local closure goes to `RuntimeContext::external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`, `EXPORT_EXT`) has no closure but its identity *is* the callee's `M:F/A`, so it resolves to that module's export label through the cross-module seam's **own** `resolve_external_call`, admitted under exactly the same refusals; `Ok(None)` therefore remains for the fun kinds with no in-machine entry — the `-eval` closure (`EVAL_FUN_UNIQ`) and any external fun the resolver refuses — keeping the value-returning `apply_fun` fallback byte-identical.
The engine consults the seam **first** in `call_fun`/`call_fun2`: on `Some` it places the closure's free variables in `x(arity..)` (C's order) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch`; entering an external fun in the calling process (as C's `call_fun` does) is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`) instead of folding into the nested run's `blocked()` gap ([`../boot/CONTEXT.md`](../boot/CONTEXT.md)).
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context`, and `reset` — not `resume_outcome` — clears contexts; a fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier` (`../tests/fun_entry_receive.rs`).
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap: `alloc_words_rooted` collects over the machine's handed-in root set on a bump failure, the unrooted `alloc_words` is handed no root set and **never collects**, and the engine's doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect and grow the nursery to fit an oversized request (`Process::ensure_capacity`, when `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to `Process::collect()`) — see *Known Issues* for the arena fallback and its soundness valve.
**Registry precedence (gotcha for new `beam_bifs` registrations).** The native floor runs *before* the registry (so a `beam_bifs` entry can never shadow a floor-served key) and the registry runs *before* the external-module load (so a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`).

### In-machine execution-position door (`position.rs`)
A process's execution-position items — `erlang:process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel` — are read out of the [`Machine`](beam_engine::Machine) that owns its frame (see `../native/memory`).
The scheduler **takes the executing process's machine out** of [`RunnerState`](crate::runner::RunnerState) for the whole slice, so the runner-state view that answers *every other* pid cannot see the caller's own machine — the case `gen_server:handle_common_reply/5`'s `?STACKTRACE()` macro needs, i.e. a `gen_server` reaching a `terminate/2`.
`beam_engine`'s defaulted [`ExecutionContext::wants_bif_in_machine`]/[`call_bif_in_machine`] seam (funnelled through `Machine::dispatch_bif_call` on **both** tiers) hands an opted-in host the live `&Machine` and the run's entry module on every BIF dispatch; `position.rs` is that opt-in, deliberately narrow: `in_machine_probe` answers `true` (the engine latches it **once per run**) and `dispatch_in_machine` rejects every dispatch that is not an `erlang:process_info/1,2` with a single string compare.
**Only** for such a query whose first argument **is the executing process** (`pid == self.pid()`) does it read the five machine-sourced values once (`machine_position`, against the run's entry module) and publish them in the runtime-owned slot `Runtime::in_machine` for the duration of the nested `call_bif`, clearing it immediately after; `../native/memory`'s `position_value`/`catchlevel_value` consult that slot first via `in_machine_value` (the published terms need no root set — no collection can run while a BIF call is in flight — so the window is exactly one nested `call_bif`).
Everything else — another pid, a nested query while an outer door call is in flight, a pid-less first argument, a name the machine does not source, a machine with no such position — falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated.
Both overrides live in `execution.rs`; the runner's `BudgetContext` carries them onto the **scheduled** path ([`../runner/CONTEXT.md`](../runner/CONTEXT.md)).

### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One shared helper serves **all three** entry points — `alias.rs::alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying the destination by **provenance first** through `Runtime::local_reference(to)`: a monitor/alias reference `Some(Some(_))` is the only shape looked up via `table.resolve_alias`; a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias; unknown provenance `None` (a decoded or received copy) falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`.
* the BIF route (`erlang:send/2`, `erlang:'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery;
* the compiled `Dest ! Msg` route — `RuntimeContext::resolve_send_destination` (an inherent method, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` (`../lib/stdlib/src/gen_server.erl:549-553`) compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteName`) and `RuntimeContext::deliver_remote` transmits it over the connection the runtime is a node on; the local-only `RuntimeContext::resolve_send_target` is a `#[cfg(test)]` wrapper beside it.
C arm reproduced: `send_altact_message` (`../../erts/emulator/beam/bif.c:2478-2492`) + `handle_altact_msg` (`../../erts/emulator/beam/erl_proc_sig_queue.c:6009-6112`).
The two reference id spaces are **bridged, not unified** (`Runtime::refs` for `make_ref/0`/timers/`seq_trace`; the `ProcessTable`'s own allocator for monitors/aliases); the typed-`badarg`-vs-silent-drop divergence and the reference-**identity** hazard are in the module docs and the crate `Known Issues`.

### `call_registered` — nine dispatch arms, the gated seam handles, the port provider
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook.
The shared `TableRegistry` is installed by an explicit rule:
```rust
let reentrant = Self::reentrancy_capable(args);          // an argument is a fun (unchanged)
let install_tables = !reentrant || Self::tables_capable(module, function, arity);
let mut tables = if install_tables { tables_handle.try_borrow_mut().ok() } else { None };
```
`reentrancy_capable` is **unchanged** and keeps its own, separate meaning: it is what gates the result rewind (`call_registered`'s `safe_to_rewind`, `false` for the six heap-retaining arms and for any reentrant call).
So a plain call installs the cell, and a **reentrant call that does not read the `TableRegistry` seam installs nothing**, leaving the `RefCell` free for the fun it applies to re-enter and reach `ets:*`.
`Self::tables_capable(module, function, arity)` (`dispatch.rs`) names the seam's consumers, derived from `beam_bifs` (read-only; `src/ets*.rs`): **every registered `ets:*` verb** (each resolves its handle through `resolve_handle`/`take_table_gated`, all reading `ctx.tables()`) plus the two `erts_internal` raw-walk aliases `ets_raw_first/1`/`ets_raw_next/2` (the C's aliases of `ets:first/1`/`ets:next/2`, delegating into that same family).
Intersected with the fun-argument predicate this yields exactly the two fun-folds `ets:foldl/3`/`ets:foldr/3` — which take the table out of the registry before applying the fun, so they must hold the cell or `ctx.tables()` is `None` and they raise the typed `unsupported_bif`.
Every other reentrant call (`lists:map/2`, …) still installs nothing, so a fun it applies can re-enter and reach `ets:*`.
Exactly **one** bridge is then selected, first-match, from the `DispatchHooks` the caller's `dispatch` memo computed — one boolean per `uses_*` predicate, so no predicate runs per call:
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1`; a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — `whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_flag/2`, `group_leader/0` (`process_info/1,2` is intercepted by the floor first) over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>`; the per-process `erlang:group_leader/2` and `erts_internal:group_leader/2,3` are served by the floor.
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised.
  Its long-lived host is built with `services = None` (it is moved into the runtime's `NifRegistry`) and `crate::info::schedulers_count(runtime)` as its `scheduler_threads`, so a `load`/`unload` callback's `system_info` stays honest and every `NifHostServices` hook stays the typed default there.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; unloaded module / undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`erlang:'!'/2` delegating to `RuntimeContext::send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered; a **reference alias** destination goes to the alias **owner**).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR.
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store (a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow), keeping raw `Eterm` words (safe while the heaps stay pointer-stable; a value that must survive a heap move is stabilized through `Runtime::try_stabilize_escaped`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`; `runtime_hooks.rs`) — partly serves the **172**-key roster `beam_bifs::RUNTIME_HOOKS_BIFS`: the timer family (`start_timer/3,4` delivering `{timeout,TRef,Msg}`; `send_after/4`, also the `{abs,true}` form; `cancel_timer/2`), `function_exported/3` (the **`erts_is_builtin` half** — the declared `bif.tab` surface plus the `erlang`-namespace registry extras — OR the loaded module's export table), `link/1`/`unlink/1` (the `ProcessTable` link set; a **remote** pid routes through `link_term`/`unlink_term` to the installed `DistSignalRouter`, the only gap being a peer with no established link), `os:set_signal/2`, `net_kernel:dflag_unicode_io/1`, `erts_internal:scheduler_wall_time/1` (arms/disarms the node-global sampling switch, answering the **previous** state; drives no sampling, so `statistics(scheduler_wall_time)` stays `undefined`), `erts_internal:erase_persistent_terms/0` and `erlang:statistics/1` (`run_queue`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io`; the remaining valid keys are a typed gap).
  Its other served keys are **fixed oracle-absent answers**, catalogued per key under *Truthful fixed answers*.
  Every other roster key (incl. `read_timer/1,2`) is the typed `unsupported_bif` gap (closable ones under *Closable host-seam keys*) or is served **earlier** by the native floor (`alias/0,1`/`unalias/1`, the four `erl_ddll` keys); a key outside the roster is bare `error::undef`. It holds `&mut Runtime` **plus** a `&mut ProcessTable`, so it is its own arm; `timeout` is a `boot::CORE_ATOMS` seed (the shared table is borrowed immutably for the whole call).
* **`FunBridge`** (`FunCaller`; the fallback) — `RuntimeContext::apply_fun` over `&mut Runtime`, carrying a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`, and **no** `TableRegistry`.
`NodeIdentity` answers this runtime's **own** node — `Runtime::local_node()` (the live `node@host` atom on a `-name`/`-sname` node, else `nonode@nohost`), creation `0` — emitting `NEW_PID_EXT` (`88`) for an internal pid and `V4_PORT_EXT` (`120`) for an internal port; the **decode** direction installs the same identity (`Decoder::with_local_node`) and demotes a local-node `NEW_PID_EXT`/`V4_PORT_EXT` to the internal id, so `binary_to_term(term_to_binary(self())) =:= self()`.
`FunIdentityBridge` supplies the identity a **compiled module's** fun hands to the `LocalFunIdentity` seam, on the `uses_fun_identity` arm (`erlang:term_to_binary/1,2`, `erlang:external_size/1,2` and the introspection pair `erlang:fun_info/1,2`). For a `make_fun3` (`FunKind::Local`) argument it derives the `NEW_FUN_EXT` (`112`) image from the code server's **cached** loaded-module snapshot (`CodeServer::fun_module_snapshot`, scanned **caller-first**) plus the node atom — `Ok(None)`, never an error, for a context with no calling module (the `-eval` evaluator), an unreadable `.beam`, or a fun no loaded module defines; otherwise module atom + module MD5 + `old_index`/`old_uniq` from `FunT` + the `FunT` entry's `function` (the `name` item) + the fixed `<0.0.0>` creator (`bridges.rs::local_fun_identity`/`module_md5`). An `External` (`EXPORT_EXT`) fun and a non-fun are the clean `Ok(None)`; a decoded `Imported` (`NEW_FUN_EXT`) fun resolves only its `name` (see the `fun_identity.rs` routing entry).
`RuntimeMemory` (the `MemoryHook`) is built only on the `uses_memory_hook` arm (`erlang:memory/0,1`); ungated its `code_bytes` snapshot (a `CodeServer::loaded()` clone+sort plus a `std::fs::metadata` per module) would cost ~13 µs on **every** registered call.

### The pooled BIF-heap frontier — `take_bif_frontier`
Both pool-consuming call sites (`call_registered`, `try_call_nif`) take their allocation frontier through `RuntimeContext::take_bif_frontier` (`calls.rs`) rather than `Runtime::take_bif_heap` directly.
The pool is shared, so the region it hands back may be **nearly exhausted** — `available() < capacity() / BIF_HEAP_GROWTH_DIVISOR` (16). That is reachable on the **table-less** route (the `-eval` evaluator and every single-pass nested run): with no scheduled process, `move_result_into_process_heap` answers `None`, so a container result is never copied off the pool and the pool is never rewound — every container a BIF builds stays on the region it was built on for the run's whole life, whose bump pointer would otherwise march to the fixed capacity and hand the next call `AllocKind::Heap` (`error:system_limit`) for a reason unrelated to any live set.
Growth is by **region replacement** — never relocation, never a retry: the exhausted region is pushed back (`Runtime::put_bif_heap`) and a fresh, larger one becomes this call's frontier *before* the BIF runs. A `beam_alloc::Heap` never moves its terms and is never freed here, so every word a caller still owns stays valid at its own address, and no BIF is re-invoked and no side effect repeated. The new capacity is the old capacity doubled (`saturating_mul(2)`), floored at `Runtime::bif_heap_words` and capped by a configured `+hmax` (`Runtime::config().heap_options().policy().max_heap_words`; `0` = no cap). Where the cap leaves no room (`computed <= capacity()`) the region is returned as it is, so an explicit `+hmax` still yields the same `error:system_limit`.
`call_registered` reads its per-call `mark = heap.used()` **after** the helper (a freshly grown region starts at 0); a nested call may be handed a region an outer call retired — the same check applies there, and the `mark = used()` rule still keeps a rewind from recycling words another caller owns.

### The dispatch memo · `DispatchHooks`
`RuntimeContext::dispatch(module, function, arity) -> DispatchAnswer` is the **only** producer of a registered call's dispatch answer; its result is memoized in a per-context **direct-mapped 8-slot** memo (`DispatchMemo`; the slot from `dispatch_slot` over the key's **name bytes** and the arity).
`DispatchAnswer` is `{ bif: Option<BifFn>, hooks: DispatchHooks }`: `bif` is `Runtime::registry.lookup(module, function, arity)` — the implementation the caller then **invokes directly** (no second lookup); `contains` **is** `lookup(…).is_some()` (`crates/beam_bifs/src/registry.rs:189`, pinned equal by that crate's `contains_always_agrees_with_lookup`), so `call_registered` is reached only when `lookup` answered `Some`.
`hooks` is one boolean per `uses_*` predicate — the eight mutually-exclusive arm selectors plus the two build gates (`fun_identity`, `memory_hook`) — computed by `DispatchHooks::of`, the **only** place the `binary_search`es over `beam_bifs`' `&'static` `needs_*` rosters run; `call_registered` selects its arm and its two optional handles from `hooks.*` instead of re-running the predicates.
A **miss** computes and stores the answer; a **slot collision** overwrites, and the evicted key recomputes on its next call — an eviction costs work, never a result.
`dispatch_slot` hashes the key's **bytes** (FNV-1a over `module`, a `0xFF` separator, `function`, then the arity) and avalanches the result with a fixed multiply (high bits), so same-length keys span distinct slots (`ets:insert/2` and `ets:lookup/2` do not collide); the constant is **chosen**, not derived, so the crate's measured hot key set (`lists:reverse/1`, `erlang:length/1`, `ets:insert/2`, `ets:lookup/2`, the `erlang` arithmetic rows) occupies distinct slots.
Eight slots is the binding limit: more than eight hot keys still collide somewhere, and a collision costs the whole prologue (`registry.lookup` + the ten `needs_*` `binary_search`es + two `String` allocations) on every miss — never a wrong answer; enlarging the table means changing the churn assertion in `src/context/tests.rs` (`PERF.md` *DISPATCH-CUT*).
**Why a cached answer can never go stale.** Both inputs are immutable for the life of the runtime: `beam_bifs`' `needs_*` rosters are `&'static` tables with pure membership predicates, and `Runtime::registry` is an `Rc<BifRegistry>` built once at boot (nothing here calls `Rc::make_mut`/`Rc::get_mut` on it); the one **runtime-mutable** input — the NIF registry `erlang:load_nif/2` grows — is deliberately **not** memoized, since `call_bif` runs `try_call_nif` first on **every** call, so a library loaded mid-slice wins immediately (`../../tests/nif.rs` pins it).
The memo lives on the `RuntimeContext`, so it is exactly as long-lived as one run: a nested run (`FunBridge`/`SendBridge`) builds a fresh context with an empty memo.
**Two further prologue costs are gone.** (a) The **second registry lookup** — `call_bif_routed` hands the already-resolved `BifFn` to `call_registered`, and `invoke_registered` reproduces `BifRegistry::call`'s arity check so the error path is unchanged.
(b) The **NIF probe** — `try_call_nif` short-circuits on `NifRegistry::is_empty()`, so an empty registry costs one `RefCell` borrow and a length compare instead of a third `HashMap<String,_>` SipHash pass.

### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` keeps its `{base, names}` state **inline** (`InternerState::Inline(RefCell<…>)`) and allocates only when `PendingInterner::share` promotes it into a shared `Rc<RefCell<…>>`: `new(base)` roots it at the shared table's length, `commit` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers).
The ordinary registered/NIF call has a **single** writer, so it never shares and allocates nothing; `load_nif/2`'s two writers (the BIF, the C `load` callback via `enif_make_atom`) call `share()` and get two handles over one cell, so both agree on `base + <names recorded>` and the caller's single `commit` lands every name at its predicted index; `share` is the only way to obtain a second handle (`PendingInterner` implements no public `Clone`).
`run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess).
`call_registered` does **not** clone the caller's module for every call: only the NIF-loading, `send` and fun-caller arms (which need an owned `String`) clone it.
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable pooled BIF heap and the per-call `PendingInterner` is committed **after the registry borrow is released**.
`NifCallError::Raised(reason)` → `error::nif_raised`; `UnknownFunction` → bare `error::undef`; a miss is `Ok(None)`.
The per-call host gets a `crate::nif::RuntimeNifServices` provider built from **disjoint** field borrows of the runtime (`refs`/`references`/`processes`/`ports`; `processes` is the caller's mailbox table on a scheduler slice), so the host's `make_ref`/`whereis_pid` hooks **and** its `is_port_alive`/`port_command` port hooks (a `try_borrow` ⇒ the typed "cannot answer" `None` on a live borrow) are live; the registry `Rc` is cloned and the heap taken **before** those borrows, so the call itself never borrows `self.runtime`.
**Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif`.

Every other roster key reaches the fallback arm and returns a typed `unsupported_bif`.

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with two narrowly-scoped `#[allow(unsafe_code)]` exceptions (`gc_walk.rs`'s `beam_term::layout` object-walk; `../nif.rs`'s `enif_compare`/`enif_hash` `unsafe extern "C"` calls). The glue otherwise uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Dispatch cost is a first-class concern**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (any input that can change during a run — the NIF registry — must stay out). Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) (figures in [`../../PERF.md`](../../PERF.md)); `../../examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch ([`../../TRACE_AND_PERF.md`](../../TRACE_AND_PERF.md)).

## Known Issues
* **The float guard lives on the narrow door alone; the full doors are FR-safe.** The engine
  reaches only [`ensure_heap_full`](gc.rs) (`Machine::ensure_heap`/`test_heap`/`allocate_heap` →
  `ExecutionContext::ensure_heap_full` → `BudgetContext::ensure_heap_full` → `arm_gc`), which
  publishes and scatters the machine's **whole** [`RootSet`] — every x slot, the whole stack and
  the whole FR file (`fr_count = roots.fr.len()`) — so a live float register is relocated like any
  other root and [`ensure_heap_full`](gc.rs) and [`alloc_words_rooted`](gc.rs) consult **no**
  caller-module float test at all. A float-using call site therefore collects exactly like a
  float-free one. The **narrow** [`ensure_heap`](gc.rs) is handed only an x prefix and the stack
  and can never see the FR file, so its caller-module guard ([`module_may_be_collected`](gc.rs) →
  [`module_uses_floats`](gc.rs), matching `Instr::{Fmove,Fconv,Fadd,Fsub,Fmul,Fdiv,Fnegate}` and
  reached by a float literal `fmove {float,K} {fr,N}`) is load-bearing there and stays — the narrow
  door is not on the engine's path today. All four doors still refuse a run with **no** caller
  module (a fun entry, the `-eval` evaluator): no machine to name, left alone rather than guessed.
* **Both heap-admission doors OR the occupancy test with the collector's collection debt.**
  [`Process::grow_nursery`] is the no-relocation growth seam: it retires the young space it
  replaces instead of freeing it, so a growth-shaped workload keeps its whole allocation history
  resident in the retired chain until a real collection evacuates it. The doors therefore read
  `let debt = process.collection_debt();` and collect when `forced || process.should_collect(need)
  || debt`. [`Process::should_collect`] stays the **occupancy test alone** (pinned as such by its
  own unit tests); the debt is the growth seam's separate signal.
* **Residual blocker (out of this node): the runner's post-slice float pin — not this node's valve — is what stops a float-using loop.**
  A slice that ends with a live FR slot (`Machine::fr_mark() > 0`) calls `Runtime::pin_process`
  *permanently* (`src/runner/run.rs:586-589`), and `Runtime::gc_process_enabled` answers `false`
  for a pinned/halted pid — checked **first** by both doors, which then early-return with
  `take_gc_request` and collect **nothing** (which is why a pinned pid's `collections` never move,
  and why no `fallbacks` is counted: only `alloc_words`/`alloc_words_rooted` call `note_gc_fallback`).
  This node's unscanned-root valve does **not** decline a float root: this engine's FR model holds
  *terms* built on the executing process's own young heap ([`alloc_words`](gc) → `beam_term::thing::write_float`),
  so `fr[0]` is a **scanned** root (`root_is_unscanned` false; pinned by
  `tests.rs::a_live_float_term_in_fr_is_a_scanned_root`).
  Measured (fixtures compiled into `$TMPDIR`; the deterministic rig
  `tests.rs::the_post_slice_float_pin_plateaus_a_float_using_loops_collections`): a float-free
  `ets_copy` allocate-and-abandon loop's `collections` **scale** with N (5 000→40 000: 1 666→13 333,
  `pinned 0`); a payload float **literal** folds into the **literal area**
  (`{move,{literal,#{…3.5…}},{x,0}}`), so it adds **no** float-family instruction, never writes FR,
  and behaves exactly like the float-free twin (1 666→13 333, `pinned 0`) — "any module with a float
  literal writes FR slot 0" is **false**; only genuine float *operations* (`fconv`/`fmul`) do. A
  genuinely float-using loop (`float(X) * 3.5`) is `pinned 1` and its `collections` **plateau**
  (0→0 across the same 8× step; the committed `gc_floats:l1/1` fixture plateaus at 102→102), and its
  peak RSS grows with N (+75.6 MiB from N=20 000 to 100 000) while the two float-free twins stay flat
  (±0.6 MiB). Closing it needs a `src/runner/**` change (a per-slice `fr_mark` high-water handling
  that publishes/scatters the live FR prefix each slice instead of a sticky `pin_process`) —
  escalated, not papered over here.
  The same evidence also corrects the older wording: the pin is armed at the end of *every* slice, so
  a float-using loop need not collect "inside its first slice" — when slice 1 itself arms no
  collection the whole run's `collections` is exactly `0` (`gcab_flt`).
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap.** A cross-module call the engine cannot enter in-machine goes through `call_bif` → `run_export` → `run_export_blocking` (a fresh `Machine` on the same pid under a `for_process*` context, so `may_pump_scheduler()` is `false`) and `pump_once` returns `Ok(None)` **on its first line**, folding the parked callee into `beam_engine::blocked()` (an uncatchable capability gap) whether or not its `receive` carries an `after T` — the refusal is per `callee_observes_its_call_site`. Nothing here is a wrong result.
* **`erlang:fun_info/1,2` reads the `LocalFunIdentity` seam, and its `name` item comes from two wiring sites here.** `bridges.rs::local_fun_identity` attaches the `FunT` entry's `function` to the `FunIdentity` it derives for a compiled `make_fun3` fun (`with_function`; introspection-only, so the `term_to_binary` bytes are unchanged); `fun_identity.rs::imported_identity` resolves a decoded `NEW_FUN_EXT` fun's `name` from the loaded module named by the term's own `module` atom, requiring `descriptor_position(module, old_uniq, index) == Some(old_index)`. Both reachable only on the `uses_fun_identity` arm, which `dispatch.rs::reads_fun_identity_for_introspection` extends to the `erlang:fun_info/1,2` pair (`beam_bifs`' `LOCAL_FUN_IDENTITY_BIFS` roster names only the two encoders).
  The one residual: an imported fun whose **defining module is not loaded** (`descriptor_position` finds no matching module) is the typed `unsupported_bif` gap, where the oracle reports `{name,[]}` (C `mfa == NULL ⇒ NIL`, `erl_bif_info.c:4007-4010`) — the seam has no `NIL` to hand over. Pinned by `fun_identity.rs`'s `an_imported_funs_unloaded_defining_module_is_the_typed_gap_not_an_empty_name`; never a fabricated name.
* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** It is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it; `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (`beam_process`'s `gather_roots`/`scatter_roots` relocate it in place) and `RuntimeContext::resync_parked_roots` reads the relocated word back into `Machine::pending_exception_mut()` and clears the extra roots, so a delivery-driven receiver-heap collection in the park window relocates the reason with the heap.
* **The fun-image half of `callee_observes_its_call_site` is per-function.** With `erlang:term_to_binary/1,2`/`erlang:external_size/1,2` guarded only in the function that issues the call (`erlang:load_nif/2` stays module-wide), `compile:*` is admitted to the in-machine route on the **scheduled** path, and both A.9 `selfhost/*` corpus cases (`in_process_compile_file_no_spawn_deterministic`, `scheduled_process_compile_file_deterministic`) agree with the oracle on both tiers.
  A signal-driven collection on that path is declined by the runner's **park-window relocation exemption** (the delivery takes the ordinary heap-fragment fallback); evidence and the decline predicate owed to `beam_process`'s signal sites: [`../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../EPP_SCHEDULED_ROUTE_FINDINGS.md).
* **Nested ETS inside `ets:foldl/3`/`ets:foldr/3`'s own fun is the typed `unsupported_bif`.** The fold resolves the table out of the registry before it applies the fun, so the outer call holds the registry's `RefCell` for its whole duration; a *nested* `ets:*` the fun performs then fails its `try_borrow_mut` and answers `unsupported: bif` (exit 3).
  Not a regression — without the cell the outer fold failed outright with the same message, and no differential-corpus case uses `ets:foldl/3`/`ets:foldr/3`.
  Closing it needs `BifContext::with_tables`/`ctx.tables()` to lend the *shared cell* (`Rc<RefCell<TableRegistry>>`) rather than a bare `&mut TableRegistry`, so the fold's registry borrow ends before the fun runs — a `../beam_bifs/` change (handed off), not expressible in this crate (which forbids `unsafe`).
* **The arena fallback is kept sound by a two-phase unscanned-root valve.** An arena block is a container in a region the collector does not scan, so the valve **declines** (`Ok(())`) any collection whose root set — or whose process-side scanned graph — reaches one, at each of the four collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the runner's park arm `Runtime::serve_gc_request`); the fallback count is `note_gc_fallback`'s.
  The valve is **two-phase** (`context/gc.rs::root_is_unscanned` + `gc_walk.rs`): the per-word phase (always run) calls a term safe exactly when it is an **immediate**, a **literal** or a pointer the process's collector **scans** (any nursery space, current or growth-retired, or the mature generation); the descent over the process's scanned graph and root containers runs only under the sticky per-pid latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found.
  A term in a foreign region (the pooled BIF heap, the arena, the `-eval` heap, a message fragment) therefore declines the collection — **except** a registered-BIF result, which `call_registered` copies onto the running process's heap and rewinds the pool to the call's own `mark` (`Heap::reset_to`), making it a scanned root rather than a foreign holder (`calls.rs`; a small-`test_heap` loop still does not *reach* a collection — `PERF.md` *COPY-OUT-CUT*).
* **A module-literal root no longer declines the collection: `beam_loader` load-time tags the literal area.** `payload/0` is a constant, so `erlc` folds it into the **literal area** (`{move,{literal,#{…}},{x,0}}`), and the loop's only live root `x(0)` at the `test_heap,3,1` after `ets:lookup/2` IS that literal pointer.
  `beam_loader`'s `LiteralArea::decode` (`../beam_loader/src/literal.rs:124`) calls `beam_term::literal::tag_literal_area` — the safe form of the C load-time `erts_set_literal_tag` (`erts/emulator/beam/erl_term.c`) — before publishing the arena, so every boxed/list word a module's `LitT` chunk lowers to, and the literal roots the engine is handed, carry `TAG_LITERAL_PTR` **set**.
  [`gc.rs`'s `root_is_unscanned`](gc.rs) classifies a literal by the C's own `erts_is_literal` rule — a bare bit test ([`gc.rs:233`](gc.rs) → `beam_term/src/literal.rs:41`) — so a **tagged** literal is an immutable, never-moved region the collector does not scan and the valve **passes**: the constant-payload loop (the `copy_bound/ets_copy` shape) reaches its heap-admission points and its `collections` scale with N.
  The untagged-decline path survives only as a **unit construct**: `tests.rs::an_untagged_literal_root_declines_the_collection_until_the_loader_tags_literals` builds an arena the tagging step never touched and asserts `collections == 0`; its companion `tests.rs::a_tagged_literal_root_is_scanned_and_the_loop_collects` (`:6750`) pins the load-time-tagged behaviour.
  Tagging also removes a shared-literal corruption hazard: an untagged literal is silently **writable** (`beam_engine/src/terms/update.rs:67` refuses an in-place tuple write only when `is_literal` holds; `beam_ets/src/store/mod.rs:158` reads the same bit).
* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path.** `RuntimeMemory::new` (`memory_hook.rs`) sums each live process's collector capacity (nursery + mature) for `processes` and its used words for `processes_used`, so the scheduled path counts both generations; the `-eval`/single-pass path has no `Process` (it allocates on `Runtime::arena`, whose private `Arena` exposes no byte/word accessor), so both are an honest `0`; making that half real needs a new `MinimalContext` arena-words accessor plumbed through `Runtime` (owner: `beam_engine`).
* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly (`process_bridge.rs:176-343`); the `erlang:ports/0` typed gap (`:213-220`, a `try_borrow` failure) is reachable only on a **nested** path, because `call_registered` hands the arm a **separate `Rc` clone** of the port registry, so production `erlang:ports/0` works; and two unit-pinned divergences exist — `register/2` with a **port id** is a typed gap (`:184-189`; the table registers pids only) and `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg` (`:302-322`), while `process_flag(error_handler, Atom)` always answers `error_handler` (`:323-331`).
* **`NodeIdentity` carries this runtime's live node atom but a hard-coded creation `0`.** The atom comes from `Runtime::local_node()`, so `node/0` and a pid's `NEW_PID_EXT` image name a `-name`/`-sname` node correctly; the `epmd`-assigned creation is not carried.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles.** `send_source(Some(self.mailbox_pid), extra)` unions the three families a *delivery* can resolve (`extra`, the runtime's escaped-payload store and the sender's mailbox-retained families, `Runtime::source_payloads`), but the BIF route reaches it with `extra = &[]`: the in-flight `Machine` is out of `RunnerState.engines` for the whole slice (`runner/run.rs:169`) and neither `ExecutionContext::call_bif` nor `SendHook::send` carries a handle parameter (`../beam_engine/src/context.rs:304`, `../beam_bifs/src/context.rs:146,164`).
  So a term the *running* machine just built with an off-heap payload and forwards from a BIF callee **flattens** (a correct but unshared copy); only the compiled `Dest ! Msg` instruction's `send_message_with_off_heap` arm carries the machine's handles. Closing it needs a sibling change: thread the sender's handles into `ExecutionContext::call_bif`/`SendHook::send` (or expose `Machine::refc_binaries` through a shared cell).
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives.** The refusal is `Process::has_unpublished_roots()` (`relocation_exempt || state == ProcessState::Running`) or a receiver the host's `CollectionGate` declines; `beam_process`'s `copy_reason_onto`/`enqueue_down_signal`/`enqueue_exit_signal` (`../../beam_process/src/ptab.rs`) pre-test both, hand the raw `Alloc` refusal back with **no** collect, grow or retry, and turn the `{'DOWN',…}`/`{'EXIT',…}` into a fresh `HeapFragment`, so the signal arrives with the receiver's heap neither collected nor grown. The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*; terminating the receiver is the caller's cascade, not a message).
  `beam_rt` arms the exemption through `with_relocation_exempt`: the **`-eval`/nested route** wraps the whole eval driver, the **scheduled `run` route** arms it for a PARKED process (the `Wait` park arm); both deliver the waiting parent's DOWN even on a saturated nursery, pinned by `../../tests/eval_exempt_receiver_signal.rs`.

## Notes for Agents
- **The node's layout: `mod.rs` is root-only plumbing over concern-scoped submodules.** It holds the module `//!` overview + submodule map, the `mod …;` declarations, the crate-visible re-exports and the `#[cfg(test)]`-gated name plumbing, and defines no logic.
  Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs`, its methods delegating to inherent helpers in the sibling that owns the concern.
  Three siblings exceed the ~1000-line target — `runtime_hooks.rs`, `gc.rs`, `bridges.rs` — each one cohesive pre-existing concern documented at its own top; `tests.rs` is the node's deliberately single shared unit suite.
  The names `tests.rs` and `pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]`; `DispatchMemo` alone stays ungated (`bridges.rs` uses `super::DispatchMemo::default()`).
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver (`pump.rs`), one `pump_once` round per wait.
  For an ordinary (no-deadline) parking, `pump_once` advances the scheduler by `RUN_EXPORT_PUMP_SLICES` slices through `Runtime::pump_scheduler_boot` — the **imminent-only** wait policy, so a round whose only pending deadline is far out (a `gen_server` housekeeping timer an hour away, say) returns unslept instead of stalling the caller — and a pump that reports nothing ran ends the drive with the honest `beam_engine::blocked()` gap.
  The engine arms no timer for a `wait_timeout` and a nested run is not a scheduled process, so for a statically readable finite `after T` the deadline is the nested run's own to wait out: `pump_once` recovers it through `Machine::wait_deadline` and, on an empty run queue, sleeps `min(remaining, DEADLINE_PUMP_SLEEP)` and re-pumps until the wall clock reaches `start + T`, then resumes at the `timeout` continuation (a message arriving first wins).
  The loop ends on return, on a step reporting `Ok(None)` (the typed `blocked()` gap), or at the `BLOCKING_PUMP_DEADLINE` (60 s) cap — the nested counterpart of the boot drive's `DRIVE_DEADLINE`, reported as the typed `error::message("blocking pump: the scheduler was still runnable after N ms")` and sized ≈ 2.5–3× the heaviest legitimate workload on this route (the in-process compile of `lists.erl`, ≈ 17.7–24.3 s on the debug runtime); the deadline path is exercised only through the injectable `limit` parameter.
- **Closure application is entered in-machine through the `resolve_local_fun` seam — for a context the engine drives directly** (see the API Surface section); the engine's `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper**, which forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process (`beam_rt run m.beam m:f/0`) enters in-machine and is resumed by a real send, and a same-module local `call` the host serves is dispatched as a BIF through `call_bif` (`resolve_local_call` → `crate::native::prim_tty::serves_local_call`) instead of being jumped into the module's non-exported Erlang stub body.
  Pinned by `../../tests/scheduled_apply_seam.rs`; the A.9 case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle ([`../boot/CONTEXT.md`](../boot/CONTEXT.md)).
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it, so it needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` calls it with `Some(self.mailbox_pid)` (the sender: the full three-family union) and `deliver_message` with `None` (store-only), because `deliver_message`'s context is built `for_process` the **receiver** by `deliver_in_table` — unioning `self.mailbox_pid` there would resolve against the *receiver's* retained families, and `None` preserves the empty-source fast path, so a plain on-heap message still builds no table.

### Relocation exemption (the cross-crate GC correctness seam)
`RuntimeContext::with_relocation_exempt<T>(&mut self, f: impl FnOnce(&mut Self) -> Result<T>) -> Result<T>` runs `f` with the context's process (`self.mailbox_pid`) marked relocation-exempt through `beam_process`'s `ProcessTable::{is,set}_relocation_exempt`, so a delivery-driven `Process::deliver` collect can never recycle words this crate holds **outside** the process's own containers (Rust-local term handles, an unpublished `Machine`); it is **nested-safe** (it saves the previous mark, sets `true`, restores on every path — `TermNotFound` on the save means "no process", so nothing is exempted — and the closure's error wins).
Wrapped scopes (exactly five): `crate::eval::eval` (the whole `-eval` driver body), `run_export_blocking` (a fresh `Machine` on the context's pid), `run_label_blocking` (the fun-bridge / local-closure nested run), `apply_fun` (the `-eval`-closure arm) and `deliver_message_with_off_heap` (exempting the **sending** context's own pid, so a self-send whose payload does not fit routes to the heap-fragment fallback; a delivery to a *different* process is unaffected).
The **scheduled slice is deliberately not wrapped**: the runner drives its own outcome entry points (`run_export_outcome_with_tier`/`run_label_outcome_with_tier`) directly, publishes parked roots, and its armed admission point (`gc.rs::ensure_heap`/`ensure_heap_full`) stays the legitimate collection site ([`../DESIGN_DECISIONS.md`](../DESIGN_DECISIONS.md)).
The two other nested-`Machine` sites (`boot::drive::apply_boot_call`, `native::file_server::EngineContinuation::call`) are safe *only* on a `RuntimeContext::new` context (`mailbox_table == None`, which forces every allocation onto the pointer-stable arena); moving either onto a `for_process*` context would make it a delivery-collect hole for a mid-run process.
`RuntimeContext::deliver_in_table(runtime, table, to, from, message) -> Result<()>` is the pass-boundary entry to the same `deliver_message` semantics for the runtime's own delivery steps (used by `Runtime::service_file_requests`, `Runtime::deliver_port_messages`, `Runtime::fire_due_timers` and `Runtime::drain_ets_owner_exits`); its context's pid is the **receiver**, so the copy's source is `send_source(None, …)` → `Runtime::off_heap_source`, and an exempt receiver's raw `Alloc(AllocKind::Message)` refusal routes to `send_fragmented_message`'s heap-fragment fallback instead of propagating.
