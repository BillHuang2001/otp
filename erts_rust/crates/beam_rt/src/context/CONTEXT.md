# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → `call_registered` → external-module load), the nine bridge arms, the atom-interner discipline (`PendingInterner`) and the caller-module tracking.
The nine `beam_engine::Mailbox` seam methods live one level up in [`../mailbox.rs`](../mailbox.rs); this node owns the `ExecutionContext` half of the glue, and the runtime-level scheduler/runner that drives it lives in [`../runtime/`](../runtime/CONTEXT.md).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module` and `engines`; methods `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off — see `gc.rs`).
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → `call_registered` (the `beam_bifs` registry) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`context/mod.rs::call_bif`).
**No `ets:*` key is intercepted or re-implemented in `beam_rt`** — the one `ets`-family special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` (the only key it treats specially) through the **same** `call_registered` registry implementation as every other `ets:*` key, then observes the created `named_table` to index it for owner-death reclamation (a `before`/`after` `lookup_name` delta → `runtime::ets_owner::adopt_created_table`). `try_native` has **no** `ets` arm, `FLOOR_MODULES` excludes `ets`, and no NIF backs it, so **every** `ets:*` key reaches the `beam_bifs` `ets` registry (`crates/beam_bifs/src/ets.rs`) and is shadowed by nothing.
**`resolve_external_call` — the in-machine cross-module call seam (adopted).** `RuntimeContext` overrides `ExecutionContext::resolve_external_call`, so a `call_ext`/`call_ext_only`/`call_ext_last` callee runs **in the caller's machine** (the engine stores the caller's return address then enters the callee's export label) instead of recursing through `call_bif` → `run_export`. That is what lets a `receive` inside a cross-module callee **suspend** — `proc_lib:start/4`/`proc_lib:start_link/4` answer `{ok,pid}` (`../tests/proc_lib_start.rs`) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning the `Module` is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; the call args are already in `x(0..arity)` and an unknown label is the typed `unknown_label`.
It performs `find_module_file` + `code_server.load` **on demand** for an uncached callee, and returns `Ok(None)` (preserving the synchronous `call_bif` path byte-for-byte) for a native-floor `FLOOR_MODULES` import, a NIF-loaded module (`beam_engine` owns that dispatch), a `beam_bifs` registry key, a module whose `ImpT` observes its own call site (`module_observes_its_call_site` — `erlang:load_nif/2`, `erlang:term_to_binary/1,2`, `erlang:external_size/1,2`; an in-machine callee never re-enters `RuntimeContext`, so `current_module` would stay the caller's), a foreign-pid/unknown export, and an unknown label.
**`resolve_local_fun` — the in-machine closure-apply seam (`call_fun`/`call_fun2`).** `RuntimeContext` implements `ExecutionContext::resolve_local_fun` as a thin wrapper over the shared `RuntimeContext::local_fun_target` lookup: `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure — `module` is the **same** `Arc<Module>` the code server caches (the engine dedups module contexts by `Arc::ptr_eq`) and `label` is the lambda's `FunT` entry label — and `Ok(None)` passed through for the two fun kinds with no local label (an external `fun M:F/A`, the `-eval` closure `EVAL_FUN_UNIQ`). The engine consults the seam **first** in its `call_fun`/`call_fun2` arms: on `Some` it places the closure's free variables in `x(arity..)` (C's `call_fun` order) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process (`RunOutcome::Wait`) and a raise lands in the caller's live `try`/`catch`; `Ok(None)` keeps the value-returning `apply_fun` fallback byte-identical. The engine, not this host, places the free variables, so `local_fun_target`'s combined `args ++ free` list is used here only for resolution/validation.
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context` and `reset` — not `resume_outcome` — clears contexts. A fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier` (`../tests/fun_entry_receive.rs`).
**The heap seams.** `alloc_words`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap; the engine's heap-admission doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect there and **grow** the nursery to fit a request larger than it (the collector's `Process::ensure_capacity` seam, driven whenever the process's heap-size policy can reach the request via `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to a plain `Process::collect()`, preserving the pre-growth behaviour exactly). Every other context — and a request the young heap still cannot serve — falls back to the pointer-stable runtime arena byte-for-byte as before.
**Registry precedence (gotcha for new `beam_bifs` registrations).** The native floor runs *before* the registry, so a `beam_bifs` entry for a key the floor already serves can never shadow it; the registry runs *before* the external-module load, so for a **non-`erlang`** name a registration **does** shadow the fallback while for an `erlang:*` name it flips the unregistered answer (bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) to whatever the BIF returns. `apply_fun` → external `fun M:F/A` via `call_bif` (the `-eval` closure `EVAL_FUN_UNIQ` via `apply_eval_closure`; else the module's `FunDescriptor{uniq,index}` resolved by `local_fun_target` and entered through the blocking-aware `run_label_blocking` — `Machine::run_label` with the `run_export_blocking` pump, so a `receive` in the closure body suspends instead of folding into `blocked()`). `send_message_with_off_heap` copies into the receiver's heap (`deliver_message`/`deliver_message_with_off_heap`, the internal delivery halves — the `_with_off_heap` form carries the sender machine's refc-binary handles so an engine-built off-heap binary survives the copy); an oversized payload retries through the **heap-fragment** model, and a genuine exhaustion (either heap class, after the retry) becomes the documented `error:system_limit`.

### `call_registered` — nine dispatch arms, the gated seam handles, the port provider
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook; the shared `TableRegistry` is installed **unless** an argument is a fun (a fun argument can re-enter and reach `ets:*`, so the `RefCell` must stay free). Exactly **one** bridge is then selected, first-match, by its own `uses_*` predicate:
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1`; a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — nine BIFs (`whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_flag/2`, `group_leader/0`; `process_info/1,2` is intercepted by the floor first) over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>` (`src/context/process_bridge.rs`); the per-process `erlang:group_leader/2` and `erts_internal:group_leader/2,3` are served by the floor (`src/native/group_leader.rs`).
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised. Its long-lived host is built with `services = None` (it is moved into the runtime's `NifRegistry` and so cannot borrow the runtime) and with `crate::info::schedulers_count(runtime)` as its `scheduler_threads`, so a `load`/`unload` callback's `system_info` stays honest and every `NifHostServices` hook — `make_ref`, `whereis_pid`, `is_process_alive`, `is_port_alive`, `port_command` — stays the typed default there, never a fabricated value.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; an unloaded module or undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`erlang:'!'/2` delegating to `RuntimeContext::send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR.
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store; a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow. The store keeps raw `Eterm` words (safe while the runtime's heaps stay pointer-stable; a runtime-level store whose term must survive a heap move instead stabilizes its writes through `Runtime::try_stabilize_escaped`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`; `src/context/runtime_hooks.rs`) — serves ~47 keys of the 195-key roster: `start_timer/3,4` (delivers `{timeout, TRef, Msg}`), `send_after/4`, `cancel_timer/2`, `function_exported/3` (this runtime's loaded-module set **or** the live BIF registry), `link/1`/`unlink/1` (the `ProcessTable` link set; a remote pid is the typed gap), `os:set_signal/2` (`signal.rs`), `net_kernel:dflag_unicode_io/1` (the atom `true` for a local pid — this runtime's distribution entry is *this* node; `badarg` for a non-pid; the typed gap for a remote pid, whose peer flags the accepted links do not expose — the io-device read path's unicode fast-path probe, `io.erl`'s `bc_req/3`), `erlang:dt_spread_tag/1`/`dt_restore_tag/1` (identity with dynamic tracing off), the dynamic-tracing tag family (`dt_get_tag/0`/`dt_get_tag_data/0`/`dt_put_tag/1` ⇒ `undefined`; `dt_append_vm_tag_data/1`/`dt_prepend_vm_tag_data/1` ⇒ the argument), `system_profile/0`, `check_old_code/1`, `finish_loading/1`, the three on-load hooks (⇒ `badarg`), `erts_internal:is_system_process/1`/`is_process_executing_dirty/1` (⇒ `false`), `erts_internal:erase_persistent_terms/0` (⇒ `true`, and really clears the store), `erts_literal_area_collector:release_area_switch/0` (raises `error:notsup`), `erts_trace_cleaner:check/0` (⇒ `false`), `error_logger:warning_map/0` (⇒ `warning`), `code:coverage_support/0`/`get_coverage_mode/0`/`set_coverage_mode/1` and `erlang:statistics/1` (`run_queue`, `wall_clock`, the cumulative counter pairs `reductions`/`exact_reductions` and `context_switches`, `io`, and `scheduler_wall_time` ⇒ `undefined` because it is never enabled; the remaining valid statistics keys — `runtime`, `garbage_collection`, `run_queues`, `*_run_queue_lengths*`, `active_tasks*`, `scheduler_wall_time_all`, `microstate_accounting` — are the typed `unsupported` statistics gap); every other roster key — incl. the `erl_ddll` registry family, `read_timer/1,2`, `alias/1`/`unalias/1` — is the typed `unsupported_bif` gap, and a key outside the roster is bare `error::undef` (the roster is per `(module, function, arity)`). It holds `&mut Runtime` **plus** a `&mut ProcessTable`, so it is its own arm. `timeout` is a `boot::CORE_ATOMS` seed (the bridge cannot intern: the shared table is borrowed immutably for the whole call).
* **`FunBridge`** (`FunCaller`; the fallback) — `RuntimeContext::apply_fun` over `&mut Runtime`, carrying a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`, and **no** `TableRegistry`.
`NodeIdentity` answers this runtime's **own** node — `Runtime::local_node()` (the live `node@host` atom on a `-name`/`-sname` node, else `nonode@nohost`), creation `0` — for `beam_codec`'s `Encoder::with_local_node`, emitting `NEW_PID_EXT` (`88`) for an internal pid and `V4_PORT_EXT` (`120`) for an internal port. The **decode** direction is wired: `beam_bifs::binconv::decode_term_bif` installs this runtime's `local_node` identity on `beam_codec`'s decoder (`Decoder::with_local_node`), which demotes a local-node `NEW_PID_EXT`/`V4_PORT_EXT` to the internal id, so `binary_to_term(term_to_binary(self())) =:= self()`.
`FunIdentityBridge` supplies the `NEW_FUN_EXT` (`112`) identity of a **compiled module's** local (`make_fun3`) fun from an owned, borrow-free snapshot (the caller module's `Arc<Module>` + `.beam` path + the node atom): `Ok(None)` — never an error — for a non-local-fun argument, a context with no calling module (the `-eval` evaluator) or an unreadable `.beam`, otherwise module atom + module MD5 + `old_index`/`old_uniq` from `FunT` + the fixed `<0.0.0>` creator (`bridges.rs::local_fun_identity`/`module_md5`). Built only on the `uses_fun_identity` arm (`erlang:term_to_binary/1,2`, `erlang:external_size/1,2`).
`RuntimeMemory` (the `MemoryHook`) is built only on the `uses_memory_hook` arm (`erlang:memory/0,1`); ungated its `code_bytes` snapshot (a `CodeServer::loaded()` clone+sort plus a `std::fs::metadata` per module) would cost ~13 µs on **every** registered call.

### `PendingInterner` · caller-module tracking · NIF dispatch
`PendingInterner` is `Clone` over `Rc<RefCell<{base, names}>>`: `new(base)` roots it at the shared table's length, `commit` interns the recorded names in order at their predicted indices, and `beam_bifs::AtomInterner` gives append-only prediction + in-call dedup (`binary_to_term`/`list_to_atom`/`binary_to_atom` are the BIF writers); `load_nif/2`'s two writers (the BIF, the C `load` callback via `enif_make_atom`) share the cell. `run_export` **sets** `current_module` (restoring it afterwards) and `FunBridge::call_fun` **inherits** it; it reaches the BIF through `BifContext::with_current_module` (`None` ⇒ `unsupported_bif`, never a guess).
`try_call_nif` is the **first statement of `call_bif`**, so a NIF replaces the Erlang stub of the same `{module,function,arity}` exactly as the BEAM's dispatch does; its term lives in the pointer-stable pooled BIF heap and the per-call `PendingInterner` is committed **after the registry borrow is released**. `NifCallError::Raised(reason)` → `error::nif_raised`; `UnknownFunction` → bare `error::undef`; a miss is `Ok(None)`. The per-call host is handed a `crate::nif::RuntimeNifServices` provider built from **disjoint** field borrows of the runtime (`refs`/`references`/`processes`/`ports`; `processes` is the caller's mailbox table when it runs a scheduler slice), so the host's `make_ref`/`whereis_pid` hooks **and** its `is_port_alive`/`port_command` port hooks (over the `Rc<RefCell<PortRegistry>>`, a `try_borrow` ⇒ the typed "cannot answer" `None` on a live borrow) are live; the registry `Rc` is cloned and the heap taken **before** those borrows, so the call itself never borrows `self.runtime`, and the borrows are released (`host.into_heap()` + `drop(services)`) before the heap/interner work reuses it. **Interception is at external dispatch only**: a *local* `call` inside the NIF's own module never reaches `call_bif`.

## Closable host-seam keys (`runtime_hooks.rs`)
The bridge serves ~47 of the **195** `beam_bifs::RUNTIME_HOOKS_BIFS` keys (`../beam_bifs/src/hook_sets.rs:338-534`); every other roster key reaches the fallback arm `runtime_hooks.rs:1042-1045` and returns a typed `unsupported_bif`.
`uses_runtime_hooks` gates the **whole** roster, so any roster key already reaches the bridge — and the bridge holds `&mut Runtime` + `Option<&mut ProcessTable>`, so a key is closable when its backing data lives behind those borrows (or behind `Runtime`'s owned tables: code server, timers, registry) with **no** new cross-crate dependency.
Oracle answers below are from the system `erl` (OTP 29.1.1 / erts-17.1).

### Closable today (backing data + accessor already present)
* **`erlang:bump_reductions/1`** (`hook_sets.rs:366`) — oracle: `bump_reductions(10)` ⇒ `true`; a negative or float argument ⇒ `error:badarg`; observable (`statistics(exact_reductions)` rises by the argument). Backing: the node-global cumulative reduction counter (`Runtime::note_reductions`/`reductions_statistics`, already read at `runtime_hooks.rs:765-766`). Range-validate (small int ≥ 0) else `badarg`.
* **`erlang:read_timer/1,2`** (`hook_sets.rs:414-415`) — oracle: a non-ref ⇒ `error:badarg`; a **pending** ref ⇒ the remaining ms as a small int (`read_timer(T,[])` and `read_timer(T,[{async,false}])` both ⇒ the int; `[{async,true}]` ⇒ `ok`); a fired or nonexistent ref ⇒ `false`; `/2` accepts **only** `{async,Bool}` — `{info,_}`, any other key or a non-list ⇒ `badarg`. Backing: `crate::timers::Timers` is reachable (`self.runtime.timers`/`timers_mut`, already used at `runtime_hooks.rs:208,215`); `Timers::is_timer_ref` (`../timers.rs:341`) distinguishes a non-ref from a fired ref and `Timers::cancel` (`../timers.rs:352`) already computes the remaining `Duration` — closing needs a small read-only accessor returning the remaining time **without** consuming the pending entry.
* **`erlang:delete_module/1`** (`hook_sets.rs:371`) — oracle: a loaded module ⇒ `true`; an unloaded atom ⇒ `undefined`; a non-atom ⇒ `error:badarg`. Backing: `Runtime::code_server`'s loaded-module map (used at `runtime_hooks.rs:275`); closing needs a `CodeServer` removal op and the `undefined` atom interned.
* **`erlang:is_builtin/3`** (`hook_sets.rs:398`) — oracle: `is_builtin(erlang,self,0)` ⇒ `true`, `is_builtin(ets,new,2)` ⇒ `true`, but `is_builtin(lists,map,2)` ⇒ **`false`** (an Erlang fast path is not a builtin); a missing name ⇒ `false`, a non-atom ⇒ `error:badarg`. Backing: the borrowed `Runtime::registry` (`BifRegistry::contains`, `../beam_bifs/src/registry.rs:189`) — but the check must be restricted to the **declared `bif.tab`** set so a stdlib fast path is never turned into a false `true`.

### NOT closable — genuine, correctly-typed gaps (do not "close")
* `erlang:alias/1`/`unalias/1` (`hook_sets.rs:365,440`): oracle `unalias(make_ref())` ⇒ `false` (no alias exists); real aliases need monitor-tag plumbing `beam_process` does not expose.

* `erts_internal:gather_carrier_info/1`, `erts_internal:ets_super_user/1`: allocator / pid-domain introspection not exposed here.
* `re:compile/1,2` · `re:import/1` · `re:inspect/2` · `re:internal_run/4` · `re:run/2,3` · `re:version/0`: need a regex engine — a missing subsystem.
* `erts_debug:*` (18 keys) / `erl_debugger:*` (13 keys): debugger/introspection facilities not modelled.
* `erts_internal:prepare_loading/2`: the prepared-code term; `finish_loading/1`'s doc (`runtime_hooks.rs:473-493`) correctly records it unimplemented — not a fabricatable value.
* **`erlang:system_info/1` and `erlang:system_flag/2` are on the roster but are intercepted by the native floor** (`../native.rs:148,245`) **before** the registry — no bridge work can ever affect them.

## Constraints
* **`unsafe`-free**: the crate is `#![deny(unsafe_code)]`; the glue uses only the safe peripheries of the lower crates (`Heap::cons/tuple`, `AtomTable::intern`, `BifRegistry::call`).
* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Dispatch cost is a first-class concern**: `call_registered` runs per call, so every handle built there must be gated by its own `uses_*`/`needs_*` predicate; measure with [`../../examples/perf_bif.rs`](../../examples/perf_bif.rs) before and after any change to the dispatch prologue (figures in [`../../TRACE_AND_PERF.md`](../../TRACE_AND_PERF.md)).

## Known Issues
* **`alloc_words`'s arena fallback is deliberate, and the admission-point valve is what keeps it sound.** For a **collectable** slice process whose own young bump fails, `context/gc.rs::alloc_words` falls back to the pointer-stable arena and never returns a typed `Err`: the seam is the **unrooted** allocation path (`beam_engine::terms::sink::ContextSink`, metadata-only builds) and is handed **no** root set, so it can neither collect nor safely grow — calling `Process::ensure_capacity` there would collect against the possibly-stale published `process.regs`, relocating a heap out from under live machine terms (a wrong result). The arena block it hands out is a container in an unscanned region, which is already made sound by the unscanned-root valve: `root_is_unscanned`'s decline at `ensure_heap`, `ensure_heap_full` and `alloc_words_rooted` refuses any collection whose root set reaches such a container, so the root stays valid and no young word it reaches is moved. The valve calls a term safe exactly when it is an **immediate**, a **literal**, or a pointer the process's collector **scans** — `Process::heap()`'s young block (via `in_heap_block`) **or** the collector's mature generation (`AnyCollector::mature_contains`, which covers either strategy's mature space) — so a term in a foreign region (the pooled BIF heap, the arena, the `-eval` heap, a message fragment) always declines the collection.
* **`erlang:memory/0,1` reports `0` on the `-eval`/single-pass path.** `memory_hook.rs::RuntimeMemory::new` sums each live process's collector capacity (nursery + mature) for `processes` and its **used** words — nursery *and* mature (`collector.young().used_words() + collector.mature_used_words()`) — for `processes_used`, so the scheduled path counts both generations of a long-lived process. The `-eval`/single-pass path has no `Process` — it allocates on `Runtime::arena` (a `beam_engine::MinimalContext`) whose private `Arena` exposes no byte/word accessor — so its `processes`/`processes_used` are an honest `0`; making that half real needs a new `MinimalContext` arena-words accessor plumbed through `Runtime` (owner: `beam_engine`).
* **A long-running scheduled process's heap/RSS grows without bound — a cross-crate handoff owned by `beam_gc`, NOT this node.** `context/gc.rs::ensure_heap`/`ensure_heap_full` (sharing `collect_or_grow`) are only the admission doors; the sizing is `beam_gc/src/collector.rs` (`collect_minor`/`collect_major`) and `beam_gc/src/policy.rs::young_after_collection`. Measured `run` of a loop that builds a fresh 1000-element list per iteration (pure garbage, no retained live data): `heap_size` 987 → 833 026 (N=1 000) → 2 487 399 (N=5 000) → 7 427 328 (N=20 000), and re-running the *same* loop in one process regrows it (833 026 → 1 199 557) — there is no steady state. Mechanism: the collector's post-collection resize is fed the **pre-reset nursery fill** (`self.young.used_words()`) where `HeapPolicy::young_after_collection` expects the surviving live count, so its `should_grow` is always true, and `young_after_collection` steps with `next_words(…, 1)` where the C it cites (`erl_gc.c:1493`) uses `next_heap_size(p, …, 0)` (a fixed point) — one growth-table step up per collection. Peak RSS ≈ 2 × `erlang:memory(processes)` is the transient double-allocation of the from/to spaces inside a fullsweep; the measured rust `VmHWM` is **29.4 / 77.3 / 227.5 MiB** at N = 1000 / 5000 / 20000, versus a flat **~60 MiB** for the system runtime on the same workload. `ensure_capacity` is now also reached from the engine's heap-admission doors when a request exceeds the nursery (`context/gc.rs::ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`), but in *this* steady-allocating workload only `resize_nursery` grows the spaces (collections do run — all fullsweeps, hence `minor_gcs` reads 0). Do not look for this in `alloc_words`, the runner budget or `Runtime::arena`.

* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly (`process_bridge.rs:176-343`). The `erlang:ports/0` typed gap (`process_bridge.rs:213-220`, a `try_borrow` failure) is reachable only on a **nested** path: in `call_registered` the arm hands the bridge a **separate `Rc` clone** of the port registry (the provider takes one at `mod.rs:1048`, the bridge another at `mod.rs:1090`), so no borrow is held on the bridge's clone during an ordinary call and production `erlang:ports/0` works. The two divergences, both unit-pinned: `register/2` with a **port id** is a typed gap (`process_bridge.rs:184-189`; the table registers pids only), and `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg` (`process_bridge.rs:302-322`, test comment at `604-605`); `process_flag(error_handler, Atom)` always answers the atom `error_handler` (no error-handler state, `process_bridge.rs:323-331`). No other method serves stale or placeholder data.
* **`NodeIdentity` carries this runtime's live node atom but a hard-coded creation `0`.** The atom comes from `Runtime::local_node()` (`mod.rs`), so `node/0` and a pid's `NEW_PID_EXT` image name a `-name`/`-sname` node correctly; the `epmd`-assigned creation is not carried (`NodeIdentity` holds only the node atom, and its shape is pinned by a colocated unit test).

## Notes for Agents
- **`mod.rs` is ~2500 lines (pre-existing; not introduced here).** It is one cohesive unit — the `RuntimeContext` struct, its entry points and the **single** `impl ExecutionContext` — plus the colocated `#[cfg(test)]` units and the inline `mod blocking_fun_apply`. The inline test module is deliberately *not* in the sibling `tests.rs` (which stays the shared-unit home) because it needs this file's private items. A future split should follow the `call_bif` dispatch / `call_registered` arms / `apply_fun`+send seams / heap seams axes rather than carve the impl.
- **The nested blocking pump is wall-clock bounded.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver (`mod.rs`), one `pump_once` round of `RUN_EXPORT_PUMP_SLICES` slices per wait. The loop ends when the machine returns, when a pump reports nothing ran (the honest `beam_engine::blocked()` gap), or when its `BLOCKING_PUMP_DEADLINE` (10 s) cap elapses — the safety net for a process that stays **runnable forever** (the `ran == 0` exit never fires for it), reported as the typed `error::message("blocking pump: the scheduler was still runnable after N ms")`. The cap is the nested counterpart of the boot drive's `DRIVE_DEADLINE`; it is deliberately generous so no legitimate single-pass/`-eval`/boot workload (a `proc_lib` start, a `gen_server` round trip, an io-device read) is affected, so the deadline path is exercised only through the injectable `limit` parameter (the unit tests above).
- **Closure application is entered in-machine through the `resolve_local_fun` seam — for a context the engine drives directly.** The engine's `call_fun`/`call_fun2` arms consult `ExecutionContext::resolve_local_fun` **first**; `RuntimeContext` implements it as a thin wrapper over `local_fun_target` (see the API surface above), so a `.beam` local closure is entered in the **calling** machine, a `receive` inside it suspends *this* process (`RunOutcome::Wait`), and a raise lands in the caller's live `try`/`catch`. That holds for every route whose machine runs on the bare `RuntimeContext` — the single-pass/`-eval`/boot routes. The engine's `Ok(None)` fallback (an external `fun M:F/A`, the `-eval` closure) is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking` (the label-addressed twin of `run_export_blocking`), so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper, not the bare `RuntimeContext`.** That wrapper forwards `resolve_external_call` for the cross-module seam but does **not** forward `resolve_local_fun`, so on the scheduled path the engine still sees the trait default `Ok(None)` and a blocking closure applied from a scheduled process folds into the typed (and uncatchable) `beam_engine::blocked()` gap (`beam_rt run m.beam m:f/0` exits 3). Closing it is a one-method forward in `BudgetContext` (`../runner/budget.rs`, owner: the `../runner` node), mirroring the existing `resolve_external_call` forward; the engine seam itself is landed. Pinned by `../../tests/scheduled_apply_seam.rs` (an active pin of the typed gap beside an `#[ignore]`d positive for the target behaviour). Discriminator: the `#[cfg(test)] mod blocking_fun_apply` in `mod.rs` (a local closure whose body blocks, applied through a **second** module so the compiler's fun inlining cannot turn the `call_fun` into a direct call) — it drives `apply_fun`/`run_label_blocking` **directly**, so its pumpable phase passes and its `for_process` control phase keeps the typed `blocked` gap regardless of the engine seam. The A.9 differential-gate case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle (corpus `mismatch=0`) and the boot chain completes; its per-directive detail is owned outside this node, in [`../boot/CONTEXT.md`](../boot/CONTEXT.md).
- **`local_fun_target`'s free-vars-then-args closure argument order** (`mod.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it. It needs a focused test before any change.

### Relocation exemption (the cross-crate GC correctness seam)
`RuntimeContext::with_relocation_exempt<T>(&mut self, f: impl FnOnce(&mut Self) -> Result<T>) -> Result<T>` runs `f` with the context's process (`self.mailbox_pid`) marked relocation-exempt through `beam_process`'s `ProcessTable::{is,set}_relocation_exempt`, so a delivery-driven `Process::deliver` collect can never recycle words this crate holds **outside** the process's own containers (Rust-local term handles, an unpublished `Machine`). It is **nested-safe**: it saves the previous mark (`is_relocation_exempt`, resolved through the same `process_table()`/`process_table_mut()` split the mailbox seam uses, so it works for the runtime's own table and for a caller-supplied pass table), sets `true`, runs `f`, and restores the previous value on every path; `TermNotFound` on the save means "no process — nothing to exempt", so `f` runs unguarded. The closure's error wins; the restore error surfaces only when `f` succeeded.
Wrapped scopes (exactly these four): `crate::eval::eval` (the whole `-eval` driver body, so the evaluator's `Runtime::pump_scheduler` receive pump runs inside the exemption — `Runtime::eval` delegates here, so there is no second wrap), `RuntimeContext::run_export_blocking` (a fresh `Machine` on the context's pid; `run_export` delegates to it), `RuntimeContext::run_label_blocking` (the fun-bridge / local-closure nested run), and `RuntimeContext::apply_fun` (covers the `-eval`-closure arm reached when a loaded module applies an `EVAL_FUN_UNIQ` closure; it nests inside the former two, harmlessly). The **scheduled slice is deliberately not wrapped**: the runner drives `run_export_outcome_with_tier`/`run_label_outcome_with_tier` directly, publishes parked roots, and its armed admission point (`gc.rs::ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`; the latter is the one `test_heap` reaches) stays the legitimate collection site.
`RuntimeContext::deliver_in_table(runtime, table, to, from, message) -> Result<()>` is the pass-boundary entry to the same `deliver_message` semantics for the runtime's own delivery steps (which hold `runtime` and `table` apart): it builds `RuntimeContext::for_process(runtime, table, to)` and delivers, so an exempt receiver's raw `Alloc(AllocKind::Message)` refusal routes to `send_fragmented_message`'s heap-fragment fallback instead of propagating. Used by `Runtime::service_file_requests` (`../native/file_server.rs`), `Runtime::deliver_port_messages` (`../port.rs`), `Runtime::fire_due_timers` (`../runtime/scheduler.rs`) and `Runtime::drain_ets_owner_exits` (`../runtime/ets_owner.rs`).
