# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → dispatch memo → `call_registered` → external-module load), the nine bridge arms, the dispatch memo (`dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), caller-module tracking, the **lent-`TableRegistry` propagation into a nested fun application**, the **in-machine execution-position door** (`position.rs`) and the node's real `LOCAL_EXT` hash (`node_hash.rs`).
The nine `beam_engine::Mailbox` seam methods live in [`../mailbox.rs`](../mailbox.rs); the scheduler/runner that drives this glue in [`../runtime/`](../runtime/CONTEXT.md).
Mechanics-level companion: [`IMPLEMENTATION.md`](IMPLEMENTATION.md) — every per-concern detail this file points at.

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module`, `engines`, `gc_armed`, `dispatch_memo` and `lent_tables`.
Its methods: `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`lent_tables` is set only by `FunBridge::nested`; `new`/`with_output`/`for_process` set it `None`.
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`calls.rs`'s `call_bif_routed`).
`wants_reduce` returns `false` (the default `reduce` is a no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext`.
**No `ets:*` key is intercepted or re-implemented in `beam_rt`**: `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the `beam_bifs` registry shadowed by nothing.
The one `ets`-family special case is *bookkeeping, not interception*: `call_bif` routes `ets:new/2` through the **same** `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation (`runtime::ets_owner::adopt_created_table`).
**`resolve_external_call` — the in-machine cross-module call seam.** `RuntimeContext` overrides it so a `call_ext*` callee runs **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4`/`start_link/4` answer `{ok,pid}`, [`../../tests/proc_lib_start.rs`](../../tests/proc_lib_start.rs)) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It loads an uncached callee on demand (`find_module_file` + `code_server.load`) and returns `Ok(None)` (keeping the synchronous `call_bif` path byte-for-byte) for a floor-served name (`native::floor_shadows`, **key-granular**: `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label.
`callee_observes_its_call_site` is **module-wide** for `erlang:load_nif/2` and **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, which must stay synchronous so the function cannot park with an unpublished `Machine::pending_exception`.
The seam **exempts a built-in NIF library** (`crate::native::prim_tty::is_builtin_library`, A.7's `prim_*` family) from the module-wide verdict: it registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the `blocked()` gap.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure (`module` = the **same** `Arc<Module>` the code server caches; `label` = the lambda's `FunT` entry label).
A fun with no local closure goes to `external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`) has no closure but its identity *is* the callee's `M:F/A`, so it resolves to that module's export label through the cross-module seam's **own** `resolve_external_call`, under the same refusals; `Ok(None)` remains for the fun kinds with no in-machine entry (the `-eval` closure `EVAL_FUN_UNIQ` and any external fun the resolver refuses), keeping the value-returning `apply_fun` fallback byte-identical.
The engine consults the seam **first**: on `Some` it places the closure's free variables in `x(arity..)` (C's order — flagged as a possible `gen_server` init mis-entry, see *Notes for Agents*) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch`.
Entering an external fun in the calling process (as C's `call_fun` does) is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`).
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context`, and `reset` — not `resume_outcome` — clears contexts; a fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier`.
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap: both allocation seams meet a **capacity** refusal of the bump with the no-relocation `Process::grow_nursery` and a retried bump (and only then fall back), while the unrooted `alloc_words` is handed no root set and **never collects**.
`alloc_words_rooted` additionally collects over the machine's handed-in root set when the retried bump still fails or a forced request bypassed it.
The engine's doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect and grow the nursery to fit an oversized request (`Process::ensure_capacity`, when `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to `Process::collect()`) — see *Known Issues* for the arena fallback and its soundness valve.
**Registry precedence (gotcha).** The native floor runs *before* the registry (a `beam_bifs` entry can never shadow a floor-served key) and the registry *before* the external-module load; a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`.
### The dispatch memo · `DispatchHooks`
`dispatch(module, function, arity)` is the **only** producer of a registered call's dispatch answer: a direct-mapped 8-slot per-context memo of `{bif: Option<BifFn>, hooks: DispatchHooks}`, where `hooks` is **one boolean per `uses_*` predicate** (the eight mutually-exclusive bridge-arm selectors plus the `fun_identity`/`memory_hook`/`export_gate` build gates) and `bif` is the `BifRegistry` lookup the caller then invokes **directly** (no second lookup); `call_registered` is reached only on `Some`.
A cached answer can never go stale: the one mutable input, the **NIF registry**, is deliberately not memoized (`call_bif` runs `try_call_nif` first on every call).
Slot hash, the miss/collision rules, hit/miss cost, pooled BIF heap and `PendingInterner`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-dispatch-memo--dispatchhooks).
### In-machine execution-position door (`position.rs`)
`position.rs` serves a process's execution-position items (`process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel`) out of the [`Machine`](beam_engine::Machine) that owns its frame, through `beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine` seam: `in_machine_probe` opts in **once per run** and `dispatch_in_machine` rejects every dispatch that is not an `erlang:process_info/1,2` for the executing process, published in `Runtime::in_machine` for exactly one nested `call_bif`.
Everything else (another pid, a nested query, a pid-less argument, an unsourced name) falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated; the runner's `BudgetContext` carries the pair onto the **scheduled** path.
Why the machine is out of `RunnerState` for the slice, the five values and the root-set window: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-in-machine-execution-position-door--positionrs).
### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One helper serves **all three** entry points — `alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying by **provenance first** through `Runtime::local_reference(to)`: a monitor/alias reference `Some(Some(_))` is looked up via `table.resolve_alias`, a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias, and unknown provenance `None` (a decoded or received copy) falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`.
* the BIF route (`erlang:send/2`, `'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery;
* the compiled `Dest ! Msg` route — `resolve_send_destination` (inherent, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteName`) and `deliver_remote` transmits it over the connection the runtime is a node on; `resolve_send_target` is a `#[cfg(test)]`-only local wrapper.
The two reference id spaces are **bridged, not unified** (`Runtime::refs` for `make_ref/0`/timers/`seq_trace`; the `ProcessTable`'s own allocator for monitors/aliases); the typed-`badarg`-vs-silent-drop divergence and the reference-**identity** hazard are in the module docs and the crate `Known Issues`.
C arm reproduced: `send_altact_message` (`bif.c`) + `handle_altact_msg` (`erl_proc_sig_queue.c`).
### `call_registered` — the gated dispatch arms, the lent/held `TableRegistry`
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook.
The `TableRegistry` is installed from **two** sources, in precedence order:
* **lent** — the one live `&mut TableRegistry` an outer `BifContext::call_fun` handed the [`FunBridge`](#the-nine-bridges) for one nested call; the outer `ets:foldl/3`/`ets:foldr/3` `take`s it out of its own `BifContext` before applying the fun, so the lent `&mut` is **exclusive by construction** and installing it cannot alias.
  It is installed for **every** nested call (not gated by the cell rule below), which carries it through a reentrant intermediate that installs no cell of its own (`ets:foldl` fun → `lists:map` fun → `ets:lookup`).
* **held** — otherwise the shared cell, held exactly when this call needs it: `install_tables = !reentrancy_capable(args) || tables_capable(module, function, arity)`.
  A reentrant call that itself reads the seam (the two `ets` fun-folds) holds it; one that does **not** read the seam installs nothing, leaving the `RefCell` free for the fun it applies to re-enter and reach `ets:*` (that is why `lists:map(fun(X) -> ets:lookup(T, X) end, L)` works).
`try_borrow_mut` (never `borrow_mut`) stays the rule: an unexpected outer borrow degrades to "no ETS", never a panic; `reentrancy_capable` also gates the result rewind (`safe_to_rewind`, `false` for the six heap-retaining arms and for any reentrant call).
The copy-out has **two** destinations, chosen by who is running (`calls.rs::rehome_container_result`): a scheduled process gets the result on its own **scanned** young heap (`move_result_into_process_heap`), while the **table-less** route (the `-eval` evaluator, `-s`/`-run` and every single-pass `run_*` entry) copies it onto the runtime's long-lived `Runtime::eval_heap` + `Runtime::eval_off_heap` store (`pool.rs::move_result_into_runtime_store`).
The **move** is unconditional on a process route (`move_container = mailbox_table.is_some() || safe_to_rewind`): a container result left on the pooled BIF heap sits in a region no collector scans and a later call's rewind recycles, so Erlang code that stores it in a heap object would hold a dangling pointer (`compile:debug_info_chunk/1` storing `lists:filter/2`'s result inside a tuple is that shape).
On the **table-less** route the move stays gated on `safe_to_rewind`: there is no collector to make the result collectable and a non-rewindable call never rewinds, so an unconditional move would only duplicate it into the never-reset store.
A **reference-holding** graph (`calls.rs::graph_holds_reference`) is neither moved nor rewound — a reference's identity is its address (`Runtime::references` is a `HashMap<Eterm, _>` and `Timers::is_timer_ref` keys on the term word), so a copy would stop being the timer/monitor it names.
The **rewind** is the gated half: both arms deep-copy through a **fresh, empty, per-attempt** `beam_message::OffHeapTable` (so `copy_struct` takes its single-traversal `try_copy_fast` path), **adopt** its drained handles/binaries/nodes on success only, and rewind the pool to that call's `mark` only when `safe_to_rewind` holds **and** the copy succeeded (or the result is an immediate) — a refusal, an `Err` result (whose live reason term may point into this heap) and a non-rewindable call leave the result on the pool at the call's own offset and never rewind.
The store's growth by region replacement, the rewind's soundness argument and the measured counter deltas (and why they do not reduce first-touch faults): [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-table-less-arm-and-its-store).
`tables_capable` (`dispatch.rs`) names the seam's consumers, derived from `beam_bifs` (read-only; `src/ets*.rs`): **every registered `ets:*` verb** (each resolves its handle through `resolve_handle`/`take_table_gated`, all reading `ctx.tables()`) plus the two `erts_internal` raw-walk aliases `ets_raw_first/1`/`ets_raw_next/2`.
Intersected with the fun-argument predicate this yields exactly the two fun-folds — which take the table out of the registry before applying the fun, so they must hold (or lend) it, else `ctx.tables()` is `None` and they raise the typed `unsupported_bif`.
#### The nine bridges
Exactly **one** bridge is selected, first-match, from the `DispatchHooks` the caller's `dispatch` memo computed — one boolean per `uses_*` predicate, so no predicate runs per call; each bridge owns a different runtime borrow, so they cannot co-exist.
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1`; a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — all 11 `ProcessHook` methods over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>`: `whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_info_keys/1`/`process_info_item/4`, `process_flag/2`, `group_leader/0` (`process_info/1,2` is intercepted by the floor first; the per-process `group_leader/2` pair is served by the floor).
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised.
  Its long-lived host is built with `services = None` (it moves into the runtime's `NifRegistry`) and `crate::info::schedulers_count(runtime)` as its `scheduler_threads`, so a `load`/`unload` callback's `system_info` stays honest and every `NifHostServices` hook stays the typed default there.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; unloaded module / undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`'!'/2` delegating to `send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered; a **reference alias** goes to the alias **owner**).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR.
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store (a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow), holding raw `Eterm` words (safe while the heaps stay pointer-stable; a value that must survive a heap move is stabilized through `Runtime::try_stabilize_escaped`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`) — partly serves the 172-key `beam_bifs::RUNTIME_HOOKS_BIFS` roster (the timer family, `function_exported/3`, `link/1`/`unlink/1`, `os:set_signal/2`, `statistics/1`, …); the served / fixed-oracle-absent / typed-gap split: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#closable-host-seam-keys-runtime_hooksrs).
* **`FunBridge`** (`FunCaller`; the fallback) — `apply_fun` over `&mut Runtime`, carrying a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`.
  It builds the nested context in one private `nested<'b>(&'b mut self, lent_tables: Option<&'b mut TableRegistry>) -> RuntimeContext<'b>`, shared by both seam entry points so they cannot drift: `call_fun` passes `None`, while the overridden **`call_fun_with_tables`** passes the outer call's lent `&mut TableRegistry` verbatim.
`NodeIdentity` answers this runtime's **own** node — `Runtime::local_node()` (the live `node@host` atom on a `-name`/`-sname` node, else `nonode@nohost`), creation `0`, plus the real `local_node_hash` (see [the node hash](#the-node-hash-a2--node_hashrs)) — emitting `NEW_PID_EXT` (`88`) for an internal pid and `V4_PORT_EXT` (`120`) for an internal port.
The **decode** direction installs the same identity (`Decoder::with_local_node`) and demotes a local-node `NEW_PID_EXT`/`V4_PORT_EXT` to the internal id, so `binary_to_term(term_to_binary(self())) =:= self()`.
`FunIdentityBridge` supplies the identity a **compiled module's** fun hands to the `LocalFunIdentity` seam, on the `uses_fun_identity` arm (`term_to_binary/1,2`, `external_size/1,2` and the introspection pair `fun_info/1,2`).
For a `make_fun3` (`FunKind::Local`) argument it derives the `NEW_FUN_EXT` (`112`) image from the code server's **cached** loaded-module snapshot (`CodeServer::fun_module_snapshot`, scanned **caller-first**) plus the node atom — `Ok(None)`, never an error, for a context with no calling module, an unreadable `.beam`, or a fun no loaded module defines; otherwise module atom + module MD5 + `old_index`/`old_uniq` from `FunT` + the `FunT` entry's `function` + the fixed `<0.0.0>` creator.
An `External` fun and a non-fun are the clean `Ok(None)`; a decoded `Imported` fun resolves only its `name` (see the `fun_identity.rs` routing entry).
`RuntimeMemory` (the `MemoryHook`) is built only on the `uses_memory_hook` arm (`erlang:memory/0,1`); ungated its `code_bytes` snapshot (a `CodeServer::loaded()` clone+sort plus a `stat::metadata` per module) would cost ~13 µs on **every** registered call.
### The `[safe]` export gate — `export_gate.rs` (the 16th `BifContext` seam)
`ExportGateBridge<'a> { code_server: &'a CodeServer, registry: &'a BifRegistry }` implements `beam_codec::ExportGate`; its `is_export_active(m,f,a)` is the shared `runtime_hooks.rs::is_active_export` helper (`erlang:function_exported/3` now delegates to it) **OR** `registry.contains(m,f,a)` — the registry disjunct exists because this runtime's code server holds only the 22 preloaded modules.
The arm is its **own** mutually-exclusive `DispatchHooks` entry — the 11th, `export_gate`, from `RuntimeContext::uses_export_gate` = `beam_bifs::needs_export_gate`, whose roster `beam_bifs::EXPORT_GATE_BIFS` is exactly `erlang:binary_to_term/2` — installed in `calls.rs` next to `uses_record_source` because it borrows `&CodeServer` + `&BifRegistry` immutably while the fun/send/dict arms hold `&mut Runtime`.
Oracle-verified: `[safe]` accepts `lists:map/2` and `erlang:system_info/1` and refuses with `badarg` `lists:map/3`, `lists:no_such_fun_xyz/1`, `erlang:no_such_bif_xyz/1` and an unloaded module's export; the flag-free form never consults the gate.
A deliberate widening to record: a registry key is accepted even when its module is not loaded here.
Evidence: [`../../tests/safe_binary_to_term.rs`](../../tests/safe_binary_to_term.rs) (4 tests) + 6 in-module unit tests.
### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` (`runtime_hooks.rs::garbage_collection`) answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape, the third element the reserved `0` — from the runtime's **node-global cumulative** counters on `Runtime::gc_stats()`: `collections` counts every collection this runtime really ran, and `reclaimed` (in words) is advanced by each collection site's own `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`, never an estimate.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`, where the oracle's are per-scheduler accumulators of a far larger emulator: the quantities match, the magnitudes do not.
The five collection sites and the accounting detail: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#erlangmemory01-and-erlangstatistics1).
### The node hash (A.2) — `node_hash.rs`
`NodeIdentity`'s `LocalNode::local_node_hash` answers `Some(node_hash())` — the **one** per-OS-process `OnceLock<u32>` mixing a nanosecond clock reading, `hostname()` and the pid, hashed by a self-contained port of the C's Bob-Jenkins `block_hash` — so `beam_bifs`' `term_to_binary(Term, [local])` (`finish_local`) can stamp the real `LOCAL_EXT` (`121`) image instead of the typed gap.
The value is per-VM-start and node-local by design, so a `[local]` differential case **must mask the four hash bytes**; `../tools/differential` (read-only sibling) still records `[local]` as an honest gap — adding the case is theirs.
The C citation (`erts_late_init_external`, `erl_term_hashing.c`), the `hostname()` fallback chain and the `block_hash` constants: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-node-hash-a2--node_hashrs).
`take_bif_frontier`, the pooled BIF-heap frontier and `PendingInterner` + NIF dispatch — mechanics in [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-pooled-bif-heap-frontier--take_bif_frontier).

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with two narrowly-scoped exceptions (`gc_walk.rs`'s `beam_term::layout` object-walk; `../nif.rs`'s `enif_compare`/`enif_hash` `unsafe extern "C"` calls); the glue otherwise uses only the safe peripheries of the lower crates.
* **Return-based errors, no silent swallowing** ([`../../../CONTEXT.md`](../../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Never fabricate a value**: a seam answer is either real state or the typed gap — `NodeIdentity`'s creation stays the truthful `0`, and the node hash is a genuine per-process computation, never a constant.
* **A lent `&mut TableRegistry` is exclusive by construction**; the shared cell is never consulted while one is lent, and `try_borrow_mut` (never `borrow_mut`) is the only way this node touches it.
* **Dispatch cost is first-class**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (an input that can change during a run — the NIF registry — must stay out).
  Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) (figures in [`../../PERF.md`](../../PERF.md)); `../../examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch.

* **The float guard lives on the narrow door alone; the full doors are FR-safe.** `ensure_heap_full` publishes each register file up to its pointer-bearing prefix and the whole stack, so a live float register relocates like any other root; the **narrow** `ensure_heap` (x prefix + stack only) keeps its `module_uses_floats` guard but is not on the engine's path today, and every door refuses a run with **no** caller module (a fun entry, the `-eval` evaluator) rather than guess one.
  Bound and door short-circuits: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-pointer-bearing-prefix-bound-of-the-full-root-doors).
* **Both heap-admission doors OR the occupancy test with the collector's collection debt.** `Process::grow_nursery` retires the young space it replaces instead of freeing it, so a growth-shaped workload keeps its whole allocation history resident until a real collection evacuates it; the doors collect when `forced || should_collect(need) || collection_debt()`, and `should_collect` stays the **occupancy test alone** (pinned by its own unit tests).
* **Only `ensure_heap`/`ensure_heap_full` reach `collect_or_grow`; the two allocation seams short-circuit past the collect.** `alloc_words_rooted`'s non-forced path serves the bump, a **capacity** refusal grows the nursery and retries, and `process.collect()` is reached only when that growth/retry *fails*; the unrooted `alloc_words` has no collection branch at all.
  Consequence, load-bearing for any heap-growth measurement: a loop emitting **no** `test_heap`/`allocate_heap` (`ensure_heap_full`'s only callers) reaches no collecting admission door, so only the **reduction/yield-boundary** door can collect it — `gc/reds_door.rs::collect_at_reds_boundary`, from the runner's `Yield` arm over the published whole `RootSet`, gated by a per-pid `REDS_BOUNDARY_MIN_REDS` interval and a **7/8** occupancy watermark OR-ed with the collection debt.
  That door runs the kind-pinned `Process::collect_kind(CollectionKind::Minor)` — a young-only collection — and escalates to the escalating `Process::collect()` only when the pinned minor reports typed heap exhaustion (the mature space cannot absorb the nursery, nothing copied), so a cadence fullsweep no longer comes from the door itself; on the **default** (native baseline JIT) tier it still fires only where a slice really ends (`../../M1_GAPS.md` *Scheduler / runner*).
* **The heap observables are CAPACITY summed over the nursery chain, so a GC-bound loop's flat `heap_size`/`total_heap_size`/`memory(total)` prove a *collapsed* chain, not the absence of growth.** `process_info(P, heap_size)` → `Nursery::capacity_words()` summed over the current **and every retired** space (`beam_gc/src/nursery.rs:154`); `total_heap_size` adds the mature capacity (`memory_hook.rs:132-174`).
  A churn loop's steady state is bump refusal → `Process::grow_nursery` → the next admission door's `collection_debt()` → `collect_or_grow` → `Nursery::collapse`, so the geometry is constant in N while `Runtime::gc_stats().collections`/`reclaimed` climb; `grow_nursery` alone moves **no** counter, and `process_info(P, garbage_collection)`'s `minor_gcs` is `minor_since_major` (reset on every fullsweep, `beam_gc/src/collector.rs:283`), never a total — the discriminating counters are `gc_stats()` and `Collector::young_space_count()`.
  The boundary door contributes the pre-emption's own collection and nothing more; its firing rate, the per-shape collections/major rates and the young-space peaks (door-on vs door-off) are **measured** in [`../runner/tests/boundary_cost.rs`](../runner/tests/boundary_cost.rs) and [`../runner/tests/reds_door.rs`](../runner/tests/reds_door.rs), not asserted as a closed-form law.
* **A slice's live float register is handled by a per-slice relocation exemption — never a permanent pin** (the guard, its decline-only bounds and the measured plateau are [`../runner/CONTEXT.md`](../runner/CONTEXT.md)'s).
  This node's half: the valve does **not** decline a float root — the engine's FR model holds *terms* built on the executing process's own young heap, so `fr[0]` is a **scanned** root (`tests.rs::a_live_float_term_in_fr_is_a_scanned_root`).
* **The "no collection can run while a BIF call is in flight" invariant is a conjunction of facts, not an enforced guard** — the BIF route (`call_bif` → `try_call_nif` → `try_native` → dispatch memo → `call_registered`) reaches no `context/gc.rs` door (`BifContext` exposes only the pooled pointer-stable `Heap`), and `gc_armed` is `take`n at each door's first statement (`execution.rs:472,486,510`), armed only by `BudgetContext` immediately before a forward.
  Both halves are structural: the latch is **unreadable** inside the dispatch (`call_registered`'s destructure discards it) and the machine is handed as `&self`, so no arm can consult it and the engine cannot mutate the register file mid-call.
  Two term holders ride that window with **no root set covering them**: the marshalled argument copy (a `[Eterm; 2]` stack array / `Machine::args_scratch`) and `InMachinePosition`'s five `Eterm`s published in `Runtime::in_machine` (`position.rs`), which `alloc_words` places on the process's **scanned young heap**.
  `Machine::pending_exception` is a third, deliberately **not** parked by `with_roots` and rooted explicitly only in the park window via `Registers::extra_roots` (`runner/run.rs:527-540`); the copy-out is **not** a collection site (`calls.rs:964-1006`: `grow_nursery` + one retry), and the one in-call collection that exists — a delivery's `Process::deliver` on the receiver — is refused for the running process by the sender/receiver relocation exemption (`send.rs:352-502`).
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap** — the call goes `call_bif` → `run_export_blocking` (a fresh `Machine` on the same pid under a `for_process*` context, so `may_pump_scheduler()` is `false`) and `pump_once` returns `Ok(None)` on its first line, folding the parked callee into the uncatchable `beam_engine::blocked()` whether or not its `receive` carries an `after T`.
* **`erlang:fun_info/1,2` reads the `LocalFunIdentity` seam, and its `name` item comes from two wiring sites here.** `bridges.rs::local_fun_identity` attaches the `FunT` entry's `function` to the derived `FunIdentity` for a compiled `make_fun3` fun (`with_function`; introspection-only, so the `term_to_binary` bytes are unchanged); `fun_identity.rs::imported_identity` resolves a decoded `NEW_FUN_EXT` fun's `name` from the loaded module named by its own `module` atom.
  Residual: an imported fun whose **defining module is not loaded** is the typed `unsupported_bif` gap where the oracle reports `{name,[]}` (C `mfa == NULL ⇒ NIL`) — never a fabricated name; pinned by `an_imported_funs_unloaded_defining_module_is_the_typed_gap_not_an_empty_name`.
* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** It is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it; `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (relocated in place) and `resync_parked_roots` reads it back into `pending_exception_mut()` and clears the extra roots.
* **The fun-image half of `callee_observes_its_call_site` is per-function** (see *API Surface*): it admits `compile:*` to the in-machine route on the **scheduled** path; a signal-driven collection there is declined by the runner's **park-window relocation exemption**, with the evidence owed to `beam_process`'s signal sites ([`../../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../../EPP_SCHEDULED_ROUTE_FINDINGS.md)).
* **The arena fallback is kept sound by a two-phase unscanned-root valve.** At each of the five collection sites the valve **declines** (`Ok(())`) any collection whose roots — or process-side scanned graph — reach a foreign container **that forwards a word the collector would follow or update**; a foreign container forwarding **nothing scanned** is inert, and the per-pid descent latch is **not** sticky (opened on a hazard, closed only by the three whole-root doors, never by a site handing over less than the whole root set).
  A decline costs a collection and nothing else (the allocation falls back to the pointer-stable arena); the two phases, the five sites and `note_gc_fallback`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-unscanned-root-valve--two-phases).
* **A module-literal root does not decline the collection: `beam_loader` load-time tags the literal area.** A constant payload is folded into the module's **literal area**, so the loop's only live root `x(0)` at its `test_heap` site IS that literal pointer; `LiteralArea::decode` calls `beam_term::literal::tag_literal_area` — the safe form of the C load-time `erts_set_literal_tag` — before publishing, so every literal root carries `TAG_LITERAL_PTR` **set** and `gc.rs::root_is_unscanned` classifies it by the C's bare-bit `erts_is_literal` rule: an immutable, never-moved region, so the valve **passes** and a constant-payload loop's `collections` scale with N.
  Tagging also removes a shared-literal corruption hazard: an untagged literal is silently **writable** (`beam_engine/src/terms/update.rs::set_tuple_element` refuses an in-place tuple write only when `is_literal` holds).
* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path** — there is no `Process` to sum (it allocates on `Runtime::arena`, whose `Arena` exposes no word accessor, so both are an honest `0`); closing it needs a `MinimalContext` arena-words accessor plumbed through `Runtime` (owner `beam_engine`).
* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly; the `erlang:ports/0` typed gap (a `try_borrow` failure) is reachable only on a **nested** path, because `call_registered` hands the arm a **separate `Rc` clone** of the port registry, so production `ports/0` works.
  `register/2` with a **port id** is a typed gap (the table registers pids only), `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg`, and `process_flag(error_handler, Atom)` always answers `error_handler`.
  `process_flag(max_heap_size, Map|Int)` parses through the **same** parser as `spawn_opt`'s option (`native/process.rs::max_heap_setting`) and stores the setting per pid in `Runtime::max_heap`; the `badarg` matrix, the previous-value answer in the C's key order and the **caller-only** scope are oracle-pinned by `tests/max_heap_flag.rs`. The bound **is enforced** on the **prospective post-collection capacity**: the verdict is drained at every collection/admission and at `serve_gc_request` (`gc.rs::drain_max_heap_verdict`, an ERTS `=ERROR REPORT====` on stderr once per killing breach) before latching `Kill`, which `runner/run.rs::take_max_heap_kill` turns into `RunOutcome::Exit(<bare atom killed>)`. Residuals (`tests/max_heap_enforce.rs`): stderr vs the oracle's stdout `logger` stream, 7 of the C's 9 fields, a kill at the next slice boundary, and an `-eval` verdict never drained — `M1_GAPS.md` *Heap switches*.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles**, so a term the *running* machine just built off-heap and forwards from a BIF callee **flattens** (a correct but unshared copy); only the compiled `Dest ! Msg` instruction carries them.
  `send_source` unions the three families a *delivery* can resolve (`extra`, the runtime's escaped-payload store, the sender's mailbox-retained families) but the BIF route passes `extra = &[]` (the in-flight `Machine` is out of `RunnerState.engines` for the whole slice, and neither `ExecutionContext::call_bif` nor `SendHook::send` carries a handle parameter); closing it needs a sibling change in `beam_engine`/`beam_bifs`.
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives** — `beam_process`'s `copy_reason_onto`/`enqueue_down_signal`/`enqueue_exit_signal` pre-test `has_unpublished_roots()` and the host's `CollectionGate`, hand the raw `Alloc` refusal back with **no** collect, grow or retry, and turn the `{'DOWN',…}`/`{'EXIT',…}` into a fresh `HeapFragment`.
  The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*); pinned by [`../../tests/eval_exempt_receiver_signal.rs`](../../tests/eval_exempt_receiver_signal.rs).

## Notes for Agents
- **Layout: `mod.rs` is root-only plumbing over concern-scoped submodules** (module `//!` overview + submodule map, `mod …;` declarations, crate-visible re-exports, `#[cfg(test)]`-gated name plumbing; no logic).
  Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs`, its methods delegating to inherent helpers in the sibling that owns the concern.
  Five siblings exceed the ~1000-line target — `runtime_hooks.rs`, `calls.rs`, `gc.rs`, `pump.rs`, `bridges.rs` — each one cohesive pre-existing concern documented at its own top; `tests.rs` is the node's shared unit suite and `calls/tests.rs` the colocated suite for `calls.rs`, and the names `tests.rs`/`pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]` (`DispatchMemo` alone stays ungated).
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned` driver, capped by `BLOCKING_PUMP_DEADLINE` (900 s) — the nested counterpart of the boot drive's `DRIVE_DEADLINE`; the wait policy and the rejected forward-progress alternative: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#the-nested-blocking-pump-and-its-bounds).
- **Closure application is entered in-machine through the `resolve_local_fun` seam for a context the engine drives directly**; the engine's `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes.
  **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper**, which forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process enters in-machine and is resumed by a real send, and a same-module local `call` the host serves is dispatched through `call_bif` instead of being jumped into the module's non-exported Erlang stub body.
  Pinned by [`../../tests/scheduled_apply_seam.rs`](../../tests/scheduled_apply_seam.rs); the A.9 case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle.
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it, so it needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` passes `Some(self.mailbox_pid)` (the full three-family union); `deliver_message` passes `None` (store-only), because its context is built `for_process` the **receiver** and `None` keeps the empty-source fast path, so a plain on-heap message still builds no table.
- **Per-call cost is a first-class concern of this node** — the dispatch prologue's hit/miss costs, the two Θ-shaped codec costs, the copy-out/rewind shape and the BIFs that never reach `call_bif`: [`IMPLEMENTATION.md`](IMPLEMENTATION.md#per-call-cost-of-a-registered-call).
### Which seam allocates where, and what the latch is (read before touching a heap seam)
- **No heap pointer is cached** — not on the context, not on the machine.
  `alloc_words`/`alloc_words_rooted` re-derive `process.heap_mut()` → `Heap::hp()` on **every** call (`gc.rs::bump`), so nothing can inherit a stale `*mut Eterm` after a collection; the pointer a call returns is uninitialized storage valid only until the next admission point or collecting allocation (`Machine::alloc_rooted` docs), which is why the engine re-reads live terms out of `x`/`stack`/`fr` after any allocating read (`reread_ctx`).
- **`gc_armed` is a per-call *permission* bit, not a "collection is due" flag.** Its only armer is the slice's `BudgetContext` (`../runner/budget.rs`): `ensure_heap`, `ensure_heap_full` and `alloc_words_rooted` arm it, while **`alloc_words` (the unrooted seam) does not** — that seam never collects (its refusal path is the no-relocation `Process::grow_nursery` + retried bump, then the runtime arena).
  Whether a collection is *due* is the door's own test, made inside `ensure_heap_full`/`alloc_words_rooted`: `forced || should_collect(heap_need) || collection_debt()`, then the unscanned-root valve, then `collect_or_grow`.
  `call_ext`/`call_import` reach **none** of the three arming doors (`ensure_heap`/`ensure_heap_full`/`alloc_words_rooted`), so the engine-side path adds no collection point either.
- **The runtime-native floor route has no copy-out and no pool rewind** (`calls.rs:1142-1146` returns before both), so a floor result stays in whatever region the arm built it in. An arm that materializes on `Runtime::info_heap` (`erlang:system_info/1`, `format_term`) rewinds that region through `Runtime::reset_info_scratch` at its own entry (`runtime.rs`, `native.rs`), which refuses once `Runtime::info_heap_tainted` is latched — so a refused relocation can never be recycled under a live term. `erlang:system_info/1` alone hands a value **out** to Erlang code, so it relocates it first with `RuntimeContext::relocate_off_scratch` (the registered-BIF container copy-out: the running process's scanned young heap, else the table-less `-eval` store), and a retained value is sound (`tests/system_info_retained.rs`).
- **Four regions, never interchangeable**:
  1. the process's own `beam_gc` young heap (`process.heap_mut()` — the only *scanned* region, target of both alloc seams *and* of the process-route BIF copy-out);
  2. the runtime's pointer-stable `arena` (`Runtime::alloc_words`, unscanned — the fallback);
  3. the pooled `beam_alloc::Heap` regions (`Runtime::take_bif_heap`/`put_bif_heap`, where a registered BIF/NIF builds its result, and which `call_registered` rewinds to that call's `mark` once the result has been copied out);
  4. the **table-less store** (`Runtime::eval_heap`, its off-heap payload owner `Runtime::eval_off_heap`, and its retired regions `Runtime::eval_heap_retired` — the `-eval`/single-pass copy-out's destination; pointer-stable, never `reset`, grown only by region replacement, and retained for the run's life because Milestone 1 has no collector on it).
