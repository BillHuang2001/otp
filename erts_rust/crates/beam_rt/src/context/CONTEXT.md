# `beam_rt::context` — the concrete `ExecutionContext` glue

## Intent
The concrete `beam_engine::ExecutionContext` the runtime installs: it adapts the engine's seam types onto the real `beam_bifs` registry, the `beam_alloc` heap and the `beam_process` process/port tables, and installs **every** optional `beam_bifs` host seam.
It owns the BIF dispatch order (`try_call_nif` → `try_native` → dispatch memo → `call_registered` → external-module load), the nine bridge arms, the dispatch memo (`dispatch` + `DispatchHooks`), the atom-interner discipline (`PendingInterner`), caller-module tracking, the **lent-`TableRegistry` propagation into a nested fun application**, the **in-machine execution-position door** (`position.rs`) and the node's real `LOCAL_EXT` hash (`node_hash.rs`).
The nine `beam_engine::Mailbox` seam methods live in [`../mailbox.rs`](../mailbox.rs); the scheduler/runner that drives this glue in [`../runtime/`](../runtime/CONTEXT.md).

## API Surface
### `context/` — the concrete `ExecutionContext` (the glue)
`RuntimeContext<'a>` carries the runtime borrow, the optional `output` sink (`SharedSink`, a cloneable `Rc<RefCell<..>>`; stdout when `None`), `mailbox_pid`/`mailbox_table`, `may_pump_scheduler`, `current_module`, `engines`, `gc_armed`, `dispatch_memo` and `lent_tables`; methods `new`, `with_output`, `heap_available()`, `for_process` (runs **as** the given pid — the scheduler seam), `pid()`, `eval_heap()`, `enter_module`, `run_export`, `resync_parked_roots` (the resume half of the runner's parked-machine root hand-off).
`lent_tables` is set only by `FunBridge::nested`; `new`/`with_output`/`for_process` set it `None`.
`impl ExecutionContext`: `call_bif` serves, **in order**, `try_call_nif` (a loaded NIF wins — the BEAM's dispatch order) → `try_native` (the native floor) → [`dispatch`](#the-dispatch-memo--dispatchhooks) (the memoized registry implementation + hook roster, so the prologue runs once per key per context) → `call_registered` (the `beam_bifs` registry — reached only when the memoized registration flag is set) → for the `erlang` namespace, `is_known_unimplemented_bif` ? `unsupported:` : bare `error::undef` → else load the module file and `run_export` (`calls.rs`'s `call_bif_routed`).
`wants_reduce` returns `false` (the default `reduce` is a no-op), so the per-instruction reduction hook is skipped on every non-budgeted run; the one host declaring `true` is the runner's `BudgetContext`.
**No `ets:*` key is intercepted or re-implemented in `beam_rt`**: `try_native` has no `ets` arm, `FLOOR_MODULES` excludes `ets` and no NIF backs it, so every `ets:*` key reaches the `beam_bifs` registry shadowed by nothing; the one `ets`-family special case is *bookkeeping, not interception* — `call_bif` routes `ets:new/2` through the **same** `call_registered` implementation and then observes the created `named_table` to index it for owner-death reclamation (`runtime::ets_owner::adopt_created_table`).
**`resolve_external_call` — the in-machine cross-module call seam.** `RuntimeContext` overrides it so a `call_ext*` callee runs **in the caller's machine** (the engine stores the caller's return address, then enters the callee's export label) instead of recursing through `call_bif` → `run_export`; that is what lets a `receive` inside a cross-module callee **suspend** (`proc_lib:start/4`/`start_link/4` answer `{ok,pid}`, `../tests/proc_lib_start.rs`) instead of folding into the uncatchable `error::blocked()`.
It returns `Some((arc, label))` only for an import runnable in this machine: `arc` is the **same** `Arc<Module>` held by `CodeServer::modules` (contexts dedupe by `Arc::ptr_eq`, so cloning it is a correctness bug) and `label` is `arc.export(atom, arity)` — the label *after* `func_info`; an unknown label is the typed `unknown_label`.
It loads an uncached callee on demand (`find_module_file` + `code_server.load`) and returns `Ok(None)` (keeping the synchronous `call_bif` path byte-for-byte) for a floor-served name (`native::floor_shadows`, **key-granular**: `io` is the one `FLOOR_MODULES` namespace where the floor owns only `io:put_chars/1,2`), a NIF-loaded module, a `beam_bifs` registry key, a callee that observes its own call site, a foreign/unknown export and an unknown label.
`callee_observes_its_call_site` is **module-wide** for `erlang:load_nif/2` and **per-function** for the fun-image BIFs `erlang:term_to_binary/1,2`/`erlang:external_size/1,2`, which must stay synchronous so the function cannot park with an unpublished `Machine::pending_exception`.
The seam **exempts a built-in NIF library** (`crate::native::prim_tty::is_builtin_library`, A.7's `prim_*` family) from the module-wide verdict: it registers nothing, so refusing it would only fold its wrappers' blocking `receive` into the `blocked()` gap.
**`resolve_local_fun` — the in-machine fun-apply seam (`call_fun`/`call_fun2`).** `local_fun_target` returns `Some((module, label))` for a `.beam` **local** (`make_fun3`) closure (`module` = the **same** `Arc<Module>` the code server caches; `label` = the lambda's `FunT` entry label).
A fun with no local closure goes to `external_fun_target` (`apply.rs`): an **external** fun (`fun M:F/A`) has no closure but its identity *is* the callee's `M:F/A`, so it resolves to that module's export label through the cross-module seam's **own** `resolve_external_call`, admitted under the same refusals; `Ok(None)` remains for the fun kinds with no in-machine entry (the `-eval` closure `EVAL_FUN_UNIQ`, and any external fun the resolver refuses), keeping the value-returning `apply_fun` fallback byte-identical.
The engine consults the seam **first**: on `Some` it places the closure's free variables in `x(arity..)` (C's order — the order is flagged as a possible `gen_server` init mis-entry, see *Notes for Agents*) and enters the lambda body **in the calling machine**, so a `receive` inside the closure suspends *this* process and a raise lands in the caller's live `try`/`catch`; entering an external fun in the calling process (as C's `call_fun` does) is what lets `gen_server`'s `fun Mod:handle_call/3` callback suspend *this* process (`RunOutcome::Wait`).
**Resume contract:** `resume_outcome` takes the run's ENTRY module; the suspended `(func, pc)` live in `Machine::context`, and `reset` — not `resume_outcome` — clears contexts; a fun-bodied process entry resolves its own `LocalFunTarget` once and enters via `run_label_outcome_with_tier`.
**The heap seams.** `alloc_words`/`alloc_words_rooted`/`heap_available` (`gc.rs`) serve a scheduled process from its **own** young heap: `alloc_words_rooted` collects over the machine's handed-in root set on a bump failure, the unrooted `alloc_words` is handed no root set and **never collects**, and the engine's doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`) collect and grow the nursery to fit an oversized request (`Process::ensure_capacity`, when `HeapPolicy::next_words(need,0) >= need`; a bounded `+hmax` below it falls back to `Process::collect()`) — see *Known Issues* for the arena fallback and its soundness valve.
**Registry precedence (gotcha).** The native floor runs *before* the registry (a `beam_bifs` entry can never shadow a floor-served key) and the registry *before* the external-module load (a registration shadows the fallback for a non-`erlang` name, while an `erlang:*` one flips the unregistered answer — bare `error::undef`, or `unsupported` when curated in `error::KNOWN_UNIMPLEMENTED_ERLANG_BIFS`).
### In-machine execution-position door (`position.rs`)
A process's execution-position items (`process_info/1,2`'s `initial_call`/`current_function`/`current_location`/`current_stacktrace` plus `catchlevel`) are read out of the [`Machine`](beam_engine::Machine) that owns its frame (see `../native/memory`).
The scheduler **takes the executing process's machine out** of [`RunnerState`](crate::runner::RunnerState) for the whole slice, so the runner-state view that answers *every other* pid cannot see the caller's own machine — the case `gen_server:handle_common_reply/5`'s `?STACKTRACE()` macro needs.
`beam_engine`'s defaulted `wants_bif_in_machine`/`call_bif_in_machine` seam (funnelled through `Machine::dispatch_bif_call` on **both** tiers) hands an opted-in host the live `&Machine` and the run's entry module on every BIF dispatch; `position.rs` opts in narrowly — `in_machine_probe` answers `true` (the engine latches it **once per run**) and `dispatch_in_machine` rejects every dispatch that is not an `erlang:process_info/1,2` with one string compare.
**Only** for such a query whose first argument **is** the executing process does it read the five machine-sourced values once (`machine_position`, against the run's entry module) and publish them in the runtime-owned slot `Runtime::in_machine` for the duration of the nested `call_bif`, clearing it immediately after; `../native/memory`'s `position_value`/`catchlevel_value` consult that slot first via `in_machine_value` (the published terms need no root set — no collection can run while a BIF call is in flight — so the window is exactly one nested `call_bif`).
Everything else (another pid, a nested query while an outer door call is in flight, a pid-less argument, a name the machine does not source, a machine with no such position) falls through to the ordinary `call_bif`, so a typed gap stays a typed gap and no frame is ever fabricated.
Both overrides live in `execution.rs`; the runner's `BudgetContext` carries them onto the **scheduled** path.
### Reference-alias send destinations (`alias.rs`)
A `send` destination that is an **internal reference** is resolved as an alias: the message goes to the alias **owner** and the reference is consumed after a successful delivery (`reply_demonitor`), while an `explicit_unalias` alias survives.
One helper serves **all three** entry points — `alias_destination(runtime, table, to) -> Option<(ProcessId, MonitorRef)>` — classifying by **provenance first** through `Runtime::local_reference(to)`: a monitor/alias reference `Some(Some(_))` is the only shape looked up via `table.resolve_alias`; a bare `make_ref/0`/timer/`seq_trace` reference `Some(None)` is never an alias; unknown provenance `None` (a decoded or received copy) falls back to `MonitorRef::from_eterm(to)` then `table.resolve_alias`.
* the BIF route (`erlang:send/2`, `'!'/2`) — `SendBridge::resolve` picks the table (`mailbox_table` else `&runtime.processes`) and `SendHook::send` consumes the reference through the **same** table after delivery;
* the compiled `Dest ! Msg` route — `resolve_send_destination` (an inherent method, **not** on the `ExecutionContext` trait) is used by `send_message_with_off_heap`, which consumes the alias right after a successful delivery and before the trace events — what `gen_server:reply/2`'s `Alias ! {Tag, Reply}` compiles to.
The same classifier resolves a **remote** destination (`SendDestination::RemotePid`/`RemoteName`) and `deliver_remote` transmits it over the connection the runtime is a node on; `resolve_send_target` is a `#[cfg(test)]`-only local wrapper.
C arm reproduced: `send_altact_message` (`bif.c:2478-2492`) + `handle_altact_msg` (`erl_proc_sig_queue.c:6009-6112`).
The two reference id spaces are **bridged, not unified** (`Runtime::refs` for `make_ref/0`/timers/`seq_trace`; the `ProcessTable`'s own allocator for monitors/aliases); the typed-`badarg`-vs-silent-drop divergence and the reference-**identity** hazard are in the module docs and the crate `Known Issues`.
### `call_registered` — nine dispatch arms, the lent/held `TableRegistry`, the port provider
`call_registered` builds **one** `BifContext` and installs on **every** arm the cheap handles — the atom interner (`PendingInterner`), the port provider (`RuntimePorts`) and the `Copy` `NodeIdentity` hook.
The `TableRegistry` is installed from **two** sources, in precedence order:
```rust
let reentrant = Self::reentrancy_capable(args);          // an argument is a fun
let install_tables = !reentrant || Self::tables_capable(module, function, arity);
// A LENT registry wins and is installed for EVERY nested call; the shared cell is then
// not consulted at all (the outer fold holds it for its whole duration).
let mut held_tables = if lent_tables.is_none() && install_tables {
    tables_handle.try_borrow_mut().ok()
} else {
    None
};
let mut tables = match lent_tables.as_deref_mut() {
    Some(lent) => Some(lent),
    None => held_tables.as_deref_mut(),
};
```
* **lent** — the one live `&mut TableRegistry` an outer `BifContext::call_fun` handed the [`FunBridge`](#the-nine-bridges) for one nested call. The outer `ets:foldl/3`/`ets:foldr/3` `take`s it out of its own `BifContext` before applying the fun, so the lent `&mut` is **exclusive by construction** and installing it cannot alias; it is installed for **every** nested call (not gated by `install_tables`), which carries it through a reentrant intermediate that installs no cell of its own (`ets:foldl` fun → `lists:map` fun → `ets:lookup`).
* **held** — otherwise the shared cell, held exactly when this call needs it. A reentrant call that itself reads the seam (the two `ets` fun-folds) holds it; a reentrant call that does **not** read the seam installs nothing, leaving the `RefCell` free for the fun it applies to re-enter and reach `ets:*` (that is why `lists:map(fun(X) -> ets:lookup(T, X) end, L)` works).
`try_borrow_mut` (never `borrow_mut`) stays the rule: an unexpected outer borrow degrades to "no ETS", never a panic.
`reentrancy_capable` keeps its own, separate meaning: it gates the result rewind (`safe_to_rewind`, `false` for the six heap-retaining arms and for any reentrant call).
`tables_capable` (`dispatch.rs`) names the seam's consumers, derived from `beam_bifs` (read-only; `src/ets*.rs`): **every registered `ets:*` verb** (each resolves its handle through `resolve_handle`/`take_table_gated`, all reading `ctx.tables()`) plus the two `erts_internal` raw-walk aliases `ets_raw_first/1`/`ets_raw_next/2` (the C's aliases of `ets:first/1`/`ets:next/2`).
Intersected with the fun-argument predicate this yields exactly the two fun-folds — which take the table out of the registry before applying the fun, so they must hold (or lend) it, else `ctx.tables()` is `None` and they raise the typed `unsupported_bif`.
#### The nine bridges
Exactly **one** bridge is selected, first-match, from the `DispatchHooks` the caller's `dispatch` memo computed — one boolean per `uses_*` predicate, so no predicate runs per call. Each bridge owns a different runtime borrow, so they cannot co-exist.
* **`DictBridge`** (`DictHook`; `uses_dict`) — the process dictionary over the **running process's** `beam_process::Dict` (the pass table, else the runtime's): `put/2`, `get/1`, `get/0`, `erase/1`, `erase/0`, `get_keys/0,1`; a missing pid is `error::no_mailbox`.
* **`ProcessBridge`** (`ProcessHook`; `uses_process_hook`) — `whereis/1`, `register/2`, `unregister/1`, `registered/0`, `is_process_alive/1`, `processes/0`, `ports/0`, `process_flag/2`, `group_leader/0` over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>` (`process_info/1,2` is intercepted by the floor first; the per-process `group_leader/2` pair is served by the floor).
* **`NifBridge`** (`NifLoader`; `uses_nif_loader`) — `erlang:load_nif/2`, checked **before** the filesystem; a reload of an already-loaded module is `NifLoadError::Reload`; a load failure is mapped variant-for-variant and **returned**, never raised. Its long-lived host is built with `services = None` (it moves into the runtime's `NifRegistry`) and `crate::info::schedulers_count(runtime)` as its `scheduler_threads`, so a `load`/`unload` callback's `system_info` stays honest and every `NifHostServices` hook stays the typed default there.
* **`RecordBridge`** (`RecordSource`; `uses_record_source`) — `records:get_definition/2` from the loaded module's `Recs` chunk (`Module::record_by_name`), field atoms name-resolved; unloaded module / undeclared record ⇒ `Ok(None)` ⇒ the oracle's `badarg`; an unresolvable field atom is a typed `TermNotFound`.
* **`SendBridge`** (`SendHook`; `uses_send_hook`) — `erlang:send/2`/`'!'/2` delegating to `send_message` (the return value **is** the message term; a send to a pid with no process succeeds silently; a non-pid-like destination is `badarg`; a registered name is delivered; a **reference alias** goes to the alias **owner**).
* **`ModuleInfoBridge`** (`ModuleInfo`; `uses_module_info`) — `erlang:get_module_info/1,2` from the loaded module's IR.
* **`PersistentTermBridge`** (`PersistentTerm`; `uses_persistent_term`) — the seven `persistent_term:*` BIFs over the runtime's shared store (a cheap `Rc<RefCell<..>>` clone with **no** runtime borrow), holding raw `Eterm` words (safe while the heaps stay pointer-stable; a value that must survive a heap move is stabilized through `Runtime::try_stabilize_escaped`).
* **`RuntimeHooksBridge`** (`RuntimeHooks`; `uses_runtime_hooks`) — partly serves the **172**-key `beam_bifs::RUNTIME_HOOKS_BIFS` roster; it holds `&mut Runtime` **plus** `Option<&mut ProcessTable>`, so it is its own arm (`timeout` is a `boot::CORE_ATOMS` seed, the shared table being borrowed immutably for the whole call). Served: the timer family (`start_timer/3,4` → `{timeout,TRef,Msg}`; `send_after/4` incl. the `{abs,true}` form; `cancel_timer/2`), `function_exported/3` (the declared `bif.tab` surface plus the registry extras OR the loaded module's export table), `link/1`/`unlink/1` (the `ProcessTable` link set; a **remote** pid routes through `link_term`/`unlink_term` to the installed `DistSignalRouter`, the only gap being a peer with no established link), `os:set_signal/2`, `net_kernel:dflag_unicode_io/1`, `erts_internal:scheduler_wall_time/1` (arms/disarms the node-global sampling switch, answering the **previous** state; drives no sampling, so `statistics(scheduler_wall_time)` stays `undefined`), `erts_internal:erase_persistent_terms/0` and `statistics/1` (`run_queue`, `wall_clock`, `reductions`/`exact_reductions`, `context_switches`, `io`, `garbage_collection` — the node-global cumulative counters, see *GC accounting*); other served keys are **fixed oracle-absent answers** (the truthful fixed answers — [`IMPLEMENTATION.md`](IMPLEMENTATION.md)), and every other roster key is the typed `unsupported_bif` (closable ones in [`IMPLEMENTATION.md`](IMPLEMENTATION.md)) or is served **earlier** by the floor (`alias/0,1`/`unalias/1`, the four `erl_ddll` keys); a key outside the roster is bare `error::undef`.
* **`FunBridge`** (`FunCaller`; the fallback) — `apply_fun` over `&mut Runtime`, carrying a clone of the caller's `SharedSink`, the mailbox identity, the scheduler-pump permission and `current_module`. It builds the nested context in one private `nested<'b>(&'b mut self, lent_tables: Option<&'b mut TableRegistry>) -> RuntimeContext<'b>`, shared by both seam entry points so they cannot drift: `call_fun` passes `None` (the nested `call_registered` then borrows the shared cell, free because the outer call installed nothing), and the overridden **`call_fun_with_tables`** passes the outer `BifContext::call_fun`'s lent `&mut TableRegistry` verbatim.
`NodeIdentity` answers this runtime's **own** node — `Runtime::local_node()` (the live `node@host` atom on a `-name`/`-sname` node, else `nonode@nohost`), creation `0`, plus the real `local_node_hash` (see [the node hash](#the-node-hash-a2--node_hashrs)) — emitting `NEW_PID_EXT` (`88`) for an internal pid and `V4_PORT_EXT` (`120`) for an internal port; the **decode** direction installs the same identity (`Decoder::with_local_node`) and demotes a local-node `NEW_PID_EXT`/`V4_PORT_EXT` to the internal id, so `binary_to_term(term_to_binary(self())) =:= self()`.
`FunIdentityBridge` supplies the identity a **compiled module's** fun hands to the `LocalFunIdentity` seam, on the `uses_fun_identity` arm (`term_to_binary/1,2`, `external_size/1,2` and the introspection pair `fun_info/1,2`). For a `make_fun3` (`FunKind::Local`) argument it derives the `NEW_FUN_EXT` (`112`) image from the code server's **cached** loaded-module snapshot (`CodeServer::fun_module_snapshot`, scanned **caller-first**) plus the node atom — `Ok(None)`, never an error, for a context with no calling module (the `-eval` evaluator), an unreadable `.beam`, or a fun no loaded module defines; otherwise module atom + module MD5 + `old_index`/`old_uniq` from `FunT` + the `FunT` entry's `function` (the `name` item) + the fixed `<0.0.0>` creator. An `External` fun and a non-fun are the clean `Ok(None)`; a decoded `Imported` fun resolves only its `name` (see the `fun_identity.rs` routing entry).
`RuntimeMemory` (the `MemoryHook`) is built only on the `uses_memory_hook` arm (`erlang:memory/0,1`); ungated its `code_bytes` snapshot (a `CodeServer::loaded()` clone+sort plus a `stat::metadata` per module) would cost ~13 µs on **every** registered call.
### GC accounting — `erlang:statistics(garbage_collection)`
`erlang:statistics(garbage_collection)` (`runtime_hooks.rs::garbage_collection`) answers `{collections, reclaimed, 0}` — the C's `gather_gc_info_result/1` shape (`../../erts/preloaded/src/erlang.erl`), the third element the reserved `0` — from the runtime's **node-global cumulative** counters on `Runtime::gc_stats()`.
`collections` counts every collection this runtime really ran; `reclaimed` (in words) is advanced by **every** collection site — `Runtime::serve_gc_request` (`../runtime/gc.rs`) and the three `src/context/gc.rs` collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`) — each recording its own collection's `Collection::stats.words_reclaimed` through `Runtime::note_gc_reclaimed`, never an estimate.
Both are this runtime's own work since *its* start, the same class as `reductions`/`context_switches`, where the oracle's are per-scheduler accumulators of a far larger emulator: the quantities match, the magnitudes do not.
### The node hash (A.2) — `node_hash.rs`
`term_to_binary(Term, [local])` must stamp the node's `LOCAL_EXT` (`121`) image, whose first four payload bytes are the VM's node hash; `beam_bifs`' `binconv.rs` (`encode_image`/`plain_image_of`) asks the `LocalNode` seam for it and, on `None`, returns the typed `unsupported_bif` gap.
The C computes it **once per VM start** in `erts_late_init_external` (`../../erts/emulator/beam/external.c:136-200`): a buffer of `time_offset(8 LE bytes) || hostname || pid-string` hashed by the Bob-Jenkins **block hash** seeded with `(Uint32)(mtime & 0xffffffff)`, stored in a `static Uint32 local_node_hash` — **per-start and node-local by design**, hence never byte-comparable across runtimes.
`node_hash.rs` reproduces that shape from real process/host state, self-contained under this node and stable for the whole OS process:
* `node_hash() -> u32` — the **one** value per OS process (`static HASH: OnceLock<u32>`), mixing `clock_nanos().to_le_bytes() || hostname() || std::process::id().to_string()` with the seed `clock_nanos() as u32`. `clock_nanos()` is the wall-clock reading in nanoseconds since the epoch (the C's monotonic clock is unreachable without a clock dependency; a pre-epoch system clock only makes that field `0`, the hash still mixing host and pid).
* `hostname()` resolves from real host state with no new dependency: `/proc/sys/kernel/hostname`, then `HOSTNAME`, then `COMPUTERNAME`, else the empty string — the C's own answer when `sys_get_hostname` fails.
* `block_hash(bytes, seed) -> u32` is a self-contained port of the C's `erts_block_hash_init`/`erts_block_hash` (`erl_term_hashing.c:427-501`): 12-byte blocks, `HCONST = 0x9e3779b9`, the 9-round `MIX`, the buffer's full length added into `c`, the descending-shift tail fold, a final `MIX` answering `c`.
`NodeIdentity`'s `LocalNode::local_node_hash` returns `Some(node_hash())`; `beam_codec`'s `Encoder::finish_local(hash)` writes `[VERSION_MAGIC][LOCAL_EXT:121][hash:4 BE][body]`.
**A differential case covering `[local]` must MASK the four hash bytes** and compare the rest (the value differs per VM start on **both** runtimes); `../tools/differential` (read-only sibling) still records `[local]` as an honest gap — adding the case is theirs.

## Constraints
* **`unsafe`-free by default**: the crate is `#![deny(unsafe_code)]`, with two narrowly-scoped exceptions (`gc_walk.rs`'s `beam_term::layout` object-walk; `../nif.rs`'s `enif_compare`/`enif_hash` `unsafe extern "C"` calls). The glue otherwise uses only the safe peripheries of the lower crates.
* **Return-based errors, no silent swallowing** ([`../../CONTEXT.md`](../../CONTEXT.md) §3): every fallible helper returns `beam_common::Result`; no `panic!`/`unwrap()` on runtime data.
* **Call down, never duplicate**: a BIF is served by `beam_bifs`/the native floor, never re-implemented here.
* **Never fabricate a value**: a seam answer is either real state or the typed gap — `NodeIdentity`'s creation stays the truthful `0`, and the node hash is a genuine per-process computation, never a constant.
* **A lent `&mut TableRegistry` is exclusive by construction**; the shared cell is never consulted while one is lent, and `try_borrow_mut` (never `borrow_mut`) is the only way this node touches it.
* **Dispatch cost is first-class**: every handle built in `call_bif`/`call_registered` must be gated by its own `uses_*`/`needs_*` predicate, and every per-call input the prologue derives belongs in the `dispatch` memo (an input that can change during a run — the NIF registry — must stay out). Measure with [`../../examples/perf_call.rs`](../../examples/perf_call.rs) (figures in [`../../PERF.md`](../../PERF.md)); `../../examples/perf_bif.rs`'s `pc:*` fixture lowers to an inlined `gc_bif` and **cannot** measure registry dispatch.
## Known Issues
The measurement narrative behind these entries is in [`../M1_GAPS.md`](../M1_GAPS.md) and [`../../PERF.md`](../../PERF.md); every entry is a typed capability gap or a measured own-state difference, never a wrong result.
* **The float guard lives on the narrow door alone; the full doors are FR-safe.** The engine reaches only `ensure_heap_full` (`Machine::ensure_heap`/`test_heap`/`allocate_heap` → `ExecutionContext::ensure_heap_full` → `arm_gc`), which publishes and scatters the machine's **whole** `RootSet` — every x slot, the whole stack and the whole FR file (`fr_count = roots.fr.len()`) — so a live float register is relocated like any other root and the full doors consult **no** caller-module float test. The **narrow** `ensure_heap` sees only an x prefix and the stack, so its caller-module guard (`module_may_be_collected` → `module_uses_floats`, matching `Instr::{Fmove,Fconv,Fadd,Fsub,Fmul,Fdiv,Fnegate}`) is load-bearing there and stays — the narrow door is not on the engine's path today. All four doors refuse a run with **no** caller module (a fun entry, the `-eval` evaluator): no machine to name, left alone rather than guessed.
* **Both heap-admission doors OR the occupancy test with the collector's collection debt.** `Process::grow_nursery` retires the young space it replaces instead of freeing it, so a growth-shaped workload keeps its whole allocation history resident in the retired chain until a real collection evacuates it; the doors therefore collect when `forced || should_collect(need) || collection_debt()`. `should_collect` stays the **occupancy test alone** (pinned as such by its own unit tests).
* **A slice's live float register is handled by a per-slice relocation exemption — never a permanent pin.** A slice ending with a live FR prefix (`Machine::fr_mark() > 0`) marks the process relocation-exempt for the inter-slice window (`src/runner/run.rs` `process.set_relocation_exempt(true)`), and the next slice entry clears the mark (`set_relocation_exempt(pid, false)`), so `Runtime::gc_stats().pinned` stays **0** and a float-using loop's `collections` **scale** with N; the guard is decline-only and bounded — a delivery into the window takes the ordinary heap-fragment fallback, and the process's own admission point collects as soon as the resume has cleared the mark — so nothing grows unboundedly. Inside a slice the engine reaches only the **full** heap-admission door, which publishes the machine's whole `RootSet` (FR file included), so a float-using call site collects exactly like a float-free one. This node's valve does **not** decline a float root: the engine's FR model holds *terms* built on the executing process's own young heap (`alloc_words` → `beam_term::thing::write_float`), so `fr[0]` is a **scanned** root (`a_live_float_term_in_fr_is_a_scanned_root`). Measured (`the_post_slice_float_pin_plateaus_a_float_using_loops_collections`, the in-file deterministic rig): three `ets_copy` allocate-and-abandon loops all **scale with N and pin nothing** — a float-free row, a float-**literal**-payload row (the compiler folds the literal into the literal area, so it adds **no** float-family instruction and never writes FR — "a module with a float literal writes FR slot 0" is **false**), and a genuinely float-using row (`fconv`/`fmul`) — `pinned` is 0 everywhere and each larger run collects strictly more than its smaller twin.
* **A scheduled slice's out-of-line nested run cannot pump the scheduler, so a callee that parks in a `receive` is the typed `blocked()` gap.** Such a cross-module call goes `call_bif` → `run_export` → `run_export_blocking` (a fresh `Machine` on the same pid under a `for_process*` context, so `may_pump_scheduler()` is `false`) and `pump_once` returns `Ok(None)` **on its first line**, folding the parked callee into `beam_engine::blocked()` (uncatchable) whether or not its `receive` carries an `after T` — the refusal is per `callee_observes_its_call_site`. Nothing here is a wrong result.
* **`erlang:fun_info/1,2` reads the `LocalFunIdentity` seam, and its `name` item comes from two wiring sites here.** `bridges.rs::local_fun_identity` attaches the `FunT` entry's `function` to the derived `FunIdentity` for a compiled `make_fun3` fun (`with_function`; introspection-only, so the `term_to_binary` bytes are unchanged); `fun_identity.rs::imported_identity` resolves a decoded `NEW_FUN_EXT` fun's `name` from the loaded module named by the term's own `module` atom, requiring `descriptor_position(module, old_uniq, index) == Some(old_index)`. Both are reachable only on the `uses_fun_identity` arm, which `reads_fun_identity_for_introspection` extends to the `fun_info/1,2` pair (`beam_bifs`' roster names only the two encoders). Residual: an imported fun whose **defining module is not loaded** is the typed `unsupported_bif` gap where the oracle reports `{name,[]}` (C `mfa == NULL ⇒ NIL`) — the seam has no `NIL` to hand over; pinned by `an_imported_funs_unloaded_defining_module_is_the_typed_gap_not_an_empty_name`, never a fabricated name.
* **A parked machine's live `Machine::pending_exception` reason IS a GC root across the park window.** It is a machine *field*, not an `x`/stack/FR slot, so the closed `RootSet` shape cannot carry it; `src/runner/run.rs::publish_parked_roots` publishes it as the process's `Registers::extra_roots` word (`gather_roots`/`scatter_roots` relocate it in place) and `resync_parked_roots` reads the relocated word back into `pending_exception_mut()` and clears the extra roots.
* **The fun-image half of `callee_observes_its_call_site` is per-function.** Guarding `term_to_binary/1,2`/`external_size/1,2` only in the function that issues the call (`load_nif/2` stays module-wide) admits `compile:*` to the in-machine route on the **scheduled** path, and both A.9 `selfhost/*` corpus cases agree with the oracle on both tiers. A signal-driven collection there is declined by the runner's **park-window relocation exemption** (the delivery takes the heap-fragment fallback); evidence owed to `beam_process`'s signal sites: [`../EPP_SCHEDULED_ROUTE_FINDINGS.md`](../EPP_SCHEDULED_ROUTE_FINDINGS.md).
* **The arena fallback is kept sound by a two-phase unscanned-root valve.** An arena block is a container in a region the collector does not scan, so the valve **declines** (`Ok(())`) any collection whose root set — or whose process-side scanned graph — reaches one, at each of the four collection sites (`ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`, the runner's park arm `Runtime::serve_gc_request`); the fallback count is `note_gc_fallback`'s. Phase 1 (`root_is_unscanned`, always run) calls a term safe exactly when it is an **immediate**, a **literal** or a pointer the collector **scans** (any nursery space, current or growth-retired, or the mature generation); phase 2 (`gc_walk.rs`) descends the process's scanned graph and root containers under the sticky per-pid latch (`Runtime::foreign_reachable`), so a foreign container at depth ≥ 2 is found. A term in a foreign region (pooled BIF heap, arena, `-eval` heap, message fragment) declines the collection — **except** a registered-BIF result, which `call_registered` copies onto the running process's heap and rewinds the pool to the call's own `mark` (`Heap::reset_to`), making it a scanned root rather than a foreign holder.
* **A module-literal root no longer declines the collection: `beam_loader` load-time tags the literal area.** `payload/0` is a constant, so `erlc` folds it into the **literal area** (`{move,{literal,#{…}},{x,0}}`), and the loop's only live root `x(0)` at the `test_heap,3,1` after `ets:lookup/2` IS that literal pointer.
  `beam_loader`'s `LiteralArea::decode` (`beam_loader/src/literal.rs:124`) calls `beam_term::literal::tag_literal_area` — the safe form of the C load-time `erts_set_literal_tag` (`../../erts/emulator/beam/erl_term.c`) — before publishing the arena, so every boxed/list word a module's `LitT` chunk lowers to, and every literal root the engine is handed, carry `TAG_LITERAL_PTR` **set**.
  [`gc.rs`'s `root_is_unscanned`](gc.rs) classifies a literal by the C's own `erts_is_literal` rule — a bare bit test (`gc.rs:237` → `beam_term/src/literal.rs:41`) — so a **tagged** literal is an immutable, never-moved region the collector does not scan and the valve **passes**: the constant-payload loop (the `copy_bound/ets_copy` shape) reaches its heap-admission points and its `collections` scale with N.
  The untagged-decline path survives only as a **unit construct**: `tests.rs::an_untagged_literal_root_declines_the_collection_until_the_loader_tags_literals` builds an arena the tagging step never touched and asserts `collections == 0`; its companion `tests.rs::a_tagged_literal_root_is_scanned_and_the_loop_collects` (`:6899`) pins the load-time-tagged (collecting) behaviour.
  Tagging also removes a shared-literal corruption hazard: an untagged literal is silently **writable** (`beam_engine/src/terms/update.rs:67` refuses an in-place tuple write only when `is_literal` holds; `beam_ets/src/store/mod.rs:158` reads the same bit).
* **`erlang:memory/0,1` reports `0` for `processes`/`processes_used` on the `-eval`/single-pass path.** `RuntimeMemory::new` sums each live process's collector capacity (nursery + mature) and used words, so the scheduled path counts both generations; the `-eval` path has no `Process` (it allocates on `Runtime::arena`, whose private `Arena` exposes no word accessor), so both are an honest `0`; closing it needs a `MinimalContext` arena-words accessor plumbed through `Runtime` (owner `beam_engine`).
* **`ProcessBridge` reads real state; one typed gap and two documented divergences.** All 11 `ProcessHook` methods read `ProcessTable`/`Runtime` directly; the `erlang:ports/0` typed gap (a `try_borrow` failure) is reachable only on a **nested** path, because `call_registered` hands the arm a **separate `Rc` clone** of the port registry, so production `ports/0` works; and `register/2` with a **port id** is a typed gap (the table registers pids only) while `process_flag(save_calls, V)` returns the previous value for a non-boolean/non-small `V` where the oracle raises `badarg`, and `process_flag(error_handler, Atom)` always answers `error_handler`.
* **`NodeIdentity` carries this runtime's live node atom but a hard-coded creation `0`.** The atom comes from `Runtime::local_node()`, so `node/0` and a pid's `NEW_PID_EXT` image name a `-name`/`-sname` node correctly; the `epmd`-assigned creation is not carried. The `local_node_hash` half **is** real.
* **The `erlang:send/2`/`'!'/2` BIF path cannot see the sending machine's in-flight refc-binary handles.** `send_source(Some(self.mailbox_pid), extra)` unions the three families a *delivery* can resolve (`extra`, the runtime's escaped-payload store, the sender's mailbox-retained families), but the BIF route reaches it with `extra = &[]`: the in-flight `Machine` is out of `RunnerState.engines` for the whole slice and neither `ExecutionContext::call_bif` nor `SendHook::send` carries a handle parameter. So a term the *running* machine just built off-heap and forwards from a BIF callee **flattens** (a correct but unshared copy); only the compiled `Dest ! Msg` instruction carries the machine's handles. Closing it needs a sibling change: thread the sender's handles into `call_bif`/`SendHook::send`, or expose `Machine::refc_binaries` through a shared cell.
* **An enqueue-time control signal refused by the receiver's full nursery is built into a heap fragment and the message arrives.** The refusal is `Process::has_unpublished_roots()` (`relocation_exempt || state == Running`) or a receiver the host's `CollectionGate` declines; `beam_process`'s `copy_reason_onto`/`enqueue_down_signal`/`enqueue_exit_signal` pre-test both, hand the raw `Alloc` refusal back with **no** collect, grow or retry, and turn the `{'DOWN',…}`/`{'EXIT',…}` into a fresh `HeapFragment`, so the signal arrives with the receiver's heap neither collected nor grown. The only refusal still surfaced is an **exit** signal to a **non-trapping** receiver (it carries the exit *policy*; terminating the receiver is the caller's cascade). Pinned by `../../tests/eval_exempt_receiver_signal.rs`.

## Notes for Agents
- **Layout: `mod.rs` is root-only plumbing over concern-scoped submodules** (module `//!` overview + submodule map, `mod …;` declarations, crate-visible re-exports, `#[cfg(test)]`-gated name plumbing; no logic). Because Rust forbids a second `impl ExecutionContext` (E0119), the seam lives in **one** block in `execution.rs`, its methods delegating to inherent helpers in the sibling that owns the concern. Three siblings exceed the ~1000-line target — `runtime_hooks.rs`, `gc.rs`, `bridges.rs` — each one cohesive pre-existing concern documented at its own top; `tests.rs` is the node's deliberately single shared unit suite. The names `tests.rs` and `pump.rs`'s inline `mod blocking_fun_apply` reach through `use super::*;` are re-imported in `mod.rs` under `#[cfg(test)]`; `DispatchMemo` alone stays ungated.
- **The nested blocking pump is wall-clock bounded, and a finite `receive … after T` it must wait out itself.** `run_export_blocking`/`run_label_blocking` drive a suspended callee's `receive` through the shared `pump_until_returned(limit, outcome, step)` driver (`pump.rs`), one `pump_once` round per wait. For an ordinary (no-deadline) parking `pump_once` advances the scheduler by `RUN_EXPORT_PUMP_SLICES` slices through `Runtime::pump_scheduler_boot` — the **imminent-only** wait policy, so a round whose only pending deadline is far out returns unslept instead of stalling the caller — and a pump reporting nothing ran ends the drive with the honest `beam_engine::blocked()` gap. The engine arms no timer for a `wait_timeout` and a nested run is not a scheduled process, so for a statically readable finite `after T` `pump_once` recovers the deadline through `Machine::wait_deadline` and, on an empty run queue, sleeps `min(remaining, DEADLINE_PUMP_SLEEP)` and re-pumps until the wall clock reaches `start + T`, then resumes at the `timeout` continuation (a message arriving first wins). The loop ends on return, on a step reporting `Ok(None)`, or at the `BLOCKING_PUMP_DEADLINE` (60 s) cap — the nested counterpart of the boot drive's `DRIVE_DEADLINE`, reported as a typed `error::message(...)` and sized ≈ 2.5–3× the heaviest legitimate workload on this route (the in-process compile of `lists.erl`); the deadline path is exercised only through the injectable `limit`.
- **Closure application is entered in-machine through the `resolve_local_fun` seam for a context the engine drives directly**; the engine's `Ok(None)` fallback is the value-returning `apply_fun`, whose `Some(LocalFunTarget{..})` arm enters a closure through the blocking-aware `run_label_blocking`, so on a route that **may** pump such a closure still suspends and resumes. **A scheduled slice's machine runs on the runner's `BudgetContext` wrapper**, which forwards `resolve_external_call`, `resolve_local_fun` **and** `resolve_local_call`, so a blocking local closure applied from a scheduled process enters in-machine and is resumed by a real send, and a same-module local `call` the host serves is dispatched as a BIF through `call_bif` (`resolve_local_call` → `crate::native::prim_tty::serves_local_call`) instead of being jumped into the module's non-exported Erlang stub body. Pinned by `../../tests/scheduled_apply_seam.rs`; the A.9 case `boot/proc_lib_start_link_blocks_the_boot_path` agrees with the oracle.
- **`local_fun_target`'s free-vars-then-args closure argument order** (`apply.rs`) is flagged in the `beam_engine` handoff list as a possible mis-entry of `gen_server`'s init closure; no boot directive implicates it, so it needs a focused test before any change.
- **`send_source` is the one place a delivery builds the copy's source off-heap table — keep both delivery paths going through it.** `send_message_with_off_heap` calls it with `Some(self.mailbox_pid)` (the sender: the full three-family union) and `deliver_message` with `None` (store-only), because `deliver_message`'s context is built `for_process` the **receiver** by `deliver_in_table` — unioning `self.mailbox_pid` there would resolve against the *receiver's* retained families, and `None` preserves the empty-source fast path, so a plain on-heap message still builds no table.
- **A `[local]` differential case must mask the four hash bytes** (per-VM-start on both runtimes); the corpus is the read-only sibling `../tools/differential`'s to extend.

* `node_hash.rs` → the node's `LOCAL_EXT` hash: `node_hash()` (the one `OnceLock<u32>` per OS process, seeded from a clock reading + hostname + pid) and the self-contained port of the C's Bob-Jenkins `block_hash` (`HCONST`/`MIX`/12-byte blocks/tail fold).
* `position.rs` → the in-machine execution-position door: `InMachinePosition`, `in_machine_probe`/`dispatch_in_machine` + `machine_position`, and the published-slot reader `in_machine_value` that `../native/memory` consults first.
* `alias.rs` → `alias_destination`, the shared **provenance-classified** reference-alias → (`owner`, `MonitorRef`) lookup behind all three send routes.
* `fun_identity.rs` → `FunIdentityBridge`: the `NEW_FUN_EXT` (`112`) image of a local (`make_fun3`) closure **and** the `name` item of `fun_info/1,2` for both fun kinds whose identity is not wholly on the term. `local_fun_identity` classifies through `beam_codec::term::fun_kind_term`: a `Local` term goes to the caller-first loaded-module snapshot scan, a decoded `Imported` term to `imported_identity` (which reads the identity off the wire descriptor and resolves only the **name** from the loaded module named by the term's own `module` atom, requiring `descriptor_position(module, old_uniq, index) == Some(old_index)` before reading `module.funs()[old_index].function`); an `External` fun and a non-fun are the clean `Ok(None)`. Both arms reuse `bridges.rs::descriptor_position`.
* `gc.rs` → the engine's heap-admission doors (`ensure_heap`/`ensure_heap_full`, sharing `collect_or_grow`), the allocation seams for a *scheduled* process, the two root hand-off pairs (`publish_roots`/`scatter_roots` and the whole-`RootSet` `publish_roots_full`/`scatter_roots_full`, whose `fr_count` bounds the published FR prefix), and the per-word classifier `root_is_unscanned`; a pending **forced** GC request is honoured by **both** full-root doors, so `erlang:garbage_collect()` is served even by a process whose only allocation goes through `alloc_words_rooted`: the request is peeked *before* the young-heap bump, bypasses it, runs one collection over the whole root set and is consumed exactly once at the commit point — every refusal (the process valves, a run with no caller module, the unscanned-root valve) leaves it armed for the runner's park arm, the observable behaviour of a refusal being unchanged (arena fallback). The runtime-level GC state/accounting/valves are [`../runtime/gc.rs`](../runtime/CONTEXT.md). **Debt/valve cost:** the `collection_debt()` term is folded into both doors' occupancy OR, so a growth-retired chain makes the full door evaluate `any_root_is_unscanned` on **every** admission point even when the *current* space has room; the per-word `root_is_unscanned` (`gc.rs:237`) reaches `Collector::young_contains` → `Nursery::contains` (`beam_gc/src/nursery.rs`), which iterates **every** space of the nursery chain, so a retired-space pointer costs O(chain length), and the chain is collapsed only by a real collection (`Nursery::collapse`).
* `gc_walk.rs` → the unscanned-root reachability walk: `any_root_is_unscanned`/`process_roots_are_unscanned` (phase 1 always run, phase 2 under the per-pid descent latch) + the reusable `WalkScratch` (an open-addressing, generation-tagged visited set allocated once on `Runtime`) + `RuntimeCollectionGate`, the `beam_process::CollectionGate` host seam (`Runtime::new` installs it) giving `beam_process`'s signal sites the same decision with an **unconditional** descent.
* `trace.rs` → the execution-trace seam (`call`/`return_from`/`return_to` over `ExecutionContext::trace_event`).
* `process_bridge.rs` → the `ProcessHook` arm over the real `ProcessTable` + `Rc<RefCell<PortRegistry>>`.
* `module_info.rs` → the `ModuleInfo` arm (`get_module_info/1,2` from the loaded module's IR).
* `persistent_term.rs` → the `PersistentTerm` arm (the seven `persistent_term:*` BIFs over the runtime's shared store).
* `runtime_hooks.rs` → the `RuntimeHooks` arm; its `link`/`unlink` pair classifies a **remote** pid through `link_target` and routes it via `ProcessTable::link_term`/`unlink_term`.
* `signal.rs` → the `os:set_signal/2` arm over one process-global `beam_io::SignalFacility` held in a `thread_local`; a caught signal's `{notify, Signal}` is delivered by the port layer's pumps (`../port/watch.rs` + `../port.rs`'s `take_signals`) to the process registered as `erl_signal_server`, dropped silently when none is registered — matching the C (`sys.c:589-604`).
* `memory_hook.rs` → the `MemoryHook` arm + `RuntimeMemory` (`erlang:memory/0,1`).
* `tests.rs` / `test_support.rs` → the colocated unit suite + the shared test helpers.
