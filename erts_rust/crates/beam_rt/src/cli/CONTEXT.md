# `beam_rt::cli` — the A.6 command-line surface (switch parser · `ERL_*FLAGS` merge · emulator-flag validators)

## Intent
The command-line surface of the `beam_rt` executable (contract A.6).
The parser and driver live in the sibling file `../cli.rs`; this directory holds the two concerns split out of it: the `ERL_*FLAGS` environment merge (`env.rs`) and the validators for the emulator switches that have no runtime-visible effect (`flags.rs`).
All three share two goals: a tokenized environment flag must be indistinguishable from a command-line flag, and the init-argument set must match the oracle's `init:get_argument/1`.

## API Surface
`../cli.rs` (re-exported at `beam_rt::cli`):
* `parse(args: &[String]) -> Result<RuntimeConfig>` — **pure**, never reads the process environment (the unit tests, the driver and the differential harness call it directly); it splits **its own** stream into flags and plain arguments (`env::split_plain`) and records the tails in `RuntimeConfig::plain_args`.
* `parse_with_env(args: &[String], env: &dyn Env) -> Result<RuntimeConfig>` — merges the environment, then calls the pure `parse`, then replaces `plain_args` with the merged form's plain tails.
* `run(args: Vec<String>) -> i32` — the driver; it calls `parse_with_env(&args, &ProcessEnv)`.
* `USAGE` (the usage text) and `EXIT_OK`/`EXIT_RUNTIME`/`EXIT_USAGE`/`EXIT_UNSUPPORTED` (= 0/1/2/3).
* `merge_argv`, `split_plain`, `merge_argv_with_plain`, `tokenize`, `otp_flags_var`, `Env`, `MapEnv`, `ProcessEnv` — re-exported from `env`.
`env.rs`:
* `trait Env { fn get(&self, name: &str) -> Option<String> }` — the environment the merge reads from.
* `ProcessEnv` — the production `Env` over `std::env::var`; a variable that is set but not valid UTF-8 is folded into "unset".
* `MapEnv(HashMap<String, String>)` — the fixed, unit-testable `Env`.
* `tokenize(&str) -> Vec<String>` — the `build_args_from_string` (`allow_comments = 0`) tokenizer.
* `merge_argv(args, env) -> Vec<String>` — the `initial_argv_massage` merge (the flag stream alone).
* `split_plain(args) -> (flags, plain)` — one **entity**'s `-extra`/`--` split.
* `merge_argv_with_plain(args, env) -> (flags, plain)` — the merge that keeps every entity's plain tail aside; its `.0` is exactly `merge_argv`'s result.
* `otp_flags_var() -> String` — the `ERL_OTP<sysver>_FLAGS` variable name (`ERL_OTP30_FLAGS`).
`flags.rs` (all `pub(super)`, consumed by `../cli.rs`) — **one reader per switch, named after the C call site it reproduces**:
* the integer readers `atoi` (`pub(crate)` too: the `+e` effect re-reads its value), `strtol10`, `scan_int`, `lax_int` (the allocator family's `ErtsStrToSint`).
* the scheduler-count machinery `scan_count_pair` → `resolve_scheduler_counts`.
* the per-switch validators `parse_max_ports` (`+Q`), `parse_max_processes` (`+P`), `parse_atom_table_size` (`+t`), `parse_ets_tables` (`+e`), `parse_kernel_poll` (`+K`), `parse_sbt` (`+sbt`, shared by `+stbt`), `parse_busy_wait_threshold` (`+sbwt`/`+sbwtdcpu`/`+sbwtdio`), `parse_scheduler_boolean` (`+scl`/`+spp`/`+sub`), `parse_wakeup_strategy` (`+sws`), `parse_wakeup_threshold` (`+swt`), `parse_wake_cleanup_threshold` (`+swct`), `parse_sched_thread_stack_size` (`+sss`/`+sssdcpu`/`+sssdio`), `parse_forced_wakeup_interval` (`+sfwi`), `parse_scheduler_percent` (`+SP`/`+SDPcpu`), `parse_dirty_cpu_schedulers` (`+SDcpu`), `parse_dirty_io_schedulers` (`+SDio`), `parse_emu_flavor` (`-emu_flavor`), `is_allocator_switch`/`parse_allocator` (`+M*`).
* `scheduler_value_switch` — resolves a `+s…` token against `SCHEDULER_SUB_OPTIONS` (the twenty `has_prefix` rows with their `takes_value` flag), the one family whose spelling is data rather than a table row.
* the ground-truth constants `ERTS_MIN_PORTS`/`ERTS_MAX_PORTS`/`ERTS_MIN_PROCESSES`/`ERTS_MAX_PROCESSES`, `ERTS_MAX_NO_OF_SCHEDULERS`, `MIN_ATOM_TABLE_SIZE`/`MAX_ATOM_TABLE_SIZE`, `SCHEDULER_MIN_STACK_SIZE`/`SCHEDULER_MAX_STACK_SIZE`, and the name tables `SCHEDULER_BIND_TYPES`/`SCHEDULER_BUSY_WAIT_THRESHOLDS`/`SCHEDULER_WAKEUP_STRATEGIES`/`SCHEDULER_WAKEUP_THRESHOLDS`/`SCHEDULER_WAKE_CLEANUP_THRESHOLDS`.
`vars.rs` (the `ERL_*` variables **outside** the `*FLAGS` merge; see the section below):
* `ErlEnv` — `{ inetrc, max_ports, crash_dump, crash_dump_seconds, rootdir, max_ets_tables, fullsweep_after }`, every field `Option` (`None` = unset).
* `from_env(&dyn Env) -> ErlEnv` — re-exported at `beam_rt::cli` (`pub use vars::{from_env, ErlEnv}`).
* `has_plus_q_switch(&[String]) -> bool` (`pub(super)`) — the `+Q`-wins-over-`ERL_MAX_PORTS` test.
* per-variable private parsers (`parse_max_ports`, `parse_atoi_var`, `c_atoi`) so each is unit-testable alone.

## The supported switches (the exact A.6 surface)
| Switch | Effect in `beam_rt` |
|---|---|
| `-version`, `--version` | print the version banner (OTP `30.0-rc0` / erts `17.1`) and exit 0 |
| `-noshell` | run head-less (M1 has no interactive shell) |
| `-eval Expr` | evaluate a general Erlang expression and print nothing; one trailing `.` is tolerated and stripped |
| `-s Mod Func [Args…]` | apply `Mod:Func(a, b, …)` with **atom** arguments; result discarded |
| `-run Mod Func [Args…]` | same, but arguments are plain **strings** (char lists); result discarded |
| `-pa Dir` / `-pz Dir` | add `Dir` to the code path: `-pa` **heads** it (each occurrence is prepended in turn, so the head is the `-pa` group in reverse command-line order), `-pz` **tails** it (behind the system `ebin` directories). Applied on **every** route — the bare `-boot` one included — before anything runs |
| `+S Total[:Online]` | the normal scheduler counts, read with the C's `sscanf("%d:%d")` → `sscanf(":%d")` cascade (`erl_init.c:1107-1162`): the `%d` conversion is a digit prefix and the `:` must follow it immediately, so `+S1bogus:2` is the single field `1`; a non-positive half is an **offset from the default** (`+S 0` = the processor count, `+S -1` one fewer, `+S +3` = 3) and the online half defaults to `min(total, default online)`; the resolved total must land in `1..=1024` and the online count in `1..=total` (`+S 4:5`, `+S 4:0`, `+S abc`, `+S :` are refused) → `emulator.schedulers` plus `online_schedulers` |
| `+SP Pct[:Pct]` / `+SDPcpu Pct[:Pct]` | scheduler **percentages** — the same cascade with negativity as its only test (no upper bound, no total/online relation): `+SP 50`, `+SP 100:100`, `+SP :3`, `+SP 0`, `+SP 9999` pass, `+SP -1`, `+SP 5:-1`, `+SP abc` are refused; preserved verbatim |
| `+SDcpu N[:N]` | dirty-CPU scheduler count — the same cascade **plus** the `chk_S` bounds (`1..=1024` total, `1..=total` online), so a non-positive half is an offset (`+SDcpu -1` passes) while `+SDcpu 1025` and `+SDcpu 4:5` are refused; preserved verbatim |
| `+SDio N` | dirty-I/O scheduler count — `atoi` then `1..=1024`, so `+SDio 0`, `+SDio 1025` and `+SDio abc` (its `0`) are refused; preserved verbatim |
| `-smp enable\|disable\|auto` | scheduler model; `disable` (and its one-token spelling `-smpdisable`) is refused in favour of `+S 1`, while every other value (and a missing one) leaves SMP on |
| `-name N` / `-sname N` | node name → `emulator.node_name`; makes the runtime a distributed node (A.5 phase 1) |
| `-setcookie C` | distribution cookie → `emulator.cookie` (also the init argument `setcookie`) |
| `-env VAR VALUE` | the **launcher**'s environment switch: the pair is consumed blindly (its value may look like a switch) and applied to the child's environment **before** `parse_with_env`, so `os:getenv/1`, every inherited OS child and `vars::from_env` (`ERL_MAX_PORTS`) all observe it — and it is **never** an init argument (`init:get_argument(env)` is the bare atom `error`). A trailing `-env` (no name/value) is the launcher's diagnostic: exit 1 with `beam_rt: Missing argument(s) for '-env'.` and no usage block |
| `-config F` | config file, recorded as the init argument `config`; an **unreadable** one fails the boot with the oracle's byte-exact `Could not start kernel pid (application_controller) …` stderr (CRLF, the resolved `<F>.config` named) and exit 1, really writing the crash dump |
| `-boot F` | boot script: recorded as the init argument `boot` **and** the script the runtime drives (the explicit value, else this runtime's own release's `bootstrap/bin/start.boot`) through the A.7 boot-script executor **before** the action's own start instruction (every action but `-version`) |
| `-emu_flavor emu\|jit\|smp` | emulator flavor → `emulator.flavor` + `FeatureFlags` |
| `+A N` | async-thread pool size — `atoi`, with only a **negative** result refused (`+A abc` ⇒ 0 and passes, `+A -5` is refused); preserved verbatim |
| `+P N` | max process count — `legacy`, or `strtol` into `1024..=134217727` (the digit prefix is the value: `+P65536bogus` ⇒ 65536) → `emulator.max_processes` |
| `+Q N` | max port count — `legacy` (the default table), or `strtol` into `1024..=134217727` (`+Q1024x` ⇒ 1024), preserved verbatim; `system_info(port_limit)` adds the table's power-of-two sizing |
| `+K VALUE` | kernel-poll switch — **no validation at all** (the emulator only `get_arg`s the value, `erl_check_io.c:2467`), so `+K bogus` passes; preserved verbatim |
| `+t N` | atom-table size — `strtol` then `8192..=(2³¹-1)` (`MIN`/`MAX_ATOM_TABLE_SIZE`): `+t 100`, `+t bogus`, `+t -1`, `+t 4000000000` are refused while `+t1048576x` is `1048576`; preserved verbatim, and `atom_limit` follows it |
| `+e N` | ETS-table count — `atoi` narrowed to the C's `int`, with only a **negative** result refused (`+e abc` ⇒ 0 and passes; `+e 2147483648` truncates negative and is refused); preserved verbatim, and `ets_limit` follows it |
| `+sbt TYPE` / `+stbt TYPE` | scheduler bind type — exactly the nine `u`/`db`/`s`/`ps`/`ts`/`tnnps`/`nnps`/`nnts`/`ns` (`erl_cpu_topology.c:623-647`), preserved verbatim |
| `+sbwt NAME` / `+sbwtdcpu NAME` / `+sbwtdio NAME` | scheduler busy-wait threshold — **only** the six spin-count names `very_long`/`long`/`medium`/`short`/`very_short`/`none` (`erl_process.c:5851-5888`); a number (`+sbwt 1000`), a case variant (`NONE`) and the neighbouring `low`/`very_high` family are refused; preserved verbatim |
| `+sws S` / `+swt T` / `+swct T` | the three named scheduler tunings, each a closed symbolic set — `+sws` `default`/`legacy`, `+swt` `very_high`/`high`/`medium`/`low`/`very_low`, `+swct` `very_lazy`/`lazy`/`medium`/`eager`/`very_eager` (a number, or a name from another family, is refused); preserved verbatim |
| `+scl B` / `+spp B` / `+sub B` | scheduler booleans — exactly `true`/`false` (`+scl 1` and `+scl TRUE` are refused); preserved verbatim |
| `+sss N` / `+sssdcpu N` / `+sssdio N` | suggested scheduler-thread stack size in kilo words — `atoi` then `20..=8192` (`+sss 19`, `+sss 8193`, `+sssdio 0` are refused); preserved verbatim |
| `+sfwi N` | run-queue-supervision forced-wakeup interval — `strtol` + `errno`: a value that converts nothing is the C's `0` and passes (`+sfwi x`), a negative or overflowing one is refused; preserved verbatim |
| `+secio V` | **any** value — the C reads it only to discard it ("eager check io no longer used", `erl_init.c:2037-2041`), so `+secio bogus` passes; preserved verbatim |
| `+sct SPEC` | the full CPU-topology token language, accepted and preserved **unvalidated** — a recorded gap, see *Known Issues* |
| `+swtdcpu T` / `+swtdio T` | the per-pool wakeup thresholds, recognized and preserved **unvalidated** where the oracle applies `+swt`'s five names — a recorded gap, see *Known Issues* |
| `+M*` / `+MM*` / `+MB*` | ERTS allocator flags: `+M*` is an emulator flag — validated against the `erl_alloc.c` grammar and then **discarded** (`../cli.rs`'s allocator arm calls only `flags::parse_allocator`; it does **not** call `Builder::preserve`, so nothing reaches `extra_emulator_flags`, and no init argument is recorded); a user `-M*` is an ordinary unknown `-flag` (recorded as `init:get_argument(NAME)`, its value consumed) |
| `+hms N` / `+hmbs N` / `+hmax N` / `+hmaxk\|el\|ib B` | GC heap policy (`beam_gc::HeapPolicy`), visible in `garbage_collection`: `+hms`/`+hmbs` are `atoi`'d and must be `> 0` (`+hms 100abc` ⇒ 100, `+hms 0` refused); `+hmax` is `atoi`'d into `0..=MAX_SMALL` (`0` = unlimited) and checked against a **previously** parsed `+hms`; `+hmaxk\|el\|ib` accept exactly `true`/`false` |
| `+JPperf VALUE` | perf support (`true`/`false`/`dump`/`map`/`fp`/`no_fp`) → `PerfMapConfig` (validated, preserved verbatim; a rejected value exits 1 like the other emulator flags, one `beam_rt: bad value …` line and no `USAGE`) |
| `+JPperfdirectory Dir` | where the perf files are written (default `/tmp`; `ERL_SYM_MAP_FILE` overrides the map file's whole path) → `PerfMapConfig` (preserved verbatim) |
| `run <file.beam> <mod>:<func>/<arity> [arg…]` | the vertical slice and the runtime's **banner-free non-interactive batch runner**: load the file, run, print the result — and nothing else, because the action records the `noshell` init argument. It still drives the default boot script (see *The boot-script drive*) |
Every `+` switch that this runtime **validates** reads its value with the **C's own reader at that call site** — a bare `atoi`, a `strtol` + `errno` test, or the `sscanf("%d:%d")` cascade — so a value the oracle accepts is accepted here and one it refuses is refused, the trailing-garbage tolerance included (see *Exit codes*); the two unvalidated exceptions (`+sct`, `+swtdcpu`/`+swtdio`) are named in the table.
An unmodeled `-FLAG` is **data, not a usage error** (it is recorded as an init argument). An **unmodeled `+FLAG`** is refused by the emulator — `erlexec` rewrites it to `-X`, so a `+X` the emulator does not recognize prints `beam_rt: unknown flag -X` and exits 1 (a *recognized* spelling such as `+Weird` stays accepted). A **plain positional argument** outside `run` is accepted and ignored (exit 0), never a usage error. The two markers `-extra` and `--` are the exception: they are consumed by the plain-argument splitter and never reach the switch table (see *Plain arguments: `-extra` and `--`*).

### A `+`-switch takes its value attached or separated
A value-taking `+`-switch accepts its value in **either** spelling, exactly as the C's `get_arg(argv[i] + 2, argv[i+1], &i)` does (`erts/emulator/beam/erl_init.c`): the text after the switch name inside the token **is** the value (`get_arg`'s `name == NULL` arm sets the value and leaves the index alone), and only when that text is empty is the next token consumed, which then advances the index by two.
So `+S1` = `+S 1`, `+A0` = `+A 0`, `+P65536` = `+P 65536`, `+Q1024` = `+Q 1024`, `+hms233` = `+hms 233`, `+hmbs5000` = `+hmbs 5000`, `+hmax1000000` = `+hmax 1000000`, `+hmaxktrue` = `+hmaxk true`, `+Ktrue` = `+K true`, `+t100000` = `+t 100000`, `+e10000` = `+e 10000`, `+sbtu` = `+sbt u`; each pair reaches the same field and the same preserved flag pair.
The switch is resolved by **longest prefix** among the value-taking set, so a longer name always wins over a shorter one it prefixes — `+hmaxk…`/`+hmaxel…`/`+hmaxib…` over `+hmax…`, the scheduler-*size* switches `+SP`/`+SDcpu`/`+SDPcpu`/`+SDio` over the bare `+S` (they are `+S` plus a letter, never the `+s` family), and `+sssdcpu…`/`+sssdio…` over `+sss`.
The `+s*` scheduler sub-parameter family takes an attached value too (`+sbwtmedium`, `+sbwtdcpulong`, `+sbwtdiovery_long`, `+sclfalse`, `+spptrue`, `+subtrue`, `+swslegacy`, `+swtvery_high`, `+swctvery_lazy`, `+sctcpus:1`, `+seciotrue`, `+sss64`, `+sssdcpu64`, `+sssdio64`, `+sfwi100`, `+stbtu`), the preserved pair always naming the **full** sub-parameter spelling.
The preserved pair in [`extra_emulator_flags`](../config.rs) is always the canonical `(switch, value)` two-token form, whatever the spelling (`+sbtu` ⇒ `["+sbt","u"]`, `+Q1024` ⇒ `["+Q","1024"]`), because that is the shape every consumer reads — `vars::has_plus_q_switch`'s `+Q` test included.
The refusals are unchanged in both spellings: an **unknown** `+Xyz` is still the launcher's `unknown flag -X` (exit 1), a **missing** operand is still `Missing argument(s) for '<switch>'.` (exit 1 — and a following `--` is not a value), a **bad** value keeps the one-line `bad value "<v>" for switch <flag>` diagnostic (exit 1, no `USAGE`), and the two switches that take **no** value in the C (`+ec`, `+ssrct`) are still recognized without one (`+srct` is a spelling neither runtime recognizes: both exit 1).

### Plain arguments: `-extra` and `--`
`init`'s plain-argument rule is modelled per **entity** — the command line, or one `ERL_*FLAGS` variable — because an `-extra` "only effects the remaining command-line flags in the entity in which it is passed" (`erts/preloaded/src/init.erl:127-139`, `parse_boot_args/4` + `check/2` at `init.erl:1664-1740`):
* `-extra` is consumed and **every** following token of its own entity is a plain argument — a later literal `-extra` included, which is then data (`-extra a b -o outdir` ⇒ `["a","b","-o","outdir"]`).
* `--` is consumed and the tokens after it are plain **until the next token beginning with `-` or `+`** (a switch-looking one), which stays in the flag stream and resumes flag mode (`-- a b` ⇒ `["a","b"]`; `-- a -noshell b` ⇒ `["a"]`); a switch-looking token therefore ends a `--` run and then acts as the `-extra` of the rule above.
* every **other** token stays in the flag stream, so the splitter never guesses a switch's arity (`b` in `-noshell b` is the parser's business, not the splitter's).
* the tails of all entities **concatenate in merge order** (the documented multi-entity example: `ERL_AFLAGS="-extra a" ERL_ZFLAGS="-extra d" erl -extra b -extra c` ⇒ `["a","b","-extra","c","d"]`).
The split is [`env::split_plain`] (one entity) and [`env::merge_argv_with_plain`] (the whole merge, whose flag half is byte-identical to `merge_argv`'s). The plain arguments land in [`RuntimeConfig::plain_args`](../config.rs), never in `InitArgs` — so `init:get_argument(extra)` is the bare atom `error` and `init:get_argument(o)` does not exist for `-extra … -o outdir` — and they are what the native floor reports from `init:get_plain_arguments/0` (`../native/init.rs`). An invocation with **no** marker splits to `(args, [])`, so its parse is unchanged.
`parse` stays pure: it splits the args it is **handed** (never the environment), and `parse_with_env` overwrites `plain_args` with the merged form's tails, so an `ERL_AFLAGS`-borne `-extra` reaches `init:get_plain_arguments/0` on the real route.
Two [`HeapOptions`](../config.rs) knobs have **no CLI arm** (the emulator has no `+h`-style switch for either, so they are host/test knobs, not part of this surface): the policy's `initial_mature_words` and its `fullsweep_after`. `ERL_FULLSWEEP_AFTER` is parsed into `ErlEnv` but **not** applied; `BEAM_RT_GC_STRATEGY` (the default-OFF `immix` opt-in) is read by `Runtime::new`, never by this parser — neither is an init argument.

### The boot-script drive
Every action but `-version` drives a boot script: `../cli.rs`'s `boot_script_to_drive` resolves it **once** — the explicit `-boot FILE` value when one was given, else **this runtime's own release's** script (`CodeServer::own_bootstrap_boot_script`: the committed `bootstrap/bin/start.boot` of the source tree the binary runs from), and only when even that is undiscoverable `DEFAULT_BOOT_SCRIPT` (`start`, `init`'s own default) — and `boot_then` runs `Runtime::boot` + `run_boot_script` before the action's own instruction, the order `init`'s `do_boot/3` uses (resolve the boot file, run it, then the start instruction).
`-version` is the one action that drives none: it prints the banner and never builds a runtime.
A non-`-version` action can also return **before** the drive, without doing any boot work: an execution tier this build cannot serve (`BEAM_RT_TIER=cranelift` without the `cranelift` Cargo feature) is refused first, by `runner::unbuilt_tier_request()` — `beam_rt: unsupported: …` naming the Cargo feature, exit 3 (`../runner/CONTEXT.md` *The Cranelift tier and its feature gate*, `../../tests/tier_selection.rs`).
`run_boot_script` boots the 22 preloaded modules, resolves the `-boot` value exactly as `init`'s `get_boot/2` does and executes the script through the A.7 boot-script executor (`Runtime::boot_from_script`).
Its helpers are `boot_file_argument` (the recorded `boot` init argument, first occurrence wins), `boot_file_root` (the Erlang root above `<lib>`) and `resolve_boot_file` (the `<Name>.boot` candidate plus the string-concatenated `<Root>/bin/<candidate>` fallback; a `$ROOT/…` value is read against the same root).
A missing script is the typed `cannot get bootfile <Name>` error; a malformed script, and a script whose executor meets a directive it cannot run, are typed errors too — all reported `beam_rt: <error>` with exit 1, never a silent skip, a panic or a hang.
The command line's `-pa`/`-pz` switches are already in force when the script starts: `Runtime::new` seeds them into the code server *before* `Runtime::boot` appends the system `ebin` directories, so a `-pa` directory heads the code path and can shadow an installed module for the script's very first `{primLoad, …}` batch.
That is the same effective order `init`'s `make_path/4` builds (`Pa ++ ScriptPath ++ Pz`, `erts/preloaded/src/init.erl:1418`), so the two runtimes resolve a boot-script module from the added directory alike; `../../tests/boot_code_path.rs` pins it oracle-cross-checked (and pins that the same directory is honoured on the ordinary `-eval` route).
The resolved script runs **all 22** of its directives to completion — the repo's `bootstrap/bin/start.boot` (the default route's script) and an explicitly named one alike — ending at the final `{progress,started}` (directive index 21), so `-boot bootstrap/bin/start` exits **0** with empty stdout and stderr. Because the default route loads **this runtime's own** release's script, `init:script_id/0` reports `{"Erlang/OTP","30"}`, self-consistent with `erlang:system_info(otp_release)` (`"30"`); an explicit `-boot FILE` still reports *that* script's header (see `../native/CONTEXT.md`).
Directive 20's `{apply,{c,erlangrc,[]}}` issues a `{open, …}` of `$HOME/.erlang` that the booted `kernel_sup`'s own `file_server_2` child answers; on every driving route `Runtime::new` consults `RuntimeConfig::drives_a_boot_script()` and spawns the native service **unregistered**, so the booted `kernel_sup` owns `file_server_2`.
The booted kernel's `user`/`user_drv` prints the OTP slogan (`Erlang/OTP 30 [erts-17.1] [source] [64-bit]`) to **stdout** whenever `init:get_argument(noshell)` is the bare atom `error`, so the `-eval`/`-s`/`-run`/bare-shell actions carry that line ahead of their own output unless `-noshell` is given — exactly as the oracle behaves (`erl -eval 'io:format("hi~n")'` prints the slogan plus an `Eshell` prompt; `erl -noshell -eval …` prints just `hi`).
The `run <file.beam> …` batch action is the exception by construction: `../cli.rs`'s `parse_run_file` records the `noshell` init argument when the command line does not already carry a `-noshell`, so the booted kernel's `user_drv` prints no slogan and a probe or test can assert byte-exact stdout without passing `-noshell`. `-version` is exempt differently: it prints its own banner and never boots.
Per-directive detail is in `../boot/CONTEXT.md`.

### The action's process identity (the caller `-eval`/`-s`/`-run` see)
`-eval` (`Action::Eval`), `-s` (`Action::Apply`) and `-run` (`Action::Run`) evaluate their action in a **freshly spawned, unregistered** process (`Runtime::as_action_process`), matching the oracle, whose `-eval` runs in a spawned child of `init`.
Inside the action `self()` is **not** the pid registered as `init`, `erlang:process_info(self(), registered_name)` is `[]` and `whereis(init) =:= self()` is `false`.
The child is spawned into the runtime's own process table the way the never-enqueued service stand-ins are and takes the root process's group leader (so `erlang:group_leader/0` is unchanged).
When the action ends the result is copied onto the runtime's stable arena **before** the child exits, and the child then dies through the real process-death path (`beam_process::ProcessTable::terminate`, reason `normal`, running the exit observer) — never a silent removal, which would free the heap the returned term points into.
Its death leaves no table entry, so `erlang:processes/0`, `system_info(process_count)` and the `+JPperf` map describe the node the action left.
The boot script still runs **first** on the runtime's own root process; the action's identity is the only thing that moves, so `whereis(init)`, `process_info(init, …)`, `which_applications/0` and `init:get_status/0` keep answering what they answered before. `whereis(init)` is the **`init` stand-in** (`Runtime::init_pid`, `<0.0.0>`) — the pid the root also reports as its `parent` — never the root process (`<0.1.0>`), which holds no registered name.
`run <file.beam>` (`Action::RunFile`) is unchanged: it runs its own scheduled process through `Runtime::run_scheduled`.

## `ERL_*FLAGS` — the environment merge
`parse_with_env` merges four environment variables into the command line before parsing, in real `erl`'s order (`erts/etc/common/erlexec.c`, `initial_argv_massage`):
`[ERL_OTP<sysver>_FLAGS] [ERL_AFLAGS] [command line] [ERL_FLAGS] [ERL_ZFLAGS]`.
So `ERL_AFLAGS` is **prepended** before the command line and `ERL_FLAGS` then `ERL_ZFLAGS` are **appended** after it, the command line keeping the middle position.
`<sysver>` is the OTP **system version** — the major of `OTP_VERSION` — so this runtime's variable is `ERL_OTP30_FLAGS` (`otp_flags_var`).
An **unset** variable contributes nothing; every set variable is `tokenize`d, so one variable can expand to several switches (and a whitespace-only value to none).
A merged token is then indistinguishable from a command-line flag to `init:get_argument/1`.

### Tokenizer rules (`build_args_from_string`, `allow_comments = 0`)
* Runs of the six ASCII whitespace bytes (space, `\t`, `\n`, `\r`, `\x0b`, `\x0c`) separate tokens — **not** Unicode whitespace.
* A `'…'` or `"…"` group is **one** token with the quotes removed; the matching quote ends the group, and quotes may open mid-token (`ab"c d"ef` → the token `abc def`, `"a b"'c d'` → `a bc d`).
* `\` escapes (literalizes) the **next** character, including whitespace and a quote (`a\ b` → the token `a b`).
* `#` is an ordinary character — it is **not** a comment.
* An empty string yields no tokens; a quoted empty group (`""`) yields one empty token.

## Environment variables beyond the `*FLAGS` chain (`vars.rs`)
A **second** family is read outside `initial_argv_massage` — by the emulator's start-up `getenv`s (`erts/emulator/beam/erl_init.c:1327-1344`, `erl_crash_dump.c:427-457`), by `inet_config` (`lib/kernel/src/inet_config.erl:436`) and by the `erl` **launcher script** (`ERL_ROOTDIR`).
`vars::from_env` parses them into `RuntimeConfig::env` (`config.env_vars()`); **none is an init argument** — verified against the oracle (OTP 29.1.1 / erts-17.1), where `init:get_argument(inetrc|crash_dump|crash_dump_seconds|max_ports|max_ets_tables|fullsweep_after)` is the bare atom `error`, so none is ever recorded in `InitArgs`.

| Variable | Oracle effect | `beam_rt` handling | Observable? |
|---|---|---|---|
| `ERL_MAX_PORTS` | `atoi`, then **clamped** into `[1024, 134217727]` (`erl_init.c:1341`); sizes the port table | `ErlEnv::max_ports` (the clamped `usize`) **and**, when the merged argv has no `+Q`, `RuntimeConfig::max_ports` (the same request field `+Q N` sets) **and** a preserved `+Q <clamped>` in `extra_emulator_flags` | yes — `system_info(port_limit)` (the power-of-two table sizing on top of the request is `../info`'s) |
| `ERL_INETRC` | path the `inet` resolver reads at start-up | `ErlEnv::inetrc` (verbatim; `Some("")` when set-but-empty) | no — parsed-but-inert (M1 has no resolver) |
| `ERL_CRASH_DUMP` | crash-dump file name (emulator default `erl_crash.dump`) | `ErlEnv::crash_dump` (verbatim) | no — parsed-but-inert (no crash-dump subsystem) |
| `ERL_CRASH_DUMP_SECONDS` | `atoi` (`erl_crash_dump.c:451-457`): `0` = no dump + break now, `< 0` = dump until complete, `> 0` = alarm-bounded | `ErlEnv::crash_dump_seconds` (`i64`; a malformed value is `atoi`'s `0`) | no — parsed-but-inert |
| `ERL_ROOTDIR` | OTP-root relocation honoured by the `erl` **launcher script** | `ErlEnv::rootdir` (verbatim) | no — parsed-but-inert (this binary is not relocatable) |
| `ERL_MAX_ETS_TABLES` | `atoi` (`erl_init.c:1328-1331`); `0` = the emulator default | `ErlEnv::max_ets_tables` (`i64`) | no — parsed-but-inert (no ETS table limit here) |
| `ERL_FULLSWEEP_AFTER` | `atoi` (`erl_init.c:1334-1338`); the emulator stores it in a `Uint16` gen-GC interval | `ErlEnv::fullsweep_after` (`i64`, stored **untruncated** — no gen-GC consumer exists) | no — parsed-but-inert |

**Numeric semantics** are the C's `atoi` (`vars::c_atoi`): leading whitespace, an optional sign, then digits, stopping at the first non-digit — so a non-numeric value is `0`, never a dropped variable and never a wrong value.
`ERL_MAX_PORTS` is the one member with an effect, and it is applied exactly as a `+Q` the merged argv does not already carry:

* the clamp is what the emulator does to the value (`1`/`100`/`bogus` ⇒ 1024, `999999999` ⇒ 134217727); the `2000 ⇒ 2048` step the oracle **observes** in `system_info(port_limit)` is the port table's power-of-two sizing (`erts_ptab_init_table`/`erts_ptab_max`, `erl_ptab.c:383-388`/`erl_ptab.h:266-270`), which `../info`'s `port_limit` applies to every request — this parser models the clamp only;
* a `+Q` **anywhere in the merged argv** — the command line or `ERL_AFLAGS`/`ERL_FLAGS`/`ERL_ZFLAGS` — overrides the variable outright (oracle: `ERL_MAX_PORTS=2048 erl +Q 4096` and `ERL_FLAGS='+Q 4096' erl` both observe 4096), so `ERL_MAX_PORTS` is applied **only** when no `+Q` is present;
* the asymmetry is the oracle's: `+Q` **validates** (and rejects out-of-range), `ERL_MAX_PORTS` **clamps silently**.
`parse` stays pure — it never reads an environment, so it always yields `ErlEnv::default()` and `max_ports: None`; only `parse_with_env` fills `env_vars` and performs the `+Q`/`ERL_MAX_PORTS` routing.
`+Q N` itself sets `RuntimeConfig::max_ports` to the validated request (`+Q legacy` ⇒ `None`, the default table) and preserves the two tokens in `extra_emulator_flags` verbatim.

## Init arguments (`init:get_argument/1`) — the exact recording rule
The parser reproduces the oracle's split between emulator/`init` switches and flags:
* A **`-`-switch** (recognized or not) is recorded as an `InitArgs` occurrence — the source of `init:get_argument/1`.
* A **`+`-flag** is an **emulator** flag and is **not** recorded (the oracle's `init:get_argument('S'|'Q'|'K'|'A'|'P'|'sbt')` is the bare atom `error`).
* The `-eval`/`-s`/`-run` **Start instructions** are consumed by `init` and are **not** recorded (`init:get_argument('eval'|'s'|'run')` is the bare atom `error`).
* The `run` **action** *adds* one valueless `noshell` occurrence of its own when the command line carries no `-noshell` — the `parse_run_file` recording that makes the batch runner banner-free (see *The boot-script drive*). It is not the `-noshell` switch: the `run`/`FILE`/`MFA`/`ARG` tokens themselves are not init arguments.
* A **plain argument** (`-extra`/`--` — see *Plain arguments: `-extra` and `--`*) is never recorded: neither the marker nor any tail token is an init argument, whatever it looks like (`-extra -o outdir` records neither `extra` nor `o`).
A flag's name is its switch with the leading `-`/`+` run removed (`--nope` → `nope`, `-pa` → `pa`).
A valueless flag is one occurrence with no values (`-noshell` ⇒ `{ok,[[]]}`); `-pa /a -pa /b` is two occurrences (`{ok,[["/a"],["/b"]]}`).
The oracle additionally reports its own `root`/`bindir`/`progname`/`home` entries in this listing, none of which is an `InitArgs` occurrence here: the native `init:get_argument/1` floor answers `root`/`home`/`progname` from the runtime's own state (`../native/init.rs`) — where `progname` is a deliberate, invocation-dependent gap, each runtime reporting the basename **it** was invoked as — while `bindir` is not modelled.

## Exit codes (the stable external contract)
| Code | Meaning | stderr |
|---|---|---|
| `0` (`EXIT_OK`) | success | — |
| `1` (`EXIT_RUNTIME`) | a genuine failure: a load/execute/BIF error (a missing `.beam`, an `undef`, BIF `system_limit`), a switch value the emulator/launcher **rejects**, an unreadable `-config` file, and the launcher's trailing-`-env` diagnostic | `beam_rt: <error>` for the runtime and single-line cases; the oracle's byte-exact two-line boot-failure text for `-config` |
| `2` (`EXIT_USAGE`) | usage error: a missing operand of an ordinary `-`-switch, a malformed `run` spec/argument | `beam_rt: <error>` then `USAGE` |
| `3` (`EXIT_UNSUPPORTED`) | **unsupported** — a Milestone-1 capability gap | exactly one line: `beam_rt: unsupported: <reason>` (no `USAGE`) |
A **rejected emulator switch value** is exit 1 with **one** stderr line — `beam_rt: bad value "<v>" for switch <flag>` — and **no** `USAGE` block, matching `beam.smp` (`+t 2`, `+P 0`, `+Q 0`, `+hms 0`, `+sbt zz`, `+sbwt 1000`, `+scl 1000`, `+e -1`, `+hmax -1`, `+hmaxk x`, `+A -5`, `+SP -1`, `+SDio 0`, `+sss 19`, `+S abc`, `+S 4:5`).
It is identical for the attached and separated spellings (`+scl1000` and `+scl 1000`).
The other direction is just as uniform: a **trailing-garbage** value is not a rejection but its digit prefix — `+S1bogus` ⇒ 1 scheduler, `+P65536bogus` ⇒ `process_limit` 65536, `+Q1024x` ⇒ `port_limit` 1024, `+t1048576x` ⇒ `atom_limit` 1048576, `+A abc`/`+e abc`/`+sfwi x` ⇒ the C's `0`, `+hms 100abc` ⇒ 100 — all exit 0, as the oracle does.
The classifier is `error::flag_rejected` (reason-atom prefix `beam_rt_flag:`), pinned by [`../../tests/cli.rs`] and [`../../tests/cli_flags.rs`]. The same `beam_rt_flag:` family carries the **launcher's** own exit-1 diagnostics: an **unrecognized `+`-flag** (`beam_rt: unknown flag -X`), a **missing operand of a `+`-switch** or of `-name`/`-sname` (`beam_rt: Missing argument(s) for '<switch>'.`) and the **refused `-smp disable`/`-smpdisable`** (`beam_rt: Argument '-smp disable' not supported. Use "+S 1" instead.`). A missing operand of an ordinary `-`-switch stays exit 2 + `USAGE`.
A `-s`/`-run` **module that cannot be loaded** is a call-like route: the loader's expected-name refusal (a `<Name>.beam` whose object code names another module) raises the bare `error:undef`, exit 1 with empty stdout — indistinguishable from a module with no `.beam` at all (`error::call_load_failure`).
A malformed `-eval` expression is **not** decided by the parser — it is a capability gap detected when the expression is evaluated (exit 3).
A runtime **halt** the program requests is neither: it exits with the requested status printing nothing.

## Documented divergences
* **A `+s…` spelling outside `SCHEDULER_SUB_OPTIONS`' twenty rows is rejected with the emulator's status and this CLI's wording.** The C's chain is a `has_prefix` list, so `+sstbt u` matches no branch (`bt` is not a prefix of `stbt`) and neither does this CLI's table: the oracle's `else` arm prints `bad scheduling option <token>` and exits 1 (`erl_init.c:2208-2211`), while `beam_rt` reaches the same exit **1** through the `unknown flag -<token>` fallthrough (`+sstbt u`, `+sfoo 1`).
* **`+hmax` is checked against `+hms` order-dependently, as the emulator does it.** `Builder::rejects_max_heap` reproduces `erl_init.c:1634-1639`: a `+hmax` is refused (exit 1, `max heap size (<max>) is not allowed to be smaller than min heap size (<min>)`) iff a **previously parsed** `+hmax` is nonzero and below the current raw `+hms`, so `+hmax 500 +hms 1000 +hmax 200` and `+hmax 200 +hmax 500` (the second against the default 233) are rejected while `+hms 4000 +hmax 500` and `+hmax 500 +hms 4000` parse. The pair that ends up installed with `min > max` is a *runtime* death on the oracle (its boot process is killed at the limit) and here hits the typed heap-exhaustion door, because `Runtime::system_spawn_policy` keeps `+hmax` off the runtime's own boot processes.
* **The `beam.smp` usage block is not reproduced.** The oracle prints its own leading diagnostic wording followed by a 7331-byte usage dump; `beam_rt` prints one `beam_rt: …` line and no `USAGE` for an exit-1 case (its own `USAGE` appears only on a usage error, exit 2).
* **`-emu_flavor` is broader than `erlexec`.** The oracle's `erlexec` accepts only `smp` and rejects `emu`/`jit` (`erlexec: Invalid emulator type or flavor…`, exit 1); `beam_rt` accepts `emu`/`jit`/`smp` so `Flavor::Emu` is reachable.
* **`-M*` vs `+M*`.** Through the `erl` wrapper a `-M*` flag is **not** forwarded to the emulator (`erlexec.c:865`, it falls to `add_arg`), so the oracle never validates it; only `+M*` is rewritten to `-M*` and validated. `beam_rt` recognizes the whole family but validates only `+M*` (oracle parity for `-M*`).
* **`-eval`/`-s`/`-run` are documented subsets.** Supported: the expression subset, the **send operator**, a bare `receive` driving a spawned sender, the spawn probes and a bounded scheduler pump. Gaps (typed errors in `../eval/mod.rs`): a `receive` that never receives, a `receive` inside an in-slice spawned process (a closure `spawn`ed from the `-eval` route is compiled into a real module and does park), `after infinity`; real `erl` start-script processing / `-init_debug` are absent.

## Known Issues (verified against the code, not just the docs)
* **`+M*` is validated and dropped, contradicting the source docs.** `../cli.rs`'s allocator arm (`other if flags::is_allocator_switch(other) => index = flags::parse_allocator(...)`) never calls `Builder::preserve`, so unlike every other modelled emulator flag a `+M*` value reaches **neither** `extra_emulator_flags` **nor** any init argument. `../cli.rs`'s own module-table row ("all preserved verbatim") and `USAGE` ("preserved verbatim"), plus `flags.rs`'s module doc ("preserved verbatim in `extra_emulator_flags` so that nothing is lost") and its "-M*/+M* family … records neither as an init argument" claim, are therefore **stale/wrong** for the `+M*` form. Functional impact is nil (allocator flags have no runtime effect here), but the "nothing is lost" promise is not kept.
* **`+JPperf`/`+JPperfdirectory` are implemented but omitted from `USAGE`.** The two switches are parsed, validated, preserved and routed into `PerfMapConfig`, yet `USAGE` does not list them, and `../cli.rs`'s `usage_text_documents_every_supported_switch` is only a spot-check — it also omits `-smp` and the `+hms`/`+hmbs`/`+hmax`/`+hmaxk`/`+hmaxel`/`+hmaxib` heap switches (which *are* in `USAGE`) — so a `USAGE` regression on any unlisted spelling goes unnoticed.
* **The integer readers are one family in `flags.rs`, one per C call site.** `atoi` (no leading-whitespace skip, saturating), `strtol10` (whitespace skipped, digit prefix, `None` on no-digit/overflow), `scan_int` (the `sscanf` prefix, returning the unconverted remainder) and `lax_int` (the allocator family's `ErtsStrToSint`); `../cli.rs`'s `parse_heap_words`/`parse_max_heap_size` build on `atoi`. `vars.rs::c_atoi` is the one separate reader — the `ERL_*` variables' `atoi` — and it skips only `u8::is_ascii_whitespace`, which omits `\x0b` (vertical tab) that C `isspace`/`strtol` skips, so a value like `"\x0b2000"` parses as `0` there rather than `2000` (`env.rs::is_whitespace` does include `\x0b`).
* **`+sct`'s value is accepted unvalidated.** Its grammar is the full CPU-topology token language (`erts/emulator/beam/erts_cpu_topology.c:1076-1300`: `cpus`/`cpu`/`node`/`core`/`thread`/`processor` nodes, `id=…`/`logical=…`, `/`-separated lists, `;`-separated declarations), so `+sct cpus:1` passes here where the oracle refuses it (`bad cpu topology 'cpus:1': invalid identifier`, exit 1) — a deliberate gap, since half-validating that language would be worse than preserving it verbatim. `+swtdcpu`/`+swtdio` (the `+swt` siblings, whose value really is the five `+swt` threshold names) are likewise recognized and preserved **without** validation, so `+swtdio turbo` passes here where the oracle exits 1.
* **Action switches are last-wins.** `../cli.rs`'s `parse` assigns `builder.action` per switch, so `-version -eval X` takes the `-eval` action (no banner) and `-eval X -version` takes `Version`. No test or oracle comparison covers a mixed action line.
* **The `ERL_MAX_PORTS` `+Q`-override detection is a raw token scan.** `vars::has_plus_q_switch` matches any `+Q` token in the merged argv, including one sitting in a flag-operand position (e.g. `-pa +Q`), so `ERL_MAX_PORTS` would be suppressed by a token that is not an operative `+Q`. Edge case only.

## Constraints
* **Errors are return-based** (workspace-wide): the parser returns `beam_common::Result`; a usage error is a `BeamError` message naming the offending switch/argument. No crate-local error enum.
* **`unsafe`-free** — `../cli.rs` and this directory are plain safe Rust over `std`.
* **`parse` is pure.** It must never read the process environment; only `parse_with_env` does, through an `Env`.
