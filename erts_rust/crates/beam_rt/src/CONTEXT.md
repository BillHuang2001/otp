# `beam_rt/src` — runtime source root

## Intent
The crate's implementation root: the `main.rs` shim plus every production module the Routing Table
names — the `Runtime` façade, the CLI, the concrete `ExecutionContext` glue, the runtime-native BIF
floor, the A.4 port layer, the A.8 introspection surface, the distribution node, the NIF host, the
allocator free-page release and the observability modules.
This node owns the crate's **cross-cutting seams** — one section each below — because each is spread
across several modules and no child can own it; the per-module catalogue, the CLI table, the exit
codes, the `system_info` keys and the gap ledger live in `../CONTEXT.md` and in the child
`CONTEXT.md`s.

## Term-lifetime rules this node is bound by
One line each; the full statement is `../CONTEXT.md` § *Cross-crate laws → Term lifetime and rooting*.
- A raw `Eterm` in a long-lived slot **roots nothing** — a raise reason, a pending reply, a parked value, a cache entry must be copied onto a scanned heap (or explicitly stabilized) before its owner's heap can relocate.
- A pointer-stable, never-scanned store (the arena, `alloc_words`) is the **wrong home** for a container whose children live on a scanned young heap: the copier gives such a container `Target::Foreign` and never descends, so the GC leaves the container verbatim while relocating the children out from under it.
- An **exempted** heap-growth or move (`relocation_exempt`, `has_unpublished_roots() == true`) must **refuse ⇒ stabilize, never dangle**, and the refusing path first makes its roots publishable.
- A **lease** (`Rc` handle over a shared store) held across an allocation is a deep copy or a dangle hazard, never a cheap borrow.
The per-site inventory of every store that can name a relocatable word is the relocation inventory
below; the mutable root door that a move rewrites through is `runtime/roots/CONTEXT.md`.

## Version / boot-script / system-root resolution (cross-cutting seam)
Binding for A.6/A.7/A.9 work; the pieces are spread across `codeserver.rs`, `cli.rs`, `boot*.rs`,
`info/system.rs` and `native/{code,init}.rs`, so the rule is recorded here and the per-consumer list
in `codeserver/CONTEXT.md` § *Where the resolved root is consumed*.

- **The version constants are compile-time.** `beam_common::{OTP_VERSION = "30.0-rc0", ERTS_VERSION = "17.1"}` (`../beam_common/src/version.rs:39,42`) serve `erlang:system_info(otp_release / version / system_version / compat_rel)`, the NIF `ErlDrvSysInfo` strings and the `-version` banner (`info/system.rs`, `boot.rs:317-319` printed by `cli.rs:1596`, `nif.rs:476,480`).
- **The runtime has NO notion of its own root/release**; the code path/root is resolved **only from the filesystem**, preferring the `erl` on `$PATH` (`codeserver.rs::native_roots:660-683`, seed order `erl`-on-`$PATH` ancestors → `current_exe` ancestors → `$ERL_TOP` → `STANDARD_OTP_ROOTS`, each tried as itself and as `<seed>/lib/erlang`).
- **The first root passing the `SYSTEM_APPS` probe wins** (`stdlib`/`lists.beam` is the hard requirement — `native_system_ebins:644-646`, `system_ebins_under:693-713`, `SYSTEM_APPS:825`); `bootstrap/` is **never** a candidate root, so with an `erl` on `$PATH` the consumed root is that system install's (`CodeServer::lib_root`, `codeserver.rs:335-340`), which then yields the whole release's ebin list through `codeserver/path.rs` — the oracle's `code:get_path/0` exactly (`../../tests/code_path.rs`).
- **`CodeServer::lib_root()` is never repointed at the source tree** (it feeds `bindir`/`app_dir`/system-ebin resolution/`$ROOT` expansion); `own_bootstrap_boot_script` is a **separate** discovery that walks `current_exe()`'s ancestors (bounded, as `native_roots` does) and then `$ERL_TOP`, checking each for `bootstrap/bin/start.boot` (tests use an explicit `env!("CARGO_MANIFEST_DIR")` path, which a relocated binary could not report truthfully).
- **The default route loads THIS runtime's own release's boot script.** With no `-boot`, `cli.rs`'s `boot_script_to_drive` prefers `CodeServer::own_bootstrap_boot_script()` — the committed `bootstrap/bin/start.boot` of the tree the binary runs from — so the default route drives the OTP-30 primary bootstrap (header `{"Erlang/OTP","30"}`) and `init:script_id/0` agrees with `otp_release` (`"30"`).
- **Only with no reachable source tree** does it fall back to `DEFAULT_BOOT_SCRIPT = "start"` → `resolve_boot_file` (candidate `<value>.boot`, else the `<Root>/bin/<value>.boot` string-concat fallback) → `<systemRoot>/bin/start.boot`; an **explicit** `-boot FILE` is untouched and resolves exactly as `init`'s `get_boot/2` does, and `-boot bootstrap/bin/start` stays **CWD-relative** (as on the oracle).
- **`init:script_id/0`** (`native/init.rs`) reads `Runtime::boot_script_id`, set from the loaded `BootScript`'s `{Name,Vsn}` header (`runtime.rs boot_from_script`/`boot_from_script_reporting`); with no loaded script it is the typed `unsupported: init:script_id/0 (no boot script has been loaded)` gap.

## The `-eval` route's term storage (cross-cutting seam)
- **The rule:** no `Machine` spans a `-eval` expression — the tree-walker holds only `&mut RuntimeContext` with `mailbox_table: None` and `gc_armed: false`, so every term it builds lands in a `Runtime` field (`arena`, the pooled `bif_heaps`, `eval_heap`, `eval_off_heap`), and the only `Machine`s are the per-nested-call short-lived ones whose payload handles are adopted into `eval_off_heap` before they drop.
- **Consequence:** nothing on this route collects or relocates by itself; the route's reclamation is the region-reclaim pass and its prune, at non-running sites only.
- **Where the detail lives:** `eval/CONTEXT.md` (the re-homed statement of the route's regions, the walker's live-term holders, the `OffHeapTable` traps and the park prune's inapplicability), `eval/scratch.rs`/`eval/reclaim.rs` module docs, `runtime/roots/CONTEXT.md` § *The `-eval` store* (the relocation side) and `runtime/CONTEXT.md` § *The region-reclaim pass*.
- **The one number a reader needs:** `eval_heap` is the single rewritable store (`eval/scratch.rs::reset_to`), so any word held outside it must be enumerated at a statement boundary.

## The off-heap refc-binary reclamation loop
Binding for anyone reading an `erlang:memory(binary)` figure or touching `context/gc/bin_vheap.rs`;
the mechanism is `context/gc/CONTEXT.md` § *The off-heap refc-binary reservoir prune*, the per-slice
site `runner/CONTEXT.md` § *The slice boundary's off-heap refc-binary prune*, the figures
`../M1_GAPS_GC.md` § *GC / heap model* and `../M1_GAPS_GC.md` § *Memory and statistics*.

- **The prune has exactly one caller**, the `Yield` (pre-emption) arm at `runner/run.rs` → `RuntimeRunner::reclaim_off_heap_binaries` → `context::gc::bin_vheap::reclaim`; neither the `Wait` arm nor a `BifOutcome::Suspend` park calls it, so a process that parks in a `receive` after building payloads keeps them until its next **pre-emption**.
- **At a pre-emption the reservoir is pruned whole**: the census line (`released`/`retained_by_live`/`retained_by_shared`/`binary_alloc_live`, `BEAM_RT_BOOT_TRACE=1` only) reports `retained_by_live = 0` and `retained_by_shared = 0` at every park of every shape measured, so the `refcount() > 1` belt is a belt and not a working set: the peak a park-reaching loop shows is **one pre-emption window**, not a sum over parks.
- **A monotone `erlang:memory(binary)` ladder is a slice phase, not a leak.** A dead payload is freed only at that point, so the figure is exactly the payloads the current slice built since the last park and a fixed-offset read samples the same point of the cycle every time. The **two tests of a real leak**: does the *trough* grow with the park count, and does the peak grow with the iteration count at **zero** parks.
- **The prune's valve is stronger than the collection valve's, with exactly one exemption.** A pointer-bearing word in a region the collector does not scan declines the prune whether or not it forwards anything — except a **reference thing** (`gc_walk.rs::is_inert_reference`: the `[header, node, serial, id]` block or a C-layout reference), whose payload words are immediates or packed `u32` ids and can name no payload. That exemption is what keeps the point reachable in ordinary code: a process holding one live reference in its root set (every `gen_server` with a monitor, every owner of an unnamed ETS table, anything that called `make_ref/0`) reads the same flat figure as a reference-free one.
- **The bin-vheap budget GATES the prune; it can never CAUSE one.** `OffHeapReclaimer::triggered` (the C's `MSO(p).overhead > bin_vheap_sz`, 46 422 words by default) is one gate `reclaim` consults and nothing consults it to *ask* for a reclaim, so one slice's dead off-heap garbage is bounded by the **slice length**, never by the configured budget — a per-process residue whose bytes are payload-size proportional, i.e. a capacity residual rather than a leak.
- **A dead process's reservoir is released at the pass boundary**, not by this arm: `RunnerState::prune_dead` (`runner/entry.rs`) drops the engine — the machine and therefore its `refc_binaries` — of every pid the pass's table no longer holds, cancelling the deadline a parked one armed (`runtime/scheduler.rs`, once per pass round).
- **The one unbounded shape is a slice that never ends.** On the default native baseline tier a **linked** tail exit charges no reduction (`Linker::emit_tail_exit`; `jit/baseline/runtime.rs::jit_tail_call` is only the checked frame pop) and a BIF dispatch only *spends*, so a self-recursive tail loop whose body is a binary build plus BIF calls runs its whole computation inside one slice: **no park, no prune, the reservoir linear in the loop count** — and `max_heap_size`/`+hmax` (which charge `Process::set_off_heap_binary_bytes` **at the prune**) bound nothing there. The repair is a reduction charge on the linked tail exit / block entry — a **`beam_engine`** change this crate cannot make; no host-side substitute works, and `BEAM_RT_TIER=interpreter` (one charge per instruction) is the honest mitigation. Figures: `../M1_GAPS_GC.md` § *GC / heap model*.

## The debt gate on the fun-applying stdlib fast paths (cross-cutting: execution · bridges · gc)
Binding for `RuntimeContext::resolve_external_call`, `FunBridge` and the collection doors.
- **What it gates:** `lists`/`maps` keys whose `beam_bifs` implementation applies a fun argument back into the runtime — the roster is **not** restated here: it is `beam_bifs::needs_fun_caller(module, function, arity)` (the registry's allocation-free binary-search answer over `FUN_CALLER_BIFS`' pinned 18 `lists` + 4 `maps` + 2 `ets` keys), narrowed to `module` ∈ {`lists`, `maps`} by `execution.rs`'s `nests_a_fun_apply`.
- **The verdict reaches both branches as one memo bit.** `DispatchHooks::FUN_CALLER` is the roster's twelfth, verdict-only bit (`RuntimeContext::uses_fun_caller`): `needs_fun_caller` runs **once per `(module, function, arity)`** on a `DispatchMemo` miss and every hit reads the bit — so the seam's `call_ext*` pays **one** `dispatch` lookup (which also supplies the registered leg through `host_serves_given`).
- **The predicate:** `RuntimeContext::calling_process_has_collection_debt` (`execution.rs`) reads `Process::collection_debt` for `mailbox_pid` off `mailbox_table`; a **table-less** context answers `false` (no process, no debt), which keeps the `-eval` route's synchronous dispatch byte-for-byte unchanged.
- **What a decline buys:** the key's real `.beam` body is entered **in this machine**, so the callee's registers/stack/frames join the caller's root set and every heap-admission point is the caller's **armed** one — the door that fires on `Process::collection_debt` and collapses the retired-nursery chain. The `lists`/`maps` bodies *are* the reference semantics of the fast paths, so no result changes.
- **The gate must be a pure function of the heap state:** the native baseline tier consults `resolve_external_call` **twice** per `call_ext*` (`jit::baseline`'s `jit_ext_call`, then `jit_step_one`) back-to-back inside one instruction step, and `Process::grow_nursery` (the only setter) and a collection (the only clearer) both need execution — so the second consultation cannot answer differently.
- **The two `ets` folds stay on the synchronous path on purpose:** `ets.erl`'s `foldl/3`/`foldr/3` reach `ets:first/1`/`next/2` and then a `lists` key internally, so gating them would relocate the nesting rather than remove it while replacing an implementation whose per-interior object ordering is pinned against the oracle.

## Reaching a `-sname` node from a real peer (A.5, cross-cutting: dist · eval · scheduler)
- **`net_adm:ping(<this node>)` answers `pong` whenever a scheduler pass runs** — on the `run` route and on `-eval` with repeated short receives. The `'N'` responder handshake, the `net_kernel` service's `is_auth` answer (`native/net_kernel.rs`), the alias reply (`dist/links.rs::route_alias` → `DOP_ALIAS_SEND`, `DFLAG_ALIAS` negotiated by OTP 29) and the peer binding (`runtime/scheduler.rs:999`) are all live; a **wrong cookie** answers `pang` (a real refusal), which is the discriminator against a timeout.
- **The `-eval` `receive … after T` route pumps the scheduler every port-poll slice, so a peer is accepted however late it dials.** Both per-iteration waits of the `after` arm are bounded by `PORT_POLL_SLICE` (the port poller's own budget, reused) and the pump between them is the **non-blocking** `Runtime::pump_scheduler_now`, with the deadline tested **before** the pump — so the wait ends on the **caller's** deadline rather than on a pump call's schedule, and `pump_dist` → `DistNode::pump` → `accept_one` is re-entered every slice (charging the whole window to `PortRegistry::pump(timeout)` would leave a peer unaccepted in the listen backlog while any port is live). The arm's observable timing is the oracle's, pinned by `eval::tests::{an_after_window_fires_on_its_own_deadline, a_message_that_beats_the_deadline_is_picked_up_promptly, a_long_after_window_is_waited_out_in_port_poll_slices, a_sub_slice_after_window_never_loops}`.
- **`DistNode::is_idle` (`dist/node.rs` → `links.rs`) means "no live LINK"** — the listener and a pending accept are not counted as work, so a distributed node with nothing to run is `is_quiescent`; the `run` route only survives an idle `receive` because the live `inet_gethost` port keeps `has_nothing_to_poll()` false, and `RUN_DEADLINE` (60 s) bounds that route.
- **This node is PUBLISHED to real peers, and `-hidden` is honoured.** Both halves advertise `dist.rs::advertised_flags(hidden)` = the emulator default (`preferred_flags`) **OR** `publish_flag(hidden, true)`, i.e. `DFLAG_PUBLISHED` unless `-hidden` (as a real node does per peer, `lib/kernel/src/dist_util.erl:152-160`); `Runtime::new` tells the acceptor and the connector the same value (`DistNode::set_hidden`/`DistClient::set_hidden`), since visibility belongs to the node, not to who dialled, and a hidden **peer** is recorded-not-refused (`DistConnection::peer_visibility`). Per-case detail: `dist/CONTEXT.md`, `../../tests/DISTRIBUTION_EVIDENCE.md`.

## Contract A.5 — cross-node invariants and behaviour limits
Measured against a real system `erl` (`-sname` only on this host). These are the **invariants**; the
per-family routing, the `Unsupported` families and the two-live-VM case tally are `dist/CONTEXT.md`
(the authoritative per-case ledger) and `../../tests/DISTRIBUTION_EVIDENCE.md`.

- **Inbound delivery is on by default** (`Runtime::inbound_delivery`), every inbound family takes the C's **route-free receipt** primitive (it emits no outbound `DOP_*`), and `beam_dist`'s `LocalIdentity` is installed per drain on all three decode paths — so an inbound pid/port/reference naming this node decodes to the internal term and `Pid =:= self()` holds.
- **Outbound ordering: every send drains its link's pending control queue first** (`DistClient::flush_queued_controls` at the top of `send_reg_send`/`send_message_pid`/`send_alias`), so an earlier `link`/`unlink`/`exit`/`exit2`/`monitor`/`demonitor`/`monitor-exit` is never overtaken by a later message — the property ERTS gets from writing controls synchronously under the link lock, re-established at the write. Statement and rationale: `../CONTEXT.md`.
- **Inbound large-term delivery falls back to a heap fragment past the receiver's young space**: a receiver caught **`Running`** mid-pass has unpublished roots (and a relocation-exempt one may not move at all), so `Process::deliver` returns the copier's raw refusal and `LocalDeliverySink::enqueue_fragmented` turns it into a `beam_message::send_fragmented` (the C's `erts_try_alloc_message_on_heap`/`new_message_buffer`). The bound is the default nursery's arithmetic — 117 cons cells is 234 words against a 233-word young space — so it is **list length**, not wire bytes: a `lists:seq(1,N)` with `N ≥ 117` needs the fragment route on either string encoding, while a 600-byte **binary** does not (past 64 bytes it is an off-heap refc payload of 8 heap words).
- **The local send path's fragment route spends the refusal's own price**: `context/send.rs::deliver_into_mailbox` is the crate's one delivery door and it *holds* the refusal, so it calls `send_fragmented_message_after_refusal` with that failure's `AllocFailure::requested` — no trial copy and no `size_object`-class pricing walk. A `receive`-parked receiver **publishes** its host-held terms through `Registers::extra_roots`, so its `has_unpublished_roots()` is false and the ordinary blocking receiver is delivered into its own heap; the fragment route serves the remaining refusal classes.
- **A delivery refusal is an outcome, never a link failure**: the `Alloc` arm answers `Delivered` (fragment route) or `Dropped`, never `Err`, so an oversized message from a peer cannot retire the link (`dist/inbound/tests.rs`).
- **Inbound delivery needs the target name registered before a peer sends** — a send that lands before the name exists is dropped, so an inbound assertion registers the receiver first; and a decoded arrival can carry a term that is not a proper list, on which `length/1` raises `badarg` (exit 1).
- **A send to a link-less peer dials it first** (`Runtime::dist_ensure_link`/`dist_ensure_link_to_node`), so atoms/tuples/binaries/maps/130-element lists arrive with no prior `net_adm:ping/1`; only an unreachable peer answers the typed `distribution: no established connection to node <label>` (exit 1), never a silent drop, and `-eval` cannot `~w`-print a term holding a **foreign pid** (`unsupported: external_term`).
- **`rpc:call` is unachievable in both directions** until the distributed-spawn family exists (OTP 29's `rpc:call/5` is `erpc`, i.e. `spawn_request/5` + `DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`); what this crate owes and why it is not a missing sibling seam is `../CONTEXT.md`, and the per-item list `dist/CONTEXT.md` § *Missing sibling APIs*.
- **Cross-node monitors work in both directions for a pid** (in and out, with the peer's own reference `=:=` and `demonitor` suppressing the `'DOWN'`); the remaining gap is a **named** monitor — oracle→us on `{Name,Node}` is `native/process/monitor.rs::named_node_target` (`unsupported`, exit 3). Evidence: `tests/live_signals.rs`.
- **Oracle `monitor_node/2` on us agrees**: `{nodedown,Node}` (bare 2-tuple, no reason) arrives on our death and no `{nodeup,_}` is emitted on a later connect — a real-OTP↔real-OTP control reproduces exactly this, so it is oracle behaviour.
- **A `-sname` node survives a connected peer**: `net_kernel:monitor_nodes(true, #{connection_id => true})` → `nodes(visible, #{connection_id => true})` answers the peer's **real per-link integer** (`native/net/nodes.rs::nodes_2` over `Runtime::dist_connection_id`), never a capability gap.

## Module literal areas — shared by word, owned by the `Module` (cross-cutting)
Binding for "where does a module constant live, and can it be copied or freed?".
- **A module's `LitT` literals live in one immutable `beam_alloc::Heap` owned by the module** (`beam_loader/src/literal.rs:76-90`), reached as `Module::literal(idx) -> Option<Eterm>` (`beam_loader/src/ir.rs:425-432`), held behind `Arc<LiteralArea>` (`literal.rs:177-182`) and literal-tagged exactly once at load (`literal.rs:112-124` → `beam_term::literal::tag_literal_area`). `Module::literal` returns a **copy of the word**, i.e. a pointer into that area.
- **`beam_rt` never resolves, rebuilds or copies a module literal**: no `.literal(`/`LiteralArea` use exists in this crate's production code (the engine resolves `Operand::Literal` against `&Module`), and the arena (`Runtime::alloc_words`, `runtime.rs:2351`; the admission seam `context/gc.rs:1536-1578`) only ever carries **newly built** terms.
- **Every copy this crate performs shares a literal verbatim, at zero destination words.** `Runtime::stabilize_term`/`stabilize_term_with`, `copy_result_fresh` and the two re-homing arms (`context/pool.rs`, `context/calls.rs`) all drive `beam_message`'s copier, whose `is_shared` (`beam_message/src/copy.rs:267-275`) returns a literal-tagged compound word unchanged — so a **root** literal is skipped by every re-homing check by design (`result_is_foreign_container`, the immediates/literals skip, `relocate_off_scratch`).
- **No collector or window walk touches a literal**: `word_region` answers `None` for it (`context/gc.rs:382-400`), and the same literal test guards the valve oracle (`context/gc/valve_bounds.rs`), the reachability descent (`context/gc_walk.rs`), the statement-window reclaim (`eval/reclaim.rs`, `eval/reclaim/resource.rs`) and the window latch test (`eval/scratch.rs`).
- **Consequence: an object on a process heap, the arena, `eval_heap` or a pooled BIF heap may hold a literal word as a raw child, sound only while the owning `Module` is alive.** Retention is `CodeServer.modules: HashMap<String, Arc<Module>>` plus every live clone: `ProcessEntry::Export{module}` (`runner/entry.rs:47-56`), `LocalFunTarget.module` (`context/apply.rs:66`), the fun-identity snapshot, the thread-local descriptor index (`context/ir_cache.rs:272-278`), `get_until`'s continuation (`native/file_server/get_until.rs:235`).
- **Known issue — there is no literal-area release handshake.** The code store's one removal really unloads (`erlang:delete_module/1` → `context/runtime_hooks.rs:824` → `CodeServer::forget_module`; a reload replaces the entry), each dropping the cache's `Arc`, while `erts_internal:purge_module/2` and `erts_literal_area_collector:release_area_switch/0` are the oracle's `notsup`/unimplemented and no old-code slot exists. A term kept in a runtime store that carries a literal **word** — a `persistent_term` value, a timer's `Msg`, a `seq_trace` label, and any copier-based store such as ETS or a mailbox — can therefore outlive the module whose literal area it names. ERTS prevents this with the old-code slot plus the release handshake; this runtime has neither.
- **An `-eval` "literal" is a different thing**: the expression has no module literal area, so the evaluator builds each source literal on the run's store every time, and an `erlang:spawn/1` closure is compiled into a real `beam_rt_eval_fun_<n>` module (`eval/compile.rs`) whose literal area then belongs to the code server like any other module's.

`Eterm` in a `Runtime` field/Vec outlives every `beam_engine` call, so it must be rewritten or it
dangles. `Runtime` is at `runtime.rs:289-1082`; `stabilize_*` copies land on **`Runtime::eval_heap`**
(the copy is `beam_message::copy_struct_simple(term, &mut self.eval_heap)`), **not** on the arena.

`eval_heap` is rewritten at four non-running sites — the `-eval` statement window, `grow_eval_heap`'s
retirement, and the region-reclaim pass's two actions (dead-prefix `reset_to`, the store move's fresh
destination) — and `MAX_EVAL_HEAP_WORDS` (`1 << 25`) is a floor under the ceiling, so a bigger
configured store is never shrunk. `RetentionStats.eval_heap_words` is **capacity**, not written
volume, so `BEAM_RT_MEM_TRACE` cannot show a store-write regression.

### `mailbox.rs` — no release point, on purpose
`MailboxState` (`mailbox.rs:146`) holds a `QueueCursor` (an index), the markers (`Marker.term` is a
`make_small`, `Marker.reference` is the raw `make_ref` word `recv_marker_bind` recorded) and four
payload-handle vectors (`retained_fragments`/`retained_binaries`/`retained_off_heap`/`retained_nodes`).
A removed message's `Fragments` chain is *moved* into `retained_fragments` — retention, never
`Fragments::move_into` — and **nothing removes a pid's `MailboxState`**, so every fragment a process
ever removed lives for the runtime's lifetime; that absence *is* the soundness mechanism for a payload
word that escaped the message (the process heap, a container built around a received subterm, the
`seq_trace` label, an ETS `copy_struct` source), and it is why a receiver collection leaves such a
payload alone (`Target::Foreign`). Consequence: adding a `mailboxes.remove(pid)` on process death
would be a use-after-free for every raw-word store, and the two `Process::receive(|_| true)` **dequeue**
sites (`native/file_server.rs`, `native/net_kernel.rs`) bypass the retention — sound only because the
reply envelope they derive is deep-copied inside the same loop iteration, while the `Message` binding
is still alive.

## Term-carrying stores in `nif*.rs` · `codeserver.rs` · `boot*` (raw-word inventory)
What in these files holds a raw `Eterm` across a call boundary, and on which heap (§ *Host-side term
stores* in `../CONTEXT.md` is the crate-wide rule). Verified by reading the fields, not inferred.
The NIF half — every site, with its region and its lifetime — is `nif/CONTEXT.md`.
- **No NIF-side term is on the arena or the `-eval` store except the one `stabilize_term` copy**: a per-call `NifHostImpl` heap is the **pooled BIF heap** (`context/calls.rs` `take_bif_frontier` → `put_bif_heap`) and the load/unload host's is a dedicated `beam_alloc::Heap` owned by `NifEntry.host` — neither region is compacted, so the hosts' words are stable by construction.
- **`nif.rs` mints reference terms into `Runtime::references`**, and `nif_select.rs` stabilizes a select registration's reference/message onto `Runtime::eval_heap` (stored as `SelectPayload` in `SelectWatch.registrations`, `port/select.rs`) — **the one cross-file landing point of the `-eval` store outside `eval/`**, so a store move must relocate it (`RootFamily::SelectPayload`).
- **`codeserver.rs` holds no `Eterm` at all** (zero occurrences): `CodeServer` is `atoms: Rc<AtomTable>`, `modules: HashMap<String, Arc<Module>>`, two `String`-keyed location maps, `loaded_generation`, `fun_modules` and path vectors. The `Arc<Module>` does carry a literal area (`beam_loader/src/ir.rs:315`), and `erlang:delete_module/1` drops it, so a host store caching a literal word outlives its area (the "no literal-area release handshake" issue above).
- **`boot.rs` holds no term** (`PreloadedModules { names: Vec<&'static str> }`; `PRELOADED_MODULE_NAMES`/`CORE_ATOMS` are `&[&str]`), and `boot/preloaded.rs` has none either. `boot/bootscript.rs:518` `boot_args -> Vec<Eterm>` is a **per-directive local** on the **arena** and is never stored — but `Runtime::spawn_process` → `note_pending_spawn` re-copies each arg into `PendingSpawn.args` (`runtime.rs:4181-4185`), which **is** a struct field (inventory row above). `BootScript`/`Instruction`/`Mfa.args` are owned typed `Value`s, so a parsed script survives any term movement.
