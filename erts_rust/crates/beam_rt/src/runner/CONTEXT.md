# `beam_rt::runner` — the process runner behind the scheduler (tier · slice · park · off-heap prune)

## Intent
The concrete [`ProcessRunner`](beam_process::ProcessRunner) that `beam_process`'s scheduler drives: **one reduction slice of one scheduled process**.
It builds a [`RuntimeContext`](crate::context::RuntimeContext) that runs **as that pid** in the caller-supplied process table, takes the pid's engine out of [`RunnerState`], executes it and records the observable outcome.
A first entry runs `run_export_outcome_with_tier`; a re-entry — a reduction pre-emption, a `receive` park, a BIF suspend — runs `resume_outcome_with_tier` on the process's **remembered** tier.
The return value is stabilized (`Runtime::stabilize_term_with`) onto the runtime's `-eval` store (`Runtime::eval_heap` + its off-heap payload table) and recorded in `RunnerState::results`; a raise's live reason is stabilized (`Runtime::stabilize_error_live_reason`) into `RunnerState::exits`, with the original `BeamError` in `RunnerState::errors`.
A run to `return` exits `normal` — `x(0)` is the function's return value, not the exit reason — and a failure exits with the raise's own reason term, so nothing is swallowed and nothing is invented.
This node also owns the **execution-tier decision** (taken once per process, carried for its life), the **park root hand-off**, the **slice-boundary collection door**, the **slice-boundary off-heap refc-binary prune**, and the process's own pre-sleep signal work.
Per-suite routing: [`tests/CONTEXT.md`](tests/CONTEXT.md). Every measured figure and its caveats: [`MEASURED.md`](MEASURED.md).

## API Surface (crate-internal, `pub(crate)`)
* [`mod.rs`](mod.rs) — module docs (the borrow strategy: a pass `mem::take`s the process table and `RunnerState` out of the runtime, because the crate is `#![deny(unsafe_code)]` and may not alias), sub-module wiring, and the root re-exports (`ProcessEntry`, `RunnerState`, `EngineParkCensus`, `UnrunnableProcess`, `registered_name`, `RuntimeRunner`, `unbuilt_tier_request`, plus the `#[cfg(test)]` counter readers).
* [`entry`] — `ProcessEntry` (`Export { module, function, arity }` / `Fun`), `ProcessEngine` (the machine, the entry, `args`, `parked: Option<(func, pc)>`, the park bookkeeping `parked_published`/`fr_published`/`parked_timeout`, the remembered `tier`, the `arena_args` stability flag, `off_heap: Option<OffHeapReclaimer>`), `RunnerState`, and the two diagnostics `EngineParkCensus`/`UnrunnableProcess`.
  `RunnerState`'s pid-keyed maps (`engines`/`results`/`exits`/`errors`/`unrunnable`) are `crate::hasher::FastHashMap` — probed by pid only, never iterated for an observable order.
  `prune_dead(live, cancel_timeout)` drops the engine of every pid the pass's table no longer holds (cancelling the deadline a parked process armed), and runs once per scheduler-pass round beside `Runtime::prune_gc_requests` — so every death path (the `Exit` outcome, `ProcessTable::terminate*`, a kill-signal at schedule-in, a death while parked) releases the parked machine exactly once.
  Dropping a dead parked engine releases its machine (heap words and the off-heap refc-binary reservoir), its bin-vheap budget and its park state; a **live** parked engine is never pruned — the next pass finds and resumes it.
  `results`/`exits`/`errors` are deliberately **not** pruned (the CLI reads them after the target left the table), and `Runtime::mailboxes`' per-pid entries are never removed (that retention is the soundness mechanism for the raw-word payload stores).
  Read seams: `engine_at` (execution position; declines a fun entry and the pid currently executing), `position_engine_at` (the same plus the fun shapes and `apply/2`'s `$initial_call`), `reservoir_at` (`erlang:process_info(P, binary)` reads `Machine::refc_binaries` straight through it), `result`/`exit`/`take_error`, `contains`, `for_each_engine_census`, `for_each_error_live_reason`.
  Spawn seams: `spawn` (arguments **not** asserted stable, so the engine contributes no reclamation root), `spawn_stable` (the args and entry fun were copied onto the pointer-stable arena first — the only shape `gather_off_heap_roots` may hand over), `spawn_fun`.
  **Term-word holders** a rewriting pass must reach: `ProcessEngine::args`, `ProcessEntry::Fun::fun`, a resolved local target's args, `RunnerState::results`/`exits` (words on `Runtime::eval_heap`, not the arena) and the machine's own root slices.
  `gather_off_heap_roots` is the one value walk — an `arena_args && !args_consumed` engine's args+fun, and an un-published parked machine's roots (`live` filters that family only); it never visits `results`/`exits`, and it is empty during a pass.
  The four **mutable** doors hand `&mut [Eterm]` slices to a rewriting visitor (`FnMut(&mut [Eterm]) -> beam_common::Result<()>`, lengths fixed, order unspecified): `for_each_engine_args_root_mut`, `for_each_parked_machine_root_mut`, and the split pair `for_each_result_root_mut`/`for_each_exit_root_mut` (so the runtime-level walk tags `RootFamily::RunnerResult`/`RunnerExit` separately).
  `errors`' live reason word is reachable for **liveness only** (`for_each_error_live_reason`): `BeamError` exposes no mutable accessor, so a *moving* pass must refuse a region a recorded reason names instead of rewriting it.
* [`run`] — `RuntimeRunner`: the slice itself — tier selection, tier-aware first entry/resume, the three park arms, the boundary door, the off-heap prune, the parked-receive deadline rearm, the outcome stabilization. Detail in the sections below.
* [`budget`] — `BudgetProbe` (`charge` = the **refusing** primitive, `spend` = **pricing and never refusing**) and `BudgetContext`, the slice's outermost `ExecutionContext`: it owns `wants_reduce`/`reduce` (one charge per interpreted reduction) and forwards every seam it does not implement.
* [`tier`] — `JitMode`, the pure `mode_from_value`, the memoized `env_default` (plus the `#[cfg(test)]` per-thread `force`/`clear` override), `select_entry_tier`, and the CLI-facing startup check `tier_unavailable`/`unbuilt_tier_request`.
* [`reason`] — `normal`, `killed`, `exit_reason` only; the finite-`receive` deadline recovery lives in the engine (`Machine::wait_deadline`/`Machine::timeout_delay`), so no delay decoding is duplicated here.
* [`perf`] — `record_baseline_code`, the `+JPperf` code map (contract A.8; fills only an enabled perf map).
* `#[cfg(test)]` accounting in [`run`] — `run_slice_counters()` (slices/yields/waits/suspends; `note_slice_suspended` records a suspend as *also* a yield, which is what makes "the instruction was not applied and will be re-executed" structurally observable), `park_publish_counters()` (published/skipped) and `boundary_door_counters()` (checks/unpublished/collections/request_collected), each a per-thread `Cell` with a reader and a reset.
  Every one of them is a deterministic structural observation, never a timing, and a non-test build carries none of the increments.

## The execution tier (one decision per process)
### `BEAM_RT_TIER` — `mode_from_value` is the single definition of the value semantics
| value | mode | meaning |
|---|---|---|
| unset | `Auto` (**the `#[default]`**) | the native baseline tier for **every** process entry |
| `auto` | `Auto` | the default, named explicitly |
| `baseline` | `Baseline` | the same selection, forced explicitly (a measurement/debugging alias) |
| `cranelift`, `jit-cranelift` | `Cranelift` | the optional hot tier; sane only in a build with the `cranelift` Cargo feature (below) |
| `interpreter`, **anything else** | `Interpreter` | the always-correct reference tier and the **only kill switch**; an unknown value resolves here rather than being an error |

`env_default()` reads the variable once (a `OnceLock`), so a long-running process pays one `getenv`; `mode_from_value` itself is pure (no environment read), which is how a test pins the semantics without `set_var` (edition 2024 makes it `unsafe`).
`jit-cranelift` is accepted because it is exactly `Tier::Cranelift::name()`'s spelling, so a value copied from a tier report selects that tier back; `hot` is deliberately **not** a value — it names no tier.

### How and when the tier is chosen
```text
tier = match engine.parked { Some(_) => engine.tier,            // a resume re-uses the remembered tier
                             None    => { let t = select_entry_tier(.., state.jit_mode());
                                          engine.tier = t; t } }
```
The choice is made **once**, at a process's first entry, before the `RuntimeContext` borrow (the context takes `Runtime` mutably), and written to `ProcessEngine::tier`; every later slice takes the `Some(_)` arm, so a process keeps its tier for its whole life and is never silently demoted.
It is passed to both first-entry sites (the export entry's own label, and the resolved local-fun entry) and to the resume through `Machine::resume_outcome_with_tier`, whose `Tier::Interpreter` arm delegates to the plain `Machine::resume_outcome` (an interpreter-tier process is byte-for-byte unchanged).
The remembered tier is observable only at a **slice boundary**; a process that runs to completion inside its first slice never re-enters.
`select_entry_tier` is the single tier-decision seam and the **mode alone** decides: the baseline tier is sound for any module, so neither the entry's module nor its code is inspected (the parameters are kept for a future per-module policy).
The mode resolves from `state.jit_mode` if a test set it, else from `env_default()`.

### Why the native baseline tier is sound for any module
There is **no module the baseline tier cannot run**, so there is no per-module safety predicate and no warm-up: the tier is selected eagerly at the first entry, because a bounded warm-up would pin exactly the native hot loops to the reference tier for their whole life.
A compiled block is bound to one module (code, label map, literal area), so the one shape it cannot take alone is a `Step::Enter` — a step that continues in *another* module's code.
The engine's driver handles it: `Step::Enter` (from a compiled `call_ext`/`return` or the interpreter's own step) calls `Machine::switch_context`, rebinds module/label map/literal area and continues in the **callee's** compiled blocks, including the first sight of a not-yet-compiled module. That is a driver round-trip — a performance property, not a correctness one (engine-side detail: `crates/beam_engine/src/jit/CONTEXT.md`).
One host-side obligation remains, and it is enforced outright rather than by a predicate: **the cross-module seam must be idempotent**. The native `call_ext*` arm resolves through `ExecutionContext::resolve_external_call`, and when the host declines (`Ok(None)`) the *whole instruction* is re-run by the interpreter step, which consults the same seam a **second** time; a seam whose answer changed between the two consultations would route the callee two ways and could enter it in-machine under the caller's module identity. `RuntimeContext::resolve_external_call` is written for exactly this, pinned by `src/context/tests.rs` and `tests/nif.rs`.

### The Cranelift hot tier is opt-in twice over, and its absence is a typed gap
The backend is compiled in only behind the runtime's **`cranelift`** Cargo feature (default OFF, a pure re-export of `beam_engine/jit-cranelift`), so a plain `cargo build` has no hot tier at all; selecting it additionally requires `BEAM_RT_TIER=cranelift`.
The **selection is not feature-gated** — `select_entry_tier` answers `Tier::Cranelift` unconditionally, so the choice never depends on the build; whether that tier can be **served** is decided at two places, in a fixed order, both reading the *same* feature so they can never disagree.
1. **Startup rejection, owned by `beam_rt`'s CLI.** `tier_unavailable(mode)` answers the typed gap for a `Cranelift` request in a feature-off build (`None` for every other mode in every build, and `None` for `Cranelift` with the feature on); `unbuilt_tier_request()` is that check over the effective `BEAM_RT_TIER`, and `cli::drive` calls it once **before** the boot script is resolved or driven. The invocation then reports `beam_rt: unsupported: BEAM_RT_TIER=cranelift: this build has no cranelift execution tier (rebuild with the `cranelift` Cargo feature)` and exits 3 having done no boot work; `-version` is exempt (it runs no code).
2. **The engine's feature-gated entry points**, which answer `unsupported: opcode: jit-cranelift tier not built` at the moment an entry is attempted. They are the second line because without the startup check the *boot* processes are the first to try the tier, their per-process failures are re-wrapped by the boot drive, and the CLI would print an exit-1 `beam_rt: exit <structured reason>` that names no feature and reads like a crash.

A Cranelift process **resumes on its remembered tier**: `Machine::resume_outcome_with_tier` sends `Tier::Cranelift` to `jit::run_cranelift_resume_outcome`, which takes the artifact from the tier's retained store (keyed by the same `jit::cache::CacheKey` the baseline tier's cross-run cache uses) and re-enters the parked address through the shared no-reset native resume seam — same registers, same Erlang stack, same call frames, no recompile.
An address that is **not an enterable block start** advances by the driver's per-instruction interpreter step — the documented deopt, and the interpreter's exact semantics: a `wait`/`wait_timeout` suspension pc (which no block boundary names), a mid-block reduction refusal, a suspended BIF's own instruction, and every instruction of a cross-module callee.
So a feature-ON CLI session completes under `BEAM_RT_TIER=cranelift` (a `run`/`-eval` action and the whole `-boot` script, whose own processes all park and resume), never a wrong result and never a silent tier change.
Evidence: `fib_runs_to_the_same_result_on_all_three_tiers` (first entry), `a_preempted_process_resumes_on_its_cranelift_tier` and `a_receive_parked_process_resumes_on_its_cranelift_tier` (both suspension kinds), and the CLI suite `tests/tier_selection.rs` — see [`tests/CONTEXT.md`](tests/CONTEXT.md).

## The three park arms and the root hand-off (runner ↔ GC)
A slice can end three ways, and **all three** hand the machine over through the **one** entry point `park_window(table, pid, engine, fr_count, ParkExemption)`, right before `engines.insert`: the pre-emption/`Yield` arm, the `receive` `Wait` arm and the BIF-park `Suspend` arm.
A suspended process's machine lives in `RunnerState::engines`, but its registers are only a *copy* of the process's own root set — and a collection driven while the process is parked is **not** gated by `Runtime::gc_process_enabled` (`Process::deliver`'s exit cascade and the signal paths both collect), so a parked machine that had not published its roots would be collected against a partial root set and left with a stale word in its `x`.
**The invariant is: *a window that skips the root publication holds the relocation exemption for its whole duration*.** `park_window` derives one `exempt` value from its `ParkExemption` argument, writes the process flag from that same value **in both directions** (so a publishing window can never inherit a stale `true`) and only then delegates to `park_machine` — the flag and the publication decision cannot be set by different sites, and a new park arm chooses a `ParkExemption` and cannot forget the flag.
There is exactly **one** `ParkExemption` variant, `LiveFloats`: the exemption holds exactly when the slice ended with a live FR prefix (`fr_count > 0`), because the machine keeps those slots as roots of its own and no publication can carry the whole file. **Which arm parked never decides the exemption — only the slice's FR prefix does.**
The exemption has one writer (`park_window`) and one clearer (`run`'s parked branch, `set_relocation_exempt(pid, false)`, where a parked window ends).
`park_machine` (whose sole caller is `park_window`) always records the live prefix on `ProcessEngine::fr_published`, and then either sets `parked_published = false` without publishing (an exempt window) or sets `parked_published = true` and calls `publish_parked_roots` (a non-exempt one).
`parked_published` is an **unconditional** claim, not `publish_roots_full`'s answer: the helper's `bool` is discarded, sound only because both of its `false` arms are structurally unreachable today (`live = min(x.len(), MAX_REG)` cannot fail `set_live`; the stack-length check cannot mismatch on the one append order). A future change that can make it fail must gate `parked_published` on that answer instead, or the `Yield` arm's boundary collection and off-heap prune would run against a **partially** published root set.
`resume_from_process_roots(ctx, pid, machine, fr_count)` runs **only** when the matching park published (then clearing the flag), and is called after `ctx.enter_module(module)` whenever `engine.parked.is_some()`; it replays the **same** `fr_count` the park used (`ProcessEngine::fr_published`).
The window's `set_relocation_exempt(pid, false)` is cleared unconditionally afterwards.

### Why the skip is sound, and what the publication carries
The skip is sound because for an exempt window's whole duration **nothing can relocate this process's heap**: `Process::collect`/`ensure_capacity` return the typed refusals and `collect_if_needed` answers `false`; `ProcessTable::deliver` and every `beam_process` signal site refuse on `has_unpublished_roots()` (which is `relocation_exempt || Running`); `Runtime::serve_gc_request` returns before collecting and drops the request; the host collection gate declines; and `Process::grow_nursery` — the one growth path deliberately **not** gated — relocates nothing (it retires the old space onto a chain the next collection collapses).
So the parked machine stays the authoritative root set and the publish+resync pair would be a pure identity round-trip over a `min(x.len(), MAX_REG)`-word x file plus the Erlang stack, both ways (the argument is on `park_machine` itself).
A **dead**-FR window publishes and holds no exemption, so a delivery into a blocked receiver really collects/grows its nursery and copies the payload **straight into it** — the C's own route, and the default path of every ping-pong and server loop.
The exemption is **additional** to the installed host collection gate (`context/gc_walk.rs`'s `RuntimeCollectionGate`, installed by `Runtime::new`): the gate declines when an unscanned container is reachable from the receiver's *gathered* roots, while the exemption refuses *any* relocation for the window.
Admission points inside a resumed slice are unaffected, because the next slice entry clears the mark — the reaction is per slice, never a permanent pin.
Every park arm also calls `Runtime::serve_gc_request` (`erlang:garbage_collect/0,1`): it is served in a publishing window, where the machine's whole root set including the extra roots was just handed over, and declined-and-dropped under an exemption, where the process's own next admission point (after the resume cleared the mark) serves it.

What the pair publishes and reads back is the **shared** root-hand-off mechanism, not this node's: `publish_parked_roots`/`resume_from_process_roots` delegate to `context::gc`'s one implementation (`publish_roots_full`/`scatter_roots_full`, `fr_count` bounding the published FR prefix), which the in-slice admission points (`ensure_heap_full`/`alloc_words_rooted`) also use, so the park/resume and the admission doors can never drift (`../context/IMPLEMENTATION.md`, `../context/gc/CONTEXT.md`). This node owns **which arm publishes and when it may skip**; the facts it relies on:
* `publish_parked_roots` hands the roots over with `RootSet::ALL_LIVE` — the conservative choice, since a parked machine's live count is not exposed and over-approximating a copying collector's roots can only keep a term alive.
* The FR file is published only up to `Machine::fr_mark()`, read **once** per slice and reused for both the post-slice reaction and the `publish_parked_roots` call. `fr_mark` is an **exact upper bound**: every FR write goes through `Machine::set_fr` and the baseline tier refuses an FR destination (deopting to the interpreter), so a slot at or above it is `NIL` and roots nothing — a float-free park publishes **no** FR word instead of the 1024 slots `process.regs` would carry, and being an upper bound it can only err by over-pinning.
* The count is stored on `ProcessEngine::fr_published` at the park and replayed at the resume, so `scatter_roots_full` never sees a length mismatch (a mismatch halts the process's collection rather than writing a mis-sized block back).
* `publish_parked_roots` **also** publishes the terms the engine holds **outside** the closed `RootSet` shape, because they are *fields*: the machine's live `pending_exception` reason **first**, then the engine's host-held families (`ProcessEngine::append_parked_host_terms` — the first-run arguments, a fun entry's fun term and a resolved local fun's argument list, each only while `args_consumed` is false). They go onto the process's `Registers::extra_roots` (the host escape hatch `beam_process`'s `gather_roots`/`scatter_roots` relocate in place); with **no** live term of either kind the set is left **empty** (cleared, never a `NIL` placeholder), so a stale root can never keep an otherwise-dead term alive.
* The word it publishes is live by construction, so it is published unfiltered: `Machine::with_roots` parks the machine's loose heap terms (`LOOSE_HEAP_TERMS` — the two failed-clause argument latches, the pending exception's reason and the two supplied-trace latches) at the tail of the Erlang stack for the closure's duration and re-seats every field from the slot the host wrote back, and that funnel sits behind `Machine::alloc_rooted`/`Machine::ensure_heap`, hence behind **every** in-slice collection door on every tier.
* An extra root is a **relocation channel, not a liveness claim**, so the published word is always an immediate, a literal-area pointer (nothing a collection moves) or a container inside a region `pid`'s own collector relocates — never a word a collection would have to follow without being able to move it.
* `resume_from_process_roots` is `RuntimeContext::resync_parked_roots`: the engine first adopts its own relocated families back into the fields they were published from (`adopt_relocated_parked_roots`, skipping the reason slot when one is armed), then the context copies the process's authoritative root set back into the machine (the leading FR words only up to `fr_count`), writes the already-relocated extra-root reason into `Machine::pending_exception_mut()`, **clears** the extra roots (the machine owns the relocated term now), and halts the process's collection (`Runtime::halt_process_gc`) if the slices no longer match.
* The resume's re-derivation is self-consistent only because nothing host-side touches the machine between park and resume: `scatter_roots_full` recomputes the expected width as `machine.stack.len() + armed loose terms`, which can differ from the park's only if the machine's stack or its loose-term latches changed while parked.

### The raise arm is the escape boundary for a raised error
The runner stabilizes the `BeamError` itself, because its structured reason term is a raw `Eterm` in the raise's live-reason slot, built on the dying process's heap or on the recyclable pooled BIF region.
The copy's `SourcePayloads` come from `Runtime::source_payloads` — the executing **machine's** handles unioned with the whole off-heap family the pid's scan retained from the messages it received (`MailboxState::retained_binaries`/`retained_off_heap`/`retained_nodes`), since a payload the process *received* carries its handles on the message envelope, not on this machine.
So a reason that *is* an off-heap binary (`exit(<<big/binary>>)`) is resolved and shared rather than tripping the valve, whether the process built it or received it; the recorded exit reason is derived from the stabilized error (`reason::exit_reason`: atom → the stabilized live term → interned `Display` text), so one copy serves both exit propagation and every later rendering.
A reason that cannot be copied is the honest `error:system_limit`, never a stored dangling word; `Runtime::as_action_process` is the same boundary for the `-eval`/`-s`/`-run`/boot-directive routes.

## The slice boundary's off-heap refc-binary prune
`run`'s `Yield` arm is the **one** site that prunes the machine's payload reservoir: `RuntimeRunner::reclaim_off_heap_binaries` → `context::gc::reclaim`, immediately after the boundary collection and before `take_max_heap_kill` on the same park.
It is here because a prune is sound only against the process's **complete** root set, and the park is the one site holding `&mut Machine` (the runner just drove it), `&mut Process` (through the table) and `&mut Runtime` at once; an admission door runs *inside* a slice, where the engine is held out of `RunnerState::engines` and the `ExecutionContext` seam exposes no `&mut Machine` at all.
The call refuses unless `engine.parked_published`. `Process::has_unpublished_roots()` is deliberately **not** the gate — it is `true` for a `Running` process, which a pre-empted process still is.
The state it needs is per engine (`ProcessEngine::off_heap`, built lazily from `process.collector().policy()` so a `+hms`/`+hbm*` policy is honoured and the budget dies with the machine), so one call reaches `&mut machine` and `&mut off_heap` without a second table.
The gates (relocation exemption, `gc_process_enabled`, the bin-vheap trigger, the collection valve, the prune-only valve, the reachability walk) and the release predicate are [`../context/CONTEXT.md`](../context/CONTEXT.md) *The off-heap refc-binary reclamation*; every one of them is a decline, so this call never fails a program.
Per-slice cost on a non-triggered bin vheap is **one cached observation**: `OffHeapReclaimer::observe` returns the recorded overhead while the reservoir's handle count has not moved, so the `O(reservoir)` `Machine::off_heap_overhead_bytes` is read only when it moved or once per triggered prune.
**Residuals — each a leak, never a dangle.** The `Wait` arm runs no prune, and the bin-vheap budget only *gates* a prune (`triggered` is consulted, never asked), so it can never *cause* one: the window a build-a-binary loop can accumulate is **one slice's length**, always, even for a process that never reaches a `receive`. A process that blocks forever keeps its reservoir until it wakes and yields again; a declined prune retains the whole reservoir; a dead process's reservoir is released by the pass boundary's `prune_dead`, not by this arm.
The reservoir is **not** mirrored onto the process: `Machine::refc_binaries` is the one holder of what the process's compiled bitstring code built, so `erlang:process_info(Pid, binary)` reads it through `RunnerState::reservoir_at` (another pid) or the in-machine door's published roster (the executing one) and the PCB's own off-heap table stays empty — mirroring would hand `beam_gc::OffHeap`'s never-compacted slot space a slot per payload per slice and make a build-a-binary loop quadratic in its own iteration count.
The `-eval` route never prunes **this** reservoir (its machine is not in `RunnerState` and publishes nothing); the store it does prune is the separate escaped-payload store `Runtime::eval_off_heap`, swept at the evaluator's depth-0 statement boundaries and at the nested-run epilogue (`adopt_nested_payloads` → `Runtime::prune_off_heap`), which owns the payloads a fun applied on that route builds. On the `run` route the same body runs **in-machine**, so its payloads land in `Machine::refc_binaries` where this arm does bound them.
Envelope, figures and the `emqx_base62:encode/1` end-to-end record: [`MEASURED.md`](MEASURED.md) *The off-heap prune's per-fixture envelope*, *The off-heap reclamation end to end*.

## The collection sites this node owns (and what each publishes)
**The scheduled path is the only path that collects at all.** `RuntimeContext::gc_armed` is `mem::take`n as the **first statement** of each rooted door (`../context/execution.rs`), and the only arming sites in the workspace are `budget`'s three doors (`BudgetContext::ensure_heap`, `ensure_heap_full`, `alloc_words_rooted`). So on the `-eval` route, a nested `run_export`, a fun a BIF applied and the evaluator, `armed` is `false` and every door refuses to collect — **a heap can only move during a scheduler slice**.
`BudgetContext::call_bif_in_machine` and `reduce` do **not** arm, so no collection can run inside a BIF dispatch — the invariant `../context/position.rs` relies on.
| site | reached from | publishes | gate |
|---|---|---|---|
| `context::gc::ensure_heap_full` | `Instr::TestHeap`/`AllocateHeap` → `Machine::ensure_heap` + the baseline-JIT twins | `x[..pointer_prefix_len]`, whole stack, `fr[..pointer_prefix_len]` | `armed` + the unscanned-root valve |
| `context::gc::alloc_words_rooted` | `terms::reserve`, i.e. every `*_rooted` builder, per built term | the same narrowing | `armed` + valve |
| `context::gc::ensure_heap` (narrow) | **no engine call site** | `x[..live]` + stack, **no FR file**; float-guarded | `armed` |
| `context::gc::reds_door::collect_at_reds_boundary` | `run`'s `Yield` arm only | `RootSet::ALL_LIVE`: all 1024 x slots + whole stack + `fr[..fr_count]` | `parked_published`, `gc_process_enabled`, the 4 000-red interval, `is_relocation_exempt`, 7/8 occupancy or `collection_debt`, valve; skipped when a `garbage_collect` request already collected over the same published roots |
| `context::gc::alloc_words` | anywhere | **never collects** (grow + retry, else the arena) | — |
The slice-boundary off-heap prune is **not** a collection site and gets no row: it relocates nothing, publishes nothing of its own, and prunes the machine's payload reservoir rather than a heap.
Out of slice, `ProcessTable::deliver`/`enqueue_exit_signal`/`grow_receiver_for_signal` relocate a **non-running** receiver only (all refusing on `has_unpublished_roots()`), so they cannot touch a running process's heap.
**Publication is airtight for `x`/`stack`/`fr`; the open root-set question is a holder in NO root set.** The park publishes all 1024 x slots (`live = min(x.len(), MAX_REG)`) and no production site shrinks `live`, so `XRegs::gather_roots` gathers every published slot; `is_pointer_bearing` is exactly "not `TAG_PRIMARY_IMMED1`", so an atom/small/`NIL` can never be bound away by `pointer_prefix_len`.
What no root set covers: the marshalled BIF `args` copy at the `&self` door `Machine::dispatch_bif_call` (no write-back channel), and the `Runtime`-owned term stores (`Runtime::in_machine`, `timers`' reference key, `references`, mailbox markers, `trace`/`seq_trace` specs, `eval_closures`).
**Two hand-off asymmetries a dangling-pointer hunt must know.** (a) A failed publication would leave a **stale** published set behind a window a collection may still move — unreachable today only because `XRegs::set_live` errs on `n > MAX_REG` alone and `publish_roots_full` clamps to it. (b) A failed **scatter** halts collection *after* the collection already moved the heap, which is not the "unmoved heap" `Runtime::halt_process_gc` documents: the parked machine keeps its from-space words and the process keeps running on them, so the failure surfaces later as a dangling term read rather than a typed error.

## Per-slice (not per-instruction) host cost
Beyond the `BudgetContext` charges (a per-instruction `reduce` on the interpreter tier, the two `ensure_heap` doors, a per-BIF/per-call `spend` on the native tier), one slice's prologue/epilogue does this host work — amortized over the whole 4 000-reduction budget, so per-`run`, never per-iteration:
* **O(1), no allocation:** the engine take-out/re-insert, the FR prefix read (`Machine::fr_mark()`), the tier lookup, `note_reductions`, `serve_gc_request` (early-returns with no pending request), and — on the `Yield` arm only — `current_code()`, `reset_reductions`/`bump_reductions`.
* **One allocation per slice:** `RuntimeContext::enter_module` builds a fresh `String` of the module name on every slice; a `RuntimeContext` itself is a stack value.
* **O(size), on a park whose window is NOT relocation-exempt:** the publication copies the whole x file (up to `beam_process::registers::MAX_REG` = 1024 words) + the whole Erlang stack + the live FR prefix onto the process's root set, and appends the extra roots. An exempt window skips the copy entirely.
* **Amortized O(1):** the off-heap trigger (see the prune section) — a slice that built no payload pays one cached observation, and the payloads need no per-slice work because no slot is ever handed out on the process's own table.
* **First entry / flag-gated only:** `record_baseline_code` (`+JPperf`), the `Arc::clone` of the entry module, `describe_site` (debug-trace). `source_payloads` runs only on the terminating `Returned`/`Err` arms.
* **No production time read:** `Instant` appears only in `tests.rs`; the slice path makes no `sys` call of its own.

## A process's own signal work before it sleeps
A signal a process queues on **itself** is delivered before its next schedule-in, through two mechanisms because the C has both.
**The in-scan fetch** (`../context/execution.rs`'s `receive_next`, the C's `i_loop_rec` → `erts_proc_sig_receive_helper` → `erts_proc_sig_fetch`): an exhausted scan with a non-empty signal queue applies its **receive-applicable prefix** through `ProcessTable::service_receive_signals` and re-reads the scan, so a trapped `{'EXIT', …}` and an awaited `'DOWN'` cost no extra scheduling round.
That drain is strictly FIFO and stops *before* the head it cannot apply: a trapped exit and a monitor `'DOWN'` are delivered, an `Ignore` head (a `normal` exit to a non-trapping receiver) is discarded, and the walk halts at the first head whose `exit_policy` is `Terminate`, leaving it and everything behind it queued — a `Terminate(_)` verdict has no channel inside the machine's instruction stream to report a death, so the terminating classes are left to the net below rather than duplicating `exit_policy` here.
**The schedule-out net** (`run`'s `Wait` arm, the C's `schedule_out_process`/`active_sys_enqueue`): after every park bookkeeping step, a process whose `pending_signals` are non-zero returns `RunOutcome::Yield` instead of `Wait`, so the scheduler's `slice_end` re-enqueues it and `slice_begin`'s `service_signals` applies the queue at its next entry — the C's re-enqueue-instead-of-sleep, and the only site that may terminate it.
Three invariants hold: the pid is put back on its run queue by exactly the arm that owns the `Runnable` transition (no double scheduling, no lost wakeup); the queue drains monotonically, so a process cannot spin (one re-entry either matches the materialised message or parks again with an empty queue); and the `Waiting` state is overwritten to `Runnable` while the park window's publication stands, so a delivered message either lands on the receiver's heap or takes the documented heap-fragment fallback when a valve declines the collection.
The residual is scheduling **granularity**, not the answer: the drain applies the whole receive-applicable prefix in one call where the C's walk is reduction-bounded, so pre-emption inside a long signal burst is the engine's own reduction budget at the caller (`ProcessTable::service_receive_signals`'s documented approximation). No term and no order changes.
Pinned end to end by `tests/signal_self_delivery.rs` over `tests/fixtures/sigself.erl` — all eight shapes print the live oracle's own line.

## Term-lifetime rules this node is bound by
* A raw `Eterm` in a long-lived slot roots nothing: both recorded outcome terms are stabilized **before** the engine re-enters (or drops out of) `RunnerState`, and a parked machine's whole root set is either published or kept authoritative by the window's exemption.
* The process's root set — not the machine's stale copy — is the truth across a park, so a resume always starts from `resume_from_process_roots` when the park published.
* Refuse ⇒ stabilize, never dangle: an off-heap payload is resolved from `source_payloads` and copied, and a reason that cannot be copied becomes the honest `error:system_limit`.
* The machine's reservoir is never mirrored onto the process's never-compacted off-heap slot space; the *published* per-park FR/stack/x words are the only per-slice term traffic.
* This node holds no `Rc<AtomTable>` (and no other `Rc` lease) across an allocation — the deep-copy/danger rule is `../codeserver.rs`'s, and the runner takes no handle at all.

## Constraints
* **`#![deny(unsafe_code)]`**; no `unwrap()` on runtime data; typed `beam_common::Result` errors, no crate-local error enum, no panic-as-control-flow.
* The tier is resolved **before** the `RuntimeContext` borrow — the selection happens in the slice's prologue, before the context takes `Runtime` mutably.
* A test forces a tier by setting `state.jit_mode = Some(..)` (or the `#[cfg(test)]` per-thread `force`/`clear`) — never `std::env::set_var`, which edition 2024 makes `unsafe`. `BEAM_RT_TIER` is the CLI-facing equivalent, and its semantics are pinned through the pure `mode_from_value`, not through the environment.
* `JitMode::Baseline` is an alias of the default selection; only `JitMode::Interpreter` turns the native tier off, and `JitMode::Cranelift` is the third selection — whether it can be *served* is the `cranelift` Cargo feature, read by the CLI-side startup check, never a mode and never an arm inside the selection.
* Files target ~1000 lines; `run.rs` (1 585 lines of production) and `tests.rs` (a 216 KB suite) are the pre-existing overages, catalogued in `../CONTEXT.md`'s *File-size overages*.

## Known Issues / Gaps
* **An early return out of `run` between the engine take-out and a re-insert drops that process's machine.** The `Yield` arm's `current_code() == None` return and the `?`s that follow it all return while `engine` is still a local; the pid stays on the run queue, so the next slice answers `refuse_engine_less` → `Wait` with the state restored to `Runnable` and nothing ever runs it again — and the machine, the only holder of that process's live x/stack while parked, is gone. Minimal fix: re-insert the engine before returning the error.
* **A natively executed compiled block is charged at a deopt, at a heap-admission point and at each *priced* BIF/call seam — but only a *refusing* seam can end its slice.** `spend` never refuses and is a silent no-op once the budget is gone, so a **non-allocating BIF-and-call-only loop still ends no slice of its own**: the single `Yield` such a row reads is the run's epilogue seam, and the boundary door stays unreachable for the loop. The memory half is served (that one `Yield` does collect, so `heap_size` sits on the collector's floor instead of tracking N).
  A refusing charge cannot be taken at a call seam today, because the native tier publishes `machine.current_code` at **block** granularity and its call paths consult the seam before storing any position of their own — a refusal would park at block entry and the resume would re-execute the block prefix. **Handoff (out of this crate):** `beam_engine` must store the instruction address before consulting the seam at those sites, after which a call seam may refuse and `tests/slice_charging.rs`'s third pin is the assertion that must change.
* **A matched-N `ns_per_call` comparison against a runtime that never collects is not like-for-like** on an allocation-shaped loop: that runtime runs **zero** collections (the admission declines and the nursery grows) where this one collects 2.65 times per call, so the difference is the memory management each performs — not dispatch, not tier. Figures: [`MEASURED.md`](MEASURED.md) *Not like-for-like*.
* **An uncaught raise's stacktrace is never rendered on the compiled route.** The runner flattens a raise to a reason **term**, and the CLI prints one line (`beam_rt: <class> <reason>`, with `cli.rs::reported_reason` swapping in the `~w` rendering of a live structured reason on every route). There is no `** exception error:` / `=ERROR REPORT` renderer in this crate (the one ERTS report text is the `max_heap_size` block in `../context/gc.rs`), so `Raise::stacktrace` has **no consumer** here: its only readers are the `-eval` catch fold and `process_info(_, current_stacktrace)` (from the live machine, not from a raise).
* **The `-eval` route is not this node's:** `RuntimeContext::mailbox_table` is `None` there, so no engine parks, no machine publishes, `gc_armed` is `false` and the escaped-payload store (not the reservoir) is the prune target.
