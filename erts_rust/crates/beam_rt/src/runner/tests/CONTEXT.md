# `beam_rt::runner::tests` — the runner's whole-run accounting suites

## Intent
The three `#[cfg(test)]` sub-suites the runner declares from the **head of `../tests.rs`** (`mod boundary_cost; mod reds_door; mod slice_charging;`, `../tests.rs:52-54`), so they live here.
Each drives a real `Runtime` through the runner and pins **deterministic counters** — never a timing — about exactly one accounting surface: what the slice-boundary collection door costs and how often it fires (`boundary_cost`), that the door really is the only collection point for a shape that reaches no heap-admission instruction (`reds_door`), and what a reduction slice charges on the native tier (`slice_charging`).
The seam-level rows (tier selection, park hand-off, budget primitives, finite receive, recorded outcome) are the colocated unit suites in `../tests.rs`, 59 `#[test]`s; these three are the whole-run accounting layer above them and share its harness.
**The measured tables and their full derivations live in each suite's own module doc** (`boundary_cost.rs`, `reds_door.rs`, `slice_charging.rs`) — that is the table's home; read the module doc of the file you touch rather than expecting a table here.
Cross-runtime figures and the general caveat record: `../MEASURED.md`; this node's contracts: `../CONTEXT.md`.

## API Surface (suite-internal helpers, `#[cfg(test)]`)
* `../tests.rs` (shared harness, declared before the three `mod` lines): `GrowthCounters` (`:3907` — slices/yields/waits/collections/major/peak young spaces/capacity/used/mature capacity/used/reductions/debt boundaries/value/errors), `run_growth_counted` (`:3949`), `run_growth_function` (`:3962`), `growth_runtime` (`:4025`), and `COUNTER_RUN_DEADLINE` (`:3903`, 300 s).
* Every helper drives the run through `Runtime::spawn_process` + the scheduler loop and samples the collector **at slice boundaries** — the only window in which a live process's collector is readable from outside the runner (a terminated process is gone from the table), which is why a run that completes inside its first slice reports **no** nursery capacity.
* Each suite prints its own measured row (`report`/`eprintln!`, visible with `--nocapture`), so a pin and the figure it prints are always the same run; nothing here reads a wall clock.
* `boundary_cost.rs` adds `Run` (the shape's `GrowthCounters` plus the door's own `BoundaryDoorCounters`) with the per-boundary `peak_young_used`/`copy_words`/`process_collections` samples, and `run_counted` (which takes the entry function name, because `slice:fib/1` has no `run/1`, and resets the door and slice counters around the run).
* `reds_door.rs` adds `peak_heap_size` (the `process_info(P, garbage_collection)` `heap_size` read after the loop) and `plateau_words` (the fullsweep/minor **fixed point** the plateau must satisfy — it asserts the policy's own rules reproduce their target, so the plateau is a steady state rather than a quoted number).
* `slice_charging.rs` adds `native_reds_row`/`heap_growth_row` (one row per N), `emulator_default_policy`, `collector_floor_words`, `last_linear_native_reds_n` and `report`.

## `boundary_cost.rs` — what the door costs on a hot shape
The `gc_bound` churn shape (`fixtures/churn.beam`), the allocate-and-abandon loop whose bench row is one of the hot ones; on a shape that also reaches the heap-admission doors the total collection count mixes two sites, so the runner tallies the door itself and this suite pins that tally.
One `#[test]`: `the_boundary_door_is_a_per_preemption_watermarked_site_on_the_churn_shape` (`:394`).
Pins (`:41-70` and the asserts): one door check per pre-emption and one pre-emption per full slice (`door.checks == yields`, `slices == ceil(reductions / 4 000)`, `yields == slices - 1`); the seven-eighths watermark's ration band `door.collections * 8 <= door.checks <= door.collections * 12` with the door collecting under 1 % of the run's own collections; the shape's totals linear in N at a fixed per-call rate, pinned as the exact measured table rather than as a formula.
`peak_young_spaces == 1` on every row (`:587`); the table itself is the module doc's; the ON-vs-OFF *cost* delta is deliberately **not** claimed (it would need a door-disabled build).

## `reds_door.rs` — the door on a shape that reaches no admission point
`fixtures/reds_boundary.erl` (`run/1`): a BIF-only allocation loop — `list_to_tuple(lists:seq(1, 400))` — whose module contains **no** `test_heap`/`allocate_heap` at all (`erlc -S`), so `alloc_words` and the BIF-result copy-out can only *grow* the nursery and nothing but the slice-boundary door can ever collect it.
One `#[test]`: `a_bif_only_loop_is_collected_at_the_yield_boundary_and_its_heap_size_plateaus` (`:232`).
The two halves it pins: with the door live, `heap_size` plateaus at **2 586** words with one young space at every N and `yields == collections` (every pre-emption collects exactly once), the plateau's live set being the whole in-flight iteration (1 201 words) so the capacity is the fullsweep rule's target and never a function of the loop count; with the door disabled the same rows retain ≈1 300 words per iteration and take **0** collections.
The run is forced onto the **interpreter** (`tier::force`/`clear` behind a `Drop` guard, `:71-98`), because only the interpreter is pre-empted — the native tier links this self-tail-recursive loop into one block that never crosses the per-instruction hook and would complete inside a single slice, making the counters meaningless.
Figures and the per-N table: the module doc.

## `slice_charging.rs` — the native tier's slice charge, and the shape that can never end its own slice
`fixtures/native_reds.{erl,beam}` (`heap/1`: `reds_boundary`'s BIF-and-call-only loop plus one in-process `process_info(self(), heap_size)` read) and `fixtures/heap_growth.{erl,beam}` (one 401-word `test_heap` per iteration).
One `#[test]`: `the_slice_budget_prices_native_work_and_a_refusing_seam_still_ends_the_slice` (`:401`), whose four pins are the module doc's `# The four pins`:
1. the charge is real and, below the budget, an **exact** price: `reductions == 4N + 9` (4 = the two `call_ext` resolutions + the two BIF dispatches; 9 = the run's entry/epilogue seams, asserted as a sum only), with `priced(N) = reductions - 9` an exact multiple at every N;
2. the budget boundary is **derived**, not calibrated: `floor((4 000 - 9) / 4) = 997` is the last single-slice N, `998` is the clipped crossing row (`spend` is a no-op on an exhausted probe, so it reports exactly 4 000), `999` is the first row needing a second slice;
3. a native loop that reaches a **refusing** seam does end its slice: `yields + 1 == slices`, `slices == ceil(reductions / 4 000)`, at most `4 000 / 3 = 1 333` iterations per slice, and collections `1 + N/K` with `K = 2` derived from the row's own settled capacity (843 words, or 987 once a fullsweep has re-sized the mature region) — both branches of the fullsweep mechanism pinned, never a threshold in N;
4. **the honest residual**: `native_reds` prices only through `spend`, so past the budget it runs *uncharged* and its one `Yield` is the epilogue's refusing charge — `reductions` saturates at exactly **4 006** and `slices/yields` stay `2/1` over a 40× N span where a loop-driven cadence would need `ceil((4N+9)/4 000)`.
The interpreter control is the same fixture under `JitMode::Interpreter`: it charges per instruction, so its totals track the work — the residual's discriminator — and its `heap_size` is bounded by the live-set-targeted minor rule instead of following N.
The suite asserts the native baseline selection on entry and fails loudly otherwise, so an ambient `BEAM_RT_TIER` cannot silently invalidate every row.

## The cadence invariants and their pins (read before changing any heap-admission policy in `../../context/gc.rs`)
* **`peak_young_spaces == 1` per measured row** — the nursery chain never carries a retired space: `../tests.rs:4283` (bundled with `debt_boundaries == 0`, in `the_heap_growth_workloads_per_call_counters_are_flat_in_n`), `boundary_cost.rs:587`, `slice_charging.rs:855`.
* **`collections == 1 + N / K`, with `K` *derived* from the row's own measured capacity, never quoted**: `../tests.rs:4110`'s `heap_growth_iterations_per_nursery` (measured `K = 2` on every row, asserted at `:4256`-`:4276`) and `slice_charging.rs`'s `heap_growth` rows; the `churn` counterpart is the per-row exact table (`boundary_cost.rs:327`'s `MEASURED_YOUNG_CAPACITY = 2_585` plus the module doc's table).
* **The door's ration laws**: `door.checks == yields`, `slices == ceil(reductions / 4 000)`, `yields == slices - 1`, and the band `door.collections * 8 <= door.checks <= door.collections * 12` (`boundary_cost.rs`); there is deliberately no target firing frequency — the lower edge is a non-no-op floor, and a thinner ration is strictly cheaper.
* **This node asserts no exact `Runtime::gc_stats().reclaimed` figure and never calls `note_gc_reclaimed`**; `gc_stats().collections` is read only as a before/after delta or an inequality.
* **The direct `Process::collection_debt()` assertions are `../../context/`'s** (`../../context/tests.rs`, `../../context/calls/exempt_window_tests.rs`); here the debt appears only as a sampled `debt_boundaries` count that must be `0` (`../tests.rs:3993`, `boundary_cost.rs:257` sample it; the asserts require it to stay zero).
* **No test in this crate compares live GC counters, `process_info(_, garbage_collection)` or `erlang:memory` figures against the oracle** — a cadence figure is a function of this runtime's own policy, not of parity.

## Constraints
* **No wall clock, ever.** Every pin reads a deterministic counter or a structural tally; `Instant` appears only in the fixtures' sampling deadlines (`COUNTER_RUN_DEADLINE`), never in an assertion.
* **A test forces a tier through `tier::force`/`clear` (per thread, behind a `Drop` guard) or `RunnerState::jit_mode`** — never `std::env::set_var` (edition 2024 makes it `unsafe`), so a failing assertion cannot leak a tier into another test.
* **A suite that needs the system Erlang skips loudly** through `../../../tests/support/mod.rs` (`skip_loudly`/`require_oracle`) rather than silently passing.
* Fixtures are the committed `.beam`s under `../../../tests/fixtures/` (sources beside them); a suite never compiles one at run time unless its own doc says so.
* `#![deny(unsafe_code)]` and the crate's error discipline apply here unchanged; a fixture's own raise is asserted as a value, never swallowed.

## Notes for Agents
* Suite gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_rt runner::` (plus the crate gate for the whole node). `--nocapture` prints the measured rows.
* **A figure in a module doc is only true if its own pin still reads it** — when a change moves a constant (the per-iteration price, `DEFAULT_REDUCTIONS_PER_SLICE`, a capacity), the derivation in the module doc must be redone, not the assertion relaxed; the suites' docs say which law each figure is derived from.
* Adding a suite: declare it as `mod <name>;` in `../tests.rs` (the three existing ones sit together at `:52-54`) and put the file here; share the harness rather than re-implementing a scheduler loop.
* The suites deliberately do not test the sibling `../../context/`'s valves or the door's internals — only what the runner observes through them; a policy change belongs there.
