# `beam_rt::port::driver` — the driver C-ABI host for `{spawn_driver, Name}` ports (A.4)
## Intent
This node is the runtime's **own** driver C-ABI host: the code in the parent node's `src/port/driver.rs` plus every file under `src/port/driver/`.
It is **separate** from `beam_io`'s own host layer (`beam_io::abi`), so end-to-end `.so`-driver traffic goes through this tree.
`driver.rs` pairs a loaded driver library with the per-port host its callbacks run against, implements `beam_abi`'s frozen `DriverHost` seam and maps that host onto `beam_io::Driver`.
`state.rs` owns the driver-private byte queue and the one-PDL guard; `monitor.rs` owns the driver monitor tree; the suites beside them pin both against real C drivers.
The driver-emitted-term queue (`erl_drv_output_term` / `erl_drv_send_term`) is the host's one term-carrying channel.
Relative paths inside the paragraphs below are written from the parent node (`src/port/`), so `../native/…`, `../tests/…` and `../runtime/…` name the parent's own siblings.
The runtime halves of the six driver→owner channels — `completion.rs`, `failure.rs`, `exit.rs`, `inet_opts.rs`, `active_input.rs`, `peer_closed.rs` — are files of the parent node; this node documents their mechanics because a driver callback is what stages every one of them.
## API Surface
### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a loaded driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops); `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_`, whose handle **is** the per-port `DriverEnv`'s address.
`load_driver(candidates, name)` delegates to `beam_abi::driver::loader::load`, tries each candidate and reports the **last** typed error; the loader appends the shared-object suffix to **every** candidate unconditionally (`erl_unix_sys_ddll.c:104-118`), so `shared_object_stem` strips one trailing `.so` first.
`binary_to_term` (`erl_drv_binary_to_term`) decodes into a **per-thread memoized image** of the shared table (`crate::nif::with_decode_scratch`, validated in O(1) by an `AtomSnapshot` witness), records an appended name at its predicted index (`intern`, never `intern_atom`: the interner's `base` is fixed at host build) and answers the C's `ERTS_DDT_FAIL` (`None`) for an invalid image, never a raise; the registry hooks carry the C's codes — `add_driver_entry` → `0`, `remove_driver_entry` `1`/`0`/`-1` (`io.c:7698`), `lock_driver` off the load state (`:7324`), `create_port` = the invalid-port sentinel.
`DriverPort` owns the driver-private state the frozen seam has no home for: `driver/state.rs` holds the C's `prt->ioq` (`io.c:6790-6919`) byte queue (one chunk per successful `driver_enq`/`driver_pushq`) behind `enq`/`pushq`/`deq`/`sizeq`/`peekq`, plus the `pdl_created` one-PDL guard; `with_port_flags` carries the port's **state** stream bits (`StreamType::port_flags` → `PORT_FLAG_BINARY` (1) for a `binary` port, else `0`), a **different** cell from `set_control_flags`' `control_flags` (`io.c:5325-5344` vs `:5318`); `clear_driver_state` (from `stop` **and** the adapter's `Drop`) drops the queue so a late drain never reads a gone port's bytes.
`DriverPortAdapter` is the port **lifecycle**: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, in a `Box` that never moves); `output` hands queued bytes to `outputv` when declared (**the C's preference**, `io.c:1782`/`:1597`) and to `output` otherwise — so an **`outputv`-only** entry receives `port_command` — and queues the `driver_output` reply as the port's **input**; `stop` runs the entry's `stop`, the drop `finish` + `dlclose`. An `OUTPUT` task (`Port::run_task` → `ready_output`) **always** drains the output queue through that one `output` path and *then* runs a declared `ready_output` slot as the write-**readiness** notification (`erl_port_task.c:1793-1797`); the adapter maps `load`/`name`/`state`/`selected`/`control` (verb parsed as a `c_uint`)/`control_reply`/`notify_ready` (one **already-resolved** descriptor's `ready_input`/`ready_output`) plus the monitor tree, `has_process_exit` and the shared `Rc<ProcessLiveness>`.
`build.rs`'s `-Wl,--export-dynamic` publishes the `driver_*`/`erl_drv_*` symbols; `open_port({spawn_driver, Name}, Options)` routes here for a name no built-in driver answers, an unknown or empty driver name being `badarg`.
**Two shared flags, seized at load.** `BusyFlag` (`driver.rs:540`) is one handle for both halves of the busy state — `busy` (a `Rc<Cell<bool>>` written by `DriverHost::set_busy_port`, `io.c:5208-5264`) and `soft_busy` (stamped by `load` from `library.entry().driver_flags`, so the bit is the **entry's**); `OsPidFlag` (`:599`) the same for the OS child pid, written by `DriverHost::set_os_pid` (`io.c:2971`) and read for `port_info(Port, os_pid)` (`erl_bif_info.c:3814-3817`). Both are seized **before** `load` consumes the boxed host (`DriverPort::busy_flag`/`os_pid_flag`); `PortMeta::driver_busy` is the runtime's handle (`port.rs:613`), `PortMeta::driver_os_pid` its owed counterpart (Known Issues). Three `beam_io::Driver` capability overrides read them — `is_busy` forwards `BusyFlag::is_busy`, `flags` reports `DriverFlags::SOFT_BUSY` **iff** the entry advertises `ERL_DRV_FLAG_SOFT_BUSY`, `has_control` the entry's own `control != NULL`; `set_os_pid` answers `0` when a port lifecycle has claimed the host and `-1` otherwise, and `clear_driver_state` does **not** clear it (the C's `prt->os_pid` outlives the driver's private state).
`DriverPort` implements **35 of the 45** `DriverHost` hooks declared in `beam_abi/src/driver/host.rs` — all four registry slots, the failure channel's three (`failure`, `port_exit`, `port_term`) and `async_pool` (the handle `driver_async` submits through, `:2104`); the other **10** keep the frozen trait default (the C's own failure code) in three groups — the `r#async` **legacy fallback** (reached only by a host with no pool) and `async_port_key`, the **lifecycle** family minus `set_os_pid` (`busy_msgq_limits`/`init_ack`/`pdl_lock`/`pdl_unlock`/`pdl_inc_refc`/`pdl_dec_refc`/`pdl_get_refc`) and **`now`** — each needing runtime structure a per-port host holds no handle to.
**The failure latch, and `ERL_DRV_PORT`.** `FailureLatch` (`:643`): `set` is **first-wins** (a second answers `-1`), `take` the drain, `is_pending` the quiescence probe, `clear` the teardown's forget. `DriverPort::failure` maps the seam's `PortFailure` onto `beam_io::DriverFailure` (`Eof`/`Atom`/`Posix`/`Error`), flushes the private `ioq` (`io.c:7220`) and answers `0`/`-1`; `port_exit` latches `DriverFailure::exit(code)` (`signals_owner = false`); neither can close a port, so `DriverPortAdapter::settle` drains the latch — **output first, then the request** (`DriverContext::deliver_read` refuses a read once a failure is latched), a refused hand-off **re-latched** for the next callback.
`PortTerms` (`:714`) is the per-port `ERL_DRV_PORT` state behind `DriverHost::port_term` (`erl_driver.h:523`): `driver_mk_port` answers the **handle** while the term-data layer has no port table, so it is stamped with the handle/`PortId` pair in `start`, read back by the hook, `mark_gone`'d from `clear_driver_state` — a cached `ErlDrvPort` cannot become a dead port's id term, and an unstamped host answers `None` (the C's `ERTS_DDT_FAIL`). The timer family matches the C for **every** live port (a silent `no_timeout_callback` substitutes when the entry declares no `timeout` slot, `io.c:7601`), so `io.c:6918`'s `-1` stands only for an invalid port.
`apply_select` is the adapter's interest half: a direction mask is widened or dropped through `beam_io`'s reregister/deregister, and the C's "done with this event" form (`driver_select(p, e, ERL_DRV_USE, 0)`) runs the entry's `stop_select` through `fire_stop_select` once nothing is left armed (`erl_check_io.c:1212-1216`).
The event handed back is `fd as ErlDrvEvent` — the identical handle the driver gave `driver_select` — and an entry with no `stop_select` slot is the C's `no_stop_select_callback` (`io.c:7546-7553`), a no-op.
`armed_event` recovers the descriptor a `ready_input`/`ready_output` call must hand the driver from the driver's own selections: exact for one registration per direction, and a typed capability gap (never a wrong descriptor) once a driver has armed several.
`LOADED_DRIVERS` (`driver.rs:1322`) is the runtime's one name-keyed loaded-driver list — `record_driver_loaded` fills it from both load routes — and it is the list `erl_ddll:*` reports **and** the one `open_port({spawn_driver, Name}, …)` resolves a name against.
### Driver-emitted terms (`erl_drv_output_term` / `erl_drv_send_term`) — `TermQueue`
`beam_abi` decodes the driver's term-data stack machine into a real term on the host's arena and calls `DriverHost::send_term(port, to: Option<Eterm>, term)`; the C delivers there and then (`io.c:5664`) and the frozen seam gives the host no route to a receiver's mailbox, so the term is **queued** in a per-port shared `TermQueue` — `None` = the connected process (`io.c:6254`), `Some(pid)` an explicit destination (`:6289`).
A queued term's words live on the host arena, so the adapter empties the queue in both `beam_io::Driver::stop` (`io.c:6213`) and its `Drop`; `PortRegistry` seizes the handle as `meta.driver_terms` at `open_port/2`, and `take_driver_terms` surfaces each as `PortEvent::Term{port, to, term, owner}`, which the pump copies onto the pointer-stable arena (`stabilize_driver_term`) and delivers.

### `port/completion.rs` — the driver→owner **completion channel** (A.4)
A socket driver cannot answer a `port_command/2` (nor a queued async op) in a control op's return value — the C *sends a message* — so `completion.rs` turns `beam_io::PortCompletion` (`beam_io/src/completion.rs:289`) into `InetReply` → `{inet_reply,…}` / `InetAsync` → `{inet_async,…}`, which is what unblocks `prim_inet:send/4` and its siblings in `receive {inet_reply,S,Status,Mref}`.
`CompletionPacket { port, owner, stream, event }` (`:105`) is term-free and resolves recipient and stream at **drain** time (a completion staged around a teardown outlives its `PortMeta`, the C's `async_error_am_all`); `ClosedPortSnapshot { port, owner, stream, line }` (`:129`) is taken by `close` **before** `meta.remove` and consulted only for the number closed; `PortEvent::Completion { packet }` rides `pending_events`, so `has_nothing_to_poll` covers it and both routes match exhaustively (`Runtime::deliver_port_messages`; `RuntimeContext::poll_port_messages`, the latter taking only a completion addressed to itself).
**One drain entry point**: `PortRegistry::drain_io_completions(fallback)` (`:175`) composes `drain_failures()` **first** (the driver-closed-its-own-port channel) and sweeps every snapshot that drain answered plus the caller's `fallback`, so an operation a teardown answered through `async_error_am_all` is attributed through the closed port's snapshot and the failure channel needs no drain row.

|---|---|---|
| `pump`'s round, right after `execute_port_tasks` | `:1811` | the task (or the `output`/`control` it runs) stages it |
| `pump`'s "nothing live to poll" early return, after `report_pending_closes` | `:1884` | minting the last close report answers its queued operations |
| `write_command`, inline `registry.output` (a `.so` driver) | `:1336` | the driver's own `output` stages a `gen_udp:send` reply |
| `write_command`, `execute_port_tasks` branch (a built-in) | `:1373` | the `OUTPUT` task that carries the command |
| `port_control` (defensive) | `:1445` | `prim_inet`'s `recv`/`accept` arms queue an operation that completes later |
| `close`, after `registry.close` | `:1718` | the teardown's `async_error_am_all`, harvested into a registry-owned queue |
**Rendering** — `RuntimeContext::{completion_message, inet_reply_message, inet_async_message, decode_caller_tag}` on the pointer-stable `-eval` arena after the registry borrow drops, every atom interned in the runtime's **one shared** table; `Id` is the 16-bit id the control-op reply handed out, as a small integer; `decode_caller_tag` (`:499`) decodes the `term_to_binary(Mref,[local])` image through `crate::nif::with_decode_scratch`, interning any appended name back into the live table.

**`Accepted { fd }` adoption.** `PortRegistry::adopt_accepted` (`:312`) is the runtime's half of the C's `tcp_inet_copy` (`inet_drv.c:11795`), and it drives the C's own copy constructor: `self.registry.driver_as::<TcpInetDriver>(listener)` resolves the listener's concrete driver through `beam_io`'s read-only downcast, `TcpInetDriver::from_accepted(fd, listener)` (`beam_io/src/drivers/inet/mod.rs:924`) adopts `fd` as **owned** and copies the listener's option store plus the cached `stype`/`family` inside the driver, and the result is registered in the `PortMeta` block `open_port/2`'s built-in arm builds (no OS child, the driver's own `control` capability, the **listening** port's `stream`/`line`).
The inherited block therefore reaches the accepted driver by **struct copy**, so no `port_control` replay happens at all.
The runtime's own `PortInetOptions` mirror is seeded by direct copy of the listener's `mode` and `exit_on_close` (`seed_inet_latches`, `inet_opts.rs:393`; the C copies `inet.mode` at `inet_drv.c:11811` and `inet.exitf` at `:11812`) while `active` starts **unknown**, i.e. the passive default — the copy list (`:11814`-`:11844`) omits `inet.active` and `inet_start` resets it, so `{active,…}` is left to `prim_inet:accept_opts/3`'s Erlang half exactly as the C leaves it.
The descriptor is **owned by the completion** from staging on: every path hands it to a driver (closed on teardown) or releases it via `discard_descriptor(fd)` (`:431`, `beam_io::close_fd`) — **never leaked**.
A refused `from_accepted` releases it and answers the constructor's **own** errno (`BeamError::Io`'s `raw_os_error()`, so a descriptor that is not a socket is `enotsock`, never a borrowed `ebadf`); a refusal that carries no errno — an unresolvable listener driver, or a non-`Io` constructor failure — ⇒ `{error, closed}`, the C's own teardown reason (`inet_drv.c:12690`); no port number left ⇒ `{error, emfile}`.
The `None`-downcast arm (a listener that is not a `TcpInetDriver`) is unreachable from `beam_io`'s accept path — only the in-crate `TcpInetDriver` stages `InetAsyncResult::Accepted` (`beam_io/src/drivers/inet/accept.rs:345-384`), and `INET_REQ_FDOPEN`'s prebound route copies nothing (`inet_drv.c:5223-5282`) — yet it releases the descriptor and answers rather than panicking.
### `port/failure.rs` — the driver-failure channel's runtime half (A.4)
A driver closes its **own** port through the C's `driver_failure*` family or `driver_exit` (`io.c:7196-7278`) — a **port-closing request**, not a return value: `beam_io` latches it inside the callback (`DriverContext::signal_failure`), runs the ordinary teardown (`reap_failures` → its `PortRegistry::close`, so the driver's `stop` runs, the port leaves the live map and its `Closed` report is minted) and queues the term-free `PortFailure` (`take_failures`); this module is the half `beam_io` cannot do, owning no terms and no process table.
`signal_reason(&FailureReason) -> PortSignalReason` (`pub(crate)`) is the **one** reason rule: `Eof`/`Normal` ⇒ `PortSignalReason::Normal` (not `Atom("normal")`, so the link family's *`normal` is ignored* policy applies), `Atom(name)` ⇒ that name, `Posix(errno)` ⇒ `InetReason::from_errno(..).atom_name()` (the lowercase name, never `{error, ·}`), `Code(n)` ⇒ `Integer(n)`.
`PortRegistry::drain_failures()` takes every queued failure and answers the `ClosedPortSnapshot` of each port it finished, for the completion sweep that follows; `fail_port(id, failure)` is `close`'s bookkeeping **minus** the two steps `beam_io` already performed (no `registry.close`, no `notify_port_exit`) and otherwise the same helpers in the same order: `closed_snapshot`, `remember_failed_read(id)` (the recipient the read its callback wrote before failing needs, captured at the only instant it is readable), `failed_port_monitors(id)`, `port_exit_signals(id, reason, failure.signals_owner, monitors)` **before** the metadata goes, `pre_round_monitors.remove`, `meta.remove`, `extras.forget_port`, the purge of retained events — which drops only what an earlier round retained for the port, the failing callback's own read being folded **after** this teardown — then `push_port_signals` — straight into the deliverable queue, never stashed, because the port is already closed **and** reported, so one failure yields exactly one `'EXIT'` and one `'DOWN'`.
**Delivery policy** is the C's single `erts_deliver_port_exit(prt, id, reason, 0, 0)` path, so one close's `'EXIT'` **and** `'DOWN'` render the same reason; `signals_owner == false` (the `driver_exit` family, `io.c:7244`) produces **no `Exit` entry** while every monitor still gets its `'DOWN'`, and `RuntimeContext::port_exit_reason_term` interns the atom name in the runtime's one shared table (so a `receive` clause can match it) or builds the bare small integer.
### `port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`
A port is linkable and monitorable, so a close owes what a dying process owes its peers: `{'EXIT',Port,Reason}` to a **trapping** link and `{'DOWN',Ref,port,Port,Reason}` to every watcher, `'EXIT'` before `'DOWN'`.
Two closers only, both carrying a reason — `port_close/1` (`PortRegistry::close`) with `normal`, a driver closing its own port with its own (`failure.rs`); the reason rides the signal (`PortSignal::reason`), so one close's `'EXIT'` and `'DOWN'` can never disagree. Policy: a **trapping** peer gets that `'EXIT'`, a non-trapping one **nothing** on `normal` and termination with that reason otherwise, every watcher its `'DOWN'` (outgoing `PortWatch` removed), a recipient the table lacks is skipped. `PortSignalKind{Exit, Down(MonitorRef)}` + `PortSignal{port, to, kind, reason}` are per **recipient**, so a route observing only its own mailbox takes its own entries and leaves the rest queued in `PendingPortSignals{unreported, ready}`.
The obligation is discharged in **two steps**, because `beam_process`'s `ProcessTable::port_closed` frees the port number while `beam_io` keeps it until its `PortNotification::Closed` report is minted (`take_closed_notifications` → `ids.release`), so a `close`+`open` in one slice cannot make a deferred report name a different live port. `port_exit_signals(id, reason, signals_owner, monitors)` is that obligation's pure reader (the metadata, the link set — `extra_links`, or the owner for a never-reconnected port — and the caller's monitor reading, **not** the always-empty `PortMeta::monitors`); `capture_port_exit(id)`, called from `close` while all three are readable, wraps it with `normal` and only **stashes** the snapshot, and `fold_notifications`'s `PortNotification::Closed` arm moves it into `ready`.
The monitor set is a **parameter** because there is one pure reader and two sources: `close` passes the live `beam_process::PortTable::monitors` (authoritative there — the port has not been reaped yet), and `fail_port` passes `failed_port_monitors(id)`, the one place that chooses — the live table while `beam_io` has closed but not yet reported the port, the pre-round snapshot once minting has retired the number and dropped its monitors with it. `signals_owner` is the owner-`'EXIT'` suppression mark (`PortExtras::no_owner_exit` ⇒ `false`, `exit.rs:290`), producing the `'DOWN'`-only set the C's `driver_exit` produces (`io.c:7244` unlinks first). The failure channel bypasses that second stage (`push_port_signals` → `push_ready`) because `beam_io` has already closed *and* reported its port when `take_failures` answers.
Delivery is **pull-based**: `Runtime::deliver_port_signals` takes every deliverable entry (the `run` route, via `RuntimeContext::deliver_in_table`, so a parked receiver wakes) and `RuntimeContext::poll_port_signals()` only its own process's (`take_port_signals_for`, the `-eval` route); `PendingPortSignals::prune(alive)` drops an undeliverable entry, which would otherwise hold `has_nothing_to_poll()` false for ever.
### `port/inet_opts.rs` — the per-port inet option mirror (A.4)
`prim_inet:open/6` opens every `inet` driver port with **one** option, `[binary]` (`erts/preloaded/src/prim_inet.erl:99-137`), and applies every other socket option afterwards through `setopts/2` — an `erlang:port_control/3` call carrying the C's `[opt_code, val_be32]` records — so neither `open_port/2`'s options nor `PortMeta::stream` know what the **driver** has been told; `inet_opts.rs` is that knowledge, keyed by **port number** inside `PortExtras` (`inet: InetOptions`) so `forget_port` drops it.
The mirror is **three latches**, decoded out of each `setopts` argument as it arrives: the driver's `{mode, list|binary}` (`PortInetOptions::mode`, option code `INET_LOPT_MODE`), its `{active,…}` (`::active_mode`) and its `{exit_on_close,…}` (`::exit_on_close`, code 26).
There is **no recorded-bytes store** and no inheritance replay: an accepted socket's option block is inherited inside the driver, by `TcpInetDriver::from_accepted`'s struct copy, so this module never has to resend a record.
One entry point — `PortRegistry::note_inet_setopts(id, arg, ok)`, called from `src/port.rs:1843` once the driver has answered, gated on `is_setopts_control(op)` and `setopts_succeeded(reply)` — so a rejected `setopts` can never move a latch; the reply is read, never consumed, and the suites' own `setopts` helpers **detect** that hook so they are no-ops on a wired runtime (`accept_inherit_tests.rs::a_setopts_control_call_populates_the_option_mirror_from_production_alone`).
**The wire reader.** `walk` splits an argument into records while `rest.len() >= 5` (the C's `while (len >= 5)`, `inet_drv.c:6908`) and answers `None` if **any** byte is left over: the C ignores a partial trailing record, whereas a latch moved by a half-parsed argument would claim a configuration the port does not have. `record_len` is the C's per-code span: `linger` `RECORD+4`, `multicast_if` the whole `RECORD`, membership `RECORD+12` (IPv4) / `RECORD+20` (IPv6) and `None` for any other domain, `{active,N}` `RECORD+2`, `raw` `RECORD+8+arg_sz` with `arg_sz` at `RECORD+4..RECORD+8`, `netns`/`bind_to_device` `RECORD+value`; `RecordBytes` is the borrowed slice a decoded record names.
**Two consuming groups, and that is the whole surface.** (i) `PortInetOptions::mode` → `PortRegistry::data_mode(id, fallback)`, which every inet delivery renderer reads, because a post-`open_port/2` `{mode,…}` never reaches `beam_io`; (ii) the `active_mode`/`exit_on_close` latches the `peer_closed.rs` gates read (`inet_active`/`inet_exit_on_close`, and `inet_exit_on_close` defaults to the C's `true`).
`seed_inet_latches(id, mode, exit_on_close)` is how an adopted socket's `mode` and `exit_on_close` latches are filled from its listener — inherited, the C's `inet.mode` (`inet_drv.c:11811`) and `inet.exitf` (`:11812`) copies (its `seed_inet_mode` step fills `mode` alone); its `active` latch is **not** inherited (the copy list omits `inet.active`), so an adopted socket starts passive-unknown exactly as the oracle's does.
### `port/active_input.rs` — the `{active, …}` input channel (A.4)
The driver→owner path of an `{active, true|once|N}` socket: such a socket never parks its input in the port's byte queue, so the driver *sends a message to the owner* from its read-readiness callback (`beam_io`'s `drivers/inet/active.rs`, `drivers/inet/udp/active.rs`, one `ActiveInput { port, event }` per delivered unit through `DriverContext::deliver_active_input`); `active_input.rs` is the runtime half, its module docs carrying the C derivation.

| `ActiveInputEvent::Passive` | `udp_inet` | `{udp_passive, S}` | the same builder, the other branch |
- **`ActiveInputPacket { port, owner, data_mode, kind, event }`** mirrors `CompletionPacket`: owner, stream mode and port **kind** resolve at **drain** time (`PortRegistry::drain_active_inputs`, from `PortMeta`), because a delivery staged around a teardown outlives the metadata; `ActivePortKind { Tcp, Udp, Other }` comes from `driver_path_name(&meta.command)`, `Other` being a **typed gap** for both events, never a fabricated `{tcp,…}`, never a silent drop; a delivery whose port has left is **dropped**, and the packet carries the `owner`/`port` it resolved, so nothing is re-attributed to a later port reusing the number.
- **One delivered unit is `beam_io`'s decision**: one frame under a framing `{packet,N}` (header already stripped), one read burst under `{packet,raw}`; a read's `header` is the `{header,N}` option (`desc->hsz`) for a stream port and the 7-byte packed source address for a datagram port — never the framing header.
- **Payload rendering goes through the one stream shaper**: TCP calls `make_stream_payload(read, mode, StreamShape::Data)`; UDP decodes the address out of the read's header (`decode_packed_address`: `[INET_AF_INET(=1), port_hi, port_lo, a, b, c, d]`, port big-endian) and shapes the **body alone** from a header-less `ReadMessage`; a header that is not exactly one packed IPv4 record is a typed gap.
- **The mode seam is `PortMeta::data_mode`** (body = `self.stream`, the **open-time** option): `{mode, list|binary}` never reaches `beam_io`, so a post-`open_port/2` change lives only in the `inet_opts` mirror and the rendering mode is resolved at the delivery arms from `PortRegistry::data_mode(port, packet.data_mode)`; do not add a second `PortMeta::data_mode` in `port.rs` (a duplicate inherent method is a compile error).
- **Delivery rides every point a driver callback can stage one**: `drain_active_spends()` runs first — harvesting `PortRegistry::take_active_spends` into the option mirror — and `drain_active_inputs()` immediately after, at each of the six `drain_io_completions(...)` sites, publishing `PortEvent::ActiveInput { packet }` on `pending_events`, so `has_nothing_to_poll` stays truthful without an arm of its own and `PortEvent::port()` answers `None`, so `close`'s purge can never re-attribute or drop a staged delivery; `Runtime::deliver_port_messages` (the `run` route) delivers to `packet.owner` through `deliver_in_table`, `RuntimeContext::poll_port_messages` (the `-eval` route) only when `packet.owner == self.pid()`.
- **Residual — `hsz > len`, a `beam_io` seam.** The C's list branch is `(mode == LIST) || (hsz > len)`, so a `{header,N}` wider than the payload is one flat string with no binary tail; `beam_io`'s `split_payload` clamps `hsz` and hands that case up as a whole-payload header with a present-but-empty body, rendering `[104|<<>>]`; field order is kept, `[list]` mode is exact, every shape the e2e suite exercises has `hsz <= len`, and it is pinned at the renderer (`active_input_tests.rs::a_header_as_wide_as_the_payload_keeps_an_empty_binary_tail`).
- **A spent `{active,once}`/`{active,N}` grant keeps the peer's bytes in the socket.** The delivery that spends the last credit clears the driver's read arm (`beam_io`'s `TcpInetDriver::read_armed`, the C's `sock_select(desc, FD_READ, 0)`), so a write arriving while the grant is spent reaches the owner as **nothing** — no `{tcp,S,Data}`, no passive `{Port,{data,…}}` — until a re-arm's inline read hands it over, and that delivery spends the re-arm's own grant. The oracle's row (`active_input_e2e_tests.rs`'s `TCP_PROBE`, re-measured by `the_oracle_renders_every_shape_these_cases_assert`): `<<104,101,108,108,111>>` under the grant, `timeout` for the write under the spent grant, `<<119,111,114,108,100>>` at the re-arm, `timeout` for the write after it, `<<97,103,97,105,110>>` at the next re-arm; `active_input_e2e_tests.rs` cases 1 and 5 and `../../../tests/inet_active.rs`'s `t3` assert that sequence.
### `port/peer_closed.rs` — the peer-close channel (`{tcp_closed, Port}`)
`beam_io::PortRegistry::port_closed(id)` is a **latched, sticky** observation that a connected socket's peer has closed; `peer_closed.rs` turns it into the oracle's 2-tuple. `PeerCloseKind::Tcp` (`:129`) is the only kind — deliberately **no `udp_closed`**, because the C has no such atom, so a `udp_inet` port never reports a peer close. `PeerCloseReport { port, owner, kind, exit_on_close }` (`:151`) is the term-free drained report; `PeerCloseLatches` (`:184`, `is_reported`/`mark_reported`/`forget`/`prune`/`len`) is the once-per-descriptor latch set keyed on *reported*, so the sticky re-fire works; the latches live in `PortExtras::peer_closes` and are dropped by `forget_port`.
`collect_peer_closes` (`:283`) gates on `is_tcp_inet` over `driver_path_name` (so a `{spawn_driver,"tcp_inet"}` port and a spelled object path both resolve) and reads `registry.port_closed(id)`; an error or `false` forgets the latch, because a number `beam_io` recycled after an unseen close must start clean; it then skips an already-reported number, gates on `inet_active`, reads `inet_exit_on_close`, marks reported and pushes. `drain_peer_closes`/`drain_peer_closes_for(to)` (`:263`/`:277`) wrap that one collect, the `-eval` form leaving a foreign recipient's latch **undrained** rather than dropping it; `forget_peer_close(number)` (`:392`) is the idempotent per-number half.
`inet_active` (`:426`) is the port's **live** `{active,…}` state, read from **two sources**: `beam_io::PortRegistry::active_mode` first (the driver's own live `desc->inet.active`, spent or not), the mirror only when the registry cannot answer because the port already left `beam_io`; an **unknown mode is passive**, the C's own `inet_start` default (`inet_drv.c:10932`), because a fabricated `{tcp_closed,S}` is worse than none, and a passive observation **keeps its latch**, so a later `{active,…}` makes the report due (the C's sticky arm, `inet_drv.c:7013-7021`); `inet_exit_on_close` (`:415`) mirrors code 26 and defaults to `true` (`desc->inet.exitf = 1`, `inet_drv.c:10929`).
**Delivery, each half shaped like its `exit.rs` sibling.** `Runtime::deliver_peer_closes(&mut ProcessTable)` (`:454`) is the `run` route: it drains, skips an owner the table no longer holds (but still retires when `exit_on_close`), builds `peer_close_message` after the registry borrow drops, and delivers through `RuntimeContext::deliver_in_table` with the port as sender, so a receiver parked in `receive` wakes; `RuntimeContext::poll_peer_closes()` (`:535`) is the `-eval` route — `drain_peer_closes_for(self.pid())` paired with its sender (the port) for the mailbox delivery, retiring when `exit_on_close` — and `peer_close_message` (`:565`) interns `kind.tag()` (`"tcp_closed"`) in the runtime's **one shared** table and builds `terms_tuple(&[tag, report.port.to_eterm()])` on the pointer-stable arena.
**Retirement is `driver_exit`, not `port_close/1`.** `PortRegistry::retire_peer_closed(id)` (`:378`) mirrors `tcp_recv_closed`'s `if (desc->inet.exitf) driver_exit(desc->inet.port, 0)` (`inet_drv.c:12835-12837`), which runs `unlink_proc` **before** it delivers (`io.c:7244`): it refuses a port the runtime no longer holds (tested before the mark), sets `PortExtras::no_owner_exit`, then calls the ordinary `close`, so the `'DOWN'` set is `signals_owner = false` — every monitor gets `{'DOWN', Ref, port, S, normal}` and a **trapping linked owner gets nothing**, measured on the oracle (`erlang:port_info(S, connected)` ⇒ `undefined`); those `'DOWN'`s become deliverable at the port's close **report**, so the caller's route reports them one round later, and `Runtime::retire_peer_closed_port(id)` (`:502`) skips a port already gone rather than folding that `badarg` into a delivery error.
Its 16 cases are `peer_closed_tests.rs`: the active-mode and `exit_on_close` mirrors, the latch's recycle rule, one report per descriptor, the passive-then-armed re-fire, the two **spent-grant** twins (`{active,N}` exhausted and `{active,once}` spent — silent close, then exactly one report at the re-arm, with the driver's own spent state asserted and the `{tcp_passive,S}` that only the `INET_MULTI` arm sends), `udp_inet` reporting nothing, the tag atom, the `'DOWN'`-only retirement, both delivery routes, the foreign-latch rule, one real loopback peer close end to end, and the two `erl` oracle cross-checks of the spent-grant twins (the real `gen_tcp` listen/accept/client program, its printed answer compared with the ports masked).
A spent grant is passive **at the close**: `inet_active` reads `beam_io::PortRegistry::active_mode` first (the driver's own `desc->inet.active`, cleared by the delivery that spent it, `INET_CHECK_ACTIVE_TO_PASSIVE`, `inet_drv.c:1552-1560`), so the close takes the passive arm (`:12819-12832`, no message, no port death) and the observation keeps its latch for the sticky re-fire (`:6968-7016`) — `{active,once}` never sends a `{tcp_passive,S}` (`:1554-1555`), the `{active,N}` arm does at its zero (`:1556-1558`).
## Constraints
- `#![deny(unsafe_code)]`: the registry slots operate over a **thread-local** entry list `DRIVER_ENTRIES`, not a process-global `DriverTable`, because the runtime drives every port on one thread.
- Every driver callback runs under `publishing` → `beam_abi::with_current_host` (`start`/`ready_*`/`output`/`timeout`/`stop`), which lets the two port-less registry slots reach a host during a callback.

## Known Issues (the host's own residuals — each a typed capability gap or a measured own-state difference, never a wrong result)
- **`port_control/3`** — behind `has_driver_control`. The reply's **shape is the first discriminator**: a `NULL` reply pointer is `[]` for **every** `PORT_CONTROL_FLAG_BINARY` word (`io.c:4134`, tested before the flag is read); a real buffer is a **binary** when the flag is set — zero bytes included, i.e. `<<>>` (`io.c:4136-4162`) — and a **byte-int list** otherwise (`io.c:4163-4166`, at every length); a reply from the driver's **own** memory is the typed *unsupported* (Handoffs).
- **The shape and the flag are both facts of the call just made, read after it**: `beam_io::ControlReplyShape` comes from the driver (`Driver::control_reply_shape`, latched by `driver.rs` on every successful `control`), the flag from the port (`PortRegistry::control_binary`). A built-in driver answers the `Buffer` default. Pinned by `driver/control_tests.rs` (the adapter's `NULL` vs `cres == 0`-on-a-buffer rows) and `driver/control_reply_oracle_tests.rs` (the four rows over one real `cc`-built driver under both runtimes).
- **A driver port can never report `{exit_status,N}`** — `driver_report_exit` (`io.c:5533`) is not declared in `erl_driver.h`, so `take_exit_status`'s `Ok(None)` is correct, not a gap.
- **`driver_async` is LIVE; `driver_async_port_key` is the async residual.** `driver_async` submits to `DriverHost::async_pool` (`beam_abi/src/driver/drv/port.rs:756-792`) — the pool's monotonic ids, `+A N` workers and `async_free` bookkeeping are `beam_abi/src/driver/async_pool.rs`; `drain_async_pool` runs on **every** round (`port.rs:2194`, `:2219`, `:2244`); each port's drive point calls `ready_async` or the job's `async_free` under the C's `need_free` policy (`driver.rs:2862`, `:3176`); `+A 0` is a genuine zero-worker pool whose jobs run inline (`runtime.rs:1193-1197`, `port.rs:1215-1218`, pinned by `async_ready_tests.rs`, 5/5 green); a port closed with jobs in flight keeps its library mapped until `pending_for(port) == 0` (`async_ready.rs:139-146`, `:367-399`). Still the trait default: `async_port_key` (and the legacy `r#async`, now only a no-pool fallback — `beam_abi/src/driver/host.rs:498`), so `driver_async_port_key` answers the C's `0` (`beam_abi/src/driver/drv/lifecycle.rs:540-548`), never a key.
- **Driver-interned atoms land at the port boundary** — a predicted index, `dropped` if the table moved past it, never interned at a foreign index; the deep clone is gated on `has_pending_driver_atoms` (`tests.rs::an_idle_port_round_does_not_clone_the_shared_atom_table`).
- **The monitor family is live end to end** — `DriverMonitors` seized as `PortMeta.driver_monitors`; `monitor_process_result` ⇒ `-1` (no `process_exit` slot, or a non-local pid), `0` (observed-alive, **or no observation**), `1` (observed-dead); `drain_driver_monitor_exits` **defers** with `Ok(0)` on a live borrow, run just before `deliver_port_messages`.
- **Line framing is adopted** — `line`/`{line,N}` (bare = `LINE_DEFAULT_MAX_LEN` 512) through `set_line_mode`; `StreamType::port_flags` ORs `PORT_FLAG_BINARY` (1) and `PORT_FLAG_LINE` (2) independently; exclusivity is checked after the whole list parses (`line` + `{packet,N}`, `stderr_to_stdout` without `use_stdio` ⇒ `badarg`).
- **`get_port_flags` answers from inside `start` where the oracle answers `0`** (`erl_bif_port.c:1139-1143` sets the bits only after `open_driver` returns); no corpus case calls it there.
- **Two registrations per direction from one driver** ⇒ typed `unsupported` (`armed_event`), never a wrong descriptor.
- **A `dlopen`ed driver's split read survives** — `DriverHost::output2` records `(header, Option<body>)` (`None` = the C's `buf == NULL`) and `collect_outputs` hands each call over as **one** read, so `driver_output2`/`driver_output_binary`/`driver_outputv` are oracle-identical (`driver_output_shape_tests.rs`, the `eventsplit` fixture).
- **A zero-byte read produces no message in RAW mode** — `beam_io` does mint the read (`beam_io/src/port.rs:738-758`), but `fold_notifications` drops an empty `ReadMessage` (`port.rs:2418-2420`), so `driver_output(NULL,0)` and `driver_output2(NULL,0,NULL,0)` are silent where the oracle answers `{Port,{data,[]}}` (measured on both; a `binary` port's answer is the **proper** empty list, not `<<>>`). In **line** mode both runtimes are silent (the C's `read_linebuf` yields nothing for a zero-byte call). Shapes pinned at the builder (`stream_shape_tests.rs`).
- **`locking` is `driver_level` for every `{spawn_driver,Name}` port** (the C decides on `ERL_DRV_FLAG_USE_PORT_LOCKING`, `erl_bif_info.c:3875-3894`, a bit `DriverFlags` does not carry); OS-child ports answer `port_level`, the oracle's own.
- **`driver_failure_atom/2` crosses the seam as UTF-8 where the C interns Latin-1 bytes** — `-1` for a non-UTF-8 name, one atom for a multi-byte name where the C interns the bytes; only the ASCII rows are oracle-identical.
- **The data-then-failure row is pinned by `failure_e2e_tests.rs`** — the failing callback's read arrives **before** the exit signal (`fail_port`'s `failed_read_recipients`, consumed once, dropped at `Closed`, cleared on `register`; the e2e row observes the read in the message buffer a pump drains and takes it *before* the exit signals the same failure published, because the round that reaped the port also consumed the bytes), a non-trapping owner dies of a non-`normal` reason and survives `normal`, and `driver_exit` never signals a linked owner.
- **A completion's recipient is `PortMeta::owner`, not the C's `desc->caller`** (the seam exposes no `driver_caller`, `completion.rs:67-73`); identical for every `prim_inet` caller.
- **A post-`open_port/2` `{mode, list}` does not re-render a completion** — `PortMeta::stream` is fixed at open (`prim_inet:open/5` passes `[binary]`) and `{mode,…}` travels verbatim as a control op (`completion.rs:176-181`).
## Handoffs (owned by OTHER nodes)
- **`beam_abi` / `beam_io`** — a **safe reply-copy** helper for a `control` reply the driver answered from its own memory (the `unsafe` slice read inside `impl Driver for DriverPort`, `beam_io/src/abi/port.rs:823`); until it exists this node's `DriverPortAdapter::control_reply` answers the typed *unsupported* for a reply it cannot address inside its own buffers.
