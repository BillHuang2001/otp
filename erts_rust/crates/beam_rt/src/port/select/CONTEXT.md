# `beam_rt::port::select` — the runtime's ONE select mechanism (A.3 `enif_select` + A.7 `prim_tty:tty_select/2`)
## Intent
`select.rs` is the term-storing half of `beam_io`'s poller: `beam_io` owns the reactor, this node owns what an arm records, when a registration disarms, and the one resource reference keeping a NIF object alive between arming and readiness.
A NIF's `enif_select` interest (A.3) and `prim_tty:tty_select/2`'s tty interest (A.7) are **one** mechanism here, never two.
The node is `#![deny(unsafe_code)]`-clean and never fabricates a notification: an unservable step is a typed `BeamError`.
## API Surface
### The registration store
`SelectWatch` is the registration store: one `SelectRegistration` per descriptor (its poller `Token`, `fd`, the caller-intent `Interest`, the owner `ProcessId`, the payload, the handle term and the raw `obj`), keyed by poller key, with a `by_fd` map and a `(fd, handle_key)` index beside it for the `STOP`/`CANCEL` lookups.
### Arming, stopping, cancelling, taking readiness
`arm(poller, fd, interest, owner, payload, handle, obj)` records a **one-shot** interest; `stop` de-registers and answers the `Cancelled` directions it really had armed (the C's `ERL_NIF_SELECT_STOP`, which addresses a registration by its descriptor, so a handle naming nothing on an armed fd still stops it); `cancel` clears exactly the named directions and answers which of them were armed, de-registering the fd once none is left; `take_ready` reports the ready registrations and **disarms** them; `prune_dead(live)` drops every registration whose owner the predicate denies (the C's `tty_monitor_down` `STOP` arm).
### Payloads and events
`SelectPayload::{Plain { reference }, Custom { message }}` are the C's two notification shapes (the `{select, ResourceTerm, Ref, EventAtom}` tuple vs `ERL_NIF_SELECT_CUSTOM_MSG`'s own term) and `SelectEvent::{ReadyInput, ReadyOutput, ReadyError}` its three event atoms; `events_of` reports every **observed-and-requested** direction in the C's `input` → `output` → `error` order (`erl_check_io.c:2126-2175`) as one `SelectDelivery` per event, with a bare hang-up falling back to the requested direction.
### The poller-key reservation
The key reservation runs from `TTY_KEY_TOP = u64::MAX - 2` down to `TTY_KEY_FLOOR = 1 << 60`: **below** `watch.rs`'s signal-facility key (`u64::MAX - 1`) and `beam_io::WAKER_KEY` (`u64::MAX`) and **above** the port-number space, so a select event can never be mistaken for a port's readiness, and an exhausted reservation is a typed `unsupported`, never a wrapped key.
### One registration's worth of state per descriptor
`beam_io::Poller::register` refuses a duplicate descriptor, so a second `arm` on an already-registered fd goes through `Poller::reregister`, **widening** the interest mask and replacing the payload, owner, handle and object — one registration's worth of state, which is why the store is keyed by poller key with the `(fd, handle)` index beside it.
### `prim_tty:tty_select/2` — a special case, not a second mechanism
`prim_tty:tty_select/2` is a **special case**, not a second mechanism: `PortRegistry`'s tty arm (`port.rs`) is a thin wrapper over `arm_nif_select` supplying the C `tty_select_nif`'s own arguments (fd `0` = `TTY_IFD`, `Interest::READABLE`, the stabilised tty handle term, and a null object), so its report rides `PortEvent::Select` on **both** delivery routes — `Runtime::deliver_port_messages` (the scheduler/`run` route) and `RuntimeContext::poll_port_messages` (the `-eval` receive route, which returns the notification the evaluator itself armed and leaves other processes' to the scheduler route).
## Constraints
- Both stored terms are **stabilised** on the runtime's never-reset arena before the registration records them, because a registration outlives the call that armed it and a heap a collection may relocate is never stored.
- The raw `obj` a NIF select carries is only ever **moved**, never dereferenced (this crate is `#![deny(unsafe_code)]`); it is minted into a resource term at delivery by `port.rs::select_notification_handle` → `crate::nif::resource_term_for`, which refuses a null/foreign/dying pointer instead of fabricating a term, while a `tty_select/2` arming (null object) delivers its stored handle term as-is.
- The registration holds **one reference per armed interest** on that object (`SelectHold` over `beam_abi`'s `keep_resource`, the C's `enif_keep_resource` at `erl_check_io.c:1446`), taken at `arm` — before the poller commits, so a refusal registers nothing and a poller failure releases it — and given back **exactly once** at disarm: `stop`, `cancel`, `prune_dead` and the store's own teardown all release it through the registration, and the hold travels with the first delivery only.
- A non-null object this runtime cannot keep alive (not one of its own, or already dying) is refused at arm time, so no interest is armed for an object no notification could name.
- On the delivery path only, the hold is released **after** the notification's term has been minted — `port.rs`'s scheduler arm and the `-eval` arm both drop it there — because the mint takes a reference of its own and releasing first would leave a window in which the object dies between the disarm and the mint.
## Test Strategy
- Releasing only after the mint is what makes an object a NIF has already released still deliver its readiness; the end-to-end pins are `../../tests/nif_select.rs`'s `enif_select_interest_reference_keeps_a_released_object_alive_until_readiness` (the released object delivers), `enif_select_stop_releases_the_interests_reference_exactly_once` and `enif_select_interest_of_a_dead_owner_is_pruned_and_released` (the reference is given back once, at a stop and at a dead owner's prune), with `select/tests.rs` pinning the same half at the unit level.
- `select/tests.rs` (15 cases) pins the store with no poller callback: the key reservation, the once-only readiness report, a foreign key ignored, the widening re-arm, `stop`/`cancel`, the dead-owner prune, the C event order with the bare-hang-up fallback, and the hold's no-object/refused-object/refused-re-registration/first-delivery edges.
