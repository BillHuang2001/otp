# `beam_rt::port` — the runtime's A.4 port layer (`../port.rs` provider + `driver.rs` host + `watch.rs` signal half)

## Intent
The runtime side of contract A.4, in three files.
`../port.rs` is the **port provider**: `open_port/2`'s `Name`/`Options` decoding, the poller/registry (`PortRegistry`), the port-task round and the `{Port,{data,..}}`/`{Port,{exit_status,..}}` message pump behind `beam_io`.
`driver.rs` is the runtime's **own** driver C-ABI host for `{spawn_driver, Name}` ports (contract A.4), written directly over `beam_abi`'s frozen `DriverHost` seam.
`watch.rs` is the **delivery half** of `os:set_signal/2`: the process's one `beam_io::signal::SignalFacility`, its registration with the runtime's one poller, and the drain that turns a handled signal into the `{notify, Signal}` the port pumps deliver.
It is deliberately **separate** from the sibling crate `beam_io`'s own host layer (`beam_io::abi`): `beam_rt` never references `beam_io::abi`, `make_loaded`, `AbiHost` or `DriverTable` (verified: no matches anywhere in the crate), so end-to-end `.so`-driver traffic goes through this file, not `beam_io`'s.
The native `port_command`/`port_info` floor lives in `../native/port.rs`.

## API Surface
### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS` (incl. `registered_name`), `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver,SpawnDriverBuiltin}`, `StreamType{List,Binary}` (list default), `IoCounters` (the node-global counters behind `erlang:statistics(io)`; the runtime keeps a clone of the same `Rc` so the arm reads them without borrowing the registry), and `RuntimePorts` (the `beam_bifs::PortHook` impl: `open_port/2`, `port_close/1`, `port_info/1,2`) built from `Rc<RefCell<PortRegistry>>` + the shared `Rc<AtomTable>` + the owning `ProcessId` (the `Rc<RefCell<..>>` is the ETS pattern — `FunBridge` needs `&mut Runtime` at the same time; a nested borrow is a typed gap, never a panic).
`PortRegistry` (private `{poller, registry, meta, builtin_drivers, heap, io_counters, watch, liveness}`): `new()` (anchors the `driver_*` codegen unit and builds the **one** `beam_io::DriverRegistry::with_builtins` `fd`/`efile`/`tcp_inet` table), the registry queries/commands (`is_live`/`contains`, `write_command`, **`is_busy`/`soft_busy`**, `port_control`, `len`, `is_empty`/`has_nothing_to_poll`, `has_pending_driver_atoms`, `io_counters`, `ids`, `close`, `driver_lookup`, `create_builtin_driver`, `liveness`, `refresh_liveness`), and the private pass (`register`/`pump(timeout) -> Vec<PortEvent>`/`take_due_exit_statuses`/`take_driver_outputs`/`take_driver_terms`/`take_signals`/`info`); consumers are `Runtime::deliver_port_messages` + the `-eval` trio `poll_port_messages`/`port_data_message`/`port_exit_message`.
`ProcessLiveness` (crate-internal): the runtime's most recent **process-liveness observation**, shared with every `{spawn_driver, Name}` port's `DriverPort` host — the state behind `driver_monitor_process`'s positive `ERL_DRV_MONITOR_NOT_ALIVE` (the C's `1`). `new()` starts in the **no-observation** state (`RefCell<Option<HashSet<ProcessId>>>` = `None`); `observe(pids)` replaces the view with the runtime's latest observation; `clear()` drops it back to no-observation (a runtime with no C-driver port keeps none); `is_alive(pid) -> Option<bool>` is `try_borrow`-based — it is called *from* a driver callback, which may hold unrelated runtime state borrowed — and answers `None` ("no observation available") rather than panicking. `PortRegistry::liveness()` clones the shared `Rc` (taken while the host is built in `RuntimePorts::open_port`); `PortRegistry::refresh_liveness(&ProcessTable)` republishes the snapshot from `table.pids()`, **gated on a live `{spawn_driver, Name}` port** (any `meta.driver_monitors.is_some()`), and otherwise clears it, so a runtime that never opened such a port pays nothing. It is called at the **start of every port round** — the one place driver callbacks normally run — from `Runtime::deliver_port_messages` (the scheduler path) and `RuntimeContext::poll_port_messages` (the `-eval` path). The view is therefore a **snapshot refreshed once per round**, not a live query: a callback reached **outside** a round (the driver's own `start` during `open_port/2`, or a `control` callback during `port_control/3`) consults the previous round's snapshot, and one reached **before any round** sees `None` — which `monitor_process_result` answers by installing the monitor anyway (`MonitorResult::Ok`), never a fabricated `NotAlive` (an unobserved process must not be reported dead, since a silently dropped driver watch is the one failure a driver cannot detect).
**Built-in driver resolution (the `{spawn_driver, Name}` fallback).** `RuntimePorts::open_port`'s `PortName::SpawnDriver` arm resolves the name against `create_builtin_driver` **before** any `dlopen`, exactly as the C resolves it against the loaded-driver list (`io.c:599-628`), so `open_port({spawn_driver,"tcp_inet"},[])` opens a real live port (the oracle answers `#Port<…>`) rather than failing to load a `.so` that does not exist. A **hit** registers the built-in `Box<dyn Driver>` through the same `PortRegistry::register`/`PortMeta` path with `kind = PortName::SpawnDriverBuiltin`; a **miss** keeps the `dlopen` path byte-identical (the existing `.so` driver tests are unchanged), and an unknown name is still `badarg` — a built-in whose factory fails surfaces that typed failure, never a fabricated port.
The two `PortName` predicates route the byte paths (`PortName::has_driver_control`/`bytes_from_driver_output`, both exhaustive `match`es so a new variant is a compile error): a built-in driver port is a **driver port** for `is_driver_port`/`port_control` (its driver has a `control` callback) but its bytes are **not** drained by `take_driver_outputs` — they arrive through its poller-registered descriptor on the port-task round, like every non-`.so` port, and `write_command` takes the ordinary `port_command` path for it.
`PortRegistry::port_control(id, op, arg)` (`../port.rs:862`) and `RuntimePorts::port_control(port, op, arg)` (`../port.rs:1616`) forward the verb **verbatim** to `beam_io::PortRegistry::port_control` (`beam_io/src/registry.rs:357`, which reserves the `"close"` verb), so for a `{spawn_driver, Name}` port the operation reaches `DriverPortAdapter::control` and a C driver's verb is the decimal `c_uint` string `erts_internal:port_control/3` produces from its integer `Command`. The **reachable** entry is `PortRegistry::port_control`: the native floor's `erlang:port_control/3` (`../native/port.rs`) calls it directly, so `RuntimePorts::port_control` is retained but has **no caller** (a `runtime.rs`-internal seam; `beam_bifs::PortHook` exposes no `port_control` method and needs none).
Two "is it empty" predicates: `is_empty()` counts **ports only** (`system_info(port_count)`), while `has_nothing_to_poll()` is the **nothing-pending** predicate — no live port, no armed `tty_select/2` interest **and** no **fired, undrained** `os:set_signal/2` self-pipe (`watch::SignalWatch::has_pending_signal`) — i.e. the honest "a blocked process can no longer be woken, and a poll round would be pure sleep" test. An **armed but idle** `handle` disposition is deliberately **not** pending work (its descriptor can only become readable when a signal actually arrives), so a runtime that only handles a signal and never opened a port is quiescent and pays no sleep; a signal that *has* been caught makes the pipe readable and **is** pending work.
`pump` first `watch.sync`s the signal self-pipe into the poller, harvests the already-queued driver output/terms and any handled signal, then — **only** when there is a real wake source (a live port or an armed `tty_select/2` interest; an armed-but-idle signal self-pipe is *not* one) — polls in `PORT_POLL_SLICE` (25 ms) slices clamped by the earliest driver deadline, runs the port tasks, harvests each driver's `driver_output`, and reports `PortEvent::{Data,Line,Exited,Term,Signal}`; the sentinel `watch::SIGNAL_KEY` readiness event is filtered out before the port consumers see it (no port ever sees the signal pipe). The early return is taken **after** the unconditional `take_signals` harvest, so a caught signal is returned at once instead of polling a now-drained pipe. Immediately after every port-task round and **before** the round's early-return test, `pump` takes the due `exit_status`s and then drains the **line channel** — `flush_line_stream_ends` (which runs `PortRegistry::take_eof` for every `line`/`{line,N}` port, whose side effect is `Port::flush_linebuf`, the C's `driver_eof` → `flush_linebuf_messages`) and then `PortRegistry::take_line_notifications`, one `PortEvent::Line` per staged frame, so a reaped child's `{exit_status,S}` precedes the flush of its own trailing partial line (the oracle's order). The drain is unconditional because `take_line_notifications` **empties** every port's staged frames: a round that returned before draining would lose them.
`SpawnDriver` is the **single** OS-child implementation (this crate owns only `open_port/2`'s decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`). `deliver_port_messages` delivers each event into the **owning** process's mailbox: `{Port,{data,..}}`/`{Port,{exit_status,..}}` to `owner`, a driver-emitted term (stabilized onto the pointer-stable arena) to `to.unwrap_or(owner)`, and `{notify, Name}` (sender `system`) to the pid `whereis` resolves for the interned `erl_signal_server` atom — each through `deliver_simple`, so a blocked receiver is woken; `close` calls `beam_io`'s `notify_port_exit(…, Closed)` **before** `registry.close(...)`.

The **read path and the child streams**: one `{Port,{data,Data}}` is built per driver read (`RuntimeContext::port_data_message` in `../port.rs`): a `binary` stream delivers a `binary` **at whatever width the child wrote** — up to `beam_io`'s `READ_CHUNK` (64 KiB) per `read(2)` — built by `beam_codec::term::make_binary` on the pointer-stable `eval_heap` (the on-heap `ErlHeapBits` layout at every width, so `terms::make_heap_binary`'s 64-byte limit never applies), and a `list` stream a char list. Both builders share one payload helper (`RuntimeContext::port_data_payload`), so the framed shape below can never drift from the unframed one.
A port opened with **`line`/`{line,N}`** delivers the **framed** shape instead — `{Port,{data,{eol,Data}}}` for a newline-terminated frame, `{Port,{data,{noeol,Data}}}` for a length-limited chunk or the trailing partial line released at end-of-stream. It is `RuntimeContext::port_line_message` (the C's `deliver_linebuf_message`, `io.c:3454`, wrapper at `io.c:3430-3435`) over the `PortEvent::Line` arm, whose `Data` is shaped by `stream` exactly as the unframed builder shapes it. Unlike the unframed arm an **empty payload is a real frame**: a blank line is the oracle's `{Port,{data,{eol,[]}}}`. The port's own `input` counter and the node-global `IoCounters` are bumped per frame, exactly as the unframed arm does per read. The child's **stderr is inherited** from the emulator by default — it is never port data — and the `stderr_to_stdout` option (`PortOptions::stderr_to_stdout`, `PortOptions::overlay`, `PortOptions::stream_options()` → `beam_io::StreamOptions` → `SpawnDriver::with_stream_options`) makes the child's descriptor 2 an exact duplicate of descriptor 1, so its diagnostics arrive as port data interleaved with stdout in true write order (the C's `stderrfd = opts->redir_stderr ? ifd[1] : dup(2)`, `erts/emulator/sys/unix/sys_drivers.c:500`).

### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a loaded driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops). `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_`: the handle **is** the per-port `DriverEnv`'s address (a driver-private term arena, the shared `AtomTable` + a `PendingInterner`, the owning `ProcessId`, and the output/pid services). `load_driver(candidates, name)` delegates to the **dedicated driver loader `beam_abi::driver::loader::load`** (a real `ErlDrvEntry` loader, distinct from the NIF loader and needing no host), tries each candidate (the loader appends `.so`) and reports the **last** typed error.
`DriverPort::binary_to_term` (the `DriverHost` hook `erl_drv_binary_to_term` reaches) decodes the driver's bytes with `beam_codec::decode_term`: the decoder needs `&mut AtomTable`, so it decodes into a **per-thread memoized image** of the shared table (`crate::nif::with_decode_scratch` — revalidated index-by-index, so no O(table) clone per call) and a name it appended is recorded on the pending interner at its predicted index (via `intern`, never `intern_atom` — the interner's `base` was fixed when the host was built) for the port's atom-commit step; an invalid image is the C's `ERTS_DDT_FAIL` (`None`), never a raise.
The `DriverHost` registry hooks carry the C's exact codes: `add_driver_entry`/`remove_driver_entry` (`add` returns `0`; `remove` `1`/`0`/`-1` per `io.c:7698`), `lock_driver` keyed off the port's load state (`io.c:7324`) and `create_port` = the invalid-port sentinel.
`DriverPort` also owns the per-port **driver-private state** the frozen seam has no term/home for, in `driver/state.rs`: the driver's private byte queue — the C's `prt->ioq` (`io.c:6790-6919`), an ordered list of enqueue **chunks**, one per successful `driver_enq`/`driver_pushq` — behind `enq`/`pushq`/`deq`/`sizeq`/`peekq`, plus the `pdl_created` one-PDL guard behind `pdl_create`. This queue is distinct from both the Erlang→driver output queue `beam_io` owns (`prt->queue`) and the port's *input* queue (what `driver_output` answers with). `DriverPort::with_port_flags` carries the port's **state** stream bits (`StreamType::port_flags` → `PORT_FLAG_BINARY` (1) for a `binary` port, else `0`), which `get_port_flags` reports — a **different** cell from the `control_flags` `set_control_flags` records for the `port_control` reply form (`io.c:5325-5344` vs `:5318`); `clear_driver_state` (called from `DriverPortAdapter::stop` **and** its `Drop`) drops the queue so a late drain never reads bytes of a port that has gone away.
`DriverPortAdapter` is the **port lifecycle** the host alone lacks — a `beam_io::Driver` over a loaded C driver: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, kept in a `Box` that never moves), `output` hands the port's queued bytes to the entry's `outputv` when it declares one (**the C's preference**, `io.c:1782`/`io.c:1597`) and to `output` otherwise — so an **`outputv`-only** entry (an entry whose `output` slot is `NULL`) really receives `port_command` (`ErlIOVec` = an empty writable header `iov[0]` + the data `iov[1]`, parallel all-NULL `binv`, built on the caller's stack exactly as `io.c:1806/1842-1864`), queues the `driver_output` reply as the port's **input** (surfaced by `take_driver_outputs` as `{Port,{data,Data}}`), `stop` runs the entry's `stop`, and the drop runs `finish` + `dlclose`. It also seizes the host's `Rc<DriverMonitors>` at `load` and overrides `has_pending_async`/`drive_async`: that per-round drive point fires the entry's `process_exit` once for each marked monitor (`driver/monitor.rs`), and the tree is cleared in `stop` **and** at the top of `Drop`, so no callback can run after the library unloads. An `OUTPUT` port task (`Port::run_task` → `DriverPortAdapter::ready_output`) **always** drains the port's output queue through the single write path (`DriverPortAdapter::output` → the entry's `outputv`/`output`, the C's `port_command` delivery, `io.c:1782`/`io.c:1597`) and *then* runs the entry's `ready_output` slot, when the entry declares one, as the write-**readiness** notification (the C's `ERTS_PORT_TASK_OUTPUT` arm, `erl_port_task.c:1793-1797`) — never as a second write path; the write-armed descriptor handed to that notification is captured **before** the write, because `output`/`outputv` are free to re-arm with `driver_select`. `build.rs`'s `-Wl,--export-dynamic` publishes the `driver_*`/`erl_drv_*` symbols; `open_port({spawn_driver, Name}, Options)` routes here for a name no built-in driver answers, and an unknown or empty driver name is `badarg` (a name a built-in does answer is registered as a `SpawnDriverBuiltin` port instead, never `dlopen`ed — see the API Surface above).

### Driver-emitted terms (`erl_drv_output_term` / `erl_drv_send_term`) — `TermQueue`
`beam_abi` decodes the driver's term-data stack machine into a real term on the host's arena and calls `DriverHost::send_term(port, to: Option<Eterm>, term)`. The C *delivers* there and then (`driver_deliver_term`, `io.c:5664`: the decoded term itself, `from = prt->common.id`); the frozen seam gives the host no route to a receiver's mailbox, so the term is **queued**: `TermQueue` (`pub struct`, `Rc<RefCell<Vec<(Option<Eterm>, Eterm)>>>`) is per port and shared by handle — `DriverPort::term_queue()` returns the handle, `send_term` pushes onto it (while still recording the accumulate-only `DriverPort::sent` view the A.4 test reads), `take()` drains, `is_empty()` reports. `None` = the port's connected process (`erl_drv_output_term`, `io.c:6254`), `Some(pid)` = an explicit destination (`erl_drv_send_term`, `io.c:6289`). **Lifetime invariant:** a queued term's words live on the host arena, so `DriverPortAdapter` **empties** the queue both in `beam_io::Driver::stop` (the C refuses a delivery while `ERTS_PORT_SFLG_CLOSING`, `deliver_term_check_port`, `io.c:6213`) and in its `Drop`; a late drain observes an empty queue, never a freed arena.
**The drain is wired end to end**: `PortRegistry` seizes the handle as `meta.driver_terms` at `open_port/2`, `take_driver_terms` surfaces each queued term as `PortEvent::Term{port, to, term, owner}`, and the pump copies it onto the pointer-stable arena (`RuntimeContext::stabilize_driver_term`) and delivers it to the destination — the connected process for `None`, the explicit pid for `Some`. `tests/driver.rs` pins both paths against the oracle with `EVENT_DRIVER_MODE` 2/3 (`erl_drv_output_term` / `erl_drv_send_term`).

### `port/watch.rs` — the `os:set_signal/2` delivery half (`pub(crate)`)
One `thread_local!` `FACILITY: RefCell<FacilitySlot>`, holding the facility created lazily by the first `os:set_signal/2` and **never dropped in production** (a per-call facility would be dropped at the end of the call and `SignalFacility::drop` restores the prior dispositions), so a later call observes the disposition an earlier one installed. `HANDLED: RefCell<BTreeSet<Signal>>` mirrors which signals currently hold `Disposition::Handle` (a later `ignore`/`default` removes the entry), so `SignalWatch::is_pollable` answers without a syscall. Accessors `with_facility` (creates on first use) / `with_existing_facility` (never creates). `install(signal, disposition)` sets the disposition and updates the mirror; a failed install leaves the mirror untouched.
`SignalWatch { token: Option<Token>, fd: Option<RawFd> }` is the poller registration, owned by `PortRegistry`. `sync(poller)` registers the facility's `read_fd()` under the sentinel key `SIGNAL_KEY` (= `u64::MAX - 1`, distinct from the poller's own `WAKER_KEY`) on the first poll round after a `handle` disposition — idempotent, and a no-op when nothing is handled; it fires from `pump`, so it happens exactly on the rounds that actually have a wake source to wait on. `is_pollable()` (registered **or** a `handle` disposition exists) is the **poll-set** half of the watch — it says `sync` has a descriptor to register, *not* that there is work to wait for; a `handle` disposition the OS accepted but whose registration fails is surfaced, never silently leaving signals undelivered. `has_pending_signal()` is the **pending-work** half: a non-destructive readiness probe of the self-pipe — a throwaway `Poller` registered on the facility's `read_fd()` and polled with a zero timeout, so it neither blocks nor consumes — answering `true` iff a signal was caught and no `drain` has consumed it yet (`false` with no facility, or when the probe cannot be built: the honest "no evidence of a caught signal"). The pipe byte is the *whether* (written by `beam_io`'s lock-free async-signal-safe trampoline), the facility's private bitmask the *what*, and `drain()` clears both. `is_registered()`/`ready(events)`/`drain() -> Vec<&'static str>` (the `Signal::name()` atoms) round it out. `crate::context::signal` owns the oracle answer surface (`{ok, OldDisposition}`/`badarg`, the kernel-only `sigstop` rule) and delegates the facility here (Rust privacy: `context::mod` declares `signal` privately, so `port` cannot name `context::signal`, but `context::signal` can name `pub mod port`'s child).
The message itself is `RuntimeContext::signal_notify_message(name)` → `(from, {notify, Name})` with `subject` interned as `system`; the caller resolves the recipient, so the same builder serves any delivery path.

### `erlang:port_command/2,3` and the port **busy state** (A.4)
A driver marks its port busy with `set_busy_port` (`io.c:5208-5264`); `erlang:port_command/2,3`'s answer then depends on that bit and on whether the loaded **driver entry** advertises `ERL_DRV_FLAG_SOFT_BUSY`.
`BusyFlag` (`driver.rs`) is the one shared handle for both halves: `busy` (`Rc<Cell<bool>>`, written by `DriverHost::set_busy_port` from inside a driver callback) and `soft_busy` (`Rc<Cell<bool>>`, stamped by `DriverPortAdapter::load` from `library.entry().driver_flags & ERL_DRV_FLAG_SOFT_BUSY` once the `dlopen` has happened — the load site is the one place the host and the loaded entry first coexist). Accessors `new`/`is_busy`/`set_busy`/`soft_busy`/`set_soft_busy`; builder `DriverPort::with_soft_busy`; handle `DriverPort::busy_flag`, taken **before** the host is boxed into the port lifecycle (the boxed driver exposes no host), exactly like `control_flags`.
`PortMeta.driver_busy` (`../port.rs`) seizes that handle at registration from `host.busy_flag()` — `Some` only for a `{spawn_driver, Name}` C-driver port; `None` for a `spawn`/`fd` port and for a **built-in** driver port (whose entry flags the built-in registry does not expose), which is the C's "never busy, no `SOFT_BUSY`" case. `PortRegistry::is_busy(id)` / `soft_busy(id)` read it back (`false` for an unknown port and for a port with no handle).
`../native/port.rs`'s `port_command` reads both (under one borrow, after the liveness check) and picks the arm the C picks (`erts_port_output`, `io.c:1749-1764`; `erl_bif_port.c:192-220`):

| port | options | answer |
|---|---|---|
| idle | `[]` / none / `[nosuspend]` | the atom `true` |
| idle | `[force]` | the atom `true` iff the **driver entry** advertises `ERL_DRV_FLAG_SOFT_BUSY`, else `error:notsup` |
| busy | `[nosuspend]` (no `force`) | the atom `false` — the command is dropped, nothing written |
| busy | `[force]` | the atom `true` iff the entry advertises `ERL_DRV_FLAG_SOFT_BUSY`, else `error:notsup` |
| busy | neither | the typed capability gap (see Known Issues) |
The `force` rule is a property of the driver **entry**, **not** of the current busy state: `erl_bif_port.c:195-198` rejects `[force]` with `notsup` whenever the entry lacks the flag, **idle or busy alike** (oracle-measured on erts-17.1). A `spawn`/`fd` port — and a built-in driver port — therefore always answers `notsup` for `[force]`, the oracle's own answer for `{spawn, Cmd}`/`{fd, N}`. The busy check precedes the iodata conversion (`io.c:1760-1764`), so a busy port's `[nosuspend]` answers `false` even for non-iodata. A malformed/unknown option is `badarg`, and the option list is validated **before** the port is even looked up; the port-liveness check precedes the `force`/busy decisions, so a dead port with `[force]` is `badarg`, not `notsup`.

## Constraints
- Crate is `#![deny(unsafe_code)]`: the registry slots operate over a **thread-local** entry list
  `DRIVER_ENTRIES` (`805`), not a process-global `DriverTable`. The runtime drives every port on one thread.
- Every driver callback runs under `publishing` → `beam_abi::with_current_host` (`878`), used at
  `start` (`1838`), `ready_*` (`1664`/`1693`), `output` (`1890`), `timeout` (`2116`) and `stop` (`2156`) — this is
  what lets the two port-less registry slots reach a host during a callback.
- The `SignalFacility` is a `thread_local` (not a `Runtime` field) for the same reason `context::trace`'s slot is: the runtime is single-threaded (`!Send`), so the slot *is* the process's one facility. A **second** live facility would re-point `beam_io`'s trampoline write end at its own pipe; the one `FacilitySlot` the slot holds — created lazily by the first `os:set_signal/2` and **never dropped** (production never drops the runtime's facility, and a test build `mem::forget`s it in `Drop` so a libtest thread teardown cannot restore the process-global dispositions under a live signal test) — is what prevents that.
- Never a fabricated success: failures are typed `BeamError`s, and a state/lifecycle it cannot serve
  returns the C's own failure code.
- The `Rc<RefCell<..>>` handles are the ETS pattern so a port operation never needs a runtime borrow a
  `fun` argument already holds — a nested borrow is a typed gap, never a panic.

## Known Issues (this is a floor, not the full C `io.c`)
- **`erlang:port_control/3` is live end to end**: the native floor (`../native/port.rs`'s `port_control`,
  dispatched from `../native.rs`'s `try_native` — it is *not* a `PortHook` method and *not* in `../error.rs`'s
  `KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) validates `Port`/`Operation`/`Data` (`term_to_Uint` + `erts_iolist_to_buf`,
  `erl_bif_port.c:322-360`) and forwards the verb to `PortRegistry::port_control`, which reaches the driver as
  the decimal `c_uint` string via `DriverPortAdapter::control`. The callback reproduces the C's codes exactly —
  an **absent** `control` slot and a **negative** `cres` are both `badarg` (`io.c:4035`/`4074`) — and the reply
  bytes come from the buffer the driver was handed. An **internal** port
  (`{spawn,_}`/`{spawn_executable,_}`/`{fd,_}`) is `badarg` for **every** verb, the C's own
  `if (!prt->drv_ptr->control) return ERTS_PORT_OP_BADARG;` (`io.c:4035`); a `{spawn_driver, Name}`
  port — a loaded `.so` **or** a built-in driver such as `tcp_inet` — has a `control` callback, so the
  verb reaches the driver.
  **Reply encoding** (`write_port_control_result`, `io.c:4098-4175`): the bytes render as a **list of byte
  integers** at every length — there is no size threshold — and as a **binary** only when the driver set
  `PORT_CONTROL_FLAG_BINARY` through `set_port_control_flags`, a per-port flag that **persists** across calls;
  a `NULL` reply pointer is the C's `NIL` (the bare `[]`). The one residual gap is a reply the driver answers
  from **its own** memory (a pointer addressing neither the reply buffer nor the request buffer), which is the
  typed *unsupported* — reading it needs the raw access `beam_rt`'s `#![deny(unsafe_code)]` forbids — never a
  fabricated or truncated reply; closing it needs a safe copy helper on `beam_abi`'s `DriverLibrary` (see
  Handoffs).
- **The one `erlang:port_command/2,3` divergence: a plain command on a busy port.** The C **suspends** the
  caller (`erts_suspend` + `ERTS_BIF_YIELD3`, `erl_bif_port.c:211-220`) until the port goes idle and then
  re-runs the BIF, so the oracle eventually answers `true`. This runtime's BIF seam
  (`ExecutionContext::call_bif`) returns only `Result<Eterm>` — a value or an error, with **no block
  channel** — and the engine's only suspend is the receive family's `Step::Wait`, so there is no truthful
  suspend to take, and answering the eventual `true` would be a fabricated (wrong) result. That arm
  therefore raises the typed capability gap (`../error.rs::unsupported`, exit 3, reason naming the busy
  state). Every **other** arm — `true`, `false`, and both `notsup`s — matches the oracle; the four-way
  behaviour table is in the API Surface above, and the arms are pinned by `../native/port.rs`'s colocated
  `port_command_*` tests.
- **A NULL driver reply with `PORT_CONTROL_FLAG_BINARY` set answers `<<>>` where the C answers `[]`**:
  `write_port_control_result` (`io.c:4126`) returns `NIL` for a NULL reply pointer **before** it looks at
  the flag, so the oracle answers the bare `[]`; here `DriverPortAdapter::control` collapses "the driver
  left `*rbuf` NULL" and "the driver answered zero bytes" into one empty `Vec`, which
  `PortRegistry::control_binary` then renders as `<<>>`. Closing it needs the "pointer was NULL" bit
  threaded from `DriverPortAdapter::control` to `PortRegistry::port_control` (a shared
  `Rc<Cell<bool>>` beside `driver_control_flags`, `../port.rs`), because the `beam_io::Driver::control ->
  Result<Vec<u8>>` seam carries no such bit.
- **`driver_async` schedules nothing**: `DriverHost::r#async` keeps the frozen default `-1`, because `Runtime` is `!Send` (owning `Rc`/`RefCell` tables, a `dlopen`ed library registry and pointer-stable term arenas), so no worker thread can call back into it, and the C's in-band path when the pool is empty (`erl_async.c:604-613`: `(*invoke)(data)`, then `async_ready` → the entry's `ready_async`, then `free(data)` unless a `ready_async` slot exists) needs the entry's `ready_async`, which the *host* does not hold — `DriverPortAdapter`'s loaded library does. `beam_abi` supplies the host half: `AsyncJob`/`AsyncCallback` (`src/driver/async_job.rs`) make `invoke`/`finish` safe over the operands `driver_async` hands the hook, with `AsyncJob::new` that crate's one `unsafe` constructor; `DriverLibrary::ready_async(data, tdata)` is safely callable, and `beam_io::abi`'s `AbiHost` implements `r#async` over its own bounded pool — a host this crate never references. Returning a handle without running the job would be fabricated success, so the honest `-1` stands (the adoption's remaining needs are in Handoffs).
- A queued `TermQueue` entry carries no sending-port identity (the C stamps `from = prt->common.id`).
- `beam_io`'s `EfileDriver`/`FdDriver` are implemented and tested but do open/read/write only and are
  **never constructed by this runtime** (only `SpawnDriver` is); file I/O here is the `std::fs`/`std::env`
  native floor under `../native/prim*.rs`, not `beam_io`.
- **Driver-interned atoms land at the port boundary, not inline**: a name first interned *inside* a driver callback (`erl_drv_output_term`/`binary_to_term`/`intern_atom` — all sharing this path) gets a **predicted** index, because the live table is borrowed for the whole callback and this crate is `#![deny(unsafe_code)]`. `PortRegistry::commit_driver_atoms` — driven from `RuntimePorts::deliver_port_messages`, committing `code_server.atoms_mut()` — lands it at exactly that index; a prediction the table has moved past is **reported** (`dropped` and printed), never interned at a foreign index (which would make the driver's already-built term name a different atom). This is the one residual `Rc::make_mut` site: `RuntimePorts`/`DriverPort` hold an `Rc<AtomTable>`, so `atoms_mut` deep-clones the shared table **once in a port-task round where a driver really interned a new name** (a rare boundary, not per call); removing that last clone needs a `beam_io`/`PortRegistry` API change (a commit that does not keep the table pinned, since a `{spawn_driver,…}` port's `DriverPort` host holds its handle for the port's whole life). The round applies `DriverAtoms::is_empty`'s guard **before** the borrow — `PortRegistry::has_pending_driver_atoms`, consulted by `Runtime::deliver_port_messages` — because merely *reaching* `atoms_mut` with a live host handle clones the whole table (every name `String` plus the index map; `../tests/atom_table_commit_alloc.rs`'s clone control measures ~4 054 allocations / ~226 KiB at the booted table size) for a round that interns nothing. So an idle round never touches the table at all, pinned by `tests.rs::an_idle_port_round_does_not_clone_the_shared_atom_table`, which observes the clone as the code server's `Rc` moving to a fresh allocation.
- The exact success code of the four term-emitting calls differs: the C returns `1` for a well-formed spec, this runtime's `send_term` returns `0` (the **accept/refuse split** agrees and is pinned by the `driver_abi` corpus).
- `take_exit_status` is always `Ok(None)` — a driver port owns no child, so no `{Port,{exit_status,…}}`.
- **The monitor family is live** (`monitor_process`/`monitor_process_result`/`demonitor_process`/`get_monitored_process`): `DriverPort` keeps the per-port monitor tree (`driver/monitor.rs`'s `DriverMonitors`, keyed on the C's 24-byte reference identity, read/written only through the safe `beam_abi::monitor_identity`/`monitor_from_identity`), and `DriverPortAdapter` fires the entry's C `process_exit` for each marked monitor at its per-round drive point (`has_pending_async`/`drive_async` over `beam_io`'s existing probe, `beam_io/src/registry.rs:291-317`), the tree cleared in `stop` and at the top of `Drop` so no callback can run after the library unloads. `monitor_process_result` answers the C's `0`/`1`/`-1` from the published `ProcessLiveness` view over a five-way split (no `process_exit` slot ⇒ `-1`; a non-local pid ⇒ `-1`; an observed-alive local pid ⇒ `0` plus a freshly minted holder; an observed-dead local pid ⇒ `1` (`MonitorResult::NotAlive`), nothing installed; **no observation** ⇒ `0`, the non-regression fallback), and `beam_abi`'s wrapper prefers that hook over the two-way `monitor_process`, so the C's `1` is reachable end to end.
- **The monitor family is live end to end.** `PortMeta.driver_monitors` seizes the per-port `Rc<DriverMonitors>` at `open_port/2` beside `driver_terms`/`driver_atoms`/`driver_control_flags` (`../port.rs`, `Some` only for a `{spawn_driver,…}` C-driver port). The **marking** half: `PortRegistry::note_driver_monitor_exits(&ProcessTable)` iterates every live port's tree through `driver_monitors(id)`, asks `monitored_pids()` for the watched pids, and calls `note_process_exit(pid)` for each one `ProcessTable::contains` no longer holds (a cascade death and a monitor installed on an already-dead pid both count); `Runtime::drain_driver_monitor_exits(&mut self, &ProcessTable) -> Result<usize>` clones the `ports` `Rc` and takes it with `try_borrow`, **deferring** with `Ok(0)` on a live borrow (marking is idempotent and lives in the port metadata, so the next pass retries naturally). The scheduler pass runs it immediately before `deliver_port_messages`, so the same round's port-task probe fires the entry's C `process_exit` for each newly marked monitor.
- **The marking is a pass-boundary scan, never an exit observer.** `beam_process`'s `exit_observer` is a single slot already occupied by `EtsExitObserver`, so a second `set_process_exit_observer` would silently drop the ETS owner-death obligation; the pass-boundary scan holds the live `ProcessTable` instead (the `drain_ets_owner_exits`/`drain_port_monitor_exits` pattern).
- **`PORT_FLAG_LINE` (2) is reachable, and line framing is adopted end to end.** `open_port/2` decodes `line` and `{line, N}` in `port_options` (`../port.rs`) into `PortOptions::line: Option<usize>` (a bare `line` is the oracle's default `512`; `{line, N}` requires a positive small integer, so `0`/negative/non-integer are `badarg`), carries it as a **separate** `PortMeta::line` field (so `[binary, line]` sets both state bits), and `PortRegistry::register` arms it on the freshly-registered port through `beam_io`'s `PortRegistry::set_line_mode(id, Some(max_len))`. `StreamType::port_flags(line)` ORs `PORT_FLAG_BINARY` (1) and `PORT_FLAG_LINE` (2) independently, and `use_stdio`/`nouse_stdio` are decoded into `PortOptions::use_stdio: Option<bool>` (default `true`) for the mutual-exclusion check. So a `[line]` driver port answers `2`, `[binary]` `1`, `[binary, line]` `3` and no stream option `0` (oracle-verified through a C driver's `get_port_flags` from a `control` callback). The oracle's exclusivity rules are enforced after the whole list is parsed: `line` + `{packet, N}` ⇒ `badarg` (unless a later `stream` cancels the packet) and `stderr_to_stdout` without `use_stdio` ⇒ `badarg`.
  **The framing reaches the owner's mailbox.** `PortOptions::stream_options` asks the child driver for its **end-of-stream observation** (`StreamOptions::eof`) on exactly the line-mode ports, which is what lets `flush_line_stream_ends` release the trailing partial line; the `eof` *option*'s own `{Port,eof}` report stays unsynthesised (the returned bool is deliberately discarded). Oracle-measured frame sequences, all reproduced byte-identically: `printf 'a\nbb\n\nccc'` + `[line]` ⇒ `{eol,"a"}`, `{eol,"bb"}`, `{eol,[]}` (the blank line **is** a frame), `{noeol,"ccc"}` (the partial line released at EOF); the same on `[binary,line]` with binary payloads; `printf 'abcdefgh'` + `{line,3}` ⇒ three `noeol` chunks (`abc`/`def`/`gh`); `printf '\n'` ⇒ one `{eol,[]}`; `printf 'partial'` ⇒ one `{noeol,"partial"}`.
- **`get_port_flags` is answerable from inside `start` where the oracle answers `0`.** The oracle ORs `ERTS_PORT_SFLG_BINARY_IO`/`_LINEBUF_IO` into `port->state` only **after** `open_driver` returns (`erl_bif_port.c:1139-1143`), so a driver calling `get_port_flags` in its own `start` sees `0` for every stream option (oracle-verified for `[binary]`/`[line]`/none; visible only from a *later* callback, e.g. `control`). `DriverPort::with_port_flags` sets the bits at host construction (`../port.rs:1946`), **before** the adapter's `start` runs, so `beam_rt` answers the stream's real flags there. No corpus case calls `get_port_flags` from `start`, so the gate does not see it; making the bits take effect after `start` would be a behaviour change needing its own A.4 case.
- **`driver_async_port_key` stays unimplemented** (`async_port_key` keeps the trait default `-1`), and the ground truth is now read: the C body is `erts/emulator/beam/erl_async.c:518-525` and returns `(unsigned int)(UWord)internal_port_data(driver_mk_port(port))` — the port's internal data word, **truncated to 32 bits**, i.e. an address-derived opaque value whose only defined use is the async-pool bucket selector `*key % erts_async_max_threads` (`erl_async.c:585-593`, where `key` is an in/out `unsigned int*` the call overwrites with the chosen `qix`; `sys_drivers.c:320` seeds it from this call). Two independent reasons it is unpinnable: the seam has no handle to a port term's data word (and this crate is `#![deny(unsafe_code)]`), and the value is a raw pointer truncation that differs by address space — so it is not even oracle-comparable, only its `%`-bucket *use* is. `beam_rt` is single-threaded with no async pool, so there are no queues to key into. `driver_async/5` is likewise untouched (the `AsyncJob` runner and its remaining adoption needs are in the `driver_async` item above and in Handoffs).
- A driver that armed **more than one** registration per direction is a typed `unsupported`
  (`armed_event`, `1631`), never a wrong descriptor.
- `os:set_signal/2`'s notification is **dropped when no `erl_signal_server` is registered** — the C's own behaviour (`signal_notify_requested`, `sys.c:589-604` sends nothing when the process is absent), never an error. The `-eval` receive path (`poll_port_messages`) can only observe its own mailbox, so it drops a `PortEvent::Signal`; the scheduler path (`deliver_port_messages`) is the one that delivers it.

## Known divergence from the oracle: no child-exit auto-close
- ERTS **auto-closes** a `{spawn, Program}` port once its child exits: after the child is reaped, `erlang:port_info(P)` is `undefined`, `lists:member(P, erlang:ports())` is `false`, and — crucially — `erlang:port_close(P)` then raises `error:badarg` (measured on the erts-17.1 oracle).
- This runtime does **not** auto-close on child exit. `PortMeta.notify_exit` is only set by the `exit_status` option, so nothing reaps/removes the port until an explicit `port_close` (or registry drop): `PortRegistry::close` (`../port.rs`) kills+reaps, `meta.remove`s and releases the id, and `port_close` is `badarg` iff `!is_live` — the whole close is **synchronous**, so `port_close`→`port_info` cannot be order/timing-sensitive here.
- The corpus **sidesteps** the divergence rather than pinning it: the five `driver/port_*` close cases (incl. `port_command_after_close_is_badarg`) each open `{spawn,"cat"}`, a child alive until the explicit `port_close/1`, so the close is a synchronous success on both runtimes. (A `{spawn,"true"}` child would be auto-closed by the oracle first, so its own `port_close` would raise `badarg` and drift from the golden.) **No case pins the auto-close difference**, so the gate's 0-mismatch verdict is consistent with it — the divergence is real but unpinned.

## Handoffs (owned by OTHER nodes)
- **`beam_abi`** — `DriverHost::r#async` adoption needs a **safe** route from the hook's three raw operands to an `AsyncJob`: the runner exists (`AsyncJob`/`AsyncCallback`, `invoke`/`finish` safe, `DriverLibrary::ready_async(data, tdata)` safely callable), but `AsyncJob::new` — the constructor whose `# Safety` contract covers exactly those operands — is that crate's one `unsafe` entry point, while this crate is `#![deny(unsafe_code)]`.
- **`beam_abi` / `beam_io`** — a **safe reply-copy** helper for a `control` reply the driver answered from memory of its own, so the one remaining driver-`control` gap can close. The copy already exists as an `unsafe` slice read inside `impl Driver for DriverPort` (`beam_io/src/abi/port.rs:710-747`; after `control` returns `cres ≥ 0` and `rbuf` non-null, `core::slice::from_raw_parts(rbuf, n)` at `:745`), but `beam_rt` never names `beam_io::abi` and is `#![deny(unsafe_code)]`, and the frozen `beam_abi::DriverLibrary::control` (`driver/loader.rs:288`) reports only the `cres` and the re-pointed `*mut c_char` — dereferencing it is the caller's `unsafe`. The helper belongs on `beam_abi`'s `DriverLibrary` (e.g. a `control_reply` that returns the copied bytes) or on `beam_io`'s public wrapper, never as a re-derived `unsafe` block in `port/driver.rs`; until it exists `DriverPortAdapter::control_reply` answers the typed *unsupported*.
- **`beam_io` — closed, no seam needed.** Firing the driver's `process_exit` does not need a new `beam_io::Driver` method: `PortRegistry::execute_port_tasks` already probes `Driver::has_pending_async` and calls `Driver::drive_async` for every live port each round (`beam_io/src/registry.rs:291-317`, `beam_io/src/port.rs:548/562`), and `DriverPortAdapter` overrides both — `has_pending_async` reports the monitor tree, `drive_async` fires every pending monitor's `process_exit` and returns the count. `Port::notify_exit`/`Driver::port_exit` stay the *port's own* exit channel (once-only, `PortExitReason` carries no monitor), unrelated to a monitored process's death.
- **`beam_process` — no seam needed for the marking.** Its exit observer is a single slot already occupied by `beam_rt`'s `EtsExitObserver`, and an observer runs inside the finalizer while the dying heap is live, so it may **only record**; the driver-monitor marking is a scheduler-pass scan of the live `ProcessTable` instead (`Runtime::drain_driver_monitor_exits` → `PortRegistry::note_driver_monitor_exits`), needing no observer install and no `beam_process` change.

## Line-mode evidence (contract A.4)
`src/port/tests.rs` pins the whole `open_port/2` line surface against the LIVE oracle (system `erl`, OTP 29.1.1 / erts-17.1), reusing the `LineHarness`/`collect_line_frames` harness in that suite rather than duplicating it.
`the_open_port_line_option_matrix_matches_the_oracle` pins the strict whitelist plus the two order-independent mutual-exclusion rules: the six rejected shapes (`[line,{packet,2}]`, `[line,stderr_to_stdout,nouse_stdio]`, `{line,0}`, `{line,-1}`, `{line,foo}`, `{line,4,5}`) are `badarg`, the fifteen accepted ones decode, a bare `line` is `Some(512)`, `{line,N}` is `Some(N)`, the length is last-wins, and `[{line,7},line]` has `port_flags() == 2`.
`a_line_of_exactly_the_limit_is_a_single_frame` and `a_full_line_without_a_newline_flushes_as_noeol` pin the `{line,N}` split/`noeol` boundary: a line of exactly `N` bytes (with or without a trailing newline) is one frame; only a longer line splits.
`the_default_512_limit_splits_only_past_512_bytes` pins the bare-`line` default: 512 bytes then `\n` is `[{eol,512}]`, 513 bytes then `\n` is `[{noeol,512},{eol,1}]` (measured live).
`the_delivered_data_half_encodes_byte_for_byte_like_the_oracle` pins the delivered half's exact term bytes: the runtime's own encoder renders `term_to_binary(element(2, Msg))` for each `{data,{eol|noeol,Data}}` frame, and it must equal the oracle's `binary:encode_hex` image for both a `[binary,line]` and a `[line]` stream.
Sequence coverage from the same harness: `a_real_childs_lines_are_delivered_as_eol_and_noeol_frames` (`printf 'a\nbb\n\nccc'` ⇒ `{eol,"a"}`,`{eol,"bb"}`,`{eol,[]}`,`{noeol,"ccc"}`), `a_binary_line_stream_renders_each_frame_as_a_binary`, `a_line_length_limit_splits_the_stream_into_noeol_chunks` (`printf 'abcdefgh'` ⇒ three `noeol` chunks), `a_blank_line_is_an_empty_eol_frame`, `a_trailing_partial_line_is_flushed_as_a_noeol_frame_at_eof`, `a_carriage_return_before_the_newline_is_not_part_of_the_frame` and `a_rejected_line_option_list_opens_no_port` — plus `the_trailing_noeol_flush_is_delivered_after_the_exit_status`, which pins that one round's order (10 runs, oracle-cross-checked).
