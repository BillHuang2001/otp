# `beam_rt::port` — the runtime's A.4 port layer (`port.rs` provider · `driver.rs` host · `ops.rs` tables)
## Intent
The runtime side of contract A.4.
`port.rs` is the **port provider**: `open_port/2`'s `Name`/`Options` decoding, the `PortRegistry`, the port-task round, the `{Port,{data,..}}` pump behind `beam_io`.
Each child owns one post-`open_port/2` fact over the one `PortExtras` side table: `ops.rs` the table-entry operations, `exit.rs` the `'EXIT'`/`'DOWN'` a close owes, `failure.rs` the driver's own close request, `info_extras.rs` the derived `port_info/2` items.
Four are driver→owner channels: `completion.rs` (`{inet_reply,…}`/`{inet_async,…}`, what makes `prim_inet:send/4` return), `active_input.rs` (`{tcp,…}`/`{udp,…}`/`{tcp_passive,…}`), `peer_closed.rs` (`{tcp_closed,S}`), `inet_opts.rs` (the per-port `mode`/`active`/`exit_on_close` mirror, whose `{active,…}` half is kept in
step with the driver's own spend path by `PortRegistry::drain_active_spends`).
Those runtime halves and the closing-port signals are files of this node; the mechanics of every one of them are in [`driver/CONTEXT.md`](driver/CONTEXT.md), which owns the driver side that stages them.
`driver.rs` is this runtime's **own** driver C-ABI host for `{spawn_driver,Name}` ports over `beam_abi`'s frozen `DriverHost` seam (`driver/`); `watch.rs` delivers `os:set_signal/2` and `select.rs` the `prim_tty:tty_select/2` interest, the special case of its `enif_select` store (`select/`).
**Separate** from `beam_io`'s own host layer (`beam_io::abi`), so end-to-end `.so`-driver traffic goes through this tree.
## API Surface
### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS`, `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver,SpawnDriverBuiltin}`, `StreamType{List,Binary}` (list default), `IoCounters` (behind `erlang:statistics(io)`), `PortEvent`, `RuntimePorts` — the `beam_bifs::PortHook` impl (`open_port/2`, `port_close/1`, `port_info/1,2`) over `Rc<RefCell<PortRegistry>>`, the shared `Rc<AtomTable>` and the owning `ProcessId`.
`PortEvent::{Data,Line,Exited,Term,Completion,ActiveInput,Signal,Select}`; `PortEvent::port()` is the **one** port-bearing roster — `Data`/`Line`/`Exited`/`Term` → `Some`, the rest → `None`.
`PortRegistry`: `new()` (anchors the `driver_*` codegen unit, builds the **one** `DriverRegistry::with_static_spawn_drivers`); queries `is_live`, `port_control`, `has_driver_control`, `is_busy`/`soft_busy`, `is_empty`/`has_nothing_to_poll`/`awaits_port_reply`/`awaits_async_completion`, `has_pending_driver_atoms`, `io_counters`, `ids`; commands `command`/`command_with_data` (the one decision table, `write_command` its no-options wrapper), `close`, `create_static_spawn_driver`, `refresh_liveness`, `arm_tty_select`; private pass `register`, `run_port_tasks`/`handle_port_events` (the two entries into a `beam_io` round), `capture_round_monitors`/`failed_port_monitors`, `pump(timeout) -> Vec<PortEvent>`, the `take_*` harvests, the line helpers, `info`, `fold_notifications`, `drain_pending_events`, `report_pending_closes`, `drain_io_completions`, `closed_snapshot`.
`ProcessLiveness` (crate-internal) is the observation behind `driver_monitor_process`'s `ERL_DRV_MONITOR_NOT_ALIVE`: `is_alive(pid) -> Option<bool>`, `try_borrow`-based because it runs *from* a callback, republished each round by `refresh_liveness(&ProcessTable)`; `None` ⇒ install the monitor, never a fabricated `NotAlive`.
`PortName::SpawnDriver` resolves against `create_static_spawn_driver` **before** any `dlopen` (`io.c:599-628`), membership being `driver::is_static_driver` over `beam_io`'s `STATIC_SPAWN_DRIVERS` (the C's `driver_tab.c`) — **not** "a factory registered here", so `fd`/`efile` and an invented name take the `dlopen` route to the oracle's `badarg`; a factory failure surfaces its typed error.
A driver port's reply is one `PortNotification::Data` per `driver_output*` call from the **port-task round** (`Port::take_input_notifications`), never a pre-round harvest off `beam_io`'s flat `Port::drain_input` view, which joins a `driver_output2` call's header and body into one byte string (`src/port.rs:2173-2182`); `PortMeta::has_driver_control` gates `port_control`, whose `PortRegistry::port_control(id, op, arg)` forwards the verb **verbatim** to `beam_io` (`beam_io/src/registry.rs:357`, which reserves `"close"`).
`is_empty()` counts **ports only** (`system_info(port_count)`); `has_nothing_to_poll()` is **nothing-pending** — no live port, no harvested-but-unreported `pending_events`, no owed `'EXIT'`/`'DOWN'` (`pending_port_signals`), no armed `tty_select/2` interest, no fired-undrained `os:set_signal/2` self-pipe; an **armed but idle** `handle` disposition is **not** pending work.
`pump` drains retained events, queued driver output/terms, due exit statuses and handled signals, then — only on a real wake source (a live port or an armed `tty_select/2` interest) — polls in `PORT_POLL_SLICE` (25 ms) slices clamped by the earliest driver deadline, returning early only **after** `take_signals` and `report_pending_closes`; each round ends with the due `exit_status`s then the line channel (`take_eof` → `Port::flush_linebuf`, the C's `driver_eof`, then `take_line_notifications`), a reaped child's `{exit_status,S}` preceding its trailing partial line through `hold_or_report_line`'s `PortMeta::held_lines` (FIFO, once, when the status is taken or `EXIT_STATUS_FLUSH_GRACE` = 1 s expires, `sys_drivers.c:1230-1252`).
A port-task round is **destructive**, so `write_command`'s round (a **built-in** driver answering from that `output` call) folds through the same `fold_notifications` for the next `pump` to report via `drain_pending_events`; `close` purges a closed port's buffer, so a **reused** number inherits nothing.
**Every** entry into a `beam_io` round goes through `run_port_tasks`/`handle_port_events`, which snapshot each live port's incoming monitor set first (`capture_round_monitors` → `pre_round_monitors`), because a round both reaps a driver-failed port and mints its `PortNotification::Closed` report, and minting retires the port **number** — and with it the owner, the links and the incoming monitors.
`PortRegistry::command` drains the failure/completion channels **before** it folds the round's notifications, the order `PortRegistry::pump` uses, so a failing callback's read is rendered from the recipient `fail_port` snapshotted instead of from metadata that teardown is about to purge.
`drain_pending_events` reports a retained `PortEvent::Data` even for a port that has left the runtime: a `Data` recipient is resolved where the read is folded (live metadata, else that snapshot), so the liveness rule there could only suppress the one read the failure's row owes **ahead of** the exit signal, and a read with no recoverable recipient is dropped by the fold itself.
`SpawnDriver` is the **single** OS-child implementation; this crate owns only `open_port/2`'s decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`.
`deliver_port_messages` delivers into the **owning** mailbox through `deliver_in_table`, so a blocked receiver wakes: data/exit-status → `owner`, a driver term → `to.unwrap_or(owner)`, `{select,Handle,Ref,ready_input}` → the arming process, `{notify,Name}` (sender `system`) → `whereis(erl_signal_server)`; `close` calls `notify_port_exit(…, Closed)` **before** `registry.close(...)`.
**Read path**: one `{Port,{data,Data}}` per driver read (`PortEvent::Data { port, read, stream, shape, owner }` → `RuntimeContext::port_data_message_shaped` → `make_stream_payload`) out of the read's own `hbuf`/`buf` split (`beam_io`'s `ReadMessage { header, body }`, the C's `driver_output2` operands): on `[binary]` a body-only read is the bare binary (to `READ_CHUNK`, 64 KiB, on the pointer-stable `eval_heap`), both halves the improper `[H1..Hh|<<Body>>]`, `body: None` the proper `[H1..Hh]`, a header-less empty read `[]`; `[list]` is `ReadMessage::flattened()`; `StreamShape::DriverOutput` marks a built-in driver port and decides only a **header-less** read (Known Issues).
**`{packet,N}`** (`N` ∈ `{1,2,4}`, `packet.rs`) frames the spawn/spawn_executable/fd family only: `write_command` prepends the big-endian header (`PacketFraming::frame_output`), `fold_notifications` reassembles whole packets (`PacketFraming::push`) — one message per packet, header stripped, counters on **payload** bytes; a driver port carries `PortMeta::packet = None`, a partial packet at end of stream is **dropped**, and `{packet,1}` past 255 B / `{packet,2}` past 65535 is a typed `unsupported` where the C kills the port with `einval`.
**`line`/`{line,N}`** delivers through `port_line_message` (`io.c:3454`) as `{eol,Data}`/`{noeol,Data}` — an **empty payload is a real frame** (`{eol,[]}`); a frame's header is the read prefix that produced it (`beam_io::Port::stage_line_frames` stamps it on **every** frame the call produced — the C's per-frame cons, `io.c:3464`), but **only the frame's content bytes are charged** to `port_info(P,input)`/`statistics(io)` (`port.rs:2344-2355`), so a line-mode port **under**-counts by the header plus every separator and held byte: the C charges `hlen + len` **once per `driver_output*` call** (`io.c:6403`, measured — `driver_output2("HDR",3,"ab\ncd\nef",8)` on `[binary,line]` gives `port_info(P,input)` **11** on the oracle and **4** here, the frames themselves agreeing byte for byte).
**The read path never blocks**: stdout is `O_NONBLOCK`ed (`beam_io/src/drivers/spawn.rs:791-795`; `{fd,N}` at `:730`), registered `Interest::READABLE` (`:1088-1090`), `SpawnDriver::ready_input` (`:1105-1137`) looping `read` in `READ_CHUNK` (`:179`) until `EAGAIN` (`packet.rs:192-194`). The boot's `inet_gethost` child is that shape (`inet_gethost_native.erl:416`), carries no `exit_status` ⇒ never status-polled, and its live-but-idle port keeps `has_nothing_to_poll()` false (*Measured*). The child's **stderr is inherited** by default; `stderr_to_stdout` duplicates fd 1 onto 2 (`sys/unix/sys_drivers.c:500`).

### `port/inet_opts.rs` — the per-port inet option mirror (A.4)
Detail: [`driver/CONTEXT.md`](driver/CONTEXT.md) *`port/inet_opts.rs` — the per-port inet option mirror (A.4)*.
`prim_inet:open/6` opens every inet port with `[binary]` alone and applies every other option through `setopts/2`, so this node mirrors the driver's `{mode,…}`/`{active,…}`/`{exit_on_close,…}` out of each accepted `port_control/3` argument; `PortRegistry::data_mode(id, fallback)` is the one consuming accessor the delivery renderers read.
`PortRegistry::drain_active_spends` (`inet_opts.rs:455`) is the spend channel's drain: it takes
`beam_io::PortRegistry::take_active_spends` (destructive — every spend consumed exactly once) and applies each
to the mirror (`InetOptions::spend_active` ⇒ `active = INET_PASSIVE`, `active_count = 0`), and it runs **before**
`collect_peer_closes`'s gate at every drive point, so the peer-close gate never reads a mode a same-round spend
already invalidated; `PortInetOptions::active_state` is the mirror's `ActiveMode` reader, the fallback half of
that gate behind `beam_io::PortRegistry::active_mode`.
### `port/active_input.rs` — the `{active, …}` input channel (A.4)
Detail: [`driver/CONTEXT.md`](driver/CONTEXT.md) *`port/active_input.rs` — the `{active, …}` input channel (A.4)*.
An `{active, true|once|N}` socket parks no input in the port's byte queue, so the driver sends the owner `{tcp,S,Data}`/`{udp,S,IP,Port,Data}`/`{tcp_passive,S}`/`{udp_passive,S}`; the staged `PortEvent::ActiveInput` rides `pending_events`, so `has_nothing_to_poll` sees it.
### `port/peer_closed.rs` — the peer-close channel (`{tcp_closed, Port}`)
Detail: [`driver/CONTEXT.md`](driver/CONTEXT.md) *`port/peer_closed.rs` — the peer-close channel (`{tcp_closed, Port}`)*.
`beam_io::PortRegistry::port_closed(id)` is a latched, sticky observation that a connected socket's peer has closed; `PeerCloseKind::Tcp` is the only kind (the C has no `udp_closed`), and retirement is the C's `driver_exit`, not `port_close/1`.
The gate's `{active,…}` half is the **live** driver state, not the last `setopts`: `inet_active` reads `beam_io::PortRegistry::active_mode` first, so a socket whose `{active,once}`/`{active,N}` grant a delivery spent is passive there and its close is silent — the C's passive arm (`inet_drv.c:12819-12832`, the grant cleared at the spend by `INET_CHECK_ACTIVE_TO_PASSIVE`, `:1552-1560`) — while the observation keeps its latch, so a later active `setopts` re-fires it once (`inet_set_opts`'s sticky arm, `:6968-7016`). Both spent-grant twins are pinned against the oracle in `peer_closed_tests.rs`, including the `{tcp_passive,S}` that only the `{active,N}` arm sends (`:1556-1558`).
### `port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`
Detail: [`driver/CONTEXT.md`](driver/CONTEXT.md) *`port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`*.
A close owes a **trapping** link its `{'EXIT',Port,Reason}` and every watcher its `{'DOWN',Ref,port,Port,Reason}`, `'EXIT'` before `'DOWN'`; the reason rides the signal, so one close's two signals can never disagree.
### `port/failure.rs` — the driver-failure channel's runtime half (A.4)
Detail: [`driver/CONTEXT.md`](driver/CONTEXT.md) *`port/failure.rs` — the driver-failure channel's runtime half (A.4)*.
A driver closes its **own** port through the C's `driver_failure*` family or `driver_exit` (`io.c:7196-7278`) — a **port-closing request**, not a return value — which `beam_io` latches inside the callback; `signal_reason` is the one reason rule and `fail_port` publishes the resulting `'EXIT'`/`'DOWN'` straight into the deliverable queue.
### `port/ops.rs` — the port **table** operations (`port_set_data/2`, the name registry, `port_connect/2`)
`PortExtras` (`pub(crate)`, keyed by **port number** like `meta`) holds what `open_port/2` does *not* establish: `data` (the C's `prt->data`, `erl_bif_port.c:687-760`; absent = never set, rendered `undefined`), `names` and `links` (`ERTS_P_LINKS(prt)`), the `inet_opts` mirror, the `peer_closed` latches and the owner-`'EXIT'` suppression mark; `forget_port(number)` drops all of them from `PortRegistry::close`, the single place a port leaves the runtime.
Accessors: `set_port_data`/`port_data` (`badarg` for a port the registry does not hold, `:693-695`), the name entries, `resolve_port` (the C's `lookup_port`, `:126-143`: an internal port term **or** an atom naming a registered port), `extra_links` (`None` = the port's only link is its owner), `connect_port` (the C's `set_port_connected`, `io.c:2330-2419`: **adds** a link and moves `PortMeta::owner`, the one field every delivery site reads), `suppress_owner_exit`/`owner_exit_suppressed` (`:204`/`:210`, the mark `exit.rs` reads).
The free `connect(ports, table, port, target)` is `erlang:port_connect/2`'s whole body, shared by the floor's `erlang:` spelling and the `RuntimeHooks` bridge's `erts_internal:` one (`erl_bif_port.c:435-470`): resolve the port, require an internal **live** pid target (a dead one ⇒ `badarg`), then transfer — a nested registry borrow being the typed gap. The `ProcessHook` bridge (`../context/process_bridge.rs`) serves the name registry over the **process** table first and the port registry second, so one name has one holder (`register(init, Port)` is `badarg`); the badarg matrix is the oracle's throughout, and `port_get_data/1` of a fresh port is `undefined`.
### `port/info_extras.rs` — the derived `port_info/2` items
`queue_size` is the C's `erts_port_ioq_size(prt)` (`erl_bif_info.c:3868-3874`), the driver's own staging area in both directions; `beam_io::Port` holds exactly those two queues, so the answer is `input_len() + output_len()` (a fresh port `0`).
`memory` is the `am_memory` arm (`:3838-3860`): link nodes, monitor records, the `port_set_data/2` heap and the line buffer, **deliberately excluding the `Port` struct itself**, with `link_size`/`monitor_size` **assigning** rather than accumulating (`:3648-3660`), so N links report one link node and N watchers one monitor half; its constants are the C struct sizes on a 64-bit build (`allocate_linebuf`'s `LINEBUF_INITIAL` 100, `io.c:3155-3166`), and the oracle answers `48` for a bare port, `90` at `{line,10}`, `180` at bare `line`, `72` with one watcher.
`monitored_by` is the `am_monitored_by` arm (`:3735-3765`) read from the port table's incoming monitor list — the authority `erlang:monitor(port, Port)` writes and `Runtime::port_monitors` reports; `locking` is `port_level` for a `spawn`/`spawn_executable`/`fd` port (the C's own drivers set `ERL_DRV_FLAG_USE_PORT_LOCKING`, `sys_drivers.c:251`) and the driver's own level for every `{spawn_driver,Name}` port (the driver node's Known Issues); `parallelism` is truthfully `false`, the runtime never granting `ERTS_PTS_FLG_PARALLELISM` (`erl_bif_info.c:3895-3905`). `awaits_port_reply` — the poll-budget predicate — is defined here too (*Measured*), and so is its read-side twin `awaits_async_completion` (`beam_io::Driver::has_pending_async` over the live ports); `PortRegistry::info` chains all of these after the seven `/1` items.

### `port/watch.rs` — the `os:set_signal/2` delivery half (`pub(crate)`)

### `erlang:port_command/2,3` and the port **busy state** (A.4)
The decision table lives in **`beam_io`'s `Port::command`** (`beam_io/src/port.rs:428`), reached through `PortRegistry::port_command_with` (`beam_io/src/registry.rs:470`, `port_command` folding the outcome away): `PortCommandOutcome::{Done,Busy}` from `PortCommandOptions::{with_force,with_nosuspend}` and the driver's own capability/state.
| port | options | outcome / answer | C |
|---|---|---|---|
| any | `[force]`, driver **without** `SOFT_BUSY` | `Err` = `error:notsup`, **before any output is written** | `erl_bif_port.c:195-198` |
| idle | any (incl. `[force]` with `SOFT_BUSY`) | `Done` — queued, an `OUTPUT` task scheduled; the oracle's `true` | `io.c:1763` |
| busy | `[force]` + `SOFT_BUSY` | `Done` — the busy state is bypassed | `io.c:1731`, `:1763` |
| busy | plain or `[nosuspend]` | `Busy` with **nothing queued**; `[nosuspend]` ⇒ `false`, a plain command is waited out and re-issued where its caller owns a scheduler pass (`busy_wait`) | `io.c:1763-1769` |
The run order is fixed: this crate's **pre-conversion** gate first (`PortRegistry::command_with_data` → `decide_before_data`: the live-port `badarg`, the `[force]`/`SOFT_BUSY` refusal, the busy answer), and only for an accepted command `beam_io`'s own table (`port_command_with`) — so `beam_io` is the decision and this crate holds the C's cheaper pre-checks, never a second table.
The `[force]` refusal is a property of the driver's **capability flag word, never of the busy state**, so it is `notsup` whether or not the port is busy; a `Busy` answer leaves the bytes out of the output queue because the oracle suspends the caller and re-issues the command when the driver clears the state (`erts_port_resume_procs`, `io.c:5265`). The two busy cells the driver host owns are the state pair `Port::command` reads through `PortMeta::driver_busy` (a `driver::BusyFlag`).
The `SOFT_BUSY` bit reaches `PortRegistry::soft_busy` from whichever place owns it: a loaded `ErlDrvEntry::driver_flags` (written onto the seized handle by `DriverPortAdapter::load`) and a built-in driver's own `Driver::flags()` (`open_port`'s `{spawn_driver, Name}` arm stamps it from the concrete driver while it is still in hand) — never from a driver-name test.
So `[force]` on `{spawn_driver,"tcp_inet"}` is the oracle's `true` (`tcp_inet_driver_entry` declares `ERL_DRV_FLAG_SOFT_BUSY`, `erts/emulator/drivers/common/inet_drv.c:1374`) and on `{spawn_driver,"udp_inet"}`/`{spawn_driver,"ram_file_drv"}` its `error:notsup` (`:1432` declares only `ERL_DRV_FLAG_USE_PORT_LOCKING`; `ram_file_drv.c:116` declares nothing) — pinned against the live oracle by `src/port/soft_busy_builtin_tests.rs`.
`[force]` is `notsup` for a `spawn`/`spawn_executable`/`fd` port too, which has no driver flag word at all (`PortMeta::driver_busy` is `None` there).
The runtime's own `port_command` (`../native/port.rs`) runs that gate (`PortRegistry::command_with_data`) and then the accepted command's round/accounting; a **plain** command on a busy port goes through `busy_wait::issue`, which drives `Runtime::pump_scheduler` in bounded rounds until the port reports idle and then re-issues the command — the C's `erts_suspend` + `ERTS_BIF_YIELD3` re-run, taken on the routes that own the pass.
### `port/busy_wait.rs` — the C's suspend-and-retry for a busy port (A.4)
`issue(runtime, may_pump, owner, id, make_data, options) -> Result<PortWrite>` is the whole `erts_port_output` outcome matrix for both `erlang:port_command/2,3` and `erlang:send/2,3`: one `attempt` through `RuntimePorts::command_with_data` (the pre-conversion gate plus the accepted command's round), then `Done` ⇒ `PortWrite::Written` and `Busy` + `[nosuspend]` ⇒ `PortWrite::Suspended` — while `Busy` plain enters `wait_until_idle` and re-issues the command once the port reports idle.
`make_data` is a `Fn` (not `FnOnce`) precisely because a busy port issues the command **twice**, matching the C, which converts the iolist only on the attempt it accepts (`io.c:1749-1754` before `:1790`) so a refused attempt never pays for the conversion.
`wait_until_idle`/`IdleWait::{Idle,Gone,Deadline,CannotPump}` re-tests the port state first (an already-idle or already-gone port costs no round), then runs one bounded `Runtime::pump_scheduler` step — the pass that carries the **port round** (where a driver's `output`/`ready_output`/`timeout` callbacks clear the bit), the **run queue** (where another process's `erlang:port_control/3` runs) and the **timer heap** (so a deadline that frees that process fires); one iteration therefore always either progresses or sleeps, never a busy-spin.
`BUSY_PORT_DEADLINE` (**5 s**) and `BUSY_PORT_PUMP_SLICES` (**64**, the `-eval` receive pump's budget) bound the wait where the C is unbounded, because a single-threaded runtime that owns its own pass would otherwise hang the executable; a caller that may not re-enter the scheduler (a compiled process inside a slice) **parks** instead: `issue` answers `Park`, `RuntimeContext::request_suspend` makes it `BifOutcome::Suspend`, and the runner re-enqueues the process so the BIF is re-executed on resume (the deadline covers that route too); the two typed gaps are `DEADLINE_REASON` (still busy at the deadline) and `BUSY_AGAIN_REASON` (busy again right after an idle verdict — unreachable single-threaded, reported rather than asserted), and `NO_PUMP_REASON` is the **`send`/inline-`!`** route's answer (that instruction cannot consume a suspend latch). `src/port/busy_suspend_tests.rs` pins the in-process park → pump → resume loop with the fixture driver's write counter (one write, never two).
`send_message_to_port` is the **send** route: `classify_message` decomposes the message exactly as `erts_port_command` (`io.c:3981-4013`) — `{InternalPid, {command, Data}}` ⇒ `PortMessage::Command`, `{InternalPid, close}` ⇒ `PortMessage::Close`, everything else (a non-tuple, a non-internal pid as the `from`, an unknown tag) ⇒ `PortMessage::Drop` — and `PortSend::{Write(_), Dropped}` keeps the C's silent-success verdicts (`ERTS_PORT_OP_BADARG`/`_DROPPED`, `bif.c:2594-2600`) distinct from a write.
The `{Pid, {connect, NewPid}}` shape stays `Drop` (Handoffs); a `{Pid, close}` really closes the port.
### The nested port wait — `PORT_EVENT_DEADLINE` (A.4)
A passive `gen_tcp:recv/2,3`, a `gen_tcp:accept/1,2` and a `gen_udp:recv/2,3` are not control-op answers: `prim_inet`'s `recv0/3`/`accept0/3` issue the operation, get an id back, and `receive` the driver's `{inet_async, Port, Id, Result}`, which only a later port round can produce.
A caller that is not a scheduled process — the nested `-eval`/`-s`/`-run`/boot route — sits that wait out itself (`../context/pump.rs::wait_for_port_event`, and the `-eval` bare receive's port branch in `../eval/mod.rs`), over `Runtime::pump_scheduler` so each round really blocks in the poller.
The wait is entered when `PortRegistry::awaits_async_completion` reports a queued operation — the read-side predicate beside `awaits_port_reply`'s written-byte one.
`PORT_EVENT_DEADLINE` (5 s) bounds one window of **no** progress, `restart_port_event_window` re-arms it on a round that made progress, and `PORT_EVENT_DEADLINE_REASON` is the typed capability gap a port that never answers reports (the C suspends the process for ever).
A round is progress when any of three signals moves, and each is necessary: the pass executed a slice, the pass **delivered a port message** (`Runtime::port_events_delivered`, bumped at `deliver_port_messages`'s one site), or no live port holds an asynchronous operation any more.
The delivery signal is the one the other two are blind to — a completion lands in the mailbox in a round that ran no slice and no run-queue entry.
`awaits_async_completion` is **accept-inclusive** (`has_pending_async` counts a listening socket's standing accept interest, and must: this wait is entered *for* an `accept`), so it is read only as "someone could still answer me", never as "an answer is owed".
Nothing is armed, latched or consumed by the wait: the operation was queued **once** by the machine's own control call and a resume only re-scans the mailbox, so a re-park waits on the same operation and never burns a second id (a second `TCP_REQ_RECV` would be the driver's `ealready`).
Agreeing with the oracle on the nested route: `gen_tcp:accept/1,2` ⇒ `{ok, Port}`; a passive `gen_tcp:recv/2,3` whose data arrives **after** the read is armed ⇒ `{ok, Data}`, on an accepted socket and on a connect-side one; `gen_tcp:shutdown/2` ⇒ `ok` (a synchronous control request, so it never needed a wait); `gen_tcp:connect/2,3,4` plus a passive receive against an external server ⇒ `{ok, Data}`.
With no client at all, `accept` ends `rc=3` with that typed `unsupported: port event: … within the 5 s bound` — a bounded diagnostic, never a hang.
Residual, `beam_io`-owned: a passive read on an **accepted** socket whose data was already buffered **before** the read op was armed produces no port event at all, so the wait ends only at the peer's close and answers `{error,closed}` where the oracle answers `{ok, <<"hi">>}`; the connect-side socket with the same pre-buffered data answers `{ok, Data}`, so the loss is in the accepted-socket path (`TcpInetDriver::from_accepted`'s read-interest registration).
The C instead attempts the read synchronously at control time (`erts/emulator/drivers/common/inet_drv.c:12309`) and serves an already-buffered complete unit before it observes the EOF (`:13161-13162`, `:13206-13232`).
One further `beam_io` point this wait touches: a send-then-close peer loses its buffered data in the driver's `read_bytes`/`latch_peer_close` (the destructive latch runs inside the drain loop, before the collected bytes are served).
## Constraints
- The `SignalFacility` is a `thread_local` (not a `Runtime` field) because the runtime is single-threaded (`!Send`), so the slot *is* the process's one facility.
- Never a fabricated success: failures are typed `BeamError`s and an unservable state/lifecycle returns the C's own failure code.
- A payload is credited where it is harvested and the queue it came from is empty afterwards (`fold_notifications` + `drain_pending_events` for the data lane, `PortNotification::Closed` for the signal lane).

## Measured — the poll budget a pass hands this layer (`startup_ms`)
The largest wall-clock cost this layer can impose on a CLI start-up is **not work**: the *blocking budget* a zero-slice scheduler pass hands `PortRegistry::pump`.
- **`PORT_POLL_SLICE` is 25 ms**, *both* the poller's inner clamp and the `port_timeout` an empty pass passes in (`../runtime/scheduler.rs::scheduler_pass`), so a live-but-idle port costs a whole `epoll_wait(…, 25)` per such pass — `strace -f -w` measures five `epoll_wait(3, [], 1024, 25) = 0` at 25.07–26.2 ms each when it does.
- **The predicate separating the two cases is `PortRegistry::awaits_port_reply`** (`info_extras.rs`) over the per-port byte counters kept for `port_info(Port, input)`/`output` (`PortMeta::{input, output}`): `output > input` means unanswered bytes, so the wait is justified, while a port that answered everything (the boot's `inet_gethost` child) cannot speak again until written to.
- **The budget cannot simply be zeroed**: that poll resolves the kernel's `inet_gethost` round trip, and forced to zero `drive_scheduler` returns `0` on its first pump, so the `{apply,{application,start_boot,…}}` directive folds to `unsupported: opcode: run: process blocked` (exit 3 — measured); the predicate therefore *shortens* the wait only for a port that owes nothing.
- **The gate is applied** at `../runtime/scheduler.rs` (`Runtime::awaits_port_reply`, beside `Runtime::ports_awaiting_async` for the read half): a `TimerWait::ImminentWithin(_)` pass — only the boot drive uses that policy — gets `Duration::ZERO` when **neither** predicate holds, and stays patient when the table cannot be borrowed. Measured: blocking rounds **8 → 1**, `strace -f -c -w`'s `epoll_wait` total **130.8 ms → 4.1 ms** over the same **15** calls, `read` 233 ms → 104 ms, the lookup unchanged (**98** `.beam` opens, exactly one `execve` of `<erts>/bin/inet_gethost`), CPU identical either side; paired medians in [`PERF.md`](../../PERF.md).
- **The rule for any future change**: a pass may block on the poller only when something can answer — a port with a reply in flight, a driver holding one of its own asynchronous operations (`awaits_async_completion`, the read's half), an armed driver deadline (`beam_io::PortRegistry::next_deadline`) or an armed `tty_select/2` interest; blocking merely because a port is *live* costs a slice per pass for ever.
- **Re-measure with deterministic counters, not timings**: non-zero `port_timeout` rounds per run, `strace -f -c -w`'s `epoll_wait` total, the `.beam` openat count (**98**) and `execve` of `<erts>/bin/inet_gethost` (**exactly 1**); the pins are `tests.rs::a_port_awaits_a_reply_exactly_while_a_written_command_is_unanswered` and `../runtime/scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing`.

## Known divergence from the oracle: no child-exit auto-close
- ERTS **auto-closes** a `{spawn, Program}` port once its child exits: after the reap, `erlang:port_info(P)` is `undefined`, `lists:member(P, erlang:ports())` is `false`, `erlang:port_close(P)` raises `error:badarg`.
- This runtime does **not**: `PortMeta.notify_exit` is only set by the `exit_status` option, so nothing reaps or removes the port until an explicit `port_close` — which kills and reaps, `meta.remove`s, forgets the extras and releases the id, synchronously.
- The child is reaped at exactly two points, both **`SIGKILL`ing it then blocking in `wait`**: `PortRegistry::close` → `Driver::stop` (`drivers/spawn.rs:1139-1154`) → `kill_and_reap` (`:1225-1246`), and — for a port nobody closed — the driver's `Drop` (`:1165-1175`) when the `Runtime` drops; because `main` evaluates `cli::run` and only then calls `std::process::exit` (`src/main.rs:29`), the `Runtime` in `cli::run`'s `source` **is** dropped on the `halt()` path, so the boot's idle `inet_gethost` child is killed and waited for there and a `wait4` after the last poll round belongs to that teardown.
- The corpus **sidesteps** the divergence rather than pinning it (the five `driver/port_*` close cases each open a child alive until the explicit `port_close/1`), so the gate's 0-mismatch verdict is consistent with it.
- **An abnormal abort can make the boot's `inet_gethost` helper signal the whole process group.** A `SIGKILL` mid-request — the `halt()` teardown above, or a failed boot such as the load-induced `process blocked` exit 3 — drives the installed OTP 29.1.1 helper's `fatal("Cannot write reply to erlang process…")` path (`erts/etc/common/inet_gethost.c:1486`) into `kill_all_workers()` (`:1137-1145`), which walks the worker table it inherited across `fork()`; a slot with `pid == 0` makes that a group-wide `kill(0, SIGUSR1)`.
- Consequence for testing: a suite that spawns `beam_rt` can die with `signal: 10` (test binary, `cargo` and the invoking shell at once), while a clean `halt()` shutdown kills each worker by pid and never signals the group — so a `signal: 10` run is an environment artifact of the abnormal path, not a runtime failure; wrap a long run in `setsid` and retry.
- The in-tree 30.0-rc0 source already guards the child (`close_all_worker_fds(); num_busy_workers = num_free_workers = num_stalled_workers = 0;`, "Make \"fatal\" not find any children", `inet_gethost.c:1670-1672`); the installed 29.1.1 binary does not.
## Handoffs (owned by OTHER nodes)
- **`beam_io` — the driver-downcast seam EXISTS; the residual is a mode accessor.** `core::any::Any` is a supertrait of `Driver` (`beam_io/src/driver.rs:544`), with one downcast path — the inherent `dyn Driver::downcast_ref::<T>()` (`:870`, no `as_any` method to implement) — surfaced **read-only** as `Port::driver_as::<T>()` (`beam_io/src/port.rs:223`) and `PortRegistry::driver_as::<T>(PortId) -> Option<&T>` (`beam_io/src/registry.rs:224`); there is deliberately no `&mut` form, because the port-task round drives the driver. `adopt_accepted` is its one consumer: `driver_as::<TcpInetDriver>(listener)` → `TcpInetDriver::from_accepted(fd, listener)` (the C's `tcp_inet_copy`) → `register`, so the inherited block arrives by struct copy and nothing goes back through `setopts`. Firing the driver's `process_exit` needs no new seam: `execute_port_tasks` already calls `drive_async` each round (`beam_io/src/registry.rs:291-317`).
  The genuine residual: the driver exposes **no mode accessor**, so `PortInetOptions::mode` — read through `PortRegistry::data_mode` — stays the only source for the delivery renderers.
- **`beam_io`** — two further asks: `ERL_DRV_FLAG_USE_PORT_LOCKING` must cross the seam (`DriverFlags` keeps only `SOFT_BUSY`), and a **line-mode** read must name its producing call (or stamp the header on the **first** frame only) so a frame's prefix is charged once, as the C charges `hlen + len` per call.
- **`beam_io` (the completion channel's ask)** — a `driver_caller` on the frozen `Driver` seam would address a completion to the C's `desc->caller` instead of `PortMeta::owner`; the driver's own `{mode, list|binary}` crossing the seam is the same missing **mode accessor** named above, and it is what a post-`open_port/2` `{mode,…}` would need to re-render an `{inet_async,…}` payload.
- **`beam_bifs`** — `erlang:read_timer/1,2` was the connects' blocker (`inet:timeout/1` calls it unconditionally, `lib/kernel/src/inet.erl:4953-4957`); this crate's `RuntimeHooksBridge` serves it, so the connect path needs nothing further there.
- **`beam_process`** — no seam needed for the marking (its single exit observer stays `EtsExitObserver`), **but** a tagged port monitor's `'DOWN'` needs that crate to expose the monitor's `{tag, Tag}`, and `ProcessTable::port_closed`'s `PortTable::close`-first order is what keeps the exit signalling out of that crate — an API that snapshots relations without freeing the port number would move the whole obligation there.
