# `beam_rt::port` — the runtime's A.4 port layer (`port.rs` provider · `driver.rs` host · `ops.rs`/`exit.rs`/`info_extras.rs` side tables)
## Intent
The runtime side of contract A.4: `port.rs` — the **port provider** (`open_port/2`'s `Name`/`Options` decoding, the poller/registry `PortRegistry`, the port-task round and the `{Port,{data,..}}` pump behind `beam_io`) — plus its child modules.
`ops.rs` owns the operations that treat a port as a **table entry** rather than a signal to its driver — the `port_set_data/2`/`port_get_data/1` data term, the registered name, `port_connect/2`'s owner transfer — over one `PortExtras` side table.
`exit.rs` owns the `'EXIT'`/`'DOWN'` messages a closing port owes its links and monitors.
`info_extras.rs` owns the **derived** `port_info/2` items (`queue_size`, `memory`, `monitored_by`, `locking`, `parallelism`), each carrying the C's own derivation.
`driver.rs` is the runtime's **own** driver C-ABI host for `{spawn_driver, Name}` ports over `beam_abi`'s frozen `DriverHost` seam; `watch.rs` is the **delivery half** of `os:set_signal/2` and `tty.rs` the same half of `prim_tty:tty_select/2`'s `enif_select` interest.
It is **separate** from `beam_io`'s own host layer (`beam_io::abi`), so end-to-end `.so`-driver traffic goes through this tree; the native `port_command`/`port_control`/`port_connect`/`port_info` floor lives in `../native/port.rs`.
## API Surface
### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS` (incl. `registered_name`), `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver,SpawnDriverBuiltin}`, `StreamType{List,Binary}` (list default), `IoCounters` (the node-global counters behind `erlang:statistics(io)`), `PortEvent`, and `RuntimePorts` (the `beam_bifs::PortHook` impl: `open_port/2`, `port_close/1`, `port_info/1,2`) over `Rc<RefCell<PortRegistry>>` + the shared `Rc<AtomTable>` + the owning `ProcessId`.
The `Rc<RefCell<..>>` is the ETS pattern, because `FunBridge` needs `&mut Runtime` at the same time, and a nested borrow is a typed gap, never a panic.
`PortEvent::{Data,Line,Exited,Term,Signal,Select}`; `PortEvent::port()` is the **one** port-bearing roster (`Data`/`Line`/`Exited`/`Term` → `Some`, `Signal`/`Select` → `None`), read by `drain_pending_events` and the suites' drain helpers.
`PortRegistry` (private `{poller, registry, meta, static_spawn_drivers, heap, io_counters, watch, tty, liveness, extras, pending_events, pending_port_signals}`) exposes `new()` (anchors the `driver_*` codegen unit, builds the **one** `beam_io::DriverRegistry::with_static_spawn_drivers` table — `beam_io`'s `STATIC_SPAWN_DRIVERS`, the emulator's own drivers `tcp_inet`/`udp_inet`/`ram_file_drv`), the queries/commands (`is_live`, `write_command`, `is_busy`/`soft_busy`, `port_control`, `has_driver_control`, `is_empty`/`has_nothing_to_poll`, `has_pending_driver_atoms`, `io_counters`, `ids`, `close`, `create_static_spawn_driver`, `refresh_liveness`, `arm_tty_select`/`prune_dead_tty`) and the private pass (`register`/`pump(timeout) -> Vec<PortEvent>`/`take_due_exit_statuses`/`take_driver_outputs`/`take_driver_terms`/`take_signals`/`flush_line_stream_ends`/`info`/`fold_notifications`/`drain_pending_events`/`report_pending_closes`).
`ProcessLiveness` (crate-internal) is the runtime's most recent **process-liveness observation** — the state behind `driver_monitor_process`'s positive `ERL_DRV_MONITOR_NOT_ALIVE` — `is_alive(pid) -> Option<bool>` being `try_borrow`-based because it runs *from* a driver callback that may hold unrelated runtime state borrowed.
`refresh_liveness(&ProcessTable)` republishes it from `table.pids()`, **gated on a live `{spawn_driver, Name}` port** and run at the **start of every port round**, so a callback reached **before any round** sees `None` — which `monitor_process_result` answers by installing the monitor anyway, never a fabricated `NotAlive`.
**Static emulator-driver resolution.** `open_port`'s `PortName::SpawnDriver` arm resolves the name against `create_static_spawn_driver` **before** any `dlopen`, as the C resolves it against its loaded-driver list (`io.c:599-628`), so `open_port({spawn_driver,"tcp_inet"},[])` opens a real live port. The membership test is `beam_io`'s static set — `driver::is_static_driver` over `beam_io::STATIC_SPAWN_DRIVERS`/`is_static_spawn_driver`, the C's `driver_tab.c` entries whose `handle == NULL` — **not** "is a factory registered here": `fd`/`efile` are this crate's own *internal* drivers and an invented name is nothing at all, so both take the `dlopen` route and end as the oracle's `badarg`. A **hit** registers the static `Box<dyn Driver>` through the same `register`/`PortMeta` path with `kind = PortName::SpawnDriverBuiltin`, a **miss** keeps the `dlopen` path, and a factory failure surfaces that typed error, never a fabricated port.
`PortName::bytes_from_driver_output` routes the byte paths (an exhaustive `match`, so a new variant is a compile error): a built-in driver port's bytes never travel `take_driver_outputs`, which is `.so`-only, so its reply reaches `pending_events` as an ordinary `PortNotification::Data` (see *the retained-events lane*). `PortMeta::has_driver_control` answers the driver-**`control`-capability** question behind `PortRegistry::has_driver_control` and the `port_control` gate: a `dlopen`ed `.so` port's answer is its entry's own `control` slot (enforced by `beam_io`'s ABI adapter), a **built-in** port's is `builtin_driver_has_control` over `BUILTIN_DRIVERS_WITHOUT_CONTROL` (the single name `ram_file_drv`, the one fact `beam_io`'s `Driver::control` default cannot express), and `spawn`/`spawn_executable`/`fd` are `false`.
`PortRegistry::port_control(id, op, arg)` forwards the verb **verbatim** to `beam_io::PortRegistry::port_control` (`beam_io/src/registry.rs:357`, which reserves the `"close"` verb), where a C driver's verb is the decimal `c_uint` string `erts_internal:port_control/3` produces from its integer `Command`.
Two "is it empty" predicates: `is_empty()` counts **ports only** (`system_info(port_count)`), while `has_nothing_to_poll()` is the **nothing-pending** predicate — no live port, no retained event a round harvested but no pump has reported (`pending_events`), no close's `'EXIT'`/`'DOWN'` still owed (`pending_port_signals`), no armed `tty_select/2` interest and no fired, undrained `os:set_signal/2` self-pipe: the honest "a blocked process cannot be woken and a poll round would be pure sleep" test.
An **armed but idle** `handle` disposition is **not** pending work (its descriptor can only become readable when a signal arrives), so a runtime that only handles a signal and never opened a port is quiescent and pays no sleep.
`pump` first `watch.sync`s the signal self-pipe into the poller, drains the retained events of earlier rounds, the queued driver output/terms, any due exit status and any handled signal, then — **only** when a real wake source exists (a live port or an armed `tty_select/2` interest) — polls in `PORT_POLL_SLICE` (25 ms) slices clamped by the earliest driver deadline, runs the port tasks and reports each driver's `driver_output` as `PortEvent::{Data,Line,Exited,Term,Signal,Select}`, the sentinel `SIGNAL_KEY` readiness event filtered out of the port batch.
Its early return comes **after** the unconditional `take_signals` harvest (so a caught signal is returned at once) and mints the outstanding close reports (`report_pending_closes` → `handle_events` with an empty readiness batch), because minting a close report is what retires the port's number and releases its signals.
Immediately after every round and **before** its early-return test, `pump` takes the due `exit_status`s and then drains the **line channel** — `flush_line_stream_ends` (running `take_eof` on every `line`/`{line,N}` port, whose side effect is `Port::flush_linebuf`, the C's `driver_eof` → `flush_linebuf_messages`) then `take_line_notifications` — so a reaped child's `{exit_status,S}` precedes the flush of its own trailing partial line, the oracle's order.
`SpawnDriver` is the **single** OS-child implementation (this crate owns only `open_port/2`'s decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`).
`deliver_port_messages` delivers each event into the **owning** process's mailbox — data/exit-status to `owner`, a driver-emitted term to `to.unwrap_or(owner)`, a `{select,Handle,Ref,ready_input}` to the arming process and `{notify, Name}` (sender `system`) to the pid `whereis` resolves for `erl_signal_server` — each through `deliver_in_table`, so a blocked receiver is woken; `close` calls `beam_io`'s `notify_port_exit(…, Closed)` **before** `registry.close(...)`.
**The retained-events lane.** A port-task round is **destructive**: `beam_io::PortRegistry::execute_port_tasks` drains every live port's buffered input into `PortNotification::Data` (`Port::take_input_notifications`), so a round run *outside* a pump would discard its bytes — and the one such round is `write_command`'s, which runs the `OUTPUT` task that carried the command, and a **built-in** driver (`ram_file_drv`, `efile`) writes its reply from that very `output` call.
`write_command` therefore folds its round's notifications into `pending_events` through the **single** `fold_notifications` helper the pump also uses, and the next `pump` reports them first through `drain_pending_events`.
Delivery is still **exactly once**: the bytes left `beam_io`'s input queue at harvest, so no later round can produce them again, and `drain_pending_events` `mem::take`s the buffer as it reports it; `take_driver_outputs` stays `.so`-only, so the two lanes never consume the same bytes, and `close` purges the closed port's retained events (`pending_events.retain(|event| event.port() != Some(id))`) so a **reused** port number cannot inherit a dead port's messages.
`fold_notifications` credits a payload in **both** places at the one harvest instant — the node-global `IoCounters::note_input` behind `erlang:statistics(io)` and the port's own `PortMeta::input` behind `port_info(Port, input)` — while `output` stays credited in `write_command`, at the write instant.
The **read path** is one `{Port,{data,Data}}` per driver read (`port_data_message`): a `binary` stream delivers a `binary` **at whatever width the child wrote** (up to `beam_io`'s `READ_CHUNK`, 64 KiB) built by `beam_codec::term::make_binary` on the pointer-stable `eval_heap` (the on-heap `ErlHeapBits` layout at every width), a `list` stream a char list; `port_data_message_shaped` is the same builder with the driver output call's **header/data split** ([`StreamShape`]), which is what renders a C driver's reply shapes (see Known Issues).
A port opened with **`{packet, N}`** (`N` ∈ `{1,2,4}`, `packet.rs`) is **framed by the emulator**, for the spawn/spawn_executable/fd family only (`PortName::frames_packets()`): `write_command` prepends the big-endian length header (`PacketFraming::frame_output`) and `fold_notifications` reassembles the child's bytes into whole packets (`PacketFraming::push`), so the owner receives one message per complete packet with the header stripped — out of one read or across several — while both counters count **payload** bytes only. A driver port carries `PortMeta::packet = None`: its `packet` option belongs to its driver, and the emulator adds no header (measured: a `{packet,4}` `ram_file_drv` port answers a bare `SIZE` byte exactly as the unframed port does). A partial packet at end of stream is **dropped**, because the reassembler lives on `PortMeta` and dies with the port at `close`; a `{packet,1}` payload past 255 bytes or a `{packet,2}` payload past 65535 is a typed `unsupported` gap where the C kills the port with `einval`.
A port opened with **`line`/`{line,N}`** delivers the **framed** shape instead — `{Port,{data,{eol,Data}}}` for a newline-terminated frame, `{Port,{data,{noeol,Data}}}` for a length-limited chunk or the trailing partial line released at end-of-stream — through `port_line_message` (the C's `deliver_linebuf_message`, `io.c:3454`), an **empty payload being a real frame** (`{eol,[]}`) with `input`/`IoCounters` bumping per frame.
The child's **stderr is inherited** by default (never port data); `stderr_to_stdout` duplicates descriptor 1 onto 2, so its diagnostics arrive as port data interleaved with stdout in true write order (`sys/unix/sys_drivers.c:500`).
### `port/ops.rs` — the port **table** operations (`port_set_data/2`, the name registry, `port_connect/2`)
`PortExtras` (`pub(crate)`, keyed by **port number** like `meta`, so a lookup is one hash probe) holds the state `open_port/2` does *not* establish: `data: HashMap<u64, Eterm>` (the C's `prt->data`, `erl_bif_port.c:687-760`; absent means never set, rendered `undefined`), `names: HashMap<u64, Atom>` (one name per port and one port per name, the register table's port entry) and `links: HashMap<u64, Vec<ProcessId>>` (the C's `ERTS_P_LINKS(prt)`); `forget_port(number)` drops all three from `PortRegistry::close` — the single place a port leaves the runtime — so a closed port's name disappears from `whereis/1` and a recycled number starts clean.
Accessors: `set_port_data`/`port_data` (`badarg` for a port the registry does not hold, the C's `data_lookup_port` failure at `erl_bif_port.c:693-695`), the name entries, `resolve_port` (the C's `lookup_port`, `:126-143`: an internal port term **or** an atom naming a registered port), `extra_links` (`None` = the port's only link is its owner) and `connect_port`.
`connect_port` is the C's `set_port_connected` (`io.c:2330-2419`) in its non-`!` form: it **adds** a link (the previous owner's stays, which is why the oracle's `port_info(Port, links)` grows) and moves `PortMeta::owner` — the one field every delivery site reads.
The free `connect(ports, table, port, target)` is `erlang:port_connect/2`'s whole body, shared by its two entry points (the floor's `erlang:` spelling and the `RuntimeHooks` bridge's `erts_internal:` one), and its steps are the C's (`erl_bif_port.c:435-470`): resolve the port, require an internal **live** pid target (a link to a dead process ⇒ `ERTS_PORT_OP_DROPPED`, rendered `badarg`), then transfer — a nested registry borrow being the typed capability gap.
`erlang:port_set_data/2`, `erlang:port_get_data/1` and `erts_internal:port_connect/2` are served by the `RuntimeHooks` bridge; the name registry is served by the `ProcessHook` bridge (`../context/process_bridge.rs`), which consults the **process** table first and the port registry second, so one name can only ever be held by one of them (`register(init, Port)` is `badarg`).
The badarg matrix is the oracle's throughout: a pid/integer/dead port as the port argument, a dead target pid, a port that already has a name, a name another entity holds, an unregistered name; `port_get_data/1` of a fresh port is `undefined`.
### `port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`
A port is linkable and monitorable — `open_port/2` links it to its owner, `port_connect/2` adds links, `erlang:monitor(port, Port)` records an incoming monitor — so a close owes what a dying process owes its peers: `{'EXIT', Port, normal}` to a **trapping** link and `{'DOWN', Ref, port, Port, normal}` to every watcher, `'EXIT'` before `'DOWN'`.
The policy, measured on the oracle: a **trapping** linked process gets `{'EXIT',Port,normal}`; a non-trapping one gets **nothing** and is **not** terminated (a `normal` reason in the link family is ignored); every watcher gets its `'DOWN'` and has its outgoing `PortWatch` removed; a recipient the table does not hold is skipped.
`PortSignalKind{Exit, Down(MonitorRef)}` + `PortSignal{port, to, kind}` are per **recipient**, so a route that can only observe its own mailbox takes its own entries and leaves the rest queued, in `PendingPortSignals{unreported: HashMap<u64, Vec<PortSignal>>, ready: Vec<PortSignal>}`.
**Why the obligation is discharged in two steps.** `beam_process`'s own `ProcessTable::port_closed` implements this table, but its first step `PortTable::close` frees the port number immediately, while `beam_io` keeps a closed port's number allocated until its `PortNotification::Closed` report is minted (`take_closed_notifications` → `ids.release`) so a `close`+`open` pair in one slice cannot make a deferred report name a different, live port.
So `capture_port_exit(id)` — called from `close` while the metadata, the link set (`extra_links`, or the owner for a never-reconnected port) and the incoming monitors (the authoritative `beam_process::PortTable::monitors`, **not** the always-empty `PortMeta::monitors`) are still readable — only **stashes** the snapshot, and `fold_notifications`'s `PortNotification::Closed` arm moves it into `ready` (`PendingPortSignals::report`), the one point at which the port has genuinely left the runtime.
The reason is not carried: `port_close/1` is this runtime's only closer and always closes with `normal`.
Delivery is **pull-based**: `Runtime::deliver_port_signals(&mut self, table)` takes every deliverable entry (the scheduler `run` route, through `RuntimeContext::deliver_in_table`, so a parked receiver wakes) and `RuntimeContext::poll_port_signals()` takes only its own process's entries (`take_port_signals_for`, the `-eval` `receive` route).
`PendingPortSignals::prune(alive)` (driven from `poll_port_signals` through `prune_dead_port_signals`) drops an undeliverable entry, because a route taking only its own entries can leave one for a recipient that will never poll again — holding `has_nothing_to_poll()` false for ever.
### `port/info_extras.rs` — the derived `port_info/2` items
`queue_size` is the C's `erts_port_ioq_size(prt)` (`erl_bif_info.c:3868-3874`), the driver's own staging area in both directions; `beam_io::Port` holds exactly those two queues, so the answer is `input_len() + output_len()` (a fresh port `0`).
`memory` is the C's `am_memory` arm (`:3838-3860`): the port's link nodes, its monitor records, its `port_set_data/2` heap and its line buffer, **deliberately excluding the `Port` struct itself**; the C's `link_size`/`monitor_size` callbacks **assign** rather than accumulate (`:3648-3660`), so N links report one link node and N watchers one monitor half, reproduced verbatim here.
The constants are the C struct sizes on a 64-bit build: `LINK_NODE_BYTES` 48 (`sizeof(ErtsLink)`), `MONITOR_DATA_BYTES` 72 (`erts_monitor_size`, `144 / refc 2`), `PORT_DATA_HEAP_BYTES` 72 (`sizeof(ErtsPortDataHeap)`) and `LINEBUF_BYTES` 32 + `LINEBUF_INITIAL` 100 (`allocate_linebuf`, `io.c:3155-3166`: `ovsiz = min(bufsiz, 100)`, `bufsiz` being `{line,N}`'s `N` or a bare `line`'s 512).
Measured against the oracle: `{memory,48}` for a bare port (one link), `90` at `{line,10}`, `180` at bare `line`, `72` with one watcher and still `48` with two links.
`monitored_by` is the C's `am_monitored_by` arm (`:3735-3765`) read from the port table's incoming monitor list — the same authority `erlang:monitor(port, Port)` writes and `Runtime::port_monitors` reports.
`locking` is `port_level` for a `spawn`/`spawn_executable`/`fd` port (the C's own drivers set `ERL_DRV_FLAG_USE_PORT_LOCKING`, `sys_drivers.c:251`) and `driver_level` for every `{spawn_driver,Name}` port (see Known Issues); `parallelism` is truthfully `false`, this runtime never granting `ERTS_PTS_FLG_PARALLELISM` (`erl_bif_info.c:3895-3905`), the oracle's own answer for a `spawn` and a driver port alike.
`PortRegistry::info` chains them after the seven `/1` items, and the native floor's `port_info/1` keeps only the C's `ERTS_PORT_INFO_1_ITEMS` roster, so no `/2`-only pair can leak into `/1`.
### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a loaded driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops); `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_`, and the handle **is** the per-port `DriverEnv`'s address — a driver-private term arena, the shared `AtomTable` + a `PendingInterner`, the owning `ProcessId`, and the output/pid services.
`load_driver(candidates, name)` delegates to `beam_abi::driver::loader::load` (a real `ErlDrvEntry` loader, distinct from the NIF loader and needing no host), tries each candidate (the loader appends `.so`) and reports the **last** typed error.
`binary_to_term` (the hook `erl_drv_binary_to_term` reaches) decodes into a **per-thread memoized image** of the shared table (`crate::nif::with_decode_scratch`, validated in O(1) by an `AtomSnapshot` witness), records a name it appended on the pending interner at its predicted index (`intern`, never `intern_atom`, since the interner's `base` is fixed when the host is built) for the atom-commit step, and answers the C's `ERTS_DDT_FAIL` (`None`) for an invalid image, never a raise.
The registry hooks carry the C's exact codes: `add_driver_entry`/`remove_driver_entry` (`add` → `0`; `remove` `1`/`0`/`-1` per `io.c:7698`), `lock_driver` keyed off the port's load state (`:7324`) and `create_port` = the invalid-port sentinel.
`DriverPort` owns the per-port **driver-private state** the frozen seam has no term/home for, in `driver/state.rs`: the C's `prt->ioq` (`io.c:6790-6919`) byte queue — an ordered list of enqueue chunks, one per successful `driver_enq`/`driver_pushq` — behind `enq`/`pushq`/`deq`/`sizeq`/`peekq`, plus the `pdl_created` one-PDL guard; it is distinct from both the Erlang→driver output queue `beam_io` owns (`prt->queue`) and the port's *input* queue.
`with_port_flags` carries the port's **state** stream bits (`StreamType::port_flags` → `PORT_FLAG_BINARY` (1) for a `binary` port, else `0`), which `get_port_flags` reports — a **different** cell from the `control_flags` `set_control_flags` records for the `port_control` reply form (`io.c:5325-5344` vs `:5318`); `clear_driver_state` (called from `stop` **and** the adapter's `Drop`) drops the queue so a late drain never reads bytes of a port that has gone away.
`DriverPortAdapter` is the **port lifecycle** the host alone lacks — a `beam_io::Driver` over a loaded C driver: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, kept in a `Box` that never moves); `output` hands the port's queued bytes to the entry's `outputv` when it declares one (**the C's preference**, `io.c:1782`/`:1597`) and to `output` otherwise, so an **`outputv`-only** entry really receives `port_command`; it queues the `driver_output` reply as the port's **input**; `stop` runs the entry's `stop` and the drop runs `finish` + `dlclose`.
It also seizes the host's `Rc<DriverMonitors>` at `load` and overrides `has_pending_async`/`drive_async`, that per-round drive point firing the entry's `process_exit` once per marked monitor (`driver/monitor.rs`), the tree cleared in `stop` **and** at the top of `Drop` so no callback can run after the library unloads.
An `OUTPUT` port task (`Port::run_task` → `ready_output`) **always** drains the output queue through the single `output` write path and *then* runs the entry's `ready_output` slot, when declared, as the write-**readiness** notification (the C's `ERTS_PORT_TASK_OUTPUT` arm, `erl_port_task.c:1793-1797`).
`build.rs`'s `-Wl,--export-dynamic` publishes the `driver_*`/`erl_drv_*` symbols; `open_port({spawn_driver, Name}, Options)` routes here for a name no built-in driver answers, an unknown or empty driver name being `badarg`.
`DriverPort` also carries the per-port monitor tree, the `has_process_exit` flag, the shared `Rc<ProcessLiveness>` and the shared `BusyFlag` `set_busy_port` writes (`busy_flag`, stamped with `ERL_DRV_FLAG_SOFT_BUSY` by `load`).
The adapter maps `load`/`name`/`state`/`selected` plus `start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`stop`; `control(command: &str, arg: &[u8])` parses the verb as a `c_uint`, `control_reply(reply, request, rbuf, len)` resolves the reply source, and `notify_ready(ctx, fd, read)` runs one **already-resolved** descriptor's `ready_input`/`ready_output` while `dispatch_ready` keeps the resolution half.
`DriverPort` implements **28 of the 41** `DriverHost` hooks — the 4 required ones, `binary_to_term`, the timer family, `connected_pid`/`caller_pid`, the driver-private queue family, both port flags, `set_busy_port`, `pdl_create`, the monitor family and the 4 registry slots (all four overridden: `lock_driver` = `0` iff the driver is loaded else `-1`, `create_port` the invalid-port sentinel).
The other **13** keep the frozen trait default (the C's own failure code) — `r#async` (`-1`), the lifecycle family (`failure`/`port_exit`/`busy_msgq_limits`/`init_ack`/`set_os_pid`/`async_port_key`), the PDL refcount family and `now` — because each needs runtime structure a per-port host holds no handle to (the exit/OS-pid state lives in `beam_io::Port`; a refcounted PDL *lock object*; `std::time` for `now`), so a C driver calling any of the 13 gets the C's failure code, never a fabricated success.
The timer family matches the C for **every** live port: the C substitutes a silent `no_timeout_callback` when the entry declares no `timeout` slot (`io.c:7601`), so `io.c:6918`'s `-1` stands only for an invalid port; a fired deadline runs the entry's `timeout` or is the C's silent no-op.
### Driver-emitted terms (`erl_drv_output_term` / `erl_drv_send_term`) — `TermQueue`
`beam_abi` decodes the driver's term-data stack machine into a real term on the host's arena and calls `DriverHost::send_term(port, to: Option<Eterm>, term)`; the C delivers there and then (`driver_deliver_term`, `io.c:5664`), and the frozen seam gives the host no route to a receiver's mailbox, so the term is **queued** in a per-port shared `TermQueue`, `None` = the connected process (`erl_drv_output_term`, `io.c:6254`) and `Some(pid)` = an explicit destination (`erl_drv_send_term`, `:6289`).
A queued term's words live on the host arena, so the adapter empties the queue in both `beam_io::Driver::stop` (`deliver_term_check_port`, `io.c:6213`) and its `Drop`; `PortRegistry` seizes the handle as `meta.driver_terms` at `open_port/2`, `take_driver_terms` surfaces each as `PortEvent::Term{port, to, term, owner}`, and the pump copies it onto the pointer-stable arena (`stabilize_driver_term`) and delivers it.
### `port/watch.rs` — the `os:set_signal/2` delivery half (`pub(crate)`)
One `thread_local!` `FACILITY: RefCell<FacilitySlot>` holds the facility the first `os:set_signal/2` creates and production **never drops** (a per-call facility would drop at the end of the call, and `SignalFacility::drop` restores the prior dispositions); `HANDLED: RefCell<BTreeSet<Signal>>` mirrors which signals hold `Disposition::Handle`, so `is_pollable` answers without a syscall.
`SignalWatch{token, fd}` is the poller registration, owned by `PortRegistry`: `sync(poller)` registers the facility's `read_fd()` under `SIGNAL_KEY` (= `u64::MAX - 1`) on the first round after a `handle` disposition; `is_pollable()` is the **poll-set** half and `has_pending_signal()` the **pending-work** half — a non-destructive zero-timeout readiness probe of the self-pipe, whose byte is the *whether* and the facility's private bitmask the *what*.
`crate::context::signal` owns the oracle answer surface (`{ok, OldDisposition}`/`badarg`, the kernel-only `sigstop` rule) and delegates the facility here; the message is `signal_notify_message(name)` → `(from, {notify, Name})` with `subject` interned as `system`.
### `erlang:port_command/2,3` and the port **busy state** (A.4)
A driver marks its port busy with `set_busy_port` (`io.c:5208-5264`); `port_command/2,3`'s answer then depends on that bit and on whether the loaded **driver entry** advertises `ERL_DRV_FLAG_SOFT_BUSY`.
`BusyFlag` (`driver.rs`) is the one shared handle for both halves: `busy` (`Rc<Cell<bool>>`, written by `set_busy_port` from inside a driver callback) and `soft_busy` (`Rc<Cell<bool>>`, stamped by `load` from `library.entry().driver_flags`).
`PortMeta.driver_busy` seizes it at registration from `host.busy_flag()` — `Some` only for a `{spawn_driver, Name}` C-driver port, `None` for a `spawn`/`fd` port and for a **built-in** driver port (whose entry flags the built-in registry does not expose), the C's "never busy, no `SOFT_BUSY`" case.
`../native/port.rs`'s `port_command` reads both (under one borrow, after the liveness check) and picks the arm the C picks (`erts_port_output`, `io.c:1749-1764`; `erl_bif_port.c:192-220`):
| port | options | answer |
|---|---|---|
| idle | `[]` / none / `[nosuspend]` | the atom `true` |
| idle | `[force]` | the atom `true` iff the **driver entry** advertises `ERL_DRV_FLAG_SOFT_BUSY`, else `error:notsup` |
| busy | `[nosuspend]` (no `force`) | the atom `false` — the command is dropped, nothing written |
| busy | `[force]` | the atom `true` iff the entry advertises `ERL_DRV_FLAG_SOFT_BUSY`, else `error:notsup` |
| busy | neither | the typed capability gap (see Known Issues) |
The `force` rule is a property of the driver **entry**, **not** of the busy state: `erl_bif_port.c:195-198` rejects `[force]` with `notsup` whenever the entry lacks the flag, **idle or busy alike**, so a `spawn`/`fd` port — and a built-in driver port — always answers `notsup` for `[force]`.
The busy check precedes the iodata conversion (`io.c:1760-1764`), so a busy port's `[nosuspend]` answers `false` even for non-iodata; a malformed/unknown option is `badarg` and the list is validated **before** the port is looked up, while the liveness check precedes the `force`/busy decisions, so a dead port with `[force]` is `badarg`, not `notsup`.
## Constraints
- Crate is `#![deny(unsafe_code)]`: the registry slots operate over a **thread-local** entry list `DRIVER_ENTRIES`, not a process-global `DriverTable`, because the runtime drives every port on one thread.
- Every driver callback runs under `publishing` → `beam_abi::with_current_host` (`start`/`ready_*`/`output`/`timeout`/`stop`), which is what lets the two port-less registry slots reach a host during a callback.
- The `SignalFacility` is a `thread_local` (not a `Runtime` field) because the runtime is single-threaded (`!Send`), so the slot *is* the process's one facility, and a **second** live facility would re-point `beam_io`'s trampoline write end at its own pipe.
- Never a fabricated success: failures are typed `BeamError`s, and a state/lifecycle it cannot serve returns the C's own failure code.
- The `Rc<RefCell<..>>` handles are the ETS pattern so a port operation never needs a runtime borrow a `fun` argument already holds — a nested borrow is a typed gap, never a panic.
- Nothing is delivered twice: a payload is credited where it is harvested and the queue it came from is empty afterwards (`fold_notifications` + `drain_pending_events` for the data lane, `PortNotification::Closed` for the signal lane).
## Known Issues (this is a floor, not the full C `io.c`)
- **`erlang:port_control/3` is live end to end**: the native floor's `port_control` (not a `PortHook` method, not in `KNOWN_UNIMPLEMENTED_ERLANG_BIFS`) validates `Port`/`Operation`/`Data` (`erl_bif_port.c:322-360`) and forwards the verb as the decimal `c_uint` string; an **absent** `control` slot and a **negative** `cres` are both `badarg` (`io.c:4035`/`4074`), so `port_control/3` is `badarg` for **every** verb on a port whose driver declares no `control` callback. That is the `PortRegistry::has_driver_control` capability gate, answered per **driver entry** rather than per `Name` form: an internal port (`spawn`/`spawn_executable`/`fd`) never has one, and among the built-ins `ram_file_drv` does not (`BUILTIN_DRIVERS_WITHOUT_CONTROL`) — `port_control(P, 1, <<0,0,0,3,97,98,99>>)` on `{spawn_driver,"ram_file_drv"}` is `badarg` even though the driver answers that verb through `port_command`. A `{spawn_driver, Name}` port whose driver **does** declare one — a loaded `.so`, or the built-in `tcp_inet`/`udp_inet` — reaches its callback. The driverless port's verb-blind `badarg` and the driver's own per-verb operand rejection converge on the same atom but are distinct by cause.
  The reply renders as a **list of byte integers** at every length and as a **binary** only once the driver set `PORT_CONTROL_FLAG_BINARY` through `set_port_control_flags` (a per-port flag that persists across calls), a `NULL` reply pointer being the C's `NIL` (the bare `[]`); the one residual gap is a reply the driver answers from **its own** memory, the typed *unsupported* (see Handoffs), never a fabricated or truncated reply.
- **The one `port_command/2,3` divergence: a plain command on a busy port.** The C **suspends** the caller (`erts_suspend` + `ERTS_BIF_YIELD3`, `erl_bif_port.c:211-220`) until the port goes idle and re-runs the BIF, so the oracle eventually answers `true`; this runtime's BIF seam (`ExecutionContext::call_bif`) returns only `Result<Eterm>` — no block channel — so that arm raises the typed capability gap (exit 3, reason naming the busy state) rather than fabricating the eventual `true`; every other arm (`true`, `false`, both `notsup`s) matches the oracle.
- **A NULL driver reply with `PORT_CONTROL_FLAG_BINARY` set answers `<<>>` where the C answers `[]`**: `write_port_control_result` (`io.c:4126`) returns `NIL` for a NULL reply pointer **before** it looks at the flag, while the adapter collapses "the driver left `*rbuf` NULL" and "the driver answered zero bytes" into one empty `Vec`; closing it needs that bit threaded to `PortRegistry::port_control`, because the `beam_io::Driver::control -> Result<Vec<u8>>` seam carries none.
- **`driver_async` schedules nothing**: `r#async` keeps the frozen default `-1`, because `Runtime` is `!Send`, no worker thread can call back into it, and the C's in-band path when the pool is empty (`erl_async.c:604-613`) needs the entry's `ready_async`, which only the adapter's loaded library holds.
- A queued `TermQueue` entry carries no sending-port identity (the C stamps `from = prt->common.id`).
- `beam_io`'s `EfileDriver`/`FdDriver` are implemented and tested but do open/read/write only and are **never constructed by this runtime** (only `SpawnDriver` is); file I/O here is the `std::fs`/`std::env` native floor under `../native/prim*.rs`.
- **Driver-interned atoms land at the port boundary, not inline**: a name first interned *inside* a driver callback gets a **predicted** index, because the live table is borrowed for the whole callback; `commit_driver_atoms` commits it at that exact index, and a prediction the table has moved past is **reported** (`dropped` and printed), never interned at a foreign index.
  `atoms_mut` deep-clones the shared table **once in a round where a driver really interned a new name**, so the round applies `has_pending_driver_atoms`'s guard **before** the borrow (merely *reaching* `atoms_mut` with a live host handle clones the whole table, Θ(N)), pinned by `tests.rs::an_idle_port_round_does_not_clone_the_shared_atom_table`.
- The exact success code of the four term-emitting calls differs: the C returns `1` for a well-formed spec, this runtime's `send_term` returns `0` (the **accept/refuse split** agrees and is pinned by the `driver_abi` corpus).
- `take_exit_status` is always `Ok(None)` — a driver port owns no child, so no `{Port,{exit_status,…}}`.
- **The monitor family is live end to end**: `DriverPort` keeps the per-port `DriverMonitors` tree (keyed on the C's 24-byte reference identity, read/written only through the safe `beam_abi::monitor_identity`/`monitor_from_identity`), seized as `PortMeta.driver_monitors` at `open_port/2`; `monitor_process_result` answers the C's `0`/`1`/`-1` over a five-way split (no `process_exit` slot ⇒ `-1`; a non-local pid ⇒ `-1`; an observed-alive local pid ⇒ `0` plus a fresh holder; an observed-dead local pid ⇒ `1` with nothing installed; **no observation** ⇒ `0`, the non-regression fallback).
  The **marking** half: `note_driver_monitor_exits(&ProcessTable)` walks every live port's tree and calls `note_process_exit(pid)` for each watched pid the table no longer holds; `Runtime::drain_driver_monitor_exits` **defers** with `Ok(0)` on a live borrow, and the scheduler pass runs it immediately before `deliver_port_messages` so the same round's probe fires the entry's C `process_exit`.
- **`PORT_FLAG_LINE` (2) is reachable, and line framing is adopted end to end.** `open_port/2` decodes `line`/`{line, N}` into `PortOptions::line: Option<usize>` (a bare `line` is `LINE_DEFAULT_MAX_LEN` = `512`; `{line, N}` requires a positive small integer), carries it as a **separate** `PortMeta::line` field (so `[binary, line]` sets both state bits) and arms it through `beam_io`'s `set_line_mode(id, Some(max_len))`.
  `StreamType::port_flags(line)` ORs `PORT_FLAG_BINARY` (1) and `PORT_FLAG_LINE` (2) independently, so `[line]` answers `2`, `[binary]` `1`, `[binary, line]` `3` and no stream option `0` (oracle-verified through a C driver's `get_port_flags`), and the exclusivity rules are checked after the whole list is parsed (`line` + `{packet, N}`, `stderr_to_stdout` without `use_stdio` ⇒ `badarg`); `stream_options` asks the child driver for its **end-of-stream observation** on exactly the line-mode ports, which is what lets `flush_line_stream_ends` release the trailing partial line, while the `eof` *option*'s own `{Port,eof}` report stays unsynthesised.
- **`get_port_flags` is answerable from inside `start` where the oracle answers `0`.** The oracle ORs `ERTS_PORT_SFLG_BINARY_IO`/`_LINEBUF_IO` into `port->state` only **after** `open_driver` returns (`erl_bif_port.c:1139-1143`), while `with_port_flags` sets the bits at host construction, **before** the adapter's `start` runs; no corpus case calls it from `start`, so the gate does not see it.
- **`driver_async_port_key` stays unimplemented** (`async_port_key` keeps the trait default `-1`): the C body (`erl_async.c:518-525`) returns the port's internal data word **truncated to 32 bits**, an address-derived opaque value whose only defined use is the pool bucket selector (`:585-593`); the seam has no handle to a port term's data word, the value is not oracle-comparable, and this runtime has no async pool to key into.
- A driver that armed **more than one** registration per direction is a typed `unsupported` (`armed_event`), never a wrong descriptor.
- `os:set_signal/2`'s notification is **dropped when no `erl_signal_server` is registered** — the C's own behaviour (`sys.c:589-604`), never an error; the `-eval` receive path can only observe its own mailbox, so it drops a `PortEvent::Signal`, while the scheduler path delivers it.
- **The `[binary]` stream's *term shape* is a function of the driver output call, and the builder renders every shape — the *producer* is still `beam_io`** (`ram_file_matrix_tests.rs`, `stream_shape_tests.rs`). Measured on the oracle: `OK`/`NUMBER`/`ERROR` (`driver_output2`, `ram_file_drv.c:181-228`) arrive as a **proper** list (`[3,0,0,0,0]`, `[0]`, `[1,101,105,110,118,97,108]`) and `DATA` (`driver_output_binary`, `:448`) as an **improper** `[2,0,0,0,2|<<97,98>>]` — the zero-length end-of-file form being `[2,0,0,0,0|<<>>]`; the default `list` stream renders the same bytes as `[2,0,0,0,2,97,98]`. `StreamShape::{Data,Header,HeaderThenData}` + `RuntimeContext::port_data_message_shaped`/`make_stream_payload` reproduce each of those terms exactly. End to end the runtime still emits one **binary**, because `beam_io`'s stream layer folds `driver_output2`'s header/data split into one `Vec<u8>`: the port layer is handed bytes without the split and reports `StreamShape::Data`. The bytes and both byte counters agree; carrying the split across the seam is the `beam_io` handoff below, never a port-layer substitute.
- **`port_set_data/2`'s term words are not counted by `port_info(Port, memory)`**: the C copies the term onto a private heap and counts `sizeof(ErtsPortDataHeap) + (hsize-1)·8`, while this runtime keeps it on its pointer-stable store, so `port_set_data(P,{foo,1})` reports `120` where the oracle reports `136`; no number is fabricated.
- **`locking` reports `driver_level` for every `{spawn_driver, Name}` port.** The C decides on the driver entry's `ERL_DRV_FLAG_USE_PORT_LOCKING` (`erl_bif_info.c:3875-3894`), but the bit does not cross the `beam_io` seam (`DriverFlags` keeps only `SOFT_BUSY`); the OS-child drivers report `port_level`, the oracle's own answer.
- **A tagged port monitor's `'DOWN'` carries the default head.** `erlang:monitor/3`'s `{tag, Tag}` for a **port** monitor lives in `beam_process`'s private `ProcessTable::tags` map, which no API of that crate exposes; the untagged shape is byte-exact.
- **The `-eval`/action process starts with `trap_exit = false`** (`../runtime.rs::as_action_process`), where the oracle's `-eval` process reports `{trap_exit,true}` — a known own-state divergence, which is why every port-exit fixture sets the flag explicitly.

## Known divergence from the oracle: no child-exit auto-close
- ERTS **auto-closes** a `{spawn, Program}` port once its child exits: after the child is reaped, `erlang:port_info(P)` is `undefined`, `lists:member(P, erlang:ports())` is `false`, and `erlang:port_close(P)` raises `error:badarg` (measured on the erts-17.1 oracle).
- This runtime does **not** auto-close on child exit: `PortMeta.notify_exit` is only set by the `exit_status` option, so nothing reaps or removes the port until an explicit `port_close` — `close` kills+reaps, `meta.remove`s, forgets the extras and releases the id, the whole close being synchronous.
- The corpus **sidesteps** the divergence rather than pinning it: the five `driver/port_*` close cases each open `{spawn,"cat"}`, a child alive until the explicit `port_close/1`, so the close is a synchronous success on both runtimes — the divergence is real but unpinned, and the gate's 0-mismatch verdict is consistent with it.
## Handoffs (owned by OTHER nodes)
- **`beam_abi`** — `r#async` adoption needs a **safe** route from the hook's three raw operands to an `AsyncJob`: the runner and `DriverLibrary::ready_async` exist, but `AsyncJob::new` is that crate's one `unsafe` entry point.
- **`beam_abi` / `beam_io`** — a **safe reply-copy** helper for a `control` reply the driver answered from memory of its own (today an `unsafe` slice read inside `impl Driver for DriverPort`, `beam_io/src/abi/port.rs:710-747`); until it exists `control_reply` answers the typed *unsupported*.
- **`beam_io`** — the driver-entry flag `ERL_DRV_FLAG_USE_PORT_LOCKING` would have to cross the seam (`DriverFlags` keeps only `SOFT_BUSY`) for `port_info(Port, locking)` to answer `port_level` for a driver that asks, and the stream-message layer is where the `[binary]` term shape's **producer** lives: it must hand the port layer `driver_output2`'s header/data split (so `port_data_message_shaped` can render it) instead of one flat `Vec<u8>`; firing the driver's `process_exit` needs no new seam, since `execute_port_tasks` already calls `drive_async` each round (`beam_io/src/registry.rs:291-317`).
- **`beam_process` — no seam needed for the marking** (its single exit observer stays `EtsExitObserver`), **but** a tagged port monitor's `'DOWN'` needs that crate to expose the monitor's `{tag, Tag}`, and `ProcessTable::port_closed`'s `PortTable::close`-first order is what keeps the exit signalling out of that crate — an API that snapshots relations without freeing the port number would move the whole obligation there.
