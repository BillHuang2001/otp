# `beam_rt::port` — the runtime's A.4 port layer (`port.rs` provider · `driver.rs` host · `ops.rs` tables)
## Intent
The runtime side of contract A.4.
`port.rs` is the **port provider**: `open_port/2`'s `Name`/`Options` decoding, the `PortRegistry`, the port-task round, the `{Port,{data,..}}` pump behind `beam_io`.
Each child owns one post-`open_port/2` fact over the one `PortExtras` side table: `ops.rs` the table operations, `exit.rs` the `'EXIT'`/`'DOWN'` a close owes, `failure.rs` the driver's own close request, `info_extras.rs` the derived `port_info/2` items.
Four are driver→owner channels: `completion.rs` (`{inet_reply,…}`/`{inet_async,…}`, what makes `prim_inet:send/4` return), `active_input.rs` (`{tcp,…}`/`{udp,…}`/`{tcp_passive,…}`), `peer_closed.rs` (`{tcp_closed,S}`) and `inet_opts.rs` (the per-port `mode`/`active`/`exit_on_close` mirror, whose `{active,…}` half `drain_active_spends` keeps in step with the driver's spend path).
The driver side that stages them, and each channel's mechanics, are [`driver/CONTEXT.md`](driver/CONTEXT.md).
`driver.rs` is this runtime's **own** driver C-ABI host for `{spawn_driver,Name}` ports over `beam_abi`'s frozen `DriverHost` seam (`driver/`); `watch.rs` delivers `os:set_signal/2` and `select.rs` the `prim_tty:tty_select/2` interest, the special case of its `enif_select` store (`select/`).
**Separate** from `beam_io`'s own host layer (`beam_io::abi`), so end-to-end `.so`-driver traffic goes through this tree.
## API Surface
### `port.rs` — the `PortHook` provider (A.4)
`RuntimePorts` is the `beam_bifs::PortHook` impl (`open_port/2`, `port_close/1`, `port_info/1,2`) over `Rc<RefCell<PortRegistry>>`, the shared `Rc<AtomTable>` and the owning `ProcessId`; public beside it: `PORT_INFO_ATOMS`, `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver,SpawnDriverBuiltin}`, `StreamType{List,Binary}` (list default), `IoCounters` and `PortEvent::{Data,Line,Exited,Term,Completion,ActiveInput,Signal,Select}`, whose `port()` is the **one** port-bearing roster (`Data`/`Line`/`Exited`/`Term` → `Some`, the rest → `None`).
`PortRegistry` owns the poller, the port-task round and the per-port metadata: the decision entry points are `command`/`command_with_data` (`write_command` the no-options wrapper), the pass is `pump(timeout) -> Vec<PortEvent>`, and the predicates a host reads are `is_live`, `is_empty`, `has_nothing_to_poll`, `awaits_port_reply`, `awaits_async_completion`, `has_pending_driver_atoms`, `is_busy`/`soft_busy`, `io_counters`, `ids`.
`PortName::SpawnDriver` and `{spawn, Cmd}` resolve against the **static membership gate** `driver::is_static_driver` over `beam_io`'s `STATIC_SPAWN_DRIVERS` (the C's `driver_tab.c`: `tcp_inet`/`udp_inet`/`ram_file_drv`; `io.c:599-628`) — a command over its **first token** (`spawn_names_driver`) against that set ‖ `driver::driver_is_loaded` — before any `dlopen`.
Membership is **not** "a factory registered here", so `fd`/`efile` and an invented name take the `dlopen` route to the oracle's `badarg`, while `{spawn,"ram_file_drv"}` IS that driver's port (`PortName::SpawnDriverBuiltin`, `{name,"ram_file_drv"}`/`{os_pid,undefined}`, what `ram_file.erl:383` needs); `opens_a_driver_port` (the `[exit_status]` refusal) reads the same helper, so the two cannot drift.
`ProcessLiveness` (crate-internal) backs `driver_monitor_process`'s `ERL_DRV_MONITOR_NOT_ALIVE` with `is_alive(pid) -> Option<bool>`, `try_borrow`-based (it runs *from* a callback) and republished each round by `refresh_liveness`; `None` ⇒ install the monitor, never a fabricated `NotAlive`.
A driver port's reply is one `PortNotification::Data` per `driver_output*` call from the **port-task round** (`Port::take_input_notifications`), never a pre-round harvest off `beam_io`'s flat `Port::drain_input` view, which joins a `driver_output2` call's header and body; `has_driver_control` gates `port_control`, which forwards the verb **verbatim** to `beam_io`.
`is_empty()` counts **ports only** (`system_info(port_count)`); `has_nothing_to_poll()` is **nothing-pending** — no live port, no harvested-but-unreported `pending_events`, no owed `'EXIT'`/`'DOWN'`, no armed `tty_select/2` interest, no fired-undrained `os:set_signal/2` self-pipe; an armed-but-idle `handle` disposition is **not** pending work.
`pump` drains retained events, queued driver output/terms, due exit statuses and handled signals, then — only on a real wake source (a live port or an armed `tty_select/2` interest) — polls in `PORT_POLL_SLICE` slices clamped by the earliest driver deadline, returning early only **after** `take_signals` and `report_pending_closes`; a round ends with the due `exit_status`s then the line channel (`take_eof` → `flush_linebuf`, then `take_line_notifications`), a reaped child's `{exit_status,S}` preceding its trailing partial line via `PortMeta::held_lines` (once, at the status or `EXIT_STATUS_FLUSH_GRACE`).
A port-task round is **destructive** and goes through `run_port_tasks`/`handle_port_events`, which snapshot each live port's incoming monitors first (`capture_round_monitors`), because the round both reaps a driver-failed port and mints its `PortNotification::Closed` report — and minting retires the port **number** with its owner, links and monitors; `write_command`'s round folds through the same `fold_notifications` for a later `pump` to report, and `close` purges a closed port's buffer so a **reused** number inherits nothing.
`PortRegistry::command` drains the failure/completion channels **before** folding the round's notifications, as `pump` does, so a failing callback's read renders from its snapshotted recipient; `drain_pending_events` reports a retained `PortEvent::Data` even for a port that has left the runtime, and drops a read with no recoverable recipient.
`SpawnDriver` is the **single** OS-child implementation; this crate owns only `open_port/2`'s decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`.
`deliver_port_messages` delivers into the **owning** mailbox through `deliver_in_table` so a blocked receiver wakes: data/exit-status → `owner`, a driver term → `to.unwrap_or(owner)`, `{select,Handle,Ref,ready_input}` → the arming process, `{notify,Name}` (sender `system`) → `whereis(erl_signal_server)`; `close` calls `notify_port_exit(…, Closed)` **before** `registry.close(...)`.
**Read path**: one `{Port,{data,Data}}` per driver read (`PortEvent::Data { port, read, stream, shape, owner }` → `port_data_message_shaped` → `make_stream_payload`) out of the read's own `(hbuf,hlen,buf,len)` split (`beam_io`'s `ReadMessage { header, body }`, the C's `driver_output2` operands): on `[binary]` a body-only read is the bare binary (to `READ_CHUNK`, 64 KiB, on the pointer-stable `eval_heap`), both halves the improper `[H1..Hh|<<Body>>]`, `body: None` the proper `[H1..Hh]`, a header-less empty read `[]`; `[list]` is `ReadMessage::flattened()`; `StreamShape::DriverOutput` marks a built-in driver port and decides only a **header-less** read (Known Issues).
Every port message builder interns through `port.rs`'s `intern_reuse` — look the name up on the shared table first, reach `atoms_mut()` only for a genuine miss — so a live NIF-library or `{spawn_driver, Name}` host holding the atom-table lease cannot make each delivered message deep-clone the shared table (`tests.rs::a_port_message_build_does_not_clone_the_shared_atom_table_while_a_lease_is_held`).
**A driver port holds no atom-table handle between rounds**: its view is a *lease* on the `driver::DriverAtoms` record the registry shares with the host, taken for a **drive window** only — `PortRegistry::open_driver_atom_view(atoms)` adopts it before driver code runs, `PortRegistry::close_driver_atom_view` releases it the moment that code returns (re-entrant via a depth counter, so a nested close cannot release early), and between windows the view is `None`.
Every site that can run a driver callback opens the window (`deliver_port_messages`/`drain_port_messages` around `pump`, `RuntimePorts::{command, command_with_data, port_control, close_port}`, `open_port`'s `register`, `retire_peer_closed_port`, `RuntimeNifServices::port_command`, the native `erlang:port_control/3` floor), so between rounds no driver port causes an `Rc::make_mut` copy on anybody's intern while inside a window no intern can occur; the commit step tests `has_pending_driver_atoms()` **before** reaching `atoms_mut()`, so the transient view is dropped first and the shared table takes its append path.
**A driver-port `register` MUST run inside an open window** — `DriverPort::new` adopts the table at construction (the driver's `start` callback runs inside `register`) and only `close_driver_atom_view` releases it, so a `register` off the window path would leave the view on the port until the *next* window close and re-arm the whole-table copy for every intern in between (`tests.rs::a_driver_atom_commit_does_not_deep_copy_the_shared_atom_table`).
The three transient `RuntimePorts` leases (`busy_wait.rs`'s `attempt` and `close_port`, `native/port.rs`'s `port_info_pairs`) are lookup-only, `RuntimePorts` being a stack local at every production call site (`tests.rs::a_port_open_command_close_round_does_not_clone_the_shared_atom_table`).
**`{packet,N}`** (`N` ∈ `{1,2,4}`, `packet.rs`) frames the spawn/spawn_executable/fd family only: `write_command` prepends the big-endian header (`PacketFraming::frame_output`), `fold_notifications` reassembles whole packets (`PacketFraming::push`) — one message per packet, header stripped, counters on **payload** bytes; a driver port carries `PortMeta::packet = None`, a partial packet at end of stream is **dropped**, and a `{packet,1}`/`{packet,2}` packet past 255/65 535 B is a typed `unsupported` where the C kills the port with `einval`.
**`line`/`{line,N}`** delivers `{eol,Data}`/`{noeol,Data}` through `port_line_message` — an **empty payload is a real frame** (`{eol,[]}`); a frame's header is the read prefix that produced it (`stage_line_frames` stamps it on **every** frame the call produced), but **only the frame's content bytes are charged** to `port_info(P,input)`/`statistics(io)`, so a line-mode port **under**-counts by its headers and separators where the C charges `hlen + len` **once per `driver_output*` call** (Handoffs).
**The read path never blocks**: stdout is `O_NONBLOCK`ed and registered `Interest::READABLE`, `SpawnDriver::ready_input` looping `read` in `READ_CHUNK` until `EAGAIN`; the boot's `inet_gethost` child is that shape, carries no `exit_status` ⇒ never status-polled, and its live-but-idle port keeps `has_nothing_to_poll()` false; its **stderr is inherited** by default, `stderr_to_stdout` duplicating fd 1 onto 2.
### `port/completion.rs` — the driver→owner **completion channel** (A.4)
`beam_io::PortCompletion` becomes `{inet_reply,…}`/`{inet_async,…}`, which unblocks `prim_inet:send/4` and its siblings in `receive {inet_reply,S,Status,Mref}`; `PortRegistry::drain_io_completions(fallback)` is the one drain entry point and `adopt_accepted` the runtime's half of the C's `tcp_inet_copy` (`inet_drv.c:11795`) — [`driver/CONTEXT.md`](driver/CONTEXT.md).
### `port/inet_opts.rs` — the per-port inet option mirror (A.4)
`prim_inet:open/6` opens every inet port with `[binary]` alone and applies every other option through `setopts/2`, so this node mirrors the driver's `{mode,…}`/`{active,…}`/`{exit_on_close,…}` out of each accepted `port_control/3` argument; `PortRegistry::data_mode(id, fallback)` is the one consuming accessor the delivery renderers read.
`PortRegistry::drain_active_spends` takes `beam_io::PortRegistry::take_active_spends` (destructive — every spend consumed once) and applies each to the mirror (`InetOptions::spend_active` ⇒ passive) **before** `collect_peer_closes`'s gate at every drive point, so that gate never reads a mode a same-round spend invalidated; `PortInetOptions::active_state` is the fallback half behind `beam_io::PortRegistry::active_mode`.
### `port/active_input.rs` — the `{active, …}` input channel (A.4)
An `{active, true|once|N}` socket parks no input in the port's byte queue, so the driver sends the owner `{tcp,S,Data}`/`{udp,S,IP,Port,Data}`/`{tcp_passive,S}`/`{udp_passive,S}`; the staged `PortEvent::ActiveInput` rides `pending_events`, so `has_nothing_to_poll` sees it — [`driver/CONTEXT.md`](driver/CONTEXT.md).
### `port/peer_closed.rs` — the peer-close channel (`{tcp_closed, Port}`)
`beam_io::PortRegistry::port_closed(id)` is a latched, sticky observation that a connected socket's peer has closed; `PeerCloseKind::Tcp` is the only kind (the C has no `udp_closed`), and retirement is the C's `driver_exit`, not `port_close/1`.
The gate's `{active,…}` half is the **live** driver state, not the last `setopts`: `inet_active` reads `beam_io::PortRegistry::active_mode` first, so a socket whose `{active,once}`/`{active,N}` grant a delivery spent is passive there and its close is silent (`inet_drv.c:12819-12832`), while the observation keeps its latch so a later active `setopts` re-fires it once.
### `port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`
A close owes a **trapping** link its `{'EXIT',Port,Reason}` and every watcher its `{'DOWN',Ref,port,Port,Reason}`, `'EXIT'` before `'DOWN'`; the reason rides the signal, so one close's two signals can never disagree — [`driver/CONTEXT.md`](driver/CONTEXT.md).
### `port/failure.rs` — the driver-failure channel's runtime half (A.4)
A driver closes its **own** port through the C's `driver_failure*` family or `driver_exit` (`io.c:7196-7278`) — a **port-closing request**, not a return value — latched by `beam_io` inside the callback; `signal_reason` is the one reason rule and `fail_port` publishes the resulting `'EXIT'`/`'DOWN'` into the deliverable queue — [`driver/CONTEXT.md`](driver/CONTEXT.md).
### `port/ops.rs` — the port **table** operations (`port_set_data/2`, the name registry, `port_connect/2`)
`PortExtras` (`pub(crate)`, keyed by **port number** like `meta`) holds what `open_port/2` does *not* establish: `data` (the C's `prt->data`; absent = never set, rendered `undefined`), `names` and `links` (`ERTS_P_LINKS(prt)`), the `inet_opts` mirror, the `peer_closed` latches and the owner-`'EXIT'` suppression mark; `forget_port(number)` drops all of them from `PortRegistry::close`, the single place a port leaves the runtime.
Accessors: `set_port_data`/`port_data` (`badarg` for a port the registry does not hold), the name entries, `resolve_port` (the C's `lookup_port`: an internal port term **or** an atom naming a registered port), `extra_links` (`None` = the only link is the owner), `connect_port` (the C's `set_port_connected`, `io.c:2330-2419`: **adds** a link and moves `PortMeta::owner`, the one field every delivery site reads) and `suppress_owner_exit`.
The free `connect(ports, table, port, target)` is `erlang:port_connect/2`'s whole body, shared by the floor's `erlang:` spelling and the `RuntimeHooks` bridge's `erts_internal:` one (`erl_bif_port.c:435-470`): resolve the port, require an internal **live** pid target (a dead one ⇒ `badarg`), then transfer; the `ProcessHook` bridge serves the name registry over the **process** table first and the port registry second (so `register(init, Port)` is `badarg`), and `port_get_data/1` of a fresh port is `undefined`.
### `port/info_extras.rs` — the derived `port_info/2` items
`queue_size` is the C's `erts_port_ioq_size(prt)` (`erl_bif_info.c:3868-3874`), the driver's own staging area in both directions; `beam_io::Port` holds exactly those two queues, so the answer is `input_len() + output_len()` (a fresh port `0`).
`memory` is the `am_memory` arm (`:3838-3860`): link nodes, monitor records, the `port_set_data/2` heap and the line buffer, **deliberately excluding the `Port` struct itself**, with `link_size`/`monitor_size` **assigning** rather than accumulating, so N links report one link node and N watchers one monitor half; its constants are the C struct sizes on a 64-bit build (`LINEBUF_INITIAL` 100).
`monitored_by` is the `am_monitored_by` arm (`:3735-3765`) read from the port table's incoming monitor list — the authority `erlang:monitor(port, Port)` writes; `locking` is `port_level` for a `spawn`/`spawn_executable`/`fd` port (their drivers set `ERL_DRV_FLAG_USE_PORT_LOCKING`, `sys_drivers.c:251`) and the driver's own level for a `{spawn_driver,Name}` port; `parallelism` is truthfully `false`.
`awaits_port_reply` and its read-side twin `awaits_async_completion` (`beam_io::Driver::has_pending_async` over the live ports) are defined here too (*The poll budget*); `PortRegistry::info` chains all of these after the seven `/1` items.
### `port/driver.rs` and driver-emitted terms → [`driver/CONTEXT.md`](driver/CONTEXT.md)
The driver C-ABI host itself, and the per-port `TermQueue` a driver-emitted term (`erl_drv_output_term`/`erl_drv_send_term`) lands in (its emptying in `stop`/`Drop`, its two destination forms), are in [`driver/CONTEXT.md`](driver/CONTEXT.md).
### `port/async_ready.rs` — the `driver_async` pool's delivery half
`AsyncReady` is one shared `Rc` cell between the async-job pool, every driver port's host/`DriverPortAdapter` (which performs the real `ready_async` delivery at its own drive point) and the `PortRegistry`, because the pool is drained on the port round (which holds no driver) while `ready_async` needs the loaded `DriverLibrary`; `pool_is_busy` substitutes for the C's `erts_notify_check_async_ready_queue` wake-up.
### `port/watch.rs` — the `os:set_signal/2` delivery half (`pub(crate)`)
One `thread_local!` `FACILITY: RefCell<FacilitySlot>` holds the facility the first `os:set_signal/2` creates and production **never drops** (a per-call one would restore the prior dispositions at the end of the call); `HANDLED` mirrors which signals hold `Disposition::Handle`, so `is_pollable` answers without a syscall.
`SignalWatch{token, fd}` registers the facility's `read_fd()` under `SIGNAL_KEY` (`u64::MAX - 1`) on the first round after a `handle` disposition; `is_pollable()` is the **poll-set** half and `has_pending_signal()` the **pending-work** half (a non-destructive zero-timeout probe, whose byte is the *whether* and the facility's private bitmask the *what*); `crate::context::signal` owns the oracle answer surface (`{ok, OldDisposition}`/`badarg`, the kernel-only `sigstop` rule) and delegates the facility here, the message being `signal_notify_message(name)` → `(from, {notify, Name})` with `subject` interned as `system`.
### `port/select.rs` — the runtime's ONE select mechanism (A.3 `enif_select` + A.7 `prim_tty:tty_select/2`)
`select.rs` owns the runtime's **one** readiness store; its arming, payload/event, key-reservation and object-reference rules are in [`select/CONTEXT.md`](select/CONTEXT.md).
### `erlang:port_command/2,3` and the port **busy state** (A.4)
The decision table lives in **`beam_io`'s `Port::command`** (`beam_io/src/port.rs:428`), reached through `PortRegistry::port_command_with` (`beam_io/src/registry.rs:470`): `PortCommandOutcome::{Done,Busy}` from `PortCommandOptions::{with_force,with_nosuspend}` and the driver's own capability/state.
| port | options | outcome / answer | C |
|---|---|---|---|
| any | `[force]`, driver **without** `SOFT_BUSY` | `Err` = `error:notsup`, **before any output is written** | `erl_bif_port.c:195-198` |
| idle | any (incl. `[force]` with `SOFT_BUSY`) | `Done` — queued, an `OUTPUT` task scheduled; the oracle's `true` | `io.c:1763` |
| busy | `[force]` + `SOFT_BUSY` | `Done` — the busy state is bypassed | `io.c:1731`, `:1763` |
| busy | plain or `[nosuspend]` | `Busy` with **nothing queued**; `[nosuspend]` ⇒ `false`, a plain command is waited out and re-issued where its caller owns a scheduler pass (`busy_wait`) | `io.c:1763-1769` |
The run order is fixed: this crate's **pre-conversion** gate first (`PortRegistry::command_with_data` → `decide_before_data`: the live-port `badarg`, the `[force]`/`SOFT_BUSY` refusal, the busy answer), and only for an accepted command `beam_io`'s own table — so `beam_io` is the decision and this crate holds the C's cheaper pre-checks, never a second table.
The `[force]` refusal is a property of the driver's **capability flag word, never of the busy state**, so it is `notsup` whether or not the port is busy; a `Busy` answer leaves the bytes out of the output queue because the oracle suspends the caller and re-issues the command when the driver clears the state (`io.c:5265`); the two busy cells sit in `PortMeta::driver_busy` (a `driver::BusyFlag`).
The `SOFT_BUSY` bit reaches `PortRegistry::soft_busy` from whoever owns it — a loaded `ErlDrvEntry::driver_flags` (written onto the seized handle by `DriverPortAdapter::load`) or a built-in driver's `Driver::flags()` (`open_port`'s `{spawn_driver, Name}` arm stamps it while the driver is still in hand) — **never a driver-name test**, which is why `[force]` on `tcp_inet` is the oracle's `true` (`inet_drv.c:1374`) and on `udp_inet`/`ram_file_drv` its `error:notsup`, pinned by `soft_busy_builtin_tests.rs`; a `spawn`/`spawn_executable`/`fd` port has no flag word, so `[force]` is `notsup`.
The runtime's own `port_command` (`../native/port.rs`) runs that gate and then the accepted command's round/accounting; a **plain** command on a busy port goes through `busy_wait::issue` — the C's `erts_suspend` + `ERTS_BIF_YIELD3` re-run, taken on the routes that own the pass.
### `port/busy_wait.rs` — the C's suspend-and-retry for a busy port (A.4)
`issue(runtime, may_pump, owner, id, make_data, options) -> Result<PortWrite>` is the whole `erts_port_output` outcome matrix for `erlang:port_command/2,3` and `erlang:send/2,3`: one `attempt` through `RuntimePorts::command_with_data`, then `Done` ⇒ `PortWrite::Written`, `Busy` + `[nosuspend]` ⇒ `PortWrite::Suspended`, while `Busy` plain enters `wait_until_idle` and re-issues once the port reports idle; `make_data` is a `Fn` because a busy port issues the command **twice**, the C converting the iolist only on the attempt it accepts (`io.c:1749-1754`).
`wait_until_idle`/`IdleWait::{Idle,Gone,Deadline,Park}` re-tests the port state first (an already-idle or already-gone port costs no round), then runs one bounded `Runtime::pump_scheduler` step — the pass carrying the **port round** (where a driver's `output`/`ready_output`/`timeout` callbacks clear the bit), the **run queue** and the **timer heap** — so one iteration always progresses or sleeps, never a busy-spin.
`BUSY_PORT_DEADLINE` (**5 s**) and `BUSY_PORT_PUMP_SLICES` (**64**) bound the wait where the C is unbounded, a single-threaded runtime that owns its own pass otherwise hanging the executable; the wait start is `Runtime::note_busy_port_wait`'s, keyed **`(pid, port)`** and idempotent, so a caller parked and resumed repeatedly still expires at its first attempt's deadline.
A caller that may not re-enter the scheduler (a compiled process inside a slice) **parks** instead: `issue` answers `PortWrite::Parked`, `RuntimeContext::request_suspend` makes it `BifOutcome::Suspend`, and the runner re-enqueues the process so the BIF re-executes on resume (the same deadline covers that route).
The typed gaps are `DEADLINE_REASON` (still busy at the deadline), `BUSY_AGAIN_REASON` (busy again right after an idle verdict — unreachable single-threaded, reported rather than asserted) and `NO_PUMP_REASON` (the **`send`/inline-`!`** route, whose instruction cannot consume a suspend latch); `busy_suspend_tests.rs` pins the in-process park → pump → resume loop with the fixture driver's write counter (one write, never two).
`send_message_to_port` is the **send** route: `classify_message` decomposes the message exactly as `erts_port_command` (`io.c:3981-4013`) — `{InternalPid, {command, Data}}` ⇒ `PortMessage::Command`, `{InternalPid, close}` ⇒ `PortMessage::Close`, everything else ⇒ `PortMessage::Drop` — and `PortSend::{Write(_), Dropped}` keeps the C's silent-success verdicts distinct from a write; a `{Pid, close}` really closes the port, `{Pid, {connect, NewPid}}` stays `Drop` (Handoffs).
### The nested port wait — `PORT_EVENT_DEADLINE` (A.4)
A passive `gen_tcp:recv/2,3`, a `gen_tcp:accept/1,2` and a `gen_udp:recv/2,3` are not control-op answers: `prim_inet`'s `recv0/3`/`accept0/3` issue the operation, get an id back, and `receive` the driver's `{inet_async, Port, Id, Result}`, which only a later port round can produce.
A caller that is not a scheduled process — the nested `-eval`/`-s`/`-run`/boot route — sits that wait out itself (`../context/pump.rs::wait_for_port_event`, and the `-eval` bare receive's port branch in `../eval/mod.rs`), over `Runtime::pump_scheduler` so each round really blocks in the poller; it is entered when `PortRegistry::awaits_async_completion` reports a queued operation.
`PORT_EVENT_DEADLINE` (5 s) bounds one window of **no** progress, `restart_port_event_window` re-arms it on a round that made progress, and `PORT_EVENT_DEADLINE_REASON` is the typed gap a port that never answers reports (the C suspends the process for ever); a round is progress when the pass ran a slice, **delivered a port message** (`Runtime::port_events_delivered`, the signal the other two are blind to, a completion landing in the mailbox in a round that ran no slice) or no live port holds an asynchronous operation any more.
`awaits_async_completion` is **accept-inclusive** (`has_pending_async` counts a listening socket's standing accept interest, and must: this wait is entered *for* an `accept`), so it reads as "someone could still answer me", never "an answer is owed"; nothing is armed, latched or consumed by the wait — the operation was queued **once** by the machine's own control call and a resume only re-scans the mailbox, so a re-park never burns a second id (a second `TCP_REQ_RECV` would be `ealready`).
Oracle-agreeing on the nested route: `gen_tcp:accept/1,2` ⇒ `{ok, Port}`; a passive `gen_tcp:recv/2,3` whose data arrives **after** the read is armed ⇒ `{ok, Data}` (accepted and connect-side); `gen_tcp:shutdown/2` ⇒ `ok`; `gen_tcp:connect/2,3,4` + a passive receive against an external server ⇒ `{ok, Data}`; with no client at all, `accept` ends `rc=3` with the typed `unsupported: port event: … within the 5 s bound`, a bounded diagnostic rather than a hang.
Residual, `beam_io`-owned: a passive read on an **accepted** socket whose data was buffered **before** the read op was armed produces no port event, so the wait ends at the peer's close and answers `{error,closed}` where the oracle answers `{ok, Data}` (a connect-side socket with the same data does answer `{ok, Data}`, so the loss is `TcpInetDriver::from_accepted`'s read-interest registration, where the C reads synchronously at control time, `inet_drv.c:12309`); a send-then-close peer also loses its buffered data to the driver's destructive `latch_peer_close`.
## Constraints
- The `SignalFacility` is a `thread_local` (not a `Runtime` field) because the runtime is single-threaded (`!Send`), so the slot *is* the process's one facility.
- Never a fabricated success: failures are typed `BeamError`s and an unservable state/lifecycle returns the C's own failure code.
- A payload is credited where it is harvested and the queue it came from is empty afterwards (`fold_notifications` + `drain_pending_events` for the data lane, `PortNotification::Closed` for the signal lane).

## The poll budget a pass hands this layer (measured; figures in [`PERF.md`](../../PERF.md), [`STARTUP_COST.md`](../../STARTUP_COST.md))
The largest wall-clock cost this layer can impose on a CLI start-up is **not work** but the *blocking budget* a zero-slice scheduler pass hands `PortRegistry::pump`: `PORT_POLL_SLICE` is *both* the poller's inner clamp and the `port_timeout` an empty pass passes in (`../runtime/scheduler.rs::scheduler_pass`), so a live-but-idle port costs a whole `epoll_wait` per such pass.
**The rule for any future change**: a pass may block on the poller only when something can answer — a port with a reply in flight (`PortRegistry::awaits_port_reply`: `output > input` over the `port_info(Port, input)`/`output` counters), a driver holding one of its own asynchronous operations (`awaits_async_completion`, `beam_io::PortRegistry::next_deadline`) or an armed `tty_select/2` interest; blocking merely because a port is *live* costs a slice per pass for ever.
The budget can only be **shortened, never zeroed** — that poll resolves the kernel's `inet_gethost` round trip — so a `TimerWait::ImminentWithin(_)` pass (only the boot drive uses it) gets `Duration::ZERO` when **neither** predicate holds, and stays patient when the table cannot be borrowed.
Pins: `tests.rs::a_port_awaits_a_reply_exactly_while_a_written_command_is_unanswered`, `../runtime/scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing`; re-measure with deterministic counters (non-zero `port_timeout` rounds per run, `strace -f -c -w`'s `epoll_wait` total, the `.beam` openat and `inet_gethost` `execve` counts), never timings — figures in [`PERF.md`](../../PERF.md), [`STARTUP_COST.md`](../../STARTUP_COST.md).

## Known divergence from the oracle: no child-exit auto-close
- ERTS **auto-closes** a `{spawn, Program}` port once its child exits: after the reap, `erlang:port_info(P)` is `undefined`, `lists:member(P, erlang:ports())` is `false`, `erlang:port_close(P)` raises `error:badarg`.
- This runtime does **not**: `PortMeta.notify_exit` is only set by the `exit_status` option, so nothing reaps or removes the port until an explicit `port_close` — which kills and reaps, `meta.remove`s, forgets the extras and releases the id, synchronously.
- The child is reaped at exactly two points, both **`SIGKILL`ing it then blocking in `wait`**: `PortRegistry::close` → `Driver::stop` (`drivers/spawn.rs:1139-1154`) → `kill_and_reap` (`:1225-1246`), and — for a port nobody closed — the driver's `Drop` (`:1165-1175`) when the `Runtime` drops; the `Runtime` in `cli::run`'s `source` **is** dropped on the `halt()` path (`cli::run` returns before `main`'s `std::process::exit`, `src/main.rs:29`), so a `wait4` after the last poll round belongs to that teardown.
- The corpus **sidesteps** the divergence (the five `driver/port_*` close cases each open a child alive until the explicit `port_close/1`), so the gate's 0-mismatch verdict is consistent with it.
- **An abnormal abort can make the boot's `inet_gethost` helper signal the whole process group**: a `SIGKILL` mid-request (the `halt()` teardown above, or a failed boot such as the load-induced `process blocked` exit 3) drives the installed OTP 29.1.1 helper's `fatal(…)` path into `kill_all_workers()`, which walks the worker table inherited across `fork()`, and a slot with `pid == 0` makes that a group-wide `kill(0, SIGUSR1)`; a clean `halt()` kills each worker by pid and never signals the group, and the in-tree 30.0-rc0 source guards the child (`close_all_worker_fds(); … = 0;`, `inet_gethost.c:1670-1672`) where the installed 29.1.1 binary does not.
- Consequence for testing: a suite that spawns `beam_rt` can die with `signal: 10` (test binary, `cargo` and the invoking shell at once) — an environment artifact of the abnormal path, not a runtime failure; wrap a long run in `setsid` and retry.
## Handoffs (owned by OTHER nodes)
- **`beam_io` — `driver_as` is the only way to a concrete driver.** `core::any::Any` is a supertrait of `Driver` (`beam_io/src/driver.rs:544`), with one downcast path — the inherent `dyn Driver::downcast_ref::<T>()` (`:870`, no `as_any` method) — surfaced **read-only** as `Port::driver_as::<T>()` (`beam_io/src/port.rs:223`) and `PortRegistry::driver_as::<T>(PortId) -> Option<&T>` (`beam_io/src/registry.rs:224`), deliberately with no `&mut` form (the port-task round drives the driver); `adopt_accepted` is its one consumer (`driver_as::<TcpInetDriver>(listener)` → `TcpInetDriver::from_accepted(fd, listener)` → `register`, the C's `tcp_inet_copy`, so the inherited block arrives by struct copy).
- **`beam_io` — the mode accessor and the completion recipient.** The driver exposes **no mode accessor**, so `PortInetOptions::mode` — read through `PortRegistry::data_mode` — stays the only source for the delivery renderers and a post-`open_port/2` `{mode,…}` cannot re-render an `{inet_async,…}` payload; a `driver_caller` on the frozen seam would address a completion to the C's `desc->caller` instead of `PortMeta::owner`.
- **`beam_io`** — two further asks: `ERL_DRV_FLAG_USE_PORT_LOCKING` must cross the seam (`DriverFlags` keeps only `SOFT_BUSY`), and a **line-mode** read must name its producing call (or stamp the header on the **first** frame only) so a frame's prefix is charged once, as the C charges `hlen + len` per call.
- **`beam_process`** — no seam needed for the marking (its single exit observer stays `EtsExitObserver`), **but** a tagged port monitor's `'DOWN'` needs that crate to expose the monitor's `{tag, Tag}`; `ProcessTable::port_closed`'s `PortTable::close`-first order is what keeps the exit signalling out of that crate.
