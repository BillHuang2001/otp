# `beam_rt::port` — the runtime's A.4 port layer (`port.rs` provider · `driver.rs` host · `ops.rs` tables)
## Intent
The runtime side of contract A.4.
`port.rs` is the **port provider**: `open_port/2`'s `Name`/`Options` decoding, the `PortRegistry`, the port-task round, the `{Port,{data,..}}` pump behind `beam_io`.
Each child owns one post-`open_port/2` fact over the one `PortExtras` side table: `ops.rs` the table-entry operations, `exit.rs` the `'EXIT'`/`'DOWN'` a close owes, `failure.rs` the driver's own close request, `info_extras.rs` the derived `port_info/2` items.
Four are driver→owner channels: `completion.rs` (`{inet_reply,…}`/`{inet_async,…}`, what makes `prim_inet:send/4` return), `active_input.rs` (`{tcp,…}`/`{udp,…}`/`{tcp_passive,…}`), `peer_closed.rs` (`{tcp_closed,S}`), `inet_opts.rs` (the option mirror an accepted socket inherits).
`driver.rs` is this runtime's **own** driver C-ABI host for `{spawn_driver,Name}` ports over `beam_abi`'s frozen `DriverHost` seam; `watch.rs`/`tty.rs` deliver `os:set_signal/2` and `prim_tty:tty_select/2`'s `enif_select` interest.
**Separate** from `beam_io`'s own host layer (`beam_io::abi`), so end-to-end `.so`-driver traffic goes through this tree.
## API Surface
### `port.rs` — the `PortHook` provider (A.4)
Public: `PORT_INFO_ATOMS`, `PortName{Spawn,SpawnExecutable,Fd,SpawnDriver,SpawnDriverBuiltin}`, `StreamType{List,Binary}` (list default), `IoCounters` (behind `erlang:statistics(io)`), `PortEvent`, `RuntimePorts` — the `beam_bifs::PortHook` impl (`open_port/2`, `port_close/1`, `port_info/1,2`) over `Rc<RefCell<PortRegistry>>`, the shared `Rc<AtomTable>` and the owning `ProcessId`.
`PortEvent::{Data,Line,Exited,Term,Completion,ActiveInput,Signal,Select}`; `PortEvent::port()` is the **one** port-bearing roster — `Data`/`Line`/`Exited`/`Term` → `Some`, the rest → `None`.
`PortRegistry`: `new()` (anchors the `driver_*` codegen unit, builds the **one** `DriverRegistry::with_static_spawn_drivers`); queries `is_live`, `port_control`, `has_driver_control`, `is_busy`/`soft_busy`, `is_empty`/`has_nothing_to_poll`/`awaits_port_reply`, `has_pending_driver_atoms`, `io_counters`, `ids`; commands `write_command`, `close`, `create_static_spawn_driver`, `refresh_liveness`, `arm_tty_select`; private pass `register`, `pump(timeout) -> Vec<PortEvent>`, the `take_*` harvests, the line helpers, `info`, `fold_notifications`, `drain_pending_events`, `report_pending_closes`, `drain_io_completions`, `closed_snapshot`.
`ProcessLiveness` (crate-internal) is the observation behind `driver_monitor_process`'s `ERL_DRV_MONITOR_NOT_ALIVE`: `is_alive(pid) -> Option<bool>`, `try_borrow`-based because it runs *from* a callback, republished each round by `refresh_liveness(&ProcessTable)`; `None` ⇒ install the monitor, never a fabricated `NotAlive`.
`PortName::SpawnDriver` resolves against `create_static_spawn_driver` **before** any `dlopen` (`io.c:599-628`), membership being `driver::is_static_driver` over `beam_io`'s `STATIC_SPAWN_DRIVERS` (the C's `driver_tab.c`) — **not** "a factory registered here", so `fd`/`efile` and an invented name take the `dlopen` route to the oracle's `badarg`; a factory failure surfaces its typed error.
`PortName::bytes_from_driver_output`: a driver port's reply is one `PortNotification::Data` per `driver_output*` call from the **port-task round** (`Port::take_input_notifications`), never a pre-round harvest off `beam_io`'s flat queue; `PortMeta::has_driver_control` gates `port_control`, whose `PortRegistry::port_control(id, op, arg)` forwards the verb **verbatim** to `beam_io` (`beam_io/src/registry.rs:357`, which reserves `"close"`).
`is_empty()` counts **ports only** (`system_info(port_count)`); `has_nothing_to_poll()` is **nothing-pending** — no live port, no harvested-but-unreported `pending_events`, no owed `'EXIT'`/`'DOWN'` (`pending_port_signals`), no armed `tty_select/2` interest, no fired-undrained `os:set_signal/2` self-pipe; an **armed but idle** `handle` disposition is **not** pending work.
`pump` drains retained events, queued driver output/terms, due exit statuses and handled signals, then — only on a real wake source (a live port or an armed `tty_select/2` interest) — polls in `PORT_POLL_SLICE` (25 ms) slices clamped by the earliest driver deadline, returning early only **after** `take_signals` and `report_pending_closes`; each round ends with the due `exit_status`s then the line channel (`take_eof` → `Port::flush_linebuf`, the C's `driver_eof`, then `take_line_notifications`), a reaped child's `{exit_status,S}` preceding its trailing partial line through `hold_or_report_line`'s `PortMeta::held_lines` (FIFO, once, when the status is taken or `EXIT_STATUS_FLUSH_GRACE` = 1 s expires, `sys_drivers.c:1230-1252`).
A port-task round is **destructive**, so `write_command`'s round (a **built-in** driver answering from that `output` call) folds through the same `fold_notifications` for the next `pump` to report via `drain_pending_events`; `close` purges a closed port's buffer, so a **reused** number inherits nothing.
`SpawnDriver` is the **single** OS-child implementation; this crate owns only `open_port/2`'s decoding into a term-free `SpawnSpec`/`SpawnOptions`, plus `PortMeta`.
`deliver_port_messages` delivers into the **owning** mailbox through `deliver_in_table`, so a blocked receiver wakes: data/exit-status → `owner`, a driver term → `to.unwrap_or(owner)`, `{select,Handle,Ref,ready_input}` → the arming process, `{notify,Name}` (sender `system`) → `whereis(erl_signal_server)`; `close` calls `notify_port_exit(…, Closed)` **before** `registry.close(...)`.
**Read path**: one `{Port,{data,Data}}` per driver read (`PortEvent::Data { port, read, stream, shape, owner }` → `RuntimeContext::port_data_message_shaped` → `make_stream_payload`) out of the read's own `hbuf`/`buf` split (`beam_io`'s `ReadMessage { header, body }`, the C's `driver_output2` operands): on `[binary]` a body-only read is the bare binary (to `READ_CHUNK`, 64 KiB, on the pointer-stable `eval_heap`), both halves the improper `[H1..Hh|<<Body>>]`, `body: None` the proper `[H1..Hh]`, a header-less empty read `[]`; `[list]` is `ReadMessage::flattened()`; `StreamShape::DriverOutput` marks a built-in driver port (Known Issues).
**`{packet,N}`** (`N` ∈ `{1,2,4}`, `packet.rs`) frames the spawn/spawn_executable/fd family only: `write_command` prepends the big-endian header (`PacketFraming::frame_output`), `fold_notifications` reassembles whole packets (`PacketFraming::push`) — one message per packet, header stripped, counters on **payload** bytes; a driver port carries `PortMeta::packet = None`, a partial packet at end of stream is **dropped**, and `{packet,1}` past 255 B / `{packet,2}` past 65535 is a typed `unsupported` where the C kills the port with `einval`.
**`line`/`{line,N}`** delivers through `port_line_message` (`io.c:3454`) as `{eol,Data}`/`{noeol,Data}` — an **empty payload is a real frame** (`{eol,[]}`); a frame's header is the read prefix that produced it, charged as its content bytes where the C counts `hlen + len` once (Handoffs).
**The read path never blocks**: stdout is `O_NONBLOCK`ed (`beam_io/src/drivers/spawn.rs:791-795`; `{fd,N}` at `:730`), registered `Interest::READABLE` (`:1088-1090`), `SpawnDriver::ready_input` (`:1105-1137`) looping `read` in `READ_CHUNK` (`:179`) until `EAGAIN` (`packet.rs:192-194`). The boot's `inet_gethost` child is that shape (`inet_gethost_native.erl:416`), carries no `exit_status` ⇒ never status-polled, and its live-but-idle port keeps `has_nothing_to_poll()` false (*Measured*). The child's **stderr is inherited** by default; `stderr_to_stdout` duplicates fd 1 onto 2 (`sys/unix/sys_drivers.c:500`).
### `port/completion.rs` — the driver→owner **completion channel** (A.4)
A socket driver cannot answer a `port_command/2` (nor a queued async op) in a control op's return value — the C *sends a message* — so `completion.rs` turns `beam_io::PortCompletion` (`beam_io/src/completion.rs:289`) into `InetReply` → `{inet_reply,…}` / `InetAsync` → `{inet_async,…}`, which is what unblocks `prim_inet:send/4` and its siblings in `receive {inet_reply,S,Status,Mref}`.
`CompletionPacket { port, owner, stream, event }` (`:105`) is term-free and resolves recipient and stream at **drain** time (a completion staged around a teardown outlives its `PortMeta`, the C's `async_error_am_all`); `ClosedPortSnapshot { port, owner, stream, line }` (`:129`) is taken by `close` **before** `meta.remove` and consulted only for the number closed; `PortEvent::Completion { packet }` rides `pending_events`, so `has_nothing_to_poll` covers it and both routes match exhaustively (`Runtime::deliver_port_messages`; `RuntimeContext::poll_port_messages`, the latter taking only a completion addressed to itself).
**One drain entry point**: `PortRegistry::drain_io_completions(fallback)` (`:175`) composes `drain_failures()` **first** (the driver-closed-its-own-port channel) and sweeps every snapshot that drain answered plus the caller's `fallback`, so an operation a teardown answered through `async_error_am_all` is attributed through the closed port's snapshot and the failure channel needs no drain row.

| `close`, after `registry.close` | `:1718` | the teardown's `async_error_am_all`, harvested into a registry-owned queue |
**Rendering** — `RuntimeContext::{completion_message, inet_reply_message, inet_async_message, decode_caller_tag}` on the pointer-stable `-eval` arena after the registry borrow drops, every atom interned in the runtime's **one shared** table; `Id` is the 16-bit id the control-op reply handed out, as a small integer; `decode_caller_tag` (`:499`) decodes the `term_to_binary(Mref,[local])` image through `crate::nif::with_decode_scratch`, interning any appended name back into the live table.

**`Accepted { fd }` adoption.** `PortRegistry::adopt_accepted` (`:286`) is the runtime half of `tcp_inet_copy` (`inet_drv.c:11834`): `beam_io::TcpInetDriver::from_socket(fd)` in the `PortMeta` block `open_port/2`'s built-in arm builds (no OS child, the driver's own `control` capability, the **listening** port's `stream`/`line` inherited), registered, then the inherited block installed (`data_mode(listener, stream)`, `seed_inet_mode`, `inherit_inet_options`); a replay the driver rejects closes the new port and fails the accept `{error, einval}`. The descriptor is **owned by the completion** from staging on: every path hands it to a driver (closed on teardown) or releases it via `discard_descriptor(fd)` (`:363`, `FdDriver::read_only`) — **never leaked**; an indescribable descriptor ⇒ `{error, ebadf}`, no port number left ⇒ `{error, emfile}`.
### `port/ops.rs` — the port **table** operations (`port_set_data/2`, the name registry, `port_connect/2`)
`PortExtras` (`pub(crate)`, keyed by **port number** like `meta`) holds what `open_port/2` does *not* establish: `data` (the C's `prt->data`, `erl_bif_port.c:687-760`; absent = never set, rendered `undefined`), `names` and `links` (`ERTS_P_LINKS(prt)`), the `inet_opts` mirror, the `peer_closed` latches and the owner-`'EXIT'` suppression mark; `forget_port(number)` drops all of them from `PortRegistry::close`, the single place a port leaves the runtime.
Accessors: `set_port_data`/`port_data` (`badarg` for a port the registry does not hold, `:693-695`), the name entries, `resolve_port` (the C's `lookup_port`, `:126-143`: an internal port term **or** an atom naming a registered port), `extra_links` (`None` = the port's only link is its owner), `connect_port` (the C's `set_port_connected`, `io.c:2330-2419`: **adds** a link and moves `PortMeta::owner`, the one field every delivery site reads), `suppress_owner_exit`/`owner_exit_suppressed` (`:204`/`:210`, the mark `exit.rs` reads).
The free `connect(ports, table, port, target)` is `erlang:port_connect/2`'s whole body, shared by the floor's `erlang:` spelling and the `RuntimeHooks` bridge's `erts_internal:` one (`erl_bif_port.c:435-470`): resolve the port, require an internal **live** pid target (a dead one ⇒ `badarg`), then transfer — a nested registry borrow being the typed gap. The `ProcessHook` bridge (`../context/process_bridge.rs`) serves the name registry over the **process** table first and the port registry second, so one name has one holder (`register(init, Port)` is `badarg`); the badarg matrix is the oracle's throughout, and `port_get_data/1` of a fresh port is `undefined`.
### `port/exit.rs` — a closing port's `'EXIT'`/`'DOWN'`
A port is linkable and monitorable, so a close owes what a dying process owes its peers: `{'EXIT',Port,Reason}` to a **trapping** link and `{'DOWN',Ref,port,Port,Reason}` to every watcher, `'EXIT'` before `'DOWN'`.
Two closers only, both carrying a reason — `port_close/1` (`PortRegistry::close`) with `normal`, a driver closing its own port with its own (`failure.rs`); the reason rides the signal (`PortSignal::reason`), so one close's `'EXIT'` and `'DOWN'` can never disagree. Policy: a **trapping** peer gets that `'EXIT'`, a non-trapping one **nothing** on `normal` and termination with that reason otherwise, every watcher its `'DOWN'` (outgoing `PortWatch` removed), a recipient the table lacks is skipped. `PortSignalKind{Exit, Down(MonitorRef)}` + `PortSignal{port, to, kind, reason}` are per **recipient**, so a route observing only its own mailbox takes its own entries and leaves the rest queued in `PendingPortSignals{unreported, ready}`.
The obligation is discharged in **two steps**, because `beam_process`'s `ProcessTable::port_closed` frees the port number while `beam_io` keeps it until its `PortNotification::Closed` report is minted (`take_closed_notifications` → `ids.release`), so a `close`+`open` in one slice cannot make a deferred report name a different live port. `port_exit_signals(id, reason, signals_owner)` is that obligation's pure reader (the metadata, the link set — `extra_links`, or the owner for a never-reconnected port — and the incoming monitors of the authoritative `beam_process::PortTable::monitors`, **not** the always-empty `PortMeta::monitors`); `capture_port_exit(id)`, called from `close` while all three are readable, wraps it with `normal` and only **stashes** the snapshot, and `fold_notifications`'s `PortNotification::Closed` arm moves it into `ready`. `signals_owner` is the owner-`'EXIT'` suppression mark (`PortExtras::no_owner_exit` ⇒ `false`, `exit.rs:290`), producing the `'DOWN'`-only set the C's `driver_exit` produces (`io.c:7244` unlinks first). The failure channel bypasses that second stage (`push_port_signals` → `push_ready`) because `beam_io` has already closed *and* reported its port when `take_failures` answers.
Delivery is **pull-based**: `Runtime::deliver_port_signals` takes every deliverable entry (the `run` route, via `RuntimeContext::deliver_in_table`, so a parked receiver wakes) and `RuntimeContext::poll_port_signals()` only its own process's (`take_port_signals_for`, the `-eval` route); `PendingPortSignals::prune(alive)` drops an undeliverable entry, which would otherwise hold `has_nothing_to_poll()` false for ever.
### `port/failure.rs` — the driver-failure channel's runtime half (A.4)
A driver closes its **own** port through the C's `driver_failure*` family or `driver_exit` (`io.c:7196-7278`) — a **port-closing request**, not a return value: `beam_io` latches it inside the callback (`DriverContext::signal_failure`), runs the ordinary teardown (`reap_failures` → its `PortRegistry::close`, so the driver's `stop` runs, the port leaves the live map and its `Closed` report is minted) and queues the term-free `PortFailure` (`take_failures`); this module is the half `beam_io` cannot do, owning no terms and no process table.
`signal_reason(&FailureReason) -> PortSignalReason` (`pub(crate)`) is the **one** reason rule: `Eof`/`Normal` ⇒ `PortSignalReason::Normal` (not `Atom("normal")`, so the link family's *`normal` is ignored* policy applies), `Atom(name)` ⇒ that name, `Posix(errno)` ⇒ `InetReason::from_errno(..).atom_name()` (the lowercase name, never `{error, ·}`), `Code(n)` ⇒ `Integer(n)`.
`PortRegistry::drain_failures()` takes every queued failure and answers the `ClosedPortSnapshot` of each port it finished, for the completion sweep that follows; `fail_port(id, failure)` is `close`'s bookkeeping **minus** the two steps `beam_io` already performed (no `registry.close`, no `notify_port_exit`) and otherwise the same helpers in the same order: `closed_snapshot`, `port_exit_signals(id, reason, failure.signals_owner)` **before** the metadata goes, `meta.remove`, `extras.forget_port`, the purge of retained events, then `push_port_signals` — straight into the deliverable queue, never stashed, because the port is already closed **and** reported, so one failure yields exactly one `'EXIT'` and one `'DOWN'`.
**Delivery policy** is the C's single `erts_deliver_port_exit(prt, id, reason, 0, 0)` path, so one close's `'EXIT'` **and** `'DOWN'` render the same reason; `signals_owner == false` (the `driver_exit` family, `io.c:7244`) produces **no `Exit` entry** while every monitor still gets its `'DOWN'`, and `RuntimeContext::port_exit_reason_term` interns the atom name in the runtime's one shared table (so a `receive` clause can match it) or builds the bare small integer.
### `port/info_extras.rs` — the derived `port_info/2` items
`queue_size` is the C's `erts_port_ioq_size(prt)` (`erl_bif_info.c:3868-3874`), the driver's own staging area in both directions; `beam_io::Port` holds exactly those two queues, so the answer is `input_len() + output_len()` (a fresh port `0`).
`memory` is the `am_memory` arm (`:3838-3860`): link nodes, monitor records, the `port_set_data/2` heap and the line buffer, **deliberately excluding the `Port` struct itself**, with `link_size`/`monitor_size` **assigning** rather than accumulating (`:3648-3660`), so N links report one link node and N watchers one monitor half; its constants are the C struct sizes on a 64-bit build (`allocate_linebuf`'s `LINEBUF_INITIAL` 100, `io.c:3155-3166`), and the oracle answers `48` for a bare port, `90` at `{line,10}`, `180` at bare `line`, `72` with one watcher.
`monitored_by` is the `am_monitored_by` arm (`:3735-3765`) read from the port table's incoming monitor list — the authority `erlang:monitor(port, Port)` writes and `Runtime::port_monitors` reports; `locking` is `port_level` for a `spawn`/`spawn_executable`/`fd` port (the C's own drivers set `ERL_DRV_FLAG_USE_PORT_LOCKING`, `sys_drivers.c:251`) and `driver_level` for every `{spawn_driver,Name}` port (Known Issues); `parallelism` is truthfully `false`, the runtime never granting `ERTS_PTS_FLG_PARALLELISM` (`erl_bif_info.c:3895-3905`). `awaits_port_reply` — the poll-budget predicate — is defined here too (*Measured*), and `PortRegistry::info` chains all of these after the seven `/1` items.
### `port/driver.rs` — the driver C ABI host (A.4)
`Driver{library, host: Box<DriverPort>}` pairs a loaded driver with the host its callbacks run against (**field order is load-bearing**: the library's `Drop` runs the entry's `finish` before the host drops); `DriverPort` is the concrete `beam_abi::DriverHost` behind the opaque `ErlDrvPort_`, whose handle **is** the per-port `DriverEnv`'s address.
`load_driver(candidates, name)` delegates to `beam_abi::driver::loader::load`, tries each candidate and reports the **last** typed error; the loader appends the shared-object suffix to **every** candidate unconditionally (`erl_unix_sys_ddll.c:104-118`), so `shared_object_stem` strips one trailing `.so` first.
`binary_to_term` (`erl_drv_binary_to_term`) decodes into a **per-thread memoized image** of the shared table (`crate::nif::with_decode_scratch`, validated in O(1) by an `AtomSnapshot` witness), records an appended name at its predicted index (`intern`, never `intern_atom`: the interner's `base` is fixed at host build) and answers the C's `ERTS_DDT_FAIL` (`None`) for an invalid image, never a raise; the registry hooks carry the C's codes — `add_driver_entry` → `0`, `remove_driver_entry` `1`/`0`/`-1` (`io.c:7698`), `lock_driver` off the load state (`:7324`), `create_port` = the invalid-port sentinel.
`DriverPort` owns the driver-private state the frozen seam has no home for: `driver/state.rs` holds the C's `prt->ioq` (`io.c:6790-6919`) byte queue (one chunk per successful `driver_enq`/`driver_pushq`) behind `enq`/`pushq`/`deq`/`sizeq`/`peekq`, plus the `pdl_created` one-PDL guard; `with_port_flags` carries the port's **state** stream bits (`StreamType::port_flags` → `PORT_FLAG_BINARY` (1) for a `binary` port, else `0`), a **different** cell from `set_control_flags`' `control_flags` (`io.c:5325-5344` vs `:5318`); `clear_driver_state` (from `stop` **and** the adapter's `Drop`) drops the queue so a late drain never reads a gone port's bytes.
`DriverPortAdapter` is the port **lifecycle**: `start` runs the entry's `start` (the `ErlDrvPort` **is** the environment's address, in a `Box` that never moves); `output` hands queued bytes to `outputv` when declared (**the C's preference**, `io.c:1782`/`:1597`) and to `output` otherwise — so an **`outputv`-only** entry receives `port_command` — and queues the `driver_output` reply as the port's **input**; `stop` runs the entry's `stop`, the drop `finish` + `dlclose`. An `OUTPUT` task (`Port::run_task` → `ready_output`) **always** drains the output queue through that one `output` path and *then* runs a declared `ready_output` slot as the write-**readiness** notification (`erl_port_task.c:1793-1797`); the adapter maps `load`/`name`/`state`/`selected`/`control` (verb parsed as a `c_uint`)/`control_reply`/`notify_ready` (one **already-resolved** descriptor's `ready_input`/`ready_output`) plus the monitor tree, `has_process_exit` and the shared `Rc<ProcessLiveness>`.
`build.rs`'s `-Wl,--export-dynamic` publishes the `driver_*`/`erl_drv_*` symbols; `open_port({spawn_driver, Name}, Options)` routes here for a name no built-in driver answers, an unknown or empty driver name being `badarg`.
**Two shared flags, seized at load.** `BusyFlag` (`driver.rs:540`) is one handle for both halves of the busy state — `busy` (a `Rc<Cell<bool>>` written by `DriverHost::set_busy_port`, `io.c:5208-5264`) and `soft_busy` (stamped by `load` from `library.entry().driver_flags`, so the bit is the **entry's**); `OsPidFlag` (`:599`) the same for the OS child pid, written by `DriverHost::set_os_pid` (`io.c:2971`) and read for `port_info(Port, os_pid)` (`erl_bif_info.c:3814-3817`). Both are seized **before** `load` consumes the boxed host (`DriverPort::busy_flag`/`os_pid_flag`); `PortMeta::driver_busy` is the runtime's handle (`port.rs:613`), `PortMeta::driver_os_pid` its owed counterpart (Known Issues). Three `beam_io::Driver` capability overrides read them — `is_busy` forwards `BusyFlag::is_busy`, `flags` reports `DriverFlags::SOFT_BUSY` **iff** the entry advertises `ERL_DRV_FLAG_SOFT_BUSY`, `has_control` the entry's own `control != NULL`; `set_os_pid` answers `0` when a port lifecycle has claimed the host and `-1` otherwise, and `clear_driver_state` does **not** clear it (the C's `prt->os_pid` outlives the driver's private state).
`DriverPort` implements **33 of the 43** `DriverHost` hooks in `beam_abi/src/driver/host.rs` — all four registry slots and the failure channel's three (`failure`, `port_exit`, `port_term`); the other **10** keep the frozen trait default (the C's own failure code) in three groups — the **async** pair (`r#async`, `async_port_key`), the **lifecycle** family minus `set_os_pid` (`busy_msgq_limits`/`init_ack`/`pdl_lock`/`pdl_unlock`/`pdl_inc_refc`/`pdl_dec_refc`/`pdl_get_refc`) and **`now`** — each needing runtime structure a per-port host holds no handle to.
**The failure latch, and `ERL_DRV_PORT`.** `FailureLatch` (`:643`): `set` is **first-wins** (a second answers `-1`), `take` the drain, `is_pending` the quiescence probe, `clear` the teardown's forget. `DriverPort::failure` maps the seam's `PortFailure` onto `beam_io::DriverFailure` (`Eof`/`Atom`/`Posix`/`Error`), flushes the private `ioq` (`io.c:7220`) and answers `0`/`-1`; `port_exit` latches `DriverFailure::exit(code)` (`signals_owner = false`); neither can close a port, so `DriverPortAdapter::settle` drains the latch — **output first, then the request** (`DriverContext::deliver_read` refuses a read once a failure is latched), a refused hand-off **re-latched** for the next callback.
`PortTerms` (`:714`) is the per-port `ERL_DRV_PORT` state behind `DriverHost::port_term` (`erl_driver.h:523`): `driver_mk_port` answers the **handle** while the term-data layer has no port table, so it is stamped with the handle/`PortId` pair in `start`, read back by the hook, `mark_gone`'d from `clear_driver_state` — a cached `ErlDrvPort` cannot become a dead port's id term, and an unstamped host answers `None` (the C's `ERTS_DDT_FAIL`). The timer family matches the C for **every** live port (a silent `no_timeout_callback` substitutes when the entry declares no `timeout` slot, `io.c:7601`), so `io.c:6918`'s `-1` stands only for an invalid port.
### Driver-emitted terms (`erl_drv_output_term` / `erl_drv_send_term`) — `TermQueue`
`beam_abi` decodes the driver's term-data stack machine into a real term on the host's arena and calls `DriverHost::send_term(port, to: Option<Eterm>, term)`; the C delivers there and then (`io.c:5664`) and the frozen seam gives the host no route to a receiver's mailbox, so the term is **queued** in a per-port shared `TermQueue` — `None` = the connected process (`io.c:6254`), `Some(pid)` an explicit destination (`:6289`).
A queued term's words live on the host arena, so the adapter empties the queue in both `beam_io::Driver::stop` (`io.c:6213`) and its `Drop`; `PortRegistry` seizes the handle as `meta.driver_terms` at `open_port/2`, and `take_driver_terms` surfaces each as `PortEvent::Term{port, to, term, owner}`, which the pump copies onto the pointer-stable arena (`stabilize_driver_term`) and delivers.
### `port/watch.rs` — the `os:set_signal/2` delivery half (`pub(crate)`)
One `thread_local!` `FACILITY: RefCell<FacilitySlot>` holds the facility the first `os:set_signal/2` creates and production **never drops** (a per-call one would restore the prior dispositions at the end of the call); `HANDLED: RefCell<BTreeSet<Signal>>` mirrors which signals hold `Disposition::Handle`, so `is_pollable` answers without a syscall.
`SignalWatch{token, fd}` is the poller registration: `sync(poller)` registers the facility's `read_fd()` under `SIGNAL_KEY` (= `u64::MAX - 1`) on the first round after a `handle` disposition; `is_pollable()` is the **poll-set** half and `has_pending_signal()` the **pending-work** half — a non-destructive zero-timeout readiness probe of the self-pipe, whose byte is the *whether* and the facility's private bitmask the *what*.
`crate::context::signal` owns the oracle answer surface (`{ok, OldDisposition}`/`badarg`, the kernel-only `sigstop` rule) and delegates the facility here; the message is `signal_notify_message(name)` → `(from, {notify, Name})` with `subject` interned as `system`.
### `erlang:port_command/2,3` and the port **busy state** (A.4)
The decision table lives in **`beam_io`'s `Port::command`** (`beam_io/src/port.rs:428`), reached through `PortRegistry::port_command_with` (`beam_io/src/registry.rs:470`, `port_command` folding the outcome away): `PortCommandOutcome::{Done,Busy}` from `PortCommandOptions::{with_force,with_nosuspend}` and the driver's own capability/state.
| port | options | outcome / answer | C |
|---|---|---|---|
| any | `[force]`, driver **without** `SOFT_BUSY` | `Err` = `error:notsup`, **before any output is written** | `erl_bif_port.c:195-198` |
| idle | any (incl. `[force]` with `SOFT_BUSY`) | `Done` — queued, an `OUTPUT` task scheduled; the oracle's `true` | `io.c:1763` |
| busy | `[force]` + `SOFT_BUSY` | `Done` — the busy state is bypassed | `io.c:1731`, `:1763` |
| busy | plain or `[nosuspend]` | `Busy` with **nothing queued**; `[nosuspend]` ⇒ `false`, a plain command suspends the caller | `io.c:1763-1769` |
The `[force]` refusal is a property of the driver **entry's flag word, never of the busy state**, so it is `notsup` whether or not the port is busy; a `Busy` answer leaves the bytes out of the output queue because the oracle suspends the caller and re-issues the command when the driver clears the state (`erts_port_resume_procs`, `io.c:5265`). `BusyFlag`'s two cells are the state pair `Port::command` reads through `PortMeta::driver_busy`.
`[force]` is `notsup` for a `spawn`/`spawn_executable`/`fd` port and for a built-in driver port that reports no entry flags — `ram_file_drv` and `udp_inet`, measured on the oracle.
Only **two** of the three static drivers are flagless: `tcp_inet_driver_entry` declares `ERL_DRV_FLAG_SOFT_BUSY` (`erts/emulator/drivers/common/inet_drv.c:1374`; oracle `port_command(P,<<1,2,3>>,[force])` on `{spawn,"tcp_inet"}` ⇒ `true`), while `udp_inet_driver_entry` declares only `ERL_DRV_FLAG_USE_PORT_LOCKING` (`inet_drv.c:1432`; oracle ⇒ `error:notsup`).
This runtime's built-in `tcp_inet`/`udp_inet` ports (`beam_io`'s static drivers) report **no** entry flags, so `[force]` on a `{spawn,"tcp_inet"}` port answers `notsup` here where the oracle answers `true` — a residual owned by `beam_io`, not by `beam_rt`. The runtime's own `port_command` (`../native/port.rs`) runs only the **pre-conversion** gate (`PortRegistry::command_with_data`) and then the accepted command's round/accounting; a plain (unsuspendable) command on a busy port still raises the typed capability gap.
## Constraints
- `#![deny(unsafe_code)]`: the registry slots operate over a **thread-local** entry list `DRIVER_ENTRIES`, not a process-global `DriverTable`, because the runtime drives every port on one thread.
- Every driver callback runs under `publishing` → `beam_abi::with_current_host` (`start`/`ready_*`/`output`/`timeout`/`stop`), which lets the two port-less registry slots reach a host during a callback.
- The `SignalFacility` is a `thread_local` (not a `Runtime` field) because the runtime is single-threaded (`!Send`), so the slot *is* the process's one facility.
- Never a fabricated success: failures are typed `BeamError`s and an unservable state/lifecycle returns the C's own failure code.
- A payload is credited where it is harvested and the queue it came from is empty afterwards (`fold_notifications` + `drain_pending_events` for the data lane, `PortNotification::Closed` for the signal lane).
## Measured — the poll budget a pass hands this layer (`startup_ms`)
The largest wall-clock cost this layer can impose on a CLI start-up is **not work**: the *blocking budget* a zero-slice scheduler pass hands `PortRegistry::pump`.
- **`PORT_POLL_SLICE` is 25 ms**, *both* the poller's inner clamp and the `port_timeout` an empty pass passes in (`../runtime/scheduler.rs::scheduler_pass`), so a live-but-idle port costs a whole `epoll_wait(…, 25)` per such pass — `strace -f -w` measures five `epoll_wait(3, [], 1024, 25) = 0` at 25.07–26.2 ms each when it does.
- **The predicate separating the two cases is `PortRegistry::awaits_port_reply`** (`info_extras.rs`) over the per-port byte counters kept for `port_info(Port, input)`/`output` (`PortMeta::{input, output}`): `output > input` means unanswered bytes, so the wait is justified, while a port that answered everything (the boot's `inet_gethost` child) cannot speak again until written to.
- **The budget cannot simply be zeroed**: that poll resolves the kernel's `inet_gethost` round trip, and forced to zero `drive_scheduler` returns `0` on its first pump, so the `{apply,{application,start_boot,…}}` directive folds to `unsupported: opcode: run: process blocked` (exit 3 — measured); the predicate therefore *shortens* the wait only for a port that owes nothing.
- **The gate is applied** at `../runtime/scheduler.rs` (`Runtime::awaits_port_reply`): a `TimerWait::ImminentWithin(_)` pass — only the boot drive uses that policy — gets `Duration::ZERO` when the predicate is false, and stays patient when the table cannot be borrowed. Measured: blocking rounds **8 → 1**, `strace -f -c -w`'s `epoll_wait` total **130.8 ms → 4.1 ms** over the same **15** calls, `read` 233 ms → 104 ms, the lookup unchanged (**98** `.beam` opens, exactly one `execve` of `<erts>/bin/inet_gethost`), CPU identical either side; paired medians in [`../PERF.md`](../PERF.md).
- **The rule for any future change**: a pass may block on the poller only when something can answer — a port with a reply in flight, an armed driver deadline (`beam_io::PortRegistry::next_deadline`) or an armed `tty_select/2` interest; blocking merely because a port is *live* costs a slice per pass for ever.
- **Re-measure with deterministic counters, not timings**: non-zero `port_timeout` rounds per run, `strace -f -c -w`'s `epoll_wait` total, the `.beam` openat count (**98**) and `execve` of `<erts>/bin/inet_gethost` (**exactly 1**); the pins are `tests.rs::a_port_awaits_a_reply_exactly_while_a_written_command_is_unanswered` and `../runtime/scheduler/tests.rs::the_port_poll_blocks_only_for_a_round_that_ran_nothing`.
## Known Issues (this is a floor, not the full C `io.c`)
- **`port_control/3`** — behind `has_driver_control`; a **byte-int list** at every length, a **binary** only after `PORT_CONTROL_FLAG_BINARY` (per port); a reply from the driver's **own** memory is the typed *unsupported* (Handoffs).
- **A `NULL` reply with `PORT_CONTROL_FLAG_BINARY` set ⇒ `<<>>` where the C answers `[]`** (`io.c:4126` returns `NIL` before it reads the flag).
- **A plain `port_command/2,3` on a busy port** — the C suspends (`erts_suspend` + `ERTS_BIF_YIELD3`, `erl_bif_port.c:211-220`) and the BIF seam has no block channel ⇒ the typed gap (exit 3, reason naming the busy state); every other arm matches.
- **A driver port can never report `{exit_status,N}`** — `driver_report_exit` (`io.c:5533`) is not declared in `erl_driver.h`, so `take_exit_status`'s `Ok(None)` is correct, not a gap.
- **`driver_async` schedules nothing; `driver_async_port_key` unimplemented** — `r#async`/`async_port_key` keep `-1` (`Runtime` is `!Send`; `erl_async.c:518-525`, `:585-593`, `:604-613`).
- `beam_io`'s `EfileDriver`/`FdDriver` are **never constructed here** (only `SpawnDriver`); file I/O is the `std::fs`/`std::env` floor under `../native/prim*.rs`.
- **Driver-interned atoms land at the port boundary** — a predicted index, `dropped` if the table moved past it, never interned at a foreign index; the deep clone is gated on `has_pending_driver_atoms` (`tests.rs::an_idle_port_round_does_not_clone_the_shared_atom_table`).
- **The monitor family is live end to end** — `DriverMonitors` seized as `PortMeta.driver_monitors`; `monitor_process_result` ⇒ `-1` (no `process_exit` slot, or a non-local pid), `0` (observed-alive, **or no observation**), `1` (observed-dead); `drain_driver_monitor_exits` **defers** with `Ok(0)` on a live borrow, run just before `deliver_port_messages`.
- **Line framing is adopted** — `line`/`{line,N}` (bare = `LINE_DEFAULT_MAX_LEN` 512) through `set_line_mode`; `StreamType::port_flags` ORs `PORT_FLAG_BINARY` (1) and `PORT_FLAG_LINE` (2) independently; exclusivity is checked after the whole list parses (`line` + `{packet,N}`, `stderr_to_stdout` without `use_stdio` ⇒ `badarg`).
- **`get_port_flags` answers from inside `start` where the oracle answers `0`** (`erl_bif_port.c:1139-1143` sets the bits only after `open_driver` returns); no corpus case calls it there.
- **Two registrations per direction from one driver** ⇒ typed `unsupported` (`armed_event`), never a wrong descriptor.
- **`os:set_signal/2`'s notification is dropped with no `erl_signal_server`** (`sys.c:589-604`), never an error; the `-eval` route drops a `PortEvent::Signal`, the scheduler path delivers it.
- **A built-in driver port's `{data,D}` renders as list elements on either stream** (`StreamShape::DriverOutput`, `io.c:3404-3435`), so a header-only reply is the oracle's exact list; residual: `beam_io`'s flat `DriverContext::input()` cannot name the producing `driver_output*` call, so `DATA`'s improper tail (`ram_file_drv.c:448`) is a proper list of the same bytes.
- **A `dlopen`ed driver's split read survives** — `DriverHost::output2` records `(header, Option<body>)` (`None` = the C's `buf == NULL`) and `collect_outputs` hands each call over as **one** read, so `driver_output2`/`driver_output_binary`/`driver_outputv` are oracle-identical (`driver_output_shape_tests.rs`, the `eventsplit` fixture).
- **A zero-byte read produces no message** (`fold_notifications` drops an empty `ReadMessage`), so `driver_output2(NULL,0,NULL,0)` is silent where the oracle answers `{Port,{data,[]}}`; both shapes are pinned at the builder (`stream_shape_tests.rs`).
- **`port_set_data/2`'s words are not counted by `port_info(Port, memory)`** — `120` where the oracle answers `136`; no number is fabricated.
- **`locking` is `driver_level` for every `{spawn_driver,Name}` port** (the C decides on `ERL_DRV_FLAG_USE_PORT_LOCKING`, `erl_bif_info.c:3875-3894`, a bit `DriverFlags` does not carry); OS-child ports answer `port_level`, the oracle's own.
- **A tagged port monitor's `'DOWN'` carries the default head** — `{tag,Tag}` lives in `beam_process`'s private `ProcessTable::tags`, which no API of that crate exposes.
- **The `-eval`/action process starts with `trap_exit = false`** (`../runtime.rs::as_action_process`) where the oracle reports `true`; every port-exit fixture sets it.
- **The inet stack reaches this node end to end** — `gen_udp:open/1,2`, `gen_tcp:listen/2`, `inet:getstat/1,2`, a two-socket UDP round trip, and `gen_tcp:connect/2,3,4` (via `inet:timeout/1` → `erlang:read_timer/1` over `Timers::remaining`, `../timers.rs`; a closed loopback port ⇒ `{error,econnrefused}`, an in-runtime listener ⇒ `ok`). Residuals: a **nested blocking call on the `-eval` route** folds to `blocked()` (exit 3, `../context/pump.rs`, sibling-owned), where the scheduled `run` route resumes; the **async-op queue** (`INET_MAX_ASYNC`) is unmodelled, so a control-op `recv` reads now (`[1]` vs the oracle's `[1,0,0]` plus a later `{inet_async,…}`).
- **A completion's recipient is `PortMeta::owner`, not the C's `desc->caller`** (the seam exposes no `driver_caller`, `completion.rs:67-73`); identical for every `prim_inet` caller.
- **A post-`open_port/2` `{mode, list}` does not re-render a completion** — `PortMeta::stream` is fixed at open (`prim_inet:open/5` passes `[binary]`) and `{mode,…}` travels verbatim as a control op (`completion.rs:176-181`).
- **`port_command/2,3` and `port_control/3` take only a port term** — `PortId::from_eterm` ⇒ `badarg` where the C's `lookup_port` resolves an atom (`erl_bif_port.c:129-141`; specs `erlang.erl:12006,12207`); `port_info/1,2` and `port_connect/2` **do** resolve a name.
- **`driver_failure_atom/2` crosses the seam as UTF-8 where the C interns Latin-1 bytes** — `-1` for a non-UTF-8 name, one atom for a multi-byte name where the C interns the bytes; only the ASCII rows are oracle-identical.
- **The data-then-failure row is pinned by `failure_e2e_tests.rs`** — the failing callback's read arrives **before** the exit signal (`fail_port`'s `failed_read_recipients`, consumed once, dropped at `Closed`, cleared on `register`), a non-trapping owner dies of a non-`normal` reason and survives `normal`, and `driver_exit` never signals a linked owner.
- **`{udp_closed,_}` does not exist in the oracle** — a `udp_inet` port never reports a peer close; a connected socket's ICMP failure is `{udp_error,S,econnrefused}`.
## Notes for Agents
- **A new driver-callback site must add a row to the completion channel's drain-point table**: `has_nothing_to_poll` only sees what has already been **drained** into `pending_events`, so a site that folds notifications without draining loses its driver's `{inet_reply,…}`/`{inet_async,…}`.
- **How the `inet` stack reaches this node — exactly two doors.** `erts/preloaded/src/prim_inet.erl` is the only module in the tree that opens an `{spawn_driver, …}` port (`:103`), with **one** option, `[binary]`; every socket option travels separately through `setopts/2`, and every *request* is `erlang:port_control(Port, Req + 16#03f1a300, Buf)` via `ctl_cmd` (`:2972-2984`).
- The colocated signal tests share **one** `watch::test_guard()` lock so they serialize on the process-global dispositions, and send with `Command::new("kill") -USR1 <pid>` on `std::process::id()` — **never** `libc::raise`, which would need `unsafe`.
- A test calling `run_scheduled` must account for the port loop parking (`Runtime::is_nt` reads `has_nothing_to_poll`; see `../runtime/CONTEXT.md`), and one closing a linked port must drain **both** lanes — the `run` route a further pass for `deliver_port_signals`, the `-eval` route a further `poll_port_signals`.
- A new `port_info` item belongs in `PortRegistry::info` **and** in `../native/port.rs`'s `PORT_INFO_1_ITEMS` decision: the `/1` roster is the C's `ERTS_PORT_INFO_1_ITEMS` and nothing else.
- **The sibling `../../tools/differential/divergences.md` A.4 entries are STALE** against `driver.rs`/`port.rs` (the driver-monitor family, an `outputv`-only entry, `driver_set_timer/2` without a `timeout` callback, `commit_atoms/1`): all four agree with this node — escalate a correction to that node's owner.

## Known divergence from the oracle: no child-exit auto-close
- ERTS **auto-closes** a `{spawn, Program}` port once its child exits: after the reap, `erlang:port_info(P)` is `undefined`, `lists:member(P, erlang:ports())` is `false`, `erlang:port_close(P)` raises `error:badarg`.
- This runtime does **not**: `PortMeta.notify_exit` is only set by the `exit_status` option, so nothing reaps or removes the port until an explicit `port_close` — which kills and reaps, `meta.remove`s, forgets the extras and releases the id, synchronously.
- The child is reaped at exactly two points, both **`SIGKILL`ing it then blocking in `wait`**: `PortRegistry::close` → `Driver::stop` (`drivers/spawn.rs:1139-1154`) → `kill_and_reap` (`:1225-1246`), and — for a port nobody closed — the driver's `Drop` (`:1165-1175`) when the `Runtime` drops; because `main` evaluates `cli::run` and only then calls `std::process::exit` (`src/main.rs:29`), the `Runtime` in `cli::run`'s `source` **is** dropped on the `halt()` path, so the boot's idle `inet_gethost` child is killed and waited for there and a `wait4` after the last poll round belongs to that teardown.
- The corpus **sidesteps** the divergence rather than pinning it (the five `driver/port_*` close cases each open a child alive until the explicit `port_close/1`), so the gate's 0-mismatch verdict is consistent with it.
## Handoffs (owned by OTHER nodes)
- **`beam_abi`** — `r#async` adoption needs a **safe** route from the hook's three raw operands to an `AsyncJob`: the runner and `DriverLibrary::ready_async` exist, but `AsyncJob::new` is that crate's one `unsafe` entry point.
- **`beam_abi` / `beam_io`** — a **safe reply-copy** helper for a `control` reply the driver answered from its own memory (today an `unsafe` slice read inside `impl Driver for DriverPort`, `beam_io/src/abi/port.rs:710-747`); until it exists `control_reply` answers the typed *unsupported*.
- **`beam_io` — the pure-read seam this node is missing.** Nothing exposes a listener's concrete `TcpInetDriver`: `Port { driver: Box<dyn Driver> }` publishes only `driver_name()`, `pub trait Driver` (`beam_io/src/driver.rs:507`) has no `as_any`/downcast, and `PortRegistry` hands out only `&Port`/`&mut Port`; with `Driver::as_any(&self) -> &dyn Any` (or `PortRegistry::driver_as::<T>()`), `adopt_accepted` could become `TcpInetDriver::from_accepted(fd, listener_driver)` and most of the mirror replay would go — except `data_mode`, whose consumers are the payload renderers. Firing the driver's `process_exit` needs no new seam: `execute_port_tasks` already calls `drive_async` each round (`beam_io/src/registry.rs:291-317`).
- **`beam_io`** — three further asks: `ERL_DRV_FLAG_USE_PORT_LOCKING` must cross the seam (`DriverFlags` keeps only `SOFT_BUSY`); a **line-mode** read must name its producing call (or stamp the header on the **first** frame only) so a frame's prefix is charged once, as the C charges `hlen + len` per call; and the **in-tree** drivers must hand bytes up through `DriverContext::deliver_read(header, body)` rather than the flat `input()` for a `DATA` reply to render the oracle's improper `[2,0,0,0,2|<<97,98>>]`.
- **`beam_io` (the completion channel's two asks)** — a `driver_caller` on the frozen `Driver` seam would address a completion to the C's `desc->caller` instead of `PortMeta::owner`, and the driver's own `{mode, list|binary}` must cross it for a post-`open_port/2` `{mode,…}` to re-render an `{inet_async,…}` payload.
- **`beam_bifs`** — `erlang:read_timer/1,2` was the connects' blocker (`inet:timeout/1` calls it unconditionally, `lib/kernel/src/inet.erl:4953-4957`); this crate's `RuntimeHooksBridge` serves it, so the connect path needs nothing further there.
- **`src/context/**` (sibling node)** — the `-eval` pump cannot resume a parked nested call, so a completion arriving for a nested `gen_udp:recv/3`/`gen_tcp:accept` has no waiter and the route folds to the typed `blocked()` gap (`../context/pump.rs`); the channel delivers the message, the resume is that node's.
- **`beam_process`** — no seam needed for the marking (its single exit observer stays `EtsExitObserver`), **but** a tagged port monitor's `'DOWN'` needs that crate to expose the monitor's `{tag, Tag}`, and `ProcessTable::port_closed`'s `PortTable::close`-first order is what keeps the exit signalling out of that crate — an API that snapshots relations without freeing the port number would move the whole obligation there.
## `port/active_input.rs` — the `{active, …}` input channel (A.4)
The driver→owner path of an `{active, true|once|N}` socket: such a socket never parks its input in the port's byte queue, so the driver *sends a message to the owner* from its read-readiness callback (`beam_io`'s `drivers/inet/active.rs`, `drivers/inet/udp/active.rs`, one `ActiveInput { port, event }` per delivered unit through `DriverContext::deliver_active_input`); `active_input.rs` is the runtime half, its module docs carrying the C derivation.
| event | port kind | message | C |
|---|---|---|---|
| `ActiveInputEvent::Data(read)` | `tcp_inet` | `{tcp, S, Data}` | `inet_drv.c:3979-4055` |
| `ActiveInputEvent::Data(read)` | `udp_inet` | `{udp, S, IP, Port, Data}` | `packet_binary_message`, `:4105-4160` |
| `ActiveInputEvent::Passive` | `tcp_inet` | `{tcp_passive, S}` | `packet_passive_message`, `:4215` |
| `ActiveInputEvent::Passive` | `udp_inet` | `{udp_passive, S}` | the same builder, the other branch |
- **`ActiveInputPacket { port, owner, data_mode, kind, event }`** mirrors `CompletionPacket`: owner, stream mode and port **kind** resolve at **drain** time (`PortRegistry::drain_active_inputs`, from `PortMeta`), because a delivery staged around a teardown outlives the metadata; `ActivePortKind { Tcp, Udp, Other }` comes from `driver_path_name(&meta.command)`, `Other` being a **typed gap** for both events, never a fabricated `{tcp,…}`, never a silent drop; a delivery whose port has left is **dropped**, and the packet carries the `owner`/`port` it resolved, so nothing is re-attributed to a later port reusing the number.
- **One delivered unit is `beam_io`'s decision**: one frame under a framing `{packet,N}` (header already stripped), one read burst under `{packet,raw}`; a read's `header` is the `{header,N}` option (`desc->hsz`) for a stream port and the 7-byte packed source address for a datagram port — never the framing header.
- **Payload rendering goes through the one stream shaper**: TCP calls `make_stream_payload(read, mode, StreamShape::Data)`; UDP decodes the address out of the read's header (`decode_packed_address`: `[INET_AF_INET(=1), port_hi, port_lo, a, b, c, d]`, port big-endian) and shapes the **body alone** from a header-less `ReadMessage`; a header that is not exactly one packed IPv4 record is a typed gap.
- **The mode seam is `PortMeta::data_mode`** (body = `self.stream`, the **open-time** option): `{mode, list|binary}` never reaches `beam_io`, so a post-`open_port/2` change lives only in the `inet_opts` mirror and the rendering mode is resolved at the delivery arms from `PortRegistry::data_mode(port, packet.data_mode)`; do not add a second `PortMeta::data_mode` in `port.rs` (a duplicate inherent method is a compile error).
- **Delivery rides every point a driver callback can stage one**: `drain_active_inputs()` runs immediately after each of the six `drain_io_completions(...)` sites, publishing `PortEvent::ActiveInput { packet }` on `pending_events`, so `has_nothing_to_poll` stays truthful without an arm of its own and `PortEvent::port()` answers `None`, so `close`'s purge can never re-attribute or drop a staged delivery; `Runtime::deliver_port_messages` (the `run` route) delivers to `packet.owner` through `deliver_in_table`, `RuntimeContext::poll_port_messages` (the `-eval` route) only when `packet.owner == self.pid()`.
- **Residual — `hsz > len`, a `beam_io` seam.** The C's list branch is `(mode == LIST) || (hsz > len)`, so a `{header,N}` wider than the payload is one flat string with no binary tail; `beam_io`'s `split_payload` clamps `hsz` and hands that case up as a whole-payload header with a present-but-empty body, rendering `[104|<<>>]`; field order is kept, `[list]` mode is exact, every shape the e2e suite exercises has `hsz <= len`, and it is pinned at the renderer (`active_input_tests.rs::a_header_as_wide_as_the_payload_keeps_an_empty_binary_tail`).
- **Measured difference from the oracle.** A write arriving while an `{active,once}`/`{active,N}` grant is spent: the C disarms the descriptor (`sock_select(desc, FD_READ, 0)`) so the *re-arm's* inline read delivers those bytes, while `beam_io`'s poller stays armed and `async_ready_input` harvests them into the port data queue; the suite asserts only what both sides agree on and prints the oracle's own differing value.
## `port/inet_opts.rs` — the accepted socket's inherited option block (A.4)
`prim_inet:open/6` opens every `inet` driver port with **one** option, `[binary]` (`erts/preloaded/src/prim_inet.erl:99-137`), and applies every other socket option afterwards through `setopts/2` — an `erlang:port_control/3` call carrying the C's `[opt_code, val_be32]` records — so neither `open_port/2`'s options nor `PortMeta::stream` know what the **driver** has been told; `inet_opts.rs` is that knowledge, keyed by **port number** inside `PortExtras` (`inet: InetOptions`) so `forget_port` drops it. **Recorded**: every **successful** `setopts` argument verbatim and in arrival order (`PortInetOptions::records`, the replay source), the driver's current `{mode, list|binary}` (`::mode`) and its `{exit_on_close,…}`.
One entry point — `PortRegistry::note_inet_setopts(id, arg, ok)`, called from `src/port.rs::port_control` after the completion drain, gated on `is_setopts_control(op)` and `setopts_succeeded(reply)` — so a rejected `setopts` can never be inherited; the reply is read, never consumed, and the suites' own `setopts` helpers **detect** that hook so they are no-ops on a wired runtime (`accept_inherit_tests.rs::a_setopts_control_call_populates_the_option_mirror_from_production_alone`).
**The wire reader.** `walk` splits an argument into records while `rest.len() >= 5` (the C's `while (len >= 5)`, `inet_drv.c:6908`) and answers `None` if **any** byte is left over: the C ignores a partial trailing record, but this walker's output is **replayed**, and replaying the subset that happens to parse could claim a configuration the listener does not have. `record_len` is the C's per-code span: `linger` `RECORD+4`, `multicast_if` the whole `RECORD`, membership `RECORD+12` (IPv4) / `RECORD+20` (IPv6) and `None` for any other domain, `{active,N}` `RECORD+2`, `raw` `RECORD+8+arg_sz` with `arg_sz` at `RECORD+4..RECORD+8`, `netns`/`bind_to_device` `RECORD+value`.
**Replayed onto an accepted port** — exactly the set `tcp_inet_copy` copies into the new descriptor (`inet_drv.c:11810-11827`), i.e. `is_inherited_record`'s 16 codes:
| code | record | C |
|---|---|---|
| 7 | `{recbuf, N}` — **raises** the copied `bufsz` while `INET_FLG_BUFFER_SET` is clear | `:7350-7360` |
| 20 | `{buffer, N}` — **assigns** the copied `bufsz` and sets that flag | `:7318-7330`, `:11820` |
| 21, 23, 24, 25, 26, 27, 28, 30, 32, 35, 36, 37, 39, 49 | `nodelay`/`priority`/`tos`/`tclass`/`exit_on_close`/`reuseaddr`/`keepalive`/`sndbuf`/`delay_send`/`ipv6_v6only`/`bind_to_device`/`raw`/`netns`/`show_econnreset` — copied verbatim | `:11810-11827` |
`INET_OPT_RCVBUF = 7` sits beside `INET_LOPT_BUFFER = 20` because the copied `inet.bufsz` has **two** writers, so a replay carrying only `{buffer,N}` would drop a listener configured by `{recbuf,N}` alone; `accept_inherit_tests.rs::INHERITED_CODES` is the same 16 codes and asserts observable driver `getopts` agreement over every one, not replay shape.
## `port/peer_closed.rs` — the peer-close channel (`{tcp_closed, Port}`)
`beam_io::PortRegistry::port_closed(id)` is a **latched, sticky** observation that a connected socket's peer has closed; `peer_closed.rs` turns it into the oracle's 2-tuple. `PeerCloseKind::Tcp` (`:129`) is the only kind — deliberately **no `udp_closed`**, because the C has no such atom, so a `udp_inet` port never reports a peer close. `PeerCloseReport { port, owner, kind, exit_on_close }` (`:151`) is the term-free drained report; `PeerCloseLatches` (`:184`, `is_reported`/`mark_reported`/`forget`/`prune`/`len`) is the once-per-descriptor latch set keyed on *reported*, so the sticky re-fire works; the latches live in `PortExtras::peer_closes` and are dropped by `forget_port`.
`collect_peer_closes` (`:283`) gates on `is_tcp_inet` over `driver_path_name` (so a `{spawn_driver,"tcp_inet"}` port and a spelled object path both resolve) and reads `registry.port_closed(id)`; an error or `false` forgets the latch, because a number `beam_io` recycled after an unseen close must start clean; it then skips an already-reported number, gates on `inet_active`, reads `inet_exit_on_close`, marks reported and pushes. `drain_peer_closes`/`drain_peer_closes_for(to)` (`:263`/`:277`) wrap that one collect, the `-eval` form leaving a foreign recipient's latch **undrained** rather than dropping it; `forget_peer_close(number)` (`:392`) is the idempotent per-number half.
`inet_active` (`:406`) is the port's **mirrored** `{active,…}` (`inet_opts::PortInetOptions::active_mode`), because `beam_io`'s socket driver holds the state machine but exposes no accessor while the runtime observes every accepted `{active,…}` record; an **unknown mode is passive**, the C's own `inet_start` default (`inet_drv.c:10932`), because a fabricated `{tcp_closed,S}` is worse than none, and a passive observation **keeps its latch**, so a later `{active,…}` makes the report due (the C's sticky arm, `inet_drv.c:7013-7021`); `inet_exit_on_close` (`:415`) mirrors code 26 and defaults to `true` (`desc->inet.exitf = 1`, `inet_drv.c:10929`).
**Delivery, each half shaped like its `exit.rs` sibling.** `Runtime::deliver_peer_closes(&mut ProcessTable)` (`:454`) is the `run` route: it drains, skips an owner the table no longer holds (but still retires when `exit_on_close`), builds `peer_close_message` after the registry borrow drops, and delivers through `RuntimeContext::deliver_in_table` with the port as sender, so a receiver parked in `receive` wakes; `RuntimeContext::poll_peer_closes()` (`:535`) is the `-eval` route — `drain_peer_closes_for(self.pid())` returned inline, retiring when `exit_on_close` — and `peer_close_message` (`:565`) interns `kind.tag()` (`"tcp_closed"`) in the runtime's **one shared** table and builds `terms_tuple(&[tag, report.port.to_eterm()])` on the pointer-stable arena.
**Retirement is `driver_exit`, not `port_close/1`.** `PortRegistry::retire_peer_closed(id)` (`:378`) mirrors `tcp_recv_closed`'s `if (desc->inet.exitf) driver_exit(desc->inet.port, 0)` (`inet_drv.c:12835-12837`), which runs `unlink_proc` **before** it delivers (`io.c:7244`): it refuses a port the runtime no longer holds (tested before the mark), sets `PortExtras::no_owner_exit`, then calls the ordinary `close`, so the `'DOWN'` set is `signals_owner = false` — every monitor gets `{'DOWN', Ref, port, S, normal}` and a **trapping linked owner gets nothing**, measured on the oracle (`erlang:port_info(S, connected)` ⇒ `undefined`); those `'DOWN'`s become deliverable at the port's close **report**, so the caller's route reports them one round later, and `Runtime::retire_peer_closed_port(id)` (`:502`) skips a port already gone rather than folding that `badarg` into a delivery error.
**Owed (Known Issues).** The two consuming call sites in `src/port.rs` — `deliver_port_messages` and `poll_port_messages` — are absent, so the channel is compiled, unit-pinned and unreachable end to end until they land. **Residual.** A **spent** `{active,once}`/`{active,N}` grant is still mirrored as active, so a close observed after a grant is exhausted reports where the C would stay silent until re-armed.
Its 12 cases are `peer_closed_tests.rs`: the active-mode and `exit_on_close` mirrors, the latch's recycle rule, one report per descriptor, the passive-then-armed re-fire, `udp_inet` reporting nothing, the tag atom, the `'DOWN'`-only retirement, both delivery routes, the foreign-latch rule, and one real loopback peer close end to end.
