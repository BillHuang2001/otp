# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Built-in Drivers

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — one of the two clean rewrite seams (Part II §A): the layer reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**), so a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.

Hosts five things: the `mio`-backed **poller/reactor** (`Token`→registration map); the **`Port`** (a process-like I/O endpoint with input + output byte queues, a lifecycle, driver dispatch); **port-task scheduling** (`INPUT`/`OUTPUT`/`TIMEOUT` + reductions, `port_task.rs`, mirroring `erts_port_task_execute`); the **`Driver` trait + built-in drivers** (`fd`, `efile`, the OS-child `spawn`, the TCP `tcp_inet`, `{line, N}` buffering, the text⇄binary phase-change protocol); and the **driver C-ABI host layer** (`src/abi/`) — a `.so` loaded by `beam_abi::driver::loader` presented as a `Box<dyn Driver>` by [`DriverPort`], its `driver_*`/`erl_drv_*` calls served by [`AbiHost`] (a `beam_abi::driver::host::DriverHost` impl over this crate's poller/queues/timer), with atom interning (the one hook it cannot fill) the [`PortHost`] trait and [`DriverTable`] (`src/abi/table.rs`) the **process-global driver registry** (the C's `driver_list`) plus its port-creation service.

`beam_rt` (boot/`system_info`/driver registration) consumes and **drives this crate's ports**: one long-lived `Poller` + `PortRegistry`, a [`SpawnDriver`] from its decoded `open_port/2` terms, the port-task round (`execute_port_tasks`) from its main loop, and the resulting [`PortNotification`]s turned into `{Port,{data,…}}`/`{Port,{exit_status,…}}` delivered to the owning process (waking a blocked receiver through the `beam_process` scheduler). `beam_process` observes ports by id (the peer of pids in `ptab`). A C driver `.so` reaches the same `Driver` trait via [`make_loaded`] → [`DriverPort`], opened by `beam_rt` with `PortRegistry::open` exactly like a built-in. This crate is the **library**; the scheduler *thread* wiring (poll loop, port run queues) lives in `beam_rt`.

Legacy C ground truth (read-only): `../../erts/emulator/sys/common/erl_poll.c` + `erl_check_io.c` (poll loop, one-shot re-armed readiness, self-pipe wakeup), `../../erts/emulator/beam/io.c` (`erts_port_command`/`erts_port_control`, the `ioq` output queue), `erl_port.h`, `erl_io_queue.{c,h}` (`SysIOVec` queue), `erl_port_task.{c,h}` (the async work unit + reductions), `../../erts/emulator/drivers/common/inet_drv.c`, `../../erts/emulator/sys/unix/erl_child_setup.c` (`{line, N}` / binary phase-change).

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`. Only the **frozen contracts and non-obvious behaviour** are listed; rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque registration handle; **token `0` is the waker's**; user tokens start at `1`.
- `Interest` — readiness mask (`READABLE`/`WRITABLE`/`BOTH`). · `Ready` — observed readiness, **no public constructor** (only `Ready::default()` and `From<Ready> for Readiness`). · `Event` — a readiness event (`token`/`key`/`ready`); `Event::new` lets tests forge one.
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`** created in `new()`; registered by raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks); `waker()` an infallible cheap clone.
- `Waker` — an `Arc`-backed, cloneable, thread-safe handle to that one wakeup handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).
- **Regular-file fallback (internal, no public signature change).** `mio`/epoll refuses regular files (`EPOLL_CTL_ADD` ⇒ `EPERM`), so `Poller::register` keeps a `libc::poll(2)`-backed fallback set: an unsupported descriptor is watched with `poll(2)` and its readiness **merged** into `Poller::poll` in the same `Event`/`Ready` shape; other ops treat both sources uniformly, any other `mio` error stays `BeamError::Io`, and `poll` never blocks indefinitely while the fallback set is non-empty (`FALLBACK_POLL_CAP`, 1 ms; zero wait when the fallback probe already fired).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — a single deadline; `Timer` — deadlines keyed by `u64`. · `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS = 4000`; `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS / 100 (40)`; `PORT_REDS_EXECUTE = CONTEXT_REDS / 4 (1000)`.
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`); `PortTask` (`Copy + Eq + Debug`).
- `PortTaskQueue` — one pending task per kind (dedupe), ordered by kind priority then FIFO `seq`, timeouts deadline-gated. `arm_timeout(deadline)` re-points/replaces a pending `TIMEOUT`, unlike the dedupe-by-kind `enqueue_timeout`, which cannot re-point.
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed), `is_idle()`, `From<Ready>`.
- `PortNotification::Data { port, bytes } | Closed { port }` — the seam the runtime turns into `{Port, {data, Data}}`/port-exit messages. · `PortTaskOutcome { pub ran, pub reds_used, pub notifications }` — one round's result.

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }`. · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` — the budget `handle_events` runs.
- `PortControl::CLOSE == "close"` — the one **reserved** control-op name (a namespace marker, not an enum: any other name is a driver verb).
- `PortCommandOptions { nosuspend, force }` — carried/validated but no-ops (M1 ports never busy; the BIF layer owns their effect once a busy-port command queue exists).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the endpoint, scheduling (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`) and exit/async (`take_exit_status`/`drive_async`/`notify_exit`) surfaces. **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`) refreshes the port timer from `Driver::next_timeout` via `refresh_timeout`: `Some(d)` arms/**re-points** the single `TIMEOUT` task at `d`, `None` clears it (a driver's declaration is authoritative until its next interaction). Re-exports `PortRegistry` so `crate::port::PortRegistry` resolves.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` keyed by port number; basic ops (`new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`). Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`); `execute_port_tasks` (port-number order under a reduction budget ⇒ a `PortTaskOutcome`); `schedule_events`/`schedule_readiness` (enqueue only — readiness ⇒ an `INPUT`/`OUTPUT` task per `read_ready`/`write_ready`, **only for directions the driver armed** (`driver::PortArms`)); `port_command` (queue output + schedule an `OUTPUT` task; the write happens in the task); `port_control` (the reserved `"close"` closes with an empty reply; **any other `op`** goes verbatim to `control(op, arg)`, its reply returned); `take_exit_status` (the reaped child status **once** — `Ok(None)` = no child / not yet exited / already reported); `schedule_timeout`/`cancel_timeout`/`next_deadline` (explicit port timers; `next_deadline` = the min over live drivers' `Driver::next_timeout`, clamping a poll timeout); `notify_port_exit` (`Driver::port_exit` **at most once**, port left live, independent of `close`/`stop`); `drive_async` (the async drive point — `Driver::drive_async`, once per port-task round).

### `driver.rs`
- `DriverFlags(u32)` — `Copy + Eq`; `SOFT_BUSY`. · `PortExitReason { Closed, OwnerExited, Normal }` — the port-exit notification vocabulary.
- `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number. (`pub(crate) PortArms` records the directions the driver armed; not public.)
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`), `control`, `timeout`, `next_timeout() -> Option<Instant>` (= `None`; the driver's **declaration** of its next deadline, mirrored into the port's `TIMEOUT` after each interaction, deadline-gated so it never fires early), `port_exit(PortExitReason)` (= `Ok(())`; the once-only, advisory port-exit notification, distinct from the teardown `stop`), `drive_async` (= `Ok(0)`; the `driver_async`-completion drive point, `DriverPort` overrides it with `poll_async`), `take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`; overridden only by `SpawnDriver`). New capabilities must be additive with defaults that keep the built-in drivers compiling.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"` and `"tcp_inet"`**.

### `drivers/` (each module's role is in the Routing Table)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver; **owns** its fds (closed on `stop`/`Drop`). Constructors `pipe`/`connected(read_fd, write_fd)`/`read_only`/`write_only`; line/phase modes (`with_line_mode`/`set_line_mode` (0 = unlimited)/`set_binary_mode`/`is_line_buffered`/`phase`/`set_phase`/`max_line_len`). `Driver`: `start` registers the read fd `READABLE`; `output`/`ready_output` drain `ctx.output()` to the write fd (`EAGAIN` ⇒ keep queued + arm `WRITABLE`); `ready_input` reads into `ctx.input()` (loops to `EAGAIN`, latches `read_eof` on `read(2)==0`, flushes a pending partial line at EOF, then **de-registers the read fd** so an exhausted — level-triggered fallback — regular file stops producing events; the fd stays attached/owned, so a post-EOF `ready_input` is still `Ok`). `control` verbs: `line [decimal(N) | "line,<N>"]`, `noline`, `binary`, `text`, `getopts` (reply `b"line,<N>"`/`b"binary"`); unknown ⇒ `BadArg`.
- `line_buffer.rs` — `LineBuffer` + `DEFAULT_MAX_LINE_LEN = 1024`: frames on `\n` (a preceding `\r` is kept as part of the terminator), splits a line longer than `max_len`, holds a partial line until `flush_all`/EOF.
- `binary_io.rs` — `Phase { Text, Binary }` + `PhaseChange`, the `erl_child_setup` text⇄binary phase machine, default `Phase::Binary` (byte-identical to raw passthrough); `handle` frames Binary as one raw frame and Text as line frames; `flush` returns the trailing partial line (Text only).
- `efile.rs` — `EfileDriver` (`name() == "efile"`) delegates byte movement to a composed `FdDriver`; `control` verbs `open <path>` / `close` / `path` / `eof` plus the delegated `line`/`noline`/`binary`/`text`/`getopts`. `open` works on **regular files** (poller `poll(2)` fallback) and on epoll-servable descriptors (pipes/FIFOs/char devices/sockets); `write_only`/`connected` write regular files too. `make_efile()` is its `DriverFactory` (the built-in `"efile"`).
- `spawn.rs` — `SpawnStream { Binary, List }` (`Default = List`): the `binary`/`list` option, applied by the **runtime** building `{Port, {data, Data}}` (the driver passes bytes through). `SpawnSpec { Spawn { command, argv }, SpawnExecutable { path }, Fd { fd } }` = the term-free `open_port/2` `Name` (`/bin/sh -c Cmd`; `argv`/`Path` direct, `Path` + `SpawnOptions::args`; or an adopted descriptor, no child); `command()` = the `port_info(Port, name)` value (`fd:<N>` for the descriptor form). `SpawnOptions { stream, cd, env, args, exit_status }` (`Default`: `list`). `build_command(spec, options)` sets the argv, shell-vs-direct, `{cd, …}`/`{env, …}` and standard streams (`stdin`/`stdout` piped, `stderr` `/dev/null`) — `None` for `SpawnSpec::Fd`, `BadArg` for an empty argv; it starts nothing, so it is unit-testable alone. `SpawnDriver` (`name() == "spawn"`) is constructed directly, **really spawning** in `new(...)` and reaping eagerly (see *Design Decisions*); accessors `os_pid`/`command`/`stream`/`eof`/`exited()` (a plain liveness probe)/`take_exit_status()` (the `exit_status` option, once). `start` registers the descriptors; stdout → the port input queue (drained to `EAGAIN`, EOF latched + deregistered/closed); stdin drains the output queue (`O_NONBLOCK`; `EAGAIN` leaves the remainder queued + arms write readiness; a write failure is `BeamError::Io`); `stop`/`Drop` kill + reap + deregister/close every descriptor; spawned descriptors are owned/closed, an adopted `{fd, N}` **never** closed.
- `inet/` (`mod.rs` + `wire.rs`) — `DRIVER_NAME = "tcp_inet"` = the name `port_info(Port, name)` reports and `prim_inet` opens; `make_tcp_inet()` = its `DriverFactory`. `TcpInetDriver` (`name() == "tcp_inet"`) = a non-blocking TCP socket behind a port; `from_socket(fd)` adopts a descriptor and probes its kernel state (`SO_ACCEPTCONN` ⇒ listening, `getpeername` ⇒ connected, else open), like `inet_ctl_fdopen`; `connect_error()` = the late `SO_ERROR` of a non-blocking `connect`; `InetState` = the socket state. Control verbs (the C `INET_REQ_*`/`TCP_REQ_*` codes) ⇒ replies: `open`/`listen`/`close` `[1]`; `bind` `[1] ++ port_be16`; `accept` `[1] ++ fd_be32` (bare `[1]` if nothing pending, `[0]einval` if not listening); `connect` `[1]` (or `[0]exbadport`/`[0]eisconn`/`[0]einval`/`[0]++errno`); `send`/`recv`/`shutdown` `[1]` (or `[0]enotconn`). Operational failures = `[0] ++ lowercase-errno-name` (`erl_errno_id`); malformed args / unknown verbs ⇒ `BadArg`; packed addresses use `INET_AF_INET`/`ANY`/`LOOPBACK`. Flow control mirrors `FdDriver` (`MSG_NOSIGNAL`; `EAGAIN` keeps the remainder queued + arms write readiness; a drained queue drops writability and applies a deferred `shutdown`; reads drain to `EAGAIN` and latch EOF; `EINPROGRESS` arms write readiness). **Deferred** (module docs): the second-port `accept`, the async-op queue, `driver_set_timer` timeouts, `fdopen`/`sendfile`/`unrecv`/`getopts`/`setopts`/`getstats`/`getfd`/`ignorefd`, `recv`'s timeout/length, IPv6/UDP/SCTP/Unix-domain sockets, `{active,…}` modes, DNS (literal addresses).

### `src/abi/` (`mod.rs` + `host.rs` + `job.rs` + `port.rs` + `table.rs`) — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a [`Driver`](src/driver.rs) — the only place here holding raw `ErlDrv*` pointers and calling foreign code; a `pub` sub-tree (`pub use crate::abi::*`).
- `mod.rs` — module docs (the derivation, the stable `ErlDrvPort` handle, the built-in/`.so` unification, the `unsafe`-module marking, where each of the four process-global `driver_*` slots reaches or refuses) + `pub mod host; job; port; table;` + re-exports.
- `host.rs`:
  - `pub trait PortHost` — the runtime hook `beam_io` cannot fill: required `intern_atom(name) -> Option<Eterm>`; defaulted `connected_pid()`/`caller_pid()` (`None`) and `send_term(to, term) -> bool` (`false`; the sink for `erl_drv_output_term`/`erl_drv_send_term`, `to == None` = the port owner). **A locally-interned atom does NOT match the runtime's atom table** — `beam_rt` MUST inject its own `PortHost` over the shared table.
  - `pub struct LocalAtomPortHost { atoms: AtomTable }` — a **test/standalone** host only (seeds names in order; inherits the optional defaults; *not* the runtime's table).
  - `SelectedFd { token, interest }` (`pub(crate)`) and `DriverState` — the port's persistent C-ABI state: `selected: BTreeMap<RawFd, SelectedFd>` (a `BTreeMap` so `ready_input`/`ready_output` pick a **stable** fd), `deadline: Option<Instant>` (the `driver_set_timer` deadline), `jobs: AsyncJobs`.
  - `AbiHost` — the `DriverHost` impl, **owning** everything (`port_host: Box<dyn PortHost>`, `heap: Heap`, `state: DriverState`, `driver: Option<DriverIdentity>`, `ctx: Cell<*mut c_void>`) so it `Box`es behind a stable `ErlDrvPort` (a `DRIVER_HEAP_WORDS = 1024`-word term heap). With **no context installed** every port-touching method fails gracefully (`-1`/`None`/no-op), never derefs null. Behaviors: `intern_atom`/`connected_pid`/`caller_pid`/`send_term` → `PortHost`; `output` → the port's **input** queue (`0`/`-1`); `select(_, event, mode, on)` → `fd = event as usize as RawFd` (the C's fd-cast): `on != 0` registers / **re-registers in place** (interest updated) / `on == 0` de-registers (unknown fd ⇒ `0`), READ→READABLE, WRITE→WRITABLE, both→BOTH, **neither→READABLE** (M1 ignores `ERL_DRV_USE`; the fd must still be watched for close/error); `set_timer` arms `deadline` (`0`), `cancel_timer` clears it (`0`), `read_timer` = remaining ms (`Some(0)` expired, `None` none); `r#async` → `AsyncJobs::schedule` (`id as c_long`; thread failure runs the driver's `free(data)` and returns `-1`); the four **driver-registry** hooks → `add_driver_entry` records `de` in `DriverTable` (`0`; `1` the entry's `init` refused it — assertable only because the C's `void` wrapper discards that code, positive staying distinct from the trait default `-1` = "no current host"), `remove_driver_entry` forwards `1`/`0`/`-1`, `lock_driver` `0` for a `dlopen`ed-driver port (the C consults the **port's own** driver, never a name lookup) / `-1` for a bare/static host, `create_port` = `ERTS_INVALID_ERL_DRV_PORT` (see *Design Decisions*).
  - `DriverIdentity { name, loaded }` (`pub(crate)`) — the port's registered driver name + whether it came from a `dlopen`ed object; `AbiHost::new` = none, `AbiHost::for_driver(host, name, loaded)`/`with_driver(...)` record one (`DriverPort::from_library` sets it from `library.name()`, `loaded = true`). A field on `AbiHost`, **not** a `DriverHost` method.
- `job.rs` — `AsyncJobs`: one `std::thread` per job, an `mpsc` completion channel and the `driver_async` queue position; `schedule(invoke, data, free)` (`None` `invoke` = fire-and-forget: a valid position, no work, no completion) and `drain() -> Vec<AsyncCompletion>`; `AsyncData(*mut c_void)` is the one `unsafe impl Send`. **Deviation:** `async_free` runs on the **port** thread (the C uses the worker).
- `port.rs`:
  - `DriverPort` — a loaded `ErlDrvEntry` as `impl Driver` (`lib: Arc<DriverLibrary>`/`name`/`command`/`abi: Box<AbiHost>`/`env: Box<DriverEnv>`/`data: ErlDrvData`). The library is an **`Arc`** so the process-global table can keep one loaded object registered while ports are created from it (several ports share one `dlopen` handle; `DriverLibrary::drop` — `finish` + `dlclose` — runs with the last owner). `DriverPort::load(...)` calls `beam_abi::driver::loader::load` (validating `command` **first**, so an interior NUL is `BadArg`, not a load failure), mapping `DriverLoadError` to `BeamError::Raise(Raise::error(ExitReason::atom(err.reason_atom())))` (`unspecified_error` unopenable; `no_driver_init`/`bad_driver_name`/`driver_incorrect_version`/`driver_init_failed`); `DriverPort::from_library(Arc<DriverLibrary>, CString, host)` wraps an **already loaded** object without a second `dlopen` (the registry's port-creation path; does **not** re-run `init`). `env` + `abi` are **both boxed**, so the `ErlDrvPort` a driver sees is the **same pointer for the port's whole life** (the C guarantees `&prt->drv_port` never moves).
  - `poll_async` — drains the jobs, sorts by queue position (deterministic, the C's order), runs `ready_async` if the entry has one else the driver's `async_free`; `beam_rt` calls it from the port-task round. `make_loaded(path, name, command, host) -> Result<Box<dyn Driver>>` is the built-in/`.so` unification helper (see *Design Decisions*).
  - **Current-host publication** — `DriverPort::call` wraps every callback it routes (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`port_exit`/`stop`, plus `poll_async`'s `ready_async` branch) in `beam_abi::with_current_host`; `poll_async`'s `async_free` branch (which bypasses `call`) publishes separately. These are the only paths running driver code, so the two port-less slots (`add_driver_entry`/`remove_driver_entry`) reach a host during a callback and answer the C's failure value outside one — **scoped to this crate's `abi::DriverPort` only; the running runtime's `.so` path is `beam_rt`'s own `DriverPort`, which publishes no current host (see Known Issues).** The published `&mut dyn DriverHost` comes from a raw `*mut AbiHost` (the `Box` the port owns) with a documented `// SAFETY:` rationale, so it does not conflict with `call`'s shared borrow.
  - `Driver` mapping: `name` = the entry's name; `flags` = `SOFT_BUSY` iff `ERL_DRV_FLAG_SOFT_BUSY` (other `ERL_DRV_FLAG_*` bits have no counterpart); `start` (absent slot or any of `ERL_DRV_ERROR_GENERAL`/`ERRNO`/`BADARG` ⇒ `BadArg`, else keeps the `ErlDrvData`); `output`/`ready_output` (drain the port output queue; absent `ready_output` falls back to `output`; drained bytes treated as written — the C callbacks are `void`); `ready_input` (the read-armed fd, else null; absent ⇒ no-op); `timeout` (call, then clear `deadline`); `control` (the `&str` command is a **decimal `c_uint`**; absent slot or `cres < 0` ⇒ `BadArg`; reply copied from `*rbuf`, `n` bytes, into a `CONTROL_REPLY_CAPACITY = 4096` buffer); `next_timeout` = `state.deadline`; `port_exit` → `process_exit` (null `*mut ErlDrvMonitor`) if present, else `emergency_close` if present, else no-op; `take_exit_status` = default `Ok(None)`; `stop` (absent ⇒ no-op).
- `table.rs` — the **process-global driver registry + its port-creation service** (the `beam_io` half of the four `ErlDrvApi` slots, reached through [`AbiHost`](src/abi/host.rs)). `unsafe`-marked (stores/derefs `*mut ErlDrvEntry`, calls the entry's `init`); the one `unsafe impl Send for Inner` (mutex-serialized) carries a rationale.
  - `DriverTable` — `global()` (the C's one `driver_list`; `OnceLock`) / `new()` (isolated, tests). `add_entry(*mut ErlDrvEntry)` (**`unsafe`**; the C's `add_driver_entry`) records a **statically linked** entry after running its `init` (`Option<fn() -> c_int>`; non-zero ⇒ the `driver_init_failed` raise and **no** registration, matching `erts_add_driver_entry`'s "remove it again"); null entry/name ⇒ `BadArg`. `add_loaded(DriverLibrary)` records a **dynamically loaded** driver (`entry()` + `.name()` + `Arc<DriverLibrary>` handle) without re-running `init`. `remove_entry(*mut ErlDrvEntry)` (safe — address comparison) answers the C's `-1` (dynamic: *"Not allowed for dynamic drivers"*) / `1` (removed) / `0` (not found), newest first. `lock_driver(name)` = `0` (locked; has a handle) / `-1` (no handle = statically linked, or unknown). `lookup(name) -> Option<RegisteredDriver>` (newest wins, the C's head-inserted list) / `names()` / `len()` / `is_empty()`. `create_port(&mut PortRegistry, &mut Poller, name, command, host) -> Result<PortId>` resolves the registered driver, builds a `DriverPort::from_library` and opens it via `PortRegistry::open` (so `start` runs and supplies the instance's `ErlDrvPort`); the table lock is **released before** `start`, so a driver may re-enter the table.
  - `RegisteredDriver { name, entry: *mut ErlDrvEntry, dynamic, locked }` — the read-only snapshot.
  - **Deviation:** the C's `driver_create_port` re-uses the *creating port's* driver instance and stores the caller's `drv_data` verbatim; here a **fresh** instance is created by running `start` (no shared instance across ports), so no `drv_data` operand is accepted — it is `start`'s return.
  - **M1 gap:** `create_port` needs a [`Driver`] adapter, which exists only over a loaded `DriverLibrary`; a **statically linked** registration answers the typed `notsup` raise (never a wrong port).

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures ⇒ `BeamError::Io`, argument faults ⇒ `BeamError::BadArg`, id/registration exhaustion ⇒ `BeamError::SystemLimit`. **Never panic** on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` is confined to the raw-fd syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`close`) and `mio::unix::SourceFd` construction. Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean (`--workspace` lint).
- **Port ids are allocated by `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate (via `beam_process::PortId`); a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**; concurrent registration/dispatch is unsupported. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound. (Not yet enforced on `Poller`/`Waker` — the `Waker` is explicitly meant to cross threads.)
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures. New driver capabilities must be additive with defaults that keep the built-in drivers compiling.
- Files target ~1000 lines, split by responsibility: poller / port / registry / port_task / driver / timer / queue / drivers.
- Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only. No new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge the C-ABI host layer requires).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so an io_uring/`/dev/poll` backend is a drop-in (io_uring not M1).
- **One `mio::Waker` per `Poller`** (`mio` permits one per `Poll`), created in `new()`, shared by `Arc` clone (`Poller::waker` — idempotent, safe to drop); `Poll` returns an owned `Vec<Event>` (reusing the internal `mio::Events` buffer) so the glue can hold `&mut Poller` while iterating.
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends and calls `Driver::output`, which **pulls** from `ctx.output()`; `EAGAIN` queues the remainder + arms `WRITABLE` (no double buffering).
- **Task execution here; the scheduler thread above.** `PortTask`/`PortTaskKind`/`PortTaskQueue`/reductions model `erl_port_task.h`; the poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`. `PortNotification` is the seam so the runtime (not this crate) turns port output into messages and wakes the owner via `beam_process` (clean DAG, engine/runtime split intact).
- **Readiness ⇒ task, gated by `PortArms`.** The poller keys by port number, so an `Event` names the port, not the fd; `DriverContext` records the armed directions in `PortArms`, so a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) does not schedule a bogus OUTPUT task on a read-only driver (what the C gets from per-event handles `ErlDrvEvent`). **Divergence:** the C keeps three FIFO queues, no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT), `seq` tie-break — observable only in the order two *different* kinds run in a round.
- **`handle_events` schedules *and* runs the default round**; full budget control = `schedule_events` + `execute_port_tasks`. It does **not** harvest `PortNotification`s (input stays in the port queue, via `Port::drain_input`; closes unreported) — only `execute_port_tasks` yields `Data`/`Closed`.
- **Driver = Rust trait; the bridge is a `Driver` over a loaded `ErlDrvEntry`.** Built-ins implement `Driver` directly; the frozen `ErlDrvEntry`/`ErlDrvApi` is an ABI, so `DriverPort` adapts it over a `DriverLibrary` (`start→init/start`, `output→output/outputv`, `ready_input`/`ready_output`/`control`/`timeout`/`stop`, `driver_select` ⇒ `DriverContext::register`), changing no `Driver`/`Port`/`PortRegistry` signature.
- **The four driver-registry slots: two process-global, `driver_lock_driver` per-port, `driver_create_port` refuses.** `add_driver_entry`/`remove_driver_entry` act on the process-global `DriverTable`, so they reach a host only via `beam_abi::with_current_host`; this crate's `abi::DriverPort` publishes around every callback it routes, so inside one they reach the table and outside one answer the C's `-1`/`0` — **that publication belongs to this crate's `abi::DriverPort`; the running runtime drives `.so` drivers through `beam_rt`'s own `DriverPort`, which does not publish a current host, so end-to-end these slots answer their no-host defaults (see Known Issues).** `driver_lock_driver` consults the port's **own** driver (the C's `prt->drv_ptr->handle`), never a name lookup: a `dlopen`ed `DriverPort` ⇒ `0` (table touched only for its `locked` flag), a bare/static host ⇒ `-1`. `driver_create_port` ⇒ `ERTS_INVALID_ERL_DRV_PORT` because a callback already holds a `&mut` into the port registry (re-entering `PortRegistry::open` would be unsound aliasing) and a new port needs a `Box<dyn PortHost>` only `beam_rt` can supply — the C's own sentinel, never a fabricated port.
- **One boxed `AbiHost` behind a stable pointer; the live port is reached via an installed `DriverContext`.** A `DriverHost` method runs inside a callback, where the port exists only as that borrowed context; with none installed every port-touching method fails gracefully (never derefs null). `DriverEnv` is lifetime-erased (one `*mut dyn DriverHost`), kept valid for the `DriverPort`'s life.
- **`driver_output` is harvested by a non-empty input queue, not an `INPUT` task.** `AbiHost::output` pushes onto the port's *input* queue; `Port::take_input_notification` reports+drains `Some(PortNotification::Data)` whenever non-empty. A driver calls `driver_output` from `start`/`control`/`timeout`/`output`/`ready_input` — *outside* any `INPUT` task — so gating on task completion would drop those bytes; the queue delivers every `driver_output` once per round.
- **The port thread owns `async_free` in M1; jobs drain in queue-position order** (the C runs `async_free` on the **worker**; here the completion is recorded and the port thread decides — a deviation, never a leak). `poll_async` sorts by `driver_async` queue position (the C's order under concurrency).
- **Built-in and loaded unify at `Box<dyn Driver>`; the `.so` path is a helper, not a registry method.** `make_loaded(...)` presents a loaded `.so` as the same `Box<dyn Driver>` `DriverRegistry::create` returns for a built-in; it cannot be a `DriverFactory` (`fn()` pointer) — it needs a path/name/command/`PortHost`, as does `SpawnDriver`. `DriverRegistry`/`open_named` stay frozen.
- **`control` is numeric for a loaded driver.** Built-ins use string verbs (`"close"`, `"line"`, …), a C driver's are integer `INET_REQ_*`-style codes, so `DriverPort::control` parses the `&str` as a decimal `c_uint`; absent slot or `cres < 0` ⇒ `BadArg` (`io.c:4035`/`io.c:4074`). Reply = `cres` bytes at `*rbuf` (our `CONTROL_REPLY_CAPACITY = 4096` buffer, or the driver's own memory valid until the next call) — a **trust boundary** (a driver is native code).
- **`set_timer` always succeeds; `read_timer` = remaining ms, `None` only when disarmed.** The C refuses `driver_set_timer` with no timer (`if (prt->timeout == NULL) return -1;`), but this port always has one (expired ⇒ `Some(0)`, as the C writes `0`); `beam_abi`'s `driver_read_timer` maps `None` ⇒ `-1` (deviation from `io.c:6936`, which answers `0`/`0`).
- **`ready_input`/`ready_output` name the fd from the driver's own `driver_select` bookkeeping.** The poller keys by **port number**, so a readiness event names the port, not the fd (the C carries it per-`ErlDrvEvent`); `DriverState::selected` (a `BTreeMap`) restores it — M1 passes the stable first fd in the wanted direction (fd order), one callback per round — a floor for a port with several fds selected the same way.
- **The `beam_io → beam_abi`/`beam_alloc` edge (directionally legal).** Wave 5 → wave 0; `beam_abi` is the frozen ABI to adapt, `beam_alloc`'s `Heap` the term arena a driver builds terms on. No cycle, no `*_dev` edge.
- **Line/phase framing is driver-side.** `{line, N}` + text⇄binary live in `FdDriver` (via `LineBuffer`/`PhaseChange`), matching `erl_child_setup`: the line flag affects how a port *delivers input to its owner*, not output acceptance. Default phase Binary.
- **Exit status via a defaulted trait method, not a notification variant.** The runtime needs a child's reaped status **once** for an `exit_status` port without reaching into driver internals: defaulted `Driver::take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`, so `FdDriver`/`EfileDriver` compile unchanged) + additive `PortRegistry::take_exit_status(id)` — `Ok(None)` = "no child"/"not reaped"/"already reported", `Result` so a failing `wait` is reported. A `PortNotification` variant is rejected: exit status is not a *task-round* outcome (neither readiness- nor reduction-driven) and would force every round to carry a status the port may not owe.
- **The spawn driver is constructed, not registered — and reaps eagerly.** A `DriverFactory` is a no-arg `fn` and cannot carry the command/argv/options, so it is built directly from a `SpawnSpec` (`Driver::name()` stays `"spawn"` for `port_info`). The child starts in the **constructor**, so a failed spawn registers nothing and the runtime can read `os_pid()` before `PortRegistry::open`. `{fd, N}` adopts one descriptor as a **duplex** stream (one `Interest::BOTH`; `arm_output`/`disarm_output`/`release_stdout` no-ops) and never closes it (the Erlang side owns it, matching `LivePort::close`). `stop`/`Drop` kill **and** reap (an already-exited child via `try_wait`, no kill) — `Drop` reaps because Rust's `Child` does not, else a zombie leaks.
- **Regular files ride a `poll(2)` fallback inside the poller.** `epoll` cannot watch a regular file, so `Poller` keeps a second `libc::poll(2)`-based set for descriptors `mio` rejects and merges its readiness into `Poller::poll` — the reference path ("a regular file is trivially always ready", `erts/emulator/sys/common/erl_poll.c`) with no API change and no new dependency; being level-triggered, it forces `FdDriver` to de-register a read fd at EOF.
- **A failed spawn raises the errno atom.** A **direct-exec** spawn failure (a missing program, `EACCES`, `ENOTDIR`, …) is a `BeamError::Raise` carrying the errno's lowercase name (`enoent`/`eacces`/`enotdir`/…), matching the oracle — the reference raises `erl_errno_id(errno)` from `erts_internal_open_port_2` (`erts/emulator/beam/erl_bif_port.c`); an unmapped errno falls back to `BeamError::Io` (see `src/error.rs`).
- **The child's stderr is discarded (`Stdio::null()`), not piped** — a piped-but-undrained stderr deadlocks a child past the pipe capacity, and a child's stderr is not port data (the oracle does not deliver it either); `build_command` sends it to `/dev/null`. No `stderr_to_stdout` option.
- **Timer seam driver-declared + mirrored; port-exit channel advisory + once-only.** `Driver::next_timeout` is mirrored into the single `TIMEOUT` task after each interaction (deadline-gated, never early), with `PortRegistry::{schedule_timeout,cancel_timeout}` as the runtime's explicit override; `Driver::port_exit` fires at most once, distinct from the teardown `stop`. Both additive defaults.
- **The TCP driver is a floor, not a full `inet`** — see the module docs for the deferred verbs.

## Known Issues
- **The A.4 driver-registry hooks here are correct and tested, but the running runtime does not use this crate's host layer.** The four hooks live in `src/abi/host.rs` over `src/abi/table.rs`'s process-global `DriverTable` and are reachable only through this crate's own `abi::DriverPort` callback path (which wraps each callback it routes in `beam_abi::with_current_host`); the runtime's `.so` driver path belongs to `beam_rt` (`crates/beam_rt/src/port/driver.rs`, its own `impl DriverHost for DriverPort`), and nothing outside `beam_io` references `beam_io::abi`/`make_loaded`/`AbiHost`/`DriverTable`, so end-to-end the four slots answer the C's failure defaults: `driver_lock_driver(<port>)` from a driver's `start` ⇒ oracle `0`, Rust `-1` (the `lock_driver` hook is left at its trait default); `add_driver_entry(&e)`+`remove_driver_entry(&e)` from a callback ⇒ oracle `1`, Rust `0`; `driver_create_port(<port>, 0, <an unknown name>, NULL)` ⇒ oracle blocks forever (never call it in a test), Rust returns the invalid-port sentinel; `enif_alloc_env()` in a real NIF ⇒ oracle a live env (`ok` round-trips through `enif_make_copy`), Rust NULL. Closing the gap is a `beam_rt` change: override the four hooks on its `DriverPort` and wrap its driver callbacks in `beam_abi::with_current_host`.
- **The C-ABI host layer is a floor; a driver must not stash `ErlDrvPort` beyond the callback in M1.** The context is installed per callback (`install`/`clear` around each `DriverPort` call), so a driver that keeps the handle and calls `driver_*` outside a callback (e.g. its own worker thread) gets the C's `-1` (a `driver_output` from a plain `std::thread` returns `-1`; its bytes are dropped). The handle *pointer* is stable for the port's whole life; the **installed context** is callback-scoped. `ready_async` receives no port (`erl_driver.h`), so a driver that needs it there uses the handle it stashed in `start` — which works because `poll_async` runs inside a `DriverPort` method with the context installed; only the completion hand-off (`ready_async`/`async_free`) is driven, via `Driver::drive_async`.
- **`driver_async` has no `PortTaskKind::Async`: `beam_rt` must call `PortRegistry::drive_async(poller, id)` once per port-task round for a port with pending jobs** (the C's `call_async_ready`). Completed jobs reach `ready_async`/`async_free` only there — no readiness/reduction task does it (a `PortTaskKind::Async` is a documented follow-up).
- **`beam_rt` must inject a real `PortHost` (handoff).** A driver's `erl_drv_output_term`/`erl_drv_send_term`/`driver_mk_atom` gets its atom from `PortHost::intern_atom`; a locally-interned atom (`LocalAtomPortHost`, tests/standalone) does **not** match the runtime's table, so the term compares unequal to the same atom built by running code — a silently wrong result. `beam_rt` owns the shared `beam_term::atom::AtomTable` (`beam_engine`'s `ExecutionContext`/`beam_bifs`' `AtomInterner`), so it supplies `PortHost` (intern into it; `connected_pid`/`caller_pid`/`send_term` over the process/message path).
- **`ErlDrvApi` slots served vs. deferred (handoff to `beam_abi`).** The four **driver-registry** slots are served through this crate's host layer (end-to-end status per the first known issue). The rest are `None` in `beam_abi`'s `DRIVER_API` (`DriverHost` has no method); each group lists the `DriverHost` methods `beam_abi` must add:
  - **port queues** — `driver_vec_to_buf` + the `driver_enq`/`driver_pushq`/`driver_deq`/`driver_sizeq`/`driver_peekq*`/`driver_enqv`/`driver_pushqv` family. Needs: `enq`, `enq_bin`, `pushq`, `pushq_bin`, `deq`, `sizeq`, `peekq`, `peekqv`, `enqv`, `pushqv`, `vec_to_buf`.
  - **port lifecycle & attributes** — `erl_drv_init_ack`, `erl_drv_set_os_pid`, `erl_drv_busy_msgq_limits`, the `driver_failure*`/`driver_exit` family, `set_busy_port`, `set_port_control_flags`, `get_port_flags`, `driver_async_port_key`, `driver_get_now` (deprecated), `driver_binary_get_refc`/`inc_refc`/`dec_refc`. Needs: `init_ack`, `set_os_pid`, `busy_msgq_limits`, `failure_eof`/`failure_atom`/`failure_posix`/`failure`, `exit`, `set_busy_port`, `set_port_control_flags`, `get_port_flags`, `async_port_key`, `get_now`, `binary_get_refc`/`binary_inc_refc`/`binary_dec_refc`.
  - **monitors & port data lock** — `driver_monitor_*` needs `monitor_process`/`demonitor_process`/`get_monitored_process`/`compare_monitors`; `driver_pdl_*` needs a port-data-lock accessor group.
  - **async thread pool** — `driver_async_port_key` (the "fair" key derives from the port's id term, which the seam cannot represent).
  - **threads** — `erl_drv_mutex_*`/`erl_drv_cond_*`/`erl_drv_rwlock_*`/`erl_drv_tsd_*`/`erl_drv_thread_*`/`erl_drv_*_name`. Needs `mutex_*`/`cond_*`/`rwlock_*`/`tsd_*`/`thread_*` + the `*_name` accessors.
  - **deliberately `None`** — the binary-refcount trio (`driver_binary_get_refc`/`inc_refc`/`dec_refc`): `ErlDrvBinary` is exactly `{ orig_size, orig_bytes }` (16 bytes), no refcount word, so nothing to report/adjust.
- **Single-OS-thread only.** No poll threads, no `ThreadProgress`/generation handoff, no `ERTS_POLL_USE_WAKEUP` beyond `Waker`; the invariant is enforced on `Port`/`PortRegistry` (see Constraints) but **not** on `Poller` — use it from one thread.
- **Readiness is edge-triggered** (`mio` `EPOLLET`), so a driver *must* drain to `EAGAIN` per callback — `FdDriver` reads/writes in an `EAGAIN`-terminated loop. Readiness is scheduled only for directions the driver armed (`PortArms`), so an unregistered direction never fires.
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop. No port run queue, no dedicated poll thread.
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output (the emulator's line flag). No `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Decoding `open_port/2` into [`SpawnSpec`](src/drivers/spawn.rs)/`SpawnOptions` (and synthesizing `{Port, {data, …}}`, `{Port, {exit_status, …}}`, `{Port, eof}`) stays the runtime's job — this crate only moves bytes and kills/reaps. EOF is signalled only by latching state (`eof()`), not an event. Writing to a child that closed its stdin fails with a typed `BeamError::Io` (the remainder is kept). Adoption requires non-blocking (`F_SETFL` + `O_NONBLOCK`); a descriptor that refuses (some inherited ones ⇒ `EPERM`) fails the open with `BeamError::Io` (the edge-triggered reactor cannot serve a blocking one). Input is not line-framed (no `line` verb): the `binary`/`list` choice rides `SpawnStream` for the runtime. End-to-end `port_command` to `{fd, N}` is still `unsupported` in `beam_rt` (a handoff).
- **`port_control`/control atoms are not decoded here.** `port_control(op, &[u8])` takes a `&str` op + raw bytes; the C decodes Erlang tuples in `io.c` — decoding `{command, …}`/`{connect, …}` is the runtime's job.
- **`mio` fd registration is `os-ext`/Unix-only** (`mio::unix::SourceFd`); Windows/iocp out of scope (as in `beam_abi`).
- **Residual `open_port` divergences.** `open_port({spawn_executable, "/etc"}, [])` (a **directory**) opens a port in the oracle (`ok`) but this crate's synchronous `Command::spawn` reports `eacces`; `open_port({spawn, ""}, [])` / `{spawn_executable, ""}` is `badarg` in the oracle (runtime name validation) while the driver would map an empty name to `enoent`. Both open handoffs (an `access(X_OK)` precheck / `beam_rt` name decoding).
- **The `tcp_inet` driver is a floor.** The async-op queue, per-op `driver_set_timer` timeouts, the second-port `accept`, IPv6/UDP/SCTP/Unix-domain sockets, `{active,…}` modes and DNS are absent; `recv` rejects a timeout/length argument with `BadArg`. Covered verbs match the C's reply shapes (oracle-cross-checked).
- **File sizes (source vs. in-module tests).** `src/port.rs` 610 source (the `Port` endpoint + its `PortRegistry` re-export; no in-module tests); `src/registry.rs` 1080 (≈490 source + ≈590 tests) — both sources under the ~1000 baseline. `src/drivers/inet/mod.rs` ≈991 source (wire vocabulary in `src/drivers/inet/wire.rs`, 182). `src/drivers/spawn.rs` 1071 (≈793 source + ≈278 tests) — over 1000 only for its in-module suite; if it grows, split the term-free spec (`SpawnSpec`/`SpawnOptions`/`SpawnStream`/`build_command`) into a sibling module, and the `tcp_inet` raw syscall helpers (`socket_fd`/`accept_socket`/`has_peer`/`local_port`/`is_listening`/`socket_error`/`shutdown_socket`/`close_fd`) into a third inet sibling. `src/abi/port.rs` 762 and `src/abi/host.rs` 1066 (≈601 source + ≈465 tests) — over 1000 only for their in-module suites; if either grows, split its test module into a sibling `tests/` file.

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks`. Keys are port *numbers* (`PortId::number()`).
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`); do not close them elsewhere. `EfileDriver` composes an `FdDriver`, so the same ownership rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- `Ready` has **no public constructor**: tests that need a specific readiness forge it through `Event::new(token, key, ready)` with a real `Ready` or through the public `schedule_readiness(key, Readiness)`.
