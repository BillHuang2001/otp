# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Drivers, io-device Requests, Signals, CPU time, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.
Hosts the `mio`-backed **poller/reactor**, the **`Port`** (a process-like I/O endpoint over a `Box<dyn Driver>` + two byte queues), **port-task scheduling** (`erts_port_task_execute`), the **io-device request layer**, the **`Driver` trait + built-in drivers** (`fd`, `efile`, OS-child `spawn`, `tcp_inet`, `udp_inet`, `ram_file_drv`, `{line,N}` buffering, the text⇄binary phase change), the **driver C-ABI host layer** (`src/abi/`), and the safe raw-OS floors `beam_rt` (`#![deny(unsafe_code)]`) cannot issue itself: OS signals (`os:set_signal/2`), CPU time (`erlang:statistics(runtime)`), `ddll`, `fs_access`, `close_fd`.
Per-driver, `inet`, `abi` and io-device detail lives in the child nodes named by the Routing Table.

Four driver→owner side channels sit beside the port's own `{Port,{data,…}}` notification: the `{line,N}` frames (`LineNotification`), the completions (`PortCompletion`), the `{active,…}` deliveries (`ActiveInput`) and the failure latch (`PortFailure`).
`beam_rt` is the only consumer: it owns the poll loop, the port run queues and the scheduler thread, drives one long-lived `Poller` + `PortRegistry`, and renders those drains plus the once-only `take_exit_status`/`take_eof` as the owner's messages (`{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}`, `{Port,{data,{eol|noeol,_}}}`, the async/`{inet_reply,…}` set and the `{tcp,S,Data}`/`{udp,S,IP,Port,Data}`/`{tcp_passive,S}`/`{udp_passive,S}` set), delivering each to the owning process and waking a blocked receiver through `beam_process`, which observes ports by id (the peer of pids in `ptab`).
`take_failures` is the one channel no consumer drains yet (*Handoffs*), and `DynLib` the one facility with no consumer outside this crate.

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed, rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque handle; **token `0` is the waker's**, user tokens start at `1`. · `Interest` (`READABLE`/`WRITABLE`/`BOTH`/`ERROR`, **no empty mask**; `readable()`/`writable()`/`error()` constructors, `is_readable`/`is_writable`/`is_error` predicates and the `const fn add` union, so `READABLE.add(ERROR)` spells the driver/NIF `ERL_DRV_READ | ERL_NIF_SELECT_ERROR`) · `Ready` — observed readiness, **no public constructor** (`Ready::default()`/`From<Ready> for Readiness`) · `Event` (`token`/`key`/`ready`; `Event::new` lets tests forge one). **`Interest::ERROR` is a caller-intent bit, not an OS request**: no poll backend takes an error request (`erl_poll.c`'s `ev2pollev` maps only `IN`/`OUT`; `mio` 1.x's interest set is `READABLE`/`WRITABLE`/`AIO`/`LIO`/`PRIORITY`), while `epoll`/`kqueue` — and the `poll(2)` fallback's `POLLERR`/`POLLNVAL` — report error readiness unconditionally, so the delivery half is `Ready::is_error()` and the registration mask never suppresses it.
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`**; registers a raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks). `Waker` is the `Arc`-backed cloneable handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).
- **`poll` is `EINTR`-tolerant**: an `ErrorKind::Interrupted` wait is **retried** and the retry **preserves the deadline** (`poll(Some(d))` subtracts elapsed time; `poll(None)` resumes).
- **Regular-file fallback (internal):** epoll refuses regular files (`EPOLL_CTL_ADD`⇒`EPERM`), so `register` keeps a `libc::poll(2)`-backed fallback set whose readiness is merged into `poll` in the same `Event`/`Ready` shape; `poll` never blocks indefinitely while that set is non-empty (`FALLBACK_POLL_CAP`, 1 ms).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — one deadline · `Timer` — deadlines keyed by `u64`, self-contained (nothing in-crate consumes it): `schedule` replaces **any** deadline for a key, `pop_expired` returns due keys in **schedule** order. · `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS` is `beam_common::CONTEXT_REDS` (4000), re-exported (no local copy); `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = 40`, `PORT_REDS_EXECUTE = 1000`. `PortTaskOutcome::reds_used` models the per-kind cost only (the C also charges `ERTS_PORT_CALLBACK_VREDS` per task).
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout) · `PortTask` (`Copy + Eq`) · `PortTaskQueue` — one pending task per kind, ordered by kind **priority only** (`seq` is never a live tie-break); a not-yet-due `TIMEOUT` stays queued (divergence: the C dequeues it, charges 0 reds and drops it); `arm_timeout` re-points/replaces a pending `TIMEOUT`.
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed ‖ error — a poll error re-triggers **every** armed direction, the C's `ERTS_POLL_EV_ERR`), `is_idle()`, `From<Ready>`.
- `ReadMessage { header: Vec<u8>, body: Option<Vec<u8>> }` — one completed read with the C `driver_output2` header/body split preserved: one `ReadMessage` is one **`driver_output*` call**, never one byte chunk. `body: None` is the C's `buf == NULL`; `Some(vec![])` is a present empty body. Helpers `body_only`/`len`/`is_empty`/`has_body`/`flattened` (the `[list]`-mode byte sequence); the rustdoc carries the oracle-pinned shape table.
- `PortNotification::Data { port, read } | Closed { port }` — **exactly two variants** (exhaustively matchable by `beam_rt`: two arms, no wildcard); a round reports **one `Data` per `driver_output*` call**, in arrival order, and an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** channel a `{line, N}` port reports through (`ERTS_PORT_SFLG_LINEBUF_IO`), a struct rather than a third `PortNotification` variant precisely so that enum stays exhaustive. `header` is the producing read's `ReadMessage::header`, which the C prepends as cons cells to **every** frame that call completes; an empty `eol` frame is a real frame (a blank line is `{data,{eol,[]}}`).
- `ActiveInput { port, event }` / `ActiveInputEvent { Data(ReadMessage), Passive }` — the **separate `{active, …}` input channel**, built exactly like `LineNotification` so `PortNotification` keeps two variants and `CompletionEvent` gains none. `Data` is one delivered input with the header/body split preserved — the stream's `{header,N}` bytes (`hsz`, empty by default) with the `{packet,N}` framing header already stripped, the datagram's 7 packed source-address bytes (`wire::pack_address`) — two are never merged, and an empty body is a real delivery. `Passive` is a spent `{active,N}` counter (`packet_passive_message`) and carries **no atom**: the runtime picks `{tcp_passive,_}` vs `{udp_passive,_}` from the driving port's driver name.
- `PortTaskOutcome { ran, reds_used, notifications }` — `notifications` carries `PortNotification`s only; line frames ride `PortRegistry::take_line_notifications`, completions `take_completions`, `{active,…}` deliveries `take_active_inputs`.

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` · `PortControl::CLOSE == "close"` — the one **reserved** control-op name (any other name is a driver verb) · `PortCommandOptions { nosuspend, force }` — the `erlang:port_command/3` flag set, a `Copy` value the runtime validates once and then carries through every retry of a suspended command.
- `PortCommandOutcome { Done, Busy }` + `Port::command(&mut self, data, options) -> Result<PortCommandOutcome>` — the port layer's implementation of the C's `erts_port_output` busy arm and **the one place the decision table lives**: a non-`Open` port ⇒ `BadArg`; `[force]` on a driver **without** `DriverFlags::SOFT_BUSY` ⇒ the typed `notsup` raise (the crate's existing `error::notsup`, i.e. exactly what the C BIF raises), decided from the driver's **flag word** and **before** any output is attempted, so it is `notsup` busy or idle (`erl_bif_port.c:168-235`); `[force]` **with** `SOFT_BUSY` ⇒ `Done` with the busy state bypassed (`io.c:1731`, `busy_flgs = 0` under `FORCE`); idle ⇒ `Done`, bytes queued plus one `OUTPUT` task (`io.c:1763`); busy with a plain or `[nosuspend]` command ⇒ `Busy` **with nothing queued and no task** (`io.c:1763-1769`), the caller keeping the bytes and the runtime choosing between `false` and a suspend-then-retry (`PortCommandOptions`'s rustdoc carries the option→outcome table).
- `Port::is_busy()` / `Port::port_closed()` — the two driver-state accessors a runtime reads: the first forwards to `Driver::is_busy` (the `set_busy_port` state `Port::command` decides on), the second to `Driver::port_closed` (a **latched, sticky** peer/OS close, so a drain made a round late still sees it).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the scheduling surface (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`has_pending_task`/`next_task`/`timeout`), the exit/async surface (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`), the owner drains (`take_completions`/`take_active_inputs`/`take_line_frames`) and the failure latch (`take_failure`); re-exports `PortRegistry`.
- **Every driver interaction — `start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`drive_async`/`port_exit`/`stop`, nine of them — installs all four sinks** (`DriverContext::with_reads`/`with_completions`/`with_active`/`with_failure`); the timer path included because `Port::run_task`'s `Timeout` arm discards `Driver::timeout`'s `Result<()>`.
- The seven interactions that can plan I/O refresh the port timer from `Driver::next_timeout` (`Some(d)` **re-points** the single `TIMEOUT` task, `None` clears it). A driver write (`output`/`ready_output`) is **verified**: the output queue must shrink by exactly the count the driver reported (else the typed `error::unsupported(...)`), and a non-empty queue left behind schedules an `OUTPUT` task, so a short write cannot stall.
- Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (`Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof`=`driver_eof` point; a `close` never flushes). A round harvests raw-mode input as ≤1 `PortNotification::Data`; in line mode it stages `LineNotification` frames on an internal queue, so a line-mode port reports **nothing** through `PortNotification`.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number (`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`close`); `port_table`/`port_table_mut` expose that **same** id table. `close` runs the driver's `stop`, harvests whatever the driver staged before and during the teardown, drops the port and **retires the port number only when its `Closed` notification is reported**, so a deferred `Closed` can never name a reused id.
- Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`); `execute_port_tasks` (port-number order under a reduction budget; drives async completions *before* harvesting input); `schedule_events`/`schedule_readiness` (enqueue only, gated by `PortArms`); `port_command_with` (the registry surface of `Port::command`, answering the `PortCommandOutcome`; the write itself belongs to the scheduled `OUTPUT` task) and its legacy `port_command`, which keeps its `Result<()>` signature and is exactly `port_command_with(..).map(|_| ())`, so a caller that must tell "written" from "the port is busy" calls the `_with` form; `is_busy`/`port_closed` (the same forwarding accessors); `port_control` (reserved `"close"`; **any other `op`** goes verbatim to `control(op, arg)`); `take_exit_status`/`take_eof`; `schedule_timeout`/`cancel_timeout`/`next_deadline`; `notify_port_exit` (`Driver::port_exit` **at most once**, port left live); `drive_async`; `set_line_mode`/`flush_linebuf`; `take_failures` (the ports a driver closed from inside a callback, in reap order).
- The three owner drains share one shape and one rule — drain after **every** round, after **every** explicit driver interaction and after **every** `close`, because draining is what removes the entries: `take_line_notifications` (every live port's frames in **port-number order**), `take_completions` (every live port's completions in port-number order, then the `closed_completions` queue `close` fills) and `take_active_inputs` (the same for `ActiveInput`, then `closed_active`). A completion or delivery staged before or at a `close` is therefore reported **exactly once**.

### `port_failure.rs` — the driver-failure channel (the C's `driver_failure*`/`driver_exit`)
A driver *closing its own port* is neither a return value nor a message, so it gets its own channel; `PortNotification` keeps two variants and `PortCompletion` stays an owner message.
- `FailureReason { Eof, Normal, Atom(String), Posix(i32), Code(i32) }` — the C's whole family, with `atom_name()` (`normal`/the driver's atom/the errno's POSIX name via the crate's single errno table; `Code` ⇒ `None`), `code()`, `is_eof()` (the flag that makes a `{line,N}` port flush its partial line first) · `DriverFailure { reason, signals_owner }` + `eof`/`atom`/`posix`/`error`/`exit`: `signals_owner` is `false` only for `driver_exit`, which unlinks the owner **before** closing, so rendering an `'EXIT'` would invent a message the oracle never sends.
- Flow: a driver latches one through `DriverContext::signal_failure` (**exactly one**; the three `deliver_*` seams refuse afterwards, the C's `-1`), `Port::take_failure` collects it, and `PortRegistry::reap_failures` (**private**) tears the port down through the ordinary `close` path after the callback returned — `stop` runs, the port leaves the live map, already-staged input is reported ahead of the close, and the number is retired only by the deferred `Closed` report. `take_failures()` is the public drain.
- Wired into every entry point that drives a driver: `execute_port_tasks`/`handle_events` reap at the end of their round, and `output`/`port_control`/`drive_async`/`notify_port_exit` right after the single callback they made (a callback's own error is still the one reported).

### `driver.rs`
- `DriverFlags(u32)` (`SOFT_BUSY`) · `PortExitReason { Closed, OwnerExited, Normal }`.
- `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number (`pub(crate) PortArms` records the armed directions). Four delivery seams, each the typed `unsupported` without its sink (never flattened, never dropped) and each refusing once a failure latched in the same callback: `deliver_read(header, body: Option<&[u8]>)` (the `driver_output2`/`output_binary`/`outputv` seam; bytes banked on `input()` close into their own body-only read **first**) · `deliver_completion(event)` (the async/`{inet_reply,…}` side channel) · `deliver_active_input(event)` (an `{active,…}` delivery owed the **owner**, stamped with this context's own port and queued in call order) · `signal_failure(failure)` (the `driver_failure*`/`driver_exit` latch, a request and never a teardown). The sinks are installed by `pub(crate) with_reads`/`with_completions`/`with_active`/`with_failure`.
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`) · `control` · `has_control()` (**`false` iff the driver's C counterpart has `control == NULL`**, e.g. `ram_file_drv` — then `port_control/3` answers the oracle's `badarg`; `DriverPort` answers `entry().control.is_some()`) · `is_busy()` (the `set_busy_port` **state** half, `false` for every built-in — none ever marks its port busy — and overridden by `abi::DriverPort` from `AbiHost::is_busy`) · `port_closed()` (a **latched, sticky** peer/OS close for the runtime to render as `{tcp_closed, Port}`; `false` for a driver that cannot know, overridden by `drivers::TcpInetDriver` from its own `peer_closed()` latch) · `timeout` (its `Result<()>` is discarded — no reply channel) · `next_timeout()` (mirrored into the port's `TIMEOUT` after each interaction) · `port_exit(PortExitReason)` (once-only advisory, distinct from the teardown `stop`) · `drive_async` · `has_pending_async()` · `take_exit_status()`/`take_eof()` (only `SpawnDriver`). Further capabilities must be additive with defaults that keep the built-ins compiling.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`**.
- **The statically-linked (emulator `driver_tab`) set is a separate, narrower contract** — `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` + `is_static_spawn_driver`, `with_static_spawn_drivers()` and `create_static_spawn(name)`, which refuses a name outside the set with `BeamError::BadArg` (the oracle's `badarg` for `open_port({spawn_driver,"fd"},[])`) **even on a `with_builtins()` registry that registers them**. The set is exactly the oracle's `erl_ddll:loaded_drivers/0` answer: those three are linked into the emulator, never `.so`-loaded.

### `completion.rs` — the driver→owner completion side channel
A side channel beside `PortNotification` (two variants) and the `{line,N}` frames: a driver reports an asynchronous outcome here and the runtime turns it into the oracle's message.
- `PortCompletion { port, event }` — the port id stamped by `DriverContext::deliver_completion`, never by the driver.
- `CompletionEvent { InetReply { caller_ref: Option<Vec<u8>>, reply: InetReply }, InetAsync { id: u16, result: InetAsyncResult } }` — the `{inet_reply, Port, Reply[, Tag]}` and `{inet_async, Port, Id, Result}` shapes.
- `InetReply { Ok, Error(InetReason) }` · `InetReason { Closed, Timeout, Errno(i32) }` (`atom_name` = the lowercase POSIX name, with the C's `errno_<N>` fallback) · `InetAsyncResult { Ok, Data(ReadMessage), Accepted { fd }, Port(PortId), Error(InetReason) }`. `Data` keeps the header/body split; `Accepted` hands the descriptor over **owned** — the driver never stores it, so no teardown path can close it.
- Term-free: `caller_ref` is the `prim_inet` caller tag carried **verbatim** (a 131-led `term_to_binary(Mref,[local])` image); this crate never decodes it.

### `drivers/` (per-driver roles, verb tables, constant tables and suites: `src/drivers/CONTEXT.md`)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver: **owns** its fds (closed on `stop`/`Drop`; `EfileDriver` composes it, so the rule carries through), line/phase modes (`Some(0)` = no line limit), the `line`/`noline`/`binary`/`text`/`getopts` verbs (unknown⇒`BadArg`), EOF de-registration (the fd stays attached). `line_buffer.rs` (`LineBuffer`, `LineFrame`, `DEFAULT_MAX_LINE_LEN = 1024`, the C's `LINEBUF_EOL`/`CR_AFTER` rules) and `binary_io.rs` (`Phase { Text, Binary }`, the `erl_child_setup` text⇄binary machine, default `Binary` = raw passthrough) are the two input-framing facilities.
- `efile.rs` — `EfileDriver` (`name() == "efile"`), byte movement delegated to a composed `FdDriver`; `make_efile()` = its `DriverFactory`. A failed syscall ⇒ the raw `BeamError::Io` errno (the `{error,atom}` rendering is the runtime's `prim_file` floor); an unopened port / unparsable argument ⇒ `BadArg`.
- `spawn.rs` — `SpawnDriver` (`name() == "spawn"`), the **only** module here that may spawn OS children; **constructed** (`with_stream_options`), **really spawning** in the constructor and reaping eagerly (`take_exit_status()`/`take_eof()` once only); `SpawnStream { Binary, List }` (`Default = List`) = the `binary`/`list` option (the **runtime** builds `{Port,{data,Data}}`), and `SpawnSpec`/`SpawnOptions`/`StreamOptions`/`build_command` are the term-free `open_port/2` shape (empty command/path or argv⇒`BadArg`). `stop`/`Drop` kill + reap + deregister/close every descriptor, but an adopted `{fd,N}` is **never** closed.
- `ram_file.rs` — the built-in **`ram_file_drv`** (`RamFileDriver`/`make_ram_file`): a command-driven port (an opcode byte on the output queue → a reply on the input queue) over a `Vec<u8>`, the C's 13 opcodes and its `OK`/`NUMBER`/`DATA`/`ERROR` reply encodings.
- `inet/` — the built-in **`tcp_inet`** (stream) and **`udp_inet`** (datagram) drivers, one socket behind one port, reached via `open_port({spawn_driver, tcp_inet | udp_inet}, …)`; they share `wire.rs`/`opt.rs`/`sys.rs`/`stat.rs`, apply `{packet, N}` framing on **both** the read and the send path, and `opcode.rs` decodes the decimal `erlang:port_control/3` numberspace onto the same named-verb bodies.
- `TcpInetDriver::from_accepted(fd, listener)` — the C's `tcp_inet_copy` (`inet_drv.c:11795`) as an additive inherent constructor: adopts `fd` **owned** exactly as `from_socket` does and then applies the listener's inherited option set plus its cached `stype`/`family`; it is the **only** copy path (`INET_REQ_FDOPEN`'s `adopt_prebound` copies nothing, as the C's `inet_ctl_fdopen` does), and the runtime uses it when it opens the second port for an accept. `TcpInetDriver::peer_closed()` is the driver's latched peer-close observation, mirrored by `Driver::port_closed`. Per-field detail: `src/drivers/inet/CONTEXT.md`.
- **The async-op queue** (`async.rs` + its accept half `accept.rs`, `udp/async.rs`, the C's `desc->async`): one receive slot (`INET_MAX_ASYNC = 1` ⇒ a second concurrent receive answers `[0]"ealready"`; an id is consumed even by a refused enqueue) + a multi-op accept list; `deadline_for` merges into `Driver::next_timeout`; `drain_closed` answers `{error, closed}` **exactly once** per pending op. Served: `TCP_REQ_RECV`(42), `ACCEPT`(26) (its `Accepted { fd }` handed off **owned**) and `udp_inet`'s `PACKET_REQ_RECV`(60), whose `Length` operand is ignored. Both drivers' `port_command/2` runs the C's **size-only** `init_caller` strip and then either writes and stages `{inet_reply, Port, ok|{error,Reason}, Tag}` or answers out of band; `INET_REQ_CONNECT`(3) is a bounded synchronous wait consuming no async id (a documented divergence). Rows, guards and refusals: `src/drivers/inet/CONTEXT.md`.
- **A.4 port/driver residuals** (each a typed error): a `driver_output2`/`driver_output_binary` DATA reply's improper list (`[hdr|<<body>>]`) renders because `PortNotification::Data` carries `ReadMessage { header, body: Option<Vec<u8>> }` (`(hbuf,hlen,buf,len)` preserved; one notification = one `driver_output*` call); the `PACKET_REQ_RECV`/`TCP_REQ_RECV`/`ACCEPT` **async-op queue** is served (one receive slot + a multi-op accept list, `{inet_async, Port, Ref, Result}` on the completion channel); `INET_REQ_FDOPEN`'s prebound descriptor is never closed (borrowed, port-lifetime), and `ignorefd`/`tcp_sendfile` reproduce their refusals only.

### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; a `pub` sub-tree (`pub use crate::abi::*`); the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code. Four modules — `host.rs` (`PortHost`/`AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, preferring the entry's **`outputv`** on both write paths, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` **implements** `beam_abi::DriverHost::set_busy_port` (records the per-port `DriverState::busy`, answers the C's `0`; read back via `AbiHost::is_busy`/`DriverPort::is_busy`), exposes `queue_head` (the safe `&[u8]` companion of the raw `driver_peekq` hook), and `DriverPort::control` returns the **empty list** for the C's documented `*rbuf == NULL` reply rather than `badarg`. Detail: **`src/abi/CONTEXT.md`**.

### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
`Encoding { Latin1, Unicode }` (any other name — a tuple encoding, … — is refused, never guessed) · `ByteSource` (`read_chunk(size) -> Result<Option<Vec<u8>>>`, `None` = eof; impls for `std::fs::File`, `SliceSource`, `EmptySource`) · `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`, whose request is `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>`.
The device loop (`READ_SIZE_BINARY` 8 KiB / `READ_SIZE_LIST` 128) reproduces `get_chars/5` → `get_chars_apply/7`: a stashed leftover is fed **before** any read, the `latin1` clause matches only when `Enc == latin1` **and** `unic == latin1`, the general clause decodes/transcodes (`InEnc = unic`, `OutEnc = Enc`) and carries an incomplete-UTF-8 tail across a `{more,…}` re-read, `eof` is delivered as `eof`, and a sequence spanning end-of-file is the `invalid_unicode` stop.
The **`Continuation` seam** (`Continuation`/`ContData`/`Applied`/`Leftover`) is the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])`; the charlist is a `Vec<u32>` and `cast_reply` is `io_lib`'s list→binary cast. `NoEngineContinuation` is the not-installed default: every `apply` is the typed `unsupported` (naming the missing `erl_scan:tokens/4`), never a fabricated reply. **Deviations:** term-free; the `{stop, Reason, {error, Fn}, State}` boxing and the `erl_scan`-specific `invalid_unicode_error/4` hack are the runtime's; `Leftover` is flat. Detail: **`src/io_device/CONTEXT.md`**.

### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
`Signal` — the twelve signals `os:set_signal/2` accepts (`sigttin`/`sigttou` are **not** accepted), `Signal::ALL` = the `drain` report order · `Disposition { Default, Handle, Ignore }`.
`SignalFacility` — `set(&mut self, Signal, Disposition)` (`sigaction(2)`, **empty `sa_mask`**, **`SA_RESTART`**), `disposition`, `read_fd()` (registered with `Poller` by the **runtime**, which owns the token), `drain() -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order). `SigStop` is **kernel-only** (a typed `BeamError::Io`; the consumer answers the oracle's `ok`).
The handler is **async-signal-safe** — one atomic bitmask OR (swapped *before* the pipe is drained, so a signal landing in that window is deferred, never lost) plus one `libc::write` whose byte count is **not** the source of truth. The facility is **process-global** (keep exactly one alive; `Drop` restores every prior disposition) and unix-only.

### `cpu_time.rs` — the CPU-time facility (safe `getrusage`/`clock_gettime`)
`CpuTimes { user_ms, system_ms }` in whole **milliseconds** (the oracle's unit: µs ÷ 1000, truncating). `process_cpu_times()` (`getrusage(RUSAGE_SELF)`) is exactly the C's `erlang:statistics(runtime)` measurement; `thread_cpu_times()` reports the calling thread's time as `user_ms` with `system_ms == 0` and is **not** what that BIF uses.
`RuntimeClock` (`new`/`Default` anchor **0**, `runtime()`, `reset()`) is the `statistics(runtime)` counter: `(Total, SinceLastCall)` in ms, so the **first** call returns two equal elements (the C's `runtime_prev.data.user = 0`) and **system time is not used**; a failed `getrusage` is the typed `BeamError::Io` and leaves the anchor **unchanged**.

### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
`DynLib` — an owned `dlopen(3)` handle (`open`/`open_with`/`open_cstr`, `symbol`/`try_symbol`; `Drop` closes exactly once), deliberately no `into_raw`/`from_raw`, not `Send`/`Sync`. `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default and the mode `beam_abi`'s loaders use), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`.
`DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary (`reason_atom`, `errcode` **derived** from the single `ERRCODE_TAB` via `atom_to_errcode`, `text`, `is_*` classifiers), with `ERRCODE_TAB` (the emulator's `errcode_tab`, byte-for-byte), `errcode_to_atom`/`format_error_text`/`symbol_name`/`ERL_DE_*`; **no** `.so` suffix is appended. Classification is **text-based only** (a failed `dlopen` does not set `errno` reliably), mirroring the emulator's `find_errcode`. The `-Wl,--export-dynamic` requirement belongs to the **loading** link (shared with `beam_abi`/`beam_rt`); this crate's part is its `build.rs`.

### `fs_access.rs` — the safe `access(2)` / `geteuid(2)` / `getegid(2)` floor
`AccessMode { Exists, Read, Write, Execute }`. `try_access(&Path, AccessMode)` — the crate's **one `access(2)` call site**, errno-preserving: `Ok(())` iff the kernel grants the mode, `Err(BeamError::Io(err))` with the untouched errno on refusal (`EINTR` retried), `BadArg` for an interior-NUL path. `access(&Path, AccessMode) -> Result<bool>` — a **refusal** is `Ok(false)`, only a genuine syscall failure is `BeamError::Io`; `path_access(&Path)` is the `#file_info{}` `access` slot (two **independent** probes) and `process_credentials()` the **effective** ids `check_access` compares a `stat` against.

### `close_fd.rs` — the safe descriptor-close facility (`close(2)` + `OwnedFd`)
`close_fd(RawFd)` — an `EINTR`-retried `close(2)` that reports `EBADF` instead of swallowing it. `OwnedFd` — closed exactly once, `into_raw` being the way to hand ownership to a driver. It is the crate's **safe, public** close primitive for a descriptor the *runtime* owns or decides not to adopt (an `InetAsyncResult::Accepted` socket), not the crate's only `close(2)`: each driver closes the descriptors it owns.

### `error.rs` — the crate's single errno→name table
`ERRNO_NAMES` (**61 rows**) is the one table (the file/`fork`/`exec` set plus the socket set the inet drivers can produce). `errno_atom` is the `Option` form (unrecognised ⇒ `None`, never an invented atom); `errno_name` is the `[0] ++ Name` form the inet replies carry, with the C's `errno_<N>` fallback; `EOPNOTSUPP` renders **`enotsup`** (the emulator's collision list precedes its libc lookup). `drivers/inet/wire.rs::errno_name` forwards here and `InetReason`/`FailureReason` both read it, so no second table exists. The rows are pinned against measured oracle rows (`ORACLE_ERRNO_ROWS` + a live `erl` probe).

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures⇒`BeamError::Io`, argument faults⇒`BeamError::BadArg`, id/registration exhaustion⇒`BeamError::SystemLimit`. Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`dup2`, `inet`'s `setsockopt`/`getsockopt`, `cpu_time`'s `getrusage`/`clock_gettime`, `signal`'s `pipe2`/`sigaction`, `ddll`'s `dlopen`/`dlsym`/`dlclose`, `fs_access`'s `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling; every block carries a preceding `// SAFETY:` rationale and `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids come from `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync` (`Poller`/`Waker` are exempt — the waker must cross threads; `SignalFacility` is process-global).
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait, `DriverContext`'s public methods and the `Port`/`PortRegistry` signatures are the frozen driver seam**, extended only by **additive, defaulted** members that leave every existing implementor and call site behaving as before (`Driver::is_busy`/`Driver::port_closed` defaulting to `false`, `PortCommandOutcome` beside `Port::command`, `port_command_with` beside `port_command`) — never by changing an existing signature. Files target ~1000 lines. Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only; no new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` behind a **mio-independent** API (`RawFd` + `Interest`/`Token`/`Ready`), so another backend could be added later (an io_uring/`/dev/poll` backend is **not implemented today**). The epoll backend is **edge-triggered** (`mio` registers with `EPOLLET`), so a driver must drain a readable descriptor to `EAGAIN`. `mio` fd registration is Unix-only, so Windows/iocp is out of scope (as in `beam_abi`).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **Task execution here, the scheduler thread above.** The poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver. A poll **error** reaches both armed directions (C parity), so a fully armed port gets an `Output` task from a pure `EPOLLERR` while the gate denies it to a read-only port. **Divergence:** the C keeps three FIFO queues with no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT) — observable only in the order two *different* kinds run in a round.
- **The spawn driver is constructed, not registered, and reaps eagerly:** a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (a failed spawn registers nothing and `os_pid()` is readable before `PortRegistry::open`); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it.
- **The TCP/UDP drivers are a floor, not a full `inet`** — the served verbs, the framing types and the `{active,…}` matrix are oracle-cross-checked (see `src/drivers/inet/CONTEXT.md`).

## Known Issues
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output; no `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` from its bytes, latched EOF and once-only exit status is the runtime's job. Writing to a child that closed its stdin fails with a typed `BeamError::Io` (remainder kept); adoption needs non-blocking, and a refusing descriptor (some inherited ones ⇒ `EPERM`) fails the open. Input is framed at the **port**, not in the driver (no `line` verb): `binary`/`list` rides `SpawnStream`, `[line]`/`[binary,{line,N}]` goes through `Port::set_line_mode` + `take_line_notifications`.
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes: packing `erlang:port_control/3`'s `Data` term into the C's request payload is the runtime's job, while an integer `Op` is forwarded as its **decimal string** and decoded onto the named verbs by `src/drivers/inet/opcode.rs`. The `INET_REQ_*` surface, its guard order, its `[0]exbadport` wrapping and its refusal-only arms are `src/drivers/inet/CONTEXT.md`'s.
- **The inet drivers' `port_command/2` path adopts the failure seam; the `init_caller` rule is size-only.** Both `write_command`s run the C's `init_caller` with the tag's bytes **never inspected**, so a *plain* payload reads as a huge length and is the C's `FALSE`. Oracle-measured rows: a **malformed/untagged** payload is consumed and charged, nothing is written, `signal_failure(posix(EINVAL))` is latched and the registry reaps the port after the round (the call still answers `true`, later ones the oracle's `badarg`); a **well-formed prefix on a socket-less/unconnected port** is consumed and answered out of band (`{error,enotconn}` for `tcp_inet`, `{error,einval}` for a socket-less `udp_inet`; an open-but-unconnected datagram port really sends) with the port alive; an empty or non-ETF tag stages **no** reply. The **named** verbs answer `[0]enotconn`(stream)/`[0]einval`(datagram) for a missing socket or peer, and a `udp_inet` command carrying ancillary data (`anc_len != 0`) is the typed `unsupported`, command left queued.
- **A completion is addressed to the port's owner, not to the C's `driver_caller`.** `InetReply`/`InetAsync` are staged with `deliver_completion` and drained by `take_completions`; the C sends to `desc->caller`. Rendering and delivering is the runtime's (*Handoffs*).
- **The `driver_output2` header/body split survives to the consumer; the term shape is the runtime's.** `PortNotification::Data` carries `ReadMessage` (pinned shapes in its rustdoc, exercised by `tests/driver_output2.rs`), and a **loaded C** driver reaches it with the split intact (`AbiHost::output2` → `deliver_read`), so **one notification is one `driver_output*` call**. Turning the bytes into `{Port,{data,Data}}` (list vs binary) is the runtime's.
- **The busy-port flow control is decided here; the caller-blocking half is not.** `Port::command` owns the whole decision table and answers it as a `PortCommandOutcome` (or the typed `notsup`), and `PortRegistry::port_command_with`/`is_busy` expose it. What no layer here can do is the **caller-blocking** half of a plain command on a busy port: the oracle suspends the caller and re-issues the BIF once the driver clears the state, then answers `true`, which needs a process this crate does not have. Oracle-pinned rows the table reproduces: `[nosuspend]` ⇒ `false`; `[force]` ⇒ `notsup` unless the driver advertises `ERL_DRV_FLAG_SOFT_BUSY`, `true` with it; a plain `port_command/2` **suspends** until `set_busy_port(port,0)`.
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` callbacks are `void`.** Counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`); do not "fix" it into a remainder. Detail: `src/abi/CONTEXT.md`.
- **No `Driver::flush` / asynchronous CLOSING on port close.** `close` runs the driver's `stop` and drops both byte queues; with no flush hook, output queued at close time is not flushed (the C calls `drv->flush` and parks a non-empty `ioq` in `ERTS_PORT_SFLG_CLOSING`). `beam_rt` mitigates by notifying the port owner first.
- **Driver-readiness residuals.** `DriverState::fd_armed` hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a multi-fd port would starve the others (harmless for every current driver — one fd each). A `{fd,N}` spawn port keeps an `Interest::BOTH` registration for its life, so a spurious `OUTPUT` task is scheduled on every write-readiness event.
- **File sizes (`wc -l`) sit over the ~1000-line target for the grown halves** — `registry.rs` 2311, `drivers/inet/mod.rs` 2426, `drivers/spawn.rs` 1978, `drivers/inet/{tests,udp,packet,sys}.rs` 1971/1507/1245/1229, `port.rs` 1761, `driver.rs` 1416, `port_task.rs` 1189 and the two biggest `inet` halves (`async.rs` 862 + `accept.rs` 501, under it after the accept split). Each is a source half plus its suite; a grown source half splits its test module into a sibling file (`opcode_tests*.rs`, `opt_*_tests.rs`, `port_command_tests.rs`, `registry_busy_tests.rs`, `*_tests.rs`), never by trimming the suite.

## Handoffs (beam_rt — out of this node)
**Adopted upstream:** `{line,N}` framing (`set_line_mode` + `take_line_notifications`), the completion channel (`take_completions`), the `#file_info{}` `access`/`uid`/`gid` path, the signal and CPU-time facilities, `create_static_spawn`, the once-only `take_eof`, the port-monitor id table, the `{get_until,…}` io request, `ram_file_drv`'s port path, `erlang:port_control/3` and a refused command's `badarg`.
**Owed for the busy-port flow control:** `Port::command`/`PortRegistry::port_command_with`/`is_busy` are the port layer's whole half, so what remains is the runtime's `erlang:port_command/2,3`: `beam_rt` decides the busy arms over the busy flag of its **own** self-contained C host (`crates/beam_rt/src/port/driver.rs::BusyFlag`, seized per port) rather than routing the command through `port_command_with`, and answers a plain command on a busy port — the oracle's suspend-then-retry — with its typed capability gap, because its BIF seam has no "block the caller and re-run me" shape (`crates/beam_rt/src/native/port.rs::RuntimeContext::port_command`).
**Owed for the driver-failure channel:** a driver can latch a failure (`DriverContext::signal_failure`) and `PortRegistry` closes the port through the ordinary path, but **rendering the owner's exit message** — `{'EXIT',Port,Reason}` from `take_failures()`, gated on `DriverFailure::signals_owner` — is `beam_rt`'s; nothing above this crate drains `take_failures()` yet.
**The one thing owed for the `{active,…}` channel — the drivers PRODUCE, the runtime must RENDER.** `beam_rt` must drain `PortRegistry::take_active_inputs()` after **every** round **and after every `close`** (draining is what removes the entries), split a datagram `Data`'s 7 packed header bytes into `{IP, Port}` (`<<1,137,18,127,0,0,1>>` ⇒ `{{127,0,0,1},35090}`), and render `{udp, S, IP, Port, Data}` / `{tcp, S, Data}` — a **flat list** under `[list]`, `[H1..Hsz|<<Body>>]` (or the bare binary when `Hsz == 0`) under `[binary]` — plus `{tcp_passive,S}`/`{udp_passive,S}` for a `Passive` event, the atom chosen from the driving port's driver name (the event carries none). **Do not add a variant to `PortNotification`** (two arms, no wildcard) and do not route these through `CompletionEvent`.
**Still owed, each a seam the frozen `Driver`/`DriverContext` trait lacks:**
- **The runtime's half of the completion channel.** Both drivers stage every outcome (`TCP_REQ_RECV`(42), `ACCEPT`(26), `PACKET_REQ_RECV`(60), the `port_command` caller reply, the teardown drains); `beam_rt` must drain `take_completions()` after **every** round and after **every** `close`, and render `InetReply { caller_ref, reply }` as `{inet_reply, Port, Reply[, DecodedTag]}` (decoding the 131-led `caller_ref` with `beam_codec`) and `InetAsync { id, result }` as `{inet_async, Port, Id, Result}`, where `Data(read)` renders per the port's mode and `Ok`/`Port`/`Error` are the other arms. `InetAsyncResult::Accepted { fd }` is adopted into a **second** port (`TcpInetDriver::from_accepted(fd, listener)` — the `tcp_inet_copy` inheritance — or the served `INET_REQ_FDOPEN`) **or** closed by the runtime — `beam_io` never closes it. A **built-in** driver port has no term path of its own (`PortMeta::driver_terms` is `None` for `PortName::SpawnDriverBuiltin`); `PortEvent::Term` exists only for `dlopen`ed driver ports.
- **`driver_caller`.** The C sends `{inet_reply,…}` to the command's `desc->caller`; this floor stages it for the port's **owner**, so addressing the reply to the caller needs a caller notion the frozen seam lacks.
- **The delivered-data term shape (`mode` list vs binary) and the `LineNotification` header stamp are the runtime's.** `PortNotification::Data` carries bytes while the C's `tcp_reply_data` builds the term from `desc->mode`; `beam_rt` matches `{ port, read }`, renders the oracle's improper-list shape and stamps a `LineNotification`'s `header` as the same cons prefix on `{eol|noeol, Data}`.
- **The async-op queue's genuinely refused arms** — `{deliver, port|term}`, **`send_timeout`/`send_timeout_close`**, **`controlling_process`**, **`SUBSCRIBE`'s notification half** (`{empty_out_q, Port}`), the **`IGNOREFD`/`TcpSendfile`/`Getservby*`** refusal-only arms, and **`udp_inet`'s ancillary data (`anc_len != 0`)** — are refused honestly, each a typed error rather than a wrong result; the missing seam and the C ground truth for each are in `src/drivers/inet/CONTEXT.md` › *Handoffs/Divergences*.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** The observation half is done: `TcpInetDriver::peer_closed()` latches the close, `Driver::port_closed` mirrors it (so `Port::port_closed`/`PortRegistry::port_closed` report it), and `recv`/`send` already answer `[0]closed`/`[0]enotconn`. What remains is the runtime **rendering**: `beam_rt` must read `port_closed` once per port-task round and deliver the oracle's `{tcp_closed, Port}` (the C's `tcp_recv_closed` message, `inet_drv.c:13202`).
- **`beam_rt`'s `src/port/inet_matrix_tests.rs::the_residuals_no_oracle_column_can_pin_stay_typed` asserts an `INET_REQ_FDOPEN`-adoption typed gap** that this crate's served path contradicts (it gets the non-mirror's `[0]einval` "already holds a socket" answer). That node's owner must update the row; this crate cannot.
- **`DynLib` has no consumer outside this crate.** `beam_rt`'s `erl_ddll` floor is built on `beam_abi::driver::loader`, so the safe `dlopen`/`dlsym`/`dlclose` wrapper stays an unadopted seam; a consolidation would move it **down** into `beam_abi` (its own loaders cannot call this module) and re-export it here.
- **The `erl_ddll` error taxonomy is duplicated OUTSIDE this crate (report — not fixable here).** A full atom+code+message copy lives in `crates/beam_bifs/src/runtime/ddll.rs` and a partial one in `crates/beam_abi/src/driver/loader.rs`; the recommended single owner is `beam_abi`, but `beam_bifs` does not depend on it, so that adds a DAG edge whose zero-new-edge alternative is the LCA `beam_common` — an **owner decision + a `CHANGE.md` entry**, not this node's. Artifact validation is already single-owner per kind (`beam_abi::{driver,nif}::loader::load`).
- **The `file:*` API belongs to `beam_rt`'s `prim_file` floor.** The `efile` driver offers the driver-level verb set only; `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`, so routing `file:open/2`+`read/2`+`write/2` onto it would still owe the `{error,atom}` and `FileDataMode` renderings.

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A new `access(2)` use belongs in `src/fs_access.rs`, never as a second `unsafe` wrapper.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** so the driver and its context borrow disjoint fields; never add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks` (poller keys are port *numbers*). A handled OS signal wakes it through `SignalFacility::read_fd()`.
- A new owner-facing message goes on a **new** channel (a struct + a `DriverContext::deliver_*` sink + a `PortRegistry::take_*` drain, drained after every round *and* after every `close`), never as a third `PortNotification` variant and never as a `CompletionEvent` arm: `beam_rt` matches both exhaustively.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`) — do not close them elsewhere; `EfileDriver` composes an `FdDriver`, so the same rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the syscall's duration — build it from a local `let mut fd = fd;` inside the wrapper.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP, restore it, serialize on a shared `Mutex` (the facility is process-global) and raise thread-directed with `pthread_kill(pthread_self(), …)`.

## TCP accept state machine
The state machine itself is the child node's: the **sticky** multi-accept `INET_F_MULTI_CLIENT` bit behind `GETSTATUS`, the per-port sorted accept-timer list (the C's `desc->mtd`), the `[0]einval` ladder for every non-listening state and the arm/re-arm/disarm readiness cycle live in `src/drivers/inet/CONTEXT.md` and are pinned by `src/drivers/inet/accept_tests.rs` (19) + `tests/inet_accept.rs` (7).
The accepted descriptor is handed over **owned** (`InetAsyncResult::Accepted { fd }`), and the listener's option set comes across through `TcpInetDriver::from_accepted(fd, listener)` — this crate's implementation of the C's `tcp_inet_copy` — so the runtime must open the second port with **that** constructor rather than `from_socket`.
