# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Built-in Drivers, Signals, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.

Hosts seven things: the `mio`-backed **poller/reactor** (`Token`→registration map, `EINTR`-tolerant `poll`); the **`Port`** (process-like I/O endpoint: input+output byte queues, lifecycle, driver dispatch); **port-task scheduling** (`INPUT`/`OUTPUT`/`TIMEOUT` + reductions, `port_task.rs`, mirroring `erts_port_task_execute`); the **`Driver` trait + built-in drivers** (`fd`, `efile`, OS-child `spawn`, TCP `tcp_inet`, `{line,N}` buffering, the text⇄binary phase-change protocol); the **driver C-ABI host layer** (`src/abi/`) — a `.so` loaded by `beam_abi::driver::loader`, presented as `Box<dyn Driver>` by `DriverPort`, its `driver_*`/`erl_drv_*` calls served by `AbiHost` over this crate's poller/queues/timer, plus `PortHost` (atom interning — the one hook it cannot fill) and `DriverTable` (the process-global registry = the C's `driver_list`, + port creation); the **OS-signal facility** (`src/signal.rs`) — self-pipe + async-signal-safe trampoline (`sigaction(2)` install/query) backing `os:set_signal/2`, the signal `unsafe` work `beam_rt` (`#![deny(unsafe_code)]`) cannot do itself; and the **dynamic-library primitive** (`src/ddll.rs`) — safe `dlopen`/`dlsym`/`dlclose` with the `erl_ddll` error-atom taxonomy behind `beam_rt`'s `erl_ddll` floor.

`beam_rt` is the only consumer and **drives this crate's ports** (the poll loop, port run queues and scheduler thread are `beam_rt`'s): one long-lived `Poller` + `PortRegistry`, a `SpawnDriver` from its decoded `open_port/2` terms, the port-task round from its main loop, and the resulting `PortNotification`s + `take_exit_status`/`take_eof` turned into `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` for the owning process (waking a blocked receiver through `beam_process`); `beam_process` observes ports by id (the peer of pids in `ptab`). Only `SpawnDriver` is on that path.

Legacy C ground truth (read-only; full paths in the Routing Table): `erl_poll.c` + `erl_check_io.c` (poll loop, one-shot re-armed readiness, self-pipe wakeup), `io.c` (`erts_port_command`/`erts_port_control`, the `ioq` output queue), `erl_port.h`, `erl_io_queue.{c,h}` (`SysIOVec` queue), `erl_port_task.{c,h}` (async work unit + reductions), `inet_drv.c`, `erl_child_setup.c` (`{line,N}`/binary phase-change), `erl_bif_ddll.c` + `erl_unix_sys_ddll.c` (`erl_ddll` errcode/atoms + `dlopen` flags), `sys.c` (`signalterm_to_signum`, the `os:set_signal/2` set).

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`. Only **frozen contracts and non-obvious behaviour** are listed; rustdoc carries mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque registration handle; **token `0` is the waker's**, user tokens start at `1`. · `Interest` — readiness mask (`READABLE`/`WRITABLE`/`BOTH`). · `Ready` — observed readiness, **no public constructor** (only `Ready::default()`/`From<Ready> for Readiness`). · `Event` (`token`/`key`/`ready`); `Event::new` lets tests forge one.
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`** created in `new()`; registered by raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks); `waker()` an infallible cheap clone. `Waker` is the `Arc`-backed, cloneable, thread-safe handle to that one wakeup handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).
- **`poll` is `EINTR`-tolerant**: an `ErrorKind::Interrupted` wait is **retried**, never returned as `BeamError::Io` (`mio` does not retry `EINTR`; `epoll_wait`/`poll`/`select` are never restarted after a handler runs, `SA_RESTART` notwithstanding). The retry **preserves the deadline** (`poll(Some(d))` subtracts elapsed time, so repeated signals never block past `d`; `poll(None)` resumes).
- **Regular-file fallback (internal, no signature change):** epoll refuses regular files (`EPOLL_CTL_ADD`⇒`EPERM`), so `register` keeps a `libc::poll(2)`-backed fallback set — an unsupported descriptor is watched with `poll(2)` and its readiness merged into `poll` in the same `Event`/`Ready` shape; the probe reports its `std::io::Error`; `poll` never blocks indefinitely while the set is non-empty (`FALLBACK_POLL_CAP`, 1 ms).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — a single deadline; `Timer` — deadlines keyed by `u64`. · `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS = 4000`; `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS/100 (40)`; `PORT_REDS_EXECUTE = CONTEXT_REDS/4 (1000)`. · `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`); `PortTask` (`Copy + Eq + Debug`). · `PortTaskQueue` — one pending task per kind (dedupe), ordered by kind priority then FIFO `seq`, timeouts deadline-gated; `arm_timeout(deadline)` re-points/replaces a pending `TIMEOUT` (unlike the dedupe-only `enqueue_timeout`).
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed), `is_idle()`, `From<Ready>`. · `PortNotification::Data { port, bytes } | Closed { port }` — the seam the runtime turns into `{Port,{data,Data}}`/port-exit messages. · `PortTaskOutcome { pub ran, pub reds_used, pub notifications }`.

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }`. · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` — the budget `handle_events` runs. · `PortControl::CLOSE == "close"` — the one **reserved** control-op name (a namespace marker: any other name is a driver verb). · `PortCommandOptions { nosuspend, force }` — carried/validated but no-ops (ports never busy; the BIF layer owns their effect once a busy-port command queue exists).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the scheduling surface (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`) and the exit/async/stream surfaces (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`). **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`) refreshes the port timer from `Driver::next_timeout` via `refresh_timeout`: `Some(d)` arms/**re-points** the single `TIMEOUT` task at `d`, `None` clears it. Re-exports `PortRegistry`.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number; basic ops (`new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`); `port_table`/`port_table_mut` expose that **same** id table (see the port-monitor handoff; `port_table_mut`'s rustdoc carries the borrowing rule). Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`); `execute_port_tasks` (port-number order under a reduction budget ⇒ a `PortTaskOutcome`; drives async completions for every live port whose driver answers `has_pending_async` *before* harvesting input, so a `driver_async` job reaches `ready_async`/`async_free` with no runtime call); `schedule_events`/`schedule_readiness` (enqueue only — an `INPUT`/`OUTPUT` task for directions the driver armed (`PortArms`)); `port_command` (queue output + schedule an `OUTPUT` task; the write happens in the task); `port_control` (reserved `"close"` closes with an empty reply; **any other `op`** goes verbatim to `control(op, arg)`, its reply returned); `take_exit_status`/`take_eof` (once-only reaped child status / EOF report); `schedule_timeout`/`cancel_timeout`/`next_deadline` (`next_deadline` = min over live drivers' `next_timeout`); `notify_port_exit` (`Driver::port_exit` **at most once**, port left live, independent of `close`/`stop`); `drive_async` (a manual async drive point for one port).

### `driver.rs`
- `DriverFlags(u32)` — `Copy + Eq`; `SOFT_BUSY`. · `PortExitReason { Closed, OwnerExited, Normal }`. · `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number (`pub(crate) PortArms` records the armed directions).
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`), `control`, `timeout`, `next_timeout() -> Option<Instant>` (the declared deadline, mirrored into the port's `TIMEOUT` after each interaction; default `None`), `port_exit(PortExitReason)` (= `Ok(())`; the once-only advisory port-exit notification, distinct from the teardown `stop`), `drive_async` (= `Ok(0)`; `DriverPort` overrides with `poll_async`), `has_pending_async() -> bool` (= `false`; overridden via `AbiHost`), `take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`; only `SpawnDriver` overrides), `take_eof() -> Result<bool>` (= `Ok(false)`; only `SpawnDriver`). Further capabilities must be additive with defaults that keep the built-ins compiling. · `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"`, `"tcp_inet"`**.

### `drivers/` (each module's role is in the Routing Table)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver; **owns** its fds (closed on `stop`/`Drop`). Ctors `pipe`/`connected(read_fd,write_fd)`/`read_only`/`write_only`; modes `with_line_mode`/`set_line_mode` (0 = unlimited)/`set_binary_mode`/`is_line_buffered`/`phase`/`set_phase`/`max_line_len`. `Driver`: `start` registers the read fd `READABLE`; `output`/`ready_output` drain `ctx.output()` to the write fd (`EAGAIN`⇒keep queued + arm `WRITABLE`); `ready_input` reads into `ctx.input()` (loops to `EAGAIN`, latches `read_eof` on `read(2)==0`, flushes a partial line at EOF, then **de-registers the read fd** so an exhausted level-triggered fallback file stops firing; the fd stays attached/owned, so a post-EOF `ready_input` is still `Ok`). `control` verbs `line [decimal(N)|"line,<N>"]`/`noline`/`binary`/`text`/`getopts` (reply `b"line,<N>"`/`b"binary"`); unknown⇒`BadArg`. `pub(crate)` write-slot seams `adopt_write_fd`/`release_write_fd`/`has_write_fd`/`attached_fd` (the efile read+write open attaches one fd in both slots).
- `line_buffer.rs` — `LineBuffer` + `DEFAULT_MAX_LINE_LEN = 1024`: frames on `\n` (a preceding `\r` kept as part of the terminator), splits a line longer than `max_len`, holds a partial line until `flush_all`/EOF. · `binary_io.rs` — `Phase { Text, Binary }` + `PhaseChange`, the `erl_child_setup` text⇄binary machine, default `Phase::Binary` (byte-identical to raw passthrough); `handle` frames Binary as one raw frame, Text as line frames; `flush` returns the trailing partial line (Text only).
- `efile.rs` — `EfileDriver` (`name() == "efile"`) delegates byte movement to a composed `FdDriver`. `control` verbs: **`open [<flags> ]<path>`** (mode list translated exactly as the C's `efile_translate_modelist`+`get_flags`, always plus `O_NONBLOCK|O_CLOEXEC`/`FILE_MODE 0666`; a bare `<path>` keeps the read-only form, spaces included, `open ./read` the documented disambiguation), `close` (both slots), `path`, `eof`, `position [<N>]`/`seek <whence>[,<offset>]` (whence = the C's `EFILE_SEEK_*`; reply = decimal absolute offset), `sync` (`fsync(2)`), `truncate [<len>]` (no arg ⇒ `ftruncate(fd, lseek(fd,0,SEEK_CUR))`; negative⇒`BadArg`), `binary`/`list` (records the public `FileDataMode` via `data_mode()`, selects the raw byte phase), plus the delegated `line`/`noline`/`text`/`getopts`. `open` refuses a **directory** with `EISDIR` (the oracle's `open_file_is_dir` check) and attaches a **read+write** open's descriptor in *both* slots via a `dup(2)` of one file description (each fd closed exactly once). Works on **regular files** (poller `poll(2)` fallback) and on epoll-servable descriptors (pipes/FIFOs/char devices/sockets); `write_only`/`connected` write regular files too. A failed `open`/syscall⇒`BeamError::Io` carrying the errno (the `{error,atom}` rendering is `prim_file`'s); an unopened port / unparsable argument⇒`BadArg`. `make_efile()` = its `DriverFactory`.
- `spawn.rs` — `SpawnStream { Binary, List }` (`Default = List`) = the `binary`/`list` option (the **runtime** builds `{Port,{data,Data}}`; the driver passes bytes through). `SpawnSpec { Spawn { command, argv }, SpawnExecutable { path }, Fd { fd } }` = the term-free `open_port/2` `Name`; `command()` = the `port_info(Port, name)` value (`fd:<N>` for the descriptor form). `SpawnOptions { stream, cd, env, args, exit_status }` (`Default`: `list`) describes the process; `StreamOptions { stderr_to_stdout, eof }` (`Default`: both `false`) shapes only the child's **streams**. `build_command(spec, options)` (= `build_command_with_stream(spec, options, StreamOptions::default())`) sets argv, shell-vs-direct, `{cd,…}`/`{env,…}` and the standard streams (`stdin`/`stdout` piped, `stderr` inherited or, under `stderr_to_stdout`, an **exact fd-1 duplicate** via `pre_exec` `dup2(1,2)`); an empty command/path or argv⇒`BadArg`; it starts nothing, so it is unit-testable alone. `SpawnDriver` (`name() == "spawn"`) is **constructed** (`new` = `with_stream_options(spec, options, StreamOptions::default())`), **really spawning** in the constructor and reaping eagerly; accessors `os_pid`/`command`/`stream`/`eof`/`exited()`, plus the once-only `take_exit_status()`/`take_eof()`. A **failed spawn** has two shapes: an `access(X_OK)`-rejected path ⇒ a constructor `BeamError::Raise` (errno atom); a path the check accepts but `exec` rejects (a searchable **directory**, a no-executable-format file) **opens the port** via `fork_exec_child`'s `libc::fork`/`execve`, whose child `_exit(errno)` sets the exit status to the errno. `start` registers the descriptors; stdout → the port input queue (drained to `EAGAIN`, EOF latched + deregistered/closed); stdin drains the output queue (`O_NONBLOCK`; `EAGAIN` keeps the remainder queued + arms write readiness); `stop`/`Drop` kill + reap + deregister/close every descriptor, but an adopted `{fd,N}` is **never** closed. **The only module here that may spawn OS children** (project invariant).
- `inet/` (`mod.rs`+`wire.rs`+`sys.rs`+`opt.rs`+`tests.rs`) — `DRIVER_NAME = "tcp_inet"` = the `port_info(Port,name)` value and the name `prim_inet` opens; `make_tcp_inet()` = its `DriverFactory`. `TcpInetDriver` (`name() == "tcp_inet"`) = a non-blocking TCP socket behind a port; `from_socket(fd)` adopts a descriptor and probes kernel state (`SO_ACCEPTCONN`⇒listening, `getpeername`⇒connected, else open); `connect_error()` = the late `SO_ERROR` of a non-blocking `connect`; `peer_closed()`; `InetState`. Control verbs = the C's `INET_REQ_*`/`TCP_REQ_*` (`open`/`listen`/`close`/`bind`/`accept`/`connect`/`send`/`recv`/`shutdown`): `[1]` (+ a `port_be16`/`fd_be32` operand where the C has one) on success, else `[0]` + a lowercase-errno-name (`erl_errno_id`) or a fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`). Option verbs (`opt.rs`): `setopts` takes five-byte `[opt,val_be32]` records and answers `[1]`; `getopts` takes one-byte codes and answers `[1] ++ [opt,val_be32]*` in request order; a trailing partial record is ignored, an empty payload is a bare `[1]`, an unserved code is the whole `[0]++"einval"`, and neither has the C's `IS_OPEN` guard. Four codes are served — `keepalive`(`SO_KEEPALIVE`)/`sndbuf`(`SO_SNDBUF`)/`recbuf`(`SO_RCVBUF`)/`nodelay`(`TCP_NODELAY`) — direct `setsockopt`/`getsockopt`, so `recbuf`/`sndbuf` report the **kernel's** value (Linux doubles a request: 4096 ⇒ 8192, the oracle) and a rejected `setsockopt` is not propagated (the C's `propagate = 0`). Malformed args / unknown verbs⇒`BadArg`; packed addresses use `INET_AF_INET`/`ANY`/`LOOPBACK`. **Peer close** is latched (`PeerClose`): a `read(2)==0`, a reset (`ECONNRESET`/`ECONNABORTED`/`EPIPE`) or a send error is one event — registration released, queued output dropped; the **first** `recv`/`send` after it answers `[0]closed`, later ones `[0]enotconn` (`TCP_ADDF_DELAYED_CLOSE_*`). Flow control mirrors `FdDriver` (`MSG_NOSIGNAL`; `EAGAIN` keeps the remainder + arms write readiness; a drained queue drops writability + applies a deferred `shutdown`; `EINPROGRESS` arms write readiness). **Absent by design** (each answers a clear `[0]einval`/`BadArg`/state error, never a wrong result; the module docs name what each needs): `{active,…}`/`{deliver,…}`/`active_count`; `{packet,N}`/`line`/`http`/`raw` header decoding; per-op `driver_set_timer` timeouts (incl. `send_timeout`/`send_timeout_close`) and the async-op queue (`INET_MAX_ASYNC = 1`, `{inet_async,…}`) — why `recv` rejects the 8-byte `Timeout(4),Length(4)` payload with `BadArg`; IPv6/UDP/SCTP/Unix-domain sockets + DNS; second-port `accept`; `controlling_process` (see *Handoffs*); `fdopen`/`sendfile`/`unrecv`/`getstats`/`getfd`/`ignorefd`.

### `src/abi/` (`mod.rs` + `host.rs` + `job.rs` + `port.rs` + `table.rs`) — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; a `pub` sub-tree (`pub use crate::abi::*`); the only place here holding raw `ErlDrv*` pointers and calling foreign code. `mod.rs` = host-layer docs (the stable `ErlDrvPort` handle, built-in/`.so` unification, the `unsafe`-module marking, the four `driver_*` slots' reach/refusal) + `pub mod host; job; port; table;` + re-exports.
- `host.rs` — `pub trait PortHost` (the hook `beam_io` cannot fill): required `intern_atom(name) -> Option<Eterm>`; defaulted `connected_pid()`/`caller_pid()` (`None`) and `send_term(to, term) -> bool` (`false`; the sink for `erl_drv_output_term`/`erl_drv_send_term`, `to == None` = the port owner). **A locally-interned atom does NOT match the runtime's atom table**, so `beam_rt` MUST inject its own `PortHost` over the shared table (`LocalAtomPortHost` = test/standalone only). `SelectedFd { token, interest, owes_stop_select }` (`pub(crate)`) = the **sticky** `ERL_DRV_USE` release obligation, merged on re-selection (the C's `ERTS_EV_FLAG_USED`; `wants_stop_select()` = `ERL_DRV_USE` without `_NO_CALLBACK`). `DriverState` = the port's persistent C-ABI state (`selected: BTreeMap<RawFd, SelectedFd>` so `ready_input`/`ready_output` pick a **stable** fd; `deadline`; `jobs: AsyncJobs`; `queued_stop_select` + `take_queued_stop_select()`); deliberately **no `Drop`** (draining there could race the worker). `AbiHost` = the `DriverHost` impl, **owning** everything (`port_host`, `heap: Heap`, `state`, `driver: Option<DriverIdentity>`, `ctx: Cell<*mut c_void>`), boxed behind a stable `ErlDrvPort` (`DRIVER_HEAP_WORDS = 1024`-word term heap); with **no context installed** every port-touching method fails gracefully (`-1`/`None`/no-op), never derefs null. It forwards `intern_atom`/`connected_pid`/`caller_pid`/`send_term` to `PortHost`, serves the four registry hooks (*Design Decisions*), and otherwise matches the C: `output` → the port's **input** queue (`0`/`-1`); `select(_, event, mode, on)` treats the event as the fd — `on != 0` registers / **re-registers in place**, `on == 0` de-registers (unknown fd⇒`0`), READ→READABLE, WRITE→WRITABLE, both→BOTH, **neither→READABLE** (an `ERL_DRV_USE`-only `mode` still watches the fd for close/error) — merges the sticky obligation (a re-select without `ERL_DRV_USE` keeps an earlier request; `_NO_CALLBACK` declines it) and queues the *deselecting* call's event when the release owes `stop_select`; `has_pending_async` ← `jobs.in_flight() > 0`; `set_timer` arms `deadline` (`0`), `cancel_timer` clears it (`0`), `read_timer` = remaining ms (`Some(0)` expired, `None` none); `r#async` → `AsyncJobs::schedule` (`id as c_long`; a failure runs the driver's `free(data)`, returns `-1`). `DriverIdentity { name, loaded }` (`pub(crate)`) = the registered driver name + whether it is `dlopen`ed; on `AbiHost`, not a `DriverHost` method (`for_driver`/`with_driver`).
- `job.rs` — `AsyncJobs`: a **bounded, process-global worker pool** (`POOL_THREADS = 4` long-lived threads, lazily started, one shared job queue — the C's async thread pool), a per-port `mpsc` completion channel and the `driver_async` queue position; `schedule(invoke, data, free)` (`None` `invoke` = fire-and-forget: a valid position and `free(data)` IS run — the C null-derefs here, a documented deviation; `Err(())` only when no worker could start) and `drain() -> Vec<AsyncCompletion>`; `in_flight()` backs `has_pending_async`; `AsyncData(*mut c_void)` is the one `unsafe impl Send`. `set_keepalive`/`KeepAlive` pin the loaded `DriverLibrary` for outstanding jobs (the C's `DE_Handle`), so `async_free` always runs **mapped** code.
- `port.rs` — `DriverPort` = a loaded `ErlDrvEntry` as `impl Driver` (`lib: Arc<DriverLibrary>`/`name`/`command`/`abi: Box<AbiHost>`/`env: Box<DriverEnv>`/`data: ErlDrvData`). The library is an **`Arc`** so the process-global table keeps one loaded object registered while ports are created from it; a per-port `LibraryKeepAlive` (`Arc<dyn Any + Send + Sync>`, documented `unsafe impl Send/Sync`) holds it down while any `driver_async` job is outstanding, so `DriverLibrary::drop` (`finish` + `dlclose`) runs with the last owner **and** after the last job. `load(...)` calls `beam_abi::driver::loader::load` (validating `command` **first**, so an interior NUL is `BadArg`, not a load failure), mapping `DriverLoadError` to a typed `BeamError::Raise`; `from_library(Arc<DriverLibrary>, CString, host)` wraps an **already loaded** object without a second `dlopen` (the registry's port-creation path; does **not** re-run `init`) and installs the `KeepAlive`; `env` + `abi` are **both boxed**, so the `ErlDrvPort` a driver sees is the **same pointer for the port's whole life**. `poll_async` drains the jobs, sorts by queue position (the C's order), runs `ready_async` if present (then `handed_to_ready_async()` — disarmed, `async_free` never runs) else `release()` (runs `async_free` with the host still published); the **port-task round drives it** (via `has_pending_async`). `make_loaded(path, name, command, host) -> Result<Box<dyn Driver>>` is the built-in/`.so` unification helper.
  - **`stop_select`** (the `ERL_DRV_USE` release callback) and **current-host publication** are the two things a `DriverPort` does *around* the port seam: `DriverPort` fires the entry's `stop_select(event, NULL)` from three places, each **after** the driver call that produced the release returned (as in the C) — a `driver_select(...,0)` (right after the routing `call`, with the *deselecting* call's event), port teardown (`Driver::stop`, every still-selected registration, fd cast to an `ErlDrvEvent`) and `Drop` (a `DriverPort` dropped without `stop`, e.g. a failed `start`); `USE_NO_CALLBACK`/an absent slot is skipped and `release_selects_on_teardown` also drains `take_queued_stop_select()`. `DriverPort::call` wraps every callback it routes (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`port_exit`/`stop`, plus `poll_async`'s `ready_async` branch) in `beam_abi::with_current_host`, as does the `stop_select` firing; `poll_async`'s `async_free` branch (bypassing `call`) publishes separately. Those are the only paths running driver code, so the two port-less slots reach a host inside a callback and answer the C's failure value outside one; the `&mut dyn DriverHost` comes from a raw `*mut AbiHost` (documented `// SAFETY:`).
  - **`Driver` mapping:** `flags` = `SOFT_BUSY` iff `ERL_DRV_FLAG_SOFT_BUSY`; `start` (absent slot or `GENERAL`/`ERRNO`/`BADARG`⇒`BadArg`, else keeps the `ErlDrvData`); `output`/`ready_output` drain the port output queue (absent `ready_output` falls back to `output`; drained bytes count as written — the callbacks are `void`); `ready_input` = the read-armed fd, else null (absent⇒no-op); `timeout` then clears `deadline`; `control`'s `&str` is a **decimal `c_uint`** (absent slot or `cres < 0`⇒`BadArg`; the reply is a `cres`-byte copy of `*rbuf` into a `CONTROL_REPLY_CAPACITY = 4096` buffer); `next_timeout` = `state.deadline`; `port_exit` → `process_exit` (null `*mut ErlDrvMonitor`) else `emergency_close` else no-op; `stop` (absent⇒no-op, then releases every still-selected registration, firing the owed `stop_select`s); `Drop` drains `jobs` **before** `release_selects_on_teardown(None)`.
- `table.rs` — the **process-global driver registry + port-creation service** (the `beam_io` half of the four `ErlDrvApi` slots, reached through `AbiHost`); `unsafe`-marked (stores/derefs `*mut ErlDrvEntry`, calls the entry's `init`), one `unsafe impl Send for Inner` (mutex-serialized). `DriverTable`: `global()`/`new()`; `add_entry(*mut ErlDrvEntry)` (**`unsafe`**) records a **statically linked** entry after running its `init` (non-zero ⇒ `driver_init_failed` raise, no registration; null⇒`BadArg`); `add_loaded(DriverLibrary)` records a **dynamically loaded** driver without re-running `init`; `remove_entry` (safe — address comparison) answers `-1` (dynamic) / `1` (removed) / `0` (not found); `lock_driver(name)` = `0` (has a handle) / `-1` (static/unknown); `lookup` (newest wins, the C's head-inserted list) / `names()` / `len()` / `is_empty()`; `create_port(&mut PortRegistry, &mut Poller, name, command, host) -> Result<PortId>` resolves the driver, builds a `DriverPort::from_library` and opens it via `PortRegistry::open` (so `start` runs and supplies the instance's `ErlDrvPort`), the table lock **released before** `start` so a driver may re-enter the table; `RegisteredDriver { name, entry, dynamic, locked }` is a read-only snapshot. **Deviations:** the C's `driver_create_port` re-uses the *creating port's* instance and stores `drv_data` verbatim — here a **fresh** instance is created by running `start`; a **statically linked** registration answers the typed `notsup` raise (never a wrong port), since `create_port` needs a `Driver` adapter that exists only over a loaded `DriverLibrary`.

### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
- `Signal` — the twelve signals `os:set_signal/2` accepts, fixed by `signalterm_to_signum` (`sys.c`) and `lib/kernel/src/os.erl`: `SigHup`/`SigQuit`/`SigAbrt`/`SigAlrm`/`SigTerm`/`SigUsr1`/`SigUsr2`/`SigChld`/`SigStop`/`SigTstp`/`SigCont`/`SigWinch` (`sigcont`/`sigwinch` ARE accepted; `sigttin`/`sigttou` are **not** — `!`-commented rows in the C table; `siginfo` is `#ifdef SIGINFO` and excluded). `Signal::ALL: [Signal; 12]` (the `drain` report order); `name()`/`from_name()` (the lowercase BEAM atom, exact/case-sensitive); `signo()`/`from_signo()` (the `libc::SIG*`). · `Disposition { Default, Handle, Ignore }` — `ALL`; `name()`/`from_name()` for `default`/`handle`/`ignore`.
- `SignalFacility` — `new() -> Result<Self>` (self-pipe via `pipe2(O_CLOEXEC|O_NONBLOCK)` on Linux/Android, `pipe`+`fcntl` fallback on other unix; publishes the write end to the process-global handler plumbing); `set(&mut self, Signal, Disposition)` (`sigaction(2)`: `SIG_DFL`/`SIG_IGN`/the trampoline, **empty `sa_mask`**, **`SA_RESTART`**; the prior action is captured only on the first change of a signal); `disposition(&self, Signal) -> Result<Disposition>` (read back from the kernel: `SIG_DFL`→Default, `SIG_IGN`→Ignore, any real handler→Handle); `read_fd(&self) -> RawFd` (the fd the runtime registers with `Poller` — **the runtime owns the registration/token**); `drain(&mut self) -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order, then drains the pipe). `Drop` restores every prior disposition and closes the pipe (safe when `set` was never called); the global write end is cleared only if it is still this facility's.
- **Async-signal-safety (frozen).** The installed handler does exactly two async-signal-safe things: one atomic OR into a `static AtomicU64` per-signal bitmask and one `libc::write` of the signal number to the non-blocking pipe. No allocation/locking/unwinding/arbitrary Rust; the signo→`Signal` mapping happens in `drain` (normal context). The pipe byte count is **not** the source of truth (a stray/coalesced byte never duplicates a report; a dropped byte never loses one). **Single instance:** the trampoline, the bitmask and the write fd are process-global statics — keep exactly one facility alive; `new`-after-`drop` is safe. **Portability:** unix only; the self-pipe path is the default on every unix target (no `signalfd`). **Errors:** `BeamError::Io` for a failing `pipe`/`sigaction`; no panic/`unwrap`/`todo!`/`unreachable!`.

### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
- `DynLib` — an owned `dlopen(3)` handle; `Drop` calls `dlclose(3)` exactly once. `open(&Path)`/`open_with(&Path, DynLibFlags)`/`open_cstr(&CStr, DynLibFlags)`; `symbol(&CStr) -> Result<*mut c_void, DllError>`/`try_symbol(&CStr) -> Option<*mut c_void>`; `handle() -> *mut c_void`. Deliberately **no** `into_raw`/`from_raw` (an owned, reliably-closed handle) and not `Send`/`Sync` (raw pointer — single-OS-thread, the crate's invariant).
- `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default and the emulator's mode, `erl_unix_sys_ddll.c:133`; **matches** `beam_abi::driver::loader`/`nif::loader`), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`, `from_bits`/`bits`.
- `DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary: `Open` (the dynamic `{open_error, Code}` case), `SymbolNotFound`, `NoDriverInit`, `DriverInitFailed`, `BadDriverName`, `DriverNameTooLong`, `DriverIncorrectVersion`, `NoDdllAvailable`, `Unspecified`, `BadArg`; `reason_atom()`, `errcode()`, `text()`, `is_missing_file()`/`is_format_error()`/`is_undefined_symbol()`. Classification is **text-based only** (a failed `dlopen` does not set `errno` reliably and a stale value must never be trusted), mirroring the emulator's `find_errcode`.
- `ERRCODE_TAB` (the emulator's `errcode_tab`, `erl_bif_ddll.c:1709-1720`, byte-for-byte), `errcode_to_atom`/`atom_to_errcode`/`format_error_text`, `symbol_name(&str) -> Result<CString, DllError>`, and the `ERL_DE_*` numeric constants. Path spelling is the caller's: **no** `.so` suffix is appended (unlike `erts_sys_ddll_open`). The module docs state the **`-Wl,--export-dynamic`** requirement (an `RTLD_NOW` load resolves `enif_*`/`driver_*` out of the loading executable's `.dynsym`; `beam_rt`'s binary must link with it exactly as this crate's `build.rs` does for its test targets).

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures⇒`BeamError::Io`, argument faults⇒`BeamError::BadArg`, id/registration exhaustion⇒`BeamError::SystemLimit`. Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`access`/`dup2`, the `inet` socket helpers incl. `setsockopt`/`getsockopt` in `drivers/inet/sys.rs`, the `signal.rs` `pipe2`/`sigaction`, the `ddll.rs` `dlopen`/`dlsym`/`dlclose`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling. Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids come from `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync`. (Not enforced on `Poller`/`Waker` — the `Waker` is meant to cross threads; `SignalFacility` is process-global.)
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures. Files target ~1000 lines, split by responsibility. Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only; no new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so an io_uring/`/dev/poll` backend is a drop-in (io_uring not M1). 
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **Task execution here, the scheduler thread above.** The poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; `PortNotification` keeps the engine/runtime split and the DAG clean. Only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver. **Divergence:** the C keeps three FIFO queues with no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT, `seq` tie-break) — observable only in the order two *different* kinds run in a round.
- **Driver = Rust trait; the bridge is a `Driver` over a loaded `ErlDrvEntry`:** `DriverPort` adapts the frozen `ErlDrvEntry`/`ErlDrvApi` over a `DriverLibrary`, changing no `Driver`/`Port`/`PortRegistry` signature.
- **The four driver-registry slots: two process-global, `lock_driver` per-port, `create_port` refuses.** `add_driver_entry`/`remove_driver_entry` act on the process-global `DriverTable` via `beam_abi::with_current_host` (outside a callback: the C's `-1`/`0`); `lock_driver` consults the port's **own** driver (`0` `dlopen`ed, `-1` bare/static); `create_port`⇒`ERTS_INVALID_ERL_DRV_PORT` — a callback already holds a `&mut` into the port registry (re-entering `PortRegistry::open` would alias unsoundly) and a new port needs a `Box<dyn PortHost>` only `beam_rt` can supply (the C's own sentinel, never a fabricated port).
- **`driver_output` is harvested by a non-empty input queue, not an `INPUT` task:** `AbiHost::output` pushes onto the port's *input* queue; `Port::take_input_notification` reports+drains `Some(Data)` whenever non-empty — drivers call `driver_output` from `start`/`control`/`timeout`/`output`/`ready_input`, *outside* any `INPUT` task, so task-gating would drop those bytes.
- **`driver_async` runs on a bounded, process-global worker pool (`POOL_THREADS = 4`), driven by the port-task round** (an unbounded `thread::spawn` per job could exhaust the OS thread limit; the C bounds concurrency too). The release obligation is a **value** (`AsyncCompletion`) owning `async_data`/`async_free`, released on `Drop` unless disarmed (`handed_to_ready_async()`), so `async_free` runs **exactly once** even if the port dies mid-job; `AsyncJobs::Drop` drains undelivered completions; the worker drops a completion a failed `tx.send` hands back (the C's `!p`); `schedule(None, ..)` releases immediately. **Deviation:** the port thread owns `async_free` (the C uses the worker).
- **`control` is numeric for a loaded driver** (a C driver's verbs are integer `INET_REQ_*`-style codes ⇒ the `&str` is parsed as a decimal `c_uint`); the reply is a `cres`-byte copy of `*rbuf` (`CONTROL_REPLY_CAPACITY = 4096`, or the driver's own memory valid until the next call) — a **trust boundary** (a driver is native code).
- **`set_timer` always succeeds (this port always has one); `read_timer` = remaining ms, `None` only when disarmed** — expired ⇒ `Some(0)` (the C writes `0`); `beam_abi`'s `driver_read_timer` maps `None`⇒`-1` (deviation from `io.c`'s `0`/`0`).
- **The `beam_io → beam_abi`/`beam_alloc` edge is directionally legal (wave 5 → wave 0), cycle-free, no `*_dev` edge** (`beam_abi` = the frozen ABI to adapt, `beam_alloc`'s `Heap` = the driver's term arena). **Consequence:** `beam_abi`'s own `dlopen` loaders cannot use `beam_io::ddll`.
- **Exit status via a defaulted trait method, not a notification variant** (a variant would force every round to carry a status the port may not owe): `Driver::take_exit_status()` (= `Ok(None)`, so `FdDriver`/`EfileDriver` compile unchanged) + additive `PortRegistry::take_exit_status(id)` (`Ok(None)` = no child / not reaped / already reported; `Result` so a failing `wait` is reported).
- **The spawn driver is constructed, not registered, and reaps eagerly:** a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec` (`Driver::name()` stays `"spawn"` for `port_info`); the child starts in the **constructor**, so a failed spawn registers nothing and `os_pid()` is readable before `PortRegistry::open`; `{fd, N}` adopts one descriptor as a **duplex** stream (one `Interest::BOTH`) and never closes it; `stop`/`Drop` kill **and** reap (`Drop` reaps because Rust's `Child` does not).
- **A failed spawn splits in two, like the reference:** an `access(Path, X_OK)`-rejected path is an `open_port/2` **error** (`BeamError::Raise` with the failing `errno`'s lowercase atom, matching `erts_internal_open_port_2`); a path the check *accepts* but `exec` rejects **opens the port** (the child's `_exit(errno)` becomes the exit status, e.g. `{spawn_executable, "/etc"}` ⇒ `{exit_status, 13}`). **The child's stderr is inherited by default; `stderr_to_stdout` aliases it onto fd 1** via a `pre_exec` `dup2(1,2)` (one pipe, true write ordering).
- **Timer seam driver-declared + mirrored (deadline-gated, never early); `PortRegistry::{schedule_timeout,cancel_timeout}` is the runtime's explicit override; `Driver::port_exit` fires at most once, distinct from the teardown `stop`.**
- **The TCP driver is a floor, not a full `inet`** (*Absent by design*; the served verbs incl. `setopts`/`getopts` are oracle-cross-checked). **`mio` fd registration is `os-ext`/Unix-only** (`mio::unix::SourceFd`), so Windows/iocp is out of scope (as in `beam_abi`).
- **The signal facility is a self-pipe with an async-signal-safe trampoline**, `SA_RESTART` so a handled signal does not spuriously fail unrelated syscalls; the `EINTR`-tolerant poller makes `read_fd` the notification channel the runtime must register (no `signalfd` — portability).

## Known Issues
- **The A.4 driver-registry hooks here are correct and tested, but the running runtime does not route through this crate's host layer.** They live in `src/abi/host.rs` over `src/abi/table.rs`'s process-global `DriverTable`, and nothing outside `beam_io` references `beam_io::abi`/`make_loaded`/`AbiHost`/`DriverTable`, so this layer is exercised only by this crate's own tests. `beam_rt` serves the four slots through its own self-contained host (`crates/beam_rt/src/port/driver.rs`), which overrides all four hooks and publishes the current host around every driver callback — oracle-pinned (`beam_rt/tests/driver.rs` asserts `0,1,0,-1`) — and already delivers `{Port,{data,…}}`/`{Port,{exit_status,…}}` and `{fd,N}` `port_command`. `enif_alloc_env()` in a real NIF is a live env in the oracle / NULL here.
- **The C-ABI host layer is a floor; a driver must not stash `ErlDrvPort` beyond the callback.** With the context installed per callback (`install`/`clear` around each `DriverPort` call), a driver that keeps the handle and calls `driver_*` outside a callback (e.g. its own worker thread) gets the C's `-1` (a `driver_output` from a plain `std::thread` returns `-1`, its bytes dropped). The handle *pointer* is stable for the port's whole life (asserted in `tests/abi_async.rs`); the **installed context** is callback-scoped. `ready_async` receives no port (`erl_driver.h`), so a driver needing it there uses the handle it stashed in `start` — which works because `poll_async` runs inside a `DriverPort` method with the context installed.
- **`ErlDrvApi` slots served vs. deferred (handoff to `beam_abi`).** Only the four **driver-registry** slots are served through this crate's host layer; every other slot is `None` in `beam_abi`'s `DRIVER_API` because `DriverHost` has no method for it — the port-queue family, port lifecycle & attributes, monitors & the port data lock (`driver_monitor_*`/`driver_pdl_*`), and the mutex/cond/rwlock/tsd/thread families; the binary-refcount trio is deliberately `None` too (an `ErlDrvBinary` is exactly `{ orig_size, orig_bytes }`). Each deferred group names the `DriverHost` methods `beam_abi` must add; see `../beam_abi/CONTEXT.md`.
- **Readiness is edge-triggered** (`mio` `EPOLLET`), so a driver *must* drain to `EAGAIN` per callback (`FdDriver` reads/writes in an `EAGAIN`-terminated loop).
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop.
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output (the emulator's line flag); no `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Decoding `open_port/2` into `SpawnSpec`/`SpawnOptions`/`StreamOptions` and synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` is the runtime's job — this crate only moves bytes, reports the latched EOF/exit status **once**, and kills/reaps. Writing to a child that closed its stdin fails with a typed `BeamError::Io` (the remainder kept); adoption requires non-blocking (`F_SETFL`+`O_NONBLOCK`), and a descriptor that refuses (some inherited ones ⇒ `EPERM`) fails the open with `BeamError::Io`. Input is not line-framed (no `line` verb): the `binary`/`list` choice rides `SpawnStream`.
- **`port_control`/control atoms are not decoded here.** `port_control(op, &[u8])` takes a `&str` op + raw bytes; the C decodes Erlang tuples in `io.c`, so decoding `{command,…}`/`{connect,…}` is the runtime's job.
- **`tcp_inet` is a floor** — the API Surface's *Absent by design* list names every missing capability, and the covered verbs (incl. `setopts`/`getopts`) match the C's reply shapes (oracle-cross-checked, including the latched peer close). `recv` rejects a timeout/length argument with `BadArg`; surfacing the latched peer close as `{tcp_closed, Port}` is a `beam_rt` handoff.
- **File sizes (source vs. in-module tests).** `src/port.rs` 675 source (no in-module tests); `src/registry.rs` 1258 (≈610 + ≈648); `src/drivers/inet/mod.rs` 1116 source (+107 module docs; `opt.rs` 173; `wire.rs` 182; `sys.rs` ~280; suite `tests.rs` 937); `src/poller.rs` 966; `src/drivers/spawn.rs` 1946 (≈1360 + ≈586); `src/drivers/efile.rs` 1123 (≈685 + ≈438) and `src/drivers/fd.rs` 1141 (≈645 + ≈496); `src/abi/host.rs` 1232 and `src/abi/port.rs` 881; `src/signal.rs` 861, `src/ddll.rs` 850. Over 1000 only for their suites; if a source half grows, split its test module into a sibling `tests/` file (and `src/drivers/inet/mod.rs` if it grows further).

## Handoffs (beam_rt — out of this node)
**Runtime adoption still owed** (seams exist and are tested here):
- **The OS-signal facility (`os:set_signal/2`).** `beam_bifs` registers `os:set_signal/2` as a `RuntimeHooks`-gated key that `beam_rt` does not install, so a call is the typed `unsupported_bif`. **API contract:** `Signal::from_name/1` → `Option<Signal>` (the twelve accepted atoms, exact/lowercase; anything else ⇒ the oracle's `badarg`); `Disposition::from_name/1` → `Option<Disposition>`; `SignalFacility::new()` → one long-lived process-global facility for the runtime's life; `set(sig, disp)` → install (`Ok(())` = the oracle's `ok`, a failure = `BeamError::Io`); `disposition(sig)` → the current view; `read_fd()` → register with the process `Poller` (`Interest::READABLE`, runtime-chosen key) — **the runtime owns the registration/token**, and `Poller::poll` is `EINTR`-tolerant; on readiness → `drain()` → `Vec<Signal>` in `Signal::ALL` order → deliver `{notify, Signal::name()}` to the registered `erl_signal_server`. `Drop` restores every disposition and closes the pipe — drop it (or let the process exit) rather than signalling after shutdown. `beam_bifs/CONTEXT.md` is internally inconsistent on `os:set_signal/2` (owned by that node — worth reconciling).
- **`erl_ddll` → `beam_io::ddll`.** `DynLib` is the safe `dlopen`/`dlsym`/`dlclose` primitive `beam_rt`'s `erl_ddll` floor must build on: open with `DynLibFlags::EMULATOR`, resolve `driver_init`/`_driver_init`, render `{error, Atom}` from `DllError::reason_atom()`/`ERRCODE_TAB`. **The dynamic `{open_error, Code}` is the floor's to own** — an index into the process-local table of raw `dlerror` strings (`find_errcode`, `ERL_DE_DYNAMIC_ERROR_OFFSET = -10`), so `beam_rt` keeps that table (built from `DllError::text()`) and builds the tuple. `DllErrorKind::BadArg` is a **raise**, not an `{error, Atom}` return. **Dependency direction:** `beam_io` depends on `beam_abi`, so `beam_abi`'s own loaders cannot call this module — a future consolidation could instead move the wrapper **down** into `beam_abi` and re-export it from `beam_io`.
- **File-module surface: the `file:*` API belongs to `beam_rt`'s `prim_file` floor, not to this driver.** The `efile` driver offers the driver-level verb set (`open` with modes, `path`, `close`, `position`, `seek`, `sync`, `truncate`, `binary`/`list`, `eof`, framing), but nothing in the running runtime reaches it — `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`. **Served there:** `get_cwd/0,1`, `read_file/1`, `delete/1`, `rename/2`, `make_dir/1`, `del_dir/1`, `read_link/1`, `make_link/2`, `make_symlink/2`, `altname/1`. **Unimplemented** (they fall through to the preloaded `.beam`): `file:open/2`, `read/2`, `write/2`, `position/2`, `sync/1`, `truncate/1`, `copy/2`, `list_dir/1`, `write_file/2`, the `read_file_info/*`+`read_link_info/*` family, `datasync/1`, `advise/4`. Wiring `file:open/2`+`read/2`+`write/2`+`position/2` onto this driver is the natural next step: the driver returns the raw errno and the raw byte stream, so `prim_file`'s remaining job is the `{error,atom}` rendering, the `FileDataMode` → binary/string rendering (`EfileDriver::data_mode`), and `read_ahead`/`delayed_write` (**not** `open(2)` flags — the C translator drops them, `prim_file_nif.c:521-524`; `read_ahead` is a `prim_file` read cache, `delayed_write` a `file` write-batching policy, both above the driver).
- **`controlling_process` is port-ownership transfer, not driver state.** `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain of buffered `{tcp,S,Data}`/`{tcp_closed,S}`/`{inet_async,…}` messages; there is no `INET_REQ_*` for it and the `Driver` seam has no owner notion. The runtime must implement it as `PortRegistry`/`beam_process::ProcessTable` ownership transfer plus the message drain.
- **`erlang:port_control/3` → `PortRegistry::port_control`.** The registry seam (with the reserved `"close"`) and a loaded C driver's `control` reply (through `rbuf`/`cres`) are pinned by tests; the BIF/`DrvPort` wiring is owed, and the runtime's own `.so` `DriverPort` adapter must forward `control` too (its number-verb form).
- **`open_port/2` stream options → `SpawnDriver::with_stream_options`.** The runtime must pass `stderr_to_stdout`/`eof` as a `StreamOptions` and, for an `eof` port, poll `PortRegistry::take_eof(id)` and emit the bare `{Port, eof}` message (the oracle's shape) exactly once.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** `TcpInetDriver::peer_closed()` latches the close and the driver's `recv`/`send` already answer the C's `[0]closed`/`[0]enotconn`; the runtime needs a `Driver` accessor (e.g. `port_closed()`) to observe it and deliver `{tcp_closed, Port}`.
- **A `>64`-byte `binary`-stream read is a `beam_rt` gap** (a port read larger than the on-heap binary limit must become an off-heap refc binary in the runtime's binary-build path); and **file/`prim_file`/`standard_io`/`io_request` handling is `beam_rt`/`beam_bifs`, not `beam_io`** (this crate provides only the `efile`/`fd` drivers and framing).
- **`erlang:monitor/2` on a port target → `PortRegistry::{port_table,port_table_mut}`.** Those accessors hand out the registry's **own** id table (the `PortTable` `open`/`close` allocate/release through) — the `&mut PortTable` operand `beam_process::ProcessTable::{monitor_port,monitor_port_term,demonitor_port}` require; `ProcessTable::monitor_term` answers a typed `unsupported` for a port target, so a port monitor MUST be routed through the port API with this table. **Borrowing rule (in `port_table_mut`'s rustdoc):** the `&mut PortTable` borrows the registry, so a caller holding it behind a `RefCell` (`beam_rt`: `Rc<RefCell<PortRegistry>>`) must take the registry's `RefMut` + the `&mut PortTable`, run the single monitor/demonitor call, and drop the whole chain before any nested borrow of the same registry (else `beam_rt`'s `registry_mut` returns the typed `error::unsupported(...)`, or a bare `borrow_mut()` panics); the `&mut ProcessTable` side has the same rule. **Runtime adoption is owed.**

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks`. Keys are port *numbers* (`PortId::number()`). To be woken by a handled OS signal, register `SignalFacility::read_fd()` with the poller.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`); do not close them elsewhere. `EfileDriver` composes an `FdDriver`, so the same ownership rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- `Ready` has **no public constructor**: tests that need a specific readiness forge it through `Event::new(token, key, ready)` with a real `Ready` or through the public `schedule_readiness(key, Readiness)`.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP and restore it. The facility is process-global — serialize tests on a shared `Mutex`. A libtest binary delivers `kill(getpid(), ..)` to the harness's idle thread, so addresses to a *waiting* thread use `pthread_kill`.
