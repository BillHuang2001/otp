# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Built-in Drivers, Signals, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — one of the two clean rewrite seams (Part II §A): the layer reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**), so a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.

Hosts seven things: the `mio`-backed **poller/reactor** (`Token`→registration map, `EINTR`-tolerant `poll`); the **`Port`** (a process-like I/O endpoint with input + output byte queues, a lifecycle, driver dispatch); **port-task scheduling** (`INPUT`/`OUTPUT`/`TIMEOUT` + reductions, `port_task.rs`, mirroring `erts_port_task_execute`); the **`Driver` trait + built-in drivers** (`fd`, `efile`, the OS-child `spawn`, TCP `tcp_inet`, `{line, N}` buffering, the text⇄binary phase-change protocol); the **driver C-ABI host layer** (`src/abi/`) — a `.so` loaded by `beam_abi::driver::loader` presented as a `Box<dyn Driver>` by [`DriverPort`], its `driver_*`/`erl_drv_*` calls served by [`AbiHost`] over this crate's poller/queues/timer, with [`PortHost`] for atom interning (the one hook it cannot fill) and [`DriverTable`] (`src/abi/table.rs`) the process-global driver registry (the C's `driver_list`) plus its port-creation service; the **OS-signal facility** (`src/signal.rs`) — the self-pipe + async-signal-safe trampoline (with `sigaction(2)` install/query) backing `os:set_signal/2`, the signal `unsafe` work `beam_rt` (which is `#![deny(unsafe_code)]`) cannot do itself; and the **dynamic-library primitive** (`src/ddll.rs`) — a safe `dlopen`/`dlsym`/`dlclose` wrapper with the `erl_ddll` error-atom taxonomy that `beam_rt`'s `erl_ddll` floor builds on.

`beam_rt` (boot/`system_info`/driver registration) consumes and **drives this crate's ports**: one long-lived `Poller` + `PortRegistry`, a [`SpawnDriver`] from its decoded `open_port/2` terms, the port-task round (`execute_port_tasks`) from its main loop, and the resulting [`PortNotification`]s plus the `take_exit_status`/`take_eof` seams turned into `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` delivered to the owning process (waking a blocked receiver through the `beam_process` scheduler). `beam_process` observes ports by id (the peer of pids in `ptab`). This crate presents a C driver `.so` as the same `Box<dyn Driver>` a built-in gets, through [`make_loaded`] → [`DriverPort`] — **its own** A.4 host path; the *running* runtime opens `.so` drivers through `beam_rt`'s own driver host instead (see *Known Issues*). This crate is the **library**; the scheduler *thread* wiring (poll loop, port run queues) lives in `beam_rt`. The `efile`/`fd`/`tcp_inet` drivers and the `signal`/`ddll` facilities are **not yet on the running runtime's path** — only `SpawnDriver` is constructed by `beam_rt` today (see *Handoffs*).

Legacy C ground truth (read-only): `../../erts/emulator/sys/common/erl_poll.c` + `erl_check_io.c` (poll loop, one-shot re-armed readiness, self-pipe wakeup), `../../erts/emulator/beam/io.c` (`erts_port_command`/`erts_port_control`, the `ioq` output queue), `erl_port.h`, `erl_io_queue.{c,h}` (`SysIOVec` queue), `erl_port_task.{c,h}` (the async work unit + reductions), `../../erts/emulator/drivers/common/inet_drv.c`, `../../erts/emulator/sys/unix/erl_child_setup.c` (`{line, N}` / binary phase-change), `../../erts/emulator/beam/erl_bif_ddll.c` + `../../erts/emulator/sys/unix/erl_unix_sys_ddll.c` (the `erl_ddll` errcode/atoms + `dlopen` flags), `../../erts/emulator/sys/unix/sys.c` (`signalterm_to_signum`, the `os:set_signal/2` set).

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`. Only the **frozen contracts and non-obvious behaviour** are listed; rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque registration handle; **token `0` is the waker's**; user tokens start at `1`.
- `Interest` — readiness mask (`READABLE`/`WRITABLE`/`BOTH`). · `Ready` — observed readiness, **no public constructor** (only `Ready::default()` and `From<Ready> for Readiness`). · `Event` — a readiness event (`token`/`key`/`ready`); `Event::new` lets tests forge one.
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`** created in `new()`; registered by raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks); `waker()` an infallible cheap clone.
- **`Poller::poll` is `EINTR`-tolerant.** An `ErrorKind::Interrupted` wait is **retried**, not returned as `BeamError::Io`: `epoll_wait`/`poll`/`select` are never restarted after a handler runs, not even with `SA_RESTART` (`signal(7)`), so a handled signal (see `signal::SignalFacility`) would otherwise break the runtime's poll loop. The retry **preserves the deadline** (`poll(Some(d))` subtracts the elapsed time, so repeated signals can never block past `d`; `poll(None)` resumes). `mio` does not retry `EINTR` itself.
- **Regular-file fallback (internal, no public signature change).** `mio`/epoll refuses regular files (`EPOLL_CTL_ADD` ⇒ `EPERM`), so `Poller::register` keeps a `libc::poll(2)`-backed fallback set: an unsupported descriptor is watched with `poll(2)` and its readiness merged into `Poller::poll` in the same `Event`/`Ready` shape; the fallback probe reports its `std::io::Error` (an `EINTR` probe is retried by the same loop; any other failure is surfaced), and `poll` never blocks indefinitely while the fallback set is non-empty (`FALLBACK_POLL_CAP`, 1 ms).
- `Waker` — an `Arc`-backed, cloneable, thread-safe handle to that one wakeup handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — a single deadline; `Timer` — deadlines keyed by `u64`. · `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS = 4000`; `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS / 100 (40)`; `PORT_REDS_EXECUTE = CONTEXT_REDS / 4 (1000)`.
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`); `PortTask` (`Copy + Eq + Debug`).
- `PortTaskQueue` — one pending task per kind (dedupe), ordered by kind priority then FIFO `seq`, timeouts deadline-gated. `arm_timeout(deadline)` re-points/replaces a pending `TIMEOUT`, unlike the dedupe-by-kind `enqueue_timeout`, which cannot re-point.
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed), `is_idle()`, `From<Ready>`.
- `PortNotification::Data { port, bytes } | Closed { port }` — the seam the runtime turns into `{Port, {data, Data}}`/port-exit messages. · `PortTaskOutcome { pub ran, pub reds_used, pub notifications }` — one round's result.

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }`. · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` — the budget `handle_events` runs.
- `PortControl::CLOSE == "close"` — the one **reserved** control-op name (a namespace marker, not an enum: any other name is a driver verb).
- `PortCommandOptions { nosuspend, force }` — carried/validated but no-ops (M1 ports never busy; the BIF layer owns their effect once a busy-port command queue exists).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the endpoint, scheduling (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`) and exit/async/stream surfaces (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`). **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`) refreshes the port timer from `Driver::next_timeout` via `refresh_timeout`: `Some(d)` arms/**re-points** the single `TIMEOUT` task at `d`, `None` clears it (a driver's declaration is authoritative until its next interaction). Re-exports `PortRegistry` so `crate::port::PortRegistry` resolves.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` keyed by port number; basic ops (`new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`). `port_table`/`port_table_mut` expose that **same** id table (see the port-monitor handoff); `port_table_mut`'s rustdoc carries the borrowing rule. Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`); `execute_port_tasks` (port-number order under a reduction budget ⇒ a `PortTaskOutcome`; before harvesting input it drives async completions for every live port whose driver answers `Driver::has_pending_async`, so a `driver_async` job reaches `ready_async`/`async_free` with **no** runtime call); `schedule_events`/`schedule_readiness` (enqueue only — an `INPUT`/`OUTPUT` task only for directions the driver armed (`driver::PortArms`)); `port_command` (queue output + schedule an `OUTPUT` task; the write happens in the task); `port_control` (the reserved `"close"` closes with an empty reply; **any other `op`** goes verbatim to `control(op, arg)`, its reply returned); `take_exit_status`/`take_eof` (the once-only reaped child status / EOF report); `schedule_timeout`/`cancel_timeout`/`next_deadline` (explicit port timers; `next_deadline` = the min over live drivers' `Driver::next_timeout`); `notify_port_exit` (`Driver::port_exit` **at most once**, port left live, independent of `close`/`stop`); `drive_async` (a manual async drive point for one port).

### `driver.rs`
- `DriverFlags(u32)` — `Copy + Eq`; `SOFT_BUSY`. · `PortExitReason { Closed, OwnerExited, Normal }` — the port-exit notification vocabulary.
- `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number. (`pub(crate) PortArms` records the directions the driver armed; not public.)
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`), `control`, `timeout`, `next_timeout() -> Option<Instant>` (= `None`; the driver's declared next deadline, mirrored into the port's `TIMEOUT` after each interaction), `port_exit(PortExitReason)` (= `Ok(())`; the once-only advisory port-exit notification, distinct from the teardown `stop`), `drive_async` (= `Ok(0)`; the async-completion drive point, `DriverPort` overrides it with `poll_async`), `has_pending_async() -> bool` (= `false`; the probe the port-task round uses, `DriverPort` overrides via `AbiHost::has_pending_async`), `take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`; the once-only reaped child status, overridden only by `SpawnDriver`), `take_eof() -> Result<bool>` (= `Ok(false)`; the once-only EOF report, overridden only by `SpawnDriver`). New capabilities must be additive with defaults that keep the built-in drivers compiling.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"` and `"tcp_inet"`**.

### `drivers/` (each module's role is in the Routing Table)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver; **owns** its fds (closed on `stop`/`Drop`). Constructors `pipe`/`connected(read_fd, write_fd)`/`read_only`/`write_only`; line/phase modes (`with_line_mode`/`set_line_mode` (0 = unlimited)/`set_binary_mode`/`is_line_buffered`/`phase`/`set_phase`/`max_line_len`). `Driver`: `start` registers the read fd `READABLE`; `output`/`ready_output` drain `ctx.output()` to the write fd (`EAGAIN` ⇒ keep queued + arm `WRITABLE`); `ready_input` reads into `ctx.input()` (loops to `EAGAIN`, latches `read_eof` on `read(2)==0`, flushes a pending partial line at EOF, then **de-registers the read fd** so an exhausted — level-triggered fallback — regular file stops producing events; the fd stays attached/owned, so a post-EOF `ready_input` is still `Ok`). `control` verbs: `line [decimal(N) | "line,<N>"]`, `noline`, `binary`, `text`, `getopts` (reply `b"line,<N>"`/`b"binary"`); unknown ⇒ `BadArg`. New `pub(crate)` write-slot seams `adopt_write_fd`/`release_write_fd`/`has_write_fd`/`attached_fd` (the efile read+write open attaches one fd in both slots).
- `line_buffer.rs` — `LineBuffer` + `DEFAULT_MAX_LINE_LEN = 1024`: frames on `\n` (a preceding `\r` is kept as part of the terminator), splits a line longer than `max_len`, holds a partial line until `flush_all`/EOF.
- `binary_io.rs` — `Phase { Text, Binary }` + `PhaseChange`, the `erl_child_setup` text⇄binary phase machine, default `Phase::Binary` (byte-identical to raw passthrough); `handle` frames Binary as one raw frame and Text as line frames; `flush` returns the trailing partial line (Text only).
- `efile.rs` — `EfileDriver` (`name() == "efile"`) delegates byte movement to a composed `FdDriver`; `control` verbs: **`open [<flags> ]<path>`** (`read`/`write`/`append`/`exclusive`/`sync`/`binary`/`list`, translated exactly as the C's `efile_translate_modelist` + `get_flags` — `read` ⇒ `O_RDONLY`, `write` ⇒ `O_TRUNC|O_WRONLY|O_CREAT`, `read`+`write` ⇒ `O_RDWR|O_CREAT`, `append` cancels `O_TRUNC` and adds `O_APPEND`, `exclusive` ⇒ `O_EXCL`, `sync` ⇒ `O_SYNC`, `append`/`exclusive` imply write and no access flag defaults to read — always plus `O_NONBLOCK|O_CLOEXEC` and the C's `FILE_MODE 0666`; a bare `<path>` keeps the original read-only form, spaces included, with `open ./read` as the documented disambiguation), `close` (releases the read *and* write slots), `path`, `eof`, **`position [<N>]`** / **`seek <whence>[,<offset>]`** (whence `bof`/`cur`/`eof` = the C's `EFILE_SEEK_*`; reply = decimal absolute offset), **`sync`** (`fsync(2)`), **`truncate [<len>]`** (no arg ⇒ `ftruncate(fd, lseek(fd,0,SEEK_CUR))`, the C's `truncate/1`; negative ⇒ `BadArg`), **`binary`**/**`list`** (record the public `FileDataMode` via `EfileDriver::data_mode()` and select the raw byte phase — `file:` has no line framing), plus the delegated `line`/`noline`/`text`/`getopts`. `open` refuses a **directory** with `EISDIR` (the oracle's `open_file_is_dir` type check; `open(2)` alone would open one read-only) and attaches a **read+write** open's descriptor in *both* slots via a `dup(2)` of one file description, so each fd is closed exactly once. `open` works on **regular files** (poller `poll(2)` fallback) and on epoll-servable descriptors (pipes/FIFOs/char devices/sockets); `write_only`/`connected` write regular files too. A failed `open`/syscall ⇒ `BeamError::Io` carrying the errno (the `{error,atom}` rendering is `prim_file`'s); an unopened port / unparsable argument ⇒ `BadArg`. `make_efile()` is its `DriverFactory` (the built-in `"efile"`).
- `spawn.rs` — `SpawnStream { Binary, List }` (`Default = List`) = the `binary`/`list` option (the **runtime** builds `{Port, {data, Data}}`; the driver passes bytes through). `SpawnSpec { Spawn { command, argv }, SpawnExecutable { path }, Fd { fd } }` = the term-free `open_port/2` `Name` (`/bin/sh -c Cmd`; `argv`/`Path` direct, `Path` + `SpawnOptions::args`; or an adopted descriptor, no child); `command()` = the `port_info(Port, name)` value (`fd:<N>` for the descriptor form). `SpawnOptions { stream, cd, env, args, exit_status }` (`Default`: `list`) describes the process; `StreamOptions { stderr_to_stdout, eof }` (`Default`: both `false`) the two options shaping only the child's **streams**. `build_command(spec, options)` (= `build_command_with_stream(spec, options, StreamOptions::default())`) sets argv, shell-vs-direct, `{cd,…}`/`{env,…}` and the standard streams (`stdin`/`stdout` piped, `stderr` inherited or, under `stderr_to_stdout`, an **exact fd-1 duplicate** via `pre_exec` `dup2(1, 2)`); an empty command/path or argv ⇒ `BadArg`; it starts nothing, so it is unit-testable alone. `SpawnDriver` (`name() == "spawn"`) is **constructed** (`new` = `with_stream_options(spec, options, StreamOptions::default())`), **really spawning** in the constructor and reaping eagerly; accessors `os_pid`/`command`/`stream`/`eof`/`exited()`, plus the once-only `take_exit_status()`/`take_eof()`. A **failed spawn** has two shapes: an `access(X_OK)`-rejected path ⇒ a constructor `BeamError::Raise` (errno atom); a path the check accepts but the `exec` rejects (a searchable **directory**, a no-executable-format file) **opens the port** via `fork_exec_child`'s `libc::fork`/`execve`, whose child `_exit(errno)` sets the exit status to the errno. `start` registers the descriptors; stdout → the port input queue (drained to `EAGAIN`, EOF latched + deregistered/closed); stdin drains the output queue (`O_NONBLOCK`; `EAGAIN` keeps the remainder queued + arms write readiness); `stop`/`Drop` kill + reap + deregister/close every descriptor, but an adopted `{fd, N}` is **never** closed. **This is the ONLY module in the crate that may spawn OS children** (project invariant).
- `inet/` (`mod.rs` + `wire.rs` + `sys.rs` + `opt.rs` + `tests.rs`) — `DRIVER_NAME = "tcp_inet"` = the name `port_info(Port, name)` reports and `prim_inet` opens; `make_tcp_inet()` = its `DriverFactory`. `TcpInetDriver` (`name() == "tcp_inet"`) = a non-blocking TCP socket behind a port; `from_socket(fd)` adopts a descriptor and probes its kernel state (`SO_ACCEPTCONN` ⇒ listening, `getpeername` ⇒ connected, else open), like `inet_ctl_fdopen`; `connect_error()` = the late `SO_ERROR` of a non-blocking `connect`; `peer_closed()` = whether the peer's close is latched; `InetState` = the socket state. Control verbs (the C `INET_REQ_*`/`TCP_REQ_*`): `open`/`listen`/`close` `[1]`; `bind` `[1] ++ port_be16`; `accept` `[1] ++ fd_be32` (bare `[1]` if nothing pending, `[0]einval` if not listening); `connect` `[1]` (or `[0]exbadport`/`[0]eisconn`/`[0]einval`/`[0]++errno`); `send`/`recv`/`shutdown` `[1]` (or `[0]enotconn`); plus **`setopts`/`getopts`** (`src/drivers/inet/opt.rs`, the `inet_drv.c` `INET_REQ_SETOPTS`/`GETOPTS` wire): `setopts` takes five-byte `[opt, val_be32]` records and answers `[1]`, `getopts` takes one-byte codes and answers `[1] ++ [opt, val_be32]*` in request order; a trailing partial `setopts` record is ignored, an empty payload is a bare `[1]`, an unserved code is the whole `[0] ++ "einval"`, and neither has the C's `IS_OPEN` guard. Four codes are served — `keepalive`(`SO_KEEPALIVE`)/`sndbuf`(`SO_SNDBUF`)/`recbuf`(`SO_RCVBUF`)/`nodelay`(`TCP_NODELAY`) — each a direct `setsockopt`/`getsockopt`, so `recbuf`/`sndbuf` report the **kernel's** value (Linux doubles a request: 4096 reads back 8192, exactly the oracle); a rejected `setsockopt` is not propagated (the C's `propagate = 0`). Operational failures = `[0] ++ lowercase-errno-name` (`erl_errno_id`); malformed args / unknown verbs ⇒ `BadArg`; packed addresses use `INET_AF_INET`/`ANY`/`LOOPBACK`. **Peer close** is latched (`PeerClose`): a `read(2)==0`, a reset (`ECONNRESET`/`ECONNABORTED`/`EPIPE`) or a send error is the same event — the poller registration is released and queued output dropped, and the **first** `recv`/`send` after it answers `[0]closed`, every later one `[0]enotconn` (`TCP_ADDF_DELAYED_CLOSE_*`). Flow control mirrors `FdDriver` (`MSG_NOSIGNAL`, `EAGAIN` keeps the remainder queued + arms write readiness, a drained queue drops writability and applies a deferred `shutdown`, `EINPROGRESS` arms write readiness). **Absent by design** (each answers a clear `[0]einval`/`BadArg`/state error, never a wrong result; the module docs name what each needs): `{active,false|true|once|N}` + `{deliver,…}` + `active_count` (a driver-owned delivery path — the C's `tcp_deliver`/`tcp_recv` loop); `{packet,N}`/`line`/`http`/`raw` header decoding (the `htype`/`tcp_parse_options` re-framing machinery + `INET_LOPT_LINE_DELIM`; the largest single piece); per-op timeouts — `TCP_REQ_RECV`'s 4-byte timeout and `send_timeout`/`send_timeout_close` (the C's driver multi-timer + an **asynchronous** `{error,timeout}` reply, which this port's single `TIMEOUT` task and absent async channel cannot express); the async-op queue (`INET_MAX_ASYNC = 1`, `[1] ++ async_id_be16` + `{inet_async,…}`, why `recv` rejects the 8-byte `Timeout(4),Length(4)` payload with `BadArg`); IPv6/UDP/SCTP/Unix-domain sockets + DNS; the second-port `accept`/multi-accept; `controlling_process` (not driver state — see *Handoffs*); `fdopen`/`sendfile`/`unrecv`/`getstats`/`getfd`/`ignorefd`.

### `src/abi/` (`mod.rs` + `host.rs` + `job.rs` + `port.rs` + `table.rs`) — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a [`Driver`](src/driver.rs) — the only place here holding raw `ErlDrv*` pointers and calling foreign code; a `pub` sub-tree (`pub use crate::abi::*`).
- `mod.rs` — module docs (the derivation, the stable `ErlDrvPort` handle, the built-in/`.so` unification, the `unsafe`-module marking, where each of the four process-global `driver_*` slots reaches or refuses) + `pub mod host; job; port; table;` + re-exports.
- `host.rs`:
  - `pub trait PortHost` — the runtime hook `beam_io` cannot fill: required `intern_atom(name) -> Option<Eterm>`; defaulted `connected_pid()`/`caller_pid()` (`None`) and `send_term(to, term) -> bool` (`false`; the sink for `erl_drv_output_term`/`erl_drv_send_term`, `to == None` = the port owner). **A locally-interned atom does NOT match the runtime's atom table** — `beam_rt` MUST inject its own `PortHost` over the shared table.
  - `pub struct LocalAtomPortHost { atoms: AtomTable }` — a **test/standalone** host only (seeds names in order; inherits the optional defaults; *not* the runtime's table).
  - `pub(crate) SelectedFd { token, interest, owes_stop_select }` (a **sticky** `ERL_DRV_USE` release obligation, merged on re-selection — the C's `ERTS_EV_FLAG_USED`; `wants_stop_select()` = `ERL_DRV_USE` without `_NO_CALLBACK`) and `DriverState` — the port's persistent C-ABI state: `selected: BTreeMap<RawFd, SelectedFd>` (a `BTreeMap` so `ready_input`/`ready_output` pick a **stable** fd), `deadline: Option<Instant>` (the `driver_set_timer` deadline), `jobs: AsyncJobs`, and `queued_stop_select: Vec<ErlDrvEvent>` (events a `driver_select(..., 0)` released, taken by `take_queued_stop_select` for the port to fire). Deliberately **no `Drop`** (draining there could race the worker; `AsyncJobs::Drop` + the channel close is race-free).
  - `AbiHost` — the `DriverHost` impl, **owning** everything (`port_host: Box<dyn PortHost>`, `heap: Heap`, `state: DriverState`, `driver: Option<DriverIdentity>`, `ctx: Cell<*mut c_void>`) so it `Box`es behind a stable `ErlDrvPort` (a `DRIVER_HEAP_WORDS = 1024`-word term heap). With **no context installed** every port-touching method fails gracefully (`-1`/`None`/no-op), never derefs null. Behaviors: `intern_atom`/`connected_pid`/`caller_pid`/`send_term` → `PortHost`; `output` → the port's **input** queue (`0`/`-1`); `select(_, event, mode, on)` → `fd = event as usize as RawFd` (the C's fd-cast): `on != 0` registers / **re-registers in place** / `on == 0` de-registers (unknown fd ⇒ `0`), READ→READABLE, WRITE→WRITABLE, both→BOTH, **neither→READABLE** (an `ERL_DRV_USE`-only `mode` still watches the fd for close/error), and the sticky obligation is merged (a re-select without `ERL_DRV_USE` keeps an earlier request; `_NO_CALLBACK` declines it); a release that owes `stop_select` pushes the *deselecting* call's event onto `DriverState::queued_stop_select`; `has_pending_async` → `DriverState::jobs.in_flight() > 0`; `set_timer` arms `deadline` (`0`), `cancel_timer` clears it (`0`), `read_timer` = remaining ms (`Some(0)` expired, `None` none); `r#async` → `AsyncJobs::schedule` (`id as c_long`; failure runs the driver's `free(data)` and returns `-1`); the four **driver-registry** hooks → `add_driver_entry` records `de` in `DriverTable` (`0`, or `1` if the entry's `init` refused it), `remove_driver_entry` forwards `1`/`0`/`-1`, `lock_driver` `0` for a `dlopen`ed-driver port / `-1` for a bare/static host, `create_port` = `ERTS_INVALID_ERL_DRV_PORT` (see *Design Decisions*).
  - `DriverIdentity { name, loaded }` (`pub(crate)`) — the port's registered driver name + whether it came from a `dlopen`ed object; a field on `AbiHost`, **not** a `DriverHost` method (`for_driver`/`with_driver`).
- `job.rs` — `AsyncJobs`: a **bounded, process-global worker pool** (`POOL_THREADS = 4` long-lived threads, lazily started, fed by one shared job queue — the C's async thread pool), a per-port `mpsc` completion channel and the `driver_async` queue position; `schedule(invoke, data, free)` (`None` `invoke` = fire-and-forget: a valid position, and `free(data)` IS run — the C null-derefs here, a documented deviation; `Err(())` only when no worker could start at all) and `drain() -> Vec<AsyncCompletion>`; `in_flight()` is the probe behind `AbiHost::has_pending_async`; `AsyncData(*mut c_void)` is the one `unsafe impl Send`. **Exactly-once release:** `AsyncCompletion` owns `async_data`/`async_free` and runs `async_free` on `Drop` unless disarmed by `handed_to_ready_async()`; `AsyncJobs::Drop` drains every undelivered completion; the worker drops the completion a failed `tx.send` hands back (the C's `!p` branch). `set_keepalive`/`KeepAlive` pin the loaded `DriverLibrary` for outstanding jobs (the C's `DE_Handle` reference), so `async_free` always runs **mapped** code. **Deviation:** `async_free` runs on the **port** thread (the C uses the worker).
- `port.rs`:
  - `DriverPort` — a loaded `ErlDrvEntry` as `impl Driver` (`lib: Arc<DriverLibrary>`/`name`/`command`/`abi: Box<AbiHost>`/`env: Box<DriverEnv>`/`data: ErlDrvData`). The library is an **`Arc`** so the process-global table can keep one loaded object registered while ports are created from it; a per-port `LibraryKeepAlive` (`Arc<dyn Any + Send + Sync>`, a documented `unsafe impl Send/Sync`) holds it down while any `driver_async` job is outstanding, so `DriverLibrary::drop` (`finish` + `dlclose`) runs with the last owner **and** after the last job. `DriverPort::load(...)` calls `beam_abi::driver::loader::load` (validating `command` **first**, so an interior NUL is `BadArg`, not a load failure), mapping `DriverLoadError` to a typed `BeamError::Raise` (`err.reason_atom()`); `DriverPort::from_library(Arc<DriverLibrary>, CString, host)` wraps an **already loaded** object without a second `dlopen` (the registry's port-creation path; does **not** re-run `init`) and installs the `KeepAlive`. `env` + `abi` are **both boxed**, so the `ErlDrvPort` a driver sees is the **same pointer for the port's whole life**.
  - `poll_async` — drains the jobs, sorts by queue position (deterministic, the C's order), runs `ready_async` if the entry has one (then `handed_to_ready_async()` — the completion is disarmed, `async_free` never runs) else `release()` (runs `async_free` with the host still published); the **port-task round drives it** (via `Driver::has_pending_async`), so a completion reaches the driver with no runtime call. `make_loaded(path, name, command, host) -> Result<Box<dyn Driver>>` is the built-in/`.so` unification helper (see *Design Decisions*).
  - **`stop_select` (the `ERL_DRV_USE` release callback).** `AbiHost::select` records the sticky obligation; `DriverPort` fires the loaded entry's `stop_select(event, NULL)` from three places, all **after** the driver call that produced the release has returned (as in the C): a `driver_select(..., 0)` (drained right after the routing `call` returns, with the event the *deselecting* call was given), port teardown (`Driver::stop`, for every registration still selected, with the fd cast to an `ErlDrvEvent`), and `Drop` (a `DriverPort` dropped without `stop` — e.g. a failed `start`). A `USE_NO_CALLBACK` registration or an entry with no `stop_select` slot is skipped (the C's `no_stop_select_callback`); the host is published around each callback. `release_selects_on_teardown` also drains `take_queued_stop_select()` (a release an earlier deselect queued and no `call`/`poll_async` drained would otherwise be dropped on `Drop`).
  - **Current-host publication** — `DriverPort::call` wraps every callback it routes (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`port_exit`/`stop`, plus `poll_async`'s `ready_async` branch) in `beam_abi::with_current_host`, and so does the `stop_select` firing; `poll_async`'s `async_free` branch (which bypasses `call`) publishes separately. These are the only paths running driver code, so the two port-less slots (`add_driver_entry`/`remove_driver_entry`) reach a host during a callback and answer the C's failure value outside one — **scoped to this crate's `abi::DriverPort` only; the running runtime's `.so` path is `beam_rt`'s own `DriverPort` (see Known Issues).** The published `&mut dyn DriverHost` comes from a raw `*mut AbiHost` (the `Box` the port owns) with a documented `// SAFETY:` rationale.
  - `Driver` mapping: `name` = the entry's name; `flags` = `SOFT_BUSY` iff `ERL_DRV_FLAG_SOFT_BUSY`; `start` (absent slot or any of `ERL_DRV_ERROR_GENERAL`/`ERRNO`/`BADARG` ⇒ `BadArg`, else keeps the `ErlDrvData`); `output`/`ready_output` (drain the port output queue; absent `ready_output` falls back to `output`; drained bytes treated as written — the C callbacks are `void`); `ready_input` (the read-armed fd, else null; absent ⇒ no-op); `timeout` (call, then clear `deadline`); `control` (the `&str` command is a **decimal `c_uint`**; absent slot or `cres < 0` ⇒ `BadArg`; reply copied from `*rbuf`, `n` bytes, into a `CONTROL_REPLY_CAPACITY = 4096` buffer); `next_timeout` = `state.deadline`; `has_pending_async` = `AbiHost::has_pending_async`; `port_exit` → `process_exit` (null `*mut ErlDrvMonitor`) if present, else `emergency_close` if present, else no-op; `take_exit_status` = default `Ok(None)` (a driver-private child is a `beam_rt` handoff); `take_eof` = default `Ok(false)`; `stop` (absent ⇒ no-op, then releases every still-selected registration, firing the owed `stop_select`s). `Drop` drains `jobs` **before** `release_selects_on_teardown(None)` (i.e. while `lib` is still mapped).
- `table.rs` — the **process-global driver registry + its port-creation service** (the `beam_io` half of the four `ErlDrvApi` slots, reached through [`AbiHost`](src/abi/host.rs)). `unsafe`-marked (stores/derefs `*mut ErlDrvEntry`, calls the entry's `init`); the one `unsafe impl Send for Inner` (mutex-serialized) carries a rationale.
  - `DriverTable` — `global()` (the C's one `driver_list`; `OnceLock`) / `new()` (isolated, tests). `add_entry(*mut ErlDrvEntry)` (**`unsafe`**; the C's `add_driver_entry`) records a **statically linked** entry after running its `init` (non-zero ⇒ the `driver_init_failed` raise and **no** registration); null entry/name ⇒ `BadArg`. `add_loaded(DriverLibrary)` records a **dynamically loaded** driver (`entry()` + `.name()` + `Arc<DriverLibrary>` handle) without re-running `init`. `remove_entry(*mut ErlDrvEntry)` (safe — address comparison) answers the C's `-1` (dynamic: *"Not allowed for dynamic drivers"*) / `1` (removed) / `0` (not found), newest first. `lock_driver(name)` = `0` (locked; has a handle) / `-1` (no handle = statically linked, or unknown). `lookup(name) -> Option<RegisteredDriver>` (newest wins, the C's head-inserted list) / `names()` / `len()` / `is_empty()`. `create_port(&mut PortRegistry, &mut Poller, name, command, host) -> Result<PortId>` resolves the registered driver, builds a `DriverPort::from_library` and opens it via `PortRegistry::open` (so `start` runs and supplies the instance's `ErlDrvPort`); the table lock is **released before** `start`, so a driver may re-enter the table.
  - `RegisteredDriver { name, entry: *mut ErlDrvEntry, dynamic, locked }` — the read-only snapshot.
  - **Deviation:** the C's `driver_create_port` re-uses the *creating port's* driver instance and stores the caller's `drv_data` verbatim; here a **fresh** instance is created by running `start` (no shared instance across ports).
  - **M1 gap:** `create_port` needs a [`Driver`] adapter, which exists only over a loaded `DriverLibrary`; a **statically linked** registration answers the typed `notsup` raise (never a wrong port).

### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
- `Signal` — the twelve signals `os:set_signal/2` accepts, fixed by `signalterm_to_signum` (`../../erts/emulator/sys/unix/sys.c`) and `lib/kernel/src/os.erl`: `SigHup`/`SigQuit`/`SigAbrt`/`SigAlrm`/`SigTerm`/`SigUsr1`/`SigUsr2`/`SigChld`/`SigStop`/`SigTstp`/`SigCont`/`SigWinch` (`sigcont`/`sigwinch` ARE accepted; `sigttin`/`sigttou` are **not** — they are `!`-commented rows in the C table; `siginfo` is `#ifdef SIGINFO` and excluded). `Signal::ALL: [Signal; 12]` (the `drain` report order); `name()`/`from_name()` (the lowercase BEAM atom, exact/case-sensitive); `signo()`/`from_signo()` (the `libc::SIG*`).
- `Disposition { Default, Handle, Ignore }` — `ALL`; `name()`/`from_name()` for the `default`/`handle`/`ignore` atoms.
- `SignalFacility` — `new() -> Result<Self>` (self-pipe via `pipe2(O_CLOEXEC|O_NONBLOCK)` on Linux/Android, `pipe`+`fcntl` fallback on other unix; publishes the write end to the process-global handler plumbing); `set(&mut self, Signal, Disposition)` (`sigaction(2)`: `SIG_DFL`/`SIG_IGN`/the trampoline, **empty `sa_mask`**, **`SA_RESTART`** — a documented choice; the prior action is captured only on the first change of a signal); `disposition(&self, Signal) -> Result<Disposition>` (read back from the kernel: `SIG_DFL`→Default, `SIG_IGN`→Ignore, any real handler→Handle); `read_fd(&self) -> RawFd` (the fd the runtime registers with `Poller` — **the runtime owns the registration/token**); `drain(&mut self) -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order, then drains the pipe). `Drop` restores every prior disposition and closes the pipe (safe when `set` was never called); the global write end is cleared only if it is still this facility's.
- **Async-signal-safety (frozen).** The installed handler does exactly two async-signal-safe things: one atomic OR into a `static AtomicU64` per-signal bitmask and one `libc::write` of the signal number to the non-blocking pipe. No allocation/locking/unwinding/arbitrary Rust; the signo→`Signal` mapping happens in `drain` (normal context). The pipe byte count is **not** the source of truth (a stray/coalesced byte never duplicates a report; a dropped byte never loses one).
- **Single instance.** The trampoline, the bitmask and the write fd are process-global statics; only one facility should be alive, and `new`-after-`drop` is safe.
- **Portability:** unix only; the self-pipe path is the default on every unix target (no `signalfd` fast path). **Errors:** `BeamError::Io` for a failing `pipe`/`sigaction`; no panic/`unwrap`/`todo!`/`unreachable!`.

### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
- `DynLib` — an owned `dlopen(3)` handle; `Drop` calls `dlclose(3)` exactly once. `open(&Path)` / `open_with(&Path, DynLibFlags)` / `open_cstr(&CStr, DynLibFlags)`; `symbol(&CStr) -> Result<*mut c_void, DllError>` / `try_symbol(&CStr) -> Option<*mut c_void>`; `handle() -> *mut c_void`. Deliberately **no** `into_raw`/`from_raw` (the runtime needs an owned, reliably-closed handle) and not `Send`/`Sync` (raw pointer — single-OS-thread, the crate's invariant).
- `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default and the emulator's mode, `erl_unix_sys_ddll.c:133`; this **matches** `beam_abi::driver::loader`/`nif::loader`), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`, `from_bits`/`bits`.
- `DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary: `Open` (the dynamic `{open_error, Code}` case), `SymbolNotFound` (`symbol_not_found`), `NoDriverInit`, `DriverInitFailed`, `BadDriverName`, `DriverNameTooLong`, `DriverIncorrectVersion`, `NoDdllAvailable`, `Unspecified`, `BadArg`; `reason_atom()`, `errcode()`, `text()`, and the predicates `is_missing_file()` / `is_format_error()` / `is_undefined_symbol()`. Classification is **text-based only** (a failed `dlopen` does not set `errno` reliably and a stale value must never be trusted), mirroring the emulator's `find_errcode`.
- `ERRCODE_TAB` (the emulator's `errcode_tab`, `erl_bif_ddll.c:1709-1720`, byte-for-byte), `errcode_to_atom`/`atom_to_errcode`/`format_error_text`, `symbol_name(&str) -> Result<CString, DllError>`, and the `ERL_DE_*` numeric constants. Path spelling is the caller's: **no** `.so` suffix is appended (unlike `erts_sys_ddll_open`).
- Module docs state the **`-Wl,--export-dynamic`** requirement (an `RTLD_NOW` load resolves `enif_*`/`driver_*` out of the loading executable's `.dynsym`; `beam_rt`'s binary must link with it exactly as this crate's `build.rs` does for its test targets).

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures ⇒ `BeamError::Io`, argument faults ⇒ `BeamError::BadArg`, id/registration exhaustion ⇒ `BeamError::SystemLimit`. **Never panic** on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` is confined to the raw syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`access`/`dup2`, the `inet` socket helpers incl. `setsockopt`/`getsockopt` in `drivers/inet/sys.rs`, the `signal.rs` `pipe2`/`sigaction`, the `ddll.rs` `dlopen`/`dlsym`/`dlclose`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling. Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids are allocated by `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate (via `beam_process::PortId`); a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync`. (Not yet enforced on `Poller`/`Waker` — the `Waker` is explicitly meant to cross threads; `SignalFacility` is process-global.)
- **Only `drivers/spawn.rs` may spawn OS children** (a project invariant); the `signal`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures. New driver capabilities must be additive with defaults that keep the built-in drivers compiling.
- Files target ~1000 lines, split by responsibility: poller / port / registry / port_task / driver / timer / queue / signal / ddll / drivers.
- Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only. No new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge the C-ABI host layer requires).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so an io_uring/`/dev/poll` backend is a drop-in (io_uring not M1).
- **One `mio::Waker` per `Poller`** (`mio` permits one per `Poll`), created in `new()`, shared by `Arc` clone (`Poller::waker` — idempotent, safe to drop); `Poll` returns an owned `Vec<Event>` (reusing the internal `mio::Events` buffer) so the glue can hold `&mut Poller` while iterating.
- **An interrupted wait is retried, never reported as a failure.** `signal(7)` singles out `epoll_wait`/`poll`/`select` as never restarted after a handler runs, `SA_RESTART` notwithstanding, and `mio` does not retry `EINTR` itself, so a handled signal (the `signal` facility's self-pipe is the runtime's only such handler) would otherwise surface as a spurious `BeamError::Io` out of `Poller::poll` and stop the main loop. `poll` retries on `ErrorKind::Interrupted` with the **remaining** budget measured from the call's start (`Instant`), so repeated signals can only shorten the wait; `poll(None)` resumes outright. The `libc::poll(2)` fallback probe reports its `std::io::Error` instead of collapsing `-1` into "no readiness" — the same retry handles its `EINTR`, and every other probe failure is surfaced rather than silently swallowed.
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends and calls `Driver::output`, which **pulls** from `ctx.output()`; `EAGAIN` queues the remainder + arms `WRITABLE` (no double buffering).
- **Task execution here; the scheduler thread above.** `PortTask`/`PortTaskKind`/`PortTaskQueue`/reductions model `erl_port_task.h`; the poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`. `PortNotification` is the seam so the runtime (not this crate) turns port output into messages and wakes the owner via `beam_process` (clean DAG, engine/runtime split intact).
- **Readiness ⇒ task, gated by `PortArms`.** The poller keys by port number, so an `Event` names the port, not the fd; `DriverContext` records the armed directions in `PortArms`, so a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) does not schedule a bogus OUTPUT task on a read-only driver. **Divergence:** the C keeps three FIFO queues, no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT), `seq` tie-break — observable only in the order two *different* kinds run in a round.
- **`handle_events` schedules *and* runs the default round**; full budget control = `schedule_events` + `execute_port_tasks`. It does **not** harvest `PortNotification`s (input stays in the port queue, via `Port::drain_input`; closes unreported) — only `execute_port_tasks` yields `Data`/`Closed`.
- **Driver = Rust trait; the bridge is a `Driver` over a loaded `ErlDrvEntry`.** Built-ins implement `Driver` directly; the frozen `ErlDrvEntry`/`ErlDrvApi` is an ABI, so `DriverPort` adapts it over a `DriverLibrary` (`start→init/start`, `output→output/outputv`, `ready_input`/`ready_output`/`control`/`timeout`/`stop`, `driver_select` ⇒ `DriverContext::register`), changing no `Driver`/`Port`/`PortRegistry` signature.
- **The four driver-registry slots: two process-global, `driver_lock_driver` per-port, `driver_create_port` refuses.** `add_driver_entry`/`remove_driver_entry` act on the process-global `DriverTable`, so they reach a host only via `beam_abi::with_current_host`; this crate's `abi::DriverPort` publishes around every callback it routes, so inside one they reach the table and outside one answer the C's `-1`/`0`. `driver_lock_driver` consults the port's **own** driver, never a name lookup: a `dlopen`ed `DriverPort` ⇒ `0`, a bare/static host ⇒ `-1`. `driver_create_port` ⇒ `ERTS_INVALID_ERL_DRV_PORT` because a callback already holds a `&mut` into the port registry (re-entering `PortRegistry::open` would be unsound aliasing) and a new port needs a `Box<dyn PortHost>` only `beam_rt` can supply — the C's own sentinel, never a fabricated port.
- **One boxed `AbiHost` behind a stable pointer; the live port is reached via an installed `DriverContext`.** A `DriverHost` method runs inside a callback, where the port exists only as that borrowed context; with none installed every port-touching method fails gracefully (never derefs null). `DriverEnv` is lifetime-erased (one `*mut dyn DriverHost`), kept valid for the `DriverPort`'s life.
- **`driver_output` is harvested by a non-empty input queue, not an `INPUT` task.** `AbiHost::output` pushes onto the port's *input* queue; `Port::take_input_notification` reports+drains `Some(PortNotification::Data)` whenever non-empty. A driver calls `driver_output` from `start`/`control`/`timeout`/`output`/`ready_input` — *outside* any `INPUT` task — so gating on task completion would drop those bytes; the queue delivers every `driver_output` once per round.
- **`driver_async` runs on a bounded, process-global worker pool; the port-task round drives the completions.** `AsyncJobs::schedule` queues onto one shared pool (`POOL_THREADS = 4`) rather than spawning a thread per job — an unbounded `thread::spawn` per `driver_async` lets a driver exhaust the OS thread limit, while the C bounds concurrency too. A completed job is recorded on the port's channel and handed to the driver only at a drive point; `PortRegistry::execute_port_tasks` runs that drive point for every live port whose driver answers `has_pending_async`, so a job completes with **no** runtime call. The release obligation is a **value** (`AsyncCompletion`) that owns `async_data`/`async_free` and releases on `Drop` unless disarmed, so `async_free` runs **exactly once** even if the port dies with a job in flight (a `KeepAlive` pins the loaded object until the last job finishes). **Deviation:** the port thread owns `async_free` (the C runs it on the **worker**). `poll_async` sorts by `driver_async` queue position (the C's order under concurrency).
- **`stop_select` is a host-layer obligation, fired outside the `Driver` trait.** A `driver_select` with `ERL_DRV_USE` records a **sticky** obligation on the `SelectedFd`; because the callback receives no port and no failure channel, the `Driver` trait has no method for it — the `DriverPort` adapter fires it directly on deselect (right after the routing `call` returns, matching the C's ordering), at teardown, and on `Drop`, skipping `USE_NO_CALLBACK`/absent-slot. This is the one A.4 entry point that runs *around* the port seam rather than through it.
- **Built-in and loaded unify at `Box<dyn Driver>`; the `.so` path is a helper, not a registry method.** `make_loaded(...)` presents a loaded `.so` as the same `Box<dyn Driver>` `DriverRegistry::create` returns for a built-in; it cannot be a `DriverFactory` (`fn()` pointer) — it needs a path/name/command/`PortHost`, as does `SpawnDriver`. `DriverRegistry`/`open_named` stay frozen.
- **`control` is numeric for a loaded driver.** Built-ins use string verbs (`"close"`, `"line"`, …), a C driver's are integer `INET_REQ_*`-style codes, so `DriverPort::control` parses the `&str` as a decimal `c_uint`; absent slot or `cres < 0` ⇒ `BadArg`. Reply = `cres` bytes at `*rbuf` (our `CONTROL_REPLY_CAPACITY = 4096` buffer, or the driver's own memory valid until the next call) — a **trust boundary** (a driver is native code).
- **`set_timer` always succeeds; `read_timer` = remaining ms, `None` only when disarmed.** The C refuses `driver_set_timer` with no timer; but this port always has one (expired ⇒ `Some(0)`, as the C writes `0`); `beam_abi`'s `driver_read_timer` maps `None` ⇒ `-1` (deviation from `io.c`, which answers `0`/`0`).
- **`ready_input`/`ready_output` name the fd from the driver's own `driver_select` bookkeeping.** The poller keys by **port number**, so a readiness event names the port, not the fd (the C carries it per-`ErlDrvEvent`); `DriverState::selected` (a `BTreeMap`) restores it — M1 passes the stable first fd in the wanted direction (fd order), one callback per round — a floor for a port with several fds selected the same way.
- **The `beam_io → beam_abi`/`beam_alloc` edge (directionally legal).** Wave 5 → wave 0; `beam_abi` is the frozen ABI to adapt, `beam_alloc`'s `Heap` the term arena a driver builds terms on. No cycle, no `*_dev` edge. **Consequence:** `beam_abi`'s own `dlopen` loaders cannot use `beam_io::ddll` (cycle) — see the ddll handoff.
- **Line/phase framing is driver-side.** `{line, N}` + text⇄binary live in `FdDriver` (via `LineBuffer`/`PhaseChange`), matching `erl_child_setup`: the line flag affects how a port *delivers input to its owner*, not output acceptance. Default phase Binary.
- **Exit status via a defaulted trait method, not a notification variant.** The runtime needs a child's reaped status **once** for an `exit_status` port without reaching into driver internals: defaulted `Driver::take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`, so `FdDriver`/`EfileDriver` compile unchanged) + additive `PortRegistry::take_exit_status(id)` — `Ok(None)` = "no child"/"not reaped"/"already reported", `Result` so a failing `wait` is reported. A `PortNotification` variant is rejected: exit status is not a *task-round* outcome and would force every round to carry a status the port may not owe.
- **The spawn driver is constructed, not registered — and reaps eagerly.** A `DriverFactory` is a no-arg `fn` and cannot carry the command/argv/options, so it is built directly from a `SpawnSpec` (`Driver::name()` stays `"spawn"` for `port_info`). The child starts in the **constructor**, so a failed spawn registers nothing and the runtime can read `os_pid()` before `PortRegistry::open`. `{fd, N}` adopts one descriptor as a **duplex** stream (one `Interest::BOTH`) and never closes it. `stop`/`Drop` kill **and** reap — `Drop` reaps because Rust's `Child` does not, else a zombie leaks.
- **Regular files ride a `poll(2)` fallback inside the poller.** `epoll` cannot watch a regular file, so `Poller` keeps a second `libc::poll(2)`-based set for descriptors `mio` rejects and merges its readiness into `Poller::poll` — the reference path ("a regular file is trivially always ready", `erl_poll.c`) with no API change and no new dependency; being level-triggered, it forces `FdDriver` to de-register a read fd at EOF.
- **A failed spawn splits in two, like the reference.** A path the emulator's parent-side `access(Path, X_OK)` check rejects — a missing program, a file without its execute bit, a path through a non-file — is an `open_port/2` **error**: a `BeamError::Raise` carrying the failing `errno`'s lowercase atom (`enoent`/`eacces`/`enotdir`/…), matching `erts_internal_open_port_2`. A path the check *accepts* but the `exec` rejects (a searchable **directory**, a file with no executable format) instead **opens the port**: `fork_exec_child` starts a real `libc::fork`+`execve` child whose `_exit(errno)` makes the exit status equal the errno (`{spawn_executable, "/etc"}` ⇒ `{exit_status, 13}`). An empty program/name ⇒ `BadArg`.
- **The child's stderr is inherited by default; `stderr_to_stdout` aliases it onto fd 1.** The default is `Stdio::inherit` — the reference's `dup(2)`: the child's diagnostics reach the emulator's own stderr and are never port data. The `stderr_to_stdout` stream option makes the child's fd 2 an **exact duplicate of fd 1** via a `pre_exec` `dup2(1, 2)` (one pipe, true write ordering, no second buffer).
- **Timer seam driver-declared + mirrored; port-exit channel advisory + once-only.** `Driver::next_timeout` is mirrored into the single `TIMEOUT` task after each interaction (deadline-gated, never early), with `PortRegistry::{schedule_timeout,cancel_timeout}` as the runtime's explicit override; `Driver::port_exit` fires at most once, distinct from the teardown `stop`. Both additive defaults.
- **The TCP driver is a floor, not a full `inet`** — see the module docs + the *Absent by design* list in the API surface; the served verbs (incl. `setopts`/`getopts`) are oracle-cross-checked.
- **The efile `open` flags are the C's mode translation.** A `read+write` open attaches one `dup(2)`ed descriptor in both slots so each fd is closed exactly once; `read_ahead`/`delayed_write` are NOT open flags and are `prim_file` handoffs (see *Handoffs*).
- **The signal facility is a self-pipe with an async-signal-safe trampoline.** `SA_RESTART` is chosen (a handled signal must not spuriously fail unrelated syscalls); the poller is `EINTR`-tolerant, so the facility's `read_fd` is the notification channel and the runtime must register it. `signalfd` is not used (portability).

## Known Issues
- **The A.4 driver-registry hooks here are correct and tested, but the runtime does not route through this crate's host layer.** The four hooks live in `src/abi/host.rs` over `src/abi/table.rs`'s process-global `DriverTable`; nothing outside `beam_io` references `beam_io::abi`/`make_loaded`/`AbiHost`/`DriverTable`, so this layer is exercised only by this crate's own tests. The running runtime serves the four slots through `beam_rt`'s own self-contained host (`crates/beam_rt/src/port/driver.rs`), which overrides all four hooks and publishes the current host around every driver callback — oracle-pinned (`beam_rt/tests/driver.rs` asserts `0,1,0,-1`). `enif_alloc_env()` in a real NIF remains oracle a live env / Rust NULL.
- **The C-ABI host layer is a floor; a driver must not stash `ErlDrvPort` beyond the callback in M1.** The context is installed per callback (`install`/`clear` around each `DriverPort` call), so a driver that keeps the handle and calls `driver_*` outside a callback (e.g. its own worker thread) gets the C's `-1` (a `driver_output` from a plain `std::thread` returns `-1`; its bytes are dropped). The handle *pointer* is stable for the port's whole life (asserted in `tests/abi_async.rs`); the **installed context** is callback-scoped. `ready_async` receives no port (`erl_driver.h`), so a driver that needs it there uses the handle it stashed in `start` — which works because `poll_async` runs inside a `DriverPort` method with the context installed.
- **The `driver_async` release is exactly-once by construction, and every arm is pinned.** `AsyncCompletion` owns `async_data`/`async_free` and runs `async_free` on `Drop` unless disarmed by `handed_to_ready_async()`; `AsyncJobs::Drop` drains undelivered completions; the worker drops the completion a failed `tx.send` hands back; `schedule(None, ..)` releases the data immediately. `tests/abi_async.rs` (6 tests) exercises every arm over the real C fixture, including a port dropped while a slow job is in flight and one dropped after completion but before any drain. The remaining (cosmetic) gap: the C gives async work its own port-task kind (`call_async_ready`); here it rides the round as an extra drive point rather than a scheduled task.
- **`beam_rt` must inject a real `PortHost` (handoff).** A driver's `erl_drv_output_term`/`erl_drv_send_term`/`driver_mk_atom` gets its atom from `PortHost::intern_atom`; a locally-interned atom (`LocalAtomPortHost`, tests/standalone) does **not** match the runtime's table, so the term compares unequal to the same atom built by running code — a silently wrong result. `beam_rt` owns the shared `beam_term::atom::AtomTable`, so it supplies `PortHost`.
- **`ErlDrvApi` slots served vs. deferred (handoff to `beam_abi`).** The four **driver-registry** slots are served through this crate's host layer; every other slot is `None` in `beam_abi`'s `DRIVER_API` because `DriverHost` has no method for it — the port-queue family (`driver_enq`/`pushq`/`deq`/`sizeq`/`peekq*`/`enqv`/`pushqv`/`vec_to_buf`), port lifecycle & attributes (`erl_drv_init_ack`/`set_os_pid`/`busy_msgq_limits`, the `driver_failure*`/`driver_exit` family, `set_busy_port`, `set_port_control_flags`, `get_port_flags`, `driver_async_port_key`, `driver_get_now`), monitors & the port data lock (`driver_monitor_*`/`driver_pdl_*`), and the mutex/cond/rwlock/tsd/thread families. Deliberately `None`: the binary-refcount trio (an `ErlDrvBinary` is exactly `{ orig_size, orig_bytes }`). Each deferred group names the `DriverHost` methods `beam_abi` must add; see `../beam_abi/CONTEXT.md`.
- **Single-OS-thread only.** No poll threads, no `ThreadProgress`/generation handoff, no `ERTS_POLL_USE_WAKEUP` beyond `Waker`; the invariant is enforced on `Port`/`PortRegistry` but **not** on `Poller` — use it from one thread.
- **Readiness is edge-triggered** (`mio` `EPOLLET`), so a driver *must* drain to `EAGAIN` per callback — `FdDriver` reads/writes in an `EAGAIN`-terminated loop. Readiness is scheduled only for directions the driver armed (`PortArms`).
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop.
- **The file/`efile`, `tcp_inet` drivers and the `signal`/`ddll` facilities are NOT on the running runtime's path.** `beam_rt` constructs only `SpawnDriver`; `file:*` is a Rust-`std::fs` floor in `beam_rt`; `gen_tcp` does not open `tcp_inet`; `os:set_signal/2` has no runtime hook; `erl_ddll` has no floor. They are driver-level/facility-level correct and oracle-cross-checked here — adoption is owed by `beam_rt` (see *Handoffs*).
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output (the emulator's line flag). No `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Decoding `open_port/2` into `SpawnSpec`/`SpawnOptions`/`StreamOptions` (and synthesizing `{Port, {data, …}}`, `{Port, {exit_status, …}}`, `{Port, eof}`) stays the runtime's job — this crate only moves bytes, reports the latched EOF/exit status **once**, and kills/reaps. Writing to a child that closed its stdin fails with a typed `BeamError::Io` (the remainder is kept). Adoption requires non-blocking (`F_SETFL` + `O_NONBLOCK`); a descriptor that refuses (some inherited ones ⇒ `EPERM`) fails the open with `BeamError::Io`. Input is not line-framed (no `line` verb): the `binary`/`list` choice rides `SpawnStream` for the runtime. End-to-end `port_command` to `{fd, N}` is served by `beam_rt` over this driver's duplex output queue.
- **`port_control`/control atoms are not decoded here.** `port_control(op, &[u8])` takes a `&str` op + raw bytes; the C decodes Erlang tuples in `io.c` — decoding `{command, …}`/`{connect, …}` is the runtime's job.
- **`mio` fd registration is `os-ext`/Unix-only** (`mio::unix::SourceFd`); Windows/iocp out of scope (as in `beam_abi`).
- **`tcp_inet` is a floor.** The async-op queue, per-op `driver_set_timer` timeouts, the second-port `accept`, IPv6/UDP/SCTP/Unix-domain sockets, `{active,…}`/`{packet,…}` framing and DNS are absent (see the API surface's *Absent by design*); `recv` rejects a timeout/length argument with `BadArg`. Covered verbs (incl. `setopts`/`getopts`) match the C's reply shapes (oracle-cross-checked), including the latched peer close; surfacing that as `{tcp_closed, Port}` is a `beam_rt` handoff.
- **The `ddll` module is not on any runtime path yet** (the `beam_abi` loaders cannot use it — cycle; see the handoff), and its `{open_error, Code}` dynamic-code table is the runtime floor's to own.
- **File sizes (source vs. in-module tests).** `src/port.rs` 675 source (no in-module tests); `src/registry.rs` 1258 (≈610 source + ≈648 tests); `src/drivers/inet/mod.rs` 1116 source (the +107 is the module docs: verb table, options, accurate-deferred; the option vocabulary/logic is the sibling `src/drivers/inet/opt.rs`, 173; `wire.rs` 182; `sys.rs` ~280; the in-module suite `tests.rs` 937); `src/poller.rs` 966 (the `EINTR` retry + docs); `src/drivers/spawn.rs` 1946 (≈1360 source + ≈586 tests — over 1000 only for its in-module suite; if the source grows, split the term-free spec or the `fork`/`exec` child); `src/drivers/efile.rs` 1123 (≈685 source + ≈438 tests) and `src/drivers/fd.rs` 1141 (≈645 + ≈496) — over 1000 only for their in-module suites; `src/abi/host.rs` 1232 and `src/abi/port.rs` 881 — over 1000 only for their in-module suites; `src/signal.rs` 861, `src/ddll.rs` 850. If any source half grows, split its test module into a sibling `tests/` file. `src/drivers/inet/mod.rs` should be split if it grows further.

## Handoffs (beam_rt — out of this node)
Everything below is **runtime adoption still owed**, not a `beam_io` defect: the seam exists and is tested here; the wiring lives in `beam_rt`/`beam_bifs`.
- **The OS-signal facility (`os:set_signal/2`).** `beam_bifs` registers `os:set_signal/2` as a `RuntimeHooks`-gated key that `beam_rt` does not install, so a call is the typed `unsupported_bif` today. **API contract:** `Signal::from_name/1` → `Option<Signal>` (the twelve accepted atoms, exact/lowercase; anything else ⇒ the oracle's `badarg`); `Disposition::from_name/1` → `Option<Disposition>`; `SignalFacility::new()` → one long-lived facility for the runtime's life (process-global — keep exactly one alive); `set(sig, disp)` → install (`Ok(())` is the oracle's `ok`, a failure is `BeamError::Io`); `disposition(sig)` → the current view; `read_fd()` → register with the process `Poller` (`Interest::READABLE`, runtime-chosen key) — **the runtime owns the registration/token** and `Poller::poll` is already `EINTR`-tolerant; on readiness → `drain()` → `Vec<Signal>` in `Signal::ALL` order → deliver `{notify, Signal::name()}` to the registered `erl_signal_server`. `Drop` restores every disposition and closes the pipe — drop it (or let the process exit) rather than signalling after shutdown. `beam_bifs/CONTEXT.md` is internally inconsistent on `os:set_signal/2` (owned by that node — worth reconciling).
- **`erl_ddll` → `beam_io::ddll`.** `beam_io::ddll::DynLib` is the safe `dlopen`/`dlsym`/`dlclose` primitive `beam_rt`'s `erl_ddll` floor must build on: open with `DynLibFlags::EMULATOR` (the emulator's `RTLD_NOW | RTLD_LOCAL`), resolve `driver_init`/`_driver_init`, and render `{error, Atom}` from `DllError::reason_atom()`/`ERRCODE_TAB`. **The dynamic `{open_error, Code}` is the floor's to own:** it is an index into the process-local table of raw `dlerror` strings (`find_errcode`, `ERL_DE_DYNAMIC_ERROR_OFFSET = -10`), so `beam_rt` must keep that table (use `DllError::text()`) and build the tuple. `DllErrorKind::BadArg` is a **raise**, not an `{error, Atom}` return. **Dependency direction:** `beam_io` depends on `beam_abi`, so `beam_abi`'s own loaders cannot call this module — a future consolidation could instead move the wrapper **down** into `beam_abi` and re-export it from `beam_io`.
- **File-module surface: the `file:*` API is owed by `beam_rt`'s `prim_file` floor, not by this driver.** The `efile` driver now offers the full driver-level file verb set (`open` with modes, `path`, `close`, `position`, `seek`, `sync`, `truncate`, `binary`/`list`, `eof`, framing), but nothing in the running runtime reaches it — `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`. **Already served there:** `get_cwd/0,1`, `read_file/1`, `delete/1`, `rename/2`, `make_dir/1`, `del_dir/1`, `read_link/1`, `make_link/2`, `make_symlink/2`, `altname/1`. **Still unimplemented** (they fall through to the preloaded `.beam`): `file:open/2`, `read/2`, `write/2`, `position/2`, `sync/1`, `truncate/1`, `copy/2`, `list_dir/1`, `write_file/2`, the `read_file_info/*`+`read_link_info/*` family, `datasync/1` and `advise/4`. Wiring `file:open/2`+`read/2`+`write/2`+`position/2` onto this driver is the natural next step: the driver already returns the raw errno and the raw byte stream, so `prim_file`'s remaining job is the `{error,atom}` rendering, the `FileDataMode` → binary/string rendering (`EfileDriver::data_mode`), and `read_ahead`/`delayed_write` (**not** `open(2)` flags: the C translator drops them — *"Modes like 'raw', 'ram', 'delayed_writes' etc are handled further up the chain"* (`prim_file_nif.c:521-524`); `read_ahead` is a `prim_file` read cache, `delayed_write` a `file` write-batching policy — both must be implemented above the driver).
- **`controlling_process` is port-ownership transfer, not driver state.** `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain of buffered `{tcp,S,Data}`/`{tcp_closed,S}`/`{inet_async,…}` messages; there is no `INET_REQ_*` for it and the `Driver` seam has no owner notion. The runtime must implement it as `PortRegistry`/`beam_process::ProcessTable` ownership transfer plus the message drain.
- **`erlang:port_control/3` → `PortRegistry::port_control`.** The registry seam (with the reserved `"close"`) and a loaded C driver's `control` reply (through `rbuf`/`cres`) are pinned by tests; the BIF/`DrvPort` wiring is owed. The runtime's own `.so` `DriverPort` adapter must also forward `control` (its number-verb form).
- **`open_port/2` stream options → `SpawnDriver::with_stream_options`.** The runtime must pass `stderr_to_stdout`/`eof` as a `StreamOptions` and, for an `eof` port, poll `PortRegistry::take_eof(id)` and emit the bare `{Port, eof}` message (the oracle's shape) exactly once.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** `TcpInetDriver::peer_closed()` latches the close and the driver's `recv`/`send` already answer the C's `[0]closed`/`[0]enotconn`; the runtime needs a `Driver` accessor (e.g. `port_closed()`) to observe it and deliver `{tcp_closed, Port}`.
- **A `>64`-byte `binary`-stream read is a `beam_rt` gap** (a port read larger than the on-heap binary limit must become an off-heap refc binary in the runtime's binary-build path); and **file/`prim_file`/`standard_io`/`io_request` handling is `beam_rt`/`beam_bifs`, not `beam_io`** (this crate provides only the `efile`/`fd` drivers and framing).
- **`erlang:monitor/2` on a port target → `PortRegistry::{port_table,port_table_mut}`.** Those accessors hand out the registry's **own** id table (the `PortTable` `open`/`close` allocate/release through), which is the `&mut PortTable` operand `beam_process::ProcessTable::{monitor_port,monitor_port_term,demonitor_port}` require — `ProcessTable::monitor_term` deliberately answers a typed `unsupported` for a port target, so a port monitor MUST be routed through the port API with this table. **Borrowing rule (in `port_table_mut`'s rustdoc):** the `&mut PortTable` borrows the registry, so a caller holding the registry behind a `RefCell` (`beam_rt`: `Rc<RefCell<PortRegistry>>`) must take the registry's `RefMut` + the `&mut PortTable`, run the single monitor/demonitor call, and drop the whole chain before any nested borrow of the same registry (else `beam_rt`'s `registry_mut` returns the typed `error::unsupported(...)`, or a bare `borrow_mut()` panics); the `&mut ProcessTable` side has the same rule. **Runtime adoption is still owed.**
- **Owed (details in Known Issues):** an `eof` port never delivers `{Port, eof}`, `tcp_inet` peer close never delivers `{tcp_closed, Port}`, `port_control/3` is not routed to the driver `control` callback, and a `>64`-byte `binary`-stream read is `unsupported`. (`beam_rt` supplies its own host over `beam_abi`, not `beam_io::abi`, and already delivers `{Port, {data, …}}`/`{Port, {exit_status, …}}` and `{fd, N}` `port_command`.)

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks`. Keys are port *numbers* (`PortId::number()`). To be woken by a handled OS signal, register `SignalFacility::read_fd()` with the poller.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`); do not close them elsewhere. `EfileDriver` composes an `FdDriver`, so the same ownership rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- `Ready` has **no public constructor**: tests that need a specific readiness forge it through `Event::new(token, key, ready)` with a real `Ready` or through the public `schedule_readiness(key, Readiness)`.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP and restore it. The facility is process-global — serialize tests on a shared `Mutex`. A libtest binary delivers `kill(getpid(), ..)` to the harness's idle thread, so addresses to a *waiting* thread use `pthread_kill`.
