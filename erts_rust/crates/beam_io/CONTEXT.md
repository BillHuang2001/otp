# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Drivers, io-device Requests, Signals, CPU time, ddll
## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** (Part II §A), reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.
Hosts the `mio`-backed **poller/reactor**, the **`Port`** (a process-like endpoint over a `Box<dyn Driver>` + two byte queues), **port-task scheduling** (`erts_port_task_execute`), the **io-device request layer**, the **`Driver` trait + built-ins**, the **driver C-ABI host** (`src/abi/`), and the safe raw-OS floors `beam_rt` (`#![deny(unsafe_code)]`) cannot issue (`signal`, `cpu_time`, `ddll`, `fs_access`, `close_fd`).
A close is **asynchronous**: a port whose output queue is not empty parks in `PortState::Closing` and the teardown finishes on later rounds (`Port::close` → `PortRegistry::finish_closing_ports`).
Four driver→owner side channels sit beside `{Port,{data,…}}`: `{line,N}` frames (`LineNotification`), completions (`PortCompletion`), `{active,…}` deliveries (`ActiveInput`) and the failure latch (`PortFailure`); spent grants come off `ActiveSpend` and a live `{active, Mode}` is read through `PortRegistry::active_mode`.
`beam_rt` is the only consumer: it owns the poll loop, port run queues and scheduler thread, drives one long-lived `Poller` + `PortRegistry`, and renders those drains plus the once-only `take_exit_status`/`take_eof` as the owner's messages; `DynLib` has no consumer outside this crate (*Handoffs*).
## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed — rustdoc carries signatures, port-level mechanism/per-suite detail is `src/CONTEXT.md`.
### `poller.rs`
`Token(usize)` (**token `0` is the waker's**, users start at `1`) · `Interest` (`READABLE`/`WRITABLE`/`BOTH`/`ERROR`, **no empty mask**) · `Ready` — observed readiness, **no public constructor** · `Event` (`token`/`key`/`ready`).
- **`Interest::ERROR` is caller intent, never a registration request**: no backend takes one (`erl_poll.c`'s `ev2pollev` maps only `IN`/`OUT`), while epoll/kqueue and the `poll(2)` fallback report error readiness unconditionally — the delivery half is `Ready::is_error()`.
- `Poller` owns `mio::Poll` **and the single `mio::Waker`**; `poll(timeout)` answers an **owned `Vec<Event>`** (`None` blocks) and is **`EINTR`-tolerant**, an `Interrupted` wait retried with the **deadline preserved**.
- **Edge-triggered (`EPOLLET`)**: a readable descriptor must be drained to `EAGAIN` (each driver's `ready_input`/write-pending job); fd registration is Unix-only (no iocp, as in `beam_abi`).
- Regular files are refused by epoll (`EPERM`), so `register` keeps a `libc::poll(2)` fallback set merged into `poll`'s answer, capped (`FALLBACK_POLL_CAP`, 1 ms) so a non-empty set never blocks.
### `timer.rs` / `queue.rs`
`Timeout` (`Copy`) — one deadline.
`Timer` — deadlines keyed by `u64`, self-contained (nothing in-crate consumes it): `schedule` replaces **any** deadline for a key, `pop_expired` answers due keys in **schedule** order.
`ByteQueue` — `front()` is always contiguous.
### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reds: `CONTEXT_REDS` is `beam_common::CONTEXT_REDS` (4000), re-exported (no local copy); `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = 40`, `PORT_REDS_EXECUTE = 1000`; `PortTaskOutcome::reds_used` models the per-kind cost only.
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout) · `PortTaskQueue` — **one pending task per kind**, by kind **priority only**; `arm_timeout` re-points a pending `TIMEOUT`. Divergences: a not-yet-due `TIMEOUT` stays queued (the C drops it) and one ordered queue replaces the C's three FIFOs.
- `Readiness::read_ready()`/`write_ready()` fold a poll **error** into **every** armed direction (the C's `ERTS_POLL_EV_ERR`); a full close reports both.
- `ReadMessage { header, body: Option<Vec<u8>> }` — one **`driver_output*` call**, never a byte chunk; `body: None` is the C's `buf == NULL`, `Some(vec![])` a present empty body.
- `PortNotification::Data { port, read } | Closed { port }` — **exactly two variants** (exhaustively matchable by `beam_rt`); an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** `{line,N}` channel (a struct, so `PortNotification` stays exhaustive), its `header` prefixed to **every** frame its call completes.
- `ActiveInput { port, event }` / `ActiveInputEvent { Data(ReadMessage), Passive, Error(InetReason) }` — the **separate `{active,…}` channel**, built like `LineNotification`; `Passive` a spent `{active,N}`, `Error` a read failure, neither carrying an atom.
- `ActiveMode { False, True, Once, Multi { remaining: i16 } }` + `ActiveSpend { Once, Multi }` — the **state seam**: `ActiveMode::from_parts(active: i32, active_count: i16)` is the **single** home of the C's `INET_PASSIVE`/`INET_ACTIVE`/`INET_ONCE`/`INET_MULTI` = `0/1/2/3` encoding, `is_active()` is `active > 0` on the **mode** field, `remaining()` the **running** `active_count` (`Some` only for `Multi`); a spend is a grant a delivery exhausted — `Once` flips the mode **silently**, `Multi` reports the zero, `True`/`False` never spent.
- `PortTaskOutcome { ran, reds_used, notifications }` — `notifications` carries `PortNotification`s only.
### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` · `PortControl::CLOSE == "close"` (the one **reserved** control-op name; any other is a driver verb) · `PortCommandOptions { nosuspend, force }`, the `erlang:port_command/3` flag set carried through every retry.
- **`PortState::Closing` is real and observable** via `is_closing()`/`is_closed()`/`output_len()`, with `CLOSING_DRAIN_STALL_LIMIT` (16). `Port::close` is two halves — **begin** (`driver_flush()`, then a synchronous `drain_output_during_close()` under one budget, a pending `INPUT`/`TIMEOUT` task dropped first) and, only when the queue emptied, `finish_close` (`stop`, then `Closed`; a `stop` failure still leaves it `Closed`).
- A queue that is **not** empty **parks** the port in `Closing`, `OUTPUT` task pending, poller registrations armed; `stop` has not run and the port stays in the registry. `note_closing_drain()` gives up after `CLOSING_DRAIN_STALL_LIMIT` consecutive no-progress rounds against `closing_watermark` (a **refused write counts as no progress**; a slow drain is never cut off); a second `close` on a `Closing`/`Closed` port is an idempotent `Ok(())`.
- `PortCommandOutcome { Done, Busy }` + `Port::command(&mut self, data, options)` — **the one place the decision table lives**: non-`Open` (a parked `Closing` included) ⇒ `BadArg`; `[force]` **without** `DriverFlags::SOFT_BUSY` ⇒ the typed `notsup` raise, from the driver's **flag word** and **before** any output; `[force]` **with** it ⇒ `Done`; idle ⇒ `Done`, bytes queued plus one `OUTPUT` task; busy with a plain or `[nosuspend]` command ⇒ `Busy`, nothing queued, no task.
- Driver-state forwards: `is_busy()` · `port_closed()` (**latched, sticky**) · `active_mode()` (with the **running** counter) · `awaits_callers_async_op()` · `take_active_spends()` (**oldest first**, consumed on take, **unstamped**; the registry's form is stamped); `driver_as::<T>()`/`driver()` are the read-only views and `PortControlReply { bytes, shape }` is the whole `erlang:port_control/3` reply (`ControlReplyShape` stated once in `driver.rs`).
- **Every driver interaction installs all four sinks** (`with_reads`/`with_completions`/`with_active`/`with_failure`) and refreshes the port timer from `Driver::next_timeout`; a write (`output`/`ready_output`) is **verified** — the queue shrinks by exactly the reported count, else the typed `error::unsupported(...)` — and a non-empty queue left behind schedules an `OUTPUT` task.
- Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (`Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof` point; a `close` never flushes); a round harvests raw-mode input as ≤1 `PortNotification::Data`.
### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number; `port_table`/`port_table_mut` expose that **same** id table.
- `close` runs `Port::close` and removes the port from the live map **only when it really finished** (`is_closed()`); a **parked** port stays live with its number, descriptors and poller registrations, and a port's **number** retires only when its `Closed` notification is reported, so a deferred `Closed` can never name a reused id; `is_closing(id)` says whether `close` parked it.
- A private `finish_closing_ports` runs from **both** round drivers (`execute_port_tasks`, `handle_events`) **after** `reap_failures` and **before** the closed drain, so a port whose queue empties this round is reported `Closed` in that same round; `reap_failures` uses the forced `close_now` — a failed driver's queue is **dropped**, not drained.
- Frozen seams (all `BadArg` for an unknown id): `handle_events` (schedules **and** runs one round) and `execute_port_tasks` (port-number order under a reduction budget, async completions driven *before* input), or `schedule_events`/`schedule_readiness` gated by `PortArms`; `port_command_with`/`port_command`; `is_busy`/`port_closed`/`active_mode`/`is_closing`/`awaits_callers_async_op`; `port_control` (reserved `"close"`, any other `op` verbatim to `control(op, arg)`); `take_exit_status`/`take_eof`; the timer seams; `notify_port_exit` (`Driver::port_exit` **at most once**); `drive_async`; `set_line_mode`/`flush_linebuf`; `take_failures`.
- The four owner drains share one rule — drain after **every** round, **every** explicit driver interaction and **every** `close`: `take_line_notifications` (**port-number order**), `take_completions`, `take_active_inputs`, `take_active_spends`, each followed by the `closed_*` queue the removal fills, the spend queue **after** the driver's `stop`; a completion, delivery or spend staged before or at a `close` is reported **exactly once**.
- `port_control_reply(..)` is `port_control`'s reply **with** its `ControlReplyShape` (the reserved `"close"` arm answering an empty `Buffer`); `control_reply_shape(id)` reports the last reply's shape alone.
### `port_failure.rs` / `completion.rs` — the two side channels beside `PortNotification`
`PortNotification` keeps two variants and `PortCompletion` stays an owner message, so a driver that *closes its own port* and one that reports an *asynchronous outcome* each get a channel of their own.
- **Failure** (`port_failure.rs`, the C's `driver_failure*`/`driver_exit`): `FailureReason { Eof, Normal, Atom(String), Posix(i32), Code(i32) }` with `atom_name()`/`code()`/`is_eof()` (the flag that makes a `{line,N}` port flush its partial line first) · `DriverFailure { reason, signals_owner }`, `signals_owner` `false` only for `driver_exit`, which unlinks the owner **before** closing. `DriverContext::signal_failure` latches **exactly one** (the three `deliver_*` seams refuse afterwards), and `reap_failures` tears the port down through `close_now` after the callback returned — `stop` runs, the port leaves the live map, staged input is reported ahead of the close, the number retires only with the deferred `Closed`.
- **Completion** (`completion.rs`): `PortCompletion { port, event }` — the id stamped by `DriverContext::deliver_completion`, never by the driver · `CompletionEvent { InetReply { caller_ref, reply }, InetAsync { id: u16, result } }` · `InetReply { Ok, Error(InetReason) }`, `InetReason { Closed, Timeout, Errno(i32) }` (the lowercase POSIX name, with the C's `errno_<N>` fallback) · `InetAsyncResult { Ok, Data(ReadMessage), Accepted { fd }, Port(PortId), Error(InetReason) }`, `Data` keeping the header/body split and `Accepted` handing the descriptor over **owned**. `caller_ref` is the `prim_inet` caller tag carried **verbatim** (a 131-led `term_to_binary(Mref,[local])` image).
### `driver.rs`
- `DriverFlags(u32)` (`SOFT_BUSY`) · `PortExitReason { Closed, OwnerExited, Normal }`; `SOFT_BUSY` **membership**: `tcp_inet` advertises it, `udp_inet` and `ram_file_drv` do not — so `[force]` is the oracle's `notsup` on those two and `true` on `tcp_inet`.
- **`ControlReplyShape { Null, Buffer }` is the second fact a `control` reply carries** (stated once, here): `Null` is the C's `*rbuf == NULL` (`*rbufp` tested **first**, `io.c:4134`), answered as the empty **list** for **every** flag word; `Buffer` is a real reply buffer, so zero bytes under `PORT_CONTROL_FLAG_BINARY` is `<<>>` and zero bytes without it is `[]`; reported by the **defaulted** `Driver::control_reply_shape()` (`Buffer`, honest for every built-in), overridden only by `abi::DriverPort`.
- `DriverContext<'a>` — the driver's view of its port and **the only way it touches the poller or the queues** (keys are the port number); its four delivery seams are each the typed `unsupported` without a sink and each refusing once a failure latched in the callback: `deliver_read(header, body: Option<&[u8]>)` (the `driver_output2`/`output_binary`/`outputv` seam), `deliver_completion`, `deliver_active_input`, `signal_failure` (a request, never a teardown).
- `pub trait Driver: core::any::Any` — **frozen**, with the one downcast path `impl dyn Driver { pub fn downcast_ref<T: Driver + 'static>(&self) }` (trait upcasting: no `unsafe`, no `as_any`, every driver `'static`); required `name()` (+ `flags()`), `start`, `output`, `ready_input`, `stop`.
- Defaulted members that carry a contract: `has_control()` (**`false` iff the C counterpart has `control == NULL`**, e.g. `ram_file_drv` — then `port_control/3` is `badarg`) · `is_busy()` · `port_closed()` (**latched, sticky**) · `active_mode()` · `take_active_spends()` · `has_pending_async()` (the **drive** gate) · `take_exit_status()`/`take_eof()` (`SpawnDriver` only).
- `flush(&mut self, ctx: &mut DriverContext<'_>) -> Result<()>` — additive **defaulted** no-op, the C's `drv->flush`, called **once** from `Port::close` after `Closing` and **before** the drain. **Three overriders**: `TcpInetDriver` — the only discarding one, `discard_output = !(token.is_some() && interest.is_writable()) || options.linger_zero` then `ctx.output().clear()` · `SpawnDriver` — latches `terminating` only · `abi::DriverPort` — forwards the loaded entry's slot; `FdDriver`/`RamFileDriver`/`UdpInetDriver` inherit the no-op (a NULL C slot).
- `awaits_callers_async_op(&self) -> bool` — additive **defaulted** (default `self.has_pending_async()`), the wait predicate split from the drive predicate: `TcpInetDriver`/`UdpInetDriver` answer their queued-op probe (**accept-inclusive**), `abi::DriverPort` `false`.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>` · `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers `"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`.
- **The statically-linked (emulator `driver_tab`) set is the narrower contract**: `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` + `is_static_spawn_driver`, `with_static_spawn_drivers()` and `create_static_spawn(name)`, refusing any other name with `BeamError::BadArg` **even on a `with_builtins()` registry that registers it**.
### `drivers/` — the built-in drivers
Roster, all `Driver`/`DriverContext`-only, each owning its descriptors: `fd` (`FdDriver`, byte stream) · `efile` (`EfileDriver`, composing an `FdDriver`, `make_efile()`) · `spawn` (`SpawnDriver`, **the only child-spawner**, from a `SpawnSpec`, spawning in the constructor) · `ram_file_drv` (`RamFileDriver`/`make_ram_file`, command-driven `Vec<u8>` "file") · `inet/` (`tcp_inet` + `udp_inet`). Verbs, `{line,N}`/phase framing, the option vocabulary and every per-driver suite are `src/drivers/CONTEXT.md`'s (+ `src/drivers/inet/CONTEXT.md`).
- `tcp_inet` frames **once per command**, at queue time and after the connection guard: the `{packet,1|2|4}` header announces the **payload** length after the `prim_inet` caller-tag strip, and `stat.send_oct` counts header + payload; `udp_inet` frames nothing, and the queue is one byte stream with **no per-command boundary** (*Known Issues*).
- **The read path: a complete buffered unit wins over a pending peer close**, and only a read the C *would* have made may apply one (*The inet read path past a peer close*).
- **The `erlang:port_control/3` opcode bridge** (`inet/opcode.rs`): an integer `Op` reaches the driver as its **decimal string**, accumulated mod 2³² and `wrapping_sub(CONTROL_MAGIC_NUMBER = 0x03f1_a300)`-ed, then dispatched by the C's three switches onto the same verb bodies the named form uses; a number no entry owns — another driver's switch, or any op below the magic — answers `[0]exbadport`; an unserved opcode is the typed `not_served()` raise and the **operand** decode is the caller's (*Known Issues*).
- **A.4 residuals** (a typed refusal or a refusal-only arm, never a wrong result): the improper `[hdr|<<body>>]` DATA reply renders through `ReadMessage`; `INET_REQ_FDOPEN`'s prebound descriptor is never closed (borrowed, port-lifetime); `ignorefd`/`tcp_sendfile` reproduce their refusals only.
### The inet read path past a peer close (the `ReadReport` selection rule)
The C selects a socket's read side in exactly **two** states — a granted `{active,…}` (`sock_select(desc,(FD_READ|FD_CLOSE),(desc->active>0))`, `inet_drv.c:7966`) and a waiting `TCP_REQ_RECV` (`:12317`) — so `ReadReport::Answered` (a queued `TCP_REQ_RECV`, the `recv` verb, an `{active,…}` delivery) **applies** the close it finds.
This floor's poller also reads a **passive** socket with no receive queued — a delivery shortcut for `{Port,{data,…}}`, not a discovery — so that read is `ReadReport::Unselected`: it delivers its bytes, **records** the close in `TcpInetDriver::pending_close` and applies **nothing** (no `delayed_close_*`, no teardown), leaving the close owed.
Hence `{Port,{data,…}}` precedes `{tcp_closed,…}`, the `tcp_recv_closed`/`tcp_recv_error` ladder is unchanged in the selected case, `pending_close` is sticky and cleared only by the latch, and `latch_peer_close` is the **single** latch site (*`src/drivers/inet/CONTEXT.md`*, `src/CONTEXT.md`).
### The inet write path after `gen_tcp:shutdown(S, write)`
`shutdown/2` only **records the intent**: the socket is not closed (state stays `{ok,[connected,open]}`, `GETFD` still answers) and zero-length sends answer `ok` **for ever**, the one-shot ladders being armed by the **first failing write** — which answers `{error,closed}`, every later one `{error,enotconn}`.
The answer matrix, the command-accounting invariant (`InetStat::output` counts a **command**, not a write, so a zero-length command advances `send_cnt` and adds nothing; `send_pend` is the port's own output-queue depth) and their pins (`src/drivers/inet/write_shutdown_matrix_tests.rs`, `stat_send_tests.rs`'s `RAW_ROWS`, the differential corpus's `inet_write` group) are `src/drivers/CONTEXT.md` › *The inet write path — the answer matrix and the accounting invariant*.
### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`, the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code. Modules: `host.rs` (`PortHost`/`AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, preferring the entry's **`outputv`** on both write paths, forwarding its `flush` slot, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` **implements** `beam_abi::DriverHost::set_busy_port` (records the per-port `DriverState::busy`, answers the C's `0`, read back via `AbiHost::is_busy`/`DriverPort::is_busy`); `DriverPort::control` reports a `*rbuf == NULL` reply as `ControlReplyShape::Null` instead of `badarg` — the one place that can (*`src/abi/CONTEXT.md`*).
### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
`Encoding { Latin1, Unicode }` (any other name — a tuple encoding, … — is refused, never guessed) · `ByteSource` (`read_chunk(size) -> Result<Option<Vec<u8>>>`, `None` = eof) · `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`, whose request is `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>`; the `Continuation` seam (`Continuation`/`ContData`/`Applied`/`Leftover`) is the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])`, with `NoEngineContinuation` the not-installed default, every `apply` a typed `unsupported` naming the missing `erl_scan:tokens/4` — never a fabricated reply. Device loop, transcode clauses, `invalid_unicode` stop: **`src/io_device/CONTEXT.md`**.
### The five raw-OS floors and the errno table
`signal.rs` — `Signal` (the twelve `os:set_signal/2` accepts; `sigttin`/`sigttou` are **not**), `Disposition { Default, Handle, Ignore }`, `SignalFacility::set` (`sigaction(2)`, **empty `sa_mask`**, **`SA_RESTART`**)/`read_fd()`/`drain()` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order); the handler is **async-signal-safe** (one atomic mask OR before the pipe drain, then one `libc::write`), the facility is process-global (`Drop` restores every prior disposition) and unix-only, and `SigStop` is kernel-only (typed `BeamError::Io`).
`cpu_time.rs` — `CpuTimes { user_ms, system_ms }` in whole **milliseconds** (µs ÷ 1000); `process_cpu_times()` (`getrusage(RUSAGE_SELF)`) **is** `erlang:statistics(runtime)`'s measurement, which does not use `thread_cpu_times()`; `RuntimeClock` is the `(Total, SinceLastCall)` counter, so the **first** call returns two equal elements and system time is unused, and a failed `getrusage` is the typed `BeamError::Io` leaving the anchor **unchanged**.
`ddll.rs` — `DynLib` (an owned `dlopen(3)` handle, no `into_raw`/`from_raw`, not `Send`/`Sync`) + `DynLibFlags` (`EMULATOR` = `RTLD_NOW | RTLD_LOCAL`, the default `beam_abi`'s loaders use; `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`) and `DllError { kind, text }`/`DllErrorKind`, whose `errcode` is **derived** from the single `ERRCODE_TAB`, with **no** `.so` suffix appended and classification **text-based only**.
`fs_access.rs` — `try_access(&Path, AccessMode)` is the crate's **one `access(2)` call site**, errno-preserving; the bool `access(..)` makes a **refusal** `Ok(false)`, `path_access(&Path)` is the `#file_info{}` `access` slot (two **independent** probes) and `process_credentials()` the **effective** ids.
`close_fd.rs` — `close_fd(RawFd)` (an `EINTR`-retried `close(2)` reporting `EBADF`) and `OwnedFd` (closed exactly once; `into_raw` hands ownership to a driver): the crate's **safe, public** close primitive for a descriptor the *runtime* owns or declines, not the crate's only `close(2)`.
`error.rs` — `ERRNO_NAMES` (**61 rows**) is the one errno→name table (`errno_atom` its `Option` form, `errno_name` the `[0] ++ Name` form with the C's `errno_<N>` fallback), `EOPNOTSUPP` renders **`enotsup`**, and `drivers/inet/wire.rs::errno_name` forwards here so `InetReason`/`FailureReason` read one table.
## Constraints
- Errors: **`beam_common::{Result, BeamError}` only** — I/O/syscall ⇒ `BeamError::Io`, argument faults ⇒ `BeamError::BadArg`, id/registration exhaustion ⇒ `BeamError::SystemLimit`; never panic on runtime data, never `unwrap()`/`todo!`/`unreachable!`.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, `fork`/`execve`/`waitpid`/`dup2`, `setsockopt`/`getsockopt`, `getrusage`/`clock_gettime`, `pipe2`/`sigaction`, `dlopen`/`dlsym`/`dlclose`, `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction and the `abi` host's raw `ErlDrv*`, each block with a preceding `// SAFETY:` rationale and `unsafe_op_in_unsafe_fn` clean.
- **Edge-triggered byte path**: every `ready_input`/write-pending drains to `EAGAIN`; a short write leaves the exact remainder queued and arms write readiness; a short read never drops or duplicates bytes.
- **Port ids come from `beam_process::PortTable`** — no second allocator; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: drive them from **one OS thread**, `PortRegistry` carrying a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; `DynLib` likewise, while `Poller`/`Waker` are exempt (the waker must cross threads) and `SignalFacility` is process-global.
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **A `Closing` port must always finish**: whatever a drain does — a short write, a refused write, a driver that never consumes — the close completes, the park bounded by `CLOSING_DRAIN_STALL_LIMIT` and the teardown (`flush` → drain → `stop` → `Closed` → number retirement) run exactly once per port.
- **The `Driver` trait, `DriverContext`'s public methods and the `Port`/`PortRegistry` signatures are the frozen driver seam**, extended only by **additive, defaulted** members; files target ~1000 lines; deps `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only.
## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` **GREEN**, and `... build --workspace --all-targets` **GREEN, warning-free**; the wrapper is mandatory because the sandbox `$HOME` (hence cargo's default `CARGO_HOME`) is read-only.
- **No counts here**: lib suites sit beside their module (`src/CONTEXT.md`, `src/drivers/CONTEXT.md`, `src/abi/CONTEXT.md`), integration suites and their `cc` fixtures in `tests/CONTEXT.md`.
- A suite needing `cc`/`erl_driver.h`/`erl` **skips loudly** (`SKIP:` banner + early return) and never fails; fixtures are built by the test binary itself; every oracle comparison is **byte-exact**.
- A wait is a **condition under a hang guard** — never a fixed sleep, never `waitpid(2)` from a test. Pinned: the parked close + `flush` seam, the busy-port decision table, `{packet,N}` framing on **both** write routes, the `{active,…}` mode/spend seam, the `inet` option/control surface against the live oracle.
## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` behind a **mio-independent** API (`RawFd` + `Interest`/`Token`/`Ready`), so another backend could be added later (io_uring/`/dev/poll` is **not implemented today**).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **The parked close is the C's Limbo state, with a valve of our own.** A close with a non-empty queue goes through `flush_port` → `ERTS_PORT_SFLG_CLOSING` and finishes at the driver-callback epilogue; the C has **no bound** there, so `CLOSING_DRAIN_STALL_LIMIT` (16 consecutive no-progress rounds) is a **documented divergence** — without it a stuck driver would hold the port number, descriptors and poller registrations indefinitely; a slow drain is never cut off.
- **Task execution here, the scheduler thread above**: the poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver, and a poll **error** reaches both armed directions.
- **The spawn driver is constructed, not registered, and reaps eagerly**: a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (a failed spawn registers nothing); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it.
- **The TCP/UDP drivers are a floor, not a full `inet`** — served verbs, framing types and the `{active,…}` matrix are oracle-cross-checked (`src/drivers/inet/CONTEXT.md`).
## Known Issues
- **`FdDriver` is deliberately minimal** (byte-stream only; no output line framing, no packet framing) and **`SpawnDriver` is the OS-child floor**, not the whole `spawn` driver — synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` from its bytes, latched EOF and once-only exit status is the runtime's job (*`src/drivers/CONTEXT.md`*).
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes: packing `erlang:port_control/3`'s `Data` term into the C's request payload is the runtime's job, an integer `Op` being forwarded as its **decimal string**; the `INET_REQ_*` surface, its guard order and its refusal-only arms are `src/drivers/inet/CONTEXT.md`'s.
- **The inet drivers' `port_command/2` path adopts the failure seam; the `init_caller` rule is size-only** — the tag's bytes are **never inspected**, so a *plain* payload reads as a huge length and is the C's `FALSE`; the four oracle-measured rows (malformed, socket-less/unconnected, empty queue, empty/non-ETF tag) are `src/drivers/CONTEXT.md`.
- **A completion is addressed to the port's owner, not the C's `driver_caller`** — rendering and delivering is the runtime's (*Handoffs*).
- **The busy-port decision table is the whole of the flow control this crate owns** (`Port::command`, exposed by `PortRegistry::port_command_with`/`is_busy`); the **caller-blocking** half needs a process this crate has none of, so it lives in `beam_rt` (`crates/beam_rt/src/port/busy_wait.rs::issue`).
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` callbacks are `void`**; counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`), so it must not be "fixed" into a remainder.
- **The output queue is one byte stream with no per-command boundary.** The `{packet,1|2|4}` header and the `send_oct` charge are decided **once per command**, at queue time and after the connection guard, so a **second** command behind a stalled partial write lands behind the first command's remainder, unframed and uncounted.
- **Driver-readiness residuals.** `DriverState::fd_armed` hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a multi-fd port would starve the others (harmless today — one fd each); a `{fd,N}` spawn port keeps an `Interest::BOTH` registration for its life, scheduling a spurious `OUTPUT` task on every write-readiness event.
## Handoffs (beam_rt — out of this node)
**Adopted upstream:** `{line,N}` framing, the completion/failure/`{active,…}` channels (`crates/beam_rt/src/port/{completion,failure,active_input}.rs`), the peer-close latch (`crates/beam_rt/src/port/peer_closed.rs`), the control-reply **shape** (`crates/beam_rt/src/native/port.rs::port_control`), the raw-OS facilities, `create_static_spawn`, the busy-port wait and `erlang:port_control/3`.
**A closed port is not gone at `close`'s return:** a parked close leaves it live (`contains`, `is_closing`, poller registrations) and `erlang:port_command` on it is `badarg`; the `Closed` arrives from a **later** round, so `beam_rt` keeps its port-table entry and keeps driving rounds until that report names the port.
**The two async predicates: `has_pending_async` drives, `awaits_callers_async_op` waits** — `crates/beam_rt/src/context/pump.rs::wait_for_port_event` reads the drive predicate and counts delivered port events per round for progress.
**The busy-port wait is `crates/beam_rt/src/port/busy_wait.rs::issue`; residual:** a 5 s `BUSY_PORT_DEADLINE` where the C is unbounded, and the `send`-to-port route (`erlang:send/2,3`, `Instr::Send`) cannot consume a suspend latch — like `RuntimePorts::write_command` it stays the typed `NO_PUMP_REASON` gap.
**The control-reply shape belongs to the runtime** (`PortControlReply { bytes, shape }` is the whole reply; the flag word is not part of it), and `control_reply_shape` is `BadArg` for a port a driver reaped from inside its own `control` callback.
**The failure channel: this crate latches and tears down, the runtime renders** — `take_failures` hands up the term-free `PortFailure { reason, signals_owner }` in reap order; `{'EXIT',Port,Reason}` and every monitor's `{'DOWN',…}`, gated on `signals_owner`, are `crates/beam_rt/src/port/failure.rs`'s.
**The `{active,…}` channel: this crate produces the delivery, the runtime renders the message** (`crates/beam_rt/src/port/active_input.rs`): `{tcp, S, Data}` under the port's `[list]`/`[binary]` shape, `{udp, S, IP, Port, Data}`, `{tcp_passive,S}`, `{udp_passive,S}`, `{tcp_error,S,Reason}`/`{udp_error,S,Reason}` (the atom from the driver name), the `{mode, list|binary}` decision and the delivered-data/header shapes `PortNotification` leaves to `desc->mode`. **Never add a `PortNotification` variant** and never route these through `CompletionEvent`.
**The completion channel: this crate stages, the runtime addresses and renders** (`crates/beam_rt/src/port/completion.rs`: `{inet_reply, Port, Reply[, DecodedTag]}`, its 131-led `caller_ref` decoded by `beam_codec`, and `{inet_async, Port, Id, Result}`); an `InetAsyncResult::Accepted { fd }` is adopted into a **second** port (`TcpInetDriver::from_accepted` or `INET_REQ_FDOPEN`) **or** closed — `beam_io` never closes it; a **built-in** driver port has no term path (`PortMeta::driver_terms` `None` for `PortName::SpawnDriverBuiltin`); residual `driver_caller`: the C addresses `desc->caller`, this floor stages for the **owner**.
**`tcp_inet` peer close → `{tcp_closed, Port}`: this crate observes, the runtime reports** — `TcpInetDriver` latches it (`peer_closed()`, mirrored by `Driver::port_closed`, sticky); `crates/beam_rt/src/port/peer_closed.rs` gates the message on the live `{active,…}` mode and retires the port through the `driver_exit` route.
**Two owner-facing messages are still missing:** a `send_timeout` expiry's `{inet_reply, Port, {error,timeout}}` (stored, never armed) and `SUBSCRIBE`(24)'s later `{empty_out_q, Port}` — *missing messages*, so a caller waiting on either hangs; the options (`{deliver, port|term}`, `send_timeout`, `send_timeout_close`, codes 25/30/35) are stored and reported byte-exactly, and `Getservby*`/`SUBSCRIBE`'s reply are **served**.
**`DynLib` has no consumer outside this crate, and the `erl_ddll` taxonomy is duplicated OUTSIDE it (report — not fixable here):** `beam_rt`'s `erl_ddll` floor is built on `beam_abi::driver::loader`, so consolidating `DynLib` would move it **down** into `beam_abi`, while the taxonomy is fully copied in `crates/beam_bifs/src/runtime/ddll.rs` and partly in `crates/beam_abi/src/driver/loader.rs` — a single owner is an **owner decision + a `CHANGE.md` entry**.
**`file:*`/`prim_file` belongs to `beam_rt`** (`beam_rt/src/native/prim.rs`, a Rust-`std::fs` floor) and **no `beam_io` code is on that path** — the `file_io` workload's whole-file and **raw-handle** (`[raw]`) shapes touch **no port, no driver and no poller round**; the one port case is `file:open(Name,[ram,…])` — `open_port({spawn,"ram_file_drv"},Opts)`, whose first-token lookup is `beam_rt`'s; `HANDOFF_FILE_IO_PERF.md` carries the attribution and the exact patch.
**Every other handoff is a child node's:** the driver/async-op/accept-family seams (incl. the datagram `{header,N}` impossibility and `INET_REQ_FDOPEN`'s documented non-mirror) are `src/drivers/inet/CONTEXT.md` › *Handoffs*; the io-device request's `{stop,…}` boxing and `Leftover` are `src/io_device/CONTEXT.md` › *Deviations from the oracle*.

## Notes for Agents
- Read `../CONTEXT.md`, `../beam_process/CONTEXT.md` and `../../CONTEXT.md` §1 A.4/§3 first; build/test with `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (the wrapper is mandatory — the sandbox `$HOME` is read-only); never `cd`, never touch `../../tools/`.
- A new `access(2)` use belongs in `src/fs_access.rs` (never a second `unsafe` wrapper), and a new descriptor close goes through `close_fd`/`OwnedFd` unless the driver owns that descriptor.
- A driver reaches the queues and the poller only through `DriverContext`; a `Port` method calling it must **destructure `self`** so driver and context borrow disjoint fields, never adding a combined raw-pointer accessor.
- `Poller::poll` returns owned, `EINTR`-tolerant events: call `registry.handle_events(&mut poller, &events)` after it, or drive the queue with `schedule_events` + `execute_port_tasks` (poller keys are port *numbers*); a handled OS signal wakes it through `SignalFacility::read_fd()`.
- A new owner-facing message needs a **new** channel (a struct + a `DriverContext::deliver_*` sink + a `PortRegistry::take_*` drain), never a third `PortNotification` variant and never a `CompletionEvent` arm.
- Output queued before a close is **written, not dropped**: a discarding driver says so in `flush` (consuming those bytes off `ctx.output()`) and leaves the queue alone when the port can still write them (`stop` runs only after the drain).
- `FdDriver` closes the fds it is given (on `stop` and `Drop`) and `EfileDriver` composes it, so the same rule applies through it; `mio::unix::SourceFd` borrows `&mut RawFd` only for the syscall, so build it from a local `let mut fd = fd;`.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self: install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP, restore it, serialize on a shared `Mutex` (the facility is process-global) and raise thread-directed with `pthread_kill(pthread_self(), …)`.
## TCP accept state machine
The state machine is the child node's: the **sticky** multi-accept `INET_F_MULTI_CLIENT` bit behind `GETSTATUS`, the per-port sorted accept-timer list (the C's `desc->mtd`), the `[0]einval` ladder for every non-listening state and the arm/re-arm/disarm readiness cycle live in `src/drivers/inet/CONTEXT.md`, pinned by `src/drivers/inet/accept_tests.rs` + `tests/inet_accept.rs`.
The accepted descriptor is handed over **owned** (`InetAsyncResult::Accepted { fd }`), and the listener's option set comes across through `TcpInetDriver::from_accepted(fd, listener)` — this crate's `tcp_inet_copy`.
The seam: `PortRegistry::driver_as::<TcpInetDriver>(listener)` reaches the listener's concrete driver and the accepted driver is opened as a second port, so the runtime must use **that** constructor rather than `from_socket` — otherwise it closes the fd.
