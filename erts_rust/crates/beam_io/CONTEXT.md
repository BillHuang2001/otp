# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Built-in Drivers, io-device requests, Signals, CPU time, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.

Nine subsystems: the `mio`-backed **poller/reactor**; the **`Port`** (a process-like I/O endpoint over a `Box<dyn Driver>` + two byte queues); **port-task scheduling** (`erts_port_task_execute`); the **io-device request layer** (`src/io_device/` — the `{get_until,…}` incremental reader, its `Mod:Func` application a runtime seam); the **`Driver` trait + built-in drivers** (`fd`, `efile`, OS-child `spawn`, `tcp_inet`, `udp_inet`, `ram_file_drv`, `{line,N}` buffering, the text⇄binary phase change); the **driver C-ABI host layer** (`src/abi/`); the **OS-signal facility** behind `os:set_signal/2` (the signal `unsafe` work `beam_rt`, `#![deny(unsafe_code)]`, cannot do itself); the **CPU-time facility** (`src/cpu_time.rs`) behind `erlang:statistics(runtime)`; and the **dynamic-library primitive** (`src/ddll.rs`) behind `beam_rt`'s `erl_ddll` floor.
The API Surface below carries the frozen detail; the Routing Table names one file per subsystem.

`beam_rt` is the only consumer: it owns the poll loop, the port run queues and the scheduler thread, drives one long-lived `Poller` + `PortRegistry` plus a `SpawnDriver` built from its decoded `open_port/2` terms, and turns `PortNotification`s and the once-only `take_exit_status`/`take_eof` into `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` for the owning process (waking a blocked receiver through `beam_process`); `beam_process` observes ports by id (the peer of pids in `ptab`).
Only `SpawnDriver` is on that path — `tcp_inet`/`udp_inet`/`ram_file_drv`, signal, CPU-time, ddll and the io-device request layer are **not** adopted yet (*Handoffs*).

Legacy C ground truth (read-only): `erl_poll.c` + `erl_check_io.c` (poll loop, one-shot re-armed readiness, self-pipe wakeup), `io.c` (the `ioq` queue + the driver callback call sites), `erl_port_task.{c,h}`, `inet_drv.c` + `packet_parser.{c,h}`, `erl_child_setup.c`, `erl_bif_ddll.c` + `erl_unix_sys_ddll.c`, `sys.c`, `erl_time_sup.c` + `erl_bif_info.c` — full paths in the Routing Table and the child docs.

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed, rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque handle; **token `0` is the waker's**, user tokens start at `1` · `Interest` (`READABLE`/`WRITABLE`/`BOTH`) · `Event` · `Ready` — observed readiness, **no public constructor** (`Ready::default()`/`From<Ready>`; tests forge readiness through `Event::new`).
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`**; `register(RawFd, Interest, key)`, `poll(timeout) -> owned Vec<Event>` (`None` blocks), `waker()`. `Waker` is the `Arc`-backed cloneable thread-safe wakeup handle (`key() == WAKER_KEY`, `u64::MAX`).
- **`poll` is `EINTR`-tolerant**: an `Interrupted` wait is **retried** (never `BeamError::Io`) with the **deadline preserved**. **Regular-file fallback (internal):** epoll refuses regular files (`EPOLL_CTL_ADD`⇒`EPERM`), so `register` keeps a `libc::poll(2)`-backed set merged into the same `Event`/`Ready` shape; `poll` never blocks past `FALLBACK_POLL_CAP` (1 ms) while it is non-empty.
### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — one deadline · `Timer` — deadlines keyed by `u64`; self-contained helpers (nothing in-crate consumes them); `Timer::schedule` replaces **any** deadline for a key, `Timer::pop_expired` returns due keys in **schedule** order.
- `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS` is the canonical `beam_common::CONTEXT_REDS` (4000) re-exported here (no local copy); `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS/100 (40)`; `PORT_REDS_EXECUTE = CONTEXT_REDS/4 (1000)`.
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`) · `PortTask` · `PortTaskQueue` — one pending task per kind, ordered by kind **priority only**; a not-yet-due `TIMEOUT` stays queued (divergence: the C dequeues, charges 0 reds and drops it); `arm_timeout` re-points a pending `TIMEOUT` (unlike `enqueue_timeout`).
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()`, `write_ready()` (a poll error re-triggers **every** armed direction, `ERTS_POLL_EV_ERR` = `EPOLLERR|EPOLLHUP`), `is_idle()`, `From<Ready>`.
- `PortTaskOutcome { pub ran, pub reds_used, pub notifications }` — `reds_used` models the per-kind cost only; `notifications` carries `PortNotification`s only, line frames ride `PortRegistry::take_line_notifications`.
- `ReadMessage { header: Vec<u8>, body: Option<Vec<u8>> }` — one completed read with the C `driver_output2` header/body split preserved (`header` = `hbuf`/`hlen`, `body` = `buf`/`len`): one `ReadMessage` is one **`driver_output*` call**, never one byte chunk. `body: None` is the C's `buf == NULL` (no binary tail at all) and `Some(vec![])` a present empty body (`<<>>` tail) — different messages. Helpers `body_only`/`len` (`hlen+len`, the `bytes_in` accounting)/`is_empty`/`has_body`/`flattened` (the `[list]`-mode byte sequence); the oracle-pinned shape table (`io.c:3363-3442`) is in its rustdoc.
- `PortNotification::Data { port, read: ReadMessage } | Closed { port }` — the seam the runtime turns into `{Port,{data,Data}}`/port-exit messages. **Exactly these two variants** (exhaustively matchable by `beam_rt`: two arms, no wildcard). A round reports **one `Data` per `driver_output*` call**, in arrival order — several per port per round, two calls never merged — and an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** channel a `{line, N}` port reports through (the `{eol|noeol, Data}` wrapper of `ERTS_PORT_SFLG_LINEBUF_IO`, `io.c:3430-3435`); a distinct struct, *not* a third `PortNotification` variant precisely so that enum stays exhaustive for its outside consumers. `header` is the producing read's `ReadMessage::header`, which the C prepends as cons cells to **every** frame that call completes (`driver_output2("HDR",3,"a\nb\n",4)` ⇒ two frames, each carrying `"HDR"`; a line spanning two calls gets the header of the call that completed it), and is empty for a plain read and for the EOF flush. Unlike `Data`, an empty `eol` frame is a real frame (a blank line is `{data,{eol,[]}}`).

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` (the budget `handle_events` runs) · `PortControl::CLOSE == "close"` — the one **reserved** control-op name (any other name is a driver verb) · `PortCommandOptions { nosuspend, force }` — carried but **inert at this layer**: no busy flag exists here, so a command is never suspended or refused (the C-ABI host's `busy` and the BIF caller-blocking half are `src/abi/` + `beam_rt`).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the scheduling surface (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`), the exit/async/stream surface (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`) and the read-frame state; re-exports `PortRegistry`.
- **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`) refreshes the port timer from `Driver::next_timeout` (`Some(d)` arms/**re-points** the single `TIMEOUT` task, `None` clears it). A driver write is **verified** — the output queue must shrink by exactly the reported count (else the typed `error::unsupported`) — and an `OUTPUT` task is scheduled whenever the queue is left non-empty.
- Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (the `ERTS_PORT_SFLG_LINEBUF_IO` bit + `linebuf->max_len`; `Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof`=`driver_eof` point; a `close` never flushes). Raw mode harvests **one `PortNotification::Data` per `driver_output*` call** (bytes banked on `ctx.input()` close into one body-only `ReadMessage`); line mode stages `LineNotification` frames on an internal queue (`take_line_frames()`, `pub(crate)`), each stamped with the header of the read that produced it, so a line-mode port reports **nothing** through `PortNotification`.
### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>`; `new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`, plus `port_table`/`port_table_mut` over that **same** id table (`port_table_mut`'s rustdoc carries the borrowing rule). `close` runs the driver's `stop`, drops the port and **retires the number only when its `Closed` is reported**, so a deferred `Closed` never names a reused id.
- Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET` ⇒ `PortTaskOutcome`); `execute_port_tasks` (port-number order under a reduction budget ⇒ `PortTaskOutcome`, driving async completions for every port whose driver answers `has_pending_async` *before* harvesting input); `schedule_events`/`schedule_readiness` (enqueue an `INPUT`/`OUTPUT` task for directions the driver armed, `PortArms`); `port_command` (queue + schedule an `OUTPUT` task — the write happens in the task); `port_control` (reserved `"close"`; **any other `op`** goes verbatim to `control(op, arg)`); `take_exit_status`/`take_eof`; `schedule_timeout`/`cancel_timeout`/`next_deadline` (min over live drivers' `next_timeout`); `notify_port_exit` (`Driver::port_exit` **at most once**, port left live); `drive_async`; `set_line_mode`/`flush_linebuf`/`take_line_notifications` (drains every port's staged frames in **port-number order**, after a round).
### `driver.rs`
- `DriverFlags(u32)` (`Copy + Eq`; `SOFT_BUSY`) · `PortExitReason { Closed, OwnerExited, Normal }`.
- `DriverContext<'a>` — the driver's view of its port and **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`; keys are port numbers, `pub(crate) PortArms` records the armed directions); no message-send path. `deliver_read(header, body: Option<&[u8]>) -> Result<()>` is the driver-side `driver_output2`/`driver_output_binary`/`driver_outputv` seam: one read message, header apart from body, `None` = the C's `NULL` body, with bytes banked on `input()` closing into their own body-only read **first**. A context built without the port's sink (`pub(crate) with_reads`) answers the typed `unsupported` rather than flattening the split into `input()`.
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`), `control`, `has_control() -> bool` (= `true`; **`false` iff the driver's C counterpart has `control == NULL`**, e.g. `ram_file_drv`, and then `erlang:port_control/3` answers the oracle's `badarg` without consulting `Driver::control`; `DriverPort` answers `entry().control.is_some()`), `timeout`, `next_timeout() -> Option<Instant>` (mirrored into the port's `TIMEOUT`), `port_exit(PortExitReason)` (= `Ok(())`; once-only, distinct from the teardown `stop`), `drive_async` (= `Ok(0)`; `DriverPort` overrides with `poll_async`), `has_pending_async() -> bool` (= `false`), `take_exit_status() -> Result<Option<i32>>` (= `Ok(None)`; only `SpawnDriver` overrides), `take_eof() -> Result<bool>` (= `Ok(false)`; only `SpawnDriver`). New capabilities must be additive with defaults that keep the built-ins compiling.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`**.
- **The statically-linked (emulator `driver_tab`) set is a separate, narrower contract** — `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` (sorted) + `is_static_spawn_driver(name) -> bool`, `DriverRegistry::with_static_spawn_drivers()` (`names()` is exactly those three) and `DriverRegistry::create_static_spawn(name) -> Result<Box<dyn Driver>>` (membership gate first, then the ordinary factory lookup). `create_static_spawn` refuses a non-member with `BeamError::BadArg` — the oracle's `badarg` for `{spawn_driver,"fd"}`/`{spawn_driver,"efile"}` — **even on a `with_builtins()` registry that registers them**; the set is exactly the oracle's `erl_ddll:loaded_drivers/0` answer (`{ok,["tcp_inet","udp_inet","ram_file_drv"]}`), statically linked and **not** `.so`-loadable (`src/CONTEXT.md`).
### `drivers/` (per-driver detail is in `src/drivers/CONTEXT.md`; port-side framing in `src/CONTEXT.md`)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver: **owns** its fds (closed on `stop`/`Drop`), `pipe`/`connected`/`read_only`/`write_only` ctors, line/phase modes, the `line`/`noline`/`binary`/`text`/`getopts` control verbs, the `pub(crate)` write-slot seams (`adopt_write_fd`/`release_write_fd`/`has_write_fd`/`attached_fd`).
- `line_buffer.rs` — `LineBuffer` + `LineFrame { bytes, eol }` + `DEFAULT_MAX_LINE_LEN = 1024` (frames on `\n`, splits an over-long line, holds a partial line until a flush; `eol` = the C `LINEBUF_EOL`, **`false`** for a limit split, the `CR_AFTER` split and every flush). The frame API (`take_frames`/`drain_frames`/`flush_frames`/`flush_into_ready`) is what the **port** consumes; the byte-only views serve `binary_io.rs`, whose `Phase { Text, Binary }`/`PhaseChange` is the `erl_child_setup` text⇄binary machine (default `Phase::Binary`).
- `efile.rs` — `EfileDriver` (`name() == "efile"`) over a composed `FdDriver`; `make_efile()` is its `DriverFactory`; `data_mode()` records `FileDataMode`. The C's `open`/`close`/`path`/`eof`/`position`/`seek`/`sync`/`truncate`/`binary`/`list` verbs; `read_ahead`/`delayed_write` are **not** `open(2)` flags, a directory open is `EISDIR`, a failed syscall⇒the raw `BeamError::Io` errno (the `{error,atom}` rendering is the runtime's `prim_file` floor).
- `spawn.rs` — `SpawnStream { Binary, List }`; `SpawnSpec { Spawn { command, argv }, SpawnExecutable { path }, Fd { fd } }` = the term-free `open_port/2` `Name`; `SpawnOptions { stream, cd, env, args, exit_status }`; `StreamOptions { stderr_to_stdout, eof }`; `build_command`. `SpawnDriver` (`name() == "spawn"`) is **constructed**, really spawning in the constructor and reaping eagerly; once-only `take_exit_status()`/`take_eof()`; `stop`/`Drop` kill + reap + close every descriptor, but an adopted `{fd,N}` is **never** closed. **The only module here that may spawn OS children.**
- `inet/` — the built-in `tcp_inet` TCP driver (`{packet, N}` framing on **both** read and send paths), the `udp_inet` datagram driver over the shared `wire.rs`/`opt.rs`/`sys.rs`, and `opcode.rs` (the decimal `port_control/3` numberspace onto the named verbs); one socket behind one port, reachable through `open_port({spawn_driver, tcp_inet | udp_inet}, …)`. Detail: `src/drivers/inet/CONTEXT.md`.
- `ram_file.rs` — the built-in `ram_file_drv` driver (`RamFileDriver`/`make_ram_file`): a command-driven port over a `Vec<u8>`, the C's 13 opcodes and its `OK`/`NUMBER`/`DATA`/`ERROR` reply encodings.
### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; a `pub` sub-tree; the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code. Modules: `host.rs` (`PortHost` + `AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, preferring the entry's **`outputv`** on both write paths, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` exposes `queue_head` (the safe `&[u8]` companion of `driver_peekq`), **implements** `beam_abi::DriverHost::set_busy_port` (records `DriverState::busy`; read back via `AbiHost::is_busy`/`DriverPort::is_busy`), and `DriverPort::control` returns the **empty list** for the C's `*rbuf == NULL` reply. Detail: `src/abi/CONTEXT.md`.
### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
- `Encoding { Latin1, Unicode }` — the request's `Enc` / the device's `unic` (`name()`/`from_name()`; any other name, e.g. `{utf16,binary}`, is refused, never guessed) · `ByteSource` — the device's read, `read_chunk(size) -> Result<Option<Vec<u8>>>` (`None` = eof), impls for `std::fs::File` (EINTR-retrying), `SliceSource`, `EmptySource`.
- `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`: `new(source, encoding, read_mode)`/`with_buffer`/`encoding()`/`set_encoding`/`read_mode()`/`set_read_mode`/`buffer()`/`set_buffer`/`take_buffer`/`has_stashed_buffer`/`source_mut`; `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>` is the request.
- The **device loop** (`read_size` = `READ_SIZE_BINARY` 8 KiB / `READ_SIZE_LIST` 128): `get_chars/5` feeds a stashed leftover **before** any read, then `get_chars_empty`/`get_chars_notempty` → `get_chars_apply`, whose `latin1` clause matches only when `Enc == latin1` **and** `unic == latin1`; the general clause decodes/transcodes and carries the incomplete-UTF-8 tail. EOF is `eof`; a `unicode` sequence spanning end of file is the `invalid_unicode` stop (`src/io_device/CONTEXT.md`).
- The **`Continuation` seam** (`Continuation`/`ContData`/`Applied`/`Leftover`) — the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])` (`erl_scan:tokens/4` for `io`'s own calls): `apply(cont, ContData, out_encoding) -> Result<Applied<Cont, Reply>>`, the charlist being a `Vec<u32>`; `cast_reply` is `io_lib`'s list→binary cast. `NoEngineContinuation` is the not-installed default — every `apply` is the typed `unsupported` (`NO_ENGINE_CONTINUATION` names the missing `erl_scan:tokens/4`).
- **Deviations:** term-free (byte/code-point data, caller-defined reply/cont types); the `{stop, Reason, {error, Fn}, State}` boxing and the `invalid_unicode_error/4` position hack are the runtime's; `Leftover` is a flat `binary | charlist | nothing`.
### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
- `Signal` — the twelve signals `os:set_signal/2` accepts: `SigHup`/`SigQuit`/`SigAbrt`/`SigAlrm`/`SigTerm`/`SigUsr1`/`SigUsr2`/`SigChld`/`SigStop`/`SigTstp`/`SigCont`/`SigWinch` (fixed by `signalterm_to_signum`, `sys.c`, and `lib/kernel/src/os.erl`; `sigttin`/`sigttou` are **not** accepted, `siginfo` is excluded). `Signal::ALL: [Signal; 12]` is the `drain` report order; `name()`/`from_name()` (the lowercase BEAM atom, exact/case-sensitive), `signo()`/`from_signo()`. · `Disposition { Default, Handle, Ignore }` — `ALL`; `name()`/`from_name()` for `default`/`handle`/`ignore`.
- `SignalFacility` — `new() -> Result<Self>` (self-pipe via `pipe2(O_CLOEXEC|O_NONBLOCK)` on Linux/Android, `pipe`+`fcntl` elsewhere); `set(&mut self, Signal, Disposition)` (`sigaction(2)`: `SIG_DFL`/`SIG_IGN`/the trampoline, **empty `sa_mask`**, **`SA_RESTART`**); `disposition(&self, Signal)`; `read_fd(&self) -> RawFd` (the fd the runtime registers with `Poller` — **the runtime owns the registration/token**); `drain(&mut self) -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order). The bitmask is swapped *before* the pipe is drained, so a signal landing in that window is reported by the **next** drain — deferred, never lost.
- `SigStop` is **kernel-only** — `sigaction(2)` refuses every disposition change (`EINVAL`), so `set(SigStop, _)` always answers the typed `BeamError::Io` (the consumer `beam_rt` skips the syscall and answers the oracle's `ok`). `Drop` restores every prior disposition, closes the pipe and resets the pending bitmask **only** when the global write-end CAS shows this facility was still the live one.
- **Async-signal-safety (frozen).** The handler does exactly two async-signal-safe things: one atomic OR into a `static AtomicU64` per-signal bitmask and one `libc::write` of the signal number to the non-blocking pipe; `drain` maps signo→`Signal` in normal context, and the pipe byte count is **not** the source of truth. **Single instance** (process-global statics — keep exactly one facility alive). **Portability:** unix only, no `signalfd`. **Errors:** `BeamError::Io` for a failing `pipe`/`sigaction`.
### `cpu_time.rs` — the CPU-time facility (safe `getrusage`/`clock_gettime`)
- `CpuTimes { user_ms, system_ms }` (`Copy + Eq`) — a reading in whole **milliseconds** (the oracle's unit: µs ÷ 1000, truncating).
- `process_cpu_times() -> Result<CpuTimes>` — `getrusage(RUSAGE_SELF)`, the **process's** user+system time; exactly the C's measurement for `erlang:statistics(runtime)` (`erts_runtime_elapsed_both`, `erl_time_sup.c:1421-1481`; **system time is NOT used** by that arm, `erl_bif_info.c:4277-4291`).
- `thread_cpu_times() -> Result<CpuTimes>` — `clock_gettime(CLOCK_THREAD_CPUTIME_ID)`, the thread's **combined** user+system time as `user_ms` with `system_ms == 0` (that clock does not split them); the analogue of `sys_get_cputime`, **not** what `statistics(runtime)` uses.
- `RuntimeClock` (`new`/`Default` anchor **0**, `runtime() -> Result<(u64, u64)>`, `reset()`) — the `erlang:statistics(runtime)` counter: `(Total, SinceLastCall)` in **milliseconds**, `SinceLastCall` from the previous call, so the **first** call returns two equal elements (the C's `runtime_prev.data.user = 0`). A **failed** `getrusage` returns the typed `BeamError::Io` and leaves the anchor **unchanged** (never a fabricated `0`); `reset()` is an additive seam the C lacks.
### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
- `DynLib` — an owned `dlopen(3)` handle whose `Drop` calls `dlclose(3)` exactly once; `open(&Path)`/`open_with(&Path, DynLibFlags)`/`open_cstr(&CStr, DynLibFlags)`, `symbol(&CStr) -> Result<*mut c_void, DllError>`/`try_symbol(&CStr)`, `handle()`; deliberately **no** `into_raw`/`from_raw`, and not `Send`/`Sync`.
- `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default and the emulator's mode, `erl_unix_sys_ddll.c:133`; **matches** `beam_abi::driver::loader`/`nif::loader`), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`, `from_bits`/`bits`.
- `DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary: `Open` (the dynamic `{open_error, Code}` case), `SymbolNotFound`, `NoDriverInit`, `DriverInitFailed`, `BadDriverName`, `DriverNameTooLong`, `DriverIncorrectVersion`, `NoDdllAvailable`, `Unspecified`, `BadArg`; `reason_atom()`, `errcode()`, `text()`, `is_missing_file()`/`is_format_error()`/`is_undefined_symbol()`. `DllErrorKind::errcode()` is **derived** from the single `ERRCODE_TAB` via `atom_to_errcode(reason_atom())`; classification is **text-based only** (a failed `dlopen` does not set `errno` reliably), mirroring `find_errcode`.
- `ERRCODE_TAB` (the emulator's `errcode_tab`, `erl_bif_ddll.c:1709-1720`, byte-for-byte), `errcode_to_atom`/`atom_to_errcode` (`const fn`), `format_error_text`, `symbol_name(&str)`, and the `ERL_DE_*` constants; path spelling is the caller's (**no** `.so` suffix appended). The `-Wl,--export-dynamic` requirement belongs to the **loading** link, shared with `beam_abi`/`beam_rt`.
### `fs_access.rs` — the safe `access(2)` / `geteuid(2)` / `getegid(2)` floor
- `AccessMode { Exists, Read, Write, Execute }` (`ALL`; `libc_mode()` reads `libc`'s `F_OK`/`R_OK`/`W_OK`/`X_OK`).
- `try_access(&Path, AccessMode) -> Result<()>` — the crate's **one `access(2)` call site**, errno-preserving: `Ok(())` iff the kernel grants the mode, `Err(BeamError::Io(err))` with the untouched errno on refusal (`EINTR` retried), `Err(BeamError::BadArg)` for an interior-NUL path — the form a caller needs when the *reason* matters (the spawn driver's `X_OK` render as `error:enoent`/`error:eacces`).
- `access(&Path, AccessMode) -> Result<bool>` — a **refusal** (`EACCES`/`ENOENT`/`ENOTDIR`/`ELOOP`/`ENAMETOOLONG`/`EPERM`/`EROFS`/`ETXTBSY`) is `Ok(false)`; only a genuine syscall failure is `BeamError::Io`.
- `path_access(&Path) -> Result<(bool /*read*/, bool /*write*/)>` — the `#file_info{}` `access` slot: two **independent** `R_OK`/`W_OK` probes (`efile_read_info`, `unix_prim_file.c:754-762`), each [`access`], so a refusal is `false` (a writable-but-unreadable path answers `(false, true)`).
- `process_credentials() -> Result<(u32 /*euid*/, u32 /*egid*/)>` — the **effective** `geteuid(2)`/`getegid(2)` the reference's `check_access` compares a `stat` against (`unix_prim_file.c:771-801`); always `Ok`. `unsafe` only in the two syscall wrappers, each with a `// SAFETY:` rationale; re-exported at the crate root and in `prelude`.

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures⇒`BeamError::Io`, argument faults⇒`BeamError::BadArg`, id/registration exhaustion⇒`BeamError::SystemLimit`.
  Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`dup2`, the `inet` socket helpers incl.
  `setsockopt`/`getsockopt` in `drivers/inet/sys.rs`, the `cpu_time.rs` `getrusage`/`clock_gettime`, the `signal.rs` `pipe2`/`sigaction`, the `ddll.rs` `dlopen`/`dlsym`/`dlclose`, the `fs_access.rs` `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling.
  Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids come from `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**.
  `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync`.
  (Not enforced on `Poller`/`Waker` — the `Waker` is meant to cross threads; `SignalFacility` is process-global.)
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures.
  Files target ~1000 lines, split by responsibility.
  Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only; no new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so a different backend could be added behind it (an io_uring/`/dev/poll` backend is **not implemented today**).
  `mio` fd registration is `os-ext`/Unix-only, so Windows/iocp is out of scope (as in `beam_abi`).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **Task execution here, the scheduler thread above.** The poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; `PortNotification` keeps the engine/runtime split and the DAG clean.
  Only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver.
  A poll **error** likewise reaches both armed directions (C parity), so a fully armed port gets an `Output` task from a pure `EPOLLERR`, while the `PortArms` gate still denies it to a read-only port.
  **Divergence:** the C keeps three FIFO queues with no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT, `seq` tie-break) — observable only in the order two *different* kinds run in a round.
- **The spawn driver is constructed, not registered, and reaps eagerly:** a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (so a failed spawn registers nothing and `os_pid()` is readable before `PortRegistry::open`); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it; `stop`/`Drop` kill **and** reap (`Drop` reaps because Rust's `Child` does not).
  The failed-spawn split and the `stderr_to_stdout` alias are detailed in the `spawn.rs` API bullet above.
- **The TCP driver is a floor, not a full `inet`** — the served verbs incl.
  `setopts`/`getopts` and the framing types are oracle-cross-checked (see `src/drivers/inet/CONTEXT.md`).

## Known Issues
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output (the emulator's line flag); no `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Decoding `open_port/2` into `SpawnSpec`/`SpawnOptions`/`StreamOptions` and synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` is the runtime's job — this crate only moves bytes, reports the latched EOF/exit status **once**, and kills/reaps.
  Writing to a child that closed its stdin fails with a typed `BeamError::Io` (the remainder kept); adoption requires non-blocking, and a descriptor that refuses it fails the open with `BeamError::Io`. Input is not line-framed **in the driver**: the `binary`/`list` choice rides `SpawnStream`, and the `[line]`/`[binary,{line,N}]` framing is applied at the **port** (the C's placement) via `Port::set_line_mode` + the separate `PortRegistry::take_line_notifications` channel, cross-checked in `tests/spawn.rs::line_framing_matches_the_oracle`; the remaining `beam_rt` half is in `src/drivers/CONTEXT.md` › *Known Issues*.
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes; turning `erlang:port_control/3`'s `Data` term into the C's packed request payload is the runtime's job. The integer `Op` is forwarded as its decimal string and the built-in `tcp_inet`/`udp_inet` drivers decode it (`src/drivers/inet/opcode.rs`) onto the same verb body the named form uses, answering the C's `[0]exbadport` for an unmatched/wrapped or foreign opcode; **80 (`tcp_inet`) + 89 (`udp_inet`) oracle calls agree byte-for-byte**. The three families needing a seam the frozen `Driver` trait lacks are the *Known Gaps* ledger below; the served-vs-refused table and exact reply shapes are in `src/drivers/inet/CONTEXT.md` › *Handoffs*.
- **`port_command/2` on a socket-less or peerless inet port is a typed refusal** (`write_pending` ⇒ `BeamError::BadArg`, queued bytes retained), which `Port::check_write_accounting` short-circuits and `PortRegistry::execute_port_tasks` propagates out of the round, so it reaches `erlang:port_command/2`'s caller. The oracle answers `true` and then either delivers `{error,enotconn}` out of band or kills the port (`init_caller` ⇒ `driver_failure_posix(EINVAL)`) — neither reachable through the frozen `Driver` trait (no `driver_failure` seam, no driver→owner message path).
- **The busy-port flow control has no consumer above `src/abi/`.** `AbiHost::set_busy_port` records the per-port busy state and `AbiHost::is_busy`/`DriverPort::is_busy` read it back, but `Port`/`PortRegistry` carry no busy flag and `PortCommandOptions`'s `nosuspend`/`force` stay inert, so `port_command` here never suspends or refuses. Oracle-pinned: `[nosuspend]` ⇒ `false`; `[force]` ⇒ `notsup` for **any** driver lacking `ERL_DRV_FLAG_SOFT_BUSY` (busy or not) and `true` with it; `port_command/2` **suspends** the caller until `set_busy_port(port,0)`. The caller-blocking half, `DriverFlags::SOFT_BUSY` exposure and the `port_command` outcome belong to `beam_rt`'s `erlang:port_command/2,3` (handoff below).
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` entry callbacks are `void`.** Discarding the callback result and counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`), which frees the command and never re-queues; do not "fix" it into a remainder. The `int`/negative-"not accepted" contract belongs to the opposite direction (`driver_output*`, modelled as `0`/`-1`). Detail: `src/abi/CONTEXT.md`.
- **A C driver's `driver_output2`/`driver_output_binary`/`driver_outputv` still arrive here *flattened*.** `beam_abi`'s `DriverHost` has one `output(port, &[u8])` hook and its `drv/port.rs` joins the header onto the body, so a `.so` driver's two-buffer reply reaches `AbiHost::output` as one body-only push: the split this crate carries (`ReadMessage`) is produced by a Rust driver calling `DriverContext::deliver_read`, not yet by a loaded C driver. Closing it needs an **additive, defaulted `DriverHost::output2(port, header, body)`** hook (C ABI unchanged); `beam_abi` is another node's, so this is reported, not reached across.
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop.
- **No `Driver::flush` / asynchronous CLOSING on port close.** `PortRegistry::close`/`Port::close` run the driver's `stop` and drop both byte queues; the trait has no flush hook, so output queued at close time is not flushed (the C calls `drv->flush` and parks a non-empty queue in `ERTS_PORT_SFLG_CLOSING`, `io.c:3659-3700,3946-3956`). `beam_rt` mitigates by notifying the port owner before closing.
- **A multi-fd driver's readiness is not per-fd.** `DriverState::fd_armed` always hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a port with ≥2 fds selected the same way would starve the others; correcting it needs the fired fd reported through the poller/`DriverContext` (a frozen-seam change). Harmless for every current driver (one fd each).
- **File sizes (`wc -l`).** 15 modules exceed 1000 — `src/registry.rs` and `src/drivers/spawn.rs` 1978, `src/drivers/inet/tests.rs` 1789, `src/drivers/inet/mod.rs` 1698, `src/port.rs` 1484, `src/drivers/efile.rs` 1404, `src/drivers/inet/packet.rs` 1245, `src/drivers/fd.rs` 1193, `src/driver.rs` 1176, `src/drivers/ram_file_tests.rs` 1144, `src/drivers/inet/udp.rs` 1143, `src/port_task.rs` 1127, `src/signal.rs` 1105, `src/abi/port.rs` 1038, `src/drivers/inet/opcode_tests.rs` 1033 (each a source half plus its suite, or an `inet` subtree with its own child doc); all other modules are under 1000. `src/port.rs`/`src/port_task.rs` are source-plus-suite, so the next split is each file's `#[cfg(test)]` module into a sibling (`port_tests.rs`/`port_task_tests.rs`), as `src/drivers/inet/udp/`, `src/drivers/inet/opcode_tests*.rs`, `src/drivers/ram_file_tests.rs`, `src/registry_reply_tests.rs` and `src/abi/` already do.

## Handoff to beam_rt — the CPU-time facility
`beam_rt` owns the `erlang:statistics(runtime)` BIF and must adopt `src/cpu_time.rs`:
- Own **ONE `RuntimeClock` for the runtime's entire life** (a fresh clock per call makes `SinceLastCall == Total` every time — the anchor is the C's process-global `runtime_prev`), and serve the `statistics/1` `runtime` arm from `RuntimeClock::runtime()` (`RuntimeHooksBridge`, `crates/beam_rt/src/context/runtime_hooks.rs`), rendering the `(Total, SinceLastCall)` ms pair as the oracle's 2-tuple of integers (no runtime arithmetic).

### Handoff to `beam_rt` — the A.4 driver/port grammar (driver side closed in this crate)
- **`{spawn_driver, Name}` resolution → `DriverRegistry::create_static_spawn`.** At that site *only*, apply the emulator `driver_tab` membership gate first, so `{spawn_driver,"fd"}`/`{spawn_driver,"efile"}` become the oracle's `badarg` while `tcp_inet`/`udp_inet`/`ram_file_drv` are unchanged; render `Err(BadArg)` as `badarg` and keep `create`/the `SpawnDriver` path for other `Name` forms. `with_static_spawn_drivers()`'s `names()` is also the oracle's `erl_ddll:loaded_drivers/0` answer.
- **A built-in driver's reply → `{Port, {data, Data}}`.** This crate's half is pinned (`src/registry_reply_tests.rs`, `tests/driver_output2.rs`): one `PortNotification::Data` per driver hand-up, once. The runtime must render `ReadMessage` into the message and deliver it to the owner (oracle `{P,{data,<<3,0,0,0,0>>}}` vs `timeout`), and serve `port_info(P, input)` from `ReadMessage::len`/`Port::input_len` (oracle `{input,5}` vs `{input,0}`).
  **Rendering rule (oracle-pinned, `io.c:3363-3442`):** a `[binary]` port renders `header` as **one cons cell per byte** and the body as the improper tail — `[72,68,82|<<97,98,99>>]` (`is_list` true but `length/1` `badarg`), `[72,68,82|<<>>]` for `body: Some([])`, the *proper* list `[72,68,82]` for `body: None`, and the bare binary `<<97,98,99>>` for an empty header with a body; a `[list]` port renders `read.flattened()` as a flat int list (`[72,68,82,97,98,99]`), where the split is not observable at all.
- **A refused command → `badarg`.** A driver's `Err` from `output`/`ready_output` (e.g. a socket-less inet port's `BadArg`) surfaces out of `Port::output`/`Port::ready_output` and out of the whole `execute_port_tasks` round, with the bytes retained and the failed task popped (never re-driven); the runtime must raise `badarg` rather than answering `true`.
- **`open_port/2` stream options → `SpawnDriver::with_stream_options`.** Pass `stderr_to_stdout`/`eof` as a `StreamOptions` and, for an `eof` port, poll `PortRegistry::take_eof(id)` and emit the bare `{Port, eof}` message exactly once.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** `TcpInetDriver::peer_closed()` latches the close and `recv`/`send` already answer the C's `[0]closed`/`[0]enotconn`; the runtime needs a `Driver` accessor (e.g. `port_closed()`) to observe it.
- **A `>64`-byte `binary`-stream read is a `beam_rt` gap** (a port read larger than the on-heap binary limit must become an off-heap refc binary); `file`/`prim_file`/`standard_io`/`io_request` handling is `beam_rt`/`beam_bifs`, not `beam_io`.
- **`erlang:monitor/2` on a port target → `PortRegistry::{port_table,port_table_mut}`.** Those accessors hand out the registry's **own** id table — the `&mut PortTable` operand `beam_process::ProcessTable::{monitor_port,monitor_port_term,demonitor_port}` require (`monitor_term` answers a typed `unsupported` for a port target). **Borrowing rule** (in `port_table_mut`'s rustdoc): that `&mut` borrows the registry, so a caller holding it behind a `RefCell` (`beam_rt`: `Rc<RefCell<PortRegistry>>`) must take the `RefMut` + `&mut PortTable`, run the one call, and drop the whole chain before any nested borrow (else the typed `unsupported` or a `borrow_mut()` panic). **Runtime adoption is owed.**
- **The `{get_until,…}` io request → `beam_io::io_device`.** `beam_io` hosts the DEVICE SIDE: `IoDevice` reproduces `file_io_server`'s `get_chars/5` → `get_chars_apply/7` loop and `io_lib:get_until/4`'s conversions and reply cast; the one step that runs Erlang code — `apply(Mod, Func, [Cont, Chars | XtraArgs])` (`erl_scan:tokens/4` for `io`) — is the caller-supplied `Continuation` seam, whose default `NoEngineContinuation` is the typed `unsupported`. **Owner: `beam_rt`** — replace the `_ => error::unsupported(…)` fallback in `crates/beam_rt/src/native/file_server.rs::serve_device_request` with a `("get_until", 5)` arm that decodes `Enc`/`Mod`/`Func`/`XtraArgs`, builds `IoDevice::new(self.device_file(service)?, enc, read_mode)`, and installs an engine-backed `Continuation` (`cast_reply` = `io_lib`'s list→binary cast); the same `unicode:characters_to_binary/3` conversion unblocks `reply_get_chars`/`reply_put_chars`, which hard-refuse every non-`latin1` encoding.

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper).
  Never `cd`; never touch `../../tools/`.
- `src/fs_access.rs` is the crate's **only** `access(2)`/`geteuid(2)`/`getegid(2)` call site (the spawn driver's `X_OK` check delegates to `fs_access::try_access`).
  A new `access(2)` use belongs there, never as a second `unsafe` wrapper.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`.
  When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks`.
  Keys are port *numbers* (`PortId::number()`).
  To be woken by a handled OS signal, register `SignalFacility::read_fd()` with the poller.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`); do not close them elsewhere.
  `EfileDriver` composes an `FdDriver`, so the same ownership rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- `Ready` has **no public constructor**: tests that need a specific readiness forge it through `Event::new(token, key, ready)` with a real `Ready` or through the public `schedule_readiness(key, Readiness)`.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP and restore it.
  `SignalFacility` test raises are thread-directed — the facility is process-global, so serialize tests on a shared `Mutex`, raise to the process with `kill(getpid(), …)` or, where deterministic delivery is needed, use `pthread_kill(pthread_self(), …)` (POSIX delivers a target thread's pending signal before it returns).
