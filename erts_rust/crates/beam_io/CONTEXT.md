# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Built-in Drivers, io-device requests, Signals, CPU time, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.
Hosts nine subsystems: the `mio`-backed **poller/reactor**, the **`Port`** (a process-like I/O endpoint over a `Box<dyn Driver>` + two byte queues), **port-task scheduling** (`erts_port_task_execute`), the **io-device request layer** (`src/io_device/`), the **`Driver` trait + built-in drivers** (`fd`, `efile`, OS-child `spawn`, `tcp_inet`, `udp_inet`, `ram_file_drv`, `{line,N}` buffering, the text⇄binary phase-change protocol), the **driver C-ABI host layer** (`src/abi/`), the **OS-signal facility** behind `os:set_signal/2` (the signal `unsafe` work `beam_rt`, `#![deny(unsafe_code)]`, cannot do itself), the **CPU-time facility** (`src/cpu_time.rs`) behind `erlang:statistics(runtime)`, and the **dynamic-library primitive** (`src/ddll.rs`).
The API Surface below carries the frozen contracts; the per-driver, `inet`, `abi` and `io_device` detail lives in the child nodes named by the Routing Table.

`beam_rt` is the only consumer: it owns the poll loop, the port run queues and the scheduler thread, drives one long-lived `Poller` + `PortRegistry`, and turns `PortNotification`s plus the once-only `take_exit_status`/`take_eof`/`take_line_notifications` into `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}`/`{Port,{data,{eol|noeol,_}}}` for the owning process (waking a blocked receiver through `beam_process`); `beam_process` observes ports by id (the peer of pids in `ptab`).
Every built-in driver is reachable from there — `{spawn_driver, Name}` for the three statically linked names, the `spawn`/`fd`/`efile` constructors for the rest — and so are the signal, CPU-time, `fs_access`, ddll-floor and io-device facilities; `src/ddll.rs`'s `DynLib` is the one facility with no consumer outside this crate (*Handoffs*).
Legacy C ground truth (read-only) is listed under *Routing Table* › *Siblings and ground truth*.
## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed, rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque registration handle; **token `0` is the waker's**, user tokens start at `1`.
  · `Interest` — readiness mask (`READABLE`/`WRITABLE`/`BOTH`).
  · `Ready` — observed readiness, **no public constructor** (only `Ready::default()`/`From<Ready> for Readiness`).
  · `Event` (`token`/`key`/`ready`); `Event::new` lets tests forge one.
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`** created in `new()`; registered by raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks); `waker()` an infallible cheap clone.
  `Waker` is the `Arc`-backed, cloneable, thread-safe handle to that one wakeup handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).
- **`poll` is `EINTR`-tolerant**: an `ErrorKind::Interrupted` wait is **retried**, never returned as `BeamError::Io` (`mio` does not retry `EINTR`; `epoll_wait`/`poll`/`select` are never restarted after a handler runs, `SA_RESTART` notwithstanding), and the retry **preserves the deadline** (`poll(Some(d))` subtracts elapsed time, so repeated signals never block past `d`; `poll(None)` resumes).
- **Regular-file fallback (internal, no signature change):** epoll refuses regular files (`EPOLL_CTL_ADD`⇒`EPERM`), so `register` keeps a `libc::poll(2)`-backed fallback set — an unsupported descriptor is watched with `poll(2)` and its readiness merged into `poll` in the same `Event`/`Ready` shape; the probe reports its `std::io::Error`; `poll` never blocks indefinitely while the set is non-empty (`FALLBACK_POLL_CAP`, 1 ms).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — one deadline · `Timer` — deadlines keyed by `u64`; self-contained helpers (nothing in-crate consumes them); `Timer::schedule` replaces **any** deadline for a key, `Timer::pop_expired` returns due keys in **schedule** order.
- `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS` is the canonical `beam_common::CONTEXT_REDS` (4000), re-exported so `beam_io::port_task::CONTEXT_REDS` / `beam_io::CONTEXT_REDS` keep resolving — no local copy; `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS/100 (40)` and `PORT_REDS_EXECUTE = CONTEXT_REDS/4 (1000)` derive from it.
  `PortTaskOutcome::reds_used` models the per-kind cost only: the C additionally charges `ERTS_PORT_CALLBACK_VREDS` (`CONTEXT_REDS/20`) per task plus `ERTS_PORT_REDS_FREE` on teardown and bounds the round at `CONTEXT_REDS` (`erl_port_task.c:1730,1833,1848,1854-1860`).
  · `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`); `PortTask` (`Copy + Eq + Debug`).
  · `PortTaskQueue` — one pending task per kind (the C guards that in the caller via the per-direction `ErtsIoTask` handle / the port's single `timeout_task` handle, `erl_check_io.c:1848-1871`), ordered by kind **priority only** (`seq` is recorded but never a live tie-break); a not-yet-due `TIMEOUT` stays queued (divergence: the C dequeues it, charges 0 reds and drops it, `erl_port_task.c:1759-1774`); `arm_timeout(deadline)` re-points/replaces a pending `TIMEOUT` (unlike the dedupe-only `enqueue_timeout`).
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed ‖ error — a poll error is re-triggered for **every** armed direction, `ERTS_POLL_EV_ERR`, `erl_poll.h:184`; `revents = state->active_events`, `erl_check_io.c:2018-2027`), `is_idle()`, `From<Ready>`.
  · `PortNotification::Data { port, bytes } | Closed { port }` — the seam the runtime turns into `{Port,{data,Data}}`/port-exit messages. **Exactly these two variants**: it must stay exhaustively matchable by `beam_rt` (`beam_rt/src/port.rs`, two arms, no wildcard).
  · `LineNotification { port, bytes, eol }` — the **separate** channel a `{line, N}` port reports through (the `{eol|noeol, Data}` wrapper of `ERTS_PORT_SFLG_LINEBUF_IO`, `io.c:3430-3435`); a distinct struct, *not* a third `PortNotification` variant precisely so the enum above stays exhaustive for its outside consumers. Unlike `Data`, an empty `eol` frame is a real frame (a blank line is `{data,{eol,[]}}`).
  · `PortTaskOutcome { pub ran, pub reds_used, pub notifications }` (`notifications` carries `PortNotification`s only; line frames ride `PortRegistry::take_line_notifications`).

- `ReadMessage { header: Vec<u8>, body: Option<Vec<u8>> }` — one completed read with the C `driver_output2` header/body split preserved (`header` = `hbuf`/`hlen`, `body` = `buf`/`len`): one `ReadMessage` is one **`driver_output*` call**, never one byte chunk. `body: None` is the C's `buf == NULL` (no binary tail at all) and `Some(vec![])` a present empty body (`<<>>` tail) — different messages. Helpers `body_only`/`len` (`hlen+len`, the `bytes_in` accounting)/`is_empty`/`has_body`/`flattened` (the `[list]`-mode byte sequence); the oracle-pinned shape table (`io.c:3363-3442`) is in its rustdoc.
- `PortNotification::Data { port, read: ReadMessage } | Closed { port }` — the seam the runtime turns into `{Port,{data,Data}}`/port-exit messages. **Exactly these two variants** (exhaustively matchable by `beam_rt`: two arms, no wildcard). A round reports **one `Data` per `driver_output*` call**, in arrival order — several per port per round, two calls never merged — and an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** channel a `{line, N}` port reports through (the `{eol|noeol, Data}` wrapper of `ERTS_PORT_SFLG_LINEBUF_IO`, `io.c:3430-3435`); a distinct struct, *not* a third `PortNotification` variant precisely so that enum stays exhaustive for its outside consumers. `header` is the producing read's `ReadMessage::header`, which the C prepends as cons cells to **every** frame that call completes (`driver_output2("HDR",3,"a\nb\n",4)` ⇒ two frames, each carrying `"HDR"`; a line spanning two calls gets the header of the call that completed it), and is empty for a plain read and for the EOF flush. Unlike `Data`, an empty `eol` frame is a real frame (a blank line is `{data,{eol,[]}}`).
### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` (the budget `handle_events` runs) · `PortControl::CLOSE == "close"` — the one **reserved** control-op name (any other name is a driver verb) · `PortCommandOptions { nosuspend, force }` — carried/validated but **inert at this layer**: `Port`/`PortRegistry` carry no busy flag, so a command is never suspended or refused here (the C-ABI host layer's per-port `busy` state and the BIF caller-blocking half are `src/abi/` + `beam_rt`; see *Known Issues*).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; the scheduling surface (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`) and the exit/async/stream surfaces (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`).
  **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`) refreshes the port timer from `Driver::next_timeout` via `refresh_timeout`: `Some(d)` arms/**re-points** the single `TIMEOUT` task at `d`, `None` clears it.
  A driver write (`output`/`ready_output`) is **verified**: the port checks the output queue shrank by exactly the count the driver reported (a mismatch is the typed `error::unsupported(...)`), and schedules an `OUTPUT` task whenever the queue is left non-empty, so a short write cannot stall without re-driving.
  Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (the `ERTS_PORT_SFLG_LINEBUF_IO` bit + `linebuf->max_len`; `Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof`=`driver_eof` point; a `close` never flushes). A round harvests raw-mode input as ≤1 `PortNotification::Data`; in line mode it stages `LineNotification` frames on an internal queue (`take_line_frames()`, `pub(crate)`), so a line-mode port reports **nothing** through `PortNotification`.
  Re-exports `PortRegistry`.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number; basic ops (`new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`); `port_table`/`port_table_mut` expose that **same** id table (see the port-monitor handoff; `port_table_mut`'s rustdoc carries the borrowing rule).
  `close` runs the driver's `stop`, drops the port from the map and **retires the port number only when its `Closed` notification is reported** — so a deferred `Closed` can never name a reused id (both round drivers mint closes through one `take_closed_notifications` helper).
  Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`, returning its `PortTaskOutcome` and reporting/retiring the closes it drains); `execute_port_tasks` (port-number order under a reduction budget ⇒ a `PortTaskOutcome`; drives async completions for every live port whose driver answers `has_pending_async` *before* harvesting input, so a `driver_async` job reaches `ready_async`/`async_free` with no runtime call); `schedule_events`/`schedule_readiness` (enqueue only — an `INPUT`/`OUTPUT` task for directions the driver armed, `PortArms`); `port_command` (queue output + schedule an `OUTPUT` task; the write happens in the task); `port_control` (reserved `"close"` closes with an empty reply; **any other `op`** goes verbatim to `control(op, arg)`); `take_exit_status`/`take_eof` (once-only reaped child status / EOF report); `schedule_timeout`/`cancel_timeout`/`next_deadline` (min over live drivers' `next_timeout`); `notify_port_exit` (`Driver::port_exit` **at most once**, port left live, independent of `close`/`stop`); `drive_async`; `set_line_mode`/`flush_linebuf` and `take_line_notifications` (drains every port's staged `LineNotification` frames in **port-number order** after a round — the accessor style of `take_eof`/`take_closed_notifications`).

### `driver.rs`
- `DriverFlags(u32)` — `Copy + Eq`; `SOFT_BUSY`. · `PortExitReason { Closed, OwnerExited, Normal }`.
  · `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number (`pub(crate) PortArms` records the armed directions). It carries **no** message-send path and no per-frame drain (see the `tcp_inet` active-mode handoff). `deliver_read(header, body: Option<&[u8]>) -> Result<()>` is the driver-side `driver_output2`/`driver_output_binary`/`driver_outputv` seam: one read message, the C's header/body split preserved (`None` = the C's `NULL` body), with bytes banked on `input()` closing into their own body-only read **first**; a context built without the port's sink answers the typed `unsupported` rather than flattening the split.
- `pub trait Driver` — **frozen**.
  Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`.
  Defaulted: `ready_output` (= `output`), `control`, `has_control() -> bool` (= `true`; **`false` iff the driver's C counterpart has `control == NULL`**, e.g. `ram_file_drv` — then `erlang:port_control/3` must answer the oracle's `badarg` without consulting `Driver::control`, `io.c:4034-4036`; `DriverPort` answers `entry().control.is_some()`), `timeout` (its `Result<()>` is discarded by `Port::run_task`'s `Timeout` arm — no reply channel), `next_timeout() -> Option<Instant>` (the declared deadline, mirrored into the port's `TIMEOUT` after each interaction), `port_exit(PortExitReason)` (the once-only advisory port-exit notification, distinct from the teardown `stop`), `drive_async` (default `Ok(0)`; `DriverPort` overrides with `poll_async`), `has_pending_async()` (default `false`; overridden via `AbiHost`), `take_exit_status()` (only `SpawnDriver` overrides), `take_eof()` (only `SpawnDriver`). Further capabilities must be additive with defaults that keep the built-ins compiling.
  · `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`**.
  **The statically-linked (emulator `driver_tab`) set is a separate, narrower contract** — `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` (sorted) + `is_static_spawn_driver(name) -> bool`, `DriverRegistry::with_static_spawn_drivers()` (a registry whose `names()` is exactly those three) and `DriverRegistry::create_static_spawn(name) -> Result<Box<dyn Driver>>` (membership gate first, then the ordinary factory lookup). `create_static_spawn` refuses a name outside the set with `BeamError::BadArg` — the oracle's own `badarg` for `open_port({spawn_driver,"fd"},[])`/`{spawn_driver,"efile"},[]}` — **even on a `with_builtins()` registry that registers them**; `with_builtins()` is unchanged because this crate's own `fd`/`efile` ports are built through it. That set is exactly the oracle's `erl_ddll:loaded_drivers/0` answer (`{ok,["tcp_inet","udp_inet","ram_file_drv"]}`): they are statically linked into the emulator, **not** `.so`-loadable (`erts-*/lib/` ships zero `.so`).

### `drivers/` (module roles, verb tables and per-driver suites: `src/drivers/CONTEXT.md`)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver; **owns** its fds (closed on `stop`/`Drop`); line/phase modes (`Some(0)` = no line limit), the `line`/`noline`/`binary`/`text`/`getopts` control verbs (unknown⇒`BadArg`), EOF de-registration (the fd stays attached/owned), and the `pub(crate)` write-slot seams `adopt_write_fd`/`release_write_fd`/`has_write_fd`/`attached_fd`.
  · `line_buffer.rs` — `LineBuffer` + `LineFrame { bytes, eol }` + `DEFAULT_MAX_LINE_LEN = 1024` (the C's `LINEBUF_EOL`/`LINEBUF_NOEOL` split, limit and `CR_AFTER` splits); `binary_io.rs` — `Phase { Text, Binary }` + `PhaseChange`, the `erl_child_setup` text⇄binary machine, default `Phase::Binary` (byte-identical to raw passthrough).
- `efile.rs` — `EfileDriver` (`name() == "efile"`) delegates byte movement to a composed `FdDriver`; `make_efile()` = its `DriverFactory`. A failed syscall⇒the raw `BeamError::Io` errno (the `{error,atom}` rendering is the runtime's `prim_file` floor); an unopened port / unparsable argument⇒`BadArg`.
- `spawn.rs` — `SpawnDriver` (`name() == "spawn"`), the **only** module here that may spawn OS children; **constructed** (`with_stream_options`), **really spawning** in the constructor and reaping eagerly (once-only `take_exit_status()`/`take_eof()`); `SpawnStream { Binary, List }` (`Default = List`) = the `binary`/`list` option (the **runtime** builds `{Port,{data,Data}}`), and `SpawnSpec`/`SpawnOptions`/`StreamOptions`/`build_command` are the term-free `open_port/2` shape (empty command/path or argv⇒`BadArg`). `stop`/`Drop` kill + reap + deregister/close every descriptor, but an adopted `{fd,N}` is **never** closed.
- `inet/` — the built-in **`tcp_inet`** TCP socket driver (`{packet, N}` framing on **both** the read path and the send path) plus the **`udp_inet`** datagram driver (`udp.rs`), sharing `wire.rs`/`opt.rs`/`sys.rs`/`stat.rs`; `opcode.rs` decodes the decimal `erlang:port_control/3` numberspace onto the same named-verb bodies, and `sys::wait_connected` is the bounded `poll(2)`+`SO_ERROR` completion that makes `INET_REQ_CONNECT` synchronous.
  Shared option arms read the driver's **cached `stype`** (there is no local `stream` flag): `{mode, list|binary}`(24) and `{deliver, port|term}`(25) are **ungated** on both drivers (`inet_set_opts` `inet_drv.c:6939-6956`, `inet_fill_opts` `:9168-9175`), `{read_packets, N}`(33) is gated on a **datagram** `stype` (`:7138-7146`/`:9258-9270`), and `send_timeout`/`send_timeout_close` on a **stream** one.
  Each driver is one socket behind one port, reachable through `open_port({spawn_driver, tcp_inet | udp_inet}, …)`. Full detail (control-verb tables, option wire, the `PacketType` decoder, the `gen_tcp`/`gen_udp` handoffs): **`src/drivers/inet/CONTEXT.md`**.
- `ram_file.rs` — the built-in **`ram_file_drv`** in-memory file driver (`RamFileDriver`/`make_ram_file`): a command-driven port (an opcode byte on the output queue → a reply on the input queue) over a `Vec<u8>`, the C's 13 opcodes and its `OK`/`NUMBER`/`DATA`/`ERROR` reply encodings.

### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; a `pub` sub-tree (`pub use crate::abi::*`); the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code.
Four modules — `host.rs` (`PortHost` + `AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, which prefers the entry's **`outputv`** on both write paths, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` **implements** `beam_abi::DriverHost::set_busy_port` (records the per-port `DriverState::busy` flag, answers the C's `0`; read back via `AbiHost::is_busy`/`DriverPort::is_busy`), exposes `queue_head` (the safe `&[u8]` companion of the raw `driver_peekq` hook, as `DriverState::queue_len()` is of `sizeq`), and `DriverPort::control` returns the **empty list** for the C's documented `*rbuf == NULL` reply rather than `badarg`. Detail: the child node **`src/abi/CONTEXT.md`**.

### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
`Encoding { Latin1, Unicode }` (any other name — a tuple encoding, … — is refused, never guessed) · `ByteSource` (`read_chunk(size) -> Result<Option<Vec<u8>>>`, `None` = eof; impls for `std::fs::File`, `SliceSource`, `EmptySource`) · `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`, whose request is `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>`.
The device loop (`READ_SIZE_BINARY` 8 KiB / `READ_SIZE_LIST` 128) reproduces `get_chars/5` → `get_chars_apply/7`: a stashed leftover is fed **before** any read, the `latin1` clause matches only when `Enc == latin1` **and** `unic == latin1`, the general clause decodes/transcodes (`InEnc = unic`, `OutEnc = Enc`) and carries the incomplete-UTF-8 tail across a `{more,…}` re-read, `eof` is delivered as `eof`, and a sequence spanning end-of-file is the `invalid_unicode` stop.
The **`Continuation` seam** (`Continuation`/`ContData`/`Applied`/`Leftover`) is the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])`; the charlist is a `Vec<u32>` of code points and `cast_reply` is `io_lib`'s list→binary cast. `NoEngineContinuation` is the not-installed default: every `apply` is the typed `unsupported` (`NO_ENGINE_CONTINUATION` names the missing `erl_scan:tokens/4`), never a fabricated reply.
**Deviations:** term-free (byte/code-point data, caller-defined reply/cont types); the `{stop, Reason, {error, Fn}, State}` reply boxing and the `erl_scan`-specific `invalid_unicode_error/4` position hack are the runtime/protocol layer's; `Leftover` is a flat `binary | charlist | nothing` (no deep iolist). Detail: **`src/io_device/CONTEXT.md`**.

### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
`Signal` — the twelve signals `os:set_signal/2` accepts (`SigHup`/`SigQuit`/`SigAbrt`/`SigAlrm`/`SigTerm`/`SigUsr1`/`SigUsr2`/`SigChld`/`SigStop`/`SigTstp`/`SigCont`/`SigWinch`; `sigttin`/`sigttou` are **not** accepted), `Signal::ALL` = the `drain` report order, `name`/`from_name`/`signo`/`from_signo`; `Disposition { Default, Handle, Ignore }`.
`SignalFacility` — `new()`, `set(&mut self, Signal, Disposition)` (`sigaction(2)`, **empty `sa_mask`**, **`SA_RESTART`**), `disposition`, `read_fd()` (the fd the runtime registers with `Poller` — **the runtime owns the registration/token**), `drain() -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order; the bitmask is swapped *before* the pipe is drained, so a signal landing in that window is deferred, never lost).
`SigStop` is **kernel-only** (`sigaction(2)` refuses every disposition change, so `set(SigStop, _)` is the typed `BeamError::Io`; the consumer answers the oracle's `ok`).
The handler is **async-signal-safe** — one atomic bitmask OR plus one `libc::write` to a non-blocking self-pipe, whose byte count is **not** the source of truth; `drain` maps signo→`Signal` in normal context. The facility is **process-global** (keep exactly one alive; `new`-after-`drop` is safe; `Drop` restores every prior disposition, resetting the pending bitmask only if this facility was still the live one) and unix-only (no `signalfd`). Full detail: `src/signal.rs`.

### `cpu_time.rs` — the CPU-time facility (safe `getrusage`/`clock_gettime`)
`CpuTimes { user_ms, system_ms }` — whole **milliseconds** (the oracle's unit: µs ÷ 1000, truncating).
`process_cpu_times()` (`getrusage(RUSAGE_SELF)`, the process's user+system time over its threads) is exactly the C's `erlang:statistics(runtime)` measurement (`erts_runtime_elapsed_both`, `erl_time_sup.c:1421-1481`); `thread_cpu_times()` (`clock_gettime(CLOCK_THREAD_CPUTIME_ID)`) reports the calling thread's combined time as `user_ms` with `system_ms == 0` and is **not** what that BIF uses.
`RuntimeClock` (`new`/`Default` anchor **0**, `runtime() -> Result<(u64, u64)>`, `reset()`) is the `statistics(runtime)` counter: `(Total, SinceLastCall)` in **milliseconds**, so the **first** call returns two equal elements (the C's `runtime_prev.data.user = 0`) and **system time is not used** (`erl_bif_info.c:4277-4291`); a failed `getrusage` returns the typed `BeamError::Io` and leaves the anchor **unchanged** (never a fabricated `0`).

### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
`DynLib` — an owned `dlopen(3)` handle (`open`/`open_with`/`open_cstr`, `symbol`/`try_symbol`, `handle()`; `Drop` closes exactly once); deliberately no `into_raw`/`from_raw`, and not `Send`/`Sync`. `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default, the emulator's mode and the mode `beam_abi`'s loaders use), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`.
`DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary, with `reason_atom()`, `errcode()` (**derived** from the single `ERRCODE_TAB` via `atom_to_errcode(reason_atom())`, not a second hand-written match), `text()`, `is_*()` classifiers; classification is **text-based only** (a failed `dlopen` does not set `errno` reliably), mirroring the emulator's `find_errcode`. `ERRCODE_TAB` (the emulator's `errcode_tab`, `erl_bif_ddll.c:1709-1720`, byte-for-byte) plus `errcode_to_atom`/`format_error_text`/`symbol_name`/`ERL_DE_*`; **no** `.so` suffix is appended (path spelling is the caller's).
The `-Wl,--export-dynamic` requirement is a property of the **loading** link, shared with `beam_abi`/`beam_rt`; this crate's part is its `build.rs`.

### `fs_access.rs` — the safe `access(2)` / `geteuid(2)` / `getegid(2)` floor
`AccessMode { Exists, Read, Write, Execute }` (`libc_mode()` reads `libc`'s `F_OK`/`R_OK`/`W_OK`/`X_OK`).
`try_access(&Path, AccessMode) -> Result<()>` — the crate's **one `access(2)` call site**, errno-preserving: `Ok(())` iff the kernel grants the mode, `Err(BeamError::Io(err))` with the untouched errno on refusal (`EINTR` retried), `Err(BeamError::BadArg)` for an interior-NUL path — the form a caller needs when the *reason* matters (the spawn driver's `X_OK` render).
`access(&Path, AccessMode) -> Result<bool>` — the boolean form: a **refusal** (`EACCES`/`ENOENT`/`ENOTDIR`/`ELOOP`/`ENAMETOOLONG`/`EPERM`/`EROFS`/`ETXTBSY`) is `Ok(false)`, only a genuine syscall failure is `BeamError::Io`; `path_access(&Path) -> Result<(read, write)>` is the `#file_info{}` `access` slot (two **independent** probes, `unix_prim_file.c:754-762`, so a writable-but-unreadable path answers `(false, true)`); `process_credentials() -> Result<(euid, egid)>` are the **effective** ids `check_access` compares a `stat` against (`:771-801`) and cannot fail.

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures⇒`BeamError::Io`, argument faults⇒`BeamError::BadArg`, id/registration exhaustion⇒`BeamError::SystemLimit`.
  Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`dup2`, the `inet` socket helpers incl.
  `setsockopt`/`getsockopt` in `drivers/inet/sys.rs`, the `cpu_time.rs` `getrusage`/`clock_gettime`, the `signal.rs` `pipe2`/`sigaction`, the `ddll.rs` `dlopen`/`dlsym`/`dlclose`, the `fs_access.rs` `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling.
  Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids come from `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**.
  `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync`.
  (Not enforced on `Poller`/`Waker` — the `Waker` is meant to cross threads; `SignalFacility` is process-global.)
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures.
  Files target ~1000 lines, split by responsibility.
  Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only; no new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so a different backend could be added behind it (an io_uring/`/dev/poll` backend is **not implemented today**).
  `mio` fd registration is `os-ext`/Unix-only, so Windows/iocp is out of scope (as in `beam_abi`).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **Task execution here, the scheduler thread above.** The poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; `PortNotification` keeps the engine/runtime split and the DAG clean.
  Only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver.
  A poll **error** likewise reaches both armed directions (C parity), so a fully armed port gets an `Output` task from a pure `EPOLLERR`, while the `PortArms` gate still denies it to a read-only port.
  **Divergence:** the C keeps three FIFO queues with no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT, `seq` tie-break) — observable only in the order two *different* kinds run in a round.
- **The spawn driver is constructed, not registered, and reaps eagerly:** a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (so a failed spawn registers nothing and `os_pid()` is readable before `PortRegistry::open`); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it; `stop`/`Drop` kill **and** reap (`Drop` reaps because Rust's `Child` does not).
- **The TCP driver is a floor, not a full `inet`** — the served verbs incl. `setopts`/`getopts` and the framing types are oracle-cross-checked (see `src/drivers/inet/CONTEXT.md`).

## Known Issues
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output (the emulator's line flag); no `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Decoding `open_port/2` into `SpawnSpec`/`SpawnOptions`/`StreamOptions` and synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` is the runtime's job — this crate only moves bytes, reports the latched EOF/exit status **once**, and kills/reaps.
  Writing to a child that closed its stdin fails with a typed `BeamError::Io` (the remainder kept); adoption requires non-blocking (`F_SETFL`+`O_NONBLOCK`), and a descriptor that refuses (some inherited ones ⇒ `EPERM`) fails the open with `BeamError::Io`.
  Input is not line-framed **in the driver** (no `line` verb): the `binary`/`list` choice rides `SpawnStream`, and the `[line]`/`[binary,{line,N}]` framing is applied at the **port** — the C's placement — via `Port::set_line_mode` + the separate `PortRegistry::take_line_notifications` channel (cross-checked in `tests/spawn.rs::line_framing_matches_the_oracle`).
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes; turning `erlang:port_control/3`'s `Data` term into the C's packed request payload is the runtime's job. The integer `Op` is forwarded as its decimal string and `src/drivers/inet/opcode.rs` decodes it (the `0x03f1a300` magic, wrapping unsigned subtraction, the C's three switches) onto the same verb body the named form uses; an unmatched/wrapped number and the other driver's opcode answer the C's `[0]exbadport`, and the C's guard order (state before operand length) is reproduced per arm.
  The whole `INET_REQ_*` surface is served wherever the reply is computable from driver state plus plain syscalls — **80 (`tcp_inet`) + 89 (`udp_inet`) + 11 (`LISTEN`/`CONNECT`) oracle calls agree byte-for-byte**, incl. the cached-`stype` post-close `GETTYPE`, the fake `SETNAME`/`SETPEER` endpoint, the `GETLADDRS`/`GETPADDRS` fallbacks and `SUBSCRIBE`(24)'s `[1] ++ (op ++ be32(outq))*` reply; `INET_REQ_LISTEN`(27) is verified with no gap of its own.
  `INET_REQ_GETSTAT`(11) renders the C's real per-descriptor counters (`src/drivers/inet/stat.rs`: `recv_cnt`/`recv_max`/`recv_avg`/`recv_dvi`, `send_cnt`/`send_max`/`send_avg`, `send_pend` from the port's output queue) as `[1] ++ [op, u32_be]*`, with 9-byte `[op, u64_be]` records for the two octet counters and `badarg` for an unknown op.
  `INET_REQ_FDOPEN`(13) serves the full `inet_ctl_fdopen` **success path on both drivers** (non-blocking, poller-registered `READABLE`, `sock_peer` promoting a **stream** adoption to `Connected`, cached `stype`/`family`), and a `prebound` descriptor is never `close(2)`d — the `close` verb, `stop` and `Drop` only deregister it (`erl_inet_close`, `:5102`-`:5117`). What remains is the pre-adoption ladder (length/family/type/`sock_name`/negative-word refusals) and one deliberate **non-mirror**: FDOPEN on a port that already holds a socket answers `[0]einval` with the live socket untouched, where the C overwrites `desc->s` and leaks the old one.
  `INET_REQ_CONNECT`(3) completes **synchronously** under a bounded `poll(2)`+`SO_ERROR` wait (`sys::wait_connected`, clamped to `CONNECT_WAIT_CAP_MS` = 30 s): bare `[1]` on success, `[0] ++ errno` on failure or `etimedout`, and it is **not** in the async-op family.
  The `gen_udp:send`/`gen_tcp:send` grammar follows the C's `packet_inet_command` (`:15142`-`:15260`): an **open but unconnected** datagram socket `sendto`s the address the command carries (the plain `[address][anc_len:be32][anc][data]` form, with the `prim_inet` caller-ref-prefixed form as a fallback), and `{mode, list|binary}` is accepted, so `gen_tcp:listen(0, [binary])` is not refused.
  Three families remain, each needing a seam the frozen `Driver` trait lacks, and are documented in `src/drivers/inet/CONTEXT.md` › *Handoffs*: (a) the **async-op queue** — `TCP_REQ_RECV`(42)/`PACKET_REQ_RECV`(60)/`ACCEPT`(26) answer the synchronous read-now `[1]` instead of `[1] ++ async_id_be16` + a later `{inet_async,…}`; (b) **`accept` creates no second port** (the port transfers itself to the connection); (c) **refusal-only arms** — `Getservby*`(17/18), `Ignorefd`(28), `TcpSendfile`(45) reproduce the C's refusals exactly and raise the typed `not_served` on the success path only. `SUBSCRIBE`(24) is the one served opcode whose **notification** half has no seam: its reply is exact, but the later `{empty_out_q, Port}` message is never sent (no driver→owner channel).
- **`port_command/2` on a socket-less inet port is a typed refusal** (`TcpInetDriver`/`UdpInetDriver::write_pending` ⇒ `BeamError::BadArg`, queued bytes retained), which `Port::check_write_accounting` short-circuits and `PortRegistry::execute_port_tasks` propagates out of the round, so `erlang:port_command/2` raises.
  The C's guard is `!IS_CONNECTED` for `tcp_inet` but `!IS_OPEN` for `udp_inet`: an open-but-unconnected datagram port really sends (the destination rides the command), so only a socket-less one refuses. Where the oracle answers `true` and then either delivers `{error,enotconn}` out of band (a caller-ref-prefixed payload) or kills the port (`init_caller` ⇒ `driver_failure_posix(EINVAL)`), neither shape is reachable through the frozen `Driver` trait (no `driver_failure` seam, no driver→owner message path).
- **The `prim_inet` caller-reference prefix is stripped only for `udp_inet`.** The UDP `send` verb recovers the `[n:be16][tag]` head from the payload alone (its post-prefix grammar starts with an address tag); a TCP payload is structureless after the prefix, so `TcpInetDriver::verb_send` keeps the plain byte-stream grammar and a prefixed `gen_tcp:send` payload would be written as data. Closing that half needs a `driver_caller` equivalent on the frozen seam (*Handoffs*).
- **`{inet_reply, S, ok | {error, Reason}, Mref}` cannot be sent from this crate.** The C echoes the caller's tag bytes in `desc->caller_ref` (`inet_reply_finish`/`inet_reply_caller_ref`, `inet_drv.c:2610`-`:2660`); with no driver→owner message channel here, `prim_inet:send/3`'s and `prim_inet:sendto/4`'s `receive {inet_reply,S,Reply,Ref}` has no counterpart — the datagram/bytes go out but the caller never gets its reply (*Handoffs*; detail in `src/drivers/inet/CONTEXT.md` › *Known Issues*).
- **The `driver_output2` DATA reply's improper-list rendering is the runtime's.** The producer half is done: `PortNotification::Data` carries a `ReadMessage { header, body: Option<Vec<u8>> }` so the C's `(hbuf,hlen,buf,len)` split survives to the consumer (oracle-pinned shapes in `ReadMessage`'s rustdoc, `io.c:3363-3442`: `[binary]` port ⇒ `[H | <<B>>]`, `body: None` ⇒ a **proper** list with no tail, empty header + body ⇒ a bare binary, `[list]` port ⇒ `read.flattened()`). `beam_rt`'s message builder must render that shape. A **loaded C** driver still arrives flattened: `beam_abi::DriverHost` has only `output(port, &[u8])` and its `drv/port.rs` joins header onto body, so closing that half needs an **additive, defaulted `DriverHost::output2(port, header, body)`** hook (owner: the `beam_abi` node; the C ABI itself is unchanged).
- **The busy-port flow control has no consumer above `src/abi/`.** `AbiHost::set_busy_port` records the per-port busy state and `AbiHost::is_busy`/`DriverPort::is_busy` read it back, but `Port`/`PortRegistry` carry no busy flag and `PortCommandOptions`'s `nosuspend`/`force` stay inert, so `port_command` here never suspends or refuses; the caller-blocking half is `beam_rt`'s (*Handoffs*).
  Oracle-pinned (a `cc`-built driver whose `start` calls `set_busy_port(port,1)`): `[nosuspend]` ⇒ `false`; `[force]` ⇒ `notsup` for **any** driver lacking `ERL_DRV_FLAG_SOFT_BUSY` (busy or not) and `true` with it; `port_command/2` **suspends** the caller until `set_busy_port(port,0)`.
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` entry callbacks are `void`.** Discarding the callback result and counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`), which frees the command and never re-queues; do not "fix" it into a remainder. The `int`/negative-"not accepted" contract belongs to the opposite direction (`driver_output*`, already modelled as `0`/`-1`). Detail and the pinned oracle observations: `src/abi/CONTEXT.md`.
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop.
- **No `Driver::flush` / asynchronous CLOSING on port close.** `PortRegistry::close`/`Port::close` run the driver's `stop` and drop both byte queues; the `Driver` trait has no flush hook, so output queued at close time is not flushed (the C calls `drv->flush` and parks a port with a non-empty `ioq` in `ERTS_PORT_SFLG_CLOSING`, `../../erts/emulator/beam/io.c:3659-3700`, `:3946-3956`).
  `beam_rt` mitigates by notifying the port owner before closing.
- **A multi-fd driver's readiness is not per-fd.** `DriverState::fd_armed` always hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a port with ≥2 fds selected the same way would starve the others; correcting it needs the fired fd reported through the poller/`DriverContext` (a frozen-seam change).
  Harmless for every current driver (one fd each).
- **`{fd,N}` spawn port holds an `Interest::BOTH` registration for its life.** `arm_output`/`disarm_output` are no-ops for `duplex`, so the single adopted descriptor stays registered both ways after read EOF (`release_stdout` is a no-op for duplex). Harmless under the edge-triggered poller, but a spurious `OUTPUT` task is scheduled on every write-readiness event.

## Handoffs (beam_rt — out of this node)
**Adopted upstream:** `{line,N}` framing (`set_line_mode` + `take_line_notifications`), busy-port flow control (`DriverPort::is_busy`/`soft_busy` + `SOFT_BUSY`), the `#file_info{}` `access`/`uid`/`gid` path (`fs_access`), the signal and CPU-time facilities, `create_static_spawn`, the once-only `take_eof`, the port-monitor id table, the `{get_until,…}` io request, `ram_file_drv`'s port path, `erlang:port_control/3` and a refused command's `badarg`.
**Still owed, each a seam the frozen `Driver`/`DriverContext` trait lacks:**
- **The `{inet_reply, S, Reply, Mref}` driver→owner message channel.** `prim_inet:send/3` and `prim_inet:sendto/4` block in `receive {inet_reply,S,Reply,Ref}` after a successful command, so the datagram/bytes go out but the caller never gets its reply until that channel exists (`inet_reply_finish`/`inet_reply_caller_ref`, `inet_drv.c:2610-2660`).
  Owner: `beam_rt` — its `PortEvent::Term` machinery exists for `dlopen`ed driver ports, but a **built-in** driver port has no term path (`PortMeta::driver_terms` is `None` for `PortName::SpawnDriverBuiltin`).
- **`driver_caller`.** The TCP command payload's caller-reference prefix cannot be stripped: a TCP payload is structureless after the prefix, so there is no sound discriminator without a caller notion on the frozen `Driver`/`DriverContext` seam.
- **The delivered-data term shape (`mode` list vs binary) is decided above this crate.** `PortNotification::Data` carries bytes and `beam_rt` builds the message (`prim_inet:open/5` always passes `[binary]` to `open_port`), whereas the C's `tcp_reply_data` builds the term from `desc->mode`. Storing/reporting `mode` is closed here; rendering is `beam_rt`'s.
- **The async-op queue** (`TCP_REQ_RECV` 42 / `PACKET_REQ_RECV` 60 / `ACCEPT` 26 answer synchronous read-now shapes; `accept` transfers the port instead of creating a second one), **`{active,N|once}`/`{deliver,…}`/`active_count` input delivery**, **`send_timeout`/`send_timeout_close`**, **`controlling_process`**, **`SUBSCRIBE`'s notification half**, the **`IGNOREFD`/`TcpSendfile`/`Getservby*` refusal-only arms**, and **`udp_inet`'s active-mode `{udp, S, IP, Port, Data}` delivery + ancillary data (`anc_len != 0`)** — all refused honestly today; the owner, the missing seam and the C ground truth for each are in `src/drivers/inet/CONTEXT.md` › *Handoffs/Divergences*.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** `TcpInetDriver::peer_closed()` latches the close and the driver's `recv`/`send` already answer the C's `[0]closed`/`[0]enotconn`; the runtime needs a `Driver` accessor (e.g. `port_closed()`) to observe it and deliver the message.
- **The DATA header/body rendering (runtime side).** The split now crosses `PortNotification::Data` as `ReadMessage { header, body }`; `beam_rt` must match `PortNotification::Data { port, read }` (was `bytes`) and render the oracle's improper list, and stamp a `LineNotification`'s `header` as the same cons prefix on `{eol|noeol, Data}`.
- **`beam_rt`'s `src/port/inet_matrix_tests.rs::the_residuals_no_oracle_column_can_pin_stay_typed` still asserts the old `INET_REQ_FDOPEN`-adoption typed gap** and fails against this crate's served path (it now gets the `[0]einval` "already holds a socket" answer of the non-mirror). That node's owner must update the row; this crate cannot.
- **`src/ddll.rs`'s `DynLib` has no consumer outside this crate.** `beam_rt`'s `erl_ddll` floor is built on `beam_abi::driver::loader` (`DriverLoadError`), so the safe `dlopen`/`dlsym`/`dlclose` wrapper stays an unadopted seam (`DynLibFlags::EMULATOR` matches `beam_abi`'s mode; the dynamic `{open_error, Code}` tuple at `ERL_DE_DYNAMIC_ERROR_OFFSET = -10` is the floor's to own). **Dependency direction:** `beam_io` depends on `beam_abi`, so `beam_abi`'s own loaders cannot call this module — a consolidation would move the wrapper **down** into `beam_abi` and re-export it here.
- **The `erl_ddll` error taxonomy is duplicated OUTSIDE this crate (report — not fixable here).** A full atom+code+message copy lives in `crates/beam_bifs/src/runtime/ddll.rs` (`ERRCODE_ERRORS`, `CODE_ERRORS`, `DYNAMIC_ERROR_OFFSET`) and a partial one in `crates/beam_abi/src/driver/loader.rs` (`DriverLoadError::reason_atom` + its message consts); the recommended single owner is `beam_abi` (re-exported by `beam_io::ddll`), but `beam_bifs` does not depend on `beam_abi`, so that choice adds a `beam_bifs → beam_abi` DAG edge and the zero-new-edge alternative is the LCA `beam_common` — an **owner decision + a `CHANGE.md` entry**, not this node's. Artifact-validity validation itself is correctly single-owner per kind (driver: `beam_abi::driver::loader::load`; NIF: `beam_abi::nif::loader::load`) and `beam_io::ddll` validates no entry.
- **The `file:*` API belongs to `beam_rt`'s `prim_file` floor, not to this driver.** The `efile` driver offers the driver-level verb set, but `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`; the driver returns the raw errno and the raw byte stream, so a `file:open/2`+`read/2`+`write/2`+`position/2` route onto it would still owe the `{error,atom}` rendering and the `FileDataMode` → binary/string rendering (`EfileDriver::data_mode`).

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A new `access(2)` use belongs in `src/fs_access.rs`, never as a second `unsafe` wrapper.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`.
  When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks` (keys are port *numbers*, `PortId::number()`).
  To be woken by a handled OS signal, register `SignalFacility::read_fd()` with the poller.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`) — do not close them elsewhere; `EfileDriver` composes an `FdDriver`, so the same rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP and restore it.
  `SignalFacility` test raises are thread-directed — the facility is process-global, so serialize tests on a shared `Mutex`, raise to the process with `kill(getpid(), …)` or, where deterministic delivery is needed, use `pthread_kill(pthread_self(), …)` (POSIX delivers a target thread's pending signal before it returns).
