# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Drivers, io-device Requests, Signals, CPU time, ddll
## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.
Hosts the `mio`-backed **poller/reactor**, the **`Port`** (a process-like I/O endpoint over a `Box<dyn Driver>` + two byte queues), **port-task scheduling** (`erts_port_task_execute`), the **io-device request layer**, the **`Driver` trait + built-in drivers**, the **driver C-ABI host layer** (`src/abi/`), and the safe raw-OS floors `beam_rt` (`#![deny(unsafe_code)]`) cannot issue itself (signals, CPU time, `ddll`, `fs_access`, `close_fd`).
A close is **asynchronous**: a port whose output queue is not empty when it is closed parks in `PortState::Closing` and the port layer finishes the teardown on the rounds that follow (`Port::close` → `PortRegistry::finish_closing_ports`).
Four driver→owner side channels sit beside the port's own `{Port,{data,…}}` notification: `{line,N}` frames (`LineNotification`), completions (`PortCompletion`), `{active,…}` deliveries (`ActiveInput`) and the failure latch (`PortFailure`); the grants a delivery *spends* come off a drain beside them (`ActiveSpend`), and a driver's live `{active, Mode}` is read through `PortRegistry::active_mode`.
`beam_rt` is the only consumer: it owns the poll loop, the port run queues and the scheduler thread, drives one long-lived `Poller` + `PortRegistry`, renders those drains plus the once-only `take_exit_status`/`take_eof` as the owner's messages, and wakes a blocked receiver through `beam_process`. `DynLib` is the one facility here with no consumer outside this crate (*Handoffs*).
## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed — rustdoc carries the signatures, and port-level mechanism/per-suite detail is `src/CONTEXT.md`.
### `poller.rs`
`Token(usize)` (— **token `0` is the waker's**, users start at `1`) · `Interest` (`READABLE`/`WRITABLE`/`BOTH`/`ERROR`, **no empty mask**) · `Ready` — observed readiness, **no public constructor** · `Event` (`token`/`key`/`ready`).
- **`Interest::ERROR` is caller intent, never a registration request**: no backend takes an error request (`erl_poll.c`'s `ev2pollev` maps only `IN`/`OUT`), while epoll/kqueue and the `poll(2)` fallback report error readiness unconditionally — the delivery half is `Ready::is_error()`.
- `Poller` owns `mio::Poll` **and the single `mio::Waker`**; `poll(timeout)` answers an **owned `Vec<Event>`** (`None` blocks) and is **`EINTR`-tolerant** — an `Interrupted` wait is retried with the **deadline preserved**.
- **Edge-triggered (`EPOLLET`)**: a readable descriptor must be drained to `EAGAIN` (each driver's `ready_input`/write-pending job); fd registration is Unix-only (no iocp, as in `beam_abi`).
- Regular files are refused by epoll (`EPERM`), so `register` keeps a `libc::poll(2)` fallback set merged into `poll`'s answer, capped (`FALLBACK_POLL_CAP`, 1 ms) so a non-empty set never blocks.
### `timer.rs` / `queue.rs`
`Timeout` (`Copy`) — one deadline · `Timer` — deadlines keyed by `u64`, self-contained (nothing in-crate consumes it): `schedule` replaces **any** deadline for a key, `pop_expired` answers due keys in **schedule** order · `ByteQueue` — `front()` is always contiguous.
### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reds: `CONTEXT_REDS` is `beam_common::CONTEXT_REDS` (4000), re-exported (no local copy); `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = 40`, `PORT_REDS_EXECUTE = 1000`; `PortTaskOutcome::reds_used` models the per-kind cost only.
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout) · `PortTask` · `PortTaskQueue` — **one pending task per kind**, ordered by kind **priority only**; `arm_timeout` re-points/replaces a pending `TIMEOUT`. Documented divergences: a not-yet-due `TIMEOUT` stays queued (the C dequeues, charges 0 reds and drops), and the single priority-ordered queue replaces the C's three unprioritised FIFOs (visible only in the order two *different* kinds run in a round).
- `Readiness::read_ready()`/`write_ready()` both fold a poll **error** in (an error re-triggers **every** armed direction, the C's `ERTS_POLL_EV_ERR`); a full close reports both, so a read-only driver never gets a bogus OUTPUT task.
- `ReadMessage { header, body: Option<Vec<u8>> }` — one completed read with the C `driver_output2` split kept: one `ReadMessage` is one **`driver_output*` call**, never a byte chunk; `body: None` is the C's `buf == NULL`, `Some(vec![])` a present empty body.
- `PortNotification::Data { port, read } | Closed { port }` — **exactly two variants** (exhaustively matchable by `beam_rt`): one `Data` per `driver_output*` call in arrival order, and an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** `{line,N}` channel, a struct so `PortNotification` stays exhaustive; `header` is the completing read's `ReadMessage::header`, prepended as cons cells to **every** frame that call completes.
- `ActiveInput { port, event }` / `ActiveInputEvent { Data(ReadMessage), Passive, Error(InetReason) }` — the **separate `{active,…}` input channel** (built like `LineNotification`, so `PortNotification` keeps two variants and `CompletionEvent` gains none); `Passive` is a spent `{active,N}`, `Error` a read failure, and none carries an atom — the runtime picks the message from the driving port's driver name.
- `ActiveMode { False, True, Once, Multi { remaining: i16 } }` + `ActiveSpend { Once, Multi }` — the machine's **state seam**: `ActiveMode::from_parts(active: i32, active_count: i16)` is the **single** home of the C's `INET_PASSIVE`/`INET_ACTIVE`/`INET_ONCE`/`INET_MULTI` = `0/1/2/3` encoding, `is_active()` is the C's `active > 0` on the **mode** field, `remaining()` is the **running** `active_count` (`Some` only for `Multi`). A spend is a grant a delivery exhausted: `Once` flips the mode **silently** (no passive message), `Multi` reports a counter that hit zero, `True`/`False` are never spent. Published through `Driver::active_mode`/`Driver::take_active_spends`.
- `PortTaskOutcome { ran, reds_used, notifications }` — `notifications` carries `PortNotification`s only; every other channel has its own drain.
### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` · `PortControl::CLOSE == "close"` (the one **reserved** control-op name; any other name is a driver verb) · `PortCommandOptions { nosuspend, force }` — the `erlang:port_command/3` flag set, carried through every retry of a suspended command.
- **`PortState::Closing` is a real, observable state**: `is_closing()`/`is_closed()`/`output_len()`, `CLOSING_DRAIN_STALL_LIMIT` (16). `Port::close` is two halves — **begin** (`driver_flush()`, then a synchronous `drain_output_during_close()` under one budget through the ordinary output-task path, a pending `INPUT`/`TIMEOUT` task dropped first because a closing port has no owner left) and, only when the queue emptied, `finish_close` (driver `stop`, then `Closed`; a `stop` failure still leaves it `Closed`, so it can never look open again).
- A queue that is **not** empty **parks** the port in `Closing` with an `OUTPUT` task pending and its poller registrations armed; `stop` has not run and the port stays in the registry. `note_closing_drain()` compares each round against the port's `closing_watermark` and gives up after `CLOSING_DRAIN_STALL_LIMIT` consecutive no-progress rounds (a **refused write counts as no progress**; a slow drain is never cut off). A second `close` on a `Closing`/`Closed` port is an idempotent `Ok(())`.
- `PortCommandOutcome { Done, Busy }` + `Port::command(&mut self, data, options)` — the C's `erts_port_output` busy arm and **the one place the decision table lives**: non-`Open` (a parked `Closing` included) ⇒ `BadArg`; `[force]` **without** `DriverFlags::SOFT_BUSY` ⇒ the typed `notsup` raise, from the driver's **flag word** and **before** any output; `[force]` **with** it ⇒ `Done`, busy bypassed; idle ⇒ `Done`, bytes queued plus one `OUTPUT` task; busy with a plain or `[nosuspend]` command ⇒ `Busy`, nothing queued, no task.
- Driver-state accessors are plain forwards: `is_busy()` · `port_closed()` (a **latched, sticky** peer/OS close, so a drain made a round late still sees it) · `active_mode()` (with the **running** counter) · `awaits_callers_async_op()` · `take_active_spends()` (**oldest first**, consumed on take and **unstamped**; the registry's form is stamped).
- `Port::driver_as::<T>()`/`driver()` are the read-only views (the downcast is the accepted-socket adoption's route to a listener's driver). `PortControlReply { bytes, shape }` is the whole `erlang:port_control/3` reply; `ControlReplyShape` and the shape/bytes/flag matrix are stated once, in `driver.rs`.
- **Every driver interaction — `start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`drive_async`/`port_exit`/`flush`/`stop` — installs all four sinks** (`with_reads`/`with_completions`/`with_active`/`with_failure`), the timeout and flush paths included because both discard the driver's `Result<()>` and a `flush` may hand a final completion up; the seven that can plan I/O refresh the port timer from `Driver::next_timeout`. A write (`output`/`ready_output`) is **verified**: the queue must shrink by exactly the count the driver reported (else the typed `error::unsupported(...)`), and a non-empty queue left behind schedules an `OUTPUT` task.
- Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (`Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof` point; a `close` never flushes). A round harvests raw-mode input as ≤1 `PortNotification::Data`; in line mode it stages `LineNotification` frames instead (`src/CONTEXT.md`).
### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number; `port_table`/`port_table_mut` expose that **same** id table.
- `close` runs `Port::close` and removes the port from the live map **only when it really finished** (`is_closed()`), harvesting what its teardown staged; a **parked** port stays live with its number, descriptors and poller registrations. A port's **number** retires only when its `Closed` notification is reported, so a deferred `Closed` can never name a reused id. `is_closing(id)` answers whether `close` parked it; `awaits_callers_async_op()` whether **any** live port owes a parked caller an answer (keys snapshotted first, no driver context touched).
- A private `finish_closing_ports` runs from **both** round drivers (`execute_port_tasks`, `handle_events`) **after** `reap_failures` and **before** the closed drain, so a port whose queue empties this round is reported `Closed` in that same round: it re-drains each live closing port, then finishes it (`stop`, removal, queued `Closed`) or leaves it parked. `reap_failures` uses the forced `close_now` instead — a failed driver's queue is **dropped**, not drained.
- Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round) and `execute_port_tasks` (port-number order under a reduction budget; async completions driven *before* input is harvested) — or `schedule_events`/`schedule_readiness` to enqueue only, gated by `PortArms`; `port_command_with` (the registry surface of `Port::command`; the write itself belongs to the scheduled `OUTPUT` task) and the legacy `port_command` (keeping its `Result<()>`); the accessors `is_busy`/`port_closed`/`active_mode`/`is_closing`/`awaits_callers_async_op`; `port_control` (reserved `"close"`; **any other `op`** goes verbatim to `control(op, arg)`); `take_exit_status`/`take_eof`; the timer seams; `notify_port_exit` (`Driver::port_exit` **at most once**, port left live); `drive_async`; `set_line_mode`/`flush_linebuf`; `take_failures` (the ports a driver closed from inside a callback, in reap order).
- The four owner drains share one rule — drain after **every** round, after **every** explicit driver interaction and after **every** `close`, because draining is what removes the entries: `take_line_notifications` (in **port-number order**), `take_completions`, `take_active_inputs`, `take_active_spends`, each followed by its `closed_*` queue that the removal fills — the spend queue **after** the driver's `stop`. A completion, delivery or spend staged before or at a `close` is reported **exactly once**.
- `port_control_reply(..)` is `port_control`'s reply **with** its `ControlReplyShape` (the reserved `"close"` arm answering an empty `Buffer` — no driver ran, no reply pointer existed); `control_reply_shape(id)` reports the last reply's shape alone; `port_control` keeps its `Result<Vec<u8>>` shape.
### `port_failure.rs` / `completion.rs` — the two side channels beside `PortNotification`
`PortNotification` keeps two variants and `PortCompletion` stays an owner message, so a driver that *closes its own port* and a driver that reports an *asynchronous outcome* each get a channel of their own.
- **Failure** (`port_failure.rs`, the C's `driver_failure*`/`driver_exit`): `FailureReason { Eof, Normal, Atom(String), Posix(i32), Code(i32) }` with `atom_name()`/`code()`/`is_eof()` (the flag that makes a `{line,N}` port flush its partial line first) · `DriverFailure { reason, signals_owner }`, where `signals_owner` is `false` only for `driver_exit`, which unlinks the owner **before** closing, so an `'EXIT'` would invent a message the oracle never sends. Flow: `DriverContext::signal_failure` latches **exactly one** (the three `deliver_*` seams refuse afterwards, the C's `-1`), `Port::take_failure` collects it, and `reap_failures` tears the port down through `close_now` after the callback returned — `stop` runs, the port leaves the live map, already-staged input is reported ahead of the close, and the number retires only with the deferred `Closed`. Both round drivers reap at their end, and `output`/`port_control`/`drive_async`/`notify_port_exit` right after the single callback they made.
- **Completion** (`completion.rs`): `PortCompletion { port, event }` — the port id stamped by `DriverContext::deliver_completion`, never by the driver · `CompletionEvent { InetReply { caller_ref, reply }, InetAsync { id: u16, result } }` (the `{inet_reply, Port, Reply[, Tag]}` and `{inet_async, Port, Id, Result}` shapes) · `InetReply { Ok, Error(InetReason) }`, `InetReason { Closed, Timeout, Errno(i32) }` (`atom_name` = the lowercase POSIX name, with the C's `errno_<N>` fallback) · `InetAsyncResult { Ok, Data(ReadMessage), Accepted { fd }, Port(PortId), Error(InetReason) }`, whose `Data` keeps the header/body split and whose `Accepted` hands the descriptor over **owned**, so no teardown path can close it. `caller_ref` is the `prim_inet` caller tag carried **verbatim** (a 131-led `term_to_binary(Mref,[local])` image), never decoded here.
### `driver.rs`
- `DriverFlags(u32)` (`SOFT_BUSY`) · `PortExitReason { Closed, OwnerExited, Normal }`. `SOFT_BUSY` **membership**: `tcp_inet` advertises it, `udp_inet` and `ram_file_drv` do not — so `erlang:port_command/3` with `[force]` is the oracle's `notsup` on those two and `true` on `tcp_inet`.
- **`ControlReplyShape { Null, Buffer }` is the second fact a `control` reply carries, which the bytes alone cannot** (stated once, here; cross-referenced from `port.rs`/`registry.rs`): `Null` is the C's `*rbuf == NULL` (`*rbufp` tested **first**, `io.c:4134`), answered as the empty **list** for **every** flag word; `Buffer` is a real reply buffer, so zero bytes under `PORT_CONTROL_FLAG_BINARY` is `<<>>`, zero bytes without it is `[]`, and a non-empty reply is a list, or a binary under the flag. Reported by the **defaulted** `Driver::control_reply_shape()` (`Buffer` — honest for every built-in) and overridden only by `abi::DriverPort`, the one holder of a foreign reply pointer.
- `DriverContext<'a>` — the driver's view of its port and **the only way it touches the poller or the queues** (`register`/`reregister`/`deregister`/`input`/`output`; keys are the port number). Four delivery seams, each the typed `unsupported` without its sink (never flattened, never dropped) and each refusing once a failure latched in the same callback: `deliver_read(header, body: Option<&[u8]>)` (the `driver_output2`/`output_binary`/`outputv` seam; bytes banked on `input()` close into their own body-only read **first**) · `deliver_completion` · `deliver_active_input` (stamped with this context's port, in call order) · `signal_failure` (a request, never a teardown).
- `pub trait Driver: core::any::Any` — **frozen**, with the one downcast path `impl dyn Driver { pub fn downcast_ref<T: Driver + 'static>(&self) }` (trait upcasting to `&dyn Any`: no `unsafe`, no `as_any` boilerplate, every driver `'static`). Required: `name()` (+ `flags()`), `start`, `output`, `ready_input`, `stop`.
- Defaulted members that carry a contract: `has_control()` (**`false` iff the driver's C counterpart has `control == NULL`**, e.g. `ram_file_drv` — then `port_control/3` is the oracle's `badarg`) · `is_busy()` (the `set_busy_port` **state**, `false` for every built-in, overridden by `abi::DriverPort`) · `port_closed()` (a **latched, sticky** peer/OS close, for the runtime to render as `{tcp_closed, Port}`) · `active_mode()` (`ActiveMode::False`) · `take_active_spends()` (an empty, allocation-free `Vec`) · `has_pending_async()` (the **drive** gate) · `take_exit_status()`/`take_eof()` (only `SpawnDriver`). Further capabilities must be additive with defaults that keep the built-ins compiling.
- `flush(&mut self, ctx: &mut DriverContext<'_>) -> Result<()>` — additive **defaulted** (a no-op), the C's `drv->flush` (`io.c:3659`, slot test at `:3664`, call at `:3687`). Called **once** from `Port::close`, after the port entered `Closing` and **before** the output drain, so what it leaves in `ctx.output()` is what the drain writes; a discarding flush takes the bytes off the queue itself and no count is verified (the C's `flush` is `void`). **Three overriders**: `TcpInetDriver` — the only discarding one, `discard_output = !(token.is_some() && interest.is_writable()) || options.linger_zero` then `ctx.output().clear()` · `SpawnDriver` — latches `terminating` only (the C's `fd_flush`) · `abi::DriverPort` — forwards the loaded entry's slot. `FdDriver`, `RamFileDriver` and `UdpInetDriver` inherit the no-op deliberately (a NULL C slot).
- `awaits_callers_async_op(&self) -> bool` — additive **defaulted**, the wait predicate split from the drive predicate: default `self.has_pending_async()`. `TcpInetDriver`/`UdpInetDriver` answer their queued-op probe (**accept-inclusive** — a queued `accept` carries a real caller's `{inet_async,…}`); `abi::DriverPort` answers `false` (a `driver_async` job completes in the driver's own `ready_async`). The drive gate stays `has_pending_async()`.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>` · `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers `"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`.
- **The statically-linked (emulator `driver_tab`) set is a separate, narrower contract** — `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` + `is_static_spawn_driver`, `with_static_spawn_drivers()` and `create_static_spawn(name)`, which refuses a name outside the set with `BeamError::BadArg` (the oracle's `badarg` for `open_port({spawn_driver,"fd"},[])`) **even on a `with_builtins()` registry that registers them** — exactly the oracle's `erl_ddll:loaded_drivers/0` answer.
### `drivers/` — the built-in drivers
Roster, all `Driver`/`DriverContext`-only, each owning the descriptors it was given: `fd` (`FdDriver`, byte stream) · `efile` (`EfileDriver`, byte movement delegated to a composed `FdDriver`, `make_efile()` its factory) · `spawn` (`SpawnDriver`, **the only module in this crate that may spawn OS children**, constructed from a `SpawnSpec` and really spawning in the constructor) · `ram_file_drv` (`RamFileDriver`/`make_ram_file`, command-driven `Vec<u8>` "file") · `inet/` (`tcp_inet` stream + `udp_inet` datagram, one socket behind one port).
Verbs, `{line,N}`/phase framing, the option vocabulary, constants and every per-driver suite: `src/drivers/CONTEXT.md` (+ `src/drivers/inet/CONTEXT.md`). The rules a crate-root reader needs:
- Only `drivers/spawn.rs` forks/`execve`s (*Constraints*).
- `tcp_inet`'s write path frames **once per command**, at queue time and after the connection guard: the `{packet,1|2|4}` header announces the **payload** length after the `prim_inet` caller-tag strip, and `stat.send_oct` counts header + payload; `udp_inet` frames nothing. The queue is one byte stream with **no per-command boundary**, so a command queued behind a stalled partial write is never re-framed or re-counted (*Known Issues*).
- **The read path: a complete buffered unit wins over a pending peer close**, and only a read the C *would* have made may apply one (*The inet read path past a peer close*).
- **The `erlang:port_control/3` opcode bridge** (`inet/opcode.rs`): an integer `Op` reaches the driver as its **decimal string**, is accumulated mod 2³² and `wrapping_sub(CONTROL_MAGIC_NUMBER = 0x03f1_a300)`-ed, then dispatched by the C's three switches onto the **same** verb bodies the named form uses, so both routes answer identical bytes. A number no entry owns — a case of the other driver's switch, and every op below the magic (`"1"`, `"99"`) — answers the C's `[0]exbadport`; an opcode the C serves but this floor does not is the typed `not_served()` raise. The **operand** decode is the caller's (*Known Issues*).
- **A.4 residuals** (a typed refusal or a refusal-only arm, never a wrong result): the improper `[hdr|<<body>>]` DATA reply renders through `ReadMessage`; `INET_REQ_FDOPEN`'s prebound descriptor is never closed (borrowed, port-lifetime); `ignorefd`/`tcp_sendfile` reproduce their refusals only.
### The inet read path past a peer close (the `ReadReport` selection rule)
The C selects a socket's read side in exactly **two** states — a granted `{active,…}` (`sock_select(desc,(FD_READ|FD_CLOSE),(desc->active>0))`, `inet_drv.c:7966`) and a waiting `TCP_REQ_RECV` (`:12317`) — so every read it makes is one somebody answers, and `ReadReport::Answered` (a queued `TCP_REQ_RECV`, the `recv` verb, an `{active,…}` delivery) **applies** the close it finds.
This floor's poller also reads a **passive** socket with no receive queued — a delivery shortcut for `{Port,{data,…}}`, not a discovery — so that read is `ReadReport::Unselected`: it delivers its bytes, **records** the close in `TcpInetDriver::pending_close` and applies **nothing** (no `delayed_close_*`, no teardown), leaving the close owed to the first read the C would have made.
Hence `{Port,{data,…}}` still precedes `{tcp_closed,…}` and the `tcp_recv_closed`/`tcp_recv_error` reply ladder is unchanged in the selected case; `pending_close` is sticky (a reset is reported once), cleared only by the latch, and `latch_peer_close` is the **single** latch site. Per-site split and oracle-measured consequences: `src/drivers/inet/CONTEXT.md`, `src/CONTEXT.md`.
### The inet write path after `gen_tcp:shutdown(S, write)`
`shutdown/2` only **records the intent**: the socket is not closed (state stays `{ok,[connected,open]}`, `GETFD` still answers) and zero-length sends answer `ok` **for ever**, because the two one-shot ladders are armed by the **first failing write**, never by the shutdown — the first non-empty send answers `{error,closed}` and every later one `{error,enotconn}`.
The full answer matrix, the command-accounting invariant (`InetStat::output` counts a **command**, not a write, so a zero-length command advances `send_cnt` and adds nothing; `send_pend` is the port's own output-queue depth, rendered at `inet:getstat/1` time) and their pins (`src/drivers/inet/write_shutdown_matrix_tests.rs`, `stat_send_tests.rs`'s `RAW_ROWS`, the differential corpus's `inet_write` group) are `src/drivers/CONTEXT.md` › *The inet write path — the answer matrix and the accounting invariant*.
### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code. Modules: `host.rs` (`PortHost`/`AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, preferring the entry's **`outputv`** on both write paths, forwarding its `flush` slot, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` **implements** `beam_abi::DriverHost::set_busy_port` (records the per-port `DriverState::busy`, answers the C's `0`; read back via `AbiHost::is_busy`/`DriverPort::is_busy`) and exposes `queue_head` (the safe `&[u8]` companion of the raw `driver_peekq` hook); `DriverPort::control` reports a `*rbuf == NULL` reply as `ControlReplyShape::Null` instead of `badarg` — the one place that can. Detail: **`src/abi/CONTEXT.md`**.
### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
`Encoding { Latin1, Unicode }` (any other name — a tuple encoding, … — is refused, never guessed) · `ByteSource` (`read_chunk(size) -> Result<Option<Vec<u8>>>`, `None` = eof) · `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`, whose request is `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>`; the `Continuation` seam (`Continuation`/`ContData`/`Applied`/`Leftover`) is the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])`, with `NoEngineContinuation` as the not-installed default (every `apply` is the typed `unsupported` naming the missing `erl_scan:tokens/4`, never a fabricated reply). Device loop, transcode clauses, `invalid_unicode` stop: **`src/io_device/CONTEXT.md`**.
### The five raw-OS floors and the errno table
`signal.rs` — `Signal` (the twelve `os:set_signal/2` accepts; `sigttin`/`sigttou` are **not**), `Disposition { Default, Handle, Ignore }`, `SignalFacility::set` (`sigaction(2)`, **empty `sa_mask`**, **`SA_RESTART`**)/`read_fd()` (the runtime registers it and owns the token)/`drain()` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order). The handler is **async-signal-safe** — one atomic bitmask OR swapped *before* the pipe is drained (a signal landing in that window is deferred, never lost) plus one `libc::write` whose byte count is **not** the source of truth; the facility is **process-global** (one alive at a time; `Drop` restores every prior disposition) and unix-only, and `SigStop` is **kernel-only** (typed `BeamError::Io`; the consumer answers `ok`).
`cpu_time.rs` — `CpuTimes { user_ms, system_ms }` in whole **milliseconds** (µs ÷ 1000, truncating); `process_cpu_times()` (`getrusage(RUSAGE_SELF)`) **is** the C's `erlang:statistics(runtime)` measurement (`thread_cpu_times()` is not what that BIF uses); `RuntimeClock` is the `(Total, SinceLastCall)` counter, so the **first** call returns two equal elements and **system time is not used**, and a failed `getrusage` is the typed `BeamError::Io` leaving the anchor **unchanged**.
`ddll.rs` — `DynLib` (an owned `dlopen(3)` handle: `open`/`open_with`/`open_cstr`, `symbol`/`try_symbol`, `Drop` closes exactly once, deliberately no `into_raw`/`from_raw`, not `Send`/`Sync`) + `DynLibFlags` (`EMULATOR` = `RTLD_NOW | RTLD_LOCAL`, the default and the mode `beam_abi`'s loaders use; `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`), and the `erl_ddll` reason vocabulary `DllError { kind, text }`/`DllErrorKind` with `errcode` **derived** from the single `ERRCODE_TAB` (the emulator's `errcode_tab`, byte-for-byte), **no** `.so` suffix appended and classification **text-based only** (a failed `dlopen` does not set `errno` reliably).
`fs_access.rs` — `try_access(&Path, AccessMode)` is the crate's **one `access(2)` call site**, errno-preserving (`Ok(())` iff the kernel grants the mode; `Err(BeamError::Io(err))` with the untouched errno on refusal, `EINTR` retried; `BadArg` for an interior-NUL path); `access(..) -> Result<bool>` makes a **refusal** `Ok(false)`; `path_access(&Path)` is the `#file_info{}` `access` slot (two **independent** probes) and `process_credentials()` the **effective** ids `check_access` compares a `stat` against.
`close_fd.rs` — `close_fd(RawFd)` (an `EINTR`-retried `close(2)` that reports `EBADF` instead of swallowing it) and `OwnedFd` (closed exactly once; `into_raw` hands ownership to a driver): the crate's **safe, public** close primitive for a descriptor the *runtime* owns or declines to adopt (an `InetAsyncResult::Accepted` socket), not the crate's only `close(2)` — each driver closes the descriptors it owns.
`error.rs` — `ERRNO_NAMES` (**61 rows**) is the one errno→name table; `errno_atom` is the `Option` form (unrecognised ⇒ `None`, never an invented atom), `errno_name` the `[0] ++ Name` form the inet replies carry with the C's `errno_<N>` fallback, and `EOPNOTSUPP` renders **`enotsup`**. `drivers/inet/wire.rs::errno_name` forwards here and `InetReason`/`FailureReason` both read it, so no second table exists.
## Constraints
- Errors: **`beam_common::{Result, BeamError}` only** — I/O/syscall ⇒ `BeamError::Io`, argument faults ⇒ `BeamError::BadArg`, id/registration exhaustion ⇒ `BeamError::SystemLimit`. Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`dup2`, the inet `setsockopt`/`getsockopt`, `getrusage`/`clock_gettime`, `pipe2`/`sigaction`, `dlopen`/`dlsym`/`dlclose`, `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling; every block carries a preceding `// SAFETY:` rationale and `unsafe_op_in_unsafe_fn` stays clean.
- **Edge-triggered byte path**: every `ready_input`/write-pending drains to `EAGAIN`; a short write leaves the exact unwritten remainder queued and arms write readiness; a short read never drops or duplicates bytes (`ByteQueue::front()` is always the whole contiguous remainder).
- **Port ids come from `beam_process::PortTable`** — no second number allocator; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number, so no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; `DynLib` likewise (`Poller`/`Waker` are exempt — the waker must cross threads; `SignalFacility` is process-global).
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **A `Closing` port must always be able to finish**: whatever a drain does — a short write, a refused write, a driver that never consumes — the close completes, the park bounded by `CLOSING_DRAIN_STALL_LIMIT` and the teardown (`flush` → drain → `stop` → `Closed` → number retirement) run exactly once per port.
- **The `Driver` trait, `DriverContext`'s public methods and the `Port`/`PortRegistry` signatures are the frozen driver seam**, extended only by **additive, defaulted** members that leave every existing implementor and call site behaving as before — never by changing an existing signature. Files target ~1000 lines. Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only (*Design Decisions* has the `beam_io → beam_abi`/`beam_alloc` edge).
## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` **GREEN**, and `... build --workspace --all-targets` **GREEN, warning-free**. The wrapper is mandatory — the sandbox `$HOME` is read-only, so cargo's default `CARGO_HOME` is unusable.
- **No counts here**: lib suites sit beside their module (`src/CONTEXT.md`, `src/drivers/CONTEXT.md`, `src/abi/CONTEXT.md`), integration suites and their `cc` fixtures in `tests/CONTEXT.md`.
- A suite needing `cc`/`erl_driver.h`/`erl` **skips loudly** (`SKIP:` banner + early return) and never fails; fixtures are built by the test binary itself; every oracle comparison is **byte-exact**.
- A wait is a **condition under a hang guard** — never a fixed sleep, never `waitpid(2)` from a test (the spawn driver reaps eagerly and caches its status).
- Pinned properties: the parked close + the `flush` seam (at the `Port` level, over the byte-stream and command drivers, and over `cc`-built C drivers), the busy-port decision table at both levels (plain-Rust driver and real C driver), `{packet,N}` write framing on **both** write routes through `PortRegistry`, the `{active,…}` mode/spend seam, and the `inet` option/control surface byte-compared against the live oracle whenever `erl` is on `PATH`.
## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` behind a **mio-independent** API (`RawFd` + `Interest`/`Token`/`Ready`), so another backend could be added later (io_uring/`/dev/poll` is **not implemented today**).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **The parked close is the C's Limbo state, with a valve of our own.** A close with a non-empty queue goes through `flush_port` → `ERTS_PORT_SFLG_CLOSING` and finishes at the driver-callback epilogue, which is why `PortState::Closing` exists: the bytes are the caller's and must still be written. The C has **no bound** there, but this port layer must always be able to complete a close, so `CLOSING_DRAIN_STALL_LIMIT` (16 consecutive no-progress rounds, any shrinkage resetting the count) is a **documented divergence** — without it a driver that cannot write a byte would hold the port number, its descriptors and its poller registrations indefinitely and the owner would never be told. A slow drain is never cut off.
- **Task execution here, the scheduler thread above**: the poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver, and a poll **error** reaches both armed directions (C parity).
- **The spawn driver is constructed, not registered, and reaps eagerly**: a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (a failed spawn registers nothing, `os_pid()` readable before `PortRegistry::open`); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it.
- **The TCP/UDP drivers are a floor, not a full `inet`** — served verbs, framing types and the `{active,…}` matrix are oracle-cross-checked (`src/drivers/inet/CONTEXT.md`).
## Known Issues
- **`FdDriver` is deliberately minimal** (byte-stream only; no output line framing, no packet framing) and **`SpawnDriver` is the OS-child floor**, not the whole `spawn` driver — synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` from its bytes, latched EOF and once-only exit status is the runtime's job. Per-driver limits: `src/drivers/CONTEXT.md`.
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes: packing `erlang:port_control/3`'s `Data` term into the C's request payload is the runtime's job, while an integer `Op` is forwarded as its **decimal string** and decoded by `src/drivers/inet/opcode.rs`. The `INET_REQ_*` surface, its guard order and its refusal-only arms are `src/drivers/inet/CONTEXT.md`'s.
- **The inet drivers' `port_command/2` path adopts the failure seam; the `init_caller` rule is size-only** — the tag's bytes are **never inspected**, so a *plain* payload reads as a huge length and is the C's `FALSE`. The four oracle-measured rows (malformed, socket-less/unconnected, empty queue, empty/non-ETF tag) are `src/drivers/CONTEXT.md`.
- **A completion is addressed to the port's owner, not to the C's `driver_caller`** — the C sends to `desc->caller`; rendering and delivering is the runtime's (*Handoffs*).
- **The busy-port decision table is the whole of the flow control this crate owns.** `Port::command` owns it (`PortRegistry::port_command_with`/`is_busy` expose it); the **caller-blocking** half of a plain command on a busy port (suspend the caller, re-issue once the driver clears the state, answer `true`) needs a process this crate has none of, so it lives in `beam_rt` (`crates/beam_rt/src/port/busy_wait.rs::issue`).
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` callbacks are `void`.** Counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`); do not "fix" it into a remainder.
- **The output queue is one byte stream with no per-command boundary.** The `{packet,1|2|4}` header and the `send_oct` charge are decided **once per command**, at queue time and after the connection guard, so a **second** command queued behind a still-stalled partial write is not framed or counted independently — its bytes land behind the first command's remainder, where the framing and accounting latches are still set. The `prim_inet` caller-tag strip shares that property, exactly as the C's single `ioq` plus its one `tcp_sendv` call per `port_command` do.
- **Driver-readiness residuals.** `DriverState::fd_armed` hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a multi-fd port would starve the others (harmless today — one fd each). A `{fd,N}` spawn port keeps an `Interest::BOTH` registration for its life, so a spurious `OUTPUT` task is scheduled on every write-readiness event.
## Handoffs (beam_rt — out of this node)
**Adopted upstream:** `{line,N}` framing (`set_line_mode` + `take_line_notifications`), the completion channel (`take_completions` → `crates/beam_rt/src/port/completion.rs`), the failure channel (`take_failures` → `crates/beam_rt/src/port/failure.rs`), the `{active,…}` channel (`take_active_inputs`/`take_active_spends`/`active_mode` → `crates/beam_rt/src/port/active_input.rs`), the peer-close latch (`port_closed` → `crates/beam_rt/src/port/peer_closed.rs`), the control-reply **shape** (`port_control_reply`, rendered by `crates/beam_rt/src/native/port.rs::port_control`), the `#file_info{}` ids path, the signal and CPU-time facilities, `create_static_spawn`, the once-only `take_eof`, the port-monitor id table, the `{get_until,…}` io request, `ram_file_drv`'s port path, the busy-port caller-blocking wait, `erlang:port_control/3` and a refused command's `badarg`.
**A closed port is not gone at `close`'s return.** A parked close leaves the port live (`contains`, `is_closing`, its poller registrations) and `erlang:port_command` on it is the C's `badarg`; the `Closed` arrives from a **later** round and the number retires with that report, so `beam_rt` must keep its port-table entry and keep driving rounds (or read `is_closing`) until the `Closed` it drains names the port.
**The two async predicates: `has_pending_async` drives, `awaits_callers_async_op` waits.** `beam_rt`'s caller-blocking port wait reads the **drive** predicate (`crates/beam_rt/src/context/pump.rs::wait_for_port_event` → `Runtime::ports_awaiting_async` → its `PortRegistry::awaits_async_completion`, folding `Driver::has_pending_async` over the live ports) and counts delivered port events per round to detect progress, because a listener's standing accept interest must keep that wait alive — an answer being gone is caught by the delivery count, not the wait-side predicate.
**The busy-port flow control is complete on the `port_command` route.** `erlang:port_command/2,3` reaches this crate's decision through `PortRegistry::port_command_with` (`crates/beam_rt/src/port.rs::RuntimePorts::command_with_data`, its `decide_before_data` gate then `PortRegistry::command`); the caller-blocking half is `crates/beam_rt/src/port/busy_wait.rs::issue` — a caller owning the scheduler pass pumps bounded rounds until `is_busy` clears and re-issues, while a caller inside a slice parks (`PortWrite::Parked` → `BifOutcome::Suspend`, the instruction re-run on resume), the C's `erts_suspend` + `ERTS_BIF_YIELD3` re-run. **Residual:** the wait is bounded by a 5 s deadline where the C is unbounded (`BUSY_PORT_DEADLINE`), and the `send`-to-port route (`erlang:send/2,3` and the inline `Instr::Send`) cannot consume a suspend latch, so a plain command on a busy port there — like `RuntimePorts::write_command`, which holds no `Runtime` to pump with — stays the typed `NO_PUMP_REASON` gap.
**The control-reply shape is the fact the bytes cannot carry.** `PortControlReply { bytes, shape }` (`PortRegistry::port_control_reply`) is the whole `erlang:port_control/3` reply; the flag word is not part of it and the rendering is `beam_rt`'s (`crates/beam_rt/src/native/port.rs::port_control`). `control_reply_shape` reports the last reply alone and is `BadArg` for a port a driver reaped from inside its own `control` callback, so a caller that must not lose the shape takes the combined call.
**The failure channel: this crate latches and tears down, the runtime renders.** A driver closing its own port latches exactly one `FailureReason`; `reap_failures` runs the forced teardown after the callback returns and `take_failures` hands the term-free `PortFailure { reason, signals_owner }` up in reap order, the driver's `stop` already run and `Closed` already minted, with the bytes that callback delivered ahead of it (`take_reaped_notifications` re-prepends them). Rendering the owner's `{'EXIT',Port,Reason}` / every monitor's `{'DOWN',…}`, gated on `signals_owner`, is `beam_rt`'s (`crates/beam_rt/src/port/failure.rs`).
**The `{active,…}` channel: this crate produces the delivery, the runtime renders the message.** `take_active_inputs`/`take_active_spends`/`active_mode` answer one `ActiveInputEvent` per delivery with the header/body split intact, the grants spent and the driver's live mode with its running counter; the messages — `{udp, S, IP, Port, Data}` (the 7 packed header bytes split into `{IP, Port}`, one `INET_AF_INET` record, the only family served), `{tcp, S, Data}` under the port's `[list]`/`[binary]` shape, `{tcp_passive,S}`/`{udp_passive,S}`, `{tcp_error,S,Reason}`/`{udp_error,S,Reason}` with the atom chosen from the driving port's driver name — are `beam_rt`'s (`crates/beam_rt/src/port/active_input.rs`), as is the `{mode, list|binary}` decision. **Do not add a variant to `PortNotification`** and do not route these through `CompletionEvent`.
**The completion channel: this crate stages, the runtime addresses and renders.** `take_completions` answers one `PortCompletion` per event, port stamped by `deliver_completion`; `beam_rt` (`crates/beam_rt/src/port/completion.rs`) renders `{inet_reply, Port, Reply[, DecodedTag]}` (decoding the 131-led `caller_ref` with `beam_codec`) and `{inet_async, Port, Id, Result}`, and adopts an `InetAsyncResult::Accepted { fd }` into a **second** port (`TcpInetDriver::from_accepted(fd, listener)` or the served `INET_REQ_FDOPEN`) **or** closes it — `beam_io` never closes it. A **built-in** driver port has no term path (`PortMeta::driver_terms` is `None` for `PortName::SpawnDriverBuiltin`); `PortEvent::Term` exists only for `dlopen`ed driver ports.
**`driver_caller`.** The C sends `{inet_reply,…}` to the command's `desc->caller`; this floor stages it for the port's **owner**, so addressing the reply to the caller needs a caller notion the frozen seam lacks.
**The delivered-data term shape (`mode` list vs binary) and the `LineNotification` header stamp are the runtime's.** `PortNotification::Data` carries bytes while the C's `tcp_reply_data` builds the term from `desc->mode`; `beam_rt` matches `{ port, read }`, renders the oracle's improper-list shape and stamps a `LineNotification`'s `header` as the same cons prefix on `{eol|noeol, Data}`.
**`tcp_inet` peer close → `{tcp_closed, Port}`: this crate observes, the runtime reports.** `TcpInetDriver` latches it (`peer_closed()`, mirrored by `Driver::port_closed`, sticky; `recv`/`send` answer `[0]closed`/`[0]enotconn`), read once per port-task round beside the other driver→owner channels; `beam_rt` (`crates/beam_rt/src/port/peer_closed.rs`) gates the message on the driver's **live** `{active,…}` mode and then retires the port through the `driver_exit` route, so a grant a delivery spent stays silent and the report is at most one per descriptor.
**Two owner-facing messages are still missing — the real refusal-list gap:** a `send_timeout` expiry's `{inet_reply, Port, {error,timeout}}` (the option is stored, never armed) and `SUBSCRIBE`(24)'s later `{empty_out_q, Port}`; both are *missing messages*, not wrong values, so a caller waiting on either hangs, and neither has a channel today. The options (`{deliver, port|term}`, `send_timeout`, `send_timeout_close`, codes 25/30/35) are stored and reported byte-exactly, and `Getservby*`/`SUBSCRIBE`'s reply are **served**.
**`DynLib` has no consumer outside this crate.** `beam_rt`'s `erl_ddll` floor is built on `beam_abi::driver::loader`, so the safe `dlopen`/`dlsym`/`dlclose` wrapper stays unadopted; a consolidation would move it **down** into `beam_abi` (its own loaders cannot call this module).
**The `erl_ddll` error taxonomy is duplicated OUTSIDE this crate (report — not fixable here).** A full atom+code+message copy lives in `crates/beam_bifs/src/runtime/ddll.rs` and a partial one in `crates/beam_abi/src/driver/loader.rs`; the recommended single owner is `beam_abi`, but `beam_bifs` does not depend on it, so that adds a DAG edge whose zero-new-edge alternative is the LCA `beam_common` — an **owner decision + a `CHANGE.md` entry**, not this node's.
**The `file:*` API belongs to `beam_rt`'s `prim_file` floor, and no `beam_io` code is on that path.** The `efile` driver offers the driver-level verb set only; `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`, so routing `file:open/2`+`read/2`+`write/2` onto it would still owe the `{error,atom}` and `FileDataMode` renderings. Hence the `file_io` workload's whole-file and **raw-handle** (`[raw]` `read`/`write`/`close`) shapes touch **no port, no driver and no poller round** — a direct `prim_file` BIF call per operation, so a per-operation cost there is never this crate's. The one `file_io` case that *is* a port is `file:open(Name,[ram,…])`: `ram_file.erl` opens it as `open_port({spawn,"ram_file_drv"},Opts)`, the `{spawn,Cmd}` name form, whose first-token driver lookup belongs to `beam_rt`'s `open_port` classification (`{spawn_driver,Name}` reaches `create_static_spawn` here; `{spawn,Cmd}` does not). `HANDOFF_FILE_IO_PERF.md` carries the measured attribution and the exact `beam_rt` patch for both.
**Every other handoff is a child node's:** the driver/async-op/accept-family seams (incl. the datagram `{header,N}` impossibility and `INET_REQ_FDOPEN`'s documented non-mirror) are `src/drivers/inet/CONTEXT.md` › *Handoffs*; the io-device request's `{stop,…}` boxing and `Leftover` are `src/io_device/CONTEXT.md` › *Deviations from the oracle*, beside its `reply_get_chars`/`reply_put_chars` residual in *Handoff to `beam_rt`*.

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` and `../../CONTEXT.md` §1 A.4/§3 first. Build/test with `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A new `access(2)` use belongs in `src/fs_access.rs`, never as a second `unsafe` wrapper. A new descriptor close goes through `close_fd`/`OwnedFd` unless the driver owns that descriptor.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** so the driver and its context borrow disjoint fields; never add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks` (poller keys are port *numbers*). A handled OS signal wakes it through `SignalFacility::read_fd()`.
- A new owner-facing message goes on a **new** channel (a struct + a `DriverContext::deliver_*` sink + a `PortRegistry::take_*` drain, drained after every round *and* after every `close`), never as a third `PortNotification` variant and never as a `CompletionEvent` arm: `beam_rt` matches both exhaustively.
- Output queued before a close is **written, not dropped**: a driver that discards bytes on close must say so in `flush` (and consume them off `ctx.output()`), and must leave the queue alone when the port can still write them. `stop` runs only after the drain (or the stall bound), so it may assume an empty queue.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`) — do not close them elsewhere; `EfileDriver` composes an `FdDriver`, so the same rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the syscall's duration — build it from a local `let mut fd = fd;` inside the wrapper.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP, restore it, serialize on a shared `Mutex` (the facility is process-global) and raise thread-directed with `pthread_kill(pthread_self(), …)`.
## TCP accept state machine
The state machine is the child node's: the **sticky** multi-accept `INET_F_MULTI_CLIENT` bit behind `GETSTATUS`, the per-port sorted accept-timer list (the C's `desc->mtd`), the `[0]einval` ladder for every non-listening state and the arm/re-arm/disarm readiness cycle live in `src/drivers/inet/CONTEXT.md`, pinned by `src/drivers/inet/accept_tests.rs` + `tests/inet_accept.rs`.
The accepted descriptor is handed over **owned** (`InetAsyncResult::Accepted { fd }`), and the listener's option set comes across through `TcpInetDriver::from_accepted(fd, listener)` — this crate's implementation of the C's `tcp_inet_copy` (field-by-field inheritance list in the child node).
The seam exists: `PortRegistry::driver_as::<TcpInetDriver>(listener)` reaches the listener's concrete driver, and the accepted driver is opened as a second port (proven end to end by `src/drivers/inet/inherit_tests.rs`'s registry-route rows). The runtime must open that second port with **that** constructor rather than `from_socket`, and an `InetAsyncResult::Accepted { fd }` is either adopted that way **or** closed by the runtime.
