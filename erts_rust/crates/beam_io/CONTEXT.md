# `beam_io` — Poller/Reactor, Ports, Port-Task Scheduling, Drivers, io-device Requests, Signals, CPU time, ddll

## Intent
Owns the **I/O subsystem** of the Rust ERTS rewrite (Stage 5, Part II §H) and the **OS/driver seam** — a clean rewrite seam (Part II §A) reproduced with the *frozen* driver C ABI (workspace `../CONTEXT.md` §1 **A.4**): a driver `.so` compiled against the unmodified `erl_driver.h` links and behaves identically.
Hosts nine subsystems: the `mio`-backed **poller/reactor**, the **`Port`** (a process-like I/O endpoint over a `Box<dyn Driver>` + two byte queues), **port-task scheduling** (`erts_port_task_execute`), the **io-device request layer** (`src/io_device/`), the **`Driver` trait + built-in drivers** (`fd`, `efile`, OS-child `spawn`, `tcp_inet`, `udp_inet`, `ram_file_drv`, `{line,N}` buffering, the text⇄binary phase-change protocol), the **driver C-ABI host layer** (`src/abi/`), the **OS-signal facility** behind `os:set_signal/2` (the signal `unsafe` work `beam_rt`, `#![deny(unsafe_code)]`, cannot do itself), the **CPU-time facility** behind `erlang:statistics(runtime)`, and the **dynamic-library primitive** (`src/ddll.rs`).
The per-driver, `inet`, `abi` and `io_device` detail lives in the child nodes named by the Routing Table.

`beam_rt` is the only consumer: it owns the poll loop, the port run queues and the scheduler thread, drives one long-lived `Poller` + `PortRegistry`, and turns `PortNotification`s plus the once-only `take_exit_status`/`take_eof` into `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}`, `take_line_notifications` into `{Port,{data,{eol|noeol,_}}}`, and `take_completions` into the async/`{inet_reply,…}` messages — delivering each to the owning process and waking a blocked receiver through `beam_process`, which observes ports by id (the peer of pids in `ptab`). Every built-in driver, the signal/CPU-time/`fs_access`/ddll-floor and the io-device facilities are reachable from there; `src/ddll.rs`'s `DynLib` is the one facility with no consumer outside this crate (*Handoffs*).
## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_io::prelude::*`; only **frozen contracts and non-obvious behaviour** are listed, rustdoc carries the mechanical signatures.

### `poller.rs`
- `Token(usize)` — opaque registration handle; **token `0` is the waker's**, user tokens start at `1`. · `Interest` (`READABLE`/`WRITABLE`/`BOTH`) · `Ready` — observed readiness, **no public constructor** (only `Ready::default()`/`From<Ready> for Readiness`) · `Event` (`token`/`key`/`ready`; `Event::new` lets tests forge one).
- `Poller` — owns `mio::Poll` **and the single `mio::Waker`** created in `new()`; registered by raw `RawFd` + `Interest` + a caller `key`; `poll(timeout)` returns an **owned `Vec<Event>`** (`None` blocks); `waker()` is an infallible cheap clone. `Waker` is the `Arc`-backed, cloneable, thread-safe handle to that one wakeup handle; its event carries `key() == WAKER_KEY` (`u64::MAX`).
- **`poll` is `EINTR`-tolerant**: an `ErrorKind::Interrupted` wait is **retried**, never returned as `BeamError::Io` (`mio` does not retry `EINTR`, and a signal-handler run does not restart the wait, `SA_RESTART` notwithstanding), and the retry **preserves the deadline** (`poll(Some(d))` subtracts elapsed time, so repeated signals never block past `d`; `poll(None)` resumes).
- **Regular-file fallback (internal, no signature change):** epoll refuses regular files (`EPOLL_CTL_ADD`⇒`EPERM`), so `register` keeps a `libc::poll(2)`-backed fallback set — an unsupported descriptor is watched with `poll(2)` and its readiness merged into `poll` in the same `Event`/`Ready` shape; the probe reports its `std::io::Error`; `poll` never blocks indefinitely while the set is non-empty (`FALLBACK_POLL_CAP`, 1 ms).

### `timer.rs` / `queue.rs`
- `Timeout` (`Copy`) — one deadline · `Timer` — deadlines keyed by `u64`; self-contained helpers (nothing in-crate consumes them); `Timer::schedule` replaces **any** deadline for a key, `Timer::pop_expired` returns due keys in **schedule** order.
- `ByteQueue` — a byte buffer whose `front()` is always contiguous.

### `port_task.rs` (port-task scheduling — `erts_port_task_execute`)
- Reduction constants: `CONTEXT_REDS` is the canonical `beam_common::CONTEXT_REDS` (4000), re-exported so `beam_io::port_task::CONTEXT_REDS`/`beam_io::CONTEXT_REDS` resolve (no local copy); `PORT_REDS_{INPUT,OUTPUT,TIMEOUT} = CONTEXT_REDS/100` (40), `PORT_REDS_EXECUTE = CONTEXT_REDS/4` (1000). `PortTaskOutcome::reds_used` models the per-kind cost only: the C also charges `ERTS_PORT_CALLBACK_VREDS` per task plus `ERTS_PORT_REDS_FREE` on teardown and bounds the round at `CONTEXT_REDS` (`erl_port_task.c`).
- `PortTaskKind { Input, Output, Timeout }` (`priority()`: Input < Output < Timeout; `reductions()`) · `PortTask` (`Copy + Eq + Debug`) · `PortTaskQueue` — one pending task per kind (the C guards that in the caller), ordered by kind **priority only** (`seq` is recorded but never a live tie-break); a not-yet-due `TIMEOUT` stays queued (divergence: the C dequeues it, charges 0 reds and drops it); `arm_timeout(deadline)` re-points/replaces a pending `TIMEOUT` (unlike the dedupe-only `enqueue_timeout`).
- `Readiness { readable, writable, error, read_closed, write_closed }` — `read_ready()` (readable ‖ read_closed ‖ error), `write_ready()` (writable ‖ write_closed ‖ error — a poll error is re-triggered for **every** armed direction, the C's `ERTS_POLL_EV_ERR`), `is_idle()`, `From<Ready>`.
- `ReadMessage { header: Vec<u8>, body: Option<Vec<u8>> }` — one completed read with the C `driver_output2` header/body split preserved (`header` = `hbuf`/`hlen`, `body` = `buf`/`len`): one `ReadMessage` is one **`driver_output*` call**, never one byte chunk. `body: None` is the C's `buf == NULL` (no binary tail) and `Some(vec![])` a present empty body (`<<>>` tail) — different messages. Helpers `body_only`/`len`/`is_empty`/`has_body`/`flattened` (the `[list]`-mode byte sequence); its rustdoc carries the oracle-pinned shape table.
- `PortNotification::Data { port, read: ReadMessage } | Closed { port }` — the seam the runtime turns into `{Port,{data,Data}}`/port-exit messages. **Exactly these two variants** (exhaustively matchable by `beam_rt`: two arms, no wildcard). A round reports **one `Data` per `driver_output*` call**, in arrival order — several per port per round, two calls never merged — and an explicit empty read is a real `{Port,{data,[]}}`.
- `LineNotification { port, header, bytes, eol }` — the **separate** channel a `{line, N}` port reports through (the `{eol|noeol, Data}` wrapper of `ERTS_PORT_SFLG_LINEBUF_IO`); a distinct struct, *not* a third `PortNotification` variant precisely so that enum stays exhaustive for its outside consumers. `header` is the producing read's `ReadMessage::header`, which the C prepends as cons cells to **every** frame that call completes (a line spanning two calls gets the header of the call that completed it); empty for a plain read and for the EOF flush. Unlike `Data`, an empty `eol` frame is a real frame (a blank line is `{data,{eol,[]}}`).
- `PortTaskOutcome { ran, reds_used, notifications }` — `notifications` carries `PortNotification`s only; line frames ride `PortRegistry::take_line_notifications`, async/caller completions ride `PortRegistry::take_completions`.

### `port.rs`
- `PortState { Opening, Open, Closing, Closed }` · `DEFAULT_READINESS_RED_BUDGET = PORT_REDS_EXECUTE` (the budget `handle_events` runs) · `PortControl::CLOSE == "close"` — the one **reserved** control-op name (any other name is a driver verb) · `PortCommandOptions { nosuspend, force }` — carried/validated but **inert at this layer**: `Port`/`PortRegistry` carry no busy flag, so a command is never suspended or refused here (the per-port `busy` state is `src/abi/`'s, the caller-blocking half `beam_rt`'s; see *Known Issues*).
- `Port` — owns a `Box<dyn Driver>` + the two byte queues; exposes the scheduling surface (`queue_output`/`schedule_task`/`schedule_timeout`/`arm_timeout`/`cancel_timeout`/`next_timeout`/`pending_tasks`/`next_task`/`has_pending_task`/`timeout`), the exit/async/stream surface (`take_exit_status`/`take_eof`/`has_pending_async`/`drive_async`/`notify_exit`) and the completion stage (`completions`/`take_completions`); re-exports `PortRegistry`.
- **Every driver interaction** (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`drive_async`/`port_exit`/`stop`) installs the completion sink (`completion.rs`), the timer path included because `Port::run_task`'s `Timeout` arm discards `Driver::timeout`'s `Result<()>`; the seven that can plan I/O also refresh the port timer from `Driver::next_timeout` (`Some(d)` arms/**re-points** the single `TIMEOUT` task at `d`, `None` clears it). A driver write (`output`/`ready_output`) is **verified** — the port checks the output queue shrank by exactly the count the driver reported (a mismatch is the typed `error::unsupported(...)`) and schedules an `OUTPUT` task whenever the queue is left non-empty, so a short write cannot stall without re-driving.
- Line framing: `set_line_mode(Option<usize>)`/`line_mode()` (the `ERTS_PORT_SFLG_LINEBUF_IO` bit + `linebuf->max_len`; `Some(0)` = no limit) and `flush_linebuf()` (the C `flush_linebuf_messages`, run from the `take_eof`=`driver_eof` point; a `close` never flushes). A round harvests raw-mode input as ≤1 `PortNotification::Data`; in line mode it stages `LineNotification` frames on an internal queue (`take_line_frames()`, `pub(crate)`), so a line-mode port reports **nothing** through `PortNotification`.

### `registry.rs`
- `PortRegistry` — id allocation (inner `beam_process::PortTable`) + `HashMap<u64, Port>` by port number; basic ops (`new`/`open`/`open_named`/`get`/`get_mut`/`output`/`contains`/`len`/`is_empty`/`close`); `port_table`/`port_table_mut` expose that **same** id table (see the port-monitor handoff; `port_table_mut`'s rustdoc carries the borrowing rule). `close` runs the driver's `stop`, drops the port from the map and **retires the port number only when its `Closed` notification is reported** — so a deferred `Closed` can never name a reused id (both round drivers mint closes through one `take_closed_notifications` helper).
- Frozen seams (all `BadArg` for an unknown id): `handle_events` (**schedules *and* runs** one round under `DEFAULT_READINESS_RED_BUDGET`, returning its `PortTaskOutcome` and reporting/retiring the closes it drains); `execute_port_tasks` (port-number order under a reduction budget ⇒ a `PortTaskOutcome`; drives async completions for every live port whose driver answers `has_pending_async` *before* harvesting input, so a `driver_async` job reaches `ready_async`/`async_free` with no runtime call); `schedule_events`/`schedule_readiness` (enqueue only — an `INPUT`/`OUTPUT` task for directions the driver armed, `PortArms`); `port_command` (queue output + schedule an `OUTPUT` task; the write happens in the task); `port_control` (reserved `"close"` closes with an empty reply; **any other `op`** goes verbatim to `control(op, arg)`); `take_exit_status`/`take_eof` (once-only reaped child status / EOF report); `schedule_timeout`/`cancel_timeout`/`next_deadline`; `notify_port_exit` (`Driver::port_exit` **at most once**, port left live, independent of `close`/`stop`); `drive_async`; `set_line_mode`/`flush_linebuf` + `take_line_notifications` (every port's staged `LineNotification` frames in **port-number order** after a round, in the `take_eof` accessor style); `take_completions` (the same pattern for the completion side channel: every live port's `PortCompletion`s in **port-number order**, then the `closed_completions` queue `close` fills, so a completion staged before or at a close is reported exactly once).

### `driver.rs`
- `DriverFlags(u32)` — `Copy + Eq`; `SOFT_BUSY`. · `PortExitReason { Closed, OwnerExited, Normal }`.
- `DriverContext<'a>` — the driver's view of its port; **the only way a driver touches the poller or the queues** (`port`/`register`/`reregister`/`deregister`/`input`/`output`); registration keys are the port number (`pub(crate) PortArms` records the armed directions). Its two delivery seams carry **no** per-frame stream drain (see the `tcp_inet` active-mode handoff): `deliver_read(header, body: Option<&[u8]>)` — the driver-side `driver_output2`/`driver_output_binary`/`driver_outputv` seam, one read message with the C's header/body split preserved (`None` = the C's `NULL` body), bytes banked on `input()` closing into their own body-only read **first** — and `deliver_completion(event)`, the async/`{inet_reply,…}` side channel (`PortCompletion`). Both answer the typed `unsupported` without the port's sink, never flattening or dropping the event.
- `pub trait Driver` — **frozen**. Required: `name()` (+ `flags()` default `empty()`), `start`, `output`, `ready_input`, `stop`. Defaulted: `ready_output` (= `output`) · `control` · `has_control()` (**`false` iff the driver's C counterpart has `control == NULL`**, e.g. `ram_file_drv` — then `erlang:port_control/3` answers the oracle's `badarg` without consulting `Driver::control`; `DriverPort` answers `entry().control.is_some()`) · `timeout` (its `Result<()>` is discarded by `Port::run_task`'s `Timeout` arm — no reply channel) · `next_timeout() -> Option<Instant>` (the declared deadline, mirrored into the port's `TIMEOUT` after each interaction) · `port_exit(PortExitReason)` (the once-only advisory port-exit notification, distinct from the teardown `stop`) · `drive_async` (default `Ok(0)`; `DriverPort` overrides with `poll_async`) · `has_pending_async()` (default `false`; overridden via `AbiHost`) · `take_exit_status()`/`take_eof()` (only `SpawnDriver`). Further capabilities must be additive with defaults that keep the built-ins compiling.
- `DriverFactory = fn() -> Result<Box<dyn Driver>>`; `DriverRegistry` — name→factory (the `driver_tab.c` seam); `with_builtins()` registers **`"fd"`, `"efile"`, `"tcp_inet"`, `"udp_inet"`, `"ram_file_drv"`**.
- **The statically-linked (emulator `driver_tab`) set is a separate, narrower contract** — `STATIC_SPAWN_DRIVERS: [&str; 3] = ["ram_file_drv", "tcp_inet", "udp_inet"]` (sorted) + `is_static_spawn_driver(name)`, `DriverRegistry::with_static_spawn_drivers()` (whose `names()` is exactly those three) and `DriverRegistry::create_static_spawn(name)` (membership gate first, then the ordinary factory lookup). It refuses a name outside the set with `BeamError::BadArg` — the oracle's own `badarg` for `open_port({spawn_driver,"fd"},[])`/`{spawn_driver,"efile"},[]}` — **even on a `with_builtins()` registry that registers them** (that constructor is unchanged: this crate's own `fd`/`efile` ports are built through it). The set is exactly the oracle's `erl_ddll:loaded_drivers/0` answer (`{ok,["tcp_inet","udp_inet","ram_file_drv"]}`): those three are linked into the emulator, **not** `.so`-loadable (`erts-*/lib/` ships zero `.so`).

### `completion.rs` — the driver→owner completion side channel
A **third** side channel beside `PortNotification` (which stays exactly two variants) and the `{line,N}` frames: a driver reports an asynchronous outcome here and the runtime turns it into the oracle's message.
- `PortCompletion { port: PortId, event: CompletionEvent }` — the port id stamped by `DriverContext::deliver_completion`, never by the driver.
- `CompletionEvent { InetReply { caller_ref: Option<Vec<u8>>, reply: InetReply }, InetAsync { id: u16, result: InetAsyncResult } }` — the `{inet_reply, Port, Reply[, Tag]}` and `{inet_async, Port, Id, Result}` shapes.
- `InetReply { Ok, Error(InetReason) }` · `InetReason { Closed, Timeout, Errno(i32) }` (`from_errno`, `atom_name` — the lowercase POSIX name, with the C's `errno_<N>` fallback) · `InetAsyncResult { Ok, Data(ReadMessage), Accepted { fd }, Port(PortId), Error(InetReason) }`. `Data` keeps the header/body read split; `Accepted` hands an accepted descriptor over **owned** — the driver never stores it, so no teardown path can close it.
- Term-free: `caller_ref` is the `prim_inet` caller tag carried **verbatim** (a 131-led `term_to_binary(Mref,[local])` ETF image); this crate never decodes it — the runtime does.
- Delivery invariants: `deliver_completion` **stamps the port id itself** (a context without the port's sink is the typed `unsupported`); the port installs its sink at **all nine** driver interaction points (`start`/`output`/`ready_input`/`ready_output`/`timeout`/`control`/`drive_async`/`port_exit`/`stop`), so a completion lands in the port's queue whatever the interaction point; `PortRegistry::take_completions()` drains every live port's completions in **port-number order** and then the close-harvest queue, so a completion staged before or at a `close` is reported **exactly once** — drain it after **every** round and after **every** `close`.

### `drivers/` (per-driver roles, verb tables, constant tables and suites: `src/drivers/CONTEXT.md`)
- `fd.rs` — `FdDriver`, the built-in `"fd"` byte-stream driver: **owns** its fds (closed on `stop`/`Drop`; `EfileDriver` composes it, so the rule carries through), line/phase modes (`Some(0)` = no line limit), the `line`/`noline`/`binary`/`text`/`getopts` control verbs (unknown⇒`BadArg`), EOF de-registration (the fd stays attached/owned). `line_buffer.rs` (`LineBuffer`, `LineFrame { bytes, eol }`, `DEFAULT_MAX_LINE_LEN = 1024`, the C's `LINEBUF_EOL`/`LINEBUF_NOEOL` and `CR_AFTER` rules) and `binary_io.rs` (`Phase { Text, Binary }`/`PhaseChange`, the `erl_child_setup` text⇄binary machine, default `Binary` = raw passthrough) are the two input-framing facilities.
- `efile.rs` — `EfileDriver` (`name() == "efile"`), byte movement delegated to a composed `FdDriver`; `make_efile()` = its `DriverFactory`. A failed syscall ⇒ the raw `BeamError::Io` errno (the `{error,atom}` rendering is the runtime's `prim_file` floor); an unopened port / unparsable argument ⇒ `BadArg`.
- `spawn.rs` — `SpawnDriver` (`name() == "spawn"`), the **only** module here that may spawn OS children; **constructed** (`with_stream_options`), **really spawning** in the constructor and reaping eagerly (once-only `take_exit_status()`/`take_eof()`); `SpawnStream { Binary, List }` (`Default = List`) = the `binary`/`list` option (the **runtime** builds `{Port,{data,Data}}`), and `SpawnSpec`/`SpawnOptions`/`StreamOptions`/`build_command` are the term-free `open_port/2` shape (empty command/path or argv⇒`BadArg`). `stop`/`Drop` kill + reap + deregister/close every descriptor, but an adopted `{fd,N}` is **never** closed.
- `inet/` — the built-in **`tcp_inet`** (stream) and **`udp_inet`** (datagram) socket drivers, one socket behind one port, reachable through `open_port({spawn_driver, tcp_inet | udp_inet}, …)`; they share `wire.rs`/`opt.rs`/`sys.rs`/`stat.rs`, apply `{packet, N}` framing on **both** the read and the send path, and `opcode.rs` decodes the decimal `erlang:port_control/3` numberspace onto the same named-verb bodies (`udp_inet`'s named `recv` is this floor's own read-now convenience — the C has no such control op).
- **The async-op queue** (`async.rs` + `udp/async.rs`, the C's `desc->async`): `NEW_ASYNC_ID = op_ref++ & 0xffff`, taken **before** the capacity check (a refused enqueue still consumes an id); one receive slot (`INET_MAX_ASYNC = 1` ⇒ a second concurrent receive answers `[0]"ealready"`) + a multi-op accept list (never `ealready`; `getstatus` reports its accepting bits); `deadline_for` (`<0` = infinity, `0` = now) merges into `Driver::next_timeout`; `drain_closed` answers `{error, closed}` **exactly once** per pending op at a close. Served: `TCP_REQ_RECV`(42), `ACCEPT`(26) (its `Accepted { fd }` handed off **owned**) and `udp_inet`'s `PACKET_REQ_RECV`(60), whose `Length` operand is **ignored** and which completes `Data(ReadMessage { header: 7 packed address bytes, body: payload })`. Both write paths strip one caller tag and stage `{inet_reply, Port, ok|{error,Reason}, Tag}` (a zero-length tag is consumed, staging **no** reply). `INET_REQ_CONNECT`(3) is a bounded synchronous wait consuming no async id (a documented divergence).
- `ram_file.rs` — the built-in **`ram_file_drv`** in-memory file driver (`RamFileDriver`/`make_ram_file`): a command-driven port (an opcode byte on the output queue → a reply on the input queue) over a `Vec<u8>`, the C's 13 opcodes and its `OK`/`NUMBER`/`DATA`/`ERROR` reply encodings. Every option/verb/refusal row, the `PacketType` decoder and the `gen_tcp`/`gen_udp` handoffs belong to **`src/drivers/inet/CONTEXT.md`**.

### `src/abi/` — the driver C-ABI host layer (A.4)
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver`; a `pub` sub-tree (`pub use crate::abi::*`); the only place in this crate holding raw `ErlDrv*` pointers and calling foreign code. Four modules — `host.rs` (`PortHost` + `AbiHost`), `job.rs` (`AsyncJobs`, the bounded `driver_async` pool), `port.rs` (`DriverPort`, which prefers the entry's **`outputv`** on both write paths, plus the once-only `stop_select`), `table.rs` (the process-global `DriverTable` + the four registry slots reproducing the oracle's `0,1,0,-1`).
`AbiHost` **implements** `beam_abi::DriverHost::set_busy_port` (records the per-port `DriverState::busy` flag, answers the C's `0`; read back via `AbiHost::is_busy`/`DriverPort::is_busy`), exposes `queue_head` (the safe `&[u8]` companion of the raw `driver_peekq` hook, as `DriverState::queue_len()` is of `sizeq`), and `DriverPort::control` returns the **empty list** for the C's documented `*rbuf == NULL` reply rather than `badarg`. Detail: **`src/abi/CONTEXT.md`**.

### `io_device/` — the io-device request layer (`{get_until, Enc, Prompt, Mod, Func, XtraArgs}`)
`Encoding { Latin1, Unicode }` (any other name — a tuple encoding, … — is refused, never guessed) · `ByteSource` (`read_chunk(size) -> Result<Option<Vec<u8>>>`, `None` = eof; impls for `std::fs::File`, `SliceSource`, `EmptySource`) · `IoDevice` — `file_io_server`'s `#state{handle,buf,read_mode,unic}`, whose request is `get_until::<C>(&mut self, continuation: &mut C, out_encoding) -> Result<C::Reply>`.
The device loop (`READ_SIZE_BINARY` 8 KiB / `READ_SIZE_LIST` 128) reproduces `get_chars/5` → `get_chars_apply/7`: a stashed leftover is fed **before** any read, the `latin1` clause matches only when `Enc == latin1` **and** `unic == latin1`, the general clause decodes/transcodes (`InEnc = unic`, `OutEnc = Enc`) and carries an incomplete-UTF-8 tail across a `{more,…}` re-read, `eof` is delivered as `eof`, and a sequence spanning end-of-file is the `invalid_unicode` stop.
The **`Continuation` seam** (`Continuation`/`ContData`/`Applied`/`Leftover`) is the oracle's `apply(Mod, Func, [Cont, Chars | XtraArgs])`; the charlist is a `Vec<u32>` of code points and `cast_reply` is `io_lib`'s list→binary cast. `NoEngineContinuation` is the not-installed default: every `apply` is the typed `unsupported` (naming the missing `erl_scan:tokens/4`), never a fabricated reply. **Deviations:** term-free (byte/code-point data, caller-defined reply/cont types); the `{stop, Reason, {error, Fn}, State}` reply boxing and the `erl_scan`-specific `invalid_unicode_error/4` position hack are the runtime/protocol layer's; `Leftover` is a flat `binary | charlist | nothing` (no deep iolist). Detail: **`src/io_device/CONTEXT.md`**.

### `signal.rs` — the OS-signal facility (safe `sigaction` + self-pipe)
`Signal` — the twelve signals `os:set_signal/2` accepts (`sigttin`/`sigttou` are **not** accepted; rustdoc lists the set), `Signal::ALL` = the `drain` report order, `name`/`from_name`/`signo`/`from_signo`; `Disposition { Default, Handle, Ignore }`.
`SignalFacility` — `new()`, `set(&mut self, Signal, Disposition)` (`sigaction(2)`, **empty `sa_mask`**, **`SA_RESTART`**), `disposition`, `read_fd()` (the fd the runtime registers with `Poller` — **the runtime owns the registration/token**), `drain() -> Vec<Signal>` (**each distinct signal since the last drain exactly once**, in `Signal::ALL` order; the bitmask is swapped *before* the pipe is drained, so a signal landing in that window is deferred, never lost). `SigStop` is **kernel-only** (`sigaction(2)` refuses every disposition change, so `set(SigStop, _)` is the typed `BeamError::Io`; the consumer answers the oracle's `ok`).
The handler is **async-signal-safe** — one atomic bitmask OR plus one `libc::write` to a non-blocking self-pipe, whose byte count is **not** the source of truth; `drain` maps signo→`Signal` in normal context. The facility is **process-global** (keep exactly one alive; `new`-after-`drop` is safe; `Drop` restores every prior disposition, resetting the pending bitmask only if this facility was still the live one) and unix-only (no `signalfd`).

### `cpu_time.rs` — the CPU-time facility (safe `getrusage`/`clock_gettime`)
`CpuTimes { user_ms, system_ms }` — whole **milliseconds** (the oracle's unit: µs ÷ 1000, truncating). `process_cpu_times()` (`getrusage(RUSAGE_SELF)`, the process's user+system time over its threads) is exactly the C's `erlang:statistics(runtime)` measurement (`erts_runtime_elapsed_both`); `thread_cpu_times()` (`clock_gettime(CLOCK_THREAD_CPUTIME_ID)`) reports the calling thread's combined time as `user_ms` with `system_ms == 0` and is **not** what that BIF uses.
`RuntimeClock` (`new`/`Default` anchor **0**, `runtime() -> Result<(u64, u64)>`, `reset()`) is the `statistics(runtime)` counter: `(Total, SinceLastCall)` in **milliseconds**, so the **first** call returns two equal elements (the C's `runtime_prev.data.user = 0`) and **system time is not used**; a failed `getrusage` returns the typed `BeamError::Io` and leaves the anchor **unchanged** (never a fabricated `0`).

### `ddll.rs` — the dynamic-library primitive (safe `dlopen`/`dlsym`/`dlclose`)
`DynLib` — an owned `dlopen(3)` handle (`open`/`open_with`/`open_cstr`, `symbol`/`try_symbol`, `handle()`; `Drop` closes exactly once); deliberately no `into_raw`/`from_raw`, and not `Send`/`Sync`. `DynLibFlags` — `EMULATOR` (`RTLD_NOW | RTLD_LOCAL`, the default, the emulator's mode and the mode `beam_abi`'s loaders use), `NOW_GLOBAL`, `LAZY_LOCAL`, `LAZY_GLOBAL`.
`DllError { kind, text }` + `DllErrorKind` — the `erl_ddll` reason vocabulary, with `reason_atom()`, `errcode()` (**derived** from the single `ERRCODE_TAB` via `atom_to_errcode(reason_atom())`, not a second hand-written match), `text()`, `is_*()` classifiers; classification is **text-based only** (a failed `dlopen` does not set `errno` reliably), mirroring the emulator's `find_errcode`. `ERRCODE_TAB` (the emulator's `errcode_tab`, byte-for-byte) plus `errcode_to_atom`/`format_error_text`/`symbol_name`/`ERL_DE_*`; **no** `.so` suffix is appended (path spelling is the caller's). The `-Wl,--export-dynamic` requirement is a property of the **loading** link, shared with `beam_abi`/`beam_rt`; this crate's part is its `build.rs`.

### `fs_access.rs` — the safe `access(2)` / `geteuid(2)` / `getegid(2)` floor
`AccessMode { Exists, Read, Write, Execute }` (`libc_mode()` reads `libc`'s `F_OK`/`R_OK`/`W_OK`/`X_OK`).
`try_access(&Path, AccessMode) -> Result<()>` — the crate's **one `access(2)` call site**, errno-preserving: `Ok(())` iff the kernel grants the mode, `Err(BeamError::Io(err))` with the untouched errno on refusal (`EINTR` retried), `Err(BeamError::BadArg)` for an interior-NUL path — the form a caller needs when the *reason* matters (the spawn driver's `X_OK` render). `access(&Path, AccessMode) -> Result<bool>` — the boolean form: a **refusal** (`EACCES`/`ENOENT`/`ENOTDIR`/`ELOOP`/`ENAMETOOLONG`/`EPERM`/`EROFS`/`ETXTBSY`) is `Ok(false)`, only a genuine syscall failure is `BeamError::Io`; `path_access(&Path) -> Result<(read, write)>` is the `#file_info{}` `access` slot (two **independent** probes, so a writable-but-unreadable path answers `(false, true)`); `process_credentials() -> Result<(euid, egid)>` are the **effective** ids `check_access` compares a `stat` against and cannot fail.

## Constraints
- Errors: **`beam_common::{Result, BeamError}` only**; I/O/syscall failures⇒`BeamError::Io`, argument faults⇒`BeamError::BadArg`, id/registration exhaustion⇒`BeamError::SystemLimit`. Never panic on runtime data, never `unwrap()`, never `todo!`/`unreachable!` in shipped code.
- **Safe Rust by default.** `unsafe` only in the raw syscall wrappers (`libc::read`/`write`/`pipe`/`fcntl`/`open`/`dup`/`fstat`/`lseek`/`fsync`/`ftruncate`/`close`, the spawn driver's `fork`/`execve`/`waitpid`/`dup2`, `inet`'s `setsockopt`/`getsockopt` in `drivers/inet/sys.rs`, the `cpu_time.rs` `getrusage`/`clock_gettime`, the `signal.rs` `pipe2`/`sigaction`, the `ddll.rs` `dlopen`/`dlsym`/`dlclose`, the `fs_access.rs` `access`/`geteuid`/`getegid`), `mio::unix::SourceFd` construction, and the `abi` host's raw `ErlDrv*` handling. Every `unsafe` block carries a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
- **Port ids come from `beam_process::PortTable`** — no second number allocator; `PortId` encoding stays `beam_term`'s internal-port immediate; a failed `start` runs the driver's teardown (deregistering any fd) and releases the number — no id-space/poller leak.
- **Single-thread invariant (enforced).** `Port`/`PortRegistry` are **not** thread-safe and this crate has no locking: create and drive them from **one OS thread**. `PortRegistry` carries a `PhantomData<core::cell::Cell<()>>` marker so it is neither `Send` nor `Sync`; a `Port` holds a `Box<dyn Driver>` with no `Send`/`Sync` bound; `DynLib` is likewise not `Send`/`Sync`. (Not enforced on `Poller`/`Waker` — the `Waker` is meant to cross threads; `SignalFacility` is process-global.)
- **Only `drivers/spawn.rs` may spawn OS children**; the `signal`/`cpu_time`/`ddll`/`inet`/`file` modules never fork/`Command::spawn`.
- **The `Driver` trait and `DriverContext` public methods are the frozen driver seam** — do not change their signatures. Files target ~1000 lines, split by responsibility. Deps: `beam_common`, `beam_term`, `beam_process`, `beam_abi`, `beam_alloc`, `libc`, `mio` only; no new deps (see *Design Decisions* for the `beam_io → beam_abi`/`beam_alloc` edge).

## Design Decisions
- **`mio` backend.** A portable, safe `Poll`/`Registry`/`Waker` with a one-shot re-arm matching the C's `EPOLLONESHOT`/`EV_ONESHOT`; the public API is **mio-independent** (`RawFd` + `Interest`/`Token`/`Ready`), so a different backend could be added behind it (an io_uring/`/dev/poll` backend is **not implemented today**). `mio` fd registration is `os-ext`/Unix-only, so Windows/iocp is out of scope (as in `beam_abi`).
- **The `Port` owns both `ByteQueue`s, not the driver** (the C `ioq`): `Port::output` appends then calls `Driver::output`, which **pulls** from `ctx.output()` — no double buffering.
- **Task execution here, the scheduler thread above.** The poll loop, port run queues and scheduler-charged reductions are `beam_process`/`beam_rt`; `PortNotification` keeps the engine/runtime split and the DAG clean. Only `execute_port_tasks` yields `Data`/`Closed`.
- **Readiness ⇒ task, gated by `PortArms`**: a full close (`EPOLLHUP` ⇒ `read_closed` **and** `write_closed`) schedules no bogus OUTPUT task on a read-only driver. A poll **error** likewise reaches both armed directions (C parity), so a fully armed port gets an `Output` task from a pure `EPOLLERR`, while the `PortArms` gate still denies it to a read-only port. **Divergence:** the C keeps three FIFO queues with no cross-kind priority; here one queue is kind-priority-ordered (INPUT → OUTPUT → TIMEOUT) — observable only in the order two *different* kinds run in a round.
- **The spawn driver is constructed, not registered, and reaps eagerly:** a `DriverFactory` cannot carry command/argv/options, so it is built from a `SpawnSpec`; the child starts in the **constructor** (so a failed spawn registers nothing and `os_pid()` is readable before `PortRegistry::open`); `{fd, N}` adopts a descriptor as a **duplex** stream and never closes it; `stop`/`Drop` kill **and** reap (`Drop` reaps because Rust's `Child` does not).
- **The TCP driver is a floor, not a full `inet`** — the served verbs incl. `setopts`/`getopts` and the framing types are oracle-cross-checked (see `src/drivers/inet/CONTEXT.md`).

## Known Issues
- **`FdDriver` is deliberately minimal.** Byte-stream only; line mode frames input but does **not** line-frame output; no `inet`/`forker` drivers; no packet framing.
- **`SpawnDriver` is the OS-child floor, not the whole `spawn` driver.** Synthesizing `{Port,{data,…}}`/`{Port,{exit_status,…}}`/`{Port,eof}` from its bytes, latched EOF and once-only exit status is the runtime's job. Writing to a child that closed its stdin fails with a typed `BeamError::Io` (remainder kept); adoption needs non-blocking, and a descriptor that refuses (some inherited ones ⇒ `EPERM`) fails the open. Input is framed at the **port**, not in the driver (no `line` verb): `binary`/`list` rides `SpawnStream`, and `[line]`/`[binary,{line,N}]` goes through `Port::set_line_mode` + `PortRegistry::take_line_notifications` (`tests/spawn.rs::line_framing_matches_the_oracle`).
- **A control verb's *operand* is decoded by the caller, but its *opcode* is not.** `port_control(op, &[u8])` takes a `&str` op + raw bytes: packing `erlang:port_control/3`'s `Data` term into the C's request payload is the runtime's job, while an integer `Op` is forwarded as its **decimal string** and decoded onto the named verbs by `src/drivers/inet/opcode.rs`. The served `INET_REQ_*` surface, its guard order, its wrapping/`[0]exbadport` rules and its refusal-only arms are `src/drivers/inet/CONTEXT.md`'s.
- **A socket-less or unconnected inet command is a typed refusal; a caller tag is stripped by shape, not by caller.** `write_pending` answers `BeamError::BadArg` (queued bytes retained), which `Port::check_write_accounting` short-circuits and `execute_port_tasks` propagates out of the round, so the BIF raises; the C's guard is `!IS_CONNECTED` for `tcp_inet` but `!IS_OPEN` for `udp_inet`, so an open-but-unconnected datagram port really sends (the destination rides the command). The C's other two shapes — answer `true` then `{error,enotconn}` out of band, or kill the port via `init_caller` ⇒ `driver_failure_posix(EINVAL)` — are unreachable through the frozen `Driver` trait (no `driver_failure` seam, no driver→owner data path). A caller tag is spotted from the bytes alone — a `[n:be16][n bytes]` head with a non-zero, fitting `n` whose first byte is `ETF_VERSION_MAGIC` (131) — with `udp_inet` trying its plain `[address][payload]` grammar **first**, so a valid plain command is never misread. Residual: a short/unparsable prefix is the same `BadArg`, and a *prefixed* tag of **≥ 256 bytes** is taken as plain — impossible for `prim_inet:send/3`, which always prefixes a tens-of-bytes `term_to_binary/1` blob.
- **A completion is addressed to the port's owner, not to the C's `driver_caller`.** `InetReply`/`InetAsync` are staged with `DriverContext::deliver_completion` and drained by `PortRegistry::take_completions`; the C sends to `desc->caller` (`inet_reply_caller_ref`). Rendering and delivering the messages is the runtime's (*Handoffs*).
- **The `driver_output2` header/body split survives to the consumer; the term shape is the runtime's.** `PortNotification::Data` carries `ReadMessage { header, body: Option<Vec<u8>> }` (pinned shapes in its rustdoc, exercised by `tests/driver_output2.rs`). A **loaded C** driver still arrives flattened — `beam_abi::DriverHost` has only `output(port, &[u8])` and `drv/port.rs` joins header onto body — so that half needs an additive, defaulted `DriverHost::output2(port, header, body)` hook (owner: the `beam_abi` node; the C ABI unchanged).
- **The busy-port flow control has no consumer above `src/abi/`.** `set_busy_port` records the per-port flag (`AbiHost::is_busy`/`DriverPort::is_busy` read it), but `Port`/`PortRegistry` carry no busy flag and `PortCommandOptions`'s `nosuspend`/`force` stay inert, so `port_command` never suspends or refuses here; the caller-blocking half is `beam_rt`'s. Oracle-pinned (a `cc`-built driver whose `start` calls `set_busy_port(port,1)`): `[nosuspend]` ⇒ `false`; `[force]` ⇒ `notsup` unless the driver sets `ERL_DRV_FLAG_SOFT_BUSY` (busy or not), `true` with it; `port_command/2` **suspends** until `set_busy_port(port,0)`.
- **The loaded-driver write path has no byte-count/remainder by design — the C's `output`/`outputv`/`ready_output` callbacks are `void`.** Counting the whole drained buffer as written is exactly the C (`prt->bytes_out += size`), which frees the command and never re-queues; do not "fix" it into a remainder. The `int`/"not accepted" contract belongs to the opposite direction (`driver_output*`, modelled as `0`/`-1`). Detail: `src/abi/CONTEXT.md`.
- **This crate has no poll thread of its own.** `execute_port_tasks` runs a round on demand; the per-iteration drive (poll → `schedule_events`/`handle_events` → `execute_port_tasks`), the reduction budget and the single long-lived `Poller` live in `beam_rt`'s single-threaded main loop.
- **No `Driver::flush` / asynchronous CLOSING on port close.** `close` runs the driver's `stop` and drops both byte queues; with no flush hook, output queued at close time is not flushed (the C calls `drv->flush` and parks a port with a non-empty `ioq` in `ERTS_PORT_SFLG_CLOSING`). `beam_rt` mitigates by notifying the port owner first.
- **Driver-readiness residuals.** `DriverState::fd_armed` hands `ready_input`/`ready_output` the first `BTreeMap`-ordered fd matching the direction, so a multi-fd port selected the same way would starve the others (fixing it needs the fired fd on the poller/`DriverContext` seam; harmless for every current driver — one fd each). A `{fd,N}` spawn port keeps an `Interest::BOTH` registration for its life (`arm_output`/`disarm_output` are no-ops for `duplex`), so a spurious `OUTPUT` task is scheduled on every write-readiness event.
- **File sizes (`wc -l`, over the ~1000-line target).** Crate sources: `registry.rs` 2048, `drivers/spawn.rs` 1978, `port.rs` 1533, `drivers/efile.rs` 1404, `driver.rs` 1236, `drivers/fd.rs` 1193, `drivers/ram_file_tests.rs` 1144, `port_task.rs` 1127, `signal.rs` 1105, `abi/port.rs` 1044, `completion_tests.rs` 610, `completion.rs` 305; the `inet` subtree starts at `mod.rs` 1897, `tests.rs` 1789, `udp.rs` 1500 and is itemised in its child doc; integration: `tests/spawn.rs` 1698, `abi_driver.rs` 1206, `udp_inet.rs` 1143, `efile.rs` 1063, `inet_async.rs` 1028, `ram_file.rs` 1003. Each is a source half plus its suite — a grown source half splits its test module into a sibling file (`src/drivers/inet/udp/`, `opcode_tests*.rs`, `{opt,stat}_tests.rs`, `ram_file_tests.rs`, `registry_reply_tests.rs`, `abi/host_tests.rs`, `completion_tests.rs`).

## Handoffs (beam_rt — out of this node)
**Adopted upstream:** `{line,N}` framing (`set_line_mode` + `take_line_notifications`), busy-port flow control (`DriverPort::is_busy`/`soft_busy` + `SOFT_BUSY`), the `#file_info{}` `access`/`uid`/`gid` path (`fs_access`), the signal and CPU-time facilities, `create_static_spawn`, the once-only `take_eof`, the port-monitor id table, the `{get_until,…}` io request, `ram_file_drv`'s port path, `erlang:port_control/3` and a refused command's `badarg`.
**Still owed, each a seam the frozen `Driver`/`DriverContext` trait lacks:**
- **The runtime's half of the completion channel.** Both drivers stage every outcome (`TCP_REQ_RECV`(42), `ACCEPT`(26), `PACKET_REQ_RECV`(60), the `port_command` caller reply, the teardown drains); `beam_rt` must drain `PortRegistry::take_completions()` after **every** round and after **every** `close`, and render:
  - `InetReply { caller_ref, reply }` as `{inet_reply, Port, Reply[, DecodedTag]}`, decoding `caller_ref` (the verbatim 131-led `term_to_binary(Mref,[local])` image) with `beam_codec`.
  - `InetAsync { id, result }` as `{inet_async, Port, Id, Result}`; `InetAsyncResult::Data(read)` renders per the port's mode — `read.flattened()` for `[list]`, header + improper binary tail for `[binary]` (the datagram side puts its 7-byte packed-address header first) — and `Ok`/`Port`/`Error` are the other three arms.
  - `InetAsyncResult::Accepted { fd }` is adopted into a **second** port (`from_socket`, or the served `INET_REQ_FDOPEN`) **or** closed by the runtime — `beam_io` never closes it.
  Owner: `beam_rt` — its `PortEvent::Term` machinery exists for `dlopen`ed driver ports, but a **built-in** driver port has no term path (`PortMeta::driver_terms` is `None` for `PortName::SpawnDriverBuiltin`).
- **`driver_caller`.** A TCP command's caller prefix can only be stripped by shape, so no sound discriminator exists without a caller notion on the frozen `Driver`/`DriverContext` seam (*Known Issues*).
- **The delivered-data term shape (`mode` list vs binary) and the `LineNotification` header stamp are the runtime's.** `PortNotification::Data` carries bytes while the C's `tcp_reply_data` builds the term from `desc->mode`; `beam_rt` matches `{ port, read }`, renders the oracle's improper-list shape and stamps a `LineNotification`'s `header` as the same cons prefix on `{eol|noeol, Data}` (`prim_inet:open/5` always passes `[binary]` to `open_port`; storing/reporting `mode` is closed here).
- **The async-op queue's remaining arms** — `{active,N|once}`/`{deliver,…}`/`active_count` input delivery, **`send_timeout`/`send_timeout_close`**, **`controlling_process`**, **`SUBSCRIBE`'s notification half** (`{empty_out_q, Port}`), the **`IGNOREFD`/`TcpSendfile`/`Getservby*` refusal-only arms**, and **`udp_inet`'s active-mode `{udp, S, IP, Port, Data}` delivery + ancillary data (`anc_len != 0`)** — all refused honestly; the owner, the missing seam and the C ground truth for each are in `src/drivers/inet/CONTEXT.md` › *Handoffs/Divergences*.
- **`tcp_inet` peer close → `{tcp_closed, Port}`.** `TcpInetDriver::peer_closed()` latches the close and the driver's `recv`/`send` already answer the C's `[0]closed`/`[0]enotconn`; the runtime needs a `Driver` accessor (e.g. `port_closed()`) to observe it and deliver the message.
- **`beam_rt`'s `src/port/inet_matrix_tests.rs::the_residuals_no_oracle_column_can_pin_stay_typed` asserts an `INET_REQ_FDOPEN`-adoption typed gap** that this crate's served path contradicts (it gets the non-mirror's `[0]einval` "already holds a socket" answer). That node's owner must update the row; this crate cannot.
- **`src/ddll.rs`'s `DynLib` has no consumer outside this crate.** `beam_rt`'s `erl_ddll` floor is built on `beam_abi::driver::loader` (`DriverLoadError`), so the safe `dlopen`/`dlsym`/`dlclose` wrapper stays an unadopted seam (`DynLibFlags::EMULATOR` matches `beam_abi`'s mode; the dynamic `{open_error, Code}` tuple at `ERL_DE_DYNAMIC_ERROR_OFFSET = -10` is the floor's). **Dependency direction:** `beam_abi`'s own loaders cannot call this module, so a consolidation would move the wrapper **down** into `beam_abi` and re-export it here.
- **The `erl_ddll` error taxonomy is duplicated OUTSIDE this crate (report — not fixable here).** A full atom+code+message copy lives in `crates/beam_bifs/src/runtime/ddll.rs` and a partial one in `crates/beam_abi/src/driver/loader.rs` (`DriverLoadError::reason_atom`); the recommended single owner is `beam_abi` (re-exported by `beam_io::ddll`), but `beam_bifs` does not depend on `beam_abi`, so that adds a `beam_bifs → beam_abi` DAG edge and the zero-new-edge alternative is the LCA `beam_common` — an **owner decision + a `CHANGE.md` entry**, not this node's. Artifact validation itself is single-owner per kind (driver: `beam_abi::driver::loader::load`; NIF: `beam_abi::nif::loader::load`); `beam_io::ddll` validates no entry.
- **The `file:*` API belongs to `beam_rt`'s `prim_file` floor, not to this driver.** The `efile` driver offers the driver-level verb set, but `file:*`/`prim_file` is a Rust-`std::fs` floor in `beam_rt/src/native/prim.rs`; the driver returns the raw errno and the raw byte stream, so a `file:open/2`+`read/2`+`write/2`+`position/2` route onto it would still owe the `{error,atom}` rendering and the `FileDataMode` → binary/string rendering (`EfileDriver::data_mode`).

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the poller/`Port`/driver-registry seam), `../beam_process/CONTEXT.md` (`PortTable`/`PortId`, `Scheduler`/`ProcessTable`) and `../../CONTEXT.md` §1 A.4/§3 before changing this crate.
- Build/test: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- A new `access(2)` use belongs in `src/fs_access.rs`, never as a second `unsafe` wrapper.
- A driver never touches the queues or the poller directly — it goes through `DriverContext`. When a `Port` method calls the driver, **destructure `self`** (`let Port { driver, input, output, id, .. }`) so the driver and its context borrow disjoint fields; do not add a combined raw-pointer accessor.
- `Poller::poll` returns owned events and is `EINTR`-tolerant; call `registry.handle_events(&mut poller, &events)` after it, or drive the queue explicitly with `schedule_events` + `execute_port_tasks` (keys are port *numbers*, `PortId::number()`). To be woken by a handled OS signal, register `SignalFacility::read_fd()` with the poller.
- `FdDriver` closes the fds it is given (on `stop` and on `Drop`) — do not close them elsewhere; `EfileDriver` composes an `FdDriver`, so the same rule applies through it.
- `mio::unix::SourceFd` borrows `&mut RawFd` only for the duration of the syscall — build it from a local `let mut fd = fd;` inside the wrapper; the raw fd number is what mio registers.
- Signal tests must NEVER raise SIGTERM/SIGKILL/SIGSTOP to self; install a `Handle` disposition for SIGUSR1/SIGUSR2/SIGHUP and restore it. The facility is process-global, so serialize those tests on a shared `Mutex` and raise thread-directed with `pthread_kill(pthread_self(), …)` (POSIX delivers a target thread's pending signal before it returns).
