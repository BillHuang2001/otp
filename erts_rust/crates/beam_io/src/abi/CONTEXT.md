# `src/abi/` — the driver C-ABI host layer (contract A.4)

## Intent
Presents a **loaded C driver** (`beam_abi::driver::loader::load`) as a `Driver` — the bridge between the frozen driver C ABI that `beam_abi` owns (the `#[repr(C)]` `ErlDrv*` types, the `ErlDrvApi` table, the implemented `driver_*`/`erl_drv_*` host functions, the `DriverHost` seam and the `dlopen` loader) and the port/poller/queues/timer that `beam_io` owns.
A `pub` sub-tree (`pub use crate::abi::*`) and the **only** place in `beam_io` holding raw `ErlDrv*` pointers and calling foreign code; every module here is an explicitly-marked `unsafe` module (workspace `../CONTEXT.md` §3).
Legacy C ground truth (read-only): `erts/emulator/beam/erl_driver.h`, `erts/emulator/beam/io.c` (`call_driver_control`, `driver_output`, `driver_read_timer`, `async_ready`, `init_driver`, and the port queue at `io.c:6790-6919`), `erts/emulator/beam/erl_io_queue.{c,h}` (the queue's own implementation), `erts/emulator/sys/unix/erl_check_io.c` (`driver_select`), `erts/emulator/beam/erl_async.c` (the async worker).

## API Surface (FROZEN)
- `mod.rs` = the host-layer docs (the stable `ErlDrvPort` handle, built-in/`.so` unification, the `unsafe`-module marking, the four `driver_*` slots' reach/refusal) + `pub mod host; job; port; table;` + re-exports.

### `host.rs` — `PortHost` + `AbiHost` (tests in `host_tests.rs`)
- `pub trait PortHost` (the one hook `beam_io` cannot fill): required `intern_atom(name) -> Option<Eterm>`; defaulted `connected_pid()`/`caller_pid()` (`None`) and `send_term(to, term) -> bool` (`false`; the sink for `erl_drv_output_term`/`erl_drv_send_term`, `to == None` = the port owner).
  **A locally-interned atom does NOT match the runtime's atom table**, so `beam_rt` MUST inject its own `PortHost` over the shared table (`LocalAtomPortHost` = test/standalone only).
- `SelectedFd { token, interest, owes_stop_select }` (`pub(crate)`) — the **sticky** `ERL_DRV_USE` release obligation, merged on re-selection (the C's `ERTS_EV_FLAG_USED`; `wants_stop_select()` = `ERL_DRV_USE` without `_NO_CALLBACK`).
- `DriverState` — the port's persistent C-ABI state (`selected: BTreeMap<RawFd, SelectedFd>` so `ready_input`/`ready_output` pick a **stable** fd; `deadline`; `jobs: AsyncJobs`; `queued_stop_select` + `take_queued_stop_select()`; `ioq: ByteQueue` — the **driver-private** queue the `driver_enq*` family fills, its byte count exposed as `queue_len()`); deliberately **no `Drop`** (draining there could race the worker).
- `AbiHost` = the `DriverHost` impl, **owning** everything (`port_host`, `heap: Heap`, `state`, `driver: Option<DriverIdentity>`, `ctx: Cell<*mut c_void>`), boxed behind a stable `ErlDrvPort` (`DRIVER_HEAP_WORDS = 1024`-word term heap); with **no context installed** every port-touching method fails gracefully (`-1`/`None`/no-op), never derefs null.
  It forwards `intern_atom`/`connected_pid`/`caller_pid`/`send_term` to `PortHost`, serves the four registry hooks (below), and otherwise matches the C.
  `output` → the port's **input** queue (`0`/`-1`).
  `select(_, event, mode, on)` treats the event as the fd — `on != 0` registers / **re-registers in place**, `on == 0` de-registers (unknown fd⇒`0`), READ→READABLE, WRITE→WRITABLE, both→BOTH, **neither→READABLE** (an `ERL_DRV_USE`-only `mode` still watches the fd for close/error) — merges the sticky obligation (a re-select without `ERL_DRV_USE` keeps an earlier request; `_NO_CALLBACK` declines it), and queues the *deselecting* call's event when the release owes `stop_select`.
  A de-select drops the fd record and queues that release **only after a successful `ctx.deregister`**; a failed deregister (or none installed) answers `-1` and leaves both the record and its release obligation in place, so the withdrawal — and with it the exactly-once `stop_select` — stays possible.
  `has_pending_async` ← `jobs.in_flight() > 0`; `set_timer` arms `deadline` (`0`), `cancel_timer` clears it (`0`), `read_timer` = remaining ms (`Some(0)` expired, `None` none); `r#async` → `AsyncJobs::schedule` (`id as c_long`; a failure runs the driver's `free(data)`, returns `-1`).
- **The `driver_enq`/`driver_pushq`/`driver_deq`/`driver_sizeq`/`driver_peekq[v]` family is implemented over a driver-private `ByteQueue`** (`DriverState::ioq`, the C's `prt->ioq`) — deliberately **not** the port's `DriverContext::output()` queue (see the Design Decisions entry).
  `enq` appends and `pushq` prepends (empty `data` = the C's `len == 0` early return, `io.c:6881`), both answering `0` (a `Vec` cannot report the C's allocation failure); `sizeq` the byte count; `deq` drops from the head and reports the bytes dropped; `peekq` one `SysIOVec` over the queue's contiguous front, `None` when empty.
  None of them needs an installed `DriverContext` (the queue is the host's own state, as the C's `drvport2ioq(ix)` is) and `is_binary` is not consulted (the seam hands over a slice, not an `ErlDrvBinary`).
  The family's **safe companions**: `DriverState::queue_len()` answers `sizeq`'s byte count, and `AbiHost::queue_head(&self) -> Option<&[u8]>` answers the head bytes that `peekq`'s raw `SysIOVec` addresses — so a caller can read the queued bytes with **no** `unsafe` (the frozen `peekq` seam is unchanged and still publishes `iov_base`/`iov_len` for the C ABI). `queue_head` takes `&self` while every mutating hook takes `&mut self`, so the borrow checker enforces the "valid until the next `enq`/`pushq`/`deq`" lifetime `peekq` documents; `None` = the empty queue (the raw hook's `NULL` view), and it needs no installed `DriverContext` either.
  **Documented deviations:** `peekq` always reports a single entry (`vlen == 1`) where the C counts one per enqueue (two `driver_enq` → `*vlen == 2`; byte order and count are identical either way), and `deq` **clamps** an over-long request where `erts_ioq_deq` fails `-1` leaving the queue untouched (`erl_io_queue.c:351`) — a difference unreachable through `driver_deq`, which takes that branch itself by comparing against `sizeq` first (`queues.rs::driver_deq`) — while a negative length is refused.
- `DriverIdentity { name, loaded }` (`pub(crate)`) — the registered driver name + whether it is `dlopen`ed; on `AbiHost`, not a `DriverHost` method (`for_driver`/`with_driver`).

### `job.rs` — `AsyncJobs` (`driver_async`)
- A **bounded, process-global worker pool** (`POOL_THREADS = 4` long-lived threads, lazily started, one shared job queue — the C's async thread pool), a per-port `mpsc` completion channel and the `driver_async` queue position.
- `schedule(invoke, data, free)` (`None` `invoke` = fire-and-forget: a valid position and `free(data)` IS run — the C null-derefs here, a documented deviation; `Err(())` only when no worker could start) and `drain() -> Vec<AsyncCompletion>`; `in_flight()` backs `has_pending_async`; `AsyncData(*mut c_void)` is the one `unsafe impl Send`.
- `set_keepalive`/`KeepAlive` pin the loaded `DriverLibrary` for outstanding jobs (the C's `DE_Handle`), so `async_free` always runs **mapped** code.

### `port.rs` — `DriverPort`
- `DriverPort` = a loaded `ErlDrvEntry` as `impl Driver` (`lib: Arc<DriverLibrary>`/`name`/`command`/`abi: Box<AbiHost>`/`env: Box<DriverEnv>`/`data: ErlDrvData`).
  The library is an **`Arc`** so the process-global table keeps one loaded object registered while ports are created from it; a per-port `LibraryKeepAlive` (`Arc<dyn Any + Send + Sync>`, documented `unsafe impl Send/Sync`) holds it down while any `driver_async` job is outstanding, so `DriverLibrary::drop` (`finish` + `dlclose`) runs with the last owner **and** after the last job.
- `load(...)` calls `beam_abi::driver::loader::load` (validating `command` **first**, so an interior NUL is `BadArg`, not a load failure), mapping `DriverLoadError` to a typed `BeamError::Raise`; `from_library(Arc<DriverLibrary>, CString, host)` wraps an **already loaded** object without a second `dlopen` (the registry's port-creation path; does **not** re-run `init`) and installs the `KeepAlive`; `env` + `abi` are **both boxed**, so the `ErlDrvPort` a driver sees is the **same pointer for the port's whole life**.
- `poll_async` drains the jobs, sorts by queue position (the C's order), runs `ready_async` if present (then `handed_to_ready_async()` — disarmed, `async_free` never runs) else `release()` (runs `async_free` with the host still published); the **port-task round drives it** (via `has_pending_async`).
  A completion reaches `ready_async` **exactly once** and its release runs **exactly once** even when the port dies first.
- `make_loaded(path, name, command, host) -> Result<Box<dyn Driver>>` — the built-in/`.so` unification helper.
- **The write path prefers `outputv`** (the C's `if (drv->outputv) … else … drv->output`, `io.c:1782`).
  A private `write_driver` helper backs **both** `Driver::output` (the registry-level direct write, which runs on whatever it just drained) and the write half of `Driver::ready_output` (what an `OUTPUT` port task runs): the port's output queue is drained through the entry's `outputv`/`output` slot, and an entry declaring neither gets the C's logging `no_output_callback` (`io.c:7516-7520`).
  The `ready_output` write half runs **only when the drained buffer is non-empty** — the C never calls `output`/`outputv` with nothing to write (a write-readiness-only `OUTPUT` task carries no command: `io.c` hands the command's vector to `outputv` from `erts_port_output`, never from the port task), and a zero-length call would make `inet_drv`'s `tcp_sendv` frame an empty buffer (`inet_drv.c:13756-13770`).
  The entry's own `ready_output` slot then fires **unconditionally**, since the C's `ERTS_PORT_TASK_OUTPUT` arm exists to notify write readiness whatever the task carried (`erl_port_task.c:1793-1797`).
  It builds the C's `ErlIOVec`: `iov[0]` the empty **header** block, `iov[1]` the data, `binv` parallel with every entry NULL, `vsize` 2 and `size` = the data's byte count (`io.c:1842-1864`).
  Drained bytes count as written (the callbacks are `void`).
- **`stop_select`** (the `ERL_DRV_USE` release callback) and **current-host publication** are the two things a `DriverPort` does *around* the port seam: it fires the entry's `stop_select(event, NULL)` from three places, each **after** the driver call that produced the release returned (as in the C) — a `driver_select(...,0)` (right after the routing `call`, with the *deselecting* call's event), port teardown (`Driver::stop`, every still-selected registration, fd cast to an `ErlDrvEvent`) and `Drop` (a `DriverPort` dropped without `stop`, e.g. a failed `start`); `USE_NO_CALLBACK`/an absent slot is skipped and `release_selects_on_teardown` also drains `take_queued_stop_select()`.
  Each release fires **exactly once**.
- `DriverPort::call` wraps every callback it routes (`start`/`output`/`ready_input`/`ready_output`/`control`/`timeout`/`port_exit`/`stop`, plus `poll_async`'s `ready_async` branch) in `beam_abi::with_current_host`, as does the `stop_select` firing; `poll_async`'s `async_free` branch (bypassing `call`) publishes separately.
  Those are the only paths running driver code, so the two port-less slots reach a host inside a callback and answer the C's failure value outside one; the `&mut dyn DriverHost` comes from a raw `*mut AbiHost` (documented `// SAFETY:`).
- **`Driver` mapping:** `flags` = `SOFT_BUSY` iff `ERL_DRV_FLAG_SOFT_BUSY`; `start` (absent slot or `GENERAL`/`ERRNO`/`BADARG`⇒`BadArg`, else keeps the `ErlDrvData`); `output`/`ready_output` both drain the port output queue through `write_driver` (the C's `port_command` → `outputv`/`output`), the `ready_output` half only when the drained buffer is non-empty, and `ready_output` additionally runs the entry's `ready_output` slot when present — unconditionally — as the C's write-readiness notification; `ready_input` = the read-armed fd, else null (absent⇒no-op); `timeout` then clears `deadline`; `control`'s `&str` is a **decimal `c_uint`** (absent slot or `cres < 0`⇒`BadArg`; the reply is a `cres`-byte copy of `*rbuf` into a `CONTROL_REPLY_CAPACITY = 4096` buffer); `next_timeout` = `state.deadline`; `port_exit` → `process_exit` (null `*mut ErlDrvMonitor`) else `emergency_close` else no-op; `stop` (absent⇒no-op, then releases every still-selected registration, firing the owed `stop_select`s); `Drop` drains `jobs` **before** `release_selects_on_teardown(None)`.

### `table.rs` — the process-global driver registry + port creation
- The `beam_io` half of the four `ErlDrvApi` slots, reached through `AbiHost`; `unsafe`-marked (stores/derefs `*mut ErlDrvEntry`, calls the entry's `init`), one `unsafe impl Send for Inner` (mutex-serialized).
- `DriverTable`: `global()`/`new()`; `add_entry(*mut ErlDrvEntry)` (**`unsafe`**) records a **statically linked** entry after running its `init` (non-zero ⇒ `driver_init_failed` raise, no registration; null⇒`BadArg`); `add_loaded(DriverLibrary)` records a **dynamically loaded** driver without re-running `init`; `remove_entry` (safe — address comparison) answers `-1` (dynamic) / `1` (removed) / `0` (not found); `lock_driver(name)` = `0` (has a handle) / `-1` (static/unknown); `lookup` (newest wins, the C's head-inserted list) / `names()` / `len()` / `is_empty()`; `create_port(&mut PortRegistry, &mut Poller, name, command, host) -> Result<PortId>` resolves the driver, builds a `DriverPort::from_library` and opens it via `PortRegistry::open` (so `start` runs and supplies the instance's `ErlDrvPort`), the table lock **released before** `start` so a driver may re-enter the table; `RegisteredDriver { name, entry, dynamic, locked }` is a read-only snapshot.
- **The four registry slots reproduce the oracle's `0,1,0,-1` sequence** over a live loaded fixture port (mirroring `beam_rt/tests/driver.rs`): `add_driver_entry` (runs `init`), `remove_driver_entry` (`1`), `lock_driver` (`0`), `create_port` (the sentinel).
  Outside a callback: `add_driver_entry` is dropped, `remove_entry` `0`, `lock_driver` `-1` (null port / bare host / static identity), `create_port` the `ERTS_INVALID_ERL_DRV_PORT` sentinel.
- **Deviations:** the C's `driver_create_port` re-uses the *creating port's* instance and stores `drv_data` verbatim — here a **fresh** instance is created by running `start`; a **statically linked** registration answers the typed `notsup` raise (never a wrong port), since `create_port` needs a `Driver` adapter that exists only over a loaded `DriverLibrary`.

## Design Decisions
- **Driver = Rust trait; the bridge is a `Driver` over a loaded `ErlDrvEntry`:** `DriverPort` adapts the frozen `ErlDrvEntry`/`ErlDrvApi` over a `DriverLibrary`, changing no `Driver`/`Port`/`PortRegistry` signature.
- **The four driver-registry slots: two process-global, `lock_driver` per-port, `create_port` refuses.** `add_driver_entry`/`remove_driver_entry` act on the process-global `DriverTable` via `beam_abi::with_current_host` (outside a callback: the C's `-1`/`0`); `lock_driver` consults the port's **own** driver (`0` `dlopen`ed, `-1` bare/static); `create_port`⇒`ERTS_INVALID_ERL_DRV_PORT` — a callback already holds a `&mut` into the port registry (re-entering `PortRegistry::open` would alias unsoundly) and a new port needs a `Box<dyn PortHost>` only `beam_rt` can supply (the C's own sentinel, never a fabricated port).
- **`driver_output` is harvested by a non-empty input queue, not an `INPUT` task:** `AbiHost::output` pushes onto the port's *input* queue; `Port::take_input_notification` reports+drains `Some(Data)` whenever non-empty — drivers call `driver_output` from `start`/`control`/`timeout`/`output`/`ready_input`, *outside* any `INPUT` task, so task-gating would drop those bytes.
- **The driver queue is the port's own `ByteQueue`, not the port's output queue.** `AbiHost`'s `enq`/`pushq`/`deq`/`sizeq`/`peekq` hold bytes on `DriverState::ioq`, the C's `prt->ioq`, which only the driver touches (`io.c:6790-6919`) and drains from its own `ready_output` (the reference user is `inet_drv`'s `tcp_sendv`/`tcp_inet_output`, `inet_drv.c:13771-13842,14093-14104`).
  Mapping the hooks onto `DriverContext::output()` (the Erlang→driver channel) would re-deliver a driver's own queued bytes to its `outputv` as if they were a fresh port command — the C never puts those bytes in `prt->ioq` (`io.c:1609-1646`, `:1795-1846`) and an `OUTPUT` task runs only `ready_output` (`erl_port_task.c:1793-1797`) — so `inet_drv`'s `tcp_sendv`, which prepends a `{packet,N}` length header to every command it is handed (`inet_drv.c:13756-13770`), would frame them a second time.
  Two deviations are documented on the hooks: `deq` clamps an over-long request (unreachable through `driver_deq`, which takes the C's `-1` branch itself) instead of leaving the queue untouched, and `peekq` publishes one contiguous entry (`vlen == 1`) where the C counts one entry per enqueue.
  A de-select likewise withdraws the fd record only once the poller registration is really gone, so a failed/absent deregister keeps both the record and its `ERL_DRV_USE` release obligation (never a lost `stop_select`).
- **`driver_async` runs on a bounded, process-global worker pool (`POOL_THREADS = 4`), driven by the port-task round** (an unbounded `thread::spawn` per job could exhaust the OS thread limit; the C bounds concurrency too).
  The release obligation is a **value** (`AsyncCompletion`) owning `async_data`/`async_free`, released on `Drop` unless disarmed (`handed_to_ready_async()`), so `async_free` runs **exactly once** even if the port dies mid-job; `AsyncJobs::Drop` drains undelivered completions; the worker drops a completion a failed `tx.send` hands back (the C's `!p`); `schedule(None, ..)` releases immediately.
  **Deviation:** the port thread owns `async_free` (the C uses the worker).
- **`control` is numeric for a loaded driver** (a C driver's verbs are integer `INET_REQ_*`-style codes ⇒ the `&str` is parsed as a decimal `c_uint`); the reply is a `cres`-byte copy of `*rbuf` (`CONTROL_REPLY_CAPACITY = 4096`, or the driver's own memory valid until the next call) — a **trust boundary** (a driver is native code).
- **`set_timer` always succeeds (this port always has one); `read_timer` = remaining ms, `None` only when disarmed** — expired ⇒ `Some(0)` (the C writes `0`); `beam_abi`'s `driver_read_timer` maps `None`⇒`-1` (deviation from `io.c`'s `0`/`0`).
- **The `beam_io → beam_abi`/`beam_alloc` edge is directionally legal (wave 5 → wave 0), cycle-free, no `*_dev` edge** (`beam_abi` = the frozen ABI to adapt, `beam_alloc`'s `Heap` = the driver's term arena).
  **Consequence:** `beam_abi`'s own `dlopen` loaders cannot use `beam_io::ddll`.
- **Readiness is edge-triggered** (`mio` `EPOLLET`), so a driver *must* drain to `EAGAIN` per callback.

## Known Issues
- **The A.4 driver-registry hooks here are correct and tested, but the running runtime does not route through this crate's host layer.** They live in `src/abi/host.rs` over `src/abi/table.rs`'s process-global `DriverTable`, and nothing outside `beam_io` references `beam_io::abi`/`make_loaded`/`AbiHost`/`DriverTable`, so this layer is exercised only by this crate's own tests.
  `beam_rt` serves the four slots through its own self-contained host (`crates/beam_rt/src/port/driver.rs`), which overrides all four hooks and publishes the current host around every driver callback — oracle-pinned (`beam_rt/tests/driver.rs` asserts `0,1,0,-1`) — and already delivers `{Port,{data,…}}`/`{Port,{exit_status,…}}` and `{fd,N}` `port_command`.
  `enif_alloc_env()` in a real NIF is a live env in the oracle / NULL here.
- **`outputv`-only entries are served on both write paths here; the runtime's own adapter is not.** `write_driver` makes a `beam_io`-hosted `outputv`-only entry receive its `port_command` bytes from both `Driver::output` and `Driver::ready_output`, pinned by `tests/abi_vector.rs` over `tests/fixtures/vector_driver.c`; `tools/differential/GAPS.md` §"A.4" records the `outputv`-only divergence for the **runtime's** adapter, whose adoption is a `beam_rt` handoff.
- **The C-ABI host layer is a floor; a driver must not stash `ErlDrvPort` beyond the callback.** With the context installed per callback (`install`/`clear` around each `DriverPort` call), a driver that keeps the handle and calls `driver_*` outside a callback (e.g. its own worker thread) gets the C's `-1` (a `driver_output` from a plain `std::thread` returns `-1`, its bytes dropped).
  The handle *pointer* is stable for the port's whole life (asserted in `tests/abi_async.rs`); the **installed context** is callback-scoped.
  `ready_async` receives no port (`erl_driver.h`), so a driver needing it there uses the handle it stashed in `start` — which works because `poll_async` runs inside a `DriverPort` method with the context installed.
- **`ErlDrvApi` slots served vs. deferred (handoff to `beam_abi`).** Only the four **driver-registry** slots are served as table slots through this crate's host layer; the port lifecycle & attributes, monitors & the port data lock (`driver_monitor_*`/`driver_pdl_*`) and the mutex/cond/rwlock/tsd/thread families are still `None` in `beam_abi`'s `DRIVER_API` (`DriverHost` has no method for them); the binary-refcount trio is deliberately `None` too (an `ErlDrvBinary` is exactly `{ orig_size, orig_bytes }`).
  Each deferred group names the `DriverHost` methods `beam_abi` must add; see `../../beam_abi/CONTEXT.md`.
- **The `control` reply's NULL-`*rbuf` arm diverges from the oracle.** When a driver's `control` returns `cres > 0` but pointed `*rbuf` at `NULL`, `DriverPort::control` answers the typed `badarg`; the oracle returns the empty list `[]` (`erts/doc/references/driver_entry.md` › *control*: "If `*rbuf` is set to `NULL`, an empty list is returned"; oracle-pinned on OTP 29/erts-17.1: a driver `control` doing `*rbuf = NULL; return 5;` answers `port_control(P,1,<<>>) == []`). `cres == 0` already answers `[]` (matching) and `cres < 0` ⇒ `badarg` (matching), so only the `cres > 0 && *rbuf == NULL` arm is wrong.
  Closable entirely here: the `if rbuf.is_null()` arm must answer an empty reply, not `badarg`. No fixture/test covers it today (`tests/fixtures/host_driver.c`'s `control` never nulls `*rbuf`).
- **`set_busy_port` is unmodelled, so a loaded driver cannot put its port in the busy state.** `AbiHost` leaves `beam_abi::DriverHost::set_busy_port` at its `-1` default, `Port`/`PortRegistry` carry no busy flag, and [`PortCommandOptions`](crate::PortCommandOptions)'s `nosuspend`/`force` are inert — so a driver's `set_busy_port(port, 1)` is a silent no-op and every `port_command/2,3` succeeds immediately.
  Oracle (OTP 29/erts-17.1, a `cc`-built driver whose `start` runs `set_busy_port(port,1)` + `driver_set_timer(port,300)` and whose `timeout` clears it): `port_command(P,D,[nosuspend])` ⇒ `false`; `port_command(P,D,[force])` ⇒ `error:notsup` for a driver **without** `ERL_DRV_FLAG_SOFT_BUSY` and `true` for one **with** it; `port_command(P,D)` **suspends** the caller until `set_busy_port(port,0)`, then returns `true` (measured ~301 ms).
  A **non-busy** driver's `[force]` is also `notsup` (the oracle checks the flag, not the state).
  **Scope split:** the state half (the `set_busy_port` host hook + a per-port busy flag + [`DriverFlags::SOFT_BUSY`](crate::DriverFlags) exposure + a `port_command` outcome) is additive and belongs here; the caller-blocking half (return `false` / raise `notsup` / suspend the process) is `erlang:port_command/2,3` in `beam_rt` (which today hardcodes `notsup` for `force` and ignores `nosuspend`: `crates/beam_rt/src/native/port.rs`).
- **The loaded-driver write path deliberately has no byte-count/remainder — do not add one.** The C's `output`/`outputv`/`ready_output` entry callbacks are **`void`** (`erts/emulator/beam/erl_driver.h:235,254`; `erts/doc/references/driver_entry.md`; there is no `ErlDrvOutputv` typedef), so the C discards the call's result and counts the whole command as written (`prt->bytes_out += size`, `io.c:1405`+`1408`, `:1517`+`:1520`), then frees the command buffer/vector (`cleanup_scheduled_outputv`/`cleanup_scheduled_output`) — it never re-queues unconsumed bytes.
  `write_driver` discarding the result plus `DriverPort::output`/`ready_output` consuming the whole drained buffer is therefore **exactly** the C, not a deviation. Oracle-pinned: a driver whose `output` consumes/emits nothing still answers `port_command/2 == true` with no `{Port,{data,_}}`, and so does an entry declaring neither `output` nor `outputv` (`no_output_callback`).
  The `int` "negative = not accepted" contract belongs to the **opposite** direction — the driver→emulator `driver_output`/`driver_output2`/`driver_outputv`/`driver_output_binary` (`io.c:6349,6397,6469`; `-1` = invalid port, `0` = delivered/closing) — which `AbiHost::output` already renders as `0`/`-1`.
- **File sizes.** `src/abi/port.rs` 1017 (source half 869 + its 8 in-module tests), `src/abi/host.rs` 902 (source), `src/abi/host_tests.rs` 774 (its test module), `src/abi/table.rs` 586, `src/abi/job.rs` 530, `src/abi/mod.rs` 115.
  `host.rs`'s in-module suite lives in the sibling `host_tests.rs`, included as `#[cfg(test)] #[path = "host_tests.rs"] mod tests;` so the source half stays under the workspace's ~1000-line convention while the tests keep `super::` access to the module's private items (`DRIVER_HEAP_WORDS`, `AbiHost::heap`); `port.rs`/`table.rs`/`job.rs` keep their suites in the source file (each source half is well under 1000).

Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` **GREEN** (sandbox `$HOME` read-only — always the wrapper; never `cd`).
- In-module `src/abi/` suites: **36** (`host_tests.rs` 18, `port.rs` 8, `table.rs` 7, `job.rs` 3).
