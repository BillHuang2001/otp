# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in `tcp_inet` driver (`mod.rs`): one non-blocking TCP socket behind one port — `inet_drv.c`'s `tcp_inet`, under `gen_tcp`/`inet_tcp`; its datagram half `udp_inet` (`udp.rs`), under `gen_udp`.
Frozen names `DRIVER_NAME = "tcp_inet"` / `UDP_DRIVER_NAME = "udp_inet"` (`port_info(Port, name)`), registered by `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, `from_socket(fd)` (owned), or `adopt_prebound(ctx, fd, stype)` (`INET_REQ_FDOPEN` — borrowed: port-lifetime, never closed here); the descriptor a numeric `accept`(26) completion hands over (`InetAsyncResult::Accepted`) belongs to that completion's consumer.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
`erlang:port_control(Port, Op, Data)` carries an integer, `beam_rt` forwards its decimal string, and `PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`, so both drivers decode it here before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a decimal command (optional `-`, ASCII digits accumulated mod-2³², the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; non-decimal ⇒ `None`, so every named verb keeps its path byte-for-byte; unmatched ⇒ `Opcode::Unknown`. The wrapping is observable: an `Op` below the magic matches no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, shared `inet_ctl`): one numberspace, each number a `case` of exactly one, so a number owned by *the other* driver's switch is owned by neither ⇒ `[0]exbadport`.
- `Opcode` — one variant per table row (same names, numbers) plus `Unknown`, with `ALL`/`code`/`from_code`/`scope`/`name`, `not_served() -> BeamError` (typed `unsupported` naming opcode and switch).

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A decimal command decodes to an opcode, anything else is the named verb of the same row, and both run one body so replies are identical. `s` = served (whole arm); `ref` = the C's refusals reproduced, success path `Err(Opcode::not_served())`; an error name is the `[0]`-tagged reply (`einval` = `[0]einval`, …), `⇒` the success reply. Three `erl` matrices byte-compare every row against the system driver: `opcode_tests.rs::oracle_matrix` (`tcp_inet`, 80 calls), `opcode_tests_udp.rs::oracle_matrix` (`udp_inet`, 89), `opcode_tests_states.rs` (11 rows), over the bare/opened/listening-or-bound/connected/post-close states in one `erl` run.

Both drivers are symmetric on every shared `inet_ctl` arm; only the per-driver switches, the `Fdopen` type guard and `Sendfile` differ.

#### Packed address
- Packed address (`bind`/`connect`/datagram source): `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag ⇒ `BadArg` (DNS/IPv6 out of scope). Layout = `inet_get_address`'s (`:4890`): family byte, the host-order port via `put_int16` (MSB first = big-endian, `../beam/sys.h:1314`), then raw `sin_addr` bytes in network order; `load_address` (`:1916`) decodes it with `get_int16`; `addrlen` 7 for IPv4 (`:1156`-`:1160`).

### `mod.rs` — the TCP driver
- `DRIVER_NAME: &str = "tcp_inet"`; `make_tcp_inet()`; `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket. Constructors `new()` (socket-less registry factory; the `open` verb creates the socket, the C's `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts + probes kernel state: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound` (`Fdopen`(13)).
- The entry's capability word is `DriverFlags::SOFT_BUSY` — the C's `ERL_DRV_FLAG_SOFT_BUSY` beside `ERL_DRV_FLAG_USE_PORT_LOCKING` (`inet_drv.c:1374`), and the one bit of that pair with a counterpart here; `Driver::flags()` reports it and nothing else.
  `erlang:port_command(Port, Data, [force])` reads it (`erl_bif_port.c:195-198` refuses a flag-less driver with `notsup`, `io.c:1731` clears `busy_flgs` under `force`), so a forced command on this driver is `PortCommandOutcome::Done` — the oracle's `true` (`soft_busy_tests.rs`).
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`/`state_code()`) is the C's `INET_STATE_*`; `eof()`/`peer_closed()` are the latched read EOF / peer close, `connect_error()` the late `SO_ERROR`.
- Fake endpoints `name_addr`/`peer_addr` (`desc->name_ptr`/`peer_ptr`): installed/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address`, reported by `Name`/`Peer`; `Getladdrs`/`Getpaddrs` ignore them, and only `len == 0` clears them (a `close` leaves them).
- `PeerClose` (`TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND`) — `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event (*The peer-close ladder*): registration released, the socket never read or written again, the one-shot `closed`/`enotconn` replies armed (first `recv`/`send` answer `closed`, later ones `enotconn`).
- Control verbs — `Driver::control` takes the packed payload as raw bytes in both wire forms (see [`opcode`](#opcoders--the-numeric-control-opcode-bridge)); an unknown non-numeric verb is `BadArg`.
- `connect` completes synchronously under a bounded wait. `EINPROGRESS` settles in-call via `sys::wait_connected(fd, connect_wait_ms(timeout_ms))`: `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`; `Some(errno)` ⇒ `[0]++<lowercase errno>`, errno kept in `connect_error`; `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout`. Budget `CONNECT_WAIT_CAP_MS = 30_000` (negative — `INET_INFINITY` — ⇒ cap, `0` ⇒ one poll, positive ⇒ clamped), so `EINPROGRESS` never yields the C's `[1]++async_id_be16` (a divergence; `prim_inet:connect_cmd/3` maps `{ok,[]}` to `ok`).
- Readiness & flow control: `EPOLLET` ⇒ every callback drains to `EAGAIN`; the socket is one descriptor ⇒ one registration with a flipped `Interest` mask — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and arms write readiness) or an over-budget `connect` is in flight, dropped when the queue drains. Output left at a latched peer close is dropped (`tcp_clear_output`); writes use `send(2)` + `MSG_NOSIGNAL`.
- Accept readiness IS the listener's read readiness. `FD_ACCEPT` is `ERL_DRV_READ` (`:631`) ⇒ one `Interest::READABLE` registration, no separate accept interest: `verb_open` registers it, `verb_listen` arms nothing (the C's `sock_select(INETP(desc), FD_ACCEPT, 1)` fires only on the first queued accept, `:12224`), `async_accept` re-arms on every enqueue (an `epoll_ctl(MOD)` re-reporting a connection that arrived while nothing was queued), `disarm_accepts` deregisters once the list empties (an op taken, a successful accept `:13538`-`:13562`, a due timeout `:12607`-`:12611`) — only while `is_listening()`, so a connected recv or a `Connecting` write interest is never disturbed; a ghost `EAGAIN` stays armed (the C's `goto done`), and `drive_async_ops` still makes one non-blocking `accept(2)` attempt.
- A command on a socket-less or unconnected port is consumed and answered out of band, never dropped. `init_caller` (`:1820`-`:1890`) runs first, size-only: a malformed/untagged command latches `DriverFailure::posix(EINVAL)` (`io.c:7273`), so `PortRegistry::reap_failures` closes the port after the round (`port_command/2` still `true`, every later command the oracle's `badarg`); a well-formed prefix on a port that cannot write stages `Error(ENOTCONN)` (`tcp_inet`, `:12674`) / `Error(EINVAL)` (socket-less `udp_inet`, `:15068`) with the port alive; an empty or non-ETF tag stages no reply (`echoable_caller_tag`). The named verbs answer `[0]enotconn`(stream)/`[0]einval`(datagram).
- One socket, one port — the C's `INET_REQ_ACCEPT` creates a second Erlang port; this seam cannot, so the numeric request reports the descriptor inside its completion (`Accepted { fd }`, never stored, so no teardown closes it) and the runtime opens the second port (*Handoffs* (0)); only the named `accept` transfers this port. N queued accepts answer their own id in enqueue order.
- No completion is produced inside a control call — the id is the whole reply; the production points are `ready_input`, the port timer (`next_timeout`/`timeout`) and the round's `drive_async` (which also serves data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` first.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, only under a framing `{packet, N}` (never raw); the C's `desc->i_buf`, cleared when the socket is replaced/closed. A `{packet, …}`/`{line_delim, …}` change with bytes buffered is not flushed: the next `recv` re-decodes them under the new options (a switch to `raw` delivers the retained buffer verbatim).
- Ownership: `prebound` (`desc->prebound`) is set only by `adopt_prebound`, cleared by `adopt`, honoured by `close_socket`'s early return — an owned descriptor (`open`/`accept` create, `from_socket` adopts) is closed on `stop`, the `close` verb and `Drop`, a prebound one only deregistered.

### `udp.rs` (`pub`) — the datagram driver
- `UDP_DRIVER_NAME: &str = "udp_inet"`; `make_udp_inet()`; `UdpInetDriver` — one datagram socket: `new()` (socket-less; the `open` verb creates it), `from_socket(fd)`, `adopt_prebound` (`stype` the operand's `INET_TYPE_*` tag; stream and dgram both admitted); `prebound`/`stat`/ownership follow the stream driver's, `socket()`/`state()` read the same `InetState`.
- The entry's capability word is **empty**: the C declares `ERL_DRV_FLAG_USE_PORT_LOCKING` only (`inet_drv.c:1432`), so `Driver::flags()` is `DriverFlags::empty()` and `erlang:port_command(U, D, [force])` is the oracle's `error:notsup` (`erl_bif_port.c:195-198`), not `true`.
  `RamFileDriver` is the same (`ram_file_drv.c:126` declares `0`), pinned beside it in `soft_busy_tests.rs` so neither gets a `SOFT_BUSY` bit it does not have.
- Control verbs — the same two wire forms over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_getopts` (`setopts` goes through `setopts_with_effects`, whose `ctx`-carrying form also arms and can stage a `Passive`). `open` caches `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only; `bind` refuses any state but `Open` with `exbadport` and reports the bound port; `connect` installs the default peer (`EISCONN` = "already connected"), an empty operand dissolving to `Open`, the operand `[Timeout(4), address]` or a bare packed address.
- Reception has two paths; the source address rides only the asynchronous one. The source cannot ride the byte-only input queue, so `PACKET_REQ_RECV`(60) queues on the shared async slot with the 7 packed source bytes as header. The named `recv` verb is this floor's read-now convenience (no such control op in the C): one `recvfrom(2)`, the payload pushed to the port input queue and the eight-byte `[1, port_hi, port_lo, a, b, c, d]` reply; `EAGAIN` ⇒ a bare `[1]`, socket-less ⇒ `einval`. `Driver::ready_input` completes a queued operation and with none queued reads nothing — the property that makes the active path safe.
- `send` (`verb_send`, the C's `packet_inet_command`) takes two wire forms, the plain one authoritative: `wire::split_address`'s `[address][payload]` first, and only when that refuses `wire::split_caller_ref`'s `[n:be16][n tag bytes]` `prim_inet` prefix (`n >= 1`, `2 + n` fits, `arg[2] == 131`) then `wire::split_datagram`'s `[address][anc_len:be32][anc][data]` — truncated ⇒ `einval`, non-zero `anc_len` ⇒ typed `unsupported`, neither keeping rule 1's `badarg`. A queued command needs only an *open* socket; the destination comes from the command: `write_command` strips one caller tag, stages the out-of-band refusals, then `write_pending` guards `!IS_OPEN`, parses the queued front with the same grammar and picks `send(2)` when connected (address ignored) or `sendto(2)` with it when not — so `gen_udp:send/4`'s unconnected form really sends (`stat.output(payload.len())`); a socket-less port, a malformed operand or a command in neither form is `BadArg`, bytes never consumed, and once the queue drains `settle_command` stages `{inet_reply, Port, ok | {error, Reason}, Tag}` from the tag taken verbatim (no tag, or the C's zero-length `[0,0]` tag, stages nothing).
- Deliberate non-mirrors: a `getopts` on a socket-less port answers a well-formed reply where the C's `inet_fill_opts` can walk a `NULL` descriptor. Absent by design (a typed error): `{deliver, port}` (the `term` mode is this channel's default and only expressible mode) and ancillary data (`recvmsg`/`sendmsg`/`IP_PKTINFO` cmsgs), the `INET_REQ_PEER`/`INET_REQ_NAME` named forms (the numeric `Peer`(4)/`Name`(5) opcodes ARE served), IPv6/SCTP/Unix sockets and DNS resolution.

### `async.rs` + `accept.rs` (private) / `udp/async.rs` — the asynchronous-operation queue
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword; `udp/async.rs` = the datagram bodies under the same hook names).
- `AsyncQueue` — one receive slot (`INET_MAX_ASYNC = 1`, a second concurrent receive `[0]ealready`) plus a multi-operation accept list (never `ealready`; `accept.rs`'s `AcceptQueue`); `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- The multi-accept bit is sticky. `AcceptQueue::multi` is the C's `INET_F_MULTI_CLIENT` bit of `desc->inet.state`: `enqueue` latches it when a second accept joins the list (the C's `INET_STATE_MULTI_ACCEPTING`, `:12189`-`:12194`), `take`/`expire` clear it only when the list is left empty (the C's restore, `:13536`-`:13540` / `:12607`-`:12611`), `take_all` clears it with the teardown drain, and `state_bits` derives `GETSTATUS`'s `0` / `INET_F_ACC` / `INET_F_ACC|INET_F_MULTI_CLIENT` from it — never from the list length. Measured (OTP 29.1.1): bare `9`; one queued (infinity) `41`; two `297`; `[inf, 50ms]` after the 50 ms firing (reporting the head's id 0, id 1 surviving) `297`; two queued with one served `297`; both served `9`; a further single enqueue `41`.
- The accept timer is per port; its entries are a separate sorted list. `AcceptQueue::timers` is the C's `desc->mtd` (one `MultiTimerData` per *finite* deadline): `enqueue` inserts it in sorted position (`add_multi_timer`, `:15744`-`:15790`), `next_deadline`/`timeout_due` read only the earliest entry, and `expire(now)` performs one `fire_multi_timers` iteration (`:15650`) — consumes that entry, removes the accept list's head (`tcp_inet_multi_timeout` `:12600`-`:12615` → `remove_multi_op` with `timeout_p == NULL`, `:2379`-`:2405`) and answers the head's id. Because the firing does not remove the *head's own* entry, a head owning a later deadline stays armed and later expires the next head (`[500, 50]` reports id 0 at ~51 ms and id 1 at ~501 ms — measured); only a successful completion cancels its own entry, through `take` (`deq_multi_op` + `remove_multi_timer`, `:13553`-`:13559`); `take_all` clears the list with the accepts.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, from 0, taken before the capacity check so a *refused* enqueue still consumes an id; wraps at 65536 (the 255→256 step carries into the high byte). `deadline_for(timeout_ms)` — a negative timeout is the C's `INET_INFINITY` (`None`), `0` "now", positive an `Instant`; `parse_recv_operand`/`length_too_large` decode `Timeout(4), Length(4)` (the accept `Timeout(4)` operand is `accept.rs`'s); `async_ok_reply` builds `[1]++<<Id:16/big>>`.
- Hooks: `try_complete_recv` (read path), `async_ready_input` (readiness), `async_timeout` (port timer), `drive_async_ops` (the round's drive point), `drain_closed`; the accept entries `async_accept`/`accept_ready_once`/`disarm_accepts`/`accepts_completed`/`serve_accepts`/`accept_timeouts` are `accept.rs`'s — the teardown drain answering `{error, closed}` once per pending operation, from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) sits beside the queue in each driver: one prefix per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.

### Active-mode input delivery (`active.rs` = the TCP half, `udp/active.rs` = the datagram half)
Each arriving input goes to the port's owner on the crate's `{active,…}` channel (`ActiveInputEvent::{Data,Passive,Error}`, `deliver_active_input`, `take_active_inputs`) — never `{Port,{data,…}}`/`CompletionEvent`; the C splits the same way (`erl_drv_output_term` to `desc->dport`, `erl_drv_send_term` to the caller).
- Shape — one `ReadMessage` per delivered unit. A datagram's `header` is the 7 packed source-address bytes (`wire::pack_address`, `inet_drv.c:4896`), its body the payload. A stream's `header` is the `{header,N}` option only (`desc->hsz`, written only at init `:10922` and the setopts arm `:6931`/`:6936`, so 0 unless set) — not the framing header, which `frame::extract` strips (`packet_get_body()`, `../beam/packet_parser.h:152-164`, from `tcp_reply_data` `:4285`/`tcp_reply_binary_data` `:4314`) — its body the rest of one frame. The `hsz` half of the C's `(mode == INET_MODE_LIST) || (hsz > len)` arm (seven reply functions: `:2760`/`:2779`/`:3182`/`:3951`/`:4000`/`:4038`/`:4142`) IS this layer's: `header::split_payload` (one helper for both paths) yields the narrow header + binary tail, the `hsz == len` header + empty tail, and for `hsz > len` the whole payload as the header with no body (the flat list); only the `mode` half is the runtime's. The datagram drivers do not apply `hsz` (handoff (a0)).
- The C's message builders (the runtime's rendering ground truth): `packet_binary_message` `:4106` (`{udp,S,IP,Port,Data}`, `LOAD_TUPLE 5` `:4158`; a 6-tuple with `recvmsg` ancillary data `:4155`), `tcp_message` `:3987` (`{tcp,S,Data}` `:4002`/`:4014`), `tcp_binary_message` `:4026`, `{tcp_closed,S}` `:4073`, `{tcp_error,S,Atom}` `:4090`, `packet_passive_message` `:4215`; address/header bytes are `LOAD_STRING`/`load_address` (lists of small ints), the payload a binary under `{mode,binary}`; the dispatch point is `packet_reply_binary_data` `:4335` (`tcp_reply_data` `:4279`, `tcp_reply_binary_data` `:4306`).
- The third event is a read error — `Error(InetReason)`, the term-free `{tcp_error,S,Reason}` (`tcp_error_message`, `:4079`) / `{udp_error,S,Reason}` (`packet_error_message`, `:4245`), from the C's `tcp_recv_error` active arm (`:12871`), `tcp_send_or_shutdown_error`'s (`:13625`, a reset under `{show_econnreset,true}` only) and `packet_inet_input`'s (`:15486`, any non-`ERRNO_BLOCK` `recvfrom` failure). It precedes the close it accompanies (the C runs `tcp_error_message` then `tcp_closed_message`, `:12880`-`:12881`), so `{tcp_closed,S}` is the `port_closed()` latch the same callback sets, never a second event; a datagram port has no close message and keeps running. Passive mode reports the same reason as an `{error, Reason}` completion instead (`async_error_am_all(error_atom(err))`, `:12877`) and no event. The atom is `InetReason::atom_name()`, rendered by the runtime (like `Passive`) from the driving port's driver name.
- One unit at a time; the loop stops the moment the mode flips (the C's `if (!desc->inet.active)`, `:13108`-`:13114`): one `{packet,N}` frame per message (the remainder stays in `pending_input`), exactly one message per read burst in `{packet,raw}` (`:13099`-`:13123`); the burst is bounded by `{read_packets}` (`INET_LOPT_UDP_READ_PACKETS`, default `INET_PACKET_POLL = 5`, `:1072`/`:14508`) — `packet_inet_input` (`:15361`) reads at most that many datagrams per call (`:15367`, `while (packet_count--)` `:15378`), `EAGAIN` ending it early, the passive path returning after the first packet (`:15570`-`:15574`). `stat.input(len)` counts each delivered payload (`:15513`).
- The matrix (`INET_CHECK_ACTIVE_TO_PASSIVE`, `:1552`-`:1560`, per delivered packet via `:4302`/`:4329`/`:4352`): `{active,true}` never changes; `{active,once}` flips silently (the following bytes stay in the kernel until the next arm or a passive read); `{active,N}` decrements and on 0 flips and stages one `Passive` (`packet_passive_message`, `:4215`). `Passive` has exactly two sources — the delivery that spent the last credit and the `setopts` walk; `{active,true}`/`{active,false}` never emit one.
- `{active,N}` is `INET_MULTI` (3) plus a trailing big-endian 16-bit counter. `opt_state::set_active` accumulates it (`ac += nval`; past the `Sint16` range ⇒ `einval` at `:6985` after `desc->active = INET_MULTI` at `:6974` — no rollback), clamps a negative sum to 0 and turns a 0 sum into `INET_PASSIVE` inside the walk (`:6993`-`:6998`); any non-multi `{active,…}` zeroes the counter (`:6999`-`:7000`). `set_options_tracked` reports that out of the walk (`landed_at_zero`, never cleared) and each driver's `after_setopts` turns it into the delivery.
- Arming is a driver-side state gate, not a poller mask. The C selects the read side on `active > 0` (`sock_select(desc, FD_READ|FD_CLOSE, …)`, `:7944`-`:7987`; setopts `:7966`, tcp connect `:12126`/`:14286`, udp open/fdopen `:14621`/`:14682`), deselects it when a delivery spends the grant (`:13106`-`:13114`) and re-selects it for a queued async recv (`tcp :12317`, only when `timeout != 0`; udp `:15496`). `poller::Interest` has no empty mask and `mio`'s epoll is edge-triggered (`EPOLLET`), not one-shot, so `TcpInetDriver::read_armed` reproduces that selection while the registration lives on: cleared by the delivery that spends an `{active,once}`/`{active,N}` grant; set by an armed grant (re-arming with `set_interest(…, Interest::READABLE)` — an `epoll_ctl(MOD)`, a fresh edge for buffered data, never a re-register per flip), by a queued `TCP_REQ_RECV`, by the synchronous `recv` verbs and on every fresh connection. While clear, `async_ready_input` reads nothing, so the peer's bytes wait in the kernel instead of landing on the passive `{Port,{data,…}}` channel; a never-armed port keeps its `read_armed = true` eager read into the port queue.
- Readiness dispatches on state, exactly once. `TcpInetDriver::ready_input` takes the C's `tcp_inet_input` shape (`:13461`/`:13598`-`:13599` — accept dispatch / `tcp_recv(desc,0)`, never touching `hsz`; `tcp_deliver` `:13042` loops packet-by-packet, `:13069`/`:13094`): a connected + active socket with no queued `TCP_REQ_RECV` goes to `active_delivery` only; the accept ladder, a queued receive and a passive connection's bytes-into-the-port-queue stay with `async_ready_input` — running both is a defect (`read_available` would starve the active path).
- The inline burst is TCP-only and only for `{active,once}`/`{active,N}`. `inet_set_opts`'s tail returns 2 (`trigger_recv`) only for `SOCK_STREAM` with `!old_active`, the new mode `once`/`multi` and an unchanged `{packet,…}` (`:7955`-`:7961`), and `INET_REQ_SETOPTS`'s consumer reads 2 as an inline `tcp_recv` + re-arm (`:11145`), so a waiting byte is delivered inside the ctl; `{active,true}` returns 1 ⇒ arm only (this floor pre-reads nothing), and a UDP re-arm always waits for the next readiness event (both `/* XXX: UDP sockets could also trigger immediate read here NIY */` comments, `:7949`/`:7969`). `{deliver,port}` divergence: *Handoffs* (a).

### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- The record walk — `set_options`/`get_options`/`set_options_tracked`, `Step { Done(usize), Refused }`, the code table (`INET_*`/`TCP_*`/`UDP_*`) and the store `SocketOptions` (the C descriptor's fields, incl. the `{active,N}` counter and the 9216-byte `{buffer,…}` default). Each code is offered to `opt_state` then `opt_sys`; an unclaimed one is the C's `default` ⇒ the whole reply `[0]einval`, and a `setopts` refused that way still applies the records already passed. `OptScope { stype, family, protocol }` is the cached descriptor state every gate reads (`0` = unset), built as `OptScope::new(stype, family, IPPROTO_TCP|IPPROTO_UDP)` by both drivers' setopts and `getopts` sites.
- Wire forms: five-byte `[opt, val_be32]` records walked `while (len >= 5)`; `getopts` takes one-byte codes (`while (len--)`, an empty payload answering a bare `[1]`) and answers `[1]++[opt, val_be32]*` in request order — variable-length codes (`{active,N}`, `linger`, `netns`, `raw`, `bind_to_device`, multicast, `pktoptions`) carrying extra bytes both ways.
- The two families: `opt_state.rs` (descriptor fields + `stype`/protocol gates, the two watermark pairs clamped both ways) and `opt_sys.rs` (every `SO_*` code with local Linux uapi constants, the nine `propagate = 1` codes — `priority`/`tos`/`ipv6_v6only`/`tclass`/`bind_to_device`/`recvtos`/`recvtclass`/`ttl`/`recvttl`, a failed `setsockopt` there being the whole reply — and the non-`int` shapes). Every value is stored/reported only; acting on `{packet,…}`/`{mode,…}` is the read path's and the runtime's. The three C misses are preserved, each observable: a failed `getsockopt` truncates that record only (later codes still tried); a platform-less option answers a literal `0`; a code with no `case` is `RETURN_ERROR()` ⇒ the whole reply `[0]einval`.

### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant IS the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`; unsupported (their bodies need the C's term-building `PacketCallbacks`): `Http`/`HttpH`/`HttpBin`/`HttpHBin`/`SslTls`. `PacketLength { Complete, NeedMore, Invalid, Unsupported }` is `packet_get_length`'s `> 0`/`0`/`< 0` plus an explicit "not implemented" (`as_error()`: `Invalid`⇒`badarg`, `Unsupported`⇒`notsup`); `Complete(len)` is the total length including the header.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — `packet_get_length`'s four arguments; `Default` = `{packet, raw}`, delimiter `\n`, no limits; `max_plen == 0` is "no limit" (`INT_MAX - hlen`), bounding the payload, never the frame. `PacketType::payload_range` is the `packet_get_body` strip (removed for `Len1`/`Len2`/`Len4`, FCGI padding subtracted for `Fcgi`; every other type as is, so `{packet, line}` keeps its delimiter). Three quirks: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter, both strictly after; `Raw` on an empty buffer is `NeedMore`, not `Complete(0)`.

### `frame.rs` (private) — the framing glue (read + send)
Bridges `SocketOptions` to the pure decoder on both paths (the C's `tcp_remain`/`tcp_reply_data`/`tcp_send`); all `pub(super)`: `options` (`trunc_len` 0 — it grows a `Vec`); `framed` (`None` only for `Raw` and an out-of-range code); `write_header` (the `send` verb's 1-/2-/4-byte big-endian header); `extract` — exactly one frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.

### `sys.rs` (private) — the raw socket syscalls
Every `unsafe` block of the drivers lives here (each with a `// SAFETY:` rationale): the socket/bind/listen/accept/connect/getsockopt/setsockopt/read/send/shutdown/close wrappers, the int-option pair, `socket_family` (the `FDOPEN` pre-check probe), `local_address`/`peer_address` — one `getsockname(2)`/`getpeername(2)` into a `sockaddr_storage` decoded by a private `decode_inet_address` (`AF_INET` only; any other family is the C's failure ⇒ `NAME`/`PEER` answer their errno reply) — the option helpers (`get_socket_linger`/`set_socket_linger`, `get_socket_bytes`/`set_socket_bytes`), the datagram family (`sendto(2)` unconnected, `send(2)` connected, one `recvfrom(2)` returning the payload length with the source `InetAddr`) over the shared `has_peer`/`local_port`/`close_fd`, and the interface/name-service floors. `wait_connected(fd, timeout_ms)` is the synchronous completion behind `INET_REQ_CONNECT`: one `poll(2)` for `POLLOUT` (deadline from an `Instant`, `EINTR` retried) then `getsockopt(SO_ERROR)` ⇒ `Some(0)` established, `Some(errno)` failed, `None` expired.

## Accepted-socket option inheritance — `tcp_inet_copy` (`from_accepted` / `SocketOptions::inherited_from`)
The C's `tcp_inet_copy` (`inet_drv.c:11795`-`:11845`, call sites `:12236` numeric `INET_REQ_ACCEPT`, `:13510`, `:13580`) copies a fixed field set from the listener's descriptor onto the freshly-started accepted one; here the runtime opens the second port, so this crate owns the copy, as an additive inherent API (no `Driver`/`DriverContext` change):
- `TcpInetDriver::from_accepted(fd: RawFd, listener: &TcpInetDriver) -> Result<TcpInetDriver>` — adopts `fd` (owned, exactly like [`TcpInetDriver::from_socket`], which still probes the kernel state), then applies the listener's inherited options plus the cached `stype`/`family`; it is the only copy path, because `INET_REQ_FDOPEN`'s `adopt_prebound` copies nothing (the C's `inet_ctl_fdopen`, `:5223`-`:5282`).
- `SocketOptions::inherited_from(&self, parent: &SocketOptions) -> SocketOptions` (`pub(super)`, `opt.rs`) is the mapping in ONE place, pure and unit-tested; it names every field explicitly (no `..*self`) so a new field forces a decision.
- Inherited (C field → our code): `inet.mode`→`mode` (24), `inet.exitf`→`exit_on_close` (26), `inet.deliver`→`deliver` (25), `inet.htype`→`packet` (23), `inet.psize`→`packet_size` (32), `inet.stype`/`inet.sfamily`, `inet.hsz`→`header` (21), `inet.bufsz`→`buffer` (20), `desc->high`/`low` (27/28), `desc->send_timeout` (30), `desc->send_timeout_close` (35), `tcp_add_flags & (SHOW_ECONNRESET|LINGER_ZERO|NO_READ_AHEAD)`→`show_econnreset` (39)/`linger_zero`/`read_ahead` (49), plus the listener's busy msgq limits (`erl_drv_busy_msgq_limits` READ_ONLY from the parent, written to the child, `:11835`-`:11845`)→`msgq_high`/`msgq_low` (36/37).
- Not inherited, each verified: `active`/`active_count` (`inet_start` `:10932`-`:10933` zeroes them; measured — an `{active,true}` listener's accepted socket reports `active` 0), `debug` (`:10975`), `netns`, `read_packets` (a `udp_descriptor`-side field), `line_delim` (`desc->delimiter` is outside the copy list), `delay_send` (`TCP_ADDF_DELAY_SEND` is outside the mask), `buffer_set` (the C's `INET_FLG_BUFFER_SET` lives in `desc->flags`, which `prep_tcp_inet_start` clears at `:10967`; only the `{buffer,N}` walk sets it), and kernel socket options (the kernel inherits those across `accept(2)`).
- The split with the Erlang side: `{active,…}`, `nodelay`, `keepalive`, `delay_send`, `priority`, `linger`, `reuseaddr` are re-applied by `prim_inet:accept_opts/3` (`erts/preloaded/src/prim_inet.erl:502`-`:517`) — a different half, pinned separately by `accept_opts_tests.rs`; a code missing from `tcp_inet_copy` still arrives, but only because Erlang re-sends it.
  The copy itself is the driver's, and the registry route below carries it to the port the runtime opens.
- The **registry route is available now**: `PortRegistry::driver_as::<TcpInetDriver>(listener)` hands out the listener's own driver through the port layer's `Box<dyn Driver>` (the `Driver: core::any::Any` supertrait + `downcast_ref` seam), so `TcpInetDriver::from_accepted(fd, listener)` is reachable from a port and not only from a driver the caller already owns.
- The obligation stays with the runtime: `beam_rt` must open the second port with **that** constructor — `PortRegistry::open` over `TcpInetDriver::from_accepted(fd, listener)` — rather than `TcpInetDriver::from_socket`, which inherits nothing; the served `INET_REQ_FDOPEN` is the other, copy-free route.
- `inherit_tests.rs` pins the whole route end to end: the listener opened as a registry port, the reactor round producing the `Accepted { fd }` completion, the `driver_as` downcast, `from_accepted`, and the accepted driver opened as a second port whose `getopts` reply carries the listener's inherited block (and not its `{active, …}`).

## The peer-close ladder — reset vs end-of-file, and the two discovery routes
`PeerClose` models the C's three independent flags — `TCP_ADDF_DELAYED_CLOSE_RECV` (`:855`), `TCP_ADDF_DELAYED_CLOSE_SEND` (`:856`), `TCP_ADDF_DELAYED_ECONNRESET` (`:862`) — plus the two reasons it owes, both `Option<InetReason>` with `None` meaning `closed`: `delayed_reason` (what the deferred reply answers, `TCP_ADDF_DELAYED_ECONNRESET` generalised into the `error_atom(err)` a read error or a reactor discovery carries) and `observed` (what the operation that discovered the close reports, read through `observed_reason()`).
- The receive ladder clears both close one-shots and, when the reset bit is latched, reports `econnreset` and clears it (`:12279`-`:12288`); otherwise `closed`; with neither latched, `enotconn`. The send ladder clears only the send one-shot and leaves the reset bit armed for the next receive (`:12681`-`:12692`) — so a send never consumes the receive's `econnreset`.
- `econnreset` appears only when the observation was an `ECONNRESET` and `{show_econnreset,true}` (`:13190`, `:13615`) was in effect at that moment; a clean end-of-file is always `closed`.
- Two discovery routes, one caller-visible sequence. A close the `recv` verb discovers answers inline (`CloseSource::Read { error, report: ReadReport::Answered }`): a clean end-of-file arms the send one-shot (`tcp_recv_closed` `:12816`), a read error (`error: Some(errno)`) arms nothing, `tcp_recv_error`'s `:12849`-`:12890` arm. A close the reactor discovers (`ready_input`, possible here because the socket keeps its read registration for its life) arms the receive one-shot too (`ReadReport::OwedToNextRecv`) and carries the reason in `delayed_reason`, because in the C the first receive is always the discoverer and answers from `async_error_am_all(am_closed/error_atom(err))` (`:12829`/`:12877`) — the reply is owed either way, so the user sees `closed`/`econnreset`/the errno then `enotconn` on both routes.
- Teardown at the latch — the C's `tcp_desc_close`. A close de-registers the socket then closes the descriptor (fd closed, `pending_input` cleared, `state = InetState::Closed`) at the C's three `tcp_desc_close` discovery sites: always for a write discovery (`tcp_send_or_shutdown_error`, `:13670`), and for a read discovery (`tcp_recv_closed` `:12824`-`:12827`, `tcp_recv_error` `:12872`-`:12875`) only under `exit_on_close != 0`, the `exitf = 1` default (`:10929`), `erl_inet_close` (`:5098`-`:5117`) being its closing half. Under `{exit_on_close,false}` the C only stops selecting for read (`desc_close_read`, `:5083`-`:5098`, never touching `desc->state`), and a prebound descriptor keeps both its fd and its state (`erl_inet_close`'s `else if` arm, `:5101`-`:5116`). `peer_close.rs`'s `tears_down_on_close`/`close_descriptor` are the two halves; the latch does not run `close_socket` (which resets `peer_close`/`read_eof`), while the C keeps `desc->tcp_add_flags` across `tcp_desc_close`. Because the teardown makes `!is_connected` true, `async_recv`/`verb_recv`/`verb_send` read their armed one-shot before the connection guard — the C's flag-before-state order (`:12279`-`:12286`, `:12681`-`:12692`).
- Residual: an `{active, _}` socket with `{exit_on_close,true}` takes the C's `driver_exit(desc->inet.port, 0)` arm (`inet_drv.c:12831` in `tcp_recv_closed`, `:12876` in `tcp_recv_error` with the errno) and kills the port, which this floor does not model — its teardown predicate is `false` whenever `options.active != 0`, so an active socket's peer close only latches and de-registers.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: operational socket failure ⇒ the `[0]`-tagged reply; malformed argument / unknown named verb ⇒ `BeamError::BadArg`; I/O syscall failure ⇒ `BeamError::Io`; undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- One `Driver` is one port: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port), only the named verb transfers the port.
- `unsafe` only in `sys.rs`; the `Driver`/`DriverContext` seam is frozen; a grown source half splits its suite into a sibling test module (*Known Issues*).

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
Rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted` and the registry drains are the crate doc's *Handoffs*; only the driver-family seams are here, each needing a change outside `src/drivers/inet/`.
- (0) The accept completion's second port is the runtime's, and the seam it needs is available now. The listener side is complete (id reply, multi-op list, arm/disarm, descriptor handed over owned), and `PortRegistry::driver_as::<TcpInetDriver>(listener)` hands out the listener's own driver through the port layer's `Box<dyn Driver>` (the `Driver: core::any::Any` + `downcast_ref` seam), so `TcpInetDriver::from_accepted(fd, listener)` — the `tcp_inet_copy` inheritance above — is reachable from the port itself, exactly where `beam_rt` is when the `Accepted { fd }` completion arrives.
  The runtime's obligation stands: `beam_rt` opens the second port with **that** constructor, `PortRegistry::open` over `TcpInetDriver::from_accepted(fd, listener)`, and never with `TcpInetDriver::from_socket`, which inherits nothing; the served `INET_REQ_FDOPEN` (copy-free `adopt_prebound`) is the other, inheritance-free route.
  `InetAsyncResult::Accepted { fd }` is adopted that way **or** closed by the runtime — this crate never closes it — and `beam_rt` then renders `{inet_async, Listener, Id, {ok, NewPort}}` (the C's `send_async_ok_port` shape `prim_inet:accept0/3` matches); a refused `from_accepted` keeps its errno but has no reply channel here, so it must answer `{inet_async, Listener, Id, {error, Reason}}` with the descriptor closed — never dropped.
- (a0) The datagram drivers do not apply `{header,N}`, and cannot in the frozen shape. The C splits the datagram payload too (`packet_binary_message` `:4140`-`:4154` active, `inet_async_binary_data` `:3928`-`:3944` passive, same `(desc->mode == INET_MODE_LIST) || (hsz > len)` branch after `load_address`); `ReadMessage` has one header slot and `udp_inet` spends it on the 7 packed source-address bytes `beam_rt` decodes as `{IP,Port}`, so a second, `hsz`-sized header cannot be expressed (a `hsz > len` delivery would drop the address or the payload — a wrong result). Closing it needs a third component on the delivered read, i.e. a `beam_rt`-visible shape change.
- (a) `{active, N|true|once}` delivery — channel, arming gate, burst bound and matrix are served here; the rendering contract (drain after every round *and* every `close`, the four message shapes, `Passive`/error atoms from the driving port's driver name) is the crate doc's *Handoffs*. Do not add a variant to `PortNotification` (two arms, no wildcard). Unserved here: `{deliver, port|term}`, which routes the raw bytes through `{Port,{data,…}}` — stored and reported, nothing delivered.
- (b) `send_timeout` / `send_timeout_close` — stored and reported, not acted on: the answer is an asynchronous `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`), needing a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port's one `TIMEOUT` task is already armed by the receive/accept operations).
- (c) `controlling_process` — not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain; there is no `INET_REQ_*` and no owner notion on the `Driver` seam, so it needs `beam_process::PortTable::set_owner` + `beam_rt`'s `PortMeta.owner`.
- (d) The refusal-only / unmodelled arms — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, `udp_inet`'s ancillary data — each refused honestly today; the missing seam for each is under *Known Issues*.

## Known Issues
- Caller-reference stripping is by shape, not by caller — the C keys on `driver_caller(port)` being an internal pid, which the frozen seam lacks, so `write_command` decides from the bytes: a `[n:be16][n bytes]` prefix with `n` non-zero, fitting and `arg[2] == 131` is a caller reference, stripped once per command, echoed verbatim. Residuals: a *plain* TCP payload of that shape loses its head (unreachable from `prim_inet:send/3`, which always prefixes); a *prefixed* UDP command with a tag ≥ 256 bytes begins with a 1/3/4 byte, so the plain `[address][payload]` grammar wins.
- The TCP `port_command` write path does not count statistics (UDP's does). `TcpInetDriver::output` has no per-command byte boundary (`ByteQueue` is a byte stream), so those bytes are uncounted where the C's `inet_output_count` sees every `tcp_inet_command`; only a `Driver`-seam boundary closes it.
- `SUBSCRIBE`(24)'s reply is exact, its notification is not. `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte, but the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send — none is ever sent.
- Framing divergences: an out-of-range `{packet,N}` code is no framing where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`). The `11` `multicast_if` read-back is uninitialised memory in the C (`inet_fill_opts`, `:9494`-`:9520`), so only tag/code/family/length are pinned — this floor answers `[opt][0,0,0,0][INET_AF_INET]`. A short `14`/`15` multicast-membership payload answers `einval` where the C reads past the request; a `{active,N}` record truncated before its counter is `BadArg`.
- The watermark, `netns`, `delay_send` and send-timeout options are stored and reported only. `{high,low}_msgq_watermark` (`36`/`37`) have no busy-msgq limit on the frozen `Driver`/`Port` seam, `{netns,…}` (`38`) no `setns(2)` in `beam_io`, and `{delay_send,…}` (`31`), `{high,low}_watermark` (`27`/`28`), `{send_timeout,…}`/`{send_timeout_close,…}` (`30`/`35`) are `beam_rt`/`beam_abi` timer/flow-control work (*Handoffs* (b)).
- The `INET_REQ_FDOPEN` `bound == 0` form refuses by errno where the C adopts blind. With the ten-byte form and a zero `bound` word the C skips every probe (its `SET_NONBLOCKING` failure discarded) and answers `[1]`, failing at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe (`fdopen_errno_tests.rs`).
- Two `-eval` failure modes hide a probe's real cause. An abnormal exit (a failed match, an `erlang:error`) loses the whole `erl` dump — the node dies with the group-leader buffer unflushed, so the failure surfaces only as `the oracle expression failed: ` with empty stderr; a probe that merely *hangs* reads as `SKIP: erl did not answer within 30s`, almost always a dead expression (a raw `INET_REQ_CONNECT`(3) refused `[0]"eafnosupport"` leaves the following `gen_tcp:accept` hanging). Every bounded wait therefore gives up through `io:format(standard_error, …)` (survives the exit) + `erlang:halt(1)`, and every step that must have succeeded is asserted (`[1] = erlang:port_control(…)`, the async id via `<<1,Id:16>> = iolist_to_binary([Rq])`).

## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (the wrapper; `$HOME` is read-only).
