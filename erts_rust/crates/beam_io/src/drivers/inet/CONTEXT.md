# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in **`tcp_inet`** driver (`mod.rs`): **one** non-blocking TCP socket behind one port — the Rust counterpart of the C `tcp_inet` half of `inet_drv.c` that `gen_tcp`/`inet_tcp` sit on. The built-in **`udp_inet`** driver (`udp.rs`) is the datagram half of the same C file, the driver `gen_udp` sits on. Frozen registered names **`DRIVER_NAME = "tcp_inet"`** / **`UDP_DRIVER_NAME = "udp_inet"`** (what `port_info(Port, name)` reports), registered with the crate's `DriverRegistry` through `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, from `from_socket(fd)` (**owned** — `open`/the named `accept`/`from_socket`) or from `adopt_prebound(ctx, fd, stype)` (the `INET_REQ_FDOPEN` form — **borrowed**: used for the port's life, never closed here). A descriptor a **numeric** `accept`(26) completion hands over (`InetAsyncResult::Accepted`) belongs to that completion's consumer from the moment it is reported; no path here closes it.
The subtree also owns the **numeric control-opcode bridge** (`opcode.rs`), the **asynchronous-operation queue** behind `TCP_REQ_RECV`(42)/`ACCEPT`(26)/`PACKET_REQ_RECV`(60) (`async.rs` shared, `udp/async.rs` the datagram bodies), the `{packet, N}` framing on the read and send paths (`packet.rs` + `frame.rs`, a term-free port of the C `packet_parser`), the **socket-option vocabulary** (`opt.rs`), the **per-descriptor statistics block** (`stat.rs`) and every raw socket syscall (`sys.rs`).
Legacy C ground truth (read-only): `erts/emulator/drivers/common/inet_drv.c`, `erts/emulator/beam/packet_parser.{c,h}`, `erts/emulator/beam/sys.h` (the magic number), `erts/preloaded/src/prim_inet.erl`.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
The Erlang side never sends a control *verb*: `erlang:port_control(Port, Op, Data)` carries an **integer**, `beam_rt` forwards it as its **decimal string**, and `beam_io::PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`. Both drivers decode it here, before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of the C's `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a **decimal** command (optional `-`, then ASCII digits accumulated **mod-2³²** exactly as the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; an unmatched code is `Opcode::Unknown`, a **non-decimal** command `None`, so every named verb keeps its own path byte-for-byte.
- **The wrapping is observable:** an `Op` below the magic becomes a huge value matching no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`, not `INET_REQ_OPEN`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, the shared `inet_ctl`): one numberspace, but each number is a `case` of exactly one switch, so a number owned by the *other* driver's switch is owned by neither here ⇒ `[0]exbadport`.
- `Opcode` — one variant per row of the table below (same names, same numbers) plus `Unknown` for an unmatched code, with `ALL`/`code`/`from_code`/`scope`/`name` and `not_served() -> BeamError` (the typed `unsupported` raise naming the opcode and its switch).

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A **decimal** command decodes to an opcode; any other command is the **named verb of the same row** — both routes run one body, so their replies are identical. **`s`** = served (the whole arm, success included); **`ref`** = the C's refusals reproduced exactly with the success path `Err(Opcode::not_served())`.
**Three `erl` matrices byte-compare every row against the system driver** — `opcode_tests.rs::oracle_matrix` (`tcp_inet`, **80 calls**), `opcode_tests_udp.rs::oracle_matrix` (`udp_inet`, **89**) and `opcode_tests_states.rs::the_listen_and_connect_rows_agree_with_the_oracle` (**11** rows) — driving bare / opened / listening-or-bound / connected / post-close states in one `erl` run.

**Neither switch owns the number** ⇒ `[0]exbadport` on both drivers (`Unknown`, a wrapped/sub-magic `Op`, a number that is a `case` of *the other* driver's switch, and `Listen`(27) on the datagram driver — SCTP compiled out). A refused opcode is **never** a fabricated success and never an invented number. The drivers are **symmetric** on every arm of the shared `inet_ctl` switch; only the per-driver switches, the `Fdopen` type guard (TCP admits the stream type only, the datagram driver both) and `Sendfile` differ.

#### Reply shape, packed address, error split
- **Reply shape** = the C's `ctl_reply`: a one-byte result tag (`INET_REP_OK` 1 / `INET_REP_ERROR` 0) + payload; `wire::ctl_ok`/`ctl_error(errno)`/`ctl_xerror(name)` build one, the errno rendered as a lowercase name (`erl_errno_id`) or a fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`/`ebadf`/`closed`).
- **Operational** failures are the `[0]`-tagged reply; a **malformed argument** or an **unknown (non-numeric) verb** is `BeamError::BadArg`.
- **Packed address** (`bind`/`connect`/datagram source): `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag is `BadArg` (DNS/IPv6 out of scope).

### `stat.rs` (private) — the socket statistics counters
- `InetStat` (`Debug, Default, Clone, Copy, PartialEq`, `pub(super)`) — the C's `inet_descriptor` statistics block: `recv_`/`send_` × `cnt`/`max`/`avg`/`dvi`, plus `recv_oct`/`send_oct`; one per driver, and `Default` is the C's zeroed init, which is why a socket-less port answers an all-zero `INET_REQ_GETSTAT` reply.
- `input(len)` / `output(len)` — the C's `inet_input_count`/`inet_output_count` on the `ARCH_64` path: `n = cnt.wrapping_add(1)`, `n == 0 ⇒ 1` (the "WRAP, use old avg as input to a new sequence" restart), octets `wrapping_add`, `recv_max`/`send_max` only upwards. They do **not** share a body: `input` takes the deviation from the **updated** average, `output` captures `avg` **before** the update and uses the old value in the numerator; both are observed only through `inet_fill_stat`'s 32-bit truncation.
- Accounting sites: TCP `read_available`'s raw path (every **retained + newly read** byte pushed to the port queue), `verb_send` (payload **plus** any `{packet,1|2|4}` header), `verb_recv_framed` (the **delivered payload only**); UDP `verb_send` and the queued command (payload only — never the caller-reference prefix, the packed address or the ancillary-length word) and `verb_recv` (the datagram payload). The TCP `Driver::output`/`erlang:port_command/2` path deliberately does **not** count (*Known Issues*).

### `mod.rs` — the TCP driver
- `DRIVER_NAME: &str = "tcp_inet"`; `make_tcp_inet() -> Result<Box<dyn Driver>>` (the `DriverFactory`); `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket.
- Constructors: `new()` (socket-less, the registry factory; the `open` verb creates the socket, mirroring `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts a descriptor and probes kernel state: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound(ctx, fd, stype)` (the `Fdopen`(13) adoption). `prebound: bool` (the C's `desc->prebound`) is set **only** by `adopt_prebound`, cleared by `adopt`, and honoured by `close_socket`, which returns early for a prebound descriptor so neither the `close` verb, `stop` nor `Drop` closes a caller's number — they only deregister it, leaving the number valid in the OS and the cached state intact. `stat: stat::InetStat` feeds `INET_REQ_GETSTAT`.
- Accessors: `socket() -> Option<RawFd>`, `state() -> InetState`, `eof() -> bool` (read EOF latched), `peer_closed() -> bool` (the peer-close latch), `connect_error() -> Option<&str>` (the late `SO_ERROR` of a non-blocking `connect`, a lowercase errno name).
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`, `state_code()`) — the C descriptor's `INET_STATE_*`: no socket until `open`; `listen` makes a listener; `connect`/`accept` make a connection.
- The **fake endpoint** pair `name_addr`/`peer_addr` (the C's `desc->name_ptr`/`peer_ptr`): installed/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address`, reported by `Name`/`Peer` in place of `getsockname`/`getpeername`. `Getladdrs`/`Getpaddrs` do **not** read them, and like the C's pointers they are cleared only by the `len == 0` form — a `close` leaves them installed. A pure **reporting** substitution: nothing binds, connects or resolves to a fake address.
- `PeerClose` (the C's `TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND`): after a peer close the **first** `recv` and the **first** `send` answer `closed`, every later one `enotconn`.
- **Control verbs** — `Driver::control` takes the C's packed request payload as raw bytes in **both** wire forms: a decimal command is an [`opcode`](#opcoders--the-numeric-control-opcode-bridge)-decoded opcode, anything else is the **named verb** of the same table row, and both run one `verb_*` body; an unknown non-numeric verb is `BadArg`.
- **`connect` completes synchronously under a bounded wait.** An `EINPROGRESS` is settled inside the call by `sys::wait_connected(fd, connect_wait_ms(timeout_ms))`: `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`; `Some(errno)` ⇒ descriptor released, errno in `connect_error`, `[0] ++ <lowercase errno>`; `None` ⇒ `WRITABLE` armed, state `Connecting`, `[0]etimedout`. The budget is `CONNECT_WAIT_CAP_MS = 30_000` via `const fn connect_wait_ms(i32)` — negative (the C's `INET_INFINITY`) ⇒ the cap, `0` ⇒ one poll, positive ⇒ clamped. Connect is the **one** family answered inline rather than through the async queue, so `EINPROGRESS` never yields the C's `[1] ++ async_id_be16` (documented divergence; `prim_inet:connect_cmd/3` maps `{ok, []}` to `ok`, so the caller-visible path matches).
- **Readiness & flow control**: the poller is edge-triggered (`EPOLLET`), so every callback drains to `EAGAIN`. A socket is **one** descriptor ⇒ **one** registration whose `Interest` mask is flipped: readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and **arms** write readiness) and while a `connect` that outran its budget is in flight (`Connecting`); a drained queue drops writability. Output still queued when a peer close is latched is dropped (the C's `tcp_clear_output`); writes use `send(2)` with `MSG_NOSIGNAL`.
- **A command on a port with no connection is refused, not dropped.** `output`/`ready_output` → `write_pending` → `connected_socket()?` answers the typed `BeamError::BadArg` and the queued bytes are **never consumed** (a re-driven `OUTPUT` task refuses identically instead of losing data); that `Err` reaches `erlang:port_command/2`'s caller through `Port::check_write_accounting`'s `result?` → `PortRegistry::execute_port_tasks` → `beam_rt`'s `write_command` (*Known Issues* lists the two oracle shapes this cannot reproduce).
- **Peer close**: `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event — registration released, socket never touched again, the one-shot `closed`/`enotconn` replies armed.
- **One socket, one port (the `accept` divergence)**: the C's `INET_REQ_ACCEPT` creates a **second** Erlang port for the accepted socket; this seam has no port-creation capability, so the **numeric** request queues on the multi-operation accept list and reports what it took off the listener **inside its completion** (`InetAsyncResult::Accepted { fd }`) — the runtime opens the second port itself (`from_socket`, or the already-served `INET_REQ_FDOPEN`) — and the driver never stores that descriptor, so no teardown path can close it and the listener keeps accepting. Only the **named** `accept` verb still **transfers this port to the connection** (listener closed, accepted descriptor adopted, reply `[1] ++ fd_be32`) and never produces an `{inet_async, …}`; N queued accepts each answer their own id and complete in enqueue order.
- **No completion is produced inside a control call** — the id is the whole reply. The production points are socket readiness (`ready_input`), the port timer (`Driver::next_timeout`/`timeout`, armed from the operation's deadline) and the round's async drive point (`drive_async`, which also serves data that arrived *before* the operation was enqueued); a close drains every pending operation as `{error, closed}` before the descriptor goes away.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, used only under a framing `{packet, N}` (never raw); the counterpart of the C's `desc->i_buf`, cleared when the socket is replaced/closed. A `{packet, …}`/`{line_delim, …}` change arriving with bytes buffered is **not** flushed: the next `recv` re-decodes them under the new options (a switch **to** `raw` delivers the whole retained buffer verbatim).
- **Ownership**: an **owned** descriptor (`open`/`accept` create; `from_socket` adopts) is closed on `stop`, on the `close` verb and on `Drop`; a **prebound** `INET_REQ_FDOPEN` descriptor is only deregistered — never closed, because it belongs to the caller.

### `udp.rs` (`pub`) — the datagram driver
- `UDP_DRIVER_NAME: &str = "udp_inet"`; `make_udp_inet() -> Result<Box<dyn Driver>>`; `UdpInetDriver` (`Driver::name() == "udp_inet"`) — one datagram socket with `new()` (socket-less; the `open` verb creates the socket), `from_socket(fd)` and `adopt_prebound(ctx, fd, stype)` (`stype` is the operand's own `INET_TYPE_*` tag, both stream and dgram admitted). `prebound: bool` / `stat: stat::InetStat` follow the stream driver's rules; accessors `socket()`, `state()` over the same `InetState`; ownership rules are the TCP driver's.
- **Control verbs** — the same two wire forms as the TCP driver, over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_setopts`/`verb_getopts`. `open` sets the cached `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only; `bind` refuses a state other than `Open` with `[0]exbadport` and reports the bound port (`local_port` when the operand asked for `0`); `connect` installs the default peer (`EISCONN` is the racy spelling of "already connected"), an empty operand is the dissolve form back to `Open`, and the argument is accepted as `[Timeout(4), address]` or as a bare packed address (decided by whether it already starts with a family tag).
- **Reception has two paths; the source address rides only the asynchronous one.** A datagram's source cannot ride the byte-only input queue and `PortNotification` must keep exactly two variants, so `PACKET_REQ_RECV`(60) queues the operation on the shared async slot, answers `[1] ++ <<Id:16/big>>`, and completes later as `InetAsyncResult::Data` — one `ReadMessage` whose **header is the 7 packed source-address bytes** and body the payload, the shape the C's reply renderer consumes. The named `recv` verb is this floor's own read-now convenience (the C has no such control op): **one** `recvfrom(2)` into a 64 KiB buffer (`DATAGRAM_CHUNK`, larger than the largest IPv4 UDP payload), the payload pushed to the port input queue (harvested by the runtime as a `Data` notification, rendered `{udp, S, IP, Port, Data}`) and the **eight**-byte `[1, INET_AF_INET, port_hi, port_lo, a, b, c, d]` reply; `EAGAIN` ⇒ the **bare** `[1]` with nothing delivered (the reply length distinguishes the two); a socket-less port ⇒ `[0]einval`. `Driver::ready_input` completes a queued operation; with **none** queued it is a documented **no-op** (read readiness stays registered and the runtime issues `recv`).
- **`send` accepts two wire forms** (`verb_send`, the C's `packet_inet_command`), tried in this order — **the plain form is authoritative**: (1) `wire::split_address`, the `[address][payload]` grammar every direct `port_control` caller uses, so a plain command can never be misread; (2) only when rule 1 refuses, `wire::split_caller_ref` strips the `[n:be16][n tag bytes]` `prim_inet` prefix (`n >= 1`, `2 + n` fits, `arg[2] == 131`), then `wire::split_datagram` decodes `[address][anc_len:be32][anc][data]` — fewer than 4 bytes left or a truncated payload ⇒ `[0]einval`, a **non-zero** `anc_len` ⇒ the typed `unsupported` raise (the C's `sendmsg(2)`-with-cmsgs arm has no seam here), and neither form keeps rule 1's `badarg`. Plain-first is sound because a prefix leads with the 16-bit *tag length*, whose high byte is `0` for any realistic `term_to_binary/1` tag and `0` is never a valid address tag (1/3/4); only a *prefixed* command with a tag length ≥ 256 can be misread (*Known Issues*).
- **A queued command needs only an *open* socket; the destination comes from the command.** `write_pending` guards `!IS_OPEN`, parses the queued front with the same `[address][anc_len:be32][anc][data]` grammar, then picks `send(2)` when connected (the address parsed and then **ignored**) or `sendto(2)` with that address when not — so `gen_udp:send/4`'s unconnected form really sends; accounting is `stat.output(payload.len())` at issue time. A socket-less port, a malformed operand (the two `return_einval` guards, an unparsable address) or a command in neither form is `BeamError::BadArg` with the queued bytes **never consumed**. A caller-tagged command is answered once its bytes drain: `strip_caller_prefix` takes the tag **verbatim** (this crate never decodes the ETF image) and `settle_command` stages `{inet_reply, Port, ok | {error, Reason}, Tag}` as a `PortCompletion`; no tag, and the C's zero-length `[0,0]` tag, stage **nothing**.
- **Deliberate non-mirrors** (so the floor never leaks a socket or answers a wrong result): `open` of a second socket on a live port answers `[0]einval` where the C's `inet_ctl_open` answers `[0]exbadseq` (the TCP driver makes the same choice); `open` accepts only `INET_TYPE_DGRAM` (the C serves `SOCK_STREAM` from either entry point, being one driver file); a `getopts` on a socket-less port answers a well-formed reply where the C's `inet_fill_opts` can walk a `NULL` descriptor. **Absent by design** (a typed error, never a wrong result): `{active, …}` datagram delivery (*Handoffs*), ancillary data (`recvmsg`/`sendmsg`/`IP_PKTINFO` cmsg flags), the `INET_REQ_PEER`/`INET_REQ_NAME` **named**-verb forms (the numeric `Peer`(4)/`Name`(5) opcodes ARE served), and IPv6/SCTP/Unix-domain sockets and DNS resolution.

### `async.rs` (private) / `udp/async.rs` — the asynchronous-operation queue
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword; `udp/async.rs` supplies the datagram bodies under the same hook names).
- `AsyncQueue` — one **receive slot** (`INET_MAX_ASYNC = 1`: a second concurrent receive is `[0]ealready`) plus a **multi-operation accept list** (an accept never answers `ealready`; `accept_state_bits` reports `INET_F_ACC`/`INET_F_MULTI_CLIENT` through `GETSTATUS`). `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, starting at **0**, taken **before** the capacity check so a *refused* enqueue still consumes an id; it wraps at 65536 (the 255→256 step is the carry into the high byte).
- `deadline_for(timeout_ms)` — a **negative** timeout is the C's `INET_INFINITY` (`None`), `0` is "now", a positive value an `Instant` deadline. `parse_recv_operand`/`parse_timeout_operand`/`length_too_large` decode the C's `Timeout(4), Length(4)`; `async_ok_reply` builds `[1] ++ <<Id:16/big>>`.
- Completion hooks: `try_complete_recv` (the read path), `async_ready_input` (socket readiness), `async_timeout` (the port timer), `drive_async_ops` (the round's drive point, which also serves data that arrived before the request), `accept_ready_once`, and `drain_closed` — the teardown drain answering `{error, closed}` **exactly once** per pending operation, run from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_caller_prefix`/`settle_command`) lives beside the queue in each driver: one prefix stripped per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.

### `wire.rs` (private) — the wire vocabulary
- Constants: the result tags (`INET_REP_OK`/`INET_REP_ERROR`), address tags (`INET_AF_INET`/`ANY`/`LOOPBACK` = 1/3/4), socket types (`INET_TYPE_STREAM`/`DGRAM` = 1/2), protocols (`INET_PROTO_*`), `TCP_SHUT_*`, `INET_IFOPT_*`/`INET_IFF_*` — values in the rustdoc.
- The **packed-address codec** (`InetAddr`, `parse_address`/`pack_address`/`packed_addr_reply`, `split_address` — the `[address][payload]` splitter), `FakeAddress`/`parse_fake_address` (the `SETNAME`/`SETPEER` decoder, switching on the **cached** family), and `ctl_ok`/`ctl_error`/`ctl_xerror`/`errno_name` (the lowercase `erl_errno_id` renderer; `EBADF` ⇒ `"ebadf"`).
- The **shared `inet_ctl` reply bodies**, so no driver hand-builds one: `getstat_reply(arg, &InetStat, send_pend: usize)`, `gettype_reply`, `getfd_reply`, `getstatus_reply`, `name_reply`, `peer_reply`, `subscribe_reply`, `getservbyname_reply`, `getservbyport_reply` — each reproducing the C arm exactly, including the socket-less refusals (`einval` for `GETTYPE`/`GETFD`, `ebadf` for `NAME`, `enotconn` for `PEER`) and `getstat_reply`'s `BadArg` for an op outside 1-10.
- The datagram operand `split_datagram`/`DatagramCommand` and the `prim_inet` caller-reference strip (`ETF_VERSION_MAGIC = 131`, `split_caller_ref`), plus the interface family `fdopen_precheck`/`ifget_flags`/`interface_reply`/`getif*_reply`. The constants are re-exported at `crate::drivers::inet::*`; these helpers stay `pub(super)`.

### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- **Wire forms**: `setopts` takes five-byte `[opt, val_be32]` records (`while (len >= 5)`, so a trailing partial record is ignored) and answers `[1]`; the one **seven**-byte record is `{active, N}` (a trailing big-endian 16-bit `N`). `getopts` takes one-byte codes (`while (len--)`, so an empty payload answers a bare `[1]`) and answers `[1] ++ [code, val_be32]*` **in request order**; an `{active, N}` read-back appends a two-byte counter.
- **Syscall-backed codes**: `0` `reuseaddr` (`SO_REUSEADDR`), `1` `keepalive` (`SO_KEEPALIVE`), `4` `broadcast` (`SO_BROADCAST`), `6` `sndbuf` (`SO_SNDBUF`), `7` `recbuf` (`SO_RCVBUF`), `10` `nodelay` (`TCP_NODELAY`), `46` `ttl` (`IP_TTL`). `recbuf`/`sndbuf` report the **kernel's** value (Linux doubles a request: 4096 ⇒ 8192, the oracle); the one `resolve` table serves both drivers, so `reuseaddr`/`broadcast`/`ttl` are served on a datagram socket too.
- **Driver-state codes** (stored in `SocketOptions`; `packet`/`packet_size`/`line_delim` are **acted on** on the TCP read path), with the oracle's defaults: `22` `{active, …}` (`false`, + `active_count`), `23` `{packet, …}` (`raw`), `24` `{mode, …}` (`list`), `25` `{deliver, …}` (`term`), `30` `{send_timeout, …}` (`infinity`), `32` `{packet_size, …}` (`0`), `33` `{read_packets, N}` (`5`), `35` `{send_timeout_close, …}` (`false`), `40` `{line_delim, …}` (`'\n'`, **set-only**). `set_options`/`get_options` both take the driver's **cached socket type** (`stype`, `0` = none) and derive every gate from it (the C gates on `desc->stype`).
- Gates: `{mode, …}`/`{deliver, …}` are **ungated** on both drivers — which is what makes `gen_tcp:listen(0,[binary])` ⇒ `{mode,binary}` work; `{read_packets, N}` is gated on `stype == SOCK_DGRAM`, so on any other type (a stream socket, or none) a `setopts` is **silently ignored and still answers `[1]`** (the `N <= 0 ⇒ [0]einval` test lives *inside* the gate) and a `getopts` contributes **no record** (a bare `[1]`, not an error); `send_timeout`/`send_timeout_close` are gated on `stype == SOCK_STREAM`, and `stype` is set by `open` and **never cleared by `close`**, so a read-back survives a close (as does `GETTYPE`'s cached pair).
- An **unserved** code (`HEADER`/`BUFFER`/`EXITONCLOSE`/`TCP_DELAY_SEND`) is the C's whole-reply `[0] ++ "einval"` (never a partial reply), so a mixed request like `[keepalive, 200]` answers exactly that.
- **Mirrored quirks**, each measured against `erl` byte-for-byte: a configured buffer reports the kernel value; `setopts` answers `[1]` even when the kernel rejects the option (the C's `propagate = 0`); neither verb has an `IS_OPEN` guard, so on a socket-less port `setopts` answers `[1]` and `getopts` drops a syscall-backed record but an unserved code is still `[0]einval`; `getopts` of `line_delim` (`40`) is the C's `[0]einval` and replaces the **whole** reply (while `setopts` of `40` is served); `{active, N}` **adds** to the running counter, clamps at zero (falling back to `{active, false}`), a sum outside the signed 16-bit range is the whole-reply `[0]einval`, and any other `{active, …}` value resets the counter.
- **One deliberate non-mirror**: a **truncated** `{active, N}` record (value but no trailing 16-bit `N`) is `BadArg` (the C reads past the payload). A failed `getsockopt(2)` on a live socket is **not** a divergence: that record alone is dropped and the search continues (the C's `TRUNCATE_TO(0, ptr); continue;`), with every already-produced record kept and later codes still tried.

### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant **is** the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`. **Unsupported**: the HTTP family `Http`/`HttpH`/`HttpBin`/`HttpHBin` and `SslTls` — their bodies need the C's term-building `PacketCallbacks`.
- `PacketLength { Complete(usize), NeedMore, Invalid, Unsupported }` — the C's `packet_get_length` `> 0`/`0`/`< 0` plus an explicit "not implemented"; `is_complete()`/`complete()`/`as_error()` (`Invalid`⇒`badarg`, `Unsupported`⇒`notsup`). `Complete(len)` is the **total** length including the header, known as soon as the header suffices.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — the four arguments of `packet_get_length`; `Default` = `{packet, raw}`, delimiter `DEFAULT_DELIMITER` (`\n`), no limits; builders `new`/`with_delimiter`/`with_max_plen`/`with_trunc_len`; `decode(&[u8]) -> PacketLength`. `max_plen == 0` means "no limit" (`INT_MAX - hlen`) and bounds the **payload** (`plen`), never the total frame.
- `PacketType::payload_range(&[u8]) -> Result<Range<usize>>` — the C's `packet_get_body` header strip: removed for `Len1`/`Len2`/`Len4`, the FCGI padding subtracted for `Fcgi`; every other type (including `LineLf`) is returned **as is**, so a `{packet, line}` payload keeps its delimiter (the oracle's `gen_tcp:recv`).
- **Three faithfully-reproduced C quirks**: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter is found, and both strictly after; `Raw` with an empty buffer is `NeedMore`, not `Complete(0)`.

### `frame.rs` (private) — the framing glue (read + send)
The bridge from the driver's stored `SocketOptions` to the pure decoder, called by the driver's read and send paths (a port of the C's `tcp_remain`/`tcp_reply_data`/`tcp_send` pair), all `pub(super)`:
`options(&SocketOptions) -> PacketOptions` (`trunc_len` stays 0 — no fixed input buffer, it accumulates into a growable `Vec`); `framed(&SocketOptions) -> Option<PacketType>` (`None` only for `Raw` and an out-of-range code); `write_header(&SocketOptions, len) -> Option<Vec<u8>>` (the send-path counterpart of `extract` — the 1-/2-/4-byte big-endian header the `send` verb prepends under `{packet,1|2|4}`, `None` otherwise); `extract(&mut Vec<u8>, &PacketOptions) -> Result<Option<Vec<u8>>>` — **exactly one** frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.

### `sys.rs` (private) — the raw socket syscalls
- Every `unsafe` block of the drivers lives here: `socket`/`bind`/`listen`/`accept`/`connect`/`getsockname`/`getsockopt`/`setsockopt`/`read`/`send`/`shutdown`/`close`, each with a `// SAFETY:` rationale, plus `get_socket_int_option`/`set_socket_int_option`, `socket_family` (the `FDOPEN` pre-check probe), and `local_address(fd)`/`peer_address(fd)` — one `getsockname(2)`/`getpeername(2)` into a `sockaddr_storage` decoded by a private `decode_inet_address` (**`AF_INET` only**; any other family is the C's failure, so `INET_REQ_NAME`/`INET_REQ_PEER` answer their errno reply rather than a wrong address).
- The datagram family shares the file: `dgram_socket_fd`, `bind_socket`, `connect_socket`, `send_to` (an unconnected socket, `sendto(2)`), `send_connected` (`send(2)` on a connected one) and `recv_from` (one `recvfrom(2)`, returning the payload length with the source `InetAddr`), over the shared `has_peer`/`local_port`/`close_fd`, plus the interface/name-service floors behind `wire`'s reply builders.
- `wait_connected(fd, timeout_ms) -> Result<Option<i32>>` — the synchronous-completion primitive behind `INET_REQ_CONNECT`: one `poll(2)` for `POLLOUT` (the deadline recomputed from an `Instant` so a retry can never extend the budget, `EINTR` retried) then `getsockopt(SO_ERROR)`, answering `Some(0)` for an established connection, `Some(errno)` for a failed one and `None` when the budget expired.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: an operational socket failure ⇒ the `[0]`-tagged reply; a malformed argument / unknown named verb ⇒ `BeamError::BadArg`; an I/O syscall failure ⇒ `BeamError::Io`; an undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- **One `Driver` is one port**: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port) and only the named verb transfers the port.
- Safe Rust except `sys.rs`; `unsafe_op_in_unsafe_fn` stays clean; the `Driver`/`DriverContext` seam is frozen.
- Files target ~1000 lines; a suite (`tests.rs`, `opcode_tests*.rs`, `opt_tests.rs`, `stat_tests.rs`, `frame_tests.rs`, `async_tests.rs`, `udp/udp_tests.rs`, `udp/async_tests.rs`) is an in-module test module split from its source half to keep each source file near the target.

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
The completion channel's runtime contract (rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted`, draining the registry) is owned by the crate doc's *Handoffs*; only the driver-family seams are here. Each needs a change **outside** `src/drivers/inet/` and is a real `gen_tcp`/`gen_udp` capability the floor refuses honestly today.
- **(a) `{active, N|true|once}` / `{deliver, port|term}` / `active_count` delivery.** The options are stored and reported, but a driver never delivers input on its own: bytes land in the port input queue (or `pending_input` under framing) and the runtime decides when to fetch them. Needs a per-frame input drain plus a driver→owner **data** message — `DriverContext::deliver_completion` carries async results and caller replies, not stream data, and a port-task round harvests a port's input in one step. **The datagram driver has the same gap**: `{active, true|once|N}` never fires and `{udp, S, IP, Port, Data}` is never fabricated by the driver, so a runtime that wants active mode must issue `PACKET_REQ_RECV`(60), build the tuple from its packed-address header, and install the missing data path. **Do not add a variant to `PortNotification`**: `beam_rt` matches it exhaustively (two arms, no wildcard), so a third variant breaks a crate outside this node; the precedent for a per-frame channel is `{line,N}` — a **separate** struct (`LineNotification`) plus a registry drain accessor (`take_line_notifications`) polled after a round.
- **(b) `send_timeout` / `send_timeout_close`.** Both are stored and reported but not acted on: the C arms a driver multi-timer that fires while output is queued and answers an **asynchronous** `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`). Needs a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port has exactly one `TIMEOUT` task, and the receive/accept operations already arm it); the `{inet_reply, …}` tag path exists (`CompletionEvent::InetReply`).
- **(c) `controlling_process`.** Not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` + an Erlang-side drain of buffered `{tcp, S, Data}`/`{tcp_closed, S}`/`{inet_async, …}` messages; there is no `INET_REQ_*` and the `Driver` seam has no owner notion. Needs `beam_process::PortTable::set_owner` (exists, unused) + `beam_rt`'s `PortMeta.owner`.
- **(d) The remaining refusal-only / unmodelled arms** — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, and `udp_inet`'s ancillary data / active-mode delivery — each refused honestly today; the missing seam and the C ground truth for each are under *Known Issues* and the opcode table.

## Known Issues
- **Two oracle shapes for a socket-less command are unreachable, so the driver answers the third honestly.** Measured on a bare `{spawn_driver,"tcp_inet"}` port: `port_command(P,<<0,0,1>>)` (a caller-ref-prefixed payload) ⇒ the oracle answers `true`, the port stays **alive**, and `{error,enotconn}` arrives out of band (the real `IS_CONNECTED` guard); `port_command(P,<<1>>)` (no prefix — what a plain CLI probe sends) ⇒ `true`, then the port is **dead** (`port_info(P, name)` is `undefined`, `init_caller` → `driver_failure_posix(EINVAL)`) and every later command raises `badarg`. Neither shape is reachable through the frozen `Driver` trait (a `{inet_reply, …}` completion is expressible, but answering the C's way means accepting a command and counting its bytes for a write that never happened, and there is no `driver_failure` seam), so the driver answers the typed `BeamError::BadArg` with the bytes retained and `erlang:port_command/2` raises — the only observable difference from the oracle on that path. A malformed or short caller prefix takes the same `BadArg`.
- **A completion goes to the port's owner, not to the C's `driver_caller`** — the channel's one residual: on both drivers every operand is validated exactly as the C does and the reply-then-completion split is the C's; what a caller still cannot observe is the *message* itself (`beam_rt` owes its rendering and delivery — crate doc › *Handoffs*).
- **The TCP caller-reference prefix is stripped by shape, not by caller.** `init_caller`/`init_caller_iov` strip the `[n:be16][tag]` prefix only when `driver_caller(port)` is an internal pid, and the frozen `Driver`/`DriverContext` seam has no caller notion, so `write_command` decides from the bytes alone: a `[n:be16][n bytes]` prefix whose `n` is non-zero, fits, and whose first tag byte is `ETF_VERSION_MAGIC` (131) is a caller reference (`wire::split_caller_ref_parts`), stripped **once per command** and echoed verbatim in the completion. Residual: a *plain* payload beginning with exactly that shape loses its head — `prim_inet:send/3` always prefixes, so no oracle caller produces one, only a hand-written `port_command` payload. The control `send` verb keeps the plain grammar (no strip at all), and a port with no connection is not inspected, so its refusal keeps every byte queued.
- **The TCP `port_command` write path does not count statistics (the UDP one does).** `InetStat` is fed from the `send`/`recv` control verbs and the framed read path, and `udp_inet::write_pending` feeds it from the queued command's payload; `TcpInetDriver::output` has no per-command byte boundary — the port's `ByteQueue` is a byte stream — so bytes written through `erlang:port_command/2` are not counted there, whereas the C's `inet_output_count` sees every `tcp_inet_command`. Only a per-command boundary on the `Driver` seam (or a caller-ref-tagged command queue) would close it.
- **The UDP caller-reference strip is a payload heuristic, but only a *fallback*.** `verb_send` tries the plain `[address][payload]` grammar first, so a *valid* plain command is always sent as plain — including the shape a caller-ref-**first** order would misread, pinned by `udp/udp_tests.rs::a_plain_command_with_a_0x83_low_port_byte_is_not_read_as_a_caller_reference`. The residual runs the other way: a *prefixed* command whose tag length is **≥ 256** has a first byte of 1/3/4, so the plain rule wins and the prefix is taken as an address; `prim_inet:send/3`'s tag is a small `term_to_binary/1` blob, so no oracle caller can produce it.
- **`SUBSCRIBE`(24)'s reply is exact; its *notification* is not.** `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte; the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends it `{empty_out_q, Port}`, which this crate's `Driver`/`PortNotification` seam cannot send, so **no notification is ever sent**. A caller that only waits for the reply (`prim_inet:close/1`'s `subscribe(S, [subs_empty_out_q])`, the boot path) sees the C exactly; one that waits for the message sees nothing.
- **Non-obvious framing divergences recorded in code**: an out-of-range `{packet,N}` code is treated as **no framing** where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`).
- **File sizes (`wc -l`, this subtree).** Over the ~1000-line target: `mod.rs` **1897**, `udp.rs` **1500**, `udp/udp_tests.rs` **1381**, `wire.rs` **1179**, `async_tests.rs` **937**, `async.rs` **910**, `udp/async_tests.rs` **791**; the rest (`packet.rs`, `sys.rs`, `opcode_tests*.rs`, `frame_tests.rs`, `opt_tests.rs`, `opt.rs`, `opcode.rs`, `frame.rs`, `stat*.rs`, `udp/async.rs`) sit at or just under it. A grown source half splits its test module into a sibling file — the patterns are `opcode_tests*.rs`, `opt_tests.rs`/`stat_tests.rs`, `udp/udp_tests.rs` and the `udp/async.rs` + `udp/async_tests.rs` pair.

- `async_tests.rs` / `udp/async_tests.rs` — the async-op suites over a real `PortRegistry` port (the runtime's own `port_control`/`port_command` route, draining `take_completions`): the **id sequence** (first id `0`; a refused enqueue still consumes one; the high-byte carry at 256), the two **queue disciplines** (the single slot's `[0]ealready` versus N queued accepts completing in enqueue order, and `GETSTATUS`'s `INET_F_ACC`/`INET_F_MULTI_CLIENT` bits — `[1,0,0,1,41]` with one accept, `297` with two), the **guard ladder** in the C's order, reply-then-completion **ordering** (the reply is the id alone; the completion appears only after a round, exactly once), the **data shapes** (body-only `ReadMessage`, "exactly `n` bytes", `{packet,2}` header stripped, `{packet,line}` delimiter kept, `{mode,binary}` stored only, an **over-long datagram `Length` accepted**), the **three production points** (already-arrived data via `drive_async`; a `50` and a `0` deadline via `timeout`/`next_timeout`, the `0` one reported **after** the reply; the teardown drain for a peer close and for `PortRegistry::close`, `{error, closed}` exactly once), the **owned descriptor hand-off** (`fcntl(F_GETFD)` succeeds after `port.close()`; a timeout carries no fd), and the **send path's caller tag** (the golden `[0,26][ETF…]` prefix stripped, the tag echoed verbatim in `InetReply`, the peer reading only the payload; a `[0,0]` tag staging nothing; no tag ⇒ no reply), plus **oracle cross-checks** of the ladders, a completed receive's flattened `[1,PortHi,PortLo,A,B,C,D,…data]`, the timeout/teardown pair and the send-path replies.
- `opt_tests.rs` / `udp/udp_tests.rs` / `frame_tests.rs` — the option vocabulary over real loopback sockets (the `stype`-gated set/get rows, the driver-state defaults, the `mode`/`deliver` either-type rows, the `read_packets`/`send_timeout` gates, the `{active,N}` accumulate/truncation rows, the `line_delim` whole-reply replacement, the failed-`getsockopt` record drop, `gen_tcp:listen(0,[binary])`, a 23-row `tcp` + 13-row `udp` `erl` matrix); the datagram verbs (open/bind/send/recv round trip with its source address, connected-socket send, the option wire, the driver name); the **queued-command path** (unconnected `sendto`, connected-ignores-address, the socket-less refusal keeping its bytes, the ancillary-word ladder, a malformed address's `badarg`); the **two-form command grammar** (`split_caller_ref` discriminator rows, a caller-reference command end-to-end, the length-does-not-fit fallback, the `0x83`-low-port-byte plain-form regression) with **five `erl` cross-checks**; and the `{packet, N}` read path against the system `gen_tcp` oracle.
- **Crate-level (`tests/`):** `inet_async.rs` (8) — the completion channel + async-op queue end-to-end over loopback sockets through `PortRegistry`, i.e. the exact path `beam_rt` must run (the reply-is-only-the-id/complete-later split, the single receive slot with the refused enqueue still consuming an id, the guard ladder and the caller-tag round trip both against `erl`, the `Accepted { fd }` hand-off adopted back through `INET_REQ_FDOPEN`(13), the exactly-once `{error, closed}` teardown, and the "`PortNotification` stays exactly two variants" invariant); `inet.rs` (8) a loopback byte round trip through a `"tcp_inet"` port from the `DriverRegistry`, a stalled write arming write-readiness + an unknown verb's `BadArg`, the post-close `[0]closed` shape, a reactor-observed peer close releasing the registration, four `erl` cross-checks; `udp_inet.rs` (5) the datagram driver through the **real port layer** (a datagram surfacing as the eight-byte `recv` reply then as a `PortNotification::Data`, the read/write-readiness rounds, an unknown verb's `BadArg` plus the reserved `close`, the `erl` cross-check).
- **Every `erl`/`cc` oracle case skips loudly** (`SKIP:` banner + early `return`) when the tool is absent or exceeds its 30 s budget, never fails; comparisons are **byte-exact** except where a reply carries an ephemeral port number or an fd (then tag/length/family/octets are compared).
