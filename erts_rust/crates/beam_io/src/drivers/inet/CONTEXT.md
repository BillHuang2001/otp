# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` driver + its `udp_inet` sibling

## Intent
`mod.rs` is the built-in `tcp_inet` driver: one non-blocking TCP socket behind one port — `inet_drv.c`'s `tcp_inet`, under `gen_tcp`/`inet_tcp`.
Its datagram sibling `udp_inet` (`udp.rs` + `udp/`) is its own child node — `udp/CONTEXT.md`.
The two **share every layer here** — the wire vocabulary (`wire.rs`), the option wire (`opt*.rs`), the opcode bridge (`opcode.rs`), framing (`packet.rs`/`frame.rs`), statistics (`stat.rs`), the syscall floor (`sys.rs`) and the async-op queue (`async.rs`) — so a change to a shared layer changes both.
Frozen names `DRIVER_NAME = "tcp_inet"` / `UDP_DRIVER_NAME = "udp_inet"` (`port_info(Port, name)`), registered by `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, `from_socket(fd)` (owned), or `adopt_prebound(ctx, fd, stype)` (`INET_REQ_FDOPEN` — borrowed: port-lifetime, never closed here); the descriptor a numeric `accept`(26) completion hands over (`Accepted`) belongs to that completion's consumer.

## API Surface (FROZEN)
### `opcode.rs` — the numeric control-opcode bridge
`erlang:port_control(Port, Op, Data)` carries an integer, `beam_rt` forwards its decimal string, and `PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`, so both drivers decode it here before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a decimal command (`-` allowed, digits accumulated mod-2³², the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; non-decimal ⇒ `None`, so every named verb keeps its path byte-for-byte; unmatched ⇒ `Opcode::Unknown`.
- **The wrap is observable:** an `Op` below the magic matches no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport` (the C's `default:`), **not** `INET_REQ_OPEN`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, the shared `inet_ctl`): one numberspace, each number a `case` of exactly one, so a number owned by *the other* driver's switch is owned by neither ⇒ `[0]exbadport` (measured: `PACKET_REQ_RECV`(60) on a `tcp_inet` port, `TCP_REQ_RECV`(42) on a `udp_inet` one).
- `Opcode` — one variant per roster row (same names, numbers) plus `Unknown`, with `ALL`(33)/`code`/`from_code`/`scope`/`name` and `not_served() -> BeamError` (typed `unsupported` naming opcode **and** the owning switch, so both drivers report their gaps through one function).
### The control vocabulary — one numberspace, two switches
`op` = `code + 0x03f1_a300`. A decimal command decodes to an opcode, anything else is the **named verb** of the same row, and both run **one body**, so the numeric and named routes answer identical bytes.
`s` = served (whole arm); `ref` = only the C's refusals reproduced, success path `Err(Opcode::not_served())`; `✗` = `[0]exbadport` (no such `case` in that driver's switch); an error name is the `[0]`-tagged reply (`einval` = `[0]einval`), `⇒` the success reply.
**This roster is the index, not the grammar.** Per-row operand⇒reply grammar and guard ladders live in rustdoc: `mod.rs`'s module-doc verb table (`verb | C request | argument | reply`) for the named forms, and one `wire::*_reply` builder per numeric opcode, each stating its C arm, its guard and its refusal.

Any number no row owns (`Unknown`, a wrapped/sub-magic `Op`, a `case` of *the other* driver's switch, `Listen`(27) on the datagram driver — SCTP compiled out) ⇒ `[0]exbadport` on both drivers; only the per-driver switches, the `Fdopen` type guard and `Sendfile` differ, every shared `inet_ctl` arm being symmetric.
**Pins a caller depends on:**
- `Open`(1) decodes its `[AF, TYPE, PROTO]` operand **before** the state guard, so a non-`Closed` port is `exbadseq` (opened/listening/connected all answer it) and a `close` restores `Closed`; bad protocol ⇒ `eprotonosupport`, family ≠ `INET_AF_INET` ⇒ `eafnosupport`, wrong type (stream TCP / dgram UDP) ⇒ `einval`.
- `Getstat`(11) has **no** `IS_OPEN` guard, so a socket-less port answers the all-zero 59-byte block with `send_pend` = `ctx.output().len()`; one op byte per counter, a record per op in request order (5-byte ops 1-8, 9-byte `recv_oct`/`send_oct`); an op outside 1-10 is the C's `default: return -1` ⇒ typed `badarg`, never `einval`.
- `Getstatus`(16) is `be32(state_code())` (Closed 0, Open 1, Connected 5, Listening 9, Connecting 17) + `accept_state_bits()` (`INET_F_ACC` 0x20 / sticky `INET_F_MULTI_CLIENT` 0x100); pinned `9` / `41` / `297` — the middle values while any accept remains, `9` once the list drains.
- The async arms (`Accept` 26, `TcpRecv` 42, `PacketRecv` 60) answer `[1] ++ <<Id:16/big>>` — the id is the *whole* synchronous answer — and a **refused** enqueue still consumes an id; `INET_MAX_ASYNC = 1` makes a second concurrent receive `[0]ealready`, the accept list never does.
- `TcpRecv`'s guard is the connection guard (incl. `PeerClose`'s one-shot `closed`/`econnreset`) **first**, then `active || len != 8` ⇒ `einval`; a non-zero `Length` means exactly `n` bytes with the raw header only, `> TCP_MAX_PACKET_SIZE` (`0x0400_0000`) ⇒ `enomem`. `Accept`'s guard is `!is_listening || len != 4` ⇒ `einval` in every non-listening state (never `exbadport`), `{active,…}` does not gate it, and the named `accept` is synchronous and transfers the port.
- The `ref` rows and the `Fdopen`/`Gettype`/`Name`/`Peer`/`Setname` guard ladders are those builders' rustdoc plus `opcode_tests_refusals.rs`'s rows; `fdopen`'s adoption non-mirrors are *Known Issues*.
Three `erl` matrices byte-compare every row — `opcode_tests.rs::oracle_matrix` (TCP, 80 calls), `opcode_tests_udp.rs::oracle_matrix` (UDP, 89), `opcode_tests_states.rs` (11 rows) — over the bare/opened/listening-or-bound/connected/post-close states in one `erl` run.
#### Packed address
`bind`/`connect`/datagram source: `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag ⇒ `BadArg` (DNS/IPv6 out of scope). Layout = `inet_get_address`'s: family byte, then the host-order port via `put_int16` (MSB first = big-endian), then raw `sin_addr` in network order; `load_address` decodes it with `get_int16`.
### `mod.rs` — the TCP driver
`TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket; `new()` (socket-less registry factory — the `open` verb creates the socket), `from_socket(fd)` (adopts + probes: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound` (`Fdopen`(13)).
- Capability word `DriverFlags::SOFT_BUSY` (the C's `ERL_DRV_FLAG_SOFT_BUSY` beside `USE_PORT_LOCKING`) ⇒ `erlang:port_command(P, D, [force])` is `PortCommandOutcome::Done`, the oracle's `true` (`soft_busy_tests.rs`); a flag-less driver (`udp_inet`, `ram_file_drv`) ⇒ `notsup`.
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`/`state_code()`) is the C's `INET_STATE_*`; `eof()`/`peer_closed()` latch the read EOF / peer close, `connect_error()` the late `SO_ERROR`.
- Fake endpoints `name_addr`/`peer_addr` (`desc->name_ptr`/`peer_ptr`): set/cleared by `Setname`/`Setpeer`, reported by `Name`/`Peer`; `Getladdrs`/`Getpaddrs` ignore them, only `len == 0` clears them, and a `close` leaves them.
- `connect` completes synchronously under a bounded wait: `EINPROGRESS` settles in-call via `sys::wait_connected(fd, connect_wait_ms(timeout_ms))` — `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`, `Some(errno)` ⇒ `[0]++<lowercase errno>` with the errno kept in `connect_error`, `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout`; budget `CONNECT_WAIT_CAP_MS = 30_000` (negative — `INET_INFINITY` — ⇒ cap, `0` ⇒ one poll), so `EINPROGRESS` never yields the C's `[1]++async_id_be16` (a divergence; `prim_inet:connect_cmd/3` maps `{ok,[]}` to `ok`).
- Readiness & flow control: `EPOLLET` ⇒ every callback drains to `EAGAIN`; one descriptor ⇒ one registration with a flipped `Interest` mask — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and arms write readiness) or an over-budget `connect` is in flight, dropped when the queue drains; output left at a latched peer close is dropped (`tcp_clear_output`), writes use `send(2)` + `MSG_NOSIGNAL`.
- Accept readiness IS the listener's read readiness (`FD_ACCEPT` is `ERL_DRV_READ`): `verb_open` registers it, `verb_listen` arms nothing, `async_accept` re-arms per enqueue, `disarm_accepts` deregisters once the list empties (an op taken, a successful accept, a due timeout) — only while `is_listening()`; a ghost `EAGAIN` stays armed and `drive_async_ops` still makes one non-blocking `accept(2)` attempt.
- A command on a socket-less or unconnected port is consumed and answered out of band: `init_caller` runs first, **size-only** — malformed ⇒ `DriverFailure::posix(EINVAL)` and `PortRegistry::reap_failures` closes the port after the round (`port_command/2` still `true`, later commands `badarg`); a well-formed prefix that cannot write stages `Error(ENOTCONN)` / `Error(EINVAL)` (socket-less `udp_inet`) with the port alive; an empty or non-ETF tag stages no reply (`echoable_caller_tag`).
- One socket, one port: the C's `INET_REQ_ACCEPT` creates a second Erlang port, which this seam cannot, so the numeric request reports the descriptor inside its completion (`Accepted { fd }`, never stored, so no teardown closes it) and the runtime opens the second port (*Handoffs* (0)); only the named `accept` transfers this port, and N queued accepts answer their own id in enqueue order.
- No completion is produced inside a control call — the id is the whole reply; production points are `ready_input`, the port timer (`next_timeout`/`timeout`) and the round's `drive_async` (which also serves data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` first.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, only under a framing `{packet, N}` (never raw); the C's `desc->i_buf`, cleared when the socket is replaced/closed; a `{packet, …}`/`{line_delim, …}` change with bytes buffered is not flushed, the next `recv` re-decoding them under the new options (a `raw` switch delivers the retained buffer verbatim). Ownership: `prebound` (`desc->prebound`) is set only by `adopt_prebound`, cleared by `adopt`, honoured by `close_socket`'s early return — an owned descriptor is closed on `stop`, the `close` verb and `Drop`, a prebound one only deregistered.
### The read path — a complete buffered unit wins over a pending peer close
`read_bytes` takes no `DriverContext` and **never latches**: a `read(2)` of `0` or a reset sets `read_eof`, records the observation in `TcpInetDriver::pending_close` as `CloseSource::Read { error }` (`observe_read_close`; `error` `None` for `ECONNRESET` without `{show_econnreset,true}`) and answers only `Result<()>` — whether it is *applied* is the caller's `ReadReport`.
Latching is the caller's act: `latch_peer_close(ctx, source)` is the **single** site running the whole ladder (the active `Error` event first when `options.active > INET_PASSIVE`, `peer_close.observe`, `pending_shutdown = None`, `drain_error_all`, `ctx.output().clear()`, `deregister`, `tears_down_on_close` ⇒ `close_descriptor`).
`read_available` latches **before** queueing the bytes it just read when the read is one the C would have made (`ReadReport::Answered`), so a passive `{Port, {data, …}}` precedes the `{tcp_closed, …}` the same callback produces and a `{packet, N}` frame completed by that call survives the teardown's `tcp_clear_input` (the C clears and only then delivers); `active.rs`'s `deliver_framed`/`deliver_raw` latch right after their own `read_bytes`.
`try_complete_recv` (`async.rs`) instead leaves the observation in `pending_close`: the loop delivers a complete buffered unit first and only when nothing complete is left calls the private `latch_pending(ctx)`, so a queued `TCP_REQ_RECV`(42) answers `{ok, Data}` rather than `{error, closed}` and the close stays owed to the operations after it; a receive finding `pending_close` already set latches before reading, an empty read latches and breaks. `pending_close` is reset at each of the three `pending_input.clear()` sites — `adopt`, `adopt_prebound`, `mark_connected` — because a replaced socket's observation belongs to the old descriptor.
**`ReadReport` is the selection test.** The C selects a socket's read side in exactly two states — a granted `{active, …}` (`sock_select(desc,(FD_READ|FD_CLOSE),(desc->active>0))`) and a waiting `TCP_REQ_RECV` — so every read it makes is one somebody answers: `ReadReport::Answered` (a queued `TCP_REQ_RECV`, the `recv` verb, an `{active, …}` delivery) **applies** the close it finds.
This floor's edge-triggered poller also reads a passive socket with no receive queued — the passive `{Port, {data, …}}` shortcut — which the C never does, so that read is `ReadReport::Unselected`: it delivers the bytes and only **records** the observation in `pending_close`, applying **nothing** (no `delayed_close_*`, no teardown).
**The rule:** `tcp_recv` classifies what the drain collected before it acts on the end-of-file, its delivery points run first and only a **later** call's `n == 0` reaches `tcp_recv_closed`; the enqueue side agrees (the read precedes `driver_select`).
### The close path on this driver — `flush`, `linger_zero` and `stop`
`TcpInetDriver::flush` is the C's `tcp_inet_flush`: `discard_output = !(token.is_some() && interest.is_writable()) || options.linger_zero`, and only then does it clear `ctx.output()` (`tcp_clear_output`) — otherwise the bytes stay queued and the port parks in `PortState::Closing` for its own drain.
`interest.is_writable()` is the C's `event_mask & FD_WRITE` half; `token.is_some()` models `erl_inet_close`, which zeroes the event mask where this floor deregisters instead, so a closed or peer-closed descriptor counts as unarmed.
`SocketOptions::linger_zero` is the C's `TCP_ADDF_LINGER_ZERO`: `opt_sys.rs` latches `value != 0 && linger == 0` **before** the `setsockopt` under `scope.is_tcp_protocol()` (`propagate = 0`), so a descriptor whose syscall cannot run latches it too; `inherited_from` copies it and no option reply reports it.
`TcpInetDriver::stop` calls `release_socket(ctx)`, never `desc_close(ctx)`: `tcp_inet_stop` is `tcp_close_check` + `tcp_clear_input` + `inet_stop` and **never touches the `ioq`**, while `desc_close`'s unconditional `tcp_clear_output` belongs only to the close **verb**. A forced close (a latched driver failure, the C's `prt->ioq.size = 0`) drops the remainder with the port's own `stopq`.
`udp_inet` has **no** `flush` override (its C entry leaves the slot NULL): `flush_port`'s `flush != NULL` test calls nothing, so the datagram driver inherits the default and a close keeps its queued output — detail in `udp/CONTEXT.md`.
### `udp_inet` — the datagram sibling (detail: `udp/CONTEXT.md`)
`udp_inet` is the same port/driver seam over one `AF_INET`/`SOCK_DGRAM` socket, built from the same shared layers; its whole surface (verbs, socket options, async bodies, `{active,…}` deliveries, suites) lives in the child node `udp/`.
What a reader of *this* file must know: **no write-side framing** (neither the named `send` verb nor a queued `port_command` prepends a `{packet,N}` header); **no `{header,N}`** (a datagram's `ReadMessage.header` is spent on the 7 packed source-address bytes — *Handoffs* (a0)); **no `flush` override** (queued output is always written by the port layer's `Closing` drain); **no `{udp_closed, S}`** (its peerless failures are a `{udp_error, S, Reason}` on the `{active,…}` channel and an `{error, Reason}` completion for a parked receive); an **empty datagram is a delivery** (`body: Some(vec![])`, never `None`) on every channel.
## Accepted-socket option inheritance — `tcp_inet_copy` (`from_accepted` / `SocketOptions::inherited_from`)
The C's `tcp_inet_copy` copies a fixed field set from the listener's descriptor onto the freshly-started accepted one; here the runtime opens the second port, so this crate owns the copy, as an additive inherent API (no `Driver`/`DriverContext` change).
- `TcpInetDriver::from_accepted(fd: RawFd, listener: &TcpInetDriver) -> Result<TcpInetDriver>` — adopts `fd` (owned, exactly like `from_socket`), then applies the listener's inherited options plus the cached `stype`/`family`; it is the only copy path, because `INET_REQ_FDOPEN`'s `adopt_prebound` copies nothing.
- `SocketOptions::inherited_from` (`pub(super)`, `opt.rs`) is that mapping in ONE place, pure and unit-tested, naming every field explicitly (no `..*self`) so a new field forces a decision — that explicit field list **is** the exact inherited set (mode/exit_on_close/deliver/packet/packet_size/header/buffer, the two watermark pairs, the send-timeout pair, `show_econnreset`/`linger_zero`/`read_ahead`, the busy msgq limits, `stype`/`family`), pinned by `inherit_tests.rs`.
- **Surprising negatives (each a live constraint):** `active`/`active_count` are **not** inherited — `inet_start` zeroes them, so an `{active,true}` listener's accepted socket is **passive**; `debug`, `netns`, `read_packets`, `line_delim`, `delay_send` (`TCP_ADDF_DELAY_SEND` is outside the mask) and `buffer_set` (`INET_FLG_BUFFER_SET` lives in `desc->flags`; only the `{buffer,N}` walk sets it) are not inherited either; **kernel** socket options are inherited by the kernel across `accept(2)`, not by this copy.
- The split with the Erlang side: `{active,…}`, `nodelay`, `keepalive`, `delay_send`, `priority`, `linger`, `reuseaddr` are re-applied by `prim_inet:accept_opts/3` — a **different** half, pinned by `accept_opts_tests.rs`/`accept_opts_family_tests.rs`; a code missing from `tcp_inet_copy` still arrives, but only because Erlang re-sends it.
- The registry route: `PortRegistry::driver_as::<TcpInetDriver>(listener)` hands out the listener's own driver through `Box<dyn Driver>` (the `Driver: Any` + `downcast_ref` seam), so `from_accepted(fd, listener)` is reachable from a port; the obligation stays with the runtime — `PortRegistry::open` over `from_accepted`, never over `from_socket`, which inherits nothing.
### The `{active, …}` state seam on the two socket drivers (`Driver::active_mode` / `take_active_spends`)
Both drivers answer `ActiveMode::from_parts(self.options.active, self.options.active_count)` — the C's `desc->inet.active`/`active_count` — so the **running** `{active, N}` counter is readable and a runtime need not mirror the `setopts` walk it sent; the mode is written by `opt_state::set_active` and by nothing but a delivery's spend.
`Driver::take_active_spends` drains a per-driver `active_spends: Vec<ActiveSpend>` (oldest first, consumed on take) recorded at **exactly one site per driver** — the per-delivery spend site: TCP `count_delivery` (`active.rs`) and the datagram twin `UdpInetDriver::after_delivery` (`udp/active.rs`).
`INET_ONCE` records `ActiveSpend::Once` (a silent flip, no message at all) and an `INET_MULTI` counter reaching `0` records `ActiveSpend::Multi` (whose `{tcp_passive,S}`/`{udp_passive,S}` already rides `ActiveInputEvent::Passive`); `INET_ACTIVE`/`INET_PASSIVE` never record, and the delivery loop ends at the flip so a burst spends at most one grant.
The `setopts` walk driving a counter to zero (`landed_at_zero`) **records nothing** — it emits its `Passive`, because the C spends a grant only per **delivered** packet. The private read-side predicate (`desc->active > 0`) is `is_active_mode`, **not** `active_mode`, because the `Driver` trait publishes that name and an inherent method would shadow it at every call site.
`active_seam_tests.rs` pins the four modes per driver, the `setopts`-to-zero distinction, the registry route over a factory-built `"tcp_inet"` port, and three `erl` rows phrased as data/passive counts.
### The asynchronous-operation queue (`async.rs` + `accept.rs`; the datagram bodies are `udp/async.rs`)
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword).
- `AsyncQueue` — one receive slot (`INET_MAX_ASYNC = 1`) plus a multi-operation accept list (never `ealready`; `accept.rs`'s `AcceptQueue`); `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- The multi-accept bit is **sticky** (`AcceptQueue::multi`, the C's `INET_F_MULTI_CLIENT`): `enqueue` latches it when a second accept joins, `take`/`expire` clear it only when the list is left empty, `take_all` clears it with the teardown drain, and `state_bits` derives `GETSTATUS`'s `0` / `INET_F_ACC` / `INET_F_ACC|INET_F_MULTI_CLIENT` from it, never from the list length.
- The accept timer is per port, its entries a separate sorted list (`AcceptQueue::timers`, the C's `desc->mtd`, one `MultiTimerData` per *finite* deadline) — inserted in sorted position, `next_deadline`/`timeout_due` read only the earliest, and `expire(now)` performs one `fire_multi_timers` iteration that consumes that entry, removes the accept list's head and answers the head's id. Because the firing does not remove the *head's own* entry, a head owning a later deadline stays armed and later expires the next head (`[500, 50]` reports id 0 at ~51 ms and id 1 at ~501 ms — measured); only a successful completion cancels its own entry, through `take`.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, from 0, taken **before** the capacity check so a *refused* enqueue still consumes an id; wraps at 65536 (the 255→256 step carries into the high byte). `deadline_for(timeout_ms)` — a negative timeout is `INET_INFINITY` (`None`), `0` "now", positive an `Instant`; `parse_recv_operand`/`length_too_large` decode `Timeout(4), Length(4)`; `async_ok_reply` builds `[1]++<<Id:16/big>>`.
- Hooks: `try_complete_recv`, `async_ready_input`, `async_timeout`, `drive_async_ops`, `drain_closed`; the accept entries `async_accept`/`accept_ready_once`/`disarm_accepts`/`accepts_completed`/`serve_accepts`/`accept_timeouts` are `accept.rs`'s — the teardown drain answering `{error, closed}` once per pending operation, from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) sits beside the queue in each driver: one prefix per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.
### Passive receive is the async-op queue, and it PARKS
`gen_tcp:recv/2,3` issues no synchronous control request: `prim_inet:recv/2` is `recv0(S, Length, -1)`, which waits in `receive {inet_async, S, Ref, Status}` with **no `after`**, so the read is `?TCP_REQ_RECV`(42) on the single receive slot and `Ref` is the raw 16-bit op id the control reply carried.
`[1] ++ <<Id:16/big>>` is the whole synchronous answer, and a would-block read is a **park** — `try_complete_recv` makes no progress on `read_bytes`' `EAGAIN` arm and breaks out instead of raising, the C's `ERRNO_BLOCK` arm leaving the op enqueued with the read armed. Completion is later, exactly once per op, from `async_ready_input` (through `Driver::ready_input`) or `drive_async_ops` (once per port round by `PortRegistry::execute_port_tasks`, which also serves data that arrived *before* the enqueue); expiry answers `Error(InetReason::Timeout)` after one last `try_complete_recv`, so arrived data wins over the deadline.
A close or a peer close while parked answers `{error, closed}` exactly once (`async_error_am_all(am_closed)`), after which a further receive is `[0]enotconn`.
`shutdown/2` is the plain `TCP_REQ_SHUTDOWN`(44) control op: `read`/`write`/`read_write` ⇒ `TCP_SHUT_RD`/`WR`/`RDWR` = `0`/`1`/`2` (`wire.rs`), the reply the bare `[1]` `ctl_cmd` maps to `{ok,[]}`, the guards `!IS_CONNECTED ⇒ enotconn` **before** `len != 1 ⇒ einval`.
`TCP_ADDF_SHUTDOWN_WR_DONE` is set in exactly **two** places, neither the direct success arm (which latches nothing): the **failed** write-side `shutdown(2)` before its error reply and the **deferred** drain `tcp_shutdown_async` on success; it is consumed by `tcp_send_or_shutdown_error` (`err == EPIPE && !(tcp_add_flags & TCP_ADDF_SHUTDOWN_WR_DONE)` ⇒ `ECONNRESET`), which then picks `econnreset` vs `closed` under `{show_econnreset,…}` — so a **successful direct** `shutdown(write)` leaves the flag clear and a later `EPIPE` becomes `{error,econnreset}` under `{show_econnreset,true}`, while a **deferred** shutdown latches it and the same write answers `{error,closed}` whatever the option says.
### Active-mode input delivery (the TCP half: `active.rs`)
Each arriving input goes to the owner on the crate's `{active,…}` channel (`ActiveInputEvent::{Data,Passive,Error}`, `deliver_active_input`, `take_active_inputs`), never `{Port,{data,…}}`/`CompletionEvent`; the C splits the same way (`erl_drv_output_term` → `desc->dport`, `erl_drv_send_term` → the caller).
- Shape — one `ReadMessage` per unit: a stream's `header` is the `{header,N}` option only (`desc->hsz`), `body` the rest of one frame (framing header stripped by `frame::extract`). `header::split_payload` is the `hsz` half of `(mode == INET_MODE_LIST) || (hsz > len)` — narrow header + binary tail, `hsz == len` header + empty tail, `hsz > len` all-header; the `mode` half is the runtime's.
- The third event is a read error — `Error(InetReason)`, the term-free `{tcp_error,S,Reason}` — from `tcp_recv_error`'s active arm and `tcp_send_or_shutdown_error`'s (a reset under `{show_econnreset,true}` only); it precedes the close it accompanies, so `{tcp_closed,S}` = the `port_closed()` latch the same callback sets, never a second event. Passive mode reports the reason as an `{error,Reason}` completion; the atom is `InetReason::atom_name()`, rendered (like `Passive`) from the driving port's driver name.
- One unit at a time; the loop stops the moment the mode flips: one `{packet,N}` frame per message (the remainder stays in `pending_input`), one message per read burst in `{packet,raw}`; the burst is bounded by `{read_packets}` (default `INET_PACKET_POLL = 5`).
- The matrix (`INET_CHECK_ACTIVE_TO_PASSIVE`): `{active,true}` never changes; `{active,once}` flips silently (the bytes stay in the kernel until the next arm or a passive read); `{active,N}` decrements and on 0 flips and stages one `Passive`; so `Passive` has exactly two sources — the credit-spending delivery and the `setopts` walk — and `{active,true}`/`{active,false}` never emit one. `{active,N}` = `INET_MULTI` (3) + a trailing big-endian counter: `opt_state::set_active` accumulates it (`ac += nval`; past `Sint16` ⇒ `einval` after the mode is already set, no rollback), clamps a negative sum to 0, turns a 0 sum into `INET_PASSIVE` and zeroes the counter for any non-multi `{active,…}`; `set_options_tracked` reports `landed_at_zero` (never cleared) and `after_setopts` turns it into the delivery.
- Arming is a driver-side state gate, not a poller mask: the C selects the read side on `active > 0`, deselects when a delivery spends the grant, re-selects for a queued async recv (only when `timeout != 0`). `TcpInetDriver::read_armed` mirrors it while the registration lives on (`poller::Interest` has no empty mask; `mio` epoll is edge-triggered) — cleared by the spending delivery, set by an armed grant (an `epoll_ctl(MOD)` re-arm, never a re-register), a queued `TCP_REQ_RECV`, the synchronous `recv` verbs and every fresh connection. While clear, `async_ready_input` reads nothing, the peer's bytes waiting in the kernel instead of landing on the passive `{Port,{data,…}}` channel; a never-armed port keeps its eager `read_armed = true` read into the port queue.
- Readiness dispatches on state, exactly once: `ready_input` takes `tcp_inet_input`'s shape (accept dispatch / `tcp_recv(desc,0)`, never touching `hsz`; `tcp_deliver` loops packet-by-packet), so a connected + active socket with no queued `TCP_REQ_RECV` goes to `active_delivery` only, while the accept ladder, a queued receive and a passive connection's bytes-into-the-port-queue stay with `async_ready_input` (**running both is a defect** — `read_available` would starve the active path).
- The inline burst is TCP-only, `{active,once}`/`{active,N}` only: `inet_set_opts`'s tail returns 2 (`trigger_recv`) only for `SOCK_STREAM` with `!old_active`, the new mode `once`/`multi` and an unchanged `{packet,…}`, and `INET_REQ_SETOPTS`'s consumer reads 2 as an inline `tcp_recv` + re-arm; `{active,true}` returns 1 ⇒ arm only, a UDP re-arm always waits for the next readiness event. `{deliver,port}` divergence: *Handoffs* (a).
### `wire.rs` (private) — the wire vocabulary
- The wire constants (result tags, address tags, socket types, protocols, `TCP_SHUT_*`, `INET_IFOPT_*`/`INET_IFF_*` — values in the rustdoc), duplicated by hand in `lib/kernel/src/inet_int.hrl`: **nothing enforces the sync**, so changing an opcode/option number requires editing both.
- The packed-address codec (`InetAddr`, `parse_address`/`pack_address`/`packed_addr_reply`, `split_address`), `FakeAddress`/`parse_fake_address` (on the cached family), `ctl_ok`/`ctl_error`/`ctl_xerror`/`errno_name` (`EBADF` ⇒ `"ebadf"`), the datagram operand `split_datagram`/`DatagramCommand` + the caller-reference strip (`ETF_VERSION_MAGIC = 131`, `split_caller_ref`).
- The reply shape: the C's `ctl_reply` — one result-tag byte (`INET_REP_OK` 1 / `INET_REP_ERROR` 0) + payload, built by `ctl_ok`/`ctl_error(errno)`/`ctl_xerror(name)` with the errno a lowercase `erl_errno_id` name or a fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`/`ebadf`/`closed`); **one builder per served opcode**, each reproducing its C arm and guard — socket-less refusals too. Constants re-export at `crate::drivers::inet::*`; helpers stay `pub(super)`.
### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- The record walk — `set_options`/`get_options`/`set_options_tracked`, `Step { Done(usize), Refused }`, the code table (`INET_*`/`TCP_*`/`UDP_*`) and the store `SocketOptions` (the C descriptor's fields, incl. the `{active,N}` counter, `linger_zero` and the 9216-byte `{buffer,…}` default). Each code is offered to `opt_state` then `opt_sys`; an unclaimed one is the C's `default` ⇒ the whole reply `[0]einval`, and a `setopts` refused that way still applies the records already passed. `OptScope { stype, family, protocol }` is the cached state every gate reads (`0` = unset).
- Wire forms: five-byte `[opt, val_be32]` records walked `while (len >= 5)` (a trailing partial record ignored); `getopts` takes one-byte codes (`while (len--)`, an empty payload answering a bare `[1]`) and answers `[1]++[opt, val_be32]*` in request order — variable-length codes (`{active,N}`, `linger`, `netns`, `raw`, `bind_to_device`, multicast, `pktoptions`) carrying extra bytes both ways.
- The two families: `opt_state.rs` (descriptor fields + `stype`/protocol gates, the two watermark pairs clamped both ways) and `opt_sys.rs` (every `SO_*` code with local Linux uapi constants, the nine `propagate = 1` codes — `priority`/`tos`/`ipv6_v6only`/`tclass`/`bind_to_device`/`recvtos`/`recvtclass`/`ttl`/`recvttl`, a failed `setsockopt` there being the whole reply — and the non-`int` shapes). Values are stored/reported only; acting on `{packet,…}`/`{mode,…}` is the read path's and the runtime's. The three C misses are preserved: a failed `getsockopt` truncates that record only; a platform-less option answers a literal `0`; a code with no `case` is `RETURN_ERROR()` ⇒ the whole reply `[0]einval`.
### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant IS the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`; unsupported (their bodies need the C's term-building `PacketCallbacks`): `Http`/`HttpH`/`HttpBin`/`HttpHBin`/`SslTls`. `PacketLength { Complete, NeedMore, Invalid, Unsupported }` is `packet_get_length`'s `> 0`/`0`/`< 0` plus an explicit "not implemented" (`as_error()`: `Invalid`⇒`badarg`, `Unsupported`⇒`notsup`); `Complete(len)` is the total length including the header.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — `packet_get_length`'s four arguments; `Default` = `{packet, raw}`, delimiter `\n`, no limits; `max_plen == 0` is "no limit", bounding the payload, never the frame. `payload_range` is the `packet_get_body` strip (removed for `Len1`/`Len2`/`Len4`, FCGI padding subtracted for `Fcgi`; every other type as is, so `{packet, line}` keeps its delimiter). Three quirks: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter, both strictly after; `Raw` on an empty buffer is `NeedMore`, not `Complete(0)`.
### `frame.rs` (private) — the framing glue (read + send)
Bridges `SocketOptions` to the pure decoder on both paths; all `pub(super)`: `options` (`trunc_len` 0 — it grows a `Vec`); `framed` (`None` only for `Raw` and an out-of-range code); `write_header` (the `send` verb's 1-/2-/4-byte big-endian header); `extract` — exactly one frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.
The C frames in `tcp_send`/`tcp_sendv`, announcing the payload **after** the caller-tag strip (`init_caller_iov`) — once per command (the `out_framed` latch, cleared in lockstep with `caller_stripped` when `write_pending` sees the queue drain), after the connection/pending-shutdown guard and never on the malformed arm; `stat.send_oct` counts payload **plus** header on both routes.
## The peer-close ladder — reset vs end-of-file, and who answers a discovery
`PeerClose` models the C's three independent flags — `TCP_ADDF_DELAYED_CLOSE_RECV`, `_SEND`, `TCP_ADDF_DELAYED_ECONNRESET` — plus the two reasons it owes, both `Option<InetReason>` with `None` meaning `closed`: `delayed_reason` (what a reply ladder answers) and `observed` (`observed_reason()`, what the **discovering** operation reports).
- The receive ladder clears both close one-shots and, when the reset bit is latched, reports `econnreset` and clears it; otherwise `closed`; with neither latched, `enotconn`. The send ladder clears **only** the send one-shot and leaves the reset bit armed for the next receive — a send never consumes the receive's `econnreset`.
- `econnreset` appears only when the observation was an `ECONNRESET` and `{show_econnreset,true}` was in effect; a clean end-of-file is always `closed`.
- Read-side discoveries, one caller-visible sequence. A `CloseSource::Read` observation is the same wherever it is made, and the reader that makes it is the party it is answered to (`ReadReport::Answered`): the `recv`/`verb_recv_framed` verbs answer inline from `observed_reason()`, a queued `TCP_REQ_RECV`(42) is answered by `try_complete_recv`'s tail, and an `{active, …}` delivery reports `{tcp_closed, S}`/`{tcp_error, S, Reason}`. A clean end-of-file arms the send one-shot (`tcp_recv_closed`), a read error arms nothing, and `delayed_reason` is armed only by the **write** path (`tcp_send_or_shutdown_error`) — so a read discovery never turns a later `closed` into `econnreset`.
- The reactor's eager passive read (`ReadReport::Unselected`) is **not** a discovery: a close it stumbles on is only recorded in `pending_close`, so the sequence above starts at the first read the C would have made — the user sees `closed`/`econnreset`/the errno once, then `enotconn`.
- Residual: an `{active, _}` socket with `{exit_on_close,true}` takes the C's `driver_exit(desc->inet.port, 0)` arm and kills the port, which this floor does not model — its teardown predicate is `false` whenever `options.active != 0`, so an active socket's peer close only latches and de-registers.
## Constraints
- Errors are `beam_common::{Result, BeamError}` only: operational socket failure ⇒ the `[0]`-tagged reply; malformed argument / unknown named verb ⇒ `BeamError::BadArg`; I/O syscall failure ⇒ `BeamError::Io`; undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- One `Driver` is one port: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port), only the named verb transfers the port.
- `unsafe` only in `sys.rs`; the `Driver`/`DriverContext` seam is frozen; a grown source half splits its suite into a sibling test module.
## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
Rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted` and the registry drains are the crate doc's *Handoffs*; only the driver-family seams are here.
- (0) The accept completion's second port is the runtime's, and the seam is available now (`driver_as` → `from_accepted`): `beam_rt` must open the second port with **that** constructor and render `{inet_async, Listener, Id, {ok, NewPort}}` (`prim_inet:accept0/3`'s shape); `Accepted { fd }` is adopted that way **or** closed by the runtime — this crate never closes it — and a refused `from_accepted` has no reply channel here, so the runtime answers `{inet_async, Listener, Id, {error, Reason}}` with the descriptor closed, never dropped.
- (a0) The datagram drivers do not apply `{header,N}` and cannot in the frozen shape: `ReadMessage` has one header slot and `udp_inet` spends it on the 7 packed source-address bytes `beam_rt` decodes as `{IP,Port}`, so a second `hsz`-sized header (which the C does apply) cannot be expressed; closing it needs a third component on the delivered read (`udp/`).
- (a) `{active, N|true|once}` delivery — channel, arming gate, burst bound and matrix are served here; the rendering contract (drain after every round *and* every `close`, the four message shapes, `Passive`/error atoms from the driving port's driver name) is the crate doc's *Handoffs*. Do not add a variant to `PortNotification` (two arms, no wildcard). Unserved here: `{deliver, port|term}` — stored and reported, nothing delivered.
- (b) `send_timeout`/`send_timeout_close` — stored and reported, not acted on: the answer is an asynchronous `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`), needing a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port's one `TIMEOUT` task is already armed by the receive/accept operations).
- (c) `controlling_process` — not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain; there is no `INET_REQ_*` and no owner notion on the `Driver` seam, so it needs `beam_process::PortTable::set_owner` + `beam_rt`'s `PortMeta.owner`.
- (d) The refusal-only/unmodelled arms — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, `udp_inet`'s ancillary data — each refused honestly today; the missing seam for each is under *Known Issues*.
## Known Issues
- **`tools/differential`'s `src/corpus/inet_write.rs`, `divergences.md` §A.4 and `GAPS.md` still claim send-side counters stay zero and that a bare-integer payload is written by the oracle and dropped here; both are wrong** — `write_command`/`verb_send` both count and `wire::getstat_reply` renders both, pinned green by `write_frame_tests.rs`/`stat_tests.rs`; and a **top-level** integer payload is the oracle's `badarg` too (`port_command(P,42)`), accepted only as a list element (`prim_inet:send/3` wraps `Data` in `[<<Size:16,MrefBin/binary>>, Data]`), a term conversion that is `beam_rt`'s because this crate is term-free. The corpus docs are the ones to correct (their owner's node).
- Caller-reference stripping is by shape, not by caller (the C keys on `driver_caller(port)` being an internal pid, which the frozen seam lacks): a `[n:be16][n bytes]` prefix with `n` non-zero, fitting and `arg[2] == 131` is a caller reference, stripped once per command and echoed verbatim. Residuals: a *plain* TCP payload of that shape loses its head (unreachable from `prim_inet:send/3`, which always prefixes); a *prefixed* UDP command whose tag is ≥ 256 bytes begins with a 1/3/4 byte, so the plain `[address][payload]` grammar wins.
- The write-side framing and accounting are decided **once per command**, when it is queued — a **second** command queued behind a still-stalled partial write is not framed or counted independently, and the caller-tag strip inherits that property (both latches re-arm only when the queue drains). The C has the same single `ioq` and one-`tcp_sendv`-per-`port_command` shape; the residual is the missing per-command boundary, not a wrong count for the command that was framed.
- `SUBSCRIBE`(24)'s reply is exact, its notification is not: `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte, but the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send — none is ever sent.
- Framing/option divergences: an out-of-range `{packet,N}` code is no framing where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`); the `11` `multicast_if` read-back is uninitialised memory in the C, so only tag/code/family/length are pinned — this floor answers `[opt][0,0,0,0][INET_AF_INET]`; a short `14`/`15` multicast-membership payload answers `einval` where the C reads past the request; a `{active,N}` record truncated before its counter is `BadArg`. The watermark, `netns`, `delay_send` and send-timeout options are stored and reported only: `{high,low}_msgq_watermark` (`36`/`37`) have no busy-msgq limit on the frozen seam, `{netns,…}` (`38`) no `setns(2)` in `beam_io`, and `{delay_send,…}` (`31`), `{high,low}_watermark` (`27`/`28`), `{send_timeout,…}`/`{send_timeout_close,…}` (`30`/`35`) are `beam_rt`/`beam_abi` timer/flow-control work (*Handoffs* (b)).
- The `INET_REQ_FDOPEN` `bound == 0` form refuses by errno where the C adopts blind: with the ten-byte form and a zero `bound` word the C skips every probe and answers `[1]`, failing at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe (`fdopen_errno_tests.rs`); a live socket is `einval` untouched where the C overwrites `desc->s`.
- Two `-eval` failure modes hide a probe's real cause: an abnormal exit (a failed match, an `erlang:error`) loses the whole `erl` dump — the node dies with the group-leader buffer unflushed, so the failure surfaces only as `the oracle expression failed: ` with empty stderr — and a *hanging* probe reads as `SKIP: erl did not answer within 30s`, almost always a dead expression (a raw `INET_REQ_CONNECT`(3) refused `[0]"eafnosupport"` leaves the following `gen_tcp:accept` hanging). Every bounded wait therefore gives up through `io:format(standard_error, …)` (survives the exit) + `erlang:halt(1)`, and every step that must have succeeded is asserted.
## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (the wrapper; `$HOME` is read-only).
- One mechanism: a real loopback socket through `PortRegistry` + `Poller`, the peer/injector outside the port (a datagram injector is `os:cmd("printf … > /dev/udp/127.0.0.1/P")`, never a second VM); waits pump `poller.poll` → `handle_events` → the relevant `take_*` drain until a condition holds under a 10–20 s hang guard, **never a fixed sleep**.
- The three suites pinning this node's load-bearing invariants are the read-ordering rule (`write_then_close_tests.rs`), the close path (`flush_tests.rs`, `close_tests.rs`) and the write-shutdown matrix (`write_shutdown_matrix_tests.rs`); every other suite's subject is in the Routing Table beside its file, and `src/drivers/CONTEXT.md` records the subtree total.
- **Read shapes.** A header-less read of a built-in driver port is a **runtime-policy** observation, not a driver defect: `tcp_inet`'s passive bytes stay in `pending_input` (unframed bytes never become a message here) and the inert legacy `driver_tbl` port the differential corpus creates never runs a read, so both sides agree. Every read carrying the C's `(hbuf, hlen, buf, len)` split does render it: an explicit read is one `ReadMessage { header, body }` per `driver_output*` call, reaching the owner as `PortNotification::Data`.
- Every `erl`/`cc` oracle case skips loudly (`SKIP:` banner + early `return`) without the tool or over its 30 s budget — never fails; comparisons are byte-exact except for an ephemeral port or fd.
