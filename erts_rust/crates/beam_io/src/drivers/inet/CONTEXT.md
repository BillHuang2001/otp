# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in **`tcp_inet`** driver (`mod.rs`): **one** non-blocking TCP socket behind one port — the Rust counterpart of the C `tcp_inet` half of `inet_drv.c` that `gen_tcp`/`inet_tcp` sit on; its datagram half is the built-in **`udp_inet`** driver (`udp.rs`), which `gen_udp` sits on. Frozen registered names **`DRIVER_NAME = "tcp_inet"`** / **`UDP_DRIVER_NAME = "udp_inet"`** (what `port_info(Port, name)` reports), registered with the crate's `DriverRegistry` through `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, from `from_socket(fd)` (**owned** — `open`/the named `accept`/`from_socket`) or from `adopt_prebound(ctx, fd, stype)` (the `INET_REQ_FDOPEN` form — **borrowed**: used for the port's life, never closed here). A descriptor a **numeric** `accept`(26) completion hands over (`InetAsyncResult::Accepted`) belongs to that completion's consumer from the moment it is reported; no path here closes it.
The subtree also owns the **numeric control-opcode bridge** (`opcode.rs`), the **async-operation queue** behind `TCP_REQ_RECV`(42)/`ACCEPT`(26)/`PACKET_REQ_RECV`(60) (`async.rs` shared, `udp/async.rs` the datagram bodies), the `{packet, N}` framing on the read and send paths (`packet.rs` + `frame.rs`, a term-free port of the C `packet_parser`), the **socket-option vocabulary** (`opt.rs`'s record walk + `OptScope` over `opt_state.rs`/`opt_sys.rs`), the **`INET_REQ_FDOPEN` adoption-errno channel** (`adopt_probe.rs`), the **statistics block** (`stat.rs`) and every raw socket syscall (`sys.rs`).
Legacy C ground truth (read-only): `erts/emulator/drivers/common/inet_drv.c`, `erts/emulator/beam/packet_parser.{c,h}`, `erts/emulator/beam/sys.h` (the magic number), `erts/preloaded/src/prim_inet.erl`.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
The Erlang side never sends a control *verb*: `erlang:port_control(Port, Op, Data)` carries an **integer**, `beam_rt` forwards it as its **decimal string**, and `beam_io::PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`. Both drivers decode it here, before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of the C's `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a **decimal** command (optional `-`, then ASCII digits accumulated **mod-2³²** exactly as the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; an unmatched code is `Opcode::Unknown`, a **non-decimal** command `None`, so every named verb keeps its own path byte-for-byte.
- **The wrapping is observable:** an `Op` below the magic becomes a huge value matching no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`, not `INET_REQ_OPEN`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, the shared `inet_ctl`): one numberspace, but each number is a `case` of exactly one switch, so a number owned by the *other* driver's switch is owned by neither here ⇒ `[0]exbadport`.
- `Opcode` — one variant per row of the table below (same names, same numbers) plus `Unknown` for an unmatched code, with `ALL`/`code`/`from_code`/`scope`/`name` and `not_served() -> BeamError` (the typed `unsupported` raise naming the opcode and its switch).

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A **decimal** command decodes to an opcode; any other command is the **named verb of the same row** — both routes run one body, so their replies are identical. **`s`** = served (the whole arm, success included); **`ref`** = the C's refusals reproduced exactly with the success path `Err(Opcode::not_served())`.
**Three `erl` matrices byte-compare every row against the system driver** — `opcode_tests.rs::oracle_matrix` (`tcp_inet`, **80 calls**), `opcode_tests_udp.rs::oracle_matrix` (`udp_inet`, **89**) and `opcode_tests_states.rs::the_listen_and_connect_rows_agree_with_the_oracle` (**11** rows) — driving bare / opened / listening-or-bound / connected / post-close states in one `erl` run.

**Neither switch owns the number** ⇒ `[0]exbadport` on both drivers (`Unknown`, a wrapped/sub-magic `Op`, a number that is a `case` of *the other* driver's switch, and `Listen`(27) on the datagram driver — SCTP compiled out). A refused opcode is **never** a fabricated success and never an invented number. The drivers are **symmetric** on every arm of the shared `inet_ctl` switch; only the per-driver switches, the `Fdopen` type guard (TCP admits the stream type only, the datagram driver both) and `Sendfile` differ.

#### Reply shape, packed address, error split
- **Reply shape** = the C's `ctl_reply`: a one-byte result tag (`INET_REP_OK` 1 / `INET_REP_ERROR` 0) + payload; `wire::ctl_ok`/`ctl_error(errno)`/`ctl_xerror(name)` build one, the errno rendered as a lowercase name (`erl_errno_id`) or a fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`/`ebadf`/`closed`).
- **Operational** failures are the `[0]`-tagged reply; a **malformed argument** or an **unknown (non-numeric) verb** is `BeamError::BadArg`.
- **Packed address** (`bind`/`connect`/datagram source): `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag is `BadArg` (DNS/IPv6 out of scope).

### `stat.rs` (private) — the socket statistics counters
- `InetStat` (`Debug, Default, Clone, Copy, PartialEq`, `pub(super)`) — the C's `inet_descriptor` statistics block: `recv_`/`send_` × `cnt`/`max`/`avg`/`dvi` plus `recv_oct`/`send_oct`; one per driver, its `Default` the C's zeroed init (why a socket-less port answers an all-zero `INET_REQ_GETSTAT` reply).
- `input(len)` / `output(len)` — the C's `inet_input_count`/`inet_output_count` on the `ARCH_64` path: `n = cnt.wrapping_add(1)`, `n == 0 ⇒ 1` (the "WRAP, use old avg as input to a new sequence" restart), octets `wrapping_add`, `recv_max`/`send_max` only upwards. They do **not** share a body — `input` takes the deviation from the **updated** average, `output` the pre-update one in the numerator — and both are observed only through `inet_fill_stat`'s 32-bit truncation.
- Accounting sites: TCP `read_available`'s raw path (every **retained + newly read** byte pushed to the port queue), `verb_send` (payload **plus** any `{packet,1|2|4}` header), `verb_recv_framed` (the delivered payload only); UDP `verb_send` and the queued command (payload only — never the caller reference, packed address or ancillary-length word) and `verb_recv`. The TCP `port_command` path deliberately does **not** count (*Known Issues*).

### `mod.rs` — the TCP driver
- `DRIVER_NAME: &str = "tcp_inet"`; `make_tcp_inet() -> Result<Box<dyn Driver>>` (the `DriverFactory`); `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket.
- Constructors: `new()` (socket-less, the registry factory; the `open` verb creates the socket, mirroring `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts a descriptor and probes kernel state: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound(ctx, fd, stype)` (the `Fdopen`(13) adoption). `prebound: bool` (the C's `desc->prebound`) is set **only** by `adopt_prebound`, cleared by `adopt`, and honoured by `close_socket`'s early return, so neither the `close` verb, `stop` nor `Drop` closes a caller's number — they only deregister it.
- Accessors: `socket() -> Option<RawFd>`, `state() -> InetState`, `eof() -> bool` (read EOF latched), `peer_closed() -> bool` (the peer-close latch), `connect_error() -> Option<&str>` (the late `SO_ERROR`, a lowercase errno name); `stat: stat::InetStat` feeds `INET_REQ_GETSTAT`.
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`, `state_code()`) — the C descriptor's `INET_STATE_*`: no socket until `open`; `listen` makes a listener; `connect`/`accept` make a connection.
- The **fake endpoint** pair `name_addr`/`peer_addr` (the C's `desc->name_ptr`/`peer_ptr`): installed/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address`, reported by `Name`/`Peer` in place of `getsockname`/`getpeername`; `Getladdrs`/`Getpaddrs` do **not** read them, and they are cleared only by the `len == 0` form (a `close` leaves them installed). A pure **reporting** substitution: nothing binds, connects or resolves to a fake address.
- `PeerClose` (the C's `TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND`): after a peer close the **first** `recv` and the **first** `send` answer `closed`, every later one `enotconn`.
- **Control verbs** — `Driver::control` takes the C's packed request payload as raw bytes in **both** wire forms: an [`opcode`](#opcoders--the-numeric-control-opcode-bridge)-decoded decimal, or the **named verb** of the same table row, both running one `verb_*` body; an unknown non-numeric verb is `BadArg`.
- **`connect` completes synchronously under a bounded wait.** An `EINPROGRESS` is settled inside the call by `sys::wait_connected(fd, connect_wait_ms(timeout_ms))` — `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`, `Some(errno)` ⇒ `[0] ++ <lowercase errno>` with the errno kept in `connect_error`, `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout` (row 3). The budget is `CONNECT_WAIT_CAP_MS = 30_000` via `const fn connect_wait_ms(i32)` — negative (the C's `INET_INFINITY`) ⇒ the cap, `0` ⇒ one poll, positive ⇒ clamped; connect is the **one** family answered inline, so `EINPROGRESS` never yields the C's `[1] ++ async_id_be16` (a documented divergence; `prim_inet:connect_cmd/3` maps `{ok, []}` to `ok`, so the caller-visible path matches).
- **Readiness & flow control**: the poller is edge-triggered (`EPOLLET`), so every callback drains to `EAGAIN`; the socket is **one** descriptor ⇒ **one** registration whose `Interest` mask is flipped — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and **arms** write readiness) and while an over-budget `connect` is in flight; a drained queue drops writability. Output still queued at a latched peer close is dropped (the C's `tcp_clear_output`); writes use `send(2)` with `MSG_NOSIGNAL`.
- **A command on a socket-less or unconnected port is consumed and answered out of band, never dropped.** The C runs `init_caller` (`inet_drv.c:1820`-`:1890`) **before** it looks at the connection, and its rule is size-only, so: a **malformed/untagged** command charges itself and latches `DriverContext::signal_failure(DriverFailure::posix(EINVAL))` (the C's `driver_failure_posix`, `io.c:7273`), which `PortRegistry::reap_failures` turns into a reaped port after the round — `erlang:port_command/2` still answers `true` and every later `port_command`/`port_control` is the oracle's `badarg` (`tests`/`udp_tests` pin the driver half, `async_tests::a_socket_less_command_closes_the_port` the registry half); a **well-formed** prefix on a port that cannot write is consumed and answered through `DriverContext::deliver_completion(CompletionEvent::InetReply { …, Error(ENOTCONN) })` for `tcp_inet` (`:12674`-`:12683`) and `Error(EINVAL)` on a **socket-less** `udp_inet` (its `!IS_OPEN` arm, `:15068`-`:15077`) — an open-but-unconnected datagram port really sends, the destination riding the command — the port staying **alive**. An **empty** output queue is `Ok(0)` and latches nothing (a re-driven `OUTPUT` task after a finished write cannot kill the port). A tag that is empty or not ETF-led is consumed but stages **no** reply (`echoable_caller_tag`, the C's failed `erl_drv_send_term`).
- The **named** control verbs are a separate synchronous vocabulary and answer the C's `[0]enotconn`(stream)/`[0]einval`(datagram) control replies for a missing socket or peer; `write_pending`'s own `BadArg` refusal is unreachable behind both callers' connectedness pre-checks and is kept as a defensive arm only. Residuals, each a typed error: `udp_inet`'s ancillary data (`anc_len != 0`, the C's `sendmsg`-with-cmsgs arm) is `unsupported` with the command left queued; and a tag of **≥ 256 bytes** would read as plain — impossible for `prim_inet:send/3`, which prefixes a tens-of-bytes `term_to_binary/1` blob.
- **Peer close**: `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event — registration released, socket never touched again, the one-shot `closed`/`enotconn` replies armed.
- **One socket, one port (the `accept` divergence)**: the C's `INET_REQ_ACCEPT` creates a **second** Erlang port; this seam has no port-creation capability, so the **numeric** request joins the multi-op accept list and reports what it took off the listener **inside its completion** (`InetAsyncResult::Accepted { fd }`) — the runtime opens the second port itself (`from_socket` or `INET_REQ_FDOPEN`), and the driver never stores the descriptor, so no teardown can close it and the listener keeps accepting. Only the **named** `accept` **transfers this port** (listener closed, descriptor adopted, reply `[1] ++ fd_be32`); N queued accepts each answer their own id in enqueue order.
- **No completion is produced inside a control call** — the id is the whole reply; the production points are socket readiness (`ready_input`), the port timer (`Driver::next_timeout`/`timeout`, armed from the operation's deadline) and the round's async drive point (`drive_async`, which also serves data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` before the descriptor goes away.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, used only under a framing `{packet, N}` (never raw); the counterpart of the C's `desc->i_buf`, cleared when the socket is replaced/closed. A `{packet, …}`/`{line_delim, …}` change with bytes buffered is **not** flushed: the next `recv` re-decodes them under the new options (a switch **to** `raw` delivers the retained buffer verbatim).
- **Ownership**: an **owned** descriptor (`open`/`accept` create; `from_socket` adopts) is closed on `stop`, on the `close` verb and on `Drop`; a **prebound** `INET_REQ_FDOPEN` descriptor is only deregistered — never closed, because it belongs to the caller.

### `udp.rs` (`pub`) — the datagram driver
- `UDP_DRIVER_NAME: &str = "udp_inet"`; `make_udp_inet() -> Result<Box<dyn Driver>>`; `UdpInetDriver` (`Driver::name() == "udp_inet"`) — one datagram socket with `new()` (socket-less; the `open` verb creates the socket), `from_socket(fd)` and `adopt_prebound(ctx, fd, stype)` (`stype` is the operand's own `INET_TYPE_*` tag, stream and dgram both admitted). `prebound`/`stat` follow the stream driver's rules; accessors `socket()`/`state()` over the same `InetState`; ownership is the TCP driver's.
- **Control verbs** — the same two wire forms as the TCP driver, over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_setopts`/`verb_getopts`. `open` sets the cached `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only; `bind` refuses any state but `Open` with `[0]exbadport` and reports the bound port; `connect` installs the default peer (`EISCONN` spells "already connected"), an empty operand dissolves to `Open`, and the operand is `[Timeout(4), address]` or a bare packed address (a family tag decides).
- **Reception has two paths; the source address rides only the asynchronous one.** A datagram's source cannot ride the byte-only input queue and `PortNotification` keeps exactly two variants, so `PACKET_REQ_RECV`(60) queues on the shared async slot and completes later as `InetAsyncResult::Data` (row 60). The named `recv` verb is this floor's own read-now convenience (the C has no such control op): one `recvfrom(2)`, the payload pushed to the port input queue (a `Data` notification the runtime renders `{udp, S, IP, Port, Data}`) and the eight-byte `[1, INET_AF_INET, port_hi, port_lo, a, b, c, d]` reply; `EAGAIN` ⇒ a **bare** `[1]`, socket-less ⇒ `[0]einval`. `Driver::ready_input` completes a queued operation; with **none** queued it is a documented **no-op** (readiness stays registered and the runtime issues `recv`).
- **`send` accepts two wire forms** (`verb_send`, the C's `packet_inet_command`), **the plain form authoritative**: `wire::split_address`'s `[address][payload]` grammar (what every direct `port_control` caller uses) first, and only when it refuses `wire::split_caller_ref`'s `[n:be16][n tag bytes]` `prim_inet` prefix (`n >= 1`, `2 + n` fits, `arg[2] == 131`) then `wire::split_datagram`'s `[address][anc_len:be32][anc][data]` — a truncated operand ⇒ `[0]einval`, a **non-zero** `anc_len` ⇒ the typed `unsupported` raise, and neither form keeps rule 1's `badarg` (*Known Issues*: a *prefixed* command whose tag length is ≥ 256 begins with a 1/3/4 byte, so the plain rule wins — unreachable from `prim_inet:send/3`).
- **A queued command needs only an *open* socket; the destination comes from the command.** `write_command` strips one caller tag (`strip_command_prefix`), stages the out-of-band refusals above, and hands the remainder to `write_pending`, which guards `!IS_OPEN`, parses the queued front with the C's `[address][anc_len:be32][anc][data]` grammar, then picks `send(2)` when connected (the address **ignored**) or `sendto(2)` with it when not — so `gen_udp:send/4`'s unconnected form really sends; accounting is `stat.output(payload.len())` at issue time. A socket-less port, a malformed operand or a command in neither form is `BeamError::BadArg` with the queued bytes **never consumed**. Once the queue drains, `settle_command` stages `{inet_reply, Port, ok | {error, Reason}, Tag}` as a `PortCompletion` from the tag `strip_command_prefix` took **verbatim**; no tag, and the C's zero-length `[0,0]` tag, stage **nothing**. The queued grammar is parsed **once**, after the one `init_caller` pass — `split_caller_ref` is `verb_send`'s discriminator, never the queued path's.
- **Deliberate non-mirrors** (the floor never leaks a socket or answers a wrong result): a second `open` on a live port answers `[0]einval` where the C answers `[0]exbadseq`; `open` admits `INET_TYPE_DGRAM` only (the C serves `SOCK_STREAM` from either entry point, being one driver file); a `getopts` on a socket-less port answers a well-formed reply where the C's `inet_fill_opts` can walk a `NULL` descriptor. **Absent by design** (a typed error, never a wrong result): `{active,…}` datagram delivery (*Handoffs*), ancillary data (`recvmsg`/`sendmsg`/`IP_PKTINFO` cmsgs), the `INET_REQ_PEER`/`INET_REQ_NAME` **named** forms (the numeric `Peer`(4)/`Name`(5) opcodes ARE served), IPv6/SCTP/Unix-domain sockets and DNS resolution.

### `async.rs` (private) / `udp/async.rs` — the asynchronous-operation queue
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword; `udp/async.rs` supplies the datagram bodies under the same hook names).
- `AsyncQueue` — one **receive slot** (`INET_MAX_ASYNC = 1`, so a second concurrent receive is `[0]ealready`) plus a **multi-operation accept list** (an accept never answers `ealready`); `accept_state_bits` reports `INET_F_ACC`/`INET_F_MULTI_CLIENT` through `GETSTATUS`. `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, starting at **0**, taken **before** the capacity check so a *refused* enqueue still consumes an id; it wraps at 65536 (the 255→256 step carries into the high byte).
- `deadline_for(timeout_ms)` — a **negative** timeout is the C's `INET_INFINITY` (`None`), `0` "now", positive an `Instant` deadline. `parse_recv_operand`/`parse_timeout_operand`/`length_too_large` decode the C's `Timeout(4), Length(4)`; `async_ok_reply` builds `[1] ++ <<Id:16/big>>`.
- Completion hooks: `try_complete_recv` (read path), `async_ready_input` (socket readiness), `async_timeout` (port timer), `drive_async_ops` (the round's drive point, which also serves data that arrived before the request), `accept_ready_once`, and `drain_closed` — the teardown drain answering `{error, closed}` **exactly once** per pending operation, run from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) lives beside the queue in each driver: one prefix stripped per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.

### `wire.rs` (private) — the wire vocabulary
- The wire constants (result tags, address tags, socket types, protocols, `TCP_SHUT_*`, `INET_IFOPT_*`/`INET_IFF_*` — values in the rustdoc).
- The **packed-address codec** (`InetAddr`, `parse_address`/`pack_address`/`packed_addr_reply`, `split_address` — the `[address][payload]` splitter), `FakeAddress`/`parse_fake_address` (the `SETNAME`/`SETPEER` decoder, switching on the **cached** family), `ctl_ok`/`ctl_error`/`ctl_xerror`/`errno_name` (the lowercase `erl_errno_id` renderer; `EBADF` ⇒ `"ebadf"`), and the datagram operand `split_datagram`/`DatagramCommand` + the `prim_inet` caller-reference strip (`ETF_VERSION_MAGIC = 131`, `split_caller_ref`).
- The **shared `inet_ctl` reply bodies**, so no driver hand-builds one (one builder per served opcode, `getstat_reply(arg, &InetStat, send_pend: usize)` among them), each reproducing the C arm exactly — including the socket-less refusals (`einval` for `GETTYPE`/`GETFD`, `ebadf` for `NAME`, `enotconn` for `PEER`) and `getstat_reply`'s `BadArg` for an op outside 1-10 — plus the interface family (`fdopen_precheck`/`ifget_flags`/`getif*_reply`). Constants re-export at `crate::drivers::inet::*`; these helpers stay `pub(super)`.

### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- **The record walk** — `set_options`/`get_options`, `Step { Done(usize), Refused }`, the code table (`INET_*`/`TCP_*`/`UDP_*` constants) and the option store `SocketOptions` (the C descriptor's fields, incl. the `{active,N}` counter and the 9216-byte `{buffer,…}` default). Each code is offered to `opt_state` then `opt_sys`; an unclaimed one is the C's `default` ⇒ the **whole** reply `[0]einval`, and a `setopts` refused that way still applies the records already passed.
- **`OptScope { stype, family, protocol }`** — the cached descriptor state every gate reads (`0` = unset), so no gate re-derives the socket type; `mod.rs`/`udp.rs` hand `OptScope::new(stype, family, IPPROTO_TCP|IPPROTO_UDP)` to their four `verb_setopts`/`verb_getopts` sites.
- **Wire forms**: five-byte `[opt, val_be32]` records walked `while (len >= 5)`; `getopts` takes one-byte codes (`while (len--)`, so an empty payload answers a bare `[1]`) and answers `[1] ++ [opt, val_be32]*` in request order — the variable-length codes (`{active,N}`, `linger`, `netns`, `raw`, `bind_to_device`, multicast, `pktoptions`) carrying extra bytes both ways.
- **`opt_state.rs`** — the **driver-state** family: descriptor fields plus their `stype`/protocol gates and the two watermark pairs (clamped both ways, the C's busy-msgq rule); **`opt_sys.rs`** — the **syscall/special-shape** family: every `SO_*` code with local Linux uapi constants, the **nine `propagate = 1`** codes (`priority`/`tos`/`ipv6_v6only`/`tclass`/`bind_to_device`/`recvtos`/`recvtclass`/`ttl`/`recvttl`, whose failed `setsockopt` is the whole reply) and the non-`int` shapes. Every value is stored and reported only; acting on `{packet,…}`/`{mode,…}` is the read path's and the runtime's.
- **The three C misses are preserved, because each is observable**: a failed `getsockopt` is `TRUNCATE_TO(0, ptr)` — that record only, later codes still tried; a platform-less option answers a literal `0`; a code with no `case` (the get side of the set-only `line_delim` and membership pair) is `default: RETURN_ERROR()` ⇒ the whole reply `[0]einval`.
- Per-code gates, defaults and oracle-pinned rows are the family modules' rustdoc and their suites (`opt_tests.rs`/`opt_state_tests.rs`/`opt_sys_tests.rs`, all over `opt_oracle.rs`).

### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant **is** the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`. **Unsupported**: the HTTP family `Http`/`HttpH`/`HttpBin`/`HttpHBin` and `SslTls` — their bodies need the C's term-building `PacketCallbacks`.
- `PacketLength { Complete(usize), NeedMore, Invalid, Unsupported }` — the C's `packet_get_length` `> 0`/`0`/`< 0` plus an explicit "not implemented"; `is_complete()`/`complete()`/`as_error()` (`Invalid`⇒`badarg`, `Unsupported`⇒`notsup`). `Complete(len)` is the **total** length including the header, known as soon as the header suffices.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — `packet_get_length`'s four arguments; `Default` = `{packet, raw}`, delimiter `\n` (`DEFAULT_DELIMITER`), no limits; builders `new`/`with_delimiter`/`with_max_plen`/`with_trunc_len`; `decode(&[u8]) -> PacketLength`. `max_plen == 0` means "no limit" (`INT_MAX - hlen`) and bounds the **payload**, never the total frame.
- `PacketType::payload_range(&[u8]) -> Result<Range<usize>>` — the C's `packet_get_body` header strip: removed for `Len1`/`Len2`/`Len4`, the FCGI padding subtracted for `Fcgi`; every other type (including `LineLf`) is returned **as is**, so a `{packet, line}` payload keeps its delimiter (the oracle's `gen_tcp:recv`).
- **Three faithfully-reproduced C quirks**: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter is found, and both strictly after; `Raw` with an empty buffer is `NeedMore`, not `Complete(0)`.

### `frame.rs` (private) — the framing glue (read + send)
Bridges the driver's stored `SocketOptions` to the pure decoder from the read and send paths (the C's `tcp_remain`/`tcp_reply_data`/`tcp_send` pair); all `pub(super)`:
`options(&SocketOptions) -> PacketOptions` (`trunc_len` stays 0 — it accumulates into a growable `Vec`); `framed(&SocketOptions) -> Option<PacketType>` (`None` only for `Raw` and an out-of-range code); `write_header(&SocketOptions, len) -> Option<Vec<u8>>` (the `send` verb's 1-/2-/4-byte big-endian header under `{packet,1|2|4}`, `None` otherwise); `extract(&mut Vec<u8>, &PacketOptions) -> Result<Option<Vec<u8>>>` — **exactly one** frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.

### `sys.rs` (private) — the raw socket syscalls
- **Every `unsafe` block of the drivers lives here** (each with a `// SAFETY:` rationale): the socket/bind/listen/accept/connect/getsockopt/setsockopt/read/send/shutdown/close wrappers, the int-option pair, `socket_family` (the `FDOPEN` pre-check probe) and `local_address(fd)`/`peer_address(fd)` — one `getsockname(2)`/`getpeername(2)` into a `sockaddr_storage` decoded by a private `decode_inet_address` (**`AF_INET` only**; any other family is the C's failure, so `INET_REQ_NAME`/`INET_REQ_PEER` answer their errno reply).
- The option-facing helpers the two `opt` families call: the `int` pair, the `struct linger` pair (`get_socket_linger`/`set_socket_linger`) and the variable-length byte pair (`get_socket_bytes`/`set_socket_bytes`, for `SO_BINDTODEVICE` and the `raw` form).
- The datagram family shares the file (`sendto(2)` unconnected, `send(2)` connected, one `recvfrom(2)` returning the payload length with the source `InetAddr`), over the shared `has_peer`/`local_port`/`close_fd`, plus the interface/name-service floors behind `wire`'s reply builders.
- `wait_connected(fd, timeout_ms) -> Result<Option<i32>>` — the synchronous-completion primitive behind `INET_REQ_CONNECT`: one `poll(2)` for `POLLOUT` (deadline recomputed from an `Instant`, so a retry can never extend the budget; `EINTR` retried) then `getsockopt(SO_ERROR)` ⇒ `Some(0)` established, `Some(errno)` failed, `None` expired.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: an operational socket failure ⇒ the `[0]`-tagged reply; a malformed argument / unknown named verb ⇒ `BeamError::BadArg`; an I/O syscall failure ⇒ `BeamError::Io`; an undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- **One `Driver` is one port**: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port) and only the named verb transfers the port.
- Safe Rust except `sys.rs`; `unsafe_op_in_unsafe_fn` stays clean; the `Driver`/`DriverContext` seam is frozen.
- Files target ~1000 lines; a suite (`tests.rs`, `opcode_tests*.rs`, `opt_tests.rs`, `stat_tests.rs`, `frame_tests.rs`, `async_tests.rs`, `udp/udp_tests.rs`, `udp/async_tests.rs`) is an in-module test module split from its source half to keep each source file near the target.

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
The completion channel's runtime contract (rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted`, draining the registry) is owned by the crate doc's *Handoffs*; only the driver-family seams are here. Each needs a change **outside** `src/drivers/inet/` and is a real `gen_tcp`/`gen_udp` capability the floor refuses honestly today.
- **(a) `{active, N|true|once}` / `{deliver, port|term}` / `active_count` delivery.** The options are stored and reported, but a driver never delivers input on its own: bytes land in the port input queue (or `pending_input` under framing) and the runtime decides when to fetch them — the missing seam is a per-frame input drain plus a driver→owner **data** message (`deliver_completion` carries async results and caller replies, not stream data). **The datagram driver has the same gap**: a runtime wanting active mode must issue `PACKET_REQ_RECV`(60) and build the `{udp, S, IP, Port, Data}` tuple from its packed-address header. **Do not add a variant to `PortNotification`**: `beam_rt` matches it exhaustively (two arms, no wildcard); the precedent for a per-frame channel is `{line,N}` — a **separate** struct (`LineNotification`) plus a registry drain accessor polled after a round.
- **(b) `send_timeout` / `send_timeout_close`.** Both are stored and reported but not acted on: the answer would be an **asynchronous** `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`). Needs a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port has exactly one `TIMEOUT` task, and the receive/accept operations already arm it); the `{inet_reply, …}` tag path exists (`CompletionEvent::InetReply`).
- **(c) `controlling_process`.** Not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` + an Erlang-side drain of buffered messages; there is no `INET_REQ_*` and the `Driver` seam has no owner notion. Needs `beam_process::PortTable::set_owner` (exists, unused) + `beam_rt`'s `PortMeta.owner`.
- **(d) The remaining refusal-only / unmodelled arms** — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, and `udp_inet`'s ancillary data / active-mode delivery — each refused honestly today; the missing seam for each is under *Known Issues*.

## Known Issues
- **Two oracle shapes for a socket-less command are unreachable, so the driver answers the third honestly.** Measured on a bare `{spawn_driver,"tcp_inet"}` port: a caller-ref-prefixed payload (`<<0,0,1>>`) ⇒ the oracle answers `true`, the port stays **alive** and `{error,enotconn}` arrives out of band; a prefix-less one (`<<1>>`) ⇒ `true`, then the port is **dead** (`init_caller` → `driver_failure_posix(EINVAL)`) and every later command raises `badarg`. Neither is reachable through the frozen `Driver` trait (no `driver_failure` seam; answering the C's way means counting bytes for a write that never happened), so the driver answers the typed `BeamError::BadArg` with the bytes retained and `erlang:port_command/2` raises — the only observable difference on that path; a malformed or short caller prefix takes the same `BadArg`.
- **A completion goes to the port's owner, not to the C's `driver_caller`** — the channel's one residual: every operand is validated as the C does and the reply-then-completion split is the C's, but the *message* itself stays unobservable until `beam_rt` renders and delivers it (crate doc › *Handoffs*).
- **The TCP caller-reference prefix is stripped by shape, not by caller.** The C strips the `[n:be16][tag]` prefix only when `driver_caller(port)` is an internal pid, and the frozen `Driver`/`DriverContext` seam has no caller notion, so `write_command` decides from the bytes: a `[n:be16][n bytes]` prefix whose `n` is non-zero, fits, and whose first tag byte is `ETF_VERSION_MAGIC` (131) is a caller reference (`wire::split_caller_ref_parts`), stripped **once per command** and echoed verbatim in the completion. Residual: a *plain* payload beginning with exactly that shape loses its head — `prim_inet:send/3` always prefixes, so no oracle caller produces one; the control `send` verb keeps the plain grammar, and an unconnected port is never inspected, so its refusal keeps every byte queued.
- **The TCP `port_command` write path does not count statistics (the UDP one does).** `InetStat` is fed from the `send`/`recv` control verbs and the framed read path, and `udp_inet::write_pending` from the queued command's payload; `TcpInetDriver::output` has no per-command byte boundary — the port's `ByteQueue` is a byte stream — so `erlang:port_command/2` bytes go uncounted, whereas the C's `inet_output_count` sees every `tcp_inet_command`; only a per-command boundary on the `Driver` seam would close it.
- **The UDP caller-reference strip is a payload heuristic, but only a *fallback*.** `verb_send` tries the plain `[address][payload]` grammar first, so a *valid* plain command is always sent as plain (pinned by `udp/udp_tests.rs::a_plain_command_with_a_0x83_low_port_byte_is_not_read_as_a_caller_reference`); the residual runs the other way — a *prefixed* command whose tag length is **≥ 256** begins with a 1/3/4 byte, so the plain rule wins and the prefix is taken as an address, which no `prim_inet:send/3` caller (`term_to_binary/1` of a ref/pid) can produce.
- **`SUBSCRIBE`(24)'s reply is exact; its *notification* is not.** `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte; the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send, so **no notification is ever sent**. A caller that only waits for the reply (`prim_inet:close/1`'s `subscribe(S, [subs_empty_out_q])`, the boot path) sees the C exactly; one that waits for the message sees nothing.
- **Non-obvious framing divergences recorded in code**: an out-of-range `{packet,N}` code is treated as **no framing** where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`).
- **The `11` `multicast_if` read-back is uninitialised memory in the C.** The C reserves nine reply bytes but advances its length by five, so the value slot is uninitialised and the address lands past the reported length (`inet_fill_opts`, `:9494`-`:9520`), making its replies vary run to run; only tag/code/family/length are pinned against the oracle, and this floor answers the deterministic `[opt][0,0,0,0][INET_AF_INET]`.
- **The watermark, `netns`, `delay_send` and send-timeout options are stored and reported only.** `{high,low}_msgq_watermark` (`36`/`37`) have no busy-msgq limit on the frozen `Driver`/`Port` seam, `{netns,…}` (`38`) has no `setns(2)` facility in `beam_io`, and `{delay_send,…}` (`31`), `{high,low}_watermark` (`27`/`28`) and `{send_timeout,…}`/`{send_timeout_close,…}` (`30`/`35`) are `beam_rt`/`beam_abi` timer/flow-control work (*Handoffs* (b)).
- **A short `14`/`15` multicast-membership payload answers `[0]einval`** where the C reads past the request; a `{active,N}` record truncated before its trailing counter is instead the crate's `BadArg` (the C reads past the payload too).
- **The shared option harness needs a `|` in the oracle dump.** `opt_oracle::parse_reply_dump` reads the `a,b|d,e` line, so a one-request sequence has no comparable dump; the syscall suite pairs such a request with a neighbour.
- **The `INET_REQ_FDOPEN` `bound == 0` form refuses by errno where the C adopts blind.** With the ten-byte form and a zero `bound` word the C skips every probe (its `SET_NONBLOCKING` failure discarded) and answers `[1]`, failing only later at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe's errno (`fdopen_errno_tests.rs`).
- **File sizes (`wc -l`, this subtree).** Over the ~1000-line target: `mod.rs` **1934**, `udp.rs` **1517**, `udp/udp_tests.rs` **1546**, `wire.rs` **1192**, `opt_sys_tests.rs` **1056**, `async_tests.rs` **972**, `async.rs` **957**, `opt_state_tests.rs` **897**, `opt_sys.rs` **603**, `opt.rs` **586**, `accept_opts_tests.rs` **515**, `fdopen_errno_tests.rs` **416**, `opt_state.rs` **403**, `opt_oracle.rs` **230**, `adopt_probe.rs` **143**; the rest sit at or just under it. A grown source half splits its test module into a sibling file (the patterns: `opcode_tests*.rs`, `opt_oracle.rs` + the four option suites, `stat_tests.rs`, `udp/udp_tests.rs`, `udp/async.rs` + `udp/async_tests.rs`).

- `opcode_tests*.rs` — the numeric bridge through a **real `PortRegistry` port** (the runtime's own `port_control(port, &opcode.to_string(), &arg)` route): every served and refused row of the opcode table, **named-vs-numeric reply equality**, the C's guard **order**, the cross-driver `[0]exbadport` and wrapped/sub-magic refusals, the cached-`stype` post-close `GETTYPE` rows and the `GETLADDRS`/`GETPADDRS` fallbacks; `opcode_tests_refusals.rs` adds the `FDOPEN`(13) adoptions with their `GETTYPE`/`GETSTATUS`/`NAME`/`PEER`/`LISTEN` rows, the prebound-never-closed invariant (numeric CLOSE then `Drop` still leaves the fd registered and accept-capable), second adoption ⇒ `[0]einval`, and the interface ops against the live host tables (compared structurally — the kernel's answer, read by two processes).
- `async_tests.rs` / `udp/async_tests.rs` — the async-op queue end-to-end over a real `PortRegistry` port, draining `take_completions`: the **id sequence** (first id `0`, a refused enqueue still consuming one, the high-byte carry at 256), the two **queue disciplines** with their `GETSTATUS` accept bits, the **guard ladder** in the C's order, reply-then-completion **ordering** (exactly one completion, only after a round), the `ReadMessage` **data shapes** (header stripped / delimiter kept / an over-long datagram `Length` accepted), the **three production points** (readiness, deadline — a `0` one reported after the reply — and the teardown `{error, closed}` exactly once), the **owned** `Accepted{fd}` hand-off, and the send path's caller tag (verbatim echo, a `[0,0]` tag staging nothing) — plus `erl` cross-checks of the ladders and rendered shapes.
- **The option suites** (`opt_tests.rs` / `opt_state_tests.rs` / `opt_sys_tests.rs` / `accept_opts_tests.rs`, all over `opt_oracle.rs`) — every served and refused code driven through a **real `PortRegistry` port** and byte-compared against the system driver: the `stype`/protocol/family gates, the driver-state defaults, the `{active,N}` counter rows, `line_delim`'s whole-reply replacement, the failed-`getsockopt` record drop, the three C misses, the non-`int` shapes, the nine `propagate = 1` codes, a `tcp` + `udp` matrix, and the exact `prim_inet:accept_opts/3` sequence (listener `getopts` then accepted-socket `setopts`, plus a real `gen_tcp:listen(0,[binary,{active,false},{reuseaddr,true}])` + `accept/1`).
- `udp/udp_tests.rs` / `frame_tests.rs` — the datagram verbs and the **queued-command path** (unconnected `sendto`, connected-ignores-address, the socket-less refusal keeping its bytes, the ancillary-word ladder), the **two-form command grammar**, and the `{packet, N}` read path against the system `gen_tcp` oracle.
- **Crate-level (`tests/`):** `inet_async.rs` (8) — the completion channel + async-op queue through `PortRegistry`, i.e. the exact path `beam_rt` must run (reply-is-only-the-id/complete-later, the caller-tag round trip against `erl`, `Accepted{fd}` adopted back through `INET_REQ_FDOPEN`(13), the exactly-once teardown, and the "`PortNotification` stays exactly two variants" invariant); `inet.rs` (8) — a loopback round trip through a `"tcp_inet"` port from the `DriverRegistry`, a stalled write arming write-readiness + an unknown verb's `BadArg`, the post-close `[0]closed` shape, a reactor-observed peer close releasing the registration, four `erl` cross-checks; `udp_inet.rs` (5) — the datagram driver through the **real port layer** (a datagram as the eight-byte `recv` reply then as a `PortNotification::Data`, the readiness rounds, an unknown verb's `BadArg`).
- **Every `erl`/`cc` oracle case skips loudly** (`SKIP:` banner + early `return`) when the tool is absent or exceeds its 30 s budget, never fails; comparisons are **byte-exact** except where a reply carries an ephemeral port number or an fd (then tag/length/family/octets are compared).
