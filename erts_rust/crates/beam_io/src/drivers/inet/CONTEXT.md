# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in **`tcp_inet`** driver (`mod.rs`): **one** non-blocking TCP socket behind one port — the Rust counterpart of the C `tcp_inet` half of `inet_drv.c` that `gen_tcp`/`inet_tcp` sit on; the built-in **`udp_inet`** driver (`udp.rs`) is the datagram half of the same C file, the driver `gen_udp` sits on.
Frozen registered names **`DRIVER_NAME = "tcp_inet"`** / **`UDP_DRIVER_NAME = "udp_inet"`** (`port_info(Port, name)`; `inet_drv.c:1348`/`:11834` for TCP, `:1406` for UDP), registered with the crate's `DriverRegistry` through `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, from `from_socket(fd)` (**owned** — `open`/`accept`/`from_socket`) or from `adopt_prebound(ctx, fd, stype)` (the `INET_REQ_FDOPEN` form — **borrowed**: used for the port's life, never closed here).
This subtree also owns the **numeric control-opcode bridge** (`opcode.rs`), the `{packet, N}` framing on both the read and send paths (`packet.rs` + `frame.rs`, a term-free port of the C `packet_parser`), the **socket-option vocabulary** (`opt.rs`), the **per-descriptor statistics block** (`stat.rs`) and every raw socket syscall (`sys.rs`).
Legacy C ground truth (read-only): `erts/emulator/drivers/common/inet_drv.c`, `erts/emulator/beam/packet_parser.{c,h}`, `erts/emulator/beam/sys.h` (the magic number), `erts/preloaded/src/prim_inet.erl`.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
The Erlang side never sends a control *verb*: `erlang:port_control(Port, Op, Data)` carries an **integer**, `beam_rt` forwards it to `beam_io::PortRegistry::port_control` as its **decimal string**, and that passes any non-`"close"` op verbatim to `Driver::control`.
Both drivers therefore decode it here, before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` — `ERTS_INET_DRV_CONTROL_MAGIC_NUMBER` (`erts/emulator/beam/sys.h:1466`), subtracted at the top of `tcp_inet_ctl` (`inet_drv.c:11958`) and `packet_inet_ctl` (`:14574`).
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a **decimal** command (optional `-`, then ASCII digits, accumulated **mod-2³²** exactly as the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; a code no table entry matches is `Opcode::Unknown`; a **non-decimal** command is `None`, so every named verb keeps its own path byte-for-byte.
- **The wrapping is observable:** an `Op` below the magic becomes a huge value matching no `case`, so it is *not* an opcode — measured `port_control(P, 1, <<1,2,0>>)` ⇒ `[0]exbadport`, not `INET_REQ_OPEN`, and `port_control(P, 99, <<>>)` ⇒ the same.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl` `:11953`, `packet_inet_ctl` `:14570`, the shared `inet_ctl` `:10988`). The numbers are **one** numberspace (`:805-834`) but each number is a `case` of exactly one switch, so a number owned by the *other* driver's switch is owned by neither here ⇒ `[0]exbadport`.
- `Opcode` — `Open`(1) `Close`(2) `Connect`(3) `Peer`(4) `Name`(5) `Bind`(6) `Setopts`(7) `Getopts`(8) `Getstat`(11) `Gethostname`(12) `Fdopen`(13) `Getfd`(14) `Gettype`(15) `Getstatus`(16) `Getservbyname`(17) `Getservbyport`(18) `Setname`(19) `Setpeer`(20) `Getiflist`(21) `Ifget`(22) `Ifset`(23) `Subscribe`(24) `Getifaddrs`(25) `Accept`(26) `Listen`(27) `Ignorefd`(28) `Getladdrs`(29) `Getpaddrs`(30) `TcpRecv`(42) `TcpUnrecv`(43) `TcpShutdown`(44) `TcpSendfile`(45) `PacketRecv`(60) `Unknown`; `ALL`/`code`/`from_code`/`scope`/`name`, plus `not_served() -> BeamError` — the typed `error:unsupported: control opcode \`X\` (<switch>) is not served by this driver floor` raise.

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A **decimal** command decodes to an opcode; any other command is the **named verb of the same row** — both routes run one body, so their replies are identical (the `tests::*` suites pin the named replies byte-for-byte).
"Served" means the whole arm is implemented, success included; "ref-only" means the C's refusals are reproduced exactly and the success path is the typed `Err(Opcode::not_served())`.
**Two `erl` matrices compare every served/refused row byte-for-byte against the system driver** — `opcode_tests.rs::oracle_matrix` (the `tcp_inet` half, **80 calls**) and `opcode_tests_udp.rs::oracle_matrix` (the `udp_inet` half, **89 calls**) — each driving bare / opened / listening-or-bound / connected / post-close states in one `erl` run, plus `opcode_tests_states.rs::the_listen_and_connect_rows_agree_with_the_oracle`'s **11** rows.

**Neither switch owns the number** ⇒ `[0]exbadport` on both drivers: `Unknown`, a wrapped/sub-magic `Op`, a number that is a `case` of *the other* driver's switch (`PACKET_REQ_RECV` on TCP, `TCP_REQ_*`/`Accept` on UDP), and `Listen`(27) on the datagram driver (SCTP compiled out).
A refused opcode is **never** a fabricated success and never an invented number.
The two drivers are **symmetric** on every arm of the shared `inet_ctl` switch (`:10988`) — the datagram half reproduces each shared refusal too — so only the per-driver switches (`tcp_inet_ctl`/`packet_inet_ctl`), the `Fdopen` type guard (TCP admits the stream type only, the datagram driver both) and `Sendfile` differ.

#### Reply shape, packed address, error split
- **Reply shape** = the C's `ctl_reply` (`:2260-2311`): a one-byte result tag (`INET_REP_OK` 1 / `INET_REP_ERROR` 0, `:869-871`) + payload; `wire::ctl_ok`/`ctl_error(errno)`/`ctl_xerror(name)` build one, the errno rendered as a lowercase name by `erl_errno_id` (`:2249`) or as a fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`/`ebadf`/`closed`).
- **Operational** failures are the `[0]`-tagged reply; a **malformed argument** or an **unknown (non-numeric) verb** is `BeamError::BadArg` (the C's `ctl_error(EINVAL)` for the former).
- **Packed address** (`bind`/`connect`, the C's `inet_set_faddress`/`inet_set_address` `:4795`/`:4706`): `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag is `BadArg` (DNS/IPv6 are out of scope).

### `stat.rs` (private) — the socket statistics counters
- `InetStat { recv_cnt, recv_max, recv_avg, recv_dvi, send_cnt, send_max, send_avg, recv_oct, send_oct }` (`Debug, Default, Clone, Copy, PartialEq`, `pub(super)`) — the C's `inet_descriptor` statistics block (`inet_drv.c:11560`-`:11623`), one per driver; `Default` is `inet_init_desc`'s zeroed state, which is why a socket-less port answers an all-zero `INET_REQ_GETSTAT` reply.
- `input(len)` / `output(len)` — the C's `inet_input_count` (`:11585`-`:11617`) and `inet_output_count` (`:11560`-`:11582`) on the `ARCH_64` path: `n = cnt.wrapping_add(1)` with `n == 0 ⇒ 1` (the C's "WRAP, use old avg as input to a new sequence" restart, `:11576`/`:11603`), the octet counters `wrapping_add`, `recv_max`/`send_max` only moving upwards.
  They do **not** share a body because the C's arithmetic differs: `input` takes the deviation from the **updated** average (`avg` reassigned before `recv_dvi` updates), `output` captures `avg` **before** the update and uses the old value in the numerator; both are observed only through `inet_fill_stat`'s 32-bit truncation ([`wire::getstat_reply`]'s `as u32`, the C's `(unsigned long)`).
- Accounting sites (the C arm each mirrors): TCP `read_available`'s raw path (every **retained + newly read** byte pushed to the port queue, `tcp_deliver` `:13064`), `verb_send` (the payload **plus** any `{packet,1|2|4}` header, `tcp_send` `:13763`), `verb_recv_framed` (the **delivered payload only**, header stripped, `:13064`); UDP `verb_send` and the queued command (the payload only — never the caller-reference prefix, the packed address or the ancillary-length word, `:15163`) and `verb_recv` (the received datagram payload, `:15513`/`:15526`).
  The TCP `Driver::output`/`erlang:port_command/2` write path deliberately does **not** count (see *Known Issues*).

### `mod.rs` — the TCP driver
- `DRIVER_NAME: &str = "tcp_inet"`; `make_tcp_inet() -> Result<Box<dyn Driver>>` (the `DriverFactory`).
- `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket: `new()` (socket-less, the registry factory; the `open` verb creates the socket, mirroring `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts a descriptor and probes kernel state: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound(ctx, fd, stype)` (the `INET_REQ_FDOPEN` adoption — `Fdopen`(13) row).
- `prebound: bool` — the C's `desc->prebound` (`inet_drv.c:5266`): set **only** by `adopt_prebound`, cleared by `adopt` (an `open`/`accept`/`from_socket` descriptor is the driver's own), and honoured by `close_socket`, which returns early for a prebound descriptor so neither the `close` verb, `stop` nor `Drop` closes a caller's number — they only deregister it, leaving the number valid in the OS and the cached state intact (`erl_inet_close`, `:5102`-`:5117`).
- `stat: stat::InetStat` — the per-descriptor counters [`stat`] feeds and `INET_REQ_GETSTAT` renders.
- Accessors: `socket() -> Option<RawFd>`, `state() -> InetState`, `eof() -> bool` (read EOF latched), `peer_closed() -> bool` (the peer-close latch), `connect_error() -> Option<&str>` (the late `SO_ERROR` of a non-blocking `connect`, a lowercase errno name).
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`, `state_code()`) — mirrors the C descriptor's `INET_STATE_*`: no socket until `open`; `listen` makes a listener; `connect`/`accept` make a connection.
- The **fake endpoint** pair `name_addr`/`peer_addr` — the C's `desc->name_ptr`/`peer_ptr` (`inet_drv.c:1269`/`:1268`): installed/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address` and reported by `Name`/`Peer` in place of `getsockname`/`getpeername`; `Getladdrs`/`Getpaddrs` deliberately do **not** read them (the C's non-SCTP fallbacks call `sock_name`/`sock_peer` directly), and like the C's pointers they are cleared only by the `len == 0` form — a `close` leaves them installed.
  A pure **reporting** substitution: nothing binds, connects or resolves to a fake address.
- `PeerClose` — the C's `TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND` bookkeeping (`:855-856`): after a peer close the **first** `recv` and the **first** `send` answer `closed`, every later one `enotconn` (`:12798-12819`, `:13662-13684`).
- **Control verbs** — `Driver::control` takes the C's packed request payload as raw bytes in **both** wire forms: a decimal command is an [`opcode`](#opcoders--the-numeric-control-opcode-bridge)-decoded opcode, anything else is the **named verb** of the same opcode-table row, and both run one `verb_*` body; the table carries each reply.
  Two operand rules live in the verb bodies: a **non-empty** `recv` argument is `BadArg` (the numeric `TcpRecv`(42) route validates its 8-byte operand and forwards `&[]`), and an unknown non-numeric verb is `BadArg`.
- **`connect` completes synchronously under a bounded wait.** An `EINPROGRESS` is settled inside the call by `sys::wait_connected(fd, connect_wait_ms(timeout_ms))` — one `poll(2)` for `POLLOUT` on an `Instant` deadline (`EINTR`-retried), then `getsockopt(SO_ERROR)`: `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`; `Some(errno)` ⇒ the descriptor released, the errno in `connect_error`, reply `[0] ++ <lowercase errno>`; `None` ⇒ `WRITABLE` armed, state stays `Connecting`, reply `[0]etimedout`.
  The budget is `CONNECT_WAIT_CAP_MS = 30_000` via `const fn connect_wait_ms(i32)` — a negative value (the C's `INET_INFINITY`) becomes the cap, `0` a single poll, a positive one is clamped — and no async-op queue is involved, so `EINPROGRESS` never yields the C's `[1] ++ async_id_be16`; `prim_inet:connect_cmd/3` maps `{ok, []}` to `ok`, so the substitution takes the same caller-visible path (`:12064`-`:12145`).
- **Readiness & flow control**: the poller is edge-triggered (`EPOLLET`), so every callback drains to `EAGAIN`.
  A socket is **one** descriptor ⇒ **one** registration whose `Interest` mask is flipped: readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and **arms** write readiness) and while a `connect` that outran its wait budget is still in flight (`Connecting`); a drained queue drops writability.
  Output still queued when a peer close is latched is dropped (the C's `tcp_clear_output`, `:12786`); writes use `send(2)` with `MSG_NOSIGNAL`.
- **A command on a port with no connection is refused, not dropped.** `output`/`ready_output` → `write_pending` → `connected_socket()?` answers the typed `BeamError::BadArg` and the queued bytes are **never consumed** (so a re-driven `OUTPUT` task refuses identically instead of losing data); that `Err` reaches `erlang:port_command/2`'s caller through `Port::check_write_accounting`'s `result?` → `PortRegistry::execute_port_tasks` → `beam_rt`'s `write_command` (C ground truth: `tcp_inet_command` `:12629` with `init_caller` `:1854` and the `IS_CONNECTED` guard `:12645`; see *Known Issues* for the two oracle shapes this cannot reproduce).
- **Peer close**: `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event — registration released, socket never touched again, the one-shot `closed`/`enotconn` replies armed.
- **One socket, one port (the `accept` divergence)**: the C's `INET_REQ_ACCEPT` creates a **second** Erlang port for the accepted socket (`tcp_inet_copy` + `driver_create_port` + `async_ok_port`, `:12236-12252`) and answers a two-byte async id; this seam has no port-creation capability, so `accept` **transfers this port to the connection** — the listener is deregistered/closed, the accepted descriptor becomes the port's socket, and the reply carries the **new descriptor** (`[1] ++ fd_be32`) for correlation.
  Multi-accept is deferred (needs the async-op queue + port creation).
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, used only under a framing `{packet, N}` (never `{packet, raw}`); the counterpart of the C's `desc->i_buf`, cleared when the socket is replaced/closed.
  A `{packet, …}`/`{line_delim, …}` change arriving with bytes buffered is **not** flushed: the next `recv` re-decodes them under the new options (a switch **to** `raw` delivers the whole retained buffer verbatim).
- **Ownership**: an **owned** descriptor (`open`/`accept` create; `from_socket` adopts) is closed on `stop`, on the `close` verb and on `Drop`; a **prebound** `INET_REQ_FDOPEN` descriptor is only deregistered — never closed, because it belongs to the caller; nothing else may close either kind.

### `udp.rs` (`pub`) — the datagram driver
- `UDP_DRIVER_NAME: &str = "udp_inet"`; `make_udp_inet() -> Result<Box<dyn Driver>>` (the `DriverFactory`, the counterpart of `make_tcp_inet`).
- `UdpInetDriver` (`Driver::name() == "udp_inet"`) — one datagram socket; `new()` (socket-less; the `open` verb creates the socket, mirroring `udp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts a caller's descriptor) and `adopt_prebound(ctx, fd, stype)` (the `INET_REQ_FDOPEN` adoption; `stype` is the operand's own `INET_TYPE_*` tag, both stream and dgram admitted — see the `Fdopen`(13) row).
- `prebound: bool` / `stat: stat::InetStat` — the C's `desc->prebound` (`inet_drv.c:5266`) and statistics block, with the same rules as the stream driver: `adopt` clears `prebound`, `adopt_prebound` sets it, and `close_socket` returns early for it so neither the `close` verb, `stop` nor `Drop` closes a caller's descriptor (only deregisters it).
- Accessors: `socket() -> Option<RawFd>`, `state() -> InetState` — the lifecycle reuses the same `InetState` (`Closed` until `open`, `Open` after it, `Connected` after a `connect`).
- **Control verbs** — the same two wire forms as the TCP driver (a decimal command is an [`opcode`](#opcoders--the-numeric-control-opcode-bridge) opcode; anything else is a named verb of the same table row), over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_setopts`/`verb_getopts`; the opcode table carries each reply.
  `open` sets the cached `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only.
  `bind` refuses a state other than `Open` with `[0]exbadport` and reports the bound port (`local_port` when the operand asked for `0`).
  `connect` installs the default peer (`EISCONN` is the racy spelling of "already connected"), an empty operand is the C's dissolve form back to `Open`, and the argument is accepted as the C's `[Timeout(4), address]` or as a bare packed address (decided by whether it already starts with a family tag).
- **`recv` carries the source address (the one design decision).** A datagram's source cannot ride the port's byte-only input queue and [`crate::PortNotification`] must keep exactly its two variants (an outside crate matches it exhaustively), so reception is **verb-driven**: `recv` performs **one** `recvfrom(2)` into a 64 KiB buffer (`DATAGRAM_CHUNK`, larger than the largest IPv4 UDP payload), pushes the payload to the port input queue (harvested by the runtime as a `Data` notification and rendered as `{udp, S, IP, Port, Data}`) and answers the **eight**-byte `[1] ++ [INET_AF_INET, port_hi, port_lo, a, b, c, d]`; on `EAGAIN` it answers the **bare** `[1]` and delivers nothing, so the reply length distinguishes the two; a socket-less port answers `[0]einval`.
  `Driver::ready_input` is therefore a documented **no-op** — the socket still registers read readiness, and the runtime sees the event and issues `recv`.
- **The `send` operand accepts two wire forms** (`udp.rs::verb_send`, the C's `packet_inet_command` `:15037`-`:15260`), tried in this order — **the plain form is authoritative**:
  1. the **plain form, tried first** — `wire::split_address(arg)`, the `[address][payload]` grammar every direct `port_control` caller and `port_command`-shaped probe uses; when it parses, that **is** the command, so a plain command can never be misread as a prefixed one.
  2. the **caller-reference form, only when rule 1 refuses** — `wire::split_caller_ref(arg)` strips the `[n:be16][n tag bytes]` `prim_inet` prefix (when `n >= 1`, `2 + n` fits and `arg[2] == 131`), then `wire::split_datagram` decodes the C's `[address][anc_len:be32][anc_data][data]`: fewer than 4 bytes left or a truncated payload ⇒ `Einval` ⇒ the `[0]einval` reply, and a **non-zero** `anc_len` ⇒ the typed `unsupported` raise (the C's `sendmsg(2)`-with-cmsgs arm has no seam here); an argument in **neither** form keeps rule 1's `badarg`.
  **Plain-first is sound** because a caller-reference prefix starts with the 16-bit *tag length*, whose first byte is `0` for every realistic tag (`term_to_binary/1` of a `ref`/pid is tens of bytes) and `0` is never a valid address tag (1/3/4); only a *prefixed* command with a tag length ≥ 256 can be misread (see *Known Issues*).
- **A queued command needs only an *open* socket; the destination comes from the command.** `write_pending` (the C's `packet_inet_command`) guards `!IS_OPEN` only (`:15068`), parses the queued front with the C's `[address][anc_len:be32][anc][data]` grammar, then picks `send(2)` when the socket is connected (the address is parsed and then **ignored**, `:15164`) or `sendto(2)` with that address when it is not (`:15174`) — so `gen_udp:send/4`'s unconnected-socket form really sends.
  Grammar order (the same helpers, no second parser): `split_datagram(front)` first, and only on a grammar refusal `split_caller_ref` then `split_datagram`; that order is sound here because the queued path has no `[address][data]`-without-anc_len shape in the C and a caller-reference prefix leads with a `0` byte.
  Accounting is `stat.output(payload.len())` — the payload only (`inet_output_count`, `:15163`), counted at issue time. `anc_len != 0` is the typed `unsupported`; a socket-less port, a malformed operand (the two `return_einval` guards, an unparsable address) or a command in neither form is the typed `BeamError::BadArg` with the queued bytes **never consumed** (the honest analogue of the C's `[0]einval` reply, which this path cannot send).
- **Deliberate non-mirrors** (each chosen so the floor never leaks a socket or answers a wrong result): `open` of a second socket on a live port answers `[0]einval` where the C's `inet_ctl_open` answers `[0]exbadseq` (`:5130`), the same choice the TCP driver makes; `open` accepts only `INET_TYPE_DGRAM` (the C serves `SOCK_STREAM` from either entry point, being one driver file); a `getopts` on a socket-less port answers a well-formed reply where the C's `inet_fill_opts` can walk a `NULL` descriptor.
  **Absent by design** (a typed error, never a wrong result): `{active, …}` datagram delivery (*Handoffs*), ancillary data (`recvmsg`/`sendmsg`/`IP_PKTINFO` cmsg flags), the async-op queue, the `INET_REQ_PEER`/`INET_REQ_NAME` **named**-verb forms (the numeric `Peer`(4)/`Name`(5) opcodes ARE served), and IPv6/SCTP/Unix-domain sockets and DNS resolution.
- **Ownership** — as the TCP driver: an `open`/`from_socket` descriptor is closed on `stop`, on the `close` verb and on `Drop`; a **prebound** `INET_REQ_FDOPEN` socket is only deregistered and never closed, because it belongs to the caller (`erl_inet_close`, `:5102`-`:5117`).

### `wire.rs` (private) — the wire vocabulary
- Constants: result tags `INET_REP_OK`(1)/`INET_REP_ERROR`(0); address tags `INET_AF_INET`(1)/`INET_AF_ANY`(3)/`INET_AF_LOOPBACK`(4); socket types `INET_TYPE_STREAM`(1)/`INET_TYPE_DGRAM`(2); `INET_PROTO_DEFAULT`(0)/`INET_PROTO_TCP`(1)/`INET_PROTO_UDP`(2); `TCP_SHUT_RD`/`_WR`/`_RDWR`; `INET_IFOPT_*`/`INET_IFF_*`.
- The **packed-address codec** (`InetAddr`, `parse_address`/`pack_address`/`packed_addr_reply`, and `split_address` — the `[address][payload]` splitter) and `FakeAddress`/`parse_fake_address` (the `SETNAME`/`SETPEER` decoder, switching on the **cached** family).
- `ctl_ok`/`ctl_error`/`ctl_xerror` (the C's `ctl_reply`/`ctl_reply_ok`/`ctl_error`) and `errno_name` (the lowercase `erl_errno_id` renderer; `EBADF` ⇒ `"ebadf"`).
- The **shared `inet_ctl` reply bodies**, so no driver hand-builds one: `getstat_reply(arg, &InetStat, send_pend: usize)`, `gettype_reply`, `getfd_reply`, `getstatus_reply`, `name_reply`, `peer_reply`, `subscribe_reply`, `getservbyname_reply`, `getservbyport_reply` — each reproduces the C arm exactly, including the socket-less refusals (`einval` for `GETTYPE`/`GETFD`, `ebadf` for `NAME`, `enotconn` for `PEER`) and `getstat_reply`'s `BadArg` for an op outside 1-10.

  The constants are re-exported at `crate::drivers::inet::*`; these helpers stay `pub(super)` inside the subtree.

### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- **Wire forms**: `setopts` takes five-byte `[opt, val_be32]` records (`inet_set_opts`, `:6915-6918`; `while (len >= 5)`, so a trailing partial record is ignored) and answers `[1]`; the one **seven**-byte record is `{active, N}` (a trailing big-endian 16-bit `N`, `:6975-6987`).
  `getopts` takes one-byte codes (`while (len--)`, so an empty payload answers a bare `[1]`) and answers `[1] ++ [code, val_be32]*` **in request order** (`inet_fill_opts`, `:9141-9751`); an `{active, N}` read-back appends a two-byte counter (`:9179-9183`).
- **Syscall-backed codes** (a direct `setsockopt`/`getsockopt`): `0` `reuseaddr` (`SO_REUSEADDR`), `1` `keepalive` (`SO_KEEPALIVE`), `4` `broadcast` (`SO_BROADCAST`), `6` `sndbuf` (`SO_SNDBUF`), `7` `recbuf` (`SO_RCVBUF`), `10` `nodelay` (`TCP_NODELAY`), `46` `ttl` (`IP_TTL`).
  `recbuf`/`sndbuf` report the **kernel's** value (Linux doubles a request: 4096 ⇒ 8192, the oracle); the one `resolve` table serves both drivers, so `reuseaddr`/`broadcast`/`ttl` are served on a datagram socket too (the C's `INET_OPT_*` table is shared between its TCP and UDP halves).
- **Driver-state codes** (stored in `SocketOptions` and reported with the oracle's defaults; `packet`/`packet_size`/`line_delim` are **acted on** on the TCP read path): `22` `{active, …}` (default `false`, + `active_count`), `23` `{packet, …}` (default `raw`), `24` `{mode, list|binary}` (default `list`), `25` `{deliver, port|term}` (default `term`), `30` `{send_timeout, …}` (default `infinity`), `32` `{packet_size, …}` (default `0`), `33` `{read_packets, N}` (default `5`), `35` `{send_timeout_close, …}` (default `false`), `40` `{line_delim, …}` (default `'\n'`, **set-only**).
  `set_options`/`get_options` both take the driver's **cached socket type** (`stype`, `0` = none) and derive every gate from it — the C gates on `desc->stype`.
  `{mode, …}`/`{deliver, …}` are **ungated** — set and reported identically on both drivers (`inet_drv.c:6939-6956`, `:9168-9175`), which is what makes `gen_tcp:listen(0,[binary])` (⇒ `{mode,binary}`) work.
  `{read_packets, N}` is gated on `stype == SOCK_DGRAM` (`:7138-7146`, `:9258-9270`), so on any other type — a stream socket, or no socket at all — a `setopts` is **silently ignored and still answers `[1]`** (the `N <= 0 ⇒ [0]einval` test lives *inside* the gate) and a `getopts` contributes **no record** (a bare `[1]`, not an error).
  `send_timeout`/`send_timeout_close` are gated on `stype == SOCK_STREAM`, and `stype` is set by `open` and **never cleared by `close`**, so a read-back survives a close (as does `GETTYPE`'s cached pair).
- An **unserved** code (`HEADER`/`BUFFER`/`EXITONCLOSE`/`TCP_DELAY_SEND`) is the C's whole-reply `[0] ++ "einval"` (never a partial reply), so a mixed request like `[keepalive, 200]` answers exactly that.
- **Mirrored quirks**, each measured against `erl` byte-for-byte: a configured buffer reports the kernel value; `setopts` answers `[1]` even when the kernel rejects the option (the C's `propagate = 0`, `:7898`/`:7923-7942`); neither verb has an `IS_OPEN` guard, so on a socket-less port `setopts` answers `[1]` and `getopts` drops a syscall-backed record but an unserved code is still `[0]einval`; `getopts` of `line_delim` (`40`) is the C's `[0]einval` and replaces the **whole** reply (while `setopts` of `40` is served); `{active, N}` **adds** to the running counter (`:6987`), clamps at zero (falling back to `{active, false}`, `:6993-6998`), a sum outside the signed 16-bit range is the whole-reply `[0]einval`, and any other `{active, …}` value resets the counter.
- **One deliberate non-mirror**: a **truncated** `{active, N}` record (value but no trailing 16-bit `N`) is `BadArg` (the C reads past the payload). A failed `getsockopt(2)` on a live socket is **not** a divergence: that record alone is dropped and the search continues, exactly the C's `TRUNCATE_TO(0, ptr); continue;` (`:9734`-`:9741`), with every already-produced record kept and later codes still tried.

### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant **is** the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`.
  Decoded: `Raw`(0), `Len1`(1), `Len2`(2), `Len4`(3), `Asn1`(4), `Rm`(5), `Cdr`(6), `Fcgi`(7), `LineLf`(8), `Tpkt`(9).
  **Unsupported**: the HTTP family `Http`(10)/`HttpH`(11)/`HttpBin`(13)/`HttpHBin`(14) and `SslTls`(12) — their bodies need the C's term-building `PacketCallbacks`.
- `PacketLength { Complete(usize), NeedMore, Invalid, Unsupported }` — the C's `packet_get_length` `> 0`/`0`/`< 0` plus an explicit "not implemented"; `is_complete()`/`complete()`/`as_error()` (`Invalid`⇒`badarg`, `Unsupported`⇒`notsup`).
  `Complete(len)` is the **total** length including the header, known as soon as the header suffices.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — the four arguments of `packet_get_length`; `Default` = `{packet, raw}`, delimiter `DEFAULT_DELIMITER` (`\n`), no limits; builders `new`/`with_delimiter`/`with_max_plen`/`with_trunc_len`; `decode(&[u8]) -> PacketLength`.
  `max_plen == 0` means "no limit" (`INT_MAX - hlen`) and bounds the **payload** (`plen`), never the total frame.
- `PacketType::payload_range(&[u8]) -> Result<Range<usize>>` — the C's `packet_get_body` header strip: the header is removed for `Len1`/`Len2`/`Len4` and the FCGI padding subtracted for `Fcgi`; every other type (including `LineLf`) is returned **as is**, so a `{packet, line}` payload keeps its delimiter (the oracle's `gen_tcp:recv`).
- **Three faithfully-reproduced C quirks**: `Raw` ignores `max_plen` (`:258`); line mode compares `max_plen` strictly-but `trunc_len` inclusively before a delimiter is found, and both strictly after (`:298-320`); `Raw` with an empty buffer is `NeedMore`, not `Complete(0)` (`:258`).

### `frame.rs` (private) — the framing glue (read + send)
- The bridge from the driver's stored `SocketOptions` to the pure decoder, called by the driver's read and send paths; a port of the C's `tcp_remain`/`tcp_reply_data`/`tcp_send` pair.
- `options(&SocketOptions) -> PacketOptions` (the C's arguments at `inet_drv.c:12975`; `trunc_len` stays 0 — this driver has no fixed input buffer, it accumulates into a growable `Vec`); `framed(&SocketOptions) -> Option<PacketType>` (`None` only for `Raw` and an out-of-range code); `write_header(&SocketOptions, len) -> Option<Vec<u8>>` (the send-path counterpart of `extract` — the 1-/2-/4-byte big-endian length header the `send` verb prepends under `{packet,1|2|4}`, `None` for every other code); `extract(&mut Vec<u8>, &PacketOptions) -> Result<Option<Vec<u8>>>` — **exactly one** frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.
  All four are `pub(super)`.

### `sys.rs` (private) — the raw socket syscalls
- Every `unsafe` block of the drivers lives here: `socket`/`bind`/`listen`/`accept`/`connect`/`getsockname`/`getsockopt`/`setsockopt`/`read`/`send`/`shutdown`/`close`, each with a `// SAFETY:` rationale.
  Also `get_socket_int_option`/`set_socket_int_option` (the syscall-backed option family), and `local_address(fd)`/`peer_address(fd)` — one `getsockname(2)`/`getpeername(2)` into a `sockaddr_storage`, decoded by a private `decode_inet_address` (**`AF_INET` only**; any other family is the C's failure, so `INET_REQ_NAME`/`INET_REQ_PEER` answer their errno reply rather than a wrong address).
- The datagram family the UDP driver needs shares the file: `dgram_socket_fd` (the `AF_INET`/`SOCK_DGRAM` socket), `bind_socket`, `connect_socket`, `send_to` (an unconnected socket, `sendto(2)`), `send_connected` (`send(2)` on a connected one) and `recv_from` (one `recvfrom(2)`, returning the payload length together with the source `InetAddr`), over the shared `has_peer`/`local_port`/`close_fd`.
- `wait_connected(fd, timeout_ms) -> Result<Option<i32>>` — the synchronous-completion primitive behind `INET_REQ_CONNECT`: one `poll(2)` for `POLLOUT` (the deadline recomputed from an `Instant` so a retry can never extend the budget, `EINTR` retried) followed by `getsockopt(SO_ERROR)`, answering `Some(0)` for an established connection, `Some(errno)` for a failed one and `None` when the budget expired.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: an operational socket failure ⇒ the `[0]`-tagged reply; a malformed argument / unknown named verb ⇒ `BeamError::BadArg`; an I/O syscall failure ⇒ `BeamError::Io`; an undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`.
  Never a wrong result, never a panic.
- **One `Driver` is one port**: no port-creation capability (the `accept` transfer + the port-creation deferral above).
- Safe Rust except `sys.rs`; `unsafe_op_in_unsafe_fn` stays clean; the `Driver`/`DriverContext` seam is frozen.
- Files target ~1000 lines; the suite files (`tests.rs`, `opcode_tests*.rs`, `opt_tests.rs`, `stat_tests.rs`, `frame_tests.rs`, `udp/udp_tests.rs`) are in-module test modules split from their source half to keep each source file near the target.

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
Each needs a change **outside** `src/drivers/inet/`; every one is a real `gen_tcp` capability the floor refuses honestly today (bullet (a) is the one the datagram driver needs too).
- **(a) `{active, N|true|once}` / `{deliver, port|term}` / `active_count` delivery.** The options are stored and reported, but a driver never delivers input on its own: bytes land in the port input queue (or `pending_input` under framing) and the runtime decides when to fetch them.
  Needs a per-frame input drain plus a driver→owner send path — `DriverContext` reaches only the port id/poller/two byte queues, and a port-task round harvests its input in one step.
  **The datagram driver has exactly this gap in its most visible form**: `udp_inet`'s `recv` is the only datagram path there is, so `{active, true|once|N}` never fires and `{udp, S, IP, Port, Data}` is never fabricated — a runtime that wants active mode must drive `recv` itself, build the tuple from the reply's source address, and install the missing driver→owner message path.
  **Do not add a variant to `PortNotification`**: `beam_rt` matches it exhaustively (two arms, no wildcard), so a third variant breaks a crate outside this node; the precedent for a per-frame channel is the `{line,N}` work — a **separate** frame struct (`LineNotification`) plus a drain accessor on the registry (`PortRegistry::take_line_notifications`), polled after a round.
- **(b) `send_timeout` / `send_timeout_close`.** Both are stored and reported but not acted on: the C arms a driver multi-timer (`add_multi_timer(..., &tcp_inet_send_timeout)`, `:13789`) that fires while output is queued and answers an **asynchronous** `{inet_reply, S, Status, Mref}`-shaped `{error, timeout}` (closing under `send_timeout_close`, `:12458-12482`).
  Needs a reply channel out of `Driver::timeout()` (its `Result<()>` is discarded by `Port::run_task`'s `Timeout` arm) + a pending-command slot + the `{inet_reply, …}` tag.
- **(c) `controlling_process`.** Not driver state: `inet:tcp_controlling_process/2` (`lib/kernel/src/inet.erl:4848`) is `erlang:port_connect(S, NewOwner)` + an Erlang-side drain of buffered `{tcp, S, Data}`/`{tcp_closed, S}`/`{inet_async, …}` messages; there is no `INET_REQ_*` and the `Driver` seam has no owner notion.
  Needs `beam_process::PortTable::set_owner` (exists, unused) + `beam_rt`'s `PortMeta.owner`.
- **(d) The async-op queue + the `{inet_async, …}`/`{inet_reply, …}` messages.** `INET_MAX_ASYNC = 1` (`:1069`), `enq_async`, the `[1] ++ async_id_be16` reply, the later `{inet_async, Port, Ref, Result}` message, a per-port 16-bit op ref and a **second-port** `accept`; the same driver→owner send path is the missing seam for `{inet_reply, S, ok | {error, Reason}, Mref}` (`inet_reply_finish`/`inet_reply_caller_ref`, `:2610`-`:2660`), for `{active,N}` delivery, for `send_timeout` and for `SUBSCRIBE`'s `{empty_out_q, Port}`.
  `recv` and `accept` stay **synchronous** — which is why `TCP_REQ_RECV`/`PACKET_REQ_RECV` validate the C's 8-byte `Timeout(4), Length(4)` operand and *ignore* it, `ACCEPT` validates its 4-byte timeout and ignores it, and `accept` transfers the port rather than returning an async id — and `connect` **does not touch the queue at all**: it completes inside the control call under the bounded `sys::wait_connected` wait.

## Known Issues
- **Two oracle shapes for a socket-less command are unreachable, so the driver answers the third honestly.** Measured on a bare `{spawn_driver,"tcp_inet"}` port: `port_command(P,<<0,0,1>>)` (a payload carrying the 2-byte caller-ref prefix) ⇒ the oracle answers `true`, the port stays **alive**, and `{error,enotconn}` is delivered out of band (`inet_drv.c:12645` — the real `IS_CONNECTED` guard); `port_command(P,<<1>>)` (no prefix — what a plain CLI probe sends) ⇒ the oracle answers `true` and then the port is **dead** (`port_info(P, name)` is `undefined`, `init_caller` `:1854` → `driver_failure_posix(EINVAL)`, `:12634`), every later command raising `badarg`.
  Neither shape is reachable through the frozen `Driver` trait (no `driver_failure` seam, no asynchronous `{inet_reply, …}` channel), so the driver answers the typed `BeamError::BadArg` with the bytes retained and `erlang:port_command/2` raises — the honest driver-side refusal, and the only observable difference from the oracle on that path.
- **`recv`/`recv`-alike answer a synchronous read-now, and `{inet_reply, …}` cannot be sent** (both are the missing driver→owner channel of *Handoffs* (d); every operand is validated exactly as the C does, so only a caller inspecting the reply tag/length — or waiting on `{inet_reply, S, Reply, Mref}`, which `prim_inet:send/3`/`do_sendto/4` do — can tell).
- **The TCP caller-reference prefix is not stripped (no sound discriminator).** `init_caller`/`init_caller_iov` (`inet_drv.c:1820`-`:1890`) strip the `[n:be16][tag]` prefix at the head of `tcp_inet_command` (`:12634`), but only when `driver_caller(port)` is an internal pid; a TCP payload carries no structure after the prefix, so nothing tells a prefixed payload from a plain byte stream that happens to begin with those bytes — unlike the UDP `send` verb, whose post-prefix grammar starts with an address tag.
  The frozen `Driver`/`DriverContext` seam has no caller notion, so `TcpInetDriver::verb_send` keeps the plain grammar and a `gen_tcp:send` payload's prefix would be written as data; closing the gap needs a `driver_caller` equivalent on the seam (or the strip above this crate, in `beam_rt`).
- **The TCP `port_command` write path does not count statistics (the UDP one does).** [`stat::InetStat`] is fed from the `send`/`recv` control verbs and the framed read path, and `udp_inet::write_pending` feeds it from the queued command's payload (`inet_output_count`, `:15163`); `TcpInetDriver::output` has no per-command byte boundary — the port's `ByteQueue` is a byte stream — so bytes written through `erlang:port_command/2` are not counted there, whereas the C's `inet_output_count` sees every `tcp_inet_command`.
  Only a per-command boundary on the `Driver` seam (or a caller-ref-tagged command queue) would close it.
- **The UDP caller-reference strip is a payload heuristic, but only a *fallback*.** `verb_send` tries the plain `[address][payload]` grammar first, so a *valid* plain command is always sent as plain — including the shape a caller-ref-**first** order would misread, pinned by `udp/udp_tests.rs::a_plain_command_with_a_0x83_low_port_byte_is_not_read_as_a_caller_reference`.
  The residual runs the other way: a *prefixed* command whose tag length is **≥ 256** has a first byte of 1/3/4, so the plain rule wins and the prefix is taken as an address; `prim_inet:send/3`'s tag is a small `term_to_binary/1` blob, so no oracle caller can produce it.
- **`SUBSCRIBE`(24)'s reply is exact; its *notification* is not.** `wire::subscribe_reply` reproduces `inet_subscribe` (`:10819`) byte for byte; the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends it `{empty_out_q, Port}` from `send_empty_out_q_msgs`, which this crate's `Driver`/`PortNotification` seam cannot send, so **no notification is ever sent**.
  A caller that only waits for the reply (`prim_inet:close/1`'s `subscribe(S, [subs_empty_out_q])`, the boot path) sees the C exactly; one that waits for the message sees nothing.
