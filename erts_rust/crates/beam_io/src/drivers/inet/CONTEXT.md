# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in **`tcp_inet`** driver (`mod.rs`): **one** non-blocking TCP socket behind one port — the counterpart of `inet_drv.c`'s `tcp_inet`, under `gen_tcp`/`inet_tcp`; its datagram half **`udp_inet`** (`udp.rs`), under `gen_udp`. Frozen names **`DRIVER_NAME = "tcp_inet"`** / **`UDP_DRIVER_NAME = "udp_inet"`** (`port_info(Port, name)`), registered by `make_tcp_inet()`/`make_udp_inet()`.
A port's socket: the `open` verb, `from_socket(fd)` (**owned**: `open`/named `accept`/`from_socket`) or `adopt_prebound(ctx, fd, stype)` (`INET_REQ_FDOPEN` — **borrowed**: port-lifetime, never closed here); a descriptor a **numeric** `accept`(26) completion hands over (`InetAsyncResult::Accepted`) belongs to that completion's consumer, none closed here.
Also owned: the **control-opcode bridge** (`opcode.rs`), the **async-op queue** behind `TCP_REQ_RECV`(42)/`ACCEPT`(26)/`PACKET_REQ_RECV`(60) (`async.rs`, `udp/async.rs`), the **active-input delivery** halves (`active.rs`, `udp/active.rs`), `{packet, N}` framing (`packet.rs`+`frame.rs`, a term-free `packet_parser` port), the **option vocabulary** (`opt.rs` walk + `OptScope` over `opt_state.rs`/`opt_sys.rs`), the **`INET_REQ_FDOPEN` errno channel** (`adopt_probe.rs`), `stat.rs`, `wire.rs` and every raw socket syscall (`sys.rs`). Ground truth: *See Also*.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
The Erlang side never sends a control *verb*: `erlang:port_control(Port, Op, Data)` carries an **integer**, `beam_rt` forwards its **decimal string**, `PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`; both drivers decode it here, before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a **decimal** command (optional `-`, ASCII digits accumulated **mod-2³²** as the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; unmatched ⇒ `Opcode::Unknown`, **non-decimal** ⇒ `None`, so every named verb keeps its path byte-for-byte.
- **The wrapping is observable:** an `Op` below the magic matches no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`, not `INET_REQ_OPEN`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, shared `inet_ctl`): one numberspace, each number a `case` of exactly one, so one owned by the *other* driver's switch is owned by neither ⇒ `[0]exbadport`.
- `Opcode` — one variant per table row below (same names, numbers), plus `Unknown`, with `ALL`/`code`/`from_code`/`scope`/`name`, `not_served() -> BeamError` (typed `unsupported` raise naming opcode and switch).

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A **decimal** command decodes to an opcode; any other is the **named verb of the same row** — both routes run one body, so replies are identical. **`s`** = served (whole arm, success included); **`ref`** = the C's refusals reproduced exactly, success path `Err(Opcode::not_served())`.
**Three `erl` matrices byte-compare every row against the system driver** — `opcode_tests.rs::oracle_matrix` (`tcp_inet`, **80 calls**), `opcode_tests_udp.rs::oracle_matrix` (`udp_inet`, **89**), `opcode_tests_states.rs::the_listen_and_connect_rows_agree_with_the_oracle` (**11** rows) — over bare / opened / listening-or-bound / connected / post-close states in one `erl` run.

**Neither switch owns the number** ⇒ `[0]exbadport` on both drivers (`Unknown`, a wrapped/sub-magic `Op`, a number that is a `case` of *the other* driver's switch, and `Listen`(27) on the datagram driver — SCTP compiled out). A refused opcode is **never** a fabricated success or an invented number. Both drivers are **symmetric** on every shared `inet_ctl` arm; only the per-driver switches, the `Fdopen` type guard (TCP stream only, the datagram driver both) and `Sendfile` differ.

#### Reply shape, packed address, error split
- **Reply shape** = the C's `ctl_reply`: one result-tag byte (`INET_REP_OK` 1 / `INET_REP_ERROR` 0) + payload; `wire::ctl_ok`/`ctl_error(errno)`/`ctl_xerror(name)` build one, the errno a lowercase name (`erl_errno_id`) or fixed atom (`einval`/`enotconn`/`eisconn`/`exbadport`/`ebadf`/`closed`).
- **Operational** failures ⇒ the `[0]`-tagged reply; **malformed argument** / **unknown (non-numeric) verb** ⇒ `BeamError::BadArg`.
- **Packed address** (`bind`/`connect`/datagram source): `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag ⇒ `BadArg` (DNS/IPv6 out of scope).

### `stat.rs` (private) — the socket statistics counters
- `InetStat` (`pub(super)`) — one per driver: `recv_`/`send_` × `cnt`/`max`/`avg`/`dvi` plus `recv_oct`/`send_oct`, `Default` the C's zeroed init (why a socket-less port answers an all-zero `INET_REQ_GETSTAT`).
- `input(len)`/`output(len)` — the C's `inet_input_count`/`inet_output_count` on the `ARCH_64` path: `n = cnt.wrapping_add(1)`, `n == 0 ⇒ 1` (the wrap restart), octets `wrapping_add`, `max` upwards only. They differ: `input` takes the deviation from the **updated** average, `output` the pre-update one in the numerator; both are observed only through `inet_fill_stat`'s 32-bit truncation.
- Accounting sites: TCP `read_available`'s raw path (every retained + newly read byte), `verb_send` (payload **plus** any `{packet,1|2|4}` header), `verb_recv_framed` (payload only); UDP `verb_send` and the queued command (payload only — never the caller reference, packed address or ancillary-length word) and `verb_recv`. The TCP `port_command` path deliberately does **not** count (*Known Issues*).
### `mod.rs` — the TCP driver
- `DRIVER_NAME: &str = "tcp_inet"`; `make_tcp_inet() -> Result<Box<dyn Driver>>` (the `DriverFactory`); `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket.
- Constructors: `new()` (socket-less registry factory; the `open` verb creates the socket, the C's `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts + probes kernel state: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound(ctx, fd, stype)` (`Fdopen`(13)).
- Accessors: `socket() -> Option<RawFd>`, `state() -> InetState`, `eof()`/`peer_closed()` (latched read EOF / peer close), `connect_error() -> Option<&str>` (late `SO_ERROR`); `stat: stat::InetStat` feeds `INET_REQ_GETSTAT`. `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`, `state_code()`) is the C's `INET_STATE_*` (no socket before `open`).
- **Fake endpoints** `name_addr`/`peer_addr` (`desc->name_ptr`/`peer_ptr`): installed/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address`, reported by `Name`/`Peer` for `getsockname`/`getpeername`; `Getladdrs`/`Getpaddrs` do **not** read them, and only `len == 0` clears them (a `close` leaves them).
- `PeerClose` (`TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND`) — `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event: registration released, socket never touched again, the one-shot `closed`/`enotconn` replies armed (**first** `recv`/`send` answer `closed`, every later one `enotconn`).
- **Control verbs** — `Driver::control` takes the packed payload as raw bytes in **both** wire forms: an [`opcode`](#opcoders--the-numeric-control-opcode-bridge)-decoded decimal, or the **named verb** of the same row, both running one `verb_*` body; an unknown non-numeric verb is `BadArg`.
- **`connect` completes synchronously under a bounded wait.** `EINPROGRESS` settles in-call via `sys::wait_connected(fd, connect_wait_ms(timeout_ms))`: `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`; `Some(errno)` ⇒ `[0] ++ <lowercase errno>`, errno kept in `connect_error`; `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout` (row 3). Budget `CONNECT_WAIT_CAP_MS = 30_000` (`const fn connect_wait_ms`: negative — `INET_INFINITY` — ⇒ cap, `0` ⇒ one poll, positive ⇒ clamped). The one inline family, so `EINPROGRESS` never yields the C's `[1] ++ async_id_be16` (a divergence; `prim_inet:connect_cmd/3` maps `{ok,[]}` to `ok`).
- **Readiness & flow control**: the poller is edge-triggered (`EPOLLET`), so every callback drains to `EAGAIN`; the socket is **one** descriptor ⇒ **one** registration with a flipped `Interest` mask — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and **arms** write readiness) or an over-budget `connect` is in flight, dropped when the queue drains. Output left at a latched peer close is dropped (`tcp_clear_output`); writes use `send(2)` + `MSG_NOSIGNAL`.
- **A command on a socket-less or unconnected port is consumed and answered out of band, never dropped.** `init_caller` (`:1820`-`:1890`) runs before the connection is looked at, size-only: a **malformed/untagged** command latches `DriverFailure::posix(EINVAL)` (`io.c:7273`), so `PortRegistry::reap_failures` closes the port after the round (`port_command/2` still `true`, every later command the oracle's `badarg`); a **well-formed** prefix on a port that cannot write stages `Error(ENOTCONN)` (`tcp_inet`, `:12674`) / `Error(EINVAL)` (**socket-less** `udp_inet`, `:15068`), port **alive**; an **empty** queue is `Ok(0)`, latching nothing; an empty or non-ETF tag is consumed, staging **no** reply (`echoable_caller_tag`). The **named** verbs answer `[0]enotconn`(stream)/`[0]einval`(datagram) for a missing socket or peer.
- **One socket, one port (the `accept` divergence)**: the C's `INET_REQ_ACCEPT` creates a **second** Erlang port; this seam cannot, so the **numeric** request joins the multi-op accept list and reports what it took off the listener **inside its completion** (`InetAsyncResult::Accepted { fd }`) — the runtime opens the second port (`from_socket`/`INET_REQ_FDOPEN`); the driver never stores the descriptor, so no teardown closes it and the listener keeps accepting. Only the **named** `accept` **transfers this port** (listener closed, descriptor adopted, reply `[1] ++ fd_be32`); N queued accepts answer their own id in enqueue order.
- **No completion is produced inside a control call** — the id is the whole reply; the production points are readiness (`ready_input`), the port timer (`Driver::next_timeout`/`timeout`, armed from the operation's deadline) and the round's async drive (`drive_async`, also serving data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` first.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, only under a framing `{packet, N}` (never raw); the C's `desc->i_buf`, cleared when the socket is replaced/closed. A `{packet, …}`/`{line_delim, …}` change with bytes buffered is **not** flushed: the next `recv` re-decodes them under the new options (a switch **to** `raw` delivers the retained buffer verbatim).
- **Ownership**: `prebound: bool` (`desc->prebound`) is set **only** by `adopt_prebound`, cleared by `adopt`, honoured by `close_socket`'s early return — an **owned** descriptor (`open`/`accept` create, `from_socket` adopts) is closed on `stop`, the `close` verb and `Drop`, while a **prebound** `INET_REQ_FDOPEN` one is only deregistered, never closed (it belongs to the caller).

### `udp.rs` (`pub`) — the datagram driver
- `UDP_DRIVER_NAME: &str = "udp_inet"`; `make_udp_inet() -> Result<Box<dyn Driver>>`; `UdpInetDriver` (`Driver::name() == "udp_inet"`) — one datagram socket, with `new()` (socket-less; the `open` verb creates it), `from_socket(fd)` and `adopt_prebound(ctx, fd, stype)` (`stype` the operand's `INET_TYPE_*` tag, stream and dgram both admitted). `prebound`/`stat`/ownership follow the stream driver's; accessors `socket()`/`state()` over the same `InetState`.
- **Control verbs** — the same two wire forms, over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_getopts` (`setopts` goes through `setopts_with_effects`, whose `ctx`-carrying form also arms and can stage a `Passive`, `udp/active.rs`). `open` caches `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only; `bind` refuses any state but `Open` with `[0]exbadport` and reports the bound port; `connect` installs the default peer (`EISCONN` = "already connected"), an empty operand dissolving to `Open`, the operand `[Timeout(4), address]` or a bare packed address (a family tag decides).
- **Reception has two paths; the source address rides only the asynchronous one.** A datagram's source cannot ride the byte-only input queue, so `PACKET_REQ_RECV`(60) queues on the shared async slot (row 60), its header the 7 packed source bytes. The named `recv` verb is this floor's read-now convenience (the C has no such control op): one `recvfrom(2)`, the payload pushed to the port input queue and the eight-byte `[1, INET_AF_INET, port_hi, port_lo, a, b, c, d]` reply; `EAGAIN` ⇒ a **bare** `[1]`, socket-less ⇒ `[0]einval`. `Driver::ready_input` completes a queued operation; with **none** queued it reads nothing, which is what makes the active path safe (*Active-mode input delivery*).
- **`send` accepts two wire forms** (`verb_send`, the C's `packet_inet_command`), **the plain form authoritative**: `wire::split_address`'s `[address][payload]` grammar first, and only when it refuses `wire::split_caller_ref`'s `[n:be16][n tag bytes]` `prim_inet` prefix (`n >= 1`, `2 + n` fits, `arg[2] == 131`) then `wire::split_datagram`'s `[address][anc_len:be32][anc][data]` — a truncated operand ⇒ `[0]einval`, a **non-zero** `anc_len` ⇒ the typed `unsupported` raise, neither form keeping rule 1's `badarg` (*Known Issues*).
- **A queued command needs only an *open* socket; the destination comes from the command.** `write_command` strips one caller tag, stages the out-of-band refusals, then hands the rest to `write_pending`, which guards `!IS_OPEN`, parses the queued front with the C's `[address][anc_len:be32][anc][data]` grammar, then picks `send(2)` when connected (address **ignored**) or `sendto(2)` with it when not — so `gen_udp:send/4`'s unconnected form really sends; accounting is `stat.output(payload.len())` at issue. A socket-less port, a malformed operand or a command in neither form is `BeamError::BadArg`, bytes **never consumed**. Once the queue drains, `settle_command` stages `{inet_reply, Port, ok | {error, Reason}, Tag}` from the tag taken **verbatim**; no tag, and the C's zero-length `[0,0]` tag, stage **nothing**. The queued grammar is parsed **once**, after the one `init_caller` pass.
- **Deliberate non-mirrors**: a second `open` answers `[0]einval` where the C answers `[0]exbadseq`; `open` admits `INET_TYPE_DGRAM` only; a `getopts` on a socket-less port answers a well-formed reply where the C's `inet_fill_opts` can walk a `NULL` descriptor. **Absent by design** (a typed error): `{deliver, port|term}` and ancillary data (`recvmsg`/`sendmsg`/`IP_PKTINFO` cmsgs), the `INET_REQ_PEER`/`INET_REQ_NAME` **named** forms (the numeric `Peer`(4)/`Name`(5) opcodes ARE served), IPv6/SCTP/Unix sockets and DNS resolution.

### `async.rs` (private) / `udp/async.rs` — the asynchronous-operation queue
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword; `udp/async.rs` = the datagram bodies under the same hook names).
- `AsyncQueue` — one **receive slot** (`INET_MAX_ASYNC = 1`, a second concurrent receive `[0]ealready`) plus a **multi-operation accept list** (never `ealready`); `accept_state_bits` reports `INET_F_ACC`/`INET_F_MULTI_CLIENT` through `GETSTATUS`. `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, from **0**, taken **before** the capacity check so a *refused* enqueue still consumes an id; wraps at 65536 (the 255→256 step carries into the high byte).
- `deadline_for(timeout_ms)` — a **negative** timeout is the C's `INET_INFINITY` (`None`), `0` "now", positive an `Instant`; `parse_recv_operand`/`parse_timeout_operand`/`length_too_large` decode `Timeout(4), Length(4)`; `async_ok_reply` builds `[1] ++ <<Id:16/big>>`.
- Hooks: `try_complete_recv` (read path), `async_ready_input` (readiness), `async_timeout` (port timer), `drive_async_ops` (the round's drive point, also serving data that arrived before the request), `accept_ready_once`, `drain_closed` — the teardown drain answering `{error, closed}` **once** per pending operation, from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) sits beside the queue in each driver: one prefix per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.
### Active-mode input delivery (`active.rs` = the TCP half, `udp/active.rs` = the datagram half)
An `{active, true|once|N}` port delivers each arriving input to its **owner** on the crate's `{active,…}` channel (`ActiveInput`/`ActiveInputEvent::{Data(ReadMessage), Passive}`, `DriverContext::deliver_active_input`, `PortRegistry::take_active_inputs`) — never via `{Port,{data,…}}` or a `CompletionEvent`; `PortNotification` keeps its two variants, and rendering the oracle's messages from the drain is `beam_rt`'s (*Handoffs* (a)).
- **Shape** — one `ReadMessage` per delivered unit, term-free. A datagram's `header` is the 7 packed source-address bytes (`wire::pack_address`: family byte, **big-endian** port word, four network-order address bytes, `inet_drv.c:4896`), its body the payload — the prefix `PACKET_REQ_RECV` builds. A stream's `header` is the **`{header,N}` option only** (`desc->hsz`, `:6931`, default 0, `:10922`) — **not** the framing header, which `frame::extract` already stripped — its body the rest of one frame. `{mode, list|binary}` never reaches this layer: bytes are handed up either way, the flattening the runtime's (`tcp_message:3979`, `:4000`/`:4142` short-circuit on `INET_MODE_LIST`).
- **One unit at a time; the loop stops the moment the mode flips** (the C's `if (!desc->inet.active)`, `:13108`-`:13114`): one `{packet,N}` frame per message (a partial or merged frame is never delivered — the remainder stays in `pending_input`) and exactly **one** message per read burst in `{packet,raw}` (`packet_get_length` calls the whole buffer one unit, `:13099`-`:13123`).
- **The burst is bounded by `{read_packets}`** (`INET_LOPT_UDP_READ_PACKETS`, default `INET_PACKET_POLL = 5`, `:1072`/`:14508`; `packet_inet_input`'s `while (packet_count--)`, `:15378`): at most that many datagrams per readiness callback, `EAGAIN` ending it early and the next round taking the rest. `stat.input(len)` counts each delivered payload (`inet_input_count`, `:15513`).
- **The matrix** (`INET_CHECK_ACTIVE_TO_PASSIVE`, `:1552`-`:1560`, per delivered packet via `:4302`/`:4329`/`:4352`): `{active,true}` never changes; `{active,once}` flips **silently** (no message; the next input stays in the kernel for a later passive read); `{active,N}` decrements, and on 0 flips **and** stages one `Passive` (`packet_passive_message`, `:4215`). `Passive` comes from exactly **two** places — the delivery that spent the last credit, and the `setopts` walk below; `{active,true}`/`{active,false}` never emit one.
- **`{active,N}` is `INET_MULTI` (3) plus a trailing big-endian 16-bit counter**. `opt_state::set_active` accumulates it (`ac = active_count; ac += nval`; past the `Sint16` range ⇒ `[0]einval` **with no rollback** of `active`, `:6975`), clamps a negative sum to 0, and turns a 0 sum into `INET_PASSIVE` **inside the walk** ⇒ the `Passive` arrives from the control path with no datagram, round or poll (`:6993`-`:6998`); any non-multi `{active,…}` zeroes the counter (`:6999`-`:7000`). `opt::set_options_tracked` reports that out of the walk (`landed_at_zero`, never cleared) — the only place that knows which record carried the payload — and each driver's `after_setopts` turns it into the delivery.
- **Arming is a driver-side gate, not a poller mask.** The C calls `sock_select(desc, FD_READ|FD_CLOSE, active > 0)` (`:7944`-`:7987`), but `crate::poller::Interest` has no empty mask (`READABLE`/`WRITABLE`/`BOTH` only) and `mio`'s epoll is **edge-triggered (`EPOLLET`), not one-shot**. Substitution: the socket keeps its read registration for its life, the driver gates delivery on `options.active > 0`, and a passive→active transition **re-arms** with `set_interest(ctx, Interest::READABLE)` (an `epoll_ctl(MOD)`, which yields a fresh edge for already-buffered data) — never a deregister/re-register per flip.
- **Readiness dispatches on state, exactly once.** `TcpInetDriver::ready_input` takes the C's `tcp_inet_input` shape (`:13461`/`:13598`): a **connected + active** socket with no queued `TCP_REQ_RECV` goes to `active_delivery` **only**; the accept ladder, a queued receive and a passive connection's bytes-into-the-port-queue stay with `async_ready_input`. Running both paths is a defect — `read_available` would push the bytes onto the passive channel (`ctx.input()` raw, `pending_input` framed) and starve the active path.
- **The inline burst is TCP-only and only for `{active,once}`/`{active,N}`.** `inet_set_opts`'s tail returns 2 (`trigger_recv`) only for `SOCK_STREAM` with `!old_active`, the new mode `once`/`multi` and an unchanged `{packet,…}` (`:7955`-`:7961`), and the `INET_REQ_SETOPTS` consumer reads 2 as an inline `tcp_recv` + re-arm (`:11145`), so a waiting byte is delivered **inside** the ctl. `{active,true}` returns 1 ⇒ arm only (this floor pre-reads nothing, so the ctl delivers nothing); a UDP re-arm always waits for the next readiness event (both `/* XXX: UDP sockets could also trigger immediate read here NIY */` comments, `:7949`/`:7969`).

### `wire.rs` (private) — the wire vocabulary
- The wire constants (result tags, address tags, socket types, protocols, `TCP_SHUT_*`, `INET_IFOPT_*`/`INET_IFF_*` — values in the rustdoc).
- The **packed-address codec** (`InetAddr`, `parse_address`/`pack_address`/`packed_addr_reply`, `split_address`), `FakeAddress`/`parse_fake_address` (the `SETNAME`/`SETPEER` decoder, on the **cached** family), `ctl_ok`/`ctl_error`/`ctl_xerror`/`errno_name` (lowercase `erl_errno_id`; `EBADF` ⇒ `"ebadf"`), the datagram operand `split_datagram`/`DatagramCommand` + the caller-reference strip (`ETF_VERSION_MAGIC = 131`, `split_caller_ref`).
- The **shared `inet_ctl` reply bodies**, so no driver hand-builds one (one builder per served opcode, `getstat_reply(arg, &InetStat, send_pend: usize)` among them), each reproducing its C arm — socket-less refusals too (`einval` for `GETTYPE`/`GETFD`, `ebadf` for `NAME`, `enotconn` for `PEER`), `getstat_reply`'s `BadArg` outside 1-10, the interface family (`fdopen_precheck`/`ifget_flags`/`getif*_reply`). Constants re-export at `crate::drivers::inet::*`; helpers stay `pub(super)`.
### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- **The record walk** — `set_options`/`get_options`/`set_options_tracked`, `Step { Done(usize), Refused }`, the code table (`INET_*`/`TCP_*`/`UDP_*`) and the store `SocketOptions` (the C descriptor's fields, incl. the `{active,N}` counter and the 9216-byte `{buffer,…}` default). Each code is offered to `opt_state` then `opt_sys`; an unclaimed one is the C's `default` ⇒ the **whole** reply `[0]einval`, and a `setopts` refused that way still applies the records already passed.
- **`OptScope { stype, family, protocol }`** — the cached descriptor state every gate reads (`0` = unset), so no gate re-derives the socket type; `mod.rs`/`udp.rs` hand `OptScope::new(stype, family, IPPROTO_TCP|IPPROTO_UDP)` to the drivers' setopts (`setopts_with_effects`/`setopts_with_delivery`) and `getopts` sites.
- **Wire forms**: five-byte `[opt, val_be32]` records walked `while (len >= 5)`; `getopts` takes one-byte codes (`while (len--)`, an empty payload answering a bare `[1]`) and answers `[1] ++ [opt, val_be32]*` in request order — variable-length codes (`{active,N}`, `linger`, `netns`, `raw`, `bind_to_device`, multicast, `pktoptions`) carrying extra bytes both ways.
- **The two families**: `opt_state.rs` (descriptor fields + `stype`/protocol gates, the two watermark pairs clamped both ways per the busy-msgq rule) and `opt_sys.rs` (every `SO_*` code with local Linux uapi constants, the **nine `propagate = 1`** codes — `priority`/`tos`/`ipv6_v6only`/`tclass`/`bind_to_device`/`recvtos`/`recvtclass`/`ttl`/`recvttl`, a failed `setsockopt` there being the whole reply — and the non-`int` shapes). Every value is stored/reported only; acting on `{packet,…}`/`{mode,…}` is the read path's and the runtime's.
- **The three C misses are preserved, each observable**: a failed `getsockopt` is `TRUNCATE_TO(0, ptr)` — that record only, later codes still tried; a platform-less option answers a literal `0`; a code with no `case` (the get side of the set-only `line_delim` and membership pair) is `default: RETURN_ERROR()` ⇒ the whole reply `[0]einval`. Per-code gates and oracle-pinned rows: the family modules' rustdoc + their suites.
### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant **is** the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`. **Unsupported**: `Http`/`HttpH`/`HttpBin`/`HttpHBin`/`SslTls` — their bodies need the C's term-building `PacketCallbacks`.
- `PacketLength { Complete(usize), NeedMore, Invalid, Unsupported }` — the C's `packet_get_length` `> 0`/`0`/`< 0` plus an explicit "not implemented"; `is_complete()`/`complete()`/`as_error()` (`Invalid`⇒`badarg`, `Unsupported`⇒`notsup`). `Complete(len)` is the **total** length including the header, known once the header suffices.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — `packet_get_length`'s four arguments; `Default` = `{packet, raw}`, delimiter `\n` (`DEFAULT_DELIMITER`), no limits; builders `new`/`with_delimiter`/`with_max_plen`/`with_trunc_len`; `decode(&[u8]) -> PacketLength`. `max_plen == 0` is "no limit" (`INT_MAX - hlen`), bounding the **payload**, never the total frame.
- `PacketType::payload_range(&[u8]) -> Result<Range<usize>>` — the `packet_get_body` strip: removed for `Len1`/`Len2`/`Len4`, the FCGI padding subtracted for `Fcgi`; every other type (incl. `LineLf`) **as is**, so a `{packet, line}` payload keeps its delimiter (the oracle's `gen_tcp:recv`). **Three reproduced quirks**: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter, both strictly after; `Raw` on an empty buffer is `NeedMore`, not `Complete(0)`.
### `frame.rs` (private) — the framing glue (read + send)
Bridges the driver's `SocketOptions` to the pure decoder on both paths (the C's `tcp_remain`/`tcp_reply_data`/`tcp_send`); all `pub(super)`:
`options(&SocketOptions) -> PacketOptions` (`trunc_len` 0 — it accumulates into a growable `Vec`); `framed(&SocketOptions) -> Option<PacketType>` (`None` only for `Raw` and an out-of-range code); `write_header(&SocketOptions, len) -> Option<Vec<u8>>` (the `send` verb's 1-/2-/4-byte big-endian header under `{packet,1|2|4}`, `None` otherwise); `extract(&mut Vec<u8>, &PacketOptions) -> Result<Option<Vec<u8>>>` — **exactly one** frame's payload per call, `Ok(None)` while more bytes are needed (buffer untouched), `Err(badarg)` for `Invalid`/`Err(notsup)` for `Unsupported`.
### `sys.rs` (private) — the raw socket syscalls
- **Every `unsafe` block of the drivers lives here** (each with a `// SAFETY:` rationale): the socket/bind/listen/accept/connect/getsockopt/setsockopt/read/send/shutdown/close wrappers, the int-option pair, `socket_family` (the `FDOPEN` pre-check probe) and `local_address(fd)`/`peer_address(fd)` — one `getsockname(2)`/`getpeername(2)` into a `sockaddr_storage` decoded by a private `decode_inet_address` (**`AF_INET` only**; any other family is the C's failure ⇒ `INET_REQ_NAME`/`INET_REQ_PEER` answer their errno reply).
- The option-facing helpers: the `int` pair, `get_socket_linger`/`set_socket_linger`, `get_socket_bytes`/`set_socket_bytes` (`SO_BINDTODEVICE` and the `raw` form); the datagram family (`sendto(2)` unconnected, `send(2)` connected, one `recvfrom(2)` returning the payload length with the source `InetAddr`) over the shared `has_peer`/`local_port`/`close_fd`; the interface/name-service floors behind `wire`'s reply builders.
- `wait_connected(fd, timeout_ms) -> Result<Option<i32>>` — the synchronous-completion primitive behind `INET_REQ_CONNECT`: one `poll(2)` for `POLLOUT` (deadline recomputed from an `Instant`, so a retry cannot extend the budget; `EINTR` retried) then `getsockopt(SO_ERROR)` ⇒ `Some(0)` established, `Some(errno)` failed, `None` expired.
## Constraints
- Errors are `beam_common::{Result, BeamError}` only: operational socket failure ⇒ the `[0]`-tagged reply; malformed argument / unknown named verb ⇒ `BeamError::BadArg`; I/O syscall failure ⇒ `BeamError::Io`; undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- **One `Driver` is one port**: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port), only the named verb transfers the port.
- Safe Rust except `sys.rs`; `unsafe_op_in_unsafe_fn` stays clean; the `Driver`/`DriverContext` seam is frozen.
- Files target ~1000 lines; a grown source half splits its suite into a sibling test module (*Known Issues*).

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
The completion channel's runtime contract (rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted`, draining the registry) is the crate doc's *Handoffs*; only the driver-family seams are here. Each needs a change **outside** `src/drivers/inet/`.
- **(a) `{active, N|true|once}` delivery — the drivers PRODUCE, the runtime must RENDER.** Channel, arming gate, burst bound, active/once/N matrix and TCP-only inline burst are served here (main body › *Active-mode input delivery*). Owed above: `beam_rt` must drain `PortRegistry::take_active_inputs()` after every round **and after every close**, split a datagram's 7 packed header bytes into `{IP, Port}` (`<<1,137,18,127,0,0,1>>` ⇒ `{{127,0,0,1},35090}`), and render `{udp, S, IP, Port, Data}`/`{tcp, S, Data}` — flat list under `[list]`, `[H1..Hsz | <<Body>>]` (or the bare binary when `Hsz == 0`) under `[binary]` — plus `{udp_passive,S}`/`{tcp_passive,S}` for a `Passive` event, the atom from the driving port's driver name (the event carries none). **Do not add a variant to `PortNotification`** (two arms, no wildcard).
  **Still unserved here:** `{deliver, port|term}` — it routes the **raw** bytes through `{Port,{data,…}}` instead of the active channel: on a datagram socket the 7-byte packed address ++ payload (`<<1,137,18,127,0,0,1,100,112>>`, port word big-endian, address bytes network order — the prefix a `PACKET_REQ_RECV` `ReadMessage.header` carries), on a TCP socket the payload alone (a flat list even in `[binary]`, so the option also overrides the mode). Stored and reported; the read path treats it as neither active nor a passive queue fill, so nothing is delivered.
- **(b) `send_timeout` / `send_timeout_close`.** Both stored and reported, not acted on: the answer would be an **asynchronous** `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`). Needs a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port has one `TIMEOUT` task, already armed by the receive/accept operations); the `{inet_reply, …}` tag path exists (`CompletionEvent::InetReply`).
- **(c) `controlling_process`.** Not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` + an Erlang-side drain of buffered messages; there is no `INET_REQ_*` and no owner notion on the `Driver` seam. Needs `beam_process::PortTable::set_owner` (exists, unused) + `beam_rt`'s `PortMeta.owner`.
- **(d) The remaining refusal-only / unmodelled arms** — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, `udp_inet`'s ancillary data — each refused honestly today; the missing seam for each is under *Known Issues*.
## Known Issues
- **A completion goes to the port's owner, not the C's `driver_caller`**: operands are validated as the C does and the reply-then-completion split matches, but the *message* stays unobservable until `beam_rt` renders and delivers it (*Handoffs*).
- **Caller-reference stripping is by shape, not by caller** — the C keys on `driver_caller(port)` being an internal pid, which the frozen seam lacks, so `write_command` decides from the bytes: a `[n:be16][n bytes]` prefix with `n` non-zero, fitting and `arg[2] == 131` is a caller reference, stripped **once per command**, echoed verbatim. Residuals: a *plain* TCP payload of that shape loses its head (unreachable from `prim_inet:send/3`, which always prefixes); a *prefixed* UDP command with a tag **≥ 256** bytes begins with a 1/3/4 byte, so the plain `[address][payload]` grammar wins.
- **The TCP `port_command` write path does not count statistics (UDP's does).** `TcpInetDriver::output` has no per-command byte boundary (`ByteQueue` is a byte stream), so those bytes are uncounted where the C's `inet_output_count` sees every `tcp_inet_command`; only a `Driver`-seam boundary closes it. `InetStat` is otherwise fed from the `send`/`recv` verbs, the framed read path and the active deliveries (`udp_inet::write_pending` from the queued payload).
- **`SUBSCRIBE`(24)'s reply is exact, its *notification* is not.** `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte, but the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send — **none is ever sent**. A caller waiting only for the reply (`prim_inet:close/1`'s `subscribe(S, [subs_empty_out_q])`) sees the C exactly; one waiting for the message sees nothing.
- **Framing divergences recorded in code**: an out-of-range `{packet,N}` code is **no framing** where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`).
- **The `11` `multicast_if` read-back is uninitialised memory in the C** (`inet_fill_opts`, `:9494`-`:9520`: nine reply bytes reserved, the length advanced by five), so only tag/code/family/length are pinned; this floor answers the deterministic `[opt][0,0,0,0][INET_AF_INET]`.
- **The watermark, `netns`, `delay_send` and send-timeout options are stored and reported only.** `{high,low}_msgq_watermark` (`36`/`37`) have no busy-msgq limit on the frozen `Driver`/`Port` seam, `{netns,…}` (`38`) no `setns(2)` in `beam_io`, and `{delay_send,…}` (`31`), `{high,low}_watermark` (`27`/`28`), `{send_timeout,…}`/`{send_timeout_close,…}` (`30`/`35`) are `beam_rt`/`beam_abi` timer/flow-control work (*Handoffs* (b)).
- **A short `14`/`15` multicast-membership payload answers `[0]einval`** where the C reads past the request; a `{active,N}` record truncated before its trailing counter is the crate's `BadArg` (the C reads past it too).
- **The shared option harness needs a `|` in the oracle dump**: `opt_oracle::parse_reply_dump` finds the `a,b|d,e` line, so a one-request sequence has no comparable dump — the syscall suite pairs it with a neighbour. The separator is safe there: those fields are decimal byte lists, so no reply byte can be mistaken for it.
- **The `INET_REQ_FDOPEN` `bound == 0` form refuses by errno where the C adopts blind.** With the ten-byte form and a zero `bound` word the C skips every probe (its `SET_NONBLOCKING` failure discarded) and answers `[1]`, failing at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe (`fdopen_errno_tests.rs`).
- **File sizes (`wc -l`).** Over the ~1000-line target: `mod.rs` 1957, `udp/udp_tests.rs` 1625, `udp.rs` 1517, `wire.rs` 1192, `opt_sys_tests.rs` 1056, `udp/active_tests.rs` 993, `async_tests.rs` 972, `async.rs` 957, `opt_state_tests.rs` 897, `active_tests.rs` 757, `active.rs` 417, `udp/active.rs` 324; the rest sit at or just under it. A grown source half splits its test module into a sibling file (`opcode_tests*.rs`, `opt_oracle.rs` + the four option suites, `stat_tests.rs`, `udp/udp_tests.rs` → `udp/oracle_dump_tests.rs`, `udp/async*.rs`, `active*.rs`/`udp/active*.rs`).
