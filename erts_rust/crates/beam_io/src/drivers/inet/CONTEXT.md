# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` driver + its `udp_inet` sibling

## Intent
`mod.rs` is the built-in `tcp_inet` driver: one non-blocking TCP socket behind one port — `inet_drv.c`'s `tcp_inet`, under `gen_tcp`/`inet_tcp`.
Its datagram sibling `udp_inet` (`udp.rs` + `udp/`) is its own child node — `udp/CONTEXT.md`.
The two **share every layer here** — the wire vocabulary (`wire.rs`), the option wire (`opt*.rs`), the opcode bridge (`opcode.rs`), framing (`packet.rs`/`frame.rs`), statistics (`stat.rs`), the syscall floor (`sys.rs`) and the async-op queue (`async.rs`) — so a shared-layer change moves both.
Frozen names `DRIVER_NAME = "tcp_inet"` / `UDP_DRIVER_NAME = "udp_inet"` (`port_info(Port, name)`), registered by `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, `from_socket(fd)` (owned), or `adopt_prebound(ctx, fd, stype)` (`Fdopen`(13) — borrowed: port-lifetime, never closed here); the descriptor a numeric `accept`(26) completion hands over (`Accepted`) belongs to that completion's consumer.

## API Surface (FROZEN)
### `opcode.rs` — the numeric control-opcode bridge
`erlang:port_control(Port, Op, Data)` carries an integer, `beam_rt` forwards its decimal string, and `PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`, so both drivers decode it here before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a decimal command (`-` allowed, digits accumulated mod-2³², the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; non-decimal ⇒ `None`, so every named verb keeps its path byte-for-byte; unmatched ⇒ `Opcode::Unknown`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches: one numberspace, each number a `case` of exactly one, so a number owned by *the other* driver's switch is owned by neither (measured: `PacketRecv`(60) on a `tcp_inet` port, `TcpRecv`(42) on a `udp_inet` one). The wrap is observable in the same way: an `Op` below the magic matches no `case`.
- `Opcode` — one variant per roster row (same names, numbers) plus `Unknown`, with `ALL`(33)/`code`/`from_code`/`scope`/`name` and `not_served() -> BeamError`, the typed `unsupported` naming opcode **and** the owning switch, so both drivers report their gaps through one function.
### The control vocabulary — one numberspace, two switches
`op` = `code + 0x03f1_a300`. A decimal command decodes to an opcode, anything else is the **named verb** of the same row, and both run **one body**, so the numeric and named routes answer identical bytes.
`s` = served (whole arm); `ref` = only the C's refusals reproduced, success path `Err(Opcode::not_served())`; `✗` = `[0]exbadport` (no such `case` in that switch); an error name is the `[0]`-tagged reply (`einval` = `[0]einval`).
**This roster is the index, not the grammar** — per-row operand⇒reply grammar, guards and refusal ladders live in rustdoc: `mod.rs`'s module-doc verb table (`verb | C request | argument | reply`) for the named forms, one `wire::*_reply` builder per numeric opcode.

Any number no row owns (`Unknown`, a sub-magic `Op` — `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`, never `Open` — a `case` of *the other* switch, `Listen`(27) on the datagram driver since SCTP is compiled out) ⇒ the C's `default:` `[0]exbadport` on both; only the per-driver switches, the `Fdopen` type guard and `Sendfile` differ, every shared `inet_ctl` arm being symmetric.
**Pins a caller depends on.** `Open`(1) decodes `[AF, TYPE, PROTO]` **before** the state guard, so a non-`Closed` port is `exbadseq` (bad protocol ⇒ `eprotonosupport`, family ≠ `INET_AF_INET` ⇒ `eafnosupport`, wrong type ⇒ `einval`) · `Getstat`(11) has **no** open guard (a socket-less port answers the all-zero 59-byte block, `send_pend` = `ctx.output().len()`; an op outside 1-10 is the C's `return -1` ⇒ typed `badarg`) · `Getstatus`(16) is `be32(state_code())` (Closed 0, Open 1, Connected 5, Listening 9, Connecting 17) + `accept_state_bits()` (sticky `INET_F_ACC` 0x20 / `INET_F_MULTI_CLIENT` 0x100), pinned `9` / `41` / `297` · the async arms (`Accept`, `TcpRecv`, `PacketRecv`) answer `[1] ++ <<Id:16/big>>` — the id is the *whole* synchronous answer — and a **refused** enqueue still consumes one (`INET_MAX_ASYNC = 1` ⇒ a second concurrent receive `[0]ealready`; the accept list never refuses) · `TcpRecv`'s connection guard runs **first** (incl. the one-shot `closed`/`econnreset`), then `active || len != 8` ⇒ `einval`, `> TCP_MAX_PACKET_SIZE` (`0x0400_0000`) ⇒ `enomem` · `Accept` guards `!is_listening || len != 4` ⇒ `einval` in every non-listening state (never `exbadport`), `{active,…}` does not gate it, and the named `accept` is synchronous and transfers the port.
The `ref` rows' ladders and `Fdopen`/`Gettype`/`Name`/`Peer`/`Setname`'s are those builders' rustdoc plus `opcode_tests_refusals.rs`; `fdopen`'s adoption non-mirrors are *Known Issues*.
Three `erl` matrices byte-compare every row — `opcode_tests.rs::oracle_matrix` (TCP, 80 calls), `opcode_tests_udp.rs::oracle_matrix` (UDP, 89), `opcode_tests_states.rs` (11 rows) — over the bare/opened/listening-or-bound/connected/post-close states in one `erl` run.
#### Packed address
`bind`/`connect`/datagram source: `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag ⇒ `BadArg` (DNS/IPv6 out of scope); the layout (`inet_get_address`'s) is `wire.rs`'s codec rustdoc.
### `mod.rs` — the TCP driver
`TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket; `new()` (socket-less registry factory — the `open` verb creates the socket), `from_socket(fd)` (adopts + probes: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound`.
`InetState` (`Closed`/`Open`/`Listening`/`Connecting`/`Connected`, the C's `INET_STATE_*`) with its `eof`/`peer_closed`/`connect_error` latches is the descriptor, as are the fake endpoints (`name_addr`/`peer_addr`: set/cleared by `Setname`/`Setpeer`, reported by `Name`/`Peer`, ignored by `Getladdrs`/`Getpaddrs`, cleared only by `len == 0`, left by a `close`); `prebound` is set only by `adopt_prebound`, cleared by `adopt`, honoured by `close_socket`'s early return — an owned descriptor closes on `stop`, the `close` verb and `Drop`, a prebound one only deregisters.
- `DriverFlags::SOFT_BUSY` (the C's `ERL_DRV_FLAG_SOFT_BUSY`) ⇒ `erlang:port_command(P, D, [force])` is `PortCommandOutcome::Done`, the oracle's `true` (`soft_busy_tests.rs`); a flag-less driver (`udp_inet`, `ram_file_drv`) ⇒ `notsup`.
- `connect` settles synchronously under a bounded wait: `EINPROGRESS` resolves in-call through `sys::wait_connected` — `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`, `Some(errno)` ⇒ `[0]++<lowercase errno>` kept in `connect_error`, `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout`; budget `CONNECT_WAIT_CAP_MS = 30_000` (negative ⇒ cap, `0` ⇒ one poll), so `EINPROGRESS` never yields the C's `[1]++async_id_be16` (a divergence `prim_inet:connect_cmd/3` masks as `{ok,[]}` ⇒ `ok`).
- Readiness and flow control: `EPOLLET` ⇒ every callback drains to `EAGAIN`; one descriptor ⇒ one registration with a flipped `Interest` mask — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and arms write readiness) or an over-budget `connect` is in flight, dropped when the queue drains; output left at a latched peer close is dropped (`tcp_clear_output`); writes use `send(2)` + `MSG_NOSIGNAL`.
- Accept readiness IS the listener's read readiness (`FD_ACCEPT` is `ERL_DRV_READ`): `verb_open` registers it, `verb_listen` arms nothing, `async_accept` re-arms per enqueue, `disarm_accepts` deregisters once the list empties — only while `is_listening()`; a ghost `EAGAIN` stays armed and `drive_async_ops` still makes one non-blocking `accept(2)` attempt.
- A command on a socket-less or unconnected port is consumed and answered out of band: `init_caller` runs first, **size-only** — malformed ⇒ `DriverFailure::posix(EINVAL)` and `PortRegistry::reap_failures` closes the port after the round (`port_command/2` still `true`, later commands `badarg`); a well-formed prefix that cannot write stages `Error(ENOTCONN)` / `Error(EINVAL)` (socket-less `udp_inet`) with the port alive; an empty or non-ETF tag stages no reply.
- One socket, one port, and no completion inside a control call: the C's `INET_REQ_ACCEPT` creates a second Erlang port, which this seam cannot, so the numeric request reports the descriptor inside its completion (`Accepted { fd }`, never stored, so no teardown closes it) and the runtime opens the second port (*Handoffs* (0)) — only the named `accept` transfers this port, and N queued accepts answer their own id in enqueue order. Completions are produced only by `ready_input`, the port timer and the round's `drive_async` (which also serves data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` first.
- `pending_input` (the C's `desc->i_buf`) holds bytes read but not yet a whole frame, under a framing `{packet, N}` only, cleared when the socket is replaced/closed; a `{packet,…}`/`{line_delim,…}` change with bytes buffered is not flushed, so the next `recv` re-decodes them under the new options (a switch to `raw` delivers the retained buffer verbatim).
### The read path — a complete buffered unit wins over a pending peer close
`read_bytes` takes no `DriverContext` and **never latches**: a `read(2)` of `0` or a reset sets `read_eof`, records `CloseSource::Read { error }` in `pending_close` (`observe_read_close`; `error` `None` for `ECONNRESET` without `{show_econnreset,true}`) and answers only `Result<()>` — whether it is *applied* is the caller's `ReadReport`.
Latching is the caller's act: `latch_peer_close(ctx, source)` is the **single** site running the whole ladder (the active `Error` event first when `options.active > INET_PASSIVE`, `peer_close.observe`, `pending_shutdown = None`, `drain_error_all`, `ctx.output().clear()`, `deregister`, `tears_down_on_close` ⇒ `close_descriptor`).
`read_available` latches **before** queueing the bytes it just read when the read is one the C would have made (`ReadReport::Answered`), so a passive `{Port, {data, …}}` precedes the `{tcp_closed, …}` the same callback produces and a `{packet, N}` frame completed by that call survives the teardown's `tcp_clear_input` (the C clears and only then delivers); `active.rs`'s `deliver_framed`/`deliver_raw` latch right after their own `read_bytes`.
`try_complete_recv` (`async.rs`) instead leaves the observation in place: it delivers a complete buffered unit first and only when nothing complete is left calls the private `latch_pending(ctx)`, so a queued `TcpRecv`(42) answers `{ok, Data}` rather than `{error, closed}` and the close stays owed to the operations after it; a receive finding `pending_close` already set latches before reading, an empty read latches and breaks.
`pending_close` is reset at each of the three `pending_input.clear()` sites — `adopt`, `adopt_prebound`, `mark_connected` — because a replaced socket's observation belongs to the old descriptor.
**`ReadReport` is the selection test.** The C selects a socket's read side in exactly two states — a granted `{active, …}` and a waiting `TcpRecv` — so every read it makes is one somebody answers: `ReadReport::Answered` (a queued `TcpRecv`, the `recv` verb, an `{active, …}` delivery) **applies** the close it finds. This floor's edge-triggered poller also reads a passive socket with no receive queued — the passive `{Port, {data, …}}` shortcut — which the C never does, so that read is `ReadReport::Unselected`: it delivers the bytes and only **records** the observation in `pending_close`, applying **nothing** (no `delayed_close_*`, no teardown).
**The rule:** `tcp_recv`'s delivery points run first — only a **later** call's `n == 0` reaches `tcp_recv_closed` — and the enqueue side agrees (the read precedes `driver_select`).
### The close path on this driver — `flush`, `linger_zero` and `stop`
`TcpInetDriver::flush` is the C's `tcp_inet_flush`: `discard_output = !(token.is_some() && interest.is_writable()) || options.linger_zero`, and only then does it clear `ctx.output()` (`tcp_clear_output`) — otherwise the bytes stay queued and the port parks in `PortState::Closing` for its own drain.
`interest.is_writable()` is the C's `event_mask & FD_WRITE` half; `token.is_some()` models `erl_inet_close`, which zeroes the event mask where this floor deregisters instead, so a closed or peer-closed descriptor counts as unarmed.
`SocketOptions::linger_zero` is the C's `TCP_ADDF_LINGER_ZERO`: `opt_sys.rs` latches `value != 0 && linger == 0` **before** the `setsockopt` under `scope.is_tcp_protocol()` (`propagate = 0`), so a descriptor whose syscall cannot run latches it too; `inherited_from` copies it and no option reply reports it.
`TcpInetDriver::stop` calls `release_socket(ctx)`, never `desc_close(ctx)`: `tcp_inet_stop` is `tcp_close_check` + `tcp_clear_input` + `inet_stop` and **never touches the `ioq`**, while `desc_close`'s unconditional `tcp_clear_output` belongs only to the close **verb**. A forced close (a latched driver failure) drops the remainder with the port's own `stopq`.
### `udp_inet` — the datagram sibling (detail: `udp/CONTEXT.md`)
`udp_inet` is the same port/driver seam over one `AF_INET`/`SOCK_DGRAM` socket, built from the same shared layers; its whole surface lives in `udp/CONTEXT.md` (verbs, socket options, the `PACKET_REQ_RECV`(60) async bodies, the `{active,…}` deliveries, the suites).
What a reader of *this* file must know: **no write-side framing** (neither the `send` verb nor a queued `port_command` prepends a `{packet,N}` header); **no `{header,N}`** (a datagram's `ReadMessage.header` is spent on the 7 packed source-address bytes — *Handoffs* (a0)); **no `flush` override** (its C entry's slot is NULL, so queued output is always written by the port layer's `Closing` drain); **no `{udp_closed, S}`** (a peerless failure is a `{udp_error, S, Reason}` on the `{active,…}` channel, and an `{error, Reason}` completion for a parked receive); an **empty datagram is a delivery** (`body: Some(vec![])`, never `None`) on every channel.
## Accepted-socket option inheritance — `tcp_inet_copy` (`from_accepted` / `SocketOptions::inherited_from`)
The C's `tcp_inet_copy` copies a fixed field set from the listener's descriptor onto the freshly-started accepted one; here the runtime opens the second port, so this crate owns the copy, as an additive inherent API (no `Driver`/`DriverContext` change).
- `TcpInetDriver::from_accepted(fd: RawFd, listener: &TcpInetDriver) -> Result<TcpInetDriver>` — adopts `fd` (owned, exactly like `from_socket`), then applies the listener's inherited options plus the cached `stype`/`family`; the only copy path, because `adopt_prebound` copies nothing.
- `SocketOptions::inherited_from` (`pub(super)`, `opt.rs`) is that mapping in ONE place, pure and unit-tested, naming every field explicitly (no `..*self`) so a new field forces a decision — that explicit field list **is** the exact inherited set, pinned by `inherit_tests.rs`.
- **Surprising negatives:** `active`/`active_count` are **not** inherited — `inet_start` zeroes them, so an `{active,true}` listener's accepted socket is **passive**; `debug`, `netns`, `read_packets`, `line_delim`, `delay_send` and `buffer_set` are not inherited either; **kernel** socket options are inherited by the kernel across `accept(2)`, not by this copy; `prim_inet:accept_opts/3` re-applies a **different** Erlang-side set (`{active,…}`, `nodelay`, `keepalive`, `delay_send`, `priority`, `linger`, `reuseaddr`), so a code missing from `tcp_inet_copy` still arrives — only because Erlang re-sends it (`accept_opts_tests.rs`/`accept_opts_family_tests.rs`).
- The registry route: `PortRegistry::driver_as::<TcpInetDriver>(listener)` hands out the listener's own driver through `Box<dyn Driver>` (the `Driver: Any` + `downcast_ref` seam), so `from_accepted(fd, listener)` is reachable from a port; the obligation stays with the runtime — `PortRegistry::open` over `from_accepted`, never over `from_socket`, which inherits nothing.
### The `{active, …}` state seam (`Driver::active_mode` / `take_active_spends`)
Both drivers answer `ActiveMode::from_parts(self.options.active, self.options.active_count)` (the C's `desc->inet.active`/`active_count`), so the **running** `{active, N}` counter is readable and a runtime need not mirror the `setopts` walk it sent; `from_parts` is the single place the `INET_PASSIVE`/`ACTIVE`/`ONCE`/`MULTI` = `0`/`1`/`2`/`3` encoding lives, and the mode is written by `opt_state::set_active` and by nothing but a delivery's spend.
`take_active_spends` drains a per-driver `active_spends` vector (oldest first, consumed on take) recorded at **exactly one site per driver** — the per-delivery spend site: TCP `count_delivery` (`active.rs`), the datagram twin `UdpInetDriver::after_delivery` (`udp/active.rs`).
`INET_ONCE` records `ActiveSpend::Once` (a silent flip, no message at all); an `INET_MULTI` counter reaching `0` records `ActiveSpend::Multi` (whose `{tcp_passive,S}`/`{udp_passive,S}` already rides `ActiveInputEvent::Passive`); `INET_ACTIVE`/`INET_PASSIVE` never record, and the delivery loop ends at the flip so a burst spends at most one grant.
The `setopts` walk driving a counter to zero (`landed_at_zero`) **records nothing** — it emits its `Passive`, because the C spends a grant only per **delivered** packet. The private read-side predicate (`desc->active > 0`) is `is_active_mode`, **not** `active_mode`, because the `Driver` trait publishes that name and an inherent method would shadow it at every call site.
`active_seam_tests.rs` pins the four modes per driver, the `setopts`-to-zero distinction, the registry route over a factory-built `"tcp_inet"` port, and three `erl` rows phrased as data/passive counts.
### The asynchronous-operation queue — and why a passive receive PARKS (`async.rs` + `accept.rs`; datagram bodies are `udp/async.rs`)
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword).
- `AsyncQueue` — one receive slot (`INET_MAX_ASYNC = 1`) plus a multi-operation accept list (never `ealready`; `accept.rs`'s `AcceptQueue`); `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- The multi-accept bit is **sticky** (`AcceptQueue::multi`, the C's `INET_F_MULTI_CLIENT`): `enqueue` latches it when a second accept joins, `take`/`expire` clear it only when the list is left empty, `take_all` clears it with the teardown drain, and `state_bits` derives `GETSTATUS`'s `0` / `INET_F_ACC` / `INET_F_ACC|INET_F_MULTI_CLIENT` from it, never from list length.
- The accept timer is per port, its entries a separate sorted list (the C's `desc->mtd`, one `MultiTimerData` per *finite* deadline): inserted in sorted position, `next_deadline`/`timeout_due` read only the earliest, and `expire(now)` performs one `fire_multi_timers` iteration that consumes that entry, removes the accept list's head and answers the head's id. Because the firing does not remove the *head's own* entry, a head owning a later deadline stays armed and later expires the next head (`[500, 50]` reports id 0 at ~51 ms and id 1 at ~501 ms — measured); only a successful completion cancels its own entry, through `take`.
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, from 0, taken **before** the capacity check so a *refused* enqueue still consumes an id; wraps at 65536. `deadline_for(timeout_ms)` — negative is `INET_INFINITY` (`None`), `0` "now", positive an `Instant`; the recv operand is `Timeout(4), Length(4)`; `async_ok_reply` builds `[1]++<<Id:16/big>>`; the teardown drain (`drain_closed`, from `stop`/`verb_close`/`latch_peer_close`) answers `{error, closed}` once per pending operation.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) sits beside the queue in each driver: one prefix per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.
**A passive receive is that queue, and it PARKS.** `gen_tcp:recv/2,3` issues no synchronous control request: `prim_inet:recv/2` is `recv0(S, Length, -1)`, which waits in `receive {inet_async, S, Ref, Status}` with **no `after`**, so the read is `TcpRecv`(42) on the single receive slot and `Ref` is the raw 16-bit op id the control reply carried. A would-block read is therefore a **park**: `try_complete_recv` makes no progress on `read_bytes`' `EAGAIN` arm and breaks out instead of raising. Completion is later and exactly once per op, from `async_ready_input` (through `Driver::ready_input`) or `drive_async_ops` (once per port round, which also serves data that arrived *before* the enqueue); expiry answers `Error(InetReason::Timeout)` after one last `try_complete_recv`, so arrived data wins over the deadline; a close or peer close while parked answers `{error, closed}` exactly once, after which a further receive is `[0]enotconn`.
`shutdown/2` is the plain `TcpShutdown`(44) control op: `read`/`write`/`read_write` ⇒ `TCP_SHUT_RD`/`WR`/`RDWR` = `0`/`1`/`2`, the bare `[1]` reply `ctl_cmd` maps to `{ok,[]}`, and the guards `!IS_CONNECTED ⇒ enotconn` **before** `len != 1 ⇒ einval`. `TCP_ADDF_SHUTDOWN_WR_DONE` is set only by the **failed** direct write-side `shutdown(2)` and by the **deferred** drain `tcp_shutdown_async`'s success — a **successful direct** `shutdown(write)` leaves it clear — and `tcp_send_or_shutdown_error` consumes it (`EPIPE` with it clear ⇒ `ECONNRESET`) before picking `econnreset` vs `closed` under `{show_econnreset,…}`: a direct successful shutdown's later `EPIPE` is `{error,econnreset}` under that option, a deferred shutdown's same write `{error,closed}` whatever the option says.
### Active-mode input delivery (the TCP half: `active.rs`)
Each arriving input goes to the owner on the crate's `{active,…}` channel (`ActiveInputEvent::{Data,Passive,Error}`, `deliver_active_input`, `take_active_inputs`), never `{Port,{data,…}}`/`CompletionEvent`; the C splits the same way (`erl_drv_output_term` → `desc->dport`, `erl_drv_send_term` → the caller).
- Shape — one `ReadMessage` per unit: a stream's `header` is the `{header,N}` option only (`desc->hsz`), `body` the rest of one frame (framing header stripped by `frame::extract`); `header::split_payload` is the `hsz` half of `(mode == INET_MODE_LIST) || (hsz > len)` (narrow header + binary tail, `hsz == len` header + empty tail, `hsz > len` all-header), the `mode` half the runtime's.
- The third event is a read error — `Error(InetReason)`, the term-free `{tcp_error,S,Reason}`, from a reset under `{show_econnreset,true}` only — and it precedes the close it accompanies, so `{tcp_closed,S}` is the `port_closed()` latch the same callback sets, never a second event; passive mode reports the reason as an `{error,Reason}` completion. The atom is `InetReason::atom_name()`, rendered (like `Passive`) from the driving port's driver name.
- One unit at a time; the loop stops the moment the mode flips: one `{packet,N}` frame per message (the remainder stays in `pending_input`), one message per read burst in `{packet,raw}`, the burst bounded by `{read_packets}` (default `INET_PACKET_POLL = 5`).
- The matrix (`INET_CHECK_ACTIVE_TO_PASSIVE`): `{active,true}` never changes; `{active,once}` flips silently (bytes stay in the kernel until the next arm or a passive read); `{active,N}` decrements and on 0 flips and stages one `Passive` — so `Passive` has exactly two sources, the credit-spending delivery and the `setopts` walk, and `{active,true}`/`{active,false}` never emit one. `{active,N}` is `INET_MULTI` (3) + a trailing big-endian counter: `opt_state::set_active` accumulates it (past `Sint16` ⇒ `einval` after the mode is already set, no rollback), clamps a negative sum to 0 and turns a 0 sum into `INET_PASSIVE`; `set_options_tracked` reports `landed_at_zero` and `after_setopts` turns it into the delivery.
- Arming is a driver-side state gate, not a poller mask: the C selects the read side on `active > 0`, deselects when a delivery spends the grant and re-selects for a queued async recv (only when `timeout != 0`). `TcpInetDriver::read_armed` mirrors it while the registration lives on (`poller::Interest` has no empty mask; `mio` epoll is edge-triggered) — cleared by the spending delivery, set by an armed grant (an `epoll_ctl(MOD)` re-arm, never a re-register), a queued `TcpRecv`, the synchronous `recv` verbs and every fresh connection; while clear `async_ready_input` reads nothing, so the peer's bytes wait in the kernel instead of landing on the passive `{Port,{data,…}}` channel, and a never-armed port keeps its eager `read_armed = true` read into the port queue.
- Readiness dispatches on state, exactly once: `ready_input` is accept dispatch, else `tcp_recv(desc,0)` (never touching `hsz`), so a connected + active socket with no queued `TcpRecv` goes to `active_delivery` only, while the accept ladder, a queued receive and a passive connection's bytes-into-the-port-queue stay with `async_ready_input` (**running both is a defect** — `read_available` would starve the active path). The inline burst is `SOCK_STREAM` + `{active,once}`/`{active,N}` + an unchanged `{packet,…}` only (`inet_set_opts`'s `trigger_recv` tail ⇒ an inline `tcp_recv` + re-arm); `{active,true}` ⇒ arm only, and a UDP re-arm always waits for the next readiness event. `{deliver,port}` divergence: *Handoffs* (a).
### `wire.rs`, `opt.rs`, `packet.rs`, `frame.rs` — the shared protocol layers (private except `packet.rs`)
These four own a shared wire detail each; their rustdoc carries the per-code/per-type grammar, and only the cross-cutting facts live here.
- **`wire.rs`** — the wire vocabulary and reply shape: the constants (result/address tags, socket types, protocols, `TCP_SHUT_*`, `INET_IFOPT_*`/`INET_IFF_*`), the packed-address codec, `FakeAddress`, the datagram operand (`split_datagram`), the caller-reference strip (`ETF_VERSION_MAGIC = 131`, `split_caller_ref`) and the C's `ctl_reply` (one result-tag byte `INET_REP_OK` 1 / `INET_REP_ERROR` 0 + payload, the errno a lowercase `erl_errno_id` name or a fixed atom), plus **one `*_reply` builder per served opcode**. **The constants are duplicated by hand in `lib/kernel/src/inet_int.hrl` and nothing enforces the sync** — changing an opcode/option number means editing both.
- **`opt.rs`** (`Setopts`/`Getopts`) — `SocketOptions` is the store (the C descriptor's fields, incl. the `{active,N}` counter, `linger_zero`, the 9216-byte `{buffer,…}` default); each code is offered to `opt_state` then `opt_sys`, and an unclaimed one is the C's `default` ⇒ the whole reply `[0]einval` (a `setopts` refused that way still applies the records already passed). `OptScope { stype, family, protocol }` is the cached state every gate reads (`0` = unset). Records are five-byte `[opt, val_be32]`, `getopts` takes one-byte codes and answers `[1]++[opt, val_be32]*` in request order. **Three C misses preserved:** a failed `getsockopt` truncates that record only; a platform-less option answers a literal `0`; a code with no `case` ⇒ `[0]einval`.
- **`packet.rs`** (`pub`) — the pure framing decoder. `PacketType`'s `u8` discriminant **is** the `{packet, N}` wire code (`code()`/`from_code()`); the ten `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt` types decode, `Http*`/`SslTls` are `Unsupported` (their bodies need the C's term-building `PacketCallbacks`) ⇒ `notsup`, and `Invalid` ⇒ `badarg`. `Complete(len)` includes the header; `max_plen == 0` is "no limit" and bounds the payload, never the frame; `payload_range` strips `Len1`/`Len2`/`Len4` and FCGI padding and leaves everything else — so **`{packet, line}` keeps its delimiter**. Three quirks: `Raw` ignores `max_plen`; line mode compares `max_plen` strictly but `trunc_len` inclusively before a delimiter; `Raw` on an empty buffer is `NeedMore`, not `Complete(0)`.
- **`frame.rs`** — the read/send bridge from `SocketOptions` to that decoder: `options` (`trunc_len` 0, since it grows a `Vec`), `framed` (`None` only for `Raw` and an out-of-range code), `write_header` (the `send` verb's 1-/2-/4-byte big-endian header), `extract` (one frame's payload per call, `Ok(None)` while more bytes are needed, buffer untouched). The C frames in `tcp_send`/`tcp_sendv`, announcing the payload **after** the caller-tag strip — once per command (the `out_framed` latch, cleared with `caller_stripped` when `write_pending` sees the queue drain), after the connection/pending-shutdown guard and never on the malformed arm; `stat.send_oct` counts payload **plus** header on both routes.
## The peer-close ladder — reset vs end-of-file, and who answers a discovery
`PeerClose` models the C's three independent flags — `TCP_ADDF_DELAYED_CLOSE_RECV`, `_SEND`, `TCP_ADDF_DELAYED_ECONNRESET` — plus the two reasons it owes, both `Option<InetReason>` with `None` meaning `closed`: `delayed_reason` (what a reply ladder answers) and `observed` (`observed_reason()`, what the **discovering** operation reports).
- The receive ladder clears both close one-shots and, when the reset bit is latched, reports `econnreset` and clears it; otherwise `closed`; with neither latched, `enotconn`. The send ladder clears **only** the send one-shot and leaves the reset bit armed for the next receive — a send never consumes the receive's `econnreset`.
- `econnreset` appears only when the observation was an `ECONNRESET` and `{show_econnreset,true}` was in effect; a clean end-of-file is always `closed`.
- Read-side discoveries, one caller-visible sequence. A `CloseSource::Read` observation is the same wherever it is made, and the reader that makes it is the party it is answered to (`ReadReport::Answered`): the `recv`/`verb_recv_framed` verbs answer inline from `observed_reason()`, a queued `TcpRecv`(42) is answered by `try_complete_recv`'s tail, an `{active, …}` delivery reports `{tcp_closed, S}`/`{tcp_error, S, Reason}`. A clean end-of-file arms the send one-shot, a read error arms nothing, and `delayed_reason` is armed only by the **write** path — so a read discovery never turns a later `closed` into `econnreset`.
- The reactor's eager passive read (`ReadReport::Unselected`, *The read path*) is **not** a discovery: a close it stumbles on is only recorded in `pending_close`, so the sequence above starts at the first read the C would have made — the user sees `closed`/`econnreset`/the errno once, then `enotconn`.
- Residual: an `{active, _}` socket with `{exit_on_close,true}` takes the C's `driver_exit(…, 0)` arm and kills the port, which this floor does not model — its teardown predicate is `false` whenever `options.active != 0`, so an active socket's peer close only latches and de-registers.
## Constraints
- Errors are `beam_common::{Result, BeamError}` only: operational socket failure ⇒ the `[0]`-tagged reply; malformed argument / unknown named verb ⇒ `BadArg`; I/O syscall failure ⇒ `Io`; undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- One `Driver` is one port: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port), only the named verb transfers the port.
- `unsafe` only in `sys.rs`; the `Driver`/`DriverContext` seam is frozen; a grown source half splits its suite into a sibling test module.
## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
Rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted` and the registry drains are the crate doc's *Handoffs*; only the driver-family seams are here.
- (0) The accept completion's second port is the runtime's, and the seam is available now (`driver_as` → `from_accepted`): `beam_rt` must open the second port with **that** constructor and render `{inet_async, Listener, Id, {ok, NewPort}}` (`prim_inet:accept0/3`'s shape); `Accepted { fd }` is adopted that way **or** closed by the runtime — this crate never closes it — and a refused `from_accepted` has no reply channel here, so the runtime answers `{inet_async, Listener, Id, {error, Reason}}` with the descriptor closed, never dropped.
- (a0) The datagram drivers do not apply `{header,N}` and cannot in the frozen shape: `ReadMessage` has one header slot and `udp_inet` spends it on the 7 packed source-address bytes `beam_rt` decodes as `{IP,Port}`, so a second `hsz`-sized header (which the C does apply) cannot be expressed; closing it needs a third component on the delivered read (`udp/CONTEXT.md`).
- (a) `{active, N|true|once}` delivery — channel, arming gate, burst bound and matrix are served here; the rendering contract (drain after every round *and* every `close`, the four message shapes, `Passive`/error atoms from the driving port's driver name) is the crate doc's *Handoffs*. Do not add a variant to `PortNotification` (two arms, no wildcard). Unserved here: `{deliver, port|term}` — stored and reported, nothing delivered.
- (b) `send_timeout`/`send_timeout_close` — stored and reported, not acted on: the answer is an asynchronous `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`), needing a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port's one `TIMEOUT` task is already armed by the receive/accept operations).
- (c) `controlling_process` — not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain; there is no `INET_REQ_*` and no owner notion on the `Driver` seam, so it needs `beam_process::PortTable::set_owner` + `beam_rt`'s `PortMeta.owner`.
- (d) The refusal-only/unmodelled arms — `Ignorefd`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `Subscribe`(24)'s notification half, `udp_inet`'s ancillary data — each refused honestly today; the missing seam for each is under *Known Issues*.
## Known Issues
- **`tools/differential`'s `src/corpus/inet_write.rs`, `divergences.md` §A.4 and `GAPS.md` still claim send-side counters stay zero and that a bare-integer payload is written by the oracle and dropped here; both are wrong** — `write_command`/`verb_send` count and `wire::getstat_reply` renders both (pinned by `write_frame_tests.rs`/`stat_tests.rs`), and a **top-level** integer payload is the oracle's `badarg` too (`port_command(P,42)`); only a list element is accepted (`prim_inet:send/3`'s `[<<Size:16,MrefBin/binary>>, Data]` wrap), a term conversion that is `beam_rt`'s because this crate is term-free. Correcting those corpus docs is their owner node's.
- Caller-reference stripping is by shape, not by caller (the C keys on `driver_caller(port)` being an internal pid, which the frozen seam lacks): a `[n:be16][n bytes]` prefix with `n` non-zero, fitting and `arg[2] == 131` is a caller reference, stripped once per command and echoed verbatim. Residuals: a *plain* TCP payload of that shape loses its head (unreachable from `prim_inet:send/3`, which always prefixes); a *prefixed* UDP command whose tag is ≥ 256 bytes begins with a 1/3/4 byte, so the plain `[address][payload]` grammar wins.
- The write-side framing and accounting are decided **once per command**, when it is queued — a **second** command queued behind a still-stalled partial write is not framed or counted independently, and the caller-tag strip inherits that property (both latches re-arm only when the queue drains). The C has the same single `ioq` and one-`tcp_sendv`-per-`port_command` shape; the residual is the missing per-command boundary, not a wrong count for the command that was framed.
- `Subscribe`(24)'s reply is exact, its notification is not: `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte, but the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send — none is ever sent.
- Framing/option divergences: an out-of-range `{packet,N}` code is no framing where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`); the `11` `multicast_if` read-back is uninitialised memory in the C, so only tag/code/family/length are pinned (this floor answers `[opt][0,0,0,0][INET_AF_INET]`); a short `14`/`15` multicast-membership payload answers `einval` where the C reads past the request; a `{active,N}` record truncated before its counter is `BadArg`. The watermark, `netns`, `delay_send` and send-timeout options are **stored and reported only** — no busy-msgq limit or `setns(2)` exists on the frozen seam, and their timer/flow-control halves are `beam_rt`/`beam_abi` work (*Handoffs* (b)).
- The `Fdopen`(13) `bound == 0` form refuses by errno where the C adopts blind: with the ten-byte form and a zero `bound` word the C skips every probe and answers `[1]`, failing at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe (`fdopen_errno_tests.rs`); a live socket is `einval` untouched where the C overwrites `desc->s`.
- Two `-eval` failure modes hide a probe's real cause: an abnormal exit loses the whole `erl` dump (the node dies with the group-leader buffer unflushed, so the failure surfaces only as `the oracle expression failed: ` with empty stderr), and a *hanging* probe reads as `SKIP: erl did not answer within 30s`, almost always a dead expression (a raw `INET_REQ_CONNECT`(3) refused `[0]"eafnosupport"` leaves the following `gen_tcp:accept` hanging). Every bounded wait therefore gives up through `io:format(standard_error, …)` + `erlang:halt(1)` and asserts every step that must have succeeded.
## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (the wrapper; `$HOME` is read-only).
- One mechanism: a real loopback socket through `PortRegistry` + `Poller`, the peer/injector outside the port (a datagram injector is `os:cmd("printf … > /dev/udp/127.0.0.1/P")`, never a second VM); waits pump `poller.poll` → `handle_events` → the relevant `take_*` drain until a condition holds under a 10–20 s hang guard, **never a fixed sleep**.
- The three suites pinning this node's load-bearing invariants are the read-ordering rule (`write_then_close_tests.rs`), the close path (`flush_tests.rs`, `close_tests.rs`) and the write-shutdown matrix (`write_shutdown_matrix_tests.rs`); every other suite's subject sits beside its file in the Routing Table, and `src/drivers/CONTEXT.md` records the subtree total (this node holds 603 of the crate's 1074 lib tests; the datagram files are the `udp` group's 79).
- **Read shapes.** A header-less read of a built-in driver port is a **runtime-policy** observation, not a driver defect: `tcp_inet`'s passive bytes stay in `pending_input` (unframed bytes never become a message here) and the inert legacy `driver_tbl` port the differential corpus creates never runs a read, so both sides agree. Every read carrying the C's `(hbuf, hlen, buf, len)` split does render it: one `ReadMessage { header, body }` per `driver_output*` call, reaching the owner as `PortNotification::Data`.
- Every `erl`/`cc` oracle case skips loudly (`SKIP:` banner + early `return`) without the tool or over its 30 s budget — never fails; comparisons are byte-exact except for an ephemeral port or fd.
