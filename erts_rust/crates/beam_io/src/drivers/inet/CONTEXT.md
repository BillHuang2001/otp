# `inet` driver subtree (`src/drivers/inet/`) — the built-in `tcp_inet` and `udp_inet` socket drivers

## Intent
The built-in `tcp_inet` driver (`mod.rs`): one non-blocking TCP socket behind one port — `inet_drv.c`'s `tcp_inet`, under `gen_tcp`/`inet_tcp`; its datagram half `udp_inet` (`udp.rs`), under `gen_udp`.
Frozen names `DRIVER_NAME = "tcp_inet"` / `UDP_DRIVER_NAME = "udp_inet"` (`port_info(Port, name)`), registered by `make_tcp_inet()`/`make_udp_inet()`.
A port's socket comes from the `open` verb, `from_socket(fd)` (owned), or `adopt_prebound(ctx, fd, stype)` (`INET_REQ_FDOPEN` — borrowed: port-lifetime, never closed here); the descriptor a numeric `accept`(26) completion hands over (`InetAsyncResult::Accepted`) belongs to that completion's consumer.

## API Surface (FROZEN)

### `opcode.rs` — the numeric control-opcode bridge
`erlang:port_control(Port, Op, Data)` carries an integer, `beam_rt` forwards its decimal string, and `PortRegistry::port_control` passes any non-`"close"` op verbatim to `Driver::control`, so both drivers decode it here before their named-verb match.
- `CONTROL_MAGIC_NUMBER: u32 = 0x03f1_a300` (`ERTS_INET_DRV_CONTROL_MAGIC_NUMBER`), subtracted at the top of `tcp_inet_ctl`/`packet_inet_ctl`.
- `decode(command: &str) -> Option<Opcode>` — `Some` only for a decimal command (optional `-`, ASCII digits accumulated mod-2³², the C's `(unsigned int)` cast: `4294967297` ⇒ `1`, `-1` ⇒ `u32::MAX`), then `wrapping_sub(CONTROL_MAGIC_NUMBER)`; non-decimal ⇒ `None`, so every named verb keeps its path byte-for-byte; unmatched ⇒ `Opcode::Unknown`. The wrapping is observable: an `Op` below the magic matches no `case`, so `port_control(P, 1, <<1,2,0>>)` and `port_control(P, 99, <<>>)` ⇒ `[0]exbadport`.
- `Scope { Tcp, Udp, Shared }` — the C's three switches (`tcp_inet_ctl`, `packet_inet_ctl`, shared `inet_ctl`): one numberspace, each number a `case` of exactly one, so a number owned by *the other* driver's switch is owned by neither ⇒ `[0]exbadport`.
- `Opcode` — one variant per table row (same names, numbers) plus `Unknown`, with `ALL`/`code`/`from_code`/`scope`/`name`, `not_served() -> BeamError` (typed `unsupported` naming opcode and switch).

### The opcode/verb table (FROZEN)
`op` = `code + 0x03f1_a300`. A decimal command decodes to an opcode, anything else is the named verb of the same row, and both run one body so replies are identical. `s` = served (whole arm); `ref` = the C's refusals reproduced, success path `Err(Opcode::not_served())`; an error name is the `[0]`-tagged reply (`einval` = `[0]einval`, …), `⇒` the success reply. Three `erl` matrices byte-compare every row against the system driver: `opcode_tests.rs::oracle_matrix` (`tcp_inet`, 80 calls), `opcode_tests_udp.rs::oracle_matrix` (`udp_inet`, 89), `opcode_tests_states.rs` (11 rows), over the bare/opened/listening-or-bound/connected/post-close states in one `erl` run.

Both drivers are symmetric on every shared `inet_ctl` arm; only the per-driver switches, the `Fdopen` type guard and `Sendfile` differ.

#### Packed address
`bind`/`connect`/datagram source: `[INET_AF_INET(1), port_hi, port_lo, a, b, c, d]` (7 bytes) or `[INET_AF_ANY(3) | INET_AF_LOOPBACK(4), port_hi, port_lo]` (3 bytes); any other family tag ⇒ `BadArg` (DNS/IPv6 out of scope).
Layout = `inet_get_address`'s (`:4890`): family byte, the host-order port via `put_int16` (MSB first = big-endian, `../beam/sys.h:1314`), then raw `sin_addr` bytes in network order; `load_address` (`:1916`) decodes it with `get_int16`; `addrlen` 7 for IPv4 (`:1156`-`:1160`).

### `mod.rs` — the TCP driver
- `TcpInetDriver` (`Driver::name() == "tcp_inet"`) — one listening or connected socket; `new()` (socket-less registry factory — the `open` verb creates the socket, the C's `tcp_inet_start` + `INET_REQ_OPEN`), `from_socket(fd)` (adopts + probes: `SO_ACCEPTCONN`⇒Listening, `getpeername`⇒Connected, else Open), `adopt_prebound` (`Fdopen`(13)).
- Capability word `DriverFlags::SOFT_BUSY`, the C's `ERL_DRV_FLAG_SOFT_BUSY` beside `ERL_DRV_FLAG_USE_PORT_LOCKING` (`inet_drv.c:1374`) — so `erlang:port_command(Port, Data, [force])` (`erl_bif_port.c:195-198` refuses a flag-less driver with `notsup`, `io.c:1749-1751` clears `busy_flgs` under `force`) is `PortCommandOutcome::Done`, the oracle's `true` (`soft_busy_tests.rs`).
- `InetState { Closed, Open, Listening, Connecting, Connected }` (`is_connected`/`is_listening`/`state_code()`) is the C's `INET_STATE_*`; `eof()`/`peer_closed()` latch the read EOF / peer close, `connect_error()` the late `SO_ERROR`.
- Fake endpoints `name_addr`/`peer_addr` (`desc->name_ptr`/`peer_ptr`): set/cleared by `Setname`/`Setpeer` via `wire::parse_fake_address`, reported by `Name`/`Peer`; `Getladdrs`/`Getpaddrs` ignore them and only `len == 0` clears them (a `close` leaves them).
- `PeerClose` (`TCP_ADDF_DELAYED_CLOSE_RECV`/`_SEND`) — `read(2) == 0` or a reset (`ECONNRESET`/`ECONNABORTED` on read, `ECONNRESET`/`EPIPE` on write) latches one event (*The peer-close ladder*): registration released, the socket never read or written again, the one-shot `closed`/`enotconn` replies armed.
- `Driver::control` takes the packed payload as raw bytes in both wire forms (*opcode.rs*); an unknown non-numeric verb is `BadArg`.
- `connect` completes synchronously under a bounded wait: `EINPROGRESS` settles in-call via `sys::wait_connected(fd, connect_wait_ms(timeout_ms))` — `Some(0)` ⇒ `mark_connected()` + `READABLE` + `[1]`, `Some(errno)` ⇒ `[0]++<lowercase errno>` with the errno kept in `connect_error`, `None` ⇒ `WRITABLE` armed, `Connecting`, `[0]etimedout`; budget `CONNECT_WAIT_CAP_MS = 30_000` (negative — `INET_INFINITY` — ⇒ cap, `0` ⇒ one poll, positive ⇒ clamped), so `EINPROGRESS` never yields the C's `[1]++async_id_be16` (a divergence; `prim_inet:connect_cmd/3` maps `{ok,[]}` to `ok`).
- Readiness & flow control: `EPOLLET` ⇒ every callback drains to `EAGAIN`; one descriptor ⇒ one registration with a flipped `Interest` mask — readable while connected, plus writable while the output queue is non-empty (a short write keeps the remainder queued and arms write readiness) or an over-budget `connect` is in flight, dropped when the queue drains; output left at a latched peer close is dropped (`tcp_clear_output`), writes use `send(2)` + `MSG_NOSIGNAL`.
- Accept readiness IS the listener's read readiness (`FD_ACCEPT` is `ERL_DRV_READ`, `:631`): `verb_open` registers it, `verb_listen` arms nothing (`sock_select(INETP(desc), FD_ACCEPT, 1)` fires on the first queued accept, `:12224`), `async_accept` re-arms per enqueue, `disarm_accepts` deregisters once the list empties (an op taken, a successful accept `:13538`-`:13562`, a due timeout `:12607`-`:12611`) — only while `is_listening()`; a ghost `EAGAIN` stays armed and `drive_async_ops` still makes one non-blocking `accept(2)` attempt.
- A command on a socket-less or unconnected port is consumed and answered out of band: `init_caller` (`:1820`-`:1890`) runs first, size-only — malformed ⇒ `DriverFailure::posix(EINVAL)` (`io.c:7273`) and `PortRegistry::reap_failures` closes the port after the round (`port_command/2` still `true`, later commands the oracle's `badarg`); a well-formed prefix that cannot write stages `Error(ENOTCONN)` (`:12693`) / `Error(EINVAL)` (socket-less `udp_inet`, `:15068`) with the port alive; an empty or non-ETF tag stages no reply (`echoable_caller_tag`).
- One socket, one port: the C's `INET_REQ_ACCEPT` creates a second Erlang port, which this seam cannot, so the numeric request reports the descriptor inside its completion (`Accepted { fd }`, never stored, so no teardown closes it) and the runtime opens the second port (*Handoffs* (0)); only the named `accept` transfers this port, and N queued accepts answer their own id in enqueue order.
- No completion is produced inside a control call — the id is the whole reply; the production points are `ready_input`, the port timer (`next_timeout`/`timeout`) and the round's `drive_async` (which also serves data that arrived *before* the enqueue); a close drains every pending operation as `{error, closed}` first.
- `pending_input: Vec<u8>` (private) — bytes read but not yet a whole frame, only under a framing `{packet, N}` (never raw); the C's `desc->i_buf`, cleared when the socket is replaced/closed; a `{packet, …}`/`{line_delim, …}` change with bytes buffered is not flushed, the next `recv` re-decoding them under the new options (a switch to `raw` delivers the retained buffer verbatim).
- Ownership: `prebound` (`desc->prebound`) is set only by `adopt_prebound`, cleared by `adopt`, honoured by `close_socket`'s early return — an owned descriptor (`open`/`accept` create, `from_socket` adopts) is closed on `stop`, the `close` verb and `Drop`, a prebound one only deregistered.

### The read path — a complete buffered unit wins over a pending peer close
`read_bytes` takes no `DriverContext` and **never latches**: a `read(2)` of `0` or a reset sets `read_eof`, records the observation in `TcpInetDriver::pending_close` as `CloseSource::Read { error }` (`observe_read_close`; `error` `None` for `ECONNRESET` without `{show_econnreset,true}`) and answers only `Result<()>` — whether the observation is *applied* is the caller's `ReadReport`.
Latching is the caller's act: `latch_peer_close(ctx, source)` is the single site running the whole ladder (the active `Error` event first when `options.active > INET_PASSIVE`, `peer_close.observe`, `pending_shutdown = None`, `drain_error_all`, `ctx.output().clear()`, `deregister`, `tears_down_on_close` ⇒ `close_descriptor`).
`read_available` latches **before** queueing the bytes it just read when the read is one the C would have made (`ReadReport::Answered`), so a passive `{Port, {data, …}}` precedes the `{tcp_closed, …}` the same callback produces and a `{packet, N}` frame completed by that call survives the teardown's `tcp_clear_input` (the C clears and only then delivers, `inet_drv.c:12824`-`:12829`); `active.rs`'s `deliver_framed`/`deliver_raw` latch right after their own `read_bytes`.
`try_complete_recv` (**`async.rs`**) instead leaves the observation in `pending_close`: the loop delivers a complete buffered unit first and only when nothing complete is left calls the private `latch_pending(ctx)` (which applies `pending_close` through `latch_peer_close`), so a queued `TCP_REQ_RECV`(42) answers `{ok, Data}` rather than `{error, closed}` and the close stays owed to the operations that follow; a receive finding `pending_close` already set latches before reading, an empty read latches and breaks.
`pending_close: Option<CloseSource>` (`mod.rs`) is reset at each of the three `pending_input.clear()` sites — `adopt`, `adopt_prebound`, `mark_connected` — because a replaced socket's observation belongs to the old descriptor.
**`ReadReport` is the selection test.** The C selects a socket's read side in exactly two states — a granted `{active, …}` (`sock_select(desc,(FD_READ|FD_CLOSE),(desc->active>0))`, `inet_drv.c:7966`) and a waiting `TCP_REQ_RECV` (`:12317`) — so every read it makes is one somebody answers: `ReadReport::Answered` (a queued `TCP_REQ_RECV`, the `recv` verb, an `{active, …}` delivery) **applies** the close it finds. This floor's edge-triggered poller also reads a passive socket with no receive queued — the passive `{Port, {data, …}}` delivery shortcut — which the C never does, so that read is `ReadReport::Unselected`: it delivers the bytes and only **records** the observation, applying nothing.
**The rule:** `tcp_recv` (`:13130`) classifies what the drain collected before it acts on the end-of-file, its delivery points (`:13216`-`:13217`, `:13229`-`:13230`) run first and only a **later** call's `n == 0` reaches `tcp_recv_closed` (`:13206`-`:13208`); the enqueue side agrees (the read at `:12309` precedes `driver_select` at `:12315`).

### The close path on this driver — `flush`, `linger_zero` and `stop`
`TcpInetDriver::flush` is the C's `tcp_inet_flush` (`inet_drv.c:12708`-`:12731`): `discard_output = !(token.is_some() && interest.is_writable()) || options.linger_zero`, and only then does it clear `ctx.output()` (the C's `tcp_clear_output`, `:11718`) — otherwise the bytes stay queued and the port parks in `PortState::Closing` for its own drain.
`SocketOptions::linger_zero` is the C's `TCP_ADDF_LINGER_ZERO` (`:864`): `opt_sys.rs` latches `value != 0 && linger == 0` **before** the `setsockopt` under `scope.is_tcp_protocol()` (`:7382`-`:7386`, `propagate = 0`), so a descriptor whose syscall cannot run latches it too; `inherited_from` copies it (the C flag mask `:11829`-`:11831`) and no option reply reports it.
`udp_inet` has **no** `flush` override, because the C's entry leaves the slot NULL (`:1406`-`:1443`, where `tcp_inet` fills it at `:1368`): `flush_port`'s `flush != NULL` test (`io.c:3664`) calls nothing, so the datagram driver inherits the default and a close keeps its queued output.
`TcpInetDriver::stop` calls `release_socket(ctx)`, never `desc_close(ctx)`: the C's `tcp_inet_stop` (`:11895`-`:11924`) is `tcp_close_check` + `tcp_clear_input` + `inet_stop` and **never touches the `ioq`**, while `desc_close`'s unconditional `tcp_clear_output` (`:11932`-`:11939`) belongs only to the close **verb**. A forced close (a latched driver failure, `io.c:7220`'s `prt->ioq.size = 0`, below the CLOSING branch at `:7212`) drops the remainder with the port's own `stopq` (`io.c:3768`).

### `udp.rs` (`pub`) — the datagram driver
- `UdpInetDriver` — one datagram socket: `new()` (socket-less; the `open` verb creates it), `from_socket(fd)`, `adopt_prebound` (`stype` the operand's `INET_TYPE_*` tag; stream and dgram both admitted); `prebound`/`stat`/ownership follow the stream driver's, `socket()`/`state()` read the same `InetState`.
- Capability word **empty**: the C declares `ERL_DRV_FLAG_USE_PORT_LOCKING` only (`inet_drv.c:1432`), so `Driver::flags()` is `DriverFlags::empty()` and `erlang:port_command(U, D, [force])` is the oracle's `error:notsup` (`erl_bif_port.c:195-198`), not `true`; `RamFileDriver` is the same (`ram_file_drv.c:126`), pinned beside it in `soft_busy_tests.rs`.
- Control verbs run over `verb_open`/`verb_bind`/`verb_connect`/`verb_send`/`verb_recv`/`verb_close`/`verb_getopts` (`setopts` goes through `setopts_with_effects`, whose `ctx`-carrying form also arms and can stage a `Passive`): `open` caches `family`/`stype` (what `GETTYPE` reports for the port's life) and admits `INET_TYPE_DGRAM` only; `bind` refuses any state but `Open` with `exbadport` and reports the bound port; `connect` installs the default peer (`EISCONN` = "already connected"), an empty operand dissolving to `Open`.
- Reception has two paths; the source address rides only the asynchronous one, because it cannot ride the byte-only input queue: `PACKET_REQ_RECV`(60) queues on the shared async slot with the 7 packed source bytes as header; the named `recv` verb is this floor's read-now convenience (no such control op in the C) — one `recvfrom(2)`, the payload pushed to the port input queue and the eight-byte `[1, port_hi, port_lo, a, b, c, d]` reply, `EAGAIN` ⇒ a bare `[1]`, socket-less ⇒ `einval`. `Driver::ready_input` completes a queued operation and with none queued reads nothing — the property that makes the active path safe.
- `send` (`verb_send`, the C's `packet_inet_command`) parses three wire forms in order: `split_address`'s `[address][payload]`, the `[n:be16][n tag bytes]` `prim_inet` prefix (`n >= 1`, `2 + n` fits, `arg[2] == 131`), then `split_datagram`'s `[address][anc_len:be32][anc][data]` (truncated ⇒ `einval`, non-zero `anc_len` ⇒ typed `unsupported`); a queued command needs only an *open* socket — `send(2)` connected, `sendto(2)` with the operand address otherwise, so `gen_udp:send/4`'s unconnected form really sends; a malformed command is `BadArg` with its bytes unconsumed.

### `async.rs` + `accept.rs` (private) / `udp/async.rs` — the asynchronous-operation queue
The C's `desc->async` machinery, shared by both drivers (`mod op_queue`, `async` being a keyword; `udp/async.rs` = the datagram bodies under the same hook names).
- `AsyncQueue` — one receive slot (`INET_MAX_ASYNC = 1`, a second concurrent receive `[0]ealready`) plus a multi-operation accept list (never `ealready`; `accept.rs`'s `AcceptQueue`); `RecvOp`/`AcceptOp` carry the deadline; `next_deadline` is the earliest (`Driver::next_timeout` mirrors it into the port's single `TIMEOUT` task), `has_pending` gates the async drive.
- The multi-accept bit is sticky: `AcceptQueue::multi` is the C's `INET_F_MULTI_CLIENT` bit of `desc->inet.state` — `enqueue` latches it when a second accept joins (`:12189`-`:12194`), `take`/`expire` clear it only when the list is left empty (`:13536`-`:13540` / `:12607`-`:12611`), `take_all` clears it with the teardown drain, and `state_bits` derives `GETSTATUS`'s `0` / `INET_F_ACC` / `INET_F_ACC|INET_F_MULTI_CLIENT` from it, never from the list length. Measured (OTP 29.1.1): bare `9`; one queued (infinity) `41`; two `297`; `[inf, 50ms]` after the 50 ms firing (the head's id 0, id 1 surviving) `297`; one of two served `297`; both served `9`; a further single enqueue `41`.
- The accept timer is per port, its entries a separate sorted list: `AcceptQueue::timers` is the C's `desc->mtd` (one `MultiTimerData` per *finite* deadline) — `enqueue` inserts in sorted position (`add_multi_timer`, `:15744`-`:15790`), `next_deadline`/`timeout_due` read only the earliest, and `expire(now)` performs one `fire_multi_timers` iteration (`:15650`) that consumes that entry, removes the accept list's head (`tcp_inet_multi_timeout` `:12600`-`:12615` → `remove_multi_op` with `timeout_p == NULL`, `:2379`-`:2405`) and answers the head's id. Because the firing does not remove the *head's own* entry, a head owning a later deadline stays armed and later expires the next head (`[500, 50]` reports id 0 at ~51 ms and id 1 at ~501 ms — measured); only a successful completion cancels its own entry, through `take` (`deq_multi_op` + `remove_multi_timer`, `:13553`-`:13559`).
- `NEW_ASYNC_ID` = `op_ref++ & 0xffff`, from 0, taken before the capacity check so a *refused* enqueue still consumes an id; wraps at 65536 (the 255→256 step carries into the high byte). `deadline_for(timeout_ms)` — a negative timeout is the C's `INET_INFINITY` (`None`), `0` "now", positive an `Instant`; `parse_recv_operand`/`length_too_large` decode `Timeout(4), Length(4)` (the accept `Timeout(4)` operand is `accept.rs`'s); `async_ok_reply` builds `[1]++<<Id:16/big>>`.
- Hooks: `try_complete_recv`, `async_ready_input`, `async_timeout`, `drive_async_ops`, `drain_closed`; the accept entries `async_accept`/`accept_ready_once`/`disarm_accepts`/`accepts_completed`/`serve_accepts`/`accept_timeouts` are `accept.rs`'s — the teardown drain answering `{error, closed}` once per pending operation, from `stop`/`verb_close`/`latch_peer_close`.
- The send path's caller tag (`write_command`/`strip_command_prefix`/`fail_malformed_command`/`settle_command`) sits beside the queue in each driver: one prefix per command, the tag staged verbatim in `CompletionEvent::InetReply`, a zero-length tag staging nothing.

### Passive receive is the async-op queue, and it PARKS
`gen_tcp:recv/2,3` issues no synchronous control request: `prim_inet:recv/2` is `recv0(S, Length, -1)`, which waits in `receive {inet_async, S, Ref, Status}` with **no `after`** (`erts/preloaded/src/prim_inet.erl:800-818`), so the read is `?TCP_REQ_RECV`(42) on the single receive slot and `Ref` is the raw 16-bit op id the control reply carried (`{ok,[R1,R0]} -> {ok, ?u16(R1,R0)}`).
The contract: `[1] ++ <<Id:16/big>>` is the whole synchronous answer, and a would-block read is a **park** — `try_complete_recv` makes no progress on `read_bytes`' `EAGAIN` arm and breaks out instead of raising, the C's `ERRNO_BLOCK` arm leaving the op enqueued with the read armed (`inet_drv.c:12265-12325`, `:13130`; `sock_select(FD_READ|FD_CLOSE,1)` `:12315`).
Completion is later, exactly once per op, from `async_ready_input` (through `Driver::ready_input`) or `drive_async_ops` (once per port round by `PortRegistry::execute_port_tasks`, which also serves data that arrived *before* the enqueue); expiry answers `Error(InetReason::Timeout)` after one last `try_complete_recv`, so arrived data wins over the deadline (`tcp_inet_recv_timeout` `:12480`).
`INET_MAX_ASYNC = 1` makes a second concurrent receive `[0]"ealready"` while the first stays pending, and the refused enqueue still consumes an id (`:1069`, `:12307`); a close or a peer close while parked answers `{error, closed}` exactly once (`async_error_am_all(am_closed)` `:11887`/`:12829`/`:12877`), after which a further receive is `[0]enotconn`.
`shutdown/2` is the plain `TCP_REQ_SHUTDOWN`(44) control op (`prim_inet.erl:156-167`): `read`/`write`/`read_write` ⇒ `TCP_SHUT_RD`/`WR`/`RDWR` = `0`/`1`/`2` (`wire.rs:125/128/131`), the reply the bare `[1]` that `ctl_cmd` maps to `{ok,[]}`, the guards `!IS_CONNECTED ⇒ enotconn` (`inet_drv.c:12349`) **before** `len != 1 ⇒ einval` (`:12352`).
`TCP_ADDF_SHUTDOWN_WR_DONE` is set in exactly **two** places, neither the direct success arm (`:12378`, `ctl_reply_ok(...)`, which latches nothing): the **failed** write-side `shutdown(2)` before its error reply (`:12372`) and the **deferred** drain `tcp_shutdown_async` on success (`:13973`); it is consumed at `:13717` (`err == EPIPE && !(tcp_add_flags & TCP_ADDF_SHUTDOWN_WR_DONE)` ⇒ `ECONNRESET`), `tcp_send_or_shutdown_error` then picking `econnreset` vs `closed` under `{show_econnreset,…}` (`:13615`).
A **successful direct** `shutdown(write)` leaves the flag clear, so a later `EPIPE` becomes `{error,econnreset}` under `{show_econnreset,true}`, while a **deferred** shutdown latches it and the same write answers `{error,closed}` whatever the option says.

### Active-mode input delivery (`active.rs` = the TCP half, `udp/active.rs` = the datagram half)
Each arriving input goes to the owner on the crate's `{active,…}` channel (`ActiveInputEvent::{Data,Passive,Error}`, `deliver_active_input`, `take_active_inputs`), never `{Port,{data,…}}`/`CompletionEvent`; the C splits the same way (`erl_drv_output_term` → `desc->dport`, `erl_drv_send_term` → the caller).
- Shape — one `ReadMessage` per unit: a datagram's `header` = the 7 packed source-address bytes (`wire::pack_address`, `inet_drv.c:4896`), `body` = payload; a stream's `header` = the `{header,N}` option only (`desc->hsz`, init `:10922`, setopts `:6931`/`:6936`), `body` = the rest of one frame (framing header stripped by `frame::extract`/`packet_get_body()`, `../beam/packet_parser.h:152-164`; `tcp_reply_data` `:4285`/`tcp_reply_binary_data` `:4314`). `header::split_payload` is the `hsz` half of `(mode == INET_MODE_LIST) || (hsz > len)` (`:2760`-`:4142`) — narrow header + binary tail, `hsz == len` header + empty tail, `hsz > len` all-header; the `mode` half is the runtime's; datagrams apply no `hsz` (*Handoffs* (a0)).
- The third event is a read error — `Error(InetReason)`, the term-free `{tcp_error,S,Reason}` (`tcp_error_message`, `:4079`)/`{udp_error,S,Reason}` (`packet_error_message`, `:4245`) — from `tcp_recv_error`'s active arm (`:12871`), `tcp_send_or_shutdown_error`'s (`:13625`, a reset under `{show_econnreset,true}` only) and `packet_inet_input`'s (`:15486`, any non-`ERRNO_BLOCK` `recvfrom` failure); it precedes the close it accompanies (`:12880`-`:12881`), so `{tcp_closed,S}` = the `port_closed()` latch the same callback sets, never a second event, and a datagram port has no close message. Passive mode reports the reason as an `{error,Reason}` completion (`async_error_am_all(error_atom(err))`, `:12877`); the atom is `InetReason::atom_name()`, rendered (like `Passive`) from the driving port's driver name.
- One unit at a time; the loop stops the moment the mode flips (`if (!desc->inet.active)`, `:13108`-`:13114`): one `{packet,N}` frame per message (the remainder stays in `pending_input`), one message per read burst in `{packet,raw}` (`:13099`-`:13123`); the burst is bounded by `{read_packets}` (`INET_LOPT_UDP_READ_PACKETS`, default `INET_PACKET_POLL = 5`, `:1072`/`:14508`), so `packet_inet_input` (`:15361`) reads at most that many datagrams per call (`:15367`, `:15378`), `EAGAIN` ending it early and the passive path returning after the first (`:15570`-`:15574`); `stat.input(len)` counts each delivered payload (`:15513`).
- The matrix (`INET_CHECK_ACTIVE_TO_PASSIVE`, `:1552`-`:1560`, per delivered packet via `:4302`/`:4329`/`:4352`): `{active,true}` never changes; `{active,once}` flips silently (the bytes stay in the kernel until the next arm or a passive read); `{active,N}` decrements and on 0 flips and stages one `Passive` (`packet_passive_message`, `:4215`); so `Passive` has exactly two sources — the credit-spending delivery and the `setopts` walk — and `{active,true}`/`{active,false}` never emit one. `{active,N}` = `INET_MULTI` (3) + a trailing big-endian 16-bit counter: `opt_state::set_active` accumulates it (`ac += nval`; past `Sint16` ⇒ `einval` at `:6985` after `desc->active = INET_MULTI` at `:6974`, no rollback), clamps a negative sum to 0, turns a 0 sum into `INET_PASSIVE` (`:6993`-`:6998`) and zeroes the counter for any non-multi `{active,…}` (`:6999`-`:7000`); `set_options_tracked` reports `landed_at_zero` (never cleared) and `after_setopts` turns it into the delivery.
- Arming is a driver-side state gate, not a poller mask: the C selects the read side on `active > 0` (`:7944`-`:7987` — setopts `:7966`, tcp connect `:12126`/`:14286`, udp open/fdopen `:14621`/`:14682`), deselects when a delivery spends the grant (`:13106`-`:13114`), re-selects for a queued async recv (tcp `:12317` only when `timeout != 0`; udp `:15496`). `TcpInetDriver::read_armed` mirrors it while the registration lives on (`poller::Interest` has no empty mask; `mio` epoll is edge-triggered) — cleared by the spending delivery, set by an armed grant (an `epoll_ctl(MOD)` re-arm, never a re-register), a queued `TCP_REQ_RECV`, the synchronous `recv` verbs and every fresh connection. While clear, `async_ready_input` reads nothing, the peer's bytes waiting in the kernel instead of landing on the passive `{Port,{data,…}}` channel; a never-armed port keeps its eager `read_armed = true` read into the port queue.
- Readiness dispatches on state, exactly once: `TcpInetDriver::ready_input` takes `tcp_inet_input`'s shape (`:13461`/`:13598`-`:13599` — accept dispatch / `tcp_recv(desc,0)`, never touching `hsz`; `tcp_deliver` `:13042` loops packet-by-packet, `:13069`/`:13094`), so a connected + active socket with no queued `TCP_REQ_RECV` goes to `active_delivery` only, while the accept ladder, a queued receive and a passive connection's bytes-into-the-port-queue stay with `async_ready_input` (running both is a defect — `read_available` would starve the active path). The inline burst is TCP-only, `{active,once}`/`{active,N}` only: `inet_set_opts`'s tail returns 2 (`trigger_recv`) only for `SOCK_STREAM` with `!old_active`, the new mode `once`/`multi` and an unchanged `{packet,…}` (`:7955`-`:7961`), and `INET_REQ_SETOPTS`'s consumer reads 2 as an inline `tcp_recv` + re-arm (`:11145`); `{active,true}` returns 1 ⇒ arm only, a UDP re-arm always waits for the next readiness event (`:7949`/`:7969`). `{deliver,port}` divergence: *Handoffs* (a).

### `opt.rs` (private) — the socket-option vocabulary (`INET_REQ_SETOPTS`/`INET_REQ_GETOPTS`)
- The record walk — `set_options`/`get_options`/`set_options_tracked`, `Step { Done(usize), Refused }`, the code table (`INET_*`/`TCP_*`/`UDP_*`) and the store `SocketOptions` (the C descriptor's fields, incl. the `{active,N}` counter, `linger_zero` and the 9216-byte `{buffer,…}` default). Each code is offered to `opt_state` then `opt_sys`; an unclaimed one is the C's `default` ⇒ the whole reply `[0]einval`, and a `setopts` refused that way still applies the records already passed. `OptScope { stype, family, protocol }` is the cached descriptor state every gate reads (`0` = unset), built by both drivers' setopts and `getopts` sites.
- Wire forms: five-byte `[opt, val_be32]` records walked `while (len >= 5)`; `getopts` takes one-byte codes (`while (len--)`, an empty payload answering a bare `[1]`) and answers `[1]++[opt, val_be32]*` in request order — variable-length codes (`{active,N}`, `linger`, `netns`, `raw`, `bind_to_device`, multicast, `pktoptions`) carrying extra bytes both ways.

Values are stored/reported only; acting on `{packet,…}`/`{mode,…}` is the read path's and the runtime's. The three C misses are preserved: a failed `getsockopt` truncates that record only; a platform-less option answers a literal `0`; a code with no `case` is `RETURN_ERROR()` ⇒ the whole reply `[0]einval`.

### `packet.rs` (`pub`) — the pure packet-framing decoder
- `PacketType` — the C's `enum PacketParseType`; the `u8` discriminant IS the `{packet, N}` wire code (`code()`/`from_code()`), `ALL: [PacketType; 15]`, `is_supported()`. Decoded: `Raw`/`Len1`/`Len2`/`Len4`/`Asn1`/`Rm`/`Cdr`/`Fcgi`/`LineLf`/`Tpkt`; unsupported (their bodies need the C's term-building `PacketCallbacks`): `Http`/`HttpH`/`HttpBin`/`HttpHBin`/`SslTls`. `PacketLength { Complete, NeedMore, Invalid, Unsupported }` is `packet_get_length`'s `> 0`/`0`/`< 0` plus an explicit "not implemented" (`as_error()`: `Invalid`⇒`badarg`, `Unsupported`⇒`notsup`); `Complete(len)` is the total length including the header.
- `PacketOptions { packet, delimiter, max_plen, trunc_len }` — `packet_get_length`'s four arguments; `Default` = `{packet, raw}`, delimiter `\n`, no limits; `max_plen == 0` is "no limit" (`INT_MAX - hlen`), bounding the payload, never the frame. `payload_range` is the `packet_get_body` strip (removed for `Len1`/`Len2`/`Len4`, FCGI padding subtracted for `Fcgi`; every other type as is, so `{packet, line}` keeps its delimiter). ## Accepted-socket option inheritance — `tcp_inet_copy` (`from_accepted` / `SocketOptions::inherited_from`)
The C's `tcp_inet_copy` (`inet_drv.c:11795`-`:11845`, call sites `:12236` numeric `INET_REQ_ACCEPT`, `:13510`, `:13580`) copies a fixed field set from the listener's descriptor onto the freshly-started accepted one; here the runtime opens the second port, so this crate owns the copy, as an additive inherent API (no `Driver`/`DriverContext` change).
- `TcpInetDriver::from_accepted(fd: RawFd, listener: &TcpInetDriver) -> Result<TcpInetDriver>` — adopts `fd` (owned, exactly like `from_socket`, which still probes the kernel state), then applies the listener's inherited options plus the cached `stype`/`family`; it is the only copy path, because `INET_REQ_FDOPEN`'s `adopt_prebound` copies nothing (the C's `inet_ctl_fdopen`, `:5223`-`:5282`).
- `SocketOptions::inherited_from(&self, parent: &SocketOptions) -> SocketOptions` (`pub(super)`, `opt.rs`) is the mapping in ONE place, pure and unit-tested; it names every field explicitly (no `..*self`) so a new field forces a decision.
- Inherited (C field → our code): `inet.mode`→`mode` (24), `inet.exitf`→`exit_on_close` (26), `inet.deliver`→`deliver` (25), `inet.htype`→`packet` (23), `inet.psize`→`packet_size` (32), `inet.stype`/`inet.sfamily`, `inet.hsz`→`header` (21), `inet.bufsz`→`buffer` (20), `desc->high`/`low` (27/28), `desc->send_timeout` (30), `desc->send_timeout_close` (35), `tcp_add_flags & (SHOW_ECONNRESET|LINGER_ZERO|NO_READ_AHEAD)`→`show_econnreset` (39)/`linger_zero`/`read_ahead` (49), plus the listener's busy msgq limits (`:11835`-`:11845`)→`msgq_high`/`msgq_low` (36/37).
- Not inherited, each verified: `active`/`active_count` (`inet_start` `:10932`-`:10933` zeroes them; measured — an `{active,true}` listener's accepted socket reports `active` 0), `debug` (`:10975`), `netns`, `read_packets`, `line_delim`, `delay_send` (`TCP_ADDF_DELAY_SEND` is outside the mask), `buffer_set` (`INET_FLG_BUFFER_SET` lives in `desc->flags`, cleared at `:10967`; only the `{buffer,N}` walk sets it), and kernel socket options (the kernel inherits those across `accept(2)`).
- The split with the Erlang side: `{active,…}`, `nodelay`, `keepalive`, `delay_send`, `priority`, `linger`, `reuseaddr` are re-applied by `prim_inet:accept_opts/3` (`erts/preloaded/src/prim_inet.erl:502`-`:517`) — a different half, pinned separately by `accept_opts_tests.rs`; a code missing from `tcp_inet_copy` still arrives, but only because Erlang re-sends it.
- The registry route: `PortRegistry::driver_as::<TcpInetDriver>(listener)` hands out the listener's own driver through the port layer's `Box<dyn Driver>` (the `Driver: core::any::Any` + `downcast_ref` seam), so `from_accepted(fd, listener)` is reachable from a port. The obligation stays with the runtime: `PortRegistry::open` over `from_accepted(fd, listener)`, never over `from_socket`, which inherits nothing; the served `INET_REQ_FDOPEN` is the other, copy-free route. `inherit_tests.rs` pins the route end to end (the `Accepted { fd }` completion, the `driver_as` downcast, and the accepted port's `getopts` reply carrying the inherited block but not `{active, …}`).

### The `{active, …}` state seam on the two socket drivers (`Driver::active_mode` / `take_active_spends`)
Both drivers answer `ActiveMode::from_parts(self.options.active, self.options.active_count)` — the C's `desc->inet.active`/`active_count` (`inet_drv.c:786`-`:789`) — so the **running** `{active, N}` counter is readable and a runtime need not mirror the `setopts` walk it sent; the mode is written by `opt_state::set_active` (`:6967`-`:7000`) and by nothing but a delivery's spend.
`Driver::take_active_spends` drains a per-driver `active_spends: Vec<ActiveSpend>` (oldest first, consumed on take) recorded at **exactly one site per driver** — the per-delivery spend site: TCP `count_delivery` (`active.rs`; the C's `INET_CHECK_ACTIVE_TO_PASSIVE` `:1552`-`:1561`, reached per packet from `:4302`/`:4329`) and the datagram twin `UdpInetDriver::after_delivery` (`udp/active.rs`, from `:4352`).
`INET_ONCE` records `ActiveSpend::Once` (a silent flip, no message at all) and an `INET_MULTI` counter reaching `0` records `ActiveSpend::Multi` (whose `{tcp_passive,S}`/`{udp_passive,S}` already rides `ActiveInputEvent::Passive`); `INET_ACTIVE`/`INET_PASSIVE` never record, and the delivery loop ends at the flip (`:13108`-`:13114`), so a burst spends at most one grant. The `setopts` walk driving a counter to zero (`landed_at_zero`, `:6993`-`:6998`) **records nothing** — it emits its `Passive` as before, because the C spends a grant only per **delivered** packet.
The private read-side predicate (`desc->active > 0`) is `is_active_mode`, **not** `active_mode`, because the `Driver` trait publishes that name and an inherent method would shadow it at every call site.
`active_seam_tests.rs` (9) pins the four modes per driver, the `setopts`-to-zero distinction, the registry route over a factory-built `"tcp_inet"` port, and three `erl` rows phrased as data/passive counts.

## The peer-close ladder — reset vs end-of-file, and who answers a discovery
`PeerClose` models the C's three independent flags — `TCP_ADDF_DELAYED_CLOSE_RECV` (`:855`), `TCP_ADDF_DELAYED_CLOSE_SEND` (`:856`), `TCP_ADDF_DELAYED_ECONNRESET` (`:862`) — plus the two reasons it owes, both `Option<InetReason>` with `None` meaning `closed`: `delayed_reason` (what a reply ladder answers, `TCP_ADDF_DELAYED_ECONNRESET` generalised into the `econnreset` only the **write** path arms) and `observed` (`observed_reason()`, what the **discovering** operation reports).
- The receive ladder clears both close one-shots and, when the reset bit is latched, reports `econnreset` and clears it (`:12279`-`:12288`); otherwise `closed`; with neither latched, `enotconn`. The send ladder clears only the send one-shot and leaves the reset bit armed for the next receive (`:12681`-`:12692`) — a send never consumes the receive's `econnreset`.
- `econnreset` appears only when the observation was an `ECONNRESET` and `{show_econnreset,true}` (`:13190`, `:13615`) was in effect; a clean end-of-file is always `closed`.
- Read-side discoveries, one caller-visible sequence. A `CloseSource::Read` observation is the same wherever it is made, and the reader that makes it is the party it is answered to (`ReadReport::Answered`): the `recv`/`verb_recv_framed` verbs answer inline from `observed_reason()`, a queued `TCP_REQ_RECV`(42) is answered by `try_complete_recv`'s tail (`async_error_am_all(am_closed)`/`(error_atom(err))`, `:12829`/`:12877`), and an `{active, …}` delivery reports `{tcp_closed, S}`/`{tcp_error, S, Reason}` (`:12841`/`:12871`) through `ActiveInputEvent::Error`. A clean end-of-file arms the send one-shot (`tcp_recv_closed` `:12816`), a read error arms nothing (`tcp_recv_error`'s `:12849`-`:12890` arm), and `delayed_reason` is armed only by the **write** path (`tcp_send_or_shutdown_error`, `:13615`/`:13683`) — so a read discovery never turns a later `closed` into `econnreset`. The reactor's eager passive read (`ReadReport::Unselected`) is **not** a discovery: the C selects a socket's read side only for a granted `{active, …}` or a waiting `TCP_REQ_RECV`, so a close it stumbles on is only recorded in `pending_close` and the sequence above starts at the first read the C would have made — the user sees `closed`/`econnreset`/the errno once, then `enotconn`.
- Residual: an `{active, _}` socket with `{exit_on_close,true}` takes the C's `driver_exit(desc->inet.port, 0)` arm (`:12831` in `tcp_recv_closed`, `:12876` in `tcp_recv_error` with the errno) and kills the port, which this floor does not model — its teardown predicate is `false` whenever `options.active != 0`, so an active socket's peer close only latches and de-registers.

## Constraints
- Errors are `beam_common::{Result, BeamError}` only: operational socket failure ⇒ the `[0]`-tagged reply; malformed argument / unknown named verb ⇒ `BeamError::BadArg`; I/O syscall failure ⇒ `BeamError::Io`; undecodable packet type ⇒ the `badarg`/`notsup` raise; a control opcode the C serves but this floor does not ⇒ `Err(Opcode::not_served())`. Never a wrong result, never a panic.
- One `Driver` is one port: no port-creation capability — a numeric `accept` hands its descriptor to the completion's consumer (the runtime opens the second port), only the named verb transfers the port.
- `unsafe` only in `sys.rs`; the `Driver`/`DriverContext` seam is frozen; a grown source half splits its suite into a sibling test module.

## Handoffs (out of this node — the cross-crate seams `gen_tcp`/`gen_udp` still need)
Rendering `{inet_reply, …}`/`{inet_async, …}`, decoding `caller_ref`, adopting `Accepted` and the registry drains are the crate doc's *Handoffs*; only the driver-family seams are here.
- (0) The accept completion's second port is the runtime's, and the seam is available now (`driver_as` → `from_accepted`): `beam_rt` must open the second port with **that** constructor and render `{inet_async, Listener, Id, {ok, NewPort}}` (the C's `send_async_ok_port` shape `prim_inet:accept0/3` matches); `Accepted { fd }` is adopted that way **or** closed by the runtime — this crate never closes it — and a refused `from_accepted` has no reply channel here, so the runtime answers `{inet_async, Listener, Id, {error, Reason}}` with the descriptor closed, never dropped.
- (a0) The datagram drivers do not apply `{header,N}` and cannot in the frozen shape: the C splits the datagram payload too (`packet_binary_message` `:4140`-`:4154` active, `inet_async_binary_data` `:3928`-`:3944` passive), but `ReadMessage` has one header slot and `udp_inet` spends it on the 7 packed source-address bytes `beam_rt` decodes as `{IP,Port}`, so a second `hsz`-sized header cannot be expressed; closing it needs a third component on the delivered read.
- (a) `{active, N|true|once}` delivery — channel, arming gate, burst bound and matrix are served here; the rendering contract (drain after every round *and* every `close`, the four message shapes, `Passive`/error atoms from the driving port's driver name) is the crate doc's *Handoffs*. Do not add a variant to `PortNotification` (two arms, no wildcard). Unserved here: `{deliver, port|term}` — stored and reported, nothing delivered.
- (b) `send_timeout`/`send_timeout_close` — stored and reported, not acted on: the answer is an asynchronous `{error, timeout}`-shaped `{inet_reply, S, Status, Mref}` (closing under `send_timeout_close`), needing a pending-command slot plus a deadline merged into `Driver::next_timeout` (the port's one `TIMEOUT` task is already armed by the receive/accept operations).
- (c) `controlling_process` — not driver state: `inet:tcp_controlling_process/2` is `erlang:port_connect(S, NewOwner)` plus an Erlang-side drain; there is no `INET_REQ_*` and no owner notion on the `Driver` seam, so it needs `beam_process::PortTable::set_owner` + `beam_rt`'s `PortMeta.owner`.
- (d) The refusal-only/unmodelled arms — `IGNOREFD`(28), `TcpSendfile`(45), `Getservby*`(17/18) success paths, `SUBSCRIBE`(24)'s notification half, `udp_inet`'s ancillary data — each refused honestly today; the missing seam for each is under *Known Issues*.

## Known Issues
- The differential corpus docs list two A.4 inet data-path divergences this driver does **not** have (`tools/differential/src/corpus/inet_write.rs`:147-151, `divergences.md` §A.4, `GAPS.md`): "send-side counters stay zero / owner `beam_io`" — stale, `write_command`/`verb_send` both count, `wire::getstat_reply` renders both, pinned green by `write_frame_tests.rs`/`stat_tests.rs`; "a bare-integer payload is written by the oracle and dropped by `beam_rt`" — the oracle answers `badarg` for a **top-level** integer (`port_command(P,42)`) and accepts one only as a list element (`prim_inet:send/3` wraps `Data` in `[<<Size:16,MrefBin/binary>>, Data]`, `erts/preloaded/src/prim_inet.erl`:578-585); this crate is term-free and the conversion is `beam_rt`'s.
- Caller-reference stripping is by shape, not by caller (the C keys on `driver_caller(port)` being an internal pid, which the frozen seam lacks): a `[n:be16][n bytes]` prefix with `n` non-zero, fitting and `arg[2] == 131` is a caller reference, stripped once per command and echoed verbatim. Residuals: a *plain* TCP payload of that shape loses its head (unreachable from `prim_inet:send/3`, which always prefixes); a *prefixed* UDP command whose tag is ≥ 256 bytes begins with a 1/3/4 byte, so the plain `[address][payload]` grammar wins.
- The write-side framing and accounting are decided **once per command**, when it is queued — a **second** command queued behind a still-stalled partial write is not framed or counted independently, and the caller-tag strip inherits that property (both latches re-arm only when the queue drains). The C has the same single `ioq` and one-`tcp_sendv`-per-`port_command` shape; the residual is the missing per-command boundary, not a wrong count for the command that was framed.
- `SUBSCRIBE`(24)'s reply is exact, its notification is not: `wire::subscribe_reply` reproduces the C's `inet_subscribe` byte for byte, but the C also saves the caller as a subscriber when the out-queue depth is `> 0` and later sends `{empty_out_q, Port}`, which the `Driver`/`PortNotification` seam cannot send — none is ever sent.
- Framing/option divergences: an out-of-range `{packet,N}` code is no framing where the C's `packet_get_length` `default:` rejects it (`frame.rs`); an unknown packed-address family is `badarg` where the C answers `eafnosupport` (`wire.rs`); the `11` `multicast_if` read-back is uninitialised memory in the C (`inet_fill_opts`, `:9494`-`:9520`), so only tag/code/family/length are pinned — this floor answers `[opt][0,0,0,0][INET_AF_INET]`; a short `14`/`15` multicast-membership payload answers `einval` where the C reads past the request; a `{active,N}` record truncated before its counter is `BadArg`. The watermark, `netns`, `delay_send` and send-timeout options are stored and reported only: `{high,low}_msgq_watermark` (`36`/`37`) have no busy-msgq limit on the frozen `Driver`/`Port` seam, `{netns,…}` (`38`) no `setns(2)` in `beam_io`, and `{delay_send,…}` (`31`), `{high,low}_watermark` (`27`/`28`), `{send_timeout,…}`/`{send_timeout_close,…}` (`30`/`35`) are `beam_rt`/`beam_abi` timer/flow-control work (*Handoffs* (b)).
- The `INET_REQ_FDOPEN` `bound == 0` form refuses by errno where the C adopts blind: with the ten-byte form and a zero `bound` word the C skips every probe and answers `[1]`, failing at I/O time; the poller cannot register an invalid descriptor, so this floor answers `[0]"ebadf"` naming the failing probe (`fdopen_errno_tests.rs`).
- Two `-eval` failure modes hide a probe's real cause: an abnormal exit (a failed match, an `erlang:error`) loses the whole `erl` dump — the node dies with the group-leader buffer unflushed, so the failure surfaces only as `the oracle expression failed: ` with empty stderr — and a *hanging* probe reads as `SKIP: erl did not answer within 30s`, almost always a dead expression (a raw `INET_REQ_CONNECT`(3) refused `[0]"eafnosupport"` leaves the following `gen_tcp:accept` hanging). Every bounded wait therefore gives up through `io:format(standard_error, …)` (survives the exit) + `erlang:halt(1)`, and every step that must have succeeded is asserted.

## Test Strategy
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_io` (the wrapper; `$HOME` is read-only). `-p beam_io --lib` is 1071 tests; this subtree holds **602** (group totals: `packet` 62, `udp` 79, `opt` 69, `op_queue` 36, `tests` 34, `active_tests` 29); per-suite counts are the Routing Table's.
- One mechanism: a real loopback socket through `PortRegistry` + `Poller`, the peer/injector outside the port (a datagram injector is `os:cmd("printf … > /dev/udp/127.0.0.1/P")`, never a second VM); waits pump `poller.poll` → `handle_events` → the relevant `take_*` drain until a condition holds under a 10–20 s hang guard, never a fixed sleep.
- **The read path's ordering** (`write_then_close_tests.rs`, 5) on a peer that writes then closes: a queued `TCP_REQ_RECV`(42) answers `{ok, Data}` and owes the close to the operations after it; the same through `from_accepted`; an inherited `{packet,2}` record surviving `tcp_clear_input`; a passive port reporting `{Port,{data,…}}` and the close separately, each exactly once; the `erl` row (`gen_tcp:recv/3` ⇒ `{ok,Data}` then `{error,closed}`).
- **`tcp_inet`'s `flush`** (`flush_tests.rs`, 6, real loopback with a stalled 16 MiB command): an unarmed write interest discarding the queued output; the `linger_zero` trio (the discard decision, the latch before `setsockopt`, accept inheritance); the teardown keeping the queue where the close **verb** clears it; `udp_inet` keeping it because it has no `flush`.
- **The close path** (`close_tests.rs`, 5): the close verb emptying the queued output (no guard); a teardown keeping what write readiness can still send (the port parks in `PortState::Closing`, the stall bound dropping only what never moves); a close dropping a partially buffered `{packet,N}` frame; a prebound close keeping descriptor and state (`GETSTATUS`/`GETFD`/`NAME`/`GETTYPE` unchanged); the `erl` cross-check of the close verb's output row.
- `INET_REQ_GETSTAT`(11) field by field against the oracle on every route and both drivers: `stat_send_tests.rs` (10) both `tcp_inet` write routes through the raw `5/0/10/0/0` and a `{packet,2}` sequence, the 59-byte ten-counter reply, the 16 MiB short write's `send_oct`/`send_max`/`send_cnt`/`send_pend`, the argument rows; `stat_send_udp_tests.rs` (4) the datagram twin on both routes and the accepted-socket route.
- Error delivery: `error_delivery_tests.rs` (6) a `libc` `SO_LINGER{1,0}` + drop `RST` on the accepted peer (error then close under `{show_econnreset,true}`, the close alone under `false`, none after a clean `shutdown`, once-only); `udp/error_tests.rs` (2) an ICMP port-unreachable (one `ActiveInputEvent::Error(InetReason::Errno(ECONNREFUSED))`, port live, no `{udp_closed,_}`).
- Empty datagrams and the dump format: `udp/empty_datagram_tests.rs` (4) — a zero-length datagram is a delivery on every channel (`body: Some(vec![])`, never `None`): active, two back-to-back empties, a queued `PACKET_REQ_RECV`(60) completion, the `erl` rows; `oracle_dump.rs` (10) the length-framed dump (`ERL_FRAME_ELEMENT`/`decode`/`encode`) so a reply holding the `|` delimiter, an empty reply, a NUL, a length-word-like body or a truncation cannot collide; `udp/oracle_dump_tests.rs` (2) an explicit low-byte-`0x7C` bind and the ephemeral bind.
- Passive reads and the shutdown aftermath against the oracle: `passive_recv_tests.rs` (9) a 16-row `escript` cross-check through `prim_inet:async_recv/3` (ids rebased — a raw `INET_REQ_CONNECT` spends id 0 on the oracle); `shutdown_contract_tests.rs` (12) a 34-row dump of `shutdown/2`'s three `how` values and their aftermath (`GETSTATUS`, the next send/recv, a repeated shutdown, the listener's `{error,enotconn}`) plus two `{show_econnreset,true}` groups.
- Crate-level (`tests/`): `inet_async.rs` (8) the completion channel + queue through `PortRegistry` — the path `beam_rt` must run; `inet_accept.rs` (7) the accept chain over a foreign `std::net::TcpStream` peer; `inet.rs` (10) a loopback round trip through a `"tcp_inet"` `DriverRegistry` port plus the peer-close shapes; `udp_inet.rs` (6) the datagram driver through the real port layer.
- **Read shapes.** A header-less read of a built-in driver port is a **runtime-policy** observation, not a driver defect: `tcp_inet`'s and `udp_inet`'s passive bytes stay in `pending_input` (unframed bytes never become a message here) and the inert legacy `driver_tbl` port the differential corpus creates never runs a read, so both sides agree. Every read carrying the C's `(hbuf, hlen, buf, len)` split does render it: an explicit read is one `ReadMessage { header, body }` per `driver_output*` call, reaching the owner as `PortNotification::Data`.
- Every `erl`/`cc` oracle case skips loudly (`SKIP:` banner + early `return`) without the tool or over its 30 s budget — never fails; comparisons are byte-exact except for an ephemeral port or fd.
