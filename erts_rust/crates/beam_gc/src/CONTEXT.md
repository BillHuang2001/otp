## Design Decisions
- **Two generations: a young nursery + `mature`, a minor tenuring young→mature (immediate promotion).**
  A minor Cheney-copies every live young term into `mature` and resets the nursery; a major (fullsweep) evacuates young **and** mature into one freshly-sized space and resets the nursery (the C `major_collection`/`full_sweep_heaps`).
  Terms are immutable, so a mature object can never acquire a pointer to a later-allocated young object: the *no-mature→young-pointer* invariant holds after every minor, and mature objects are **never rescanned** — the generational payoff.
- **The collection kind is chosen from the LIVE promotion, and the destination is sized and checked up front (no partial-copy rollback) from the exact reachable live set plus the young occupancy — never the mature occupancy.**
  A minor runs only when `mature.available_words() >= minor_room_words(roots)`; otherwise `collect` escalates to a major that sizes `mature_after_fullsweep(capacity, live, need)` *before* copying, so a collection never leaves the from-space half-forwarded (`live` from `live.rs`; `need` = the young occupancy **clamped to `young_after_fullsweep(nursery.capacity_words(), live)`**, the capacity the collapse installs right after — the C `adjust_after_fullsweep` `need_after`, `erl_gc.c:2061-2098`).
  `Collector::collect` escalates only when `minor_promotion_fits` fails (the C `mature_size <= OLD_HEND(p) - OLD_HTOP(p)`, `erl_gc.c:1486-1488`, whose failure sends the collection to `do_major_collection`, `:1573-1577`), and both it and `collect_minor`'s pre-copy refusal read the **one** input `minor_room_words(roots)` — the fill when that already fits (`Nursery::used_words`, a cheap short-circuit because it is an upper bound on the live count), else the exact live promotion (`young_promotion_words(roots)`) — so the choice and the refusal cannot disagree.
  A shape whose boundary accumulated a large dead occupancy therefore keeps selecting minors (the shapes `beam_rt`'s `reds_door`/`boundary_cost` fixtures drive run minors on that pattern, the fullsweeps left to the `fullsweep_after` cadence), and on the `gc_bound/churn` shape every escalation it takes is genuine: `../MEASURED.md`'s churn attribution records the mature as low as **1** free word when an escalation fired, so the **0.067** majors/op are forced by the mature generation's promoted garbage, not by a conservative test (the read-only live walk costs one young traversal per collection *only* when the fill does not already fit).
  The young occupancy must be **bounded** for the mature target to be a fixed point, and the bound cannot be the nursery capacity: `Nursery::used_words` is chain-summed, so unclamped it counts every dead word the mutator (or a host's unrooted BIF copy-out, which bumps the process heap and never rewinds) accumulated since the last collection.
  Clamping to the capacity the collapse is about to install restores the C's own premise for that term — `HEAP_TOP(p) - HEAP_START(p)` is one young block's usage, bounded by that block's `HEAP_SIZE`, and the C re-sizes the young block from the live set at every collection (`erl_gc.c:1875-1888`) — so the mature capacity stays a function of the **live set** (upper-bounded by `YOUNG_SHRINK_FACTOR` × `young_target_words(live)`, and identical to the collapse so no escalation mismatch is introduced); a *narrower* bound of `young_target_words(live)` alone is rejected because it leaves the mature region too small whenever the collapse keeps a band capacity, so every collection escalates.
  The mature occupancy is never an input: it is garbage-inflated, so the mature rule's grow bracket (`capacity < target`) would fire on every fullsweep and creep the capacity without bound — and it is never a **minor's** live figure either, for the same reason (a minor does not copy the mature generation).
  Gates: `tests/mature_capacity_feedback.rs` (the clamped occupancy — a 4 062-word dead occupancy and a 16 062-word one both answer 987 words where an unclamped count answers 10 958 and 46 422), `tests/escalation_bound.rs` (the kind choice) and `tests/minor_room_upper_bound.rs` (the requirement is exactly the copy volume).
- **The nursery's post-collection size is a live-set target, resolved in a single application — one per collection kind, so the capacity is a fixed point of the rule, not a ratchet.**
  A **fullsweep** sizes the nursery from the **whole-heap** live set it measured exactly: `young_target_words(live) = next_words(YOUNG_TARGET_LIVE_MULTIPLE * live + need_reserve_words, 0)`, with `YOUNG_TARGET_LIVE_MULTIPLE = 2` bounding the copy work amortized per allocated word at `1/2` (`live / nursery`).
  A **minor** sizes it from the **young** live set the round evacuated — its copy volume, `GcStats::words_copied` — through `young_minor_target_words(live) = next_words(live + need_reserve_words, 0)`: one times the live set, because a young-only figure under-estimates the heap's whole live set, and `next_words(live + reserve)` is the smallest curated capacity at which the round's own survival does not itself force the next collection; the 2× memory-for-copy-amortisation trade belongs to the fullsweep, the one collection that measures the whole heap exactly.
  That 1× multiple is the **flatness-vs-amortisation** choice: the keep band lets the growth seam step the capacity one growth-table entry at a time up to the last entry below the band's upper edge, so the settled capacity stays flat in N at a constant live set.
  The settled *values* are measured, never read off the rule: on the current geometry the dependent `beam_rt` `boundary_cost` churn fixture holds a 2 585-word young space — a **chain sum materialised into a single young space** by `young_after_collection`'s keep branch, `2 585 = 987 + 1598`, inside the band around its 376-word minor target, so 2 585 is not a growth-table entry and 2 586 is — and a 4 185-word mature region, at 2.6522 / 2.6861 / 2.7109 collections per call over its 2 001 / 4 001 / 10 001 calls (N = 2 000 / 4 000 / 10 000), its boundary door firing one collection per 8.86 / 9.40 / 9.96 checks at 0.1949 / 0.1950 / 0.1952 checks per call (`beam_rt`'s `src/runner/tests/boundary_cost.rs` is canonical and re-derives them).
  A larger minor multiple would amortise further but would move the converged capacity off the live set's own curated size — the figure the dependents pin (`beam_rt`'s `reds_door` has a 1 201-word live set and converges on `young_target_words(1 201)` = 2 586 at N = 2 000, 20 000 and 200 000, with `young_minor_target_words(1 201)` = 1 598 as that capacity's band edge; its `slice_charging` control reads 233 = `young_minor_target_words(0)`) — so the amortisation is spent on the mature side instead (`../MEASURED.md`, "The flatness-vs-amortisation trade").
  `YOUNG_SHRINK_FACTOR = 8` widens the keep band around either target so a live set that swings within one operation does not oscillate the capacity, but it does **not** cover the target's own sampling error: a minor's target is `next_words(words_copied + 64)` and `words_copied` swings with **where in the iteration the collection lands** (a trough sample promotes ~0 → target = the 233 floor, an in-flight 256-cell list promotes ~513 → target = 610), so the band's upper edge swings `8 × 233 = 1 864` … `8 × 610 = 4 880`.
  A capacity in that window — in practice a **kept chain sum** such as `987 + 1598 = 2 585` or the next growth step `next_words_above(1598) = 2 586` — is therefore *kept* by a peak sample and given **back to 233** by a trough sample: the `233 ↔ 2 586` swing `beam_rt`'s `gc_bound/churn` trace shows, at 2.3 collections/churn; each climb back is `Nursery::grow`'s strict-progress step, one growth-table entry per growth event, and every step **retires** a space (a carrier allocation; nothing is freed) until the next collapse frees the chain — which is where a churn's `malloc`/`free` share comes from, not from the copy loop.
  `HeapPolicy::young_after_collection(capacity, young_live)` **installs** the minor target when `capacity > YOUNG_SHRINK_FACTOR × target` (shrink) or `capacity < target` (grow) and otherwise **keeps** the capacity; `young_after_fullsweep(capacity, live)` applies its own `[4/3 × target, YOUNG_SHRINK_FACTOR × target]` band — growing a nursery that re-copies its live set too often, shrinking one a dead burst over-sized — and both rules are fixed points.
  The oscillation this rules out is the one a capacity-keyed or fill-keyed target has: `next_words` would step the growth table up on every collection because the fill is ≈ the capacity at a collection (`../MEASURED.md`, the rejected nursery-sizing variants).
  Seams: `HeapPolicy::{young_after_fullsweep, young_after_collection, young_target_words, young_minor_target_words, nursery_floor_words}`, `Nursery::collapse_after_fullsweep` (the fullsweep seam) alongside `Nursery::collapse` (the minor seam), and `grow_major`/`relocate_major`'s `live_words`; each collapse records its target as `Nursery::live_target_words`, which narrows the no-relocation growth seam from above until the next collection (`./nursery/CONTEXT.md`).
- **The floor is a real lower bound a dependent can assert, not an emergent `max()`.**
  `nursery_floor_words() = next_words(need_reserve_words, 0)`; `young_minor_target_words(live) >= floor` and `young_target_words(live) >= floor` hold for **every** `live` (both go through the monotone `next_words` on an argument of at least `need_reserve_words`, and an empty live set makes both return exactly the floor), `nursery_floor_words() >= need_reserve_words` unless `max_heap_words` clamps it below, and the three-way rule installing the target whenever the capacity is below it is what makes the floor bite on a collection rather than only on a derivation.
  `HeapPolicy::default()`: floor **90**, `initial_heap_words()` **233**; a spawn policy (`min_heap_words = 233`): floor **233** = `DEFAULT_MIN_HEAP_WORDS` = `young_minor_target_words(0)`; `src/policy.rs`'s in-module suite pins the three facts exhaustively over the growth table and over min/max-clamped policies.
- **The mature generation's post-fullsweep size is a live-set target too, and it is the one place the 2× memory-for-amortisation trade is spent.**
  `HeapPolicy::mature_target_words(live, young_occupancy) = next_words(MATURE_TARGET_LIVE_MULTIPLE × need_after_fullsweep(live, young_occupancy), 0)`, with `need_after_fullsweep(live, young) = live + young + need_reserve_words` (the C `adjust_after_fullsweep`'s `need_after`, `erl_gc.c:2072`) and `MATURE_TARGET_LIVE_MULTIPLE = 2`.
  One `need_after` admits exactly one minor promotion, so the multiple is literally how many promotions one mature space is sized for: it divides the fullsweep count (each of which copies the whole live set) by 2, at a memory cost of 2 × the room a fullsweep's result needs.
  `mature_after_fullsweep(capacity, live, young_occupancy)` is **target-keyed**: it grows onto the target when `capacity < target`, shrinks onto `target.min(capacity)` when `should_shrink(capacity, target)` (`cap > 4 × target && cap > min`), and otherwise keeps the capacity — so each branch installs the target in the direction its own comparison established (the grow side is deliberately not `should_grow`, whose "less than a quarter of headroom left" arm fires for a capacity one table step *above* the target and would make a branch named *grow* shrink a space).
  Both brackets read the **live set**, never the mature space's own occupancy or capacity, so the capacity is a fixed point rather than a ratchet (`tests/mature_capacity_convergence.rs` is that regression's gate) and a clamped policy's fixed point is its clamped target.
  On the default-policy churn cadence this halves the fullsweep rate for +4 186 words of mature capacity with the copy work unchanged (`../MEASURED.md`, "The mature-generation room policy (generational cadence)").
- **The young nursery is a CHAIN of spaces and `grow_nursery` is a NO-RELOCATION seam** (the growth rule, the strict-progress step, the `max_heap_words` chain budget, the provably-empty-space re-adoption and the indexed containment live in `./nursery/CONTEXT.md`): a growth installs a fresh space and leaves every live word at its original address, the chain's length is the bounded quantity, and only a collection collapses it back to one space on the live-set target.
- **The copier relocates exactly the from-set-reachable graph — nothing else.**
  `Copier::complete` walks only the objects it copied into to-space, forwarding each child slot the canonical `beam_term::layout::for_each_child_slot` walk reports; a reference the `EvacDest` classifies `Target::Foreign` is left verbatim and its target is **not** descended into.
  So a from-space word reached *only* through a container outside the from-set (a mature object during a minor, a literal, the runtime's pooled BIF heap / pointer-stable arena / `beam_message` fragment) is neither kept alive nor updated; a major scans young *and* mature and so repairs a mature→young pointer, which a minor never can.
- **In-place Cheney forwarding, exactly as C.** A boxed object's **header word is overwritten** with the new BOXED-tagged pointer; a cons cell's car becomes `THE_NON_VALUE` and its cdr the new LIST pointer; the scan reproduces the C `sweep()` over the canonical per-object walk, so `copy.rs` holds no per-shape stepping logic.
- **`xptr_tag` is not needed.** The C ORs the literal bit back in only for literal-area copies; this collector copies only in-heap objects, so an out-of-from-space reference fails the `FromSet.contains` test and is left verbatim.
- **Funs are sized and scanned from the inlined-descriptor layout in `beam_term::fun`, NOT `header_arity`/`thing_arityval`.** This runtime inlines the C's `entry` as descriptor words, so a fun block is `[header][desc_words(kind)][env[0..num_free]]` with `desc_words` = 2 (`Local`), 3 (`External`), 10 (`Imported`); `header_arity` deliberately returns the C `ERL_FUN_SIZE - 1 == 1`, which would under-size the copy and land the scan on a raw descriptor word, following it as a bogus term reference and corrupting the heap.
- **Per-object sizing/walking is `beam_term`'s, shared not duplicated, with ONE copy-size override here.** `beam_term::layout::{object_words, for_each_child_slot}` is the only per-object walk, consumed by the copying `Copier` and the mark-region `immix/` phases; `space.rs`, `collector.rs`, `policy.rs`, `stats.rs`, `config.rs` and `error.rs` never inspect a term's interior, and `beam_message` keeps its own private walk; the exception is `copy.rs::move_size`, which returns `ERL_SUB_BITS_SIZE` (5) rather than the sizing graph's `ERL_REFC_BITS_SIZE` (8) for an `ErlSubBits` — the words a copier lays down, after which forwarding `orig` copies the separate 3-word `BinRef`.
- **Root set = a flat `&mut [Eterm]`.** The C scans the whole stack word by word with no frame metadata (a word is a term iff its primary tag is BOXED/LIST and it points into a swept area), so a flat slice of root words (live x registers + live stack cells) is **semantically faithful**, not a shortcut; frame-aware stack relocation (`copy_erlang_stack`) and the process dictionary / message-queue / saved-argument sub-rootsets belong to `beam_process`.
- **`HeapSpace` wraps `beam_alloc::Heap`; it is not a new allocator.** `beam_alloc::Heap` is the production bump heap (its `AllocKind::Heap` exhaustion means "collect") and `HeapSpace` adds only space semantics, so collector and mutator share one allocation implementation.
- **The off-heap list (`Mso`/`MsoHandle` + `beam_alloc::RefcBinary` + `OffHeap`) is not bolted onto the heap.** Both payload kinds live outside every process heap; the collector copies only the small heap-resident handle's scalar words and leaves every off-heap pointer verbatim (the C `sweep_off_heap` rule), and refcount changes are the off-heap API's, so the collector never walks off-heap payloads.
- **`OffHeap` is slot-stable for the list's whole lifetime** — a released slot is kept in place as `None`, so `sweep` never shifts, reorders, compacts or reuses a slot, which an on-heap off-heap reference's `val`-word slot index requires (`beam_message::layout::make_off_heap_container` / `off_heap_slot`).
- **The off-heap *liveness* test is this crate's (the C `sweep_off_heap`), because only a holder of both the root set and the roster can answer it.**
  `src/offheap.rs` is that lowest common ancestor: `for_each_reachable_binary_payload` drives the collector's own safe whole-heap view walk and reports the payload first-data-byte pointer of every reachable `HEADER_BIN_REF` handle (word 1 is `BinRef.val`, i.e. exactly `RefcBinary::data_ptr`), and `sweep_unreachable_binaries` feeds that **sorted** set to the slot-stable `OffHeap::sweep` (`O(n log n)`), releasing every `OffHeapEntry::Binary` no reachable `BinRef` names, keeping every `Mso` unconditionally (an MSO has no `BinRef`-shaped reference) and releasing **nothing** when the walk errors.
  The child walk descends an `ErlSubBits`'s `orig` slot, so the `BinRef` behind every reachable `ErlSubBits` is reported as an object of its own and the header test alone covers the frozen 8-word pair; a match-context `ErlSubBits` is correctly not reported.
  The placement is the point: a wrong payload word index, or a per-host copy of the subtag test, silently leaks every off-heap binary of the process — `beam_process`'s private `reachable_bin_ref_payload` probe is the copy this module is the LCA of; the module is safe Rust (no raw pointer arithmetic, the frozen header and word index read from `beam_term`, the typed error propagated).
  Neither half reclaims on its own: without the trigger a loop that reaches no heap-admission door never collects, so the sweep never runs, and without the sweep a collection reclaims nothing off-heap because the owning handle lives outside the process heap; `tests/offheap_retention.rs` pins the pair as a **counter** contract (with both, `binary_alloc`'s live bytes and the roster length are the same small band at N = 0/250/500/1000 and identical between N = 500 and N = 1000; with the sweep omitted, the identical loop retains exactly one 64 KiB payload and one roster entry per call).
- **`BinVheap` is the trigger half: the C `bin_vheap_sz` budget, and the only signal that off-heap bytes need collecting.**
  Growing the *heap* never says off-heap payload is piling up, so ERTS adds a second disjunct to its collection predicate (`erl_gc.h:132-135`, `ERTS_IS_GC_DESIRED_INTERNAL`): `off_heap.overhead > bin_vheap_sz`, which `BinVheap::triggered` reproduces **strictly greater** (an overhead exactly at the limit is still within budget); `triggered_for` charges a roster as `overhead_bytes() / size_of::<Eterm>()`, agreeing with the C's per-binary division up to the rounding of the summed remainder.
  `BinVheap::new` starts at `HeapPolicy::min_bin_vheap_words` — the C `p->min_vheap_size` / `BIN_VH_MIN_SIZE` (46422 words, `next_heap_size(32768, 0)`), the value `process_info(P, garbage_collection)` reports as `min_bin_vheap_size` — which makes that policy field the launch budget.
  `record_collection` is the C's `p->bin_vheap_sz = next_vheap_size(p, bin_vheap, p->bin_vheap_sz)` with the surviving overhead passed in: grow by the golden ratio (`(Uint64) vheap_sz * 1.618`, a truncating `double` multiply) while `vheap/3 > vheap_sz/4`, halve when `vheap < vheap_sz/4`, hold still in the 25–75 % band, then floor at the policy minimum.
  The one addition is a non-stagnation guard: the loop also stops when the truncating `f64` product fails to advance (the C returns the current size when the multiply wraps), since a limit past `2^53` would otherwise never terminate; the grown limit is a fixed point above the surviving payload, so the next collection is never due immediately.
- **`GenImmixCollector` = the same copying nursery + a mark-region mature space**, promoted through an ATOMIC two-phase driver with a reclaim-first major (`./immix_collector/CONTEXT.md`, and `./immix/CONTEXT.md` for the space itself); the strategy is decided by `AnyCollector::from_config` on `config.mature()`, and the dispatch seam carries no collection logic, so neither strategy depends on the other.
- **Heap sizing is ERTS-shaped and applied at every collection**: `HeapPolicy` carries the C minimums and the `fullsweep_after` cadence, `from_spawn_opts` reproduces the C `spawn_opt` rounding, and `Collector::collect` picks the collection with `fullsweep_due` **or** when the mature space cannot receive the nursery's live promotion (`minor_promotion_fits`).

## The off-heap reclaim seam and its production adoption
Both halves are this crate's; the driver is whoever owns the per-process off-heap roster — reclaim by reachability at a point where the owner's *full* root set is scanned (`for_each_reachable_binary_payload`, or `sweep_unreachable_binaries` for a host that keeps a `beam_gc::OffHeap`), and trigger it with `BinVheap::triggered`/`record_collection` (the C `ERTS_IS_GC_DESIRED_INTERNAL` clause that makes such a collection happen at all for a loop which reaches no heap-admission door).
**`beam_rt` adopts both, per process** (`beam_rt/src/context/gc/bin_vheap.rs`: one `OffHeapReclaimer` per process, home `runner/entry.rs`'s `ProcessEngine.off_heap`, built from `process.collector().policy()`), at **exactly one** reclamation point — the runner's park arm (`runner/run.rs`), after the rooted collection — which on a trigger gathers the just-published roots, hands the payload set `for_each_reachable_binary_payload` reports to `Machine::retain_refc_binaries` (payloads at `refcount > 1` retained), then re-seeds the budget and republishes the process's off-heap figure through `Process::set_off_heap_binary_bytes`.
Every gate is a decline that retains everything: `is_relocation_exempt`, `gc_process_enabled`, the `BinVheap` trigger (strictly `overhead > limit`), the collection valve, and the prune-only `reaches_an_unscanned_word` criterion; `Process::has_unpublished_roots()` is deliberately **not** a valve (it is true for a `Running` process, which is what a pre-empted process still is at every park).
The engine's overhead figure is `Machine::off_heap_overhead_bytes` — Σ `RefcBinary::reserved_bytes` over the reservoir, i.e. the backing store matching this crate's `BinVheap` accounting, not `len()` — and a `Wait` park declines because that window publishes no root set, so the point is the `Yield`/park-after-slice arm.
The process-owned PCB roster keeps its own two halves (`beam_process`'s `sweep_off_heap_binaries` for the declared-dead set, `sweep_off_heap_binaries_reachable` for the reachability set); `sweep_unreachable_binaries` stays the roster-owning form for a host that keeps a `beam_gc::OffHeap`, which the runtime's reservoir path does not.
Pinch-points of the pair: the in-crate counter contract is `tests/offheap_retention.rs`, and the runtime consequence is the `## Measured` bullet in `../CONTEXT.md` (capacity, never latency).

## Heap ownership, the free paths, and the soundness precondition
- **The collector owns its spaces outright; no host or arena owns them.** `Collector` holds `nursery: Nursery` (a chain of `HeapSpace`) + `mature: HeapSpace`; `GenImmixCollector` holds the same nursery + `mature: ImmixSpace`; `AnyCollector` holds one of the two **by value**, and `beam_process::Process` owns that `AnyCollector` (built once at spawn).
  Each space owns exactly one eagerly allocated `beam_alloc::Heap` block at its full capacity, so a space's base is fixed for its whole life and no space ever reallocates.
- **Five sites end a block's life, and one rewinds one** (there is no from-space/to-space swap and no `Collector::reset`): `Nursery::install_collapsed`'s `self.retired.clear()` (`nursery.rs:576`) drops the whole retired chain, its `self.current = HeapSpace::with_allocator(alloc, target)?` (`:583`) replaces the collapsed current space, `Collector::collect_major`'s `self.mature = fresh;` (`collector.rs:452`), `GenImmixCollector::relocate_major`'s `self.mature = fresh;` (`immix_collector.rs:858`), and the owner's own `Drop` (the collector, or the process holding it); the dropped *trial* regions of the mark-region path (`promote`'s `WouldNotFit`, `grow_major`/`relocate_major`'s pre-checks) were never installed.
  The rewind is `Nursery::install_collapsed`'s `self.current.reset()` (`nursery.rs:580`) when the target capacity equals the current one — the words stay mapped and are simply handed out again.
  `install_collapsed` frees the retired chain **before** it allocates the replacement current space (`:576-584`), so the fresh space is the first-fit candidate for the blocks just released and a stale pointer can end up naming the new current space's base and be overwritten by later allocations.
- **`Nursery::grow` frees nothing.** `Nursery::install` (`nursery.rs:501-511`) `core::mem::replace`s the current space into `retired` and `readopt_retired` only swaps two chain members, so the no-relocation growth seam never invalidates a term — only a collection does.
- **Each free runs only after that space's live words were copied out, so the soundness precondition is the caller's root slice.** The minor's from-set is the nursery chain and the major's is chain + mature, and both refusals precede any copy, so an *aborted* collection frees nothing — but a **completed** one frees every from-space, so any live term reachable only from a root the caller did not pass (an engine register outside `[0..Live)`, a host arena, a `Machine` store) is dangling afterwards.
  The walk reaches **only** what the caller's slice names: the crate takes no other sub-rootset (no x-register array, stack frames, dictionary, mailbox, saved args, engine arena or `beam_message` fragment); see `../../../beam_engine/CONTEXT.md` "Heap-region ownership & invalidation".
  On the equal-capacity (reset) branch a stale word reads **reused** words rather than an unmapped page — the mechanism by which a stale cons cell can still look like a cons cell and fault only on the next deref of a garbage cdr.
- **Nothing validates that a "foreign" pointer is still mapped.** Classification is a pure address-range test against the from-set (`copy.rs` → `space.rs`/`FromSet::locate`), a freed address is simply *not contained*, `Target::Foreign` leaves the word byte-identical, and the reachability walk skips the same addresses.
  So a dangle survives every later collection unchanged and faults on first dereference (`beam_term::list::car`), never at the collection that created it; `ScannedBounds::may_contain`/`definitely_unscanned` (`bounds.rs`) is a reject-only filter over the same addresses and is not a mapping test either.
- **The off-heap walk rests on the same slice.** `for_each_reachable_binary_payload` descends what the roots reach and admits only addresses inside the collector's own from-set (`reachable.rs`), so a live `BinRef` in any foreign region (engine arena, `ReservedHeap` grid, pooled BIF heap, message fragment) is invisible, its payload looks dead, and the prune frees memory a live term names; the walk reports no under-approximation signal (`Ok(())`) — the decline guard is the *caller's* (`beam_rt`'s `Criterion::PayloadPrune` valve), not this crate's.
### Which of those sites unmaps and which merely recycles
**The unmap-class set is exhaustive:** a dangling pointer whose target was **freed/unmapped** (a SIGSEGV, not a wrong term) can only come from this list; every other invalidation in the crate merely **recycles** words and would show up as a wrong term instead.
- `nursery.rs`'s `install_collapsed` (`self.retired.clear()` / `retired_regions.clear()` / `empty_retired.clear()`, then `self.current.reset()` or `self.current = HeapSpace::with_allocator(..)`), reachable only from `collect_minor`→`collapse` (`collector.rs:361`), `collect_major`→`collapse_after_fullsweep` (`:467`) and the Immix siblings (`immix_collector.rs:622,724,881`) — i.e. only **after** a round evacuated the whole chain, so the precondition is "the copier forwarded every live word reachable from the slice it was given".
- `collector.rs:452` `self.mature = fresh;` and `immix_collector.rs:858` `self.mature = fresh` (`relocate_major`), under the same precondition over the fullsweep's single from-set (nursery chain + mature).
- `mso.rs:364` `*slot = None` in `OffHeap::sweep` — drops the entry, so the payload goes when the roster held the last reference; `MsoHandle::drop`'s `Box::from_raw` (`mso.rs:143-152`) frees through the **global** allocator, not `beam_alloc` (`Mso::new` boxes it, `mso.rs:72-77`, and nothing in production installs a custom `#[global_allocator]`), so a large MSO payload is the one site here whose pages glibc itself may `munmap`, while a `RefcBinary` payload returns through the `beam_alloc` carrier path (`beam_alloc/src/binary.rs:511-529`).
- `beam_alloc::Heap::drop` (`beam_alloc/src/heap.rs:242-260`, `self.alloc.dealloc(ptr, layout)`) is the OS free behind all of the above.
- **Recycle-class only** (never a SIGSEGV source): `HeapSpace::reset` (`space.rs`, rewinds `used`), `ImmixSpace::reset` (`immix/mod.rs`, "Invalidation, not reclamation"), `release_dead_lines`/`finalize` (`immix/collect.rs`, bits inside a still-live region), `release_words`/`release_lines` (`immix/mod.rs`) and `promote.rs::rollback` (reservation rollback; never dereferences `ptr`).
Two invariants hold the unmap-class set sound, and both were re-verified by a static audit:
- **The from-set covers the whole chain, always.** `Nursery::spaces()` is `retired.iter().chain(once(&current))` and `add_to_from_set` adds every one of them; `retired`/`retired_regions`/`empty_retired` have exactly one insertion point (`install`) and one removal (`readopt_retired`), plus the two clears in `install_collapsed`, so there is no out-of-sync state; `Copier::classify_boxed`/`classify_cons` answer `Target::Foreign` only when `!from.contains(ptr)`, and `FromSet::locate` is the single range-geometry interpreter shared with `live.rs`/`reachable.rs` — so a retired-space pointer is **never** skipped.
- **`Nursery::install`'s `old.used_words() == 0` emptiness decision is exact.** `used_words` is the bump offset (`Heap::used()`), and the only `reset` that can zero it while words are live is `install_collapsed`'s, which runs *after* the round evacuated that same space and cleared the chain — so a space re-adopted by `readopt_retired` genuinely holds no word (a `reset` while words were still reachable would be a *recycling* bug, and the re-adopted space is never unmapped).
Consequence: `beam_gc` cannot itself be the cause of an unmap-class dangling pointer **given a complete root slice** — the enforcement gap is the seam, not the copy; every collection door takes a bare `&mut [Eterm]` (`collector.rs`, `immix_collector.rs`, forwarded by `any_collector.rs`) and none can verify completeness, so a host that collects while its machine's live x-registers/stack/FR are unpublished frees exactly the words those roots name.
**The site a missed root actually faults at** is far from the collection that freed the word: a retired-but-still-mapped space yields garbage, and only a *dropped* space unmaps (`heap.rs:242-260`).
### What the freed bytes reach
- `Heap::drop` calls `Allocator::dealloc` on the crate's **default** allocator, the production `CarrierAllocator` (`Collector::new` takes it); `StdlibAllocator`'s `std::alloc::dealloc` exists only under `#[cfg(test)]`.
  Block-size classes decide the path: `≤1024 B` (≤128 words) is a slab block whose carrier lives for the allocator's lifetime (released only in `AllocatorState::drop`, which never runs for the `static` registry allocators), `1024 B…<512 KiB` (129…65 535 words — the 233-word spawn floor and every realistic nursery) is an MBC block coalesced in place inside a pooled 1 MiB carrier, and `≥512 KiB` (≥65 536 words) or `align > 16` is a **dedicated single-block carrier**.
- **Neither arm calls `munmap` directly.** `Carrier::unmap` is `drop(self)` (`carrier.rs`) → `Segment::drop` → `MsegInner::release` (`mseg/state.rs:142-156`), which pushes the segment onto the process-global **mseg reuse cache** (10 entries, FIFO) and genuinely unmaps only on eviction or a bad-fit tail trim (`mseg/state.rs:119-139` → `mapping.rs:99-105` `libc::munmap`).
- So by **default** a dropped space's pages stay mapped and are recycled: a stale word reads the previous owner's bytes (nothing `madvise`s or zeroes a recycled segment — `AllocatorConfig::zeroed_carriers` is inert) or is silently re-aliased by the next allocation of that size class.
  A SIGSEGV needs the dedicated-carrier class **plus** cache pressure (an 11th ≥512 KiB release), and a dedicated-carrier space is the shape a grown compile nursery reaches — so a large process heap is the configuration in which a stale pointer can fault.

## Handoffs (collector-internal, other owners)
- **The memory reporter should read `HeapFootprint`, not re-derive the formulas** (the per-key map, the owned-vs-invisible split and the m16 evidence are in `ACCOUNTING.md`).
  `beam_rt/src/context/memory_hook.rs`'s `RuntimeMemory::new` computes `processes_used` as `collector.young().used_words() + collector.mature_used_words()`, whose first term is the **current** nursery space only, so every retired space contributes 0 occupied words; the replacement is `collector.total_heap_used_words()`.
  `process_bytes` already reads the chain-summed `collector.total_heap_size_words()` — the figure `HeapFootprint::of(collector, process.owned_off_heap()).capacity_bytes()` derives — and both `Process::owned_off_heap()` and the chain-summed `Process::heap_used_words()` exist, so the one-call seam is adoptable as written.
  A `processes`-side figure must never also absorb `off_heap_payload_bytes` while `binary` is reported — those payloads **are** `erlang:memory(binary)`; the roster's slot array is the half no allocator type records (it is the global allocator's, not `beam_alloc`'s), so it belongs in the `emulator` half if a reporter wants it. Owner: `beam_rt`.
- **`beam_process`'s reachability sweep still applies its own per-object probe.** `sweep_off_heap_binaries_reachable` runs the private `reachable_bin_ref_payload` over the `ReachableObject` views (`beam_process/src/process.rs`) — exactly the predicate `for_each_reachable_binary_payload` is the lowest common ancestor of, which the runtime's reservoir prune already calls. Owner: `beam_process`.
- **The `gc_bound/churn` residual is not this crate's.** The major count stays capacity-forced by the mature generation's promoted garbage and this crate's copy loop is only **4.2 %** of a `perf` profile of the shape; the dominant costs are the interpreter tier (20 %), libc malloc/free/memmove (15 %), `beam_rt::context::gc` (12.7 %) and `beam_bifs`' `Vec` churn (4.9 %) — `beam_bifs/src/{binconv.rs,term_ops.rs,arith.rs}` and `beam_rt/src/context/gc.rs`'s per-op space install. Owners: `beam_bifs` / `beam_engine` / `beam_rt`.
- **The `gc_bound/churn` nursery's capacity is the fullsweep's live-set target** — **4 185** words = `young_target_words(1 353)` for the shape's 1 353-word fullsweep live set, i.e. `next_words(2 × 1 353 + 64)`, with a peak occupancy of 3 523 against an 806-words/op allocation shape, **0.0007** space installs/op and `peak nursery spaces = 1` (`tests/churn_attribution.rs`).
- **The kind-pinned collection is wired end to end.** This crate's side is `AnyCollector::collect_kind`; `beam_process`'s `pub fn collect_kind(&mut self, kind: CollectionKind) -> Result<Collection>` is the `relocation_exempt` guard naming `collect_kind`, then `self.run_rooted_collection(|collector, roots| collector.collect_kind(kind, roots))`; the `beam_rt` handoff is `process.collect_kind(CollectionKind::Minor)?`, which yields `Collection { kind: Minor, .. }` or the typed `out_of_memory`, never an escalated fullsweep.
- **The growth seam is adopted; a `run` process collects only at a `test_heap`/`allocate_heap` admission door, so a loop with no admission instruction never collects.**
  `beam_rt/src/context/gc.rs`'s `collect_or_grow` (behind both `ensure_heap*` doors) grows the running process's nursery through `Process::ensure_capacity` when the policy admits the request and otherwise collects, and `Process::deliver` retries a refused copy the same way; a bounded `+hmax N` policy the request cannot reach still refuses, and that exhaustion raises `error:system_limit`.
  Those two doors are the only readers of `collection_debt()`, and the per-term seams short-circuit first, so such a loop retires space after space with `minor_gcs == 0` while the chain-summed `heap_size` climbs in N, stopped only by the `max_heap_words` budget.
  `ensure_capacity` is the only method that collects unconditionally, and an explicit `erlang:garbage_collect()` is honoured before the bump on both seams, so a `heap_size` that collapses after it distinguishes "no door reached" from a valve decline. Owner of the doors: `beam_rt`.
- **Cross-crate term caveats.** A pid is a heap term via `beam_term::thing::write_external_pid` and `beam_term::compare::eq` orders it structurally through its parts (`external_pid_parts` reads them), and `compare::eq` still recurses forever on a cycle; an MSO has no on-heap reference *term* (the safe reference is the `OffHeap::insert -> slot` index), and a refc binary's `BinRef` is reached via the `ErlSubBits` `orig` slot, not pointer adjacency.

## Notes for Agents (observational forensics)
- **`minor_gcs` is NOT monotone — it is `minor_since_major`, and a major RESETS it to 0.** The only increment sites are `collector.rs`'s `collect_minor` and `immix_collector.rs`'s `run_minor`; both majors (`collect_major`, `run_major`'s in-place path and `relocate_major`) assign 0, so a **constant non-zero** `minor_gcs` read at two different workloads proves *no collection of either kind ran in between*, and a major-only workload reports `0`, never a stale count.
  The monotone lifetime counters are `GcStats::{minor_collections, major_collections}` via `stats()`, and they are **not** part of `HeapInfo` / `process_info(P, garbage_collection)`, whose only collection counter is `minor_gcs`.
- **`heap_size`/`total_heap_size` are CAPACITIES (occupancy-independent), so a flat footprint is NOT evidence that collections are running.** `heap_size_words` = `Nursery::capacity_words` (summed over the chain); `total_heap_size_words` = nursery + mature capacity; only a collapse or a `grow_nursery`/`ensure_capacity` growth changes them.
  A collection with a small live set *shrinks* them, so a steady state under continuous collection shows a converged constant capacity plus a **rising** `minor_gcs`; a constant capacity with a frozen `minor_gcs` means no collection.
- **`GcStats` *returned* by `collect()` is per-collection; `stats()` is lifetime-cumulative for all five fields** — `words_copied`/`words_reclaimed`/`objects_copied` are `+=`-accumulated into the collector's own `GcStats`, so only the returned value (`src/stats.rs`) describes one collection.
- **The single-object size helper is `beam_term::layout::object_words(header, ptr) -> usize` (`pub unsafe`, in `beam_term::prelude`), NOT `beam_gc::copy::move_size`.** `move_size` is `pub(crate)` and equals `object_words` except for the `ErlSubBits` override; `beam_term::size::size_object(Eterm)` is the whole-graph public size, `for_each_ref` is `pub(crate)`, and the public enumerator is `beam_term::layout::for_each_child_slot`.
- **There is no public from-space / "retired spaces" / epoch accessor for a collector's OWN spaces.** `FromSet` itself is fully public (`new`/`add(&HeapSpace)`/`unsafe from_ranges`/`ranges`/`range_count`/`words`/`is_empty`/`contains`), but nothing enumerates the nursery chain (see `./nursery/CONTEXT.md`), and a major drops the old mature space, so a collection's own from-set must be captured from `young()`/`mature_base()` **before** it runs.
- **The only counter-free reclamation is the bump-pointer rewind** `HeapSpace::reset`/`Heap::reset`/`Heap::reset_to`, reached through `young_mut().heap_mut()` and used by `beam_rt` per BIF call on its *pooled* BIF heap, never on a process heap.
- **Diagnosing off-heap retention: three structural counters and one rule.** `OffHeap::overhead_bytes()` (live entries only), the roster `len()` and `beam_alloc`'s `AllocType::Binary` `live_bytes`/`carrier_bytes` are structural, so they are the ones to assert; `BinVheap::limit_words()` says which side of the trigger a process is on, and a roster growing one entry per call with a flat collection count means no trigger site evaluated it — in the runtime the trigger is the slice-boundary park, and a `Wait` park declines because that window publishes no root set.
  An `OffHeapEntry::Mso` surviving `sweep_unreachable_binaries` is correct behaviour, not a leak — that seam keeps MSOs.

## Per-collection allocations (what `collect` allocates; there is no scratch reuse)
- **No collector field is a scratch buffer.** `Collector`'s fields are the two spaces, the counters and `mature_generation`; `GenImmixCollector`'s are the spaces, counters and `last_immix` (its own per-call allocations are in `./immix_collector/CONTEXT.md`); everything below is a **fresh** allocation on every collection call.
- **From-set.** `FromSet::new()` is `Vec::new()`; the first `add`→`insert` grows it — one tiny `Vec` growth per range (1 for a minor, 2 for a fullsweep). `FromSet::words()` is an `O(#ranges)` iterator sum.
- **Copying strategy.** `Copier` allocates nothing; `roots` is scanned **in place** (`forward_roots`) and never copied. A minor's only allocations are the from-set, the optional live walk and — when the policy's target differs from the chain capacity — a **whole fresh nursery space** (`Nursery::install_collapsed`; the equal-capacity branch's `self.current.reset()` allocates nothing). A fullsweep additionally allocates the **whole fresh mature space** and runs the live walk.
- **The escalated-major double walk.** `collect` asks `minor_promotion_fits`→`minor_room_words`, whose cheap branch is the fill test; when the fill exceeds the mature space's room, `young_promotion_words` runs a full `live` walk and the escalation then runs `collect_major`, which walks again — two walk allocations (and two traversals) for that one collection.
- **A minor that takes the walk branch evaluates `minor_room_words` TWICE.** `collect`'s kind choice and `collect_minor`'s own pre-copy requirement each call it, and neither memoizes the result: when the fill short-circuit holds (`mature.available_words() >= fill`) both are `O(1)`, but when it does not, the exact `live` walk — with its fresh `FromSet`, bitmap and worklist — runs once for the kind choice and again for the copy. The choice and the refusal must agree, so the input is shared by *call*, not by value.
- **Every walk allocates a 1-bit-per-from-set-word bitmap plus a worklist.** `reachable.rs::walk_reachable` does `Visited::new` → `first: Vec::with_capacity(#ranges)` and `bits: vec![0; total.div_ceil(64)]`, plus `work: Vec<*mut Eterm> = Vec::new()` grown to the live object count.
  Consumers: `live`/`live_words_in`/`live_full` (`src/live.rs`), `for_each_reachable_object{,_view}` (`src/collector.rs`, `src/immix_collector.rs`), `for_each_reachable_in`, `for_each_reachable_binary_payload` (`src/offheap.rs`) and `sweep_unreachable_binaries` (which also builds and sorts a `Vec<usize>` of live payloads).
- **What a collection does *not* touch:** the off-heap roster and `BinVheap` are host-driven, never walked by `collect`; `OffHeap::overhead_bytes` (`src/mso.rs`) is an `O(#slots)` iterator sum (released slots included), `sweep` is an in-place pass, `slot_bytes`/`len` are `O(1)`, and `BinVheap::triggered_for` (`src/bin_vheap.rs`) is that sum divided by the word size.
- **Allocation-free observables:** `ScannedBounds` (`src/bounds.rs`, three plain fields), `heap_used_words`/`heap_size_words`/`total_heap_size_words` (an `O(#spaces)` chain sum, `src/nursery.rs`), `minor_gcs`, `collection_debt` (`retired.is_empty()`), `young_space_count` (`retired.len()+1`), `should_collect` (`available_words()`), `young`/`young_mut`, `HeapFootprint::of` (`src/footprint.rs`) and `HeapInfo::of` (`src/heap_info.rs`).
