# `beam_gc` — Implementation Detail (`src/`)

## Intent
The implementation node of the `beam_gc` crate: how the collector is built, module by module.
`../CONTEXT.md` (the crate directory) owns the seam shape a dependent designs against, the crate constraints and the measured headlines; this file owns the design decisions, the collector-internal gaps, the seam other owners adopt, the forensics rules and the routing.
The legacy C (`../../../erts/emulator/beam/{erl_gc.c,erl_gc.h,copy.c}`) is the ground-truth behaviour mirrored here without its C structure; the design source is `../../ERTS_RUST_REWRITE_DEEPDIVE.md` §D and the Stage-4 row of §H.

## Design Decisions
- **Two generations: a young nursery + `mature`, with a minor tenuring young→mature (immediate promotion).**
  A minor Cheney-copies every live young term into `mature` and resets the nursery; a major (fullsweep) evacuates young **and** mature into one freshly-sized space, resetting the nursery (the C `major_collection`/`full_sweep_heaps`).
  Terms are immutable, so a mature object can never acquire a pointer to a later-allocated young object: the *no-mature→young-pointer* invariant holds after every minor and mature objects are **never rescanned** — the generational payoff.
- **The destination is sized and checked up front — no partial-copy rollback — from the EXACT reachable live set plus the young heap's occupancy, never the mature occupancy.**
  A minor runs only when `mature.available_words() >= minor_room_words(roots)`; otherwise `collect` escalates to a major that sizes `mature_after_fullsweep(capacity, live, need)` *before* copying, so a collection never leaves the from-space half-forwarded (`live` from `live.rs`, `need` = the young occupancy **clamped to `young_after_fullsweep(nursery.capacity_words(), live)`**, the capacity the nursery's collapse installs right after — the C `adjust_after_fullsweep` `need_after`, `erl_gc.c:2061-2098`).
  The young occupancy lets the mature region receive the **next** nursery's promotion, so minors actually run; it must be **bounded** for the grow branch's target to be a fixed point, and the bound cannot be the nursery capacity: `Nursery::used_words` is chain-summed, so unclamped it counts every dead word the mutator (or a host's unrooted BIF copy-out, which bumps the process heap and never rewinds) accumulated since the last collection. Clamping to the capacity the collapse is about to install restores the C's own premise for that term — `HEAP_TOP(p) - HEAP_START(p)` is one young block's usage, bounded by that block's `HEAP_SIZE`, and the C re-sizes the young block from the live set at every collection (`erl_gc.c:1875-1888`) — so the mature capacity stays a function of the **live set** (upper-bounded by `YOUNG_SHRINK_FACTOR` × `young_target_words(live)`, and identical to the collapse so no escalation mismatch is introduced; a *narrower* bound of `young_target_words(live)` alone is rejected — it leaves the mature region too small whenever the collapse keeps a band capacity, so every collection escalates to a fullsweep). The **kind-selection predicate** is the *live* promotion, never the chain sum: `Collector::collect` escalates only when `minor_promotion_fits` fails (the C `mature_size <= OLD_HEND(p) - OLD_HTOP(p)`, `erl_gc.c:1486-1488`, whose failure sends the collection to `do_major_collection`, `:1573-1577`), and both it and `collect_minor`'s pre-copy refusal read the **one** input `minor_room_words(roots)` — the fill when it already fits (`Nursery::used_words`, a cheap short-circuit because it is an upper bound on the live count), else the exact live promotion (`young_promotion_words(roots)`) — so the choice and the refusal cannot disagree, and a shape whose boundary accumulated a large dead occupancy keeps selecting minors (the shapes `beam_rt`'s `reds_door`/`boundary_cost` fixtures drive run minors on that pattern, with the fullsweeps left to the `fullsweep_after` cadence). (`tests/mature_capacity_feedback.rs` is the mature half's gate: it re-derives the capacity from the *clamped* occupancy, so a 4 062-word dead occupancy and a 16 062-word one both answer 987 words where an unclamped count answers 10 958 and 46 422; `tests/escalation_bound.rs` is the kind-choice half's, and `tests/minor_room_upper_bound.rs` pins that the requirement is exactly the copy volume.)
  The mature occupancy must never be used: it is garbage-inflated, so the mature rule's grow bracket (`capacity < target`) would fire on every fullsweep and creep the capacity without bound — and it is never a **minor's** live figure either, for the same reason (a minor does not copy the mature generation).
- **The nursery's post-collection size is a live-set target, resolved in a single application — one per collection kind.**
  Both targets are a property of the workload (`live`), never of the nursery's own capacity or of the pre-collection fill, so re-deriving one at the same live set reproduces the same capacity: the capacity is a **fixed point** of the rule, not a ratchet.
  A **fullsweep** sizes the nursery from the **whole-heap** live set it measured exactly: `HeapPolicy::young_target_words(live) = next_words(YOUNG_TARGET_LIVE_MULTIPLE * live + need_reserve_words, 0)`, with `YOUNG_TARGET_LIVE_MULTIPLE = 2` bounding the copy work amortized per allocated word at `1/2` (`live / nursery`).
  A **minor** sizes it from the **young** live set the round evacuated — its copy volume, `GcStats::words_copied` — through `HeapPolicy::young_minor_target_words(live) = next_words(live + need_reserve_words, 0)`: one times the live set, because a young-only figure under-estimates the heap's whole live set, and `next_words(live + reserve)` is the smallest curated capacity at which the round's own survival does not itself force the next collection. The 2× memory-for-copy-amortisation trade belongs to the fullsweep, the one collection that measures the whole heap exactly.
  That 1× multiple is the **flatness-vs-amortisation** choice: the nursery's target holds `target / per-iteration allocation` iterations of the mutator's own allocation, and `young_after_collection`'s keep band lets the growth seam step the capacity one growth-table entry at a time up to the last entry below the band's upper edge, so the settled capacity stays flat in N at a constant live set (the settled *values* are measured, never read off the rule: on the current geometry the dependent `beam_rt` `boundary_cost` churn fixture holds a 2 585-word young space — a **chain sum materialised into a single young space** by `young_after_collection`'s keep branch, `2 585 = 987 + 1598`, inside the band around its 376-word minor target, so 2 585 is not a growth-table entry and 2 586 is — and a 6 772-word mature region at 2.36 collections per call over its 2 001 calls; `beam_rt`'s `src/runner/tests/boundary_cost.rs` is canonical and re-derives them).
  A larger minor multiple would amortise further but would move the converged capacity off the live set's own curated size — the figure the dependents pin (`beam_rt`'s `reds_door` converges on `young_target_words(401)` = 987 at N = 2 000, 20 000 and 200 000, with `young_minor_target_words(401)` = 610 as that capacity's band edge; its `slice_charging` control 233 = `young_minor_target_words(0)`), so the amortisation is spent on the mature side instead (`../MEASURED.md`, "The flatness-vs-amortisation trade").
  `YOUNG_SHRINK_FACTOR = 8` widens the keep band around either target, so a live set that swings within one operation does not oscillate the capacity.
  `HeapPolicy::young_after_collection(capacity, young_live)` **installs** the minor target when `capacity > YOUNG_SHRINK_FACTOR × target` (shrink) or `capacity < target` (grow), and otherwise **keeps** the capacity — so a collection can never leave a nursery below `HeapPolicy::nursery_floor_words()` = `next_words(need_reserve_words, 0)` (**90** for the default policy, **233** = `DEFAULT_MIN_HEAP_WORDS` = `young_minor_target_words(0)` for a spawn policy, the figure `beam_rt`'s `COLLECTOR_FLOOR` pin reads).
  `young_after_fullsweep(capacity, live)` applies its own `[4/3 × target, YOUNG_SHRINK_FACTOR × target]` band: it grows a nursery that re-copies its live set too often and shrinks one a dead burst over-sized.
  Seams: `HeapPolicy::{young_after_fullsweep, young_after_collection, young_target_words, young_minor_target_words, nursery_floor_words}`, `Nursery::collapse_after_fullsweep` (the fullsweep seam) alongside `Nursery::collapse` (the minor seam), and `grow_major`/`relocate_major`'s `live_words`.
- **Both collapse seams may grow or shrink, and both are fixed points.**
  Each applies its own target (`young_after_collection` from the promoted words, `young_after_fullsweep` from the whole-heap live set) and records that target as `Nursery::live_target_words`, which **narrows the no-relocation growth seam from above** until the next collection — it is applied *before* the seam's strict-progress step, so it can never install a same-size space (see the growth rule below).
  The oscillation this rules out is the one a capacity-keyed or fill-keyed target has: `next_words` steps the growth table up on every collection because the fill is ≈ the capacity at a collection (`../MEASURED.md`, the rejected nursery-sizing variants).
- **The floor is a real lower bound a dependent can assert, not an emergent `max()`.**
  `nursery_floor_words() = next_words(need_reserve_words, 0)`; `young_minor_target_words(live) >= floor` and `young_target_words(live) >= floor` hold for **every** `live` (both go through the monotone `next_words` on an argument of at least `need_reserve_words`, and an empty live set makes both return exactly the floor), `nursery_floor_words() >= need_reserve_words` unless `max_heap_words` clamps it below, and the three-way rule installing the target whenever the capacity is below it is what makes the floor bite on a collection rather than only on a derivation.
  `HeapPolicy::default()`: floor **90**, `initial_heap_words()` **233**; a spawn policy (`min_heap_words = 233`): floor **233** = `DEFAULT_MIN_HEAP_WORDS` = `young_minor_target_words(0)`. `src/policy.rs`'s in-module suite pins the three facts exhaustively over the growth table and over min/max-clamped policies.
- **`GenImmixCollector` = the same copying nursery + a mark-region mature space, and a minor promotes through an ATOMIC two-phase driver** (`src/immix_collector/promote.rs`, `Result<PromoteOutcome>`): phase R reserves each first-time live object, copies its words and writes the forwarding marker but rewrites **no** reference word; phase C rewrites the recorded slots and roots once every object of the traversal is placed.
  The barrier-free invariant holds because promotion only ever moves young objects *into* mature, and a reservation that finds no run rolls both spaces back byte-for-byte (`PromoteOutcome::WouldNotFit`) instead of leaving a half-forwarded heap.
- **The Immix major is reclaim-first, and sound for the young→mature edge an in-place reclaim cannot ignore.**
  A read-only `scan_young` reports the promotion's exact **line** count and every nursery word pointing into mature; `ImmixSpace::collect` takes those terms as its `promoted` roots (a mature object reachable only through the live nursery survives), each recorded nursery slot is rewritten to the object's final address, and only then does promotion run — by which point the nursery's mature references are `Foreign` and final.
  Reclaim-first is what lets a would-not-fit minor escalate to a major that *makes room*; `words_reclaimed` = mature reclaim + nursery garbage.
- **`GenImmixCollector` ignores the `MatureKind` in `with_config`, and `AnyCollector` only forwards.**
  The type *is* the Immix-backed collector, so `with_config` always builds one over `cfg.policy()`; the strategy is decided by `AnyCollector::from_config` (on `config.mature()`) / `GcConfig::mature_choice`.
  The dispatch seam carries no collection logic, so neither strategy depends on the other, and the geometry accessors exist only because the two mature spaces are differently typed.
- **Heap sizing is ERTS-shaped and applied at every collection**: `HeapPolicy` carries the C minimums and the `fullsweep_after` cadence, `from_spawn_opts` reproduces the C `spawn_opt` rounding, and `Collector::collect` picks the collection with `fullsweep_due` **or** when the mature space cannot receive the nursery's live promotion (`minor_promotion_fits`).
- **The mature generation's post-fullsweep size is a live-set target too, and it is the one place the 2× memory-for-amortisation trade is spent.**
  A fullsweep measures the whole live set exactly, so it is where the mature generation learns its size: `HeapPolicy::mature_target_words(live, young_occupancy) = next_words(MATURE_TARGET_LIVE_MULTIPLE × need_after_fullsweep(live, young_occupancy), 0)`, with `need_after_fullsweep(live, young) = live + young + need_reserve_words` (the C `adjust_after_fullsweep`'s `need_after`, `erl_gc.c:2072`) and `MATURE_TARGET_LIVE_MULTIPLE = 2`.
  One `need_after` admits exactly one minor promotion, so the multiple is literally how many promotions one mature space is sized for: it divides the fullsweep count (each of which copies the whole live set) by 2, at a memory cost of 2 × the room a fullsweep's result needs.
  `HeapPolicy::mature_after_fullsweep(capacity, live, young_occupancy)` is **target-keyed**: it grows onto the target when `capacity < target`, shrinks onto `target.min(capacity)` when `should_shrink(capacity, target)` (`cap > 4 × target && cap > min`), and otherwise keeps the capacity — so each branch installs the target in the direction its own comparison established (the grow side is deliberately not `should_grow`, whose "less than a quarter of headroom left" arm fires for a capacity one table step *above* the target and would make a branch named *grow* shrink a space).
  Both brackets read the **live set**, never the mature space's own occupancy or capacity, so the capacity is a fixed point rather than a ratchet (`tests/mature_capacity_convergence.rs` is that regression's gate) and a clamped policy's fixed point is its clamped target.
  On the default-policy churn cadence this halves the fullsweep rate for +4 186 words of mature capacity with the copy work unchanged (`../MEASURED.md`, "The mature-generation room policy (generational cadence)").
- **The young nursery is a CHAIN of spaces (`src/nursery.rs`), and `grow_nursery` is a NO-RELOCATION seam.**
  `HeapSpace` never reallocates, so growing by replacement would strand every live word; `Nursery::grow` retains the old space and points the allocator at a fresh one, so every live word keeps its **original address**.
  The step is the plain `next_words(need_words, 0)` whenever that already enlarges the space, and **at least** `next_words(2 * capacity, 0)` otherwise — so a caller growing repeatedly at a constant request climbs the growth table geometrically and the chain stays `O(log(heap))` long. A nursery that has **collected** narrows the fresh space **from above** at `min(target, max(one_step, live_target_words))` (`one_step = next_words(need_words).max(capacity)`), so the seam can neither refuse a request that fits (`one_step >= need_words`) nor install a capacity the next collection would immediately give back — while a genuinely large request still gets its own `one_step` size. A fresh nursery, with no measured live set yet, keeps the plain rule.
  Applied **last**, so nothing above can defeat it, is the policy's strict-progress step `target = max(target, policy.next_words_above(capacity))`: a growth **always installs a strictly larger space than the one it retires** — the C's "never the same size when *growing*" rule (`erts_next_heap_size(size, 1)`, `erl_gc.c:310-338`) — so the chain can never stack equally sized spaces (each of which would append a whole capacity while granting no room). `next_words_above` is `next_words(size, 1)` completed to a total function (`size + 1` past the growth table's top), and only the two legitimate ceilings — the table's own limit and `max_heap_words` — can still refuse, both before anything is allocated or retired.
  The consequence for a pre-empted burst is a **chain of strictly increasing spaces** — every growth one table step above the space it retires, held near the remembered live target while the burst is small — rather than one space grown in place: the retained words stay the burst's own allocation, the cost is the space count, and a collection collapses the chain back onto the live-set target (`../MEASURED.md`, "The CLI flatness probe and the burst residual").
- **The ceiling bounds the chain, not one space, and a provably empty space is re-adopted rather than re-allocated.**
  `max_heap_words` is the process's heap budget (the C `+hmax`) and the chain *is* the young heap, so it is enforced against `capacity_words()`: a fresh space may claim only the remaining budget, and a request that budget cannot cover is the typed `heap_exhausted`, decided before anything is allocated or retired.
  A retired space with `used_words() == 0` is provably empty (no term can name into it) and is therefore re-adopted as the current space — the smallest adequate one — which allocates nothing, moves nothing and consumes no budget; the chain's *set* of spaces is unchanged, so `extent` cannot move, but the geometry epoch advances because *which* space is current is part of the cached geometry.
  The selection is `O(log #spaces)`, not a chain scan: retirement indexes every empty space in `empty_retired`, a `BTreeSet<(capacity, serial, base)>`, so `empty_retired_for(need_words)` is one range query (the smallest adequate capacity, oldest among equals, via the retirement serial) and `readopt_retired` removes exactly that key.
- **Containment over the chain is indexed, not scanned.**
  `Nursery::contains` answers from an ordered index of the retired spaces' live regions (`retired_regions: BTreeMap<base, top>`) plus one direct test of the current space, so it is `O(log #spaces)`; the intervals are pairwise disjoint, an indexed `top` is frozen from retirement, and the only space whose `top` moves is tested directly.
  That keeps the seam sound for a caller holding **no root set** — the un-rooted `beam_rt` allocation path, which must not collect.
- **The chain is collapsed to exactly ONE space after any collection**, so `young()`/`young_mut()` keep returning the current allocatable space while `young_contains` covers every space; a ceiling that cannot reach a growth request returns the typed `heap_exhausted` and retires nothing.
  The chain's **length** is the bounded quantity; its retained **bytes** are the ladder's geometric sum, `O(requirement)`, not a function of the call count.
- **`xptr_tag` is not needed.**
  The C ORs the literal bit back in only for literal-area copies; this collector copies only in-heap objects, so an out-of-from-space reference fails the `FromSet.contains` test and is left verbatim.
- **The copier relocates exactly the from-set-reachable graph — nothing else.**
  `Copier::complete` walks only the objects it copied into to-space, forwarding each child slot the canonical `beam_term::layout::for_each_child_slot` walk reports; a reference the `EvacDest` classifies `Target::Foreign` is left verbatim and its target is **not descended into**.
  So a from-space word reached *only* through a container outside the from-set (a mature object during a minor, a literal, the runtime's pooled BIF heap / pointer-stable arena / `beam_message` fragment) is neither kept alive nor updated; a major scans young *and* mature and so repairs a mature→young pointer, which a minor never can.
- **In-place Cheney forwarding, exactly as C.**
  A boxed object's **header word is overwritten** with the new BOXED-tagged pointer; a cons cell's car becomes `THE_NON_VALUE` and its cdr the new LIST pointer.
  The scan reproduces the C `sweep()` over the canonical per-object walk, so `copy.rs` holds no per-shape stepping logic.
- **Funs are sized and scanned from the inlined-descriptor layout in `beam_term::fun`, NOT `header_arity`/`thing_arityval`.**
  This runtime inlines the C's `entry` as descriptor words, so a fun block is `[header][desc_words(kind)][env[0..num_free]]` with `desc_words` = 2 (`Local`), 3 (`External`), 10 (`Imported`).
  `header_arity` deliberately returns the C `ERL_FUN_SIZE - 1 == 1`, which would under-size the copy and land the scan on a raw descriptor word, following it as a bogus term reference and corrupting the heap.
- **Per-object sizing/walking is `beam_term`'s, shared not duplicated, with ONE copy-size override here.**
  `beam_term::layout::{object_words, for_each_child_slot}` is the only per-object walk, consumed by the copying `Copier` and the mark-region `immix/` phases; `space.rs`, `collector.rs`, `policy.rs`, `stats.rs`, `config.rs` and `error.rs` never inspect a term's interior, and `beam_message` keeps its own private walk.
  The exception is `copy.rs::move_size`, which returns `ERL_SUB_BITS_SIZE` (5) rather than the sizing graph's `ERL_REFC_BITS_SIZE` (8) for an `ErlSubBits` — the words a copier lays down, after which forwarding `orig` copies the separate 3-word `BinRef`.
- **Root set = a flat `&mut [Eterm]`.**
  The C scans the whole stack word by word with no frame metadata (a word is a term iff its primary tag is BOXED/LIST and it points into a swept area), so a flat slice of root words (live x registers + live stack cells) is **semantically faithful**, not a shortcut.
  Frame-aware stack relocation (`copy_erlang_stack`) and the process dictionary / message-queue / saved-argument sub-rootsets belong to `beam_process`.
- **`HeapSpace` wraps `beam_alloc::Heap`; it is not a new allocator.**
  `beam_alloc::Heap` is the production bump heap (its `AllocKind::Heap` exhaustion means "collect") and `HeapSpace` adds only space semantics, so collector and mutator share one allocation implementation.
- **The off-heap list is `Mso`/`MsoHandle` + `beam_alloc::RefcBinary` + `OffHeap`, not bolted onto the heap.**
  Both payload kinds live outside every process heap; the collector copies only the small heap-resident handle's scalar words and leaves every off-heap pointer verbatim (the C `sweep_off_heap` rule), and refcount changes are the off-heap API's, so the collector never walks off-heap payloads.
- **`OffHeap` is slot-stable for the list's whole lifetime** — a released slot is kept in place as `None`, so `sweep` never shifts, reorders, compacts or reuses a slot, which an on-heap off-heap reference's `val`-word slot index requires (`beam_message::layout::make_off_heap_container` / `off_heap_slot`).
- **The off-heap *liveness* test is this crate's (the C `sweep_off_heap`), because only a holder of both the root set and the roster can answer it.**
  `src/offheap.rs` is that lowest common ancestor: `for_each_reachable_binary_payload` drives the collector's own safe whole-heap view walk and reports the payload first-data-byte pointer of every reachable `HEADER_BIN_REF` handle (word 1 is `BinRef.val`, i.e. exactly `RefcBinary::data_ptr`), and `sweep_unreachable_binaries` feeds that **sorted** set to the slot-stable `OffHeap::sweep` (`O(n log n)`), releasing every `OffHeapEntry::Binary` no reachable `BinRef` names, keeping every `Mso` unconditionally (an MSO has no `BinRef`-shaped reference), and releasing **nothing** when the walk errors.
  The child walk descends an `ErlSubBits`'s `orig` slot, so the `BinRef` behind every reachable `ErlSubBits` is reported as an object of its own and the header test alone covers the frozen 8-word pair; a match-context `ErlSubBits` is correctly not reported.
  The placement is the point: a wrong payload word index, or a per-host copy of the subtag test, silently leaks every off-heap binary of the process — `beam_process`'s private `reachable_bin_ref_payload` probe is the copy this module is the LCA of.
  It is safe Rust: no raw pointer arithmetic, the frozen header and word index read from `beam_term`, the typed error propagated.
- **`BinVheap` is the trigger half: the C `bin_vheap_sz` budget, and the only signal that off-heap bytes need collecting.**
  Growing the *heap* never says off-heap payload is piling up, so ERTS adds a second disjunct to its collection predicate (`erl_gc.h:132-135`, `ERTS_IS_GC_DESIRED_INTERNAL`): `off_heap.overhead > bin_vheap_sz`, which `BinVheap::triggered` reproduces **strictly greater** (an overhead exactly at the limit is still within budget); `triggered_for` charges a roster as `overhead_bytes() / size_of::<Eterm>()`, agreeing with the C's per-binary division up to the rounding of the summed remainder.
  `BinVheap::new` starts at `HeapPolicy::min_bin_vheap_words` — the C `p->min_vheap_size` / `BIN_VH_MIN_SIZE` (46422 words, `next_heap_size(32768, 0)`), the value `process_info(P, garbage_collection)` reports as `min_bin_vheap_size` — which makes that policy field the launch budget.
  `record_collection` is the C's `p->bin_vheap_sz = next_vheap_size(p, bin_vheap, p->bin_vheap_sz)` with the surviving overhead passed in: grow by the golden ratio (`(Uint64) vheap_sz * 1.618`, a truncating `double` multiply) while `vheap/3 > vheap_sz/4`, halve when `vheap < vheap_sz/4`, hold still in the 25–75 % band, then floor at the policy minimum.
  The one addition is a non-stagnation guard: the loop also stops when the truncating `f64` product fails to advance (the C returns the current size when the multiply wraps), since a limit past `2^53` would otherwise never terminate.
  The grown limit is a fixed point above the surviving payload, so the next collection is never due immediately.
- **Neither half reclaims on its own, and that is the retention contract.**
  Without the trigger a loop that reaches no heap-admission door never collects, so the sweep never runs; without the sweep a collection reclaims nothing off-heap, because the owning handle lives outside the process heap.
  The pair is pinned by `tests/offheap_retention.rs` as a **counter** contract: with both, `binary_alloc`'s live bytes and the roster length are the same small band at N = 0/250/500/1000 and identical between N = 500 and N = 1000; with only the sweep omitted, the identical loop retains exactly one 64 KiB payload and one roster entry per call.
- **The scanned-region aggregate is cached in the nursery chain and derived, not stored, at the collector.**
  `Nursery` keeps `extent: ScannedBounds` over the reserved extents of every space: `grow` only *widens* it (`O(1)` regardless of chain length) because the retired space was already covered while current, and a collapse re-seeds it from the surviving space; both advance the epoch.
  `Collector`/`GenImmixCollector` compose it with their mature extent and a `mature_generation` counter bumped where the mature space is actually replaced, the reported `generation` being the **sum** of the two monotone counters.
  The **reserved** extent (not the moving `top()`) is used because `top()` moves on every allocation.
- **The minor→major escalation test is the LIVE promotion, and on the `gc_bound/churn` shape every escalation it takes is genuine** — `minor_room_words` short-circuits on the chain fill only when that already fits, so a nursery carrying a large dead occupancy beside a small live set keeps running minors, while a live promotion the mature space cannot hold escalates (`../MEASURED.md`'s churn attribution records the mature as low as **1** free word when an escalation fired, so the **0.067** majors/op are forced by the mature generation's promoted garbage, not by a conservative test). The read-only live walk costs one young traversal per collection *only* when the fill does not already fit.
- **Tightening the aggregate is not worth implementing; its acquisition is the only lever.**
  The covering equals the union of the scanned regions to within one block except after a collection, where a per-space interval list or a nursery-vs-mature split is a lateral trade — what falls through tier one is mature- and retired-space pointers, which every interval shape must fall through on (`may_contain` is a reject filter by contract) — so since `beam_rt` re-reads a freshly built `ScannedBounds` per reference word, hoisting one read per walk (a parameter here) is the cheaper lever.

### Region-generic relocating compaction (`src/relocate.rs`) — the foreign-region seam
- **The copy engine is driven over a destination the HOST owns, not only over a process heap.** `Relocator`/`compact` run the same Cheney protocol (forward through `forward_slot` → in-place marker → scan the destination) with the from-set built from **raw word ranges** and the destination supplied by the caller, so a foreign region — a `beam_alloc::ReservedHeap`, a pre-reserved `Vec<Eterm>`, an mmap'd arena, `beam_engine`'s term arena — is compacted without a `Collector`, a `Nursery` or a `HeapSpace`. Nothing on the collection path reads this surface (`Collector`/`GenImmixCollector`/`AnyCollector`/`Copier` behaviour is unchanged), and the copies are accounted by `copy.rs::forward_accounted` — the **one** site `Copier::forward_one` also delegates to — so a relocation and a collection cannot count differently.
- **`FromSet::from_ranges(ranges: &[(usize, usize)])` is the `unsafe` constructor, and its `# Safety` list is the load-bearing part.** Each `(base_address, used_words)` must be word-aligned; its byte extent must be readable **and writable** (a copier forwards in place) for as long as the set is in use; `used_words` must be a **prefix of a real live allocation**, never a fabricated or previously-owned extent (an over-stated extent makes the copier rewrite words no term owns, an under-stated one strands live terms outside the evacuation); the ranges must be pairwise disjoint; and no other thread may free, reallocate or mutate those words while a copy is in flight, with **completeness** (no live term outside the ranges) the caller's claim — exactly as it is for a root slice (`../CONTEXT.md`, "What frees term memory"). Zero-length entries are skipped, and every entry goes through the private `insert`, so the sorted-by-`lo` invariant and `locate`'s "single interpreter of the range geometry" property are preserved rather than re-implemented; alignment and disjointness are `debug_assert!`s, so a release build trusts the caller. `ranges()` is `pub` (half-open **byte** pairs, sorted by `lo`) beside `range_count()`/`words()`/`is_empty()`, and `words()` still over-counts a range registered before its region was filled.
- **`copy.rs::EvacDest` is the public destination seam, and `Target` with it.** The four existing methods are unchanged (`classify_boxed`/`classify_cons`/`can_reserve`/`reserve`), and the trait doc now states the implementation contract: a method may dereference a pointer only **after** establishing the destination owns that memory (containment before the header read; `Foreign` is the only correct answer for a foreign address), `reserve` is called only for a request `can_reserve` admitted and may not alias the source (the marker is written *into* the source object), and `classify_boxed` must answer `Forwarded` for an object already moved — which is what makes a revisit a follow rather than a second copy. The one **defaulted** method, `copied_top() -> Option<*mut Eterm>`, is the walkability declaration a Cheney destination scan needs: `Some` means copies land in one contiguous run that advances monotonically in reservation order (`impl EvacDest for Copier` answers `Some(self.to.top())`, the bump pointer the scan is seeded from), and the default `None` declares the destination unwalkable — which is how the line-granular mark-region space keeps its own block-structured driver. `forward_slot`/`forward_accounted`/`move_size`/`for_each_ref` stay `pub(crate)`: a host supplies a destination and calls the driver, never the marker scheme itself.
- **`LinearDest` is the turnkey destination for a flat host region**, so a host never reimplements the forwarding-marker protocol: `LinearDest::new(from, base, capacity_words)` (unsafe — word-aligned, writable, exclusively-owned words that stay valid and unmoved until the relocator finishes, and **no overlap with any from-range**: the overlap test is what the marker relies on), then `base`/`capacity_words`/`used_words`/`available_words`. Its classification is `Copier`'s rule verbatim (`!from.contains(ptr)` ⇒ `Foreign`; else `is_header(*ptr)` ⇒ `Live`, otherwise `Forwarded` for a boxed word and `is_non_value(*ptr)` ⇒ `Forwarded`/`Live` for a cons), `reserve` bumps `used` and refuses with the typed `heap_exhausted(words)`, and `copied_top` is `Some(base + used)`.
- **`Relocator` is the multi-slice driver; `compact` is its atomic single-slice form.** `Relocator::new` records the destination's `copied_top()` as the **scan origin** and returns `BeamError::BadArg` when it is `None` (an unwalkable destination), mutating nothing; `new_checked` adds the preflight — `!dest.can_reserve(required_words)` is `heap_exhausted(required_words)` before the first word moves — which is what makes a **multi-root-slice** compaction atomic (pass the exact copy volume, `live_words_in` summed over every slice; an over-estimate only causes a conservative refusal). `forward_roots` is **idempotent and callable once per root slice**: a slot already rewritten names the destination, which classifies `Foreign`, so a second pass over the same slice copies nothing and a shared subterm reached from two slices is copied once — while an immediate, a bare header word and a reference outside every range are left byte-identical. `complete` runs the destination scan to completion — `while scan < dest.copied_top()`, per word on `primary_tag`: `Header` ⇒ `move_size` + `for_each_child_slot` forwarding + `scan.add(total)`, `Boxed`/`List` ⇒ one reference word + `scan.add(1)`, `Immed1` ⇒ `scan.add(1)` — and reports `Relocation { stats, dest_words_used }`, with `words_reclaimed = from.words() - words_copied` and the two collection counters **`0`** (a relocation is not a collection of a process heap: it advances no `minor_gcs`/`fullsweep` cadence). For a linear destination `dest_words_used == stats.words_copied` — the host's new used length.
- **The failure semantics are a hard edge and are documented as one.** Every `new`/`new_checked` failure mutates nothing. A `heap_exhausted` (or a `reserve` error) raised from `forward_roots`/`complete` leaves the source **partially forwarded** — some header words hold markers, some roots are rewritten — with the destination holding the copies made so far: **not recoverable**, and the source must not be read afterwards. The two sound patterns are therefore `compact` (one root slice, preflighted from the exact live walk, atomic) and `live_words_in` over every root slice → `Relocator::new_checked(from, dest, total)` → one `forward_roots` per slice → `complete`; `compact`'s atomicity stops at the preflight, so a destination whose `can_reserve` lied and refused only at `reserve` carries the same partial-forwarding hazard.
- **`live_words_in` and `for_each_reachable_in` are the public walking helpers, and they are thin wrappers over the existing walkers** — `live(from, roots).words` and `for_each_reachable_view` — so there is no second walker to keep in step. `live_words_in` is **exactly** the `words_copied` a relocation of the same from-set and roots reports (the walk sizes objects by the copier's own `move_size`, counts each once and skips exactly the references the copier calls `Foreign`), which is why it is the correct `required_words`; summed over **overlapping** slices it over-estimates (a shared object counted twice) — the safe direction, since an over-estimate causes only a conservative refusal. `for_each_reachable_in` reports each reachable **boxed** object once through a safe `ReachableObject` (cons cells are traversed but not reported — they carry no header), read-only and iterative, so a foreign arena can be inspected immediately before a relocation over the same ranges.

## The off-heap reclaim seam and its production adoption
Both halves are this crate's; the driver is whoever owns the per-process off-heap roster.
(i) **Reclaim by reachability.** At a point where the owner's *full* root set is scanned, it drops the handles of the payloads no reachable `BinRef` names — `for_each_reachable_binary_payload` reports that pointer set through the collector's own walk, and `sweep_unreachable_binaries` is the form that writes a `beam_gc::OffHeap` directly (the C `sweep_off_heap`).
(ii) **Trigger it.** `BinVheap::triggered` (or `triggered_for` over a roster) decides whether the off-heap overhead is past the budget the process last sized itself to, and `record_collection` re-seeds that budget from what survived — the C `ERTS_IS_GC_DESIRED_INTERNAL` clause that makes such a collection happen at all for a loop which reaches no heap-admission door.
**`beam_rt` adopts both, per process** (`beam_rt/src/context/gc/bin_vheap.rs`: one `OffHeapReclaimer` per process, home `runner/entry.rs`'s `ProcessEngine.off_heap`, built from `process.collector().policy()`), at **exactly one** reclamation point — the runner's park arm (`runner/run.rs`), after the rooted collection — which on a trigger gathers the just-published roots, hands the payload set `for_each_reachable_binary_payload` reports to `Machine::retain_refc_binaries` (payloads at `refcount > 1` retained), then re-seeds the budget and republishes the process's off-heap figure through `Process::set_off_heap_binary_bytes`.
Every gate is a decline that retains everything: `is_relocation_exempt`, `gc_process_enabled`, the `BinVheap` trigger (strictly `overhead > limit`), the collection valve, and the prune-only `reaches_an_unscanned_word` criterion; `Process::has_unpublished_roots()` is deliberately **not** a valve (it is true for a `Running` process, which is what a pre-empted process still is at every park).
The engine's overhead figure is `Machine::off_heap_overhead_bytes` — Σ `RefcBinary::reserved_bytes` over the reservoir, i.e. the backing store matching this crate's `BinVheap` accounting, not `len()` — and a `Wait` park declines because that window publishes no root set, so the point is the `Yield`/park-after-slice arm.
The process-owned PCB roster keeps its own two halves (`beam_process`'s `sweep_off_heap_binaries` for the declared-dead set, `sweep_off_heap_binaries_reachable` for the reachability set); `sweep_unreachable_binaries` stays the roster-owning form for a host that keeps a `beam_gc::OffHeap`, which the runtime's reservoir path does not.
Pinch-points of the pair: the in-crate counter contract is `tests/offheap_retention.rs`, and the runtime consequence is the `## Measured` bullet in `../CONTEXT.md` (capacity, never latency).
## Heap ownership, the free paths, and the one soundness precondition
- **The collector owns its spaces outright; no host or arena owns them.** `Collector` holds `nursery: Nursery` (a chain of `HeapSpace`) + `mature: HeapSpace` (`collector.rs:63-74`); `GenImmixCollector` holds the same nursery + `mature: ImmixSpace` (`immix_collector.rs:190-202`); `AnyCollector` holds one of the two **by value** (`any_collector.rs:52-57`), and `beam_process::Process` owns that `AnyCollector` (`process.rs:321`, built once at `:517`). Each space owns exactly one eagerly allocated `beam_alloc::Heap` block at its full capacity (`space.rs:51-55`, `immix/mod.rs:342-347`), so a space's base is fixed for its whole life and no space ever reallocates.
- **Five sites end a block's life, and one rewinds one** (there is no from-space/to-space swap and no `Collector::reset`): `Nursery::install_collapsed`'s `self.retired.clear()` (`nursery.rs:576`) drops the whole retired chain, its `self.current = HeapSpace::with_allocator(alloc, target)?` (`nursery.rs:583`) replaces the collapsed current space, `Collector::collect_major`'s `self.mature = fresh; // drops the old mature space` (`collector.rs:452`), `GenImmixCollector::relocate_major`'s `self.mature = fresh` (`immix_collector.rs:858`), and the owner's own `Drop` (the collector, or the process holding it). The rewind is `Nursery::install_collapsed`'s `self.current.reset()` (`nursery.rs:579-580`) when the target capacity equals the current one — the words stay mapped and are simply handed out again.
- **Each free runs only after that space's live words were copied out, so the soundness precondition is the caller's root slice.** The minor's from-set is the nursery chain and the major's is chain + mature (`nursery.rs:274-278`, `collector.rs:334`, `:384-386`, `immix_collector/promote.rs:87-100`), and both refusals precede any copy (`collector.rs:335-338`, `promote.rs:177-180` + `rollback` `:337-346`), so an *aborted* collection frees nothing — but a **completed** one frees every from-space, so any live term reachable only from a root the caller did not pass (an engine register outside `[0..Live)`, a host arena, a `Machine` store) is dangling afterwards. See `../../../beam_engine/CONTEXT.md` "Heap-region ownership & invalidation".
- **Nothing validates that a "foreign" pointer is still mapped.** Classification is a pure address-range test against the from-set (`copy.rs:334-348`, `:350-361` → `space.rs:189-191`/`locate` `:203-217`), a freed address is simply *not contained*, `Target::Foreign` leaves the word byte-identical (`copy.rs:240`, `:280`), and the reachability walk skips the same addresses (`reachable.rs:253-259`). So a dangle survives every later collection unchanged and faults on first dereference (`beam_term::list::car`), never at the collection that created it. `ScannedBounds::may_contain`/`definitely_unscanned` (`bounds.rs:169-181`) is a reject-only filter over the same addresses and is not a mapping test either.
- **Whether the dangling read faults or silently returns garbage depends on the allocator path.** `Heap::drop` (`beam_alloc/src/heap.rs:242-260`) calls `Allocator::dealloc` on the crate's **default** allocator, which is the production `CarrierAllocator` (`beam_alloc/src/registry.rs:54-77`; `Collector::new` takes it at `collector.rs:79`) — `StdlibAllocator`'s `std::alloc::dealloc` (`heap.rs:355-366`) exists only under `#[cfg(test)]`.
  Block-size classes decide the path: `≤1024 B` (≤128 words) is a slab block whose carrier lives for the allocator's lifetime (`allocator/state.rs:227-240`, released only in `AllocatorState::drop` `:256-275`, which never runs for the `static` registry allocators), `1024 B…<512 KiB` (129…65 535 words — the 233-word spawn floor and every realistic nursery) is an MBC block coalesced in place inside a pooled 1 MiB carrier (`allocator/core.rs:496-524`, `mbc.rs:343`), and `≥512 KiB` (≥65 536 words) or `align > 16` is a **dedicated single-block carrier** (`allocator/core.rs:527-543`).
  **Neither arm calls `munmap` directly.** `Carrier::unmap` is `drop(self)` (`carrier.rs:227-229`) → `Segment::drop` → `MsegInner::release` (`mseg/state.rs:142-156`), which pushes the segment onto the process-global **mseg reuse cache** (10 entries, FIFO) and genuinely unmaps only on eviction or a bad-fit tail trim (`mseg/state.rs:119-139` → `mapping.rs:99-105` `libc::munmap`; `:147-151`, `:183-204`).
  So by **default** a dropped space's pages stay mapped and are recycled — a stale word reads the previous owner's bytes (nothing `madvise`s or zeroes a recycled segment: `AllocatorConfig::zeroed_carriers` is inert) or is silently re-aliased by the next allocation of that size class; a SIGSEGV needs the dedicated-carrier class **plus** cache pressure (an 11th ≥512 KiB release).
  A dedicated-carrier space is the shape a grown compile nursery reaches, so a large process heap is the configuration in which a stale pointer can fault.
### Which of those sites unmaps and which merely recycles
#### The unmap-class set
This list is exhaustive:

A dangling pointer whose target was **freed/unmapped** (a SIGSEGV, not a wrong term) can only come from this list; every other invalidation in the crate merely **recycles** words and would show up as a wrong term instead.
- `nursery.rs`'s `install_collapsed` (`self.retired.clear()` / `retired_regions.clear()` / `empty_retired.clear()`, then `self.current.reset()` or `self.current = HeapSpace::with_allocator(..)`).
  Reachable only from `collect_minor`→`collapse` (`collector.rs:361`), `collect_major`→`collapse_after_fullsweep` (`collector.rs:467`) and the Immix siblings (`immix_collector.rs:622,724,881`) — i.e. only **after** a round evacuated the whole chain, so the precondition is "the copier forwarded every live word reachable from the slice it was given".
- `collector.rs:452` `self.mature = fresh; // drops the old mature space` and `immix_collector.rs:858` `self.mature = fresh` (`relocate_major`).
  Same precondition, over the fullsweep's single from-set (nursery chain + mature).
- `mso.rs:364` `*slot = None` in `OffHeap::sweep` — drops the entry, so the payload goes when the roster held the last reference.
  `MsoHandle::drop`'s `Box::from_raw` (`mso.rs:143-152`) frees through the **global** allocator, not `beam_alloc` — `Mso::new` boxes it (`mso.rs:72-77`) and nothing in production installs a custom `#[global_allocator]` — so a large MSO payload is the one site here whose pages glibc itself may `munmap`; a `RefcBinary` payload returns through the `beam_alloc` carrier path instead (`beam_alloc/src/binary.rs:511-529`).
- `beam_alloc::Heap::drop` (`beam_alloc/src/heap.rs:242-260`, `self.alloc.dealloc(ptr, layout)`) is the OS free behind all of the above.
- **Recycle-class only** (never a SIGSEGV source): `HeapSpace::reset` (`space.rs:102`, rewinds `used`), `ImmixSpace::reset` (`immix/mod.rs:462`, "Invalidation, not reclamation"), `release_dead_lines`/`finalize` (`immix/collect.rs:282,298`, bits inside a still-live region), `release_words`/`release_lines` (`immix/mod.rs:640,677`) and `promote.rs::rollback` (reservation rollback; never dereferences `ptr`).

Two invariants hold the unmap-class set sound, and both were re-verified by a static audit (see the parent report on the `compile:file/2` SIGSEGV):
- **The from-set covers the whole chain, always.** `Nursery::spaces()` is `retired.iter().chain(once(&current))` and `add_to_from_set` adds every one of them; `retired`/`retired_regions`/`empty_retired` have exactly one insertion point (`install`) and one removal (`readopt_retired`), plus the two clears in `install_collapsed`, so there is no out-of-sync state.
  `Copier::classify_boxed`/`classify_cons` answer `Target::Foreign` only when `!from.contains(ptr)`, and `FromSet::locate` is the single range-geometry interpreter shared with `live.rs`/`reachable.rs` — so a retired-space pointer is **never** skipped.
- **`Nursery::install`'s `old.used_words() == 0` emptiness decision is exact.** `used_words` is the bump offset (`Heap::used()`), and the only `reset` that can zero it while words are live is `install_collapsed`'s, which runs *after* the round evacuated that same space and cleared the chain — so a space re-adopted by `readopt_retired` genuinely holds no word. (A `reset` while words were still reachable would be a *recycling* bug, and the re-adopted space is never unmapped.)

Consequence: `beam_gc` cannot itself be the cause of an unmap-class dangling pointer **given a complete root slice** — the enforcement gap is the seam, not the copy. Every collection door takes a bare `&mut [Eterm]` (`collector.rs:258,297,332,383,497`, `immix_collector.rs:337,386,406,425,447`, forwarded by `any_collector.rs:270,296,308,316,332`) and none can verify completeness; a host that collects while its machine's live x-registers/stack/FR are unpublished frees exactly the words those roots name.
**The site a missed root actually faults at** is far from the collection that freed the word: a retired-but-still-mapped space yields garbage, and only a *dropped* space unmaps (`heap.rs:242-260`).

## Known Gaps (collector-internal)
- **The mark-region strategy is reachable in production; the DEFAULT remains the copying `Collector`.**
  `beam_process::Process` owns an `AnyCollector` built from the spawn policy, and `beam_rt` drives it at its heap-admission point (`src/context/gc.rs::{ensure_heap, ensure_heap_full}`), reading the mature generation through `mature_contains` (the unscanned-root valve) and `mature_used_words` (the memory hook).
  `select_mature` chooses `Immix` only at/above `IMMIX_BREAK_EVEN_WORDS`, which the default 233-word policy never reaches, so `GcConfig::default()` builds the copying `Collector`; Immix needs a large configured mature generation (`beam_rt`'s default-OFF `BEAM_RT_GC_STRATEGY=immix` opt-in) or an explicit pin — and the mature generation is genuinely exercised either way (**147 minors : 73 fullsweeps** at the default).
- **The Immix region never reallocates in place; the collector grows it by relocation.**
  A major replaces the whole region — the live set relocated into a fresh `ImmixSpace` sized by the policy (`relocate_major`), or a larger one when an in-place fullsweep's reclaim cannot fit the nursery's promotion (`grow_major`).
  So a growable heap never fails a collectable collection; only a `max_heap_words` ceiling the promotion cannot fit returns the typed `heap_exhausted` (before any copy).
- **A retired nursery space is freed only by a collection; a provably empty one is re-adopted instead** (Design Decisions).
  `Nursery::grow` supersedes the space the mutator was allocating in without collecting and without moving a term, so a live term may still name into it: it stays addressable as a chain link and only a collapse frees it.
  `max_heap_words` bounds the summed chain capacity, so `capacity_words() <= max_heap_words` after every successful growth; `max_heap_words == 0` (the default) is "no cap", bounded only by the growth table's last entry (just under `(1<<53)/8` words).
  A policy whose `initial_young_words` already exceeds `max_heap_words` starts above the ceiling (the caller's explicit configuration), and every growth is then the same typed refusal.
- **The chain's collection debt is an opt-in seam; `should_collect` stays occupancy-only** (semantics: Notes for Agents).
  `Nursery::retains_old_spaces` is exported as `collection_debt() -> bool` on all three collector types; `true` means *a collection is required to reclaim the chain*, and the retention is then **one space at most**, however many cycles run (measured: 400 grow+admit cycles → peak chain **2** spaces, peak *retired* **15 143** words on Copying / **8 980** on Immix, against a peak current nursery of **46 422** / **37 670** words; the converged tail is **1** space / **0** retained and the mature capacity settles at **17 731** / **4 352** words — `../MEASURED.md`, "The debt signal and the collection").
  Folding it into `should_collect` would tax **every** admission, which is why it is a separate accessor.
- **A refused promotion is ATOMIC; `collect` recovers, `collect_minor` does not.**
  Line-granular allocation needs a contiguous run inside one 16-line block, so a fragmented region can refuse an object although region-wide `free_lines()` reports room; the driver then rolls BOTH spaces back byte-for-byte (`PromoteOutcome::WouldNotFit`) — no marker, no rewritten root, no counter advanced.
  `collect` escalates to a fullsweep and `grow_major` rebuilds a fresh region, even at the current capacity when a ceiling forbids growing; only a ceiling that cannot hold the live set in ANY layout reports the typed exhaustion, and `collect_minor`'s own contract reports that error rather than escalating, which is `collect`'s job.
- **Deliberately NOT ported:** the C `high_water` single-block layout, per-object tenuring (`GEN_GCS`/`MAX_GEN_GCS`) and the `F_NEED_FULLSWEEP` flag protocol (this crate's two-space scheme instead); the dirty-scheduler escape for long collections (`ERTS_POTENTIALLY_LONG_GC_HSIZE`); and literal-area collection (`erts_garbage_collect_literals`, purge/`xptr_tag`) — literals are treated as permanent and left verbatim.
- **Out of scope by ownership:** frame-aware stack relocation (`copy_erlang_stack`), the process dictionary, on-heap message/signal queues and saved BIF/NIF arguments as sub-rootsets — `beam_process`'s, since this crate takes a flat root slice; and A.6 runtime heap options (`+hms`, `+hmbs`, …) — this crate exposes `HeapPolicy`, not the CLI surface (`beam_rt`'s).
- **`OffHeap` is on the production path as both the MSO slot store and a per-process binary store, and nothing in this crate reclaims an off-heap payload by itself.**
  It IS the production MSO slot store inside `beam_message::OffHeapTable`, and `beam_process::Process` owns a dedicated `OffHeap` (`owned_binaries`) swept as the last step of every rooted collection in two halves: a reachability-driven half (release every owned payload no reachable `BinRef` names; it declines, retaining everything, for a process with `has_unpublished_roots()`) and a conservative half (release exactly the entries the caller declared dead).
  The collector leaves every off-heap pointer verbatim and the liveness predicate is the *owner's*: the runtime's reservoir prune is `beam_rt`'s (above), and a roster whose owner drives neither the walk nor the trigger retains one payload per allocation (`../MEASURED.md`).
## Handoffs (collector-internal, other owners)
- **The memory reporter should read `HeapFootprint`, not re-derive the formulas** (the per-key map, the owned-vs-invisible split and the m16 evidence are in `ACCOUNTING.md`).
  `beam_rt/src/context/memory_hook.rs`'s `RuntimeMemory::new` computes `processes_used` as `collector.young().used_words() + collector.mature_used_words()`, whose first term is the **current** nursery space only, so every retired space contributes 0 occupied words; the replacement is `collector.total_heap_used_words()`.
  `process_bytes` already reads the chain-summed `collector.total_heap_size_words()` — the figure `HeapFootprint::of(collector, process.owned_off_heap()).capacity_bytes()` derives — and both `Process::owned_off_heap()` and the chain-summed `Process::heap_used_words()` exist, so the one-call seam is adoptable as written.
  A `processes`-side figure must never also absorb `off_heap_payload_bytes` while `binary` is reported — those payloads **are** `erlang:memory(binary)`; the roster's slot array is the half no allocator type records (it is the global allocator's, not `beam_alloc`'s), so it belongs in the `emulator` half if a reporter wants it.
  Owners: `beam_rt`.
- **`beam_process`'s reachability sweep still applies its own per-object probe.**
  `sweep_off_heap_binaries_reachable` runs the private `reachable_bin_ref_payload` over the `ReachableObject` views (`beam_process/src/process.rs`) — exactly the predicate `for_each_reachable_binary_payload` is the lowest common ancestor of, which the runtime's reservoir prune already calls.
  Owner: `beam_process`.
- **The `gc_bound/churn` residual is not this crate's.**
  The major count stays capacity-forced by the mature generation's promoted garbage and this crate's copy loop is only **4.2 %** of a `perf` profile of the shape; the dominant costs are the interpreter tier (20 %), libc malloc/free/memmove (15 %), `beam_rt::context::gc` (12.7 %) and `beam_bifs`' `Vec` churn (4.9 %) — `beam_bifs/src/{binconv.rs,term_ops.rs,arith.rs}` and `beam_rt/src/context/gc.rs`'s per-op space install.
  Owners: `beam_bifs` / `beam_engine` / `beam_rt`.
- **The `gc_bound/churn` nursery's capacity is the fullsweep's live-set target** — **4 185** words = `young_target_words(1 353)` for the shape's 1 353-word fullsweep live set, i.e. `next_words(2 × 1 353 + 64)`, with a peak occupancy of 3 523 against an 806-words/op allocation shape, **0.0007** space installs/op and `peak nursery spaces = 1` (`tests/churn_attribution.rs`).
- **The strategy switch is adopted; the residual is an explicit pin on the process-construction path** — `ProcessTable::spawn` takes only a `HeapPolicy`, so the strategy is always the automatic rule, and an explicit `GcConfig`/`MatureSelection` pin would need a parameter there (owner: `beam_process`).
- **`Process::collect_kind` is owed by `beam_process`** (this crate's half is in place: `AnyCollector::collect_kind`): `pub fn collect_kind(&mut self, kind: CollectionKind) -> Result<Collection>` = the `relocation_exempt` guard naming `collect_kind`, then `self.run_rooted_collection(|collector, roots| collector.collect_kind(kind, roots))`.
  The `beam_rt` handoff: `process.collect_kind(CollectionKind::Minor)?` yields `Collection { kind: Minor, .. }` or the typed `out_of_memory`, never an escalated fullsweep.
- **The growth seam is adopted; a `run` process collects only at a `test_heap`/`allocate_heap` admission door, so a loop with no admission instruction never collects.**
  `beam_rt/src/context/gc.rs`'s `collect_or_grow` (behind both `ensure_heap*` doors) grows the running process's nursery through `Process::ensure_capacity` when the policy admits the request and otherwise collects, and `Process::deliver` retries a refused copy the same way; a bounded `+hmax N` policy the request cannot reach still refuses, and that exhaustion raises `error:system_limit`.
  Those two doors are the only readers of `collection_debt()`, and the per-term seams short-circuit first, so such a loop retires space after space with `minor_gcs == 0` while the chain-summed `heap_size` climbs in N, stopped only by the `max_heap_words` budget.
  `ensure_capacity` is the only method that collects unconditionally, and an explicit `erlang:garbage_collect()` is honoured before the bump on both seams, so a `heap_size` that collapses after it distinguishes "no door reached" from a valve decline.
  Owner of the doors: `beam_rt`.
- **Cross-crate term caveats.**
  A pid is a heap term via `beam_term::thing::write_external_pid` and `beam_term::compare::eq` orders it structurally through its parts (`external_pid_parts` reads them), and `compare::eq` still recurses forever on a cycle.
  An MSO has no on-heap reference *term*: the safe reference is the `OffHeap::insert -> slot` index; reach a refc binary's `BinRef` via the `ErlSubBits` `orig` slot, not pointer adjacency.

## Notes for Agents (observational forensics)
- **`minor_gcs` is NOT monotone — it is `minor_since_major`, and a major RESETS it to 0.**
  The only increment sites are `collector.rs`'s `collect_minor` and `immix_collector.rs`'s `run_minor`; both majors (`collect_major`, `run_major`'s in-place path and `relocate_major`) assign 0.
  So a **constant non-zero** `minor_gcs` read at two different workloads proves *no collection of either kind ran in between*, and a major-only workload reports `0`, never a stale count.
  The monotone lifetime counters are `GcStats::{minor_collections, major_collections}` via `stats()`, and they are **not** part of `HeapInfo` / `process_info(P, garbage_collection)`, whose only collection counter is `minor_gcs`.
- **`heap_size`/`total_heap_size` are CAPACITIES (occupancy-independent), so a flat footprint is NOT evidence that collections are running.**
  `heap_size_words` = `Nursery::capacity_words` (summed over the chain); `total_heap_size_words` = nursery + mature capacity; only a collapse or a `grow_nursery`/`ensure_capacity` growth changes them.
  A collection with a small live set *shrinks* them, so a steady state under continuous collection shows a converged constant capacity plus a **rising** `minor_gcs`; a constant capacity with a frozen `minor_gcs` means no collection.
- **`should_collect` is occupancy-only and ignores the chain, so a retired space is visible only through `collection_debt()`.**
  `should_collect(need)` reads the current space alone, and a growth guarantees that room, so it cannot be true right after a growth that satisfied the same `need`.
  `collection_debt()` is `!retired.is_empty()`, set by every `Nursery::grow` that replaces a space and cleared only by a collapse, so the runtime's pairing (`collect_or_grow` / `Process::deliver`) makes `young_space_count` oscillate ≈`1`→`2`→`1`.
  `retired.clear()`/`retired_regions.clear()`/`empty_retired.clear()` exist in exactly one place, `Nursery::install_collapsed` (`src/nursery.rs:576-578`), and `retired.push` in exactly one, `Nursery::install` (`src/nursery.rs:510`).
- **Address-level membership is public; enumeration of the nursery chain is NOT.**
  From outside the crate a caller reaches only the current space (`young()`), a space count (`young_space_count()`) and a membership test over every space (`young_contains(ptr)`); the chain itself is `pub(crate)`, while the mature side is fully addressable (`mature_base`/`mature_capacity_words`/`mature_used_words`/`mature_contains`; `Collector::mature()`, `GenImmixCollector::mature()`).
- **There is no public from-space / "retired spaces" / epoch accessor for a collector's OWN spaces.**
  `FromSet` itself is fully public (`new`/`add(&HeapSpace)`/`unsafe from_ranges`/`ranges`/`range_count`/`words`/`is_empty`/`contains`), but nothing enumerates the nursery chain, and a major drops the old mature space, so a collection's own from-set must be captured from `young()`/`mature_base()` **before** it runs.
- **The single-object size helper is `beam_term::layout::object_words(header, ptr) -> usize` (`pub unsafe`, in `beam_term::prelude`), NOT `beam_gc::copy::move_size`.**
  `move_size` is `pub(crate)` and equals `object_words` except for the `ErlSubBits` override; `beam_term::size::size_object(Eterm)` is the whole-graph public size, `for_each_ref` is `pub(crate)`, and the public enumerator is `beam_term::layout::for_each_child_slot`.
- **Reading the counters for a leak-vs-recycle diagnosis.**
  `heap_size_words()` is the summed capacity of the chain, so a value constant across N iterations proves no uncollected retirement is outstanding without reading `collection_debt()`; no counter advances on the `grow_nursery` path except `young_space_count()`, `collection_debt()` and that summed `heap_size_words()`.
  The only counter-free reclamation is the bump-pointer rewind `HeapSpace::reset`/`Heap::reset`/`Heap::reset_to`, reached through `young_mut().heap_mut()` and used by `beam_rt` per BIF call on its *pooled* BIF heap, never on a process heap.
- **Address stability under growth vs. collection.**
  A `grow_nursery` always installs a new `HeapSpace` (so `young().base()` changes); a collapse keeps the base when the target capacity equals the current one and installs a new space only when it differs.
- **`young()` is the CURRENT space; every "nursery" figure in `HeapInfo` is CHAIN-SUMMED** — `young().capacity_words()` is the current space only, while `heap_size_words()`/`HeapInfo::heap_size` is `Nursery::capacity_words()` (`src/collector.rs:654-656`); they agree only while `young_space_count() == 1`.
- **`GcStats` *returned* by `collect()` is per-collection; `stats()` is lifetime-cumulative for all five fields** — `words_copied`/`words_reclaimed`/`objects_copied` are `+=`-accumulated into the collector's own `GcStats` (`src/collector.rs:207-210`, `:284-287`, `immix_collector.rs:531-538`), so only the returned value (`src/stats.rs:25-27`) describes one collection.
- **Diagnosing off-heap retention: three structural counters and one rule.**
  `OffHeap::overhead_bytes()` (live entries only), the roster `len()` and `beam_alloc`'s `AllocType::Binary` `live_bytes`/`carrier_bytes` are structural, so they are the ones to assert; `BinVheap::limit_words()` says which side of the trigger a process is on, and a roster growing one entry per call with a flat collection count means no trigger site evaluated it — in the runtime the trigger is the slice-boundary park, and a `Wait` park declines because that window publishes no root set.
  An `OffHeapEntry::Mso` surviving `sweep_unreachable_binaries` is correct behaviour, not a leak — that seam keeps MSOs.

- **A minor sizes the nursery from the words it promoted, so a nursery too small for its live set is grown onto that target by the collection itself.**
  `Nursery::collapse` (a minor's seam) applies `HeapPolicy::young_after_collection` over the round's `words_copied`, so a nursery smaller than its young live set's target is enlarged onto it at the first collection that measures one, and `nursery_floor_words()` is a real lower bound on whatever capacity the collection installs (a tiny nursery therefore cannot ratchet *and* cannot stay below the floor).
  The two request-driven growth seams are `Collector::ensure_capacity` and the un-rooted `Nursery::grow`, which installs `max( strict_progress, min(target, max(one_step, live_target)) )` — `one_step = next_words(need).max(capacity)`, `target` the plain curated step (at least a doubling), `live_target` the target the last collapse recorded and `strict_progress = policy.next_words_above(capacity)` the always-strictly-larger step applied last — so a burst's growths stay bounded by the live set, a growth always makes room over the space it retires, and a nursery that has not collected yet (no live target) climbs the plain growth table.
  `tests/heap_growth.rs::ensure_capacity_reports_a_typed_error_when_growth_is_capped` pins the capped half at `initial_young_words: 51` with `max_heap_words: 233`: a 4 096-word request is the typed `out_of_memory` and leaves the 51-word space and the chain's summed capacity untouched, while a 64-word request collects a minor and installs the 90-word `next_words(64)` step.
  The refusal is honest — the ceiling bounds the chain's summed capacity and a 51-word space cannot host a 4 096-word request — and a policy that wants the request to fit must give the chain the room (or `Nursery::grow` would have to free a provably empty current space instead of retiring it, which is not implemented).
- **The Immix mature space's `used_words()` is line-granular (`used_lines() * LINE_WORDS`), so it is an upper bound on the live words rather than an exact figure — which is why no sizing rule reads it.**
  `GenImmixCollector::run_minor` feeds `Nursery::collapse` the words the promotion actually moved (`stats.words_copied`), exactly the quantity the copying collector feeds it, which is what keeps the two strategies' collapsed capacities equal for the same live set.
- **Both strategies run the same collection *kind* on the same cadence once both spaces are fixed points of the sizing rules** (`tests/production_dispatch.rs`): the nursery half is shared, so under a policy whose nursery is its own live-set target and whose mature region keeps every fullsweep's `need_after` inside its keep band, the copying and the mark-region run ask the same admission questions, run the same kinds, and answer the same `heap_info` field for field.
  The mature generations are otherwise differently sized (**987** vs **1 024** words at the default policy, `tests/steady_state.rs`), and a policy that lets either space resize can diverge in kind, because the mark-region space's line-granular accounting makes the two runs promote different word counts.

### The four points a space is freed or rewound (and the one contract they rest on)
- A term can only be invalidated **inside a collection**, and only at these sites: `Nursery::install_collapsed`'s `self.retired.clear()` (`src/nursery.rs:576`, frees every growth-retired space) and its `self.current = HeapSpace::with_allocator(alloc, target)?` (`src/nursery.rs:583`, frees the previous current space when the target differs — the equal-capacity branch `self.current.reset()` (`src/nursery.rs:580`) only rewinds the bump pointer, leaving the block mapped), `Collector::collect_major`'s `self.mature = fresh;` (`src/collector.rs:452`, frees the whole previous mature space) and `GenImmixCollector::relocate_major`'s `self.mature = fresh;` (`src/immix_collector.rs:858`), plus the dropped *trial* regions of the mark-region path (`promote`'s `WouldNotFit`, `grow_major`/`relocate_major`'s pre-checks), which were never installed.
  The free itself is `beam_alloc`'s (`Heap::drop` → `alloc.dealloc`, `../../beam_alloc/src/heap.rs:242-260`), so each site above hands the block back to the allocator — but whether the *pages* are unmapped is the allocator's answer, and by default they are not (see "Which of those sites unmaps and which merely recycles"): a stale word there reads garbage, or is re-aliased, and faults only on the dedicated-carrier-plus-cache-eviction path.
  `install_collapsed` frees the retired chain **before** it allocates the replacement current space (`nursery.rs:576-584`), so the fresh space is the first-fit candidate for the blocks just released and a stale pointer can end up naming the new current space's base and be overwritten by later allocations.
- **`Nursery::grow` frees nothing.** `Nursery::install` (`src/nursery.rs:501-511`) `core::mem::replace`s the current space into `retired` and `readopt_retired` only swaps two chain members, so the no-relocation growth seam never invalidates a term — only a collection does.
- Every free is legal only because the collection just rewrote each live root through `Copier`/`promote` over `roots: &mut [Eterm]`, and that walk reaches **only** what the caller's slice names: the crate takes no other sub-rootset (no x-register array, stack frames, dictionary, mailbox, saved args, engine arena or `beam_message` fragment), so a live term held outside the slice at a collection dangles.
  On the equal-capacity (reset) branch it reads **reused** words rather than an unmapped page — the mechanism by which a stale cons cell can still look like a cons cell and fault only on the next deref of a garbage cdr.
- **The off-heap walk rests on the same slice.** `for_each_reachable_binary_payload` descends what the roots reach and admits only addresses inside the collector's own from-set (`src/reachable.rs:122-124`), so a live `BinRef` in any foreign region (engine arena, `ReservedHeap` grid, pooled BIF heap, message fragment) is invisible, its payload looks dead, and the prune frees memory a live term names; the walk reports no under-approximation signal (`Ok(())`) — the decline guard is the *caller's* (`beam_rt`'s `Criterion::PayloadPrune` valve), not this crate's.
