# `beam_gc` — Per-Process Garbage Collector (Stage 4)

## Intent
Owns the **per-process collector** of the Rust ERTS rewrite: a **generational semi-space Cheney copying** collector over the per-process heap, the off-heap **refcounted large-object (MSO / refc-binary)** interface and the process **heap-size policy**.
It is **barrier-free by construction**: terms are immutable ⇒ *no term on the mature heap may refer to a term on the young heap*, so the mutator pays zero per-store overhead.
Reproduce the collector semantics of the legacy C (`../../../erts/emulator/beam/erl_gc.c` + `copy.c`) without its C structure; the design source is `../../ERTS_RUST_REWRITE_DEEPDIVE.md` §D and the Stage-4 row of §H.
Consumed by `beam_process`, which drives collections at safepoints (wave 1); it depends downward only on `beam_common`, `beam_term`, `beam_alloc` and `libc`.
Honours the crate-layer contracts of `../CONTEXT.md`: the root-set contract (no frame liveness maps), the frozen term layout (§2) and the return-based error strategy (§3).
MMTk/Boehm are **rejected**; GenImmix is a **measurement-gated** mature-generation option selected by the **measurement-derived automatic rule** (`selection.rs`) or an explicit pin.
**How it is built** — the design decisions, the collector-internal gaps, the observational-forensics rules, the handoff seams and the module-by-module routing — lives in `src/CONTEXT.md` (the implementation node).

## API Surface (the seam shape a dependent designs against)
Everything is re-exported at the crate root and via `beam_gc::prelude::*`.
**The rustdoc in `src/` is authoritative for every signature and its full contract** — this section gives names and the one-line semantic contract only.
- `space.rs` — `HeapSpace` (one copying semi-space over `beam_alloc::Heap`; `contains`/`contains_term`/`reset`/`base`/`top`/`limit`, capacity/used/available words; it **never reallocates**) and `FromSet` (the from-space ranges of one collection, kept sorted by `lo` so a per-reference `contains` is one binary search).
- `copy.rs` — the Cheney copy engine: `Copier` (`new`/`forward_roots`/`complete`/`run`) and `collect(from, to, roots)`; the `pub(crate)` evacuation primitives (`Target`, `EvacDest`, `forward_slot`, `move_size`, `for_each_ref`) are shared with `immix/`, the promotion driver and `live.rs`.
- `collector.rs` — `CollectionKind { Minor, Major }`, `Collection { kind, stats }`, and `Collector` (the young nursery **chain** + a mature `HeapSpace` + the `HeapPolicy`): `should_collect(need)` (occupancy-only), `collection_debt()`, `collect`/`collect_minor`/`collect_major`/`collect_kind(kind, roots)`, `ensure_capacity`/`grow_nursery`, `young`/`young_mut`/`mature`, `young_contains(ptr)`/`young_space_count()`, `stats`/`minor_gcs`, `for_each_reachable_object`/`…_view`, `scanned_bounds()`, `impl HeapObservable`.
  `collect` picks minor vs major and escalates a would-not-fit minor; `collect_kind` runs exactly the kind it is given and **never escalates**; a capacity pre-check returns the typed `heap_exhausted` *before* any copy.
- `live.rs` — the `pub(crate)` **exact-live counter** (`live`, `live_full`, `Live { words, lines }`): counts the exactly reachable from-set graph without mutating it, so a fullsweep can size itself from it.
- `reachable.rs` — `ReachableObject` (the public safe view: `header()`/`words()`/`word(i)`/`len()`/`address()`) over the `pub(crate)` read-only whole-heap walk (each reachable boxed object once, cons cells traversed but not reported, no forwarding marker).
- `immix/mod.rs` + `immix/collect.rs` — `ImmixSpace`: a line/block mark-region mature generation (`LINE_WORDS` 16, `LINES_PER_BLOCK` 16, `BLOCK_WORDS` 256), line-granular `alloc_words`, `mark`/`collect`, the `release_*` rollback primitives, `ImmixStats`/`ImmixCounters`, and its `EvacDest` impl.
- `immix_collector.rs` (+ `immix_collector/promote.rs`) — `GenImmixCollector`: the same copying nursery paired with an `ImmixSpace` mature and the same call set, plus `last_immix_stats()`; its minor promotes through the **atomic** two-phase driver in `promote.rs` (`promote`, `PromoteOutcome`).
- `any_collector.rs` — `AnyCollector { Copying, Immix }`: a **complete drop-in for the concrete `Collector`** (whole call set incl. `collect_kind`), `new`/`from_config`/`kind`/`mature_choice`/`heap_info`, plus mature **geometry accessors** (`mature_base`/`mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_contains`) because the two mature spaces are differently typed. Forwarding only.
- `config.rs` + `selection.rs` — the mature-generation decision: `GcConfig { policy, selection }` (`new`/`auto`/`copying`/`immix`/`growable`/`with_selection`/`with_mature`/`mature()`/`mature_choice()`), `MatureKind`, `MatureSelection { Auto, Explicit }`, `MatureSource`, `MatureChoice`, and the rule itself — `IMMIX_BREAK_EVEN_WORDS = 8 * BLOCK_WORDS` (2048), `IMMIX_BREAK_EVEN_BLOCKS`, `select_mature`, `mature_words_of`, `resolve_mature`, `choice_for`.
- `policy.rs` — `HeapPolicy`: `min_heap_words`, `max_heap_words` (0 = unbounded), `fullsweep_after` (65535), `min_bin_vheap_words` (46422 = the C `BIN_VH_MIN_SIZE`), `initial_young_words` (233), `initial_mature_words`, `need_reserve_words`; `default`/`from_min_max`/`unbounded`/builder, `initial_heap_words` (**the fresh-process nursery size**: `min_heap_words` when one is set — the C `sz = heap_need < min_heap_size ? min_heap_size : erts_next_heap_size(heap_need, 0)`, `erl_process.c:12586-12592` — else `initial_young_words`; **both collector constructors size their nursery with it**, so a new process's `heap_size` is exactly its `min_heap_size` and `+hms 100` really starts a 142-word heap, below the 233 seed), `spawn_policy(&global, min_heap, min_bin_vheap, fullsweep)` (a `spawn_opt` heap request floored against the **emulator's** policy — the C `H_MIN_SIZE`/`BIN_VH_MIN_SIZE` globals `erl_process.c:12321-12350`, not the 233/46422 constants; `from_spawn_opts` is `HeapPolicy::default().spawn_policy(…)`, so an unconfigured emulator is unchanged), `fullsweep_due`, the sizing rules (`next_words`, `size_after_fullsweep`, `mature_after_fullsweep`, `mature_target_words`, `need_after_fullsweep`, `young_target_words`, `young_minor_target_words`, `nursery_floor_words`, `young_after_collection`, `young_after_fullsweep`, `should_grow`, `should_shrink`), the **two live-set multiples** `YOUNG_TARGET_LIVE_MULTIPLE` (2, the fullsweep nursery rule; the minor rule is **one** times the young live set, the flatness-vs-amortisation choice) and `MATURE_TARGET_LIVE_MULTIPLE` (2, the mature rule — the one place the memory-for-amortisation trade is spent), the keep-band factor `YOUNG_SHRINK_FACTOR` (8), `DEFAULT_MIN_HEAP_WORDS`, `heap_sizes()`, `next_heap_size`.
  The nursery's post-collection capacity is a **live-set target**, never a function of the nursery's own capacity or of its pre-collection fill — one target per collection kind, and both collapse seams may grow *or* shrink onto it:
  a **fullsweep** uses `young_target_words(live) = next_words(YOUNG_TARGET_LIVE_MULTIPLE * live + need_reserve_words, 0)` = `next_words(2 * live + 64)` over the **whole-heap** live set (`young_after_fullsweep(capacity, live)` / `Nursery::collapse_after_fullsweep`: grow to the target, shrink back once the live set has fallen `YOUNG_SHRINK_FACTOR` times below it, else keep), because a fullsweep is the one collection that measures the whole live set exactly;
  a **minor** uses `young_minor_target_words(live) = next_words(live + need_reserve_words, 0)` = `next_words(live + 64)` over the **young** live set the round evacuated — its copy volume, `GcStats::words_copied` (`GenImmixCollector::run_minor` passes the words the promotion moved, the identical quantity, so both strategies collapse to the same capacity for the same live set). One times the live set: a young-only figure under-estimates the heap's whole live set, and the 2× copy-amortisation trade belongs to the fullsweep.
  `young_after_collection(capacity, young_live)` / `Nursery::collapse` **installs the target** when `capacity > YOUNG_SHRINK_FACTOR × target` (the live set fell far below what the nursery is sized for: give the memory back) or when `capacity < target` (enlarge onto it), and otherwise **keeps** the capacity. The **mature space's occupancy is never a minor's live figure**: a minor does not copy the mature generation, so it holds every garbage object the minors since the last fullsweep promoted, and a target derived from it follows the run's total promotion instead of its live set.
  `nursery_floor_words() = next_words(need_reserve_words, 0)` is a real **lower bound** on every capacity the policy installs, assertable by a dependent: `young_minor_target_words(live) >= nursery_floor_words()` and `young_target_words(live) >= floor` for **every** `live` (both go through the monotone `next_words` on an argument of at least `need_reserve_words`, and `young_minor_target_words(0) == nursery_floor_words()`), `nursery_floor_words() >= need_reserve_words` unless `max_heap_words` clamps it, and because the three-way rule installs the target whenever the capacity is below it, a collection can never leave a nursery below the floor. Figures: `HeapPolicy::default()` floor = **90** words; a spawn policy (`min_heap_words = DEFAULT_MIN_HEAP_WORDS`) floor = **233** words = `DEFAULT_MIN_HEAP_WORDS` = `young_minor_target_words(0)` (the figure `beam_rt`'s `COLLECTOR_FLOOR` pin reads); `HeapPolicy::default().initial_heap_words() == 233`.
  Every result is the capacity or the target, so both rules are **fixed points**, and the live-set target a collection derives is remembered (`Nursery::live_target_words`, recorded by *both* collapse seams) to cap the no-relocation `Nursery::grow` at `min(target, max(one_step, live_target))` with `one_step = next_words(need).max(capacity)`; a fresh nursery that has not collected yet has no live target and follows the plain curated growth rule (the `next_words` step, at least a doubling).
  The initial young space is **not** modelled on the C's `arg_size + S_RESERVED` heap need: a child's spawn arguments are copied in later and the heap grows on demand, so a spawn with a very large argument graph starts smaller than the oracle's. The visible consequence is the `-eval`/`-s`/`-run` action process, which the oracle spawns with the expression as its argument and therefore starts it at `erts_next_heap_size(heap_need, 0)` above the 233 minimum, while here it starts at its `min_heap_size`. Two probes are unaffected: a **fresh spawned process** (`spawn`/`spawn_opt` of a fun with no arguments) answers exactly the oracle's figure, and a `+hms` above the heap need dominates on both runtimes.
- `heap_info.rs` — `HeapInfo { minor_gcs, fullsweep_after, min_heap_size, min_bin_vheap_size, max_heap_size, heap_size, total_heap_size }` — the `erlang:process_info(Pid, garbage_collection)` item (`new`, `values()`, `items()`, `of(&collector)`); `HeapObservable` — `minor_gcs`/`heap_size_words`/`total_heap_size_words` (the **capacity** pair), `heap_used_words`/`total_heap_used_words` (the **occupancy** pair — chain-summed, so a space a `grow_nursery` retired keeps counting), `old_heap_size_words` (the mature capacity **once a collection has created that generation**, else `0` — the C `p->old_heap ? old_hend - old_heap : 0`, `erl_bif_info.c:1023-1030`), `heap_policy`, implemented by `Collector`, `GenImmixCollector` and `AnyCollector`.
  `GARBAGE_COLLECTION_KEYS` — the oracle's key order (`max_heap_size`, `min_bin_vheap_size`, `min_heap_size`, `fullsweep_after`, `minor_gcs`), defaults `0`/`46422`/`233`/`65535`.
  `heap_size` = the nursery capacity (C `HEAP_SIZE`); `total_heap_size_words` = nursery + mature capacity (the **accounting** figure `footprint.rs`/`erlang:memory` and the `max_heap_size` door read, so it is not the reported item); the reported `total_heap_size` composes the C's shape from `heap_size_words() + old_heap_size_words()`, which is why a fresh process answers `total_heap_size == heap_size`; the message buffer is `beam_message`'s.
  The runtime surfaces these itself — `beam_rt` builds `HeapInfo` directly (`HeapInfo::new` and `HeapObservable`) for `erlang:process_info(Pid, garbage_collection)` and `system_info(garbage_collection)`, in `GARBAGE_COLLECTION_KEYS` order (`beam_rt/src/native/memory/mod.rs`, `src/info/memory.rs`); `AnyCollector::heap_info()` itself is called only from tests — this module is the memory-accounting consumer's source of truth.
- `footprint.rs` — `HeapFootprint` (the one-call per-process account): `of(&collector, &off_heap)`, `capacity_words`/`used_words`/`capacity_bytes`/`used_bytes`, `heap_bytes` (**allocator-visible** = reserved capacity + live off-heap payload) and `total_bytes` (that + the off-heap roster's reserved slot array, which no allocator type records); module const `WORD_BYTES`. The `//!` doc states the three-way split (reserved capacity · live payload, **already counted by `erlang:memory(binary)`** — never add it to `processes` on top of `binary` · the roster array), and that it is a reserved-capacity + payload account, not an RSS estimate: no mailbox/queue bytes, no carrier retention beyond live payload, no runtime text/data. `tests/heap_accounting.rs` pins it (the `heap_bytes() <= Σ live_bytes` invariant is the honesty gate).
- `mso.rs` — `RefCount` (**re-exported** from `beam_alloc`, the workspace's single `erts_refc_*` primitive), `Mso`/`MsoHandle` (an off-heap immutable refcounted payload and its clonable owning handle), `OffHeapEntry { Mso, Binary }` (`overhead_bytes`/`apparent_size`/`as_mso`/`as_binary`) and `OffHeap` — the per-process list (`MSO(p)`), **slot-stable for its whole lifetime**: `push`, `insert -> slot`, `get`, `iter`, `len`/`is_empty`/`overhead_bytes`, the retained-array accessors `slot_count`/`slot_bytes` (the reserved slot array itself — retained footprint neither `overhead_bytes` nor any `beam_alloc` type reports), and `sweep(is_live) -> usize` releasing dead entries in place (never shifting, reordering, compacting or reusing a slot).
- `offheap.rs` — the **off-heap reclaim half** (the C `sweep_off_heap`): `for_each_reachable_binary_payload(collector, roots, visit)` (the read-only walk reporting the payload pointer of every reachable `BinRef`) and `sweep_unreachable_binaries(&mut OffHeap, collector, roots) -> Result<usize>` (drops every `OffHeapEntry::Binary` no reachable `BinRef` names, keeps every `Mso`, slot-stable, releases nothing on a walk error).
- `bin_vheap.rs` — the **trigger half** (the C `bin_vheap_sz`): `BinVheap { limit_words }` with `new(&HeapPolicy)` (floored at `min_bin_vheap_words`), `limit_words()`, `triggered(overhead_words)` (the C's strict `off_heap.overhead > bin_vheap_sz`), `triggered_for(&OffHeap)` and `record_collection(&HeapPolicy, surviving_overhead_words)` (the C `next_vheap_size` grow-at-1.618 / halve / hold rule).
  **An off-heap refc-binary roster is reclaimed by reachability (`offheap.rs`, the C `sweep_off_heap`) and triggered by the binary-virtual-heap rule (`bin_vheap.rs`, the C `ERTS_IS_GC_DESIRED_INTERNAL` `off_heap.overhead > bin_vheap_sz` clause)** — the two halves together are what make an off-heap-building loop flat in the number of calls; `beam_rt` drives both, per process, at its slice-boundary park (one `BinVheap` per process, the walk → `Machine::retain_refc_binaries`, the surviving figure republished through `Process::set_off_heap_binary_bytes`); see `src/CONTEXT.md`.
- `bounds.rs` — `ScannedBounds`: the covering interval of **every** live scanned region of a collector plus a monotone geometry epoch (`new`/`at`, `EMPTY`, `base`/`limit`/`generation`/`is_empty`, `may_contain`, `definitely_unscanned`, `span_words`); a **fast-REJECT filter, never a containment claim** (a false `may_contain` is harmless, a false reject would be a memory-safety bug), built from each space's **reserved** extent so a cached value cannot go stale, and consumed by `beam_rt`'s unscanned-root valve.
- `stats.rs` / `error.rs` — `GcStats { words_copied, words_reclaimed, objects_copied, minor_collections, major_collections }`; `error.rs` holds `pub(crate)` allocation-failure constructors only (no crate-local error enum).

## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only.
  Heap exhaustion while copying a term is `BeamError::Alloc(AllocFailure::new(AllocKind::Heap, bytes))` — never panic, never a crate-local error enum, never `unwrap()` on runtime data.
  `beam_term::TermError` is reconciled to `BeamError` upstream, so `?` crosses the boundary.
- **`unsafe` confinement:** production `unsafe` lives only in the word-level code — `copy.rs` (the Cheney copier), `immix_collector*` (the promotion driver), `reachable.rs` (the read-only whole-heap walk and its one-bit-per-word visited set), `live.rs` (the exact-live counter), `immix/` (the mark-region mark/evacuation walks) and the two narrow `NonNull`-deref / `Box::from_raw` blocks in `mso.rs`.
  Every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
  `space.rs`, `policy.rs`, `heap_info.rs`, `footprint.rs`, `stats.rs`, `bounds.rs`, `config.rs`, `offheap.rs`, `bin_vheap.rs` and the `Collector`/`GenImmixCollector`/`AnyCollector` driving logic are safe Rust.
- **Do NOT modify `beam_term` or `beam_alloc`** — build on their public APIs only.
  Do not touch `../../../erts/` (read-only ground truth) or `../../tools/`.
- **Never break the frozen term layout or the barrier-free invariant** (a minor must not leave a mature→young pointer).
- Files target ~1000 lines; split by responsibility.
- Licensing Apache-2.0; deps `beam_common`, `beam_term`, `beam_alloc`, `libc` only.

## Measured
Every figure, table and caveat is in **`MEASURED.md`**; this section keeps only the load-bearing headlines and the section to read them in.
- The `gc_bound/churn` shape allocates **806 words/op** against **0.201 collections/op** in-crate (0.167 minor + 0.034 major — one collection per five ops), copies **271.1 words/op = 0.336×** the allocated volume, and settles at a peak nursery of **4 185** words and mature of **10 958** (peak resident **15 143** words) — `MEASURED.md`, "Per-op attribution of the `gc_bound/churn` shape".
- A `perf` profile of that shape puts this crate's copy loop at **4.2 %** of samples (interpreter 20 %, libc malloc/free/memmove 15 %), so the dominant terms are the interpreted recursion and `beam_bifs`' `Vec` churn, not the copy loop (Handoffs in `src/CONTEXT.md`) — same section.
- The nursery follows **one live-set target**, so its capacity is a workload property rather than a leftover of the nursery's own fill: on the churn shape that is **7.5× fewer collections** (1.500 → 0.201/op) for **4.7× less copy work** (1 283.5 → 271.1 words/op) and **4.1× fewer objects copied** (425.01 → 103.40), paid for in resident words (peak nursery + mature 3 195 → 15 143) — `MEASURED.md`, "The nursery follows the live set — the live-set nursery target", with the rejected sizing variants in the same section.
- **The flatness-vs-amortisation trade, measured from the dependent runtime.** A minor's target is **one** times the young live set, so at a constant live set the nursery is *flat in N*: `beam_rt`'s constant-live-set probe (a 400-element tuple rebuilt every iteration, `process_info(self(), heap_size)` sampled every iteration, release runtime, four N values over 2 000 … 200 000) reads a min of **987** and a max of **830 667** on the native tier and **2 586** / **134 530** with `BEAM_RT_TIER=interpreter`, with the post-loop reading **610** = `young_minor_target_words(401)` on both tiers — the min is the installed capacity, the max is the chain-summed mid-burst figure (`beam_rt`'s probe, whose table is canonical there), and a *single* sample spans 2 586–830 667 so it is never the measurement. The same ratio on `beam_rt`'s `boundary_cost` fixture is **1.73 collections per iteration** for a **1 220**-word nursery carrying 1.5 iterations of allocation (1 220 / 806), its boundary door firing one collection per **7.06** checks at 0.452 checks/call. A larger minor multiple would amortise further and is excluded (it would move the converged capacity off the dependents' pin), so the 2× trade lives on the mature side (`MATURE_TARGET_LIVE_MULTIPLE`) — `MEASURED.md`, "The flatness-vs-amortisation trade".
- End to end on the release `beam_rt` `gc_bound` workload, three paired alternating rounds in a quiet window (load 1.3–3.9): **0.871×** on the per-op clock (**1.148×** speed-up; per-round 0.915 / 0.871 / 0.846 against a ±4 % A/B band) for **+0.3–0.4 MiB** peak RSS, moving the cross-runtime ratio against the system oracle from **18.75×** (m17) to **13.46×** — `MEASURED_M18.md` §4. The residual is **not** collection work: it is the interpreted loop, the per-heap-admission root walk and `beam_bifs` allocation churn (`../../BOTTLENECKS.md` §B1's `perf` profile, same caveat).
- **A collection's nursery capacity is the live set, and both runtime pins read it.** `beam_rt`'s boundary-door pin (`reds_door`, interpreter, sampled between slices) reports `heap_size` **610** at both N = 2 000 and N = 20 000 — `young_minor_target_words(401)`, one nursery space, 9 / 89 boundary collections, flat in N — and `slice_charging`'s interpreter control reports **233** = `young_minor_target_words(0)` = the spawn policy's `nursery_floor_words()`, as does every boundary-sampled row at N = 799 / 800 / 2 000 / 4 000 / 20 000. The same CLI probe (`native_reds:heap/1`) reads **233 flat in N** on the native tier, because the run fits in one slice and collects nothing. On the interpreter tier the process's *final* reading is a mid-burst sample — a chain of ~500 target-sized (610-word) spaces at N = 20 000, i.e. the slice's own allocation demand, which the next collection collapses back onto the live-set target; that space count is the residual cost of capping the growth seam at the live target. `MEASURED.md`, "The acceptance measurements: a collection's capacity is the live set" and "The CLI flatness probe and the burst residual".
- Against the **oracle** the rust process collects **more** often, because a minor's nursery is sized from the **young** live set (`young_minor_target_words`), which is small once the kept list has been promoted to the mature generation: **2.50×** the oracle's per-op collections on a small live set (2.616 vs 1.047 per iteration) and **18.0×** on a live-set-protected one (26.01 vs 1.446), at a final `heap_size` of 466–699 words against the oracle's 610 / 4 185 and node `memory(total)` **7.8–8.0 MB** against **34.9 MB** — `MEASURED.md`, "The cadence against the oracle (counts)".
  The `+hms` floor is a cadence lever: a floor above the live set cuts the count on both shapes (26 134 → 3 772 → 223 on `steady/1` and 260 007 → 38 035 → 2 225 on `live/1` at `+hms` 233 / 1 000 / 20 000, N = 10 000), and `beam_rt`'s `DEFAULT_HEAP_WORDS` sizes only its term-construction heaps, never a process nursery — a fresh `run` process reports `heap_size` 233 words against the oracle's 376.
- Folding the young heap's occupancy into the fullsweep's size request is what makes the mature generation reachable at the default policy, and `MATURE_TARGET_LIVE_MULTIPLE` (2) is what turns one promotion's room into a **run** of minors: the copying default runs **203 minors : 17 fullsweeps** (longest minor run 12, mature 987 words) — `MEASURED.md`, "The mature-generation room policy (generational cadence)".
- GenImmix wins **copy work on long-lived data** but pays footprint and pause on the small-heap/high-churn shape, so **`MatureKind::Copying` remains the default**; Immix is auto-selected at ≥ `IMMIX_BREAK_EVEN_WORDS` (2048, from the construction-time `initial_mature_words`) or by an explicit pin (`BEAM_RT_GC_STRATEGY=immix`) — `MEASURED.md`, "The long-lived break-even sweep" and "The two-axis selection curve".
- Under a fixed demand both capacities converge: nursery/mature **233/987** (total 1 220) for Copying and **233/1 024** (total 1 257) for Immix — `MEASURED.md`, "Heap-sizing measurements" (`tests/steady_state.rs`).
- Off-heap retention is measured as a **counter** contract, never a clock: with the trigger + the reachability sweep, `binary` live bytes and the roster length are identical at N = 500 and N = 1000 (flat in N), while the same loop with the sweep omitted retains one 64 KiB payload and one roster entry per call — `MEASURED.md`, the off-heap retention section, and `tests/offheap_retention.rs`.
- With the pair driven end to end, the **runtime's** off-heap retention is a capacity fix, measured on `emqx_base62:encode/1` (the unmodified EMQX module, identical `.beam`, release builds, paired interleaved rounds): `erlang:memory(binary)` **1 072 000 B at N = 1 000 → 10 720 000 B at N = 10 000** before the wiring — exactly **1 072 B/call**, the 1 024-byte payload plus a 48-byte off-heap header — and `VmHWM` 132.1 MB at N = 10 000 rising to **878.7 MB at N = 600 000**; after the wiring **272 288 B → 315 168 B** (+42 880 B over 9 000 extra calls, one-off heap growth rather than a per-call trend) with `VmHWM` flat at **119.8–119.9 MB** up to N = 600 000. The system oracle sits at ~21–32 KB on the same probe.
  The honest reading: this is a **capacity** fix, not a throughput one — the leaked payloads were unreferenced and never traversed, so the leak cost no measurable time (**post/pre ns/call 0.885**, bound 0.885–0.958 over two sessions). A memory figure is never latency evidence, nor the reverse.
  Ownership: the figure and its harness are `beam_rt`'s (`src/context/gc/bin_vheap.rs`, `tests/off_heap_reclaim.rs`); this crate owns the accounting model (`bin_vheap.rs`, `offheap.rs`) and the algorithm. The canonical benchmark table is `../../tools/bench/RESULTS.md`'s and is not restated here.
- The footprint's allocator-visible half sits at **0.99389×** of the allocators' summed `live_bytes` on the `tests/heap_accounting.rs` workload (2 010 072 B accounted against 2 022 432 B live; the pinned band is **[0.90, 1.00]**, heap capacity 47.5 % and off-heap payload 51.9 %, so neither half alone passes) — `MEASURED.md`, "The accounting band".

## Capacity growth — what feeds it, and where a capacity feedback can arise
Every `heap_size` / `total_heap_size` / `erlang:memory(processes)` / `max_heap_size` figure this crate publishes is a **chain sum**, never one space's capacity, and the chain is released only by a collection.
- `Nursery::capacity_words()` (`src/nursery.rs:225`) sums `current` **plus every space a no-relocation growth retired**; `HeapObservable::heap_size_words`/`total_heap_size_words` (`src/collector.rs:526,531`) forward it and `process_info(P,{total_heap_size,memory})`, the `processes` category and `MaxHeapUsage::heap_words` all read it. Each space is eagerly allocated at its full capacity (`HeapSpace::with_allocator` → `Heap::with_allocator`, `src/space.rs:51`), so the figure is reserved memory, not an occupancy.
- `Nursery::install` (`src/nursery.rs:426`) **retires** the space it replaces — nothing frees it outside `Nursery::collapse` (`src/nursery.rs:496`, `retired.clear()`). A growth whose installed `target` equals the current capacity therefore still adds a whole space to the chain sum: capacity-per-space and summed capacity are different quantities.
- `Nursery::grow` (`src/nursery.rs:334`) is the one capacity rule keyed on the **previous capacity**: `one_step = policy.next_words(need).max(capacity)`, and when that would not enlarge the space it takes `next_words(capacity * 2)`. The live-set cap `target.min(one_step.max(live_target))` applies only when `live_target_words` is `Some` — set **only by a collapse** (`install_collapsed`, `src/nursery.rs:505`) — so a nursery that has not collected since it last grew climbs the growth table on its own capacity.
- `Nursery::collapse` (`src/nursery.rs:465`) asks the policy with `collected_capacity = self.capacity_words()` (the **chain sum**) and `live_words = stats.words_copied` (exact). `HeapPolicy::young_after_collection`'s keep branch (`capacity ∈ [target, 8·target]`) then materializes that summed capacity as **one** space; its shrink branch (`capacity > 8·target`) is what bounds it.
- **The retained tail is freed by exactly one statement.** `Nursery::install_collapsed`'s `self.retired.clear()` (`src/nursery.rs:497`, with `retired_regions.clear()` beside it) drops the `HeapSpace`s and their `beam_alloc::Heap` `Drop` (`../../beam_alloc/src/heap.rs:242`) returns each block to the allocator. There is **no** `free_retired`/`shrink`/`reclaim` seam and `Nursery` itself is `pub(crate)` (`src/nursery.rs:108`, reachable crate-internally as `Collector::nursery`), so nothing outside `beam_gc` can release a provably-garbage retired tail without running a collection.
- **Of the growth/collection doors only a collection bounds the chain.** `grow_nursery` (`src/collector.rs:402`, `src/immix_collector.rs:480`) adds a link and reclaims nothing; `ensure_capacity` (`src/collector.rs:369`, `src/immix_collector.rs:447`) is the collecting growth API — it collects **then** grows, so the collection collapses the chain first and the growth starts from one space; `collect`/`collect_minor`/`collect_major`/`collect_kind` collapse the chain but must be asked for. A caller that only ever grows accumulates the chain until `max_heap_words` refuses.
- `Collector::collect_major` (`src/collector.rs:306`) and `GenImmixCollector::run_major` (`src/immix_collector.rs:656`) pass `young_occupancy = self.nursery.used_words()` — again the **chain-summed** occupancy — into `HeapPolicy::mature_after_fullsweep`, so the mature target is `next_words(MATURE_TARGET_LIVE_MULTIPLE × (live + young_occupancy + reserve))`. The convergence argument (this crate's docs and `tests/mature_capacity_convergence.rs`) rests on the young occupancy being bounded by a live-set-derived nursery capacity; a growth-retained chain breaks that premise.
- Forensic signature of a capacity feedback rather than a policy blow-up: a process's `minor_gcs` flat at 0 while its `total_heap_size` climbs — no collection reached it (only `ensure_heap`/`ensure_heap_full` OR `collection_debt`, and the unrooted `alloc_words` never collects; see `beam_rt/src/context/gc.rs`), so `live_target_words` stays `None`, the growth seam doubles, and the retained chain is what the reported figure accumulates.
- The invariants a monotonically growing capacity would violate are pinned by `tests/nursery_bounded.rs` (a settled capacity is a live-set target or the capacity it already had, never a third value), `tests/nursery_growth_retention.rs` ("a settled capacity is a function of the live set and never of the iteration count"; a grow + debt⇒collect loop keeps the chain at ≤1 retired space) and `tests/mature_capacity_convergence.rs`.
- **A collection-free growth loop ratchets the reported capacity, and it is exactly linear in the event count** — reproduced and measured by `tests/capacity_ratchet.rs`. After one collection the nursery's remembered `live_target_words` clamps a growth's fresh space to `target.min(one_step.max(live_target))` (`src/nursery.rs`); with `one_step == capacity` (any request smaller than the space) and `live_target <= capacity` that evaluates to the **current capacity**, so the seam discards its doubling fallback and installs a same-size space while the chain sum gains a whole capacity: `heap_size` **90 → 90 090 → 180 090 → 1 800 090 → 9 000 090** words at N = 1 000 / 2 000 / 20 000 / 100 000 events (90-word nursery, 32-word requests) and **233 → 160 033 → 1 598 233** at N = 100 / 1 000 (default 233-word nursery, the host's `GROW_MIN_WORDS`-floored 1 024-word request, which installs one 1 598-word table step and then repeats it). The same loop on an **uncollected** nursery (no remembered target ⇒ no clamp) climbs `610, 1598, 4185, 10958, 28690`, isolating the clamp as the cause; one collection collapses the chain back onto its live-set target. Three of the file's four assertions are red by design today (live-set-bounded and flat in the event count; strict progress per event); the collapse control is green. Also note the seam's own cost on that path: `Nursery::grow` scans the whole retired chain (`empty_retired_for`) on every call, so a growth loop that never collects is **O(N²)** as well as O(N) in stranded capacity (100 000 events ≈ 40 s per strategy).
