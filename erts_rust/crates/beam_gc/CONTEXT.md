# `beam_gc` — Per-Process Garbage Collector (Stage 4)

## Intent
Owns the **per-process collector** of the Rust ERTS rewrite: a **generational semi-space Cheney copying** collector over the per-process heap, the off-heap **refcounted large-object (MSO / refc-binary)** interface and the process **heap-size policy**.
It is **barrier-free by construction**: terms are immutable ⇒ *no term on the mature heap may refer to a term on the young heap*, so the mutator pays zero per-store overhead.
Reproduce the collector semantics of the legacy C (`../../../erts/emulator/beam/erl_gc.c` + `copy.c`) without its C structure; the design source is `../../ERTS_RUST_REWRITE_DEEPDIVE.md` §D and the Stage-4 row of §H.
Consumed by `beam_process`, which drives collections at safepoints (wave 1); it depends downward only on `beam_common`, `beam_term`, `beam_alloc` and `libc`.
Honours the crate-layer contracts of `../CONTEXT.md`: the root-set contract (no frame liveness maps), the frozen term layout (§2) and the return-based error strategy (§3).
MMTk/Boehm are **rejected**; GenImmix is a **measurement-gated** mature-generation option selected by the **measurement-derived automatic rule** (`selection.rs`) or an explicit pin.
How it is built — the design decisions, collector-internal gaps, forensics rules, handoff seams and per-module routing — lives in `src/CONTEXT.md`.

  The nursery's post-collection capacity is a **live-set target**, never a function of the nursery's own capacity or of its pre-collection fill — one target per collection kind, and both collapse seams may grow *or* shrink onto it: a **fullsweep** uses `young_target_words(live) = next_words(2 * live + 64)` over the **whole-heap** live set (`young_after_fullsweep` / `Nursery::collapse_after_fullsweep`), the one collection that measures the whole live set exactly; a **minor** uses `young_minor_target_words(live) = next_words(live + 64)` over the **young** live set the round evacuated — its copy volume, `GcStats::words_copied` (`GenImmixCollector::run_minor` passes the words the promotion moved, the identical quantity, so both strategies collapse to the same capacity). One times the live set for a minor: a young-only figure under-estimates the heap's whole live set, and the 2× copy-amortisation trade belongs to the fullsweep.
  `young_after_collection(capacity, young_live)` / `Nursery::collapse` **installs the target** when `capacity > YOUNG_SHRINK_FACTOR × target` (the live set fell far below what the nursery is sized for) or when `capacity < target` (enlarge onto it), and otherwise **keeps** the capacity. The **mature space's occupancy is never a minor's live figure**: a minor does not copy the mature generation, so it holds every garbage object the minors since the last fullsweep promoted, and a target derived from it would follow the run's total promotion instead of its live set.
  `nursery_floor_words() = next_words(need_reserve_words, 0)` is a real **lower bound** on every capacity the policy installs, assertable by a dependent: `young_minor_target_words(live) >= nursery_floor_words()` and `young_target_words(live) >= floor` for **every** `live` (both go through the monotone `next_words`, and `young_minor_target_words(0) == nursery_floor_words()`), `nursery_floor_words() >= need_reserve_words` unless `max_heap_words` clamps it, and because the three-way rule installs the target whenever the capacity is below it, a collection can never leave a nursery below the floor. Figures: `HeapPolicy::default()` floor = **90** words; a spawn policy (`min_heap_words = DEFAULT_MIN_HEAP_WORDS`) floor = **233** words = `DEFAULT_MIN_HEAP_WORDS` = `young_minor_target_words(0)` (the figure `beam_rt`'s `COLLECTOR_FLOOR` pin reads); `HeapPolicy::default().initial_heap_words() == 233`.
  Every result is the capacity or the target, so both rules are **fixed points**, and the live-set target a collection derives is remembered (`Nursery::live_target_words`, recorded by *both* collapse seams) to **narrow** the no-relocation `Nursery::grow` from above (§Capacity growth).
  The initial young space is **not** modelled on the C's `arg_size + S_RESERVED` heap need: spawn arguments are copied in later and the heap grows on demand, so a huge argument graph starts smaller than the oracle's — the visible case is the `-eval`/`-s`/`-run` action process, which the oracle sizes from the expression as its argument. Two probes are unaffected: a **fresh spawned process** with no arguments answers exactly the oracle's figure, and a `+hms` above the heap need dominates on both runtimes.

  **An off-heap refc-binary roster is reclaimed by reachability (`offheap.rs`, the C `sweep_off_heap`) and triggered by the binary-virtual-heap rule (the C `ERTS_IS_GC_DESIRED_INTERNAL` `off_heap.overhead > bin_vheap_sz` clause)** — together they make an off-heap-building loop flat in the number of calls; `beam_rt` drives both per process at its slice-boundary park (one `BinVheap` per process, the walk → `Machine::retain_refc_binaries`, the surviving figure republished through `Process::set_off_heap_binary_bytes`).
- `bounds.rs` — `ScannedBounds`: the covering interval of **every** live scanned region of a collector plus a monotone geometry epoch (`new`/`at`, `EMPTY`, `base`/`limit`/`generation`/`is_empty`, `may_contain`, `definitely_unscanned`, `span_words`); a **fast-REJECT filter, never a containment claim** (a false `may_contain` is harmless, a false reject would be a memory-safety bug), built from each space's **reserved** extent so a cached value cannot go stale, and consumed by `beam_rt`'s unscanned-root valve.
- `stats.rs` / `error.rs` — `GcStats { words_copied, words_reclaimed, objects_copied, minor_collections, major_collections }`; `error.rs` holds `pub(crate)` allocation-failure constructors only (no crate-local error enum).

## The allocation request (`need`) — why `ensure_capacity` does NOT carry one
The legacy C folds the pending allocation request into the next young block's size (`need_after = (HEAP_TOP(p) - HEAP_START(p)) + need + stack_size (+ S_RESERVED)`, `erl_gc.c:1503-1509`) so that a collection run *because* the mutator must allocate leaves that room behind. `HeapPolicy` carries the additive rule (`young_after_collection_with_need` and its three twins; the un-augmented forms are the `need == 0` cases) but **no collector calls it with a non-zero need**.
Why: `need_reserve_words` (64) already stands for the C's `need + S_RESERVED` inside the sizing rules, so folding the actual request in additively **double-counts** it (`next_words(64 + 64) = 142` where the rule's own figure is `next_words(64) = 90`); and because it makes the trailing `grow` a no-op, the growth seam's strict-progress step (which installed a two-request-wide space) never runs, so the nursery settles exactly **one** pending request wide — one collection per request instead of one per two on an admission shape. A measured fold cost the whole `beam_rt` boot 384 → 414 young collections and +0.44 % retired instructions.
A future attempt must therefore either subtract `need_reserve_words` from the request or keep the growth step's width, and must re-measure the boot collection count before it lands.

## What frees term memory (the root-set obligation)
Only a **successful collection** frees an Eterm-carrying region, and it frees it **unconditionally** — there is no check that the supplied root slice named every live term, and the crate has **no conservative/heap-scan mode** (every walk descends from `roots`: `reachable.rs::walk_reachable`).
- **The free sites.** `Nursery::install_collapsed` (`src/nursery.rs:575`) is the nursery's only free site: `retired.clear()` (`:576`, every growth-retired space) plus the old current space dropped at `:583` when the fold's target differs from its capacity (the equal branch `:580` is a bare `reset()` that frees nothing). It is reachable only from `collapse`/`collapse_after_fullsweep` (`:544`/`:561`), i.e. from `Collector::collect_minor`/`collect_major` (`src/collector.rs:361`/`:467`) and `GenImmixCollector::run_minor`/`run_major`/`relocate_major` (`src/immix_collector.rs:622`/`:723`/`:881`). A fullsweep also drops the old **mature** space (`src/collector.rs:452`) / mark-region (`src/immix_collector.rs:858`). Process death drops the whole `AnyCollector` (`../../beam_process/src/ptab.rs:2598`) — nursery chain and mature together. `HeapSpace` has no `Drop` of its own (`src/space.rs:37`); the release is `beam_alloc`'s `impl Drop for Heap` (`../../beam_alloc/src/heap.rs:242-260`).
- **A growth frees nothing and moves nothing.** `Nursery::grow`/`grow_nursery` (`src/nursery.rs:381`, `src/collector.rs:530`) only pushes the superseded `HeapSpace` onto `retired`: the memory stays mapped, every live word keeps its original address, `Nursery::contains` (`:261`) still answers `true` for it and `add_to_from_set` (`:274`) still evacuates it (`readopt_retired` at `:477` re-installs a provably empty space). A growth is therefore legal for a caller holding no root set, but it **moves the danger to the next collection**: a pointer the host never publishes dies at that collapse. `collection_debt` (`src/collector.rs:174`) is opt-in; a host must not carry unpublished terms across a `grow_nursery`.
- **No other release.** `OffHeap::sweep` (`src/mso.rs:356`) frees **no** Eterm region, and a **foreign-region compaction** (`Relocator`/`compact`) frees **nothing** — it copies out, rewrites the roots and reports `dest_words_used`, so the host owns both regions and must not release the source before every root slice has been forwarded and `complete` has returned.
- **Root-set completeness is the host's claim, and this crate never checks it.** `collect*`/`ensure_capacity`/`for_each_reachable_object{,_view}` take a flat `&mut [Eterm]` (there is no `RootSet` here); `collect_minor` copies (`src/collector.rs:339`) and *then* collapses (`:361`), so any live word the caller omitted is left pointing into a space freed two statements later. No post-collection verification, no debug assertion and no generation tag exists to catch that — the only defence is the host's unscanned-region valve (`ScannedBounds`, `src/bounds.rs`, a **fast-reject only**).
- **Recycling aliases a stale word onto a new space.** `FromSet::contains`/`locate` (`src/space.rs:189`, `:203`) are pure address tests and `Visited` (`src/reachable.rs:272`) is keyed by address: a freed region reused for a fresh `HeapSpace` makes an old word land inside a *live* `[base, top)`, so the copier forwards it as a live reference (`Target::Live`, `src/copy.rs:334-361`) and the walk admits it as an object — garbage sized from whatever header word sits there.
- **The walk trusts the header for size.** `move_size` (`src/copy.rs:70`) derives an object's word count from its header and `walk_reachable` only checks the *first* word is in a range (`src/reachable.rs:88`, `:103`), so the view's `from_raw_parts(ptr, total)` (`:220`) and `for_each_ref`'s `ptr.add(offset)` (`src/copy.rs:135`) are not bounded by the covering range's `hi`. Over a well-formed heap this never matters; over a conservatively-admitted garbage word it is an out-of-region read. Nothing here dereferences a cons cell through `beam_term::list::{car,cdr}`, and `Nursery::grow` never frees or moves a term (`Process::grow_nursery`, `../../beam_process/src/process.rs:1747`, adds only `record_max_heap_verdict`).
- **Freed memory reaches the OS only sometimes:** `HeapSpace` → `beam_alloc::Heap::drop` → carrier release → mseg reuse cache (default 10, `MAX_CACHE_SIZE` 30) → `munmap`. A **slab** block is merely returned to a free list with its carrier retained, so a stale pointer into a *small* freed space reads recycled words (silent corruption) while a *large* one (a compiler-sized nursery) is eventually munmapped (SIGSEGV).
**Consequence:** a stale word into a collapsed from-space is **not** a deterministic SIGSEGV — it is either unmapped (trap) or mapped and reusable by an unrelated allocation (silent garbage), so a change in allocation SIZE alone can flip a silent wrong answer into a fault. Soundness rests on the root set being complete, never on the free. The allocator's size routing and the recycling walk are in `src/CONTEXT.md`.

## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only.
  Heap exhaustion while copying a term is `BeamError::Alloc(AllocFailure::new(AllocKind::Heap, bytes))` — never panic, never a crate-local error enum, never `unwrap()` on runtime data.
  `beam_term::TermError` is reconciled to `BeamError` upstream, so `?` crosses the boundary.
- **`unsafe` confinement:** production `unsafe` lives only in the word-level code — `copy.rs` (the Cheney copier and the marker primitives), `relocate.rs` (the destination seam and the compaction driver), `immix_collector*` (the promotion driver), `reachable.rs` (the read-only whole-heap walk and its one-bit-per-word visited set), `live.rs` (the exact-live counter), `immix/` (the mark-region mark/evacuation walks), the two narrow `NonNull`-deref / `Box::from_raw` blocks in `mso.rs`, and `space.rs`'s one `unsafe` constructor (`FromSet::from_ranges`, which takes the caller's word-region assertion).
  Every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale; `unsafe_op_in_unsafe_fn` stays clean.
  `policy.rs`, `heap_info.rs`, `footprint.rs`, `stats.rs`, `bounds.rs`, `config.rs`, `offheap.rs`, `bin_vheap.rs` and the `Collector`/`GenImmixCollector`/`AnyCollector` driving logic are safe Rust.
- **Do NOT modify `beam_term` or `beam_alloc`** — build on their public APIs only.
  Do not touch `../../../erts/` (read-only ground truth) or `../../tools/`.
- **Never break the frozen term layout or the barrier-free invariant** (a minor must not leave a mature→young pointer).
- Files target ~1000 lines; split by responsibility.
- Licensing Apache-2.0; deps `beam_common`, `beam_term`, `beam_alloc`, `libc` only. Every `*.rs` file carries the OTP `%CopyrightBegin% … %CopyrightEnd%` Apache-2.0 header block (repo scanner: `ERL_TOP="$PWD" escript scripts/license-header.es scan --path erts_rust`).

## Measured
Every figure, table and caveat is in **`MEASURED.md`**; this section keeps only the load-bearing headlines and the section to read them in.
- The `gc_bound/churn` shape allocates **806 words/op** against **0.201 collections/op** in-crate (0.175 minor + 0.025 major — one collection per five ops), copies **271.1 words/op = 0.336×** the allocated volume, and settles at a peak nursery of **4 185** words and mature of **10 958** (peak resident **15 143** words) — `MEASURED.md`, "Per-op attribution of the `gc_bound/churn` shape"; `tests/churn_attribution.rs -- --nocapture` re-derives every figure and is byte-identical across runs. A `perf` profile of that shape puts this crate's copy loop at **4.2 %** of samples (interpreter 20 %, libc malloc/free/memmove 15 %), so the dominant terms are the interpreted recursion and `beam_bifs`' `Vec` churn, not the copy loop.
- **The reported capacity is live-set bounded, never a call-count ratchet.** A registered-BIF tail loop (`integer_to_list/1` whose argument rides a variable, so it cannot be folded) reports `heap_size` / `total_heap_size` = **609 / 609 words, flat over N = 1 … 30 000 000 calls** on the release `beam_rt`: 609 is not a growth-table entry (610 is) but the chain sum `233 + 376` the growth seam leaves behind, and `total_heap_size` equals `heap_size` because no collection created a mature generation on that shape. The pinned form of the same property is `beam_rt`'s `reds_door`/`slice_charging`: a figure read between slices is the chain sum at that moment, and a *smaller* N reading larger is the sampling point, not the workload.
- **The two A.9 sources that block on a naive compiler route compile in-process at a bounded capacity** (`compile:file/2` with `no_spawn_compiler_process` — the default spawns a compiler worker that never returns here): `lib/debugger/src/dbg_iload.erl` (48 353 B) → `{ok,dbg_iload,32980,warnings,0}` in 359.9 s on the tree's bootstrap compiler (where an unbounded nursery answers `error:system_limit`), and `lib/kernel/src/inet_parse.erl` (36 960 B) → `{ok,inet_parse,26588,warnings,0}` in 17.0 s with no `max_heap_size` cap and exit 0 (where it grows to a 590 M-word capacity and SIGSEGVs).

- **The flatness-vs-amortisation trade, measured from the dependent runtime.** A minor's target is **one** times the young live set, so at a constant live set the nursery is *flat in N*. Two of `beam_rt`'s pins read it, each figure the rule's own fixed point: `reds_door` converges on `young_target_words(1 201)` = **2 586** words at N = 2 000, 20 000 and 200 000 (a 100× range) — `young_target_words(1 201) = next_words(2 × 1 201 + 64)`, one nursery space, **8 / 84 / 849** boundary collections (**7 / 81 / 827** of them minors), flat in N — and 1 598 = `young_minor_target_words(1 201) = next_words(1 201 + 64)` is that capacity's keep-band lower edge (its upper edge is `8 × 1 598 = 12 784`), not the reading. The boundary window holds the **whole in-flight iteration**: `list_to_tuple(lists:seq(1, 400))`'s 400 cons cells (800 words) plus the 401-word tuple built from them, **1 201** words — which is why the live set is 1 201 and not the tuple's 401. `slice_charging`'s collected **native** rows sit on the **233**-word floor `young_minor_target_words(0)` because their boundary promotions are empty, while its **interpreter** control reads the phase-dependent mid-burst figure — **190 104** words at N = 2 000 and **312 394** at N = 20 000 — because those rows are pre-empted and end the loop inside a burst. The CLI probe (`native_reds:heap/1`) reads **233 flat in N** on the native tier, because the run fits in one slice and collects nothing.
  The churn fixture settles its young space at **2 585** words — a **chain sum materialised into one space** by `young_after_collection`'s keep branch, `2 585 = 987 + 1 598`, inside the keep band `[376, max(3 000, 8 × 376 = 3 008)]` around its own 376-word minor target (`young_minor_target_words(238) = next_words(238 + 64)`), i.e. 3.2 of its 806-word iterations — and its mature region at **4 185** words, at **2.6522 / 2.6861 / 2.7109 collections per call** over its **2 001 / 4 001 / 10 001** calls (N = 2 000 / 4 000 / 10 000), its boundary door firing one collection per **8.86 / 9.40 / 9.96** checks at **0.1949 / 0.1950 / 0.1952 checks per call**. ## Capacity growth — what feeds it, and where a capacity feedback can arise
Every `heap_size` / `total_heap_size` / `erlang:memory(processes)` / `max_heap_size` figure this crate publishes is a **chain sum**, never one space's capacity, and the chain is released only by a collection.
- `Nursery::capacity_words()` (`src/nursery.rs:247`) sums `current` **plus every space a no-relocation growth retired**; `HeapObservable::heap_size_words`/`total_heap_size_words` (`src/collector.rs:654,659`) forward it and `process_info(P,{total_heap_size,memory})`, the `processes` category and `MaxHeapUsage::heap_words` all read it. Each space is eagerly allocated at full capacity, so the figure is reserved memory, not an occupancy. `Nursery::install` (`src/nursery.rs:501`) **retires** the space it replaces — nothing frees it outside a collapse — so capacity-per-space and summed capacity differ, and every link is strictly larger than the one behind it.
- `Nursery::grow` (`src/nursery.rs:381`) is the one capacity rule keyed on the **previous capacity**, and it **always installs a space strictly larger than the one it retires**: `one_step = policy.next_words(need).max(capacity)`, `next_words(capacity * 2)` when that would not enlarge, the remembered live-set bound narrowing that choice from above (`min(target, max(one_step, live_target))`), and then — **last, so nothing above can defeat it** — `max(target, HeapPolicy::next_words_above(capacity))`. The live-set bound (set **only by a collapse**) can therefore only *narrow* the choice, so the chain never stacks equally sized spaces. The only refusals are the two ceilings a larger space could not honour either — the growth table's limit and `capacity_words() <= max_heap_words` — both returned as the typed `error::heap_exhausted` **before** anything is allocated or retired, leaving the nursery byte-for-byte unchanged with `collection_debt()` untouched. A fresh nursery has no live target and follows the plain curated growth rule.
- **A collection, not the growth seam, bounds the retained capacity, and it is the only thing that does.** `Nursery::collapse` (`src/nursery.rs:544`) asks the policy with `collected_capacity = self.capacity_words()` (the **chain sum**) and `live_words = stats.words_copied` (exact): `young_after_collection`'s keep branch (`capacity ∈ [target, 8·target]`) materializes it as **one** space, and its shrink branch (`capacity > 8·target`) bounds it. `install_collapsed`'s `self.retired.clear()` (`src/nursery.rs:576`) is **the one statement** that frees the retained tail; there is **no** `free_retired`/`shrink`/`reclaim` seam and `Nursery` is `pub(crate)` (`src/nursery.rs:111`), so nothing outside `beam_gc` can release a provably-garbage retired tail without a collection. Of the doors, `grow_nursery` (`src/collector.rs:530`, `src/immix_collector.rs:480`) adds a link and reclaims nothing while `ensure_capacity` (`src/collector.rs:497`, `src/immix_collector.rs:447`) collects **then** grows; the seam never refuses a growth to *bound* the chain, because a caller holding no root set cannot collect and a refusal is not a bound — a runtime that absorbs it keeps the words elsewhere. `collection_debt()` reports the chain so the caller can collect.
- `Collector::collect_major` (`src/collector.rs:383`) and `GenImmixCollector::run_major` (`src/immix_collector.rs:635`) fold the young heap's occupancy into `HeapPolicy::mature_after_fullsweep` **clamped** to the capacity the collapse is about to install: `young_occupancy = nursery.used_words().min(young_after_fullsweep(nursery.capacity_words(), live))`, so the mature target is `next_words(MATURE_TARGET_LIVE_MULTIPLE × (live + young_occupancy + reserve))` — a function of the **live set** alone. `Nursery::used_words()` is chain-summed, so unclamped it also counts every word the mutator (or a host's unrooted BIF copy-out) has abandoned since the last collection, and a dead figure folded in is the one feedback no collection can pay back (the next fullsweep measures it again). The clamp keeps the term's purpose — a whole nursery's worth of promotion room, so a *run* of minors follows a fullsweep — bounded by `YOUNG_SHRINK_FACTOR × young_target_words(live)`.
- **Forensic signatures.** (1) `minor_gcs` flat at 0 while `total_heap_size` climbs: no collection reached the process (only `ensure_heap`/`ensure_heap_full`/the park arm/`reds_door` OR `collection_debt` — the unrooted `alloc_words` never collects; `beam_rt/src/context/gc.rs`), so `live_target_words` stays `None`, the growth seam climbs its table and the retained chain is what accumulates. (2) `heap_size` flat while `total_heap_size` climbs: that half is the **mature** capacity, and because both of its inputs are live-set functions such a climb means the **live set itself** is growing — a mature capacity tracking a dead occupancy is a rule reading `Nursery::used_words()` unclamped. The reported figure is *visible*, not hidden: the plain candidate is `next_words(2 × capacity)` (`src/nursery.rs:396-402`), so a chain sums to under ~2× its current capacity and is `O(log)` long, and a large `processes` against a much smaller `processes_used` is the retired-chain signature (a retired space's `used_words` still counts in `heap_used_words`, while `processes_used` reads `young().used_words()` — the hole in `src/ACCOUNTING.md`). A reported total far **below** RSS points the other way: at bytes no key counts (the runtime's pointer-stable arena, pooled BIF scratch heaps, retained `Module` IR, the JIT block cache — `src/ACCOUNTING.md`, "Categories this crate cannot see").
- **A nested/blocking run never collapses the chain, and a collection-free growth loop is bounded by the caller's cadence, not by its own event count.** `Nursery::collapse` has exactly two production callers (`src/collector.rs:361`, `src/immix_collector.rs:622`) plus the two `collapse_after_fullsweep` sites, all inside a collection, so a host that declines every collection in a window (e.g. `beam_rt`'s relocation-exempt blocking `compile:file/2` pump) keeps the spaces its `grow_nursery` retirements created alive until the next slice collects — `collection_debt` is a real retained allocation for that whole window. A growth always makes strict progress, so the chain is `O(log)` spaces and its sum is bounded by the words actually installed, but a nursery that is **never** collected still grows with its allocation: that is the honest residual and the fix belongs to the caller (the C answers it by collecting — `delay_garbage_collection` sets `F_FORCE_GC`, `erl_gc.c:500-599`). `Nursery::empty_retired_for` (`src/nursery.rs:456`) re-adopts the smallest adequate provably-empty space from the `empty_retired` index in `O(log #spaces)`, so a 50 000-event growth loop completes in milliseconds.
The tests that pin all of the above are in §Test Strategy; the refused sizing variants and measured capacity rows are in `MEASURED.md`.

## Foreign regions — the relocating compaction surface
The walk and the copy are both **region-generic and public**: a region need not be a process heap, so a host can compact its own word area (a `beam_alloc::ReservedHeap`, a pre-reserved `Vec<Eterm>`, an mmap'd arena, `beam_engine`'s term arena) without a `Collector`, a `Nursery` or a `HeapSpace`. Naming the regions (`FromSet::from_ranges`) and flattening the roots remain the owner's job.
Production posture: the **engine side hosts this surface** — `beam_engine`'s Tier-B `MinimalContext::reclaim_heap`/`reclaim_heap_with_capacity` (`beam_engine/src/context/reclaim.rs`) drives `FromSet::from_ranges` + `LinearDest` + `Relocator::new_checked` + one `forward_roots` per root slice (the machine's root families come from `Machine::for_each_root_mut`), depositing the copies **straight into the survivor region** because the relocator bakes each child slot's address in at copy time (a scratch destination would leave the survivor's interior pointers dangling). `beam_rt` still declines any collection that reaches an engine-arena word (`beam_rt/src/context/gc_walk.rs`), so this surface remains the foundation for bounding its two unbounded regions (the `-eval` store's retired chain and the engine arena).
- **From ranges.** `unsafe FromSet::from_ranges(&[(base_address, used_words)])` — its `# Safety` list is the load-bearing part: each base word-aligned, its byte extent readable **and writable** (a copier forwards in place), `used_words` a **prefix of a real live allocation** (an over-stated extent rewrites words no term owns, an under-stated one strands live terms outside the evacuation), the ranges pairwise disjoint, no other thread freeing/reallocating/mutating those words during a copy, and **completeness** (no live term outside the ranges) as the caller's claim — exactly the claim a root slice already carries. Alignment and disjointness are `debug_assert!`s, so a release build trusts the caller; enumerating a region grid is the owner's job too (`Heap` and `ReservedHeap` share no trait; `beam_engine` exposes `MinimalContext::for_each_heap_region`).
- **Destination.** `EvacDest` (+ `Target`) is the public seam: a host's region type becomes a destination by implementing `classify_boxed`/`classify_cons`/`can_reserve`/`reserve` and declaring walkability with `copied_top() -> Option<*mut Eterm>` — `Some` means copies land in one contiguous run advancing monotonically in reservation order (what the Cheney destination scan requires); the default `None` declares the destination unwalkable (the honest answer for the line-granular mark-region space, which keeps its own driver), and `Relocator::new` refuses it with `BadArg` before any copy. `LinearDest` is the turnkey impl, so a host never reimplements the forwarding-marker protocol; the marker primitives stay `pub(crate)`.
- **Driver.** `Relocator::new`/`new_checked` → `forward_roots(&mut [Eterm])`, callable **once per root slice**: what makes a scattered root set correct is **idempotence** — a rewritten slot names the destination, which the destination classifies `Foreign`, so a repeat call over the same slice copies and rewrites nothing → `complete()`, the Cheney scan of the destination → `Relocation { stats: GcStats, dest_words_used }`. `dest_words_used == stats.words_copied` for a linear destination, i.e. the live length of the host's new region; **trimming and releasing that region is the host's**, since nothing here frees a foreign region.
- **Walking a foreign region read-only.** `live_words_in(&FromSet, &[Eterm]) -> usize` is the exact copy volume (hence the right `required_words` for `new_checked`) and `for_each_reachable_in(&FromSet, &[Eterm], visit)` is the same walk; both are thin wrappers over the one walker (`walk_reachable`) and the one counter (`live`). The walk reports **boxed** objects (cons cells are traversed but not reported), so its count reconciles with `objects_copied` by `boxed_words + 2 × cells`.
- **Failure semantics — what a host must plan for.** `new`/`new_checked` mutate nothing: a too-small destination is the typed `heap_exhausted` (`BeamError::Alloc` with `AllocKind::Heap`) and an unwalkable destination is `BadArg`. A `heap_exhausted` raised *inside* `forward_roots`/`complete` leaves the source **partially forwarded** — some objects hold forwarding markers, some roots are rewritten — which is not recoverable, so the two sound patterns are `compact` (one root slice, atomic) and `live_words_in` over every slice → `Relocator::new_checked(from, dest, total)` → one `forward_roots` per slice → `complete`. Summing `live_words_in` over **overlapping** slices over-estimates, which only refuses conservatively.
- **Still absent, by design:** a root-set trait (the root contract is a flat `&mut [Eterm]`, so flattening a host's scattered roots is its own job — `beam_engine::context::RootSet`, `x`/`stack`/`fr`, is already that shape); a conservative (word-by-word) scan — every walk descends from exact roots and sizes each object from its header, so a word that merely *looks* boxed is never treated as an object start (a fabricated start could yield a garbage size and an out-of-region read; this is also why `ImmixSpace` allocates line-aligned); a mark bitmap or free-list over an arbitrary address range (the walk's `Visited`, one bit per from-set word, is the natural seed); and any region *enumeration* (`beam_engine → beam_gc` would be a legal downward, acyclic wave-4 → wave-1 edge).
- `for_each_reachable_binary_payload`/`sweep_unreachable_binaries` still see only a collector's own spaces, so a refc-binary payload named *only* from a foreign region is a false reject for them — and a false reject frees a live payload; a host that compacts a foreign region but sweeps payload liveness must contribute that region's roots itself.
- Per-word predicates that **do** exist: the tag test (`primary_tag`/`is_boxed`/`is_list`/`is_term_word`) plus a containment test (`FromSet::contains`, `HeapSpace::contains{,_term}`, `ImmixSpace::contains`, `AnyCollector::young_contains`/`mature_contains`, and `ScannedBounds::may_contain` as a sound fast-**reject** only).
- The **shape requirement differs between the walk and the copy**: the walk descends from roots and never scans a range linearly, so a from-set need not be a dense object chain (holes are never visited; `words_reclaimed` counts them as reclaimed), while the *destination* must be one dense contiguous run scanned `while scan < dest.copied_top()`, and the source must be handed writable words (the marker is written into the evacuated object).

## Test Strategy
- Per-crate in-module `#[cfg(test)]` unit tests plus a `tests/` integration suite; **each integration file's `//!` module doc states the contract it pins and why**.
- The suite is organised around six invariants (exact copy correctness per term shape; generations/cadence/sizing; the nursery chain; the aggregate scanned bounds; Immix; off-heap reclaim), plus cross-cutting adversarial coverage — the per-file map and the mutation-verified cases live in `src/CONTEXT.md`.
- Four gates cover the capacity-feedback and escalation family: `tests/capacity_ratchet.rs` (no door but a collection bounds the retained capacity), `tests/mature_capacity_feedback.rs` (the mature capacity is flat in the dead young occupancy; consecutive fullsweeps are a fixed point), `tests/escalation_bound.rs` (a dead-inclusive fill keeps selecting minor, a genuine over-capacity live promotion escalates, `collect_kind(Minor)` refuses before copying) and `tests/minor_room_upper_bound.rs` (`minor_room_words` is a tight upper bound: exactly `W` words admit the minor, `W - 1` is the typed refusal).
