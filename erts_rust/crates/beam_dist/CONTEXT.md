# `beam_dist` — Distribution Protocol (v6) + `epmd` Client

## Intent
Owns compatibility contract **A.5** (*distribution/ETF wire*) at the *protocol/value* layer plus the Stage-0 foundations of Part II §H: the connect/challenge handshake and its MD5 authentication, capability (`DFLAG_*`) negotiation, control-message (`DOP_*`) framing + term payloads, message fragmentation/reassembly, the distribution atom cache, the packet-length framing, the distribution-header envelope, and the `epmd` port-mapper client.

The core is **pure protocol/value code over the abstract `transport` seam** — the codecs never open a socket.
`connection` adds a concrete `std::net::TcpStream` adapter (`TcpTransport` + `TcpListener`) plus the blocking `Connection`, and drives a live link end-to-end (epmd lookup → handshake → `DOP_*` exchange).
`driver` adds the non-blocking `ConnectionDriver` (a poll/step state machine over a byte-fed buffer) so a runtime can multiplex many links on one thread.
Both are live-tested against a real `erl` node; the runtime's production transport is `beam_io`'s.

Term encoding/decoding is **never re-implemented here**: every term crosses the wire through `beam_codec` (ETF).
This crate owns only the *distribution-specific* wire: the flag/opcode vocabulary, the handshake state machine, the length framing, the header envelope, fragmentation, and the atom cache.

Dependents: `beam_rt` (node startup `-name`/`-sname`, both distribution halves, `system_info(dist)`), `beam_io` (transport).

Ground truth (read-only, never modified); **all byte values, tag bytes and field orders are wire-frozen** (A.5) — reproduce them exactly:
`erts/emulator/beam/dist.h` + `dist.c` (`DFLAG_*`, `enum dop`, the mandatory/default/rejectable flag sets, the control-tuple dispatch, `invalid_message`/`decode_error` → `erts_kill_dist_connection`) · `external.c` + `external.h` (the dist-header encode/fragment/finalize, the atom cache, `dec_is_this_node`, `'D'`/`'E'`/`'F'`, the cache sizes) · `packet_parser.c` (length framing; a tick is a zero-length packet) · `erts/doc/guides/erl_dist_protocol.md` + `erl_ext_dist.md` · `lib/kernel/src/dist_util.erl` (`gen_digest/2`, `check_dflags`, `mark_pending`) · `lib/erl_interface/src/{connect,epmd}/*.c` · `erts/epmd/src/epmd_srv.c`.

## Status
**Implemented and live-verified:** the `DFLAG_*`/`DOP_*` vocabulary, the transport seam, 2-/4-byte framing, the handshake codecs + MD5 authentication, the byte-exact distribution header, fragmentation/reassembly, the inbound and outbound atom cache, the control-message codec (all 30 `Dop` variants), inbound delivery classification (plain and per-link validated), the `epmd` client over real TCP, the blocking `Connection`, the non-blocking `ConnectionDriver`, and the `src/bin/dist_probe.rs` loopback CLI.
Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_dist` is green; the workspace builds warning-free; the crate is `#![deny(unsafe_code)]`.

**Wire facts pinned by the suite.** All 30 `Dop` opcodes round-trip exhaustively (encode → decode → byte-identical re-encode) with a byte-exact golden vector each, cross-checked against the system `erl` oracle (`term_to_binary/1` of the equivalent tuple, `VERSION_MAGIC` stripped).
There is **no** `DOP_NODEUP`/`DOP_NODEDOWN` in v6 (node up/down are *local* emulator events, `dist.c:6931`), and no `DOP_DEMONITOR_ID`/`DOP_UNLINK_MONITOR_ID`/`DOP_DEMONITOR_MONITOR_ID`; `Dop::from_u8` accepts exactly 30 values and rejects `0, 5, 9-11, 14-15, 17, >= 38`.
`control::carries_message` names the 16 opcodes carrying a trailing **Message** term (the 9 send family + the 5 payload-exit family + `SPAWN_REQUEST`/`_TT`); `SPAWN_REPLY`/`_TT` are excluded (`dist.c:1897` sets `ctx->msg = THE_NON_VALUE`).
`DOP_ALTACT_SIG_SEND` is the one **variable-arity** opcode (`tuple_arity >= 4`, `dist.c:2625`).

**Live interop with a real `erl` node** — blocking `Connection`, non-blocking `ConnectionDriver`, and this crate as handshake **server**: `DOP_REG_SEND` both ways, `DOP_SEND(_SENDER)`, a monitor round-trip (`DOP_MONITOR_P` → `DOP_MONITOR_P_EXIT`), a client-originated `DOP_MONITOR_P` (the peer kills the watched worker; `DOP_PAYLOAD_MONITOR_P_EXIT` decoded with all four fields), `DOP_EXIT2`, an outbound `DOP_UNLINK_ID` carrying a non-zero id answered by the peer's `DOP_UNLINK_ID_ACK` (this crate writes the request and consumes the ack; it emits no ack — see Known Issues), and fragmented >`DIST_FRAGMENT_SIZE` messages in both directions with `'E'`/`'F'` frames recorded on the wire.
The server-side round trip requires the pid's node name to be the **full `node@host`** (a bare short name is refused) and the creation to be the **epmd-assigned** `Alive2Resp::creation()`, threaded into both the driver and the pid; peer visibility is proven in both directions through the `publish_flag` override.
**Hermetic (no `erl`, no `epmd`):** `tests/two_node_loopback.rs`, `tests/two_node_session.rs`, `tests/hermetic_epmd.rs` — per-suite claims in `tests/CONTEXT.md`.

**The outbound atom cache is wired end-to-end.** `OutboundAtomCache` implements `beam_codec::AtomCacheWriter`, `encode_control_cached` threads it through one `Encoder` per control message, and both `Connection::send_payload` and `ConnectionDriver::send_control` emit the real `take_header()` header: an atom-bearing payload writes `ATOM_CACHE_REF` (`82`) + index and the header teaches/re-uses those refs; an atom-free message emits exactly `131, 68, 0`.

**`epmd` over real TCP** covers the complete request set — `ALIVE2_REQ`/`_RESP`/`_X_RESP`, `PORT2_REQ`/`_RESP` (alias `PORT_PLEASE2_REQ`, same wire byte `'z'`), `NAMES_REQ`, and the interactive `DUMP`/`KILL`/`STOP` — with a live publish / second-connection lookup / de-registration / `DUMP` round trip; `connect_to_node` chains epmd lookup → TCP connect → handshake; `not_registered` ⇒ `Io(NotFound)`, never a silent port `0`.

**The handshake error path is typed.** `Status::kind()` classifies the peer's status text into `StatusKind { Ok, Simultaneous, Named, Nok, NotAllowed, Alive, Other }` and the single shared `handshake::status_error(&Status)` maps it (`Nok` → `ConnectionRefused`, `NotAllowed` → `PermissionDenied`, `Alive` → `ConnectionAborted`, `Named` → `AlreadyExists`, `Simultaneous` → `ConnectionAborted`, unknown → `InvalidData`; `no_creation`/`system_limit` are not status texts in this release and land in `Other`).
A refusing acceptor frames+flushes the status to the peer (the exact 14 bytes `snot_allowed`, `dist_util.erl:286`) before returning the error; a refusing connector just aborts.

**The acceptor can refuse** through the defaulted `AcceptDecision` seam (`accept_server_with_decision`, `Connection::server_with_decision`, `ConnectionDriver::server_with_decision`), consulted with the peer's decoded `Name` **after** the mandatory check: `Ok` is the default (byte-identical `sok`), `Refuse(status)` writes that status (`nok`/`alive`/`not_allowed`) framed+flushed before returning `status_error(&status)`, on both the blocking and the non-blocking path. The *decision source* is the caller's (see Known Issues).
**Node visibility** is the per-connection `publish_flag` piece: `publish_flag(hidden, published)` / `publish_type(flags)` read `DFLAG_PUBLISHED`, ORed into the opt-in `*_with_flags` seams. The dynamic-name branch (`DFLAG_NAME_ME`) is deliberately **not** modelled — this crate speaks only the static OTP-23 `'N'` name.
**The in-term flag vocabularies** are complete and decoded: `DIST_SPAWN_FLAG_LINK`/`_MONITOR`, `DOP_ALTACT_SIG_FLG_PRIO`/`_TOKEN`/`_ALIAS`/`_NAME`/`_EXIT` (value-pinned from `dist.h:185-192`) via the typed `DistSpawnFlags`/`AltactSigFlags`, carried by the `SpawnRequest`/`SpawnReply`/`AltactSigSend` deliveries.

### `src/transport.rs` — the abstract transport seam
`trait Read`/`trait Write` (big-endian helpers) + blanket `trait Transport`; `MemoryTransport` is the full-duplex in-memory test double.
`Read::read_exact_or_eof(buf) -> Result<bool>` is the **frame-boundary seam**: `Ok(true)` filled, `Ok(false)` on a clean end of stream **before any byte was read**, `BadArg` when some bytes arrived but `buf` was not filled (the default delegates to `read_exact`).

### `src/fragment.rs` — fragmentation: `'E'` header, `'F'` continuation

### `src/atom_cache.rs` — the distribution atom cache / segments
Addressing `ENTRIES_PER_SEGMENT` (256), `ATOM_CACHE_SIZE` (2048), `USE_ATOM_CACHE_SIZE` (2039), `slot_index`, `atom_to_cix(atom)`.
`SegmentCache` — the persistent 2048-slot 8×256 store (`get`/`set`/`clear`/`occupied`); receive side `apply_header(&DistHeader, &mut SegmentCache, &mut beam_codec::AtomCache)` + `ReceiveAtomCache`; send side `OutboundAtomCache` (`ref_for`/`payload_index`/`payload_ref_for`/`header`/`take_header`/`advance_segment`/`clear`), classifying atoms `New`/`Cached` and yielding `payload_ref_for`'s `[82, index]`.
**`impl beam_codec::AtomCacheWriter for OutboundAtomCache`** (`intern` = `ref_for` + `payload_index`) — the hook `Encoder::with_atom_cache` calls so the encoder emits `[82, index]` instead of the inline atom name.

### `src/control.rs` — the `DOP_*` control-message codec (wire-exact)
The control message is an ETF **tuple** (`SMALL_TUPLE_EXT`/`LARGE_TUPLE_EXT + arity + element_1 …`), `element_1` the opcode as a `SMALL_INTEGER_EXT`; for message-carrying opcodes one trailing **Message** term follows in the same body. No leading `VERSION_MAGIC` (the distribution header carries it).
`ControlMessage { dop, terms }` — *flattened* (control args, then the trailing message); `carries_message(dop)`; arity is exactly `Dop::arity` except the variable-arity `DOP_ALTACT_SIG_SEND`.
`encode_control_cached(dop, terms, atoms, Option<&mut dyn beam_codec::AtomCacheWriter>)` + the cache-less `encode_control`: opcode, control args and message go through **one** `Encoder::new_body(atoms)` so a supplied cache sees every atom in payload order (= header ref order); arity is caller-driven, like the C encoder.
`decode_control(body, &mut Heap, &mut AtomTable, Option<&AtomCache>)` — unknown opcode / wrong arity / malformed tuple / trailing bytes ⇒ `BadArg`; term decoding is **only** `beam_codec`; it equals `decode_control_with_identity(…, None)`.
`decode_control_with_identity(body, heap, atoms, cache, Option<LocalIdentity>)` — the **single identity-aware decode funnel**: with an identity installed an external pid/port/reference whose node **and** creation are this node's decodes to the **internal** term (the C's `dec_is_this_node`, `external.c:3123-3129`), in the control arguments **and** the trailing message. It is the only place the crate installs `beam_codec::Decoder::with_local_node`.
`LocalIdentity { node: Atom, creation: u32 }` + `LocalIdentity::intern(&mut AtomTable, sysname, creation)` (non-UTF-8 ⇒ `BadArg`); `node` is this node's full wire name (`name@host`, `ErlNode.sysname`) interned in the **same** table the body decodes against — a foreign-table atom is inert (no demotion, never a wrong match).

### `src/delivery.rs` — inbound `DOP_*` classification + the `InboundSink` seam
`Delivery` classifies **all 30** opcodes: the 9-opcode send family (incl. `AliasSend`/`RegSend` with token), link/exit/`Exit2`, `UnlinkId`/`UnlinkIdAck`, monitor/demonitor/`MonitorExit`, `GroupLeader`, the payload-exit trio, spawn request/reply (`_TT`), altact-sig-send; **the only `Other(dop)` is `DOP_UNLINK`**, which the C itself rejects (`dist.c:2277-2282`). Argument order is `dist.c`'s; the enum in `src/delivery.rs` is the authority for fields. An out-of-range spawn/altact flag (`>= 1 << 27`, non-small, negative) is an honest `BadArg`.
`DeliveryOutcome { Delivered, NoSuchProcess, Unsupported, Dropped }` + `Dispatched { delivery, outcome }`.
`trait InboundSink { fn deliver(&mut self, &Delivery) -> Result<DeliveryOutcome> }` — **defaulted** to `Unsupported` (a runtime with no process registry never mis-delivers); `UnsupportedSink` is the do-nothing impl, the production impl lives in `beam_rt`, keeping this value layer free of the message/process crates.
The **checked** view: `LinkIdentity { peer_node, local_node }` + `LinkIdentity::intern(&mut AtomTable, peer_name, local_name)` + `Delivery::classify_validated` — `classify` **plus** the C's per-opcode `invalid_message` shape/`dep` anti-spoof checks, so a forged or malformed message is `Err(BadArg)` instead of mis-delivered; opt-in (`classify` unchanged).
The validator's **reference** guard is the C's *per-opcode* predicate, never one blanket rule: the generic `is_ref` (internal **and** external) for the alias/altact `to` fields, the monitor/demonitor references and both monitor-exit references; internal-or-this-node-external for `SpawnReply.reference`; external-only for `SpawnRequest.reference` — the `dist.c` line for each is cited in `src/delivery.rs`. The internal arm is reachable only with a `LocalIdentity` installed, since no wire image can carry an internal reference.
The **integer** guard is per-opcode too: `DOP_UNLINK_ID`'s id must be a **non-zero** unsigned integer (`dist.c:2291-2295`), `DOP_UNLINK_ID_ACK`'s any unsigned integer (`:2320-2322` — a zero-id ack is a legitimate wire message and is delivered), both sharing the endpoint checks (`unlink_endpoints_ok`). A bignum id — accepted by the C's `term_to_Uint64`, emitted by `erts_dsig_send_unlink` above `MAX_SMALL` — is a typed `BadArg`: an honest refusal, not an approximation.
Both entry points have unchecked and checked forms (`recv_delivery(_checked)`/`dispatch_inbound(_checked)` on `Connection`, `next_delivery(_checked)`/`dispatch_inbound(_checked)` on `ConnectionDriver`).

### `src/connection.rs` — the blocking connection-level API + the `TcpStream` adapter
`TcpTransport` (`connect`/`from_stream`/`set_read_timeout`/`set_nodelay`/`into_inner`, `DEFAULT_READ_TIMEOUT` 10 s) and `TcpListener` (`bind`/`local_addr`/`accept`/`set_nonblocking`; an accepted stream is timed-out + `TCP_NODELAY`).
Handshake drivers over 2-byte framing: `connect_client[_with_creation|_with_flags]`, `accept_server[_with_flags]`, `accept_server_with_decision(t, our_name, cookie, creation, flags, decide: impl FnOnce(&Name) -> AcceptDecision)`, all `-> Result<Handshake>`; `CLIENT_CREATION = 0`; the plain forms pass the private always-`Ok` `continue_handshake`.
`connect_to_node[_with_creation](host, node_name, our_name, cookie)` = `epmd::lookup_port` → `TcpTransport::connect` → `Connection::client`.
`Connection<T: Transport>` (established, 4-byte framing): `client*`/`server*`/`server_with_decision`, `negotiated`/`client_flags`/`server_flags`/`peer_name`/`peer_creation`/`peer_visibility`/`handshake`/`ticks_answered`/`into_inner`, `send_control`/`send_message`/`send_tick` + the typed `send_reg_send`/`send_link`/`send_exit`/`send_monitor_p`/`send_demonitor_p`, `recv`/`recv_delivery(_checked)`/`dispatch_inbound(_checked)`, `MAX_ESTABLISHED_PACKET_BODY`; it owns the `OutboundAtomCache` that `send_payload` drains via `take_header()`.
`read_message_body`/`parse_header` distinguish a **clean peer EOF at a frame boundary** (`Io` with `UnexpectedEof`) from a truncated/malformed frame (`BadArg`); the handshake reads keep the plain `read_packet`/`BadArg` behaviour.
The **local-identity seam** (defaulted `None`): `set_local_identity`/`local_identity`/`clear_local_identity`, stored next to the receive atom cache (initialised `None` in the single construction funnel) and handed to `decode_control_with_identity` by `recv`, so `recv_delivery`, `recv_delivery_checked` and `dispatch_inbound*` inherit it without a signature change.

### `src/driver.rs` — the non-blocking poll/step state machine
`ConnectionDriver` + `DriverState { Handshaking, Established, Closed, Failed }` + `StepOutcome { WouldBlock, Handshaking, Established, Progress, Closed, Failed }`.
Constructors `client`/`server` (+ `*_with_challenge`/`*_with_flags`) and `server_with_decision(our_name, cookie, creation, flags, Box<dyn Fn(&Name) -> AcceptDecision + Send + Sync>)`.
`feed`/`feed_eof`; `step()` (incremental 2-byte handshake, then 4-byte-framed established frames, tick replies, `'E'`/`'F'` reassembly); `take_output`/`has_output`; `next_message` (decode-then-commit) → `next_delivery(_checked)` → `dispatch_inbound(_checked)` (drain every queued message through a caller `InboundSink`, `Vec<Dispatched>` in arrival order); `set_local_identity`/`local_identity`/`clear_local_identity`; `send_control`/`send_message`/`send_tick`; `state`/`negotiated`/`client_flags`/`server_flags`/`peer_name`/`peer_creation`/`peer_visibility`/`handshake`/`ticks_answered`/`is_eof`; `failed_frame`.
The **responder sequence is byte-exact**: consume the 2-byte-framed `'N'` NAME (`'N'+flags:8+creation:4+namelen:2+name`) → buffer `sok` **then** the `'N'` CHALLENGE (`'N'+flags:8+challenge:4+creation:4+namelen:2+name`) → consume `'r'` CHALLENGE_REPLY (`'r'+challenge:4+digest:16`) → buffer `'a'`+digest:16 CHALLENGE_ACK → `Established`, the **only** `Established` transition.

### `src/bin/dist_probe.rs` — the hermetic-loopback CLI (bin target, not library API)
`dist_probe loopback <report>` stands up two in-process endpoints and prints exactly one deterministic, host-independent stdout line (exit `0`); the differential harness drives it as an external command.
The report kinds and their frozen stdout: `src/bin/CONTEXT.md`.

### `src/epmd.rs` — the port-mapper + admin client
2-byte-BE-framed **requests** (replies are **not** framed — see Design Decisions) + `EpmdClient<T: Transport>` (`publish`/`port_please`/`names`/`dump`/`kill`/`stop`); `EpmdClient<TcpTransport>::connect` and the free `epmd::connect` are the real TCP client (read timeout + `TCP_NODELAY`).
`epmd::lookup`/`lookup_port` are thin wrappers pinned to `EPMD_DEFAULT_ADDR` (`"127.0.0.1:4369"`), delegating to `lookup_at(addr, name)`/`lookup_port_at(addr, name)` — the arbitrary-address forms that reach a private daemon (`erl -epmd_port N`); `Port2Resp::Error` ⇒ `Io(NotFound)`, never a silent port `0`.
Typed accessors on the response enums (`Alive2Resp` accepted/rejected/conflict/`creation`, `Port2Resp` registered/not-registered, `KillResp::is_ok`, `StopResp::is_stopped`, `DumpLine::is_active`, `DumpResp::active`).
Admin/`DUMP` codecs: `DumpReq`/`DumpResp`/`DumpLine`/`DumpNodeKind`, `KillReq`/`KillResp` (`"OK"`/`"NO"`), `StopReq`/`StopResp` (success text is **`"STOPPED"`**, not `"OK"` — `epmd_srv.c`). `MAX_DUMP_RESP_BODY` (1 MiB) bounds the open-ended `DUMP_RESP`, over-ceiling ⇒ `SystemLimit`; `kill`/`stop` are codec-only by design (destructive); `NamesResp::encode` is lossy on per-node ports.

## Constraints
- **Safe Rust only** — `#![deny(unsafe_code)]`; `TcpTransport` uses only `std::net`.
- **Errors**: only `beam_common::{Result, BeamError}`. Malformed/short/unknown wire data ⇒ `BadArg`; an advertised length/size beyond a wire/message ceiling ⇒ `SystemLimit`; transport failure ⇒ `Io`. **Never** panic on wire data, never `unwrap()` on decoded bytes.
- **Big-endian** for every multi-byte field; field order and exact byte counts are wire-frozen.
- **No duplicated term codec** — all term encode/decode goes through `beam_codec`.
- **No new external dependencies** (the workspace's `beam_common::md5` stands in for the `md-5` crate).
- **Bounded allocation**: validate advertised lengths/buffered fragments against a ceiling before allocating; oversize ⇒ `SystemLimit`.
- Files target ~1000 lines, split by responsibility. Four files run over it today (`delivery.rs`, `connection.rs`, `epmd.rs`, `driver.rs`); `connection.rs` keeps its size largely by path-including its unit tests from `connection_tests.rs`. Licensing: Apache-2.0.

- In-module `#[cfg(test)]` unit tests per module (`connection`'s are path-included from `src/connection_tests.rs`: the frame-read EOF seam over `MemoryTransport` and the blocking decode-failure policy) + the `tests/` integration suites for the cross-module seams.
- **Per-suite claims, the live-`erl` recipes and the shared spawn harness live in `tests/CONTEXT.md`** — that file is the source of truth for what each suite proves.
- Live suites skip **honestly** (clear `eprintln`, never a faked pass) when `erl`/`epmd` is absent from `PATH`; the hermetic suites always run.
- The `beam_rt` two-live-VM suites are the runtime's, not this crate's: `../beam_rt/tests/dist_two_vm{,_rust,_wire}.rs`.

## Design Decisions
- **MD5 is the workspace's single `beam_common::md5`, not a crate-local copy.** `beam_common` is the lowest common ancestor (contracts A.2 module checksums, A.5 handshake digests and A.7 `erlang:md5/1` need the same RFC 1321 arithmetic); the `ChallengeDigest` seam keeps the provider replaceable and no `md-5`/`digest` dependency is added.
- **The digest is `md5(cookie ++ decimal(challenge))` — cookie first.** Ground truth: `dist_util.erl` `gen_digest/2` = `erlang:md5([atom_to_list(Cookie)|integer_to_list(Challenge)])`, `ei_connect.c` `gen_digest` = `md5(cookie)` then `sprintf("%u", challenge)`. The challenge is its **unsigned decimal** string (no leading zeros, no length prefix, cookie has no NUL).
- **`DistFlags` newtype + raw `u64` consts** (ergonomic `contains`/bitops while value pins stay `u64`), chosen over `bitflags` (no new dep); `DistSpawnFlags`/`AltactSigFlags` mirror the shape over `u32` (the in-term field width).
- **The outbound atom cache is threaded through a single `Encoder` per control message.** The trait hook lives in `beam_codec` (which must not depend on `beam_dist`); because the encoder interns atoms in payload order and `OutboundAtomCache` assigns ref positions in the same order (ERTS `insert_acache_map`), the payload's `82` index is exactly the header ref position. `send_payload` drains the message-level ref list with `take_header()`, while the persistent per-connection cache survives to serve `Cached` refs on later messages.
- **Decode-then-commit, and a frame-level decode failure kills the link.** The C kills the connection on any decode error (`dist.c:3173-3188`), so both Rust paths make a frame-level failure (header parse, receive atom-cache apply, payload slice, control decode) fatal and **retain** the frame — the driven path peeks instead of popping, the blocking path keeps the already-read body in `failed_frame()` because the bytes left the socket. Both restore the caller's heap to its entry mark (no half-built terms survive) and both expose the failure (`failed_frame()`, `is_failed()`/`DriverState::Failed`) instead of silently resynchronising.
  **Classification** (after a successful decode) stays **non-fatal**: a wrong-arity *control tuple* is a decode error, but a shape/`dep`/reference violation is reported to the caller, which decides (`beam_rt` retires just that link). That deliberate divergence from the C's blanket `invalid_message` → kill rule keeps a link's fate in the runtime that owns it.
- **The accept handshake exists twice (by design) and both halves are live-tested**: the blocking `connection::accept_server_core` and the non-blocking `ConnectionDriver` server states share the codecs, `check_mandatory`, `auth` and `status_error` but not the state machine; `tests/live_accept.rs` pins the driver path and `tests/live_accept_blocking.rs` the blocking path, so the two cannot drift.
- **The accept-policy seam takes `impl FnOnce(&Name)` on the blocking path and a boxed `dyn Fn(&Name) + Send + Sync` in the driver**: the driver is a reusable state machine consulted once per connection, so it needs a shared policy, boxed to keep `ConnectionDriver` one concrete type. The policy is consulted **after** `check_mandatory` (a real node runs `check_dflags` first, `dist_util.erl:286`), and a refusal reuses the driver's output-flush path so it cannot leave the peer hanging.
- **A refusing acceptor notifies the peer; a refusing connector does not.** `dist_util.erl:286` sends `status(not_allowed)` only on the `other_started = true` branch, so both acceptors frame+flush that status (the exact bytes `00 0C 73 6E 6F 74 5F 61 6C 6C 6F 77 65 64`) before returning the error.
- **There is ONE status→error mapping, shared.** `handshake::status_error(&Status)` is the single source, delegated to by `connection.rs` and `driver.rs`; it returns `BeamError` values backed by `std::io::ErrorKind` — no new `BeamError` variant, no crate-local error enum, and classification is a *value* type on the decoded `Status`.
- **`DistHeader::decode_tail` is shared** by the `'D'` and `'E'` (fragmented) decoders, so the flag/ref/long-atoms logic is written once.
- **Fragment wire layout.** `'E'`/`'F'` prefixes are `VERSION_MAGIC + tag + seq_id(8) + frag_id(8)` (18 bytes); there is **no** separate `dist_hdr_flags` byte on the wire (ERTS folds it into the `Flags` half-bytes). `'E'` carries the normal-header tail verbatim, `'F'` raw payload; the continuation fragment id counts **down** (the last fragment is `1`). The reassembler is strictly in-order (as ERTS requires) and bounds buffered bytes.
- **Atom cache: two spaces.** `beam_codec::AtomCache` is the **per-message translation table** (≤255 entries, addressed by the payload `ATOM_CACHE_REF` byte = the ref's *position* in the header); the **persistent 8×256 segment space** lives in `atom_cache::SegmentCache`. The segment index is a fixed function of the atom hash (`atom.raw() % 2039`), not a per-message rotation.
- **The control message is a wire tuple** — the opcode is the tuple's first element as a small integer, not a raw leading byte (real ERTS requires it); `ControlMessage` keeps a flattened `terms` view as an ergonomic decoded form.
- **`connection` deliberately opens a `TcpStream`.** The A.5 core stays transport-agnostic; the adapter is what makes the handshake + `DOP_*` layer demonstrable end-to-end, and the runtime's production transport is `beam_io`'s.
- **Handshake framing is 2-byte; established framing is 4-byte.** The frame read after `ChallengeAck` is treated as the OTP-23 `Complement` only when its tag is `'c'`; otherwise it is buffered and delivered by the next receive.
- **Driver handshake errors are terminal.** Every `step` error funnels through one arm that sets `DriverState::Failed`; a later `step()` returns `Ok(StepOutcome::Failed)`, and `WouldBlock` is returned only when more bytes are genuinely needed — never to paper over an error.
- **`ConnectionDriver` is byte-fed, and its header parse is deferred to `next_message`.** The runtime owns the socket (keeping this crate free of `mio`); `step` does a cheap *structural* check of each packet's leading bytes so garbage is rejected immediately, but the header is decoded and applied to the receive atom cache in `next_message`, because a `NewAtomCacheRef`'s interned atoms must land in the *same* `AtomTable` the payload decodes against.
- **The frame-boundary EOF seam is a *defaulted* `Read` method**, so the trait needs no implementor support beyond the default (which can only answer `Ok(true)` or an error). `TcpTransport` overrides it (`0` bytes at the start ⇒ `Ok(false)`, a partial read ⇒ `BadArg`) and `MemoryTransport` maps exhausted input to `Ok(false)`; the blocking established-frame read turns that into `Io(UnexpectedEof)`, distinct from a truncated frame's `BadArg`, while the handshake reads keep the plain `read_packet` behaviour and the non-blocking path reports `Closed`.
- **epmd frames its requests but not its replies.** A client *request* is 2-byte length-framed (`epmd_port.c`), but `epmd` writes every *reply* body straight to the socket (`epmd_srv.c` `reply()`), so the client reads it unframed/self-delimiting — by tag for `'y'`/`'v'`/`'w'`, and "read until the transport goes quiet" for the open-ended `NAMES_RESP` list.
- **An accepted inbound pid must carry the verbatim handshake node name.** `dist.c:2358` requires `external_pid_dist_entry(watcher) == dep`, keyed on **sysname only** (`erl_node_tables.c:286-292`), and `dist_util.erl:590,:783-793` stores the verbatim `Name` string — the **full `node@host`** on the wire (a bare short name fails). The creation comes from `ALIVE2_RESP` and is *not* part of the check.
- **The local node identity is an *installed*, defaulted value — never a change to the term codec or to a decode signature.** The C decoder is not purely wire-driven: `dec_is_this_node` (`external.c:3123-3129`) asks *"is this identifier's node the node I am running on?"* and, if so, builds the **internal** term. That rule needs node identity, which the value layer does not own, so each link carries `LocalIdentity { node, creation }` into `decode_control_with_identity` — one funnel, with `decode_control` = the same call with `None`.
  * **Additivity is the contract with `beam_rt`**: with nothing installed every decoded pid/port/reference keeps its faithful external form (pinned by `tests/local_identity.rs`'s identity-less legs). Hence the identity is an `Option` field on `Connection`/`ConnectionDriver` rather than a required `recv`/`next_message` parameter — no signature changes, and the derive-offs inherit it for free.
  * **The atom must come from the decode-time `AtomTable`** (an atom is a table-local index compared by raw word), so a foreign-table atom is **inert** — which is why `LocalIdentity::intern` takes the table and the full wire name.
  * **The demotion carries the C's identity-gated bounds**: a local pid number/serial or port id past the internal immediate's range, and a local `NEWER_REFERENCE_EXT` first number at or past `MAX_REFERENCE`, are `BadArg` (`external.c:3175-3179`, `:4718-4721`, `:4804-4813`); a local reference whose packed id does not fit the 60-bit slot keeps the faithful external form. Everything stays `BeamError::BadArg` — no new error variant.
  * **Identity is decode-side only**: `classify_validated`'s per-link checks compare **external** node atoms (the C's `dep`) and are untouched. The one interaction is the reference *form* — the validator's `is_ref` spans internal and external references like the C's `is_not_ref`, so a demoted internal term passes the guard that accepts a peer's external reference, and with no identity installed that arm is inert.

## Known Issues / Remaining Gaps
- **The crate classifies inbound deliveries but performs no side effects.** Nothing here acts on a `Delivery` (no link/monitor/spawn/exit bookkeeping); routing is the caller's job via `InboundSink`, whose production impl over `beam_process`/`Mailbox` lives in `beam_rt`. Typed *outbound* helpers exist for `Send(_Sender)`/`RegSend`/`Link`/`Exit`/`MonitorP`/`DemonitorP`; every other opcode is sent through the generic `send_control`.
- **Spawn/altact/payload-exit are classified, not executed.** Those delivery variants and the in-term bit vocabularies are fully decoded, but the semantics (`dist.c:2590-2698`, `:3090-3146`) are interpreted by neither this crate nor `beam_process`.
  **Typed gaps at the runtime/signal layer:** the distributed-spawn family (`DOP_SPAWN_REQUEST`/`DOP_SPAWN_REPLY`), `Delivery::Other(_)`, the ack-owing `DOP_UNLINK_ID` half (`id != 0`), a remote **named** monitor `{Name, Node}`, and `DOP_PAYLOAD_MONITOR_P_EXIT` (the plain 5-tuple is always emitted).
- **`InboundSink` has no reply channel — the C's per-opcode replies are not emitted.** `deliver(&mut self, &Delivery) -> Result<DeliveryOutcome>` returns only an outcome and a sink owns no connection/driver/output queue, so three C replies cannot be produced: `DOP_EXIT` with reason `noproc` for an inbound `DOP_LINK` whose `to` is dead (`dist.c:2268-2272`), `DOP_MONITOR_P_EXIT` with `noproc` for a dead `DOP_MONITOR_P` target (`:2406-2410`), and the `DOP_UNLINK_ID_ACK` an inbound `DOP_UNLINK_ID` with a **non-zero** id owes (`reply_dist_unlink_ack`, `erl_proc_sig_queue.c:2753-2791`; `beam_rt` reports the wire half `Unsupported` after dropping the link record). The `id == 0` half is unreachable as a message anyway (`dist.c:2294` rejects it as `invalid_message`), and an inbound `DOP_UNLINK_ID_ACK` is classified, not replied to.
  Smallest additive seam: a defaulted `fn reply(&mut self, &Delivery, DeliveryOutcome) -> Option<Reply>` + `pub struct Reply { dop: Dop, terms: Vec<Eterm> }`, written by the caller's `dispatch_inbound*` through the existing `send_control`.
- **The outbound control encode installs no local-node identity, so a control argument or message holding an internal pid/port/reference is a typed `unsupported` — never a wrong image.** `encode_control_cached` builds `Encoder::new_body(atoms)` and only adds the atom cache; `beam_codec`'s encoder needs `Encoder::with_local_node` to write an internal id and otherwise answers `unsupported`, while a PEER's external pid/ref needs no identity at all (so a peer-minted monitor ref can be written back verbatim). Consequence: outbound `DOP_LINK`/`DOP_EXIT*`/`DOP_EXIT2*`/`DOP_MONITOR_P_EXIT`/`DOP_UNLINK_ID(_ACK)`/`DOP_GROUP_LEADER`/`DOP_SEND_SENDER`/`DOP_REG_SEND`/`DOP_SPAWN_REPLY` encode only when the caller pre-spells this node's ids as external terms — which is what `beam_rt/src/dist_client/{client,signals}.rs` does, plus the payload-only externalize round trip. An identity-taking encode (`Option<LocalIdentity>` parameter or a `*_with_identity` variant) is the clean fix.
- **`Delivery` terms are the caller's heap words, never copied — a sink must be done with them before the drain heap is reset.** Every field is a raw `Eterm` decoded into the `&mut Heap` the caller passes to `recv`/`next_message`, and `reason`/`payload`/`message`/`args` can be boxed; this crate owns no arena and resets nothing, so a sink that STORES a field past `heap.reset()` keeps a stale pointer (immediates survive). Copying onto the receiver's heap is the sink's obligation.
- **`ConnectionDriver` advances the receive atom cache only in `next_message`**, not `step`: a runtime that never calls `next_message` makes no header/atom progress.
- **`DOP_UNLINK` never routes to a side effect.** The C *rejects* the bare opcode (`dist.c:2277-2282`), so `classify` leaves it `Other(DOP_UNLINK)` — encodable/decodable, carrying no semantic `Delivery`.
- **The accept policy can refuse, but there is no net-kernel pending-connection registry.** `AcceptDecision::Refuse(status)` writes the status and aborts; the *decision source* is missing — the oracle's `mark_pending` (`dist_util.erl:318-368`) selects `ok`/`named`/`ok_simultaneous`/`nok`/`alive` from a `net_kernel`-level pending-connection registry, so a simultaneous-connect race or a reconnect-alive probe is only answered as a real node would once a caller supplies such a policy. The seam also cannot *continue* on a non-`ok` status: `named` (dynamic node names) and `ok_simultaneous` are continuations with no `AcceptDecision` representation.
- **The server never emits a `'c'` Complement** (the codec exists, is never driven) and never validates the peer name's shape — no counterpart of `dist_util.erl:801-812` `is_name_ok` or `check_allowed/2`.
- **Classification failures are non-fatal** (a deliberate divergence from the C's `invalid_message` → kill rule; see Design Decisions) — a caller that wants the C's behaviour must drop the link itself when `classify`/`classify_validated` returns `Err`.
- **Tick *scheduling* is `net_kernel`'s job.** The `net_ticktime` timeout and the resulting `{nodedown,Node}` decision belong to `lib/kernel/src/net_kernel.erl`; this crate only answers an inbound tick.
- **`LOCAL_EXT` (`121`) is not wired in.** `beam_codec` provides `Encoder::finish_local(hash)`/`encode_term_local` (a caller-supplied node hash) for the `DFLAG_LOCAL_EXT` same-node short-circuit; it is a `dist.c`-level local-delivery optimisation, not part of the remote wire, so reach for it only if a local-link path is added.
- **Two `classify_validated` divergences from the C, both honest refusals.** (a) The C's monitor `Ref` guard is `is_not_ref` (`dist.c:2361`), so an *internal* ref is accepted and echoed back naming THIS node; `Delivery::Monitor.reference` keeps it internal, but `beam_process`'s `RemoteRef::from_eterm` requires `is_external_ref` (`beam_process/src/remote.rs:243`), so that shape ends `Unsupported` downstream. (b) `DOP_LINK`'s `to` is not validated, so the C's "an external `to` of a THIRD node is `invalid_message`" (`dist.c:2240-2243`) is not reproduced; the dead/old-incarnation case is the sink's business instead.
- **`beam_rt`'s adoption is tracked in `../beam_rt/CONTEXT.md`** (both distribution halves, the checked per-link drain, inbound delivery). What stays here: the value layer, the accept/connect state machines, and the codecs.

## Notes for Agents
- **Handshake tags: `NAME_TAG == CHALLENGE_TAG == b'N'` (78), `STATUS_TAG == b's'` (115).** No legacy form is supported: a pre-OTP-23 `'n'` (110) NAME or a `'S'` status fails the tag check with `BadArg`, and the driver goes to `Failed` **without emitting a byte** (the peer sees `{error,closed}` on its next read).
- **A refusal is buffered into `take_output` *before* `step` returns `Err`, so a caller must drain `take_output()` even on the error path** (the `not_allowed` mandatory-flag refusal and an `AcceptDecision::Refuse`). A `let outcome = driver.step()?;` that returns before the flush drops the only status the responder ever sends.
- **Drive `step` to `WouldBlock`, not once per socket read.** After a failure it returns `Ok(StepOutcome::Failed)`/`Ok(StepOutcome::Closed)` — never `Err` twice. A decode failure in `next_message` is the third terminal case: drop the link, and read `failed_frame()` if you want the bytes.
- **A safe pid/port/ref term builder exists**: `beam_codec::term::{make_external_pid, make_external_port, make_external_ref}` are safe public wrappers over `beam_term::thing`'s raw writers, so a `#![deny(unsafe_code)]` crate can materialize external pids/ports/refs (the live tests use them). The hermetic tests place small-int stand-ins in pid/ref slots, which compare `==` across heaps.
- **A remote send needs `{Name, Node}`, not `{Node, Name}`** (`bif.c:2614-2626` matches the tuple in that order), so `{Node, Name} ! Msg` silently delivers nothing.
- **In a live probe, a read timeout is NOT a peer rejection.** `DEFAULT_READ_TIMEOUT` surfaces as `Io(WouldBlock, errno 11)`: the link is still open and nothing arrived. An orderly end-of-link is the `Ok(0)`/`Closed` path.
- **A real node can be pointed at a private `epmd`** with `erl -epmd_port <N>` (`erl_epmd:get_epmd_port/0` reads `init:get_argument(epmd_port)`; the client connects to `127.0.0.1`) — how `tests/hermetic_epmd.rs` validates the in-process stub without a host `epmd`.
- **Do not run `cargo fmt` on this crate.** It is intentionally not default-rustfmt-clean; a bulk pass rewrites hundreds of unrelated lines. Hand-format to match the surrounding style.
