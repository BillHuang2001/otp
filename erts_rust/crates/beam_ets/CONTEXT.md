# `beam_ets` — ETS Tables (Stage 3 data structures)

## Intent
Owns the **observable semantics of `ets:*`** — Erlang Term Storage — over **flat, table-owned term storage** (the A.1 "copy boundary"): Part I §A.1 (term/key/value semantics), §A.8 (`ets:info/1` introspection), and the Stage-3 row of Part II §H.
Only the **semantics** are contract — which object wins on a duplicate key, key equality/ordering, `size`, and what `lookup`/`select`/`tab2list`/`first`/`next` return.
The **interiors are NOT externally pinned** (crate-layer `../CONTEXT.md` §2): bucket layout, hash-map thresholds, tree fan-out and load factors are choices.
Term **ordering** and **hashing** are owned by `beam_term` (`compare::{cmp,cmp_arith,eq}`, `hashing::term_hash`) and MUST NOT be re-implemented here.
Legacy ground truth (read-only): `../../erts/emulator/beam/{erl_db.c,erl_db_hash.c,erl_db_tree.c,erl_db_util.c,erl_db*.h}` — mirror the SEMANTICS, not the layouts.
Companions: **`ETS_SURFACE.md`** (the per-`ets:*`-operation coverage census — this crate / `beam_bifs` / missing, the oracle-probed semantic facts, the runtime gaps and the exact API each needs, and the full `ets:info(T,stats)` detail) and **`PERF.md`** (every measured figure, both sides of each ratio).

## Position & dependencies
Crate-layer **wave 1** (`../CONTEXT.md`).
Depends only on `beam_common` (errors), `beam_term` (terms + ordering/hashing), `beam_alloc` (table-owned allocation) and `libc`; consumed by `beam_bifs` (the `ets:*` BIFs) and `beam_rt`.
No new dependency edges without reporting to `../`.
The **atom table is a per-call parameter**: every op that compares or hashes a term takes `atoms: &AtomTable` (one live global table owned by `beam_rt`; a `Table` stores no atom state).

## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_ets::prelude::*`.

### `kind.rs` — kinds, access, options
- `TableKind { Set (default), OrderedSet, Bag, DuplicateBag }` (`is_multi`/`is_ordered`/atom-name round trip), `Access { Public, Protected (default), Private }`, `Concurrency { None, Read, Write, ReadWrite }` — **advisory** (parsed/reported, never enforced).
- `WriteConcurrency { Off (default), On, Auto, FixedLocks(u32) }` — the `{write_concurrency,_}` **mode**, whose `Off`/`On` projection is the bool API (`is_enabled`/`fixed_locks`/`as_atom_name`); `FixedLocks(n)` keeps the **requested** count.
  `lock_count()` is the **effective** `tb->hash.nlocks` (the last element of `ets:info(Tab, stats)`) — the one implementation of `db_hash_init`'s normalization: `Off` ⇒ 1, `On`/`Auto` ⇒ 64, `FixedLocks(n)` ⇒ the request rounded **down** to a power of two and clamped **up** to 64.
- `SetInterior { Chained, Champ (default) }`, `OrderedInterior { BPlusTree (default), Sorted }` — crate-internal interior selectors (`Table::with_*_interior` install, `set_interior()`/`ordered_interior()` report); not `TableOptions` fields, no BIF surface.
- `TableOptions` — the builder (defaults `Set`, keypos 1, `Protected`, unnamed, uncompressed, no concurrency/heir/`decentralized_counters`): one setter and one getter per field (`set_keypos` rejects 0 and is the only fallible builder; `set_name` records the name only, not `named_table`), plus `write_concurrency_mode`, `decentralized_counters{,_option}`, `concurrency` and `lock_count`; a `private` table forces the effective `write_concurrency` off. Tests `src/kind/tests.rs`.
- `can_read`/`can_write(access, owner, requester)` — the access matrix (`requester == owner` ⇒ everything).

### `key.rs` — object/key rules
- `key_of(object, keypos) -> Result<Eterm>`: an object **must be a tuple** with `arity >= keypos` (non-tuple / short arity / `keypos == 0` ⇒ `badarg`), plus `is_valid_object` and the `unsafe` `object_elements` tuple slice the select predicates read.

### `store/` — table-owned term storage (the copy boundary)
- `TermStore` — a **never-relocating bump arena** over a `beam_alloc::AllocRef` (`AllocType::Ets`) with **per-object reclamation**: `copy`/`free(root) -> usize`/`relinquish`/`reset`/`words`/`blocks`/`memory`, `Drop` frees every block; deep-copy covers every kind `ets:insert/2` accepts (residual typed `badarg`s in Known Issues). Detail: `store/CONTEXT.md`.

### `table/` — the `Table` handle + ops
- `TableId(u64)` (`new`/`raw`/`next` — the process-global monotone table-handle counter starting at 1; `Display`), `OwnerId(u64)` (an opaque owner, **not** a pid), and `Table`: metadata + a table-owned `TermStore` + one interior behind the private `Interior` trait (constructors `new`, `with_allocator`, `with_set_interior`, `with_ordered_interior`).
- **Unnamed-tid rule.** An unnamed table's tid is an internal ref thing whose `id` word is `TableId::raw()`, so `beam_bifs::access::ref_thing_id` decodes it straight back to the registry handle (`beam_bifs`'s `ets:new/2` builds it with `make_ref_thing`; `beam_rt`'s `tid_ref_thing` builds the same shape via `MonitorRef::from_id(handle).to_eterm`).
  The id is **derived, never minted**: it comes from the table-handle band, draws nothing from the workspace's one reference-id space (`beam_common::next_ref_id`), and `MonitorRef::from_id` is the non-mint constructor whose uniqueness is the caller's claim.
- **Shape conventions.** Every fallible op returns `beam_common::Result<_>`; `first`/`last`/`next`/`prev` return `Option` (`None` = `'$_end_of_table'`), and navigation on an unknown anchor is `badarg`; an op takes `atoms: &AtomTable`, and the select/match family plus the element updates also take `heap: &mut Heap` (scratch).
- **Metadata/ownership:** `id`, `kind`, `name()`, `keypos()`, `access`, `is_named_table`, `owner`/`set_owner`, `heir`/`set_heir`/`heir_data`, `give_away`/`give_away_with_gift -> Transfer`, `setopts(caller, SetOpt)`, `set_access`, `owner_died -> OwnerDeath`, `info -> TableInfo`, `rename -> RenameOutcome`.
- **Writes** (object = the whole tuple, key from `keypos`): `insert` (upsert), `insert_new -> bool`, `insert_list` (**ATOMIC**), `delete(key)`, `delete_object`, `delete_all_objects`, the `pub(crate)` `replace_key` behind a `duplicate_bag` `select_replace`.
- **Reads/navigation:** `lookup`/`member`/`lookup_element*` (the `_all` forms for the multi kinds), `slot(i64) -> Result<Option<Vec>>` (0-based; `None` ⇒ `'$_end_of_table'`; out of range ⇒ `badarg`), `memory` (store **plus** index), `size` (objects, not keys, for `bag`/`duplicate_bag`), `is_empty`, `tab2list` (ordered for `ordered_set`), `take(key)`, `first`/`last`/`next`/`prev`; hash-kind `last`/`prev` alias `first`/`next`.
- **Element updates:** `update_counter`, `update_counter_with`, `update_element(key, &[(pos, term)]) -> bool`.
- **Select family** (`select/`) + `select_all(pred)`: `select`, `select_reverse`, `select_delete`, `select_count`, `match_object`, `match_`, `match_delete`, `select_replace`, plus the limit/continue forms over them (each `-> (Vec<Eterm>, Option<MatchContinuation>)`); and `set_fixation`/`is_fixed`/`deferred_objects` (`ets:safe_fixtable/2`) with `match_spec_run`.
- `stats() -> TableStats` — the interior's own figures: a separate **O(n)** entry point, deliberately **not** folded into the O(1) `info()` snapshot (see `stats.rs`).
- `pub(crate) trait Interior` — the dispatch seam, whose `insert` returns **whether the object was retained** (so `Table::insert` reclaims the copy it made when the interior rejects it), plus two defaulted statistics seams (`bucket_chains` for the hash family, `node_shape` for the tree family); `Table::stats()` dispatches on the table **kind** first.
- `TableAccess` (from `as_requester`) rechecks `can_read`/`can_write` per op and raises `badarg`: the write family is write-gated; the read family (plus `set_fixation` — the oracle gates `safe_fixtable/2` as a READ) and the limited forms are read-gated; `ets:match_spec_run/2` and `ets:info/1,2` are deliberately ungated; `give_away*` has no protection check; `setopts`/`set_access` are owner-gated.
- `rename(name, is_taken) -> RenameOutcome { Named { previous_name }, Unnamed }`: only the recorded name changes, so objects/`TableId`/owner/access/kind/keypos survive by construction; with `named_table` an already-registered new name (including its own) is `badarg` and the BIF returns the new name atom, without it the rename always succeeds and the BIF returns the unchanged identifier (the registry rekey is the host's).
- `Heir { owner, data: Option<Eterm> }` (`Some` = `{heir, Pid, Data}`, `None` = `{heir, Pid}`), `SetOpt { Heir, ClearHeir, Access }` (the modelled `setopts/2` subset, owner-gated **first**, so a non-owner mutates nothing), `Transfer { to, from, data }` (the `{'ETS-TRANSFER', Tid, FromPid, GiftData}` obligation — the `Tid`/`FromPid` **terms** are the host's), `install_heir` **copies** the gift into table storage (`copy_heir`/`replace_heir` are the shared copy/reclaim seams), and `OwnerDeath { NotOwner, Deleted, Transferred(Heir) }` + `owner_died(dead, is_alive)`, which performs only the transition — dropping the table and delivering the transfer are the runtime's.
- `SharedTable` (`Arc<RwLock<Table>>`) and the **guard-scoped, lifetime-tagged views** `TableRead`/`TableWrite`/`TableTerm`/`HeirView`: a term read through a view cannot outlive its guard (a compile error, pinned by `compile_fail` doctests) and the only way to keep one is `TableTerm::copy_into(&mut TermStore)`; the default path allocates nothing, and a poisoned lock is the typed `unsupported_ets: table lock poisoned`.
- Per-file signatures: `table/CONTEXT.md`; the views: `table/view/CONTEXT.md`.

### `champ_interior.rs` — CHAMP open-addressing interior (**default `set`**)
- `ChampInterior`: each level consumes `WIDTH = 5` bits of the 64-bit `term_hash`, compressing children into a `datamap` (inline slots) + `nodemap` (sub-nodes); a full-hash collision lives in an `eq`-compared `CollisionNode`, so a pathological hash cannot recurse past 64 bits.
  Every `Interior` method is overridden; delete canonicalization is bottom-up (a sub-node holding exactly one entry is **inlined** into its parent — a sub-node is indexed by the *next* 5 hash bits, so promoting a multi-entry sub-node wholesale would break routing), and a removal gives capacity back (`trim_capacities`).

### `hash_interior/` — chained hash-index interior (`bag`/`duplicate_bag`; opt-in `set`)
- `HashInterior`: buckets `Vec<Vec<Entry>>` (`Entry { key, objs }`), lookup by `term_hash(key) % buckets` then `eq`; `set` keeps ≤ 1 object per key, `bag` rejects a duplicate **object** within a key (its `insert` returns `false`, so the caller reclaims the rejected copy), `duplicate_bag` keeps a multiset, and `delete_object` removes **every** equal object (the oracle).
  `capacity.rs` owns the bucket array's growth/release policy — grow past a `3/4` object load, release below `1/8` (a 6× hysteresis band), rebuild at exactly the target count, per-entry slack released past `4×` — and `slot` is the bucket-array override (`bucket_count()` is the `nactive` boundary). Detail: `hash_interior/CONTEXT.md`.

### `ordered_interior/` — the `ordered_set` interiors (B+-tree + sorted `Vec`)
- `OrderedSetInterior`: a K-ary B+-tree (`ORDER = 32`, `MIN_OCCUPANCY = 16`) over a non-relocating arena `NodeStore` with a leaf chain; every navigation and key comparison goes through `beam_term::compare::cmp_arith`, so **`1` and `1.0` are the same key** (whole-object identity in `delete_object/2` stays the exact `compare::eq`).
  `sorted.rs` is the same semantics over one sorted `Vec` (O(log n) lookup, O(n) insert/remove), selectable as `OrderedInterior::Sorted`; the non-relocating arena, the split/borrow-or-merge tree ops and the leaf-chain iterator are `node.rs`/`tree.rs`/`iter.rs`. Detail: `ordered_interior/CONTEXT.md`.

### `select/` — the match-spec compiler + executor
- `compile(spec, atoms) -> Result<MatchSpec>` — `MatchSpec { clauses }`, `MatchClause { head, guard, body }`, the `SelectPredicate` alias behind `Table::select_all`, `Pattern` (nested tuple/list/improper patterns, quoted literals, `'_'`, `'$N'` binds with repeat-occurrence equality; every other atom — `'$_'`/`'$$'` are special only in a *body* — is an exact `=:=` literal) and `Expr` (the connectives, comparisons, type tests, guard BIFs, map construction, and the body forms).
- Two `thread_local` seams keep wave-1 `beam_ets` free of a `beam_bifs` dependency edge: `SelfHook` for `self/0` and `ArithHook` for arithmetic (both default to a typed failure; the host installs them; a candidate to lift into `beam_term`).
- `exec.rs` implements the select family over the compiler (`BodyKind` reuses it for `ets:match*`), `run.rs` is `match_spec_run`, `continuation.rs` the opaque owned `MatchContinuation` + its private `Cursor`. The guard/body capability census and the trace/`select_replace` corners: `select/CONTEXT.md`.

### `info.rs` — `ets:info`
- `TableInfo` + `entries(&self, atoms) -> Vec<(Atom, Eterm)>` — the heap-free `{Key, Value}` pairs of the oracle's **15** `ets:info/1` fields in the oracle's own order (from `id` to `protection`); the `beam_bifs` bridge builds the observable proplist identically.

### `stats.rs` — the `ets:info(Tab, stats)` interior statistics (heap-free)
- `TableStats { Hash(HashStats), Tree(TreeStats), Absent }` (`Absent` = the oracle's atom `false`), `HashStats` (the hash 8-tuple's figures), `TreeStats { route_nodes, base_nodes, max_depth }` (integers only) and the `pub(crate) BucketChains` occupancy histogram with its one finishing step `hash_stats(kept_items, nlocks)`.
  Plain `usize`/`f64` snapshots — **no terms and no atom state**: rendering the tuple and interning `false` are the BIF layer's (`beam_bifs::ets::stats_term`).
- The observable mapping — the answer depends on the table **type**, never on its contents:

| table | answer |
|---|---|
| `set` / `bag` / `duplicate_bag` | the **8-tuple** `{Nactive, AvgChainLen, StdDevChainLen, StdDevExpected, MinChainLen, MaxChainLen, KeptItems, NLocks}` — the counts integer, the three chain figures float |
| `ordered_set` **with** an effective `{write_concurrency, …}` (a catree) | the **3-tuple** `{RouteNodes, BaseNodes, MaxDepth}`, all integer (the oracle answers `{0,1,0}` for every catree it builds) |
| every other `ordered_set` — a plain one, or a `private` one whose `write_concurrency` is normalized away | the atom `false` |

- **Agree by value:** the shape, arity, element order, element types, `nlocks` (element 8) and `kept_items` (element 7 — `Table::deferred_objects`, `0` on an unfixed table).
  **Legitimately differ:** `Nactive`, the whole chain block and every `TreeStats` element — they measure *this* crate's interiors with the oracle's own formulas, so the meaning is the same and the numbers are not ERTS's.
  **A chain statistic must NEVER be pinned value-for-value** — pin the shape/arity/types, `nlocks` and `kept_items`; `tests/ets_stats.rs` is the crate-side contract, and the formulas with the `f32` precision model (both roundings load-bearing, radicands clamped at `0.0`) live in `ETS_SURFACE.md` §1.

### `error.rs` — failure constructors
- `pub(crate) badarg()` / `unsupported(what)`: `BeamError::BadArg`, or a `BeamError::Raise` (error class) whose reason atom is `unsupported_ets: <what>`. No crate-local error enum.

## Constraints
- **Errors:** only `beam_common::{Result, BeamError}`; `badarg`-style failures ⇒ `BeamError::BadArg`; never `panic!`/`unwrap()` on runtime data, and no table op panics on malformed input.
- **Never re-implement term order/hash** (`beam_term::compare::{cmp,cmp_arith,eq}`, `beam_term::hashing::term_hash`) — workspace Prevent-Duplication rule.
- **Table-owned storage only (A.1 copy boundary).** An inserted object is **deep-copied** into the table's `TermStore`; the table never retains a pointer into a caller's heap, while objects/keys returned from reads alias table storage and are valid for the table's lifetime (see Known Issues).
- **No `ExecutionContext`/`alloc_words` callback seam.** This crate cannot copy a term out into a caller's GC/process heap; the only allocation targets a caller can supply are a `&mut beam_alloc::Heap` (the select family's scratch arena, used **only** for freshly constructed result tuples/lists/cons cells) and a `&mut TermStore` (the copy-out forms, `TableTerm::copy_into`, `tab2list_into`).
  A select result is therefore a **mixed** graph — a `'$_'`/`'$N'` value is the raw table-owned word, while a constructed tuple/cons is on the scratch heap and carries that aliasing word inside it — so it is invalidated both by the table freeing the object **and** by the scratch heap being rewound.
- **`unsafe` confinement.** Only `store/`, the tuple accessor in `key.rs`, the small term-reading blocks in `select/`, `table/mod.rs` (`select_all`) and `hash_interior/mod.rs` (the destructive counter-element write), plus the `unsafe impl Send/Sync` on `TermStore`; `hash_interior/capacity.rs` and `hash_interior/tests.rs` have none.
  Every `unsafe fn` has a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale (`beam_common::safety`).
- **Files ~1000 lines**, one responsibility per file — `src/hash_interior/` is the split example (`mod.rs` type/ops/`Interior` impl, `capacity.rs` the growth/release policy, `tests.rs` unit tests); the only `src/` files over budget are unit-test siblings (`store/tests.rs`, `ordered_interior/tests.rs`, `table/view/tests.rs`) and `select/expr/mod.rs`, and large `tests/` modules are legitimate.
- **Licensing** Apache-2.0; no new external deps (only `beam_common`/`beam_term`/`beam_alloc`/`libc`).

## Design Decisions
- **The shared handle is guard-scoped, not copy-on-read.** `TableRead`/`TableWrite` hold the `RwLock` guard and every term they yield is a `TableTerm<'g>` bound to the view's borrow, so holding one past the guard is a **compile error** (six `compile_fail` doctests), not a caveat.
- **Heir gift data is table-owned; arity 2 is representable.** `Heir.data: Option<Eterm>` distinguishes `{heir, Pid}` from `{heir, Pid, undefined}`; the data is deep-copied at creation and at `install_heir`, and reclaimed by `replace_heir` at every overwrite site — the caller's term would dangle once its heap died.
- **`ordered_set` defaults to a K-ary B+-tree** (`ORDER = 32`, `MIN_OCCUPANCY = 16`) over a non-relocating arena; keys compare by `cmp_arith`, so `1` and `1.0` are the same key, and the sorted-`Vec` interior stays selectable as a comparison index (`PERF.md` §3 settles the choice).
- **The tree stays dense and separator-faithful by construction:** the delete unwind rebalances eagerly (borrow-then-merge, never carrying sparsity), `NodeStore::compact` reclaims arena slots/capacity only (it is *not* the rebalance), and an `InsertStep` re-materialises a separator only where the subtree max actually moved — an upsert reclaims the object that established it. Mechanism and invariants: `ordered_interior/CONTEXT.md`.
- **`set` defaults to CHAMP; `bag`/`duplicate_bag` stay chained**, over a private `Interior` trait rather than a pinned layout (generic rebuild-on-heap defaults, in-place destructive hash overrides, so the B+-tree needs no writable index slot).
  Measurement-driven, index only (CHAMP wins on insert, iteration and index bytes/entry, ties on lookup-hit, loses on delete); `Chained` stays selectable for `set` and `src/interior_parity.rs` proves the traces identical.
- **One `TermStore` per table, copy-on-insert, per-object free.** `free(root)` returns a removed root's exact-word-size runs to per-size free lists that `copy` reuses before bumping, and is a no-op for a root the store never tracked (which makes the heir reclaim path safe).
- **Two allocators, two halves of a table's memory.** The term **payload** arena (`TermStore`) is `beam_alloc`-backed — a per-table `AllocRef`, `beam_alloc::allocator(AllocType::Ets)` by default, or any `AllocRef` a caller hands `Table::with_allocator` — so block ownership and release are the crate's and nothing routes through a process heap.
  The **index** structures are plain Rust `Vec`/`Box` over the Rust global allocator; `Table::memory()` reports **both** halves in words (`store.words() + interior.memory()`), which is why a table's `ets:info/1` figure is reproducible without an allocator query.
- **`take` hands back checked-out copies and reclaims the stored originals.** Copy-before-free is mandatory (freeing first would let a later same-size `copy` reuse the words the caller holds); each copy is `relinquish`ed — valid for the table's lifetime, never handed out again, no longer counted toward `memory()`.
- **Every interior releases index capacity as occupancy falls,** so `ets:info(T, memory)` tracks the **live** key/object count rather than a bulk teardown's high-water mark, each home keeping its own hysteresis so a stable-size churn never reallocates.
  The **contract is the shape**, not a word count: memory falls with live data, a stable-size churn neither grows nor shrink/re-grows, and the empty floor is exact via `release_empty_interior` (a downsized index is not a *fresh* one). `ets:safe_fixtable/2` is the one deliberate exception — removed storage waits in `deferred_frees`, so memory falls at unfix. Trajectories: `PERF.md` §2, pinned by `tests/ets_capacity.rs`.
- **An interior's stored key term aliases a live, table-owned object.** `key_of` returns a pointer *into* the object's `TermStore` storage, so an interior keeping a key must re-point it whenever it replaces or removes the object it aliased (a `set` upsert; a `bag`/`duplicate_bag` `delete_object`); `Table::relocate_rebuilt_object` derives the index key from the **table-owned copy**, never the caller's key.
- **Access and ownership are `Table`-level, not access-mode concerns.** `can_read`/`can_write` mirror `db_check_access` (`requester == owner` ⇒ full access); `TableAccess` enforces while the raw `Table` ops stay owner-level; `give_away/3` and `setopts/2` never consult `protection` (they are owner-gated).
- **`{write_concurrency,_}` is a mode, not a bool.** `WriteConcurrency` is the model and the bool API its `Off`/`On` projection, so `beam_bifs` stays source-compatible; the fine-locking normalization is a **creation-time** property of `TableOptions`, so a runtime `set_access` never re-normalizes it (the oracle agrees).
- **`ets:info/1` mirrors the oracle's 15 fields in the oracle's order**, with `heir`/`node` as runtime-shape constants and `decentralized_counters` resolving to the effective `write_concurrency` **and** the explicit option when given, else `kind.is_ordered()` (the CATREE default); a `private` table normalizes the concurrency flags off, so it is false too.
- **`insert_list` is atomic; `select_replace/2` is a two-phase rewrite with the C's static body check** — a body outside `'$_'`/`{{…}}`/`{const,{…}}`/`{element,KeyPos,'$_'}` is `badarg` for the whole call even with no match (table unchanged), while a valid body applies atomically.
  A `duplicate_bag` replacement **rebuilds the affected key** (it must land on the **specific** matched object): the replacement is computed on the caller's scratch heap and `Table::replace_key` deep-copies the new list into table storage **first**, then frees the old.
- **The hash kinds' `last`/`prev` ARE their `first`/`next`** (ERTS installs the same function twice and its reverse select delegates to the forward chunk function): for `set`/`bag`/`duplicate_bag` there is **no** backward walk, an unknown anchor stays `badarg`, and `select_reverse` returns exactly what `select` returns. The trait defaults stay the `ordered_set` semantics.
- **Hash-kind navigation order is unspecified (a deliberate freedom).** Every key a walk yields is present, `first`+`next` is a permutation of the stored keys, and `next`/`prev` on an absent anchor are `badarg`; `ordered_set` navigation is exact — ascending arithmetic key order, an absent key reading as a range bound.
- **`ets:slot/2` is one contract over three decompositions, and the slot count is always the index's, never the object count.** Slots are **0-based** (`N` ⇒ `'$end_of_table'`, beyond/negative ⇒ `badarg`); `ChampInterior` uses its root index space and `HashInterior` its bucket array (so a **free hash slot answers the empty list**), both ordered interiors a one-object-per-slot partition. Only the **relation** is pinned (`0..N-1` are lists partitioning `tab2list/1`), never ERTS's own slot count. Decompositions: `table/CONTEXT.md`.
- **Select-family continuations are key-anchored on an `ordered_set`, ordinal on the hash kinds**, chosen by the table kind (`Cursor::{Begin, Anchor, Position}`); the ordered anchor is an **exclusive** `next`/`prev` bound (surviving its own deletion). They are opaque **owned values, not terms** (a resume needs no re-compile), identified by the table id + the `named_table` name atom, with `None` = `'$end_of_table'` and the read gate ahead of consumption. Detail: `select/CONTEXT.md`.
- **A BODY runtime failure yields the atom `EXIT`; a GUARD failure skips the clause** (a guard that would raise or is non-boolean skips it; a capability gap propagates as a typed error); boolean *bodies* still render as the interned `true`/`false`.
  `match_delete` returns the deleted count, not the BIF's `true`; `size` counts objects, not keys; a `Table` cannot own atom state (indices are global); the registered `name` and the `named_table` flag are independent.

## Concurrency, fixation & sharing
- **`Table` is `Send + Sync` and shareable across processes**: plain `Eterm` data + a `Box<dyn Interior>` (`Interior: Send + Sync`) + a `TermStore` (`unsafe impl Send/Sync`, rationale: no interior mutability, every storage-reaching method takes `&mut self`).
- **`SharedTable`'s coarse lock is the whole story — no lost updates.** One `write()` guard spans a whole check-then-act sequence (`insert_new`, `update_counter`, `select_replace`), so concurrent writers lose nothing; fine-grained `{write_concurrency}` affects throughput only, never results.
- **`ets:safe_fixtable/2` fixation = deferred reclamation.** While fixed, every removed object's storage goes onto `deferred_frees` (and `delete_all_objects` defers each root instead of `reset()`ing); unfixing flushes them, so `ets:info(T, memory)` holds while fixed and falls at unfix. `deferred_frees` is not counted in `memory()`.
- **Subterm sharing (the copy-boundary trim).** `TermStore::copy_term` shares exactly the one literal whose liveness the crate can prove — the global empty tuple; `beam_term::literal::LiteralArea` literals are deep-copied (the area may be dropped and the crate holds no handle). `{keypos, N}` keys live inside the stored tuple; `compressed` is parsed/reported with no storage effect.

## Test Strategy

- **Integration suites over the public API** (`tests/ets_*.rs`, `tests/select.rs`, `tests/match_spec_run.rs`; helpers `tests/common/`, live-`erl` plumbing `tests/common/oracle.rs`) — one file per concern, most asserting exact values against the live oracle: accounting/reclamation, the access matrix per operation, the behavioural per-operation files, and the deterministic split-crossing `first`+`next`/`last`+`prev` walks interleaved with mutation. Per-file detail: `tests/CONTEXT.md`.

## Known Issues (honest gaps — not full parity)
- **The raw `Table`/`TableAccess` read family still returns bare `Eterm`s that alias table storage** — a caller can hold one past its borrow (or past `take`, or past the table) and then observe words reclaimed by a later same-size insert; the one exception inside the tagged views is `TableWrite::as_requester`, whose reads are bare aliasing `Eterm`s **by design** (`view/tests.rs::as_requester_reads_are_a_documented_residual_hazard`). The fix is a cross-crate decision (`ETS_SURFACE.md` §7.6 names every method that should move behind the tagged-term discipline).
- **`Concurrency` is advisory.** `read_concurrency`/`write_concurrency` are parsed and reported but there is no fine-grained locking; the only synchronisation is `SharedTable`'s coarse `Arc<RwLock>`, and fine-grained locking is a **throughput** workstream, never a correctness gap. `{write_concurrency, auto}` and `{debug_hash_fixed_number_of_locks, N}` **are** representable (`WriteConcurrency::Auto`/`FixedLocks(n)`); only the *rendering* stays host-side.
- **Owner death is driven by the runtime, for named and unnamed tables alike.** `beam_rt::runtime::ets_owner::drain_ets_owner_exits` (over the `ProcessTable`'s `EtsExitObserver`) calls `Table::owner_died`; `beam_bifs`'s `ets:new/2` records the owner, and the roster is `TableRegistry::handles_owned_by` (**unnamed** tables included) with the `OwnerIndex` unioned in for the registered name a `named_table`'s drop releases (`ETS_SURFACE.md` §7.4).
  **Ownership modelling has no pid/liveness concept** — `give_away/3` treats `None` as the non-pid/dead-pid target (both `badarg`), and delivering the transfer message and dropping the table stay the runtime's job.
- **`TableInfo::entries` renders `owner` as `undefined` and `id` as a small integer** — the crate's own 15-field proplist has no pid/ref term, so the `beam_bifs` bridge substitutes the recorded owner pid and the tid reference; the BIF output matches the oracle.
- **`ets:setopts/2` is modelled for `{heir, …}` and `{protection, Access}` only.** Every other option (`safe_fixtable`, `{write_concurrency, _}`, …) is the `beam_bifs` parser's `badarg`, and `ets:info(T, holder)` is `badarg` in the oracle so none is emitted.
- **Scalar `lookup_element` is a deliberate typed refusal for the multi kinds** — a scalar `Eterm` cannot express the oracle's *list*; the faithful forms are `lookup_element_all{,_or}`, and the BIFs branch on `kind().is_multi()`, so the refusal is unreachable through the BIF surface.
- **`tab2file`/`file2tab`/`tabfile_info` are BLOCKED, not merely out of scope.** The table-file format is `{Header, Objects, Footer}` with every field an ETF term, so it needs `beam_codec` plus file I/O (`beam_io` is wave 5 — an upward edge, forbidden for a wave-1 crate); `tab2list` + `first`/`next` remain the enumeration path (`ETS_SURFACE.md` §5).
- **Operations served by the `beam_bifs` bridge over this crate's primitives, not here:** `update_element/4` (`Table::member` + `Table::update_element` plus the validated default object), the `foldl`/`foldr` BIFs (they need the `FunCaller` seam) and `whereis/1` (over the name registry).
  Still **missing** (`ETS_SURFACE.md` §1–§5 names the owner and blocker for each): `table/1,2`, the remaining `ets.erl` helpers (`from_dets/2`, `to_dets/2`, `init_table/2`, `test_ms/2`, `i/0..3`, `fun2ms/1`, `repair_continuation/2`) and the seam-backed `internal_request_all/0` typed gap (`ets:clear/1` and `ets:size/1` do not exist in OTP 29). The limited forms *are* implemented; their opaque continuation terms and the bare-vs-`{Results,'$end_of_table'}` shaping are the bridge's.
- **`match_spec_run` accepts a RAW spec, unlike the oracle**, which requires `ets:match_spec_compile/1` first; this crate has no compiled-spec *term*, so `run.rs` compiles the raw spec and the bridge maps `match_spec_compile/1` onto the compiled `MatchSpec`.
- **Named-table lookup-by-name is the runtime's job.** `Table` exposes `name()`/`is_named()` only; the name→table registry is `beam_bifs::ets::TableRegistry` (this crate holds no global state).
- **A hash-kind continuation is an ordinal into iteration order; an `ordered_set`'s is a key anchor.** The ordered form (an **exclusive** `next`/`prev` bound) is oracle-verified across a mutation *including the anchor's own deletion*; the hash kinds keep the ordinal because ERTS's cursor there is a bucket/index, so a mutation at or behind it can skip or repeat an object across a resume straddling it — never a typed error, and never a wrong result for a mutation-free walk.
- **Deep-copy covers every kind the oracle accepts in `ets:insert/2`** — immediates, cons cells, tuples, flat **and hash** maps, funs (all three kinds), boxed leaves (float, bignum, internal ref, on-heap bitstring), external pid/port/reference, and sub-bitstrings / off-heap refc binaries (re-materialised as self-contained on-heap bitstrings); the residual typed gaps (`BadArg`, never a wrong result) are a bare `BinRef` root, a native record (`RECORD_SUBTAG`), the reserved boxed subtags, a bare header word, and a malformed `ErlSubBits`.
- **`ets:take/2` retains the checked-out object's arena until the table drops.** `Table::take` copies the removed object out and `relinquish`es the copy: `store.words()` drops by its word count, but the words stay **valid** and never return to the free lists — so take churn grows `blocks` (bounded by the total taken volume) until `store.reset()`/`ets:delete_all_objects/1` or a table drop.
- **The match-spec compiler's typed divergences** (never a wrong result; head-**map** patterns, map **guards** and map **bodies** are oracle parity): `self/0` resolves through the thread-local `SelfHook`, default typed `badarg` (so an *un-hooked* `self/0` guard skips its clause and an un-hooked `self/0` body is `badarg`); integer arithmetic leaving the 60-bit small range through `DefaultArithHook` is `unsupported_ets`; and a **body** runtime failure yields the atom `EXIT` **from the caller's `AtomTable`**, so a host running a raising body must pre-intern `EXIT` (an uninterned one ⇒ `badarg`).
- **Three aliasing paths are NOT closed by the A.1 copy boundary**, each leaving a raw `Eterm` (a word pointing outside any `TermStore`) reachable after the storage it names can be reclaimed: (a) the **heritage gift** — the raw heir primitives (`Table::set_heir`, `Table::setopts(SetOpt::Heir)`, `TableAccess::setopts`, `TableWrite::set_heir`) store the caller's gift **verbatim**, while only `install_heir`/`copy_heir` deep-copy (`table/ownership.rs`); (b) **match specs / continuations** — `select::compile` copies nothing and a `MatchContinuation` holds that spec **plus** an `ordered_set` anchor key aliasing `TermStore` storage, and the continuation itself lives in `beam_bifs`'s registry (`src/select/CONTEXT.md`); (c) `do_update_counter`'s mid-loop error window (`src/table/CONTEXT.md`).
  Reclamation is **address-reusing** (exact-word-count free lists), so a freed alias usually reads a *different live object* rather than faulting; the hard invalidation point is `TermStore::reset` — `ets:delete_all_objects/1` on an **unfixed** table and `Drop for TermStore` — which deallocates every block.
- **Two match-spec corners live in `src/select/CONTEXT.md`.** `erlang:match_spec_test/3`'s `trace` dialect is left-open (typed `unsupported` — it needs a trace-**runner** subsystem, not a lint-only subset; the `table` dialect *is* implemented), and `select_replace/2`'s static key check has two approximated exotic shapes (a call-shaped raw tuple inside a `{const, X}` subterm compared against a literal head tuple, and the double-tuple unwrap inside a const subterm) — reachable only from hand-written specs.
- **`cmp_arith`'s big-integer↔float key comparison is a best-effort `f64` approximation** (a `beam_term` gap): `number_as_f64` rounds an out-of-range bignum to `±inf`; every representable integer/float pair is exact.
- **The B+-tree's `>= MIN_OCCUPANCY` floor below the root is held up by the delete unwind alone.** `merge` drops the parent's separator and child before the parent's own under-full check runs and asserts nothing about the result, and `collapse_root` only collapses a *root* branch that dropped to a single child, so nothing in the production code forbids an internal node from holding a **single** child — a branch is guaranteed only to be non-childless.
  Only the caller-level rebalance restores the floor and only the test-only `Tree::check_invariants`/`assert_occupancy_floor` assert it, so the shape is reachable only through merge-cascade churn: legal for the invariant set the code states, never observably wrong for a lookup, a walk or `size`.

## Host adoption (`beam_bifs` / `beam_rt`)
The whole `ets:*` BIF surface, the name→table registry and the option parser live in `beam_bifs` (`src/ets/`; detail in `../beam_bifs/src/ets/CONTEXT.md`), which owns the access gate, the continuation/compiled-spec registries, whole-table `ets:delete/1` (this crate has no whole-table-delete primitive), and the `SendHook` delivery of `{'ETS-TRANSFER', …}`.
It also installs the two match-spec seams around **every** match-spec evaluation (`ets/self_hook.rs::SpecEval::install(ctx.self_pid())` — the `SelfHook` plus the arbitrary-precision `ArithHook` for the guard's lifetime), so a `self/0` guard/body sees the caller's pid and big-integer arithmetic is exact.
`beam_rt` drives owner death (`drain_ets_owner_exits` → `Table::owner_died`, the drop and the transfer message) and builds the `{'ETS-TRANSFER', …}`/tid terms.
What stays host-side by construction: the `auto`/`FixedLocks` `write_concurrency` **rendering** (`TableInfo::write_concurrency` is a `bool`; the profile travels alongside the table in the registry).
Which side owns each operation, and each runtime-level gap's required API: `ETS_SURFACE.md` §1–§7.
