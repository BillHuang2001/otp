# `beam_codec` — External Term Format (ETF) Codec

## Intent
Owns the **External Term Format**: `term_to_binary`/`binary_to_term` encode+decode, the distribution payload/control-term format and the ETS wire format — the in-memory half of contract **A.5** (workspace `../CONTEXT.md` §1, Part I §A.5; Stage 0 of Part II §H).
Dependents: `beam_dist` (handshake/control/payload terms), `beam_message` (terms across the copy boundary), `beam_ets` (`DFLAG_ETS_COMPRESSED` term blobs), `beam_rt` (`term_to_binary/1`, `binary_to_term/1`).
Decoding is **allocation-aware**: terms go into a caller-supplied [`beam_alloc::Heap`] and atoms resolve through a caller-supplied [`beam_term::AtomTable`], so *one* path serves distribution, ETS and `term_to_binary`; a large binary's **payload** may go off-heap via the optional [`OffHeapBinaries`] host (§Off-heap binaries).
Ground truth = legacy C `../../erts/emulator/beam/external.c` (`erts_encode_ext`/`erts_decode_ext`, `enc_term`/`dec_term`), `external.h` (tags), `erl_term.h` + `erl_map.h` (layouts), and `../../erts/doc/guides/erl_ext_dist.md`.
All tag values/encodings are **wire-frozen**; read the C, never modify it.

### `src/reader.rs` / `src/writer.rs` — the wire seam
- `pub struct Reader<'a>` — bounds-checked BE cursor: `new(&'a [u8])`, `position()`, `remaining()`, `is_empty()`, `u8()`, `u16be()`, `u32be()`, `u64be()`, `bytes(n) -> Result<&'a [u8]>`, `rest()`, `peek_u8()`.
- `pub struct Writer` — growable sink: `new()`, `with_capacity(n)`, `u8/u16be/u32be/u64be(v)`, `bytes(&[u8])`, `len()`, `is_empty()`, `as_slice()`, `into_vec()`, `clear()`, plus crate-internal `patch_u32be(pos, value) -> Result<()>` — the only backward write (patches the `NEW_FUN_EXT` size field), bounds-checked (`pos + 4 <= len`, else `BadArg`), never panics/short-writes.

### `src/atom_cache.rs` — atom-cache seam: read (`AtomCache`) + write (`AtomCacheWriter`)
- `pub struct AtomCache` (**read**): 8 segments × 256 = 2048 slots — `new()`, `set(index: u8, atom)`, `get(index: u8) -> Option<Atom>`, `clear()`. The *distribution header* (`68`/`78`) is `beam_dist`'s; `beam_dist` fills this cache and the `Decoder` resolves `ATOM_CACHE_REF` (`82`) through it (unset index ⇒ `BadArg`).
- `pub trait AtomCacheWriter` (**write**): `fn intern(&mut self, atom: Atom, atoms: &AtomTable) -> Option<u8>`, installed with `Encoder::with_atom_cache`; a cached atom encodes as `ATOM_CACHE_REF` (`82`) + index (C `enc_atom`, `external.c:2877`, `get_iix_acache_map` first; `-1` ⇒ inline). `beam_dist::OutboundAtomCache` implements it (the persistent 8×256 classification lives in `beam_dist`).

### `src/off_heap.rs` — off-heap binary host seam (`OffHeapBinaries`)
Optional host hook letting a decoded large binary's **payload** live off the process heap (the module doc-comments carry the full contract). Mirrors `AtomCacheWriter`: the codec owns the wire, the host owns the state.
- `pub trait OffHeapBinaries { fn alloc_refc_payload(&mut self, bytes: &[u8]) -> Result<*mut Eterm>; }` — the host allocates + **retains** the payload (typically a `beam_alloc::RefcBinary`) and returns the raw pointer to its **first data byte** — the `BinRef.val` value (`beam_term::refc::bin_ref_parts`'s `val` = `RefcBinary::data_ptr` cast to `*mut Eterm`).
- **Contract:** the pointer must stay valid/unmoved/readable at least as long as any term built from it (the host's store *is* the ownership record — the decoder keeps none, so releasing early dangles); the payload holds `bytes`; the first byte must be **word-aligned** (the low `BITSTRING_POINTER_FLAG_MASK` bits of `ErlSubBits::base_flags` are flags; `RefcBinary` guarantees this); never mutated afterwards; failure (e.g. OOM) is return-based.
- Installed with `Decoder::with_off_heap(self, host: &'a mut dyn OffHeapBinaries) -> Decoder<'a>`; **additive** (`Decoder::new`/`new_body`/`with_atom_cache`/`decode`/`finish`/`position`/`remaining` unchanged). No host ⇒ seam inert, every binary on-heap (same observable term).
- Ground truth: C `case BINARY_EXT/BIT_BINARY_EXT` (`external.c:4893-4980`) allocates off-heap via `erts_bin_nrml_alloc(NBYTES(size_in_bits))` and wraps with `erts_wrap_refc_bitstring(..., data, 0, size_in_bits)`; only `size_in_bits <= ERL_ONHEAP_BITS_LIMIT` is on-heap.
- **HANDOFF (owned elsewhere):** `beam_rt` must implement `OffHeapBinaries` (retain each `RefcBinary` + register it with `beam_gc::OffHeap`/MSO bookkeeping) and install it via `Decoder::with_off_heap`; until then the seam is opt-in/uninstalled and the runtime decodes on-heap.

### `src/compress.rs` — zlib plumbing for `COMPRESSED` (`80`)
Safe Rust (`flate2` zlib wrappers, no `unsafe`); owns only the RFC-1950 stream (the wrapper bytes are `encode`'s, recognising the wrapper is `decode`'s).
- `compress(data: &[u8], level: u8) -> Result<Vec<u8>>` — zlib at `level` `0..=9` (the C `{compressed, Level}`); out-of-range ⇒ `BadArg`.
- `decompress(data: &[u8]) -> Result<Vec<u8>>` — any zlib error (bad header, truncation, corrupt deflate, bad Adler-32) ⇒ `BadArg`; the output is capped at [`MAX_UNCOMPRESSED`] (32 MiB). It is the *declaration-free* helper (re-exported through `prelude`) and is **not** the decode path's entry point.
- `decompress_bounded(data: &[u8], limit: usize) -> Result<Vec<u8>>` — the decode path's helper: inflates and refuses to grow past `limit` (any zlib error, or an inflated length `> limit` ⇒ `BadArg`), so a payload the image's *declared* size admits is never rejected by a fixed ceiling. [`decode::decompress_wrapper`] calls it with that declared size, mirroring the C `binary2term_uncomp_size` behaviour (`external.c:1768-1781`).
- `pub const MIN_LEVEL: u8 = 0`, `MAX_LEVEL: u8 = 9`, `MAX_UNCOMPRESSED: usize`; `pub(crate) reject_bad_level(level) -> Result<()>`.

- Convenience (additive, existing signatures unchanged): `encode_term(Eterm, &AtomTable)` (with `131`), `encode_term_body(Eterm, &AtomTable)` (without) — both **uncompressed**; `encode_term_compressed(Eterm, &AtomTable, level: u8)`, `encode_term_body_compressed(Eterm, &AtomTable, level: u8)`, `encode_term_local(Eterm, &AtomTable, hash: u32)`, `encode_term_with_minor_version(Eterm, &AtomTable, MinorVersion)`.
- Funs, compression and the `LOCAL_EXT` wrapper are described under §Fun encodings, §Design Decisions (shrink rule) and §Term-layout ownership (the caller-supplied node hash).

#### Minor-version flavours (`{minor_version, N}`)
`parse_t2b_opts` (`external.c:1501-1516`) maps `{minor_version,N}` onto dflags; `TERM_TO_BINARY_DFLAGS` (`dist.h:138-139`) is `DFLAG_NEW_FLOATS | DFLAG_UTF8_ATOMS` with **no** `DFLAG_SMALL_ATOM_TAGS`:

| `MinorVersion` | atoms | floats |
|---|---|---|
| `V0` (`{minor_version,0}`) | `ATOM_EXT` (`100`) for a Latin-1 name (never `115`, any length), UTF-8 tags for a non-Latin-1 name | `FLOAT_EXT` (`99`), 31-byte text |
| `V1` (`{minor_version,1}`) | same as `V0` | `NEW_FLOAT_EXT` (`70`) |
| `V2` (default, `{minor_version,2}`) | `AtomEncoding` (UTF-8 by default) | `NEW_FLOAT_EXT` (`70`) |

- The crate-internal `AtomFlavour` projects the C `enc_atom` decision (`external.c:2906-2950`); the public `AtomEncoding::Latin1` (`DFLAG_SMALL_ATOM_TAGS` dist flavour — `115`/`100`, `unsupported` for a non-Latin-1 name) is consulted only under `V2`. Under `V0`/`V1` the `Latin1WideOnly` flavour always emits `ATOM_EXT` for a Latin-1 name and **falls back to UTF-8 tags** for a non-Latin-1 one (`external.c:2910`: `utf8_atoms || a->latin1_chars < 0`) — never `unsupported`.
- Floats: `NEW_FLOAT_EXT` + 8 IEEE-754 bytes when `DFLAG_NEW_FLOATS` (`V1`/`V2`); else `FLOAT_EXT` + a **fixed 31-byte** field — `sys_double_to_chars(f, buf, 31)` (= `snprintf(buf, 31, "%.20e", f)`, `SYS_DEFAULT_FLOAT_DECIMALS 20`) then zero-fill (`external.c:3840-3847`). `src/encode/float.rs`: Rust's `format!("{:.20e}", f)` matches glibc's correctly-rounded (round-half-to-even) mantissa but has a different exponent tail (`e0`/`e-5`/`e20`), so `normalize_exponent` rewrites it to C's always-signed ≥2-digit `e+00`/`e-05`/`e+20`; non-finite values use glibc's `inf`/`-inf`/`nan`. A >31-byte render is a `SystemLimit` (unreachable for finite `f64`).
- Byte-exactness: `tests/minor_version.rs` + `src/encode/float.rs` unit tests.

### `src/decode/` — the `Decoder` seam (`mod.rs` + `fun.rs` + `record.rs`)
- `pub struct Decoder<'a>`: `new(&'a [u8]) -> Result<Decoder<'a>>` (requires+consumes `VERSION_MAGIC`), `new_body(&'a [u8]) -> Decoder<'a>`, `with_atom_cache(&'a AtomCache)`, `with_off_heap(self, host: &'a mut dyn OffHeapBinaries) -> Decoder<'a>` (§Off-heap binaries), `decode(&mut self, &mut Heap, &mut AtomTable) -> Result<Eterm>`, `position()`, `remaining()`, `finish() -> Result<()>` (trailing bytes ⇒ `BadArg`).
- Convenience: `decode_term(&[u8], &mut Heap, &mut AtomTable) -> Result<Eterm>`.
- Funs are decoded **inside the shared term walker** (`src/decode/fun.rs`: `decode_export`, `decode_new_fun`, `decode_small_u32`, the wire-direct `decode_creator_pid`), so a fun nested in a tuple/list/map (a `.beam` `LitT` literal) decodes like any sub-term; the bitstring arms route on the bit size (§Off-heap binaries).
- `MAP_EXT` (`116`) materializes through `crate::term::make_map` (the canonical ERTS constructor) and the arm rejects a bit-31 pair count and a duplicate-key image (§Map decode).
- **`COMPRESSED` is top-level-only**: `decode_term` detects `bytes[0] == VERSION_MAGIC && bytes[1] == COMPRESSED_EXT` (≥6 bytes), reads the 4-byte inner size, inflates bounded by that declared size (`compress::decompress_bounded`), requires the inflated length to equal the declaration and decodes the body via `Decoder::new_body` + `decode` **without** `finish()` — bytes after the inner term are ignored (`binary2term_prepare`, `external.c:1744-1816`). The **plain** path keeps its strict `finish()`. A `Tag::Compressed` *inside* a term is malformed ⇒ `BadArg` (`external.c:1759`), never `unsupported`.
- **`LOCAL_EXT` (`121`)** consumes its 4-byte node hash and returns the following term (`external.c:5250-5254`); a short read ⇒ `BadArg`.
- **`DIST_HEADER` (`68`) is malformed, not a term**: the C has no `case DIST_HEADER` (`goto error`, `external.c:6464`) so `68` ⇒ `BadArg`; the `'D'`/`'E'`/`'F'` framing is wholly `beam_dist`'s (`../beam_dist/src/dist_header.rs`).

## Tag coverage (current)
**Encode + decode + byte-exact round-trip** (the full producible set):
`97, 98, 110, 111` integers (a big fitting a 60-bit small decodes to a small, as in C; any non-zero sign byte means negative — §Legacy and scalar wire rules);
`99`/`70` floats (decode both — a `70` must be finite; **encode `70`**, `99` only under `MinorVersion::V0`);
`100, 115, 118, 119` atoms (all decode; encode UTF-8, or the `{minor_version,0|1}` `ATOM_EXT`/UTF-8-fallback form);
`101, 114, 90` references; `102, 89, 120` ports (all decode; **encode always `120 V4_PORT_EXT`** with the full 64-bit id, as the C — `102`/`89` decode-only); `103, 88` pids (all decode; **encode always `88 NEW_PID_EXT`**) — the legacy forms carry the extra validation of §Legacy identifier forms;
`104, 105` tuples; `106` NIL;
`107` strings (decode ⇒ list of smalls; encode ⇒ `107` for a byte list ≤ 65535 else `108`); `108` lists (incl. improper tails);
`109`/`77` binary/bit-binary (decode on-heap `ErlHeapBits`, or — host installed and > `ERL_ONHEAP_BITS_LIMIT` bits — the off-heap `[BinRef][ErlSubBits]` pair; **encode handles both**, emitting `109` when byte-aligned else `77` — §Off-heap binaries);
`116` maps of any pair count — decode **canonicalizes** through `term::make_map` (flat ≤ 32 sorted, HAMT above; a bit-31 count or a duplicate-key image ⇒ `BadArg` — §Map decode), encode emits the term's **stored** order (flat = the caller/constructor order, hash = the reversed `map_pairs_storage_order` — §Map key encode order);
`82` atom-cache refs (resolved through an attached `AtomCache`; emitted whenever an `AtomCacheWriter` is attached);
`80` `COMPRESSED` (top-level zlib wrapper, inflated in `decode_term` bounded by the declared inner size; encode emits it only via `*_compressed`/`finish_compressed` and only when zlib shrinks the body, else the plain image);
`121` `LOCAL_EXT` (`[local]` wrapper — decoded inline past its 4-byte hash; encoded via `encode_term_local`/`finish_local`);
`67` `RECORD_EXT` (native records — §Records; layout is `beam_term::record`'s);
`112`/`113` `NEW_FUN_EXT`/`EXPORT_EXT` (funs — §Fun encodings).
**No recognized tag is left `unsupported`.** `unsupported` remains only for a *term kind* the wire cannot carry: an unrepresentable atom name, a `FunKind::Local` on **encode** with no [`FunIdentity`] (`error::unsupported_local_fun`, §Error surface), and an **internal pid/port immediate with no local node identity** (§Internal ids).
**Rejected as malformed `BadArg`** (exactly as the C): `68 DIST_HEADER` (a transport wrapper, never a term — `goto error`, `external.c:6464`), `117 FUN` (removed OTP 23, `external.c:6399-6404`), `78 NEW_CACHE` (dead `#if 0`, `external.h:77-81`).

### Legacy identifier forms (`101`/`102`/`103`/`114`)
The pre-`DFLAG_BIG_CREATION` identifier tags decode with their full C widths and their legacy validation, and re-encode to the modern forms the C always emits (`90`/`88`/`120`) — pinned byte-for-byte against `term_to_binary(binary_to_term(Img))` by `tests/port_ext_legacy.rs`:
- `PORT_EXT` (`102`) — `[PORT_EXT][node][id:4 BE u32][creation:1]` (`external.c:4685-4716`: `get_uint32` + `get_int8`; the sizing pass skips 5 extra bytes, `atom_extra_skip = 5`, `external.c:6210-6211`). The id is a full 32-bit word.
- `PID_EXT` (`103`) — `[node][number:u32][serial:u32][creation:1]` (`dec_pid`, `external.c:3141-3197`).
- `REFERENCE_EXT` (`101`) — `[node][id:4 BE u32][creation:1]`; `NEW_REFERENCE_EXT` (`114`) — `[len:2][node][creation:1][ids:len×u32]` (`external.c:4743-4784`). All three reference tags read their first id word **unconditionally** (before the creation byte for `101`, after it for `114`/`90`, `external.c:4752-4763`/`:4780`/`:4795`), so exactly `max(1, len)` id words are on the wire after the creation field — a `len == 0` image therefore stays stream-aligned and decodes to a **zero-id external ref** (the unconditional first id word is consumed for alignment but **no** ids are stored), re-encoding byte-exactly as the 11-byte `[90][0][node][creation]` image, matching the oracle **for a remote node** (a local-node image is demoted to 3 ids — see the demotion bullet below); only the pure 11-byte *input* form that omits the unconditional first id word is `BadArg`.
- **Tiny creation**: the 8-bit creation of `REFERENCE_EXT`/`NEW_REFERENCE_EXT`/`PORT_EXT`/`PID_EXT` must be ≤ 3 (`is_tiny_creation`, `external.c:71-72`) else `BadArg`.
- **`MAX_REFERENCE`**: the first id of `REFERENCE_EXT`/`NEW_REFERENCE_EXT` must be `< 1 << 18` (`262144`, `erl_term.h:771`; `external.c:4757`/`:4782`) else `BadArg` — an **unsigned** comparison, so a high-bit id is out of range too, and it is checked *before* the node is resolved, so it holds for a remote node as well. `NEWER_REFERENCE_EXT` has no *pre-node* bound, but the C re-checks `r0 >= MAX_REFERENCE` inside its **local-node** branch (`external.c:4807`): a *remote* node keeps any `r0`, while the local node (same sysname **and** creation) is `BadArg`. That local-node re-check is **not applied here** (the decoder never compares the node against the local node), so `<<131,90,0,1,119,13,"nonode@nohost",0,0,0,0,0,4,0,0>>` is `badarg` in the oracle and decodes here.
- **A local-node ref is demoted by the C, not here**: when the image's node *is* the local node the C builds an **internal** ref of exactly `ERTS_REF_NUMBERS` (3) numbers — a shorter id list is zero-padded, a longer one truncated (`external.c:4804-4860`) — so it re-encodes with `len = 3`. This decoder always builds the external layout and keeps the wire `len`, so a local-node image with `len != 3` (any of `101`/`114`/`90`) re-encodes differently from the oracle (a `len = 1` image: oracle `90,0,3,…`, here `90,0,1,…`). Remote-node images agree byte-for-byte.
- **`MAX_REF_IDS`**: a `NEWER_REFERENCE_EXT` id count above `ERTS_MAX_REF_NUMBERS` (5) is `BadArg` (§Constraints).

### Scalar wire rules (`SMALL_BIG`/`LARGE_BIG`, `FLOAT`/`NEW_FLOAT`, atoms)
- A bignum's sign byte is a **boolean**: `neg = get_int8(ep)` is only tested for zero-ness (`bytes_to_big`'s `if (xsgn) d = -d;`, `big.c:3446-3448`), so **any** non-zero sign byte means negative (`2` and `1` both negate), while a zero magnitude is `0` whatever the sign byte is (`external.c:4484-4486`). Leading zero bytes are stripped first (a magnitude fitting a 60-bit small decodes to a small, never a bignum). Pinned by `tests/scalar_ext_decode.rs`.
- `NEW_FLOAT_EXT` (`70`) must be **finite** — `if (!erts_isfinite(ff.fd)) goto error;` (`external.c:4667-4669`) — so an infinity or NaN is `BadArg`.
- `FLOAT_EXT` (`99`) is 31 bytes of a NUL-terminated `%.20e` rendering, but the decoder does **not** simply `strtod` it: `sys_chars_to_double` (`../../erts/emulator/sys/unix/sys_float.c:72-140`) accepts exactly `[+-]? DIGIT+ [.,] DIGIT+ ([eE] [+-]? DIGIT+)?` and requires a **finite** result, so `inf`/`-inf`/`nan`/`infinity`/`1e5` (no radix)/`1.`/`.5`/` 1.0`/hex floats/… are `BadArg` (Rust's `parse::<f64>()` would accept several). A `,` radix is accepted (the C retries with the flipped radix character, `sys_float.c:115-124`). Pinned by `tests/legacy_scalar_oracle.rs`.
- An atom name longer than `MAX_ATOM_CHARS` (255 **characters**, not bytes) is malformed: C rejects it in `erts_atom_put`/`erts_atom_get` (`atom.c:258-274`, `atom.c:392-418`) and `dec_term` turns that into `goto error` (`external.c:4529-4539`) ⇒ `BadArg` on **decode** (an over-long name on **encode** is a `SystemLimit`, §Constraints). Invalid UTF-8 under a UTF-8 atom tag is `BadArg`.

### Off-heap binaries (`src/off_heap.rs` + `decode_bitstring` + `make_refc_binary`)
`Decoder::decode_bitstring` routes by the **bit** size: `size_in_bits > ERL_ONHEAP_BITS_LIMIT` (512 bits = 64 bytes) **and** an installed host ⇒ `crate::term::make_refc_binary(heap, host, data, 0, size_in_bits)` (offset 0, size = `size_in_bits`, payload = the `len` bytes read) — for **both** `BINARY_EXT` and `BIT_BINARY_EXT`; otherwise `make_bitstring` (on-heap — identical to the behaviour with no off-heap seam). C `external.c:4893-4980`.
`make_refc_binary` allocates `ERL_REFC_BITS_SIZE` (8) words and calls `beam_term::refc::write_refc_binary`; it guards a `bytes` slice too short for the `offset_bits + size_bits` window, an overflowing window and a null/misaligned host pointer (⇒ `BadArg`, nothing written — the pair is allocated only after the payload exists, so a failed payload leaves the heap untouched) and passes `next = null` (the host store is the ownership record; nothing in this workspace walks the ERTS MSO `next` link).
The wire is `[len:4 BE][data]` for a binary and `[len:4 BE][bits:1][data]` for a bit binary — the length field comes **before** the trailing-bit count. `len` is attacker-controlled and checked against the bytes left in the cursor *before* any allocation (a lying length ⇒ `BadArg`, never a blind allocation); for `BIT_BINARY_EXT` the trailing-bit count must be `1..=8` and `len * 8 >= 8`, with `size_in_bits = len * 8 - (8 - bits)`. The C clears the last byte's unused trailing bits before copying; `make_bitstring`/`make_refc_binary` zero them, so no garbage from a hostile wire survives. Pinned by `tests/refc_decode.rs`.

### Internal ids — `NEW_PID_EXT` / `V4_PORT_EXT` from internal immediates
A runtime pid/port (`self()`, a spawned process, a port) is an **internal 60-bit immediate** (`beam_term::immediate`: `is_internal_pid`/`pid_number`/`pid_serial`, `is_internal_port`/`port_number`), *not* a boxed **external** id thing — so the boxed probes (`external_pid_parts`/`external_port_parts`/`external_ref_parts`) do not match it.
`Encoder::with_local_node(node: Atom, creation: u32)` supplies the **local node identity** (the `sysname` atom + the node's `creation`; node identity is `beam_rt`/`beam_dist`'s, so the caller passes it). With it set `encode` emits internally-tagged ids byte-identically to the oracle:
- internal pid ⇒ `NEW_PID_EXT` (`88`): `[node atom][number:u32 BE][serial:u32 BE][creation:u32 BE]` — e.g. `term_to_binary(self())` on `nonode@nohost`, id 10: `131,88,119,13,"nonode@nohost",0,0,0,10,0,0,0,0,0,0,0,0`;
- internal port ⇒ `V4_PORT_EXT` (`120`): `[node atom][number:u64 BE][creation:u32 BE]` (the C always emits the v4 form for a port, never `NEW_PORT_EXT`).

Without a configured local node an internal id stays **`unsupported`** (never a wrong image) — the codec cannot invent a sysname; a value merely *containing* one fails the same way (the encoder recurses). Internal **references** are not representable (no internal-ref layout; the runtime has no `make_ref/0`), so only the *external* ref forms are encoded (every decode form is accepted; §Term-layout ownership).

### Fun encodings (`EXPORT_EXT` `113` / `NEW_FUN_EXT` `112`)
Both fun tags are handled **inside the shared term walker** (`Decoder::decode`), so a fun nested in a tuple/list/map (a `.beam` `LitT` literal) decodes like any sub-term. The interior layout is `beam_term::fun`'s; this crate allocates the block (`beam_alloc`) and forwards to `write_fun_external`/`write_fun_imported` (`src/term/fun.rs`). `encode` probes the fun family with `is_any_fun` (via `fun_kind_term`) **before** the boxed-family probes (a fun header's distinct subtag makes the classification exact) and routes to `src/encode/fun.rs` (`encode_fun`/`encode_fun_external`/`encode_fun_imported`/`encode_fun_local`, imported+local sharing `encode_new_fun_ext`, the `size` field patched via `patch_u32be`).
- **`EXPORT_EXT` (`113`) ⇒ `FunKind::External`** — `[113][module atom][function atom][arity term]`, materialized as the 4-word `[header, module, function, arity]` block (`external.c:5006-5040`). The two atoms decode in stream order via `decode_node_atom` (interning follows the wire order); the arity is a **normal decoded term** that must be a small `>= 0` (C `is_small`/`signed_val`) else `BadArg`, and the term stores the **true** arity (descriptor word 3) while the 8-bit header field carries `arity & FUN_MAX_FIELD` — so `fun_arity_term` masks and `fun_true_arity_term` is exact, mirroring the oracle's split between `fun_info(F, arity)` and `term_to_binary/1`. One exception above 32 bits: the C's `Export` arity field is a `Uint`, so an arity `>= 2^32` is truncated to `arity & 0xFFFFFFFF` there and re-emitted as a small, while this tree keeps the full 60-bit value (`arity = 2^32` ⇒ oracle `97,0`, here `110,5,0,0,0,0,0,1`). Encode emits `[113][module][function][<true arity>]`.
- **`NEW_FUN_EXT` (`112`) ⇒ `FunKind::Imported`** — `[size:4 BE][arity:1][uniq:16][index:4 BE][num_free:4 BE][module atom][old_index term][old_uniq term][creator pid term][env…]` (`external.c:5102-5176`).
  - `size` is **read and ignored** (since OTP 23 the C may write a wrong total size, `external.c:5115`). On encode it is `4 + payload_len` — bytes from the size field's first byte through the end of the fun (C `ep - size_p`, `external.c:3363`, tag byte excluded). Verified against the oracle: `ftest:make3("aa","bb","cc")` → `131,112,0,0,0,86,…` with 82 = 86 − 4 payload bytes after the size field.
  - `old_index`/`old_uniq` must decode to **smalls** (C `is_small`) else `BadArg`; stored as the descriptor's `u32`s.
  - `num_free > MAX_ARG` (255) cannot fit the 8-bit header field ⇒ `BadArg` (never a corrupt header).
  - The creator pid is parsed **directly off the wire** by `decode_creator_pid` (only `PID_EXT` `103`/`NEW_PID_EXT` `88`; the C always emits `88`, `external.c:3989`), so no throw-away external-pid block is left on the caller's heap and the node atom is interned in wire order. A legacy `PID_EXT` creator must have a tiny (≤ 3) creation, else `BadArg` (the field goes through `dec_pid`; `external.c:5153-5160`, pinned by `tests/legacy_scalar_oracle.rs`). Anything else (incl. a `LOCAL_EXT` pid, unmodelled here) ⇒ `BadArg` — a **slight narrowing vs C** (which accepts any `is_pid`). Encode always emits `NEW_PID_EXT` via `encode_pid`.
  - **ENV ORDER — wire order is the env order**: stream element `k` is `env[k]`. The C decoder links `env[0]` first (`external.c:5171-5174`, `for (i = num_free-1; i >= 0; i--) funp->env[i] = next`) and the encoder pushes `env[num_free-1]…env[0]` onto a LIFO stack emitting `env[0]` first (`external.c:3991-3993`) — so decode reads and encode writes `env[k]` in order; nothing is reversed. (Confirmed empirically: flipping the wire-first env byte of `term_to_binary(ftest:make3("aa","bb","cc"))` changes the fun body's `x0`.)
  - `FunKind::Local` (the `make_fun3` closure) stores only its engine-internal descriptor (`[uniq: u64][index: u32]`) — no module / 16-byte `uniq` / creator pid. Encoded as `NEW_FUN_EXT` **iff** an [`FunIdentity`] was installed; the body is the C local-fun body (`external.c:3966-3993`): arity/index/`num_free`/env from the term, module/uniq/`old_index`/`old_uniq`/creator from the identity. Without an identity ⇒ `error::unsupported_local_fun()`, never a mis-encoded term.

### Fun identity (`FunIdentity`) — the local-fun encode input
`Encoder::with_fun_identity(FunIdentity)` is the additive, optional seam letting the runtime encode a `make_fun3` closure; `None` by default, so every existing signature and un-flavoured `encode_term` is byte-for-byte unchanged. Its fields mirror the C `ErlFunEntry` (§API Surface `src/encode/`); the term's own `index` (descriptor word 2) is the wire `index`, and its inlined `uniq: u64` is engine-internal, never on the wire. The runtime supplies it (it owns the running module and its MD5); faithfulness is pinned byte-exactly by `tests/local_fun_encode.rs::compiled_local_fun_encodes_byte_exactly_like_the_oracle`.

### Records (`RECORD_EXT` `67`)
Native records (the OTP 29 `ErtsRecordDefinition`/`ErtsRecordInstance` terms produced by the `records:*` BIFs, distinct from classic tagged-tuple records) decode/encode through **`beam_term::record`** (`../beam_term/CONTEXT.md`). Wire form (`external.c:4006-4036` encode, `:5257-5381` decode):
```text
[67][num_fields:4 BE][flags:1][module atom][name atom]
[num_fields × key atom]                 # DECLARATION order
[num_fields × value term]               # DECLARATION order
```
- `flags` is `0` (`is_exported == false`) or `1` (`true`); any other byte ⇒ `BadArg`.
- Keys and values are both in **declaration** order (the store is ascending atom-index order, so the encoder maps declaration → sorted rank through `field_order`, `erl_record.c:1072-1073`, and the decoder inverts it).
- A duplicate key ⇒ `BadArg`; a field count whose definition arity overflows `MAX_ARITYVAL` ⇒ `BadArg` (checked before any allocation — the C routes every decode failure, bounds included, to `B2TBadArg`, `external.c:1989-1991`); the record block is allocated only after every value decodes, so a malformed tail never leaves a half-built record.
- Code: `src/term/record.rs` forwards to `beam_term::record` (`is_record`, `make_record`, `record_block_words`, the `record_*` readers); `src/encode/record.rs` (`Encoder::encode_record`) and `src/decode/record.rs` (`Decoder::decode_record`) are the wire halves. `Encoder::encode` probes `is_record` **before** the boxed-family probes (a record header carries the distinct `RECORD_SUBTAG`).
- **The cached definition hash (definition word 2) is the real bit-exact `make_hash2`.** `crate::term::make_record` stores `beam_term::hashing::compute_record_definition_hash(def, atoms)` — `make_hash2({module, name, is_exported, keys-in-declaration-order})`, what C's `records_create_4` stores (`erl_record.c:1041-1046`) — not a placeholder. The circularity (`write_record` takes the hash as an explicit `Eterm`; the hash reads only module/name/`is_exported`/declaration-ordered keys) is broken by writing the block once with a placeholder, computing the hash from the resulting definition term, then rewriting the **same `hp`** with `make_small(hash as i64)` (idempotent; no setter added to `beam_term`); `Decoder::decode_record` passes its `atoms` through, so decoded records carry the real hash too.
- The hash is **not on the wire** (round-trips stay byte-exact) but *is* observable through term hashing: `beam_term`'s `make_hash2_from` seeds a record instance's hash from its definition hash, e.g. `phash2(record)`. Only the **definition** hash is interning-order independent; an instance's `phash2` total depends on the relative interning order of the record's key atoms, so a ≥2-field record instance total is not stable across VM starts. `tests/record_roundtrip.rs` pins the definition hash and the deterministic declaration-order tuple hash.

## Map key encode order
`encode_map`/`encode_hashmap_pairs` (`src/encode/mod.rs`) are the sole `MAP_EXT` (`116`) emitters; they **never** sort, deduplicate or re-canonicalize, both emit `K1,V1,…,Kn,Vn` (unsorted unless the `deterministic` dflag is set), but which order differs by representation:
- **Flat map** (≤ 32 pairs) — `encode_map` emits the map's **stored** pair order verbatim (C walks the flat arrays in order, `external.c:3746-3769`, `flatmap_get_keys`/`flatmap_get_values` + `ENC_MAP_PAIR`, so the wire order *is* the keys-tuple order). Order is the **constructor's** job, applied before the term reaches the codec — [`beam_term::map::write_map`] (used by `beam_engine`'s `…_map` opcodes and by this crate's `decode` via `crate::term::make_map`) sorts ≤ [`beam_term::map::MAP_SMALL_MAP_LIMIT`] (32) keys in `erts_cmp_flatmap_keys` order (`erl_utils.h:265-272`: two **atom** keys by atom-table index, every other pair by full term order); a flat map built directly on a heap (`beam_codec::term::make_flatmap`, `beam_term::thing::write_flatmap`) keeps the caller's pair order.
- **Hash map** (> 32 pairs, a HAMT) — `encode_hashmap_pairs` emits the C encoder's wire order, the **reverse** of the ascending node-slot pre-order: `crate::term::map_pairs_storage_order` (→ [`beam_term::map::map_pairs_storage_order`]) returns pairs in **ascending** node-slot pre-order (slots `0..sz`, descending depth-first at each), while the C encoder (`external.c:3745-3823`) pushes each node's slots onto a **LIFO** work stack and pops them (`WSTACK_POP` is a pre-decrement pop; the collision-node tuple takes the same path, `external.c:3415-3427`), visiting slots in **descending** index order — exactly `reverse(ascending pre-order)`, so the path reverses the pair list before emitting.

The `encode` dispatch reaches a map's pairs by two probes, in order: [`flatmap_parts`] (flat, ≤ 32) → `encode_map`, then `map_pairs_storage_order` (hash) → `encode_hashmap_pairs`; each matches exactly one representation, so the flat path is untouched.
A **locally built HAMT encodes byte-identically to the oracle**: `beam_term` drives the trie with the **bit-exact** `erts_map_hash` (`../beam_term/src/map.rs`) so the node structure matches ERTS's, and the reversal reproduces ERTS's `MAP_EXT` bytes for the same key set — pinned live (integer keys, stable across VM starts) by `tests/map_key_order.rs::hashmap_images_match_the_oracle_byte_exactly` (**33/40/50/64/100/1000** keys) and asserted ERTS-decodable by `oracle_accepts_our_hashmap_image`.
A decoded map re-encodes **byte-exactly** for non-atom keys: the decoder stores ERTS's canonical form (§Map decode) and the encoder reproduces the term's stored order, so `decode → encode` of an oracle image is the identity (pinned for a > 32-pair HAMT image by `tests/map_ext_decode.rs`).
**Atom-keyed multi-key maps are byte-comparable across implementations only when their atom tables agree**: a flat map's atom keys sort by **atom-table index**, which depends on the order atoms were first interned *during this VM start* (unstable across runs) — the same map can produce different `MAP_EXT` bytes in two fresh `erl` processes (shown live by `atom_keyed_map_bytes_depend_on_interning_order`). **Non-atom** keys need no such care, so the live oracle cross-checks use **integer-** (`oracle_and_our_encoder_agree_for_integer_keyed_maps`) and **binary-** (`binary_keyed_map_matches_the_oracle_byte_exactly`) keyed corpora; for atom keys the check mirrors the oracle's intern order first (`atom_keyed_map_matches_the_oracle_in_index_order_not_name_order`, `decoded_flatmap_canonicalises_into_atom_index_order`). A fixture whose atom interning differs (e.g. `tests/ground_truth.rs::literals_gen_server_decodes_with_its_export_funs`) asserts the canonical image is a **fixed point** rather than equal to the input bytes.
The **encoder must not sort**: the map's stored order is authoritative, so a `make_flatmap`-built map (which keeps the caller's order) must emit that order verbatim — pinned by `tests/map_key_order.rs::flatmap_pairs_encode_in_stored_order`.

## Map decode (ERTS canonicalization)
`Decoder`'s `Tag::Map` arm reads the 4-byte pair count — rejecting a count whose bit 31 is set (`(n >> 31) != 0`, `external.c:6311-6315`) — then the interleaved `K1,V1,…,Kn,Vn` pairs, and materializes the map through **`crate::term::make_map`**: the canonical ERTS constructor, which delegates to [`beam_term::map::write_map`] and produces either a **flat map** whose keys are sorted in `erts_cmp_flatmap_keys` order (at most [`MAP_SMALL_MAP_LIMIT`] = 32 pairs) or a **hash map** (HAMT, keyed by the bit-exact `erts_map_hash`) above that. This is exactly the `external.c:5438-5456` fixup (`erts_validate_and_sort_flatmap`, `erl_map.c:3187`; `erts_hashmap_from_array(..., 1)`, `erl_map.c:644`), so a decoded map carries ERTS's storage order and re-encodes byte-identically.
`write_map` **collapses** duplicate keys (last value wins), so the arm detects a duplicate by comparing the produced [`beam_term::map::map_size`] against the wire count and returns `BadArg` on a mismatch. ERTS **rejects** a duplicate-keyed image in both representations (`external.c:5448` `error_map_fixup`) — only `maps:from_list/1` collapses duplicates, never `binary_to_term/1`. Keys `1` and `1.0` are `=:=`-distinct and both survive.
Pinned live by `tests/map_ext_decode.rs`: a duplicate-key image is `badarg` in both implementations (same error class); an unsorted ≤ 32-pair image decodes to the oracle's canonical (sorted) term; the oracle's own 40-pair HAMT image decodes to a > 32-pair HAMT and re-encodes byte-identically; `1`/`1.0` stay two keys.

## Term-layout ownership
The boxed interior layout of floats, bignums, flatmaps and the external pid/port/ref blocks is `beam_term`'s (`src/thing.rs`, `../beam_term/CONTEXT.md`); this crate's `src/term/` only forwards to it. The bitstring block (`ErlHeapBits`/`ErlSubBits` + the off-heap `BinRef` pair) is `beam_term::bitstring`/`refc`'s and the record block `beam_term::record`'s; `src/term/binary.rs` is a **thin forwarder** keeping only the codec-side type/bounds guards and the `&[u8]` view construction. The off-heap **payload** behind a `BinRef` is not a term layout at all — it is the [`OffHeapBinaries`] host's (`beam_alloc::RefcBinary`), so the codec never owns it (§Off-heap binaries).
The codec's own layout-relevant policy is the **wire** form of a bignum magnitude — base-256 bytes (`big_to_bytes`/`bytes_to_big`, `big.c:3405-3490`): full eight bytes per non-leading digit, only the leading digit's significant bytes; `SMALL_BIG_EXT` carries the byte count while < 256, `LARGE_BIG_EXT` otherwise, wire bound `BIG_ARITY_MAX * sizeof(ErtsDigit)` bytes (`external.c:6146`).
- `VERSION_MAGIC` is **not** part of a distribution payload following a distribution header.
- The `LOCAL_EXT` (`121`) 4-byte field is a **node hash the caller supplies**: `Encoder::finish_local(hash)`/`encode_term_local(term, atoms, hash)` take it as an argument and `decode` consumes it without checking (matching C `dec_term`, `external.c:5250`). The hash (`local_node_hash`, seeded from monotonic time so it differs on every VM start) and its verification belong to the node-identity owner (`beam_rt`/`beam_dist`); the C verifies it in the sizing pass (`decoded_size`, `external.c:6437-6512`), which **`binary_to_term/1` always runs** — so the oracle answers `badarg` for an image whose 4-byte hash is not its own block hash, while this decoder returns the inner term (verified: `binary_to_term(<<131,121,0,0,0,0,97,5>>)` ⇒ oracle `badarg`, here `5`). No node-identity type is in this crate's scope.

## Constraints
- **Errors: `beam_common::{Result, BeamError}` only** — no crate-local error enum. **Never panic, never `unwrap()` runtime data, never silently truncate or mis-encode.** The class depends on the direction:
  - **Decode** (`binary_to_term`): malformed/truncated input, an unknown/obsolete tag, an invalid UTF-8 atom name, an atom name longer than 255 characters, a non-finite `NEW_FLOAT_EXT`, a bad legacy `FLOAT_EXT` spelling, a non-tiny legacy creation, a legacy first id ≥ `MAX_REFERENCE`, and **every length/arity/count bound** (`LARGE_TUPLE` arity > `MAX_ARITYVAL`, `LARGE_BIG` byte count > `BIG_ARITY_MAX * 8`, `NEWER_REFERENCE` id count > `MAX_REF_IDS`, `RECORD_EXT` field count, a `MAP_EXT` bit-31 count or duplicate key, a lying `STRING`/`LIST`/`BINARY` length) ⇒ `BeamError::BadArg`. The C routes every decode failure — bounds included — to `B2TBadArg` (`binary_to_term_int`, `external.c:1989-1991`), so `badarg` is always the oracle's answer.
  - **Encode** (`term_to_binary`): a value beyond a wire bound (an atom name > 255 characters, a tuple/flatmap arity past the encodable field, an internal id that does not fit its field, a `>u32` image length) ⇒ `BeamError::SystemLimit`.
  - Either direction: heap exhaustion ⇒ `BeamError::Alloc` (from `Heap`); **not-yet-supported ⇒ `error::unsupported(tag)`** = `BeamError::Raise(Raise::error(ExitReason::atom(error::UNSUPPORTED_REASON)))` (`UNSUPPORTED_REASON = "unsupported_external_term"`, detectable via `error::is_unsupported`).
  <a id="error-surface"></a>
  **Error surface (additive, `src/error.rs`).** Encoding a `FunKind::Local` fun with no supplied [`FunIdentity`] uses its own reason atom, kept distinct from `UNSUPPORTED_REASON` so a caller can tell "no identity to encode" from "tag not implemented": `pub const LOCAL_FUN_REASON: &str = "unsupported_local_fun"`, `pub fn unsupported_local_fun() -> BeamError`, `pub fn is_unsupported_local_fun(&BeamError) -> bool`. `UNSUPPORTED_REASON`/`unsupported`/`is_unsupported` unchanged.
- **Deps:** `beam_common`, `beam_term`, `beam_alloc`, `libc`, plus `flate2` (zlib for `COMPRESSED`, pure-Rust `miniz_oxide` backend: `default-features = false, features = ["rust_backend"]`, no C toolchain, no build-time network beyond crates.io; `MIT OR Apache-2.0`, Part I §G.6). `flate2` is declared in **this crate's `Cargo.toml`**, not hoisted into `[workspace.dependencies]` (`erts_rust/Cargo.toml` is outside this node) — centralising it (a `flate2 = { version = "1", … }` workspace entry + `flate2.workspace = true` here) is owed at the crate-layer node. Any *other* dependency edge requires reporting to the crate-layer node (`../`).
- **No wire-format duplication**: tag values and field widths come from `tag.rs` only; the term layer never re-derives a tag from a term layout.
- Files target ~1000 lines; one responsibility per file. Licensing Apache-2.0.

## Design Decisions
- **Two layers, one `unsafe` module.** The *wire layer* (`tag`, `reader`, `writer`, `atom_cache`, `off_heap` and every byte-level `encode`/`decode` step) is safe Rust. The *term layer* (`src/term/`) forwards to `beam_term`, its `unsafe` limited to `beam_alloc` allocation calls, the `beam_term` accessors (an `Eterm`'s validity is a caller invariant) and the minimal type/size guards that turn a wrong-kind term into a `BeamError` instead of UB; enforcement is mechanical (`#![deny(unsafe_code)]` + the single `#[allow(unsafe_code)] mod term;`).
- **This crate does not own the term layout — `beam_term` does**; the decoder writes straight into `beam_alloc::Heap` + `beam_term::AtomTable` (no trait, no intermediate value tree). `src/term/mod.rs` forwards to the heap-agnostic `beam_term::thing` writers/readers and `beam_term::{tuple_size, tuple_element, car, cdr}`, keeping only allocation sizing (`beam_term::thing::*_size_words`) and the guard constants (`BIG_ARITY_MAX`, `EXTERNAL_THING_HEAD_SIZE`, `U32_PER_WORD`); `src/term/binary.rs`/`record.rs` likewise forward to `beam_term::{bitstring,refc,record}`.
- **Map decode delegates the canonical layout to the LCA writer.** `crate::term::make_map` just reserves `beam_term::map::map_words_capacity` words and forwards to `beam_term::map::write_map`, so the flat/HAMT threshold, the `erts_cmp_flatmap_keys` sort and the hash-trie shape are the layout owner's; the decoder adds only the two checks ERTS applies at the same seam (bit-31 count, duplicate key ⇒ `BadArg`, §Map decode). Encoding is the mirror image: the encoder never re-canonicalizes (§Map key encode order).
- **Off-heap binaries are a host seam, not codec state** (§Off-heap binaries): a decoded term outlives the decoder and an off-heap payload's reclamation follows the owning process heap, so the codec keeps no handle on it — the same "the codec owns the wire, the host owns the state" split as `AtomCacheWriter`.
- **Integer width policy mirrors C** (`external.c:3542-3599`): `< 256 ⇒ 97`; `98` when the value fits a signed 32-bit; else `110` when the magnitude's significant base-256 **byte** count < 256, else `111` — the count derived from the `ErtsDigit`s as `big_to_bytes` does (full eight bytes per non-leading digit, only the leading digit's significant bytes, at least one byte), high zero bytes stripped first. `110`/`111` decode to a small int whenever the value fits a 60-bit small, else a bignum.
- **Atoms are interned, never compared by name**: the decoder interns into the caller's `AtomTable` (insertion order = wire order), the encoder renders names from it. Atom length ≤ 255 *characters* (the OTP limit); longer ⇒ `BadArg` on decode / `SystemLimit` on encode (§Constraints).
- **Strings**: `decode` of `107` ⇒ a list of smalls (byte-list semantics); `encode` re-emits `107` for a proper byte list ≤ 65535, `108` once an element is not a byte.
- **Redundant identifier forms decode to one representation**: `101/114/90`, `102/89`, `103/88` all decode to the *external* thing layouts (the legacy forms with the extra validation of §Legacy identifier forms); the encoder always emits the modern form — `90`/`88` for references/pids, `120 V4_PORT_EXT` for ports — with `Len`/`Creation` widths per spec.
- **`VERSION_MAGIC` is handled by the constructor**, not the term loop (`Decoder::new` requires+consumes it, `new_body` does not; same split on `Encoder`), so one code path serves `term_to_binary` and the distribution payload.
- **`COMPRESSED` (`80`) is a *top-level-only* wrapper** (`external.c:1754-1813`): a `80` inside a term ⇒ `BadArg`. The 4-byte size is the inner **body** length (version byte excluded); the payload is a **zlib-wrapped** (RFC 1950) stream (`flate2`'s `ZlibEncoder`/`ZlibDecoder`, matching `deflateInit`/`inflateInit`, never raw deflate). Decode inflates bounded by that declared size (`decompress_bounded`), not by a fixed ceiling. Encoding writes the wrapper **only** on explicit `*_compressed` entry points and only when it *shrinks* the body — zlib gets a destination cap of `body_len - 5` (the C rule, `external.c:2276-2298`) — so `encode_term` is never compressed and `encode_term_compressed` matches the oracle's wrapper-vs-plain *choice* byte-exactly.
- **Only the *deflate bytes* of a compressed image are not byte-comparable with the oracle** (zlib (C) vs `miniz_oxide` produce different, equally valid streams): the `COMPRESSED` ground-truth vector pins the **decoder** and the **inner body**, not our compressor's bytes; interop is asserted live by `tests/compressed_oracle.rs`.
- **A native record's layout is `beam_term::record`'s; the codec only maps it to the wire.** `RECORD_EXT` (`67`) is *not* a tuple: the encoder probes `is_record` before the tuple/boxed families and forwards to `beam_term::record`, so the atom-index sort rule, `field_order` and the declaration↔sorted inversion stay in the layout owner. The cached definition `hash` is not on the wire but is the real `make_hash2` (§Records) because it is observable through term hashing.
- **The interop harness compares terms structurally, not by `beam_term::compare::eq`** (whose fallback for maps/identifiers compares the raw heap word): `terms_equal` (`tests/interop.rs`) walks the structure through the safe `beam_codec::term` accessors (atoms by name, floats by bits, bitstrings bit-by-bit) and never compares bytes across the oracle boundary (map key order and the `FLOAT_EXT`→`NEW_FLOAT_EXT` rewrite are not byte-canonical).

## Known Issues / Remaining gaps
- **A bitstring decodes on-heap by default; off-heap only when a host is installed.** `BINARY_EXT`/`BIT_BINARY_EXT` decodes to an on-heap `ErlHeapBits` unless `size_in_bits > ERL_ONHEAP_BITS_LIMIT` (512 bits = 64 bytes) *and* a `Decoder::with_off_heap` host is installed, in which case it becomes the off-heap `[BinRef][ErlSubBits]` pair over the host's refcounted payload (ERTS keeps a binary larger than `ERL_ONHEAP_BINARY_LIMIT` = 64 bytes off-heap behind a `BinRef`). The **wire** image is identical either way (what the vectors assert) and *encode* handles **both** representations (`tests/internal_ids.rs`); until a host is installed the runtime decodes large binaries on-heap (§Off-heap binaries handoff).
- **Maps encode byte-identically to ERTS in both representations, and decode canonicalizes like ERTS.** A hash map (HAMT, > 32 pairs) emits the C wire order, the reverse of `beam_term::map::map_pairs_storage_order`'s ascending node-slot pre-order (the C encoder pushes node slots on a LIFO work stack, `global.c` `WSTACK_POP`), which `encode` reproduces by reversing the collected pair list (`src/encode/mod.rs::encode_hashmap_pairs`); pinned live for 33/40/50/64/100/1000 integer-keyed pairs. Decode builds the canonical map through `crate::term::make_map` (§Map decode).
- **Constructed flat maps may hold any pair count** (`src/term/mod.rs::make_flatmap`): `n <=` `beam_term::map::MAP_SMALL_MAP_LIMIT` (32) forwards to `beam_term::thing::write_flatmap`; above it the crate-local `write_large_flatmap` emits the same order-preserving **flat**-map image — this cannot be delegated, since `beam_term::thing::write_flatmap` asserts that limit and `beam_term::map::write_map` would switch to a *hash* map (a different term kind), so there is no LCA producer for a > 32-pair flat map. The retained writer is pinned word-for-word to `beam_term::thing::write_flatmap` by `oversized_flatmap_layout_matches_beam_term`. A flat map of any size encodes and round-trips; pair order is preserved as-is; duplicate keys are **not** detected (that is the caller's concern — the map **decoder** detects them by comparing `map_size` against the wire count, §Map decode).
- **A decoded record carries the real definition hash, but this crate exposes no safe reader for it.** `crate::term::make_record` commits the bit-exact `make_hash2` value (§Records), yet `beam_codec::term` has no forwarder for definition word 2 — `record_definition_hash` exists in `beam_term::record`, and a forwarder in `src/term/record.rs` would need a `src/term/mod.rs` re-export. The hash is not on the wire, so this is not wire-observable.
- **`NEW_FUN_EXT`'s creator pid is read directly off the wire by `decode_creator_pid`** (accepting only `PID_EXT`/`NEW_PID_EXT`), so a `LOCAL_EXT` creator pid — unmodelled here — is `BadArg`: a slight narrowing vs C (which accepts any `is_pid`).
- **`decode_term`'s *plain* path is deliberately stricter than the oracle on trailing bytes** (it calls `finish()`), whereas `binary_to_term/1,2` (via `Decoder::decode` in `beam_bifs`) and `decode_term`'s *compressed* path tolerate them — a crate-local convenience contract, not observable through the BIF; pinned by `tests/compressed_decode.rs`.
- Identifiers always **decode** as *external* things (the wire has no internal-id form); internal pid/port *encode* goes through `Encoder::with_local_node` (§Internal ids). The codec holds no node registry — the local node identity is supplied by the caller.
- **`node` occupies the sysname-atom slot; `creation` is carried in C's off-heap `next` link (a documented M1 substitution).** In C `ExternalThing`'s first data word points to a *registered node* (carrying `sysname` + `creation`) and the second is the off-heap `next` link (`etp->node = erts_find_or_insert_node(sysname, cre, …)`). With no node registry here, the `node` slot holds the sysname atom and the unused `next` slot holds `creation` — yielding **exactly C's word positions/arities** (head 3 words, pid/port 4, ref `EXTERNAL_THING_HEAD_SIZE + ref_words/2 + 1`) while preserving the round-trip of `creation`. The pointer semantics land when a node-identity type exists (`beam_term`/`beam_dist`); only then can the local-node fast path replace the external forms.
- **`FLOAT_EXT` (99) is decoded via its validated `%.20e`-grammar string form**; encode emits `70` by default and `99` only under `MinorVersion::V0`, so a decode↔encode round-trip of a `99`-encoded float under the default flavour is representation-preserving, not byte-identical; under `V0` the 31-byte text form is reproduced exactly.
- **A non-finite float has no oracle-verifiable `FLOAT_EXT` golden.** The system `erl`'s `binary_to_term` aborts on a NaN/Inf `NEW_FLOAT_EXT` (`badarg`, §Scalar wire rules), so such a term never reaches `term_to_binary/2 {minor_version,0}`; `src/encode/float.rs` still renders `inf`/`-inf`/`nan` (the glibc `%.20e` spelling) rather than panicking.
- **The `LOCAL_EXT` (121) node hash is a caller-supplied value the codec does not verify.** `decode` consumes the 4 bytes without checking them (`external.c:5250`); the C verifies the hash only against `local_node_hash` in its sizing pass (`external.c:6437-6512`), and node identity is the caller's (§Term-layout ownership).
