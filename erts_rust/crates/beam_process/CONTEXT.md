# `beam_process` — Processes, Scheduler, Run Queues, Signals
## Intent
Owns the **OS-thread-level concurrency plumbing** of the Rust ERTS rewrite (Stage 5, Part II §H): the per-process control block (PCB), the four-level run queue, the cooperative scheduler loop, the **multi-scheduler (SMP) pool** (`SchedulerPool`: N scheduler threads over one shared table, per-scheduler run queues with work stealing, the `ThreadProgress` cross-scheduler barrier, the `TimerService` and two `DirtyPool`s), the **exit-signal / link / monitor** machinery (the decoupled per-process signal queue + its signal-message builders), the process table (`ptab`) with its local name registry, the **port-id table** and its ownership/link/monitor surface, and the local records for **remote (distributed) links/monitors**.
It is what makes Erlang **processes** real — isolation, `spawn`, links, monitors and exit propagation — the process half of workspace `../CONTEXT.md` §1 **A.1**.
It is consumed by `beam_bifs` (spawn/send/receive/`process_info`/`monitor`/`link` BIFs), `beam_io` (ports + the process side of I/O completion) and `beam_rt` (boot/CLI/`system_info`).
It **drives** `beam_gc` (collector + MSO) at safepoints and **uses** `beam_message` (`Queue` mailbox + `send`/`receive` copy engine) — it reimplements neither.
Legacy C ground truth (read-only `../../erts/emulator/beam/`; the Routing Table maps each to its module): `erl_process.{c,h}` (PCB/scheduler/run queues), `erl_proc_sig_queue.c`, `erl_monitor_link.c`, `erl_ptab.{c,h}`, `erl_process_dict.c`, `erl_vm.h` (`MAX_REG`/`MAX_ARG`), `erl_thr_progress.c`, `erl_hl_timer.c`, `erl_nfunc_sched.c`.
**Attribution boundary** (a C-deletion record must not attribute these here): the allocators (`erl_alloc*.c`, `erl_goodfit/bestfit/afit/ao_firstfit_alloc.c` → `beam_alloc`), the message copy engine (`erl_message.c`/`copy.c` → `beam_message`), crash dumping (`erl_process_dump.c`/`erl_crash_dump.c` → `beam_rt`'s `crash_dump.rs`); microstate accounting (`erl_msacc.c`) and flexible counters (`erl_flxctr.c`) are modelled by no crate (`beam_rt` lists the `mc_*`/`scheduler_wall_time` BIFs as a native gap); `erl_thr_queue.c`, `erl_sched_spec_pre_alloc.c`, `erl_process_lock.c` are unmodelled; time services (`time.c`/`erl_time_sup.c`) are `beam_bifs`'s time BIFs / `beam_rt`'s, and this crate's `timer.rs` is the `erl_hl_timer.c` analogue.
## Milestone-1 scope
Two scheduler fronts share the **same** slice logic — `scheduler::{slice_begin, slice_end}` (with `run_one` = both halves around one full-budget runner call) plus `drain_woken_into`: the single-threaded `Scheduler` loop (slice semantics frozen) and the SMP `SchedulerPool` (N threads over one shared table), so SMP adds *concurrency* and a bounded lock hold (one reduction **quantum**, `SchedulerConfig::set_lock_quantum`, default `DEFAULT_LOCK_QUANTUM = 256`), not a second scheduler.
"Correct" means the pid table, the four-level run-queue order, message delivery, the decoupled per-process signal queue, the monitor/registration surface, the process-dictionary and saved-argument sub-rootsets, the port ownership/link/monitor surface, remote links/monitors through the `DistSignalRouter` seam, and a safepoint GC over the process root set all match the C/oracle for the common cases and are test-covered; deliberate gaps are under Known Issues.

- `process.rs` → `Process` (the PCB), `ProcessState`, **`DeliverOutcome { Enqueued, Woke }`** (the resume-on-send verdict of `Process::deliver`), `ProcessFlags`; `deliver`/`deliver_simple`/`receive`/`wake`, `status`/`status_atom`, `new`/`with_policy`/`with_policy_and_priority`; the collection doors `collect`/`collect_kind` (kind-pinned: runs **exactly** the requested `CollectionKind`, never choosing and never escalating) / `ensure_capacity`/`collect_if_needed` and the **no-relocation** `grow_nursery`; the decline gate `has_unpublished_roots()` and the host's additive `CollectionGate { declines_relocation(&mut self, receiver: &Process) -> bool }`; the two split borrows `heap_and_off_heap_mut`/`heap_and_mailbox_mut`; the off-heap seams (next bullet); and the `max_heap_size` policy half — `set_max_heap_size`/`max_heap_size`, `max_heap_usage`, `heap_limit_verdict(prospective_words)`/`current_heap_limit_verdict`, `max_heap_verdict`/`take_max_heap_verdict`.
- **Off-heap seams (frozen).** `owned_off_heap()` is the read-only roster handle `beam_gc::HeapFootprint::of` takes; `off_heap_binary_bytes()` reports the **host-asserted** `set_off_heap_binary_bytes(n)` figure when one is installed (the engine machine's reservoir, which the PCB cannot see) and the roster-derived sum otherwise — so a `max_heap_size` charge and a footprint report can legitimately differ, and the host owns the asserted number's accuracy; the three sweeps are `sweep_off_heap_binaries` (declared-dead), `sweep_off_heap_binaries_reachable` (reachability-driven; declines and retains everything for a process with unpublished roots) and `retain_off_heap_binaries(predicate)`.

- `run_queue.rs` → `Priority { Max=0, High=1, Normal=2, Low=3 }` + `LEVELS = [Max, High, Normal, Low]` (the scheduling **precedence**, NOT the derived `Ord`), `RunQueue` (four per-priority FIFOs); the C's `RESCHEDULE_LOW` deferral is what the four-FIFO form replaces.
- `scheduler.rs` → `RunOutcome { Yield, Wait, Suspend, Exit(Eterm) }`, **`ProcessRunner`** (the engine seam: a runner counts its own reductions and returns `Yield` at its budget — the scheduler never pre-empts), `Scheduler` (`enqueue(_with_priority)`, `set_priority`, `run_slice(_with_ports)`, `run_ready(_with_ports)`, **`resume_woken`** — the resume-on-send half, `set_ports`/`take_ports`), and the shared `pub(crate)` `slice_begin`/`slice_end`/`run_one` + **`drain_woken_into`** (the wake sweep, driven over the scheduler's own reusable `woken` scratch so it allocates nothing after warm-up); `DEFAULT_REDUCTIONS_PER_SLICE = 4000`.
- `smp/` → `SchedulerPool`, `SchedulerConfig` (`set_lock_quantum`), `SchedulerStats`/`SchedulerStat`, `SharedProcessTable`; the **BINDING** locking discipline and the bounded-quantum rule (`run_locked_quanta`) are in `src/smp/CONTEXT.md`.

- `monitor.rs` → `MonitorRef { id: u64 }` (+ `to_eterm`, which refuses an id past `MAX_SMALL` with `SystemLimit`, and `from_eterm`) with the one **non-mint** constructor `from_id` (an explicitly *derived* id — today the unnamed-ETS-table tid, whose id must be the table handle — which draws nothing from the shared space and consumes nothing; its uniqueness is the caller's claim); **`RefAllocator`** — a **zero-sized handle** onto the single shared local reference-id space `beam_common::next_ref_id`, with **no private counter**, so no two local producers (monitors/aliases, `make_ref/0`, timers, `seq_trace`, NIF resource terms) can ever issue the same id; `UnaliasMode { ExplicitUnalias, Demonitor, ReplyDemonitor }`, `AliasEntry`, `MonitorKind { Process, Port }`, `PortWatch`, `Monitor`/`MonitoredBy` (**field sets frozen**), `Monitors`, `payload_is_down_for`.
- `ptab.rs` → `ProcessTable` — the signal/link/monitor hub and name registry: slots + free list, `alloc_pid`/`insert`/`take`, the name registry (`name_of`/`register_name`), `deliver`, signal servicing (`service_signals(_with_ports)` at schedule-in, the **receive-scan** `service_receive_signals(pid)`, which applies only the *receive-applicable* head signals strictly FIFO, discards an `Ignore` head, stops before the first `Terminate` head, never terminates/cascades and takes no `PortTable`), links/monitors/aliases, the wake accessors **`drain_woken`/`drain_woken_into`/`woken`**, the remote record tables (`remote_links`/`remote_monitors`/`remote_watchers`), the collection gate, the reservation surface, and the route-free inbound receipt primitives (see below); `Slot { serial, process }`, `NamedTarget { name, node }`, `ExitEffect`.
- `reserve.rs` → `Reservations` (the per-table claim store) + `Reservation { id(), pid(), number(), serial() }`, a `Copy` handle carrying its issuing table's tag so a **foreign** handle is `badarg`; plain values only (no term, no heap, no GC root, no `unsafe`, `Send + Sync` — which is what keeps `SharedProcessTable`'s two `unsafe impl`s sound); a reservation is explicitly consumed or cancelled (**no `Drop` arm**), and the guarantee is that a stale/cancelled/consumed handle can never install a process and never leaks.
- `exit_observer.rs` → `ProcessExitObserver { process_exited(&ProcessExit<'_>) }` + `ProcessExit { pid, reason, name, port_monitors }` (invoked once per death by `terminate_into`).
- `remote.rs` → `RemotePid { node, number, serial, creation }`, `RemoteRef { node, ids, n_ids, creation }` (a peer-minted external reference, decomposed), `PidTarget { Local, Remote }`, `RemoteMonitor` (outgoing), `RemoteWatcher { reference, watcher, kind }` + `RemoteWatcherRef { Local(MonitorRef), Remote(RemoteRef) }` (incoming, keyed by the whole reference identity), `DistSignal`, and **`DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()> }`** — the outbound distribution seam, implemented downstream over `beam_dist` (no crate dependency); `route` must serialise synchronously, because a `reason` may live in the signaller's heap.
- `port.rs` → `PortTable` (`alloc`/`alloc_owned`/`release`/`close` + the ownership/link/monitor accessors), `PortMonitor`, `PortClose`.
- `max_heap.rs` → the authoritative `max_heap_size` policy (the C `MAX_HEAP_SIZE(p)`/`MAX_HEAP_SIZE_FLAGS(p)` pair): `MaxHeapFlags { kill, error_logger, include_shared_binaries }` (`Default` = the C `H_MAX_FLAGS`), `MaxHeapSetting { size, flags }` (`unlimited(flags)`/`is_unlimited()`/`violates_floor(min_heap_words)` — the oracle's `size != 0 && size < min_heap_size` rule, single-sourced for the parse site — and `verdict(usage)`, the **strict-`>`** decision), `MaxHeapUsage { heap_words, off_heap_binary_bytes }` with `charged_words(flags)` = heap capacity + (with `include_shared_binaries`) `ceil(bytes / size_of::<Eterm>())`, and `HeapLimitVerdict { Within, Kill, Log }`. `Kill` = the host must self-exit the process with the **bare atom `killed`** (not `kill`, not an exception); `Log` = an `=ERROR REPORT====` with `Context: maximum heap size reached` after which the process **keeps running**; there is deliberately **no** `Raise` variant, because the oracle has no exception path for this limit.
- `scratch.rs` → `CollectionScratch` (crate-internal, `pub(crate)`): the per-collection reused buffers, owned once per `Process`; `error.rs` → `pub(crate)` error constructors only (no new error type).
### Cross-module binding rules
- **Eager-vs-queued signalling (`ptab.rs`).** A signalling operation **enqueues** a `PendingSignal` on the receiver (copying the reason into its own heap) — never applies it inline; servicing happens at the receiver's schedule-in (`service_signals`, from `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is *not* the currently `Running` process (`apply_exit_signal`/`terminate`/`send_exit` share one rule: every receiver joins the service worklist unless `ProcessState::Running`). `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. A **remote** (external-pid) or **port** signal bypasses the queue entirely (no `trap_exit` policy to defer), so `node_down`/`port_closed` materialise it straight into the mailbox. An exit signal's `ExitFamily` rides the queued signal and is read back at service time, so the local link cascade still decides a `kill` as a **link** exit; `apply_exit_signal`/`send_exit`/`send_exit_term` are the explicit `erlang:exit/2` family, while the `terminate_into` link loop, `node_down` and `port_closed` are the link family.
- **Collect-then-apply worklist (`ptab.rs`).** `ProcessTable` is the single place that mutates ≥2 processes (the C ptab lock domain); its cross-process operations collect the intended effects into a worklist and apply it after the mutation pass. M1 is single-threaded, so the table holds `Process` values directly.
- **Split borrows (`process.rs`).** `heap_and_off_heap_mut()` (young heap + off-heap table, drives `beam_message::Fragments::move_into`) and `heap_and_mailbox_mut()` (young heap + mailbox, drives `beam_message::send_fragmented`) are the only two `*_mut` pairs with a real caller need; each destructures `self` into two disjoint `&mut` fields in safe Rust and **must not** be joined into one raw-pointer accessor.
- **Frozen field sets.** `Monitor`/`MonitoredBy`/`PortWatch` are constructed by struct literal from `beam_rt`, so no field may be added (the `monitor/3` user tag lives in a private `ProcessTable` side table instead); `Process`'s field shape and `ProcessExit<'a>`'s private-fields-plus-accessors shape are frozen the same way.
- **`DistSignalRouter` is OUTBOUND only** (local → remote), and it stays that way. `DistSignal` keeps the link exit (`Exit`) and `erlang:exit/2` (`Exit2`) apart and adds `Link`/`Unlink`/`Monitor`/`Demonitor`/`MonitorExit`. The crate also owns the inbound (receipt) **primitives** — `ProcessTable::{record_remote_link, apply_remote_exit_signal, unlink_from_remote, unlink_ack_from_remote, monitor_from_remote, monitor_from_remote_ref, demonitor_from_remote, demonitor_from_remote_ref, remote_watchers, remote_monitor_down, set_group_leader_from_remote, group_leader}` — which take the **already-parsed** pieces of a `DOP_*` and never route (the C's receipt arms do not echo the opcode they received, `dist.c:2258`). A wire reason is **materialised on the recipient before it is embedded**: the builders copy a non-immediate reason onto the recipient's heap — or into the message's heap fragment when that heap refuses — so a queued `{'EXIT',…}`/`{'DOWN',…}` never points into the host's recycled per-drain decoder arena; `node_down`'s immediate reason is embedded verbatim, and its record purge covers all three directions, including the **incoming** `remote_watchers` entries naming the lost node. The `_ref` spellings key a `RemoteWatcher` by the whole reference identity, so two distinct peer references never collapse. Decoding the wire and choosing which primitive to call remains `beam_rt`'s (`../beam_rt/src/dist_client.rs`), as does the `DistSignal`→`Dop` adapter.
- **`Message::from` must be an immediate** — a producer contract, reasoned in `KNOWN_ISSUES.md`.
## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only — never a crate-local error enum, never `panic!`/`unwrap()` on runtime data. Unknown pid/name/ref ⇒ `BeamError::TermNotFound`; a malformed pid term or out-of-range register index ⇒ `BeamError::BadArg`; pid/port space exhaustion ⇒ `BeamError::SystemLimit`; `beam_term::TermError` is reconciled upstream, so `?` crosses the boundary.
- **Heap exhaustion (`AllocKind::Heap`/`AllocKind::Message`) is collect-grow-and-retry, not fatal OOM.** During a delivery **or a signal build** the receiver's nursery is collected, grown on demand, and the operation retried **once** (propagating the retry's own `BeamError::Alloc`) — `Process::deliver` and the `ptab.rs` signal builders (through the shared `grow_receiver_for_signal`) implement it. An ordinary **`receive` park is a legal direct-copy target**: the park holds `ParkExemption::LiveFloats` only, and the parked engine publishes its host-held terms through the `Registers::extra_roots` seam (`../beam_rt/src/runner/entry.rs`), so `has_unpublished_roots()` is **false** there and the message is copied straight into the receiver's heap. The three refusal classes are a **`Running`** receiver (its own machine's x/stack/float registers live outside `Process::regs`), a **relocation-exempt** one (the host holds live terms the root set does not publish), and a destination still full after collection + growth. A refusal has two sources — the crate-owned `has_unpublished_roots` (the O(1) predicate, tested **first**) and the host's installed `CollectionGate` (OR-ed with it) — and either takes the same refusal: no collection, no growth, no relocation (the no-relocation `grow_nursery` is unaffected), so the payload goes into a `beam_message::HeapFragment` instead (the C's model, `erl_proc_sig_queue.c`), at **both** refusal sites: the apply-time message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) and the enqueue-time reason copy (`copy_reason_onto` → `enqueue_down_signal`/`enqueue_exit_signal`, which build the message the queue would have materialised and wake a blocked receiver themselves). The one refusal still surfaced is the exit **policy** one — an exit signal to a **non-trapping** receiver, which would have to *terminate* it, and a termination is the caller's cascade rather than a message; a collection/growth refused for an exempt process is the typed `relocation_exempt` raise. A raw `AllocKind::Heap`/`AllocKind::Message` reaching a caller therefore means the receiver's relocating collection was **declined** or its policy could not grow the nursery to fit the payload; with an unbounded policy and published roots every payload is delivered into the grown young heap.
- **Inside `terminate_into` a per-peer signal-build (or `route`) failure is *not* propagated** — the process is already reclaimed, so it is logged via `beam_common::beam_error!` and the cascade continues.
- **`unsafe` is confined** to the modules that touch raw words: `monitor.rs` (message/ref builders) and `remote.rs` (the external-pid thing via `beam_term`'s `unsafe` predicates, tuple/ref words via `beam_alloc::Heap::alloc_words`), plus `src/smp/mod.rs`'s two documented `unsafe impl Send`/`Sync for SharedProcessTable` — nothing else in the SMP pool. `process.rs` holds **no production `unsafe`** (the off-heap reachability sweep reads a reachable `BinRef`'s payload word through `beam_gc`'s safe `ReachableObject` view). Every `unsafe fn` has a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale (`../beam_common/src/safety.rs`); `unsafe_op_in_unsafe_fn` stays clean. Everything else is safe Rust, with synchronisation via `parking_lot` mutexes/condvars + atomics.
- **Never assume a different term layout** — build/inspect terms only through `beam_term`'s public accessors + `beam_alloc::Heap`'s builders; pid/port immediates are bit-exact with `beam_term::immediate` (`make_internal_pid`/`pid_number`/`pid_serial`).
- **Reuse, do not reimplement:** the mailbox is `beam_message::Queue`; the copy engine is `beam_message::{send, receive, CopyContext}`; the heaps are `beam_gc::AnyCollector`/`beam_gc::HeapSpace`/`beam_alloc::Heap`; the off-heap objects are `beam_gc::MsoHandle`/`beam_message::OffHeapTable`.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`, `beam_message`, `libc`, `parking_lot`; adding a dependency edge requires reporting to `../`. `beam_engine` is **NOT** a dependency (the `ProcessRunner` trait keeps the DAG acyclic).
- Files target ~1000 lines, one responsibility per file, Apache-2.0. Three files are over it, deliberately: `src/ptab.rs` (the table + signal hub) and `src/process.rs` (the PCB + its collection root set) stay whole because their servicing/root-set logic is coupled to private fields (`slots`/`atoms`/`refs`/`ready`; the PCB's own heap/mailbox/off-heap tables) a sibling module cannot reach, and `src/scheduler.rs` is just over. All three are structural-debt candidates if they grow further or field visibility widens.

## Known Issues (intentionally NOT covered in Milestone-1)
Current-state gaps and deliberate deviations: each is a typed `unsupported`/`badarg`/`relocation_exempt` refusal or a documented, test-pinned divergence — never a wrong result.
**`KNOWN_ISSUES.md` carries every bullet in full, with its C file:line citations, oracle anchors and test pins.** The classes it covers:
- **Monitor/alias/tag refusals**: no reference alias on a port monitor or a remote target; a `{tag, T}` must be heap-independent (immediate or literal-area); no `TimeOffset` kind; `monitor_node` out of scope; a named port monitor is `unsupported`.
- **Signalling deviations**: the born-down `noproc` DOWN is delivered **eagerly** (so `message_queue_len` is 1 where the oracle reports 0); the signal queue is not cross-ordered with the mailbox; not every self-queued signal is serviceable inside one slice.
- **The GC-relocation producer contracts**: a producer's `Message::from` must be an immediate; `Process::deliver`'s `term` and `port_closed`'s `reason` must not reside in the receiver's own young heap; the host's `CollectionGate` is asked **second** and must assume neither that it is called for every receiver nor that it has a side effect.
- **Off-heap reclamation residuals**: a copy-engine binary is not auto-registered; a process with unpublished roots is retained wholesale (its decline valve).
- **SMP gaps**: opportunistic (never wake-a-peer) work stealing, an exclusive table lock so processes do not run in parallel, no dirty-job term plumbing, no `ThreadProgress`↔`beam_alloc` delayed dealloc, no port-task balancing, no `+S`/`+SDcpu`/`+SDio` parsing.
- **Priority/queue gaps**: no port tasks, no shared NORMAL/LOW physical queue, `save_calls`' effect unmodelled.
- **Pre-emption is `beam_rt`'s runner's obligation** (budget + `RunOutcome::Yield`); the scheduler never pre-empts.
- **Host-owned gaps**: `process_flag`'s `min_heap_size`/`min_bin_vheap_size`/`fullsweep_after` previous-value arms, the off-heap (`off_heap`) message queue, `port_info`'s `queue_size`/`locking`.
- **`ProcessId::to_eterm` is unchecked** (see `HANDOFFS.md`), and a distributed-spawn reservation has no `Drop` arm by design.
- **The compatibility gate is the sibling harness's**, not this crate's; its counts drift, so none are quoted here.

## Notes for Agents
- **This crate quotes no throughput ratio of its own.** The process-side send/wake/receive path is measured by `examples/perf_delivery.rs`, one rooted collection's scaffolding by `examples/perf_collection.rs`, and the control-signal fragment reservation by `examples/perf_signal_fragment.rs`; all three are recorded with their method and load caveat in `PERF.md`; end-to-end target-project figures live in `../tools/bench/RESULTS.md`, which is authoritative — read the numbers there, never a copy.
- Read `../CONTEXT.md` (crate-layer contracts, the `Process`/`Scheduler` seam) and `../../CONTEXT.md` §1 A.1/§3/§5 before changing this crate. Ground truth is the legacy C listed above — **read it; never modify it.** Module-level notes (the GC root-set rule, the `Registers`/FR hand-off, PCB/heap address stability, pre-emption as the runner's obligation, the split-borrow rule, the SMP `!Send` workaround's causes, the oracle probes) live in `src/NOTES.md`.
- Build/test with the manifest path: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_process` (sandbox `$HOME` is read-only — always the wrapper). Never `cd`; never touch `../../tools/`.
- **A collection FREES memory, so a pre-collection heap pointer is a use-after-free.** A collapse drops every retired space and may replace the current young space, and a fullsweep drops the old mature space — so a host-held `Eterm`, a saved `*mut Eterm` from `alloc_words`, or a nested `Machine`'s `x`/`stack`/`fr` that the root set did not publish dangles after `collect`/`collect_kind`/`ensure_capacity`/`collect_if_needed`. Re-obtain `heap_mut()` after any collection; never cache a heap pointer across one. The remaining three rooting rules are in `src/NOTES.md` §module-notes (an in-heap reference must be a root; `Process::regs` is a host-published snapshot the scheduler never writes; `port_monitors` is deliberately not a root).
- **Reading a nursery's cost from outside** — which accessor discriminates a bounded steady state from an accumulating chain (`young_space_count`/`collection_debt`, the curated growth-table entries, `stats()` vs `minor_gcs`, why `young().base()` is not evidence) — is `src/NOTES.md` §process.rs.
- **Per-collection bookkeeping allocates nothing in steady state.** `Process` owns **one** `CollectionScratch` for its lifetime and `begin()` clears all three buffers unconditionally, so the flat root slice, the mailbox-drain list and the off-heap reachability set are never allocated per collection (capacity survives, including across a failed round); the walk-free fast paths are `sweep_off_heap_binaries_reachable_from` (no owned binary), `sweep_off_heap_binaries` (nothing declared dead) and `record_max_heap_verdict` (unlimited setting). The collector's own per-call allocations remain `beam_gc`'s (`../beam_gc/src/CONTEXT.md`).
- **Adoption notes for `beam_rt`/`beam_bifs`** (do NOT edit them from here): the crate-side seams a host still has to call — and the list of points already wired — are in `HANDOFFS.md`.
