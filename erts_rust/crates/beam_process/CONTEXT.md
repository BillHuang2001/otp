# `beam_process` — Processes, Scheduler, Run Queues, Signals
## Intent
Owns the **OS-thread-level concurrency plumbing** of the Rust ERTS rewrite (Stage 5, Part II §H): the per-process control block (PCB), the four-level run queue, the cooperative scheduler loop, the **multi-scheduler (SMP) pool** (`SchedulerPool`: N scheduler threads over one shared table, per-scheduler run queues with work stealing, the `ThreadProgress` cross-scheduler barrier, the `TimerService` and two `DirtyPool`s), the **exit-signal / link / monitor** machinery (the decoupled per-process signal queue + its signal-message builders), the process table (`ptab`) with its local name registry, the **port-id table** and its ownership/link/monitor surface, and the local records for **remote (distributed) links/monitors**.
It is what makes Erlang **processes** real — isolation, `spawn`, links, monitors and exit propagation — the process half of workspace `../CONTEXT.md` §1 **A.1**.
It is consumed by `beam_bifs` (spawn/send/receive/`process_info`/`monitor`/`link` BIFs), `beam_io` (ports + the process side of I/O completion) and `beam_rt` (boot/CLI/`system_info`).
It **drives** `beam_gc` (collector + MSO) at safepoints and **uses** `beam_message` (`Queue` mailbox + `send`/`receive` copy engine) — it reimplements neither.
Legacy C ground truth (read-only `../../erts/emulator/beam/`; the Routing Table maps each to its module): `erl_process.{c,h}` (PCB/scheduler/run queues), `erl_proc_sig_queue.c`, `erl_monitor_link.c`, `erl_ptab.{c,h}`, `erl_process_dict.c`, `erl_vm.h` (`MAX_REG`/`MAX_ARG`), `erl_thr_progress.c`, `erl_hl_timer.c`, `erl_nfunc_sched.c`.
**Attribution boundary** (a C-deletion record must not attribute these here): the allocators (`erl_alloc*.c`, `erl_goodfit/bestfit/afit/ao_firstfit_alloc.c` → `beam_alloc`), the message copy engine (`erl_message.c`/`copy.c` → `beam_message`), crash dumping (`erl_process_dump.c`/`erl_crash_dump.c` → `beam_rt`'s `crash_dump.rs`); microstate accounting (`erl_msacc.c`) and flexible counters (`erl_flxctr.c`) are modelled by no crate (`beam_rt` lists the `mc_*`/`scheduler_wall_time` BIFs as a native gap); `erl_thr_queue.c`, `erl_sched_spec_pre_alloc.c`, `erl_process_lock.c` are unmodelled; time services (`time.c`/`erl_time_sup.c`) are `beam_bifs`'s time BIFs / `beam_rt`'s, and this crate's `timer.rs` is the `erl_hl_timer.c` analogue.
## Milestone-1 scope
Two scheduler fronts share the **same** slice logic — `scheduler::{slice_begin, slice_end}` (with `run_one` = both halves around one full-budget runner call) plus `drain_woken_into`: the single-threaded `Scheduler` loop (slice semantics frozen) and the SMP `SchedulerPool` (N threads over one shared table), so SMP adds *concurrency* and a bounded lock hold (one reduction **quantum**, `SchedulerConfig::set_lock_quantum`, default `DEFAULT_LOCK_QUANTUM = 256`), not a second scheduler.
"Correct" means the pid table, the four-level run-queue order, message delivery, the decoupled per-process signal queue, the monitor/registration surface, the process-dictionary and saved-argument sub-rootsets, the port ownership/link/monitor surface, remote links/monitors through the `DistSignalRouter` seam, and a safepoint GC over the process root set all match the C/oracle for the common cases and are test-covered; deliberate gaps are under Known Issues.

### Cross-module binding rules
- **Eager-vs-queued signalling (`ptab.rs`).** A signalling operation **enqueues** a `PendingSignal` on the receiver (copying the reason into its own heap) — never applies it inline; servicing happens at the receiver's schedule-in (`service_signals`, from `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is *not* the currently `Running` process (ERTS's early signal handling): `apply_exit_signal`/`terminate`/`send_exit` share one rule — every receiver joins the service worklist unless `ProcessState::Running`. `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. A **remote** (external-pid) or **port** signal bypasses the queue entirely (no `trap_exit` policy to defer), so `node_down`/`port_closed` materialise it straight into the mailbox.
  An exit signal's `ExitFamily` is carried **on the queued signal** (`PendingSignal::Exit`'s `family`) and read back at service time by `apply_head_signal`, so the local link cascade — which defers to the receiver's schedule-in — still decides a `kill` as a **link** exit.
  `apply_exit_signal`/`send_exit`/`send_exit_term` are the explicit `erlang:exit/2` family, while the `terminate_into` link loop, `node_down` and `port_closed` step 2 are the link family.
- **Collect-then-apply worklist (`ptab.rs`).** `ProcessTable` is the single place that mutates ≥2 processes (the C ptab lock domain); its cross-process operations collect the intended effects into a worklist and apply it after the mutation pass. M1 is single-threaded, so the table holds `Process` values directly.
- **Split borrows (`process.rs`).** `heap_and_off_heap_mut()` (young heap + off-heap table, drives `beam_message::Fragments::move_into`) and `heap_and_mailbox_mut()` (young heap + mailbox, drives `beam_message::send_fragmented`) are the only two `*_mut` pairs with a real caller need; each destructures `self` into two disjoint `&mut` fields in safe Rust and **must not** be joined into one raw-pointer accessor.
- **Frozen field sets.** `Monitor`/`MonitoredBy`/`PortWatch` are constructed by struct literal from `beam_rt`, so no field may be added (the `monitor/3` user tag lives in a private `ProcessTable` side table instead); `Process`'s field shape and `ProcessExit<'a>`'s private-fields-plus-accessors shape are frozen the same way.
- **`DistSignalRouter` is OUTBOUND only** (local → remote), and it stays that way. The crate now also owns the inbound (receipt) **primitives** — `ProcessTable::{record_remote_link, apply_remote_exit_signal, unlink_from_remote, unlink_ack_from_remote, monitor_from_remote, monitor_from_remote_ref, demonitor_from_remote, demonitor_from_remote_ref, remote_watchers, remote_monitor_down, set_group_leader_from_remote, group_leader}` — which take the **already-parsed** pieces of a `DOP_*` (an `RemotePid`, a `MonitorRef` *or* a decomposed peer `RemoteRef`, a reason term) and never route: the C's receipt arms do not echo the opcode they received (`dist.c:2258` `break; /* Done */`). A wire reason is **materialised on the recipient before it is embedded**: `apply_remote_exit_signal`'s trap arm and `remote_monitor_down` build one empty `OffHeapTable` per call (a wire payload carries no off-heap handles) and the builders copy a non-immediate reason onto the recipient's heap — or into the message's heap fragment when that heap refuses — so the queued `{'EXIT',…}`/`{'DOWN',…}` never points into the host's recycled per-drain decoder arena; `node_down`'s reason is an immediate and is embedded verbatim. `node_down`'s record purge covers all three directions, including the **incoming** `remote_watchers` entries naming the lost node (a dead node's monitor can never be resolved nor demonitored). The `_ref` spellings key a `RemoteWatcher` by the whole reference identity, so a peer's wire reference is stored faithfully (no lossy `u64` pack: two distinct peer references never collapse). Decoding the wire and choosing which primitive to call remains `beam_rt`'s (`../beam_rt/src/dist_client.rs`), as does the `DistSignal`→`Dop` adapter.
- **`Message::from` must be an immediate** — a producer contract, reasoned in Known Issues below.
## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only — never a crate-local error enum, never `panic!`/`unwrap()` on runtime data. Unknown pid/name/ref ⇒ `BeamError::TermNotFound`; a malformed pid term or out-of-range register index ⇒ `BeamError::BadArg`; pid/port space exhaustion ⇒ `BeamError::SystemLimit`; `beam_term::TermError` is reconciled upstream, so `?` crosses the boundary.
- **Heap exhaustion (`AllocKind::Heap`) is collect-grow-and-retry, not fatal OOM.** During a delivery **or a signal build** the receiver's nursery is collected, grown on demand, and the operation retried **once** (propagating the retry's own `BeamError::Alloc`) — the policy `Process::deliver` and the `ptab.rs` signal builders (through the shared `grow_receiver_for_signal`) implement. A receiver whose relocating collection is **declined** — by the crate-owned `Process::has_unpublished_roots`, or by the host's installed `CollectionGate` (`declines_relocation`, consulted first at every signal site and at `ProcessTable::deliver` and OR-ed with the crate-owned predicate) — never collects or grows **on demand** for a delivery: the crate-owned predicate covers a **relocation-exempt** receiver (whose host holds live terms the root set does not publish) and a currently **`Running`** one (whose own machine's x/stack/float registers live outside `Process::regs`, a host-published snapshot refreshed only at a heap-admission point or a park, so a mid-slice collection would relocate the heap against a stale root set and recycle live words), and the host gate covers a receiver whose live root set is not fully scanned by its collector. Either source takes the same refusal — no collection, no growth, no relocation (the collect-then-grow `ensure_capacity` route is what is refused; the no-relocation `grow_nursery` is unaffected by the flag) — so a control signal such a receiver cannot take is put in a `beam_message::HeapFragment` instead (the C's model, `erl_proc_sig_queue.c`), whichever of the two sites refused it: the **apply-time** message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) or the **enqueue-time** reason copy (`copy_reason_onto` → `enqueue_down_signal`/`enqueue_exit_signal`, which build the message the queue would have materialised straight from the enqueue site, since a queued signal's reason can live nowhere but the receiver's own heap, and wake a blocked receiver themselves). The one refusal still surfaced is the exit **policy** one — an exit signal to a **non-trapping** receiver, which would have to *terminate* it, and a termination is the caller's cascade rather than a message; a collection/growth refused for an exempt process is the typed `relocation_exempt` raise. Because the nursery grows on demand, a refused delivery — the raw `AllocKind::Heap`/`AllocKind::Message` a caller's heap-fragment fallback keys on (`../beam_rt`'s `deliver_message`) — means either that the receiver's relocating collection was **declined** (no collection was attempted) or that its heap policy could NOT grow the nursery to fit the payload (e.g. a `max_heap_words` cap, or a collection that cannot make room); with an unbounded policy and published roots every payload is delivered into the grown young heap.
- **Inside `terminate_into` a per-peer signal-build (or `route`) failure is *not* propagated** — the process is already reclaimed, so it is logged via `beam_common::beam_error!` and the cascade continues.
- **`unsafe` is confined** to the modules that touch raw words: `monitor.rs` (message/ref builders) and `remote.rs` (the external-pid thing via `beam_term`'s `unsafe` predicates, tuple/ref words via `beam_alloc::Heap::alloc_words`), plus `src/smp/mod.rs`'s two documented `unsafe impl Send`/`Sync for SharedProcessTable` — nothing else in the SMP pool. **`process.rs` has no production `unsafe`**: the off-heap reachability sweep reads a reachable `BinRef`'s payload word through `beam_gc`'s safe `ReachableObject` view (`AnyCollector::for_each_reachable_object_view`), so no raw-pointer arithmetic of its own is needed. Every `unsafe fn` has a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale (`../beam_common/src/safety.rs`); `unsafe_op_in_unsafe_fn` stays clean. Safe Rust (production): `pid.rs`, `registers.rs`, `run_queue.rs`, `link.rs`, `monitor.rs` set logic, `process.rs`, `max_heap.rs`, `signal.rs`, `ptab.rs` bookkeeping, `signal_queue.rs`, `port.rs`, `progress.rs`, and all of `smp/`'s `queues.rs`/`worker.rs`/`stats.rs`/`pool.rs` + `timer.rs`/`dirty.rs` (synchronisation via `parking_lot` mutexes/condvars + atomics).
- **Never assume a different term layout** — build/inspect terms only through `beam_term`'s public accessors + `beam_alloc::Heap`'s builders; pid/port immediates are bit-exact with `beam_term::immediate` (`make_internal_pid`/`pid_number`/`pid_serial`).
- **Reuse, do not reimplement:** the mailbox is `beam_message::Queue`; the copy engine is `beam_message::{send, receive, CopyContext}`; the heaps are `beam_gc::AnyCollector`/`beam_gc::HeapSpace`/`beam_alloc::Heap`; the off-heap objects are `beam_gc::MsoHandle`/`beam_message::OffHeapTable`.

## Known Issues (intentionally NOT covered in Milestone-1)

Current-state gaps and deliberate deviations: each one is a typed `unsupported`/`badarg`/`relocation_exempt` refusal or a documented, test-pinned divergence — never a wrong result.
The classes are the monitor/alias/tag refusals and the eager `noproc` DOWN's timing, the message-envelope and GC-relocation producer contracts (with the host `CollectionGate`), the SMP pool's remaining gaps, the off-heap reclamation residuals, the `process_flag`/`spawn_opt`/`port_info` items owned by `beam_rt`/`beam_bifs`, and the one unchecked narrowing left in `ProcessId::to_eterm` (`HANDOFFS.md`).
- **A remote link is invisible to `process_info(P, links)`.** `link_term`'s remote branch and the inbound `record_remote_link` write the table's `remote_links` side table (`src/ptab.rs`), while the item is rendered from `Process::links()` (`../beam_rt/src/native/memory/mod.rs`) — so neither a locally initiated nor an inbound (`DOP_LINK`) remote partner ever appears there, whereas the C's links item walks the whole link tree including `ERTS_LNK_TYPE_DIST_PROC` (`erts/emulator/beam/erl_bif_info.c:575-587`, `:1758-1777`). `monitored_by` is the item that DOES surface inbound remote watchers, as external pids (`ProcessTable::remote_watchers` + `RuntimeContext::monitored_by_value`); `monitors` stays outgoing-only.
- **`port_closed`'s caller-supplied `reason` is not validated as heap-independent, and the two port builders route it through `build_signal_message`'s `src: None` arm**, which reuses the `reason` word verbatim after its one collect-and-grow retry (`src/ptab.rs:295-308`). Only the envelope `from` is the port immediate; the `reason` is whatever `ProcessTable::port_closed(ports, port, reason)` was handed. A host passing a term minted on the **receiver's own young heap** would therefore have the retry re-read a relocated-away word. `port_closed` has no production caller today (only `beam_process`'s own tests, all with immediate reasons), so the gap is latent — but a caller must pass an immediate or a term outside the receiver's young heap.
- **`Process::deliver`'s `term` has one unstated precondition: it must not reside in the receiver's own young heap.** The retry after `ensure_capacity` (`src/process.rs:1262-1263`) reuses the caller's `term` word, and a receiver-heap word is not in the root set unless the host published it — the collection would evacuate it as garbage. `beam_rt` satisfies this by building every delivery message on the arena / pooled BIF heap, and a **self-send** with a heap-resident term is caught by the `Running` half of `has_unpublished_roots`.
- **`slice_begin_inner` sets `ProcessState::Running` *before* `service_signals`** (`src/scheduler.rs:673` then `:684`), so every schedule-in signal build runs with `has_unpublished_roots() == true`. A signal whose build does not fit the receiver's nursery is therefore delivered **heap-fragment-resident** at schedule-in rather than by collecting — correct, but it makes fragments more common than the "declined relocation" framing suggests.
**`KNOWN_ISSUES.md` carries every bullet verbatim, with all C file:line citations and test pins.**

- **Reading a nursery's cost from outside: which accessors actually discriminate a bounded steady state from an accumulating chain.** `Process::grow_nursery` retires a space (it never frees it), so a caller that never collects is left with a chain whose per-growth retention is invisible to every *occupancy* query. The observables, with their exact semantics, are:
  - `collector().heap_size_words()` / `collector().total_heap_size_words()` are **summed over the whole chain** (`beam_gc::nursery::capacity_words` = `spaces().map(capacity_words).sum()`), i.e. capacities, not used words. `process_info(P, heap_size)`/`total_heap_size` and `erlang:memory(processes)` read exactly these (`beam_rt/src/native/memory/mod.rs:1121`, `context/memory_hook.rs`), so an un-collapsed chain **inflates them** — their constancy across two workload sizes is therefore positive evidence that something collapsed the chain.
  - A single space's capacity is always a **curated growth-table entry** (`beam_gc::policy::heap_sizes()` = 12, 38, 51, 90, 142, 233, 376, 610, 987, 1598, 2586, …): `Nursery::grow` targets `next_words(…)` and `Nursery::collapse` targets `young_after_collection(…)` or keeps the previous (curated) capacity. So a reported `heap_size` that is **not** a table entry (e.g. 1596) is necessarily a **chain sum** — do not infer "one space" from it.
  - `collector().minor_gcs()` is `minor_since_major`, **not** a total: every fullsweep zeroes it (`beam_gc::collector::collect_major`), and a chained nursery escalates to Major (`collect` picks Major when `mature.available_words() < nursery.used_words()`, both chain-wide). A flat `minor_gcs` therefore proves nothing about how many collections ran; the cumulative pair is `collector().stats()` (`minor_collections`/`major_collections`/`words_reclaimed`), and node-globally `beam_rt::Runtime::gc_stats().collections` (published as `erlang:statistics(garbage_collection)`'s first element).
  - `collector().young_space_count()` and `collection_debt()` are the **direct** chain queries (length; length > 1) — the cheapest (A)-vs-(B) probe at this node, alongside `tests/collection_debt.rs::growing_and_admitting_in_rounds_keeps_the_young_capacity_bounded`, whose control half measures the accumulating signature (one retired space per round, `young_space_count == ROUNDS + 1`, capacity ≈514 838 words after 8 rounds).
  - `Process::heap_used_words()` is the **chain-summed occupied** words (`beam_gc::HeapObservable::heap_used_words`) — the one occupant figure that includes a retired space's live words until a collection collapses the chain, so it tracks the live set rather than the reservation and needs no correction for chaining.
  - Off-heap reporting has **one** accounting call: `beam_gc::HeapFootprint::of(process.collector(), process.owned_off_heap())` (payload bytes + reserved slot array from the roster itself). `Process::off_heap_binary_bytes()` answers whatever figure the host asserted with `set_off_heap_binary_bytes` — the engine machine's reservoir, which this crate cannot see — and falls back to the roster sum only when no override is installed, so the `max_heap_size` charge and a footprint report can legitimately differ; the host owns the asserted number's accuracy.
  - `collector().young().base()` is **not** stable evidence: every growth installs a fresh `HeapSpace` (new `beam_alloc::Heap` block) and a collapse either rewinds in place (`HeapSpace::reset`, base kept) or installs a new space. A retired space is freed only by `Nursery::collapse`, via `Heap`'s `Drop` → `beam_alloc` `dealloc`, so the allocator's free list / MBC pool / mseg segment cache can hand the same pages back (constant page faults are consistent with per-iteration space turnover, not only with "no allocation"). **A collection therefore FREES memory, and not only retired spaces**: `Nursery::install_collapsed` clears the retired chain (each `HeapSpace` → `Heap::drop` → `dealloc`) and, when the target capacity differs, **replaces the current space too** (`self.current = HeapSpace::with_allocator(...)`, whose assignment drops the old one), and a fullsweep frees the old mature space (`self.mature = fresh; // drops the old mature space`, `beam_gc/src/collector.rs`). So a pointer into the pre-collection young **or** mature heap (a host-held `Eterm`, a saved `*mut Eterm` from `alloc_words`, a nested `Machine`'s `x`/`stack`/`fr` that the root set did not publish) is a **use-after-free** after `collect`/`collect_kind`/`ensure_capacity`/`collect_if_needed`, not merely a stale word — the `capacity == target` branch (`HeapSpace::reset`, base kept) is the only collapse that keeps the pages mapped.
