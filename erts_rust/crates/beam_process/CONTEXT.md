# `beam_process` — Processes, Scheduler, Run Queues, Signals
## Intent
Owns the **OS-thread-level concurrency plumbing** of the Rust ERTS rewrite (Stage 5, Part II §H): the per-process control block (PCB), the four-level run queue, the cooperative scheduler loop, the **multi-scheduler (SMP) pool** (`SchedulerPool`: N scheduler threads over one shared table, per-scheduler run queues with work stealing, the cross-scheduler `ThreadProgress` barrier, the `TimerService` and the two `DirtyPool`s), the **exit-signal / link / monitor** machinery (the decoupled per-process signal queue plus its signal-message builders), the process table (`ptab`) with the local name registry, the **port-id table with its ownership/link/monitor surface**, and the local records for **remote (distributed) links/monitors**.
It is what makes Erlang **processes** real — isolation, `spawn`, links, monitors and exit propagation — the process half of workspace `../CONTEXT.md` §1 **A.1**.
It is consumed by `beam_bifs` (spawn/send/receive/`process_info`/`monitor`/`link` BIFs), `beam_io` (ports + the process side of I/O completion) and `beam_rt` (boot/CLI/`system_info`).
It **drives** `beam_gc` (collector + MSO) at safepoints and **uses** `beam_message` (`Queue` mailbox + `send`/`receive` copy engine) — it reimplements neither.
Legacy C ground truth (read-only `../../erts/emulator/beam/`; the Routing Table maps each to its module): `erl_process.{c,h}` (PCB/scheduler/run queues), `erl_proc_sig_queue.c`, `erl_monitor_link.c`, `erl_ptab.{c,h}`, `erl_process_dict.c`, `erl_vm.h` (`MAX_REG`/`MAX_ARG`), `erl_thr_progress.c`, `erl_hl_timer.c`, `erl_nfunc_sched.c`.
**Attribution boundary** (a C-deletion record must not attribute these here): the allocators (`erl_alloc*.c`, `erl_goodfit/bestfit/afit/ao_firstfit_alloc.c` → `beam_alloc`), the message copy engine (`erl_message.c`/`copy.c` → `beam_message`) and crash dumping (`erl_process_dump.c`/`erl_crash_dump.c` → `beam_rt`'s `crash_dump.rs`); microstate accounting (`erl_msacc.c`) and flexible counters (`erl_flxctr.c`) are modelled by no crate (`beam_rt` lists the `mc_*`/`scheduler_wall_time` BIFs as a native gap); `erl_thr_queue.c`, `erl_sched_spec_pre_alloc.c` and `erl_process_lock.c` are not modelled; low-level time + Erlang time services (`time.c`/`erl_time_sup.c`) are served by `beam_bifs`'s time BIFs / `beam_rt` — this crate's `timer.rs` is the `erl_hl_timer.c` analogue.
## Milestone-1 scope
Two scheduler fronts share the **same** slice logic — `scheduler::{slice_begin, slice_end}` (with `run_one` = both halves around one full-budget runner call) plus `drain_woken_into`: the single-threaded `Scheduler` loop (slice semantics frozen) and the SMP `SchedulerPool` (N threads over one shared table), so SMP adds *concurrency* and a bounded lock hold (one reduction **quantum**, `SchedulerConfig::set_lock_quantum`, default `DEFAULT_LOCK_QUANTUM = 256`), not a second scheduler.
"Correct" means the pid table, the four-level run-queue order, message delivery, the decoupled per-process signal queue, the monitor/registration surface, the process-dictionary and saved-argument sub-rootsets, the port ownership/link/monitor surface, remote links/monitors through the `DistSignalRouter` seam, and a safepoint GC over the process root set all match the C/oracle for the common cases and are test-covered; deliberate gaps are under Known Issues.
## API Surface (FROZEN — dependents route here)
Re-exported at the crate root and via `beam_process::prelude::*`. Each module's `src/<module>.rs` rustdoc (the top-of-file `//!` block plus the per-item `///` docs) is **authoritative for its complete method list and its detailed contracts**; this section keeps the frozen seam types, their shapes, the constants, the named entry points dependents call and the behavioural caveats that must not be lost.
### `pid.rs` — process/port identity (bit-exact with `beam_term::immediate`)
- `ProcessId { number: u64, serial: u64 }` (`Copy + Eq + Hash + Ord + Debug`) — `to_eterm() -> Eterm` = `make_internal_pid(make_pid_data(serial, number))`; `from_eterm(Eterm) -> Result<ProcessId>` is `BadArg` unless an internal pid; `is_process(Eterm)`.
- `PortId { number: u64 }` — same shape via `make_internal_port`/`is_internal_port`.
- Limits: `MAX_PROCESS_NUMBER = (1 << 28) - 1` (`PID_NUM_SIZE`); `MAX_PROCESS_SERIAL = 2^32 - 1` (`PID_SER_SIZE`).
### `registers.rs` — the root-set containers (x-register file + Erlang stack)
Honors the crate-layer root-set contract: `x_reg_array[0..Live)` **plus the whole stack**, no frame liveness maps; `MAX_REG = 1024` (`erl_vm.h`), `MAX_ARG = 255`.
- `XRegs` (boxed `[Eterm; MAX_REG]` + `live`; `new` = all `NIL`, `live == 0`), `Stack` (`Vec<Eterm>`), `Registers { x, stack }` with the GC pair `gather_roots(&self, out: &mut Vec<Eterm>) -> usize` (appends `x[0..live)` then every stack word; returns the `x_live` split point) / `scatter_roots(&mut self, roots, x_live)`.
### `process.rs` — the process control block (PCB)
- `ProcessState { Runnable, Running, Waiting, Suspended, Exiting, Terminated }` (`Copy`); `DeliverOutcome { Enqueued, Woke }` (`Copy + Eq`, `woke() -> bool`) — `Enqueued` = recipient not blocked, `Woke` = it was blocked (`Waiting`/`Suspended`) and is now `Runnable`; `ProcessFlags` — a `u32` bitset (no `bitflags` dep) over `trap_exit`, `system`, `in_run_queue`, `garbage_collecting`, `active`, `sensitive` (`bits()/from_bits()` + per-flag get/set).
- `Process` fields (shape frozen): `pid`, `state`, `flags`, `priority`, `save_calls: u16`, `collector: beam_gc::AnyCollector`, `relocation_exempt: bool`, `off_heap: beam_message::OffHeapTable` (the **persistent** off-heap table — a queued signal's reason objects and a host's moved-fragment objects; the send path stages through its own fresh table, never this one), `owned_binaries: beam_gc::OffHeap` + `owned_binary_slots: usize` + `dead_binaries: Vec<usize>`, `mailbox: beam_message::Queue`, `regs: Registers`, `dict: Dict`, `saved_args: SavedArgs`, `signals: SignalQueue`, `reductions: u64`, `links: Links`, `monitors: Monitors` (outgoing), `monitored_by: Vec<MonitoredBy>` (incoming), `port_monitors: Vec<PortWatch>` (outgoing port watches), `exit_reason: Option<Eterm>`.
- `collector` resolves its mature strategy from the spawn policy — the copying space below `beam_gc::IMMIX_BREAK_EVEN_WORDS`, the mark-region (GenImmix) space at/above it (a default policy resolves below it); `new(pid)`/`with_policy(pid, policy)`/`with_policy_and_priority(pid, policy, Priority)` construct it, the last the **spawn-at-priority** form (a runtime composes `alloc_pid` + it + `ProcessTable::insert`, so a child is born at its level, not Normal).
- Contracts: `heap()/heap_mut()` is the **young** mutator heap; `wake(&mut self) -> bool` (`Waiting`/`Suspended` ⇒ `Runnable` + `true` — resume-on-send); `status_atom`/`status` map the state (with `garbage_collecting` layered over it) to the oracle's `process_info(P, status)` atoms `"running"`/`"runnable"`/`"waiting"`/`"suspended"`/`"exiting"`, `None` for `Terminated` (a dead pid answers `undefined`; the BIF layer supplies that); **no receive scan position is stored on `Process`** — the mailbox is a pure FIFO and a `QueueCursor` is a transient caller-local value (only `ProcessTable::demonitor_flush` drives one, re-derived per removal).
- **Owned off-heap binaries** — the process's second, **process-owned** `beam_gc::OffHeap`, distinct from the message-transit `off_heap` (never swept): one slot per payload (the legacy `MSO(p)` invariant — a duplicate registration returns the existing slot and drops the surplus handle), the readers expose the live payload bytes (the `system_info` memory hook), `declare_off_heap_binary_dead(slot)` is the **provable-death** signal, and `sweep_off_heap_binaries()` (**crate-driven** — the last step of every `run_rooted_collection`, releasing exactly the declared-dead entries) / `retain_off_heap_binaries(is_live)` (the caller-predicate form) are the sweeps; slots are stable for the process's lifetime (a released slot answers `None` and is never reused).
- **Split borrows** — the only two `*_mut` pairs with a real caller need (the rest were audited); both destructure `self` into two disjoint `&mut` fields in safe Rust (compiler-proven, no raw pointer) and must not be joined into a combined raw-pointer accessor: `heap_and_off_heap_mut()` (young heap + off-heap table) drives `beam_message::Fragments::move_into`, the only way to move a **fragmented** payload onto the heap; `heap_and_mailbox_mut()` (young heap + mailbox) drives `beam_message::send_fragmented`.
- **Delivery and collection:** `deliver(from: Eterm, term: Eterm, src_off_heap: &OffHeapTable) -> Result<DeliverOutcome>` copies `term` into the young heap **through a fresh per-send staging `OffHeapTable`** (drained into the resulting `Message`; the persistent `off_heap` is never touched, so a send cannot steal a queued signal's off-heap handles), enqueues then `wake()`s (`deliver_simple` is the no-off-heap form, `receive(pred)` delegates to `beam_message::receive`); `collector() -> &beam_gc::AnyCollector` (`kind()`/`mature_choice()` name the strategy, the mature generation is read through `mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_base`/`mature_contains` — the two mature spaces are differently typed — while `young`/`stats`/`minor_gcs`/`policy`/`should_collect`/`heap_used_words`/`collect_if_needed` are strategy-agnostic); `collect() -> Result<Collection>` gathers the root set, runs the collector and scatters back, `ensure_capacity(need_words) -> Result<Collection>` is the on-demand-growth sibling (collect once, then grow the nursery to the smallest curated size covering the request; a fail-fast typed `AllocKind::Heap` when the policy's ceiling makes it unreachable), and both route through one shared `run_rooted_collection` that writes every root region back even when the collection action returned `Err` and ends with `sweep_off_heap_binaries()`.
- Each queued message contributes **three** roots — `payload()`, `from()`, `token()` — all written back into the re-installed envelope (`Message::with_payload` / `set_from` / `set_token`), so the message keeps its **whole envelope** (`from`, `token`, off-heap handles, refc binaries, node entries and — for an oversized payload that lives *in* them — its `Fragments` chain); a queued payload referencing an off-heap refc binary therefore stays alive across the collection (a fragment-resident payload is outside every evacuated range).
- **Relocation exemption:** `set_relocation_exempt`/`is_relocation_exempt` (default `false`) — a per-`Process` flag for a host holding live terms from this process's young heap in Rust locals / nested-`Machine` registers that are **not** in the crate root set. While exempt: `deliver` surfaces the raw refusal; `collect`/`ensure_capacity` refuse with the typed `error::relocation_exempt(what)` raise (a `BeamError::Raise` whose reason atom is `relocation_exempt: <what>`); `collect_if_needed` answers `Ok(false)`; `run_rooted_collection` is unreachable from those three. Opt-in per process, not a global valve.
### `dict.rs` — the per-process dictionary
- `Dict` (`Default`) backs `erlang:put/2`/`get/1`/`erase/1` (last put wins, `put` returns the replaced value) with `new()` (empty) / `with_atoms(Rc<AtomTable>)` and the GC pair `gather_roots`/`scatter_roots` (never-panic). `None` is the C `THE_NON_VALUE` (the BIF layer maps it to `undefined`); keys — and, for `get_keys_for_value`, **values** — compare with `beam_term::compare::eq` (the C's `EQ`, `erl_utils.h:113`: structural `=:=`), so a *boxed* key matches a distinct-but-equal term (`put({a},1), get({a})` ⇒ `1`); atom names resolve through the `Rc<AtomTable>` handle (`new()` ⇒ empty table, whose unknown-name fallback is the raw atom index — the C's `EQ` for two immediates). Holds terms resident in THIS process's young heap (a `Process::collect` sub-rootset). Iteration is insertion-ordered — a documented deviation from the C's hash-array order (`pd_hash_get_all`), an unspecified artifact **not stable across VM starts** and so unpinnable by a differential case; `tests/dict_oracle.rs` compares `get/0` as a **set**. See `DESIGN_DECISIONS.md`.
### `fragments.rs` — saved BIF/NIF arguments
- `SavedArgs` (`Default`) — the saved BIF/NIF argument root list (the C `ErlSaveCallArgs`): `push`/`pop`, `as_slice`/`as_mut_slice`, `len`/`clear` plus the GC pair (the region of `Process::collect`'s root set after the dictionary, before the pending signals).
### `run_queue.rs` — the ready queue (four priority levels)
- `Priority { Max=0, High=1, Normal=2, Low=3 }` (`Copy + Ord + Hash`; `Default = Normal`); the derived `Ord` is the C *numeric* order (`Max < High < Normal < Low`), which is **NOT** scheduling precedence — precedence is `LEVELS = [Max, High, Normal, Low]` (highest-first); `index()/from_index(u8)` (the C `PRIORITY_*` value); `name()/from_name(&str)`.
- `RunQueue` — four per-priority FIFOs; `dequeue` serves the highest-priority non-empty level, FIFO within a level; `enqueue(pid)` ⇒ **normal** (`enqueue_with_priority` for the rest); `reprioritize(pid, Priority) -> bool` moves an already-queued pid to the tail of the new level (never double-enqueues, never inserts a non-queued pid) — the run-queue half of `Scheduler::set_priority`; `split_off_half(&mut self) -> Vec<ProcessId>` removes up to half the queue's pids (highest priority first, `dequeue` order) so a work-stealing victim keeps at least half (0/1 pids ⇒ empty) — the victim half of the SMP steal.
- **Fairness deviation (documented):** the C keeps MAX/HIGH dedicated but lets **NORMAL and LOW share one physical queue**, deferring LOW by `schedule_count` (`RESCHEDULE_LOW = 8`, `erl_process.h`); this crate uses **four physically distinct FIFOs**, so LOW runs only once MAX/HIGH/NORMAL are empty — the relative precedence is unchanged (LOW last), only the LOW/NORMAL interleaving ratio differs.
### `scheduler.rs` — the single-threaded scheduler loop + the engine seam
- `RunOutcome { Yield, Wait, Suspend, Exit(Eterm) }` — what happened in a reduction slice (`Exit(reason_term)` = the process terminated with that reason); `ProcessRunner { fn run(&mut self, pid: ProcessId, table: &mut ProcessTable, budget: u32) -> Result<RunOutcome> }` — **the engine seam** (`beam_engine` is NOT a dependency; `beam_rt`/`beam_engine` implement it over an `ExecutionContext`).
- `Scheduler` — `new()` defaults `DEFAULT_REDUCTIONS_PER_SLICE = 4000` (override `with_slice(u32)`), and optionally owns a `PortTable` (`with_ports`/`set_ports`/`take_ports`/`ports(_mut)`/`has_ports`; `new`/`with_slice` own none). Entry points: `enqueue`(⇒ normal)/`enqueue_with_priority`, `progress()/progress_mut()`, `set_priority(&mut self, table, pid, priority) -> Result<()>` (updates the PCB priority and, **iff** the pid is already queued at a different level, moves it to the new level's tail — the C `erts_set_process_priority` requeue; `TermNotFound` for an unknown pid leaves the queue untouched), `run_slice`/`run_ready`/`resume_woken` and the explicit `run_slice_with_ports`/`run_ready_with_ports` forms.
- A slice pops one pid, **services its pending signals** (schedule-in; a fatal signal can terminate the pid, in which case it runs zero reductions) and runs one slice: `Yield` ⇒ requeue at the tail of the process's **own** current priority; `Wait`/`Suspend` ⇒ leave the queue; `Exit(reason)` ⇒ terminate (through `terminate_with_ports` when a port table is owned, else the port-less `terminate`); afterwards (and on the empty-queue early return) it absorbs the table's wake list. `run_ready(…, max_slices: Option<u64>) -> Result<u64>` runs until the ready queue is empty or `max_slices` slices ran; `resume_woken(&mut self, table) -> usize` drains `table.drain_woken()` and enqueues each still-live `Runnable` pid not already queued **at its own priority** (also the hook `beam_rt` calls after a send made **outside** a slice).
- **Reduction accounting is delegated to the runner:** `ProcessRunner::run` receives `DEFAULT_REDUCTIONS_PER_SLICE` as its `budget` and owns the reduction count (the scheduler never reads or resets `Process::reductions`), so **pre-emption is cooperative** (see Known Issues).
- **Shared slice helpers (the SMP reuse seam):** `pub(crate)` `slice_begin(pid, table) -> Result<bool>` (mark executing + apply the queued signals), `slice_end<F>(pid, table, outcome, enqueue)` (schedule-out), `run_one<R, F>(pid, table, runner, reductions, enqueue)` = `slice_begin` + one full-budget runner call + `slice_end`, and `drain_woken_into<F>(table, enqueue)`; the `*_with_ports` mirrors share private `*_inner` bodies. `run_slice`/`resume_woken` delegate to them, and the SMP pool calls the same helpers (splitting a slice into lock quanta) with a closure that **buffers** requeues instead of touching a queue.
- **Port-aware adoption and the `beam_rt` orchestration contract** (spawn ⇒ `spawn_default` + `enqueue`; a runner blocking on an empty receive sets `ProcessState::Waiting` **before** returning `RunOutcome::Wait`; a send inside a runner is absorbed at slice end, one outside a slice needs an explicit `resume_woken`; run ⇒ `run_ready(&mut table, &mut runner, None)`) are documented in full in the module rustdoc.
### `smp/` — the multi-scheduler (SMP) pool
The `Scheduler` counterpart for SMP: N scheduler threads over one shared process table, per-scheduler run queues + work stealing, the `ThreadProgress` barrier, the `TimerService` and the two `DirtyPool`s. Crate-root re-exports: `beam_process::{SchedulerPool, SchedulerConfig, SchedulerStats, SchedulerStat, SharedProcessTable}`. Full API surface, the **BINDING locking discipline** (three lock families, the buffer-requeues rule), the **bounded-quantum lock** rule (`run_locked_quanta`, `set_lock_quantum`) and the `unsafe impl Send/Sync` handoff live in **`src/smp/CONTEXT.md`**. `SchedulerPool::set_priority(pid, priority)` implements the same requeue as the single-threaded `Scheduler` (PCB update under the table lock, then an `O(schedulers)` search of the injector + every local queue, one queue lock at a time).
### `timer.rs` — the high-level timer service
- `TimerService` — one background thread over a deadline min-heap; `TimerRef { id, generation }` (`Copy`); `TimerSink: Send + Sync { fn timer_fired(&self, target: ProcessId, message: Eterm); }` — the seam the pool implements. It is the delivery **mechanism** only (one message to one `ProcessId` after a delay); the `erlang:send_after/3`, `start_timer/3` (`{timeout,Ref,Msg}` needs `make_ref`), `cancel_timer/1,2`, `read_timer/1`, `start_timer/4` and `receive ... after T` timeout-label semantics are BIF/engine-side (`beam_bifs`/`beam_rt`); `read_timer` and a hibernate state are absent here. **Message contract:** the stored message must be **thread-valid** — an immediate (small int/atom/pid) or a literal-area/interned term; a term resident in a per-process heap is a caller contract violation (needs an off-heap handle; documented follow-up).
### `dirty.rs` — the two dirty scheduler pools
- `DirtyKind { Cpu, Io }` (`ALL`, `name()` = `"dirty_cpu_scheduler"`/`"dirty_io_scheduler"`); `DirtyOutcome { Done, Reschedule(ProcessId), Deliver { target, message } }` — routing data the normal scheduler acts on (`Reschedule` re-enters the pid, `Deliver` delivers and wakes); `DirtyJob = Box<dyn FnOnce() -> DirtyOutcome + Send + 'static>` — a plain closure carrying **no** live heap data; `DirtyCompletionSink: Send + Sync { fn dirty_completed(&self, DirtyOutcome); }`; `DirtyPool` (`start(cpu, io)`, `set_sink`, `cpu_schedulers()`/`io_schedulers()`, `schedulers(kind)`, `submit(kind, job)`, `pending(kind)`, `shutdown()`, `join()`). A kind with **0 workers buffers** jobs (never drops on submit, discards at join); a panicking job does not kill the pool.
### `progress.rs` — thread progress (the cross-scheduler barrier)
- `ThreadProgress` (`generation`, `bump() -> u64`, `wait(u64)`, `safepoint() -> u64` = `bump`+`wait`, `managed_thread() -> ManagedThread`, `managed_count`, `set_waker`, `is_blocking`/`block`/`unblock`/`blocking_count`) — the real barrier; cheap to clone, and every clone shares the generation, the managed-thread registry and the blocking counter. `ManagedThread` is the per-thread slot a scheduler registers (`progress`, `update` = confirm the current generation, `is_active`/`set_active(bool)` — an inactive/parked thread is already at a safepoint and is excluded from the wait — `id`).
### `signal.rs` — exit signals, reasons and signal-message builders
- `SignalAtoms { exit, down, process, port, normal, kill, killed, noproc, system }` — the well-known atom indices used to build signal messages; `from_table(&mut AtomTable)` interns `'EXIT'`/`'DOWN'`/`process`/`port`/`normal`/`kill`/`killed`/`noproc`/`system`; `system` is the C's `am_system`, used as the `Message::from` immediate of a failed-by-name monitor DOWN (`erl_proc_sig_queue.c:4991`).
- `ReasonClass { Normal, Kill, Other }` + `SignalAtoms::classify(reason) -> ReasonClass`; `ExitSignal { from: ProcessId, reason: Eterm }` (`Copy`); `ExitPolicy { Terminate(Eterm), Trap, Ignore }` (`Trap` = deliver `{'EXIT', From, Reason}` as a message) and `exit_policy(reason, trapping, &SignalAtoms) -> ExitPolicy` (`kill` ⇒ `Terminate(killed)`, untrappable; else trapping ⇒ `Trap`; else `normal` ⇒ `Ignore`; else `Terminate(reason)`).
- **Signal-message builders** (each allocates on the *receiving* process's heap; the full list is in the rustdoc): the exit pair `build_exit_message(heap, atoms, from: ProcessId, reason)` / `build_exit_message_term(heap, atoms, from: Eterm, reason)` (`{'EXIT', From, Reason}`; the `_term` form's `from` may be an external pid term); the DOWN family `build_down_message(heap, atoms, user_tag: Option<Eterm>, reference, pid, reason)` (`{'DOWN', Ref, process, Pid, Reason}`, or `{Tag, Ref, process, Pid, Reason}` when `user_tag` is `Some`) / `build_down_message_port(...)` (the `port`-**kind** form) / `build_down_message_remote(...)` (materialises the external-pid target on the same heap) and the fully general `build_down_message_term(heap, atoms, user_tag: Option<Eterm>, reference, kind: Atom, target: Eterm, reason)`. `kind` is the `{'DOWN', …}` 3rd-element **kind** atom (`process`/`port`), distinct from the caller's `user_tag` (which replaces the message's head atom).
### `signal_queue.rs` — the decoupled per-process pending-signal queue
A signal is *queued* on the receiver and applied later (eager-vs-queued rule under `ptab.rs`); its `reason` is copied into the receiver's own heap at enqueue time, so the queue is an in-heap sub-rootset. `PendingSignalKind { Exit, Down }`; `PendingSignal { Exit { from, reason }, Down { reference: MonitorRef, target: ProcessId, kind: MonitorKind, tag: Option<Eterm>, reason } }` (`Copy`) with the `exit`/`down` constructors and `kind()`/`tag()`/`reason()` — the `tag` is the caller's `monitor/3` user tag, carried so the deferred `{'DOWN', …}` materialises with the right head atom. `SignalQueue` (a `VecDeque<PendingSignal>`, `Default`) is the per-process FIFO (application order) plus the GC pair `gather_roots` (one word per queued signal's `reason`) / `scatter_roots`; monitor references are stored by value, not on the heap. **Ordering:** a total FIFO order per receiver (a single FIFO) — subsuming the C's per-`(sender, receiver)` order; **not** cross-ordered with the mailbox.
### `link.rs` — bidirectional links
- `Links { pids: Vec<ProcessId> }` — `add(pid) -> bool` (false if already linked), `remove(pid) -> bool`, `contains(pid)`, `iter()`, `drain()`.
### `monitor.rs` — monitors and monitor references
- `MonitorRef { id: u64 }` (`Copy + Eq + Hash`) — `to_eterm(self, heap) -> Result<Eterm>` builds the on-heap `Ref` thing (`DESIGN_DECISIONS.md`), `from_eterm(term) -> Result<MonitorRef>` is the reverse (parses the frozen `[header, node, serial, id]` ref thing, `BadArg` for anything else — the send path's destination→key step, with guard-chain parsing like `payload_is_down_for`). `RefAllocator { next: u64 }` — `next() -> MonitorRef` (monotonic, never reuses an id); owned by `ProcessTable`.
- `UnaliasMode { ExplicitUnalias, Demonitor, ReplyDemonitor }` (`Copy + Eq + Hash`) — the `{alias, Mode}` un-alias mode of `erlang:monitor/3`/`alias/1` (the C `ERTS_ML_STATE_ALIAS_*` flag values); the atom→mode parsing is the BIF layer's, so the enum is the frozen value the alias entry points take. `AliasEntry { owner: ProcessId, mode: UnaliasMode }` (`Copy`) — one `ProcessTable` `aliases` entry (`owner` is the process a message sent to the reference is delivered to); plain values only (not a GC root).
- `MonitorKind { Process, Port }` — `type_name() -> &'static str` (`"process"`/`"port"`) and `from_type_name(&str) -> Option<MonitorKind>` back the `erlang:monitor/2` type dispatch (any other type name ⇒ `None` ⇒ the caller's `badarg`, matching the oracle).
- `PortWatch { reference: MonitorRef, port: PortId }` (`Copy`) — the **outgoing** half of a port monitor, held in `Process::port_monitors`; plain values only (not a GC root).
- `Monitor { reference, target: ProcessId, kind }` (outgoing) / `MonitoredBy { reference, watcher: ProcessId, kind }` (incoming) — field sets **frozen** (constructed by struct literal from `beam_rt`, so no field may be added); the `monitor/3` user **tag** therefore lives in a `ProcessTable` side table, not here. `Monitors { entries: Vec<Monitor> }` — `push`, `remove(reference)`, `find(reference)`, `iter`, `drain`.
- `payload_is_down_for(payload: Eterm, reference: MonitorRef, down_atom: Atom) -> bool` — the guarded `{'DOWN', Ref, _, _, _}` shape test `demonitor_flush` scans mailboxes with (one `unsafe` block, no out-of-bounds read).
### `ptab.rs` — the process/port table + name registry + signal/link/monitor hub
The single place that mutates ≥2 processes (mirrors the C ptab lock domain), using a **collect-then-apply worklist**; M1 single-threaded, so it holds `Process` values directly (`PortTable` lives in `port.rs`). The module rustdoc is authoritative for the full entry-point list (allocation/lookup, priority, the GC relocation-exemption pair, delivery, the local signal/link/monitor ops, the `*_with_tag`/`*_with_options` points, decoupled servicing, the `*_term`/`remote_*` forms, the distribution and process-death-observer seams, `node_down`/`port_closed`, the name registry, liveness/reason). Frozen shape and the contracts that must not be lost:
- `ProcessTable { slots, free, names: HashMap<Atom, ProcessId>, refs: RefAllocator, atoms: SignalAtoms, ready: Vec<ProcessId>, remote_links, remote_monitors, named_monitors: HashMap<MonitorRef, NamedTarget>, local_node: Option<Atom>, router: Option<Box<dyn DistSignalRouter>> }` (`Slot { serial: u64, process: Option<Process> }`; `NamedTarget { name: Atom, node: Atom }`). `ready` is the **wake list** (a delivery/signal pushes a woken pid; `drain_woken` returns **and** clears it); `router` is the distribution seam (`None` ⇒ record-only). `alloc_pid` reuses a free slot and bumps its serial (`SystemLimit` on exhaustion); `take` bumps the serial **and** drops the wake entry.
- `link(a, b)` has `a`/`b` set semantics and a **non-live `b`** with a live `a` records no link and applies a `noproc` exit signal from `b` to `a` — a trapping `a` is handed `{'EXIT', b, noproc}` and a non-trapping one is terminated with the bare atom `noproc` (the oracle *raises* `error:noproc`; signalled here as the bare reason — a documented approximation owned by `beam_rt`'s link floor); `TermNotFound` is returned only when the caller `a` is unknown (`link_term`'s local branch inherits this).
- `terminate`/`terminate_with_ports` are **best-effort per peer**: the pid is reclaimed first, so a per-peer signalling failure (a local signal that cannot be queued, a remote `route` transport error) is dropped-and-logged (ERTS's `erts_dsig_drop`) and the cascade continues — the observer and the port-monitor cleanup always run; `TermNotFound` for an unknown pid is the only `Err` on this path. `terminate_with_ports` threads the port table so a dying process's outgoing `port_monitors` also remove their matching **incoming** `PortMonitor` entries (`terminate` is its no-ports delegation).
- `monitor(watcher, target: ProcessId, kind) -> Result<MonitorRef>` — a **non-live** target with a live watcher yields `Ok(ref)` plus an immediate `{'DOWN', Ref, process, Target, noproc}` in the watcher's mailbox (the oracle's `noproc`); `demonitor`/`demonitor_flush` (`flush` also removes a queued `{'DOWN', …}` for that reference — `erlang:demonitor(Ref,[flush])`). `monitor_named(watcher, name: Atom, node: Atom, kind)` + `set_local_node`/`local_node` implement `erlang:monitor(process, Name)`: the DOWN target is the 2-tuple `{Name, node}`; with no local node installed ⇒ typed `unsupported`. `monitor_term` dispatches a pid → `monitor`, an atom name → `monitor_named`, an external pid → the remote record + route; a **port term** with `MonitorKind::Process` ⇒ `BadArg` (oracle) and with `MonitorKind::Port` ⇒ typed `unsupported` (that entry point has no `&mut PortTable` — use `monitor_port_term`); anything else ⇒ `BadArg`. A **target's death resolves both halves** — `terminate_into` also removes the watcher's outgoing `Monitor`, so `process_info(W, monitors)` stops listing it and a later `demonitor(Ref)` reports it gone (the `{Name, node}` descriptor of a named monitor survives until its DOWN is materialised, so the DOWN still carries the name). `monitor_port(_term)`/`demonitor_port` are the port-track forms (`erlang:monitor(port, Port)`).
- **`erlang:monitor/3` user tag (additive):** the `*_with_tag` points (`monitor_with_tag`, `monitor_named_with_tag`, `monitor_port_with_tag`, `monitor_port_term_with_tag`, `monitor_term_with_tag`) take a trailing `tag: Option<Eterm>` (the no-tag methods delegate with `None`); a `Some(tag)` makes the delivered message `{Tag, Ref, Kind, Target, Reason}` instead of `{'DOWN', Ref, Kind, Target, Reason}` — the tag replaces the head atom only. The tag is stored in the private `tags: HashMap<MonitorRef, Eterm>` side table (`remember_tag`/`forget_tag`, cleaned up at `demonitor`/`demonitor_port`/termination/port close) — **never** in the frozen `Monitor`/`MonitoredBy`/`PortWatch` structs. The tag must be a heap-independent **immediate**; a non-immediate tag (or any tag on a **remote** external-pid target — `DOP_MONITOR_P` carries no tag) is a typed `unsupported`.
- **Reference aliases (`erlang:monitor/3` `{alias, Mode}`, `erlang:alias/1`, `erlang:unalias/1`):** a `MonitorRef` may name an **alias** — a send destination that resolves to its owner — held in the private `aliases: HashMap<MonitorRef, AliasEntry>` side table (next to `tags`; nothing else stores it). `MonitorOptions { tag, alias }` plus the `*_with_options` points (`monitor_with_options`, `monitor_named_with_options`, `monitor_port_with_options`, `monitor_port_term_with_options`, `monitor_term_with_options`) register the alias; the existing `*_with_tag` methods delegate with `alias: None`, so their signatures are unchanged. `resolve_alias(reference) -> Option<ProcessId>` is the send-path resolver — `Some(owner)` iff the reference names an alias whose owner is **live**; `create_alias(owner, mode) -> Result<MonitorRef>` is `alias/1`; `unalias(owner, reference) -> Result<bool>` is `unalias/1` (clears only the alias of `owner`, keeping a sharing monitor); `alias_reply_delivered(reference) -> Result<()>` is the reply site. **Auto-removal** follows the C (`bif.c:470-492`, `erl_proc_sig_queue.c:6009-6112,:6466-6493`): `reply_demonitor` ⇒ gone once a message is delivered through it; `demonitor`/`reply_demonitor` ⇒ gone when the monitor's DOWN is materialised (the shared `apply_alias_on_down`, used by the termination/`port_closed` and born-down `noproc` paths); `explicit_unalias` ⇒ survives its DOWN and an explicit `demonitor` (re-derived as a standalone alias) and is cleared only by `unalias/1`. A dying owner's aliases are all swept (`aliases.retain(|_, e| e.owner != pid)`), so no alias ever resolves to a dead pid. A `{alias, …}` on a **port** monitor or on a **remote** external-pid target is a typed `unsupported` (see Known Issues).
- `service_signals(pid) -> Result<()>` drains + applies the pid's pending-signal queue in FIFO order, cascading to any process those signals affect (the scheduler calls it at schedule-in); `service_signals_with_ports(&mut PortTable, pid)` threads the port table so such a cascade also cleans a terminated process's incoming port monitors (the plain form delegates with no ports).
- `node_down(node: Eterm, reason)` resolves + purges every remote relationship with `node` (a `{'DOWN', …}` per monitor, a trapped/fatal `{'EXIT', …}` per link); `port_closed(&mut PortTable, port, reason)` drains the port's owner/links/monitors, delivers the `{'DOWN', Ref, port, Port, Reason}` / `{'EXIT', Port, Reason}` shapes, and terminates any non-trapping linked peer through `terminate_with_ports` so that peer's own port monitors are cleaned too. This is the **port-died** direction; the reverse (a **watcher process** dies) is handled in `terminate_into` by draining `Process::port_monitors` and calling `PortTable::demonitor` on the matching incoming entries — but only when a port table was threaded in.
- `register(name, pid)` is `BadArg` for a taken name **or a non-live pid**; `unregister(name)` is `BadArg` for an unknown name; `whereis(name)`/`registered()`/`name_of(pid) -> Option<Atom>` (the reverse lookup a `process_info(P, registered_name)` BIF needs; live-only); `is_process_alive(pid) -> bool` is table membership and `exit_reason(pid) -> Result<Option<Eterm>>` is live-only. `ExitEffect { Terminated, Trapped, Ignored }` — the outcome of `apply_exit_signal` (target terminated / got a `{'EXIT'}` message / ignored it).
- **Eager-vs-queued rule.** A signalling operation **enqueues** a `PendingSignal` on the receiver (copying the reason into the receiver's own heap) — never applies it inline; servicing happens at the receiver's schedule-in (`service_signals`, called by `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is *not* the currently `Running` process (ERTS's early signal handling): `apply_exit_signal`/`terminate`/`send_exit` share one rule — every receiver is added to the service worklist unless it is `ProcessState::Running`. `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. A **remote** (external-pid) or **port** signal bypasses the queue entirely (no `trap_exit` policy to defer), so `node_down`/`port_closed` materialise it straight into the mailbox.
### `exit_observer.rs` — the process-death observer seam
The host hook for per-process resources this crate does not own (the **ETS tables a pid owns** are the motivating case). Mirrors the `DistSignalRouter` pattern: a trait object on the table, implemented downstream, so the table stays free of any dependency on the observing subsystem; with **no** observer installed (`None`) behaviour is unchanged.
- `ProcessExitObserver { fn process_exited(&mut self, exit: &ProcessExit<'_>); }` — called **exactly once per death** from `terminate_into`, after the death has been propagated (links/monitors signalled **best-effort** — a peer that cannot be signalled is dropped-and-logged, never an abort, so this hook always runs) and **before** `drop(process)` (so `reason`, which may live in the dying heap, is still valid). No `Send` bound (consistent with `router`).
- `ProcessExit<'a>` — the payload, **private fields + read-only accessors**, built only by the finalizer: `pid: ProcessId` (the key an observer uses to release its own per-pid state; an immediate ⇒ retainable), `reason: Eterm` (the exit reason exactly as received; may live in the dying heap, so an observer that retains it must copy it), `name: Option<Atom>` (the registered name, captured **before** the registry entry is dropped; without it the registration would be unobservable), `port_monitors: &'a [PortWatch]` (the drained outgoing port watches; plain values ⇒ heap-independent).
- **Failure policy:** an absent observer is a no-op; a **panicking** observer is contained with `std::panic::catch_unwind(AssertUnwindSafe(...))` (the observer gets only an immutable payload and holds no reference to the table, so a panic cannot half-update the table — only the observer's own state), reported via `beam_common::beam_error!`, and termination still completes. Implementations should be cheap (they run on the finalizing scheduler thread) and prefer returning over panicking for expected conditions.
### `remote.rs` — remote (external-node) links and monitors
The **local record** of a process's relationships with processes on other nodes; the wire format is `beam_dist`'s, reached through a trait seam (this crate never depends on `beam_dist`).
- `RemotePid { node: Eterm, number: u32, serial: u32, creation: u32 }` (`Copy`) — a decomposed external pid (the `[header, node, creation, data]` thing), holding no boxed pointer into another heap; `from_eterm(term) -> Result<RemotePid>` (`BadArg` unless an external pid), `to_eterm(self, &mut Heap)`. `PidTarget { Local(ProcessId), Remote(RemotePid) }` — `from_eterm` (external ⇒ `Remote`, internal ⇒ `Local`, else `BadArg`). `RemoteMonitor { reference: MonitorRef, remote: RemotePid, kind: MonitorKind }` — an outgoing monitor on a remote process/port.
- `DistSignal { Link { from, to }, Unlink { from, to }, Monitor { watcher, target, reference, kind }, Demonitor { watcher, target, reference }, Exit { from, to, reason }, Exit2 { from, to, reason } }` — the control signal the runtime routes to the remote node. `Exit` is a **link** exit → `{DOP_EXIT, From, To, Reason}` → `Dop::Exit`; `Exit2` is `erlang:exit/2` → `{DOP_EXIT2, From, To, Reason}` → `Dop::Exit2` (distinct opcodes with distinct receipt semantics); the full `DOP_*` mapping is documented on the module.
- `DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()>; }` — **the distribution seam**: implemented downstream (`beam_rt`) over `beam_dist`; `route` must serialise the signal **synchronously** (`reason` may live in the signaller's heap, which the caller may drop right after). Its transport error propagates out of the relationship ops (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`node_down`), but **not** out of a dying process's termination (the remote step of `terminate_into` drops-and-logs a failed `route`). The table's remote records (`remote_links`/`remote_monitors`) and `set_dist_router`/`has_dist_router` are on `ptab.rs`. **This seam is OUTBOUND only** (local → remote): there is no inbound control-message (`DOP_LINK`/`DOP_MONITOR_P`/…) interpreter here — an inbound handler belongs to `beam_rt` (see Known Issues).
### `port.rs` — the port-id table + ownership / link / monitor surface
`PortTable` is the number table the C keeps alongside the pid table, extended with the relationships a dying port must resolve; port *behaviour* (driver, scheduling, read path) is `beam_io`'s. The crate-root re-export keeps `beam_process::PortTable` resolving here.
- `PortMonitor { reference: MonitorRef, watcher: ProcessId }` — a monitor placed on a port. `PortClose { owner: Option<ProcessId>, links: Vec<ProcessId>, monitors: Vec<PortMonitor> }` — what `close` releases.
- `PortTable { slots: Vec<bool>, free, owners, links, monitors }` — `alloc() -> Result<PortId>` (`SystemLimit` on exhaustion), `alloc_owned(owner)`, `release(PortId)` (frees the number + drops every relationship), `close(PortId) -> Result<PortClose>` (frees the number, returns **and clears** owner/links/monitors; unknown id ⇒ `BadArg`), plus the ownership (`owner`/`set_owner` — unknown id ⇒ `BadArg` — /`clear_owner`), links (`link` — deduped, `false` if already linked — /`unlink`/`links`) and monitors (`monitor`/`demonitor`/`monitors`) accessors. Every relationship mutation on an unallocated id returns `BeamError::BadArg`; `ProcessTable::port_closed` is the one-call orchestrator resolving a closing port's relationships.
### `error.rs` — `pub(crate)` constructors only (no new error enum)
## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only — never a crate-local error enum, never `panic!`/`unwrap()` on runtime data. Unknown pid/name/ref ⇒ `BeamError::TermNotFound`; a malformed pid term or out-of-range register index ⇒ `BeamError::BadArg`; pid/port space exhaustion ⇒ `BeamError::SystemLimit`; heap exhaustion during a delivery **or a signal build** ⇒ collect, grow the nursery on demand and retry once, propagating the retry's own `BeamError::Alloc` (a **relocation-exempt** receiver propagates the *first* raw `AllocKind::Heap`/`Message` refusal unchanged, no retry); a collection/growth refused for an exempt process ⇒ the typed `relocation_exempt` raise; **inside `terminate_into` a per-peer signal-build (or `route`) failure is *not* propagated** — the process is already reclaimed, so it is logged via `beam_common::beam_error!` and the cascade continues; `beam_term::TermError` is reconciled upstream, so `?` crosses the boundary. Because the nursery grows on demand, a refused delivery — the raw `AllocKind::Message` a caller's heap-fragment fallback keys on (`../beam_rt`'s `deliver_message`) — means the receiver's heap policy could NOT grow the nursery to fit the payload (e.g. a `max_heap_words` cap, or a collection that cannot make room); with an unbounded policy every payload is delivered into the grown young heap.
- **`unsafe` is confined** to the modules that touch raw words: `signal.rs`/`monitor.rs` message builders and `remote.rs` (reading/writing the external-pid thing through `beam_term`'s `unsafe` predicates, building tuple/ref words through `beam_alloc::Heap::alloc_words`), plus `src/smp/mod.rs`'s two documented `unsafe impl Send`/`Sync for SharedProcessTable` — nothing else in the SMP pool. Every `unsafe fn` carries a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale (`../beam_common/src/safety.rs` convention); `unsafe_op_in_unsafe_fn` stays clean. `pid.rs`, `registers.rs`, `run_queue.rs`, `link.rs`, `monitor.rs` set logic, `ptab.rs` bookkeeping, `signal_queue.rs`, `port.rs` and `progress.rs` are safe Rust; `queues.rs`/`worker.rs`/`stats.rs`/`pool.rs` and `timer.rs`/`dirty.rs` are safe Rust (synchronisation is `parking_lot` mutexes/condvars + atomics).
- **Never assume a different term layout** — build/inspect terms only through `beam_term`'s public accessors + `beam_alloc::Heap`'s builders; pid/port immediates are bit-exact with `beam_term::immediate` (`make_internal_pid`/`pid_number`/`pid_serial`).
- **Reuse, do not reimplement:** the mailbox is `beam_message::Queue`; the copy engine is `beam_message::{send, receive, CopyContext}`; the heaps are `beam_gc::AnyCollector`/`beam_gc::HeapSpace`/`beam_alloc::Heap`; the off-heap objects are `beam_gc::MsoHandle`/`beam_message::OffHeapTable`.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`, `beam_message`, `libc`, `parking_lot`; adding a dependency edge requires reporting to `../`. `beam_engine` is **NOT** a dependency (the `ProcessRunner` trait keeps the DAG acyclic).
- Files target ~1000 lines, one responsibility per file, Apache-2.0 licensing. The `src/smp/*` files, `src/timer.rs` and `src/dirty.rs` are each well under that figure; `src/ptab.rs` (the table + signal hub) is the only file over it and deliberately stays whole because the signal/link/monitor servicing is tightly coupled to `ProcessTable`'s private fields (`slots`/`atoms`/`refs`/`ready`), which a sibling module cannot reach — a structural-debt candidate to extract if it grows further or if field visibility is widened.

## Design Decisions
The rationale (why) behind the frozen API and constraints lives in **`DESIGN_DECISIONS.md`** (this file keeps the what: API Surface, Constraints, Known Issues).
## Known Issues (intentionally NOT covered in Milestone-1)
- **Reference aliases are unsupported on a port monitor and on a remote target.** `monitor(port, P, [{alias, _}])` and `monitor(process, RemotePid, [{alias, _}])` are typed `unsupported`s rather than accepted aliases: `alias_reply_delivered` holds no `&mut PortTable`, so a `reply_demonitor` port alias could not remove the port's incoming `PortMonitor`, and a later `port_closed` would deliver a `{'DOWN', …}` the oracle never does — a **wrong result**, so it is refused instead (reason string `error::unsupported_port_monitor_alias()`, mirroring the pre-existing remote-tag diagnostic). No OTP caller combines either.
- **The `{tag, Tag}` monitor option accepts only an immediate.** The oracle accepts any term; this crate refuses a non-immediate tag with a typed `unsupported`, because a tag lives in the `tags: HashMap<MonitorRef, Eterm>` side table, which is **not** a GC root — a per-process-heap tag could not be relocated and would dangle after a collection. Making it faithful needs a gather/scatter of the tag table in the collection walk. (The `aliases` side table is the same concern but its entries are plain values — no term — so it needs no rooting.)
- **The `from`/`token` envelope roots are gathered and relocated, but no in-tree producer enqueues a heap word there yet.** `beam_message::Queue::enqueue`'s debug `debug_assert_enqueue_terms` tripwire still rejects a non-immediate `from`/`token`, so a host storing a heap word (the C permits a heap `token` tuple, `erl_message.c:388-390`, and a heap Info-tuple `from`, `erl_proc_sig_queue.c:2272`) must (a) opt into the gather — done: `run_rooted_collection` pushes `Message::from`/`token` and scatters them back through `set_from`/`set_token` — **and** (b) deliberately relax that tripwire in the sibling `beam_message`, which has not happened. Until then every envelope word stays an immediate and this rooting is defensive.
- **A host holding unpublished live roots is the reason the relocation exemption exists — and the `beam_rt` defect it mitigates is owned there.** `Process::deliver`'s on-exhaustion collect relocates the young heap against the crate root set only (registers/stack + mailbox payloads + dict + saved args + pending signals), so a host holding live terms from that heap in Rust locals / nested-`Machine` registers (the `-eval` evaluator environment; a nested `Machine` from `RuntimeContext::run_export`) can see a recycled word — the `beam_rt` WRONG-RESULT defect reproduced by three sequential `io:scan_erl_exprs/4` calls then reading the FIRST result. This crate provides the **fix seam** (`set_relocation_exempt(true)` makes `deliver` surface the raw refusal and `collect`/`ensure_capacity` refuse); **adoption is a `beam_rt` responsibility** — the runtime must mark the affected process from its own GC valve and fall back to its fragment path (`RuntimeContext::deliver_message` → `send_fragmented_message`); until it does, the defect stands. Full mechanism/repro in `../beam_rt/M1_GAPS.md`.
- **Multi-scheduler / SMP (remaining gaps)**: lock-free/threaded run queues, scheduler **balancing**, and the `+S`/`+SDcpu`/`+SDio` flag parsing are not modelled. The table lock is narrower (one reduction quantum, not a slice) but still exclusive, so a process **does not run in parallel** across schedulers (exactly one executes at a time). Dirty-job **term plumbing** is absent (a `DirtyJob` carries no live heap data) and a timer message must be thread-valid (no heap-resident terms). `ThreadProgress` implements the barrier but has **no** delayed-dealloc coupling with `beam_alloc`, and **port tasks are not load-balanced** across schedulers.
- **The signal queue is not cross-ordered with the mailbox.** A trapped `{'EXIT', …}`/`{'DOWN', …}` becomes a mailbox message only when the queued signal is *applied*, so an ordinary send already in the mailbox can be seen before it; remote (external-pid) and port signals bypass the queue entirely. The C's per-*sender* signal-queue granularity and the signal-vs-message ordering barrier remain follow-ups. The queue itself is unbounded (a `VecDeque`, matching the oracle's effectively-unbounded signal queue) with total, defensive GC gather/scatter — it has no overflow or panic path.
- **Off-heap refc-binary reclamation is caller-declared only — there is no automatic liveness scan (owner: `beam_gc` for a public scan-driven predicate, `beam_rt` to drive it).** `Process` owns the off-heap refc binaries it registers (`owned_binaries`) and **sweeps** them on the process path (`run_rooted_collection`'s last step + `sweep_off_heap_binaries()`) with a deliberately **conservative** predicate: an entry is released only when the caller has asserted the death (`declare_off_heap_binary_dead`). Deciding liveness faithfully would require walking the heap for nested on-heap `BinRef`/`ErlSubBits` containers, and that walk (`beam_gc`'s `copy::move_size`/`for_each_ref` via `live.rs`) is `pub(crate)` to `beam_gc`; a shallow raw-word scan from here would be **unsound** (a `BinRef` may live in the mature space, in a message's `Fragments`, or inside another off-heap payload). Consequences, all leak-not-dangle: a payload no caller declares stays owned until the process dies (its `Drop` frees it at reference count 0); an off-heap binary crossing into a process through the **copy engine** is owned by the `Message`/`OffHeapTable`, not by `owned_binaries`, so nothing registers it there automatically; and a relocation-exempt process never runs a collection, so its declared deaths wait for an explicit sweep. `retain_off_heap_binaries` is the seam for whoever can walk the heap. Evidence: `tests/off_heap_binaries.rs`; rationale in `DESIGN_DECISIONS.md`.
- **`Message::from` is NOT a GC root — every producer must store an immediate.** `Process::run_rooted_collection` gathers only each queued message's `payload`/`from`/`token` and re-installs the envelope around the relocated payload, so a producer must keep `from` an **immediate**, matching the C's `ASSERT(is_immed(ERL_MESSAGE_FROM(msg)))` (`erl_proc_sig_queue.c:8441`), where the `{Name,node}` pair / external pid live in the message **body** instead. Every in-crate producer satisfies this: the send paths store the sender pid immediate; a process-monitor `'DOWN'` stores the resolved target pid immediate (`build_and_enqueue_down`); a **failed-by-name** named monitor stores the `system` atom (`deliver_named_noproc_down`, the C's `am_system`); the port builders store the port immediate; the **remote** DOWN/EXIT store the **node atom** (`enqueue_remote_down_message`/`enqueue_remote_exit_message`, the C's DIST_PROC/DIST_PORT rule). `tests/message_from_is_immediate.rs` pins each. Residual (host contract, not fixed here): a caller that hands `Process::deliver` an on-heap `from` term gets no relocation — the general hardening (a `beam_message::Message` `from` setter + gathering `from` in the root set) is owned by the sibling `beam_message`/host.
- **`Process::exit_reason` is not gathered, but is unreachable by a collection (audited).** It is written only in `terminate_into` (`src/ptab.rs`), immediately **after** `take(pid)` and before the PCB drop, and read only through `ProcessTable::exit_reason` — which needs a live pid `take` has already removed — so no collection can invalidate it. Caveat: a future change that reads it post-collection or re-inserts a terminated PCB would need it rooted. (Divergence from the C, which keeps a dead pid's exit reason observable via `process_info`; here `exit_reason` answers `TermNotFound`.)
- **`Message::token` has no producer in this crate** (always `NIL`) and is likewise not gathered — a future `with_token` of an on-heap term would hit the same class as `from`.
- **The `noproc` DOWN is delivered eagerly (documented deviation).** `monitor/2` on a non-live target materialises `{'DOWN', Ref, process, Target, noproc}` straight into the watcher's mailbox, so `process_info(self(), message_queue_len)` reports 1 immediately after the call where the oracle reports 0 (it defers the DOWN as a signal and reveals it at the next `receive`). The divergence is not only against *other* DOWNs but against **ordinary messages** too: the crate always reports the DOWN before a later send, whereas the oracle typically reports the send first (its own order is timing-dependent). A born-down also records **no** local monitor entry, so `demonitor(Ref, [info])` answers `false` where the oracle (itself racy here) answers `true`. Deferring here would be *wrong* until the runtime services pending signals when entering `receive` (the same workaround `beam_rt` already applies to self-directed `exit/2`), so eagerness is deliberate: the receive-visible result and the relative order against later DOWNs both match the oracle. Servicing `service_signals` at the receive point is what would make it exact.
- **Priority run queues**: port tasks, and the C's shared NORMAL/LOW physical queue `schedule_count`/`RESCHEDULE_LOW` fairness deferral (this crate uses four physically distinct FIFOs — see `run_queue.rs`), are follow-ups. `Scheduler::set_priority`/`SchedulerPool::set_priority` DO requeue an already-queued process. The `save_calls` *effect* (saving the last `N` calls for `seq_trace`/`dbg`) is not modelled — only the `process_flag(save_calls, N)` value contract.
- **Pre-emption is produced by `beam_rt`'s runner.** `beam_rt::RuntimeRunner::run` honours its `budget` (charged at the machine's heap-admission points through `beam_rt/src/runner/budget.rs`) and returns `RunOutcome::Yield`, parking the process at the exact instruction — `beam_rt/tests/preempt.rs` pins the resulting interleaving. The crate-level contract is unchanged: the scheduler never pre-empts, so a runner that ignored its budget and never yielded would still run to completion in one call (the scheduler half is pinned by `tests/preemption.rs`).
- **Process-dictionary interior and heap fragments.** The dictionary is modelled as a flat key/value list (no hash-array interior), and `erlang:process_info/1`'s view of it is still absent. A real in-heap `ErlHeapFragment` (a `beam_gc`/`beam_message`-owned type, still absent) is not modelled: saved args are a plain `Eterm` root list and `Process::deliver` fits a message into the receiver's own young heap, growing that heap on demand (collect + grow + retry once) rather than falling back to a fragment. The `ptab.rs` signal builders (`build_signal_term`, `copy_reason_onto`, `deliver_head_signal`) follow the same exhaustion policy through the shared `grow_receiver_for_signal`, so an oversized `{'EXIT',…}`/`{'DOWN',…}` reason also grows the receiver's nursery on demand instead of being lost, and a **relocation-exempt** receiver surfaces the raw `AllocKind::Heap`/`Message` refusal unchanged (no collect, no growth, no retry) — `tests/signal_exhaustion.rs`.
- **Distribution-wide links/monitors**: external pids are decomposed into a `remote::RemotePid` and recorded (`remote_links`/`remote_monitors`), and every relationship change is routed through the `remote::DistSignalRouter` trait seam (implemented downstream over `beam_dist`; no crate dependency). **Inbound** decoded control messages (`DOP_LINK`/`DOP_MONITOR_P`/`DOP_EXIT`/`DOP_EXIT2`) are **not** yet fed into the table — that interpreter and the `DistSignal`→`Dop` adapter belong to `beam_rt` (a documented handoff); with no router installed the table is record-only (`has_dist_router()`). The outbound `DistSignal` keeps the link exit (`Exit` → `DOP_EXIT`) and `erlang:exit/2` (`Exit2` → `DOP_EXIT2`) distinct.
- **Port lifecycle driving** — port scheduling, port signals and the port's read path — remains `beam_io`'s; `PortTable` owns only the id plus the ownership/links/monitors, and `ProcessTable::port_closed` delivers the closing port's messages.
- **Port-monitor cleanup on death needs a `PortTable` handle; the `Scheduler` adopts one.** `terminate_into` always drains `Process::port_monitors` (and the exit observer always sees them), but the matching *incoming* `PortMonitor` entries are removed from the `PortTable` only when a handle is supplied. A `Scheduler` built with `with_ports`/`set_ports` owns a `PortTable`, and its default `run_slice`/`run_ready` then service signals through `service_signals_with_ports` and terminate through `terminate_with_ports`, so a process that dies in a slice cleans its dangling incoming `PortMonitor` (`tests/scheduler_ports.rs`). A scheduler built with `new`/`with_slice` owns none and keeps the port-less behaviour (outgoing watches drained, incoming left in place); the explicit `run_slice_with_ports`/`run_ready_with_ports` take a table that overrides the owned one for that call. The port-less `ProcessTable` entry points (`terminate`, `service_signals`, `apply_exit_signal`/`send_exit` (`erlang:exit/2`), `node_down`) still pass no ports, so a process killed through one of those leaves its incoming `PortMonitor` until the owner runs `service_signals_with_ports` at the peer's next schedule-in. The SMP pool is port-less — adopting a table there would add a **fourth lock family** to the BINDING discipline in `src/smp/CONTEXT.md`, so it is deferred (the pool has no production consumer).
- **Exact exit-reason term from `beam_common::ExitReason`**: signal reasons are carried as live `Eterm` terms (the deliverable form), not the term-independent `beam_common::ExitReason`; the mapping between them belongs to the raising BIF layer (`beam_bifs`).
- **`process_info` source data.** Every item this crate can answer is backed by a public accessor (`tests/process_info_source.rs` pins the mapping): `status` → `Process::status()`, `registered_name` → `ProcessTable::name_of(pid)`, `message_queue_len` → `Process::mailbox().len()`, `links` → `Process::links().iter()`, `monitors` → `Process::monitors().iter()` (+ `port_monitors()` for the `{port, Port}` entries), `monitored_by` → `Process::monitored_by()`, `trap_exit` → `Process::is_trapping_exit()`, `priority` → `Process::priority()`, `reductions` → `Process::reductions()`. Still absent: `current_function`/`current_location` (nothing tracks the running MFA) and the `erlang:process_info/1` whole-dictionary view.
- **Monitor semantics not modelled.** `MonitorKind` has no `TimeOffset` variant (`erlang:monitor(time_offset, _)` is the oracle's `badarg`, which the BIF layer raises); `erlang:monitor_node/2,3` is **out of this crate's scope** — node-level distribution needing a local node identity plus an inbound `DOP_*` path, neither of which this crate owns; and a **named** port monitor (`monitor(port, Name)`) is a typed `unsupported` (the local name registry resolves names to processes only, so answering with a process monitor would be a wrong result). `erlang:monitor/2` on a non-live target yields the oracle's `noproc`; only its **timing** is a deviation (the DOWN is delivered eagerly — see above). `erlang:monitor/3`'s `{tag, T}` form **is** implemented for an **immediate** `T` on process **and** port targets (the tag lives in the `tags` side table); the remaining gap is exactly a **non-immediate** tag and a tag on a **remote** external-pid target (both typed `unsupported`). The tag-less `monitor/2` form is complete.
- **`process_flag` coverage gap (owner: `beam_rt`/`beam_gc`).** `beam_rt`'s `ProcessBridge::process_flag` answers `badarg` for every flag except `trap_exit`/`sensitive`/`priority`/`save_calls`/`error_handler`, where the oracle returns the **previous value** for `max_heap_size`/`min_heap_size`/`min_bin_vheap_size`/`fullsweep_after`/`message_queue_data`. `Process` has no `max_heap_size` storage and `beam_gc::AnyCollector` exposes only `policy()` (no `policy_mut`), so the setter and the kill/log enforcement are a `beam_rt`+`beam_gc` handoff. No `max_heap_size` enforcement exists in this crate.
- **`spawn_opt` option validation gap (owner: `beam_rt`/`beam_gc`).** `{max_heap_size, N}` with `N != 0` and `N < min_heap_size` is accepted where the oracle is `badarg` (the C `erl_process.c`'s `max_heap_size < min_heap_size ⇒ -1`); and `process_info(P, message_queue_data)` reports `on_heap` regardless of a `{message_queue_data, off_heap}` spawn option.
- **`port_info` item gap (owner: `beam_bifs`/`beam_rt`).** `port_info(P, queue_size)` and `port_info(P, locking)` are `badarg` where the oracle answers `{queue_size, 0}` / `{locking, port_level}`; the 7-item `port_info/1` roster and order already match.
- **The compatibility gate is green.** `tools/differential/gate.sh --strict --allowlist tools/differential/known-gaps.txt` (a sibling, read-only here) reports `total=1328 agree=1327 mismatch=0 unsupported=1 skipped=0 allowed=1 unauthorized=0 stale=0` (exit 0). The single allowlisted gap is `wire/new_fun_ext_encode` (A.5, unclosable by design — an `erl_eval` template closure). Re-run `gate.sh` for the live figure.

## Notes for Agents
- Read `../CONTEXT.md` (crate-layer contracts, the `Process`/`Scheduler` seam) and `../../CONTEXT.md` §1 A.1/§3/§5 before changing this crate. Ground truth is the legacy C listed above — **read it; never modify it.**
- The **SMP pool lives in `src/smp/`** and must follow the **locking discipline** documented in `src/smp/CONTEXT.md` (never hold a queue lock while taking the table lock and vice-versa; buffer requeues while the table guard is held; the only nested order is *signals mutex → queue lock*). It reuses the frozen `slice_begin`/`slice_end`/`drain_woken_into` helpers (in `run_locked_quanta`) — do **not** re-implement slice logic in a worker.
- `ProcessTable` is `!Send`, so moving it into the pool needs `SharedProcessTable`'s two `unsafe impl Send/Sync` — the **contained workaround** (all access is serialised by the inner mutex). The measured `!Send` causes are **five**: `beam_alloc::Heap`'s `base: *mut Eterm`, `beam_gc::MsoHandle`'s `ptr: NonNull<Mso>` (via `beam_message::OffHeapTable`), the `Rc<AtomTable>` in each `Dict`, and this crate's own `Option<Box<dyn DistSignalRouter>>` and `Option<Box<dyn ProcessExitObserver>>` (`beam_alloc::RefcBinary` is already `Send`). The `Rc<AtomTable>` is never cloned and never shared outside the table, so no `Rc` is touched from two threads. The full invariant lives in `src/smp/CONTEXT.md` and `src/smp/mod.rs`. Removing the workaround needs an upstream `beam_gc`/`beam_alloc` change this crate must not make — do not widen this `unsafe`.

Exact policy under Constraints.
- The collector moves live terms, so **every** in-heap reference must be a root. `Process::collect` scans registers/stack, mailbox payloads, the process dictionary (`Dict`), the saved args (`SavedArgs`) and the pending-signal queue (`SignalQueue`) — add any NEW in-heap sub-rootset to its gather/scatter, in the same order, in the same change. `Process::port_monitors` is deliberately **not** a root: a `PortWatch` holds only plain values (a `MonitorRef` and a `PortId`).
- **Where the PCB and its heap live (address stability).** A `Process` is stored **inline** in `ProcessTable`'s `slots: Vec<Slot>` (`Slot.process: Option<Process>`, `src/ptab.rs`), so growing the table (`alloc_pid`/`insert`) can reallocate the `Vec` and **move** the PCB — and with it its embedded `AnyCollector`/`HeapSpace`/`Heap` struct — to a new address. The heap *words* are unaffected by that move: `beam_alloc::Heap` owns a separate allocator block (`Heap::base: *mut Eterm`, `beam_alloc/src/heap.rs`), so terms obtained via `get_mut(pid).heap_mut()` stay valid across a table growth (Rust's borrow rules forbid holding the `&mut` across the growth anyway). The `&mut Heap` **identity** is *not* stable across a collection, though: a fullsweep replaces the mature space (`AnyCollector::collect_major`) and `resize_nursery`/`grow_nursery` replace the nursery, so re-obtain `heap_mut()` after any `collect()` — never cache a heap pointer across one.
- **Pre-emption is the RUNNER's obligation.** A `ProcessRunner` must count its own reductions and return `RunOutcome::Yield` at its `budget`; the scheduler then requeues at the PCB's current priority. A runner that never yields is not pre-empted. `tests/preemption.rs` pins the scheduler half; `beam_rt`'s runner and its `beam_rt/tests/preempt.rs` interleaving pin are under Known Issues.

Every other host use (`young()`, `stats()`, `minor_gcs()`, `policy()`, `heap_size_words()`, `total_heap_size_words()`) resolves unchanged.
