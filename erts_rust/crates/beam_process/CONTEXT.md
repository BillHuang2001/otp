# `beam_process` — Processes, Scheduler, Run Queues, Signals
## Intent
Owns the **OS-thread-level concurrency plumbing** of the Rust ERTS rewrite (Stage 5, Part II §H): the per-process control block (PCB), the four-level run queue, the cooperative scheduler loop, the **multi-scheduler (SMP) pool** (`SchedulerPool`: N scheduler threads over one shared table, per-scheduler run queues with work stealing, the `ThreadProgress` cross-scheduler barrier, the `TimerService` and two `DirtyPool`s), the **exit-signal / link / monitor** machinery (the decoupled per-process signal queue + its signal-message builders), the process table (`ptab`) with its local name registry, the **port-id table** and its ownership/link/monitor surface, and the local records for **remote (distributed) links/monitors**.
It is what makes Erlang **processes** real — isolation, `spawn`, links, monitors and exit propagation — the process half of workspace `../CONTEXT.md` §1 **A.1**.
It is consumed by `beam_bifs` (spawn/send/receive/`process_info`/`monitor`/`link` BIFs), `beam_io` (ports + the process side of I/O completion) and `beam_rt` (boot/CLI/`system_info`).
It **drives** `beam_gc` (collector + MSO) at safepoints and **uses** `beam_message` (`Queue` mailbox + `send`/`receive` copy engine) — it reimplements neither.
Legacy C ground truth (read-only `../../erts/emulator/beam/`; the Routing Table maps each to its module): `erl_process.{c,h}` (PCB/scheduler/run queues), `erl_proc_sig_queue.c`, `erl_monitor_link.c`, `erl_ptab.{c,h}`, `erl_process_dict.c`, `erl_vm.h` (`MAX_REG`/`MAX_ARG`), `erl_thr_progress.c`, `erl_hl_timer.c`, `erl_nfunc_sched.c`.
**Attribution boundary** (a C-deletion record must not attribute these here): the allocators (`erl_alloc*.c`, `erl_goodfit/bestfit/afit/ao_firstfit_alloc.c` → `beam_alloc`), the message copy engine (`erl_message.c`/`copy.c` → `beam_message`), crash dumping (`erl_process_dump.c`/`erl_crash_dump.c` → `beam_rt`'s `crash_dump.rs`); microstate accounting (`erl_msacc.c`) and flexible counters (`erl_flxctr.c`) are modelled by no crate (`beam_rt` lists the `mc_*`/`scheduler_wall_time` BIFs as a native gap); `erl_thr_queue.c`, `erl_sched_spec_pre_alloc.c`, `erl_process_lock.c` are unmodelled; time services (`time.c`/`erl_time_sup.c`) are `beam_bifs`'s time BIFs / `beam_rt`'s, and this crate's `timer.rs` is the `erl_hl_timer.c` analogue.
## Milestone-1 scope
Two scheduler fronts share the **same** slice logic — `scheduler::{slice_begin, slice_end}` (with `run_one` = both halves around one full-budget runner call) plus `drain_woken_into`: the single-threaded `Scheduler` loop (slice semantics frozen) and the SMP `SchedulerPool` (N threads over one shared table), so SMP adds *concurrency* and a bounded lock hold (one reduction **quantum**, `SchedulerConfig::set_lock_quantum`, default `DEFAULT_LOCK_QUANTUM = 256`), not a second scheduler.
"Correct" means the pid table, the four-level run-queue order, message delivery, the decoupled per-process signal queue, the monitor/registration surface, the process-dictionary and saved-argument sub-rootsets, the port ownership/link/monitor surface, remote links/monitors through the `DistSignalRouter` seam, and a safepoint GC over the process root set all match the C/oracle for the common cases and are test-covered; deliberate gaps are under Known Issues.

### Cross-module binding rules
- **Eager-vs-queued signalling (`ptab.rs`).** A signalling operation **enqueues** a `PendingSignal` on the receiver (copying the reason into its own heap) — never applies it inline; servicing happens at the receiver's schedule-in (`service_signals`, from `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is *not* the currently `Running` process (ERTS's early signal handling): `apply_exit_signal`/`terminate`/`send_exit` share one rule — every receiver joins the service worklist unless `ProcessState::Running`. `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. A **remote** (external-pid) or **port** signal bypasses the queue entirely (no `trap_exit` policy to defer), so `node_down`/`port_closed` materialise it straight into the mailbox.
  An exit signal's `ExitFamily` is carried **on the queued signal** (`PendingSignal::Exit`'s `family`) and read back at service time by `apply_head_signal`, so the local link cascade — which defers to the receiver's schedule-in — still decides a `kill` as a **link** exit.
  `apply_exit_signal`/`send_exit`/`send_exit_term` are the explicit `erlang:exit/2` family, while the `terminate_into` link loop, `node_down` and `port_closed` step 2 are the link family.
- **Collect-then-apply worklist (`ptab.rs`).** `ProcessTable` is the single place that mutates ≥2 processes (the C ptab lock domain); its cross-process operations collect the intended effects into a worklist and apply it after the mutation pass. M1 is single-threaded, so the table holds `Process` values directly.
- **Split borrows (`process.rs`).** `heap_and_off_heap_mut()` (young heap + off-heap table, drives `beam_message::Fragments::move_into`) and `heap_and_mailbox_mut()` (young heap + mailbox, drives `beam_message::send_fragmented`) are the only two `*_mut` pairs with a real caller need; each destructures `self` into two disjoint `&mut` fields in safe Rust and **must not** be joined into one raw-pointer accessor.
- **Frozen field sets.** `Monitor`/`MonitoredBy`/`PortWatch` are constructed by struct literal from `beam_rt`, so no field may be added (the `monitor/3` user tag lives in a private `ProcessTable` side table instead); `Process`'s field shape and `ProcessExit<'a>`'s private-fields-plus-accessors shape are frozen the same way.
- **`DistSignalRouter` is OUTBOUND only** (local → remote), and it stays that way. The crate now also owns the inbound (receipt) **primitives** — `ProcessTable::{record_remote_link, apply_remote_exit_signal, unlink_from_remote, unlink_ack_from_remote, monitor_from_remote, monitor_from_remote_ref, demonitor_from_remote, demonitor_from_remote_ref, remote_watchers, remote_monitor_down, set_group_leader_from_remote, group_leader}` — which take the **already-parsed** pieces of a `DOP_*` (an `RemotePid`, a `MonitorRef` *or* a decomposed peer `RemoteRef`, a reason term) and never route: the C's receipt arms do not echo the opcode they received (`dist.c:2258` `break; /* Done */`). The `_ref` spellings key a `RemoteWatcher` by the whole reference identity, so a peer's wire reference is stored faithfully (no lossy `u64` pack: two distinct peer references never collapse). Decoding the wire and choosing which primitive to call remains `beam_rt`'s (`../beam_rt/src/dist_client.rs`), as does the `DistSignal`→`Dop` adapter.
- **`Message::from` must be an immediate** — a producer contract, reasoned in Known Issues below.
## Constraints
- **Errors:** `beam_common::{Result, BeamError}` only — never a crate-local error enum, never `panic!`/`unwrap()` on runtime data. Unknown pid/name/ref ⇒ `BeamError::TermNotFound`; a malformed pid term or out-of-range register index ⇒ `BeamError::BadArg`; pid/port space exhaustion ⇒ `BeamError::SystemLimit`; `beam_term::TermError` is reconciled upstream, so `?` crosses the boundary.
- **Heap exhaustion (`AllocKind::Heap`) is collect-grow-and-retry, not fatal OOM.** During a delivery **or a signal build** the receiver's nursery is collected, grown on demand, and the operation retried **once** (propagating the retry's own `BeamError::Alloc`) — the policy `Process::deliver` and the `ptab.rs` signal builders (through the shared `grow_receiver_for_signal`) implement. A receiver whose relocating collection is **declined** — by the crate-owned `Process::has_unpublished_roots`, or by the host's installed `CollectionGate` (`declines_relocation`, consulted first at every signal site and at `ProcessTable::deliver` and OR-ed with the crate-owned predicate) — never collects or grows **on demand** for a delivery: the crate-owned predicate covers a **relocation-exempt** receiver (whose host holds live terms the root set does not publish) and a currently **`Running`** one (whose own machine's x/stack/float registers live outside `Process::regs`, a host-published snapshot refreshed only at a heap-admission point or a park, so a mid-slice collection would relocate the heap against a stale root set and recycle live words), and the host gate covers a receiver whose live root set is not fully scanned by its collector. Either source takes the same refusal — no collection, no growth, no relocation (the collect-then-grow `ensure_capacity` route is what is refused; the no-relocation `grow_nursery` is unaffected by the flag) — so a control signal such a receiver cannot take is put in a `beam_message::HeapFragment` instead (the C's model, `erl_proc_sig_queue.c`), whichever of the two sites refused it: the **apply-time** message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) or the **enqueue-time** reason copy (`copy_reason_onto` → `enqueue_down_signal`/`enqueue_exit_signal`, which build the message the queue would have materialised straight from the enqueue site, since a queued signal's reason can live nowhere but the receiver's own heap, and wake a blocked receiver themselves). The one refusal still surfaced is the exit **policy** one — an exit signal to a **non-trapping** receiver, which would have to *terminate* it, and a termination is the caller's cascade rather than a message; a collection/growth refused for an exempt process is the typed `relocation_exempt` raise. Because the nursery grows on demand, a refused delivery — the raw `AllocKind::Heap`/`AllocKind::Message` a caller's heap-fragment fallback keys on (`../beam_rt`'s `deliver_message`) — means either that the receiver's relocating collection was **declined** (no collection was attempted) or that its heap policy could NOT grow the nursery to fit the payload (e.g. a `max_heap_words` cap, or a collection that cannot make room); with an unbounded policy and published roots every payload is delivered into the grown young heap.
- **Inside `terminate_into` a per-peer signal-build (or `route`) failure is *not* propagated** — the process is already reclaimed, so it is logged via `beam_common::beam_error!` and the cascade continues.
- **`unsafe` is confined** to the modules that touch raw words: `monitor.rs` (message/ref builders) and `remote.rs` (the external-pid thing via `beam_term`'s `unsafe` predicates, tuple/ref words via `beam_alloc::Heap::alloc_words`), plus `src/smp/mod.rs`'s two documented `unsafe impl Send`/`Sync for SharedProcessTable` — nothing else in the SMP pool. **`process.rs` has no production `unsafe`**: the off-heap reachability sweep reads a reachable `BinRef`'s payload word through `beam_gc`'s safe `ReachableObject` view (`AnyCollector::for_each_reachable_object_view`), so no raw-pointer arithmetic of its own is needed. Every `unsafe fn` has a `# Safety` section and every `unsafe` block a preceding `// SAFETY:` rationale (`../beam_common/src/safety.rs`); `unsafe_op_in_unsafe_fn` stays clean. Safe Rust (production): `pid.rs`, `registers.rs`, `run_queue.rs`, `link.rs`, `monitor.rs` set logic, `process.rs`, `signal.rs`, `ptab.rs` bookkeeping, `signal_queue.rs`, `port.rs`, `progress.rs`, and all of `smp/`'s `queues.rs`/`worker.rs`/`stats.rs`/`pool.rs` + `timer.rs`/`dirty.rs` (synchronisation via `parking_lot` mutexes/condvars + atomics).
- **Never assume a different term layout** — build/inspect terms only through `beam_term`'s public accessors + `beam_alloc::Heap`'s builders; pid/port immediates are bit-exact with `beam_term::immediate` (`make_internal_pid`/`pid_number`/`pid_serial`).
- **Reuse, do not reimplement:** the mailbox is `beam_message::Queue`; the copy engine is `beam_message::{send, receive, CopyContext}`; the heaps are `beam_gc::AnyCollector`/`beam_gc::HeapSpace`/`beam_alloc::Heap`; the off-heap objects are `beam_gc::MsoHandle`/`beam_message::OffHeapTable`.
- **Deps (fixed by `Cargo.toml`):** `beam_common`, `beam_term`, `beam_alloc`, `beam_gc`, `beam_message`, `libc`, `parking_lot`; adding a dependency edge requires reporting to `../`. `beam_engine` is **NOT** a dependency (the `ProcessRunner` trait keeps the DAG acyclic).
- Files target ~1000 lines, one responsibility per file, Apache-2.0. The `src/smp/*` files, `src/timer.rs` and `src/dirty.rs` are each well under that figure; `src/ptab.rs` (the table + signal hub) is the only file over it and deliberately stays whole because the signal/link/monitor servicing is tightly coupled to `ProcessTable`'s private fields (`slots`/`atoms`/`refs`/`ready`), which a sibling module cannot reach — a structural-debt candidate to extract if it grows further or field visibility widens.

## Design Decisions
The rationale (why) behind the frozen API and constraints lives in **`DESIGN_DECISIONS.md`** (this file keeps the what: API Surface, Constraints, Known Issues).
## Known Issues (intentionally NOT covered in Milestone-1)
- **Reference aliases are unsupported on a port monitor and on a remote target.** `monitor(port, P, [{alias, _}])` and `monitor(process, RemotePid, [{alias, _}])` are typed `unsupported`s rather than accepted aliases: `alias_reply_delivered` holds no `&mut PortTable`, so a `reply_demonitor` port alias could not remove the port's incoming `PortMonitor`, and a later `port_closed` would deliver a `{'DOWN', …}` the oracle never does — a **wrong result**, so it is refused instead (reason string `error::unsupported_port_monitor_alias()`, mirroring the pre-existing remote-tag diagnostic). No OTP caller combines either.
- **The `{tag, Tag}` monitor option accepts only an immediate.** The oracle accepts any term; this crate refuses a non-immediate tag with a typed `unsupported`, because a tag lives in the `tags: HashMap<MonitorRef, Eterm>` side table, which is **not** a GC root — a per-process-heap tag could not be relocated and would dangle after a collection. Making it faithful needs a gather/scatter of the tag table in the collection walk. (The `aliases` side table is the same concern but its entries are plain values — no term — so it needs no rooting.)
- **The `from`/`token` envelope roots are gathered and relocated, but no in-tree producer enqueues a heap word there yet.** `beam_message::Queue::enqueue`'s debug `debug_assert_enqueue_terms` tripwire still rejects a non-immediate `from`/`token`, so a host storing a heap word (the C permits a heap `token` tuple, `erl_message.c:388-390`, and a heap Info-tuple `from`, `erl_proc_sig_queue.c:2272`) must (a) opt into the gather — done: `run_rooted_collection` pushes `Message::from`/`token` and scatters them back through `set_from`/`set_token` — **and** (b) deliberately relax that tripwire in the sibling `beam_message`, which has not happened. Until then every envelope word stays an immediate and this rooting is defensive.
- **A host holding unpublished live roots is why the delivery gate exists.** `Process::deliver`'s on-exhaustion collect relocates the young heap against the crate root set only (registers/stack + mailbox payloads + dict + saved args + pending signals), so a host holding live terms from that heap in Rust locals / nested-`Machine` registers (the `-eval` evaluator environment; a nested `Machine` from `RuntimeContext::run_export`) must not have the heap move under it. Two conditions mark such a receiver — together the crate-owned `has_unpublished_roots`: the per-process **relocation-exempt** flag (`set_relocation_exempt(true)` makes `deliver` surface the raw refusal and `collect`/`ensure_capacity` refuse), which the host asserts, and the **`Running`** state, which the crate derives for the process its own engine is executing. `beam_rt` **adopts** the exempt half — it runs the `-eval` driver and the nested-`Machine` scopes under `RuntimeContext::with_relocation_exempt` and exempts the sending context's own pid on the send path (`deliver_message_with_off_heap`), routing a refused delivery to its fragment fallback (`RuntimeContext::deliver_message` → `send_fragmented_message`) — so the `-eval` held-result case agrees with the oracle (`beam_rt/tests/io_scan.rs::a_scan_result_held_across_later_requests_matches_the_live_oracle`). Setting the exempt flag remains a host responsibility (only the host can assert that a process's root set is unpublished); the `Running` half needs no host marking. The host's **`CollectionGate`** is the same policy's third case — a predicate the host installs (`ProcessTable::set_collection_gate`) to decline a relocating collection for a receiver whose live root set is **not** fully scanned by its collector; a decline refuses the relocation only, so the notification is still delivered fragment-resident. Full mechanism and the residual hazards outside this gate: `../beam_rt/M1_GAPS.md`.
- **Multi-scheduler / SMP (remaining gaps)**: lock-free/threaded run queues, scheduler **balancing**, and the `+S`/`+SDcpu`/`+SDio` flag parsing are not modelled. The table lock is narrower (one reduction quantum, not a slice) but still exclusive, so a process **does not run in parallel** across schedulers (exactly one executes at a time). Dirty-job **term plumbing** is absent (a `DirtyJob` carries no live heap data) and a timer message must be thread-valid (no heap-resident terms). `ThreadProgress` implements the barrier but has **no** delayed-dealloc coupling with `beam_alloc`, and **port tasks are not load-balanced** across schedulers.
- **The signal queue is not cross-ordered with the mailbox.** A trapped `{'EXIT', …}`/`{'DOWN', …}` becomes a mailbox message only when the queued signal is *applied*, so an ordinary send already queued can be seen before it; remote (external-pid) and port signals bypass the queue entirely. The C's per-*sender* signal-queue granularity and the signal-vs-message ordering barrier remain follow-ups. The queue itself is unbounded (a `VecDeque`, matching the oracle's effectively-unbounded signal queue) with total, defensive GC gather/scatter — no overflow or panic path.
- **Off-heap refc-binary reclamation is reachability-driven, with two residual gaps.** A process's **own** owned list (`owned_binaries`) is reclaimed automatically by the **reachability** sweep (`sweep_off_heap_binaries_reachable`), the crate half of the automatic liveness decision: `run_rooted_collection` runs it (through `sweep_off_heap_binaries_reachable_from`, over the roots it just gathered) as the **first** half of its off-heap step, so a payload no reachable on-heap `BinRef` names is released — using `beam_gc::AnyCollector::for_each_reachable_object_view`, the public/safe/read-only/whole-heap walk, whose reachable `HEADER_BIN_REF` objects name their payload at `BinRef` word 1 (the frozen `BinRef.val` contract, `RefcBinary::data_ptr()`), read through the safe `ReachableObject::word` accessor. The **conservative** declared-dead sweep (`sweep_off_heap_binaries`, releasing only a caller's asserted `declare_off_heap_binary_dead`) always runs as the **second** half, so a declared death is honoured whether or not the reachability half was sound. Evidence: `tests/off_heap_binaries.rs`, `tests/off_heap_reachability.rs`; rationale in `DESIGN_DECISIONS.md`. Two gaps remain: (1) an off-heap binary arriving via the **copy engine** is owned by the `Message`/`OffHeapTable`, not `owned_binaries`, so nothing auto-registers it — only the process's own registrations are swept; (2) a process with **unpublished roots** — relocation-exempt, or currently `Running` — is **retained entirely** by the reachability sweep (its **decline valve**: `sweep_off_heap_binaries_reachable` returns `Ok(0)` and retains everything), because its root set is incomplete and a missed live `BinRef` would release a live payload (a dangle); only the conservative declared-dead path (or a later non-declined collection) reclaims such a process's payloads.
- **`Message::from` is NOT a GC root — every producer must store an immediate.** `Process::run_rooted_collection` gathers only each queued message's `payload`/`from`/`token` and re-installs the envelope around the relocated payload, so a producer must keep `from` an **immediate**, matching the C's `ASSERT(is_immed(ERL_MESSAGE_FROM(msg)))` (`erl_proc_sig_queue.c:8441`), where the `{Name,node}` pair / external pid live in the message **body** instead. Every in-crate producer does: the send paths store the sender pid immediate; a process-monitor `'DOWN'` the resolved target pid immediate (`deliver_down_message`); a **failed-by-name** named monitor the `system` atom (`deliver_named_noproc_down`, the C's `am_system`); the port builders the port immediate; the **remote** DOWN/EXIT the **node atom** (`enqueue_remote_down_message`/`enqueue_remote_exit_message`, the C's DIST_PROC/DIST_PORT rule). `tests/message_from_is_immediate.rs` pins each. Residual (host contract): `beam_message::Queue::enqueue`'s debug tripwire still rejects a non-immediate `from`/`token`, so a host storing a heap word there must relax that tripwire in the sibling `beam_message`; the gather/scatter hardening (`run_rooted_collection` pushes `from`/`token` and writes them back via `Message::set_from`/`set_token`) is already in place here.
- **`build_signal_message` reuses its `reason` argument verbatim across its collect-grow retry; `deliver_head_signal` does not.** `src/ptab.rs`'s `build_signal_message(recipient, from, reason, build)` runs `grow_receiver_for_signal` (which can relocate the receiver's **whole** young heap) and then calls `build(recipient.heap_mut(), reason)` with the **same** word, so a caller must pass a `reason` that is an immediate or lives outside the receiver's young heap (every in-tree caller does: the `noproc` atom, a node-down / port-close reason). The queued-signal path is immune because `deliver_head_signal` re-derives the reason from the receiver's own signal queue (`head_signal_reason`) each attempt — precisely because that reason *does* live in the receiver's heap (copied there by `copy_reason_onto` at enqueue time).
- **`Process::exit_reason` is not gathered, but is unreachable by a collection (audited).** It is written only in `terminate_into` (`src/ptab.rs`), immediately **after** `take(pid)` and before the PCB drop, and read only through `ProcessTable::exit_reason` — which needs a live pid `take` has already removed — so no collection can invalidate it. Caveat: a future change that reads it post-collection or re-inserts a terminated PCB would need it rooted. (Divergence from the C, which keeps a dead pid's exit reason observable via `process_info`; here `exit_reason` answers `TermNotFound`.)
- **`Message::token` has no producer in this crate** (always `NIL`) and is likewise not gathered — a future `with_token` of an on-heap term would hit the same class as `from`.
- **The `noproc` DOWN is delivered eagerly (documented deviation).** `monitor/2` on a non-live target materialises `{'DOWN', Ref, process, Target, noproc}` straight into the watcher's mailbox, so `process_info(self(), message_queue_len)` reports 1 right after the call where the oracle reports 0 (it defers the DOWN as a signal and reveals it at the next `receive`). The divergence is against **ordinary messages** too: the crate always reports the DOWN before a later send, whereas the oracle typically reports the send first (its own order is timing-dependent). A born-down also records **no** local monitor entry, so `demonitor(Ref, [info])` answers `false` where the oracle (itself racy here) answers `true`. Deferring would be *wrong* until the runtime services pending signals on entering `receive` (the workaround `beam_rt` already applies to self-directed `exit/2`), so eagerness is deliberate: the receive-visible result and the order against later DOWNs both match the oracle. Servicing `service_signals` at the receive point would make it exact.
- **Priority run queues**: port tasks, and the C's shared NORMAL/LOW physical queue `schedule_count`/`RESCHEDULE_LOW` fairness deferral (this crate uses four physically distinct FIFOs — see `run_queue.rs`), are follow-ups. `Scheduler::set_priority`/`SchedulerPool::set_priority` DO requeue an already-queued process. The `save_calls` *effect* (saving the last `N` calls for `seq_trace`/`dbg`) is not modelled — only the `process_flag(save_calls, N)` value contract.
- **Pre-emption is produced by `beam_rt`'s runner.** `beam_rt::RuntimeRunner::run` honours its `budget` (charged at the machine's heap-admission points through `beam_rt/src/runner/budget.rs`) and returns `RunOutcome::Yield`, parking the process at the exact instruction — `beam_rt/tests/preempt.rs` pins the resulting interleaving. The crate-level contract is unchanged: the scheduler never pre-empts, so a runner that ignored its budget and never yielded would still run to completion in one call (the scheduler half is pinned by `tests/preemption.rs`).
- **Process-dictionary interior and heap fragments.** The dictionary is modelled as a flat key/value list (no hash-array interior), and `erlang:process_info/1`'s view of it is still absent. Saved args are a plain `Eterm` root list and `Process::deliver` fits a message into the receiver's own young heap, growing that heap on demand (collect + grow + retry once — the Constraints policy) rather than falling back to a fragment; the fragment-resident cases are a control signal for a receiver whose relocating collection is declined — the crate-owned **unpublished live roots** (**relocation-exempt** or **`Running`**) or the host's `CollectionGate` — the apply-time message build **and** the enqueue-time reason copy (their own suites, `tests/signal_fragment_fallback.rs`, `tests/decline_gate.rs`). `tests/signal_exhaustion.rs` covers the collect-grow-and-retry path and the exit-**policy** refusal a receiver whose collection is declined still meets (an exit signal that would terminate it).
- **Distribution-wide links/monitors**: external pids are decomposed into a `remote::RemotePid` and recorded (`remote_links`/`remote_monitors`), and every relationship change routes through the `remote::DistSignalRouter` trait seam (implemented downstream over `beam_dist`; no crate dependency). **Inbound** decoded control messages (`DOP_LINK`/`DOP_MONITOR_P`/`DOP_EXIT`/`DOP_EXIT2`) are **not** yet fed into the table — that interpreter and the `DistSignal`→`Dop` adapter belong to `beam_rt` (a documented handoff); with no router the table is record-only (`has_dist_router()`). The outbound `DistSignal` keeps the link exit (`Exit` → `DOP_EXIT`) and `erlang:exit/2` (`Exit2` → `DOP_EXIT2`) distinct.
- **Port lifecycle driving** — port scheduling, port signals and the port's read path — remains `beam_io`'s; `PortTable` owns only the id plus the ownership/links/monitors, and `ProcessTable::port_closed` delivers the closing port's messages.
- **Port-monitor cleanup on death needs a `PortTable` handle; the `Scheduler` adopts one.** `terminate_into` always drains `Process::port_monitors` (and the exit observer always sees them), but the matching *incoming* `PortMonitor` entries leave the `PortTable` only when a handle is supplied. A `Scheduler` built with `with_ports`/`set_ports` owns one, so its default `run_slice`/`run_ready` service signals through `service_signals_with_ports` and terminate through `terminate_with_ports` — a process dying in a slice cleans its dangling incoming `PortMonitor` (`tests/scheduler_ports.rs`). A scheduler built with `new`/`with_slice` owns none and keeps the port-less behaviour (outgoing watches drained, incoming left in place); the explicit `run_slice_with_ports`/`run_ready_with_ports` override the owned table for one call. The port-less `ProcessTable` entry points (`terminate`, `service_signals`, `apply_exit_signal`/`send_exit` (`erlang:exit/2`), `node_down`) pass no ports, so a process killed through one leaves its incoming `PortMonitor` until the owner runs `service_signals_with_ports` at the peer's next schedule-in. The SMP pool is port-less — a table there would add a **fourth lock family** to the BINDING discipline in `src/smp/CONTEXT.md`, so it is deferred (the pool has no production consumer).
- **Exact exit-reason term from `beam_common::ExitReason`**: signal reasons are carried as live `Eterm` terms (the deliverable form), not the term-independent `beam_common::ExitReason`; the mapping between them belongs to the raising BIF layer (`beam_bifs`).
- **`process_info` source data.** Every item this crate can answer is backed by a public accessor (`tests/process_info_source.rs` pins the mapping): `status` → `Process::status()`, `registered_name` → `ProcessTable::name_of(pid)`, `message_queue_len` → `Process::mailbox().len()`, `links` → `Process::links().iter()`, `monitors` → `Process::monitors().iter()` (+ `port_monitors()` for the `{port, Port}` entries), `monitored_by` → `Process::monitored_by()`, `trap_exit` → `Process::is_trapping_exit()`, `priority` → `Process::priority()`, `reductions` → `Process::reductions()`. Still absent: `current_function`/`current_location` (nothing tracks the running MFA) and the `erlang:process_info/1` whole-dictionary view.
- **Monitor semantics not modelled.** `MonitorKind` has no `TimeOffset` variant (`erlang:monitor(time_offset, _)` is the oracle's `badarg`, raised by the BIF layer); `erlang:monitor_node/2,3` is **out of scope** — node-level distribution needing a local node identity plus an inbound `DOP_*` path, neither owned here; and a **named** port monitor (`monitor(port, Name)`) is a typed `unsupported` (the name registry resolves names to processes only, so a process monitor would be a wrong result). `erlang:monitor/2` on a non-live target yields the oracle's `noproc`; only its **timing** deviates (the DOWN is delivered eagerly — see above). `erlang:monitor/3`'s `{tag, T}` form **is** implemented for an **immediate** `T` on process **and** port targets (the tag lives in the `tags` side table); the remaining gap is a **non-immediate** tag and a tag on a **remote** external-pid target (both typed `unsupported`). The tag-less `monitor/2` form is complete.
- **`process_flag` coverage gap (owner: `beam_rt`/`beam_gc`).** `beam_rt`'s `ProcessBridge::process_flag` answers `badarg` for every flag except `trap_exit`/`sensitive`/`priority`/`save_calls`/`error_handler`, where the oracle returns the **previous value** for `max_heap_size`/`min_heap_size`/`min_bin_vheap_size`/`fullsweep_after`/`message_queue_data`. `Process` has no `max_heap_size` storage and `beam_gc::AnyCollector` exposes only `policy()` (no `policy_mut`), so the setter and the kill/log enforcement are a `beam_rt`+`beam_gc` handoff. No `max_heap_size` enforcement exists in this crate.
- **`spawn_opt` option validation gap (owner: `beam_rt`/`beam_gc`).** `{max_heap_size, N}` with `N != 0` and `N < min_heap_size` is accepted where the oracle is `badarg` (the C `erl_process.c`'s `max_heap_size < min_heap_size ⇒ -1`); and `process_info(P, message_queue_data)` reports `on_heap` regardless of a `{message_queue_data, off_heap}` spawn option.
- **`port_info` item gap (owner: `beam_bifs`/`beam_rt`).** `port_info(P, queue_size)` and `port_info(P, locking)` are `badarg` where the oracle answers `{queue_size, 0}` / `{locking, port_level}`; the 7-item `port_info/1` roster and order already match.
- **Two independent reference-id spaces make a bare `make_ref/0` and a monitor/alias reference with equal ids `=:=` (HAZARD 2 — a documented divergence, pinned by `tests/reference_ids.rs`).** The `ProcessTable` owns a `RefAllocator` (fed by every `erlang:monitor/2,3` and `erlang:alias/0,1`), and `beam_rt`'s `Runtime::refs` owns a **second**, independent `RefAllocator` (fed by `erlang:make_ref/0`, the NIF `make_ref`, the `send_after/3`/`start_timer/3` timer references and `seq_trace`). Both are monotone from `0` and both render through the same frozen block `[make_header(3, REF_SUBTAG), node = 0, serial = 0, id]` — the runtime side goes through the very same `MonitorRef::to_eterm` (`beam_rt::native`'s `mint_timer_ref`) — so the first reference of each space carries the same id and is the **same term**. `beam_term::compare::cmp_refs` compares the payload words only (never the header subtag), and both producers pin `node`/`serial` to `0`, leaving the id as the sole distinguishing word, so the two compare `=:=`. The oracle has **one** id space, so it can never produce such a pair: a divergence, not desirable behaviour. The **send** path is already correct — it classifies a destination by **provenance** (the reference term word), not by id (`beam_rt/src/context/tests.rs::resolve_send_target_rejects_a_bare_reference_that_collides_with_a_live_alias`) — so the residual is purely reference **identity**. It is **not closable from `beam_process`**: varying `node`/`serial` would break `binary_to_term(term_to_binary(M)) =:= M` because `beam_codec`'s internal-reference codec is **id-only** (it rebuilds through `write_internal_ref`, which zeroes both); a distinct header subtag is not consulted by `cmp_refs`; a distinct header arity would break `internal_ref_id`/`MonitorRef::from_eterm` and still not round-trip; and changing `RefAllocator::new()`'s start value or banding per instance breaks `beam_rt`'s monotone-from-0 dependency (its `force_next_reference_id` helper). **Owner:** a cross-crate change — extend `beam_codec`'s internal-reference codec to preserve the whole payload, **or** unify the two allocators via `beam_rt` (draw `make_ref/0` from the `ProcessTable`'s allocator).
- **The compatibility gate is the sibling `../tools/differential/`'s, not this crate's.** It is `erts_rust/tools/differential/gate.sh`, which drives `differential suite --strict --allowlist <file>` (`gate.sh` itself accepts only `--allowlist`; `--strict` is the differential binary's flag). Read the live pass/fail and per-contract split from its own output — the counts drift as the corpus grows, so none are quoted here. This crate's own gate is `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_process` (green: see `## Status`) plus the sibling suites the delivery is cross-checked against (`-p beam_rt`, `-p beam_engine`, `-p beam_gc`).

- **Adoption notes for `beam_rt`/`beam_bifs`** (do NOT edit them from here; verify each against the consumer — several are already wired, e.g. the budget-honouring `RuntimeRunner` (1), the installed `ProcessExitObserver` (9), and `send_fragmented` through `heap_and_mailbox_mut` (11)): (1) `RuntimeRunner::run` honours `budget` and returns `Yield`; (2) use `ProcessState::status_atom`/`Process::status` instead of its own status mapping; (3) `erlang:demonitor/2 [flush]` → `demonitor_flush`; (4) `erlang:monitor/2` type dispatch via `MonitorKind::from_type_name` + `monitor_port_term`/`monitor_named`, and install `set_local_node` at boot for name targets; (5) `process_info(P, registered_name)` → `name_of`, and `process_info(P, monitors)` must surface `Process::port_monitors()` as `{port, Port}`; (6) `spawn_opt` heap knobs → `beam_gc::HeapPolicy::from_spawn_opts` + `with_policy_and_priority`; (7) `erlang:monitor/3`'s `{tag, T}` option → the `monitor_*_with_tag` entry points (the tag is a `ProcessTable` side table, never a `Monitor` field — no shape change); (8) a **fragmented** message payload moves onto the receiver's heap with `Process::heap_and_off_heap_mut()` + `beam_message::Fragments::move_into` (heap growth via `AnyCollector::ensure_capacity` is still needed for a payload larger than the M1 heap); (9) release a dead pid's resources by installing a `ProcessExitObserver` via `set_process_exit_observer` (the ETS tables a pid owns are the motivating case — key the cleanup on `exit.pid()`; copy `exit.reason()` if retained); (10) with a `PortTable` alongside the `ProcessTable`, terminate through `terminate_with_ports` (and `service_signals_with_ports` at schedule-in) so a dead port-watcher's incoming `PortMonitor` is removed; (11) `beam_message::send_fragmented` through `Process::heap_and_mailbox_mut()` instead of re-composing the fragment primitives; (12) install the owned `PortTable` on the `Scheduler` (`set_ports`/`with_ports`) so its default `run_slice`/`run_ready` clean the port side (or drive `run_slice_with_ports`/`run_ready_with_ports` when the table is owned elsewhere); (13) the `link`/`link_term` `noproc` signal (the `RuntimeHooksBridge::link` comment claiming it "simply never arrives" is stale — it is delivered); (14) the `process_flag(max_heap_size/min_heap_size/…)` arm returning the previous value; (15) `spawn_opt`'s `max_heap_size < min_heap_size ⇒ badarg` and honest `message_queue_data`; (16) `port_info`'s `queue_size`/`locking` items. `Process::collector()` returns `&beam_gc::AnyCollector` (the mature-strategy dispatch), so a host reads the mature generation through its geometry accessors (`mature_contains`, `mature_used_words`, `mature_capacity_words`, `mature_base`) instead of a `&HeapSpace` — `beam_rt` does so in `src/context/gc.rs` (the unscanned-root valve) and `src/context/memory_hook.rs`. Every other host use (`young()`, `stats()`, `minor_gcs()`, `policy()`, `heap_size_words()`, `total_heap_size_words()`) is unchanged.
