# `beam_process` — Design Decisions

Rationale ("why") behind the frozen `beam_process` API and its constraints; the "what" lives in `CONTEXT.md`. Read alongside `CONTEXT.md` (Intent, API Surface, Constraints, Known Issues).

- **A decoupled, ordered per-process signal queue.** A signal is **enqueued** on the receiver's own `SignalQueue` at generation time — never applied inline — so its `reason` is copied into the receiver's heap at enqueue time and outlives the signaller's heap; `exit_policy` is evaluated at **service** time against the receiver's `trap_exit` *then*, and ordering is a total FIFO per receiver (subsuming ERTS's per-`(sender, receiver)` order), **not** cross-ordered with the mailbox (see Known Issues).
- **Resume-on-send: a wake list on the table + absorption by the scheduler.** The wake is *recorded* on `ProcessTable::ready` rather than re-enqueued by every caller (which would double-enqueue a pid the `Yield` branch already requeued); `resume_woken` skips a pid that is dead, not `Runnable`, or already `in_run_queue` — the last guard prevents the double enqueue. Both `Waiting` and `Suspended` are woken (the C's `SUSPENDED`-vs-suspend-counter nuance is a follow-up).
- **`ProcessRunner` is the engine seam — `beam_engine` is not a dependency**, so the scheduler does not know how a process executes and the DAG stays acyclic (`beam_engine` → `beam_loader` only).
- **The `ProcessTable` is the ≥2-process mutation hub.** Links/monitors/signal delivery touch two PCBs; two `&mut Process` from a `HashMap` is a borrow-checker impossibility, so these live on `ProcessTable` and use a **collect-then-apply worklist** (`Process` holds only its own sets).
- **A signalled reason is COPIED into the receiver's heap at ENQUEUE time.** The source heap is dropped when it terminates, so embedding a reason by reference would dangle (and a safepoint GC would corrupt): `copy_reason_onto` `copy_struct`s it at enqueue (`enqueue_exit_signal`/`enqueue_down_signal`), registering referenced off-heap objects in the receiver's table; `terminate_into` copies the dying process's reason into every peer **before** `drop`ping its PCB; a self-signal is already in the receiver's heap; immediates/literals are shared by `copy_struct`, so the common reasons pay nothing.
- **GC root set = registers + mailbox payloads + dictionary + saved args + pending signals**, gathered into a flat `&mut [Eterm]` (the collector takes a flat slice; `beam_gc` delegates on-heap message queues to `beam_process`). `Process::collect` gathers in a fixed order — registers/stack, mailbox payloads, dictionary, saved args, pending signals — runs the collector, then writes each region back in the same order: since `beam_message::Message` has no payload setter, the queue is **drained**, each payload appended to the root buffer, and each `Message` **rebuilt** from its relocated payload via the public builder; the dict/saved-args/signal regions scatter back through their own `scatter_roots`; MSO handles are off-heap and do not move. `Process::port_monitors` is **not** a root — a `PortWatch` holds plain values only.
- **The dictionary compares keys — and `get_keys/1` values — with `beam_term::compare::eq` (the C's `EQ`)** rather than raw word equality, which would report a *boxed* key absent when the looked-up term is a distinct-but-equal heap word (`put({a},1), get({a})`); the `Rc<AtomTable>` handle (not `&AtomTable`) keeps signatures unchanged and matches `beam_rt`'s `CodeServer` convention — no dependency edge. Its insertion-order iteration (vs the C's hash-array `pd_hash_get_all` order, `get()` ⇒ `[{b,2},{a,1}]` on OTP 29.1.1) is a documented deviation: porting the hash array is the deferred O(1)-lookup optimization, while the *value* semantics (last put wins, returns the replaced value, `erase` returns the erased value) are pinned by tests.
- **Monitor references are on-heap `Ref` things built locally (`monitor.rs`).** `beam_term` has no `make_ref` in M1, so a reference is the frozen 4-word thing `[make_header(3, REF_SUBTAG), node(0), serial, id]` built with `make_header`; `beam_message::layout::object_words` copies it verbatim (no navigable children) and `compare` compares internal refs by raw payload words, so a `{'DOWN', Ref, …}` round-trips. When `beam_term` gains a proper `make_ref`, only `MonitorRef::to_eterm` changes.
- **Named monitors and the `monitor/3` user tag use `ProcessTable` side tables, not a `Monitor` field.** `Monitor`, `MonitoredBy` and `PortWatch` are built by struct literal from `beam_rt` and carry only `ProcessId`s, so their field sets are **frozen** (adding one would break that crate's compile). `named_monitors: HashMap<MonitorRef, NamedTarget>` (two atoms — no heap term, no rootset) plus `local_node: Option<Atom>` make the DOWN target the 2-tuple `{Name, node}`; `tags: HashMap<MonitorRef, Eterm>` (`remember_tag`/`forget_tag`, cleaned up at `demonitor`/`demonitor_port`/termination/port close) carries the tag, validated to a heap-independent **immediate** before any state changes (`check_tag`) because the side table is not a collector rootset — a heap word stored there would dangle after a GC (so a non-immediate tag returns the typed `unsupported` rather than a wrong result, though the oracle accepts any term). The DOWN builders read the tag at build time (`tags.get(&reference).copied()`, `None` ⇒ the `'DOWN'` atom), and the internal `PendingSignal::Down` carries it to the deferred materialisation point.
- **`Links` is a set in M1.** Re-linking is a no-op and unlinking removes once, matching the observable `erlang:link/1`/`unlink/1` semantics; the C's per-link refcount (for `monitor` on links and distributed links) is a follow-up.
- **`trap_exit` is a PCB flag, not a queue.** `exit_policy` reads it at *service* time and decides `Terminate`/`Trap`/`Ignore`; `Trap` builds `{'EXIT', From, Reason}` into the mailbox — exactly the observable `process_flag(trap_exit, true)` behaviour.
- **`Process` owns a `beam_gc::Collector`, not raw `Heap`s.** The young space is the mutator heap; policy (`should_collect`/`collect`) is `beam_gc::HeapPolicy`'s — no heap logic is reimplemented here. **`parking_lot` is the synchronisation primitive; `libc` remains unused** (declared; reserved for the deferred OS-level threading work).
- **The SMP pool reuses the frozen slice and bounds the table lock.** `Worker::run` calls the same `pub(crate)` helpers via `run_locked_quanta`, the only difference being the worker's requeue closure, which **buffers** requeues locally; the pool holds one `Mutex<ProcessTable>` for at most **one reduction quantum** (`ceil(reductions_per_slice / lock_quantum)`, default 256) releasing it between quanta, and each quantum re-checks `table.contains(pid)` since a peer may terminate it between quanta (`lock_quantum >= reductions_per_slice` reproduces the old one-lock-hold behaviour exactly). Exactly one process **executes** at a time: it keeps its whole budget and stays in-flight (out of every run queue). **Locking discipline (BINDING):** the three lock families (queue locks, the table lock, the signals mutex) follow the order in `src/smp/CONTEXT.md` — **never hold a queue lock while taking the table lock and vice-versa**; requeues produced while the table guard is held are buffered and flushed **only after** the guard drops; the only nested acquisition is *signals mutex → queue lock*.
- **`SharedProcessTable`'s `unsafe impl Send/Sync` is a contained handoff.** `ProcessTable` is `!Send`; the two impls assert that confining every access to the inner `parking_lot::Mutex` makes the wrapper sound. Measured `!Send` causes: `beam_alloc::Heap`'s `base: *mut Eterm` (via `beam_gc::HeapSpace`/`Collector`), `beam_gc::MsoHandle`'s `ptr: NonNull<Mso>` (via `beam_message::OffHeapTable`), and this crate's own `Option<Box<dyn DistSignalRouter>>`; `beam_alloc::RefcBinary` is already `Send`. The durable fix belongs upstream — do not widen this `unsafe`.
- **Non-flaky `wait_idle` and loss-free park/notify.** The pool reports idle only when every queue is empty **and** `InFlight` is zero; a pop increments `InFlight` in the same critical section that dequeues, and a worker flushes its local `buf` **before** `finish_slice` decrements (flushing after would leave the queues empty and the count zero while a yielded pid sits only in `buf`). A worker re-checks the queue predicate **under the signals mutex** immediately before `Condvar::wait` and every notifier takes that mutex before signalling, so a wake-up cannot be lost; the mutex→queue-lock order is consistent everywhere.
