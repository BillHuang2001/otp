# `beam_process` — Design Decisions

Rationale ("why") behind the frozen `beam_process` API and its constraints; the "what" lives in `CONTEXT.md`. Read alongside `CONTEXT.md` (Intent, API Surface, Constraints, Known Issues).

- **A decoupled, ordered per-process signal queue.** A signal is **enqueued** on the receiver's own `SignalQueue` at generation time — never applied inline — so its `reason` is copied into the receiver's heap at enqueue time and outlives the signaller's heap; `exit_policy` is evaluated at **service** time against the receiver's `trap_exit` *then* **and the signal's carried `ExitFamily`**, and ordering is a total FIFO per receiver (subsuming ERTS's per-`(sender, receiver)` order), **not** cross-ordered with the mailbox (see Known Issues).
- **Resume-on-send: a wake list on the table + absorption by the scheduler.** The wake is *recorded* on `ProcessTable::ready` rather than re-enqueued by every caller (which would double-enqueue a pid the `Yield` branch already requeued); `resume_woken` skips a pid that is dead, not `Runnable`, or already `in_run_queue` — the last guard prevents the double enqueue. Both `Waiting` and `Suspended` are woken (the C's `SUSPENDED`-vs-suspend-counter nuance is a follow-up).
- **`ProcessRunner` is the engine seam — `beam_engine` is not a dependency**, so the scheduler does not know how a process executes and the DAG stays acyclic (`beam_engine` → `beam_loader` only).
- **The `ProcessTable` is the ≥2-process mutation hub.** Links/monitors/signal delivery touch two PCBs; two `&mut Process` from a `HashMap` is a borrow-checker impossibility, so these live on `ProcessTable` and use a **collect-then-apply worklist** (`Process` holds only its own sets).
- **A signalled reason is COPIED into the receiver's heap at ENQUEUE time.** The source heap is dropped when it terminates, so embedding a reason by reference would dangle (and a safepoint GC would corrupt): `copy_reason_onto` `copy_struct`s it at enqueue (`enqueue_exit_signal`/`enqueue_down_signal`), registering referenced off-heap objects in the receiver's table; `terminate_into` copies the dying process's reason into every peer **before** `drop`ping its PCB; a self-signal is already in the receiver's heap; immediates/literals are shared by `copy_struct`, so the common reasons pay nothing.
- **GC root set = registers + mailbox payloads + dictionary + saved args + pending signals**, gathered into a flat `&mut [Eterm]` (the collector takes a flat slice; `beam_gc` delegates on-heap message queues to `beam_process`). `Process::collect` gathers in a fixed order — registers/stack, mailbox payloads, dictionary, saved args, pending signals — runs the collector, then writes each region back in the same order: since `beam_message::Message` has no payload setter, the queue is **drained**, each payload appended to the root buffer, and each `Message` **rebuilt** from its relocated payload via the public builder; the dict/saved-args/signal regions scatter back through their own `scatter_roots`; MSO handles are off-heap and do not move. `Process::port_monitors` is **not** a root — a `PortWatch` holds plain values only.
- **The process owns its off-heap refc binaries in a `beam_gc::OffHeap` of its own and sweeps them with a reachability walk over its root set.** `beam_gc::OffHeap` is the workspace's slot-stable off-heap list; `beam_message::OffHeapTable` (the process's persistent `off_heap` field) deliberately never sweeps, so the process keeps its own ownership list. `Process` therefore gains a **separate** list — `owned_binaries: beam_gc::OffHeap` — as the process's **binary-ownership home**, plus the explicit-death worklist `dead_binaries: Vec<usize>` (payload pointers) and the `owned_binary_slots` slot counter. Why a *separate* list rather than the existing `off_heap` table: that table is the **message-transit / queued-signal** table the copy boundary writes into and whose slot indices an on-heap container names, so it must keep its slot space intact and is not the process's own ownership record; the two lists hold **different objects** (this one only the payloads the process took ownership of via `register_off_heap_binary`; `off_heap` the MSO handles and the refc binaries a copied message/fragment carries), so no handle is owned twice and no ownership is duplicated — the rule is simply *never register the same payload in both*. Why the list holds at most **one** reference per payload (a duplicate registration returns the existing slot and drops the surplus handle, the legacy `MSO(p)` invariant): the sweep predicate sees an entry, not a slot, so a bijection between payload identity (`RefcBinary::data_ptr`, the frozen `BinRef.val` contract) and slot is what makes a declared-death exact. **The automatic predicate is a reachability walk over the process's own root set**: `beam_gc::AnyCollector::for_each_reachable_object_view` (public, safe, read-only, whole-heap — nursery chain incl. growth-retained spaces + mature, iterative/cycle-safe) reports every reachable BOXED object once as a safe `beam_gc::ReachableObject` view, so a `visit` that records the payload pointer of every reachable `HEADER_BIN_REF` (BinRef word 1 = `val` = `RefcBinary::data_ptr`, read through `ReachableObject::word(1)`) yields exactly the live set — no shallow raw-word scan is involved and no term moves. So `run_rooted_collection` ends with two halves: `sweep_off_heap_binaries_reachable` (release iff NOT reachable, reusing the roots the collection already gathered) and then `sweep_off_heap_binaries` (release iff declared dead). The conservative half always runs so a caller's asserted death is honoured even where the walk declines; the reachability half retains everything for a process with `has_unpublished_roots()` (a missed live `BinRef` would release a live payload = a dangle) and is a cheap no-op for a process that owns no off-heap binaries. The **deferred** release (declare, then sweep) rather than an immediate one is what makes the sweep the single place a death becomes a reclaim — a run of declarations costs one sweep, and `retain_off_heap_binaries(is_live)` is the same seam for a party that *can* decide liveness faithfully (a collector- or host-side scan), applied to the live entries only. Residual gaps: an off-heap binary that arrives via the **copy engine** is owned by the `Message`/`OffHeapTable`, not `owned_binaries`, so nothing auto-registers it into the swept list; and a process whose root set is incomplete (`has_unpublished_roots()` — relocation-exempt or `Running`) is retained entirely, so its genuinely-dead payloads still await the conservative declared-death path or process exit. Evidence: `tests/off_heap_binaries.rs` + `tests/off_heap_reachability.rs`.
- **The off-heap reachability sweep adopts `beam_gc`'s safe reachable-object view, so `process.rs` keeps no production `unsafe`.**
  The sweep walks the process's own root-reachable graph with `beam_gc::AnyCollector::for_each_reachable_object_view` and reads each reported object through `beam_gc::ReachableObject` — `header()` plus `word(1)`, the frozen `BinRef.val` payload pointer — instead of the raw `(header, ptr)` pair the walk once reported.
  The two forms are **one walk** (the raw enumeration is expressed in terms of the view form), so the reachable-object set is identical and the sweep's decision is unchanged; the view merely replaces the crate's own `*ptr.add(1)` read with the sibling's **safe** accessor, which is why `process.rs` now holds no production `unsafe` at all (`remote.rs`/`monitor.rs` term builders and `smp/mod.rs`'s two `unsafe impl Send/Sync` remain).
  The view **borrows the heap for the visit only** — the visitor is `FnMut(ReachableObject<'_>)`, higher-ranked over the borrow — so no slice can escape the callback, exactly right for a sweep that records only a `usize` payload pointer per object and relocates nothing.
  The per-object test is unchanged in meaning: a `HEADER_BIN_REF` object names a payload at word 1, while a narrower object (or one whose header lied) names nothing.
- **The oversized-message retry grows the nursery on demand, and the retry stays authoritative.** The young generation is **bounded** — `beam_gc::HeapPolicy::young_after_collection` never grows it merely because a collection ran — so `Process::deliver`'s retry after a refused copy cannot rely on a collection having enlarged the nursery. On an `AllocKind::Heap | AllocKind::Message` refusal it recovers the refused request's word count from the failure (`requested / size_of::<Eterm>()`; the copier reports the whole graph's flat count in bytes for both kinds) and calls `Process::ensure_capacity(need_words)` — `beam_gc::AnyCollector::ensure_capacity` collects once, then grows the now-empty nursery to the smallest curated size covering the request. The growth's own error is **ignored on purpose**: when the policy's ceiling makes the request unreachable it fails *fail-fast* with `AllocKind::Heap` and leaves the collector untouched, and the retry then reproduces the refusal as the raw `AllocKind::Message` that `beam_rt::deliver_message` keys its heap-fragment fallback on — surfacing the growth error instead would change that caller-visible contract, so the retry's result is what the delivery returns. `collect` and `ensure_capacity` share one `run_rooted_collection` helper that writes every root region back **even when the collection action returned `Err`**, because an `ensure_capacity` failure can happen *after* its collection relocated the roots in place (a fail-fast failure makes the same write-back a harmless no-op of un-relocated values). The `ProcessTable` signal builders (`copy_reason_onto`/`build_signal_message`/`deliver_head_signal`/`enqueue_fragment_signal`) share this policy through one `grow_receiver_for_signal` helper, so an oversized `{'EXIT',…}`/`{'DOWN',…}` reason grows the receiver's nursery the same way instead of being lost. A receiver whose relocating collection must not happen — one with **unpublished roots** (`Process::has_unpublished_roots`: a **relocation-exempt** process, or a **`Running`** one whose `regs` snapshot is stale) **or** one the host's `CollectionGate` declines — cannot collect or grow at all, so every apply-time builder tests `has_unpublished_roots() || <gate decline>` *first* and builds the message into a `beam_message::HeapFragment` (the local analogue of the send path's `send_fragmented`) — the model the C always uses for signals — and the **enqueue-time** reason copy (`copy_reason_onto`) pre-tests the same predicate the same way, so its callers (`enqueue_down_signal`/`enqueue_exit_signal`) route the refused signal into a fragment too — the message the queue would have materialised, built straight from the enqueue site, because a queued signal's reason can live nowhere but the receiver's own heap. The only refusal still surfaced is the exit **policy** one: an exit signal to a **non-trapping** receiver whose collection is declined, which would have to *terminate* it rather than message it.
- **The dictionary compares keys — and `get_keys/1` values — with `beam_term::compare::eq` (the C's `EQ`)** rather than raw word equality, which would report a *boxed* key absent when the looked-up term is a distinct-but-equal heap word (`put({a},1), get({a})`); the `Rc<AtomTable>` handle (not `&AtomTable`) keeps signatures unchanged and matches `beam_rt`'s `CodeServer` convention — no dependency edge. Its insertion-order iteration (vs the C's hash-array `pd_hash_get_all` order, which is an unspecified artifact and is **not stable across VM starts** — the same `put(a,1), put(b,2), get()` comes back in either order) is a documented choice: porting the hash array is the deferred O(1)-lookup optimization, and the deterministic insertion order is what `dict_oracle.rs` compares `get/0` against as a **set**, while the *value* semantics (last put wins, returns the replaced value, `erase` returns the erased value) are pinned by tests.
- **Monitor references are on-heap `Ref` things built locally (`monitor.rs`).** `beam_term` has no `make_ref` in M1, so a reference is the frozen 4-word thing `[make_header(3, REF_SUBTAG), node(0), serial, id]` built with `make_header`; `beam_message::layout::object_words` copies it verbatim (no navigable children) and `compare` compares internal refs by raw payload words, so a `{'DOWN', Ref, …}` round-trips. When `beam_term` gains a proper `make_ref`, only `MonitorRef::to_eterm` changes.
- **Named monitors and the `monitor/3` user tag use `ProcessTable` side tables, not a `Monitor` field.** `Monitor`, `MonitoredBy` and `PortWatch` are built by struct literal from `beam_rt` and carry only `ProcessId`s, so their field sets are **frozen** (adding one would break that crate's compile). `named_monitors: HashMap<MonitorRef, NamedTarget>` (two atoms — no heap term, no rootset) plus `local_node: Option<Atom>` make the DOWN target the 2-tuple `{Name, node}`; `tags: HashMap<MonitorRef, Eterm>` (`remember_tag`/`forget_tag`, cleaned up at `demonitor`/`demonitor_port`/termination/port close) carries the tag, validated to a heap-independent **immediate** before any state changes (`check_tag`) because the side table is not a collector rootset — a heap word stored there would dangle after a GC (so a non-immediate tag returns the typed `unsupported` rather than a wrong result, though the oracle accepts any term). The DOWN builders read the tag at build time (`tags.get(&reference).copied()`, `None` ⇒ the `'DOWN'` atom), and the internal `PendingSignal::Down` carries it to the deferred materialisation point.
- **`Links` is a set in M1.** Re-linking is a no-op and unlinking removes once, matching the observable `erlang:link/1`/`unlink/1` semantics; the C's per-link refcount (for `monitor` on links and distributed links) is a follow-up.
- **`trap_exit` is a PCB flag, not a queue.** `exit_policy` reads it (with the signal's carried `ExitFamily`) at *service* time and decides `Terminate`/`Trap`/`Ignore`; `Trap` builds `{'EXIT', From, Reason}` into the mailbox — exactly the observable `process_flag(trap_exit, true)` behaviour.
- **The exit policy is signal-FAMILY-aware, and the family rides on the queued signal.**
  `exit_policy(reason, trapping, family, atoms)` implements the C's `handle_exit_signal` (`../../erts/emulator/beam/erl_proc_sig_queue.c:4740-4770`) over the two operation families (`../../erts/emulator/beam/erl_proc_sig_queue.h:176-177`): `kill` is **untrappable — and rewritten to `killed` — only in the explicit `erlang:exit/2` family** (`ExitFamily::Explicit` = `ERTS_SIG_Q_OP_EXIT`), while a **link exit** (`ExitFamily::Linked` = `ERTS_SIG_Q_OP_EXIT_LINKED`) makes `kill` an ordinary trappable reason whose termination reason is **unchanged** (`kill`, never `killed`) — a trapping peer receives `{'EXIT', Peer, kill}` and survives; `normal` is ignored by a non-trapping receiver in **both** families.
  The family is a field of `PendingSignal::Exit` (`signal.rs`/`signal_queue.rs`) rather than being re-derived at service time because a local link exit is **deferred** to the receiver's schedule-in (`apply_head_signal`), long after the generating `terminate_into` link loop has returned — nothing at service time could tell a link exit from an `erlang:exit/2` one, so the generating site must carry it.
  `apply_exit_signal`/`send_exit`/`send_exit_term` are the explicit family; the `terminate_into` link loop and `node_down`/`port_closed` step 2 are the link family; and `apply_remote_exit_signal` keeps its public `untrappable: bool` and maps it onto the family (`true` ⇒ Explicit, `false` ⇒ Linked), so its C-derived `DOP_EXIT`/`DOP_EXIT2` split is preserved.
  The C's `ERTS_SIG_LNK_X_FLAG_NORMAL_KILLS` escape (`../../erts/emulator/beam/erl_proc_sig_queue.c:1809`, `:4758-4759`) — which would make a `normal` link exit terminate anyway — is deliberately **not** modelled (a documented gap).
  A monitor `{'DOWN', …}` (`ERTS_SIG_Q_OP_MONITOR_DOWN`) is a **third** signal category that never consults this policy: it is delivered **unconditionally** (`deliver_down_message`), whatever the receiver's `trap_exit` flag says, exactly as the C handles it in its own arm (`../../erts/emulator/beam/erl_proc_sig_queue.c:6355`).
  `enqueue_exit_signal`'s heap-fragment fallback keys on the family-aware `Trap` outcome rather than on `is_trapping_exit()` alone, so an untrappable explicit `kill` to a trapping receiver is never delivered as a `{'EXIT', …}` fragment — the wrong result the family-blind form could produce.
- **`Process` owns a `beam_gc::AnyCollector`, not raw `Heap`s.** The young space is the mutator heap; policy (`should_collect`/`collect`) is `beam_gc::HeapPolicy`'s — no heap logic is reimplemented here. The **strategy-dispatching** collector (not the concrete `beam_gc::Collector`) is what makes the GC strategy a property of the process: built through `AnyCollector::new(policy)`, the process's mature generation is the one the policy resolves to — the copying space below `beam_gc::IMMIX_BREAK_EVEN_WORDS`, the mark-region (GenImmix) space at/above it — while a default policy resolves to the copying space, so the ownership swap is behaviour-identical. Adopting the dispatcher also settles the shape of the accessor: the two mature spaces are differently typed, so `Process::collector()` hands back the wrapper and the mature generation is read through its **geometry** methods (`mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_base`/`mature_contains`) rather than a `mature()` reference. **`parking_lot` is the synchronisation primitive; `libc` remains unused** (declared; reserved for the deferred OS-level threading work).
- **The SMP pool reuses the frozen slice and bounds the table lock.** `Worker::run` calls the same `pub(crate)` helpers via `run_locked_quanta`, the only difference being the worker's requeue closure, which **buffers** requeues locally; the pool holds one `Mutex<ProcessTable>` for at most **one reduction quantum** (`ceil(reductions_per_slice / lock_quantum)`, default 256) releasing it between quanta, and each quantum re-checks `table.contains(pid)` since a peer may terminate it between quanta (`lock_quantum >= reductions_per_slice` reproduces the old one-lock-hold behaviour exactly). Exactly one process **executes** at a time: it keeps its whole budget and stays in-flight (out of every run queue). **Locking discipline (BINDING):** the three lock families (queue locks, the table lock, the signals mutex) follow the order in `src/smp/CONTEXT.md` — **never hold a queue lock while taking the table lock and vice-versa**; requeues produced while the table guard is held are buffered and flushed **only after** the guard drops; the only nested acquisition is *signals mutex → queue lock*.
- **`SharedProcessTable`'s `unsafe impl Send/Sync` is a contained handoff.** `ProcessTable` is `!Send`; the two impls assert that confining every access to the inner `parking_lot::Mutex` makes the wrapper sound. Measured `!Send` causes (**six**): `beam_alloc::Heap`'s `base: *mut Eterm` (via `beam_gc::AnyCollector`/`beam_gc::HeapSpace`), `beam_gc::MsoHandle`'s `ptr: NonNull<Mso>` (via `beam_message::OffHeapTable`), the `Rc<AtomTable>` in each `Dict`, and this crate's own `Option<Box<dyn DistSignalRouter>>`, `Option<Box<dyn ProcessExitObserver>>` and `Option<Box<dyn CollectionGate>>`; `beam_alloc::RefcBinary` is already `Send`. The `Rc<AtomTable>` is never cloned or shared outside the table. The invariant is stated in `src/smp/CONTEXT.md` and `src/smp/mod.rs`; the durable fix belongs upstream — do not widen this `unsafe`.
- **Non-flaky `wait_idle` and loss-free park/notify.** The pool reports idle only when every queue is empty **and** `InFlight` is zero; a pop increments `InFlight` in the same critical section that dequeues, and a worker flushes its local `buf` **before** `finish_slice` decrements (flushing after would leave the queues empty and the count zero while a yielded pid sits only in `buf`). A worker re-checks the queue predicate **under the signals mutex** immediately before `Condvar::wait` and every notifier takes that mutex before signalling, so a wake-up cannot be lost; the mutex→queue-lock order is consistent everywhere.
- **The scheduler owns an optional `PortTable`; a passed one overrides it.** `Scheduler` carries an optional **owned** `PortTable` (`Scheduler::with_ports`/`set_ports`/`take_ports`/`ports`/`ports_mut`/`has_ports`), which the **default** `run_slice`/`run_ready` use when it is present — so a process that dies inside a slice, or is terminated at schedule-in by a queued signal, has its dangling **incoming** `PortMonitor` removed (the last step of `ProcessTable::terminate_into`) without a special entry point. `new`/`with_slice` own none, so the prior port-less behaviour is the default (a dying process's outgoing watch set is drained but the port table is untouched). `run_slice_with_ports`/`run_ready_with_ports` (and the `pub(crate)` `run_one_with_ports`/`slice_begin_with_ports`/`slice_end_with_ports`) take the table **explicitly** and it **takes precedence over the owned one for that call only** — the owned table is left untouched, so a caller can drive a slice against a table it owns itself. Every entry point shares one private `*_inner` body taking `Option<&mut PortTable>`, destructuring the scheduler so the run-queue borrow (the requeue closure) and the owned-port borrow are provably disjoint fields (the free `resume_woken_into(run_queue, table)` lets the split-borrowed body absorb wakes without re-borrowing the whole scheduler). The slice semantics are unchanged in every case: schedule-in, one runner call for the whole budget, schedule-out, the wake sweep. The SMP pool stays port-less — its `slice_begin`/`slice_end` calls carry no port table, and its BINDING locking discipline (`src/smp/CONTEXT.md`) names no port-table lock, so adopting one there is deferred rather than half-wired.
- **`link` on a non-live target signals `noproc` from it.** A `link(a, b)` whose `b` is not live records no link and applies a `noproc` exit signal from `b` to `a` through the existing `apply_exit_signal` (no new mechanism), so it inherits the eager-vs-deferred rule; `TermNotFound` is reserved for an unknown *caller*. The non-trapping reason is the bare atom `noproc` where the oracle *raises* `error:noproc` — a documented approximation owned by `beam_rt`'s link floor.
- **A target's death resolves the watcher's outgoing `Monitor`.** `terminate_into` removes the watcher's outgoing entry right after enqueuing the DOWN, so both halves are cleared and a later `demonitor(Ref)` reports it gone. A **named** monitor's `{Name, node}` descriptor is deliberately kept until `deliver_down_message` materialises the (possibly deferred) DOWN, so the DOWN still carries the name.
- **The GC relocation exemption is PER PROCESS, not a global valve — so the default is byte-identical to before.** A host can hold live terms from a process's young heap in Rust locals / nested-`Machine` registers that the crate root set (registers/stack + mailbox + dict + saved args + pending signals) does **not** publish; collecting against that incomplete root set recycles live words (the WRONG-RESULT hazard the `-eval` held-result case exposed). A global switch would have to be honoured by *every* `deliver`/`collect` in the runtime and could silently disable GC for the whole node, so the flag lives on the `Process` (`relocation_exempt: bool`, default `false`, set by `set_relocation_exempt` / mirrored by `ProcessTable::set_relocation_exempt`) and only a process the host explicitly marks is affected — a process the host does not mark behaves exactly as before. It is opt-in because only the host can assert that a process's root set is (un)published.
- **`deliver` surfaces the RAW refusal for an exempt receiver, and BOTH the short-circuit and the GC-entry guards are required.** When exempt, `deliver` returns the first `AllocKind::Heap`/`AllocKind::Message` refusal unchanged (`kind` preserved) instead of collecting, growing and retrying. That raw refusal is deliberately *not* the growth's own error: it is exactly the signal the host's fragment fallback keys on (`beam_rt::context::RuntimeContext::deliver_message` → `send_fragmented_message`), so the oversized message is still delivered — through a fragment — without moving a heap word, and the host-visible contract is unchanged. The exempt path also *independently* refuses at `collect`/`ensure_capacity` (the retry's growth call would otherwise reach `beam_gc` even if the short-circuit were later removed), so the no-relocation guarantee is doubly enforced rather than resting on one `if`; the discriminating test `tests/gc_exemption.rs` exercises both (it fails if either guard is dropped).
- **`collect`/`ensure_capacity` report the refusal as a TYPED error, not a fake `Collection`; `collect_if_needed` answers `Ok(false)`.** `beam_gc::Collection` has only `Minor`/`Major` — there is no `None` kind — so a refused relocation cannot be represented as a real value without lying about which collection ran; the crate therefore adds `error::relocation_exempt(what)` (a `BeamError::Raise` whose reason atom is `relocation_exempt: <what>`, mirroring the `unsupported` constructor's shape), which is honest, greppable and non-swallowing. `collect_if_needed` is the one entry whose *return value already means* "a collection ran", so its no-op is `Ok(false)` — the truthful answer — rather than a raise, and it never reaches `run_rooted_collection`.
- **Adoption of the exemption flag is the host's (`beam_rt`); the `Running` half is the crate's own.** This crate provides the seam; the runtime marks the process whose root set it cannot publish and lets the exempt `deliver`'s raw refusal trigger its fragment fallback. `beam_rt` does so — the `-eval`/nested-`Machine` scopes run under `RuntimeContext::with_relocation_exempt` and the send path exempts the sending context's own pid (`deliver_message_with_off_heap`) — while the **`Running`** case (the second half of `has_unpublished_roots`) the crate derives itself, so a mid-slice delivery to the executing process is refused with no host marking. The flag defaults off, so a process the host does not mark and that is not running behaves exactly as before.
- **The delivery-collect gate refuses a relocating collection whose live roots are not all published, from two sources — the crate-owned `has_unpublished_roots` (`relocation_exempt || state == Running`) and a host-installed `CollectionGate` — and it is consulted at EVERY delivery-driven collect/grow site.** `Process::regs` is a **host-published snapshot** of the running process's root set, refreshed only at the engine's heap-admission points and at a park — never around a `call`/`call_ext`, so mid-slice it is stale by up to one slice of instructions (live machine x/stack/FR words a post-publish allocation made are invisible to the collector). Collecting or growing the young heap of a `ProcessState::Running` receiver from a **delivery** would therefore relocate it against that incomplete snapshot and recycle words the running machine (and a `beam_bifs` fast-path BIF's Rust-local accumulator) still points at. Refusing is **sound and cannot leak unboundedly**: the delivery either still fits the current nursery (no relocation, no corruption) or falls back to a `beam_message::HeapFragment` exactly as for a relocation-exempt receiver, and the running process returns to the scheduler, whose own next heap-admission point publishes **current** roots and collects — so nothing accumulates. The gate has two sources so no delivery site can consult one and forget the other: the crate-owned `has_unpublished_roots` predicate **or** a decline from a host-installed `CollectionGate`, consulted first at every delivery-driven collect/grow site — the `ptab.rs` signal builders and `Process::deliver`, the latter honouring a decline by marking the receiver relocation-exempt for the duration of exactly one `Process::deliver` call. The **host admission points are deliberately left ungated**: `Process::collect`/`ensure_capacity`/`collect_if_needed` publish the roots *before* they run (that is what makes them admission points), and `grow_nursery` relocates nothing anyway, so they are gated only by the explicit `relocation_exempt` flag (which makes them refuse with the typed `relocation_exempt` raise) — gating them on `Running` too would make the host's own legitimate collection impossible. Evidence: `process::tests::has_unpublished_roots_covers_the_exemption_and_a_running_process` and `tests/signal_fragment_fallback.rs` cases 6–8.
- **The host's unscanned-root refusal is a SEPARATE, host-installed predicate, not a widening of the crate-owned one.** The crate derives two cases of an unpublished root set itself — the `relocation_exempt` flag (the host asserts it) and the `Running` state (its own executing process) — but a third is invisible to it: a receiver whose live root set is **not** fully **scanned** by its collector (a root word, or a container the receiver's scanned graph reaches, living in a region the collector does not walk). Only the host can see that, so the host owns the valve; the seam is the `CollectionGate` trait — `declines_relocation(&mut self, receiver: &Process) -> bool` — installed with `ProcessTable::set_collection_gate`, whose motivating implementation is `beam_rt`'s unscanned-root predicate (`src/context/gc.rs::root_is_unscanned`, `src/context/gc_walk.rs::any_root_is_unscanned`). The refusal is deliberately limited to the **relocation**: a declined move still delivers the notification (through the same heap-fragment route the `Running`/relocation-exempt receiver takes) and still permits a no-relocation growth (`Process::grow_nursery`), so declining can never lose a signal, and the host's own admission-point collections are unaffected. The seam is **additive and defaulted** — the table field is `Option<Box<dyn CollectionGate>>`, defaulting to `None`, and `declines_signal_collection` answers `false` with no gate — so a sibling compiles unchanged; and `beam_rt` **installs** one — `Runtime::new` wraps its unscanned-root predicate (`src/context/gc_walk.rs::RuntimeCollectionGate`) and calls `ProcessTable::set_collection_gate`, alongside the park-window `relocation_exempt` exemption (which covers a live term the walk cannot see) — so the `beam_process` signal sites decide identically to the host's heap-admission points.
- **The termination cascade is BEST-EFFORT per peer, because the death has already happened.** `terminate_into` reclaims the pid **first** (`take` bumps the slot serial, dropping every name registration and relationship), so by the time the per-peer signals are generated the process *is* dead — the cascade is a notification, not a transaction, and there is nothing left to roll back to. Every per-peer step therefore drops-and-logs its failure (a local `enqueue_exit_signal`/`enqueue_down_signal` whose reason copy cannot be made — an unreachable heap, a relocation-exempt receiver; a remote `DistSignal::Exit` whose `DistSignalRouter::route` transport fails — a down node, an I/O error) and **continues**: `beam_common::beam_error!` reports it, the loop moves to the next peer, and steps 5 (the process-death observer) and 6 (the port-monitor cleanup) always run. Propagating the error instead would be neither honest nor safe: the process is already gone, so the `Err` cannot undo it — it only leaves the *later* peers unsignalled, the observer unrun (leaking exactly the host-owned resources the seam exists to release — ETS tables owned by the pid are the motivating case; `beam_rt`'s tables would leak until node restart) and the `PortTable` holding a dangling incoming `PortMonitor` for a watcher that no longer exists. ERTS takes the same stance on a control signal it cannot deliver: `erts_dsig_drop` (`dist.c`) drops-and-logs rather than failing the death. This is **not** silent swallowing — every dropped signal is logged with both pids and the failure — and the failure policy is confined to `terminate_into`; the ordinary relationship ops (`link_term`, `unlink_term`, `monitor_term`, `demonitor`, `node_down`, `port_closed`, `apply_exit_signal`, `send_exit`) still propagate their errors to the caller, which is the only place the caller can still do something about them. Consequences: `terminate`/`terminate_with_ports` answer `Ok(())` for a **live** pid (`TermNotFound` for an unknown one), and a watcher's outgoing `Monitor` record is resolved even when its `{'DOWN', …}` never made it out of the table — a retained record for an already-dead target could never be resolved afterwards, and a **named** monitor's `{Name, node}` descriptor is dropped with it (nothing will ever materialise the DOWN that would otherwise have consumed it). Deterministic evidence: `tests/terminate_best_effort.rs` (a permanently failing router; an unreachable peer heap) FAILS with a typed `Io`/`Alloc` out of `terminate` — observer unrun, port monitor still listed — the moment the per-peer `?`-propagation is restored.- **The inbound (receipt) distribution primitives are SEPARATE methods, not the outbound entry points.** A locally-initiated relationship change (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`send_exit_term`) always ends by handing a `DistSignal` to the installed `DistSignalRouter`. The C's inbound receipt arms do not: after a successful `DOP_LINK` the arm ends `break; /* Done */` (`dist.c:2258`) and sends **nothing** back, `DOP_UNLINK_ID` answers only the *different* opcode `DOP_UNLINK_ID_ACK`, `DOP_MONITOR_P`/`DOP_DEMONITOR_P`/`DOP_GROUP_LEADER` install/cancel local state and answer nothing, and `DOP_MONITOR_P_EXIT` queues the local `{'DOWN', …}` only (`dist.c:2341-2413`, `:2415-2450`, `:2700-2755`, `:2889-2900`). Reusing an outbound entry point for an inbound message would therefore put an echo of the received opcode on the wire — a *wrong* result, not an inefficiency. So the inbound APIs (`ProcessTable::{record_remote_link, apply_remote_exit_signal, unlink_from_remote, unlink_ack_from_remote, monitor_from_remote, demonitor_from_remote, remote_watchers, remote_monitor_down, set_group_leader_from_remote, group_leader}`) are route-free *by construction* (they never call `route`), which `tests/remote_inbound.rs` pins with a recording router that must stay empty. Two consequences worth recording: the outbound `demonitor_remote`’s record removal was factored into a private route-free `remove_remote_monitor` (the inbound DOWN needs the removal, not the route), and the required `DOP_UNLINK_ID_ACK` reply cannot be expressed as a signal — see the next entry.
- **`DistSignal` gained no variant for the inbound families (`erl_proc_sig_queue.c`-style) because the sibling matches it exhaustively.** `beam_rt/src/dist_client.rs` matches `DistSignal` with **no wildcard**, so an added variant (e.g. `UnlinkAck`) would break a crate that must keep compiling — the additive-only constraint every concurrent sibling change depends on. The one inbound signal that genuinely has to go back out is the `{DOP_UNLINK_ID_ACK, Id, To, From}` reply to an `id != 0` `DOP_UNLINK_ID`, and that is modelled as the **return value** of `unlink_from_remote` — `Some(id)` means "the caller must send the ACK" — because the ACK is a different opcode, the wire is `beam_rt`'s, and the id of a locally-initiated unlink is minted by the router (`remote.rs`'s mapping), which keeps no pending-op record. That last fact is also why `unlink_ack_from_remote` (the *received* ACK, which the C resolves against the local pending unlink op, `erl_proc_sig_queue.c:6733-6760`) can only validate liveness: there is no pending-op bookkeeping in this crate to resolve — its owner is the router.
