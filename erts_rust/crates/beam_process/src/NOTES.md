## module-notes

- **`Registers` has NO float-register (FR) container: the FR file rides in the `Stack`.** The engine's FR slots hold `Eterm` words (no hardware float regs in this engine), so a live float register can point into the process heap and must be a root — but it has nowhere of its own to live here. The host (`beam_rt`'s `context::gc::publish_roots_full`) therefore closes the FR file **onto the end of `Registers::stack`** (after the real Erlang stack words) for the duration of one hand-off, and `scatter_roots_full` splits that region back into `stack` + `fr` by length. So at this node a "stack word" is really a stack-or-FR word: `Registers::gather_roots` roots them all, indistinguishably, in one `Vec<Eterm>`. Adding a real FR field here would change the frozen `Registers` shape — do not.
- **The collector moves live terms, so every in-heap reference must be a root.** `Process::collect` scans registers/stack, mailbox payloads, the process dictionary (`Dict`), the saved args (`SavedArgs`) and the pending-signal queue (`SignalQueue`) — add any NEW in-heap sub-rootset to its gather/scatter, in the same order, in the same change. `Process::port_monitors` is deliberately **not** a root: a `PortWatch` holds only plain values.
- **`Process::regs` is a HOST-published snapshot the scheduler never writes.** The `Registers` container (`x[0..live)` + the whole `Stack`) is filled **only** from outside this crate — the host (`beam_rt`) copies the running machine's own x/stack/FR into it (`publish_roots_full`/`publish_roots`) at a heap-admission point or a park. Nothing in `scheduler.rs`'s slice path (`slice_begin`/`slice_end`/`run_one`/`run_ready`) reads or writes `regs`. `Process::collect`/`collect_kind`/`ensure_capacity` relocate the young heap against this snapshot, so between two publishes it is stale by up to one slice of instructions (live machine x/stack/FR words a post-publish allocation made are invisible to the collector); the crate cannot detect that, so the host must gate it with `set_relocation_exempt` when it holds live terms from the process outside the root set. The **`Running`** case is the second, crate-derived case of the same gate (`has_unpublished_roots`): a delivery to the currently executing process is refused with no host marking, so its stale `regs` snapshot is never collected against. Full hazard analysis: `../../beam_rt/CONTEXT.md` (GC-relocation hazards).
- **Where the PCB and its heap live (address stability).** A `Process` is stored **inline** in `ProcessTable`'s `slots: Vec<Slot>` (`Slot.process: Option<Process>`, `ptab.rs`), so growing the table (`alloc_pid`/`insert`) can reallocate the `Vec` and **move** the PCB — and its embedded `AnyCollector`/`HeapSpace`/`Heap` — to a new address. The heap *words* are unaffected: `beam_alloc::Heap` owns a separate allocator block (`Heap::base: *mut Eterm`), so terms from `get_mut(pid).heap_mut()` stay valid across a table growth (Rust's borrow rules forbid holding the `&mut` across it anyway). The `&mut Heap` **identity** is *not* stable across a collection, though: a fullsweep replaces the mature space (`AnyCollector::collect_major`) and `resize_nursery`/`grow_nursery` replace the nursery, so re-obtain `heap_mut()` after any `collect()` — never cache a heap pointer across one.
- **Pre-emption is the RUNNER's obligation.** A `ProcessRunner` must count its own reductions and return `RunOutcome::Yield` at its `budget`; the scheduler then requeues at the PCB's current priority. A runner that never yields is not pre-empted. `tests/preemption.rs` pins the scheduler half; `beam_rt`'s runner and its `beam_rt/tests/preempt.rs` interleaving pin are under `../CONTEXT.md` Known Issues.
- **The two split borrows** (`Process::heap_and_off_heap_mut`/`heap_and_mailbox_mut`), their callers and the rule against adding a combined raw-pointer accessor are in the `process.rs` API section above (and the module rustdoc).
- **`ProcessTable` is `!Send`; the SMP pool contains it with two `unsafe impl Send/Sync`.** The measured causes are **six**: `beam_alloc::Heap`'s `base: *mut Eterm`, `beam_gc::MsoHandle`'s `ptr: NonNull<Mso>` (via `beam_message::OffHeapTable`), the `Rc<AtomTable>` in each `Dict`, and this crate's own `Option<Box<dyn DistSignalRouter>>`, `Option<Box<dyn ProcessExitObserver>>` and `Option<Box<dyn CollectionGate>>` (`beam_alloc::RefcBinary` is already `Send`). The `Rc<AtomTable>` is never cloned and never shared outside the table, so no `Rc` is touched from two threads. The full invariant lives in `smp/CONTEXT.md` and `smp/mod.rs`. Removing the workaround needs an upstream `beam_gc`/`beam_alloc` change this crate must not make — do not widen this `unsafe`.
- **The SMP pool (`smp/`) must follow its BINDING locking discipline** (`smp/CONTEXT.md`): never hold a queue lock while taking the table lock and vice-versa; buffer requeues while the table guard is held; the only nested order is *signals mutex → queue lock*. It reuses the frozen `slice_begin`/`slice_end`/`drain_woken_into` helpers (in `run_locked_quanta`) — do **not** re-implement slice logic in a worker.
- **Oracle-probed semantics live in the tests, not this file.** Before changing monitor/registration/signal behaviour, run the relevant probe: `erl -noshell -eval '<expr>, halt(0).'` — the oracle is OTP 29.1.1 / erts-17.1. The `erl`-cross-checked suites (`tests/dict_oracle.rs`, `registry_monitors.rs`) skip loudly when `erl` is absent.

## process.rs

- **Owned off-heap binaries** — the process's second, **process-owned** `beam_gc::OffHeap`, distinct from the message-transit `off_heap` (never swept): one slot per payload (the legacy `MSO(p)` invariant — a duplicate registration returns the existing slot and drops the surplus handle), the readers expose the roster (`off_heap_binary`/`off_heap_binaries`/`off_heap_binary_count`) and hand it out read-only (`owned_off_heap`, the handle `beam_gc::HeapFootprint::of` takes), and `off_heap_binary_bytes()` reports the payload bytes — the **host-asserted** figure when `set_off_heap_binary_bytes` installed one, otherwise the roster-derived sum (the `system_info` memory hook), `declare_off_heap_binary_dead(slot)` is the **provable-death** signal, and three sweeps. `sweep_off_heap_binaries_reachable()` is the **reachability-driven** one: it gathers the root set read-only via `gather_scan_roots` (the same regions `run_rooted_collection` gathers — `Registers::gather_roots` for the x-registers/stack/extra roots, each queued message's `payload`/`from`/`token` read **in place** via `Queue::iter`, the dict, the saved args and the pending signals), enumerates the whole heap with `beam_gc::AnyCollector::for_each_reachable_object_view`, reading each reported object through `beam_gc`'s **safe** `beam_gc::ReachableObject` view (`object.header()` / `object.word(1)` — no raw-word arithmetic of this crate's own, so the sweep needs **no** `unsafe`), records the off-heap payload pointer of every reachable `HEADER_BIN_REF` object (BinRef word 1 = `RefcBinary::data_ptr()`, the frozen `BinRef.val` contract; the walk descends an `ErlSubBits`'s `orig` slot into its `BinRef`, so the single header test covers the whole refc pair), and releases every owned payload no reachable `BinRef` names — through the same `retain_off_heap_binaries` seam. It **declines** (retains everything, `Ok(0)`) for a process whose root set is incomplete — `has_unpublished_roots()`, i.e. a relocation-exempt or `Running` one — where a missed live `BinRef` would release a live payload (a dangle), and it skips the O(heap) walk entirely when `owned_binaries` is empty. `sweep_off_heap_binaries()` is the **crate-driven conservative** form (releasing exactly the declared-dead entries, and returning `0` before any roster work when nothing has been declared dead — the common case, since it runs at the tail of every rooted collection) and `retain_off_heap_binaries(is_live)` the caller-predicate form. Slots are stable for the process's lifetime (a released slot answers `None` and is never reused).
- **Delivery and collection:** `deliver(from: Eterm, term: Eterm, src_off_heap: &OffHeapTable) -> Result<DeliverOutcome>` copies `term` into the young heap **through a fresh per-send staging `OffHeapTable`** (drained into the resulting `Message`; the persistent `off_heap` is never touched, so a send cannot steal a queued signal's off-heap handles), enqueues then `wake()`s (`deliver_simple` is the no-off-heap form, `receive(pred)` delegates to `beam_message::receive`); `collector() -> &beam_gc::AnyCollector` (`kind()`/`mature_choice()` name the strategy, the mature generation is read through `mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_base`/`mature_contains`, while `young`/`stats`/`minor_gcs`/`policy`/`should_collect`/`collection_debt`/`heap_used_words`/`collect_if_needed` are strategy-agnostic; `collection_debt()` is the retention query — the collector is carrying a space a no-collect `grow_nursery` retired, and only a collection reclaims it; `admission_requires_collection(need_words)` is the crate's own heap-admission predicate, `should_collect(need_words)` **OR** `collection_debt()`, self-limiting because a collection collapses the chain so the debt half cannot fire twice for one debt; `collect_if_needed(need)` runs that predicate, so a chain built by `grow_nursery` is collapsed by the crate's own admission instead of accumulating spent spaces); `collect() -> Result<Collection>` gathers the root set, runs the collector and scatters back, `collect_kind(kind: CollectionKind) -> Result<Collection>` is the kind-pinned sibling (it runs **exactly** `kind` over that same root set — `beam_gc::AnyCollector::collect_kind`, which neither chooses by policy nor escalates a would-not-fit minor to a major, so a pinned `Minor` whose promotion cannot fit the mature space yields the typed `AllocKind::Heap` exhaustion with the nursery, the mature space and the counters untouched; it takes the same `relocation_exempt` refusal as `collect` and goes through the same `run_rooted_collection`), `ensure_capacity(need_words) -> Result<Collection>` is the on-demand-growth sibling (collect once, then grow the nursery to the smallest curated size covering the request; a fail-fast typed `AllocKind::Heap` when the policy's ceiling makes it unreachable), and both route through one shared `run_rooted_collection` that writes every root region back even when the collection action returned `Err` and ends with a **two-half** off-heap reclamation (in this order): the **reachability** sweep (`sweep_off_heap_binaries_reachable_from`, reusing the roots the collection just gathered) and the **conservative** declared-dead sweep (`sweep_off_heap_binaries`) — so a caller's asserted `declare_off_heap_binary_dead` death is always honoured, even for a process the reachability half declines or whose handle is still on the heap; a reclamation walk error surfaces only when the collection itself succeeded; `grow_nursery(need_words) -> Result<usize>` is the **no-relocation** growth passthrough (forwarded straight to `AnyCollector::grow_nursery`, never through `run_rooted_collection`): it retains the space it replaces (the nursery becomes a chain — `young_space_count` grows, `young().capacity_words()` grows), moves no live term and runs no collection (`minor_gcs` unchanged), returns the new young capacity in words and yields the typed `BeamError::Alloc` when the policy's ceiling cannot reach the request. **A delivery never collects or grows a receiver whose relocating collection is declined** — the crate-owned `has_unpublished_roots` predicate or the host's installed `CollectionGate`: `deliver` (and the `ptab.rs` signal builders) return the raw `AllocKind::Heap`/`AllocKind::Message` refusal **unchanged** — no collection, no growth, no retry — which is exactly the signal the host's heap-fragment fallback keys on, so the payload is still delivered (fragment-resident) without a heap word moving. `collect`/`collect_kind`/`ensure_capacity`/`collect_if_needed` are the **host admission points** and are **not** gated by `has_unpublished_roots` (the host publishes the roots *before* calling them); they are gated only by the explicit `relocation_exempt` flag.
- **Heap observables: the chain sum vs the current space.** `Process` exposes no `heap_size`/`minor_gcs` of its own — a host reads them off `collector()`. `heap_used_words()` is the young heap's **chain-summed** occupancy — the same reading as `beam_gc::HeapObservable::heap_used_words`, so a space a no-collect `grow_nursery` retired keeps contributing the live words it holds until a collection collapses the chain — while `collector().heap_size_words()`/`total_heap_size_words()` are the **capacities** summed over the whole nursery chain (retired spaces included) plus the mature capacity, so a host's `process_info(P, heap_size)` climbs with every `grow_nursery` even if no collection has ever run. `collector().minor_gcs()` is `minor_since_major` (reset by a major), not a lifetime count — `0` means "no collection since construction or the last fullsweep"; the lifetime pair is `collector().stats()`. A host admission route that only grows (never `collect_if_needed`/`admission_requires_collection`/`ensure_capacity`) therefore reports linearly climbing `heap_size` with `minor_gcs` frozen at `0`.

## max_heap.rs

- `MaxHeapUsage { heap_words, off_heap_binary_bytes }` — `heap_words` is the total heap **capacity** (nursery chain + mature, i.e. the oracle's `Total Heap Size`), **not** the occupied words; `charged_words(flags)` adds `ceil(off_heap_binary_bytes / size_of::<Eterm>())` only when `include_shared_binaries` is set, saturating rather than wrapping. Honest gap: the C also adds `bin_old_vheap`, which this crate does not model (an under-estimate, never an over-estimate).
- `Process` side (in `process.rs`): `set_max_heap_size`/`max_heap_size` (wholesale replacement — no validation here), `max_heap_usage`, `heap_limit_verdict(prospective_words)` (the pure prospective decision for a host admission door) / `current_heap_limit_verdict`, `max_heap_verdict`/`take_max_heap_verdict` (the latch), and the private `record_max_heap_verdict` run at the **tail** of `collect`, `collect_kind`, `ensure_capacity` and `grow_nursery` (and `collect_if_needed` through its `collect` call). This is what makes the check land on the **prospective post-collection capacity** — the site where `total_heap_size_words()` already reflects the installed growth — and it stores only a **breach** (storing `Within` would make the latch meaningless), returning immediately for an **unlimited** setting — a limit-less process pays no off-heap accounting at the tail of every collection/growth, which matters because the charge's off-heap half is an O(off-heap slots) sum over the owned roster. A breach never alters the collection's `Result`. The off-heap half itself is `off_heap_binary_bytes()`: `set_off_heap_binary_bytes(n)` is the **host's** assertion of the process's off-heap payload bytes (in production the payloads live in the engine machine's reservoir, which the PCB cannot see; the host owns the number's accuracy) and takes precedence over the roster-derived sum, while `owned_off_heap()` is the read-only roster handle a memory reporter charges through `beam_gc::HeapFootprint::of`.

## dict.rs

- `Dict` (`Default`) backs `erlang:put/2`/`get/1`/`erase/1` (last put wins, `put` returns the replaced value) with `new()` (empty) / `with_atoms(Rc<AtomTable>)` and the never-panic GC pair `gather_roots`/`scatter_roots`. `None` is the C `THE_NON_VALUE` (the BIF layer maps it to `undefined`); keys — and, for `get_keys_for_value`, **values** — compare with `beam_term::compare::eq` (the C's `EQ`, `erl_utils.h:113`: structural `=:=`), so a *boxed* key matches a distinct-but-equal term (`put({a},1), get({a})` ⇒ `1`); atom names resolve through the `Rc<AtomTable>` handle (`new()` ⇒ empty table, whose unknown-name fallback is the raw atom index — the C's `EQ` for two immediates). Holds terms resident in THIS process's young heap (a `Process::collect` sub-rootset). Iteration is insertion-ordered — a documented deviation from the C's hash-array order (`pd_hash_get_all`), an unspecified artifact **not stable across VM starts** and so unpinnable by a differential case; `tests/dict_oracle.rs` compares `get/0` as a **set**. See `../DESIGN_DECISIONS.md`.

## monitor.rs

- `MonitorRef { id: u64 }` (`Copy + Eq + Hash`) — `to_eterm(self, heap) -> Result<Eterm>` builds the on-heap `Ref` thing through `beam_term`'s checked `write_internal_ref` (`Alloc` when the heap is full; `../DESIGN_DECISIONS.md`), `from_eterm(term) -> Result<MonitorRef>` is the reverse (parses the frozen `[header, node, serial, id]` ref thing, `BadArg` for anything else — the send path's destination→key step, with guard-chain parsing like `payload_is_down_for`). The whole id rides the block's single small-integer word, so it is **checked** against `beam_term`'s `SMALL_BITS`/`MAX_SMALL` (`0..=MAX_SMALL`, never re-derived) **before** any heap word is reserved: an id past it is refused with `BeamError::SystemLimit` (`error::system_limit()`, the pid/port-space analogue) — never a panic, a wrapped negative small or a layout-breaking bignum — while ids below the bound encode byte-identically. `RefAllocator` — a **zero-sized handle** onto the runtime's one shared local reference-id space (`beam_common::next_ref_id`): `new()` + `next() -> MonitorRef`, which *is* that one draw (`next` stays infallible by contract; the counter's out-of-range half is simply unencodable, so the encoder is the one checked gate and no *usable* id is ever reused). It holds no counter of its own, so every local producer — this crate's monitors/aliases (`ProcessTable::refs`, `ProcessTable::next_reference`), `erlang:make_ref/0`, the NIF `make_ref`, the timers, `seq_trace` and NIF resource terms — draws from the same monotone sequence, and two producers (or two `ProcessTable`/`Runtime` instances in one OS process) can never issue the same id; a bare `make_ref/0` reference therefore can never be `=:=` a monitor/alias reference (`tests/reference_ids.rs` pins the shared source exactly and the absence of a collision). `from_id(id: u64) -> MonitorRef` is the one **non-mint** constructor: it names an explicit, caller-derived id — today the unnamed-ETS-table tid, whose id must be the table handle so `beam_rt`'s `tid_ref_thing` writes a reference the table-taking BIFs decode back to that handle — draws nothing from the shared space and consumes nothing (`tests/reference_ids.rs::from_id_consumes_no_shared_id`), so its uniqueness is the caller's claim: a `from_id` id must never be one a live mint could hand out unless the caller is deliberately probing it. It is total and infallible; the encodable bound stays `to_eterm`'s.

## ptab.rs

- **`erlang:monitor/3` user tag (additive):** the `*_with_tag` points (`monitor_with_tag`, `monitor_named_with_tag`, `monitor_port_with_tag`, `monitor_port_term_with_tag`, `monitor_term_with_tag`) take a trailing `tag: Option<Eterm>` (the no-tag methods delegate with `None`); a `Some(tag)` makes the delivered message `{Tag, Ref, Kind, Target, Reason}` instead of `{'DOWN', Ref, Kind, Target, Reason}` — the tag replaces the head atom only. The tag is stored in the private `tags: HashMap<MonitorRef, Eterm>` side table (`remember_tag`/`forget_tag`, cleaned up at `demonitor`/`demonitor_port`/termination/port close) — **never** in the frozen `Monitor`/`MonitoredBy`/`PortWatch` structs. The tag must be **heap-independent**: an **immediate**, or a term resident in a **literal area** (`is_immediate(t) || ((is_boxed_term(t) || is_list(t)) && is_literal(t))` — `is_literal` is a bare `TAG_LITERAL_PTR` bit test, meaningful only on a BOXED/LIST word, so it is guarded by the pointer-tag test); a **heap-resident** tag (or any tag on a **remote** external-pid target — `DOP_MONITOR_P` carries no tag) is a typed `unsupported`.
- **Reference aliases (`erlang:monitor/3` `{alias, Mode}`, `erlang:alias/1`, `erlang:unalias/1`):** a `MonitorRef` may name an **alias** — a send destination that resolves to its owner — held in the private `aliases: HashMap<MonitorRef, AliasEntry>` side table (next to `tags`; nothing else stores it). `MonitorOptions { tag, alias }` plus the `*_with_options` points (`monitor_with_options`, `monitor_named_with_options`, `monitor_port_with_options`, `monitor_port_term_with_options`, `monitor_term_with_options`) register the alias; the existing `*_with_tag` methods delegate with `alias: None`, so their signatures are unchanged. `resolve_alias(reference) -> Option<ProcessId>` is the send-path resolver — `Some(owner)` iff the reference names an alias whose owner is **live**; `create_alias(owner, mode) -> Result<MonitorRef>` is `alias/1`; `unalias(owner, reference) -> Result<bool>` is `unalias/1` (clears only the alias of `owner`, keeping a sharing monitor); `alias_reply_delivered(reference) -> Result<()>` is the reply site. **Auto-removal** follows the C (`bif.c:470-492`, `erl_proc_sig_queue.c:6009-6112,:6466-6493`): `reply_demonitor` ⇒ gone once a message is delivered through it; `demonitor`/`reply_demonitor` ⇒ gone when the monitor's DOWN is materialised (the shared `apply_alias_on_down`, used by the termination/`port_closed` and born-down `noproc` paths); `explicit_unalias` ⇒ survives its DOWN and an explicit `demonitor` (re-derived as a standalone alias) and is cleared only by `unalias/1`. A dying owner's aliases are all swept (`aliases.retain(|_, e| e.owner != pid)`), so no alias ever resolves to a dead pid. A `{alias, …}` on a **port** monitor or on a **remote** external-pid target is a typed `unsupported` (see `../CONTEXT.md` Known Issues).
- `service_signals(pid) -> Result<()>` drains + applies the pid's pending-signal queue in FIFO order, cascading to any process those signals affect (the scheduler calls it at schedule-in); a pid whose queue is **empty** (or unknown) returns immediately — nothing to apply, and the worklist's only growth source is a signal read off a queue, so the cascade cannot grow from nothing — which keeps the common per-schedule-in case free of the worklist's heap allocation; `service_signals_with_ports(&mut PortTable, pid)` threads the port table so such a cascade also cleans a terminated process's incoming port monitors (the plain form delegates with no ports). `service_receive_signals(pid) -> Result<()>` — the **receive-scan** entry point: applies the **receive-applicable** head signals strictly FIFO (a trapped exit ⇒ `{'EXIT',From,Reason}` through `deliver_trapped_exit`, a monitor `DOWN` ⇒ `{'DOWN',…}`/`{Tag,…}` through `deliver_down_message`), **discards** an `Ignore` head (a `normal` reason to a non-trapping receiver, which the C drops), and **stops before** the first `Terminate` head, leaving it and everything behind it queued and untouched (`Ok(())`). It never terminates and therefore never cascades and takes **no `PortTable`** — no `_with_ports` sibling, because only a terminating cascade drains a dying process's incoming port monitors. Termination is the schedule-out net's (the runtime's park arm re-queues instead of parking; the next schedule-in's `service_signals` applies it and cascades) — the C's `i_loop_rec` `get_out > 0` ⇒ `do_schedule` (`emu/msg_instrs.tab:60-140`, `erl_proc_sig_queue.c:7729`). Quiet/unknown pid ⇒ `Ok(())` with zero mutation and zero allocation. Builders' `BeamError::Alloc` propagates exactly as in the schedule-in path, and the `Running`/relocation-exempt + `CollectionGate` heap-fragment fallback is unchanged. It reuses `apply_head_signal` (whose cascade worklist stays empty: only its terminating arm pushes) and leaves `service_signals`/`service_signals_with_ports`/`apply_head_signal`/`drain_signals` unchanged for their callers.
- **Signal-build exhaustion:** a signal the receiver's full nursery refuses is routed into a heap fragment when the receiver's relocating collection is **declined** — the crate-owned `Process::has_unpublished_roots` (**relocation-exempt** or currently **`Running`**) OR the host's `CollectionGate` (consulted first at every signal site; no collection, no growth, no relocation either way), at **both** refusal sites — the apply-time message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) and the enqueue-time reason copy (`copy_reason_onto` → `enqueue_down_signal`'s `deliver_down_fragment` / `enqueue_exit_signal`'s `deliver_exit_fragment`, which build the message the queue would have materialised straight from the enqueue site and wake a blocked receiver themselves). The enqueue-time **exit** fallback keys on the **family-aware** policy — the `Trap` arm of `exit_policy(reason, recipient.is_trapping_exit(), family, &atoms)`, never `is_trapping_exit()` alone — so an **untrappable** explicit `kill` sent to a trapping receiver is never delivered as a `{'EXIT', From, kill}` fragment, while a trappable `Linked` `kill` is. The shared helper is `enqueue_fragment_payload` (it takes the **source** process's off-heap table, `None` meaning the receiver's own). The only refusal still surfaced is the exit **policy** one: an exit signal to a **non-trapping** receiver whose collection is declined, which would have to terminate it (the caller's cascade, not a message).

## remote.rs

- `DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()>; }` — **the distribution seam**: implemented downstream (`beam_rt`) over `beam_dist`; `route` must serialise the signal **synchronously** (`reason` may live in the signaller's heap, which the caller may drop right after). Its transport error propagates out of the relationship ops (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`node_down`), but **not** out of a dying process's termination (the remote steps of `terminate_into` — one `DistSignal::Exit` per remote link partner and one `DistSignal::MonitorExit` per incoming `RemoteWatcher` record — drop-and-log a failed `route`, ERTS's `erts_dsig_drop`, and keep routing the remaining peers). The table's remote records (`remote_links`/`remote_monitors`) and `set_dist_router`/`has_dist_router` are on `ptab.rs`. **This seam is OUTBOUND only** (local → remote): it never consumes a control message. The crate *does* own the inbound (receipt) **primitives**, as route-free `ProcessTable` methods that take a `DOP_*`'s already-parsed pieces — `record_remote_link` (DOP_LINK), `apply_remote_exit_signal` (DOP_EXIT/DOP_EXIT2 — keeps its public `untrappable: bool` and maps it onto the `ExitFamily` (`true` ⇒ `Explicit`, `false` ⇒ `Linked`); both former hand-rolled branch bodies are now one `exit_policy` call on that family, with only the link removal family-specific, and the recorded link is removed **before** the policy runs), `unlink_from_remote`/`unlink_ack_from_remote` (DOP_UNLINK_ID/_ACK), `monitor_from_remote`/`monitor_from_remote_ref`/`demonitor_from_remote`/`demonitor_from_remote_ref`/`remote_watchers` (DOP_MONITOR_P/_DEMONITOR_P, on the `RemoteWatcher` side table; the `_ref` spellings key the record by the **whole peer-minted** reference — a decomposed `RemoteRef` — so two distinct peer references never collapse), `remote_monitor_down` (DOP_MONITOR_P_EXIT, removes the outgoing `RemoteMonitor` **without** routing a DOP_DEMONITOR_P; its outbound mirror is `DistSignal::MonitorExit`, which `terminate_into` routes once per drained `RemoteWatcher`), `set_group_leader_from_remote`/`group_leader` (DOP_GROUP_LEADER, on a `PidTarget`-valued `group_leaders` store), plus `next_reference` (the additive HAZARD-2 seam: the table's own `RefAllocator`). They never echo the opcode they received (`dist.c:2258` `break; /* Done */`), so they must NOT go through the locally-initiated entry points, which all route. Decoding the wire, resolving a name target and choosing the primitive remains `beam_rt`'s (`../beam_rt/src/dist_client.rs`).
