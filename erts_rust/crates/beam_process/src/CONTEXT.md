# `beam_process/src` — the module layer (21 modules + `smp/`)

## Intent
One routing node for the modules of the `beam_process` crate. The **crate-level contracts** — Intent,
the frozen-seam overview, Constraints, Test Strategy, Handoffs, Known Issues — live in
`../CONTEXT.md`; read that first.

Each `src/<module>.rs`'s **top-of-file `//!` rustdoc plus its per-item `///` docs is authoritative for
its complete method list and detailed contracts**. This node records the *frozen* API surface a
dependent designs against: the seam types and shapes, the constants, the entry points dependents call,
and the behavioural caveats that must not be lost. Everything here is re-exported at the crate root and
via `beam_process::prelude::*`.

The cross-module binding rules (eager-vs-queued signalling, the collect-then-apply worklist, the
split-borrow rule, the `from`-is-immediate producer rule, the exhaustion policy) are stated **once** in
`../CONTEXT.md` and cited below.

## API Surface (FROZEN — dependents route here)
### `pid.rs` — process/port identity (bit-exact with `beam_term::immediate`)
- `ProcessId { number: u64, serial: u64 }` (`Copy + Eq + Hash + Ord + Debug`) — `to_eterm() -> Eterm` = `make_internal_pid(make_pid_data(serial, number))`; `from_eterm(Eterm) -> Result<ProcessId>` is `BadArg` unless an internal pid; `is_process(Eterm)`.
- `PortId { number: u64 }` — same shape via `make_internal_port`/`is_internal_port`.
- Limits: `MAX_PROCESS_NUMBER = (1 << 28) - 1` (`PID_NUM_SIZE`); `MAX_PROCESS_SERIAL = 2^32 - 1` (`PID_SER_SIZE`).
### `registers.rs` — the root-set containers (x-register file + Erlang stack + host-published extra roots)
Honors the crate-layer root-set contract: `x_reg_array[0..Live)` **plus the whole stack**, no frame liveness maps; `MAX_REG = 1024` (`erl_vm.h`), `MAX_ARG = 255`.
- `XRegs` (boxed `[Eterm; MAX_REG]` + `live`; `new` = all `NIL`, `live == 0`), `Stack` (`Vec<Eterm>`), `Registers { x, stack, extra_roots }` with the GC pair `gather_roots(&self, out: &mut Vec<Eterm>) -> usize` (appends `x[0..live)`, then every stack word, then every extra root; returns the `x_live` split point) / `scatter_roots(&mut self, roots, x_live)` (writes the first `x_live` back into `x`, the next `stack.len()` into the stack, the remainder into `extra_roots`; total — a mismatched short slice leaves the uncovered tail untouched, never panics).
- **`extra_roots: Vec<Eterm>`** — the one host-published extension of the frozen root shape: terms a host holds **outside** `x`/`stack` but that must survive a relocation (the motivating case is a parked engine `Machine`'s live pending-exception reason term while the process waits). Accessors `extra_roots() -> &[Eterm]` / `extra_roots_mut() -> &mut Vec<Eterm>` (a mutable container, not a by-value setter: the host pushes on suspend and clears on resume, with terms resident across any number of collections in between); empty in `new()`. `Process::run_rooted_collection` hands `scatter_roots` exactly the register prefix it gathered, so the extra roots ride along with `x`/stack automatically.
### `process.rs` — the process control block (PCB)
- `ProcessState { Runnable, Running, Waiting, Suspended, Exiting, Terminated }` (`Copy`); `DeliverOutcome { Enqueued, Woke }` (`Copy + Eq`, `woke() -> bool`) — `Enqueued` = recipient not blocked, `Woke` = it was blocked (`Waiting`/`Suspended`) and is now `Runnable`; `ProcessFlags` — a `u32` bitset (no `bitflags` dep) over `trap_exit`, `system`, `in_run_queue`, `garbage_collecting`, `active`, `sensitive` (`bits()/from_bits()` + per-flag get/set).
- `Process` fields (shape frozen): `pid`, `state`, `flags`, `priority`, `save_calls: u16`, `collector: beam_gc::AnyCollector`, `relocation_exempt: bool`, `off_heap: beam_message::OffHeapTable` (the **persistent** off-heap table — a queued signal's reason objects and a host's moved-fragment objects; the send path stages through its own fresh table, never this one), `owned_binaries: beam_gc::OffHeap` + `owned_binary_index: std::collections::HashMap<usize, usize>` + `owned_binary_slots: usize` + `dead_binaries: Vec<usize>` (the process-owned list, its live `data_ptr → slot` index, its slot-space-size mirror, and the declared-death worklist; swept by the reachability-driven `sweep_off_heap_binaries_reachable` and the conservative `sweep_off_heap_binaries` — see the owned-off-heap-binaries bullet below), `off_heap_binary_bytes_override: Option<usize>` (the host's asserted payload byte figure; `set_off_heap_binary_bytes` installs it and it takes precedence over the roster-derived sum), `mailbox: beam_message::Queue`, `regs: Registers`, `dict: Dict`, `saved_args: SavedArgs`, `signals: SignalQueue`, `reductions: u64`, `links: Links`, `monitors: Monitors` (outgoing), `monitored_by: Vec<MonitoredBy>` (incoming), `port_monitors: Vec<PortWatch>` (outgoing port watches), `exit_reason: Option<Eterm>`, `max_heap: crate::max_heap::MaxHeapSetting` (the C per-process `MAX_HEAP_SIZE(p)`/`MAX_HEAP_SIZE_FLAGS(p)` pair; born unlimited with `MaxHeapFlags::default`) + `max_heap_verdict: Option<HeapLimitVerdict>` (the latched breach notice the collection/growth doors record — see the `max_heap.rs` section).
- `collector` resolves its mature strategy from the spawn policy — the copying space below `beam_gc::IMMIX_BREAK_EVEN_WORDS`, the mark-region (GenImmix) space at/above it (a default policy resolves below it); `new(pid)`/`with_policy(pid, policy)`/`with_policy_and_priority(pid, policy, Priority)` construct it, the last the **spawn-at-priority** form (a runtime composes `alloc_pid` + it + `ProcessTable::insert`, so a child is born at its level, not Normal).
- Contracts: `heap()/heap_mut()` is the **young** mutator heap; `wake(&mut self) -> bool` (`Waiting`/`Suspended` ⇒ `Runnable` + `true` — resume-on-send); `status_atom`/`status` map the state (with `garbage_collecting` layered over it) to the oracle's `process_info(P, status)` atoms `"running"`/`"runnable"`/`"waiting"`/`"suspended"`/`"exiting"`, `None` for `Terminated` (a dead pid answers `undefined`; the BIF layer supplies that); **no receive scan position is stored on `Process`** — the mailbox is a pure FIFO and a `QueueCursor` is a transient caller-local value (only `ProcessTable::demonitor_flush` drives one, re-derived per removal).
- **Owned off-heap binaries** — the process's second, **process-owned** `beam_gc::OffHeap`, distinct from the message-transit `off_heap` (never swept): one slot per payload (the legacy `MSO(p)` invariant — a duplicate registration returns the existing slot and drops the surplus handle), the readers expose the roster (`off_heap_binary`/`off_heap_binaries`/`off_heap_binary_count`) and hand it out read-only (`owned_off_heap`, the handle `beam_gc::HeapFootprint::of` takes), and `off_heap_binary_bytes()` reports the payload bytes — the **host-asserted** figure when `set_off_heap_binary_bytes` installed one, otherwise the roster-derived sum (the `system_info` memory hook), `declare_off_heap_binary_dead(slot)` is the **provable-death** signal, and three sweeps. [`NOTES.md` §process.rs carries the rest of this bullet.]
- **Off-heap-binary registration is O(1) amortized, not O(slot space).** `owned_binary_index: std::collections::HashMap<usize, usize>` maps each **live** payload's `RefcBinary::data_ptr()` to its slot.
  `register_off_heap_binary` resolves the slot with one index lookup (`owned_binary_slot`), never a scan over the slot space, and on a fresh insert writes the new `data_ptr → slot` entry alongside the `owned_binaries.insert`.
  `retain_off_heap_binaries` — the **one** release funnel both sweeps go through — prunes the index of every payload `is_live` reported dead, after `OffHeap::sweep` returns, so the index can never map a `data_ptr` to a released slot.
  A released payload's re-registration therefore takes a **fresh** slot; dedup-on-`data_ptr`, slot stability and never-reuse are unchanged.
  `owned_binary_slots` stays the slot-space-size mirror: a fresh insert returns exactly the **pre-insert** mirror (the mirror's current value *is* the next fresh slot index) and then sets it to `slot + 1` — the returned slot is checked against that pre-insert value by a `debug_assert!`; a sweep never changes the mirror.
  Pinned by `off_heap_binary_registration_work_is_independent_of_slot_count` and `off_heap_binary_release_prunes_the_index_and_a_fresh_registration_gets_a_new_slot` (`process.rs` in-module tests).
- **Split borrows** — the only two `*_mut` pairs with a real caller need; both destructure `self` into two disjoint `&mut` fields in safe Rust (compiler-proven, no raw pointer) and must not be joined into a combined raw-pointer accessor (the crate-level split-borrow rule): `heap_and_off_heap_mut()` (young heap + off-heap table) drives `beam_message::Fragments::move_into`, the only way to move a **fragmented** payload onto the heap; `heap_and_mailbox_mut()` (young heap + mailbox) drives `beam_message::send_fragmented`.
- **Delivery and collection:** `deliver(from: Eterm, term: Eterm, src_off_heap: &OffHeapTable) -> Result<DeliverOutcome>` copies `term` into the young heap **through a fresh per-send staging `OffHeapTable`** (drained into the resulting `Message`; the persistent `off_heap` is never touched, so a send cannot steal a queued signal's off-heap handles), enqueues then `wake()`s (`deliver_simple` is the no-off-heap form, `receive(pred)` delegates to `beam_message::receive`); `collector() -> &beam_gc::AnyCollector` (`kind()`/`mature_choice()` name the strategy, the mature generation is read through `mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_base`/`mature_contains`, while [`NOTES.md` §process.rs carries the rest of this bullet.]
- **Heap observables: the chain sum vs the current space.** `Process` exposes no `heap_size`/`minor_gcs` of its own — a host reads them off `collector()`. [`NOTES.md` §process.rs carries the rest of this bullet.]
- Each queued message contributes **three** roots — `payload()`, `from()`, `token()` — all written back into the re-installed envelope (`Message::with_payload` / `set_from` / `set_token`), so the message keeps its **whole envelope** (`from`, `token`, off-heap handles, refc binaries, node entries and — for an oversized payload that lives *in* them — its `Fragments` chain); a queued payload referencing an off-heap refc binary therefore stays alive across the collection (a fragment-resident payload is outside every evacuated range).
- **Relocation exemption:** `set_relocation_exempt`/`is_relocation_exempt` (default `false`) — a per-`Process` flag for a host holding live terms from this process's young heap in Rust locals / nested-`Machine` registers that are **not** in the crate root set. While exempt: `deliver` surfaces the raw refusal; `collect`/`collect_kind`/`ensure_capacity` refuse with the typed `error::relocation_exempt(what)` raise (a `BeamError::Raise` whose reason atom is `relocation_exempt: <what>`); `collect_if_needed` answers `Ok(false)` without collecting, so an exempt process keeps any collection debt `grow_nursery` gave it and the debt is settled by whichever non-exempt admission collects it later; `run_rooted_collection` is unreachable from those four. `grow_nursery` is **not** gated by the flag (it relocates nothing, so it is legal for an exempt process). Opt-in per process, not a global valve. The reachability-driven off-heap sweep (`sweep_off_heap_binaries_reachable`) also refuses for such a process (retains everything, `Ok(0)`) — the same incomplete-root-set reasoning: a missed live `BinRef` would release a live payload. The exemption is **one of the two** cases of `has_unpublished_roots() -> bool`, the crate-owned half of the **relocation-decline gate** every delivery-driven collect/grow site consults (`Process::deliver` and every `ptab.rs` signal site: `grow_receiver_for_signal`, `build_signal_message`, `copy_reason_onto`, `deliver_head_signal`, the `enqueue_exit_signal`/`enqueue_down_signal` pair, and the `deliver_noproc_down`/`deliver_named_noproc_down`/`enqueue_remote_down_message`/`enqueue_remote_exit_message`/`enqueue_port_down_message`/`enqueue_port_exit_message` builders) — whose other case is a `ProcessState::Running` process (the one its own engine is executing, whose `regs` snapshot is stale mid-slice); the `Running` case needs no host marking. Rationale: `../CONTEXT.md` Known Issues.
  **Nothing guards the relocating collection doors against a mid-slice call**: `collect`/`collect_kind`/`ensure_capacity`/`collect_if_needed` test **only** `relocation_exempt` (no `ProcessState::Running` check, no re-entrancy guard, no `garbage_collecting` assert), so a host that calls one while its own engine is executing (state `Running`, `regs` a stale snapshot) must have published its roots first — the `Running` half of the gate is consulted by `deliver` and the `ptab.rs` signal sites only. `grow_nursery` relocates nothing and needs neither.
- **Host collection gate:** `CollectionGate` — the host's half of the same exhaustion policy, an additive trait `{ fn declines_relocation(&mut self, receiver: &Process) -> bool; }`. It takes `&mut self` (a gate may keep state — a cache, a counter) and receives the receiver's PCB (so it can consult the process's pid/heap/collector geometry); answering `true` declines only the **relocation**, so a no-relocation growth (`Process::grow_nursery`) or a heap-fragment delivery still proceeds and the notification is never lost. Installed on the process table (`ProcessTable::set_collection_gate`) and consulted at every signal site (OR-ed with `has_unpublished_roots`) plus `ProcessTable::deliver`; the motivating host is `beam_rt`'s unscanned-root predicate (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs::any_root_is_unscanned`). `ptab.rs` exposes `set_collection_gate`/`take_collection_gate`/`has_collection_gate` and the private `declines_signal_collection`.
### `max_heap.rs` — the per-process `max_heap_size` policy (setting · accounting · verdict)
The authoritative model of the C's per-process `MAX_HEAP_SIZE(p)`/`MAX_HEAP_SIZE_FLAGS(p)` pair and its `check_max_heap_size` decision. Pure decision surface: types and arithmetic only, **no** mutation of a process and no termination (the host performs the verdict).
- `MaxHeapFlags { kill: bool, error_logger: bool, include_shared_binaries: bool }` (`Default` = the C `H_MAX_FLAGS`, `erl_init.c:814-815`: kill on, error_logger on, shared binaries **excluded**) — the flags select the **exceed behaviour**, not the bound; `error_logger` is independent of `kill`, so `kill: false, error_logger: true` logs on every subsequent over-limit collection.
- `MaxHeapSetting { size: usize, flags: MaxHeapFlags }` — `size` is in **words, stored raw** (no growth-table rounding) and `size == 0` is the C's *no upper bound*; `unlimited(flags)`, `is_unlimited()`, `violates_floor(min_heap_words) -> bool` (the oracle's `size != 0 && size < min_heap_size` rule, single-sourced because the two call sites use different floors — `spawn_opt`'s own rounded `min_heap_size` vs `process_flag`'s `MIN_HEAP_SIZE(p)`; a `min_heap_size` set *after* a `max_heap_size` is deliberately not re-validated), and `verdict(usage) -> HeapLimitVerdict` (the **strict-`>`** comparison; a charge exactly equal to `size` is within).
- `MaxHeapUsage { heap_words, off_heap_binary_bytes }` — `heap_words` is the total heap **capacity** (nursery chain + mature, i.e. the oracle's `Total Heap Size`), **not** the occupied words; `charged_words(flags)` adds `ceil(off_heap_binary_bytes / size_of::<Eterm>())` only when `include_shared_binaries` is set, saturating rather than wrapping. [`NOTES.md` §max_heap.rs carries the rest of this bullet.]
- `HeapLimitVerdict { Within, Kill, Log }` — `Kill`: the host must **self-exit the process with the bare atom `killed`** (not `kill`, not an exception; untrappable by the victim, a trapping linked peer sees `{'EXIT', Pid, killed}`, a monitoring peer a `'DOWN' … killed`). `Log`: an `=ERROR REPORT====` with `Context: maximum heap size reached` after which the process **keeps running**. There is deliberately **no** `Raise` variant: the oracle has **no** exception path for this limit (`kill => false` is log-only, empirically), so a fabricated `system_limit` would contradict it. `is_breach()`.
- `Process` side (in `process.rs`): `set_max_heap_size`/`max_heap_size` (wholesale replacement — no validation here), `max_heap_usage`, `heap_limit_verdict(prospective_words)` (the pure prospective decision for a host admission door) / `current_heap_limit_verdict`, `max_heap_verdict`/`take_max_heap_verdict` (the latch), and the private `record_max_heap_verdict` run at the **tail** of `collect`, `collect_kind`, `ensure_capacity` and `grow_nursery` (and `collect_if_needed` through its `collect` call). [`NOTES.md` §max_heap.rs carries the rest of this bullet.]
### `dict.rs` — the per-process dictionary
- `Dict` (`Default`) backs `erlang:put/2`/`get/1`/`erase/1` (last put wins, `put` returns the replaced value) with `new()` (empty) / `with_atoms(Rc<AtomTable>)` and the never-panic GC pair `gather_roots`/`scatter_roots`. `None` is the C `THE_NON_VALUE` (the BIF layer maps it to `undefined`); keys — and, for `get_keys_for_value`, **values** — compare with `beam_term::compare::eq` (the C's `EQ`, `erl_utils.h:113`: structural `=:=`), so a *boxed* key matches a distinct-but-equal term (`put({a},1), get({a})` ⇒ `1`); atom names resolve through the `Rc<AtomTable>` handle (`new()` ⇒ empty table, whose unknown-name fallback is the raw atom index — the C's `EQ` for two immediates). [`NOTES.md` §dict.rs carries the rest of this bullet.]
### `fragments.rs` — saved BIF/NIF arguments
- `SavedArgs` (`Default`) — the saved BIF/NIF argument root list (the C `ErlSaveCallArgs`): `push`/`pop`, `as_slice`/`as_mut_slice`, `len`/`clear` plus the GC pair (the region of `Process::collect`'s root set after the dictionary, before the pending signals).
### `run_queue.rs` — the ready queue (four priority levels)
- `Priority { Max=0, High=1, Normal=2, Low=3 }` (`Copy + Ord + Hash`; `Default = Normal`); the derived `Ord` is the C *numeric* order (`Max < High < Normal < Low`), which is **NOT** scheduling precedence — precedence is `LEVELS = [Max, High, Normal, Low]` (highest-first); `index()/from_index(u8)` (the C `PRIORITY_*` value); `name()/from_name(&str)`.
- `RunQueue` — four per-priority FIFOs; `dequeue` serves the highest-priority non-empty level, FIFO within a level; `enqueue(pid)` ⇒ **normal** (`enqueue_with_priority` for the rest); `reprioritize(pid, Priority) -> bool` moves an already-queued pid to the tail of the new level (never double-enqueues, never inserts a non-queued pid) — the run-queue half of `Scheduler::set_priority`; `split_off_half(&mut self) -> Vec<ProcessId>` removes up to half the queue's pids (highest priority first, `dequeue` order) so a work-stealing victim keeps at least half (0/1 pids ⇒ empty) — the victim half of the SMP steal.
- **Fairness deviation (documented):** the C keeps MAX/HIGH dedicated but lets **NORMAL and LOW share one physical queue**, deferring LOW by `schedule_count` (`RESCHEDULE_LOW = 8`, `erl_process.h`); this crate uses **four physically distinct FIFOs**, so LOW runs only once MAX/HIGH/NORMAL are empty — the relative precedence is unchanged (LOW last), only the LOW/NORMAL interleaving ratio differs.
### `scheduler.rs` — the single-threaded scheduler loop + the engine seam
- `RunOutcome { Yield, Wait, Suspend, Exit(Eterm) }` — what happened in a reduction slice (`Exit(reason_term)` = the process terminated with that reason); `ProcessRunner { fn run(&mut self, pid: ProcessId, table: &mut ProcessTable, budget: u32) -> Result<RunOutcome> }` — **the engine seam** (`beam_engine` is NOT a dependency; `beam_rt`/`beam_engine` implement it over an `ExecutionContext`).
- `Scheduler` — `new()` defaults `DEFAULT_REDUCTIONS_PER_SLICE = 4000` (override `with_slice(u32)`), and optionally owns a `PortTable` (`with_ports`/`set_ports`/`take_ports`/`ports(_mut)`/`has_ports`; `new`/`with_slice` own none). Entry points: `enqueue`(⇒ normal)/`enqueue_with_priority`, `progress()/progress_mut()`, `set_priority(&mut self, table, pid, priority) -> Result<()>` (updates the PCB priority and, **iff** the pid is already queued at a different level, moves it to the new level's tail — the C `erts_set_process_priority` requeue; `TermNotFound` for an unknown pid leaves the queue untouched), `run_slice`/`run_ready`/`resume_woken` and the explicit `run_slice_with_ports`/`run_ready_with_ports` forms.
- A slice pops one pid, **services its pending signals** (schedule-in; a fatal signal can terminate the pid, in which case it runs zero reductions) and runs one slice: `Yield` ⇒ requeue at the tail of the process's **own** current priority; `Wait`/`Suspend` ⇒ leave the queue; `Exit(reason)` ⇒ terminate (through `terminate_with_ports` when a port table is owned, else the port-less `terminate`); afterwards (and on the empty-queue early return) it absorbs the table's wake list. `run_ready(…, max_slices: Option<u64>) -> Result<u64>` runs until the ready queue is empty or `max_slices` slices ran; `resume_woken(&mut self, table) -> usize` moves the table's wake list into the scheduler's own reusable `woken` scratch (`ProcessTable::drain_woken_into`, so neither buffer reallocates after warm-up) and enqueues each still-live `Runnable` pid not already queued **at its own priority** (also the hook `beam_rt` calls after a send made **outside** a slice).
- **Reduction accounting is delegated to the runner:** `ProcessRunner::run` receives `DEFAULT_REDUCTIONS_PER_SLICE` as its `budget` and owns the reduction count (the scheduler never reads or resets `Process::reductions`), so **pre-emption is cooperative** (see `../CONTEXT.md` Known Issues).
- **Shared slice helpers (the SMP reuse seam):** `pub(crate)` `slice_begin(pid, table) -> Result<bool>` (mark executing + apply the queued signals), `slice_end<F>(pid, table, outcome, enqueue)` (schedule-out), `run_one<R, F>(pid, table, runner, reductions, enqueue)` = `slice_begin` + one full-budget runner call + `slice_end`, `drain_woken_into<F>(table, enqueue)` (the owns-its-buffer form, kept for the SMP callers) and the capacity-retaining `drain_woken_scratch_into<F>(table, woken, enqueue)`/`resume_woken_scratch_into(run_queue, table, woken)`; the `*_with_ports` mirrors share private `*_inner` bodies. `run_slice`/`resume_woken` delegate to them, and the SMP pool calls the same helpers (splitting a slice into lock quanta) with a closure that **buffers** requeues instead of touching a queue.
- **Port-aware adoption and the `beam_rt` orchestration contract** (spawn ⇒ `spawn_default` + `enqueue`; a runner blocking on an empty receive sets `ProcessState::Waiting` **before** returning `RunOutcome::Wait`; a send inside a runner is absorbed at slice end, one outside a slice needs an explicit `resume_woken`; run ⇒ `run_ready(&mut table, &mut runner, None)`) are documented in full in the module rustdoc.
### `smp/` — the multi-scheduler (SMP) pool
The `Scheduler` counterpart for SMP: N scheduler threads over one shared process table, per-scheduler run queues + work stealing, the `ThreadProgress` barrier, the `TimerService` and the two `DirtyPool`s. Crate-root re-exports: `beam_process::{SchedulerPool, SchedulerConfig, SchedulerStats, SchedulerStat, SharedProcessTable}`. Full API surface, the **BINDING locking discipline** (three lock families, the buffer-requeues rule), the **bounded-quantum lock** rule (`run_locked_quanta`, `set_lock_quantum`) and the `unsafe impl Send/Sync` handoff live in **`smp/CONTEXT.md`**. `SchedulerPool::set_priority(pid, priority)` implements the same requeue as the single-threaded `Scheduler` (PCB update under the table lock, then an `O(schedulers)` search of the injector + every local queue, one queue lock at a time).
### `timer.rs` — the high-level timer service
- `TimerService` — one background thread over a deadline min-heap; `TimerRef { id, generation }` (`Copy`); `TimerSink: Send + Sync { fn timer_fired(&self, target: ProcessId, message: Eterm); }` — the seam the pool implements. It is the delivery **mechanism** only (one message to one `ProcessId` after a delay); the `erlang:send_after/3`, `start_timer/3` (`{timeout,Ref,Msg}` needs `make_ref`), `cancel_timer/1,2`, `read_timer/1`, `start_timer/4` and `receive ... after T` timeout-label semantics are BIF/engine-side (`beam_bifs`/`beam_rt`); `read_timer` and a hibernate state are absent here. **Message contract:** the stored message must be **thread-valid** — an immediate (small int/atom/pid) or a literal-area/interned term; a term resident in a per-process heap is a caller contract violation (needs an off-heap handle; documented follow-up).
### `dirty.rs` — the two dirty scheduler pools
- `DirtyKind { Cpu, Io }` (`ALL`, `name()` = `"dirty_cpu_scheduler"`/`"dirty_io_scheduler"`); `DirtyOutcome { Done, Reschedule(ProcessId), Deliver { target, message } }` — routing data the normal scheduler acts on (`Reschedule` re-enters the pid, `Deliver` delivers and wakes); `DirtyJob = Box<dyn FnOnce() -> DirtyOutcome + Send + 'static>` — a plain closure carrying **no** live heap data; `DirtyCompletionSink: Send + Sync { fn dirty_completed(&self, DirtyOutcome); }`; `DirtyPool` (`start(cpu, io)`, `set_sink`, `cpu_schedulers()`/`io_schedulers()`, `schedulers(kind)`, `submit(kind, job)`, `pending(kind)`, `shutdown()`, `join()`). A kind with **0 workers buffers** jobs (never drops on submit, discards at join); a panicking job does not kill the pool.
### `progress.rs` — thread progress (the cross-scheduler barrier)
- `ThreadProgress` (`generation`, `bump() -> u64`, `wait(u64)`, `safepoint() -> u64` = `bump`+`wait`, `managed_thread() -> ManagedThread`, `managed_count`, `set_waker`, `is_blocking`/`block`/`unblock`/`blocking_count`) — the real barrier; cheap to clone, and every clone shares the generation, the managed-thread registry and the blocking counter. `ManagedThread` is the per-thread slot a scheduler registers (`progress`, `update` = confirm the current generation, `is_active`/`set_active(bool)` — an inactive/parked thread is already at a safepoint and is excluded from the wait — `id`).
### `signal.rs` — exit signals, reasons and signal-message builders
- `SignalAtoms { exit, down, process, port, normal, kill, killed, noproc, system }` — the well-known atom indices used to build signal messages; `from_table(&mut AtomTable)` interns `'EXIT'`/`'DOWN'`/`process`/`port`/`normal`/`kill`/`killed`/`noproc`/`system`; `system` is the C's `am_system`, used as the `Message::from` immediate of a failed-by-name monitor DOWN (`erl_proc_sig_queue.c:4991`).
- `ReasonClass { Normal, Kill, Other }` + `SignalAtoms::classify(reason) -> ReasonClass`; `ExitFamily { Explicit, Linked }` — the C's signal op family (`ERTS_SIG_Q_OP_EXIT`/`ERTS_SIG_Q_OP_EXIT_LINKED`); `ExitSignal { from: ProcessId, reason: Eterm }` (`Copy`); `ExitPolicy { Terminate(Eterm), Trap, Ignore }` (`Trap` = deliver `{'EXIT', From, Reason}` as a message) and `exit_policy(reason: Eterm, trapping: bool, family: ExitFamily, atoms: &SignalAtoms) -> ExitPolicy`, the C's `handle_exit_signal` (`erl_proc_sig_queue.c:4740-4770`, `erl_proc_sig_queue.h:176-177`): `untrappable = family == ExitFamily::Explicit && class == ReasonClass::Kill`, then `!untrappable && trapping` ⇒ `Trap`; else `Normal` ⇒ `Ignore`; else `untrappable` ⇒ `Terminate(killed)`; else `Terminate(reason)`. So `kill` is untrappable and rewritten to `killed` **only** in the `Explicit` (`erlang:exit/2`) family, while a `Linked` link exit of reason `kill` **is** trappable (a trapping receiver gets `{'EXIT', From, kill}` and survives) and otherwise terminates with the reason **unchanged** (`kill`, never `killed`); `normal` is ignored by a non-trapping receiver in **both** families. The C's `ERTS_SIG_LNK_X_FLAG_NORMAL_KILLS` escape (a `normal` link exit terminating anyway) is deliberately **not** modelled, and a monitor `{'DOWN', …}` never consults this policy at all (`ptab.rs::deliver_down_message`). `ReceiveApplicability { Apply, Discard, Stop }` + `receive_applicability(signal: PendingSignal, trapping: bool, atoms: &SignalAtoms) -> ReceiveApplicability` — the **receive-time reading** of the propagation rule: `ExitPolicy::Trap ⇒ Apply`, `Ignore ⇒ Discard`, `Terminate ⇒ Stop`, and a `Down` is unconditional `Apply`. Pure, and derived from `exit_policy`, so a receive scan and the schedule-in path can never disagree (unit-tested over the whole `{normal,kill,other} × {Explicit,Linked} × trapping` matrix with the expectations themselves read from `exit_policy`).
- **Signal-message builders** (each allocates on the *receiving* process's heap; the full list is in the rustdoc): the exit pair `build_exit_message(heap, atoms, from: ProcessId, reason)` / `build_exit_message_term(heap, atoms, from: Eterm, reason)` (`{'EXIT', From, Reason}`; the `_term` form's `from` may be an external pid term); the DOWN family `build_down_message(heap, atoms, user_tag: Option<Eterm>, reference, pid, reason)` (`{'DOWN', Ref, process, Pid, Reason}`, or `{Tag, Ref, process, Pid, Reason}` when `user_tag` is `Some`) / `build_down_message_port(...)` (the `port`-**kind** form) / `build_down_message_remote(...)` (materialises the external-pid target on the same heap) and the fully general `build_down_message_term(heap, atoms, user_tag: Option<Eterm>, reference, kind: Atom, target: Eterm, reason)`. `kind` is the `{'DOWN', …}` 3rd-element **kind** atom (`process`/`port`), distinct from the caller's `user_tag` (which replaces the message's head atom).
### `signal_queue.rs` — the decoupled per-process pending-signal queue
A signal is *queued* on the receiver and applied later (the crate-level eager-vs-queued rule); its `reason` is copied into the receiver's own heap at enqueue time, so the queue is an in-heap sub-rootset. `PendingSignalKind { Exit, Down }`; `PendingSignal { Exit { from: ProcessId, reason: Eterm, family: ExitFamily }, Down { reference: MonitorRef, target: ProcessId, kind: MonitorKind, tag: Option<Eterm>, reason } }` (`Copy`) with the constructors `exit(from, reason, family)` / `down(…)` and `kind()`/`tag()`/`reason()` — an exit signal stores its `ExitFamily` **verbatim** (the queue applies no trap rule; `ptab.rs::apply_head_signal` reads the family back and consults `exit_policy` with it), and the `tag` is the caller's `monitor/3` user tag, carried so the deferred `{'DOWN', …}` materialises with the right head atom. `SignalQueue` (a `VecDeque<PendingSignal>`, `Default`) is the per-process FIFO (application order) plus the GC pair `gather_roots` (one word per queued signal's `reason`) / `scatter_roots`; monitor references are stored by value, not on the heap. **Ordering:** a total FIFO order per receiver (a single FIFO) — subsuming the C's per-`(sender, receiver)` order; **not** cross-ordered with the mailbox.

### `monitor.rs` — monitors and monitor references
- `RefAllocator` — the reference mint: a **zero-sized handle** onto the runtime's one process-wide local reference-id space (`beam_common::next_ref_id`), `new() -> RefAllocator` + `next() -> MonitorRef`. It holds **no counter of its own** (no start value, no band, no `u64` field), so every draw — this crate's monitors/aliases *and* `erlang:make_ref/0`, the NIF `make_ref`, timers, `seq_trace` and NIF resource terms — comes from one monotone source and two producers can never issue the same reference id (see `tests/reference_ids.rs`). `next()` stays total; the encodable bound (`MAX_SMALL`) is checked at `MonitorRef::to_eterm`, which is the one `SystemLimit` gate.
- `MonitorRef { id: u64 }` (`Copy + Eq + Hash`) — the id is a draw of that shared space. `from_id(id: u64) -> MonitorRef` is the one **non-mint** constructor: it names an **explicit, caller-derived** id (today the unnamed-ETS-table tid, whose id must be the table handle so the table-taking BIFs decode it back to that handle; also a deliberately colliding term in a regression test), draws nothing from the shared space and consumes nothing (`tests/reference_ids.rs::from_id_consumes_no_shared_id`), so its uniqueness is the caller's claim — a `from_id` id must never be one a live mint could hand out unless the caller is deliberately probing it. It is total and infallible; the encodable bound is still `to_eterm`'s. `to_eterm(self, heap) -> Result<Eterm>` builds the on-heap `Ref` thing through `beam_term`'s checked `write_internal_ref` (`Alloc` when the heap is full; `../DESIGN_DECISIONS.md`), `from_eterm(term) -> Result<MonitorRef>` is the reverse (parses the frozen `[header, node, serial, id]` ref thing, `BadArg` for anything else — the send path's destination→key step, with guard-chain parsing like `payload_is_down_for`). [`NOTES.md` §monitor.rs carries the rest of this bullet.]- `UnaliasMode { ExplicitUnalias, Demonitor, ReplyDemonitor }` (`Copy + Eq + Hash`) — the `{alias, Mode}` un-alias mode of `erlang:monitor/3`/`alias/1` (the C `ERTS_ML_STATE_ALIAS_*` flag values); the atom→mode parsing is the BIF layer's, so the enum is the frozen value the alias entry points take. `AliasEntry { owner: ProcessId, mode: UnaliasMode }` (`Copy`) — one `ProcessTable` `aliases` entry (`owner` is the process a message sent to the reference is delivered to); plain values only (not a GC root).
- `MonitorKind { Process, Port }` — `type_name() -> &'static str` (`"process"`/`"port"`) and `from_type_name(&str) -> Option<MonitorKind>` back the `erlang:monitor/2` type dispatch (any other type name ⇒ `None` ⇒ the caller's `badarg`, matching the oracle).
- `PortWatch { reference: MonitorRef, port: PortId }` (`Copy`) — the **outgoing** half of a port monitor, held in `Process::port_monitors`; plain values only (not a GC root).
- `Monitor { reference, target: ProcessId, kind }` (outgoing) / `MonitoredBy { reference, watcher: ProcessId, kind }` (incoming) — field sets **frozen** (constructed by struct literal from `beam_rt`, so no field may be added); the `monitor/3` user **tag** therefore lives in a `ProcessTable` side table, not here. `Monitors { entries: Vec<Monitor> }` — `push`, `remove(reference)`, `find(reference)`, `iter`, `drain`.
- `payload_is_down_for(payload: Eterm, reference: MonitorRef, down_atom: Atom) -> bool` — the guarded `{'DOWN', Ref, _, _, _}` shape test `demonitor_flush` scans mailboxes with (one `unsafe` block, no out-of-bounds read). The element-1 block must carry **both** `REF_SUBTAG` and the ref payload arity (the subtag alone is also worn by the C-layout arity-2 block, which has no id slot), and the id test is total/sign-safe (`u64::try_from(signed_value(word)).ok() == Some(reference.id())`), so a negative id word can never match a huge id.
### `ptab.rs` — the process/port table + name registry + signal/link/monitor hub
The single place that mutates ≥2 processes (mirrors the C ptab lock domain), using the crate-level **collect-then-apply worklist**; M1 single-threaded, so it holds `Process` values directly (`PortTable` lives in `port.rs`). The module rustdoc is authoritative for the full entry-point list (allocation/lookup, priority, the GC relocation-exemption pair, delivery, the local signal/link/monitor ops, the `*_with_tag`/`*_with_options` points, decoupled servicing, the `*_term`/`remote_*` forms, the distribution and process-death-observer seams, `node_down`/`port_closed`, the name registry, liveness/reason). Frozen shape and the contracts that must not be lost:
- `ProcessTable { slots, free, names: HashMap<Atom, ProcessId>, refs: RefAllocator` (a zero-sized handle onto the one shared local reference-id space, `beam_common::next_ref_id`), `atoms: SignalAtoms, ready: Vec<ProcessId>, remote_links, remote_monitors, remote_watchers, group_leaders, named_monitors: HashMap<MonitorRef, NamedTarget>, local_node: Option<Atom>, router: Option<Box<dyn DistSignalRouter>>, collection_gate: Option<Box<dyn CollectionGate>> }` (`Slot { serial: u64, process: Option<Process> }`; `NamedTarget { name: Atom, node: Atom }`). `ready` is the **wake list** (a delivery/signal pushes a woken pid; `drain_woken` returns **and** clears it, `drain_woken_into(out)` moves it into a caller-owned buffer while retaining both allocations, `woken` peeks without clearing); `router` is the distribution seam (`None` ⇒ record-only); `collection_gate` is the host collection-gate seam (`None` ⇒ no gate; `set_collection_gate`/`take_collection_gate`/`has_collection_gate` install/take/test it, and the private `declines_signal_collection(pid)` — a split borrow of `slots`/`collection_gate` — answers whether the host declines a relocating collection of that pid's heap, `false` with no gate or an unknown pid). `remote_watchers` is the **incoming** remote-monitor side table (`HashMap<ProcessId, Vec<RemoteWatcher>>`) and `group_leaders` the remote-capable group-leader store (`HashMap<ProcessId, PidTarget>`); both are keyed by the local pid, both are dropped by `terminate_into` (which routes one `DistSignal::MonitorExit` per drained watcher record, best-effort, before the dying heap is released), `remote_watchers` is also purged by `node_down` for a lost node, and neither adds a field to the frozen `Process`/`MonitoredBy` shapes. `alloc_pid` reuses a free slot and bumps its serial (`SystemLimit` on exhaustion); `take` bumps the serial **and** drops the wake entry.
  The **distributed-spawn reservation** surface: `reserve_remote(RemotePid) -> Result<Reservation>` (claims the local pid identity an inbound `DOP_SPAWN_REQUEST` will occupy; the pid's node must be the table's `local_node` — a wrong node **or an uninstalled one** is `badarg`), `reserve_identity(ProcessId)` (the node-less spelling; one shared claim table, so a number can never be claimed twice), `spawn_reserved(Reservation, HeapPolicy) -> Result<ProcessId>` (installs a `Process::with_policy` PCB at **exactly** `reservation.pid()`, which is what the spawn reply carries, consuming the claim; every failure path returns the number to the reuse list), `cancel_reservation(Reservation) -> Result<()>` (the aborted-request rollback; a stale handle is `badarg`, so a double cancel cannot duplicate a `free` entry), plus the `reserved_count`/`is_reserved`/`reserved_pids`/`free_count`/`slot_count` diagnostics. `alloc_pid` never hands out a claimed number (it materialises a slot for the claim and skips it); `insert` drops a claim at its number, so a squatter makes a later `spawn_reserved` a typed `badarg` instead of a clobber. `ProcessTable` carries a private `reserved: Reservations`. Failure modes: pid space ⇒ `system_limit`, everything else ⇒ `badarg`.
- `link(a, b)` has `a`/`b` set semantics and a **non-live `b`** with a live `a` records no link and applies a `noproc` exit signal from `b` to `a` — a trapping `a` is handed `{'EXIT', b, noproc}` and a non-trapping one is terminated with the bare atom `noproc` (the oracle *raises* `error:noproc`; signalled here as the bare reason — a documented approximation owned by `beam_rt`'s link floor); `TermNotFound` is returned only when the caller `a` is unknown (`link_term`'s local branch inherits this).
- `terminate`/`terminate_with_ports` are **best-effort per peer**: the pid is reclaimed first, so a per-peer signalling failure (a local signal that cannot be queued, a remote `route` transport error) is dropped-and-logged (ERTS's `erts_dsig_drop`) and the cascade continues — the observer and the port-monitor cleanup always run; `TermNotFound` for an unknown pid is the only `Err` on this path. `terminate_with_ports` threads the port table so a dying process's outgoing `port_monitors` also remove their matching **incoming** `PortMonitor` entries (`terminate` is its no-ports delegation).
- `monitor(watcher, target: ProcessId, kind) -> Result<MonitorRef>` — a **non-live** target with a live watcher yields `Ok(ref)` plus an immediate `{'DOWN', Ref, process, Target, noproc}` in the watcher's mailbox (the oracle's `noproc`); `demonitor`/`demonitor_flush` (`flush` also removes a queued `{'DOWN', …}` for that reference — `erlang:demonitor(Ref,[flush])`). `monitor_named(watcher, name: Atom, node: Atom, kind)` + `set_local_node`/`local_node` implement `erlang:monitor(process, Name)`: the DOWN target is the 2-tuple `{Name, node}`; with no local node installed ⇒ typed `unsupported`. `monitor_term` dispatches a pid → `monitor`, an atom name → `monitor_named`, an external pid → the remote record + route; a **port term** with `MonitorKind::Process` ⇒ `BadArg` (oracle) and with `MonitorKind::Port` ⇒ typed `unsupported` (that entry point has no `&mut PortTable` — use `monitor_port_term`); anything else ⇒ `BadArg`. A **target's death resolves both halves** — `terminate_into` also removes the watcher's outgoing `Monitor`, so `process_info(W, monitors)` stops listing it and a later `demonitor(Ref)` reports it gone (the `{Name, node}` descriptor of a named monitor survives until its DOWN is materialised, so the DOWN still carries the name). `monitor_port(_term)`/`demonitor_port` are the port-track forms (`erlang:monitor(port, Port)`).
- **`erlang:monitor/3` user tag (additive):** the `*_with_tag` points (`monitor_with_tag`, `monitor_named_with_tag`, `monitor_port_with_tag`, `monitor_port_term_with_tag`, `monitor_term_with_tag`) take a trailing `tag: Option<Eterm>` (the no-tag methods delegate with `None`); a `Some(tag)` makes the delivered message `{Tag, Ref, Kind, Target, Reason}` instead of `{'DOWN', Ref, Kind, Target, Reason}` — the tag replaces the head atom only. [`NOTES.md` §ptab.rs carries the rest of this bullet.]
- **Reference aliases (`erlang:monitor/3` `{alias, Mode}`, `erlang:alias/1`, `erlang:unalias/1`):** a `MonitorRef` may name an **alias** — a send destination that resolves to its owner — held in the private `aliases: HashMap<MonitorRef, AliasEntry>` side table (next to `tags`; nothing else stores it). `MonitorOptions { tag, alias }` plus the `*_with_options` points (`monitor_with_options`, `monitor_named_with_options`, `monitor_port_with_options`, `monitor_port_term_with_options`, `monitor_term_with_options`) register the alias; the existing `*_with_tag` methods delegate with `alias: None`, so their signatures are unchanged. [`NOTES.md` §ptab.rs carries the rest of this bullet.]
- `service_signals(pid) -> Result<()>` drains + applies the pid's pending-signal queue in FIFO order, cascading to any process those signals affect (the scheduler calls it at schedule-in); a pid whose queue is **empty** (or unknown) returns immediately — nothing to apply, and the worklist's only growth source is a signal read off a queue, so the cascade cannot grow from nothing — which keeps the common per-schedule-in case free of the worklist's heap allocation; `service_signals_with_ports(&mut PortTable, pid)` threads the port table so such a cascade also cleans a terminated process's incoming port monitors (the plain form delegates with no ports). [`NOTES.md` §ptab.rs carries the rest of this bullet.]
- `node_down(node: Eterm, reason)` resolves + purges every remote relationship with `node` (a `{'DOWN', …}` per monitor, a trapped/fatal `{'EXIT', …}` per link), in three steps: outgoing monitors → outgoing links → the record purge. The reason is the caller's immediate — the C's `am_noconnection` (`dist.c:320`, `erl_proc_sig_queue.c:2571-2573`) — signalled in the **link** family, so a trapping peer traps `{'EXIT', RemotePid, noconnection}` and a non-trapping one dies with exactly `noconnection` (never rewritten to `killed`). The purge covers **all three** record directions — the outgoing links (`remote_links`), the outgoing monitors (`remote_monitors`) and the **incoming watcher records** (`remote_watchers`) whose `RemoteWatcher.watcher` names the lost node — because a monitor a process on a dead node holds on a local process can never be resolved (no `DOP_MONITOR_P_EXIT` can arrive) nor demonitored (no `DOP_DEMONITOR_P` either), so keeping the record would leak it forever and a re-connect must not resurrect it; other nodes' records are untouched, and each step collects its snapshot before applying (never mutating while iterating), dropping the now-empty inner `Vec`s and map entries. This mirrors the C's connection-down cleanup, which walks the dead node's `ErtsMonLnkDist` tables with `foreach_delete` iterators and deletes both directions (`dist.c:379-423`, `ERTS_CML_CLEANUP_STATE_LINKS`/`_MONITORS`/`_ONAME_MONITORS`); `port_closed(&mut PortTable, port, reason)` drains the port's owner/links/monitors, delivers the `{'DOWN', Ref, port, Port, Reason}` / `{'EXIT', Port, Reason}` shapes, and terminates any non-trapping linked peer through `terminate_with_ports` so that peer's own port monitors are cleaned too. This is the **port-died** direction; the reverse (a **watcher process** dies) is handled in `terminate_into` by draining `Process::port_monitors` and calling `PortTable::demonitor` on the matching incoming entries — but only when a port table was threaded in.
- `register(name, pid)` is `BadArg` for a taken name **or a non-live pid**; `unregister(name)` is `BadArg` for an unknown name; `whereis(name)`/`registered()`/`name_of(pid) -> Option<Atom>` (the reverse lookup a `process_info(P, registered_name)` BIF needs; live-only); `is_process_alive(pid) -> bool` is table membership and `exit_reason(pid) -> Result<Option<Eterm>>` is live-only. `ExitEffect { Terminated, Trapped, Ignored }` — the outcome of `apply_exit_signal` (target terminated / got a `{'EXIT'}` message / ignored it).
- **Eager-vs-queued rule** (stated in full at crate level): a signalling operation **enqueues** a `PendingSignal` on the receiver — never inline; servicing is at the receiver's schedule-in (`service_signals`, called by `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is not the currently `Running` process (ERTS's early signal handling), and `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. **Every exit signal carries an `ExitFamily`** (the private `enqueue_exit_signal(to, from, reason, family, src)` takes it): `ExitFamily::Explicit` for the `erlang:exit/2` family (`apply_exit_signal` — its signature stays family-free and it always signals explicitly — plus `send_exit`/`send_exit_term`; a `noproc` is family-independent, being neither `kill` nor `normal`) and for a signal drained off the queue (`apply_head_signal` re-reads the family the queue stored); `ExitFamily::Linked` for the local link cascade (`terminate_into`'s link loop), `node_down` step 2 and `port_closed` step 2. A **remote** or **port** signal bypasses the queue, so `node_down`/`port_closed` materialise it straight into the mailbox.
- **Signal-build exhaustion:** a signal the receiver's full nursery refuses is routed into a heap fragment when the receiver's relocating collection is **declined** — the crate-owned `Process::has_unpublished_roots` (**relocation-exempt** or currently **`Running`**) OR the host's `CollectionGate` (consulted first at every signal site; no collection, no growth, no relocation either way), at **both** refusal sites — the apply-time message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) and the enqueue-time reason copy (`copy_reason_onto` → `enqueue_down_signal`'s `deliver_down_fragment` / `enqueue_exit_signal`'s `deliver_exit_fragment`, which build the message the queue would have materialised straight from the enqueue [`NOTES.md` §ptab.rs carries the rest of this bullet.]
- **A remote (inbound) receipt reason is materialised on the recipient before it is embedded.** `apply_remote_exit_signal`'s `ExitPolicy::Trap` arm and `remote_monitor_down` build one `OffHeapTable::new()` per call (a wire payload carries no off-heap handles) and pass it as `src: Option<&OffHeapTable>` to `enqueue_remote_exit_message`/`enqueue_remote_down_message`, which forward it straight to `build_signal_message` — the **one** home of the rule: a **non-immediate** reason with a source table is never copied and then reused across a collection: the payload is built around it on a `SIGNAL_SCRATCH_WORDS` scratch `Heap` (whose words cannot move with the recipient's) and the **whole** graph is copied onto the recipient's own heap in one step (`copy_reason_onto`, whose collect-grow-retry reads only that scratch arena and the caller's table), the enqueue following immediately, so nothing the build embeds lives in the recipient's heap until the copy returns; when that heap refuses (declined collection, or a genuine `AllocKind::Heap`/`Message` ceiling) the whole payload goes into a heap fragment (`enqueue_fragment_payload`) from the same source table. A reason decoded off the host's per-drain dispatch arena (`beam_rt` resets its `dispatch_heap` — `dist/node.rs::dispatch_inbound`) therefore never reaches a mailbox by pointer. An **immediate** is embedded verbatim (never copied, never a collection); `node_down` passes `None` because its `noconnection` reason is an immediate by contract. Builders share one `wake`/`self.ready.push` tail.
### `reserve.rs` — the distributed-spawn reservation seam
- `Reservations` (per-table claim store: a fresh-instance tag from a static atomic, a monotone reservation id with a checked add, the claimed identities by id, and the reverse number index) with `claim`/`validate`/`release`/`release_number`/`is_reserved`/`pids`/`len`/`is_empty`; `Reservation { id(), pid(), number(), serial() }` is a `Copy` handle carrying its issuing table's tag, so a **foreign**-table handle is `badarg` even when id spaces collide; `pub(crate) check_identity` (`SystemLimit` past `MAX_PROCESS_NUMBER`/`MAX_PROCESS_SERIAL`) and `check_local_node` (`BadArg` when unset or different).
- Plain values: no term, no heap, no GC root, no `unsafe`, `Rc`-free and `Send + Sync` (pinned), so `SharedProcessTable`'s `unsafe impl Send/Sync` keeps holding.
- `release` is the **single** release funnel, and `ProcessTable::release_reserved_number` is the only place a number returns to the reuse list — at most once and only for an existing empty slot, so no number beyond the table's end is materialised by a claim.
- No `Drop`: a reservation is explicitly consumed (`spawn_reserved`) or cancelled (`cancel_reservation`); the guaranteed property is that a stale/consumed/cancelled/foreign handle can never install a process and never leaks a pid number or a slot.
- **Honest C premise (stated in the module docs):** `erts/emulator/beam/dist.c` (`DOP_SPAWN_REQUEST` receipt `:2919-3025`, `erts_dsig_send_spawn_reply` `:1882-1900`, `DOP_SPAWN_REPLY` receipt `:3033-3120`) and `erl_process.c` pre-reserve **no** pid on this path — the executing node allocates the pid inside `erl_create_process` and reports `p->common.id`, so this seam is a Rust-side split-creation construct reproducing only the C's `badarg`/`system_limit` vocabulary. The reply-path contract (`{spawn_reply, Ref, To, Flags, From}` built from the reservation's pid) is documented there.
### `exit_observer.rs` — the process-death observer seam
The host hook for per-process resources this crate does not own (the **ETS tables a pid owns** are the motivating case). Mirrors the `DistSignalRouter` pattern: a trait object on the table, implemented downstream, so the table stays free of any dependency on the observing subsystem; with **no** observer installed (`None`) behaviour is unchanged.
- `ProcessExitObserver { fn process_exited(&mut self, exit: &ProcessExit<'_>); }` — called **exactly once per death** from `terminate_into`, after the death has been propagated (links/monitors signalled **best-effort** — a peer that cannot be signalled is dropped-and-logged, never an abort, so this hook always runs) and **before** `drop(process)` (so `reason`, which may live in the dying heap, is still valid). No `Send` bound (consistent with `router`).
- `ProcessExit<'a>` — the payload, **private fields + read-only accessors**, built only by the finalizer: `pid: ProcessId` (the key an observer uses to release its own per-pid state; an immediate ⇒ retainable), `reason: Eterm` (the exit reason exactly as received; may live in the dying heap, so an observer that retains it must copy it), `name: Option<Atom>` (the registered name, captured **before** the registry entry is dropped; without it the registration would be unobservable), `port_monitors: &'a [PortWatch]` (the drained outgoing port watches; plain values ⇒ heap-independent).
- **Failure policy:** an absent observer is a no-op; a **panicking** observer is contained with `std::panic::catch_unwind(AssertUnwindSafe(...))` (the observer gets only an immutable payload and holds no reference to the table, so a panic cannot half-update the table — only the observer's own state), reported via `beam_common::beam_error!`, and termination still completes. Implementations should be cheap (they run on the finalizing scheduler thread) and prefer returning over panicking for expected conditions.
### `remote.rs` — remote (external-node) links and monitors
The **local record** of a process's relationships with processes on other nodes; the wire format is `beam_dist`'s, reached through a trait seam (this crate never depends on `beam_dist`).
- `RemotePid { node: Eterm, number: u32, serial: u32, creation: u32 }` (`Copy`) — a decomposed external pid (the `[header, node, creation, data]` thing), holding no boxed pointer into another heap; `from_eterm(term) -> Result<RemotePid>` (`BadArg` unless an external pid), `to_eterm(self, &mut Heap)`. `RemoteRef { node: Eterm, ids: [u32; MAX_REF_IDS], n_ids: u8, creation: u32 }` (`Copy`) — the mirror decomposition of an **external reference** (a peer-minted wire `Ref`); `from_eterm`/`to_eterm` plus `node`/`ids`/`creation` accessors; all-immediate, never a GC root (`BadArg` unless a well-formed external ref whose id count fits its block). `RemoteWatcherRef { Local(MonitorRef), Remote(RemoteRef) }` (`Copy`) — the all-immediate reference identity a `RemoteWatcher` is keyed by; the two variants never collapse. `PidTarget { Local(ProcessId), Remote(RemotePid) }` — `from_eterm` (external ⇒ `Remote`, internal ⇒ `Local`, else `BadArg`). `RemoteMonitor { reference: MonitorRef, remote: RemotePid, kind: MonitorKind }` — an outgoing monitor on a remote process/port. `RemoteWatcher { reference: RemoteWatcherRef, watcher: RemotePid, kind: MonitorKind }` — the **incoming** record an inbound `DOP_MONITOR_P` installs.
- `DistSignal { Link { from, to }, Unlink { from, to }, Monitor { watcher, target, reference, kind }, Demonitor { watcher, target, reference }, Exit { from, to, reason }, Exit2 { from, to, reason }, MonitorExit { watched, watcher, reference: RemoteWatcherRef, reason } }` — the control signal the runtime routes to the remote node. `Exit` is a **link** exit → `{DOP_EXIT, From, To, Reason}` → `Dop::Exit`; `Exit2` is `erlang:exit/2` → `{DOP_EXIT2, From, To, Reason}` → `Dop::Exit2` (distinct opcodes with distinct receipt semantics); `MonitorExit` is a watched local process's death → `{DOP_MONITOR_P_EXIT, Watched(local), Watcher(remote), Ref, Reason}` (the C's `erts_dsig_send_m_exit`, `dist.c:1497-1519`) — **watched first**, the reverse of the monitor family, with the reference in the spelling the watcher record carries (`RemoteWatcherRef`); the full `DOP_*` mapping is documented on the module.
- `DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()>; }` — **the distribution seam**: implemented downstream (`beam_rt`) over `beam_dist`; `route` must serialise the signal **synchronously** (`reason` may live in the signaller's heap, which the caller may drop right after). Its transport error propagates out of the relationship ops (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`node_down`), but **not** out of a dying process's termination (the remote step of `terminate_into` drops-and-logs a failed `route`). The table's remote records (`remote_links`/`remote_monitors`) and `set_dist_router`/`has_dist_router` are on `ptab.rs`. **This seam is OUTBOUND only** (local → remote): it never consumes a control message. [`NOTES.md` §remote.rs carries the rest of this bullet.]
### `port.rs` — the port-id table + ownership / link / monitor surface
`PortTable` is the number table the C keeps alongside the pid table, extended with the relationships a dying port must resolve; port *behaviour* (driver, scheduling, read path) is `beam_io`'s. The crate-root re-export keeps `beam_process::PortTable` resolving here.
- `PortMonitor { reference: MonitorRef, watcher: ProcessId }` — a monitor placed on a port. `PortClose { owner: Option<ProcessId>, links: Vec<ProcessId>, monitors: Vec<PortMonitor> }` — what `close` releases.
- `PortTable { slots: Vec<bool>, free, owners, links, monitors }` — `alloc() -> Result<PortId>` (`SystemLimit` on exhaustion), `alloc_owned(owner)`, `release(PortId)` (frees the number + drops every relationship), `close(PortId) -> Result<PortClose>` (frees the number, returns **and clears** owner/links/monitors; unknown id ⇒ `BadArg`), plus the ownership (`owner`/`set_owner` — unknown id ⇒ `BadArg` — /`clear_owner`), links (`link` — deduped, `false` if already linked — /`unlink`/`links`) and monitors (`monitor`/`demonitor`/`monitors`) accessors. Every relationship mutation on an unallocated id returns `BeamError::BadArg`; `ProcessTable::port_closed` is the one-call orchestrator resolving a closing port's relationships.

## Notes for Agents (module level)
The module-level agent notes — the GC root set, the `Registers`/FR hand-off, PCB/heap address stability,
pre-emption as the runner's obligation, the split borrows, the SMP `!Send` workaround and its six causes,
and the oracle-probe rule — are stated in full in `NOTES.md` §module-notes.
- **Who can mutate a published root array (length vs contents).** The *length* of `Registers::stack` is changed by exactly one accessor — `Registers::stack_mut()` (`registers.rs:226`) → `Stack::{push,pop,clear,truncate}` — and **no production code in this crate calls it** (only `registers.rs`'s own tests and `process.rs`'s collection tests); filling it is the host's publish step. *Contents* are rewritten in place by `Process::run_rooted_collection`'s `self.regs.scatter_roots(&roots[..reg_words], x_live)` (`process.rs:1825`), which is length-preserving and slot-exact (`registers.rs:261-285`: x prefix, then `stack.len()` words, then the extra-root tail, each `min`-clamped and the uncovered tail left untouched).
- **A parked-but-not-exempt process IS a legal relocation target.** `has_unpublished_roots()` is `relocation_exempt || state == Running` only, so a `Waiting`/`Runnable` pid whose roots the host published is *not* gated: another process's `ProcessTable::deliver` (`ptab.rs:1119`) or a signal builder (`grow_receiver_for_signal`, `ptab.rs:206`) can collect its heap and rewrite `regs` (`x`, `stack`, `extra_roots`) **in place, with the lengths unchanged**, while the host's own `RootSet` copies stay at their pre-collection (from-space) words. The host must therefore read the relocated words back out of `Process::registers()` at resume; a length check (`relocated_stack.len() == stack.len() + fr_count`) cannot catch a write-back of its own stale copies — that shows up later as a dangling term (e.g. a `list::car` read into the evacuated from-space), not as a mismatch.
- **No fragment is ever pushed on the Erlang stack.** The C's message-fragment-on-stack trick has no counterpart here: the exhaustion route builds a `beam_message::HeapFragment` owned by the enqueued `Message` (`ptab.rs:330-355`), so a signal/delivery between a publish and a resume cannot change the published stack length.
## Notes for Agents — the GC relocation seam inventory (what does NOT exist)
- **No caller-supplied extra-root set beyond `Registers::extra_roots`.** `Process::run_rooted_collection` (`process.rs:1781`) is **private** and takes the collection *action* (`F: FnOnce(&mut AnyCollector, &mut [Eterm]) -> Result<Collection>`), not a roots provider; the root list is fixed (regs → each message's payload/from/token → dict → saved args → signals) and the only host contribution is the `Registers::extra_roots` tail (`registers.rs:250-256`, scattered back at `:261-285`). There is **no** `collect_with` / roots-provider trait / mover-or-forwarding callback / post-collection fixup anywhere in this crate.
- **The root word list is the only mover interface.** `beam_gc`'s `copy::collect(from, to, roots: &mut [Eterm])` (`beam_gc/src/copy.rs:489`) rewrites the root words **in place** and leaves a word pointing outside the evacuated range untouched, so a host term is relocatable only by putting its *word* in the root slice — an interior pointer, a `*mut Eterm`, or a Rust-local copy stays stale (the tests pin exactly that: `tests/remote_reason_copy.rs:504-521`, `tests/off_heap_reachability.rs:577-581`).
- `Process::copy_into_heap` (`process.rs:1298`) is `pub(crate)`: a host cannot ask the PCB to copy a foreign term onto a process heap; it must drive `Process::heap_mut()`/`heap_and_mailbox_mut()` (and `heap_and_off_heap_mut()`) plus `beam_message`'s copy engine itself.
