# `beam_process/src` — the module layer (20 modules + `smp/`)

## Intent
One routing node for the modules of the `beam_process` crate. The **crate-level contracts** — Intent,
the frozen-seam overview, Constraints, Test Strategy, Handoffs, Known Issues — live in
`../CONTEXT.md`; read that first.

Each `src/<module>.rs`'s **top-of-file `//!` rustdoc plus its per-item `///` docs is authoritative for
its complete method list and detailed contracts**. This node records the *frozen* API surface a
dependent designs against: the seam types and shapes, the constants, the entry points dependents call,
and the behavioural caveats that must not be lost. Everything here is re-exported at the crate root and
via `beam_process::prelude::*`.

The cross-module binding rules (eager-vs-queued signalling, the collect-then-apply worklist, the
split-borrow rule, the `from`-is-immediate producer rule, the exhaustion policy) are stated **once** in
`../CONTEXT.md` and cited below.

## API Surface (FROZEN — dependents route here)
### `pid.rs` — process/port identity (bit-exact with `beam_term::immediate`)
- `ProcessId { number: u64, serial: u64 }` (`Copy + Eq + Hash + Ord + Debug`) — `to_eterm() -> Eterm` = `make_internal_pid(make_pid_data(serial, number))`; `from_eterm(Eterm) -> Result<ProcessId>` is `BadArg` unless an internal pid; `is_process(Eterm)`.
- `PortId { number: u64 }` — same shape via `make_internal_port`/`is_internal_port`.
- Limits: `MAX_PROCESS_NUMBER = (1 << 28) - 1` (`PID_NUM_SIZE`); `MAX_PROCESS_SERIAL = 2^32 - 1` (`PID_SER_SIZE`).
### `registers.rs` — the root-set containers (x-register file + Erlang stack + host-published extra roots)
Honors the crate-layer root-set contract: `x_reg_array[0..Live)` **plus the whole stack**, no frame liveness maps; `MAX_REG = 1024` (`erl_vm.h`), `MAX_ARG = 255`.
- `XRegs` (boxed `[Eterm; MAX_REG]` + `live`; `new` = all `NIL`, `live == 0`), `Stack` (`Vec<Eterm>`), `Registers { x, stack, extra_roots }` with the GC pair `gather_roots(&self, out: &mut Vec<Eterm>) -> usize` (appends `x[0..live)`, then every stack word, then every extra root; returns the `x_live` split point) / `scatter_roots(&mut self, roots, x_live)` (writes the first `x_live` back into `x`, the next `stack.len()` into the stack, the remainder into `extra_roots`; total — a mismatched short slice leaves the uncovered tail untouched, never panics).
- **`extra_roots: Vec<Eterm>`** — the one host-published extension of the frozen root shape: terms a host holds **outside** `x`/`stack` but that must survive a relocation (the motivating case is a parked engine `Machine`'s live pending-exception reason term while the process waits). Accessors `extra_roots() -> &[Eterm]` / `extra_roots_mut() -> &mut Vec<Eterm>` (a mutable container, not a by-value setter: the host pushes on suspend and clears on resume, with terms resident across any number of collections in between); empty in `new()`. `Process::run_rooted_collection` hands `scatter_roots` exactly the register prefix it gathered, so the extra roots ride along with `x`/stack automatically.
### `process.rs` — the process control block (PCB)
- `ProcessState { Runnable, Running, Waiting, Suspended, Exiting, Terminated }` (`Copy`); `DeliverOutcome { Enqueued, Woke }` (`Copy + Eq`, `woke() -> bool`) — `Enqueued` = recipient not blocked, `Woke` = it was blocked (`Waiting`/`Suspended`) and is now `Runnable`; `ProcessFlags` — a `u32` bitset (no `bitflags` dep) over `trap_exit`, `system`, `in_run_queue`, `garbage_collecting`, `active`, `sensitive` (`bits()/from_bits()` + per-flag get/set).
- `Process` fields (shape frozen): `pid`, `state`, `flags`, `priority`, `save_calls: u16`, `collector: beam_gc::AnyCollector`, `relocation_exempt: bool`, `off_heap: beam_message::OffHeapTable` (the **persistent** off-heap table — a queued signal's reason objects and a host's moved-fragment objects; the send path stages through its own fresh table, never this one), `owned_binaries: beam_gc::OffHeap` + `owned_binary_slots: usize` + `dead_binaries: Vec<usize>`, `mailbox: beam_message::Queue`, `regs: Registers`, `dict: Dict`, `saved_args: SavedArgs`, `signals: SignalQueue`, `reductions: u64`, `links: Links`, `monitors: Monitors` (outgoing), `monitored_by: Vec<MonitoredBy>` (incoming), `port_monitors: Vec<PortWatch>` (outgoing port watches), `exit_reason: Option<Eterm>`.
- `collector` resolves its mature strategy from the spawn policy — the copying space below `beam_gc::IMMIX_BREAK_EVEN_WORDS`, the mark-region (GenImmix) space at/above it (a default policy resolves below it); `new(pid)`/`with_policy(pid, policy)`/`with_policy_and_priority(pid, policy, Priority)` construct it, the last the **spawn-at-priority** form (a runtime composes `alloc_pid` + it + `ProcessTable::insert`, so a child is born at its level, not Normal).
- Contracts: `heap()/heap_mut()` is the **young** mutator heap; `wake(&mut self) -> bool` (`Waiting`/`Suspended` ⇒ `Runnable` + `true` — resume-on-send); `status_atom`/`status` map the state (with `garbage_collecting` layered over it) to the oracle's `process_info(P, status)` atoms `"running"`/`"runnable"`/`"waiting"`/`"suspended"`/`"exiting"`, `None` for `Terminated` (a dead pid answers `undefined`; the BIF layer supplies that); **no receive scan position is stored on `Process`** — the mailbox is a pure FIFO and a `QueueCursor` is a transient caller-local value (only `ProcessTable::demonitor_flush` drives one, re-derived per removal).
- **Owned off-heap binaries** — the process's second, **process-owned** `beam_gc::OffHeap`, distinct from the message-transit `off_heap` (never swept): one slot per payload (the legacy `MSO(p)` invariant — a duplicate registration returns the existing slot and drops the surplus handle), the readers expose the live payload bytes (the `system_info` memory hook), `declare_off_heap_binary_dead(slot)` is the **provable-death** signal, and `sweep_off_heap_binaries()` (**crate-driven** — the last step of every `run_rooted_collection`, releasing exactly the declared-dead entries) / `retain_off_heap_binaries(is_live)` (the caller-predicate form) are the sweeps; slots are stable for the process's lifetime (a released slot answers `None` and is never reused). Liveness gap: `../CONTEXT.md` Known Issues.
- **Split borrows** — the only two `*_mut` pairs with a real caller need; both destructure `self` into two disjoint `&mut` fields in safe Rust (compiler-proven, no raw pointer) and must not be joined into a combined raw-pointer accessor (the crate-level split-borrow rule): `heap_and_off_heap_mut()` (young heap + off-heap table) drives `beam_message::Fragments::move_into`, the only way to move a **fragmented** payload onto the heap; `heap_and_mailbox_mut()` (young heap + mailbox) drives `beam_message::send_fragmented`.
- **Delivery and collection:** `deliver(from: Eterm, term: Eterm, src_off_heap: &OffHeapTable) -> Result<DeliverOutcome>` copies `term` into the young heap **through a fresh per-send staging `OffHeapTable`** (drained into the resulting `Message`; the persistent `off_heap` is never touched, so a send cannot steal a queued signal's off-heap handles), enqueues then `wake()`s (`deliver_simple` is the no-off-heap form, `receive(pred)` delegates to `beam_message::receive`); `collector() -> &beam_gc::AnyCollector` (`kind()`/`mature_choice()` name the strategy, the mature generation is read through `mature_capacity_words`/`mature_used_words`/`mature_available_words`/`mature_base`/`mature_contains`, while `young`/`stats`/`minor_gcs`/`policy`/`should_collect`/`heap_used_words`/`collect_if_needed` are strategy-agnostic); `collect() -> Result<Collection>` gathers the root set, runs the collector and scatters back, `ensure_capacity(need_words) -> Result<Collection>` is the on-demand-growth sibling (collect once, then grow the nursery to the smallest curated size covering the request; a fail-fast typed `AllocKind::Heap` when the policy's ceiling makes it unreachable), and both route through one shared `run_rooted_collection` that writes every root region back even when the collection action returned `Err` and ends with `sweep_off_heap_binaries()`; `grow_nursery(need_words) -> Result<usize>` is the **no-relocation** growth passthrough (forwarded straight to `AnyCollector::grow_nursery`, never through `run_rooted_collection`): it retains the space it replaces (the nursery becomes a chain — `young_space_count` grows, `young().capacity_words()` grows), moves no live term and runs no collection (`minor_gcs` unchanged), returns the new young capacity in words and yields the typed `BeamError::Alloc` when the policy's ceiling cannot reach the request. **A delivery never collects or grows a receiver whose relocating collection is declined** — the crate-owned `has_unpublished_roots` predicate or the host's installed `CollectionGate`: `deliver` (and the `ptab.rs` signal builders) return the raw `AllocKind::Heap`/`AllocKind::Message` refusal **unchanged** — no collection, no growth, no retry — which is exactly the signal the host's heap-fragment fallback keys on, so the payload is still delivered (fragment-resident) without a heap word moving. `collect`/`ensure_capacity`/`collect_if_needed` are the **host admission points** and are **not** gated by `has_unpublished_roots` (the host publishes the roots *before* calling them); they are gated only by the explicit `relocation_exempt` flag.
- Each queued message contributes **three** roots — `payload()`, `from()`, `token()` — all written back into the re-installed envelope (`Message::with_payload` / `set_from` / `set_token`), so the message keeps its **whole envelope** (`from`, `token`, off-heap handles, refc binaries, node entries and — for an oversized payload that lives *in* them — its `Fragments` chain); a queued payload referencing an off-heap refc binary therefore stays alive across the collection (a fragment-resident payload is outside every evacuated range).
- **Relocation exemption:** `set_relocation_exempt`/`is_relocation_exempt` (default `false`) — a per-`Process` flag for a host holding live terms from this process's young heap in Rust locals / nested-`Machine` registers that are **not** in the crate root set. While exempt: `deliver` surfaces the raw refusal; `collect`/`ensure_capacity` refuse with the typed `error::relocation_exempt(what)` raise (a `BeamError::Raise` whose reason atom is `relocation_exempt: <what>`); `collect_if_needed` answers `Ok(false)`; `run_rooted_collection` is unreachable from those three. `grow_nursery` is **not** gated by the flag (it relocates nothing, so it is legal for an exempt process). Opt-in per process, not a global valve. The exemption is **one of the two** cases of `has_unpublished_roots() -> bool`, the crate-owned half of the **relocation-decline gate** every delivery-driven collect/grow site consults (`Process::deliver` and every `ptab.rs` signal site: `grow_receiver_for_signal`, `build_signal_message`, `copy_reason_onto`, `deliver_head_signal`, the `enqueue_exit_signal`/`enqueue_down_signal` pair, and the `deliver_noproc_down`/`deliver_named_noproc_down`/`enqueue_remote_down_message`/`enqueue_remote_exit_message`/`enqueue_port_down_message`/`enqueue_port_exit_message` builders) — whose other case is a `ProcessState::Running` process (the one its own engine is executing, whose `regs` snapshot is stale mid-slice); the `Running` case needs no host marking. Rationale: `../CONTEXT.md` Known Issues.
- **Host collection gate:** `CollectionGate` — the host's half of the same exhaustion policy, an additive trait `{ fn declines_relocation(&mut self, receiver: &Process) -> bool; }`. It takes `&mut self` (a gate may keep state — a cache, a counter) and receives the receiver's PCB (so it can consult the process's pid/heap/collector geometry); answering `true` declines only the **relocation**, so a no-relocation growth (`Process::grow_nursery`) or a heap-fragment delivery still proceeds and the notification is never lost. Installed on the process table (`ProcessTable::set_collection_gate`) and consulted at every signal site (OR-ed with `has_unpublished_roots`) plus `ProcessTable::deliver`; the motivating host is `beam_rt`'s unscanned-root predicate (`context/gc.rs::root_is_unscanned` + `context/gc_walk.rs::any_root_is_unscanned`). `ptab.rs` exposes `set_collection_gate`/`take_collection_gate`/`has_collection_gate` and the private `declines_signal_collection`.
### `dict.rs` — the per-process dictionary
- `Dict` (`Default`) backs `erlang:put/2`/`get/1`/`erase/1` (last put wins, `put` returns the replaced value) with `new()` (empty) / `with_atoms(Rc<AtomTable>)` and the never-panic GC pair `gather_roots`/`scatter_roots`. `None` is the C `THE_NON_VALUE` (the BIF layer maps it to `undefined`); keys — and, for `get_keys_for_value`, **values** — compare with `beam_term::compare::eq` (the C's `EQ`, `erl_utils.h:113`: structural `=:=`), so a *boxed* key matches a distinct-but-equal term (`put({a},1), get({a})` ⇒ `1`); atom names resolve through the `Rc<AtomTable>` handle (`new()` ⇒ empty table, whose unknown-name fallback is the raw atom index — the C's `EQ` for two immediates). Holds terms resident in THIS process's young heap (a `Process::collect` sub-rootset). Iteration is insertion-ordered — a documented deviation from the C's hash-array order (`pd_hash_get_all`), an unspecified artifact **not stable across VM starts** and so unpinnable by a differential case; `tests/dict_oracle.rs` compares `get/0` as a **set**. See `../DESIGN_DECISIONS.md`.
### `fragments.rs` — saved BIF/NIF arguments
- `SavedArgs` (`Default`) — the saved BIF/NIF argument root list (the C `ErlSaveCallArgs`): `push`/`pop`, `as_slice`/`as_mut_slice`, `len`/`clear` plus the GC pair (the region of `Process::collect`'s root set after the dictionary, before the pending signals).
### `run_queue.rs` — the ready queue (four priority levels)
- `Priority { Max=0, High=1, Normal=2, Low=3 }` (`Copy + Ord + Hash`; `Default = Normal`); the derived `Ord` is the C *numeric* order (`Max < High < Normal < Low`), which is **NOT** scheduling precedence — precedence is `LEVELS = [Max, High, Normal, Low]` (highest-first); `index()/from_index(u8)` (the C `PRIORITY_*` value); `name()/from_name(&str)`.
- `RunQueue` — four per-priority FIFOs; `dequeue` serves the highest-priority non-empty level, FIFO within a level; `enqueue(pid)` ⇒ **normal** (`enqueue_with_priority` for the rest); `reprioritize(pid, Priority) -> bool` moves an already-queued pid to the tail of the new level (never double-enqueues, never inserts a non-queued pid) — the run-queue half of `Scheduler::set_priority`; `split_off_half(&mut self) -> Vec<ProcessId>` removes up to half the queue's pids (highest priority first, `dequeue` order) so a work-stealing victim keeps at least half (0/1 pids ⇒ empty) — the victim half of the SMP steal.
- **Fairness deviation (documented):** the C keeps MAX/HIGH dedicated but lets **NORMAL and LOW share one physical queue**, deferring LOW by `schedule_count` (`RESCHEDULE_LOW = 8`, `erl_process.h`); this crate uses **four physically distinct FIFOs**, so LOW runs only once MAX/HIGH/NORMAL are empty — the relative precedence is unchanged (LOW last), only the LOW/NORMAL interleaving ratio differs.
### `scheduler.rs` — the single-threaded scheduler loop + the engine seam
- `RunOutcome { Yield, Wait, Suspend, Exit(Eterm) }` — what happened in a reduction slice (`Exit(reason_term)` = the process terminated with that reason); `ProcessRunner { fn run(&mut self, pid: ProcessId, table: &mut ProcessTable, budget: u32) -> Result<RunOutcome> }` — **the engine seam** (`beam_engine` is NOT a dependency; `beam_rt`/`beam_engine` implement it over an `ExecutionContext`).
- `Scheduler` — `new()` defaults `DEFAULT_REDUCTIONS_PER_SLICE = 4000` (override `with_slice(u32)`), and optionally owns a `PortTable` (`with_ports`/`set_ports`/`take_ports`/`ports(_mut)`/`has_ports`; `new`/`with_slice` own none). Entry points: `enqueue`(⇒ normal)/`enqueue_with_priority`, `progress()/progress_mut()`, `set_priority(&mut self, table, pid, priority) -> Result<()>` (updates the PCB priority and, **iff** the pid is already queued at a different level, moves it to the new level's tail — the C `erts_set_process_priority` requeue; `TermNotFound` for an unknown pid leaves the queue untouched), `run_slice`/`run_ready`/`resume_woken` and the explicit `run_slice_with_ports`/`run_ready_with_ports` forms.
- A slice pops one pid, **services its pending signals** (schedule-in; a fatal signal can terminate the pid, in which case it runs zero reductions) and runs one slice: `Yield` ⇒ requeue at the tail of the process's **own** current priority; `Wait`/`Suspend` ⇒ leave the queue; `Exit(reason)` ⇒ terminate (through `terminate_with_ports` when a port table is owned, else the port-less `terminate`); afterwards (and on the empty-queue early return) it absorbs the table's wake list. `run_ready(…, max_slices: Option<u64>) -> Result<u64>` runs until the ready queue is empty or `max_slices` slices ran; `resume_woken(&mut self, table) -> usize` drains `table.drain_woken()` and enqueues each still-live `Runnable` pid not already queued **at its own priority** (also the hook `beam_rt` calls after a send made **outside** a slice).
- **Reduction accounting is delegated to the runner:** `ProcessRunner::run` receives `DEFAULT_REDUCTIONS_PER_SLICE` as its `budget` and owns the reduction count (the scheduler never reads or resets `Process::reductions`), so **pre-emption is cooperative** (see `../CONTEXT.md` Known Issues).
- **Shared slice helpers (the SMP reuse seam):** `pub(crate)` `slice_begin(pid, table) -> Result<bool>` (mark executing + apply the queued signals), `slice_end<F>(pid, table, outcome, enqueue)` (schedule-out), `run_one<R, F>(pid, table, runner, reductions, enqueue)` = `slice_begin` + one full-budget runner call + `slice_end`, and `drain_woken_into<F>(table, enqueue)`; the `*_with_ports` mirrors share private `*_inner` bodies. `run_slice`/`resume_woken` delegate to them, and the SMP pool calls the same helpers (splitting a slice into lock quanta) with a closure that **buffers** requeues instead of touching a queue.
- **Port-aware adoption and the `beam_rt` orchestration contract** (spawn ⇒ `spawn_default` + `enqueue`; a runner blocking on an empty receive sets `ProcessState::Waiting` **before** returning `RunOutcome::Wait`; a send inside a runner is absorbed at slice end, one outside a slice needs an explicit `resume_woken`; run ⇒ `run_ready(&mut table, &mut runner, None)`) are documented in full in the module rustdoc.
### `smp/` — the multi-scheduler (SMP) pool
The `Scheduler` counterpart for SMP: N scheduler threads over one shared process table, per-scheduler run queues + work stealing, the `ThreadProgress` barrier, the `TimerService` and the two `DirtyPool`s. Crate-root re-exports: `beam_process::{SchedulerPool, SchedulerConfig, SchedulerStats, SchedulerStat, SharedProcessTable}`. Full API surface, the **BINDING locking discipline** (three lock families, the buffer-requeues rule), the **bounded-quantum lock** rule (`run_locked_quanta`, `set_lock_quantum`) and the `unsafe impl Send/Sync` handoff live in **`smp/CONTEXT.md`**. `SchedulerPool::set_priority(pid, priority)` implements the same requeue as the single-threaded `Scheduler` (PCB update under the table lock, then an `O(schedulers)` search of the injector + every local queue, one queue lock at a time).
### `timer.rs` — the high-level timer service
- `TimerService` — one background thread over a deadline min-heap; `TimerRef { id, generation }` (`Copy`); `TimerSink: Send + Sync { fn timer_fired(&self, target: ProcessId, message: Eterm); }` — the seam the pool implements. It is the delivery **mechanism** only (one message to one `ProcessId` after a delay); the `erlang:send_after/3`, `start_timer/3` (`{timeout,Ref,Msg}` needs `make_ref`), `cancel_timer/1,2`, `read_timer/1`, `start_timer/4` and `receive ... after T` timeout-label semantics are BIF/engine-side (`beam_bifs`/`beam_rt`); `read_timer` and a hibernate state are absent here. **Message contract:** the stored message must be **thread-valid** — an immediate (small int/atom/pid) or a literal-area/interned term; a term resident in a per-process heap is a caller contract violation (needs an off-heap handle; documented follow-up).
### `dirty.rs` — the two dirty scheduler pools
- `DirtyKind { Cpu, Io }` (`ALL`, `name()` = `"dirty_cpu_scheduler"`/`"dirty_io_scheduler"`); `DirtyOutcome { Done, Reschedule(ProcessId), Deliver { target, message } }` — routing data the normal scheduler acts on (`Reschedule` re-enters the pid, `Deliver` delivers and wakes); `DirtyJob = Box<dyn FnOnce() -> DirtyOutcome + Send + 'static>` — a plain closure carrying **no** live heap data; `DirtyCompletionSink: Send + Sync { fn dirty_completed(&self, DirtyOutcome); }`; `DirtyPool` (`start(cpu, io)`, `set_sink`, `cpu_schedulers()`/`io_schedulers()`, `schedulers(kind)`, `submit(kind, job)`, `pending(kind)`, `shutdown()`, `join()`). A kind with **0 workers buffers** jobs (never drops on submit, discards at join); a panicking job does not kill the pool.
### `progress.rs` — thread progress (the cross-scheduler barrier)
- `ThreadProgress` (`generation`, `bump() -> u64`, `wait(u64)`, `safepoint() -> u64` = `bump`+`wait`, `managed_thread() -> ManagedThread`, `managed_count`, `set_waker`, `is_blocking`/`block`/`unblock`/`blocking_count`) — the real barrier; cheap to clone, and every clone shares the generation, the managed-thread registry and the blocking counter. `ManagedThread` is the per-thread slot a scheduler registers (`progress`, `update` = confirm the current generation, `is_active`/`set_active(bool)` — an inactive/parked thread is already at a safepoint and is excluded from the wait — `id`).
### `signal.rs` — exit signals, reasons and signal-message builders
- `SignalAtoms { exit, down, process, port, normal, kill, killed, noproc, system }` — the well-known atom indices used to build signal messages; `from_table(&mut AtomTable)` interns `'EXIT'`/`'DOWN'`/`process`/`port`/`normal`/`kill`/`killed`/`noproc`/`system`; `system` is the C's `am_system`, used as the `Message::from` immediate of a failed-by-name monitor DOWN (`erl_proc_sig_queue.c:4991`).
- `ReasonClass { Normal, Kill, Other }` + `SignalAtoms::classify(reason) -> ReasonClass`; `ExitSignal { from: ProcessId, reason: Eterm }` (`Copy`); `ExitPolicy { Terminate(Eterm), Trap, Ignore }` (`Trap` = deliver `{'EXIT', From, Reason}` as a message) and `exit_policy(reason, trapping, &SignalAtoms) -> ExitPolicy` (`kill` ⇒ `Terminate(killed)`, untrappable; else trapping ⇒ `Trap`; else `normal` ⇒ `Ignore`; else `Terminate(reason)`).
- **Signal-message builders** (each allocates on the *receiving* process's heap; the full list is in the rustdoc): the exit pair `build_exit_message(heap, atoms, from: ProcessId, reason)` / `build_exit_message_term(heap, atoms, from: Eterm, reason)` (`{'EXIT', From, Reason}`; the `_term` form's `from` may be an external pid term); the DOWN family `build_down_message(heap, atoms, user_tag: Option<Eterm>, reference, pid, reason)` (`{'DOWN', Ref, process, Pid, Reason}`, or `{Tag, Ref, process, Pid, Reason}` when `user_tag` is `Some`) / `build_down_message_port(...)` (the `port`-**kind** form) / `build_down_message_remote(...)` (materialises the external-pid target on the same heap) and the fully general `build_down_message_term(heap, atoms, user_tag: Option<Eterm>, reference, kind: Atom, target: Eterm, reason)`. `kind` is the `{'DOWN', …}` 3rd-element **kind** atom (`process`/`port`), distinct from the caller's `user_tag` (which replaces the message's head atom).
### `signal_queue.rs` — the decoupled per-process pending-signal queue
A signal is *queued* on the receiver and applied later (the crate-level eager-vs-queued rule); its `reason` is copied into the receiver's own heap at enqueue time, so the queue is an in-heap sub-rootset. `PendingSignalKind { Exit, Down }`; `PendingSignal { Exit { from, reason }, Down { reference: MonitorRef, target: ProcessId, kind: MonitorKind, tag: Option<Eterm>, reason } }` (`Copy`) with the `exit`/`down` constructors and `kind()`/`tag()`/`reason()` — the `tag` is the caller's `monitor/3` user tag, carried so the deferred `{'DOWN', …}` materialises with the right head atom. `SignalQueue` (a `VecDeque<PendingSignal>`, `Default`) is the per-process FIFO (application order) plus the GC pair `gather_roots` (one word per queued signal's `reason`) / `scatter_roots`; monitor references are stored by value, not on the heap. **Ordering:** a total FIFO order per receiver (a single FIFO) — subsuming the C's per-`(sender, receiver)` order; **not** cross-ordered with the mailbox.
### `link.rs` — bidirectional links
- `Links { pids: Vec<ProcessId> }` — `add(pid) -> bool` (false if already linked), `remove(pid) -> bool`, `contains(pid)`, `iter()`, `drain()`.
### `monitor.rs` — monitors and monitor references
- `MonitorRef { id: u64 }` (`Copy + Eq + Hash`) — `to_eterm(self, heap) -> Result<Eterm>` builds the on-heap `Ref` thing (`../DESIGN_DECISIONS.md`), `from_eterm(term) -> Result<MonitorRef>` is the reverse (parses the frozen `[header, node, serial, id]` ref thing, `BadArg` for anything else — the send path's destination→key step, with guard-chain parsing like `payload_is_down_for`). `RefAllocator { next: u64 }` — `next() -> MonitorRef` (monotonic, never reuses an id); owned by `ProcessTable`. Its id space is **one of two** independent spaces in the running system — `beam_rt`'s `Runtime::refs` (fed by `make_ref/0`, the NIF `make_ref`, the timers and `seq_trace`) is the other — so a bare `make_ref/0` reference and a monitor/alias reference with **equal ids** are the same term and compare `=:=` (HAZARD 2: a documented divergence pinned by `tests/reference_ids.rs`; the exact reason it is not closable here and its owner are in the crate `CONTEXT.md` Known Issues).
- `UnaliasMode { ExplicitUnalias, Demonitor, ReplyDemonitor }` (`Copy + Eq + Hash`) — the `{alias, Mode}` un-alias mode of `erlang:monitor/3`/`alias/1` (the C `ERTS_ML_STATE_ALIAS_*` flag values); the atom→mode parsing is the BIF layer's, so the enum is the frozen value the alias entry points take. `AliasEntry { owner: ProcessId, mode: UnaliasMode }` (`Copy`) — one `ProcessTable` `aliases` entry (`owner` is the process a message sent to the reference is delivered to); plain values only (not a GC root).
- `MonitorKind { Process, Port }` — `type_name() -> &'static str` (`"process"`/`"port"`) and `from_type_name(&str) -> Option<MonitorKind>` back the `erlang:monitor/2` type dispatch (any other type name ⇒ `None` ⇒ the caller's `badarg`, matching the oracle).
- `PortWatch { reference: MonitorRef, port: PortId }` (`Copy`) — the **outgoing** half of a port monitor, held in `Process::port_monitors`; plain values only (not a GC root).
- `Monitor { reference, target: ProcessId, kind }` (outgoing) / `MonitoredBy { reference, watcher: ProcessId, kind }` (incoming) — field sets **frozen** (constructed by struct literal from `beam_rt`, so no field may be added); the `monitor/3` user **tag** therefore lives in a `ProcessTable` side table, not here. `Monitors { entries: Vec<Monitor> }` — `push`, `remove(reference)`, `find(reference)`, `iter`, `drain`.
- `payload_is_down_for(payload: Eterm, reference: MonitorRef, down_atom: Atom) -> bool` — the guarded `{'DOWN', Ref, _, _, _}` shape test `demonitor_flush` scans mailboxes with (one `unsafe` block, no out-of-bounds read).
### `ptab.rs` — the process/port table + name registry + signal/link/monitor hub
The single place that mutates ≥2 processes (mirrors the C ptab lock domain), using the crate-level **collect-then-apply worklist**; M1 single-threaded, so it holds `Process` values directly (`PortTable` lives in `port.rs`). The module rustdoc is authoritative for the full entry-point list (allocation/lookup, priority, the GC relocation-exemption pair, delivery, the local signal/link/monitor ops, the `*_with_tag`/`*_with_options` points, decoupled servicing, the `*_term`/`remote_*` forms, the distribution and process-death-observer seams, `node_down`/`port_closed`, the name registry, liveness/reason). Frozen shape and the contracts that must not be lost:
- `ProcessTable { slots, free, names: HashMap<Atom, ProcessId>, refs: RefAllocator, atoms: SignalAtoms, ready: Vec<ProcessId>, remote_links, remote_monitors, named_monitors: HashMap<MonitorRef, NamedTarget>, local_node: Option<Atom>, router: Option<Box<dyn DistSignalRouter>>, collection_gate: Option<Box<dyn CollectionGate>> }` (`Slot { serial: u64, process: Option<Process> }`; `NamedTarget { name: Atom, node: Atom }`). `ready` is the **wake list** (a delivery/signal pushes a woken pid; `drain_woken` returns **and** clears it); `router` is the distribution seam (`None` ⇒ record-only); `collection_gate` is the host collection-gate seam (`None` ⇒ no gate; `set_collection_gate`/`take_collection_gate`/`has_collection_gate` install/take/test it, and the private `declines_signal_collection(pid)` — a split borrow of `slots`/`collection_gate` — answers whether the host declines a relocating collection of that pid's heap, `false` with no gate or an unknown pid). `alloc_pid` reuses a free slot and bumps its serial (`SystemLimit` on exhaustion); `take` bumps the serial **and** drops the wake entry.
- `link(a, b)` has `a`/`b` set semantics and a **non-live `b`** with a live `a` records no link and applies a `noproc` exit signal from `b` to `a` — a trapping `a` is handed `{'EXIT', b, noproc}` and a non-trapping one is terminated with the bare atom `noproc` (the oracle *raises* `error:noproc`; signalled here as the bare reason — a documented approximation owned by `beam_rt`'s link floor); `TermNotFound` is returned only when the caller `a` is unknown (`link_term`'s local branch inherits this).
- `terminate`/`terminate_with_ports` are **best-effort per peer**: the pid is reclaimed first, so a per-peer signalling failure (a local signal that cannot be queued, a remote `route` transport error) is dropped-and-logged (ERTS's `erts_dsig_drop`) and the cascade continues — the observer and the port-monitor cleanup always run; `TermNotFound` for an unknown pid is the only `Err` on this path. `terminate_with_ports` threads the port table so a dying process's outgoing `port_monitors` also remove their matching **incoming** `PortMonitor` entries (`terminate` is its no-ports delegation).
- `monitor(watcher, target: ProcessId, kind) -> Result<MonitorRef>` — a **non-live** target with a live watcher yields `Ok(ref)` plus an immediate `{'DOWN', Ref, process, Target, noproc}` in the watcher's mailbox (the oracle's `noproc`); `demonitor`/`demonitor_flush` (`flush` also removes a queued `{'DOWN', …}` for that reference — `erlang:demonitor(Ref,[flush])`). `monitor_named(watcher, name: Atom, node: Atom, kind)` + `set_local_node`/`local_node` implement `erlang:monitor(process, Name)`: the DOWN target is the 2-tuple `{Name, node}`; with no local node installed ⇒ typed `unsupported`. `monitor_term` dispatches a pid → `monitor`, an atom name → `monitor_named`, an external pid → the remote record + route; a **port term** with `MonitorKind::Process` ⇒ `BadArg` (oracle) and with `MonitorKind::Port` ⇒ typed `unsupported` (that entry point has no `&mut PortTable` — use `monitor_port_term`); anything else ⇒ `BadArg`. A **target's death resolves both halves** — `terminate_into` also removes the watcher's outgoing `Monitor`, so `process_info(W, monitors)` stops listing it and a later `demonitor(Ref)` reports it gone (the `{Name, node}` descriptor of a named monitor survives until its DOWN is materialised, so the DOWN still carries the name). `monitor_port(_term)`/`demonitor_port` are the port-track forms (`erlang:monitor(port, Port)`).
- **`erlang:monitor/3` user tag (additive):** the `*_with_tag` points (`monitor_with_tag`, `monitor_named_with_tag`, `monitor_port_with_tag`, `monitor_port_term_with_tag`, `monitor_term_with_tag`) take a trailing `tag: Option<Eterm>` (the no-tag methods delegate with `None`); a `Some(tag)` makes the delivered message `{Tag, Ref, Kind, Target, Reason}` instead of `{'DOWN', Ref, Kind, Target, Reason}` — the tag replaces the head atom only. The tag is stored in the private `tags: HashMap<MonitorRef, Eterm>` side table (`remember_tag`/`forget_tag`, cleaned up at `demonitor`/`demonitor_port`/termination/port close) — **never** in the frozen `Monitor`/`MonitoredBy`/`PortWatch` structs. The tag must be a heap-independent **immediate**; a non-immediate tag (or any tag on a **remote** external-pid target — `DOP_MONITOR_P` carries no tag) is a typed `unsupported`.
- **Reference aliases (`erlang:monitor/3` `{alias, Mode}`, `erlang:alias/1`, `erlang:unalias/1`):** a `MonitorRef` may name an **alias** — a send destination that resolves to its owner — held in the private `aliases: HashMap<MonitorRef, AliasEntry>` side table (next to `tags`; nothing else stores it). `MonitorOptions { tag, alias }` plus the `*_with_options` points (`monitor_with_options`, `monitor_named_with_options`, `monitor_port_with_options`, `monitor_port_term_with_options`, `monitor_term_with_options`) register the alias; the existing `*_with_tag` methods delegate with `alias: None`, so their signatures are unchanged. `resolve_alias(reference) -> Option<ProcessId>` is the send-path resolver — `Some(owner)` iff the reference names an alias whose owner is **live**; `create_alias(owner, mode) -> Result<MonitorRef>` is `alias/1`; `unalias(owner, reference) -> Result<bool>` is `unalias/1` (clears only the alias of `owner`, keeping a sharing monitor); `alias_reply_delivered(reference) -> Result<()>` is the reply site. **Auto-removal** follows the C (`bif.c:470-492`, `erl_proc_sig_queue.c:6009-6112,:6466-6493`): `reply_demonitor` ⇒ gone once a message is delivered through it; `demonitor`/`reply_demonitor` ⇒ gone when the monitor's DOWN is materialised (the shared `apply_alias_on_down`, used by the termination/`port_closed` and born-down `noproc` paths); `explicit_unalias` ⇒ survives its DOWN and an explicit `demonitor` (re-derived as a standalone alias) and is cleared only by `unalias/1`. A dying owner's aliases are all swept (`aliases.retain(|_, e| e.owner != pid)`), so no alias ever resolves to a dead pid. A `{alias, …}` on a **port** monitor or on a **remote** external-pid target is a typed `unsupported` (see `../CONTEXT.md` Known Issues).
- `service_signals(pid) -> Result<()>` drains + applies the pid's pending-signal queue in FIFO order, cascading to any process those signals affect (the scheduler calls it at schedule-in); `service_signals_with_ports(&mut PortTable, pid)` threads the port table so such a cascade also cleans a terminated process's incoming port monitors (the plain form delegates with no ports).
- `node_down(node: Eterm, reason)` resolves + purges every remote relationship with `node` (a `{'DOWN', …}` per monitor, a trapped/fatal `{'EXIT', …}` per link); `port_closed(&mut PortTable, port, reason)` drains the port's owner/links/monitors, delivers the `{'DOWN', Ref, port, Port, Reason}` / `{'EXIT', Port, Reason}` shapes, and terminates any non-trapping linked peer through `terminate_with_ports` so that peer's own port monitors are cleaned too. This is the **port-died** direction; the reverse (a **watcher process** dies) is handled in `terminate_into` by draining `Process::port_monitors` and calling `PortTable::demonitor` on the matching incoming entries — but only when a port table was threaded in.
- `register(name, pid)` is `BadArg` for a taken name **or a non-live pid**; `unregister(name)` is `BadArg` for an unknown name; `whereis(name)`/`registered()`/`name_of(pid) -> Option<Atom>` (the reverse lookup a `process_info(P, registered_name)` BIF needs; live-only); `is_process_alive(pid) -> bool` is table membership and `exit_reason(pid) -> Result<Option<Eterm>>` is live-only. `ExitEffect { Terminated, Trapped, Ignored }` — the outcome of `apply_exit_signal` (target terminated / got a `{'EXIT'}` message / ignored it).
- **Eager-vs-queued rule** (stated in full at crate level): a signalling operation **enqueues** a `PendingSignal` on the receiver — never inline; servicing is at the receiver's schedule-in (`service_signals`, called by `run_slice`) and **eagerly at the end of the sending operation** for a receiver that is not the currently `Running` process (ERTS's early signal handling), and `apply_exit_signal` returns the `exit_policy`-predicted `ExitEffect` for a merely-queued signal. A **remote** or **port** signal bypasses the queue, so `node_down`/`port_closed` materialise it straight into the mailbox.
- **Signal-build exhaustion:** a signal the receiver's full nursery refuses is routed into a heap fragment when the receiver's relocating collection is **declined** — the crate-owned `Process::has_unpublished_roots` (**relocation-exempt** or currently **`Running`**) OR the host's `CollectionGate` (consulted first at every signal site; no collection, no growth, no relocation either way), at **both** refusal sites — the apply-time message build (`build_signal_message`/`deliver_head_signal` → `enqueue_fragment_signal`) and the enqueue-time reason copy (`copy_reason_onto` → `enqueue_down_signal`'s `deliver_down_fragment` / `enqueue_exit_signal`'s `deliver_exit_fragment`, which build the message the queue would have materialised straight from the enqueue site and wake a blocked receiver themselves). The shared helper is `enqueue_fragment_payload` (it takes the **source** process's off-heap table, `None` meaning the receiver's own). The only refusal still surfaced is the exit **policy** one: an exit signal to a **non-trapping** receiver whose collection is declined, which would have to terminate it (the caller's cascade, not a message).
### `exit_observer.rs` — the process-death observer seam
The host hook for per-process resources this crate does not own (the **ETS tables a pid owns** are the motivating case). Mirrors the `DistSignalRouter` pattern: a trait object on the table, implemented downstream, so the table stays free of any dependency on the observing subsystem; with **no** observer installed (`None`) behaviour is unchanged.
- `ProcessExitObserver { fn process_exited(&mut self, exit: &ProcessExit<'_>); }` — called **exactly once per death** from `terminate_into`, after the death has been propagated (links/monitors signalled **best-effort** — a peer that cannot be signalled is dropped-and-logged, never an abort, so this hook always runs) and **before** `drop(process)` (so `reason`, which may live in the dying heap, is still valid). No `Send` bound (consistent with `router`).
- `ProcessExit<'a>` — the payload, **private fields + read-only accessors**, built only by the finalizer: `pid: ProcessId` (the key an observer uses to release its own per-pid state; an immediate ⇒ retainable), `reason: Eterm` (the exit reason exactly as received; may live in the dying heap, so an observer that retains it must copy it), `name: Option<Atom>` (the registered name, captured **before** the registry entry is dropped; without it the registration would be unobservable), `port_monitors: &'a [PortWatch]` (the drained outgoing port watches; plain values ⇒ heap-independent).
- **Failure policy:** an absent observer is a no-op; a **panicking** observer is contained with `std::panic::catch_unwind(AssertUnwindSafe(...))` (the observer gets only an immutable payload and holds no reference to the table, so a panic cannot half-update the table — only the observer's own state), reported via `beam_common::beam_error!`, and termination still completes. Implementations should be cheap (they run on the finalizing scheduler thread) and prefer returning over panicking for expected conditions.
### `remote.rs` — remote (external-node) links and monitors
The **local record** of a process's relationships with processes on other nodes; the wire format is `beam_dist`'s, reached through a trait seam (this crate never depends on `beam_dist`).
- `RemotePid { node: Eterm, number: u32, serial: u32, creation: u32 }` (`Copy`) — a decomposed external pid (the `[header, node, creation, data]` thing), holding no boxed pointer into another heap; `from_eterm(term) -> Result<RemotePid>` (`BadArg` unless an external pid), `to_eterm(self, &mut Heap)`. `PidTarget { Local(ProcessId), Remote(RemotePid) }` — `from_eterm` (external ⇒ `Remote`, internal ⇒ `Local`, else `BadArg`). `RemoteMonitor { reference: MonitorRef, remote: RemotePid, kind: MonitorKind }` — an outgoing monitor on a remote process/port.
- `DistSignal { Link { from, to }, Unlink { from, to }, Monitor { watcher, target, reference, kind }, Demonitor { watcher, target, reference }, Exit { from, to, reason }, Exit2 { from, to, reason } }` — the control signal the runtime routes to the remote node. `Exit` is a **link** exit → `{DOP_EXIT, From, To, Reason}` → `Dop::Exit`; `Exit2` is `erlang:exit/2` → `{DOP_EXIT2, From, To, Reason}` → `Dop::Exit2` (distinct opcodes with distinct receipt semantics); the full `DOP_*` mapping is documented on the module.
- `DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()>; }` — **the distribution seam**: implemented downstream (`beam_rt`) over `beam_dist`; `route` must serialise the signal **synchronously** (`reason` may live in the signaller's heap, which the caller may drop right after). Its transport error propagates out of the relationship ops (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`node_down`), but **not** out of a dying process's termination (the remote step of `terminate_into` drops-and-logs a failed `route`). The table's remote records (`remote_links`/`remote_monitors`) and `set_dist_router`/`has_dist_router` are on `ptab.rs`. **This seam is OUTBOUND only** (local → remote): there is no inbound control-message (`DOP_LINK`/`DOP_MONITOR_P`/…) interpreter here — an inbound handler belongs to `beam_rt` (see `../CONTEXT.md` Known Issues).
### `port.rs` — the port-id table + ownership / link / monitor surface
`PortTable` is the number table the C keeps alongside the pid table, extended with the relationships a dying port must resolve; port *behaviour* (driver, scheduling, read path) is `beam_io`'s. The crate-root re-export keeps `beam_process::PortTable` resolving here.
- `PortMonitor { reference: MonitorRef, watcher: ProcessId }` — a monitor placed on a port. `PortClose { owner: Option<ProcessId>, links: Vec<ProcessId>, monitors: Vec<PortMonitor> }` — what `close` releases.
- `PortTable { slots: Vec<bool>, free, owners, links, monitors }` — `alloc() -> Result<PortId>` (`SystemLimit` on exhaustion), `alloc_owned(owner)`, `release(PortId)` (frees the number + drops every relationship), `close(PortId) -> Result<PortClose>` (frees the number, returns **and clears** owner/links/monitors; unknown id ⇒ `BadArg`), plus the ownership (`owner`/`set_owner` — unknown id ⇒ `BadArg` — /`clear_owner`), links (`link` — deduped, `false` if already linked — /`unlink`/`links`) and monitors (`monitor`/`demonitor`/`monitors`) accessors. Every relationship mutation on an unallocated id returns `BeamError::BadArg`; `ProcessTable::port_closed` is the one-call orchestrator resolving a closing port's relationships.
### `error.rs` — `pub(crate)` constructors only (no new error enum)

## Notes for Agents (module level)
- **`Registers` has NO float-register (FR) container: the FR file rides in the `Stack`.** The engine's FR slots hold `Eterm` words (no hardware float regs in this engine), so a live float register can point into the process heap and must be a root — but it has nowhere of its own to live here. The host (`beam_rt`'s `context::gc::publish_roots_full`) therefore closes the FR file **onto the end of `Registers::stack`** (after the real Erlang stack words) for the duration of one hand-off, and `scatter_roots_full` splits that region back into `stack` + `fr` by length. So at this node a "stack word" is really a stack-or-FR word: `Registers::gather_roots` roots them all, indistinguishably, in one `Vec<Eterm>`. Adding a real FR field here would change the frozen `Registers` shape — do not.
- **The collector moves live terms, so every in-heap reference must be a root.** `Process::collect` scans registers/stack, mailbox payloads, the process dictionary (`Dict`), the saved args (`SavedArgs`) and the pending-signal queue (`SignalQueue`) — add any NEW in-heap sub-rootset to its gather/scatter, in the same order, in the same change. `Process::port_monitors` is deliberately **not** a root: a `PortWatch` holds only plain values.
- **`Process::regs` is a HOST-published snapshot the scheduler never writes.** The `Registers` container (`x[0..live)` + the whole `Stack`) is filled **only** from outside this crate — the host (`beam_rt`) copies the running machine's own x/stack/FR into it (`publish_roots_full`/`publish_roots`) at a heap-admission point or a park. Nothing in `scheduler.rs`'s slice path (`slice_begin`/`slice_end`/`run_one`/`run_ready`) reads or writes `regs`. `Process::collect`/`ensure_capacity` relocate the young heap against this snapshot, so between two publishes it is stale by up to one slice of instructions (live machine x/stack/FR words a post-publish allocation made are invisible to the collector); the crate cannot detect that, so the host must gate it with `set_relocation_exempt` when it holds live terms from the process outside the root set. The **`Running`** case is the second, crate-derived case of the same gate (`has_unpublished_roots`): a delivery to the currently executing process is refused with no host marking, so its stale `regs` snapshot is never collected against. Full hazard analysis: `../../beam_rt/CONTEXT.md` (GC-relocation hazards).
- **Where the PCB and its heap live (address stability).** A `Process` is stored **inline** in `ProcessTable`'s `slots: Vec<Slot>` (`Slot.process: Option<Process>`, `ptab.rs`), so growing the table (`alloc_pid`/`insert`) can reallocate the `Vec` and **move** the PCB — and its embedded `AnyCollector`/`HeapSpace`/`Heap` — to a new address. The heap *words* are unaffected: `beam_alloc::Heap` owns a separate allocator block (`Heap::base: *mut Eterm`), so terms from `get_mut(pid).heap_mut()` stay valid across a table growth (Rust's borrow rules forbid holding the `&mut` across it anyway). The `&mut Heap` **identity** is *not* stable across a collection, though: a fullsweep replaces the mature space (`AnyCollector::collect_major`) and `resize_nursery`/`grow_nursery` replace the nursery, so re-obtain `heap_mut()` after any `collect()` — never cache a heap pointer across one.
- **Pre-emption is the RUNNER's obligation.** A `ProcessRunner` must count its own reductions and return `RunOutcome::Yield` at its `budget`; the scheduler then requeues at the PCB's current priority. A runner that never yields is not pre-empted. `tests/preemption.rs` pins the scheduler half; `beam_rt`'s runner and its `beam_rt/tests/preempt.rs` interleaving pin are under `../CONTEXT.md` Known Issues.
- **The two split borrows** (`Process::heap_and_off_heap_mut`/`heap_and_mailbox_mut`), their callers and the rule against adding a combined raw-pointer accessor are in the `process.rs` API section above (and the module rustdoc).
- **`ProcessTable` is `!Send`; the SMP pool contains it with two `unsafe impl Send/Sync`.** The measured causes are **six**: `beam_alloc::Heap`'s `base: *mut Eterm`, `beam_gc::MsoHandle`'s `ptr: NonNull<Mso>` (via `beam_message::OffHeapTable`), the `Rc<AtomTable>` in each `Dict`, and this crate's own `Option<Box<dyn DistSignalRouter>>`, `Option<Box<dyn ProcessExitObserver>>` and `Option<Box<dyn CollectionGate>>` (`beam_alloc::RefcBinary` is already `Send`). The `Rc<AtomTable>` is never cloned and never shared outside the table, so no `Rc` is touched from two threads. The full invariant lives in `smp/CONTEXT.md` and `smp/mod.rs`. Removing the workaround needs an upstream `beam_gc`/`beam_alloc` change this crate must not make — do not widen this `unsafe`.
- **The SMP pool (`smp/`) must follow its BINDING locking discipline** (`smp/CONTEXT.md`): never hold a queue lock while taking the table lock and vice-versa; buffer requeues while the table guard is held; the only nested order is *signals mutex → queue lock*. It reuses the frozen `slice_begin`/`slice_end`/`drain_woken_into` helpers (in `run_locked_quanta`) — do **not** re-implement slice logic in a worker.
- **Oracle-probed semantics live in the tests, not this file.** Before changing monitor/registration/signal behaviour, run the relevant probe: `erl -noshell -eval '<expr>, halt(0).'` — the oracle is OTP 29.1.1 / erts-17.1. The `erl`-cross-checked suites (`tests/dict_oracle.rs`, `registry_monitors.rs`) skip loudly when `erl` is absent.
