# `beam_process/src` — the module layer (23 modules + `smp/`)

## Intent
One routing node for the modules of the `beam_process` crate; the crate-level contracts (Intent, frozen-seam overview, Constraints, Test Strategy, Handoffs, Known Issues) live in `../CONTEXT.md`.
Each `src/<module>.rs`'s top-of-file `//!` rustdoc plus its per-item `///` docs is authoritative for its complete method list; this node records the *frozen* API surface a dependent designs against — seam types and shapes, constants, the entry points dependents call, and the caveats that must not be lost. Everything here is re-exported at the crate root (`lib.rs`) and via `beam_process::prelude::*`.
The cross-module binding rules (eager-vs-queued signalling, the collect-then-apply worklist, the split-borrow rule, the `from`-is-immediate producer rule, the exhaustion policy) are stated **once** in `../CONTEXT.md` and cited below; long-form caveats live in `NOTES.md` (one section per module, named by the bracketed pointers), rationale ("why") in `../DESIGN_DECISIONS.md`.

## API Surface (FROZEN — dependents route here)
### `pid.rs` — process/port identity (bit-exact with `beam_term::immediate`)
- `ProcessId { number: u64, serial: u64 }` (`Copy + Eq + Hash + Ord + Debug`) — `to_eterm() -> Eterm` = `make_internal_pid(make_pid_data(serial, number))`; `from_eterm(Eterm) -> Result<ProcessId>` is `BadArg` unless an internal pid; `is_process(Eterm)`.
- `PortId { number: u64 }` — the same shape via `make_internal_port`/`is_internal_port`.
- Limits: `MAX_PROCESS_NUMBER = (1 << 28) - 1` (`PID_NUM_SIZE`); `MAX_PROCESS_SERIAL = 2^32 - 1` (`PID_SER_SIZE`).
### `registers.rs` — the root-set containers (x-register file + stack + extra roots)
- The crate-layer root-set contract: `x_reg_array[0..Live)` **plus the whole stack**, no frame liveness maps; `MAX_REG = 1024`, `MAX_ARG = 255`.
- `XRegs` (boxed `[Eterm; MAX_REG]` + `live`), `Stack` (`Vec<Eterm>`), `Registers { x, stack, extra_roots }` with the GC pair `gather_roots(&self, out: &mut Vec<Eterm>) -> usize` (appends `x[0..live)`, then every stack word, then every extra root; returns the `x_live` split point) / `scatter_roots(&mut self, roots, x_live)` (the first `x_live` into `x`, the next `stack.len()` into the stack, the remainder into `extra_roots`; **total** — a short slice leaves the uncovered tail untouched).
- **`extra_roots: Vec<Eterm>`** — the one host-published extension of the frozen root shape: terms held outside `x`/`stack` that must survive a relocation (motivating case: a parked engine `Machine`'s live reason term). `extra_roots()`/`extra_roots_mut()` (a mutable container, not a setter; the host pushes on suspend, clears on resume); empty in `new()`; `run_rooted_collection` scatters exactly the gathered prefix, so they ride along.
- **No float-register container:** the host closes the engine's FR words onto the **end of `Stack`** for one hand-off and splits them out by length, so a "stack word" is a stack-or-FR word (`NOTES.md` §module-notes).
### `process.rs` — the process control block (PCB)
- `ProcessState { Runnable, Running, Waiting, Suspended, Exiting, Terminated }` (`Copy`); `DeliverOutcome { Enqueued, Woke }` (`Copy + Eq`, `woke() -> bool`) — `Woke` = the recipient was blocked (`Waiting`/`Suspended`) and is now `Runnable`; `ProcessFlags` — a `u32` bitset over `trap_exit`, `system`, `in_run_queue`, `garbage_collecting`, `active`, `sensitive`.
- `Process` fields (shape frozen): `pid`, `state`, `flags`, `priority`, `save_calls`, `collector: beam_gc::AnyCollector`, `relocation_exempt`, `off_heap: beam_message::OffHeapTable` (persistent: queued-signal reasons and host-moved fragments; a send stages through its own fresh table), the owned list (`owned_binaries`/`owned_binary_index`/`owned_binary_slots`/`dead_binaries`/`off_heap_binary_bytes_override`), `mailbox`, `regs`, `dict`, `saved_args`, `signals`, `scratch`, `reductions`, `links`, `monitors`, `monitored_by`, `port_monitors`, `exit_reason`, `max_heap: MaxHeapSetting`, `max_heap_verdict`.
- Spawn: `new(pid)`/`with_policy(pid, policy)`/`with_policy_and_priority(pid, policy, Priority)` (spawn-at-priority: `alloc_pid` + it + `ProcessTable::insert`); the mature strategy comes from the policy — copying below `beam_gc::IMMIX_BREAK_EVEN_WORDS`, GenImmix at/above. `heap()/heap_mut()` is the **young** heap; `wake() -> bool`; `status_atom`/`status` render `process_info(P, status)`'s atoms (`"running"`/`"runnable"`/`"waiting"`/`"suspended"`/`"exiting"`, `None` for `Terminated`); **no receive scan position is stored on `Process`** (pure-FIFO mailbox, transient `QueueCursor`); `collector() -> &beam_gc::AnyCollector`.
- **Owned off-heap binaries** — a second, process-owned `beam_gc::OffHeap` (never swept with the message-transit one): one slot per payload, deduped on `data_ptr` through `owned_binary_index` (O(1)). Readers `off_heap_binary`/`off_heap_binaries`/`off_heap_binary_count`, **`owned_off_heap()`** (the roster handle `beam_gc::HeapFootprint::of` takes), **`off_heap_binary_bytes()`** (the host-asserted **`set_off_heap_binary_bytes`** figure when installed, else the roster sum), `declare_off_heap_binary_dead(slot)`. **Three sweeps:** `sweep_off_heap_binaries_reachable` (reachability-driven; declines — retains everything, `Ok(0)` — for a process with unpublished roots), `sweep_off_heap_binaries` (declared-dead) and `retain_off_heap_binaries(predicate)` (the one release funnel all three use). [`NOTES.md` §process.rs.]
- **Split borrows:** `heap_and_off_heap_mut()` (drives `beam_message::Fragments::move_into`, the only way to move a fragmented payload onto the heap) and `heap_and_mailbox_mut()` (drives `beam_message::send_fragmented`) — disjoint-field destructuring in safe Rust, never a combined raw-pointer accessor. A queued message contributes **three** roots — `payload()`, `from()`, `token()` — written back via `Message::with_payload`/`set_from`/`set_token`, so the whole envelope (off-heap handles, refc binaries, node entries, `Fragments` chain) survives. Heap and nursery observables: `NOTES.md` §process.rs.
- **Collection doors**, all through the private `run_rooted_collection` (fixed root list regs → each message's `payload`/`from`/`token` → dict → saved args → signals; every region written back even on `Err`): `collect()`; `collect_kind(kind)` — **exactly** that kind, never choosing and never escalating; `ensure_capacity(need_words)` — collect once, then grow to the smallest curated size covering the request; `collect_if_needed(need) -> Result<bool>` — `Ok(false)` when `admission_requires_collection` says no; `grow_nursery(need_words) -> Result<usize>` — the **no-relocation** growth passthrough.
- **Relocation exemption + decline gate.** `set_relocation_exempt`/`is_relocation_exempt` marks a host holding live terms outside the root set: while exempt `deliver` surfaces the raw refusal, `collect`/`collect_kind`/`ensure_capacity` raise `relocation_exempt: <what>`, `collect_if_needed` answers `Ok(false)`, the reachability sweep declines, and only `grow_nursery` stays usable. The relocating doors test **only** this flag (no `Running` check, no re-entrancy guard), so a host calling one mid-slice must have published its roots first. `has_unpublished_roots()` is the crate-owned O(1) half — `relocation_exempt || state == Running` — tested **first** at every delivery-driven site; the host half is the additive `CollectionGate { fn declines_relocation(&mut self, receiver: &Process) -> bool; }` (`ProcessTable::set_collection_gate`/`take_`/`has_`), OR-ed after it and consulted only when the crate half does not already decline. `true` declines only the relocation, so a `grow_nursery` or a fragment delivery still proceeds.
- **`deliver(from, term, src_off_heap) -> Result<DeliverOutcome>`** copies `term` into the young heap through a fresh per-send staging table, enqueues, then `wake()`s (`deliver_simple` = no-off-heap form; `receive(pred)` delegates to `beam_message::receive`). A declined delivery returns the raw `AllocKind::Heap`/`Message` refusal unchanged (no collection, growth or retry) — what the host's fragment fallback keys on.
### `scratch.rs` — the reused per-collection buffers (crate-internal, `pub(crate)` only)
- `CollectionScratch` — the **only** owner of the three allocations one rooted collection needs: `roots: Vec<Eterm>`, `drained: Vec<Message>` (messages taken out of the mailbox while their envelope words are roots, re-installed afterwards in FIFO order) and `reachable: HashSet<usize>`. `pub(crate)` plumbing behind `Process`; `new()` allocates nothing.
- The **sole accessor** `begin(&mut self) -> ScratchBuffers<'_>` **clears all three buffers unconditionally** and lends them as disjoint field borrows (private fields, so a dirty scratch cannot be constructed and no buffer seeded before it has been cleared); the clear keeps each buffer's capacity.
- **Clear-before-seed is a MEMORY-SAFETY rule:** a stale root word is a **wrong root set**, a stale `Message` a **duplicated/dangling message** (it owns a `Fragments` chain and the refcounts of what it copied), a stale `usize` in `reachable` a **payload retained though nothing names it**. The clear happens **before anything is seeded, on both arms**; whole-`self` predicates (`has_unpublished_roots()`) are computed **before** the split. Pinned by `tests/collection_scratch_reuse.rs`.
### `max_heap.rs` — the per-process `max_heap_size` policy (setting · accounting · verdict)
- The authoritative model of the C's `MAX_HEAP_SIZE(p)`/`MAX_HEAP_SIZE_FLAGS(p)` pair and its `check_max_heap_size` decision: types and arithmetic only, **no** process mutation and no termination (the host performs the verdict).
- `MaxHeapFlags { kill, error_logger, include_shared_binaries }` (`Default` = kill on, error_logger on, shared binaries excluded) — the flags select the **exceed behaviour**, not the bound; `error_logger` is independent of `kill`.
- `MaxHeapSetting { size: usize, flags }` — `size` in **words, stored raw**; `size == 0` is the C's *no upper bound*; `unlimited(flags)`, `is_unlimited()`, `violates_floor(min_heap_words)` (the oracle's `size != 0 && size < min_heap_size` rule, single-sourced for the two call sites), `verdict(usage)` (**strict-`>`**: a charge exactly equal to `size` is within).
- `MaxHeapUsage { heap_words, off_heap_binary_bytes }` — `heap_words` is the total heap **capacity** (nursery chain + mature, the oracle's `Total Heap Size`), not the occupied words; `charged_words(flags)` adds `ceil(off_heap_binary_bytes / size_of::<Eterm>())` only with `include_shared_binaries`, saturating. [`NOTES.md` §max_heap.rs.]
- `HeapLimitVerdict { Within, Kill, Log }` — `Kill`: the host must **self-exit the process with the bare atom `killed`** (not `kill`, not an exception; a trapping linked peer sees `{'EXIT', Pid, killed}`). `Log`: an `=ERROR REPORT====` with `Context: maximum heap size reached`, after which the process keeps running. There is deliberately **no** `Raise` variant — the oracle has no exception path here. `is_breach()`.
- `Process` side: `set_max_heap_size`/`max_heap_size` (wholesale replacement), `max_heap_usage`, `heap_limit_verdict(prospective_words)`/`current_heap_limit_verdict`, `max_heap_verdict`/`take_max_heap_verdict` (the latch), and the private `record_max_heap_verdict` at the **tail** of `collect`, `collect_kind`, `ensure_capacity` and `grow_nursery`.
### `dict.rs` — the per-process dictionary
- `Dict` (`Default`) backs `erlang:put/2`/`get/1`/`erase/1` (last put wins, `put` returns the replaced value) with `new()`/`with_atoms(Rc<AtomTable>)` and the never-panic GC pair `gather_roots`/`scatter_roots`. `None` is the C `THE_NON_VALUE` (the BIF layer maps it to `undefined`); keys — and, for `get_keys_for_value`, values — compare with `beam_term::compare::eq` (structural `=:=`), so a boxed key matches a distinct-but-equal term. Iteration is insertion-ordered — a documented deviation from the C's hash order, unpinnable by a differential case. [`NOTES.md` §dict.rs.]
### `fragments.rs` — saved BIF/NIF arguments
- `SavedArgs` (`Default`) — the saved BIF/NIF argument root list (the C `ErlSaveCallArgs`): `push`/`pop`, `as_slice`/`as_mut_slice`, `len`/`clear` plus the GC pair (the root region after the dictionary, before the pending signals).
### `run_queue.rs` — the ready queue (four priority levels)
- `Priority { Max=0, High=1, Normal=2, Low=3 }` (`Copy + Ord + Hash`; `Default = Normal`); the derived `Ord` is the C *numeric* order, **NOT** scheduling precedence — precedence is `LEVELS = [Max, High, Normal, Low]`; `index()/from_index(u8)`; `name()/from_name(&str)`.
- `RunQueue` — four per-priority FIFOs; `dequeue` serves the highest-priority non-empty level, FIFO within a level; `enqueue(pid)` ⇒ normal (`enqueue_with_priority` otherwise); `reprioritize(pid, Priority)` moves an already-queued pid to the tail of the new level (never double-enqueues, never inserts a non-queued pid); `split_off_half() -> Vec<ProcessId>` removes up to half the pids (highest priority first) so a stealing victim keeps at least half.
- **Fairness deviation (documented):** the C lets NORMAL and LOW share one physical queue, deferring LOW by `RESCHEDULE_LOW = 8`; four distinct FIFOs here mean LOW runs only once MAX/HIGH/NORMAL are empty — relative precedence unchanged.
### `scheduler.rs` — the single-threaded scheduler loop + the engine seam
- `RunOutcome { Yield, Wait, Suspend, Exit(Eterm) }` — what happened in a reduction slice; `ProcessRunner { fn run(&mut self, pid: ProcessId, table: &mut ProcessTable, budget: u32) -> Result<RunOutcome> }` — **the engine seam** (`beam_engine` is NOT a dependency; `beam_rt` implements it over an `ExecutionContext`).
- `Scheduler` — `new()` defaults `DEFAULT_REDUCTIONS_PER_SLICE = 4000` (override `with_slice(u32)`); optionally owns a `PortTable` (`with_ports`/`set_ports`/`take_ports`/`ports(_mut)`/`has_ports`). Entry points: `enqueue`(⇒ normal)/`enqueue_with_priority`, `progress()/progress_mut()`, `set_priority(&mut self, table, pid, priority) -> Result<()>` (PCB priority plus, **iff** already queued at a different level, a move to the new level's tail — the C requeue; `TermNotFound` leaves the queue untouched), `run_slice`/`run_ready`/`resume_woken` and their `_with_ports` forms.
- A slice pops one pid, services its pending signals (schedule-in — a fatal signal can terminate it, which then runs zero reductions) and runs one slice: `Yield` ⇒ requeue at the tail of the process's **own** current priority; `Wait`/`Suspend` ⇒ leave the queue; `Exit(reason)` ⇒ terminate (via `terminate_with_ports` when a port table is owned); afterwards (and on the empty-queue early return) it absorbs the table's wake list. `run_ready(…, max_slices: Option<u64>) -> Result<u64>` runs until the queue empties or the bound is hit.
- **`resume_woken(&mut self, table) -> usize`** — the resume-on-send half — moves the wake list into the scheduler's own reusable `woken` scratch (`ProcessTable::drain_woken_into`, so neither buffer reallocates) and enqueues each still-live `Runnable` pid not already queued **at its own priority** (the hook `beam_rt` calls after a send made **outside** a slice; a send inside a slice is absorbed at slice end).
- **Pre-emption is cooperative:** the runner receives the slice budget and owns the reduction count (the scheduler never reads or resets `Process::reductions`). [`../CONTEXT.md` Known Issues.]
- **Shared slice helpers (the SMP reuse seam):** `pub(crate)` `slice_begin(pid, table) -> Result<bool>` (mark executing + apply queued signals), `slice_end<F>(pid, table, outcome, enqueue)` (schedule-out), `run_one<R, F>(…)` = both plus one full-budget runner call, `drain_woken_into<F>(table, enqueue)` and the capacity-retaining `drain_woken_scratch_into<F>`/`resume_woken_scratch_into`; the `*_with_ports` mirrors share private `*_inner` bodies. The SMP pool reuses them (splitting a slice into lock quanta) with a closure that buffers requeues.
- `beam_rt`'s orchestration contract (spawn ⇒ `spawn_default` + `enqueue`; a runner blocking on an empty receive sets `ProcessState::Waiting` **before** returning `RunOutcome::Wait`; run ⇒ `run_ready(&mut table, &mut runner, None)`) is in the module rustdoc.
### `smp/` — the multi-scheduler (SMP) pool
- N scheduler threads over one shared process table, per-scheduler run queues + work stealing, the `ThreadProgress` barrier, the `TimerService` and the two `DirtyPool`s. Crate-root re-exports `SchedulerPool`, `SchedulerConfig`, `SchedulerStats`, `SchedulerStat`, `SharedProcessTable`. The full API surface, the per-file routing table, the **BINDING locking discipline**, the bounded-quantum rule (`run_locked_quanta`, `set_lock_quantum`) and the `unsafe impl Send/Sync` handoff live in **`smp/CONTEXT.md`**.
### `timer.rs` — the high-level timer service
- `TimerService` — one background thread over a deadline min-heap; `TimerRef { id, generation }` (`Copy`); `TimerSink: Send + Sync { fn timer_fired(&self, target: ProcessId, message: Eterm); }`. Delivery mechanism only (`send_after`/`start_timer`/`cancel_timer`/`read_timer`/`receive … after T` are BIF/engine-side). **Message contract:** the stored message must be **thread-valid** — an immediate or a literal-area/interned term; a heap-resident term is a caller contract violation.
### `dirty.rs` — the two dirty scheduler pools
- `DirtyKind { Cpu, Io }` (`ALL`, `name()` = `"dirty_cpu_scheduler"`/`"dirty_io_scheduler"`); `DirtyOutcome { Done, Reschedule(ProcessId), Deliver { target, message } }` — routing data the normal scheduler acts on; `DirtyJob = Box<dyn FnOnce() -> DirtyOutcome + Send + 'static>`, carrying no live heap data; `DirtyCompletionSink: Send + Sync`; `DirtyPool` (`start(cpu, io)`, `set_sink`, `cpu_schedulers()`/`io_schedulers()`, `schedulers(kind)`, `submit(kind, job)`, `pending(kind)`, `shutdown()`, `join()`). A kind with 0 workers buffers jobs (never dropped on submit, discarded at join); a panicking job does not kill the pool.
### `progress.rs` — thread progress (the cross-scheduler barrier)
- `ThreadProgress` (`generation`, `bump() -> u64`, `wait(u64)`, `safepoint()` = `bump`+`wait`, `managed_thread() -> ManagedThread`, `managed_count`, `set_waker`, `is_blocking`/`block`/`unblock`/`blocking_count`) — the real barrier; cheap to clone, every clone sharing the generation, the managed-thread registry and the blocking counter. `ManagedThread` is the per-thread slot a scheduler registers (`progress`, `update`, `is_active`/`set_active(bool)` — an inactive/parked thread is already at a safepoint and excluded from the wait — `id`).
### `signal.rs` — exit signals, reasons and signal-message builders
- `SignalAtoms { exit, down, process, port, normal, kill, killed, noproc, system }` — the well-known atom indices for signal messages; `from_table(&mut AtomTable)` interns them all; `system` is the `Message::from` immediate of a failed-by-name monitor DOWN.
- `ReasonClass { Normal, Kill, Other }` + `SignalAtoms::classify(reason)`; `ExitFamily { Explicit, Linked }`; `ExitSignal { from: ProcessId, reason: Eterm }` (`Copy`); `ExitPolicy { Terminate(Eterm), Trap, Ignore }` (`Trap` = deliver `{'EXIT', From, Reason}` as a message) and `exit_policy(reason, trapping, family, atoms) -> ExitPolicy`: `untrappable = family == Explicit && class == Kill`; then `!untrappable && trapping` ⇒ `Trap`; else `Normal` ⇒ `Ignore`; else `untrappable` ⇒ `Terminate(killed)`; else `Terminate(reason)`.
- Consequences to preserve: `kill` is untrappable and rewritten to `killed` **only** in the `Explicit` (`erlang:exit/2`) family; a `Linked` exit of reason `kill` **is** trappable and otherwise terminates with the reason **unchanged**; `normal` is ignored by a non-trapping receiver in both families; the C's `ERTS_SIG_LNK_X_FLAG_NORMAL_KILLS` escape is deliberately not modelled, and a monitor `{'DOWN', …}` never consults this policy.
- `ReceiveApplicability { Apply, Discard, Stop }` + `receive_applicability(signal, trapping, atoms)` — the receive-time reading (`Trap ⇒ Apply`, `Ignore ⇒ Discard`, `Terminate ⇒ Stop`, a `Down` unconditional `Apply`), pure and derived from `exit_policy`, so a receive scan and the schedule-in path cannot disagree (unit-tested over the whole `{normal,kill,other} × {Explicit,Linked} × trapping` matrix).
- **Signal-message builders** (each allocates on the receiving heap; the rustdoc lists them all): `build_exit_message`/`build_exit_message_term` (`{'EXIT', From, Reason}`; the `_term` form's `from` may be an external pid term); `build_down_message` (`{'DOWN', Ref, process, Pid, Reason}`, or `{Tag, …}` with a user tag), `build_down_message_port` (the `port`-kind form), `build_down_message_remote` (materialises the external-pid target on the same heap) and the general `build_down_message_term(…, kind: Atom, target: Eterm, reason)`; `kind` is the 3rd-element kind atom (`process`/`port`), distinct from the caller's `user_tag` (which replaces the head atom).
### `signal_queue.rs` — the decoupled per-process pending-signal queue
- A signal is queued on the receiver and applied later; its `reason` is copied into the receiver's own heap at enqueue, so the queue is an in-heap sub-rootset. `PendingSignalKind { Exit, Down }`; `PendingSignal { Exit { from: ProcessId, reason: Eterm, family: ExitFamily }, Down { reference: MonitorRef, target: ProcessId, kind: MonitorKind, tag: Option<Eterm>, reason } }` (`Copy`) with `exit(from, reason, family)` / `down(…)` and `kind()`/`tag()`/`reason()` — an exit stores its `ExitFamily` verbatim (the queue applies no trap rule; `ptab.rs::apply_head_signal` reads it and consults `exit_policy`), and `tag` is the `monitor/3` user tag.
- `SignalQueue` (a `VecDeque<PendingSignal>`, `Default`) is the per-process FIFO plus the GC pair `gather_roots` (one word per queued reason) / `scatter_roots`; monitor references are stored by value. **Ordering:** a total FIFO per receiver (subsuming the C's per-`(sender, receiver)` order); **not** cross-ordered with the mailbox.
### `link.rs` — bidirectional links
- `Links { pids: Vec<ProcessId> }` — `add(pid) -> bool` (false if already linked), `remove(pid) -> bool`, `contains(pid)`, `iter()`, `drain()`.
### `monitor.rs` — monitors and monitor references
- `RefAllocator` — the reference mint: a **zero-sized handle** onto the runtime's one process-wide local reference-id space (`beam_common::next_ref_id`), `new()` + `next() -> MonitorRef`. It holds **no counter of its own** (no start value, no band, no `u64` field), so every draw — this crate's monitors/aliases *and* `erlang:make_ref/0`, the NIF `make_ref`, timers, `seq_trace` and NIF resource terms — comes from one monotone source (`tests/reference_ids.rs`). `next()` stays total; the encodable bound (`MAX_SMALL`) is checked at `MonitorRef::to_eterm`, the one `SystemLimit` gate.
- `MonitorRef { id: u64 }` (`Copy + Eq + Hash`). `from_id(id: u64) -> MonitorRef` is the one **non-mint** constructor: it names an explicit, caller-derived id (today the unnamed-ETS-table tid, which must be the table handle so the table-taking BIFs decode it back), draws nothing from the shared space and consumes nothing (`tests/reference_ids.rs::from_id_consumes_no_shared_id`) — its uniqueness is the caller's claim. `to_eterm(self, heap)` writes the on-heap `Ref` thing through `beam_term`'s checked `write_internal_ref` (`Alloc` when full); `from_eterm` parses the frozen `[header, node, serial, id]` thing (`BadArg` otherwise — the send path's destination→key step). [`NOTES.md` §monitor.rs.]
- `UnaliasMode { ExplicitUnalias, Demonitor, ReplyDemonitor }` (`Copy + Eq + Hash`) — the `{alias, Mode}` mode of `monitor/3`/`alias/1` (atom→mode parsing is the BIF layer's). `AliasEntry { owner: ProcessId, mode: UnaliasMode }` (`Copy`) — one `ProcessTable` alias entry (the process a message sent to the reference is delivered to); plain values, not a GC root.
- `MonitorKind { Process, Port }` — `type_name()`/`from_type_name(&str) -> Option<MonitorKind>` back the `erlang:monitor/2` dispatch (any other name ⇒ `None` ⇒ the caller's `badarg`). `PortWatch { reference: MonitorRef, port: PortId }` (`Copy`) — the outgoing half of a port monitor, held in `Process::port_monitors`; plain values, not a GC root.
- `Monitor { reference, target: ProcessId, kind }` (outgoing) / `MonitoredBy { reference, watcher: ProcessId, kind }` (incoming) — field sets **frozen** (constructed by struct literal from `beam_rt`, so no field may be added); hence the `monitor/3` user tag lives in a `ProcessTable` side table. `Monitors { entries: Vec<Monitor> }` — `push`, `remove(reference)`, `find(reference)`, `iter`, `drain`.
- `payload_is_down_for(payload, reference, down_atom) -> bool` — the guarded `{'DOWN', Ref, _, _, _}` shape test `demonitor_flush` scans mailboxes with (one `unsafe` block, no out-of-bounds read). The element-1 block must carry **both** `REF_SUBTAG` and the ref payload arity (the subtag alone is also worn by the arity-2 block, which has no id slot), and the id test is total/sign-safe.
### `ptab.rs` — the process/port table + name registry + signal/link/monitor hub
The one place that mutates ≥2 processes (the C ptab lock domain), via the crate-level **collect-then-apply worklist**; single-threaded in M1, holding `Process` values directly (`PortTable` lives in `port.rs`). The module rustdoc lists every entry point.
- `ProcessTable { slots, free, names: HashMap<Atom, ProcessId>, refs: RefAllocator, atoms: SignalAtoms, ready: Vec<ProcessId>, remote_links, remote_monitors, remote_watchers, group_leaders, named_monitors: HashMap<MonitorRef, NamedTarget>, local_node: Option<Atom>, router: Option<Box<dyn DistSignalRouter>>, collection_gate: Option<Box<dyn CollectionGate>> }` (`Slot { serial, process }`; `refs` = the zero-sized `RefAllocator` over `beam_common::next_ref_id`).
- `ready` is the **wake list** (`drain_woken` returns **and** clears, `drain_woken_into(out)` moves it out retaining both allocations, `woken` peeks); `router` = the distribution seam (`None` ⇒ record-only); `collection_gate` = the host gate, read by the private `declines_signal_collection(pid)` (crate predicate first).
- `remote_watchers` (incoming remote-monitor records) and `group_leaders` are keyed by local pid and add no field to the frozen shapes; `terminate_into` drains both (one best-effort `DistSignal::MonitorExit` per watcher) and `node_down` purges `remote_watchers`.
- `alloc_pid` reuses a free slot and bumps its serial (`SystemLimit` on exhaustion); `take` bumps the serial and drops the wake entry. Reservation entry points (`reserve_remote`/`reserve_identity`/`spawn_reserved`/`cancel_reservation` + the `reserved_*`/`free_count`/`slot_count` diagnostics) keep `alloc_pid` off claimed numbers, and `insert` drops a claim at its number — see `reserve.rs`.
- `link(a, b)` has set semantics; a non-live `b` with a live `a` records no link and signals `noproc` (a trapping `a` gets `{'EXIT', b, noproc}`, else it dies with the bare atom `noproc`; the oracle raises `error:noproc` — an approximation owned by `beam_rt`). `TermNotFound` only when `a` is unknown. `terminate`/`terminate_with_ports` are best-effort per peer (a failed signal or `route` is dropped-and-logged): the exit observer and the port-monitor cleanup always run, `TermNotFound` is the only `Err`, and the port form also removes the outgoing `port_monitors`' matching incoming entries.
- `monitor(watcher, target: ProcessId, kind) -> Result<MonitorRef>`; a non-live target with a live watcher ⇒ `Ok(ref)` + an immediate `{'DOWN', Ref, process, Target, noproc}`. `demonitor`/`demonitor_flush` (`flush` also drops a queued `{'DOWN', …}`). `monitor_named` + `set_local_node`/`local_node` implement `monitor(process, Name)` (DOWN target `{Name, node}`; no local node ⇒ `unsupported`). `monitor_term`: pid → `monitor`, atom → `monitor_named`, external pid → the remote record + route, port term ⇒ `BadArg` under `MonitorKind::Process` / `unsupported` under `MonitorKind::Port` (use `monitor_port_term`), else `BadArg`; `monitor_port(_term)`/`demonitor_port` are the port forms. A target's death removes the watcher's outgoing `Monitor`.
- **`monitor/3` options:** `MonitorOptions { tag, alias }` + the `*_with_options` points; the `*_with_tag` points take `tag: Option<Eterm>` and delegate with `alias: None`, and `Some(tag)` makes the DOWN `{Tag, Ref, Kind, Target, Reason}`. A `MonitorRef` may name an **alias** (`{alias, Mode}`, `alias/1`, `unalias/1`) resolving to its owner, held in the private `aliases` side table — never in the frozen structs. [`NOTES.md` §ptab.rs.]
- **Signal hub:** `service_signals(pid)` drains and applies the queue FIFO, cascading (schedule-in; empty/unknown ⇒ no allocation); `service_signals_with_ports` also cleans incoming port monitors; `service_receive_signals(pid)` is the receive-scan reading (receive-applicable heads FIFO, an `Ignore` head discarded, stopping before the first `Terminate` head, no cascade, no `PortTable`).
- `node_down(node, reason)` purges every remote relationship with `node` (outgoing monitors → outgoing links → record purge) in the **link** family with the caller's immediate: trapping peers trap `{'EXIT', RemotePid, noconnection}`, others die with exactly `noconnection`; all three record directions are covered, including the incoming `remote_watchers`, snapshotting before applying. `port_closed(&mut PortTable, port, reason)` drains owner/links/monitors, delivers `{'DOWN', Ref, port, Port, Reason}`/`{'EXIT', Port, Reason}`, and terminates non-trapping linked peers via `terminate_with_ports`.
- `register(name, pid)` is `BadArg` for a taken name or a non-live pid; `unregister` `BadArg` for an unknown name; `whereis`/`registered`/`name_of(pid) -> Option<Atom>` (live-only; the `process_info(P, registered_name)` lookup), `is_process_alive(pid)` = table membership, `exit_reason(pid)` live-only; `ExitEffect { Terminated, Trapped, Ignored }` for `apply_exit_signal`.
- Eager-vs-queued, the `ExitFamily` tagging and fragment exhaustion are the crate-level rules (`../CONTEXT.md`) and are not restated here: the sites in this module only pick a family (`apply_head_signal` re-reads the queued one; `Explicit` for `apply_exit_signal`/`send_exit`/`send_exit_term`; `Linked` for `terminate_into`'s link loop, `node_down`, `port_closed`) or a refusal route (`enqueue_fragment_signal`, `deliver_down_fragment`/`deliver_exit_fragment`). An inbound receipt reason is materialised on the recipient before embedding, so a reason decoded off the host's per-drain arena never reaches a mailbox by pointer. [`NOTES.md` §ptab.rs; `PERF.md`.]
### `reserve.rs` — the distributed-spawn reservation seam
- `Reservations` (per-table claim store: a fresh-instance tag from a static atomic, a monotone id with checked add, the claimed identities by id, the reverse number index) with `claim`/`validate`/`release`/`release_number`/`is_reserved`/`pids`/`len`/`is_empty`; `Reservation { id(), pid(), number(), serial() }` is a `Copy` handle carrying its issuing table's tag, so a foreign-table handle is `badarg` even when id spaces collide; `pub(crate) check_identity` (`SystemLimit` past `MAX_PROCESS_NUMBER`/`MAX_PROCESS_SERIAL`) and `check_local_node` (`BadArg` when unset or different).
- Plain values only: no term, no heap, no GC root, no `unsafe`, `Rc`-free and `Send + Sync` (pinned), so `SharedProcessTable`'s `unsafe impl Send/Sync` keeps holding. `release` is the single release funnel; `ProcessTable::release_reserved_number` is the only place a number returns to the reuse list — at most once, only for an existing empty slot. There is no `Drop`: a reservation is explicitly consumed (`spawn_reserved`) or cancelled (`cancel_reservation`), so a stale, consumed, cancelled or foreign handle can never install a process and never leaks a number or slot. The reply contract (`{spawn_reply, Ref, To, Flags, From}`) is in the module docs.
### `exit_observer.rs` — the process-death observer seam
- The host hook for per-process resources this crate does not own (the ETS tables a pid owns are the motivating case): a trait object on the table, implemented downstream; with none installed (`None`) behaviour is unchanged.
- `ProcessExitObserver { fn process_exited(&mut self, exit: &ProcessExit<'_>); }` — called **exactly once per death** from `terminate_into`, after the death has been propagated and **before** `drop(process)` (so `reason`, which may live in the dying heap, is still valid); no `Send` bound. `ProcessExit<'a>` is private fields plus read-only accessors, built only by the finalizer: `pid` (an immediate ⇒ retainable), `reason` (an observer that retains it must copy it), `name: Option<Atom>` (captured before the registry entry is dropped), `port_monitors: &'a [PortWatch]`.
- A panicking observer is contained with `std::panic::catch_unwind(AssertUnwindSafe(...))`, reported via `beam_common::beam_error!`, and termination still completes; implementations run on the finalizing scheduler thread and should be cheap.
### `remote.rs` — remote (external-node) links and monitors
The local record of a process's relationships with processes on other nodes; the wire format is `beam_dist`'s, reached through a trait seam (this crate never depends on `beam_dist`).
- Decompositions, all `Copy` and all-immediate (never a GC root, no boxed pointer into another heap): `RemotePid { node: Eterm, number: u32, serial: u32, creation: u32 }` (`from_eterm` is `BadArg` unless an external pid; `to_eterm(self, &mut Heap)`), `RemoteRef { node, ids: [u32; MAX_REF_IDS], n_ids: u8, creation }`, `RemoteWatcherRef { Local(MonitorRef), Remote(RemoteRef) }` (the identity a `RemoteWatcher` is keyed by — the variants never collapse), `PidTarget { Local, Remote }`, `RemoteMonitor { reference, remote, kind }` (outgoing) and `RemoteWatcher { reference: RemoteWatcherRef, watcher: RemotePid, kind }` (the incoming record an inbound `DOP_MONITOR_P` installs).
- `DistSignal { Link { from, to }, Unlink { from, to }, Monitor { watcher, target, reference, kind }, Demonitor { watcher, target, reference }, Exit { from, to, reason }, Exit2 { from, to, reason }, MonitorExit { watched, watcher, reference: RemoteWatcherRef, reason } }` — the control signal the runtime routes: `Exit` is a link exit → `{DOP_EXIT, From, To, Reason}`; `Exit2` is `erlang:exit/2` → `{DOP_EXIT2, …}` (a distinct opcode with distinct receipt semantics); `MonitorExit` is a watched local process's death → `{DOP_MONITOR_P_EXIT, Watched(local), Watcher(remote), Ref, Reason}` — **watched first**, the reverse of the monitor family. The full `DOP_*` mapping is on the module.
- `DistSignalRouter { fn route(&mut self, signal: DistSignal) -> Result<()>; }` — the distribution seam, implemented downstream over `beam_dist`; `route` must serialise **synchronously** (`reason` may live in the signaller's heap). Its transport error propagates out of the relationship ops (`link_term`/`unlink_term`/`monitor_term`/`demonitor`/`node_down`) but **not** out of a dying process's termination. **This seam is OUTBOUND only** (local → remote): it never consumes a control message.
- The crate also owns the inbound (receipt) **primitives** — route-free `ProcessTable` methods taking a `DOP_*`'s already-parsed pieces, which must NOT be routed: `record_remote_link`, `apply_remote_exit_signal`, `unlink_from_remote`/`unlink_ack_from_remote`, `monitor_from_remote`(/_ref)/`demonitor_from_remote`(/_ref)/`remote_watchers`, `remote_monitor_down`, `set_group_leader_from_remote`/`group_leader`, plus `next_reference`. The `_ref` spellings key a `RemoteWatcher` by the whole peer-minted identity, so two distinct peer references never collapse; decoding the wire and choosing the primitive is `beam_rt`'s. [`NOTES.md` §remote.rs.]
### `port.rs` — the port-id table + ownership / link / monitor surface
- `PortTable` is the number table the C keeps alongside the pid table, extended with the relationships a dying port must resolve; port *behaviour* (driver, scheduling, read path) is `beam_io`'s. `PortMonitor { reference: MonitorRef, watcher: ProcessId }`; `PortClose { owner: Option<ProcessId>, links: Vec<ProcessId>, monitors: Vec<PortMonitor> }`.
- `PortTable { slots: Vec<bool>, free, owners, links, monitors }` — `alloc()` (`SystemLimit` on exhaustion), `alloc_owned(owner)`, `release(PortId)` (frees the number and drops every relationship), `close(PortId) -> Result<PortClose>` (frees the number, returns **and clears** owner/links/monitors; unknown id ⇒ `BadArg`), plus the ownership (`owner`/`set_owner`/`clear_owner`), links (`link` — deduped — /`unlink`/`links`) and monitors (`monitor`/`demonitor`/`monitors`) accessors. Every relationship mutation on an unallocated id is `BeamError::BadArg`; `ProcessTable::port_closed` is the one-call orchestrator.
### `error.rs` — `pub(crate)` constructors only (no new error enum)
- The one place this crate spells its failures; every fallible path still returns `beam_common::BeamError`, and `src/error.rs`'s per-constructor docs are authoritative. Families:
- **not-found** — `unknown_process()` (`TermNotFound`; also an unregistered name or a dangling monitor reference).
- **badarg** — `bad_pid()` (malformed pid/port, out-of-range register index, `register/2` of a non-live pid), `name_taken()`, `bad_arg()` (a wrong-shaped term, e.g. a malformed external reference).
- **system-limit** — `system_limit()` (pid/port number-space exhaustion).
- **typed capability gaps** — `unsupported(what)` plus `named_port_monitor()`, `unsupported_port_monitor_alias()` and `unsupported_tag()`, each a `BeamError::Raise` whose reason atom is `unsupported: <what>` (never a silent default, never a wrong result).
- **relocation refusal** — `relocation_exempt(what)`, likewise a `Raise` with reason atom `relocation_exempt: <what>` (there is no `CollectionKind::None`, so the refusal cannot be a fake `Collection`). Heap exhaustion is not modelled here: it is the underlying `BeamError::Alloc` propagated after a collect-and-retry.

## Notes for Agents (module level)
- The module-level agent notes (the GC root set, the `Registers`/FR hand-off, PCB/heap address stability, pre-emption as the runner's obligation, the split borrows, the SMP `!Send` workaround, the oracle-probe rule) are stated in full in `NOTES.md` §module-notes.
- **Who can mutate a published root array (length vs contents).** The *length* of `Registers::stack` changes through exactly one accessor — `Registers::stack_mut()` → `Stack::{push,pop,clear,truncate}` — and **no production code in this crate calls it**; filling it is the host's publish step. *Contents* are rewritten in place by `run_rooted_collection`'s `scatter_roots` call, length-preserving and slot-exact (x prefix, then `stack.len()` words, then the extra-root tail, each `min`-clamped).
- **A parked-but-not-exempt process IS a legal relocation target.** `has_unpublished_roots()` is `relocation_exempt || state == Running` only, so a `Waiting`/`Runnable` pid whose roots the host published is *not* gated: another process's `deliver` or a signal builder can collect its heap and rewrite `regs` **in place with the lengths unchanged**, while the host's own `RootSet` copies stay at their pre-collection words. The host must read the relocated words back out of `Process::registers()` at resume — a length check cannot catch a write-back of its own stale copies, which surfaces later as a dangling term.
- **No fragment is ever pushed on the Erlang stack:** the exhaustion route builds a `beam_message::HeapFragment` owned by the enqueued `Message`, so nothing between a publish and a resume can change the published stack length.

## Notes for Agents — the GC relocation seam inventory (what exists, what does NOT)
- **No caller-supplied root set beyond `Registers::extra_roots`.** `run_rooted_collection` is private and takes the collection *action*, not a roots provider; the root list is fixed. There is **no** `collect_with`, roots-provider trait, mover/forwarding callback or post-collection fixup anywhere in this crate.
- **The root word list is the only mover interface.** `beam_gc`'s `copy::collect(from, to, roots: &mut [Eterm])` rewrites the root words **in place** and leaves a word pointing outside the evacuated range untouched, so a host term is relocatable only by putting its *word* in the root slice — an interior pointer, a `*mut Eterm` or a Rust-local copy stays stale. `Process::copy_into_heap` is `pub(crate)`: a host copy of a foreign term goes through `heap_mut()`/`heap_and_mailbox_mut()`/`heap_and_off_heap_mut()` plus `beam_message`'s copy engine.
- **Mutable write-back is per-family gather/scatter, not a `&mut` slot accessor** — `Registers`, `Dict`, `SavedArgs` and `SignalQueue` each expose `scatter_roots` (via `Process::{registers_mut,dict_mut,saved_args_mut,signals_mut}`); no `set_registers`, no per-family setter, so a host re-implements the region bookkeeping.
- **The mailbox is the one family with no in-place write seam:** `Queue` has `iter()` and **no `iter_mut`**, and `Message` writes only through `set_from`/`set_token` and the consuming `with_payload`. The supported route is drain → rewrite → re-enqueue in FIFO order; `Queue::enqueue`'s debug-only tripwire requires `from`/`token` to be **immediates**, so re-enqueueing a relocated heap `from`/`token` panics in a debug build.
- **Gather order is load-bearing:** regs (x, stack, extra roots) → each message's `[payload, from, token]` → dict → saved args → signals (matching `MESSAGE_ROOT_*`, `payload=0`/`from=1`/`token=2`); the hosts' ad-hoc off-heap gathers push `token` before `from` and the dict first. Every `scatter_roots` is total and length-tolerant, so a mis-ordered write-back is a dangling term, never an error.
- **One `&mut Process` at a time.** `ProcessTable::get_mut(&mut self, pid) -> Option<&mut Process>` is the per-process mutable door; `pids()` borrows `&self` over `slots`, so a pid list must be collected into a `Vec` first — no whole-table `iter_mut`. `SharedProcessTable::lock()` is the SMP route to the same.
