# `beam_process/tests` — integration evidence for the crate

## Intent
The cross-module integration tests pinning this crate's Milestone-1 guarantees (unit tests live in each `src/*.rs` module).
Each file is one topic and states, in its module docs, the guarantee it pins and how it is made non-flaky; nothing here is production code.
The 53 numbered entries are the 53 top-level `tests/*.rs` targets; `common/mod.rs` is the shared support module.

## How these tests run (gate + conventions)
- Gate: `erts_rust/scripts/cargo.sh test --manifest-path erts_rust/Cargo.toml -p beam_process` — always the wrapper (sandbox `$HOME` is read-only, so it sets a writable `CARGO_HOME`).
- The manifest path is mandatory (a bare `cargo -p <crate>` from the repo root cannot resolve the workspace); never `cd`; never touch `../../tools/`.
- Cross-checks against real ERTS belong to the sibling differential harness (`../../tools/differential/`); the `oracle_*` tests here are local probes of the system `erl` on `PATH`.
- `oracle_*` convention: ONE shared driver (`common/mod.rs`) runs `erl -noshell -kernel logger_level none -eval …` and normalizes the captured stdout, so a crashed probe helper's `=ERROR REPORT====` block can never make a comparison flaky; every such suite skips loudly when `erl` is absent.
- Anti-flakiness: every SMP/lock-scope/timer/dirty/progress assertion is forced by **synchronization**, never `std::thread::sleep`; `tests/lock_scope.rs` is the only wall-clock-bounded file (deliberately loose and two-sided); a wedged pool fails with a clear timeout instead of hanging.

## API Surface (what each file pins)
**Support module — `common/mod.rs`**: the shared `erl` oracle driver used by `alias.rs`, `registry_monitors.rs`, `dict_oracle.rs`, `monitor_tag.rs`, `lifecycle_oracle.rs`, `capability_inventory.rs` and `port_monitor_cleanup.rs` — `ERL_TIMEOUT`, `erl_stdout`, `expect_oracle`, `strip_logger_reports` (+ 4 normalizer unit tests), with `#![allow(dead_code)]`.

Single-threaded scheduler, mailbox, signals, GC roots, PCB state:
1. `scheduler.rs` (6 tests) — pid allocation (+ serial bump on reuse, stale-pid rejection); round-robin order (one slice each, requeued at the tail on `Yield`, `Wait` leaves the queue); resume-on-send (a blocked receiver re-enqueued in the same slice) + a two-process counter ping-pong.
2. `messaging.rs` (3 tests) — send into a mailbox, selective `receive` (FIFO, non-matches stay queued), `DeliverOutcome::Woke` vs `Enqueued`.
3. `signals.rs` (17 tests) — link exit propagation (non-trapping dies, trapping survives with `{'EXIT', A, Reason}`), monitor down-message, reason ownership (a structured reason survives the recipient's `Process::collect`), trapping peer, cascaded A→B→C link, `{'DOWN'}`, self-signal, a target's death resolving the watcher's outgoing monitor, and `link_to_a_non_live_pid_signals_noproc_from_it`.
   It also pins the **exit-family split**: a link exit of `kill` is trappable and delivered unchanged, while an explicit `erlang:exit/2` `kill` is untrappable and rewritten to `killed` (the cross-module rule lives in `../CONTEXT.md`; the C is `erl_proc_sig_queue.c:4740-4770`).
4. `gc.rs` (1 test) — safepoint GC over the process root set (x-register + stack + mailbox payload relocate while garbage is reclaimed).

6. `pending_signals.rs` (4 tests) — deferred (schedule-in) vs eager application, FIFO across senders, a structured reason surviving `collect`.
7. `preemption.rs` (7 tests) — reduction-quantum fairness (2/3/4 processes interleave strictly round-robin, within one slice of each other; `Wait` leaves the ready queue; `Yield` requeues at the process's **current** priority) plus the current-state limit that pre-emption is **cooperative only**: the schedule is invariant under the reduction budget, and the non-yielding-runner failure mode (which would hang the scheduler) is an `#[ignore]`d test — it cannot be exercised without hanging the suite.

39. `signal_fragment_fallback.rs` (8 tests) — the **heap-fragment fallback** at **both** refusal sites for a receiver with **unpublished live roots** (a relocation-exempt process or a `Running` one, `Process::has_unpublished_roots`): the **apply-time** build (`build_signal_message`/`deliver_head_signal` via `enqueue_fragment_signal`) and the **enqueue-time** reason copy (`copy_reason_onto` via `deliver_down_fragment`/`deliver_exit_fragment`). A refused payload is built on a 64-word scratch arena and copied **whole** into a fresh `beam_message::HeapFragment` the queued `Message` owns (the shared `enqueue_fragment_payload`, copying through the source process's off-heap table) instead of being lost — the C's model, `erl_proc_sig_queue.c`; the mechanism itself is owned by `../CONTEXT.md` and `../KNOWN_ISSUES.md`.
   A controlled experiment on a 7-word nursery drained one word short of the four-word head build, each case first asserting the refusal and that a refused request writes nothing: (1)/(2) an exempt watcher's `{'DOWN', Ref, process, Target, noproc}` and a trapping receiver's `{'EXIT', Dying, normal}` arrive exactly once, FIFO behind the filler, `compare::eq` to the expected tuple, fragment-resident, with the nursery observables unchanged; (3)/(4) the enqueue-time route for a reason one word larger than the **whole** nursery — never queued (`pending_signals` 0) yet delivered fragment-resident, waking a blocked receiver by the delivery itself; (5) the non-exempt contrast takes the grow-and-retry arm, so the fallback did not replace it; (6) the delivery half — `Process::deliver` to a `Running` receiver surfaces the raw refusal, while the host's `send_fragmented` through `heap_and_mailbox_mut` delivers fragment-resident; (7) the schedule-in half — a queued `noproc` DOWN refuses at the apply-time build in `service_signals` and lands fragment-resident; (8) the `ProcessState::Waiting` control collects, grows and is serviced **eagerly** — so the gate is the *running* state, not a blanket refusal.
   A **non-trapping** exempt receiver is not covered by the fallback (it would terminate) and stays a surfaced refusal — `signal_exhaustion.rs`. Deterministic: sizes from the public heap-policy arithmetic, no sleeps, no wall-clock bounds, no oracle.
40. `decline_gate.rs` (4 tests) — the **host collection gate** (`CollectionGate`) of `ProcessTable`: a host-installed `declines_relocation` predicate is consulted at every signal site (OR-ed with the crate-owned `Process::has_unpublished_roots`) and at `ProcessTable::deliver`, declining only the **relocation**, so the notification still arrives through the same heap-fragment route. Pins an oversized link exit and an oversized monitor DOWN delivered fragment-resident with the nursery untouched and the blocked receiver woken; the delivery half (the copy engine's raw `AllocKind::Heap`/`Message` refusal, the gate marking the receiver exempt for exactly one `Process::deliver`, the flag restored); the no-gate control that collects and grows. Every "did nothing" claim is checked against the receiver's own nursery observables. Seam contract: `../CONTEXT.md`, `../KNOWN_ISSUES.md`.
41. `reference_ids.rs` (10 tests) — **PIN — the reference-id space is ONE shared, process-wide source** (`beam_common::next_ref_id`), and `beam_process::RefAllocator` is a **zero-sized handle** onto it: a table or plain draw is exactly the shared counter's next id (serialized on a module `static TEST_LOCK`, since the counter is shared by the whole binary); two independent handles draw one strictly increasing sequence, not two from `0`; a table alias reference can never collide with an independent `make_ref/0`-shaped draw; the payload is compared word for word leaving only the id (the frozen `[header, node, serial, id]` layout facts, `node`/`serial` being `0`); a real draw encodes and decodes byte-exactly (the `MAX_SMALL` bound stays in `MonitorRef::to_eterm`).
   The **non-mint** `from_id` has three pins: it names its explicit id with the encoding still checked (`MAX_SMALL + 1`/`i64::MAX`/`u64::MAX` refused at the writer with `SystemLimit`, reserving no heap words, `from_id` itself total), it consumes no shared id (two bracketing draws), and its term equals a minted one only at a deliberately shared id.
   No absolute ids are asserted (the counter advances under every test in the binary), and there is no oracle cross-check: the oracle has **one** id space, so it cannot express "two producers, one id".
42. `off_heap_reachability.rs` (9 tests) — the **reachability-driven** liveness decision for the process-owned off-heap refc binaries (`sweep_off_heap_binaries_reachable`, over `AnyCollector::for_each_reachable_object_view` + the read-only `gather_scan_roots` root set, every object read through the **safe** `beam_gc::ReachableObject` view, so the sweep adds no `unsafe`; `run_rooted_collection` runs it automatically over the just-gathered roots).
   Pinned: a payload reachable through an on-heap `[BinRef][ErlSubBits]` handle, a nested tuple/list/flat-map value, or **any** root region (a queued `Message` payload, a dict value, a saved BIF/NIF arg, a `PendingSignal::exit(..)` reason — so `gather_scan_roots` cannot lag the collection's gather) is retained, while an unreachable one is reclaimed at refcount 0 with slot `None` and no double free; a process with unpublished roots (exempt or `Running`) is not swept (`Ok(0)`, every payload retained — the decline valve, since an incomplete root set could miss a live `BinRef` and dangle) yet a declared death is still honoured; the `MSO(p)` dedup and slot stability hold; a declared death wins over the verdict; a collection that relocates the handle keeps the payload's `data_ptr`.
43. `decline_gate_builders.rs` (13 tests) — the collection-decline path of the six `build_signal_message`-only builders (`deliver_noproc_down`, `deliver_named_noproc_down`, `enqueue_remote_down_message`, `enqueue_remote_exit_message`, `enqueue_port_down_message`, `enqueue_port_exit_message`), each through its public trigger (a born-down monitor, a named monitor on an unregistered name, `node_down` for a remote monitor and for a trapping remote link, `port_closed` for a port monitor and for a trapping port link) with a saturated nursery (three free words, one short of the four-word first allocation all six make).
   Each of the six gets one case under the **crate-owned** valve (a relocation-exempt receiver) and one under the **host** `CollectionGate` (the crate-owned predicate asserted false, so only the host could have declined), every case asserting a whole, FIFO, **fragment-resident** notification with the receiver's nursery untouched (`minor_gcs`, `base`/`used_words`, the mature used words). The thirteenth, `without_a_decline_each_builder_collects_and_grows`, is the **shared control** for all six — an on-heap message, one collection, no fragment — so the fragment route is an additional decline, never a replacement.
44. `alias.rs` (12 tests, 9 `oracle_*`) — **reference aliases**: `erlang:alias/1`/`erlang:unalias/1` and the `erlang:monitor/3` `{alias, Mode}` option, cross-checked against the real `erl`.
   A standalone alias (`create_alias`, no monitor behind it) resolves to its owner for a send and reports `true`/`false` out of `unalias`; `unalias` clears the alias and keeps the monitor. The **three expiry sites** — the target's DOWN, `demonitor/1`, the reply site (`alias_reply_delivered`) — are pinned one mode at a time: `explicit_unalias` survives both the DOWN and `demonitor/1`, `demonitor` expires at the DOWN, `reply_demonitor` at the DOWN **and** the reply.
   Also: a dying owner takes every alias with it; a standalone alias is not a monitor (probed through `demonitor(Ref, [info])`'s internal verdict, since `demonitor/1` renders the C's `am_false` as `true`); a monitor reference round-trips through its term and rejects every non-reference with `BadArg`; `monitor_term_with_options` routes every local dispatch through the alias path (a pid term → `monitor_with_options`, a name atom → `monitor_named_with_options` carrying the `{Name, Node}` DOWN target); a monitor-with-alias on an already-dead target registers the alias **before** the immediate `noproc` DOWN; a port monitor and a remote (external-pid) target each refuse the option with their own typed `unsupported`, leaking no relationship or message.
45. `collection_debt.rs` (4 tests) — the crate's own heap-admission point honouring the collector's **collection debt**: a fresh process carries none (`collection_debt()`/`should_collect(1)`/`admission_requires_collection(1)` false, `collect_if_needed(1)` ⇒ `Ok(false)`); a `grow_nursery(4096)` sets it while the current space is still roomy, and one `collect_if_needed(1)` collects once (`Ok(true)`, debt cleared, chain collapsed to one space) after which the next admission answers `Ok(false)` — the debt half is **self-limiting**.
   Eight "grow to twice the current capacity, then admit" rounds each end debt-free with one space and a **bounded** young capacity — bounded as a **period-3 cycle**, pinned as the *period* (`capacities[round] == capacities[round - CYCLE_ROUNDS]` past the fresh one) plus a peak bound, never a size, so a policy change that moves the sizes but keeps the loop bounded still reads correctly. The occupancy-only control that never collects blows up into a long space chain over the same rounds — the regression the debt OR removes; and a relocation-exempt process with debt answers `Ok(false)`, keeping the debt and its chain with `minor_gcs()` `0`.
46. `service_signals_fast_path.rs` (6 tests) — the **quiet-process fast path** of per-schedule-in signal servicing plus the capacity-retaining wake-list hand-over: a quiet schedule-in is a no-op (state, mailbox, links and heap unchanged, no wake queued, no collection), an unknown or **stale** pid is a no-op that does not disturb the process now owning the recycled slot, a queued signal is still applied in full (the fast path covers the empty case only), a queued **fatal** signal still drives the whole link cascade (its worklist grows while servicing), `drain_woken_into` agrees with the take-based `drain_woken` and clears rather than appends to its reused buffer, and the `Scheduler`'s reusable wake scratch never double-enqueues a woken process.
47. `max_heap.rs` (11 tests) — the PCB's **`max_heap_size` policy** (types in `src/max_heap.rs`; host-owned gaps in `../KNOWN_ISSUES.md`): the `include_shared_binaries` flag deciding a real `Process`'s verdict at one bound (within without it, `Kill`/`Log` with it — the oracle's decisive probe); the verdict recorded by every collection/growth door (`collect`, `collect_kind`, a `deliver`-forced growth, `ensure_capacity`, `grow_nursery`) with the collection's own `Result` untouched and the latch clearable exactly once; `kill: false` recording `Log` (log-only); the **prospective** rule (an admission installing a capacity above the bound is recorded while the pre-admission size was within it); an unlimited setting and a comfortably-within process recording nothing; the setting round-tripping; the queries never latching.
48. `receive_signals.rs` (18 tests) — the **receive-scan** entry point `ProcessTable::service_receive_signals`: a trapped link exit applied as `{'EXIT',…}`; a link-exit `kill` trapped while an explicit `exit/2` `kill` **stops** the scan (both read through `receive_applicability`, each expectation derived from `exit_policy`, never restated); a plain and a `{tag,T}` monitor `DOWN`; the **FIFO** order pinned in both arrangements; a terminating head leaving the queue byte-identical with the process alive (plus the `service_signals` regression pin); a trapped exit applied ahead of a terminating head; an `Ignore` head discarded with the next `DOWN` delivered; quiet/unknown/stale-pid no-ops; a delivered message waking a `Waiting` receiver onto the wake list; a `Running` receiver's in-scan `DOWN` via a **heap fragment** with an untouched nursery; and 5 `oracle_*` probes (trapped link exit, link `kill` trapped, explicit `kill` ⇒ `killed`, monitor `DOWN` reason, `normal` link exit ignored).
   Determinism limit (recorded in the module docs): the relative order of two independently generated signals is not oracle-probeable — Erlang orders only per `(sender,receiver)` pair — so the C's single per-process FIFO is the ordering source.
49. `reserve_remote.rs` (13 tests) — the **distributed-spawn reservation** seam: `reserve_remote` ⇒ `spawn_reserved` puts a live process at exactly the reserved `(number, serial)` with the claim gone; a claim creates no process and keeps `alloc_pid` off the number while a second allocation still works; two claims of different numbers coexist; live-number / already-claimed / out-of-range (`system_limit`) / wrong-or-uninstalled-node refusals; stale, cancelled, consumed and foreign handles install nothing; `cancel_reservation` makes the number allocatable again (bumped serial) while a stale `spawn_reserved` is `badarg`; a double cancel leaves exactly one `free` entry (the leak pin); a forced `spawn_reserved` failure releases the claim; 64 reserve/cancel rounds leave `slot_count`/`free_count` stable.
   No oracle probe: a local pid pre-post-allocation is not observable from `erl -noshell -eval` without a second live node and a full `DOP_SPAWN_REQUEST` peer, so `dist.c`'s line ranges (cited in `src/reserve.rs`) are the documented basis.
50. `remote_monitor_exit.rs` (7 tests) — the **outbound** half of the same families: `DistSignal::MonitorExit`, the `DOP_MONITOR_P_EXIT` a watched local process's death routes to every recorded `RemoteWatcher` (the C's `erts_dsig_send_m_exit`, `TUPLE5(DOP_MONITOR_P_EXIT, Watched, Watcher, Ref, Reason)`, `dist.c:1497-1519` — **watched-first**, the reverse of the monitor family's `{DOP_MONITOR_P, watcher, watched, ref}`); `remote_inbound.rs` pins the record, this file the signal it *emits*, which is what gives a peer's `erlang:monitor(process, RemotePid)` its `{'DOWN', Ref, process, Watched, Reason}` at all.
   Every case destructures through one `monitor_exit` helper that **panics on any other `DistSignal` variant**, so each also proves nothing else went on the wire: a peer-minted record's `RemoteWatcherRef::Remote(..)` verbatim plus the very word the death was handed (a heap-built 2-tuple, so "carried" is provable); two sysnames giving one signal each in **record order**, no de-duplication; the `monitor_from_remote` spelling routing `RemoteWatcherRef::Local(..)`; only the dying process's own watchers routed; a structured reason arriving intact; a death with no router still `Ok` and record-only.
51. `remote_reason_copy.rs` (6 tests) — the **wire reason is materialised on the recipient** by the two inbound receipt builders (`src/ptab.rs`'s `enqueue_remote_exit_message`/`enqueue_remote_down_message`). Method: each test builds a **boxed** reason on a **separate** `beam_alloc::Heap` simulating the host's per-drain dispatch arena, calls the public receipt entry point (`apply_remote_exit_signal`/`remote_monitor_down`), then **resets and rewrites the arena** before asserting — so every assertion reads only the recipient's heap.
   Pointer non-aliasing is pinned for the trapped link exit's `{'EXIT', From, Reason}` and the monitor DOWN's reason (walked after the arena is gone); an exempt recipient and a gate-declined watcher get the reason in the message's `Fragments` with the nursery untouched and no collection; and two tight-nursery cases (a 38-word nursery that takes the reason copy but not the payload's own wrapper — the geometry asserted, not assumed) keep the **retry** honest: the receiver really is collected and grown before the retry, and the queued reason answers in the **live** heap (`young_contains`/`mature_contains`, checked before anything dereferences the word). No `erl` oracle (it cannot observe a Rust-side heap word).
52. `node_down.rs` (4 tests) — `ProcessTable::node_down`'s **`noconnection` semantics and record purge**, through the public API: a trapping link partner survives with `{'EXIT', RemotePid, noconnection}` at the mailbox head (external pid in the body, node atom as the message `from`); a non-trapping one dies with exactly `noconnection`, never `killed` (the link family); a remote monitor DOWN is delivered **and** wakes a `Waiting` watcher onto `drain_woken`; the purge removes only the lost node's incoming `remote_watchers` and its `remote_links`/`remote_monitors` records, unrelated nodes' records surviving.
   No `erl` oracle probe is possible — it would need a live second node (a real `net_kernel` connection to break) — so the C ground truth is cited instead (`dist.c:304-324`/`:341-345`/`:379-423`, `erl_proc_sig_queue.c:2553-2576`).
53. `collection_scratch_reuse.rs` (4 tests) — the process's **reusable collection scratch** (`scratch::CollectionScratch`'s `roots`/`drained`/`reachable`, cleared by `begin()` before every round) is a pure allocation saving: two consecutive collections over the same `Process`, each with its own root layout, report exactly what a freshly constructed process reports, and no off-heap payload is retained or freed by a *previous* round's verdict (both mirrored directions — a set cleared *after* its walk would dangle a live payload); a failed collection leaves no residue either. Each case is asserted **against a freshly constructed reference process**, never constants. The buffer contract itself is pinned by `src/scratch.rs`'s in-module tests.

## Routing Table
Single-threaded scheduler / engine plumbing:
- `scheduler.rs`, `messaging.rs`, `signals.rs`, `priority.rs`, `preemption.rs`, `pending_signals.rs`, `service_signals_fast_path.rs`, `scheduler_ports.rs` → the single-threaded scheduler, mailbox, signals (incl. the **family-aware** exit policy — a link-exit `kill` traps, an explicit `erlang:exit/2` `kill` does not), four-level priority and pre-emption/fairness, and the port-aware slice cleanup (see `../CONTEXT.md`).
- `gc.rs`, `fragments.rs`, `dict.rs`, `dict_oracle.rs` → GC roots: the safepoint collection over the process root set, the saved-BIF/NIF-argument sub-rootset, and the process dictionary (with its `erl`-cross-checked equality evidence).
- `split_borrow.rs` → the two `Process` split borrows (`heap_and_off_heap_mut` + `Fragments::move_into`; `heap_and_mailbox_mut` + `send_fragmented`).

Signals, heap exhaustion and the collection-decline routes:
- `exhaustion.rs`, `signal_exhaustion.rs` → the collect-grow-and-retry path of `Process::deliver` and of the `{'EXIT',…}`/`{'DOWN',…}` builders' enqueue-time reason copy, plus the typed refusal where no fragment can carry the signal.
- `signal_fragment_fallback.rs`, `decline_gate.rs`, `decline_gate_builders.rs` → the heap-fragment fallback for a declined relocation — crate-owned unpublished roots (relocation exemption, `Running`) or the host `CollectionGate` — at the apply-time build, the enqueue-time reason copy, and the six `build_signal_message`-only builders (see `../CONTEXT.md`, `../KNOWN_ISSUES.md`).
- `gc_exemption.rs` → the GC relocation exemption itself (`set_relocation_exempt` and its `ProcessTable` delegation).
- `message_relocation.rs`, `gc_refc_binary_message.rs`, `off_heap_send_isolation.rs` → the collection's whole-envelope queued-message re-install (fragments, refc-binary/node lists, FIFO), the queued message's off-heap ownership, and the send-path staging-table isolation.
- `message_from_is_immediate.rs` → the `Message::from`-is-an-immediate producer invariant on every signal path.
- `off_heap_binaries.rs`, `off_heap_reachability.rs` → the process-owned off-heap refc-binary list: conservative declared-dead sweep, `retain_off_heap_binaries`, and the **reachability-driven** sweep with its decline valve.
- `terminate_best_effort.rs` → the best-effort termination cascade (a failing `DistSignalRouter`, or an unreachable peer heap, must not abort the death; the observer and the port-monitor cleanup still run).
- `process_exit_observer.rs`, `port_monitor_cleanup.rs` → the process-death observer seam and the death-side port-monitor cleanup.

Heap admission, scratch reuse, `max_heap_size`, collector dispatch:
- `collection_debt.rs`, `collection_scratch_reuse.rs`, `max_heap.rs` → the crate's own heap-admission point (the collector's collection debt), the **reuse soundness** of the per-collection scratch (nothing a previous round left behind may reach the next one), and the PCB's `max_heap_size` policy (types in `src/max_heap.rs`).
- `collector_dispatch.rs` → the GC **strategy dispatch** a `Process`'s heap policy resolves to, and the unchanged default cadence.

Process-control surface:
- `registry_monitors.rs`, `monitor_tag.rs`, `alias.rs`, `capability_inventory.rs`, `process_info_source.rs`, `spawn_options.rs`, `lifecycle_oracle.rs` → name registry + monitors (incl. the `monitor/3` user tag), the alias semantics (`alias/1`/`unalias/1` and the `{alias, Mode}` expiry rules), the typed-error/capability inventory, the `process_info` item→accessor map, spawn-option composition, and the lifecycle semantics (link exit propagation, the **exit-family split** for a `kill`, exit-reason shapes, `exit/2` propagation, the registry round trip, `demonitor` `[info]`/`[flush]`).
- `ports.rs`, `remote.rs` → the port table and distributed links/monitors.
- `smp.rs`, `lock_scope.rs`, `timers.rs`, `dirty.rs`, `progress.rs` → the SMP pool (see `../src/smp/CONTEXT.md`).

Distribution:
- `remote_inbound.rs` → the inbound (receipt) half of the link/monitor/exit/unlink/group-leader families: the route-free `ProcessTable` entry points (non-echoing by construction), pinned with a recording `DistSignalRouter`.
- `remote_monitor_exit.rs` → the **outbound** mirror of `remote_inbound.rs`: `DistSignal::MonitorExit` (`DOP_MONITOR_P_EXIT`, watched-first, `dist.c:1497-1519`) — one signal per recorded `RemoteWatcher`, the reference in the spelling the record holds, the death's own reason, in record order.
- `remote_reason_copy.rs` → the **wire-reason copy** of the two inbound receipt builders: a boxed reason built on a simulated decoder arena, embedded, then the arena recycled — asserted on the recipient's heap (or the message's `Fragments`), for the trap, the monitor DOWN, both heap-fragment routes, and the tight-nursery collect-and-retry.
- `node_down.rs` → `node_down`'s `noconnection` semantics (trapped, fatal, monitor DOWN + wake) and its three-direction record purge; no `erl` oracle probe is possible (it needs a second live node).
- `reserve_remote.rs` → the distributed-spawn reservation seam (`reserve_remote`/`spawn_reserved`/`cancel_reservation`, the no-leak rollback pins).

Cross-cutting:
- `reference_ids.rs` → the **shared reference-id-space pin**: `RefAllocator` is a zero-sized handle onto `beam_common::next_ref_id`, so a draw *is* the shared counter's next id and a monitor/alias reference can never collide with a bare `make_ref/0`-shaped one.
- `alias.rs`, `dict_oracle.rs`, `registry_monitors.rs`, `monitor_tag.rs`, `lifecycle_oracle.rs`, `capability_inventory.rs`, `port_monitor_cleanup.rs` (their `oracle_*` tests) → `erl`-cross-checked process-dictionary, alias, process-control, lifecycle and port-monitor evidence (loud skip when `erl` is absent); driver is the shared `common/mod.rs`.
- `receive_signals.rs` → the receive-scan signal entry point (`service_receive_signals`: receive-applicable FIFO application, the `Ignore` discard, the `Terminate` stop, the heap-fragment route for a `Running` receiver).
- `common/mod.rs` → the shared `erl` oracle driver (`erl_stdout`/`expect_oracle`/`strip_logger_reports`), included by the seven `oracle_*` suites above.
